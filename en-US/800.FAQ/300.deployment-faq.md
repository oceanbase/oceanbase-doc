## What is LSE?

LSE is a feature introduced in ARMv8.1, which stands for "Large System Extensions" (Large System Extensions). LSE provides a set of atomic operations to support synchronization and mutual exclusion access in a multi-processor environment. These atomic operations include Load-Exclusive (LDE), Store-Exclusive (STE), and the Conditional Compare Exchange (CCXE) instruction. LSE also provides new instructions and memory barriers to maintain data consistency and ordering.

Using LSE instructions, you can efficiently access shared memory and implement more granular lock mechanisms with lower overhead. Compared to traditional synchronization instructions, LSE instructions can reduce lock contention, improve concurrency performance, and provide better scalability.

### From which version of OCP can you deploy OceanBase Database packages with the nolse tag?

OCP can deploy OceanBase Database RPM packages with the nolse tag starting from version V4.3.0. This primarily addresses the issue of identifying the Large System Extensions (LSE) extension instructions in ARM architecture.

### Considerations for OBD deployment

You can upload both OceanBase Database RPM packages with and without the nolse tag. OBD will adaptively deploy the packages based on the system's support. Alternatively, you can upload and install only the supported packages as needed.

### Considerations for OCP deployment

Although you can upload both OceanBase Database RPM packages with and without the nolse tag to OCP, adaptive installation is not supported. When selecting the version for cluster deployment, you must choose whether to use the LSE-supported package as needed.

## Can an OBServer node support both IPv4 and IPv6?

For example, can an OBServer node use IPv4 for RPC communication with other OBServer nodes and IPv6 for SQL communication with external clients, or vice versa?

No, because:

* If IPv6 is not enabled, the OBServer node will not listen on IPv6.
* If IPv6 is enabled, the OBServer node will set the IPV6_V6ONLY option when listening on the SQL port, preventing IPv4 connections.

## Can IPv4 and IPv6 be mixed in an OceanBase cluster?

In other words, is it allowed to deploy IPv4 and IPv6 addresses in the same cluster, where some OBServer nodes are started with IPv4 addresses and others with IPv6 addresses.

Yes.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>When an OBServer node is started with an IPv4 address, its operating system and underlying network must support IPv6 to ensure normal communication with other IPv6-based OBServer nodes.</p>
</main>
