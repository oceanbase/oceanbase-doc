# What's New

OceanBase Database V4.5.0 is an agile iteration version for AI scenarios. It significantly enhances the AI capabilities of the core database engine. The new version comprehensively optimizes the IVF_FLAT and IVF_PQ indexes from four dimensions: construction, query, DML, and usability. It also supports memory-based sparse vector indexes, providing superior sparse vector retrieval performance. The new version significantly enhances the hybrid search capabilities, supporting hybrid search with multiple vectors and allowing the results of multiple vector queries to be fused and reordered using weighted methods. Based on the built-in embedding capabilities, the new version supports users to create semantic indexes based on text columns, simplifying the process of using vector indexes.

In addition, the new version supports the INTERVAL partitioning feature in Oracle tenant mode, reducing the complexity of partition management. The new version improves the performance and stability of the Index Skip Scan feature and enables it by default.

This topic describes the key features and major performance improvements of OceanBase Database V4.5.0.

## Key features

### Core enhancements

* **Enhanced Index Skip Scan**

    The new version improves the performance and stability of the Index Skip Scan feature. Even if the optimizer incorrectly chooses an Index Skip Scan plan, the performance will not degrade significantly. The new version enables the Index Skip Scan feature by default. After collecting statistics, the optimizer can automatically generate an Index Skip Scan plan if the rules and cost conditions are met.

* **Support for index merge for JSON multi-value indexes**

    By integrating JSON multi-value indexes into the Index Merge framework, the new version significantly reduces the number of table lookups by merging the scan results of multiple indexes. This improves the performance of filtering JSON columns with JSON multi-value indexes using the member of, json_overlaps, and json_contains expressions.

### Shared storage

The new version introduces new configuration items related to shared storage, including shared directories, private directories, upload, minor, major, and attach statistics.

### Oracle compatibility

* **INTERVAL partitioning in Oracle mode**

    The new version supports the INTERVAL partitioning feature in Oracle tenant mode. When new data exceeds the range of existing partitions, new partitions are automatically created, reducing the complexity of partition management.

### AI feature enhancements

* **Optimized IVF vector index performance**

    The new version comprehensively optimizes the IVF/IVF_PQ indexes from four dimensions: construction, query, DML, and usability. In terms of construction, the new version optimizes the index construction time by parallelizing K-means and adapting the domain ID merge framework. In terms of query, the new version introduces an iterative filtering algorithm that intelligently selects pre/post filter strategies based on different filtering rates, ensuring result completeness while improving query performance. In terms of DML, the new version optimizes incremental write efficiency using a caching mechanism. In terms of usability, the new version introduces new features such as index rebuild parameter modification, build progress monitoring, and dynamic configuration of the nprobes parameter at the statement level.

* **Enhanced automatic partition rebuilding**

    Automatic partition rebuilding of vector indexes effectively reduces memory usage. However, for scenarios with a large number of partitions and large data volumes per partition, the single-threaded model used by automatic partition rebuilding is inefficient. To make better use of cluster resources, the new version supports multi-threaded parallel construction for asynchronous indexes. You can set the `vector_index_optimization_concurrency` parameter to specify the number of threads.

* **Enhanced hybrid search**

    The new version further enhances the hybrid search feature, supporting hybrid search with multiple vectors and scalar conditions. It also allows the results of multiple vector queries to be fused and reordered using weighted methods.

* **Optimized full-text index performance**

    The new version optimizes the performance of full-text indexes by using adaptive BMM/BMW pruning algorithms for topK scenarios.

* **AI_Prompt and Similarity expressions**

    The new version introduces the `AI_Prompt` function, which upgrades static text prompts to reusable and parameterizable function templates. This supports prompt reuse and dynamic combinations of prompts with data, enabling efficient prompt engineering. The `AI_Complete` expression allows you to call a text generation model to process data based on prompts, such as in sentiment analysis and summarization scenarios. The new version also supports three expressions for calculating vector similarity: `inner_product_similarity`, `cosine_similarity`, and `l2_similarity`. A value closer to 1 indicates higher similarity between two vectors.

### Performance improvements

* **Optimized Multi Get performance**

    The new version optimizes the performance of Multi Get by implementing the following measures:

  * Columnar storage projection is supported for columnar scans.

  * The `filter` clause is optimized using skip index prefixes.

  * `blockscan` is supported for `keep order` scans.

  * Real-time statistics collection at the storage layer.

    After these optimizations, the performance of table lookups is significantly improved, especially in scenarios with large data volumes. The performance of wide tables with more than 80 columns projected in row-column redundancy mode is also significantly improved. Additionally, the scan performance in vectorized `nest loop join` scenarios is improved.

* **Optimized Insert Up performance**

    Under the premise of good data locality, the primary keys of batch table lookups are relatively continuous. The new version merges multiple range point queries into a single range scan, reducing the number of ranges and further improving the performance of table lookups. The new version also restructures the main process of the `Insert Up` operator, optimizes the conflict detection mechanism, and effectively improves the overall performance.
