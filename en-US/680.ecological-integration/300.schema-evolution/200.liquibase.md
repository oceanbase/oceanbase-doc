# Manage the version of OceanBase Database by using Liquibase

Liquibase is an open-source database version control tool that supports version tracking, updating, and rolling back of database schemas.

## Prerequisites

- You have downloaded and decompressed [Liquibase](https://www.liquibase.org/get-started/quickstart) and installed it.
- You have downloaded the MySQL JDBC driver from the [official website](https://dev.mysql.com/downloads/connector/j/) and obtained the `mysql-connector-j-x.x.x.jar` file.
* You have installed OceanBase Database and created a MySQL tenant.

## Version compatibility

We recommend that you use OceanBase Database V4.2.3 or later to ensure a better integration experience.

## Procedure

### Step 1: Obtain a database connection string

Obtain a database connection string from an OceanBase deployment engineer or administrator. For example:

```
obclient -h$host -P$port -u$user_name -p$password -D$database_name
```

**The parameters are described as follows:**

* `$host`: the IP address for connecting to OceanBase Database. For connection through OceanBase Database Proxy (ODP), this parameter is the IP address of an ODP. For direct connection, this parameter is the IP address of an OBServer node.
* `$port`: the port for connecting to OceanBase Database. For connection through ODP, the default value is `2883`, which can be customized when ODP is deployed. For direct connection, the default value is `2881`, which can be customized when OceanBase Database is deployed.
* `$database_name`: the name of the database to be accessed.

    <main id="notice" type='notice'>
        <h4>Notice</h4>
        <p>The user for connecting to a tenant must have the <code>CREATE</code>, <code>INSERT</code>, <code>DROP</code>, and <code>SELECT</code> privileges on the database. For more information about user privileges, see <a href="../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md">Privilege types in MySQL mode</a>. </p>
    </main>

* `user_name`: the username in the **username@tenant name#cluster name** or **username@SERVICE:service name** format. If you use the **username@tenant name#cluster name** format, the default tenant is 'sys' and the administrator user is 'root'. When you directly connect to a database, you can omit the cluster name. When you connect to a database through ODP, you must specify the cluster name.
* `$password`: the account password.

For more information about connection strings, see [Connect to an OceanBase tenant by using OBClient](../../300.develop/100.application-development-of-mysql-mode/100.connect-to-oceanbase-database-of-mysql-mode/300.connect-to-an-oceanbase-tenant-by-using-obclient-of-mysql-mode.md).

**Here is an example:**

```shell
obclient -hxxx.xxx.xxx.xxx -P2881 -utest_user001@mysql001 -p****** -Dtest
```

### Step 2: Use a reference example of Liquibase

1. **Copy the JDBC driver to the `lib` directory of Liquibase**

   In your virtual machine, locate the folder where you decompressed Liquibase, and go to the `lib` directory. Copy the `mysql-connector-j-x.x.x.jar` file to this directory.

   Or, run the following command:

   ```bash
   mv path/to/mysql-connector-j-x.x.x.jar path/to/liquibase/lib/
   ```

2. **Create a configuration file**

   In the root directory of Liquibase, create a configuration file named `liquibase.properties`. You can use any text editor (such as `nano`, `vim`, or `gedit`) to create the file and write the following content to it:

   ```
   url: jdbc:mysql://xxx.xxx.xxx.xxx:2881/test
   username: your_username
   password: your_password
   classpath: lib/mysql-connector-j-8.3.0.jar
   ```

   Replace `xxx.xxx.xxx.xxx` with the host address of your OceanBase Database, and enter the database port, username, and password. For more information about how to obtain the database host address, port, username, and password, see **Step 1**.

3. **Take a snapshot of the current database schema**

   Go to the root directory of Liquibase and run the following command to take a snapshot of the current database schema:

   ```shell
   ./liquibase --changeLogFile=mydatabase_changelog.xml generateChangeLog
   ```

   The actual parameters may vary depending on your version of Liquibase. For more information, see [Liquibase documentation](https://docs.liquibase.com/home.html?_ga=2.193221357.1372013942.1726823585-713905107.1726823585).

4. **Create a new table**

   In the root directory of Liquibase, create a file named `dbchangelog.xml` and write the following content to it:

   ```xml
   <?xml version="1.0" encoding="UTF-8"?>  
   <databaseChangeLog  
       xmlns="http://www.liquibase.org/xml/ns/dbchangelog"  
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"  
       xmlns:pro="http://www.liquibase.org/xml/ns/pro"  
       xsi:schemaLocation="http://www.liquibase.org/xml/ns/dbchangelog http://www.liquibase.org/xml/ns/dbchangelog/dbchangelog-4.4.xsd
           http://www.liquibase.org/xml/ns/pro http://www.liquibase.org/xml/ns/pro/liquibase-pro-4.5.xsd">
       <changeSet author="BobR" id="myIDNumber123">
           <createTable tableName="actor">
               <column autoIncrement="true" name="id" type="INTEGER">
                   <constraints nullable="false" primaryKey="true" primaryKeyName="actor_pkey"/>
               </column>
               <column name="firstname" type="VARCHAR(255)"/>
               <column name="lastname" type="VARCHAR(255)"/>
               <column name="twitter" type="VARCHAR(15)"/>
           </createTable>
       </changeSet>
   </databaseChangeLog>
   ```

5. **Execute the change**

   Run the following command to execute the change and create the `actor` table:

   ```shell
   ./liquibase update --changeLogFile=dbchangelog.xml
   ```

6. **Roll back the change**

   After the change is successfully executed, you can also execute the rollback operation to roll back the database to the previous version:

   ```shell
   ./liquibase rollbackCount 1 --changelog-file=dbchangelog.xml
   ```
