# Connect to OceanBase Database and obtain data by using Debezium

Debezium is an open-source distributed platform that monitors database changes and captures data change events, and exports them as event streams to various consumers. Debezium is built on Apache Kafka and supports multiple database systems.

## Prerequisites

Before you use Debezium, make sure that you have installed oblogproxy. For more information, see [Install oblogproxy](https://www.oceanbase.com/docs/community-oblogproxy-doc-1000000000438540).

## Procedure

This topic describes how to use Debezium to connect to OceanBase Database and obtain data by using Docker. This deployment method is not suitable for production environments. Perform the following steps:

1. Start Zookeeper.

    ```shell
    docker run -it -d --name zookeeper -p 2181:2181 -p 2888:2888 -p 3888:3888 quay.io/debezium/zookeeper:2.4
    ```

2. Start Kafka.

    ```shell
    docker run -it -d --name kafka -p 9092:9092 --link zookeeper:zookeeper quay.io/debezium/kafka:2.4
    ```

3. Start the Kafka Connect service. This service exposes a REST API for managing the Debezium MySQL connector.

    ```shell
    docker run -it -d --name connect -p 8083:8083 -e GROUP_ID=1 -e CONFIG_STORAGE_TOPIC=my_connect_configs -e OFFSET_STORAGE_TOPIC=my_connect_offsets -e STATUS_STORAGE_TOPIC=my_connect_statuses --link kafka:kafka  quay.io/debezium/connect:2.4
    ```

4. Create a `payload.json` file and write the following sample configuration to it.

   ```json
      {
      "name": "inventory-connector",
      "config": {
        "connector.class": "io.debezium.connector.mysql.MySqlConnector",
        "tasks.max": "1",
        "database.hostname": "xxxx.cn-hangzhou.oceanbase.aliyuncs.com",
        "database.port": "3306",
        "database.user": "root",
        "database.password": "xxxx",
        "database.server.id": "1",
        "topic.prefix": "observer1",
        "database.include.list": "debe",
        "table.include.list":"debe.earthquake",
        "schema.history.internal.store.only.captured.tables.ddl":true,
        "schema.history.internal.skip.unparseable.ddl":true,
        "schema.history.internal.kafka.bootstrap.servers": "kafka:9092",
        "schema.history.internal.kafka.topic": "schema-changes.inventory",
        "snapshot.locking.mode": "none"
      }
    }
   ```

<main id="notice" type='notice'>
<h4>Notice</h4>
<p><ol>
  <li>The MySQL connector cannot recognize OceanBase Database syntaxes such as <code>PURGE TABLE</code>. You can configure the <code>schema.history.internal.skip.unparseable.ddl</code> option to avoid this issue.</li>
  <li>You may not want to synchronize virtual tables and views that are unique to OceanBase Database. You can use the <code>table.include.list</code> or <code>table.exclude.list</code> parameter to filter them out.</li>
  <li>Use the curl command to submit a POST request to the /connectors resource of the Kafka Connect service API, and attach the JSON document of the new connector.<br><code>
cat payload.json | tr -d "\n" | curl -X POST -H "Content-Type: application/json" -d @- localhost:8083/connectors/</code></li>
<li>After a connector is registered, it generates a large amount of log output in the Kafka Connect container. You can observe the process of the connector from its creation to the start of reading Binlog from OceanBase Database in the log output.
<br><code>docker run -it --rm --name watcher --link zookeeper:zookeeper --link kafka:kafka quay.io/debezium/kafka:2.4 watch-topic -a -k observer1.debe.earthquake</code></li>
</ol>
</p>
