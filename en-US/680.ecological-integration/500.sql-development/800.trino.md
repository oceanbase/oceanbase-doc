# Connect to OceanBase Database by using Trino

Trino is an open-source distributed SQL query engine that supports high-performance interactive queries across various data sources. With the Trino OceanBase connector, you can use standard SQL to query and analyze OceanBase Database, suitable for data exploration, report generation, and cross-data source join queries.

## Version compatibility

| Component | Version requirement |
|------|---------|
| Trino | ≥ 433 |
| OceanBase Database | ≥ V4.2.5 |

## Prerequisites

Before you connect to OceanBase Database by using Trino, make sure that the following conditions are met:
* Docker is installed. For more information, see the [Docker official documentation](https://docs.docker.com/get-docker/).
* Java 23.0.0 or later (64-bit) is installed. For more information, see [Oracle Java official website](https://www.oracle.com/java/).
* OceanBase Database is deployed and a MySQL or Oracle mode user tenant is created. For more information, see [Create a tenant](../../600.manage/200.tenant-management/600.common-tenant-operations/200.manage-create-tenant.md).

## Procedure

### Step 1: Obtain the connection string of OceanBase Database

Contact the OceanBase Database deployment personnel to obtain the connection string. For example:

```shell
obclient -h$host -P$port -u$user_name -p$password -D$database_name
```

**Parameter description:**
* `$host`: the IP address for connection. For ODP connection, use the ODP address. For direct connection, use the OBServer IP address.
* `$port`: the port for connection. For ODP connection, the default value is `2883`. For direct connection, the default value is `2881`.
* `$database_name`: the name of the database.
  <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>The user for connecting to the tenant must have the <code>CREATE</code>, <code>INSERT</code>, <code>DROP</code>, and <code>SELECT</code> privileges on the database. For more information about user privileges, see <a href="../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md">Privilege classification in MySQL mode</a> and <a href="../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/300.permission-of-oracle-mode/000.permission-classification-of-oracle-mode.md">Privilege classification in Oracle mode</a>.</p>
  </main>
* `$user_name`: the username for connection. For ODP connection, the format is `user@tenant#cluster` or `cluster:tenant:user`. For direct connection, the format is `user@tenant`.
* `$password`: the password for the account.

For more information about the connection string, see [Connect to an OceanBase tenant by using OBClient](../../300.develop/100.application-development-of-mysql-mode/100.connect-to-oceanbase-database-of-mysql-mode/300.connect-to-an-oceanbase-tenant-by-using-obclient-of-mysql-mode.md).

**Here is an example:**

```shell
obclient -hxxx.xxx.xxx.xxx -P2881 -utest_user001@mysql001 -p****** -Dtest
```

### Step 2: Build the Trino OceanBase connector

This topic uses Trino 468 as an example to describe how to build and deploy the Trino OceanBase connector.

1. Clone the Trino OceanBase source code:

   ```shell
   git clone https://github.com/oceanbase/trino-oceanbase.git
   ```

2. In the root directory of the project, run the following command to build the connector:

   ```shell
   cd trino-oceanbase
   ./mvnw clean package -DskipTests
   ```

   <main id="notice" type='notice'>
     <h4>Notice</h4>
     <p>The parent.version in trino-oceanbase/pom.xml must be consistent with the Trino version.</p>
   </main>

3. After the build is complete, the connector file is located in the `./target/trino-oceanbase-468` directory. You can run the following command to view the file:

   ```shell
   ls -l ./target/trino-oceanbase-468
   ```

### Step 3: Deploy the Trino container and configure the connection

1. Create a log configuration file named `log.properties`:

   ```shell
   cat > ./log.properties << EOF
   io.trino=DEBUG
   EOF
   ```

2. Create an OceanBase connection configuration file named `oceanbase.properties`:

   ```shell
   cat > ./oceanbase.properties << EOF
   connector.name=oceanbase
   connection-url=jdbc:oceanbase://\$host:\$port/\$database_name
   connection-user=\$user_name
   connection-password=\$password
   oceanbase.compatible-mode=mysql
   oceanbase.auto-reconnect=true
   oceanbase.remarks-reporting.enabled=true
   decimal-mapping=ALLOW_OVERFLOW
   decimal-rounding-mode=HALF_UP
   EOF
   ```

   **Parameter description:**
   * `$host`: the IP address for connecting to OceanBase Database.
   * `$port`: the port for connecting to OceanBase Database.
   * `$database_name`: the name of the database.
   * `$user_name`: the username for connection.
   * `$password`: the password for the account.

3. Start the Trino Docker container:

   ```shell
   docker run -d \
     --name trino \
     -e TZ=Asia/Shanghai \
     -v ./target/trino-oceanbase-468:/usr/lib/trino/plugin/oceanbase \
     -v ./oceanbase.properties:/etc/trino/catalog/oceanbase.properties \
     -v ./log.properties:/etc/trino/log.properties \
     trinodb/trino:468

   # View the container status.
   docker ps -a |grep trino
   ```

## Verify the result

Run the `SHOW CATALOGS;` command in the Trino CLI.

```shell
docker exec -it trino trino --execute 'SHOW CATALOGS;'
```

If the schema list of OceanBase Database is displayed, the connection is configured correctly.

```text
"jmx"
"memory"
"oceanbase"
"system"
"tpcds"
"tpch"
```
