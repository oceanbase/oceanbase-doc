# Manage memory for vector indexes

This topic describes how to estimate and manage the memory usage of **all types of vector indexes** in OceanBase Database.

## Configure memory for vector indexes

OceanBase Database allows you to configure the memory for vector indexes by using the [ob_vector_memory_limit_percentage](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/6150.ob_vector_memory_limit_percentage.md) parameter:

The default value is `0`, which indicates the adaptive mode. In this mode, the system automatically adjusts the memory usage ratio of vector index data in the tenant. You do not need to manually adjust the memory usage ratio.
  * If the actual memory of the tenant is 8 GB or less, the value is automatically adjusted to `40`.
  * If the actual memory of the tenant is more than 8 GB, the value is automatically adjusted to `50`.

## Estimate and query the memory usage of vector indexes

You can use the `DBMS_VECTOR` system package to estimate the memory usage of vector indexes:

* Before you create a table, you can call the [INDEX_VECTOR_MEMORY_ADVISOR](../../700.reference/600.pl-reference/200.pl-mysql/1000.pl-system-package-mysql/17850.dbms-vector-mysql/500.index-vector-memory-advisor-mysql.md) procedure to estimate the memory usage of vector indexes.
* After you create a table and insert data into it, you can call the [INDEX_VECTOR_MEMORY_ESTIMATE](../../700.reference/600.pl-reference/200.pl-mysql/1000.pl-system-package-mysql/17850.dbms-vector-mysql/400.index-vector-memory-estimate-mysql.md) procedure to analyze the memory usage of vector indexes.

The memory usage estimation of vector indexes returns two pieces of information: the minimum memory configuration required to create vector indexes, and the actual memory usage after the creation of HNSW_SQ and IVF indexes.

  <h4>Notice</h4>

You can query the [GV$OB_VECTOR_MEMORY](../../700.reference/700.system-views/400.system-view-of-mysql-mode/300.performance-view-of-mysql-mode/4650.gv-ob_vector_memory-of-mysql-mode.md) or [V$OB_VECTOR_MEMORY](../../700.reference/700.system-views/400.system-view-of-mysql-mode/300.performance-view-of-mysql-mode/35350.v-ob_vector_memory-of-mysql-mode.md) view to obtain the actual memory usage.

## Optimize memory usage during index rebuild

For partitioned tables, we provide the `vector_index_memory_saving_mode` parameter to control the memory usage during index rebuild. Enabling this mode reduces the memory consumption during the rebuild of vector indexes in partitioned tables. Typically, vector index rebuilds require twice the memory of the index. When this mode is enabled, the system temporarily deletes the memory index of each partition after it is built to free up memory, thereby significantly reducing the total memory required for the rebuild. For more information, see [vector_index_memory_saving_mode](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/8240.vector_index_memory_saving_mode.md).
