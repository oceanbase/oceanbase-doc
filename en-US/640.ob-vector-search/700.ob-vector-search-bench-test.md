# VectorDBBench benchmark test

VectorDBBench is a tool for generating benchmark test results of mainstream vector databases and cloud services. This topic describes how to use VectorDBBench to benchmark OceanBase Database's vector search performance. VectorDBBench is designed to be user-friendly so that you can easily replicate the test results or run benchmark tests on new systems.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>At present, this test supports only HNSW index-based search. </p>
</main>

## Prerequisites

* You have deployed an OceanBase cluster of version V4.3.5 or later.
* You have created a MySQL tenant. For more information, see [Create a tenant](../600.manage/200.tenant-management/600.common-tenant-operations/200.manage-create-tenant.md).
* You have installed Python 3.11 or later. The example below shows how to install Python 3.11 using Conda.
  ```bash
  # Download and install Conda
  mkdir -p ~/miniconda3
  wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh -O ~/miniconda3/miniconda.sh
  bash ~/miniconda3/miniconda.sh -b -u -p ~/miniconda3
  rm ~/miniconda3/miniconda.sh

  # Open a new terminal window and initialize Conda
  source ~/miniconda3/bin/activate
  conda init --all

  # Create and initialize the Python environment required by VectorDBBench
  conda create -n vdb python=3.11
  conda activate vdb
  ```
* Connect to the business tenant and optimize the memory and query parameters for HNSW vector index search:
  ```sql
  -- Set ob_vector_memory_limit_percentage to 30%.
  ALTER SYSTEM SET ob_vector_memory_limit_percentage = 30;
  -- Set ob_query_timeout to 24 hours.
  SET GLOBAL ob_query_timeout = 86400000000;
  -- Set max_allowed_packet to 1 GB.
  SET GLOBAL max_allowed_packet=1073741824;
  ```
  Here, the example shows the parameter setting `ob_vector_memory_limit_percentage = 30`, which is just a sample value. You need to adjust it based on the memory size and business volume of the tenant. For more information, see [ob_vector_memory_limit_percentage](../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/6150.ob_vector_memory_limit_percentage.md).

## Test methods

### Clone the VectorDBBench code

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>We recommend that you deploy VectorDBBench on a different server from OceanBase Database to avoid competing for CPU resources, which can improve the reliability of the test results.</p>
</main>

Clone the VectorDBBench code to your local server.

```bash
git clone -b v0.1.0 https://github.com/wyfanxiao/VectorDBBench.git
```

### Install dependencies

Go to the VectorDBBench directory and install the dependencies.

```bash
cd VectorDBBench
pip install .
```

### Run the test

Run the VectorDBBench tool.

```bash
# Replace $host, $port, and $user with the actual connection information of OceanBase Database.
vectordbbench oceanbasehnsw --host $host --port $port --user $user --database test --m 16 --ef-construction 200 --ef-search 40 --k 10 --case-type Performance768D1M
```

For more information about the parameters of the `vectordbbench oceanbasehnsw` command, run the following command:

```bash
vectordbbench oceanbasehnsw --help
```

Here are two commonly used parameters:

* `--num-concurrency`: the concurrency level. VectorDBBench will execute the vector queries with the specified concurrency level and select the maximum QPS (Queries Per Second, queries per second) as the final result.
* `--skip-drop-old`/`--skip-load`: specifies to skip deleting old data and loading new data. If these options are added, the command will only perform vector query operations without deleting old data or loading new data.
* `--k`: the number of the top-k neighbor results to be returned in a vector query.
* `--ef-search`: the candidate set size parameter in an HNSW query.
