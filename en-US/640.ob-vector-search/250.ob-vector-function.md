# Use SQL functions

This topic describes the vector functions supported by OceanBase Database and their usage notes.

## Considerations

* If the vector dimensions are different, an error `different vector dimensions %d and %d` is returned.
* If the result exceeds the floating-point value range, an error `value out of range: overflow / underflow` is returned.
* The dense index supports L2, inner product, and cosine distance as index distance algorithms. The memory sparse index supports only the inner product as the index distance algorithm. For more information, see [Dense vector index](200.ob-vector-index/200.ob-vector-index.md).
* You can call the `L2_distance`, `Cosine_distance`, `Inner_product`, and `Negative_inner_product` distance functions in this topic.

## Configure vector index memory

OceanBase Database allows you to configure vector index memory by setting the [ob_vector_memory_limit_percentage](../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/6150.ob_vector_memory_limit_percentage.md) parameter:

* **Before you use HNSW/HNSW_SQ/HNSW_BQ vector indexes in versions earlier than V4.4.1**, you must manually set the `ob_vector_memory_limit_percentage` parameter to enable vector features. We recommend that you set this parameter to `30` for optimal retrieval performance. If you do not set this parameter, the system does not allocate memory for vector indexes, and an error is returned when you create an index. The IVF/IVF_SQ/IVF_PQ indexes do not need to be resident in memory, so you do not need to consider this parameter. Example:
    ```sql
    ALTER SYSTEM SET ob_vector_memory_limit_percentage = 30;
    ```

* **Starting from V4.4.1**, vector retrieval is enabled by default. The default value of `0` indicates adaptive mode, where the system automatically adjusts the memory usage ratio of vector index data in the tenant. You do not need to manually adjust this parameter:
  * If the actual memory of the tenant is 8 GB or less, the value is automatically adjusted to `40`.
  * If the actual memory of the tenant is more than 8 GB, the value is automatically adjusted to `50`.

## Distance function

The distance function calculates the distance between two vectors, and the calculation method varies depending on the distance algorithm.

### L2_distance

The Euclidean distance reflects the distance between the coordinates of the compared vectors, which is essentially the straight-line distance between two vectors. The Pythagorean theorem is applied to the vector coordinates to calculate it:

![Pythagorean theorem](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer/V4.3.5/vector_search/%E5%8B%BE%E8%82%A1%E5%AE%9A%E7%90%86.jpg)

The function syntax is as follows:

```sql
l2_distance(vector v1, vector v2)
```

The parameters are described as follows:

* In addition to the vector type, other types that can be strongly cast to a vector type are also accepted. These include single-level array types (e.g., `[1,2,3,..]`) and string types (e.g., `'[1,2,3]'`).

* The dimensions of the two parameters must be the same.

* When a single-level array type parameter is present, the elements of the parameter cannot contain `NULL`.

The return value is described as follows:

* The return value is a `distance(double)` value.

* If any parameter is `NULL`, `NULL` is returned.

Here is an example:

```sql
CREATE TABLE t1(c1 vector(3));
INSERT INTO t1 VALUES('[1,2,3]');
SELECT l2_distance(c1, [1,2,3]), l2_distance([1,2,3],[1,1,1]), l2_distance('[1,1,1]','[1,2,3]') FROM t1;
```

The result is as follows:

```shell
+--------------------------+------------------------------+----------------------------------+
| l2_distance(c1, [1,2,3]) | l2_distance([1,2,3],[1,1,1]) | l2_distance('[1,1,1]','[1,2,3]') |
+--------------------------+------------------------------+----------------------------------+
|                        0 |             2.23606797749979 |                 2.23606797749979 |
+--------------------------+------------------------------+----------------------------------+
1 row in set
```

### Cosine_distance

Cosine similarity measures the angular difference between two vectors, reflecting their directional similarity regardless of their magnitudes. The cosine similarity value ranges from `[-1, 1]`, where `1` indicates the vectors are in the same direction, `0` indicates orthogonality, and `-1` indicates opposite directions.

The calculation method for cosine similarity is as follows:

![Cosine similarity](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer/V4.3.5/vector_search/%E4%BD%99%E5%BC%A6%E7%9B%B8%E4%BC%BC%E5%BA%A6.jpg)

Since a higher cosine similarity value indicates greater similarity, cosine distance (or cosine dissimilarity) is sometimes used as a measure of distance between vectors. Cosine distance can be calculated by subtracting the cosine similarity from 1:

![Cosine distance](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer/V4.3.5/vector_search/%E4%BD%99%E5%BC%A6%E8%B7%9D%E7%A6%BB.jpg)

The cosine distance value ranges from `[0, 2]`, where `0` indicates the same direction (no distance), and `2` indicates the opposite direction.

The function syntax is as follows:

```sql
cosine_distance(vector v1, vector v2)
```

The parameters are described as follows:

* In addition to the vector type, other types that can be strongly cast to a vector type are also accepted. These include single-level array types (e.g., `[1,2,3,..]`) and string types (e.g., `'[1,2,3]'`).

* The dimensions of the two parameters must be the same.

* When a single-level array type parameter is present, the elements of the parameter cannot contain `NULL`.

The return value is described as follows:

* The return value is a `distance(double)` value.

* If any parameter is `NULL`, `NULL` is returned.

Here is an example:

```sql
CREATE TABLE t3(c1 vector(3));
INSERT INTO t3 VALUES('[1,2,3]');
INSERT INTO t3 VALUES('[1,2,1]');
SELECT cosine_distance(c1, [1,2,3]) FROM t3;
```

```shell
+------------------------------+
| cosine_distance(c1, [1,2,3]) |
+------------------------------+
|                            0 |
|          0.12712843905603044 |
+------------------------------+
2 rows in set
```

### Inner_product

The inner product, also known as the dot product or scalar product, represents a type of multiplication between two vectors. In a geometric sense, the inner product indicates the directional and magnitude relationships between two vectors. The calculation method for the inner product is as follows:

![Inner product](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer/V4.3.5/vector_search/%E5%86%85%E7%A7%AF.jpg)

The syntax is as follows:

```sql
inner_product(vector v1, vector v2)
```

The parameters are described as follows:

* In addition to vector types, other types that can be strongly converted to vector types are also supported, including single-level array types (such as `[1,2,3,..]`) and string types (such as `'[1,2,3]'`).

* The dimensions of the two parameters must be the same.

* When a single-level array type is used as a parameter, the elements of the array cannot contain `NULL`.

* When sparse vectors are used with this function, one of the parameters can be a sparse vector in string format, such as `c2,'{1:2.4}'`; both parameters cannot be strings.

The return value is described as follows:

* The return value is a `distance(double)` value.

* If any parameter is `NULL`, the return value is `NULL`.

Here is an example of dense vectors:

```sql
CREATE TABLE t4(c1 vector(3));
INSERT INTO t4 VALUES('[1,2,3]');
INSERT INTO t4 VALUES('[1,2,1]');
SELECT inner_product(c1, [1,2,3]) FROM t4;
```

The result is as follows:

```shell
+----------------------------+
| inner_product(c1, [1,2,3]) |
+----------------------------+
|                         14 |
|                          8 |
+----------------------------+
2 rows in set
```

Here is an example of sparse vectors:

```sql
CREATE TABLE t4(c1 INT, c2 SPARSEVECTOR, c3 SPARSEVECTOR);
INSERT INTO t4 VALUES(1, '{1:1.1, 2:2.2}', '{1:2.4}');
INSERT INTO t4 VALUES(2, '{1:1.5, 3:3.6}', '{4:4.5}'));
SELECT inner_product(c2,c3) FROM t4;

The result is as follows:

```shell
+----------------------+
| inner_product(c2,c3) |
+----------------------+
|    2.640000104904175 |
|                    0 |
+----------------------+
2 rows in set

### Vector_distance

vector_distance is used to calculate the distance between two vectors. You can specify a parameter to select a different distance algorithm.

The syntax is as follows:

```sql
vector_distance(vector v1, vector v2 [, string metric])
```

The `vector v1/v2` parameters are described as follows:

* In addition to vector types, other types that can be strongly converted to vector types are also supported, including single-level array types (such as `[1,2,3,..]`) and string types (such as `'[1,2,3]'`).

* The dimensions of the two parameters must be the same.

* When a single-level array type is used as a parameter, the elements of the array cannot contain `NULL`.

The `metric` parameter specifies the distance algorithm. Valid values are as follows:

* If this parameter is not specified, the default algorithm is `euclidean`.

* If this parameter is specified, the only valid value is:

* `euclidean`: indicates the Euclidean distance, which is the same as L2_distance.

* `manhattan`: indicates the Manhattan distance, which is the same as L1_distance.

* `cosine`: indicates the cosine distance, which is the same as Cosine_distance.

* `dot`: indicates the inner product, which is the same as Inner_product.

The return value is described as follows:

* The return value is a `distance(double)` value.

* If any parameter is `NULL`, the return value is `NULL`.

Here is an example:

```sql
CREATE TABLE t5(c1 vector(3));
INSERT INTO t5 VALUES('[1,2,3]');
INSERT INTO t5 VALUES('[1,2,1]');
SELECT vector_distance(c1, [1,2,3], euclidean) FROM t5;
```

The result is as follows:

```shell
+-----------------------------------------+
| vector_distance(c1, [1,2,3], euclidean) |
+-----------------------------------------+
|                                       0 |
|                                       2 |
+-----------------------------------------+
2 rows in set
```

## Arithmetic functions

Arithmetic functions provide addition, subtraction, and multiplication operations for vector types, single-level array types, and special string types. These operations are performed element-wise. For example, the addition operation is performed as follows:

![Addition](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer/V4.3.5/vector_search/%E5%8A%A0%E6%B3%95.jpg)

The syntax is as follows:

```sql
v1 + v2
v1 - v2
v1 * v2
```

The parameters are described as follows:

* In addition to vector types, parameters can accept any type that can be strongly cast to a vector type, including single-level array types (e.g., `[1,2,3,..]`) and string types (e.g., `'[1,2,3]'`). **Note:** One of the parameters must be a vector or single-level array type. Both parameters cannot be string types.

* The dimensions of the two parameters must be the same.

* If a parameter is a single-level array type, its elements cannot contain `NULL`.

The return value is described as follows:

* If at least one parameter is a vector type, the return value is a vector type with the same dimension as the vector parameter.

* If both parameters are single-level array types, the return value is of the `array(float)` type.

* If any parameter is `NULL`, the return value is `NULL`.

Here is an example:

```sql
CREATE TABLE t6(c1 vector(3));
INSERT INTO t6 VALUES('[1,2,3]');
SELECT [1,2,3] + '[1.12,1000.0001, -1.2222]', c1 - [1,2,3] FROM t6;
```

The return result is as follows:

```shell
+---------------------------------------+--------------+
| [1,2,3] + '[1.12,1000.0001, -1.2222]' | c1 - [1,2,3] |
+---------------------------------------+--------------+
| [2.12,1002,1.7778]                    | [0,0,0]      |
+---------------------------------------+--------------+
1 row in set
```

## Vector search functions for semantic indexes

In addition to the general vector functions mentioned earlier, OceanBase Database provides vector search functions for semantic indexes (vector indexes created on text columns):

* `semantic_distance(column_name, 'query_text')`: This function performs vector retrieval based on the original text. The system automatically calls the embedding model to convert the text into a vector.
* `semantic_vector_distance(column_name, query_vector)`: This function performs vector retrieval based on the vector. It supports both index-based retrieval (with the `APPROXIMATE` or `APPROX` clause) and full-table scan (without the `APPROXIMATE` or `APPROX` clause).

These two functions are specifically designed for semantic index scenarios. For more information and examples, see [Semantic indexes](200.ob-vector-index/300.ob-semantic-index.md).
