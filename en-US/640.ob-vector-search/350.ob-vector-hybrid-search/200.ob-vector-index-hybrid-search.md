# Hybrid search (PL interface)

This topic describes how to use the hybrid search (PL interface) of OceanBase Database to combine full-text search and vector search. You can construct an internal SQL statement to obtain the search results and return the search results in JSON format. By using this feature, you can perform multi-dimensional searches efficiently and improve the accuracy and usability of queries.

Hybrid search combines vector-based semantic search and full-text search based on full-text indexes. It provides more accurate and comprehensive search results by using a combined ranking method. Vector search is good at semantic approximate matching but is not suitable for precise matching of keywords, numbers, and proper nouns. Full-text search can effectively compensate for this limitation. Therefore, hybrid search has become one of the key features of vector databases and is widely used in various products.

## Usage

The hybrid search feature is provided by the new system package `DBMS_HYBRID_SEARCH`, which contains two subprograms:

| Member Method Name | Description |
| ------------ | -------- |
| `DBMS_HYBRID_SEARCH.SEARCH` | Returns the search results in JSON format, sorted by relevance. |
| `DBMS_HYBRID_SEARCH.GET_SQL` | Returns the actual executed SQL statement as a string. |

For more information about the syntax and parameters, see [DBMS_HYBRID_SEARCH](../../700.reference/600.pl-reference/200.pl-mysql/1000.pl-system-package-mysql/9000.dbms-hybrid-search-mysql/100.dbms-hybrid-search-overview.md).

## Considerations

* Mixed search PL interfaces are supported only on **heap tables**. The examples in this topic are based on heap tables.
* When you use mixed search, we recommend that you specify the `_source` field to specify the column range. If you do not specify the `_source` field, all columns in the table are returned. If the table contains vector columns, the response time (RT) increases significantly.

### Scalar search

Some common use cases for scalar search include:

* Product filtering on an e-commerce platform: Users want to view all products of a specific brand. For example, users want to view all products of the `GamerZone` brand.
* Content management system: Administrators need to filter articles or documents of a specific category. For example, find all articles by a specific author.
* User management system: Find users of a specific status or role. For example, find all VIP users.

Here is an example:

1. Set the query parameters.

    ```sql
    SET @parm = '{
    "query": {
        "bool": {
            "must": [
            {"term": {"brand": "GamerZone"}}
            ]
        }
    },
    "_source": ["product_id", "product_name", "description", "brand", "category", "tags", "price", "stock_quantity", "release_date", "is_on_sale"]
    }';
    ```

2. Search for all records where the `brand` is `"GamerZone"`.

    ```sql
    SELECT json_pretty(DBMS_HYBRID_SEARCH.SEARCH('products', @parm)); 
    ```

### Scalar range search

Some common use cases for scalar range search include:

* Price range filtering: Filter products by price range on an e-commerce platform. For example, find products in the price range `[30~80]`.
* Time range query: Find orders or logs within a specific time period. For example, find orders from the last 30 days.
* Numeric range filtering: Filter by numeric ranges such as ratings or stock quantities. For example, find products with ratings in the range `[4~5]`.

Here is an example:

1. Set the search parameters.

    ```sql
    SET @parm = '{
    "query": {
        "range" : {
        "price" : {
            "gte" : 30,
            "lte" : 80
        }
        }
    },
    "_source": ["product_id", "product_name", "description", "brand", "category", "tags", "price", "stock_quantity", "release_date", "is_on_sale"]
    }';
    ```

2. Query all records where the `price` is in the range `[30~80]`.

### Multi-vector search

Multi-vector search refers to searching across multiple vector indexes and returning the most similar records.

Here's an example:

1. Set the search parameters.

    ```sql
    -- Specify 3 vector search paths, each specifying a vector index field, the number of results to return, and the query vector.
    SET @param_multi_knn = '{
    "knn" : [{
                "field": "vec1",
                "k": 5,
                "query_vector": [0.5,0.1,0.6,0.9]
            },
            {
    ```

### Hybrid full-text and vector search

Hybrid full-text and vector search is applicable in the following scenarios:

* Intelligent search: A comprehensive search that combines keywords and semantic understanding. For example, if a user enters `"I need a gaming keyboard"`, the system matches the keywords `"gaming"` and `"keyboard"` and understands the semantic meaning of `"gaming equipment"`.
* Document search: A search that supports both exact keyword matching and semantic understanding in a large number of documents. For example, when you search for `"database optimization"`, the system matches documents containing these words and finds content related to `"performance tuning"` and `"query optimization"`.
* Product recommendation: An e-commerce platform that supports both product name searches and demand description searches. For example, if a user describes `"a notebook suitable for office use"`, the system matches the keywords and understands the semantic need for `"business office equipment"`.

Here's an example:

1. Set the search parameters.

    ```sql
    SET @parm = '{
    ```

### Hybrid full-text and vector RRF search

By default, the results of the full-text subquery and the vector subquery are combined using weighted hybrid search. You can use the `Rank` syntax to configure the combination method to `RRF` (Reciprocal Rank Fusion) sorting hybrid search. This method is applicable in the following scenarios:

* Multi-dimensional sorting: A search that considers the results of multiple search dimensions. For example, in an academic search system, when you search for papers in a paper database, you need to consider both keyword matching and semantic relevance.
* Fairness requirements: A search that ensures that the results of different search methods are reasonably displayed. For example, on an e-commerce platform, you need to consider both the text information such as the title and description of a product and the visual information such as the image and video of the product.
* Complex queries: A search that involves multiple query conditions. For example, in a medical system, you need to consider both the symptoms described by the patient and the medical history and test results.

Here's an example:

Set the search parameters.

```sql
SET @rrf_query_param = '{
  "query": {
    "query_string": {
      "fields": ["title", "author", "description"],
      "query": "fiction American Dream"
    }
  },
  "knn" : {
    "field": "vector_embedding",
    "k": 5,
    "query_vector": [0.1, 0.2, 0.3, 0.4]
  },
  "rank" : {
    "rrf" : {
      "rank_window_size" : 10,
      "rank_constant" : 60
    }
  },
  "_source": ["title", "author", "description"]
}';
```

The RRF algorithm calculates the final relevance score by fusing the rankings of the result sets of multiple subqueries. The calculation formula is as follows:

```sql
score = 0.0
for q in queries:
    if d in result(q):
        score += 1.0 / ( k + rank( result(q), d ) ) # K is the configured rank_constant
return score
```

The examples in this topic demonstrate the powerful application value of hybrid search:

* Intelligent search upgrade: Integrate semantic understanding into traditional keyword search to provide more accurate and intent-aligned search results.
* Optimize user experience: Support natural language queries to simplify operations and improve information retrieval efficiency.
* Enable diverse business scenarios: Apply hybrid search in e-commerce, content management, knowledge bases, and intelligent customer service to cover everything from basic filtering to intelligent recommendations.
* Leverage technical advantages: Combine exact matching with semantic understanding to significantly improve the accuracy and comprehensiveness of search results.

Hybrid search is an ideal choice for handling large volumes of unstructured data and building intelligent search and recommendation systems.
