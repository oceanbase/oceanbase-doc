# Hybrid search

This topic describes how to perform hybrid search in OceanBase Database.

Hybrid search combines vector-based semantic search and keyword search based on full-text indexes. It provides more accurate and comprehensive search results by using a comprehensive ranking method. Vector search is good at semantic approximate matching but is not good at precise matching of keywords, numbers, and proper nouns. Full-text search can effectively compensate for this shortcoming. Therefore, hybrid search has become one of the key features of vector databases and is widely used in various products.

## Use

The hybrid search feature is provided through the new system package `DBMS_HYBRID_SEARCH`, which contains two subprograms:

| Member Method | Description |
| ------------ | -------- |
| `DBMS_HYBRID_SEARCH.SEARCH` | Returns the search results in JSON format, sorted by relevance. |
| `DBMS_HYBRID_SEARCH.GET_SQL` | Returns the actual SQL statement executed as a string. |

For detailed syntax and parameter information, see [DBMS_HYBRID_SEARCH](../../700.reference/600.pl-reference/200.pl-mysql/1000.pl-system-package-mysql/9000.dbms-hybrid-search-mysql/100.dbms-hybrid-search-overview.md).

## Considerations

* At present, the hybrid search interface is only supported for **heap tables**. The examples in this topic are based on heap tables.
* We recommend that you specify the `_source` field when you use the hybrid search interface. This allows you to specify the range of columns to return. If you do not specify the `_source` field, all columns in the table will be returned by default. If the table contains vector columns, this will significantly increase the response time (RT).

### Scalar search

Scalar search is used in the following scenarios:

* E-commerce product filtering: Users want to view all products of a specific brand. For example, users want to view all products of the `GamerZone` brand.
* Content management system: Administrators need to filter articles or documents of a specific category. For example, find all articles by a specific author.
* User management system: Find users of a specific status or role. For example, find all VIP users.

Here is an example:

1. Set the search parameters.

    ```sql
    SET @parm = '{
    "query": {
        "bool": {
            "must": [
            {"term": {"brand": "GamerZone"}}
            ]
        }
    },
    "_source": ["product_id", "product_name", "description", "brand", "category", "tags", "price", "stock_quantity", "release_date", "is_on_sale"]
    }';
    ```

2. Search for records where `brand` is `"GamerZone"`.

    ```sql
    SELECT json_pretty(DBMS_HYBRID_SEARCH.SEARCH('products', @parm)); 
    ```

### Scalar range search

Scalar search is used in the following scenarios:

* Price range filtering: E-commerce platforms filter products by price range. For example, find products in the `[30~80]` price range.
* Time range query: Find orders or logs within a specific time period. For example, find orders from the last 30 days.
* Numerical range filtering: Filter products by rating, stock quantity, etc. For example, find products with a rating in the `[4~5]` range.

Here is an example:

1. Set the search parameters.

    ```sql
    SET @parm = '{
    "query": {
        "range" : {
        "price" : {
            "gte" : 30,
            "lte" : 80
        }
        }
    },
    "_source": ["product_id", "product_name", "description", "brand", "category", "tags", "price", "stock_quantity", "release_date", "is_on_sale"]
    }';
    ```

2. Search for records where `price` is in the `[30~80]` range.

    ```sql
    SELECT json_pretty(DBMS_HYBRID_SEARCH.SEARCH('products', @parm));
    ```

### Full-text search

Full-text search is used in the following scenarios:

* Document search: Search for content containing specific keywords in a large number of documents. For example, search for documents containing `"how to use"` in the FAQ.
* Product search: Perform fuzzy search based on product name and description. For example, search for products containing `"OceanBase"`.
* Knowledge base search: Search for related questions in FAQs and help documents. For example, search for answers to related questions in the customer service system's knowledge base.

Here is an example:

1. Set the search parameters.

    ```sql
    SET @query_str_with_mini = '{
    "query": {
        "query_string": {
        "type": "best_fields",
        "fields": ["product_name^3", "description^2.5", "tags^1.5"],
        "query": "Gamer-Pro^2 keyboard^1.5 audio^1.2",
        "boost": 1.5
        }
    },
    "_source": ["product_id", "product_name", "description", "brand", "category", "tags", "price", "stock_quantity", "release_date", "is_on_sale"]
    ```

* Intelligent search: Combines keyword matching with semantic understanding. For example, when a user searches for `"I need a gaming keyboard"`, the system matches keywords like `"gaming"` and `"keyboard"` and also understands the semantic intent of `"gaming equipment"`.
* Document search: Supports both precise keyword matching and semantic understanding in large document sets. For example, when searching for `"database optimization"`, the system matches documents containing these keywords and also finds semantically related content like `"performance tuning"` and `"query optimization"`.
* Product recommendation: Supports both product name searches and demand-based searches in e-commerce platforms. For example, when a user searches for `"a laptop suitable for office work"`, the system matches keywords and also understands the semantic intent of `"business office equipment"`.

### Full-text and vector RRF hybrid search

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>This feature is available starting from V4.4.1 BP0 HotFix1. </p>
</main>

By default, the results of the full-text subquery and the vector subquery are combined using weighted hybrid search. You can use the `Rank` syntax to configure the combination method to `RRF` (Reciprocal Rank Fusion) sorting hybrid search. Here are some common use cases:

* Multi-dimensional sorting: Considers the results of multiple search dimensions. For example, in an academic search system, when searching a paper database, both keyword matching and semantic relevance are considered.
* Fairness requirements: Ensures that results from different search methods are reasonably displayed. For example, in an e-commerce platform, both textual information such as product titles and descriptions and visual information such as product images and videos are considered.
* Complex queries: Involves multiple query conditions. For example, in a medical system, both the patient's symptoms and medical history and test results are considered.

Here is an example:

Set the search parameters.

```sql
SET @rrf_query_param = '{
  "query": {
    "query_string": {
      "fields": ["title", "author", "description"],
      "query": "fiction American Dream"
    }
  },
  "knn" : {
    "field": "vector_embedding",
    "k": 5,
    "query_vector": [0.1, 0.2, 0.3, 0.4]
  },
  "rank" : {
    "rrf" : {
      "rank_window_size" : 10,
      "rank_constant" : 60
    }
  },
  "_source": ["title", "author", "description"]
}';
```

The RRF algorithm calculates the final relevance score by fusing the rankings of multiple subquery result sets. The calculation formula is as follows:

```sql
score = 0.0
for q in queries:
    if d in result(q):
        score += 1.0 / ( k + rank( result(q), d ) ) # K is the rank_constant parameter
return score
```

### Summary

The examples in this topic demonstrate the powerful application value of hybrid search:

* Intelligent search upgrade: Integrates semantic understanding into traditional keyword search to provide more accurate and intent-aligned search results.
* Optimize user experience: Supports natural language queries, simplifies operations, and improves information retrieval efficiency.
* Enable diverse business scenarios: Widely applied in e-commerce, content management, knowledge bases, and intelligent customer service, covering everything from basic filtering to intelligent recommendations.
* Combine technical advantages: Integrates precise matching with semantic understanding to significantly improve the accuracy and comprehensiveness of search results.

Hybrid search is an ideal choice for processing large volumes of unstructured data and building intelligent search and recommendation systems.
