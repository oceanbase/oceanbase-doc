# Hybrid search (SQL interface)

This topic describes the hybrid search SQL interface of OceanBase Database. You can use the `HYBRID_SEARCH` keyword to combine full-text search, vector search, and filter conditions in a single `SELECT` statement and return the results sorted by relevance.

Hybrid search combines vector-based semantic search with keyword search based on full-text indexes. It provides more accurate and comprehensive search results by integrating the strengths of both approaches. Vector search excels at semantic approximate matching but is less effective for precise keyword, numeric, and proper noun matching. Full-text search effectively compensates for this limitation. As a result, hybrid search has become a key feature of vector databases and is widely used in various products.

## Limitations

* Currently, the `HYBRID_SEARCH` SQL clause is supported only for **heap tables**.
* Vector search requires that the target vector column has a vector index. Multi-vector search is supported only for dense vector columns.
* Full-text search requires that the target text column has a full-text index. If the full-text column has a composite index, it is not supported for hybrid search.
* Scalar filtering and JSON/ARRAY filtering can be performed without an index, but it is recommended to create the corresponding index for better performance.
* Only HNSW vector index types are supported in the current version.
* Only rowstore tables are supported.
* Generated columns are not supported.

This section only lists the limitations. For a complete understanding, refer to the syntax limitations of `HYBRID_SEARCH` at the end of the document.

## Syntax

```sql
SELECT select_list
FROM HYBRID_SEARCH(TABLE table_name, dsl_string);
```

The parameters are described as follows:

* `table_name`: the name of the target table, which must be a heap table (`ORGANIZATION = HEAP`). Supports partitioned and non-partitioned tables.
* `dsl_string`: a JSON string that describes the query semantics, such as full-text search, vector search, filtering, and sorting.

For more information about the complete syntax, parameters, and limitations, see the `HYBRID_SEARCH` section at the end of the document.

## Quick start examples

This section provides six simple core examples covering common hybrid search scenarios, including vector search, full-text search, vector search + full-text search (RRF fusion), multi-vector search, filter condition merging, and score threshold filtering.

### Vector search

This example searches for the 3 most similar records in the `doc_table` table to the vector `[1,2,3]` and returns the `c1` column.

```sql
SELECT c1 FROM HYBRID_SEARCH(
  TABLE doc_table,
  '{
    "knn": {
      "field": "vector",
      "k": 3,
      "query_vector": "[1,2,3]"
    }
  }'
);
```

The expected return result is as follows:

:::collapse
```sql
+------+
| c1   |
+------+
|    1 |
|    5 |
|    2 |
+------+
3 rows in set
```
:::

### Full-text and vector RRF hybrid search

This example statement simultaneously performs full-text search (matching the keyword `"oceanbase mysql"`) and vector search (searching for the 5 most similar records to the vector `[1,2,3]`), then uses the RRF fusion algorithm to merge the two sets of results. By default, it returns the 10 most relevant documents, with a total of 6 records meeting the criteria.

```sql
SELECT * FROM HYBRID_SEARCH(
  TABLE doc_table,
  '{
    "query": {
      "match": {"content": "oceanbase mysql"}
    },
    "knn": {
      "field": "vector",
      "k": 5,
      "query_vector": "[1,2,3]"
    },
    "rank": {
      "rrf": {
        "rank_constant": 60,
        "rank_window_size": 10
      }
    }
  }'
);
```

### Filter condition merging

This example searches for 6 records in the `doc_table` table where the `content` column contains `oceanbase mysql`, filters for `c1` values between 3 and 5, and returns the `c1` column.

```sql
SELECT c1 FROM HYBRID_SEARCH(
  TABLE doc_table,
  '{
    "query": {
      "bool": {
        "must": [{"match": {"content": "oceanbase mysql"}}],
        "filter": [{"range": {"c1": {"gte": 3}}}]
      }
    },
    "knn": {
      "field": "vector",
      "k": 10,
      "query_vector": "[1,2,3]",
      "filter": [
        {"range": {"c1": {"lte": 5}}}
      ]
    }
  }'
);
```

The expected return result is as follows:
:::collapse
```sql
+------+
| c1   |
+------+
|    1 |
|    3 |
|    6 |
|    5 |
|    2 |
|    4 |
+------+
6 rows in set
```
:::

## Advanced examples

This section provides more complex examples covering advanced hybrid search scenarios, including filtering on complex types (such as JSON and ARRAY), weighted hybrid search of vectors and full-text, WRRF hybrid search, normalization, and hybrid search score queries.

### Scalar + JSON/ARRAY filtering

These examples require the use of search indexes. In hybrid search scenarios, full-text search handles tokenization and keyword retrieval, while search indexes are used for structured, semi-structured, or simple scalar conditions within complex types. These two types of indexes can coexist in the same table and work together with vector indexes to improve query performance.

Additionally, in analytical wide-table scenarios, search indexes can leverage the optimizer's index merge capability to automatically identify and combine available full-text and scalar indexes, selecting the optimal scan path to further enhance query performance. For more information about search indexes, including usage, syntax, and complete examples, please refer to [Search Indexes (Search Index)](../700.ob-vector-search-reference/400.ob-ai-search-index.md).

### Other hybrid search scenarios

```sql
    "knn": {
      "field": "vector",
      "k": 5,
      "query_vector": "[1,2,3]",
      "boost": 0.7

);
```
