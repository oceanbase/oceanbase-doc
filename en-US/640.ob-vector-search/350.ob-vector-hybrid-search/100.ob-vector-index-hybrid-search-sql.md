# Hybrid search (SQL interface)

This topic describes the hybrid search SQL interface of OceanBase Database. You can use this interface to combine full-text search, vector search, and filter conditions in a single `SELECT` statement by using the `HYBRID_SEARCH` keyword. The interface returns the results sorted by relevance.

Hybrid search combines vector-based semantic search with keyword search based on full-text indexes. It provides more accurate and comprehensive search results by integrating the two search methods. Vector search is good at semantic approximate matching but is not effective in matching exact keywords, numbers, and proper nouns. Full-text search can effectively compensate for this limitation. Therefore, hybrid search has become a key feature of vector databases and is widely used in various products.

## Limitations

* At present, the `HYBRID_SEARCH` SQL clause is only supported for **heap tables**.
* Vector search requires that the target vector column has a vector index. Multi-vector search is only supported for dense vector columns.
* Full-text search requires that the target text column has a full-text index. If the full-text column has a composite index that includes multiple columns, hybrid search is not supported.
* Scalar filtering and JSON/ARRAY filtering can be executed without an index, but we recommend that you create an index for better performance.
* At present, the only supported vector index type is HNSW.
* Only rowstore tables are supported.
* Generated columns are not supported.

This section only lists the functional limitations. You also need to combine the syntax limitations listed in the `HYBRID_SEARCH` section at the end of the document.

## Syntax

```sql
SELECT select_list
FROM HYBRID_SEARCH(TABLE table_name, dsl_string);
```

The parameters are described as follows:

* `table_name`: the name of the target table. The table must be a heap table (`ORGANIZATION = HEAP`). It can be a partitioned table or a non-partitioned table.
* `dsl_string`: a JSON string that describes the query semantics of full-text search, vector search, filtering, and sorting.

For more information about the complete syntax, parameters, and limitations, see the `HYBRID_SEARCH` section at the end of the document.

## Quick start examples

This section provides six simple core examples covering common scenarios in hybrid search, including vector search, full-text search, vector search + full-text search (RRF fusion), multi-vector search, filter condition merging, and score threshold filtering.

### Vector search

This example searches for the 3 most similar records in the `doc_table` table to the vector `[1,2,3]` and returns the `c1` column.

```sql
SELECT c1 FROM HYBRID_SEARCH(
  TABLE doc_table,
  '{
    "knn": {
      "field": "vector",
      "k": 3,
      "query_vector": "[1,2,3]"
    }
  }'
);
```

The expected return result is as follows:

| c1   |
+------+
|    1 |
|    5 |
|    2 |

### Full-text and vector RRF hybrid search

By default, it returns the 10 most relevant documents to the query, with a total of 6 documents meeting the criteria.

      "field": "vector",
      "k": 5,

### Filter condition merging

This example searches for 6 records in the `doc_table` table where the `content` column contains `oceanbase mysql`, filters for `c1` values between 3 and 5 (inclusive), and returns the `c1` column.

```sql
SELECT c1 FROM HYBRID_SEARCH(
  TABLE doc_table,
  '{
    "query": {
      "bool": {
        "must": [{"match": {"content": "oceanbase mysql"}}],
        "filter": [{"range": {"c1": {"gte": 3}}}]
      }
    },
    "knn": {
      "field": "vector",
      "k": 10,
      "query_vector": "[1,2,3]",
      "filter": [
        {"range": {"c1": {"lte": 5}}}
      ]
    }
  }'
);
```

The expected return result is as follows:
:::collapse
```sql
+------+
| c1   |
+------+
|    1 |
|    3 |
|    6 |
|    5 |
|    2 |
|    4 |
+------+
6 rows in set
```
:::

## Advanced examples

This section provides more complex examples covering advanced scenarios in hybrid search, including filtering with complex types (JSON/ARRAY), weighted hybrid search of vectors and full-text, WRRF hybrid search, normalization, and score queries in hybrid search.

### Scalar + JSON/ARRAY filtering

These examples require the use of search indexes. In hybrid search scenarios, full-text tokenization and keyword retrieval are handled by the full-text index, while the search index is used for structured, semi-structured, or simple scalar conditions within complex types. These two types of indexes can coexist in the same table and are used in conjunction with vector indexes to improve query performance.

In analytical wide tables, search indexes can also leverage the optimizer's index merge capability to automatically identify and combine available full-text and scalar indexes, selecting the optimal scan path to further enhance query performance. For more information about search indexes, including usage, syntax, and complete examples, please refer to [Search Index (Search Index)](../700.ob-vector-search-reference/400.ob-ai-search-index.md).

### Other hybrid search scenarios
