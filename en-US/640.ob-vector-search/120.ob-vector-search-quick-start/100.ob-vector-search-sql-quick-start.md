# Perform a vector search by using an SQL statement

OceanBase Database allows you to perform a vector search by using an SQL statement. This topic describes how to do so.

## Prerequisites

* You have deployed an OceanBase cluster and created a MySQL-compatible tenant. For more information, see [Deploy an OceanBase cluster](../../400.deploy/100.deploy-overview.md).

* You have connected to OceanBase Database. For more information, see [Connection methods](../../300.develop/100.application-development-of-mysql-mode/100.connect-to-oceanbase-database-of-mysql-mode/100.connection-methods-overview-of-mysql-mode.md).

## Quick start

## Configure vector index memory

OceanBase vector search allows you to configure vector index memory by setting [ob_vector_memory_limit_percentage](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/6150.ob_vector_memory_limit_percentage.md):

* **Before V4.3.5 BP3**, you need to manually set `ob_vector_memory_limit_percentage` to enable vector search. We recommend that you set it to `30` for optimal query performance. If you use the default value, no memory is allocated for vector indexes, and an error will be returned when you create an index. Here is an example:
    ```sql
    ALTER SYSTEM SET ob_vector_memory_limit_percentage = 30;
    ```

* **Starting from V4.3.5 BP3**, the vector search feature is enabled by default. The default value `0` indicates adaptive mode, where the system automatically adjusts the memory usage ratio for vector index data within the tenant, so manual adjustment is not required.
  * When the tenant’s actual memory is 8 GB or less, the value is set to `40`.
  * When the tenant’s actual memory is more than 8 GB, the value is set to `50`.

### Create a vector column and a vector index

You can declare a specified column as a vector column and specify the dimension of the vector column when you create a table. A vector index must be created on a vector column, and the `type` and `distance` parameters must be specified.

In the following example, the `embedding` column is created as a vector column with a dimension of `3`. An HNSW index is created on the `embedding` column, and the L2 distance algorithm is specified.

```sql
CREATE TABLE t1(
    id INT PRIMARY KEY,
    doc VARCHAR(200),
    embedding VECTOR(3),
    VECTOR INDEX idx1(embedding) WITH (distance=L2, type=hnsw)
    );
```

If a large amount of data is to be imported, we recommend that you create a vector index after the data import is completed. For more information, see Vector indexes <temp-hide-link>.

### Write vector data

To simulate a vector search scenario, you must first construct some vector data. Each data record contains a description of the data and the corresponding vector. In the example, the vector corresponding to `'apple'` is `'[1.2,0.7,1.1]'`, and the vector corresponding to `'carrot'` is `'[5.3,4.8,5.4]'`.

```sql
INSERT INTO t1
  VALUES (1, 'apple', '[1.2,0.7,1.1]'),
         (2, 'banana', '[0.6,1.2,0.8]'),
         (3, 'orange','[1.1,1.1,0.9]'),
         (4, 'carrot', '[5.3,4.8,5.4]'),
         (5, 'spinach', '[4.9,5.3,4.8]'),
         (6, 'tomato','[5.2,4.9,5.1]');
```

In this example, the dimension of the vector is simplified to 3 for the sake of convenience of display. The vector is manually generated. In practice, you must use an embedding model to generate vectors from real texts, and the dimension can reach hundreds or thousands.

You can query data in the table to check whether the data is written successfully.

```sql
SELECT * FROM t1;
```

The expected return result is as follows:

```shell
+----+-----------+---------------+
| id | doc       | embedding     |
+----+-----------+---------------+
|  1 | apple      | [1.2,0.7,1.1] |
|  2 | banana      | [0.6,1.2,0.8] |
|  3 | orange      | [1.1,1.1,0.9] |
|  4 | carrot    | [5.3,4.8,5.4] |
|  5 | spinach    | [4.9,5.3,4.8] |
|  6 | tomato    | [5.2,4.9,5.1] |
+----+-----------+---------------+
6 rows in set
```

### Perform a vector search

To perform vector search, you need to provide a vector as the search condition. In this example, it is assumed that you want to find all `'fruits'`, whose vector is `[0.9, 1.0, 0.9]`. The corresponding SQL statement is as follows:

```sql
SELECT id, doc FROM t1
ORDER BY l2_distance(embedding, '[0.9, 1.0, 0.9]')
APPROXIMATE LIMIT 3;
```

The expected return result is as follows:

```shell
+----+--------+
| id | doc    |
+----+--------+
|  3 | orange |
|  2 | banana |
|  1 | apple |
+----+--------+
3 rows in set
```
