# AI function service syntax and examples

This topic describes the AI function service of OceanBase Database. It covers the features, syntax, and parameters of each function, as well as various usage examples. The supported functions are `AI_SPLIT_DOCUMENT`, `AI_EMBED`, `AI_COMPLETE`, `AI_PROMPT`, and `AI_RERANK`.

AI functions allow you to integrate AI model capabilities directly into data processing within the database through SQL expressions. This significantly simplifies operations such as data retrieval, analysis, summarization, and storage using large AI models. It is a significant new feature in the database and data warehouse fields. In MySQL mode, OceanBase Database provides AI model and endpoint management through the `DBMS_AI_SERVICE` package, introduces several new built-in AI function expressions, and supports monitoring AI model calls through views.

## Prerequisites (excluding `AI_SPLIT_DOCUMENT`)

* You have the required permissions for AI models. For more information, see [AI function service permissions](150.ob-vector-search-ai-function-permission.md).
* If you have not registered an AI model and endpoint, register them by following the instructions in [Register an AI model](200.ob-vector-search-ai-function-register-model.md).

## Considerations (excluding `AI_SPLIT_DOCUMENT`)

* `CREATE AI MODEL` and `DROP AI MODEL` operations are synchronized between primary and standby tenants, but `CREATE AI MODEL ENDPOINT`, `ALTER AI MODEL ENDPOINT`, and `DROP AI MODEL ENDPOINT` operations are not. Therefore, standby tenants need to manually configure AI model endpoints to use the AI Function Service.
* Hybrid Search relies on the model management and embedding features of the AI Function Service. When deleting an AI model, check if it is referenced by Hybrid Search to avoid potential issues.

## Function syntax and examples

This section describes the syntax and provides examples of the AI Function Service.

### AI_SPLIT_DOCUMENT

The `AI_SPLIT_DOCUMENT` function splits text into multiple segments to prepare for further processing.

#### Usage

The syntax is as follows:

```sql
AI_SPLIT_DOCUMENT(content TEXT, [parameters JSON]) [AS alias_name]
```

Parameter description:

| Parameter | Description | Type | Nullable |
|------|------|------|----------|
| content | The user's input text data, currently only supporting markdown format, UTF-8 encoded text. | VARCHAR / TEXT | No. Must be specified; if empty, an empty table is returned. |
| parameters | Used to configure optional parameters provided by the API, in JSON object or JSON string format. Currently supported parameters include:<ul><li><code>type</code>: can be <code>text</code> or <code>markdown</code>, defaulting to <code>markdown</code></li><li><code>by</code>: can be <code>word</code> or <code>sentence</code>, indicating whether to split by word or sentence, defaulting to <code>word</code></li><li><code>max</code>: the maximum number of words or sentences per chunk, defaulting to 256. Range: [1,1000]</li><li><code>overlap</code>: the maximum number of overlapping words or sentences between adjacent chunks, defaulting to 0, which cannot exceed half the maximum value.</li></ul> | JSON | Yes |
| alias_name | Specifies the alias for the returned result. | VARCHAR(128) | Yes |

Return value:

* A relational table containing four fields: `CHUNK_ID`, `CHUNK_OFFSET`, `CHUNK_LENGTH`, and `CHUNK_TEXT`. Here, `CHUNK_ID` is the ID of the split chunk, `CHUNK_OFFSET` is the starting position of the split chunk, `CHUNK_LENGTH` is the length of the split chunk in bytes, and `CHUNK_TEXT` is the text content of the split chunk.

Limitations:

* Currently, only UTF-8 encoded data can be split.
* This function can only be used as a table function after the `FROM` clause and cannot be directly used as a scalar function in the `SELECT` list.

#### Example

```sql
SELECT * FROM ai_split_document("Hello World", '{"max":1}');
```

The returned result is as follows:

```sql
+----------+--------------+--------------+------------+
| CHUNK_ID | CHUNK_OFFSET | CHUNK_LENGTH | CHUNK_TEXT |
+----------+--------------+--------------+------------+
|        0 |            0 |            6 | Hello      |
|        1 |            6 |            6 | World      |
+----------+--------------+--------------+------------+
```

### AI_EMBED

The `AI_EMBED` function specifies an embedded model (Embedding Model) registered in the database using `model_key` and converts the user's input text data into vector data. When the model supports multiple dimensions, the `dim` parameter can be used to specify the output dimensions.

#### Usage

The syntax is as follows:

```sql
AI_EMBED(model_key, input, [dim])
```

Parameter description:

| Parameter | Description | Type | Nullable |
|------|------|------|----------|
| model_key | The model registered in the database. | VARCHAR(128) | No |
| input | The user's input text data to be converted. | VARCHAR | No |
| dim | Specifies the output dimensions of the vector. Some large model vendors' APIs support configuring multiple dimensions. | INT64 | Yes |

Both `model_key` and `input` must be specified, and if one of them is `NULL`, the function will return an error.

Return value:

* A string in vector format, representing the vector generated by the embedding model based on the text.

#### Example

1. Embed single-row data

    ```sql
    SELECT AI_EMBED("ob_embed","Hello world") AS embedding;
    ```

    The returned result is as follows:

    ```sql
    +----------------+
    | embedding      |
    +----------------+
    | [0.1, 0.2, 0.3]|	
    +----------------+
    ```

2. Embed columns in a table

    ```sql
    CREATE TABLE comments (
        id INT AUTO_INCREMENT PRIMARY KEY,
        content TEXT
    );

    INSERT INTO comments (content) VALUES ('hello world!');

    SELECT AI_EMBED("ob_embed",content) AS embedding FROM comments;
    ```

    The returned result is as follows:

    ```sql
    +----------------+
    | embedding      |
    +----------------+
    | [0.1, 0.2, 0.3]|	
    +----------------+
    ```

### AI_COMPLETE and AI_PROMPT

The `AI_COMPLETE` function specifies a registered large language model (LLM) using the `model_key` parameter, processes the provided prompt and data, and returns the generated text from the LLM. Users can customize the prompt and data format within the `prompt` parameter. This approach not only supports diverse text processing but also enables batch processing within the database, effectively avoiding the overhead of data transfer between the database and the LLM.

In many AI applications, prompts are often highly structured and require dynamic injection of specific data. Manually concatenating prompts and input content using functions like `CONCAT` is not only costly in development but also prone to errors that can lead to formatting issues. To address the need for prompt reuse and dynamic combination with data, OceanBase Database provides the `AI_PROMPT` function. This function upgrades prompts from static text to reusable, parameterized templates that can be directly used in `AI_COMPLETE`, significantly simplifying the prompt construction process and enhancing development efficiency and accuracy.

#### AI_PROMPT function

The `AI_PROMPT` function dynamically constructs formatted prompts based on templates and supports dynamic data insertion.

##### Syntax

The syntax for the `AI_PROMPT` function is as follows:

```sql
AI_PROMPT('template', expr0 [ , expr1, ... ]);
```

Parameters:

| Parameter | Description | Type | Nullable |
|------|------|------|----------|
| template | The user-provided prompt template. | VARCHAR(max_length) | No |
| expr | The user-provided data. | VARCHAR(max_length) | No |

Both `template` and `expr` are required parameters and cannot be empty. Note that the `expr` parameter only supports the `VARCHAR` type and does not support the `JSON` type.

<main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>The indices of parameter placeholders in the prompt template must be unique; otherwise, an error will occur. For example, in <code>AI_PROMPT("tell me {0}+{0}=?", '10', '10')</code>, multiple <code>{0}</code> placeholders are present, which is not allowed. The correct usage involves each placeholder appearing only once, such as in <code>AI_PROMPT("tell me {0}+{1}=?", '10', '10')</code>.</p>
</main>

Return value:

* The formatted prompt, returned as JSON.

##### Examples

The `AI_PROMPT` function organizes the template string and dynamic data into JSON format:

* The first parameter (template string) is placed in the `template` field of the returned JSON.
* Subsequent parameters (data values expr0, expr1, etc.) are placed in the `args` array of the returned JSON.
* Placeholders like `{0}` and `{1}` in the template correspond to data in the `args` array by index and are automatically replaced when used in the `AI_COMPLETE` function.

For example:

```sql
SELECT AI_PROMPT('Recommend {0} of the most popular {1} to me.', 'ten', 'mobile phones');
```

The result is as follows:

```json
{
  "template": "Recommend {0} of the most popular {1} to me.",
  "args": ["ten", "mobile phones"]
}
```

Using the `AI_PROMPT` function in the `AI_COMPLETE` function:

```sql
SELECT AI_COMPLETE("ob_complete",AI_PROMPT('Recommend {0} of the most popular {1} to me.just output name in json array format', 'two', 'mobile phones')) AS ans;
```

The result is as follows:

```json
+--------------------------------------------------+
| ans                                              |
+--------------------------------------------------+
| ["iPhone 15 Pro Max","Samsung Galaxy S24 Ultra"] |
+--------------------------------------------------+
```

#### AI_COMPLETE function

##### Syntax

The syntax for the `AI_COMPLETE` function is as follows:

```sql
AI_COMPLETE(model_key, prompt[, parameters])
-- If you use the AI_PROMPT function, replace the prompt parameter with the AI_PROMPT function. For an example, see the AI_PROMPT function.
AI_COMPLETE(model_key, AI_PROMPT(prompt_template, data))
```

Parameters:

| Parameter | Description | Type | Nullable |
|------|------|------|----------|
| model_key | The registered model in the database. | VARCHAR(128) | No |
| prompt | The user-provided prompt information. | VARCHAR/TEXT(LONGTEXT) | No |
| parameters | Optional parameters provided by the API. These parameters are directly included in the generated message body and may vary by vendor. Common optional parameters include `temperature`, `top_p`, and `max_tokens`. Generally, you can use the default configuration without specifying these parameters. | JSON | Yes |

The `model_key` and `prompt` parameters must be specified, and if one of them is `NULL`, the function will return an error.

Return value:

* text, the text generated by the LLM based on the prompt.

##### Examples

1. Sentiment analysis example

    ```sql
    SELECT AI_COMPLETE("ob_complete","Your task is to perform sentiment analysis on the provided text to determine if it is positive or negative.
    The text to be analyzed is as follows:
    <text>
    The weather is really nice.
    </text>
    The judgment criteria are as follows:
    If the text expresses a positive sentiment, output 1; if it expresses a negative sentiment, output -1. Do not output anything else.\n") AS ans;
    ```

    The result is as follows:

    ```sql
    +-----+
    | ans |
    +-----+
    | 1   |
    +-----+
    ```

2. Translation example

    ```sql
    CREATE TABLE comments (
        id INT AUTO_INCREMENT PRIMARY KEY,
        content TEXT
    );

    INSERT INTO comments (content) VALUES ('hello world!');

    -- Replace the processed data with column names from the comments table in the database using a CONCAT expression, enabling batch processing of database data without copying data to and from the LLM
    SELECT AI_COMPLETE("ob_complete",
    concat("You are a translation master. You need to translate the following English text into Chinese. The text to be translated is as follows:<text>",
        content,
        "</text>")) AS ans FROM comments;
    ```
    The result is as follows:

    ```sql
    +-------------+
    | ans         |
    +-------------+
    | Hello, world!  |
    +-------------+
    ```

3. Classification example

    ```sql
    SELECT AI_COMPLETE("ob_complete","You are a classification master. You will receive a set of question texts and need to categorize them. The categories are [\"Hardware Department\",\"Software Department\",\"Other\"]. The text to be analyzed is as follows:
    <text>
    This screen is of poor quality.
    </text>") AS res;
    ```

    The result is as follows:

    ```sql
    +--------+
    | res    |
    +--------+
    | Hardware Department |
    +--------+
    ```

### AI_RERANK

The `AI_RERANK` function specifies a registered rerank model (Rerank Model) using `model_key`, organizes the user's query and document list according to the vendor's rules, sends the messages to the specified model, parses the model's response, and returns the sorted results. This function is suitable for reranking scenarios in RAG.

#### Usage

The syntax is as follows:

```sql
AI_RERANK(model_key, query, documents[, document_key])
```

Parameters:

| Parameter | Description | Type | Nullable |
|------|------|------|----------|
| model_key | The model registered in the database. | VARCHAR(128) | No |
| query | The text input by the user. | VARCHAR(1024) | No |
| documents | The list of documents input by the user. | JSON ARRAY, for example, `'["apple", "banana"]'` | No |

If `model_key`, `query`, and `documents` are not all specified, or if one of them is `NULL`, the function will return an error.

Return value:

* A JSON array containing the documents and their relevance scores returned by the rerank model, sorted in descending order of relevance scores.

#### Example

```sql
SELECT AI_RERANK("ob_rerank","Apple",'["apple","banana","fruit","vegetable"]');
```

The return result is as follows:

```sql
+-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| ai_rerank("ob_rerank","Apple",'["apple","banana","fruit","vegetable"]')                                                                                                                                                                                                                                                                                   |
+-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| [{"index": 0, "document": {"text": "apple"}, "relevance_score": 0.9912109375}, {"index": 1, "document": {"text": "banana"}, "relevance_score": 0.0033512115478515625}, {"index": 2, "document": {"text": "fruit"}, "relevance_score": 0.0003669261932373047}, {"index": 3, "document": {"text": "vegetable"}, "relevance_score": 0.00001996755599975586}] |
+-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
```
