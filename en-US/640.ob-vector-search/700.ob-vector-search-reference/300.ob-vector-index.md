# Vector indexes

This topic describes how to create, query, maintain, and drop vector indexes in OceanBase Database.

A vector index in OceanBase Database has the following characteristics:

* Supports HNSW indexes, with a maximum dimension of 4096 for the indexed column. An HNSW index is a memory-based index that needs to be fully loaded into memory. It supports DML operations and real-time queries.

* Supports L2, inner product (IP), and cosine distance as the index distance algorithm.

## Index-based queries

Vector index-based queries are a type of approximate nearest neighbor search (ANNS) and do not guarantee that the result is 100% correct. The metric for measuring the accuracy of a vector index-based query is the recall rate. For example, if 9 correct results are consistently returned when 10 nearest neighbors are searched, the recall rate is 90%. The recall rate is described as follows:

* The recall rate is subject to the build parameters and query parameters.

* The query parameter is specified during index creation and cannot be modified later. However, you can use the session variable `ob_hnsw_ef_search`. If `ob_hnsw_ef_search` is specified, its value prevails. For more information, see [ob_hnsw_ef_search](../../700.reference/800.configuration-items-and-system-variables/200.system-variable/400.session-system-variable/550.ob_hnsw_ef_search.md).

The syntax is as follows:

```sql
SELECT ... FROM $table_name ORDER BY $distance_function($column_name, $vector_expr) [APPROXIMATE|APPROX] LIMIT|OFFSET $num;
```

Take note of the following considerations:

* At present, only the syntax where the `ORDER BY` clause is followed with a vector condition is supported. Otherwise, the following error will be returned: `ERROR 1235 (0A000): Multi order by item when using vector index is not supported`.

* If the query contains a `WHERE` condition, regardless of whether the condition involves other index columns, a vector index is used as long as the preceding syntax is met. The `WHERE` condition is used as a filter condition after the vector index-based query is executed.

* The query plan will select a vector index only if the `APPROXIMATE` or `APPROX` keyword is used.

* The `ORDER BY` clause supports the `l2_distance`, `inner_product`, and `negative_inner_product` distance functions. `l2_distance` and `negative_inner_product` will select an indexed plan, and `inner_product` will not.

* For distance functions other than `l2_distance`, `inner_product`, and `negative_inner_product`, if you specify the `APPROXIMATE` or `APPROX` keyword to select a vector index, the following error will be returned: `ERROR 1235 (0A000): Using vector index without vector_sort_expr is not supported`.

* The value range of `LIMIT` and `OFFSET` is `(0,  16384]`.

## Examples of creating, querying, and dropping indexes

### Considerations

You can create a vector index when you create a table or after the table is created. Note that:

* Once a vector index is created, you cannot modify any of its parameters.

* You must specify the `VECTOR` keyword when you create a vector index.

* The parameters and description for adding a vector index are the same as those for creating a vector index when you create a table.

* If a large amount of data is to be loaded, we recommend that you load the data first and then create a vector index to ensure the query performance.

### Create a vector index when you create a table

Create a test table.

```sql
CREATE TABLE t1(c1 INT, c0 INT, c2 VECTOR(10), c3 VECTOR(10), PRIMARY KEY(c1), VECTOR INDEX idx1(c2) WITH (distance=l2, type=hnsw, lib=vsag),  VECTOR INDEX idx2(c3) WITH (distance=l2, type=hnsw, lib=vsag));
```

Write test data.

```sql
INSERT INTO t1 VALUES(1, 1,'[0.203846,0.205289,0.880265,0.824340,0.615737,0.496899,0.983632,0.865571,0.248373,0.542833]', '[0.203846,0.205289,0.880265,0.824340,0.615737,0.496899,0.983632,0.865571,0.248373,0.542833]');

INSERT INTO t1 VALUES(2, 2, '[0.735541,0.670776,0.903237,0.447223,0.232028,0.659316,0.765661,0.226980,0.579658,0.933939]', '[0.213846,0.205289,0.880265,0.824340,0.615737,0.496899,0.983632,0.865571,0.248373,0.542833]');
```

Perform an approximate nearest neighbor query.

Drop the vector index.

```sql
DROP INDEX vec_idx1 ON vec_table;
```

Query the dropped index.



## Index maintenance

When a large amount of incremental data is written, query performance will decrease. To reduce the volume of incremental data in a vector index, OceanBase Database introduced the `DBMS_VECTOR` package for maintaining vector indexes.

### Incremental refresh

If a large amount of data is written after the index is created, we recommend that you use incremental refresh.

The syntax is as follows:

```shell
  PROCEDURE refresh_index(
    IN     idx_name               VARCHAR(65535),                 ---- Index name
    IN     table_name             VARCHAR(65535),                 ---- Table name
    IN     idx_vector_col         VARCHAR(65535) DEFAULT NULL,    ---- Vector column name
    IN     refresh_threshold      INT DEFAULT 10000,              ---- Number of incremental data records
    IN     refresh_type           VARCHAR(65535) DEFAULT NULL);   ---- FAST
```

The system checks for incremental refreshes every 15 minutes. If more than 10,000 incremental data records are found, an incremental refresh is automatically initiated.

### Complete refresh

If a large amount of data is updated or deleted after the index is created, we recommend that you use complete refresh.

The syntax is as follows:

```shell
  PROCEDURE rebuild_index(
    IN     idx_name                VARCHAR(65535),                    ---- Index name
    IN     table_name              VARCHAR(65535),                    ---- Table name
    IN     idx_vector_col          VARCHAR(65535) DEFAULT NULL,       ---- Vector column name
    IN     delta_rate_threshold    FLOAT DEFAULT 0.2,                 ---- Proportion of incremental data
    IN     idx_organization        VARCHAR(65535) DEFAULT NULL,       ---- Index type
    IN     idx_distance_metrics    VARCHAR(65535) DEFAULT 'EUCLIDEAN',---- Distance type
    IN     idx_parameters          LONGTEXT DEFAULT NULL,             ---- Index parameters
    IN     idx_parallel_creation   INT DEFAULT 1);                    ---- Degree of parallelism for creating an index, reserved, only supported in syntax
```

The system checks for complete refreshes every 24 hours. If more than 20% of the original data is added, a complete refresh is automatically initiated.

#### Index maintenance example

Create a test table.

```sql
CREATE TABLE vector_index_test(c1 INT, c2 VECTOR(3), PRIMARY KEY(c1), VECTOR INDEX idx1(c2) WITH (distance=l2, type=hnsw, lib=vsag));
```

Write test data.

```sql
INSERT INTO vector_index_test VALUES(1, '[0.203846,0.205289,0.880265]');
INSERT INTO vector_index_test VALUES(2, '[0.484526,0.669954,0.986755]');
INSERT INTO vector_index_test VALUES(3, '[0.327936,0.048756,0.084670]');
INSERT INTO vector_index_test VALUES(4, '[0.148869,0.878546,0.028024]');
INSERT INTO vector_index_test VALUES(5, '[0.334970,0.857377,0.886132]');
INSERT INTO vector_index_test VALUES(6, '[0.117582,0.302352,0.471198]');
INSERT INTO vector_index_test VALUES(7, '[0.551185,0.231134,0.075354]');
INSERT INTO vector_index_test VALUES(8, '[0.185221,0.315131,0.558301]');
INSERT INTO vector_index_test VALUES(9, '[0.928764,0.254038,0.272721]');
```

Trigger an update.

```sql
-- Trigger an incremental refresh.
call dbms_vector.refresh_index('idx1', 'vector_index_test', 'c2', 1, 'FAST');
-- Trigger a complete refresh.
call dbms_vector.rebuild_index('idx1','t1','c2');
```
