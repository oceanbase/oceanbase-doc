# Create a vector index

This topic describes how to create, query, maintain, and drop a vector index in OceanBase Database.

The following points provide specific information about vector indexes in OceanBase Database:

* HNSW indexes are supported. The maximum dimension of an indexed column cannot exceed 4,096. HNSW indexes are memory-based indexes that can be fully loaded into memory. They support DML operations and real-time queries.

* HNSW_SQ indexes are supported. HNSW_SQ indexes offer similar construction speed, query performance, and recall rate as HNSW indexes, but they use 1/2 to 1/3 of the memory. They are suitable for scenarios that require high performance and recall rate.

* (Experimental) IVF indexes are supported. Unlike HNSW and HNSW_SQ indexes, IVF indexes are created based on database tables and do not consume permanent memory. They are suitable for scenarios with high data volume, where performance is not a major concern, and costs need to be controlled.

* L2, inner product (IP), and cosine distance can be used as the index distance algorithm.

* Vector queries with filters are supported. The filter can be a scalar condition or a spatial relationship, such as ST_Intersects. Multi-valued indexes, full-text indexes, or global indexes cannot be used as pre-filters.

* You can create vector indexes and full-text indexes on the same table.

* For more information about DDL operations on vector indexes, see [Offline DDL](../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/700.ddl-function-of-mysql-mode/150.online-and-offline-ddl-list-of-mysql-mode.md).

## Prerequisites

Before you use vector indexes with HNSW or HNSW_SQ, you must enable the vector feature by setting [ob_vector_memory_limit_percentage](../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/6150.ob_vector_memory_limit_percentage.md). However, you do not need to manually set this parameter to enable the vector feature for IVF, IVF_SQ, or IVF_PQ indexes, because these indexes do not need to be resident in memory.

```sql
ALTER SYSTEM SET ob_vector_memory_limit_percentage = 30;
```

## Overview

Vector index queries are approximate nearest neighbor searches, and do not guarantee 100% accuracy of the results. The accuracy of vector index queries is measured by recall. For example, if 9 out of 10 nearest neighbors can be correctly returned in stable manner, the recall is 90%. The following table describes recall.

* Recall is affected by the construction parameters and query parameters.

* Index query parameters are specified when the index is created, and cannot be modified. However, you can set session variables to specify the parameters for different index types. For `HNSW` and `HNSW_SQ` indexes, specify the `ob_hnsw_ef_search` variable. For `IVF`, `IVF_SQ`, and `IVF_PQ` indexes, specify the `ob_ivf_nprobes` variable. If you set a session variable, its value takes precedence. For more information, see [ob_hnsw_ef_search](../700.reference/800.configuration-items-and-system-variables/200.system-variable/400.session-system-variable/550.ob_hnsw_ef_search.md) and [ob_ivf_nprobes](../700.reference/800.configuration-items-and-system-variables/200.system-variable/400.session-system-variable/560.ob_ivf_nprobes.md).

The syntax for vector index queries is as follows:

```sql
SELECT ... FROM $table_name ORDER BY $distance_function($column_name, $vector_expr) [APPROXIMATE|APPROX] LIMIT $num (OFFSET $num);
```

The following table describes the syntax.

* Query syntax requirements:

  * The `APPROXIMATE` or `APPROX` keyword must be specified to select the vector index path.
  * The `ORDER BY` and `LIMIT` clauses must be included.
  * The `ORDER BY` clause supports only a single vector condition.
  * The value of `LIMIT + OFFSET` must be greater than 0 and no more than 16,384.

* Distance function usage rules:

  * If the `inner_product`, `negative_inner_product`, or `L2` distance function is called without the `APPROXIMATE` or `APPROX` keyword, the query plan does not select the vector index path, but does not report an error either.
  * If the `APPROXIMATE` or `APPROX` keyword is specified, and the distance function does not match the vector index algorithm, the query plan does not select the vector index path, but does not report an error either.
  * If the `APPROXIMATE` or `APPROX` keyword is specified, and the expression is `inner_product`, the query plan does not select the vector index path.
  * If the `APPROXIMATE` or `APPROX` keyword is specified, and the expression is `negative_inner_product` or `L2`, the expression matches the vector index algorithm, and the query plan selects the vector index path.

## Examples of index creation, query, and deletion

### Considerations

OceanBase vector indexes can be created when a table is created or at a later time. When you create an index, take note of the following considerations:

* After a vector index is created, you cannot modify it by using any parameters.

* You must add the `VECTOR` keyword when you create a vector index.

* The parameters and descriptions of a later-created index are the same as those when the index is created during table creation.

* If a large amount of data is to be imported, we recommend that you write the data first and then create an index to obtain the best query performance.

* We recommend that you create HNSW_SQ indexes, IVF indexes, IVF_SQ indexes, and IVF_PQ indexes after data is written and rebuild the indexes after a large amount of incremental data is written. Specific instructions on how to create each index are provided in the following examples.

### Create indexes when creating tables

#### HNSW_SQ index example

```sql
CREATE TABLE hgraph_vecindex_suite_table_test (c1 INT AUTO_INCREMENT, c2 VECTOR(3), PRIMARY KEY(c1), VECTOR INDEX idx1(c2) WITH (distance=l2, type=hnsw_sq, lib=vsag));
```

The following table describes the parameters of the HNSW and HNSW_SQ indexes.

| Parameter | Default value | Value range | Required | Description | Remarks |
|------|--------|----------|----------|------|------|
| distance |  | l2/inner_product/cosine | Yes | The type of vector distance function. | l2 indicates the Euclidean distance, inner_product indicates the inner product distance, and cosine indicates the cosine distance. |
| type |  | hnsw | Yes | The type of the index. | At present, only `hnsw` and `hnsw_sq8` are supported. |
| lib | vsag | vsag | No | The type of the vector index library. | At present, only the VSAG vector library is supported. |
| m | 16 | [5,64] | No | The maximum number of neighbors for each node in an HNSW index. | The value indicates the number of neighbors. The larger the value, the slower the index is constructed and the better the query performance is. |
| ef_construction | 200 | [5,1000] | No | The candidate set size during HNSW index construction. | The value indicates the size of the candidate set. The larger the value, the slower the index is constructed and the better the index quality is. The value of this parameter must be greater than that of the `m` parameter. |
| ef_search | 64 | [1,1000] | No | The candidate set size during HNSW index search. | The value indicates the size of the candidate set. The larger the value, the slower the query is and the higher the recall rate is. |

```sql
DROP INDEX vec_idx1 ON vec_table;
```

Query the dropped index.

```sql

```

Rebuild a vector index.

```sql
CALL dbms_vector.rebuild_index('vec_idx1','vec_table','c2');
```

## Index maintenance

If too much incremental data is generated, the query performance will decrease. To reduce the volume of incremental data tables, OceanBase Database introduces the `DBMS_VECTOR` package for maintaining vector indexes.

### Incremental refresh

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>Incremental refresh is not supported for IVF, IVF_SQ, and IVF_PQ indexes.</p>
</main>

If a large amount of data is written after the index is created, we recommend that you use incremental refresh.

The syntax is as follows:

```shell
  PROCEDURE refresh_index(
    IN     idx_name               VARCHAR(65535),                 ---- The name of the index.
    IN     table_name             VARCHAR(65535),                 ---- The name of the table.
    IN     idx_vector_col         VARCHAR(65535) DEFAULT NULL,    ---- The name of the vector column.
    IN     refresh_threshold      INT DEFAULT 10000,              ---- The threshold of incremental data.
    IN     refresh_type           VARCHAR(65535) DEFAULT NULL);   ---- The refresh type. Value: FAST.
```

Incremental refresh is checked every 15 minutes. If more than 10,000 pieces of incremental data are generated, incremental refresh is automatically triggered.

### Full refresh

If a large amount of data is updated or deleted after the index is created, we recommend that you use full refresh.

The syntax is as follows:

```shell
  PROCEDURE rebuild_index(
    IN     idx_name                VARCHAR(65535),                    ---- The name of the index.
    IN     table_name              VARCHAR(65535),                    ---- The name of the table.
    IN     idx_vector_col          VARCHAR(65535) DEFAULT NULL,       ---- The name of the vector column.
    IN     delta_rate_threshold    FLOAT DEFAULT 0.2,                 ---- The threshold of incremental data.
    IN     idx_organization        VARCHAR(65535) DEFAULT NULL,       ---- The index type.
    IN     idx_distance_metrics    VARCHAR(65535) DEFAULT 'EUCLIDEAN',---- The distance type.
    IN     idx_parameters          LONGTEXT DEFAULT NULL,             ---- The index parameters.
    IN     idx_parallel_creation   INT DEFAULT 1);                    ---- The parallelism of index creation. Reserved. Supported only in syntax.
```

Full refresh is checked every 24 hours. If the amount of new data exceeds 20% of the original data, full refresh is automatically triggered. Full refresh clears the original index and rebuilds a new index in the background, which is time-consuming.
