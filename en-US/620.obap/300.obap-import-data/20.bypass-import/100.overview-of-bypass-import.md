# Overview

OceanBase Database allows you to insert data into a database by using direct load. In other words, OceanBase Database allows you to directly write data to data files. Direct load can bypass the SQL layer and directly allocate space and insert data into data files, thereby improving the data import efficiency.

Traditional data import methods in OceanBase Database, such as `LOAD DATA`, OBLOADER, and OMS, rely on `INSERT` statements and involve the following process:

* SQL parsing -> transaction processing -> MemTable writing -> minor compaction and major compaction -> SSTable.
* Bottlenecks:

  * High consumption of CPU and memory resources.
  * Performance degradation when importing large amounts of data.

OceanBase Database uses direct load technology to bypass the intermediate steps and directly write data to the SSTable. This reduces resource consumption (CPU and memory usage) and supports efficient full or incremental data import.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>It is not recommended to perform upgrades during a direct load task. Otherwise, the direct load task may fail. </p>
</main>

## Technical architecture

![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.4.0/620.obap/300.obap-import-data/1.%E5%AF%BC%E5%85%A5%E8%B7%AF%E5%BE%84.png)

* **Traditional import path (blue path):**

  Client -> SQL parsing -> Transaction processing -> MemTable -> Minor/Major compaction -> SSTable

  Disadvantages: The path is long, resource consumption is high, and write speed is limited.

* **Direct load path (green path):**

  Client -> Type conversion -> Primary key sorting (optional) -> Direct write to Major SSTable (full) or Mini SSTable (incremental)

  Advantages:

  * Skips intermediate modules such as SQL parsing, transactions, and MemTable, reducing resource consumption.
  * Directly writes data to the underlying storage, avoiding the overhead of multiple major compactions.

### Core mechanisms of direct load

* Skipping intermediate layers: Bypasses SQL parsing, transactions, and MemTable, directly writing to the SSTable.
* Type conversion and sorting:

  * Data type conversion (such as converting CSV data to OceanBase table structure).
  * Primary key sorting (required for full import to ensure the order of the Major SSTable).

## Storage layer architecture and direct load process

### Storage layer hierarchy

![2](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.4.0/620.obap/300.obap-import-data/2.%E5%AD%98%E5%82%A8%E5%B1%82%E5%88%86%E5%B1%82%E7%BB%93%E6%9E%84.png)

The LSM-Tree-based storage layer of OceanBase Database consists of three levels:

1. MemTable: a row-based structure in memory that supports high-concurrency writes.
2. Mini SSTable: a row-based structure on disk generated by the minor compaction of MemTable.
3. Major SSTable: a column-based structure generated by daily major compactions, offering the best query performance.

## Feature overview

OceanBase Database supports two types of direct load: full direct load and incremental direct load.

When you use the `LOAD DATA`, `INSERT INTO SELECT`, or `CREATE TABLE AS SELECT` statement to import data, you can specify the direct load mode by adding a hint to the statement or by setting the global parameter [default_load_mode](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2050.default_load_mode.md).

* **Full direct load**

  * Full direct load is used to directly write the complete dataset to the database's data files at once. This method bypasses the SQL layer interface, directly allocating space and inserting data into the data files, thereby enhancing the efficiency of data import.
  * Full direct load is typically used for initializing the database, data migration, or quickly loading a large amount of data when needed.

* **Incremental direct load**

  * Incremental direct load is used to directly write the new data to the database's data files without using the SQL interface, even if there is a large amount of existing data. This method bypasses the SQL layer data processing process, directly writing the new data to the data files, thereby improving the write efficiency.
  * Incremental direct load is typically used in high-throughput data write scenarios, such as large-scale real-time data collection and log writing.

| Dimension | Full load | Incremental load |

| Import process | <ol><li>Data is converted and sorted by primary key (if the table has a primary key). </li><li>Directly written to the Major SSTable (columnar format). </li><li>Does not reuse existing macroblocks and processes data row by row to avoid conflicts with existing data. </li></ol>| <ol><li>Data is written to the Mini SSTable (row-based format). </li><li>Depends on daily major compaction to convert the Mini SSTable into a columnar Major SSTable. </li></ol>|
| Write location | Major SSTable (columnar) | Mini SSTable (row-based) |
| Performance characteristics | Data is processed row by row and rewritten to the Major SSTable, with higher overhead as the data volume increases. | Lock mechanism | Table lock (the entire table is unavailable) | Partition lock (only the target partition is locked) |
| Query performance | Columnar tables have a columnar structure, and row-based tables have a row-based structure, offering better query performance. | Both columnar and row-based tables have a row-based structure, resulting in poor query performance. |

## Scenarios

The direct load feature can be applied in the following scenarios:

* Data migration and synchronization. For data migration and synchronization, a large amount of data in various formats needs to be migrated from different data sources to OceanBase Database. The traditional SQL interface may not meet the timeliness requirements.

* Traditional ETL. After data is extracted and transformed in the source, a large amount of data needs to be loaded to the target within a short time. The direct load technology can improve the import performance. During the data loading process, the direct load technology can also enhance the efficiency.

* Loading data from text files or other data sources to OceanBase Database. The direct load technology can also improve the data loading efficiency.
