# OceanBase routing strategy configuration

## Core scenarios and solutions

### Scenario 1: TP and AP can be distinguished (recommended for read/write separation)

**Scenario description**: The business can clearly distinguish between online transaction processing (OLTP, such as order submission) and analytics processing (OLAP, such as user behavior statistics). If the OLAP analysis can tolerate a certain degree of eventual consistency, the resources need to be isolated through routing strategies.

**Solution**:

+ **Read/write separation configuration**:

    - **Implementation method**:
        * Route OLTP requests to the **leader replica** to ensure transaction consistency and low latency.
        * Route OLAP requests to the columnar storage replica to ensure that OLAP queries are executed through columnar storage, which can accelerate aggregate queries.

 For more information, see [OceanBase read/write separation configuration](../700.reference/1200.database-proxy/700.route-management/400.odp-routing-policy/100.read-write-splitting.md) and [Use columnar storage replicas](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000003378476).

+ **Secondary priority read strategy**:

    - **Implementation method**: OLAP queries prioritize reading from the follower replica, and the leader replica only handles OLTP requests.

For more information, see [Secondary priority read configuration](../700.reference/1200.database-proxy/700.route-management/400.odp-routing-policy/200.secondary-priority-read.md).

#### Scenario 2: TP and AP cannot be distinguished

**Scenario description**: OLAP analysis requires strong consistency, or it is difficult to separate OLTP and OLAP business.

**Solution**:

+ **Implementation method**: Route all requests to the leader replica (Leader), for example, by configuring the following parameter:

```sql
-- Disable weak consistency reads
SET GLOBAL OB_READ_CONSISTENCY='STRONG';
```

<main id="notice" >
<h4>Notice</h4>
<p>OceanBase Cloud and the OceanBase Database kernel are different. In OceanBase Cloud, the primary address is a dedicated concept. All requests are routed with strong consistency by default. However, OLAP queries may consume resources on the leader replica. You need to enable resource group isolation through the OceanBase Cloud console. For more information, see <a href="https://www.oceanbase.com/docs/common-oceanbase-cloud-1000000001018073">Configure the primary address in OceanBase Cloud</a>.</p>

## Other routing strategies

| **Strategy type** | **Applicable scenario** |
| --- | --- |
| **LDC routing** | Deployments across regions, with requests routed to the nearest replica |
| **Weighted routing** | Dynamically distribute requests based on node load |
| **Random routing** | Evenly distribute read requests across all available replicas |

For more information, see [ODP routing best practices](https://www.oceanbase.com/docs/common-best-practices-1000000001591716)
