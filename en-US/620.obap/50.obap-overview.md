# Overview of OceanBase AP

## What is OceanBase AP

OceanBase is an enterprise-level native distributed database independently developed. It runs on general-purpose hardware and offers financial-grade high availability. OceanBase is the first to set the "five IDCs in three regions" standard for city-level automated, lossless disaster recovery. It has broken multiple TPC-C benchmarks and achieves a single cluster of 1,500 nodes. OceanBase is cloud-native, strongly consistent, and highly compatible with Oracle and MySQL. In the V4.3.x version, OceanBase enhances the analytics processing (AP) capability. In one system, you can run both online transaction processing (TP) and real-time analytics (AP). This version offers a unified row-store and column-store engine, a vectorized engine, and a cost model based on the column-based storage path. The column-based engine released in this version marks the milestone of OceanBase's full real-time analytics capability.

## Core features

* **Unified row-column integrated storage engine**

  You can flexibly define row-stores, column-stores, and hybrid row-column stores based on different load types. The encoding compression, skipindexing, and query pushdown capabilities are enhanced to achieve better query performance and higher compression ratios.

* **Vectorized execution engine**

  The vectorized engine is upgraded to support columnar data formats and optimized to achieve higher query performance.

* **Multi-mode support**

  OceanBase DB supports multiple data formats and technologies, including Btree indexes, JSON multivalue indexes, full-text indexes, and vector indexes.

* **Materialized view**

  OceanBase DB supports materialized views with SQL rewriting, which accelerates large-scale queries.

* **Data import**

  OceanBase DB supports the import of data in CSV, Parquet, and ORC formats. It integrates with object storage services (OSS), Hadoop Distributed File System (HDFS), Simple Storage Service (S3), and Object Data Processing Service (ODPS) and accesses data in the ODPS catalog.

* **Decoupling of storage and computing**

  OceanBase DB separates storage and computing and supports horizontal and vertical scaling of computing nodes, data storage, and log services. You can store hot data in local disks to improve query performance and store cold data in object storage services to reduce storage costs.

## Application scenarios

#### Scenario 1: HTAP hybrid loads

* A unified architecture: one engine and one set of data support transaction and analysis. OceanBase DB supports hybrid row and column storage and column storage replicas to meet different requirements.
* Low storage cost: OceanBase DB reduces the storage costs by 70%–90% based on the LSM-Tree and advanced encoding compression technologies.
* Support for high concurrent computing: The peer architecture of OceanBase DB supports parallel computing. OceanBase DB supports PB-level storage and ensures that your business data is stored reliably.
* Resource isolation: you can use resource isolation and user group technologies to achieve resource isolation among tasks of multiple users and applications.

#### Scenario 2: Real-time analytics

* Efficient write: data can be written to the system in real time based on the LSM-Tree architecture. Baseline data is stored in columnar storage and incremental data is stored in row-stores. Periodic and adaptive major compactions generate new column-based baselines. Data is immediately available for queries after written to the system, ensuring its real-time availability.
* High accuracy and strong consistency: Multi-Paxos protocol ensures data consistency. Multi-Version Concurrency Control (MVCC) ensures consistent transaction data read and nonblocking read and write operations. You can read data in a strong or weak consistency mode. You can also ensure atomicity and durability by using the Write-Ahead Logging (WAL) mechanism.
* High-performance computing: OceanBase DB uses columnar storage, query pushdown, and processing of compressed data to support high-performance data queries. Optimizer query rewriting and plan selection capabilities of OceanBase DB support high performance for query execution by using the vectorized and parallel engines.
* High availability: OceanBase DB inherits the high availability capability of the TP architecture, with RPO=0 and RTO <8s. You can deploy OceanBase DB to a single IDC or across three regions. OceanBase Cloud supports a single-replica architecture with shared storage and independent log services.
* Smooth horizontal and vertical scaling: You can scale out OceanBase DB without interrupting services. Data redistribution is implemented automatically when OceanBase DB is scaled out or in.
* Full support for multiple data formats: OceanBase DB supports Btree indexes, JSON multivalue indexes, full-text indexes, and vector indexes.
* Decoupling of storage and computing: Multiple computing nodes can access the same data. Local persistent caching and object storage ensure high performance and low costs.

#### Scenario 3: PL/SQL batch processing

* OceanBase DB supports massive data processing. OceanBase DB provides high performance in batch processing. The columnar storage engine of OceanBase DB is designed for analytics and provides higher compression ratios and less I/O load. The vectorized engine processes an entire batch of data (rather than one row at a time) in the cache. This significantly improves the cache hit rate and computing efficiency. For typical batch processing tasks, OceanBase DB provides 10x higher performance. This makes it possible for you to shorten or eliminate the batch processing window and perform real-time analytics.
* OceanBase DB is highly compatible with Oracle. OceanBase DB not only supports common SQL statements and data types, but also supports PL/SQL stored procedures. This way, you can almost unchangedly migrate PL/SQL stored procedures from Oracle to OceanBase DB. Application layer codes do not need to be modified. This significantly reduces the risks, costs, and cycles of system upgrades. This makes it possible for you to upgrade your legacy system.
* OceanBase DB has an integrated architecture. In the past, you need to maintain an online transaction processing (OLTP) database and a data warehouse and big data platform in isolation. The two systems require ETL/CDC to synchronize data. The system architecture is complex and the cost is high. With an integrated architecture, OceanBase DB supports online transaction and batch processing on a single system. You can isolate resources for transaction and analysis to avoid resource competition. This simplifies the technical stack, reduces the operation and maintenance complexity, avoids redundant data storage and cross-system synchronization, and reduces the total cost of ownership (TCO) of your enterprise.
