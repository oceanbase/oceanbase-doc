# Overview of OceanBase AP

## What is OceanBase AP?

OceanBase Database is a fully self-developed, enterprise-grade, native distributed database that achieves financial-grade high availability on standard hardware. It sets a new standard for automatic, lossless disaster recovery across five IDCs in three regions, and has set a new world record in the TPC-C benchmark. With over 1,500 nodes in a single cluster, it offers cloud-native capabilities, strong consistency, and high compatibility with Oracle and MySQL. In the V4.3.x version, OceanBase Database has been optimized for analytical processing (AP) capabilities, supporting both online transaction processing (TP) and real-time analysis (AP) in a single system. This update introduces a unified row-column store engine, a new vectorized engine, and a cost-based model for columnar storage paths. The introduction of a self-developed columnar store engine marks a milestone in achieving complete real-time analysis capabilities.

## Core features

* **Unified row-column store engine:**

  Flexibly define row-store, column-store, or hybrid row-column store tables based on workload types. Enhance encoding compression, skip-index, and query pushdown capabilities to improve query performance and compression ratios.

* **Vectorized execution engine:**

  Upgrade the vectorized engine with a more efficient columnar data description format. Optimize operators, expressions, and storage vectorization based on this new format to significantly boost query performance.

* **Multi-model integration:**

  Fully support various multi-model types, including B-tree indexes, JSON multi-value indexes, full-text indexes, and vector indexes.

* **Materialized views:**

  Support near real-time and real-time materialized views, as well as SQL automatic rewriting, to accelerate large-scale queries.

* **Data import:**

  Enhance external table capabilities to support common data formats like CSV, Parquet, and ORC. Compatibility with storage systems like S3, OSS, HDFS, and ODPS is ensured, and ODPS Catalog is integrated.

* **Compute-storage separation:**

  Support cold-warm data tiering, with full data stored in object storage to reduce costs and hot data cached in local disks to improve query performance. Compute nodes, data storage, and log services can be independently scaled to ensure high availability and cost efficiency.

## Application scenarios

#### Scenario 1: HTAP hybrid workload

* **Unified, minimalist architecture:** A single engine and dataset support both transactional and analytical workloads. Choose between hybrid row-column or column-store deployment based on business needs.
* **Cost-effective, massive storage:** Use LSM-Tree and advanced compression encoding to reduce storage costs by 70-90% compared to traditional solutions.
* **High-concurrency computing:** OceanBase's peer-to-peer architecture supports parallel computing across multiple nodes, with PB-level capacity for stable, scalable storage.
* **Multi-scenario isolation:** Isolate resources for different scenarios and users using underlying resource isolation and user resource groups.

#### Scenario 2: Real-time data analysis

* **Real-time data updates:** Use LSM-Tree for efficient real-time writes, storing incremental data in row-store and baseline data in column-store. Regular or adaptive major compactions generate new columnar baseline data. Data is immediately queryable after write, ensuring real-time access.
* **High accuracy and strong consistency:** Use Multi-Paxos for multi-replica data consistency. MVCC supports non-blocking reads and writes, ensuring transactional consistency. Support strong reads from primary replicas and weak reads from other replicas. Use WAL for data persistence and atomicity.
* **High-performance computing:** Use columnar storage, query pushdown, and compressed data processing for high-performance queries. Optimize with query rewriting, rule-based/ cost-based plan selection, and parallel/vectorized execution engines. Materialized views further support large-scale query analysis.
* **High availability:** Inherit TP high availability with RPO=0 and RTO<8s. Support flexible deployment from single IDC to five IDCs across three regions. Cloud databases support single-replica mode with shared storage and independent log service for cost-effective high availability.
* **Smooth scaling:** Scale horizontally or vertically without service interruption. Data dynamic balancing ensures even distribution of data and workload during scaling.
* **Multi-model integration:** Fully support various multi-model types, including B-tree indexes, JSON multi-value indexes, full-text indexes, and vector indexes.
* **Compute-storage separation:** Allow multiple compute nodes to access the same storage data. Use local persistent cache and object storage for high-performance, cost-effective compute-storage separation.

#### Scenario 3: PL/SQL batch processing

* **Extreme performance boost:** OceanBase's columnar store engine is designed for analytics, with higher compression ratios and reduced I/O. The vectorized engine allows CPU to process batches of data in memory, significantly improving cache hit rate and computational efficiency. Batch processing tasks can achieve 10x or higher performance gains, shortening business batch windows and enabling near real-time analysis.
* **Seamless, risk-free migration:** OceanBase is highly compatible with Oracle, supporting common SQL syntax, data types, and PL/SQL stored procedures. Customers can migrate Oracle stored procedures with minimal changes to OceanBase. Application code remains unchanged, minimizing migration risks, costs, and time.
* **Cost-effective, efficient architecture:** Traditional architectures require separate OLTP databases and data warehouses/big data platforms, with complex ETL/CDC synchronization. OceanBase's integrated architecture supports both online transactions and batch processing in a single system. Built-in resource isolation ensures analytical tasks on columnar stores don't conflict with transactional tasks on row-stores. This simplifies the technology stack, reduces O&M complexity, avoids data redundancy, and lowers total cost of ownership (TCO).
