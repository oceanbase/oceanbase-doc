# Data processing in OceanBase Database

Data processing refers to the process of performing a series of processing and conversion operations on raw data to make it more suitable for specific analysis, applications, or presentations. It typically includes operations such as data cleaning, data transformation, data integration, data aggregation, data enrichment, data filtering, and data annotation. The goal is to convert raw, unstructured, and disorganized data into structured, high-quality, and easily usable datasets. This enables more efficient and high-performance query and analysis capabilities.

The execution of an efficient data processing task relies on several factors, including high-performance data reading, a rich set of functions, efficient query analysis, and high-performance data writing capabilities. Additionally, it depends on features that align with business characteristics.

This topic will focus on the features of OceanBase Database that are beneficial for data processing tasks.

## `INSERT OVERWRITER SELECT` operation

The `INSERT OVERWRITER SELECT` operation is used to insert the results of a query into a target table, overwriting the existing data in the target table. It is primarily used in data cleaning and transformation processes to efficiently batch insert processed data into the database. This operation ensures atomicity, meaning that if any exceptions occur during execution, the entire operation will be rolled back.

### Use cases

+ When you need to batch import data and overwrite the target table, the `INSERT OVERWRITER SELECT` operation provides a convenient method.
+ When you need to clean data and replace the existing data in the target table with new data.
+ When the source table can be an internal or external table.

### Syntax example

```sql
INSERT [/*+PARALLEL(N)*/] OVERWRITE table_name [(list_of_columns)] [PARTITION (partition_name, ...)] select_stmt;
```

### Considerations

+ Use this operation with caution, as it will delete all data from the target table or partition. Ensure that your business has backed up the data to prevent accidental deletion.
+ Ensure that the data returned by the `SELECT` query is in the same format as the target table to avoid data insertion failures.
+ The difference between `INSERT INTO SELECT` and `INSERT OVERWRITE SELECT` is that `INSERT INTO SELECT` does not clear the target table or partition before insertion, and the processed data is incrementally written to the target table.
+ Do not write data to the same table using both the `INSERT OVERWRITE SELECT` operation and real-time write methods (such as `INSERT INTO`, `REPLACE INTO`, `DELETE`, and `UPDATE`). Otherwise, the data written using real-time methods will be discarded.

For more information about the operation, see [Insert data by using the INSERT OVERWRITE SELECT statement in MySQL mode](../../300.develop/100.application-development-of-mysql-mode/400.write-data-of-mysql-mode/100.insert-data-of-mysql-mode-in-develop.md) and [Insert data by using the INSERT OVERWRITE SELECT statement in Oracle mode](../../300.develop/200.application-development-of-oracle-mode/400.write-data-of-oracle-mode/100.insert-data-of-oracle-mode-in-develop.md).

## Submit a job (`Submit Job`)

In OceanBase Database, the job submission feature allows you to submit and execute complex data processing tasks. These tasks can include data batch processing, ETL (extract, transform, load) jobs, or other background data processing operations. When you use `INSERT INTO` or `INSERT OVERWRITE SELECT` to import data, the default execution mode is synchronous. When the data volume is large, the session may need to remain active for a long time. Therefore, for large data volumes, we recommend that you submit data import tasks asynchronously.

### Use cases

+ To periodically execute complex data processing operations, such as batch data import, data cleaning, and report generation.
+ To schedule large-scale data migration or transformation tasks.

### Submit a job example

```sql
-- Submit a job.
SUBMIT JOB INSERT OVERWRITE test
SELECT ex1.c1,t2.c2,sum(ex1.c3)
FROM ex1,t2
WHERE ex1.id = t2.id
GROUP BY ex1.c1,t2,c2;
-- Query the status of an asynchronous task.
SHOW JOB STATUS WHERE job='job_id';
```

A job typically consists of multiple steps, such as data extraction, transformation, and loading, to ensure the automation of the entire data processing process.

## Scheduled jobs

Scheduled jobs are used to periodically execute specified jobs according to a set schedule. By using scheduled jobs, you can automate data processing workflows and reduce the cost of manual maintenance.

### Use cases

+ To periodically clean up expired data, generate reports, and synchronize data.
+ To automatically execute data processing jobs at specific times or during periodic tasks.

### Create a scheduled job example

- **MySQL mode**: Use the `Event Scheduler` command to create a scheduled job.

```sql
-- Create a scheduled job.
CREATE EVENT myevent
    ON SCHEDULE AT '2024-12-26 00:00:00' + INTERVAL 1 DAY
    DO
      INSERT INTO test SELECT * FROM ex_test WHERE date_key = curdate();

-- View the scheduled job.
SELECT * FROM information_schema.events WHERE event_name='myevent';
```

- **Oracle mode**: Use the `DBMS_SCHEDULER` system package to create a scheduled job.

```sql
-- Create a scheduled job.
BEGIN
    DBMS_SCHEDULER.CREATE_JOB(
        job_name         => 'myscheduler',                      -- The name of the job.
        job_type         => 'STORED_PROCEDURE',                 -- The type of the job is stored procedure.
        job_action       => 'data_cleaning',                    -- The stored procedure to be executed by the job.
        number_of_argument => 0,                                -- No parameters are required.
        start_date       => SYSDATE,                            -- The start time of the job.
        repeat_interval  => 'FREQ=DAILY; INTERVAL=1',           -- The job is executed every day.
        end_date         => NULL,                               -- The job will run indefinitely without an end date.
        job_class        => 'DEFAULT_JOB_CLASS',                -- The class of the job is default.
        enabled          => TRUE,                               -- The job is enabled.
        auto_drop        => TRUE,                               -- The job is automatically deleted after it is completed.
        comments         => 'Daily data cleaning and conversion',               -- The comment of the job.
        credential_name  => NULL,                               -- No credentials are required.
        destination_name => NULL,                               -- No destination database is specified.
        max_run_duration => 0                                   -- The default value is 0, which is effective for 30 seconds.
    );
    COMMIT;
END;
/
-- View the scheduled job.
SELECT * FROM DBA_SCHEDULER_JOBS WHERE job_name = 'myscheduler';
SELECT * from DBA_SCHEDULER_JOB_RUN_DETAILS WHERE job_name ='myscheduler';
```
