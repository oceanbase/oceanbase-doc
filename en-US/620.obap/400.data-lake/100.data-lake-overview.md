# Data lake overview

OceanBase supports accessing external data through **external tables** and **external catalogs**, covering file-based data (CSV/Parquet/ORC), Hive/Iceberg lake tables, and data sources such as MaxCompute (ODPS).

You can query and analyze data stored in external systems such as object storage, HDFS, or MaxCompute within OceanBase, and perform federated analysis with internal tables.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>Data lake capabilities are primarily supported in the <strong>MySQL-compatible mode</strong>; Catalog capabilities are currently only supported in MySQL-compatible mode. For specific syntax and version boundaries, refer to the SQL reference documentation under <code>700.reference</code>. For access steps, see the sub-documents in this directory.</p>
</main>

The data lake capabilities currently supported by OceanBase include:

* Access to lake table formats (Hive, Iceberg via External Catalog)
* Access to external file formats (CSV, Parquet, ORC)
* Integration with external catalogs (ODPS Catalog; HMS Catalog)
* Access to external storage (local, OSS, S3, HDFS, etc.)
* Querying, partial writing, and exporting of external data
* Management of external tables and external catalogs

## Data lake access model

When OceanBase accesses external data, it involves the following layers:

* **Storage Layer**: The actual location where the data is stored, such as OSS, S3, HDFS, or a local file system.
* **File Format Layer**: The encoding method of the data files, such as Parquet, ORC, CSV.
* **Lake Table Format Layer**: The organization and metadata management methods of tables, such as Iceberg, Hive.
* **Catalog Layer**: External metadata services, such as HMS, REST, FILESYSTEM (for Iceberg), ODPS Catalog.
* **Access Layer**: Incorporates external data into the OceanBase SQL query system via external tables or External Catalogs.

MaxCompute (ODPS) is an external data warehouse service. It is accessed via **ODPS Catalog** or **ODPS external tables** (`PROPERTIES (TYPE = 'ODPS' ...)`), and does not belong to the same lake table format category as Iceberg/Hive.

## Supported data lake formats

### Lake table format

| Format | Description | Access Method | Description |
| --- | --- | --- | --- |
| Apache Iceberg | Open Source Table Format | External Catalog (HMS, REST, FILESYSTEM, etc.) | Read-only queries are the primary operation. Write capability varies by catalog type and version. For details, see [Load an Iceberg table via a catalog](200.data-lake-integration/200.load-iceberg-via-catalog.md). |
| Apache Hive | Hadoop ecosystem table format | HMS Catalog(V4.4.1+) | Read-only queries; for more information, see [Load a Hive table via Catalog](200.data-lake-integration/100.hive/100.load-hive-via-catalog.md). |

### External data sources

| Data Source | Description | Access Method |
| --- | --- | --- |
| MaxCompute(ODPS) | Alibaba Cloud Big Data Computing Service | [ODPS Catalog](200.data-lake-integration/300.odps/100.odps-catalog.md) (Project-level, read-only) or [ODPS external table](200.data-lake-integration/300.odps/200.odps-external-table.md) (single table, supports `INSERT`) |

### File format

| Format | Description | Typical Scenarios |
| --- | --- | --- |
| Apache Parquet | Columnar storage | File external tables, HMS/Hive tables, Iceberg underlying files, and `SELECT INTO OUTFILE` |
| Apache ORC | Columnar storage | File external tables, Hive tables, and `SELECT INTO OUTFILE` |
| CSV | Text format | File external tables, `SELECT INTO OUTFILE`, `LOAD DATA`, and URL external tables (`FILES()`) |

File formats and lake table formats belong to different layers. For example, Iceberg tables typically use Parquet for data storage at the underlying layer.

## Supported storage types

### Object storage and distributed storage

| Storage Type | URI prefix | Description |
| --- | --- | --- |
| Alibaba Cloud OSS | `oss://` | File external tables, URL external tables, `SELECT INTO OUTFILE`, and so on |
| AWS S3 | `s3://` | Same as above |
| HDFS | `hdfs://` | V4.3.5 BP1 or later; requires a Java SDK environment |
| Local File System | `file://` or a path | Subject to the `secure_file_priv` limit |

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>Azure Blob (<code>azblob://</code>) is currently used in scenarios such as backup and archiving. Whether the external table <code>LOCATION</code> supports it depends on the <a href="../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2200.create-external-table-of-mysql-mode.md">CREATE EXTERNAL TABLE</a>.</p>
</main>

### Location and access credentials

When creating an external table or location, you need to configure access credentials (such as `access_id` and `access_key`). These can be configured in advance via URL parameters or using `CREATE LOCATION` (for syntax, refer to [CREATE LOCATION](../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2230.create-location-of-mysql-mode-in-sql.md)).

## Supported data operations

### Read operations (SELECT)

| Action | Applicability | Description |
| --- | --- | --- |
| `SELECT` query | File external tables, URL external tables, and External Catalog tables | For more information about the supported types, see the corresponding subdocuments. |
| Partition Pruning | Hive / Iceberg (via Catalog) | Partition columns specified in the `WHERE` clause reduce the scan scope. |
| Time Travel | Iceberg | Supported scenarios |
| `JOIN` | The preceding external objects and internal tables | Supports federated queries |

### Write operations and exports

| Action | Applicability | Description |
| --- | --- | --- |
| `INSERT INTO` | [ODPS external table](200.data-lake-integration/300.odps/200.odps-external-table.md) | Write data to a remote table by using the MaxCompute API. File external tables are read-only. |
| `INSERT INTO` | Iceberg table | Some catalog types and versions may be supported. In HMS Catalog, they are usually read-only. For more information, see [Load an Iceberg table via a catalog](200.data-lake-integration/200.load-iceberg-via-catalog.md). |
| `SELECT INTO OUTFILE` | CSV, Parquet, and ORC | Export to object storage or a local file |
| `CREATE TABLE AS SELECT` | — | Create **internal tables** from external data |

### External table and catalog management

| Action | Description |
| --- | --- |
| `CREATE EXTERNAL TABLE` | Create a file external table or an ODPS external table. |
| `CREATE EXTERNAL CATALOG` | Create External Directory |
| `ALTER EXTERNAL TABLE` | Refresh the file list, manage partitions, and so on. |
| `DROP TABLE` / `DROP CATALOG` | Drop External Table or Catalog |
| `AUTO_REFRESH` | Supports `OFF`, `IMMEDIATE`, and `INTERVAL` |

### Iceberg feature support

The following capabilities apply to Iceberg tables accessed via External Catalog. The specific supported scope varies by Catalog type and version:

| Features | Supported operations |
| --- | --- |
| Partitioning and Partition Transform | Supports reading partitions transformed by operators such as `year()`, `bucket()`, and `truncate()` |
| Delete File | Features such as Position Delete and Equality Delete are subject to the current version. |
| Data File Format | Primarily use Parquet |
| Metadata | Resolution of `metadata.json`, `manifest`, `manifest-list`, and so on |

## Capability boundaries

### Known limitations

| Limitations | Description |
| --- | --- |
| FILE FOREIGN TABLE | Read-only, no support for DML, constraints, or indexes |
| External Catalog | Objects under a Catalog are read-only. `INSERT`, `DROP TABLE`, and similar operations are not supported (to write to ODPS, use an ODPS external table). |
| `INSERT OVERWRITE` | Iceberg tables are not supported. |
| Iceberg partition write | Writing to partitions of an Iceberg table by using `INSERT INTO` is subject to limits. |
| COS external table | Creation is no longer supported. |
| Catalog Mode | Currently only MySQL-compatible mode |
