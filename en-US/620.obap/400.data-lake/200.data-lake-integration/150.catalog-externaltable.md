# Catalog and external tables

## Feature overview

OceanBase supports accessing external data through **Catalogs** and **External Tables**. Both provide external data access capabilities, but differ in metadata management methods and application scenarios:

- **Catalog**: Connects to an external metadata service (such as Hive Metastore or MaxCompute Project) to automatically synchronize database and table structures. Suitable for structured data sources with existing metadata centers.
- **External Table**: Manually defines the table structure and access path within OceanBase. Suitable for scenarios such as file paths, temporary data, or single-table mapping.

OceanBase has supported ODPS Catalog since V4.3.5 BP2 and HMS Catalog since V4.4.1. Through Catalogs, you can query Hive tables, Iceberg tables managed by HMS, and tables in MaxCompute (ODPS). During queries, you can perform federated analysis with internal tables in the internal Catalog.

<main id="notice" type='notice'>
  <h4>Note</h4>
  <p>Currently, only the MySQL-compatible mode of OceanBase supports Catalog capabilities.</p>
</main>

## Deployment and environment dependencies

| Project | Description |
| ------ | ------ |
| Cross-IDC Deployment | If HMS and OBServer are deployed across data centers, metadata retrieval latency can reach seconds, affecting query performance. It is recommended to deploy HMS and OBServer within the same low-latency network. |
| HDFS Storage | When the underlying storage is HDFS, you must deploy the Java runtime environment (JDK 8/11) on the OBServer node and enable Java support (`ob_enable_java_env = true`). For more information, see [Deploy the OceanBase Java SDK environment](../../../400.deploy/300.deploy-oceanbase-enterprise-edition/500.deploy-the-ob-java-sdk-environment.md). |

## Relationship between Catalogs and external tables

When OceanBase accesses external data, the following hierarchy is involved; do not confuse them:

| Level | Description |
| ------ | ------ |
| External storage | Physical location of the data file, such as HDFS, OSS, or S3 |
| Metadata | Information on structures such as databases, tables, and partitions can be defined and maintained by HMS, ODPS, or external OceanBase tables. |
| Access Entry | Catalog or external tables, integrating external data into the SQL query system |

OceanBase provides two external data access modes:

| schema | Metadata Source | Application scenarios | Typical usage |
| ------ | ------------ | ---------- | ---------- |
| **Catalog mode** | Automatic Synchronization by External Metadata Service | Structured data sources with existing metadata centers such as Hive data warehouses and ODPS projects | `SET CATALOG my_hms;`<br>`SELECT * FROM db1.sales;` |
| **Explicit external table** | Manually defined in OceanBase | Non-Catalog Scenarios Such as File Paths, Temporary Probing, and Single-Table API Mapping | `CREATE EXTERNAL TABLE t1 (...) LOCATION = 'oss://...';` |

**Selection guide:**

- Catalogs are suitable for scenarios where the data source is already registered in HMS or MaxCompute. OceanBase reads metadata through Catalogs and then accesses underlying storage or remote tables.
- Explicit external tables are suitable for accessing CSV/Parquet/ORC files by path, or mapping a single ODPS table via the MaxCompute API.
- **Iceberg tables** are accessed through External Catalogs (such as HMS Catalog or REST Catalog) and **do not** belong to the `CREATE EXTERNAL TABLE` access method. For details, see [Load an Iceberg table through Catalog](200.load-iceberg-via-catalog.md).

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p><ul><li>A Catalog is a metadata abstraction of underlying data, not the storage location itself.</li><li>HMS Catalog only supports connecting to Hive Metastore and cannot directly point to any HDFS path. To access files not registered with HMS, use the <code>CREATE EXTERNAL TABLE ... LOCATION</code> method.</li></ul></p>
</main>

## Catalog types

Catalogs are the top-level namespace for database objects, used to organize and isolate metadata from different data sources. OceanBase supports internal Catalogs and external Catalogs:

| Catalog type | Data Source | Supported Table Types | Typical Scenarios |
| -------------- | -------- | ------------ | ---------- |
| Internal Catalog (`internal`) | Local storage of OceanBase Database | OceanBase table | Core business data within the tenant |
| ODPS Catalog | Alibaba Cloud MaxCompute | ODPS Table | Offline data warehouse analytics |
| HMS Catalog | Hive Metastore | Hive tables and Iceberg tables | Hadoop Ecosystem Integration |

### Internal Catalog

Each tenant has one and only one internal Catalog named `internal`, which contains objects created within that tenant using DDL statements such as `CREATE DATABASE` and `CREATE TABLE`. The internal Catalog is logically isolated from external Catalogs; creating, deleting, or renaming the internal Catalog is not supported.

- By default, you can directly use `USE database;` to access it without explicitly specifying the Catalog.
- Supports complete DDL/DML; data is stored in the OceanBase distributed storage engine.

```sql
USE ap_db;
SELECT COUNT(*) FROM user_behavior;

-- Explicitly specify the internal catalog (optional)
SELECT COUNT(*) FROM internal.ap_db.user_behavior;
```

<main id="notice" type='notice'>
  <h4>Note</h4>
  <p>The internal Catalog name is <code>internal</code>, which can usually be omitted.</p>
</main>

## Create and access Catalogs

### Create an External Catalog

The internal Catalog does not require manual creation. For the syntax to create an external Catalog, see [CREATE EXTERNAL CATALOG](../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2150.create-external-catalog-of-mysql-mode.md); descriptions of various parameters are provided in the aforementioned integration documents.

### View a Catalog

```sql
SHOW CATALOGS;
```

### Switch Catalogs and perform cross-Catalog queries

When referencing tables, follow these rules:

- If the session context has not been switched, use the three-part identifier: `catalog_name.database_name.table_name`
- After executing `SET CATALOG` and `USE`, you can use the abbreviated table name.

**Method 1: Three-part identifier (no context switching required)**

```sql
SELECT CURRENT_CATALOG();
SELECT DATABASE();

SELECT * FROM hive_catalog.hive_db.hive_table;

SELECT h.*, o.*
FROM hive_catalog.hive_db.hive_table h
JOIN internal.ap_db.ap_table o ON h.id = o.id;
```

**Method 2: Use the abbreviated table name after switching contexts**

```sql
SET CATALOG hive_catalog;
USE hive_db;

SELECT h.*, o.*
FROM hive_table h
JOIN internal.ap_db.ap_table o ON h.id = o.id;
```

You can also execute `SET CATALOG catalog_name;` separately, or specify it explicitly in the query:

```sql
SELECT * FROM odps_catalog.database_name.table_name;
```

<main id="notice" type='notice'>
  <h4>Note</h4>
  <p><ul><li>If you directly execute <code>SELECT * FROM hive_table;</code> without executing <code>SET CATALOG</code> and <code>USE</code>, the system will search for the table in the current catalog (such as internal) and may return an error.</li><li>Switching contexts only affects subsequent statements, not the connection or transaction status.</li></ul></p>
</main>

For more information about the syntax, see [SET CATALOG](../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/8250.set-catalog-of-mysql-mode.md) and [Query catalogs](../../../700.reference/300.database-object-management/100.manage-object-of-mysql-mode/1000.manage-catalog-of-mysql-mode/300.view-catalog-of-mysql-mode.md).

## Catalog support

This topic describes the capabilities of external catalogs. For more information about creating catalogs, authenticating to catalogs, and configuring locations, see the corresponding integration topics.

### HMS Catalog

| Project | Description |
| ------ | ------ |
| Access mode | Read-only; DML/DDL such as `INSERT`, `UPDATE`, and `DROP TABLE` is not supported |
| Hive table | ORC, Parquet, TextFile, and CSV formats are supported. For complex data types, only the PARQUET format for the ARRAY type is currently supported. |
| Iceberg table | Supports V1 and V2 formats (Parquet is recommended); supports Schema Evolution, Partition Transform, and more. |
| Hive version | Hive versions 1.2.x, 2.3.x, 3.1.x, and 4.x are supported. Iceberg table metadata can be accessed after it is registered in HMS. |

For more information about the ARRAY data type, see [Overview of array data types](../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/100.basic-elements-of-mysql-mode/100.data-type-of-mysql-mode/1200.array-data-type-of-mysql-mode/100.array-data-type-overview-of-mysql-mode.md). For more information about how to authenticate to HMS and HDFS, see [Load Hive tables by using Catalogs](100.hive/100.load-hive-via-catalog.md).

### ODPS Catalog

| Project | Description |
| ------ | ------ |
| Supported operations | Analytical queries such as `SELECT`, `JOIN`, and `GROUP BY` |
| Unsupported operations | Write operations or DDL such as `INSERT`, `UPDATE`, and `DROP TABLE` |
| Query optimization | Supports pruning pushdown under partition pruning and column pruning conditions |

For more information about parameters and API modes, see [ODPS Catalog](300.odps/100.odps-catalog.md).

## Catalog privileges management

Catalog privileges are divided into two levels:

| Level | Scope |
| ------ | ---------- |
| User Level (Global) | All catalogs (corresponding to `*.*` in MySQL-compatible mode) |
| Catalog Level (Object Level) | Specify Catalog |

### Privileges in MySQL-compatible mode

| Permission | Scope | Purpose |
| ------ | ---------- | ------ |
| `CREATE CATALOG` | User Level | Execute `CREATE` / `DROP EXTERNAL CATALOG` statements |
| `USE CATALOG` | User Level or Catalog Level | `SET CATALOG`, `SHOW CATALOGS`, and querying `catalog.db.table` |

**To grant global privileges:**

```sql
GRANT CREATE CATALOG ON *.* TO 'user1';
GRANT USE CATALOG ON *.* TO 'user1' WITH GRANT OPTION;
```

**To grant specific catalog privileges:**

```sql
GRANT SELECT, USE CATALOG ON CATALOG odps_prod TO 'user1' WITH GRANT OPTION;
REVOKE USE CATALOG ON CATALOG odps_prod FROM 'user1';
```

**Additional information:**

1. After you successfully execute the `CREATE EXTERNAL CATALOG` statement, the creator automatically obtains the `USE CATALOG` and `SELECT` privileges on that catalog.
2. Catalog privileges are independent of data access privileges. Taking HMS as an example, the catalog layer connects to Hive Metastore to obtain metadata, and the location layer accesses data files stored in storage systems such as HDFS. You must configure authentication for both layers separately.

**Privilege verification example:**

```sql
GRANT SELECT, USE CATALOG ON CATALOG ca1 TO zhangsan WITH GRANT OPTION;
SHOW GRANTS FOR zhangsan;
```

**Privilege query views:**

- [`information_schema.USER_PRIVILEGES`](../../../700.reference/700.system-views/300.system-view-of-sys-tenant/200.dictionary-view-of-sys-tenant/2700.information_schema-user_privileges-of-sys-tenant.md)
- [`oceanbase.DBA_OB_USERS`](../../../700.reference/700.system-views/300.system-view-of-sys-tenant/200.dictionary-view-of-sys-tenant/24100.o-dba_ob_users-of-sys-tenant.md) / [`CDB_OB_USERS`](../../../700.reference/700.system-views/300.system-view-of-sys-tenant/200.dictionary-view-of-sys-tenant/11900.o-cdb_ob_users-of-sys-tenant.md)

## External tables

An external table stores the table definition and access path in OceanBase Database, while the data remains in external storage (such as object storage, HDFS, or MaxCompute). External tables are typically read-only and do not support constraints or indexes.

Compared with the Catalog mode, explicit external tables are suitable for the following scenarios:

- Accessing data in formats such as CSV, Parquet, or ORC by file path, and the data is not registered with HMS.
- Temporarily exploring external files without needing to pre-build a Catalog.
- Mapping a single ODPS table (not an entire project) through the MaxCompute API.

OceanBase supports the following external table types:

| Type | Description | Documentation |
| ------ | ------ | ------ |
| File external table | Access CSV, Parquet, and ORC files in paths such as OSS, S3, and HDFS. | [File external table](400.file-external-table.md) |
| URL External Table | Directly reads external files through `FILES()` without pre-creating an external table | [URL external table](../300.url-external-table.md) |
| ODPS external table | Map a single ODPS table by using the MaxCompute API | [ODPS external tables](300.odps/200.odps-external-table.md) |

Iceberg tables are not accessed using the `CREATE EXTERNAL TABLE` statement; instead, you should use an External Catalog. For more information, see [Load an Iceberg table through a Catalog](200.load-iceberg-via-catalog.md).
