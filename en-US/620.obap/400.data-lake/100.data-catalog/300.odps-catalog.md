# ODPS catalog

OceanBase Database supports the catalog (data directory) feature starting from V4.3.5 BP2. This feature adds a catalog layer to the traditional `Database → Table` two-level model, forming a `Catalog → Database → Table` three-level architecture.

With the ODPS catalog feature, you can directly query data from tables in Alibaba Cloud MaxCompute (formerly known as ODPS) without manually creating external table mappings. This feature is suitable for accelerating offline data warehouse queries.

- Direct query without ETL: You can directly access tables in MaxCompute and avoid the tedious process of creating external tables.
- Unified metadata: The database and table structures in ODPS projects are automatically synchronized.
- Cross-source JOIN: You can join tables in OceanBase Database with tables in MaxCompute.

## Supported capabilities

- **Read-only queries**: Supports analysis operations such as `SELECT`, `JOIN`, and `GROUP BY`.
- **No write operations**: Prohibits DML/DDL operations such as `INSERT`, `UPDATE`, and `DROP TABLE`.
- **Partition and column pruning**: Automatically pushes down filter conditions to reduce data transmission.

## Limitations

| Limitation | Description |
|--------|------|
| Complex data types | Does not support nested complex types such as `ARRAY<MAP<STRING, BIGINT>>`. |
| Performance dependency | Query speed is affected by the MaxCompute Tunnel quota and network bandwidth. |
| Environment dependency | Requires deployment of the Java SDK (since the MaxCompute SDK is based on Java). |

For more information about the environment dependency, see [Deploy the OceanBase JAVA SDK environment](../../../400.deploy/300.deploy-oceanbase-enterprise-edition/500.deploy-the-ob-java-sdk-environment.md).

## Prerequisites

1. **Permissions**

   * The current user must have the `CREATE CATALOG` permission (MySQL mode) or the `CREATE CATALOG` system permission (Oracle mode).
   * The user must have the `USE CATALOG` permission (which can be granted to a specific catalog or globally) for queries.

2. **Access credentials**

   * The AccessKey ID and secret (or STS token) of MaxCompute must be obtained.
   * The OceanBase cluster must be able to access the MaxCompute endpoint and tunnel endpoint.

3. **Authorization configuration**
   * The RAM user used by OceanBase must be authorized in the MaxCompute project (at least `Read` permission). For more information, see [Overview of MaxCompute Open Storage](https://www.alibabacloud.com/help/en/maxcompute/user-guide/overview-1?spm=a2c63.p38356.help-menu-27797.d_2_3_1_0.4b5a70bfbUDbSC).

## Syntax for creating an ODPS catalog

```sql
CREATE EXTERNAL CATALOG [IF NOT EXISTS] catalog_name
PROPERTIES (
    TYPE = 'ODPS',
    [ACCESSTYPE = 'aliyun' | 'sts' | 'app'],
    ACCESSID = 'your-access-id',
    ACCESSKEY = 'your-access-key',
    [STSTOKEN = 'your-sts-token'],  -- Required only when ACCESSTYPE = 'sts'
    ENDPOINT = 'http://service.cn-hangzhou.maxcompute.aliyun.com/api',
    TUNNEL_ENDPOINT = 'http://dt.cn-hangzhou.maxcompute.aliyun.com',
    PROJECT_NAME = 'your_odps_project',
    [QUOTA_NAME = 'your_quota'],
    [COMPRESSION = 'zlib' | 'zstd' | 'lz4' | 'odps_lz4'],
    API_MODE = {"tunnel_api" | "storage_api"},
    SPLIT = {"byte" | "row"}
    REGION = 'region_name'
);
```

## Parameters

| Parameter | Required | Description |
|------|----------|------|
| TYPE | Yes | Fixed to `'ODPS'` |
| ACCESSTYPE | No | The account type. Default value: `aliyun`. Valid values: `aliyun`, `sts`, and `app`. |
| ACCESSID / ACCESSKEY | Yes | The AccessKey of the RAM user (not the main account AK). |
| STSTOKEN | Conditional | Required only when `ACCESSTYPE = 'sts'`. |
| ENDPOINT | Yes | The endpoint of MaxCompute, including the region. |
| TUNNEL_ENDPOINT | Yes | The tunnel endpoint, used for efficient data retrieval. |
| PROJECT_NAME | Yes | The name of the MaxCompute project (equivalent to a database). |
| QUOTA_NAME | No | The name of the compute resource quota (if applicable). |
| COMPRESSION | No | The data compression format, which must be consistent with that of the ODPS table. If this parameter is not specified, compression is not enabled. |
| API_MODE | Yes | The API mode for accessing ODPS. Valid values: `tunnel_api` and `storage_api`. For more information, see the description of API_MODE below. |
| SPLIT | Yes | Specifies the task splitting method when `storage_api` is used. Valid values: `byte` and `row`. When the data size of each row in a table varies significantly, set this parameter to `byte`. In other cases, set this parameter to `row`. |
| REGION | Yes | The region where MaxCompute is enabled. |

### API_MODE

For OceanBase Database V4.3.5, API_MODE and SPLIT parameters are supported starting from V4.3.5 BP3:

- tunnel_api (default):

  + No special network configuration is required: applicable to all deployment scenarios, without the need for OceanBase Database and MaxCompute to be in the same VPC (Virtual Private Cloud).
  + No additional MaxCompute permissions are required: only the AccessID and AccessKey are needed for authentication, without the need to enable the MaxCompute Storage API.

  + Applicable environments:
    * OceanBase Database and MaxCompute are not deployed in the same VPC.
    * The MaxCompute Storage API is not enabled.
    * The data transmission has low latency requirements.

- storage_api:

  + Network dependency: requires OceanBase Database and MaxCompute to be deployed in the same VPC to achieve low-latency, high-throughput data transmission.
  + Permission dependency: requires enabling the Storage API in MaxCompute and ensuring the AccessKey has the necessary permissions.
  + Quota requirements: when using the storage_api mode, the QUOTA parameter must be set to pay-as-you-go (on-demand) to ensure proper billing and execution of Storage API calls. For more information, see [Overview of MaxCompute Open Storage](https://www.alibabacloud.com/help/en/maxcompute/user-guide/overview-1?spm=a2c63.p38356.help-menu-27797.d_2_3_1_0.4b5a70bfbUDbSC).

  + Applicable environments:
    * OceanBase Database and MaxCompute are in the same VPC.
    * The MaxCompute Storage API is enabled.
    * The data volume is extremely large or real-time requirements are high.

## Example

```sql
CREATE EXTERNAL CATALOG odps_prod
PROPERTIES (
    TYPE = 'ODPS',
    ACCESSID = 'LTAI5tXXXXXX',
    ACCESSKEY = 'xxxxxxxxxxxxxx',
    ENDPOINT = 'http://service.cn-hangzhou.maxcompute.aliyun.com/api',
    TUNNEL_ENDPOINT = 'http://dt.cn-hangzhou.maxcompute.aliyun.com',
    PROJECT_NAME = 'sales_analytics',
    REGION = 'cn-hangzhou'
);
```

**Security recommendations**:
- Use RAM sub-accounts and follow the principle of least privilege.
- Avoid hardcoding plaintext AKs in SQL statements. Instead, inject them using variables or a key management service.

## How to use

### Switch the catalog

```sql
-- Method 1: Switch only the catalog.
SET CATALOG odps_prod;

-- Method 2: Switch both the catalog and database.
USE odps_prod.sales_db;
```

### Query an ODPS table

```sql
-- If the catalog has been switched to odps_prod, you can directly query the table.
SELECT * FROM user_log
WHERE dt = '20250401'
LIMIT 10;

-- Federated query (JOIN with an internal table)
SELECT o.order_id, u.city
FROM internal.test_db.orders o
JOIN users u ON o.user_id = u.id;
```

### Metadata operations

```sql
-- View the table structure.
DESC odps_prod.sales_db.user_log;

-- View the CREATE TABLE statement.
SHOW CREATE TABLE odps_prod.sales_db.user_log;

-- List all catalogs in the current tenant.
SHOW CATALOGS;

-- View the CREATE CATALOG statement.
SHOW CREATE CATALOG odps_prod;
```

### Delete a catalog

```sql
DROP CATALOG IF EXISTS odps_prod;
```
