# Data transfer overview

In OceanBase AP scenarios, **data transmission** encompasses **data migration**, **data import**, **data synchronization**, and **data subscription**: targeting database switchover, batch table loading, continuous write alignment, and change event distribution respectively. The following section summarizes the key selection points based on **business objectives** and provides corresponding documentation links.

## Data migration

Complete **target database setup or replacement** within a defined time point or phase, switch business read and write traffic to OceanBase (or a new tenant), and achieve schema alignment and data convergence.

* **Typical scenarios**: One-time or phased replacement from MySQL/Oracle; OceanBase version upgrade or cluster replacement; migrating TP databases first and then doing AP; requiring only historical snapshots at a certain moment without continuous CDC for a few offline migrations.

* **Related documentation**: [Data Migration Overview](200.data-migration/100.ap-data-migration-overview.md), [Migrate Data Using Tools](200.data-migration/200.migrate-data-with-tools.md), [Data Import Strategies and Best Practices](200.data-migration/500.best-practices-migrating-from-mainstream-databases-to-oceanbase.md), [Best Practices for Migrating Mainstream AP Databases to OceanBase](200.data-migration/500.best-practices-migrating-from-mainstream-databases-to-oceanbase.md).

### Data import

When **importing external data into an internal OceanBase table**, the data source can be local files, object storage, or HDFS, and the import can be performed by using methods such as `LOAD DATA`, external tables, the `FILES` table function, or `INSERT INTO ... SELECT`.

* **Typical scenarios**: Batch warehousing of historical details and log archives; CSV/ORC/Parquet files located in remote paths like OSS or HDFS; writing ultra-large tables or full data more efficiently using **direct load**; reading lakehouse data via external tables or `FILES` and then **importing it into internal tables**.

* **Related documentation**: [Data Import Overview](300.data-import/100.data-import-overview.md), [LOAD DATA FROM FILES](300.data-import/200.load-data-import.md), [LOAD DATA INFILE](300.data-import/200.load-data-import.md), [LOAD DATA LOCAL INFILE](300.data-import/200.load-data-import.md), [Direct Load Overview](300.data-import/100.data-import-overview.md), [Full Direct Load](300.data-import/100.data-import-overview.md), [INSERT INTO SELECT FROM FILES](300.data-import/300.insert-into/100.insert-into-select-from-files.md), [Import via INSERT INTO SELECT from External Tables](300.data-import/300.insert-into/200.insert-into-select-from-external-table.md), [Import Data Using obloader](300.data-import/500.import-data-with-obloader.md).

### Data synchronization

Maintain **business-acceptable consistency** or a latency upper bound between the target database (often OceanBase) and the source database over a **long period**, with tools **continuously writing to the target database**.

* **Typical scenarios**: Intra-city/out-of-town disaster recovery, dual-machine hot standby; short-period dual-write and rollback windows before and after switchover; aligning replicas with the primary database under multi-active or read/write splitting.

* **Related documentation**: [Data Synchronization Overview](400.data-synchronization/100.data-synchronization.md).

### Data subscription

Continuously read **database logs or CDC events** from upstream, parse them, and transmit them to **Kafka, Flink**, etc., for consumption, processing, or selective database writing by **multiple downstream systems**.

* **Typical scenarios**: Use components like Canal or Flink CDC to subscribe to database changes and write the changed data to message systems such as Kafka, for real-time data warehouses, stream processing tasks, or multiple business systems to consume separately.

* **Related documentation**: [Data Subscription Overview](400.data-synchronization/300.data-subscription.md), [Data Synchronization Overview](400.data-synchronization/100.data-synchronization.md) (read in conjunction with the OMS database writing path), [Data Import Strategies and Best Practices](200.data-migration/500.best-practices-migrating-from-mainstream-databases-to-oceanbase.md).
