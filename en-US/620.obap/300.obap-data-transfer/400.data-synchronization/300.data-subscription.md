# Data subscription

Data subscription uses **Change Data Capture (CDC)** to continuously **read database logs** from upstream sources (such as MySQL Binlog or OceanBase Binlog Service). After parsing, sorting, or transforming the incremental changes, it replays them at the **target side**. Common targets include **OceanBase** and **Kafka**; from there, Flink or custom consumers can write the data to analytics databases or wide tables.

**Typical scenarios**: Real-time synchronization to BI/data warehouses, cache and search engine refreshes, incremental data catch-up during migration and cutover, traffic throttling via Kafka for multi-team consumption, and distribution via OceanBase Binlog.

## Subscribe to MySQL Binlog using Canal

Canal simulates a MySQL Slave **subscribing to Binlog** and delivers row-level changes to the client. It can be configured to directly synchronize to OceanBase, or first write to a message system via modes such as **TCP / Kafka / RocketMQ / RabbitMQ**, and then be consumed downstream and written to the target database (including OceanBase).

## Subscribe to multiple source databases using Flink CDC

Flink CDC provides a **Database CDC Source** on top of Flink, which can pull **stock + incremental** data from various databases. Combined with Flink SQL for joins, widening, and aggregation, it then writes to sinks like Kafka, JDBC (including OceanBase), and Hive. This is suitable for pipelines requiring **multi-source integration**, **real-time processing**, and high **Exactly-Once** requirements.

## Data subscription scenarios for writing to Kafka / OceanBase

A common pattern is: **CDC or Canal parses logs → writes to Kafka (buffering, multi-subscription) → Flink/OMS/custom consumer → persists to OceanBase or other storage**. Alternatively, Flink CDC can **directly** sink data to OceanBase JDBC, omitting Kafka, depending on throughput and coupling requirements.

| Scenario | Description | Documentation / Links |
| --- | --- | --- |
| TiDB:TiCDC → Kafka → OMS → OceanBase | TiDB incremental data is delivered via Kafka and consumed by OMS to write into an OceanBase MySQL-compatible tenant (a new data source must be bound to Kafka). | [Use OMS to migrate data from a TiDB database to an OceanBase database (MySQL-compatible tenant)](../../../500.data-migration/620.migrate-data-from-tidb-database-to-oceanbase-database/100.use-oms-to-migrate-data-from-tidb-database-to-oceanbase-database-mysql-tenant.md) |
| Connect OMS to Kafka/RocketMQ/DataHub | Supported downstream messaging and data integration formats on the product side, which can be combined with subscription links. | [Data Migration Overview · Data Sources Supported by OMS](../../../500.data-migration/100.data-migration-overview.md) (Migration Solution Support Table); [OMS Documentation](https://www.oceanbase.com/docs/oms-doc-cn) |
| Canal → Kafka (re-consume and write to OB) | Configure Canal `serverMode` and similar settings to `kafka`. During synchronization, changes are first written to the topic and then consumed by OceanBase Database. | [Use Canal to synchronize data from a MySQL database to OceanBase Database](../../../500.data-migration/200.migrate-data-from-mysql-database-to-oceanbase-database/500.use-canal-to-migrate-data-from-mysql-database-to-oceanbase-database.md) |
| Flink CDC → Kafka → Downstream | Flink writes the CDC stream to Kafka for real-time data warehouse and multi-team consumption. For sink selection, refer to the Flink documentation. | [Flink Kafka Connector](https://nightlies.apache.org/flink/flink-docs-master/docs/connectors/table/kafka/) |
