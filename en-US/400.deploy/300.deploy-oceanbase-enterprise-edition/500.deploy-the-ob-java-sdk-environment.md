# Deploy OceanBase Database Java SDK

OceanBase Database now supports connecting to a file system as an external data source by using the Java SDK. This feature uses the JNI framework, so the OceanBase Database environment must be deployed with the Java SDK.

## Configure environment

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>If you want to use the HDFS/ODPS external table feature and OceanBase Database is deployed in a distributed manner, you must configure the Java environment and install the dependencies on all corresponding nodes. You cannot configure only one node. </p>
</main>

All environment configuration and dependency installation operations must be performed by the admin user. To switch to the admin user, run the following command: 

```bash
su - admin
```

### Deploy and configure Java environment

1. Download the OpenJDK installation package from [Download Link](https://www.openlogic.com/openjdk-downloads).

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>Please download the latest version of OpenJDK 11. </p>
    </main>

    This topic provides an example of using the OpenJDK 11.0.29+7 release. The steps are as follows:    

    ```shell
    [admin@xxx /home/admin/rpm]# wget https://builds.openlogic.com/downloadJDK/openlogic-openjdk/11.0.29+7/openlogic-openjdk-11.0.29+7-linux-x64.tar.gz
    ```

2. Extract the package normally.    

    Example:    

    ```shell
    [admin@xxx /home/admin/rpm]# sudo tar -zxvf openlogic-openjdk-11.0.29+7-linux-x64.tar.gz
    ```    

    Installation path:    

    ```shell
    /home/admin/rpm/openlogic-openjdk-11.0.29+7-linux-x64
    ```    

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>This path is used to configure the java home directory for the current OBServer node, which corresponds to the configuration parameter <a href="../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16635.ob_java_home.md">ob_java_home</a>. </p>
    </main>

### Install dependent components

If you want to use the HDFS or ODPS external table feature of OceanBase Database, you need to install the following components:    

* devdeps-hdfs-sdk RPM package:    

  This package contains dynamic link library files and key interfaces of the Java Native Interface (JNI) that are used for the runtime of HDFS or ODPS external tables. As a bridge between the Java Virtual Machine (JVM) and the local external table Java Software Development Kit (SDK), this component ensures the stable operation of the external table feature.    

* devdeps-java-extensions RPM package:    

  This package integrates the key dependency libraries (JAR files) required for HDFS external tables and other external data sources, such as ODPS. This extension package contains a complete Java runtime dependency chain, ensuring the compatibility and performance optimization of the external table feature in distributed scenarios.

#### Deploy devdeps-hdfs-sdk package

1. Download the devdeps-hdfs-sdk RPM installation package.    

    * For Enterprise Edition, contact Technical Support for the devdeps-hdfs-sdk RPM installation package.
    * For Community Edition, go to the [OceanBase Database image](https://mirrors.aliyun.com/oceanbase/) page, click `development-kit/`, go to the development kit resources directory, and download the devdeps-hdfs-sdk RPM installation package.    

2. After obtaining the package, run the following command to install it:    

    ```shell
    sudo rpm -Uvh devdeps-hdfs-sdk-3.3.6-xxxxx.xxx.xxx.rpm
    ```    

    Example:    

    ```shell
    sudo rpm -Uvh devdeps-hdfs-sdk-3.3.6-112024123116.el7.x86_64.rpm
    ```    

3. Verify that the installation is successful.    

    The `libhdfs.so` and `libhdfs.so.0.0.0` files must exist, and the corresponding symbolic links must be valid.    

    Example:    

    ```shell
    $ll /usr/local/oceanbase/deps/devel/lib
    total 376
    lrwxrwxrwx 1 root root     16 Dec 24 19:49 libhdfs.so -> libhdfs.so.0.0.0
    -rwxr-xr-x 1 root root 384632 Dec 24 19:09 libhdfs.so.0.0.0
    ```

#### Deploy devdeps-java-extensions package

1. Download the devdeps-java-extensions RPM installation package.    

    * For Enterprise Edition, contact Technical Support for the devdeps-java-extensions RPM installation package.
    * For Community Edition, go to the [OceanBase Database image](https://mirrors.aliyun.com/oceanbase/) page, click `development-kit/`, go to the development kit resources directory, and download the devdeps-java-extensions RPM installation package.    
       <ul>
          <li>For OceanBase Database V4.3.5 BP1 or earlier: please download the 1.0.0 version of the devdeps-java-extensions RPM installation package.</li>
          <li>For OceanBase Database V4.3.5 BP2 or later: please download the 1.0.1 version of the devdeps-java-extensions RPM installation package.</li>
          <li>For OceanBase Database V4.4.0: please download the 1.0.1 version of the devdeps-java-extensions RPM installation package.</li>
          <li>For OceanBase Database V4.4.1: please download the 1.0.2 version of the devdeps-java-extensions RPM installation package.</li>
          <li>For OceanBase Database V4.4.2 or later: please download the 1.0.3 version of the devdeps-java-extensions RPM installation package.</li>
       </ul>

2. Run the following command to install the RPM package:    

    ```shell
    sudo rpm -Uvh devdeps-java-extensions-x.x.x-xxxxxxxxxxxx.xxx.xxxxxx.rpm --prefix=/user_install_directory
    ```    

    Example:    

    ```shell
    sudo rpm -Uvh devdeps-java-extensions-1.0.0-122025032514.el7.x86_64.rpm --prefix=/home/admin/oceanbase
    ```    

3. Verify that the installation is successful.    

    Check whether the `oceanbase-odps-connector-jar-with-dependencies.jar` file exists in the `/home/admin/oceanbase/jni_packages/v1.0.0` directory.    

    Example:    

    ```shell
    $ll /home/admin/oceanbase/jni_packages/v1.0.0
    total 52756
    drwxr-sr-x 4 root root     4096 Dec 24 20:25 hadoop
    drwxr-xr-x 3 root root     4096 Dec 24 20:25 lib
    -rw-r--r-- 1 root root 54008720 Dec 24 19:52 oceanbase-odps-connector-jar-with-dependencies.jar
    ```    

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>This path specifies the path of the executable dependency JAR file that the JVM of the OBServer node can load, corresponding to the configuration parameter <a href="../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16640.ob_java_connector_path.md">ob_java_connector_path</a>. </p>
    </main>

## (Optional) Restart observer process

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p><ul><li>If you are using the Java SDK for the first time, you do not need to restart the observer process.</li><li>Since the current OBServer does not support flexible and immediate configuration changes for JNI-related settings, if you need to modify related Java environment variables, you must restart the observer process for the changes to take effect.</li></ul></p>
</main>

When using HDFS/ODPS external table features, you need to configure the corresponding OBServer servers. The configuration steps are as follows. Note that all the following configuration items are cluster-level settings. You need to configure them only once, without the need to configure them on each node individually.

### Step 1: Set Java environment startup-related parameters

The following settings are performed in the sys tenant.

1. Enable the Java environment to allow access to the SDK (Java SDK) for external tables.

    **Here is an example:**

    ```sql
    ALTER SYSTEM SET ob_enable_java_env = true;
    ```

    For more information, see [ob_enable_java_env](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16630.ob_enable_java_env.md).

2. Set the Java home directory on the node where the current OBServer is running.

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>This path is obtained from the OpenJDK Java installation path. </p>
    </main>

    **Here is an example:**

    ```sql
    ALTER SYSTEM SET ob_java_home = "/home/admin/rpm/openlogic-openjdk-11.0.29+7-linux-x64";
    ```

    For more information, see [ob_java_home](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16635.ob_java_home.md).

3. Set the path to the executable dependency JAR packages that can be loaded by the JVM when the OBServer starts.

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>This path is obtained from the JAR package RPM installation path. </p>
    </main>

    **Here is an example:**

    ```sql
    ALTER SYSTEM SET ob_java_connector_path = "/home/admin/oceanbase/jni_packages/v1.0.0";
    ```

    For more information, see [ob_java_connector_path](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16640.ob-java-connector-path.md).

4. Set the Java environment startup-related parameters.

   1. Create the corresponding log folder path.

       ```shell
       mkdir -p /home/user/jvmlogs
       mkdir -p /home/user/jvmlogs/heapdumps
       ```

   2. Set the JVM startup parameters for Java runtime.

       **Here is an example:**

       ```sql
       ALTER SYSTEM SET ob_java_opts="-Xmx2048m -Xms2048m -XX:-CriticalJNINatives -Djdk.lang.processReaperUseDefaultStackSize=true -Xrs -XX:+HeapDumpOnOutOfMemoryError -Xloggc:/home/admin/gc.log -XX:+PrintGCDetails -XX:+PrintGCDateStamps -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/home/admin/heapdumps/ -XX:+UseConcMarkSweepGC -XX:+UseParNewGC -XX:CMSInitiatingOccupancyFraction=75 -XX:+UseCMSInitiatingOccupancyOnly -XX:+CMSClassUnloadingEnabled -XX:+TieredCompilation -XX:+ExplicitGCInvokesConcurrentAndUnloadsClasses ";
       ```

       For more information, see [ob_java_opts](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16650.ob_java_opts.md).

       <main id="notice" type='notice'>
         <h4>Notice</h4>
         <p><ul><li>Changing this parameter requires restarting the observer process. Since the current HDFS integration uses direct memory copying from the HDFS data stream to the C++ memory heap, you can appropriately reduce the <code>-Xmx2048m -Xms2048m</code> setting. </li><li>GC log files are generated only when the configuration folder path exists; if the path does not exist, no GC log files will be generated. </li></ul></p>
       </main>

5. (Optional) Set the ODPS Java SDK configuration parameter.

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>The HDFS Java SDK does not require this parameter, while other parameters are the same. </p>
    </main>

    If you want to use the Java SDK, set `_use_odps_jni_connector` to `true`.

    ```sql
    ALTER SYSTEM SET _use_odps_jni_connector = true;
    ```

### Step 2 (Optional): Decompress hdfs-sdk package without sudo privileges

1. If you cannot obtain `sudo` privileges to execute the installation command, you can manually decompress the devdeps-hdfs-sdk RPM installation package using the `rpm2cpio` command. You can place the required package in the desired path as needed.

    **Here is an example:**

    ```shell
    rpm2cpio devdeps-hdfs-sdk-3.3.6-xxxxx.xxx.xxx.rpm | cpio -idmv
    ```

2. Specify the target path.

    After decompressing the installation package, you can use the `mv` command to move the decompressed files to a custom path that you can access (e.g., `~/hdfs_lib`).

    **Here is an example:**

    ```shell
    mv ./usr/local/oceanbase/deps/devel/lib/* ~/hdfs_lib/
    ```

3. Obtain and confirm the absolute path.

    You can use the `realpath` command to view the absolute path of the custom path.

    **Here is an example:**

    ```shell
    realpath ~/hdfs_lib
    ```

    The return result is as follows:

    ```shell
    /home/${user_name}/hdfs_lib
    ```

4. Configure the OceanBase Database path variable.

    **Here is an example:**

    Log in to the sys tenant and execute the following command to register the custom path to the system configuration.

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p><ul><li>When executing the following statement, please replace <code>${user_name}</code> in the example with the actual path. </li><li>The path must be an absolute path, and multiple paths are separated by colons <code>:</code>, with no spaces. </li></ul></p>
    </main>

    ```sql
    ALTER SYSTEM SET _ob_additional_lib_path = '/home/${user_name}/hdfs_lib';
    ```

### Step 3: Restart observer process

Stop the observer process on all servers and then restart it.

1. Switch to the `admin` user.

    ```shell
    [admin@xxx /home/admin/oceanbase/etc]# su - admin
    ```

2. Stop the observer process.

    ```shell
    -bash-4.2$ kill -9 `pidof observer`
    ```

3. Start the observer process.

    ```shell
    -bash-4.2$ cd /home/admin/oceanbase && /home/admin/oceanbase/bin/observer
    ```

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>When you restart the observer process, you do not need to specify the startup parameters because they have already been written to the parameter file. </p>
    </main>
