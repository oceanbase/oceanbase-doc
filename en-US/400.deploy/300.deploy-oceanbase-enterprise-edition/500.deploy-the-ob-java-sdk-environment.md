# Deploy the Java SDK environment for OceanBase Database

OceanBase Database now supports connecting to file systems using the Java SDK as a third-party data source for external tables. This feature leverages the JNI framework, so the corresponding OceanBase Database environment must include the Java SDK.

## Environment configuration

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>If you need to use the HDFS/ODPS external table feature and OceanBase Database is deployed in distributed mode, you must perform the following deployment configurations for the Java environment and install dependencies on all corresponding server nodes. You cannot configure only one node.</p>
</main>

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>All environment configurations and dependency installation operations must be performed as the admin user. Please switch users as follows.</p>
</main>

```bash
su - admin
```

### Deploy and configure the Java environment

1. Download the OpenJDK Java installation package from the [Download Center](https://www.openlogic.com/openjdk-downloads).

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>Use the latest version of OpenJDK 11.</p>
    </main>

    This topic uses downloading OpenJDK 11.0.29+7 as an example. The specific procedure is as follows:

    ```shell
    [admin@xxx /home/admin/rpm]# wget https://builds.openlogic.com/downloadJDK/openlogic-openjdk/11.0.29+7/openlogic-openjdk-11.0.29+7-linux-x64.tar.gz
    ```

2. Extract the corresponding installation package normally.

    Example:

    ```shell
    [admin@xxx /home/admin/rpm]# tar -zxvf openlogic-openjdk-11.0.29+7-linux-x64.tar.gz
    ```

    The installation path is as follows:

    ```shell
    /home/admin/rpm/openlogic-openjdk-11.0.29+7-linux-x64
    ```

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>This path is used to configure the Java Home directory on the current OBServer running node, that is, the value of the <a href="../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16635.ob_java_home.md">ob_java_home</a> parameter.</p>
    </main>

### Install dependencies

OceanBase Database's use of the HDFS/ODPS external table feature also depends on the following components:

* devdeps-hdfs-sdk RPM package:

  This package contains the dynamic link library files required for the runtime of external tables such as HDFS/ODPS, providing the core interface for interaction between the JVM environment and JNI (Java Native Interface). This component serves as a communication bridge between the Java Virtual Machine and the local external table Java SDK, ensuring the stable operation of the external table feature.

* The devdeps-java-extensions RPM package:

  This package integrates the core dependency libraries (JAR files) required for HDFS external tables and other external data sources (such as ODPS). This extension package contains a complete Java runtime dependency chain, ensuring compatibility and performance optimization for external table functionality in distributed scenarios.

  Starting from version 1.0.6, this package also provides dependencies required for JDBC Catalog and JVM monitoring features.

#### Deploy the configured dependency HDFS.so dynamic library

1. Obtain the devdeps-hdfs-sdk RPM installation package.

    * Enterprise Edition users: Please contact technical support to obtain the devdeps-hdfs-sdk RPM installation package.
    * Open Source Edition users: On the [Alibaba Cloud OceanBase Image](https://mirrors.aliyun.com/oceanbase/) page, click the `development-kit/` directory to enter the development tools resource directory, and download the devdeps-hdfs-sdk RPM installation package.

2. After obtaining the installation package, install it using the following command.

    ```shell
    sudo rpm -Uvh devdeps-hdfs-sdk-3.3.6-xxxxx.xxx.xxx.rpm
    ```

    Example:

    ```shell
    sudo rpm -Uvh devdeps-hdfs-sdk-3.3.6-112024123116.el7.x86_64.rpm
    ```

3. Check whether the installation meets expectations.

    The `libhdfs.so` and `libhdfs.so.0.0.0` files must be present, and the corresponding soft links must be valid.

    Example:

    ```shell
    $ll /usr/local/oceanbase/deps/devel/lib
    total 376
    lrwxrwxrwx 1 root root     16 Dec 24 19:49 libhdfs.so -> libhdfs.so.0.0.0
    -rwxr-xr-x 1 root root 384632 Dec 24 19:09 libhdfs.so.0.0.0
    ```

#### Deploy the configured dependency JAR package path

1. Obtain the devdeps-java-extensions RPM installation package.

    * Enterprise Edition users: Please contact technical support to obtain the devdeps-java-extensions RPM installation package.
    * Open Source Edition users: On the [Alibaba Cloud OceanBase Image](https://mirrors.aliyun.com/oceanbase/) page, click the `development-kit/` directory to enter the development tools resource directory, and download the devdeps-java-extensions RPM installation package.

      <main id="notice" type='notice'>
        <h4>Notice</h4>
        <p><ul>
          <li>OceanBase Database V4.3.5 BP1 and earlier versions: Download the 1.0.0 version of the devdeps-java-extensions RPM installation package.</li>
          <li>OceanBase Database V4.3.5 BP2 and later versions: Download the 1.0.1 version of the devdeps-java-extensions RPM installation package.</li>
          <li>OceanBase Database V4.4.0: Download the 1.0.1 version of the devdeps-java-extensions RPM installation package.</li>
          <li>OceanBase Database V4.4.1: Download the 1.0.2 version of the devdeps-java-extensions RPM installation package.</li>
          <li>OceanBase Database V4.4.2 to V4.4.2 BP2: Download the 1.0.4 version of the devdeps-java-extensions RPM installation package.</li>
          <li>OceanBase Database V4.4.2 BP3: Download the 1.0.5 version of the devdeps-java-extensions RPM installation package.</li>
          <li>OceanBase Database V4.4.2 BP4 and later: Download the 1.0.6 version of the devdeps-java-extensions RPM installation package.</li></ul></p>
      </main>

2. After obtaining the installation package, install it using the following command.

    ```shell
    sudo rpm -Uvh devdeps-java-extensions-x.x.x-xxxxxxxxxxxx.xxx.xxxxxx.rpm --prefix=/user_install_directory
    ```

    Example:

    ```shell
    sudo rpm -Uvh devdeps-java-extensions-1.0.0-122025032514.el7.x86_64.rpm --prefix=/home/admin/oceanbase
    ```

3. Check whether the installation meets expectations.

    Check whether the `oceanbase-odps-connector-jar-with-dependencies.jar` file exists in the installation path `/home/admin/oceanbase/jni_packages/v1.0.0`.

    Example:

    ```shell
    $ll /home/admin/oceanbase/jni_packages/v1.0.0
    total 52756
    drwxr-sr-x 4 root root     4096 Dec 24 20:25 hadoop
    drwxr-xr-x 3 root root     4096 Dec 24 20:25 lib
    -rw-r--r-- 1 root root 54008720 Dec 24 19:52 oceanbase-odps-connector-jar-with-dependencies.jar
    ```

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>This path specifies the location of the executable dependency JAR files that the JVM used to start the OBServer node can load. It corresponds to the value of the <a href="../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16640.ob-java-connector-path.md">ob_java_connector_path</a> parameter.</p>
    </main>

## (Optional) Restart the observer process

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p><ul><li>If you are using the Java SDK environment for the first time, you do not need to restart the observer process.</li><li>Since the JNI-related parameters supported by the current OBServer cannot be set and take effect flexibly and promptly, if you need to try changing the configuration of related Java environment variables, you must restart the observer process for the changes to take effect.</li></ul></p>
</main>

When using the HDFS/ODPS external table feature, you need to configure the corresponding OBServer server. For the procedure, see the following section.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>All of the following parameters are cluster-level configurations. Set them once, as they do not need to be configured individually on all nodes.</p>
</main>

### Step 1: Configure parameters for Java environment startup

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>All of the following settings are performed in the sys tenant.</p>
</main>

1. Enable Java Env for SDK (Java SDK) access to external tables.

    **Example:**

    ```sql
    ALTER SYSTEM SET ob_enable_java_env = true;
    ```

    For more information about this setting, see [ob_enable_java_env](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16630.ob_enable_java_env.md).

2. Set the Java Home directory on the current OBServer node.

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>This path is derived from the OpenJDK installation directory.</p>
    </main>

    **Example:**

    ```sql
    ALTER SYSTEM SET ob_java_home = "/home/admin/rpm/openlogic-openjdk-11.0.29+7-linux-x64";
    ```

    For more information about this setting, see [ob_java_home](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16635.ob_java_home.md).

3. Set the JVM classpath for loading executable dependency JAR files when starting OBServer.

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>This path is derived from the RPM installation directory of the JAR package.</p>
    </main>

    **Example:**

    ```sql
    ALTER SYSTEM SET ob_java_connector_path = "/home/admin/oceanbase/jni_packages/v1.0.0";
    ```

    For more information about this parameter, see [ob_java_connector_path](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16640.ob-java-connector-path.md).

4. Set the parameters for starting the Java environment.

   1. Create the corresponding log folder path.

       ```shell
       mkdir -p /home/user/jvmlogs
       mkdir -p /home/user/jvmlogs/heapdumps
       ```

   2. Set the JVM startup parameters for Java execution.

       **Example:**

       ```sql
       ALTER SYSTEM SET ob_java_opts="-Xmx2048m -Xms2048m -XX:-CriticalJNINatives -Djdk.lang.processReaperUseDefaultStackSize=true -Xrs -XX:+HeapDumpOnOutOfMemoryError -Xloggc:/home/admin/gc.log -XX:+PrintGCDetails -XX:+PrintGCDateStamps -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/home/admin/heapdumps/ -XX:+UseConcMarkSweepGC -XX:+UseParNewGC -XX:CMSInitiatingOccupancyFraction=75 -XX:+UseCMSInitiatingOccupancyOnly -XX:+CMSClassUnloadingEnabled -XX:+TieredCompilation -XX:+ExplicitGCInvokesConcurrentAndUnloadsClasses ";
       ```

       For more information about this parameter, see [ob_java_opts](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16650.ob_java_opts.md).

       <main id="notice" type='notice'>
         <h4>Notice</h4>
         <p><ul><li>Changing this parameter requires restarting the observer process. Since the current HDFS integration directly copies data from the HDFS stream to the C++ memory heap, you can appropriately reduce the <code>-Xmx2048m -Xms2048m</code> setting.</li><li>GC log files are generated only if the configuration folder path exists; if the path does not exist, they will not be generated.</li></ul></p>
       </main>

5. (Optional) Set the JAVA SDK parameters for ODPS.

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>This parameter is not required for the HDFS JAVA SDK; all other parameters are the same.</p>
    </main>

    To use the JAVA SDK, set `_use_odps_jni_connector` to `true`.

    ```sql
    ALTER SYSTEM SET _use_odps_jni_connector = true;
    ```

### Step 2 (Optional): Decompress the hdfs-sdk package without sudo privileges

1. If you cannot execute the installation command with `sudo` privileges in the current environment, you can manually decompress the devdeps-hdfs-sdk RPM package using the `rpm2cpio` command. You can then place the files in any desired directory.

    **Example:**

    ```shell
    rpm2cpio devdeps-hdfs-sdk-3.3.6-xxxxx.xxx.xxx.rpm | cpio -idmv
    ```

2. Specify the target path.

    After decompressing the package, use the `mv` command to move the decompressed files to a custom accessible path (for example, `~/hdfs_lib`).

    **Example:**

    ```shell
    mv ./usr/local/oceanbase/deps/devel/lib/* ~/hdfs_lib/
    ```

3. Obtain and confirm the absolute path.

    You can use the `realpath` command to view the absolute path of the custom directory.

    **Example:**

    ```shell
    realpath ~/hdfs_lib
    ```

    The result is as follows:

    ```shell
    /home/${user_name}/hdfs_lib
    ```

4. Configure the OceanBase database path variable.

    **Example:**

    Log in to the sys tenant and execute the following command to register the custom path in the system configuration.

    <main id="notice" type='notice'>
      <h4>Note</h4>
      <p><ul><li>Replace <code>${user_name}</code> with the actual path in the example when executing the following statement.</li><li>The path must be an absolute path. Multiple paths must be separated with a colon <code>:</code> and must not contain spaces.</li></ul></p>
    </main>

    ```sql
    ALTER SYSTEM SET _ob_additional_lib_path = '/home/${user_name}/hdfs_lib';
    ```

### Step 3: Restart the observer process

Stop the observer process on all servers, then restart it.

1. Switch to the `admin` user.

    ```shell
    [admin@xxx /home/admin/oceanbase/etc]# su - admin
    ```

2. Stop the observer process.

    ```shell
    -bash-4.2$ kill -9 `pidof observer`
    ```

3. Restart the observer process.

    ```shell
    -bash-4.2$ cd /home/admin/oceanbase && /home/admin/oceanbase/bin/observer
    ```

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>You do not need to specify startup parameters when restarting the observer process, because they have already been written into the parameter file.</p>
    </main>
