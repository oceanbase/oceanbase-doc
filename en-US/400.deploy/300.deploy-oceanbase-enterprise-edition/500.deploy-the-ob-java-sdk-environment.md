# Deploy OceanBase Database Java SDK environment

OceanBase Database now supports connecting to a file system as an external data source using the Java SDK.

This feature uses the JNI framework, so the OceanBase Database environment needs to have the Java SDK deployed.

## Configure environment

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>If you want to use the HDFS/ODPS external table feature and OceanBase Database is deployed in a distributed manner, you must configure the Java environment and install the required dependencies on all corresponding nodes. Do not configure only one node. </p>
</main>

All environment configuration and dependency installation operations must be performed as the admin user. To switch to the admin user, run the following command:

```bash
su - admin
```

### Deploy and configure Java environment

1. Download the OpenJDK installation package from [Download address](https://www.openlogic.com/openjdk-downloads).

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>Please use the latest version of OpenJDK 11. </p>
    </main>

    This example uses the OpenJDK 11.0.29+7 version. The specific operation steps are as follows:

    ```shell
    [admin@xxx /home/admin/rpm]# wget https://builds.openlogic.com/downloadJDK/openlogic-openjdk/11.0.29+7/openlogic-openjdk-11.0.29+7-linux-x64.tar.gz
    ```

2. Decompress the installation package normally.

    Example:

    ```shell
    [admin@xxx /home/admin/rpm]# sudo tar -zxvf openlogic-openjdk-11.0.29+7-linux-x64.tar.gz
    ```

    The installation path is as follows:

    ```shell
    /home/admin/rpm/openlogic-openjdk-11.0.29+7-linux-x64
    ```

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>This path is used to configure the Java home directory on the current OBServer node, which corresponds to the value of the <a href="../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16635.ob_java_home.md">ob_java_home</a> parameter. </p>
    </main>

### Install dependencies

OceanBase Database requires the following components to use the HDFS/ODPS external table feature:

* devdeps-hdfs-sdk RPM package:

  This package contains dynamic link library files required for the runtime of HDFS/ODPS external tables, providing core interfaces for interaction between the JVM environment and JNI (Java Native Interface). This component serves as a communication bridge between the Java Virtual Machine and the native Java SDK of external tables, ensuring the stable operation of external table features.

* devdeps-java-extensions RPM package:

  This package integrates core dependency libraries (JAR files) required for HDFS external tables and other external data sources (such as ODPS). The extension package contains a complete Java runtime dependency chain, ensuring compatibility and performance optimization of external table features in distributed scenarios.

#### Deploy and configure the HDFS.so dynamic library

1. Obtain the devdeps-hdfs-sdk RPM installation package.

    * Enterprise Edition users should contact Technical Support for the devdeps-hdfs-sdk RPM installation package.
    * Community Edition users can download the devdeps-hdfs-sdk RPM installation package by clicking the `development-kit/` directory on the [OceanBase Database image](https://mirrors.aliyun.com/oceanbase/) page, entering the development tool resource directory, and downloading the devdeps-hdfs-sdk RPM installation package.

2. After obtaining the installation package, install it using the following command.

    ```shell
    sudo rpm -Uvh devdeps-hdfs-sdk-3.3.6-xxxxx.xxx.xxx.rpm
    ```

    Example:

    ```shell
    sudo rpm -Uvh devdeps-hdfs-sdk-3.3.6-112024123116.el7.x86_64.rpm
    ```

3. Verify that the installation meets the expected results.

    The `libhdfs.so` and `libhdfs.so.0.0.0` files must exist, and the corresponding soft links must be normal.

    Example:

    ```shell
    $ll /usr/local/oceanbase/deps/devel/lib
    total 376
    lrwxrwxrwx 1 root root     16 Dec 24 19:49 libhdfs.so -> libhdfs.so.0.0.0
    -rwxr-xr-x 1 root root 384632 Dec 24 19:09 libhdfs.so.0.0.0
    ```

#### Deploy and configure the jar package path

1. Obtain the devdeps-java-extensions RPM installation package.

    * Enterprise Edition users should contact Technical Support for the devdeps-java-extensions RPM installation package.
    * Community Edition users can download the devdeps-java-extensions RPM installation package by clicking the `development-kit/` directory on the [OceanBase Database image](https://mirrors.aliyun.com/oceanbase/) page, entering the development tool resource directory, and downloading the devdeps-java-extensions RPM installation package.
      <ul>
          <li>For OceanBase Database V4.3.5 BP1 and earlier versions: Please download the devdeps-java-extensions RPM installation package of version 1.0.0. </li>
          <li>For OceanBase Database V4.3.5 BP2 and later versions: Please download the devdeps-java-extensions RPM installation package of version 1.0.1. </li>
          <li>For OceanBase Database V4.4.0: Please download the devdeps-java-extensions RPM installation package of version 1.0.1. </li>
          <li>For OceanBase Database V4.4.1: Please download the devdeps-java-extensions RPM installation package of version 1.0.2. </li>
          <li>For OceanBase Database V4.4.2 and later versions: Please download the devdeps-java-extensions RPM installation package of version 1.0.3. </li>
      </ul>

2. After obtaining the installation package, install it using the following command.

    ```shell
    sudo rpm -Uvh devdeps-java-extensions-x.x.x-xxxxxxxxxxxx.xxx.xxxxxx.rpm --prefix=/user_install_directory
    ```

    Example:

    ```shell
    sudo rpm -Uvh devdeps-java-extensions-1.0.0-122025032514.el7.x86_64.rpm --prefix=/home/admin/oceanbase
    ```

3. Verify that the installation meets the expected results.

    Check whether the `oceanbase-odps-connector-jar-with-dependencies.jar` file exists in the `/home/admin/oceanbase/jni_packages/v1.0.0` directory.

    Example:

    ```shell
    $ll /home/admin/oceanbase/jni_packages/v1.0.0
    total 52756
    drwxr-sr-x 4 root root     4096 Dec 24 20:25 hadoop
    drwxr-xr-x 3 root root     4096 Dec 24 20:25 lib
    -rw-r--r-- 1 root root 54008720 Dec 24 19:52 oceanbase-odps-connector-jar-with-dependencies.jar
    ```

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>This path is used to configure the path of the executable dependency JAR package that can be loaded by the JVM when OBServer starts, which corresponds to the value of the <a href="../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16640.ob-java-connector-path.md">ob_java_connector_path</a> parameter. </p>
    </main>

## (Optional) Restart observer process

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p><ul><li>If you are using the Java SDK for the first time, you do not need to restart the observer process.</li><li>Since the current OBServer does not support flexible and immediate configuration changes for JNI-related settings, you need to restart the observer process for the changes to take effect.</li></ul></p>
</main>

When using the HDFS/ODPS external table feature, you need to configure the corresponding OBServer server. The configuration steps are as follows:

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>All the following configuration items are cluster-level settings. You need to configure them only once, without needing to configure them on each node separately.</p>
</main>

### Step 1: Set the environment configuration required to start the Java environment

The following settings are for the sys tenant only.

1. Enable Java environment for accessing the SDK for the external tables (Java SDK).

    **For example:**

    ```sql
    ALTER SYSTEM SET ob_enable_java_env = true;
    ```

    For more information, see [ob_enable_java_env](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16630.ob_enable_java_env.md).

2. Set the Java home directory of the current OBServer running node.

    <main id="notice" type='explain'>
      <h4>Explanation</h4>
      <p>This path comes from the OpenJDK Java installation path.</p>
    </main>

    **Here is an example:**

    ```sql
    ALTER SYSTEM SET ob_java_home = "/home/admin/rpm/openlogic-openjdk-11.0.29+7-linux-x64";
    ```

    For more information about this parameter, see [ob_java_home](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16635.ob_java_home.md).

3. Specify the path to the dependency jar packages that can be loaded by the JVM of the OBServer.

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>This path comes from the RPM installation path of the jar package.</p>
    </main>

    **Example:**

    ```sql
    ALTER SYSTEM SET ob_java_connector_path = "/home/admin/oceanbase/jni_packages/v1.0.0";
    ```

    For more information, see [ob_java_connector_path](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16640.ob-java-connector-path.md).

4. Set the necessary configuration items for the Java environment to start.

   1. Create the corresponding log file path.

       ```shell
       mkdir -p /home/user/jvmlogs
       mkdir -p /home/user/jvmlogs/heapdumps
       ```

   2. Set the JVM startup options for Java execution.

       **Example:**

       ```sql
       ALTER SYSTEM SET ob_java_opts="-Xmx2048m -Xms2048m -XX:-CriticalJNINatives -Djdk.lang.processReaperUseDefaultStackSize=true -Xrs -XX:+HeapDumpOnOutOfMemoryError -Xloggc:/home/admin/gc.log -XX:+PrintGCDetails -XX:+PrintGCDateStamps -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/home/admin/heapdumps/ -XX:+UseConcMarkSweepGC -XX:+UseParNewGC -XX:CMSInitiatingOccupancyFraction=75 -XX:+UseCMSInitiatingOccupancyOnly -XX:+CMSClassUnloadingEnabled -XX:+TieredCompilation -XX:+ExplicitGCInvokesConcurrentAndUnloadsClasses ";
       ```

       For more information about this parameter, see [ob_java_opts](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16650.ob_java_opts.md).

       <main id="notice" type='notice'>
         <h4>Note</h4>
         <p><ul><li>This configuration change requires restarting the observer process. Currently, HDFS uses direct memory copy to transfer data streams to the C++ memory heap. Therefore, the settings of <code>-Xmx2048m -Xms2048m</code> can be adjusted accordingly.</li><li>GC log files are generated only when the configuration folder path exists; otherwise, no log files will be generated.</li></ul></p>
       </main>

5. (Optional) Set the configurations for the Java SDK of ODPS.

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>The HDFS Java SDK does not require this configuration parameter to be set, while all other configuration parameters remain the same.</p>
    </main>

    For information about how to use the Java SDK, see the "Java SDK" section in the SDK user guide. Set the `_use_odps_jni_connector` parameter to `true`.

    ```sql
    ALTER SYSTEM SET _use_odps_jni_connector = true;
    ```

### Step 2 (Optional): Unzip the hdfs-sdk package without sudo privileges.

1. If you cannot use `sudo` to run the installation command in your current environment, you can manually decompress the devdeps-hdfs-sdk RPM installation package using the `rpm2cpio` command. You can place it in the path you need as needed.

    **Example:**

    ```shell
    rpm2cpio devdeps-hdfs-sdk-3.3.6-xxxxx.xxx.xxx.rpm | cpio -idmv
    ```

2. Specify the destination path.

    Once the installation package is extracted, you can move the extracted files to a custom path accessible by the user, such as `~/hdfs_lib`, using the `mv` command.

    **Example:**

    ```shell
    mv ./usr/local/oceanbase/deps/devel/lib/* ~/hdfs_lib/
    ```

3. Obtain and verify the absolute path.

    Use the `realpath` command to find the absolute path of the custom path.

    **Example:**

    ```shell
    realpath ~/hdfs_lib
    ```

    The result is as follows:

    ```shell
    /home/${user_name}/hdfs_lib
    ```

4. Configure the path for OceanBase Database.

    Log in to the sys tenant, and execute the following command to register the custom paths to the system configuration.

    <main id="notice" type='notice'>
      <h4>Note</h4>
      <p><ul><li>When you execute the following statement, make sure to replace <code>${user_name}</code> with the actual path in the example. </li><li>The path must be an absolute path, multiple paths are separated by colon <code>:</code> and no space is allowed. </li></ul></p>
    </main>

    ```sql
    ALTER SYSTEM SET _ob_additional_lib_path = '/home/${user_name}/hdfs_lib';
    ```

### Step 3: Restart observer process

Stop the observer process on all servers and then restart it.

1. Switch to the `admin` user.

    ```shell
    [admin@xxx /home/admin/oceanbase/etc]# su - admin
    ```

2. Stop the observer process.

    ```shell
    -bash-4.2$ kill -9 `pidof observer`
    ```

3. Restart the observer process.

    ```shell
    -bash-4.2$ cd /home/admin/oceanbase && /home/admin/oceanbase/bin/observer
    ```

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>When you restart the observer process, you do not need to specify the startup parameters because they have already been written to the parameter file. </p>
    </main>
