# Deploy the OceanBase Database Java SDK

OceanBase Database now supports connecting to a file system as an external data source by using the Java SDK. This feature uses the JNI framework, so you must deploy the Java SDK environment in OceanBase Database.

## Environment configuration

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>If you want to use the HDFS/ODPS external table feature and OceanBase Database is deployed in a distributed manner, you must configure the Java environment and install the dependencies on all corresponding nodes, not just one node.</p>
</main>

All environment configuration and dependency installation operations must be performed as the admin user. Please switch to the admin user by using the following command: 

```bash
su - admin
```

### Configure the Java environment

1. Download the OpenJDK installation package from [Download Link](https://www.openlogic.com/openjdk-downloads).

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>Please use the latest version of OpenJDK 11.</p>
    </main>

    This example uses OpenJDK 11.0.29+7. The specific steps are as follows: 

    ```shell
    [admin@xxx /home/admin/rpm]# wget https://builds.openlogic.com/downloadJDK/openlogic-openjdk/11.0.29+7/openlogic-openjdk-11.0.29+7-linux-x64.tar.gz
    ```

2. Decompress the installation package normally. 

    Here is an example: 

    ```shell
    [admin@xxx /home/admin/rpm]# tar -zxvf openlogic-openjdk-11.0.29+7-linux-x64.tar.gz
    ```

    The installation path is as follows: 

    ```shell
    /home/admin/rpm/openlogic-openjdk-11.0.29+7-linux-x64
    ```

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>This path is used to configure the Java home directory on the OBServer node, which corresponds to the value of the <a href="../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16635.ob_java_home.md">ob_java_home</a> parameter.</p>
    </main>

### Install dependencies

To use the HDFS/ODPS external table feature in OceanBase Database, you also need to install the following components: 

* devdeps-hdfs-sdk RPM package: 

  This package contains dynamic link library files required for the runtime of HDFS/ODPS external tables. It provides core interfaces for interaction between the JVM environment and JNI (Java Native Interface). This component serves as a bridge between the Java Virtual Machine and the local external table Java SDK, ensuring the stable operation of the external table feature. 

* devdeps-java-extensions RPM package: 

  This package integrates core dependency libraries (JAR files) required for HDFS external tables and other external data sources (such as ODPS). The extension package contains a complete Java runtime dependency chain, ensuring compatibility and performance optimization of the external table feature in distributed scenarios.

#### Deploy and configure the HDFS.so dynamic library

1. Obtain the devdeps-hdfs-sdk RPM installation package. 

    * For Enterprise Edition users, contact Technical Support to obtain the devdeps-hdfs-sdk RPM installation package.
    * For Community Edition users, click the `development-kit/` directory on the [OceanBase Database Image](https://mirrors.aliyun.com/oceanbase/) page to enter the development tool resources directory and download the devdeps-hdfs-sdk RPM installation package. 

2. After obtaining the installation package, install it by using the following command: 

    ```shell
    sudo rpm -Uvh devdeps-hdfs-sdk-3.3.6-xxxxx.xxx.xxx.rpm
    ```

    Here is an example: 

    ```shell
    sudo rpm -Uvh devdeps-hdfs-sdk-3.3.6-112024123116.el7.x86_64.rpm
    ```

3. Check whether the installation meets the expected results. 

    The `libhdfs.so` and `libhdfs.so.0.0.0` files must exist, and the corresponding soft links must be normal. 

    Here is an example: 

    ```shell
    $ll /usr/local/oceanbase/deps/devel/lib
    total 376
    lrwxrwxrwx 1 root root     16 Dec 24 19:49 libhdfs.so -> libhdfs.so.0.0.0
    -rwxr-xr-x 1 root root 384632 Dec 24 19:09 libhdfs.so.0.0.0
    ```

#### Deploy and configure the JAR package path

1. Obtain the devdeps-java-extensions RPM installation package. 

    * For Enterprise Edition users, contact Technical Support to obtain the devdeps-java-extensions RPM installation package.
    * For Community Edition users, click the `development-kit/` directory on the [OceanBase Database Image](https://mirrors.aliyun.com/oceanbase/) page to enter the development tool resources directory and download the devdeps-java-extensions RPM installation package. 

      <main id="notice" type='notice'>
        <h4>Notice</h4>
        <p><ul>
          <li>For OceanBase Database V4.3.5 BP1 and earlier: Download the 1.0.0 version of the devdeps-java-extensions RPM installation package.</li>
          <li>For OceanBase Database V4.3.5 BP2 and later: Download the 1.0.1 version of the devdeps-java-extensions RPM installation package.</li>
          <li>For OceanBase Database V4.4.0: Download the 1.0.1 version of the devdeps-java-extensions RPM installation package.</li>
          <li>For OceanBase Database V4.4.1: Download the 1.0.2 version of the devdeps-java-extensions RPM installation package.</li></ul></p>
      </main>

2. After obtaining the installation package, install it by using the following command: 

    ```shell
    sudo rpm -Uvh devdeps-java-extensions-x.x.x-xxxxxxxxxxxx.xxx.xxxxxx.rpm --prefix=/user_install_directory
    ```

    Here is an example: 

    ```shell
    sudo rpm -Uvh devdeps-java-extensions-1.0.0-122025032514.el7.x86_64.rpm --prefix=/home/admin/oceanbase
    ```

3. Check whether the installation meets the expected results. 

    Check whether the `oceanbase-odps-connector-jar-with-dependencies.jar` file exists in the `/home/admin/oceanbase/jni_packages/v1.0.0` directory. 

    Here is an example: 

    ```shell
    $ll /home/admin/oceanbase/jni_packages/v1.0.0
    total 52756
    drwxr-sr-x 4 root root     4096 Dec 24 20:25 hadoop
    drwxr-xr-x 3 root root     4096 Dec 24 20:25 lib
    -rw-r--r-- 1 root root 54008720 Dec 24 19:52 oceanbase-odps-connector-jar-with-dependencies.jar
    ```

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>This path is used to configure the path of the executable dependency JAR package that can be loaded by the JVM when OBServer starts, which corresponds to the value of the <a href="../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16640.ob-java-connector-path.md">ob_java_connector_path</a> parameter.</p>
    </main>

## (Optional) Restart the observer process

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p><ul><li>If you are using the Java SDK for the first time, you do not need to restart the observer process. </li><li>Since the current OBServer does not support flexible and immediate setting of JNI-related configurations, you need to restart the observer process for changes to the Java environment variables to take effect. </li></ul></p>
</main>

When using the HDFS/ODPS external table feature, you need to configure the corresponding OBServer server. The configuration steps are as follows:

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>All the following configurations are cluster-level configurations. You need to set them only once, without having to configure each node separately. </p>
</main>

### Step 1: Set the Java environment startup-related parameters

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>The following settings are performed in the sys tenant. </p>
</main>

1. Enable the Java environment for the SDK (Java SDK) to access external tables.

    **Here is an example:**

    ```sql
    ALTER SYSTEM SET ob_enable_java_env = true;
    ```

    For more information, see [ob_enable_java_env](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16630.ob_enable_java_env.md).

2. Set the Java home directory on the current OBServer node.

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>The path is the installation path of OpenJDK. </p>
    </main>

    **Here is an example:**

    ```sql
    ALTER SYSTEM SET ob_java_home = "/home/admin/rpm/openlogic-openjdk-11.0.29+7-linux-x64";
    ```

    For more information, see [ob_java_home](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16635.ob_java_home.md).

3. Set the path of the executable dependency jar package that can be loaded by the JVM when the OBServer is started.

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>The path is the RPM installation path of the jar package. </p>
    </main>

    **Here is an example:**

    ```sql
    ALTER SYSTEM SET ob_java_connector_path = "/home/admin/oceanbase/jni_packages/v1.0.0";
    ```

    For more information, see [ob_java_connector_path](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16640.ob-java-connector-path.md).

4. Set the Java environment startup-related parameters

   1. Create the corresponding log folder path.

       ```shell
       mkdir -p /home/user/jvmlogs
       mkdir -p /home/user/jvmlogs/heapdumps
       ```

   2. Set the JVM startup parameters for Java runtime.

       **Here is an example:**

       ```sql
       ALTER SYSTEM SET ob_java_opts="-Xmx2048m -Xmn2048m -XX:-CriticalJNINatives -Djdk.lang.processReaperUseDefaultStackSize=true -Xrs -XX:+HeapDumpOnOutOfMemoryError -Xloggc:/home/admin/gc.log -XX:+PrintGCDetails -XX:+PrintGCDateStamps -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/home/admin/heapdumps/ -XX:+UseConcMarkSweepGC -XX:+UseParNewGC -XX:CMSInitiatingOccupancyFraction=75 -XX:+UseCMSInitiatingOccupancyOnly -XX:+CMSClassUnloadingEnabled -XX:+TieredCompilation -XX:+ExplicitGCInvokesConcurrentAndUnloadsClasses ";
       ```

       For more information, see [ob_java_opts](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16650.ob_java_opts.md).

       <main id="notice" type='notice'>
         <h4>Notice</h4>
         <p><ul><li>After you change this parameter, you must restart the observer process. In the current HDFS integration, the memory copy is directly copied from the HDFS data stream to the C++ memory heap. Therefore, you can reduce the <code>-Xmx2048m -Xms2048m</code> setting. </li><li>GC log files are generated only when the configuration folder path exists. If the path does not exist, no GC log file is generated. </li></ul></p>
       </main>

5. (Optional) Set the ODPS Java SDK parameters.

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>The HDFS Java SDK does not require this parameter. Other parameters are the same. </p>
    </main>

    If you want to use the Java SDK, set `_use_odps_jni_connector` to `true`.

    ```sql
    ALTER SYSTEM SET _use_odps_jni_connector = true;
    ```

### Step 2 (Optional): Decompress the hdfs-sdk package without sudo privileges

1. If you cannot obtain `sudo` privileges to execute the installation command, you can manually decompress the devdeps-hdfs-sdk RPM installation package by using the `rpm2cpio` command. You can place the package in the required path as needed.

    **Here is an example:**

    ```shell
    rpm2cpio devdeps-hdfs-sdk-3.3.6-xxxxx.xxx.xxx.rpm | cpio -idmv
    ```

2. Specify the target path.

    After decompressing the installation package, you can use the `mv` command to move the decompressed files to a custom path accessible by the user, such as `~/hdfs_lib`.

    **Here is an example:**

    ```shell
    mv ./usr/local/oceanbase/deps/devel/lib/* ~/hdfs_lib/
    ```

3. Obtain and confirm the absolute path.

    You can use the `realpath` command to view the absolute path of the custom path.

    **Here is an example:**

    ```shell
    realpath ~/hdfs_lib
    ```

    The returned result is as follows:

    ```shell
    /home/${user_name}/hdfs_lib
    ```

4. Configure the OceanBase Database path variable.

    **Here is an example:**

    Log in to the sys tenant and execute the following command to register the custom path to the system configuration.

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p><ul><li>When you execute the following statement, replace <code>${user_name}</code> in the example with the actual path. </li><li>The path must be an absolute path. Multiple paths are separated by colons <code>:</code>, and spaces are not allowed. </li></ul></p>
    </main>

    ```sql
    ALTER SYSTEM SET _ob_additional_lib_path = '/home/${user_name}/hdfs_lib';
    ```

### Step 3: Restart the observer process

Stop the observer process on all servers and then restart the observer process.

1. Switch to the `admin` user.

    ```shell
    [admin@xxx /home/admin/oceanbase/etc]# su - admin
    ```

2. Stop the observer process.

    ```shell
    -bash-4.2$ kill -9 `pidof observer`
    ```

3. Start the observer process.

    ```shell
    -bash-4.2$ cd /home/admin/oceanbase && /home/admin/oceanbase/bin/observer
    ```

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>When you start the observer process again, you do not need to specify the startup parameters because the previous startup parameters have been written to the parameter file. </p>
    </main>
