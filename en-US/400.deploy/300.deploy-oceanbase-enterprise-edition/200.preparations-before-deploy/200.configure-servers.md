This topic describes the hardware and software configuration requirements for servers, including the operating system, BIOS settings, disk mounting, and NIC settings.

## BIOS settings for OceanBase Database servers

### Special settings

* In an Intel x86 architecture environment:

  * We recommend that you modify the configuration file `/etc/sysctl.conf` and set the `vm.swappiness` parameter to `0`, as follows:

    ```bash
      [root@xxx /]
      $vi /etc/sysctl.conf
      vm.swappiness = 0
      ```

    Apply the values configured in the `sysctl.conf` configuration file:

    ```bash
      [root@xxx /]
      $sysctl -p    
      ```

* In an AMD or ARM architecture environment, we recommend that you enable NUMA.

* In an ARM or Hygon architecture environment, we recommend that you modify the configuration file `/etc/sysctl.conf` and set the `kernel.numa_balancing`, `vm.zone_reclaim_mode`, and `vm.swappiness` parameters to `0`, as follows:

  ```bash
   [root@xxx /]
   $vi /etc/sysctl.conf
   kernel.numa_balancing = 0
   vm.zone_reclaim_mode = 0
   vm.swappiness = 0
   ```

  Apply the values configured in the `sysctl.conf` configuration file:

  ```bash
   [root@xxx /]
   $sysctl -p
   ```

### BIOS options to be disabled

* C-State
* P-State
* EIST
* Power saving

### BIOS options to be configured

* Automatic Power on After Power Loss: Always on
* Intel Virtualization Technology: Enable
* Hyper-Threading: Enable
* Hardware prefetcher: Enable
* VT-d: Enable
* SR-IOV: Enable
* Turbo Mode: Enable
* Energy Performance: Maximum Performance

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>The methods for modifying BIOS settings vary among different servers. For specific operations, see the server operation manual.</p>
  </main>

## Disk mounting

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>If the capacity of a directory at a mount point is greater than 16 TB, only the xfs type is supported.</p>
</main>

* Disk mounting point requirements for OCP servers are shown in the following table.

  | Mounting point | Size | Purpose | Disk format |
  |------------|----------------|-------------|-------------------------|
  | /home      | 100 GB~300 GB | Operation log disk for components | Ext4 or XFS is recommended |
  | /data/log1 | 3~4 times the memory size   | OCP MetaDB log disk | Ext4 or XFS is recommended |
  | /data/1    | Depends on the required storage size for data   | OCP MetaDB data disk | Ext4 or XFS is recommended |
  | /docker    | 200 GB~500 GB | Docker root directory  | Ext4 or XFS is recommended |

* Disk mounting point requirements for OBServer nodes are shown in the following table.

  | Mounting point | Size | Purpose | File system format |
  |------------|----------------|----------------|-------------------------|
  | /home      | 100 GB~300 GB | Operation log disk of the observer process | Ext4 or XFS is recommended |
  | /data/log1 | 3~4 times the memory size   | Log disk of the observer process   | Ext4 or XFS is recommended |
  | /data/1    | Depends on the required storage size for data   | Data disk of the observer process   | Ext4 or XFS is recommended |

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>We recommend that the root directory is at least 50 GB. If you use LVM, we recommend that you use stripe parameters when creating directories. Example:</p>
    <p><code>lvcreate -n data -L 3000G obvg --stripes=3 --stripesize=128</code></p>
  </main>

### Server disk configuration

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>Do not separately mount the <code>/var</code> and <code>/opt</code> directories. </p>
</main>

* If the disk configuration is 480G*2 + 3.84T NVME*8 and the memory configuration is 512G:

  1. Configure two 480G system disks as RAID 1 to install the operating system. Mount 50G to the root directory and 350G to `/home`.
  2. Configure eight 3.84T disks as LVM. Then, allocate 2.1T to `/data/log1` as the log disk. Mount the remaining disks to `/data/1` as the data disk. (Select three servers as OCP servers and allocate 800G from `/data/1` to `/docker`.)

* If the disk configuration is 480G*2 + 3.84T SATA SSD*8 and the memory configuration is 512G:

  1. Configure two 480G system disks as RAID 1 to install the operating system. Mount 50G to the root directory and 350G to `/home`.
  2. Configure two disks as RAID 1 and allocate 2.1T to `/data/log1`. Configure the remaining six disks as RAID 5 and mount them to `/data/1` as the data disk. (Select three servers as OCP servers and allocate 800G from `/data/1` to `/docker`.)

* If the disk configuration is 480G*2 + 1.92T SATA SSD*6 and the memory configuration is 768G:

  1. Configure two 480G system disks as RAID 1 to install the operating system. Mount 50G to the root directory and 350G to `/home`.
  2. Configure three 1.92T disks as RAID 5 and allocate 3.1T to `/data/log1` as the log disk. Configure the remaining three 1.92T disks as RAID 5 and mount them to `/data/1` as the data disk. (Select three servers as OCP servers and allocate 800G from `/data/1` to `/docker`.)

* If the disk configuration is 480G*2 + 1.6T NVME*6 and the memory configuration is 768G:

  1. Configure two 480G system disks as RAID 1 to install the operating system. Mount 50G to the root directory and 350G to `/home`.
  2. Configure six 1.6T disks as LVM. Allocate 3.1T to `/data/log1` as the log disk. Mount the remaining disks to `/data/1` as the data disk. (Select three servers as OCP servers and allocate 800G from `/data/1` to `/docker`.)

* If the disk configuration is 960 SATA SSD*10 and the memory configuration is 384G:

  1. Configure four 960G disks as RAID 5. Mount 50G to the root directory and 500G to `/home`. Mount the remaining disks to `/data/log1`.
  2. Configure six 960G disks as RAID 5 and mount them to `/data/1`. (Select three servers as OCP servers and allocate 800G from `/data/1` to `/docker`.)

* If the disk configuration is 480G*2 + 1.6T SATA SSD*6 and the memory configuration is 384G:

  1. Configure two 480G system disks as RAID 1 to install the operating system. Mount 50G to the root directory and 350G to `/home`.
  2. Configure three disks as RAID 5 and allocate 2.1T to `/data/log1`. Configure the remaining three disks as RAID 5 and mount them to `/data/1`. (Select three servers as OCP servers and allocate 800G from `/data/1` to `/docker`.)

## NIC settings

We recommend that you configure two 10 Gbit/s NICs:

* Name the bond mode `bond0`. You can choose `mode1` or `mode4`, but `mode4` is recommended. For `mode4`, you must configure the 802.3ad protocol on the switch.
* We recommend that you name the NICs `eth0` and `eth1`.
* We recommend that you use the network service and do not use NetworkManager.
* We recommend that you do not use team for bonding because team prevents the system from identifying the speed of the NICs in `/sys/class/net/team0/speed`.
* All NICs in the same bond must be connected to different switches.

## RAID settings

* Enable write back for the cache of the RAID card.
* Disable disk cache.
* Enable automatic rebuild.
* For an LSI RAID card, disable consistency check and patrol read. After you replace or upgrade the RAID card or the driver or firmware of the RAID card, disable consistency check and patrol read again.

## Network ports

Make sure that the following network ports of OceanBase Database are not occupied:

| Server | Port | Description |
| --------- | ------ | ---- |
| OAT server | 7000 | OAT management console |
| OCP server | 8080 | OCP API/OCP-Server web service port |
| OBServer server | 2881 | OBServer SQL listening port |
| OBServer server | 2882 | RPC communication port between OBServer nodes |
| ODP server | 2883 | ODP listening port |
| ODP server | 2884 | ODP monitoring metrics API listening port |

For more information about the listening ports of other components, see [List of component listening ports](https://www.oceanbase.com/docs/common-ocp-1000000004276399).

## Recommendations for SSD I/O scheduler

* The default I/O scheduler for NVMe SSDs is `none`, and no adjustment is required.
* For SATA SSDs, we recommend that you set the I/O scheduler to `none`.

## Considerations

OceanBase Database has added requirements for the instruction set when running in an X86 architecture environment in V4.2.5 BP3, V4.2.5 BP4, V4.2.5 BP5, V4.3.5 BP1, V4.3.5 BP2, V4.3.5 BP3, and V4.4.0. The OBServer process checks whether the current environment supports the AVX instruction set before startup. If the AVX instruction set is not supported, startup is prohibited.
