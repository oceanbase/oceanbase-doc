# Software and hardware requirements

OceanBase Database is a distributed cluster product. At least three servers are required in the production environment. In a learning environment, you can deploy a standalone instance. OceanBase Database deployment shares much in common with traditional database deployment. Best practice recommendations are provided for operating system, hardware, and software configuration. These form the basis for OceanBase Database to achieve high performance and stable operation.

## Server configuration requirements

### Deploy OceanBase cluster with obd

The minimum available configuration requirements for servers are as follows:

| Item | Description |
|------|-------|
| Deployment product | OceanBase cluster and obd |
| Server count | <ul><li>Minimum 1 server in test environment</li><li>Minimum 3 servers in production environment</li></ul> |
| Minimum configuration for test and development | <ul><li>CPU: Minimum 2 cores, 4 cores or more recommended, 24 cores or more recommended for performance test scenarios.</li><li>Memory: Minimum 6 GB, 8 GB or more recommended, 128 GB to 1024 GB recommended for performance test scenarios.</li></ul> |
| Minimum configuration for production | <ul><li>CPU: Minimum 4 cores, 32 cores or more recommended.</li><li>Memory: Minimum 16 GB, 32 GB or more required for long-term use, 256 GB to 1024 GB recommended.</li></ul> |
| Disk configuration | Use SSD storage, minimum 20 GB.<main id="notice" type='explain'><h4>Note</h4><p>The log disk must be at least three times the memory size. The data disk must meet the storage requirements for target data volume.</p></main> |
| File system | ext4 or xfs. Only xfs is supported when data exceeds 16 TB. |

### Server BIOS settings

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>Different servers use different methods to modify BIOS settings. For specific operations, see the server operation manual.</p>
</main>

#### BIOS options to disable

* Cstate
* Pstate
* EIST
* Power saving

#### BIOS options to configure

* Automatic Power on After Power Loss: Always on
* Intel Virtualization Technology: Enable
* Hyper-threading: Enable
* Hardware prefetcher: Enable
* VT-d: Enable
* SR-IOV: Enable
* Turbo Mode: Enable
* Energy performance: Set to maximum performance

### Disable transparent huge pages

For Red Hat operating systems earlier than RHEL 9, run the following command to manually disable transparent huge pages:

```bash
echo never > /sys/kernel/mm/redhat_transparent_hugepage/enabled
```

For Red Hat operating system RHEL 9 or CentOS, run the following command to manually disable transparent huge pages:

```bash
echo never > /sys/kernel/mm/transparent_hugepage/enabled
```

## Hardware environment requirements

### CPU

If the machines to deploy OceanBase Database use the x86 architecture, the CPU must support AVX.

Run the following command to check whether the CPU supports AVX:

```shell
lscpu | grep Flags | grep avx
```

If the output does not contain `avx`, the CPU does not support AVX and the machine must be replaced. If the output contains `avx`, the CPU supports AVX.

### Memory

Run the following command to view memory:

```shell
free -g
```

Expected output:

```shell
              total        used        free      shared  buff/cache   available
Mem:            174          38           6           0         129         123
Swap:             0           0           0
```

Ensure that the `free` value under `Mem` is sufficient to meet the configuration requirements in **Server configuration requirements**. If not, clear the cache or replace the server.

You can run the following command to clear the cache:

```shell
sudo sysctl -w vm.drop_caches=3
# or
sudo echo 3 > /proc/sys/vm/drop_caches
```

### NIC settings

We recommend configuring two 10 GbE NICs:

For bond mode, name it `bond0`. The binding mode can be `mode1` or `mode4`. We recommend `mode4`. For `mode4`, the switch must be configured with the 802.3ad protocol.
