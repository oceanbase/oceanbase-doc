# (Optional) Configure limits.conf

This topic describes how to limit the number of processes by configuring the `limits.conf` file.

If you are an individual user, you can skip this topic. If you are an enterprise user, we recommend that you configure the `limits.conf` file.

You can modify resource limits at the global level by using the configuration file `/etc/security/limits.conf`. The limits for OceanBase Database processes include the maximum stack size (Stack), maximum number of file handles (Open Files), and core file size (Core File Size).

## Modify the configuration

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>You must perform this operation on each server. </p>
</main>

Set the session-level maximum stack size to `unlimited`, the maximum number of file handles to `655350`, and the core file size to `unlimited`.

Run the following command to open the `/etc/security/limits.conf` configuration file:

```shell
[admin@test001 ~]$ sudo vim /etc/security/limits.conf
```

Add the following content to the `/etc/security/limits.conf` configuration file:

```shell
* soft nofile 655350
* hard nofile 655350
* soft stack unlimited
* hard stack unlimited
* soft nproc 655360
* hard nproc 655360
* soft core unlimited
* hard core unlimited
```

<main id="notice" type='explain'>
  <h4>Note</h4>
  <ul>
  <li><p>You must check for the <code>nproc</code> configuration in the <code>/etc/security/limits.d/20-nproc.conf</code> file. If it exists, you must also modify the value of <code>nproc</code> in that file accordingly.</p></li>
  <li><p>The configuration in <code>limits.conf</code> takes effect only for new sessions (such as new terminals, SSH connections, or newly started processes). Existing sessions or processes do not automatically inherit the new configuration. You need to log in again or restart the related services.</p></li>
  </ul>
</main>

## View the configuration

Log off from the current session and log in again. Run the following command to check whether the configuration has taken effect:

```shell
[admin@test001 ~]$ ulimit -a
```

The output is as follows: 

```shell
core file size          (blocks, -c) unlimited
data seg size           (kbytes, -d) unlimited
scheduling priority             (-e) 0
file size               (blocks, -f) unlimited
pending signals                 (-i) 252876
max locked memory       (kbytes, -l) 64
max memory size         (kbytes, -m) unlimited
open files                      (-n) 655350
pipe size            (512 bytes, -p) 8
POSIX message queues     (bytes, -q) 819200
real-time priority              (-r) 0
stack size              (kbytes, -s) unlimited
cpu time               (seconds, -t) unlimited
max user processes              (-u) 655360
virtual memory          (kbytes, -v) unlimited
file locks                      (-x) unlimited
```

From the result, you can see that:

* `core file size` indicates the maximum threshold for core files (in blocks). It corresponds to the `core` parameter in the `limits.conf` configuration file. Check whether the value is `unlimited`.

* `open files` indicates the maximum number of open file descriptors. It corresponds to the `nofile` parameter in the `limits.conf` configuration file. Check whether the value is `655350`.

* `stack size` indicates the stack size (in kilobytes). It corresponds to the `stack` parameter in the `limits.conf` configuration file. Check whether the value is `unlimited`.

* `max user processes` indicates the maximum number of user processes. It corresponds to the `nproc` parameter in the `limits.conf` configuration file. Check whether the value is `655360`.
