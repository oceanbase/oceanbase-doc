# Overview

OceanBase Database Community Edition supports the following deployment methods:

* If you want to quickly deploy a single-node OceanBase Database for feature experience, refer to the Quick Deployment section.

* If you want to deploy OceanBase Database in a production environment, refer to the Standard Deployment section.

* If you want to experience OceanBase Database online, refer to the Online Experience section.

## Quick deployment

Quick deployment is suitable for deploying a single OceanBase Database instance on one server. This method helps you quickly build a working OceanBase Database environment. The deployed OceanBase Database instance supports basic database features, which can help you understand OceanBase Database. However, this environment does not support distributed capabilities or high availability. We recommend that you do not use this environment for a long time.

* For non-native operating systems (such as macOS and Windows), we recommend that you deploy OceanBase Database by using a Docker image. For more information, see [Deploy OceanBase Database in a container environment](200.local-deployment/700.deploy-by-docker.md).

* For native operating systems (Linux, see the list of supported operating systems), we recommend that you deploy OceanBase Database by using obd. For more information, see the [Quick Start/Quick Deployment](https://www.oceanbase.com/docs/community-obd-cn-1000000001882000) section of the OceanBase Installation and Deployment Tool documentation.

## Standard deployment

Standard deployment is suitable for users who want to understand the architecture and features of OceanBase Database. The deployed OceanBase Database cluster supports all database features and distributed high availability. You need to prepare at least three servers with 4 vCPUs, 16 GB of memory, and 100 GB of SSD or higher-performance disks.

* (Recommended) Manage OceanBase clusters by using the graphical interface

  If you want to deploy multiple OceanBase clusters, we recommend that you deploy OceanBase Cloud Platform (OCP). OCP helps you better manage and maintain OceanBase Database, significantly reducing the maintenance workload.

  First, deploy OCP and its MetaDB on three servers. For more information, see the [User Guide/Graphical Interface/Deploy OCP by using the graphical interface](https://www.oceanbase.com/docs/community-obd-cn-1000000002691294) section of the OceanBase Installation and Deployment Tool documentation. After OCP is deployed, you can create new OceanBase clusters on OCP to serve your business. For more information, see the [Cluster Management](https://www.oceanbase.com/docs/common-ocp-1000000002380760) section of the OceanBase Cloud Platform documentation.

  <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>MetaDB is used only as the metadata database of OCP. Do not use it for your business clusters. </p>
  </main>

* Manage OceanBase clusters by using commands

  If you only want to deploy one OceanBase cluster, you can deploy the cluster by using obd and then manage the cluster by using obd commands. For more information about how to deploy OceanBase clusters by using obd, see [Deploy OceanBase clusters by using the obd graphical interface](200.local-deployment/400.deploy-by-ui/100.deploy-by-obd.md) in the OceanBase Database documentation. For more information about obd commands, see [obd commands/cluster commands](https://www.oceanbase.com/docs/community-obd-cn-1000000002691284) in the OceanBase Installation and Deployment Tool documentation.

* Deploy OceanBase clusters in a Kubernetes environment

  This method is suitable for users who have deployed a large number of Kubernetes clusters in a production environment and have some experience with OceanBase Database. The deployed OceanBase Database cluster supports all database features and distributed high availability.

  Before you start, make sure that you meet the following conditions:

  * You have a Kubernetes cluster with at least 9 available CPUs, 33 GB of available memory, and 360 GB of available storage space.

  * ob-operator depends on cert-manager. Make sure that you have installed cert-manager. For more information about how to install cert-manager, see the corresponding [Installation Guide](https://cert-manager.io/docs/installation/).

  For more information about how to deploy OceanBase clusters in a Kubernetes environment, see [Deploy OceanBase clusters in a Kubernetes environment](300.deploy-in-the-k8s-cluster.md) in the OceanBase Database documentation.

## Online experience

For users who want to experience OceanBase Database online, log in to [OceanBase Experience Center](https://www.oceanbase.com/demo/deploy-a-oceanbase-ce-single-node-cluster) to try out the features.
