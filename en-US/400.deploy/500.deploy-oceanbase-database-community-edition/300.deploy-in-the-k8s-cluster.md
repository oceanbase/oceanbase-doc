# Deploy an OceanBase cluster in a Kubernetes environment

This topic describes how to deploy an OceanBase cluster in a Kubernetes environment. It can serve as a reference for production deployment.

## Prerequisites

Before you begin deployment, ensure that your environment meets the following requirements.

### Hardware resources

To ensure stability and performance in production, we recommend that the remaining Kubernetes resources meet the following configuration:

* CPU: 24 or more available CPUs.

* Memory: 72 GB or more available memory.

* Storage: Use SSD storage with 400 GB or more available space.

### Software dependencies

* Kubernetes cluster: Version v1.18 or later is required.

* helm: Used to deploy ob-operator and OceanBase Dashboard. For installation, see the [helm installation documentation](https://helm.sh/docs/intro/install/).

* cert-manager: ob-operator depends on cert-manager for certificate management. For installation, see the [cert-manager installation documentation](https://cert-manager.io/docs/installation/).

* Storage: The cluster must have an available storage class. We have tested some common storage systems. The following table shows the test results. You can refer to the storage compatibility test results to determine whether your environment meets the requirements. This topic uses [local-path-provisioner](https://github.com/rancher/local-path-provisioner) as an example.

  | Storage solution | Tested version | Compatible | Description |
  |----|----|----|----|
  | local-path-provisioner | 0.0.23 | ✅ | Recommended for development and test environments |
  | Rook CephFS | v1.6.7 | ❌ | CephFS does not support the fallocate system call |
  | Rook RBD (Block) | v1.6.7 | ✅ |  |
  | OpenEBS (cStor) | v3.6.0 | ✅ |  |
  | GlusterFS | v1.2.0 | ✅ | Compatible when the machine kernel version is 5.14 or later |
  | Longhorn | v1.6.0 | ✅ |  |
  | JuiceFS | v1.1.2 | ✅ |  |
  | NFS | v5.5.0 | ❌ | Cluster can start when NFS protocol >= 4.2, but tenant resources cannot be recycled |

* MySQL client or OBClient: Used to connect to the OceanBase cluster.

## Procedure

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This topic uses ob-operator V2.3.3 and OceanBase Dashboard V0.5.0 as examples. The procedure may vary slightly with other versions.</p>
</main>

### Step 1: Deploy ob-operator

ob-operator is the core control component of OceanBase in Kubernetes. We recommend deploying it by using Helm.

1. Add the ob-operator repository

   ```shell
   helm repo add ob-operator https://oceanbase.github.io/ob-operator/
   helm repo update ob-operator
   ```

2. Install ob-operator

   ```shell
   helm install ob-operator ob-operator/ob-operator --namespace=oceanbase-system --create-namespace
   ```

   `--namespace` is used to set the installation namespace. You can customize it as needed. We recommend using `oceanbase-system`.

3. Verify that the installation is successful

   ```shell
   kubectl get pod -n oceanbase-system
   ```

   The expected output is as follows. The pod `STATUS` should be `Running`.

   ```shell
   NAME                                            READY   STATUS    RESTARTS   AGE
   oceanbase-controller-manager-644b489fcc-6hlwf   2/2     Running   0          1m
   ```

### Step 2: Deploy OceanBase Dashboard

OceanBase Dashboard provides visual cluster management and monitoring capabilities.

1. Install OceanBase Dashboard

   ```shell
   helm install oceanbase-dashboard ob-operator/oceanbase-dashboard --namespace=oceanbase-system --set service.type=NodePort
   ```

   <main id="notice" type='explain'>
     <h4>Note</h4>
     <p>The default value of <code>service.type</code> is <code>NodePort</code>. If your environment supports LoadBalancer, you can set <code>service.type</code> to <code>LoadBalancer</code> to obtain an external IP.</p>
   </main>

2. Obtain the access address

   ```shell
   # View the service port
   kubectl get svc -n oceanbase-system oceanbase-dashboard-oceanbase-dashboard
   ```

3. Log in to OceanBase Dashboard

   Use the service port obtained in the previous step to access OceanBase Dashboard through a browser. The default username and password are both `admin`. You must change the password upon the first login.

   * If <code>service.type</code> is NodePort, access via `http://<any-node-IP>:<NodePort>`.

   * If <code>service.type</code> is LoadBalancer, access via `http://<External-IP>:<port>`.

### Step 3: Deploy an OceanBase cluster

After you log in to OceanBase Dashboard, click **Clusters** in the left-side navigation pane. On the Clusters page, click **Create Cluster** in the upper-right corner of **Cluster List** to open the **Create Cluster** page.

1. Configure basic information

   On this page, you can configure **namespace**, **cluster name**, **cluster mode**, **root password**, and other information.

   <!-- ![Basic information](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.4.1/400.deploy/500.community-edition/300.deploy-in-the-k8s-cluster-01.png) -->

   | Parameter | Description |
   |-------|-------|
   | Namespace | Select the namespace for creating the OceanBase cluster from the drop-down list. You can also click **+ Add Namespace** in the drop-down list to create a new namespace. When adding a namespace, the name must start with a lowercase letter and end with a lowercase letter or digit. It can contain lowercase letters, digits, and `-`, and must not exceed 63 characters. |
   | Resource name | The OceanBase cluster custom resource in Kubernetes. It cannot be the same as an existing OceanBase cluster resource name in the same namespace. When customizing, the name must start with a lowercase letter and end with a lowercase letter or digit. It can contain lowercase letters, digits, and `-`, and must not exceed 63 characters. |
   | Cluster name | The OceanBase cluster name. It must start with a letter and end with a letter or digit. It can contain letters, digits, and underscores, and must be 2 to 32 characters in length. |
   | Cluster mode | Select the cluster deployment mode from the drop-down list. Different cluster modes have different requirements for the OceanBase Database version and affect the recovery strategy when failures occur. Select based on your environment and cluster version.<ul><li><b>Normal mode:</b> No special processing. Bootstrap is performed directly using pod IP addresses. Currently supports calico and kube-ovn plugins. When rebuilding a failed pod, the previous IP address is used. We recommend allocating a separate network segment for the OceanBase cluster to avoid occupation by other pods. If the K8s cluster uses other network plugins, a scale-out-then-scale-in recovery strategy is used, which often takes longer to replicate large amounts of data and cannot recover from majority-node failure scenarios.</li><li><b>Standalone mode:</b> Uses <code>127.0.0.1</code> for bootstrap. Only for single-node cluster deployment. Since <code>127.0.0.1</code> is specified as the OBServer service address, data can be reused for quick recovery when a pod is rebuilt.</li><li><b>Service mode:</b> Creates a service for each OBServer service and uses the service cluster IP address for bootstrap. Data can also be reused for quick recovery when a pod is rebuilt. We recommend this mode in general.</li></ul> |
   | Optimization scenario | Provides parameter templates for common OceanBase cluster usage scenarios. Selecting a scenario automatically configures parameters. |
   | root password | The root user password of the sys tenant. You can click **Random generate** to have Dashboard automatically generate a random string, or set a custom password. For custom passwords: <ul><li>Length: 8-32 characters</li><li>Can only contain letters, digits, and special characters (<code>~!@#%^&*_-+=\|()[]:;,.?/</code>)</li><li>Must contain at least 2 of each: uppercase letters, lowercase letters, digits, and special characters</li></ul>After configuration, you can click **Copy password** to copy and save the configured password. |
   | Deletion protection | Select to enable or disable deletion protection. When enabled, deletion of the OceanBase cluster will be intercepted by the webhook. You must disable it before the cluster can be deleted. |
   | Advanced configuration | Click the expand icon after **Advanced configuration** to configure **proxyro password**. When **Advanced configuration** is not opened, Dashboard automatically generates a random string as the proxyro password.<br>The proxyro password is the proxyro user password of the sys tenant. ODP can access the corresponding OceanBase cluster only when the proxyro password in the OceanBase cluster matches that in ODP. You can click **Random generate** to have Dashboard generate a random string, or set a custom password. For custom passwords, the same requirements as root password apply. |

   Cluster topology mainly configures all Zone information for the cluster. Generally, at least 3 Zones need to be configured. You can click **+ Add Zone** or the delete icon after a Zone to add or remove Zones.

   | Parameter | Description |
   |-------|-------|
   | Zone name | The Zone name in OceanBase Database. Can be customized. Must start with a letter and end with a letter or digit. Can contain letters, digits, and underscores. Length: 2-32 characters. |
   | Server count | The number of OBServer services in the current Zone. |
   | K8s cluster | This parameter applies only to multi-K8s cluster deployment. Used to set which K8s cluster this Zone is deployed to. Can be left empty for single-K8s cluster deployment. |
   | Topology | Click the expand button before **Topology** to configure affinity (node selector, pod affinity, and toleration). The configuration applies only to OBServer service pods in the current Zone. |

The configuration for data, runtime logs, and redo logs must be at least three times the **memory** configuration. Supports independent lifecycle for PVCs. ### Step 4: Create a tenant

After the cluster is deployed, we recommend creating a business tenant for application use. Click **Tenants** in the left-side navigation pane. On the Tenants page, click **Create Tenant** in the upper-right corner of **Tenant List** to open the **Create Tenant** page.

1. Enter basic tenant information

   <!-- ![Basic information](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.4.1/400.deploy/500.community-edition/300.deploy-in-the-k8s-cluster-06.png) -->

   | Parameter | Description |
   |--------|-------|
   | OB cluster | Select the OceanBase cluster for the tenant from the drop-down list. |
   | Resource name | The tenant custom resource name in Kubernetes. The tenant is created in the same namespace as the cluster. |
   | Tenant name | The name of the tenant to be created. |
   | Password | The root account password of the tenant. You can click **Random generate** or set a custom password. For custom passwords, the same requirements as root password apply. |
   | Optimization scenario | Provides parameter templates for common OceanBase Database usage scenarios. Selecting a scenario automatically configures parameters. |
   | Connection allowlist | The allowlist addresses that can connect to the tenant. Default `%` indicates any address. |
   | Deletion protection | Select to enable or disable deletion protection. When enabled, deletion of the tenant will be intercepted by the webhook. |

2. Configure tenant resource pool

   <!-- ![Resource configuration](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.4.1/400.deploy/500.community-edition/300.deploy-in-the-k8s-cluster-08.png) -->

   | Parameter | Description |
   |--------|-------|
   | Replica distribution | Click the checkboxes before each Zone to configure which Zones the tenant is distributed in, and set the priority, replica type, and unit count for each Zone. |
   | Resource unit specification | Configure the resources for each unit of the tenant. We recommend configuring based on the **Available resources** displayed in the **Replica distribution** module. |

3. Submit and wait for creation to succeed

   After configuration, click **Submit**. Wait until **Status** in **Tenant List** changes to **Running** to indicate that the tenant has been created successfully.

### Step 5: Deploy ODP

ODP (also known as OBProxy) is a necessary component for applications to connect to a distributed OceanBase cluster. It routes requests to the correct OBServer nodes. Click **OBProxy** in the left-side navigation pane. On the OBProxy page, click **Create OBProxy Cluster** in the upper-right corner of **Cluster List** to open the **Create OBProxy Cluster** page.

1. Configure basic information

   <!-- ![Basic information](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.4.1/400.deploy/500.community-edition/300.deploy-in-the-k8s-cluster-10.png) -->

   | Parameter | Description |
   |-------|------|
   | Resource name | The deployment name created in Kubernetes. Must start with a lowercase letter and end with a lowercase letter or digit. Can contain lowercase letters, digits, and `-`. Length must not exceed 63 characters. |
   | OBProxy cluster name | The ODP application name. |
   | Connect to OB cluster | Select the OceanBase cluster to connect to from the drop-down list. By default, rs_list is used to connect to the selected OceanBase cluster. |
   | Namespace | The Kubernetes namespace for deploying ODP. After selecting an OceanBase cluster, the namespace of the selected OceanBase cluster is automatically filled. |
   | OBProxy root password | The root user password of the ODP management tenant (`proxysys`). You can click **Random generate** or set a custom password. For custom passwords, the same requirements as root password apply. |

2. More configuration

   <!-- ![More configuration](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.4.1/400.deploy/500.community-edition/300.deploy-in-the-k8s-cluster-11.png) -->

   | Parameter | Description |
   |--------|-------|
   | Image | The image for deploying ODP. You can click **Image list** to view all images. We recommend deploying the latest version. The image tag corresponds to the ODP version. Use the full format `registry/image:tag`, for example `oceanbase/obproxy-ce:4.3.3.0-5`. |
   | Service type | Select the service type for ODP from the drop-down list. For access only within the Kubernetes cluster, use ClusterIP. For access from outside the cluster, choose NodePort or LoadBalancer as appropriate. |
   | Replicas | The number of ODP replicas. |
   | CPU cores | The CPU cores allocated to ODP. |
   | Memory size | The memory resources allocated to ODP. |
   | Parameter settings | Click **+ Add** to configure ODP parameters in key-value format. |

3. Submit and wait for creation to succeed

   After completing the configuration above, click **Submit**. Wait until **Status** in **Cluster List** changes to **Running** to indicate that ODP has been created successfully.
