# Deploy an OceanBase cluster in a Kubernetes environment

This topic describes how to deploy an OceanBase cluster in a Kubernetes environment, which can be used as a reference for production deployment. For more information about custom deployment and configuration methods, see [OceanBase K8s O&M tool documentation](https://www.oceanbase.com/docs/ob-operator-doc).

## Prerequisites

Before you deploy OceanBase Database, make sure that your environment meets the following requirements.

### Hardware resources

To ensure the stability and performance of the production environment, we recommend that you configure the following resources for the Kubernetes cluster:

* CPU: 24 or more available CPU cores.

* Memory: 72 GB or more available memory.

* Storage: SSD storage with 400 GB or more available space.

### Software dependencies

* Kubernetes cluster: v1.18 or later.

* Helm: used to deploy ob-operator and OceanBase Dashboard. For more information, see [Install Helm](https://helm.sh/docs/intro/install/).

* Cert-manager: ob-operator depends on cert-manager for certificate management. For more information, see [Install cert-manager](https://cert-manager.io/docs/installation/).

* Storage: The cluster must have an available storage class. We have tested some common storage systems. The following table lists the results. You can refer to the test results to determine whether the storage system meets your requirements. In this topic, we use [local-path-provisioner](https://github.com/rancher/local-path-provisioner) as an example.

  | Storage system | Tested version | Compatibility | Description |
  |----|----|----|----|
  | local-path-provisioner | 0.0.23 | ✅ | Recommended for development and test environments |
  | Rook CephFS | v1.6.7 | ❌ | CephFS does not support the fallocate system call. |
  | Rook RBD (Block) | v1.6.7 | ✅ |  |
  | OpenEBS (cStor) | v3.6.0 | ✅ |  |
  | GlusterFS | v1.2.0 | ✅ | Compatible with Linux kernels of 5.14 or later |
  | Longhorn | v1.6.0 | ✅ |  |
  | JuiceFS | v1.1.2 | ✅ |  |
  | NFS | v5.5.0 | ❌ | A cluster can be started with NFS protocol 4.2 or later, but tenant resources cannot be recycled. |

* MySQL client or OBClient: used to connect to an OceanBase cluster.

## Procedure

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>The following procedure applies to ob-operator V2.3.3 and OceanBase Dashboard V0.5.0. The procedure may vary for other versions. </p>
</main>

### Step 1: Deploy ob-operator

ob-operator is the core management component of OceanBase in Kubernetes. We recommend that you deploy ob-operator by using Helm.

1. Add the ob-operator repository.

   ```shell
   helm repo add ob-operator https://oceanbase.github.io/ob-operator/
   helm repo update ob-operator
   ```

2. Install ob-operator.

   ```shell
   helm install ob-operator ob-operator/ob-operator --namespace=oceanbase-system --create-namespace
   ```

   The `--namespace` option specifies the namespace where ob-operator is to be installed. You can customize the namespace as needed. We recommend that you use `oceanbase-system`.

3. Verify whether ob-operator is installed.

   ```shell
   kubectl get pod -n oceanbase-system
   ```

   The expected output is as follows, where the `STATUS` of the pod is `Running`.

   ```shell
   NAME                                            READY   STATUS    RESTARTS   AGE
   oceanbase-controller-manager-644b489fcc-6hlwf   2/2     Running   0          1m
   ```

### Step 2: Deploy OceanBase Dashboard

OceanBase Dashboard provides visual cluster management and monitoring capabilities.

1. Install OceanBase Dashboard.

   ```shell
   helm install oceanbase-dashboard ob-operator/oceanbase-dashboard --namespace=oceanbase-system --set service.type=NodePort
   ```

   <main id="notice" type='explain'>
     <h4>Note</h4>
     <p>The default value of <code>service.type</code> is <code>NodePort</code>. If your environment supports LoadBalancer, you can set <code>service.type</code> to <code>LoadBalancer</code> to obtain an external IP address. </p>
   </main>

2. Obtain the access address.

   ```shell
   # View the service port
   kubectl get svc -n oceanbase-system oceanbase-dashboard-oceanbase-dashboard
   ```

3. Log in to OceanBase Dashboard.

   You can use the service port obtained in the previous step to access OceanBase Dashboard in a browser. The default username and password are both `admin`. You must change the password for the first login.

   * If <code>service.type</code> is set to NodePort, you can access OceanBase Dashboard by using `http://<IP address of any node>:<NodePort port>`.

   * If <code>service.type</code> is set to LoadBalancer, you can access OceanBase Dashboard by using `http://<External-IP>:<port>`.

   | Parameter  | Description   |
   |-------|-------|
   | Namespace | Select the namespace from the drop-down list to create an OceanBase cluster. You can also click **+ Add Namespace** in the drop-down list to create a new namespace. When you create a new namespace, the namespace name must start with a lowercase letter and end with a lowercase letter or a digit. It can contain lowercase letters, digits, and hyphens (-), and must be no longer than 63 characters. |
   | Resource Name  | The custom resource name of the OceanBase cluster in Kubernetes. It must be unique in the same namespace. When you create a custom resource name, the name must start with a lowercase letter and end with a lowercase letter or a digit. It can contain lowercase letters, digits, and hyphens (-), and must be no longer than 63 characters. |
   | Cluster Name | The name of the OceanBase cluster. The cluster name must start with an English letter and end with an English letter or a digit. It can contain English letters, digits, and underscores (_), and must be 2 to 32 characters in length.  |
   | Cluster Mode | Select the cluster deployment mode from the drop-down list. Different cluster deployment modes have different requirements on the version of OceanBase Database. The cluster deployment mode also affects the fault recovery strategy. You must select the deployment mode based on the actual environment and cluster version.<ul><li><b>General Mode:</b> In this mode, no special processing is performed. The pod IP address is directly used for bootstrap. Currently, this mode can identify the calico and kube-ovn plugins. When a pod fails, the IP address before the failure is used for pod reconstruction. We recommend that you allocate a dedicated network segment for the OceanBase cluster to avoid being occupied by other pods. If the Kubernetes cluster uses other network plugins, the fault recovery strategy involves expansion and scaling down, which often takes a long time to replicate a large amount of data and cannot recover from a majority node failure.</li><li><b>Single Node Mode:</b> In this mode, the <code>127.0.0.1</code> IP address is used for bootstrap. This mode is only for deploying a single-node cluster. Since the <code>127.0.0.1</code> IP address is specified as the OBServer service address, the original data can be reused for quick recovery when the pod is rebuilt.</li><li><b>Service Mode:</b> In this mode, a service is created for each OBServer service. The cluster IP address of the service is used for bootstrap. The original data can also be reused for quick recovery when the pod is rebuilt. We recommend that you use this mode. </li></ul>  |
   | Optimization Scenario | You can select a commonly used OceanBase cluster usage scenario from the drop-down list to automatically configure the parameters. For more information about the optimization scenarios, see [Best Practices](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000004475424). |
   | Root Password  | The password of the root user of the sys tenant. You can click **<UI-TERM key="oat.pages.User.RandomGeneration">Randomly generated</UI-TERM>** to let the Dashboard generate a random string. You can also set a custom password. When you set a custom password, it must meet the following requirements:<ul><li>8 to 32 characters in length</li><li>Contain only letters, digits, and special characters (<code>~!@#%^&*_-+=\|()[]:;,.?/</code>)</li><li>Contain at least two uppercase letters, two lowercase letters, two digits, and two special characters</li></ul>After you configure the password, you can click **<UI-TERM key="oat.components.StrengthPassword.CopyPassword">Copy Password</UI-TERM>** to copy the password. |
   | Delete Protection  | You can enable or disable delete protection. If you enable delete protection, the operation to delete the OceanBase cluster will be intercepted by a webhook. You must disable delete protection to delete the cluster.  |
   | Advanced Configuration | You can click the expand icon next to **<UI-TERM key="oat.Config.New.NewODC.AdvancedConfiguration">Advanced Configuration</UI-TERM>** to configure the **proxyro Password**. If you do not enable **<UI-TERM key="ocp-v2.component.S3StorageBackupConfig.AdvancedConfiguration">Advanced Configuration</UI-TERM>**, the Dashboard will automatically generate a random string as the proxyro password.<br>The proxyro password is the password of the proxyro user of the sys tenant. If the proxyro password of the OceanBase cluster is the same as that of the ODP, the ODP can access the OceanBase cluster. You can click **<UI-TERM key="oat.pages.User.RandomGeneration">Randomly generated</UI-TERM>** to let the Dashboard generate a random string. You can also set a custom password. When you set a custom password, it must meet the following requirements:<ul><li>8 to 32 characters in length</li><li>Contain only letters, digits, and special characters (<code>~!@#%^&*_-+=\|()[]:;,.?/</code>)</li><li>Contain at least two uppercase letters, two lowercase letters, two digits, and two special characters</li></ul>After you configure the password, you can click **<UI-TERM key="oat.components.Password.CopyPassword">Copy Password</UI-TERM>** to copy the password.  |

### Step 5: Deploy ODP

ODP (also known as OBProxy) is a necessary component for applications to connect to a distributed OceanBase cluster. It routes requests to the correct OBServer node. You can click **OBProxy** in the left-side navigation pane, and then click **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">Clusters</UI-TERM>** in the upper-right corner of the OBProxy page to go to the **Create OBProxy Cluster** page.

1. Configure basic information.

   ![Basic information](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.4.1/400.deploy/500.community-edition/300.deploy-in-the-k8s-cluster-10.png)

   | Parameter  | Description  |
   |-------|------|
   | Resource Name | The name of the deployment created in Kubernetes. The name must start with a lowercase letter and end with a lowercase letter or a digit. It can contain lowercase letters, digits, and hyphens (-), and must be no longer than 63 characters.  |
   | OBProxy Cluster Name | The application name of ODP.  |
   | Connect to OceanBase Cluster | You can select an OceanBase cluster from the drop-down list. By default, the selected OceanBase cluster is connected by using the rs_list method.  |
   | Namespace | The namespace in which ODP is deployed in Kubernetes. After you select an OceanBase cluster, the namespace of the selected OceanBase cluster is automatically filled in.  |
   | OBProxy Root Password | The password of the `root` user of the ODP management tenant (`proxysys`). You can click **<UI-TERM key="oat.pages.User.RandomGeneration">Randomly generated</UI-TERM>** to let the Dashboard generate a random string, or you can set a custom password. If you set a custom password, it must meet the following requirements:<ul><li>Length: 8 to 32 characters</li><li>Must contain only letters, digits, and special characters (<code>~!@#%^&*_-+=\|()[]:;,.?/</code>)</li><li>Must contain at least two uppercase letters, two lowercase letters, and two digits</li></ul>After you set the password, you can click **<UI-TERM key="oat.components.StrengthPassword.CopyPassword">Copy Password</UI-TERM>** to copy the password. |

2. Configure more parameters.

   ![More parameters](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.4.1/400.deploy/500.community-edition/300.deploy-in-the-k8s-cluster-11.png)

   | Parameter  | Description  |
   |--------|-------|
   | Image  | The image used to deploy ODP. You can click **Image List** to view all images. We recommend that you deploy the latest version. The image tag corresponds to the ODP version number.
