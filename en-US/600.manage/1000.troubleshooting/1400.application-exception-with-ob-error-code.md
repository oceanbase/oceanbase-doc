# Application exception -- error message contains an OceanBase error code

During database operation, various exceptions may occur, such as application errors, database connection errors, database permission issues, database resource issues, and network problems. One such exception is an application exception where the error message contains an OceanBase error code.

To help you quickly identify the root cause of such exceptions and efficiently resolve them, this topic provides a clear and practical troubleshooting process for application exceptions with error messages containing OceanBase error codes. The process offers step-by-step guidance to improve problem-solving efficiency and minimize business impact, thereby supporting your routine O&M work.

## Procedure

When an application execution exception is reported with OceanBase error codes, you can troubleshoot the issue by following this procedure.

First, determine whether you can use OBClient to connect to the database and manually reproduce the issue:

* If yes, connect to the database after the issue is reproduced for further troubleshooting.

* If no, troubleshoot the program configuration's data source information.

### Troubleshoot the issue by reproducing it

1. Use OBClient to connect to the OceanBase cluster at port 2881 (the default SQL port). If you specified a custom port, use the custom port instead.

2. Manually execute the SQL statement that returns an error to reproduce the issue.

3. Execute the following statement to obtain the `trace_id`.

    <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>You must execute the following statement immediately after the SQL statement that returns an error is executed; otherwise, the <code>trace_id</code> of the SQL statement that returns an error cannot be obtained. </p>
    </main>

    :::tab
    tab MySQL mode

    The following statement is used to obtain the `trace_id` in MySQL mode:

    ```shell
    obclient> SELECT last_trace_id();
    ```

    tab Oracle mode

    The following statement is used to obtain the `trace_id` in Oracle mode:

    ```shell
    obclient> SELECT last_trace_id() FROM DUAL;
    ```

    :::

4. Obtain the host information where the SQL statement is actually executed.

    OceanBase clusters are generally deployed across multiple nodes. You can execute the following SQL statement to obtain the node where the SQL statement is actually executed, and then filter the logs.

    :::tab
    tab MySQL mode

    Execute the following statement in MySQL mode:

    ```shell
    obclient> SELECT * FROM oceanbase.GV$OB_SQL_AUDIT WHERE trace_id=last_trace_id;
    ```

    Replace `last_trace_id` with the `trace_id` obtained in the previous step.

    tab Oracle mode

    Execute the following statement in Oracle mode:

    ```shell
    obclient> SELECT * FROM SYS.GV$OB_SQL_AUDIT WHERE trace_id=last_trace_id;
    ```

    Replace `last_trace_id` with the `trace_id` obtained in the previous step.

    :::

    According to the query result of the `GV$OB_SQL_AUDIT` view, the host corresponding to `svr_ip` is the host where the SQL statement is actually executed.

5. Use the `ssh` command to log in to the host based on the obtained host information.

6. Go to the log directory.

    Assume that the installation directory of OceanBase Database is `/home/admin/oceanbase`. The following example shows the specific path of logs, which may vary depending on your actual environment.

    ```shell
    cd /home/admin/oceanbase/log
    ```

7. Execute the following command to filter out the relevant information from the logs.

    ```shell
    grep "${trace_id}" observer.log
    ```

    ```shell
    grep "${trace_id}" observer.log.xxx
    ```

    Replace `${trace_id}` with the `trace_id` obtained earlier. Replace `observer.log.xxx` with the log file that contains a timestamp, and replace `xxx` with the actual timestamp when the SQL statement was executed.

8. Based on the information provided in the logs and the error messages, analyze the issue.

    For more information about logs, see [Overview](../800.logging/100.logging-overview.md). If the information in the logs is unclear, contact Technical Support for assistance.

### Troubleshoot the data source configuration

1. Based on the data source, identify the access link.

2. The access link contains the following information:

    * The number and addresses of OBProxy

    * The number and addresses of OBServer hosts

3. Determine whether OBProxy is involved.

    * If yes, follow these steps to troubleshoot the issue:

      1. Run the `ssh` command to log in to the corresponding OBProxy node.

      2. Run the `cd` command to go to the log directory of OBProxy. The OBProxy logs are stored in the `/log` directory under its installation directory.

      3. Run the following command to filter out the error logs:

         ```shell
         grep "Error text" obproxy_error.log obproxy_error.log.xxx | grep "Error time"
         ```

      4. Identify the OBServer node that the error SQL statement is routed to based on the filtered log entries.

      5. Run the `ssh` command to log in to the corresponding OBServer node for troubleshooting.

    * If not, follow these steps to troubleshoot the issue:

      1. Run the `ssh` command to log in to the corresponding OBProxy node.

      2. Go to the log directory.

         Assume that the installation directory of OceanBase Database is `/home/admin/oceanbase`. The specific log path depends on your actual setup.

         ```shell
         cd /home/admin/oceanbase/log
         ```

      3. Run the following command to filter out the error logs:

         ```shell
         grep "sending error" observer.log observer.log.xxx | grep "Error code"
         ```

      4. Obtain the trace_id from the filtered logs, and then filter the logs again using trace_id.

         ```shell
         grep "trace id" observer.log observer.log.xxx
         ```

      5. Analyze the issue based on the information provided in the logs and related error messages.

         For more information about logs, see [Overview](../800.logging/100.logging-overview.md). If the information in the logs is unclear, contact technical support for assistance.
