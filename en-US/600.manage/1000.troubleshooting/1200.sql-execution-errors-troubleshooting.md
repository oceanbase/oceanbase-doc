# Troubleshooting SQL execution errors

In database operations, SQL execution errors are very common and can have a direct impact on business operations. There are many reasons for SQL execution errors, such as incorrect database connection, insufficient user permissions, syntax errors, or data not meeting query conditions.

To help you quickly identify the root cause and efficiently resolve the issue, we have summarized a clear and practical SQL error troubleshooting process. This process provides specific steps to improve the efficiency of issue resolution and minimize the impact on business operations, providing strong support for daily maintenance tasks.

The SQL execution error troubleshooting process is shown in the following figure.

![SQL execution error troubleshooting process](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.3.5/troublethooting/V4xsql-execution-troubleshooting-new1.png)

## Procedure

When an error occurs during SQL execution, follow these steps to troubleshoot the issue.

After an SQL error occurs, first check the error message. If the error message contains a specific error code, use the error code to troubleshoot the issue. If the error message does not contain a specific error code, determine whether the error is caused by an application or by manual SQL execution:

1. If the error is caused by an application, refer to [Application exceptions with no OceanBase Database error code](1300.application-exception-without-ob-error-code.md) and [Application exceptions with OceanBase Database error code](1400.application-exception-with-ob-error-code.md) for troubleshooting.

2. If the error is caused by manual SQL execution, determine whether the error can be reproduced.

   1. If the error cannot be reproduced, search for relevant information in the [Knowledge Base](https://www.oceanbase.com/knowledge-base/oceanbase-database-1000000000324072) based on the SQL statement.
   2. If the error can be reproduced, reproduce the issue. Connect to the OceanBase cluster through port 2881 or 2883, and execute the original SQL statement to reproduce the issue.

      After reproducing the SQL error, collect the following information to troubleshoot the issue.

      1. Execute the following statement to obtain the `trace_id`.

         <main id="notice" type='notice'>
         <h4>Notice</h4>
         <p>Execute the following statement immediately after the error occurs. Otherwise, the query will not return the <code>trace_id</code> of the error SQL statement. </p>
         </main>

         :::tab
         tab MySQL mode

         In MySQL mode, execute the following statement to obtain the `trace_id`:

         ```shell
         obclient> SELECT last_trace_id();
         ```

         tab Oracle mode

         In Oracle mode, execute the following statement to obtain the `trace_id`:

         ```shell
         obclient> SELECT last_trace_id() FROM DUAL;
         ```

         :::

      2. Obtain the host information where the SQL statement was actually executed based on the `trace_id`.

         OceanBase Database is typically deployed in a multi-node cluster. You can execute the following SQL statement to obtain the node where the SQL statement was actually executed, and then filter the logs.

         :::tab
         tab MySQL mode

         In MySQL mode, execute the following statement:

         ```shell
         obclient> SELECT * FROM oceanbase.GV$OB_SQL_AUDIT WHERE trace_id=last_trace_id;
         ```

         Replace `last_trace_id` with the `trace_id` obtained in the previous step.

         tab Oracle mode

         In Oracle mode, execute the following statement:

         ```shell
         obclient> SELECT * FROM SYS.GV$OB_SQL_AUDIT WHERE trace_id=last_trace_id;
         ```

         Replace `last_trace_id` with the `trace_id` obtained in the previous step.

         :::

         Based on the query result of the `GV$OB_SQL_AUDIT` view, the host corresponding to `svr_ip` is the host where the SQL statement was actually executed.

      3. Use the `ssh` command to log in to the host.

      4. Go to the log directory.

         The following example assumes that the installation directory of OceanBase Database is `/home/admin/oceanbase`. The actual log path may vary.

         ```shell
         cd /home/admin/oceanbase/log
         ```

      5. Run the following commands to filter the relevant information from the logs.

         ```shell
         grep "${trace_id}" observer.log
         ```

         ```shell
         grep "${trace_id}" observer.log.xxx
         ```

         In these commands, `${trace_id}` should be replaced with the `trace_id` obtained in the previous step. `observer.log.xxx` refers to a log file with a timestamp, and `xxx` should be replaced with the actual timestamp corresponding to the time when the SQL error occurred.

      6. Analyze the issue based on the information provided in the logs, along with the error codes or related error messages.

         For more information about logs and error codes, see [Overview of Logs](../800.logging/100.logging-overview.md) and [Overview of Error Messages](../../700.reference/900.error-code/600.error-code-of-mysql-mode/100.use-error-information-of-mysql-mode.md).

         If the information in the logs is unclear, contact technical support for assistance.

## Examples

The following examples describe how to troubleshoot SQL execution errors.

:::tab
tab MySQL mode

* When an SQL error occurs, the database returns an error code.

  * When a `SELECT` statement contains a large number of `OR` conditions, a large number of `AND`-connected `IN` conditions, or a large number of `AND NOT` conditions, the statement execution returns an error `-4013, No memory or reach tenant memory limit`. For more information, see [SQL parsing error -4013, tenant memory is full](https://www.oceanbase.com/knowledge-base/oceanbase-database-1000000000209941?back=kb).

* The error code is recorded in the log.

  * When an SQL statement processes a `longtext` field, an error `ErrorCode=5098` is returned. For more information, see [SQL error: Varchar value is too long for the column](https://www.oceanbase.com/knowledge-base/oceanbase-database-1000000000670003?back=kb).

  * When an SQL statement returns an error `-4119 (RPC packet to send too long)`, you can query the `observer.log` file by using the `trace_id` to obtain the information `obrpc packet payload execced its limit`. For more information, see [SQL execution error -4119, RPC packet to send too long](https://www.oceanbase.com/knowledge-base/oceanbase-database-1000000000210005?back=kb).

* Other error information is recorded in the log.

  * When the number of conditions for different fields in the filter clause of an SQL statement exceeds 64, an error `-4002 Invalid argument` is returned. For more information, see [SQL filter clause error -4002, the number of conditions for different fields exceeds 64](https://www.oceanbase.com/knowledge-base/oceanbase-database-1000000000450149?back=kb).

tab Oracle mode

* When an SQL error occurs, the database returns an error code.

  * When a query statement contains the `c1`, `c2`, and `c3` columns, and the `c1` and `c2` columns hit an index, and multiple `IN` expressions exist on the `c1` or `c2` columns, an error `internal error` is returned when the statement is executed. The error code is `ORA-00600`. For more information, see [SQL execution error 4016, multiple IN and vector expressions are specified](https://www.oceanbase.com/knowledge-base/oceanbase-database-20000043623?back=kb).

* The error code is recorded in the log.

  * When an SQL statement returns an error `Timeout`, the error code is `ORA-00600`. For more information, see [SQL execution error timeout](https://www.oceanbase.com/knowledge-base/odc-1000000000262293?back=kb).

:::
