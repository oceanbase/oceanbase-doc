# Manually trigger partition balancing

In addition to configuring a scheduled partition balancing task, you can manually trigger a partition balancing by calling the `TRIGGER_PARTITION_BALANCE` subprogram in the `DBMS_BALANCE` system package.

## Limitations

Manual partition rebalancing is supported only for user tenants, not for the sys tenant.

## Considerations

* If other rebalancing tasks are ongoing in the system, you cannot manually trigger a partition rebalancing task. You need to wait for the current rebalancing task to complete before manually triggering a partition rebalancing task.

   The sys tenant can check the [CDB_OB_BALANCE_JOBS](../../../700.reference/700.system-views/300.system-view-of-sys-tenant/200.dictionary-view-of-sys-tenant/7800.o-cdb_ob_balance_jobs-of-sys-tenant.md) view to see if other rebalancing tasks are ongoing for a specified tenant. User tenants can check the [DBA_OB_BALANCE_JOBS](../../../700.reference/700.system-views/400.system-view-of-mysql-mode/200.dictionary-view-of-mysql-mode/7800.o-dba_ob_balance_jobs-of-mysql-mode.md) view to see if other rebalancing tasks are ongoing.

* Before manually triggering a partition rebalancing task, make sure that the values of the `enable_rebalance` and `enable_transfer` parameters at the tenant level are both `True`. If either parameter is not set to `True`, the manual partition rebalancing command will fail.

* If the partitions in the current tenant are already balanced, the system will display the error message `partitions are already balanced, no need to trigger partition balance`.

## Manually trigger a partition balance

1. Log in to the MySQL or Oracle tenant of the cluster as a tenant administrator.

   The following example shows how to connect to the MySQL tenant. Replace the actual values with those in your environment.

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql_tenant#obdemo -p***** -A
   ```

2. Call the `TRIGGER_PARTITION_BALANCE` subprogram in the `DBMS_BALANCE` system package to manually trigger a partition balance.

    :::tab
    tab MySQL mode

    The statement in MySQL mode is as follows:

    ```sql
    CALL DBMS_BALANCE.TRIGGER_PARTITION_BALANCE(balance_timeout);
    ```

    The `balance_timeout` parameter specifies the timeout period for the background partition balance task, in seconds. If you do not specify this parameter, the background partition balance task does not have a timeout period. The task continues to run until it is completed.

    Here are some examples:

    * Trigger a partition balance without a timeout period.

      ```shell
      obclient [oceanbase]> CALL DBMS_BALANCE.TRIGGER_PARTITION_BALANCE();
      ```

    * Trigger a partition balance with a timeout period of 7200 seconds.

      ```shell
      obclient [oceanbase]> CALL DBMS_BALANCE.TRIGGER_PARTITION_BALANCE(7200);
      ```

    For more information about the `TRIGGER_PARTITION_BALANCE` subprogram in the `DBMS_BALANCE` system package, see [TRIGGER_PARTITION_BALANCE](../../../700.reference/600.pl-reference/200.pl-mysql/1000.pl-system-package-mysql/20800.dbms-balance-mysql/200.trigger-partition-balance-mysql.md).

    tab Oracle mode

    The statement in Oracle mode is as follows:

    ```sql
    BEGIN
        DBMS_BALANCE.TRIGGER_PARTITION_BALANCE(balance_timeout);
    END;
    ```

    The `balance_timeout` parameter specifies the timeout period for the background partition balance task, in seconds. If you do not specify this parameter, the background partition balance task does not have a timeout period. The task continues to run until it is completed.

    Here are some examples:

    * Trigger a partition balance without a timeout period.

      ```shell
      obclient [SYS]> DELIMITER //
      ```

      ```shell
      obclient [SYS]> BEGIN
          DBMS_BALANCE.TRIGGER_PARTITION_BALANCE();
      END;//
      ```

      ```shell
      obclient [SYS]> DELIMITER ;
      ```

    * Trigger a partition balance with a timeout period of 7200 seconds.

      ```shell
      obclient [SYS]> DELIMITER //
      ```

      ```shell
      obclient [SYS]> BEGIN
          DBMS_BALANCE.TRIGGER_PARTITION_BALANCE(7200);
      END;//
      ```

      ```shell
      obclient [SYS]> DELIMITER ;
      ```

For more information about the `TRIGGER_PARTITION_BALANCE` subprogram in the `DBMS_BALANCE` system package, see [TRIGGER_PARTITION_BALANCE](../../../700.reference/600.pl-reference/300.pl-oracle/1400.pl-system-package-oracle/2700.dbms-balance-oracle/200.trigger-paptition-balance-oracle.md).

    :::


## Next steps

After manually triggering partition balancing, the actual partition transfers will be executed asynchronously by the background balancing task. You can view the execution process of the partition balancing task by using the view. For more information, see [View background partition balancing tasks](500.view-background-partition-balancing-task.md).
