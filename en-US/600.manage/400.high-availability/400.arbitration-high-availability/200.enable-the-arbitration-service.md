# Enable arbitration service for a tenant

<main id="notice" >
<h4>Applicability</h4>
<p>This topic applies only to OceanBase Database Enterprise Edition. OceanBase Database Community Edition does not support the arbitration service. </p>
</main>

You can enable the arbitration service for a tenant when you create the tenant. For more information, see [Create a tenant](../../200.tenant-management/600.common-tenant-operations/200.manage-create-tenant.md). If you do not enable the arbitration service when you create a tenant, you can enable it after the tenant is created. This topic describes how to enable the arbitration service for an existing tenant.

## Prerequisites

* Make sure that the arbitration service is deployed in the current cluster. For more information, see [Deploy an OceanBase cluster with two replicas and an arbitration service](../../../400.deploy/300.deploy-oceanbase-enterprise-edition/400.deploy-through-the-command-line/200.deploy-the-oceanbase-cluster-command-line/200.deploy-the-quorum-high-availability-service.md).

* Before you enable the arbitration service, make sure that the Locality of the tenant to be enabled is 2F or 4F. At present, only tenants with a Locality of 2F or 4F can enable the arbitration service.

  <main id="notice" type='explain'>
  <h4>Note</h4>
  <p>The arbitration service can be enabled for a tenant only if the number of F replicas in the tenant's Locality is sufficient. The number of R replicas in the tenant's Locality does not affect the enablement of the arbitration service. For example, the arbitration service can be enabled for a tenant with a Locality of <code>F@z1,F@z2</code> or <code>F@z1,F@z2,R@z3</code>. </p>
  </main>

## Procedure

1. Log in to the `sys` tenant of the cluster as the `root` user.

   The following is an example of connecting to the database. Please replace the parameters with those in your actual environment.

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

   For more information about how to connect to the database, see [Overview of connecting to the database (MySQL mode)](../../../300.develop/100.application-development-of-mysql-mode/100.connect-to-oceanbase-database-of-mysql-mode/100.connection-methods-overview-of-mysql-mode.md) and [Overview of connecting to the database (Oracle mode)](../../../300.develop/200.application-development-of-oracle-mode/100.connect-to-oceanbase-database-of-oracle-mode/100.connection-methods-overview-of-oracle-mode.md).

2. Execute the following command to view the communication status of nodes in the cluster.

   ```shell
   obclient(root@sys)[oceanbase]> SELECT * FROM oceanbase.GV$OB_ARBITRATION_SERVICE_STATUS;
   ```

   The query result is as follows.

   ```shell
   +----------------+----------+-----------------------------+----------+
   | SVR_IP         | SVR_PORT | ARBITRATION_SERVICE_ADDRESS | STATUS   |
   +----------------+----------+-----------------------------+----------+
   | xx.xx.xx.197   |     2882 | xx.xx.xx.192:2882           | ACTIVE   |
   | xx.xx.xx.194   |     2882 | xx.xx.xx.192:2882           | ACTIVE   |
   +----------------+----------+-----------------------------+----------+
   2 rows in set
   ```

   Based on the value of the `STATUS` field in the query result, you can determine the communication status between each node and the arbitration service:

   * `ACTIVE`: The arbitration service communicates normally with the node. You can enable the arbitration service for the tenant only when all nodes communicate normally with the arbitration service.
   * `INACTIVE`: The arbitration service cannot communicate with the node. You cannot enable the arbitration service for the tenant. You need to check the network communication between the node and the arbitration service.

3. Execute the following command to view the status of the arbitration service for the tenant.

   ```shell
   obclient(root@sys)[oceanbase]> SELECT * FROM oceanbase.DBA_OB_TENANTS WHERE tenant_name = 'oracle001'\G
   ```

   The query result is as follows.

   ```shell
   *************************** 1. row ***************************
                    TENANT_ID: 1004
                  TENANT_NAME: oracle001
                  TENANT_TYPE: USER
                  CREATE_TIME: 2026-01-26 19:40:21.457857
                  MODIFY_TIME: 2026-01-27 13:51:47.053502
                 PRIMARY_ZONE: zone1;zone2
                     LOCALITY: FULL{1}@zone1, FULL{1}@zone2
            PREVIOUS_LOCALITY: NULL
           COMPATIBILITY_MODE: ORACLE
                       STATUS: NORMAL
                IN_RECYCLEBIN: NO
                       LOCKED: NO
                  TENANT_ROLE: PRIMARY
            SWITCHOVER_STATUS: NORMAL
             SWITCHOVER_EPOCH: 0
                     SYNC_SCN: 1687845116605766616
               REPLAYABLE_SCN: 1687845116605766616
                 READABLE_SCN: 1687845116605766616
           RECOVERY_UNTIL_SCN: 4611686018427387903
                     LOG_MODE: NOARCHIVELOG
   ARBITRATION_SERVICE_STATUS: DISABLED
                     UNIT_NUM: 1
           ZONE_UNIT_NUM_LIST: zone1:1,zone2:1
                   COMPATIBLE: 4.6.0
                    MAX_LS_ID: 1002
            RESTORE_DATA_MODE: NORMAL
            FLASHBACK_LOG_SCN: NULL
                      COMMENT:
              PROTECTION_MODE: MAXIMUM PERFORMANCE
             PROTECTION_LEVEL: MAXIMUM PERFORMANCE
   1 row in set
   ```

   The arbitration service for a tenant can be in one of the following states:

   * `ENABLED`: The arbitration service is enabled for the tenant.

   * `DISABLED`: The arbitration service is disabled for the tenant.

   * `ENABLING`: The arbitration service is being enabled for the tenant.

   * `DISABLING`: The arbitration service is being disabled for the tenant.

   Based on the query result, the value of the `ARBITRATION_SERVICE_STATUS` column is `DISABLED`, which indicates that the arbitration service is disabled for the tenant.

   For more information about the `DBA_OB_TENANTS` view, see [DBA_OB_TENANTS](../../../700.reference/700.system-views/300.system-view-of-sys-tenant/200.dictionary-view-of-sys-tenant/23100.o-dba_ob_tenants-of-sys-tenant.md).

4. Execute the following command to enable the arbitration service for the tenant.

   The statement is as follows:

   ```sql
   ALTER TENANT tenant_name [SET] ENABLE_ARBITRATION_SERVICE = true;
   ```

   In the statement, `tenant_name` specifies the name of the tenant for which you want to enable the arbitration service, and `SET` is an optional keyword.

   The following example shows how to enable the arbitration service for the `oracle001` tenant:

   ```shell
   obclient(root@sys)[oceanbase]> ALTER TENANT oracle001 ENABLE_ARBITRATION_SERVICE = true;
   ```

5. After the command is executed, query the `DBA_OB_TENANTS` view again to confirm whether the arbitration service is enabled for the tenant.

   ```shell
   obclient(root@sys)[oceanbase]> SELECT * FROM oceanbase.DBA_OB_TENANTS WHERE tenant_name = 'oracle001'\G
   ```

   The query result is as follows.

   ```shell

                       LOCKED: NO

             SWITCHOVER_EPOCH: 0

                     LOG_MODE: NOARCHIVELOG

                     UNIT_NUM: 1
           ZONE_UNIT_NUM_LIST: zone1:1,zone2:1
   ```

   Based on the query result, the value of the `ARBITRATION_SERVICE_STATUS` column is `ENABLED`, which indicates that the arbitration service is enabled for the tenant.

6. After the arbitration service is enabled, the tenant may still have log streams without arbitration members. These log streams cannot be upgraded or downgraded normally. You can follow the steps below to confirm this.

   The successful enablement of the arbitration service indicates that all log streams created before the enablement can use the arbitration service. However, new log streams created after the enablement may lack arbitration members. This is because the creation of log streams is not strictly enforced, and it cannot be guaranteed that arbitration members will be created successfully. Therefore, you can use the following statement to confirm whether all log streams of the tenant have arbitration members.

   The statement is as follows:

   ```sql
   (SELECT distinct ls_id FROM GV$OB_LOG_STAT WHERE tenant_id = tenantid) EXCEPT
   (SELECT ls_id FROM GV$OB_LOG_STAT WHERE tenant_id = tenantid AND role = 'LEADER' AND arbitration_member = 'arb_server_ip:arb_server_port');
   ```

   The parameters are described as follows:

   * `tenantid`: the tenant ID of the tenant for which you want to enable the arbitration service.

   * `arb_server_ip`: the IP address of the arbitration service.

   * `arb_server_port`: the RPC port of the arbitration service. The default value is 2882.

   The following example shows how to use the statement.

   ```shell
   obclient(root@sys)[oceanbase]> (SELECT distinct ls_id FROM GV$OB_LOG_STAT WHERE tenant_id = 1004) EXCEPT
   (SELECT ls_id FROM GV$OB_LOG_STAT where tenant_id = 1004 and role = 'LEADER' and arbitration_member = '100.xx.xx.xx:2882');
   ```

   If the query result is empty, it indicates that all log streams have arbitration members and the arbitration service is available. If the query result is not empty, the Root Service will automatically add arbitration members to these log streams in the background. You can query the `CDB_OB_LS_ARB_REPLICA_TASKS` view to check whether there are ongoing tasks to add arbitration members. If such tasks exist and are ongoing, you need to wait for them to complete.

   After the tasks to add arbitration members are completed, you can query the `CDB_OB_LS_ARB_REPLICA_TASK_HISTORY` view to check the task results. If the tasks are successful, it indicates that the arbitration members have been added to the log streams and the arbitration service is available. If the tasks fail, you need to contact OceanBase support for assistance.

    For more information about the fields in the `GV$OB_LOG_STAT` view, see [GV$OB_LOG_STAT](../../../700.reference/700.system-views/400.system-view-of-mysql-mode/300.performance-view-of-mysql-mode/1300.gv-ob_log_stat-of-mysql-mode.md).
