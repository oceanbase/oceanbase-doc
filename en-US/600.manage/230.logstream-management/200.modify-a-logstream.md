# Log stream

A log stream belongs to a log stream group. The number of log streams in a log stream group is determined by the number of zones in the Primary Zone. Each zone in the zone list of the Primary Zone hosts the leader of one log stream in the log stream group.

You can perform operations on a log stream as needed to manually rebalance the distribution of log streams across `UNIT_GROUP` units.

## Considerations

Before you perform operations on a log stream, take note of the following considerations:

* The log stream must exist and be in the `NORMAL` state.

* The tenant of the log stream must be in the `NORMAL` state.

* If you modify the `UNIT_GROUP` attribute of a log stream in the primary tenant, make sure that no load balancing task is being performed on any log stream of the tenant.

* We recommend that you do not modify the `UNIT_GROUP` attribute of a log stream in the standby tenant. The `UNIT_GROUP` attribute of a log stream in the standby tenant is automatically adjusted. Therefore, manually modifying the `UNIT_GROUP` attribute of a log stream in the standby tenant may not take effect.

* When you modify the `UNIT_GROUP` attribute of a log stream, make sure that the target `UNIT_GROUP` is in the `ACTIVE` state.

* When you modify the `PRIMARY_ZONE` attribute of a log stream, make sure that the new zone is included in the `ZONE_LIST` attribute of the tenant. For a log stream, you can set only one zone as the `PRIMARY_ZONE` attribute. For example, you can set `z1` or `z2`. You cannot set `z1,z2`, `z1; z2`, or `RANDOM` as the `PRIMARY_ZONE` attribute of a log stream.

* When you modify a log stream, make sure that the tenant-level parameter `enable_rebalance` is disabled, that is, its value is `False`. If `enable_rebalance` is enabled, the load balancing module of the tenant may automatically adjust the `PRIMARY_ZONE` and `UNIT_GROUP` attributes of the log stream.

* Only broadcast log streams and system log streams (Log Stream 1) support setting the `UNIT_GROUP` attribute to 0.

## Step 1: Perform checks before the change

1. Log in to the `sys` tenant or user tenant of the cluster as the administrator.

   The following is an example of the connection command. The actual command may vary based on the environment.

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. Query the status of the tenant to which the log stream belongs and ensure that the status is `NORMAL`.

   * System tenant

      ```shell
      obclient> SELECT TENANT_ID, TENANT_NAME, STATUS, TENANT_ROLE FROM oceanbase.DBA_OB_TENANTS WHERE tenant_name = 'mq_t1';
      ```

   * User tenant

      :::tab
      tab MySQL mode

      In MySQL mode, execute the following command to query the tenant status.

      ```shell
      obclient> SELECT TENANT_ID, TENANT_NAME, STATUS, TENANT_ROLE FROM oceanbase.DBA_OB_TENANTS;
      ```

      tab Oracle mode

      In Oracle mode, execute the following command to query the tenant status.

      ```shell
      obclient> SELECT TENANT_ID, TENANT_NAME, STATUS, TENANT_ROLE FROM SYS.DBA_OB_TENANTS;
      ```

      :::

   The query result is as follows:

   ```shell
   +-----------+-------------+--------+-------------+
   | TENANT_ID | TENANT_NAME | STATUS | TENANT_ROLE |
   +-----------+-------------+--------+-------------+
   |      1002 | mq_t1       | NORMAL | PRIMARY     |
   +-----------+-------------+--------+-------------+
   1 row in set
   ```

   The tenant status is `NORMAL`.

3. Query whether a load balancing task is being performed on the log stream. If you modify the `UNIT_GROUP` attribute of a log stream in the main tenant, ensure that no load balancing task is being performed on all log streams of the tenant.

   * System tenant

      ```shell
      obclient> SELECT count(*) AS task_cnt FROM oceanbase.CDB_OB_BALANCE_TASKS WHERE TENANT_ID=1002 AND (SRC_LS = 1001 or DEST_LS=1001);
      ```

   * User tenant

      :::tab
      tab MySQL mode

      In MySQL mode, execute the following command to query the load balancing task status of the log stream.

      ```shell
      obclient> SELECT count(*) AS task_cnt FROM oceanbase.DBA_OB_BALANCE_TASKS WHERE SRC_LS = 1001 or DEST_LS=1001;
      ```

      tab Oracle mode

      In Oracle mode, execute the following command to query the load balancing task status of the log stream.

      ```shell
      obclient> SELECT count(*) AS task_cnt FROM SYS.DBA_OB_BALANCE_TASKS WHERE SRC_LS = 1001 or DEST_LS=1001;
      ```

      :::

   The query result is as follows:

   ```shell
   +----------+
   | task_cnt |
   +----------+
   |        0 |
   +----------+
   1 row in set
   ```

   The query result is `0`, indicating that no load balancing task is being performed on the log stream.

5. If you want to modify the `UNIT_GROUP` attribute of the log stream, query the unit information of the tenant and ensure that the remaining disk space on the target `UNIT_GROUP` can accommodate the log stream to be modified.

   The following operations must be performed in the system tenant.

   1. Execute the following command to query the unit information of the tenant and confirm that the status of the target `UNIT_GROUP` is `ACTIVE`.

      ```shell
      obclient> SELECT UNIT_GROUP_ID, UNIT_ID, ZONE, SVR_IP, SVR_PORT FROM oceanbase.DBA_OB_UNITS WHERE TENANT_ID=1002 AND STATUS = 'ACTIVE' ORDER BY UNIT_GROUP_ID;
      ```

      The query result is as follows:

      ```shell
      +---------------+---------+------+----------------+----------+
      | UNIT_GROUP_ID | UNIT_ID | ZONE | SVR_IP         | SVR_PORT |
      +---------------+---------+------+----------------+----------+

      |          1001 |    1002 | z2   | xxx.xx.xxx.196 |     2882 |
      ```

   2. Based on the `UNIT_GROUP_ID`, `SVR_IP`, and `SVR_PORT` information, query the remaining disk space on the server corresponding to the target `UNIT_GROUP`.

      ```shell
      obclient> SELECT SVR_IP, SVR_PORT, (DATA_DISK_CAPACITY - DATA_DISK_IN_USE) / 1024 / 1024 / 1024 AS REST_DATA_SIZE_IN_GB FROM oceanbase.GV$OB_SERVERS;
      ```

   3. Query the disk space requirements of the log stream to be modified.

      ```shell
      obclient> SELECT SVR_IP, SVR_PORT, TENANT_ID, LS_ID, 
      SUM(OCCUPY_SIZE)/1024/1024/1024 AS OCCUPY_SIZE_GB, 
      SUM(REQUIRED_SIZE)/1024/1024/1024 AS REQUIRED_SIZE_GB 
      FROM __ALL_VIRTUAL_TABLET_POINTER_STATUS
      ```

7. Check whether the value of the `enable_rebalance` parameter is `False`. If the value is `True`, after you modify the log stream, the load balancing module of the tenant may automatically modify the `PRIMARY_ZONE` and `UNIT_GROUP` attributes of the log stream.

   ```shell
   obclient> SHOW PARAMETERS LIKE '%enable_rebalance%';
   ```

   If the value is not `False`, execute the following command to set the value of the `enable_rebalance` parameter to `False`.

   * System tenant

      ```shell
      obclient> ALTER SYSTEM SET enable_rebalance = 'False' TENANT = mq_t1;
      ```

   * User tenant

      ```shell
      obclient> ALTER SYSTEM SET enable_rebalance = 'False';
      ```

## Step 2: Change the log stream

After all the checks are passed, based on the business situation, perform the required operation to change the log stream.

### Change the log stream of a user tenant

1. Log in to the `sys` tenant of the cluster as the `root` user.

   The following is an example of how to connect to the database. Please note that the actual environment may vary.

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. Change the log stream.

   The SQL statement to change the log stream of a user tenant in the sys tenant is as follows:

   ```sql
   ALTER SYSTEM MODIFY LS [=] ls_id [UNIT_GROUP [=] unit_group_id],[PRIMARY_ZONE [=] 'zone_name'] TENANT [=] 'tenant_name';
   ```

   The statement is described as follows:

   * `ls_id`: the ID of the log stream to be changed.

   * `unit_group_id`: the ID of the target unit group to which the log stream is to be changed. You can obtain the `unit_group_id` by querying the `oceanbase.DBA_OB_UNITS` view in the sys tenant.

   * `zone_name`: the name of the target zone.

   * `tenant_name`: the name of the target tenant of the log stream.

   * When you change the log stream, you must modify at least one attribute of the log stream: `UNIT_GROUP` or `PRIMARY_ZONE`.

   Here are some examples:

   * Change only the `UNIT_GROUP` attribute of the log stream.

      Change the location of log stream 1002 of the `mq_t1` tenant to the `UNIT_GROUP` of log stream 1002.

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_GROUP 1002 TENANT = mq_t1;
      ```

   * Change only the `PRIMARY_ZONE` attribute of the log stream.

      Change the primary zone of leader of log stream 1002 of the `mq_t1` tenant to `z1`.

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 PRIMARY_ZONE 'z1' TENANT = mq_t1;
      ```

   * Change both the `UNIT_GROUP` and `PRIMARY_ZONE` attributes of the log stream.

      Change the location of log stream 1002 of the `mq_t1` tenant to the `UNIT_GROUP` of log stream 1002, and change the primary zone of leader of log stream 1002 of the `mq_t1` tenant to `z1`.

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_GROUP 1002, PRIMARY_ZONE 'z1' TENANT = mq_t1;
      ```

3. Check whether the log stream is changed.

   ```shell
   obclient> SELECT LS_ID, PRIMARY_ZONE, UNIT_GROUP_ID, LS_GROUP_ID FROM oceanbase.CDB_OB_LS WHERE TENANT_ID=1002 AND LS_ID = 1002 AND STATUS = 'NORMAL';
   ```

   The query result is as follows:

   ```shell
   +-------+--------------+---------------+-------------+
   | LS_ID | PRIMARY_ZONE | UNIT_GROUP_ID | LS_GROUP_ID |
   +-------+--------------+---------------+-------------+
   |  1002 | z1;z2,z3     |          1002 |        1001 |
   +-------+--------------+---------------+-------------+
   1 row in set
   ```

   Compare the log stream before and after the change. If the `UNIT_GROUP` and `PRIMARY_ZONE` attributes of the log stream are consistent with the expected values, the change is successful.

### Change the log stream of a user tenant

1. Log in to the database as the tenant administrator of a MySQL or Oracle tenant.

   The following example shows how to log in to the database. Take the actual environment into account when you log in to the database.

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mq_t1#obdemo -p***** -A
   ```

2. Change the log stream.

   The SQL statement for changing the log stream of a user tenant is as follows:

   ```sql
   ALTER SYSTEM MODIFY LS [=] ls_id [UNIT_GROUP [=] unit_group_id],[PRIMARY_ZONE [=] 'zone_name'];
   ```

   The statement is described as follows:

   * `ls_id`: the ID of the log stream to be modified.

   * `unit_group_id`: the ID of the target Unit Group of the log stream to be modified. You can obtain `unit_group_id` by querying the `oceanbase.DBA_OB_UNITS` view in the system tenant.

   * `zone_name`: the name of the target zone.

   * When you change the log stream, you must modify at least one attribute of the log stream: `UNIT_GROUP` or `PRIMARY_ZONE`.

   Here are some examples:

   * Modify only the `UNIT_GROUP` attribute of the log stream.

      Move the log stream with ID 1002 to the `UNIT_GROUP` of the same ID.

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_GROUP 1002;
      ```

   * Modify only the `PRIMARY_ZONE` attribute of the log stream.

      Change the primary zone of the log stream with ID 1002 to `z1`.

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 PRIMARY_ZONE 'z1';
      ```

   * Modify both the `UNIT_GROUP` and `PRIMARY_ZONE` attributes of the log stream.

      Move the log stream with ID 1002 to the `UNIT_GROUP` of the same ID, and change the primary zone of the log stream to `z1`.

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_GROUP 1002, PRIMARY_ZONE 'z1';
      ```

3. Check whether the log stream is changed.

   ```shell
   obclient> SELECT LS_ID, PRIMARY_ZONE, UNIT_GROUP_ID, LS_GROUP_ID FROM oceanbase.DBA_OB_LS WHERE LS_ID = 1002 AND STATUS = 'NORMAL';
   ```

   The query result is as follows:

   ```shell
   +-------+--------------+---------------+-------------+
   | LS_ID | PRIMARY_ZONE | UNIT_GROUP_ID | LS_GROUP_ID |
   +-------+--------------+---------------+-------------+
   |  1002 | z1;z2,z3     |          1002 |        1001 |
   +-------+--------------+---------------+-------------+
   1 row in set
   ```

   Compare the log stream before and after the change. If the `UNIT_GROUP` and `PRIMARY_ZONE` attributes of the log stream are as expected, the change is successful.
