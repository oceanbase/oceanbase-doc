# Identity authentication

This topic describes the identity authentication mechanism in the Oracle-compatible mode of OceanBase Database, including user authentication, identity components, and the use of authentication plugins.

The identity authentication feature validates the user identity when a user logs on to a database to access data, verifies whether the user can be associated with a database user, and implements security control on the activities of the user in the database based on the privileges of the associated database user. The Authentication Plugin is used for password verification. In Oracle-compatible mode, OceanBase Database supports using authentication plugins to control the hash calculation and verification methods of passwords.

<main id="notice" >
   <h4>Applicability</h4>
   <p>This topic applies only to the Oracle-compatible mode of OceanBase Database. OceanBase Database Community Edition only supports MySQL-compatible mode. For more information about identity authentication in MySQL-compatible mode, see <a href="../100.identification-and-authentication-of-mysql-mode/100.identification-of-mysql-mode.md">Identity authentication</a>. </p>
</main>

## User authentication

In Oracle-compatible mode, this feature authenticates a user's username and password to recognize the user's identity and access to features and resources. OceanBase Database requires all users to log in with the correct username and password to ensure database security.

## Identity components

In Oracle-compatible mode, usernames are unique within a tenant, but users in different tenants can have the same username. Therefore, a user is uniquely identified globally in the system in the `username@tenant name` format. Here is a direct example:

1. Log in to an Oracle-compatible tenant of a cluster as the `SYS` user.

   ```shell
   obclient -usys@oracle -h10.xxx.xxx.1 - P2881 -P*******
   ```

2. Execute the following statement to create a user named `u1`.

   ```shell
   obclient> CREATE USER u1 IDENTIFIED BY ******;
   Query OK, 0 rows affected (0.064 sec)
   ```

3. Execute the following statement to grant user `u1` the privilege to connect to the database.

   ```shell
   obclient>GRANT CREATE SESSION TO u1;
   Query OK, 0 rows affected (0.045 sec)
   ```

4. Log in to the cluster as user `u1`.

   ```shell
   $obclient -h10.xxx.xxx.1 -P2881 -uu1@oracle001 -p****** -A

## Authentication plugins

<main id="notice" type='notice'>
  <h4>Note</h4>
  <p>Starting from V4.4.2 BP2, OceanBase Database supports the password authentication plugin mechanism in Oracle-compatible mode.</p>
</main>

* When creating or modifying a user, you can explicitly specify to use the `caching_sha2_password` authentication plugin (based on the SHA-256 algorithm), which provides a higher level of security.

  * If the authentication plugin is not specified when creating a user, `ob_native_password` is used by default (equivalent to `mysql_native_password`, using the SHA-1 algorithm). To set `caching_sha2_password` as the default authentication plugin, you can configure the system variable [default_authentication_plugin](../../../../700.reference/800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/2100.default_authentication_plugin-global.md).

* ob_sm3_password: This plugin fully reuses the `caching_sha2_password` protocol and state machine (AuthSwitch, fast authentication/complete authentication, TLS/RSA key transmission), but maintains independent algorithms and metadata. It has the following features:

  * SM3 hash algorithm (GB/T 32905-2016): Replaces SHA-256 for password storage and authentication verification.
  * Dual authentication mode: Fast authentication (memory cache) + Complete authentication (disk-stored string + SSL/RSA key transmission).
  * Adjustable iteration count: You can control the number of SM3 iterations performed by the `ob_sm3_password` authentication plugin when generating a password authentication string via the system variable [ob_sm3_password_digest_rounds](../../../../700.reference/800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/8950.ob_sm3_password_digest_rounds-global.md) (default is 5000).

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>For V4.4.2, the <code>ob_sm3_password</code> authentication plugin is supported starting from V4.4.2 BP3.</p>
  </main>

### Component and driver version requirements

When using the `caching_sha2_password` authentication plugin, the database components and client drivers must meet the following version requirements:

| Component/Driver | Version Requirement |
|-----------|----------|
| OceanBase Database Proxy (ODP) | V4.4.0 or later |
| OBClient | V2.2.13 or later |
| OB-JDBC | V2.4.18 or later |
| OBCI | V2.1.1.3 or later |

When using the `caching_sha2_password` or `ob_sm3_password` authentication plugin, the database components and client drivers must meet the following version requirements:

|        **Component/Driver**       | **caching_sha2_password** | **ob_sm3_password** |
|----------------------------|---------------------------|---------------------|
| OceanBase Database Proxy (ODP) | V4.4.0 or later          | V4.4.2.0 or later |
| OBClient                   | V2.2.13 or later         | V2.2.14 or later |
| libobclient                | V2.2.13 or later         | V2.2.14 or later |
| OB-JDBC                    | V2.4.18 or later         | V2.4.20 or later |
| OBCI                       | V2.1.1.4 or later        | V2.1.1.4 or later|

### Example


When creating or modifying a user, you can specify the authentication plugin using the `IDENTIFIED WITH auth_plugin` syntax.

* Create user `user1` without explicitly specifying an authentication plugin (uses `ob_native_password` by default).

    CREATE USER user1 IDENTIFIED BY "******";
    ```shell
    obclient> CREATE USER user1 IDENTIFIED BY "******";

```

    -- Explicitly specify to use caching_sha2_password
    * Create user `user2` and explicitly specify to use `caching_sha2_password`.
    ```shell

obclient> CREATE USER user2 IDENTIFIED WITH caching_sha2_password BY "******";

    ```
    * Modify the authentication plugin for user `user1` to `caching_sha2_password`.
    SELECT username, plugin FROM dba_users WHERE username LIKE 'USER_%';

```shell

    obclient> ALTER USER user1 IDENTIFIED WITH caching_sha2_password BY "******";
    ```
    * Create user `sm3_user` and explicitly specify to use `ob_sm3_password`.

```shell

    obclient> CREATE USER sm3_user IDENTIFIED WITH ob_sm3_password BY "******";
    ```
    * View the authentication plugin information of a user.

```shell

obclient> SELECT username, plugin FROM dba_users WHERE username LIKE '%USER%';
