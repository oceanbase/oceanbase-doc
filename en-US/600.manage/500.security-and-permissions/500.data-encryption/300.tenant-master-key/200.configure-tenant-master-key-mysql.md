# Generate a tenant master key (MySQL mode)

This topic describes how to generate a tenant master key in a MySQL mode tenant. After the tenant master key is generated, you can use the transparent data encryption (TDE), column encryption, and function encryption features.

<main id="notice" type='notice'>
  <h4>Applicability</h4>
  <p>Community Edition of OceanBase Database does not support tenant master key-related features. </p>
</main>

## Prerequisites

* You have created a MySQL mode tenant.
* You have logged in to the tenant as the administrator.

## Generate a tenant master key

Before you generate a tenant master key, make sure that the following conditions are met:

1. To enable the TDE feature, you must generate a tenant master key whose value is not `none`. To avoid a circular dependency during log replay, if the `tde_method` parameter is set to `internal`, the TDE clogs are not encrypted.
2. To enable the column encryption feature, you must generate a tenant master key whose value is not `none`.
3. To enable the function encryption feature, you must generate a tenant master key whose value is not `none`.
4. We recommend that you set the `tde_method` parameter to `obcloud` for the TDE, column encryption, and function encryption features.

The following example shows how to generate a tenant master key by using the `obcloud` method. If you want to use an external key management service (KMS), set the `tde_method` parameter to `obcloud` and configure the `external_kms_info` parameter.

1. Log in to the MySQL tenant of the cluster as the administrator.

2. Execute the following statement to enable the `obcloud` encryption method.

   The `tde_method` parameter specifies the storage method of the tenant master key. The default value is `none`, which indicates that encryption is disabled.

   For more information about the `tde_method` parameter, see [tde_method](../../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/7800.tde_method.md).

   <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>Once the <code>tde_method</code> parameter is set, it cannot be modified. </p>
   </main>

   ```sql
   ALTER SYSTEM SET tde_method='obcloud';
   ```

3. Execute the following statement to confirm that the value of the `tde_method` parameter is `obcloud` on all OBServer nodes of the tenant.

   ```sql
   SHOW PARAMETERS LIKE 'tde_method';
   ```

4. Execute the following statement to configure the key management information.

   For more information about the `external_kms_info` parameter, see [external_kms_info](../../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3200.external_kms_info.md).

   ```sql
   -- The following example is for reference only. Replace the key management information with the actual information.
   ALTER SYSTEM SET external_kms_info='{
            "KMS_HOST": "kms.ob.com:443",
            "ROOT_CERT": "******",
            "PRIVATE_KEY": "******",
            "PRIVATE_KEY_PHRASE": "ob2025",
            "SCENE": "ANT",
            "KEY_NAME": "ob_cluster_key",
            "CALLER": "oceanbase_admin"}';
   ```

5. Execute the following statement to generate a tenant master key.

   <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>This statement can be executed only when the value of the <code>tde_method</code> parameter is <code>internal</code> on all OBServer nodes of the tenant. The first execution of this statement takes about 20 seconds to take effect. </p>
   </main>

   ```sql
   ALTER INSTANCE ROTATE INNODB MASTER KEY;
   ```

## Rotate a tenant master key

For security reasons, we recommend that you rotate the tenant master key regularly. After the tenant master key is rotated, new data is encrypted with the new key, and old data can still be decrypted with the old key.

```sql
ALTER INSTANCE ROTATE INNODB MASTER KEY;
```

## What to do next

After you generate a tenant master key, you can:

* Use the TDE feature: For more information, see [Enable transparent encryption for a new table](../400.data-storage-encryption/200.data-storage-encryption-of-mysql-mode/100.configure-internal-storage-encryption-of-mysql-mode.md).
* Use the column encryption feature: For more information, see [Create a column encryption rule](../500.column-encryption/200.column-encryption-of-mysql-mode/200.create-column-encryption-rule-of-mysql-mode.md).
* Use the function encryption feature: For more information, see [ENHANCED_AES_ENCRYPT](../../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/400.functions-of-mysql-mode/500.encryption-and-compression-functions-of-mysql-mode/820.enhanced-aes-encrypt-of-mysql-mode.md) and [ENHANCED_AES_DECRYPT](../../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/400.functions-of-mysql-mode/500.encryption-and-compression-functions-of-mysql-mode/830.enhanced-aes-decrypt-of-mysql-mode.md).
