# Overview of tenant master keys

A tenant master key is the infrastructure for data encryption in OceanBase Database. The **Transparent Data Encryption (TDE)**, **Column Encryption**, and **Function Encryption** features all rely on tenant master keys.

<main id="notice" type='notice'>
  <h4>Applicability</h4>
  <p>Community Edition of OceanBase Database does not support tenant master keys. </p>
</main>

## Two-level key system

OceanBase Database implements data encryption using a two-level key system:

* Tenant master key (Master Key): Each tenant has a master key used to encrypt and protect data keys. The master key is stored in the Keystore.
* Data key: Used to directly encrypt data. Each encrypted tablespace has a corresponding data key.

![Data encryption](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.2.1/manage/datastore-encryption.png)

To ensure data security, users cannot directly view or specify the master key and data key. These keys are generated by the system and are not stored in plaintext on the disk, significantly enhancing system security.

### Keystore

Keystore is the module responsible for managing the primary key, providing key management services. The features of Keystore include:

* Primary key generation: The primary key is generated by Keystore based on the encryption algorithm, and users cannot specify it.
* Storage of primary key information: Keystore ensures the multi-replica, consistency, and fault tolerance of the related information.
* Primary key management and multi-version control: The multi-version mechanism allows new primary keys to take effect gradually without needing to be immediately active.
* High availability service for retrieving the primary key.
* Processing operation instructions for Keystore.

### Primary key storage methods

The storage method for the primary key is controlled by the configuration item [tde_method](../../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/7800.tde_method.md):

| `tde_method` value | Description |
|------------------|------|
| `none` | No tenant primary key is generated (default value) |
| `internal` | The primary key is stored in an internal table |
| `bkmi` | The primary key is stored in an external BKMI system |
| `obcloud` | The primary key is stored in the OceanBase Cloud KMS service |

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <ul>
    <li>Encryption cannot be enabled for the sys tenant. </li>
    <li>Once the <code>tde_method</code> configuration item is set to a value other than <code>none</code>, it cannot be modified. You cannot switch to another encryption method unless you rebuild the tenant. </li>
  </ul>
</main>

The following table describes the primary key storage methods:

| Method | Description |
|------------------|------|
| `internal` and `obcloud` | The `internal` method stores the primary key encryption information in an internal table. To avoid cyclic dependencies during log replay, the clog is not encrypted. The `obcloud` method manages the primary key through the OceanBase Cloud KMS or OCP KMS proxy service. |
| External KMS (such as `obcloud`) | In addition to setting `tde_method`, you can configure [external_kms_info](../../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3200.external_kms_info.md) to specify the address, authentication information, and key name of the KMS. The database uses this configuration to connect to and access the external KMS to obtain the primary key.

When encryption is enabled, the primary key is used to encrypt the data key, resulting in an encrypted data key ciphertext. This ciphertext is stored in the internal table, macroblock header, and clog header. The data key is not stored in plaintext anywhere. When data needs to be encrypted or decrypted, the primary key is used to decrypt the ciphertext to obtain the data key, which is then used to encrypt or decrypt the user data in the macroblock or clog.
