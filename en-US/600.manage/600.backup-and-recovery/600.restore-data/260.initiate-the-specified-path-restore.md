# Restore from a specified path

When a data backup set (backup_set) and log archive (archivelog_piece) are manually moved to another path for business reasons, you can restore the tenant by loading the corresponding backup_set and archivelog_piece and then issuing a restore command.

## Prerequisites

* You have obtained the storage paths for the backup set and archive log pieces to be restored.

* The backup set and archive log pieces to be restored belong to the same tenant. Currently, restoring from a backup set and archive log pieces of the same tenant is only allowed to create a new tenant.

* You have completed the pre-restoration preparations. For specific operations, see [Prepare before restore](../600.restore-data/100.preparation-before-recovery.md).

## Procedure

1. Log in to the `sys` tenant of the cluster where the tenant to be restored is located as the `root` user.

2. (Optional) Execute the `ALTER SYSTEM RESTORE...PREVIEW` command to specify the original data backup path, log archive path, and the desired restore time.

   The statement is as follows:

   ```sql
   ALTER SYSTEM RESTORE FROM 'uri' UNTIL { TIME='timestamp' | SCN=scn } PREVIEW;
   ```

   The relevant parameters are described as follows:

   * `uri`: Specifies the original data backup path and log archive path, separated by commas.

     * If a backup target path was specified using the `TO` syntax during data backup (for example, backing up to a specified directory A), then the `uri` should contain the backup target path specified during backup (A), not the default path configured by the system parameter `data_backup_dest`. The format remains `A,log_archive_dest`.
     * If the tenant has performed an archive backup with the `DELETE INPUT` parameter, the format is `A,log_archive_dest,backup_archive_dest`.

   * `TIME='timestamp' | SCN=scn`: Specifies the desired restore timestamp or SCN. When executing this statement, you must explicitly specify a time.

   For complete parameter descriptions, see [ALTER SYSTEM - RESTORE PREVIEW](../../../700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/3350.restore-preview.md).

   Examples are as follows:

   :::tab
   tab OSS

   * Specify the original data backup path and log archive path, and restore to the specified SCN `1712650554000909004`.

      ```shell
      obclient [oceanbase]> ALTER SYSTEM RESTORE FROM 'oss://test_bucket/data?host=***&access_id=****&access_key=****, oss://test_bucket/archive?host=***&access_id=****&access_key=****' UNTIL SCN = 1712650554000909004 PREVIEW;
      ```

   * Specify the original data backup path and log archive path, and restore to the specified timestamp `2024-04-09 16:15:54`.

      ```shell
      obclient [oceanbase]> ALTER SYSTEM RESTORE FROM 'oss://test_bucket/data?host=***&access_id=****&access_key=****, oss://test_bucket/archive?host=***&access_id=****&access_key=****' UNTIL TIME = '2024-04-09 16:15:54' PREVIEW;
      ```

   tab NFS

   * Specify the original data backup path and log archive path, and restore to the specified SCN `1712650554000909004`.

      ```shell
      obclient [oceanbase]> ALTER SYSTEM RESTORE FROM 'file:///ob_backup/data, file:///ob_backup/archive' UNTIL SCN = 1712650554000909004 PREVIEW;
      ```

   * Specify the original data backup path and log archive path, and restore to the specified timestamp `2024-04-09 16:15:54`.

      ```shell
      obclient [oceanbase]> ALTER SYSTEM RESTORE FROM 'file:///ob_backup/data, file:///ob_backup/archive' UNTIL TIME = '2024-04-09 16:15:54' PREVIEW;
      ```

   :::

3. (Optional) Run the `SHOW RESTORE PREVIEW` command to display the backup_set and archivelog_piece required to restore to the specified time.

   <main id="notice" type='notice'>
   <h4>Notice</h4>
   <p>You must run the <code>SHOW RESTORE PREVIEW</code> command after the <code>ALTER SYSTEM RESTORE...PREVIEW</code> command succeeds. Otherwise, the required results cannot be obtained.</p>
   </main>

   ```shell
   obclient [oceanbase]> SHOW RESTORE PREVIEW;
   ```

   For example, the result is as follows:

   ```shell

   | BACKUP_PIECE |         3 | file:///ob_backup/archive/piece_d1002r1p3                                      | start_scn_display: 20240409T160354, checkpoint_scn_display: 20240409T160553. |

   ```

   The query result shows all the backup_set and archivelog_piece required to restore to the specified time, along with their storage paths in the original data backup and log archive destinations. If, due to business needs, you have manually moved some or all of these files to other paths or storage media, you need to maintain the mapping between the original paths and the current paths for each backup_set and archivelog_piece based on your actual situation.

   For example, in the query result above, if you need to use the archivelog_piece with `BACKUP_PIECE` set to `1` for restoration, but this file has already been manually moved to `oss://test_bucket/archive/piece_1`, then when using the `ADD RESTORE SOURCE` command to load the backup path, you need to specify the new storage path `oss://test_bucket/archive/piece_1`.

4. Run the `ADD RESTORE SOURCE` command to load the required backup_set and archivelog_piece for restoration.

   The syntax for loading paths is as follows:

   ```sql
   ALTER SYSTEM ADD RESTORE SOURCE 'restore_path';
   ```

   Usage instructions:

   * `restore_path`: Enter the path of the backup_set or archivelog_piece to be loaded. This can be one or multiple paths.

      <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>If the backup_set or archivelog_piece to be loaded is stored on object storage, the <code>host</code>, <code>access_id</code>, and <code>access_key</code> parameters in the path for each backup_set or archivelog_piece must be the same.</p>
      </main>

   * This statement can be executed multiple times consecutively within the same session. When executed multiple times in the same session, the system will incrementally add them to the restore source list.

   Example:

   1. Load the backup_set to be restored.

      ```shell
      obclient [oceanbase]> ALTER SYSTEM ADD RESTORE SOURCE 'file:///ob_backup/data/backup_set_1_full';
      ```

   2. Load the archivelog_piece to be restored.

      ```shell
      obclient [oceanbase]> ALTER SYSTEM ADD RESTORE SOURCE 'file:///ob_backup/archive/piece_d1002r1p1,file:///ob_backup/archive/piece_d1002r1p2';
      ```

      ```shell
      obclient [oceanbase]> ALTER SYSTEM ADD RESTORE SOURCE 'oss://test_bucket/archive/piece_1?host=***&access_id=x****&access_key=****';
      ```

5. (Optional) If you load a backup set or archive log piece and find that an incorrect path was entered, you can execute the following statement to undo the previous input and then reload the correct restore path.

    ```shell
    obclient [oceanbase]> ALTER SYSTEM CLEAR RESTORE SOURCE;
    ```

6. After all paths are successfully loaded, call the restore command.

   <main id="notice" type='notice'>
   <h4>Notice</h4>
   <ul>
   <li>The session that executes the restore command must be the same one that executed the <code>ADD RESTORE SOURCE</code> command. If it is not the same session (the original session was interrupted or a new session was used), the previously loaded list of restore sources will be cleared.</li>
   <li>After executing the <code>ADD RESTORE SOURCE</code> command, you cannot restore a tenant in the same session by specifying the backup destination in a restore command.</li>
   <li>After executing the restore command, regardless of whether the restore is successful, the previously loaded list of restore sources will be cleared. If you need to call the restore command again, you must reload the required backup sets and archive log pieces.</li>
   </ul>
   </main>

   Execute the following statement:

   ```sql
   ALTER SYSTEM RESTORE restore_tenant_name [UNTIL {TIME='timestamp' | SCN=scn} ] WITH 'restore_option';
   ```

   For complete parameter descriptions, see [ALTER SYSTEM - RESTORE](../../../700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/3300.restore.md).


      For detailed descriptions of each parameter, see [Parameters related to physical restore](800.parameters-of-the-restore.md).

   An example of calling the restore command is as follows:

   * Restore tenant `mysql` from the specified path to the specified SCN `1712650554000909004`, and specify the resource pool as `restore_pool`.

      ```shell
      // Full restore
      obclient [oceanbase]> ALTER SYSTEM RESTORE mysql UNTIL SCN = 1712650554000909004 WITH 'pool_list=restore_pool';

      // Quick restore
      obclient [oceanbase]> ALTER SYSTEM RESTORE mysql UNTIL SCN = 1712650554000909004 WITH 'pool_list=restore_pool&method=quick';
      ```

   * Restore tenant `mysql` from the specified path to the specified timestamp `2024-04-09 16:15:54`, and specify the resource pool as `restore_pool`.

      ```shell
      // Full restore
      obclient [oceanbase]> ALTER SYSTEM RESTORE mysql UNTIL TIME = '2024-04-09 16:15:54' WITH 'pool_list=restore_pool';

      // Quick restore
      obclient [oceanbase]> ALTER SYSTEM RESTORE mysql UNTIL TIME = '2024-04-09 16:15:54' WITH 'pool_list=restore_pool&method=quick';
      ```

## What to do next

* After initiating a restore task, you can view the progress and results of the restore through views. For specific operations, see [View restore progress](../600.restore-data/400.view-the-restore-progress.md).

* After the restore task is completed, if you are restoring from backup data of a lower version to a cluster of a higher version, you also need to upgrade the restored tenant. For specific operations, see [Upgrade a tenant after restore](610.update-the-tenant-after-the-restore.md).

* The physical restore process is unified with that of a physical standby database. After physical restore, the tenant becomes a standby tenant. Subsequently, this tenant can provide related services as a standby tenant or be promoted to a primary tenant to provide services. For detailed operations on continuing log archiving and replaying logs from the source tenant as a standby tenant, see [Replay logs to a standby tenant](510.recover-the-standby-tenant.md); for detailed operations on promoting a standby tenant to a primary tenant, see [Convert a standby tenant into primary tenant](600.active-standby-tenant.md).
