# Preparations before backup

Before you back up data, you must perform some preparations, such as configuring the backup destination and backup keys.

## Configure the backup destination

When you configure the backup destination, note that the `sys` tenant, which is used for cluster management and does not contain user data, does not support backup and restore. Therefore, you do not need to specify the `DATA_BACKUP_DEST` parameter for the `sys` tenant.

### Considerations

When you configure the backup destination, make sure that the backup path is an empty directory for each tenant and that the backup paths of different tenants are different.

### Procedure

1. Log in to the database as the `sys` tenant or a user tenant administrator.

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <p>In MySQL mode, the administrator is the <code>root</code> user, and in Oracle mode, the administrator is the <code>SYS</code> user.</p>
   </main>

2. Configure the backup destination.

   * For the system tenant, configure the backup destination for the specified tenant.

     ```sql
     ALTER SYSTEM SET DATA_BACKUP_DEST= 'data_backup_path' TENANT = mysql_tenant;
     ```

   * For a user tenant, configure the backup destination for the current tenant.

     The statement is as follows:

     ```sql
     ALTER SYSTEM SET DATA_BACKUP_DEST= 'data_backup_path';
     ```

   <main id="notice" type='notice'>
   <h4>Note</h4>
   <p>For a scenario where OceanBase Database V4.0.x is upgraded to V4.1.0, the backup path must be changed after the version upgrade. For a scenario where OceanBase Database V4.1.x is upgraded to V4.2.0, the backup path does not need to be changed after the version upgrade.</p>
   </main>

   At present, OceanBase Database supports the following backup media: NFS, Alibaba Cloud Object Storage Service (OSS), Amazon Simple Storage Service (S3), and object storage services compatible with the S3 protocol, such as Huawei Cloud Object Storage Service (OBS), Google Cloud Storage (GCS), and Tencent Cloud Object Storage (COS). Some backup media may require meeting certain basic requirements. For more information about the requirements for each backup media, see the **Backup media requirements** section in [Overview of physical backup and restore](../100.overview-of-physical-backup-and-recovery.md).

   The following table describes the parameters in detail.

    :::tab
    tab OSS

    When OSS is used as the backup media, you can also configure the backup file cleanup mode by using the `delete_mode` parameter. The `delete_mode` parameter supports the `delete` mode and the `tagging` mode. If the `delete_mode` parameter is not explicitly specified, the `delete` mode is used by default.

    In addition, OSS also supports specifying a checksum algorithm by using the `checksum_type` parameter to verify the integrity of backup data. The supported values are `md5` and `no_checksum`. If the `checksum_type` parameter is not explicitly specified, the default value is `md5`.

    For more information about the `delete_mode` parameter and the `checksum_type` parameter, see [SET DATA_BACKUP_DEST](../../../700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/3500.set-data-backup-dest.md).

    <main id="notice" type='notice'>
    <h4>Note</h4>
    <p>When an object storage service is used as the backup media, the parameters in the object storage path are separated by the <code>&</code> character. Make sure that the values you enter for the parameters contain only uppercase and lowercase letters, numbers, <code>/-_$+=</code>, and wildcard characters. If you enter characters other than the aforesaid ones, the setting may fail.</p>
    </main>

    * When OSS is used as the backup media, the system tenant configures the backup path for the specified tenant `mysql_tenant`, specifies the backup file cleanup mode to `delete`, and sets the checksum algorithm to `md5`.

      ```shell
      obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='oss://oceanbase-test-bucket/backup/data?host=****.aliyun-inc.com&access_id=****&access_key=****&delete_mode=delete&checksum_type=md5' TENANT = mysql_tenant;
      ```

      If you do not want to verify the integrity of backup data, you can set the `checksum_type` parameter to `no_checksum`. An example is as follows:

      ```shell
      obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='oss://oceanbase-test-bucket/backup/data?host=****.aliyun-inc.com&access_id=****&access_key=****&delete_mode=delete&checksum_type=no_checksum' TENANT = mysql_tenant;
      ```

    * When OSS is used as the backup media, the user tenant configures the backup path for the current tenant and specifies the backup file cleanup mode to `delete` and the checksum algorithm to `md5`.

      ```sql
      obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='oss://oceanbase-test-bucket/backup/data?host=****.aliyun-inc.com&access_id=****&access_key=****&delete_mode=delete&checksum_type=md5';
      ```

    In the preceding examples, `oss://` indicates that the S3 protocol is used for backup media, the bucket name is `oceanbase-test-bucket`, the path in the bucket is `/backup/data`, and the other path parameters are separated with `?`. The parameter `host` is used to set the host address of the bucket, the parameter `access_id` is used to set the access ID of the OSS service, and the parameter `access_key` is used to set the access key of the OSS service. The backup file cleanup mode is set to `delete`, and the MD5 algorithm is used to verify the integrity of backup data.

    After you set the `delete` mode or the `tagging` mode, related operations for automatically cleaning up expired backup data are described in [Automatically clean up expired backup data](../500.clear-backup-data/100.cleaning-up-backed-up-data-automatically.md).

    tab NFS

    <main id="notice" type='notice'>
    <h4>Note</h4>
    <p>When an NFS is used as the backup media, note the following items:</p>
    <ul>
    <li>The value of the <code>data_backup_dest</code> parameter cannot contain a question mark (?).</li>
    <li>The value of the <code>data_backup_dest</code> parameter must be an absolute path, and the OBServer node must have write permissions on <code>data_backup_dest</code>.</li>
    <li>All OBServer nodes must mount the same NFS service. To ensure smooth backup, use the parameters recommended in this topic to mount the NFS service. For more information about how to mount the NFS service, see <a href="../200.deploy-nfs.md">Deploy an NFS client</a>.</li>
    </ul>
    </main>

    * When an NFS is used as the backup media, the system tenant configures the backup path for the specified tenant `mysql_tenant`.

      ```sql
      obclient> ALTER SYSTEM SET DATA_BACKUP_DEST= 'file:///data/nfs/backup/data' TENANT = mysql_tenant;
      ```

    * When an NFS is used as the backup media, the user tenant configures the backup path for the current tenant.

      ```sql
      obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='file:///data/nfs/backup/data';
      ```

    In the preceding examples, `file://` indicates that the NFS protocol is used for backup media, and the backup path is `file:///data/nfs/backup/data`.

    tab AWS S3

    Like OSS, AWS S3 also supports configuring the backup file cleanup mode by using the `delete_mode` parameter, and the configuration method is the same as that for OSS. In addition, AWS S3 also supports verifying the integrity of backup data by using the `checksum_type` parameter, and the supported values are `md5` and `crc32`. If the `checksum_type` parameter is not explicitly specified, the default value is `md5`.

    For more information about the `delete_mode` parameter and the `checksum_type` parameter, see [SET DATA_BACKUP_DEST](../../../700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/3500.set-data-backup-dest.md).

    <main id="notice" type='notice'>
    <h4>Note</h4>
    <p>When an object storage service is used as the backup media, the parameters in the object storage path are separated by the <code>&</code> character. Make sure that the values you enter for the parameters contain only uppercase and lowercase letters, numbers, <code>/-_$+=</code>, and wildcard characters. If you enter characters other than the aforesaid ones, the setting may fail.</p>
    </main>

    The following examples show how to configure an S3 service as the backup media:

    * When an S3 service is used as the backup media, the system tenant configures the backup path for the specified tenant `mysql_tenant`, specifies the backup file cleanup mode to `delete`, and sets the checksum algorithm to `crc32`.

      ```sql
      obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='s3://oceanbase-test-bucket/backup/data?host=s3.<region>.amazonaws.com&access_id=****&access_key=****&s3_region=****&delete_mode=delete&checksum_type=crc32' TENANT = mysql_tenant;
      ```

    * When an S3 service is used as the backup media, the user tenant configures the backup path for the current tenant and specifies the backup file cleanup mode to `delete` and the checksum algorithm to `crc32`.

      ```sql
      obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='s3://oceanbase-test-bucket/backup/data?host=s3.<region>.amazonaws.com&access_id=****&access_key=****&s3_region=****&delete_mode=delete&checksum_type=crc32';
      ```

    In the preceding examples, `s3://` indicates that the S3 protocol is used for backup media, the bucket name is `oceanbase-test-bucket`, the path in the bucket is `/backup/data`, and the other path parameters are separated with `?`. The parameter `host` is used to set the domain name of the Amazon S3 service, the parameters `access_id` and `access_key` are used to set the access ID and access key of the AWS service, respectively, `s3_region` is an optional parameter when an S3 service is used as the backup media, and it is used to specify the region where the S3 bucket is located. The backup file cleanup mode is set to `delete`, and the CRC32 algorithm is used to verify the integrity of backup data.

    tab Object storage services compatible with the S3 protocol

    Most object storage services are compatible with the S3 protocol. Therefore, object storage services that are compatible with the S3 protocol and meet the requirements of OceanBase Database can be used as the backup media of OceanBase Database. You can access compatible object storage services in the same way as you access S3, such as OBS, GCS, and COS. These object storage services are accessed through the S3 protocol.

    For object storage services such as OBS, GCS, and COS that are accessed through the S3 protocol, you can also verify the integrity of backup data by using the `checksum_type` parameter, and the supported value is only `md5`. If the `checksum_type` parameter is not explicitly specified, the default value is `md5`. For more information about the `checksum_type` parameter, see [SET DATA_BACKUP_DEST](../../../700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/3500.set-data-backup-dest.md).

    <main id="notice" type='notice'>
    <h4>Note</h4>
    <p>When an object storage service is used as the backup media, the parameters in the object storage path are separated by the <code>&</code> character. Make sure that the values you enter for the parameters contain only uppercase and lowercase letters, numbers, <code>/-_$+=</code>, and wildcard characters. If you enter characters other than the aforesaid ones, the setting may fail.</p>
    </main>

    The following examples show how to configure OBS as the backup media:

    * When OBS is used as the backup media, the system tenant configures the backup path for the specified tenant `mysql_tenant`.

      ```sql
      obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='s3://oceanbase-test-bucket/backup/data?host=obs.****.myhuaweicloud.com&access_id=****&access_key=****' TENANT = mysql_tenant;
      ```

    * When OBS is used as the backup media, the user tenant configures the backup path for the current tenant.

      ```sql
      obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='s3://oceanbase-test-bucket/backup/data?host=obs.****.myhuaweicloud.com&access_id=****&access_key=****';
      ```

    In the preceding examples, `s3://` indicates that the S3 protocol is used for backup media, the bucket name is `oceanbase-test-bucket`, the path in the bucket is `/backup/archive`, and the other path parameters are separated with `?`. The parameter `host` is used to set the host address of OBS, which is the endpoint without the bucket name, the parameter `access_id` is used to set the access ID of the OBS service, and the parameter `access_key` is used to set the access key of the OBS service.

    The following examples show how to configure GCS as the backup media:

    * When GCS is used as the backup media, the system tenant configures the backup path for the specified tenant `mysql_tenant`.

      ```sql
      obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='s3://oceanbase-test-bucket/backup/data?host=https://storage.googleapis.com&access_id=****&access_key=****' TENANT = mysql_tenant;
      ```

    * When GCS is used as the backup media, the user tenant configures the backup path for the current tenant.

      ```sql
      obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='s3://oceanbase-test-bucket/backup/data?host=https://storage.googleapis.com&access_id=****&access_key=****';
      ```

    In the preceding examples, `s3://` indicates that the S3 protocol is used for backup media, the bucket name is `oceanbase-test-bucket`, the path in the bucket is `/backup/archive`, and the other path parameters are separated with `?`. The parameter `host` is used to set the endpoint of GCS without the bucket name, the parameter `access_id` is used to set the access ID of the GCS service, and the parameter `access_key` is used to set the access key of the GCS service.

    The following examples show how to configure COS as the backup media:

        ```shell
        obclient> SHOW PARAMETERS LIKE '%ob_storage_s3_url_encode_type%';

        The following examples show how to configure COS as the backup media for the system tenant:

        ```shell
        obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='s3://oceanbase-test/backup/data?host=cos.ap-xxxx.myqcloud.com&access_id=***&access_key=***&delete_mode=delete' TENANT = mysql_tenant;

The backup file cleanup mode is set to `delete`.

3. After the configuration is completed, the `sys` tenant can query the backup path and other information of each tenant in the current cluster through the `CDB_OB_BACKUP_PARAMETER` view. For more information, see [View data backup parameters](700.parameters-of-data-backup.md).

### Considerations and descriptions after the configuration is complete

1. After the `data_backup_dest` parameter is successfully configured, the system creates a `format` file in the directory where the specified destination is located by default. The `format` file is used to verify the validity of the backup destination and ensure the integrity of data in the destination. Therefore, note the following items when you configure the destination for data backup by using the `data_backup_dest` parameter:

  * If the `format` file does not exist, the configuration fails if the directory where the specified destination is located is not empty. In this case, the system returns error code `-9080` and indicates that the `format` file does not exist.

  * If the `format` file exists, the configuration fails unless the `format` file passes the verification. In this case, the system returns error code `-9081` and indicates that the `format` file does not match. The verification of the `format` file mainly checks whether the cluster, tenant, and type of the backup destination match those of the current cluster, tenant, and backup destination type.

  * If the `format` file does not exist or fails the verification during backup task execution, the task will fail.

2. After the backup destination is specified, if you change the object storage keys for security reasons or other reasons, you must update the `access_id` and `access_key` values of the configured backup path. For more information, see [Change `access_id` and `access_key` of the backup path or log archive path](../450.change-sk-and-ak-for-the-backup-path-or-logarchive-path.md).

## Backup keys

Before you back up data, you also need to consider the encryption status of the source tenant. If the source tenant uses transparent encryption, you also need to back up the keys of the source tenant.

<main id="notice" type='notice'>
<h4>Notice</h4>
<p>After you back up keys, if the encryption information of the source tenant triggers key rotation before you restore the data, you need to back up the keys of the source tenant again. </p>
</main>

1. Log in to the database as the tenant administrator of the `sys` tenant or a user tenant.

2. Backup keys.

   * Back up keys for the specified tenant in the system tenant

     ```sql
     ALTER SYSTEM BACKUP KEY TENANT = tenant_name TO 'backup_key_path' ENCRYPTED BY 'password';
     ```

   * Back up keys for the current tenant in a user tenant

     Use the following statement:

     ```sql
     ALTER SYSTEM BACKUP KEY TO 'backup_key_path' ENCRYPTED BY 'password';
     ```

   In the statement:

   * `backup_key_path`: the path where the key is to be backed up. You must specify this path, which cannot be the same as the path for data backup or log archiving.

   * `password`: the encryption password for the key backup path.

   Here is an example of backing up keys for the `mysql_tenant` tenant in the system tenant:

   ```sql
   obclient [(none)]> ALTER SYSTEM BACKUP KEY TENANT = mysql_tenant TO 'file:///data_backup_dest/key' ENCRYPTED BY '******';
   ```

3. After the configuration is completed, you can query the path where keys are backed up by using views.

   * Query the path where keys are backed up in the system tenant by using the `CDB_OB_BACKUP_STORAGE_INFO` view

     ```sql
     SELECT * FROM oceanbase.CDB_OB_BACKUP_STORAGE_INFO;
     ```

   * Query the path where keys are backed up in a user tenant by using the `DBA_OB_BACKUP_STORAGE_INFO` view

     :::tab
     tab MySQL mode

     Use the following statement:

     ```sql
     SELECT * FROM oceanbase.DBA_OB_BACKUP_STORAGE_INFO;
     ```

     tab Oracle mode

     Use the following statement:

     ```sql
     SELECT * FROM SYS.DBA_OB_BACKUP_STORAGE_INFO;
     ```

     :::

     For more information about the fields in the `CDB_OB_BACKUP_STORAGE_INFO` and `DBA_OB_BACKUP_STORAGE_INFO` views, see [CDB_OB_BACKUP_STORAGE_INFO](../../../700.reference/700.system-views/300.system-view-of-sys-tenant/200.dictionary-view-of-sys-tenant/15100.oceanbase-cdb_ob_backup_storage_info-of-sys-tenant.md) and [DBA_OB_BACKUP_STORAGE_INFO](../../../700.reference/700.system-views/300.system-view-of-sys-tenant/200.dictionary-view-of-sys-tenant/15200.oceanbase-dba_ob_backup_storage_info-of-sys-tenant.md).
