# Schema recovery in table-level restore

After a table-level restore is performed, the following schema information and its description are provided.

| Schema  | Recoverable | Description                                                  |
|---------------|-----------|--------------------------------------------------------|
| Database      |    No      | When you perform a table-level restore, the corresponding database in the target tenant must exist. Otherwise, the restore fails. For example, if the backed-up table belongs to the `INFO` database, the system will restore the table to the `INFO` database in the target tenant unless you use the `REMAP TABLE` command to rename the table to another database in the target tenant.      |
| Tablespace    |    No      | When you perform a table-level restore, the corresponding tablespace in the target tenant must exist. Otherwise, the restore fails. For example, if the backed-up table belongs to the `TS` tablespace, the system will restore the table to the `TS` tablespace in the target tenant unless you use the `REMAP TABLE` command to rename the table to another tablespace in the target tenant.       |
| Table group          |     No      | When you perform a table-level restore, the corresponding table group in the target tenant must exist. Otherwise, the restore fails. For example, if the backed-up table belongs to the `TG` table group, the system will restore the table to the `TG` table group in the target tenant unless you use the `REMAP TABLE` command to rename the table to another table group in the target tenant. |
| Table            |    Yes      | Only user tables can be restored. Columnstore and hybrid row-columnstore tables can be restored. System tables and temporary tables cannot be restored. |
| Partition          |    Yes      | N/A |
| Tablet        |    Yes      | N/A |
| Column        |    Yes      | N/A |
| Constraint          |    Yes      | The following constraints can be restored:<ul><li>`NOT NULL` constraint </li> <li>`UNIQUE KEY` constraint </li> <li>`PRIMARY KEY` constraint <main id="notice" type='notice'><h4>Notice</h4><p>In Oracle mode, if the <code>PRIMARY KEY</code> constraint name is duplicated, the entire table restore will fail. </p></main></li> <li>`CHECK` constraint</li></ul> <main id="notice" type='explain'><h4>Note</h4><p>If the constraint name is user-defined and already exists in the target tenant, it will not be restored. </p></main> |
| Foreign key          |    Yes      | During the restore of a foreign key, the system checks the integrity of the foreign key constraint. If a foreign key references a non-existent row, the restore of the foreign key will fail. |
| View          |    No      | Views associated with the table are not restored. |
| Materialized view      |    No      | Materialized views associated with the table cannot be restored. |
| Materialized view log  |    No      | Materialized view logs associated with the table cannot be restored. |
| Local index      |    Yes      | N/A |
| Global index      |    Yes      | N/A |
| Full-text index      |    Yes      | N/A |
| JSON multi-value index |    Yes      | N/A |
| Vector index      |    Yes      | N/A |
| Spatial index      |    Yes      | When you perform a table-level restore, the coordinate system is not restored. If the target tenant does not have a reference coordinate system, the spatial index is not restored. If the target tenant has a coordinate system, the spatial index is restored. |
| Auto-increment column        |    Yes      | N/A |
| Table without a primary key      |    Yes      | N/A |
| Statistics      |    Yes      | N/A |
| Trigger        |    Yes      | <ul><li> If the table is restored by its original name, the triggers associated with the table are restored. In this case:<ul><li>In Oracle mode, if the user who owns the trigger does not exist, the restore of the trigger will fail. </li> <li>In MySQL mode, if the database that owns the trigger does not exist, the restore of the trigger will fail. </li></ul></li> <li> If the table is renamed and restored by the new name, the triggers associated with the table are not restored. </li></ul> |
| Function, stored procedure, and package |    No  | Functions, stored procedures, and packages associated with the table are not restored. |
| Synonym        |    No      | Synonyms associated with the table are not restored. |
| LOB          |    Yes      | N/A |
