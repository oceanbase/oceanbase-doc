# Preparations before table-level restore

Table-level restore requires the use of a tenant. Therefore, before performing table-level restore, you need to create the required resource pools for the auxiliary tenant in the cluster where the target tenant is located.

## Resource planning for the auxiliary tenant

During table-level restore, an auxiliary tenant needs to be created in the target cluster. Therefore, before performing table-level restore, you need to reserve sufficient CPU, memory, and disk resources in the cluster to avoid slow execution or failure of the table-level restore task due to resource shortages.

Typically, we recommend that the specifications of the auxiliary tenant be the same as those of the source tenant. If this is not possible, you need to select an appropriate specification based on the version.

In the current version, the system uses the fast restore method for table-level restore of the auxiliary tenant. The minimum specifications of the auxiliary tenant in the fast restore method are as follows:

| Resource | Minimum Specification | Description |
|----------------|-------------------|---------|
| CPU | 2C or 4C | The minimum specification is not recommended to be set too small. |
| Memory | Varies with the number of tablets | The minimum specification needs to be at least 1GB, and can support up to 20,000 tablets. |
| Disk | Backup data volume/100 + restore log volume | The minimum specification is recommended to be at least 1% of the backup data volume, plus the restore log volume. |

## Create a resource pool for the auxiliary tenant

1. Log in to the `sys` tenant of the cluster where the target tenant is located as the `root` user.

2. Create a unit (resource unit).

   Here is an example:

   ```shell
   obclient [(none)]> CREATE RESOURCE UNIT box_16c96g MAX_CPU 16, MEMORY_SIZE = '5G', MAX_IOPS 10240, MIN_IOPS=10240;
   ```

   For more information about how to create a resource unit, see [Create a tenant](../../200.tenant-management/600.common-tenant-operations/200.manage-create-tenant.md).

3. Create a resource pool.

   When creating a resource pool for the auxiliary tenant, we recommend that you keep the architecture consistent with the source tenant. In other words, we recommend that the number of `unit_num` in the resource pool of the auxiliary tenant be the same as that of the source tenant.

   Here is an example:

   ```shell
   obclient [(none)]> CREATE RESOURCE POOL restore_pool unit = 'box_16c96g', unit_num = 1, zone_list = ('z1','z2','z3');
   ```

   For more information about how to create a resource pool, see [Create a tenant](../../200.tenant-management/600.common-tenant-operations/200.manage-create-tenant.md).
