# Experience Operational OLAP

OceanBase Database can handle scenarios with mixed workloads. Based on a distributed architecture of peer nodes, it is capable of supporting high-concurrency, scalable OLTP tasks, while also performing parallel computing for OLAP tasks within the same data engine using the MPP architecture, eliminating the need to maintain two separate datasets.

In OceanBase Database, you can not only perform parallel analysis directly on large volumes of online business data, but also leverage its Parallel DML (PDML) capability to quickly and securely execute large batch-write transactions concurrently. All of this is achieved while strictly guaranteeing transaction consistency.

Below, we will manually run the TPC-H benchmark to demonstrate the features and usage of OceanBase Database in operational OLAP scenarios. TPC-H is an industry-standard benchmark for decision support business. It evaluates the analytical and decision support capabilities of a database system through a series of complex queries executed on large datasets. For more information, visit the official TPC website. (On May 20, 2021, OceanBase Database set a new world record in TPC-H with a score of 15.26 million QphH, becoming the only database to simultaneously break both TPC-C and TPC-H records, proving its ability to handle both online transaction and real-time analytics workloads. For details, see [TPC-H Result](https://www.tpc.org/tpch/results/tpch_results5.asp?version=3))

## Manually perform the TPC-H test

The following content describes how to manually perform the TPC-H test step by step using the official TPC-H tool. Manual testing can help you better understand OceanBase Database, especially the parameter settings.

### Optimize the environment

1. Optimize OceanBase Database.

   Execute the following statements in the system tenant (`sys` tenant) to configure the relevant parameters.

   ```bash
   # Adjust the memory allocated to the sys tenant to provide more resources for the test tenant, and adjust it dynamically based on the actual environment.
   ALTER SYSTEM SET system_memory='15g';
   ALTER RESOURCE UNIT sys_unit_config memory_size ='15G';
   # Tuning parameters
   ALTER SYSTEM SET trace_log_slow_query_watermark='100s';
   ALTER SYSTEM SET enable_sql_operator_dump=True;
   ALTER SYSTEM SET _hash_area_size='3g';
   ALTER SYSTEM SET memstore_limit_percentage=50;
   ALTER SYSTEM SET enable_rebalance=False;
   ALTER SYSTEM SET memory_chunk_cache_size='0';
   ALTER SYSTEM SET major_compact_trigger=5;
   ALTER SYSTEM SET cache_wash_threshold='30g';
   # Adjust the log level and retention count
   ALTER SYSTEM SET syslog_level='ERROR';
   ALTER SYSTEM SET max_syslog_file_count=100;
   ALTER SYSTEM SET enable_syslog_recycle='True';
   ```

2. Configure the tenant settings.

   Execute the following statements in the test tenant (user tenant) to configure the relevant parameters.

   ```bash
   # Set global parameters
   SET GLOBAL ob_sql_work_area_percentage=80;
   SET GLOBAL optimizer_use_sql_plan_baselines = true;
   SET GLOBAL optimizer_capture_sql_plan_baselines = true;
   ALTER SYSTEM SET ob_enable_batched_multi_statement='true';
   # Set these parameters at the tenant level to prevent transaction timeouts.
   SET GLOBAL ob_query_timeout=36000000000;
   SET GLOBAL ob_trx_timeout=36000000000;
   SET GLOBAL max_allowed_packet=67108864;
   SET GLOBAL secure_file_priv="";
   /*
   We recommend that you set parallel_server_target to 10 times the number of CPU cores allocated to the test tenant, multiplied by the number of servers, and then multiplied by 0.8.
   If the unit configuration used by the test tenant is: `CREATE RESOURCE UNIT $unit_name max_cpu 26;`
   Then the value is 26*10*3*0.8=624
   */
   SET GLOBAL parallel_servers_target=624;
   ```

3. After optimizing the parameter settings, restart the cluster.

### Enable concurrent execution

OceanBase Database's Operational OLAP capability is based on a single set of data and an execution engine, eliminating the need for heterogeneous data synchronization and maintenance. Below, we add a `parallel` hint and execute the statement again with a degree of parallelism of 8:

```sql
select /*+parallel(8) */
 l_returnflag,
 l_linestatus,
 sum(l_quantity) as sum_qty,
 sum(l_extendedprice) as sum_base_price,
 sum(l_extendedprice * (1 - l_discount)) as sum_disc_price,
 sum(l_extendedprice * (1 - l_discount) * (1 + l_tax)) as sum_charge,

 lineitem
where
 l_shipdate <= date '1998-12-01' - interval '90' day

 l_linestatus
order by
 l_returnflag,

It is worth noting that the most significant feature of OceanBase Database's parallel execution framework is its ability to perform analytical queries on large datasets concurrently across multiple nodes. For example, a table containing hundreds of millions of rows distributed across multiple OceanBase Database nodes can be analyzed using a distributed parallel execution plan generated by OceanBase Database's distributed execution framework, leveraging resources from multiple nodes. Therefore, it offers excellent scalability, and parallel settings can also be configured at multiple levels, including SQL, session, and table.

## Automatically perform TPCH testing using the obd tool

  <main id="notice" >
    <h4>Applicability</h4>
    <p>This content applies only to OceanBase Database Community Edition. OceanBase Database Enterprise Edition does not currently support the use of obd.</p>
  </main>

In addition to using the dataset generation tool provided on the official TPC website for TPC-H testing, you can also use obd to conveniently perform tasks such as dataset generation, table creation, and data import, while automatically executing the 22 SQL queries.
Before using obd for TPC-H testing, you need to install the obtpch component on the node where OceanBase and obd are deployed:

```test
sudo yum install obtpch
```

After completion, you can start a TPC-H test with a dataset size of 1 GB using the following command. The entire process includes dataset generation, schema import, and automatic test execution. This topic assumes that your test environment deployment is consistent with the steps in [Quick start with OceanBase Database Community Edition](../100.quickly-experience-oceanbase-for-community.md). If there are differences, such as cluster name, password, or installation directory, please adjust accordingly.

  <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>Ensure your disk space is sufficient to accommodate the dataset files to prevent system exceptions due to full disk space.</p>
  </main>

In this example, we use the /tmp directory for testing.

```test
cd /tmp
obd test tpch obtest --tenant=test -s 1 --password='******' --remote-tbl-dir=/tmp/tpch1 
```
