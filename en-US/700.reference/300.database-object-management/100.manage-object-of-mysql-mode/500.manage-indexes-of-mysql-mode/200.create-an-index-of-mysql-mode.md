# Create an index

This topic describes how to create an index.

## Background information

OceanBase Database allows you to create indexes on both partitioned and non-partitioned tables. The indexes can be local or global, unique or non-unique, spatial, or functional. For a unique index on a partitioned table, the local unique index must contain the partitioning key of the table partitions. For more information about indexes, see [Overview](../../../100.oceanbase-database-concepts/400.database-objects/200.database-objects-of-mysql-mode/300.index-of-oracle-mode/100.index-overview-of-mysql-mode.md).

This topic describes how to create an index on a non-partitioned table. For information about how to create an index on a partitioned table, see [Create an index on a partitioned table](../300.manage-partitions-of-mysql-mode/900.create-partition-table-index-of-mysql-mode/200.local-index-of-mysql-mode.md).

## Considerations

When you create an index, make sure that the index name is unique in the database (DataBase) scope in OceanBase Database.

## Create a normal index

You can use the `CREATE TABLE`, `CREATE INDEX`, or `ALTER TABLE` statement to create a normal index.

### Create a normal index by using the `CREATE TABLE` statement

You can use the `CREATE TABLE` statement to create an index for a table when you create the table.

The syntax is as follows:

```sql
CREATE TABLE table_name(column_name column_definition,[column_name column_definition,...] [UNIQUE] INDEX|KEY [index_name](column_name));
```

The parameters are described as follows:

* `table_name`: the name of the table to be created.

* `column_name`: the name of a column in the table.

* `column_definition`: the data type of each column in the table.

* `UNIQUE`: optional. Specifies to create a unique index. If you create a unique index, you must specify this keyword.

* `INDEX|KEY`: optional. Specifies the index keyword. You can use either INDEX or KEY.

* `index_name`: optional. the name of the index to be created. If you do not specify the name, the default index name is the same as the name of the specified column.

Here is an example of creating a `tbl1` table and an index named `tbl1_idx1` at the same time:

```sql
CREATE TABLE tbl1(id INT,name VARCHAR(18),date DATE,PRIMARY KEY (id),INDEX tbl1_idx1 (date));
```

### Create a normal index by using the `CREATE INDEX` statement

You can use the `CREATE INDEX` statement to create an index for an existing table.

The syntax is as follows:

```sql
CREATE [UNIQUE] INDEX index_name ON table_name (column_name);
```

The parameters are described as follows:

* `UNIQUE`: optional. Specifies to create a unique index. If you create a unique index, you must specify this keyword.

* `index_name`: the name of the index to be created.

* `table_name`: the name of the table on which an index is to be created.

* `column_name`: the columns to be indexed. Separate the column names with commas (,).

Here is an example. The `tbl2` table is created, and then an index named `tbl2_idx1` is created for the `tbl2` table:

1. Create the `tbl2` table.

   ```sql
   CREATE TABLE tbl2(id INT,name VARCHAR(20));
   ```

2. Create an index named `tbl2_idx1` for the `tbl2` table.

   ```sql
   CREATE INDEX tbl2_idx1 ON tbl2(id);
   ```

### Create a normal index by using the `ALTER TABLE` statement

You can use the `ALTER TABLE` statement to create an index for an existing table. You can use this statement to add multiple indexes at a time.

The syntax is as follows:

```sql
ALTER TABLE table_name ADD [UNIQUE] INDEX|KEY [index_name](column_name);
```

The parameters are described as follows:

* `table_name`: the name of the table on which an index is to be created.

* `UNIQUE`: optional. Specifies to create a unique index. If you create a unique index, you must specify this keyword.

* `INDEX|KEY`: optional. Specifies the index keyword. You can use either INDEX or KEY.

* `index_name`: optional. the name of the index to be created. If you do not specify the name, the default index name is the same as the name of the specified column.

* `column_name`: the columns to be indexed. Separate the column names with commas (,).

Here is an example. The `tbl3` table is created, and then an index named `tbl3_idx1` is created for the `tbl3` table:

1. Create the `tbl3` table.

   ```sql
   CREATE TABLE tbl3(id INT,name VARCHAR(20));
   ```

2. Create an index named `tbl3_idx1` for the `tbl3` table.

   ```sql
   ALTER TABLE tbl3 ADD INDEX tbl3_idx1(id);
   ```

## Create a spatial index

The MySQL mode of OceanBase Database supports spatial indexes. A spatial index describes the data locations stored in media and helps improve the system efficiency in data acquisition.

The syntax for creating a spatial index is similar to that for creating a normal index, which also uses the `CREATE TABLE`, `CREATE INDEX`, or `ALTER TABLE` statement to create an index. The main difference is that a spatial index requires the use of the `SPATIAL` keyword, and the columns in a spatial index must be specified as `NOT NULL`.

### Limitations on spatial indexes

Before you create a spatial index, note the following limitations:

* Only local indexes are supported. Global indexes are not supported.

* When you create a spatial index on a column, you must set the `SRID` attribute for the column. Otherwise, the spatial index will not take effect in subsequent queries on the column. This is because, when a spatial index is created, the coordinate system corresponding to the `SRID` in the column definition is used for comparisons. The spatial index stores the minimum bounding rectangle (MBR) of geometric objects, and MBR comparisons depend on the `SRID`.

  For more information about the `SRID` attribute, see [Spatial reference systems (SRS)](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/100.basic-elements-of-mysql-mode/100.data-type-of-mysql-mode/900.spatial-data-type-of-mysql-mode/200.spacial-reference-system-of-mysql-mode.md).

* A spatial index can be created only on a column of a spatial data type. For more information about spatial data types supported by OceanBase Database, see [Overview of spatial data types](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/100.basic-elements-of-mysql-mode/100.data-type-of-mysql-mode/900.spatial-data-type-of-mysql-mode/100.spatial-data-type-overview-of-mysql-mode.md).

* The column on which a spatial index is to be created must be defined as `NOT NULL`.

  Otherwise, you can use the `ALTER TABLE` statement to change the column attribute to `NOT NULL`. For more information, see [Define a column constraint](../200.manage-tables-of-mysql-mode/400.define-the-constraint-type-for-a-column-of-mysql-mode.md).

### Create a spatial index by using the `CREATE TABLE` statement

The syntax is as follows:

```sql
CREATE TABLE table_name(column_g_name GEOMETRY NOT NULL SRID 4326,[column_name column_definition,...] SPATIAL INDEX|KEY [index_name](column_g_name));
```

The parameters are described as follows:

* `table_name`: the name of the table to be created.

* `column_g_name` and `column_name`: the names of the columns in the table.

* `SRID 4326`: the `SRID` of the spatial column.

* `column_definition`: the data types of the columns in the table. The data type of the column on which a spatial index is to be created must be a spatial data type. For more information about spatial data types supported by OceanBase Database, see [Overview of spatial data types](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/100.basic-elements-of-mysql-mode/100.data-type-of-mysql-mode/900.spatial-data-type-of-mysql-mode/100.spatial-data-type-overview-of-mysql-mode.md).

* `INDEX|KEY`: specifies that in this statement, the keyword INDEX or KEY can be used.

* `index_name`: the name of the index to be added. If you do not specify the index name, the name of the column on which the index is to be created is used as the default index name.

Here is an example of creating the `tbl1_g` table and adding the spatial index `tbl1_g_idx1`:

```sql
CREATE TABLE tbl1_g (id INT,name VARCHAR(18),g GEOMETRY NOT NULL SRID 4326,SPATIAL INDEX tbl1_g_idx1(g));
```

After the table is created, you can execute the `SHOW INDEX` statement to query the index information.

```sql
SHOW INDEX FROM tbl1_g;
```

The query result is as follows:

```shell
+--------+------------+-------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+
| Table  | Non_unique | Key_name    | Seq_in_index | Column_name | Collation | Cardinality | Sub_part | Packed | Null | Index_type | Comment   | Index_comment | Visible |
+--------+------------+-------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+
| tbl1_g |          1 | tbl1_g_idx1 |            1 | g           | A         |        NULL | NULL     | NULL   |      | SPATIAL    | available |               | YES     |
+--------+------------+-------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+
```

## Create a function index

An index that is created based on the results of a function applied to one or more columns is called a function index. Function indexes are used to quickly locate matching function values in queries, thereby avoiding repeated computations and improving query efficiency.

Assume that you have a `sale` table with a `date_col` column of the `date` data type:

```sql
CREATE TABLE sale(date_col date, sales_col int, name_col varchar(10));
```

If you want to retrieve data of only March, you can use the `Month()` function for the query:

```sql
SELECT * FROM sale WHERE month(date_col) = 3;
```

In this case, the database needs to compute `month(date_col)` for each row in the table and filter out rows where `month(date_col) <> 3`. If you frequently use the month information for filtering, `month(date_col)` needs to be recomputed each time, which causes a lot of overhead. Therefore, you can create a function index on `date_col` to store `month(date_col)` in the index table to accelerate queries.

```sql
CREATE INDEX idx1 ON sale((month(date_col)));
```

You can use the `CREATE TABLE`, `CREATE INDEX`, or `ALTER TABLE` statement to create a function index. A function index can also be a unique index or a spatial index.

### Limitations on function indexes

In MySQL mode of OceanBase Database, expressions that use certain system functions are not allowed as function indexes. For a list of system functions that are supported as function indexes, see [System functions supported as function indexes](../500.manage-indexes-of-mysql-mode/500.function-index-list-of-supported-functions-of-mysql-mode.md). For a list of system functions that are not supported as function indexes, see [System functions not supported as function indexes](../500.manage-indexes-of-mysql-mode/600.function-index-list-of-not-supported-functions-of-mysql-mode.md).

### Create a function index by using the `CREATE TABLE` statement

You can create a function index when you create a table. The syntax is as follows:

```sql
CREATE TABLE table_name({column_name column_definition,[column_name column_definition,...]} [UNIQUE| SPATIAL] {INDEX|KEY} [index_name](expr));
```

The parameters are described as follows:

* `table_name`: the name of the table on which you want to create an index.

* `column_definition`: the data type of each column in the table.

* `[UNIQUE | SPATIAL]`: optional. `UNIQUE` indicates a unique index, and `SPATIAL` indicates a spatial index. You must specify this parameter when you create a unique index or a spatial index.

* `INDEX|KEY`: optional. This parameter indicates that you can use `INDEX` or `KEY` in the statement.

* `index_name`: the name of the function index that you want to create. This parameter is optional. If you do not specify this parameter, the system automatically generates a name for the index. The format of the name is `functional_index_xx`, where `xx` indicates the index number.

* `expr`: a valid function index expression, such as `c1=c1`, which is allowed to be a boolean expression.

Here is an example of creating a function index named `tbl1_func_idx1`:

```sql
CREATE TABLE tbl1_func (c1 int, c2 int, index tbl1_func_idx1 ((c1+1)), UNIQUE KEY ((c1+c2)));
```

After the function index is created, you can execute the `SHOW CREATE TABLE` statement to view the statement for creating the table. The statement is as follows:

```sql
SHOW CREATE TABLE tbl1_func;
```

The query result is as follows:

```sql
+-----------+-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| Table     | Create Table                                                                                                                                                                                                                                                                                                                                                                                        |
+-----------+-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| tbl1_func | CREATE TABLE `tbl1_func` (
  `c1` int(11) DEFAULT NULL,
  `c2` int(11) DEFAULT NULL,
  UNIQUE KEY `functional_index` ((`c1` + `c2`)) BLOCK_SIZE 16384 LOCAL,
  KEY `tbl1_func_idx1` ((`c1` + 1)) BLOCK_SIZE 16384 LOCAL
) DEFAULT CHARSET = utf8mb4 ROW_FORMAT = DYNAMIC COMPRESSION = 'zstd_1.3.8' REPLICA_NUM = 1 BLOCK_SIZE = 16384 USE_BLOOM_FILTER = FALSE TABLET_SIZE = 134217728 PCTFREE = 0 |
+-----------+-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
1 row in set
```

### Create a function index by using the `CREATE INDEX` statement

You can create a function index for an existing table. The syntax is as follows:

```sql
CREATE [UNIQUE | SPATIAL] INDEX index_name ON table_name (expr);
```

The parameters are described as follows:

* `[UNIQUE | SPATIAL]`: optional. `UNIQUE` indicates a unique index, and `SPATIAL` indicates a spatial index. You must specify this parameter when you create a unique index or a spatial index.

* `index_name`: the name of the function index that you want to create.

* `table_name`: the name of the table on which you want to create an index.

* `expr`: a valid function index expression, such as `c1=c1`, which is allowed to be a boolean expression.

Create a function index named `tbl2_func_idx1` on the `c1+c2 < 1` defined for the `tbl2_func` table.

1. Create the `tbl2_func` table.

   ```sql
   CREATE TABLE tbl2_func(c1 int, c2 int);
   ```

2. Create the function index `tbl2_func_idx1`.

   ```sql
   CREATE INDEX tbl2_func_idx1 on tbl2_func ((c1+c2 < 1));
   ```

3. View the function index.

   ```sql
   SHOW INDEX FROM tbl2_func;
   ```

   The query result is as follows:

   ```shell
   +-----------+------------+----------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+---------------------+
   | Table     | Non_unique | Key_name       | Seq_in_index | Column_name | Collation | Cardinality | Sub_part | Packed | Null | Index_type | Comment   | Index_comment | Visible | Expression          |
   +-----------+------------+----------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+---------------------+
   | tbl2_func |          1 | tbl2_func_idx1 |            1 | SYS_NC18$   | A         |        NULL | NULL     | NULL   | YES  | BTREE      | available |               | YES     | ((`c1` + `c2`) < 1) |
   +-----------+------------+----------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+---------------------+
   1 row in set
   ```

### Create a function-based index by using the `ALTER TABLE` statement

The syntax is as follows:

```sql
ALTER TABLE table_name ADD [UNIQUE | SPATIAL] {INDEX | KEY} [index_name](expr);
```

The parameters are described as follows:

* `table_name`: the name of the table on which the index is to be created.

* `[UNIQUE | SPATIAL]`: optional. `UNIQUE` indicates a unique index, and `SPATIAL` indicates a spatial index. If you create a unique index or a spatial index, you must add the corresponding keyword.

* `INDEX|KEY`: indicates that you can use the keywords `INDEX` or `KEY` in the statement.

* `index_name`: the name of the function-based index to be created. This parameter is optional. If you do not specify the parameter, the system generates a name for the index, which consists of the `functional_index` prefix and a number.

* `expr`: a valid function-based index expression. For example, `c1=c1` is a valid boolean expression.

1. Create a table named `tbl3_func`.

   ```sql
   CREATE TABLE tbl3_func(c1 int, c2 int);
   ```

2. Create two function-based indexes for the table.

   ```sql
   ALTER TABLE tbl3_func ADD INDEX ((c1+1));
   ```

   ```sql
   ALTER TABLE tbl3_func ADD INDEX ((concat(c1,'a')));
   ```

3. Query the index information.

   ```sql
   SHOW INDEX FROM tbl3_func;
   ```

   The query result is as follows:

   ```shell
   +-----------+------------+--------------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+------------------+
   | Table     | Non_unique | Key_name           | Seq_in_index | Column_name | Collation | Cardinality | Sub_part | Packed | Null | Index_type | Comment   | Index_comment | Visible | Expression       |
   +-----------+------------+--------------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+------------------+
   | tbl3_func |          1 | functional_index   |            1 | SYS_NC18$   | A         |        NULL | NULL     | NULL   | YES  | BTREE      | available |               | YES     | (`c1` + 1)       |
   | tbl3_func |          1 | functional_index_2 |            1 | SYS_NC19$   | A         |        NULL | NULL     | NULL   | YES  | BTREE      | available |               | YES     | concat(`c1`,'a') |
   +-----------+------------+--------------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+------------------+
   2 rows in set
   ```

## Create a columnstore index

You can create a columnstore index by using the `CREATE TABLE`, `CREATE INDEX`, or `ALTER TABLE` statement.

### Create a columnstore index by using the CREATE TABLE statement

You can use the `CREATE TABLE` statement to create a columnstore index when you create a table.

The syntax is as follows:

```sql
CREATE TABLE table_name(column_name column_definition,[column_name column_definition,...] [UNIQUE] INDEX|KEY [index_name](column_name) [STORING(column_name, ...)] WITH COLUMN GROUP([all columns, ]each column));
```

The parameters are described as follows:

* `table_name`: the name of the table on which you want to create an index.

* `column_name`: the name of a column in the table.

* `column_definition`: the data type of each column in the table.

* `UNIQUE`: optional. Specifies to create a unique index. If you want to create a unique index, add this keyword.

* `INDEX|KEY`: optional. Specifies that in this statement, the keywords `INDEX` and `KEY` are equivalent.

* `index_name`: optional. the name of the index that you want to create. If you do not specify this parameter, the name of the created index is the same as the name of the column on which the index is created by default.

* `STORING(column_name, ... )`: optional. specifies the redundant columns in the indexed table. Even if the `column_name` column is not an indexed column, its data is redundantly stored in the columnar format.

* `WITH COLUMN GROUP([all columns, ]each column)`: specifies the columnar properties of the index.

  * `WITH COLUMN GROUP(all columns, each column)`: specifies to create an index that has redundant data in both row-based and columnar storage modes.
  * `WITH COLUMN GROUP(all columns)`: specifies to create an index that has redundant data in the row-based storage mode.
  * `WITH COLUMN GROUP(each column)`: specifies to create an index that has redundant data in the columnar storage mode.

**Here are some examples:**

* Create a table named `tbl4`, and create a redundant index named `idx1_tbl4_cg` that has redundant data in both row-based and columnar storage modes.

   ```sql
   CREATE TABLE tbl4(id INT, name VARCHAR(18), date DATE, PRIMARY KEY (id), INDEX idx1_tbl4_cg (date) WITH COLUMN GROUP(all columns, each column));
   ```

* Create a table named `tbl5`, and create a columnstore index named `idx1_tbl5_cg`. In addition, store the redundant data of the `id` column in the indexed table.

   ```sql
   CREATE TABLE tbl5(id INT, name VARCHAR(18), date DATE, INDEX idx1_tbl5_cg (date) STORING(id) WITH COLUMN GROUP(each column));
   ```

### Create a columnstore index by using the CREATE INDEX statement

You can use the `CREATE INDEX` statement to create a columnstore index for an existing table.

The syntax is as follows:

```sql
CREATE [UNIQUE] INDEX index_name ON table_name (column_name) [STORING(column_name, ...)] WITH COLUMN GROUP([all columns, ]each column);
```

The parameters are described as follows:

* `UNIQUE`: optional. Specifies to create a unique index. If you want to create a unique index, add this keyword.

* `index_name`: the name of the index that you want to create.

* `table_name`: the name of the table on which you want to create an index.

* `column_name`: the names of the columns on which you want to create an index. Separate the names of several columns with commas (,).

* `STORING(column_name, ... )`: optional. specifies the redundant columns in the indexed table. Even if the `column_name` column is not an indexed column, its data is redundantly stored in the columnar format.

* `WITH COLUMN GROUP([all columns, ]each column)`: specifies the columnar properties of the index.

  * `WITH COLUMN GROUP(all columns, each column)`: specifies to create an index that has redundant data in both row-based and columnar storage modes.
  * `WITH COLUMN GROUP(all columns)`: specifies to create an index that has redundant data in the row-based storage mode.
  * `WITH COLUMN GROUP(each column)`: specifies to create an index that has redundant data in the columnar storage mode.

**Here is an example:**

Create a table named `tbl6`. Then, create a columnstore index named `idx1_tbl6_cg` on this table, and store the redundant data of the `age` column in the indexed table.

1. Create a table named `tbl6`.

   ```sql
   CREATE TABLE tbl6(id INT, name VARCHAR(20), age INT);
   ```

2. Create a columnstore index named `idx1_tbl6_cg` on the `tbl6` table, and store the redundant data of the `age` column in the indexed table.

   ```sql
   CREATE INDEX idx1_tbl6_cg ON tbl6(id) STORING(age) WITH COLUMN GROUP(each column);
   ```

### Create a columnstore index by using the ALTER TABLE statement

You can create a columnstore index for an existing table by using the `ALTER TABLE` statement.

The syntax is as follows:

```sql
ALTER TABLE table_name ADD [UNIQUE] INDEX|KEY [index_name](column_name) [STORING(column_name, ...)] WITH COLUMN GROUP([all columns, ]each column);
```

The parameters are described as follows:

* `table_name`: the name of the table on which you want to create an index.

* `UNIQUE`: optional. It specifies to create a unique index. If you want to create a unique index, add this keyword.

* `INDEX|KEY`: optional. It specifies that the index keyword in this statement can be `INDEX` or `KEY`.

* `index_name`: optional. The name of the index that you want to create. If you do not specify this parameter, the default name, which is the same as the name of the specified column, is used.

* `column_name`: the name of the column on which you want to create an index. Separate the names of multiple columns with commas (,).

* `STORING(column_name, ...))`: optional. Specifies the redundant columns of the index table. The data in the `column_name` column is redundantly stored in the columnar format even if this column is not an indexed column.

* `WITH COLUMN GROUP([all columns, ]each column))`: specifies the columnar storage attribute of the index.

  * `WITH COLUMN GROUP(all columns, each column))`: specifies to create an index with redundant rowstore columns.
  * `WITH COLUMN GROUP(all columns))`: specifies to create a rowstore index.
  * `WITH COLUMN GROUP(each column))`: specifies to create a columnstore index.

**Here is an example:**

Create a table named `tbl7` and then create a columnstore index named `idx1_tbl6_cg` on this table.

1. Create a table named `tbl7`.

   ```sql
   CREATE TABLE tbl7(id INT, name VARCHAR(20), age INT);
   ```

2. Create a columnstore index named `idx1_tbl7_cg` on the `tbl7` table and store the redundant data of the `age` column on the index table.

   ```sql
   ALTER TABLE tbl7 ADD INDEX idx1_tbl7_cg(id) STORING(age) WITH COLUMN GROUP(each column);
   ```

## Create multi-valued indexes

OceanBase Database allows you to create multi-valued indexes when you create a table by using the `CREATE TABLE` statement. Currently, you cannot add multi-valued indexes to a table after the table is created, but you can use the `ALTER TABLE` statement to drop existing indexes. If a primary table contains multi-valued indexes, you can perform complex DML operations on the table.

### Limitations on multi-valued indexes

* A multi-valued index can contain only one multi-valued key part. However, the `CAST(... AS ... ARRAY)` expression can reference multiple arrays in a JSON document, as shown in the following example:

   ```sql
   CAST(data->'$.arr[*][*]' AS UNSIGNED ARRAY)
   ```

   In this case, all values that match the JSON expression are stored as a single flattened array in the index.

* A multi-valued index cannot be a covering index.
* Only JSON expressions are allowed in the multi-valued key part. These expressions do not necessarily need to reference existing elements in a JSON document inserted into the indexed column, but they must be syntactically valid.
* Because the index records of the same clustered index record are scattered in a multi-valued index, range scans and scans of only index records are not supported in multi-valued indexes.
* Multi-valued indexes cannot be specified for foreign keys.
* Index prefixes cannot be defined for multi-valued indexes.
* Multi-valued indexes cannot be defined for binary data.
* For more information about multi-valued indexes in offline DDL operations, see [Offline DDL operations](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/700.ddl-function-of-mysql-mode/150.online-and-offline-ddl-list-of-mysql-mode.md).

### Create a multi-valued index by using the CREATE TABLE statement

**The following example shows the simplified syntax of the `CREATE TABLE` statement for creating a multi-valued index:**

Create a multi-valued index:

```sql
CREATE TABLE table_name(column_name column_definition, [column_name column_definition, ...],
    json_column_name JSON, 
    [UNIQUE] INDEX idx_json_name((CAST(json_column_name->'$.json_field_name' AS UNSIGNED ARRAY)))
);
```

Create a composite multi-valued index:

```sql
CREATE TABLE table_name(column_name column_definition, [column_name column_definition, ...],
    json_column_name JSON,
    INDEX idx_json_name(column_name, [column_name, ...] (CAST(json_column_name->'$.json_field_name' AS CHAR(n) ARRAY)))
);                   
```

The following table describes the related parameters.

* `table_name`: the name of the table to be created.

* `column_name`: the name of a column of data types other than `JSON`.

* `column_definition`: the data types of the columns in the table.

* `json_column_name`: the name of a column of the `JSON` data type.

* `UNIQUE`: optional. Specifies to create a unique multi-valued index. In a unique multi-valued index, index keys cannot be repeated.

   <main id="notice" type='notice'>
     <h4>Notice</h4>
     <p>Multi-valued indexes can be defined as unique indexes. If a multi-valued index is defined as a unique index, an error is returned when you try to insert a value that already exists in the multi-valued index. If duplicate values exist, the creation of a unique multi-valued index fails. </p>
   </main>

* `idx_json_name`: the name of the multi-valued index to be created.

* `json_field_name`: the name of the field on which you want to create an index in the JSON column.

For more information about the syntax of the `CREATE TABLE` statement, see [CREATE TABLE](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2600.create-table-of-mysql-mode.md).

**Here is an example of creating a multi-valued index:**

1. Create a table named `json_tbl1` and create a multi-valued index named `idx1_json_tbl1` at the same time.

   ```sql
   CREATE TABLE json_tbl1(col1 INT, col2 VARCHAR(18), col3 JSON,
      INDEX idx1_json_tbl1((CAST(col3->'$.ipcode' AS UNSIGNED ARRAY)))
   );
   ```

2. Execute the following statement to insert test data into the `json_tbl1` table.

   ```sql
   INSERT INTO json_tbl1 VALUES(1, 'a1', '{"user":"Jk001","user_id":37,"ipcode":[94582,94536]}'),
      (2, 'a2', '{"user":"Jk002","user_id":22,"ipcode":[94568,94507,94582]}'),
      (3, 'a3', '{"user":"Jk003","user_id":31,"ipcode":[94477,94507]}'),
      (4, 'a4', '{"user":"Jk004","user_id":72,"ipcode":[94536]}'),
      (5, 'a5', '{"user":"Jk005","user_id":56,"ipcode":[94507,94582]}');
   ```

**Here is an example of creating a composite multi-valued index:**

Create a table named `json_tbl2` and create a composite multi-valued index named `idx1_json_tbl2` at the same time.

```sql
CREATE TABLE json_tbl2(col1 INT, col2 VARCHAR(18), col3 JSON,
      INDEX idx1_json_tbl2(col1, (CAST(col3->'$.ipcode' AS UNSIGNED ARRAY)))
);
```

### Support for complex DML operations

For a primary table that has a multi-valued index, complex DML operations are supported. Example:

* `INSERT INTO ON DUPLICATE KEY`

   ```sql
   CREATE TABLE customers(id INT PRIMARY KEY, uid INT, j JSON);

   INSERT INTO customers VALUES (10, 21, '{"user":"Jack","user_id":37,"zipcode":[94582,94536]}');

   CREATE INDEX zips ON customers((CAST(j->'$.zipcode' AS UNSIGNED ARRAY)));

   INSERT INTO customers 
  VALUES (10, 22, '{"user":"Jack","user_id":37,"zipcode":[24582,34536]}') 
  ON DUPLICATE KEY 
  UPDATE j = '{"user":"Jack","user_id":37,"zipcode":[34582,44536]}';
   ```

* `REPLACE INTO`

   ```sql
   CREATE TABLE test_array(id int,a varchar(50),j json,INDEX index_1( (CAST(j->'$.key' AS UNSIGNED ARRAY))) );

   INSERT INTO test_array VALUES(1,'test','{"key":[1,2,3,4]}');

   REPLACE INTO test_array VALUES(1,'test','{"key":[8,9,13,43]}');
   ```

* `UPDATE` and `DELETE` operations involving multiple tables

   To perform these operations, prepare the example tables first.

   ```sql
   CREATE TABLE table_1(a int PRIMARY KEY, b json, INDEX index_1( (CAST(b->'$.key' AS UNSIGNED ARRAY))) );
   CREATE TABLE table_2(a int PRIMARY KEY, b json);

   INSERT INTO table_1 values(1, '{"key":[1,2,3,4]}');
   INSERT INTO table_2 values(1, '{"key":[1,2,3,4]}');
   ```

   Here is an example of the `UPDATE` statement:

   ```sql
   UPDATE table_1 JOIN table_2 ON table_1.a = table_2.a 
   SET table_1.b = '{"key":[11,12,13,14]}', table_2.b = '{"key":[21,22,23,24]}';

   UPDATE  table_1 JOIN table_2 ON table_1.a = table_2.a SET table_1.b = '{"key":[31,32,33,34]}';
   UPDATE table_1 JOIN table_2 ON table_1.a = table_2.a SET table_2.b = table_1.b;
   ```

   Here is an example of the `DELETE` statement:

   ```sql
   DELETE table_1, table_2 FROM table_1 JOIN table_2 ON table_1.a = table_2.a;
   DELETE table_1 FROM table_1 JOIN table_2 ON table_1.a = table_2.a;
   DELETE table_1 FROM table_1 JOIN table_2 ON table_1.a = table_2.a;
   ```

* Updatable views

   ```sql
   CREATE TABLE test(id int,a varchar(50),j json,INDEX index_1( (CAST(j->'$.key' AS UNSIGNED ARRAY))) );
   
   INSERT INTO test values(1,'test','{"key":[1,2,3,4]}');
   
   CREATE VIEW vtest AS SELECT * FROM test;

   UPDATE vtest SET j='{"key":[1,2]}';
   ```

### Creation of multi-valued indexes on existing tables

To create a multi-valued index on an existing table, you must enable the [_enable_add_fulltext_index_to_existing_table](../../../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/5980._enable_add_fulltext_index_to_existing_table.md) parameter.

```sql
ALTER SYSTEM SET _enable_add_fulltext_index_to_existing_table = true;
```

Multi-valued indexes can be created in two ways:

| Category | Description |
| --- | --- |
| Multi-valued index | Creates a non-unique multi-valued index by using the `ADD INDEX/ALTER TABLE` statement. |
| Composite multi-valued index | Creates a non-unique composite multi-valued index by using the `ADD INDEX/ALTER TABLE` statement. A composite multi-valued index allows only one column to be a multi-valued index and the other columns to be regular columns. |
| Unique multi-valued index | Creates a unique multi-valued index by using the `ADD INDEX/ALTER TABLE` statement. |
| Unique composite multi-valued index | Creates a unique composite multi-valued index by using the `ADD INDEX/ALTER TABLE` statement. A composite multi-valued index allows only one column to be a multi-valued index and the other columns to be regular columns. |

Here are some examples:

1. Create a table named `json_tbl1` and create a non-unique multi-valued index named `idx1_json_tbl1` on this table.

   ```sql
   CREATE TABLE json_tbl1(id INT PRIMARY KEY, uid INT, j JSON);

   INSERT INTO json_tbl1 VALUES 
   (10, 21, '{"user":"Jack","user_id":37,"zipcode":[94582,94536]}'),
   (11, 22, '{"user":"Jill","user_id":22,"zipcode":[94568,94507,94582]}'),
   (12, 23, '{"user":"Bob","user_id":31,"zipcode":[94477,94507]}'),
   (13, 24, '{"user":"Mary","user_id":72,"zipcode":[94536]}'),
   (14, 25, '{"user":"Ted","user_id":56,"zipcode":[94507,94582]}');

   CREATE INDEX idx1_json_tbl1 ON json_tbl1((CAST(j->'$.zipcode' AS UNSIGNED ARRAY)));
   ```

2. Create a unique multi-valued index named `idx1_json_tbl2`.

   ```sql
   CREATE TABLE json_tbl2(id INT PRIMARY KEY, uid INT, j JSON);

   INSERT INTO json_tbl2 VALUES 
   (10, 21, '{"user":"Jack","user_id":37,"zipcode":[94507,94536]}'),
   (11, 22, '{"user":"Jill","user_id":22,"zipcode":[94568,94582]}'),
   (12, 23, '{"user":"Bob","user_id":31,"zipcode":[94477]}');

   CREATE UNIQUE INDEX idx1_json_tbl2 ON json_tbl2((CAST(j->'$.zipcode' AS UNSIGNED ARRAY)));
   ```

3. Create a composite multi-valued index named `idx1_json_tbl3`.

   ```sql
   CREATE TABLE json_tbl3 (
    id BIGINT NOT NULL PRIMARY KEY,
    c1 BIGINT NOT NULL,
    modified  BIGINT NOT NULL,
    custinfo JSON
   );

   INSERT INTO json_tbl3 VALUES 
   (10, 21, 101, '{"user":"Jack","user_id":37,"zipcode":[94582,94536]}'),
   (11, 22, 102, '{"user":"Jill","user_id":22,"zipcode":[94568,94507,94582]}'),
   (12, 23, 103, '{"user":"Bob","user_id":31,"zipcode":[94477,94507]}'),
   (13, 24, 104, '{"user":"Mary","user_id":72,"zipcode":[94536]}'),
   (14, 25, 105, '{"user":"Ted","user_id":56,"zipcode":[94507,94582]}');

   CREATE INDEX idx1_json_tbl3 ON json_tbl3 (c1, modified,
        (CAST(custinfo->'$.zipcode' AS UNSIGNED ARRAY)) );
   ```

4. Create a unique composite multi-valued index named `idx1_json_tbl4`.

   ```sql
   CREATE TABLE json_tbl4 (
    id BIGINT NOT NULL PRIMARY KEY,
    c1 BIGINT NOT NULL,
    modified  BIGINT NOT NULL,
    custinfo JSON
   );

   INSERT INTO json_tbl4 VALUES 
   (10, 21, 101, '{"user":"Jack","user_id":37,"zipcode":[94582,94536]}'),
   (11, 22, 102, '{"user":"Jill","user_id":22,"zipcode":[94568,94507,94582]}'),
   (12, 23, 103, '{"user":"Bob","user_id":31,"zipcode":[94477,94507]}'),
   (13, 24, 104, '{"user":"Mary","user_id":72,"zipcode":[94536]}'),
   (14, 25, 105, '{"user":"Ted","user_id":56,"zipcode":[94507,94582]}');

   CREATE UNIQUE INDEX idx1_json_tbl4 ON json_tbl4 (c1, modified,
        (CAST(custinfo->'$.zipcode' AS UNSIGNED ARRAY)) );
   ```

## Create a full-text index

You can execute the `CREATE TABLE`, `CREATE FULLTEXT INDEX`, or `ALTER TABLE` statement to create a full-text index in MySQL mode of OceanBase Database of the current version.

For more information about full-text indexes, see [Full-text indexes](../../../100.oceanbase-database-concepts/400.database-objects/200.database-objects-of-mysql-mode/300.index-of-oracle-mode/320.full-text-indexes-of-mysql-mode-in-concepts.md).

For information about how to use a full-text index to query data, see [Full-text queries](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/500.queries-and-subqueries-of-mysql-mode/400.full-text-query-of-mysql-mode.md).

### Limitations and considerations for full-text indexes

You can create a full-text index on a non-partitioned table or a partitioned table with or without a primary key. However, there are some limitations on full-text indexes:

* Full-text indexes apply only to `CHAR`, `VARCHAR`, and `TEXT` columns.
* Only local full-text indexes are supported.
* You cannot specify the `UNIQUE` keyword when you create a full-text index.
* If you want to create a full-text index on multiple columns, make sure that these columns use the same character set.
* For more information about DDL operations on full-text indexes, see [Offline DDL](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/700.ddl-function-of-mysql-mode/150.online-and-offline-ddl-list-of-mysql-mode.md).

### Create a full-text index by using the CREATE TABLE statement

You can create a full-text index for a table when you create the table by using the `CREATE TABLE` statement. The simplified syntax is as follows:

```sql
CREATE TABLE table_name(column_name column_definition,[column_name column_definition,...]
    FULLTEXT [INDEX | KEY] [index_name](column_name)
    [WITH PARSER tokenizer_option]
    [PARSER_PROPERTIES[=](parser_properties_list)]
    [LOCAL]);

tokenizer_option:
    SPACE
    | NGRAM
    | BENG
    | IK

parser_properties_list:
    parser_properties, [parser_properties]

parser_properties:
    min_token_size = int_value
    | max_token_size = int_value
    | ngram_token_size = int_value
    | ik_mode = 'char_value'
```

For more information about the `CREATE TABLE` statement, see [CREATE TABLE](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2600.create-table-of-mysql-mode.md).

**The following table describes the related parameters.**

* `table_name`: the name of the table to be created.

* `column_name`: the column of the table.

* `column_definition`: the data type of each column in the table.

* `FULLTEXT`: the keyword that indicates to create a full-text index.

   <main id="notice" type='notice'>
     <h4>Notice</h4>
     <p>Only local full-text indexes can be created in the current version. </p>
   </main>

* `INDEX | KEY`: the keyword that indicates to use `INDEX` or `KEY`. Both keywords are supported.

* `index_name`: the name of the index to be created. This parameter is optional. If you do not specify this parameter, the default index name is the same as the name of the column on which the index is created.

* `WITH PARSER tokenizer_option`: specifies the tokenizer for the full-text index. The following tokenizers are supported:

  * `SPACE`: the default tokenizer that splits words based on spaces. You can set the following parameters for the tokenizer:

      |        Parameter      | Value range |
      |------------------|---------|
      | min_token_size   | [1, 16] |
      | max_token_size   | [10, 84]|

  * `NGRAM`: a tokenizer that splits words based on N-grams. You can set the following parameter for the tokenizer:

      |        Parameter      | Value range |
      |------------------|---------|
      | ngram_token_size | [1, 10] |

  * `BENG`: a tokenizer that splits words based on basic English. You can set the following parameters for the tokenizer:

      |        Parameter      | Value range |
      |------------------|---------|
      | min_token_size   | [1, 16] |
      | max_token_size   | [10, 84]|

  * `IK`: a tokenizer that splits words based on the IK analyzer. The `utf-8` character set is supported for the tokenizer. You can set the following parameter for the tokenizer:

      |        Parameter      | Value range |
      |------------------|---------|
      | ik_mode          | <ul><li>`smart`</li><li>`max_word`</li></ul>|

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>In OceanBase Database V4.3.5, the support for the <code>IK</code> tokenizer is added in V4.3.5 BP1. </p>
    </main>

   You can use the [TOKENIZE](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/400.functions-of-mysql-mode/960.text-processing-functions-of-mysql-mode/200.tokenize-of-mysql-mode.md) function to view the tokenization result of a text based on the specified tokenizer and in the JSON format of parameters.

* `PARSER_PROPERTIES[=](parser_properties_list)`: specifies the properties of the tokenizer. The following tokenizers are supported:

  * `min_token_size`: the minimum word length. The default value is 3, and the value range is 1 to 16.
  * `max_token_size`: the maximum word length. The default value is 84, and the value range is 10 to 84.
  * `ngram_token_size`: the word length of the `NGRAM` tokenizer. Only the `NGRAM` tokenizer is valid. The default value is 2, and the value range is 1 to 10.
  * `ik_mode`: the tokenization mode of the `IK` tokenizer. The following tokenization modes are supported:

    * `smart`: the default mode. In this mode, dictionary-based words are used to improve tokenization accuracy. Dictionary-based word boundaries are prioritized, which may reduce unnecessary expansion.
    * `max_word`: words defined in the dictionary are identified, but this does not affect the maximized expansion of tokens. In `max_word` mode, the text is still divided into more words even if they are defined in the dictionary.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>In OceanBase Database V4.3.5, the support for specifying tokenizer properties (<code>PARSER_PROPERTIES</code>) is added in V4.3.5 BP1. </p>
  </main>

* `LOCAL`: creates a local index. This parameter is optional.

**Here are some examples:**

* Create a table named `tbl1` and a full-text index named `full_idx1_tbl1` at the same time.

   ```sql
   CREATE TABLE tbl1(id INT, name VARCHAR(18), date DATE, PRIMARY KEY (id), FULLTEXT INDEX full_idx1_tbl1(name));
   ```

* Create a table named `tbl2` and a full-text index named `full_idx1_tbl2` at the same time. Specify the `NGRAM` tokenizer for the full-text index and set the tokenizer properties by using `PARSER_PROPERTIES`.

   ```sql
   CREATE TABLE tbl2(id INT, name VARCHAR(18), doc TEXT, 
       FULLTEXT INDEX full_idx1_tbl2(name, doc)
         WITH PARSER NGRAM
         PARSER_PROPERTIES=(ngram_token_size=3));
   ```

### Create a full-text index by using the CREATE FULLTEXT INDEX statement

You can execute the `CREATE FULLTEXT INDEX` statement to create a full-text index for an existing table. The syntax is as follows:

```sql
CREATE FULLTEXT INDEX index_name ON table_name (column_name, [column_name ...])
    [WITH PARSER tokenizer_option]
    [PARSER_PROPERTIES[=](parser_properties_list)]
    [LOCAL];

tokenizer_option:
    SPACE
    | NGRAM
    | BENG
    | IK

parser_properties_list:
    parser_properties, [parser_properties]

parser_properties:
    min_token_size = int_value
    | max_token_size = int_value
    | ngram_token_size = int_value
    | ik_mode = 'char_value'
```

For more information about the `CREATE INDEX` statement, see [CREATE INDEX](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2200.create-index-of-mysql-mode.md).

**The following table describes the related parameters.**

* `index_name`: the name of the index to be added.
* `table_name`: the name of the table on which the index is to be created.
* `column_name`: the names of the columns on which the index is to be created. Separate the column names with commas (,) if you are creating the index on multiple columns.
* `WITH PARSER tokenizer_option`: the tokenizer option. This option is optional. It specifies the tokenizer of the full-text index. Valid values:

  * `SPACE`: the default value, which specifies to tokenize the text based on spaces. You can set the following parameters for this tokenizer:

      |        Parameter      | Value range |
      |------------------|---------|
      | min_token_size   | [1, 16] |
      | max_token_size   | [10, 84]|

  * `NGRAM`: the tokenizer that tokenizes the text based on N-Gram (Chinese). You can set the following parameter for this tokenizer:

      |        Parameter      | Value range |
      |------------------|---------|
      | ngram_token_size | [1, 10] |

  * `BENG`: the tokenizer that tokenizes the text based on the basic English language. You can set the following parameters for this tokenizer:

      |        Parameter      | Value range |
      |------------------|---------|
      | min_token_size   | [1, 16] |
      | max_token_size   | [10, 84]|

  * `IK`: the tokenizer that tokenizes the text based on IK (Chinese). The `utf-8` character set is supported. You can set the following parameters for this tokenizer:

      |        Parameter      | Value range |
      |------------------|---------|
      | ik_mode          | <ul><li>`smart`</li><li>`max_word`</li></ul>|

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>In OceanBase Database V4.3.5, the support for the <code>IK</code> tokenizer is added in V4.3.5 BP1. </p>
    </main>

   You can use the [TOKENIZE](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/400.functions-of-mysql-mode/960.text-processing-functions-of-mysql-mode/200.tokenize-of-mysql-mode.md) function to view the tokenization result of a text based on the specified tokenizer and JSON parameters.

* `PARSER_PROPERTIES[=](parser_properties_list)`: the properties of the tokenizer. This option is optional. Valid values:

  * `min_token_size`: the minimum token size. The default value is 3, and the value range is 1 to 16.
  * `max_token_size`: the maximum token size. The default value is 84, and the value range is 10 to 84.
  * `ngram_token_size`: the token size of the `NGRAM` tokenizer. Only the `NGRAM` tokenizer is valid. The default value is 2, and the value range is 1 to 10.
  * `ik_mode`: the tokenization mode of the `IK` tokenizer. Valid values:

    * `smart`: the default value, which specifies to use dictionary words to improve tokenization accuracy, prioritize dictionary word boundaries, and reduce unnecessary expansion.
    * `max_word`: which specifies to identify dictionary words but does not affect maximized expansion. In `max_word` mode, the text is still attempted to be divided into more words even if dictionary words are defined.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>In OceanBase Database V4.3.5, the support for specifying tokenizer properties (<code>PARSER_PROPERTIES</code>) is added in V4.3.5 BP1. </p>
  </main>

* `LOCAL`: specifies to create a local index. This option is optional.

**Here is an example:**

After you create the `tbl3` table, create the full-text index `ft_idx1_tbl3`.

1. Create the `tbl3` table.

   ```sql
   CREATE TABLE tbl3(col1 INT, col2 VARCHAR(4096));
   ```

2. Create the full-text index `ft_idx1_tbl3` on the `tbl3` table, and specify the `IK` tokenizer for the full-text index. At the same time, set the tokenizer properties by using the `PARSER_PROPERTIES` clause.

   ```sql
   CREATE FULLTEXT INDEX ft_idx1_tbl3 ON tbl3(col2)
       WITH PARSER IK
       PARSER_PROPERTIES=(ik_mode='max_word');
   ```

### Create a full-text index by using the ALTER TABLE statement

You can execute the `ALTER TABLE` statement to add a full-text index to an existing table. The syntax is as follows:

```sql
ALTER TABLE table_name ADD FULLTEXT [INDEX | KEY] [index_name](column_name, [column_name ...])
    [WITH PARSER tokenizer_option]
    [PARSER_PROPERTIES[=](parser_properties_list)]
    [LOCAL];

tokenizer_option:
    SPACE
    | NGRAM
    | BENG
    | IK

parser_properties_list:
    parser_properties, [parser_properties]

parser_properties:
    min_token_size = int_value
    | max_token_size = int_value
    | ngram_token_size = int_value
    | ik_mode = 'char_value'
```

For more information about the `CREATE INDEX` statement, see [ALTER TABLE](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/1600.alter-table-of-mysql-mode.md).

**The following parameters are described:**

* `table_name`: the name of the table on which you want to create an index.
* `INDEX | KEY`: an optional parameter. If you specify `INDEX` or `KEY` in the statement, the keyword INDEX can be omitted. The default value is `KEY`.
* `index_name`: an optional parameter. The name of the index to be created. If you do not specify this parameter, the default index name is the same as the name of the specified column.
* `column_name`: the name of the column on which you want to create an index. Separate the names of multiple columns with commas (,).
* `WITH PARSER tokenizer_option`: an optional parameter. It specifies the tokenizer of the full-text index. The valid values are described as follows:

  * `SPACE`: the default value, which specifies to tokenize the text based on spaces. You can set the following parameters for the tokenizer:

      |        Parameter      | Value Range |
      |------------------|---------|
      | min_token_size   | [1, 16] |
      | max_token_size   | [10, 84]|

  * `NGRAM`: specifies to tokenize the text based on N-Gram (Chinese). You can set the following parameters for the tokenizer:

      |        Parameter      | Value Range |
      |------------------|---------|
      | ngram_token_size | [1, 10] |

  * `BENG`: specifies to tokenize the text based on the Beng (Basic English) language model. You can set the following parameters for the tokenizer:

      |        Parameter      | Value Range |
      |------------------|---------|
      | min_token_size   | [1, 16] |
      | max_token_size   | [10, 84]|

  * `IK`: specifies to tokenize the text based on the IK (Chinese) language model. The current supported character set is only `utf-8`. You can set the following parameters for the tokenizer:

      |        Parameter      | Value Range |
      |------------------|---------|
      | ik_mode          | <ul><li>`smart`</li><li>`max_word`</li></ul>|

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>In OceanBase Database V4.3.5 and later, the <code>IK</code> tokenizer is supported in BP1 and later. </p>
    </main>

   You can use the [TOKENIZE](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/400.functions-of-mysql-mode/960.text-processing-functions-of-mysql-mode/200.tokenize-of-mysql-mode.md) function to tokenize a text based on the specified tokenizer and JSON-style parameters.

* `PARSER_PROPERTIES[=](parser_properties_list)`: an optional parameter. It specifies the tokenizer properties. The valid values are described as follows:

  * `min_token_size`: the minimum token size. The default value is 3, and the value range is 1 to 16.
  * `max_token_size`: the maximum token size. The default value is 84, and the value range is 10 to 84.
  * `ngram_token_size`: the token size of the `NGRAM` tokenizer. Only the `NGRAM` tokenizer is valid. The default value is 2, and the value range is 1 to 10.
  * `ik_mode`: the tokenization mode of the `IK` tokenizer. The valid values are described as follows:

    * `smart`: the default value, which indicates that the dictionary-based words are used to improve tokenization accuracy. The boundaries of dictionary-based words are prioritized, which may reduce unnecessary expansion.
    * `max_word`: indicates that the words defined in the dictionary are identified, but it does not affect the maximized expansion of tokens. Even if the words are defined in the dictionary, the `max_word` mode still tries to split the text into more words.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>In OceanBase Database V4.3.5 and later, BP1 and later, the <code>PARSER_PROPERTIES</code> parameter is supported. </p>
  </main>

* `LOCAL`: an optional parameter. If you specify this parameter, a local index is created.

**Here is an example:**

Create a table named `tbl4` and add a full-text index named `ft_idx1_tbl4` to the table.

1. Create a table named `tbl4`.

   ```sql
   CREATE TABLE tbl4(col1 INT, col2 TEXT);
   ```

2. Add a full-text index named `ft_idx1_tbl4` to the `tbl4` table. Specify the tokenizer of the full-text index as `BENG` and set the tokenizer properties by using `PARSER_PROPERTIES`.

   ```sql
   ALTER TABLE tbl4 ADD FULLTEXT INDEX ft_idx1_tbl4(col2)
       WITH PARSER BENG
       PARSER_PROPERTIES=(min_token_size=2, max_token_size=64);
   ```
