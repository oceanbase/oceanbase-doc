# Create an index

This topic describes how to create an index.

## Background information

OceanBase Database allows you to create indexes on non-partitioned and partitioned tables. An index can be a local or global index, a unique or non-unique index, a spatial index, or a function-based index. If the table is partitioned, the unique index must be a local index that includes the partitioning key of the table partitions. For more information about indexes, see [Indexes](../../../100.oceanbase-database-concepts/400.database-objects/200.database-objects-of-mysql-mode/300.index-of-mysql-mode/100.index-overview-of-mysql-mode.md).

This topic describes how to create an index on a non-partitioned table. For information about how to create an index on a partitioned table, see [Create an index on a partitioned table](../300.manage-partitions-of-mysql-mode/900.create-partition-table-index-of-mysql-mode/200.local-index-of-mysql-mode.md).

## Considerations

When you create an index in OceanBase Database, the index name must be unique in the database.

## Create a normal index

You can use the `CREATE TABLE`, `CREATE INDEX`, or `ALTER TABLE` statement to create a normal index.

### Use the `CREATE TABLE` statement to create a normal index

You can create an index when you create a table by using the `CREATE TABLE` statement.

Syntax:

```sql
CREATE TABLE table_name(column_name column_definition,[column_name column_definition,...] [UNIQUE] INDEX|KEY [index_name](column_name));
```

The following table describes the parameters of the syntax.

* `table_name`: specifies the name of the table to be created.

* `column_name`: specifies the columns of the table.

* `column_definition`: specifies the data types of the columns of the table.

* `UNIQUE`: optional. This keyword indicates a unique index. You must specify this keyword when you create a unique index.

* `INDEX|KEY`: specifies the index keyword. You can use `INDEX` or `KEY`.

* `index_name`: optional. Specifies the name of the index to be created. If you do not specify this parameter, the index name is the same as the column name.

The following example creates a table named `tbl1` and an index named `tbl1_idx1`:

```sql
CREATE TABLE tbl1(id INT,name VARCHAR(18),date DATE,PRIMARY KEY (id),INDEX tbl1_idx1 (date));
```

### Use the `CREATE INDEX` statement to create a normal index

You can create an index for an existing table by using the `CREATE INDEX` statement.

Syntax:

```sql
CREATE [UNIQUE] INDEX index_name ON table_name (column_name);
```

The following table describes the parameters of the syntax.

* `UNIQUE`: optional. This keyword indicates a unique index. You must specify this keyword when you create a unique index.

* `index_name`: specifies the name of the index to be created.

* `table_name`: specifies the name of the table to be created.

* `column_name`: specifies the columns to be indexed. Separate multiple columns with commas (,).

The following example creates a table named `tbl2` and an index named `tbl2_idx1`:

1. Create a table named `tbl2`.

   ```sql
   CREATE TABLE tbl2(id INT,name VARCHAR(20));
   ```

2. Create an index named `tbl2_idx1` for the `tbl2` table.

   ```sql
   CREATE INDEX tbl2_idx1 ON tbl2(id);
   ```

### Use the `ALTER TABLE` statement to create a normal index

You can create an index for an existing table by using the `ALTER TABLE` statement. This statement allows you to create multiple indexes at a time.

Syntax:

```sql
ALTER TABLE table_name ADD [UNIQUE] INDEX|KEY [index_name](column_name);
```

The following table describes the parameters of the syntax.

* `table_name`: specifies the name of the table to be created.

* `UNIQUE`: optional. This keyword indicates a unique index. You must specify this keyword when you create a unique index.

* `INDEX|KEY`: specifies the index keyword. You can use `INDEX` or `KEY`.

* `index_name`: optional. Specifies the name of the index to be created. If you do not specify this parameter, the index name is the same as the column name.

* `column_name`: specifies the columns to be indexed. Separate multiple columns with commas (,).

The following example creates a table named `tbl3` and an index named `tbl3_idx1`:

1. Create a table named `tbl3`.

   ```sql
   CREATE TABLE tbl3(id INT,name VARCHAR(20));
   ```

2. Create an index named `tbl3_idx1` for the `tbl3` table.

   ```sql
   ALTER TABLE tbl3 ADD INDEX tbl3_idx1(id);
   ```

## Create a spatial index

OceanBase Database in MySQL mode allows you to create spatial indexes. A spatial index describes the location information of data stored on media and improves the efficiency of data retrieval.

The syntax for creating a spatial index is similar to that for creating a normal index. You can use the `CREATE TABLE`, `CREATE INDEX`, or `ALTER TABLE` statement to create an index. The difference is that you must use the `SPATIAL` keyword to create a spatial index, and the column in the spatial index must be of the `NOT NULL` type.

### Limitations on spatial indexes

Before you create a spatial index, you must understand the following limitations:

* Only local spatial indexes are supported. Global spatial indexes are not supported.

* The column for which you create a spatial index must be defined with the `SRID` attribute. Otherwise, when you add a spatial index to the column, the spatial index cannot be used in subsequent queries. This is because, after a spatial index is created, the `SRID` value in the column definition is used to determine the coordinate system when the spatial index is used for comparisons. Spatial indexes are built based on the minimum bounding rectangles (MBRs) of the geometries, and the comparison methods for MBRs also depend on the `SRID` values.

  For more information about `SRID`, see [Spatial reference systems (SRSs)](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/100.basic-elements-of-mysql-mode/100.data-type-of-mysql-mode/900.spatial-data-type-of-mysql-mode/200.spacial-reference-system-of-mysql-mode.md).

* You can create spatial indexes on only columns of spatial data types. The spatial data types supported by OceanBase Database are described in [Spatial data types overview](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/100.basic-elements-of-mysql-mode/100.data-type-of-mysql-mode/900.spatial-data-type-of-mysql-mode/100.spatial-data-type-overview-of-mysql-mode.md).

* The column for which you create a spatial index must have the `NOT NULL` attribute.

  If the column does not have the `NOT NULL` attribute, you can first modify the attribute to `NOT NULL` by using the `ALTER TABLE` statement, and then add the spatial index. For more information about how to change the column attribute, see [Define the constraint type of a column](../200.manage-tables-of-mysql-mode/400.define-the-constraint-type-for-a-column-of-mysql-mode.md).

### Create a spatial index by using the `CREATE TABLE` statement

The syntax is as follows:

```sql
CREATE TABLE table_name(column_g_name GEOMETRY NOT NULL SRID 4326,[column_name column_definition,...] SPATIAL INDEX|KEY [index_name](column_g_name));
```

The parameters are described as follows:

* `table_name`: the name of the table to be created.

* `column_g_name` and `column_name`: the names of the table columns.

* `SRID 4326`: specifies the `SRID` of the spatial column.

* `column_definition`: the data type of each column. The column type must be a spatial data type if you want to add a spatial index to this column. The spatial data types supported by OceanBase Database are described in [Spatial data types overview](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/100.basic-elements-of-mysql-mode/100.data-type-of-mysql-mode/900.spatial-data-type-of-mysql-mode/100.spatial-data-type-overview-of-mysql-mode.md).

* `INDEX|KEY`: specifies the keyword `INDEX` or `KEY` for the index in this statement.

* `index_name`: the name of the index to be added. The default name is the same as the column name if not specified.

Here is an example that creates a table named `tbl1_g` and adds a spatial index named `tbl1_g_idx1` to it:

```sql
CREATE TABLE tbl1_g (id INT,name VARCHAR(18),g GEOMETRY NOT NULL SRID 4326,SPATIAL INDEX tbl1_g_idx1(g));
```

After you create the index, you can view the index information by executing the `SHOW INDEX` statement.

```sql
SHOW INDEX FROM tbl1_g;
```

The query result is as follows:

```shell

+--------+------------+-------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+
| tbl1_g |          1 | tbl1_g_idx1 |            1 | g           | A         |        NULL | NULL     | NULL   |      | SPATIAL    | available |               | YES     |

The data type of the columns on which a space index is created must be a spatial data type. ## Create a function index

A function index is an index built based on the values of one or more columns in a table. It is an optimization technique that allows you to quickly locate matching function values during queries, avoiding redundant calculations and improving query efficiency.

Assume that you have a `sale` table with a `date_col` column of the `date` data type:

```sql
CREATE TABLE sale(date_col date, sales_col int, name_col varchar(10));
```

To query data for March, you can use the `Month()` function:

```sql
SELECT * FROM sale WHERE month(date_col) = 3;
```

In this case, the database needs to calculate `month(date_col)` for each row in the table and filter out rows where `month(date_col) != 3`. If you frequently use the month information to filter data, you will need to recalculate `month(date_col)` each time, which can result in significant overhead. Therefore, you can create a function index on the `date_col` column to store the `month(date_col)` values in the index table, thereby accelerating queries.

```sql
CREATE INDEX idx1 ON sale((month(date_col)));
```

You can use the `CREATE TABLE`, `CREATE INDEX`, or `ALTER TABLE` statement to create a function index. A function index can also be a unique index or a spatial index.

### Limitations on function indexes

In OceanBase Database's MySQL mode, there are limitations on the expressions that can be used for function indexes. Specifically, certain system functions are not allowed to be used as function index expressions. For more information, see [List of system functions supported for function indexes](../500.manage-indexes-of-mysql-mode/500.function-index-list-of-supported-functions-of-mysql-mode.md) and [List of system functions not supported for function indexes](../500.manage-indexes-of-mysql-mode/600.function-index-list-of-not-supported-functions-of-mysql-mode.md).

### Create a function index using the `CREATE TABLE` statement

You can create a function index when you create a table. The syntax is as follows:

```sql
CREATE TABLE table_name({column_name column_definition,[column_name column_definition,...]} [UNIQUE| SPATIAL] {INDEX|KEY} [index_name](expr));
```

The parameters are described as follows:

* `table_name`: specifies the name of the table to which the index will be added.

* `column_definition`: defines the data types of the columns in the table.

* `[UNIQUE | SPATIAL]`: optional. `UNIQUE` indicates a unique index; `SPATIAL` indicates a spatial index. You need to add the corresponding keyword when creating a unique index or a spatial index.

* `INDEX|KEY`: in this statement, both `INDEX` and `KEY` can be used for the index keyword.

* `index_name`: optional. The name of the function index to be created. If not specified, the system will automatically generate a name in the format `functional_index_xx`, where `xx` is the index number.

* `expr`: a valid function index expression, which can also be a boolean expression, such as `c1=c1`.

Here is an example of creating a function index named `tbl1_func_idx1`:

```sql
CREATE TABLE tbl1_func (c1 int, c2 int, index tbl1_func_idx1 ((c1+1)), UNIQUE KEY ((c1+c2)));
```

After the function index is created, you can view the create table statement using the `SHOW CREATE TABLE` statement. The statement is as follows:

```sql
SHOW CREATE TABLE tbl1_func;
```

The query result is as follows:

```sql
+-----------+-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| Table     | Create Table                                                                                                                                                                                                                                                                                                                                                                                        |
+-----------+-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| tbl1_func | CREATE TABLE `tbl1_func` (
  `c1` int(11) DEFAULT NULL,
  `c2` int(11) DEFAULT NULL,
  UNIQUE KEY `functional_index` ((`c1` + `c2`)) BLOCK_SIZE 16384 LOCAL,
  KEY `tbl1_func_idx1` ((`c1` + 1)) BLOCK_SIZE 16384 LOCAL
) DEFAULT CHARSET = utf8mb4 ROW_FORMAT = DYNAMIC COMPRESSION = 'zstd_1.3.8' REPLICA_NUM = 1 BLOCK_SIZE = 16384 USE_BLOOM_FILTER = FALSE TABLET_SIZE = 134217728 PCTFREE = 0 |
+-----------+-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
1 row in set
```

### Create a function index using the `CREATE INDEX` statement

After the table is created, you can create a function index for the existing table. The syntax is as follows:

```sql
CREATE [UNIQUE | SPATIAL] INDEX index_name ON table_name (expr);
```

The parameters are described as follows:

* `[UNIQUE | SPATIAL]`: optional. `UNIQUE` indicates a unique index; `SPATIAL` indicates a spatial index. You need to add the corresponding keyword when creating a unique index or a spatial index.

* `index_name`: the name of the function index to be created.

* `table_name`: the table to which the index will be added.

* `expr`: a valid function index expression, which can also be a boolean expression, such as `c1=c1`.

Here is an example of creating a function index named `tbl2_func_idx1` with the expression `c1 + c2 < 1`:

1. Create a table named `tbl2_func`.

   ```sql
   CREATE TABLE tbl2_func(c1 int, c2 int);
   ```

2. Create a function index named `tbl2_func_idx1`.

   ```sql
   CREATE INDEX tbl2_func_idx1 on tbl2_func ((c1+c2 < 1));
   ```

3. After the function index is created, you can view the created function index.

   ```sql
   SHOW INDEX FROM tbl2_func;
   ```

   The result is as follows:

   ```shell
   +-----------+------------+----------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+---------------------+
   | Table     | Non_unique | Key_name       | Seq_in_index | Column_name | Collation | Cardinality | Sub_part | Packed | Null | Index_type | Comment   | Index_comment | Visible | Expression          |
   +-----------+------------+----------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+---------------------+
   | tbl2_func |          1 | tbl2_func_idx1 |            1 | SYS_NC18$   | A         |        NULL | NULL     | NULL   | YES  | BTREE      | available |               | YES     | ((`c1` + `c2`) < 1) |
   +-----------+------------+----------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+---------------------+
   1 row in set
   ```

### Create a function index using the `ALTER TABLE` statement

The syntax is as follows:

```sql
ALTER TABLE table_name ADD [UNIQUE | SPATIAL] {INDEX | KEY} [index_name](expr);
```

The parameters are described as follows:

* `table_name`: the table to which the index will be added.

* `[UNIQUE | SPATIAL]`: optional. `UNIQUE` indicates a unique index; `SPATIAL` indicates a spatial index. You need to add the corresponding keyword when creating a unique index or a spatial index.

* `INDEX|KEY`: in this statement, both `INDEX` and `KEY` can be used for the index keyword.

* `index_name`: optional. The name of the function index to be created. If not specified, the system will automatically generate a name in the format `functional_index` followed by a number.

* `expr`: a valid function index expression, which can also be a boolean expression, such as `c1=c1`.

1. Create a table named `tbl3_func`.

   ```sql
   CREATE TABLE tbl3_func(c1 int, c2 int);
   ```

2. Create two function indexes for the table.

   ```sql
   ALTER TABLE tbl3_func ADD INDEX ((c1+1));
   ```

   ```sql
   ALTER TABLE tbl3_func ADD INDEX ((concat(c1,'a')));
   ```

3. View the index information.

   ```sql
   SHOW INDEX FROM tbl3_func;
   ```

   The query result is as follows:

   ```shell

   2 rows in set

## Create a columnstore index

You can use the `CREATE TABLE`, `CREATE INDEX`, or `ALTER TABLE` statement to create a columnstore index.

### Create a columnstore index by using the CREATE TABLE statement

You can use the `CREATE TABLE` statement to create a columnstore index when you create a table.

Syntax:

```sql
CREATE TABLE table_name(column_name column_definition,[column_name column_definition,...] [UNIQUE] INDEX|KEY [index_name](column_name) [STORING(column_name, ...)] WITH COLUMN GROUP([all columns, ]each column));
```

The following table describes the parameters in the syntax.

* `table_name`: specifies the name of the table to be created.

* `column_name`: specifies the column of the table.

* `column_definition`: specifies the data type of each column in the table.

* `UNIQUE`: optional. Specifies a unique index. You must specify this keyword when you create a unique index.

* `INDEX|KEY`: specifies the index keyword. You can use `INDEX` or `KEY` in this statement.

* `index_name`: optional. Specifies the name of the index to be created. If you do not specify this parameter, the default index name is the same as the specified column name.

* `STORING(column_name, ...)` : optional. Specifies the redundant columns in the index table. The specified columns are redundantly stored in the columnstore format, even if they are not indexed.

* `WITH COLUMN GROUP([all columns, ]each column)` : specifies the columnstore attributes of the index.

  * `WITH COLUMN GROUP(all columns, each column)`: specifies that a hybrid index is created, which is a combination of a rowstore index and a columnstore index.
  * `WITH COLUMN GROUP(all columns)`: specifies that a rowstore index is created.
  * `WITH COLUMN GROUP(each column)`: specifies that a columnstore index is created.

**Here are some examples:**

* Create a table named `tbl4` and create a hybrid index named `idx1_tbl4_cg`.

   ```sql
   CREATE TABLE tbl4(id INT, name VARCHAR(18), date DATE, PRIMARY KEY (id), INDEX idx1_tbl4_cg (date) WITH COLUMN GROUP(all columns, each column));
   ```

* Create a table named `tbl5` and create a columnstore index named `idx1_tbl5_cg`. Store the redundant data of the `id` column in the index table.

   ```sql
   CREATE TABLE tbl5(id INT, name VARCHAR(18), date DATE, INDEX idx1_tbl5_cg (date) STORING(id) WITH COLUMN GROUP(each column));
   ```

### Create a columnstore index by using the CREATE INDEX statement

You can use the `CREATE INDEX` statement to create a columnstore index for an existing table.

Syntax:

```sql
CREATE [UNIQUE] INDEX index_name ON table_name (column_name) [STORING(column_name, ...)] WITH COLUMN GROUP([all columns, ]each column);
```

The following table describes the parameters in the syntax.

* `UNIQUE`: optional. Specifies a unique index. You must specify this keyword when you create a unique index.

* `index_name`: specifies the name of the index to be created.

* `table_name`: specifies the name of the table to be indexed.

* `column_name`: specifies the column to be indexed. Separate multiple columns with commas (,).

* `STORING(column_name, ...)` : optional. Specifies the redundant columns in the index table. The specified columns are redundantly stored in the columnstore format, even if they are not indexed.

* `WITH COLUMN GROUP([all columns, ]each column)` : specifies the columnstore attributes of the index.

  * `WITH COLUMN GROUP(all columns, each column)`: specifies that a hybrid index is created, which is a combination of a rowstore index and a columnstore index.
  * `WITH COLUMN GROUP(all columns)`: specifies that a rowstore index is created.
  * `WITH COLUMN GROUP(each column)`: specifies that a columnstore index is created.

**Here are some examples:**

After you create a table named `tbl6`, create a columnstore index named `idx1_tbl6_cg`.

1. Create a table named `tbl6`.

   ```sql
   CREATE TABLE tbl6(id INT, name VARCHAR(20), age INT);
   ```

2. Create a columnstore index named `idx1_tbl6_cg` for the `tbl6` table and store the redundant data of the `age` column in the index table.

   ```sql
   CREATE INDEX idx1_tbl6_cg ON tbl6(id) STORING(age) WITH COLUMN GROUP(each column);
   ```

### Create a columnstore index by using the ALTER TABLE statement

You can use the `ALTER TABLE` statement to create a columnstore index for an existing table.

Syntax:

```sql
ALTER TABLE table_name ADD [UNIQUE] INDEX|KEY [index_name](column_name) [STORING(column_name, ...)] WITH COLUMN GROUP([all columns, ]each column);
```

The following table describes the parameters in the syntax.

* `table_name`: specifies the name of the table to be indexed.

* `UNIQUE`: optional. Specifies a unique index. You must specify this keyword when you create a unique index.

* `INDEX|KEY`: specifies the index keyword. You can use `INDEX` or `KEY` in this statement.

* `index_name`: optional. Specifies the name of the index to be created. If you do not specify this parameter, the default index name is the same as the specified column name.

* `column_name`: specifies the column to be indexed. Separate multiple columns with commas (,).

* `STORING(column_name, ...)` : optional. Specifies the redundant columns in the index table. The specified columns are redundantly stored in the columnstore format, even if they are not indexed.

* `WITH COLUMN GROUP([all columns, ]each column)` : specifies the columnstore attributes of the index.

  * `WITH COLUMN GROUP(all columns, each column)`: specifies that a hybrid index is created, which is a combination of a rowstore index and a columnstore index.
  * `WITH COLUMN GROUP(all columns)`: specifies that a rowstore index is created.
  * `WITH COLUMN GROUP(each column)`: specifies that a columnstore index is created.

**Here are some examples:**

After you create a table named `tbl7`, create a columnstore index named `idx1_tbl7_cg`.

1. Create a table named `tbl7`.

   ```sql
   CREATE TABLE tbl7(id INT, name VARCHAR(20), age INT);
   ```

2. Create a columnstore index named `idx1_tbl7_cg` for the `tbl7` table and store the redundant data of the `age` column in the index table.

   ```sql
   ALTER TABLE tbl7 ADD INDEX idx1_tbl7_cg(id) STORING(age) WITH COLUMN GROUP(each column);
   ```

## Create a multi-value index

OceanBase Database allows you to create a multi-value index when you create a table by using the `CREATE TABLE` statement. You cannot add a multi-value index to a table after the table is created. You can use the `ALTER TABLE` statement to drop an existing index. For a primary table that contains a multi-value index, you can perform complex DML operations.

### Limitations of multi-value indexes

* Each multi-value index can have only one multi-value key part. However, the `CAST(... AS ... ARRAY)` expression can reference multiple arrays in a JSON document, as shown in the following example:

   ```sql
   CAST(data->'$.arr[*][*]' AS UNSIGNED ARRAY)
   ```

   In this case, all matching JSON expressions are stored as a single flat array in the index.

* Multi-value indexes cannot be covering indexes.
* The only type of expression allowed in a multi-value key part is a JSON expression. The expression does not need to reference existing elements in the JSON document inserted into the index column, but must be syntactically valid.
* Since index records for the same clustered index record are scattered in a multi-value index, multi-value indexes do not support range scans or index-only scans.
* Multi-value indexes cannot be used in foreign key specifications.
* Prefixes cannot be defined for multi-value indexes.
* Multi-value indexes cannot be defined on Binary data.
* For information about the support of multi-value indexes for offline DDL, see [Offline DDL](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/700.ddl-function-of-mysql-mode/150.online-and-offline-ddl-list-of-mysql-mode.md).

### Create a multi-value index by using the CREATE TABLE statement

**The simplified syntax for creating a multi-value index by using the `CREATE TABLE` statement is as follows:**

Create a multi-value index:

```sql
CREATE TABLE table_name(column_name column_definition, [column_name column_definition, ...],
    json_column_name JSON, 
    [UNIQUE] INDEX idx_json_name((CAST(json_column_name->'$.json_field_name' AS UNSIGNED ARRAY)))
);
```

Create a composite multi-value index:

```sql
CREATE TABLE table_name(column_name column_definition, [column_name column_definition, ...],
    json_column_name JSON,
    INDEX idx_json_name(column_name, [column_name, ...] (CAST(json_column_name->'$.json_field_name' AS CHAR(n) ARRAY)))
);                   
```

The following table describes the parameters:

* `table_name`: specifies the name of the table to be created.

* `column_name`: specifies the name of the column of a data type other than `JSON`.

* `column_definition`: specifies the data type of each column in the table.

* `json_column_name`: specifies the name of the column of the `JSON` data type.

* `UNIQUE`: optional. Specifies to create a unique multi-value index. A unique multi-value index cannot have duplicate index keys.

   <main id="notice" type='notice'>
     <h4>Notice</h4>
     <p>You can define a multi-value index as a unique index. If you define a multi-value index as a unique index, an error will be returned when you attempt to insert a value that already exists in the multi-value index. If duplicate values already exist, an attempt to add a unique multi-value index will fail.</p>
   </main>

* `idx_json_name`: specifies the name of the multi-value index to be created.

* `json_field_name`: specifies the name of the field in the JSON column to be indexed.

For more information about the syntax of the `CREATE TABLE` statement, see [CREATE TABLE](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2600.create-table-of-mysql-mode.md).

**Here is an example of creating a multi-value index:**

1. Create a table named `json_tbl1` and create a multi-value index named `idx1_json_tbl1` in the table.

   ```sql
   CREATE TABLE json_tbl1(col1 INT, col2 VARCHAR(18), col3 JSON,
      INDEX idx1_json_tbl1((CAST(col3->'$.ipcode' AS UNSIGNED ARRAY)))
   );
   ```

2. Insert test data into the `json_tbl1` table by using the following statement:

   ```sql
   INSERT INTO json_tbl1 VALUES(1, 'a1', '{"user":"Jk001","user_id":37,"ipcode":[94582,94536]}'),
      (2, 'a2', '{"user":"Jk002","user_id":22,"ipcode":[94568,94507,94582]}'),
      (3, 'a3', '{"user":"Jk003","user_id":31,"ipcode":[94477,94507]}'),
      (4, 'a4', '{"user":"Jk004","user_id":72,"ipcode":[94536]}'),
      (5, 'a5', '{"user":"Jk005","user_id":56,"ipcode":[94507,94582]}');
   ```

**Here is an example of creating a composite multi-value index:**

Create a table named `json_tbl2` and create a composite multi-value index named `idx1_json_tbl2` in the table.

```sql
CREATE TABLE json_tbl2(col1 INT, col2 VARCHAR(18), col3 JSON,
      INDEX idx1_json_tbl2(col1, (CAST(col3->'$.ipcode' AS UNSIGNED ARRAY)))
);
```

### Support for complex DML operations

For a primary table that contains a multi-value index, you can perform complex DML operations. Here are some examples:

* `INSERT INTO ON DUPLICATE KEY`

   ```sql
   CREATE TABLE customers(id INT PRIMARY KEY, uid INT, j JSON);

   INSERT INTO customers VALUES (10, 21, '{"user":"Jack","user_id":37,"zipcode":[94582,94536]}');

   CREATE INDEX zips ON customers((CAST(j->'$.zipcode' AS UNSIGNED ARRAY)));

   INSERT INTO customers 
  VALUES (10, 22, '{"user":"Jack","user_id":37,"zipcode":[24582,34536]}') 
  ON DUPLICATE KEY 
  UPDATE j = '{"user":"Jack","user_id":37,"zipcode":[34582,44536]}';
   ```

* `REPLACE INTO`

   ```sql
   CREATE TABLE test_array(id int,a varchar(50),j json,INDEX index_1( (CAST(j->'$.key' AS UNSIGNED ARRAY))) );

   INSERT INTO test_array VALUES(1,'test','{"key":[1,2,3,4]}');

   REPLACE INTO test_array VALUES(1,'test','{"key":[8,9,13,43]}');
   ```

* `UPDATE` and `DELETE` operations on multiple tables

   Prepare the following sample table:

   ```sql
   CREATE TABLE table_1(a int PRIMARY KEY, b json, INDEX index_1( (CAST(b->'$.key' AS UNSIGNED ARRAY))) );
   CREATE TABLE table_2(a int PRIMARY KEY, b json);

   INSERT INTO table_1 values(1, '{"key":[1,2,3,4]}');
   INSERT INTO table_2 values(1, '{"key":[1,2,3,4]}');
   ```

   Here is an example of the `UPDATE` statement:

   ```sql
   UPDATE table_1 JOIN table_2 ON table_1.a = table_2.a 
   SET table_1.b = '{"key":[11,12,13,14]}', table_2.b = '{"key":[21,22,23,24]}';

   UPDATE  table_1 JOIN table_2 ON table_1.a = table_2.a SET table_1.b = '{"key":[31,32,33,34]}';
   UPDATE table_1 JOIN table_2 ON table_1.a = table_2.a SET table_2.b = table_1.b;
   ```

   Here is an example of the `DELETE` statement:

   ```sql
   DELETE table_1, table_2 FROM table_1 JOIN table_2 ON table_1.a = table_2.a;
   DELETE table_1 FROM table_1 JOIN table_2 ON table_1.a = table_2.a;
   DELETE table_1 FROM table_1 JOIN table_2 ON table_1.a = table_2.a;
   ```

* Updates to views

   ```sql
   CREATE TABLE test(id int,a varchar(50),j json,INDEX index_1( (CAST(j->'$.key' AS UNSIGNED ARRAY))) );
   
   INSERT INTO test values(1,'test','{"key":[1,2,3,4]}');
   
   CREATE VIEW vtest AS SELECT * FROM test;

   UPDATE vtest SET j='{"key":[1,2]}';
   ```

### Add a multi-value index to an existing table

To add a multi-value index to an existing table, you must first enable the `_enable_add_fulltext_index_to_existing_table` parameter.

```sql
ALTER SYSTEM SET _enable_add_fulltext_index_to_existing_table = true;
```

The following table describes the types of multi-value indexes that can be added to an existing table:

| Type | Description |
| --- | --- |
| Multi-value index | A multi-value index created by using the `ADD INDEX` or `ALTER TABLE` statement |
| Composite multi-value index | A non-unique composite multi-value index created by using the `ADD INDEX` or `ALTER TABLE` statement. A composite multi-value index allows only one column to be a multi-value index, and the other columns to be regular columns. |
| Unique multi-value index | A unique multi-value index created by using the `ADD INDEX` or `ALTER TABLE` statement |
| Unique composite multi-value index | A unique composite multi-value index created by using the `ADD INDEX` or `ALTER TABLE` statement. A composite multi-value index allows only one column to be a multi-value index, and the other columns to be regular columns. |

Here are some examples:

1. Create a table named `json_tbl1` and create a non-unique multi-value index named `idx1_json_tbl1` in the table.

   ```sql
   CREATE TABLE json_tbl1(id INT PRIMARY KEY, uid INT, j JSON);

   INSERT INTO json_tbl1 VALUES 
   (10, 21, '{"user":"Jack","user_id":37,"zipcode":[94582,94536]}'),
   (11, 22, '{"user":"Jill","user_id":22,"zipcode":[94568,94507,94582]}'),
   (12, 23, '{"user":"Bob","user_id":31,"zipcode":[94477,94507]}'),
   (13, 24, '{"user":"Mary","user_id":72,"zipcode":[94536]}'),
   (14, 25, '{"user":"Ted","user_id":56,"zipcode":[94507,94582]}');

   CREATE INDEX idx1_json_tbl1 ON json_tbl1((CAST(j->'$.zipcode' AS UNSIGNED ARRAY)));
   ```

2. Create a unique multi-value index named `idx1_json_tbl2`.

   ```sql
   CREATE TABLE json_tbl2(id INT PRIMARY KEY, uid INT, j JSON);

   INSERT INTO json_tbl2 VALUES 
   (10, 21, '{"user":"Jack","user_id":37,"zipcode":[94507,94536]}'),
   (11, 22, '{"user":"Jill","user_id":22,"zipcode":[94568,94582]}'),
   (12, 23, '{"user":"Bob","user_id":31,"zipcode":[94477]}');

   CREATE UNIQUE INDEX idx1_json_tbl2 ON json_tbl2((CAST(j->'$.zipcode' AS UNSIGNED ARRAY)));
   ```

3. Create a composite multi-value index named `idx1_json_tbl3`.

   ```sql
   CREATE TABLE json_tbl3 (
    id BIGINT NOT NULL PRIMARY KEY,
    c1 BIGINT NOT NULL,
    modified  BIGINT NOT NULL,

   INSERT INTO json_tbl3 VALUES 
   (10, 21, 101, '{"user":"Jack","user_id":37,"zipcode":[94582,94536]}'),

   (13, 24, 104, '{"user":"Mary","user_id":72,"zipcode":[94536]}'),
   (14, 25, 105, '{"user":"Ted","user_id":56,"zipcode":[94507,94582]}');

   CREATE INDEX idx1_json_tbl3 ON json_tbl3 (c1, modified,
        (CAST(custinfo->'$.zipcode' AS UNSIGNED ARRAY)) );
   ```

4. Create a unique composite multi-value index named `idx1_json_tbl4`.

   ```sql
   CREATE TABLE json_tbl4 (
    id BIGINT NOT NULL PRIMARY KEY,
    c1 BIGINT NOT NULL,
    modified  BIGINT NOT NULL,
    custinfo JSON
   );

   INSERT INTO json_tbl4 VALUES 
   (10, 21, 101, '{"user":"Jack","user_id":37,"zipcode":[94582,94536]}'),
   (11, 22, 102, '{"user":"Jill","user_id":22,"zipcode":[94568,94507,94582]}'),
   (12, 23, 103, '{"user":"Bob","user_id":31,"zipcode":[94477,94507]}'),
   (13, 24, 104, '{"user":"Mary","user_id":72,"zipcode":[94536]}'),
   (14, 25, 105, '{"user":"Ted","user_id":56,"zipcode":[94507,94582]}');

## Create a full-text index

In the current version of OceanBase Database in MySQL mode, you can use the `CREATE TABLE`, `CREATE FULLTEXT INDEX`, or `ALTER TABLE` statement to create a full-text index.

For more information about full-text indexes, see [Full-text indexes](../../../100.oceanbase-database-concepts/400.database-objects/200.database-objects-of-mysql-mode/300.index-of-oracle-mode/320.full-text-indexes-of-mysql-mode-in-concepts.md).

For more information about full-text queries, see [Full-text queries](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/500.queries-and-subqueries-of-mysql-mode/400.full-text-query-of-mysql-mode.md).

### Limitations and considerations

You can create a full-text index on a non-partitioned table or a partitioned table without a primary key. The following limitations apply:

* A full-text index can be created only on a `CHAR`, `VARCHAR`, or `TEXT` column.
* Only local (`LOCAL`) full-text indexes are supported in the current version.
* The `UNIQUE` keyword cannot be specified when you create a full-text index.
* If you create a full-text index on multiple columns, the columns must have the same character set.
* For information about the support of full-text indexes for offline DDL operations, see [Offline DDL](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/700.ddl-function-of-mysql-mode/150.online-and-offline-ddl-list-of-mysql-mode.md).

### Create a full-text index by using the CREATE TABLE statement

You can create a full-text index when you create a table by using the `CREATE TABLE` statement. The simplified syntax is as follows:

```sql
CREATE TABLE table_name(column_name column_definition,[column_name column_definition,...]
    FULLTEXT [INDEX | KEY] [index_name](column_name)
    [WITH PARSER tokenizer_option]
    [PARSER_PROPERTIES[=](parser_properties_list)]
    [LOCAL]);

tokenizer_option:
    SPACE
    | NGRAM
    | BENG
    | IK
    | NGRAM2

parser_properties_list:
    parser_properties, [parser_properties]

parser_properties:
    min_token_size = int_value
    | max_token_size = int_value
    | ngram_token_size = int_value
    | ik_mode = 'char_value'
    | min_ngram_size = int_value
    | max_ngram_size = int_value
```

For more information about the `CREATE TABLE` statement, see [CREATE TABLE](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2600.create-table-of-mysql-mode.md).

**The following table describes the related parameters:**

* `table_name`: specifies the name of the table to be created.

* `column_name`: specifies the column of the table.

* `column_definition`: specifies the data type of each column in the table.

* `FULLTEXT`: specifies to create a full-text index.

   <main id="notice" type='notice'>
     <h4>Notice</h4>
     <p>Only local full-text indexes are supported in the current version.</p>
   </main>

* `INDEX | KEY`: specifies the index keyword. You can use `INDEX` or `KEY`.

* `index_name`: specifies the name of the index to be created. This parameter is optional. If you do not specify this parameter, the index name is the same as the column name.

* `WITH PARSER tokenizer_option`: specifies the tokenizer for the full-text index. Valid values:

  * `SPACE`: the default value. The tokenizer splits the text into tokens by using spaces. You can specify the following attributes:

      |        Attribute      | Value Range |
      |------------------|---------|
      | min_token_size   | [1, 16] |
      | max_token_size   | [10, 84]|

  * `NGRAM`: the N-gram tokenizer for Chinese. You can specify the following attributes:

      |        Attribute      | Value Range |
      |------------------|---------|
      | ngram_token_size | [1, 10] |

  * `NGRAM2`: splits the text into consecutive characters of length from `min_ngram_size` to `max_ngram_size`.

      |        Attribute      | Value Range |
      |------------------|---------|
      | min_ngram_size   | [1, 16] |
      | max_ngram_size   | [1, 16] |

  * `BENG`: the basic English tokenizer. You can specify the following attributes:

      |        Attribute      | Value Range |
      |------------------|---------|
      | min_token_size   | [1, 16] |
      | max_token_size   | [10, 84]|

  * `IK`: the IK tokenizer for Chinese. Only the `utf-8` character set is supported. You can specify the following attribute:

      |        Attribute      | Value Range |
      |------------------|---------|
      | ik_mode          | <ul><li>`smart`</li><li>`max_word`</li></ul>|

   You can use the [TOKENIZE](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/400.functions-of-mysql-mode/960.text-processing-functions-of-mysql-mode/200.tokenize-of-mysql-mode.md) function to view the tokenization result of the text in the specified tokenizer and JSON format.

* `PARSER_PROPERTIES[=](parser_properties_list)`: specifies the attributes of the tokenizer. Valid values:

  * `min_token_size`: specifies the minimum token length. Default value: 3. Value range: 1 to 16.
  * `max_token_size`: specifies the maximum token length. Default value: 84. Value range: 10 to 84.
  * `ngram_token_size`: specifies the token length for the `NGRAM` tokenizer. This attribute is valid only for the `NGRAM` tokenizer. Default value: 2. Value range: 1 to 10.
  * `ik_mode`: specifies the tokenization mode for the `IK` tokenizer. Valid values:

    * `smart`: the default value. The tokenizer uses the words in the dictionary to improve the accuracy of tokenization. The boundaries of the words in the dictionary are prioritized, which may reduce unnecessary extensions.
    * `max_word`: the tokenizer recognizes the words defined in the dictionary but does not affect the maximum extension of tokenization. Even if the dictionary defines words, the `max_word` mode still tries to split the text into more words.

* `LOCAL`: specifies to create a local index. This parameter is optional.

**Here are some examples:**

* Create a table named `tbl1` and a full-text index named `full_idx1_tbl1`.

   ```sql
   CREATE TABLE tbl1(id INT, name VARCHAR(18), date DATE, PRIMARY KEY (id), FULLTEXT INDEX full_idx1_tbl1(name));
   ```

* Create a table named `tbl2` and a full-text index named `full_idx1_tbl2`. Specify the `NGRAM` tokenizer for the full-text index and set the tokenizer attributes by using the `PARSER_PROPERTIES` option.

   ```sql
   CREATE TABLE tbl2(id INT, name VARCHAR(18), doc TEXT, 
       FULLTEXT INDEX full_idx1_tbl2(name, doc)
         WITH PARSER NGRAM
         PARSER_PROPERTIES=(ngram_token_size=3));
   ```

### Use the CREATE FULLTEXT INDEX statement to create a full-text index

You can use the `CREATE FULLTEXT INDEX` statement to create a full-text index for an existing table. The syntax is as follows:

```sql
CREATE FULLTEXT INDEX index_name ON table_name (column_name, [column_name ...])
    [WITH PARSER tokenizer_option]
    [PARSER_PROPERTIES[=](parser_properties_list)]
    [LOCAL];

tokenizer_option:
    SPACE
    | NGRAM
    | BENG
    | IK
    | NGRAM2

parser_properties_list:
    parser_properties, [parser_properties]

parser_properties:
    min_token_size = int_value
    | max_token_size = int_value
    | ngram_token_size = int_value
    | ik_mode = 'char_value'
    | min_ngram_size = int_value
    | max_ngram_size = int_value
```

For more information about the `CREATE INDEX` statement, see [CREATE INDEX](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2200.create-index-of-mysql-mode.md).

**The following table describes the related parameters:**

* `index_name`: specifies the name of the index to be added.
* `table_name`: specifies the name of the table to create the index for.
* `column_name`: specifies the columns to be indexed. When multiple columns are specified, they are separated by commas.
* `WITH PARSER tokenizer_option`: an optional parameter that specifies the tokenizer for the full-text index. Valid values are as follows:

  * `SPACE`: the default value. This option specifies the tokenizer that splits the text by spaces. The following attributes can be specified:

      |        Attribute      | Value Range |
      |------------------|---------|
      | min_token_size   | [1, 16] |
      | max_token_size   | [10, 84]|

  * `NGRAM`: specifies the tokenizer that splits the text based on N-Grams (for Chinese). The following attributes can be specified:

      |        Attribute      | Value Range |
      |------------------|---------|
      | ngram_token_size | [1, 10] |

  * `NGRAM2`: specifies the tokenizer that splits the text into consecutive characters ranging from `min_ngram_size` to `max_ngram_size`. The following attributes can be specified:

      |        Attribute      | Value Range |
      |------------------|---------|
      | min_ngram_size   | [1, 16] |
      | max_ngram_size   | [1, 16] |

  * `BENG`: specifies the tokenizer that splits the text based on Beng (basic English). The following attributes can be specified:

      |        Attribute      | Value Range |
      |------------------|---------|
      | min_token_size   | [1, 16] |
      | max_token_size   | [10, 84]|

  * `IK`: specifies the tokenizer that splits the text based on IK (for Chinese). Only the `utf-8` character set is supported. The following attributes can be specified:

      |        Attribute      | Value Range |
      |------------------|---------|
      | ik_mode          | <ul><li>`smart`</li><li>`max_word`</li></ul>|

   You can use the [TOKENIZE](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/400.functions-of-mysql-mode/960.text-processing-functions-of-mysql-mode/200.tokenize-of-mysql-mode.md) function to view the tokenization result of the text based on the specified tokenizer and JSON-formatted parameters.

* `PARSER_PROPERTIES[=](parser_properties_list)`: an optional parameter that specifies the tokenizer attributes. Valid values are as follows:

  * `min_token_size`: specifies the minimum token length. The default value is 3, and the value range is 1 to 16.
  * `max_token_size`: specifies the maximum token length. The default value is 84, and the value range is 10 to 84.
  * `ngram_token_size`: specifies the token length for the `NGRAM` tokenizer. This parameter is valid only for the `NGRAM` tokenizer. The default value is 2, and the value range is 1 to 10.
  * `ik_mode`: specifies the tokenization mode for the `IK` tokenizer. Valid values are as follows:

    * `smart`: the default value. This option specifies the tokenization mode that uses the dictionary to improve the accuracy of tokenization. The boundaries of the dictionary words are prioritized, which may reduce unnecessary extensions.
    * `max_word`: specifies the tokenization mode that identifies the words defined in the dictionary but does not affect the maximum extension of tokenization. Even if the dictionary defines the words, the `max_word` mode still tries to split the text into more words.

* `LOCAL`: an optional parameter that specifies the creation of a local index.

**Here is an example:**

After you create the `tbl3` table, you can create a full-text index named `ft_idx1_tbl3`.

1. Create the `tbl3` table.

   ```sql
   CREATE TABLE tbl3(col1 INT, col2 VARCHAR(4096));
   ```

2. Create a full-text index named `ft_idx1_tbl3` for the `tbl3` table. Specify the `IK` tokenizer and set the tokenizer attributes using the `PARSER_PROPERTIES` parameter.

   ```sql
   CREATE FULLTEXT INDEX ft_idx1_tbl3 ON tbl3(col2)
       WITH PARSER IK
       PARSER_PROPERTIES=(ik_mode='max_word');
   ```

### Create a full-text index with the ALTER TABLE statement

You can add full-text indexes to existing tables using the `ALTER TABLE` statement. The syntax is as follows:

```sql
ALTER TABLE table_name ADD FULLTEXT [INDEX | KEY] [index_name](column_name, [column_name ...])
    [WITH PARSER tokenizer_option]
    [PARSER_PROPERTIES[=](parser_properties_list)]
    [LOCAL];

tokenizer_option:
    SPACE
    | NGRAM
    | BENG
    | IK
    | NGRAM2

parser_properties_list:
    parser_properties, [parser_properties]

parser_properties:
    min_token_size = int_value
    | max_token_size = int_value
    | ngram_token_size = int_value
    | ik_mode = 'char_value'
    | min_ngram_size = int_value
    | max_ngram_size = int_value

```

For more information about how to add full-text indexes to existing tables using the `ALTER TABLE` statement, see [ALTER TABLE](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/1600.alter-table-of-mysql-mode.md).

**Parameter descriptions are as follows:**

* `table_name` : Specifies the name of the table to create the index.
* `INDEX | KEY` : optional. For this statement, the index keyword can use `INDEX` or `KEY`. The default value is `KEY`.
* `index_name`: Optional. The name of the index to be created. If you do not specify the name, the system generates one based on the column name.
* `column_name` : specifies the columns to be indexed. If multiple columns are specified, they are separated by English commas.
* `WITH PARSER tokenizer_option` : Optional. Specifies the tokenizer for the full-text index. Valid values:

  * `SPACE`: the default value, which indicates that spaces are used to tokenize. The following attributes can be specified:

      |        Attribute      | Value      |
      |------------------|---------|
      | min_token_size   | [1, 16] |
      | max_token_size   | [10, 84]|

  * `NGRAM` (Chinese N-Gram): specifies to perform Chinese N-Gram tokenization. You can set the following parameters:

      |        Attribute      | Range |
      |------------------|---------|
      | ngram_token_size | [1, 10] |

  * `NGRAM2`: This splits text into n-grams with lengths ranging from `min_ngram_size` to `max_ngram_size`. You can specify the following properties:

      |        Property      | Value range |
      |------------------|---------|
      | min_ngram_size   | [1, 16] |
      | max_ngram_size   | [1, 16] |

  * `BENG`: A tokenizer based on the Bengali (basic English) algorithm. The following options can be specified:

      |        Properties      | Value range |
      |------------------|---------|
      | min_token_size   | [1, 16] |
      | max_token_size   | [10, 84]|

  * `IK`: This specifies the tokenization method based on the IK Chinese tokenizer. Only the `utf-8` character set is supported. The following attributes can be specified:

      |        Property      | Value |
      |------------------|---------|
      | ik_mode          | <ul><li>`smart`</li><li>`max_word`</li></ul>|

   You can use the [TOKENIZE](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/400.functions-of-mysql-mode/960.text-processing-functions-of-mysql-mode/200.tokenize-of-mysql-mode.md) function to view the tokenization results of text in the specified tokenizer and JSON format.

* `PARSER_PROPERTIES[=](parser_properties_list)` : Optional. Specifies the properties of the parser. Valid values:

  * `min_token_size` - the minimum token length. Default value is 3. Range from 1 to 16.
  * `max_token_size`: The maximum number of tokens in a word, with a default value of 84. Valid values: 10 to 84.
  * `ngram_token_size`: The length of the ngram, which applies only to the `NGRAM` tokenizer. The default value is 2 and the value range is 1 to 10.
  * `ik_mode`: specifies the `IK` tokenizer's segmentation mode. Valid values:

    * `smart`: Default value. Specifies to use the terms from the dictionary to improve the accuracy of the tokenization. The boundaries of the terms in the dictionary are considered before any expansion, which reduces unnecessary expansions.
    * `max_word` : This mode recognizes the words in the dictionary, but it does not limit the maximal segmentation. The `max_word` mode will still attempt to split the text into as many words as possible even if the words are defined in the dictionary.

* `LOCAL` (optional): Creates a local index.

**Example:**

After the table `tbl4` is created, add the fulltext index `ft_idx1_tbl4`.

1. Create the `tbl4` table.

   ```sql
   CREATE TABLE tbl4(col1 INT, col2 TEXT);
   ```

2. Add a full-text index named `ft_idx1_tbl4` to the `tbl4` table, specifying the `BENG` tokenizer and using `PARSER_PROPERTIES` to set the tokenizer properties.

   ```sql
   ALTER TABLE tbl4 ADD FULLTEXT INDEX ft_idx1_tbl4(col2)
       WITH PARSER BENG
       PARSER_PROPERTIES=(min_token_size=2, max_token_size=64);
   ```

## Create a search index

<main id="notice" type='notice'>
<h4>Notice</h4>
<p><ul>
<li>`WITH (...)` is applicable only to JSON columns.</li>
<li>`INCLUDE_PATHS` and `EXCLUDE_PATHS` cannot be specified at the same time.</li>
</ul></p>
</main>

### Create a search index by using the CREATE SEARCH INDEX statement

You can create a search index for an existing table by using the `CREATE SEARCH INDEX` statement, which has the following syntax:

```sql
CREATE SEARCH INDEX index_name ON table_name (
    search_index_column
    [, search_index_column ...]
) [LOCAL];

search_index_column:
    column_name [WITH (search_col_option_list)]

search_col_option_list:
    [INCLUDE_PATHS = ('path1'[, 'path2']...)]
    [| EXCLUDE_PATHS = ('path1'[, 'path2']...)]
    [| INCLUDE_TYPES = (type1[, type2]...)]
```

For more information about the syntax and data types of `CREATE SEARCH INDEX`, see [CREATE INDEX](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2200.create-index-of-mysql-mode.md).

**The following table describes the related parameters:**

* `index_name`: the name of the search index to be created.
* `table_name`: the name of the table to which the search index is to be added.
* `search_index_column`: the definition of the search index column. You can define one or more columns. For each column, you can use `WITH (...)` to specify column-level paths and options.
* `INCLUDE_PATHS / EXCLUDE_PATHS`: the column-level white list and black list. One of the two options must be specified. The specified column-level paths will be indexed.
* `INCLUDE_TYPES`: the column-level type filter. The search index indexes only JSON scalar values of the specified types. Currently, `JSON_STRING` and `JSON_NUMBER` are supported.
* `LOCAL`: an optional parameter. It is used to create a local search index in a partitioned table. Currently, a local search index can be created in a partitioned table.

**Here is an example:**

After you create a table named `tbl_search_1`, create a search index named `search_idx_1`.

1. Create the table `tbl_search_1`.

   ```sql
   CREATE TABLE tbl_search_1 (
     id INT,
     doc JSON,
     c2 VARCHAR(64)
   ) ORGANIZATION = HEAP;
   ```

2. Create the search index `search_idx_1` for the table `tbl_search_1` and configure the column-level white list and type filter for the JSON columns.

   ```sql
   CREATE SEARCH INDEX search_idx_1 ON tbl_search_1(
     doc WITH (
       INCLUDE_PATHS = ('$.name', '$.score'),
       INCLUDE_TYPES = (JSON_STRING, JSON_NUMBER)
     ),
     c2
   );
   ```

### Create a search index by using the CREATE TABLE statement

You can create a search index when you create a table by using the `CREATE TABLE` statement, which has the following syntax:

```sql
CREATE TABLE table_name (
    ...,
    SEARCH INDEX index_name (
        search_index_column
        [, search_index_column ...]
    )
) ORGANIZATION = HEAP;
```

For more information about the syntax and data types of `CREATE TABLE`, see [CREATE TABLE](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2600.create-table-of-mysql-mode.md).

**The following table describes the related parameters:**

* `table_name`: the name of the table to which the search index is to be added.
* `index_name`: the name of the search index to be created.
* `search_index_column`: the definition of the search index column. You can define one or more columns. For each column, you can use `WITH (...)` to specify column-level paths and options.

**Here is an example:**

When you create a table named `tbl_search_3`, create a search index named `search_idx_3`.

```sql
CREATE TABLE tbl_search_3 (
  id INT,
  profile JSON,
  tag VARCHAR(32),
  SEARCH INDEX search_idx_3 (
    profile WITH (EXCLUDE_PATHS = ('$.debug')),
    tag
  )
) ORGANIZATION = HEAP;
```

### Create a search index by using the ALTER TABLE statement

You can add a search index to an existing table by using the `ALTER TABLE` statement, which has the following syntax:

```sql
ALTER TABLE table_name
ADD SEARCH INDEX [index_name] (
    search_index_column
    [, search_index_column ...]
);

search_index_column:
    column_name [WITH (search_col_option_list)]

search_col_option_list:
    [INCLUDE_PATHS = ('path1'[, 'path2']...)]
    [| EXCLUDE_PATHS = ('path1'[, 'path2']...)]
    [| INCLUDE_TYPES = (type1[, type2]...)]
```

For more information about the syntax of the `ALTER TABLE` statement, see [ALTER TABLE](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/1600.alter-table-of-mysql-mode.md).

**The following table describes the related parameters:**

* `table_name`: the name of the table to which the search index is to be added.
* `index_name`: the name of the search index. If you do not specify the `index_name` parameter, the system will generate a default search index name based on the table name.
* `search_index_column`: the definition of the search index column. You can define one or more columns. For each column, you can use `WITH (...)` to specify column-level paths and options.
* `INCLUDE_PATHS / EXCLUDE_PATHS`: the column-level white list and black list. One of the two options must be specified. The specified column-level paths will be indexed.
* `INCLUDE_TYPES`: the column-level type filter. The search index indexes only JSON scalar values of the specified types. Currently, `JSON_STRING` and `JSON_NUMBER` are supported.

**Here is an example:**

After you create a table named `tbl_search_2`, add a search index named `search_idx_2` to the table by using the `ALTER TABLE` statement.

1. Create the table `tbl_search_2`.

   ```sql
   CREATE TABLE tbl_search_2 (
     id INT,
     profile JSON,
     tag VARCHAR(32)
   ) ORGANIZATION = HEAP;
   ```

2. Add the search index `search_idx_2` to the table `tbl_search_2`.

   ```sql
   ALTER TABLE tbl_search_2
   ADD SEARCH INDEX search_idx_2 (
     profile WITH (EXCLUDE_PATHS = ('$.debug')),
     tag
   );
   ```
