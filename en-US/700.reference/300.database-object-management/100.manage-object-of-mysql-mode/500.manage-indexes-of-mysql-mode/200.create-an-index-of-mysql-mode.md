# Create an index

This topic describes how to create an index.

## Background information

OceanBase Database allows you to create indexes on both partitioned and non-partitioned tables. The indexes can be local or global, unique or non-unique, and spatial or function-based. A local unique index requires the partitioning key in the table to be included in the index. For more information about indexes, see [Overview](../../../100.oceanbase-database-concepts/400.database-objects/200.database-objects-of-mysql-mode/300.index-of-oracle-mode/100.index-overview-of-mysql-mode.md).

This topic describes how to create indexes on non-partitioned tables. For more information about how to create indexes on partitioned tables, see [Create an index on a partitioned table](../300.manage-partitions-of-mysql-mode/900.create-partition-table-index-of-mysql-mode/200.local-index-of-mysql-mode.md).

## Considerations

When creating an index, make sure that the index name is unique in the database (DB) scope in OceanBase Database.

## Create a non-null index

You can execute the `CREATE TABLE`, `CREATE INDEX`, or `ALTER TABLE` statement to create a non-null index.

### Create a non-null index using the `CREATE TABLE` statement

You can use the `CREATE TABLE` statement to create a table and an index at the same time.

The syntax is as follows:

```sql
CREATE TABLE table_name(column_name column_definition,[column_name column_definition,...] [UNIQUE] INDEX|KEY [index_name](column_name));
```

The parameters are described as follows:

* `table_name`: the name of the table to be created.

* `column_name`: the name of a column in the table.

* `column_definition`: the data type of each column in the table.

* `UNIQUE`: an optional parameter to specify a unique index. If you want to create a unique index, you must add this parameter.

* `INDEX|KEY`: specifies that you can use `INDEX` or `KEY` as the index keyword in the statement.

* `index_name`: the name of the index to be created. If you do not specify this parameter, the default index name is the same as the column name.

Here is an example of creating a table named `tbl1` and an index named `tbl1_idx1` at the same time:

```sql
CREATE TABLE tbl1(id INT,name VARCHAR(18),date DATE,PRIMARY KEY (id),INDEX tbl1_idx1 (date));
```

### Create a non-null index using the `CREATE INDEX` statement

You can use the `CREATE INDEX` statement to create an index on an existing table.

The syntax is as follows:

```sql
CREATE [UNIQUE] INDEX index_name ON table_name (column_name);
```

The parameters are described as follows:

* `UNIQUE`: an optional parameter to specify a unique index. If you want to create a unique index, you must add this parameter.

* `index_name`: the name of the index to be added.

* `table_name`: the name of the table where the index is to be created.

* `column_name`: the name of the column on which the index is to be created. If you want to create an index on multiple columns, separate the column names with commas.

After the `tbl2` table is created, you can execute the following statements to create an index named `tbl2_idx1` on the table:

1. Create the `tbl2` table.

   ```sql
   CREATE TABLE tbl2(id INT,name VARCHAR(20));
   ```

2. Create an index named `tbl2_idx1` on the `tbl2` table.

   ```sql
   CREATE INDEX tbl2_idx1 ON tbl2(id);
   ```

### Create a non-null index using the `ALTER TABLE` statement

You can use the `ALTER TABLE` statement to create an index on an existing table. This statement allows you to create multiple indexes at a time.

The syntax is as follows:

```sql
ALTER TABLE table_name ADD [UNIQUE] INDEX|KEY [index_name](column_name);
```

The parameters are described as follows:

* `table_name`: the name of the table where the index is to be created.

* `UNIQUE`: an optional parameter to specify a unique index. If you want to create a unique index, you must add this parameter.

* `INDEX|KEY`: specifies that you can use `INDEX` or `KEY` as the index keyword in the statement.

* `index_name`: the name of the index to be created. If you do not specify this parameter, the default index name is the same as the column name.

* `column_name`: the name of the column on which the index is to be created. If you want to create an index on multiple columns, separate the column names with commas.

After the `tbl3` table is created, you can execute the following statements to create an index named `tbl3_idx1` on the table:

1. Create the `tbl3` table.

   ```sql
   CREATE TABLE tbl3(id INT,name VARCHAR(20));
   ```

2. Create an index named `tbl3_idx1` on the `tbl3` table.

   ```sql
   ALTER TABLE tbl3 ADD INDEX tbl3_idx1(id);
   ```

## Create a spatial index

The MySQL mode of OceanBase Database supports creating spatial indexes. A spatial index is a description of the physical locations of data stored on media. It can help improve the efficiency of data access in the system.

The syntax for creating a spatial index is similar to that for creating a regular index. You can use the `CREATE TABLE`, `CREATE INDEX`, or `ALTER TABLE` statement to create a spatial index. However, the `SPATIAL` keyword must be added in the syntax for creating a spatial index, and the column on which the spatial index is created must be of the `NOT NULL` attribute.

### Limitations on spatial indexes

Before you create a spatial index, note the following limitations:

* Spatial indexes support only local indexes but not global indexes.

* The column on which you want to create a spatial index must be defined with the `SRID` attribute. Otherwise, the spatial index you add on that column will not take effect during subsequent queries. This is because, after a spatial index is created, the coordinate system specified in the `SRID` attribute is used to compare data in the spatial index. The spatial index stores the minimum bounding rectangle (MBR) of geometric objects for construction and MBR comparison also relies on the `SRID`.

  For more information about SRID, see [Spatial reference systems (SRS)](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/100.basic-elements-of-mysql-mode/100.data-type-of-mysql-mode/900.spatial-data-type-of-mysql-mode/200.spacial-reference-system-of-mysql-mode.md).

* You can create a spatial index only on a column of a spatial data type. For more information, see [Overview of spatial data types](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/100.basic-elements-of-mysql-mode/100.data-type-of-mysql-mode/900.spatial-data-type-of-mysql-mode/100.spatial-data-type-overview-of-mysql-mode.md).

* The column on which you want to create a spatial index must be of the `NOT NULL` attribute.

  If the column is not of the `NOT NULL` attribute, you can use the `ALTER TABLE` statement to change the column attribute to `NOT NULL`. For more information, see [Define the constraint type for a column](../200.manage-tables-of-mysql-mode/400.define-the-constraint-type-for-a-column-of-mysql-mode.md).

### Create a spatial index by using the `CREATE TABLE` statement

The syntax is as follows:

```sql
CREATE TABLE table_name(column_g_name GEOMETRY NOT NULL SRID 4326,[column_name column_definition,...] SPATIAL INDEX|KEY [index_name](column_g_name));
```

The parameters are described as follows:

* `table_name`: the name of the table to be created.

* `column_g_name` and `column_name`: the names of the columns in the table.

* `SRID 4326`: specifies the `SRID` of the spatial column.

* `column_definition`: the data types of the columns in the table. The data type of the column on which you want to add a spatial index must be a spatial data type. For more information, see [Overview of spatial data types](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/100.basic-elements-of-mysql-mode/100.data-type-of-mysql-mode/900.spatial-data-type-of-mysql-mode/100.spatial-data-type-overview-of-mysql-mode.md).

* `INDEX|KEY`: indicates that the index keyword `INDEX` or `KEY` can be used in the statement.

* `index_name`: the name of the index to be added. If you do not specify a name, the default index name is the same as the column name.

Here is an example of creating a table named `tbl1_g` and adding a spatial index named `tbl1_g_idx1`:

```sql
CREATE TABLE tbl1_g (id INT,name VARCHAR(18),g GEOMETRY NOT NULL SRID 4326,SPATIAL INDEX tbl1_g_idx1(g));
```

After the table and the spatial index are created, you can use the `SHOW INDEX` statement to query the index information.



## Create a function-based index

A function-based index is an index created on the result of a function applied to one or more columns of a table. A function-based index is an optimization technique that enables quick location of matching function values during a query to avoid repeated function calls and improve query efficiency.

Assume that you have a table named `sale` with a column named `date_col` of the `date` data type:

```sql
CREATE TABLE sale(date_col date, sales_col int, name_col varchar(10));
```

If you want to retrieve data of March, you can use the `Month()` function in a query statement:

```sql
SELECT * FROM sale WHERE month(date_col) = 3;
```

In this scenario, the database needs to calculate `month(date_col)` for each row in the table and filter out rows where `month(date_col) ≠ 3`. If you need to filter data frequently by month, the database needs to recalculate `month(date_col)` each time, which causes a lot of overhead. Therefore, you can create a function-based index on `date_col` to accelerate queries.

```sql
CREATE INDEX idx1 ON sale((month(date_col)));
```

You can create a function-based index by using the `CREATE TABLE`, `CREATE INDEX`, or `ALTER TABLE` statement. A function-based index can also be a unique index or a spatial index.

### Limitations on function indexes

In MySQL mode of OceanBase Database, expressions in function indexes are restricted, and some system functions cannot be used in expressions. For more information, see [System functions supported in function indexes](../500.manage-indexes-of-mysql-mode/500.function-index-list-of-supported-functions-of-mysql-mode.md) and [System functions not supported in function indexes](../500.manage-indexes-of-mysql-mode/600.function-index-list-of-not-supported-functions-of-mysql-mode.md).

### Create a function index by using the `CREATE TABLE` statement

You can create a function index when you create a table. The syntax is as follows:

```sql
CREATE TABLE table_name({column_name column_definition,[column_name column_definition,...]} [UNIQUE| SPATIAL] {INDEX|KEY} [index_name](expr));
```

The parameters are described as follows:

* `table_name`: the name of the table to create an index on.

* `column_definition`: the data types of the columns in the table.

* `[UNIQUE | SPATIAL]`: optional. `UNIQUE` specifies to create a unique index; `SPATIAL` specifies to create a spatial index. If you want to create a unique index or a spatial index, the corresponding keyword must be added.

* `INDEX|KEY`: indicates that you can use `INDEX` or `KEY` as the index keyword in the syntax.

* `index_name`: the name of the index. It is optional. If it is not specified, the system will automatically generate a name for the index. The format is `functional_index_xx`, where `xx` is the index number.

* `expr`: a valid function index expression. Boolean expressions, such as `c1=c1`, are also supported.

Here is an example of creating a function index named `tbl1_func_idx1`:

```sql
CREATE TABLE tbl1_func (c1 int, c2 int, index tbl1_func_idx1 ((c1+1)), UNIQUE KEY ((c1+c2)));
```

After the function index is created, you can execute the `SHOW CREATE TABLE` statement to view the table creation statement. The syntax is as follows:

```sql
SHOW CREATE TABLE tbl1_func;
```

The query result is as follows:

```sql

| Table     | Create Table                                                                                                                                                                                                                                                                                                                                                                                        |
+-----------+-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| tbl1_func | CREATE TABLE `tbl1_func` (

  `c2` int(11) DEFAULT NULL,
  UNIQUE KEY `functional_index` ((`c1` + `c2`)) BLOCK_SIZE 16384 LOCAL,
  KEY `tbl1_func_idx1` ((`c1` + 1)) BLOCK_SIZE 16384 LOCAL
) DEFAULT CHARSET = utf8mb4 ROW_FORMAT = DYNAMIC COMPRESSION = 'zstd_1.3.8' REPLICA_NUM = 1 BLOCK_SIZE = 16384 USE_BLOOM_FILTER = FALSE TABLET_SIZE = 134217728 PCTFREE = 0 |
```

### Create a function index by using the `CREATE INDEX` statement

After a table is created, you can create a function index on the table. The syntax is as follows:

```sql
CREATE [UNIQUE | SPATIAL] INDEX index_name ON table_name (expr);
```

The parameters are described as follows:

* `[UNIQUE | SPATIAL]`: optional. `UNIQUE` specifies to create a unique index; `SPATIAL` specifies to create a spatial index. If you want to create a unique index or a spatial index, the corresponding keyword must be added.

* `index_name`: the name of the index.

* `table_name`: the name of the table to create an index on.

* `expr`: a valid function index expression. Boolean expressions, such as `c1=c1`, are also supported.

Here is an example of creating a function index named `tbl2_func_idx1` on the `c1` and `c2` columns of the `tbl2_func` table, with the index definition being `c1+c2 < 1`:

1. Create the `tbl2_func` table.

   ```sql
   CREATE TABLE tbl2_func(c1 int, c2 int);
   ```

2. Create the function index `tbl2_func_idx1`.

   ```sql
   CREATE INDEX tbl2_func_idx1 on tbl2_func ((c1+c2 < 1));
   ```

3. After the index is created, you can query it.

   ```sql
   SHOW INDEX FROM tbl2_func;
   ```

   The result is as follows:

   ```shell

   1 row in set
   ```

### Create a function-based index by using the `ALTER TABLE` statement

The syntax is as follows:

```sql
ALTER TABLE table_name ADD [UNIQUE | SPATIAL] {INDEX | KEY} [index_name](expr);
```

The parameters are described as follows:

* `table_name`: the name of the table where you want to create an index.

* `[UNIQUE | SPATIAL]`: the keyword `UNIQUE` indicates a unique index, and the keyword `SPATIAL` indicates a spatial index. These keywords are optional. If you specify either of these keywords, add it to the statement.

* `INDEX|KEY`: the keywords `INDEX` and `KEY` are synonyms. You can use either of them in the statement.

* `index_name`: the name of the index. If you do not specify a name, the system will automatically generate a name for the index in the format of `functional_index` followed by a number.

* `expr`: a valid function-based index expression. Boolean expressions, such as `c1=c1`, are also supported.

1. Create a table named `tbl3_func`.

   ```sql
   CREATE TABLE tbl3_func(c1 int, c2 int);
   ```

2. Create two function-based indexes on the `tbl3_func` table.

   ```sql
   ALTER TABLE tbl3_func ADD INDEX ((c1+1));
   ```

   ```sql
   ALTER TABLE tbl3_func ADD INDEX ((concat(c1,'a')));
   ```

3. Query the index information.

   ```sql
   SHOW INDEX FROM tbl3_func;
   ```

   The query result is as follows:

   ```shell
   +-----------+------------+--------------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+------------------+
   | Table     | Non_unique | Key_name           | Seq_in_index | Column_name | Collation | Cardinality | Sub_part | Packed | Null | Index_type | Comment   | Index_comment | Visible | Expression       |

   | tbl3_func |          1 | functional_index_2 |            1 | SYS_NC19$   | A         |        NULL | NULL     | NULL   | YES  | BTREE      | available |               | YES     | concat(`c1`,'a') |
   ```

## Create a columnstore index

You can execute the `CREATE TABLE`, `CREATE INDEX`, or `ALTER TABLE` statement to create a columnstore index.

### Create a columnstore index when you create a table by using the CREATE TABLE statement

You can use the `CREATE TABLE` statement to create a table and a columnstore index at the same time.

The syntax is as follows:

```sql
CREATE TABLE table_name(column_name column_definition,[column_name column_definition,...] [UNIQUE] INDEX|KEY [index_name](column_name) [STORING(column_name, ...)] WITH COLUMN GROUP([all columns, ]each column));
```

The parameters are described as follows:

* `table_name`: the name of the table to be created.

* `column_name`: the name of a column in the table.

* `column_definition`: the data type of a column in the table.

* `UNIQUE`: an optional parameter to specify a unique index. Add this parameter when you create a unique index.

* `INDEX|KEY`: indicates that you can use `INDEX` or `KEY` for the index keyword in the statement.

* `index_name`: an optional parameter to specify the name of the index. If you do not specify this parameter, the default index name is the same as the column name.

* `STORING(column_name, ... )`: an optional parameter to specify redundant columns in the index table. Even if the `column_name` column is not an index field, the data in this column will be redundantly stored in a columnar storage format.

* `WITH COLUMN GROUP([all columns, ]each column)`: specifies the columnar storage attribute of the index.

  * `WITH COLUMN GROUP(all columns, each column)`: specifies to create a hybrid rowstore-columnstore index.
  * `WITH COLUMN GROUP(all columns)`: specifies to create a rowstore index.
  * `WITH COLUMN GROUP(each column)`: specifies to create a columnstore index.

**Here is an example:**

* Create a table named `tbl4` and a hybrid rowstore-columnstore index named `idx1_tbl4_cg`.

   ```sql
   CREATE TABLE tbl4(id INT, name VARCHAR(18), date DATE, PRIMARY KEY (id), INDEX idx1_tbl4_cg (date) WITH COLUMN GROUP(all columns, each column));
   ```

* Create a table named `tbl5`, a columnstore index named `idx1_tbl5_cg`, and store redundant data of the `id` column in the index table.

   ```sql
   CREATE TABLE tbl5(id INT, name VARCHAR(18), date DATE, INDEX idx1_tbl5_cg (date) STORING(id) WITH COLUMN GROUP(each column));
   ```

### Create a columnstore index by using the CREATE INDEX statement

You can use the `CREATE INDEX` statement to create a columnstore index for an existing table.

The syntax is as follows:

```sql
CREATE [UNIQUE] INDEX index_name ON table_name (column_name) [STORING(column_name, ...)] WITH COLUMN GROUP([all columns, ]each column);
```

The parameters are described as follows:

* `UNIQUE`: an optional parameter to specify a unique index. Add this parameter when you create a unique index.

* `index_name`: the name of the index to be added.

* `table_name`: the name of the table where the index is to be created.

* `column_name`: the name of the column to be indexed. If you want to index multiple columns, separate the column names with commas (,).

* `STORING(column_name, ... )`: an optional parameter to specify redundant columns in the index table. Even if the `column_name` column is not an index field, the data in this column will be redundantly stored in a columnar storage format.

* `WITH COLUMN GROUP([all columns, ]each column)`: specifies the columnar storage attribute of the index.

  * `WITH COLUMN GROUP(all columns, each column)`: specifies to create a hybrid rowstore-columnstore index.
  * `WITH COLUMN GROUP(all columns)`: specifies to create a rowstore index.
  * `WITH COLUMN GROUP(each column)`: specifies to create a columnstore index.

**Here is an example:**

After you create the `tbl6` table, create a columnstore index named `idx1_tbl6_cg` on this table.

1. Create the `tbl6` table.

   ```sql
   CREATE TABLE tbl6(id INT, name VARCHAR(20), age INT);
   ```

2. Create a columnstore index named `idx1_tbl6_cg` on the `tbl6` table and store redundant data of the `age` column in the index table.

   ```sql
   CREATE INDEX idx1_tbl6_cg ON tbl6(id) STORING(age) WITH COLUMN GROUP(each column);
   ```

### Create a columnstore index by using the ALTER TABLE statement

You can execute the `ALTER TABLE` statement to create a columnstore index on an existing table.

The syntax is as follows:

```sql
ALTER TABLE table_name ADD [UNIQUE] INDEX|KEY [index_name](column_name) [STORING(column_name, ...)] WITH COLUMN GROUP([all columns, ]each column);
```

The parameters are described as follows:

* `table_name`: the name of the table on which to create the index.

* `UNIQUE`: the keyword to specify a unique index. Add this keyword when you create a unique index.

* `INDEX|KEY`: the keyword to indicate that an index is to be created. You can use `INDEX` or `KEY` in this clause.

* `index_name`: the name of the index. If you do not specify this parameter, the default index name is the same as the column name.

* `column_name`: the columns to be indexed. The columns are separated with commas if multiple columns are specified.

* `STORING(column_name, ... )`: the redundant columns in the index table. The data in the `column_name` column is redundantly stored in columnar storage format even if it is not an index column.

* `WITH COLUMN GROUP([all columns, ]each column)`: the columnstore attribute of the index.

  * `WITH COLUMN GROUP(all columns, each column)`: specifies to create a hybrid rowstore-columnstore index.
  * `WITH COLUMN GROUP(all columns)`: specifies to create a rowstore index.
  * `WITH COLUMN GROUP(each column)`: specifies to create a columnstore index.

**Here is an example:**

After you create the `tbl7` table, create a columnstore index named `idx1_tbl7_cg` on this table.

1. Create the `tbl7` table.

   ```sql
   CREATE TABLE tbl7(id INT, name VARCHAR(20), age INT);
   ```

2. Create a columnstore index named `idx1_tbl7_cg` on the `tbl7` table and store the redundant data of the `age` column in the index table.

   ```sql
   ALTER TABLE tbl7 ADD INDEX idx1_tbl7_cg(id) STORING(age) WITH COLUMN GROUP(each column);
   ```

## Create a multi-valued index

OceanBase Database allows you to create a multi-valued index when you create a table (`CREATE TABLE`). At present, you cannot add a multi-valued index to a table after it is created. However, you can use the `ALTER TABLE` statement to drop an existing index. You can perform complex DML operations on a primary table that contains a multi-valued index.

### Limitations on multi-valued indexes

* A multi-valued index can contain only one multi-valued key part. However, a `CAST(... AS ... ARRAY)` expression can reference multiple arrays in a JSON document, as shown below:

   ```sql
   CAST(data->'$.arr[*][*]' AS UNSIGNED ARRAY)
   ```

   In this case, all values that match the JSON expression are stored in the index as a single flat array.

* A multi-valued index cannot be a covering index.
* The only unique expression allowed in a multi-valued key part is a JSON expression. The expression does not need to reference an existing element in the JSON document that is inserted into the index column, but must be syntactically valid.
* Since the index records of the same clustered index record are scattered in the multi-valued index, the multi-valued index does not support range scans or index-only scans.
* A multi-valued index cannot be created on a foreign key.
* You cannot define a prefix on a multi-valued index.
* You cannot create a multi-valued index on data of the BINARY type.

### Create a multi-valued index by using the CREATE TABLE statement

**The simplified syntax for creating a multi-valued index by using the `CREATE TABLE` statement is as follows:**

Create a multi-valued index:

```sql
CREATE TABLE table_name(column_name column_definition, [column_name column_definition, ...],
    json_column_name JSON, 
    [UNIQUE] INDEX idx_json_name((CAST(json_column_name->'$.json_field_name' AS UNSIGNED ARRAY)))
);
```

Create a composite multi-valued index:

```sql
CREATE TABLE table_name(column_name column_definition, [column_name column_definition, ...],
    json_column_name JSON,
    INDEX idx_json_name(column_name, [column_name, ...] (CAST(json_column_name->'$.json_field_name' AS CHAR(n) ARRAY)))
);                   
```

The parameters are described as follows:

* `table_name`: the name of the table to be created.

* `column_name`: the name of a column of a data type other than `JSON` in the table.

* `column_definition`: the data types of the columns in the table.

* `json_column_name`: the name of a column of the `JSON` data type in the table.

* `UNIQUE`: an optional keyword to indicate that a unique multi-valued index is to be created. A unique multi-valued index does not allow duplicate index keys.

   <main id="notice" type='notice'>
     <h4>Notice</h4>
     <p>You can define a multi-valued index as a unique index. If you define it as a unique index, an error will be returned when you attempt to insert a value that already exists in the multi-valued index. If duplicate values exist, an error will occur when you attempt to add a unique multi-valued index. </p>
   </main>

* `idx_json_name`: the name of the multi-valued index to be created.

* `json_field_name`: the name of the field to be indexed in the JSON column.

For more information about the syntax of the CREATE TABLE statement, see [CREATE TABLE](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2600.create-table-of-mysql-mode.md).

**Here is an example of creating a multi-valued index:**

1. Create a table named `json_tbl1` and a multi-valued index named `idx1_json_tbl1`.

   ```sql
   CREATE TABLE json_tbl1(col1 INT, col2 VARCHAR(18), col3 JSON,
      INDEX idx1_json_tbl1((CAST(col3->'$.ipcode' AS UNSIGNED ARRAY)))
   );
   ```

2. Execute the following statements to insert test data into the `json_tbl1` table.

   ```sql
   INSERT INTO json_tbl1 VALUES(1, 'a1', '{"user":"Jk001","user_id":37,"ipcode":[94582,94536]}'),
      (2, 'a2', '{"user":"Jk002","user_id":22,"ipcode":[94568,94507,94582]}'),
      (3, 'a3', '{"user":"Jk003","user_id":31,"ipcode":[94477,94507]}'),
      (4, 'a4', '{"user":"Jk004","user_id":72,"ipcode":[94536]}'),
      (5, 'a5', '{"user":"Jk005","user_id":56,"ipcode":[94507,94582]}');
   ```

**Here is an example of creating a composite multi-valued index:**

Create a table named `json_tbl2` and a composite multi-valued index named `idx1_json_tbl2`.

```sql
CREATE TABLE json_tbl2(col1 INT, col2 VARCHAR(18), col3 JSON,
      INDEX idx1_json_tbl2(col1, (CAST(col3->'$.ipcode' AS UNSIGNED ARRAY)))
);
```

### Support for complex DML

After you create a primary table that contains a multi-valued index, you can perform complex DML operations on the table. Here are some examples:

* `INSERT INTO ON DUPLICATE KEY`

   ```sql
   CREATE TABLE customers(id INT PRIMARY KEY, uid INT, j JSON);

   INSERT INTO customers VALUES (10, 21, '{"user":"Jack","user_id":37,"zipcode":[94582,94536]}');

   CREATE INDEX zips ON customers((CAST(j->'$.zipcode' AS UNSIGNED ARRAY)));

   INSERT INTO customers 
  VALUES (10, 22, '{"user":"Jack","user_id":37,"zipcode":[24582,34536]}') 
  ON DUPLICATE KEY 
  UPDATE j = '{"user":"Jack","user_id":37,"zipcode":[34582,44536]}';
   ```

* `REPLACE INTO`

   ```sql
   CREATE TABLE test_array(id int,a varchar(50),j json,INDEX index_1( (CAST(j->'$.key' AS UNSIGNED ARRAY))) );

   INSERT INTO test_array VALUES(1,'test','{"key":[1,2,3,4]}');

   REPLACE INTO test_array VALUES(1,'test','{"key":[8,9,13,43]}');
   ```

* Multi-table `UPDATE` and `DELETE`

   First, prepare the sample tables as follows:

   ```sql
   CREATE TABLE table_1(a int PRIMARY KEY, b json, INDEX index_1( (CAST(b->'$.key' AS UNSIGNED ARRAY))) );
   CREATE TABLE table_2(a int PRIMARY KEY, b json);

   INSERT INTO table_1 values(1, '{"key":[1,2,3,4]}');
   INSERT INTO table_2 values(1, '{"key":[1,2,3,4]}');
   ```

   Here is an example of an `UPDATE` operation:

   ```sql
   UPDATE table_1 JOIN table_2 ON table_1.a = table_2.a 
   SET table_1.b = '{"key":[11,12,13,14]}', table_2.b = '{"key":[21,22,23,24]}';

   UPDATE  table_1 JOIN table_2 ON table_1.a = table_2.a SET table_1.b = '{"key":[31,32,33,34]}';
   UPDATE table_1 JOIN table_2 ON table_1.a = table_2.a SET table_2.b = table_1.b;
   ```

   Here is an example of a `DELETE` operation:

   ```sql
   DELETE table_1, table_2 FROM table_1 JOIN table_2 ON table_1.a = table_2.a;
   DELETE table_1 FROM table_1 JOIN table_2 ON table_1.a = table_2.a;
   DELETE table_1 FROM table_1 JOIN table_2 ON table_1.a = table_2.a;
   ```

* Updatable views

   ```sql
   CREATE TABLE test(id int,a varchar(50),j json,INDEX index_1( (CAST(j->'$.key' AS UNSIGNED ARRAY))) );
   
   INSERT INTO test values(1,'test','{"key":[1,2,3,4]}');
   
   CREATE VIEW vtest AS SELECT * FROM test;

   UPDATE vtest SET j='{"key":[1,2]}';
   ```

### Add a multi-valued index after table creation

To add a multi-valued index after table creation, you must enable the [_enable_add_fulltext_index_to_existing_table](../../../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/5980._enable_add_fulltext_index_to_existing_table.md) parameter first.

```sql
ALTER SYSTEM SET _enable_add_fulltext_index_to_existing_table = true;
```

Multi-valued indexes can be classified as follows:

| Type | Description |
| --- | --- |
| Multi-valued index | A multi-valued index created by using the `ADD INDEX/ALTER TABLE` statement. |
| Composite multi-valued index | A non-unique composite multi-valued index created by using the `ADD INDEX/ALTER TABLE` statement. A composite multi-valued index allows only one column to be a multi-valued index column, and the other columns to be normal columns. |
| Unique multi-valued index | A unique multi-valued index created by using the `ADD INDEX/ALTER TABLE` statement. |
| Unique composite multi-valued index | A unique composite multi-valued index created by using the `ADD INDEX/ALTER TABLE` statement. A unique composite multi-valued index allows only one column to be a multi-valued index column, and the other columns to be normal columns. |

Here are some examples:

1. Create a table named `json_tbl1` and a non-unique multi-valued index named `idx1_json_tbl1` on the table.

   ```sql
   CREATE TABLE json_tbl1(id INT PRIMARY KEY, uid INT, j JSON);

   INSERT INTO json_tbl1 VALUES 
   (10, 21, '{"user":"Jack","user_id":37,"zipcode":[94582,94536]}'),
   (11, 22, '{"user":"Jill","user_id":22,"zipcode":[94568,94507,94582]}'),
   (12, 23, '{"user":"Bob","user_id":31,"zipcode":[94477,94507]}'),
   (13, 24, '{"user":"Mary","user_id":72,"zipcode":[94536]}'),
   (14, 25, '{"user":"Ted","user_id":56,"zipcode":[94507,94582]}');

   CREATE INDEX idx1_json_tbl1 ON json_tbl1((CAST(j->'$.zipcode' AS UNSIGNED ARRAY)));
   ```

2. Create a unique multi-valued index named `idx1_json_tbl2` on the `json_tbl2` table.

   ```sql
   CREATE TABLE json_tbl2(id INT PRIMARY KEY, uid INT, j JSON);

   INSERT INTO json_tbl2 VALUES 
   (10, 21, '{"user":"Jack","user_id":37,"zipcode":[94507,94536]}'),
   (11, 22, '{"user":"Jill","user_id":22,"zipcode":[94568,94582]}'),
   (12, 23, '{"user":"Bob","user_id":31,"zipcode":[94477]}');

   CREATE UNIQUE INDEX idx1_json_tbl2 ON json_tbl2((CAST(j->'$.zipcode' AS UNSIGNED ARRAY)));
   ```

3. Create a composite multi-valued index named `idx1_json_tbl3` on the `json_tbl3` table.

   ```sql
   CREATE TABLE json_tbl3 (
    id BIGINT NOT NULL PRIMARY KEY,
    c1 BIGINT NOT NULL,
    modified  BIGINT NOT NULL,
    custinfo JSON
   );

   INSERT INTO json_tbl3 VALUES 
   (10, 21, 101, '{"user":"Jack","user_id":37,"zipcode":[94582,94536]}'),
   (11, 22, 102, '{"user":"Jill","user_id":22,"zipcode":[94568,94507,94582]}'),
   (12, 23, 103, '{"user":"Bob","user_id":31,"zipcode":[94477,94507]}'),
   (13, 24, 104, '{"user":"Mary","user_id":72,"zipcode":[94536]}'),
   (14, 25, 105, '{"user":"Ted","user_id":56,"zipcode":[94507,94582]}');

   CREATE INDEX idx1_json_tbl3 ON json_tbl3 (c1, modified,
        (CAST(custinfo->'$.zipcode' AS UNSIGNED ARRAY)) );
   ```

4. Create a unique composite multi-valued index named `idx1_json_tbl4` on the `json_tbl4` table.

   ```sql
   CREATE TABLE json_tbl4 (
    id BIGINT NOT NULL PRIMARY KEY,
    c1 BIGINT NOT NULL,
    modified  BIGINT NOT NULL,
    custinfo JSON
   );

   INSERT INTO json_tbl4 VALUES 
   (10, 21, 101, '{"user":"Jack","user_id":37,"zipcode":[94582,94536]}'),
   (11, 22, 102, '{"user":"Jill","user_id":22,"zipcode":[94568,94507,94582]}'),
   (12, 23, 103, '{"user":"Bob","user_id":31,"zipcode":[94477,94507]}'),
   (13, 24, 104, '{"user":"Mary","user_id":72,"zipcode":[94536]}'),
   (14, 25, 105, '{"user":"Ted","user_id":56,"zipcode":[94507,94582]}');

   CREATE UNIQUE INDEX idx1_json_tbl4 ON json_tbl4 (c1, modified,
        (CAST(custinfo->'$.zipcode' AS UNSIGNED ARRAY)) );
   ```

## Create a full-text index

You can execute the `CREATE TABLE` statement, the `CREATE FULLTEXT INDEX` statement, or the `ALTER TABLE` statement to create a full-text index in the MySQL mode of OceanBase Database of the current version.

For more information about full-text indexes, see [Full-text indexes](../../../100.oceanbase-database-concepts/400.database-objects/200.database-objects-of-mysql-mode/300.index-of-oracle-mode/320.full-text-indexes-of-mysql-mode-in-concepts.md).

For more information about how to query data using a full-text index, see [Full-text queries](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/500.queries-and-subqueries-of-mysql-mode/400.full-text-query-of-mysql-mode.md).

### Limitations and considerations

You can create a full-text index on a non-partitioned table or a partitioned table with or without a primary key. However, the following limitations apply:

* A full-text index can be created only on a column of the `CHAR`, `VARCHAR`, or `TEXT` type.
* At present, only local full-text indexes can be created.
* The `UNIQUE` keyword cannot be used when creating a full-text index.
* If you want to create a full-text index on multiple columns, make sure that these columns have the same character set.

### Create a full-text index by using the CREATE TABLE statement

You can create a full-text index when you create a table by using the `CREATE TABLE` statement. The simplified syntax is as follows:

```sql
CREATE TABLE table_name(column_name column_definition,[column_name column_definition,...]
    FULLTEXT [INDEX | KEY] [index_name](column_name)
    [WITH PARSER tokenizer_option]
    [PARSER_PROPERTIES[=](parser_properties_list)]
    [LOCAL]);

tokenizer_option:
    SPACE
    | NGRAM
    | BENG
    | IK

parser_properties_list:
    parser_properties, [parser_properties]

parser_properties:
    min_token_size = int_value
    | max_token_size = int_value
    | ngram_token_size = int_value
    | ik_mode = 'char_value'
```

For more information about the `CREATE TABLE` statement, see [CREATE TABLE](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2600.create-table-of-mysql-mode.md).

**The parameters are described as follows:**

* `table_name`: the name of the table to be created.

* `column_name`: the name of the column.

* `column_definition`: the data type of the column.

* `FULLTEXT`: specifies to create a full-text index.

   <main id="notice" type='notice'>
     <h4>Notice</h4>
     <p>At present, full-text indexes can be created only on columns of the text or ntext data type. </p>
   </main>

* `INDEX | KEY`: indicates that `INDEX` and `KEY` can be used interchangeably in the statement.

* `index_name`: the name of the index to be created. If you do not specify this parameter, the default index name is the same as the column name.

* `WITH PARSER tokenizer_option`: specifies the parser for the full-text index. The following values are supported:

  * `SPACE`: the default value, which specifies to parse the text by space. It also allows you to specify the following attributes:

      |        Attribute      | Value range |
      |------------------|---------|
      | min_token_size   | [1, 16] |
      | max_token_size   | [10, 84]|

  * `NGRAM`: specifies to parse the text based on N-Gram (Chinese). It also allows you to specify the following attribute:

      |        Attribute      | Value range |
      |------------------|---------|
      | ngram_token_size | [1, 10] |

  * `BENG`: specifies to parse the text based on Beng (basic English). It also allows you to specify the following attributes:

      |        Attribute      | Value range |
      |------------------|---------|
      | min_token_size   | [1, 16] |
      | max_token_size   | [10, 84]|

  * `IK`: specifies to parse the text based on IK (Chinese). Currently, only the `utf-8` character set is supported. It also allows you to specify the following attribute:

      |        Attribute      | Value range |
      |------------------|---------|
      | ik_mode          | <ul><li>`smart`</li><li>`max_word`</li></ul>|

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>For OceanBase Database V4.3.5, the <code>IK</code> parser is supported starting from V4.3.5 BP1. </p>
    </main>

   You can use the [TOKENIZE](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/400.functions-of-mysql-mode/960.text-processing-functions-of-mysql-mode/200.tokenize-of-mysql-mode.md) function to view the parsing results of a specified text based on the parser and the JSON-formatted parameters.

* `PARSER_PROPERTIES[=](parser_properties_list)`: specifies the attributes of the parser. The following values are supported:

  * `min_token_size`: the minimum parsing length. The default value is 3. The value range is 1 to 16.
  * `max_token_size`: the maximum parsing length. The default value is 84. The value range is 10 to 84.
  * `ngram_token_size`: the parsing length of the `NGRAM` parser. It is effective only for the `NGRAM` parser. The default value is 2. The value range is 1 to 10.
  * `ik_mode`: the parsing mode of the `IK` parser. The following values are supported:

    * `smart`: the default value, which specifies to use the dictionary-based parsing mode to improve parsing accuracy and prioritize dictionary-based parsing boundaries to possibly reduce unnecessary expansion.
    * `max_word`: specifies to parse the text based on the dictionary-based parsing mode. It does not affect the maximized expansion. The `max_word` mode will still attempt to divide the text into more words even if they are defined in the dictionary.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>For OceanBase Database V4.3.5, the <code>PARSER_PROPERTIES</code> parameter is supported starting from V4.3.5 BP1. </p>
  </main>

* `LOCAL`: specifies to create a local index.

**Here are some examples:**

* Create a table named `tbl1` and a full-text index named `full_idx1_tbl1` on the `tbl1` table.

   ```sql
   CREATE TABLE tbl1(id INT, name VARCHAR(18), date DATE, PRIMARY KEY (id), FULLTEXT INDEX full_idx1_tbl1(name));
   ```

* Create a table named `tbl2` and a full-text index named `full_idx1_tbl2` on the `tbl2` table. Set the `NGRAM` parser for the full-text index and use the `PARSER_PROPERTIES` parameter to set the attributes of the parser.

   ```sql
   CREATE TABLE tbl2(id INT, name VARCHAR(18), doc TEXT, 
       FULLTEXT INDEX full_idx1_tbl2(name, doc)
         WITH PARSER NGRAM
         PARSER_PROPERTIES=(ngram_token_size=3));
   ```

### Create a full-text index by using the CREATE FULLTEXT INDEX statement

You can execute the `CREATE FULLTEXT INDEX` statement to create a full-text index on an existing table. The syntax is as follows:

```sql
CREATE FULLTEXT INDEX index_name ON table_name (column_name, [column_name ...])
    [WITH PARSER tokenizer_option]
    [PARSER_PROPERTIES[=](parser_properties_list)]
    [LOCAL];

tokenizer_option:
    SPACE
    | NGRAM
    | BENG
    | IK

parser_properties_list:
    parser_properties, [parser_properties]

parser_properties:
    min_token_size = int_value
    | max_token_size = int_value
    | ngram_token_size = int_value
    | ik_mode = 'char_value'
```

For more information about the `CREATE INDEX` statement, see [CREATE INDEX](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2200.create-index-of-mysql-mode.md).

**The parameters are described as follows:**

* `index_name`: the name of the index to be added.
* `table_name`: the name of the table on which the index is to be created.
* `column_name`: the columns to be indexed. If you index multiple columns, separate them with commas.
* `WITH PARSER tokenizer_option`: an optional parameter that specifies the parser for the full-text index. The possible values are as follows:

  * `SPACE`: the default value, which specifies to parse the text by space. You can set the following attributes:

      |        Attribute      | Value range |
      |------------------|---------|
      | min_token_size   | [1, 16] |
      | max_token_size   | [10, 84]|

  * `NGRAM`: specifies to parse the Chinese text by using the N-Gram method. You can set the following attribute:

      |        Attribute      | Value range |
      |------------------|---------|
      | ngram_token_size | [1, 10] |

  * `BENG`: specifies to parse the text by using the Beng method. You can set the following attributes:

      |        Attribute      | Value range |
      |------------------|---------|
      | min_token_size   | [1, 16] |
      | max_token_size   | [10, 84]|

  * `IK`: specifies to parse the Chinese text by using the IK parser. The current supported character set is `utf-8`. You can set the following attribute:

      |        Attribute      | Value range |
      |------------------|---------|
      | ik_mode          | <ul><li>`smart`</li><li>`max_word`</li></ul>|

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>In OceanBase Database V4.3.5, the <code>IK</code> parser is supported starting from V4.3.5 BP1. </p>
    </main>

   You can use the [TOKENIZE](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/400.functions-of-mysql-mode/960.text-processing-functions-of-mysql-mode/200.tokenize-of-mysql-mode.md) function to view the parsing results of a specified parser and parameters in JSON format.

* `PARSER_PROPERTIES[=](parser_properties_list)`: the properties of the parser. It is an optional parameter. The possible values are as follows:

  * `min_token_size`: the minimum parsing length. The default value is 3. The value range is 1 to 16.
  * `max_token_size`: the maximum parsing length. The default value is 84. The value range is 10 to 84.
  * `ngram_token_size`: the parsing length for the NGRAM parser. It is effective only for the NGRAM parser. The default value is 2. The value range is 1 to 10.
  * `ik_mode`: the parsing mode for the IK parser. The possible values are as follows:

    * `smart`: the default value, which specifies to use the words in the dictionary to improve parsing accuracy and prioritize the word boundaries in the dictionary, which may reduce unnecessary expansion.
    * `max_word`: specifies to identify the words defined in the dictionary but does not affect the maximized expansion. The parser still attempts to split the text into more words even if they are not defined in the dictionary.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>In OceanBase Database V4.3.5, the specification of parser properties (<code>PARSER_PROPERTIES</code>) is supported starting from V4.3.5 BP1. </p>
  </main>

* `LOCAL`: specifies to create a local index. It is an optional parameter.

**Here is an example:**

After you create the `tbl3` table, create a full-text index named `ft_idx1_tbl3` on it.

1. Create the `tbl3` table.

   ```sql
   CREATE TABLE tbl3(col1 INT, col2 VARCHAR(4096));
   ```

2. Create a full-text index named `ft_idx1_tbl3` on the `tbl3` table. In this example, the `IK` parser is specified for the full-text index, and the parser properties are set by using `PARSER_PROPERTIES`.

   ```sql
   CREATE FULLTEXT INDEX ft_idx1_tbl3 ON tbl3(col2)
       WITH PARSER IK
       PARSER_PROPERTIES=(ik_mode='max_word');
   ```

### Create a full-text index by using the ALTER TABLE statement

You can execute the `ALTER TABLE` statement to add a full-text index to an existing table. The syntax is as follows:

```sql
ALTER TABLE table_name ADD FULLTEXT [INDEX | KEY] [index_name](column_name, [column_name ...])
    [WITH PARSER tokenizer_option]
    [PARSER_PROPERTIES[=](parser_properties_list)]
    [LOCAL];

tokenizer_option:
    SPACE
    | NGRAM
    | BENG
    | IK

parser_properties_list:
    parser_properties, [parser_properties]

parser_properties:
    min_token_size = int_value
    | max_token_size = int_value
    | ngram_token_size = int_value
    | ik_mode = 'char_value'
```

For more information about the `CREATE INDEX` statement, see [ALTER TABLE](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/1600.alter-table-of-mysql-mode.md).

**The parameters are described as follows:**

* `table_name`: the name of the table to which the index will be added.
* `INDEX | KEY`: an optional parameter. If you use the `INDEX` or `KEY` keyword in the statement, you can use `INDEX` or `KEY` to specify the keyword. The default value is `KEY`.
* `index_name`: the name of the index. This parameter is optional. If you do not specify a name, the default index name is the same as the column name.
* `column_name`: the name of the column to be indexed. If you specify multiple columns, separate them with commas.
* `WITH PARSER tokenizer_option`: an optional parameter. It specifies the parser for the full-text index. The following table describes the possible values:

  * `SPACE`: the default value. It specifies to parse the text by space. You can set the following attributes:

      |        Attribute      | Value range |
      |------------------|---------|
      | min_token_size   | [1, 16] |
      | max_token_size   | [10, 84]|

  * `NGRAM`: specifies to parse the text based on N-Gram (Chinese). You can set the following attribute:

      |        Attribute      | Value range |
      |------------------|---------|
      | ngram_token_size | [1, 10] |

  * `BENG`: specifies to parse the text based on Beng (basic English). You can set the following attributes:

      |        Attribute      | Value range |
      |------------------|---------|
      | min_token_size   | [1, 16] |
      | max_token_size   | [10, 84]|

  * `IK`: specifies to parse the text based on IK (Chinese). The `utf-8` character set is supported at present. You can set the following attribute:

      |        Attribute      | Value range |
      |------------------|---------|
      | ik_mode          | <ul><li>`smart`</li><li>`max_word`</li></ul>|

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>For OceanBase Database V4.3.5, the <code>IK</code> parser is supported starting from V4.3.5 BP1. </p>
    </main>

   You can use the [TOKENIZE](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/400.functions-of-mysql-mode/960.text-processing-functions-of-mysql-mode/200.tokenize-of-mysql-mode.md) function to view the parsing results of a specified text based on the specified parser and JSON parameters.

* `PARSER_PROPERTIES[=](parser_properties_list)`: an optional parameter. It specifies the attributes of the parser. The following table describes the possible values:

  * `min_token_size`: the minimum parsing length. The default value is 3. The value range is 1 to 16.
  * `max_token_size`: the maximum parsing length. The default value is 84. The value range is 10 to 84.
  * `ngram_token_size`: the parsing length for the `NGRAM` parser. Only the `NGRAM` parser is effective. The default value is 2. The value range is 1 to 10.
  * `ik_mode`: the parsing mode for the `IK` parser. The following table describes the possible values:

    * `smart`: the default value. Dictionary-based words are used to improve parsing accuracy and dictionary-based word boundaries are preferentially considered, which may reduce unnecessary extensions.
    * `max_word`: words defined in the dictionary are identified, but the parsing result is not maximized. The text is attempted to be divided into more words even if they are defined in the dictionary.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>For OceanBase Database V4.3.5, the <code>PARSER_PROPERTIES</code> parameter is supported starting from V4.3.5 BP1. </p>
  </main>

* `LOCAL`: an optional parameter. It specifies to create a local index.

**Here is an example:**

After creating a table named `tbl4`, add a full-text index named `ft_idx1_tbl4` to the table.

1. Create a table named `tbl4`.

   ```sql
   CREATE TABLE tbl4(col1 INT, col2 TEXT);
   ```

2. Add a full-text index named `ft_idx1_tbl4` to the `tbl4` table. Set the `BENG` parser for the full-text index and use `PARSER_PROPERTIES` to specify the parser attributes.

   ```sql
   ALTER TABLE tbl4 ADD FULLTEXT INDEX ft_idx1_tbl4(col2)
       WITH PARSER BENG
       PARSER_PROPERTIES=(min_token_size=2, max_token_size=64);
   ```
