# About external tables and external files

The data of an external table is stored in a storage system outside the OceanBase cluster (such as local directories, object storage, HDFS, or MaxCompute). Only the metadata and access paths are stored in the database. After an external table is successfully created, it can be used for operations such as `SELECT`, JOIN, and aggregation, just like a regular table. However, it is **read-only** and does not support DML, constraints, or indexes.

Differences from regular tables:

| Feature | External table | Regular table |
| ---- | ---- | ------ |
| Data location | External storage | Inside OceanBase |
| Read/write | External tables are **read-only**: You can perform `SELECT` operations, but you cannot execute DML operations such as `INSERT`, `UPDATE`, or `DELETE`. | Read/write |
| Constraints and indexes | **Does not support** constraints such as primary keys, unique keys, or foreign keys, and **does not support** creating indexes. | Supports |
| Typical performance | Affected by network and external systems | Faster local access |

## Considerations

* When creating an external table, the system writes the matched file list to the system table based on the `LOCATION` and `PATTERN` parameters. External files are accessed according to this list during scanning.
* **New files added to an external directory** do not appear in the list automatically. You must execute [Update the external table file list](../../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/1300.alter-external-table-of-mysql-mode.md) or refer to [Manage external files](300.manage-external-files-of-mysql-mode.md).
* When an external file is **deleted**, queries usually do not report an error; instead, the corresponding file returns an empty result.
* When an external file is **modified**, queries read the latest content. Concurrent modification of the file by queries and external modifications may result in unexpected results. Avoid modifying files during queries.

## Ways to access external data

OceanBase provides multiple ways to access external data. First, determine whether you need to **persist the table object** and whether you **frequently query the same batch of files repeatedly**:

| Method | Persistence of table objects | Typical scenarios | Syntax and reference |
| ---- | -------------- | -------- | -------------- |
| **External table (CREATE EXTERNAL TABLE)** | Yes, metadata is persisted. | Frequent queries, joins with internal tables, and management of file lists and partitions. | [CREATE EXTERNAL TABLE](../../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2200.create-external-table-of-mysql-mode.md) and [Create and query external tables](200.create-a-external-table-of-mysql-mode.md) |
| **FILES table function** | No, ad-hoc queries | Temporary exploration, one-time reading, LOAD DATA data source | [FILES table function](../../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/400.functions-of-mysql-mode/760.table-functions-of-mysql-mode/200.files-table-function-of-mysql-mode.md) and [URL external table (no metadata)](../../../../../620.obap/400.data-lake/300.url-external-table.md) |
| **External Catalog** | Connect to an external catalog | Query lakehouse tables such as Hive, Iceberg, or ODPS. Metadata is synchronized by the Catalog. | [CREATE EXTERNAL CATALOG syntax](../../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2150.create-external-catalog-of-mysql-mode.md) and [Catalog and external tables](../../../../../620.obap/400.data-lake/200.data-lake-integration/150.catalog-externaltable.md) |

## HDFS external tables and ODPS external tables

OceanBase Database supports accessing different types of external data sources through external tables, including file data in external storage systems and table data in external data platforms. Among these, HDFS belongs to an external storage system, and ODPS (MaxCompute) belongs to an external data platform.

### HDFS external tables

The Hadoop Distributed File System (HDFS) is a distributed storage system in the Hadoop ecosystem. OceanBase Database supports accessing data in HDFS through external tables starting from V4.3.5 BP1.

Before using an HDFS external table, you need to deploy the [Java SDK environment for OceanBase Database](../../../../../400.deploy/300.deploy-oceanbase-enterprise-edition/500.deploy-the-ob-java-sdk-environment.md) and configure related parameters such as [ob_enable_java_env](../../../../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16630.ob_enable_java_env.md). For syntax details, refer to the `LOCATION` and `FORMAT` sections in [CREATE EXTERNAL TABLE](../../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2200.create-external-table-of-mysql-mode.md).

### ODPS (MaxCompute) external tables

ODPS (MaxCompute) is a data platform designed for large-scale data processing. OceanBase Database supports accessing data in ODPS through external tables.

When using it, you can specify the external data source using the `PROPERTIES (TYPE = 'ODPS' ...)` clause in the external table definition. The `API_MODE` parameter can be set to `storage_api` or `tunnel_api`. For syntax details, refer to the `properties_type_options` section in [CREATE EXTERNAL TABLE](../../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2200.create-external-table-of-mysql-mode.md). For usage instructions and examples, see [ODPS external tables](../../../../../620.obap/400.data-lake/200.data-lake-integration/300.odps/200.odps-external-table.md).
