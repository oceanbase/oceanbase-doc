# About external tables

Usually, table data in a database is stored within the database's storage space, whereas the data of an external table is stored in an external storage service. When creating an external table, you need to specify the path and format of the data files. After the external table is created, you can use it to read data from the external storage service.

You can use an external table like a regular table. You can link it to other tables, aggregate data in it, and sort data in it. The following table describes the differences between an external table and a regular table.

* Data of an external table is stored in external files, while data of a regular table is stored in the database.

* An external table is read-only. You can use it in a query statement, but you cannot perform DML operations on it.

* You cannot add constraints to an external table or create indexes on it.

Generally, an external table is slower than a regular table.

## HDFS external tables

### Read data from HDFS external tables

Hadoop Distributed File System (HDFS) is a core component of the Hadoop ecosystem, designed for storing and processing large-scale datasets. To facilitate direct access to data stored in HDFS, OceanBase Database now supports the Read HDFS external table feature.

For more information about creating an HDFS external table, see [CREATE EXTERNAL TABLE](../../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2200.create-external-table-of-mysql-mode.md).

The HDFS SDK is developed in Java, while OceanBase Database is built using C++. Therefore, a bridge is needed between the two, which is achieved through the Java Native Interface (JNI) framework. Similarly, the Java SDK for ODPS also requires a Java environment to run. To use the HDFS external table feature, you need to configure a Java environment and control it using specific parameters to create tables that can access HDFS files. The relevant parameters are as follows:

* [ob_enable_java_env](../../../../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16630.ob_enable_java_env.md)
* [ob_java_home](../../../../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16635.ob_java_home.md)
* [ob_java_connector_path](../../../../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16640.ob-java-connector-path.md)
* [ob_java_opts](../../../../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16650.ob_java_opts.md)

For more information about configuring the Java environment, see [Deploy the OceanBase Database Java SDK environment](../../../../../400.deploy/300.deploy-oceanbase-enterprise-edition/500.deploy-the-ob-java-sdk-environment.md).

### Write data to HDFS external tables

OceanBase Database supports the feature of writing data to HDFS external tables in V4.4.0. For more information about this feature, see [SELECT INTO](../../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/8000.select-into-of-mysql-mode.md).

## Access external tables in ODPS

MaxCompute (ODPS) provides the following two APIs:

* Storage API: a data service interface that provides efficient, low-latency, and secure data reading.
* Tunnel API: a data upload and download interface that is mainly used for batch operations on table data (such as full table data import and export).

By adapting the ODPS APIs, OceanBase Database can access tables in ODPS through external tables. When you create an external table for ODPS, OceanBase Database provides parameters for configuring the Storage API and Tunnel API. For more information, see [CREATE EXTERNAL TABLE](../../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2200.create-external-table-of-mysql-mode.md). The following table describes the selection of the Storage API and Tunnel API.

| Dimension | Storage API | Tunnel API | Scenarios |
|--------|-------------|------------|---------|
| Features | Supports fine-grained data access (such as partition filtering and predicate pushdown). | Focuses on efficient full-table data import and export, and does not support conditional filtering. | Supports HTAP mixed load, conditional queries on partitioned tables, and deep integration with the computing engine (such as Apache Spark and ODPS). |
| Sharding strategy | Automatic sharding: dynamically splits tasks by byte or row to improve parallel efficiency. | Manual sharding: you need to calculate the partition size or row count yourself, and the configuration is relatively complex. The performance is lower than that of the Storage API, and there are no special requirements for the resource configuration of ODPS. It is compatible with all ODPS configurations. | <ul><li>Storage API: suitable for multi-partition tables and supports two dynamic sharding strategies:<ul><li>By byte: when the sizes of data records vary significantly, byte-based sharding ensures that the data volume of each shard is balanced, preventing calculation skew. </li><li>By row: when the record sizes are relatively consistent, fixed-row sharding improves parallel processing efficiency. </li></ul></li><li>Tunnel API: suitable for scenarios where the relevant Storage API service is not available in ODPS or compatibility is required. </li></ul>|
| Performance optimization | Low resource consumption: predicate pushdown reduces the amount of data to be transmitted, and computation is pushed to the database side, resulting in faster query speed. | High resource consumption: full data transmission may occupy a large amount of bandwidth and storage space. | If you need to reduce the amount of data to be transmitted and improve HTAP efficiency, choose the Storage API. If you need to perform simple ETL or full backup, choose the Tunnel API. |
| Environment requirements | OceanBase Database V4.4.0 | No special requirements. | If the environment supports VPS, choose the Storage API. If you are using an earlier version or the scenario is simple, choose the Tunnel API. |
| Data filtering capability | Supported: data can be filtered by SQL conditions (such as `WHERE`) and only the required part is transmitted. | Not supported: full data transmission is required, and local filtering is performed. | If you need to filter data based on conditions (such as analyzing the behavior of specific users), choose the Storage API. |
