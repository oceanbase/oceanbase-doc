# Create and query external tables

This topic describes how to create and query file-based external tables in MySQL-compatible mode. For complete syntax and descriptions of parameters such as `LOCATION`, `FORMAT`, and `PROPERTIES`, see [CREATE EXTERNAL TABLE](../../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2200.create-external-table-of-mysql-mode.md).

If you only need to temporarily read from an external file without creating a table object, use the [FILES table function](../../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/400.functions-of-mysql-mode/760.table-functions-of-mysql-mode/200.files-table-function-of-mysql-mode.md).

## Prerequisites

* You have deployed a cluster, created a MySQL-compatible mode tenant, and [connected to the database](../../../../../300.develop/100.application-development-of-mysql-mode/100.connect-to-oceanbase-database-of-mysql-mode/100.connection-methods-overview-of-mysql-mode.md).
* You have [created a database](../../../../../300.develop/100.application-development-of-mysql-mode/300.database-object-planning-of-mysql-mode/100.create-database-of-mysql-mode-in-develop.md).
* The current user has the `CREATE` privilege. For more information, see [View user privileges](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/400.view-user-permissions-of-mysql-mode.md).
* **Local files**: The data is placed in a path accessible to the OBServer, and [secure_file_priv](../../../../800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/12000.secure_file_priv-global.md) is configured (modifying this variable usually requires a local Unix Socket connection).
* **HDFS / ODPS**: The [OceanBase Database Java SDK environment](../../../../../400.deploy/300.deploy-oceanbase-enterprise-edition/500.deploy-the-ob-java-sdk-environment.md) has been deployed and configured.

## Examples

The following examples fall into two categories: **local file external tables** (accessing CSV files on OBServer via `LOCATION` + `FORMAT`) and **ODPS external tables** (accessing MaxCompute tables via `PROPERTIES`, requiring Java SDK). After both types of external tables are successfully created, you can use `SHOW CREATE TABLE` to view their definitions and `SELECT` to query data.

### Create a local CSV file external table

Assume a `data.csv` file exists under `/home/admin/oceanbase/` on the local machine, containing the following content.

```shell
1,"lin",98
2,"hei",90
3,"ali",95
```

1. On the OBServer node, the tenant administrator connects to the MySQL-compatible mode tenant of the cluster via a local Unix Socket connection.

   A sample connection is as follows:

   ```shell
   obclient -S /home/admin/oceanbase/run/sql.sock -uroot@sys -p********
   ```

   For specific operations and instructions on connecting to OceanBase Database via a local Unix Socket, see [secure_file_priv](../../../../800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/12000.secure_file_priv-global.md).

2. Configure the path `/home/admin/oceanbase/` accessible by the database.

    ```sql
    SET GLOBAL secure_file_priv = "/home/admin/oceanbase/";
    ```

    After the command executes successfully, you need to restart the session for the changes to take effect.

3. After reconnecting to the database, create the external table `ext_t3`.

    ```sql
    CREATE EXTERNAL TABLE ext_t3(id int, name char(10),score int)
    LOCATION = '/home/admin/oceanbase/'
    FORMAT = (
    TYPE = 'CSV'
    FIELD_DELIMITER = ','
    FIELD_OPTIONALLY_ENCLOSED_BY ='"'
    )
    PATTERN = 'data.csv';
    ```

After the external table is successfully created, you can use the `SHOW CREATE TABLE` statement to view its definition, just like a regular table.

```sql
SHOW CREATE TABLE ext_t3;
```

The query result is as follows:

```shell
+--------+------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| Table  | Create Table                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
+--------+------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| ext_t3 | CREATE EXTERNAL TABLE `ext_t3` (
  `id` int(11) GENERATED ALWAYS AS (metadata$filecol1),
  `name` char(10) GENERATED ALWAYS AS (metadata$filecol2),
  `score` int(11) GENERATED ALWAYS AS (metadata$filecol3)
)
LOCATION='file:///home/admin/oceanbase/'
PATTERN='data.csv'
FORMAT (
  TYPE = 'CSV',
  FIELD_DELIMITER = ',',
  FIELD_OPTIONALLY_ENCLOSED_BY = '"',
  ENCODING = 'utf8mb4'
)DEFAULT CHARSET = utf8mb4 ROW_FORMAT = DYNAMIC COMPRESSION = 'zstd_1.3.8' REPLICA_NUM = 1 BLOCK_SIZE = 16384 USE_BLOOM_FILTER = FALSE TABLET_SIZE = 134217728 PCTFREE = 0 |
+--------+------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
1 row in set
```

It can also be accessed like a regular table. When querying an external table, the system reads the external file directly through the external table's driver layer, parses it according to the file format, converts it into OceanBase Database's internal data types, and then returns the data rows. The following is an example of querying the newly created external table `ext_t3`.

```sql
SELECT * FROM ext_t3;
```

The query result is as follows:

```shell
+----+------+-------+
| id | name | score |
+----+------+-------+
|  1 | lin  |    98 |
|  2 | hei  |    90 |
|  3 | ali  |    95 |
+----+------+-------+
3 rows in set
```

Furthermore, external tables can be combined with regular tables for joint queries. Suppose there is a regular table named `info` in the current database, with data as follows:

```shell
+------+--------+------+
| name | sex    | age  |
+------+--------+------+
| lin  | male   |    8 |
| hei  | male   |    9 |
| li   | female |    8 |
+------+--------+------+
3 rows in set
```

The following is an example of combining the external table `ext_t3` with the regular table `info` for a joint query.

```sql
SELECT info.* FROM info, ext_t3 WHERE info.name = ext_t3.name AND ext_t3.score > 90;
```

The query result is as follows:

```shell
+------+--------+------+
| name | sex    | age  |
+------+--------+------+
| lin  | male   |    8 |
| li   | female |    8 |
+------+--------+------+
2 rows in set
```

For more information on queries, see [Read data](../../../../../300.develop/100.application-development-of-mysql-mode/500.read-data-of-mysql-mode/100.single-table-query-of-mysql-mode.md).

### Create an ODPS Java SDK external table

This example maps the TPC-H table `lineitem` under the schema `tpch_10g` of the MaxCompute public dataset `bigdata_public_dataset` (for table structure and sample data description, see [Query and read/write MaxCompute (ODPS) data in OceanBase Database](../../../../../620.obap/1000.ap-tutorials/1200.odps-external-table-query.md)). Before creating the ODPS external table, you must have [deployed the OceanBase Database Java SDK environment](../../../../../400.deploy/300.deploy-oceanbase-enterprise-edition/500.deploy-the-ob-java-sdk-environment.md) on all OBServer nodes and prepared the `ACCESSID` / `ACCESSKEY` with MaxCompute read permissions.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>If <code>API_MODE</code> is not explicitly specified, <code>tunnel_api</code> is used by default, which applies to public networks or scenarios where OceanBase Database and MaxCompute are not in the same VPC. If OceanBase Database and MaxCompute are in the same region VPC and the Storage API is enabled, you can set <code>API_MODE = 'storage_api'</code> and <code>SPLIT = 'byte'</code> to improve throughput; parameter descriptions are available in [ODPS External Table](../../../../../620.obap/400.data-lake/200.data-lake-integration/300.odps/200.odps-external-table.md) and <code>properties_type_options</code> in [CREATE EXTERNAL TABLE](../../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2200.create-external-table-of-mysql-mode.md).</p>
</main>

1. Connect to a MySQL-compatible tenant as a user with the `CREATE` privilege and switch to the target database (example database name `test`).

   ```sql
   USE test;
   ```

2. Create the ODPS external table `ext_lineitem`, ensuring its column definitions match those of the MaxCompute source table.

   ```sql
   CREATE EXTERNAL TABLE ext_lineitem (
       l_orderkey      BIGINT,
       l_partkey       BIGINT,
       l_suppkey       BIGINT,
       l_linenumber    BIGINT,
       l_quantity      DECIMAL(15,2),
       l_extendedprice DECIMAL(15,2),
       l_discount      DECIMAL(15,2),
       l_tax           DECIMAL(15,2),
       l_returnflag    CHAR(1),
       l_linestatus    CHAR(1),
       l_shipdate      DATE,
       l_commitdate    DATE,
       l_receiptdate   DATE,
       l_shipinstruct  CHAR(25),
       l_shipmode      CHAR(10),
       l_comment       VARCHAR(44)
   )
   PROPERTIES = (
       TYPE = 'ODPS',
       ACCESSID = '***********',
       ACCESSKEY = '***********',
       ENDPOINT = 'https://service.cn-hangzhou.maxcompute.aliyun.com/api',
       PROJECT_NAME = 'bigdata_public_dataset',
       SCHEMA_NAME = 'tpch_10g',
       TABLE_NAME = 'lineitem',
       QUOTA_NAME = '',
       COMPRESSION_CODE = 'zstd'
   );
   ```

   If using the Storage API (within the VPC, with MaxCompute Storage API permissions enabled), you can add `API_MODE = 'storage_api'` and `SPLIT = 'byte'` to `PROPERTIES`, and change `ENDPOINT` to an address within the same region VPC (for example, `https://service.cn-hangzhou-vpc.maxcompute.aliyun-inc.com/api`).

3. Check the external table definition to confirm that `PROPERTIES` and column mapping have taken effect.

   ```sql
   SHOW CREATE TABLE ext_lineitem;
   ```

4. Query the ODPS external table. The system accesses MaxCompute via the Java SDK and returns the results according to the external table's column definitions.

   ```sql
   SELECT * FROM ext_lineitem LIMIT 5;
   ```

   The following example shows the query result (which is consistent with the first 5 rows of the MaxCompute source table):

5. Combine an ODPS external table with a local regular table for querying (using the same JOIN method as `ext_t3` and `info` in the previous example). Assume a regular table named `orders_summary` already exists in the database, recording the order keys that require key analysis. Example:

   ```sql
   SELECT o.order_id, l.l_quantity, l.l_extendedprice
   FROM orders_summary o
   JOIN ext_lineitem l ON o.order_id = l.l_orderkey
   WHERE l.l_shipdate >= '1996-03-01'
   LIMIT 10;
   ```

## What to do next

* **After adding an external file**: Execute `ALTER EXTERNAL TABLE table_name REFRESH;`, or refer to [Manage external files](300.manage-external-files-of-mysql-mode.md).
* **Manage partitions by directory**: Refer to [Create an external table partition](210.create-table-partition-of-mysql-mode.md).
* **Column types**: Refer to [Data type mappings](400.data-type-mapping-of-mysql-mode.md).
* **Drop an external table**: Use `DROP TABLE`, which is the same as for a regular table. Refer to [Drop a table](../800.delete-a-table-of-mysql-mode.md).
