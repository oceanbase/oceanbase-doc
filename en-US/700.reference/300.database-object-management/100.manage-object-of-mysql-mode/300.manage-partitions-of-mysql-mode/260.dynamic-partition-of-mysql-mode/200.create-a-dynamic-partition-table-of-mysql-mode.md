# Create a dynamically partitioned table

In OceanBase Database, you can use the `DYNAMIC_PARTITION_POLICY` clause to specify the dynamic partition management attributes of a table during table creation.

This topic describes how to create a dynamically partitioned table by using an SQL statement.

## Limitations and considerations

* In the current version, you must specify at least one partition definition when creating a dynamically partitioned table.
* The following types of partitioned tables support enabling dynamic partition management:

  * Partitioned tables with RANGE COLUMNS partitioning and a partitioning key of `date`, `datetime`, `timestamp`, `year`, or `bigint` (with `BIGINT_PRECISION` precision specified).
  * Partitioned tables with RANGE partitioning and a partitioning key of `year` or `bigint` (with `BIGINT_PRECISION` precision specified).
  * Partitioned tables with LIST COLUMNS partitioning and a partitioning key that is a string type time column. The string partitioning key supports `VARCHAR` and `CHAR` types, and its format is determined by the value of `TIME_UNIT`:

    * When `TIME_UNIT = 'year'`: The string partitioning key format is `YYYY`, for example, `2026`.
    * When `TIME_UNIT = 'month'`: The string partitioning key format is `YYYYMM`, for example, `202608`.
    * When `TIME_UNIT = 'day'`: The string partitioning key format is `YYYYMMDD`, for example, `20260819`.
    * When `TIME_UNIT = 'hour'`: The string partitioning key format is `YYYYMMDDHH`, for example, `2026081910`.

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>For V4.4.2, dynamic partition management is supported for partitioned tables with LIST COLUMNS partitioning and a partitioning key that is a string type time column starting from V4.4.2 BP3.</p>
    </main>

* Dynamic partition management can only be enabled for a partitioned table or a subpartition of a subpartitioned table.
* Pre-creating partitions and deleting expired partitions after table creation are not executed immediately. You need to wait for the next automatic scheduling of a dynamic partition management task or manually schedule a dynamic partition management task. For more information about scheduling dynamic partition management tasks, see [Dynamic partition management tasks](500.dynamic-partition-management-task-of-mysql-mode.md).

## Privilege requirements

You must have the `CREATE` privilege to create a dynamically partitioned table. For more information about OceanBase Database privileges, see [Privilege types in MySQL-compatible mode](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md).

## Syntax

The SQL statement for creating a dynamically partitioned table is as follows:

```sql
CREATE TABLE [IF NOT EXISTS] table_name (table_definition_list)
    DYNAMIC_PARTITION_POLICY [=] (dynamic_partition_policy_list)
    partition_option;

dynamic_partition_policy_list:
    dynamic_partition_policy_option [, dynamic_partition_policy_option ...]

dynamic_partition_policy_option:
    ENABLE = {true | false}
    | TIME_UNIT = {'hour' | 'day' | 'week' | 'month' | 'year'}
    | PRECREATE_TIME = {'-1' | '0' | 'n {hour | day | week | month | year}'}
    | EXPIRE_TIME = {'-1' | '0' | 'n {hour | day | week | month | year}'}
    | TIME_ZONE = {'default' | 'time_zone'}
    | BIGINT_PRECISION = {'none' | 'us' | 'ms' | 's'}
```

### Restrictions on dynamic partition parameters

* `TIME_UNIT`: When the partitioning key is of the `date` type, the value of the `TIME_UNIT` parameter cannot be `hour`. When the partitioning key is of the `year` type, the value of the `TIME_UNIT` parameter can only be `year`.
* `PRECREATE_TIME`: You can pre-create at most 2,048 partitions.
* `TIME_ZONE`: The `TIME_ZONE` parameter can specify a custom time zone offset only when the partitioning key is of the `date`, `datetime`, or `year` type. For other types, the value must be `default`.
* `BIGINT_PRECISION`: This parameter can be set to `us`, `ms`, or `s` only when the partitioning key is of the `bigint` type. For other types, the value can only be `none`.
* The values of the `TIME_UNIT`, `TIME_ZONE`, and `BIGINT_PRECISION` parameters cannot be modified after they are specified.

## Examples

### Range Columns partitioning example

Create a dynamic partitioned table named `test_tbl1` with RANGE COLUMNS partitioning. Set the dynamic partitioning attributes as follows:

* Partitions are divided by hour.
* Pre-create partitions for the next 3 hours from the current time.
* Delete partitions whose upper boundary is earlier than 1 day before the current time.
* Use Beijing Time (UTC+8) to determine time, ensuring that partition boundaries and expiration logic are based on this time zone.
* The partitioning key `col2` is of the `DATETIME` type, so there is no need to configure timestamp precision for `bigint`.

```sql
CREATE TABLE test_tbl1 (col1 INT, col2 DATETIME)
    DYNAMIC_PARTITION_POLICY(
        ENABLE = true,
        TIME_UNIT = 'hour',
        PRECREATE_TIME = '3 hour',
        EXPIRE_TIME = '1 day',
        TIME_ZONE = '+8:00',
        BIGINT_PRECISION = 'none'
    )
    PARTITION BY RANGE COLUMNS (col2)(
        PARTITION P0 VALUES LESS THAN ('2025-04-15 13:30:00')
    );
```

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>The actions of pre-creating partitions and deleting expired partitions after the table is created are not executed immediately. They wait for the next automatic scheduling of a dynamic partition management task or require manual scheduling. For more information, see <a href="500.dynamic-partition-management-task-of-mysql-mode.md">Dynamic partition management task</a>.</p>
</main>

### List Columns partitioning example

Create a dynamic partitioned table named `test_tbl2` with LIST COLUMNS partitioning. The partitioning key is a string time column in the format `YYYYMMDD`. Set the dynamic partitioning attributes as follows:

* Automatic partition boundary creation intervals are set by day.
* Partitions are divided by day.
* Pre-create partitions for the next 3 days from the current time.
* Delete partitions whose upper boundary is earlier than 30 days before the current time.
* Use Beijing Time (UTC+8) to determine time, ensuring that partition boundaries and expiration logic are based on this time zone.
* The partitioning key `col2` is of the `VARCHAR` type, so there is no need to configure timestamp precision for `bigint`.

```shell
obclient> CREATE TABLE test_tbl2 (col1 INT, col2 VARCHAR(20))
    DYNAMIC_PARTITION_POLICY(
        ENABLE = true,
        TIME_UNIT = 'day',
        PRECREATE_TIME = '3 day',
        EXPIRE_TIME = '30 day',
        TIME_ZONE = '+8:00',
        BIGINT_PRECISION = 'none'
    )
    PARTITION BY LIST COLUMNS(col2) (
        PARTITION p_20260801 VALUES IN ('20260801')
    );
```
