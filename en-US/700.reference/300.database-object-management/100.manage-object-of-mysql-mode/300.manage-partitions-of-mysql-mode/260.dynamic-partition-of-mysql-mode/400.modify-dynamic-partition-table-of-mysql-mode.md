# Modify a dynamically partitioned table

In OceanBase Database, you can modify the dynamic partition management attributes of a table by modifying the `DYNAMIC_PARTITION_POLICY` block.

This topic describes how to use SQL statements to modify a dynamically partitioned table.

## Limitations and considerations

* After modifying dynamic partition management parameters, pre-created partitions and deleted expired partitions will not take effect immediately. You must wait for the next automatic scheduling of a dynamic partition management task or manually schedule one. For more information about scheduling dynamic partition management tasks, see [Dynamic partition management tasks](500.dynamic-partition-management-task-of-mysql-mode.md).
* The `TIME_UNIT`, `TIME_ZONE`, and `BIGINT_PRECISION` parameters are specified when creating a dynamically partitioned table and cannot be modified after specification.
* Whether to specify `TIME_UNIT` when modifying the dynamic partitioning strategy depends on whether dynamic partition management is enabled for the table:

  * For a table with dynamic partition management enabled, you do not need to specify `TIME_UNIT`, nor can it be specified in the modification statement (specification will result in an error).
  * For a table without dynamic partition management enabled (for example, a regular partitioned table), you need to specify `TIME_UNIT` in the modification statement.

## Privilege requirements

To modify a dynamically partitioned table, you must have the `ALTER` privilege. For more information about privileges in OceanBase Database, see [Privilege types in MySQL-compatible mode](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md).

## Syntax

The SQL statement format for modifying a dynamically partitioned table is as follows:

```sql
ALTER TABLE table_name [SET] DYNAMIC_PARTITION_POLICY [=] (dynamic_partition_policy_list);

dynamic_partition_policy_list:
    dynamic_partition_policy_option [, dynamic_partition_policy_option ...]

dynamic_partition_policy_option:
    ENABLE = {true | false}
    | TIME_UNIT = {'hour' | 'day' | 'week' | 'month' | 'year'}
    | PRECREATE_TIME = {'-1' | '0' | 'n {hour | day | week | month | year}'}
    | EXPIRE_TIME = {'-1' | '0' | 'n {hour | day | week | month | year}'}
```

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p><code>TIME_UNIT</code> is specified when creating the table and cannot be modified afterward: when modifying a table with dynamic partition management enabled, you cannot specify <code>TIME_UNIT</code>; when adding a dynamic partitioning strategy to a table without dynamic partition management enabled, you need to specify <code>TIME_UNIT</code>.</p>
</main>

## Description of dynamic partition management attribute parameters

| **Attribute Name** | **Description** | **Required** | **Modifiable** |
| ------------------ | ---------- | -------------- | ---------------- |
| ENABLE | Specifies whether to enable dynamic partition management. Valid values: <ul><li>`true`: The default value, which indicates that dynamic partition management is enabled.</li><li>`false`: Indicates that dynamic partition management is disabled.</li></ul> | No | Yes |
| TIME_UNIT | The time unit for partitioning, which is the interval at which partition boundaries are automatically created. Valid values: <ul><li>`hour`: Partitions are divided by hour.</li><li>`day`: Partitions are divided by day. </li><li>`week`: Partitions are divided by week (weekday).</li><li>`month`: Partitions are divided by month.</li><li>`year`: Partitions are divided by year.</li></ul>  <main id="notice" type='explain'><h4>Note</h4><p><ul><li>This parameter must be specified when creating a dynamic partitioned table and cannot be modified afterward.</li><li>When modifying a table for which dynamic partition management is already enabled, this parameter is not required and cannot be specified in the modification statement (doing so will cause an error).</li><li>When adding a dynamic partitioning strategy to a table for which dynamic partition management is not yet enabled, this parameter is required.</li><li>For the restrictions on the partitioning key type and the possible values of <code>TIME_UNIT</code>, see <a href="200.create-a-dynamic-partition-table-of-mysql-mode.md">Create a dynamic partitioned table</a>.</li></ul></p></main> | No | No |
| PRECREATE_TIME | Indicates the pre-create time. When scheduling a dynamic partition management task, partitions are pre-created so that **max_partition_upper_bound > now() + precreate_time**. Valid values: <ul><li>`-1`: The default value, indicating that partitions are not pre-created. </li><li>`0`: Indicates that only the current partition is pre-created.</li><li>`n {hour \| day \| week \| month \| year}`: Indicates to pre-create partitions for the specified time span. For example, `3 hour` means to pre-create partitions for the next 3 hours.</li></ul>  <main id="notice" type='explain'><h4>Note</h4><p><ul><li>When you need to pre-create multiple partitions, the interval between partition boundaries is <code>TIME_UNIT</code>.</li><li>The boundary of the first pre-created partition is the existing maximum partition boundary rounded up by <code>TIME_UNIT</code>.</li></ul></p></main> | No | Yes |
| EXPIRE_TIME | Indicates the partition expiration time. When dynamic partition management is scheduled, all partitions that meet the condition **upper_bound < now() - expire_time** are deleted. Valid values: <ul><li>`-1`: The default value, indicating that the partition never expires. </li><li>`0`: Indicates that all partitions except the current one have expired. </li><li>`n {hour \| day \| week \| month \| year}`: The partition expiration time. For example, `1 day` indicates the partition expires in 1 day.</li></ul> | No | Yes |

For more information about the parameters for modifying a table, see [ALTER TABLE](../../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/1600.alter-table-of-mysql-mode.md).

## Examples

1. Create a table:

    ```sql
    CREATE TABLE test_tbl1 (col1 INT, col2 DATETIME)
    DYNAMIC_PARTITION_POLICY(
        ENABLE = true,
        TIME_UNIT = 'hour',
        PRECREATE_TIME = '3 hour',
        EXPIRE_TIME = '1 day',
        TIME_ZONE = '+8:00',
        BIGINT_PRECISION = 'none'
    )
    PARTITION BY RANGE COLUMNS (col2)(
        PARTITION P0 VALUES LESS THAN ('2025-04-15 13:30:00')
    );
    ```

2. View the dynamic partition information of the `test_tbl1` table.

    ```sql
    SELECT * FROM oceanbase.DBA_OB_DYNAMIC_PARTITION_TABLES
    WHERE TABLE_NAME = 'test_tbl1';
    ```

    The query result is as follows:

    ```shell
    +---------------+------------+----------+-----------------------+--------+-----------+----------------+-------------+-----------+------------------+
    | DATABASE_NAME | TABLE_NAME | TABLE_ID | MAX_HIGH_BOUND_VAL    | ENABLE | TIME_UNIT | PRECREATE_TIME | EXPIRE_TIME | TIME_ZONE | BIGINT_PRECISION |
    +---------------+------------+----------+-----------------------+--------+-----------+----------------+-------------+-----------+------------------+
    | test          | test_tbl1  |   500004 | '2025-04-15 13:30:00' | TRUE   | HOUR      | 3HOUR          | 1DAY        | +8:00     | NONE             |
    +---------------+------------+----------+-----------------------+--------+-----------+----------------+-------------+-----------+------------------+
    1 row in set
    ```

3. Modify the dynamic partitioned table `test_tbl1` and set its dynamic partition properties as follows:

   * Pre-create partitions for the next 1 day from the current time.
   * Partitions never expire.

   ```sql
   ALTER TABLE test_tbl1 DYNAMIC_PARTITION_POLICY(
       ENABLE = true,
       PRECREATE_TIME = '1 day',
       EXPIRE_TIME = '-1'
   );
   ```

4. View the dynamic partition information of table `test_tbl1` again.

    ```sql
    SELECT * FROM oceanbase.DBA_OB_DYNAMIC_PARTITION_TABLES
    WHERE TABLE_NAME = 'test_tbl1';
    ```

    The query result is as follows:

    ```shell
    +---------------+------------+----------+-----------------------+--------+-----------+----------------+-------------+-----------+------------------+
    | DATABASE_NAME | TABLE_NAME | TABLE_ID | MAX_HIGH_BOUND_VAL    | ENABLE | TIME_UNIT | PRECREATE_TIME | EXPIRE_TIME | TIME_ZONE | BIGINT_PRECISION |
    +---------------+------------+----------+-----------------------+--------+-----------+----------------+-------------+-----------+------------------+
    | test          | test_tbl1  |   500004 | '2025-04-15 13:30:00' | TRUE   | HOUR      | 1DAY           | -1          | +8:00     | NONE             |
    +---------------+------------+----------+-----------------------+--------+-----------+----------------+-------------+-----------+------------------+
    1 row in set
    ```

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>After modifying dynamic partition management parameters, pre-created partitions and deleted expired partitions do not take effect immediately. You need to wait for the next automatically scheduled dynamic partition management task or manually schedule one. For more details, see <a href="500.dynamic-partition-management-task-of-mysql-mode.md">Dynamic partition management task</a>.</p>
    </main>

5. Add a dynamic partitioning strategy to a regular Range Columns partitioned table that has not enabled dynamic partition management.

   1. Create a regular Range Columns partitioned table named `test_tbl3`.

      ```sql
      CREATE TABLE test_tbl3 (col1 INT, col2 DATETIME)
          PARTITION BY RANGE COLUMNS (col2)(
              PARTITION P0 VALUES LESS THAN ('2026-09-14 00:00:00')
          );
      ```

   2. Add a dynamic partitioning strategy to `test_tbl3` and set its dynamic partition properties as follows:

      * Partition boundaries are divided by day.
      * Pre-create partitions for the next 3 days from the current time.
      * Delete partitions whose upper boundary is earlier than 30 days before the current time.

      ```sql
      ALTER TABLE test_tbl3 DYNAMIC_PARTITION_POLICY(
          ENABLE = true,
          TIME_UNIT = 'day',
          PRECREATE_TIME = '3 day',
          EXPIRE_TIME = '30 day'
      );
      ```

      <main id="notice" type='explain'>
        <h4>Note</h4>
        <p><ul><li>When adding a dynamic partitioning strategy to a table that has not enabled dynamic partition management, you must specify <code>TIME_UNIT</code>.</li><li>When the partitioning key is of a time type, the default value of <code>TIME_ZONE</code> is <code>default</code>, and the default value of <code>BIGINT_PRECISION</code> is <code>none</code>. These can be omitted.</li></ul></p>
      </main>

6. Manually trigger a dynamic partition management task to view the pre-created partitions.

   ```sql
   CALL DBMS_PARTITION.MANAGE_DYNAMIC_PARTITION();
   ```

   View the partition information of table `test_tbl3`:

   ```sql
   SELECT TABLE_NAME, PARTITION_NAME, PARTITION_DESCRIPTION
   FROM information_schema.PARTITIONS
   WHERE TABLE_NAME = 'test_tbl3'
   ORDER BY PARTITION_ORDINAL_POSITION;
   ```

   The query result shows the three pre-created daily partitions.
