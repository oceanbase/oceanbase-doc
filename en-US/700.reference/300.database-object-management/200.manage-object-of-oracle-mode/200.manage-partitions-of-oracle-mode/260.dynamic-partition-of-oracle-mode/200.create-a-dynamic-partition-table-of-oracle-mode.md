# Create a dynamically partitioned table

In OceanBase Database, you can use the `DYNAMIC_PARTITION_POLICY` clause to specify the dynamic partition management attributes of a table during creation.

This topic describes how to create a dynamically partitioned table by using an SQL statement.

## Limitations and considerations

* You must specify at least one partition definition when you create a dynamically partitioned table in the current version.
* The following types of partitioned tables support dynamic partition management:

  * Range-partitioned tables whose partitioning key is of the `date`, `timestamp`, `timestamp with local time zone`, or `number` type (with `BIGINT_PRECISION` precision specified).
  * List-partitioned tables whose partitioning key is a string-type time column. The string partitioning key can be of the `VARCHAR2` or `CHAR` type, and its format is determined by the value of `TIME_UNIT`:

    * When `TIME_UNIT = 'year'`: The string partitioning key is in the `YYYY` format, for example, `2026`.
    * When `TIME_UNIT = 'month'`: The string partitioning key is in the `YYYYMM` format, for example, `202608`.
    * When `TIME_UNIT = 'day'`: The string partitioning key is in the `YYYYMMDD` format, for example, `20260819`.
    * When `TIME_UNIT = 'hour'`: The string partitioning key is in the `YYYYMMDDHH` format, for example, `2026081910`.

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>For V4.4.2, dynamic partition management is supported for list-partitioned tables whose partitioning key is a string-type time column starting from V4.4.2 BP3.</p>
    </main>

* Dynamic partition management can only be enabled for a table's partitions or for the partitions of a subpartitioned table.
* Pre-created partitions and deleted expired partitions after table creation are not executed immediately. You must wait for the next automatic scheduling of a dynamic partition management task or manually schedule one. For more information about scheduling dynamic partition management tasks, see [Dynamic partition management tasks](500.dynamic-partition-management-task-of-oracle-mode.md).

## Privilege requirements

You must have the `CREATE TABLE` privilege to create a dynamically partitioned table. For more information about OceanBase Database privileges, see [Privilege types in Oracle-compatible mode](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/300.permission-of-oracle-mode/000.permission-classification-of-oracle-mode.md).

## Syntax

The SQL statement for creating a dynamically partitioned table is as follows:

```sql
CREATE TABLE [IF NOT EXISTS] table_name (table_definition_list)
    DYNAMIC_PARTITION_POLICY [=] (dynamic_partition_policy_list)
    partition_option;

dynamic_partition_policy_list:
    dynamic_partition_policy_option [, dynamic_partition_policy_option ...]

dynamic_partition_policy_option:
    ENABLE = {true | false}
    | TIME_UNIT = {'hour' | 'day' | 'week' | 'month' | 'year'}
    | PRECREATE_TIME = {'-1' | '0' | 'n {hour | day | week | month | year}'}
    | EXPIRE_TIME = {'-1' | '0' | 'n {hour | day | week | month | year}'}
    | TIME_ZONE = {'default' | 'time_zone'}
    | BIGINT_PRECISION = {'none' | 'us' | 'ms' | 's'}
```

### Restrictions on dynamic partition parameters

* `PRECREATE_TIME`: Up to 2,048 partitions can be pre-created.
* `TIME_ZONE`: The `TIME_ZONE` parameter can specify a custom time zone offset only when the partitioning key is of the `date` or `timestamp` type. For other types, the value can only be `default`.
* `BIGINT_PRECISION`: This parameter can be set to `us`, `ms`, or `s` only when the partitioning key is of the `number` type. For other types, the value can only be `none`.
* The values of `TIME_UNIT`, `TIME_ZONE`, and `BIGINT_PRECISION` cannot be modified after they are specified.

## Examples

### Range partitioning example

Create a dynamically partitioned table named `test_tbl1` with RANGE partitioning. Set the dynamic partitioning properties as follows:

* Partitions are divided by hour.
* Pre-create partitions for the next 3 hours from the current time.
* Delete partitions whose upper boundary is earlier than 1 day before the current time.
* Use Beijing Time (UTC+8) to determine time, ensuring that partition boundaries and expiration logic are based on this time zone.
* The partitioning key `col2` is of the `TIMESTAMP` type, so there is no need to configure timestamp precision for `number`.

```sql
CREATE TABLE test_tbl1 (col1 INT, col2 TIMESTAMP)
    DYNAMIC_PARTITION_POLICY(
        ENABLE = true,
        TIME_UNIT = 'hour',
        PRECREATE_TIME = '3 hour',
        EXPIRE_TIME = '1 day',
        TIME_ZONE = '+8:00',
        BIGINT_PRECISION = 'none')
    PARTITION BY RANGE (col2)(
        PARTITION P0 VALUES LESS THAN (TIMESTAMP '2024-11-11 13:30:00')
        );
```

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>The actions of pre-creating partitions and deleting expired partitions after the table is created are not executed immediately. You must wait for the next automatic scheduling of a dynamic partition management task or manually schedule one. For more information, see <a href="500.dynamic-partition-management-task-of-oracle-mode.md">Dynamic partition management task</a>.</p>
</main>

### List partitioning example

Create a dynamically partitioned table named `test_tbl2` with LIST partitioning. The partitioning key is a string time column in the format `YYYYMMDD`. Set the dynamic partitioning properties as follows:

* Partitions are automatically created at daily intervals.
* Partitions are divided by day.
* Pre-create partitions for the next 3 days from the current time.
* Delete partitions whose upper boundary is earlier than 30 days before the current time.
* Use Beijing Time (UTC+8) to determine time, ensuring that partition boundaries and expiration logic are based on this time zone.
* The partitioning key `col2` is of the `VARCHAR2` type, so there is no need to configure timestamp precision for `bigint`.

```shell
obclient> CREATE TABLE test_tbl2 (col1 INT, col2 VARCHAR2(20))
    DYNAMIC_PARTITION_POLICY(
        ENABLE = true,
        TIME_UNIT = 'day',
        PRECREATE_TIME = '3 day',
        EXPIRE_TIME = '30 day',
        TIME_ZONE = '+8:00',
        BIGINT_PRECISION = 'none'
    )
    PARTITION BY LIST (col2) (
        PARTITION p_20260801 VALUES ('20260801')
    );
```
