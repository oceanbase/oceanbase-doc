# Partition exchange

The partition exchange feature of OceanBase Database is mainly used to quickly import data into partitioned tables and achieve efficient data loading. It involves using full direct load to quickly import data into a non-partitioned table and then using the partition exchange feature to quickly import data from the non-partitioned table to the partitioned table, thereby accelerating the import of incremental data to existing partitioned tables.

We recommend that you use the partition exchange feature as an alternative to incremental direct load. For example, to import incremental data of a partitioned table A, perform the following steps:

1. Create an empty new partition P on table A.
2. Create a non-partitioned table B that has the same schema as table A, and import the incremental data to table B through direct load.
3. Use the partition exchange feature to exchange the new partition P of table A with table B.

## Limitations and considerations

* Only RANGE partitioning is supported:

  * If you exchange a partition, the partition must be a RANGE partition.
  * For a subpartitioned table, if you exchange a subpartition, no requirements are imposed on the partition type, but the subpartition must be a RANGE partition.

* Data integrity check is not supported. You must specify `WITHOUT VALIDATION`. You are responsible for ensuring the integrity of data to be exchanged.
* The table-level and column-level attributes of the partitioned table and non-partitioned table must exactly match.
* The constraints of the partitioned table and non-partitioned table must be the same. Foreign key constraints are not supported between the two tables.
* The local indexes of the partitioned table must exactly match the indexes of the non-partitioned table.
* Only `INCLUDING INDEXES` is supported (you must specify `INCLUDING INDEXES` in Oracle compatible mode). Data of local indexes are exchanged as well, and the local indexes remain available after the exchange.
* `UPDATE GLOBAL INDEXES` is not supported. Therefore, global indexes are unusable (invalid) after the exchange.
* The current partition exchange feature is recommended as a temporary replacement for incremental direct load. For more information, see [Overview](../../../../620.obap/300.obap-import-data/20.bypass-import/100.overview-of-bypass-import.md).

## Syntax

```sql
ALTER TABLE partition_table_name
    EXCHANGE PARTITION partition_name
    WITH TABLE non_partition_table_name
    INCLUDING INDEXES
    WITHOUT VALIDATION;
```

## Parameters

|        **Parameter**          |    **Description**   |
|--------------------------|---------------|
| partition_table_name     | The name of the partitioned table. |
| partition_name           | The name of the partition. |
| non_partition_table_name | The name of the non-partitioned table. |

## Usage

The partition exchange feature allows you to exchange data between a partition of a partitioned table and a non-partitioned table. This feature is intended as a temporary replacement for the incremental direct load feature. The following table describes the general characteristics of a partitioned table and a non-partitioned table:

* Partitioned table: a partitioned table that contains historical data. Such tables usually have a large data volume.
* Non-partitioned table: a table that contains incremental data.

To use the partition exchange feature, you must proceed with caution. Otherwise, data may no longer meet the partitioning key conditions of the original table, triggering a chain of errors. Therefore, before you exchange a partition between a partitioned table and a non-partitioned table, make sure that the two tables meet the following criteria.

1. Use the `SHOW CREATE TABLE` statement to query the partitioning key and target partition information of the partitioned table. Check whether the data in the non-partitioned table falls within the partitioning key range of the target partition.

    Here is the sample statement:

    ```sql
    SHOW CREATE TABLE table_name;
    ```

2. Make sure that the partitioned table and non-partitioned table meet the requirements specified in [Limitations and considerations](#usage_limitations_and_considerations).

3. Make sure that the following conditions are met before you perform a partition exchange.

    |             Attribute              | Requirement |
    |-------------------------------|-----|
    | In the same tenant?                | Yes |
    | In the same schema?          | Yes |
    | In the same table group (TableGroup)?      | Yes |
    | In the same table space (TableSpace)?    | Yes |
    | Using the same character set?         | Yes |
    | Table type?              | Yes, and both tables must be user tables, that is, `USER_TABLE`. |
    | Number of primary keys?                | Yes |
    | Row storage format?              | Yes |
    | Column format and relative column order?      | Yes |
    | Auto-increment columns?                  | Yes |
    | Default values and generation expressions for columns? | Yes |
    | Encryption methods?                | Yes |
    | Column storage formats?                | Yes |
    | Index formats, states, and quantities?     | Yes, the local indexes of the partitioned table must correspond to the indexes of the non-partitioned table. |
    | Index table names?                | No |
    | Constraint formats and included columns?       | Yes |

4. Execute the partition exchange statement to exchange partitions between the partitioned table and the non-partitioned table. After the exchange, the data in the specified partition of the partitioned table is moved to the non-partitioned table, and the data in the non-partitioned table is moved to the specified partition of the partitioned table. The global index of the partitioned table is unusable after the exchange.

## Example

1. Create a partitioned table named `tbl1_r`.

    ```sql
    CREATE TABLE tbl1_r (col1 INT PRIMARY KEY, col2 VARCHAR2(50))
        PARTITION BY RANGE(col1)
            (PARTITION p0 VALUES LESS THAN(10),
            PARTITION p1 VALUES LESS THAN(20),
            PARTITION p2 VALUES LESS THAN(30)
            );
    ```

2. Create a non-partitioned table named `tbl1`.

    ```sql
    CREATE TABLE tbl1 (col1 INT PRIMARY KEY, col2 VARCHAR2(50));
    ```

3. Insert data into the `tbl1` table.

    ```sql
    INSERT INTO tbl1 VALUES(1, 'a1'),(2, 'a2');
    ```

    The return result is as follows:

    ```shell
    Query OK, 2 rows affected
    Records: 2  Duplicates: 0  Warnings: 0
    ```

4. Exchange partition `p0` of partitioned table `tbl1_r` with non-partitioned table `tbl1`.

    ```sql
    ALTER TABLE tbl1_r
        EXCHANGE PARTITION p0
        WITH TABLE tbl1
        INCLUDING INDEXES
        WITHOUT VALIDATION;
    ```

5. View the data in the `p0` partition of the `tbl1_r` partitioned table.

    ```sql
    SELECT * FROM tbl1_r PARTITION(p0);
    ```

    The return result is as follows:

    ```shell
    +------+------+
    | COL1 | COL2 |
    +------+------+
    |    1 | a1   |
    |    2 | a2   |
    +------+------+
    2 rows in set
    ```
