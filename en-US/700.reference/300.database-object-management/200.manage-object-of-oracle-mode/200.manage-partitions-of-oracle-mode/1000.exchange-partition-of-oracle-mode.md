# Partition exchange

The partition exchange feature of OceanBase Database is primarily used to quickly import data into a partitioned table, achieving efficient data loading. This involves using a full direct load to import data into a newly created non-partitioned table and then leveraging the partition exchange feature to rapidly transfer the data from the non-partitioned table into the partitioned table, thereby enhancing the performance of incremental data imports into existing partitioned tables.

It is recommended to use the partition exchange feature as an alternative to incremental direct load. For example, to import incremental data into partitioned table A using the partition exchange feature, follow these steps:

1. Create an empty new partition P on table A.
2. Create a non-partitioned table B with the same structure as table A and use direct load to import the incremental data into table B.
3. Use the partition exchange feature to swap the new partition P from table A with table B.

## Partition exchange support

Partition exchange support is described in the table below. The column `target_partition_table_name` specifies the type of the target table, and the row `origin_table_name` specifies the type of the source table.

|         Type       | Non-partitioned table | Partitioned table | Subpartitioned table |
|--------------------|---------|-----------|-----------|
| Partitioned table          | Supported    | Not supported     | Not supported    |
| Subpartition of a subpartitioned table | Not supported  | Supported       | Not supported    |
| Subpartition of a subpartitioned table | Supported    | Not supported     | Not supported    |

## Limitations and considerations

* Data validation is not supported. Therefore, you must specify `WITHOUT VALIDATION` to guarantee the validity of the exchanged data.
* The partition level and column level attributes of a partitioned table must correspond to those of a non-partitioned table.
* The constraint requirements of partitioned tables and non-partitioned tables are identical. In addition, this version of the database does not support foreign key constraints between partitioned and non-partitioned tables.
* The local index table of a partitioned table and the index table of a non-partitioned table must correspond to each other.
* Only the `INCLUDING INDEXES` option is supported (in Oracle mode, you must explicitly specify this option). When you enable the `INCLUDING INDEXES` option, the local index that corresponds to the data in a partition is exchanged with the index of the non-partitioned table. After the exchange, the local index remains available.
* The `UPDATE GLOBAL INDEXES` option is not supported. Therefore, the global index becomes unusable after partition exchange is performed.
* The current partition exchange feature is suitable only as a temporary replacement for incremental direct load operations. For more information about incremental direct load, see [Overview](../../../../620.obap/300.obap-import-data/20.bypass-import/100.overview-of-bypass-import.md).
* When you exchange data between a partitioned table and a non-partitioned table:

  * The partitioned table must be a partitioned by range or by list.

* When you exchange data between a subpartition of a subpartitioned table and a non-partitioned table:

  * The partitioned table can be partitioned by any type, but the subpartition must be partitioned by range.

* When you exchange data between a partition of a subpartitioned table and a partitioned table:

  * `target_partition_table_name` must be a subpartitioned table, and the partition to be exchanged must be a partition of this table. In addition, the partition must be partitioned by range or by list.
  * `origin_table_name` must be a partitioned table. In addition, the partitions of the partitioned table must be the same as the partitions of the partitioned table used for exchange.
  * The statistics of the related tables become invalid after the exchange. Therefore, you must collect the statistics again.

## Syntax

```sql
ALTER TABLE target_partition_table_name
    EXCHANGE {PARTITION partition_name
             | SUBPARTITION subpartition_name}
    WITH TABLE origin_table_name
    INCLUDING INDEXES
    WITHOUT VALIDATION;
```

## Parameter description

|           **Parameter**             |    **Description**   |
|--------------------------------|---------------|
| target_partition_table_name    | The name of the target partition table.|
| PARTITION partition_name       | The name of the target partition in a partition table.|
| SUBPARTITION subpartition_name | The name of the target subpartition in a subpartitioned table.|
| origin_table_name              | The name of the source table, which is a non-partitioned table or a partitioned table. |

## Procedure

Partition exchange is a temporary solution for incremental direct load. This feature exchanges a partition of a partitioned table with a non-partitioned table. Before you use the partition exchange feature, be aware of the following limitations and considerations: 

* A partitioned table contains historical data and is usually large.
* A non-partitioned table contains incremental data.

Because a wrong operation may result in a cascade error by changing the partitioning key of the original table, take the following steps before you perform a partition exchange to determine whether the partitioned table and non-partitioned table can be exchanged. 

1. Use the `SHOW CREATE TABLE` statement to query the partition key and partition information of the partitioned table. Query the data of the non-partitioned table to determine whether the data in the non-partitioned table meets the data range requirements of the partition key of the target partition. 

    Here, `table_name` specifies the name of the table to be queried. 

    ```sql
    SHOW CREATE TABLE table_name;
    ```

2. Make sure that the partitioned table and non-partitioned table meet the requirements in the section [Limitations and considerations](#limitation). 

3. Before you perform a partition exchange, make sure that the following conditions are met. 

    |             Property              | Required |
    |-------------------------------|-----|
    | Whether the two tables are in the same tenant                | Yes |
    | Whether the two tables are in the same schema         | Yes |
    | Whether the two tables are in the same table group (TableGroup)     | Yes |
    | Whether the two tables are in the same table space (TableSpace)    | Yes |
    | Whether the two tables use the same character set      | Yes |
    | Whether the table type of the two tables is the same  | Yes. Both tables must be user tables (`USER_TABLE`)|. |
    | Whether the number of primary keys in the two tables is the same  | Yes |
    | Whether the two tables use the same row store format     | Yes |
    | Whether the column format and column order in the two tables are the same  | Yes |
    | Whether the two tables contain auto-increment columns  | Yes |
    | Whether the default values and expressions for columns in the two tables are the same | Yes |
    | Whether the encryption schemes for the two tables are the same   | Yes |
    | Whether the columnar storage formats of the two tables are the same    | Yes |
    | Whether the index formats, states, and quantities are the same in the two tables    | Yes. The local indexes of the partitioned table must correspond to the indexes of the non-partitioned table. |
    | Whether the index names are the same in the two tables    | No |
    | Whether the constraints and included columns in the two tables are the same    | Yes |

4. Perform a partition exchange. After the exchange, the data in the specified partition of the partitioned table is migrated to the non-partitioned table, and the data in the non-partitioned table is migrated to the specified partition of the partitioned table. The global indexes of the partitioned table are unusable.

## Examples

### Example 1: Exchange data between a partitioned table and a non-partitioned table

* Exchange data between a RANGE partitioned table and a non-partitioned table.

  1. Create a RANGE partitioned table named `tbl1_r`.

      ```shell
      obclient> CREATE TABLE tbl1_r (col1 INT PRIMARY KEY, col2 VARCHAR2(50))
          PARTITION BY RANGE(col1) 
              (PARTITION p0 VALUES LESS THAN(10),
              PARTITION p1 VALUES LESS THAN(20),
              PARTITION p2 VALUES LESS THAN(30)
              );
      ```

  2. Create a non-partitioned table named `tbl1`.

      ```shell
      obclient> CREATE TABLE tbl1 (col1 INT PRIMARY KEY, col2 VARCHAR2(50));
      ```

  3. Insert data into the `tbl1` table.

      ```shell
      obclient> INSERT INTO tbl1 VALUES(1, 'a1'),(2, 'a2');
      ```

      The return result is as follows:

      ```shell
      Query OK, 2 rows affected
      Records: 2  Duplicates: 0  Warnings: 0
      ```

  4. Exchange the `p0` partition of the partitioned table `tbl1_r` with the non-partitioned table `tbl1`.

      ```shell
      obclient> ALTER TABLE tbl1_r
          EXCHANGE PARTITION p0
          WITH TABLE tbl1
          INCLUDING INDEXES
          WITHOUT VALIDATION;
      ```

  5. Query the data in the `p0` partition of the partitioned table `tbl1_r`.

      ```shell
      obclient> SELECT * FROM tbl1_r PARTITION(p0);
      ```

      The return result is as follows:

      ```shell
      +------+------+
      | COL1 | COL2 |
      +------+------+
      |    1 | a1   |
      |    2 | a2   |
      +------+------+
      2 rows in set
      ```

* Exchange data between a LIST partitioned table and a non-partitioned table.

  1. Create a LIST partitioned table named `tbl1_l`.

      ```shell
      obclient> CREATE TABLE tbl1_l (col1 INT, col2 VARCHAR(50), col3 INT)
          PARTITION BY LIST(col3) 
              (PARTITION p0 VALUES (1, 2, 3, 4),
              PARTITION p1 VALUES (5, 6, 7, 8, 9),
              PARTITION p2 VALUES (DEFAULT)
              );
      ```

  2. Create a non-partitioned table named `tbl1_2`.

      ```shell
      obclient> CREATE TABLE tbl1_2 (col1 INT, col2 VARCHAR(50), col3 INT);
      ```

  3. Insert data into the `tbl1_2` table.

      ```shell
      obclient> INSERT INTO tbl1_2 VALUES(1, 'a1', 1),
          (2, 'a2', 2),
          (3, 'a3', 3),
          (4, 'a4', 4),
          (5, 'a5', 5);
      ```

      The return result is as follows:

      ```shell
      Query OK, 5 rows affected
      Records: 5  Duplicates: 0  Warnings: 0
      ```

  4. Exchange the `p0` partition of the partitioned table `tbl1_l` with the non-partitioned table `tbl1_2`.

      ```shell
      obclient> ALTER TABLE tbl1_l
          EXCHANGE PARTITION p0
          WITH TABLE tbl1_2
          INCLUDING INDEXES
          WITHOUT VALIDATION;
      ```

  5. Query the data in the `p0` partition of the partitioned table `tbl1_l`.

      ```shell
      obclient> SELECT * FROM tbl1_l PARTITION(p0);
      ```

      The return result is as follows:

      ```shell
      +------+------+------+
      | COL1 | COL2 | COL3 |
      +------+------+------+
      |    1 | a1   |    1 |
      |    2 | a2   |    2 |
      |    3 | a3   |    3 |
      |    4 | a4   |    4 |
      |    5 | a5   |    5 |
      +------+------+------+
      5 rows in set
      ```

### Example 2: Exchange data between a subpartition of a composite partitioned table and a partitioned table

1. Create a RANGE + HASH composite partitioned table named `tbl2_rh`.

    ```shell
    obclient> CREATE TABLE tbl2_rh (col1 INT PRIMARY KEY, col2 INT)
        PARTITION BY RANGE(col1)
        SUBPARTITION BY HASH(col1) SUBPARTITIONS 5
            (PARTITION p0 VALUES LESS THAN (10),
            PARTITION p1 VALUES LESS THAN (20),
            PARTITION p2 VALUES LESS THAN (30),
            PARTITION p3 VALUES LESS THAN (MAXVALUE)
            );
    ```

2. Create a HASH partitioned table named `tbl2_h`.

    ```shell
    obclient> CREATE TABLE tbl2_h (col1 INT PRIMARY KEY, col2 INT)
        PARTITION BY HASH(col1) PARTITIONS 5;
    ```

3. Insert data into the `tbl2_rh` table.

    ```shell
    obclient> INSERT INTO tbl2_rh VALUES(11, 30), (14, 40), (26, 150), (29, 160);
    ```

    The return result is as follows:

    ```shell
    Query OK, 4 rows affected
    Records: 4  Duplicates: 0  Warnings: 0
    ```

4. Query the data in the `p1` partition of the partitioned table `tbl2_rh`.

    ```shell
    obclient> SELECT * FROM tbl2_rh PARTITION(p1);
    ```

    The return result is as follows:

    ```shell
    +------+------+
    | COL1 | COL2 |
    +------+------+
    |   11 |   30 |
    |   14 |   40 |
    +------+------+
    2 rows in set
    ```

5. Insert data into the `tbl2_h` table.

    ```shell
    obclient> INSERT INTO tbl2_h VALUES(12, 20), (16, 110), (17, 170), (19, 120);
    ```

    The return result is as follows:

    ```shell
    Query OK, 4 rows affected
    Records: 4  Duplicates: 0  Warnings: 0
    ```

6. Exchange the `p1` partition of the composite partitioned table `tbl2_rh` with the partitioned table `tbl2_h`.

    ```shell
    obclient> ALTER TABLE tbl2_rh
        EXCHANGE PARTITION p1
        WITH TABLE tbl2_h
        INCLUDING INDEXES
        WITHOUT VALIDATION;
    ```

7. Query the data in the `p1` partition of the partitioned table `tbl2_rh`.

    ```shell
    obclient> SELECT * FROM tbl2_rh PARTITION(p1);
    ```

    The return result is as follows:

    ```shell
    +------+------+
    | COL1 | COL2 |
    +------+------+
    |   19 |  120 |
    |   12 |   20 |
    |   16 |  110 |
    |   17 |  170 |
    +------+------+
    4 rows in set
    ```

### Example 3: Exchange data between a subpartition of a composite partitioned table and a non-partitioned table

1. Create a RANGE + RANGE composite partitioned table named `tbl3_rr`.

    ```shell
    obclient> CREATE TABLE tbl3_rr(col1 INT, col2 INT)
        PARTITION BY RANGE(col1)
        SUBPARTITION BY RANGE(col2)
            (PARTITION p0 VALUES LESS THAN(10)
            (SUBPARTITION sp0 VALUES LESS THAN(20),
            SUBPARTITION sp1 VALUES LESS THAN(50),
            SUBPARTITION sp2 VALUES LESS THAN (MAXVALUE)
            ),
            PARTITION p1 VALUES LESS THAN(20)
            (SUBPARTITION sp3 VALUES LESS THAN(20),
            SUBPARTITION sp4 VALUES LESS THAN(50),
            SUBPARTITION sp5 VALUES LESS THAN (MAXVALUE)
            )
            );
    ```

2. Create a non-partitioned table named `tbl3`.

    ```shell
    obclient> CREATE TABLE tbl3 (col1 INT, col2 INT);
    ```

3. Insert data into the `tbl3_rr` table.

    ```shell
    obclient> INSERT INTO tbl3_rr VALUES(1, 30), (4, 40), (16, 150), (19, 160);
    ```

    The return result is as follows:

    ```shell
    Query OK, 4 rows affected
    Records: 4  Duplicates: 0  Warnings: 0
    ```

4. Query the data in the `sp1` subpartition of the partitioned table `tbl3_rr`.

    ```shell
    obclient> SELECT * FROM tbl3_rr PARTITION(sp1);
    ```

    The return result is as follows:

    ```shell
    +------+------+
    | COL1 | COL2 |
    +------+------+
    |    1 |   30 |
    |    4 |   40 |
    +------+------+
    2 rows in set
    ```

5. Insert data into the `tbl3` table.

    ```shell
    obclient> INSERT INTO tbl3 VALUES(2, 21), (6, 30), (7, 35), (9, 40);
    ```

    The return result is as follows:

    ```shell
    Query OK, 4 rows affected
    Records: 4  Duplicates: 0  Warnings: 0
    ```

6. Exchange the `sp1` subpartition of the partitioned table `tbl3_rr` with the non-partitioned table `tbl3`.

    ```shell
    obclient> ALTER TABLE tbl3_rr
        EXCHANGE SUBPARTITION sp1
        WITH TABLE tbl3
        INCLUDING INDEXES
        WITHOUT VALIDATION;
    ```

7. Query the data in the `sp1` subpartition of the partitioned table `tbl3_rr`.

    ```shell
    obclient> SELECT * FROM tbl3_rr PARTITION(sp1);
    ```

    The return result is as follows:

    ```shell
    +------+------+
    | COL1 | COL2 |
    +------+------+
    |    2 |   21 |
    |    6 |   30 |
    |    7 |   35 |
    |    9 |   40 |
    +------+------+
    4 rows in set
    ```
