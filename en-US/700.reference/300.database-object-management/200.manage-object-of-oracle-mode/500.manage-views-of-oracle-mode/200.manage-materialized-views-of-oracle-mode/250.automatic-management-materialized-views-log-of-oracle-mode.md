# Automatic management of materialized view logs

OceanBase Database supports automatic management of materialized view logs (MLOGs). This feature includes the following two aspects:

1. When a materialized view is created, the system analyzes the dependencies of the materialized view on the base table and automatically creates the required MLOGs.
2. The system periodically prunes MLOGs in the background, removing those that are no longer referenced and optimizing the column sets within MLOGs to reduce maintenance costs.

## Limitations

When you create a materialized view, an mlog is automatically created only if the materialized view is explicitly declared as an incrementally refreshed materialized view (by specifying `REFRESH FAST`) or a real-time materialized view (by specifying `ENABLE ON QUERY COMPUTATION`).

## Considerations

* When you update the definition of an mlog, OceanBase Database creates a new mlog table and replaces the original mlog. During the replacement, the incremental data in the original mlog is refreshed into the associated incrementally refreshed materialized views. Therefore, when you update the definition of an mlog, you must refresh all associated incrementally refreshed materialized views. If a base table is associated with a large number of materialized views and contains a large amount of incremental data, updating the definition of an mlog may be a time-consuming operation.

* We recommend that you do not set the value of `mlog_trim_interval` to a very small value. Otherwise, the mlog may be incorrectly trimmed, and you may have to recreate or update the mlog when you create a materialized view.

## Related configurations

OceanBase Database provides two configurations to control the automatic behavior of mlogs:

* [enable_mlog_auto_maintenance](../../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2670.enable_mlog_auto_maintenance.md): specifies whether to enable the automatic management of materialized view logs.
* [mlog_trim_interval](../../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/5650.mlog_trim_interval.md): specifies the scheduling cycle of the background automatic trimming task of mlogs.

## Examples

Enable mlog auto-maintenance.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>In OceanBase Database V4.4.2: <ul><li>For a newly created tenant, the default value of the <code>enable_mlog_auto_maintenance</code> parameter is <code>True</code>, which means that the mlog auto-maintenance feature is enabled by default. </li><li>For a tenant upgraded from a previous version of OceanBase Database (V4.4.2 or earlier), the default value of the <code>enable_mlog_auto_maintenance</code> parameter is <code>False</code>, which means that the mlog auto-maintenance feature is disabled by default. </li></ul></p>
</main>

```shell
obclient> ALTER SYSTEM SET enable_mlog_auto_maintenance = True;
```

### Example 1: Automatically create an mlog

1. Create a table named `test_tbl1`.

    ```shell
    obclient> CREATE TABLE test_tbl1(col1 INT, col2 INT, col3 INT);
    ```

2. Create an incremental refresh materialized view named `mv_test_tbl1` on the `test_tbl1` table. OceanBase Database automatically creates an mlog for the `test_tbl1` table on the required `col2` column.

    ```shell
    obclient> CREATE MATERIALIZED VIEW mv_test_tbl1
        REFRESH FAST
        AS SELECT
               col2,
               count(*) cnt
           FROM test_tbl1
           GROUP BY col2;
    ```

3. Query the information about the materialized view logs on the `test_tbl1` table. The query result is as follows:

    ```shell
    obclient> DESC mlog$_test_tbl1;
    ```

    The query result is as follows:

    ```shell
    +------------+-----------------+------+------+---------+-------+
    | FIELD      | TYPE            | NULL | KEY  | DEFAULT | EXTRA |
    +------------+-----------------+------+------+---------+-------+
    | COL2       | NUMBER(38)      | YES  | NULL | NULL    | NULL  |
    | SEQUENCE$$ | BIGINT(20)      | NO   | PRI  | NULL    | NULL  |
    | DMLTYPE$$  | VARCHAR2(1 )    | YES  | NULL | NULL    | NULL  |
    | OLD_NEW$$  | VARCHAR2(1 )    | YES  | NULL | NULL    | NULL  |
    | M_ROW$$    | BIGINT UNSIGNED | NO   | PRI  | NULL    | NULL  |
    +------------+-----------------+------+------+---------+-------+
    5 rows in set
    ```


3. Query the information about the materialized view logs on the `test_tbl2` table. The query result is as follows:

    ```shell

    ```

    The query result is as follows:

    ```shell
    +------------+-----------------+------+------+---------+-------+
    ```

### Example 3: Automatically prune an mlog

1. Create a table named `test_tbl3`.

    ```shell
    obclient> CREATE TABLE test_tbl3(col1 INT, col2 INT, col3 INT);
    ```

2. Create an incremental refresh materialized view named `mv1_test_tbl3` on the `test_tbl3` table. OceanBase Database automatically creates an mlog for the `test_tbl3` table on the required `col2` column. The query result is as follows:

    ```shell
               col2,
               count(*) cnt
           FROM test_tbl3
           GROUP BY col2;
    ```

3. Create an incremental refresh materialized view named `mv2_test_tbl3` on the `test_tbl3` table. OceanBase Database detects that the current mlog table contains only the `col2` column and updates the mlog definition to add the `col3` column to the mlog table. The query result is as follows:

    ```shell
    obclient> CREATE MATERIALIZED VIEW mv2_test_tbl3
        REFRESH FAST
        AS SELECT
            col3,
            count(*) cnt
        FROM test_tbl3
        GROUP BY col3;
    ```

4. Query the information about the materialized view logs on the `test_tbl3` table. The query result is as follows:

    ```shell
    obclient> DESC mlog$_test_tbl3;
    ```

    The query result is as follows:

    ```shell
    +------------+-----------------+------+------+---------+-------+
    | FIELD      | TYPE            | NULL | KEY  | DEFAULT | EXTRA |
    +------------+-----------------+------+------+---------+-------+
    | COL2       | NUMBER(38)      | YES  | NULL | NULL    | NULL  |
    | COL3       | NUMBER(38)      | YES  | NULL | NULL    | NULL  |
    | SEQUENCE$$ | BIGINT(20)      | NO   | PRI  | NULL    | NULL  |
    | DMLTYPE$$  | VARCHAR2(1 )    | YES  | NULL | NULL    | NULL  |
    | OLD_NEW$$  | VARCHAR2(1 )    | YES  | NULL | NULL    | NULL  |
    | M_ROW$$    | BIGINT UNSIGNED | NO   | PRI  | NULL    | NULL  |
    +------------+-----------------+------+------+---------+-------+
    6 rows in set
    ```

5. Change the mlog pruning interval to observe the pruning result faster. The query result is as follows:

    ```shell
    obclient> ALTER SYSTEM SET mlog_trim_interval = '5s';
    ```

6. Drop the `mv1_test_tbl3` materialized view. The query result is as follows:

    ```shell
    obclient> DROP MATERIALIZED VIEW mv1_test_tbl3;
    ```

7. Wait for 5 seconds and query the information about the materialized view logs on the `test_tbl3` table. The query result is as follows:

    ```shell
    obclient> DESC mlog$_test_tbl3;
    ```

    The query result is as follows:

    ```shell
    +------------+-----------------+------+------+---------+-------+
    | FIELD      | TYPE            | NULL | KEY  | DEFAULT | EXTRA |
    +------------+-----------------+------+------+---------+-------+
    | COL3       | NUMBER(38)      | YES  | NULL | NULL    | NULL  |
    | SEQUENCE$$ | BIGINT(20)      | NO   | PRI  | NULL    | NULL  |
    | DMLTYPE$$  | VARCHAR2(1 )    | YES  | NULL | NULL    | NULL  |
    | OLD_NEW$$  | VARCHAR2(1 )    | YES  | NULL | NULL    | NULL  |
    | M_ROW$$    | BIGINT UNSIGNED | NO   | PRI  | NULL    | NULL  |
    +------------+-----------------+------+------+---------+-------+
    5 rows in set
    ```

8. Drop the `mv2_test_tbl3` materialized view. The query result is as follows:

    ```shell
    obclient> DROP MATERIALIZED VIEW mv2_test_tbl3;
    ```

9. Wait for 5 seconds and query the information about the materialized view logs on the `test_tbl3` table. The query result is as follows:

    ```shell
    obclient> DESC mlog$_test_tbl3;
    ```

    The query result is as follows:

    ```shell
    OBE-04043: object TEST_USER001.MLOG$_TEST_TBL3 does not exist
    ```

10. Restore the mlog pruning interval. The query result is as follows:

    ```shell
    obclient> ALTER SYSTEM SET mlog_trim_interval = '1d';
    ```
