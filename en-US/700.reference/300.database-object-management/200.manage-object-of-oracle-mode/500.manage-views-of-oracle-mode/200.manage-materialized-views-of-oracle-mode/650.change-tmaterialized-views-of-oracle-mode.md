# Modify the attributes of a materialized view

This topic describes how to execute the SQL statement to modify the attributes of a materialized view.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>In OceanBase Database V4.3.5, the ability to modify the attributes of materialized views was introduced in V4.3.5 BP1. </p>
</main>

## Privilege requirements

To modify a materialized view, the current user must have the `ALTER` privilege on the target object. For more information about privileges in OceanBase Database, see [Privilege types in Oracle mode](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/300.permission-of-oracle-mode/000.permission-classification-of-oracle-mode.md).

## Syntax

The syntax for modifying a materialized view is as follows:

```sql
ALTER MATERIALIZED VIEW [schema.]view_name alter_mview_action_list;

alter_mview_action_list:
    alter_mview_action [, alter_mview_action ...]

alter_mview_action:
    parallel_clause
    | REFRESH [[START WITH expr] [NEXT expr]]

parallel_clause:
    NOPARALLEL
    | PARALLEL integer
```

## Parameters

* `schema.`: the schema where the materialized view resides. It is an optional parameter. If you specify `schema.`, you must specify the schema name. If you omit `schema.`, the default schema in the current session is used.
* `view_name`: the name of the materialized view to be modified.
* `alter_mview_action_list`: the list of actions by which you want to modify the materialized view. You can specify multiple actions at a time, separated by commas (`,`).

For more information about the parameters, see [ALTER MATERIALIZED VIEW](../../../../500.sql-reference/100.sql-syntax/300.common-tenant-of-oracle-mode/900.sql-statement-of-oracle-mode/100.ddl-of-oracle-mode/250.alter-materialized-view-of-oracle-mode-in-sql.md).

## Examples

1. Create a table named `test_tbl1`.

    ```sql
    CREATE TABLE test_tbl1 (col1 NUMBER PRIMARY KEY, col2 VARCHAR2(20), col3 NUMBER, col4 BLOB);
    ```

2. Create a materialized view named `mv_test_tbl1`.

    ```sql
    CREATE MATERIALIZED VIEW mv_test_tbl1
        AS SELECT col1, col2, col3
           FROM test_tbl1;
    ```

3. Set the degree of parallelism of the `mv_test_tbl1` materialized view to 5.

    ```sql
    ALTER MATERIALIZED VIEW mv_test_tbl1 PARALLEL 5;
    ```

4. Set the refresh schedule of the `mv_test_tbl1` materialized view so that the initial refresh time is the current date and the materialized view is refreshed every day thereafter.

    ```sql
    ALTER MATERIALIZED VIEW mv_test_tbl1
        REFRESH START WITH current_date NEXT current_date + 1;
    ```
