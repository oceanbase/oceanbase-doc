# Create a materialized view

This topic describes how to create a materialized view by using SQL statements. 

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>OceanBase Database does not support directly modifying the properties of a materialized view, such as the update time and refresh strategy. In this case, you can delete and recreate the materialized view to achieve the desired modifications. </p>
</main>

## Privilege requirements

To create a materialized view, you must have the `CREATE TABLE` privilege. For more information about the privileges of OceanBase Database, see [Privilege classification in Oracle mode](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/300.permission-of-oracle-mode/000.permission-classification-of-oracle-mode.md).

## Syntax

The syntax of the CREATE MATERIALIZED VIEW statement is as follows:

```sql
CREATE MATERIALIZED VIEW view_name [([column_list] [PRIMARY KEY(column_list)])]
    [table_option_list]
    [partition_option]
    [mv_column_group_option]
    [refresh_clause [query_rewrite_clause] [on_query_computation_clause]]
    AS view_select_stmt; 
```

**Parameters:**

* `view_name`: the name of the materialized view to be created.
* `column_list`: optional. The list of columns in the materialized view. If you want to specify the names of the view columns, you can use the `column_list` clause and separate the column names with commas.
* `PRIMARY KEY(column_list)`: optional. The primary key of the materialized view.
* `table_option_list`: optional. The table options of the materialized view.
* `partition_option`: optional. The partition options of the materialized view.
* `mv_column_group_option`: optional. The storage format of the materialized view. If not specified, the default is to create a row-based materialized view.
* `refresh_clause [query_rewrite_clause] [on_query_computation_clause]`: optional. The details are as follows:

  * `refresh_clause`: the refresh method of the materialized view.
  * `query_rewrite_clause`: optional. Specifies whether to enable automatic query rewriting for the current materialized view.
  * `on_query_computation_clause`: optional. Specifies whether the current materialized view is a regular or real-time materialized view.

* `AS view_select_stmt`: the query (SELECT) statement used to define the data of the materialized view. This statement is used to retrieve data from the base table and store the results in the materialized view.

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p><ul><li>OceanBase Database supports creating full-refresh materialized views with external tables as base tables.</li><li>OceanBase Database supports adding the <code>AS OF PROCTIME()</code> clause to the base table when creating a materialized view. If <code>AS OF PROCTIME()</code> is used outside of the base table creation, an error will occur. <code>AS OF PROCTIME()</code> is used to specify that this table should be skipped during incremental refreshes, and tables with <code>AS OF PROCTIME()</code> do not require an mlog to be created.</li><li>OceanBase Database supports using regular views declared as dimension tables (<code>AS OF PROCTIME()</code>) as base tables for incremental-refresh materialized views.</li></ul></p>
    </main>

For more information about the parameters of the CREATE MATERIALIZED VIEW statement, see [CREATE MATERIALIZED VIEW](../../../../500.sql-reference/100.sql-syntax/300.common-tenant-of-oracle-mode/900.sql-statement-of-oracle-mode/100.ddl-of-oracle-mode/1750.create-materialized-views-of-oracle-mode-in-sql.md).

## Create a materialized view

### Create a regular materialized view

To create a regular materialized view, omit or specify the `DISABLE ON QUERY COMPUTATION` clause.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>In OceanBase Database in Oracle mode, when you create a materialized view and specify the <code>DISABLE ON QUERY COMPUTATION</code> clause (<code>on_query_computation_clause</code>), you must also specify the refresh method (<code>refresh_clause</code>). </p>
</main>

**Here is an example:**

1. Create a table named `tbl1` as the base table of the materialized view. The following example shows how to do this in SQL statements. You can also use the Data Management Service console to create a table. For more information, see [Create a table](../../../../600.create-table/100.create-table.md).

    ```sql
    CREATE TABLE tbl1 (col1 NUMBER PRIMARY KEY, col2 VARCHAR2(20), col3 NUMBER);
    ```

2. Create a materialized view named `mv_tbl1` based on the `tbl1` table. The following example shows how to do this in SQL statements. You can also use the Data Management Service console to create a materialized view. For more information, see [Create a materialized view](../../../../600.create-mv/100.create-mv.md).

    ```sql
    CREATE MATERIALIZED VIEW mv_tbl1
        AS SELECT col1, col2
          FROM tbl1
          WHERE col3 >= 20;
    ```

    or

    ```sql
    CREATE MATERIALIZED VIEW mv_tbl1
        REFRESH FORCE
        DISABLE ON QUERY COMPUTATION
        AS SELECT col1, col2
          FROM tbl1
          WHERE col3 >= 20;
    ```

### Create a nested materialized view

A nested materialized view is a materialized view created based on another materialized view. For example, in the following figure, `mv1` is a materialized view created based on the `tbl1` and `tbl2` tables. `mv2` is a nested materialized view created based on the `mv1` materialized view and the `tbl3` table. `mv3` is a nested materialized view created based on the `mv1` and `mv2` materialized views.

![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.3.5/700.reference/300.database-object-management/600.manage-views/%E5%B5%8C%E5%A5%97%E7%89%A9%E5%8C%96%E8%A7%86%E5%9B%BE.png)

When you create a nested materialized view in OceanBase Database, you can specify the refresh strategy. Valid values: `INDIVIDUAL`, `INCONSISTENT`, and `CONSISTENT`.

* `INDIVIDUAL`: the default value. This option specifies independent refresh.
* `INCONSISTENT`: specifies cascading inconsistent refresh.
* `CONSISTENT`: specifies cascading consistent refresh.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>For a regular materialized view, cascading refresh is not supported. Therefore, specifying any refresh strategy is ineffective. By default, independent refresh is performed. The three refresh strategies are only effective when you manually use the PL package (<a href="../../../../600.pl-reference/300.pl-oracle/1400.pl-system-package-oracle/9950.dbms-mview-oracle/300.refresh-oracle.md">DBMS_MVIEW.REFRESH</a>) to schedule refresh. In this case, the refresh is performed based on the specified PL parameters. </p>
</main>

### Limitations on nested materialized views

* To enable incremental refresh for nested materialized views, you must create mlogs on the base tables of materialized views.
* If a materialized view is completely refreshed, all dependent materialized views (nested materialized views) must be completely refreshed before incremental refresh is performed. Otherwise, an error will be returned.
* You cannot create a real-time materialized view as a nested materialized view. In other words, you cannot specify the `ENABLE ON QUERY COMPUTATION` clause when you create a nested materialized view.

**Here is an example:**

1. Create a table named `tbl3` as the base table of the materialized view. The following example shows how to do this in SQL statements. You can also use the Data Management Service console to create a table. For more information, see [Create a table](../../../../600.create-table/100.create-table.md).

    ```sql
    CREATE TABLE tbl3(id INT, name VARCHAR2(30), PRIMARY KEY(id));
    ```

2. Create a table named `tbl4` as the base table of the materialized view. The following example shows how to do this in SQL statements. You can also use the Data Management Service console to create a table. For more information, see [Create a table](../../../../600.create-table/100.create-table.md).

    ```sql
    CREATE TABLE tbl4(id INT, age INT, PRIMARY KEY(id));
    ```

3. Create a materialized view named `mv1_tbl3_tbl4` based on the `tbl3` and `tbl4` tables. The following example shows how to do this in SQL statements. You can also use the Data Management Service console to create a materialized view. For more information, see [Create a materialized view](../../../../600.create-mv/100.create-mv.md).

    ```sql
    CREATE MATERIALIZED VIEW mv1_tbl3_tbl4 (PRIMARY KEY (id1, id2))
        REFRESH COMPLETE
        AS SELECT tbl3.id id1, tbl4.id id2, tbl3.name, tbl4.age
            FROM tbl3, tbl4
            WHERE tbl3.id = tbl4.id;
    ```

4. Create a nested materialized view named `mv_mv1_tbl3_tbl4` based on the `mv1_tbl3_tbl4` materialized view. The following example shows how to do this in SQL statements. You can also use the Data Management Service console to create a materialized view. For more information, see [Create a materialized view](../../../../600.create-mv/100.create-mv.md).

    ```sql
    CREATE MATERIALIZED VIEW mv_mv1_tbl3_tbl4
        REFRESH COMPLETE
        AS SELECT SUM(AGE) age_sum
            FROM mv1_tbl3_tbl4;
    ```

5. Create a nested materialized view named `mv1_mv1_tbl3_tbl4` based on the `mv1_tbl3_tbl4` materialized view. The refresh strategy is `INCONSISTENT`. The following example shows how to do this in SQL statements. You can also use the Data Management Service console to create a materialized view. For more information, see [Create a materialized view](../../../../600.create-mv/100.create-mv.md).

    ```sql
    CREATE MATERIALIZED VIEW mv1_mv1_tbl3_tbl4
        REFRESH COMPLETE INCONSISTENT
        AS SELECT SUM(AGE) age_sum
            FROM mv1_tbl3_tbl4;
    ```

### Create a real-time materialized view

To create a real-time materialized view, specify the `ENABLE ON QUERY COMPUTATION` clause.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>In OceanBase Database in Oracle mode, when you create a real-time materialized view, you must also specify the refresh method (<code>refresh_clause</code>). </p>
</main>

### Considerations for creating a real-time materialized view

* Before you create a real-time materialized view, you must create a materialized view log for each base table on which the materialized view depends. 

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>OceanBase Database supports automatic management of materialized view logs. If you enable automatic management of materialized view logs, you do not need to create a materialized view log for the base table when you create a real-time materialized view. OceanBase Database automatically creates a materialized view log or updates the definition of an existing materialized view log to include the columns required by the new materialized view. For more information, see <a href="250.automatic-management-materialized-views-log-of-oracle-mode.md">Automatic management of materialized view logs</a>. </p>
    </main>

* Only materialized views of specific types can be specified as real-time materialized views. If you specify a materialized view that does not meet the conditions as a real-time materialized view, an error is returned. The requirements for a real-time materialized view are the same as those for an incrementally refreshed materialized view. For more information, see the **Basic requirements for incremental refreshes** section in [Refresh a materialized view](400.refresh-materialized-views-of-oracle-mode.md). 

  * A materialized view that uses the `MIN` or `MAX` function cannot be specified as a real-time materialized view.
  * An aggregate materialized view that contains an outer join cannot be specified as a real-time materialized view.
  * A materialized view that contains a set query cannot be specified as a real-time materialized view.
  * A nested materialized view cannot be specified as a real-time materialized view.

* If the values of system variables in the session that executes the query do not match the values of session variables that are fixed in the materialized view, you must modify the values of system variables in the session to the values of session variables that are fixed in the real-time materialized view. Otherwise, the real-time materialized view is unavailable, that is, the query rewrite of the real-time materialized view does not take effect or an error is returned when you directly query the real-time materialized view.

**Here is an example:**

1. Create a table `tbl2` as the base table for the materialized view.

    ```sql
    CREATE TABLE tbl2(col1 INT, col2 INT, col3 INT);
    ```

2. Create a materialized view log for the `tbl2` table.

    ```sql
    CREATE MATERIALIZED VIEW LOG ON tbl2
        WITH PRIMARY KEY, ROWID, SEQUENCE (col1, col2, col3) INCLUDING NEW VALUES;
    ```

3. Create a real-time materialized view `mv_tbl2` based on the `tbl2` table.

    ```sql
    CREATE MATERIALIZED VIEW mv_tbl2
        REFRESH COMPLETE ON DEMAND
        ENABLE ON QUERY COMPUTATION
        AS SELECT col1, count(*) AS cnt
           FROM tbl2
           GROUP BY col1;
    ```

4. After the real-time materialized view is created, you can query the [DBA_MVIEWS](../../../../700.system-views/500.system-view-of-oracle-mode/200.dictionary-view-of-oracle-mode/9400.dba_mviews-of-oracle-mode.md) view to check whether the materialized view is a real-time materialized view.

    ```sql
    SELECT MVIEW_NAME, ON_QUERY_COMPUTATION
    FROM sys.DBA_MVIEWS
    WHERE MVIEW_NAME = 'MV_TBL2';
    ```

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>When the <code>MVIEW_NAME</code> field in the <code>sys.DBA_MVIEWS</code> view in Oracle mode matches the table name, the table name must be in uppercase letters. </p>
    </main>

    The returned result is as follows:

    ```shell
    +------------+----------------------+
    | MVIEW_NAME | ON_QUERY_COMPUTATION |
    +------------+----------------------+
    | MV_TBL2    | Y                    |
    +------------+----------------------+
    1 row in set
    ```


### Create a materialized view that enables query rewrite

When you create a materialized view, specify the `ENABLE QUERY REWRITE` clause to enable automatic query rewrite for the materialized view. For more information about query rewrite and query rewrite control, see [Query rewrite for materialized views](500.materialized-views-rewrite-of-oracle-mode.md). 

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>Specifying the <code>ENABLE QUERY REWRITE</code> clause for a materialized view does not guarantee that the query is rewritten. If a materialized view does not meet the query rewrite conditions, no error is returned, but the materialized view is not used for query rewrite. By default, the system variable <code>query_rewrite_enabled</code> is <code>false</code>, so materialized views that specify the <code>ENABLE QUERY REWRITE</code> clause are not used for query rewrite. </p>
</main>

**Here is an example:**

1. Create a materialized view `mv_spj_tbl1` based on the `tbl1` table and enable automatic query rewrite.

    ```sql
    CREATE MATERIALIZED VIEW mv_spj_tbl1
        NEVER REFRESH
        ENABLE QUERY REWRITE
        AS SELECT *
           FROM tbl1;
    ```

2. After the materialized view is created, you can query the [DBA_MVIEWS](../../../../700.system-views/500.system-view-of-oracle-mode/200.dictionary-view-of-oracle-mode/9400.dba_mviews-of-oracle-mode.md) view to check whether automatic query rewrite is enabled for the materialized view.

    ```sql
    SELECT MVIEW_NAME, REWRITE_ENABLED
    FROM sys.DBA_MVIEWS
    WHERE MVIEW_NAME = 'MV_SPJ_TBL1';
    ```

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>When the <code>MVIEW_NAME</code> field in the <code>sys.DBA_MVIEWS</code> view in Oracle mode matches the table name, the table name must be in uppercase letters. </p>
    </main>

    The returned result is as follows:

    ```shell
    +-------------+-----------------+
    | MVIEW_NAME  | REWRITE_ENABLED |
    +-------------+-----------------+
    | MV_SPJ_TBL1 | Y               |
    +-------------+-----------------+
    1 row in set
    ```

### Create a columnstore materialized view

OceanBase Database supports materialized views in rowstore, columnstore, and rowstore-columnstore redundant formats. You can specify the `mv_column_group_option` option to explicitly create a columnstore or rowstore-columnstore redundant materialized view. If a materialized view is a wide table that is formed by joining multiple tables, creating a columnstore materialized view can improve the performance of some queries. You can specify the `WITH COLUMN GROUP(each column)` option to create a columnstore materialized view.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>If you do not specify the <code>mv_column_group_option</code> option, a rowstore materialized view is created by default. </p>
</main>

**Here is an example:**

Create a columnstore materialized view `mv_ec_tbl1` based on the `tbl1` table.

```sql
CREATE MATERIALIZED VIEW mv_ec_tbl1
    WITH COLUMN GROUP(each column)
    AS SELECT *
       FROM tbl1;
```

## Specify a primary key when you create a materialized view

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>If you specify a primary key for a materialized view, the view maintenance or update will fail if the data does not meet the primary key constraints. </p>
</main>

**Here is an example:**

Create a materialized view named `mv_pk_tbl1` based on the `tbl1` table and specify a primary key for the materialized view.

```sql
CREATE MATERIALIZED VIEW mv_pk_tbl1(v_id, v_name, PRIMARY KEY(v_id))
    AS SELECT col1, col2
       FROM tbl1
       WHERE col3 >= 20;
```

## Specify table and partition options when you create a materialized view

When you create a materialized view, you can specify table options and partition options based on data characteristics and access patterns to improve query performance and management efficiency.

For more information about the table options and partition options, see [CREATE TABLE](../../../../500.sql-reference/100.sql-syntax/300.common-tenant-of-oracle-mode/900.sql-statement-of-oracle-mode/100.ddl-of-oracle-mode/2400.create-table-of-oracle-mode.md).

**Here is an example:**

Create a materialized view named `mv_pp_tbl1` based on the `tbl1` table. Set the parallelism of the materialized view to `5`, and hash partition the materialized view by the `col1` column into `8` partitions. Query the records in the `tbl1` table that meet the condition `col3 >= 20` as the base table, and use the query results as the data for the materialized view.

```sql
CREATE MATERIALIZED VIEW mv_pp_tbl1
    PARALLEL 5
    PARTITION BY HASH(col1) PARTITIONS 8
    AS SELECT col1, col2
       FROM tbl1
       WHERE col3 >= 20;
```

## Add an index to a materialized view

You cannot directly create an index in the statement for creating a materialized view. Instead, you can use the [CREATE INDEX](../../../../500.sql-reference/100.sql-syntax/300.common-tenant-of-oracle-mode/900.sql-statement-of-oracle-mode/100.ddl-of-oracle-mode/1600.create-index-of-oracle-mode.md) statement to create an index for a materialized view.

**Here is an example:**

Create an index named `idx_mv_tbl1` on the `col1` column of the materialized view `mv_tbl1`.

```sql
CREATE INDEX idx_mv_tbl1 ON mv_tbl1(col1);
```

## Refresh a materialized view

OceanBase Database supports the following refresh modes for materialized views: full refresh, incremental refresh, hybrid refresh, and no refresh.

* **Full refresh**: Recalculate all the data in the materialized view. A full refresh ensures that the data in the materialized view is identical to the data in the source table.
* **Incremental refresh**: Recalculate only the data that is affected by the changes in the source table. This avoids the need to recalculate the entire view.
* **Hybrid refresh**: The default refresh mode. This mode first tries incremental refresh. If incremental refresh fails, it attempts full refresh.
* **No refresh**: The view is only refreshed upon its creation. Once a materialized view is created, it cannot be refreshed again.

For more information about materialized view refresh, see [Refresh a materialized view](400.refresh-materialized-views-of-oracle-mode.md).

### Create a materialized view with a complete refresh strategy

When you create a materialized view, you can use the `REFRESH COMPLETE` clause to set the refresh strategy to complete refresh.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>If a materialized view is completely refreshed, any dependent materialized views (nested materialized views) must also be completely refreshed before they can be incrementally refreshed. Otherwise, an error will be returned.</p>
</main>

**Here is an example:**

Create a materialized view named `mv_rc_tbl1` based on the `tbl1` table. Set the refresh strategy to complete refresh (`REFRESH COMPLETE`). Specify that the data source of the materialized view consists of the `col1` and `col2` columns from the `tbl1` table where `col3` is greater than or equal to `20`.

```sql
CREATE MATERIALIZED VIEW mv_rc_tbl1
    REFRESH COMPLETE
    AS SELECT col1, col2
       FROM tbl1
       WHERE col3 >= 20;
```

#### Create a materialized view with a complete refresh strategy based on an external table

OceanBase Database allows you to create a materialized view with a complete refresh strategy based on an external table.

For more information about external tables, see [About external tables](../../100.manage-tables-of-oracle-mode/1000.manage-external-tables-of-oracle-mode/100.about-external-tables-of-oracle-mode.md).

**Here is an example:**

### Create a materialized view with incremental refresh

When creating a materialized view, use the `REFRESH FAST` clause to set the refresh strategy to incremental refresh.

#### Considerations

* At present, incremental refresh is supported for the following types of SQL statements: single-table non-aggregated, single-table aggregated, multi-table joined, multi-table joined aggregated, and `UNION ALL` queries. For SQL statements that do not fall into these five categories, incremental refresh is not supported. For more information about incremental refresh, see the **Incremental refresh** section in [Refresh a materialized view](400.refresh-materialized-views-of-oracle-mode.md).
* The `REFRESH FAST` method uses the records in the materialized view log to determine what needs to be incrementally refreshed. Therefore, when using incremental refresh to refresh a materialized view, you must create a materialized view log for the base table before you create the materialized view. For more information about how to create a materialized view log, see [Materialized view log](200.materialized-views-log-of-oracle-mode.md).

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>OceanBase Database supports automatic management of materialized view logs. If automatic management of materialized view logs is enabled, you do not need to create a materialized view log for the base table before you create an incremental refresh materialized view. OceanBase Database automatically creates the corresponding materialized view log or updates the definition of an existing materialized view log table to include the columns required by the new materialized view. For more information, see <a href="250.automatic-management-materialized-views-log-of-oracle-mode.md">Automatic management of materialized view logs</a>. </p>
    </main>

* When creating a materialized view, you can add the `AS OF PROCTIME()` clause to the base table. If you use `AS OF PROCTIME()` outside the base table, an error is returned.

  * `AS OF PROCTIME()` specifies that the incremental refresh of the materialized view should skip the table to accelerate the incremental refresh. In this case, you do not need to create a materialized view log for the table. If you want to use an alias for the table, the alias must be specified after the `AS OF PROCTIME()` clause.
  * When you use a regular view declared as a dimension table with the <code>AS OF PROCTIME()</code> clause as the base table for an incremental refresh materialized view, the following limitations apply:

    * Not all tables in the materialized view can be dimension tables, just like the base table.

**Here is an example:**

1. Create a table named `tbl5` as the base table for the materialized view.

    ```sql
    CREATE TABLE tbl5 (col1 INT PRIMARY KEY, col2 INT, col3 INT);
    ```

2. Create a materialized view log for the `tbl5` table and specify the `SEQUENCE` option for the materialized view log. This option indicates that the changes are identified by sequence numbers. Specify the `col2` and `col3` columns to be recorded.

    ```sql
    CREATE MATERIALIZED VIEW LOG ON tbl5
        WITH SEQUENCE (col2, col3) INCLUDING NEW VALUES;
    ```

3. Create a materialized view named `mv_tbl5` based on the `tbl5` table, specify the incremental refresh strategy (`REFRESH FAST`) for the materialized view, and specify the `col2` column to be used for grouping. Count the number of records in each group (`cnt`), the number of non-null records in the `col3` column (`cnt_col3`), and the sum of the `col3` column (`sum_col3`) as the results of the materialized view.

    ```sql
    CREATE MATERIALIZED VIEW mv_tbl5
        REFRESH FAST
        AS SELECT col2, COUNT(*) cnt, COUNT(col3) cnt_col3, SUM(col3) sum_col3
           FROM tbl5
           GROUP BY col2;
    ```

4. Create a materialized view named `mv2_tbl5_tbl1` based on the `tbl5` and `tbl1` tables, specify the incremental refresh strategy for the materialized view, and join the tables on the `col1` column by using an inner join (`INNER JOIN`). Use `AS OF PROCTIME()` to specify that the `tbl1` table should be skipped during the incremental refresh.

    ```sql
    CREATE MATERIALIZED VIEW mv2_tbl5_tbl1
        REFRESH FAST ON DEMAND
        AS SELECT 
            t5.col1 tbl5_c1,
            t1.col1 tbl1_c1,
            t5.col2 tbl5_c2,
            t1.col2 tbl1_c2
        FROM tbl5 t5
            INNER JOIN tbl1 AS OF PROCTIME() t1
            ON t5.col1 = t1.col1
        WHERE t5.col2 = 3;
    ```

5. Create an incremental refresh materialized view based on a regular view declared as a dimension table with the `AS OF PROCTIME()` clause.

   1. Create a view named `v1_tbl5` based on the `tbl5` table.

       ```shell
       obclient> CREATE VIEW v1_tbl5 AS SELECT * FROM tbl5;
       ```

   2. Create a materialized view named `mv3_tbl5_v_tbl5` based on the `tbl5` and `v1_tbl5` tables, specify the incremental refresh strategy for the materialized view, and join the tables on the `col1` column. Use `AS OF PROCTIME()` to specify that the `v1_tbl5` view is a dimension table.

       ```shell
       obclient> CREATE MATERIALIZED VIEW mv3_tbl5_v_tbl5
           AS SELECT
               a.col1 a_c1,
               b.col1 b_c1
           FROM tbl5 a JOIN v1_tbl5 AS OF PROCTIME() b
           ON a.col1 = b.col1;
       ```

### Create a materialized view with hybrid refresh (default option)

When creating a materialized view, omit or specify the `REFRESH FORCE` clause to set the refresh strategy to hybrid refresh.

**Here is an example:**

Create a materialized view named `mv_rf_tbl1` based on the `tbl1` table, specify the hybrid refresh strategy (`REFRESH FORCE`) for the materialized view, and specify the `col1` and `col2` columns that satisfy the `col3 >= 20` condition as the data source of the materialized view.

```sql
CREATE MATERIALIZED VIEW mv_rf_tbl1
    REFRESH FORCE
    AS SELECT col1, col2
       FROM tbl1
       WHERE col3 >= 20;
```

### Create a materialized view that never refreshes

When creating a materialized view, use the `NEVER REFRESH` clause to specify that the materialized view does not need to be refreshed. This means that the materialized view is only refreshed when it is created and cannot be refreshed again after it is created.

**Here is an example:**

Create a materialized view named `mv_nr_tbl1` based on the `tbl1` table, specify the `NEVER REFRESH` strategy for the materialized view, and specify the `col1` and `col2` columns that satisfy the `col3 >= 20` condition as the data source of the materialized view.

```sql
CREATE MATERIALIZED VIEW mv_nr_tbl1
    NEVER REFRESH
    AS SELECT col1, col2
       FROM tbl1
       WHERE col3 >= 20;
```

## Create a materialized view with an automatic refresh task

When you create a materialized view, you can specify the `START WITH datetime_expr` and `NEXT datetime_expr` clauses to create a background automatic refresh task for the materialized view.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>If you use the <code>NEXT</code> clause, the time expression in the refresh schedule must be set to a future date and time, otherwise an error will be returned. </p>
</main>

**Here is an example:**

Create a materialized view named `mv_rc_swn_tbl1` based on the `tbl1` table. The materialized view is refreshed in full. The initial refresh time is the current date and time, and the materialized view is refreshed every `1` hour after that.

```sql
CREATE MATERIALIZED VIEW mv_rc_swn_tbl1
    REFRESH COMPLETE
        START WITH current_date NEXT current_date + INTERVAL '1' HOUR
    AS SELECT col1, col2
       FROM tbl1
       WHERE col3 >= 20;
```
