# Change the attribute of a replicated table

In OceanBase Database, the `DUPLICATE_SCOPE` parameter is used to specify the attribute of a replicated table. After a table is created, you can change the value of the `DUPLICATE_SCOPE` parameter to convert the table into a normal table or a replicated table.

## Limitations and considerations

* If a load balancing task is triggered for scaling up or down, changing the primary zone, or modifying the locality of the current tenant, the task of converting a table into a replica table must wait until the balancing task is completed.

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p> The conversion of a table into a replica table is an asynchronous process. After you manually modify the <code>DUPLICATE_SCOPE</code> attribute, you must wait for the background partition balancing task to complete before you can use the table as the target attribute. For more information about partition balancing, see <a href="../../../100.oceanbase-database-concepts/500.distributed-database-objects/300.data-partitions-and-replicas/500.data-balancing/100.intra-tenant-balancing.md">Intra-tenant balancing</a>. </p>
    </main>

* A table cannot be converted into a replica table if it belongs to a table group. In this case, you can add the table to a table group and convert it into a replica table.

* The conversion of a table into a replica table depends on the load balancing and transfer features of the tenant. If any of the `enable_rebalance`, `enable_transfer`, and `enable_rereplication` tenant-level parameters is set to `false`, you cannot convert a table into a replica table. If you set the `enable_rebalance` or `enable_transfer` parameter to `false` and there are ongoing tasks of converting tables into replica tables, the tasks will be canceled.

## Prerequisites

Before you convert a table into a replica table, make sure that the following parameters are set to `True`:

* `enable_rebalance`

  The tenant-level `enable_rebalance` parameter controls whether to perform load balancing among tenants. Its user-level counterpart controls whether to perform load balancing for the current tenant. The default value is `True`. For more information about the `enable_rebalance` parameter, see [enable_rebalance](../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2800.enable_rebalance.md).

* `enable_transfer`

  The tenant-level `enable_transfer` parameter controls whether to perform transfer in the current tenant. The default value is `True`. For more information about the `enable_transfer` parameter, see [enable_transfer](../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3000.enable_transfer.md).

* `enable_rereplication`

  The cluster-level `enable_rereplication` parameter controls whether to enable automatic replica supplementation. The default value is `True`. For more information about the `enable_rereplication` parameter, see [enable_rereplication](../../../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/8000.enable_rereplication.md).

## SQL syntax for changing the replica table attribute

The SQL syntax for changing the replica table attribute is as follows:

```sql
ALTER TABLE table_name DUPLICATE_SCOPE= 'none | cluster';
```

In this syntax:

* `none`: specifies to convert the table into a non-replica table.
* `cluster`: specifies to convert the table into a replica table.

## Example

The following commands show how to convert a replica table into a normal table.

1. Create a replica table named `tbl1`.

    ```sql
    obclient [test]> CREATE TABLE tbl1 (c1 int,c2 int) DUPLICATE_SCOPE= 'cluster';
    ```

2. Convert the replica table into a normal table.

    ```sql
    ALTER TABLE tbl1 DUPLICATE_SCOPE= 'none';
    ```

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>After the preceding SQL statement modifies the table attribute, it will immediately return success. The actual conversion of the replica table into a normal table is asynchronously performed in the background by a thread.</p>
    </main>

3. View the attribute of the replica table.

    You can query the `sys.DBA_OB_TABLE_LOCATIONS` view for the attribute and the log stream ID where the replica table is located. If the `DUPLICATE_SCOPE` column displays `CLUSTER`, the table is a replica table. If it displays `NONE`, the table is a normal table.

    ```sql
    SELECT database_name, table_name, table_id, tablet_id, ls_id, role, duplicate_scope
    FROM sys.DBA_OB_TABLE_LOCATIONS
    WHERE table_name = 'TBL1';
    ```

    The return result is as follows:

    ```shell
    +---------------+------------+----------+-----------+-------+--------+-----------------+
    | DATABASE_NAME | TABLE_NAME | TABLE_ID | TABLET_ID | LS_ID | ROLE   | DUPLICATE_SCOPE |
    +---------------+------------+----------+-----------+-------+--------+-----------------+
    | SYS           | TBL1       |   500011 |    200002 |  1002 | LEADER | NONE            |
    +---------------+------------+----------+-----------+-------+--------+-----------------+
    1 row in set
    ```

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>You can follow the steps below to check whether the partition replicas of the converted table meet the desired attribute. </p>
    </main>

4. View the conversion progress.

   1. View the attribute of the log stream.

       All replica tables in a tenant must be placed on a special log stream (broadcast stream) dedicated to replica tables. You can query the `sys.DBA_OB_LS` view for the attribute of the log stream. If the `FLAG` column contains `DUPLICATE`, the log stream is a broadcast stream. Otherwise, it is a normal log stream.

       ```sql
       SELECT * FROM sys.DBA_OB_LS WHERE LS_ID = 1002;
       ```

       The return result is as follows:

       ```shell
        +-------+--------+--------------+---------------+-------------+---------------------+----------+---------------------+---------------------+-----------+
        | LS_ID | STATUS | PRIMARY_ZONE | UNIT_GROUP_ID | LS_GROUP_ID | CREATE_SCN          | DROP_SCN | SYNC_SCN            | READABLE_SCN        | FLAG      |
        +-------+--------+--------------+---------------+-------------+---------------------+----------+---------------------+---------------------+-----------+
        |  1002 | NORMAL | zone1        |             0 |           0 | 1713164474213079001 |     NULL | 1713173927933707000 | 1713173927933707000 | DUPLICATE |
        +-------+--------+--------------+---------------+-------------+---------------------+----------+---------------------+---------------------+-----------+
        1 row in set
       ```

   2. Determine whether a table conversion task needs to be generated.

       Table conversion tasks are generated in the background by the load balancing module and the transfer module. You can execute the following statement to quickly check whether a table conversion task needs to be generated. In the statement, `DUPLICATE_SCOPE` is a table attribute, and `FLAG` is the attribute of the log stream to which the table's `tablet` belongs. If the `FLAG` column contains the `DUPLICATE` keyword, the log stream is a broadcast stream. Otherwise, it is a normal log stream.

       ```sql
       SELECT A.duplicate_scope, B.flag
       FROM sys.DBA_OB_TABLE_LOCATIONS A, sys.DBA_OB_LS B
       WHERE A.ls_id = B.ls_id
       AND A.table_name = 'TBL1'
       AND A.role = 'LEADER';
       ```

       The return result is as follows:

       ```shell
        +-----------------+-----------+
        | DUPLICATE_SCOPE | FLAG      |
        +-----------------+-----------+
        | NONE            | DUPLICATE |
        +-----------------+-----------+
        1 row in set
       ```

       The return information is described as follows:

       * `DUPLICATE_SCOPE` is `NONE`, and `FLAG` contains the `DUPLICATE` keyword: The table is a non-replica table placed on a broadcast stream. A table conversion task needs to be generated to transfer the non-replica table from the broadcast stream to a normal stream.
       * `DUPLICATE_SCOPE` is `NONE`, and `FLAG` does not contain the `DUPLICATE` keyword: The table is a replica table placed on a normal stream. A table conversion task needs to be generated to transfer the replica table from a normal stream to a broadcast stream.

   3. Generate a conversion task immediately.

       You can temporarily set the `partition_balance_schedule_interval` parameter to a smaller value to generate a conversion task immediately.

       ```sql
       ALTER SYSTEM SET partition_balance_schedule_interval = '30s';
       ```

   4. View the conversion task.

       Table conversion tasks can be queried from the `DBA_OB_BALANCE_JOB_HISTORY` or `CDB_OB_BALANCE_JOB_HISTORY` view and the `DBA_OB_BALANCE_JOBS` or `CDB_OB_BALANCE_JOBS` view.

       1. Check the execution status of historical conversion tasks.

           If no historical records are returned, the system either has no tasks to perform or is performing a task.

           ```sql
           SELECT * FROM sys.DBA_OB_BALANCE_JOB_HISTORY;
           ```

           The return result is as follows:

            ```shell
            +--------+------------------------------+------------------------------+-------------------+-------------------+-----------------+-------------------------+-----------+---------+
            | JOB_ID | CREATE_TIME                  | FINISH_TIME                  | BALANCE_STRATEGY  | JOB_TYPE          | TARGET_UNIT_NUM | TARGET_PRIMARY_ZONE_NUM | STATUS    | COMMENT |
            +--------+------------------------------+------------------------------+-------------------+-------------------+-----------------+-------------------------+-----------+---------+
            | 787926 | 15-APR-24 05.41.42.226172 PM | 15-APR-24 05.41.52.235808 PM | partition balance | PARTITION_BALANCE |               1 |                       1 | COMPLETED | NULL    |
            +--------+------------------------------+------------------------------+-------------------+-------------------+-----------------+-------------------------+-----------+---------+
            1 row in set
            ```

       2. Check the execution status of current balancing tasks.

          ```sql
          SELECT * FROM sys.DBA_OB_BALANCE_JOBS;
          ```

       3. View the subtasks (including the partition list) of the conversion task.

          Replace `xxxx` in the following SQL statement with the `job_id` of the task:

          ```sql
          SELECT * FROM sys.DBA_OB_BALANCE_TASKS WHERE JOB_ID = xxxx;
          ```

          ```sql
          SELECT * FROM sys.DBA_OB_BALANCE_TASK_HISTORY WHERE JOB_ID = xxxx;
          ```

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p><ul><li>If there is another <code>BALANCE_JOB</code> running in the <code>DBA_OB_BALANCE_JOBS</code> view, the system will not schedule a partition balancing job until the current job is done. </li><li>If no corresponding <code>BALANCE_JOB</code> is found in the preceding <code>BALANCE</code> related views, the system may not have generated the <code>BALANCE_JOB</code> yet. In this case, you can wait or temporarily set the <code>partition_balance_schedule_interval</code> parameter to a smaller value. </li><li>If a conversion task is not generated after a long time, check the <code>enable_rebalance</code>, <code>enable_transfer</code>, <code>balancer_idle_time</code>, and <code>enable_rereplication</code> parameters to see whether transfer is disabled. </li></ul></p>
</main>
