# Modify a table

After a table is created, you can execute the `ALTER TABLE` statement to modify the table.

## Considerations

Do not perform other DDL operations when you change the primary key or column type of a table. Likewise, do not change the primary key or column type of a table that has other DDL operations pending.

## Add, modify, and drop columns

OceanBase Database allows you to add, modify, and drop columns.

### Add a column

OceanBase Database allows you to add a column to a table but does not allow you to add a primary key column directly. If you want to add a primary key column, we recommend that you first add the column and then add a primary key to the column. For more information, see [Define a constraint type for a column](../100.manage-tables-of-oracle-mode/400.define-the-constraint-type-for-a-column-of-oracle-mode.md).

The SQL syntax for adding a column is as follows:

```sql
ALTER TABLE table_name ADD column_definition;
```

Here is an example:

1. Create a test table named `test_tbl1`.

    ```sql
    CREATE TABLE test_tbl1 (
      col1 NUMBER(38),
      col2 VARCHAR2(50),
      PRIMARY KEY(col1));
    ```

2. Add a column named `col3` to the `test_tbl1` table.

    ```sql
    ALTER TABLE test_tbl1 ADD col3 NUMBER(38);
    ```

3. View the schema of the `test_tbl1` table.

    ```sql
    DESCRIBE test_tbl1;
    ```

    The return result is as follows:

    ```shell
    +-------+--------------+------+------+---------+-------+
    | FIELD | TYPE         | NULL | KEY  | DEFAULT | EXTRA |
    +-------+--------------+------+------+---------+-------+
    | COL1  | NUMBER(38)   | NO   | PRI  | NULL    | NULL  |
    | COL2  | VARCHAR2(50) | YES  | NULL | NULL    | NULL  |
    | COL3  | NUMBER(38)   | YES  | NULL | NULL    | NULL  |
    +-------+--------------+------+------+---------+-------+
    3 rows in set
    ```

### Modify columns

#### Modify column attributes

OceanBase Database allows you to convert between different column types and set default values and non-null constraints. For more information about the rules and details of column type conversion in OceanBase Database, see [Rules for changing column types](../../../500.sql-reference/100.sql-syntax/300.common-tenant-of-oracle-mode/1000.ddl-function-of-oracle-mode/900.column-type-change-rule-of-oracle-mode.md).

The SQL syntax for modifying a column type is as follows:

```sql
ALTER TABLE table_name MODIFY [COLUMN] column_definition;
```

Here is an example:

1. Create a test table named `test_tbl2`.

    ```sql
    CREATE TABLE test_tbl2 (
      col1 NUMBER(38),
      col2 VARCHAR2(20));
    ```

2. View the schema of the `test_tbl2` table.

    ```sql
    DESCRIBE test_tbl2;
    ```

    The return result is as follows:

    ```shell
    +-------+--------------+------+------+---------+-------+
    | FIELD | TYPE         | NULL | KEY  | DEFAULT | EXTRA |
    +-------+--------------+------+------+---------+-------+
    | COL1  | NUMBER(38)   | YES  | NULL | NULL    | NULL  |
    | COL2  | VARCHAR2(20) | YES  | NULL | NULL    | NULL  |
    +-------+--------------+------+------+---------+-------+
    2 rows in set
    ```

3. Modify the `col2` column of the `test_tbl2` table to the `CHAR(50)` type.

    ```sql
    ALTER TABLE test_tbl2 MODIFY col2 CHAR(50);
    ```

4. Set the default value of the `col1` column of the `test_tbl2` table to 0.

    ```sql
    ALTER TABLE test_tbl2 MODIFY col1 DEFAULT 0;
    ```

5. Set the values of the `col2` column of the `test_tbl2` table to non-null.

    ```sql
    ALTER TABLE test_tbl2 MODIFY col2 NOT NULL;
    ```

6. View the schema of the `test_tbl2` table.

    ```sql
    DESCRIBE test_tbl2;
    ```

    The return result is as follows:

    ```shell
    +-------+------------+------+------+---------+-------+
    | FIELD | TYPE       | NULL | KEY  | DEFAULT | EXTRA |
    +-------+------------+------+------+---------+-------+
    | COL1  | NUMBER(38) | YES  | NULL | 0       | NULL  |
    | COL2  | CHAR(50)   | NO   | NULL | NULL    | NULL  |
    +-------+------------+------+------+---------+-------+
    2 rows in set
    ```

#### Modify column names

The SQL syntax for modifying a column name is as follows:

```sql
ALTER TABLE table_name RENAME COLUMN old_col_name TO new_col_name;
```

Here is an example:

1. Create a test table named `test_tbl3`.

    ```sql
    CREATE TABLE test_tbl3 (
      col1 NUMBER(38),
      col2 VARCHAR2(20),
      PRIMARY KEY(col1));
    ```

2. Modify the name of the `col1` column of the `test_tbl3` table to `col1_new`.

    ```sql
    ALTER TABLE test_tbl3 RENAME COLUMN col1 TO col1_new;
    ```

3. View the schema of the `test_tbl3` table.

    ```sql
    DESCRIBE test_tbl3;
    ```

    The return result is as follows:

    ```shell
    +----------+--------------+------+------+---------+-------+
    | FIELD    | TYPE         | NULL | KEY  | DEFAULT | EXTRA |
    +----------+--------------+------+------+---------+-------+
    | COL1_NEW | NUMBER(38)   | NO   | PRI  | NULL    | NULL  |
    | COL2     | VARCHAR2(20) | YES  | NULL | NULL    | NULL  |
    +----------+--------------+------+------+---------+-------+
    2 rows in set
    ```

### Drop columns

You can drop columns from a table, but not the primary key columns or columns that contain indexes.

The SQL syntax for dropping a column is as follows:

```sql
ALTER TABLE table_name DROP COLUMN column_name;
```

Here is an example:

1. Create a test table named `test_tbl4`.

    ```sql
    CREATE TABLE test_tbl4 (
      col1 NUMBER(38),
      col2 VARCHAR2(50),
      PRIMARY KEY(col1));
    ```

2. Drop the `col2` column from the `test_tbl4` table.

    ```sql
    ALTER TABLE test_tbl4 DROP COLUMN col2;
    ```

3. View the schema of the `test_tbl4` table.

    ```sql
    DESCRIBE test_tbl4;
    ```

    The return result is as follows:

    ```shell
    +-------+------------+------+------+---------+-------+
    | FIELD | TYPE       | NULL | KEY  | DEFAULT | EXTRA |
    +-------+------------+------+------+---------+-------+
    | COL1  | NUMBER(38) | NO   | PRI  | NULL    | NULL  |
    +-------+------------+------+------+---------+-------+
    1 row in set
    ```

## Add a UNIQUE constraint

OceanBase Database allows you to add a UNIQUE constraint to an existing table.

The SQL syntax for adding a UNIQUE constraint is as follows:

```sql
ALTER TABLE table_name ADD [CONSTRAINT [constraint_name]] UNIQUE (column_name [, column_name ]...);
```

Here is an example:

1. Create a test table named `test_tbl5`.

    ```sql
    CREATE TABLE test_tbl5 (
      col1 NUMBER(38),
      col2 VARCHAR2(50),
      PRIMARY KEY(col1));
    ```

2. Add a UNIQUE constraint to the `col2` column of the `test_tbl5` table.

    ```sql
    ALTER TABLE test_tbl5 ADD UNIQUE(col2);
    ```

3. View the structure of the `test_tbl5` table.

    ```sql
    DESCRIBE test_tbl5;
    ```

    The return result is as follows:

    ```shell
    +-------+--------------+------+------+---------+-------+
    | FIELD | TYPE         | NULL | KEY  | DEFAULT | EXTRA |
    +-------+--------------+------+------+---------+-------+
    | COL1  | NUMBER(38)   | NO   | PRI  | NULL    | NULL  |
    | COL2  | VARCHAR2(50) | YES  | UNI  | NULL    | NULL  |
    +-------+--------------+------+------+---------+-------+
    2 rows in set
    ```

## Rename a table

After a table is created, you can rename it.

The SQL syntax for renaming a table is as follows:

```sql
ALTER TABLE old_table_name RENAME TO new_table_name;
```

or

```sql
RENAME old_table_name TO new_table_name;
```

Here is an example:

```sql
ALTER TABLE test RENAME TO t1;
```

or

```sql
RENAME test TO t1;
```

## Change the primary key and foreign key of a table

After a table is created, OceanBase Database allows you to add or drop a primary key or foreign key from the table. For more information, see [Define a column constraint](../100.manage-tables-of-oracle-mode/400.define-the-constraint-type-for-a-column-of-oracle-mode.md).

## Modify the skip index attribute of a column

OceanBase Database allows you to use the `ALTER TABLE` statement to add, modify, and drop the skip index attribute.

For more information about skip index, see [Skip index attribute](250.identify-skip-index-properties-of-oracle-mode.md).

**Here is an example:**

1. Execute the following SQL statement to create a table named `test_skidx`.

    ```sql
    CREATE TABLE test_skidx(
      col1 NUMBER SKIP_INDEX(MIN_MAX, SUM),
      col2 FLOAT SKIP_INDEX(MIN_MAX),
      col3 VARCHAR2(1024) SKIP_INDEX(MIN_MAX),
      col4 CHAR(10)
      );
    ```

2. Modify the skip index attribute of the `col2` column in the `test_skidx` table to `SUM`.

    ```sql
    ALTER TABLE test_skidx MODIFY col2 FLOAT SKIP_INDEX(SUM);
    ```

3. Add the skip index attribute to a column after table creation. Add the `MIN_MAX` skip index attribute to the `col4` column in the `test_skidx` table.

    ```sql
    ALTER TABLE test_skidx MODIFY col4 CHAR(10) SKIP_INDEX(MIN_MAX);
    ```

4. Drop the skip index attribute from a column after table creation. Drop the skip index attribute from the `col1` column in the `test_skidx` table.

    ```sql
    ALTER TABLE test_skidx MODIFY col1 NUMBER SKIP_INDEX();
    ```

## Convert a table between rowstore and columnstore

When you create a table in OceanBase Database, the table is a rowstore table by default. You can use the `WITH COLUMN GROUP` option to explicitly specify to create a columnstore table or a hybrid rowstore-columnstore table.

After a table is created, you can execute the `ALTER TABLE` statement to convert the table between rowstore and columnstore. The syntax is as follows:

* To convert a rowstore table into a columnstore table, use the following statement:

  ```sql
  ALTER TABLE table_name ADD COLUMN GROUP([all columns,] each column) [DELAYED];
  ```

* To remove the storage format of a table, use the following statement:

  ```sql
  ALTER TABLE table_name DROP COLUMN GROUP([all columns,] each column);
  ```

**Here is a breakdown of the parameters:**

* `table_name`: the specified table name.
* `ADD COLUMN GROUP(all columns, each column)`: specifies to convert a rowstore table into a hybrid rowstore-columnstore table.
* `ADD COLUMN GROUP(each column)`: specifies to convert a rowstore table into a columnstore table.
* `DELAYED`: an optional parameter. If specified, the command to convert a rowstore table into a columnstore table is executed asynchronously. After the command is executed, the storage format in the table definition is modified, but the actual conversion of the rowstore table into a columnstore table is deferred until a major compaction is performed. This operation does not block current DML operations. As an online DDL operation, it allows you to convert a rowstore table into a columnstore table without interrupting your business. If you do not specify the `DELAYED` option, the default option, which is an offline DDL operation, applies, and the rowstore table is converted into a columnstore table synchronously.

  <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p><ul><li>You can specify the <code>DELAYED</code> option only when you convert a rowstore table into a columnstore table (<code>each column</code>) or a hybrid rowstore-columnstore table (<code>all columns, each column</code>). </li><li>After you specify the <code>DELAYED</code> option to defer the conversion of a rowstore table into a columnstore table, the query performance may not meet expectations before the baseline data is actually merged. </li></ul></p>
  </main>

* `DROP COLUMN GROUP(all columns, each column)`: specifies to remove the hybrid rowstore-columnstore format from a table.
* `DROP COLUMN GROUP(all columns)`: specifies to remove the rowstore format from a table.
* `DROP COLUMN GROUP(each column)`: specifies to remove the columnstore format from a table.

### Convert a rowstore table into a columnstore table

**Here is an example:**

1. Create a rowstore table named `tbl1`.

    ```sql
    CREATE TABLE tbl1(col1 NUMBER, col2 VARCHAR2(30));
    ```

2. Convert the `tbl1` rowstore table into a columnstore table.

    * Perform an offline DDL operation as follows:

      ```sql
      ALTER TABLE tbl1 ADD COLUMN GROUP(each column);
      ```

    * Perform an online DDL operation (asynchronously convert the `tbl1` rowstore table into a columnstore table) as follows:

      ```sql
      ALTER TABLE tbl1 ADD COLUMN GROUP(each column) DELAYED;
      ```

### Convert a rowstore table into a hybrid rowstore-columnstore table

**Here is an example:**

1. Create a rowstore table named `tbl2`.

    ```sql
    CREATE TABLE tbl2(col1 NUMBER, col2 VARCHAR2(30));
    ```

2. Convert the `tbl2` rowstore table into a hybrid rowstore-columnstore table.

    * Perform an offline DDL operation as follows:

      ```sql
      ALTER TABLE tbl2 ADD COLUMN GROUP(all columns, each column);
      ```

    * Perform an online DDL operation (asynchronously convert the `tbl2` rowstore table into a hybrid rowstore-columnstore table) as follows:

      ```sql
      ALTER TABLE tbl2 ADD COLUMN GROUP(all columns, each column) DELAYED;
      ```

### Convert a hybrid rowstore-columnstore table into a columnstore table

**Here is an example:**

1. Create a hybrid rowstore-columnstore table named `tbl3`.

    ```sql
    CREATE TABLE tbl3(col1 NUMBER, col2 VARCHAR2(30)) WITH COLUMN GROUP(all columns, each column);
    ```

2. Convert the `tbl3` hybrid rowstore-columnstore table into a columnstore table.

    ```sql
    ALTER TABLE tbl3 DROP COLUMN GROUP(all columns);
    ```

### Convert a hybrid rowstore-columnstore table into a rowstore table

**Here is an example:**

1. Create a hybrid rowstore-columnstore table named `tbl4`.

    ```sql
    CREATE TABLE tbl4(col1 NUMBER, col2 VARCHAR2(30)) WITH COLUMN GROUP(all columns, each column);
    ```

2. Convert the `tbl4` hybrid rowstore-columnstore table into a rowstore table.

    ```sql
    ALTER TABLE tbl4 DROP COLUMN GROUP(each column);
    ```

    or

    ```sql
    ALTER TABLE tbl4 DROP COLUMN GROUP(all columns, each column);
    ```
