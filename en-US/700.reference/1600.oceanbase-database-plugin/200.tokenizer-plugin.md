# Part-of-speech tagger plug-in

This topic introduces how to install and use the parser plug-in in OceanBase Database. The parser plug-in is used for full-text indexing and supports custom parsing logic to meet specific business needs.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p><ul><li>Starting from V4.3.5 BP1, OceanBase Database V4.3.5 supports parser plugins. </li><li>Parser plugins are currently in the experimental stage. Therefore, we do not recommend that you use them in production environments. </li></ul></p>
</main>

## Prerequisites

Before installing and using the parser plug-in, make sure that the following conditions are met:

* The operating system supports the yum package management tool.

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>If your operating system does not support <code>yum</code>, you can install the required dependencies in other ways, for example, by manually downloading the RPM packages or using another package management tool. </p>
    </main>

* An OceanBase cluster is deployed and running.
* You have the privileges to modify configuration parameters and restart the cluster.

## Procedure

### Step 1: Install the development environment

To develop a parser plugin, you need a C/C++ compilation environment and the OceanBase Plugin Development Kit. Perform the following steps to install the C/C++ compilation environment and OceanBase Plugin Development Kit:

1. Install the basic compilation tools.

    Install the basic tools and libraries required for compiling C/C++ programs.

    ```shell
    yum install -y cmake make glibc-devel glibc-headers gcc gcc-c++
    ```

2. Configure the OceanBase software source.

    Add the official OceanBase software source so that you can use yum to install OceanBase tools and dependencies later.

    1. Install the yum-utils tool.

        ```shell
        yum install -y yum-utils
        ```

    2. Add the OceanBase software source.

        ```shell
        yum-config-manager --add-repo https://mirrors.aliyun.com/oceanbase/OceanBase.repo
        ```

3. Install the plugin development suite.

    ```shell
    yum install -y oceanbase-plugin-dev-kit
    ```

    After the installation, you can find the sample code of the OceanBase parser plugin, `space_ftparser.cpp`, in the `/usr/share/examples/ObPlugin/ftparser` directory.

    ```shell
    ls /usr/share/examples/ObPlugin/ftparser
    ```

    The return result is as follows:

    ```shell
    CMakeLists.txt  space_ftparser.cpp
    ```

### Step 2: Obtain a development template

Copy the sample code file `space_ftparser.cpp` of the OceanBase parser plugin to your development directory. Then, you can modify the `space_ftparser.cpp` file to develop your own parser plugin.

**Here is an example:**

```shell
[root@xxx packages]# cp /usr/share/examples/ObPlugin/ftparser/* /home/admin/test_plugin_dev
```

```shell
[root@xxx packages]# ls /home/admin/test_plugin_dev
```

The return result is as follows:

```shell
CMakeLists.txt  space_ftparser.cpp
```

The core file of the sample code is `space_ftparser.cpp`. You can modify this file to implement custom parsing logic based on your business needs.

### Step 3: Compile and install the plugin

1. Modify the build configuration (`CMakeLists.txt`).

    In the root directory of the sample code, you will find a `CMakeLists.txt` file. This file contains "TODO" comments to indicate the parts that you need to modify, including the following parts:

    * `PLUGIN_NAME`: the name of the plugin, which is also the name of the project and the dynamically linked library. Modify it to the name you want.
    * `SOURCES`: the list of implementation files. It can contain C or C++ source files. If you add an implementation file, remember to add the file path in this variable when you modify the build configuration file. Note that header files should not be listed in this variable.

2. Perform the compilation.

    Perform the following steps to compile the code:

   1. Switch to the work directory.

       ```shell
       cd /your/work/path/ftparser
       ```

       Switch to the directory where you want to develop the full-text parser plugin. Please replace `/your/work/path/ftparser` with the actual development directory path.

   2. Create a build directory.

       ```shell
       mkdir -p build
       ```

       Create a directory named `build` for storing intermediate files generated during compilation and the final products. The `-p` option ensures that the command does not fail even if the directory already exists.

   3. Navigate to the build directory.

       ```shell
       cd build
       ```

       Navigate to the `build` directory. Compilation will be performed in this directory, while the source code will remain unchanged to keep it tidy.

   4. Configure the build environment.

       ```shell
       cmake ..
       ```

       Run the `cmake` command to read the `CMakeLists.txt` file located in the parent directory and generate the `Makefile` file required for compilation. `..` indicates that the `CMakeLists.txt` file is located in the parent directory.

   5. Compile the source code.

       ```shell
       make
       ```

       Run the `make` command to compile the source code based on the `Makefile` file and generate a dynamically linked library file (for example, `libexample_ftparser.so`).

       After compilation is successful, the dynamically linked library file will be generated in the current directory (that is, the `build` directory).

3. Copy the compilation results.

    After compilation, the dynamically linked library file (`libexample_ftparser.so`) will be generated in the `build` directory. Copy this file to the `plugin_dir` directory of each observer node in the OceanBase cluster.

    ```shell
    cp libexample_ftparser.so /path/to/plugin_dir/
    ```

    Copy the generated dynamically linked library file to the plugin directory of OceanBase Database. Please replace `/path/to/plugin_dir/` with the actual `plugin_dir` path (which can be obtained by querying the system parameter `plugin_dir`).

4. Load the plugin.

    Log in to OceanBase Database as the sys tenant and modify the configuration parameter `plugins_load` to load the plugin:

    ```shell
    ALTER SYSTEM SET plugins_load='libexample_ftparser.so';
    ```

5. Restart the cluster to make the plugin take effect.

    * For an OceanBase cluster managed by OceanBase Deployer (OBD), you can run the following command to restart the cluster.

        ```shell
        obd cluster restart <cluster_name>
        ```

        Replace `<cluster_name>` with the actual cluster name.

    * For a cluster managed by OceanBase Cloud Platform (OCP), you can directly restart the cluster in OCP.

6. View the installed full-text parser plugins.

    ```sql
    select * from oceanbase.GV$OB_PLUGINS;
    ```

    The return result is as follows:

    ```shell
    +-----------+----------+------------------+--------+----------+------------------------+-----------------+------------------+-------------------+-----------------------+---------------+---------------------------------------------+
    | SVR_IP    | SVR_PORT | NAME             | STATUS | TYPE     | LIBRARY                | LIBRARY_VERSION | LIBRARY_REVISION | INTERFACE_VERSION | AUTHOR                | LICENSE       | DESCRIPTION                                 |
    +-----------+----------+------------------+--------+----------+------------------------+-----------------+------------------+-------------------+-----------------------+---------------+---------------------------------------------+
    | 127.0.0.1 |    55801 | ngram            | READY  | FTPARSER | NULL                   | 1.0.0           | NULL             | 0.1.0             | OceanBase Corporation | Mulan PubL v2 | This is a ngram fulltext parser plugin.     |
    | 127.0.0.1 |    55801 | beng             | READY  | FTPARSER | NULL                   | 1.0.0           | NULL             | 0.1.0             | OceanBase Corporation | Mulan PubL v2 | This is a basic english parser plugin.      |
    | 127.0.0.1 |    55801 | space            | READY  | FTPARSER | NULL                   | 1.0.0           | NULL             | 0.1.0             | OceanBase Corporation | Mulan PubL v2 | This is a default whitespace parser plugin. |
    | 127.0.0.1 |    55801 | example_ftparser | READY  | FTPARSER | libexample_ftparser.so | 1.0.0           | NULL             | 0.1.0             | OceanBase Corporation | Mulan PSL v2  | This is an example ftparser.                |
    +-----------+----------+------------------+--------+----------+------------------------+-----------------+------------------+-------------------+-----------------------+---------------+---------------------------------------------+
    ```

    If `LIBRARY` is `NULL`, it indicates that the full-text parser is built in.

### Step 4: Test the parser plug-in

1. Create a table and use the `WITH PARSER` clause to specify the `example_ftparser` parser.

    ```sql
    CREATE TABLE t_example(
        c1 INT,
        c2 VARCHAR(200),
        c3 TEXT,
        FULLTEXT INDEX (c2, c3) WITH PARSER example_ftparser
    );
    ```

2. Insert the test data into the table.

    ```sql
    INSERT INTO t_example (c1, c2, c3) VALUES
        (1, 'Alice', 'Alice loves programming and enjoys long walks.'),
        (2, 'Bob', 'Bob is an avid reader and a coffee enthusiast.'),
        (3, 'Charlie', 'Charlie is a skilled musician who plays the guitar.'),
        (4, 'Diana', 'Diana is passionate about painting and arts.'),
        (5, 'Eve', 'Eve is a fitness coach and a healthy lifestyle advocate.');
    ```

3. Query records containing the keyword `loves`.

    ```sql
    SELECT * FROM t_example WHERE MATCH(c2, c3) AGAINST ('loves') > 0;
    ```

    The return result is as follows:

    ```shell
    +------+-------+------------------------------------------------+
    | c1   | c2    | c3                                             |
    +------+-------+------------------------------------------------+
    |    1 | Alice | Alice loves programming and enjoys long walks. |
    +------+-------+------------------------------------------------+
    1 row in set
    ```

4. Query records containing the keyword `reader`.

    ```sql
    SELECT * FROM t_example WHERE MATCH(c2, c3) AGAINST ('reader') > 0;
    ```

    The return result is as follows:

    ```shell
    +------+------+------------------------------------------------+
    | c1   | c2   | c3                                             |
    +------+------+------------------------------------------------+
    |    2 | Bob  | Bob is an avid reader and a coffee enthusiast. |
    +------+------+------------------------------------------------+
    1 row in set
    ```

5. Test the parsing scores.

    ```sql
    SELECT c1, 
        MATCH (c2, c3) AGAINST ('he loves programming and reading') AS score,
        c2,
        c3
    FROM t_example;
    ```

    The return result is as follows:

    ```shell
    +------+--------------------+---------+----------------------------------------------------------+
    | c1   | score              | c2      | c3                                                       |
    +------+--------------------+---------+----------------------------------------------------------+
    |    1 |  2.665294094128556 | Alice   | Alice loves programming and enjoys long walks.           |
    |    2 | 0.2849740932642488 | Bob     | Bob is an avid reader and a coffee enthusiast.           |
    |    3 |                  0 | Charlie | Charlie is a skilled musician who plays the guitar.      |
    |    4 | 0.2989130434782609 | Diana   | Diana is passionate about painting and arts.             |
    |    5 | 0.2722772277227723 | Eve     | Eve is a fitness coach and a healthy lifestyle advocate. |
    +------+--------------------+---------+----------------------------------------------------------+
    5 rows in set
    ```
