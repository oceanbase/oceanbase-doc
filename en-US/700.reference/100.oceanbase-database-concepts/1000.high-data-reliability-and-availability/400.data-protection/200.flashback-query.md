# Flashback queries

## UNDO_RETENTION

Literally, `undo_retention` specifies the retention point of undo logs, which is how long undo logs are retained from the current time. For OceanBase Database, this means all multi-version data within this period is retained. You can set this parameter at the tenant level. The default unit is seconds.

## Flashback query

A flashback query allows you to query data of a historical version. OceanBase Database provides the following syntax for queries:

* Oracle mode: `AS OF SCN` and `AS OF TIMESTAMP`.

* MySQL mode: `AS OF SNAPSHOT`.

After you configure the tenant-level parameter `undo_retention`, you can use flashback query to query any multi-version within the time range from `T - undo_retention` to the current time `T`.

## Query replica selection

When you specify a query for data of a historical version, it does not always query the leader like a general query. Instead, it prioritizes querying the replica on the local machine. If the local replica does not exist, it prioritizes querying replicas on other machines in the same zone, and finally queries the leader.

## Considerations

If a DDL operation is performed within the time range from `T - undo_retention` to `T`:

* For add column operations, when you use flashback query to query data before the operation occurred, all newly added columns return default values.

* For create table, drop table, or drop column operations, when you use flashback query to query data before the operation occurred, the system reports an error.
