# Horizontal scaling of tenant resources

Horizontal management of tenant resources is mainly achieved by adjusting the `UNIT_NUM` of a resource pool to dynamically adjust the available resources of a tenant. Specifically, you can adjust the `UNIT_NUM` of a resource pool to change the number of units in each zone for the resource pool, thereby increasing or decreasing the service capacity of the tenant in the corresponding zone.

In the current version of OceanBase Database, the homogeneous zone mode and heterogeneous zone mode are supported for tenants:

* In the homogeneous zone mode, the `UNIT_NUM` of each zone in a tenant must be the same.

* In the heterogeneous zone mode, the `UNIT_NUM` of each zone in a tenant can be the same or different, but a tenant can have at most two different `UNIT_NUM` values across all zones.

<main id="notice" type='notice'>
<h4>Notice</h4>
<p>Generally, existing tenants or upgraded tenants use the homogeneous zone mode by default. To enable the heterogeneous zone mode, set the tenant-level parameter <code>zone_deploy_mode</code> to <code>hetero</code>. After the change, you cannot switch back to <code>homo</code> (homogeneous zone mode).</p>
</main>

Changes to `UNIT_NUM` fall into two categories: increasing and decreasing `UNIT_NUM`:

* For tenants deployed in the homogeneous zone mode:

  * If a resource pool is not assigned to any tenant, you can increase or decrease the `UNIT_NUM` of the resource pool individually.

  * If a resource pool is assigned to a tenant, you can only adjust the `UNIT_NUM` of all resource pools assigned to the tenant at the same time. Individual adjustment is not supported.

* For tenants deployed in the heterogeneous zone mode, you can adjust the `UNIT_NUM` regardless of whether the resource pool is assigned to a tenant. You can adjust the `UNIT_NUM` of all resource pools assigned to a tenant at the same time, or increase or decrease the `UNIT_NUM` of a single resource pool.

Increasing or decreasing `UNIT_NUM` essentially involves adding or deleting units. The following example shows how to adjust the `UNIT_NUM` of a resource pool:

1. For a resource pool in the heterogeneous zone mode, or for a resource pool not assigned to a tenant in the homogeneous zone mode, adjust the `UNIT_NUM` of the resource pool individually.

   Assume the resource pool to be adjusted is as follows:

   ```shell
   obclient> CREATE RESOURCE POOL rp1 UNIT 'uc1', UNIT_NUM 2, ZONE_LIST ('zone1', 'zone2');
   ```

   Adjustment examples:

   ```shell
   obclient> ALTER RESOURCE POOL rp1 UNIT_NUM 3; // Increase UNIT_NUM
   ```

   ```shell
   obclient> ALTER RESOURCE POOL rp1 UNIT_NUM 2; // Decrease UNIT_NUM
   ```

   ```shell
   obclient> ALTER RESOURCE POOL rp1 UNIT_NUM 1 DELETE UNIT = (1001, 1003); // Decrease UNIT_NUM by deleting specified units
   ```

2. Adjust the `UNIT_NUM` of all resource pools of a tenant at the same time.

   Assume the tenant has the following resource pools:

   ```shell
   obclient> CREATE RESOURCE POOL rp2 UNIT 'uc1', UNIT_NUM 2, ZONE_LIST ('zone1', 'zone2');
   ```

   ```shell
   obclient> CREATE RESOURCE POOL rp3 UNIT 'uc1', UNIT_NUM 2, ZONE_LIST ('zone3');
   ```

   ```shell
   obclient> CREATE TENANT tt RESOURCE_POOL_LIST = ('rp2', 'rp3');
   ```

   Adjustment examples:

   ```shell
   obclient> ALTER RESOURCE TENANT tt UNIT_NUM = 3; // Increase UNIT_NUM for both resource pools
   ```

   ```shell
   obclient> ALTER RESOURCE TENANT tt UNIT_NUM = 1; // Decrease UNIT_NUM for both resource pools
   ```

## Increase UNIT_NUM

* Example 1 for increasing `UNIT_NUM`:

  After you create a resource pool, you can increase the `UNIT_NUM` of a single resource pool individually.

  Assume the resource pool to be adjusted is as follows:

  ```shell
  obclient> CREATE RESOURCE POOL r_p0 UNIT 'uc1', UNIT_NUM 2, ZONE_LIST ('zone1', 'zone2', 'zone3');
  ```

  For a resource pool in the heterogeneous zone mode, or for a resource pool not assigned to a tenant in the homogeneous zone mode, use the following statement to increase the `UNIT_NUM` of the resource pool:

  ```shell
  obclient> ALTER RESOURCE POOL r_p0 UNIT_NUM 3;
  ```

* Example 2 for increasing `UNIT_NUM`:

  Increasing `UNIT_NUM` usually occurs in tenant scale-out scenarios. For example, for a resource pool already assigned to a tenant:

  ```shell
  obclient> CREATE RESOURCE POOL r_p0 UNIT 'uc1', UNIT_NUM 2, ZONE_LIST ('zone1', 'zone2', 'zone3');
  ```

  ```shell
  obclient> CREATE TENANT tt RESOURCE_POOL_LIST = ('r_p0');
  ```

  In this example, tenant `tt` uses resource pool `r_p0`. Each of `zone1`, `zone2`, and `zone3` has 2 units. As the business volume grows, 2 units per zone cannot meet the current business load. Therefore, you need to increase `UNIT_NUM` to improve the service capability of the tenant and meet the new business requirements.

  You can use the following statement to change the number of units in resource pool `r_p0` for the tenant to `3`, thereby improving the service capability of the tenant:

  ```sql
  obclient> ALTER RESOURCE TENANT tt UNIT_NUM = 3;
  ```

## Decrease UNIT_NUM

* Example 1 for decreasing `UNIT_NUM`:

  After you create a resource pool, you can decrease the `UNIT_NUM` of a single resource pool individually. Assume the resource pool to be adjusted is as follows.

  ```shell
  obclient> CREATE RESOURCE POOL r_p0 UNIT 'uc1', UNIT_NUM 2, ZONE_LIST ('zone1', 'zone2', 'zone3');
  ```

  For a resource pool in the heterogeneous zone mode, or for a resource pool not assigned to a tenant in the homogeneous zone mode, use the following statement to decrease the `UNIT_NUM` of the resource pool:

  ```shell
  obclient> ALTER RESOURCE POOL r_p0 UNIT_NUM 1;
  ```

  You can also decrease the `UNIT_NUM` of a single resource pool by deleting specified units. Use the following statement:

  ```shell
  obclient> ALTER RESOURCE POOL r_p0 UNIT_NUM 1 DELETE UNIT=(1001,1002,1003);
  ```

* Example 2 for decreasing `UNIT_NUM`:

  Decreasing `UNIT_NUM` usually occurs in tenant scale-in scenarios. For example, for a resource pool already assigned to a tenant:

  ```shell
  obclient> CREATE RESOURCE POOL r_p0 UNIT 'uc1', UNIT_NUM 2, ZONE_LIST ('zone1', 'zone2', 'zone3');
  ```

  ```shell
  obclient> CREATE TENANT tt RESOURCE_POOL_LIST = ('r_p0');
  ```

  In this example, tenant `tt` uses resource pool `r_p0`. Each of `zone1`, `zone2`, and `zone3` has 2 units. As the business adjusts, 2 units per zone are no longer needed. Therefore, you need to decrease `UNIT_NUM` to meet the new business requirements.

  You can use the following statement to change the number of units in resource pool `r_p0` for the tenant to `1`, thereby reducing the service capability of the tenant:

  ```shell
  obclient> ALTER RESOURCE TENANT tt UNIT_NUM = 1;
  ```

  Alternatively, in the homogeneous zone mode, you can also decrease `UNIT_NUM` by deleting a specified `UNIT_GROUP`.

  ```shell
  obclient> ALTER RESOURCE TENANT tt  UNIT_NUM = 1 DELETE UNIT_GROUP =(1001);
  ```
