# Stored procedures

A stored procedure is a subprogram that does not return a value. However, when a parameter type is set to OUT, the stored procedure can return a value to the caller.

## Structure of a stored procedure

The structure of a stored procedure is as follows:

```sql
CREATE
    [DEFINER = user]
    PROCEDURE sp_name ([proc_parameter[,...]])
    [characteristic ...] routine_body

proc_parameter:
    [ IN | OUT | INOUT ] param_name type

characteristic: {
    COMMENT 'string'
  | LANGUAGE SQL
  | [NOT] DETERMINISTIC
  | { CONTAINS SQL | NO SQL | READS SQL DATA | MODIFIES SQL DATA }
  | SQL SECURITY { DEFINER | INVOKER }
}

routine_body:
    Valid SQL routine statement
```

## Creation of a stored procedure

You can execute the `CREATE PROCEDURE` statement to create a stored procedure. The MySQL mode differs from the Oracle mode in the following aspects:

* In the MySQL mode, the `DECLARE` block must be placed within the `BEGIN END;` block, and all declarations must be completed before you define other statements.

* You can add subprogram characteristics such as the deterministic attribute and the SQL standard attribute to enhance the functionality of stored procedures.

* In the MySQL mode, stored procedures do not support overloading. Therefore, when you delete a stored procedure, you do not need to consider the parameter types.

Here is an example:

```sql
obclient> DELIMITER /
obclient> CREATE TABLE city(CountryCode CHAR(3))/
Query OK, 0 rows affected

obclient> CREATE PROCEDURE citycount (IN country CHAR(3), OUT cities INT)
     BEGIN
        SELECT COUNT(*) INTO cities FROM city
         WHERE CountryCode = country;
     END/
Query OK, 0 rows affected 
```

## Calling a stored procedure

You can execute the `CALL` statement to call a stored procedure that has been created, but you cannot call it as part of an SQL expression.

```sql
obclient> CALL citycount('JPN', @cities);/
+--------+
| cities |
+--------+
|      0 |
+--------+
1 row in set 

obclient> SELECT @cities/
+---------+
| @cities |
+---------+
|       0 |
+---------+
1 row in set 

obclient> DROP PROCEDURE citycount/
Query OK, 0 rows affected
```
