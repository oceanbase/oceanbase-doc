# Full-text indexes

In MySQL mode of OceanBase Database, full-text indexes can be created on columns of the `CHAR`, `VARCHAR`, and `TEXT` data types. OceanBase Database allows multiple full-text indexes to be created on a primary table, and multiple full-text indexes can also be created on the same column.

Full-text indexes can be created on non-partitioned tables and partitioned tables, regardless of whether they have a primary key. The following limitations apply when creating full-text indexes:

* Full-text indexes can only be created on columns of the `CHAR`, `VARCHAR`, and `TEXT` data types.
* Only local (`LOCAL`) full-text indexes can be created in the current version.
* The `UNIQUE` keyword cannot be specified when creating a full-text index.
* If you want to create a full-text index that involves multiple columns, these columns must have the same character set.

By using these syntaxes and rules, the full-text index feature of OceanBase Database provides efficient search and retrieval capabilities for text data.

## DML operations

For a table with a full-text index, you can perform complex DML operations such as `INSERT INTO ON DUPLICATE KEY`, `REPLACE INTO`, multi-table updates and deletes, and updates on updatable views.

**Here are some examples:**

* `INSERT INTO ON DUPLICATE KEY`:

    ```sql
    INSERT INTO articles VALUES ('OceanBase', 'Fulltext search index support insert into on duplicate key')
        ON DUPLICATE KEY UPDATE title = 'OceanBase 4.3.3';
    ```

* `REPLACE INTO`:

    ```sql
    REPLACE INTO articles(title, context) VALUES ('Oceanbase 4.3.3', 'Fulltext search index support replace');
    ```

* Multi-table updates and deletes.

  1. Create a table named `tbl1`.

     ```sql
     CREATE TABLE tbl1 (a int PRIMARY KEY, b text, FULLTEXT INDEX(b));
     ```

  2. Create a table named `tbl2`.

     ```sql
     CREATE TABLE tbl2 (a int PRIMARY KEY, b text);
     ```

  3. Perform an update (`UPDATE`) on multiple tables.

     ```sql
     UPDATE tbl1 JOIN tbl2 ON tbl1.a = tbl2.a
         SET tbl1.b = 'dddd', tbl2.b = 'eeee';
     ```

     ```sql
     UPDATE  tbl1 JOIN tbl2 ON tbl1.a = tbl2.a SET tbl1.b = 'dddd';
     ```

     ```sql
     UPDATE tbl1 JOIN tbl2 ON tbl1.a = tbl2.a SET tbl2.b = tbl1.b;
     ```

  4. Perform a delete (`DELETE`) on multiple tables.

     ```sql
     DELETE tbl1, tbl2 FROM tbl1 JOIN tbl2 ON tbl1.a = tbl2.a;
     ```

     ```sql
     DELETE tbl1 FROM tbl1 JOIN tbl2 ON tbl1.a = tbl2.a;
     ```

     ```sql
     DELETE tbl1 FROM tbl1 JOIN tbl2 ON tbl1.a = tbl2.a;
     ```

* DML operations on updatable views.

  1. Create a view named `fts_view`.

     ```sql
     CREATE VIEW fts_view AS SELECT * FROM tbl1;
     ```

  2. Perform an `INSERT` operation on the updatable view.

     ```sql
     INSERT INTO fts_view VALUES(3, 'cccc'), (4, 'dddd');
     ```

  3. Perform an `UPDATE` operation on the updatable view.

     ```sql
     UPDATE fts_view SET b = 'dddd';
     ```

     ```sql
     UPDATE fts_view JOIN normal ON fts_view.a = tbl2.a
        SET fts_view.b = 'dddd', tbl2.b = 'eeee';
     ```

  4. Perform a `DELETE` operation on the updatable view.

     ```sql
     DELETE FROM fts_view WHERE b = 'dddd';
     ```

     ```sql
     DELETE tbl1 FROM fts_view JOIN tbl1 ON fts_view.a = tbl1.a AND 1 = 0;
     ```

## Full-text index tokenizer

OceanBase Database supports multiple built-in tokenizers for full-text indexes, allowing users to select the optimal text tokenization strategy based on their business scenarios. The default tokenizer is **Space tokenizer**. Other tokenizers must be explicitly specified using the `WITH PARSER` parameter.

**List of tokenizers**:  

* **Space tokenizer**  
* **Basic English tokenizer**  
* **IK tokenizer**
* **Ngram tokenizer**
* **jieba tokenizer**

**Configuration method**:  

When creating or modifying a table, use the `CREATE TABLE` or `ALTER TABLE` statement to specify the tokenizer type for the full-text index by setting the `WITH PARSER tokenizer_option` parameter. For more information about the parameters of other tokenizers, see [Create an index](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002015436).

```sql
CREATE TABLE tbl2(id INT, name VARCHAR(18), doc TEXT,
    FULLTEXT INDEX full_idx1_tbl2(name, doc)
      WITH PARSER NGRAM
      PARSER_PROPERTIES=(ngram_token_size=3));


-- Modify the tokenizer for the full-text index of an existing table  
ALTER TABLE tbl2(id INT, name VARCHAR(18), doc TEXT,
    FULLTEXT INDEX full_idx1_tbl2(name, doc)
      WITH PARSER NGRAM
      PARSER_PROPERTIES=(ngram_token_size=3));  -- Ngram example  
```

### Space tokenizer (default)

**Concepts**:

* Splits text using spaces, punctuation marks (such as commas and periods), or non-alphanumeric characters (excluding underscores `_`).
* The tokenization results only include valid tokens with lengths between `min_token_size` (default 3) and `max_token_size` (default 84).
* Chinese characters are treated as single-character tokens.

**Scenarios**:

* For languages that use spaces to separate words, such as English ("apple watch series 9").
* For Chinese text with manually added separators, such as "Nanjing Yangtze River Bridge".

**Tokenization effect**:

```shell
OceanBase（rooteoceanbase）>select tokenize("Nanjing Yangtze River Bridge is 1 km long, see details at www.XXX.COM, email xx@OB.COM, one square kilometer is also small hello-word h_name", 'space');
+-------------------------------------------------------------------------------------------------------------+
| tokenize("Nanjing Yangtze River Bridge is 1 km long, see details at www.XXX.COM, email xx@OB.COM, one square kilometer is also small hello-word h_name", 'space')   |
+-------------------------------------------------------------------------------------------------------------+
|［"see details at www", "one square kilometer is also small", "xxx", "Nanjing Yangtze River Bridge is 1 km long", "email xx", "word", "hello", "h_name"］             |
+-------------------------------------------------------------------------------------------------------------+
```

**Example explanation**:

* Spaces, commas, periods, and other symbols are used as separators. Continuous Chinese characters are treated as words.

### Basic English (Beng) tokenizer

**Concepts**:

* Similar to the Space tokenizer, but underscores `_` are not preserved and are treated as separators.
* Suitable for splitting English phrases but may not effectively split terms without spaces, such as "iPhone15".

**Scenarios**:

* For basic retrieval of English documents, such as logs and comments.

**Tokenization effect**:

```shell
OceanBase（rooteoceanbase）>select tokenize("Nanjing Yangtze River Bridge is 1 km long, see details at WWW.XXX.COM, email xx@OB.COM, one square kilometer is also small hello-word h_name", 'beng');
+-----------------------------------------------------------------------------------------------------------------------+
| tokenize("Nanjing Yangtze River Bridge is 1 km long, see details at WWW.XXX.COM, email xx@OB.COM, one square kilometer is also small hello-word h_name", 'beng')                 |
+-----------------------------------------------------------------------------------------------------------------------+
|["see details at www", "one square kilometer is also small", "xxx", "Nanjing Yangtze River Bridge is 1 km long", "email xx", "word", "hello", "name"]                              |
+-----------------------------------------------------------------------------------------------------------------------+
```

**Example explanation**:

* Underscores `_` are split. The core difference from the Space tokenizer is how underscores `_` are handled.

### Ngram tokenizer

**Concepts**：

* **Fixed n-value tokenization**: By default, `n=2` splits consecutive non-separator characters into subsequences of length `n`.
* Separator determination rules are the same as in the Space tokenizer (retains `_` and alphanumeric characters).
* **Length limit parameter is not supported**, outputting all possible `n`-length tokens.

**Use Cases**:

* Fuzzy matching in short texts (e.g., user IDs, order numbers).
* Scenarios requiring fixed-length feature extraction (e.g., password policy analysis).

**Tokenization Effect**:

```shell
OceanBase（rooteoceanbase）>select tokenize("Nanjing Yangtze River Bridge is 1 kilometer long, see WWW.XXX.COM, email xx@OB.COM, 1 square kilometer is very small hello-word h_name", 'ngram');
+---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| tokenize("Nanjing Yangtze River Bridge is 1 kilometer long, see WWW.XXX.COM, email xx@OB.COM, 1 square kilometer is very small hello-word h_name", 'ngram')                     |
+---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
|［"email", "ww", "Bridge", "ob", "me", "is", "or", "_n", "kilometer", "small", "long", "ll", "xx", "square kilometer", "co", "also", "1 thousand", "Nanjing", "lo", "Yangtze", "el", "rd", "square", "area", "he", "am", "Nanjing", "h_", "City", "wo", "xx", "Yangtze River", "is 1", "na", "see", "area", "om", "bridge"   |
+---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
```

**Example Explanation**:

* When `n=2` is default, all 2-character tokens are output, including overlapping tokens.

### Ngram2 tokenizer

**Concepts**：

* Supports **dynamic n-value range**: The token length range is set by `min_ngram_size` and `max_ngram_size`.
* Suitable for scenarios requiring coverage across multiple token lengths.

**Use Cases**: Scenarios requiring multiple fixed-length tokens.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>When using the ngram2 tokenizer, note that it has high memory usage. For example, when setting the <code>min_ngram_size</code> and <code>max_ngram_size</code> parameters to a wide range, it can generate a large number of token combinations, potentially causing excessive resource consumption.</p>
</main>

**Tokenization Effect**:

```sql
OceanBase（rooteoceanbase）>select tokenize("Nanjing Yangtze River Bridge 1 kilometer", 'ngram2', '[{"additional_args":[{"min_ngram_size": 4},{"max_ngram_size": 6}]}]');
+----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| tokenize("Nanjing Yangtze River Bridge 1 kilometer", 'ngram2', '[{"additional_args":[{"min_ngram_size": 4},{"max_ngram_size": 6}]}]')                                                                                                              |
+----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| ["Yangtze River Bridge", "Bridge 1 kilometer", "River Bridge 1 kilometer", "Nanjing Yangtze", "Jiangnan Yangtze River", "River Bridge 1", "Nanjing", "Yangtze River", "Bridge 1 kilometer", "River Bridge 1 kilometer", "Nanjing Yangtze River", "Yangtze River Bridge", "Nanjing Yangtze River", "Bridge 1 kilometer", "Nanjing Yangtze River", "Yangtze River Bridge 1 kilometer", "Jiangnan Yangtze River Bridge", "Jiangnan Yangtze River"        |
+----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
```

**Example Explanation**:

* Outputs all 4-6-character-length continuous subsequences, and tokens can overlap.

### IK Analyzer

**Concepts**:

* Chinese tokenizer based on the open-source IK Analyzer, supporting two modes:

  * **Smart mode**: Priority is given to outputting long words and reducing the number of divisions (such as not dividing "Nanjing City" into "Nanjing" and "City").
  * **Max Word Mode**: Outputs all possible subwords of each word. For example, "Nanjing" is segmented into "Nanjing" and "City".

* Automatically recognize format of English words, e-mail addresses, URLs (excluding `://`), IP addresses, etc.

**Scenario**: Chinese word segmentation.

**Scenario**:

*  E-commerce product descriptions (e.g., "Huawei Mate60").
* Analysis of social media content (e.g., keyword extraction from user comments).

* **Smart mode** : Ensures that characters are allocated to only one word, without any overlap, and maximizes the length of each word while minimizing the total number of words. This mode will attempt to combine numbers with measure words into a single word.

```sql
OceanBase (rooteoceanbase)> SELECT tokenize("The Nanjing Yangtze River Bridge is 1 kilometer long, for more details, see WWW.XXX.COM. Contact us by email at xx@OB.COM, or connect via 192.168.1.1. You can also visit http://www.baidu.com for more information. Keywords: hello-word, hello_word", 'IK', '[{"additional_args":[{"ik_mode": "smart"}]}]');
+---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| tokenize("The Nanjing Yangtze River Bridge is 1,000 meters long. Details can be found at WWW.XXX.COM. Email: xx@OB.COM 192.168.1.1 http://www.baidu.com hello-word hello_word", 'IK', '[{"additional_args":[{"ik_mode": "smart"}]}]')                                                                                                      |
+---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
|["Email", "hello_word", "192.168.1.1", "hello-word", "Yangtze River Bridge", "www.baidu.com", "www.xxx.com", "xx@ob.com", "Length", "http", "1,000m", "Details", "Nanjing", "Yes"]                                                         |
+---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
```

* **max_word mode**:  will include the same character in different tokenizations and provide as many possible words as possible.

```sql
OceanBase (rooteoceanbase) >select tokenize("The Nanjing Yangtze River Bridge is 1 kilometer long, for details, visit WWW.XXX.COM, contact email xx@OB.COM", 'IK', '[{"additional_args":[{"ik_mode": "max_word"}]}]');
+-----------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| tokenize("Nanjing Yangtze River Bridge is 1 km long, see WWW.XXX.COM, email xx@OB.COM", 'IK', '[{"additional_args":[{"ik_mode": "max_word"}]}]')                                                |
+-----------------------------------------------------------------------------------------------------------------------------------------------------------------------+
|["meters", "Yangtze River Bridge", "mayor", "dry", "Nanjing City", "Nanjing", "kilometer", "xx", "www.xxx.com", "long", "www", "xx@ob.com", "Yangtze River", "ob", "XXX", "com", "see details", "l", "has", "bridge", "email"]       |
+-----------------------------------------------------------------------------------------------------------------------------------------------------------------------+
```

### jieba tokenizer

**Concept**: Based on the `jieba` open-source tool in Python's ecosystem. The segmenter supports precise, full, and search engine modes.

**Features**:

* **Precision mode**：Strictly segment by dictionary (e.g., "cannot" is not split into "not" and "can").
* **Full mode**: lists all the possible split combinations.
* **Search Engine mode**: Balances precision and recall by returning results that are related to both the exact term and its variations (e.g., "Nanjing Yangtze River Bridge" returns results containing "Nanjing," "Yangtze River," and "Bridge").
* Supports custom dictionaries and new word discovery, and is compatible with multiple languages (e.g., Chinese, English, Japanese).

**Scenarios**：

* Analyzes industry-specific terminology in health and technology fields (such as "AI" being segmented precisely).
* Handling multilingual mixed-text content (such as Chinese-English mixed content on social media).

The jieba tokenizer needs to be installed separately. The installation steps are as follows: [Tokenizer plugin](../../../../1600.oceanbase-database-plugin/200.tokenizer-plugin.md)

### Tokenizer selection strategy

| **Business scenario** | **Recommended tokenizer** | **Reason** |
| --- | --- | --- |
| Search for English product titles | **Space or Basic English** | Simple and efficient, aligning with English tokenization habits. |
| Retrieval of Chinese product descriptions | **IK Tokenizer** | Accurately identifies Chinese terminology and supports custom dictionaries. |
| Fuzzy matching in logs (e.g., error codes) | **Ngram Tokenizer** | No dictionary required, covering fuzzy query needs for text without spaces. |
| Keyword extraction from scientific papers | **jieba Tokenizer** | Supports new word discovery and complex pattern switching. |
