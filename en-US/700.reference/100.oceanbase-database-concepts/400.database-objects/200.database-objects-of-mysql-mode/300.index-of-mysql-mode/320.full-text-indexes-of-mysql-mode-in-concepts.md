# Full-text index

In OceanBase Database's MySQL mode, full-text indexes can be created on `CHAR`, `VARCHAR`, and `TEXT` columns. Additionally, OceanBase Database allows multiple full-text indexes to be created on the primary table, and multiple full-text indexes can also be created on the same column.

Full-text indexes can be created on both non-partitioned and partitioned tables, regardless of whether they have a primary key. The following limitations apply when creating a full-text index:

* Full-text indexes can only be created on `CHAR`, `VARCHAR`, and `TEXT` columns.
* Only local (`LOCAL`) full-text indexes are supported in the current version.
* The `UNIQUE` keyword cannot be specified when creating a full-text index.
* If you want to create a full-text index involving multiple columns, ensure that these columns have the same character set.

By using these syntaxes and rules, OceanBase Database's full-text index feature provides efficient search and retrieval capabilities for text data.

## DML operations

For tables that contain full-text indexes, you can perform complex DML operations such as `INSERT INTO ON DUPLICATE KEY`, `REPLACE INTO`, updates and deletes on multiple tables, and updates on updatable views.

**Here are some examples:**

* `INSERT INTO ON DUPLICATE KEY`:

    ```sql
    INSERT INTO articles VALUES ('OceanBase', 'Fulltext search index support insert into on duplicate key')
        ON DUPLICATE KEY UPDATE title = 'OceanBase 4.3.3';
    ```

* `REPLACE INTO`:

    ```sql
    REPLACE INTO articles(title, context) VALUES ('Oceanbase 4.3.3', 'Fulltext search index support replace');
    ```

* Updates and deletes on multiple tables.

  1. Create a table named `tbl1`.

     ```sql
     CREATE TABLE tbl1 (a int PRIMARY KEY, b text, FULLTEXT INDEX(b));
     ```

  2. Create a table named `tbl2`.

     ```sql
     CREATE TABLE tbl2 (a int PRIMARY KEY, b text);
     ```

  3. Execute an `UPDATE` statement on multiple tables.

     ```sql
     UPDATE tbl1 JOIN tbl2 ON tbl1.a = tbl2.a
         SET tbl1.b = 'dddd', tbl2.b = 'eeee';
     ```

     ```sql
     UPDATE  tbl1 JOIN tbl2 ON tbl1.a = tbl2.a SET tbl1.b = 'dddd';
     ```

     ```sql
     UPDATE tbl1 JOIN tbl2 ON tbl1.a = tbl2.a SET tbl2.b = tbl1.b;
     ```

  4. Execute a `DELETE` statement on multiple tables.

     ```sql
     DELETE tbl1, tbl2 FROM tbl1 JOIN tbl2 ON tbl1.a = tbl2.a;
     ```

     ```sql
     DELETE tbl1 FROM tbl1 JOIN tbl2 ON tbl1.a = tbl2.a;
     ```

     ```sql
     DELETE tbl1 FROM tbl1 JOIN tbl2 ON tbl1.a = tbl2.a;
     ```

* DML operations on updatable views.

  1. Create an updatable view named `fts_view`.

     ```sql
     CREATE VIEW fts_view AS SELECT * FROM tbl1;
     ```

  2. Execute an `INSERT` statement on the updatable view.

     ```sql
     INSERT INTO fts_view VALUES(3, 'cccc'), (4, 'dddd');
     ```

  3. Execute an `UPDATE` statement on the updatable view.

     ```sql
     UPDATE fts_view SET b = 'dddd';
     ```

     ```sql
     UPDATE fts_view JOIN normal ON fts_view.a = tbl2.a
        SET fts_view.b = 'dddd', tbl2.b = 'eeee';
     ```

  4. Execute a `DELETE` statement on the updatable view.

     ```sql
     DELETE FROM fts_view WHERE b = 'dddd';
     ```

     ```sql
     DELETE tbl1 FROM fts_view JOIN tbl1 ON fts_view.a = tbl1.a AND 1 = 0;
     ```

## Full-text index tokenizer

OceanBase Database provides multiple built-in tokenizers for full-text indexes to help you select the optimal text tokenization strategy based on your business scenarios. By default, the **Space tokenizer** is used. To use other tokenizers, you must explicitly specify the `WITH PARSER` parameter.  

**Tokenizers**:  

* **Space tokenizer**  
* **Basic English tokenizer**  
* **IK tokenizer**
* **Ngram tokenizer**
* **Jieba tokenizer**

**Configuration examples**:

When you create or modify a table, you can specify the tokenizer for a full-text index by using the `WITH PARSER tokenizer_option` parameter in the `CREATE TABLE` or `ALTER TABLE` statement. For more information about the parameters of other tokenizers, see [Create an index](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002015436).

```sql
CREATE TABLE tbl2(id INT, name VARCHAR(18), doc TEXT,
    FULLTEXT INDEX full_idx1_tbl2(name, doc)
      WITH PARSER NGRAM
      PARSER_PROPERTIES=(ngram_token_size=3));


-- Modify the tokenizer for a full-text index of an existing table.  
ALTER TABLE tbl2(id INT, name VARCHAR(18), doc TEXT,
    FULLTEXT INDEX full_idx1_tbl2(name, doc)
      WITH PARSER NGRAM
      PARSER_PROPERTIES=(ngram_token_size=3));  -- Ngram example
```

### Space tokenizer (default)

**Concepts**:

* Splits text using spaces, punctuation marks (such as commas and periods), or non-alphanumeric characters (excluding underscores `_`).
* The tokenization results only include valid tokens with lengths between `min_token_size` (default 3) and `max_token_size` (default 84).
* Chinese characters are treated as single-character tokens.

**Scenarios**:

* For languages separated by spaces, such as English (e.g., "apple watch series 9").
* For Chinese text with manually added separators, such as "Nanjing Yangtze River Bridge".

**Tokenization effect**:

```shell
OceanBase（rooteoceanbase）>select tokenize("Nanjing Yangtze River Bridge is 1 km long, see details at www.XXX.COM, email xx@OB.COM, one square kilometer is also small hello-word h_name", 'space');
+-------------------------------------------------------------------------------------------------------------+
| tokenize("Nanjing Yangtze River Bridge is 1 km long, see details at www.XXX.COM, email xx@OB.COM, one square kilometer is also small hello-word h_name", 'space')   |
+-------------------------------------------------------------------------------------------------------------+
|［"see details at www", "one square kilometer is also small", "xxx", "Nanjing Yangtze River Bridge is 1 km long", "email xx", "word", "hello”, "h_name"］             |
+-------------------------------------------------------------------------------------------------------------+
```

**Example explanation**:

* Spaces, commas, periods, and other symbols are used as separators. Continuous Chinese characters are treated as words.

### Basic English (Beng) tokenizer

**Concepts**:

* Similar to the Space tokenizer, but underscores `_` are not preserved and are treated as separators.
* Suitable for splitting English phrases, but may not effectively split terms without spaces, such as "iPhone15".

**Scenarios**:

* For basic retrieval of English documents, such as logs and comments.

**Tokenization effect**:

```shell
OceanBase（rooteoceanbase）>select tokenize("Nanjing Yangtze River Bridge is 1 km long, see details at WWW.XXX.COM, email xx@OB.COM, one square kilometer is also small hello-word h_name", 'beng');
+-----------------------------------------------------------------------------------------------------------------------+
| tokenize("Nanjing Yangtze River Bridge is 1 km long, see details at WWW.XXX.COM, email xx@OB.COM, one square kilometer is also small hello-word h_name", 'beng')                 |
+-----------------------------------------------------------------------------------------------------------------------+
|["see details at www", "one square kilometer is also small", "xxx", "Nanjing Yangtze River Bridge is 1 km long", "email xx", "word", "hello", "name"]                              |
+-----------------------------------------------------------------------------------------------------------------------+
```

**Example explanation**:

* Underscores `_` are split. The core difference from the Space tokenizer is how underscores `_` are handled.

### Ngram tokenizer

**Concept**:

* **Fixed n-gram tokenization**: Defaults to `n=2` and splits a sequence of consecutive non-separator characters into subsequences of length `n`.
* The delimiter determination rules are the same as those of the space tokenizer, with `_` and alphanumeric characters preserved.
* **Length limit parameters are not supported.** Output all possible `n`-length terms.

**Scenarios**:

* Short-text fuzzy matching (such as user ID, order ID).
* Use cases where fixed-length feature extraction is needed, such as password strategy analysis.

**Tf-idf values**:

```shell
OceanBase (rooteoceanbase) > select tokenize ("Nanjing Yangtze River Bridge is 1 km long, details see WWW.XXX.COM, e-mail: xx@ob.com, 1 square kilometer is very small hello-word h_name", 'ngram');
+---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| tokenize("Nanjing Yangtze River Bridge is 1 km long, details at WWW.XXX.COM, email xx@OB.COM, one square kilometer is also quite small hello-word h_name", 'ngram')                     |
+---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
|［"Email", "ww", "Bridge", "ob", "me", "Liye", "or", "_n", "Kilometer", "Very small", "Long in meters", "ll", "Boxx", "Kilometers", "See w", "co", "Also", "1,000", "Beijing", "lo", "Jiangda", "el", "rd", "One", "Square", "he", "am", "Nanjing", "h_", "Mayor", "wo", "xx", "Yangtze River", "Has 1", "na", "Details", "Square", "om", "Bridge has"   |
+---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
```

**Example** :

* By default, `n=2` outputs all continuous 2-character tokens, including overlapping tokens.

### Ngram2 tokenizer

**Concepts**:

* Supports **dynamic n value range**: specify the ngram range by using the `min_ngram_size` and `max_ngram_size` parameters.
* Used in scenarios where tokens of different lengths need to be covered.

**Scenarios**: When you need multiple fixed-length tokens.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>When using the NGram2 tokenizer, it can have high memory usage. For example, setting a wide range for <code>min_ngram_size</code> and <code>max_ngram_size</code> parameters can generate a large number of term combinations, leading to significant resource consumption. </p>
</main>

**Tokenization results**:

```sql
The execution result is as follows:
+----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| tokenize("Nanjing Yangtze River Bridge 1 km", 'ngram2', '[{"additional_args":[{"min_ngram_size": 4},{"max_ngram_size": 6}]}]')                                                                                                               |
+----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| ["Changjiang Bridge", "Bridge 1,000", "Changjiang Bridge 1,000", "Mayor's Bridge", "Beijing's Changjiang", "Changjiang Bridge 1", "Nanjing Mayor", "Changjiang Mayor's Bridge", "Bridge 1 kilometer", "Changjiang Bridge 1 kilometer", "Mayor's Changjiang Bridge 1", "Changjiang Bridge 1", "Nanjing Mayor's Changjiang", "Bridge 1 kilometer", "Nanjing Mayor's Changjiang Bridge", "Changjiang Bridge 1,000", "Beijing's Changjiang Bridge", "Beijing's Changjiang Mayor's"       |
+----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
```

**Example**：

* Find all continuous substrings with lengths ranging from 4 to 6 characters, allowing for overlapping elements.

### IK Analyzer

**Concept**：

* The Chinese Analyzer, based on the open-source IK Analyzer tool, supports two modes:

  * **Smart mode**：Preferentially outputs longer words, reducing the number of splits (e.g., "Nanjing City" without splitting into "Nanjing" and "City").
  * **Max Word mode**：output all possible short words (e.g. split "Nanjing City" into "Nanjing" and "City").

* Automatic detection of words, emails, URLs (excluding `://`), IP addresses, and other formats.

**Use case**: Chinese tokenization

**Scenario**:

* Search for product descriptions from e-commerce platforms (e.g., exact match for "Huawei Mate 60" ).
* Social media content analysis (e.g., keyword extraction from user comments).

* **Smart mode**: Each character is assigned to only one term, ensuring no overlaps and that the terms are as long as possible. It aims to minimize the number of terms generated. It also attempts to combine numerical and measure terms into a single term.

```sql
OceanBase (rooteoceanbase) > select tokenize("The Nanjing Yangtze River Bridge is 1,000 meters long. Details can be found at WWW.XXX.COM, Email: xx@OB.COM, IP address: 192.168.1.1, and URL: http://www.baidu.com. hello-word and hello_word", 'IK', "[{'additional_args':[{'ik_mode': 'smart'}]}]");
+---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| tokenize("The Nanjing Yangtze River Bridge, which has a length of 1km, is described in detail at www.xxx.com, E-mail to xx@ob.com, IP address 192.168.1.1, and more information can be found at http://www.baidu.com, hello-word and hello_word", 'IK', '[{"additional_args":[{"ik_mode": "smart"}]}]')                                                                                                      |
+---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
|["Email", "hello_word", "192.168.1.1", "hello-word", "Changjiang Bridge", "www.baidu.com", "www.xxx.com", "xx@ob.com", "Long", "http", "1 km", "see", "Nanjing city", "yes"]                                                         |
+---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
```

* **max_word mode** : this mode includes the same character into different words and maximizes the possible words.

```sql
OceanBase (rooteoceanbase) > SELECT tokenize('The Nanjing Yangtze River Bridge is 1 kilometer long, for details, visit WWW.XXX.COM and contact xx@OB.COM', 'IK', '[{"additional_args":[{"ik_mode": "max_word"}]}]');
+-----------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| tokenize("The Nanjing Yangtze River Bridge is 1 km long. See more at WWW.XXX.COM, email at xx@OB.COM", 'IK', '[{"additional_args":[{"ik_mode": "max_word"}]}]')                                                |
+-----------------------------------------------------------------------------------------------------------------------------------------------------------------------+
|["m", "River", "mayor", "dry", "Nanjing City", "Nanjing", "kilometers", "xx", "www.xxx.com", "long", "www", "xx@ob.com", "River", "ob", "XXX", "com", "see details", "l", "there is", "bridge", "email"]       |
+-----------------------------------------------------------------------------------------------------------------------------------------------------------------------+
```

### jieba Tokenizer

**Concept**: A tokenizer based on the open-source Python tool `jieba` supports accurate mode, full mode, and search engine mode.

**Features** :

* **Precise mode**: strictly segment by dictionary (such as "can't" not segmented into "can" and "not").
* **All**: Lists all possible splitting combinations.
* **Search engine mode**: balances precision and recall (e.g., "Nanjing Long River Bridge" → "Nanjing," "Mayor," and "Long River Bridge").
* Supports custom dictionaries and new word discovery, and is compatible with multiple languages (Chinese, English, Japanese, etc.).

**Use cases**:

* Terms in the medical and technology field (such as the accurate segmentation of terms like "artificial intelligence").
* Processing multilingual mixed text (e.g., social media content with Chinese and English).

You need to install the jieba tokenizer manually. For more information, see [Tokenizer plug-in](../../../../1600.oceanbase-database-plugin/200.tokenizer-plugin.md).

### Tokenizer selection strategy

| **Business scenario** | **Recommended tokenizer** | **Reason** |
| --- | --- | --- |
| Search for English product titles | **Space or Basic English** | Simple and efficient, aligns with English tokenization habits. |
| Retrieval of Chinese product descriptions | **IK Tokenizer** | Accurately identifies Chinese terms and supports custom dictionaries. |
| Fuzzy matching in logs (e.g., error codes) | **Ngram Tokenizer** | No dictionary required, covers fuzzy query needs for text without spaces. |
| Keyword extraction from scientific papers | **jieba Tokenizer** | Supports new word discovery and complex pattern switching. |
