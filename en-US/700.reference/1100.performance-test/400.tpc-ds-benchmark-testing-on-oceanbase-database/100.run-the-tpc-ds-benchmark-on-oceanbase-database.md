# OceanBase Database TPC-DS testing

This topic describes the software requirements, tenant specifications, and detailed test procedures for running TPC-DS tests on OceanBase Database.

## What is TPC-DS

TPC-DS (Transaction Processing Performance Council Decision Support Benchmark) is a data warehouse performance testing standard established by the international organization TPC. It adopts a hybrid design of the snowflake and star schemas, comprising 7 fact tables and 17 dimension tables, covering business scenarios such as retail and finance. The test process includes: generating scalable test data (supporting a scale factor from 1 TB to 100 TB), and executing 99 complex SQL queries (covering scenarios such as statistics, reporting, and data mining). Ultimately, it evaluates the system's processing capability under high concurrency and large data volumes through metrics such as QphDS (Queries Per Hour).

As an upgraded version of TPC-H, TPC-DS features a more complex data model (TPC-H has only 8 tables), richer query types, and support for OLAP operations, making it the current mainstream decision support benchmark.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>To improve user experience and ease of use, and to help every developer achieve good performance when using the database, OceanBase Database has been extensively optimized since version V4.0.0. This performance test method is tuned based only on basic parameters, so that developers can get a good database performance experience.</p>
</main>

## Prepare the environment

Before you perform the test, prepare the test environment as follows:

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This example uses a MySQL-compatible tenant.</p>
</main>

### Software requirements

* JDK: Java Development Kit 1.8u131 or later is recommended.

* make: Install it by running the `yum install make` command.

* GCC: Install it by running the `yum install gcc` command.

* mysql-devel: Install it by running the `yum install mysql-devel` command.

* Python database driver: Install it by running the `sudo yum install MySQL-python` command.

* prettytable: Install it by running the `pip install prettytable` command.

* JDBC: We recommend that you use `mysql-connector-java-5.1.47`.

* TPC-DS Tool: Click [Download](https://www.tpc.org/TPC_Documents_Current_Versions/download_programs/tools-download-request5.asp?bm_type=TPC-DS&bm_vers=3.2.0&mode=CURRENT-ONLY) to obtain it. If you use one-click testing with OBD, you can skip this tool.

* OBClient: For more information, see [OBClient documentation](https://github.com/oceanbase/obclient/blob/master/README.md).

* OceanBase Database: For more information, see [Quickly get started with OceanBase Database](../../../200.quickstart/100.quickly-experience-oceanbase-for-community.md).

* IOPS: We recommend that the disk IOPS be above 10,000.

### Configure tenant specifications

Tenant specifications are configured based on the hardware configuration in the <a href="200.tpc-ds-benchmark-report-of-oceanbase-database.md">OceanBase Database TPC-DS benchmark report</a>. You need to adjust them based on your actual hardware configuration.

* **Cluster deployment**

   1. This test requires four machines. TPC-DS and OBD are deployed on a separate machine, which serves as the stress machine for clients. To deploy the OceanBase cluster using OBD, three additional machines are required, with the OceanBase cluster scaled at a ratio of 1:1:1.

      <main id="notice" type='explain'>
         <h4>Note</h4>
         <ul>
         <li>For the TPC-DS test, the machine hosting TPC-DS and OBD only needs 4 cores and 16 GB of memory.</li>
         <li>When deploying the cluster, it is recommended not to use the <code>obd cluster autodeploy</code> command. To ensure stability, this command does not maximize resource utilization (for example, it does not use all memory). It is suggested to tune the configuration files separately to maximize resource utilization.</li>
         </ul>
      </main>

   2. After successful deployment, create a new tenant and user for executing the TPC-DS test (`sys` tenant is a built-in system tenant for managing clusters; do not use `sys` tenant directly for testing). Set the tenant's `primary_zone` to `RANDOM`. `RANDOM` means that the leader of newly created table partitions will be randomly assigned to these three machines.

* **Tenant creation**

   You can create a test tenant using the `OBD CLUSTER TENANT CREATE` command. The corresponding command is as follows:

   ```shell
   obd cluster tenant create <DEPLOY_NAME> -n <TENANT_NAME> --max-cpu=28 --memory-size=180G -–zone-list=zone1,zone2,zone3 -–primary-zone=RANDOM  --locality=F@zone1,F@zone2,F@zone3 --charset=utf8 -s 'ob_tcp_invited_nodes="%"' --optimize=<optimize>
   ```

   The parameters are explained as follows:

  * `DEPLOY_NAME`: The cluster name.
  * `TENANT_NAME`: The tenant name.
  * `--zone-list`: The list of zones for the tenant.
  * `--primary-zone`: The primary zone of the tenant.
  * `--locality`: The distribution of replicas across zones.
  * `--charset`: The character set of the tenant.
  * `-s`: The value of tenant system variables.
  * `OPTIMIZE`: The tenant workload type, including `express_oltp`, `complex_oltp`, `olap`, `htap`, and `kv`. The default workload type is `htap`, suitable for mixed OLAP and OLTP workloads. For more information on OBD deployment, see [obd cluster tenant create](https://docs.oceanbase.com/obd/cluster-commands).

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>For V4.3.x and later versions, when deploying with OBD, you can set the <code>scenario</code> parameter to select an appropriate cluster workload type. If not configured, the default <code>scenario</code> is <code>htap</code>. For more information, see <a href="https://docs.oceanbase.com/obd/deploy-oceanbase-cluster-ui">Deploy OceanBase Database with OBD</a>.</p>
    </main>

   For example, create a tenant named `tpcds_tenant`, use a cluster named `obperf` with a resource configuration of 28-core CPU and 180 GB of memory, and set the default tenant workload type to match the cluster scenario.

   ```shell
   obd cluster tenant create obperf -n tpcds_tenant --max-cpu=28 --memory-size=180G -–zone-list=zone1,zone2,zone3 -–primary-zone=RANDOM  --locality=F@zone1,F@zone2,F@zone3 --charset=utf8 -s 'ob_tcp_invited_nodes="%"' --optimize=htap
   ```

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>In this example, <code>--optimize=htap</code> sets the default workload type. In a production environment, please select an appropriate workload type based on the actual cluster type.</p>
    </main>

## Test method

After the test environment is prepared, you can perform the TPC-DS performance test using the following method.

### Manually run the TPC-DS test using the TPC-DS tool

Manual testing is performed after you select the cluster workload type and the tenant tuning scenario. It helps you gain a deeper understanding of OceanBase Database, especially in optimizing parameter settings.

1. Download the TPC-DS Tool from the [TPC-DS Tool download page](https://www.tpc.org/TPC_Documents_Current_Versions/download_programs/tools-download-request5.asp?bm_type=TPC-DS&bm_vers=3.2.0&mode=CURRENT-ONLY).

#### Step 4: Generate data

You can generate 10G, 100G, or 1T of TPC-DS data based on your actual environment. This example shows how to generate 100G of data.

1. Create a directory to store the data files.

    ```shell
    [wieck@localhost tools] $ mkdir tpcds_100g
    ```

2. Build the test data.

    ```shell
    [wieck@localhost tools] $ ./dsdgen -scale 100G -dir tpcds_100g
    ```

   When you generate 1T of data by using multiple threads, you can use OceanBase direct load to import data from multiple files into tables at the same time.

    ```shell
    [wieck@localhost tools] $
    #!/bin/bash

    # Set variables
    SCALE=$1
    PARALLEL="20"
    DIR="/data/1/tpcds/tpcds_data/"    # You can modify the path as needed.

    for ((x=1; x<=PARALLEL; x++))
    do
        # Build dsdgen command
        CMD="./dsdgen -scale ${SCALE}GB -parallel ${PARALLEL} -child ${x} -dir ${DIR}"

        # Execute commands in the background
        ${CMD} &
    done

    wait

    echo "All data generation is complete."
    ```

3. Modify the test data.

   * Modify NULL values.

        When using the pipe character `|` as a field separator, `a,NULL,c,d,NULL` is exported to a text file as `a||c|d|`. When you import the file by using the LOAD DATA method, an error occurs, indicating that the import failed. Therefore, NULL values need to be processed.

        ```shell
        [wieck@localhost tools] $ vim fix-null.sh
        #!/bin/bash
        # Replace NULL values in the first field with 0, and replace ^| with 0|.
        # Replace NULL values in the middle fields with 0, and replace || with |0|.
        # Replace the NULL value in the last field with 0 and replace |$ with |0.
        for s_f in `ls *dat`
        do
            echo "$s_f"
            i=1
            while [ `egrep '\|\||^\||\|$' $s_f |wc -l` -gt 0 ]
            do
                echo $i
                sed 's/^|/0|/g;s/||/|0|/g;s/|$/|0/g' -i $s_f
                ((i++))
            done
        done

        [wieck@localhost tools] $ sh fix-null.sh
        ```

   * Modify date fields.

        ```shell
        [wieck@localhost tools] $ vim fix-date.sh
        for s_f in item.dat store.dat web_page.dat web_site.dat call_center.dat
        do
        # Handle the case where both the first and second dates are NULL.
        sed 's/^\([A-Za-z0-9]*|[A-Za-z0-9]*\)|0|0|\(.*\)/\1|0000-00-00|0000-00-00|\2/' -i $s_f

        # Process the second date that is NULL.
        sed 's/^\([0-9A-Za-z]*|[A-Za-z0-9]*|[0-9]\{4\}-[0-9]\{2\}-[0-9]\{2\}\)|0|\(.*\)/\1|0000-00-00|\2/' -i $s_f

        # Process the first date that is NULL.
        sed 's/^\([0-9A-Za-z]*|[A-Za-z0-9]*\)|0|\([0-9]\{4\}-[0-9]\{2\}-[0-9]\{2\}|.*\)/\1|0000-00-00|\2/' -i $s_f

        done

        [wieck@localhost tools] $ sh fix-date.sh
        ```

      [wieck@localhost tools] $ vim query.sh

4. Adjust the query SQL statements.

   * Increase parallelism.

     Run the following command under the SYS tenant to view the total number of available CPUs for the tenant.

        ```shell
        obclient> SELECT sum(cpu_capacity_max) FROM oceanbase.__all_virtual_server;
        ```

     Take sql1 as an example. The modified SQL statement is as follows:

        ```shell
        with customer_total_return as
        (select /*+    parallel(96) */ sr_customer_sk as ctr_customer_sk ---Increase parallel execution
        ,sr_store_sk as ctr_store_sk
        ,sum(SR_FEE) as ctr_total_return
        from store_returns
        ,date_dim
        where sr_returned_date_sk = d_date_sk
        and d_year =2000
        group by sr_customer_sk
        ,sr_store_sk)
        select  c_customer_id
        from customer_total_return ctr1
        ,store
        ,customer
        where ctr1.ctr_total_return > (select avg(ctr_total_return)*1.2
        from customer_total_return ctr2
        where ctr1.ctr_store_sk = ctr2.ctr_store_sk)
        and s_store_sk = ctr1.ctr_store_sk
        and s_state = 'TN'
        and ctr1.ctr_customer_sk = c_customer_sk
        order by c_customer_id
        limit 100;
        ```

   * Adjust date functions.

        Adjust the date function `(cast('2025-03-04' as date) +  30 days)` in the SQL statement to `date_add(cast('2025-03-04' as date),interval 30 day)` or `(cast('2025-03-04' as date) + INTERVAL 30 day)`,
        and adjust `(cast ('2025-04-18' as date) - 30 days)` to `date_sub(cast ('2025-04-18' as date),interval 30 day)` or `(cast('2025-04-18' as date) - INTERVAL 30 day)`.

     Take an SQL statement containing a date function as an example. The modified SQL statement is as follows:

        ```sql
        select  i_item_id
            ,i_item_desc
            ,i_current_price
        from item, inventory, date_dim, catalog_sales
        where i_current_price between 22 and 22 + 30
        and inv_item_sk = i_item_sk
        and d_date_sk=inv_date_sk
        and d_date between cast('2025-04-02' as date) and (cast('2025-04-02' as date) + INTERVAL 60 day)  -----Modify the date function
        and i_manufact_id in (678,964,918,849)
        and inv_quantity_on_hand between 100 and 500
        and cs_item_sk = i_item_sk
        group by i_item_id,i_item_desc,i_current_price
        order by i_item_id
        limit 100;
        ```

   * Adjust the usage of the rollup function.

        Change the usage of the rollup function in the SQL statement to `group by <col_name> with rollup`.

        Take an SQL statement containing the rollup function as an example. The modified SQL statement is as follows:

        ```sql
        select  i_item_id,
                ca_country,
                ca_state,
                ca_county,
                avg( cast(cs_quantity as decimal(12,2))) agg1,
                avg( cast(cs_list_price as decimal(12,2))) agg2,
                avg( cast(cs_coupon_amt as decimal(12,2))) agg3,
                avg( cast(cs_sales_price as decimal(12,2))) agg4,
                avg( cast(cs_net_profit as decimal(12,2))) agg5,
                avg( cast(c_birth_year as decimal(12,2))) agg6,
                avg( cast(cd1.cd_dep_count as decimal(12,2))) agg7
        from catalog_sales, customer_demographics cd1,
            customer_demographics cd2, customer, customer_address, date_dim, item
        where cs_sold_date_sk = d_date_sk and
            cs_item_sk = i_item_sk and
            cs_bill_cdemo_sk = cd1.cd_demo_sk and
            cs_bill_customer_sk = c_customer_sk and
            cd1.cd_gender = 'M' and
            cd1.cd_education_status = 'College' and
            c_current_cdemo_sk = cd2.cd_demo_sk and
            c_current_addr_sk = ca_address_sk and
            c_birth_month in (9,5,12,4,1,10) and
            d_year = 2001 and
            ca_state in ('ND','WI','AL'
                        ,'NC','OK','MS','TN')
        group by i_item_id, ca_country, ca_state, ca_county with rollup
        order by ca_country,
                ca_state,
                ca_county,
                i_item_id
        limit 100;
        ```

#### Step 8: Execute tests

Write your own script based on the data and SQL generated in the previous steps. The following example shows how to execute tests:

1. Write a test script named tpcds.sh in the sql-ds directory.

    ```shell
    [wieck@localhost queries] $ vim tpcds.sh

      #!/bin/bash
      TPCDS_TEST="obclient -h $host_ip -P $host_port -utpcds_100g_part@tpcds_mysql  -D tpcds_100g_part  -ptest -c"
      # warmup
      for i in {1..99}
      do
          sql1="source sql${i}.sql"
          echo $sql1| $TPCDS_TEST >db${i}.log  || ret=1
      done
      # Formal execution
      for i in {1..99}
      do
          starttime=`date +%s%N`
          echo `date  '+[%Y-%m-%d %H:%M:%S]'` "BEGIN Q${i}"
          sql1="source sql${i}.sql"
          echo $sql1| $TPCDS_TEST >db${i}.log  || ret=1
          stoptime=`date +%s%N`
          costtime=`echo $stoptime $starttime | awk '{printf "%0.2f\n", ($1 - $2) / 1000000000}'`
          echo `date  '+[%Y-%m-%d %H:%M:%S]'` "END,COST ${costtime}s"
      done
    ```

2. Execute the test script.

    ```shell
    sh tpcds.sh
    ```

## Common error messages

* Data import failed. The error message is as follows:

  ```shell
  ERROR 1017 (HY000) at line 1: File not exist
  ```

  The `tbl` file must be placed in a directory on the machine where the connected OceanBase database resides, because data must be loaded locally.

* An error occurred while viewing data. The error message is as follows:

  ```shell
  ERROR 4624 (HY000): No memory or reach tenant memory limit
  ```

   Insufficient memory. It is recommended to increase the tenant memory.

* An error occurred during data import. The error message is as follows:

  ```shell
  ERROR 1227 (42501) at line 1: Access denied
  ```
