# Run the TPC-H benchmark test with OceanBase Database

This topic describes the software requirements, tenant configurations, and test procedure for running the TPC-H benchmark test with OceanBase Database.

## What is the TPC-H benchmark test

The TPC-H (Transaction Processing Performance Council-Harbor) benchmark test is a test suite designed by the Transaction Processing Performance Council (TPC) to simulate decision support applications. The TPC-H benchmark test is widely used in academia and industry to evaluate the performance of decision support technologies. This commercial benchmark test can comprehensively assess the overall business computing capabilities of a system from multiple dimensions, thereby putting vendors under higher demands. It also has broad commercial applicability in various fields, such as bank credit analysis and card analysis, telecommunications operation analysis, tax analysis, and tobacco industry decision-making.

The TPC-H benchmark evolved from TPC-D (a standard established by TPC in 1994 for testing decision support systems). TPC-H implements a data warehouse using 3NF and includes eight fundamental relations. Its primary evaluation metric is the response time of each query, which refers to the time required from query submission to result retrieval. The measurement unit for the TPC-H benchmark is the number of queries executed per hour (QphH@size), where H represents the average number of complex queries executed by the system per hour, and size indicates the scale of the database, reflecting the system's capability in processing queries. TPC-H is modeled after real production environments, enabling it to assess key performance parameters that other tests cannot evaluate. In summary, the TPC-H standard issued by the TPC organization meets the testing needs of the data warehousing field and drives vendors and research institutions to push this technology to its limits.

The performance test method described in this topic optimizes only the basic parameters to help developers quickly get started with the database. </p>
</main>

### Prerequisites

* JDK: We recommend that you use JDK 1.8u131 or later.

* make: Run the command `yum install make` to install it.

* GCC: Run the command `yum install gcc` to install it.

* mysql-devel: Run the command `yum install mysql-devel` to install it.

* Python driver for connecting to a database: Run the command `sudo yum install MySQL-python` to install it.

* prettytable: Run the command `pip install prettytable` to install it.

* JDBC: We recommend that you use `mysql-connector-java-5.1.47`.

* TPC-H tools: Download it from [Download Center](https://www.tpc.org/tpc_documents_current_versions/download_programs/tools-download-request5.asp?bm_type=TPC-H&bm_vers=3.0.0&mode=CURRENT-ONLY). If you use OBD to perform the one-click test, you can skip this tool.

* OBClient: For more information, see [OBClient](https://github.com/oceanbase/obclient/blob/master/README.md).

* OceanBase Database: For more information, see [Get started with OceanBase Database](../../../200.quickstart/100.quickly-experience-oceanbase-for-community.md).


### Tenant specifications

The tenant specifications are based on the hardware configurations in the <a href="200.tpc-h-benchmark-report-of-oceanbase-database.md">TPC-H benchmark test report of OceanBase Database</a>. You need to adjust the specifications based on the hardware configurations of your database.

* **Cluster deployment**

   1. This test requires four servers. The TPC-H and OBD components are deployed on one server as the pressure machines for the client. OceanBase Database is deployed on three servers in a 1:1:1 configuration using OBD.

      2. <main id="notice" type='explain'>
         <h4>Note</h4>
         <ul>
         <li>In the TPC-H test, a server deployed with TPC-H and OBD only needs four cores and 16 GB of memory. </li>
         <li>When you deploy a cluster, we recommend that you do not use the <code>obd cluster autodeploy</code> command. This command ensures stability by not maximizing resource utilization (for example, it does not use all memory). We recommend that you optimize the configuration file to maximize resource utilization. </li>
         </ul>
      </main>

   2. After the deployment is successful, create a tenant and a user for running the TPC-H test (the sys tenant is an internal system tenant for cluster management. Do not use it for testing). Set the `primary_zone` of the tenant to `RANDOM`. The `RANDOM` value means that the leader of a newly created table partition is randomly assigned to one of the three servers.

* **Tenant creation**

   You can use the `OBD CLUSTER TENANT CREATE` command to create a tenant. The corresponding SQL syntax is as follows:

   ```sql
   obd cluster tenant create <DEPLOY_NAME> -n <TENANT_NAME> --max-cpu=28 --memory-size=180G -–zone-list=zone1,zone2,zone3 -–primary-zone=RANDOM  --locality=F@zone1,F@zone2,F@zone3 --charset=utf8 -s 'ob_tcp_invited_nodes="%"' --optimize=<optimize>
   ```

   The parameters are described as follows:

  * `DEPLOY_NAME`: the cluster name.
  * `TENANT_NAME`: the tenant name.
  * `--zone-list`: the zone list of the tenant.
  * `--primary-zone`: the primary zone of the tenant.
  * `--locality`: the distribution of replicas across zones.
  * `--charset`: the character set of the tenant.
  * `-s`: the tenant's system variable values.
  * `OPTIMIZE`: the tenant load type. Valid values include `express_oltp`, `complex_oltp`, `olap`, `htap`, and `kv`. The default load type is `htap`, which is suitable for mixed OLAP and OLTP workloads. For more information about OBD deployment, see [obd cluster tenant create](https://www.oceanbase.com/docs/community-obd-cn-1000000000955364).

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>For V4.3.x and later, when you use OBD to deploy a cluster, you can set the <code>scenario</code> parameter to select an appropriate load type for the cluster. The default value of the <code>scenario</code> parameter is <code>htap</code>. For more information, see <a href="https://www.oceanbase.com/docs/community-obd-cn-1000000000955369">Deploy OceanBase Database using OBD</a>. </p>
    </main>

   For example, you can create a tenant named `tpcc_tenant` in the `obperf` cluster. The tenant has 28 CPU cores and 180 GB of memory. The load type of the tenant is the same as that of the cluster.

   ```shell
   obd cluster tenant create obperf -n tpcc_tenant --max-cpu=28 --memory-size=180G -–zone-list=zone1,zone2,zone3 -–primary-zone=RANDOM  --locality=F@zone1,F@zone2,F@zone3 --charset=utf8 -s 'ob_tcp_invited_nodes="%"' --optimize=htap
   ```

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p> In this example, <code>--optimize=htap</code> is the default load type. In a production environment, please select an appropriate load type based on the actual cluster type. </p>
    </main>

## Test methods

After the test environment is prepared, you can perform the TPC-H performance test using either of the following two methods:

* **Run the TPC-H test with OBD**

* **Run the TPC-H test with the TPC-H tools**

### Run the TPC-H benchmark test with one click using OBD

You can run the TPC-H benchmark test with one click using an OBD script. The sample script is as follows:

```shell
sudo yum install -y yum-utils
sudo yum-config-manager --add-repo https://mirrors.aliyun.com/oceanbase/OceanBase.repo
sudo yum install obtpch
sudo ln -s /usr/tpc-h-tools/tpc-h-tools/ /usr/local/
obd test tpch obperf  --tenant=tpch_mysql -s 100 --remote-tbl-dir=/tmp/tpch100
```

Before you run the preceding script to run the TPC-H benchmark test, note the following points:

* For more information about the parameters, see [obd test tpch](https://www.oceanbase.com/docs/community-obd-cn-10000000001031935).

* In this example, most parameters use default values. In a user scenario, you can modify some parameters according to your specific requirements. For example, in this example, the cluster name is set to `obperf`, and the tenant name is set to `tpch_mysql`.

* When you run the one-click test using OBD, the cluster must be installed and deployed by OBD. Otherwise, you cannot obtain information about the cluster and perform performance tuning based on the cluster configuration.

* If the password of the sys tenant is changed through the terminal and is different from the default empty value, you need to change it back to the default value in the terminal first. Then, use the [obd cluster edit-config](https://www.oceanbase.com/docs/community-obd-cn-10000000001031935) command to set the password in the configuration file. The password parameter is `# root_password: # root user password`. After the [obd cluster edit-config](url-placeholder/81baee13-2c89-43aa-9602-d1cfef502c5d) command completes, you need to run the `obd cluster reload` command to make the change take effect.

* After you run the `obd test tpch` command, a detailed list of the operation steps and the output are displayed. The larger the data amount, the longer the duration.

* The remote directory specified by the `remote-tbl-dir` parameter has sufficient capacity to store TPC-H data. We recommend that you use a separate disk to store the test data.

* The `obd test tpch` command automatically completes all operations, including test data generation, data transmission, OceanBase parameter optimization, data loading, and the test. If an error occurs during any intermediate step, you can retry the command. For example, you can skip data generation and data transmission and directly perform data loading and the test.

### Manually run the TPC-H benchmark test using the TPC-H tools

After you select the load type and apply tenant optimization in a cluster, you can manually run the TPC-H benchmark test to further learn about OceanBase Database and optimize parameter settings.

#### Step 1: Create a test tenant

Run the commands in the system tenant (`sys` tenant) to create a test tenant:

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>The deployment mode of the OceanBase cluster environment for this test is 1:1:1.</p>
</main>

1. Create a resource unit named `mysql_box`.

   ```sql
   CREATE RESOURCE UNIT mysql_box
      MAX_CPU 28,
      MEMORY_SIZE '200G',
      MIN_IOPS 200000,
      MAX_IOPS 12800000,
      LOG_DISK_SIZE '300G';
   ```

2. Create a resource pool named `mysql_pool`.

   ```sql
   CREATE RESOURCE POOL mysql_pool
      UNIT = 'mysql_box',
      UNIT_NUM = 1,
      ZONE_LIST = ('z1','z2','z3');

   ```sql
   CREATE TENANT mysql_tenant

      SET VARIABLES ob_compatibility_mode='mysql', ob_tcp_invited_nodes='%', secure_file_priv = "/";

#### Step 4: Generate data

Generate 10 GB, 100 GB, or 1 TB of TPC-H data as needed. The following example shows the command to generate 100 GB of data. If you want to generate 1 TB of data, you can run the following script in parallel on multiple CPU cores. OceanBase Database supports direct load, allowing you to import multiple files to a table at the same time.

```bash
./dbgen -s 100
mkdir tpch100
mv *.tbl tpch100
```

The following script generates 1 TB of data and supports direct load. You can run this script on OceanBase Database.

```bash
#!/bin/bash  

SCALE_FACTOR=1000  
CHUNK_COUNT=20  
for ((i=1; i<=CHUNK_COUNT; i++))  
do   
   CMD="./dbgen -s ${SCALE_FACTOR} -C ${CHUNK_COUNT} -S ${i} -vf"   
   $CMD &  
done  
wait  
echo "All data generation tasks completed."
```

   select sum(max_cpu) from DBA_OB_UNITS;

   ```sql
   SELECT /*+    parallel(96) */   ---Add parallel execution
   l_returnflag,
   l_linestatus,
   sum(l_quantity) as sum_qty,
   sum(l_extendedprice) as sum_base_price,
   sum(l_extendedprice * (1 - l_discount)) as sum_disc_price,
   sum(l_extendedprice * (1 - l_discount) * (1 + l_tax)) as sum_charge,

   GROUP BY
   l_returnflag,
   l_linestatus
   ORDER BY
   l_returnflag,
   l_linestatus;
   ```

1. Create a script named `load_data.sh`.

   ```bash
   #!/bin/bash
   host='$host_ip'   # Attention!!! Please fill in the IP address of an observer node, such as observer A. It is recommended to store the data files on the same server.
   port='$host_port' # Port number of observer A
   user='$user'      # Username
   tenant='$tenant_name'  # Tenant name
   password='$password'   # Password
   database='$db_name'    # Database name
   data_path='$data_file' # Attention!!! Please fill in the path where the data files generated on observer A are stored. The data files are in the .tbl format.

   function load_data
   {
      remote_user="$user"         Username of the data storage observer node
      table_name=${1}
      if [[ ${password} == "" ]];then
         obclient_conn="obclient -h${host} -P${port} -u${user} -D${database} -A -c"
      else
         obclient_conn="obclient -h${host} -P${port} -u${user} -D${database} -p${password} -A -c"
      fi
      table_list=$(ssh "${remote_user}@${host}" "ls ${data_path}/${table_name}.tbl* 2>/dev/null")  
      echo "$table_list"

      IFS=$'\n' read -d '' -r -a table_files <<< "$table_list" 
      table_files_comma_separated=$(IFS=,; echo "${table_files[*]}")
      echo "${table_files_comma_separated}"
      echo `date "+[%Y-%m-%d %H:%M:%S]"` "----------------------Importing data files of the ${table_name} table----------------------"

      # Import data in direct load mode. You can also modify the data import mode to other modes.
      echo "load data /*+ parallel(80) direct(true,0) */ infile '${table_files_comma_separated}' into table ${table_name} fields terminated by '|';" | ${obclient_conn}

   }

   starttime=`date +%s%N`
   for table in "nation" "region" "customer" "lineitem" "orders" "partsupp" "part" "supplier"
   do
      load_data "${table}"
   done
   end_time=`date +%s%N`
   totaltime=`echo ${end_time} ${starttime} | awk '{printf "%0.2f\n", ($1 - $2) / 1000000000}'`
   echo `date "+[%Y-%m-%d %H:%M:%S]"` "load data cost ${totaltime}s"
   ```

### FAQ

* Failed to import data. The error message is as follows:

  ```bash
  ERROR 1017 (HY000) at line 1: File not exist
  ```

  The `tbl` file must be placed in a directory on the server that hosts OceanBase Database, because only local data can be imported and loaded.

* An error occurred while viewing data. The error message is as follows:

  ```bash
  ERROR 4624 (HY000): No memory or reach tenant memory limit
  ```

  You are running out of memory. Allocate more memory to the tenant.

* An error occurred while importing data. The error message is as follows:

  ```bash
  ERROR 1227 (42501) at line 1: Access denied
  ```

  Grant the access privilege to the login user by running the following command:

  ```bash
  grant file on *.* to tpch_100g_part;
