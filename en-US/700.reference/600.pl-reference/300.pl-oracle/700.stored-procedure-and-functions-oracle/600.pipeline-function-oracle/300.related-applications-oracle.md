# Applications

A pipe function can be used for data conversion and supports data transmission between table functions.

  <main id="notice" >
    <h4>Applicability</h4>
    <p>This topic applies only to OceanBase Database Enterprise Edition. OceanBase Database Community Edition does not support this feature. </p>
  </main>

## Use a pipe function for data conversion

A pipe function with a cursor variable parameter can receive any parameters like a regular function. The pipe function can use the cursor variable to obtain the input rows and use the `PIPE ROW` statement to transmit the converted one or more rows to the calling program through a pipe. If the `FETCH` and `PIPE ROW` statements are located in a `LOOP` statement, the function can convert multiple input rows.

## Pass data between pipe functions

The actual parameter of the cursor variable parameter of a pipe function can be a cursor variable or a `CURSOR` expression. The latter is more efficient. When an SQL `SELECT` statement passes a `CURSOR` expression to a function, the referenced cursor is opened when the function starts and closed when the function completes.

## Obtain the result of a pipe function

You can associate a named cursor with a query that calls a pipe function to obtain the result of the pipe function. Such a cursor does not have special retrieval semantics, and the cursor variable does not have special assignment semantics.

When a pipe function is used as an aggregate function, it accepts a set of input rows and returns a single result. A `SELECT` statement can select the function result.

## Perform DML operations on the result of a pipe function

The "table" returned by a pipe function cannot be the target table of a `DELETE`, `INSERT`, `UPDATE`, or `MERGE` statement. However, you can create a view of such a table and create an `INSTEAD OF` trigger on the view. For more information about `INSTEAD OF` triggers, see [CREATE TRIGGER](../../1100.ddl-operations-on-stored-pl-units-oracle/1100.create-trigger-oracle.md).
