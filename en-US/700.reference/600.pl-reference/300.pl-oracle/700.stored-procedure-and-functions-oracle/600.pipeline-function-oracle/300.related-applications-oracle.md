# Applications

Pipe functions can be used for data conversion and support data transmission between table functions.

  <main id="notice" >
    <h4>Applicability</h4>
    <p>This topic applies only to OceanBase Database Enterprise Edition. OceanBase Database Community Edition does not support this feature. </p>
  </main>

## Use pipe functions for data conversion

A pipe function with a cursor variable parameter can accept any parameters like a regular function. The pipe function can use the cursor variable to retrieve input rows and use the `PIPE ROW` statement to pass converted rows to the calling program. If the `FETCH` and `PIPE ROW` statements are within a `LOOP` statement, the function can convert multiple input rows.

## Pass data between pipe functions

The actual argument of the cursor variable parameter of a pipe function can be a cursor variable or a `CURSOR` expression, which is more efficient. When an SQL `SELECT` statement passes a `CURSOR` expression to a function, the referenced cursor is opened when the function starts and closed when the function completes.

## Obtain results from a pipe function

You can associate a named cursor with a query that calls a pipe function to obtain the results of the pipe function. Such cursors do not have special fetching semantics, and cursor variables do not have special assignment semantics.

When a pipe function is used as an aggregate function, it accepts a set of input rows and returns a single result. The `SELECT` statement can select the function result.

## Perform DML operations on the results of a pipe function

The "table" returned by a pipe function cannot be the target table of a `DELETE`, `INSERT`, `UPDATE`, or `MERGE` statement. However, you can create views of such tables and create `INSTEAD OF` triggers on the views. For more information about `INSTEAD OF` triggers, see [CREATE TRIGGER](../../1100.ddl-operations-on-stored-pl-units-oracle/1100.create-trigger-oracle.md).
