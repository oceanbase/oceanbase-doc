# OPEN

The `OPEN` procedure is used to open an internal or external `LOB` in a specified mode. Valid modes include read-only and read/write.

  <main id="notice" >
    <h4>Applicability</h4>
    <p>This topic applies only to OceanBase Database Enterprise Edition. OceanBase Database Community Edition does not support this feature. </p>
  </main>

## Syntax

```sql
DBMS_LOB.OPEN (
lob_loc   IN OUT NOCOPY BLOB,
open_mode IN            BINARY_INTEGER);

DBMS_LOB.OPEN (
lob_loc   IN OUT NOCOPY CLOB CHARACTER SET ANY_CS,
open_mode IN            BINARY_INTEGER);
```

## Parameters

|  **Parameter**   |                                 **Description**                                  |
|-----------|-------------------------------------------------------------------------|
| lob_loc   | The `LOB` locator. For more information, see [Use DBMS_LOB](../9300.dbms-lob-oracle/100.dbms-lob-overview-oracle.md). |
| open_mode | The mode in which to open the `LOB`. For `BLOB` and `CLOB` types, the mode can be: `LOB_READONLY` or `LOB_READWRITE`.      |

## Considerations

<main id="notice" type='explain'>
    <h4>Note</h4>
    <p>If you open a <code>LOB</code> in read-only mode and attempt to write to it, an error will be returned. </p>
  </main>

* The `OPEN` procedure requires communication between the internal and external `LOB` servers. For an internal `LOB`, the `OPEN` procedure triggers other code that depends on the `OPEN` call.

* It is not mandatory to wrap all `LOB` operations in the Open/Close interface. If you open a `LOB`, you must close it before committing the transaction, otherwise an error will occur. When closing an internal `LOB`, the function indexes and domain indexes on the `LOB` column will be updated.

* Committing a transaction before closing all `LOB` objects opened by the transaction will result in an error. When an error occurs, the openness of the opened `LOB` will be discarded, but the transaction will be successfully committed, including all changes made to `LOB` and non-`LOB` data within the transaction. However, domain-based and function-based indexes will not be updated. In such cases, you should rebuild the function indexes and domain indexes on the `LOB` column.
