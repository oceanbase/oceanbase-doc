# REFRESH

`REFRESHE` is used to refresh a specified materialized view.

<main id="notice" >
  <h4>Applicability</h4>
  <p>This topic applies only to OceanBase Database Enterprise Edition. OceanBase Database Community Edition provides only MySQL mode. </p>
</main>

## Syntax

```sql
DBMS_MVIEW.REFRESH (
    { list                 IN     VARCHAR2
    | tab                  IN     DBMS_UTILITY.UNCL_ARRAY}
    [, method                 IN     VARCHAR2       := NULL]
    [, rollback_seg           IN     VARCHAR2       := NULL]
    [, push_deferred_rpc      IN     BOOLEAN        := true]
    [, refresh_after_errors   IN     BOOLEAN        := false]
    [, purge_option           IN     BINARY_INTEGER := 1]
    [, parallelism            IN     BINARY_INTEGER := 0]
    [, heap_size              IN     BINARY_INTEGER := 0]
    [, atomic_refresh         IN     BOOLEAN        := true]
    [, nested                 IN     BOOLEAN        := false]
    [, out_of_place           IN     BOOLEAN        := false]
    [, skip_ext_data          IN     BOOLEAN        := false]
    [, refresh_parallel       IN     BINARY_INTEGER := 0]
    [, nested_refresh_mode    IN     VARCHAR2       := NULL]
);
```

## Parameters

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>Non-nested materialized views do not support cascading refresh. Specifying the <code>nested</code> and <code>nested_refresh_mode</code> parameters has no effect. By default, the refresh is independent. </p>
</main>

|       **Parameter**       |           **Description**                |
|----------------------|-----------------------------------|
| list                 | A list of names of materialized views to be refreshed, separated by commas. Currently, only a single materialized view can be refreshed at a time. Multiple materialized views cannot be refreshed simultaneously.|
| tab                  | An array of names of materialized views to be refreshed. Currently, only a single array of materialized view names can be refreshed at a time. Multiple arrays of materialized view names cannot be refreshed simultaneously.|
| method               | Defines the refresh strategy for the materialized view. This parameter specifies the default refresh strategy when a materialized view is created. Valid values: <ul><li>`F` or `f`: Fast refresh.</li><li>`?`: Force refresh.</li><li>`C` or `c`: Complete refresh.</li><li>`A` or `a`: Always refresh, which is equivalent to `C`. </li></ul>|
| rollback_seg         | This parameter has no effect. It is provided for Oracle compatibility.|
| push_deferred_rpc    | This parameter has no effect. It is provided for Oracle compatibility.|
| refresh_after_errors | This parameter has no effect. It is provided for Oracle compatibility.|
| purge_option         | This parameter has no effect. It is provided for Oracle compatibility.|
| parallelism          | This parameter has no effect. It is provided for Oracle compatibility.|
| heap_size            | This parameter has no effect. It is provided for Oracle compatibility.|
| atomic_refresh       | This parameter has no effect. It is provided for Oracle compatibility.|
| nested               | Specifies the refresh mode for nested materialized views. Valid values: <ul><li>`FALSE`: Default value. Independent refresh is performed on nested materialized views. </li><li>`TRUE`: Cascading refresh is performed on nested materialized views. </li></ul>|
| out_of_place         | This parameter has no effect. It is provided for Oracle compatibility.|
| skip_ext_data        | This parameter has no effect. It is provided for Oracle compatibility.|
| refresh_parallel     | The concurrency level of the refresh operation, that is, the number of threads that can be executed simultaneously.|
| nested_refresh_mode  | Specifies whether the cascading refresh of nested materialized views is consistent or inconsistent. Valid values: <ul><li>When the `nested` parameter is set to `FALSE`, specifying the `nested_refresh_mode` parameter will result in an error. </li><li>When the `nested` parameter is set to `TRUE`: <ul><li>Valid values for the `nested_refresh_mode` parameter: <ul><li>`inconsistent`: Cascading inconsistent refresh. </li><li>`consistent`: Cascading consistent refresh. </li></ul> </li><li>If the `nested_refresh_mode` parameter is not specified, the default is cascading inconsistent refresh. </li></ul> </li></ul>|

## Examples

* Independent refresh mode:

  * Specify only the `mv_name` parameter.

    ```shell
    obclient> CALL DBMS_MVIEW.REFRESH('mv1');
    ```

  * Specify the `mv_name` parameter and set the `nested` parameter to `false`.

    ```shell
    obclient> CALL DBMS_MVIEW.REFRESH(
        'mv1',
        nested=> false);
    ```

* Cascading inconsistent refresh mode:

  * Specify the `mv_name` parameter, set the `nested` parameter to `true`, and do not specify the `nested_refresh_mode` parameter.

    ```shell
    obclient> CALL DBMS_MVIEW.REFRESH(
        'mv1',
        nested=> true);
    ```

  * Specify the `mv_name` parameter, set the `nested` parameter to `true`, and set the `nested_refresh_mode` parameter to `inconsistent`.

    ```shell
    obclient> CALL DBMS_MVIEW.REFRESH(
        'mv1',
        nested=> true,
        nested_refresh_mode => 'inconsistent');
    ```

* Cascading consistent refresh mode:

  Specify the `mv_name` parameter, set the `nested` parameter to `true`, and set the `nested_refresh_mode` parameter to `consistent`.

  ```shell
  obclient> CALL DBMS_MVIEW.REFRESH(
      'mv1',
      nested=> true,
      nested_refresh_mode => 'consistent');
  ```

* The following are error scenarios:

  * Set the `nested` parameter to `false` and specify the `nested_refresh_mode` parameter. An error is returned.

    ```shell
    obclient> CALL DBMS_MVIEW.REFRESH(
        'mv1',
        nested=> false,
        nested_refresh_mode => 'xxxx');
    ```

  * Do not specify the `nested` parameter and specify the `nested_refresh_mode` parameter. An error is returned.

    ```shell
    obclient> CALL DBMS_MVIEW.REFRESH(
        'mv1',
        nested_refresh_mode => 'xxxx');
    ```

  * Set the `nested` parameter to `true` and set the `nested_refresh_mode` parameter to an invalid string. An error is returned.

    ```shell
    obclient> CALL DBMS_MVIEW.REFRESH(
        'mv1',
        nested=> true,
        nested_refresh_mode => 'invalid string');
    ```
