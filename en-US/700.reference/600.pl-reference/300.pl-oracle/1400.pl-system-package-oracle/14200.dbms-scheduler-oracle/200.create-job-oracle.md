# CREATE_JOB

The `CREATE_JOB` procedure is used to create a job.

If the `enabled` attribute is set to `TRUE`, the Scheduler will automatically run the job according to its schedule. If the job is created in a disabled state, it will only run after being enabled using the `SET_ATTRIBUTE` procedure.

  <main id="notice" >
    <h4>Applicability</h4>
    <p>This topic applies only to OceanBase Database Enterprise Edition. </p>
  </main>

## Syntax

### Syntax for creating a job without using an existing procedure or plan

```sql
DBMS_SCHEDULER.CREATE_JOB (
job_name            IN  VARCHAR2,
job_type            IN  VARCHAR2,
job_action          IN  VARCHAR2,
number_of_argument  IN  BINARY_INTEGER DEFAULT 0,
start_date          IN  TIMESTAMP_UNCONSTRAINED DEFAULT NULL,
repeat_interval     IN  VARCHAR2 DEFAULT 'null',
end_date            IN  TIMESTAMP_UNCONSTRAINED DEFAULT NULL,
job_class           IN  VARCHAR2 DEFAULT 'DEFAULT_JOB_CLASS',
enabled             IN  BOOLEAN DEFAULT FALSE,
auto_drop           IN  BOOLEAN DEFAULT TRUE,
comments            IN  VARCHAR2 DEFAULT 'null',
credential_name     IN  VARCHAR2 DEFAULT 'null',
destination_name    IN  VARCHAR2 DEFAULT 'null',
max_run_duration    IN  BINARY_INTEGER DEFAULT 0);
```

### Syntax for creating a job by using a named procedure object and an internal plan

```sql
DBMS_SCHEDULER.CREATE_JOB  (
job_name            IN  VARCHAR2,
program_name        IN  VARCHAR2,
start_date          IN  TIMESTAMP_UNCONSTRAINED DEFAULT NULL,
repeat_interval     IN  VARCHAR2 DEFAULT 'null',
end_date            IN  TIMESTAMP_UNCONSTRAINED DEFAULT NULL,
job_class           IN  VARCHAR2 DEFAULT 'DEFAULT_JOB_CLASS',
enabled             IN  BOOLEAN DEFAULT FALSE,
auto_drop           IN  BOOLEAN DEFAULT TRUE,
comments            IN  VARCHAR2 DEFAULT 'null',
job_style           IN  VARCHAR2 DEFAULT 'REGULER',
credential_name     IN  VARCHAR2 DEFAULT 'null',
destination_name    IN  VARCHAR2 DEFAULT 'null',
max_run_duration    IN  BINARY_INTEGER DEFAULT 0);
```

## Parameters

|         Parameter        |       Description           |
|--------------------|-----------------------|
| job_name           | Specifies the name of the job. The name must be unique in the SQL namespace. If the job belongs to another schema, the schema name must be specified. If you do not specify a job name, an error is returned. You can also use the `GENERATE_JOB_NAME` procedure to generate a name. The generated name is a sequence number, which can be prefixed with a string. The resulting name is used in the `CREATE_JOB` procedure.   |
| job_type           | Specifies the type of the job to be created. If this parameter is not specified, an error is returned. The current version only supports `STORED_PROCEDURE`. This parameter is applicable only to procedures and not to functions with return values.   |
| job_action         | Specifies the action of the job. If you do not specify `job_action` for an inline procedure, an error is returned when the job is created. `job_action` is executed within autonomous transactions and follows all autonomous transaction rules and limitations. For a stored procedure, `job_action` is the name of the stored procedure. If the stored procedure is located in a different schema, the schema must be specified. If case-sensitive names are required, enclose the schema name and stored procedure name in double quotation marks. For example, `job_action_proc=>'"Schema"."myProc "'`. When the job or procedure type is `STORED_PROCEDURE`, `job_action` does not support PL procedures with `INOUT` or `OUT` parameters.   |
| number_of_argument | Specifies the number of parameters required for the job. The valid range is \[0,255\], with a default value of 0.   |
| program_name       | The name of the program associated with the job.   |
| start_date         | Specifies the date and time when the job plan is first executed. If both `start_date` and `repeat_interval` are empty, the job runs immediately after it is enabled. |
| repeat_interval    | Specifies the frequency at which the job repeats. You can use a calendar expression or a PL expression to specify the repeat interval. The next execution time of the job is determined by evaluating the specified expression.<br> **Note** If this parameter is set to an empty string, an error is returned, but the feature remains available.</br> This attribute can take the following values:<ul><li>`FREQ`: Specifies the repeat type. Required. Valid predefined frequency values are `YEARLY`, `MONTHLY`, `WEEKLY`, `DAILY`, `HOURLY`, `MINUTELY`, and `SECONDLY`. You can also specify an existing schedule as a user-defined frequency.</li><li>`INTERVAL`: Specifies a positive integer indicating the repeat frequency. The default value is `1`, indicating a repeat every second.<main id="notice" type='notice'><h4>Notice</h4><p>When used with <code>BY</code>, <code>INTERVAL</code> must appear before <code>BY</code>. For example, <code>freq=YEARLY;INTERVAL=2;BYMONTH=JUL</code>.</p></main></li><li>`BYMONTH`: Specifies the month in which the job runs. Valid values are the abbreviations of months, numbers, or a list of these values. Values in a list are separated by commas. Valid range: [1, 12].</li><li>`BYYEARDAY`: Specifies a day of the year in numeric form. Valid values: [1, 366].</li><li>`BYMONTHDAY`: Specifies the day of the month. Valid values are numbers or a list of these values. Values in a list are separated by commas. Valid range: [1, 31].</li><li>`BYDAY`: Specifies a list of days. Valid values are the abbreviations of days, such as `MON`, or a list of these abbreviations. Values in a list are separated by commas. The first day of the week is Monday.<main id="notice" type='explain'><h4>Note</h4><p>Negative values are not supported for <code>BYDAY</code>. For example, <code>FREQ=MONTHLY;BYDAY=-1FRI</code> specifies the last Friday of each month. If specified, <code>OB_PASSER_ERROR</code> is returned.</p></main></li><li>`BYHOUR`: Specifies the hour when the job runs. Valid values are numbers or a list of these values. Values in a list are separated by commas. Valid range: [0, 23].</li><li>`BYMINUTE`: Specifies the minute when the job runs. Valid values are numbers or a list of these values. Values in a list are separated by commas. Valid range: [0, 59].</li><li> `BYSECOND`: Specifies the second when the job runs. Valid values are numbers or a list of these values. Values in a list are separated by commas. Valid range: [0, 59].</li></ul> In addition to specifying the repeat frequency individually, you can also specify it in combination. The combination conditions are as follows:<ul><li>When `FREQ = YEARLY`, you can use `BYMONTH + BYMONTHDAY` or `BYYEARDAY`, followed by `BYHOUR + BYMINUTE + BYSECONDY`.</li><li>When `FREQ = MONTHLY`, you can use `BYMONTHDAY + BYHOUR + BYMINUTE + BYSECOND`.</li><li>When `FREQ = WEEKLY`, you can use `BYDAY + BYHOUR + BYMINUTE + BYSECOND`.</li><li>When `FREQ = DAILY`, you can use `BYHOUR + BYMINUTE + BYSECOND`.</li><li>When `FREQ = HOURLY`, you can use `BYMINUTE + BYSECOND`.</li><li>When `FREQ = MINUTELY`, you can use `BYSECOND`.</li><li>When `FREQ = SECONDLY`, you cannot use `BYXXX`.</li></ul>   |
| end_date           | Specifies the expiration date and time of the job, after which the job will no longer run. After `end_date`, if `auto_drop` is `TRUE`, the job is dropped. If `auto_drop` is `FALSE`, the job is disabled, and its `STATE` is set to `COMPLETED`. If you do not specify `end_date`, the job will continue to run until it reaches the maximum number of runs or failures specified by `max_runs` or `max_failures`. If neither `max_runs` nor `max_failures` is specified, the job will run indefinitely. `end_date` must be after `start_date`; otherwise, an error is returned. If `end_date` is the same as `start_date`, the job will not run and no error will be returned. |
| job_class          | The class associated with the job. |
| enabled            | Specifies whether to enable the created job. This attribute can be set to `TRUE` or `FALSE`, with a default value of `FALSE`, meaning the job is disabled by default. For disabled jobs, although their metadata is captured and they are considered database objects, the Scheduler will ignore and not process them. To process a disabled job, you can set this parameter to `TRUE` or use the `ENABLE` procedure to enable the job.  |
| auto_drop          | Specifies whether the job is automatically deleted after it completes or is automatically disabled. This attribute can be set to `TRUE` or `FALSE`. If set to `TRUE`, the job will be automatically deleted after it completes or is automatically disabled. A job is considered completed under the following conditions: <ul><li> The job's end date (or the end date of its schedule) has passed.   </li><li> The job has run `max_runs` times. You must use `SET_ATTRIBUTE` to set `max_runs`.   </li><li> The job is a one-time, non-repeating job that has run only once. </li></ul>    If a job fails `max_failures` times, it will be disabled. `max_failures` is also set using `SET_ATTRIBUTE`. If `auto_drop` is set to `FALSE`, the job will not be deleted and its metadata will be retained until it is explicitly dropped using the `DROP_JOB` procedure. By default, `auto_drop` is set to `TRUE` when a job is created.                                |
| comments           | Adds comments to the job. By default, this attribute is `NULL`.  |
| job_style          | Specifies the style of the job being created. Possible values: <ul><li> `'REGULAR' `: Creates a regular job, which is the default setting.   </li><li> `'LIGHTWEIGHT'`: Creates a lightweight job. This value is only allowed if the job references program objects. Lightweight jobs are recommended for frequent execution of many short-term jobs. In some cases, lightweight jobs can offer minor performance improvements.   </li><li> `'IN_MEMORY_RUNTIME'`: Creates an in-memory runtime job. These jobs are based on the lightweight job structure and further improve performance by maintaining an in-memory cache, thus minimizing disk access for operations before and after execution.   </li><li> `'IN_MEMORY_FULL'`: Creates a fully in-memory job. Fully in-memory jobs require a program and cannot have a schedule or repeat interval. When enabled, they automatically run and are then discarded. They store all job information in memory without backing it up to disk, meaning the information is lost upon instance restart. Their purpose is to execute critical operations with minimal overhead. </li></ul>    |
| credential_name    | Specifies the default credential used with the job. For local database jobs, this value must be `NULL`. For local external jobs, if this attribute is `NULL` (the default), the preferred (default) credential is selected.   |
| destination_name   | Specifies the database or external destination for the job. If the `credential_name` parameter of `CREATE_JOB` is `NULL`, each destination must be prefixed with a credential, in the format `sql credential.destination`.    |
| max_run_duration   | Specifies the maximum duration for which the job can run. |

## Considerations

By default, jobs created by users are disabled. You must explicitly enable a job to run it as scheduled.

To associate a job with a specific class or program, you must have the `EXECUTE` privilege on the class or program.

Not all possible job attributes can be set using `CREATE_JOB`. Some parameters must be set after the job is created. For example, parameters such as `job_priority` and `max_runs` must be set using the `SET_ATTRIBUTE` procedure.

## Examples

```sql
DECLARE
    i INTEGER;
BEGIN
    SELECT COUNT(*) INTO i FROM user_tables WHERE table_name = 'DBMS_SCHEDULER_T1';
    IF i = 0 THEN
        EXECUTE IMMEDIATE  'CREATE TABLE DBMS_SCHEDULER_T1(col DATE)';
    END IF;
    SELECT COUNT(*) INTO i FROM user_tables WHERE table_name = 'DBMS_SCHEDULER_T2';
    IF i = 0 THEN
        EXECUTE IMMEDIATE  'CREATE TABLE DBMS_SCHEDULER_T2(col DATE, job VARCHAR(128), job_name VARCHAR(128))';
    END IF;
END;
/

CREATE OR REPLACE PACKAGE JOB_UTILS IS
  PROCEDURE insert_date;
  PROCEDURE insert_date_program ( job IN VARCHAR2, job_name IN VARCHAR2);
END;
/

CREATE OR REPLACE PACKAGE BODY JOB_UTILS IS
  PROCEDURE insert_date IS
  BEGIN
    INSERT INTO DBMS_SCHEDULER_T1 VALUES(TO_CHAR(sysdate));
    COMMIT;
  END;
  PROCEDURE insert_date_program ( job IN VARCHAR2, job_name IN VARCHAR2) IS
  BEGIN
    INSERT INTO DBMS_SCHEDULER_T2 VALUES(sysdate, job, job_name);
    COMMIT;
  END;
END;
/

 BEGIN
     DBMS_SCHEDULER.CREATE_JOB(
             job_name => dbms_scheduler.generate_job_name,
             job_type => 'STORED_PROCEDURE',
             job_action => 'JOB_UTILS.insert_date',
            number_of_argument  => 5,
            start_date  => sysdate ,
             repeat_interval => 'FREQ=SECONDLY; INTERVAL=8',
            end_date  =>sysdate + 100 ,
            job_class   =>'DEFAULT_JOB_CLASS',
            enabled => true,
            auto_drop => true,
            comments =>'test' ,
           credential_name => 'null',
            destination_name => 'null');
           COMMIT;
       END;
       /

--View the job status in the business tenant:
SELECT JOB_NAME,enabled,NEXT_RUN_DATE,state,last_start_date FROM DBA_SCHEDULER_JOBS;
```
