# Overview

The `DBMS_PROFILER` package records the execution of each line of PL/SQL and aggregates the results to provide detailed execution times for each statement during PL/SQL execution.

<main id="notice" >
    <h4>Applicability</h4>
    <p>This topic applies only to OceanBase Database Enterprise Edition. OceanBase Database Community Edition does not support this feature. </p>
  </main>

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>For V4.2.x versions, starting from V4.2.5 BP7, the PL disk cache can be reused after enabling the `DBMS_PROFILER` package. <br>For V4.6.x versions, starting from V4.6.0, the PL disk cache can be reused after enabling the `DBMS_PROFILER` package. </p>
</main>

## Privilege requirements

The privilege of this package is `AUTHID CURRENT_USER`.

The following table lists the `DBMS_PROFILER` subprograms supported in the current version of OceanBase Database and their brief descriptions.

## Calling process

Call the `DBMS_PROFILER.start_profiler` procedure to start the profiler. After that, the execution count and time of each line of PL/SQL in the current session will be recorded. If the system needs to be warmed up, you can use the `DBMS_PROFILER.pause_profiler` procedure to pause the profiler to prevent the warm-up process from being recorded. After the system is warmed up, you can use the `DBMS_PROFILER.resume_profiler` procedure to resume recording the execution. After the PL/SQL execution that needs to be analyzed is completed, call the `DBMS_PROFILER.stop_profiler` procedure to stop the profiler. All recorded data will be aggregated to the data statistics table. You can query the data statistics table to analyze the performance.

## Example

1. Create the PROC1 stored procedure.

   ```sql
   obclient> CREATE OR REPLACE PROCEDURE PROC1 AS
   BEGIN
       NULL;
   END;
   /
   ```

2. Create the PROC0 stored procedure.

   ```sql
   obclient> CREATE OR REPLACE PROCEDURE PROC0 AS
   BEGIN
       PROC1();
   END;
   /
   ```

3. Start the profiler.

   ```sql
   obclient> CALL DBMS_PROFILER.start_profiler();
   ```

4. Call the PROC0 stored procedure.

   ```sql
   obclient> CALL PROC0();
   ```

   Execute the PROC0 stored procedure. Since the profiler is enabled, the data from this call will be collected for subsequent analysis.

5. Stop the profiler.

   ```sql
   obclient> CALL DBMS_PROFILER.stop_profiler();
   ```

6. View the performance analysis run information.

   ```sql
   obclient> SELECT * FROM PLSQL_PROFILER_RUNS;
   ```

   Execution result:

   ```text
   +-------+-------------+-----------+-----------+-------------+----------------+-----------------+--------------+--------+
   | RUNID | RELATED_RUN | RUN_OWNER | RUN_DATE  | RUN_COMMENT | RUN_TOTAL_TIME | RUN_SYSTEM_INFO | RUN_COMMENT1 | SPARE1 |
   +-------+-------------+-----------+-----------+-------------+----------------+-----------------+--------------+--------+
   |     1 |        NULL | SYS       | 10-JAN-25 | 10-JAN-25   |    34000000000 | NULL            | NULL         | NULL   |
   +-------+-------------+-----------+-----------+-------------+----------------+-----------------+--------------+--------+
   1 row in set (0.002 sec)
   ```

7. View the information of the analyzed units.

   ```sql
   obclient> SELECT * FROM PLSQL_PROFILER_UNITS;
   ```

   Execution result:

   ```text
   +-------+-------------+-----------+------------+-----------+----------------+------------+--------+--------+
   | RUNID | UNIT_NUMBER | UNIT_TYPE | UNIT_OWNER | UNIT_NAME | UNIT_TIMESTAMP | TOTAL_TIME | SPARE1 | SPARE2 |
   +-------+-------------+-----------+------------+-----------+----------------+------------+--------+--------+
   |     1 |      500025 | PROCEDURE | SYS        | PROCL     | 10-JAN-25      |          0 |   NULL |   NULL |
   |     1 |      500026 | PROCEDURE | SYS        | PROC0     | 10-JAN-25      |          0 |   NULL |   NULL |
   +-------+-------------+-----------+------------+-----------+----------------+------------+--------+--------+
   2 rows in set (0.004 sec)
   ```

   Query the `PLSQL_PROFILER_UNITS` table to view the information of each analyzed PL/SQL unit, including the unit type, name, and total time.

8. View the performance data at the row level.

   ```sql
   obclient> SELECT * FROM PLSQL_PROFILER_DATA;
   ```

   Execution result:

   ```text
   +-------+-------------+-------+-------------+------------+----------+----------+--------+--------+--------+--------+
   | RUNID | UNIT_NUMBER | LINE# | TOTAL_OCCUR | TOTAL_TIME | MIN_TIME | MAX_TIME | SPARE1 | SPARE2 | SPARE3 | SPARE4 |
   +-------+-------------+-------+-------------+------------+----------+----------+--------+--------+--------+--------+
   |     1 |      500025 |     1 |           1 |        537 |      537 |      537 |   NULL |   NULL |   NULL |   NULL |
   |     1 |      500025 |     3 |           1 |       7118 |     7118 |     7118 |   NULL |   NULL |   NULL |   NULL |
   |     1 |      500026 |     1 |           1 |        406 |      406 |      406 |   NULL |   NULL |   NULL |   NULL |
   |     1 |      500026 |     3 |           1 |   16031017 | 16031017 | 16031017 |   NULL |   NULL |   NULL |   NULL |
   +-------+-------------+-------+-------------+------------+----------+----------+--------+--------+--------+--------+
   4 rows in set (0.002 sec)
   ```

   Query the `PLSQL_PROFILER_DATA` table to view the detailed performance statistics of specific rows in each PL/SQL unit, including the number of times the row was executed, total execution time, and minimum and maximum execution times.
