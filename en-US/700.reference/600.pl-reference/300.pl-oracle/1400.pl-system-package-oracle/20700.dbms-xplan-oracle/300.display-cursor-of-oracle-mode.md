# DISPLAY_CURSOR

The `DISPLAY_CURSOR` function is used to display detailed information about executed query plans.

## Limitations

This feature is supported starting from V4.3.5 BP2 for V4.3.5.

## Syntax

```sql
DBMS_XPLAN.DISPLAY_CURSOR(plan_id      INTEGER          DEFAULT    0,         -- default value: last plan
                          format       VARCHAR2         DEFAULT    'TYPICAL',
                          svr_ip       VARCHAR2         DEFAULT    null,   -- default value: server connected by client
                          svr_port     INTEGER          DEFAULT    0,     -- default value: server connected by client
                          tenant_id    INTEGER          DEFAULT    0,     -- default value: current tenant
                          sql_handle   VARCHAR2         DEFAULT    NULL,
                          plan_name    VARCHAR2         DEFAULT    NULL
                        )
RETURN DBMS_XPLAN_TYPE_TABLE;
```

## Parameters

| Parameter | Description |
| ---- | ---- |
| plan_id     | The ID of the execution plan. If not specified, the plan from the last execution is used. |
| format      | Specifies the plan format. Optional parameters are as follows:<ul><li>`'BASIC'`: Displays minimal information, such as operator ID, operator name, operator remarks, and expression information.</li><li>`'TYPICAL'`: Displays basic information, such as operator ID, operator name, operator remarks, optimizer-estimated output rows, optimizer-estimated execution time, and expression information. If the plan has been executed, it also displays actual feedback information from the first execution, such as actual rows and cost.</li><li>`'ALL'`: Displays comprehensive plan information, such as operator ID, operator name, operator remarks, optimizer-estimated output rows, optimizer-estimated execution time, expression information, effective hints, query block name trace information, outline information, base table optimization information, constant parameterization information, constraint information, and plan notes.</li><li>`'ADVANCED'`: Displays comprehensive plan information, which is the same as the 'ALL' parameter. Additionally, it provides tree structure information for complex plans.</li></ul> |
| svr_ip      | The IP address of the node where the plan is located. The default is the IP address of the node to which the session is connected. |
| svr_port    | The port number of the node where the plan is located. The default is the port number of the node to which the session is connected. |
| tenant_id   | The tenant ID to which the plan belongs. The default is the tenant to which the session is currently connected. |
| sql_handle  | The handle (Handle) used to identify the SQL statement for the execution plan. When querying a specific execution plan for a SQL statement, especially when there are multiple similar SQL statements, you can use sql_handle to precisely specify the target statement. |
| plan_name   | The name of the execution plan. |

## Examples

For an Oracle tenant, this feature needs to be used in conjunction with the Function Table feature.

1. Create a table.

   ```shell
   obclient [test]> CREATE TABLE t1(c1 INT);
   ```

2. Execute a query.

   ```shell
   obclient [SYS]> SELECT * FROM t1;
   ```

3. Use the `DBMS_XPLAN` package to view historical plans.

   * Query without specifying parameters.

     obclient [SYS]> SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY_CURSOR());
