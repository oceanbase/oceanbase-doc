# PARSE

The `PARSE` stored procedure is used to parse a DML statement (including `SELECT`) or execute other statements such as DDL and system commands.

The `PARSE` procedure has multiple versions:

* Supports parameters of the `VARCHAR2` type.

* Supports parameters of the `VARCHAR2A` and `VARCHAR2S` types. For example, if the parameter is an array of strings, the `PARSE` procedure concatenates the strings in the array into a single SQL statement for parsing.

  <main id="notice" >
    <h4>Applicability</h4>
    <p>This topic applies only to OceanBase Database Enterprise Edition. OceanBase Database Community Edition provides only MySQL mode. </p>
  </main>

## Syntax

```sql
DBMS_SQL.PARSE(cursor_id       IN INTEGER,
sql_stmt      IN VARCHAR2,
language_flag   IN INTEGER);
```

```sql
DBMS_SQL.PARSE(cursor_id       IN INTEGER,
sql_stmt      IN VARCHAR2A,
lb            IN INTEGER,
ub            IN INTEGER,
lfflg         IN BOOLEAN,
language_flag   IN INTEGER);
```

```sql
DBMS_SQL.PARSE(cursor_id       IN INTEGER,
sql_stmt      IN VARCHAR2s,
lb            IN INTEGER,
ub            IN INTEGER,
lfflg         IN BOOLEAN,
language_flag   IN INTEGER);
```

## Parameters

|    **Parameter**     |           **Description**            |
|---------------|-----------------------------|
| cursor_id     | The cursor ID used to parse the statement or array.         |
| sql_stmt      | The SQL statement or array to be parsed.             |
| lb            | The lower bound of the array index.                     |
| ub            | The upper bound of the array index.                     |
| lfflg         | If the value is TRUE, a newline character is inserted after each cascading element. |
| language_flag | Specifies the behavior of the SQL statement.               |

## Considerations

* Using DBMS_SQL to dynamically execute DDL statements may cause the program to stop responding. For example, if a procedure in a package is called, the package is locked until the execution returns to the client. Any locking operations that cause conflicts (such as attempting to drop the package before the first lock is released) will prevent the program from running.

* Since client code cannot reference variables or constants in remote packages, you must explicitly use the values of constants. For example, the following code cannot be compiled on the client:

```sql
DBMS_SQL.PARSE(cur_hdl, stmt_str, DBMS_SQL.NATIVE);
-- Uses the constant DBMS_SQL.NATIVE
```

The following code is valid on the client because the parameter is explicitly provided:

```sql
DBMS_SQL.PARSE(cur_hdl, stmt_str, 1);
-- Compiled on the client
```

## Exceptions

If you create a type, procedure, function, or package using DBMS_SQL with compilation warnings, an error will be raised, but the PL unit will still be created.
