# Compile-Time Warnings

When stored PL units are compiled, the PL compiler issues warnings for conditions that do not cause errors or prevent the compilation of the unit. For example, the use of obsolete PL features.

    <h4>Function Applicability</h4>
    <p>This topic applies only to OceanBase Database Enterprise Edition. OceanBase Database Community Edition does not support this feature.</p>
  </main>

## Parameters

The format of an PL warning message code is `PLW-nnnnn`.

The following table describes the alert categories that are displayed during compilation.

| Category       |              Description              |                      Example                      |
|---------------|-------------------------------|---------------------------------------------|
| SEVERE        | May lead to unexpected behavior or incorrect results.            | Potential issues with parameter overlap.                                      |
| PERFORMANCE   | May cause performance issues.             | Passing `VARCHAR2` values to `NUMBER` columns in an `INSERT` statement. |
| INFORMATIONAL | Informational message. Does not affect performance or correctness but may require changes to make the code easier to maintain. | Never runs the code.                                    |

You can set the `PLSQL_WARNINGS` compilation parameter to achieve the following:

* Enable or disable all alerts, including one or more alert categories and the specified alerts.

* Treated as an error (must be corrected before PL units can be compiled).

The following items support setting the value of `PLSQL_WARNINGS`:

* The database instance uses the `ALTER SYSTEM` statement.

* The session uses the `ALTER SESSION` statement.

* Stored PL units use `ALTER` statement and its `compile_parameters_clause`.

For any of the above `ALTER` statements, use the following syntax to set the value of `PLSQL_WARNINGS`:

```sql
PLSQL_WARNINGS = 'value_clause [, value_clause] ...'
```

An example of using the `ALTER` statement to set the `PLSQL_WARNINGS` value is as follows.

**Example 1:** Enable all alerts for the current session.

```sql
ALTER SESSION SET PLSQL_WARNINGS='ENABLE:ALL';
```

**Example 2:** Close the `INFORMATIONAL` type of session.

```sql
ALTER SESSION SET PLSQL_WARNINGS='DISABLE:INFORMATIONAL';
```

**Example 3:** Enable the `PERFORMANCE` class alerts, disable the `SEVERE` class alerts, and treat the `PLW-07002` alerts as errors.

```sql
ALTER SESSION
SET PLSQL_WARNINGS='ENABLE:PERFORMANCE, DISABLE:SEVERE, ERROR:07002';
```

## DBMS_WARNING package

If you are writing PL/SQL units in a developement environment for compilable PL/SQL units, you can call the subprograms in the `DBMS_WARNING` package to display and set the `PLSQL_WARNINGS` value.

When you compile a complex application, the `DBMS_WARNING` subprogram can be used to set different `PLSQL_WARNINGS` values. The `DBMS_WARNING` subprogram can save the current `PLSQL_WARNINGS` setting, change the setting to compile a specified subprogram, and then restore the value to its original state.

Here is an example:

```javascript
obclient> ALTER SESSION SET PLSQL_WARNINGS='DISABLE:ALL';  --Disable all warning messages for this session.
Query OK, 0 rows affected

obclient> CREATE OR REPLACE PROCEDURE sample_code AUTHID DEFINER AS
  n CONSTANT BOOLEAN := TRUE;
BEGIN
  IF n THEN
    DBMS_OUTPUT.PUT_LINE('TRUE');
  ELSE
    DBMS_OUTPUT.PUT_LINE('FALSE');
  END IF;
END sample_code;
/
Query OK, 0 rows affected

obclient> CALL DBMS_WARNING.set_warning_setting_string ('ENABLE:ALL', 'SESSION'); --Enable all alert messages for this session.
Query OK, 0 rows affected

obclient> SELECT DBMS_WARNING.get_warning_setting_string() FROM DUAL; -- View the current warning settings.
+-------------------------------------------+
| DBMS_WARNING.GET_WARNING_SETTING_STRING() |
+-------------------------------------------+
| ENABLE:ALL                                |
+-------------------------------------------+
1 row in set
```
