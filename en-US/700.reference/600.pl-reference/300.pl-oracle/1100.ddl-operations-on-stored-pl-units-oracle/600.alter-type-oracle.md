# ALTER TYPE

The `ALTER TYPE` statement is used to add or drop member attributes or methods.

  <main id="notice" >
    <h4>Applicability</h4>
    <p>This topic applies only to OceanBase Database Enterprise Edition. OceanBase Database Community Edition does not support this statement. </p>
  </main>

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This statement is available starting from OceanBase Database V4.4.1. </p>
</main>

You can use the `ALTER TYPE` statement to change the existing attributes of an object type or modify its scalar attributes. You can also use this statement to recompile the specification or body of the type, or to change the specification of the object type by adding new object member subprogram specifications.

The `ALTER TYPE` statement can perform the following operations on types created using the `CREATE TYPE` and `CREATE TYPE BODY` statements:

* Evolve the type. This involves adding or dropping member attributes or methods.

* Change the specification of the type by adding object member subprogram specifications.

* Recompile the specification or body of the type.

* Reset the version of the type to 1, so that it is no longer considered for evolution.

## Prerequisites

If the type is in the `SYS` schema, you must connect as `SYSDBA`. Otherwise, the type must be in the current user's schema, or the user must have the `CREATE TYPE` or `CREATE ANY TYPE` system privilege.

## Syntax

```sql
  alter_type ::=
  ALTER TYPE [ schema. ] type_name {alter_type_clause | type_compile_clause};

  alter_type_clause ::=
  { alter_attribute_definition} [ dependent_handling_clause ];

  alter_attribute_definition ::=
  { { ADD | MODIFY } ATTRIBUTE
  { attribute [ datatype ]
  | ( attribute datatype [, attribute datatype ]... )
  }
  | DROP ATTRIBUTE
  { attribute
  | ( attribute [, attribute ]... )
  }
  }

  dependent_handling_clause ::=
  {CASCADE}

  type_compile_clause ::=
  COMPILE [ DEBUG ] [ SPECIFICATION | BODY ] [ REUSE SETTINGS ]
  ```

## Parameters

* `alter_attribute_definition`: used to add, drop, or modify the attributes of a user-defined type (UDT). In a single `ALTER TYPE` statement, you can add, drop, or modify multiple attributes, but each attribute can be referenced only once.
  * `ADD ATTRIBUTE`: used to add an attribute. The attribute name must not conflict with the names of existing attributes or methods. The attribute will be added to the end of the list of locally defined attributes.
  * `DROP ATTRIBUTE`: used to drop an attribute. You do not need to specify the data type of the attribute to be dropped, and you cannot drop all attributes.
  * `MODIFY ATTRIBUTE`: used to modify the data type length, precision, or scale of a scalar attribute. Currently, you can modify attributes of the `varchar`, `varchar2`, `raw`, and `number` types. You can only increase the length, precision, or scale of the attribute's data type. When you increase the scale, you must also increase the precision to ensure data range compatibility.
* `dependent_handing_clause`: a clause for handling dependent objects, such as tables or types that depend on the type. If the type being altered is depended on by other types, you must explicitly specify the `CASCADE` clause; otherwise, an error will be reported.

## Examples

Execute the following command to add a new attribute named `email` with the data type `varchar(100)` to the `person_type` type.

```shell
obclient> ALTER TYPE person_type ADD ATTRIBUTE email varchar(100);
```
