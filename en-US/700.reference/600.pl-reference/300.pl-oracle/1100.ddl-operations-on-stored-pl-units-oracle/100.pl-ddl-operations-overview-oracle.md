# Overview

This chapter describes the DDL operations supported by a database server on stored PL units, including create, alter, and drop operations.

  <main id="notice" >
    <h4>Applicability</h4>
    <p>This content applies only to OceanBase Database Enterprise Edition. OceanBase Database Community Edition does not support this feature. </p>
  </main>

## CREATE [OR REPLACE]

The `CREATE [OR REPLACE]` statement is used to create a PL unit.

The following SQL statements can be used: `CREATE FUNCTION`,
`CREATE PACKAGE`,
`CREATE PACKAGE BODY`
,`CREATE PROCEDURE`,`CREATE TRIGGER` ,
`CREATE TYPE` and
`CREATE TYPE BODY`.

Each `CREATE` statement contains an optional `OR REPLACE` clause. If you specify `OR REPLACE`, existing PL/SQL units can be re-created by changing their declarations or definitions without deleting them and then re-granting the object privileges granted to them previously. If you redefine a PL/SQL unit, the database will recompile it.

  <main id="notice" type='notice'>
    <h4>Considerations</h4>
    <p>The preceding <code>CREATE</code> statements cannot appear in a PL block. </p>
  </main>

## ALTER

The `ALTER` clause is used to recompile PL units without recreating them, without changing their declarations or definitions.

The supported SQL statements include `ALTER FUNCTION`,
The `ALTER_PACKAGE`, `ALTER_PROCEDURE`, `ALTER_TRIGGER` and
`ALTER TYPE`.

You can use `ALTER` statements for the following purposes:

* Explicitly recompiling invalidated stored units, thereby avoiding the need for implicit runtime recompilation and the associated runtime compilation errors and performance overhead.

* Recompile the stored unit with different compile options.

* Enable or disable a trigger.

## DROP

The `DROP` statement is used to remove an existing PL unit.

You can use the following SQL statements: `DROP FUNCTION`.
`DROP PACKAGE`,`DROP PROCEDURE`,`DROP TRIGGER` ,
`DROP TYPE` and
`DROP TYPE BODY`.
