# Overview

This chapter describes DDL operations on existing stored PL/SQL units.

  <main id="notice" >
    <h4>Applicability</h4>
    <p>This topic applies only to OceanBase Database Enterprise Edition. OceanBase Database Community Edition does not support this feature. </p>
  </main>

## CREATE [OR REPLACE]

Use `CREATE [OR REPLACE]` to create a PL/SQL unit.

You can execute the following SQL statements: `CREATE FUNCTION`、
`CREATE PACKAGE`、
`CREATE PACKAGE BODY`
、`CREATE PROCEDURE`、`CREATE TRIGGER` 、
`CREATE TYPE` and
`CREATE TYPE BODY`.

The `CREATE` statement can be optionally followed by the `OR REPLACE` clause. If you specify the `OR REPLACE` clause, the existing PL/SQL unit will be re-created, that is, its declaration or definition is modified without dropping the existing PL/SQL unit. Then the privileges granted to the PL/SQL unit are regranted. If you redefine the PL/SQL unit, the database recompiles it.

  <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>The <code>CREATE</code> statement cannot be used in PL/SQL blocks. </p>
  </main>

## ALTER

Use `ALTER` to recompile a PL/SQL unit without dropping it (that is, without modifying its declaration or definition).

You can execute the following SQL statements: `ALTER FUNCTION`、
`ALTER PACKAGE`、`ALTER PROCEDURE`、`ALTER TRIGGER` and
`ALTER TYPE`.

You can use the `ALTER` statement for the following reasons:

* To explicitly recompile a stored unit to avoid implicitly recompiling the unit during runtime or encountering compilation errors or performance overheads.

* To recompile a stored unit by using different compiler options.

* To enable or disable a trigger.

## DROP

Use `DROP` to drop a PL/SQL unit.

You can execute the following SQL statements: `DROP FUNCTION`、
`DROP PACKAGE`、`DROP PROCEDURE`、`DROP TRIGGER` 、
`DROP TYPE` and
`DROP TYPE BODY`.
