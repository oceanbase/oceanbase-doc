# DROP PROCEDURE

The `DROP PROCEDURE` statement is used to delete a standalone stored procedure from the database.

  <main id="notice" >
    <h4>Applicability</h4>
    <p>This topic applies only to OceanBase Database Enterprise Edition. OceanBase Database Community Edition does not support this statement. </p>
  </main>

  <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>Do not use this statement to drop a stored procedure from a package. Instead, use the <code>DROP PACKAGE</code> statement to drop the entire package, or use the <code>CREATE PACKAGE</code> statement with the <code>OR REPLACE</code> clause to redefine a package that does not contain the stored procedure. </p>
  </main>

## Prerequisites

The stored procedure must be in the current user's schema, or the user must have the `ALTER ANY PROCEDURE` system privilege.

## Syntax

The syntax of `drop_procedure` is as follows:

```sql
DROP PROCEDURE [ schema. ] procedure ;
```

## Semantics

|       Syntax       |    Keywords or syntax nodes    |                                                           Description                                                            |
|----------------|----------------|-------------------------------------------------------------------------------------------------------------------------|
| drop_procedure | schema         | The name of the schema where the stored procedure is located. The default value is the current user's schema.                                                                                    |
| drop_procedure | procedure_name | The name of the stored procedure to be dropped. When a stored procedure is dropped, the database invalidates all local objects that depend on it. If these objects are subsequently referenced, the database attempts to recompile them. If the dropped stored procedure has not been recreated, an error message is returned. |

## Examples

Drop the stored procedure `userlogin`.

```sql
DROP PROCEDURE userlogin;
```
