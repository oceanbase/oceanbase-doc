# EVENT

An EVENT is a predefined SQL task that can be automatically executed at a specific point in time or according to a specified time interval. Each event consists of a trigger condition (which is a scheduling plan), an SQL statement or stored procedure to be executed. The definition of an event is stored in the database and is maintained along with the database. This ensures that the event can be executed as scheduled even after the server is restarted.

Unlike triggers, which are triggered based on data operations, events are triggered based on time changes. Events allow you to automatically execute SQL statements or stored procedures according to preset time plans. This significantly enhances the automation capabilities of the database, making it suitable for various scenarios such as regular data maintenance, statistical summary, and scheduled notifications.

**Characteristics**：

* Scheduling rules:

  * Exact time point: You can set an EVENT to be executed at a specific point in time.

  * Periodic execution: An EVENT can be repeatedly executed on a periodic basis, such as on a second, minute, hour, day, or month.

  * Complex scheduling: You can combine keywords such as `EVERY`, `STARTS`, and `ENDS` to implement complex scheduling logic, such as executing an EVENT only on weekdays or within a specific date range.

* SQL support:

  * You can execute any valid SQL statements in an EVENT, including data insertion, update, and deletion.

  * Events support transactions to ensure the atomicity and consistency of event execution.

* Dynamic control:

  * You can enable or disable the event scheduler at runtime without restarting the service.

  * You can modify or delete existing events as needed to adapt to changing business requirements.

## Privileges required

To use events, you must have the `GRANT EVENT` privilege. For more information about privileges in OceanBase Database, see [Privilege types in MySQL mode](../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md
).

## Start and stop an EVENT

An EVENT is executed by a special event scheduler thread. You can use the following statements to start or stop the event scheduler.

* Start the event scheduler:

    ```shell
    obclient> SET GLOBAL event_scheduler = ON;
    ```

* Stop the event scheduler:

    ```shell
    obclient> SET GLOBAL event_scheduler = OFF;
    ```

## Considerations

* If you do not set `START TIME`, an EVENT that has no `END TIME` is set to run indefinitely.
* For a repeating EVENT, if the EVENT execution time is longer than the scheduling interval, multiple concurrent executions may occur. You need to ensure that the execution time is shorter than the scheduling interval.
* You cannot set an unlimited execution time. The maximum execution time for a one-time EVENT is 24 hours.
