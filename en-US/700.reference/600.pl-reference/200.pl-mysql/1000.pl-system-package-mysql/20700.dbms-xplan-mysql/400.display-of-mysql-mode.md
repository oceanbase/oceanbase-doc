# DISPLAY

The `DISPLAY` function is used to query and format historical `EXPLAIN` plans.

## Syntax

```sql
TYPE DBMS_XPLAN_TYPE_TABLE IS TABLE OF VARCHAR2(4000);

DBMS_XPLAN.DISPLAY(format VARCHAR2 DEFAULT 'TYPICAL',
                  statement_id VARCHAR2 DEFAULT null,
                  table_name   VARCHAR2 DEFAULT 'PLAN_TABLE',
                  filter_preds VARCHAR2 DEFAULT null)
RETURN DBMS_XPLAN_TYPE_TABLE;
```

## Parameters

| Parameter | Description |
| --- | --- |
| format | Specifies the plan format. Valid values are as follows:<ul><li>`'BASIC'`: displays limited information, such as operator ID, operator name, operator comment, and expression information.</li><li>`'TYPICAL'`: displays basic information, such as operator ID, operator name, operator comment, optimizer-estimated output rows, optimizer-estimated execution time, and expression information. If the plan has been executed, it also displays the actual feedback information, such as actual rows and cost.</li><li>`'ALL'`: displays comprehensive plan information, such as operator ID, operator name, operator comment, optimizer-estimated output rows, optimizer-estimated execution time, and expression information. It also displays the effective hint, query block name trace information, outline information, base table optimization information, constant parameterization information, constraint information, and plan note.</li><li>`'ADVANCED'`: displays comprehensive plan information. The plan information is the same as that specified by the 'ALL' parameter. In addition, it displays tree structure information for complex plans.</li></ul>|
| statement_id | The identifier of the `EXPLAIN` query. You can run the `EXPLAIN SET STATEMENT_ID='XXX'` command to set the identifier. |
| table_name | The target table for storing the `EXPLAIN` plan. The default value is `PLAN_TABLE`. |
| filter_preds | Additional `PLAN_TABLE` filter conditions for filtering specific operators or plans. |
