# DISPLAY

The `DISPLAY` function is used to query and format historical `EXPLAIN` plans.

## Syntax

```sql
TYPE DBMS_XPLAN_TYPE_TABLE IS TABLE OF VARCHAR2(4000);

DBMS_XPLAN.DISPLAY(format VARCHAR2 DEFAULT 'TYPICAL',
                  statement_id VARCHAR2 DEFAULT null,
                  table_name   VARCHAR2 DEFAULT 'PLAN_TABLE',
                  filter_preds VARCHAR2 DEFAULT null)
RETURN DBMS_XPLAN_TYPE_TABLE;
```

## Parameters

| Parameter | Description |
| --- | --- |
| format | Specifies the plan format information. The optional values are as follows:<ul><li>`'BASIC'`: displays a small amount of information, such as operator ID, operator name, operator remarks, and expression information.</li><li> `'TYPICAL'`: displays basic information, such as operator ID, operator name, operator remarks, optimizer-estimated output rows, optimizer-estimated execution time, and expression information. If the plan has been executed, it also displays the actual feedback information from the first execution, such as actual rows and cost.</li><li> `'ALL'`: displays rich plan information, such as operator ID, operator name, operator remarks, optimizer-estimated output rows, optimizer-estimated execution time, expression information, effective hints, query block name trace information, outline information, base table optimization information, constant parameterization information, constraint information, and plan note.</li><li> `'ADVANCED'`: displays rich plan information, which is the same as the 'ALL' parameter. In addition, it displays tree structure information for complex plans.</li></ul>|
| statement_id | The marker information for the `EXPLAIN` query. You can set the marker information for the query by using the `EXPLAIN SET STATEMENT_ID='XXX'` command. |
| table_name | The target table for saving the `EXPLAIN` plan. The default value is `PLAN_TABLE`. |
| filter_preds | Additional `PLAN_TABLE` filter conditions for filtering specific operators or plans. |
