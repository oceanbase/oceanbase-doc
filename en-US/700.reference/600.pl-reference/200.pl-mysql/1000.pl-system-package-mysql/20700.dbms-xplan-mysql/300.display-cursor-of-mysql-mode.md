# DISPLAY_CURSOR

The `DISPLAY_CURSOR` function is used to display the details of the executed query plan.

## Limitations

For V4.3.5, this feature is supported starting from V4.3.5 BP2.

## Syntax

```sql
DBMS_XPLAN.DISPLAY_CURSOR(plan_id      DECIMAL          DEFAULT    0,         -- default value: last plan
                          format       VARCHAR(32)      DEFAULT    'TYPICAL',
                          svr_ip       VARCHAR(64)      DEFAULT    null,   -- default value: server connected by client
                          svr_port     DECIMAL          DEFAULT    0,     -- default value: server connected by client
                          tenant_id    DECIMAL          DEFAULT    0,     -- default value: current tenant
                          sql_handle   VARCHAR(32)      DEFAULT    NULL,
                          plan_name    VARCHAR(32)      DEFAULT    NULL
                        )
RETURN DBMS_XPLAN_TYPE_TABLE;
```

## Parameters

| Parameter | Description |
| ---- | ---- |
| plan_id   | The ID of the execution plan. If not specified, the plan from the last execution is used. |
| format    | Specifies the format of the plan information. The optional parameters are as follows:<ul><li>`'BASIC'`: Displays minimal information, such as operator ID, operator name, operator remarks, and expression information.</li><li> `'TYPICAL'`: Displays basic information, such as operator ID, operator name, operator remarks, optimizer-estimated output rows, optimizer-estimated execution time, and expression information. If the plan has been executed, it also displays the actual feedback information from the first execution, such as actual rows and cost.</li><li> `'ALL'`: Displays comprehensive plan information, such as operator ID, operator name, operator remarks, optimizer-estimated output rows, optimizer-estimated execution time, expression information, effective hints, query block name trace information, outline information, base table optimization information, constant parameterization information, constraint information, and plan note.</li><li> `'ADVANCED'`: Displays comprehensive plan information, which is the same as the 'ALL' parameter. Additionally, for complex plans, it displays tree structure information.</li></ul> |
| svr_ip    | The IP address of the node where the plan is located. The default is the IP address of the node to which the session is connected.|
| svr_port  | The port number of the node where the plan is located. The default is the port number of the node to which the session is connected.|
| tenant_id | The tenant ID to which the plan belongs. The default is the tenant to which the session is currently connected.|
| sql_handle  | The handle (Handle) used to identify the SQL statement for the execution plan. When querying a specific execution plan for a particular SQL statement, the sql_handle can be used to precisely specify the target statement when there are multiple similar SQL statements.|
| plan_name   | The name of the execution plan.|

## Examples

In a MySQL tenant, since the Function Table feature is not available, the `DISPLAY_CURSOR` function can be directly used in a `SELECT` statement to output the plan information.

1. Create a table.

   ```shell
   obclient [test]> CREATE TABLE t1(c1 INT);
   ```

2. Execute a query.

   ```shell
   obclient [test]> SELECT * FROM t1;
   ```

3. Use the `DBMS_XPLAN` package to view historical plans.

   * Query without specifying parameters.

     ```shell
     obclient [test]> SELECT DBMS_XPLAN.DISPLAY_CURSOR() ;
     ```

     The query result is as follows:
