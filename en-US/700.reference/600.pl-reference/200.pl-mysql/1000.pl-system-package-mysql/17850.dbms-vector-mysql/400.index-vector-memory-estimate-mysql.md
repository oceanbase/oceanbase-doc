# INDEX_VECTOR_MEMORY_ESTIMATE

The `INDEX_VECTOR_MEMORY_ESTIMATE` function is used to analyze the memory usage of a vector index on an existing table.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>This function depends on statistical information. Before using it, you must execute the <code>ANALYZE TABLE</code> command to update the statistical information. </p>
</main>

## Syntax

```sql
FUNCTION INDEX_VECTOR_MEMORY_ESTIMATE (
    IN     TABLE_NAME        VARCHAR(65535),
    IN     COLUMN_NAME       VARCHAR(65535),
    IN     IDX_TYPE          VARCHAR(65535),
    IN     IDX_PARAMETERS    LONGTEXT DEFAULT NULL
);
```

Here is a description of the function:

* The `INDEX_VECTOR_MEMORY_ESTIMATE` function reads the dimension and data type of the vector column specified by `table_name` and `column_name`, and the total number of vectors and the maximum number of vectors in a partition from the statistical information. The computation process of the function is consistent with that of `INDEX_VECTOR_MEMORY_ADVISOR`.
* For sparse vectors, the function samples 100 random vectors and calculates the average number of non-zero dimensions of these vectors as the average length of the sparse vectors. It then performs memory estimation based on this average length.

## Parameters

| Parameter | Description |
| --- | --- |
| table_name | The name of the table. This parameter can be specified as the table name alone, or it can specify the database and table names. |
| column_name | The name of the vector column. |
| idx_type | The index type. Valid values: `HNSW`/`HNSW_SQ`/`HNSW_BQ`/`IVF_FLAT`/`IVF_PQ`/`SINDI`/`SINDI_SQ`. The value is case-insensitive. |
| idx_parameters | The index parameter. It is the string of vector index parameters used when creating the table. For example, `distance=l2, type=hnsw, lib=vsag`. For more information about the parameters, see [Vector index memory management](../../../../../640.ob-vector-search/200.ob-vector-index/200.ob-vector-index-memory-management.md). |

The function returns a string that describes the result of the memory estimation.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>In OceanBase Database, when you create an HNSW_BQ index, the system automatically chooses a parallel or serial method for partitioned tables based on memory availability. The recommended memory value returned by <code>INDEX_VECTOR_MEMORY_ESTIMATE</code> represents the maximum required memory for index creation in serial mode. If the available memory is only sufficient for this value, and the system cannot parallelize the index creation, the index creation time will be extended. </p>
</main>

## Examples

1. Create a table named `t1` and insert data into it.

    ```sql
    CREATE TABLE t1 (id int auto_increment, c1 vector(3));
    INSERT INTO t1(c1) SELECT array(1/UNIFORM(1,1000,RANDOM(1)), 1/UNIFORM(1,1000,RANDOM(2)) , 1/UNIFORM(1,1000,RANDOM(3))) FROM table(generator(10000));
    ```

2. Update the statistical information of table `t1`.

    ```sql
    ANALYZE TABLE t1;
    ```

3. Query the memory estimation result for the vector index of the table `t1`.

    ```sql
    -- Query the memory estimation result for the HNSW index.
    SELECT dbms_vector.index_vector_memory_estimate('t1','c1','HNSW','M=10,TYPE=HNSW');
    +-----------------------------------------------------------------------------+
    | dbms_vector.index_vector_memory_estimate('t1','c1','HNSW','M=10,TYPE=HNSW') |
    +-----------------------------------------------------------------------------+
    | Suggested minimum vector memory is 11.5 MB                                  |
    +-----------------------------------------------------------------------------+
    1 row in set

    -- Query the memory estimation result for the IVF index.
    SELECT dbms_vector.index_vector_memory_estimate('t1','c1','IVF_FLAT','SAMPLE_PER_NLIST=100');
    +---------------------------------------------------------------------------------------------------------+
    | dbms_vector.index_vector_memory_estimate('t1','c1','IVF_FLAT','SAMPLE_PER_NLIST=100')                   |
    +---------------------------------------------------------------------------------------------------------+
    | Suggested minimum vector memory is 151.5 KB, memory consumption when providing search service is 1.5 KB |
    +---------------------------------------------------------------------------------------------------------+
    1 row in set

    -- Query the memory estimation result for the SINDI index.
    SELECT dbms_vector.index_vector_memory_estimate('t1','c1','SINDI','TYPE=SINDI,LIB=VSAG,DISTANCE=INNER_PRODUCT');
    +----------------------------------------------------------------------------------------------------------+
    | dbms_vector.index_vector_memory_estimate('t1','c1','SINDI','TYPE=SINDI,LIB=VSAG,DISTANCE=INNER_PRODUCT') |
    +----------------------------------------------------------------------------------------------------------+
    | Suggested minimum vector memory is 73.6 MB                                                               |
    +----------------------------------------------------------------------------------------------------------+
    1 row in set
    ```
