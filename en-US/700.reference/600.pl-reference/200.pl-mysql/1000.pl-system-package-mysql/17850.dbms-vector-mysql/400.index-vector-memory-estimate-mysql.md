# INDEX_VECTOR_MEMORY_ESTIMATE

The `INDEX_VECTOR_MEMORY_ESTIMATE` function is used to analyze the memory usage of vector indexes in existing tables.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>The calculation of this function depends on statistics. Before calling it, you must execute the <code>ANALYZE TABLE</code> statement to update the statistics. </p>
</main>

## Syntax

```sql
FUNCTION INDEX_VECTOR_MEMORY_ESTIMATE (
    IN     TABLE_NAME        VARCHAR(65535),
    IN     COLUMN_NAME       VARCHAR(65535),
    IN     IDX_TYPE          VARCHAR(65535),
    IN     IDX_PARAMETERS    LONGTEXT DEFAULT NULL
);
```

The `INDEX_VECTOR_MEMORY_ESTIMATE` function reads the dimension and data type information of the vector column based on `table_name` and `column_name`, and obtains the total number of vectors and the maximum number of vectors in a partition based on the statistics. The calculation process of the estimated memory is the same as that of the `INDEX_VECTOR_MEMORY_ADVISOR` function.

## Parameters

| Parameter | Description |
| --- | --- |
| table_name | The name of the table. You can directly specify the table name or specify the database name and table name. |
| column_name | The name of the vector column. |
| idx_type | The type of the index. Valid values: <ul><li>For dense indexes, you can specify `HNSW`, `HNSW_SQ`, `HNSW_BQ`, `IVF_FLAT`, `IVF_SQ8`, or `IVF_PQ`. The value is case-insensitive. </li><li>For sparse indexes, you can specify `SINDI`. The value is case-insensitive. </li></ul> |
| idx_parameters | The parameters of the index. The value is the string of parameters used when the index was created. For example, `distance=l2, type=hnsw, lib=vsag`. For more information, see [Create a vector index](../../../../../640.ob-vector-search/200.ob-vector-index/200.ob-vector-index.md). |

The return value is a string that describes the estimated memory.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>In OceanBase Database, when you create an HNSW_BQ index, the system automatically selects the parallel or serial method for creating the index for a partitioned table based on the memory situation. The recommended value returned by the <code>INDEX_VECTOR_MEMORY_ESTIMATE</code> function is the maximum memory required when the index is created in serial mode. If the memory only meets this value, the index creation time may be extended because the index cannot be created in parallel. </p>
</main>

## Examples

1. Create a table named `t1` and insert data into it.

    ```sql
    CREATE TABLE t1 (id int auto_increment, c1 vector(3));
    INSERT INTO t1(c1) SELECT array(1/UNIFORM(1,1000,RANDOM(1)), 1/UNIFORM(1,1000,RANDOM(2)) , 1/UNIFORM(1,1000,RANDOM(3))) FROM table(generator(10000));
    ```

2. Update the statistics of the `t1` table.

    ```sql
    ANALYZE TABLE t1;
    ```

3. Query the memory estimation result of the vector index of the `t1` table.

    ```sql
    -- Query the memory estimation result of the HNSW index.
    SELECT dbms_vector.index_vector_memory_estimate('t1','c1','HNSW','M=10,TYPE=HNSW');
    +-----------------------------------------------------------------------------+
    | dbms_vector.index_vector_memory_estimate('t1','c1','HNSW','M=10,TYPE=HNSW') |
    +-----------------------------------------------------------------------------+
    | Suggested minimum vector memory is 11.5 MB                                  |
    +-----------------------------------------------------------------------------+
    1 row in set

    -- Query the memory estimation result of the IVF index.
    SELECT dbms_vector.index_vector_memory_estimate('t1','c1','IVF_FLAT','SAMPLE_PER_NLIST=100');
    +---------------------------------------------------------------------------------------------------------+
    | dbms_vector.index_vector_memory_estimate('t1','c1','IVF_FLAT','SAMPLE_PER_NLIST=100')                   |
    +---------------------------------------------------------------------------------------------------------+
    | Suggested minimum vector memory is 151.5 KB, memory consumption when providing search service is 1.5 KB |
    +---------------------------------------------------------------------------------------------------------+
    1 row in set

    -- Query the memory estimation result of the SINDI index.
    SELECT dbms_vector.index_vector_memory_estimate('t1','c1','SINDI','TYPE=SINDI,LIB=VSAG,DISTANCE=INNER_PRODUCT');
    +----------------------------------------------------------------------------------------------------------+
    | dbms_vector.index_vector_memory_estimate('t1','c1','SINDI','TYPE=SINDI,LIB=VSAG,DISTANCE=INNER_PRODUCT') |
    +----------------------------------------------------------------------------------------------------------+
    | Suggested minimum vector memory is 73.6 MB                                                               |
    +----------------------------------------------------------------------------------------------------------+
    1 row in set
    ```
