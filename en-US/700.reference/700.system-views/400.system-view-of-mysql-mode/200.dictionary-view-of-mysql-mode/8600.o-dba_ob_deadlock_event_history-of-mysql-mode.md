# oceanbase.DBA_OB_DEADLOCK_EVENT_HISTORY

## Purpose
The `oceanbase.DBA_OB_DEADLOCK_EVENT_HISTORY` view displays the history of deadlock events. You can query this view from a user tenant for the history of deadlock events of the current tenant.
<main id="notice" type='explain'>
<h4>Note</h4>

<p>This view is introduced since OceanBase Database V4.0.0. </p>

The `DBA_OB_DEADLOCK_EVENT_HISTORY` view shows the history of deadlock events in the current tenant.

## Columns

| Column | Type | Nullable? | Description |
| ------- | ------ | ------ | ------ |
| EVENT_ID       | bigint(20) unsigned | NO   | The number of the deadlock event. |
| SVR_IP         | varchar(46)         | NO   | The IP address of the node involved in the deadlock event.     |
| SVR_PORT       | bigint(20) unsigned | NO   | The port number of a participant node in the deadlock event.    |
| DETECTOR_ID    | bigint(20) unsigned | NO   | The ID of a node involved in the deadlock event (unique within a process).     |
| REPORT_TIME    | timestamp(6)        | NO   | The reporting time for this deadlock event (based on the timestamp of the reporting server).     |
| CYCLE_IDX      | bigint(20)          | NO   | The identifier of the node in a cycle.     |
| CYCLE_SIZE     | bigint(20)          | NO   | The number of nodes in the deadlock event.     |
| ROLE           | longtext            | NO   | The role of this node in the deadlock event:<li>witness<li>victim     |
| PRIORITY_LEVEL | longtext            | NO   | The description of the priority level of this node:<li>extreme-low<li>low<li>normal<li>high<li>extreme-high     |
| PRIORITY       | bigint(20) unsigned | NO   | The value of the node's priority. If the priorities are the same, the nodes with the lowest priority value are eliminated from the ring.     |
| CREATE_TIME    | timestamp(6)        | NO   | The time when the node is created      |
| START_DELAY_US | bigint(20) unsigned | NO   | The interval in microseconds from the node's creation until it is allowed to start detecting deadlocks.     |
| MODULE         | longtext            | NO   | The module to which the node belongs. It is fixed as transaction. |
| VISITOR        | longtext            | NO   | The identifier of the resource that is accessed by the node. The identifier is in the format `{session_id:$1}:{txid:$2}`. `$1` and `$2` are numeric values.  |
| OBJECT         | longtext            | NO   | The resource to be acquired by this node. It must be specified as `{addr:“$1:$2”}:{ls:$3}:{tablet:$4}:{row_key:{$5}}`, where<ul><li><code>\$1</code> is the IP address. </li><li><code>\$2</code> is the port number. Together with <code>\$1</code>, they form the address of the machine where the conflict occurred. </li><li><code>\$3</code> is the log stream where the conflict occurred. </li><li><code>\$4</code> is the tablet where the conflict occurred. </li><li><code>\$5</code> is the stringified content of the row lock primary key. </li></ul>     |
| EXTRA_NAME1    | longtext            | YES  | The name of extra information that is to be added to the deadlock reporting event by the upper layer. The format is `wait_sql`  |
| EXTRA_VALUE1 | longtext | YES | SQL executed when a transaction deadlock occurs |
| EXTRA_NAME2    | longtext            | YES  | The name of an extra information field to be added to a deadlock reporting event from the parent, in the format `hold_sql_request_time`.      |
| EXTRA_VALUE2   | longtext            | YES  | Request time of the locked statement     |
| EXTRA_NAME3    | longtext            | YES  | The name of the third additional information field added to the deadlock reporting event, in the format of `hold_sql`     |
| EXTRA_VALUE3   | longtext            | YES  | The SQL statements corresponding to the Object for `cycle_idx - 1` record(s)    |

## Sample query

Queries the historical record of deadlock events in the current tenant.

```shell
obclient [oceanbase]> SELECT * FROM oceanbase.DBA_OB_DEADLOCK_EVENT_HISTORY LIMIT 10;
```
