# oceanbase.DBA_OB_TABLEGROUPS

<main id="notice" type='explain'>
<h4>Note</h4>
<p>This view is available starting with V4.0.0. </p>
</main>

## Purpose

This view displays the metadata of a table group, including the partition information.

<main id="notice" type='explain'>
<h4>Note</h4>
<p>Starting from V4.2.0, the partition attribute fields in this view will no longer have meaning and will be uniformly displayed as <code>NONE</code> or <code>NULL</code>. </p>
</main>

## Columns

|           Column            |      Type      | Nullable |      Description      |
|---------------------------|--------------|------------|--------------------------------------------------------------------------------------------------------|
| TABLEGROUP_NAME           | varchar(128) | NO         | The name of the table group.          |
| PARTITIONING_TYPE         | varchar(13)  | NO         | The partitioning type of the primary partitions of the table group. Valid values: <ul><li>`NONE`: the table group is not partitioned.   </li><li> `HASH`: HASH partitioning (single partitioning key)   </li><li> `KEY`: KEY partitioning   </li><li> `RANGE`: RANGE partitioning (single partitioning key)   </li><li> `RANGE COLUMNS`: RANGE COLUMNS partitioning   </li><li> `LIST`: LIST partitioning (single partitioning key)   </li><li> `LIST COLUMNS`: LIST COLUMNS partitioning   </li><li> `UNKNOWN`: an invalid value. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p>Starting from V4.2.0, the value of this column is <code>NULL</code>. </p></main>            |
| SUBPARTITIONING_TYPE      | varchar(13)  | NO         | The partitioning type of the subpartitions of the table group. Valid values: <ul><li> `NONE`: the table group is not partitioned, or the primary partitions are not partitioned.   </li><li> `HASH`: HASH partitioning (single partitioning key)   </li><li> `KEY`: KEY partitioning   </li><li> `RANGE`: RANGE partitioning (single partitioning key)   </li><li> `RANGE COLUMNS`: RANGE COLUMNS partitioning   </li><li> `LIST`: LIST partitioning (single partitioning key)   </li><li> `LIST COLUMNS`: LIST COLUMNS partitioning   </li><li> `UNKNOWN`: an invalid value. </li></ul><main id="notice" type='explain'><h4>Note</h4><p>Starting from V4.2.0, the value of this column is <code>NULL</code>. </p></main>     |
| PARTITION_COUNT           | bigint(20)   | NO         | The value is `NULL`.            |
| DEF_SUBPARTITION_COUNT    | bigint(0)    | NO         | The value is `NULL`. |
| PARTITIONING_KEY_COUNT    | bigint(20)   | NO         | The value is `NULL`.         |
| SUBPARTITIONING_KEY_COUNT | bigint(20)   | NO         | The value is `NULL`.       |
| SHARDING                  | varchar(20)  | NO         | The SHARDING attribute of the table group. Valid values: <ul><li>`NONE`: For a table group with this attribute, all partitions of all tables in the table group are aggregated on the same server. No restrictions are imposed on tables added to the table group. </li> <li>`PARTITION`: For a table group with this attribute, the data of each table in the table group is distributed across primary partitions. If the table is a subpartitioned table, all subpartitions under each primary partition are aggregated. </li> <li>`ADAPTIVE`: For a table group with this attribute, the data of each table in the table group is distributed based on the adaptive method. Specifically, if the table is a partitioned table, the data is distributed across primary partitions. If the table is a subpartitioned table, the data is distributed across subpartitions under each primary partition. </li></ul>  <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting from V4.2.0. </p></main> |

## Sample query

1. Create a table group named `tblgroup1`.

   ```shell
   obclient [test]> CREATE TABLEGROUP tblgroup1 SHARDING = 'PARTITION';
   ```

2. Query the SHARDING attribute of the `tblgroup1` table group.

   ```shell
   obclient [test]> SELECT TABLEGROUP_NAME, SHARDING FROM oceanbase.DBA_OB_TABLEGROUPS WHERE tablegroup_name = 'tblgroup1';
   ```

   The query result is as follows:

   ```shell
   +-----------------+-----------+
   | TABLEGROUP_NAME | SHARDING  |
   +-----------------+-----------+
   | tblgroup1       | PARTITION |
   +-----------------+-----------+
   1 row in set
   ```
