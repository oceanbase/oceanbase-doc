# information_schema.role_routine_grants

<main id="notice" type='explain'>
<h4>Note</h4>
<p>This view is available starting with V4.3.3 for V4.3x and V4.2.4 for V4.2.x. </p>
</main>

## Purpose

The `role_routine_grants` view displays information about routine privileges granted to activated roles in the current session and to other roles granted to these roles.

## Columns

| **Column**   | **Type**     | **Nullable**  | **Description**        |
|----------------|--------------|----------------------|-----------------|
| GRANTOR        | varchar(97)  | YES  | The username part of the account that granted the privilege to the role.    |
| GRANTOR_HOST   | varchar(256) | YES  | The host part of the account that granted the privilege to the role.      |
| GRANTEE        | varchar(32)  | NO   | The username part of the account corresponding to the role.      |
| GRANTEE_HOST   | varchar(255) | NO   | The host part of the account corresponding to the role.    |
| SPECIFIC_CATALOG | varchar(3) | NO   | The name of the catalog to which the routine belongs. This value is always def.   |
| SPECIFIC_SCHEMA  | varchar(64)| NO   | The name of the database to which the routine belongs.   |
| SPECIFIC_NAME    | varchar(64)| NO   | The name of the routine.         |
| ROUTINE_CATALOG  | varchar(3) | NO   | The name of the catalog to which the routine belongs. This value is always def.         |
| ROUTINE_SCHEMA   | varchar(64)| NO   | The name of the database to which the routine belongs.          |
| ROUTINE_NAME     | varchar(64)| NO   | The name of the routine.         |
| PRIVILEGE_TYPE   | varchar(90)| NO   | The privilege granted. This value can be any privilege granted at the routine level.         |
| IS_GRANTABLE     | varchar(3) | NO   | Whether the role's privileges can be granted to other users.         |

## Sample query

1. Create a role and a function.

   Create a role named `employee`:

   ```shell
   obclient [test]> CREATE ROLE employee;
   ```

   Create a function named `add_numbers`:

   ```shell
   obclient [test]> DELIMITER //
   ```

   ```shell
   obclient [test]> CREATE FUNCTION test.add_numbers(a INT, b INT)
   RETURNS INT
   BEGIN
         RETURN a + b;
   END;//
   ```

   ```shell
   obclient [test]> DELIMITER ;
   ```

2. Grant routine privileges to the role.

   ```shell
   obclient [test]> GRANT EXECUTE,ALTER ROUTINE ON test.add_numbers TO employee;
   ```

3. Grant the role to a user.

   ```shell
   obclient [test]> GRANT employee TO user1;
   ```

4. Connect to the database as user `user1`.

5. Activate the `employee` role in the current session.

   ```shell
   obclient [test]> SET ROLE employee;
   ```

6. Query the routine privileges granted to activated roles in the current session.

   ```shell
   obclient [test]> USE information_schema;
   ```

   ```shell
   obclient [information_schema]> SELECT * FROM information_schema.role_routine_grants;
   ```

   The query result is as follows:

   ```shell
   +---------+--------------+-----------+--------------+------------------+-----------------+---------------+-----------------+----------------+--------------+-----------------------+--------------+
   | GRANTOR | GRANTOR_HOST | GRANTEE   | GRANTEE_HOST | SPECIFIC_CATALOG | SPECIFIC_SCHEMA | SPECIFIC_NAME | ROUTINE_CATALOG | ROUTINE_SCHEMA | ROUTINE_NAME | PRIVILEGE_TYPE        | IS_GRANTABLE |
   +---------+--------------+-----------+--------------+------------------+-----------------+---------------+-----------------+----------------+--------------+-----------------------+--------------+
   | root    | %            | employee  | %            | def              | test            | add_numbers   | def             | test           | add_numbers  | Execute,Alter Routine | NO           |
   +---------+--------------+-----------+--------------+------------------+-----------------+---------------+-----------------+----------------+--------------+-----------------------+--------------+
   1 row in set
   ```
