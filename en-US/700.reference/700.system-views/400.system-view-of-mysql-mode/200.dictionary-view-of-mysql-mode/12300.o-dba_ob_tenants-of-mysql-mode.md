# oceanbase.DBA_OB_TENANTS

<main id="notice" type='explain'>
<h4>Note</h4>
<p>This view is available starting with V4.0.0. </p>
</main>

## Purpose

This view displays the basic information of a tenant.

* When you query this view as the system tenant, the information of all tenants is displayed, including the system tenant, user-created tenant (user tenant), and Meta tenant. You can distinguish the tenant types based on the `TENANT_TYPE` column.
* When you query this view as a user tenant, only the information of the current tenant is displayed.

## Columns

| **Column** | **Type** | **Nullable** | **Description** |
| --- | --- | --- | --- |
| TENANT_ID | bigint(20)| NO | The tenant ID. <ul><li>1: the ID of the system tenant.  </li><li>Other values: the ID of a user tenant or a Meta tenant. </li></ul>|
| TENANT_NAME| varchar(128)| NO | The name of the tenant. |
| TENANT_TYPE| varchar(4)| NO | <ul><li> `SYS`: the system tenant.  </li><li> `USER`: the user tenant. </li><li>`META`: the Meta tenant. </li></ul> |
| CREATE_TIME| timestamp(6)| YES | The creation time of the tenant.|
| MODIFY_TIME| timestamp(6)| YES | The last update time of the information.|
| PRIMARY_ZONE| varchar(128)| YES | The primary zone of the tenant.|
| LOCALITY| varchar(4096)| NO | The distribution information of the tenant replicas.|
| PREVIOUS_LOCALITY| varchar(4096)| NO | The locality information before the change. <ul><li> If this value is valid, it indicates that the locality change is not completed.  </li><li>NULL indicates that no locality change has been performed.  </li></ul> |
| COMPATIBILITY_MODE| varchar(6)| NO | <ul><li>`MYSQL`: MySQL compatibility mode. </li><li>`ORACLE`: Oracle compatibility mode. </li></ul>|
| STATUS| varchar(64)| NO | The current status of the tenant. <ul><li>   `NORMAL`: normal. </li><li>`RESTORE`: physical restore in progress.  </li><li>`CREATING`: being created. </li><li> `DROPPING`: being dropped. </li></ul>|
| IN_RECYCLEBIN| varchar(3)| NO | Indicates whether the tenant is in the recycle bin. <ul><li>  `YES`: in the recycle bin. </li><li> `NO`: not in the recycle bin. </li></ul>|
| LOCKED| varchar(3)| NO | Indicates whether the tenant is locked. <ul><li>  `YES`: locked. </li><li>`NO`: not locked.  </li></ul> The value of this column is affected by the `ALTER TENANT xxx LOCK|UNLOCK` statement. |
| TENANT_ROLE| varchar(100) | NO | The cluster role. <ul><li>`PRIMARY`: primary tenant.   </li><li>  `STANDBY`: standby tenant.  </li><li> `RESTORE`: the tenant is being restored. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.1.0. </p></main> |
| SWITCHOVER_STATUS| varchar(100)| NO | The SWITCHOVER status. <ul><li>`NORMAL`: normal.   </li><li>`PREPARE SWITCHING TO PRIMARY`: preparing for standby-to-primary switch. </li><li> `SWITCHING TO PRIMARY`: standby-to-primary switch. </li><li>`PREPARE FLASHBACK`: preparing for Flashback. </li><li> `FLASHBACK`: Flashback. </li><li>`PREPARE SWITCHING TO STANDBY`: preparing for primary-to-standby switch. </li><li> `SWITCHING TO STANDBY`: primary-to-standby switch. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.1.0. </p></main> |
| SWITCHOVER_EPOCH| bigint(20)| NO | The unique identifier of the SWITCHOVER/FAILOVER. <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.1.0. </p></main> |
| SYNC_SCN| bigint(20) unsigned| NO | The snapshot version that has been synchronized for the current tenant. This column is meaningless for the system tenant and the Meta tenant, and is displayed as NULL. <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.1.0. </p></main> |
| REPLAYABLE_SCN| bigint(20) unsigned| NO | The snapshot version that can be replayed for the current tenant. This column is meaningless for the system tenant and the Meta tenant, and is displayed as NULL. <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.1.0. </p></main> |
| READABLE_SCN| bigint(20) unsigned| NO | The snapshot version that can be read for the current tenant. This column is meaningless for the system tenant and the Meta tenant, and is displayed as NULL. <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.1.0. </p></main> |
| RECOVERY_UNTIL_SCN| bigint(20) unsigned| NO | The maximum recovery point for the current tenant. This column is meaningless for the system tenant and the Meta tenant, and is displayed as NULL. <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.1.0. </p></main> |
| LOG_MODE| varchar(100)| NO | The archive mode. <ul><li>  `ARCHIVELOG`: archive mode enabled. </li><li> `NOARCHIVELOG`: archive mode not enabled. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.1.0. </p></main> |
| ARBITRATION_SERVICE_STATUS |  varchar(64)   | NO | The arbitration service status of the tenant. Valid values: <ul><li>`ENABLING`: enabling.   </li><li> `ENABLED`: enabled. </li><li> `DISABLING`: disabling. </li><li>`DISABLED`: disabled. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.1.0. </p></main> |
| UNIT_NUM | bigint(20) | NO | The minimum value of the `UNIT_NUM` of all zones of the tenant. <main id="notice" type='explain'><h4>Note</h4><ul><li>This column was introduced in V4.2.0. </li> <li>For V4.6.x, this column was introduced in V4.6.0. The column value changed from the `UNIT_NUM` of all zones of the tenant to the minimum value of the `UNIT_NUM` of all zones of the tenant. </li> <li>For V4.4.x, this column was introduced in V4.4.2. The column value changed from the `UNIT_NUM` of all zones of the tenant to the minimum value of the `UNIT_NUM` of all zones of the tenant. </li> <li>In V4.2.5, this column indicates the `UNIT_NUM` of all zones of the tenant in versions earlier than V4.2.5 BP5, and the minimum value of the `UNIT_NUM` of all zones of the tenant in V4.2.5 BP5 and later. </li></ul></main> |
| ZONE_UNIT_NUM_LIST | varchar(65536) | NO | The number of units in each zone of the tenant. <main id="notice" type='explain'><h4>Note</h4><ul><li>For V4.6.x, this column was introduced in V4.6.0. </li> <li>For V4.4.x, this column was introduced in V4.4.2. </li> <li>For V4.2.5, this column was introduced in V4.2.5 BP5. </li></ul></main> |
| COMPATIBLE | varchar(65536) | NO | The compatibility version. <main id="notice" type='explain'><h4>Note</h4><p>This column was introduced in V4.2.0. </p></main> |
| MAX_LS_ID  | bigint(20)     | NO | The largest log stream ID that ever existed for the tenant. The value is 1 for the system tenant and the meta tenant, and the actual value for user tenants. <main id="notice" type='explain'><h4>Note</h4><p>This column was introduced in V4.2.0. </p></main> |
| RESTORE_DATA_MODE  | varchar(128)     | NO | The data restore mode of the tenant. Valid values: <ul><li>`NORMAL`: indicates that the tenant was created normally or restored from full data. </li><li>`REMOTE`: indicates that the tenant was restored quickly, and the data is in a remote reference state. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column was introduced in V4.3.2. </p></main> |
| FLASHBACK_LOG_SCN | bigint(20) | NO | The latest log stream ID that was trimmed for the tenant. After a failover, you can use the standby tenant to trim logs to a specified point in time and then add the standby tenant to the new primary tenant. <main id="notice" type='explain'><h4>Note</h4><p>This column was introduced in V4.4.1. </p></main> |
| COMMENT                    | varchar(4096)       | NO   | The comment.     |
| PROTECTION_MODE            | varchar(128)        | NO   | The protection mode of the current tenant. Only `MAXIMUM PERFORMANCE` (maximum performance) is supported. <main id="notice" type='explain'><h4>Note</h4><p>This column was introduced in V4.6.0. </p></main> |
| PROTECTION_LEVEL           | varchar(128)        | NO   | The protection level of the current tenant. Only `MAXIMUM PERFORMANCE` (maximum performance) is supported. <main id="notice" type='explain'><h4>Note</h4><p>This column was introduced in V4.6.0. </p></main>  |
