# V$OB_PROCESSLIST

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This view is available starting with V4.0.0. </p>
</main>

## Purpose

The `V$OB_PROCESSLIST` view displays session information on the current OBServer node.

## Columns

|      Column      |         Type          | Nullable |                              Description                              |
|----------------|---------------------|------------|--------------------------------------------------------------|
| SVR_IP         | varchar(46)         | NO         | The IP address of the server.                                                    |
| SVR_PORT       | bigint(20)          | NO         | The port number of the server.                                                       |
| SQL_PORT       | bigint(20)          | NO         | The port number of SQL.                                                      |
| ID             | bigint(20) unsigned | NO         | The session ID.                                                        |
| USER           | varchar(32)         | NO         | The username.                                                          |

| TOTAL_TIME     | bigint(20)          | NO         | The total time taken for the command to be executed. <ul><li>If the command is received and not yet returned to the client, this value represents the time elapsed from when the command was received to the current time.  </li><li>If the command is not received, this value represents the duration of the current state. </li></ul> The unit is seconds. <main id="notice" type='explain'><h4>Note</h4><p> In versions earlier than V4.2.5, this field indicates the total execution time of the command, which is not reset when the command is retried. </p></main>                                 |

| TRANS_STATE    | varchar(32)         | NO         |  The transaction state. Valid values: <ul><li>`IDLE`: The transaction is idle. This indicates that the transaction has not been started. </li> <li>`ACTIVE`: The transaction is explicitly started by using the `START TRANSACTION` or `BEGIN` statement. </li> <li>`IMPLICIT_ACTIVE`: The transaction is implicitly started. In `autocommit = on` mode, the transaction is started after a DML statement is executed. </li> <li>`ROLLBACK_SAVEPOINT`: The transaction is being rolled back to a savepoint. </li> <li>`IN_TERMINATE`: The transaction is being terminated. This can be caused by internal reasons or by user-initiated termination (for example, by executing the `COMMIT` or `ROLLBACK` statement). </li> <li>`ABORTED`: The transaction is internally terminated or rolled back due to an exception. </li> <li>`ROLLED_BACK`: The transaction has been rolled back. </li> <li>`COMMIT_TIMEOUT`: The transaction commit times out. </li> <li>`COMMIT_UNKNOWN`: The transaction commit result is unknown. </li> <li>`COMMITTED`: The transaction has been successfully committed. </li></ul>                                                          |
| ACTION         | varchar(4096)       | NO         | The name of the current operation, which is set by calling the DBMS_APPLICATION_INFO.SET_ACTION procedure. |
| MODULE         | varchar(4096)       | NO         | The name of the current operation, which is set by calling the DBMS_APPLICATION_INFO.SET_MODULE procedure. |
| CLIENT_INFO    | varchar(4096)       | NO         | The information set by calling the DBMS_APPLICATION_INFO.SET_CLIENT_INFO procedure.              |
| LEVEL | bigint(20) | NO | The end-to-end tracing monitoring level of the session. For example, 1 indicates the diagnostic information of level 1. <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.1. </p></main> |
| SAMPLE_PERCENTAGE | bigint(20) | NO | The end-to-end tracing sampling frequency of the session.  For example, 50 indicates that diagnostic information is sampled with a 50% probability. <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.1. </p></main> |
| RECORD_POLICY | varchar(32) | NO | The end-to-end tracing recording policy of the session. The following three policies are supported: <ul><li>ALL: All trace points of traces that are sampled and enabled are printed to the log file. In this policy, trace information is printed to the log file at the end of each span. </li><li>ONLY_SLOW_QUERY: Trace points of traces that are sampled and enabled and belong to slow queries are printed to the log file. Other trace points are discarded. In this policy, trace information is printed to the log file only after the request is determined to be a slow query. In a Proxy environment, the root span, which is at the transaction level, is printed only when a slow query is detected. </li><li>SAMPLE_AND_SLOW_QUERY: Trace points of traces that are sampled and enabled are printed to the log file if the following conditions are met: <ol><li>When the hidden parameter <code>_print_sample_ppm</code> is used for sampling at a 0.01% probability, the trace information is printed to the log file only if the sampling result is selected. </li><li>The trace information meets the conditions for printing in the ONLY_SLOW_QUERY mode. </li></ol> In this policy, trace information is not printed at the end of a span. If condition 1 is met, the trace information is marked for forced printing at the client and is passed to subsequent components in the chain. If condition 2 is met, the trace information is printed at the same time as in the ONLY_SLOW_QUERY mode. </li></ul><main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.1. </p></main> |
| LB_VID | bigint(20) | NO   | If the database is directly connected to a load balancer in a public cloud environment, this column displays the VPC ID of the load balancer. | LB_VIP | varchar(46) | NO  | If the database is directly connected to a load balancer in a public cloud environment, this column displays the IP address of the load balancer. Otherwise, it displays NULL. <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.1. </p></main> |

| IN_BYTES | bigint(20) | NO | The inflow traffic of the session, in bytes.  <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.1. </p></main> |
| OUT_BYTES | bigint(20) | NO | The outflow traffic of the session, in bytes.  <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.1. </p></main> |

| PROXY_USER        | varchar(128)        | NO   |<ul><li> If the user logs in through a proxy, the name of the proxy user is returned. </li><li> If the user does not log in through a proxy, this column is empty. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.3. </p></main> |
| SERVICE_NAME      | varchar(64)         | NO   |  The service name that created the session. If the value is `NULL`, the session is not created by a service name. <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.4. </p></main> |
| TOTAL_CPU_TIME    | bigint(21)          | NO   | The CPU time used by the current command, in seconds. <main id="notice" type='explain'><h4>Note</h4><ul><li>This column was introduced in V4.3.1. </li> <li>This column was introduced in V4.2.1 BP5 for V4.2.1 and in V4.2.5 for other V4.2.x versions. </li></ul></main>      |

| MEMORY_USAGE      | bigint(20)          | NO   | The memory size used by the current SQL statement, in bytes. <main id="notice" type='explain'><h4>Note</h4><p>This column was introduced in V4.2.5 BP2. </p></main>|

```shell
obclient [oceanbase]> SELECT * FROM oceanbase.V$OB_PROCESSLIST LIMIT 1\G
```
