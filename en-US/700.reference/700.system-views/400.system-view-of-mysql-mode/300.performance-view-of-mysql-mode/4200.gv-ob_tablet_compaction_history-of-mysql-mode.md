# GV$OB_TABLET_COMPACTION_HISTORY

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This view is introduced since OceanBase Database V4.0.0. </p>
</main>

## Purpose

The `GV$OB_TABLET_COMPACTION_HISTORY` view displays the historical information about tablet-level compactions.

## Columns

| Column |  Type  | Nullable? | Description |
|-----------|-----------|----------|-------------|
| SVR_IP    | varchar(46) | NO   | The IP address of the server. |
| SVR_PORT  | bigint(20)  | NO   | The port of the server. |
| TENANT_ID | bigint(20)  | NO   | The ID of the tenant. |
| LS_ID     | bigint(20)  | NO   | The ID of the log stream. |
| TABLET_ID | bigint(20)  | NO   | The ID of the data shard. |
| TYPE      | varchar(64) | NO   | The type of compaction. Valid values include:<ul><li>`MDS_TABLE_MERGE`: persists the system metadata in the SSTable format to the disk. </li> <li>`MAJOR_MERGE`: major compaction at the tenant level. </li> <li>`MEDIUM_MERGE`: major compaction at the partition level. </li> <li>`MINI_MERGE`: minor compaction, which converts a MemTable into an SSTable. </li> <li>`MINOR_MERGE`: minor compaction, which merges multiple SSTables or merges multiple mini SSTables with a minor SSTable into one minor SSTable. </li> <li>`META_MAJOR_MERGE`: a special type of compaction that merges data before a specified time point into one meta major SSTable. The data format of the meta major SSTable is the same as that of a major SSTable, but it does not contain multi-version data or uncommitted transaction data. </li></ul>   |
| COMPACTION_SCN | bigint(20) unsigned | NO   | The version information of the compaction. |
| START_TIME | timestamp(6) | NO   | The start time. |
| FINISH_TIME | timestamp(6) | NO   | The end time. |
| TASK_ID   | varchar(64) | NO   | The trace ID of the task. |
| OCCUPY_SIZE | bigint(20) | NO   | The data volume. |
| MACRO_BLOCK_COUNT | bigint(20) | NO   | The number of macro blocks. |
| MULTIPLEXED_MACRO_BLOCK_COUNT | bigint(20) | NO   | The number of reused macro blocks. |
| NEW_MICRO_COUNT_IN_NEW_MACRO | bigint(20) | NO   | The number of new micro blocks in a new macro block. |
| MULTIPLEXED_MICRO_COUNT_IN_NEW_MACRO | bigint(20) | NO   | The number of reused micro blocks in a new macro block. |
| TOTAL_ROW_COUNT | bigint(20) | NO   | The total number of rows. |
| INCREMENTAL_ROW_COUNT | bigint(20) | NO   | The number of new rows. |
| COMPRESSION_RATIO | double | NO   | The compression ratio of the new data = the volume of compressed macro block data / the volume of uncompressed macro block data. |
| NEW_FLUSH_DATA_RATE | bigint(20) | NO   | The output speed of the new data, in KB/s. |
| PROGRESSIVE_COMPACTION_ROUND | bigint(20) | NO   | The current round of progressive compaction (if the compaction is full compaction, this column is -1). |
| PROGRESSIVE_COMPACTION_NUM | bigint(20) | NO   | The total number of rounds of progressive compaction. |
| PARALLEL_DEGREE | bigint(20) | NO   | The degree of parallelism. |
| PARALLEL_INFO | varchar(512) | NO   | Information about the parallel task, including the minimum, maximum, and average values of the data scanned, runtime, and data output by the parallel task. |
| PARTICIPANT_TABLE | varchar(512) | NO   | Information about the table that participates in the compaction. |
| MACRO_ID_LIST | varchar(256) | NO   | The list of macro blocks. If the macro block list is too long, it is not displayed. |
| COMMENTS | varchar(1024) | NO   | Remarks. This parameter displays the issues encountered during scheduling or execution. |
| START_CG_ID | bigint(20) | NO   | The start ID of the column group. <main id="notice" type="explain"><h4>Note</h4><p>This parameter was introduced in V4.3.0. </p></main>    |
| END_CG_ID | bigint(20) | NO   | The end ID of the column group. <main id="notice" type="explain"><h4>Note</h4><p>This parameter was introduced in V4.3.0. </p></main>   |
| KEPT_SNAPSHOT | varchar(128) | NO   | The multi-version snapshot retained during this compaction. <main id="notice" type="explain"><h4>Note</h4><p>This parameter was introduced in V4.3.0. </p></main>    |
| MERGE_LEVEL | varchar(64)  | NO   | Whether major compaction or microblock reuse is used during this compaction. <main id="notice" type="explain"><h4>Note</h4><p>This parameter was introduced in V4.3.0. </p></main>    |
| EXEC_MODE | varchar(64)  | NO   | The mode of this compaction trace. Valid values include:<ul><li>`EXEC_MODE_LOCAL`: local mode, which outputs macro blocks to the local disk. </li> <li>`EXEC_MODE_VALIDATE`: shared mode, which only calculates the checksum and does not output macro blocks. This mode is not supported in the current version. </li> <li>`EXEC_MODE_OUTPUT`: shared mode, which outputs macro blocks to the shared storage. This mode is not supported in the current version. </li></ul> <main id="notice" type="explain"><h4>Note</h4><p>This parameter was introduced in V4.3.3. </p></main> |
| IS_FULL_MERGE | varchar(5)   | NO   | Whether this is a full major compaction. <main id="notice" type="explain"><h4>Note</h4><p>This parameter was introduced in V4.3.3. </p></main> |
| IO_COST_TIME_PERCENTAGE | bigint(20)   | NO   | The percentage of the I/O time in the compaction time. <main id="notice" type="explain"><h4>Note</h4><p>This parameter was introduced in V4.3.3. </p></main> |
| MERGE_REASON | varchar(32)  | NO   | The reason for initiating the major compaction. Valid values include:<ul><li>`LOAD_DATA_SCENE`: data loading scenario. </li> <li>`TOMBSTONE_SCENE`: tombstone scenario. </li> <li>`INEFFICIENT_QUERY`: slow query scenario. </li> <li>`FREQUENT_WRITE`: frequent write scenario. </li> <li>`TENANT_MAJOR`: major compaction at the tenant level. </li> <li>`USER_REQUEST`: user-initiated major compaction. </li> <li>`REBUILD_COLUMN_GROUP`: row-to-column scenario. </li></ul> <main id="notice" type="explain"><h4>Note</h4><p>This parameter was introduced in V4.3.3. </p></main> |
| BASE_MAJOR_STATUS | varchar(64)  | NO   | The type of the baseline major SSTable:<ul><li>`COL_WITH_ALL`: the baseline data is stored in a hybrid row-column table. </li> <li>`COL_ONLY_ALL`: the baseline data is stored in a hybrid row-column table, and the adaptive optimization only stores row data. </li> <li>`PURE_COL`: the baseline data is stored in a columnstore table. </li> <li>`PURE_COL_ONLY_ALL`: the baseline data is stored in a hybrid row-column table, and the adaptive optimization only stores row data. </li> <li>`ROW_STORE_MAJOR`: rowstore table. </li></ul> <main id="notice" type="explain"><h4>Note</h4><p>This parameter was introduced in V4.3.3. </p></main>|
| CO_MERGE_TYPE | varchar(64)  | NO   | The columnstore major compaction type:<ul><li>`BUILD_COLUMN_STORE_MERGE`: columnstore major compaction. </li> <li>`BUILD_ROW_STORE_MERGE`: rowstore major compaction. </li> <li>`USE_RS_BUILD_SCHEMA_MATCH_MERGE`: major compaction of the storage type that matches the schema. </li></ul> <main id="notice" type="explain"><h4>Note</h4><p>This parameter was introduced in V4.3.3. </p></main> |

## Sample query

```shell
obclient [oceanbase]> SELECT * FROM oceanbase.GV$OB_TABLET_COMPACTION_HISTORY LIMIT 1\G
```
