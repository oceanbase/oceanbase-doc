# GV$OB_TABLET_COMPACTION_HISTORY

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This view is available starting with V4.0.0. </p>
</main>

## Purpose

The `GV$OB_TABLET_COMPACTION_HISTORY` view displays the history of tablet-level major compactions.

## Columns

| Column | Type | Nullable | Description |
|--------------|--------------|----------------|--------|
|SVR_IP            |varchar(46)   |NO   |The IP address of the server.    |
|SVR_PORT          |bigint(20)    |NO   |The port number of the server.    |
|TENANT_ID         |bigint(20)    |NO   |The tenant ID.    |
|LS_ID             |bigint(20)    |NO   |The log stream ID.    |
|TABLET_ID         |bigint(20)    |NO   |The tablet ID.    |
|TYPE              |varchar(64)   |NO   | The type of compaction. Valid values: <ul><li>`MDS_TABLE_MERGE`: persist the system metadata in the SSTable format to disk. </li> <li>`MAJOR_MERGE`: tenant-level compaction. </li> <li>`MEDIUM_MERGE`: partition-level compaction. </li> <li>`MINI_MERGE`: Mini Compaction. Converts a MemTable to a Mini SSTable. </li> <li>`MINOR_MERGE`: Minor Compaction. Merges multiple Mini SSTables into a new Mini SSTable or merges multiple Mini SSTables with one Minor SSTable into a new Minor SSTable. </li> <li>`META_MAJOR_MERGE`: a special type of compaction. Merges data before a specified time point into a Meta Major SSTable. The data format of the Meta Major SSTable is the same as that of a Major SSTable. It does not contain multi-version data and uncommitted transaction data. </li></ul>   |
|COMPACTION_SCN    |bigint(20) unsigned    |NO   |The compaction version.    |
|START_TIME        |timestamp(6)  |NO   |The start time.    |
|FINISH_TIME       |timestamp(6)  |NO   |The end time.    |
|TASK_ID           |varchar(64)   |NO   |The trace ID of the task.    |
|OCCUPY_SIZE       |bigint(20)    |NO   |The size of the data.    |
|MACRO_BLOCK_COUNT                |bigint(20)    |NO   |The number of macroblocks.    |
|MULTIPLEXED_MACRO_BLOCK_COUNT    |bigint(20)    |NO   |The number of reused macroblocks.    |
|NEW_MICRO_COUNT_IN_NEW_MACRO     |bigint(20)    |NO   |The number of new microblocks in new macroblocks.    |
|MULTIPLEXED_MICRO_COUNT_IN_NEW_MACRO    |bigint(20)   |NO   |The number of reused microblocks in new macroblocks.    |
|TOTAL_ROW_COUNT                  |bigint(20)    |NO   |The total number of rows.    |
|INCREMENTAL_ROW_COUNT            |bigint(20)    |NO   |The number of new rows.    |
|COMPRESSION_RATIO                |double        |NO   |The compression ratio of new data. The compression ratio is the ratio of the size of compressed data to that of the original data in new macroblocks.    |
|NEW_FLUSH_DATA_RATE              |bigint(20)    |NO   |The output speed of new data, in KB/s.    |
|PROGRESSIVE_COMPACTION_ROUND     |bigint(20)    |NO   |The current round of progressive compaction. If the compaction is a full compaction, this column is -1.    |
|PROGRESSIVE_COMPACTION_NUM       |bigint(20)    |NO   |The total number of rounds of progressive compaction.    |
|PARALLEL_DEGREE                  |bigint(20)    |NO   |The parallelism.    |
|PARALLEL_INFO                    |varchar(512)  |NO   |The information about parallel tasks. It displays the statistics of the amount of data scanned, the running time, and the amount of data output by parallel tasks (minimum, maximum, and average).    |
|PARTICIPANT_TABLE                |varchar(512)  |NO   |The information about the tables involved in the current compaction.    |
|MACRO_ID_LIST                    |varchar(256)  |NO   |The list of output macroblocks. If the list is too long, it will not be displayed.    |
|COMMENTS                         |varchar(1024) |NO   |The remarks. It displays the problems encountered during the previous scheduling or execution.    |
| START_CG_ID                     | bigint(20)   | NO   |  The start ID of the column group<main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.0. </p></main>    |
| END_CG_ID                       | bigint(20)   | NO   |  The end ID of the column group <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.0. </p></main>   |
| KEPT_SNAPSHOT                   | varchar(128) | NO   |  The information about the multi-version snapshot retained by the current compaction<main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.0. </p></main>    |
| MERGE_LEVEL                     | varchar(64)  | NO   |  The information about whether the merge or microblock reuse is used during the current execution<main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.0. </p></main>    |
| EXEC_MODE                       | varchar(64)  | NO   | The mode of the compaction trace. Valid values: <ul><li>`EXEC_MODE_LOCAL`: local mode. Outputs macroblocks to the local disk. </li> <li>`EXEC_MODE_VALIDATE`: shared mode. Calculates the checksum but does not output macroblocks. This mode is not supported in the current version. </li> <li>`EXEC_MODE_OUTPUT`: shared mode. Outputs macroblocks to shared storage. This mode is not supported in the current version. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main> |
| IS_FULL_MERGE                   | varchar(5)   | NO   | Indicates whether the compaction is a full compaction.<main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main> |
| IO_COST_TIME_PERCENTAGE         | bigint(20)   | NO   | The percentage of the I/O time in the major compaction time. <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main> |
| MERGE_REASON                    | varchar(32)  | NO   | The reason for initiating the major compaction. Valid values: <ul><li>`LOAD_DATA_SCENE`: data loading scenario</li> <li>`TOMBSTONE_SCENE`: tombstone scenario</li> <li>`INEFFICIENT_QUERY`: slow query scenario</li> <li>`FREQUENT_WRITE`: frequent write scenario</li> <li>`TENANT_MAJOR`: tenant-level major compaction</li> <li>`WINDOW_COMPACTION`: window compaction</li> <li>`USER_REQUEST`: user-initiated major compaction</li> <li>`REBUILD_COLUMN_GROUP`: row-to-column conversion scenario</li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main> |
| BASE_MAJOR_STATUS               | varchar(64)  | NO   | The type of the major SSTable before the major compaction: <ul><li>`COL_WITH_ALL`: a hybrid row-column store table is defined, and the baseline data is stored in a hybrid row-column store format</li> <li>`COL_ONLY_ALL`: a hybrid row-column store table is defined, and the baseline data is stored in a row store format</li> <li>`PURE_COL`: a pure column store table is defined, and the baseline data is stored in a column store format</li> <li>`PURE_COL_ONLY_ALL`: a pure column store table is defined, and the baseline data is stored in a row store format</li> <li>`ROW_STORE_MAJOR`: a row store table</li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main>|
| CO_MERGE_TYPE                   | varchar(64)  | NO   | The type of the column store compaction: <ul><li>`BUILD_COLUMN_STORE_MERGE`: major compaction to a column store</li> <li>`BUILD_ROW_STORE_MERGE`: major compaction to a row store</li> <li>`USE_RS_BUILD_SCHEMA_MATCH_MERGE`: major compaction to a storage type that matches the schema</li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main> |
| MDS_FILTER_INFO                 | varchar(1024) | NO  | The MDS filter information used for the major compaction. <main id="notice" type='explain'><h4>Note</h4><ul><li>This column is available starting with V4.4.0 for V4.4.x. </li><li>This column is available starting with V4.3.5 and becomes effective starting with V4.3.5 BP2. </li></ul></main> |
| EXECUTE_TIME                    | bigint(20)    | NO | The CPU time consumed by the major compaction task, in microseconds.  |
| FILTER_ROW_COUNT                | bigint(20)    | NO | The number of rows that are recycled by using the major compaction. <main id="notice" type='explain'><h4>Note</h4><ul><p>This column is available starting with V4.6.0. </p></main>  |

## Sample query

Query the tablet-level compaction history information on all OBServer nodes in the user tenant.

```shell
obclient(root@mysql001)[oceanbase]> SELECT * FROM oceanbase.GV$OB_TABLET_COMPACTION_HISTORY LIMIT 1\G
```
