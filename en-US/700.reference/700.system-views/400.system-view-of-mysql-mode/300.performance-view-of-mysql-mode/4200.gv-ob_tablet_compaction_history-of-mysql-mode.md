# GV$OB_TABLET_COMPACTION_HISTORY

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This view is available starting with V4.0.0. </p>
</main>

## Purpose

The `GV$OB_TABLET_COMPACTION_HISTORY` view displays the history of tablet-level compactions.

## Columns

| Column | Type | Nullable | Description |
|--------------|--------------|----------------|--------|
|SVR_IP            |varchar(46)   |NO   |Server IP address    |
|SVR_PORT          |bigint(20)    |NO   |Server port number    |
|TENANT_ID         |bigint(20)    |NO   |Tenant ID    |
|LS_ID             |bigint(20)    |NO   |Log stream ID    |
|TABLET_ID         |bigint(20)    |NO   |Data tablet ID    |
|TYPE              |varchar(64)   |NO   |Compaction type. Valid values: <ul><li>`MDS_TABLE_MERGE`: persist system metadata in SSTable format to disk. </li> <li>`MAJOR_MERGE`: major compaction at the tenant level. </li> <li>`MEDIUM_MERGE`: major compaction at the partition level. </li> <li>`MINI_MERGE`: minor compaction. Convert MemTable to Mini SSTable. </li> <li>`MINOR_MERGE`: minor compaction. Combine multiple Mini SSTables into a new Mini SSTable, or combine multiple Mini SSTables with one Minor SSTable into a new Minor SSTable. </li> <li>`META_MAJOR_MERGE`: major compaction. Combine data before a specified time point into a Meta Major SSTable. The data format is the same as that of a Major SSTable, which does not contain multi-version data and uncommitted transaction data. </li></ul>   |
|COMPACTION_SCN    |bigint(20) unsigned    |NO   |Compaction version information    |
|START_TIME        |timestamp(6)  |NO   |Start time    |
|FINISH_TIME       |timestamp(6)  |NO   |End time    |
|TASK_ID           |varchar(64)   |NO   |Task execution trace    |
|OCCUPY_SIZE       |bigint(20)    |NO   |Data volume    |
|MACRO_BLOCK_COUNT                |bigint(20)    |NO   |Number of macroblocks    |
|MULTIPLEXED_MACRO_BLOCK_COUNT    |bigint(20)    |NO   |Number of reused macroblocks    |
|NEW_MICRO_COUNT_IN_NEW_MACRO     |bigint(20)    |NO   |Number of new microblocks in new macroblocks    |
|MULTIPLEXED_MICRO_COUNT_IN_NEW_MACRO    |bigint(20)   |NO   |Number of reused microblocks in new macroblocks    |
|TOTAL_ROW_COUNT                  |bigint(20)    |NO   |Total number of rows    |
|INCREMENTAL_ROW_COUNT            |bigint(20)    |NO   |Number of new rows    |
|COMPRESSION_RATIO                |double        |NO   |Compression ratio of new data = (Compressed size of new macroblocks / Uncompressed size of new macroblocks)    |
|NEW_FLUSH_DATA_RATE              |bigint(20)    |NO   |Output speed of new data, in KB/s    |
|PROGRESSIVE_COMPACTION_ROUND     |bigint(20)    |NO   |Number of the current round of progressive compaction (if the compaction is a full compaction, this column is -1)    |
|PROGRESSIVE_COMPACTION_NUM       |bigint(20)    |NO   |Total number of rounds of progressive compaction    |
|PARALLEL_DEGREE                  |bigint(20)    |NO   |Parallelism    |
|PARALLEL_INFO                    |varchar(512)  |NO   |Parallel task information. It displays the statistics of the data scanned, running time, and output data of parallel tasks (min, max, and average).    |
|PARTICIPANT_TABLE                |varchar(512)  |NO   |Table information involved in the current compaction    |
|MACRO_ID_LIST                    |varchar(256)  |NO   |List of output macroblocks. If the list is too long, it will not be displayed.    |
|COMMENTS                         |varchar(1024) |NO   |Remarks. It displays the issues encountered during scheduling or execution.    |
| START_CG_ID                     | bigint(20)   | NO   |  Column Group Start ID<main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.0. </p></main>    |
| END_CG_ID                       | bigint(20)   | NO   |  Column Group End ID <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.0. </p></main>   |
| KEPT_SNAPSHOT                   | varchar(128) | NO   |  Multi-version snapshot information retained by the current compaction<main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.0. </p></main>    |
| MERGE_LEVEL                     | varchar(64)  | NO   |  Whether major compaction or microblock reuse was used during the current execution<main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.0. </p></main>    |
| EXEC_MODE                       | varchar(64)  | NO   | Execution mode of the current compaction trace. Valid values: <ul><li>`EXEC_MODE_LOCAL`: local mode. Output macroblocks to the local disk. </li> <li>`EXEC_MODE_VALIDATE`: shared mode. Calculate checksum only without outputting macroblocks. This mode is not supported in the current version. </li> <li>`EXEC_MODE_OUTPUT`: shared mode. Output macroblocks to shared storage. This mode is not supported in the current version. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main> |
| IS_FULL_MERGE                   | varchar(5)   | NO   | Indicates whether the current compaction is a full compaction.<main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main> |
| IO_COST_TIME_PERCENTAGE         | bigint(20)   | NO   | The percentage of I/O time in the major compaction time. <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main> |
| MERGE_REASON                    | varchar(32)  | NO   | The reason for the major compaction. Valid values: <ul><li>`LOAD_DATA_SCENE`: data loading scenario</li> <li>`TOMBSTONE_SCENE`: tombstone scenario</li> <li>`INEFFICIENT_QUERY`: slow query scenario</li> <li>`FREQUENT_WRITE`: frequent write scenario</li> <li>`TENANT_MAJOR`: tenant-level major compaction</li> <li>`WINDOW_COMPACTION`: window compaction</li> <li>`USER_REQUEST`: user-initiated major compaction</li> <li>`REBUILD_COLUMN_GROUP`: row-to-column scenario</li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main> |
| BASE_MAJOR_STATUS               | varchar(64)  | NO   | The type of the base major SSTable before the major compaction: <ul><li>`COL_WITH_ALL`: the table is a hybrid row-column store table, and the baseline data is stored in a hybrid row-column store format</li> <li>`COL_ONLY_ALL`: the table is a hybrid row-column store table, and the baseline data is stored in a row store format</li> <li>`PURE_COL`: the table is a pure column store table, and the baseline data is stored in a column store format</li> <li>`PURE_COL_ONLY_ALL`: the table is a pure column store table, and the baseline data is stored in a row store format</li> <li>`ROW_STORE_MAJOR`: row store table</li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main>|
| CO_MERGE_TYPE                   | varchar(64)  | NO   | The type of the column store major compaction: <ul><li>`BUILD_COLUMN_STORE_MERGE`: major compaction to column store</li> <li>`BUILD_ROW_STORE_MERGE`: major compaction to row store</li> <li>`USE_RS_BUILD_SCHEMA_MATCH_MERGE`: major compaction to a storage type that matches the schema</li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main> |
| MDS_FILTER_INFO                 | varchar(1024) | NO  | The MDS filter information used for the major compaction. <main id="notice" type='explain'><h4>Note</h4><ul><li>For V4.4.x, this column is available starting with V4.4.0. </li><li>For V4.3.5, this column is available starting with V4.3.5 BP2. </li></ul></main> |
| EXECUTE_TIME                    | bigint(20)    | NO | The CPU time consumed by the major compaction task, in microseconds.  |
| FILTER_ROW_COUNT                | bigint(20)    | NO | The number of rows recovered by the major compaction. <main id="notice" type='explain'><h4>Note</h4><ul><p>This column is available starting with V4.6.0. </p></main>  |

## Sample query

Query the tablet-level compaction history information on all OBServer nodes in the user tenant.

```shell
obclient(root@mysql001)[oceanbase]> SELECT * FROM oceanbase.GV$OB_TABLET_COMPACTION_HISTORY LIMIT 1\G
```
