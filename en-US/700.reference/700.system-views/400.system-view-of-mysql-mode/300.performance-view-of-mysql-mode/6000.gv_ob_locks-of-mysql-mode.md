# GV$OB_LOCKS

## Purpose

Displays the locks held or requested by the current user.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This view was introduced in V4.2.0. </p>
</main>

## Columns

| **Column** | **Type** | **Nullable?** | **Description** |
| --- | --- | --- | --- |
| SVR_IP | varchar(46) | NO | The IP address of the OBServer node that holds or requests a lock. |
| SVR_PORT | bigint(20) | NO | The port number of the OBServer node that holds or requests a lock. |
| TENANT_ID | bigint(20) | NO | The ID of the tenant that holds or requests a lock. |
| TRANS_ID | bigint(20) | NO | The ID of the transaction that holds or requests a lock. |
| TYPE | varchar(9) | NO | The type of lock:<ul><li>TM: table lock</li><li>TX: transaction lock</li><li>TR: row lock</li></ul> |
| ID1 | bigint(20) | NO | The first lock identifier:<ul><li>For table locks, it can be either TABLE_ID or TABLET_ID. </li><li>For transaction locks, it is TX_ID. </li><li>For row locks, it is TABLET_ID. </li></ul> |
| ID2 | varchar(533) | NO | The second lock identifier:<ul><li>For table locks, it is NULL. </li><li>For transaction locks, it is NULL. </li><li>For row locks, it is TX_ID + row key. </li></ul> |
| LMODE | varchar(4) | NO | The mode of the lock held by the transaction:<ul><li>NONE: indicates that the transaction holds no lock. </li><li>RS: indicates that the transaction holds a row share lock. </li><li>RX: indicates that the transaction holds a row exclusive lock. </li><li>S: indicates that the transaction holds a share lock. </li><li>SRX: indicates that the transaction holds a share row exclusive lock. </li><li>X: indicates that the transaction holds an exclusive lock. </li></ul> |
| REQUEST | varchar(8) | NO | The mode of the lock requested by the transaction:<ul><li>NONE: indicates that the transaction requests no lock. </li><li>RS: indicates that the transaction requests a row share lock. </li><li>RX: indicates that the transaction requests a row exclusive lock. </li><li>S: indicates that the transaction requests a share lock. </li><li>SRX: indicates that the transaction requests a share row exclusive lock. </li><li>X: indicates that the transaction requests an exclusive lock. </li></ul>|
| CTIME | bigint(20) | NO | The duration of the lock hold or wait, in microseconds. |
| BLOCK | bigint(1) | NO | Indicates whether the lock requested by the transaction is held by another transaction:<ul><li>0: indicates that the lock requested by the transaction is not held by another transaction, that is, the transaction holds the lock. </li><li>1: indicates that the lock requested by the transaction is held by another transaction, that is, the transaction is blocked. </li></ul>|
