# V$OB_LOCKS

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This view is available starting with V4.2.0. </p>
</main>

## Purpose

This view displays the lock information of tables for the current user.

## Columns

| **Column** | **Type** | **Nullable** | **Description** |
| ---- | ---- | ---- | ---- |
| SVR_IP | varchar(46) | NO | The IP address of the OBServer node that holds or requests a lock. |
| SVR_PORT | bigint(20) | NO | The port number of the OBServer node that holds or requests a lock. |
| TENANT_ID | bigint(20) | NO | The ID of the tenant that holds or requests a lock. |
| TRANS_ID | bigint(20) | NO | The ID of the transaction that holds or requests a lock. |
| SESSION_ID | bigint(20)   | NO   | The ID of the session that holds or requests a lock<ul><li>Starting from V4.3.2 in V4.3.x: <ul><li>Before V4.3.5 BP2: <br> In all connection modes (direct mode/ODP mode), this field indicates the Server Session ID. </li><li>From V4.3.5 BP2 onwards: <ul><li> In direct mode: <br> This field indicates the Server Session ID. </li> <li> In ODP mode: </li><ul><li> If the <code>client_session_id_version = 2</code> parameter is set in ODP, this field indicates the Client Session ID. </li> <li> If <code>client_session_id_version = 1</code>, this field indicates the Server Session ID. </li></ul></ul></li></ul> </li><li>Starting from V4.2.5 in V4.2.x: In all connection modes (direct mode/ODP mode), this field indicates the Server Session ID. </li></ul> |
| TYPE | varchar(9) | NO | The lock type: <ul><li>TM: table lock</li><li>TX: transaction lock</li><li>TR: row lock</li></ul> |
| ID1 | bigint(20) | NO | The first lock identifier: <ul><li>For a table lock: the value can be TABLE_ID or TABLET_ID. </li><li>For a transaction lock: TX_ID. </li><li>For a row lock: TABLET_ID. </li></ul> |
| ID2 | varchar(533) | NO | The second lock identifier: <ul><li>For a table lock: NULL. </li><li>For a transaction lock: NULL. </li><li>For a row lock: TX_ID + rowkey. </li></ul> |
| ID3 | varchar(512) | NO | The third lock identifier: <ul><li>TM: TABLE_ID / TABLET_ID </li><li>TX: NULL </li><li>TR: TABLET_ID + rowkey </li></ul> <main id="notice" type='explain'><h4>Note</h4><p><ul><li>Starting from V4.3.2 in V4.3.x. </li><li>Starting from V4.2.5 in V4.2.x. </li></ul></p></main>|
| LMODE | varchar(8) | NO | The mode in which the lock is currently held: <ul><li>NONE: indicates that no lock is held. </li><li>RS: ROW SHARE </li><li>RX: ROW EXCLUSIVE </li><li>S: SHARE </li><li>SRX: SHARE ROW EXCLUSIVE </li><li>X: EXCLUSIVE </li></ul> |
| REQUEST | varchar(8) | NO | The mode of the lock that is currently requested: <ul><li>NONE: indicates that no lock is requested. </li><li>RS: ROW SHARE </li><li>RX: ROW EXCLUSIVE </li><li>S: SHARE </li><li>SRX: SHARE ROW EXCLUSIVE </li><li>X: EXCLUSIVE </li></ul>|
| CTIME | bigint(20) | NO | The time for which the lock is held or the time for which the lock is being waited for, in microseconds. |
| BLOCK | bigint(1) | NO | Indicates whether the lock requested by the current transaction is held by another transaction: <ul><li>0: indicates that the lock is not held by another transaction. In other words, the current transaction holds the lock. </li><li>1: indicates that the lock is held by another transaction. In other words, the current transaction is blocked. </li></ul>|

## Sample query

Query the lock information of tables for the current user.

```shell
obclient [oceanbase]> SELECT * FROM oceanbase.V$OB_LOCKS LIMIT 1\G
```

The query result is as follows:

```shell
*************************** 1. row ***************************
    SVR_IP: xx.xx.xx.xx
  SVR_PORT: 2882
 TENANT_ID: 1003
  TRANS_ID: 7414198
SESSION_ID: 3221619563
      TYPE: TX
       ID1: 7414198
       ID2: 3221619563
       ID3: NULL
     LMODE: X
   REQUEST: NONE
     CTIME: 11162
     BLOCK: 0
```
