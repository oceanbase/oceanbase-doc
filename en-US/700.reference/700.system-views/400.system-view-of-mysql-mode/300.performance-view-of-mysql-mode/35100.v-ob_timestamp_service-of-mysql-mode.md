# V$OB_TIMESTAMP_SERVICE

<main id="notice" type='explain'>
<h4>Note</h4>
<p>This view is available starting with V4.2.0. </p>
</main>

## Purpose

This view displays the GTS/STS values of the tenant's clock service, the node information where the clock service is located, and the clock source type.

* The following distinctions are made based on the database:

  * For the primary database, the current GTS value allocated to the primary database is displayed.
  * For the standby database, the current readable point (STS) value of the standby database is displayed.

* The following distinctions are made based on the tenant:

  * In the system tenant, you can view the clocks of all tenants.
  * In a user tenant, you can only view the clocks of the current tenant.

## Columns

| **Column** | **Type** | **Nullable** | **Description** |
| --- | --- | --- | --- |
| TENANT_ID | bigint(20) | NO | The tenant ID. <ul><li>1: the ID of the system tenant.  </li><li>Other values: the ID of a user tenant or a meta tenant. </li></ul>|
| TS_TYPE | varchar(100) | NO | The clock source type. <ul><li>GTS: the clock of the primary database.  </li><li>STS: the clock of the standby database. </li></ul>|
| TS_VALUE | bigint(20) | NO | The current clock value stored in memory. |
| SVR_IP | varchar(46) | NO | The IP address of the node where the clock service is located. |
| SVR_PORT | bigint(20) | NO | The port number of the node where the clock service is located. |

## Sample query

In a user tenant, query the GTS/STS values, node information where the clock service is located, and clock source type of the current tenant.

```shell
obclient [oceanbase]> SELECT * FROM oceanbase.V$OB_TIMESTAMP_SERVICE;
```

The query result is as follows:

```shell
+-----------+---------+---------------------+----------------+----------+
| TENANT_ID | TS_TYPE | TS_VALUE            | SVR_IP         | SVR_PORT |
```
