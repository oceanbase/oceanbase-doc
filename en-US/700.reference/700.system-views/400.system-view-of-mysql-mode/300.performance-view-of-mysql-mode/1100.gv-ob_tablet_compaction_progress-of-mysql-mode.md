# GV$OB_TABLET_COMPACTION_PROGRESS

<main id="notice" type='explain'>
<h4>Note</h4>
<p>Introduced in V4.0.0. </p>
</main>

## Description

Displays the progress of a tablet-level major compaction.

## Field descriptions

|             Field name             |      Type      | Nullable | Description |
|------------------------------|--------------|------------|--------|
| SVR_IP                       | varchar(46)  | NO         | The IP address of the server.                                                                                |
| SVR_PORT                     | bigint(20)   | NO         | The port number of the server.|
| TENANT_ID                    | bigint(20)   | NO         | The ID of the tenant. |
| TYPE                         | varchar(64)  | NO         | The type of compaction: <ul><li>`MDS_TABLE_MERGE`: the system metadata is persisted to the disk in the SSTable format. </li> <li>`MAJOR_MERGE`: a major compaction at the tenant level. </li> <li>`MEDIUM_MERGE`: a major compaction at the partition level. </li> <li>`MINI_MERGE`: a mini compaction that transforms MemTables into a mini SSTable. </li> <li>`MINOR_MERGE`: a minor compaction that combines multiple mini SSTables into a new mini SSTable or combines multiple mini SSTables with one minor SSTable into a new minor SSTable. </li> <li>`META_MAJOR_MERGE`: a special type of compaction that synthesizes data generated before a specified time point into a Meta Major SSTable. The data format of this SSTable is the same as that of a Major SSTable, and does not contain multi-version data or uncommitted transactions. </li></ul>    |
