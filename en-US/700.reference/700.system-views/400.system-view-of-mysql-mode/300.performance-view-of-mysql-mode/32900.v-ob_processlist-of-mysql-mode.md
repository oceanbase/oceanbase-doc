# V$OB_PROCESSLIST

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This view is available starting with V4.0.0. </p>
</main>

## Purpose

The `V$OB_PROCESSLIST` view displays session information on the current OBServer node.

## Columns

|      Column      |         Type          | Nullable |                              Description                              |
|----------------|---------------------|------------|--------------------------------------------------------------|
| SVR_IP         | varchar(46)         | NO         | The IP address of the server.                                                    |
| SVR_PORT       | bigint(20)          | NO         | The port number of the server.                                                       |
| SQL_PORT       | bigint(20)          | NO         | The SQL port number.                                                      |

| USER           | varchar(32)         | NO         | The username.                                                          |

If no transaction is active for the session, this column is empty. <ul><li>`IDLE`: idle state, which indicates that no transaction has been started. </li> <li>`ACTIVE`: the transaction is explicitly started by using statements such as `START TRANSACTION` and `BEGIN`. </li> <li>`IMPLICIT_ACTIVE`: the transaction is implicitly started in `autocommit = on` mode. After you execute a DML statement, the transaction is started. </li> <li>`ROLLBACK_SAVEPOINT`: the transaction is being rolled back to a savepoint. </li> <li>`IN_TERMINATE`: the transaction is being terminated. This can be caused by internal reasons or by a user-initiated transaction termination, such as the execution of `COMMIT` or `ROLLBACK` statements. </li> <li>`ABORTED`: the transaction is internally terminated or rolled back due to an exception. </li> <li>`ROLLED_BACK`: the transaction has been rolled back. </li> <li>`COMMIT_TIMEOUT`: the transaction commit times out. </li> <li>`COMMIT_UNKNOWN`: the transaction commit result is unknown. </li> <li>`COMMITTED`: the transaction has been successfully committed. </li></ul>          |

For example, 50 indicates that diagnostic information is sampled at a frequency of 50%. <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.1. </p></main> |

If condition 1 is met, the trace log is forcibly printed at the client and the information is passed to the subsequent link components. If condition 2 is met, the trace log is printed at the same time as in the ONLY_SLOW_QUERY mode. </li></ul><main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.1. </p></main> |

```shell
obclient [oceanbase]> SELECT * FROM oceanbase.V$OB_PROCESSLIST LIMIT 1\G
```
