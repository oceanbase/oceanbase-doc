# GV$ACTIVE_SESSION_HISTORY

<main id="notice" type='explain'>
  <h4>Note</h4>
  <ul><li>This view was renamed to <a href="800.gv-ob_active_session_history-of-mysql-mode.md">GV$OB_ACTIVE_SESSION_HISTORY</a> starting from V4.2.2. </li>
  <li>This view is available starting with V4.0.0. </li></ul>
</main>

## Purpose

This view displays the history of active sessions.

## Columns

| Column | Type | Nullable | Description |
| --- | --- | --- | --- |
| SVR_IP | varchar(46) | NO | The IP address of the server to which the sample belongs. |
| SVR_PORT | bigint(20) | NO | The port number of the server to which the sample belongs. |
| SAMPLE_ID | bigint(20) | NO | The unique ID of the sample. |
| SAMPLE_TIME | datetime | NO | The time when the sample was taken. |
| CON_ID | bigint(20) | NO | The tenant ID. |
| USER_ID | bigint(20) | NO | The user ID of the session being sampled. |
| SESSION_ID | bigint(20) | NO | The ID of the session being sampled. |
| SESSION_TYPE | varchar(10) | NO | The session type. Valid values: <li>FOREGROUND: a foreground session, which is a user session<li>BACKGROUND: a background session. This value is not supported. |
| SESSION_STATE | varchar(7) | NO | The session state. Valid values: <li>ON CPU: the session is not waiting and is executing SQL logic. <li>WAITING: the session is waiting. For more information, see the `EVENT` column. |
| SQL_ID | varchar(32) | NO | The SQL ID. |
|PLAN_ID |  bigint(20) |NO  |The plan ID of the sampled SQL in the plan cache. This ID is used to associate the sampling point with the plan.|

| EVENT_NO | bigint(20) | NO | The internal number of the waiting event. This number is used for cross-table queries. |

| TIME_WAITED | bigint(20) | NO | The total waiting time of the waiting event, in microseconds (us). |

| IN_PLAN_CACHE | varchar(1) | NO | Indicates whether the session is matching a plan in the plan cache at the time of sampling. |

| IN_SQL_EXECUTION | varchar(1) | NO | Indicates whether the session is executing the SQL statement at the time of sampling. |
| IN_PX_EXECUTION | varchar(1) | NO | Indicates whether the session is executing the SQL statement in parallel at the time of sampling. If the session is in this state, it must also be in the IN_SQL_EXECUTION state. |

| IN_FILTER_ROWS | varchar(1) | NO | Indicates whether the sampling point is in the storage push-down execution stage. <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.2. </p></main> |

| IN_CONNECTION_MGR           | varchar(1)          | NO   | The current SQL link creation operation<main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.5 in the V4.2.x series. </p></main>     |
| PROGRAM | varchar(64) | YES | The name of the program being executed at the sampling point:<ul><li>Background thread: the name of the thread, for example, `observer` or `WrTimer`.  </li><li>Foreground thread:<ul><li>For a normal request, it is `user@client_ip (thread_name)`.  </li><li>For `inner_sql` remote execution, it is `INNER SQL REMOTE EXEC (thread_name)`.  </li><li>For DAS remote execution, it is `DAS REMOTE EXEC (thread_name)`.  </li></ul> </li></ul><main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.2. </p></main>|
| MODULE | varchar(64) | YES | The MODULE value recorded at the sampling point for the session. This value is set by using the `DBMS_APPLICATION_INFO.SET_MODULE` package.<main id="notice" type='explain'><h4>Note</h4><p>You can set this column starting with V4.2.3. </p></main>  |
| ACTION | varchar(64) | YES | The ACTION value recorded at the sampling point for the session. This value is set by using the `DBMS_APPLICATION_INFO.SET_ACTION` package.<main id="notice" type='explain'><h4>Note</h4><p>You can set this column starting with V4.2.3. </p></main> |
| CLIENT_ID | varchar(64) | YES | The CLIENT_ID value recorded at the sampling point for the session. This value is set by using the `DBMS_APPLICATION_INFO.set_identifier` package.<main id="notice" type='explain'><h4>Note</h4><p>You can set this column starting with V4.2.3. </p></main> |

| TM_DELTA_DB_TIME | bigint(20) | YES | The amount of time spent on database calls in the `TM_DELTA_TIME` time period in the past<main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.2. </p></main> |
