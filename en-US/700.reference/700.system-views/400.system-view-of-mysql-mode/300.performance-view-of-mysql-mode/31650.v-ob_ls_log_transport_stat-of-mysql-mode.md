# V$OB_LS_LOG_TRANSPORT_STAT

<main id="notice" type='explain'>
<h4>Note</h4>
<p>For V4.4.2, this view is available starting with V4.4.2 BP2.</p>
</main>

## Overview

The `V$OB_LS_LOG_TRANSPORT_STAT` view displays the transmission status of logs pushed from each log stream (LS) on the current node of a tenant to a standby database in strong sync mode. To query this view, you must log in as the primary tenant (or the `sys` tenant of the cluster where the primary tenant resides).

## Columns

| Column | Type | Nullable | Description |
| ----------------- | --------------------- | ---------------- | ------------- |
| TENANT_ID | bigint(20) | NO | Tenant ID |
| LS_ID | bigint(20) | NO | Log Stream ID |
| SVR_IP | varchar(46) | NO | Server IP Address |
| SVR_PORT | bigint(20) | NO | Server Port Number |
| ROLE | varchar(32) | NO | Log stream replica roles:<ul><li>`LEADER`: Primary replica</li> <li>`FOLLOWER`: Follower replica</li></ul> |
| ENABLED | tinyint(4) | NO | Whether the log transport service is enabled. |
| END_LSN | bigint(20) unsigned | NO | LSN committed by the primary tenant (primary database) Palf |
| END_SCN | bigint(20) unsigned | NO | SCN committed by the primary tenant (primary database) Palf |
| LAST_SENT_LSN | bigint(20) unsigned | NO | Last LSN sent to the standby tenant (standby database) |
| LAST_SENT_SCN | bigint(20) unsigned | NO | Last SCN sent to the standby tenant (standby database) |
| STANDBY_END_LSN | bigint(20) unsigned | NO | Confirmed LSN written on the standby tenant (standby database) |
| STANDBY_END_SCN | bigint(20) unsigned | NO | Confirmed SCN written on the standby tenant (standby database) |
| STANDBY_ADDR | varchar(52) | NO | The address of the leader of the current log stream in the standby tenant (standby database). If it is`0.0.0.0:0`, it is invalid. |

## Sample query

In the primary tenant, query the transmission status of logs pushed from each log stream on the current node to the standby tenant.

1. Confirm the synchronization mode of the primary tenant LS.

   ```shell
   obclient(root@mysql001)[oceanbase]> SELECT LS_ID, ROLE, SYNC_MODE FROM oceanbase.V$OB_LOG_STAT WHERE ROLE = 'LEADER';
   ```

   The query result is as follows:

   ```shell
   +-------+--------+-----------+
   | LS_ID | ROLE   | SYNC_MODE |
   +-------+--------+-----------+
   |     1 | LEADER | SYNC      |
   |  1001 | LEADER | SYNC      |
   +-------+--------+-----------+
   2 rows in set
   ```

   The result `SYNC` indicates that the current tenant's log stream synchronization mode is strong sync.

2. Query the transmission status of log pushing from each log stream on all nodes of the primary tenant to the standby tenant.

   ```shell
   obclient(root@mysql001)[oceanbase]> SELECT LS_ID, ROLE, ENABLED,
       END_LSN, LAST_SENT_LSN, STANDBY_END_LSN, STANDBY_ADDR
       FROM oceanbase.V$OB_LS_LOG_TRANSPORT_STAT WHERE ROLE = 'LEADER';
   ```

   The query result is as follows:

   ```shell
   +-------+--------+---------+-----------+---------------+-----------------+-------------------+
   | LS_ID | ROLE   | ENABLED | END_LSN   | LAST_SENT_LSN | STANDBY_END_LSN | STANDBY_ADDR      |
   +-------+--------+---------+-----------+---------------+-----------------+-------------------+
   |     1 | LEADER |       1 | 305300441 |     305300441 |       305300441 | 6.xx.xxx.160:2882 |
   |  1001 | LEADER |       1 | 201421647 |     201421647 |       201421647 | 6.xx.xxx.160:2882 |
   +-------+--------+---------+-----------+---------------+-----------------+-------------------+
   2 rows in set
   ```
