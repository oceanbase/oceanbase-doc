# V$SQL_JOIN_FILTER

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This view is available starting with V4.2.0. </p>
</main>

## Purpose

This view dynamically displays the execution information of the join filter for the current tenant on the current OBServer node.

## Columns

| **Column** | **Type** | **Nullable** | **Description** |
| --- | --- | --- | --- |
| SVR_IP | varchar(46) | NO | The IP address of the server. |
| SVR_PORT | bigint(20) | NO | The port number of the server. |
| QC_SESSION_ID | bigint(0) | NO | The Query Coordinator (QC) session ID of the parallel query cursor.<br>For V4.3.x: <ul><li> V4.3.5 BP2 and earlier: <br> In all connection modes (direct mode/ODP mode), this field indicates the server session ID. </li><li> V4.3.5 BP2 and later: <ul><li> In direct mode: <br> This field indicates the server session ID. </li> <li> In ODP mode: </li><ul><li> If the <code>client_session_id_version = 2</code> parameter is set in ODP, this field indicates the client session ID. </li> <li> If <code>client_session_id_version = 1</code>, this field indicates the server session ID. </li></ul></ul></li></ul> |
| QC_INSTANCE_ID | bigint(0) | NO | The Query Coordinator (QC) instance ID of the parallel query cursor. |
| SQL_PLAN_HASH_VALUE | bigint(0) | NO | The hash value of the SQL plan for the parallel query cursor. |
| FILTER_ID | bigint(20) | NO | The ID of the join filter in the cursor, which corresponds to the filter ID in the execution plan. |
| BITS_SET | bigint(0) | NO | The size of the bitmap used in the BLOOM_FILTER (join bitmap). This field is only used for compatibility in the current version. |
| FILTERED | bigint(20) | NO | The number of rows processed by the join filter. |
| PROBED | bigint(20) | NO | The total number of rows that have passed the bitmap filter test, including both filtered and unfiltered rows. |
| ACTIVE | bigint(0) | NO | Indicates whether the filter is active (YES) or inactive (NO). |
| CON_ID | bigint(20) | NO | The ID of the container to which the data belongs. |
| TRACE_ID | varchar(64) | NO | The trace ID corresponding to the SQL statement. |

## Sample query

Query the execution information of the join filter for the current tenant on the current node in the user tenant.

```shell
obclient [oceanbase]> SELECT * FROM oceanbase.V$SQL_JOIN_FILTER;
```
