# GV$OB_UNITS

<main id="notice" type='explain'>
<h4>Note</h4>
<p>This view is available starting with V4.0.0. </p>
</main>

## Purpose

This view displays the unit information of the OBServer node where the tenant is located. The system tenant can view the unit information of all OBServer nodes in the cluster.

## Columns

|       Column       |      Type      | Nullable |                                                                            Description                                                                             |
|------------------|--------------|------------|-------------------------------------------------------------------------|
| SVR_IP           | varchar(46)  | NO         | The IP address of the server.                                                              |
| SVR_PORT         | bigint(20)   | NO         | The port number of the server.                                                                 |
| UNIT_ID          | bigint(20)   | NO         | The ID of the unit.                                                                |
| TENANT_ID        | bigint(20)   | NO         | The ID of the tenant to which the unit belongs.                                                          |
| ZONE             | varchar(128) | NO         | The name of the zone.                                                                |
| ZONE_TYPE | varchar(128) | NO | The type of the zone where the unit resides. Valid values: <ul><li>`NULL`: This value is invalid. This value appears temporarily after an OBServer node restarts. </li> <li>`ReadWrite`: read/write zone</li> <li>`Encryption`: encrypted zone</li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.0. </p></main> |
| REGION | varchar(128) | NO | The name of the region to which the zone where the unit resides belongs. If this value is not set, it is `default_region` by default. If this value is `NULL`, it indicates that the value is invalid, which appears temporarily after an OBServer node restarts.<main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.0. </p></main> |
| MAX_CPU          | double       | NO         | The upper limit of the CPU specification.                                                               |
| MIN_CPU          | double       | NO         | The lower limit of the CPU specification.                                                               |
| MEMORY_SIZE      | bigint(20)   | NO         | The size of memory, in bytes.                                                           |
| MAX_IOPS         | bigint(20)   | NO         | The upper limit of the IOPS specification.                                                           |
| MIN_IOPS         | bigint(20)   | NO         | The lower limit of the IOPS specification.                                                           |
| IOPS_WEIGHT      | bigint(20)   | NO         | The IOPS weight. |
| MAX_NET_BANDWIDTH| bigint(20)   | YES        | The maximum network bandwidth of the unit, in bytes.  <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.4. </p></main> |
| NET_BANDWIDTH_WEIGHT |bigint(20)| YES        | The weight of the network bandwidth of the unit. <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.4. </p></main>  |
| LOG_DISK_SIZE    | bigint(20)   | NO         | The size of the log disk, in bytes.  |
| LOG_DISK_IN_USE  | bigint(20)   | NO         | The size of the log disk that has been used, in bytes.                                                               |
| DATA_DISK_SIZE   | bigint(20)   | YES        | <ul><li> The size of the local cache available to the unit, in bytes. This parameter applies only to the Shared-Storage (SS) mode. </li> <li> In the Shared-Nothing (SN) mode, this parameter is `NULL`, indicating that the value is undefined. The unit can use the disk space of other tenants. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.4. </p></main>     |
| DATA_DISK_IN_USE | bigint(20)   | NO         | <ul><li> In the SS mode, the size of the local cache used by the unit, in bytes. </li> <li> In the SN mode, the size of the data disk used by the unit, in bytes.  </li></ul>                    |
| STATUS           | varchar(64)  | NO         | The status of the unit:<ul><li> `NORMAL`: normal </li><li> `MIGRATING IN`: migrating in </li><li> `MIGRATING OUT`: migrating out </li><li> `MARK DELETING`: marked for deletion</li><li>`WAIT GC`: waiting for GC </li><li>`DELETING`: being deleted </li><li> `ERROR`: error </li></ul>  |
| CREATE_TIME      | timestamp(6) | NO         | The time when the unit is created on the OBServer node.                                                 |
| REPLICA_TYPE     | varchar(7)   | NO         | The replica type. The default value is `FULL` <main id="notice" type='explain'><h4>Note</h4><ul><li>For V4.5.x, the <code>REPLICA_TYPE</code> column was introduced in V4.5.0. </li><li>For V4.4.x, the <code>REPLICA_TYPE</code> column was introduced in V4.4.0 BP1. </li><li>For V4.2.5, the <code>REPLICA_TYPE</code> column was introduced in V4.2.5 BP7. </li></ul></main>   |

```shell
obclient [oceanbase]> SELECT * FROM oceanbase.GV$OB_UNITS\G
```
