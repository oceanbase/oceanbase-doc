# V$OB_TABLET_COMPACTION_HISTORY

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This view is available starting with V4.0.0. </p>
</main>

## Purpose

The `V$OB_TABLET_COMPACTION_HISTORY` view displays the history of tablet-level compactions.

## Columns

|   Column     |      Type      | **Nullable** |   Description     |
|--------------------------------------|--------------|----------------|--------|
|SVR_IP    |varchar(46)    |NO   |Server IP address    |
|SVR_PORT    |bigint(20)    |NO   |Server port number    |
|TENANT_ID    |bigint(20)    |NO   |Tenant ID    |
|LS_ID    |bigint(20)    |NO   |Log stream ID    |
|TABLET_ID    |bigint(20)    |NO   |Tablet ID    |
|TYPE    |varchar(64)    |NO   |Compaction type. Valid values: <ul><li>`MDS_TABLE_MERGE`: Persist system metadata in SSTable format to disk. </li> <li>`MAJOR_MERGE`: Tenant-level compaction. </li> <li>`MEDIUM_MERGE`: Partition-level compaction. </li> <li>`MINI_MERGE`: Mini compaction. Convert a MemTable to a Mini SSTable. </li> <li>`MINOR_MERGE`: Minor compaction. Combine multiple Mini SSTables into a new Mini SSTable or combine multiple Mini SSTables with one Minor SSTable into a new Minor SSTable. </li> <li>`META_MAJOR_MERGE`: A special type of compaction. Combine data before a specified time point into a Meta Major SSTable. The data format is the same as that of a Major SSTable. The Meta Major SSTable does not contain multi-version data or uncommitted transaction data. </li></ul>    |
|COMPACTION_SCN    |bigint(20) unsigned    |NO   |Compaction version information    |
|START_TIME    |timestamp(6)    |NO   |Start time    |
|FINISH_TIME    |timestamp(6)    |NO   |End time    |
|TASK_ID    |varchar(64)    |NO   |Task execution trace    |
|OCCUPY_SIZE    |bigint(20)    |NO   |Data volume    |
|MACRO_BLOCK_COUNT    |bigint(20)    |NO   |Number of macroblocks    |
|MULTIPLEXED_MACRO_BLOCK_COUNT    |bigint(20)    |NO   |Number of reused macroblocks    |
|NEW_MICRO_COUNT_IN_NEW_MACRO    |bigint(20)    |NO   |Number of new microblocks in new macroblocks    |
|MULTIPLEXED_MICRO_COUNT_IN_NEW_MACRO    |bigint(20)    |NO   |Number of reused microblocks in new macroblocks    |
|TOTAL_ROW_COUNT    |bigint(20)    |NO   |Total number of rows    |
|INCREMENTAL_ROW_COUNT    |bigint(20)    |NO   |Number of new rows    |
|COMPRESSION_RATIO    |double    |NO   |Compression ratio of new data = ratio of compressed data size to original data size in new macroblocks    |
|NEW_FLUSH_DATA_RATE    |bigint(20)    |NO   |Output speed of new data, in KB/s    |
|PROGRESSIVE_COMPACTION_ROUND    |bigint(20)    |NO   |Current round of progressive compaction (if it is a full compaction, this column is -1)    |
|PROGRESSIVE_COMPACTION_NUM    |bigint(20)    |NO   |Total rounds of progressive compaction    |
|PARALLEL_DEGREE    |bigint(20)    |NO   |Parallelism    |
|PARALLEL_INFO    |varchar(512)    |NO   |Information about parallel tasks, including the statistics of the amount of data scanned, running time, and output data (minimum, maximum, and average values)    |
|PARTICIPANT_TABLE    |varchar(512)    |NO   |Information about the table involved in the current compaction    |
|MACRO_ID_LIST    |varchar(256)    |NO   |List of output macroblocks. If the list is too long, it will not be displayed.    |
|COMMENTS    |varchar(256)    |NO   |Records the history of failed compactions and the time spent on the current compaction    |
| START_CG_ID                     | bigint(20)   | NO   |  Start ID of the column group<main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.0. </p></main>    |
| END_CG_ID                       | bigint(20)   | NO   |  End ID of the column group <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.0. </p></main>   |
| KEPT_SNAPSHOT                   | varchar(128) | NO   |  Multi-version snapshot information retained by the current compaction<main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.0. </p></main>    |
| MERGE_LEVEL                     | varchar(64)  | NO   |  Information about whether the current compaction involves merging or microblock reuse <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.0. </p></main>    |
| EXEC_MODE                       | varchar(64)  | NO   | The execution mode of the current compaction. Valid values: <ul><li>`EXEC_MODE_LOCAL`: Local mode. Output macroblocks to the local disk. </li> <li>`EXEC_MODE_VALIDATE`: Shared mode. Calculate only the checksum without outputting macroblocks. This mode is not supported in the current version. </li> <li>`EXEC_MODE_OUTPUT`: Shared mode. Output macroblocks to shared storage. This mode is not supported in the current version. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main> |
| IS_FULL_MERGE                   | varchar(5)   | NO   | Indicates whether the current compaction is a full compaction.<main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main> |
| IO_COST_TIME_PERCENTAGE         | bigint(20)   | NO   | The percentage of I/O time in the total compaction time. <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main> |
| MERGE_REASON                    | varchar(32)  | NO   | The reason for the major compaction. Valid values: <ul><li>`LOAD_DATA_SCENE`: Data load scenario</li> <li>`TOMBSTONE_SCENE`: Tombstone scenario</li> <li>`INEFFICIENT_QUERY`: Slow query scenario</li> <li>`FREQUENT_WRITE`: Frequent write scenario</li> <li>`TENANT_MAJOR`: Tenant-level major compaction</li> <li>`USER_REQUEST`: User-initiated major compaction</li> <li>`REBUILD_COLUMN_GROUP`: Row-to-column conversion scenario</li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main> |
| BASE_MAJOR_STATUS               | varchar(64)  | NO   | The type of the major SSTable before the major compaction. Valid values: <ul><li>`COL_WITH_ALL`: A hybrid row-column table, with hybrid row-column data in the baseline</li> <li>`COL_ONLY_ALL`: A hybrid row-column table, with row-only data in the baseline</li> <li>`PURE_COL`: A pure column table, with column data in the baseline</li> <li>`PURE_COL_ONLY_ALL`: A pure column table, with row-only data in the baseline</li> <li>`ROW_STORE_MAJOR`: A row table</li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main>|
| CO_MERGE_TYPE                   | varchar(64)  | NO   | The type of the column compaction. Valid values: <ul><li>`BUILD_COLUMN_STORE_MERGE`: Compaction to a column table</li> <li>`BUILD_ROW_STORE_MERGE`: Compaction to a row table</li> <li>`USE_RS_BUILD_SCHEMA_MATCH_MERGE`: Compaction to a storage type that matches the schema</li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main> |
| MDS_FILTER_INFO                 | varchar(1024) | NO  | The MDS filter information used for the major compaction. <main id="notice" type='explain'><h4>Note</h4><ul><li>For V4.4.x, this column is available starting with V4.4.0. </li><li>For V4.3.5, this column is available starting with V4.3.5, and becomes effective starting with V4.3.5 BP2. </li></ul></main> |
| EXECUTE_TIME                    | bigint(20)    | NO | The CPU time consumed by the major compaction task, in milliseconds.  |

## Sample query

Query the tablet-level major compaction history information on the current OBServer node as a user tenant.

```shell
obclient [oceanbase]> SELECT * FROM oceanbase.V$OB_TABLET_COMPACTION_HISTORY LIMIT 1\G
```
