# V$OB_TABLET_COMPACTION_HISTORY

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>Introduced in version V4.0.0. </p>
</main>

## Purpose

The `V$OB_TABLET_COMPACTION_HISTORY` view displays historical information about tablet-level compactions.

## Columns

| Column |  Type  | Nullable? | Description |
|--------------------------------------|--------------|----------------|--------|
| SVR_IP    | varchar(46)    | NO   | The IP address of the server.    |
| SVR_PORT    | bigint(20)    | NO   | The port of the server.    |
| TENANT_ID    | bigint(20)    | NO   | The ID of the tenant.    |
| LS_ID    | bigint(20)    | NO   | The ID of the log stream.    |
| TABLET_ID    | bigint(20)    | NO   | The ID of the data shard.    |
| TYPE    | varchar(64)    | NO   | The type of compaction. Valid values include:<ul><li>`MDS_TABLE_MERGE`: persists system metadata to disk in the SSTable format. </li> <li>`MAJOR_MERGE`: major compaction at the tenant level. </li> <li>`MEDIUM_MERGE`: major compaction at the partition level. </li> <li>`MINI_MERGE`: minor compaction, which converts MemTables into Mini SSTables. </li> <li>`MINOR_MERGE`: minor compaction, which merges multiple Mini SSTables or multiple Mini SSTables with Minor SSTables into one Minor SSTable. </li> <li>`META_MAJOR_MERGE`: a special type of compaction that synthesizes data before a specified time point into a Meta Major SSTable. The data format of the Meta Major SSTable is the same as that of a Major SSTable, but it does not contain multi-version data or uncommitted transaction data. </li></ul>    |
| COMPACTION_SCN    | bigint(20) unsigned    | NO   | The version information of the compaction.    |
| START_TIME    | timestamp(6)    | NO   | The start time of the compaction.    |
| FINISH_TIME    | timestamp(6)    | NO   | The end time of the compaction.    |
| TASK_ID    | varchar(64)    | NO   | The ID of the task execution trace.    |
| OCCUPY_SIZE    | bigint(20)    | NO   | The amount of data.    |
| MACRO_BLOCK_COUNT    | bigint(20)    | NO   | The number of macro blocks.    |
| MULTIPLEXED_MACRO_BLOCK_COUNT    | bigint(20)    | NO   | The number of reused macro blocks.    |
| NEW_MICRO_COUNT_IN_NEW_MACRO    | bigint(20)    | NO   | The number of new micro blocks in a new macro block.    |
| MULTIPLEXED_MICRO_COUNT_IN_NEW_MACRO    | bigint(20)    | NO   | The number of reused micro blocks in a new macro block.    |
| TOTAL_ROW_COUNT    | bigint(20)    | NO   | The total number of rows.    |
| INCREMENTAL_ROW_COUNT    | bigint(20)    | NO   | The number of new rows output.    |
| COMPRESSION_RATIO    | double    | NO   | The compression ratio of the new data = (the size of the compressed data after compression / the size of the data before compression)    |
| NEW_FLUSH_DATA_RATE    | bigint(20)    | NO   | The output speed of new data, in KB/s.    |
| PROGRESSIVE_COMPACTION_ROUND    | bigint(20)    | NO   | The current round of progressive compaction (if the compaction is a full major compaction, this column displays -1).    |
| PROGRESSIVE_COMPACTION_NUM    | bigint(20)    | NO   | The total number of rounds of progressive compaction.    |
| PARALLEL_DEGREE    | bigint(20)    | NO   | The degree of parallelism.    |
| PARALLEL_INFO    | varchar(512)    | NO   | Information about parallel tasks, which displays statistics (minimum value, maximum value, and average value) of the amount of data scanned, runtime, and data output by parallel tasks.    |
| PARTICIPANT_TABLE    | varchar(512)    | NO   | Information about tables that participate in the compaction.    |
| MACRO_ID_LIST    | varchar(256)    | NO   | The list of macro blocks output. If the macro block list is too long, it is not displayed.    |
| COMMENTS    | varchar(256)    | NO   | Historical information about failed compactions and information about the time taken for this compaction.    |
| START_CG_ID                     | bigint(20)   | NO   | The start ID of the column group. <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.0. </p></main>    |
| END_CG_ID                       | bigint(20)   | NO   | The end ID of the column group. <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.0. </p></main>   |
| KEPT_SNAPSHOT                   | varchar(128) | NO   | The retained multi-version site information for this compaction. <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.0. </p></main>    |
| MERGE_LEVEL                     | varchar(64)  | NO   | Whether major compaction or micro block reuse is used for this compaction. <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.0. </p></main>    |
| EXEC_MODE                       | varchar(64)  | NO   | The mode of the compaction trace. Valid values include:<ul><li>`EXEC_MODE_LOCAL`: local mode, which outputs macro blocks to the local disk. </li> <li>`EXEC_MODE_VALIDATE`: shared mode, which calculates checksums but does not output macro blocks. This mode is not supported in the current version. </li> <li>`EXEC_MODE_OUTPUT`: shared mode, which outputs macro blocks to shared storage. This mode is not supported in the current version. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.3. </p></main> |
| IS_FULL_MERGE                   | varchar(5)   | NO   | Whether the compaction is a full major compaction. <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.3. </p></main> |
| IO_COST_TIME_PERCENTAGE         | bigint(20)   | NO   | The percentage of the IO time in the compaction time. <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.3. </p></main> |
| MERGE_REASON                    | varchar(32)  | NO   | The reason for initiating the major compaction. Valid values include:<ul><li>`LOAD_DATA_SCENE`: data loading scenario. </li> <li>`TOMBSTONE_SCENE`: tombstone scenario. </li> <li>`INEFFICIENT_QUERY`: slow query scenario. </li> <li>`FREQUENT_WRITE`: frequent write scenario. </li> <li>`TENANT_MAJOR`: major compaction at the tenant level. </li> <li>`USER_REQUEST`: user-initiated major compaction. </li> <li>`REBUILD_COLUMN_GROUP`: row-to-column scenario. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.3. </p></main> |
| BASE_MAJOR_STATUS               | varchar(64)  | NO   | The type of baseline Major SSTables:<ul><li>`COL_WITH_ALL`: the table is a hybrid row-column table defined at the time of creation, and the baseline data is hybrid row-column data. </li> <li>`COL_ONLY_ALL`: the table is a hybrid row-column table defined at the time of creation, and the baseline data is adaptive row-only data. </li> <li>`PURE_COL`: the table is a pure columnar table defined at the time of creation, and the baseline data is pure columnar data. </li> <li>`PURE_COL_ONLY_ALL`: the table is a pure columnar table defined at the time of creation, and the baseline data is adaptive row-only data. </li> <li>`ROW_STORE_MAJOR`: row-store table. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.3. </p></main>|
| CO_MERGE_TYPE                   | varchar(64)  | NO   | The columnar store major compaction type. Valid values include:<ul><li>`BUILD_COLUMN_STORE_MERGE`: columnar store major compaction. </li> <li>`BUILD_ROW_STORE_MERGE`: row-store major compaction. </li> <li>`USE_RS_BUILD_SCHEMA_MATCH_MERGE`: major compaction of the storage type that matches the schema. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.3. </p></main> |

```shell
obclient [oceanbase]> SELECT * FROM oceanbase.V$OB_TABLET_COMPACTION_HISTORY LIMIT 1\G
```
