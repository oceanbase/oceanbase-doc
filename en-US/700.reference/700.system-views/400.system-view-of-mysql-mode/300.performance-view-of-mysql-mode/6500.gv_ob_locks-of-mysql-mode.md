# GV$OB_LOCKS

<main id="notice" type='explain'>
<h4>Note</h4>
<p>This view is available starting with V4.2.0. </p>
</main>

## Purpose

This view displays the locks or lock requests of tables for the current user on all OBServer nodes.

## Columns

| **Column** | **Type** | **Nullable** | **Description** |
| --- | --- | --- | --- |
| SVR_IP | varchar(46) | NO | The IP address of the OBServer node that holds or requests the lock. |
| SVR_PORT | bigint(20) | NO | The port number of the OBServer node that holds or requests the lock. |
| TENANT_ID | bigint(20) | NO | The ID of the tenant that holds or requests the lock. |
| TRANS_ID | bigint(20) | NO | The ID of the transaction that holds or requests the lock. |
| SESSION_ID | bigint(20)   | NO   | The ID of the session that holds or requests the lock. <ul><li>For V4.3.x, this column is available starting with V4.3.2. <ul><li>For versions earlier than V4.3.5 BP2: <br> In all connection modes (direct mode/ODP mode), this column indicates the server session ID. </li><li>For V4.3.5 BP2 and later: <ul><li>In direct mode: <br> This column indicates the server session ID. </li> <li>In ODP mode: </li><ul><li> If the <code>client_session_id_version</code> parameter in ODP is set to 2, this column indicates the client session ID.  </li> <li> If <code>client_session_id_version</code> is set to 1, this column indicates the server session ID. </li></ul></ul></li></ul> </li><li>For V4.2.x, this column is available starting with V4.2.5. <ul><li>For versions earlier than V4.2.5 BP4: <br> In all connection modes (direct mode/ODP mode), this column indicates the server session ID. </li><li>For V4.2.5 BP4 and later: <ul><li>In direct mode: <br> This column indicates the server session ID. </li> <li>In ODP mode: </li><ul><li> If the <code>client_session_id_version</code> parameter in ODP is set to 2, this column indicates the client session ID.  </li> <li> If <code>client_session_id_version</code> is set to 1, this column indicates the server session ID. </li></ul></ul></li></ul></li></ul>|
| TYPE | varchar(9) | NO | The lock type: <ul><li>TM: table lock</li><li>TX: transaction lock</li><li>TR: row lock</li></ul> |
| ID1 | bigint(20) | NO | Lock identifier 1: <ul><li>For a table lock: either the TABLE_ID or the TABLET_ID. </li><li>For a transaction lock: the TX_ID. </li><li>For a row lock: the TABLET_ID. </li></ul> |
| ID2 | varchar(533) | NO | Lock identifier 2: <ul><li>For a table lock: NULL. </li><li>For a transaction lock: NULL. </li><li>For a row lock: the TX_ID plus the row rowkey. </li></ul> |
| ID3 | varchar(512) | NO | Lock identifier 3: <ul><li>TM: TABLE_ID or TABLET_ID. </li><li>TX: NULL. </li><li>TR: TABLET_ID plus the row rowkey. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p><ul><li>For V4.3.x, this column is available starting with V4.3.2. </li><li>For V4.2.x, this column is available starting with V4.2.5. </li></ul></p></main>|
| LMODE | varchar(4) | NO | The mode of the lock currently held: <ul><li>NONE: indicates that no lock is held.  </li><li>RS: ROW SHARE </li><li>RX: ROW EXCLUSIVE </li><li>S: SHARE </li><li>SRX: SHARE ROW EXCLUSIVE </li><li>X: EXCLUSIVE </li></ul> |
| REQUEST | varchar(8) | NO | The mode of the lock currently requested: <ul><li>NONE: indicates that no lock is requested.  </li><li>RS: ROW SHARE </li><li>RX: ROW EXCLUSIVE </li><li>S: SHARE </li><li>SRX: SHARE ROW EXCLUSIVE </li><li>X: EXCLUSIVE </li></ul> |
| CTIME | bigint(20) | NO | The time for which the lock is held or the lock is waiting, in microseconds. |
| BLOCK | bigint(1) | NO | Indicates whether the lock requested by the current transaction is held by another transaction: <ul><li>0: indicates that the lock requested by the current transaction is not held by another transaction, that is, the current transaction holds the lock.  </li><li>1: indicates that the lock requested by the current transaction is held by another transaction, that is, the current transaction is blocked. </li></ul> |

## Sample query

Query the locks or lock requests of tables for the current user on all OBServer nodes.

```shell
obclient [oceanbase]> SELECT * FROM oceanbase.GV$OB_LOCKS;
```

The query result is as follows:

```shell
+----------------+----------+-----------+----------+------------+------+---------+------------+------+-------+---------+---------+-------+

+----------------+----------+-----------+----------+------------+------+---------+------------+------+-------+---------+---------+-------+
| 11.xxx.xxx.xxx |    28825 |      1002 |  3771300 | 3221509936 | TM   | 3770297 | 4294967295 | NULL | NONE  | N       | 4411886 |     1 |
+----------------+----------+-----------+----------+------------+------+---------+------------+------+-------+---------+---------+-------+
1 row in set
```
