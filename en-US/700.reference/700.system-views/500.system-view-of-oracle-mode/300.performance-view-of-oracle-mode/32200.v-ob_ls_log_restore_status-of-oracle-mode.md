# V$OB_LS_LOG_RESTORE_STATUS

<main id="notice" type='explain'>
<h4>Note</h4>
<p>This view is available starting with V4.2.0. </p>
</main>

## Purpose

This view displays the log restore status at the log stream level for the current tenant.

## Columns

| **Column** | **Type** | **Nullable** | **Description** |
| --- | --- | --- | --- |
| TENANT_ID | NUMBER(38) | NO | The tenant ID. |
| LS_ID | NUMBER(38) | NO | The log stream ID. |
| SYNC_LSN | NUMBER(38) | NO | The latest LSN of the majority of logs in the standby database. |
| SYNC_SCN | NUMBER(38) | NO | The latest SCN of the majority of logs in the standby database. |
| SYNC_STATUS | VARCHAR2(128) | NO | The log restore status. Valid values: <ul><li>NORMAL: The logs are being synchronized normally.  </li><li>SOURCE HAS A GAP: The log source has a gap. </li><li>STANDBY LOG NOT MATCH: The logs in the standby database and the log source are different at the same LSN.  </li><li>CHECK USER OR PASSWORD: The username or password of the replication account is incorrect, and the log source cannot be accessed.  </li><li>CHECK NETWORK: The log source is unreachable. This may be due to an incorrect tenant access IP address or port.  </li><li>FETCH LOG TIMEOUT: The log fetch operation times out.  </li><li>RESTORE SUSPEND: The log restore has reached the maximum synchronization point.  </li><li>STANDBY NEED UPGRADE: The standby database version is outdated.  </li><li>CHECK PRIMARY ALIVE: The primary database cannot be accessed. Check whether the primary database has been deleted.  </li><li> NOT AVAILABLE: The log synchronization is unavailable due to other exceptions. </li></ul>|
| ERR_CODE | NUMBER(38) | NO | The error code. This field is 0 during normal synchronization. |
| COMMENT | VARCHAR2(2048) | NO | The error details. This field is empty during normal synchronization. |

## Sample query

Query the log restore status at the log stream level for the current user tenant.

```shell
obclient [SYS]> SELECT * FROM SYS.V$OB_LS_LOG_RESTORE_STATUS;
```
