# V$OB_LOCKS

## Purpose

Displays the lock or lock request information for each table held or requested by the current user.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This view was introduced in V4.2.0. </p>
</main>

## Columns

| **Column** | **Type** | **Nullable?** | **Description** |
| --- | --- | --- | --- |
| SVR_IP | VARCHAR2(46) | NO | The IP address of the OBServer node holding or requesting locks. |
| SVR_PORT | NUMBER(38) | NO | The port number of the OBServer node holding or requesting locks. |
| TENANT_ID | NUMBER(38) | NO | The ID of the tenant holding or requesting locks. |
| TRANS_ID | NUMBER(38) | NO | The ID of the transaction holding or requesting locks. |
| TYPE | VARCHAR2(9) | NO | The lock type. Valid values include:<ul><li>TM: table lock</li><li>TX: transaction lock</li><li>TR: row lock</li></ul> |
| ID1 | NUMBER | NO | The first lock identifier. Valid values include:<ul><li>For table locks, the value can be either TABLE_ID or TABLET_ID. </li><li>For transaction locks, the value is TX_ID. </li><li>For row locks, the value is TABLET_ID. </li></ul> |
| ID2 | VARCHAR2(553) | NO | The second lock identifier. Valid values include:<ul><li>For table locks, the value is NULL. </li><li>For transaction locks, the value is NULL. </li><li>For row locks, the value is TX_ID + rowkey. </li></ul> |
| LMODE | VARCHAR2(8) | NO | The mode of the lock held by the current transaction. Valid values include:<ul><li>NONE: indicates that no lock is held. </li><li>RS: ROW SHARE</li><li>RX: ROW EXCLUSIVE</li><li>S: SHARE</li><li>SRX: SHARE ROW EXCLUSIVE</li><li>X: EXCLUSIVE</li></ul> |
| REQUEST | VARCHAR2(8) | NO | The mode of the lock requested by the current transaction. Valid values include:<ul><li>NONE: indicates that no lock is requested. </li><li>RS: ROW SHARE  </li><li>RX: ROW EXCLUSIVE  </li><li>S: SHARE  </li><li>SRX: SHARE ROW EXCLUSIVE  </li><li>X: EXCLUSIVE  </li></ul>|
| CTIME | NUMBER(38) | NO | The time in microseconds when the lock is held or requested. |
| BLOCK | NUMBER | NO | Indicates whether the lock requested by the current transaction is held by another transaction. Valid values include:<ul><li>0: indicates that the lock requested by the current transaction is not held by another transaction. In other words, the current transaction holds the lock. </li><li>1: indicates that the lock requested by the current transaction is held by another transaction. In other words, the current transaction is blocked. </li></ul>|
