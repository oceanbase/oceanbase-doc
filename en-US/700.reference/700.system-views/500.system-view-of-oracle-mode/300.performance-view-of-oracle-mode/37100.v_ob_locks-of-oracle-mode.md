# V$OB_LOCKS

<main id="notice" type='explain'>
<h4>Note</h4>
<p>This view is available starting with V4.2.0. </p>
</main>

## Purpose

This view displays the lock status of tables for the current user on the current OBServer node.

## Columns

| **Column** | **Type** | **Nullable** | **Description** |
| --- | --- | --- | --- |
| SVR_IP | VARCHAR2(46) | NO | The IP address of the OBServer node that holds or requests the lock. |
| SVR_PORT | NUMBER(38) | NO | The port number of the OBServer node that holds or requests the lock. |
| TENANT_ID | NUMBER(38) | NO | The ID of the tenant that holds or requests the lock. |
| TRANS_ID | NUMBER(38) | NO | The ID of the transaction that holds or requests the lock. |
| SESSION_ID | NUMBER(38) | NO   | The ID of the session that holds or requests the lock. <ul><li>For V4.3.x, this column is available starting from V4.3.2. <ul><li>For versions earlier than V4.3.5 BP2: <br> In all connection modes (direct mode/ODP mode), this column indicates the server session ID. </li><li>For V4.3.5 BP2 and later: <ul><li> In direct mode: <br> This column indicates the server session ID. </li> <li> In ODP mode: </li><ul><li> If the configuration parameter <code>client_session_id_version = 2</code> is set in ODP, this column indicates the client session ID. </li> <li> If <code>client_session_id_version = 1</code> is set, this column indicates the server session ID. </li></ul></ul></li></ul> </li><li>For V4.2.x, this column is available starting from V4.2.5. <ul><li>For versions earlier than V4.2.5 BP4: <br> In all connection modes (direct mode/ODP mode), this column indicates the server session ID. </li><li>For V4.2.5 BP4 and later: <ul><li> In direct mode: <br> This column indicates the server session ID. </li> <li> In ODP mode: </li><ul><li> If the configuration parameter <code>client_session_id_version = 2</code> is set in ODP, this column indicates the client session ID. </li> <li> If <code>client_session_id_version = 1</code> is set, this column indicates the server session ID. </li></ul></ul></li></ul></li></ul>|
| TYPE | VARCHAR2(9) | NO | The lock type: <ul><li>TM: table lock</li><li>TX: transaction lock</li><li>TR: row lock</li></ul> |
| ID1 | NUMBER | NO | Lock identifier 1: <ul><li>For a table lock: the value can be TABLE_ID or TABLET_ID. </li><li>For a transaction lock: TX_ID. </li><li>For a row lock: TABLET_ID. </li></ul> |
| ID2 | VARCHAR2(553) | NO | Lock identifier 2: <ul><li>For a table lock: NULL. </li><li>For a transaction lock: NULL. </li><li>For a row lock: TX_ID + row key. </li></ul> |
| ID3 | varchar(512) | NO | Lock identifier 3: <ul><li>TM: TABLE_ID / TABLET_ID </li><li>TX: NULL </li><li>TR: TABLET_ID + row key </li></ul> <main id="notice" type='explain'><h4>Note</h4><p><ul><li>For V4.3.x, this column is available starting from V4.3.2. </li><li>For V4.2.x, this column is available starting from V4.2.5. </li></ul></p></main>|
| LMODE | VARCHAR2(8) | NO | The mode in which the lock is currently held: <ul><li>NONE: no lock is requested. </li><li>RS: ROW SHARE </li><li>RX: ROW EXCLUSIVE </li><li>S: SHARE </li><li>SRX: SHARE ROW EXCLUSIVE </li><li>X: EXCLUSIVE </li></ul> |
| REQUEST | VARCHAR2(8) | NO | The mode in which the lock is currently requested: <ul><li>NONE: no lock is requested. </li><li>RS: ROW SHARE </li><li>RX: ROW EXCLUSIVE </li><li>S: SHARE </li><li>SRX: SHARE ROW EXCLUSIVE </li><li>X: EXCLUSIVE </li></ul> |
| CTIME | NUMBER(38) | NO | The time for which the lock is held or the time for which the lock is being waited for, in microseconds. |
| BLOCK | NUMBER | NO | Indicates whether the lock requested by the current transaction is held by another transaction: <ul><li>0: The lock requested by the current transaction is not held by another transaction. </li><li>1: The lock requested by the current transaction is held by another transaction. </li></ul>|
