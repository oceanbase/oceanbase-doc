# V$OB_TABLET_COMPACTION_HISTORY

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This view is introduced since OceanBase Database V4.0.0. </p>
</main>

## Purpose

The `V$OB_TABLET_COMPACTION_HISTORY` view displays the historical information about tablet-level compactions.

## Columns

| Column      |  Type  | Nullable? | Description |
|-----------------|----------|----------|------------|
| SVR_IP          | VARCHAR2(46)  | NO         | IP address of the server. |
| SVR_PORT        | NUMBER(38)    | NO         | Port number of the server. |
| TENANT_ID       | NUMBER(38)    | NO         | Tenant ID. |
| LS_ID           | NUMBER(38)    | NO         | Log stream ID. |
| TABLET_ID       | NUMBER(38)    | NO         | Data tablet ID. |
| TYPE            | VARCHAR2(64)  | NO         | Type of the compaction:<ul><li>`MDS_TABLE_MERGE`: persists the system metadata in the SSTable format to the disk. </li> <li>`MAJOR_MERGE`: major compaction at the tenant level. </li> <li>`MEDIUM_MERGE`: major compaction at the partition level. </li> <li>`MINI_MERGE`: minor compaction, which converts the MemTable into a Mini SSTable. </li> <li>`MINOR_MERGE`: minor compaction, which merges multiple Mini SSTables or a Mini SSTable and a Minor SSTable into a Minor SSTable. </li> <li>`META_MAJOR_MERGE`: a special type of compaction that synthesizes data before a specified time point into a Meta Major SSTable. The data format of the Meta Major SSTable is the same as that of a Major SSTable, but it does not contain multi-version data or uncommitted transaction data. </li></ul>    |
| COMPACTION_SCN                              | NUMBER(38)    | NO         | Compaction version: snapshot_version for minor compactions.                                                            |
| START_TIME                           | TIMESTAMP(6) WITH LOCAL TIME ZONE    | NO         | Start time.  |
| FINISH_TIME                          | TIMESTAMP(6) WITH LOCAL TIME ZONE    | NO         | End time.  |
| OCCUPY_SIZE                          | NUMBER(38)    | NO         | Data volume.   |
| MACRO_BLOCK_COUNT                    | NUMBER(38)    | NO         | Number of macro blocks.   |
| MULTIPLEXED_MACRO_BLOCK_COUNT        | NUMBER(38)    | NO         | Number of reused macro blocks. |
| NEW_MICRO_COUNT_IN_NEW_MACRO         | NUMBER(38)    | NO         | Number of new micro blocks in a new macro block.                                                                              |
| MULTIPLEXED_MICRO_COUNT_IN_NEW_MACRO | NUMBER(38)    | NO         | Number of reused micro blocks in a new macro block.                                                                             |
| TOTAL_ROW_COUNT                      | NUMBER(38)    | NO         | Total number of rows.   |
| INCREMENTAL_ROW_COUNT                | NUMBER(38)    | NO         | Number of new rows. |
| COMPRESSION_RATIO                    | NUMBER(38)    | NO         | Compression ratio of new data: the ratio of the compressed data to the original data in a new macro block.                                                                 |
| PROGRESSIVE_COMPACTION_ROUND         | NUMBER(38)    | NO         | Current round of progressive compaction. If the compaction is a full compaction, this field is -1.                                                                  |
| PROGRESSIVE_COMPACTION_NUM           | NUMBER(38)    | NO         | Total number of rounds of progressive compaction.                                                                                  |
| PARALLEL_DEGREE                      | NUMBER(38)    | NO         | Degree of parallelism.   |

| MACRO_ID_LIST    |varchar2(256)    |NO   |List of macro blocks. If the macro block list is too long, it is not displayed.    |
|COMMENTS    |varchar2(256)    |NO   |Records the historical information of failed compactions and the collection information of the duration of the current compaction.    |
| START_CG_ID                     | NUMBER(38)   | NO   | Start ID of the column group. <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.0. </p></main>    |
| END_CG_ID                       | NUMBER(38)   | NO   | End ID of the column group. <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.0. </p></main>   |
| KEPT_SNAPSHOT                   | VARCHAR2(128)| NO   | Retained multi-version points in this compaction. <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.0. </p></main>    |
| MERGE_LEVEL                     | VARCHAR2(64) | NO   | Whether major compaction or microblock reuse is used. <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.0. </p></main>    |
| EXEC_MODE                       | VARCHAR2(64) | NO   | Mode of this compaction trace:<ul><li>`EXEC_MODE_LOCAL`: local mode, which outputs macro blocks to the local disk. </li> <li>`EXEC_MODE_VALIDATE`: shared mode, which only calculates checksums and does not output macro blocks. This mode is not supported in the current version. </li> <li>`EXEC_MODE_OUTPUT`: shared mode, which outputs macro blocks to shared storage. This mode is not supported in the current version. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.3. </p></main> |
| IS_FULL_MERGE                   | VARCHAR2(5)  | NO   | Whether the compaction is a full compaction. <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.3. </p></main> |
| IO_COST_TIME_PERCENTAGE         | NUMBER(38)   | NO   | Percentage of IO time in the compaction time. <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.3. </p></main> |
| MERGE_REASON                    | VARCHAR2(32) | NO   | Reason for the compaction, which can take the following values:<ul><li>`LOAD_DATA_SCENE`: data loading scenario</li> <li>`TOMBSTONE_SCENE`: tombstone scenario</li> <li>`INEFFICIENT_QUERY`: slow query scenario</li> <li>`FREQUENT_WRITE`: frequent write scenario</li> <li>`TENANT_MAJOR`: major compaction at the tenant level</li> <li>`USER_REQUEST`: user-initiated compaction</li> <li>`REBUILD_COLUMN_GROUP`: row-to-column scenario</li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.3. </p></main> |
| BASE_MAJOR_STATUS               | VARCHAR2(64) | NO   | Type of the baseline Major SSTable:<ul><li>`COL_WITH_ALL`: a hybrid row-column table defined at the time, and the baseline data is also in hybrid row-column format. </li> <li>`COL_ONLY_ALL`: a hybrid row-column table defined at the time, and the baseline data is in rowstore-only format. </li> <li>`PURE_COL`: a columnstore table defined at the time, and the baseline data is also in columnstore format. </li> <li>`PURE_COL_ONLY_ALL`: a columnstore table defined at the time, and the baseline data is in rowstore-only format. </li> <li>`ROW_STORE_MAJOR`: a rowstore table. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.3. </p></main>|
| CO_MERGE_TYPE                   | VARCHAR2(64) | NO   | Type of columnstore major compaction:<ul><li>`BUILD_COLUMN_STORE_MERGE`: major compaction to columnstore. </li> <li>`BUILD_ROW_STORE_MERGE`: major compaction to rowstore. </li> <li>`USE_RS_BUILD_SCHEMA_MATCH_MERGE`: major compaction to the storage type that matches the schema. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.3. </p></main> |

```shell
obclient [SYS]> SELECT * FROM SYS.V$OB_TABLET_COMPACTION_HISTORY WHERE ROWNUM = 1\G
```
