# GV$ACTIVE_SESSION_HISTORY

<main id="notice" type='explain'>
  <h4>Note</h4>
  <ul>
  <li>This view was renamed to <a href="900.gv-ob_active_session_history-of-oracle-mode.md">GV$OB_ACTIVE_SESSION_HISTORY</a> starting from V4.2.2. </li>
  <li>This view is available starting with V4.0.0. </li></ul>
</main>

## Purpose

This view displays the history of active sessions.

## Columns

| Column | Type | Nullable | Description |
| --- | --- | --- | --- |
| SVR_IP | VARCHAR2(46) | NO | The IP address of the server to which the sample belongs. |
| SVR_PORT | NUMBER | NO | The port number of the server to which the sample belongs. |
| SAMPLE_ID | NUMBER | NO | The unique ID of the sample. |
| SAMPLE_TIME | TIMESTAMP(6) | NO | The time when the sample was collected. |
| CON_ID | NUMBER | NO | The tenant ID. |
| USER_ID | NUMBER | NO | The user ID of the session that was sampled. |
| SESSION_ID | NUMBER | NO | The ID of the session that was sampled. |
| SESSION_TYPE | VARCHAR2(10) | NO | The session type. Valid values: <li>FOREGROUND: a foreground session, which is a user session<li>BACKGROUND: a background session. This value is not supported. |
| SESSION_STATE | VARCHAR2(7) | NO | The session state. Valid values: <li>ON CPU: the session is not waiting and is executing the SQL logic<li>WAITING: the session is waiting. For more information, see the `EVENT` column. |
| SQL_ID | VARCHAR2(32) | YES | The SQL ID. |
| PLAN_ID |  bigint(20) |NO  |The plan ID of the SQL statement in the PLAN CACHE. This ID is used to associate the sampling point with the plan. |
| TRACE_ID | VARCHAR2(64)  | YES   | The trace ID of the operator. |

| P3TEXT | VARCHAR2(64) | NO | The name of the third parameter of the waiting event. The name varies based on the value of the `EVENT` column. |

| WAIT_CLASS_ID | NUMBER | NO | The ID of the type to which the waiting event belongs. This ID is used to associate the sampling point with other tables. |

| TIME_MODEL                  | NUMBER          | NO   | The time model information, which is a collection of all IN_XXX fields (such as IN_PARSE and IN_PL_PARSE). <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.4. </p></main>     |

| IN_PLAN_CACHE | VARCHAR2(1) | NO | Indicates whether the session is matching a plan in the plan cache at the time of sampling. |
| IN_SQL_OPTIMIZE | VARCHAR2(1) | NO | Indicates whether the session is optimizing an SQL statement at the time of sampling. |
| IN_SQL_EXECUTION | VARCHAR2(1) | NO | Indicates whether the session is executing an SQL statement at the time of sampling. |
| IN_PX_EXECUTION | VARCHAR2(1) | NO | Indicates whether the session is executing an SQL statement in parallel at the time of sampling. If the session is in this state, it must also be in the IN_SQL_EXECUTION state. |
| IN_SEQUENCE_LOAD | VARCHAR2(1) | NO | Indicates whether the session is fetching values from an auto-increment column or a sequence at the time of sampling. |
| IN_COMMITTING | VARCHAR2(1) | NO | Indicates whether the sampling point is in the transaction commit phase. <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.1. </p></main> |

| IN_STORAGE_WRITE | VARCHAR2(1) | NO | Indicates whether the sampling point is in the storage write phase. <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.1. </p></main> |
| IN_REMOTE_DAS_EXECUTION | VARCHAR2(1) | NO | Indicates whether the sampling point is in the DAS remote execution phase. <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.1. </p></main> |

| IN_CONNECTION_MGR           | VARCHAR2(1)                       | NO   | The link creation operation being performed by the current SQL statement<main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.5 in V4.2.x. </p></main>     |
| PROGRAM | VARCHAR2(64) | YES | The name of the program being executed at the current sampling point:<ul><li>Background thread: the name of the thread, such as `observer` or `WrTimer`.  </li><li>Foreground thread:<ul><li>For a normal request, it is `user@client_ip (thread_name)`.  </li><li>For an `inner_sql` remote execution, it is `INNER SQL REMOTE EXEC (thread_name)`.  </li><li>For a DAS remote execution, it is `DAS REMOTE EXEC (thread_name)`.  </li></ul> </li></ul><main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.2. </p></main>|
| MODULE | VARCHAR2(64) | YES | The MODULE value recorded at the sampling time, set by the `DBMS_APPLICATION_INFO.SET_MODULE` package.<main id="notice" type='explain'><h4>Note</h4><p>This column can be set starting with V4.2.3. </p></main> |
| ACTION | VARCHAR2(64) | YES | The ACTION value recorded at the sampling time, set by the `DBMS_APPLICATION_INFO.SET_ACTION` package.<main id="notice" type='explain'><h4>Note</h4><p>This column can be set starting with V4.2.3. </p></main> |
| CLIENT_ID | VARCHAR2(64) | YES | The CLIENT_ID value recorded at the sampling time, set by the `DBMS_APPLICATION_INFO.set_identifier` package.<main id="notice" type='explain'><h4>Note</h4><p>This column can be set starting with V4.2.3. </p></main> |

| TM_DELTA_DB_TIME | NUMBER | YES | The amount of time spent on database calls during the `TM_DELTA_TIME` time period in the past<main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.2. </p></main> |
