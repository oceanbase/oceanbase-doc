# GV$OB_JVM_STATUS

<main id="notice" type='explain'>
<h4>Note</h4>
<p>For V4.4.2, this view is available starting with V4.4.2 BP4.</p>
</main>

## Overview

This view displays the runtime status and resource usage of the JVM in the OBServer process on all OBServer nodes, including information such as the JVM status, heap memory, metaspace, GC, number of threads, and number of file descriptors. Each OBServer node corresponds to a row in the table.

The usage instructions are as follows:

* The JVM is started only when the `ob_enable_java_env` parameter is enabled. When it is not enabled, the `STATUS` is `DISABLED`.
* After the JVM is started, the system collects JVM status data by default every 60 seconds. A query on this view returns the result from the most recent collection and does not trigger JVM startup or another collection.
* Metrics that have not been successfully collected or cannot be obtained are displayed as NULL, to distinguish them from metrics whose actual value is `0`.
* For the status of the sandbox JVM when Java UDFs are executed in a sandbox process, see [GV$OB_JAVA_SANDBOX_STATUS](37300.gv_ob_java_sandbox_status-of-oracle-mode.md).

## Columns

| Field Name | Type | Whether can be NULL | Description |
| ---------------- | ------------- | ---------------- | ---------------- |
| SVR_IP | VARCHAR2(46) | NO | The IP address of the OBServer node. |
| SVR_PORT | NUMBER(38) | NO | The port number of the OBServer node. |
| PROCESS_PID | NUMBER(38) | YES | The process ID of the OBServer process. |
| STATUS | VARCHAR2(32) | NO | The status of the JVM in the OBServer process: <ul><li>`DISABLED`: The Java environment is not enabled (parameter configuration`ob_enable_java_env`is`False`)</li><li>`NOT_STARTED`: JVM has not been started yet.</li><li>`STARTING`: The JVM is starting, or has started but has not completed the first collection yet.</li><li>`UP`: The JVM is running, and the last collection was successful.</li><li>`INIT_FAILED`: JVM initialization failed.</li><li>`COLLECT_ERROR`: JVM status collection failed.</li><li>`DOWN`: The OBServer process is exiting, or JVM monitoring has stopped.</li></ul> |
| INIT_ATTEMPT_COUNT | NUMBER(38) | YES | Cumulative number of attempts for JVM initialization. |
| INIT_FAILURE_COUNT | NUMBER(38) | YES | Cumulative number of JVM initialization failures. |
| LAST_INIT_ERROR_CODE | NUMBER(38) | YES | The error code of the most recent failed JVM initialization. This parameter is NULL if no initialization failure has occurred. |
| LAST_INIT_ERROR_TIME | TIMESTAMP(6) WITH LOCAL TIME ZONE | YES | The time when the last JVM initialization failed. This column is NULL if no initialization failure has occurred. |
| JVM_START_TIME | TIMESTAMP(6) WITH LOCAL TIME ZONE | YES | The startup time of the JVM. |
| JVM_UPTIME_MS | NUMBER(38) | YES | The duration for which the JVM has been running, in milliseconds. |
| MONITOR_BRIDGE_VERSION | NUMBER(38) | YES | The version number of the JVM monitoring interface. |
| HEAP_USED_BYTES | NUMBER(38) | YES | The size of memory used by the JVM heap, in bytes. |
| HEAP_COMMITTED_BYTES | NUMBER(38) | YES | The size of committed memory in the JVM heap, in bytes. |
| HEAP_MAX_BYTES | NUMBER(38) | YES | The maximum size of the JVM heap memory available for use, in bytes. |
| YOUNG_USED_BYTES | NUMBER(38) | YES | The size of memory used by the young generation of the JVM, in bytes. |
| OLD_USED_BYTES | NUMBER(38) | YES | The size of memory occupied by the old generation of the JVM, in bytes. |
| METASPACE_USED_BYTES | NUMBER(38) | YES | The size of the used JVM metaspace, in bytes. |
| METASPACE_COMMITTED_BYTES | NUMBER(38) | YES | The size of the committed JVM metaspace, in bytes. |
| METASPACE_MAX_BYTES | NUMBER(38) | YES | The maximum size of the JVM metaspace available for use, in bytes. |
| CODE_CACHE_USED_BYTES | NUMBER(38) | YES | The size of the Code Cache used, in bytes. |
| DIRECT_BUFFER_USED_BYTES | NUMBER(38) | YES | The size of memory used by the JVM direct buffer, in bytes. |
| DIRECT_BUFFER_COUNT | NUMBER(38) | YES | The number of direct buffers in the JVM. |
| GC_COUNT | NUMBER(38) | YES | Cumulative number of GCs in the JVM. |
| GC_TIME_MS | NUMBER(38) | YES | The cumulative JVM GC time, in milliseconds. |
| YOUNG_GC_COUNT | NUMBER(38) | YES | The cumulative number of young generation GCs in the JVM. |
| YOUNG_GC_TIME_MS | NUMBER(38) | YES | The cumulative young generation GC time of the JVM, in milliseconds. |
| MAJOR_GC_COUNT | NUMBER(38) | YES | The cumulative number of major GCs in the JVM. |
| MAJOR_GC_TIME_MS | NUMBER(38) | YES | Cumulative Major GC Time in the JVM, in milliseconds. |
| THREAD_COUNT | NUMBER(38) | YES | The current number of threads in the JVM. |
| PEAK_THREAD_COUNT | NUMBER(38) | YES | The peak number of threads in the JVM. |
| OPEN_FD_COUNT | NUMBER(38) | YES | The number of file descriptors currently open by the OBServer process. |
| MAX_FD_COUNT | NUMBER(38) | YES | The maximum number of file descriptors that an OBServer process can open. |
| COLLECT_ERROR_CODE | NUMBER(38) | YES | The error code of the most recent collection.`0`indicates a successful collection. |
| COLLECT_COST_US | NUMBER(38) | YES | The time consumed in the most recent collection, in microseconds. |
| LAST_COLLECT_ATTEMPT_TIME | TIMESTAMP(6) WITH LOCAL TIME ZONE | YES | The time of the last collection attempt. |
| SNAPSHOT_TIME | TIMESTAMP(6) WITH LOCAL TIME ZONE | YES | The time of the last successful data collection. |
| SNAPSHOT_AGE_US | NUMBER(38) | YES | Time elapsed since the last successful data collection, in microseconds. |

## Sample query

```shell
obclient> SELECT SVR_IP, SVR_PORT, STATUS, HEAP_USED_BYTES, HEAP_MAX_BYTES, GC_COUNT, THREAD_COUNT, SNAPSHOT_TIME FROM SYS.GV$OB_JVM_STATUS;
```
