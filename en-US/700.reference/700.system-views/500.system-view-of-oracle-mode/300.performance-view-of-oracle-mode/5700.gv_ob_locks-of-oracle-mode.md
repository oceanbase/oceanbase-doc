# GV$OB_LOCKS

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This view is available starting with V4.2.0. </p>
</main>

## Purpose

The `GV$OB_LOCKS` view displays the lock status of tables for the current user.

## Columns

| **Column** | **Type** | **Nullable** | **Description** |
| ---- | ---- | ---- | ---- |
| SVR_IP | VARCHAR2(46) | NO | The IP address of the OBServer node that holds or requests a lock. |
| SVR_PORT | NUMBER(38) | NO | The port number of the OBServer node that holds or requests a lock. |
| TENANT_ID | NUMBER(38) | NO | The ID of the tenant that holds or requests a lock. |
| TRANS_ID | NUMBER(38) | NO | The ID of the transaction that holds or requests a lock. |
| SESSION_ID | NUMBER(38)    | NO   | The ID of the session that holds or requests a lock<ul><li> In V4.3.x versions, this column is available starting from V4.3.2. <ul><li> In versions earlier than V4.3.5 BP2: <br> In all connection modes (direct mode/ODP mode), this column indicates the server session ID. </li><li> In V4.3.5 BP2 and later versions: <ul><li> In direct mode: <br> This column indicates the server session ID. </li> <li> In ODP mode: </li><ul><li> If the <code>client_session_id_version</code> parameter in ODP is set to 2, this column indicates the client session ID. </li> <li> If <code>client_session_id_version</code> is set to 1, this column indicates the server session ID. </li></ul></ul></li></ul> </li><li> In V4.2.x versions, this column is available starting from V4.2.5. In all connection modes (direct mode/ODP mode), this column indicates the server session ID. </li></ul> |
| TYPE | VARCHAR2(9) | NO | The lock type:<ul><li> TM: table lock</li><li> TX: transaction lock</li><li> TR: row lock</li></ul> |
| ID1 | bigint(20) | NO | Lock identifier 1:<ul><li> TM: transaction ID</li><li> TX: transaction ID</li><li> TR: transaction ID</li></ul> |
| ID2 | bigint(20) | NO | Lock identifier 2:<ul><li> TM: session ID (NULL for transaction table locks) </li><li> TX: session ID</li><li> TR: session ID</li></ul> |
| ID3 | varchar(512) | NO | Lock identifier 3:<ul><li> TM: TABLE_ID / TABLET_ID</li><li> TX: NULL</li><li> TR: TABLET_ID + row rowkey</li></ul> <main id="notice" type='explain'><h4>Note</h4><p><ul><li> In V4.3.x versions, this column is available starting from V4.3.2. </li><li> In V4.2.x versions, this column is available starting from V4.2.5. </li></ul></p></main>|
| LMODE | VARCHAR2(4) | NO | The mode of the lock currently held:<ul><li> NONE: no lock is held</li><li> RS: ROW SHARE</li><li> RX: ROW EXCLUSIVE</li><li> S: SHARE</li><li> SRX: SHARE ROW EXCLUSIVE</li><li> X: EXCLUSIVE</li></ul> |
| REQUEST | VARCHAR2(8) | NO | The mode of the lock currently requested:<ul><li> NONE: no lock is requested </li><li> RS: ROW SHARE  </li><li> RX: ROW EXCLUSIVE  </li><li> S: SHARE  </li><li> SRX: SHARE ROW EXCLUSIVE  </li><li> X: EXCLUSIVE  </li></ul>|
| CTIME | NUMBER(38) | NO | The time for which the lock is held or the lock is being waited for, in microseconds. |
| BLOCK | NUMBER | NO | Indicates whether the lock requested by the current transaction is held by another transaction:<ul><li> 0: the lock requested by the transaction is not held by another transaction. </li><li> 1: the lock requested by the transaction is held by another transaction. </li></ul>|
