# GV$OB_UNITS

<main id="notice" type='explain'>
<h4>Note</h4>
<p>This view is available starting with V4.0.0. </p>
</main>

## Purpose

This view displays the unit information of the OBServer node where the tenant is located. The sys tenant can view the unit information of all OBServer nodes in the cluster.

## Columns

|       Column       |      Type      | Nullable |                                                                            Description                                                                             |
|------------------|--------------|------------|-------------------------------------------------------------------------|
| SVR_IP           | VARCHAR2(46)  | NO         | The IP address of the server.                                                              |
| SVR_PORT         | NUMBER(38)   | NO         | The port number of the server.                                                                 |
| Unit_ID          | NUMBER(38)   | NO         | The ID of the unit.                                                                |
| TENANT_ID        | NUMBER(38)   | NO         | The ID of the tenant to which the unit belongs.                                                          |
| ZONE             | VARCHAR2(128) | NO         | The name of the zone.                                                                |
| ZONE_TYPE        | VARCHAR2(128) | NO         | The type of the zone to which the unit belongs. Valid values: <ul><li>`NULL`: indicates that the value of this column is invalid. This value appears temporarily when an OBServer node restarts. </li> <li>`ReadWrite`: read/write zone</li> <li>`Encryption`: encrypted zone</li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.0. </p></main> |
| REGION           | VARCHAR2(128) | NO         | The name of the region to which the zone belongs. If this column is not set, the default value is `default_region`. If the value is `NULL`, it indicates that the value of this column is invalid. This value appears temporarily when an OBServer node restarts. <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.0. </p></main>  |
| MIN_CPU          | NUMBER(38)       | NO         | The minimum CPU specification.                                                               |
| MAX_CPU          | NUMBER(38)       | NO         | The maximum CPU specification.                                                               |
| MEMORY_SIZE      | NUMBER(38)   | NO         | The size of memory, in bytes.                                                           |
| MIN_IOPS         | NUMBER(38)   | NO         | The minimum IOPS specification.                                                           |
| MAX_IOPS         | NUMBER(38)   | NO         | The maximum IOPS specification.                                                           |
| IOPS_WEIGHT      | NUMBER(38)   | NO         | The IOPS weight.                          |
| MAX_NET_BANDWIDTH| NUMBER(38)   | YES        | The maximum network bandwidth of the unit, in bytes.  <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.4. </p></main> |
| NET_BANDWIDTH_WEIGHT |NUMBER(38)| YES        | The weight of the network bandwidth of the unit. <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.4. </p></main>  |
| LOG_DISK_SIZE    | NUMBER(38)   | NO         | The size of the log disk, in bytes.                |
| LOG_DISK_IN_USE  | NUMBER(38)   | NO         | The size of the log disk that has been used, in bytes.                                                               |
| DATA_DISK_SIZE   | NUMBER(38)   | YES        | <ul><li> The size of the local cache that can be used by the unit, in bytes. This parameter is applicable only in the Shared-Storage (SS) mode. </li> <li> In the Shared-Nothing (SN) mode, the value of this column is `NULL`, which indicates that the parameter is undefined. This parameter allows the unit to compete for disk space of other tenants. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.4. </p></main>     |
| DATA_DISK_IN_USE | NUMBER(38)   | NO         | <ul><li> In the SS mode, the size of the local cache that has been used by the unit, in bytes. </li> <li> In the SN mode, the size of the data disk that has been used by the unit, in bytes.  </li></ul>                      |
| STATUS           | VARCHAR2(64)  | NO         | The status of the unit. Valid values: <ul><li>`NORMAL`: normal status</li><li> `MIGRATING IN`: migrating in   </li><li> `MIGRATING OUT`: migrating out   </li><li> `MARK DELETING`: marked for deletion</li><li>`WAIT GC`: waiting for garbage collection </li><li>`DELETING`: garbage collection is completed, and the unit is being deleted </li><li> `ERROR`: error status </li></ul> |
| CREATE_TIME      | NUMBER(38) | NO         | The creation time of the unit on the OBServer node.                                                 |
| REPLICA_TYPE     | VARCHAR2(7)   | NO         | The replica type, which defaults to `FULL`. <main id="notice" type='explain'><h4>Note</h4><ul><li>For V4.5.x, the <code>REPLICA_TYPE</code> column is available starting with V4.5.0. </li><li>For V4.4.x, the <code>REPLICA_TYPE</code> column is available starting with V4.4.0 BP1. </li><li>For V4.2.5, the <code>REPLICA_TYPE</code> column is available starting with V4.2.5 BP7. </li></ul></main>  |

## Sample query

In SN mode, a user tenant queries the unit information of all OBServer nodes where it resides.

```shell
obclient [SYS]> SELECT * FROM SYS.GV$OB_UNITS\G
```
