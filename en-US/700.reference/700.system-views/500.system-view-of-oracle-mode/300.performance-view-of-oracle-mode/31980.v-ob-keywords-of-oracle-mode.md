# V$OB_KEYWORDS

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This view is available starting with V4.4.2 BP3. </p>
</main>

## Purpose

The `V$OB_KEYWORDS` view displays the keywords supported by OceanBase Database.

## Columns

| **Column** | **Type** | **Nullable?** | **Description** |
| --- | --- | --- | --- |
| KEYWORD | VARCHAR2(128) | NO | Keyword name |
| LENGTH | NUMBER | NO | Length of the keyword |
| TYPE | VARCHAR2(16) | NO | Keyword type. The current value can only be `SQL` or `PL` |
| RESERVED | NUMBER(38) | NO | Indicates whether it is a reserved keyword |

## Considerations

You can use this view to check whether a string can be used as an identifier. However, in the current implementation of OceanBase Database, a small number of non-reserved keywords cannot actually be used as identifiers.

The following non-reserved keywords cannot be used as identifiers in an Oracle-compatible tenant:

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>These keywords are not prohibited in all cases. For example, some of them cannot be used as table aliases but can be used as column names. We recommend that you avoid these keywords in scenarios where identifiers are required, such as when you create objects, table names, or column names.</p>
</main>

In the SQL mode of an Oracle-compatible tenant:

* `USING`
* `BULK`
* `COLLATE`
* `CROSS`
* `FULL`
* `INNER`
* `JOIN`
* `LOG`
* `LEFT`
* `NATURAL`
* `RETURN`
* `RIGHT`
* `RETURNING`

In the PL mode of an Oracle-compatible tenant:

* `CHARACTER`
* `CONSTANT`
* `DATE`
* `FLOAT`
* `LOOP`
* `NUMBER`
* `RAW`
* `REAL`
* `VARCHAR`
* `VARCHAR2`

## Sample query

```shell
obclient > SELECT * FROM SYS.V$OB_KEYWORDS WHERE ROWNUM <= 5;
```

The query result is as follows:

```shell
+---------+--------+------+----------+
| KEYWORD | LENGTH | TYPE | RESERVED |
+---------+--------+------+----------+
| access  |      6 | SQL  |        1 |
| add     |      3 | SQL  |        1 |
| all     |      3 | SQL  |        1 |
| alter   |      5 | SQL  |        1 |
| and     |      3 | SQL  |        1 |
+---------+--------+------+----------+
```
