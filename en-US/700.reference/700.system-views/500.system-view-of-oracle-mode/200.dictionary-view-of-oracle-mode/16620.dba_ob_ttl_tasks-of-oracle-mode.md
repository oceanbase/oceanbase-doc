# DBA_OB_TTL_TASKS

<main id="notice" type='explain'>
<h4>Note</h4>
<p>This view is available starting with V4.6.0. </p>
</main>

## Purpose

The `DBA_OB_TTL_TASKS` view displays the execution status of TTL tasks in the current tenant in SQL mode.

## Columns

| Column         | Type         | Nullable | Description                                       |
|---------------|---------------|-------------|-------------------------------------------|
| TABLE_NAME    | VARCHAR2(256) | NO   | The name of the table.     |
| TABLE_ID      | NUMBER(38)    | NO   | The ID of the table.     |
| TASK_ID       | NUMBER(38)    | NO   | The ID of the current batch task.     |
| START_TIME    | NUMBER(38)    | NO   | The start time of the task.     |
| MODIFIED_TIME | NUMBER(38)    | NO   | The update time of the row.   |
| TRIGGER_TYPE  | VARCHAR2(8)   | NO   | The type of task trigger:<ul><li>`PERIODIC`: the system triggers the task periodically. </li> <li>`USER`: the user manually triggers the task. </li></ul>       |
| STATUS        | VARCHAR2(10)  | NO   | The status of the task:<ul><li>`PENDING`: the task is waiting to reach an executable state. </li> <li>`CANCELED`: the task is canceled. </li> <li>`FINISHED`: the task has ended. </li> <li>`SKIP`: the task did not reach an executable state and is skipped in this round. </li> <li>`FAILED`: the task failed. </li> <li>`TRIGGERING`: the task is being triggered on the RS node. </li> <li>`SUSPENDING`: the task is being suspended on the RS node. </li> <li>`CANCELING`: the task is being canceled on the RS node. </li> <li>`MOVING`: the RS node is moving the task execution information to the task history table. </li></ul>     |
| RET_CODE      | VARCHAR2(512) | NO   | The error code returned when the task ends.    |
| TASK_TYPE     | VARCHAR2(10)  | NO   | The type of the TTL task:<ul><li>`NORMAL`: displays tenant-level information. </li> <li>`COMPACTION`: the task type at the table level, which deletes expired data through compaction. </li></ul>     |

## Sample query

Query the execution status of TTL tasks in the current user tenant.

```shell
obclient(SYS@oracle001)[SYS]> SELECT * FROM SYS.DBA_OB_TTL_TASKS;
```

The query result is as follows:

```shell
+------------+----------+---------+------------------+------------------+--------------+------------+------------+------------+
| TABLE_NAME | TABLE_ID | TASK_ID | START_TIME       | MODIFIED_TIME    | TRIGGER_TYPE | STATUS     | RET_CODE   | TASK_TYPE  |
+------------+----------+---------+------------------+------------------+--------------+------------+------------+------------+
| NULL       |       -1 |       3 | 1773199108238139 | 1773199108238139 | USER         | TRIGGERING | OB_SUCCESS | COMPACTION |
+------------+----------+---------+------------------+------------------+--------------+------------+------------+------------+
1 row in set
```
