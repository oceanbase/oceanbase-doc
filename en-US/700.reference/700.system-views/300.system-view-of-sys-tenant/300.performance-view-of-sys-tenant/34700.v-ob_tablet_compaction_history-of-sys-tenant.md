# V$OB_TABLET_COMPACTION_HISTORY

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This view is available starting with V4.0.0. </p>
</main>

## Purpose

The `V$OB_TABLET_COMPACTION_HISTORY` view displays the history of tablet-level compactions.

## Columns

|                 Column |      Type    | **Nullable** |       Description       |
|--------------------------------------|--------------|----------------|--------|
|SVR_IP    |varchar(46)    |NO   |Server IP address    |
|SVR_PORT    |bigint(20)    |NO   |Server port number    |
|TENANT_ID    |bigint(20)    |NO   |Tenant ID    |
|LS_ID    |bigint(20)    |NO   |Log stream ID    |
|TABLET_ID    |bigint(20)    |NO   |Tablet ID    |
|TYPE    |varchar(64)    |NO   | Compaction type:<ul><li>`MDS_TABLE_MERGE`: Persist the system's metadata in the SSTable format to the disk. </li> <li>`MAJOR_MERGE`: Tenant-level compaction. </li> <li>`MEDIUM_MERGE`: Partition-level compaction. </li> <li>`MINI_MERGE`: Mini compaction, which converts a MemTable to a Mini SSTable. </li> <li>`MINOR_MERGE`: Minor compaction, which combines multiple Mini SSTables into a new Mini SSTable or combines multiple Mini SSTables with a Minor SSTable into a new Minor SSTable. </li> <li>`META_MAJOR_MERGE`: A special type of compaction. It combines data from a specified point in time into a Meta Major SSTable. The data format is the same as that of a Major SSTable, which does not contain multi-version data or uncommitted transaction data. </li></ul>    |
|COMPACTION_SCN    |bigint(20) unsigned    |NO   |Compaction version information    |
|START_TIME    |timestamp(6)    |NO   |Start time    |
|FINISH_TIME    |timestamp(6)    |NO   |End time    |

|OCCUPY_SIZE    |bigint(20)    |NO   |Data volume    |
|MACRO_BLOCK_COUNT    |bigint(20)    |NO   |Number of macroblocks    |

|MULTIPLEXED_MICRO_COUNT_IN_NEW_MACRO    |bigint(20)    |NO   |Number of reused microblocks in new macroblocks    |
|TOTAL_ROW_COUNT    |bigint(20)    |NO   |Total number of rows    |

|COMPRESSION_RATIO    |double    |NO   |New data compression ratio = Compressed data volume of new macroblocks / Uncompressed data volume of new macroblocks    |
|NEW_FLUSH_DATA_RATE    |bigint(20)    |NO   |New data output speed, unit: KB/s    |
|PROGRESSIVE_COMPACTION_ROUND    |bigint(20)    |NO   |Progressive compaction round (If it is a full compaction, this column is -1.)    |

|PARTICIPANT_TABLE    |varchar(512)    |NO   |Table information involved in the current compaction    |
|MACRO_ID_LIST    |varchar(256)    |NO   |List of output macroblocks. If the list is too long, it is not displayed.    |
|COMMENTS    |varchar(256)    |NO   |Records the compaction history information of failed compactions and the time taken for the current compaction.    |
| START_CG_ID                     | bigint(20)   | NO   |  Column Group Start ID<main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.0. </p></main>    |

| MERGE_LEVEL                     | varchar(64)  | NO   |  Whether the current compaction uses merge or microblock reuse<main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.0. </p></main>    |
| EXEC_MODE                       | varchar(64)  | NO   | The mode of the current compaction trace:<ul><li>`EXEC_MODE_LOCAL`: Local mode, which outputs macroblocks to the local disk. </li> <li>`EXEC_MODE_VALIDATE`: Shared mode, which calculates only the checksum and does not output macroblocks. This mode is not supported in the current version. </li> <li>`EXEC_MODE_OUTPUT`: Shared mode, which outputs macroblocks to shared storage. | IS_FULL_MERGE                   | varchar(5)   | NO   | Indicates whether the current compaction is a full compaction.<main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main> |
| IO_COST_TIME_PERCENTAGE         | bigint(20)   | NO   | The percentage of I/O time in the total compaction time. <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main> |
| MERGE_REASON                    | varchar(32)  | NO   | The reason for the major compaction. Valid values: <ul><li>`LOAD_DATA_SCENE`: Load data scenario</li> <li>`TOMBSTONE_SCENE`: Tombstone scenario</li> <li>`INEFFICIENT_QUERY`: Slow query scenario</li> <li>`FREQUENT_WRITE`: Frequent write scenario</li> <li>`TENANT_MAJOR`: Tenant-level major compaction</li> <li>`WINDOW_COMPACTION`: Window compaction</li>  <li>`USER_REQUEST`: User-initiated major compaction</li> <li>`REBUILD_COLUMN_GROUP`: Row-to-column conversion scenario</li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main> |
| BASE_MAJOR_STATUS               | varchar(64)  | NO   | The type of the major SSTable before the major compaction. Valid values: <ul><li>`COL_WITH_ALL`: A hybrid row-column store table with hybrid row-column data</li> <li>`COL_ONLY_ALL`: A hybrid row-column store table with only row data</li> <li>`PURE_COL`: A pure columnar store table with columnar data</li> <li>`PURE_COL_ONLY_ALL`: A pure columnar store table with only row data</li> <li>`ROW_STORE_MAJOR`: A row store table</li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main>|
| CO_MERGE_TYPE                   | varchar(64)  | NO   | The type of the columnar compaction. Valid values: <ul><li>`BUILD_COLUMN_STORE_MERGE`: Compaction to a columnar store</li> <li>`BUILD_ROW_STORE_MERGE`: Compaction to a row store</li> <li>`USE_RS_BUILD_SCHEMA_MATCH_MERGE`: Compaction to a storage type that matches the schema</li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main> |
| MDS_FILTER_INFO                 | varchar(1024) | NO  | The MDS filter information used for the major compaction. <main id="notice" type='explain'><h4>Note</h4><ul><li>For V4.4.x, this column is available starting with V4.4.0. </li><li>For V4.3.5, this column is available starting with V4.3.5 BP2. </li></ul></main> |
| EXECUTE_TIME                    | bigint(20)    | NO | The CPU time consumed by the major compaction, in milliseconds.  |
| FILTER_ROW_COUNT                | bigint(20)    | NO | The number of rows recovered by the major compaction. <main id="notice" type='explain'><h4>Note</h4><ul><p>This column is available starting with V4.6.0. </p></main>  |

## Sample query

Query the history of tablet-level major compactions on the current OBServer node in the sys tenant.

```shell
obclient(root@sys)[oceanbase]> SELECT * FROM oceanbase.V$OB_TABLET_COMPACTION_HISTORY LIMIT 1\G
```
