# V$OB_TABLET_COMPACTION_HISTORY

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This view is available starting with V4.0.0. </p>
</main>

## Purpose

The `V$OB_TABLET_COMPACTION_HISTORY` view displays the history information of tablet-level compactions.

## Columns

|                 Column |      Type    | **Nullable** |       Description       |
|--------------------------------------|--------------|----------------|--------|
|SVR_IP    |varchar(46)    |NO   |The IP address of the server.    |
|SVR_PORT    |bigint(20)    |NO   |The port number of the server.    |
|TENANT_ID    |bigint(20)    |NO   |The tenant ID.    |
|LS_ID    |bigint(20)    |NO   |The log stream ID.    |
|TABLET_ID    |bigint(20)    |NO   |The tablet ID.    |
|TYPE    |varchar(64)    |NO   |The type of compaction. Valid values: <ul><li>`MDS_TABLE_MERGE`: persist the system metadata in the SSTable format to the disk. </li> <li>`MAJOR_MERGE`: major compaction at the tenant level. </li> <li>`MEDIUM_MERGE`: major compaction at the partition level. </li> <li>`MINI_MERGE`: minor compaction. Convert the MemTable to a Mini SSTable. </li> <li>`MINOR_MERGE`: minor compaction. Merge multiple Mini SSTables into a new Mini SSTable or merge multiple Mini SSTables with one Minor SSTable into a new Minor SSTable. </li> <li>`META_MAJOR_MERGE`: major compaction. Merge the data before a specified time point into a Meta Major SSTable. The data format of the Meta Major SSTable is the same as that of the Major SSTable. It does not contain multi-version data or uncommitted transaction data. </li></ul>    |
|COMPACTION_SCN    |bigint(20) unsigned    |NO   |The version information of the compaction.    |
|START_TIME    |timestamp(6)    |NO   |The start time.    |
|FINISH_TIME    |timestamp(6)    |NO   |The end time.    |
|TASK_ID    |varchar(64)    |NO   |The trace of the task.    |
|OCCUPY_SIZE    |bigint(20)    |NO   |The data size.    |
|MACRO_BLOCK_COUNT    |bigint(20)    |NO   |The number of macroblocks.    |
|MULTIPLEXED_MACRO_BLOCK_COUNT    |bigint(20)    |NO   |The number of reused macroblocks.    |
|NEW_MICRO_COUNT_IN_NEW_MACRO    |bigint(20)    |NO   |The number of new microblocks in the new macroblock.    |
|MULTIPLEXED_MICRO_COUNT_IN_NEW_MACRO    |bigint(20)    |NO   |The number of reused microblocks in the new macroblock.    |
|TOTAL_ROW_COUNT    |bigint(20)    |NO   |The total number of rows.    |
|INCREMENTAL_ROW_COUNT    |bigint(20)    |NO   |The number of new rows.    |
|COMPRESSION_RATIO    |double    |NO   |The compression ratio of the new data. The compression ratio is the ratio of the compressed data size to the original data size.    |
|NEW_FLUSH_DATA_RATE    |bigint(20)    |NO   |The output speed of the new data, in KB/s.    |
|PROGRESSIVE_COMPACTION_ROUND    |bigint(20)    |NO   |The current round of progressive compaction. If the compaction is a full compaction, this column is -1.    |
|PROGRESSIVE_COMPACTION_NUM    |bigint(20)    |NO   |The total number of rounds of progressive compaction.    |
|PARALLEL_DEGREE    |bigint(20)    |NO   |The parallelism.    |
|PARALLEL_INFO    |varchar(512)    |NO   |The information about the parallel task. It displays the statistical information about the data scanned, the running time, and the output data size of the parallel task, including the minimum, maximum, and average values.    |
|PARTICIPANT_TABLE    |varchar(512)    |NO   |The information about the table involved in the compaction.    |
|MACRO_ID_LIST    |varchar(256)    |NO   |The list of output macroblocks. If the list is too long, it will not be displayed.    |
|COMMENTS    |varchar(256)    |NO   |The information about the failed compaction history and the time spent on the current compaction.    |
| START_CG_ID                     | bigint(20)   | NO   |  The start ID of the column group<main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.0. </p></main>    |
| END_CG_ID                       | bigint(20)   | NO   |  The end ID of the column group <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.0. </p></main>   |
| KEPT_SNAPSHOT                   | varchar(128) | NO   |  The information about the multi-version snapshot retained in the current compaction<main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.0. </p></main>    |
| MERGE_LEVEL                     | varchar(64)  | NO   |  The information about whether major compaction or microblock reuse is used in the current execution<main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.0. </p></main>    |
| EXEC_MODE                       | varchar(64)  | NO   | The mode of the compaction trace. Valid values: <ul><li>`EXEC_MODE_LOCAL`: local mode. Output the macroblock to the local disk. </li> <li>`EXEC_MODE_VALIDATE`: shared mode. Calculate the checksum only. Do not output the macroblock. This mode is not supported in the current version. </li> <li>`EXEC_MODE_OUTPUT`: shared mode. Output the macroblock to the shared storage. This mode is not supported in the current version. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main> |
| IS_FULL_MERGE                   | varchar(5)   | NO   | Indicates whether the compaction is a full compaction.<main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main> |
| IO_COST_TIME_PERCENTAGE         | bigint(20)   | NO   | The percentage of the I/O time in the total compaction time. <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main> |
| MERGE_REASON                    | varchar(32)  | NO   | The reason for the major compaction. Valid values: <ul><li>`LOAD_DATA_SCENE`: data load scenario</li> <li>`TOMBSTONE_SCENE`: tombstone scenario</li> <li>`INEFFICIENT_QUERY`: slow query scenario</li> <li>`FREQUENT_WRITE`: frequent write scenario</li> <li>`TENANT_MAJOR`: tenant-level major compaction</li> <li>`WINDOW_COMPACTION`: window compaction</li>  <li>`USER_REQUEST`: user-initiated major compaction</li> <li>`REBUILD_COLUMN_GROUP`: row-to-column conversion scenario</li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main> |
| BASE_MAJOR_STATUS               | varchar(64)  | NO   | The type of the major SSTable before the major compaction: <ul><li>`COL_WITH_ALL`: the table is a hybrid row-column store table, and the baseline data is stored in a hybrid row-column store format</li> <li>`COL_ONLY_ALL`: the table is a hybrid row-column store table, and the baseline data is stored in a row store format</li> <li>`PURE_COL`: the table is a pure column store table, and the baseline data is stored in a column store format</li> <li>`PURE_COL_ONLY_ALL`: the table is a pure column store table, and the baseline data is stored in a row store format</li> <li>`ROW_STORE_MAJOR`: the table is a row store table</li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main>|
| CO_MERGE_TYPE                   | varchar(64)  | NO   | The type of the column store compaction: <ul><li>`BUILD_COLUMN_STORE_MERGE`: major compaction to a column store</li> <li>`BUILD_ROW_STORE_MERGE`: major compaction to a row store</li> <li>`USE_RS_BUILD_SCHEMA_MATCH_MERGE`: major compaction to a storage type that matches the schema</li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main> |
| MDS_FILTER_INFO                 | varchar(1024) | NO  | The MDS filter information used for the major compaction <main id="notice" type='explain'><h4>Note</h4><ul><li>For V4.4.x, this column is available starting with V4.4.0. </li><li>For V4.3.5, this column is available starting with V4.3.5 BP2. </li></ul></main> |
| EXECUTE_TIME                    | bigint(20)    | NO | The CPU time consumed by the major compaction, in microseconds  |
| FILTER_ROW_COUNT                | bigint(20)    | NO | The number of rows recovered by the major compaction <main id="notice" type='explain'><h4>Note</h4><ul><p>This column is available starting with V4.6.0. </p></main>  |

## Sample query

Query the tablet-level compaction history information on the current OBServer node in the sys tenant.

```shell
obclient(root@sys)[oceanbase]> SELECT * FROM oceanbase.V$OB_TABLET_COMPACTION_HISTORY LIMIT 1\G
```
