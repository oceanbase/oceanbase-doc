# V$OB_PROCESSLIST

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This view is available starting with V4.0.0. </p>
</main>

## Purpose

The `V$OB_PROCESSLIST` view displays session information on the current OBServer node.

## Columns

|      Column      |         Type          | Nullable |                              Description                              |
|----------------|---------------------|------------|--------------------------------------------------------------|
| SVR_IP         | varchar(46)         | NO         | The IP address of the server.                                                    |
| SVR_PORT       | bigint(20)          | NO         | The port number of the server.                                                       |
| SQL_PORT       | bigint(20)          | NO         | The port number of SQL.                                                      |
| ID             | bigint(20) unsigned | NO         | The session ID.                                                        |
| USER           | varchar(32)         | NO         | The username.                                                          |
| HOST           | varchar(128)        | NO         | The name of the client host. If the client is connected through an ODP, the value is the IP address of the ODP.                |

| TOTAL_TIME     | bigint(20)          | NO         | The total time taken for the command to be executed, in seconds. <ul><li>If the command is executed after a request is received and before the response is returned to the client, the value is the time interval from when the request was received to the current time.  </li><li>If the command is not executed after a request is received, the value is the duration of the current state. </li></ul><main id="notice" type='explain'><h4>Note</h4><p>In versions earlier than V4.2.5, the value of this field is the total execution time of the current command, which is not reset when the command is retried. </p></main>                                 |

| SSL_CIPHER     | varchar(4096)       | NO         | The name of the encryption cipher.                                                       |

| TRANS_STATE    | varchar(32)         | NO         | The transaction state. Valid values are `IDLE`, `ACTIVE`, `IMPLICIT_ACTIVE`, `ROLLBACK_SAVEPOINT`, `IN_TERMINATE`, `ABORTED`, `ROLLED_BACK`, `COMMIT_TIMEOUT`, `COMMIT_UNKNOWN`, and `COMMITTED`. For more information about the transaction states, see the following list.  <ul><li>`IDLE`: idle, which indicates that the transaction has not started. </li> <li>`ACTIVE`: the transaction is explicitly started by using a statement such as `START TRANSACTION` or `BEGIN`. </li> <li>`IMPLICIT_ACTIVE`: the transaction is implicitly started in `autocommit = on` mode. For example, the transaction is started when a DML statement such as `INSERT`, `UPDATE`, or `DELETE` is executed. </li> <li>`ROLLBACK_SAVEPOINT`: the transaction is rolled back to a savepoint. </li> <li>`IN_TERMINATE`: the transaction is in the process of ending. This may occur for internal reasons or as a result of user-initiated transactions. For example, it may occur when the `COMMIT` or `ROLLBACK` statement is executed. </li> <li>`ABORTED`: the transaction is internally terminated or rolled back due to an exception. </li> <li>`ROLLED_BACK`: the transaction has been rolled back. </li> <li>`COMMIT_TIMEOUT`: the transaction submitted times out. </li> <li>`COMMIT_UNKNOWN`: the transaction submission result is unknown. </li> <li>`COMMITTED`: the transaction has been successfully committed. </li> </ul>|
| ACTION         | varchar(4096)       | NO         | The name of the current operation, which is set by calling the DBMS_APPLICATION_INFO.SET_ACTION procedure. |
| MODULE         | varchar(4096)       | NO         | The name of the current operation being executed, set by using the DBMS_APPLICATION_INFO.SET_MODULE procedure. |

| RECORD_POLICY | varchar(32) | NO | This view displays the trace recording policy for the session. The policy must be one of the following three values: <ul><li>ALL: All trace information from traces that are traced when a trace sampling opens is printed to log files. Log files are written at the end of each span. </li><li>ONLY_SLOW_QUERY: Only trace information from Slow Query requests that are traced when a trace sampling opens is printed to log files. For this policy, log files are written when the request is determined to be a Slow Query. In the Proxy, for the root span of a transaction, logs are written when a Slow Query is discovered. </li><li>SAMPLE_AND_SLOW_QUERY: Trace information that is printed to log files must meet the following conditions:<ol><li>Trace sampling at a rate of 0.0001% must be enabled by using the hidden configuration parameter <code>_print_sample_ppm</code>. If trace sampling returns a selected result, the trace information is printed to log files. </li><li>The trace information meets the printing conditions for the ONLY_SLOW_QUERY policy. </li></ol>The log files are written only if one of the conditions is met. If condition 1 is met, the trace information is marked for forced printing at the client. The information is passed to subsequent link components. If condition 2 is met, log files are written when the request is determined to be a Slow Query. </li></ul><main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.1. </p></main> |
| LB_VID | bigint(20) | NO | The value is the VPC ID of the Load Balance service if you connect to the database directly in public cloud. Otherwise, the value is NULL<main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.1. </p></main> |
| LB_VIP | varchar(46) | NO | If this is a public cloud environment and the database is directly connected via a load balancer, this column shows the client's IP address for connecting to the load balancing service. | LB_VPORT | bigint(20) | NO | If the public cloud environment directly connects to the database by using a load balancing service, the value in this column is the client port connected to the load balancing service. | IN_BYTES | bigint(20) | NO | The size of the bytes flowing in, in bytes. <main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.1. </p></main> |

| PROXY_USER        | varchar(128)        | NO  |<ul><li>In the context of proxy user login, the name of the proxy user is returned.</li><li>In the context of non-proxy user login, this field is displayed as empty.</li></ul><main id="notice" type='explain'><h4>Note</h4><p>This column is available starting from V4.2.3. </p></main> |
| SERVICE_NAME      | varchar(64)         | NO   | The name of the service that created the session. If this value is `NULL`, the session was not created by a service.  <main id="notice" type='explain'><h4>Note</h4><p>This column was added in V4.2.4. </p></main> |
| TOTAL_CPU_TIME    | bigint(21)          | NO   | The CPU time consumed by the current command, in seconds. <main id="notice" type='explain'><h4>Note</h4><ul><li>This column was introduced in V4.3.1. </li> <li>This column was introduced in V4.2.1 BP5 for V4.2.1, and in V4.2.5 for other V4.2.x versions. </li></ul></main>      |
