# GV$OB_SERVERS

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This view is available starting with V4.0.0. </p>
</main>

## Purpose

This view displays information about all OBServer nodes.

## Columns

|          Column           |      Type      | Nullable |              Description              |
|-------------------------|--------------|------------|-------|
| SVR_IP                  | varchar(46)  | NO         | The IP address of the server.                    |
| SVR_PORT                | bigint(20)   | NO         | The port number of the server.                       |
| ZONE                    | varchar(128) | NO         | The name of the zone.                      |
| SQL_PORT                | bigint(20)   | NO         | The SQL port.                       |
| CPU_CAPACITY            | bigint(20)   | NO         | The total CPU capacity of the node.        |
| CPU_CAPACITY_MAX        | double       | NO         | The oversold value of the total CPU capacity of the node. It is controlled by the `resource_hard_limit` parameter: `CPU_CAPACITY_MAX = CPU_CAPACITY * resource_hard_limit`                                                                   |
| CPU_ASSIGNED            | double       | NO         | The total number of CPU cores already allocated to the OBServer node. It is the sum of the `MIN_CPU` specifications of all units on the OBServer node. Constraint: `CPU_ASSIGNED <= CPU_CAPACITY`                |
| CPU_ASSIGNED_MAX        | double       | NO         | The upper limit of the CPU cores already allocated to the OBServer node. It is the sum of the `MAX_CPU` specifications of all units on the OBServer node. Constraint: `CPU_ASSIGNED_MAX <= CPU_CAPACITY_MAX`       |
| MEM_CAPACITY            | bigint(20)   | NO         | The total amount of memory available for allocation to tenants on the OBServer node, calculated as `memory_limit - system_memory`, in bytes.    |
| MEM_ASSIGNED            | bigint(20)   | NO         | The amount of memory already allocated to the OBServer node, which is the sum of the `MEMORY_SIZE` specifications of all units on the OBServer node, in bytes. Constraint: `MEM_ASSIGNED <= MEM_CAPACITY`     |
| LOG_DISK_CAPACITY       | bigint(20)   | NO         | The total size of the log disk space, in bytes.     |
| LOG_DISK_ASSIGNED       | bigint(20)   | NO         | The size of the log disk space already allocated, which is the sum of the `LOG_DISK_SIZE` specifications of all units on the OBServer node, in bytes.         |
| LOG_DISK_IN_USE         | bigint(20)   | NO         | The size of the log disk space already used, in bytes.               |
| DATA_DISK_CAPACITY      | bigint(20)   | NO         | <ul><li>In Shared-Storage (SS) mode, the total size of the local cache space on the OBServer node, which is the upper limit of the sum of the `DATA_DISK_SIZE` specifications of all units on the OBServer node, in bytes.</li> <li>In Shared-Nothing (SN) mode, the total size of the data disk space on the OBServer node, in bytes. </li></ul>      |
| DATA_DISK_ASSIGNED      | bigint(20)   | YES        | <ul><li>The size of the local cache space already allocated to units on the OBServer node, which is the sum of the `DATA_DISK_SIZE` specifications of all units on the OBServer node, in bytes. This column is applicable only in SS mode.</li> <li>In SN mode, the value of this column is `NULL`, indicating that the disk space can be competed for by other tenants.</li></ul><main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.3.3. </p></main>    |
| DATA_DISK_IN_USE        | bigint(20)   | NO         | <ul><li>In SS mode, the size of the local cache space already used on the OBServer node, which is the sum of the `DATA_DISK_IN_USE` values of all units on the OBServer node, in bytes.</li> <li>In SN mode, the size of the data disk space already used on the OBServer node, in bytes. </li></ul>    |
| DATA_DISK_HEALTH_STATUS | varchar(20)  | NO         | The health status of the data disk:<ul><li> `NORMAL`: normal status </li><li>`WARNING`: abnormal status</li><li>`ERROR`: error status </li></ul>   |
| MEMORY_LIMIT            | bigint(20)   | NO         | The total amount of memory available on the OBServer node, in bytes.   |
| DATA_DISK_ALLOCATED     | bigint(20)   | NO         | The size of the data disk space already allocated to the OBServer node, in bytes<main id="notice" type='explain'><h4>Note</h4><p>This column is available starting with V4.2.0. </p></main>    |
| DATA_DISK_ABNORMAL_TIME | timestamp(6) | NO         | The last time when the data disk was in an abnormal state (`WARNING` or `ERROR`).  |
| SSL_CERT_EXPIRED_TIME    | timestamp(6) | NO         | The time when the SSL certificate used by the current OBServer node expires, along with the UTC time, in microseconds. |
| SS_DATA_DISK_OPERATION_SUGGESTED | varchar(32)| YES  | <ul><li>In SS mode, the recommendation for expanding or shrinking the local cache disk space:<ul><li>`NONE`: no operation</li> <li>`EXPAND`: expand</li> <li>`SHRINK`: shrink</li> </ul></li> <li>In SN mode, the value of this column is `NULL`. </li></ul>   <main id="notice" type='explain'><h4>Note</h4><ul><li>This column is available starting with V4.4.0 for V4.4.x versions. </li><li>This column is available starting with V4.3.5 BP2 for V4.3.5 versions. </li></ul></main>     |
| SS_DATA_DISK_SIZE_SUGGESTED      | bigint(20) | YES  | <ul><li>Indicates the recommended size of the local disk in SS mode, in bytes. If the value is `0`, you can decide the size of the disk to be expanded each time. If the value is not `0`, make sure that the size of the disk after expansion is no less than the recommended value. </li> <li>In SN mode, this field is `NULL`. </li></ul>   <main id="notice" type='explain'><h4>Note</h4><ul><li>This field is available starting with V4.4.0 in V4.4.x. </li><li>This field is available starting with V4.3.5 BP2 in V4.3.5. </li></ul></main>    |
