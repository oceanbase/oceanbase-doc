# V$OB_KV_CLIENT_INFO

<main id="notice" type='explain'>
<h4>Note</h4>
<p>This view is available starting with V4.3.4. </p>
</main>

## Purpose

In the sys tenant, the `V$OB_KV_CLIENT_INFO` view displays the configuration parameters of all OBKV tenant clients connected to the current node.

## Columns

| **Column**    | **Type**                              | **Nullable**  | **Description**        |
|----------------|--------------------------------------|--------------------|-----------------|
| client_id      | bigint                               | NO   | The client ID.                      |
| client_ip      | varchar:MAX_IP_ADDR_LENGTH           | NO   | The IP address of the client.                 |
| client_port    | bigint                               | NO   | The port number of the client.                     |
| svr_ip         | varchar:MAX_IP_ADDR_LENGTH           | NO   | The IP address of the server.              |
| svr_port       | bigint                               | NO   | The port number of the server.                  |
| tenant_id      | bigint                               | NO   | The tenant ID.                       |
| user_name      | varchar::OB_MAX_USER_NAME_LENGTH     | NO   | The username.                         |
| first_login_ts | timestamp(6)                         | NO   | The timestamp when the client first logged in.                  |
| last_login_ts  | timestamp(6)                         | NO   | The timestamp when the client last logged in.                    |
| client_info    | varchar:2048                         | NO   | The JSON string that describes the client information.           |

The `client_info` column stores a JSON string in the following format:

```json
{
  "client_id": 242153145,
  "runtime": {
    "rpc.execute.timeout": "3000",
    "rpc.operation.timeout": "10000",
    "runtime.max.wait": "3000",
    "runtime.retry.interval": "1",
    "runtime.retry.times": "1",
    "connection.max.expired.time": "8"
  },
  "log": {
    "slow.query.monitor.threshold": "10"
  },
  "route": {
    "metadata.refresh.interval": "60000",
    "continuous.failure.ceiling": "100",
    "server.address.caching.timeout": "3600000",
    "server.address.priority.timeout": "1800000",
    "table.entry.acquire.connect.timeout": "500",
    "table.entry.acquire.socket.timeout": "3000",
    "table.entry.refresh.interval.base": "100",
    "table.entry.refresh.interval.ceiling": "1600",
    "table.entry.refresh.try.times": "3"
  },
  "thread_pool": {
    "runtime.batch.executor": "false"
  }
}
```

The following table describes the parameters in the JSON string.

| **Parameter**                      | **Default Value**      |  **Description**                             |
|-------------------------------|---------------|---------------------------------------|
| metadata.refresh.interval     | 60000         | The time interval for refreshing the METADATA.               |
| rpc.execute.timeout           | 3000          | The socket timeout for executing an RPC request.         |
| rpc.operation.timeout         | 10000         | The timeout for executing an RPC request internally in OceanBase Database.    |
| runtime.continuous.failure.ceiling           | 100          | The maximum number of consecutive failures before the address of the TABLE is refreshed. |
| runtime.max.wait              | 3000          | The maximum timeout for a single execution. The request is retried within the timeout.         |
| runtime.retry.interval        | 1             | The time interval for retrying when an error occurs.                 |
| runtime.retry.times           | 1             |  The maximum number of retries for retryable errors.       |
| server.address.caching.timeout               | 3600000L          | The time for which the server address cache is valid.          |
| server.address.priority.timeout              | 1800000L          | The time for which the server address priority is valid.        |
| slow.query.monitor.threshold           | 10           | The threshold for the execution time of a slow operation that is recorded in the MONITOR log.          |
| table.entry.acquire.connect.timeout           | 500          | The maximum timeout for creating a connection for a refresh TABLE address request.          |
| table.entry.acquire.socket.timeout           | 3000          | The socket timeout for refreshing the TABLE address.          |
| table.entry.refresh.interval.base           | 100          | The base time interval for refreshing the TABLE address.          |
| table.entry.refresh.interval.ceiling           | 1600          | The maximum time interval for refreshing the TABLE address.          |
| table.entry.refresh.try.times           | 3          | The maximum number of attempts for refreshing the TABLE address.          |
| runtime.batch.executor           | false          | The thread pool for concurrent execution of batch requests.          |
| connection.max.expired.time           | 8          | The maximum time interval between client connection refreshes.          |
