# V$OB_TABLET_COMPACTION_PROGRESS

<main id="notice" type='explain'>
<h4>Note</h4>
<p>Introduced in V4.0.0. </p>
</main>

## Description

Displays the progress of a tablet-level major compaction.

## Field descriptions

|             Field              |      Type      | Nullable | Description |
|------------------------------|--------------|------------|--------|
| SVR_IP                       | varchar(46)  | NO         | The IP address of the server.                                                                                |
| SVR_PORT                     | bigint(20)   | NO         | The port number of the server.|
| TENANT_ID                    | bigint(20)   | NO         | The ID of the tenant. |
| TYPE                         | varchar(64)  | NO         | The type of compaction. Valid values are: <ul><li>`MDS_TABLE_MERGE`: The system metadata is persisted to disk in the SSTable format. </li> <li>`MAJOR_MERGE`: A major compaction at the tenant level. </li> <li>`MEDIUM_MERGE`: A major compaction at the partition level. </li> <li>`MINI_MERGE`: A mini compaction. It transforms MemTables into a mini SSTable. </li> <li>`MINOR_MERGE`: A minor compaction. It merges multiple mini SSTables into a new mini SSTable or a minor SSTable. </li> <li>`META_MAJOR_MERGE`: A special type of compaction. It synthesizes data from the start time to a specified point in time into a meta-major SSTable. The data format of the meta-major SSTable is the same as that of a major SSTable, but it does not contain multi-version data or uncommitted transactions. </li></ul>    |
| TABLE_ID                     | bigint(20)   | NO         | The ID of the primary table. |
