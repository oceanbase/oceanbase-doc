# GV$OB_LOCKS

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This view is available starting with V4.2.0. </p>
</main>

## Purpose

This view displays the locks held or requested by the current user on tables.

## Columns

| **Column** | **Type** | **Nullable** | **Description** |
| ---- | ---- | ---- | ---- |
| SVR_IP | varchar(46) | NO | The IP address of the OBServer node that holds or requests the lock. |
| SVR_PORT | bigint(20) | NO | The port number of the OBServer node that holds or requests the lock. |
| TENANT_ID | bigint(20) | NO | The ID of the tenant that holds or requests the lock. |
| TRANS_ID | bigint(20) | NO | The ID of the transaction that holds or requests the lock. |
| SESSION_ID | bigint(20)   | NO   |The ID of the session that holds or requests the lock<ul><li> In V4.3.x, this column is available starting with V4.3.2.<ul><li> In versions earlier than V4.3.5 BP2:<br> This column indicates the server session ID in all connection modes (direct mode or ODP mode). </li><li> In V4.3.5 BP2 and later versions:<ul><li> In direct mode:<br> This column indicates the server session ID. </li> <li> In ODP mode:<ul><li> If the <code>client_session_id_version</code> parameter is set to 2, this column indicates the client session ID. </li> <li> If <code>client_session_id_version</code> is set to 1, this column indicates the server session ID. </li></ul></li></ul></li></ul> </li><li> In V4.2.x, this column is available starting with V4.2.5. In all connection modes (direct mode or ODP mode), this column indicates the server session ID. </li></ul>     |
| TYPE | varchar(9) | NO | The lock type:<ul><li> TM: table lock</li><li> TX: transaction lock</li><li> TR: row lock</li></ul> |
| ID1 | bigint(20) | NO | The first lock identifier:<ul><li> TM: transaction ID</li><li> TX: transaction ID</li><li> TR: transaction ID</li></ul> |
| ID2 | bigint(20) | NO | The second lock identifier:<ul><li> TM: session ID (NULL for transaction external table locks) </li><li> TX: session ID </li><li> TR: session ID </li></ul> |
| ID3 | varchar(512) | NO | The third lock identifier:<ul><li> TM: TABLE_ID / TABLET_ID </li><li> TX: NULL </li><li> TR: TABLET_ID + rowkey </li></ul> <main id="notice" type='explain'><h4>Note</h4><p><ul><li> In V4.3.x, this column is available starting with V4.3.2. </li><li> In V4.2.x, this column is available starting with V4.2.5. </li></ul></p></main>|
| LMODE | varchar(4) | NO | The mode of the lock currently held:<ul><li> NONE: no lock is held </li><li> RS: ROW SHARE </li><li> RX: ROW EXCLUSIVE </li><li> S: SHARE </li><li> SRX: SHARE ROW EXCLUSIVE </li><li> X: EXCLUSIVE </li></ul> |
| REQUEST | varchar(8) | NO | The mode of the lock currently requested:<ul><li> NONE: no lock is requested </li><li> RS: ROW SHARE  </li><li> RX: ROW EXCLUSIVE  </li><li> S: SHARE  </li><li> SRX: SHARE ROW EXCLUSIVE  </li><li> X: EXCLUSIVE  </li></ul>|
| CTIME | bigint(20) | NO | The time for which the lock is held or the time for which the lock is being waited for, in microseconds. |
| BLOCK | bigint(1) | NO | Indicates whether the lock requested by the current transaction is held by another transaction:<ul><li> 0: the lock requested by the transaction is not held by another transaction, that is, the transaction holds the lock.  </li><li> 1: the lock requested by the transaction is held by another transaction, that is, the transaction is blocked. </li></ul>|

## Sample query

Query the locks held or requested by the current user on tables.

```shell
obclient [oceanbase]> SELECT * FROM oceanbase.GV$OB_LOCKS LIMIT 1\G
```

