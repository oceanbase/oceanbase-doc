# V$SQL_JOIN_FILTER

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This view is available starting with V4.2.0. </p>
</main>

## Purpose

This view dynamically displays the execution information of Join Filters for each tenant on the current OBServer node.

## Columns

| **Column** | **Type** | **Nullable** | **Description** |
| --- | --- | --- | --- |
| SVR_IP | varchar(46) | NO | Server IP address. |
| SVR_PORT | bigint(20) | NO | Server port number. |
| QC_SESSION_ID | bigint(0) | NO | The QC (Query Coordinator) session ID for the given parallel query cursor.<br>For V4.3.x versions:<ul><li> V4.3.5 BP2 and earlier versions:<br> In all connection modes (direct mode/ODP mode), this field indicates the Server Session ID.</li><li> V4.3.5 BP2 and later versions:<ul><li> In direct mode:<br> This field indicates the Server Session ID.</li> <li> In ODP mode:</li><ul><li> When the <code>client_session_id_version</code> parameter in ODP is set to 2, this field indicates the Client Session ID. </li> <li> When <code>client_session_id_version</code> is set to 1, this field indicates the Server Session ID.</li></ul></ul></li></ul> |
| QC_INSTANCE_ID | bigint(0) | NO | The QC (Query Coordinator) instance ID for the given parallel query cursor. |
| SQL_PLAN_HASH_VALUE | bigint(0) | NO | The hash value of the SQL plan for the given parallel query cursor. |
| FILTER_ID | bigint(20) | NO | The ID that identifies the join filter in the given cursor. This ID corresponds to the filter ID in the execution plan. |
| BITS_SET | bigint(0) | NO | The size of the bitmap (join bitmap) used in the BLOOM_FILTER. This field is only used for compatibility in the current version. |
| FILTERED | bigint(20) | NO | The number of rows processed by the join filter. |
| PROBED | bigint(20) | NO | The total number of rows in the right table that have passed the bitmap filter test, including both filtered and unfiltered rows. |
| ACTIVE | bigint(0) | NO | Indicates whether the filter is active (YES) or inactive (NO). |
| CON_ID | bigint(20) | NO | The ID of the container to which the data belongs. |
| TRACE_ID | varchar(64) | NO | The trace ID corresponding to the SQL statement. |

## Sample query

In the sys tenant, query the execution information of Join Filters for each tenant on the current OBServer node.

```shell
obclient [oceanbase]> SELECT * FROM oceanbase.V$SQL_JOIN_FILTER LIMIT 10;
```
