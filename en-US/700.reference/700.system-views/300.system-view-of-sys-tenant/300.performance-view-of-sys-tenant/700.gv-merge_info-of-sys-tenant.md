# GV$OB_MERGE_INFO

<main id="notice" type='explain'>
<h4>Note</h4>
<p>The view <code>GV$MERGE_INFO</code> was renamed to <code>GV$OB_MERGE_INFO</code> starting with V4.0.0. In V4.0.0 and later, you must use the new view name <code>GV$OB_MERGE_INFO</code> to query. Using the old view name <code>GV$MERGE_INFO</code> will result in an error. </p>
</main>

## Purpose

This view displays statistics about completed compactions in the OceanBase cluster.

## Columns

|       Column        |      Type       | Nullable |                                 Description                                  |
|-------------------|---------------|------------|-----------------------------------------------------------------------------------------------------|
| SVR_IP            | varchar(46)   | NO         | The IP address of the server.                                                           |
| SVR_PORT          | bigint(20)    | NO         | The port number of the server.                                                              |
| TENANT_ID         | bigint(20)    | NO         | The tenant ID.                                                               |
| LS_ID             | bigint(20)    | NO         | The ID of the log stream.                                                              |
| TABLET_ID         | bigint(20)    | NO         | The ID of the data tablet.                                                             |
| ACTION            | varchar(64)   | NO         | The compaction action. The value can be one of the following:<ul><li>`MDS_TABLE_MERGE`: persists system metadata in SSTable format to disk. </li> <li>`MAJOR_MERGE`: major compaction at the tenant level. </li> <li>`MEDIUM_MERGE`: major compaction at the partition level. </li> <li>`MINI_MERGE`: minor compaction, which converts a MemTable to a Mini SSTable. </li> <li>`MINOR_MERGE`: minor compaction, which combines multiple Mini SSTables into a new Mini SSTable or combines multiple Mini SSTables with one Minor SSTable into a new Minor SSTable. </li> <li>`META_MAJOR_MERGE`: major compaction at the tenant level, which combines data before a specified time point into a Meta Major SSTable. The Meta Major SSTable has the same data format as the Major SSTable and does not contain multi-version data or uncommitted transaction data. </li></ul>    |
| COMPACTION_SCN    | bigint(20) unsigned    | NO         | The compaction version number.                                                      |
| START_TIME        | timestamp(6)  | NO         | The start time of the compaction.                                                     |
| END_TIME          | timestamp(6)  | NO         | The end time of the compaction.                                                     |
| MACRO_BLOCK_COUNT | bigint(20)    | NO         | The total number of macroblocks in the compaction.                                                     |
| REUSE_PCT         | decimal(26,2) | NO         | The reuse rate of macroblocks in the compaction.                                                    |
| PARALLEL_DEGREE   | bigint(20)    | NO         | The parallelism of the compaction.                                                      |

## Sample query

Query the statistics about completed `MINI_MERGE` operations in the cluster as the sys tenant and return the first five records.

```shell
obclient [oceanbase]> SELECT * FROM oceanbase.GV$OB_MERGE_INFO WHERE ACTION='MINI_MERGE' LIMIT 5;
```
