# GV$OB_SHARED_STORAGE_QUOTA

<main id="notice" type='explain'>
<h4>Note</h4>
<p>This view is available starting with V4.3.4. </p>
</main>

## Purpose

This view displays the IO access resource information on all OBServer nodes.

## Columns

| Column     | Type          | Nullable | Description                                                        |
|-------------|---------------|----------------|-------------------------------------------------------------|
| SVR_IP      | varchar(46)   | NO   | The IP address of the OBServer node.     |
| SVR_PORT    | bigint(20)    | NO   | The port number of the OBServer node.     |
| ENDPOINT    | varchar(256)  | NO   | The endpoint of the shared storage. In Shared-Nothing (SN) mode, this field is empty.     |
| PATH        | varchar(1024) | NO   | The path of the object storage. In Shared-Nothing (SN) mode, it displays the local path.</br>The following types of paths are typically used: `local://`, `oss://`, `file://`, and `s3://`.   |
| CLASS_ID    | bigint(20)    | NO   | The ID used for tagging. The meaning of this field varies depending on the purpose of the object storage bucket:<ul><li>If the bucket is used for clog storage or data storage, this field is meaningless and its value is `0`. </li> <li>If the bucket is used for backup and restore, data import, and data export tasks, this field represents the tenant ID. </li></ul>      |
| TYPE        | varchar(32)   | NO   | The type of the metric. The following types are supported:<ul><li>`IPS`: Instructions per second</li> <li>`OPS`: Operations per second</li> <li>`IOPS`: Input/output operations per second</li> <li>`IBW`: Input bandwidth</li> <li>`OBW`: Output bandwidth</li> <li>`IOBW`: Input/output bandwidth</li> <li>`TAG`: The tag information set by the user</li></ul>     |
| REQUIREMENT | bigint(20)    | NO   | The required resources for the server.    |
| ASSIGN      | bigint(20)    | NO   | The upper limits of the resources specified by the throttling algorithm.     |

## Sample query

In the sys tenant, query the requested and limited quotas of object storage metrics on all OBServer nodes for scenarios such as clog storage and data storage. For scenarios such as backup and restore, data import, and data export, query the requested and limited quotas of object storage metrics on all OBServer nodes for all tenants.

```shell
obclient> SELECT * FROM oceanbase.GV$OB_SHARED_STORAGE_QUOTA;
```
