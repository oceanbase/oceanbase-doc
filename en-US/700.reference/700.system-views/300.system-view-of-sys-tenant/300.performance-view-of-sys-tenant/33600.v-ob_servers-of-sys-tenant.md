# V$OB_SERVERS

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This view is available starting with V4.0.0. </p>
</main>

## Purpose

This view displays the information of the current OBServer node.

## Columns

|          Column           |      Type      | Nullable |              Description              |
|-------------------------|--------------|------------|--------------------------------------------------------------|
| SVR_IP                  | varchar(46)  | NO         | The IP address of the server.                    |
| SVR_PORT                | bigint(20)   | NO         | The port number of the server.                       |
| ZONE                    | varchar(128) | NO         | The zone name.                      |
| SQL_PORT                | bigint(20)   | NO         | The SQL port.                       |
| CPU_CAPACITY            | bigint(20)   | NO         | The total CPU capacity of the node.        |
| CPU_CAPACITY_MAX        | double       | NO         | The oversold value of the total CPU capacity of the node. It is controlled by the `resource_hard_limit` parameter: `CPU_CAPACITY_MAX = CPU_CAPACITY * resource_hard_limit`                                                                   |
| CPU_ASSIGNED            | double       | NO         | The total number of CPU cores already allocated to the OBServer node. It is the sum of the `MIN_CPU` specifications of all units on the OBServer node. Constraint: `CPU_ASSIGNED <= CPU_CAPACITY`                |
| CPU_ASSIGNED_MAX        | double       | NO         | The upper limit of the CPU cores already allocated to the OBServer node. It is the sum of the `MAX_CPU` specifications of all units on the OBServer node. Constraint: `CPU_ASSIGNED_MAX <= CPU_CAPACITY_MAX`       |
| MEM_CAPACITY            | bigint(20)   | NO         | The total amount of memory available for allocation to tenants on the OBServer node. The value is `memory_limit - system_memory`, and the unit is bytes.           |
| MEM_ASSIGNED            | bigint(20)   | NO         | The amount of memory already allocated to the OBServer node. It is the sum of the `MEMORY_SIZE` specifications of all units on the OBServer node, and the unit is bytes. Constraint: `MEM_ASSIGNED <= MEM_CAPACITY`                 |
| LOG_DISK_CAPACITY      | bigint(20)   | NO         | The total size of the log disk space, in bytes.                      |
| LOG_DISK_ASSIGNED      | bigint(20)   | NO         | The size of the log disk space already allocated. It is the sum of the `LOG_DISK_SIZE` specifications of all units on the OBServer node, and the unit is bytes.         |
| LOG_DISK_IN_USE         | bigint(20)   | NO         | The size of the log disk space already used, in bytes.                                                                              |
| DATA_DISK_CAPACITY      | bigint(20)   | NO         | <ul><li>In Shared-Storage (SS) mode, it represents the total size of the local cache space on the OBServer node. It is the upper limit of the sum of the `DATA_DISK_SIZE` specifications of all units on the OBServer node, and the unit is bytes.</li> <li>In Shared-Nothing (SN) mode, it represents the total size of the data disk space on the OBServer node, in bytes. </li></ul>      |
| DATA_DISK_ASSIGNED      | bigint(20)   | YES        | <ul><li>Represents the size of the local cache space already allocated to units on the OBServer node. It is the sum of the `DATA_DISK_SIZE` specifications of all units on the OBServer node, and the unit is bytes. This field is applicable only in SS mode.</li> <li>In SN mode, this field is `NULL`, indicating that it is undefined and allows competition for disk space from other tenants.</li></ul><main id="notice" type='explain'><h4>Note</h4><p>This field is available starting with V4.3.3. </p></main>    |
| DATA_DISK_IN_USE        | bigint(20)   | NO         | <ul><li>In SS mode, it represents the size of the local cache space already used on the OBServer node. It is the sum of the `DATA_DISK_IN_USE` specifications of all units on the OBServer node, and the unit is bytes.</li> <li>In SN mode, it represents the size of the data disk space already used on the OBServer node, in bytes. </li></ul>    |
| DATA_DISK_HEALTH_STATUS | varchar(20)  | NO         | The health status of the data disk:<ul><li> `NORMAL`: normal status </li><li>`WARNING`: abnormal status </li><li>`ERROR`: error status</li></ul>    |
| MEMORY_LIMIT            | bigint(20)  | NO         | The total amount of memory available on the OBServer node, in bytes.    |
| DATA_DISK_ALLOCATED     | bigint(20)   | NO         | <ul><li>In SN mode, it represents the size of the data disk space already allocated on the OBServer node, in bytes.</li> <li>In SS mode, this value is equal to `DATA_DISK_CAPACITY`, indicating that the entire space is available.</li></ul><main id="notice" type='explain'><h4>Note</h4><p>This field is available starting with V4.2.0. </p></main>    |
| DATA_DISK_ABNORMAL_TIME | timestamp(6) | NO         | The last time when the data disk experienced an abnormality ( `WARNING` or `ERROR` status).                                                                              |
| SSL_CERT_EXPIRED_TIME   | timestamp(6) | NO | Records the expiration time of the SSL certificate used by the current OBServer node when SSL is enabled, along with the UTC time, in microseconds. |
| SS_DATA_DISK_OPERATION_SUGGESTED | varchar(32)| YES  | <ul><li>SS mode: the recommended operation for scaling the local cache disk. Valid values: <ul><li>`NONE`: no operation</li> <li>`EXPAND`: expand</li> <li>`SHRINK`: shrink</li> </ul></li> <li>SN mode: the value of this column is `NULL`. </li></ul>   <main id="notice" type='explain'><h4>Note</h4><ul><li>For V4.4.x, this column is available starting with V4.4.0. </li><li>For V4.3.5, this column is available starting with V4.3.5 BP2. </li></ul></main>     |
| SS_DATA_DISK_SIZE_SUGGESTED      | bigint(20) | YES  | <ul><li>SS mode: the recommended size of the local disk, in bytes. If the value is `0`, you can decide the size of the disk to be expanded each time. If the value is not `0`, the size of the disk after expansion must be no less than the recommended value. </li> <li>SN mode: the value of this column is `NULL`. </li></ul>   <main id="notice" type='explain'><h4>Note</h4><ul><li>For V4.4.x, this column is available starting with V4.4.0. </li><li>For V4.3.5, this column is available starting with V4.3.5 BP2. </li></ul></main>     |
