# GV$OB_TABLET_COMPACTION_HISTORY

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This view is introduced since OceanBase Database V4.0.0. </p>
</main>

## Purpose

The `GV$OB_TABLET_COMPACTION_HISTORY` view displays historical information about tablet-level compactions.

## Columns

| Column |  Type  | Nullable? | Description |
|--------------------------------------|--------------|----------------|--------|
| SVR_IP    | varchar(46)    | NO   | The IP address of the server.    |
| SVR_PORT    | bigint(20)    | NO   | The port of the server.    |
| TENANT_ID    | bigint(20)    | NO   | The ID of the tenant.    |
| LS_ID    | bigint(20)    | NO   | The ID of the log stream.    |
| TABLET_ID    | bigint(20)    | NO   | The ID of the data fragment.    |
| TYPE    | varchar(64)    | NO   | The type of compaction. Valid values include:<ul><li>`MDS_TABLE_MERGE`: the system metadata is persisted to disk in the format of SSTable. </li> <li>`MAJOR_MERGE`: tenant-level major compaction. </li> <li>`MEDIUM_MERGE`: partition-level major compaction. </li> <li>`MINI_MERGE`: mini compaction. The MemTable is converted into a Mini SSTable. </li> <li>`MINOR_MERGE`: minor compaction. Multiple Mini SSTables or multiple Mini SSTables and a Minor SSTable are combined into a Minor SSTable. </li> <li>`META_MAJOR_MERGE`: a special type of compaction. It combines data before a specified time point into a Meta Major SSTable. The data format of the Meta Major SSTable is the same as that of a Major SSTable. It does not contain multi-version data or uncommitted transaction data. </li></ul>   |
| COMPACTION_SCN    | bigint(20) unsigned    | NO   | The version information of the compaction.    |
| START_TIME    | timestamp(6)    | NO   | The start time.    |
| FINISH_TIME    | timestamp(6)    | NO   | The end time.    |
| TASK_ID    | varchar(64)    | NO   | The ID of the task trace.    |
| OCCUPY_SIZE    | bigint(20)    | NO   | The amount of data.    |
| MACRO_BLOCK_COUNT    | bigint(20)    | NO   | The number of macro blocks.    |
| MULTIPLEXED_MACRO_BLOCK_COUNT    | bigint(20)    | NO   | The number of reused macro blocks.    |
| NEW_MICRO_COUNT_IN_NEW_MACRO    | bigint(20)    | NO   | The number of new micro blocks in the new macro block.    |
| MULTIPLEXED_MICRO_COUNT_IN_NEW_MACRO    | bigint(20)    | NO   | The number of reused micro blocks in the new macro block.    |
| TOTAL_ROW_COUNT    | bigint(20)    | NO   | The total number of rows.    |
| INCREMENTAL_ROW_COUNT    | bigint(20)    | NO   | The number of new rows.    |
| COMPRESSION_RATIO    | double    | NO   | The compression ratio of the new data = the size of the compressed data after compression / the size of the data before compression.    |
| NEW_FLUSH_DATA_RATE    | bigint(20)    | NO   | The output speed of the new data, in KB/s.    |
| PROGRESSIVE_COMPACTION_ROUND    | bigint(20)    | NO   | The current round of progressive compaction (if full compaction, the value is -1).    |
| PROGRESSIVE_COMPACTION_NUM    | bigint(20)    | NO   | The total number of rounds of progressive compaction.    |
| PARALLEL_DEGREE    | bigint(20)    | NO   | The degree of parallelism.    |
| PARALLEL_INFO    | varchar(512)    | NO   | Information about parallel tasks, including the statistics of the data scanned, runtime, and data output (min, max, and avg) by parallel tasks.    |
| PARTICIPANT_TABLE    | varchar(512)    | NO   | Information about the tables that participated in the compaction.    |
| MACRO_ID_LIST    | varchar(256)    | NO   | The list of macro blocks. If the macro block list is too long, it is not displayed.    |
| COMMENTS    | varchar(256)    | NO   | Historical information about failed compactions and the duration of the current compaction.    |
| START_CG_ID                     | bigint(20)   | NO   | The start ID of the column group. <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.0. </p></main>    |
| END_CG_ID                       | bigint(20)   | NO   | The end ID of the column group. <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.0. </p></main>   |
| KEPT_SNAPSHOT                   | varchar(128) | NO   | The information about the multi-version snapshot retained during the compaction. <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.0. </p></main>    |
| MERGE_LEVEL                     | varchar(64)  | NO   | Whether major compaction or microblock reuse is used during the compaction. <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.0. </p></main>    |
| EXEC_MODE                       | varchar(64)  | NO   | The mode of the compaction trace:<ul><li>`EXEC_MODE_LOCAL`: local mode, where macro blocks are output to the local disk. </li> <li>`EXEC_MODE_VALIDATE`: shared mode, where only checksums are calculated and macro blocks are not output. This mode is not supported in the current version. </li> <li>`EXEC_MODE_OUTPUT`: shared mode, where macro blocks are output to shared storage. This mode is not supported in the current version. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.3. </p></main> |
| IS_FULL_MERGE                   | varchar(5)   | NO   | Whether the compaction is a full compaction. <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.3. </p></main> |
| IO_COST_TIME_PERCENTAGE         | bigint(20)   | NO   | The percentage of I/O time in the compaction time. <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.3. </p></main> |
| MERGE_REASON                    | varchar(32)  | NO   | The reason for initiating the compaction. Valid values include:<ul><li>`LOAD_DATA_SCENE`: data loading scenario. </li> <li>`TOMBSTONE_SCENE`: tombstone scenario. </li> <li>`INEFFICIENT_QUERY`: slow query scenario. </li> <li>`FREQUENT_WRITE`: frequent write scenario. </li> <li>`TENANT_MAJOR`: tenant-level major compaction. </li> <li>`USER_REQUEST`: user-initiated major compaction. </li> <li>`REBUILD_COLUMN_GROUP`: row-to-column scenario. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.3. </p></main> |
| BASE_MAJOR_STATUS               | varchar(64)  | NO   | The type of the baseline Major SSTable:<ul><li>`COL_WITH_ALL`: the table is defined as a hybrid rowstore-columnstore table and the baseline data is hybrid rowstore-columnstore. </li> <li>`COL_ONLY_ALL`: the table is defined as a hybrid rowstore-columnstore table and the baseline data is adaptive rowstore. </li> <li>`PURE_COL`: the table is defined as a columnstore table and the baseline data is columnstore. </li> <li>`PURE_COL_ONLY_ALL`: the table is defined as a columnstore table and the baseline data is adaptive rowstore. </li> <li>`ROW_STORE_MAJOR`: rowstore table. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.3. </p></main>|
| CO_MERGE_TYPE                   | varchar(64)  | NO   | The columnstore major compaction type:<ul><li>`BUILD_COLUMN_STORE_MERGE`: major compaction to columnstore. </li> <li>`BUILD_ROW_STORE_MERGE`: major compaction to rowstore. </li> <li>`USE_RS_BUILD_SCHEMA_MATCH_MERGE`: major compaction to the storage type that matches the schema of the rowstore table. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p>This field was introduced in V4.3.3. </p></main> |

```shell
obclient [oceanbase]> SELECT * FROM oceanbase.GV$OB_TABLET_COMPACTION_HISTORY LIMIT 1\G
```
