# GV$SQL_JOIN_FILTER

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This view is available starting with V4.2.0. </p>
</main>

## Purpose

This view dynamically displays the execution information of join filters for each tenant on all OBServer nodes.

## Columns

| **Column** | **Type** | **Nullable** | **Description** |
| --- | --- | --- | --- |
| SVR_IP | varchar(46) | NO | The IP address of the server. |
| SVR_PORT | bigint(20) | NO | The port number of the server. |
| QC_SESSION_ID | bigint(0) | NO | The Query Coordinator (QC) session ID of the cursor for the parallel query. <br>For V4.3.x: <ul><li> For versions earlier than V4.3.5 BP2: <br> This field indicates the server session ID in all connection modes (direct mode and ODP mode). </li><li> For V4.3.5 BP2 and later: <ul><li> In direct mode: <br> This field indicates the server session ID. </li> <li> In ODP mode: </li><ul><li> If the <code>client_session_id_version</code> parameter in ODP is set to 2, this field indicates the client session ID. </li> <li> If <code>client_session_id_version</code> is set to 1, this field indicates the server session ID. </li></ul></ul></li></ul> |
| QC_INSTANCE_ID | bigint(0) | NO | The Query Coordinator (QC) instance ID of the cursor for the parallel query. |
| SQL_PLAN_HASH_VALUE | bigint(0) | NO | The hash value of the SQL plan of the cursor for the parallel query. |
| FILTER_ID | bigint(20) | NO | The ID of the join filter in the cursor. This ID corresponds to the filter ID in the execution plan. |
| BITS_SET | bigint(0) | NO | The size of the bitmap (join bitmap) used in the BLOOM_FILTER. This field is only used for compatibility in the current version. |
| FILTERED | bigint(20) | NO | The number of rows processed by the join filter. |
| PROBED | bigint(20) | NO | The total number of rows in the right table that have passed the bitmap filter test. This includes both filtered and unfiltered rows. |
| ACTIVE | bigint(0) | NO | Indicates whether the filter is active (YES) or inactive (NO). |
| CON_ID | bigint(20) | NO | The ID of the container to which the data belongs. |
| TRACE_ID | varchar(64) | NO | The trace ID corresponding to the SQL statement. |

## Sample query

In the sys tenant, query the execution information of join filters for each tenant on all OBServer nodes.

```shell
obclient [oceanbase]> SELECT * FROM oceanbase.GV$SQL_JOIN_FILTER LIMIT 10;
```
