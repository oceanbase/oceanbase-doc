# oceanbase.DBA_MVIEWS

<main id="notice" type='explain'>
<h4>Note</h4>
<p>This view is available starting with V4.3.0. </p>
</main>

## Purpose

The `DBA_MVIEWS` view displays information about all materialized views.

## Columns

| **Column** | **Type** | **Nullable** | **Description** |
| --- | --- | --- | --- |
| OWNER | varchar(128) | NO | The name of the owner of the materialized view. |
| MVIEW_NAME | varchar(128) | NO | The name of the materialized view. |
| CONTAINER_NAME | varchar(128) | NO | The name of the container table of the materialized view. |
| QUERY | longtext | NO | The query that defines the materialized view. |
| QUERY_LEN | bigint(20) | NO | The length of the query, in bytes. |

| LAST_REFRESH_TYPE | varchar(8) | NO | The method used for the most recent refresh. <ul><li>COMPLETE: A full refresh.  </li><li>FAST: An incremental refresh. </li><li>NA: The materialized view has not been refreshed yet (for example, if it was created with a delay). </li></ul>|

After a full refresh, the STALENESS value of this view will become FRESH. </li><li>NEEDS_COMPILE: Some objects that the materialized view depends on have changed. Use the ALTER MATERIALIZED VIEW...COMPILE statement to verify the materialized view and calculate the staleness. </li><li>STALE: The materialized view is outdated because one or more of its master objects have changed. If the materialized view was previously FRESH and has become STALE, it is a read-consistent view of the previous state of its master objects. </li><li>UNDEFINED: The materialized view has a remote master. The concept of staleness is not defined for such materialized views. </li><li>UNKNOWN: Whether the materialized view is a read-consistent view of its master object at any given time. </li><li>UNUSABLE: The materialized view is not a read-consistent view of its master object at any given time. </li></ul><main id="notice" type='explain'> <h4>Note</h4><p>This column is only compatible and defaults to NULL. </p></main> |
