# oceanbase.CDB_OB_TABLEGROUPS

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This view is available starting with V4.0.0. </p>
</main>

## Overview

The system tenant displays the meta information of table groups for all tenants, primarily showing the partition information of the table groups.

<main id="notice" type='explain'>
<h4>Note</h4>
<p>Starting from V4.2.0, the partition attribute fields in this view will no longer be meaningful and are uniformly displayed as <code>NONE</code> or </code>NULL</code>.</p>
</main>

## Columns

| Field Name | Type | Whether can be NULL | Description |
| --------------------------- | -------------- | ------------ | -------------------------------------------------------------------------------------------------------- |
| TENANT_ID | bigint(20) | NO | Tenant ID |
| TABLEGROUP_NAME | varchar(128) | NO | Table group name |
| PARTITIONING_TYPE | varchar(13) | NO | Partition type of a partitioned table group's partition:<ul><li>`NONE`: Non-partitioned table group   </li><li>`HASH`: HASH partitioning (single partitioning key)   </li><li>`KEY`: KEY partitioning   </li><li>`RANGE`: RANGE partitioning (single partitioning key)   </li><li>`RANGE COLUMNS`: RANGE COLUMNS partitioning   </li><li>`LIST`: LIST partitioning (single partitioning key)   </li><li>`LIST COLUMNS`: LIST COLUMNS partition   </li><li>`UNKNOWN`: Exception type</li></ul><main id="notice" type='explain'><h4>Note</h4><p>Starting from V4.2.0, the value of this field is <code>NULL</code>.</p></main> |
| SUBPARTITIONING_TYPE | varchar(13) | NO | Partition type of a subpartition in a partitioned table group:<ul><li>`NONE`: non-partitioned table groups, partitioned table groups   </li><li>`HASH`: HASH partitioning (single partitioning key)   </li><li>`KEY`: KEY partitioning   </li><li>`RANGE`: RANGE partitioning (single partitioning key)   </li><li>`RANGE COLUMNS`: RANGE COLUMNS partitioning   </li><li>`LIST`: LIST partitioning (single partitioning key)   </li><li>`LIST COLUMNS`: LIST COLUMNS partition   </li><li>`UNKNOWN`: Exception type.</li></ul><main id="notice" type='explain'><h4>Note</h4><p>This field is <code>NULL</code> starting from V4.2.0.</p></main> |
| PARTITION_COUNT | bigint(20) | NO | The number of partitions in a partitioned table group. For a non-partitioned table group, this value is`NULL` |
| DEF_SUBPARTITION_COUNT | bigint(0) | NO | The number of partitions in the subpartition template of a partitioned table group. For a table group without a defined subpartition template, this value is`NULL` |
| PARTITIONING_KEY_COUNT | bigint(20) | NO | The number of partitioning keys for a partitioned table group. For a non-partitioned table group, this value is`NULL` |
| SUBPARTITIONING_KEY_COUNT | bigint(20) | NO | The number of partitioning keys for a subpartitioned table group. For a non-subpartitioned table group, this value is`NULL` |
| SHARDING | varchar(10) | NO | The SHARDING attribute of the table group. Valid values: <ul><li>`NONE`: For tables in this table group, all partitions of all tables within the group are placed on the same server, and there are no restrictions on which tables can join the group.</li> <li>`PARTITION`: For tables in the table group with this attribute, the data of each table is scattered by its partitions. For a subpartitioned table, all subpartitions under a partition are aggregated together.</li> <li>`ADAPTIVE`: For tables in the table group with this attribute, the data of each table in the group is scattered in an adaptive manner. That is, if a table in the table group is a partitioned table, its data is scattered by partitions; if a table in the table group is a subpartitioned table, its data is scattered by subpartitions within each partition.</li></ul>  <main id="notice" type='explain'><h4>Note</h4><p>This field is available starting with V4.2.0.</p></main> |

## Sample query

1. Create a table group named `tblgroup1`.

    ```shell
    obclient [test]> CREATE TABLEGROUP tblgroup1 SHARDING = 'PARTITION';
    ```

2. Check the SHARDING attribute of the table group `tblgroup1`.

    ```shell
    obclient [test]> SELECT TABLEGROUP_NAME, SHARDING FROM oceanbase.CDB_OB_TABLEGROUPS WHERE tablegroup_name = 'tblgroup1';
    ```

    The query result is as follows:

    ```shell
    +-----------------+-----------+
    | TABLEGROUP_NAME | SHARDING  |
    +-----------------+-----------+
    | tblgroup1       | PARTITION |
    +-----------------+-----------+
    1 row in set
    ```
