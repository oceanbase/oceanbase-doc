# oceanbase.DBA_OB_DEADLOCK_EVENT_HISTORY

## Purpose
The `oceanbase.DBA_OB_DEADLOCK_EVENT_HISTORY` view displays the history of deadlock events. You can query this view from a user tenant for the history of deadlock events of the current tenant.
<main id="notice" type='explain'>
<h4>Note</h4>

<p>This view is introduced since OceanBase Database V4.0.0. </p>

The view `DBA_OB_DEADLOCK_EVENT_HISTORY` displays the history of deadlock events in the current tenant.

## Columns

| Column | Type | Nullable? | Description |
| ------- | ------ | ------ | ------ |
| EVENT_ID       | bigint(20) unsigned | NO   | The number assigned to the deadlock event.     |
| SVR_IP         | varchar(46)         | NO   | The IP address of the node involved in the deadlock event.     |
| SVR_PORT       | bigint(20) unsigned | NO   | The port number of the nodes involved in the deadlock event.     |
| DETECTOR_ID    | bigint(20) unsigned | NO   | ID of the node (within a process) involved in this deadlock event     |
| REPORT_TIME    | timestamp(6)        | NO   | The timestamp when the deadlock is reported (based on the reporting server's timestamp).      |
| CYCLE_IDX      | bigint(20)          | NO   | The node's ID in the ring     |
| CYCLE_SIZE     | bigint(20)          | NO   | The number of nodes involved in the deadlock event.     |
| ROLE           | longtext            | NO   | The role of the node in the deadlock event:<li>witness<li>victim     |
| PRIORITY_LEVEL | longtext            | NO   | A description of the priority level of the node, with options:<li>extreme-low<li>low<li>normal<li>high<li>extreme-high    |
| PRIORITY       | bigint(20) unsigned | NO   | The priority value of the node. When priorities are the same, the node with the lowest priority value will be eliminated.     |
| CREATE_TIME    | timestamp(6)        | NO   | The time when the node was created     |
| START_DELAY_US | bigint(20) unsigned | NO   | The number of microseconds between the creation of this node and when it begins probing for deadlocks.     |
| MODULE         | longtext            | NO   | The module to which the node belongs, with a fixed value of transaction.     |
| VISITOR        | longtext            | NO   | The resource visitor of the current node. The format is `{session_id:$1}:{txid:$2}`. In this format, `$1` and `$2` are digits.     |
| OBJECT         | longtext            | NO   | The resource that the node wants to acquire. This field stores the row's primary key in the {addr:"$1:$2"}:{ls:$3}:{tablet:$4}:{row_key:{$5}} format, where<ul><li><code>\$1</code> is the IP address. </li><li><code>\$2</code> is the port number. Together with <code>\$1</code>, it specifies the address of the process where the conflict occurs. </li><li><code>\$3</code> is the log stream where the conflict occurs. </li><li><code>\$4</code> is the tablet where the conflict occurs. </li><li><code>\$5</code> is the string representation of the row lock's primary key. </li></ul>     |
| EXTRA_NAME1    | longtext            | YES  | The name of the additional information 1 that the parent wishes to add to the deadlock reporting event, in the format `wait_sql`. |
| EXTRA_VALUE1   | longtext            | YES  | SQL statement currently being executed when the deadlock occurs.     |
| EXTRA_NAME2    | longtext            | YES  | The second extra name for information to be added to the deadlock reporting event from the upper layer, with a format of `hold_sql_request_time`     |
| EXTRA_VALUE2   | longtext            | YES  | The request time for the locking statement     |
| EXTRA_NAME3    | longtext            | YES  | The name of the additional information to be added to the deadlock report event by the upper layer, the format is `hold_sql`    |
| EXTRA_VALUE3   | longtext            | YES  | the SQL statement corresponding to the Object of the row record with `cycle_idx - 1`     |

## Sample query

Queries all historical deadlock events of the current tenant.

```shell
obclient [oceanbase]> SELECT * FROM oceanbase.DBA_OB_DEADLOCK_EVENT_HISTORY LIMIT 10;
```
