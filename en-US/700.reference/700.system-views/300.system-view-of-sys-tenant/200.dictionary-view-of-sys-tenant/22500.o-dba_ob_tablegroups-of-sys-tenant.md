# oceanbase.DBA_OB_TABLEGROUPS

<main id="notice" type='explain'>
<h4>Note</h4>
<p>This view is available starting with V4.0.0. </p>
</main>

## Purpose

This view displays the metadata of a table group, including the partition information of the table group.

<main id="notice" type='explain'>
<h4>Note</h4>
<p>Starting from V4.2.0, the partition attribute fields in this view will be displayed as <code>NONE</code> or </code>NULL</code>. </p>
</main>

## Columns

|           Column            |      Type      | Nullable |      Description      |
|---------------------------|--------------|------------|--------------------------------------------------------------------------------------------------------|
| TABLEGROUP_NAME           | varchar(128) | NO         | The name of the table group.          |
| PARTITIONING_TYPE         | varchar(13)  | NO         | The partition type of the primary partition of the table group. Valid values: <ul><li>`NONE`: the table group is not partitioned.   </li><li> `HASH`: the table group is HASH-partitioned (single partition key).   </li><li> `KEY`: the table group is KEY-partitioned.   </li><li> `RANGE`: the table group is RANGE-partitioned (single partition key).   </li><li> `RANGE COLUMNS`: the table group is RANGE COLUMNS-partitioned.   </li><li> `LIST`: the table group is LIST-partitioned (single partition key).   </li><li> `LIST COLUMNS`: the table group is LIST COLUMNS-partitioned.   </li><li> `UNKNOWN`: the partition type is invalid. </li></ul> <main id="notice" type='explain'><h4>Note</h4><p>Starting from V4.2.0, this field is set to <code>NULL</code>. </p></main>         |
| SUBPARTITIONING_TYPE      | varchar(13)  | NO         | The partition type of the subpartition of the table group. Valid values: <ul><li>`NONE`: the table group is not partitioned.   </li><li> `HASH`: the table group is HASH-partitioned (single partition key).   </li><li> `KEY`: the table group is KEY-partitioned.   </li><li> `RANGE`: the table group is RANGE-partitioned (single partition key).   </li><li> `RANGE COLUMNS`: the table group is RANGE COLUMNS-partitioned.   </li><li> `LIST`: the table group is LIST-partitioned (single partition key).   </li><li> `LIST COLUMNS`: the table group is LIST COLUMNS-partitioned.   </li><li> `UNKNOWN`: the partition type is invalid. </li></ul><main id="notice" type='explain'><h4>Note</h4><p>Starting from V4.2.0, this field is set to <code>NULL</code>. </p></main>    |
| PARTITION_COUNT           | bigint(20)   | NO         | This field is set to `NULL`.            |
| DEF_SUBPARTITION_COUNT    | bigint(0)    | NO         | This field is set to `NULL`. |
| PARTITIONING_KEY_COUNT    | bigint(20)   | NO         | This field is set to `NULL`.         |
| SUBPARTITIONING_KEY_COUNT | bigint(20)   | NO         | This field is set to `NULL`.       |
| SHARDING                  | varchar(20)  | NO         | The SHARDING attribute of the table group. Valid values: <ul><li>`NONE`: For a table group with this attribute, all partitions of all tables in the table group are aggregated on the same server, and no restrictions are imposed on tables added to the table group. </li> <li>`PARTITION`: For a table group with this attribute, the data of each table in the table group is distributed across primary partitions. For a table group with subpartitions, all subpartitions under each primary partition are aggregated. </li> <li>`ADAPTIVE`: For a table group with this attribute, the data of each table in the table group is distributed in an adaptive manner. Specifically, if the tables in the table group are primary-partitioned, the data is distributed across primary partitions. If the tables in the table group are subpartitioned, the data is distributed across subpartitions under each primary partition. </li></ul>  <main id="notice" type='explain'><h4>Note</h4><p>This field is available starting from V4.2.0. </p></main> |

## Sample query

1. Create a table group named `tblgroup1`.

   ```shell
   obclient [test]> CREATE TABLEGROUP tblgroup1 SHARDING = 'PARTITION';
   ```

2. Query the SHARDING attribute of the table group `tblgroup1`.

   ```shell
   obclient [test]> SELECT TABLEGROUP_NAME, SHARDING FROM oceanbase.DBA_OB_TABLEGROUPS WHERE tablegroup_name = 'tblgroup1';
   ```

   The query result is as follows:

   ```shell
   +-----------------+-----------+
   | TABLEGROUP_NAME | SHARDING  |
   +-----------------+-----------+
   | tblgroup1       | PARTITION |
   +-----------------+-----------+
   1 row in set
   ```
