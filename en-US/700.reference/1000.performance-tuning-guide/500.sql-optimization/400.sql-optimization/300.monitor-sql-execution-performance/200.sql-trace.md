# SQL Trace

SQL Trace (`SHOW TRACE`) is a performance analysis tool provided by OceanBase Database. It interactively displays the trace of the previously executed SQL statement, including the call chain and the time consumed at each stage, to facilitate performance analysis and tuning.

## Purpose of SQL Trace

### Performance tuning

* Complex query optimization: When SQL execution is slow, tracing can quickly identify issues (such as full table scans or improper `JOIN` order).
* Resource contention analysis: Identify latency-causing problems such as lock waits and concurrency conflicts.
* Index effectiveness validation: Determine whether a query hits an index and whether redundant indexes exist.

### Problem diagnosis

* Slow query location: Use `ELAPSE_TIME` to find the subtask with the longest duration.
* Missing index: Abnormally high `inner_execute_read` time may indicate that an index is not being used.
* Distributed task exception: Check whether the time spent on `do_local_das_task` is balanced, to avoid single-point performance bottlenecks.

### System stability assurance

* Preventive maintenance: Regularly trace key SQL statements to proactively identify potential performance risks.
* Fault review: When an exception occurs in the production environment, use trace logs to quickly reproduce the issue.

## Use SQL Trace

The `SHOW TRACE` feature is disabled by default and can be controlled by the [ob_enable_show_trace](../../../../800.configuration-items-and-system-variables/200.system-variable/400.session-system-variable/500.ob_enable_show_trace-session.md) session variable.

### Procedure

#### Step 1: Enable SQL Trace for the current session

**Example:**

```sql
SET ob_enable_show_trace = 1;
```

#### Step 2: Execute the target SQL statement

**Example:**

1. Create table `t1`.

   ```sql
   CREATE TABLE t1(c1 INT, c2 INT, c3 INT);
   ```

2. Insert data into the table.

   ```sql
   INSERT INTO t1 VALUES(1,1,1),(2,2,2);
   ```

3. Query the data in table `t1`.

   ```sql
   SELECT/*+PARALLEL(2)*/ COUNT(*) FROM t1;
   ```

   The result is as follows:

   ```shell
   +----------+
   | COUNT(*) |
   +----------+
   |        2 |
   +----------+
   1 row in set
   ```

#### Step 3: View the trace information

Use the `SHOW TRACE;` statement to display the trace information of the last SQL statement.

**Example:**

```sql
SHOW TRACE;
```

**Key columns:**

| **Column** | **Description** |
|-------------|------|
| OPERATION | The phase of the SQL execution, such as `parse`, `optimize`, or `do_local_das_task`.|
| START_TIME | The start time of the phase, which can be used to analyze the timeline.|
| ELAPSE_TIME | The time consumed in the phase, in microseconds (µs). This column is used to locate performance bottlenecks.|
