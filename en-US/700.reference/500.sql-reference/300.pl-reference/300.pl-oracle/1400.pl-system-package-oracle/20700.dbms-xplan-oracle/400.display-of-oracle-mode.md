# DISPLAY

The `DISPLAY` function is used to query and format historical `EXPLAIN` plans.

  <main id="notice">
  <h4>Applicability</h4>
  <p>Available from V4.2.5 of the Community Edition. </p>
  </main>

## Syntax

```sql
TYPE DBMS_XPLAN_TYPE_TABLE IS TABLE OF VARCHAR2(4000);

DBMS_XPLAN.DISPLAY(format VARCHAR2 DEFAULT 'TYPICAL',
                  statement_id VARCHAR2 DEFAULT null,
                  table_name   VARCHAR2 DEFAULT 'PLAN_TABLE',
                  filter_preds VARCHAR2 DEFAULT null)
RETURN DBMS_XPLAN_TYPE_TABLE;
```

## Parameters

| Parameter | Description |
| --- | --- |
| format | Specifies the plan format. Valid values are as follows:<ul><li>`'BASIC'`: displays basic information, such as operator ID, operator name, operator comment, and expression information.</li><li>`'TYPICAL'`: displays typical information, such as operator ID, operator name, operator comment, optimizer-estimated output rows, optimizer-estimated execution time, and expression information. If the plan has been executed, it also displays the actual feedback information, such as actual rows and cost.</li><li>`'ALL'`: displays comprehensive information, such as operator ID, operator name, operator comment, optimizer-estimated output rows, optimizer-estimated execution time, expression information, effective hints, query block name trace information, outline information, base table optimization information, constant parameterization information, constraint information, and plan note.</li><li>`'ADVANCED'`: displays comprehensive information, which is the same as the 'ALL' parameter. Additionally, it displays tree structure information for complex plans.</li></ul>|
| statement_id | The identifier of the `EXPLAIN` query. You can run the `EXPLAIN SET STATEMENT_ID='XXX'` command to set the identifier. |
| table_name | The target table for storing the `EXPLAIN` plan. The default value is `PLAN_TABLE`. |
| filter_preds | Additional `PLAN_TABLE` filter conditions for filtering specific operators or plans. |
