# Outline-related hints

| Hint Name                               | Description                            |
|---------------------------------------|----------------------------------|
| `BEGIN_OUTLINE_DATA`                  | The start marker for outline data.            |
| `END_OUTLINE_DATA`                    | The end marker for outline data.           |
| `QB_NAME`                             | Specifies a name for a query block to be referenced in other hints.|
| `OPTIMIZER_FEATURES_ENABLE`           | Specifies the optimizer version for query plan generation.             |
| `CACHE`                               | Manually enables cache for a specified table and its indexes. The cache is always enabled during queries.|
| `NOCACHE`                             | Manually disables cache for a specified table and its indexes. The cache is always disabled during queries.|

## OUTLINE_DATA

**OUTLINE DATA** specifies a hint for query optimization. An example is given below:

```sql
SELECT /*+PARALLEL(2)*/ 1
FROM (SELECT c2 FROM t1 WHERE c1 = 1) v, t2
WHERE t2.c2 = v.c2;

/*+
  BEGIN_OUTLINE_DATA
  // Tuning hint
  LEADING(@"SEL$6D1A4751" ("TEST.T1"@"SEL$2" "TEST.T2"@"SEL$1"))
  USE_HASH(@"SEL$6D1A4751" "TEST.T2"@"SEL$1")
  PQ_DISTRIBUTE(@"SEL$6D1A4751" "TEST.T2"@"SEL$1" NONE BROADCAST)
  PX_JOIN_FILTER(@"SEL$6D1A4751" "TEST.T2"@"SEL$1")
  FULL(@"SEL$6D1A4751" "TEST.T1"@"SEL$2")
  FULL(@"SEL$6D1A4751" "TEST.T2"@"SEL$1")
  // Conversion reminder
  MERGE(@"SEL$2" > "SEL$1")
  // Global note
  OPTIMIZER_FEATURES_ENABLE('4.0.0.0')
  PARALLEL(2)
  END_OUTLINE_DATA
*/
```

The `BEGIN_OUTLINE_DATA` and `END_OUTLINE_DATA` hint specifies the optimizer version for the OUTLINE DATA. The specified optimizer version must be valid. Otherwise, an error will be returned.

## `OPTIMIZER_FEATURES_ENABLE` Hint

The `OPTIMIZER_FEATURES_ENABLE` hint specifies the version of the optimizer used by the current query.

### Syntax

```sql
/*+ OPTIMIZER_FEATURES_ENABLE ( version_number ) */
```

#### Parameters

- `version_number`: the optimizer version number.

### Examples

```sql
-- Use the OPTIMIZER_FEATURES_ENABLE hint to specify that the optimizer uses features from version 4.0.0.0 when generating execution plans.
SELECT /*+ OPTIMIZER_FEATURES_ENABLE('4.0.0.0') */ employee_id, last_name
FROM employees
WHERE last_name = 'Smith';
```

## `QB_NAME` Hint

`QB_NAME` specifies a name for a query block, which can then be referenced in other hints. This is very helpful when more detailed control of specific parts of the query is needed.

For more information, see [Control query optimization by using the Query Block Name and QB_NAME Hint](../150.query-block-name-qb-hint-of-oracle-mode.md).

### Syntax

```sql
/*+ QB_NAME(queryblock) */
```

## Parameters

- `qb_name` is case-insensitive, cannot contain special characters, and has a maximum length of 20 characters.

#### Considerations and Limitations

`QB_NAME` is invalid in the following situations:

- Specify multiple valid `qb_name` in the same-level query.
- Use the same `qb_name` in queries at different levels.

### Examples

```sql
-- Use the QB_NAME hint to name the query block 'qb', and use the FULL hint to force a full table scan of the employees table
SELECT /*+ QB_NAME(qb) FULL(@qb e) */ employee_id, last_name
FROM employees e
WHERE last_name = 'Smith';
```

### CACHE Hint

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>The `DELETE_SCHEMA_STATS` procedure was introduced in V4.6.0. </p>
</main>

The `CACHE` hint is used to enable cache for a specified table and its indexes manually. Cache remains enabled during queries.

<main id="notice" type='explain'>
  <h4>Notes</h4>
  <p>When there is no Hint, the cache is automatically enabled or disabled based on the adaptive strategy. </p>
</main>

**Syntax:**

```sql
/*+ CACHE ([@qb_name] table_name) */
```

## Parameters

* `@qb_name`: Optional, specifies the name of the query block (query block) that the hint applies to. If omitted, the default is the main query block of the current query.
* `table_name`: The name of the table.

**Example:**

* Manually enable cache for `tbl1`.

    ```shell
    obclient> SELECT /*+ CACHE(tbl1) */ * FROM tbl1;
    ```

* Manually enable caching for `tbl1`, and enable caching for `tbl2` with the default settings.

    ```shell
    obclient> SELECT /*+ CACHE(tbl1) */ * FROM tbl1, tbl2
        WHERE tbl1.col1 = tbl2.col1;
    ```

### NOCACHE Hint

<main id="notice" type='explain'>
  <h4>Considerations</h4>
  <p>The hint is supported starting from V4.6.0. </p>
</main>

The `NOCACHE` hint is used to manually disable caching for a specified table and its indexes. Caching is disabled during the query process for this table.

**Syntax:**

```sql
/*+ CACHE ([@qb_name] table_name) */
```

## Parameters

* `@qb_name`: Optional. The name of the query block to which the hint applies. If specified, the hint is applied to the main query block of the current query.
* `table_name`: The name of the table.

**Example:**

Manually disable the cache for `tbl1`.

```shell
obclient> SELECT /*+ NOCACHE(tbl1) */ * FROM tbl1;
```

When multiple `CACHE`/`NOCACHE` hints are specified, all hints are merged. If `CACHE` and `NOCACHE` hints conflict (i.e., they apply to the same table), the `CACHE` hint takes precedence, effectively enabling caching for that table.

**Here is the example:**

The `CACHE` clause is in effect, and `tbl1` is manually enabled for cache.

```shell
obclient> SELECT /*+ CACHE(tbl1) NOCACHE(tbl1) */ * FROM tbl1;
```
