# Distributed DML hint in the Optimized Hint category

In OceanBase Database in Oracle mode, you can use distributed DML hints to control whether to execute DML operations in distributed mode. Note the following two important concepts:

- Distributed DML: DML operations executed across multiple nodes. This is fundamentally different from non-distributed DML operations executed locally or in partition-wise manner on a single node.
- Parallel DML: DML operations executed in parallel by multiple threads on a single node.

Although these hints can be used for fixed execution plans, they are not recommended for general use. They are typically only enabled in OUTLINE DATA.

| Hint name                              | Description       |
|---------------------------------------|------------|
| `USE_DISTRIBUTED_DML`     | Enables distributed DML operations. The reverse operation is `NO_USE_DISTRIBUTED_DML`.  |
| `NO_USE_DISTRIBUTED_DML`  | Disables distributed DML operations. The reverse operation is `USE_DISTRIBUTED_DML`.    |

## `USE_DISTRIBUTED_DML` Hint

The `USE_DISTRIBUTED_DML` hint enables distributed DML operations. When this hint is enabled, DML operations are executed in a distributed manner. The reverse of this hint is `NO_USE_DISTRIBUTED_DML`.

### Syntax

```sql
/*+ USE_DISTRIBUTED_DML [ ( [ @ qb_name ] ) ] */
```

### Examples

```sql
-- Create a table tp1 with 10 hash partitions
CREATE TABLE tp1(c1 INT, c2 INT, c3 INT) PARTITION BY HASH(c1) PARTITIONS 10;

-- Update the c2 column in the tp1 table to 4 where c1 is less than 4, using the USE_DISTRIBUTED_DML hint
-- This update will be executed in a distributed manner
EXPLAIN BASIC UPDATE /*+ USE_DISTRIBUTED_DML */ tp1 SET c2 = 4 WHERE c1 < 4;
```

## `NO_USE_DISTRIBUTED_DML` Hint

The `NO_USE_DISTRIBUTED_DML` hint disables distributed execution for DML operations. Its opposite is the `USE_DISTRIBUTED_DML` hint.

### Syntax

```sql
/*+ NO_USE_DISTRIBUTED_DML [ ( [ @ qb_name ] ) ] */
```

### Examples

```sql
-- Create a table tp1 with 10 hash partitions.
CREATE TABLE tp1(c1 INT, c2 INT, c3 INT) PARTITION BY HASH(c1) PARTITIONS 10;

-- Use the NO_USE_DISTRIBUTED_DML hint to restrict update operations to be executed locally on a single node, rather than distributedly.
-- This update operation will be executed non-distributedly.
EXPLAIN BASIC UPDATE /*+ NO_USE_DISTRIBUTED_DML */ tp1 SET c2 = 4 WHERE c1 < 4;
```
