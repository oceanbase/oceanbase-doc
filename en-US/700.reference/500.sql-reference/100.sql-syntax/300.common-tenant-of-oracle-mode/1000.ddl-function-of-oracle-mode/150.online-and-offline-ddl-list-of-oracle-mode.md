# Online DDL and offline DDL operations

## Online DDL

- **Definition**: You can access the database, including reading and writing data, while online DDL operations are being performed.
- **Advantages**: It has minimal impact on business and allows you to perform DDL operations while the system is running. It is typically used in scenarios requiring high availability.
- **Characteristics**: Generally supports concurrent access and fewer locks, which can reduce downtime.

## Offline DDL

- **Definition**: During offline DDL operations, related tables are locked and users cannot access the corresponding data in the database.
- **Advantages**: Simple and easy to implement. It is suitable for scenarios with slight impact on business.
- **Characteristics**: It causes downtime during which no data can be queried or transacted.

## Transaction association

- **Transaction**: A transaction is a group of operations. All operations in a transaction are performed successfully or failed together. A transaction ensures the consistency of data during its operation.
- Generally, online DDL and offline DDL are separate operations. In some database management systems, DDL operations cannot be controlled by transactions (especially offline DDL).

## Transaction wait strategies

- **Online DDL**: Generally, does not need to wait for the current transaction to commit. It can be executed concurrently.
- **Offline DDL**: Generally, needs to wait for the current transaction to commit, because it locks the related tables during execution.

## How to determine whether a DDL operation is an online DDL operation

In the OceanBase database, the online and offline status of DDL operations is very important for the impact on business operations. This article will introduce how to determine whether a DDL operation is Online DDL, and provide specific operational steps and precautions. For some operations like column type changes or mixed DDL operations, it may be uncertain whether they are Online DDL before execution. It is recommended to first verify and judge through the following methods.

### Methods to determine whether a DDL operation is an online DDL operation

Some DDL operations have a wide range of applications, and it is impossible to list all DDL operations in online or offline modes. In this case, we recommend that you specify whether a DDL operation is an online DDL operation when you perform a hybrid DDL operation.

**The principle of offline DDL**:

An offline DDL operation in OceanBase Database is performed by " rebuilding a table". Specifically, an offline DDL operation creates a temporary hidden table (invisible to users), and then migrates the data of the original table to the new table. After the data migration is completed, the temporary table is renamed to the name of the original table, and the old table is deleted. Therefore, after an offline DDL operation is performed, the `table_id` changes. Note that DML operations are not allowed during an offline DDL operation.

You can determine whether a DDL operation is an online DDL operation based on the preceding principle.

**The method**:

Execute the following SQL statements to check whether the `table_id` changes before and after a DDL operation. If the `table_id` remains unchanged, the DDL operation is an online DDL operation. If the `table_id` changes, the DDL operation is an offline DDL operation.

```sql
select distinct(table_id) from DBA_OB_TABLE_LOCATIONS where table_name='xxx';
```

**The steps**:

Determine whether a DDL operation is an online DDL operation based on the following steps.

1. Create a verification table:

    ```sql
    CREATE TABLE t10(a INT, b INT);
    ```

2. View the current `table_id`:

    ```sql
    SELECT distinct(table_id)
    FROM DBA_OB_TABLE_LOCATIONS
    WHERE table_name='t10';
    ```

3. Perform the expected DDL operation:

    ```sql
    ALTER TABLE t10 ADD c INT, ADD CONSTRAINT c_idx UNIQUE(c);
    ```

4. View the `table_id` again:

    ```sql
    SELECT distinct(table_id)
    FROM DBA_OB_TABLE_LOCATIONS
    WHERE table_name='t10';
    ```

5. If the `table_id` returned in steps 2 and 4 are the same, the DDL operation is an online DDL operation. If the `table_id` has changed, the DDL operation is an offline DDL operation.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This method is ineffective for table and partition operations. </p>
</main>
