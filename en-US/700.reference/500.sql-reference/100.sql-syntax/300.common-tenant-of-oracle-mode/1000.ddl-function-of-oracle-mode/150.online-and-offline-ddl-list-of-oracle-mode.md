## How to determine whether an DDL operation is an online DDL operation

In OceanBase Database, the online or offline status of DDL operations is crucial for business operations. This topic explains how to determine whether an DDL operation is an online DDL operation, and provides the specific procedures and considerations. Some DDL operations, such as column type changes and hybrid DDL operations, cannot be determined beforehand to be online or offline. In this case, it is recommended to perform a test to determine whether the operation is online or offline before you proceed.

### Methods to determine whether an DDL operation is an online DDL operation

Some DDL operations cannot be determined to be online or offline due to their wide range of applications. In this case, we recommend that you specify whether an operation is online or offline when you perform a hybrid DDL operation.

**The principle of offline DDL operations**:

OceanBase Database performs offline DDL operations by rebuilding tables. Specifically, an offline DDL operation creates a temporary hidden table (invisible to users), and then migrates data from the original table to the new table. After the data migration is completed, the temporary table is renamed to the name of the original table, and the old table is deleted. Therefore, the `table_id` changes after an offline DDL operation. Note that DML operations are not allowed during an offline DDL operation.

You can use this principle to determine whether an DDL operation is an online DDL operation.

**The determination method**:

Execute the following SQL statements before and after an DDL operation to check whether the `table_id` changes. If it does not change, the DDL operation is an online DDL operation. If it does change, the DDL operation is an offline DDL operation.

```sql
select distinct(table_id) from DBA_OB_TABLE_LOCATIONS where table_name='xxx';
```

**The determination steps**:

Follow these steps to determine whether an DDL operation is an online DDL operation.

1. Create a verification table:

    ```sql
    CREATE TABLE t10(a INT, b INT);
    ```

2. View the current `table_id`:

    ```sql
    SELECT distinct(table_id)
    FROM DBA_OB_TABLE_LOCATIONS
    WHERE table_name='t10';
    ```

3. Perform the expected DDL operation:

    ```sql
    ALTER TABLE t10 ADD c INT, ADD CONSTRAINT c_idx UNIQUE(c);
    ```

4. View the `table_id` again:

    ```sql
    SELECT distinct(table_id)
    FROM DBA_OB_TABLE_LOCATIONS
    WHERE table_name='t10';
    ```

5. If the `table_id` returned in steps 2 and 4 are the same, the DDL operation is an online DDL operation. If the `table_id` is different, the DDL operation is an offline DDL operation.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This method is ineffective for table and partition operations. </p>
</main>
