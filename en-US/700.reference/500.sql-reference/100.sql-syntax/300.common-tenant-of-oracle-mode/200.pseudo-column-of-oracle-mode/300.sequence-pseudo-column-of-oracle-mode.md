# Sequence pseudocolumns

A sequence is a set of automatically generated, sequential numbers based on a specified rule in a database. Because numbers in a sequence are incremental, sequences are usually used as primary keys and unique keys. This topic explains how to use sequence pseudocolumns and provides information about their features and applications.

## Methods for obtaining sequence values

You can execute an SQL statement that contains a sequence reference to obtain a sequence value in one of the following methods:

* `CURRVAL`: returns the current value of the sequence.

* `NEXTVAL`: returns the next sequential value of the sequence.

When you use the sequence pseudocolumns, you must prefix the sequence name to both the `CURRVAL` and `NEXTVAL` keywords and reference them with a period (.). For example, if the sequence name is `SEQ_FOO`, you can obtain the current value of the `SEQ_FOO` sequence by using `SEQ_FOO.CURRVAL`, and the next sequential value by using `SEQ_FOO.NEXTVAL`.

## Scenarios for using sequence values

You can use sequence values obtained by using `CURRVAL` and `NEXTVAL` in the following scenarios:

* The select list of a `SELECT` statement that is not within a subquery or a view.

* The select list of an `INSERT` statement that contains a subquery.

* The `VALUE` clause of an `INSERT` statement.

* The `SET` clause of an `UPDATE` statement.

Sequence values obtained by using `CURRVAL` and `NEXTVAL` cannot be used in the following scenarios:

* The condition of a `DELETE`, `SELECT`, or `UPDATE` statement or a subquery thereof.

* The query of a view.

* The select list of a `SELECT` statement that contains the `DISTINCT` operator.

* The select list of a `SELECT` statement that contains the `GROUP BY` or `ORDER BY` clause.

* The select list of a `SELECT` statement that is combined with another `SELECT` statement through the `UNION`, `INTERSECT`, or `MINUS` operator.

* The `WHERE` clause of a `SELECT` statement.

* The condition of a `CHECK` constraint.

## Sequence notes

When you create a sequence, you must specify its initial value and increment. The first reference to `NEXTVAL` returns the initial value of the sequence. Subsequent references to `NEXTVAL` return the value obtained by adding the increment to the value returned from the last reference to `NEXTVAL`. The value of `CURRVAL` always returns the current value of the sequence, namely, the value returned from the last reference to `NEXTVAL`.

Before you can reference the `CURRVAL` of a sequence in a session, you must initialize the sequence value in this session by referencing the `NEXTVAL` of the sequence.

When you create a sequence, you can specify its initial value and increment. The first reference to `NEXTVAL` returns the initial value of the sequence. Subsequent references to `NEXTVAL` return the value obtained by adding the increment to the value returned from the last reference to `NEXTVAL`. Any reference to `CURRVAL` always returns the current value of the sequence, namely, the value returned from the last reference to `NEXTVAL` for the sequence. For more information, see [CREATE SEQUENCE](../900.sql-statement-of-oracle-mode/100.ddl-of-oracle-mode/2200.create-sequence-of-oracle-mode.md).

In an SQL query, the database increments the sequence in the following cases when you reference `NEXTVAL`:

* Each time a row is returned in the outermost query block of a `SELECT` statement. Such a query block can appear in the following positions:

  * The top-level `SELECT` statement.
  * The `INSERT... SELECT` statement. In a multi-table insert operation, `NEXTVAL` must be used in the `VALUES` clause. The sequence is incremented each time a row is returned in the subquery, regardless of whether `NEXTVAL` is referenced in multiple branches.
  * The `CREATE TABLE ... AS SELECT` statement.
  * The `CREATE  MATERIALIZED VIEW ... AS SELECT` statement.

* Each time a row is updated in an `UPDATE` statement.

* Each time an `INSERT` statement that contains a `VALUES` clause is executed.

In an <code>INSERT</code> statement, the sequence value is incremented each time the sequence is referenced. If a value is manually inserted into a column that references the sequence value (namely, the referenced sequence value is not used for the insertion), the sequence value remains unchanged. </p>

* Each time a row is merged in a `MERGE` statement. `NEXTVAL` can appear in the `merge_insert_clause`, `merge_update_clause`, or both. The sequence is incremented each time a row is updated or inserted, regardless of whether the sequence value is used for the update or insertion. If `NEXTVAL` is specified multiple times in these positions, the sequence is incremented for each row, and all `NEXTVAL` references in the row return the same value.

If a sequence's `NEXTVAL` is referenced multiple times in these positions, the sequence is incremented only once, namely, `NEXTVAL` in all these positions returns the next sequence value.

If both `CURRVAL` and `NEXTVAL` of a sequence are referenced in the same position, the database increments the sequence, and both `CURRVAL` and `NEXTVAL` return the next sequence value.

Sequences can be accessed by multiple users simultaneously without waits or locks.
Here is an example of querying a sequence:

```sql
SELECT SEQUENCE_NAME.NEXTVAL FROM DUAL;      /*The sequence number is incremented each time the query is executed. */
SELECT SEQUENCE_NAME.CURRVAL FROM DUAL;     /*The sequence number remains unchanged regardless of how many times the query is executed. */
```
