# INSERT

## Purpose

This statement is used to add one or more records to a table.

## Privilege requirements

To execute the `INSERT` statement, the current user must have the `INSERT` system privilege. For more information about OceanBase Database privileges, see [Privilege types in Oracle mode](../../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/300.permission-of-oracle-mode/000.permission-classification-of-oracle-mode.md).

## Syntax

```sql
INSERT [hint_options] { single_table_insert | multi_table_insert | overwrite_table_insert};

single_table_insert:
    { INTO insert_table_clause { NOLOGGING | /*EMPTY*/ } '(' column_list ')' values_clause [{ RETURNING | RETURN } returning_exprs [into_clause]]
    | INTO insert_table_clause { NOLOGGING | /*EMPTY*/ } '(' ')' values_clause [{ RETURNING | RETURN } returning_exprs [into_clause]]
    | INTO insert_table_clause { NOLOGGING | /*EMPTY*/ } values_clause [{ RETURNING | RETURN } returning_exprs [into_clause]]
    }

hint_options:
    [/*+ [APPEND | DIRECT(bool, int, load_mode)] enable_parallel_dml PARALLEL(N) | NO_DIRECT */]
    [INTO] table_name [PARTITION(PARTITION_OPTION)]

column_list:
      column_definition_ref [, column_definition_ref...]

returning_exprs:
    projection_col_name [,projection_col_name ...]

insert_into_clause:
    { INTO into_var_list | BULK COLLECT INTO into_var_list}

into_var_list:
    { USER_VARIABLE | ref_name } [, { USER_VARIABLE | ref_name }...]

values_clause:
    VALUES ({ expr | DEFAULT } [, { expr | DEFAULT } ]...  )

returning_exprs:
    projection_col_name [,projection_col_name ...]

multi_table_insert:
    { ALL { insert_into_clause [ values_clause ] [error_logging_clause] }
    | conditional_insert_clause
    } subquery

conditional_insert_clause:
    [ ALL | FIRST ]
    WHEN condition
    THEN insert_into_clause
    [ values_clause ]
    [ error_logging_clause ]
    [ insert_into_clause [ values_clause ] [ error_logging_clause ] ]...
    [ WHEN condition
        THEN insert_into_clause
        [ values_clause ]
        [ error_logging_clause ]
        [ insert_into_clause [ values_clause ] [ error_logging_clause ] ]...
    ]...
    [ ELSE insert_into_clause
        [ values_clause ]
        [ error_logging_clause ]
        [ insert_into_clause [ values_clause ] [ error_logging_clause ] ]...
    ]

error_logging_clause:
    LOG ERRORS [ INTO [schema.] table_name] [ (simple_expression) ] [ REJECT LIMIT { integer | UNLIMITED } ]

overwrite_table_insert:
    [/*+PARALLEL(N)*/] OVERWRITE [INTO] table_name [(list_of_columns)] [PARTITION (partition_name, ...)] select_stmt
```

## Parameters

|            Parameter           |                            Description                                      |
|---------------------------|---------------------------------------------------------------------|
| hint_options              | Use the Hint to enable direct loading. Optional. For more information about the Hint, see [Hint overview](../../300.basic-elements-of-oracle-mode/600.annotation-of-oracle-mode/400.hint-of-oracle-mode/100.hint-overview-of-oracle-mode.md).<main id="notice" type='notice'><h4>Notice</h4><p>During direct loading, do not upgrade OceanBase Database. Otherwise, the direct loading task may fail.</p></main> The `INSERT INTO SELECT` statement supports the `APPEND \| DIRECT()\| NO_DIRECT` Hint to control the data import mode. The format is `/*+ [APPEND \| DIRECT(bool, int, load_mode)] enable_parallel_dml PARALLEL(N) \| NO_DIRECT */`. The parameters in the Hint are described as follows:<ul><li><code>APPEND</code>: By default, it is equivalent to using <code>DIRECT(true, 0)</code>. It also enables the online statistics collection feature (</code>GATHER_OPTIMIZER_STATISTICS</code> Hint).</li><li><code>DIRECT()</code>:<ul><li><code>bool</code>: Indicates whether the data to be written needs to be sorted. <code>true</code> indicates that sorting is required. <code>false</code> indicates that sorting is not required.</li><li><code>int</code>: Indicates the maximum number of error rows that can be tolerated.</li><li><code>load_mode</code>: Optional. Indicates the direct loading mode. The value must be enclosed in English single quotes. Valid values: <ul><li><code>full</code>: Default value. Indicates full loading.</li><li><code>inc</code>: Indicates incremental loading. It supports the <code>INSERT</code> and <code>IGNORE</code> semantics.</li><li><code>inc_replace</code>: Indicates incremental loading without checking for duplicate primary keys, equivalent to incremental loading with the <code>REPLACE</code> semantics.</li></ul> </li><li><code>enable_parallel_dml parallel(N)</code>: The data loading parallelism. <code>N</code> defaults to 4.<main id="notice" type='explain'><h4>Note</h4><p>Generally, the <code>enable_parallel_dml</code> Hint and the <code>parallel</code> Hint must be used together to enable parallel DML. However, if the target table's schema specifies a table-level parallelism, only the <code>enable_parallel_dml</code> Hint is needed.</p></main></li></ul><li><code>NO_DIRECT</code>: Forces a single SQL statement to not use direct loading. If the input SQL statement contains this Hint, the entire statement ignores other direct loading Hints and executes a regular import.</li></ul>For more information about using `INSERT INTO SELECT` for direct loading, see **Use the INSERT INTO SELECT statement for direct loading**.|
| table_name                       | The name of the table to import data into. You can specify any number of columns in the table.  |
| PARTITION_OPTION                   | Specifies the partition name when performing direct loading on partitions:<ul><li>partition_option_list: The list of partitions to insert into, separated by commas (,). </li> <li>subpartition_option_list: The list of subpartitions to insert into, separated by commas (,).</li></ul>|
| single_table_insert       | Single-table insertion.                                                                                                                                                                                                             |
| insert_table_clause       | The table to insert data into. This can be a base table, an updatable view, or a special subquery.   <main id="notice" type='notice'><h4>Notice</h4><p>A special subquery is similar to the subquery corresponding to an updatable view. It should not contain complex operators such as <code>GROUP BY</code>, <code>DISTINCT</code>, or <code>WINDOW FUNCTION</code>.                                                                                                                                                                                      |
| opt_nologging             | Minimizes the amount of log information generated during insertion.                                                                                                                                                                                                     |
| column_list               | The names of the columns to insert.                                                                                                                                                                                                         |
| returning_exprs           | The projected columns to return after the data is inserted.                                                                                                                                                                                                     |
| insert_into_clause        | Inserts the column values after the data is inserted into the specified list.                                                                                                                                                                                               |
| multi_table_insert        | Multi-table insert.                                                                                                                                                                                                             |
| conditional_insert_clause | Conditional multi-table insert. <ul><li> `ALL`: Traverses all branches that match the condition. If a condition is met, the data is inserted into the corresponding table.   </li><li> `FIRST`: Finds the first branch that meets the condition and inserts the data into the corresponding table, without checking the remaining branches. </li></ul>    |
| error_logging_clause      | Saves the SQL errors and the number of affected rows into an error logging table.                                                                                                                                                                                    |
| overwrite_table_insert  | Used to replace existing data in a table or partition with the query results. For more information about using the `INSERT OVERWRITE SELECT` statement, see the **Insert data by using the INSERT OVERWRITE SELECT statement** section in [Insert data](../../../../../../300.develop/200.application-development-of-oracle-mode/400.write-data-of-oracle-mode/100.insert-data-of-oracle-mode-in-develop.md).|
| list_of_columns   | Specifies the columns in the table where data is to be inserted.                     |
| select_stmt             | Specifies the `SELECT` clause. For more information about query statements, see [SIMPLE SELECT](500.select-of-oracle-mode/100.simple-select-of-oracle-mode.md).|

## Examples

The following examples use the sample tables and data defined as follows:

```shell
obclient> CREATE TABLE tbl(col1 INT PRIMARY KEY, col2 INT,col3 INT);
Query OK, 0 rows affected

obclient> CREATE TABLE tbl2(col1 INT PRIMARY KEY, col2 INT,col3 INT);
Query OK, 0 rows affected

obclient> CREATE TABLE tbl3(col1 INT PRIMARY KEY, col2 INT,col3 INT);
Query OK, 0 rows affected
```

* Insert data into a single table: Insert two rows of data into the `tbl1` table.

  ```shell
  obclient> INSERT INTO tbl1 (col1, col2, col3) VALUES (1, 10, 100), (2, 20, 200);
  Query OK, 2 row affected

  obclient> SELECT * FROM tbl1;
  +------+------+------+
  | COL1 | COL2 | COL3 |
  +------+------+------+
  |    1 |   10 |  100 |
  |    2 |   20 |  200 |
  +------+------+------+
  2 rows in set
  ```

* Insert data into a single table: Insert data directly into a subquery.

  ```shell
  obclient>INSERT INTO tbl1 (col1, col2, col3) SELECT col1 + 2, col2 + 5, col3 + 10 FROM tbl1;
  Query OK, 2 row affected

  obclient> SELECT * FROM tbl1;
  +------+------+------+
  | COL1 | COL2 | COL3 |
  +------+------+------+
  |    1 |   10 |  100 |
  |    2 |   20 |  200 |
  |    3 |   15 |  110 |
  |    4 |   25 |  210 |
  +------+------+------+
  4 rows in set
  ```

* Insert data into a single table: Use the `RETURNING` clause.

  ```shell
  obclient> INSERT INTO tbl1 (col1, col2, col3) VALUES (5, 50, 500), (6, 60, 600) RETURNING col1;
  +------+
  | COL1 |
  +------+
  |    5 |
  |    6 |
  +------+
  2 rows in set

  obclient> SELECT * FROM tbl1;
  +------+------+------+
  | COL1 | COL2 | COL3 |
  +------+------+------+
  |    1 |   10 |  100 |
  |    2 |   20 |  200 |
  |    3 |   15 |  110 |
  |    4 |   25 |  210 |
  |    5 |   50 |  500 |
  |    6 |   60 |  600 |
  +------+------+------+
  6 rows in set
  ```

* Insert data into multiple tables: When the `tbl3` table contains at least one row, insert one row of data (7,8,9) into the `tbl1` table and one row of data (10,11,12) into the `tbl2` table.

  ```shell
  obclient> INSERT ALL INTO tbl1 VALUES(7,8,9)
                                      INTO tbl2 VALUES(10,11,12)
                  SELECT * FROM tbl3 WHERE ROWNUM< 2;
  Query OK, 2 rows affected
  Records: 2  Duplicates: 0  Warnings: 0

  obclient> SELECT * FROM tbl1;
  +------+------+------+
  | COL1 | COL2 | COL3 |
  +------+------+------+
  |    1 |   10 |  100 |
  |    2 |   20 |  200 |
  |    3 |   15 |  110 |
  |    4 |   25 |  210 |
  |    5 |   50 |  500 |
  |    6 |   60 |  600 |
  |    7 |    8 |    9 |
  +------+------+------+
  7 rows in set

  obclient> SELECT * FROM tbl2;
  +------+------+------+
  | COL1 | COL2 | COL3 |
  +------+------+------+
  |   10 |   11 |   12 |
  +------+------+------+
  1 row in set
  ```

* Insert data into multiple tables based on conditions: Use the `INSERT ALL` statement. When the value of the `col2` column in the `tbl` table is greater than `1`, insert data (10,11,12) into the `tbl1` table. When the value of the `col3` column in the `tbl` table is greater than `1`, insert data (22,23,24) into the `tbl2` table. If neither condition is met, insert data (33,34,35) into the `tbl1` table.

  ```shell
  obclient> INSERT INTO tbl VALUES(1,2,3);
  Query OK, 1 row affected

  obclient>INSERT ALL
                WHEN col2 > 1 THEN INTO tbl1 VALUES(10,11,12)
                WHEN col3 > 1 THEN INTO tbl2 VALUES(22,23,24)
                ELSE INTO tbl1 VALUES(33,34,35) SELECT col2,col3 FROM tbl;
  Query OK, 2 rows affected
  Records: 2  Duplicates: 0  Warnings: 0

  obclient> SELECT * FROM tbl1;
  +------+------+------+
  | COL1 | COL2 | COL3 |
  +------+------+------+
  |    1 |   10 |  100 |
  |    2 |   20 |  200 |
  |    3 |   15 |  110 |
  |    4 |   25 |  210 |
  |    5 |   50 |  500 |
  |    6 |   60 |  600 |
  |    7 |    8 |    9 |
  |   10 |   11 |   12 |
  +------+------+------+
  8 rows in set

  obclient> SELECT * FROM tbl2;
  +------+------+------+
  | COL1 | COL2 | COL3 |
  +------+------+------+
  |   10 |   11 |   12 |
  |   22 |   23 |   24 |
  +------+------+------+
  2 rows in set
  ```

* Insert data into multiple tables based on conditions: Use the `INSERT FIRST` statement. When the value of the `col2` column in the `tbl` table is greater than `1`, insert data (14,15,16) into the `tbl1` table and data (40,41,42) into the `tbl2` table. When the value of the `col3` column in the `tbl` table is greater than `1`, insert data (25,26,27) into the `tbl2` table. If neither condition is met, insert data (35,36,37) into the `tbl1` table.

  ```shell
  obclient>INSERT ALL
                WHEN col2 > 1 THEN INTO tbl1 VALUES(14,15,16) INTO tbl2 VALUES(40,41,42)
                WHEN col3 > 1 THEN INTO tbl2 VALUES(25,26,27)
                ELSE INTO tbl1 VALUES(35,36,37) SELECT col2,col3 FROM tbl;
  Query OK, 3 rows affected
  Records: 3  Duplicates: 0  Warnings: 0

  obclient> SELECT * FROM tbl1;
  +------+------+------+
  | COL1 | COL2 | COL3 |
  +------+------+------+
  |    1 |   10 |  100 |
  |    2 |   20 |  200 |
  |    3 |   15 |  110 |
  |    4 |   25 |  210 |
  |    5 |   50 |  500 |
  |    6 |   60 |  600 |
  |    7 |    8 |    9 |
  |   10 |   11 |   12 |
  |   14 |   15 |   16 |
  +------+------+------+
  9 rows in set

  obclient> SELECT * FROM tbl2;
  +------+------+------+
  | COL1 | COL2 | COL3 |
  +------+------+------+
  |   10 |   11 |   12 |
  |   22 |   23 |   24 |
  |   25 |   26 |   27 |
  |   40 |   41 |   42 |
  +------+------+------+
  4 rows in set
  ```

* Specify the incremental direct load mode by using the `direct` hint.

  ```sql
  obclient [SYS]> INSERT /*+ direct(true, 0, 'inc_replace') enable_parallel_dml parallel(2) */ INTO tbl2 SELECT * FROM tbl1;
  ```

  The return result is as follows:

  ```sql
  Query OK, 8 rows affected
  Records: 8  Duplicates: 0  Warnings: 0
  ```

* Specify the partitioned direct load mode.
  Assume that the partitioning rules for the `tbl1` and `tbl2` tables are as follows:

  ```sql
  partition p0 values less than (10)
      subpartition p0_1 values less than (5)
      subpartition p0_2 values less than (10)
  partition p1 values less than (20)
      subpartition p1_1 values less than (15)
      subpartition p1_2 values less than (20)
  ```

  * Specify the primary partitioned direct load mode.

    ```sql
    insert /*+ enable_parallel_dml parallel(3) append */
    into tbl2 partition(p0, p1)
    select * from tbl1 partition(p0, p1);
    ```

  * Specify the subpartitioned direct load mode.

    ```sql
    insert /*+ enable_parallel_dml parallel(3) append */
    into tbl2 partition(p0sp0_1, p1sp1_1)
    select * from tbl1 partition(p0sp0_1, p1sp1_1);
    ```
