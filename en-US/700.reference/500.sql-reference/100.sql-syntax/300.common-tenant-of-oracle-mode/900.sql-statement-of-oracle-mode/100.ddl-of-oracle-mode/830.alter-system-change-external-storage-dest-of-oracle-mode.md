# ALTER/CHANGE/MODIFY EXTERNAL_STORAGE_DEST

## Purpose

This statement is used to modify the source configuration (such as `zone`, `idc`, or `region`) of the backup or archive path for the current tenant, as well as the `access_id` and `access_key` information. After modification, the new configuration will overwrite the original one.

## Limitations and considerations

* Only the user tenant can execute this statement. The system tenant (sys tenant) cannot execute it.

* Before modifying the `zone`, `idc`, or `region` configuration of the path, if you need to set the region or IDC level, you must first use the `ALTER SYSTEM MODIFY ZONE zone_name SET REGION=region_name;` or `ALTER SYSTEM MODIFY ZONE zone_name SET IDC=idc_name;` statement to set the region or IDC information. It is recommended to set the source configuration at the IDC level. This allows the backup task to be executed in an IDC with more network bandwidth resources, and the backup task has a wider range of optional nodes. Additionally, you do not need to pay attention to changes in zones within the IDC in the cluster.

* When modifying the source configuration of the backup path, if a backup task is currently running, the running task may take up to a few minutes to detect the configuration change. Therefore, during the configuration modification, nodes outside the specified configuration range may still access the backup path, resulting in cross-data center or cross-region traffic.

* Only the `access_id` and `access_key` information of object storage paths can be modified.

## Privilege requirements

The user executing this statement must have the `ALTER SYSTEM` privilege. For more information about OceanBase Database privileges, see [Privilege classification in Oracle mode](../../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/300.permission-of-oracle-mode/000.permission-classification-of-oracle-mode.md).

## Syntax

```sql
ALTER SYSTEM {ALTER|CHANGE|MODIFY} EXTERNAL_STORAGE_DEST PATH [=] 'path' SET [ATTRIBUTE = '{zone=zone_name | idc=idc_name | region=region_name}'] [ACCESS_INFO = 'access_id=new_access_id&access_key=new_access_key'];
```

## Parameters

|          Parameter               |         Description                                      |
|-----------------------------|--------------------------------------------------|
| path                        | Specifies the backup or archive path to be modified. If the backup or archive medium is of the object storage type, it must also include the host address and access key of the object storage. For example, when the archive medium is OSS, the path format is as follows: `oss://oceanbase-test-bucket/backup/databackup?host=xxxx`  |
| zone=zone_name \| idc=idc_name \| region=region_name | Specifies the source of the current backup or archive path. You can choose the `zone`, `idc`, or `region` configuration at different levels, but only one level can be selected at a time or none can be selected. If not explicitly specified, the default is not to set any. <p>When modifying the source configuration of the archive path: <ul><li>Since all traffic for log archiving is written by the leader replica, there is no access priority difference for log archive paths. The only restriction is on the nodes that can access the archive path. If you need to set multiple zones, IDCs, or regions, separate the multiple values with commas (,) or semicolons (;). For example, `zone=z1,z2;z3` specifies `z1`, `z2`, and `z3` as the sources for archiving. </li> <li>When modifying `zone`, `idc`, or `region`, the leader replica must be located in the specified `zone`, `idc`, or `region`. Otherwise, log archiving will not proceed. </li></ul></p> <p>When modifying the source configuration of the backup path: <ul><li>If you need to set multiple zones, IDCs, or regions, separate the multiple zones/IDCs/regions with commas (,) and semicolons (;). Specifically: <ul><li>A comma (,) indicates that the nodes in the zones/IDCs/regions on both sides have the same priority when selecting nodes for executing the backup task. </li> <li>A semicolon (;) indicates that the nodes in the zone/IDC/region on the left have a higher priority than those on the right. In other words, the backup task will prioritize nodes in the zone/IDC/region on the left. </li></ul> For example, if set to `zone=z1,z2;z3`, it specifies `z1`, `z2`, and `z3` as the sources for backup. `z1` and `z2` have the same priority, and both have a higher priority than `z3`. </li> <li>When modifying the `zone`, `idc`, or `region` configuration of the backup path, the leader node of the Root Service must be located in the specified `zone`, `idc`, or `region`. Otherwise, the backup task will fail to write backup metadata to the target backup path, ultimately leading to the failure of the backup task. It is recommended to include the primary zone range in the source configuration of the backup path. </li></ul></p> |
| access_id=new_access_id&access_key=new_access_key | Specifies the new `access_id` and `access_key` information after modification. Both `access_id` and `access_key` must be filled in. |

## Examples

* Change the source configuration of the archive path

  Assume that the original source configuration of the archive path is `zone=z1,z2,z3`. Now, you need to change the source configuration to `region=region1`. After the change, only nodes in `region1` can access this path.

  * OSS

    ```shell
    obclient(SYS@oracle001)[SYS]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='oss://oceanbase-test-bucket/backup/archive?host=****.aliyun-inc.com' SET ATTRIBUTE = 'region=region1';
    ```

  * NFS

    ```shell
    obclient(SYS@oracle001)[SYS]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='file:///data/nfs/backup/archive' SET ATTRIBUTE = 'region=region1';
    ```

  * S3

    ```shell
    obclient(SYS@oracle001)[SYS]> ALTER SYSTEM CHANGE EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=s3.<region>.amazonaws.com' SET ATTRIBUTE = 'region=region1';
    ```

  * Object storage compatible with the S3 protocol (OBS/GCS/COS)

    ```shell
    obclient(SYS@oracle001)[SYS]> ALTER SYSTEM CHANGE EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=obs.****.myhuaweicloud.com' SET ATTRIBUTE = 'region=region1';
    ```

    ```shell
    obclient(SYS@oracle001)[SYS]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=https://storage.googleapis.com' SET ATTRIBUTE = 'region=region1';
    ```

    ```shell
    obclient(SYS@oracle001)[SYS]> ALTER SYSTEM ALTER EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=cos.ap-xxxx.myqcloud.com' SET ATTRIBUTE = 'region=region1';
    ```

* Change the source configuration of the backup path

  Assume that the original source configuration of the backup path is `zone=z1,z2;z3`. Now, you need to change the source configuration to `idc=idc1;idc2`. After the change, nodes in `idc1` and `idc2` can access this path, and nodes in `idc1` have higher priority than those in `idc2`.

  * OSS


  * NFS

    ```shell

    ```

  * S3

    ```shell
    obclient(SYS@oracle001)[SYS]> ALTER SYSTEM ALTER EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/data?host=s3.<region>.amazonaws.com' SET ATTRIBUTE = 'idc=idc1;idc2';
    ```
