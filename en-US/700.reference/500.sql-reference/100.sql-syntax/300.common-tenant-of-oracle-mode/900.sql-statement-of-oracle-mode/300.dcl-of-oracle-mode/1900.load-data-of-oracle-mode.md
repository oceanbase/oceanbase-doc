# LOAD DATA

## Description

This statement imports data from an external source.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p><ul><li>Tables with triggers cannot use the <code>LOAD DATA</code> statement. </li><li>To import data from an external file, you must have the <code>FILE</code> privilege and the following settings:<ul><li>If you want to load a server-side file, you must set the system variable <a href="../../../../../800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/11500.secure_file_priv-global.md">secure_file_priv</a> in advance to specify the path that is accessible for loading or exporting files. </li><li>If you want to load a local file from the client, you must add the <code>--local-infile[=1]</code> option when you start the MySQL or OBClient client to enable the data loading feature from the local file system. </li></ul></li></ul></p>
</main>

The `LOAD DATA` statement in OceanBase Database supports the following input files:

* Server-side (OBServer node) files: files stored on the OBServer nodes of OceanBase Database. You can use the `LOAD DATA INFILE` statement to load data from server-side files to database tables.

* Client-side (local) files: files stored in the local file system of the client. You can use the `LOAD DATA LOCAL INFILE` statement to load data from client-side local files to database tables.

* OSS files: files stored in the OSS file system. You can use the `LOAD DATA REMOTE_OSS INFILE` statement to load data from OSS files to database tables.

The `LOAD DATA` statement currently supports importing CSV text files. The entire import process can be divided into the following phases:

1. Parse the file: OceanBase Database reads data from the file based on the file name entered by the user and reads data from the file. It then determines whether to parse the input file in parallel or in series based on the specified parallelism.

2. Distribute data: As OceanBase Database is a distributed database, data in different partitions may be distributed across different OBServer nodes. In this step, `LOAD DATA` calculates the parsed data and determines which OBServer node the data should be sent to.

3. Insert data: Once the data is received by the target OBServer node, the `INSERT` statement is executed locally to insert the data into the corresponding partition.

To import data from an external file, you must have the `FILE` privilege. You can use the `GRANT FILE ON *.* TO $user_name;` statement to grant the privilege to the user who needs to execute the `LOAD DATA` statement, where `$user_name` is the name of the user.

## Syntax

```sql
LOAD DATA
    [ [/*+ PARALLEL(N) load_batch_size(M) APPEND */]
      | [/*+ PARALLEL(N) direct(bool, int) */] ]
    [REMOTE_OSS | LOCAL] INFILE 'file_name'
    INTO TABLE table_name
    [{FIELDS | COLUMNS}
        [TERMINATED BY 'string']
        [[OPTIONALLY] ENCLOSED BY 'char']
        [ESCAPED BY 'char']
    ]
    [LINES
        [STARTING BY 'string']
        [TERMINATED BY 'string']
    ]
    [IGNORE number {LINES | ROWS}]
    [(column_name_var
        [, column_name_var] ...)]
```

## Parameters

|                Parameter               |        Description                     |
|----------------------------------|---------------------------------|
| parallel(N)                      | The degree of parallelism for loading data. The default value of `N` is `4`. |
| load_batch_size(M)               | The batch size for inserting data. The default value of `M` is `100`. We recommend that you set this parameter to a value within the range of [100,1000].  |
| APPEND | Specifies the hint for enabling direct load, which allocates space and writes data directly into data files. By default, the APPEND hint is equivalent to the `direct(true, 0)` setting, and allows you to collect statistics online (`GATHER_OPTIMIZER_STATISTICS` hint).   |
| direct | Specifies the hint for enabling direct load. The `bool` parameter indicates whether to sort the given CSV file, where `true` indicates that sorting is required. The `int` parameter specifies the maximum number of error rows that can be tolerated. |
| REMOTE_OSS \| LOCAL | Optional. <ul><li> <code>REMOTE_OSS</code> specifies whether to read data from the OSS file system.<main id="notice" type='notice'><h4>Notice</h4><p>If you specify this parameter, the <code>file_name</code> parameter must be an address in the OSS file system. </p></main>  </li><li> <code>LOCAL</code> specifies whether to read data from the local file system of the client. If you do not specify the `LOCAL` parameter, data is read from the file system of the server, which is an OBServer node. </li></ul> |
| file_name                        | The path and name of the input file. The format of the <code>file_name</code> parameter depends on where the import file is located: <ul><li>If the import file is stored on an OBServer node or the client, specify the file in the format of <code>/\$PATH/\$FILENAME</code>. </li><li>If the import file is stored on OSS, specify the file in the format of <code>oss://\$PATH/\$FILENAME/?host=\$HOST&access_id=\$ACCESS_ID&access_key=\$ACCESSKEY</code>. </li></ul>     The parameters are described as follows: <ul><li><code>\$PATH</code> specifies the path of the file in the bucket, that is, the directory where the file is stored. </li><li><code>\$FILENAME</code> specifies the name of the file, that is, the file to be accessed. </li><li><code>\$HOST</code> specifies the host name of the OSS service or the CDN accelerated domain name, that is, the address for accessing the OSS service. </li><li><code>\$ACCESS_ID</code> specifies the Access Key ID, which is used for authentication when accessing the OSS service. </li><li><code>\$ACCESSKEY</code> specifies the Access Key Secret, which is used for authentication when accessing the OSS service. </li></ul>    <main id="notice" type='explain'> <h4>Note</h4> <p>To import a file from OSS, make sure of the following:<ul><li>You have the permissions to access the specified OSS bucket and file. You need sufficient permissions to read the specified bucket and file. This typically requires setting up access permissions in the OSS console or by using OSS APIs, and configuring the access keys (Access Key ID and Access Key Secret) as credentials with appropriate permissions. </li><li>The database server can connect to the specified <code>$HOST</code> over the network to access the OSS service. If a CDN accelerated domain name is used for the OSS service, make sure that the CDN is correctly configured and the network connection is normal. </li></ul></p> </main> |
| table_name                       | The name of the table to which the imported data is loaded. The table can be a partitioned or non-partitioned table.  |
| FIELDS \| COLUMNS                | The formats of fields. <ul><li> `ENCLOSED BY`: specifies the delimiter for exported values.  </li> <li> `TERMINATED BY`: specifies the delimiter for exported columns. </li> <li>`ESCAPED BY`: specifies the characters to be ignored in exported values.</li></ul>   |
| LINES STARTING BY                | The starting delimiter of lines.   |
| LINES TERMINATED BY              | The ending delimiter of lines. |
| IGNORE number { LINES \| ROWS } | Specifies to ignore the first several lines or rows. `LINES` indicates several lines in the file, and `ROWS` indicates several rows separated by field separators.  By default, the system matches the fields in the input file with the columns in the table one by one. If the input file does not contain all the columns in the table, the missing columns are filled with default values. The default values are specified as follows: <ul><li> Character type: an empty string.   </li> <li> Numeric type: 0.    </li> <li> Date type: `0000-00-00`.</li></ul>    |
| column_name_var                  | The name of the column to import.   |

## Examples

### Example 1: Import data from a file on the server (OBServer node)

1. Set the global security path.

   <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>For security reasons, when you set the system variable <code>secure_file_priv</code>, you can only connect to the database locally to execute the SQL statement that modifies this global variable through a local socket. For more information, see <a href="../../../../../800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/11500.secure_file_priv-global.md">secure_file_priv</a>.</p>
   </main>

   ```shell
   obclient> SET GLOBAL secure_file_priv = "/";
   ```

2. Exit the login session.

   <main id="notice" type='explain'>
     <h4>Note</h4>
     <p>After you set the <code>secure_file_priv</code> variable, you must execute <code>\q</code> to exit so that the setting takes effect. </p>
   </main>

   ```shell
   obclinet> \q
   ```

   The return result is as follows:

   ```shell
   Bye
   ```

3. Reconnect to the database and then use the `LOAD DATA` statement to import data.

   * Perform normal import.

      ```shell
      obclient> LOAD DATA INFILE '/home/admin/test.csv' INTO TABLE t1;
      ```

   * Use the `APPEND` hint to enable direct load.

      ```shell
      LOAD DATA /*+ PARALLEL(4) APPEND */ INFILE '/home/admin/test.csv' INTO TABLE t1;
      ```

### Example 2: Import data from an OSS file

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>When you use an object storage path, parameters in the object storage path are separated by <code>&</code> characters. Make sure that the values of the parameters you enter contain only uppercase and lowercase letters, numbers, and the following special characters: <code>\/-_$+=</code>, and wildcard characters. If you enter characters other than the aforesaid ones, the setting may fail. </p>
</main>

Use the `direct(bool, int)` hint to enable direct load, allowing the imported file to be stored on Alibaba Cloud OSS.

```shell
LOAD DATA /*+ direct(true,1024) parallel(16) */ REMOTE_OSS INFILE 'oss://antsys-oceanbasebackup/backup_rd/xiaotao.ht/lineitem2.tbl?host=***.oss-cdn.***&access_id=***&access_key=***' INTO TABLE tbl1 FIELDS TERMINATED BY ',';
```
