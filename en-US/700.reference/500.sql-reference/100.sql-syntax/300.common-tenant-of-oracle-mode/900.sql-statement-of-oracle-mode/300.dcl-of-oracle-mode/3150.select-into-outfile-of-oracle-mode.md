# SELECT INTO

## Purpose

This statement stores query results in a variable, a file, or a table. The statement syntax is as follows:

* The `SELECT ... INTO OUTFILE` statement stores the result set in an external file and allows you to specify the output format.

* The `SELECT ... INTO DUMPFILE` statement writes an unformatted single line to an external file.

* The `SELECT ... INTO var_list` statement stores the result set in variables.

## Privilege requirements

To execute the `SELECT INTO` statement, you must have the `SELECT` privilege on the table. For more information about privileges in OceanBase Database, see [Privilege types in Oracle-compatible mode](../../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/300.permission-of-oracle-mode/000.permission-classification-of-oracle-mode.md).

## Syntax

```sql
SELECT [/*+parallel(N)*/] column_list_option
INTO { OUTFILE 'file_name' [PARTITION BY part_expr] [{CHARSET | CHARACTER SET} charset_name] [field_opt] [line_opt] [file_opt]
     | OUTFILE 'file_name' [PARTITION BY part_expr] [FORMAT = (external_file_format_list)] [file_opt]
     | DUMPFILE 'file_name'
     | into_var_list}
FROM table_name_list
[WHERE where_conditions]
[GROUP BY group_by_list [HAVING having_search_conditions]]
[ORDER BY order_expression_list]

column_list_option:
    column_name [, column_name ...]

external_file_format_list:
  TYPE = 'CSV'
    LINE_DELIMITER = '<string>' | <expr>
    FIELD_DELIMITER = '<string>' | <expr>
    ESCAPE = '<character>' | <expr>
    FIELD_OPTIONALLY_ENCLOSED_BY = '<character>' | <expr>
    FIELD_ENCLOSED_BY = '<character>' | <expr>
    ENCODING = 'charset'
    COMPRESSION = [NONE, GZIP, DEFLATE, ZSTD] | '<string>'
    FILE_EXTENSION = ['<string>']

  TYPE = 'PARQUET',
    COMPRESSION = '<string>'
    ROW_GROUP_SIZE = '<string>' | <int>

  TYPE = 'ORC'
    COMPRESSION = '<string>'
    COMPRESSION_BLOCK_SIZE = '<string>' | <int>
    STRIPE_SIZE = '<string>' | <int>
    ROW_INDEX_STRIDE = <int>

field_opt:
    {COLUMNS | FIELDS} field_term_list

field_term_list:
  field_term [, field_term ...]

field_term:
    {[OPTIONALLY] ENCLOSED | TERMINATED | ESCAPED} BY string

line_opt:
    LINES line_term_list

line_term_list:
    line_term [line_term]

line_term:
    {STARTING | TERMINATED} BY string

file_opt:
    file_option [, file_option ...]

file_option:
    SINGLE [=] {TRUE | FALSE}
    | MAX_FILE_SIZE [=] {int | string}
    | BUFFER_SIZE [=] {int | string}
```

## Parameters

### external_file_format_list

When **TYPE = 'CSV'**, it contains the following fields:

  * `LINE_DELIMITER`: Specifies the line delimiter for the CSV file, with the default being `LINE_DELIMITER='\n'`.
  * `FIELD_DELIMITER`: Optional, specifies the column delimiter for CSV files, default is `FIELD_DELIMITER='\t'`.
  * `ESCAPE`: Specifies the escape character for the CSV file, which can only be 1 byte. The default is `ESCAPE ='\'`.
  * `FIELD_OPTIONALLY_ENCLOSED_BY`: Optional, specifies the symbol used to enclose field values in a CSV file, defaulting to empty. Using this option indicates that enclosing characters are applied only to certain types of fields (such as CHAR, VARCHAR, TEXT, JSON, etc.).
  * `FIELD_ENCLOSED_BY`: Optional, specifies the symbol used to enclose field values in a CSV file. The default is empty, indicating no enclosing symbols are used. This option applies the enclosing symbol setting to all types of fields.
  * `ENCODING`: Specifies the character set encoding format of the file. If not specified, the default value is `UTF8MB4`.
  * `COMPRESSION`: Optional, specifies the file compression format, supporting four types: NONE, GZIP, DEFLATE, and ZSTD.
    * `GZIP`/`DEFLATE`: GZIP compressed file.
    * `ZSTD`: ZSTD compressed file.
    * `NONE`: Indicates that the file is not compressed (default value).
  * `FILE_EXTENSION`: Optional, specifies the user-defined file extension, used only for multi-file export and only supported by CSV format. If this parameter is not specified, the file extension is determined by the format type. The default file extension for CSV format is `.csv`.

When **TYPE = 'PARQUET'**, it contains the following fields:

  * `COMPRESSION`: Specifies the compression format for PARQUET files. The default compressed file suffix is `.parquet`. It supports seven compression formats: `UNCOMPRESSED` (indicating no compression), `SNAPPY`, `GZIP`, `BROTLI`, `ZSTD`, `LZ4`, and `LZ4_HADOOP`. If not specified, the default is `UNCOMPRESSED`.
  * `ROW_GROUP_SIZE`: Specifies the ROW GROUP size of a PARQUET file in bytes. This option accepts either a numeric value or a string in the form of `'64MB'`. If not specified, the default value is `256MB`. The default value is recommended.

When **TYPE = 'ORC'**, it includes the following fields:

  * `COMPRESSION`: Specifies the compression format for ORC files. The default compressed file suffix is `.orc`. It supports five compression formats: `UNCOMPRESSED` (indicating no compression), `SNAPPY`, `ZLIB`, `LZ4`, and `ZSTD`. If not specified, the default is `UNCOMPRESSED`.
  * `COMPRESSION_BLOCK_SIZE`: Specifies the size of data chunks during compression, measured in bytes. This option accepts either a numeric value or a string in the format of `'64KB'`. If unspecified, the default value is `256KB`. The default value is recommended.
  * `STRIPE_SIZE`: Specifies the Stripe size of ORC files in bytes. This option accepts either a numeric value or a string in the form of `'64MB'`. If not specified, the default value is `64MB`. The default value is recommended.
  * `ROW_INDEX_STRIDE`: A parameter that controls the frequency of index records, defining how often an index is recorded per number of rows. The default value is `10000` if not specified. It is recommended to use the default value.

### field_term

* `[OPTIONALLY] ENCLOSED BY string`: Used to specify the symbols that enclose field values. By default, there are no quotation symbols. For example, `ENCLOSED BY '"'` indicates that character values are placed between double quotes. If the `OPTIONALLY` keyword is used, the specified enclosing characters are applied only to string-type values.
* `TERMINATED BY string`: Used to specify the symbol between field values. For example, `TERMINATED BY ','` specifies a comma as the delimiter between two field values.
* `ESCAPED BY string`: Used to specify the escape character for handling special characters or parsing data in special formats. The default escape character is the backslash (`\`).

### line_term

* `STARTING BY string`: Specifies the starting character of each line.
* `TERMINATED BY string`: Specifies the ending character for each line, with the default being a newline character. For example, `... LINES TERMINATED BY '\n' ...` indicates that a line will end with a newline character.

### file_option

* `SINGLE [=] {TRUE | FALSE}`: specifies whether to export data to a single file or multiple files.

  * `SINGLE [=] TRUE`: specifies to export data to a single file. This is the default value.
  * `SINGLE [=] FALSE`: specifies to export data to multiple files.

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>If the parallelism is greater than 1 and <code>SINGLE = FALSE</code>, data can be exported to multiple files to achieve parallel read and write and improve the export speed.</p>
    </main>

* `MAX_FILE_SIZE [=] {int | string}`: specifies the maximum size of a file when data is exported to multiple files. This parameter takes effect only when `SINGLE = FALSE`.

* `BUFFER_SIZE [=] {int | string}`: specifies the size of memory applied for each thread for each partition when data is exported. This parameter specifies the size of memory applied for each thread for a single partition when data is not exported by partition. The default value is 1 MB.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p><ul><li>The <code>BUFFER_SIZE</code> parameter is used for export performance tuning. If the server memory is sufficient and you want to improve the export efficiency, you can set this parameter to a large value, for example, 4 MB. If the server memory is insufficient, you can set this parameter to a small value, for example, 4 KB. If you set this parameter to 0, all partitions of a thread share a public memory.</li><li>In OceanBase Database V4.3.2, the <code>BUFFER_SIZE</code> parameter is supported in V4.3.2 BP1 and later versions.</li></ul></p>
  </main>

## Examples

### Export data to a local file

1. Set the export file path.

    To export a file, you must set the system variable `secure_file_priv` to specify a path that allows access to the exported file.

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>For security reasons, when you set the system variable <code>secure_file_priv</code>, you can connect to the database only through a local socket and execute the SQL statement to modify the global variable. For more information, see <a href="../../../../../800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/12000.secure_file_priv-global.md">secure_file_priv</a>.</p>
    </main>

    1. Log in to the OBServer node where you want to connect to OceanBase Database.

        ```bash
        ssh admin@xxx.xxx.xxx.xxx
        ```

    2. Connect to the `oracle001` tenant through a local Unix socket.

        ```bash
        obclient -S /home/admin/oceanbase/run/sql.sock -usys@oracle001 -p******
        ```

    3. Set the export path to `/home/admin/test_data`.

        ```sql
        obclient> SET GLOBAL secure_file_priv = "/home/admin/test_data";
        ```

    4. Log out.

2. After you reconnect to the database, use the `SELECT INTO OUTFILE` statement to export data. Specify the comma (,) as the delimiter between field values, use `"` to enclose the values of the string type, and use the line break as the delimiter.

   * Export data to a single file in serial mode. Specify the file name as `test_tbl1.csv`.

     ```sql
     obclient> SELECT /*+parallel(2)*/ *
     INTO OUTFILE '/home/admin/test_data/test_tbl1.csv'
       FIELDS TERMINATED BY ',' OPTIONALLY ENCLOSED BY '"'
       LINES TERMINATED BY '\n'
     FROM test_tbl1;
     ```

     The return result is as follows:

     ```shell
     Query OK, 9 rows affected
     ```

   * Write data to multiple files in parallel. Do not specify a file name, and make sure that the size of each file does not exceed 4 MB.

     ```sql
     obclient> SELECT /*+parallel(2)*/ *
       INTO OUTFILE '/home/admin/test_data/'
       FIELDS TERMINATED BY ',' OPTIONALLY ENCLOSED BY '"'
       LINES TERMINATED BY '\n'
       SINGLE = FALSE MAX_FILE_SIZE = '4MB'
     FROM test_tbl1;
     ```

     The return result is as follows:

     ```shell
     Query OK, 9 rows affected
     ```

   * Write data to multiple files in parallel. Specify the file name prefix as `dd2024`, and make sure that the size of each file does not exceed 4 MB.

     ```sql
     obclient> SELECT /*+parallel(2)*/ *
       INTO OUTFILE '/home/admin/test_data/dd2024'
       FIELDS TERMINATED BY ',' OPTIONALLY ENCLOSED BY '"'
       LINES TERMINATED BY '\n'
       SINGLE = FALSE MAX_FILE_SIZE = '4MB'
     FROM test_tbl1;
     ```

     The return result is as follows:

     ```shell
     Query OK, 9 rows affected
     ```

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p><ul><li>When multiple export tasks are exporting data to the same path at the same time, errors may occur or only a part of data may be exported. You can avoid these issues by setting the export path reasonably. For example, <code>SELECT /*+parallel(2)*/ * INTO OUTFILE 'test/data' SINGLE = FALSE FROM t1;</code> and <code>SELECT /*+parallel(2)*/ * INTO OUTFILE 'test/data' SINGLE = FALSE FROM t2;</code> may fail to execute at the same time because the exported files have the same name. In this case, you can set the export path to <code>test/data1</code> and <code>test/data2</code>.</li><li>If the export fails because of an error such as "file already exist" and <code>SINGLE = FALSE</code>, you can delete all files in the export directory whose names have the same prefix as the target file name, or delete the export directory and recreate it, and then re-export data.</br>For example, if <code>SELECT /*+parallel(2)*/ * INTO OUTFILE 'test/data' SINGLE = FALSE FROM t1;</code> fails, you can delete all files whose names start with <code>data</code> in the <code>test</code> directory, or delete the <code>test</code> directory and recreate it, and then try to export data again.</li></ul></p>
    </main>

3. Log in to the server and view the exported files in the `/home/admin/test_data` directory on the OBServer node.

  ```shell
  [xxx@xxx /home/admin/test_data]# ls
  ```

  The return result is as follows:

  ```shell
  data_0_0_0  data_0_1_0  dd2024_0_0_0  dd2024_0_1_0  test_tbl1.csv
  ```

  In this example, `test_tbl1.csv` is the file name for the example that exports data to a single file in serial mode; `data_0_0_0` and `data_0_1_0` are the file names for the example that writes data to multiple files in parallel without specifying a file name; `dd2024_0_0_0` and `dd2024_0_1_0` are the file names for the example that writes data to multiple files in parallel with the file name prefix set to `dd2024`.

### Export data to OSS

You can execute the `SELECT INTO OUTFILE` statement to export data from the `test_tbl2` table to a specified OSS storage location based on partitions. The partitions are determined by the combination of the `col1` and `col2` columns. Rows with the same values in these two columns are considered to be in the same partition and exported to the same directory.

```sql
obclient> SELECT /*+parallel(3)*/ *
  INTO OUTFILE 'oss://$DATA_FOLDER_NAME/?host=$OSS_HOST&access_id=$OSS_ACCESS_ID&access_key=$OSS_ACCESS_KEY'
    PARTITION BY CONCAT(col1,'/',col2)
    SINGLE = FALSE BUFFER_SIZE = '2MB'
FROM test_tbl2;
```

The storage location is specified by the `$DATA_FOLDER_NAME` variable. You also need to provide the host address, access ID, and access key of the OSS service.
