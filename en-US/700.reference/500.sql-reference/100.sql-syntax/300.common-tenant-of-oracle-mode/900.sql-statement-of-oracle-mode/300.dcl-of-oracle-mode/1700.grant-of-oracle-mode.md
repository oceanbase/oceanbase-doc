# GRANT

## Purpose

This statement is used by system administrators to grant permissions to users, including object permissions, system permissions, and roles.

## Privilege requirements

When executing the `GRANT` statement, the current user must have the granted privileges and the privilege to grant those privileges. For example, if user `user1` wants to grant the `SELECT` permission on table `tbl1` to user `user2`, user `user1` must have the `SELECT` permission on table `tbl1` and the privilege to grant the `SELECT` permission on table `tbl1`.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>After granting permissions to a user, the user needs to reconnect to OceanBase Database for the permissions to take effect. </p>
</main>

## Syntax

```sql
/* Grant object privileges */
GRANT {obj_all_col_priv [, obj_all_col_priv...]}
    ON obj_clause
    TO {grant_user [, grant_user...]}
    [WITH GRANT OPTION]

/* Grant system privileges or roles */
GRANT obj_all_col_priv [, obj_all_col_priv...]
    TO grantee_clause
    [WITH ADMIN OPTION]

grantee_clause:
      grant_user [, grant_user...]
    | grant_user IDENTIFIED BY password

obj_all_col_priv:
      role
    | sys_and_obj_priv [(column_list)]
    | ALL [PRIVILEGES] [(column_list)]
    | READ
    | WRITE

obj_clause:
    schema_name.relation_name
    | LOCATION location_name
    | SENSITIVE RULE relation_name
```

## Parameters

|        Parameter         |                                         Description                                          |
|-------------------|-------------------------------------------------------------------------------------|
| obj_all_col_priv | The privilege to be granted. You can directly or indirectly grant privileges to a user by granting privileges or roles. When multiple privileges are granted to a user, the privilege types are separated by commas (`,`). For more information about the privilege types, see [Privilege types](../../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/300.permission-of-oracle-mode/000.permission-classification-of-oracle-mode.md).         |
| obj_clause | The object to which the privilege is granted. For more information, see [obj_clause](#obj_clause).|
| grant_user | The user or role to which the privilege is granted. Valid values: <ul><li>`user [USER_VARIABLE]`: grants the privilege to a specific user.</li><li>`CONNECT`: grants the privilege to the CONNECT role.</li><li>`RESOURCE`: grants the privilege to the RESOURCE role.</li><li>`PUBLIC`: grants the privilege to the public role.</li></ul>|
| IDENTIFIED BY password | The password of the user to which the privilege is granted. The password is stored in plain text in the `dba_users` table and then encrypted by the server. If the password contains special characters <code>~!@#%^&*_-+=`\|(){}[]:;',.?/</code>, enclose it in double quotation marks ( <code>""</code> ).  |
| WITH GRANT OPTION | Specifies whether the privilege can be granted to other users. If this option is specified, revoking the privilege will also revoke it from all users who have been granted the privilege.                                                                 |
| WITH ADMIN OPTION | Specifies whether the privilege can be granted to other users. If this option is specified, revoking the privilege will not revoke it from users who have been granted the privilege.                                                                |
| role | The role to be granted. Valid values: <ul><li>`role_name`: the name of a custom role.</li><li>`DBA`: the database administrator role. Users with this role have full database management privileges and can execute any database operation.</li><li>`RESOURCE`: the RESOURCE role.</li><li>`CONNECT`: the CONNECT role.</li><li>`PUBLIC`: the public role.</li></ul> |

### obj_clause

* `schema_name.relation_name`: specifies that the privilege applies to database objects, such as tables, views, and sequences.
* `LOCATION location_name`: specifies that the privilege applies to a Location object. You can grant the following privileges to a user on a Location object:

  * `READ`: specifies the read privilege on a Location object.
  * `WRITE`: specifies the write privilege on a Location object.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>For OceanBase Database V4.4.x, the <code>GRANT</code> statement supports the <code>LOCATION</code> parameter and the corresponding <code>READ</code> and <code>WRITE</code> privileges starting from V4.4.1. </p>
  </main>

* `SENSITIVE RULE relation_name`: specifies that the privilege applies to a **sensitive data protection rule** named `relation_name`. For more information about the rule semantics, see [CREATE SENSITIVE RULE](../100.ddl-of-oracle-mode/2150.create-sensitive-rule-of-oracle-mode.md).

### System privileges related to sensitive data protection rules

In addition to object-level privileges, you can also grant system privileges related to sensitive data protection rules, such as:

* `CREATE SENSITIVE RULE`: allows you to create a sensitive data protection rule.
* `PLAINACCESS ANY SENSITIVE RULE`: allows you to access columns protected by a sensitive data protection rule in plain text (used in scenarios such as O&M where data desensitization needs to be bypassed. Use this privilege with caution.)

System privileges are granted using the `GRANT ... TO grantee_clause` syntax and do not require the `ON` clause.

## Examples

* Grant the `CREATE VIEW` privilege to `user1` and allow the privilege to be granted to other users.

  ```shell
  obclient> GRANT CREATE VIEW TO user1 WITH ADMIN OPTION;
  ```

* Grant the `CONNECT` role to `user1` and modify the password for `user1`.

  ```shell
  obclient> GRANT CONNECT TO user1 IDENTIFIED by '********';
  ```

  After the preceding statements are executed, query the `dba_users` table for the password of `user1`. The password is updated to the new one.

* Grant the COMMENT ANY TABLE privilege to the `role1` role.

  ```shell
  obclient> GRANT COMMENT ANY TABLE TO role1;
  ```

* Grant the read privilege on the `local_t` object in the Location schema to `user006`.

  ```sql
  obclient> GRANT READ ON LOCATION local_t TO user006;
  ```

* Grant the system privilege to `user1` to create data sensitivity rules.

  ```sql
  obclient> GRANT CREATE SENSITIVE RULE TO user1;
  ```

* Grant the system privilege to `user1` to access sensitive rules in plaintext. (Use this privilege with caution.)

  ```sql
  obclient> GRANT PLAINACCESS ANY SENSITIVE RULE TO user1;
  ```
