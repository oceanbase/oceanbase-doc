# SHOW

## Purpose

This statement is used to display information about database objects.

## Syntax

```sql
SHOW {
  | TABLE STATUS
  | [FULL] PROCESSLIST
  | RECYCLEBIN
  | VARIABLES [LIKE 'pattern']
  | PARAMETERS
  | CHARSET | CHARACTER SET
  | COLLATION
  | CREATE TABLEGROUP tablegroup_name
  | CREATE TABLE table_name
  | CREATE VIEW view_name
  | GRANTS
  | PRIVILEGES
  | ERRORS
  | TRACE [FORMAT='JSON']
  | FILES IN LOCATION @location_name['/path'] [PATTERN = 'regex_pattern']
};
```

## Parameters

|    Parameter |    Description     |
|-----------|------------|
| TABLE STATUS                       | Displays detailed information about all tables in the current user.  |
| VARIABLES \[like 'variable_name'\] | Displays variable information. If you do not specify `like 'variable_name'`, all system variable information is displayed. `variable_name` is the name of the variable. |
| CHARSET \| CHARACTER SET           | Displays supported character sets. |
| COLLATION                          | Displays supported collations.  |
| PARAMETERS                         | Displays all system configuration items.  |
| TABLEGROUPS                        | Displays table group information.   |
| CREATE TABLEGROUP tablegroup_name  | Displays the statement for creating a table group. `tablegroup_name` is the name of the table group.      |
| CREATE TABLE table_name            | Displays the statement for creating a table. `table_name` is the name of the table.|
| CREATE VIEW view_name              | Displays the statement for creating a view. `view_name` is the name of the view.  |
| ERRORS                             | Displays error information. |
| GRANTS                             | Displays the privileges of the current user. |
| PRIVILEGES                         | Displays descriptions of various privileges.|
| RECYCLEBIN                         | Displays the recycle bin. |
| \[FULL\] PROCESSLIST                 | Displays the current tenant's process list. Details are as follows:<ul><li><code>SHOW PROCESSLIST</code> displays a brief process list, as follows:  <ul><li><code>ID</code>: the process ID, which is the Client Session ID of the current session. This ID uniquely identifies the session in the client.</li><li><code>USER</code>: the username of the connected user.</li><li><code>HOST</code>: the client IP address and port (or the IP address and port of the ODP if connected through ODP).</li><li><code>DB</code>: the name of the database being accessed.</li><li><code>COMMAND</code>: the type of the command being executed, which can be <code>Query</code>, <code>Sleep</code>, etc.</li><li><code>TIME</code>: the execution time of the current command, in seconds. If the command is retried, this value is reset to zero and recalculated.</li><li><code>STATE</code>: the current session state, which can be <code>SLEEP</code>, <code>ACTIVE</code>, etc.</li><li><code>INFO</code>: displays the command currently being executed, with a length limit of 100 characters. Excess characters are truncated.</li></ul>  </li><li><code>SHOW FULL PROCESSLIST</code>: displays the full process list, including detailed information for each process, as follows:  <ul><li><code>ID</code>: the process ID, which is the Client Session ID of the current session. This ID uniquely identifies the session in the client.</li><li><code>USER</code>: the username of the connected user.</li><li><code>TENANT</code>: the connected tenant.</li><li><code>HOST</code>: the client IP address and port (or the IP address and port of the ODP if connected through ODP).</li><li><code>DB</code>: the name of the database being accessed.</li><li><code>COMMAND</code>: the type of the command being executed, which can be <code>Query</code>, <code>Sleep</code>, etc.</li><li><code>TIME</code>: the execution time of the current command, in seconds. If the command is retried, this value is reset to zero and recalculated.</li><li><code>STATE</code>: the current session state, which can be <code>SLEEP</code>, <code>ACTIVE</code>, etc.</li><li><code>INFO</code>: displays the command currently being executed.</li><li><code>IP</code>: the server IP address.</li><li><code>PORT</code>: the SQL port number.</li></ul>  </li></ul>  <main id="notice" type='explain'><h4>Note</h4><p>To query the number of sessions and their IDs in the current database using the <code>SHOW PROCESSLIST</code> statement, see <a href="../../../../../1200.database-proxy/1500.view-tenant-sessions.md">View tenant sessions</a>. </p></main>|
| TRACE [FORMAT='JSON']              | Displays the execution status of SQL statements. You can choose to output the information in JSON format.|
| FILES IN LOCATION @location_name['/path'] [PATTERN = 'regex_pattern'] | Displays files in the specified location.<ul><li>`['/path']` is an optional parameter that specifies a subdirectory.</li><li>`PATTERN = 'regex_pattern'` is an optional parameter that specifies a regular expression to filter files in the location directory.</li></ul> <main id="notice" type='explain'><h4>Note</h4><p><ul><li>To execute the <code>SHOW FILES IN LOCATION</code> statement, the current user must have the <code>READ</code> privilege on the location object.</li><li>Starting from OceanBase Database V4.4.1, this syntax is supported in OceanBase Database V4.4.x. </li></ul></p></main>|

## Examples

* View the creation information of the `tbl1` table.

  ```sql
    obclient> CREATE TABLE employees (
      emp_id INT PRIMARY KEY,
      emp_name VARCHAR(50) NOT NULL,
      hire_date DATE,
      salary NUMBER(10,2),
      department VARCHAR(30)
    );
    obclient> SHOW CREATE TABLE employees;
  ```

* View whether the recycle bin is enabled.

  ```sql
  obclient> SHOW VARIABLES LIKE 'recyclebin';
  ```

* View the contents of the recycle bin.

  ```sql
  obclient> SHOW RECYCLEBIN;
  ```

* Use `SHOW TRACE` to view the execution information of a specific SQL statement and output the information in JSON format.

  ```shell
  obclient> SET ob_enable_show_trace = 1;

  obclient> CREATE TABLE space_travelers (
      astronaut_id INT PRIMARY KEY,
      mission_code VARCHAR(50) NOT NULL,
      launch_date DATE,
      flight_hours NUMBER(10,2),
      space_station VARCHAR(30)
  );

  obclient> INSERT INTO space_travelers VALUES(1, 'APOLLO-11', TO_DATE('1969-07-16', 'YYYY-MM-DD'), 195.5, 'MOON');

  obclient> INSERT INTO space_travelers VALUES(2, 'ISS-EXP-1', TO_DATE('2000-11-02', 'YYYY-MM-DD'), 4320.8, 'ISS');

  obclient> SELECT/*+PARALLEL(2)*/ COUNT(*) FROM space_travelers;

  obclient> SHOW TRACE FORMAT='JSON'\G
  ```
