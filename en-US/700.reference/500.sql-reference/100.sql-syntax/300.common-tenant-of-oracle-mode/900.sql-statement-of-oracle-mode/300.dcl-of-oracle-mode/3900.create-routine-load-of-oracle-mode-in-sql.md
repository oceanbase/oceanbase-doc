# CREATE ROUTINE LOAD

## Purpose

This statement is used to create a Routine Load task that continuously consumes data from Kafka and imports it into a table in OceanBase Database.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>Routine Load is an automatically executed data import process in the background. After you create a Routine Load job, the system automatically consumes data from Kafka and imports it into the target table at regular intervals. </p>
</main>

## Privilege requirements

To create a Routine Load job, you must have the `INSERT` privilege on the target table. For more information about the privileges of OceanBase Database, see [Privilege classification in Oracle mode](../../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/300.permission-of-oracle-mode/000.permission-classification-of-oracle-mode.md).

## Syntax

```sql
CREATE ROUTINE LOAD job_name ON table_name
    [load_property_list]
    FROM STREAM (
        [TYPE = 'KAFKA']
        STRING = STRING
        FORMAT [=] (format_options));

load_property_list:
    PARALLEL [=] int_value
    | COLUMNS (col1, col2, ...)
    | PARTITION (partition_name_list)
    | {IGNORE | REPLACE}
    | WHERE condition

STRING = STRING:
    'bootstrap.servers' = 'string_value',
    'kafka_topic' = 'string_value',
    ['kafka_partitions' = 'string_value',]
    ['kafka_offsets' = 'string_value',]
    ['max_batch_interval' = 'string_value',]
    ['max_batch_rows' = 'string_value',]
    ['max_batch_size' = 'string_value',]

format_options:
    TYPE = 'CSV',
    LINE_DELIMITER = '<string>' | <expr>,
    FIELD_DELIMITER = '<string>' | <expr>,
    ESCAPE = '<character>' | <expr>,
    FIELD_OPTIONALLY_ENCLOSED_BY = '<character>' | <expr>,
    ENCODING = 'charset',
    NULL_IF = ('<string>' | <expr>, '<string>' | <expr> ...),
    SKIP_BLANK_LINES = {TRUE | FALSE},
    TRIM_SPACE = {TRUE | FALSE},
    EMPTY_FIELD_AS_NULL = {TRUE | FALSE}
```

## Parameters

| **Parameter** |       **Description**           |
|----------|--------------------------|
| job_name | The name of the job, which must be unique in the current tenant. It is used to identify the Routine Load job.|
| table_name | The name of the target table. Data is imported to this table.|
| load_property_list | An optional parameter that specifies data loading properties, such as the concurrency level, column mapping, partitions, conflict resolution strategy, and filter conditions. For more information, see [load_property_list](#load_property_list) below.|
| FROM STREAM | Specifies parameters related to the data source type.|
| TYPE = 'KAFKA' | An optional parameter that specifies the data source type. If this parameter is not specified, the default value is `KAFKA`. <main id="notice" type='explain'><h4>Note</h4><p>In the current version, only <code>'KAFKA'</code> is supported as the data source type. </p></main>|
| STRING = STRING | Specifies a list of Kafka-related configuration parameters in the form of key-value pairs. **The key names are case-sensitive.** In addition to format-related parameters, you can also specify standard Kafka consumer parameters, such as `security.protocol` and `sasl.mechanism`. **You do not need to specify** `group.id`. The system will automatically establish a mapping between the consumer threads and partitions based on the concurrency level. For more information, see [kafka_expr_list](#kafka_expr_list) below.|
| FORMAT [=] (format_options) | Specifies Kafka data format-related parameters. `format_options` specifies Kafka data format options. For more information, see [format_options](#format_options) below.|

### load_property_list

* `PARALLEL [=] int_value`: specifies the concurrency level. The default value is 1.
* `COLUMNS (col1, col2, ...)` : specifies the mapping between Kafka message columns and target table columns.
* `PARTITION (partition_name_list)` : specifies the target partitions to import data into.
* `{IGNORE | REPLACE}` : specifies the conflict resolution strategy for primary keys or unique keys.

  * `IGNORE`: specifies to ignore conflicting rows.

* `WHERE condition`: specifies the data filter condition. The condition is applied before the data is written to the target table.

### kafka_expr_list

* `bootstrap.servers`: specifies the list of Kafka broker addresses. Multiple addresses are separated by commas, for example, `broker1:9092,broker2:9092`. This parameter specifies the entry address for the client to connect to Kafka for the first time.
* `kafka_topic`: specifies the name of the Kafka topic to consume.
* `kafka_partitions`: specifies the list of partitions to consume, for example, `"0,1,2"`. If this parameter is not specified, all partitions of the topic are consumed.
* `kafka_offsets`: specifies the starting offset for each partition. It corresponds to `kafka_partitions` in one-to-one mapping. That is, it specifies the starting offset for each partition. If only one value is specified, it applies to all partitions. If this parameter is not specified, the system will subscribe to all partitions of the topic from `OFFSET_END` by default. Currently, you can mix numbers with `OFFSET_BEGINNING` and `OFFSET_END`.
* `"max_batch_interval"`: specifies the maximum running time of each import thread in each round of the job, in seconds. The default value is 60s. The value is related to the number of import threads and the concurrency level `PARALLEL`.
* `"max_batch_rows"`: specifies the maximum number of rows that each import thread can read in each round of the job. The value must be greater than or equal to 200000. The default value is 10000000.
* `"max_batch_size"`: specifies the maximum number of bytes that each import thread can read in each round of the job, in bytes. The value ranges from 100MB to 1GB. The default value is 1GB.

**Term explanations**:

* **offset (consumption point)**: the logical position of each message in a Kafka partition. `OFFSET_BEGINNING` specifies to start from the earliest readable message in the partition. `OFFSET_END` specifies to start from the current latest position.
* **low / high watermark**: the minimum and maximum offset that can be consumed in a Kafka partition. The specified offset must not be lower than the low watermark.

### format_options

Currently, only the **CSV** format is supported. The syntax aligns with the existing CSV parsing capabilities of OceanBase Database. For more information, see the format description in [LOAD DATA](1900.load-data-of-oracle-mode.md). The following are some commonly used options:

* `TYPE`: specifies the data format. Currently, only the CSV format is supported.
* `LINE_DELIMITER`: specifies the line delimiter of the CSV file. The default value is `LINE_DELIMITER='\n'`.
* `FIELD_DELIMITER`: specifies the column delimiter of the CSV file. The default value is `FIELD_DELIMITER='\t'`.
* `ESCAPE`: specifies the escape character of the CSV file. It must be one byte. The default value is `ESCAPE ='\'`.
* `FIELD_OPTIONALLY_ENCLOSED_BY`: specifies the symbol that wraps field values in the CSV file. The default value is an empty string. This option is used to wrap only specific types of fields, such as CHAR, VARCHAR, TEXT, and JSON.
* `ENCODING`: specifies the character set encoding format of the file. If this parameter is not specified, the default value is `UTF8MB4`.
* `NULL_IF`: specifies the string that is treated as `NULL`. The default value is an empty string.
* `SKIP_BLANK_LINES`: specifies whether to skip blank lines. The default value is `FALSE`, which indicates that blank lines are not skipped.
* `TRIM_SPACE`: specifies whether to remove leading and trailing spaces in the fields of the file. The default value is `FALSE`, which indicates that leading and trailing spaces in the fields of the file are not removed.
* `EMPTY_FIELD_AS_NULL`: specifies whether to treat an empty string as `NULL`. The default value is `FALSE`, which indicates that an empty string is not treated as `NULL`.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>Routine Load does not support <code>PARSE_HEADER</code> and <code>SKIP_HEADER</code> for CSV parsing. That is, you cannot treat the first line as the column names or skip the header line. </p>
</main>

## Examples

Create a routine load job named `load_job_0` to import data from Kafka to the `test_db.test_tbl1` table.

```sql
obclient> CREATE ROUTINE LOAD load_job_0 ON test_db.test_tbl1
    PARALLEL = 3
    WHERE id > 0
    FROM STREAM (
        TYPE = 'KAFKA',
        'bootstrap.servers' = 'xxx.xxx.xxx.1:xxxx',
        'security.protocol' = 'sasl_plaintext',
        'sasl.mechanism' = 'PLAIN',
        'sasl.username' = '******',
        'sasl.password' = '******',
        'kafka_topic' = 'test-topic',
        'kafka_partitions' = '0,1,2',
        'kafka_offsets' = '0,0,OFFSET_BEGINNING',
        'max_batch_interval' = '3000000',
        'max_batch_rows' = '200000',
        'max_batch_size' = '104857600',
        FORMAT = (
            TYPE = 'CSV',
            FIELD_DELIMITER = ',',
            TRIM_SPACE = TRUE)
        );
```
