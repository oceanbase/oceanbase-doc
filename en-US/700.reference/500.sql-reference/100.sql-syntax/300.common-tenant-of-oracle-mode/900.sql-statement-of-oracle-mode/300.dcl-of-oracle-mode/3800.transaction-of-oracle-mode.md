# TRANSACTION

## Purpose

This statement is used to start a transaction.

A database transaction is a series of operations executed as a single logical unit. Transaction processing is used to maintain database integrity by ensuring that all SQL operations in a batch are either fully executed or not executed at all.

Explicit transactions are user-defined or user-specified transactions. They are explicitly started using the `BEGIN` or `BEGIN WORK` statement (which are aliases for `START TRANSACTION`) and explicitly ended using the `COMMIT` or `ROLLBACK` statement.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <ul>
    <li>Before committing a transaction, you can execute a <code>SELECT</code> statement to check whether the operations in the transaction have taken effect.</li>
    <li>Before committing a transaction, sessions outside the current transaction cannot see the operations in the transaction. That is, before committing a transaction, only the current transaction session can access the latest results, and sessions outside the current transaction cannot see the latest results.</li>
    <li>If you want to roll back the transaction, use <code>ROLLBACK</code> instead of <code>COMMIT</code>.</li>
    </ul>
  </main>

## Syntax

```sql
{
  | START TRANSACTION [READ ONLY | READ WRITE]
  | BEGIN [WORK]
  | COMMIT [WORK]
  | ROLLBACK [WORK]
  | SET TRANSACTION {READ ONLY | READ WRITE}
}
```

## Parameters

| Parameter    | Description   |
|------------|---------|
| START TRANSACTION [READ ONLY \| READ WRITE] | Starts a transaction. Once a transaction is started, subsequent SQL data operation statements (such as `INSERT`, `UPDATE`, and `DELETE`) will only take effect after an explicit commit.<br>- `READ ONLY`: Starts a transaction in read-only mode, where no modification operations are allowed within the transaction.<br>- `READ WRITE`: Starts a transaction in read-write mode (default mode) |
| BEGIN         | `BEGIN` and `BEGIN WORK` are aliases for `START TRANSACTION`       |
| COMMIT                                  | Commits the current transaction         |
| ROLLBACK                                | Rolls back the current transaction          |
| SET TRANSACTION {READ ONLY \| READ WRITE} | Sets the current transaction to `READ ONLY` or `READ WRITE` mode    |

## Examples

This section provides examples of using transaction-related statements.

1. Create an example table `employees` and insert data:

   ```sql
   obclient> CREATE TABLE employees (
     emp_id INT,
     emp_name VARCHAR(10),
     salary INT
   );

   obclient> INSERT INTO employees VALUES
     (1, 'Alice', 5000),
     (2, 'Bob', 6000),
     (3, 'Charlie', 4500);
   ```

   View the initial data:

   ```sql
   obclient> SELECT * FROM employees;
   ```

   Result:

   ```sql
   +--------+---------+--------+
   | EMP_ID | EMP_NAME| SALARY |
   +--------+---------+--------+
   |      1 | Alice   |   5000 |
   |      2 | Bob     |   6000 |
   |      3 | Charlie |   4500 |
   +--------+---------+--------+
   ```

2. Example of committing a transaction: Start a transaction, update employee information, and add a new employee

   ```sql
   obclient> START TRANSACTION;

   obclient> UPDATE employees SET emp_name = 'Charles' WHERE emp_id = 3;
   obclient> INSERT INTO employees VALUES (4, 'David', 5500);

   obclient> COMMIT;
   ```

   View the updated data:

   ```sql
   obclient> SELECT * FROM employees;
   ```

   Result:

   ```sql
   +--------+---------+--------+
   | EMP_ID | EMP_NAME| SALARY |
   +--------+---------+--------+
   |      1 | Alice   |   5000 |
   |      2 | Bob     |   6000 |
   |      3 | Charles |   4500 |
   |      4 | David   |   5500 |
   +--------+---------+--------+
   ```

3. Example of rolling back a transaction: Start a transaction, make modifications, and then roll back

   ```sql
   obclient> BEGIN;

   obclient> UPDATE employees SET emp_name = 'Eve' WHERE emp_id = 3;
   obclient> INSERT INTO employees VALUES (5, 'Frank', 7000);

   -- View the changes in the transaction
   obclient> SELECT * FROM employees;
   ```

   Result:

   ```sql
   +--------+---------+--------+
   | EMP_ID | EMP_NAME| SALARY |
   +--------+---------+--------+
   |      1 | Alice   |   5000 |
   |      2 | Bob     |   6000 |
   |      3 | Eve     |   4500 |
   |      4 | David   |   5500 |
   |      5 | Frank   |   7000 |
   +--------+---------+--------+
   ```

   Execute the rollback:

   ```sql
   obclient> ROLLBACK;
   ```

   View the data after the rollback:

   ```sql
   obclient> SELECT * FROM employees;
   ```

   Result:

   ```sql
   +--------+---------+--------+
   | EMP_ID | EMP_NAME| SALARY |
   +--------+---------+--------+
   |      1 | Alice   |   5000 |
   |      2 | Bob     |   6000 |
   |      3 | Charles |   4500 |
   |      4 | David   |   5500 |
   +--------+---------+--------+
   ```
