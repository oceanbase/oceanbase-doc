# BACKUP KEY

## Purpose

If the original tenant has configured transparent data encryption before data backup, you must use the `ALTER SYSTEM BACKUP KEY` statement to back up the key for the source tenant.

## Limitations and considerations

You must back up the source tenant's keys again after you back up the new keys.

## Privilege requirements

It must be executed by the `root` user of the `sys` tenant (`root@sys`) or the administrator of each tenant.

* In MySQL mode, the default administrator user is `root`.
* For Oracle compatibility mode, the default admin user is `SYS`.

## Syntax

```sql
ALTER SYSTEM BACKUP KEY [TENANT [=] {tenant_name[, tenant_name]...}] TO 'backup_key_path' [ENCRYPTED BY 'password'];
```

## Parameters

| Parameter           | Description                                                                                                                                |
|-----------------------|--------------------------------------------------------------------------------------------------------------------------------------------|
| tenant_name           | Specifies the tenant name of the key to be backed up. You can specify multiple tenant names. Different tenant names are separated by commas. If you do not specify the tenant name, the keys of all user tenants in the backup cluster are backed up. <main id="notice" type='notice'> <h4>Notice</h4><p>Only the sys tenant can specify the target tenant using the <code>TENANT = tenant_name</code> clause. User tenants can only execute the command on themselves and cannot use the <code>TENANT = tenant_name</code> clause. </p></main>                        |
| backup_key_path       | The path where the keys are to be backed up. The path is defined by the user and must differ from the data backup or log archive path.                                                     |
| password              | Specifies the encryption password for the key backup path. If not specified, the backup path is not encrypted by default.                                                                                 |

## Examples

* On the sys tenant, run the following statement to grant the privileges on the tenant database:

* As the sys tenant, back up the keys of the `mysql_tenant` tenant to the `file:///data_backup_dest/key` path and set the encryption password.

  ```sql
  obclient [oceanbase]> ALTER SYSTEM BACKUP KEY TENANT = mysql_tenant TO 'file:///data_backup_dest/key' ENCRYPTED BY '******';
  ```

* The `mysql_tenant` tenant backs up the tenant key to the `file:///data_backup_dest/key` path.

  ```sql
  obclient [oceanbase]> ALTER SYSTEM BACKUP KEY TO 'file:///data_backup_dest/key';
  ```
