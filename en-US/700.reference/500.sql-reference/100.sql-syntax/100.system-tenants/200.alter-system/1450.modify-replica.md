# MODIFY REPLICA

## Purpose

This statement is used to change the type of a log stream replica.

## Limitations and considerations

* After modifying the replica type, ensure that the log stream can still form a majority. Otherwise, an error will occur during maintenance commands.

* This statement can only modify the type of one replica at a time.

* For the same log stream in a tenant, only one disaster recovery task can be executed at a time, except for replica migration tasks, which can be executed in parallel.

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>The sys tenant can check the <code>CDB_OB_LS_REPLICA_TASKS</code> view to confirm if there are ongoing disaster recovery tasks. User tenants can check the <code>DBA_OB_LS_REPLICA_TASKS</code> view for the same information.</p>
    </main>

## Privilege requirements

The user executing this statement must have the `ALTER SYSTEM` privilege. For more information about OceanBase Database privileges, see [Privilege types in MySQL mode](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md) and [Privilege types in Oracle mode](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/300.permission-of-oracle-mode/000.permission-classification-of-oracle-mode.md).

## Syntax

```sql
ALTER SYSTEM MODIFY REPLICA
    LS [=] ls_id
    SERVER [=] 'svr_ip:svr_port'
    REPLICA_TYPE [=] 'replica_type'
    [PAXOS_REPLICA_NUM [=] paxos_replica_num]
    [TENANT [=] 'tenant_name'];
```

## Parameters

|     **Parameter**      |             **Description**               |
|-------------------|------------------------------------|
| ls_id             | The ID of the log stream whose replica type is to be changed.|
| svr_ip:svr_port   | The IP address and port of the target server for the replica type change. For example, `xxx.xx.xxx.001:2882`.|
| replica_type      | The target replica type after the change. Currently, the following two replica types can be converted to each other (case-insensitive):<ul><li>Full-featured replica: specified by <code>FULL</code> or <code>F</code>.</li><li>Read-only replica: specified by <code>READONLY</code> or <code>R</code>.</li></ul>  <main id="notice" type='explain'><h4>Note</h4><p>A <code>F</code> replica can be elected as the leader (primary replica), while a <code>R</code> replica cannot be elected as the leader.</p></main>|
| paxos_replica_num | Optional. The number of required members for the leader of the log stream. If not specified, the system will use the current default value of `paxos_replica_num`. Additionally, the maximum number of full-featured replicas (F replicas) in a log stream is 7.<main id="notice" type='notice'><h4>Notice</h4><p>When specifying the value of this parameter, note the following:<ol><li>If a <code>F</code> replica is converted to a <code>R</code> replica, it is equivalent to removing a leader replica. Therefore, the value of <code>paxos_replica_num</code> needs to be decreased by 1.</li><li>If a <code>R</code> replica is converted to a <code>F</code> replica, it is equivalent to adding a leader replica. Therefore, the value of <code>paxos_replica_num</code> needs to be increased by 1.</li><li>After the modification, <code>paxos_replica_num</code> must satisfy the majority requirement.</li><li>The value of <code>paxos_replica_num</code> must be greater than or equal to the number of members in the <code>MEMBER_LIST</code> of the current leader replica. The sys tenant can check the <code>CDB_OB_LS_LOCATIONS</code> view for this information; user tenants can check the <code>DBA_OB_LS_LOCATIONS</code> view.</li><li>The absolute value of the change in <code>paxos_replica_num</code> cannot exceed 1. For example, if the current value of <code>paxos_replica_num</code> is 3, it can only be changed to 2 or 4.</li></ol>If any of the above conditions are not met, an error will be reported.</p></main>|
| tenant_name       | Optional. The name of the tenant to operate on. If not specified, the current tenant is used as the default.<main id="notice" type='notice'><h4>Notice</h4><p>The sys tenant can specify other tenants, while user tenants can only specify their own tenant. This statement does not support using <code>ALL</code>, <code>ALL_USER</code>, or <code>ALL_META</code> to specify all tenants, user tenants, or all meta tenants.</p></main>|

## Examples

Execute the following command in the sys tenant to convert a log stream replica of type `F` to type `R` in the `mysql001` tenant.

```sql
ALTER SYSTEM MODIFY REPLICA
    LS = 1001
    SERVER = 'xxx.xxx.xxx.001:2882'
    REPLICA_TYPE = 'R'
    PAXOS_REPLICA_NUM = 2
    TENANT = 'mysql001';
```

For more examples of changing the replica type of a log stream, see [Change the replica type](../../../../../600.manage/300.replica-management/200.replica-distribution/200.locality-common-operations/450.change-the-replica-type.md).
