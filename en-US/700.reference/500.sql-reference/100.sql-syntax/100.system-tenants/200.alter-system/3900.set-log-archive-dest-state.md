# SET LOG_ARCHIVE_DEST_STATE

## Purpose

The `SET LOG_ARCHIVE_DEST_STATE` statement is used to set the status of the archive destination.

## Privilege requirements

This statement must be executed by the `root` user of the `sys` tenant (`root@sys`) or the administrator user of each tenant. Specifically:

* The default administrator user in MySQL-compatible mode is the `root` user.
* The default administrator user in Oracle-compatible mode is the `SYS` user.

## Syntax

```sql
ALTER SYSTEM SET LOG_ARCHIVE_DEST_STATE={'ENABLE' | 'DEFER'} [TENANT = tenant_name];
```

## Parameters

| Parameter                    | Description                                                                                                   |
|-------------------------|--------------------------------------------------------------------------------------------------------|
| 'ENABLE' \| 'DEFER'     | Specifies the status of the archive destination:<ul><li>`ENABLE`: the enabled status. When the archive destination is in this status and the archive mode is enabled, but no archive tasks have been executed, the system will start executing archive tasks. By default, the archive destination is in this status after successful configuration.</li> <li>`DEFER`: the deferred status. When the archive destination is in this status, the archive mode is enabled, and archive tasks are present, the system will pause the archive tasks.</li></ul>                                                                   |
| tenant_name             | The name of the tenant for which the archive destination status is to be set. Only one tenant can be specified per statement.<main id="notice" type='notice'><h4>Notice</h4><p>Only the system tenant needs to specify the target tenant using the <code>TENANT tenant_name</code> clause when executing this command. User tenants can only execute this command for themselves, so this clause is not required.</p></main>  |

## Examples

Assume that the archive destination has been configured for the `mysql_tenant` tenant. Here are some examples:

* The system tenant pauses log archiving for the `mysql_tenant` tenant at the destination.

  ```sql
  obclient [oceanbase]> ALTER SYSTEM SET LOG_ARCHIVE_DEST_STATE = 'DEFER' TENANT = mysql_tenant;
  ```

* The `mysql_tenant` tenant starts log archiving at the destination.

  ```sql
  obclient [oceanbase]> ALTER SYSTEM SET LOG_ARCHIVE_DEST_STATE = 'ENABLE';
  ```
