# RECOVER STANDBY CANCEL

## Purpose

During the process of segment log replay or continuous log replay for a standby tenant, you can use the `ALTER SYSTEM RECOVER... CANCEL` statement to cancel the log replay of the standby tenant.

## Privilege requirements

This statement must be executed by the `root` user of the `sys` tenant (`root@sys`) or the administrator user of each tenant. Specifically:

* In MySQL mode, the default administrator user is `root`.
* In Oracle mode, the default administrator user is `SYS`.

## Syntax

```sql
ALTER SYSTEM RECOVER STANDBY [TENANT [=] tenant_name] CANCEL;
```

## Parameters

| Parameter | Description |
|------------|------------------------------------------------------------------------------------------------------------|
| tenant_name | Specifies the standby tenant whose log replay needs to be canceled. Only one standby tenant can be specified at a time. If multiple tenants need to be specified, the command must be executed multiple times. <main id="notice" type='notice'> <h4>Notice</h4> <p>Only the system tenant needs to specify the target tenant using the <code>TENANT = tenant_name</code> clause. Regular tenants can only execute this command for themselves and cannot use the <code>TENANT = tenant_name</code> clause. </p></main> |

## Examples

* Cancel the log replay of the standby tenant `restore_oracle_tenant` in the cluster.

  ```sql
  obclient [oceanbase]> ALTER SYSTEM RECOVER STANDBY TENANT restore_oracle_tenant CANCEL;
  ```

* Cancel the log replay of the standby tenant `restore_oracle_tenant`.

  ```shell
  obclient [SYS]> ALTER SYSTEM RECOVER STANDBY CANCEL;
  ```
