# DELETE BACKUP POLICY

You can execute the `ADD DELETE BACKUP POLICY` statement to set a deletion strategy and the `DROP DELETE BACKUP POLICY` statement to drop a deletion strategy.

If you want to enable the automatic cleanup feature for a user, you can use the `ADD DELETE BACKUP POLICY` statement to set a deletion strategy for the tenant. A tenant with a deletion strategy in effect will trigger an automatic cleanup task every hour.

While an automatic cleanup task is being executed, you can use the `CANCEL DELETE BACKUP` statement to cancel the running task. For more information, see [CANCEL DELETE BACKUP](900.cancel-delete-backup.md). If you want to stop a scheduled automatic cleanup task, you must first use the `DROP DELETE BACKUP POLICY` statement to drop the deletion strategy, and then use the `CANCEL DELETE BACKUP` statement to cancel the running task.

## Limitations and considerations

* When you use the `ADD DELETE BACKUP POLICY` statement to set a cleanup strategy, you can set only a tenant-level cleanup strategy, not a cluster-level one.

* You can set or delete a cleanup strategy for only one tenant per command.

* If you use the `DROP DELETE BACKUP POLICY` statement to delete a cleanup strategy for a tenant, and all cleanup strategies of the tenant are deleted, the automatic cleanup feature of the tenant is disabled.

* Deleting a cleanup strategy with the `DROP DELETE BACKUP POLICY` statement does not affect ongoing cleanup tasks. It only means that the deleted cleanup strategy will not generate new cleanup tasks when the system schedules the next automatic cleanup.

## Privilege requirements

You must act as the `root` user in the `sys` tenant or as the administrator of the tenant. Among them:

* The default administrator in MySQL mode is the `root` user.
* The default administrator in Oracle mode is the `SYS` user.

## Syntax

```sql
ALTER SYSTEM delete_backup_action [ TENANT [=] tenant_name ];

delete_backup_action:
      ADD DELETE BACKUP POLICY [=] policy_name [RECOVERY_WINDOW [=] recovery_window]
    | DROP DELETE BACKUP POLICY [=] policy_name
```

## Parameters

| Parameter            | Description                                                                                                               |
|-----------------|--------------------------------------------------------------------------------------------------------------------|
| tenant_name     | The name of the tenant.                                                                                                      |
| POLICY          | The name of the cleanup strategy. Currently, you can set it to the value `default`, which specifies to automatically clear only the backups in the `data_backup_dest` and `log_archive_dest` parameters. |
| RECOVERY_WINDOW | The time window for restoring backup data, in days. It is optional. If you do not specify this parameter, the default value is 0, which specifies that backup sets will not expire and the system will not clear them. For more information, see [Parameters of the cleanup statement](../../../../../600.manage/600.backup-and-recovery/500.clear-backup-data/500.parameters-of-cleaning-up-backup.md). |

## Examples

* System tenant

  * Set the cleanup strategy of the `mysql_tenant` tenant to `default`, which specifies to retain backup data for 7 days.

    ```shell
    obclient [oceanbase]> ALTER SYSTEM ADD DELETE BACKUP POLICY = 'default' RECOVERY_WINDOW ='7d' TENANT = mysql_tenant;
    ```

    After the setting is successful, you can execute the following statement to view the cleanup strategy that has been set for the tenant.

    ```sql
    obclient [oceanbase]> SELECT * FROM oceanbase.CDB_OB_BACKUP_DELETE_POLICY WHERE TENANT_ID=1002;
    ```

    The query result is as follows:

    ```shell
    +-----------+-------------+-----------------+
    | TENANT_ID | POLICY_NAME | RECOVERY_WINDOW |
    +-----------+-------------+-----------------+
    |      1002 | default     | 7d              |
    +-----------+-------------+-----------------+
    1 row in set
    ```

  * Delete the `default` cleanup strategy from the `mysql_tenant` tenant.

    ```shell
    obclient [oceanbase]> ALTER SYSTEM DROP DELETE BACKUP POLICY 'default' TENANT mysql_tenant;
    ```

* User tenant

  * Set the cleanup strategy of the `oracle_tenant` tenant to `default`, which specifies to retain backup data for 7 days.

    ```shell
    obclient [SYS]> ALTER SYSTEM ADD DELETE BACKUP POLICY 'default' RECOVERY_WINDOW '7d';
    ```

    After the setting is successful, you can execute the following statement to view the cleanup strategy that has been set for the tenant.

    ```sql
    obclient [SYS]> SELECT * FROM SYS.DBA_OB_BACKUP_DELETE_POLICY;
    ```

    The query result is as follows:

    ```shell
    +-------------+-----------------+
    | POLICY_NAME | RECOVERY_WINDOW |
    +-------------+-----------------+
    | default     | 7d              |
    +-------------+-----------------+
    1 row in set
    ```

  * Delete the cleanup strategy from the `oracle_tenant` tenant.

    ```shell
    obclient [SYS]> ALTER SYSTEM DROP DELETE BACKUP POLICY 'default';
    ```
