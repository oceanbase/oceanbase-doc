# DELETE BACKUP POLICY

The `ADD DELETE BACKUP POLICY` statement and `DROP DELETE BACKUP POLICY` statement are used to set and delete the cleanup policy.

If you want to enable automatic cleanup for a user, you can use the `ADD DELETE BACKUP POLICY` statement to set the cleanup policy for the tenant. Once a cleanup policy is set for a tenant, an automatic cleanup task will be triggered every hour.

During the execution of a cleanup task, if you only want to cancel the currently running cleanup task, you can execute the `CANCELE DELETE BACKUP` statement. For more information about the `CANCELE DELETE BACKUP` statement, see [CANCEL DELETE BACKUP](900.cancel-delete-backup.md). If you want to prevent the cleanup task from being scheduled again, you need to first execute the `DROP DELETE BACKUP POLICY` statement to delete the automatic cleanup policy, and then execute the `CANCELE DELETE BACKUP` statement to cancel the currently running cleanup task.

## Limitations and considerations

* When using the `ADD DELETE BACKUP POLICY` statement to set a cleanup policy, only tenant-level automatic cleanup policies are supported, and cluster-level cleanup policies are not supported.

* Each command can only set or delete one cleanup policy for one tenant.

* When using the `DROP DELETE BACKUP POLICY` statement to delete a tenant's cleanup policy, if all cleanup policies for the tenant are deleted, it is equivalent to disabling the automatic cleanup feature for the tenant.

* Deleting a cleanup policy using the `DROP DELETE BACKUP POLICY` statement does not affect the currently running cleanup task. It only means that the deleted cleanup policy will no longer generate cleanup tasks during the next automatic cleanup scheduling.

## Privilege requirements

The statement must be executed by the `root` user of the `sys` tenant (`root@sys`) or the administrator user of each tenant. Specifically:

* In MySQL mode, the default administrator user is `root`.
* In Oracle mode, the default administrator user is `SYS`.

## Syntax

```sql
ALTER SYSTEM delete_backup_action [ TENANT [=] tenant_name ];

delete_backup_action:
      ADD DELETE BACKUP POLICY [=] policy_name [RECOVERY_WINDOW [=] recovery_window]
    | DROP DELETE BACKUP POLICY [=] policy_name
```

## Parameters

| Parameter | Description |
|-----------------|--------------------------------------------------------------------------------------------------------------------|
| POLICY          | Specifies the cleanup policy name. Valid values:<ul><li>`default`: specifies that automatic cleanup applies only to backups stored in the `DATA_BACKUP_DEST` and `LOG_ARCHIVE_DEST` parameters of the tenant. </li> <li>`log_only`: specifies that automatic cleanup applies only to logs stored in the `LOG_ARCHIVE_DEST` parameter of the tenant. This option is suitable for scenarios where data backup is not enabled, and only log archiving is enabled. Additionally, when the cleanup policy is set to `log_only`, the `DATA_BACKUP_DEST` parameter of the tenant must be empty, indicating that data backup is not configured. Conversely, if the cleanup policy is set to `log_only`, the `DATA_BACKUP_DEST` parameter cannot be set. </li></ul> |
| RECOVERY_WINDOW | Specifies the time window during which backed-up data can be recovered. This parameter is optional. If not specified, the default value is 0 days, indicating that backups will not expire and no cleanup will be performed. For more information about this parameter, see [Parameters related to backup cleanup](../../../../../600.manage/600.backup-and-recovery/500.clear-backup-data/500.parameters-of-cleaning-up-backup.md). |
| tenant_name     | Specifies the tenant name. This parameter is optional and only required when executed by the system tenant.  |

## Examples

* System tenant

  * The system tenant sets the cleanup policy for the `mysql_tenant` tenant to `default`, with a backup recovery window of 7 days.

    ```shell
    obclient [oceanbase]> ALTER SYSTEM ADD DELETE BACKUP POLICY = 'default' RECOVERY_WINDOW ='7d' TENANT = mysql_tenant;
    ```

    After the setting is successful, you can use the following statement to view the cleanup policy set for the tenant.

    ```sql
    obclient [oceanbase]> SELECT * FROM oceanbase.CDB_OB_BACKUP_DELETE_POLICY WHERE TENANT_ID=1002;
    ```

    The query result is as follows:

    ```shell
    +-----------+-------------+-----------------+
    | TENANT_ID | POLICY_NAME | RECOVERY_WINDOW |
    +-----------+-------------+-----------------+
    |      1002 | default     | 7d              |
    +-----------+-------------+-----------------+
    1 row in set
    ```

  * The system tenant deletes the `default` cleanup policy for the `mysql_tenant` tenant.

    ```shell
    obclient [oceanbase]> ALTER SYSTEM DROP DELETE BACKUP POLICY 'default' TENANT mysql_tenant;
    ```

* User tenant

  * The `oracle_tenant` tenant sets the cleanup policy to `default` with a backup recovery window of 7 days.

    ```shell
    obclient [SYS]> ALTER SYSTEM ADD DELETE BACKUP POLICY 'default' RECOVERY_WINDOW '7d';
    ```

    After the setting is successful, you can use the following statement to view the cleanup policy set for the tenant.

    ```sql
    obclient [SYS]> SELECT * FROM SYS.DBA_OB_BACKUP_DELETE_POLICY;
    ```

    The query result is as follows:

    ```shell
    +-------------+-----------------+
    | POLICY_NAME | RECOVERY_WINDOW |
    +-------------+-----------------+
    | default     | 7d              |
    +-------------+-----------------+
    1 row in set
    ```

  * The `oracle_tenant` tenant deletes the cleanup policy.

    ```shell
    obclient [SYS]> ALTER SYSTEM DROP DELETE BACKUP POLICY 'default';
    ```
