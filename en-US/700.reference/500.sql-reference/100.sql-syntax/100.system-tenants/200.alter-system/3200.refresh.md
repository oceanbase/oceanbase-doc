# REFRESH

## Purpose

This statement series is used to trigger refresh operations, including refreshing schemas, time zone information, and various caches.

This statement can only be executed in the sys tenant.

## Syntax

```sql
alter_system_refresh_stmt:
  ALTER SYSTEM refresh_action;

refresh_action:
  REFRESH SCHEMA
  | REFRESH TIME_ZONE_INFO
  | FLUSH KVCACHE [TENANT [=] tenant_name] [CACHE [=] cache_name]
```

## Parameters

|         **Parameter**       |         **Description**          |
|------------------------|----------------------------|
| REFRESH SCHEMA         | Refreshes the schema. <br>**Considerations**  Normally, when the system performs DDL operations, the Root Service actively notifies all OBServer nodes to refresh the schema. However, if some OBServer nodes experience exceptions or network disruptions with the Root Service, manual schema refreshes are required.    |
| REFRESH TIME_ZONE_INFO | Notifies all servers in the cluster to update their local time zone information. <main id="notice" type='explain'><h4>Note</h4><p> This parameter is not supported in the current version. </p></main>  |
| FLUSH KVCACHE          | Clears the dynamically scalable memory KVCache. <ul><li> If both `tenant_name` and `cache_name` are specified, the specified KVCache for the specified tenant is cleared. </li>   <li> If only `tenant_name` is specified, all KVCache for the specified tenant is cleared. </li>   <li> If neither `tenant_name` nor `cache_name` is specified, all KVCache for all tenants is cleared. </li></ul>    |

## Examples

* Refresh the schema.

  ```shell
  obclient> ALTER SYSTEM REFRESH SCHEMA;
  Query OK, 0 rows affected
  ```

* Refresh all KVCache.

  ```shell
  obclient> ALTER SYSTEM FLUSH KVCACHE;
  Query OK, 0 rows affected
  ```

* Refresh the KVCache for the MySQL tenant.

  ```shell
  obclient> ALTER SYSTEM FLUSH KVCACHE TENANT 'MySQL';
  Query OK, 0 rows affected
  ```
