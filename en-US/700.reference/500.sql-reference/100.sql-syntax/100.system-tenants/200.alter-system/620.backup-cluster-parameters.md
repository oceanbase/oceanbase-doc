# BACKUP CLUSTER PARAMETERS

You can use the `ALTER SYSTEM BACKUP CLUSTER PARAMETERS` statement to back up cluster-level parameters.

## Limitations and considerations

* You can execute this statement only as the `root` user of the `sys` tenant.

* This statement backs up only cluster-level parameters for which default values are not used.

  <main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>The <code>all_server_list</code>, <code>rootservice_list</code>, and <code>debug_sync_timeout</code> parameters are not backed up regardless of whether default values are used for them. </p>
  </main>

## Syntax

```sql
ALTER SYSTEM BACKUP CLUSTER PARAMETERS TO 'parameters_backup_path';
```

## Parameters

| Parameter                   | Description                                                                |
|------------------------|---------------------------------------------------------------------------|
| parameters_backup_path | The backup path for cluster-level parameters. You must specify a path as needed. It must be the same as the backup destination for data backup. For more information about the backup destination, see [Preparations](../../../../../600.manage/600.backup-and-recovery/400.data-backup/100.preparation-before-data-backup.md). |

## Examples

Back up cluster-level parameters to the `oss://oceanbase-test-bucket/backup/cluster_parameters?host=***.aliyun-inc.com&access_id=***&access_key=***` directory.

```shell
obclient> ALTER SYSTEM BACKUP CLUSTER PARAMETERS TO 'oss://oceanbase-test-bucket/backup/cluster_parameters?host=***.aliyun-inc.com&access_id=***&access_key=***';
```
