# SAVEPOINT

## Purpose

The `SAVEPOINT` statement creates a savepoint in a transaction to allow partial rollback.

## Syntax

* Create a savepoint:

  ```sql
  SAVEPOINT savepoint_name
  ```

* Roll back to a savepoint:

  ```sql
  ROLLBACK [WORK] TO [SAVEPOINT] savepoint_name
  ```

* Delete a savepoint:

  ```sql
  RELEASE SAVEPOINT savepoint_name
  ```

## Parameters

|       Parameter       |                                                    Description                                                    |
|----------------|----------------------------------------------------------------------------------------------------------|
| \[WORK\]       | Optional keyword that does not affect the semantics.                                                                                             |
| savepoint_name | Specifies the name of the savepoint. The specified savepoint must be unique within the transaction. If a savepoint with the same name already exists, it will be overwritten. After a savepoint is created, you can roll back the transaction to this savepoint, or use the `ROLLBACK` statement to roll back the entire transaction. |

## Examples

Assume a transaction executes the following statements:

| **sql_no** |     **Statement**     |   **Partition**   |
|------------|----------------|------------|
| 1          | UPDATE ...;    | p1, p4     |
|            | SAVEPOINT sp1; |            |
| 2          | UPDATE ...;    | p2, p4     |
| 3          | UPDATE ...;    | p3, p5     |
|            | SAVEPOINT sp2; |            |
| 4          | UPDATE ...;    | p1, p3, p6 |
| 5          | UPDATE ...;    | p1, p5     |
|            | SAVEPOINT sp3; |            |
| 6          | SELECT ...;    |            |
| 7          | UPDATE ...;    | p5, p6     |
|            | SAVEPOINT sp4; |            |

### Record Savepoints

You can create savepoints before committing the transaction. To manage these savepoints, they need to be linked in the order they were created. The above transaction includes 7 SQL statements and 4 savepoints. The savepoint chain is shown in the following figure, where each node records the mapping `<savepoint_name, sql_no>`:

![image.png](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/3501155061/p149175.png "image.png")

### Transaction Participants List

To support rolling back all modifications after a specific SQL statement, the transaction must record the participants involved in each statement along with their corresponding `sql_no`. The above transaction executed 7 SQL statements, involving `p1` to `p6`, a total of 6 partitions:

![image.png](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/3501155061/p149176.png "image.png")

### Savepoint Rollback Process

1. Query the `savepoint_name` corresponding `sql_no` from the savepoint chain.

   For example, if the user executes `ROLLBACK to SAVEPOINT sp2`, the savepoint chain will show that `sp2` corresponds to `sql_no` 3.

2. Query the partition corresponding to the `sql_no` from the transaction participants list.

   The transaction participants list will show that statements with `sql_no` greater than 3 operate on partitions `p1`, `p3`, `p5`, and `p6`.

3. The scheduler initiates a rollback request for the partitions identified in **Step 2**, rolling back all modifications made to these partitions after the `sp2` savepoint.

   Modifications made to `p1`, `p3`, and `p5` related to this transaction are rolled back, while all modifications made to `p6` related to this transaction are rolled back.

4. Update the transaction participants list.

   Remove the information about statements with `sql_no` greater than 3 from the transaction participants list. Since all modifications made to `p6` related to this transaction are rolled back, `p6` can be removed from the participants list.

   ![1](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/3501155061/p149177.png)

5. Delete invalid savepoints.

   After the user executes `ROLLBACK to SAVEPOINT sp2` successfully, the system will delete the savepoints `sp3` and `sp4`, preventing further rollbacks to these savepoints.

   ![1](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/3501155061/p149178.png)
