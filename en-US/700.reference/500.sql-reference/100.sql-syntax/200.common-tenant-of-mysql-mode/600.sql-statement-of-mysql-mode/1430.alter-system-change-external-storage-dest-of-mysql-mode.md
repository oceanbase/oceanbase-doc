# ALTER/CHANGE/MODIFY EXTERNAL_STORAGE_DEST

## Purpose

This statement is used to change the source configuration (such as `zone`, `idc`, or `region`), I/O throttling parameters (`max_iops` and `max_bandwidth`), and key information (such as `access_id` and `access_key`) of the backup or archive path for the current tenant. After the modification, the new configuration will replace the original one.

## Limitations and considerations

* Only the user tenant can execute this statement. The sys tenant cannot execute this statement.

* Before modifying the `zone`, `idc`, or `region` configuration of the path, if you need to set the region or IDC level, you must first use the `ALTER SYSTEM MODIFY ZONE zone_name SET REGION=region_name;` or `ALTER SYSTEM MODIFY ZONE zone_name SET IDC=idc_name;` statement to set the region or IDC information. It is recommended to set the source configuration at the IDC level. This way, you can utilize an IDC with abundant network bandwidth resources for backup tasks, and the backup tasks will have a wider range of optional nodes. Additionally, you do not need to worry about changes in zones within the IDC of the cluster.

* When modifying the source configuration of the backup path, if there are ongoing backup tasks, the tasks will take at least a few minutes to detect the configuration changes. Therefore, during the configuration modification, there may still be nodes outside the specified configuration accessing the backup path, resulting in cross-data center or cross-region traffic.

* Only the I/O throttling parameters (`max_iops` and `max_bandwidth`) and the `access_id` and `access_key` information of object storage paths can be modified. If the I/O throttling parameters (`max_iops` and `max_bandwidth`) or the `access_id` and `access_key` information are set for an NFS path, the system returns an error, with the error code `1235`.

* When the `ACCESS_INFO` attribute (`access_id` and `access_key` information) is set for an object storage path, if the parameter format is incorrect (for example, if there are extra `=` signs or if `access_id` or `access_key` is missing), the system returns an error `OB_OBJECT_STORAGE_PERMISSION_DENIED` (error code `-9116`).

* When Assume Role is used to access an object storage path from a backup path or an archive path:

  * If `ACCESS_INFO = 'access_id=new_access_id&access_key=new_access_key'` is set, the system returns an error.
  
  * If only the I/O throttling parameters are set in `ATTRIBUTE` without setting the `ACCESS_INFO` attribute, the system may return an error or the settings may not take effect.

* The same `ATTRIBUTE` + `ACCESS_INFO` attribute can be set multiple times for the same path.

## Privilege requirements

The user executing this statement must have the `ALTER SYSTEM` privilege. For more information about OceanBase Database privileges, see [Privilege classification in MySQL mode](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md).

## Syntax

```sql
ALTER SYSTEM {ALTER|CHANGE|MODIFY} EXTERNAL_STORAGE_DEST 
  PATH [=] 'path' 
  SET [ATTRIBUTE = '[{zone=zone_name | idc=idc_name | region=region_name}][&max_iops=iops_num][&max_bandwidth=bandwidth_num]']
  [ACCESS_INFO = 'access_id=new_access_id&access_key=new_access_key'];
```

## Parameters

|          Parameter                                     |         Description                                      |
|---------------------------------------------------|--------------------------------------------------|
| path                                              | Specifies the backup or archive path whose key information needs to be modified. The path must be a backup or archive path already set for the current tenant and must be an object storage path. Additionally, the path must contain the `host` information. For example, in the case of OSS, the path format is as follows: `oss://oceanbase-test-bucket/backup/databackup?host=***`. |
| zone=zone_name \| idc=idc_name \| region=region_name | Specifies the source of the current backup or archive path. You can select configurations at the `zone`, `idc`, or `region` level. Only one level can be selected at a time, or none can be selected. If not explicitly specified, the default is no selection.<p>When modifying the source configuration of the archive path:<ul><li>Since all traffic for log archiving is written by the leader replica, there is no access priority difference for log archiving paths. The only restriction is on the nodes that can access the archive path. If you need to set multiple zones, multiple IDCs, or multiple regions, separate the values with commas (,) or semicolons (;). For example, `zone=z1,z2;z3` specifies `z1`, `z2`, and `z3` as the sources of the archive path.</li> <li>When modifying `zone`, `idc`, or `region`, the leader replica must be in the specified `zone`, `idc`, or `region`. Otherwise, log archiving will not proceed.</li></ul></p> <p>When modifying the source configuration of the backup path:<ul><li>If you need to set multiple zones, multiple IDCs, or multiple regions, separate the values with commas (,) and semicolons (;). For example, `zone=z1,z2;z3` specifies `z1`, `z2`, and `z3` as the sources of the backup path. `z1` and `z2` have the same priority, and both have higher priority than `z3`.</li> <li>When modifying the `zone`, `idc`, or `region` configuration of the backup path, the leader node of the Root Service must be in the specified `zone`, `idc`, or `region`. Otherwise, the backup task will fail to write backup metadata to the target backup path, resulting in the failure of the backup task. It is recommended to set the backup path source to include the primary zone range.</li></ul></p> |
| max_iops        | Specifies the maximum IOPS allowed for the current backup or archive path. The value is a positive integer, indicating the number of I/O requests per second. If not explicitly set, the path does not restrict IOPS, and the underlying object storage and network capabilities determine the IOPS.<p>Example: `max_iops=1000`</p> |
| max_bandwidth   | Specifies the maximum bandwidth allowed for the current backup or archive path. The value is a positive integer with a unit. Supported units are kb, mb, and gb, representing KB/s, MB/s, and GB/s, respectively. If not explicitly set, the path does not restrict bandwidth.<p>Example: `max_bandwidth=1000mb`</p>  |
| access_id=new_access_id&access_key=new_access_key | Specifies the new `access_id` and `access_key` information. Both `access_id` and `access_key` must be provided. |

## Examples

### Modify the source configuration of the archive path

  Assume that the original source configuration of the archive path is `zone=z1,z2,z3`. You need to change the source configuration to `region=region1`. After the change, only nodes in `region1` can access the path.

  * OSS

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='oss://oceanbase-test-bucket/backup/archive?host=****.aliyun-inc.com' SET ATTRIBUTE = 'region=region1';
    ```

  * NFS

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='file:///data/nfs/backup/archive' SET ATTRIBUTE = 'region=region1';
    ```

  * S3

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM CHANGE EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=s3.<region>.amazonaws.com' SET ATTRIBUTE = 'region=region1';
    ```

  * Object storage services compatible with the S3 protocol (OBS/GCS/COS)

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM CHANGE EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=obs.****.myhuaweicloud.com' SET ATTRIBUTE = 'region=region1';
    ```

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=https://storage.googleapis.com' SET ATTRIBUTE = 'region=region1';
    ```

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM ALTER EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=cos.ap-xxxx.myqcloud.com' SET ATTRIBUTE = 'region=region1';
    ```

* Modify the source configuration of the backup path

  Assume that the original source configuration of the backup path is `zone=z1,z2;z3`. You need to change the source configuration to `idc=idc1;idc2`. After the change, nodes in `idc1` and `idc2` can access the path, and nodes in `idc1` have higher priority than those in `idc2`.

  * OSS

    ```shell

    ```

  * NFS

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='file:///data/nfs/backup/data' SET ATTRIBUTE = 'idc=idc1;idc2';
    ```

  * S3

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM ALTER EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/data?host=s3.<region>.amazonaws.com' SET ATTRIBUTE = 'idc=idc1;idc2';
    ```

  * Object storage services compatible with the S3 protocol (OBS/GCS/COS)

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM CHANGE EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/data?host=obs.****.myhuaweicloud.com' SET ATTRIBUTE = 'idc=idc1;idc2';
    ```

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/data?host=https://storage.googleapis.com' SET ATTRIBUTE = 'idc=idc1;idc2';
    ```

### Set the I/O throttling parameters of the archive path (`max_iops` and `max_bandwidth`)

You can set the `max_iops` and `max_bandwidth` parameters at the same time, or set only one of them. Only object storage paths support I/O throttling parameters. NFS paths do not support I/O throttling parameters.

* OSS

  You can set the `max_iops` and `max_bandwidth` parameters at the same time. Example:

  ```shell
  obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='oss://oceanbase-test-bucket/backup/archive?host=****.aliyun-inc.com' SET ATTRIBUTE = 'max_iops=1000&max_bandwidth=1000mb';
  ```

  You can set only the `max_iops` parameter. Example:

  ```shell
  obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='oss://oceanbase-test-bucket/backup/archive?host=****.aliyun-inc.com' SET ATTRIBUTE = 'max_iops=1000';
  ```

  You can set only the `max_bandwidth` parameter. Example:

  ```shell
  obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='oss://oceanbase-test-bucket/backup/archive?host=****.aliyun-inc.com' SET ATTRIBUTE = 'max_bandwidth=1000mb';
  ```

* S3

  You can set the `max_iops` and `max_bandwidth` parameters at the same time. Example:

  ```shell
  obclient(root@mysql001)[(none)]> ALTER SYSTEM CHANGE EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=s3.<region>.amazonaws.com' SET ATTRIBUTE = 'max_iops=1000&max_bandwidth=1000mb';
  ```

* Object storage services compatible with the S3 protocol (OBS, GCS, and COS)

  You can set the `max_iops` and `max_bandwidth` parameters at the same time. Example:

### Set the I/O throttling parameters of the backup path (`max_iops` and `max_bandwidth`)

<main id="notice" type='explain'>
<h4>Note</h4>
<p>Recommendations for setting I/O throttling parameters: </p>
<ul><li>In a high-concurrency, multi-tenant environment that is sensitive to bandwidth, you can set different <code>max_iops</code> or <code>max_bandwidth</code> values for different backup paths to isolate the impact of backup on the bandwidth and IOPS of online services. </li>
<li>It is recommended that you first set the parameters to low values and gradually adjust them based on your actual network bandwidth and the throttling strategies of the object storage service. For example, you can first set the parameters to <code>max_iops=500&max_bandwidth=100mb</code> and observe the results. Then, you can fine-tune the parameters based on the backup duration and business peak. </li></ul>
</main>

You can set the `max_iops` and `max_bandwidth` parameters at the same time, or set only one of them. Only object storage paths support I/O throttling parameters. NFS paths do not support I/O throttling parameters.

* OSS


  ```shell
  obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='oss://oceanbase-test-bucket/backup/data?host=****.aliyun-inc.com' SET ATTRIBUTE = 'max_iops=1000';
  ```
