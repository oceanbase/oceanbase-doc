# SELECT INTO

## Purpose

You can use this statement to store query results in a variable, a file, or a table. Here are the details:

* The `SELECT ... INTO OUTFILE` statement stores the result set in an external file and allows you to specify the output format.

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>When you use the <code>SELECT ... INTO OUTFILE</code> statement to output data, you can use <code>\N</code> to represent <code>NULL</code>. </p>
    </main>

* The `SELECT ... INTO DUMPFILE` statement writes an unformatted single row to an external file.

* The `SELECT ... INTO var_list` statement stores the result set in variables.

## Privileges requirements

To execute the `SELECT INTO` statement, the user must have the `FILE` privilege and the `SELECT` privilege on the table. For more information about privileges in OceanBase Database, see [Privilege types in MySQL-compatible mode](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md).

**Here are some examples:**

You can use the following command to grant the `FILE` privilege to a user:

```sql
GRANT FILE ON *.* TO user_name;
```

In this command, `user_name` specifies the user who needs to execute the `SELECT INTO` statement.

## Syntax

```sql
select_stmt
INTO { OUTFILE 'file_name' [PARTITION BY part_expr] [{CHARSET | CHARACTER SET} charset_name] [field_opt] [line_opt] [file_opt]
     | OUTFILE 'file_name' [PARTITION BY part_expr] [FORMAT = (external_file_format_list)] [file_opt]
     | DUMPFILE 'file_name'
     | into_var_list};

external_file_format_list:
  TYPE = 'CSV'
    LINE_DELIMITER = '<string>' | <expr>
    FIELD_DELIMITER = '<string>' | <expr>
    ESCAPE = '<character>' | <expr>
    FIELD_OPTIONALLY_ENCLOSED_BY = '<character>' | <expr>
    FIELD_ENCLOSED_BY = '<character>' | <expr>
    ENCODING = 'charset'
    COMPRESSION = [NONE, GZIP, DEFLATE, ZSTD] | '<string>'
    FILE_EXTENSION = ['<string>']

  TYPE = 'PARQUET',
    COMPRESSION = '<string>'
    ROW_GROUP_SIZE = '<string>' | <int>

  TYPE = 'ORC'
    COMPRESSION = '<string>'
    COMPRESSION_BLOCK_SIZE = '<string>' | <int>
    STRIPE_SIZE = '<string>' | <int>
    ROW_INDEX_STRIDE = <int>

field_opt:
    {COLUMNS | FIELDS} field_term_list

field_term_list:
    field_term [, field_term ...]

field_term:
    {[OPTIONALLY] ENCLOSED | TERMINATED | ESCAPED} BY string

line_opt:
    LINES line_term_list

line_term_list:
    line_term [line_term]

line_term:
    {STARTING | TERMINATED} BY string

file_opt:
    file_option [, file_option ...]

file_option:
    SINGLE [=] {TRUE | FALSE}
    | MAX_FILE_SIZE [=] {int | string}
    | BUFFER_SIZE [=] {int | string}
```

### external_file_format_list

When **TYPE = 'CSV'**, it contains the following fields:

  * `LINE_DELIMITER`: Specifies the line delimiter for the CSV file, with the default being `LINE_DELIMITER='\n'`.
  * `FIELD_DELIMITER`: Optional, specifies the column delimiter for CSV files, default is `FIELD_DELIMITER='\t'`.
  * `ESCAPE`: Specifies the escape character for the CSV file, which can only be 1 byte. The default is `ESCAPE ='\'`.
  * `FIELD_OPTIONALLY_ENCLOSED_BY`: An optional parameter that specifies the symbol used to enclose field values in a CSV file. The default value is empty. Using this option means that only certain types of fields (such as CHAR, VARCHAR, TEXT, JSON, etc.) will be enclosed with the specified symbol.
  * `FIELD_ENCLOSED_BY`: Optional, specifies the symbol used to enclose field values in a CSV file. The default is empty, indicating no enclosing symbols are applied. This option applies the enclosing setting to all types of fields.
  * `ENCODING`: Specifies the character set encoding format of the file. If not specified, the default value is `UTF8MB4`.
  * `COMPRESSION`: Optional, specifies the file compression format, supporting four types: NONE, GZIP, DEFLATE, and ZSTD.
    * `GZIP`/`DEFLATE`: GZIP compressed file.
    * `ZSTD`: ZSTD compressed file.
    * `NONE`: Indicates that the file is not compressed (default value).
  * `FILE_EXTENSION`: Optional, specifies the user-defined file extension, used only for multi-file export and only supported by CSV format. If this parameter is not specified, the file extension is determined by the format type. The default file extension for CSV format is `.csv`.

When **TYPE = 'PARQUET'**, it includes the following fields:

  * `COMPRESSION`: Specifies the compression format for PARQUET files. The default compressed file suffix is `.parquet`. It supports seven compression formats: `UNCOMPRESSED` (indicating no compression), `SNAPPY`, `GZIP`, `BROTLI`, `ZSTD`, `LZ4`, and `LZ4_HADOOP`. If not specified, the default is `UNCOMPRESSED`.
  * `ROW_GROUP_SIZE`: Specifies the ROW GROUP size of a PARQUET file in bytes. This option accepts either a numeric value or a string in the form of `'64MB'`. If not specified, the default value is `256MB`. The default value is recommended.

When **TYPE = 'ORC'**, it includes the following fields:

  * `COMPRESSION`: Specifies the compression format for ORC files. The default compressed file suffix is `.orc`. It supports five compression formats: `UNCOMPRESSED` (indicating no compression), `SNAPPY`, `ZLIB`, `LZ4`, and `ZSTD`. If not specified, the default is `UNCOMPRESSED`.
  * `COMPRESSION_BLOCK_SIZE`: Specifies the size of data chunks during compression, measured in bytes. This option accepts either a numeric value or a string in the form of `'64KB'`. If unspecified, the default is `256KB`. The default value is recommended.
  * `STRIPE_SIZE`: Specifies the Stripe size of ORC files in bytes. This option can be a number or a string like `'64MB'`. If not specified, the default value is `64MB`. The default value is recommended.
  * `ROW_INDEX_STRIDE`: A parameter that controls the frequency of index records, defining how often an index is recorded in terms of rows. The default value is `10000` if not specified. It is recommended to use the default value.

### field_term

* `[OPTIONALLY] ENCLOSED BY string`: Used to specify the symbol enclosing field values. By default, there are no quotation symbols. For example, `ENCLOSED BY '"'` indicates that character values are placed between double quotes. If the `OPTIONALLY` keyword is used, the specified enclosing characters are applied only to string-type values.
* `TERMINATED BY string`: Used to specify the symbol between field values. For example, `TERMINATED BY ','` designates a comma as the delimiter between two field values.
* `ESCAPED BY string`: Used to specify the escape character for handling special characters or parsing data in special formats. The default escape character is the backslash (`\`).

### line_term

* `STARTING BY string`: Specifies the starting character of each line.
* `TERMINATED BY string`: Specifies the ending character for each line, with the default being a newline character. For example, `... LINES TERMINATED BY '\n' ...` indicates that a line will use a newline character as the ending marker.

### file_option

* `SINGLE [=] {TRUE | FALSE}`: specifies whether to export data to a single file or multiple files.

  * `SINGLE [=] TRUE`: specifies to export data to a single file. This is the default value.
  * `SINGLE [=] FALSE`: specifies to export data to multiple files.

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>When the degree of parallelism is greater than 1 and <code>SINGLE = FALSE</code>, data can be exported to multiple files to achieve parallel read and write and improve export efficiency.</p>
    </main>

* `MAX_FILE_SIZE [=] {int | string}`: specifies the maximum size of a file when data is exported to multiple files. This parameter takes effect only when `SINGLE = FALSE`.

* `BUFFER_SIZE [=] {int | string}`: specifies the size of memory applied for each thread for each partition when data is exported. If no partitioning is performed, the entire table is considered a single partition. The default value is 1 MB.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p><ul><li>The <code>BUFFER_SIZE</code> parameter is used for export performance tuning. If sufficient memory is available on the server and you want to improve export efficiency, you can set a large value (for example, 4 MB). If the memory is insufficient, you can set a small value (for example, 4 KB). If you set the parameter to 0, all partitions of a single thread share a public memory.</li><li>In OceanBase Database V4.3.2, the <code>BUFFER_SIZE</code> parameter is supported in V4.3.2 BP1 and later versions.</li></ul></p>
  </main>

## Examples

### Export data to a local file

1. Set the export file path.

    Before exporting a file, you must set the system variable `secure_file_priv` to specify a path that can be accessed to export the file.

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>For security reasons, when you set the system variable <code>secure_file_priv</code>, you can only connect to the database by using a local socket and execute the SQL statement to modify the global variable. For more information, see <a href="../../../../800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/12000.secure_file_priv-global.md">secure_file_priv</a>.</p>
    </main>

    1. Log in to the OBServer node where you want to connect to OceanBase Database.

        ```bash
        ssh admin@xxx.xxx.xxx.xxx
        ```

    2. Connect to the `mysql001` tenant by using a local Unix socket.

        ```bash
        obclient -S /home/admin/oceanbase/run/sql.sock -uroot@mysql001 -p******
        ```

    3. Set the export path to `/home/admin/test_data`.

        ```sql
        SET GLOBAL secure_file_priv = "/home/admin/test_data";
        ```

    4. Log out.

2. Reconnect to the database, and use the `SELECT INTO OUTFILE` statement to export data. Specify the comma (,) as the delimiter between field values, use `"` to enclose values of the STRING type, and use a line break as the end marker.

   * Export data to a single file in serial mode. Specify the file name as `test_tbl1.csv`.

     ```sql
     SELECT /*+parallel(2)*/ * FROM test_tbl1
     INTO OUTFILE '/home/admin/test_data/test_tbl1.csv'
       FIELDS TERMINATED BY ',' OPTIONALLY ENCLOSED BY '"'
       LINES TERMINATED BY '\n';
     ```

     The return result is as follows:

     ```shell
     Query OK, 9 rows affected
     ```

   * Write data to multiple files in parallel. Do not specify the file name (that is, use the default prefix `data`), and limit the size of each file to no more than 4 MB.

     ```sql
     SELECT /*+parallel(2)*/ * FROM test_tbl1
       INTO OUTFILE '/home/admin/test_data/'
       FIELDS TERMINATED BY ',' OPTIONALLY ENCLOSED BY '"'
       LINES TERMINATED BY '\n'
       SINGLE = FALSE MAX_FILE_SIZE = '4MB';
     ```

     The return result is as follows:

     ```shell
     Query OK, 9 rows affected
     ```

   * Write data to multiple files in parallel. Specify the file name prefix as `dd2024`, and limit the size of each file to no more than 4 MB.

     ```sql
     SELECT /*+parallel(2)*/ * FROM test_tbl1
       INTO OUTFILE '/home/admin/test_data/dd2024'
       FIELDS TERMINATED BY ',' OPTIONALLY ENCLOSED BY '"'
       LINES TERMINATED BY '\n'
       SINGLE = FALSE MAX_FILE_SIZE = '4MB';
     ```

     The return result is as follows:

     ```shell
     Query OK, 9 rows affected
     ```

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p><ul><li>When multiple export tasks are exporting data to the same path at the same time, errors may occur and only a part of data may be exported. You can avoid these problems by properly setting the export path. </br>For example, </br><code>SELECT /*+parallel(2)*/ * FROM t1 INTO OUTFILE 'test/data' SINGLE = FALSE;</code> and <code>SELECT /*+parallel(2)*/ * FROM t2 INTO OUTFILE 'test/data' SINGLE = FALSE;</code> may both be executed at the same time. If the two export tasks are given the same file name, an error may be returned. We recommend that you set the export path to <code>test/data1</code> and <code>test/data2</code>. </li><li>After <code>SINGLE = FALSE</code>, if an export task fails because of reasons such as file already exist, you can delete all files with the same prefix as the target file in the export directory, or delete the export directory and recreate it, and then execute the export task again. </br>For example, if <code>SELECT /*+parallel(2)*/ * FROM t1 INTO OUTFILE 'test/data' SINGLE = FALSE;</code> fails, you can delete all files with the prefix <code>data</code> in the <code>test</code> directory, or directly delete the <code>test</code> directory and recreate it, and then try to execute the export task again.</li></ul></p>
    </main>

3. Log in to the server and view the exported files in the `/home/admin/test_data` directory on the OBServer node.

  ```shell
  [xxx@xxx /home/admin/test_data]# ls
  ```

  The return result is as follows:

  ```shell
  data_0_0_0  data_0_1_0  dd2024_0_0_0  dd2024_0_1_0  test_tbl1.csv
  ```

  In the preceding return result, `test_tbl1.csv` is the file name when data is exported to a single file in serial mode; `data_0_0_0` and `data_0_1_0` are the file names when data is exported to multiple files in parallel without specifying the file name; `dd2024_0_0_0` and `dd2024_0_1_0` are the file names when data is exported to multiple files in parallel with the prefix of `dd2024` specified for the file name.

### Export data to OSS

You can execute the `SELECT INTO OUTFILE` statement to export data from the `test_tbl2` table to a specified OSS storage location based on partitions. The partitions are determined by the combination of the `col1` and `col2` columns. Rows with the same values in these two columns are considered to be in the same partition and exported to the same directory.

```sql
SELECT /*+parallel(3)*/ * FROM test_tbl2
  INTO OUTFILE 'oss://$DATA_FOLDER_NAME/?host=$OSS_HOST&access_id=$OSS_ACCESS_ID&access_key=$OSS_ACCESS_KEY'
    PARTITION BY CONCAT(col1,'/',col2)
    SINGLE = FALSE BUFFER_SIZE = '2MB';
```

The storage location is specified by the `$DATA_FOLDER_NAME` variable. You also need to provide the host address, access ID, and access key of the OSS service.
