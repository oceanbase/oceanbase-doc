# GRANT

## Description

This statement is used to grant privileges to a specified user or role, or to grant a role to a user or role.

## Limitations and considerations

A `GRANT` cycle is not supported. For example, if role A is granted to role B, and role B is granted to role C, then an error occurs when role C is granted to role A.

## Privilege requirements

### Privilege requirements for granting object privileges to users

* When you execute the `GRANT` statement, you must have the corresponding privileges. For example, to grant the `SELECT` privilege on the `tbl1` table to the `user2` user, the `user1` user must have the `SELECT` privilege on the `tbl1` table.

* When you execute the `GRANT` statement, you must have the `GRANT OPTION` privilege. For more information, see [Privilege types in MySQL mode](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md).

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>After you grant privileges to a user, the user needs to reconnect to OceanBase Database for the privileges to take effect. </p>
</main>

### Privilege requirements for granting roles to users or roles

* If you have the `SUPER` privilege, you can grant all roles.
* To grant a role to another user or role, you must have both the target role and the `ADMIN OPTION` privilege. For more information, see [Query user privileges](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/400.view-user-permissions-of-mysql-mode.md).

## Syntax

### Grant object privileges to a user or role

```sql
GRANT priv_type[(column_name_list)] [, priv_type[(column_name_list)] ...]
    ON [object_type] priv_level 
    TO {user [, user...]} 
    [WITH GRANT OPTION];

column_name_list:
    column_name [, column_name ...]

object_type:
    TABLE
    | FUNCTION
    | PROCEDURE

user:
    user_or_role
    | user_name IDENTIFIED [WITH auth_plugin] BY password 
    | user_name IDENTIFIED [WITH auth_plugin] BY PASSWORD password

user_or_role:
    user_name | role_name
```

### Grant a role to a user or role

```sql
GRANT role_name [, role_name ...]
    TO user_or_role [, user_or_role ...]
    [WITH ADMIN OPTION];

user_or_role:
    user_name | role_name
```

## Parameter explanation

|                 **Parameter**   |          **Description**        |
|----------------------------------------|--------------------------------------|
| priv_type                              | The type of privileges to grant. Multiple privilege types can be granted by separating them with commas (`,`). For more information, see [Privilege types in MySQL mode](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md). Note: The PROXY privilege is currently supported only in the syntax, and cannot be used. |
| column_name_list | A comma-separated list of column names. Privileges granted with a column name list take effect only on the specified columns. If this parameter is not specified, the privileges take effect on the entire table or object. For more information, see [Directly grant privileges](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/200.authority-of-mysql-mode.md). |
| object_type                            | The type of object to which the privileges are granted. For more information, see [object_type](#object_type). |
| priv_level                             | The scope on which privileges are granted. Valid values are `*.*` (all databases and tables), `db_name.*` or `*.table_name` (a specific database or a specific table), and `db_name.table_name` (a specific table in a specific database). |
| user | The user to whom the privileges are granted. Multiple users can be specified by separating them with commas (`,`). If the specified user or users do not exist, they will be created.  |
| auth_plugin | The authentication plugin for user authentication. At present, only the `mysql_native_password` authentication plugin is supported. |
| BY password | A password is specified for the user to be granted privileges. The password is stored in the `mysql.user` table after being encrypted. If the password contains special characters <code>~!@#%^&*_-+=`\|(){}[]:;',.?/</code>, it must be enclosed in a pair of quotation marks <code>''</code> or <code>""</code>. |
| BY PASSWORD password | A password is specified for the user to be granted privileges. The password is directly stored in the `mysql.user` table. |
| WITH GRANT OPTION  | Specifies whether the granted privileges can be delegated and whether they will be revoked when a privilege is revoked from the grantor. |
| role_name          | The name of the role. |
| WITH ADMIN OPTION  | Specifies whether the grantor's role privileges can be delegated and whether they will be revoked when a role privilege is revoked from the grantor. |

### object_type

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>When you use the <code>object_type</code> clause, make sure that the specified objects are of the corresponding types. Otherwise, a syntax error will occur. </p>
</main>

* `TABLE`: indicates that the object type to which the privilege is applied is a table.
* `FUNCTION`: indicates that the object type to which the privilege is applied is a function.
* `PROCEDURE`: indicates that the object type to which the privilege is applied is a stored procedure.

**Here are some examples:**

* Grant the `SELECT` privilege to `user001` on all objects in the `test` database. Since the specified objects are not of the specified type, an error occurs.

  ```sql
  GRANT SELECT ON TABLE test.* TO user001;
  ```

  The return result is as follows:

  ```shell
  ERROR 1144 (42000): Illegal GRANT/REVOKE command; please consult the manual to see which privileges can be used
  ```

* Grant the `SELECT` privilege to `user001` on the `tbl1` table in the `test` database.

  ```sql
  GRANT SELECT ON TABLE test.tbl1 TO user001;
  ```

* Grant the execute privilege to `user002` on the `calculate_salary` function in the `test` database.

  ```sql
  GRANT EXECUTE ON FUNCTION test.calculate_salary TO user002;
  ```

* Grant the execute privilege to `user003` on the `pro_generate_data` stored procedure in the `test` database.

  ```sql
  GRANT EXECUTE ON PROCEDURE test.pro_generate_data TO user003;
  ```

## Examples

### Example 1: Grant object privileges

* Grant the `CREATE VIEW` privilege on the `db1` database to the `user1` user and allow delegation. The `user1` user must exist, and the `db1` database must exist.

  ```sql
  GRANT CREATE VIEW ON db1.* TO user1 WITH GRANT OPTION;
  ```

* Grant the `CREATE` privilege on the `db1` database to the `user1` user and change the password of the `user1` user.

  ```sql
  GRANT CREATE ON db1.* TO user1 IDENTIFIED by '********';
  ```

  After the operation, check the password of the `user1` user in the `mysql.user` table. You will find that the password has been updated to the newly set one.

* Grant the `CREATE` privilege on the `db1` database to the non-existent `user2` user and set a password for the `user2` user.

  ```sql
  GRANT CREATE ON db1.* TO user2 IDENTIFIED by '********';
  ```

* Grant the `SELECT` privilege on the `col1` column of the `tbl1` table in the `test` database to the `user001` user.

  ```sql
  GRANT SELECT(col1) ON test.tbl1 TO user001;
  ```

### Example 2: Grant a role to a user or role

* Grant the privileges of the `role001` role to the `role002` role with delegation allowed. The `role001` role and the `role002` role must exist.

  ```sql
  GRANT role001 TO role002 WITH ADMIN OPTION;
  ```

* Grant the privileges of the `role001` role to the `user001` user with delegation allowed. The `role001` role and the `user001` user must exist.

  ```sql
  GRANT role001 TO user001 WITH ADMIN OPTION;
  ```
