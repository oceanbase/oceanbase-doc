# LOAD DATA

## Description

The statement is used to import data from external sources.

* **The OceanBase Database `LOAD DATA` statement supports the following input files:**

  * **Files on the OBServer node**: You can use the `LOAD DATA INFILE` statement to load data from these files to a database table.

  * **Local files on the client**: You can use the `LOAD DATA LOCAL INFILE` statement to load data from these files to a database table.

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>When OceanBase Database executes the <code>LOAD DATA LOCAL INFILE</code> statement, the system automatically adds the <code>IGNORE</code> option to the statement. </p>
    </main>

  * **Files in the Alibaba Cloud OSS file system**: You can use the `LOAD DATA REMOTE_OSS INFILE` statement to load data from these files to a database table.

* **The OceanBase Database `LOAD DATA` statement currently supports importing only text files in the CSV format. The entire import process comprises the following steps:**

  1. **Parse the file**: OceanBase Database reads data from the file based on the file name you specified and parses the data in the file in parallel or serially based on the specified degree of parallelism.

  2. **Distribute the data**: As a distributed database, OceanBase Database distributes the parsed data to the corresponding OBServer node based on the data distribution plan.

  3. **Insert the data**: After the OBServer node receives the data, the node executes the `INSERT` statement to insert the data into the corresponding partition.

## Considerations

* You cannot use the <code>LOAD DATA</code> statement for a table with triggers (trigger).
* If you want to import data from external files, make sure that the following conditions are met:

  * When you load a file from the server, set the system variable <a href="../../../../800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/12000.secure_file_priv-global.md">secure_file_priv</a> in advance to the path where the import or export file can be accessed.
  * When you load a file from the client, start the MySQL/[OBClient](https://www.oceanbase.com/softwarecenter-cloud) client with the <code>--local-infile[=1]</code> option to enable the data loading feature from the local file system.

* Take note of the following limitations on partition-level direct load:

  * The destination table cannot be a replica table, a table with an auto-increment column, an ID column, or a global index.
  * If the last-level partitioning is HASH or KEY, partition-level direct load is not supported.

## Syntax

```sql
LOAD DATA
    [/*+ PARALLEL(N) [load_batch_size(M)] [APPEND | direct(bool, int, [load_mode])] | NO_DIRECT */]
    [REMOTE_OSS | LOCAL] INFILE 'file_name'
    [REPLACE | IGNORE]
    INTO TABLE table_name [PARTITION(PARTITION_OPTION)] 
    [COMPRESSION [=] {AUTO|NONE|GZIP|DEFLATE|ZSTD}]
    [{FIELDS | COLUMNS}
        [TERMINATED BY 'string']
        [[OPTIONALLY] ENCLOSED BY 'char']
        [ESCAPED BY 'char']
    ]
    [LINES
        [STARTING BY 'string']
        [TERMINATED BY 'string']
    ]
    [IGNORE number {LINES | ROWS}]
    [(column_name_var
        [, column_name_var] ...)]

load_mode:
    'full' 
    | 'inc_replace'

PARTITION_OPTION:
    partition_option_list
    | subpartition_option_list
```

### Rules for using wildcard characters in multi-file direct load

To facilitate multi-file import, the wildcard character feature has been introduced for server-side and cloud object storage service (OSS) file import, but not for client-side file import.

* **Rules for using wildcard characters on the server side**

  * **Matching rules:**

    * Matching files: `load data /*+ parallel(20) direct(true, 0) */ infile '/xxx/test.*.csv' replace into table t1 fields terminated by '|';`

    * Matching directories: `load data /*+ parallel(20) direct(true, 0) */ infile '/aaa*bb/test.1.csv' replace into table t1 fields terminated by '|';`

    * Matching both files and directories: `load data /*+ parallel(20) direct(true, 0) */ infile '/aaa*bb/test.*.csv' replace into table t1 fields terminated by '|';`

  * **Considerations:**

    * At least one matching file must exist. Otherwise, error code 4027 is returned.

    * For the input `load data /*+ parallel(20) direct(true, 0) */ infile '/xxx/test.1*.csv,/xxx/test.6*.csv' replace into table t1 fields terminated by '|';`, `/xxx/test.1*.csv,/xxx/test.6*.csv` is considered a whole match. If no matching files are found, error code 4027 is returned.

    * Only wildcard characters supported by the POSIX GLOB function, such as `test.6*(6|0).csv` and `test.6*({0.csv,6.csv}|.csv)`, are supported. Although you can use the `ls` command to search for files that match these wildcard characters, the GLOB function cannot match any files, and error code 4027 is returned.

* **Rules for using wildcard characters in OSS**

  * **Matching rule:**

    Matching files: `load data /*+ parallel(20) direct(true, 0) */ remote_oss infile 'oss://xxx/test.*.csv?host=xxx&access_id=xxx&access_key=xxx' replace into table t1 fields terminated by '|';`

  * **Considerations:**

    * Directory matching is not supported. For example: `load data /*+ parallel(20) direct(true, 0) */ remote_oss infile 'oss://aa*bb/test.*.csv?host=xxx&access_id=xxx&access_key=xxx' replace into table t1 fields terminated by '|';` returns `OB_NOT_SUPPORTED`.

    * Only the wildcard characters `*` and `?` are supported for matching files. Other wildcard characters, even if they are allowed, cannot match any files.

### Import data from a server-side file

**Example 1: Import data from a server-side file.**

1. Set the global secure file path.

   ```shell
   obclient> SET GLOBAL secure_file_priv = "/"
   Query OK, 0 rows affected
   obclinet> \q
   Bye
   ```

   <main id="notice" type='explain'>
     <h4>Note</h4>
     <p>Since <code>secure_file_priv</code> is a <code>GLOBAL</code> variable, you need to exit and then reconnect to the database for the change to take effect. </p>
   </main>

2. Import data from an external file after reconnecting to the database.

   ```shell
   obclient> LOAD DATA INFILE 'test.sql' INTO TABLE t1;
   Query OK, 0 rows affected
   ```

**Example 2: Use the `APPEND` hint to enable direct load.**

```shell
LOAD DATA /*+ PARALLEL(4) APPEND */
   INFILE '/home/admin/a.csv'
   INTO TABLE t;
```

### Import data from a local file on the client (localhost) side

**Example 1: Import data from a local file to a table in OceanBase Database.**

1. Open a terminal or command prompt window and enter the following command to start the client.

    ```shell
    obclient --local-infile -hxxx.xxx.xxx.xxx -P2881 -uroot@mysql001 -p****** -A -Dtest
    ```

    The return result is as follows:


    <main id="notice" type='notice'>

2. In the client, execute the `LOAD DATA LOCAL INFILE` statement to load a local data file.

    ```shell
    obclient [test]> LOAD DATA LOCAL INFILE '/home/admin/test_data/tbl1.csv' INTO TABLE tbl1 FIELDS TERMINATED BY ',';
    ```

    ```shell

    Records: 3  Deleted: 0  Skipped: 0  Warnings: 0
    ```

**Example 2: Import a compressed file by setting the COMPRESSION parameter.**

```shell
LOAD DATA LOCAL INFILE '/your/file/lineitem.tbl.gz' 
    INTO TABLE lineitem 
    COMPRESSION GZIP 
    FIELDS TERMINATED BY '|';
```

**Example 3: Enable direct load for a specific partition by using the PARTITION parameter.**

* Enable direct load for a primary partition.

```shell
load data /*+ direct(true,0) parallel(2) load_batch_size(100) */ 
infile "$FILE_PATH" 
into table t1 partition(p0, p1) 
fields terminated by '|' enclosed by '' lines starting by '' terminated by '\n';
```

* Enable direct load for a subpartition.

```shell
load data /*+ direct(true,0) parallel(2) load_batch_size(100) */ 
infile "$FILE_PATH" 
into table t1 partition(p0sp0, p1sp1) 
fields terminated by '|' enclosed by '' lines starting by '' terminated by '\n';
```

**Example 1: Use the `direct(bool, int)` hint to enable direct load. The file to be imported is located on Alibaba Cloud OSS.**
