# CREATE ROUTINE LOAD

This statement is used to create a Routine Load task that continuously consumes data from Kafka and imports it into a table in OceanBase Database.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>Routine Load is an automatic data import process that runs in the background. Once you create a Routine Load job, the system will automatically consume Kafka data at regular intervals and import it into the target table in the background.</p>
</main>

## Privilege requirements

To create a Routine Load job, the current user must have the `INSERT` privilege on the target table. For more information about OceanBase Database privileges, see [Privilege types in MySQL mode](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md).

## Syntax

```sql
CREATE ROUTINE LOAD job_name ON table_name
    [load_properties]
    FROM STREAM (job_properties_expr);

load_properties:
    load_property_list

load_property_list:
    load_property [, load_property ...]

load_property:
    PARALLEL [=] int_value
  | COLUMNS (col1, col2, ...)
  | PARTITION (partition_name_list)
  | IGNORE | REPLACE
  | WHERE opt_hint_value expr

job_properties_expr:
    job_property [, job_property ...]

job_property:
    TYPE [=] 'KAFKA'
  | STRING_VALUE [=] STRING_VALUE
  | FORMAT [=] (format_options)

format_options:
    TYPE = 'CSV',
    LINE_DELIMITER = '<string>' | <expr>,
    FIELD_DELIMITER = '<string>' | <expr>,
    ESCAPE = '<character>' | <expr>,
    FIELD_OPTIONALLY_ENCLOSED_BY = '<character>' | <expr>,
    ENCODING = 'charset',
    NULL_IF = ('<string>' | <expr>, '<string>' | <expr> ...),
    SKIP_BLANK_LINES = {TRUE | FALSE},
    TRIM_SPACE = {TRUE | FALSE},
    EMPTY_FIELD_AS_NULL = {TRUE | FALSE}
```

## Parameters

| **Parameter** |       **Description**           |
|----------|--------------------------|
| job_name | The name of the job, which must be unique within the current tenant. This parameter is used to identify the Routine Load job.|
| table_name | The name of the target table. Data will be imported into this table.|
| load_property_list | An optional parameter that specifies data loading properties such as concurrency, column mapping, partitioning, conflict resolution strategy, and filter conditions. For more information, see [load_property_list](#load_property_list) below.|
| FROM STREAM | Specifies parameters related to the data source type.|
| TYPE = 'KAFKA' | An optional parameter that specifies the data source type. If not specified, the default value is `KAFKA`. <main id="notice" type='explain'><h4>Note</h4><p>In the current version, only <code>'KAFKA'</code> is supported as the data source type.</p></main>|
| STRING = STRING | Specifies a list of Kafka-related configuration parameters in key-value pairs. The keys are case-sensitive. In addition to format-related configurations, standard Kafka consumer parameters such as `security.protocol` and `sasl.mechanism` are supported. **You do not need to** configure `group.id`. The system will automatically establish a mapping between consumption threads and partitions based on the concurrency level. For more information, see [kafka_expr_list](#kafka_expr_list) below.|
| FORMAT [=] (format_options) | Specifies properties related to the Kafka data format. `format_options` specifies the Kafka data format options. For more information, see [format_options](#format_options) below.|

### load_property_list

* `PARALLEL [=] int_value`: Specifies the concurrency level. The default value is 1.
* `COLUMNS (col1, col2, ...)`: Specifies the mapping between Kafka message columns and target table columns.
* `PARTITION (partition_name_list)`: Specifies the target partitions for import.
* `{IGNORE | REPLACE}`: Specifies the conflict resolution strategy for primary key or unique key conflicts.

  * `IGNORE`: Ignores conflicting rows.

* `WHERE condition`: Specifies the data filter condition, which is applied before data is written to the target table.

### kafka_expr_list

* `bootstrap.servers`: A required parameter that specifies the list of Kafka broker addresses, separated by commas, such as `broker1:9092,broker2:9092`. This parameter specifies the entry address for the client to connect to Kafka for the first time.
* `kafka_topic`: A required parameter that specifies the name of the Kafka topic to consume.
* `kafka_partitions`: An optional parameter that specifies the list of partitions to consume, such as `"0,1,2"`. If not provided, all partitions of the topic will be consumed.
* `kafka_offsets`: An optional parameter that specifies the starting offset for each partition, corresponding to `kafka_partitions`. That is, it specifies the starting offset for each partition. If only one value is provided, it applies to all partitions. If not specified, the system will default to starting from `OFFSET_END` for all partitions of the topic. Currently, numeric values and `OFFSET_BEGINNING` and `OFFSET_END` can be mixed.
* `"max_batch_interval"`: An optional parameter that specifies the maximum runtime for each import thread per round of the job, in seconds. The default value is 60 seconds (the number of import threads is related to the concurrency level `PARALLEL`).
* `"max_batch_rows"`: An optional parameter that specifies the maximum number of rows that each import thread can read per round of the job. It must be greater than or equal to 200,000. The default value is 10,000,000.
* `"max_batch_size"`: An optional parameter that specifies the maximum number of bytes that each import thread can read per round of the job, in bytes. The range is from 100 MB to 1 GB. The default value is 1 GB.

**Term explanations**:

* **Offset (Consumption point)**: The logical position of each message in a Kafka partition. `OFFSET_BEGINNING` indicates the start of the earliest readable message in the partition, while `OFFSET_END` indicates the current latest position.
* **Low / High watermark**: The minimum and maximum offsets that can be consumed in a Kafka partition. The specified offset cannot be lower than the low watermark.

### format_options

Currently, only the **CSV** format is supported. The syntax aligns with the existing CSV parsing capabilities of OceanBase Database. For more information, see the format description in [LOAD DATA](5900.load-data-of-mysql-mode.md). Common options are as follows:

* `TYPE`: Specifies the data format. Currently, only the CSV format is supported.
* `LINE_DELIMITER`: Specifies the line delimiter for the CSV file. The default value is `LINE_DELIMITER='\n'`.
* `FIELD_DELIMITER`: An optional parameter that specifies the column delimiter for the CSV file. The default value is `FIELD_DELIMITER='\t'`.
* `ESCAPE`: Specifies the escape character for the CSV file. It must be a single byte. The default value is `ESCAPE ='\'`.
* `FIELD_OPTIONALLY_ENCLOSED_BY`: An optional parameter that specifies the symbol used to enclose field values in the CSV file. The default value is an empty string. Using this option indicates that only certain types of fields (such as CHAR, VARCHAR, TEXT, and JSON) will be enclosed.
* `ENCODING`: Specifies the character set encoding format of the file. If not specified, the default value is `UTF8MB4`.
* `NULL_IF`: Specifies the string that is treated as `NULL`. The default value is an empty string.
* `SKIP_BLANK_LINES`: Specifies whether to skip blank lines. The default value is `FALSE`, indicating that blank lines will not be skipped.
* `TRIM_SPACE`: Specifies whether to remove leading and trailing spaces from fields in the file. The default value is `FALSE`, indicating that leading and trailing spaces will not be removed.
* `EMPTY_FIELD_AS_NULL`: Specifies whether to treat empty strings as `NULL`. The default value is `FALSE`, indicating that empty strings will not be treated as `NULL`.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>Routine Load does not support <code>PARSE_HEADER</code> and <code>SKIP_HEADER</code> for CSV parsing. That is, the first row cannot be treated as the column names or skipped.</p>
</main>

## Examples

Create a routine load job named `load_job_0` to import data from Kafka to the `test_db.test_tbl1` table.

```shell
obclient> CREATE ROUTINE LOAD load_job_0 ON test_db.test_tbl1
    PARALLEL = 3
    WHERE id > 0
    FROM STREAM (
        TYPE = 'KAFKA',
        'bootstrap.servers' = 'xxx.xxx.xxx.1:xxxx',
        'security.protocol' = 'sasl_plaintext',
        'sasl.mechanism' = 'PLAIN',
        'sasl.username' = '******',
        'sasl.password' = '******',
        'kafka_topic' = 'test-topic',
        'kafka_partitions' = '0,1,2',
        'kafka_offsets' = '0,0,OFFSET_BEGINNING',
        'max_batch_interval' = '3000000',
        'max_batch_rows' = '200000',
        'max_batch_size' = '104857600',
        FORMAT = (
            TYPE = 'CSV',
            FIELD_DELIMITER = ',',
            TRIM_SPACE = TRUE)
        );
```
