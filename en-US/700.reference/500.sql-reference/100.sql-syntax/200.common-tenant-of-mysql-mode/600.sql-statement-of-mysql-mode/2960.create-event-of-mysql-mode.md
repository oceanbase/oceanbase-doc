# CREATE EVENT

## Description

This statement is used to create and schedule a new event.

<main id="notice" type='explain'>
  <h4>Note</h4>

  <p>In OceanBase Database V4.2.5, starting from V4.2.5 BP2, the EVENT task supports executing the <CODE>call</CODE> statement to call a stored procedure, and supports time expressions and functions when setting the start or end time.</p>
</main>

<main id="notice" type='notice'>
  <h4>Notice</h4>

The data source of the data source view is a data source object in the data source view.
  <p>EVENT is disabled by default. You need to execute the <code>SET GLOBAL event_scheduler = 1;</code> statement to enable it. For more information about this parameter, see <a href="../../../../../700.reference/800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/2600.event_scheduler-global.md"> event_scheduler</a>. </p></p>
</main>

## Permission requirements

The user who executes this statement must have the `CREATE` privilege. For more information about privileges in OceanBase Database, see [Privilege types in MySQL mode](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md).

## Syntax

```sql
CREATE
    [DEFINER = user]
    EVENT
    [IF NOT EXISTS]
    event_name
    ON SCHEDULE schedule
    [ON COMPLETION [NOT] PRESERVE]
[ENABLE | DISABLE | DISABLE ON SLAVE] // Default is ENABLE after creation
    [COMMENT 'string']
    DO event_body;

schedule: {
    AT timestamp [+ INTERVAL interval] ...
  | EVERY interval
    [STARTS timestamp [+ INTERVAL interval] ...]
    [ENDS timestamp [+ INTERVAL interval] ...]
}

interval:
    quantity {YEAR | QUARTER | MONTH | DAY | HOUR | MINUTE |
              WEEK | SECOND | YEAR_MONTH | DAY_HOUR | DAY_MINUTE |
              DAY_SECOND | HOUR_MINUTE | HOUR_SECOND | MINUTE_SECOND}
```

## Usage, limitations, and considerations

* If you set `EVERY interval` but do not set `START TIME` and `END TIME`, the task will run indefinitely.
* For repeated events, if the execution time of an event exceeds the scheduling interval, multiple events may be scheduled at the same time. Therefore, you must ensure that the execution time of an event is shorter than the scheduling interval.
* You cannot set the maximum execution time. The maximum execution time for a one-time event is 24 hours.
* We recommend that you do not create an event by using another event.

## Parameters

| Parameter   | Description     |
|-------|-----------|
|IF NOT EXISTS|Specifies whether to create an event if the event already exists. If this clause is not used, an error is returned when the event to be created already exists.|
|event_name|The name of the event to be created.|
|DEFINER|The user that executes the event. This parameter is optional. The default value is the current user, which is not supported.|
|ON SCHEDULE schedule|The time and frequency at which the event is to be executed. The value of this parameter can be a timestamp plus an INTERVAL value. For example, the value "2020-12-01 00:00:00" + INTERVAL 1 DAY indicates that the event is to be executed one day after December 1, 2020. The value of the timestamp must be an integer, and the unit of time can be YEAR, MONTH, DAY, HOUR, MINUTE, or SECOND.|
|ON COMPLETION [NOT] PRESERVE|Specifies whether to retain the event after it is completed. The default value is NOT PRESERVE, which indicates that the event is automatically deleted after it is executed.|
|ENABLE, DISABLE, DISABLE ON SLAVE|The state of the event. The default value is ENABLE, which indicates that the event is enabled after it is created. The value DISABLE indicates that the event is disabled after it is created. In this state, the event does not execute automatically and must be enabled manually. The value DISABLE ON SLAVE applies only to replication environments. In this state, the event does not execute on the server.|
|COMMENT 'string'|The description of the event. This parameter is optional.|
|DO event_body|The SQL statements to be executed. You can specify only one SQL statement or a block of SQL statements enclosed in the `BEGIN END` keywords. |

## Examples

```shell
obclient> CREATE EVENT myevent
    ON SCHEDULE AT '2024-07-01 00:00:00' + INTERVAL 1 HOUR
    DO
      UPDATE myschema.mytable SET mycol = mycol + 1;
```
