# AUDIT_LOG_FILTER_SET_USER

## Purpose

This function (expression) is used to set a filter to a user.

<main id="notice" >
  <h4>Applicability</h4>
  <p>This topic applies only to OceanBase Database Enterprise Edition. OceanBase Database Community Edition does not support audit features. </p>
</main>

## Syntax

```sql
AUDIT_LOG_FILTER_SET_USER('user_name', 'filter_name');
```

## Parameters

### Parameters

* `user_name`: specifies the user name.

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p><code>AUDIT_LOG_FILTER_SET_USER</code> allows you to specify a non-existent user or a wildcard in the <code>user@host</code> field. The <code>user_name</code> field has the following limitations: <ul><li>You cannot specify the <code>host</code> field. </li><li>You can only use the <code>%</code> wildcard to match the entire <code>user</code> field, not partial wildcards such as <code>test_%</code>. </li></ul></p>
    </main>

* `filter_name`: specifies the filter name.

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p><code>AUDIT_LOG_FILTER_SET_USER</code> has the <code>CREATE OR REPLACE</code> semantics. If the specified <code>filter_name</code> does not exist, the DDL operation does not take effect but does not return an error. </p>
    </main>

### Return value

The input must be a string constant, and the output is a string.

* If the DDL operation is successful, the expression returns `OK`.
* If the DDL operation fails, the `SELECT` statement still executes successfully, and the expression returns an error message.

## Examples

Set the `log_all` filter to the `user001` user.

```sql
SELECT AUDIT_LOG_FILTER_SET_USER('user001', 'log_all');
```

The return result is as follows:

```shell
+-------------------------------------------------+
| AUDIT_LOG_FILTER_SET_USER('user001', 'log_all') |
+-------------------------------------------------+
| OK                                              |
+-------------------------------------------------+
1 row in set
```
