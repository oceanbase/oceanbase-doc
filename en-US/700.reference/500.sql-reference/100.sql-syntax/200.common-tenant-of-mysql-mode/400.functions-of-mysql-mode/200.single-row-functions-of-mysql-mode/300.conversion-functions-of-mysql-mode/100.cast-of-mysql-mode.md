# CAST

## Syntax

```sql
CAST(expr AS type)
```

## Description

The `CAST()` function explicitly converts an expression from one data type to another. It converts the value of the `expr` column to the `type` data type.

### Parameters

The parameters are described as follows:

* `expr`: any valid SQL expression.

* `AS`: separates the two parameters. The part before `AS` specifies the expression to be converted, and the part after `AS` specifies the target data type.

* `type`: the data type in the target system. Valid values include:

  * `CHAR[(N)] [CHARACTER SET charset_name]`

    Generates a string of the `CHAR` data type. When the expression `expr` is empty (with a length of 0), the result type is `CHAR(0)`. If an optional length `N` is specified, `CHAR(N)` forces a conversion to use a maximum of `N` characters. Values shorter than `N` characters will not be padded. If an optional length `N` is not specified, OceanBase Database calculates the maximum length based on the expression. If the `CHARACTER SET charset_name` clause is not specified, `CHAR` generates a string with the default character set.

  * `DATE`: generates a `DATE` value.

  * `DATETIME [ (M) ]`: generates a `DATETIME` value. `M` is optional and specifies the precision for seconds in the fractional part, with a range of [0,6].

  * `DECIMAL [ (M [,D] ) ]`: generates a `DECIMAL` value. `M` and `D` are optional and specify the maximum number of digits (precision) and the number of decimal places (scale), respectively. `M` can be at most 65, and `D` can be at most 30. If `D` is omitted, it defaults to `0`. If `M` is omitted, it defaults to `10`.

  * `SIGNED [INTEGER]`: generates a signed `BIGINT` value.

  * `JSON`: generates a `JSON` value. For more information about the conversion rules between JSON values and other types of values, see [JSON data type conversion](../../../100.basic-elements-of-mysql-mode/100.data-type-of-mysql-mode/800.json-formatted-data-type-of-mysql-mode/400.json-formatted-data-type-conversion-of-mysql-mode.md).

  * `TIME [ (M) ]`: generates a `TIME` value. If `M` is provided, it specifies the precision for seconds in the fractional part.

  * `UNSIGNED [INTEGER]`: generates an unsigned `BIGINT` value.
  * `DECIMAL(m,d)`: a fixed-point number type. `m` specifies the total number of digits, and `d` specifies the number of decimal places.
  * `FLOAT`: a single-precision floating-point number, used for approximate numerical values.
  * `INT` or `INTEGER`: a 32-bit signed integer.
  * `SMALLINT`: a 16-bit signed integer.
  * `TINYINT`: an 8-bit signed integer.
  * `ARRAY`: converts elements in a `JSON` array to an array of a specific data type.

### Considerations

When using the `CAST()` function for data type conversion, the following scenarios are supported:

* The data types of the two expressions are the same.

* The two expressions can be implicitly converted.

* The data types must be explicitly converted.
* If the value of the `expr` expression exceeds the range of the target data type, the type conversion returns `null`.
* Converting a high-precision data type to a low-precision data type results in precision loss.
* Converting a fixed-point number (`DECIMAL(m,d)`) or a floating-point number (`DOUBLE` or `FLOAT`) to an integer (`INT`, `INTEGER`, `SMALLINT`, or `TINYINT`) results in precision loss.
* If the `expr` expression is of the `VARCHAR` type and not a numeric value, it returns `0` when converted to `INT`, `INTEGER`, `SMALLINT`, or `TINYINT`.
* If the `expr` expression is of the JSON type and not a numeric value, converting it to `INT`, `INTEGER`, `SMALLINT`, or `TINYINT` results in an error.
* If the `VARCHAR` or `JSON` data does not conform to the `ARRAY` format, it returns an error during conversion.

If an invalid conversion is attempted, OceanBase Database will display an error message. If the length of the data type is not specified during conversion, the maximum length allowed by OceanBase Database system is used. For example, `VARCHAR` is 262,143 bytes and `NUMBER` is 65 bits of floating-point precision.

The `CAST()` function supports operations involving signed and unsigned 64-bit values. When using a numeric operator (such as `+`) and one of the operands is an unsigned integer, the result will be unsigned. You can use `SIGNED` or `UNSIGNED` to explicitly declare the result as a signed or unsigned 64-bit integer. If either operand is a floating-point value, the result will be a floating-point value.

## Examples

* Convert the numeric value 0 to the `DATE` type.

  ```sql
  obclient> SELECT CAST(0 AS DATE);
  +-----------------+
  | CAST(0 AS DATE) |
  +-----------------+
  | 0000-00-00      |
  +-----------------+
  1 row in set
  ```

* Convert the numeric value 123 to the `TIME` type.

  ```sql
  obclient> SELECT CAST(123 AS TIME);
  +-------------------+
  | CAST(123 AS TIME) |
  +-------------------+
  | 00:01:23          |
  +-------------------+
  1 row in set
  ```

* Convert the numeric value 123 to the `DATETIME` type.

  ```sql
  obclient> SELECT CAST(123 AS DATETIME(4));
  +--------------------------+
  | CAST(123 AS DATETIME(4)) |
  +--------------------------+
  | 2000-01-23 00:00:00.0000 |
  +--------------------------+
  1 row in set
  ```

* Convert the numeric value 123 to the `DECIMAL` type.

  ```sql
  obclient>  SELECT CAST(123 AS DECIMAL(3,2));
  +---------------------------+
  | CAST(123 AS DECIMAL(3,2)) |
  +---------------------------+
  |                      9.99 |
  +---------------------------+
  1 row in set
  ```

* Convert the string "123" to the JSON type.

  ```sql
  obclient> SELECT CAST("123" AS JSON);
  +---------------------+
  | CAST("123" AS JSON) |
  +---------------------+
  | 123                 |
  +---------------------+
  1 row in set
  ```

* Represent the result of "1-2" using both signed and unsigned formats.

  ```sql
  obclient> SELECT CAST(1-2 AS UNSIGNED), CAST(cast(1-2 AS UNSIGNED) AS SIGNED);
  +-----------------------+---------------------------------------+
  | CAST(1-2 AS UNSIGNED) | CAST(cast(1-2 AS UNSIGNED) AS SIGNED) |
  +-----------------------+---------------------------------------+
  |  18446744073709551615 |                                    -1 |
  +-----------------------+---------------------------------------+
  1 row in set
  ```

* Perform a numeric operation using `CAST()`.

  ```sql
  obclient> SELECT CAST(1 AS UNSIGNED) - 2.0;
  +---------------------------+
  | CAST(1 AS UNSIGNED) - 2.0 |
  +---------------------------+
  |                      -1.0 |
  +---------------------------+
  1 row in set
  ```

* Convert the numeric value 123 to the `CHAR` type.

  ```sql
  obclient> SELECT CAST(123 AS CHAR(2));
  +----------------------+
  | CAST(123 AS CHAR(2)) |
  +----------------------+
  | 12                   |
  +----------------------+
  1 row in set
  ```

* Convert the numeric value 1 to the `CHAR` type and specify the character set.

  ```sql
  obclient> SELECT CAST(1 AS CHAR CHARACTER SET utf8mb4);
  +---------------------------------------+
  | CAST(1 AS CHAR CHARACTER SET utf8mb4) |
  +---------------------------------------+
  | 1                                     |
  +---------------------------------------+
  1 row in set
  ```

* Convert the string `123` to an integer and the integer `1` to the `INT` type.

  ```sql
  obclient> SELECT CAST('123' AS INT),CAST(1 AS CHAR(10));
  +--------------------+---------------------+
  | CAST('123' AS INT) | CAST(1 AS INT) |
  +--------------------+---------------------+
  |                123 | 1                   |
  +--------------------+---------------------+
  1 row in set
  ```

* Convert `JSON` data [1,2,3] to an `ARRAY` data type composed of `INT` type. Here is the statement:

  ```sql
  obclient> SELECT CAST( JSON '[1,2,3]' AS ARRAY<int>);
  +-------------------------------------+
  | CAST( JSON '[1,2,3]' AS ARRAY<int> |
  +-------------------------------------+
  | [1,2,3]                             |
  +-------------------------------------+
  1 row in set
  ```
