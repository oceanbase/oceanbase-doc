# Distributed DML hint

In OceanBase Database in MySQL mode, you can use the distributed DML hint to specify whether to execute DML operations in a distributed manner. Note the following two important concepts:

- Distributed DML: DML operations that are executed across multiple nodes. This is fundamentally different from non-distributed DML operations that are executed locally or in a partition-wise manner on a single node.
- Parallel DML: DML operations that are executed in parallel by multiple threads on a single node.

In addition, although such hints can be used for fixed execution plans, they are not recommended for general use. They are typically only enabled in OUTLINE DATA.

| Hint name                              | Description       |
|---------------------------------------|------------|
| `USE_DISTRIBUTED_DML`     |Enables distributed DML operations. The opposite is `NO_USE_DISTRIBUTED_DML`.  |
| `NO_USE_DISTRIBUTED_DML`  | Disables distributed DML operations. The opposite is `USE_DISTRIBUTED_DML`.    |

## `USE_DISTRIBUTED_DML` Hint

The `USE_DISTRIBUTED_DML` hint enables distributed DML operations. When this hint is enabled, DML operations are executed in a distributed manner. Its opposite is the `NO_USE_DISTRIBUTED_DML` hint.

### Syntax

```sql
/*+ USE_DISTRIBUTED_DML [ ( [ @ qb_name ] ) ] */
```

### Examples

```sql
-- Create a table named tp1 with 10 hash partitions.
CREATE TABLE tp1(c1 INT, c2 INT, c3 INT) PARTITION BY HASH(c1) PARTITIONS 10;

-- Update the tp1 table using the USE_DISTRIBUTED_DML hint, setting the value of column c2 to 4 where the value of column c1 is less than 4.
-- This update operation will be executed in a distributed manner.
EXPLAIN BASIC UPDATE /*+ USE_DISTRIBUTED_DML */ tp1 SET c2 = 4 WHERE c1 < 4;
```

## `NO_USE_DISTRIBUTED_DML` Hint

The `NO_USE_DISTRIBUTED_DML` hint prevents DML operations from using distributed execution. Its opposite is the `USE_DISTRIBUTED_DML` hint.

### Syntax

```sql
/*+ NO_USE_DISTRIBUTED_DML [ ( [ @ qb_name ] ) ] */
```

### Examples

```sql
-- Create a table tp1 with 10 hash partitions.
CREATE TABLE tp1(c1 INT, c2 INT, c3 INT) PARTITION BY HASH(c1) PARTITIONS 10;

-- Use the NO_USE_DISTRIBUTED_DML hint to limit updates to be performed locally on a single node instead of distributedly.
-- This update operation will be performed non-distributedly.
EXPLAIN BASIC UPDATE /*+ NO_USE_DISTRIBUTED_DML */ tp1 SET c2 = 4 WHERE c1 < 4;
```
