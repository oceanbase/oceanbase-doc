# Create a JSON value

A JSON value must be an object (JSON object), an array, a string, a number, a boolean value (false/true), or null. The boolean values false, true, and null must be in lowercase.

## JSON text structure

A JSON text consists of characters, strings, numbers, and three literal names. Various separators, such as spaces, horizontal tabs, line breaks, and carriage returns, are allowed before or after any structural character.

```sql
       StartArray = [ LeftBracket

       StartObject = { LeftBrace

       EndArray = ] RightBracket

       EndObject = } RightBrace

       NameSeparator = : Colon

       ValueSeparator = , Comma
```

### Objects

An object is a collection of name/value pairs (also known as members). An object consists of a pair of left and right curly braces containing zero or more name/value pairs. The names in an object must be unique. A name is a string followed by a colon to separate the name and value. A single comma separates multiple name/value pairs.
Here is an example:

```sql
{ "NAME": "SAM",  "Height": 175, "Weight":  100，"Registered" : false}
```

### Arrays

An array is a collection of values (also known as elements). The values are separated with commas. An array can contain zero or more values. The values in an array do not need to be of the same type.

Here is an example:

```sql
["abc", 10, null, true, false]
```

### Numbers

A number consists of a decimal number, which can have an integer part, a minus sign (-) as the prefix (optional), a fraction part, and an exponent part. Leading zeros are not allowed. The decimal part consists of a decimal point and one or more digits. The exponent part starts with the letter E in uppercase or lowercase, followed by a plus sign (+) or a minus sign (-). The letter E and the optional sign can be followed by one or more digits.

Here is an example:

```sql
[100, 0, -100, 100.11, -12.11, 10.22e2, -10.22e2]
```

### Strings

A string is enclosed in quotation marks ("). All Unicode characters can be placed in the quotation marks, except for characters that must be escaped (including quotation marks, backslashes, and control characters).

A JSON text is encoded in UTF-8, UTF-16, or UTF-32. The default encoding is UTF-8.

Here is an example:

```sql
{"Url":    "http://www.example.com/image/481989943"}
```

## Create a JSON value

OceanBase Database supports the following DDL operations on JSON data:

* Create a table with a JSON column.

* Add or drop a JSON column.

* Create an index on a column that is generated as a JSON column.

* Enable semi-structured encoding when creating tables in MySQL tenants.

* Enable semi-structured encoding for existing tables in MySQL tenants.

### Limitations

A user can create multiple JSON columns in each table, but the following limitations apply:

* JSON columns cannot be specified as `PRIMARY KEY`, `FOREIGN KEY`, or `UNIQUE KEY` columns. However, you can add the `NOT NULL` or `CHECK` constraint to a JSON column.

* Default values cannot be set for JSON columns.

* JSON columns cannot be partitioning key columns.

* The length of JSON data cannot exceed the limit of the `LONGTEXT` data type. In addition, the maximum depth of each JSON object or array is 99.

### Example

#### Create or modify a JSON column

```sql
obclient> CREATE TABLE tbl1 (id INT PRIMARY KEY, docs JSON NOT NULL, docs1 JSON);
Query OK, 0 rows affected

obclient> ALTER TABLE tbl1 MODIFY docs JSON CHECK(docs <'{"a" : 100}');
Query OK, 0 rows affected

obclient> CREATE TABLE json_tab(
      id         INT UNSIGNED PRIMARY KEY AUTO_INCREMENT COMMENT 'Primary key',
      json_info  JSON COMMENT 'JSON data',
      json_id    INT GENERATED ALWAYS AS (json_info -> '$.id') COMMENT 'Virtual column of JSON data',
      json_name  VARCHAR(5) GENERATED ALWAYS AS (json_info -> '$.NAME'),
      index      json_info_id_idx (json_id)
    )COMMENT 'Example table of JSON data';
Query OK, 0 rows affected

obclient> ALTER TABLE json_tab ADD COLUMN json_info1 JSON;
Query OK, 0 rows affected

obclient> ALTER TABLE json_tab ADD INDEX (json_name);
Query OK, 0 rows affected

obclient> ALTER TABLE json_tab drop COLUMN json_info1;
Query OK, 0 rows affected
```

#### Use semi-structured encoding

OceanBase Database allows you to enable semi-structured encoding when you create a table in a MySQL tenant. You can mainly control this feature by using the table-level parameter `semistruct_encoding_type`. You must also set the `row_format` parameter of the table to `COMPRESSED`. Otherwise, an error occurs. If you set `semistruct_encoding_type='encoding'`, the table is considered a semi-structured table, and semi-structured encoding is enabled for all JSON columns in the table. If you set `semistruct_encoding_type=''`, the table is considered a structured table. You can use semi-structured encoding to improve the performance of queries with the [JSON_VALUE() function](../../../400.functions-of-mysql-mode/700.json-functions-of-mysql-mode/200.search-json-text-function-of-mysql-mode/700.json-value-of-mysql-mode.md).

1. Enable semi-structured encoding.

      :::tab
      tab Syntax for enabling semi-structured encoding when creating a table

      ```sql
      CREATE TABLE t1(
        j json
      ) row_format=COMPRESSED semistruct_encoding_type = 'encoding';
      ```

      For more information, see [CREATE TABLE](../../../600.sql-statement-of-mysql-mode/2600.create-table-of-mysql-mode.md).

      tab Syntax for enabling semi-structured encoding for an existing table

      ```sql
      CREATE TABLE t1(j json);
      ALTER TABLE t1 SET row_format=COMPRESSED semistruct_encoding_type = 'encoding';
      ```

      For more information, see [ALTER TABLE](../../../600.sql-statement-of-mysql-mode/1600.alter-table-of-mysql-mode.md).
      :::

2. Disable semi-structured encoding.

      The following example shows how to disable semi-structured encoding:

      ```sql
      ALTER TABLE t1 SET row_format=COMPRESSED semistruct_encoding_type = '';
      ```

3. Query the configuration of semi-structured encoding.

      You can execute the `SHOW CREATE TABLE` statement to query the configuration of semi-structured encoding. The sample statement is as follows:

      ```sql
      SHOW CREATE TABLE t1;
      ```

      The return result is as follows:

      ```shell
      +-------+--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
      | Table | Create Table                                                                                                                                                                                                                                                                                           |
      +-------+--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
      | t1    | CREATE TABLE `t1` (
        `j` json DEFAULT NULL
      ) DEFAULT CHARSET = utf8mb4 
        ROW_FORMAT = COMPRESSED COMPRESSION = 'zstd_1.3.8' REPLICA_NUM = 1 BLOCK_SIZE = 16384 USE_BLOOM_FILTER = FALSE ENABLE_MACRO_BLOCK_BLOOM_FILTER = FALSE TABLET_SIZE = 134217728 PCTFREE = 0 
        SEMISTRUCT_ENCODING_TYPE='ENCODING' |
      +-------+--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
      1 row in set
      ```

      If the `semistruct_encoding_type` parameter is set to 'encoding', the query result shows that the semi-structured encoding feature is enabled.
