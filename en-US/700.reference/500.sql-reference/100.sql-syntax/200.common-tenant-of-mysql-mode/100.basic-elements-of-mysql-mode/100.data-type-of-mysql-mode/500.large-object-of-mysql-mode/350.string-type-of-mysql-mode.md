# STRING type

As a text type, the `STRING` type allows for easier migration of AP business and supports variable-length strings as primary keys.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>In OceanBase Database V4.3.5, the <code>STRING</code> data type is supported in the V4.3.5 BP1 version and later. </p>
</main>

## Features

* When you create a table, you do not need to specify the length for the `STRING` type. The maximum length is 16 MB (16777216 bytes).
* A column of the `STRING` type (referred to as a String column) can be used as the primary key, index, partitioning key for KEY/Range columns/List columns partitioned tables.
* The `STRING` type is a special case of the `LOB` type:

  * If a String column is a non-primary key column and its length exceeds the `LOB_INROW_THRESHOLD` (the threshold for primary key columns), the data exceeding the threshold will be stored outside the row.
  * If a String column is a primary key column, all data will be stored in the row. The data length will be limited by the primary key length.

## Limitations

* The default value of a `STRING` column can only be `NULL`.

* When a `STRING` column is a non-primary key column, whether the data of the column is stored in the row or outside the row depends on the `LOB_INROW_THRESHOLD`. When a `STRING` column is a primary key column, all data of the column is stored in the row.

    For more information about the `LOB_INROW_THRESHOLD`, see [LOB type](400.lob-type-of-mysql-mode.md) and [ob_default_lob_inrow_threshold](../../../../../../800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/6300.ob_default_lob_inrow_threshold-global.md).

* When a String column is used as the primary key or index key, the system checks the length of the primary key or index key during write (or update). If the length exceeds 16 KB, an error is returned.

* When you create a unique index that contains a String column, if the corresponding column in the primary table has data stored outside the row, the system returns an error.

* After an index is created on a String column, if the data of the column needs to be written (or updated) and the length of the data exceeds `LOB_INROW_THRESHOLD`, the system returns an error.

* If you attempt to write (or update) data to (or from) a LOB that has exceeded the row length, the system returns an error. For example, in an `INSERT INTO ... SELECT ...` statement, if the data of the `SELECT` statement exceeds the row length, an error is returned.

* In direct load, if the target table has an index on a String column and the data of the column exceeds `LOB_INROW_THRESHOLD` after the data is loaded, the system returns an error.

* In incremental direct load, if the source table has data stored outside the row for a String column and the target table has an index on the corresponding String column, the system returns an error.

## Examples

1. Create a table named `test_tbl1` with `col1`, `col2`, and `col3` as string columns. Set `col1` as the primary key. Partition the table by KEY using the values in `col1` into 4 partitions.

    ```sql
    CREATE TABLE test_tbl1 (col1 STRING PRIMARY KEY,
        col2 STRING,
        col3 STRING,
        col4 VARCHAR(10))
        PARTITION BY KEY(col1) PARTITIONS 4;
    ```

2. Create an index named `idx_test_tbl1` on the `col2` column.

    ```sql
    CREATE INDEX idx_test_tbl1 ON test_tbl1(col2);
    ```

3. View the definition of the `test_tbl1` table.

    ```sql
    SHOW CREATE TABLE test_tbl1;
    ```

    The return result is as follows:

    ```shell
    +-----------+-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
    | Table     | Create Table                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
    +-----------+-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
    | test_tbl1 | CREATE TABLE `test_tbl1` (
    `col1` string NOT NULL,
    `col2` string DEFAULT NULL,
    `col3` string DEFAULT NULL,
    `col4` varchar(10) DEFAULT NULL,
    PRIMARY KEY (`col1`),
    KEY `idx_test_tbl1` (`col2`) BLOCK_SIZE 16384 LOCAL
    ) ORGANIZATION INDEX DEFAULT CHARSET = utf8mb4 ROW_FORMAT = DYNAMIC COMPRESSION = 'zstd_1.3.8' REPLICA_NUM = 1 BLOCK_SIZE = 16384 USE_BLOOM_FILTER = FALSE ENABLE_MACRO_BLOCK_BLOOM_FILTER = FALSE TABLET_SIZE = 134217728 PCTFREE = 0
    partition by key(col1)
    (partition `p0`,
    partition `p1`,
    partition `p2`,
    partition `p3`) |
    +-----------+-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
    1 row in set
    ```

4. Insert test data into the `test_tbl1` table.

    ```sql
    INSERT INTO test_tbl1 VALUES("A1", "B1", "C1", "D1"),("A2", "B2", "C2", "D2");
    ```

5. View the data in the `test_tbl1` table.

    ```sql
    SELECT * FROM test_tbl1;
    ```

    The return result is as follows:

    ```shell
    +------+------+------+------+
    | col1 | col2 | col3 | col4 |
    +------+------+------+------+
    | A2   | B2   | C2   | D2   |
    | A1   | B1   | C1   | D1   |
    +------+------+------+------+
    2 rows in set
    ```
