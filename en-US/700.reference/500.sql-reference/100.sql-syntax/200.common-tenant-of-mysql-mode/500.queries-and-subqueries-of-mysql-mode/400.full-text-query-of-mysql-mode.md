# Full-text search

Full-text search refers to the operation of searching for or retrieving text data. It is used to find text content that contains specific keywords, phrases, or text expressions. Full-text search allows for a more comprehensive search of the entire text and returns results that match the search criteria.

## Syntax

Use the following syntax to perform a full-text search based on specified columns and keywords or phrases. You can also use specific search modifiers to adjust the search mode (that is, search conditions or rules).

```sql
MATCH (column_name [, column_name ...]) AGAINST (expr [search_modifier])

search_modifier:
    IN NATURAL LANGUAGE MODE
    | IN BOOLEAN MODE
    | IN MATCH PHRASE MODE
```

**The following table describes the related parameters:**

* `column_name`: the name of the column to be searched. Separate multiple column names with commas (,).

* `expr`: the keyword or phrase to be searched.

* `search_modifier`: optional. The value specifies the search mode. The following table describes the values and applicable scenarios.

  |         Search mode          | Parameter description | Applicable scenarios |
  |--------------------------|----------|---------|
  | IN NATURAL LANGUAGE MODE | The default value, which specifies to use the natural language search mode. | Natural language, topk scenarios, fuzzy matching, and output of relevance, where words are split by the tokenizer set in the table. |
  | IN BOOLEAN MODE <main id="notice" type='explain'><h4>Note</h4><p>For OceanBase Database V4.3.5, <code>IN BOOLEAN MODE</code> is supported starting from V4.3.5 BP1. </p></main>| Specifies to use the Boolean mode. The following table describes the Boolean operators and nested operations supported in the current version. <ul><li>`+`: indicates `AND`, the intersection. </li><li>`-`: indicates NOT, the difference. </li><li>Without an operator: when used alone, it indicates `OR`, the union. For example, `A B` indicates `A OR B`. When used with a symbol, it will increase the relevance of the sentence but lose the `OR` semantics. For example, `+A B` indicates that A must be present and the relevance of A and B in the sentence will be calculated. </li><li>`()`: indicates nested operations. When there is no symbol outside, it has the `OR` semantics. For example, `+A (nested clause)` indicates that A or the nested clause must be present. </li></ul>| Filtering semantic, exact matching, filtering based on user output syntax, and optional output of relevance, where each word is split only by spaces and `+`, `-`, and `()`. |
  | IN MATCH PHRASE MODE <main id="notice" type='explain'><h4>Note</h4><p>For OceanBase Database V4.4.0 and later, <code>IN MATCH PHRASE MODE</code> is supported. </p></main>| Specifies to use the phrase query mode. | Phrase matching, no tokenization, and query results that must exactly match. |

  **Here are some examples:**

  1. The output sentence must contain the word "computer".

      ```sql
      obclient> SELECT * FROM my_table WHERE MATCH (doc) AGAINST ("+computer" IN BOOLEAN MODE);
      ```

  2. The output sentence must contain the word "computer" and must not contain the word "weather".

      ```sql
      obclient> SELECT * FROM my_table WHERE MATCH (doc) AGAINST ("+computer -weather" IN BOOLEAN MODE);
      ```

  3. The output sentence must contain the word "computer" and "oceanbase" is more relevant.

      ```sql
      obclient> SELECT * FROM my_table WHERE MATCH (doc) AGAINST ("+computer oceanbase" IN BOOLEAN MODE);
      ```

  4. Perform a phrase query.

     * Use `MATCH AGAINST` as the `SELECT` clause.

       ```sql
       obclient> SELECT id, MATCH (title, body) AGAINST ('some words' IN MATCH PHRASE MODE) AS score
           FROM test;
       ```

     * Use `MATCH AGAINST` as the `WHERE` clause.

       ```sql
       obclient> SELECT * FROM test WHERE MATCH (title, body) AGAINST ('some words' IN MATCH PHRASE MODE);
       ```

For more information about the `MATCH AGAINST` expression, see [MATCH AGAINST](../400.functions-of-mysql-mode/1000.other-functions-of-mysql-mode/2250.match-against-of-mysql-mode.md).

### Vectorized query

For queries that contain a full-text index, you can choose to use vectorized or non-vectorized query. You can use the `/*+ opt_param('rowsets_enabled', '[true | false]')*/` hint to enable or disable vectorized query.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>If you do not specify the hint, whether to enable vectorized query depends on the system parameter configuration of the vectorized engine. By default, vectorized query is enabled. </p>
</main>

**Here are some examples:**

* Enable vectorized query.

  ```sql
  obclient> SELECT /*+ opt_param('rowsets_enabled', 'true') */ title, body
      FROM articles
      WHERE MATCH(title, body) AGAINST('tutorial');
  ```

* Disable vectorized query.

  ```sql
  obclient> SELECT /*+ opt_param('rowsets_enabled', 'false') */ title, body
      FROM articles
      WHERE MATCH(title, body) AGAINST('tutorial');
  ```

1. Create a table named `tbl1` and a full-text index named `full_idx1_tbl1`.

    obclient> CREATE TABLE tbl1(col1 INT PRIMARY KEY, col2 VARCHAR(100), col3 TEXT, FULLTEXT INDEX full_idx1_tbl1(col2, col3));

2. Insert test data into the `tbl1` table.

## Full-text search in Elasticsearch

OceanBase Database supports the following SQL syntax for full-text search in Elasticsearch, starting from V4.4.1: `MATCH()` and `SCORE()`.

* The `MATCH()` statement is used in the `WHERE` clause to specify the filtering condition. It must be used with the `SCORE()` statement.

  <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>Currently, only one <code>MATCH()</code> statement can be specified in the <code>WHERE</code> clause, and it cannot be used together with <code>MATCH() AGAINST()</code>. </p>
  </main>

* The `SCORE()` statement specifies the relevance of the corresponding `MATCH()` statement. It must be used with the `MATCH()` statement and has no meaning when used alone.

The syntax for full-text search in Elasticsearch is as follows:

```sql
SELECT [select_expr_list ,] SCORE()
FROM table_name
WHERE
    MATCH(
        A_COLUNM^x, B_COLUNM^y ...,
        'expr',
        '[parameters]'
        )
... ;

parameters:
    operator=or;
    minimum_should_match=int_value;
    boost=number_value;
    score_norm=min-max;
    type={most_fields | best_fields}
```

**The following table describes the related parameters:**

* `A_COLUNM^x, B_COLUNM^y ...`: specifies the column names and weights. The weights must be positive numbers.

  <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>Each column in the <code>MATCH()</code> statement must have a full-text index, not a composite index. For more information about how to create a full-text index, see <a href="../../../../300.database-object-management/100.manage-object-of-mysql-mode/500.manage-indexes-of-mysql-mode/200.create-an-index-of-mysql-mode.md">Create an index</a>. </p>
  </main>

* `expr`: specifies the query statement. It is divided into several tokens, and each token can have a weight. The weights must be positive numbers, and the default value is 1.
* `parameters`: an optional parameter that specifies a list of key-value pairs. If no additional parameters are specified, you must retain a pair of empty quotes `''`. The following parameters are supported:

  * `operator`: specifies the aggregation algorithm for the `expr` parameter. Valid values:

    * `or`: specifies that a result is returned if any token is matched. If the `minimum_should_match` parameter is specified, the returned result is determined by the value of the `minimum_should_match` parameter.

  * `minimum_should_match`: specifies the minimum number of keywords to be matched in the token group. Valid value: a positive integer.
  * `boost`: specifies the weight of the `MATCH` level. The weight is multiplied by the relevance. Default value: 1.
  * `score_norm`: specifies the normalization algorithm for a `MATCH` statement. Valid value: `min-max`. Default value: no normalization.
  * `type`: specifies the relevance calculation method for multiple columns in a `MATCH` statement. Valid values:

    * `most_fields`: specifies to sum the relevances of all columns.
    * `best_fields`: specifies to take the maximum relevance of all columns.

**Here are some examples:**

1. Create a full-text index on the `col2` column of the `tbl1` table.

    ```shell
    obclient> CREATE FULLTEXT INDEX ft_idx_tbl1_col2 ON tbl1(col2);
    ```

2. Create a full-text index on the `col3` column of the `tbl1` table.

    ```shell
    obclient> CREATE FULLTEXT INDEX ft_idx_tbl1_col3 ON tbl1(col3);
    ```

3. Search for rows that contain both "OceanBase" and "Database" (at least 2 keywords matched, `minimum_should_match=2`) in the `tbl1` table, and return the relevance scores (normalized to the 0-1 range) for the `col2` (weight 2) and `col3` (weight 1) columns.

    ```shell
    obclient> SELECT *, SCORE() AS relevance_score
        FROM tbl1
        WHERE
            MATCH(col2^2, col3^1,
                  'OceanBase Database',
                  'operator=or;
                  minimum_should_match=2;
                  boost=1;
                  score_norm=min-max;
                  type=most_fields'
                );
    ```

    The returned result is as follows:

    ```shell
    +------+-----------+---------------------------------------------------------------------------------------------------------------------+--------------------+
    | col1 | col2      | col3                                                                                                                | relevance_score    |
    +------+-----------+---------------------------------------------------------------------------------------------------------------------+--------------------+
    |    2 | OceanBase | OceanBase Database is a native, enterprise-level distributed database developed independently by the OceanBase team | 0.6079027355623101 |
    +------+-----------+---------------------------------------------------------------------------------------------------------------------+--------------------+
    1 row in set
    ```

4. Search for rows that contain "OceanBase" or "Database" (at least 1 keyword matched, `minimum_should_match=1`) in the `tbl1` table, and return the relevance scores (normalized to the 0-1 range) for the `col2` (weight 2) and `col3` (weight 1) columns.

    ```shell
    obclient> SELECT *, SCORE() AS relevance_score
        FROM tbl1
        WHERE
            MATCH(col2^2, col3^1,
                  'OceanBase Database',
                  'operator=or;
                  minimum_should_match=1;
                  boost=1;
                  score_norm=min-max;
                  type=most_fields'
                );
    ```

    The returned result is as follows:

    ```shell
    +------+---------------------+---------------------------------------------------------------------------------------------------------------------+--------------------+
    | col1 | col2                | col3                                                                                                                | relevance_score    |
    +------+---------------------+---------------------------------------------------------------------------------------------------------------------+--------------------+
    |    2 | OceanBase           | OceanBase Database is a native, enterprise-level distributed database developed independently by the OceanBase team | 0.4208104883442219 |
    |    3 | Database Management | Learn about SQL and database administration                                                                         | 0.2876526910145043 |
    +------+---------------------+---------------------------------------------------------------------------------------------------------------------+--------------------+
    2 rows in set
    ```
