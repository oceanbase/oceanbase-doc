# NUMBER type conversion rules

The storage format of the `NUMBER` type in OceanBase Database is the same, but it can be categorized into four different formats based on the value domain, as shown in the following table.

| Storage type | Default storage rules in MySQL mode | Default storage rules in Oracle mode | Description |
| --- | --- | --- | --- |
| Fixed-point number `DECIMAL(M,D) = {10^{-D}*i &#124; i = 0,1,...,10^M-1}` where M is a natural number and D is an integer | <ul><li> DECIMAL = DECIMAL(10, 0)</li> <li>DECIMAL(M) = DECIMAL(M, 0)</li> <li>DECIMAL(M, D) has a value range of 0 <= D <= M <= 65. </li></ul> | <ul><li> DECIMAL = NUMBER(38)</li> <li> NUMBER(M) = NUMBER(38,0)</li> <li> NUMBER(M,D) has M in the range [1, 38] and D in the range [-84,127].</li></ul>| A fixed-point number (M1,D1) is a subset of a fixed-point number (M2,D2) if and only if `D1 <= D2` and `M1-D1 <= M2-D2`. |
| Unsigned fixed-point number DECIMAL(M,D) | <ul><li> DECIMAL</li> <li> DECIMAL(M)</li> <li> DECIMAL(M,D) </li> <li>Supports the UNSIGNED attribute</li></ul>| Not supported | An unsigned fixed-point number is equivalent to the non-negative values of the fixed-point number `DECIMAL(M,D)`. |
| Floating-point NUMBER | Not supported | NUMBER | In Oracle mode, the floating-point `NUMBER` has a total precision of 38 bits and is not a subset of `NUMBER(M, D)`. However, `NUMBER(M, D)` is a subset of the floating-point `NUMBER` if and only if `M-D <= 38`. |
| Oracle FLOAT(P) | Not supported | <ul><li>REAL = FLOAT(63) </li> <li>FLOAT = FLOAT(126)</li> <li>FLOAT(P) has P in the range [1, 126].</li></ul>| Not applicable. |

The conversion rules between all `NUMBER` types in OceanBase Database V4.2.0 and later are as follows. "-" indicates that the conversion spans compatibility modes.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <ul><li><p> Floating-point <code>NUMBER</code> and Oracle <code>FLOAT</code> exist only in Oracle mode, while unsigned fixed-point numbers exist only in MySQL mode. </p></li>
  <li><p> In Oracle mode, instant conversion (schema-only conversion without data changes) is not allowed for non-empty tables. In MySQL mode, instant conversion is not allowed because even if it is allowed, not all source data can be losslessly inserted into the target type, for example, converting a fixed-point number to Oracle <code>FLOAT</code>. </p></li></ul>
</main>
