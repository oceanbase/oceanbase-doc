# ob_org_cluster_id

ob_org_cluster_id specifies the CLUSTER_ID at the session level. The value is persisted to the transaction log.

You usually do not need to set the ob_org_cluster_id variable. OceanBase Database uses the default value when it generates logs (clogs). OMS can filter data by using the ob_org_cluster_id variable. For more information about data filtering in OMS, see **Create a data migration project from a MySQL tenant to an OceanBase MySQL tenant** in [Create a data migration project](https://docs.oceanbase.com/om/2.2/userguide/migrate-mysql-to-mysql/create-mysql-to-mysql-project.html).

For example, the obcdc component of OMS sets the cluster ID blacklist to `cluster_id_black_list=2147473648`. When an OBServer node writes data, it sets the session variable to `SET ob_org_cluster_id=2147473648;`. In this case, obcdc filters data whose cluster ID is `2147473648`.

|---------|-------------------|
| Type    | int               |
| Default value     | 0                 |
| Value range    | \[0, 4294967295\] |
| Effective range    | SESSION           |
| Involved in serialization | Yes                 |
