# tracefile_identifier

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This variable is available starting with in V2.2.77. </p>
</main>

## Description

`tracefile_identifier` specifies a custom identifier that becomes part of the log so that a row iteration trace log can be identified with ease.

## Privilege requirements

* Query variables

  The `sys` tenant and all user tenants can query the value of a session system variable by using the `SHOW VARIABLES` statement or the `SYS.TENANT_VIRTUAL_SESSION_VARIABLE` view (in Oracle-compatible mode) or the `information_schema.SESSION_VARIABLES` view (in MySQL-compatible mode).

* Modify variables

  The `sys` tenant and all user tenants can directly modify the value of a session system variable in their own tenant.

## Attributes

| **Attribute** | **Description** |
|---------|---------|
| Type | Varchar |
| Default value | Empty string |
| Effective scope    | Session |
| Modifiable | Yes. It can be modified by using the `SET` statement. |

## Considerations

Using the TRACING and STAT hints allows the executor to print each row during operator execution. To make these entries easier to search and identify, you can use `tracefile_identifier` to specify a string, such as `XXXYYYZZZ`, `MY_TRACE`, etc., which will be output to the log together with the row content for easier searching.

## Example

Specify the string `MY_TRACE` so that it is output to the log together with the row content, making it easier to search later.

```shell
obclient> SET tracefile_identifier = 'MY_TRACE';
```
