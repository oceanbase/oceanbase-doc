# cardinality_estimation_model

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This variable was introduced in OceanBase Database V4.2.4. </p>
</main>

## Description

`cardinality_estimation_model` specifies the correlation assumption used by the optimizer for cardinality estimation.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>Run a full test on this variable before you use it in your production environment. </p>
</main>

## Limitations

* Query the variable

  In the `sys` tenant or a user tenant, you can execute the `SHOW VARIABLES` statement to query the variable at the global level or query the `SYS.TENANT_VIRTUAL_GLOBAL_VARIABLE` view (in Oracle mode) or `information_schema.GLOBAL_VARIABLES` view (in MySQL mode) for the variable at the global level.

* Modify the variable

  * In the `sys` tenant, you can directly change the value of the variable at the global level.

  * In a MySQL user tenant, you must have the `SUPER` or `ALTER SYSTEM` privilege to change the value of the variable at the global level.

  * In OceanBase Database V4.2.0 and later V4.x versions, you must have the `ALTER SYSTEM` privilege to change the value of the variable at the global level in an Oracle user tenant.

## Attributes

| **Attribute** | **Description** |
|-----------|---------------|
| Type | ENUM |
| Default value | PARTIAL |
| Value range |  </li><li>`INDEPENDENT`: assumes that predicates are completely independent. </li><li>`PARTIAL`: assumes that predicates are partially correlated. </li><li>`FULL`: assumes that predicates are completely correlated. </li></ul><main id="notice" type='explain'><h4>Note</h4><p>In most scenarios, the cardinality estimation results based on the three correlation assumptions sequentially increase: `INDEPENDENT` < `PARTIAL` < `FULL`. </p></main> |
| Effective scope | </li><li>Global</li><li>Session</li></ul> |
| Plan generation affected | Yes |
| Modifiable | Yes. You can use the `SET` statement to modify the variable. |

## Examples

Run cardinality estimation on a table named `t1` based on the three correlation assumptions. The results are `10`, `31`, and `98`, respectively.

1. Create a table named `t1`.

    ```shell
    obclient [test]> create table t1(c1 int, c2 int);
    Query OK, 0 rows affected (0.103 sec)
    ```

2. Insert data into the `t1` table.

    ```shell
    obclient [test]> insert into t1 select row_number() over () % 10, row_number() over () % 100 from table(generator(10000));
    Query OK, 10000 rows affected (0.077 sec)
    Records: 10000  Duplicates: 0  Warnings: 0
    ```

3. Analyze the `t1` table.

    ```shell
    obclient [test]> analyze table t1;
    Query OK, 0 rows affected (0.073 sec)
    ```

4. Set the correlation assumption to `INDEPENDENT` for cardinality estimation.

    ```shell
    obclient [test]> set cardinality_estimation_model = 'independent';
    Query OK, 0 rows affected (0.001 sec)
    ```

5. Query the cardinality estimation result.

    ```shell
    obclient [test]> explain select * from t1 where c1 = 1 and c2 = 1;
    ```
