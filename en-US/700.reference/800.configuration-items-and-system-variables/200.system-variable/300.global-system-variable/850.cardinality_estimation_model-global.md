# cardinality_estimation_model

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This variable is available starting with V4.2.4.</p>
</main>

## Description

`cardinality_estimation_model` specifies the correlation assumption used by the optimizer for cardinality estimation.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>Before you introduce this option to a production environment, make sure to thoroughly test it. </p>
</main>

## Privilege requirements

* Query variables

  `sys` tenants and all user tenants can execute the `SHOW VARIABLES` statement or query the `SYS.TENANT_VIRTUAL_GLOBAL_VARIABLE` view (Oracle mode) or the `information_schema.GLOBAL_VARIABLES` view (MySQL mode) to obtain the values of global system variables.

* Modify variables

  * `sys` tenants can directly modify the values of global system variables.

  * MySQL user tenants must have the `SUPER` or `ALTER SYSTEM` privilege to modify the values of global system variables.

  * Oracle user tenants must have the `ALTER SYSTEM` privilege to modify the values of global system variables.

## Attributes

| **Attribute**  |    **Description**  |
|-----------|---------------|
| Parameter type    |   Enum              |
| Default value      |  PARTIAL   |
| Value range    |  <ul><li>INDEPENDENT: assumes that the predicates are completely independent of each other. </li><li>PARTIAL: assumes that the predicates are partially correlated. </li><li>FULL: assumes that the predicates are completely correlated. </li></ul><main id="notice" type='explain'><h4>Note</h4><p>In most scenarios, the cardinality estimation results for the three correlation assumptions increase in the following order: INDEPENDENT < PARTIAL < FULL. </p></main>              |
| Scope    |  <ul><li>Global</li><li>Session</li></ul>  |
| Modifiable  |  Yes. You can execute the `SET` statement to modify the value. |

## Examples

In the three correlation assumptions, the cardinality estimation results for the `t1` table after filtering by the base table predicate are `10`, `31`, and `98`, respectively.

1. Create the `t1` table.

    ```shell
    obclient [test]> create table t1(c1 int, c2 int);
    Query OK, 0 rows affected (0.103 sec)
    ```

2. Insert data into the `t1` table.

    ```shell
    obclient [test]> insert into t1 select row_number() over () % 10, row_number() over () % 100 from table(generator(10000));
    Query OK, 10000 rows affected (0.077 sec)
    Records: 10000  Duplicates: 0  Warnings: 0
    ```

3. Analyze the `t1` table.

    ```shell
    obclient [test]> analyze table t1;
    Query OK, 0 rows affected (0.073 sec)
    ```

4. Set the correlation assumption to `INDEPENDENT` and execute cardinality estimation.

    ```shell
    obclient [test]> set cardinality_estimation_model = 'independent';
    Query OK, 0 rows affected (0.001 sec)
    ```

5. Query the cardinality estimation result.

    ```shell
    obclient [test]> explain select * from t1 where c1 = 1 and c2 = 1;
    ```
