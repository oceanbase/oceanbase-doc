# binlog_row_image

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This variable is available starting with V1.4. </p>
</main>

## Description

`binlog_row_image` specifies whether to record full column logs.

## Privilege requirements

* Query variables

  * Global level

    The `sys` tenant and all user tenants can execute the `SHOW VARIABLES` statement or query the `SYS.TENANT_VIRTUAL_GLOBAL_VARIABLE` view (Oracle mode) or the `information_schema.GLOBAL_VARIABLES` view (MySQL mode) to obtain the values of global system variables.

  * Session level

    The `sys` tenant and all user tenants can execute the `SHOW VARIABLES` statement or query the `SYS.TENANT_VIRTUAL_SESSION_VARIABLE` view (Oracle mode) or the `information_schema.SESSION_VARIABLES` view (MySQL mode) to obtain the values of session system variables.

* Modify variables

  * Global level

    * The `sys` tenant can modify the value of global system variables.

    * A MySQL user tenant must have the `SUPER` or `ALTER SYSTEM` privilege to modify the value of global system variables.

    * An Oracle user tenant must have the `ALTER SYSTEM` privilege to modify the value of global system variables.

  * Session level

    The `sys` tenant and all user tenants can modify the value of session system variables.

## Attributes

| **Attribute**  |    **Description**  |
|-----------|---------------|
| Type    | Enum                                                |
| Default value      | FULL                                                |
| Value range    | <ul><li>FULL: records all columns. </li><li>MINIMAL: records only the modified columns in DML operations. This option improves the throughput of master-slave replication, reduces the size of binlogs, and minimizes the consumption of network resources and server memory. </li><li>NOBLOB: not supported. </li></ul> |
| Scope    |  <ul><li>GLOBAL</li><li>Session</li></ul>  |
| Modifiable | Yes. You can execute the `SET` statement to modify the value.|

## Usage notes

* Full column logs record the **new and old values** of all columns in Update/Delete statements on OBServer nodes. Non-full column logs record only the **new values**.

* After you execute the <code>SET GLOBAL binlog_row_image= 'xxx'</code> statement to modify the variable, the change does not take effect on **any existing session**, including the session that initiated the modification.

## Examples

* Set the value of the `binlog_row_image` variable to record all columns.

* Global level

  ```shell
  obclient> SET GLOBAL binlog_row_image=FULL;
  ```

* Session level

  ```shell
  obclient> SET binlog_row_image=FULL;
  ```
