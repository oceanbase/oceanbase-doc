# binlog_row_image

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This variable is available starting with V1.4. </p>
</main>

## Description

`binlog_row_image` specifies whether to record full column logs.

## Privilege requirements

* Query variables

  * Global level

    `sys` tenants and all user tenants can execute the `SHOW VARIABLES` statement or query the `SYS.TENANT_VIRTUAL_GLOBAL_VARIABLE` view (Oracle mode) or the `information_schema.GLOBAL_VARIABLES` view (MySQL mode) to obtain the values of global system variables.

  * Session level

    `sys` tenants and all user tenants can execute the `SHOW VARIABLES` statement or query the `SYS.TENANT_VIRTUAL_SESSION_VARIABLE` view (Oracle mode) or the `information_schema.SESSION_VARIABLES` view (MySQL mode) to obtain the values of session system variables.

* Modify variables

  * Global level

    * `sys` tenants can directly modify the values of global system variables.

    * MySQL user tenants must have the `SUPER` or `ALTER SYSTEM` privilege to modify the values of global system variables.

    * Oracle user tenants must have the `ALTER SYSTEM` privilege to modify the values of global system variables.

  * Session level

    `sys` tenants and all user tenants can directly modify the values of session system variables.

## Attributes

| **Attribute**  |    **Description**  |
|-----------|---------------|
| Type    | Enum                                                |
| Default value      | FULL                                                |
| Value range    | <ul><li>FULL: records all columns. </li><li>MINIMAL: records only the modified columns in DML operations. This improves the throughput of master-slave replication, reduces the size of binlogs, and minimizes network resources and server memory usage. </li><li>NOBLOB: not supported. </li></ul> |
| Scope    |  <ul><li>Global</li><li>Session</li></ul>  |
| Modifiable | Yes. You can execute the `SET` statement to modify the value.|

## Usage notes

* Full column logs record the **old and new values of all columns** for Update/Delete statements on OBServer nodes. Non-full column logs record only the **new values**.

* After you execute the <code>SET GLOBAL binlog_row_image= 'xxx'</code> statement, the change does not take effect on **any existing sessions**, including the session that initiated the modification.

## Examples

* Set the value of the `binlog_row_image` variable to record all columns.

* Global level

   ```shell
   obclient> SET GLOBAL binlog_row_image=FULL;
   ```

* Session level

   ```shell
   obclient> SET binlog_row_image=FULL;
   ```
