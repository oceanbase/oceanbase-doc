# ob_route_policy

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This variable was introduced in OceanBase Database V1.4. </p>
</main>

## Description

`ob_route_policy` specifies the routing strategy for selecting a replica within an OBServer node.

## Attributes

| **Attribute** | **Description** |
|------------|---------------------|
| Type | ENUM |
| Default value | 1 |
| Value range | <ul><li> `1` (`READONLY_ZONE_FIRST`): Requests are preferentially routed to the zone where a read-only replica resides. </li>  <li> `2` (`ONLY_READONLY_ZONE`): Requests are routed only to the zone where a read-only replica resides.  </li>  <li> `3` (`UNMERGE_ZONE_FIRST`): Requests are preferentially routed to the zone where a replica not undergoing a major compaction resides.  </li> <li> `4` (`UNMERGE_FOLLOWER_FIRST`): Requests are preferentially routed to a follower not undergoing a major compaction.  </li> <li>`5` (`FORCE_READONLY_ZONE`): Read-only requests are routed only to zones where read-only replicas reside.</li></ul>   |
| Effective scope |   <ul><li>Global  </li><li>Session </li></ul>    |
| Modifiable | Yes. You can use the `SET` statement to modify the variable. |

## Examples

Set the routing strategy for selecting a replica within an OBServer node to preferentially routing requests to the zone where a read-only replica resides.

* Session-level operation

  ```shell
  obclient> SET ob_route_policy = 'READONLY_ZONE_FIRST';
  ```

  or

  ```shell
  obclient> SET ob_route_policy = 1;
  ```

* Global-level operation

  ```shell
  obclient> SET GLOBAL ob_route_policy = 'READONLY_ZONE_FIRST';
  ```

  or

  ```shell
  obclient> SET GLOBAL ob_route_policy = 1;
  ```
