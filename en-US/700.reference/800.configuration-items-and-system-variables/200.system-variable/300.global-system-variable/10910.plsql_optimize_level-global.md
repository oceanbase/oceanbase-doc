# plsql_optimize_level

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This variable is available starting with V4.2.3 BP1. </p>
</main>

`plsql_optimize_level` specifies the optimization level for compiling PL/SQL code.

## Privilege requirements

* Query variables

  The `sys` tenant and all user tenants can execute the `SHOW VARIABLES` statement or query the `SYS.TENANT_VIRTUAL_SESSION_VARIABLE` view (Oracle mode) or the `information_schema.SESSION_VARIABLES` view (MySQL mode) to view the values of session system variables.

* Modify variables

  The `sys` tenant and all user tenants can directly modify the values of session system variables for their own tenants.

## Description

|        Attribute        |                 Description                 |
|------------------|------------------------------------|
| Type             | Int                               |
| Default value              | 0        <main id="notice" type='explain'><h4></h4><p>This variable is available starting with V4.4.1, and the default value is 0. </p></main>                          |
| Value range             | [0,3]<ul><li>0: Disable both frontend and backend optimizations. This minimizes compilation overhead and time but may increase execution time. </li><li>1: Disable frontend optimization and enable backend optimization. This significantly reduces compilation overhead and time, but execution time may increase slightly. </li><li>2: Enable both frontend and backend optimization. This provides a balanced compilation and execution performance, which is the default optimization behavior. </li><li>3: Attempt to enable more optimization strategies, which may result in additional performance improvements. |
| Scope |  <ul><li>Global  </li><li>Session </li></ul>|
| Modifiable          | Yes. You can execute the `SET` or `ALTER SYSTEM SET` statement to modify the value.          |

## Usage notes

The higher the optimization level, the more optimization operations the compiler performs. We recommend that you set `plsql_optimize_level` to 2.

## Examples

* MySQL mode

  * Set the PL optimization level to `1` globally to disable frontend optimization and enable backend optimization.

    ```shell
    obclient> SET GLOBAL plsql_optimize_level = 1;
    ```

  * Set the PL optimization level to `2` globally to enable frontend and backend optimization.

    ```shell
    obclient> SET GLOBAL plsql_optimize_level = 2;
    ```

* Oracle mode

  * Set the PL optimization level to `1` globally to disable frontend optimization and enable backend optimization.

    ```shell
    obclient> ALTER SYSTEM SET plsql_optimize_level = 1;
    ```

  * Set the PL optimization level to `2` globally to enable frontend and backend optimization.

    ```shell
    obclient> ALTER SYSTEM SET plsql_optimize_level = 2;
    ```
