# plsql_optimize_level

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This variable was introduced in V4.2.3 BP1. </p>
</main>

## Description

The `plsql_optimize_level` variable controls the optimization level for PL code compilation.

## Privilege requirements

* Query variables

  * Global level

    Both the sys tenant and all user tenants can use the `SHOW VARIABLES` statement or the view `SYS.TENANT_VIRTUAL_GLOBAL_VARIABLE` (Oracle-compatible mode) and the view `information_schema.GLOBAL_VARIABLES` (MySQL-compatible mode) to view the values of global system variables.

  * Session level

    Both the sys tenant and all user tenants can use the `SHOW VARIABLES` statement or the view `SYS.TENANT_VIRTUAL_SESSION_VARIABLE` (Oracle-compatible mode) and the view `information_schema.SESSION_VARIABLES` (MySQL-compatible mode) to view the values of session system variables.

* Modify variables

  * Global level

    * The sys tenant can directly modify the values of global system variables.
    * MySQL-compatible tenants need to have the `SUPER` or `ALTER SYSTEM` privilege to modify the values of global system variables.
    * Oracle-compatible tenants need to have the `ALTER SYSTEM` privilege to modify the values of global system variables.

  * Session level

    Both the sys tenant and all user tenants can directly modify the values of session system variables within their own tenant.

## Attributes

|        Attribute        |                 Description                 |
|------------------|------------------------------------|
| Parameter type             | Int                               |
| Default value              | 2                                  |
| Value range             | [0,3]<ul><li>0: Optimization is disabled in the frontend and backend. This setting results in the shortest compilation overhead and time, but may lead to longer execution time. </li><li>1: Optimization is disabled in the frontend and enabled in the backend. This setting reduces the compilation overhead and time, but may slightly increase the execution time. </li><li>2: Optimization is enabled in both the frontend and backend. This setting provides a balance between compilation and execution performance. It is the default optimization behavior. </li><li>3: Optimization is enabled in both the frontend and backend, and additional optimizations are attempted. This setting may improve performance. |
| Scopes |  <ul><li>Global  </li><li>Session </li></ul>|
| Modifiable          | Yes. It can be modified by using the `SET` statement.          |

## Considerations

Higher optimization levels mean more optimizations are performed by the compiler. We recommend that you set the `plsql_optimize_level` variable to `2`. If you want more information, see [Examples](#Examples).

## Examples

* MySQL-compatible mode

  * Set the PL optimization level to `1` at the global level to disable frontend optimization and enable backend optimization.

    ```shell
    obclient> SET GLOBAL plsql_optimize_level = 1;
    ```

  * Set the PL optimization level to `2` at the global level to enable frontend and backend optimization.

    ```shell
    obclient> SET GLOBAL plsql_optimize_level = 2;
    ```

* Oracle-compatible mode

  * Set the PL optimization level to `1` at the global level to disable frontend optimization and enable backend optimization.

    ```shell
    obclient> ALTER SYSTEM SET plsql_optimize_level = 1;
    ```

  * Set the PL optimization level to `2` at the global level to enable frontend and backend optimization.

    ```shell
    obclient> ALTER SYSTEM SET plsql_optimize_level = 2;
    ```
