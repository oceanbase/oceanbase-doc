# sql_mode

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This variable is available starting with V1.4. </p>
</main>

## Description

`sql_mode` specifies the SQL mode. Different SQL modes have significant impacts on database behavior.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This variable is available only for OceanBase Database in MySQL mode. </p>
</main>

## Privilege requirements

* Query variables

  * Global level

    `sys` and all user tenants can execute the `SHOW VARIABLES` statement or query the `information_schema.GLOBAL_VARIABLES` view (MySQL mode) to view the value of a global system variable.

  * Session level

    `sys` and all user tenants can execute the `SHOW VARIABLES` statement or query the `information_schema.SESSION_VARIABLES` view (MySQL mode) to view the value of a session system variable.

* Modify variables

  * Global level

    * `sys` tenants can directly modify the value of a global system variable.

    * MySQL user tenants can modify the value of a global system variable only if they have the `SUPER` or `ALTER SYSTEM` privilege.

  * Session level

    `sys` and all user tenants can directly modify the value of a session system variable.

## Examples

Set the SQL mode to `STRICT_ALL_TABLES`, `NO_ZERO_IN_DATE`, and `NO_AUTO_CREATE_USER`.

* Session level

  ```shell
  obclient> SET sql_mode = 'STRICT_ALL_TABLES,NO_ZERO_IN_DATE,NO_AUTO_CREATE_USER';
  ```

* Global level

  ```shell
  obclient> SET GLOBAL sql_mode = 'STRICT_ALL_TABLES,NO_ZERO_IN_DATE,NO_AUTO_CREATE_USER';
  ```
