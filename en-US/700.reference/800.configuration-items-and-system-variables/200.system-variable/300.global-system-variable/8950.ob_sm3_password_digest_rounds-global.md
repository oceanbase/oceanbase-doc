# ob_sm3_password_digest_rounds

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This variable is available starting with V4.4.2 BP3.</p>
</main>

## Overview

`ob_sm3_password_digest_rounds` specifies the number of SM3 iterations performed by the `ob_sm3_password` authentication plugin when generating a password-based authentication string. A higher iteration count provides stronger protection against brute-force attacks on the password hash, but also increases the computational overhead for generating the hash and performing full password authentication. You can configure this parameter based on your security and performance requirements.

## Privilege requirements

* Query variables

  * Global level

    The `SHOW VARIABLES` statement, or the `SYS.TENANT_VIRTUAL_GLOBAL_VARIABLE` view (in Oracle-compatible mode) and the `information_schema.GLOBAL_VARIABLES` view (in MySQL-compatible mode), can be used by the `sys` tenant and all user tenants to view the values of global system variables.

* Modify variables

  * Global effective

    * The `sys` tenant can directly modify the values of global system variables.

    * MySQL user tenants must have the `SUPER` or `ALTER SYSTEM` privilege to modify the values of global system variables.

    * Oracle-compatible user tenants must have the `ALTER SYSTEM` privilege to modify the values of global system variables.

## Attributes

| **Attribute** | **Description** |
| ---------- | ---------- |
| Parameter type | Int |
| Default Value | 5000 |
| Value range | [5000, 4095000], and must be a multiple of 1000 |
| Effective Scope | Global |
| Modifiable | Yes, you can use the`SET`Statement modification. |

## Usage instructions

* This variable is global and takes effect immediately after modification. After modifying the variable, newly created users, or those whose `ob_sm3_password` hash is regenerated through operations such as `ALTER USER` or `SET PASSWORD`, will use the new number of iterations. Stored password authentication strings are not automatically recalculated; they will only use the new value after the password is reset and a new hash is generated.
* This variable only controls the number of iterations for password hashing and is not responsible for switching the default authentication plugin. Its configuration takes effect only when generating or updating passwords using the `ob_sm3_password` plugin.

## Configuration example

Set the number of SM3 password hash iterations to 10000.

```shell
obclient> SET GLOBAL ob_sm3_password_digest_rounds = 10000;
```
