# ob_route_policy

`ob_route_policy` specifies the routing strategy for selecting a replica within an OBServer node.

| **Attribute** | **Description** |
|----------|--------------------------------------------------------------------------|
| Type | ENUM |
| Default value | 1 |
| Value range | <ul><li> 1 (`READONLY_ZONE_FIRST`): Requests are preferentially routed to the zone where a read-only replica resides. </li>  <li> 2 (`ONLY_READONLY_ZONE`): Requests are routed only to the zone where a read-only replica resides. </li>  <li> 3 (`UNMERGE_ZONE_FIRST`): Requests are preferentially routed to the zone where a replica not undergoing a major compaction resides. </li> <li> 4 (`UNMERGE_FOLLOWER_FIRST`): Requests are preferentially routed to a follower not undergoing a major compaction. </li> <li>5 (`COLUMN_STORE_ONLY`): Requests are routed only to a columnstore replica. </li></ul> |
|  Effective scope | <li>Global <li>Session |
| Modifiable | Yes. You can use the `SET` statement to modify the variable. |

## Examples

* Session-level operation

  ```shell
  obclient> SET ob_route_policy = 'READONLY_ZONE_FIRST';
  ```

  or

  ```shell
  obclient> SET ob_route_policy = 1;
  ```

* Global-level operation

  ```shell
  obclient> SET GLOBAL ob_route_policy = 'READONLY_ZONE_FIRST';
  ```

  or

  ```shell
  obclient> SET GLOBAL ob_route_policy = 1;
  ```
