# schema_history_expire_time

<main id="notice" type='explain'>
<h4>Note</h4>
<ul><li>Due to internal optimization, for V4.4.2, this parameter is available starting with V4.4.2 BP1 and is changed from cluster-level to tenant-level. </li>
<li>This parameter is available starting with V1.4. </li></ul>
</main>

## Description

`schema_history_expire_time` specifies the retention period for schema history data and the retention period for delayed deletion of tenants.

## Privilege requirements

* Query the parameter

  You can use the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view to query this parameter in the `sys` tenant and all user tenants.

* Modify the parameter

  You can modify this parameter in the `sys` tenant and user tenants.

## Attributes

|      **Attribute**      |  **Description**  |
|------------------|----------|
| Type             | Time     |
| Default value               | 7d, where d indicates days<main id="notice" type='explain'><h4>Note</h4><p>Starting from V4.0.0, the default value of this parameter is changed from 30d to 7d. </p></main>    |
| Value range             | [1m, 30d]<main id="notice" type='explain'><h4>Note</h4><p>Starting from V4.0.0, the value range of this parameter is changed from [1m, 365d] to [1m, 30d]. </p></main> |
| Modifiable           | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
| Effective upon OBServer node restart | No. The setting takes effect immediately.      |

## Examples

Set the retention period for schema history data to 7 days.

```shell
obclient> ALTER SYSTEM SET schema_history_expire_time = '7d';
```

If the value of this parameter is set to 7d, schema history data generated within the last 7 days is retained, and schema history data that is no longer used is recycled.
