# ob_vector_index_active_segment_max_size

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>For V4.6.0, this parameter is available starting with V4.6.0.</p>
</main>

## Description

`ob_vector_index_active_segment_max_size` specifies the maximum memory consumption of an active segment in a partition. When the memory consumption of the newly written vector data in an active segment exceeds the specified threshold, the system triggers the freeze and persistence operation to save the incremental data in the memory to disk.

<main id="notice" type='notice'>
  <h4>Applicability</h4>
  <p>This parameter is available in OceanBase Database in MySQL mode only. </p>
</main>

## Privilege requirements

* Query the parameter

  The `sys` tenant and MySQL user tenant can query the parameter by using the `SHOW PARAMETERS` statement or querying the `GV$OB_PARAMETERS` view.

* Modify the parameter

  The `sys` tenant and MySQL user tenant can modify the parameter.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Type | Cap |
| Default value | 0, indicating that automatic threshold setting is enabled. The system automatically sets the threshold based on the available vector memory for the tenant: <ul><li>32 MB if less than 4 GB</li><li>64 MB if between 4 GB and 16 GB (inclusive)</li><li>128 MB if greater than 16 GB</li></ul> |
| Value range | [0, +∞), in MB |
| Modifiable | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
| Effective upon OBServer node restart | No. The setting takes effect immediately. |

## Considerations

* Increase the threshold: To reduce the frequency of freezing and avoid a large number of active segments due to high incremental write speed, thereby preventing search performance degradation.
* Decrease the threshold: Except for special testing scenarios, we do not recommend decreasing the threshold to avoid frequent freezing operations affecting overall search performance.
* Restart the database: A large threshold will increase the time required to restore memory data when the database is restarted. We recommend that you decrease the threshold before restarting the database to reduce the restart time. You can also restart the database during off-peak hours.

## Examples

Set the maximum memory consumption of an active segment in a partition to 256 MB.

```sql
ALTER SYSTEM SET ob_vector_index_active_segment_max_size = '256MB';
```

Check the current configuration.

```sql
SHOW PARAMETERS LIKE 'ob_vector_index_active_segment_max_size';
```
