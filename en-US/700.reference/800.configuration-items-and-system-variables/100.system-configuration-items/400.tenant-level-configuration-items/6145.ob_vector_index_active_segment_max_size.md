# ob_vector_index_active_segment_max_size

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>For V4.6.0, this parameter is available starting with V4.6.0.</p>
</main>

## Description

`ob_vector_index_active_segment_max_size` specifies the maximum memory usage of an active segment in a partition. When the memory usage of the active segment exceeds this threshold, the system triggers the freezing and persistence operations to write the incremental data in memory to disk.

<main id="notice" type='notice'>
  <h4>Applicability</h4>
  <p>This parameter is available only in OceanBase Database in MySQL mode. </p>
</main>

## Privilege requirements

* Query the parameter

  You can execute the `SHOW PARAMETERS` statement or query the `GV$OB_PARAMETERS` view in the `sys` tenant or a MySQL user tenant to query this parameter.

* Modify the parameter

  You can modify this parameter in the `sys` tenant or a MySQL user tenant.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Parameter type | Cap |
| Default value | 0, which indicates adaptive. The system automatically sets different thresholds based on the available vector memory of the tenant. The thresholds are as follows:<ul><li>32 MB for tenants with less than 4 GB of vector memory</li><li>64 MB for tenants with 4 GB to 16 GB of vector memory (inclusive)</li><li>128 MB for tenants with more than 16 GB of vector memory</li></ul> |
| Value range | [0, +∞), unit: MB |
| Modifiable | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
| Effective upon OBServer node restart | No. The setting takes effect immediately. |

## Considerations

* Increase the threshold: This reduces the freezing frequency and avoids excessive active segments due to high incremental write speed, which can degrade search performance.
* Decrease the threshold: We recommend that you do not decrease the threshold in most scenarios. Frequent freezing operations can degrade overall search performance.
* Restart the database: When you restart the database, the system needs to restore the memory data. A large threshold increases the time required for the system to restore the data. We recommend that you decrease the threshold before you restart the database to reduce the time required for the system to restore the data. Alternatively, you can restart the database during off-peak hours.

## Examples

Set the maximum memory usage of an active segment in a partition to 256 MB.

```sql
ALTER SYSTEM SET ob_vector_index_active_segment_max_size = '256MB';
```

Query the current value of this parameter.

```sql
SHOW PARAMETERS LIKE 'ob_vector_index_active_segment_max_size';
```
