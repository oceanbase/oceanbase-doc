# enable_standby_semi_sync

<main id="notice" type='explain'>
<h4>Note</h4>
<p>For V4.4.2, this parameter is available starting from V4.4.2 BP2.</p>
</main>

## Overview

The `enable_standby_semi_sync` parameter specifies whether to enable semi-synchronous replication for the standby database (standby tenant).

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| -------------------------- | ------------------------------------------------- |
| Parameter type | Bool |
| Default Value | False |
| Value range | <ul><li>`True`: Enable semi-synchronous replication for the standby database.</li> <li>`False`: Disable semi-synchronous replication for the standby database.</li></ul> |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to restart the OBServer node for the change to take effect | No, the setting takes effect immediately. |

## Usage instructions

* You can modify the value of this parameter only when the standby database is in the `MAXIMUM PERFORMANCE` protection mode.

* We recommend that you perform this operation during off-peak hours and wait for about 10 seconds before restoring normal traffic.

* In other protection modes (except `MAXIMUM PERFORMANCE`), if you want the standby database to enter semi-synchronous mode, you can first set the value of this parameter `enable_standby_semi_sync` to `True` when the standby database is in `MAXIMUM PERFORMANCE` mode, and then switch it to `MAXIMUM AVAILABILITY` or `MAXIMUM PROTECTION` mode. After the switch is successful, this parameter will become read-only.

## Configuration example

Enable the semi-synchronous replication mode for the standby database.

```shell
obclient> ALTER SYSTEM SET enable_standby_semi_sync = True;
```
