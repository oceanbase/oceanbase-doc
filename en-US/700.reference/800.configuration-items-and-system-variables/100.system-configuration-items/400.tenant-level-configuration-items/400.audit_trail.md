# audit_trail

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>For V2.2.30, this parameter is available starting with V2.2.30. </p>
</main>

## Description

`audit_trail` specifies whether to enable database audit.

## Privilege requirements

* Query the parameter

  The `sys` tenant and all user tenants can query this parameter by using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify the parameter

  The `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Type           | String     |
| Default value             | NONE        |
| Value range           | <ul><li>NONE: Disable audit. </li><li>OS: Write audit records to local files. </li><li>LOG: Write audit records to the audit log. Supports management strategies such as log archiving, compression, rotation, cleanup, and encryption. </li><li>DB: Write audit records to internal tables. </li><li>DB,EXTENDED: Write audit records to internal tables and record executed SQL statements. </li><li>DB_EXTENDED: Write audit records to internal tables and record executed SQL statements. </li></ul>  |
| Modifiable         | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
| Effective upon OBServer node restart | No. The setting takes effect immediately.   |

## Examples

Disable database audit.

```shell
obclient> ALTER SYSTEM SET audit_trail ='NONE';
```
