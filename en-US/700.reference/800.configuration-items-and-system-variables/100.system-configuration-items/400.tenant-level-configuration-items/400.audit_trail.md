# audit_trail

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>For V2.2.30, this parameter is available starting with V2.2.30.</p>
</main>

## Description

`audit_trail` specifies whether to enable database audit.

## Privilege requirements

* Query the parameter

  `sys` and all user tenants can query this parameter by using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify the parameter

  `sys` and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Type           | String     |
| Default value             | NONE        |
| Value range           | <ul><li>NONE: disables audit.</li><li>OS: writes audit records to a local file.</li><li>DB: writes audit records to an internal table.</li><li>DB,EXTENDED: writes audit records to an internal table and records contain executed SQL statements.</li><li>DB_EXTENDED: writes audit records to an internal table and records contain executed SQL statements.</li></ul>  |
| Modifiable         | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
| Effective upon OBServer node restart | No. The setting takes effect immediately.   |

## Examples

Disable database audit.

```shell
obclient> ALTER SYSTEM SET audit_trail ='NONE';
```
