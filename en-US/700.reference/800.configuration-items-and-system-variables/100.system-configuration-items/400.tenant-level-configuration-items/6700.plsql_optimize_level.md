# plsql_optimize_level

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This parameter is removed starting from V4.2.3 BP1 and replaced with the system variable <a href="../../200.system-variable/300.global-system-variable/10910.plsql_optimize_level-global.md">plsql_optimize_level (Global)</a>. </p>
</main>

## Description

`plsql_optimize_level` specifies the optimization level for PL code compilation.

## Privilege requirements

* Query the parameter

  The `sys` tenant and all user tenants can query the value of this parameter by using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify the parameter

  The `sys` tenant and all user tenants can modify this parameter.

## Attributes

|        Attribute        |                 Description                 |
|------------------|------------------------------------|
| Type             | Int                               |
| Default value               | 1                                  |
| Value range             | [0,3]<ul><li>0: Disables both frontend and backend optimizations, resulting in the shortest compilation overhead and time, but may increase execution time. </li><li>1: Disables frontend optimization and enables backend optimization, significantly reducing compilation overhead and time, but may slightly increase execution time. </li><li>2: Enables both frontend and backend optimization, providing a balanced compilation and execution performance. This is the default optimization behavior. </li><li>3: Attempts to enable more optimization strategies, which may result in additional performance improvements.  |
| Effective upon OBServer node restart | No. The setting takes effect immediately.          |

## Examples

Enable optimization for PL code compilation.

```shell
obclient> ALTER SYSTEM SET plsql_optimize_level=1;
```
