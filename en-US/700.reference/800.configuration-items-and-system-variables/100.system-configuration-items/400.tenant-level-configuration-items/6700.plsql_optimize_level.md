# plsql_optimize_level

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This parameter was removed in V4.2.3 BP1 and adjusted to the <a href="../../200.system-variable/300.global-system-variable/10910.plsql_optimize_level-glob.md">plsql_optimize_level (Global) </a> system variable. </p>
</main>

## Description

The `plsql_optimize_level` parameter controls the optimization level during compilation of PL code.

## Privilege requirements

* Query privilege
  Both the `SHOW PARAMETERS` statement and the `GV$OB_PARAMETERS` view are available to the `sys` tenant and all user tenants.
* Modify privilege
  Both the `sys` tenant and user tenants can modify this parameter.

## Attribute description

|        Attribute        |                 Description                 |
|------------------|------------------------------------|
| Parameter type             | Int                               |
| Default value               | 1                                  |
| Value range             | [0,3]<ul><li>0: Optimization is disabled in the frontend and backend. This setting results in the shortest compilation overhead and time, but may lead to longer execution time. </li><li>1: Optimization is disabled in the frontend and enabled in the backend. This setting reduces the compilation overhead and time significantly but may increase the execution time slightly. </li><li>2: Optimization is enabled in both the frontend and backend. This setting provides a balance between compilation and execution performance. It is the default optimization behavior. </li><li>3: Optimization is enabled in both the frontend and backend, trying to use more optimization strategies to potentially improve performance.  |
| Restart OBServer node required | No                                  |

## Example

Set optimization to be enabled during compilation of PL code.

```shell
obclient> ALTER SYSTEM SET plsql_optimize_level=1;
```
