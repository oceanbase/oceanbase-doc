# plsql_optimize_level

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This parameter was removed in V4.2.3 BP1 and replaced with the system variable <a href="../../200.system-variable/300.global-system-variable/10910.plsql_optimize_level-glob.md">plsql_optimize_level (Global)</a>. </p>
</main>

## Description

The `plsql_optimize_level` parameter controls the optimization level during compilation of PL code.

## Privilege requirements

* Query privilege
  Both the `sys` tenant and user tenants can use the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view to query this parameter.
* Modify privilege
  Both the `sys` tenant and user tenants can modify this parameter.

## Attributes

|        Attribute        |                 Description                 |
|------------------|------------------------------------|
| Parameter type             | Int                               |
| Default value               | 1                                  |
| Value range             | [0,3]<ul><li>0: Frontend and backend optimizations are disabled. This setting results in the shortest compilation overhead and duration, but may lead to longer execution time. </li><li>1: Frontend optimization is disabled and backend optimization is enabled. This setting obviously reduces the compilation overhead and duration, but may slightly increase the execution time. </li><li>2: Frontend and backend optimizations are enabled. This setting provides a balanced performance in compilation and execution. It is the default optimization behavior. </li><li>3: More optimization strategies are attempted to be enabled, which may bring additional performance improvements.  |
| Restart OBServer node required | No                                  |

## Example

Set optimization to be enabled during compilation of PL code.

```shell
obclient> ALTER SYSTEM SET plsql_optimize_level=1;
```
