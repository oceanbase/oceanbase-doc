# ha_mid_thread_score

## Description

The `ha_mid_thread_score` parameter specifies the number of concurrent threads for high-priority high-availability tasks.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This parameter was introduced in V4.0.0. </p>
</main>

## Related parameters

* ha_high_thread_score
* ha_low_thread_score

## Attributes

| **Attribute** | **Description** |
| --- | --- |
| Type | Integer |
| Default value | 0 |
| Value range | [0, 100] |
| Effective upon OBServer node restart | No |

## Considerations

In V4.x, tasks related to high availability, such as migration and backup and restore, are scheduled and executed by the tenant-level DagScheduler. Each tenant has limited thread resources. Therefore, the system does not distinguish between different task types but instead sets three parameters based on task priority and importance. Each parameter corresponds to a different task type:

* ha_high_thread_score: specifies the number of concurrent threads for high-priority high-availability tasks, such as replication and rebuild.
* ha_mid_thread_score: specifies the number of concurrent threads for medium-priority high-availability tasks, such as migration.
* ha_low_thread_score: specifies the number of concurrent threads for low-priority high-availability tasks, such as backup, backup and restore, and backup cleanup.
