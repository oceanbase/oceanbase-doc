# ob_proxy_readonly_transaction_routing_policy

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>Due to changes in the related logic in V4.1.x, the corresponding feature is no longer available. This parameter is deprecated starting from V4.1.0. You can query and set it, but the setting will not take effect and will not generate an error. </p>
</main>

## Description

`ob_proxy_readonly_transaction_routing_policy` specifies whether Proxy routing for transactions is affected by read-only statements.

## Privilege requirements

* Query the parameter

  You can use the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view to query this parameter in the `sys` tenant and all user tenants.

* Modify the parameter

  You can modify this parameter in the `sys` tenant and user tenants.

## Attributes

|      **Attribute**      |    **Description**    |
|------------------|--------------|
| Type             | Bool |
| Default value               | false<main id="notice" type='explain'><h4>Note</h4><p>Starting from V4.0.0, the default value of this parameter is changed from true to false. </p></main>|
| Value range             | <ul><li>true: Proxy routing for transactions is based on the routing of the first read-only statement. </li><li>false: Proxy routing for transactions is based on the statement that actually starts the transaction. </li></ul>     |
| Modifiable           | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
| Effective upon OBServer node restart | No. The setting takes effect immediately.   |

## Examples

Set Proxy routing for transactions to be based on the statement that actually starts the transaction.

```shell
obclient> ALTER SYSTEM SET ob_proxy_readonly_transaction_routing_policy = false;
```
