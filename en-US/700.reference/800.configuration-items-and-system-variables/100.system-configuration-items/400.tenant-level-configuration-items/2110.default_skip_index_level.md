# default_skip_index_level

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p><ul><li>For V4.6.x, this configuration item was introduced in V4.6.0.</li><li>For V4.3.5, this configuration item was introduced in V4.3.5 BP5.</li><li>For V4.4.x, this configuration item was introduced in V4.4.2.</li></ul></p>
</main>

## Description

`default_skip_index_level` specifies the default value of `skip_index_level` when a table is created in a tenant.

## Privilege requirements

* Query the configuration item

  Both the `sys` tenant and all user tenants can query this configuration item by using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify the configuration item

  Both the `sys` tenant and user tenants can modify this configuration item.

## Attributes

| **Attribute** | **Description** |
|----------|----------|
| Type | INT |
| Default value | 0 |
| Value range | <ul><li>0: All column-store baselines of a table generate Skip Index aggregate information. Row-store baselines generate Skip Index aggregate information based on the schema. Incremental SSTables do not generate Skip Index aggregate information.</li><li>1: In addition to the behavior of 0, incremental SSTables of a table also generate Skip Index aggregate information based on the baseline behavior.</li></ul>|
| Modifiable | Yes. You can modify this item by using the `ALTER SYSTEM SET` statement.|
| Takes effect after OBServer node restart | No. The setting takes effect immediately after modification.|

## Usage notes

The `default_skip_index_level` configuration item affects only the default format of primary tables created by user tenants. It does not affect `meta` tenants or the `sys` tenant. It also takes effect only when `skip_index_level` is not explicitly specified in the `CREATE TABLE` statement. If a user explicitly specifies `skip_index_level` for a table, the table's `skip_index_level` is resolved according to the user-specified value.

This configuration item can be set to the following values:

* 1: If `skip_index_level` is not specified in the `CREATE TABLE` statement, tables created by user tenants have `skip_index_level = 1`.
* 0: If `skip_index_level` is not specified in the `CREATE TABLE` statement, tables created by user tenants have `skip_index_level = 0`.

Modifying this configuration item does not affect tables that have already been created.

## Configuration examples

* MySQL mode: Set the default `skip_index_level` for tables created by a user tenant to 1.

    ```shell
    obclient> ALTER SYSTEM SET default_skip_index_level = 1;
    ```

* Oracle mode: Set the default `skip_index_level` for tables created by a user tenant to 1.

    ```shell
    obclient> ALTER SYSTEM SET "default_skip_index_level" = 1;
    ```
