# default_skip_index_level

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p><ul><li>For V4.6.x, this parameter is available starting with V4.6.0. </li><li>For V4.3.5, this parameter is available starting with V4.3.5 BP5. </li><li>For V4.4.x, this parameter is available starting with V4.4.2. </li></ul></p>
</main>

## Description

`default_skip_index_level` specifies the default value of `skip_index_level` when a table is created in a user tenant.

## Privilege requirements

* Query the parameter

  The `sys` tenant and all user tenants can query this parameter by using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify the parameter

  The `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
|----------|----------|
| Type  | INT |
| Default value    | 0 |
| Value range   | <ul><li>0: Skip index aggregation information is generated for columnar baselines of tables, and for rowstore baselines, skip index aggregation information is generated based on the schema. Skip index aggregation information is not generated for incremental SSTables. </li><li>1: In addition to the behavior in 0, skip index aggregation information is generated for incremental SSTables based on the behavior of the baseline. </li></ul>|
| Modifiable | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
| Effective upon OBServer node restart | No. The setting takes effect immediately. |

## Considerations

The `default_skip_index_level` parameter only affects the default format for creating tables in user tenants. It does not affect the `meta` or `sys` tenants. The parameter takes effect only when the `skip_index_level` clause is not explicitly specified in the CREATE TABLE statement. If the `skip_index_level` clause is explicitly specified, the final `skip_index_level` of the table is resolved based on the specified value.

You can set this parameter to the following values:

* 1: If the `skip_index_level` clause is not explicitly specified in the CREATE TABLE statement, the `skip_index_level` of tables created in user tenants is 1.
* 0: If the `skip_index_level` clause is not explicitly specified in the CREATE TABLE statement, the `skip_index_level` of tables created in user tenants is 0.

Changing the value of this parameter does not affect tables that have already been created.

## Examples

* MySQL mode: Set the default value of `skip_index_level` for creating tables in user tenants to 1.

    ```shell
    obclient> ALTER SYSTEM SET default_skip_index_level = 1;
    ```

* Oracle mode: Set the default value of `skip_index_level` for creating tables in user tenants to 1.

    ```shell
    obclient> ALTER SYSTEM SET "default_skip_index_level" = 1;
    ```
