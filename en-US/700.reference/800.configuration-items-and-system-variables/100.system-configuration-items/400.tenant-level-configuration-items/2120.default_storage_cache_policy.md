# default_storage_cache_policy

<main id="notice" type='explain'>
<h4>Note</h4>
<ul><li>For V4.4.x, this parameter is available starting with V4.4.0. </li>
<li>For V4.3.5, this parameter is available starting with V4.3.5 BP2. </li></ul>
</main>

## Description

`default_storage_cache_policy` specifies the default cache policy for tenant-level `storage_cache_policy`. This parameter only takes effect for newly created tables.

<main id="notice">
<h4>Applicability</h4>
<p>This parameter is applicable only to OceanBase Database in Shared-Storage (SS) mode. </p>
</main>

## Privilege requirements

* Query the parameter

  The `sys` tenant and all user tenants can query this parameter by using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify the parameter

  The `sys` tenant and user tenants can modify this parameter.

  <main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>If you modify this parameter in an Oracle tenant or in the <code>sys</code> tenant by specifying an Oracle tenant or other non-user tenant (such as the <code>sys</code> tenant or the Meta tenant), the parameter value can be modified, but the feature does not take effect. This is because the feature for manually specifying the cache policy for hot data is available only in MySQL tenants. </p>
  </main>

## Attributes

| **Attribute** | **Description** |
|----------|----------|
| Type  | String  |
| Default value    | AUTO |
| Value range   | <ul><li>`HOT`: All data in the table is cached to the local disk as hot data. </li> <li> `AUTO`: All data in the table is automatically identified as hot or cold. The shared storage system determines the storage method for the data in the table. </li><li>`COLD`: The table data is cold data, which is not cached to the local cache disk. For data that has been persisted to the cache, the cache eviction is actively triggered. Subsequent accesses to the table data can be stored in the macroblock memory cache, without being persisted to the macroblock cache or microblock cache. </li></ul> |
| Modifiable | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
| Effective upon OBServer node restart | No. The setting takes effect immediately. |

## Considerations

* All newly created tables that do not explicitly specify a cache policy by using the `storage_cache_policy` parameter use the cache policy specified by `default_storage_cache_policy`.
* Only user tables and indexes are affected by the `default_storage_cache_policy` parameter. System tables are always set to `AUTO`.

## Examples

* In a user tenant, set the default cache policy for the tenant to `HOT`.

  ```shell
  obclient> ALTER SYSTEM SET default_storage_cache_policy='HOT';
  ```

* In the `sys` tenant, specify the default cache policy for the `mysqltenant` tenant as `HOT`.

  ```shell
  obclient> ALTER SYSTEM SET default_storage_cache_policy='HOT' TENANT = mysqltenant;
  ```
