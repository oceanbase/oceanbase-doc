# default_storage_cache_policy

<main id="notice" type='explain'>
<h4>Note</h4>
<ul><li>For V4.4.x, this parameter is available starting with V4.4.0. </li>
<li>For V4.3.5, this parameter is available starting with V4.3.5 BP2. </li></ul>
</main>

## Description

`default_storage_cache_policy` specifies the default cache strategy for tables. The default value of the `storage_cache_policy` parameter at the tenant level is effective only for newly created tables.

<main id="notice">
<h4>Applicability</h4>
<p>This parameter is applicable only to OceanBase Database in Shared-Storage (SS) mode. </p>
</main>

## Privilege requirements

* Query the parameter

  The `sys` tenant and all user tenants can query the value of this parameter by using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify the parameter

  The `sys` tenant and user tenants can modify this parameter.

  <main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>If you modify this parameter in an Oracle tenant or in the <code>sys</code> tenant by specifying an Oracle tenant or another non-user tenant (such as the <code>sys</code> tenant or the meta tenant), the value of the parameter can be modified, but the feature does not take effect. This is because the feature to manually specify the cache strategy for hot data is effective only in MySQL mode. </p>
  </main>

## Attributes

| **Attribute** | **Description** |
|----------|----------|
| Type  | String  |
| Default value    | AUTO |
| Value range   | <ul><li>`HOT`: all data in the table is cached to the local disk. </li> <li> `AUTO`: all data in the table is automatically identified as hot or cold. The shared storage decides how to store the data in the table. </li><li>`COLD`: the data in the table is cold. The data is not cached to the local cache disk. For data that has been persisted to the cache, cache eviction is triggered. Subsequent accesses to the table data can store the data in the macroblock memory cache, but the data is not persisted to the macroblock cache or microblock cache. </li></ul> |
| Modifiable | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
| Effective upon OBServer node restart | No. The setting takes effect immediately. |

## Considerations

* All newly created tables in the current tenant use the cache strategy specified by `default_storage_cache_policy` if the `storage_cache_policy` parameter is not explicitly specified.
* Only user tables and indexes are affected by the `default_storage_cache_policy` parameter. System tables are always set to `AUTO`.

## Examples

* In a user tenant, set the default cache strategy to `HOT`.

  ```shell
  obclient> ALTER SYSTEM SET default_storage_cache_policy='HOT';
  ```

* In the `sys` tenant, set the default cache strategy to `HOT` for the `mysqltenant` tenant.

  ```shell
  obclient> ALTER SYSTEM SET default_storage_cache_policy='HOT' TENANT = mysqltenant;
  ```
