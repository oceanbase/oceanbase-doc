# default_load_mode

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>For V4.3.4, this parameter is available starting with V4.3.4. </p>
</main>

## Description

`default_load_mode` specifies the data import mode in data import scenarios.

## Privilege requirements

* Query the parameter

  `sys` and all user tenants can query this parameter by using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify the parameter

  `sys` and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Type  | String|
| Default value    | DISABLED |
| Value range  | <ul><li>DISABLED: bypass import is not used. </li><li>FULL_DIRECT_WRITE: full bypass import is used, and the SQL semantics are followed. </li><li>INC_DIRECT_WRITE: incremental bypass import is used in the INC mode. </li><li>INC_REPLACE_DIRECT_WRITE: incremental bypass import is used in the INC_REPLACE mode. </li></ul>|
| Modifiable | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
| Effective upon OBServer node restart | No. The setting takes effect immediately. |

## Considerations

If you do not specify a bypass import hint in a data import operation by using the `LOAD DATA INFILE`, `INSERT INTO SELECT`, or `CREATE TABLE AS SELECT` statement, the default import mode is specified by the `default_load_mode` parameter. If you specify an `APPEND/DIRECT/NO_DIRECT` hint in a data import operation, the import mode is specified by the hint.

## Examples

* In a data import scenario, set the import mode to `FULL_DIRECT_WRITE`.

  ```shell
  obclient [test]> ALTER SYSTEM SET default_load_mode ='FULL_DIRECT_WRITE';
  ```

* In a data import scenario, set the import mode to `INC_DIRECT_WRITE`.

  ```shell
  obclient [test]> ALTER SYSTEM SET default_load_mode ='INC_DIRECT_WRITE';
  ```
