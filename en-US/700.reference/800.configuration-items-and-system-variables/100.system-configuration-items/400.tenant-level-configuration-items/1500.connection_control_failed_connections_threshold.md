# connection_control_failed_connections_threshold

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>For V3.2.1, this parameter is available starting with V3.2.1. </p>
</main>

## Description

`connection_control_failed_connections_threshold` specifies the threshold for failed login attempts.

<main id="notice">
  <h4>Applicability</h4>
  <p>This parameter is applicable only to OceanBase Database in MySQL mode. </p>
</main>

## Privilege requirements

* Query the parameter

  The `sys` tenant and all user tenants can query this parameter by using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify the parameter

  The `sys` tenant and user tenants can modify this parameter.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Type             | Int      |
| Default value               | 0        |
| Value range             | [0, 2147483647] |
| Modifiable           | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
| Effective upon OBServer node restart | No. |

## Considerations

If you set the value of this parameter to `0`, the feature is disabled, which means that the number of failed login attempts is not limited. After the number of failed login attempts exceeds the value specified by this parameter, the account is locked. The lock duration is specified by the [connection_control_min_connection_delay](../400.tenant-level-configuration-items/1700.connection_control_min_connection_delay.md) and [connection_control_max_connection_delay](../400.tenant-level-configuration-items/1600.connection_control_max_connection_delay.md) parameters.

## Examples

Set the threshold for failed login attempts to 3.

```shell
obclient> ALTER SYSTEM SET connection_control_failed_connections_threshold = 3;
```
