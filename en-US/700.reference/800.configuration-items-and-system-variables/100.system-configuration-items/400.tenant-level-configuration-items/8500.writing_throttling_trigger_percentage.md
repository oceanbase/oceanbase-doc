# writing_throttling_trigger_percentage

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>For V2.2.30, this parameter is available starting with V2.2.30.</p>
</main>

## Description

`writing_throttling_trigger_percentage` specifies the threshold of the write speed.

## Privilege requirements

* Query the parameter

  The `sys` tenant and all user tenants can use the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view to query this parameter.

* Modify the parameter

  The `sys` tenant and user tenants can modify this parameter.

## Attributes

|      **Attribute**      |   **Description**   |
|--------------------|--------------|
| Type             | Int         |
| Default value               | 60 <main id="notice" type='explain'><h4>Note</h4><p>For V4.0.0, the default value is changed from 100 to 60.</p></main>        |
| Value range             | [1, 100] |
| Modifiable           | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter.|
| Effective upon OBServer node restart | No. The setting takes effect immediately.     |

## Considerations

* OceanBase Database stores the data written in the last period in the MemStore. To avoid memory overflow, the system provides two important protection mechanisms:

  * Freezing mechanism: The data in the memory is persisted to the disk to release memory space.

  * Throttling mechanism: When the memory pressure is too high, the write speed is reduced to gain time for releasing memory.

  The triggering of these two mechanisms is controlled by two tenant-level parameters: [freeze_trigger_percentage](3300.freeze_trigger_percentage.md) (freezing threshold) and `writing_throttling_trigger_percentage` (throttling threshold).

  To avoid performance degradation caused by early throttling, the value of `writing_throttling_trigger_percentage` must be greater than that of [freeze_trigger_percentage](3300.freeze_trigger_percentage.md).

* For V4.0.0 and later, the default value of this parameter is 60. This is because the throttling feature is very stable, and in most business scenarios, throttling is only triggered by sudden import traffic. In import scenarios, throttling provides a better experience than stopping writing. Therefore, we recommend that you enable this feature. To achieve smooth throttling, we set the throttling trigger point to 60 instead of 80. If the throttling trigger point is set to 80, the system will need to consume the remaining 20% buffer to relieve the 80% MEMStore memory usage. This will cause a sharp increase in the response time on the business side.

* When the memory used by the MemStore reaches this threshold, the write throttling is triggered. If the value of this parameter is 100, the write throttling mechanism is disabled.

## Examples

Set the write speed threshold to 60.

```shell
obclient> ALTER SYSTEM SET writing_throttling_trigger_percentage = 60;
```
