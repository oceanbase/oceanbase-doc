# enable_ls_leader_balance

<main id="notice" type='explain'>
<h4>Note</h4>
<ul><li>For V4.6.x, this parameter is available starting with V4.6.0. </li>
<li>For V4.4.x, this parameter is available starting with V4.4.2. </li>
<li>For V4.2.5, this parameter is available starting with V4.2.5 BP6. </li></ul>
</main>

## Description

`enable_ls_leader_balance` specifies whether to enable automatic leader rebalancing for log streams.

## Privilege requirements

* Query the parameter

  The `sys` tenant and all user tenants can query the value of this parameter by using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify the parameter

  The `sys` tenant and user tenants can use the `ALTER SYSTEM SET` statement to modify this parameter.

## Attributes

| **Attribute** | **Description** |
|-----------|----------|
| Type   | Bool |
| Default value     | True |
| Value range   | <ul><li>`True`: enable automatic leader rebalancing for log streams</li><li>`False`: disable automatic leader rebalancing for log streams</li></ul>|
| Modifiable | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
| Effective upon OBServer node restart | No. The setting takes effect immediately. |

## Considerations

* When [enable_rebalance](2800.enable_rebalance.md) is enabled (`True`), you can disable automatic leader rebalancing for log streams by setting `enable_ls_leader_balance` to `False`.

* When `enable_ls_leader_balance` is disabled (`False`), automatic leader switching does not occur at the log stream level. However, leader switching may still occur at the partition level due to log stream transfers between different leaders.

## Examples

* Disable automatic leader rebalancing for log streams in the user tenant.

  ```shell
  obclient> ALTER SYSTEM SET enable_ls_leader_balance = False;
  ```

* Disable automatic leader rebalancing for log streams in the `mysql` tenant.

  ```shell
  obclient> ALTER SYSTEM SET enable_ls_leader_balance = False TENANT = 'mysql';
  ```
