# enable_ps_meta_response_optimize

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This parameter is available starting with V4.4.2 BP3.</p>
</main>

## Overview

`enable_ps_meta_response_optimize` specifies whether to enable meta response optimization between the observer and the client under the prepared statement (PS) protocol. When this parameter is enabled, when the observer interacts with an ob-jdbc driver that supports meta caching, the meta information of the result set is returned only during the first execution of a PS statement.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>When creating a tenant, the system sets this parameter to True by default. This means the feature is enabled for the new tenant by default.</p>
</main>

## Privilege requirements

* Query parameters

  Both the `sys` tenant and all user tenants can query this parameter using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify parameters

  Both the `sys` tenant and user tenants can modify this parameter.

# Attribute description

| **Attribute** | **Description** |
| -------- | -------- |
| Parameter type | Bool |
| Default Value | False |
| Value range | <ul><li>True: enabled. </li><li>False: disabled. </li></ul> |
| Modifiable | Yes, you can use the`ALTER SYSTEM SET`Statement modification. |
| Whether to Restart the OBServer Node for the Change to Take Effect | No. The setting takes effect immediately. |

## Configuration example

* Enabled PS protocol meta response optimization.

    ```shell
    obclient> ALTER SYSTEM SET enable_ps_meta_response_optimize = TRUE;
    ```

* Disabled the PS protocol meta response optimization.

    ```shell
    obclient> ALTER SYSTEM SET enable_ps_meta_response_optimize = FALSE;
    ```
