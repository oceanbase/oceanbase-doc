# tde_method

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>For V2.2.50, this parameter is available starting with V2.2.50.</p>
</main>

## Description

`tde_method` specifies the method used for Transparent Data Encryption (TDE).

## Privilege requirements

* Query the parameter

  You can query `tde_method` in the `GV$OB_PARAMETERS` view by using the `SHOW PARAMETERS` statement. This view is available to users of the `sys` tenant and all user tenants.

* Modify the parameter

  You can execute the `ALTER SYSTEM SET` statement to modify `tde_method` in a user tenant. This statement is available to users of the `sys` tenant and all user tenants.

## Attributes

|        Attribute      |  Description  |
|------------------|-------|
| Type             | String                          |
| Default value               | none                           |
| Value range             | <ul><li>none: TDE cannot be used.</li><li>internal: TDE is implemented using an internal table.</li><li>bkmi: TDE is implemented using an external BKMI system.</li><li>obcloud: TDE is implemented using the unified KMS proxy service, supporting clog encryption.</li></ul>  |
| Modifiable           | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter.|
| Effective upon OBServer node restart | No. The setting takes effect immediately.   |

## Considerations

`TDE` is a prerequisite for data encryption. Different encryption features have different requirements for the value of `tde_method`:

| Encryption feature | Supported value of `tde_method` | Description |
|---------|------------------------|------|
| TDE | Non-`none` values. We recommend that you use the `obcloud` value. | For more information, see [Overview of data transparent encryption](../../../../600.manage/500.security-and-permissions/500.data-encryption/400.data-storage-encryption/100.datastore-encryption-overview.md). |
| Column encryption | Non-`none` values. We recommend that you use the `obcloud` value. | For more information, see [Overview of column encryption](../../../../600.manage/500.security-and-permissions/500.data-encryption/500.column-encryption/100.column-encryption-overview.md). |
| Function encryption | Non-`none` values. We recommend that you use the `obcloud` value. | For more information, see [ENHANCED_AES_ENCRYPT](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/400.functions-of-mysql-mode/500.encryption-and-compression-functions-of-mysql-mode/820.enhanced-aes-encrypt-of-mysql-mode.md). |

### `obcloud` mode

The `obcloud` option enables you to use the unified KMS proxy service for key management in TDE.

The specific usage steps are as follows:

1. Enable encryption: use the unified KMS proxy service for key management.

   ```sql
   ALTER SYSTEM SET tde_method = 'obcloud';
   ```

2. Configure parameters: set the parameters of the KMS proxy service in the `external_kms_info` parameter:

   * `kms_host`: the endpoint of the OceanBase Cloud KMS service.
   * `access_key_id`: the Access Key ID (AK) used for signature authentication.
   * `access_key_secret`: the Access Key secret (SK) used for signature authentication.
   * `cmk_id`: the ID of the customer master key (CMK).

For more information about the TDE service provided by OceanBase Cloud, see [OBCloud database TDE](https://www.oceanbase.com/docs/common-oceanbase-cloud-1000000002781386). For information about the keys in the KMS of a cloud service provider, see [Authorize a cloud service account](https://www.oceanbase.com/docs/common-oceanbase-cloud-1000000003210326).

## Examples

Set the value of `tde_method` to `internal`.

```shell
obclient> ALTER SYSTEM SET tde_method= 'internal';
```

Set the value of `tde_method` to `obcloud`.

```shell
obclient> ALTER SYSTEM SET tde_method= 'obcloud';
```
