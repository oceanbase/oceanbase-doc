# tde_method

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>For V2.2.50, this parameter is available starting with V2.2.50.</p>
</main>

## Description

The `tde_method` parameter specifies the method for transparent tablespace encryption.

## Privilege requirements

* Query the parameter

  The `sys` tenant and all user tenants can query the value of this parameter by using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify the parameter

  The `sys` tenant and user tenants can use the `ALTER SYSTEM SET` statement to modify the value of this parameter in a user tenant.

## Attributes

|        Attribute      |  Description  |
|------------------|-------|
| Parameter type             | String                          |
| Default value               | none                           |
| Value range             | <ul><li>none: Transparent tablespace encryption is unavailable.</li><li>internal: The primary key is managed by an internal table.</li><li>bkmi: The primary key is managed by an external BKMI system.</li><li>obcloud: The primary key is managed by the OBCloud KMS proxy service. This option is applicable to OBCloud deployments.</li><li>ocp: The primary key is managed by the OCP KMS proxy service. This option is applicable to OCP deployments.<main id="notice" type='explain'><h4>Note</h4><p>This option is available starting with V4.6.0. </p></main></li></ul>  |
| Modifiable           | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
| Effective upon OBServer node restart | No. The setting takes effect immediately.   |

## Considerations

`tde_method` is a prerequisite parameter for data encryption. Different encryption features have different requirements on the value of `tde_method`:

| Encryption feature | Supported value of `tde_method` | Description |
|---------|------------------------|------|
| Transparent data encryption (TDE) | A value other than `none`. For OBCloud deployments, we recommend that you set the value to `obcloud`. For OCP deployments, we recommend that you set the value to `ocp`. | For more information, see [Transparent data encryption](../../../../600.manage/500.security-and-permissions/500.data-encryption/400.data-storage-encryption/100.datastore-encryption-overview.md). |
| Column encryption | A value other than `none`. For OBCloud deployments, we recommend that you set the value to `obcloud`. For OCP deployments, we recommend that you set the value to `ocp`. | For more information, see [Column encryption](../../../../600.manage/500.security-and-permissions/500.data-encryption/500.column-encryption/100.column-encryption-overview.md). |
| Function encryption | A value other than `none`. For OBCloud deployments, we recommend that you set the value to `obcloud`. For OCP deployments, we recommend that you set the value to `ocp`. | For more information, see [ENHANCED_AES_ENCRYPT](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/400.functions-of-mysql-mode/500.encryption-and-compression-functions-of-mysql-mode/820.enhanced-aes-encrypt-of-mysql-mode.md). |

### `obcloud` mode

The `obcloud` option is applicable to OBCloud deployments. The primary key is managed by the OceanBase Cloud KMS service.

To use this option, perform the following steps:

1. Enable encryption: Use the `obcloud` KMS proxy service to manage the primary key.

   ```sql
   ALTER SYSTEM SET tde_method = 'obcloud';
   ```

2. Configure the parameters: Configure the required parameters for the KMS proxy service in the `external_kms_info` parameter.

   * `kms_host`: the endpoint of the OceanBase Cloud KMS service.
   * `access_key_id`: the AccessKey ID for signature authentication.
   * `access_key_secret`: the AccessKey secret for signature authentication.
   * `cmk_id`: the ID of the user primary key.

For more information about the TDE service of OceanBase Cloud, see [Transparent data encryption of OceanBase Cloud](https://www.oceanbase.com/docs/common-oceanbase-cloud-1000000002781386). For information about the KMS keys of cloud service providers, see [Grant permissions to the cloud service provider account](https://www.oceanbase.com/docs/common-oceanbase-cloud-1000000003210326).

### `ocp` mode

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This option is available starting with V4.6.0. </p>
</main>

The `ocp` option is applicable to OCP deployments. The primary key is managed by the OCP KMS proxy service.

To use this option, perform the following steps:

1. Enable encryption: Use the `ocp` KMS proxy service to manage the primary key.

   ```sql
   ALTER SYSTEM SET tde_method = 'ocp';
   ```

2. Configure the parameters: Configure the required parameters for the KMS proxy service in the `external_kms_info` parameter.

   * `kms_host`: the endpoint of the OCP KMS service.
   * `access_key_id`: the AccessKey ID for signature authentication.
   * `access_key_secret`: the AccessKey secret for signature authentication.
   * `cmk_id`: the ID of the user primary key.

## Examples

Set the transparent tablespace encryption method to `internal`.

```shell
obclient> ALTER SYSTEM SET tde_method= 'internal';
```

Set the transparent tablespace encryption method to `obcloud`.

```shell
obclient> ALTER SYSTEM SET tde_method= 'obcloud';
```

Set the transparent tablespace encryption method to `ocp`.

```shell
obclient> ALTER SYSTEM SET tde_method= 'ocp';
```
