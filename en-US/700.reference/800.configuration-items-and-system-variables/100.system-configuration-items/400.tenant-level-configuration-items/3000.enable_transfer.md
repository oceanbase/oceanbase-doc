# enable_transfer

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This parameter is introduced in V4.2.1.
</main>

## Description

The `enable_transfer` parameter specifies whether to allow data transfer within a tenant. This parameter is invalid when the `enable_rebalance` parameter is set to `false`.

## Attributes

| **Attribute** | **Description** |
| --- | --- |
| Parameter type | BOOL |
| Default value | True |
| Value range |<ul><li> True: Enable.  </li><li> False: Disable.  </li></ul>|
| Changeable  | Yes. You can execute the `ALTER SYSTEM SET` statement to change this parameter. |
| Effective only after OBServer restart | No |

## Usage notes

The tenant-level `enable_rebalance` and `enable_transfer` parameters control the load balancing strategy within a tenant.

When the `enable_rebalance` parameter is set in the sys tenant, it specifies whether to perform load balancing between tenants. When it is set in a user tenant, it specifies whether to perform load balancing within the tenant. The default value is `true`. This parameter takes effect without restarting the OBServer node.

The `enable_transfer` parameter specifies whether to enable the transfer feature within a tenant. The default value is `true`. This parameter takes effect without restarting the OBServer node. The `enable_transfer` parameter depends on the value of the `enable_rebalance` parameter:

* If the `enable_rebalance` parameter is set to `false`, the system will not perform automatic load balancing regardless of whether the `enable_transfer` parameter is set to `true` or `false`. The command to disable all load balancing features is as follows:

  ```shell
  obclient> ALTER SYSTEM SET enable_rebalance=false;
  ```

* If the `enable_rebalance` parameter is set to `true` and the `enable_transfer` parameter is set to `true`, the system will automatically adjust partition distribution during tenant scaling to achieve load balancing. The commands to dynamically adjust the number of log streams based on the load balancing algorithm, and to automatically perform leader and partition balancing without initiating transfers or changing the number of log streams are as follows:

  ```shell
  obclient> ALTER SYSTEM SET enable_rebalance=true;
  obclient> ALTER SYSTEM SET enable_transfer=true;
  ```

* If the `enable_rebalance` parameter is set to `true` and the `enable_transfer` parameter is set to `false`, the system will not initiate transfers during tenant scaling. Load balancing can only be achieved by migrating log streams. The commands to balance log streams based on the existing log streams without initiating transfers or changing the number of log streams are as follows:

  ```shell
  obclient> ALTER SYSTEM SET enable_rebalance=true;
  obclient> ALTER SYSTEM SET enable_transfer=false;
  ```

## Examples

* Configure the load balancing strategy for a specified tenant in the sys tenant.

  * Enable intra-tenant load balancing and the transfer feature for the specified tenant.

    ```shell
    obclient> ALTER SYSTEM SET enable_rebalance = true TENANT = 'tenant_name';
    ```

    ```shell
    obclient> ALTER SYSTEM SET enable_transfer = true TENANT = 'tenant_name';
    ```

    These statements only set the values of `enable_rebalance` and `enable_transfer` to `true` for the specified tenant.

  * Enable intra-tenant load balancing and the transfer feature for all user tenants (excluding the `sys` tenant and Meta tenant).

    ```shell
    obclient> ALTER SYSTEM SET enable_rebalance = true TENANT = all_user;
    ```

    ```shell
    obclient> ALTER SYSTEM SET enable_transfer = true TENANT = all_user;
    ```

    or

    ```shell
    obclient> ALTER SYSTEM SET enable_rebalance = true TENANT = all;
    ```

    ```shell
    obclient> ALTER SYSTEM SET enable_transfer = true TENANT = all;
    ```

    These statements set the values of `enable_rebalance` and `enable_transfer` to `true` for all user tenants.

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>Starting from OceanBase Database V4.2.1, <code>TENANT = all_user</code> and <code>TENANT = all</code> are semantically equivalent. When you need to specify the scope of effect for all user tenants, we recommend that you use <code>TENANT = all_user</code>. <code>TENANT = all</code> will be deprecated. </p>
    </main>

* Configure the load balancing strategy for the current tenant.

  :::tab
  tab MySQL mode

  The following statements enable intra-tenant load balancing and the transfer feature for a MySQL tenant:

  ```shell
  obclient> ALTER SYSTEM SET enable_rebalance = true;
  ```

  ```shell
  obclient> ALTER SYSTEM SET enable_transfer = true;
  ```

  tab Oracle mode

  The following statements enable intra-tenant load balancing and the transfer feature for an Oracle tenant:

  ```shell
  obclient> ALTER SYSTEM SET enable_rebalance = 'true';
  ```

  ```shell
  obclient> ALTER SYSTEM SET enable_transfer = 'true';
  ```

  :::
