# arbitration_timeout

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>For V4.1.0, this parameter is available starting with V4.1.0. </p>
</main>

## Description

`arbitration_timeout` specifies the timeout period for automatic downgrade.

## Privilege requirements

* Query the parameter

  `sys` tenant and all user tenants can query this parameter by using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify the parameter

  `sys` tenant and user tenants can modify this parameter.

## Attributes

|      **Attribute**    |   **Description**   |
|------------------|--------------|
| Type             |  Time |
| Default value               | 5s |
| Value range             | [1s, +∞) |
| Modifiable           | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
| Effective upon OBServer node restart |No. The setting takes effect immediately.     |

<main id="notice" type='notice'>
<h4>Notice</h4>
<p>The minimum allowed value for this parameter is <code>1s</code>. However, in a production environment, we recommend that you set it to a value greater than or equal to <code>3s</code>. A value in the <code>[1s, 3s)</code> range is recommended only for non-production environments.</p>
</main>

## Examples

Set the timeout period for automatic downgrade to 30s.

```shell
obclient> ALTER SYSTEM SET arbitration_timeout ='30s';
```
