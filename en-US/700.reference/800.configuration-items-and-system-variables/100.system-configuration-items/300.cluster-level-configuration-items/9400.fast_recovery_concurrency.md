# fast_recovery_concurrency

<main id="notice" type='explain'>
<h4>Note</h4>
<ul><li>Due to limited thread resources, V4.x no longer supports configuring thread resources by task type, and this parameter was removed starting with V4.0.0. </li>
<li>In V4.x, you can use the <code>ha_high_thread_score</code> parameter to control the number of worker threads for high-priority threads in high-availability tasks such as replication, rebuild, and recovery. For more information about the tenant-level <code>ha_high_thread_score</code> parameter, see <a href="../400.tenant-level-configuration-items/3400.ha_high_thread_score.md">ha_high_thread_score</a>. </li></ul>
</main>

## Description

`fast_recovery_concurrency` specifies the number of concurrent fast recovery tasks that the RootService schedules on an OBServer node.

## Attributes

|        Attribute        |     Description     |
|------------------|------------|
| Type             | Int         |
| Default value              | 10         |
| Value range             | \[1,1000\] |
| Effective upon OBServer node restart | No          |
