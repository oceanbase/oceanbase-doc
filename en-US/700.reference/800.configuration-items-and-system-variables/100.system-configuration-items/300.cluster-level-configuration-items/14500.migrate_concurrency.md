# migrate_concurrency

<main id="notice" type='explain'>
<h4>Note</h4>
<ul><li>Due to limited thread resources, V4.x no longer allows you to configure thread resources by task type. This parameter is removed starting from V4.0.0. </li>
<li>In V4.x, you can use the <code>ha_mid_thread_score</code> parameter to set the number of working threads for high-priority threads in migration tasks. For more information about the tenant-level parameter <code>ha_mid_thread_score</code>, see <a href="../400.tenant-level-configuration-items/3600.ha_mid_thread_score.md">ha_mid_thread_score</a>. </li></ul>
</main>

## Description

`migrate_concurrency` specifies the maximum number of concurrent internal data migration tasks.

## Attributes

|      **Attribute**      |  **Description**   |
|------------------|-----------|
| Parameter type             | Int        |
| Default value              | 10        |
| Value range             | \[0, 64\] |
| Effective upon OBServer node restart | No         |
