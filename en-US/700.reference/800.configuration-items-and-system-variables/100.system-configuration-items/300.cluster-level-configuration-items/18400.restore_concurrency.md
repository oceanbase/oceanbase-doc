# restore_concurrency

<main id="notice" type='explain'>
<h4>Note</h4>
<ul><li>Due to limited thread resources, V4.x no longer supports configuring thread resources by task type. This parameter is removed starting from V4.0.0. </li>
<li>In V4.x, you can use the <code>ha_high_thread_score</code> parameter to control the number of working threads for high-priority threads such as replication, rebuild, and restore. For more information about the tenant-level parameter <code>ha_high_thread_score</code>, see <a href="../400.tenant-level-configuration-items/3500.ha_high_thread_score.md">ha_high_thread_score</a>. </li></ul>
</main>

## Description

`restore_concurrency` specifies the maximum number of concurrent threads for restoring tenant data from a backup.

## Attributes

|      **Attribute**      |   **Description**   |
|------------------|------------|
| Parameter type             | Int         |
| Default value              | 0          |
| Value range             | \[0, 512\] |
| Effective upon OBServer node restart | No          |
