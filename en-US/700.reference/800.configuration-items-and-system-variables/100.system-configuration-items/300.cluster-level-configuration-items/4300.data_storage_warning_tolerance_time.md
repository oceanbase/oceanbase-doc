# data_storage_warning_tolerance_time

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This parameter is available starting with V2.2.77. </p>
</main>

## Description

`data_storage_warning_tolerance_time` specifies the maximum time that the data disk remains in the `WARNING` state before it is automatically set to `WARNING`.

## Privilege requirements

* Query the parameter

  The `sys` tenant and all user tenants can query the value of this parameter by using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify the parameter

  Only the `sys` tenant can modify this parameter. User tenants cannot modify this parameter.

## Attributes

|        Attribute        |      Description       |
|------------------|---------------|
| Type             | Time          |
| Default value               | 5s<main id="notice" type='explain'><h4>Note</h4><p>Starting from V4.0.0, the default value of this parameter is changed from 30s to 5s. </p></main>           |
| Value range             | [1s, 300s]<main id="notice" type='explain'><h4>Note</h4><p>Starting from V4.0.0, the value range of this parameter is changed from [10s, 300s] to [1s, 300s]. </p></main> |
| Modifiable           | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
| Effective upon OBServer node restart | No. The setting takes effect immediately.    |

## Considerations

When an unexpected I/O failure occurs, the I/O manager of OceanBase Database attempts to detect the status of the data disk through a detection thread. If the data disk status has not returned to normal after the time specified by this parameter has elapsed, the detection thread sets the data disk status to `WARNING`. This status triggers events such as primary-to-standby switchover to ensure normal business operations.

## Examples

Set the maximum time that the data disk remains in the `WARNING` state before it is automatically set to `WARNING` to 20s.

```shell
obclient> ALTER SYSTEM SET data_storage_warning_tolerance_time = 20s;
```
