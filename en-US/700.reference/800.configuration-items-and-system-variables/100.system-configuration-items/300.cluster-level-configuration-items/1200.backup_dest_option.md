# backup_dest_option

<main id="notice" type='explain'>
<h4>Note</h4>
<ul>
<li>Due to the architectural optimization of physical backup and restore in V4.x, this parameter is removed starting from V4.0.0. </li>
<li>In V4.x, the parameters in this parameter have the following functions:
<ul><li>The time interval for log archiving delay can be set by using the tenant-level parameter <a href="../400.tenant-level-configuration-items/200.archive_lag_target.md">archive_lag_target</a>. </li>
<li>Setting the time window for restoring backup data is no longer supported. The system tenant and user tenant can use the <code>RECOVERY_WINDOW</code> option in the <a href="../../../500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/1600.delete-backup.md">ALTER SYSTEM ADD DELETE BACKUP POLICY</a> statement. </li>
<li>Backup data can be automatically cleaned up, but manual cleanup is not supported. For more information about how to automatically clean up backup data, see <a href="../../../../600.manage/600.backup-and-recovery/500.clear-backup-data/100.cleaning-up-backed-up-data-automatically.md">Automatically clean up expired backup data</a>. </li>
<li>The switching cycle of a piece can be set by using the <a href="../../../500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/150.set-log-archive-dest.md">ALTER SYSTEM SET LOG_ARCHIVE_DEST</a> statement. </li>
<li>Backup data cannot be backed up again. Therefore, the redundancy of a backup set cannot be specified. </li></ul>
</li></ul>
</main>

## Description

`backup_dest_option` specifies parameters related to backup.
