# migration_disable_time

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This parameter is available starting with V1.4. </p>
</main>

## Description

`migration_disable_time` specifies the cooldown period during which new data migration operations are disabled after a data migration fails due to resource exceptions, such as disk space exhaustion.

## Privilege requirements

* Query the parameter

  The `sys` tenant and all user tenants can use the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view to query this parameter.

* Modify the parameter

  Only the `sys` tenant can modify this parameter. User tenants cannot modify this parameter.

## Attributes

| **Attribute** | **Description** |
| -------- | -------- |
| Type             | Time      |
| Default value    | 3600s     |
| Value range      | [1s, +∞) |
| Modifiable | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
| Effective upon OBServer node restart | No. The setting takes effect immediately.  |

## Examples

Set the cooldown period during which new data migration operations are disabled after a data migration fails due to resource exceptions, such as disk space exhaustion, to 3600s.

```shell
obclient> ALTER SYSTEM SET migration_disable_time = 3600s;
```
