# ob_java_opts

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This parameter is available starting with V4.3.5 BP1. </p>
</main>

## Description

`ob_java_opts` specifies the JVM startup parameters for Java.

## Privilege requirements

* Query the parameter

  You can use the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view to query this parameter in the sys tenant and all user tenants.

* Modify the parameter

  Only the sys tenant can modify this parameter. User tenants cannot modify this parameter.

## Attributes

|Attribute|Description|
|---|---|
|Type|STRING|
|Default value| An empty string. |
|Modifiable | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
|Effective upon OBServer node restart | No. The setting takes effect immediately. <main id="notice" type='explain'><h4>Note</h4><p>JVM startup parameters are basic runtime environment configurations. They are loaded according to the Java Virtual Machine (JVM) specification: <li>Parameter initialization occurs during JVM startup. </li><li>Runtime reloading is not supported. </li><li>Hot-swapping is not supported. </li></p></main>|
|Mandatory items|<ul><li>-XX:-CriticalJNINatives</ul></li><ul><li>-Djdk.lang.processReaperUseDefaultStackSize=true</ul></li><ul><li>-Xrs</ul></li>|

## Examples

In the sys tenant, run the following command to enable or configure the parameter.

```shell
ALTER SYSTEM SET ob_java_opts="-Xmx2048m -Xmn2048m -XX:-CriticalJNINatives -Djdk.lang.processReaperUseDefaultStackSize=true -Xrs -XX:+HeapDumpOnOutOfMemoryError -Xloggc:/home/admin/gc.log -XX:+PrintGCDetails -XX:+PrintGCDateStamps -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/home/admin/heapdumps/ -XX:+UseConcMarkSweepGC -XX:+UseParNewGC -XX:CMSInitiatingOccupancyFraction=75 -XX:+UseCMSInitiatingOccupancyOnly -XX:+CMSClassUnloadingEnabled -XX:+TieredCompilation -XX:+ExplicitGCInvokesConcurrentAndUnloadsClasses ";
```

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>Make sure that the <code>/home/observer/heapdumps</code> and <code>/home/observer</code> directories exist. If these directories do not exist, you must manually create them as the deployment user of OBServer. Note that the path in this example is for reference only. You can specify other paths as needed. </p>
