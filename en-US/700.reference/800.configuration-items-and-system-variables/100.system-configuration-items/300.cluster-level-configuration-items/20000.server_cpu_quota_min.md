# server_cpu_quota_min

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This parameter is available starting with V2.2.50.  </p>
</main>

## Description

`server_cpu_quota_min` specifies the minimum CPU quota that the system can use, which is automatically reserved.

## Privilege requirements

* Query the parameter

  The `sys` tenant and all user tenants can query this parameter by using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify the parameter

  Only the `sys` tenant can modify this parameter. User tenants cannot modify this parameter.

## Attributes

|      **Attribute**      |  **Description**   |
|------------------|-----------|
| Type             | Double    |
| Default value               | 0, which means adaptive adjustment<main id="notice" type='explain'><h4>Note</h4><ul><li>Starting from V4.0.0, the default value was changed from 2.5 to 1.  </li><li>Starting from V4.2.1, the default value was changed from 1 to 0. </li></ul></main>  |
| Value range             | [0, 16]<main id="notice" type='explain'><h4>Note</h4><ul><li>Starting from V4.0.0, the value range was changed from [0, 16] to [1, 16].</li><li>Starting from V4.2.1, the value range was changed from [1, 16] to [0, 16]. </li></ul></main>       |
| Modifiable           | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
| Effective upon OBServer node restart | No. The setting takes effect immediately.<main id="notice" type='explain'><h4>Note</h4><p>Starting from V4.1.0, this parameter takes effect immediately, without requiring an OBServer node restart.  </p></main>             |

## Considerations

If this parameter is set to 0, the value will be adaptively adjusted based on the `cpu_count` of the server:

1. If `cpu_count` is less than 8, the value of `server_cpu_quota_min` is adaptively adjusted to 1.
2. If 8 ≤ `cpu_count` < 16, the value of `server_cpu_quota_min` is adaptively adjusted to 2.
3. If 16 ≤ `cpu_count` < 32, the value of `server_cpu_quota_min` is adaptively adjusted to 3.
4. If `cpu_count` is 32 or more, the value of `server_cpu_quota_min` is adaptively adjusted to 4.

## Examples

Enable adaptive adjustment of the maximum CPU quota for the system.

```shell
obclient> ALTER SYSTEM SET server_cpu_quota_max=0;
```
