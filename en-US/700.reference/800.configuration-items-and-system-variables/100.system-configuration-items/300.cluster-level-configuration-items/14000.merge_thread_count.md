# merge_thread_count

<main id="notice" type='explain'>
<h4>Note</h4>
<ul><li>OceanBase Database V4.x does not support configuration of thread resources by task type due to limited thread resources. This parameter has been deprecated since OceanBase Database V4.0.0. </li>
<li>In OceanBase Database V4.x, you can use the tenant-level parameter <code>compaction_low_thread_score</code> to specify the weight of the CPU time slice occupied by the worker threads for low-priority compaction tasks. For more information about the parameter, see <a href="../400.tenant-level-configuration-items/1100.compaction_low_thread_score.md">compaction_low_thread_score</a>. </li></ul>
</main>

## Description

`merge_thread_count` specifies the number of worker threads for the daily compaction.

## Limitations

* Query the parameter

  In the `sys` tenant or a user tenant, you can execute the `SHOW PARAMETERS` statement to query the parameter or query the `GV$OB_PARAMETERS` view for the parameter.

* Modify the parameter

  You can modify the parameter only in the `sys` tenant.

## Attributes

| **Attribute** | **Description** |
|------------------|------------|
| Type | Integer |
| Default value | 0 |
| Value range | [0, 256] |
| Modifiable | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
| Effective upon OBServer node restart | No. The setting takes effect immediately.          |

## Considerations

If this parameter is set to `0`, the formula for calculating the number of worker threads for a compaction is `min{10,cpu_cnt}`, where `cpu_cnt` indicates the number of CPU cores in the system.

## Examples

```shell
obclient> ALTER SYSTEM SET merge_thread_count=100;
```
