# default_compress

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This parameter is available starting with V2.1. </p>
</main>

## Description

`default_compress` specifies the default compression strategy for tables created in Oracle-compatible mode.

<main id="notice">
  <h4>Applicability</h4>
  <p>This parameter applies only to OceanBase Database in Oracle-compatible mode. </p>
</main>

## Privilege requirements

* Query the parameter

  The `sys` tenant and all user tenants can query this parameter by using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify the parameter

  Only the `sys` tenant can modify this parameter. User tenants cannot modify this parameter.

## Attributes

|   **Attribute**    |  **Description**  |
|---------------|------------|
| Type             | String     |
| Default value               | archive                                                                  |
| Value range             | <ul><li>NOCOMPRESS: Use the Flat format without compression. </li><li>BASIC: Use the Flat format and the <code>lz4_1.0</code> compression method. </li><li>OLTP: Use the Flat format and the <code>zstd_1.3.8</code> compression method. </li><li>QUERY: Use the Encoding format and the <code>lz4_1.0</code> compression method. </li> <li>ARCHIVE: Use the Encoding format and the <code>zstd_1.3.8</code> compression method. </li></ul>     |
| Modifiable           | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
| Effective upon OBServer node restart | No. The setting takes effect immediately.  |

## Examples

Enable Debug Sync and set the timeout to 3s.

```shell
obclient> ALTER SYSTEM SET default_compress= 'NOCOMPRESS';
```
