# backup_log_archive_option

<main id="notice" type='explain'>
<h4>Note</h4>
<ul>
<li>Due to the architectural optimization of physical backup and restore in V4.x, this parameter is removed starting from V4.0.0. </li>
<li>For V4.x, the corresponding features are as follows:
<ul><li>Setting the backup mode is no longer supported. You can use the <code>BINDING</code> option in the <a href="../../../500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/3800.set-log-archive-dest.md">ALTER SYSTEM SET LOG_ARCHIVE_DEST</a> statement to set the priority mode for log archiving and business. </li>
<li>Log archiving compression is not supported. </li></ul>
</li></ul>
</main>

## Description

`backup_log_archive_option` specifies the options for archiving backup logs.

## Attributes

|**Attribute**|   **Description**      |
|------------------|--------------------------|
| Type             | String                      |
| Default value              | `OPTIONAL COMPRESSION=ENABLE`                    |
| Value range             | <ul><li>`MANDATORY`: specifies that backup takes precedence. If log archiving is too slow, write operations may be blocked. </li><li>`OPTIONAL`: specifies that write operations take precedence. If write operations are too frequent, log archiving may be interrupted. </li><li>`COMPRESSION`: specifies the compression algorithm. Valid values: `ENABLE`, `DISABLE`, `LZ4_1.0`, and `ZSTD_1.3.8`. Default value: `ENABLE`, which uses the LZ4_1.0 algorithm. </li></ul>     |
| Effective upon OBServer node restart |No     |
