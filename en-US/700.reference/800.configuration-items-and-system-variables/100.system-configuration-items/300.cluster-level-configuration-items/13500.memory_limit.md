# memory_limit

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This parameter is available starting with V1.4. </p>
</main>

## Description

`memory_limit` specifies the total amount of memory available to an OBServer node.

The `memory_limit` parameter takes effect only if the following two conditions are met:

* The reserved memory for a 500 tenant is not less than the actual memory used.
* The value of `memory_limit` is greater than the sum of the `system_memory` value and the memory allocated to each unit.

If these conditions are not met, setting `memory_limit` does not result in an error and does not take effect.

## Privilege requirements

* Query the parameter

  The `sys` tenant and all user tenants can query this parameter by using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify the parameter

  Only the `sys` tenant can modify this parameter. User tenants cannot modify this parameter.

## Considerations

* The default value of `memory_limit` is `0`. If this value is not `0`, the system will ignore the `memory_limit_percentage` setting and use the value specified by `memory_limit` instead. For example, if a physical server has 100 GB of memory, `memory_limit_percentage` is set to `80`, which means that 80% of the memory is used, and `memory_limit` is set to `'90G'`, then the memory available to OceanBase Database on the physical server is 90 GB. For more information about `memory_limit_percentage`, see [memory_limit_percentage](13600.memory_limit_percentage.md).

* The default unit of `memory_limit` is MB. For example, `memory_limit='40G'` specifies that the maximum memory usage of the OceanBase Database process is 40 GB. Since the default unit is MB, `memory_limit=40960` and `memory_limit='40G'` specify the same value.

* There is no upper limit for the value of `memory_limit`.

  * If the maximum memory limit set exceeds the total physical memory, other values calculated based on the total memory will be larger than expected.

  * If you want to limit the memory usage of a running OceanBase Database instance, you can directly modify the `memory_limit` value to achieve the desired setting. After the modification, the background parameter reload thread will dynamically apply the change without requiring a restart. However, when setting the value, ensure that it is less than the total memory available to the system.

      <h4>Notice</h4>
      <p>The value of <code>memory_limit</code> must be greater than the actual memory used by the OBServer node.</p>
    </main>

## Examples

* To set the total available memory of an OBServer node to 32 GB, execute the following command:

  ```shell
  obclient> ALTER SYSTEM SET memory_limit='32G';
  ```

* To query the current memory usage (in GB), execute the following command:

  ```shell
  obclient> SELECT value/1024/1024/1024 used_gb FROM v$sysstat WHERE name LIKE '%observer memory%' AND con_id = 1 AND stat_id=140008 AND name='observer memory used size';
  ```
