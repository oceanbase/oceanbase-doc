# schema_history_recycle_interval

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>For V1.4, this parameter is available starting with V1.4. </p>
</main>

## Description

`schema_history_recycle_interval` specifies the interval at which the system executes the `schema` multi-version record recycling task.

## Privilege requirements

* Query the parameter

  The `sys` tenant and all user tenants can use the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view to query this parameter.

* Modify the parameter

  Only the `sys` tenant can modify this parameter. User tenants cannot modify this parameter.

## Attributes

|      **Attribute**      |  **Description**   |
|------------------|-----------|
| Type             | Time      |
| Default value               | 10m, which indicates 10 minutes       |
| Value range             | [0s, +∞)<main id="notice" type='explain'><h4>Note</h4><ul><li>When the value is 0, the <code>schema</code> multi-version record recycling task is disabled. </li> <li>When the value is not 0, the interval at which the <code>schema</code> multi-version record recycling task is executed. </li></ul></main> |
| Modifiable           | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
| Effective upon OBServer node restart | No. The setting takes effect immediately.      |

## Examples

Set the interval at which the system executes the `schema` multi-version record recycling task to 10 minutes.

```shell
obclient> ALTER SYSTEM SET schema_history_recycle_interval = '10m';
```
