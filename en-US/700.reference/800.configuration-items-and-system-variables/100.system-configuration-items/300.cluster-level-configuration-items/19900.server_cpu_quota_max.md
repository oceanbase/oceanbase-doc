# server_cpu_quota_max

## Description

The `server_cpu_quota_max` parameter specifies the maximum CPU quota available to the system.

## Privilege requirements

* Query the parameter

  The `sys` tenant and all user tenants can execute the `SHOW PARAMETERS` statement or query the `GV$OB_PARAMETERS` view to obtain the value of this parameter.

* Modify the parameter

  Only the `sys` tenant can modify this parameter. User tenants cannot modify this parameter.

## Attributes

|      **Attribute**      |  **Description**   |
|--------------------|-----------|
| Type             | Double    |
| Default value               | 0 <main id="notice" type='explain'><h4>Note</h4><ul><li>Starting from V4.0.0, the default value of this parameter was changed from 5 to 1.  </li><li>Starting from V4.2.1, the default value of this parameter was changed from 1 to 0. </li></ul></main> |
| Value range             | [0, 16]  <main id="notice" type='explain'><h4>Note</h4><ul><li>Starting from V4.0.0, the value range of this parameter was changed from [0, 16] to [1, 16].</li><li>Starting from V4.2.1, the value range of this parameter was changed from [1, 16] to [0, 16]. </li></ul></main>   |
| Modifiable           | Yes. You can execute the `ALTER SYSTEM SET` statement to modify this parameter.|
| Takes effect without a server restart | No<main id="notice" type='explain'><h4>Note</h4><p>This parameter takes effect immediately starting from V4.1.0, instead of after a server restart. </p></main>           |

## Considerations

When the value is 0, the system adaptively adjusts the value of `server_cpu_quota_max` based on the value of `cpu_count`:

1. If `cpu_count` < 8c, `server_cpu_quota_max` is adaptively adjusted to 1c;
2. If 8c ≤ `cpu_count` < 16c, `server_cpu_quota_max` is adaptively adjusted to 2c;
3. If 16c ≤ `cpu_count` < 32c, `server_cpu_quota_max` is adaptively adjusted to 3c;
4. If 32c ≤ `cpu_count`, `server_cpu_quota_max` is adaptively adjusted to 4c.
