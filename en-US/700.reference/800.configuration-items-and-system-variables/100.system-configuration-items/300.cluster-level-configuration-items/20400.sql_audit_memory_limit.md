# sql_audit_memory_limit

<main id="notice" type='explain'>
<h4>Note</h4>
<ul><li>Starting from V2.x, OceanBase Database splits the SQL Audit system tables by tenant. As a result, the memory used by SQL Audit is now tenant-level. The server-level memory eviction upper limit defined by this parameter is no longer applicable and was removed starting with V4.0.0. </li>
<li>In versions 2.x and later, use the system variable <code>ob_sql_audit_percentage</code> to control the percentage of memory used by SQL Audit relative to the current tenant's memory. For more information about the system variable <code>ob_sql_audit_percentage</code>, see <a href="../../200.system-variable/300.global-system-variable/9000.ob_sql_audit_percentage-global.md">ob_sql_audit_percentage</a>. </li></ul>
</main>

## Description

`sql_audit_memory_limit` specifies the maximum amount of memory that can be used for SQL audit data.

## Attributes

|      **Attribute**      |   **Description**   |
|------------------|------------|
| Parameter type             | Capacity       |
| Default value               | 3G         |
| Value range             | \[64M, +∞) |
| Effective upon OBServer node restart | No          |
