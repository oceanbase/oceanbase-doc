# ob_storage_s3_url_encode_type

<main id="notice" type='explain'>
<h4>Note</h4>
<ul><li>For V4.2.1, this parameter is available starting with V4.2.1 BP9. For other V4.2.x versions, this parameter is available starting with V4.2.5. </li>
<li>For V4.3.x, this parameter is available starting with V4.3.3. </li></ul>
</main>

## Description

`ob_storage_s3_url_encode_type` specifies whether the URL encoding method for S3 requests is compatible with the RFC 3986 standard.

## Privilege requirements

* Query the parameter

  The `sys` tenant and all user tenants can use the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view to query this parameter.

* Modify the parameter

  Only the `sys` tenant can modify this parameter. User tenants cannot modify this parameter.

## Attributes

| **Attribute** | **Description**    |
|-----------|------------|
| Type | String |
| Default value   | default |
| Value range | <ul><li>compliantRfc3986Encoding</li> <li>default</li></ul> |
| Modifiable           | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
| Effective upon OBServer node restart | No. The setting takes effect immediately. |

## Considerations

This parameter is applicable to object storage that is compatible with the S3 protocol but may not support the default URL encoding method of the AWS S3 SDK. For more information, see [Prepare for log archiving](../../../../600.manage/600.backup-and-recovery/300.log-archive/200.preparation-before-log-archive.md).

## Examples

Set the URL encoding method for S3 requests to be compatible with the RFC 3986 standard.

```shell
obclient> ALTER SYSTEM SET ob_storage_s3_url_encode_type='compliantRfc3986Encoding';
```
