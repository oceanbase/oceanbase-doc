# memstore_limit_percentage

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This parameter is available starting with V1.4. </p>
</main>

## Description

`memstore_limit_percentage` specifies the percentage of the total available memory that is used for MemStore.

## Attributes

|      **Attribute**    |  **Description**   |
|------------------|-----------|
| Type             | INT        |
| Default value               | 0, indicating adaptive adjustment. <main id="notice" type='explain'><h4>Note</h4><p>Starting from V4.3.0, the default value is changed from 50 to 0. </p></main> |
| Value range             | [0, 100) <main id="notice" type='explain'><h4>Note</h4><p>Starting from V4.3.0, the value range is changed from (0, 100) to [0, 100). </p></main>|
| Modifiable  | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
| Effective upon OBServer node restart | No. The setting takes effect immediately.        |

## Considerations

* The `memstore_limit_percentage` parameter is used to calculate the value of `memstore_limit`. The calculation formula is as follows:

  `memstore_limit_percentage` = `memstore_limit` / `memory_size`

  Here, `memory_size` is the value specified when the tenant is created, indicating the amount of memory available to the tenant. For more information about `memstore_limit`, see [memory_limit](13500.memory_limit.md).

* In V4.3.x, you can also configure the percentage of tenant MemStore to the total tenant memory by using the tenant-level hidden parameter <code>_memstore_limit_percentage</code>, starting from V4.3.0. The functionality and default value of <code>_memstore_limit_percentage</code> are the same as those of the cluster-level parameter <code>memstore_limit_percentage</code>. However, the effective scope is different. When configuring these parameters, note the following:

  <ul><li>If you configure only <code>_memstore_limit_percentage</code> or <code>memstore_limit_percentage</code> (not the default value), the configured value (not the default value) takes precedence. </li> <li>If you configure both the tenant-level hidden parameter <code>_memstore_limit_percentage</code> (not the default value) and the cluster-level parameter <code>memstore_limit_percentage</code> (not the default value), the value of <code>_memstore_limit_percentage</code> takes precedence. </li> <li>If neither parameter is configured or both are configured with the default value, the system adopts the following adaptive strategy:<ul><li>Tenants with 8 GB (real memory) or less are configured with a MemStore ratio of 40%. </li><li>Tenants with more than 8 GB of memory are configured with a MemStore ratio of 50%. </li></ul></li></ul>

## Examples

Set the percentage of tenant MemStore to 60% of the total available memory.

```shell
obclient> ALTER SYSTEM SET memstore_limit_percentage = 60;
```
