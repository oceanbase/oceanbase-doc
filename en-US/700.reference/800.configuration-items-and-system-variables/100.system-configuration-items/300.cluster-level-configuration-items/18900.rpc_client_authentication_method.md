# rpc_client_authentication_method

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This parameter is available starting with V3.2.4. </p>
</main>

## Description

`rpc_client_authentication_method` specifies the security authentication method for an RPC client.

For the `sys` tenant, you only need to set the authentication method on the client and server.

## Privilege requirements

* Query the parameter

  The `sys` tenant and all user tenants can use the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view to query this parameter.

* Modify the parameter

  Only the `sys` tenant can modify this parameter. User tenants cannot modify this parameter.

## Attributes

| **Attribute** | **Description** |
| ------ | ------ |
| Parameter type             | String |
| Default value               | NONE |
| Value range             |<ul> <li>NONE: the default authentication method for a client, which indicates no authentication. </li> <li>SSL_NO_ENCRYPT: SSL authentication based on a local SSL certificate and private key, but no encryption is used for subsequent communications. </li></ul>|
| Modifiable | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
| Effective upon OBServer node restart | No. The setting takes effect immediately. |

## Considerations

* On the server, configure the <code>rpc_server_authentication_method</code> parameter. For more information, see [rpc_server_authentication_method](19100.rpc_server_authentication_method.md).
* If the value of this parameter is set correctly, the latest configuration takes effect. Otherwise, the original authentication method remains in effect.
* You can configure only one authentication method on a client. The default value is <code>NONE</code>, and this parameter is case-insensitive.

## Examples

Set the security authentication method for an RPC client to NONE.

```shell
obclient> ALTER SYSTEM SET rpc_client_authentication_method = 'NONE';
```
