# backup_log_archive_option

<main id="notice" type='explain'>
<h4>Note</h4>
<ul>
<li>Due to the architecture optimization of physical backup and restore in V4.x, this parameter is removed starting from V4.0.0. </li>
<li>In V4.x, the corresponding features of this parameter are as follows:
<ul><li>Backup mode cannot be set by configuring this parameter. You can use the <code>BINDING</code> option in the <a href="../../../500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/150.set-log-archive-dest.md">ALTER SYSTEM SET LOG_ARCHIVE_DEST</a> statement to set the priority mode for archiving and business operations. </li>
<li>Log archiving compression is not supported. </li></ul>
</li></ul>
</main>

## Description

`backup_log_archive_option` specifies the options for archiving backup logs.

## Attributes

|**Attribute**          |   **Description**      |
|------------------|--------------------------|
| Type             | String                                                                                                         |
| Default value              | `OPTIONAL COMPRESSION=ENABLE`                    |
| Value range             | <ul><li> `MANDATORY`: indicates that backup has priority. Slow log archiving may cause write suspension.   </li><li> `OPTIONAL`: indicates that write has priority. Writes may cause log archiving to be interrupted.   </li><li> `COMPRESSION`: supports `ENABLE`, `DISABLE`, `LZ4_1.0`, and `ZSTD_1.3.8`. The default value is `ENABLE`, which uses the LZ4_1.0 compression algorithm. </li></ul>   |
| Effective upon OBServer node restart | No                                                                                                        |
