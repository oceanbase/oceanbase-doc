# resource_hard_limit

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>For V2.2.30, this parameter is available starting with V2.2.30. </p>
</main>

## Description

`resource_hard_limit` specifies the over-subscription ratio of CPU resources. A value greater than 100 indicates that over-subscription is allowed.

## Privilege requirements

* Query the parameter

  The `sys` tenant and all user tenants can query the value of this parameter by using the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view.

* Modify the parameter

  Only the `sys` tenant can modify this parameter. User tenants cannot modify this parameter.

## Attributes

|      **Attribute**      |    **Description**    |
|------------------|--------------|
| Type             | Int             |
| Default value               | 100            |
| Value range             | [100, 10000] |
| Modifiable           | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
| Effective upon OBServer node restart | No. The setting takes effect immediately.   |

## Considerations

* Starting from OceanBase Database V4.0.0.0, you cannot use the `resource_hard_limit` parameter to over-subscribe memory resources.

* `resource_hard_limit` specifies the over-subscription ratio of CPU resources for an OBServer node. The sum of the `MAX_CPU` values of all tenants on an OBServer node cannot exceed the over-subscribed CPU capacity: `CPU_CAPACITY * resource_hard_limit`.

* After you set `resource_hard_limit` to a value greater than 100, the over-subscription ratio of CPU resources is changed. This change affects only the upper limit of CPU resources for the corresponding resource units, but not the lower limit. When you use the over-subscription mechanism, you must be cautious to ensure that the loads can be staggered to avoid system issues caused by resource over-subscription and load overloads.

## Examples

Set the over-subscription ratio of CPU resources to 100.

```shell
obclient> ALTER SYSTEM SET resource_hard_limit = 100;
```
