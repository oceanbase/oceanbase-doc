# sql_protocol_min_tls_version

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>For V4.2.1, this parameter is available starting with V4.2.1.</p>
</main>

## Description

`sql_protocol_min_tls_version` specifies the minimum version of the SSL/TLS protocol used for SSL connections to execute SQL statements.

## Privilege requirements

* Query the parameter

  The `sys` tenant and all user tenants can use the `SHOW PARAMETERS` statement or the `GV$OB_PARAMETERS` view to query this parameter.

* Modify the parameter

  Only the `sys` tenant can modify this parameter. User tenants cannot modify this parameter.

## Attributes

| **Attribute** | **Description** |
| --- | --- |
| Type             | String |
| Default value    | none |
| Value range      |<ul><li>none: No restriction is imposed on the version of the SSL/TLS protocol used for connections.  </li><li>TLSv1 / TLSv1.1 / TLSv1.2 / TLSv1.3: If you specify any of these versions, the specified version and higher versions are used for SSL encryption. </li></ul> |
| Modifiable       | Yes. You can use the `ALTER SYSTEM SET` statement to modify the parameter. |
| Effective upon OBServer node restart | No. The setting takes effect immediately. |

## Considerations

This parameter is used to control the selection of the SSL version. To enable SSL, you also need to set [ssl_client_authentication](20800.ssl_client_authentication.md).

## Examples

Set the minimum version of the SSL/TLS protocol used for SSL connections to execute SQL statements to NONE.

```shell
obclient> ALTER SYSTEM SET sql_protocol_min_tls_version = 'none';
```
