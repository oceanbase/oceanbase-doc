## ERROR 10516 (HY000) : When invoking the Increment interface, only HBase cells with a length of 8 can be converted to int64_t. the current length of the HBase cell is '%d'

* OceanBase error code: 10516

* Cause: When using the Increment interface in OBKV-HBase, the value of the cell undergoing addition or subtraction must be an 8-byte long type (Java long/int64) and must be in big-endian format (where the high-order byte precedes the low-order byte). If it is not an 8-byte long, the operation will fail. Common reasons include:

  * The incremental data written by the client is not an 8-byte long, such as being written as a string, text, int32, etc., without being encoded as a long type.
  * The column has previously been written with data other than 8 bytes using Put or Append (such as strings, variable-length binary, etc.), causing the current value type to be non-long.

* Solution:

  * When writing incremental data, the client must encode the value as an 8-byte big-endian long integer (in Java, use org.apache.hadoop.hbase.util.Bytes.toBytes(long)).
  * If a cell already contains data that is not a valid long integer, you can delete or overwrite the existing data with a valid 8-byte long integer before performing the increment operation.

## ERROR 11032 (HY000) : HDFS path message %s

* OceanBase error code: 11032

* Cause: The HDFS path message %s error occurs, commonly in the following scenarios:

  1. In an HDFS environment with Kerberos authentication enabled, when accessing an external HDFS table, if insufficient permissions prevent access, a -11032 error occurs.

  2. If Kerberos authentication is correctly configured but the "HDFS: path not found" error still occurs, it may be because the external table path specified in the external table creation statement is incorrect and points to a non-existent path.

  3. External table access is normal initially, but after running queries for a while, the 11032 error occurs. This may be because a bad block exists in a file under the HDFS external table path. That is, the HDFS DataNode reports an error and makes the data block inaccessible, triggering the error.

* Solution:
  1. Confirm that the Kerberos authentication keytab and principal are valid and that the corresponding user has access permissions to the HDFS cluster. Then, reconfigure the external table permissions and set up Kerberos authentication.

  2. Confirm that the corresponding HDFS path is correct and exists. Then, re-establish the HDFS path mapping for the external table.

  3. Report the issue to the customer's operations team. After confirming the bad block situation, you can choose to adjust the bad blocks or switch environments to continue verification.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This error code is introduced in V4.5.0.</p>
</main>

* OceanBase error code: 11114

## ERROR 11126 (HY000) : unit \'%.*s\' not recognized

* OceanBase error code: 11126
* Error cause: The time unit parameter is not recognized when calling a date truncation function (such as DATE_TRUNC or DATETRUNC).
  
* Solution: Check the first parameter of the date truncation function in your SQL statement to ensure its spelling is correct and it is a valid time unit keyword supported by OceanBase Database.
