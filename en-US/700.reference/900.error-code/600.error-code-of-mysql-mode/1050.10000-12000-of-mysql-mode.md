## ERROR 10516 (HY000): When invoking the Increment interface, only HBase cells with a length of 8 can be converted to int64_t. the current length of the HBase cell is '%d'

* OceanBase error code: 10516

* Error reason: When you use the Increment interface in OBKV-HBase, the value of a cell that is incremented or decremented must be an 8-byte long value (Java long/int64) in big-endian format, where the high-order byte precedes the low-order byte. If the value is not an 8-byte long, the operation fails. Common causes are as follows:

  * The incremental value written by the client is not an 8-byte long value. For example, it is written as a string, text, or int32 without being encoded as a long value.
  * The column has previously been written with data other than 8 bytes using Put or Append (such as strings, variable-length binary, etc.), causing the current value type to be non-long.

* Solution:

  * The client must encode the incremental value as an 8-byte big-endian long value. In Java, you can use org.apache.hadoop.hbase.util.Bytes.toBytes(long).
  * If a cell already contains data that is not a long integer, you can delete or overwrite it with a valid 8-byte long integer before performing the increment operation.

## ERROR 11046 (HY000): Invalid path: %.*s

* OceanBase error code: 11046

* SQLSTATE: HY000

* Error reason:

  * The spelling or case of the column name or path entered in the DDL statement does not match that in the file (files such as Parquet, ORC, and Arrow are usually case-sensitive).

  * An incorrect nested structure path was entered. For example, the intended access path is `addr.city`, but it was written as `addr_city` or `address.city` in the DDL statement.

  * In the same external table, some files lack this column.

  * Format symbol issues. For example, extra spaces, quotes, or incorrect escape characters before or after the column name.

* Solution:

  * Confirm whether the `data_access_path` or `EXTERNAL_FILE_COLUMN_PATTERN` on the external column in the DDL statement actually exists in the file's schema.

  * When using nested types, use the actual hierarchical path separator of the file for precise matching.

  * If the schemas of files in different partitions are different, create separate external tables for the parts lacking the column, or set a default value for that column to avoid directly using path mapping to handle missing columns.

  * Modify the incorrect column definition and recreate the external table.

## ERROR 11127 (HY000): Privilege not allowed for sensitive rules

* OceanBase error code: 11127

* Error reason: The user does not have the privilege to execute sensitive rule commands. This error only occurs when executing the `GRANT PLAINACCESS ON SENSITIVE RULE '%.*s' TO '%.*s'@'%.*s'` statement, indicating that the user executing the `GRANT` statement does not have the `PLAINACCESS` privilege on the sensitive rule `'%.*s'` (or has this privilege but lacks `GRANT OPTION`), and cannot grant this privilege to other users.

* Solution: Another user who has the `PLAINACCESS` privilege with `GRANT OPTION` on the rule must grant the `PLAINACCESS WITH GRANT OPTION` privilege to this user.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This error code is introduced in OceanBase Database V4.4.2. </p>
</main>
