# OBE-01000 ~ OBE-01499

  <main id="notice" >

* Cause: The maximum number of open cursors is exceeded.

## OBE-01002: fetch out of sequence

* OceanBase error code: 5931

* SQLSTATE: HY000

* Cause: An attempt was made to access data from an invalid cursor. This error can occur for the following reasons:

  * Accessing data from the cursor after retrieving the last row and returning the `OBE-1403` error.

  * Accessing data after issuing a `COMMIT` following the use of a cursor opened with the `FOR UPDATE` clause.

  * Rebinding all placeholders in an SQL statement and then attempting to access data before re-executing the statement.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>Implicit fetches in PL cursor loops can also cause this error.</p>
  </main>

* Solution:

  * Do not issue a `FETCH` statement after retrieving the last row.

  * Do not access data after issuing a `COMMIT` following a cursor opened with the `FOR UPDATE` clause.

  * Rebind and execute the SQL statement, then attempt to access data.

## OBE-01003: no statement parsed

* OceanBase error code: 9678

* SQLSTATE: HY000

* Cause: DBMS_SQL PARSE attempted to parse a DDL statement.

* Solution: Change the statement type of DBMS_SQL PARSE to a `SELECT` statement.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This error code is introduced in V4.0.0.</p>
</main>

## OBE-01045: user %.\*s lacks %.\*s privilege; login denied

* OceanBase error code: 5361

* SQLSTATE: HY000

* Cause: The user lacks the required privilege (usually `CREATE SESSION`) when attempting to log in. Logon is denied.

* Solution: Grant the corresponding privilege to the user. For example, to grant the `CREATE SESSION` privilege:

  ```sql
  GRANT CREATE SESSION TO username;
  ```

## OBE-01086: savepoint does not exist

* OceanBase error code: 6242

* SQLSTATE: 42000

* Cause: You attempted to roll back to a savepoint that was never established or is invalid in the current session.

* Solution: Try rolling back to the savepoint from the session that established it.

## OBE-01402: view WITH CHECK OPTION where-clause violation

* OceanBase error code: 5971

* SQLSTATE: HY000

* Cause: A DML operation on the view violates the view's `WITH CHECK OPTION` constraint.

* Solution: The data inserted into the view by an `INSERT` statement, or the data after an `UPDATE`, must satisfy the `WHERE` condition defined in the view.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This error code is introduced in V4.0.0.</p>
</main>

## OBE-01451: column to be modified to NULL cannot be modified to NULL

* OceanBase error code: 5850

* SQLSTATE: HY000

* Cause: The column may already allow `NULL` values, and the `NOT NULL` constraint is part of the primary key or a `CHECK` constraint.

* Solution: If the primary key or a `CHECK` constraint enforces the `NOT NULL` constraint, remove that constraint.

## OBE-01453: SET TRANSACTION must be first statement of transaction

* OceanBase error code: 5219

* SQLSTATE: 25001

* Cause: Transaction characteristics cannot be changed while a transaction is in progress.

* Solution: Commit (or roll back) the transaction, then re-execute the modification.

## OBE-01456: may not perform insert/delete/update operation inside a READ ONLY transaction

* OceanBase error code: 5220, 6226

* SQLSTATE: 25006

* Error cause: You cannot perform INSERT, DELETE, or UPDATE operations in a read-only transaction.

* Solution: Commit (or roll back) the transaction and try again.

## OBE-01463: cannot modify column datatype with current constraint(s)

* OceanBase error code: 5860

* SQLSTATE: HY000

* Error cause: You are trying to modify the data type of a column with a CHECK constraint. However, for a column with a CHECK constraint, you can only change its data type from CHAR to VARCHAR.

* Solution: Drop the constraint or do not perform the invalid operation.
