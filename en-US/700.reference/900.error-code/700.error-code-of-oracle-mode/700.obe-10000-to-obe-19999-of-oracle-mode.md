## OBE-12000: a materialized view log already exists on table %s

* OceanBase error code: 9756

* SQLSTATE: HY000

* Cause: You are trying to create a materialized view log on a table that already has a materialized view log. Each primary table can have only one materialized view log.

* Solution: All materialized views on a table can use the materialized view log of the table. If you want to change an existing log, drop the materialized view log and create a new one.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p>This error code was introduced in V4.2.2. </p>
</main>

## OBE-12052: cannot fast refresh materialized view %s.%s

* OceanBase error code: 9760

* SQLSTATE: HY000

* Cause: The basic requirements for creating an incremental refresh materialized view are not met. For example:

  * The base table specified in the definition of the incremental refresh materialized view does not have a materialized view log (mlog) table.
  * The definition of the incremental refresh materialized view contains set-based operations.
  * The columns used in the incremental refresh materialized view are not maintained in the mlog of the base table.

* Solution: Check whether the definition of the incremental refresh materialized view meets the basic requirements for incremental refreshes. For more information, see [Refresh materialized views](../../300.database-object-management/200.manage-object-of-oracle-mode/500.manage-views-of-oracle-mode/200.manage-materialized-views-of-oracle-mode/400.refresh-materialized-views-of-oracle-mode.md).

  <h4>Note</h4>
  <p>This error code was introduced in V4.3.0. </p>
</main>

## OBE-12704: COLLATION '%.\*s' is not valid for CHARACTER SET '%.\*s'

* OceanBase error code: 5144

* SQLSTATE: 42000

* Cause: This may be due to the following reasons:

  * The operands of a string operation (excluding the `nlsparams` parameter) for an operator or built-in function are not in the same character set.

  * The `nlsparams` operand is not in the database character set.

  * The character set used by the database does not include the character set used by the built-in function to process the string data, or the built-in function does not accept this character set.

  * The second parameter of the `CHR()` or `CSCONVERT()` function is not `CHAR_CS` or `NCHAR_CS`.

  * The character set of the string expression in the `VALUES` clause of the `INSERT` statement or the `SET` clause of the `UPDATE` statement does not match the character set of the column to be inserted into or updated.

  * The character set of the value provided in the `DEFAULT` clause of the `CREATE TABLE` statement does not match the character set of the column.

  * The character set of the parameter of the PL function does not meet the character set requirement of the corresponding parameter.

## OBE-12704: character set mismatch

* OceanBase error code: 5808

* SQLSTATE: HY000

* Cause: One of the following conditions is met:

  * String operands (excluding `nlsparams`) for an operator or built-in function are not in the same character set.

  * The value of the `nlsparams` operand is not in the database character set.

  * A character set other than the database character set is used for the string data passed to a built-in function that does not accept such a character set.

  * The second parameter of the `CHR()` or `CSCONVERT()` function is not `CHAR_CS` or `NCHAR_CS`.

  * The character set of a string expression in the `VALUES` clause of an `INSERT` statement or in the `SET` clause of an `UPDATE` statement does not match the character set of the destination column.

  * The character set of the value specified in the `DEFAULT` clause of the `CREATE TABLE` statement does not match the character set of the column.

  * The character set of a parameter of a PL function does not meet the character set requirement of the parameter.
