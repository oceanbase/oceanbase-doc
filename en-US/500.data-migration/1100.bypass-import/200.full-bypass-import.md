# Full direct load

This topic explains how to perform full direct load by using the `LOAD DATA` statement, the `INSERT INTO SELECT` statement, and the `CREATE TABLE AS SELECT` statement.

## Considerations

Take note of the following considerations when you use full direct load:

* OceanBase Database supports direct load for LOB data types since V4.3.0.
* Direct load locks the table. During this period, no data can be written to the table, and the table is read-only.
* Direct load is not advantageous when the data amount is small, because direct load writes data to the disk, while writing data only to the memory without minor or major compactions is more efficient.
* Full direct load is suitable for the first import of large tables, migration of data in the range of 10 GB to TB, and scenarios with limited CPU and memory resources. This is because the execution path of direct load is short and can save CPU overheads.
* The `LOAD DATA` statement can be executed in a multi-row transaction. However, as a Data Definition Language (DDL) operation, it will proactively commit all preceding transactions.
* The `INSERT INTO SELECT` statement supports direct load only in Parallel Data Manipulation Language (PDML) mode. Non-PDML statements are not supported.
* Take note of the following points if you want to use specified partition direct load with the `LOAD DATA` or `INSERT INTO SELECT` statement:

  * The destination table cannot be a replica table and must not contain an auto-increment column, an ID column, or a global index.
  * If the last-level partitioning is HASH or KEY, direct load for partitions is not supported.

* In the case of full direct load with a unique index, the `LOAD DATA` statement does not support the `REPLACE` or `IGNORE` keyword, nor does it support the error tolerance feature.

## Import data in direct load mode by using the LOAD DATA statement

You can use the direct load mode to import data by using the LOAD DATA statement. In direct load mode, the data is loaded to the server in a raw format, without being parsed.

The `LOAD DATA` statement can use the `APPEND | direct()` hint to perform direct load. If no hint is specified, the default load mode, which is specified in the [default_load_mode](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2050.default_load_mode.md) parameter, determines the behavior of data import.

<main id="notice" type='notice'>
  <h4>Notice</h4>
   <p>OceanBase Database uses parallel processing to optimize the data import rate of the <code>LOAD DATA</code> statement. The data is divided into multiple subtasks for parallel execution. Each subtask is considered a separate transaction. The subtasks are executed in no particular order. Therefore, for a table without a primary key, the data write order may differ from the order in the original file.

### Limitations

* You cannot execute two write statements (write to one table) at the same time during data import. This is because the table is locked during data import and only read operations are supported.
* Data Import does not support triggers (Trigger).
* Data Import does not support tables with generated columns. Some indexes generate hidden generated columns, for example, KEY `idx_c2` (`c2`(16)) GLOBAL).
* Data of more than 2 MB in size per row cannot be imported.
* Data Import does not support Liboblog or flashback queries (Flashback Query).

### Syntax

```sql
LOAD DATA /*+ [APPEND | DIRECT(need_sort,max_error,'full')] parallel(N) */ [REMOTE_OSS | LOCAL] INFILE 'file_name' INTO TABLE table_name [PARTITION(PARTITION_OPTION)] [COMPRESSION]...
```

For more information about the `LOAD DATA` statement, see [LOAD DATA](../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/5900.load-data-of-mysql-mode.md).

**The parameters are described as follows: **

|Parameter|Description|
|------|------|
| APPEND \| DIRECT()  | Enables direct load. <ul><li>The <code>APPEND</code> hint is equivalent to the <code>DIRECT(true, 0)</code> hint by default. It also enables online optimizer statistics collection (<code>GATHER_OPTIMIZER_STATISTICS</code> hint). </li><li>The <code>direct()</code> parameter is described as follows: <ul><li><code>need_sort</code>: specifies whether the data to be written needs to be sorted. The value of this parameter is of the <code>bool</code> type. <ul><li><code>true</code>: specifies that the data needs to be sorted. </li><li><code>false</code>: specifies that the data does not need to be sorted. </li></ul></li><li><code>max_error</code>: the maximum number of tolerated error lines. The value of this parameter is of the <code>INT</code> type. If the number of error lines in the file exceeds the specified value, the import task will fail. </li><li><code>full</code>: specifies to perform full direct load. It is an optional parameter and must be enclosed in English single quotation marks. </li></ul></li></ul>|
| parallel(N) | The degree of parallelism for loading data. It is a required parameter and defaults to 4. |
| REMOTE_OSS \| LOCAL | Specifies whether to read data from the local file system of the client or the OSS file system. <ul><li>Use the <code>REMOTE_OSS</code> parameter to specify to read data from the OSS file system.<main id="notice" type='notice'><h4>Notice</h4><p>If this parameter is used, <code>file_name</code> must be the URL of an object in the OSS storage bucket. </p></main>  </li><li>Use the <code>LOCAL</code> parameter to specify to read data from the local file system of the client. If the `LOCAL` parameter is not used, data will be read from the file system of the OBServer node (server-side file system). </li></ul> |
| file_name                        | The path and file name of the input file. The <code>file_name</code> parameter is in one of the following formats: <ul><li>If the import file is stored on the OBServer node or client: <code>/\$PATH/\$FILENAME</code>. </li><li>If the import file is stored on OSS: <code>oss://\$PATH/\$FILENAME/?host=\$HOST&access_id=\$ACCESS_ID&access_key=\$ACCESSKEY</code>. </li></ul>     The parameters are described as follows: <ul><li><code>\$PATH</code>: the path of the file in the bucket, which indicates the directory where the file is stored. </li><li><code>\$FILENAME</code>: the name of the file, which indicates the specific file to access. </li><li><code>\$HOST</code>: the host name of the OSS service or the domain name of the CDN accelerator, which is the address for accessing the OSS service. </li><li><code>\$ACCESS_ID</code>: the Access Key ID required for authentication when accessing the OSS service. </li><li><code>\$ACCESSKEY</code>: the Access Key Secret required for authentication when accessing the OSS service. </li></ul>    <main id="notice" type='explain'> <h4>Note</h4> <p>When you import a file from OSS, make sure that the following conditions are met: <ul><li>You have the permissions to access the OSS bucket and file. You need to have sufficient permissions to read the specified bucket and file. Typically, you need to configure access permissions in the OSS console or by using OSS API and configure the access key (Access Key ID and Access Key Secret) as the credentials with appropriate permissions. </li><li>The database server can connect to the specified <code>$HOST</code> address over the network to access the OSS service. If a CDN accelerator domain name is used for <code>$HOST</code>, make sure that the CDN is correctly configured and the network connection is normal. </li></ul></p> </main>  |
| table_name                       | The name of the destination table. You can import data into any number of columns in the table.  |
| PARTITION_OPTION                   | The partition names for direct load. You can specify the partition names for direct load of multiple partitions. The partition names are separated with commas (,). You can also specify the subpartition names for direct load of multiple subpartitions. The subpartition names are separated with commas (,). <ul><li>partition_option_list: a comma-separated list of partition names. When you specify this parameter, multiple partitions are loaded at the same time. </li> <li>subpartition_option_list: a comma-separated list of subpartition names. When you specify this parameter, multiple subpartitions are loaded at the same time. </li></ul>|
| COMPRESSION                      | The compression format of the file. It can be one of the following values: <ul><li><code>AUTO</code>: automatically detects the compression algorithm based on the file name suffix. <br>When the <code>AUTO</code> parameter is used, different suffixes have corresponding compression formats. <ul><li><code>.gz</code>: a GZIP-compressed file. </li><li><code>.deflate</code>: a DEFLATE-compressed file. </li><li><code>.zst/.zstd</code>: a ZSTD-compressed file. </li></ul></li><li><code>NONE</code>: the file is not compressed. </li><li><code>GZIP</code>: a GZIP-compressed file. </li><li><code>DEFLATE</code>: a DEFLATE-compressed file without metadata. </li><li><code>ZSTD</code>: a ZSTD-compressed file. </li></ul>You can explicitly specify the compression format or let the program automatically detect the compression format based on the file name suffix. |

1. Log in to the server where the OBServer node to connect to resides and create test data in the `/home/admin` directory.

2. Set the path where the file to be imported is located.

      <h4>Notice</h4>
      <p>For security reasons, when you set the system variable <code>secure_file_priv</code>, you can connect to the database only through a local socket to execute the SQL statement that modifies the global variable.     </main>

    1. Log in to the server where the OBServer node to connect to resides.

        ```shell
        [xxx@xxx /home/admin]# ssh admin@10.10.10.1
        ```

    2. Connect to the `mysql001` tenant through a local Unix socket.


3. After reconnecting to the database, use the `LOAD /*+ DIRECT */ DATA` statement to import data.

    1. Create a table named `tbl2`.

       ```shell
       obclient [test]> CREATE TABLE tbl2 (
                           col1 INT PRIMARY KEY,
                           col2 INT
                        ) 
                        PARTITION BY RANGE (col1) 
                           SUBPARTITION BY RANGE (col1) (
                              PARTITION p0 VALUES LESS THAN (100) (
                                    SUBPARTITION p0_1 VALUES LESS THAN (50),
                                    SUBPARTITION p0_2 VALUES LESS THAN (100)
                              ),                           
                              PARTITION p1 VALUES LESS THAN (200) (
                                    SUBPARTITION p1_1 VALUES LESS THAN (150),
                                    SUBPARTITION p1_2 VALUES LESS THAN (200)
                              )
                        );
       Query OK, 0 rows affected
       ```

    2. Query data from the `tbl2` table. At this time, the table is empty.

       ```shell
       obclient [test]> SELECT * FROM tbl2;
       Empty set
       ```

    3. Import the data from the `tbl1.csv` file to the `tbl2` table using direct load.

       * Import data from all columns of the `tbl2` table.

         ```shell
         obclient [test]> LOAD DATA /*+ direct(true,1024,'full') parallel(16) */ INFILE '/home/admin/tbl1.csv' INTO TABLE tbl2 FIELDS TERMINATED BY ',';
         Query OK, 3 rows affected
         Records: 3  Deleted: 0  Skipped: 0  Warnings: 0
         ```

       * Import data from specified columns of the `tbl2` table. For example, import data from the `col1` and `col2` columns.

         ```shell
         obclient [test]> LOAD DATA /*+ direct(true,1024,'full') parallel(16) */ INFILE '/home/admin/tbl1.csv' INTO TABLE tbl2 FIELDS TERMINATED BY ','(col1,col2);
         Query OK, 3 rows affected
         Records: 3  Deleted: 0  Skipped: 0  Warnings: 0
         ```

       * Import data from partitions of the `tbl2` table.

         ```shell
         obclient [test]> LOAD DATA /*+ direct(true,1024,'full') parallel(16) */ INFILE '/home/admin/tbl1.csv' INTO TABLE tbl2 partition(p0, p1)  FIELDS TERMINATED BY ',';
         ```

       * Import data from subpartitions of the `tbl2` table.

         ```shell
         obclient [test]> LOAD DATA /*+ direct(true,1024,'full') parallel(16) */ INFILE '/home/admin/tbl1.csv' INTO TABLE tbl2 partition(p0sp0_1, p1sp1_1)  FIELDS TERMINATED BY ',';
         ```

       * Import data based on the `default_load_mode` parameter.

         1. Set the value of the `default_load_mode` parameter to `FULL_DIRECT_WRITE`.

            ```shell
            obclient [test]> ALTER SYSTEM SET default_load_mode ='FULL_DIRECT_WRITE';
            ```

         2. Execute the `LOAD DATA` statement without hints.

            ```shell
            obclient [test]> LOAD DATA INFILE '/home/admin/tbl1.csv' INTO TABLE tbl2 FIELDS TERMINATED BY ',';
            ```

    4. Query data from the `tbl2` table to verify whether the data has been imported.

       ```shell
       obclient [test]>  SELECT * FROM tbl2;
       ```

       The query result is as follows:

       ```shell
        +------+------+
        | col1 | col2 |
        +------+------+
        |    1 |   11 |
        |    2 |   22 |
        |    3 |   33 |
        +------+------+
        3 rows in set
       ```

       The result shows that data has been imported to the `tbl2` table.

## Import data by using the INSERT INTO SELECT statement

You can use the `INSERT INTO SELECT` statement with the `append/direct()` hint and `enable_parallel_dml` set to true to import data in direct load mode. If the hint is not specified, the import mode is determined based on the [default_load_mode](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2050.default_load_mode.md) parameter.

### Limitations

* Only PDML (Parallel Data Manipulation Language) statements are supported. For more information about PDML, see [Parallel DML](../../700.reference/1000.performance-tuning-guide/500.sql-optimization/300.distributed-execution-plan/1000.parallel-dml.md).
* Two write statements (write to one table) cannot be executed at the same time. The reason is that the table is locked during data import and only read operations are supported.
* Data import statements are considered DDL statements and therefore cannot be executed within a multi-row transaction (a transaction that contains multiple operations).
  * You cannot execute them within a BEGIN block.
  * Autocommit must be set to 1.
* Data import is not supported for tables with triggers (trigger).
* Data import is not supported for tables with generated columns. Some indexes generate hidden generated columns, for example, KEY `idx_c2` (`c2`(16)) GLOBAL).
* Data import is not supported for tables with local flashback queries (flashback query).

### Syntax

```sql
INSERT /*+ [APPEND |DIRECT(need_sort,max_error,'full')] enable_parallel_dml parallel(N) */ INTO  table_name [PARTITION(PARTITION_OPTION)] select_sentence
```

For more information about the `INSERT INTO` statement, see [INSERT (MySQL mode)](../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/5700.insert-sql-of-mysql-mode.md) and [INSERT (Oracle mode)](../../700.reference/500.sql-reference/100.sql-syntax/300.common-tenant-of-oracle-mode/900.sql-statement-of-oracle-mode/200.dml-of-oracle-mode/200.insert-of-oracle-mode.md).

**The parameters are described as follows:**

|Parameter|Description|
|------|------|
| APPEND \| DIRECT()      | Enables direct load by using the hint. <ul><li>If you use the <code>APPEND</code> hint, it is equivalent to the <code>DIRECT(true, 0)</code> hint by default, and online statistics collection (<code>GATHER_OPTIMIZER_STATISTICS</code> hint) is supported. </li><li>The parameters of the <code>DIRECT()</code> hint are described as follows: <ul><li><code>need_sort</code>: indicates whether the data to be written needs to be sorted. The value is of the <code>bool</code> type. <ul><li><code>true</code>: indicates that sorting is required. </li><li><code>false</code>: indicates that sorting is not required.</li></ul></li><li><code>max_error</code>: the maximum number of erroneous rows that the import task can tolerate. The value is of the <code>INT</code> type, and the import task will fail if this number is exceeded. </li><li><code>full</code>: specifies to perform full direct load. It is an optional parameter, and the value must be enclosed in single quotation marks ('').</li></ul></li></ul>|
| enable_parallel_dml | The degree of parallelism of data loading. <main id="notice" type='explain'><h4>Note</h4><p>Generally, the <code>enable_parallel_dml</code> hint must be used in conjunction with the <code>parallel</code> hint to enable parallel DML. However, if the schema of the destination table specifies the table-level parallelism, you only need to specify the <code>enable_parallel_dml</code> hint. </p></main>|
| parallel(N) | The degree of parallelism of data loading. This parameter is mandatory and must be an integer greater than 1. |
| table_name                       | The name of the table to import data to. You can import data to any number of columns in the table.  |
| PARTITION_OPTION                   | The partition name when you enable direct load by partition: <ul><li>partition_option_list: a comma-separated (,) list of partition numbers when you want to import data to multiple partitions. </li> <li>subpartition_option_list: a comma-separated (,) list of subpartition numbers when you want to import data to multiple subpartitions.</li></ul>|

## Import data by using the CREATE TABLE AS SELECT statement

You can add the `DIRECT()` hint to the `CREATE TABLE AS SELECT` statement to specify direct load. If the hint is not specified, the default load mode specified in the [default_load_mode](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2050.default_load_mode.md) parameter determines the data import behavior.

### Syntax

```sql
CREATE /*+ [APPEND | DIRECT(need_sort,max_error,load_type)] parallel(N) */ TABLE table_name [AS] select_sentence
```

For more information about the `CREATE TABLE` statement, see [CREATE TABLE (MySQL mode)](../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2600.create-table-of-mysql-mode.md) and [CREATE TABLE (Oracle mode)](../../700.reference/500.sql-reference/100.sql-syntax/300.common-tenant-of-oracle-mode/900.sql-statement-of-oracle-mode/100.ddl-of-oracle-mode/2400.create-table-of-oracle-mode.md).

**The parameters are described as follows:**

|Parameter|Description|
|------|------|
| APPEND \| DIRECT()      | Enables direct load by using the hint. <ul><li>If you use the <code>APPEND</code> hint, the system considers it to be equivalent to the <code>DIRECT(true, 0)</code> hint. Additionally, the system supports online statistics collection (<code>GATHER_OPTIMIZER_STATISTICS</code> hint) with this hint. </li><li>The parameters of the <code>DIRECT()</code> hint are described as follows: <ul><li><code>need_sort</code>: specifies whether the data to be written needs to be sorted. The parameter value is of the <code>bool</code> type. <ul><li><code>true</code>: specifies that the data needs to be sorted. </li><li><code>false</code>: specifies that the data does not need to be sorted. </li></ul></li><li><code>max_error</code>: the maximum number of tolerated error rows. The parameter value is of the <code>INT</code> type. If the number of error rows exceeds this value, the direct load task fails. </li><li><code>full</code>: specifies to perform full direct load. It is an optional parameter and must be enclosed in single quotation marks. </li></ul></li></ul>|
| parallel(N) | The degree of parallelism of data loading. It is a required parameter and must be an integer greater than 1. |

### Examples

