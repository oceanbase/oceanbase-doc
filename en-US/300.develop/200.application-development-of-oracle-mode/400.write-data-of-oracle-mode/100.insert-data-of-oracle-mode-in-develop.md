# Insert data

After a table is created, you can execute the `INSERT` statement or other statements to insert rows into the table. This topic explains how to use these statements.

## Prepare to insert data

Before you insert data, make sure that the following conditions are met:

* You have connected to an Oracle tenant of the database. For more information, see [Overview of connection methods](../100.connect-to-oceanbase-database-of-oracle-mode/100.connection-methods-overview-of-oracle-mode.md).

  <main id="notice" type='explain'>
   <h4>Note</h4>
   <p>The tenant mode to which the logged-in user belongs can be queried from the <code>oceanbase.DBA_OB_TENANTS</code> view by the <code>sys</code> tenant.  </p>
  </main>

* You have the `INSERT` privilege on the target table. For more information, see [Check your user privileges](../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/300.permission-of-oracle-mode/600.view-user-permissions-of-oracle-mode.md). If you do not have this privilege, contact the administrator to request the privilege. For more information, see [Grant privileges](../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/300.permission-of-oracle-mode/200.authority-of-oracle-mode.md).

## Insert data by using the INSERT INTO statement

You can execute the [INSERT](../../../700.reference/500.sql-reference/100.sql-syntax/300.common-tenant-of-oracle-mode/900.sql-statement-of-oracle-mode/200.dml-of-oracle-mode/200.insert-of-oracle-mode.md) statement and follow the suggestions below to insert data into a table.

The syntax of the `INSERT INTO` statement is as follows:

```sql
INSERT INTO table_name [(list_of_columns)] VALUES (list_of_values);
```

|        Parameter        | Whether required | Description            |
|-------------------|----------|-----------------------------------------------|
| table_name        | Yes       | The name of the target table.             |
| (list_of_columns) | No       | The names of the columns where you want to insert data.         |
| (list_of_values)  | Yes       | The values to be inserted into the columns specified in the list_of_columns parameter. The values must be in one-to-one correspondence with the columns. |

### Suggestions on inserting data

* Before you insert data, learn about all columns in the table, including the column types, valid values, and NULLability.

  You can execute the `DESC` statement to view column information.

  ```shell
  obclient [SYS]> DESC ordr;
  +-------+--------------+------+-----+---------+-------+
  | FIELD | TYPE         | NULL | KEY | DEFAULT | EXTRA |
  +-------+--------------+------+-----+---------+-------+
  | C1    | NUMBER       | YES  | NULL | NULL    | NULL  |
  | C2    | VARCHAR2(50) | YES  | NULL | NULL    | NULL  |
  +-------+--------------+------+-----+---------+-------+
  2 rows in set
  ```

  * If the column attribute is `NOT NULL`

    * If the column attribute has a default value, you can omit the column value in the INSERT statement. The system will insert the default value into the column.

    * If the column attribute does not have a default value, you must specify a value for the column in the INSERT statement.

  * If the column attribute is `NULL`, you can omit the column value in the INSERT statement. The system will insert a `NULL` value into the column.

* Before you insert data, learn about the constraints defined on the columns to avoid errors during the insertion.

  You can execute the `DESC` statement to view the `NOT NULL`, `PRIMARY KEY`, and `UNIQUE` constraints, and query the `ALL_CONSTRAINTS`, `DBA_CONSTRAINTS`, or `USER_CONSTRAINTS` view for the `FOREIGN KEY` and `CHECK` constraints.

### Insert a single row of data

You can execute the `INSERT` statement to insert a single row of data. To insert multiple records, you can execute multiple `INSERT` statements or use a single `INSERT` statement that contains multiple `VALUES` clauses. Batch insertion is faster than individual insertion.

Assume that the table to which you want to insert data has the following information:

```shell
obclient [SYS]> CREATE TABLE t_insert(
    id number NOT NULL PRIMARY KEY,
    name varchar(10) NOT NULL, 
    value number,
    gmt_create DATE NOT NULL DEFAULT sysdate
 );
Query OK, 0 rows affected 
```

In this table, the `id` and `name` columns cannot be empty. The `id` column is the primary key column and therefore must meet the uniqueness requirement. It cannot have duplicate values. The `gmt_create` column has a default value.

Example 1: Insert multiple rows of data by using multiple `INSERT` statements.

Since the `gmt_create` column has a default value, you can ignore the default value in the `INSERT` statement.

```shell
obclient [SYS]> INSERT INTO t_insert(id, name, value) 
VALUES (1,'CN',10001);
Query OK, 2 rows affected

obclient [SYS]> INSERT INTO t_insert(id, name, value) 
VALUES(2,'US', 10002);
Query OK, 2 rows affected
```

Notice that if the `gmt_create` column does not have a default value, you must specify a value in the `INSERT` statement. The sample statement is as follows.

```shell
obclient [SYS]> INSERT INTO t_insert(id, name, value, gmt_create)
 VALUES (3,'EN', 10003, sysdate);
Query OK, 1 row affected 
```

### Insert multiple rows of data at a time

When you insert data, you can use a single `INSERT` statement that contains multiple `VALUES` clauses to insert multiple rows of data at a time. Multiple rows of data inserted by using a single `INSERT` statement are faster than multiple rows of data inserted by using multiple `INSERT` statements.

You can perform the same operation as in Example 1 by using the following statement.

Example 2: Insert multiple rows of data at a time.

```shell
obclient [SYS]> INSERT INTO t_insert(id, name, value) 
  VALUES (1,'CN',10001),(2,'US', 10002);
Query OK, 2 rows affected
```

Additionally, you can use a backup statement `INSERT INTO ... SELECT ... FROM` to batch insert data. This statement is similar to the `INSERT` statement, except that the `values` clause in the backup statement is replaced with a `SELECT` clause.

Example 3: Back up all data from the `t_insert` table to the `t_insert_bak` table.

```shell
obclient [SYS]> SELECT * FROM t_insert;
+----+------+-------+------------+
| ID | NAME | VALUE | GMT_CREATE |
+----+------+-------+------------+
|  1 | CN   | 10001 | 31-OCT-22  |
|  2 | US   | 10002 | 31-OCT-22  |
|  3 | EN   | 10003 | 31-OCT-22  |
+----+------+-------+------------+
3 rows in set

obclient [SYS]> CREATE TABLE t_insert_bak(
    id number NOT NULL PRIMARY KEY,
    name varchar(10) NOT NULL, 
    value number,
    gmt_create DATE NOT NULL DEFAULT sysdate
 );
Query OK, 0 rows affected 

obclient [SYS]> INSERT INTO t_insert_bak SELECT * FROM t_insert;
Query OK, 2 rows affected
Records: 3  Duplicates: 0  Warnings: 0

obclient [SYS]> SELECT * FROM t_insert_bak;
+----+------+-------+------------+
| ID | NAME | VALUE | GMT_CREATE |
+----+------+-------+------------+
|  1 | CN   | 10001 | 31-OCT-22  |
|  2 | US   | 10002 | 31-OCT-22  |
|  3 | EN   | 10003 | 31-OCT-22  |
+----+------+-------+------------+
3 rows in set
```

## Execute the INSERT OVERWRITE SELECT statement to insert data

The `INSERT OVERWRITE SELECT` statement is used to replace the existing data in a table with the query result. In other words, the data returned by the query is written to the destination table to overwrite the existing data. This operation is atomic. Any exception during execution will lead to rollback of the operation.

The syntax is as follows:

```sql
INSERT [/*+PARALLEL(N)*/] OVERWRITE table_name [(list_of_columns)] [PARTITION (partition_name, ...)] select_stmt;
```

|    Parameter      |      Description       |
|-------------|-----------------|
| PARALLEL(N) | Specifies the degree of parallelism of the overwrite operation. If it is not specified, the default value 2 is used. |
| table_name  | The name of the destination table. |
| list_of_columns   | The columns where data is to be inserted.                     |
| select_stmt | The `SELECT` clause. For more information about queries, see [SIMPLE SELECT](../../../700.reference/500.sql-reference/100.sql-syntax/300.common-tenant-of-oracle-mode/900.sql-statement-of-oracle-mode/200.dml-of-oracle-mode/500.select-of-oracle-mode/100.simple-select-of-oracle-mode.md). |
| partition_name          | The name of the partition into which data is to be inserted. Multiple partition names are separated with commas (,).      |

### Limitations on INSERT OVERWRITE SELECT

#### Limitations on table-level INSERT OVERWRITE SELECT

* This statement cannot be used in a multi-row transaction. Therefore, to ensure smooth execution, you must run the `SET autocommit = on;` statement to enable auto-commit before you execute this statement.
* A table lock is placed on the destination table during data write. This prevents concurrent DDL operations on the same table. Concurrent DML operations are queued and will wait for the table lock to be released until a timeout occurs. Queries are allowed during this period.
* The number of columns being overwritten must exactly match the number of columns being written to in the destination table. Otherwise, an error will occur.
* The data write operation in this statement is full direct load. Therefore, it is subject to the full direct load feature limitations. For more information, see the **Limitations** section in [Import data by using the INSERT INTO SELECT statement](../../../500.data-migration/1100.bypass-import/200.full-bypass-import.md).
* An error occurs when the direct load hint is specified.
* PDML (Parallel Data Manipulation Language, parallel DML) is limited to partitions and subpartitions that support PDML. Otherwise, an error not supported will occur. For more information, see [Parallel DML](../../../700.reference/1000.performance-tuning-guide/500.sql-optimization/300.distributed-execution-plan/1000.parallel-dml.md).

#### Limitations on partition-level INSERT OVERWRITE SELECT

**Overview**

* The source table can be a partitioned or non-partitioned table.
* The destination table can be partitioned or subpartitioned.
* The destination table can have a local index or a large object LOB.
* You can specify all or some partitions of the destination table. For subpartitioned tables, you can specify subpartitions alone, partitions alone, or a combination of partitions and subpartitions.
* If the data from the source table does not fall into the specified partitions of the destination table after being processed based on the partitioning rule of the destination table, an error occurs, indicating that the specified partition does not exist.
* If a specified partition of the destination table does not fall into any data from the source table, the data in the partition will be cleared (overwritten with null data).
* In OceanBase Database V4.3.5 BP1 and later, you can specify HASH or KEY partitioned subpartitions as the destination for partition-level `insert overwrite` operations.

**Limitations**

* The specified partitions must exist. Otherwise, an error will occur.
* Full direct load is used, so you do not need to add the `/*+ append */` hint. Otherwise, an error will occur.
* This statement cannot be used in a multi-row transaction. Therefore, you must run the `SET autocommit = on;` statement to enable auto-commit before you execute this statement.
* The destination table cannot have an identity column.
* The destination table cannot have a global index or a foreign key.
* The destination table cannot be an external table.

### INSERT OVERWRITE SELECT examples

#### Example 1

1. Execute the following SQL statement to enable auto-commit transactions.

    ```sql
    SET autocommit = on;
    ```

2. Create two test tables: `source_tbl1` as the source table, and `target_tbl1` as the target table.

    ```sql
    CREATE TABLE source_tbl1 (col1 INT, col2 VARCHAR2(20), col3 INT);
    ```

    ```sql
    CREATE TABLE target_tbl1 (col1 INT, col2 VARCHAR2(20), col3 INT);
    ```

3. Insert sample data into the `source_tbl1` table.

    ```sql
    INSERT INTO source_tbl1 VALUES (1, 'A1', 30),(2, 'B2', 25),(3, 'C3', 22);
    ```

4. Insert sample data into the `target_tbl1` table.

    ```sql
    INSERT INTO target_tbl1 VALUES (4, 'D4', 35),(5, 'E5', 28);
    ```

5. Query data from the `target_tbl1` table.

    ```sql
    SELECT * FROM target_tbl1;
    ```

    The return result is as follows:

    ```shell
    +------+------+------+
    | COL1 | COL2 | COL3 |
    +------+------+------+
    |    4 | D4   |   35 |
    |    5 | E5   |   28 |
    +------+------+------+
    2 rows in set
    ```

6. Use the `INSERT OVERWRITE SELECT` statement to filter data with `col3` greater than 25 from the `source_tbl1` table and insert the filtered data into the `target_tbl1` table to replace the original data in the table.

    ```sql
    INSERT OVERWRITE target_tbl1 SELECT * FROM source_tbl1 WHERE col3 > 25;
    ```

7. Query the data in the `target_tbl1` table after the data is replaced.

    ```sql
    SELECT * FROM target_tbl1;
    ```

    The return result is as follows:

    ```shell
    +------+------+------+
    | COL1 | COL2 | COL3 |
    +------+------+------+
    |    1 | A1   |   30 |
    +------+------+------+
    1 row in set
    ```

#### Example 2

Observe the following partition-level `INSTER OVERWRITE PARTITION` example:

1. Execute the following SQL statement to enable auto-commit transactions.

    ```sql
    obclient [SYS]> SET autocommit = on;
    ```

2. Execute the following SQL statement to create a partitioned table named `t1_ins_overwrt`.

    ```sql
    obclient [SYS]> create table t1_ins_overwrt (c1 int primary key, c2 int) partition by range(c1)(
           partition p0 values less than(10),
           partition p1 values less than(20),
           partition p2 values less than(30),
           partition p3 values less than (MAXVALUE)
         );
    Query OK, 0 rows affected (0.223 sec)
    ```

3. Execute the following SQL statement to create a partitioned table named `t2_ins_overwrt`.

    ```sql
    obclient [SYS]> create table t2_ins_overwrt (c1 int primary key, c2 int) partition by range(c1)(
           partition p0 values less than(10),
           partition p1 values less than(20),
           partition p2 values less than(30),
           partition p3 values less than (MAXVALUE)
         );
    Query OK, 0 rows affected (0.092 sec)
    ```

4. Insert several records into the two tables.

    ```sql
    obclient [SYS]> insert into t1_ins_overwrt values (12, 20), (34, 40), (45, 50);
    Query OK, 3 rows affected (0.002 sec)
    Records: 3  Duplicates: 0  Warnings: 0

    obclient [SYS]> insert into t2_ins_overwrt values (3, 60), (8, 80), (17, 170), (26, 260), (29, 290), (142, 1420);
    Query OK, 6 rows affected (0.003 sec)
    Records: 6  Duplicates: 0  Warnings: 0
    ```

5. Query the data in the p1 partition of the two tables.

    ```sql
    obclient [SYS]> select * from t1_ins_overwrt partition(p1);
    +------+------+
    | C1   | C2   |
    +------+------+
    |   12 |   20 |
    +------+------+
    1 row in set (0.006 sec)

    obclient [SYS]> select * from t2_ins_overwrt partition(p1);
    +------+------+
    | C1   | C2   |
    +------+------+
    |   17 |  170 |
    +------+------+
    1 row in set (0.007 sec)
    ```

6. Execute the following SQL statement to insert the data in the p1 partition of the `t1_ins_overwrt` table into the p1 partition of the `t2_ins_overwrt` table.

    ```sql
    obclient [SYS]> insert overwrite t2_ins_overwrt partition(p1) select * from t1_ins_overwrt partition(p1);
    Query OK, 3 rows affected (1.360 sec)
    Records: 3  Duplicates: 0  Warnings: 0
    ```

7. Query the `t2_ins_overwrt` table. The data in the p1 partition is covered.

    ```sql
    obclient [SYS]> SELECT * FROM t2_ins_overwrt partition(p1);
    +------+------+
    | C1   | C2   |
    +------+------+
    |   12 |   20 |
    +------+------+
    1 row in set (0.020 sec)
    ```

#### Example 3

1. Create a table named `tbl1` with partitions.

   ```shell
   obclient [SYS]> CREATE TABLE tbl1 (
    col1 INT,
    col2 INT
    )
    PARTITION BY RANGE (col1)
    SUBPARTITION BY HASH (col2)
    SUBPARTITIONS 3
    (
        PARTITION p0 VALUES LESS THAN (10),
        PARTITION p1 VALUES LESS THAN (20)
    );
    Query OK, 0 rows affected (0.093 sec)
   ```

2. Insert two records into the `tbl1` table.

   ```shell
   obclient [SYS]>  INSERT INTO tbl1 (col1, col2) VALUES (2, 3);
                    INSERT INTO tbl1 (col1, col2) VALUES (15, 2);
   ```

3. Query whether data has been inserted into the `p0` and `p1` partitions of the `tbl1` table.

   ```shell
   obclient [SYS]> SELECT * FROM tbl1 PARTITION (p0);
   ```

    The query result is as follows:

   ```shell
   +------+------+
   | col1 | col2 |
   +------+------+
   |    2 |    3 |
   +------+------+
   ```

   ```shell
   obclient [SYS]> SELECT * FROM tbl1 PARTITION (p1);
   ```

    The query result is as follows:

   ```shell
    +------+------+
    | col1 | col2 |
    +------+------+
    |   15 |    2 |
    +------+------+
   ```

4. Create a table named `tbl2` with partitions.

   ```shell
   obclient [SYS]> CREATE TABLE tbl2 (
    col1 INT,
    col2 INT
    )
    PARTITION BY RANGE (col1)
    SUBPARTITION BY HASH (col2)
    SUBPARTITIONS 3
    (
        PARTITION p0 VALUES LESS THAN (10),
        PARTITION p1 VALUES LESS THAN (20)
    );
   ```

5. Insert two records into the `tbl2` table.

   ```shell
   obclient [SYS]> INSERT INTO tbl2 (col1, col2) VALUES (0, 22);
                   INSERT INTO tbl2 (col1, col2) VALUES (18, 6);
   ```

6. Query whether data has been inserted into the `p0` and `p1` partitions of the `tbl2` table.

   ```shell
   obclient [SYS]> SELECT * FROM tbl2 PARTITION (p0);
   ```

    The query result is as follows:

   ```shell
    +------+------+
    | COL1 | COL2 |
    +------+------+
    |    0 |   22 |
    +------+------+
   ```

   ```shell
   obclient [SYS]> SELECT * FROM tbl2 PARTITION (p1);
   ```

    The query result is as follows:

   ```shell
    +------+------+
    | COL1 | COL2 |
    +------+------+
    |   18 |   6 |
    +------+------+
   ```

7. Use the `insert overwrite` statement to overwrite the data in the `p1` partition of the `tbl1` table with the data in the `tbl2` table.

   ```shell
   obclient [SYS]> INSERT INTO tbl2 PARTITION (p1) SELECT * FROM tbl1 PARTITION (p1);
   ```

8. Verify whether the data in the `p1` partition of the `tbl2` table has been overwritten.

   ```shell
   obclient [SYS]> SELECT * FROM tbl2 PARTITION (p1);
   ```

   The query result is as follows:

   ```shell
    +------+------+
    | col1 | col2 |
    +------+------+
    |   15 |    2 |
    +------+------+
   ```

   The result shows that the data in the `p1` partition of the `tbl2` table has been replaced.

## Insert data by using the MERGE INTO statement

In a batch processing task, you may need to perform a large number of `INSERT` operations on a target table. You can also use the `MERGE INTO` statement to insert records from a source table to a target table when the records to be inserted do not exist in the table. For more information, see [Replace data](../400.write-data-of-oracle-mode/400.replace-data-of-oracle-mode-in-develop.md).

<main id="notice" type='explain'>
  <h4>Note</h4>
  <p> When you use the <code>INSERT</code> statement to insert data and the table has a unique constraint, the system returns an error if you attempt to insert the same record. In this case, you can use the <code>MERGE INTO</code> statement to update table records to avoid unique constraint conflicts. </p>
</main>

## Insert data into a remote table by using a DBLink

OceanBase Database allows you to write data to OceanBase Database (in Oracle mode) and Oracle Database by using a DBLink.

For example, you can execute the following statement to insert a row `(11,11)` into a table named `t1` in a remote database:

```shell
obclient> SELECT * FROM t1@ob_dblink;
+------+------+
| C1   | C2   |
+------+------+
|    1 |    1 |
+------+------+
1 row in set

obclient> INSERT INTO t1@ob_dblink VALUES (11,11);
Query OK, 1 row affected

obclient> commit;
Query OK, 0 rows affected

obclient> SELECT * FROM t1@ob_dblink;
+------+------+
| C1   | C2   |
+------+------+
|    1 |    1 |
|   11 |   11 |
+------+------+
2 rows in set
```

In Oracle mode, OceanBase Database also supports writing data from a local table to a remote table through a DBLink by using the `INSERT`, `DELETE`, `UPDATE`, and `MERGE INTO` statements. For more information, see [Modify data in a remote Oracle database by using a DBLink](../../../700.reference/300.database-object-management/200.manage-object-of-oracle-mode/1000.manage-dblink-of-oracle-mode/400.update-data-in-remote-database-by-a-dblink-of-oracle-mode.md).
