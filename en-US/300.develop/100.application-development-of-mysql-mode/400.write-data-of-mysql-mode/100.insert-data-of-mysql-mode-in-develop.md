# Insert data

After a table is created, you can execute the `INSERT` statement or other statements to insert rows into the table. This topic explains how to use these statements.

## Prepare to insert data

Before you insert data, make sure that the following conditions are met:

* You have connected to a MySQL tenant of the database. For more information, see [Overview of connection methods](../100.connect-to-oceanbase-database-of-mysql-mode/100.connection-methods-overview-of-mysql-mode.md).

  <main id="notice" type='explain'>
   <h4>Note</h4>
   <p>The tenant mode to which the logged-in user belongs can be queried from the <code>oceanbase.DBA_OB_TENANTS</code> view in the <code>sys</code> tenant.  </p>
  </main>

* You have the `INSERT` privilege on the target table. For more information, see [Check your user privileges](../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/400.view-user-permissions-of-mysql-mode.md). If you do not have this privilege, contact the administrator to request the privilege. For more information, see [Grant privileges to a user](../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/200.authority-of-mysql-mode.md).

## Insert data by using the INSERT INTO statement

Execute the [INSERT](../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/5700.insert-sql-of-mysql-mode.md) statement and follow the suggestions below to insert data into a table.

The syntax of the `INSERT INTO` statement is as follows:

```sql
INSERT INTO table_name [(list_of_columns)] VALUES (list_of_values);
```

|        Parameter         | Required |                Description                |
|-------------------------|---------|------------------------------------|
| table_name          | Yes   | The name of the table where you want to insert data. |
| (list_of_columns)   | No    | The columns where you want to insert data.          |
| (list_of_values)    | Yes   | The values to be inserted, which must correspond one-to-one with the columns listed in list_of_columns. |

### Suggestions on inserting data

* Before you insert data, learn about all columns in the table, including their data types, effective values, and nullability.

  You can execute the `DESC` statement to view column information.

  ```sql
  obclient [test]> DESC test;
  +-------+---------+------+-----+---------+-------+
  | Field | Type    | Null | Key | Default | Extra |
  +-------+---------+------+-----+---------+-------+
  | col1  | int(11) | NO   |     | NULL    |       |
  | col2  | int(11) | YES  |     | NULL    |       |
  +-------+---------+------+-----+---------+-------+
  2 rows in set
  ```

  * If a column attribute is `NOT NULL`

    * If the column attribute has a default value, you can omit the column value in the insert statement. The system automatically inserts the default value into the column.

    * If the column attribute does not have a default value, you must specify a value for the column in the insert statement.

  * If a column attribute is `NULL`, you can omit the column value in the insert statement. The system automatically inserts a `NULL` value into the column.

* Before you insert data, learn about the constraints defined on columns to avoid errors during the insertion.

  You can execute the `DESC` statement to view the `NOT NULL`, `PRIMARY KEY`, and `UNIQUE` constraints, and query the `information_schema.TABLE_CONSTRAINTS` view for the `FOREIGN KEY` and `CHECK` constraints.

### Insert a single row of data

You can execute the `INSERT` statement to insert a single row of data. To insert multiple records, you can execute multiple `INSERT` statements or use a single statement with multiple `VALUES` clauses. For more information, see [Batch insert multiple rows of data](#Batch insert multiple rows of data).

Assume that the table to insert data into is as follows:

```sql
obclient [test]> CREATE TABLE t_insert(
    id int NOT NULL PRIMARY KEY,
    name varchar(10) NOT NULL, 
    value int,
    gmt_create DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
 );
Query OK, 0 rows affected 
```

In this table, the `id` and `name` columns cannot be null. The `id` column is the primary key column and therefore cannot contain duplicate values. The `gmt_create` column has a default value.

Example 1: Insert multiple rows of data using multiple single-row insertion statements.

As the `gmt_create` column has a default value, you can omit it in the insertion statement.

```sql
obclient [test]> INSERT INTO t_insert(id, name, value) 
VALUES (1,'CN',10001);
Query OK, 2 rows affected

obclient [test]> INSERT INTO t_insert(id, name, value) 
VALUES(2,'US', 10002);
Query OK, 2 rows affected
```

Notice that if the `gmt_create` column does not have a default value, you must specify a value for this column in the insertion statement. The sample statement is as follows.

```sql
obclient [test]> INSERT INTO t_insert(id, name, value, gmt_create)
 VALUES (3,'EN', 10003, current_timestamp ());
Query OK, 1 row affected 
```

### Insert multiple rows of data at a time

You can use a single `INSERT` statement with multiple `VALUES` clauses to insert multiple rows of data at a time. Batch insertion is faster than individual insertions.

You can also complete the operation shown in Example 1 by using the following statement.

Example 2: Insert multiple rows of data at a time.

```sql
obclient [test]> INSERT INTO t_insert(id, name, value) 
  VALUES (1,'CN',10001),(2,'US', 10002);
Query OK, 2 rows affected
```

Additionally, you can use a backup statement `INSERT INTO ... SELECT ... FROM` to back up data in a table or copy all records from one table to another.

Example 3: Back up all data from the `t_insert` table to the `t_insert_bak` table.

```sql
obclient [test]> SELECT * FROM t_insert;
+----+------+-------+---------------------+
| id | name | value | gmt_create          |
+----+------+-------+---------------------+
|  1 | CN   | 10001 | 2022-10-12 15:17:17 |
|  2 | US   | 10002 | 2022-10-12 16:29:16 |
|  3 | EN   | 10003 | 2022-10-12 16:29:26 |
+----+------+-------+---------------------+
3 rows in set

obclient [test]> CREATE TABLE t_insert_bak(
    id number NOT NULL PRIMARY KEY,
    name varchar(10) NOT NULL, 
    value number,
    gmt_create DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
 );
Query OK, 0 rows affected 

obclient [test]> INSERT INTO t_insert_bak SELECT * FROM t_insert;
Query OK, 2 rows affected

obclient [test]> SELECT * FROM t_insert_bak;
+----+------+-------+---------------------+
| id | name | value | gmt_create          |
+----+------+-------+---------------------+
|  1 | CN   | 10001 | 2022-10-12 15:17:17 |
|  2 | US   | 10002 | 2022-10-12 16:29:16 |
|  3 | EN   | 10003 | 2022-10-12 16:29:26 |
+----+------+-------+---------------------+
3 rows in set
```

### Avoid unique constraint conflicts

When a table has a unique constraint, the database returns an error if you attempt to insert the same record twice. The error code is as follows:

```sql
obclient [test]> INSERT INTO t_insert(id, name, value) VALUES (3,'UK', 10003),(4, 'JP', 10004);
ERROR 1062 (23000): Duplicate entry '3' for key 'PRIMARY'
```

You can use the `INSERT IGNORE INTO` statement or the `INSERT INTO ON DUPLICATE KEY UPDATE` statement to avoid this error.

Here are some examples:

* When you use the `INSERT IGNORE INTO` statement to avoid a unique constraint conflict, the `IGNORE` keyword allows you to ignore the `INSERT` failures caused by unique constraint conflicts.

  ```sql
  obclient [test]> INSERT IGNORE INTO t_insert(id, name, value) 
      VALUES (3,'UK', 10003),(4, 'JP', 10004);
  Query OK, 1 row affected 
  
  obclient [test]> SELECT * FROM t_insert;
  +----+------+-------+---------------------+
  | id | name | value | gmt_create          |
  +----+------+-------+---------------------+
  |  1 | CN   | 10001 | 2022-10-12 15:17:17 |
  |  2 | US   | 10002 | 2022-10-12 16:29:16 |
  |  3 | EN   | 10003 | 2022-10-12 16:29:26 |
  |  4 | JP   | 10004 | 2022-10-12 17:02:52 |
  +----+------+-------+---------------------+
  4 rows in set
  ```

  In this example, the `(3,'UK', 10003)` row fails to be inserted due to a unique constraint conflict, but no error is returned.

* When you use the `INSERT INTO ON DUPLICATE KEY UPDATE` statement to avoid a unique constraint conflict, you can specify how to handle duplicate primary keys or unique keys.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p><ul><li>If you specify  <code>ON DUPLICATE KEY UPDATE column_name = expr </code>, when a duplicate primary key or unique key is found, the system updates the data of the conflicting row based on the assignment statement <code>column_name = expr </code>. You can assign a value to one or more columns of the conflicting row with the <code>column_name = expr </code> statement. When you assign values to multiple columns, separate the columns with commas. </li><li>If you do not specify  <code>ON DUPLICATE KEY UPDATE column_name = expr </code>, an error occurs when a duplicate primary key or unique key is found during the insertion of data. </li></ul></p>
  </main>

  ```sql
  obclient [test]> INSERT INTO t_insert(id, name, value) VALUES (3,'UK', 10003),(5, 'CN', 10005) ON DUPLICATE KEY UPDATE name = VALUES(name);
  Query OK, 1 row affected 

  obclient [test]> SELECT * FROM t_insert;
  +----+------+-------+---------------------+
  | id | name | value | gmt_create          |
  +----+------+-------+---------------------+
  |  1 | CN   | 10001 | 2022-10-12 16:29:16 |
  |  2 | US   | 10002 | 2022-10-12 15:17:17 |
  |  3 | UK   | 10003 | 2022-10-12 16:29:26 |
  |  4 | JP   | 10004 | 2022-10-12 17:02:52 |
  |  5 | CN   | 10005 | 2022-10-12 17:27:46 |
  +----+------+-------+---------------------+
  5 rows in set
  ```

  In this example, `ON DUPLICATE KEY UPDATE name = VALUES(name)` means that when a duplicate primary key conflict occurs, the system updates the `name` column of the conflicting row based on the value of the `name` column of the new record. The `(3,'EN', 10003)` row is the conflicting row, and its `name` column value is updated from 'EN' to 'EN2'. Other non-conflicting rows are normally inserted.

## Use the INSERT OVERWRITE SELECT statement to insert data

The `INSERT OVERWRITE SELECT` statement is used to replace the existing data in a table or partition with the query result, that is, to overwrite the data in the target table or partition with the query result.

The syntax is as follows:

```sql
INSERT [/*+PARALLEL(N)*/] OVERWRITE table_name [(list_of_columns)] [PARTITION (partition_name, ...)] select_stmt;
```

|    Parameter      |      Description       |
|-------------|-----------------|
| PARALLEL(N) | Specifies the level of parallelism for the overwrite operation. If you do not specify this parameter, the default value of 2 is used. |
| table_name  | The name of the destination table where you want to insert data. |
| list_of_columns  | The list of destination columns where you want to insert data. |
| select_stmt | The `SELECT` clause. For more information about queries, see [SELECT statement](../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/8100.select-of-mysql-mode/100.select-of-mysql-mode.md). |
| partition_name          | The name of the destination partition where you want to insert data. If you want to insert data into multiple partitions, separate the partition names with commas (,).      |

### Limitations on INSERT OVERWRITE SELECT

#### Limitations on table-level INSERT OVERWRITE SELECT

* This statement cannot be used in a multi-row transaction. Therefore, before you execute this statement, make sure that the `autocommit` parameter is set to `on` to ensure the successful execution of the statement.
* A table lock is placed on the destination table during the data write operation. This prevents concurrent DDL operations on the same table. Concurrent DML operations are queued and will wait for the table lock to be released until the operations time out. Queries are allowed during the operation.
* The number of columns being overwritten must exactly match the number of columns in the destination table or the number of columns being written by the `INSERT OVERWRITE SELECT` statement. Otherwise, an error will occur.
* The data write operation in this statement is full direct load. Therefore, the limitations for full direct load apply to this statement. For more information, see the **Limitations** section in [Import data in full direct load mode by using the INSERT INTO SELECT statement](../../../500.data-migration/1100.bypass-import/200.full-bypass-import.md).
* This statement does not support the direct load hint. If the hint is specified, an error will occur.
* Due to the Parallel Data Manipulation Language (PDML) framework, if PDML is not supported for a specific scenario, data cannot be imported for the scenario, and the `INSERT OVERWRITE SELECT` statement returns an error not supported. For more information about parallel DML, see [Parallel DML](../../../700.reference/1000.performance-tuning-guide/500.sql-optimization/300.distributed-execution-plan/1000.parallel-dml.md).

#### Limitations on partition-level INSERT OVERWRITE SELECT

**Overview**

* The source table can be a partitioned or non-partitioned table, and the partitioning type of the source table does not matter.
* The destination table can be a partitioned or subpartitioned table.
* The destination table can have a local index or a large object LOB.
* You can specify the destination table's partitions or subpartitions, or both. If subpartitions are specified, you can specify them alone or in combination with partitions.
* If a specified destination partition does not contain any data from the source table, the data in the partition will be cleared (overwritten with null data).
* In OceanBase Database V4.3.5 BP1 and later, you can specify the hash or key partitioned subpartitioned destination table for the `insert overwrite` operation.

**Limitations**

* The specified partitions must exist. Otherwise, an error will occur.
* Since full direct load is used, you do not need to specify the `/*+ append */` hint. If you specify the hint, an error will occur.
* This statement cannot be used in a multi-row transaction. Therefore, before you execute this statement, make sure that the `autocommit` parameter is set to `on` to ensure the successful execution of the statement.
* After the data from the source table is processed according to the partitioning rule of the destination table, if the data does not fall into the specified destination partitions, an error is returned that the partition does not exist.
* The destination table cannot have an auto-increment column.
* The destination table cannot have a global index or a foreign key.
* The destination table cannot be an external table.

### INSERT OVERWRITE SELECT examples

#### Example 1

1. Create two test tables: `source_tbl1` as the source table and `target_tbl1` as the target table.

    ```sql
    CREATE TABLE source_tbl1 (col1 INT, col2 VARCHAR(20), col3 INT);
    ```

    ```sql
    CREATE TABLE target_tbl1 (col1 INT, col2 VARCHAR(20), col3 INT);
    ```

2. Insert sample data into the `source_tbl1` table.

    ```sql
    INSERT INTO source_tbl1 VALUES (1, 'A1', 30),(2, 'B2', 25),(3, 'C3', 22);
    ```

3. Insert sample data into the `target_tbl1` table.

    ```sql
    INSERT INTO target_tbl1 VALUES (4, 'D4', 35),(5, 'E5', 28);
    ```

4. Query data from the `target_tbl1` table.

    ```sql
    SELECT * FROM target_tbl1;
    ```

    The return result is as follows:

    ```shell
    +------+------+------+
    | col1 | col2 | col3 |
    +------+------+------+
    |    4 | D4   |   35 |
    |    5 | E5   |   28 |
    +------+------+------+
    2 rows in set
    ```

5. Use the `INSERT OVERWRITE SELECT` statement to filter data where `col3` is greater than 25 from the `source_tbl1` table and insert the filtered data into the `target_tbl1` table to replace the original data.

    ```sql
    INSERT OVERWRITE target_tbl1 SELECT * FROM source_tbl1 WHERE col3 > 25;
    ```

6. Query data from the `target_tbl1` table after the data is replaced.

    ```sql
    SELECT * FROM target_tbl1;
    ```

    The return result is as follows:

    ```shell
    +------+------+------+
    | col1 | col2 | col3 |
    +------+------+------+
    |    1 | A1   |   30 |
    +------+------+------+
    1 row in set
    ```

#### Example 2

The `INSERT OVERWRITE PARTITION SELECT` statement is used to insert data from one partitioned table to another partitioned table.

1. Create a partitioned table named `t1_ins_overwrt`.

    ```sql
    obclient> CREATE TABLE t1_ins_overwrt (c1 int primary key, c2 int) partition by range(c1)(
      partition p0 values less than(10),
      partition p1 values less than(20),
      partition p2 values less than(30),
      partition p3 values less than (MAXVALUE)
    );
    Query OK, 1 row affected
    ```

2. Create a partitioned table named `t2_ins_overwrt`.

    ```sql
    obclient> CREATE TABLE t2_ins_overwrt (c1 int primary key, c2 int) partition by range(c1)(
      partition p0 values less than(10),
      partition p1 values less than(20),
      partition p2 values less than(30),
      partition p3 values less than (MAXVALUE)
    );
    Query OK, 1 row affected
    ```

3. Insert several records into the two tables.

    ```sql
    obclient> INSERT INTO t1_ins_overwrt values (1, 10), (12, 20), (23, 30), (34, 40), (45, 50);
    Query OK, 5 rows affected (0.018 sec)
    Records: 5  Duplicates: 0  Warnings: 0

    obclient> INSERT INTO t2_ins_overwrt values (3, 60), (8, 80), (17, 170), (26, 260), (29, 290), (142, 1420);
    Query OK, 6 rows affected (0.015 sec)
    Records: 6  Duplicates: 0  Warnings: 0
    ```

4. Query the data in the p3 partition from the two tables.

    ```sql
    obclient> SELECT * FROM t1_ins_overwrt partition(p3);
    +------+------+
    | c1   | c2   |
    +------+------+
    |   34 |   40 |
    |   45 |   50 |
    +------+------+
    2 rows in set (0.006 sec)

    obclient> SELECT * FROM t2_ins_overwrt partition(p3);
    +------+------+
    | c1   | c2   |
    +------+------+
    |  142 | 1420 |
    +------+------+
    1 row in set (0.006 sec)
    ```

5. Execute the following SQL statement to insert the data in the p3 partition of the `t1_ins_overwrt` table into the p3 partition of the `t2_ins_overwrt` table.

    ```sql
    obclient> INSERT OVERWRITE t2_ins_overwrt partition(p3) select * from t1_ins_overwrt partition(p3);
    Query OK, 2 rows affected (1.354 sec)
    Records: 2  Duplicates: 0  Warnings: 0
    ```

6. Query the p3 partition of the `t2_ins_overwrt` table. The data has been overwritten.

    ```sql
    obclient> SELECT * FROM t2_ins_overwrt partition(p3);
    +------+------+
    | c1   | c2   |
    +------+------+
    |   34 |   40 |
    |   45 |   50 |
    +------+------+
    2 rows in set (0.006 sec)
    ```

#### Example 3

1. Create a partitioned table named `tbl1`.

   ```shell
      obclient [test]> CREATE TABLE tbl1(col1 INT,col2 INT) 
                     PARTITION BY RANGE COLUMNS(col1) 
                        SUBPARTITION BY HASH(col2) SUBPARTITIONS 3 (
                           PARTITION p0 VALUES LESS THAN(10),                                               
                           PARTITION p1 VALUES LESS THAN(20));

   ```

2. Insert a row into the `tbl1` table.

   ```shell
   obclient [test]> INSERT INTO tbl1 (col1, col2) VALUES (2, 3);
                    INSERT INTO tbl1 (col1, col2) VALUES (15, 2);
   ```

3. Query whether data has been inserted into the `p0` partition of the `tbl1` table.

   ```shell
   obclient [test]> SELECT * FROM tbl1 PARTITION (p0);
   ```

    The query result is as follows:

   ```shell
   +------+------+
   | col1 | col2 |
   +------+------+
   |    2 |    3 |
   +------+------+
   ```

   ```shell
   obclient [test]> SELECT * FROM tbl1 PARTITION (p1);
   ```

    The query result is as follows:

   ```shell
    +------+------+
    | col1 | col2 |
    +------+------+
    |   15 |    2 |
    +------+------+
   ```

4. Create a partitioned table named `tbl2`.

   ```shell
   obclient [test]> CREATE TABLE tbl2(col1 INT,col2 INT) 
                     PARTITION BY RANGE COLUMNS(col1) 
                        SUBPARTITION BY HASH(col2) SUBPARTITIONS 3 (
                           PARTITION p0 VALUES LESS THAN(10),                                               
                           PARTITION p1 VALUES LESS THAN(20));
    Query OK, 0 rows affected
   ```

5. Insert data into the `tbl2` table.

   ```shell
   obclient [test]> INSERT INTO tbl2 (col1, col2) VALUES (0, 22);
                    INSERT INTO tbl2 (col1, col2) VALUES (18, 6);
   ```

6. Query whether data has been inserted into the `p0` and `p1` partitions of the `tbl2` table.

   ```shell
   obclient [test]> SELECT * FROM tbl2 PARTITION (p0);
   ```

    The query result is as follows:

   ```shell
    +------+------+
    | c1   | c2   |
    +------+------+
    |    0 |   22 |
    +------+------+
   ```

   ```shell
   obclient [test]> SELECT * FROM tbl2 PARTITION (p1);
   ```

    The query result is as follows:

   ```shell
    +------+------+
    | c1   | c2   |
    +------+------+
    |    18 |   6 |
    +------+------+
   ```

7. Use the `insert overwrite` statement to overwrite the data in the `p1` partition of the `tbl1` table into the corresponding partition of the `tbl2` table.

   ```shell
   obclient [test]> insert overwrite tbl2 partition (p1) select * from tbl1 partition (p1);
   ```

8. Verify whether the data in the `p1` partition of the `tbl2` table has been overwritten.

   ```shell
   obclient [test]> SELECT * FROM tbl2 PARTITION (p1);

    +------+------+
    |   15 |    2 |
    +------+------+
   ```

   The result shows that the data in the `p1` partition of the `tbl2` table has been overwritten.

## Insert data using the REPLACE INTO statement

You can also use the `REPLACE INTO` statement to insert data into a table without primary keys or unique keys. If the table is empty or has no primary key or unique key conflicts, the `REPLACE INTO` statement is functionally equivalent to the `INSERT` statement. For more information about the `REPLACE INTO` statement, see [REPLACE](../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/7600.replace-of-mysql-mode.md).

Here are two examples:

* After the `t_replace` table is created, use the `REPLACE INTO` statement to insert data.

  ```sql
  obclient [test]> CREATE TABLE t_replace(
      id int NOT NULL PRIMARY KEY
      , name varchar(10) NOT NULL
      , value int
      ,gmt_create timestamp NOT NULL DEFAULT current_timestamp
  );
  Query OK, 0 rows affected 

  obclient [test]> REPLACE INTO t_replace VALUES(1,'CN',2001, current_timestamp ());
  Query OK, 1 row affected 

  obclient [test]> SELECT * FROM t_replace;
  +----+------+-------+---------------------+
  | id | name | value | gmt_create          |
  +----+------+-------+---------------------+
  |  1 | CN   |  2001 | 2022-11-23 09:52:44 |
  +----+------+-------+---------------------+
  1 row in set 
  ```

* Use the `REPLACE INTO` statement to insert data into the `t_replace` table, which contains data records.

  ```sql
  obclient [test]> SELECT * FROM t_replace;
  +----+------+-------+---------------------+
  | id | name | value | gmt_create          |
  +----+------+-------+---------------------+
  |  1 | CN   |  2001 | 2022-03-22 16:13:55 |
  +----+------+-------+---------------------+
  1 row in set 

  obclient [test]> REPLACE INTO t_replace values(2,'US',2002, current_timestamp ());
  Query OK, 1 row affected

  obclient [test]> SELECT * FROM t_replace;
  +----+------+-------+---------------------+
  | id | name | value | gmt_create          |
  +----+------+-------+---------------------+
  |  1 | CN   |  2001 | 2022-11-23 09:52:44 |
  |  2 | US   |  2002 | 2022-11-23 09:53:05 |
  +----+------+-------+---------------------+
  2 rows in set
  ```
