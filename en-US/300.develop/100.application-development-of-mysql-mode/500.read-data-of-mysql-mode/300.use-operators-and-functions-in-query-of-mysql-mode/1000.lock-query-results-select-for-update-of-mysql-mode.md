# Lock query results with SELECT FOR UPDATE

OceanBase Database supports multi-version concurrency control (MVCC). By default, a read transaction does not block the execution of a write transaction. However, you can lock the target of a read transaction using the `SELECT ... FOR UPDATE` statement to block write transactions.

This topic describes how to use `SELECT ... FOR UPDATE` to lock query results through specific examples. Starting from V4.4.2 BP4, OceanBase Database also supports the MySQL `FOR SHARE` syntax and the `OF` clause. For related usage, see [Lock query results by using the FOR SHARE and OF clauses](#Lock%20query%20results%20by%20using%20the%20FOR%20SHARE%20and%20OF%20clauses) at the end of this topic.

## Lock behavior

If a row of data is being locked by another transaction, you can use the `NOWAIT` and `SKIP LOCKED` options with the `SELECT ... FOR UPDATE` statement to avoid waiting for the other transaction to release the row lock. The specific behaviors are as follows:

* When using the `SELECT ... FOR UPDATE` clause, the following behaviors occur:

  * Lock wait: If a row is being locked by another transaction, the current transaction will wait until the lock is released or the wait times out. Once the required lock is obtained, the transaction will continue execution.
  * Block other transactions: If the current transaction holds a lock on a row and another transaction tries to lock the same row, that transaction will be blocked until the current transaction releases the row lock.

* When using the `SELECT ... FOR UPDATE NOWAIT` clause, the following behavior occurs:

  When a transaction attempts to lock a row, if the row is already locked by another transaction, an error is returned immediately instead of waiting for the lock to be released.

* When using the `SELECT ... FOR UPDATE SKIP LOCKED` clause, the following behavior occurs:

  When a transaction attempts to lock a row, if the row is already locked by another transaction, the transaction skips that row and proceeds to the next one.

## Example

Create a sample table and insert test data.

1. Create the `fruit_order` table.

    ```sql
    CREATE TABLE fruit_order(
      order_id INT NOT NULL AUTO_INCREMENT COMMENT 'Order ID',
      user_id BIGINT NOT NULL COMMENT 'Customer ID',
      user_name VARCHAR(16) NOT NULL DEFAULT '' COMMENT 'Customer name',
      fruit_price DECIMAL(10,2) NOT NULL DEFAULT 0 COMMENT 'Order amount',
      order_year SMALLINT NOT NULL COMMENT 'Year of purchase',
      PRIMARY KEY (order_id)
      ) COMMENT 'Order table';
    ```

2. Insert test data into the `fruit_order` table.

    ```sql
    INSERT INTO fruit_order(user_id, user_name, fruit_price, order_year) VALUES
      (1011,'Zhang San',13.11,'2019'),
      (1011,'Zhang San',22.21,'2020'),
      (1011,'Zhang San',58.83,'2020'),
      (1022,'Li Si',23.34,'2019'),
      (1022,'Li Si',12.22,'2019'),
      (1022,'Li Si',14.66,'2021'),
      (1022,'Li Si',34.44,'2021'),
      (1033,'Wang Wu',51.55,'2020'),
      (1033,'Wang Wu',63.66,'2021');
    ```

### Use FOR UPDATE to lock query results

1. Execute the following statement to disable auto-commit.

    ```sql
    SET GLOBAL autocommit = 0;
    ```

    For information about the auto-commit feature, see [autocommit](../../../../700.reference/800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/400.autocommit-global.md).

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>Setting a global variable is invalid for the current session. It takes effect only after you log in again to establish a new session.</p>
    </main>

2. In session 1, execute the following statement to lock the query results for order ID 7.

    ```shell
    obclient [test]> SELECT * FROM fruit_order WHERE order_id = 7 FOR UPDATE;
    ```

    The return result is as follows:

    ```shell
    +----------+---------+-----------+-------------+------------+
    | order_id | user_id | user_name | fruit_price | order_year |
    +----------+---------+-----------+-------------+------------+
    |        7 |    1022 | Li Si      |       34.44 |       2021 |
    +----------+---------+-----------+-------------+------------+
    1 row in set
    ```

3. In session 2, execute the following statement to update the `fruit_price` value in the row with order ID 7 to 16.15. This SQL statement will wait until either the preceding transaction is rolled back or the `COMMIT` statement is executed; otherwise, it will wait for a timeout error.

    ```shell
    obclient [test]> UPDATE fruit_order SET fruit_price = 16.15 WHERE order_id = 7;
    ```

    The return result is as follows:

    ```shell
    ERROR 1205 (HY000): Lock wait timeout exceeded; try restarting transaction
    ```

4. In session 1, execute the following statement to commit the transaction.

    ```sql
    COMMIT;
    ```

5. In session 2, execute the following statement again to update the `fruit_price` value in the row with order ID 7 to 16.15.

    ```shell
    obclient [test]> UPDATE fruit_order SET fruit_price = 16.15 WHERE order_id = 7;
    ```

    The return result is as follows:

    ```shell
    Query OK, 1 row affected
    Rows matched: 1  Changed: 1  Warnings: 0
    ```

6. In session 2, execute the following statement to commit the transaction.

    ```sql
    COMMIT;
    ```

7. In session 1, execute the following statement to query the updated data.

    ```shell
    obclient [test]> SELECT * FROM fruit_order WHERE order_id = 7;
    ```

    The return result is as follows:

    ```shell
    +----------+---------+-----------+-------------+------------+
    | order_id | user_id | user_name | fruit_price | order_year |
    +----------+---------+-----------+-------------+------------+
    |        7 |    1022 | Li Si      |       16.15 |       2021 |
    +----------+---------+-----------+-------------+------------+
    1 row in set
    ```

### Lock query results by using the NOWAIT or SKIP LOCKED option

1. In session 1, execute the following statement to lock the query result with order ID 7 using `FOR UPDATE`:

    ```shell
    obclient [test]> SELECT * FROM fruit_order WHERE order_id = 7 FOR UPDATE;
    ```

    The return result is as follows:

    ```shell
    +----------+---------+-----------+-------------+------------+
    | order_id | user_id | user_name | fruit_price | order_year |
    +----------+---------+-----------+-------------+------------+
    |        7 |    1022 | Li Si      |       16.15 |       2021 |
    +----------+---------+-----------+-------------+------------+
    1 row in set
    ```

2. In session 2, execute the following statement to lock the query result with order ID 7 using `FOR UPDATE NOWAIT`:

    ```shell
    obclient [test]> SELECT * FROM fruit_order WHERE order_id = 7 FOR UPDATE NOWAIT;
    ```

    The return result is as follows:

    ```shell
    ERROR 1205 (HY000): Lock wait timeout exceeded; try restarting transaction
    ```

3. In session 3, execute the following statement to lock the query results where the order ID is greater than or equal to 7 using `FOR UPDATE SKIP LOCKED`:

    ```shell
    obclient [test]> SELECT * FROM fruit_order WHERE order_id >= 7 FOR UPDATE SKIP LOCKED;
    ```

    The return result is as follows:

    ```shell
    +----------+---------+-----------+-------------+------------+
    | order_id | user_id | user_name | fruit_price | order_year |
    +----------+---------+-----------+-------------+------------+
    |        8 |    1033 | Wang Wu      |       51.55 |       2020 |
    |        9 |    1033 | Wang Wu      |       63.66 |       2021 |
    +----------+---------+-----------+-------------+------------+
    2 rows in set
    ```

### Lock query results by using the FOR SHARE and OF clauses

Starting from V4.4.2 BP4, OceanBase Database supports the MySQL `FOR SHARE` syntax and `OF` clause. The locking behavior of `FOR SHARE` is consistent with that of `FOR UPDATE`, both placing exclusive row locks on query results. It is primarily used for compatibility with MySQL and SQL generated by frameworks such as Hibernate. The `OF` clause is used to specify the table to be locked on. It supports table names, table aliases, and table names qualified by database names. If omitted, it locks all base tables within the current query block.

In session 1, execute the following statement to lock only the query result with order ID 7 in the `fruit_order` table using `FOR SHARE OF`.

```shell
obclient [test]> SELECT * FROM fruit_order WHERE order_id = 7 FOR SHARE OF fruit_order;
```

The return result is as follows:

```shell
+----------+---------+-----------+-------------+------------+
| order_id | user_id | user_name | fruit_price | order_year |
+----------+---------+-----------+-------------+------------+
|        7 |    1022 | Li Si      |       16.15 |       2021 |
+----------+---------+-----------+-------------+------------+
1 row in set
```
