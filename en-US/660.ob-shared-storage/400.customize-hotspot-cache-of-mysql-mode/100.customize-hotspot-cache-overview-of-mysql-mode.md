# Overview

In the shared storage mode of OceanBase Database, all data is stored in object storage with lower costs, while frequently accessed or actively used hot data is cached in local storage to accelerate business queries. Caching hot data is an optimization method for storage costs and database performance. By default, the system dynamically caches hot data (frequently accessed) and evicts cold data (infrequently accessed) based on data access frequency and generation time. However, for sensitive queries, the system's automatic cold-hot data identification may lead to unexpected results, causing RT jitter during queries.

For business scenarios with clear hot and cold data characteristics, such as time-series data, you can define hot data ranges based on business features (e.g., time boundaries) to customize the hot data caching strategy. This approach addresses the limitations of automatic cold-hot data identification, enhancing performance predictability. By pre-caching hot data in local storage, you can avoid RT jitter during queries.

## Applicable scenarios

* Time-sensitive business: For example, businesses that only need to view recent data.
* Business with high RT stability requirements: For example, businesses that are sensitive to query latency for frequently accessed data.

## Hot data caching mechanism

* Data attribute types:

  * `HOT`: Hot data is cached in local storage as much as possible. If the local storage capacity allows, all hot data is cached in local storage.
  * `AUTO`: Based on data access frequency, the system automatically identifies hot and cold data and dynamically prefetches and caches data.
  * `NONE`: Inherit the hot and cold data caching strategy from the parent entity (such as the main table). For example, if the caching strategy of a local index is `NONE`, it dynamically inherits the strategy from the main table.

    <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>When the hot and cold data caching strategy follows the value of the <code>STORAGE_CACHE_POLICY</code> at the upper level: <ul><li>For subpartitions, the upper level is the partition.</li><li>For partitions, the upper level is the table.</li><li>For index tables, the upper level is the main table.</li></ul></p>
    </main>

* Priority mechanism:

  * User-defined hot data has a higher priority than automatically identified hot data.

## Support for hot and cold data caching strategies

* In the shared storage mode of OceanBase Database, you can customize hot and cold data caching strategies by using SQL statements:

  * You can specify the hot and cold data caching strategy (`STORAGE_CACHE_POLICY`) at the table or partition level when you create a table (user table or index table).
  * You can modify the hot and cold data caching strategy (`STORAGE_CACHE_POLICY`) at the table or partition level for a table (user table or index table).

* OceanBase Database provides configuration items for setting global hot and cold data caching strategies:

  * Set the default caching strategy [default_storage_cache_policy](../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2120.default_storage_cache_policy.md).
  * Enable the user-defined hot and cold data caching strategy [enable_manual_storage_cache_policy](../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2650.enable_manual_storage_cache_policy.md).
  * Specify whether to suspend the background caching task [suspend_storage_cache_task](../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/8070.suspend_storage_cache_task.md).

* OceanBase Database provides views for viewing caching strategies:

  * View the overall caching status of each tenant on the current OBServer node [V$OB_TABLET_LOCAL_CACHE](../../../700.system-views/300.system-view-of-sys-tenant/300.performance-view-of-sys-tenant/34820.v-ob_tablet_local_cache-of-sys-tenant.md).
  * View the caching task information of each tenant on the current OBServer node [V$OB_STORAGE_CACHE_TASKS](../../../700.system-views/300.system-view-of-sys-tenant/300.performance-view-of-sys-tenant/34550.v-ob_storage_cache_tasks-of-sys-tenant.md).
