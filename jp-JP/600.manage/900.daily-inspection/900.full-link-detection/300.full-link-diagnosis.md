# フルリンクトレースの方法

運用保守担当者は、必要に応じてPL/SQLパッケージDBMS_MONITORの関連メソッドを使用して、アプリケーションが異なる識別情報の観点でフルリンクトレースを有効にするかどうか、およびそのトレースのイベント記録と関連情報をトレースログに出力する戦略を制御できます。ログの出力はサンプリング頻度に基づいてサンプリングされ、メモリに記録された後、一定の確率でトレースログに出力されます。

## Traceの有効化と無効化の操作

DBMS_MONITORパッケージのtrace関連メソッドを呼び出すことで、traceのさまざまなレベルのオン/オフモードを実現できます。

ここでは、メソッドに含まれる関連変数の定義を紹介します：

- `session_id`：セッションID。show processlist(MySQLモード)、GV$OB_PROCESSLISTなどのビューでクエリできます。
- `client_id`：クライアントID。GV$OB_PROCESSLISTのclientフィールドでクエリできます。
- `module_name`：モジュール名。GV$OB_PROCESSLISTのmoduleフィールドでクエリできます。
- `action_name`：アクティビティ名。GV$OB_PROCESSLISTのactionフィールドでクエリできます。
- `tenant_name`：テナント名。オプションは、NULL（非NULLは現在のテナントを表す）と各テナント名です。
- `level`：ログを出力する粒度。現在、3つの粒度レベルをサポートしています。そのうち、Level1はモジュールレベルの粗い粒度で、Level3が最も細かい粒度です。
- `sample_pct`：サンプリング頻度を制御します。値の範囲は[0,1]です。
- `record_policy`: ログ出力戦略、つまりtrace情報をログファイルに出力する戦略です。以下の3種類の戦略をサポートしています。

   - ALL：すべてのspanとtag情報をログファイルに出力し、各span終了時にもログファイルに出力します。
   - ONLY_SLOW_QUERY：現在のリクエストがslow queryの場合、その部分の情報のspanとtagをログファイルに出力します。
   - SAMPLE_AND_SLOW_QUERY：現在のリクエストがslow queryの場合、その部分の情報のspanとtagをログファイルに出力します。その他のリクエスト情報のspanとtagは一定の確率でログファイルに出力されます。

詳細については、関連する[DBMS_MONITOR](../../../700.reference/600.pl-reference/300.pl-oracle/1400.pl-system-package-oracle/10000.dbms-monitor-oracle/100.dbms-monitor-overview-oracle.md)パッケージの定義を参照してください。

### セッションレベル

#### トレースを開始

```sql
DBMS_MONITOR.OB_SESSION_TRACE_ENABLE(
  session_id   IN  BINARY_INTEGER DEFAULT NULL,
  level        IN  INT,
  sample_pct   IN  NUMBER,
  record_policy IN VARCHAR2
);

```
例：現在のセッションに関連する所要時間などの情報を記録し、サンプリング頻度は50%で、スロークエリのみを記録します。

```sql
call dbms_monitor.ob_session_trace_enable(null, 1, 0.5, 'ONLY_SLOW_QUERY');
```

#### トレースを終了

```sql
DBMS_MONITOR.OB_SESSION_TRACE_DISABLE(session_id   IN  BINARY_INTEGER);
```

例：現在のセッショントレースを終了します。

```sql
call dbms_monitor.ob_session_trace_disable(null);
```

### client_identifierレベル

#### トレースを開始

```sql
DBMS_MONITOR.OB_CLIENT_ID_TRACE_ENABLE(
  client_id    IN  VARCHAR2,
  level        IN  INT,
  sample_pct   IN  NUMBER,
  record_policy IN VARCHAR2
);
```

以下の例では、client_idがjdbcの関連する所要時間情報を記録し、サンプリング頻度は50%で、スロークエリのみを記録します。

```sql
call dbms_monitor.ob_client_id_trace_enable('jdbc', 1, 0.5, 'ONLY_SLOW_QUERY');
```

#### トレースを終了

```sql
DBMS_MONITOR.OB_CLIENT_ID_TRACE_DISABLE(client_id IN  VARCHAR2);
```

以下の例では、client_idがjdbcのトレースを終了します。

```sql
call dbms_monitor.ob_client_id_trace_disable('jdbc');
```

### モジュール/アクションレベル

#### トレースを開始

```sql
DBMS_MONITOR.OB_MOD_ACT_TRACE_ENABLE(
  module_name     IN VARCHAR2 DEFAULT ANY_MODULE,
  action_name     IN VARCHAR2 DEFAULT ANY_ACTION,
  level        IN  INT,
  sample_pct   IN  NUMBER,
  record_policy IN VARCHAR2
);
```

以下の例では、module_nameがbackup、action_nameがinsertの関連する所要時間情報を記録し、サンプリング頻度は50%で、スロークエリのみを記録します。ここでのmodule_nameとaction_nameは、dbms_application_infoパッケージのSET_MODULEメソッドで設定します。

```sql
call dbms_application_info.set_module('backup', 'insert');
call dbms_monitor.ob_mod_act_trace_enable('backup', 'insert', 1, 0.5, 'ONLY_SLOW_QUERY');
```

#### トレースを終了

```sql
DBMS_MONITOR.OB_MOD_ACT_TRACE_DISABLE(
  module_name     IN  VARCHAR2,
  action_name     IN  VARCHAR2 DEFAULT ALL_ACTIONS
);
```

以下の例では、module_nameがbackup、action_nameがinsertのトレースを終了します。

```sql
call dbms_monitor.ob_mod_act_trace_disable('backup', 'insert');
```

### テナントレベル

#### Traceの開始

```sql
DBMS_MONITOR.OB_TENANT_TRACE_ENABLE(
  level        IN  INT,
  sample_pct   IN  NUMBER,
  record_policy IN VARCHAR2
);
```

以下の例では、現在のテナント内の所要時間情報をすべて記録し、すべて出力します。

```sql
call dbms_monitor.ob_tenant_trace_enable(1, 1, 'ALL');
```

#### Traceの終了

```sql
DBMS_MONITOR.OB_TENANT_TRACE_DISABLE(tenant_name  IN VARCHAR2 DEFAULT NULL);
```

以下の例では、テナント名ORACLEのtraceを終了します。

```sql
call dbms_monitor.ob_tenant_trace_disable('ORACLE');
```

以下の例では、現在のテナントのtraceを終了します。

```sql
call dbms_monitor.ob_tenant_trace_disable();
```
