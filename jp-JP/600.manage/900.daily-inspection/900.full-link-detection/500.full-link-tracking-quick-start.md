# クイックスタート：obdiagによるエンドツーエンド機能診断

obdiagは、OceanBase専用に設計されたブラックボックス診断ツールです。その機能は、OceanBaseのログ、SQL監査、およびOceanBaseプロセススタックなどの情報のスキャン、収集、分析を網羅しています。OCPやobdでデプロイする場合でも、ドキュメントに従って手動でデプロイする場合でも、obdiagはワンクリック実行で診断情報の収集と分析を迅速に完了できます。

このドキュメントでは、obdiagを使用してOceanBaseデータベースのエンドツーエンドトレースを迅速に実行する方法をご紹介します。

## obdiagのインストールとデプロイ

1. [obdiag](https://en.oceanbase.com/softwarecenter)をダウンロードし、ダウンロードしたバージョンがv.1.5.0以上であることを確認してください。

2. 公式ドキュメント[アジャイル診断ツールobdiag](https://en.oceanbase.com/docs/obdiag-en)を参照して、obdiagのインストール、デプロイ、設定を完了してください。

## 操作手順

### ステップ1（オプション）：テナントのTraceをリセットする

包括的な診断時にすべての結果を出力したい場合は、**テナントのTraceをリセットする**操作を実行できます。

OBServerに接続した後、以下のSQLコマンドを実行します：

```sql
-- Traceを無効にする
call dbms_monitor.ob_tenant_trace_disable();
-- 現在のテナント内の所要時間情報を記録し、すべて記録してすべて出力する。
call dbms_monitor.ob_tenant_trace_enable(1, 1, 'ALL');
```

### ステップ2：SQLステートメントをクエリしてテストする

ここでは、SQLクエリステートメントを例に、フルリンク機能の診断方法を説明します。

```sql
select * from tx where c1=1 and c1=2;

-- SQL Auditで、`query_sql` を使用して疑わしいスローSQLの `flt_trace_id` を検索する
SELECT query_sql, flt_trace_id FROM oceanbase.gv$ob_sql_audit WHERE query_sql LIKE 'select * from tx where c1=1 and c1=%';
+--------------------------------------+--------------------------------------+
| query_sql                            | flt_trace_id                         |
+--------------------------------------+--------------------------------------+
| select * from tx where c1=1 and c1=2 | 00060e1a-dead-7cbd-5d74-6d64084eccfa |
+--------------------------------------+--------------------------------------+
1 row in set (0.206 sec)
```

### ステップ3：フルリンクトレースコマンドを実行する

OBServerを終了し、以下のコマンドを実行してフルリンクトレースを行います。

```shell
-- ステップ2で取得した`flt_trace_id`と設定済みの環境変数を使用して、フルリンクトレースコマンドを実行します。
$ obdiag analyze flt_trace --flt_trace_id 00060e1a-dead-7cbd-5d74-6d64084eccfa
```
