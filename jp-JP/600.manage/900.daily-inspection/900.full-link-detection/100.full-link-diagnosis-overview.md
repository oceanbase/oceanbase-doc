# フルトレースの概要

## フルトレースとは？

OceanBaseデータベースは分散システムであり、複雑な呼び出しチェーンを持っています。タイムアウトが発生した場合、OceanBase内部コンポーネントまたはネットワークの問題かどうかを迅速に特定することは難しく、運用担当者は経験やOBServerログに基づいて分析するしかありません。診断効率を向上させるため、今回の更新では新しいフルトレースメカニズムを導入しました。このメカニズムは、ユーザーのSQLリクエストがデータベース全体のプロセスにおいて、異なるコンポーネントや段階で実行される関連情報を追跡し、可視化してユーザーに表示することで、問題の位置を迅速に特定できるよう支援します。

### フルトレースのパス

フルトレースは、主に2つのデータストリームパスをカバーしています。

- 一つは、リクエストがアプリケーションから始まり、クライアント（JDBCやOCIなど）を通じてODP（プロキシサーバー）に送信され、その後ODPからOBServerに転送され、最終的に結果がアプリケーションに返されます。
- もう一つは、リクエストが直接アプリケーションからクライアントを経由してOBServerに送信され、その後結果が直接返されます。

フルトレースの目的は、これら2つのパス上のすべてのコンポーネントにおける問題の特定です。

フルトレース機能を使用する前に、[DBMS_MONITOR](../../../700.reference/500.sql-reference/300.pl-reference/300.pl-oracle/1400.pl-system-package-oracle/10000.dbms-monitor-oracle/100.dbms-monitor-overview-oracle.md)パッケージを使用して、フルトレース機能を有効にすることができます。また、ビジネス要件に応じたサンプリングレートやログ出力レベルなどの設定情報も設定可能です。機能が有効になると、設定ルールに合致するSQLは、全パスの計測情報が記録されます。

### フルトレースのログ

フルトレースのログ、すなわちトレースログ（trace logs）は、データアクセスパスに基づいて記録内容が決定されます。ODPを介してデータベースにアクセスする場合、トレース情報はODPとOBServerの両方のログファイルに同時に記録されます。一方、OBServerに直接アクセスする場合は、OBServerのログファイルにのみ記録されます。具体的には、ODPのトレースログファイル名は`obproxy_trace.log`、OBServerのトレースログファイル名は`trace.log`です。各ログファイルのサイズ制限は256MBであり、ログがこのサイズ制限に達すると、システムは新しいログファイルを作成し、古いファイルをアーカイブします。アーカイブファイルの数は構成パラメータ[max_syslog_file_count](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/13600.max_syslog_file_count.md)によって制御され、上限を超えるファイルは自動的に削除されます。
運用担当者は、すべてのトレースログを収集・分析することで、各トランザクションやSQLクエリが呼び出しチェーン全体で実行される時間やその他の関連情報を追跡できます。これは、問題の正確な特定に重要な手がかりを提供するだけでなく、運用効率も大幅に向上させます。
