# ごみ箱からのオブジェクトの復元

削除されたオブジェクトはごみ箱に移動した後、`FLASHBACK` ステートメントを使用して復元できます。

## 注意点

* テーブルを復元する際、Flashback オブジェクトの順序は従属関係に従う必要があります。つまり、データベースを先に Flashbackし、その後テーブルを Flashbackします。

* インデックスの直接復元はサポートされていません。`FLASHBACK` ステートメントでテーブルを復元すると、そのテーブルのインデックスも自動的に復元されます。

* ごみ箱からオブジェクトを復元する際、復元対象の名前を変更できますが、既存のオブジェクト名と重複してはなりません。重複するとシステムはエラーを返します。

* MySQLテナントの場合、ごみ箱からテーブルを復元する前に、そのテーブルが属するデータベースが削除されている場合は、データベースを先に復元してからテーブルを復元する必要があります。

* テーブルがごみ箱に入る前に特定のテーブルグループに属していた場合、ごみ箱から復元された後、そのテーブルはデフォルトで元のテーブルグループに戻ります。元のテーブルグループが既に削除されている場合、そのテーブルは復元後、どのテーブルグループにも属しません。

## テナントの復元

現在、テナントを削除できるのは `sys` テナントのみであるため、ごみ箱からテナントを復元できるのも `sys` テナントのみです。復元時にはテナント名を変更できますが、既存のテナント名と重複してはなりません。重複するとシステムはエラーを返します。

1. `sys` テナントでデータベースにログインします。

   接続例は以下の通りです。データベースへの接続時は、実際の環境に準じてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

   データベースへの接続操作の詳細については、[データベース接続の概要（MySQLモード）](../../../300.develop/100.application-development-of-mysql-mode/100.connect-to-oceanbase-database-of-mysql-mode/100.connection-methods-overview-of-mysql-mode.md)および[データベース接続の概要（Oracleモード）](../../../300.develop/200.application-development-of-oracle-mode/100.connect-to-oceanbase-database-of-oracle-mode/100.connection-methods-overview-of-oracle-mode.md)を参照してください。

2. `SHOW RECYCLEBIN` ステートメントを実行し、ごみ箱内のオブジェクト名を取得します。

   ```shell
   obclient [(none)]> SHOW RECYCLEBIN;
   +-------------------------------------+-------------------+----------+----------------------------+
   | OBJECT_NAME                         | ORIGINAL_NAME     | TYPE     | CREATETIME                 |
   +-------------------------------------+-------------------+----------+----------------------------+
   | RECYCLE_$_100017_1672050541224936   | oracle001         | TENANT   | 2023-01-16 11:01:40.258000 |
   | __recycle_$_100017_1673426335319344 | __idx_500788_idx1 | INDEX    | 2023-01-11 16:38:55.318878 |
   | __recycle_$_100017_1673426335331800 | t1                | TABLE    | 2023-01-11 16:38:55.331481 |
   | __recycle_$_100017_1673854707660504 | infotest          | DATABASE | 2023-01-16 15:38:27.660436 |
   +-------------------------------------+-------------------+----------+----------------------------+
   4 rows in set
   ```

3. 業務ニーズに応じて、適切なシナリオを選択し、ごみ箱内のテナントを復元します。

   * ごみ箱内のテナントを通常のテナントに復元し、復元後のテナント名はごみ箱に入る前のテナント名と同じにします。

     ステートメントは以下の通りです：

     ```sql
     FLASHBACK TENANT tenant_name TO BEFORE DROP;
     ```

     ここで、`tenant_name` にはごみ箱内の名前またはテナントの元の名前を使用できます。ごみ箱内の名前はグローバルに一意であるため、ごみ箱内の名前を使用すると、復元するのがどのテナントかを明確にできます。そのため、テナントの復元にはごみ箱内の名前の使用を推奨します。元の名前を使用する場合、ごみ箱内に同名の複数のテナントが存在すると、復元されるテナントは、それらのテナントのうち最後にごみ箱に入ったテナントになります。

     例：

     ```shell
     obclient [(none)]> FLASHBACK TENANT RECYCLE_$_100017_1672050541224936 TO BEFORE DROP;
     Query OK, 0 rows affected
     ```

   * ごみ箱内のテナントを通常のテナントに復元し、名前を変更します。

     ```sql
     FLASHBACK TENANT tenant_name TO BEFORE DROP RENAME TO new_tenant_name;
     ```

     関連パラメータの説明は以下のとおりです：

       * `tenant_name` には、ごみ箱内の名前またはテナントの元の名前を使用できます。ごみ箱内の名前はグローバルに一意であるため、ごみ箱内の名前を使用すると、どのテナントを復元するかを明確にできます。そのため、ごみ箱内の名前を使用してテナントを復元することを推奨します。元の名前を使用する場合、ごみ箱内に複数のテナントが同じ元の名前を持つと、復元されるテナントは、それらのテナントのうち最後にごみ箱に入ったテナントになります。

       * `new_tenant_name` は、復元後のテナント名、つまりごみ箱から復元されたテナントの名前を表します。

     例：

     ```shell
     obclient [(none)]> FLASHBACK TENANT RECYCLE_$_100017_1672050541224936 TO BEFORE DROP RENAME TO new_oracle;
     Query OK, 0 rows affected
     ```

## データベースの復元

`sys` テナントまたはMySQLユーザーテナントは、ごみ箱からデータベースを復元できます。復元時にデータベース名を変更できますが、既存のデータベースと同名にすることはできません。同名である場合、システムはエラーを返します。

1. `sys` テナントまたはMySQLユーザーテナントのテナント管理者がデータベースにログインします。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>デフォルトでは、MySQLテナントの管理者ユーザーは <code>root</code> ユーザーです。</p>
   </main>

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に準じてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

   データベースへの接続操作の詳細については、[データベース接続の概要（MySQLモード）](../../../300.develop/100.application-development-of-mysql-mode/100.connect-to-oceanbase-database-of-mysql-mode/100.connection-methods-overview-of-mysql-mode.md)および[データベース接続の概要（Oracleモード）](../../../300.develop/200.application-development-of-oracle-mode/100.connect-to-oceanbase-database-of-oracle-mode/100.connection-methods-overview-of-oracle-mode.md)を参照してください。

2. `SHOW RECYCLEBIN` ステートメントを実行し、ごみ箱内のオブジェクト名を取得します。

   ```shell
   obclient [(none)]> SHOW RECYCLEBIN;
   +-------------------------------------+-------------------+----------+----------------------------+
   | OBJECT_NAME                         | ORIGINAL_NAME     | TYPE     | CREATETIME                 |
   +-------------------------------------+-------------------+----------+----------------------------+
   | __recycle_$_100017_1673426335319344 | __idx_500788_idx1 | INDEX    | 2023-01-11 16:38:55.318878 |
   | __recycle_$_100017_1673426335331800 | t1                | TABLE    | 2023-01-11 16:38:55.331481 |
   | __recycle_$_100017_1673854707660504 | infotest          | DATABASE | 2023-01-16 15:38:27.660436 |
   +-------------------------------------+-------------------+----------+----------------------------+
   3 rows in set
   ```

3. 業務ニーズに応じて、適切なシナリオを選択し、ごみ箱内のデータベースを復元します。

   * ごみ箱からデータベースを復元する場合、復元後のデータベース名はごみ箱に入る前の名前になります。

     ```sql
     FLASHBACK DATABASE object_name TO BEFORE DROP;
     ```

     ここで、`object_name` はデータベースオブジェクトがごみ箱内で持つ名前を表します。元の名前の使用はサポートされていません。

     例：

     ```shell
     obclient [(none)]> FLASHBACK DATABASE __recycle_$_100017_1673854707660504 TO BEFORE DROP;
     Query OK, 0 rows affected
     ```

     このステートメントを実行した後、復元対象のデータベースとテナント内の既存データベースが同名である場合、システムはエラーを返します。

     ```shell
     obclient [(none)]> FLASHBACK DATABASE __recycle_$_100017_1673854707660504 TO BEFORE DROP;
     ERROR 1007 (HY000): Can't create database 'infotest'; database exists
     ```

   * ごみ箱からデータベースを復元し、名前を変更します。

     ```sql
     FLASHBACK DATABASE object_name TO BEFORE DROP RENAME TO new_database_name;
     ```

     ここで：

     * `object_name` はごみ箱内のデータベースオブジェクト名を表します。元の名前の使用はサポートされていません。

     * `new_database_name`：ごみ箱から復元後のデータベース名を表します。

     例：

     ```shell
     obclient [(none)]> FLASHBACK DATABASE __recycle_$_100017_1673854707660504 TO BEFORE DROP RENAME TO new_infotest;
     Query OK, 0 rows affected
     ```

## テーブルの復元

`sys`テナント、MySQLユーザーテナント、およびOracleユーザーテナントは、いずれもごみ箱からテーブルを復元できます。復元時にはテーブル名を変更できますが、既存のテーブル名と重複してはなりません。重複するとシステムはエラーを返します。

1. `sys`テナントまたはユーザーテナントのテナント管理者がデータベースにログインします。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>デフォルトでは、MySQLテナントの管理者ユーザーは<code>root</code>ユーザー、Oracleテナントの管理者ユーザーは<code>SYS</code>ユーザーです。</p>
   </main>

   接続例は以下の通りです。データベースへの接続時は、実際の環境に準じてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

   より詳細なデータベース接続操作の手順については、[データベース接続の概要（MySQLモード）](../../../300.develop/100.application-development-of-mysql-mode/100.connect-to-oceanbase-database-of-mysql-mode/100.connection-methods-overview-of-mysql-mode.md)および[データベース接続の概要（Oracleモード）](../../../300.develop/200.application-development-of-oracle-mode/100.connect-to-oceanbase-database-of-oracle-mode/100.connection-methods-overview-of-oracle-mode.md)を参照してください。

2. `SHOW RECYCLEBIN`ステートメントを実行し、ごみ箱内のオブジェクト名を取得します。

   ```shell
   obclient [(none)]> SHOW RECYCLEBIN;
   +-------------------------------------+-------------------+----------+----------------------------+
   | OBJECT_NAME                         | ORIGINAL_NAME     | TYPE     | CREATETIME                 |
   +-------------------------------------+-------------------+----------+----------------------------+
   | __recycle_$_100017_1673426335319344 | __idx_500788_idx1 | INDEX    | 2023-01-11 16:38:55.318878 |
   | __recycle_$_100017_1673426335331800 | t1                | TABLE    | 2023-01-11 16:38:55.331481 |
   | __recycle_$_100017_1673854707660504 | infotest          | DATABASE | 2023-01-16 15:38:27.660436 |
   +-------------------------------------+-------------------+----------+----------------------------+
   3 rows in set
   ```

3. 業務ニーズに応じて適切なシナリオを選択し、ごみ箱内のテーブルを復元します。

   * ごみ箱からテーブルを復元します。復元後のテーブル名は、ごみ箱に入る前のテーブル名になります。

     ```sql
     FLASHBACK TABLE object_name TO BEFORE DROP;
     ```

     ここで、`object_name`はごみ箱内のテーブルオブジェクト名を表します。元の名前を使用することも可能ですが、ごみ箱内の名前はグローバルに一意であるため、ごみ箱内の名前の使用を推奨します。

     例：

     ```shell
     obclient [(none)]> FLASHBACK TABLE __recycle_$_100017_1673426335331800 TO BEFORE DROP;
     Query OK, 0 rows affected
     ```

     このステートメントを実行すると、復元後のテーブル名はごみ箱に入る前の名前に戻り、そのテーブルが属していたデータベースまたはスキーマオブジェクトも削除前のものが維持されます。ただし、ごみ箱に入る前のテーブル名が既存のテーブル名と重複する場合、システムはエラーを返します。

   * ごみ箱からテーブルを復元して名前を変更します。

     ```sql
     FLASHBACK TABLE object_name TO BEFORE DROP RENAME To new_table_name;
     ```

     ここで、`object_name` はごみ箱内のテーブルオブジェクト名を指しますが、元の名前を使用することも可能です。ごみ箱内の名前はグローバルに一意であるため、ごみ箱内の名前の使用を推奨します。`new_table_name` はテーブル復元後の新しい名前を指します。

     例：

     ```shell
     obclient [(none)]> FLASHBACK TABLE __recycle_$_100017_1673426335331800 TO BEFORE DROP RENAME To infotable;
     Query OK, 0 rows affected
     ```

     このステートメントを実行すると、復元後のテーブル名は新しい名前になり、そのテーブルが属していたデータベースまたはスキーマオブジェクトも削除前のものが維持されます。ただし、新しい名前が既存のテーブル名と重複する場合、システムはエラーを返します。

   * ごみ箱から指定したデータベースまたはスキーマオブジェクトにテーブルを復元して名前を変更します。

     ```sql
     FLASHBACK TABLE object_name TO BEFORE DROP RENAME To database_name.new_table_name;
     ```

     ここで、`object_name` はごみ箱内のテーブルオブジェクト名を指しますが、元の名前を使用することも可能です。ごみ箱内の名前はグローバルに一意であるため、ごみ箱内の名前の使用を推奨します。`database_name.new_table_name` はテーブル復元後の新しい名前およびそれが属するデータベースまたはスキーマオブジェクトを指します。Oracleテナントでは、スキーマオブジェクト名はユーザー名と同じになります。

     例：

     ```shell
     obclient [(none)]> FLASHBACK TABLE __recycle_$_100017_1673426335331800 TO BEFORE DROP RENAME To test.infotable;
     Query OK, 0 rows affected
     ```

     このステートメントを実行すると、復元後のテーブル名は新しい名前になり、そのテーブルが属するデータベースまたはスキーマオブジェクトは指定されたものになります。ただし、新しい名前が既存のテーブル名と重複する場合、システムはエラーを返します。
