# ごみ箱のクリーンアップ

データベースオブジェクトの頻繁な削除と再作成により、ごみ箱には大量のデータが発生します。ごみ箱をクリーンアップすることで、これらのデータを削除できます。

ごみ箱のクリーンアップには、主に手動と自動の2つの方法があります。システムテナント(`sys`テナント)は`INDEX`、`TABLE`、`DATABASE`、`TENANT`の4種類のごみ箱オブジェクトをクリーンアップでき、MySQLユーザーテナントは`INDEX`、`TABLE`、`DATABASE`の3種類をクリーンアップできます。Oracleユーザーテナントは`INDEX`と`TABLE`の2種類をクリーンアップできます。

## ごみ箱の手動クリーンアップ

`PURGE`コマンドを使用して、ごみ箱を手動でクリーンアップできます。

### 注意事項

* Purge操作は、対象オブジェクトとその子孫オブジェクト(つまり、Database -> Table -> Indexの順序で)を削除します。例えば、MySQLモードでは、データベースをPurgeすると、そのデータベースと属するテーブルおよびテーブルインデックスが削除されます。

* あるオブジェクトの上位オブジェクトがPurgeされた場合、現在のごみ箱に関連付けられているその下位のオブジェクトもPurgeされます。

* Purge操作を実行する前に、ごみ箱内の削除対象オブジェクトを確認することをお勧めします。Purge操作後は、OceanBaseデータベースのごみ箱でそのオブジェクトの情報を検索することはできなくなり、実際のデータも最終的にはガベージコレクションとして回収されます。

### 手順

1. `sys`テナントまたはユーザーテナントのテナント管理者としてデータベースにログインします。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <ul>
   <li>MySQLテナントの管理者ユーザーは<code>root</code>ユーザー、Oracleテナントの管理者ユーザーは<code>SYS</code>ユーザーです。</li>
   <li>テナントのごみ箱オブジェクトをクリーンアップする必要がある場合は、<code>sys</code>テナントでデータベースにログインする必要があります。</li>
   </ul>
   </main>

   接続例は以下の通りですが、データベースへの接続時は実際の環境に準じてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

   データベース接続の詳細な操作手順については、[データベース接続の概要 (MySQLモード)](../../../300.develop/100.application-development-of-mysql-mode/100.connect-to-oceanbase-database-of-mysql-mode/100.connection-methods-overview-of-mysql-mode.md)および[データベース接続の概要 (Oracleモード)](../../../300.develop/200.application-development-of-oracle-mode/100.connect-to-oceanbase-database-of-oracle-mode/100.connection-methods-overview-of-oracle-mode.md)を参照してください。

2. `SHOW RECYCLEBIN`ステートメントを実行し、ごみ箱内のオブジェクト名を取得します。

   ```shell
   obclient [(none)]> SHOW RECYCLEBIN;
   +-------------------------------------+-------------------+----------+----------------------------+
   | OBJECT_NAME                         | ORIGINAL_NAME     | TYPE     | CREATETIME                 |
   +-------------------------------------+-------------------+----------+----------------------------+
   | RECYCLE_$_100017_1672050541224936   | oracle001         | TENANT   | 2023-01-16 11:01:40.258000 |
   | __recycle_$_100017_1673426335319344 | __idx_500788_idx1 | INDEX    | 2023-01-11 16:38:55.318878 |
   | __recycle_$_100017_1673426335331800 | t1                | TABLE    | 2023-01-11 16:38:55.331481 |
   | __recycle_$_100017_1673854707660504 | infotest          | DATABASE | 2023-01-16 15:38:27.660436 |
   +-------------------------------------+-------------------+----------+----------------------------+
   4 rows in set
   ```

3. 業務ニーズに応じて、適切なシナリオを選択し、ごみ箱をクリーンアップします。

   * テナントをごみ箱から完全に削除する

     テナントをごみ箱から完全に削除すると、そのテナントのすべてのオブジェクトも一緒に削除されます。テナントのごみ箱オブジェクトをクリーンアップできるのは`sys`テナントのみです。

     ステートメントは以下のとおりです：

     ```shell
     obclient [(none)]> PURGE TENANT tenant_name;
     ```

     ここで、`tenant_name`はごみ箱内の名前を表しますが、元の名前を使用することもできます。元の名前を使用する場合、ごみ箱内に現在同じ元の名前が複数存在すると、最も早くごみ箱に入ったテナントが削除されます。

     例：

     ```shell
     obclient [(none)]> PURGE TENANT oracle001;

     obclient [(none)]> PURGE TENANT RECYCLE_$_100017_1672050541224936;
     ```

   * ごみ箱から指定したデータベースを物理的に削除する

     ごみ箱内のデータベースオブジェクトをクリーンアップできるのは`sys`テナントとMySQLユーザーテナントのみです。

     ```sql
     obclient> PURGE DATABASE object_name;
     ```

     `object_name`は、そのスキーマオブジェクトがごみ箱内で持つ名前を表します。元の名前の使用はサポートされていません。

     例：

     ```shell
     obclient [(none)]> PURGE DATABASE __recycle_$_100017_1673854707660504;
     ```

   * ごみ箱から指定したテーブルを物理的に削除する

     ```sql
     obclient> PURGE TABLE object_name;
     ```

     `object_name`は、そのスキーマオブジェクトがごみ箱内で持つ名前を表しますが、元の名前を使用することもできます。元の名前を使用する場合、ごみ箱内に現在同じ元の名前が複数存在すると、最も早くごみ箱に入ったテーブルが削除されます。

     例：

     ```shell
     obclient [(none)]> PURGE TABLE __recycle_$_100017_1673426335331800;
     ```

   * ごみ箱から指定したインデックステーブルを物理的に削除する

     ```sql
     obclient> PURGE INDEX object_name;
     ```

     `object_name`は、そのスキーマオブジェクトがごみ箱内で持つ名前を表します。元の名前の使用はサポートされていません。

     例：

     ```shell
     obclient [(none)]> PURGE INDEX __recycle_$_100017_1673426335319344;
     ```

   * ごみ箱内のすべてのオブジェクトを完全に削除する

     ```shell
     obclient [(none)]> PURGE RECYCLEBIN;
     ```

4. コマンドの実行が成功した後、再度 `SHOW RECYCLEBIN` ステートメントを実行して、ゴミ箱内のオブジェクトが正常にクリーンアップされたかどうか確認できます。

   ```shell
   obclient [(none)]> SHOW RECYCLEBIN;
   ```

## ゴミ箱の自動クリーンアップ

OceanBaseデータベースは現在、クラスタレベル構成パラメータ `recyclebin_object_expire_time` を使用して、ゴミ箱内の期限切れSchemaオブジェクトを自動的にクリーンアップすることをサポートしています。デフォルト値は0秒です。詳細は以下の通りです：

* 値が `0s` の場合、ゴミ箱の自動Purge機能は無効です。

* 値が `0s` 以外の場合、指定された期間（`recyclebin_object_expire_time` で設定された値）前にゴミ箱に入ったオブジェクトをPurgeします。

クラスタレベル構成パラメータ `recyclebin_object_expire_time` の詳細については、[recyclebin_object_expire_time](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/17700.recyclebin_object_expire_time.md)を参照してください。

1. `root` ユーザーでデータベースの `sys` テナントにログインします。

   接続例は以下の通りですが、データベースへの接続時は実際の環境に合わせてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

   データベースへの接続手順の詳細については、[データベースへの接続](../../../300.develop/100.application-development-of-mysql-mode/100.connect-to-oceanbase-database-of-mysql-mode/100.connection-methods-overview-of-mysql-mode.md)を参照してください。

2. 以下のステートメントを実行し、ゴミ箱の自動クリーンアップポリシーを確認します。

   ```sql
   obclient [(none)]> SHOW PARAMETERS LIKE 'recyclebin_object_expire_time';
   ```

   クエリ結果は次のとおりです：

   ```shell
   +-------+----------+----------------+----------+-------------------------------+-----------+-------+--------------------------------------------------------------------------------------------------+--------------+---------+---------+-------------------+---------------+-----------+
   | zone  | svr_type | svr_ip         | svr_port | name                          | data_type | value | info                                                                                             | section      | scope   | source  | edit_level        | default_value | isdefault |
   +-------+----------+----------------+----------+-------------------------------+-----------+-------+--------------------------------------------------------------------------------------------------+--------------+---------+---------+-------------------+---------------+-----------+
   | zone1 | observer | 172.xx.xxx.xxx |     2882 | recyclebin_object_expire_time | TIME      | 0s    | recyclebin object expire time, default 0 that means auto purge recyclebin off. Range: [0s, +∞)   | ROOT_SERVICE | CLUSTER | DEFAULT | DYNAMIC_EFFECTIVE | 0s            |         1 |
   +-------+----------+----------------+----------+-------------------------------+-----------+-------+--------------------------------------------------------------------------------------------------+--------------+---------+---------+-------------------+---------------+-----------+
   1 row in set
   ```

3. 以下のステートメントを実行して、ゴミ箱の自動クリーンアップ機能を有効にし、ゴミ箱に入ってから何時間前のオブジェクトをクリーンアップするかを指定します。

   ゴミ箱の自動クリーンアップ機能を有効にし、7日前にゴミ箱に入ったSchemaオブジェクトを回収する例ステートメントは以下の通りです：

   ```shell
   obclient [(none)]>  ALTER SYSTEM SET recyclebin_object_expire_time = '7d';
   ```

   ゴミ箱の自動クリーンアップ機能を有効にした後、V4.4.2バージョンでは：

   * V4.4.2 BP1およびそれ以前のバージョンでは、ゴミ箱の自動クリーンアップアクションはシステムバックグラウンドで定期的にトリガーされ、デフォルトの時間間隔は10分です。

   * V4.4.2 BP2以降のバージョンでは、ゴミ箱の自動クリーンアップアクションはバックグラウンドのスケジュールタスク `SCHEDULED_PURGE_RECYCLEBIN` によって制御され、デフォルトのトリガー時間間隔は10分です。ユーザーはビジネスニーズに応じて、このスケジュールタスクのトリガー時間間隔を変更できます。詳細な変更操作については、[SET_ATTRIBUTE](../../../700.reference/600.pl-reference/300.pl-oracle/1400.pl-system-package-oracle/14200.dbms-scheduler-oracle/1100.set-attribute-oracle.md)を参照してください。

4. （オプション）一定時間後、以下のステートメントを実行して、ゴミ箱内の条件に合致するオブジェクトがクリーンアップされたかどうか確認できます。

   ```shell
   obclient [(none)]> SHOW RECYCLEBIN;
   ```
