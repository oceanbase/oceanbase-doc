# リサイクルビンのクリーンアップ

データベースオブジェクトを頻繁に削除して再作成すると、リサイクルビンに大量のデータが発生します。リサイクルビンをクリーンアップすることで、これらのデータを削除できます。

リサイクルビンのクリーンアップには、主に手動と自動の2つの方法があります。システムテナント(`sys`テナント)は`INDEX`、`TABLE`、`DATABASE`、`TENANT`の4種類のリサイクルビンオブジェクトをクリーンアップできます。MySQLユーザーテナントは`INDEX`、`TABLE`、`DATABASE`の3種類のリサイクルビンオブジェクトをクリーンアップできます。Oracleユーザーテナントは`INDEX`と`TABLE`の2種類のリサイクルビンオブジェクトをクリーンアップできます。

## リサイクルビンの手動クリーンアップ

`PURGE` コマンドを使用して、リサイクルビンを手動でクリーンアップできます。

### 注意事項

* Purge操作は、オブジェクトとそのオブジェクトに属するオブジェクト（つまり、データベース→テーブル→インデックス）を削除します。例えば、MySQLモードでは、データベースをPurgeすると、そのデータベースとそれに属するテーブルおよびテーブルのインデックスが削除されます。

* あるオブジェクトの上位オブジェクトがPurgeされると、現在のリサイクルビンに関連付けられている下位のオブジェクトもPurgeされます。

* Purge操作を実行する前に、リサイクルビンで削除対象のオブジェクトを確認することを推奨します。Purge操作を実行すると、OceanBaseデータベースのリサイクルビンではオブジェクトの情報をクエリできなくなり、実際のデータも最終的にはガベージコレクションとして回収されます。

### 操作手順

1. `sys` テナントまたはユーザーテナントのテナント管理者としてデータベースにログインします。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <ul>
   <li>MySQLテナントの管理者ユーザーは <code>root</code> ユーザー、Oracleテナントの管理者ユーザーは <code>SYS</code> ユーザーです。</li>
   <li>テナントのリサイクルビンのオブジェクトをクリーンアップする必要がある場合は、<code>sys</code> テナントでデータベースにログインする必要があります。</li>
   </ul>
   </main>

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に準じてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

   より詳細なデータベース接続操作の手順については、[データベース接続の概要（MySQLモード）](../../../300.develop/100.application-development-of-mysql-mode/100.connect-to-oceanbase-database-of-mysql-mode/100.connection-methods-overview-of-mysql-mode.md)および[データベース接続の概要（Oracleモード）](../../../300.develop/200.application-development-of-oracle-mode/100.connect-to-oceanbase-database-of-oracle-mode/100.connection-methods-overview-of-oracle-mode.md)を参照してください。

2. `SHOW RECYCLEBIN` ステートメントを実行し、リサイクルビン内のオブジェクト名を取得します。

   ```shell
   obclient [(none)]> SHOW RECYCLEBIN;
   +-------------------------------------+-------------------+----------+----------------------------+
   | OBJECT_NAME                         | ORIGINAL_NAME     | TYPE     | CREATETIME                 |
   +-------------------------------------+-------------------+----------+----------------------------+
   | RECYCLE_$_100017_1672050541224936   | oracle001         | TENANT   | 2023-01-16 11:01:40.258000 |
   | __recycle_$_100017_1673426335319344 | __idx_500788_idx1 | INDEX    | 2023-01-11 16:38:55.318878 |
   | __recycle_$_100017_1673426335331800 | t1                | TABLE    | 2023-01-11 16:38:55.331481 |
   | __recycle_$_100017_1673854707660504 | infotest          | DATABASE | 2023-01-16 15:38:27.660436 |
   +-------------------------------------+-------------------+----------+----------------------------+
   4 rows in set
   ```

3. 業務ニーズに応じて、適切なシナリオを選択し、リサイクルビンをクリーンアップします。

   * テナントをリサイクルビンから完全に削除する

     テナントをリサイクルビンから完全に削除する場合、そのテナント配下のすべてのオブジェクトも一緒に削除されます。テナントのリサイクルビンのオブジェクトのクリーンアップは、`sys` テナントのみサポートしています。

     ステートメントは以下のとおりです：

     ```shell
     obclient [(none)]> PURGE TENANT tenant_name;
     ```

     ここで、`tenant_name` はリサイクルビン内の名前を表しますが、元の名前を使用することもできます。元の名前を使用する場合、リサイクルビン内に現在同じ名前が複数存在すると、最も早くリサイクルビンに入ったテナントが削除されます。

     例：

     ```shell
     obclient [(none)]> PURGE TENANT oracle001;

     obclient [(none)]> PURGE TENANT RECYCLE_$_100017_1672050541224936;
     ```

   * リサイクルビンから指定したデータベースを物理的にクリーンアップする

     テナントのリサイクルビン内のデータベースオブジェクトのクリーンアップは、`sys` テナントとMySQLユーザーテナントのみサポートしています。

     ```sql
     obclient> PURGE DATABASE object_name;
     ```

     `object_name` は、そのSchemaオブジェクトがリサイクルビン内で持つ名前を表します。元の名前の使用はサポートされていません。

     例：

     ```shell
     obclient [(none)]> PURGE DATABASE __recycle_$_100017_1673854707660504;
     ```

   * リサイクルビンから指定したテーブルを物理的にクリーンアップする

     ```sql
     obclient> PURGE TABLE object_name;
     ```

     `object_name` は、リサイクルビン内でのそのSchemaオブジェクトの名前ですが、元の名前を使用することもできます。元の名前を使用する場合、その時点でリサイクルビン内に同じ名前が複数存在すると、最も早くリサイクルビンに入ったテーブルが削除されます。

     例：

     ```shell
     obclient [(none)]> PURGE TABLE __recycle_$_100017_1673426335331800;
     ```

   * リサイクルビンから指定したインデックステーブルを物理的にクリーンアップする

     ```sql
     obclient> PURGE INDEX object_name;
     ```

     `object_name` は、そのSchemaオブジェクトがリサイクルビン内で持つ名前を表します。元の名前の使用はサポートされていません。

     例：

     ```shell
     obclient [(none)]> PURGE INDEX __recycle_$_100017_1673426335319344;
     ```

   *リサイクルビンからすべてのオブジェクトを完全に削除する

     ```shell
     obclient [(none)]> PURGE RECYCLEBIN;
     ```

4. コマンドの実行が成功した後、再度 `SHOW RECYCLEBIN` ステートメントを実行し、リサイクルビン内のオブジェクトが正常にクリーンアップされたかを確認します。

   ```shell
   obclient [(none)]> SHOW RECYCLEBIN;
   ```

## リサイクルビンの自動クリーンアップ

OceanBaseデータベースは、現在クラスタレベル構成パラメータ `recyclebin_object_expire_time` を使用して、ごみ箱内の期限切れSchemaオブジェクトを自動的にクリーンアップすることをサポートしています。デフォルト値は0秒です。詳細は以下の通りです。

* 値が `0s` の場合、リサイクルビンの自動Purge機能は無効です。

* 値が `0s` 以外の場合、一定期間（`recyclebin_object_expire_time` で設定された値）前にリサイクルビンに移動したオブジェクトをPurgeします。

クラスタレベル構成パラメータ `recyclebin_object_expire_time` の詳細については、[recyclebin_object_expire_time](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/17700.recyclebin_object_expire_time.md)を参照してください。

1. `root` ユーザーでデータベースの `sys` テナントにログインします。

   接続例は以下の通りです。データベースへの接続時は、実際の環境に準じてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

   データベースへの接続操作の詳細については、[データベースへの接続](../../../300.develop/100.application-development-of-mysql-mode/100.connect-to-oceanbase-database-of-mysql-mode/100.connection-methods-overview-of-mysql-mode.md)を参照してください。

2. 以下のステートメントを実行し、リサイクルビンの自動クリーンアップ戦略を確認します。

   ```sql
   obclient [(none)]> SHOW PARAMETERS LIKE 'recyclebin_object_expire_time';
   ```

   クエリ結果は次のとおりです。

   ```shell
   +-------+----------+----------------+----------+-------------------------------+-----------+-------+--------------------------------------------------------------------------------------------------+--------------+---------+---------+-------------------+---------------+-----------+
   | zone  | svr_type | svr_ip         | svr_port | name                          | data_type | value | info                                                                                             | section      | scope   | source  | edit_level        | default_value | isdefault |
   +-------+----------+----------------+----------+-------------------------------+-----------+-------+--------------------------------------------------------------------------------------------------+--------------+---------+---------+-------------------+---------------+-----------+
   | zone1 | observer | 172.xx.xxx.xxx |     2882 | recyclebin_object_expire_time | TIME      | 0s    | recyclebin object expire time, default 0 that means auto purge recyclebin off. Range: [0s, +∞)   | ROOT_SERVICE | CLUSTER | DEFAULT | DYNAMIC_EFFECTIVE | 0s            |         1 |
   +-------+----------+----------------+----------+-------------------------------+-----------+-------+--------------------------------------------------------------------------------------------------+--------------+---------+---------+-------------------+---------------+-----------+
   1 row in set
   ```

3. 以下のステートメントを実行し、リサイクルビンの自動クリーンアップ機能を有効にし、リサイクルビンに移動してからどの程度の時間前のオブジェクトをクリーンアップするかを指定します。

   リサイクルビンの自動クリーンアップ機能を有効にし、7日前にリサイクルビンに移動したSchemaオブジェクトを回収する例ステートメントは以下のとおりです。

   ```shell
   obclient [(none)]>  ALTER SYSTEM SET recyclebin_object_expire_time = '7d';
   ```

4. （オプション）完了後、以下のステートメントを実行して、リサイクルビン内の条件に合致するオブジェクトがクリーンアップされたかどうかを確認できます。

   ```shell
   obclient [(none)]> SHOW RECYCLEBIN;
   ```
