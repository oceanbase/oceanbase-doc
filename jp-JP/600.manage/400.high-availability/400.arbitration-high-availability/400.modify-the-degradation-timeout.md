# ログストリームのデグレード制御時間の変更

<main id="notice" >
<h4>適用対象</h4>
<p>この内容はOceanBaseデータベースEnterprise版にのみ適用されます。OceanBaseデータベースCommunity版は、現在アービトレーションサービス機能をサポートしていません。</p>
</main>

テナントレベルのアービトレーションサービスを使用する場合、ログストリームのデグレード制御時間を設定する必要があります。Fレプリカの半数が障害によりログ同期に失敗し、かつログストリームのデグレード制御時間に達すると、アービトレーションサービスは自動的にログストリームのデグレードプロセスを実行してサービスを復旧します。ログストリームの自動デグレードの制御時間はデフォルトで5秒です。この値は、データセンターに障害が発生した場合のサービス中断時間も表します。

## 操作手順

1. `sys` テナントまたはユーザーテナントのテナント管理者としてデータベースにログインします。

   接続例は以下の通りですが、データベースへの接続時には実際の環境に準じてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

   より詳細なデータベース接続操作の手順については、[データベース接続の概要（MySQLモード）](../../../300.develop/100.application-development-of-mysql-mode/100.connect-to-oceanbase-database-of-mysql-mode/100.connection-methods-overview-of-mysql-mode.md)および[データベース接続の概要（Oracleモード）](../../../300.develop/200.application-development-of-oracle-mode/100.connect-to-oceanbase-database-of-oracle-mode/100.connection-methods-overview-of-oracle-mode.md)を参照してください。

2. テナントのアービトレーションサービスのログストリームデグレード制御時間を確認します。

   * システムテナントが指定テナントをクエリする場合

     ```sql
     SHOW PARAMETERS LIKE 'arbitration_timeout' TENANT = 'tenant_name';
     ```

     テナント `mysql` のアービトレーションサービスのログストリームデグレード制御時間を確認する例：

     ```shell
     obclient> SHOW PARAMETERS LIKE 'arbitration_timeout' TENANT = 'mysql';
     ```

   * ユーザーテナントが自身のテナントをクエリする場合

     ```shell
     obclient> SHOW PARAMETERS LIKE 'arbitration_timeout';
     ```

   クエリ結果は次のとおりです。

   ```sql
   +-------+----------+----------------+----------+---------------------+-----------+-------+----------------------------------------------------------------------------------------------------------------------------------------------------------+---------+--------+---------+-------------------+---------------+-----------+
   | zone  | svr_type | svr_ip         | svr_port | name                | data_type | value | info                                                                                                                                                     | section | scope  | source  | edit_level        | default_value | isdefault |
   +-------+----------+----------------+----------+---------------------+-----------+-------+----------------------------------------------------------------------------------------------------------------------------------------------------------+---------+--------+---------+-------------------+---------------+-----------+
   | zone1 | observer | 172.xx.xxx.xxx |     2882 | arbitration_timeout | TIME      | 5s    | The timeout before automatically degrading when arbitration member exists. Range: [1s,+∞]. Values from [1s,3s) are not recommended for non-POC scenarios | TRANS   | TENANT | DEFAULT | DYNAMIC_EFFECTIVE | 5s            |         1 |
   +-------+----------+----------------+----------+---------------------+-----------+-------+----------------------------------------------------------------------------------------------------------------------------------------------------------+---------+--------+---------+-------------------+---------------+-----------+
   1 row in set
   ```

3. 使用シナリオに応じて、適切なステートメントを選択してログストリームデグレード制御時間を変更します。

   テナントレベルの構成パラメータ `arbitration_timeout` は、ログストリームの自動デグレードをトリガーする制御時間を設定します。デフォルト値は5秒で、取り得る範囲は [1s, +∞) ですが、本番環境では3秒以上を推奨します。[1s, 3s) の範囲の値は非本番環境でのみ使用することを推奨します。デグレードを防ぐには、30d（30日間）のように十分に大きな値を設定できます。この構成パラメータは設定後すぐに反映され、OBServerノードの再起動は不要です。

   * ユーザーテナントが自身のテナントのログストリームデグレード制御時間を変更する場合

     ```shell
     obclient> ALTER SYSTEM SET arbitration_timeout = '10s';
     ```

   * `sys` テナントが指定テナントのログストリームデグレード制御時間を変更する場合

     ```shell
     obclient> ALTER SYSTEM SET arbitration_timeout = '10s' TENANT = 'tenant_name';
     ```

   * `sys` テナントがすべてのユーザーテナント（`sys` テナントおよびMetaテナントを除く）のログストリームデグレード制御時間を変更する場合

     ```shell
     obclient> ALTER SYSTEM SET arbitration_timeout = '10s' TENANT = all_user;
     ```

     または

     ```shell
     obclient> ALTER SYSTEM SET arbitration_timeout = '10s' TENANT = all;
     ```

     <main id="notice" type='explain'>
     <h4>説明</h4>
     <p>OceanBase データベースはバージョンV4.2.1から、<code>TENANT = all_user</code> と <code>TENANT = all</code> のセマンティクスが同じになりました。有効範囲をすべてのユーザーテナントに設定する必要がある場合は、<code>TENANT = all_user</code> の使用を推奨します。<code>TENANT = all</code> は今後廃止され、使用されなくなります。</p>
     </main>
