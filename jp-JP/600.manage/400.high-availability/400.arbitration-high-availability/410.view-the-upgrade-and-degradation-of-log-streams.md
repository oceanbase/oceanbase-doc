# ログストリームの昇格・降格関連情報の確認

テナントでアービトレーションサービスを有効にした後、ビューを通じてログストリームの昇格または降格に関する情報を確認できます。

## ログストリームの昇格・降格イベントの確認

システムテナントは `DBA_OB_SERVER_EVENT_HISTORY` ビューを使用して、すべてのログストリームの昇格または降格イベントを確認できます。

1. `root` ユーザーでクラスタの `sys` テナントにログインします。

2. 以下のコマンドを実行し、ログストリームの昇格または降格イベントが発生したかどうかを確認します。

   * ログストリームの降格イベントの確認

        ```sql
        SELECT * FROM oceanbase.DBA_OB_SERVER_EVENT_HISTORY WHERE event LIKE "%DEGRADE%";
        ```

        クエリ結果が空の場合、現在ログストリームの降格イベントは発生していないことを意味します。そうでない場合、クエリ結果には降格が発生したレプリカ情報と降格の原因が表示されます。

        降格の原因には以下のようなものがあります：

        * `CRASHED_OR_BROKEN_NETWORK`：OBServerノードのダウンまたはネットワーク切断、observerプロセスのkillまたは異常終了を示します。
        * `LOG_DISK_HANG_OR_FULL`：ログディスクの書き込みが停止した（物理障害）またはテナントのログディスク容量が満杯であることを示します。
        * `SERVER_STOPPED_OR_ZONE_STOPPED`：`STOP ZONE` または `STOP SERVER` コマンドが実行されたことを示します。
        * `LOG_SYNC_DISABLED`：レプリカのログ同期が遅延しています。
        * `LOG_VOTE_DISABLED`：レプリカでRebuildが発生しました。

   * ログストリームの昇格イベントの確認

        ```sql
        SELECT * FROM oceanbase.DBA_OB_SERVER_EVENT_HISTORY WHERE event LIKE "%UPGRADE%";
        ```

        クエリ結果が空の場合、現在ログストリームの昇格イベントは発生していないことを意味します。そうでない場合、クエリ結果には昇格が発生したレプリカ情報が表示されます。

## ログストリームの昇格・降格結果の確認

ログストリームの昇格または降格イベントが発生した後、システムテナントまたはユーザーテナントは `GV$OB_LOG_STAT`/`V$OB_LOG_STAT` ビューを使用して、ログストリームの昇格または降格結果を確認できます。

1. テナント管理者がクラスタの `sys` テナントまたはユーザーテナントにログインします。

2. 以下のコマンドを実行して、ログストリームの昇格または降格結果を確認します。

   * システムテナント

      ```sql
      SELECT * FROM oceanbase.GV$OB_LOG_STAT WHERE tenant_id= xxxx;
      ```

   * ユーザーテナント

      :::tab
      tab MySQLモード

      ステートメントは以下のとおりです：

      ```sql
      SELECT * FROM oceanbase.GV$OB_LOG_STAT WHERE tenant_id= xxxx;
      ```

      tab Oracleモード

      ステートメントは以下のとおりです：

      ```sql
      SELECT * FROM SYS.GV$OB_LOG_STAT WHERE tenant_id= xxxx;
      ```

      :::

   クエリ結果で、ログストリームのロールが `LEADER` の行における `DEGRADED_LIST` 列を確認します。ログストリームのデグレードイベントが発生した場合、この列には異常でデグレードされたログストリームのレプリカが表示されます。ログストリームのアップグレードイベントが発生した場合、アップグレードされたレプリカはこの列から削除されます。
