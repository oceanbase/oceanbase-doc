# ロールオーバー

プライマリテナントが利用可能な場合、プライマリテナントとそのうちのいずれかのスタンバイテナントとのロールを交換し、データ損失なく運用を継続します。

以下では、物理的なスタンバイデータベースの2種類のデプロイメント方式に基づいて、それぞれロールオーバーの操作手順を提供します。

## 制限事項

* システムテナント (`sys`) のテナントロールの切り替えはサポートされていません。システムテナントのロールは常に `PRIMARY` です。

* スタンバイテナントをプライマリテナントに切り替える前に、スタンバイテナントのすべてのログストリームのレプリカがオンラインである必要があります。そうでない場合、対応するレプリカが永続的にオフラインになるまで待機する必要があります。スタンバイテナントまたはその所属するクラスタの `sys` テナントでは、それぞれ `DBA_OB_LS` ビューまたは `CDB_OB_LS` ビューを使用して、すべてのログストリームレプリカがオンラインかどうかを照会できます。ログストリームレプリカの詳細については、[レプリカの紹介](../../../300.replica-management/100.replica-introduction.md)を参照してください。

* サービス名で確立されたセッション内でSwitchoverコマンドを実行することは許可されません。関連するサービスの操作と説明については、[サービスの作成](../../../200.tenant-management/600.common-tenant-operations/1700.manage-service/100.create-service.md)を参照してください。

## ネットワークベースの物理スタンバイリーダー

ネットワークベースの物理スタンバイリーダーのシナリオでは、スイッチオーバーには主に以下の3つの段階が含まれます：主テナントをスタンバイテナントに切り替える --> スタンバイテナントを主テナントに切り替える --> 元の主テナントにログ復旧ソースを設定する。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>スイッチオーバー操作を行う際には、必ず主テナントをスタンバイテナントに切り替えた後に、スタンバイテナントを主テナントに切り替える必要があります。まずスタンバイテナントを主テナントに切り替えると、ダブルマスターの問題が発生し、<code>ALTER SYSTEM SWITCHOVER TO PRIMARY</code> コマンドの実行に失敗する可能性があります。</p>
</main>

1. 主テナントをスタンバイテナントに切り替えます。

   1. 管理者ユーザーを使用して、主テナントまたは主テナントが存在するクラスタの `sys` テナントにログインします。

   2. `SWITCHOVER TO STANDBY VERIFY` コマンドを実行して、`SWITCHOVER` コマンドが正常に実行できるかどうかを検証します。

      * 主テナントが存在するクラスタの `sys` テナントで `SWITCHOVER TO STANDBY VERIFY` コマンドを実行します

        ```sql
        ALTER SYSTEM SWITCHOVER TO STANDBY TENANT [=] tenant_name VERIFY;
        ```

        例：

        ```shell
        obclient> ALTER SYSTEM SWITCHOVER TO STANDBY TENANT = mysql VERIFY;
        ```

      * 主テナントで `SWITCHOVER TO STANDBY VERIFY` コマンドを実行します

        ```shell
        obclient> ALTER SYSTEM SWITCHOVER TO STANDBY VERIFY;
        ```

        コマンドを実行した後、`OK` が返された場合、検証は成功しており、次のステップを実行できます。

        エラーが発生した場合は、エラーメッセージに従って[SwitchoverまたはFailover関連の問題](../../../1000.troubleshooting/800.physical-standby-database/200.switchover-failed.md)を参照して処理を行い、その後、このコマンドを再実行してください。

   3. 検証が成功した後、主テナントをスタンバイテナントに切り替えるコマンドを実行します。

      * 主テナントが存在するクラスタの `sys` テナントで主テナントをスタンバイテナントに切り替えます

        ```sql
        ALTER SYSTEM SWITCHOVER TO STANDBY TENANT = tenant_name；
        ```

        例：

        ```shell
        obclient> ALTER SYSTEM SWITCHOVER TO STANDBY TENANT = mysql；
        ```

      * 主テナントで自身のテナントをスタンバイテナントに切り替えます

        ```shell
        obclient> ALTER SYSTEM SWITCHOVER TO STANDBY；
        ```

   4. `DBA_OB_TENANTS` ビューをクエリして、主テナントがスタンバイテナントに切り替わったかどうかを確認します。

      * 主テナントが存在するクラスタの `sys` テナントでビューをクエリします

        ```shell
        obclient> SELECT TENANT_NAME, TENANT_TYPE, TENANT_ROLE, SWITCHOVER_STATUS FROM oceanbase.DBA_OB_TENANTS;
        ```

      * 主テナントでビューをクエリします

        MySQLモード：

        ```shell
        obclient> SELECT TENANT_NAME, TENANT_TYPE, TENANT_ROLE, SWITCHOVER_STATUS FROM oceanbase.DBA_OB_TENANTS;
        ```

        Oracleモード：

        ```shell
        obclient> SELECT TENANT_NAME, TENANT_TYPE, TENANT_ROLE, SWITCHOVER_STATUS FROM SYS.DBA_OB_TENANTS;
        ```

      クエリ結果の例は次のとおりです：

      ```shell
      +-------------+-------------+-------------+-------------------+
      | TENANT_NAME | TENANT_TYPE | TENANT_ROLE | SWITCHOVER_STATUS |
      +-------------+-------------+-------------+-------------------+
      | mysql       | USER        | STANDBY     | NORMAL            |
      +-------------+-------------+-------------+-------------------+
      1 row in set
      ```

      クエリ結果に基づいて、`TENANT_ROLE` が `STANDBY` であり、かつ `SWITCHOVER_STATUS` が `NORMAL` である場合、主テナントからスタンバイテナントへの切り替えは成功しています。

2. スタンバイテナントを主テナントに切り替えます。

   1. 管理者ユーザーを使用して、スタンバイテナントまたはその存在するクラスタの `sys` テナントにログインします。

   2. `SWITCHOVER TO PRIMARY VERIFY` コマンドを実行して、`SWITCHOVER` コマンドが正常に実行できるかどうかを検証します。

      * スタンバイテナントが存在するクラスタの `sys` テナントで `SWITCHOVER TO PRIMARY VERIFY` コマンドを実行します

        ```sql
        ALTER SYSTEM SWITCHOVER TO PRIMARY TENANT [=] tenant_name VERIFY;
        ```

        例：

        ```shell
        obclient> ALTER SYSTEM SWITCHOVER TO PRIMARY TENANT = standby1 VERIFY;
        ```

      * スタンバイテナントで `SWITCHOVER TO PRIMARY VERIFY` コマンドを実行します

        ```shell
        obclient> ALTER SYSTEM SWITCHOVER TO PRIMARY VERIFY;
        ```

        コマンドを実行した後、`OK` が返された場合、検証は成功しており、次のステップを実行できます。

        エラーが発生した場合は、エラーメッセージに従って[SwitchoverまたはFailover関連の問題](../../../1000.troubleshooting/800.physical-standby-database/200.switchover-failed.md)を参照して処理を行い、その後、このコマンドを再実行してください。

   3. 検証が成功した後、スタンバイテナントを主テナントに切り替えるコマンドを実行します。

      * スタンバイテナントが存在するクラスタの `sys` テナントでスタンバイテナントを主テナントに切り替えます

        ```sql
        ALTER SYSTEM SWITCHOVER TO PRIMARY TENANT [=] tenant_name；
        ```

        例：

        ```shell
        obclient> ALTER SYSTEM SWITCHOVER TO PRIMARY TENANT = standby1；
        ```

      * スタンバイテナントで自身のテナントを主テナントに切り替えます

        ```shell
        obclient> ALTER SYSTEM SWITCHOVER TO PRIMARY;
        ```

   4. `DBA_OB_TENANTS` ビューをクエリして、スタンバイテナントが主テナントに切り替わったかどうかを確認します。

      * スタンバイテナントが存在するクラスタの `sys` テナントでビューをクエリします

        ```shell
        obclient> SELECT TENANT_NAME, TENANT_TYPE, TENANT_ROLE, SWITCHOVER_STATUS FROM oceanbase.DBA_OB_TENANTS;
        ```

      * スタンバイテナントでビューをクエリします

        MySQLモード：

        ```shell
        obclient> SELECT TENANT_NAME, TENANT_TYPE, TENANT_ROLE, SWITCHOVER_STATUS FROM oceanbase.DBA_OB_TENANTS;
        ```

        Oracleモード：

        ```shell
        obclient> SELECT TENANT_NAME, TENANT_TYPE, TENANT_ROLE, SWITCHOVER_STATUS FROM SYS.DBA_OB_TENANTS;
        ```

      クエリ結果の例は次のとおりです：

      ```shell
      +-----------------+-------------+-------------+-------------------+
      | TENANT_NAME     | TENANT_TYPE | TENANT_ROLE | SWITCHOVER_STATUS |
      +-----------------+-------------+-------------+-------------------+
      | standby1        | USER        | PRIMARY     | NORMAL            |
      +-----------------+-------------+-------------+-------------------+
      1 row in set
      ```

      クエリ結果に基づいて、主テナントの `TENANT_ROLE` が `PRIMARY` に変更され、かつ `SWITCHOVER_STATUS` が `NORMAL` になった場合、スタンバイテナントから主テナントへの切り替えは成功しています。

3. 元の主テナントにログ復旧ソースを設定します。

   ログ復旧ソースの設定は、主/スタンバイ切り替え操作の前に実行することも、操作の後に実行することもできます。

   1. 管理者ユーザーを使用して、元の主テナントまたはその存在するクラスタの `sys` テナントにログインします。

   2. 以下のコマンドを実行して、ログ復旧ソースを設定します。

      * 元の主テナントが存在するクラスタの `sys` テナントで元の主テナントのログ復旧ソースを設定します

        ```sql
        ALTER SYSTEM SET LOG_RESTORE_SOURCE ='SERVICE=$ip_list USER=$user_name@$tenant_name PASSWORD=$password' TENANT = tenant_name;
        ```

      * 元の主テナントで自身のテナントのログ復旧ソースを設定します

        ```sql
        ALTER SYSTEM SET LOG_RESTORE_SOURCE ='SERVICE=$ip_list USER=$user_name@$tenant_name PASSWORD=$password';
        ```

      一部のパラメータの説明は次のとおりです：

      * `$ip_list`：新しい主テナントが存在するレプリカのOBServerノードのIPアドレスとSQLポート番号です。複数のOBServerノード情報を有する場合でも、すべてのOBServerノード情報を記入する必要はありません。
      * `$user_name`：新しい主テナント上で作成されたシステムビューへのアクセス用専用ユーザーです。
      * `$tenant_name`：接続対象となる新しい主テナントのテナント名です。
      * `$password`：システムビューへのアクセス用専用ユーザーに対応するユーザーパスワードです。

      例：

      ```shell
      obclient> ALTER SYSTEM SET LOG_RESTORE_SOURCE = 'SERVICE=11.xx.xx.22:17855;11.xx.xx.23:17857;11.xx.xx.24:17859 USER=rep_user2@standby_tenant PASSWORD=******' TENANT = mysql;
      ```

      ```shell
      obclient> ALTER SYSTEM SET LOG_RESTORE_SOURCE = 'SERVICE=11.xx.xx.22:17855;11.xx.xx.23:17857;11.xx.xx.24:17859 USER=rep_user2@standby_tenant PASSWORD=******';
      ```

      ログ復旧ソースの設定に関する詳細な操作と説明については、[ログ復旧ソースの設定](../300.log-transport-service/200.configure-the-log-transport-service/100.set-log-restore-source.md)を参照してください。

   3. 設定が成功した後、`DBA_OB_TENANTS` ビューをクエリして、元の主テナントが継続的にログを同期しているかどうかを確認します。

      ログ復旧ソースを設定すると、主テナントがスタンバイテナントに切り替わった後、自動的にログの継続的な同期が開始されるため、特別な処理は不要です。`DBA_OB_TENANTS` ビューをクエリすることで確認できます。

      * 元の主テナントが存在するクラスタの `sys` テナントでビューをクエリします

        ```shell
        # ユーザーテナントIDを照会し、IDが偶数の場合がユーザーテナントです
        obclient> SELECT TENANT_ID, SYNC_SCN FROM oceanbase.DBA_OB_TENANTS;
        # ユーザーテナントIDを指定して情報を照会します
        obclient> SELECT TENANT_ID, TENANT_NAME, TENANT_TYPE, TENANT_ROLE, SWITCHOVER_STATUS, SCN_TO_TIMESTAMP(SYNC_SCN), RECOVERY_UNTIL_SCN FROM oceanbase.DBA_OB_TENANTS WHERE TENANT_ID = $user_tenant_id;
        ```

      * 元の主テナントでビューをクエリします

        MySQLモード：

        ```shell
        obclient> SELECT TENANT_NAME, TENANT_TYPE, TENANT_ROLE, SWITCHOVER_STATUS, SCN_TO_TIMESTAMP(SYNC_SCN), RECOVERY_UNTIL_SCN FROM oceanbase.DBA_OB_TENANTS;
        ```

        Oracleモード：

        ```shell
        obclient> SELECT TENANT_NAME, TENANT_TYPE, TENANT_ROLE, SWITCHOVER_STATUS, SCN_TO_TIMESTAMP(SYNC_SCN), RECOVERY_UNTIL_SCN FROM SYS.DBA_OB_TENANTS;
        ```

      MySQLモードでのクエリ結果は次のとおりです：

      ```shell
      +-------------+-------------+-------------+-------------------+----------------------------+---------------------+
      | TENANT_NAME | TENANT_TYPE | TENANT_ROLE | SWITCHOVER_STATUS | SCN_TO_TIMESTAMP(SYNC_SCN) | RECOVERY_UNTIL_SCN  |
      +-------------+-------------+-------------+-------------------+----------------------------+---------------------+
      | mysql       | USER        | STANDBY     | NORMAL            | 2023-04-18 13:46:20.887793 | 4611686018427387903 |
      +-------------+-------------+-------------+-------------------+----------------------------+---------------------+
      1 row in set
      ```

      クエリ結果に基づいて、`RECOVERY_UNTIL_SCN` 列の値がMAX SCN（4611686018427387903）の値と等しい場合、元の主テナントは継続的にログを同期している状態であり、そうでない場合は、元の主テナントは継続的にログを同期していない状態です。

## ログアーカイブに基づく物理スタンバイリース

ログアーカイブに基づく物理スタンバイリースのシナリオでは、スイッチオーバーは主に以下の3つのフェーズを含みます：スタンバイテナントのログアーカイブモードの有効化 --> プライマリテナントの切り替え --> スタンバイテナントの切り替え。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>スイッチオーバーを行う際には、まずプライマリテナントをスタンバイテナントに切り替える必要があります。そうでない場合、ダブルプライマリテナントの発生や、スタンバイテナントがログ同期を完了できない問題が発生する可能性があります。また、ログアーカイブに基づく物理スタンバイリースのシナリオでは、スタンバイテナントは元のプライマリテナントの状態を認識できません。そのため、最初にスタンバイテナントをプライマリテナントに切り替えた場合でも、<code>ALTER SYSTEM SWITCHOVER TO PRIMARY</code> コマンドを実行してもシステムはエラーを報告しません。</p>
</main>

ログアーカイブに基づく物理スタンバイリースのシナリオでは、スイッチオーバーの実行フローは次の図のとおりです。

![switchover フローチャート](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.1.0/user-guide/active-and-standby-tenant/switchover-process.png)

1. スタンバイテナントでログアーカイブモードを有効化します。

   ログアーカイブに基づく物理スタンバイリースのシナリオでは、スイッチオーバー操作が成功すると、元のプライマリテナントは新しいプライマリテナント（元のスタンバイテナント）のアーカイブログを継続的に読み取って、新しいプライマリテナント（元のスタンバイテナント）上のすべての変更操作を同期する必要があるため、新しいプライマリテナント（元のスタンバイテナント）でログアーカイブモードを有効にする必要があります。同時に、スイッチオーバー実行後のログ連続性を保証するため、新しいプライマリテナント（元のスタンバイテナント）はスイッチオーバー操作を実行する前にログアーカイブを有効にする必要があります。

   1. 管理者ユーザーとして、スタンバイテナントまたはその所属クラスタの `sys` テナントにログインします。

   2. スタンバイテナントのアーカイブ宛先を設定します。

      <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>アーカイブ宛先を設定する際には、異なるテナントで使用するアーカイブパスは異なる必要があります。</p>
       </main>

      アーカイブ宛先の設定では、主に `LOCATION`、`PIECE_SWITCH_INTERVAL`、および `BINDING` プロパティを設定します。

      * スタンバイテナントが所属するクラスタの `sys` テナントで、スタンバイテナントのアーカイブ宛先を設定します

        ```sql
        ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=archive_path [PIECE_SWITCH_INTERVAL=piece_switch_interval] [BINDING=archive_mode]' TENANT = tenant_name;
        ```

      * スタンバイテナント自身のアーカイブ宛先を設定します

        ```sql
        ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=archive_path [PIECE_SWITCH_INTERVAL=piece_switch_interval] [BINDING=archive_mode]';
        ```

      関連パラメータの説明は以下のとおりです：

      * `LOCATION`：アーカイブ宛先を指定するために使用されます。現在、OceanBaseデータベースでサポートされているアーカイブ宛先のメディアはNFSとAlibaba Cloud OSSです。

      * `BINDING`：アーカイブとビジネスの優先モードを設定するために使用されます。現在、`Optional` モードと `Mandatory` モードがサポートされています。設定しない場合、デフォルトは `Optional` モードとなります。

        * `Optional` モードはユーザーのビジネスを優先することを意味します。このモードでは、アーカイブ（ログアーカイブ）の速度がログ生成の速度に追いつかなかった場合、ログがアーカイブされる前に回収され、断流が発生する可能性があります。

        * `Mandatory` モードはアーカイブを優先することを意味します。このモードでは、アーカイブがユーザーのデータ書き込みに追いつかなかった場合、ユーザーが書き込めなくなる可能性があります。

      * `PIECE_SWITCH_INTERVAL` プロパティはPieceの切り替えサイクルを設定するために使用され、値の範囲は `[1d, 7d]` です。設定しない場合、デフォルトは `1d` です。

      アーカイブメディアがNFSの場合、スタンバイテナントのアーカイブパスを `file:///data/1/standby2_archive2/` とし、アーカイブモードを `Optional` とした例は以下のとおりです：

      ```shell
      obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=file:///data/1/standby2_archive2/ BINDING=optional' TENANT = standby2;
      ```

      ```shell
      obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=file:///data/1/standby2_archive2/ BINDING=optional';
      ```

   3. スタンバイテナントでアーカイブモードを有効にします。

      * スタンバイテナントが所属するクラスタの `sys` テナントで、スタンバイテナントのアーカイブモードを有効にします

        例：

        ```shell
        obclient> ALTER SYSTEM ARCHIVELOG TENANT = standby2;
        ```

        ここで、`standby2` はスタンバイテナント名であり、実際の環境に基づいて操作を行ってください。

      * スタンバイテナント自身のアーカイブモードを有効にします

        ```shell
        obclient> ALTER SYSTEM ARCHIVELOG;
        ```

   4. スタンバイテナントのアーカイブ状態が `DOING` になっているかどうかを確認します。

      * スタンバイテナントが所属するクラスタの `sys` テナントでビューを照会します

        ```shell
        obclient> SELECT DEST_ID, ROUND_ID, DEST_NO, STATUS, CHECKPOINT_SCN, CHECKPOINT_SCN_DISPLAY, PATH FROM oceanbase.CDB_OB_ARCHIVELOG;
        ```

      * スタンバイテナントでビューを照会します

        MySQLモード：

        ```shell
        obclient> SELECT DEST_ID, ROUND_ID, DEST_NO, STATUS, CHECKPOINT_SCN, CHECKPOINT_SCN_DISPLAY, PATH FROM oceanbase.DBA_OB_ARCHIVELOG;
        ```

        Oracleモード：

        ```shell
        obclient> SELECT DEST_ID, ROUND_ID, DEST_NO, STATUS, CHECKPOINT_SCN, CHECKPOINT_SCN_DISPLAY, PATH FROM SYS.DBA_OB_ARCHIVELOG;
        ```

        MySQLモードでの照会結果の例は以下のとおりです：

        ```shell
        +---------+----------+---------+--------+---------------------+----------------------------+---------------------------------------+
        | DEST_ID | ROUND_ID | DEST_NO | STATUS | CHECKPOINT_SCN      | CHECKPOINT_SCN_DISPLAY     | PATH                                 -|
        +---------+----------+---------+--------+---------------------+----------------------------+---------------------------------------+
        |    1001 |        1 |       0 | DOING  | 1680265982125159110 | 2023-03-31 20:33:02.125159 | file:///data/1/standby2_archive2      -|
        +---------+----------+---------+--------+---------------------+----------------------------+---------------------------------------+
        1 row in set
        ```

      照会結果によると、`STATUS` の値が `DOING` の場合、アーカイブが正常に動作していることを示し、`CHECKPOINT_SCN` と `CHECKPOINT_SCN_DISPLAY` は現在のアーカイブ進捗情報を表します。

      アーカイブ状態の詳細な操作については、[アーカイブ進捗の確認](../../../600.backup-and-recovery/300.log-archive/600.view-log-archive-progress.md)を参照してください。

2. プライマリテナントをスタンバイテナントに切り替えます。

   1. プライマリテナントまたはその所属クラスタの `sys` テナントのテナント管理者がデータベースにログインします。

   2. `SWITCHOVER TO STANDBY VERIFY` コマンドを実行して、`SWITCHOVER` コマンドが正常に実行できるかどうかを検証します。

      * プライマリテナントが所属するクラスタの `sys` テナントで `SWITCHOVER TO STANDBY VERIFY` コマンドを実行します

        ```sql
        ALTER SYSTEM SWITCHOVER TO STANDBY TENANT [=] tenant_name VERIFY;
        ```

        例：

        ```shell
        obclient> ALTER SYSTEM SWITCHOVER TO STANDBY TENANT = mysql2 VERIFY;
        ```

      * プライマリテナントで `SWITCHOVER TO STANDBY VERIFY` コマンドを実行します

        ```shell
        obclient> ALTER SYSTEM SWITCHOVER TO STANDBY VERIFY;
        ```

        コマンドを実行した後、`OK` が返された場合、検証に成功し、次のステップを実行できます。

        エラーが発生した場合は、メッセージのテキスト情報に基づいてドキュメント [SwitchoverまたはFailover関連の問題](../../../1000.troubleshooting/800.physical-standby-database/200.switchover-failed.md) を参照して処理し、その後、このコマンドを再度実行してください。

   3. 検証が成功した後、プライマリからスタンバイへの切り替えコマンドを実行して、プライマリテナントをスタンバイテナントに切り替えます。

      * プライマリテナントが所属するクラスタの `sys` テナントで、プライマリテナントをスタンバイテナントに切り替えます

        ```shell
        obclient> ALTER SYSTEM SWITCHOVER TO STANDBY TENANT = tenant_name；
        ```

        例：

        ```shell
        obclient> ALTER SYSTEM SWITCHOVER TO STANDBY TENANT = mysql2;
        ```

      * プライマリテナントで、自身のテナントをスタンバイテナントに切り替えます

        ```shell
        obclient> ALTER SYSTEM SWITCHOVER TO STANDBY；
        ```

   3. `DBA_OB_TENANTS` ビューを照会して、プライマリテナントがスタンバイテナントに切り替えられたかどうかを確認します。

      * プライマリテナントが所属するクラスタの `sys` テナントでビューを照会します

        ```shell
        obclient> SELECT TENANT_ID, TENANT_NAME,TENANT_TYPE,TENANT_ROLE,SWITCHOVER_STATUS
        FROM oceanbase.DBA_OB_TENANTS
        WHERE TENANT_NAME='mysql2';
        ```

      * プライマリテナントでビューを照会します

        MySQLモード：

        ```shell
        obclient> SELECT TENANT_ID, TENANT_NAME,TENANT_TYPE,TENANT_ROLE,SWITCHOVER_STATUS
        FROM oceanbase.DBA_OB_TENANTS
        WHERE TENANT_NAME='mysql2';
        ```

        Oracleモード：

        ```shell
        obclient> SELECT TENANT_ID, TENANT_NAME,TENANT_TYPE,TENANT_ROLE,SWITCHOVER_STATUS
        FROM SYS.DBA_OB_TENANTS
        WHERE TENANT_NAME='mysql2';
        ```

       照会結果の例は以下のとおりです：

       ```shell
       +-----------+-------------+-------------+-------------+-------------------+
       | TENANT_ID | TENANT_NAME | TENANT_TYPE | TENANT_ROLE | SWITCHOVER_STATUS |
       +-----------+-------------+-------------+-------------+-------------------+

       ```

      照会結果によると、プライマリテナントの `TENANT_ROLE` が `STANDBY` に変更され、かつ `SWITCHOVER_STATUS` が `NORMAL` になった場合、プライマリからスタンバイへの切り替えに成功したことを示します。

   4. `V$OB_ARCHIVE_DEST_STATUS` ビューの `SYNCHRONIZED` フィールドを照会して、プライマリテナントのアーカイブが完了するのを待機します。

      ログアーカイブに基づく物理スタンバイリースのシナリオでは、スタンバイテナントがプライマリテナントに切り替わる前に、元のプライマリテナントのログアーカイブから完全なログを読み取る必要があります。ログアーカイブは非同期同期モードであるため、元のプライマリテナントがスタンバイテナントに切り替わった後、元のプライマリテナント上のログアーカイブが完全であるかどうかを確認する必要があります。

      * MySQLモード

        ```shell
        obclient> SELECT * FROM oceanbase.V$OB_ARCHIVE_DEST_STATUS WHERE TENANT_ID = 1004;
        ```

      * Oracleモード

        ```shell
        obclient> SELECT * FROM SYS.V$OB_ARCHIVE_DEST_STATUS WHERE TENANT_ID = 1004;
        ```

      MySQLモードでの照会結果の例は以下のとおりです：

      ```shell
      +-----------+---------+--------------------------------+--------+---------------------+--------------+---------+
      | TENANT_ID | DEST_ID | PATH                           | STATUS | CHECKPOINT_SCN      | SYNCHRONIZED | COMMENT |
      +-----------+---------+--------------------------------+--------+---------------------+--------------+---------+
      |      1004 |    1001 | file:///data/1/sh_archive      | DOING  | 1684638569520797277 | YES          |         |
      +-----------+---------+--------------------------------+--------+---------------------+--------------+---------+
      1 row in set
      ```

      照会結果によると、`SYNCHRONIZED` フィールドが `YES` と表示されている場合、プライマリテナントのアーカイブが完了したことを示します。

      <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>スタンバイからプライマリへの切り替えを行う前に、<code>SYNCHRONIZED</code> フィールドが <code>YES</code> と表示されていることを確認する必要があります。そうでない場合、スタンバイからプライマリへの切り替え操作を実行した後、Switchover後の新しいプライマリテナントのデータが不完全になる可能性があります。</p>
      </main>

3. スタンバイテナントをプライマリテナントに切り替えます。

   1. スタンバイテナントまたはその所属クラスタの `sys` テナントのテナント管理者がデータベースにログインします。

   2. `SWITCHOVER TO PRIMARY VERIFY` コマンドを実行して、`SWITCHOVER` コマンドが正常に実行できるかどうかを検証します。

      * スタンバイテナントが所属するクラスタの `sys` テナントで `SWITCHOVER TO PRIMARY VERIFY` コマンドを実行します

        ```sql
        ALTER SYSTEM SWITCHOVER TO PRIMARY TENANT [=] tenant_name VERIFY;
        ```

        例：

        ```shell
        obclient> ALTER SYSTEM SWITCHOVER TO PRIMARY TENANT = standby2 VERIFY;
        ```

      * スタンバイテナントで `SWITCHOVER TO PRIMARY VERIFY` コマンドを実行します

        ```shell
        obclient> ALTER SYSTEM SWITCHOVER TO PRIMARY VERIFY;
        ```

        コマンドを実行した後、`OK` が返された場合、検証に成功し、次のステップを実行できます。

        エラーが発生した場合は、メッセージのテキスト情報に基づいてドキュメント [SwitchoverまたはFailover関連の問題](../../../1000.troubleshooting/800.physical-standby-database/200.switchover-failed.md) を参照して処理し、その後、このコマンドを再度実行してください。

   3. 検証が成功した後、スタンバイからプライマリへの切り替えコマンドを実行して、スタンバイテナントをプライマリテナントに切り替えます。

      <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>スタンバイからプライマリへの切り替えコマンドが開始される前に、システムはスタンバイテナントが復旧ソース側のすべてのログに同期されているかどうかをチェックします。そのため、スタンバイからプライマリへの切り替えコマンドの実行時間は、スタンバイテナントとプライマリテナントの同期進捗に依存します。</p>
      </main>

      * スタンバイテナントが所属するクラスタの `sys` テナントで、スタンバイテナントをプライマリテナントに切り替えます

        ```shell
        obclient> ALTER SYSTEM SWITCHOVER TO PRIMARY TENANT = tenant_name；
        ```

        例：

        ```shell
        obclient> ALTER SYSTEM SWITCHOVER TO PRIMARY TENANT = standby2;
        ```

      * スタンバイテナントで、自身のテナントをプライマリテナントに切り替えます

        ```shell
        obclient> ALTER SYSTEM SWITCHOVER TO PRIMARY;
        ```

   3. `DBA_OB_TENANTS` ビューを照会して、スタンバイテナントがプライマリテナントに切り替えられたかどうかを確認します。

      * スタンバイテナントが所属するクラスタの `sys` テナントでビューを照会します

        ```shell
        obclient> SELECT TENANT_ID, TENANT_NAME,TENANT_TYPE,TENANT_ROLE,SWITCHOVER_STATUS
        FROM oceanbase.DBA_OB_TENANTS
        WHERE TENANT_NAME='standby2';
        ```

      * プライマリテナントでビューを照会します

        MySQLモード：

        ```shell
        obclient> SELECT TENANT_ID, TENANT_NAME,TENANT_TYPE,TENANT_ROLE,SWITCHOVER_STATUS
        FROM oceanbase.DBA_OB_TENANTS
        WHERE TENANT_NAME='standby2'';
        ```

        Oracleモード：

        ```shell
        obclient> SELECT TENANT_ID, TENANT_NAME,TENANT_TYPE,TENANT_ROLE,SWITCHOVER_STATUS
        FROM SYS.DBA_OB_TENANTS
        WHERE TENANT_NAME='standby2'';
        ```

      照会結果の例は以下のとおりです：

      ```shell
      +-----------+----------------------------+-------------+-------------+-------------------+
      | TENANT_ID | TENANT_NAME                | TENANT_TYPE | TENANT_ROLE | SWITCHOVER_STATUS |
      +-----------+----------------------------+-------------+-------------+-------------------+
      |      1006 | standby2                   | USER        | PRIMARY     | NORMAL            |
      +-----------+----------------------------+-------------+-------------+-------------------+
      1 row in set
      ```

      照会結果によると、スタンバイテナントの `TENANT_ROLE` が `PRIMARY` に変更され、かつ `SWITCHOVER_STATUS` が `NORMAL` になった場合、スタンバイからプライマリへの切り替えに成功したことを示します。

4. 新しいスタンバイテナント（元のプライマリテナント）の復旧ソースを設定し、新しいプライマリテナントのアーカイブログを受信します。

   元のプライマリテナントが切り替え操作を実行する前に、ログ復旧ソースを設定していない場合、そのログ同期ポイントは切り替え操作の実行時刻に固定されます。そのため、元のプライマリテナントにログ復旧ソースを設定し、ログ復旧ソースを新しいプライマリテナントに指す必要があります。

   ログ復旧ソースの設定は、プライマリとスタンバイの切り替え操作の前に実行することができ、また切り替え操作の後に実行することもできます。

   1. 新しいスタンバイテナント（元のプライマリテナント）またはその所属クラスタの `sys` テナントのテナント管理者がデータベースにログインします。

   2. 以下のコマンドを実行して、新しいスタンバイテナント（元のプライマリテナント）の復旧ソースを設定します。

      * 新しいスタンバイテナントが所属するクラスタの `sys` テナントで、新しいスタンバイテナントの復旧ソースを設定します

        ```shell
        ALTER SYSTEM SET LOG_RESTORE_SOURCE ='LOCATION=archive_path' TENANT = tenant_name;
        ```

      * 新しいスタンバイテナントで、自身のテナントの復旧ソースを設定します

        ```shell
        ALTER SYSTEM SET LOG_RESTORE_SOURCE ='LOCATION=archive_path';
        ```

      ここで、`LOCATION` プロパティは新しいプライマリテナントのアーカイブ宛先を指定するために使用されます。

      例：

      ```shell
      obclient> ALTER SYSTEM SET LOG_RESTORE_SOURCE ='LOCATION=file:///data/1/standby2/archive2' TENANT = mysql2;

      obclient> ALTER SYSTEM SET LOG_RESTORE_SOURCE ='LOCATION=file:///data/1/standby2/archive2';
      ```

   3. 設定が成功した後、`DBA_OB_TENANTS` ビューを照会して、元のプライマリテナントが継続的にログを同期しているかどうかを確認します。

      ログ復旧ソースを設定した後、プライマリテナントがスタンバイテナントに切り替わると、自動的にログの継続的な同期が開始されるため、特別な処理は不要です。`DBA_OB_TENANTS` ビューを照会することで確認できます。

      * 元のプライマリテナントが所属するクラスタの `sys` テナントでビューを照会します

        ```shell
        obclient> SELECT TENANT_NAME, TENANT_TYPE, TENANT_ROLE, SWITCHOVER_STATUS, SCN_TO_TIMESTAMP(SYNC_SCN), RECOVERY_UNTIL_SCN FROM oceanbase.DBA_OB_TENANTS;
        ```

      * 元のプライマリテナントでビューを照会します

        MySQLモード：

        ```shell
        obclient> SELECT TENANT_NAME, TENANT_TYPE, TENANT_ROLE, SWITCHOVER_STATUS, SCN_TO_TIMESTAMP(SYNC_SCN), RECOVERY_UNTIL_SCN FROM oceanbase.DBA_OB_TENANTS;
        ```

        Oracleモード：

        ```shell
        obclient> SELECT TENANT_NAME, TENANT_TYPE, TENANT_ROLE, SWITCHOVER_STATUS, SCN_TO_TIMESTAMP(SYNC_SCN), RECOVERY_UNTIL_SCN FROM SYS.DBA_OB_TENANTS;
        ```

      MySQLモードでの照会結果は以下のとおりです：

      ```shell
      +-------------+-------------+-------------+-------------------+----------------------------+---------------------+
      | TENANT_NAME | TENANT_TYPE | TENANT_ROLE | SWITCHOVER_STATUS | SCN_TO_TIMESTAMP(SYNC_SCN) | RECOVERY_UNTIL_SCN  |
      +-------------+-------------+-------------+-------------------+----------------------------+---------------------+
      | mysql2      | USER        | STANDBY     | NORMAL            | 2023-05-21 11:41:46.432851 | 4611686018427387903 |
      +-------------+-------------+-------------+-------------------+----------------------------+---------------------+
      ```

      照会結果によると、`RECOVERY_UNTIL_SCN` 列の値がMAX SCN（4611686018427387903）の値と等しい場合、元のプライマリテナントが継続的にログを同期していることを示し、そうでない場合、元のプライマリテナントは継続的にログを同期していないことを示します。
