# プライマリ/スタンバイテナントの削除

現在のバージョンでは、プライマリテナントとスタンバイテナントはどちらも明示的に作成されるため、テナントを削除する際には、プライマリテナントとスタンバイテナントをそれぞれ明示的に削除する必要があります。

## 注意事項

プライマリテナントとスタンバイテナントはそれぞれ独立しているため、スタンバイテナントを削除してもプライマリテナントには影響しません。しかし、プライマリテナントを削除する際、スタンバイテナントがまだ削除されていない場合、プライマリテナントの削除方法に応じて、スタンバイテナントの同期動作が若干異なります。具体的な動作は以下のとおりです：

* `DROP TENANT` ステートメントでプライマリテナントを削除する場合

  * プライマリテナントの削除状態：システムテナントでリサイクルビン機能が有効な場合、削除されたプライマリテナントはリサイクルビンに移動し、後からシステムテナントによってさらにクリーンアップまたは復元することが可能です。システムテナントでリサイクルビン機能が無効な場合、プライマリテナントは直接削除されます。

  * スタンバイテナントの同期状態：プライマリテナントがリサイクルビンに移動した場合、スタンバイテナントの同期状態に影響はなく、ログの同期を続けます。プライマリテナントが直接削除されたり、システムテナントによってリサイクルビンからクリーンアップされたりした場合、スタンバイテナントはプライマリテナントの削除またはクリーンアップの動作を同期した後、直ちにログ同期を停止します。

* `DROP TENANT FORCE` ステートメントでプライマリテナントを削除する場合

  * プライマリテナントの削除状態：システムテナントでリサイクルビン機能が有効かどうかに関わらず、プライマリテナントは即座に削除されます。

  * スタンバイテナントの同期状態：

    * ログアーカイブを利用する物理スタンバイデータベースの場合、スタンバイテナントはプライマリテナントのすべてのアーカイブ済みログを同期した後、ログ同期を停止します。

    * ネットワークを利用する物理スタンバイデータベースの場合、スタンバイテナントはプライマリテナントが削除された直後にログ同期を停止します。

## 操作手順

スタンバイテナントの削除方法はプライマリテナントの削除方法と同じで、どちらも `DROP TENANT` コマンドを使用して実行します。

1. `root` ユーザーで、プライマリテナントまたはスタンバイテナントが存在するクラスタの `sys` テナントにログインします。

2. 以下のコマンドを実行して、プライマリテナントまたはスタンバイテナントを削除します。

   * `DROP TENANT` ステートメントでテナントを削除する

     ```sql
     DROP TENANT tenant_name;
     ```

   * `DROP TENANT FORCE` ステートメントでテナントを削除する

     ```sql
     DROP TENANT tenant_name FORCE;
     ```

テナント削除の詳細な操作手順および説明については、[テナントの削除](../../200.tenant-management/600.common-tenant-operations/1200.delete-tenant.md)を参照してください。
