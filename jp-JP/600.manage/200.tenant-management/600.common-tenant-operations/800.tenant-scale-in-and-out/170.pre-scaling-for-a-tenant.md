# テナントの事前スケーリングアウト

テナントのスムーズなスケーリングをさらに実現するため、OceanBaseデータベースでは事前スケーリングアウト機能が導入されています。この機能は、テナントのスケールインからスケールアウトまでに必要なスケーリングアウト係数（ls_scale_out_factor）を設定し、スケールアウト後にも対応可能な状態と位置になるよう、十分な数のログストリームを事前に生成します。その後、テナントのスケールアップまたはスケールダウン操作を開始することで、スムーズなスケーリングを実現します。

## 背景情報

V4.x以前のバージョンでは、OceanBaseデータベースはテナントの同一構成ゾーンモードのみをサポートしており、同一構成ゾーンモードでは、テナント内の各ゾーンの`UNIT_NUM`が同一である必要がありました。V4.2.5バージョンから、OceanBaseデータベースはV4.2.5 BP5バージョン以降、テナントの異構成ゾーンモードをサポートし始めました。異構成ゾーンモードでは、テナント内の各ゾーンの`UNIT_NUM`は同一でも異なっても構いませんが、1つのテナントのすべてのゾーンにおける`UNIT_NUM`は最大で2種類までとなります。

本記事では主に同一構成ゾーンモードのテナントを例に、テナントの事前スケールアップ操作のガイドを提供します。異構成ゾーンモードのテナントについては、異構成ゾーンの運用保守手法を用いてスムーズなスケーリングを実現することを推奨します。異構成ゾーンを利用したスムーズなスケーリングのユースケースについては、[スムーズなスケーリングのユースケース](800.application-cases-of-smooth-scaling-in-and-out.md)を参照してください。

## 制限事項

V4.2.5バージョンでは、V4.2.5 BP1バージョン以降、事前スケールアップ機能がサポートされています。

## スケールアップ係数の紹介

以前のバージョンでは、1つのテナントが1つのノード上で提供するログストリームは1つだけでした。ノード内に十分な数のログストリームが存在する場合、スケールアップ時にログストリームの位置の再配置を直接トリガーでき、Transferを通じてログストリームを分割する必要はありませんでした。

スケールアップ前に十分な数のログストリームが存在するかどうかを定義するため、OceanBaseデータベースはスケールアップ係数（ls_scale_out_factor）という概念を導入しました。スケールアップ係数とは、今後のスケールアップニーズを満たすために、1つのログストリームが分割する必要があるログストリームの数を指します。

### スケールアップ係数の計算式

OceanBaseデータベースにおいて、同一構成ゾーンモードのテナントについて、各Unit Group上のテナントの通常ログストリーム数（システムログストリームおよびブロードキャストログストリームを除く）は次のとおりです：`テナントのUNIT_NUMの数（U）× テナントのPRIAMRY_ZONEの第一優先順位の数（P）`。

スケールアップ前に、テナントの`UNIT_NUM`の数をU1、テナントの`PRIAMRY_ZONE`の第一優先順位の数をP1と仮定します。スケールアップ後、テナントの`UNIT_NUM`の数をU2、テナントの`PRIAMRY_ZONE`の第一優先順位の数をP2とします。この場合、スケールアップ係数（ls_scale_out_factor）の計算式は以下のとおりです：

`ls_scale_out_factor = LCM（U1 * p1 , U2 * P2 ）/ (U1 * P1)`

つまり、`(U1 * p1)`と`(U2 * P2)`の2つの値の最小公倍数を`(U1 * P1)`で割ることで、そのテナントのスケールアップ係数を求めることができます。

## 事前スケーリングアウト

現在、同一構成のZoneモードのテナント`mq_t1`があり、そのローカリティは`F@zone1, F@zone2, F@zone3`で、各Zoneに1つのUnitが配置されています。`PRIMARY_ZONE`は`zone1`と`zone2`に分散しています。今後、テナントの`UNIT_NUM`を2に調整し、テナントの`PRIMARY_ZONE`の第一優先順位の数を変更しないことを想定します。この場合、テナントに対する事前スケーリングアウトの手順は以下のとおりです。

1. `root`ユーザーでクラスタのsysテナントにログインします。

   接続例は以下のとおりです：

   ```shell
   obclient -h172.30.xxx.xxx -P2883 -uroot@sys#obdemo -pxxxx -A
   ```

2. テナント`mq_t1`の`TENANT_ID`、`UNIT_NUM`、`PRIAMRY_ZONE`などの情報を確認します。

   ```shell
   obclient> SELECT * FROM oceanbase.DBA_OB_TENANTS WHERE TENANT_NAME = 'mq_t1';
   ```

   クエリ結果は次のとおりです：

   ```shell
   +-----------+-------------+-------------+----------------------------+----------------------------+---------------------+---------------------------------------------+-------------------+--------------------+--------+---------------+--------+-------------+-------------------+------------------+---------------------+---------------------+---------------------+---------------------+--------------+----------------------------+----------+-------------------------+------------+-----------+
   | TENANT_ID | TENANT_NAME | TENANT_TYPE | CREATE_TIME                | MODIFY_TIME                | PRIMARY_ZONE        | LOCALITY                                    | PREVIOUS_LOCALITY | COMPATIBILITY_MODE | STATUS | IN_RECYCLEBIN | LOCKED | TENANT_ROLE | SWITCHOVER_STATUS | SWITCHOVER_EPOCH | SYNC_SCN            | REPLAYABLE_SCN      | READABLE_SCN        | RECOVERY_UNTIL_SCN  | LOG_MODE     | ARBITRATION_SERVICE_STATUS | UNIT_NUM | ZONE_UNIT_NUM_LIST      | COMPATIBLE | MAX_LS_ID |
   +-----------+-------------+-------------+----------------------------+----------------------------+---------------------+---------------------------------------------+-------------------+--------------------+--------+---------------+--------+-------------+-------------------+------------------+---------------------+---------------------+---------------------+---------------------+--------------+----------------------------+----------+-------------------------+------------+-----------+
   |      1002 | mq_t1       | USER        | 2024-11-22 15:35:13.392880 | 2024-11-22 15:35:31.923530 | zone1,zone2;zone3   | FULL{1}@zone1, FULL{1}@zone2, FULL{1}@zone3 | NULL              | MYSQL              | NORMAL | NO            | NO     | PRIMARY     | NORMAL            |                0 | 1732261018646683000 | 1732261018646683000 | 1732261018646683000 | 4611686018427387903 | NOARCHIVELOG | DISABLED                   |        1 | zone1:1,zone2:1,zone3:1 | 4.2.5.5    |      1002 |
   +-----------+-------------+-------------+----------------------------+----------------------------+---------------------+---------------------------------------------+-------------------+--------------------+--------+---------------+--------+-------------+-------------------+------------------+---------------------+---------------------+---------------------+---------------------+--------------+----------------------------+----------+-------------------------+-----------+-----------+
   1 row in set
   ```

3. スケーリングアウト係数`ls_scale_out_factor`の値を計算し、テナントのスケーリングアウト係数を設定します。

   この例では、テナント`mq_t1`のスケーリングアウト前の`UNIT_NUM`は1、`PRIAMRY_ZONE`の第一優先順位の数は2です。スケーリングアウト後、テナントの`UNIT_NUM`は2、`PRIMARY_ZONE`の第一優先順位の数は変更せずに引き続き2となります。スケーリングアウト係数の計算式に基づくと、そのスケーリングアウト係数は`LCM(2 * 1, 2 * 2)/(2 * 1) = 2`となります。

   計算したスケーリングアウト係数に基づいて、構成パラメータ[ls_scale_out_factor](../../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/5530.ls_scale_out_factor.md)の値を設定します。

   ```shell
   obclient> ALTER SYSTEM SET ls_scale_out_factor = 2 TENANT = mq_t1;
   ```

4. テナントレベルの構成パラメータ[enable_rebalance](../../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2900.enable_rebalance.md)と[enable_transfer](../../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3100.enable_transfer.md)の値をどちらも有効（`True`）に設定します。これにより、テナント内で十分な数のログストリームが生成されるようにします。

   ```shell
   obclient> ALTER SYSTEM SET enable_rebalance = True TENANT = mq_t1;
   ```

   ```shell
   obclient> ALTER SYSTEM SET enable_transfer = True TENANT = mq_t1;
   ```

5. テナントが十分な数のログストリームを生成した後、現在のテナントの`NORMAL`状態のログストリームの数が予想どおりかどうかを確認します。

   スケーリングアウト係数の公式に基づくと、スケーリングアウト後の現在のテナントの`NORMAL`状態（システムログストリームとブロードキャストログストリームを除く）のログストリームの数は、スケーリングアウト前のテナントの`UNIT_NUM`（U1）× スケーリングアウト前のテナントの`PRIAMRY_ZONE`の第一優先順位の数（P1）× スケーリングアウト係数（ls_scale_out_factor）となります。つまり、現在のテナントのログストリームの数は`1 * 2 * 2 = 4`となります。

   ```shell
   obclient> SELECT TENANT_ID, STATUS, COUNT(*) FROM oceanbase.CDB_OB_LS WHERE TENANT_ID = 1002 AND FLAG = '' AND LS_ID != 1 GROUP BY STATUS;
   ```

   クエリ結果の例は次のとおりです：

   ```shell
   +-----------+--------+----------+
   | TENANT_ID | STATUS | COUNT(*) |
   +-----------+--------+----------+
   |      1002 | NORMAL |        4 |
   +-----------+--------+----------+
   1 row in set
   ```

6. スケーリングアウト対象のテナントにロードバランシングタスクが残っていないことを確認します。

   ```shell
   obclient> SELECT * FROM oceanbase.CDB_OB_BALANCE_JOBS WHERE TENANT_ID = 1002;
   ```

   クエリ結果が空であれば、今回の事前スケーリングアウト操作が完了したことを意味します。
