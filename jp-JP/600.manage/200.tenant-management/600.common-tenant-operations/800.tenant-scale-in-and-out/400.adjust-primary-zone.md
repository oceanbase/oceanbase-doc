# Primary Zoneの調整によるテナントのスケーリング

テナントのスケーリングとは、本質的にはテナントのサービス能力、すなわち計算能力やストレージ容量を向上または低下させることです。これは、単一ノードのサービス能力を垂直方向に向上または低下させることで達成することもできますし、水平方向に向上または低下させることでも達成できます。本記事では、Primary Zoneを変更することで、計算ノードを水平方向に増減し、テナント全体のサービス能力を向上または低下させ、テナントのスケールアップまたはスケールダウンを実現する方法について説明します。

## 前提条件

Primary Zoneを調整する前に、テナント内のロードバランシングポリシーを設定する必要があります。テナント内のロードバランシングポリシーは、テナントレベルの構成パラメータである`enable_rebalance`と`enable_transfer`によって共同で制御されます。

構成パラメータ`enable_rebalance`は、システムテナントではテナント間のロードバランシングを行うかどうかを制御し、ユーザーテナントではテナント内のロードバランシングを行うかどうかを制御します。デフォルト値は`true`であり、設定後はOBServerノードの再起動なしで即時に反映されます。

構成パラメータ`enable_transfer`は、テナント内のTransfer機能を有効にするかどうかを制御します。デフォルト値は`true`であり、設定後はOBServerノードの再起動なしで即時に反映されます。構成パラメータ`enable_transfer`の値の意味は、構成パラメータ`enable_rebalance`の値に依存します：

* パラメータ`enable_rebalance`の値が`false`の場合、パラメータ`enable_transfer`の値が`true`であっても`false`であっても、システムは自動ロードバランシングを行いません。

* パラメータ`enable_rebalance`の値が`true`かつ`enable_transfer`の値も`true`の場合、テナントのスケーリング操作時にシステムが自動的にパーティションの分布を調整し、ロードバランシングを実現することを意味します。

* パラメータ`enable_rebalance`の値が`true`かつ`enable_transfer`の値が`false`の場合、テナントのスケーリング操作時にシステムがTransfer操作を開始できず、ログストリーム移行によって限られたバランシングしか実現できないことを意味します。

具体的な設定方法は以下の通りです：

* システムテナントで指定テナントのロードバランシングポリシーを設定する

  * システムテナントで指定テナントのテナント内ロードバランシングおよびテナント内Transfer機能を有効にする

    ```shell
    obclient(root@sys)[(none)]> ALTER SYSTEM SET enable_rebalance = true TENANT = 'tenant_name';
    ```

    ```shell
    obclient(root@sys)[(none)]> ALTER SYSTEM SET enable_transfer = true TENANT = 'tenant_name';
    ```

    上記のステートメントは、指定テナントの構成パラメータ`enable_rebalance`と`enable_transfer`の値を`true`に設定することを意味します。

  * システムテナントで`sys`テナントおよびMetaテナントを除くすべてのユーザーテナントのテナント内ロードバランシングおよびテナント内Transfer機能を有効にする

    ```shell
    obclient(root@sys)[(none)]> ALTER SYSTEM SET enable_rebalance = true TENANT = all_user;
    ```

    ```shell
    obclient(root@sys)[(none)]> ALTER SYSTEM SET enable_transfer = true TENANT = all_user;
    ```

    または

    ```shell
    obclient(root@sys)[(none)]> ALTER SYSTEM SET enable_rebalance = true TENANT = all;
    ```

    ```shell
    obclient(root@sys)[(none)]> ALTER SYSTEM SET enable_transfer = true TENANT = all;
    ```

    上記のステートメントは、すべてのユーザーテナントの構成パラメータ`enable_rebalance`と`enable_transfer`の値を`true`に設定することを意味します。

    <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>OceanBaseデータベースはV4.2.1バージョンから、<code>TENANT = all_user</code>と<code>TENANT = all</code>は同じ意味になりました。有効範囲がすべてのユーザーテナントになる場合は、<code>TENANT = all_user</code>の使用を推奨します。<code>TENANT = all</code>は今後廃止され、使用されなくなります。</p>
    </main>

* ユーザーテナントで自身のテナントのロードバランシングポリシーを設定する

    :::tab
    タブ MySQLモード

    MySQLテナントで、このテナントのテナント内ロードバランシングとテナント内のTransfer機能を有効にするステートメントは以下のとおりです：

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM SET enable_rebalance = true;
    ```

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM SET enable_transfer = true;
    ```

    tab Oracleモード

    Oracleテナントで、そのテナント内のロードバランシングおよびテナント内のTransfer機能を有効にするステートメントは以下のとおりです：

    ```shell
    obclient(SYS@oralce001)[SYS]> ALTER SYSTEM SET enable_rebalance = 'true';
    ```

    ```shell
    obclient(SYS@oracle001)[SYS]> ALTER SYSTEM SET enable_transfer = 'true';
    ```

    :::

詳細な構成パラメータ`enable_rebalance`と`enable_transfer`の説明については、[enable_rebalance](../../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2900.enable_rebalance.md)および[enable_transfer](../../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3100.enable_transfer.md)を参照してください。

## プライマリゾーンの追加

1. `root`ユーザーでクラスタの`sys`テナントにログインします。

    ```shell
    obclient -h172.30.xxx.xxx -P2883 -uroot@sys#obdemo -pxxxx -A
    ```

2. `oceanbase`データベースに移動します。

    ```shell
    obclient(root@sys)[(none)]> use oceanbase;
    ```

3. テナント`mysql001`の基本情報、例えば`TENANT_ID`や`PRIMARY_ZONE`などの情報を照会します。

   ```shell
   obclient(root@sys)[oceanbase]> SELECT TENANT_ID, TENANT_NAME, PRIMARY_ZONE FROM oceanbase.DBA_OB_TENANTS WHERE TENANT_NAME = 'mysql001';
   ```

   クエリ結果は次のとおりです：

   ```shell
   +-----------+-------------+--------------+
   | TENANT_ID | TENANT_NAME | PRIMARY_ZONE |
   +-----------+-------------+--------------+
   |      1004 | mysql001    | zone1;zone2  |
   +-----------+-------------+--------------+
   1 row in set
   ```

   クエリ結果から、テナント`mysql001`の`TENANT_ID`は1004であり、`PRIMARY_ZONE`の第一優先順位は`zone1`であることがわかります。

4. テナント`mysql001`の現在のログストリームリーダー複製の配置情報を照会します。

   ```shell
   obclient(root@sys)[oceanbase]> SELECT TENANT_ID, LS_ID, SVR_IP, SVR_PORT, ZONE, ROLE, REPLICA_TYPE FROM oceanbase.CDB_OB_LS_LOCATIONS WHERE TENANT_ID = 1004 AND LS_ID != 1 AND ROLE = 'LEADER';
   ```

   クエリ結果は次のとおりです：

   ```shell
   +-----------+-------+---------------+----------+--------+--------+--------------+
   | TENANT_ID | LS_ID | SVR_IP        | SVR_PORT | ZONE   | ROLE   | REPLICA_TYPE |
   +-----------+-------+---------------+----------+--------+--------+--------------+
   |      1004 |  1001 | 172.xx.xxx.xx |    2882  |  zone1 | LEADER | FULL         |
   |      1004 |  1012 | 172.xx.xxx.xx |    2882  |  zone1 | LEADER | FULL         |
   +-----------+-------+---------------+----------+--------+--------+--------------+
   2 rows in set
   ```

   クエリ結果から、テナント`mysql001`には2つのリーダー複製がサービスを提供しており、それらはzone1の2台のマシンに均等に分散されていることがわかります。

5. テナント`mysql001`の`PRIMARY_ZONE`プロパティを変更し、第一優先順位ゾーンの数を1から2に調整します。

   ```shell
   obclient(root@sys)[oceanbase]> ALTER TENANT mysql001 PRIMARY_ZONE='zone1,zone2';
   ```

6. プライマリゾーン追加タスクの実行状態を確認します。

   ```shell
   obclient(root@sys)[oceanbase]> SELECT * FROM oceanbase.DBA_OB_TENANT_JOBS WHERE JOB_TYPE='ALTER_TENANT_PRIMARY_ZONE' AND TENANT_ID = 1004;
   ```

   クエリ結果は次のとおりです：

   ```shell
   +--------+---------------------------+------------+-------------+----------+----------------------------+----------------------------+-----------+--------------------------------------------------+----------------------------------------+----------------+-------------+
   | JOB_ID | JOB_TYPE                  | JOB_STATUS | RESULT_CODE | PROGRESS | START_TIME                 | MODIFY_TIME                | TENANT_ID | SQL_TEXT                                         | EXTRA_INFO                             | RS_SVR_IP      | RS_SVR_PORT |
   +--------+---------------------------+------------+-------------+----------+----------------------------+----------------------------+-----------+--------------------------------------------------+----------------------------------------+----------------+-------------+
   |      4 | ALTER_TENANT_PRIMARY_ZONE | SUCCESS    |           0 |      100 | 2024-12-18 17:26:00.069089 | 2024-12-18 17:26:20.919021 |      1004 | ALTER TENANT mysql001 PRIMARY_ZONE='zone1,zone2' | FROM: 'zone1;zone2', TO: 'zone1,zone2' | 172.xx.xxx.xx  |       2882  |
   +--------+---------------------------+------------+-------------+----------+----------------------------+----------------------------+-----------+--------------------------------------------------+----------------------------------------+----------------+-------------+
   1 row in set
   ```

   クエリ結果に基づき、以下のフィールドに従って対応するタスクレコードを見つけます：

   * `START_TIME`：タスクの開始時間。
   * `SQL_TEXT`：タスクに対応するSQL文。
   * `EXTRA_INFO`：変更前後のプライマリゾーン情報。

   対応するタスクレコードの`JOB_STATUS`値が`SUCCESS`の場合、プライマリゾーンの追加タスクが正常に実行されたことを示します。

   ビュー`DBA_OB_TENANT_JOBS`の詳細フィールドの説明については、[DBA_OB_TENANT_JOBS](../../../../700.reference/700.system-views/300.system-view-of-sys-tenant/200.dictionary-view-of-sys-tenant/22100.o-dba_ob_tenant_jobs-of-sys-tenant.md)を参照してください。

7. テナント`mysql001`の基本情報を照会し、`PRIMARY_ZONE`プロパティの変更が成功したことを確認します。第一優先順位は`zone1`から`zone1,zone2`に変更されました。

   ```shell
   obclient(root@sys)[oceanbase]> SELECT PRIMARY_ZONE FROM oceanbase.DBA_OB_TENANTS WHERE TENANT_ID = 1004;
   ```

   クエリ結果は次のとおりです：

   ```shell
   +--------------+
   | PRIMARY_ZONE |
   +--------------+
   | zone1,zone2  |
   +--------------+
   1 row in set
   ```

8. 再びテナント`mysql001`のログストリームリーダー複製の配置情報を照会します。

   ```shell
   obclient(root@sys)[oceanbase]> SELECT TENANT_ID, LS_ID, SVR_IP, SVR_PORT, ZONE, ROLE, REPLICA_TYPE FROM oceanbase.CDB_OB_LS_LOCATIONS WHERE TENANT_ID = 1004 AND LS_ID != 1 AND ROLE = 'LEADER';
   ```

   クエリ結果は次のとおりです：

   ```shell
   +-----------+-------+---------------+----------+-------+--------+--------------+
   | TENANT_ID | LS_ID | SVR_IP        | SVR_PORT | ZONE  | ROLE   | REPLICA_TYPE |
   +-----------+-------+---------------+----------+-------+--------+--------------+
   |      1004 |  1001 | 172.xx.xxx.xx |    2882  | zone1 | LEADER | FULL         |
   |      1004 |  1012 | 172.xx.xxx.xx |    2882  | zone1 | LEADER | FULL         |
   |      1004 |  1013 | 172.xx.xxx.xx |    2882  | zone2 | LEADER | FULL         |
   |      1004 |  1014 | 172.xx.xxx.xx |    2882  | zone2 | LEADER | FULL         |
   +-----------+-------+---------------+----------+-------+--------+--------------+
   4 rows in set
   ```

   クエリ結果から、テナント`mysql001`にはzone1とzone2にそれぞれ2つのリーダー複製があり、合計4つのリーダー複製がサービスを提供していることがわかります。

上記の例では、変更前にテナント`mysql001`の`PRIMARY_ZONE`の第一優先順位ゾーンの数は1で、2つのリーダー複製がサービスを提供していました。変更後、テナント`mysql001`の`PRIMARY_ZONE`の第一優先順位ゾーンの数は1から2に変更され、サービスを提供するリーダー複製は2から4に増加し、計算ノードが追加されることで、テナントの拡張が実現されました。

    ```shell
    obclient -h172.30.xxx.xxx -P2883 -uroot@sys#obdemo -pxxxx -A
    ```

2. `oceanbase`データベースに移動します。

    ```shell
    obclient(root@sys)[(none)]> use oceanbase;
    ```

3. テナント`mysql001`の基本情報、例えば`TENANT_ID`や`PRIMARY_ZONE`などの情報を照会します。

   ```shell
   obclient(root@sys)[oceanbase]>  SELECT TENANT_ID, TENANT_NAME, PRIMARY_ZONE FROM oceanbase.DBA_OB_TENANTS WHERE TENANT_NAME = 'mysql001';
   ```

   クエリ結果は次のとおりです：

   ```shell
   +-----------+-------------+--------------+
   | TENANT_ID | TENANT_NAME | PRIMARY_ZONE |
   +-----------+-------------+--------------+
   |      1004 | mysql001    | zone1,zone2  |
   +-----------+-------------+--------------+
   1 row in set
   ```

   クエリ結果から、テナント`mysql001`の`TENANT_ID`は1004であり、`PRIMARY_ZONE`の第一優先順位は`zone1`と`zone2`であることがわかります。

4. テナント`mysql001`の現在のログストリームリーダー複製の配置情報を照会します。


   ```shell
   +-----------+-------+---------------+----------+-------+--------+--------------+
   | TENANT_ID | LS_ID | SVR_IP        | SVR_PORT | ZONE  | ROLE   | REPLICA_TYPE |
   ```

上記の例では、変更前にテナント`mysql001`の`PRIMARY_ZONE`の第一優先順位ゾーンの数は2で、4つのリーダー複製がサービスを提供していました。変更後、テナント`mysql001`の`PRIMARY_ZONE`の第一優先順位ゾーンの数は2から1に変更され、サービスを提供するリーダー複製は4から2に変更され、計算ノードが削減され、テナントのスケールダウンが実現されました。
