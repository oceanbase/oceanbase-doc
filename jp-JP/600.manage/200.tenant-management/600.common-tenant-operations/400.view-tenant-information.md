# テナントとリソース情報の確認

本記事では、ビューを使用してテナントおよびリソースの関連情報を確認する方法について説明します。

## テナントのリソース

データベースのリソースは、論理リソースと物理リソースの2つに大別されます。論理リソースとは論理的概念に対応するエンティティであり、データ構造、スレッド、ロック、セッションなどが含まれます。物理リソースとはハードウェアリソースであり、CPU、ディスク、メモリなどが含まれます。テナントが作成できる論理リソースの量は物理リソースによって制限され、1つの論理リソースは1つ以上の物理リソースによって制限される場合があります。

### 論理リソース

OceanBaseデータベースの論理リソースと関連説明は以下の表のとおりです。

| リソース名      | 説明                                                                                                                                                           |
|--------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------|
|  LS	         | ログストリーム。トランザクションの基本コミット単位です。テナントが各ノード上で作成できるログストリームの数は、隠れたパラメータ（`_max_ls_cnt_per_server`）、テナントメモリ（`MAX(8, (MEMORY_SIZE - 4G) / 200MB + 8)`）、ログディスクサイズによって共同で決定されます。ここで：<ul><li>テナントレベルの隠れたパラメータ `_max_ls_cnt_per_server` は、テナントの単一ノード上でサポートされる最大ログストリームエンティティ数を設定します。値の範囲は[0, 1024]で、デフォルト値は0です。これは設定しないことを意味し、システムが一定のルールに従ってサポート可能なログストリーム数を自動的に計算します。このパラメータは変更後すぐに反映され、OBServerノードの再起動は不要です。</li> <li>`MEMORY_SIZE` はそのテナントのリソースプール内のUnitのメモリ仕様であり、テナントが使用可能なメモリを表します。</li> <li>各ログストリームエンティティが占有するログディスクサイズは512MBです。</li></ul>|
| TABLET	     | データシャーディング。データ移行の基本単位です。テナントが各ノード上で作成できるTabletの上限数は、パラメータとテナントメモリによって共同で決定され、その計算式は `(MEMORY_SIZE/1GB) * _max_tablet_cnt_per_gb` および `(MEMORY_SIZE * _storage_meta_memory_limit_percentage) / 200MB * 20000` です。ここで：<ul><li>テナントレベルの隠れたパラメータ `_max_tablet_cnt_per_gb` は、テナントUnit内の1GBあたりのメモリがサポートする最大Tablet数を設定します。値の範囲は[1000, 50000)で、デフォルト値は20000です。このパラメータは変更後すぐに反映され、OBServerノードの再起動は不要です。</li> <li>テナントレベルの隠れたパラメータ `_storage_meta_memory_limit_percentage` は、メタデータメモリがテナントメモリに占める割合を設定します。値の範囲は[0, 50)で、デフォルト値は20です。0は上限を設定しないことを意味します。このパラメータは変更後すぐに反映され、OBServerノードの再起動は不要です。</li></ul>      |
| SESSION	     | セッション。テナントが各ノード上で作成できる接続数の上限は、隠れたパラメータ `_resource_limit_max_session_num` またはテナントメモリ`(MEMORY_SIZE * 5%) / 100KB` によって決定されます。</br>ここで、テナントレベルの隠れたパラメータ `_resource_limit_max_session_num` は、ユーザーテナント内の一般ユーザーの最大同時接続数を制御します。値の範囲は[0,1000000]で、デフォルト値は0です。これは設定しないことを意味し、システム内部では `(MEMORY_SIZE * 5%) / 100KB` に従って最大接続数を計算します。`_resource_limit_max_session_num` の値が0より大きい場合は、隠れたパラメータで設定された値が優先されます。このパラメータは変更後すぐに反映され、OBServerノードの再起動は不要です。       |
| THREAD	     | スレッド。各ノード上のスレッド数の上限は、隠れたパラメータ `_ob_max_thread_num` によって決定されます。</br>クラスタレベルの隠れたパラメータ `_ob_max_thread_num` は、各ノードのスレッド数上限を設定します。値の範囲は[0,10000)で、デフォルト値は0です。これは上限を設定しないことを意味します。このパラメータはsysテナントのみが変更でき、変更後すぐに反映され、OBServerノードの再起動は不要です。   |
| TX_PARTICIPANT	| トランザクション参加者。トランザクションが特定のログストリームのデータを変更すると、そのログストリームはトランザクションの参加者となり、参加者データ構造が生成されます。アクティブなトランザクションの参加者はアクティブ参加者と呼ばれ、1つのノード上でのアクティブ参加者数の上限は70Wです。|

### 物理リソース

OceanBaseデータベースの物理リソースと関連説明は以下の表のとおりです。

| リソース名      | 説明                                                   |
|--------------|--------------------------------------------------------|
| DATA_DISK    | データディスク。ユーザー業務データを格納するディスクです。現在、すべてのテナントがデータディスクを共有しています。 |
| CLOG_DISK	   | ログディスク。テナントのclogを格納するディスクです。                        |
| CPU          | CPU。テナントが使用できる計算リソースです。                               |
| MEMORY	     | メモリ。テナントが使用できる総メモリです。                                |
| MEMSTORE	   | 業務データメモリ。テナントが使用できる業務データメモリです。                   |

### 関連ビュー

OceanBaseデータベースは、テナントとリソース情報に関連するビューを提供しており、システムテナントoceanbaseデータベースでこれらのビューを通じて関連情報を照会できます。

* `DBA_OB_UNIT_CONFIGS`：すべてのリソース仕様情報を表示します。リソース仕様ID、名前、リソース設定などが含まれます。
* `DBA_OB_RESOURCE_POOLS`：すべてのリソースプール情報を表示します。リソースプールID、名前、紐づけテナント、Zoneリストなどが含まれます。
* `DBA_OB_TENANTS`：すべてのテナントの設定情報を表示します。テナントID、名前、タイプ、リソースなどが含まれます。
* `GV$OB_UNITS`：ノードのUnit情報を表示します。ノードIP、ポート、リソース仕様ID、テナントID、リソース設定などが含まれます。
* `GV$OB_SERVERS`：ノードのリソース割り当て情報を表示します。ノードIP、ポート、所属Zone、リソース使用状況などが含まれます。
* `GV$OB_TENANT_RESOURCE_LIMIT`：テナントの各Unit上の論理リソース使用量、上限値、有効な制限条件、ダウン後再起動時の最大使用量を表示します。
* `GV$OB_TENANT_RESOURCE_LIMIT.Detail`：テナントの論理リソースが受ける制限と、各制限の上限値を表示します。

## テナントリソース構成の確認

以下のステートメントを使用して、複数のビューでテナントのリソース構成情報を検索します。

クエリ結果の mysql001 テナントを例にすると、`pool:conf` 列では、そのテナントの3つのリソースプール名と使用するリソース構成名を確認できます。`unit_info` 列では、リソースプールのユニット数が1、対応するCPU構成が1.5C、メモリ構成がどちらも6Gであることがわかります。

```shell
obclient(root@sys)[oceanbase]>SELECT c.TENANT_ID, e.TENANT_NAME, concat(c.NAME, ': ', d.NAME) `pool:conf`,concat(c.UNIT_COUNT, ' unit: ', d.min_cpu, 'C/', ROUND(d.MEMORY_SIZE/1024/1024/1024,0), "G") unit_info
                FROM DBA_OB_RESOURCE_POOLS c, DBA_OB_UNIT_CONFIGS d, DBA_OB_TENANTS e
                WHERE c.UNIT_CONFIG_ID=d.UNIT_CONFIG_ID AND c.TENANT_ID=e.TENANT_ID AND c.TENANT_ID>1000
                ORDER BY c.TENANT_ID;
```
