# リソースプールのテナントへの割り当て

リソースプールの作成が完了した後、テナント作成時にリソースプールを割り当てることも、リソースプール一覧を変更する際に未使用のリソースプールをテナントに割り当てることもできます。

## テナント作成時のリソースプール割り当て

テナント作成時に、未使用のリソースプールをテナントに割り当てることができます。SQLステートメントの例は以下のとおりです：

```sql
obclient> CREATE TENANT IF NOT EXISTS test_tenant charset='utf8mb4', primary_zone='zone1;zone2,zone3', resource_pool_list=('pool1');
```

ここで：

* 各リソースプールは1つのテナントにのみ紐づけ可能で、1つのテナントは複数のリソースプールを保有できます。
* テナントがゾーン内で割り当てられる総リソース量は、Unit仕様 × Unit数です。

テナント作成の詳細については、[テナントの作成](../200.manage-create-tenant.md)を参照してください。

## テナントのリソースプール一覧変更時のリソースプール割り当て

`ALTER TENANT` コマンドを使用して、未使用のリソースプールをテナントに割り当てることもできます。対応するSQL構文は以下のとおりです：

```sql
ALTER TENANT tenant_name RESOURCE_POOL_LIST [=](pool_name [, pool_name...]) ;
```

ステートメントの使用方法：

* このステートメントは、`sys` テナントの管理者のみが実行できます。

* `RESOURCE_POOL_LIST` については、1回につき1つのリソースプールの追加または削除のみをサポートします。

* テナントにリソースプールを追加する場合、追加対象のリソースプールと既存のリソースプールが配置されているゾーンとの間に重複があってはなりません。

テナントのリソース一覧を変更してリソースプールを追加する方法は、通常、テナントのレプリカ数を増やすシナリオで使用されます。

### 例の背景

クラスタには現在 `z1`、`z2`、`z3` の3つのゾーンしかなく、これら3つのゾーンはすべて同じリージョンに属しています。各ゾーンには1台のOBServerノードがあります。クラスタには通常テナント `tenant1` が1つあり、現在のレプリカの配置状況は `locality='F@z1,F@z2,F@z3', resource_pool_list=('pool1');` です。ビジネスニーズに基づき、テナント `tenant1` のレプリカ数を3つから5つに増やす必要があります。つまり、テナントのローカリティを `F@z1,F@z2,F@z3` から `F@z1,F@z2,F@z3,F@z4,F@z5` に変更する必要があります。

### 例の操作手順

1. クラスタには現在 `z1`、`z2`、`z3` の3つのゾーンしかなく、クラスタに `z4`、`z5` の2つのゾーンを追加する必要があります。

   クラスタにゾーンを追加する具体的な操作については、[ゾーンの追加](../../../100.cluster-management/300.common-cluster-operations/800.add-a-zone.md)を参照してください。

2. `z4`ゾーンと`z5`ゾーンにそれぞれ1台のOBServerノードを追加します。

   ゾーン内にOBServerノードを追加する具体的な操作については、[ノードの追加](../../../100.cluster-management/300.common-cluster-operations/400.add-a-node.md)を参照してください。

3. `root`ユーザーで`sys`テナントにログインし、テナント`tenant1`の`z4`および`z5`ゾーンにリソースを追加します。

   1. リソースを追加するには、利用可能なリソースユニットとリソースプールが必要です。

      ```sql
      obclient>CREATE RESOURCE UNIT unit2 MAX_CPU 1, MIN_CPU 1, MEMORY_SIZE '5G', MAX_IOPS 1024, MIN_IOPS 1024, IOPS_WEIGHT 0,LOG_DISK_SIZE '2G';

      obclient>CREATE RESOURCE POOL pool2 unit = 'unit2', unit_num = 1, zone_list=('z4','z5');
      ```

   2. 完了後、テナントの`z4`および`z5`ゾーンにリソースを追加します。

      ```sql
      obclient>ALTER TENANT tenant1 RESOURCE_POOL_LIST =('pool1', 'pool2') ;
      ```

4. テナントのローカリティを変更してレプリカを増やします。

   ローカリティの変更ルールによると、テナントのレプリカ数が3から5に変更する場合、ローカリティを直接`F@z1,F@z2,F@z3,F@z4,F@z5`に変更できます。ローカリティの変更ルールの詳細については、[ローカリティの変更](../../../300.replica-management/200.replica-distribution/200.locality-common-operations/200.modify-locality.md)を参照してください。

   ```shell
   obclient>ALTER TENANT tenant1 LOCALITY='F@z1,F@z2,F@z3,F@z4,F@z5';
   ```
