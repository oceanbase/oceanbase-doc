# リソースプールの削除

本記事では、リソースプールを削除する方法について説明します。

## 前提条件

リソースプールを削除する前に、そのリソースプールが現在どのテナントでも使用されていないことを確認してください。リソースプールがテナントで使用されている場合は、リソースプールを解放してから削除する必要があります。

* テナントに複数のリソースプールがある場合は、テナントのリソースプール設定を変更することで、テナントからリソースプールを削除できます。関連する操作については、[テナント属性の変更](../1000.modify-tenant-properties.md)を参照してください。

* テナントにリソースプールが1つしかない場合は、直接削除することはサポートされていません。

  * まず、新しいリソースプールを作成してそのテナントに割り当て、次にリソースプール設定を変更して削除する必要があるリソースプールを解放します。新しいリソースプールの作成操作については、[リソースプールの作成](../200.manage-create-tenant.md)を参照してください。
  * テナントが不要になった場合は、テナントを削除してからリソースプールを削除することもできます。詳細な操作については、[テナントの削除](../1200.delete-tenant.md)を参照してください。

## 手順

1. rootユーザーでクラスタのsysテナントにログインします。

    ```shell
    obclient -h172.30.xx.xx -P2883 -uroot@sys#cluster -p**** -A
    ```

2. `oceanbase`データベースに入ります。

    ```shell
    obclient [(none)]> USE oceanbase;
    ```

3. `DBA_OB_RESOURCE_POOLS`ビューで、リソースプールの設定情報を確認します。`TENANT_ID`がNULLの場合、リソースプールは割り当てられておらず、削除できます。

   `mq_pool_02`の設定情報を照会する例を示します：

    ```shell
    obclient [oceanbase]> SELECT TENANT_ID,NAME FROM DBA_OB_RESOURCE_POOLS WHERE NAME = 'mq_pool_02';
    +-----------+------------+
    | tenant_id | name       |
    +-----------+------------+
    |      NULL | mq_pool_02 |
    +-----------+------------+
    1 row in set
    ```

    `DBA_OB_RESOURCE_POOLS`ビューの詳細については、[DBA_OB_RESOURCE_POOLS](../../../../700.reference/700.system-views/300.system-view-of-sys-tenant/200.dictionary-view-of-sys-tenant/21000.o-dba_ob_resource_pools-of-sys-tenant.md)を参照してください。

4. `DROP RESOURCE POOL`ステートメントを使用して、リソースプールを削除します。

    リソースプール`mq_pool_02`を削除する例を示します：

    ```shell
    obclient [oceanbase]> DROP RESOURCE POOL mq_pool_02;
    Query OK, 0 rows affected
    ```

    `DROP RESOURCE POOL`ステートメントの詳細については、[DROP RESOURCE POOL](../../../../700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/900.drop-resource-pool.md)を参照してください。

5. `DBA_OB_RESOURCE_POOLS`ビューを確認し、リソースプールが正常に削除されたことを確認します。

    ```shell
    obclient [oceanbase]> SELECT * FROM DBA_OB_RESOURCE_POOLS WHERE NAME = 'mq_pool_02';
    Empty set
    ```
