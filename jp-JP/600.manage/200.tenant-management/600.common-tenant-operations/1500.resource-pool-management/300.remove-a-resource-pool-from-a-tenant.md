# テナントからリソースプールを削除する

`ALTER TENANT` ステートメントを使用して、テナントからリソースプールを削除できます。

テナントからリソースプールを削除するSQL構文は以下のとおりです：

```sql
ALTER TENANT tenant_name RESOURCE_POOL_LIST [=](pool_name [, pool_name...]) ;
```

ステートメントの使用方法：

* このステートメントは、`sys` テナントの管理者によってのみ実行できます。

* `RESOURCE_POOL_LIST` については、一度に削除できるリソースプールは1つのみです。

テナントからリソースプールを削除するシナリオは、通常、テナントのレプリカ数をダウングレードする場合に使用されます。

## 背景情報

クラスタに現在 `z1`、`z2`、`z3`、`z4`、`z5` の合計5つのゾーンがあり、5つのゾーンはすべて同一のリージョンに属しており、各ゾーンに1台のOBServerが配置されているとします。クラスタ内には通常のテナント `tenant1` があり、現在のレプリカの分布状況は `locality='F@z1,F@z2,F@z3,F@z4,F@z5', resource_pool_list=('pool1','pool2')`、リソースプールのリソース分布状況は `CREATE RESOURCE POOL pool1 UNIT 'uc1', UNIT_NUM 1, ZONE_LIST ('z1', 'z2', 'z3')` と `CREATE RESOURCE POOL pool2 UNIT 'uc2', UNIT_NUM 1, ZONE_LIST ('z4', 'z5')` です。

業務上のニーズに基づき、テナント `tenant1` を5レプリカから3レプリカに調整し、リソースプールを1つに調整する必要があります。つまり、テナントのローカリティを `locality='F@z1,F@z2,F@z3,'` に変更し、リソースプールを `resource_pool_list=('pool1')` に変更します。

## 手順

1. `root` ユーザーでクラスタの `sys` テナントにログインします。

2. テナント `tenant1` のローカリティを変更してレプリカを削除します。

   ローカリティの変更ルールによれば、テナントのレプリカ数が5から3に変更される場合、ローカリティを直接 `F@z1,F@z2,F@z3` に変更できます。ローカリティの変更ルールの詳細については、[Localityの変更](../../../300.replica-management/200.replica-distribution/200.locality-common-operations/200.modify-locality.md)を参照してください。

   ```shell
   obclient>ALTER TENANT tenant1 LOCALITY='F@z1,F@z2,F@z3';
   ```

3. `z4` および `z5` のリソースプール `pool2` を削除します。

   ```sql
   obclient>ALTER TENANT tenant1 RESOURCE_POOL_LIST =('pool1') ;
   ```

## 詳細を見る

他のシナリオでは、テナントの利用可能なリソースを調整する必要がある場合は、リソースプール内のリソース仕様の設定と数量を変更することで実現できます。リソースユニットの設定を変更する関連操作については、[リソース仕様の変更](../1600.resource-specification-management/200.modify-the-configuration-of-a-resource-unit.md)を参照してください。リソースプール内のリソースユニットの数量を変更する関連操作については、[リソースプールのプロパティの変更](../900.modify-resource-pool-properties.md)を参照してください。
