# テーブルレベルリストアの Schema リストアに関する説明

テーブルレベルリストアを実行した後、リストアされる各スキーマ情報とその詳細説明は以下の通りです。

| スキーマ情報   | リストアは可能か | 説明                                                  |
|---------------|-----------|--------------------------------------------------------|
| データベース      |    不可      | テーブルレベルのリストアを実行する場合、対象テナント内に対応するデータベースが存在していなければ、リストアは失敗します。例えば、バックアップされたテーブルが元々 `INFO` という名前のデータベースに属していた場合、`REMAP TABLE` コマンドを使用しない場合（`REMAP TABLE` コマンドはテーブルを対象テナント内の別のデータベースにリネームできます）、システムもリストア時にテーブルを対象テナント内の `INFO` という名前のデータベースに配置します。      |
| テーブル領域    |    不可      | テーブルレベルのリストアを実行する場合、対象テナント内に対応するテーブル領域が存在していなければ、リストアは失敗します。例えば、バックアップされたテーブルが元々 `TS` という名前のテーブル領域に属していた場合、`REMAP TABLE` コマンドを使用しない場合（`REMAP TABLE` コマンドはテーブルを対象テナント内の別のテーブル領域にリネームできます）、システムもリストア時にテーブルを対象テナント内の `TS` という名前のテーブル領域に配置します。       |
| テーブルグループ（表組）  |     不可      | テーブルレベルのリストアを実行する場合、対象テナント内に対応するテーブルグループが存在していなければ、リストアは失敗します。例えば、バックアップされたテーブルが元々 `TG` という名前のテーブルグループに属していた場合、`REMAP TABLE` コマンドを使用しない場合（`REMAP TABLE` コマンドはテーブルを対象テナント内の別のテーブルグループにリネームできます）、システムもリストア時にテーブルを対象テナント内の `TG` という名前のテーブルグループに配置します。 |
| テーブル            |    はい      | ユーザーテーブルのみのリストアをサポートします。カラムストアおよび行列混合形式のテーブルのリストアもサポートしますが、システムテーブルや一時テーブルのリストアはサポートしません。 |
| パーティション          |    はい      | N/A |
| Tablet        |    はい      | N/A |
| 列            |    はい      | N/A |
| 制約          |    はい      | リストアがサポートされる制約は以下のとおりです：<ul><li>`NOT NULL` 制約 </li> <li>`UNIQUE KEY` 制約 </li> <li>`PRIMARY KEY` 制約 <main id="notice" type='notice'><h4>注意</h4><p>Oracleモードでは、重複する <code>PRIMARY KEY</code> 制約名が存在すると、テーブル全体のリストアが失敗します。</p></main></li> <li>`CHECK` 制約</li></ul> <main id="notice" type='explain'><h4>説明</h4><p>制約名がユーザー定義であり、かつ対象テナント内に既に存在する場合は、リストアしません。</p></main> |
| 外部キー          |    はい      | 外部キーをリストアする過程で、システムは外部キー制約の整合性をチェックします。外部キーが存在しない行を参照していることが検出された場合、その外部キーのリストアは失敗します。 |
| ビュー          |    いいえ      | テーブルをリストアする際、そのテーブルに関連付けられたビューはリストアされません。 |
| マテリアライズドビュー      |    いいえ      | 当該テーブルに関連付けられたマテリアライズドビューのリストアはサポートされていません。 |
| マテリアライズドビューのログ  |    いいえ      | 当該テーブルに関連付けられたマテリアライズドビューのログのリストアはサポートされていません。 |
| ローカルインデックス      |    はい      | N/A |
| グローバルインデックス      |    はい      | N/A |
| フルテキストインデックス      |    はい      | N/A|
| JSON複数値インデックス |    はい      | N/A|
| ベクトルインデックス      |    はい      | N/A|
| 空間インデックス      |    はい      | テーブルレベルのリストアを実行する際、座標系はリストアされません。対象テナントに参照用の座標系が存在しない場合、空間インデックスはリストアされません。対象テナントに座標系が存在する場合、空間インデックスはリストアされます。 |
| 自動インクリメント列        |    はい      | N/A |
| プライマリキーのないテーブル      |    はい      | N/A |
| 統計情報      |    はい      | N/A |
| トリガー        |    はい      | <ul><li> テーブルを元のテーブル名でリストアする場合、そのテーブルに関連付けられたトリガーもリストアされます。ただし、<ul><li>Oracleモードでは、トリガーが存在するユーザーが存在しない場合、そのトリガーのリストアは失敗します。</li> <li>MySQLモードでは、トリガーが存在するデータベースが存在しない場合、そのトリガーのリストアは失敗します。</li></ul></li> <li>テーブルがリネームされている場合、つまり新しいテーブル名でリストアする場合、そのテーブルに関連付けられたトリガーはリストアされません。</li></ul> |
| 関数、ストアドプロシージャ、パッケージ |    いいえ  | テーブルをリストアする際、そのテーブルに関連付けられた関数、ストアドプロシージャ、およびパッケージはリストアされません。 |
| シノニム        |    いいえ      | テーブルをリストアする際、そのテーブルに関連付けられたシノニムはリストアされません。 |
| LOB          |    はい      | N/A |
| Sequence     |    いいえ      | テーブルをリストアする際、そのテーブルが依存するSequenceはリストアされません |
