# テーブルレベル復元のスキーマ復元に関する説明

テーブルレベル復元を実行した後、復元される各スキーマ情報とその詳細説明は以下の通りです。

| スキーマ情報   | 復元は可能か | 説明                                                  |
|---------------|-----------|--------------------------------------------------------|
| データベース      |    不可      | テーブルレベルの復元を実行する場合、対象テナント内に対応するデータベースが存在していなければ、復元は失敗します。例えば、バックアップされたテーブルが元々 `INFO` という名前のデータベースに属していた場合、`REMAP TABLE` コマンドを使用しない場合（`REMAP TABLE` コマンドはテーブルを対象テナント内の別のデータベースにリネームできます）、システムも復元時にテーブルを対象テナント内の `INFO` という名前のデータベースに配置します。      |
| テーブル領域    |    不可      | テーブルレベルの復元を実行する場合、対象テナント内に対応するテーブル領域が存在していなければ、復元は失敗します。例えば、バックアップされたテーブルが元々 `TS` という名前のテーブル領域に属していた場合、`REMAP TABLE` コマンドを使用しない場合（`REMAP TABLE` コマンドはテーブルを対象テナント内の別のテーブル領域にリネームできます）、システムも復元時にテーブルを対象テナント内の `TS` という名前のテーブル領域に配置します。       |
| テーブルグループ（表组）  |     不可      | テーブルレベルの復元を実行する場合、対象テナント内に対応するテーブルグループが存在していなければ、復元は失敗します。例えば、バックアップされたテーブルが元々 `TG` という名前のテーブルグループに属していた場合、`REMAP TABLE` コマンドを使用しない場合（`REMAP TABLE` コマンドはテーブルを対象テナント内の別のテーブルグループにリネームできます）、システムも復元時にテーブルを対象テナント内の `TG` という名前のテーブルグループに配置します。 |
| テーブル            |    はい      | ユーザーテーブルのみの復元をサポートします。カラムストアおよび行列混合形式のテーブルの復元もサポートしますが、システムテーブルや一時テーブルの復元はサポートしません。 |
| パーティション          |    はい      | N/A |
| Tablet        |    はい      | N/A |
| 列            |    はい      | N/A |
| 制約          |    はい      | 復元がサポートされる制約は以下のとおりです：<ul><li>`NOT NULL` 制約 </li> <li>`UNIQUE KEY` 制約 </li> <li>`PRIMARY KEY` 制約 <main id="notice" type='notice'><h4>注意</h4><p>Oracleモードでは、重複する <code>PRIMARY KEY</code> 制約名が存在すると、テーブル全体の復元が失敗します。</p></main></li> <li>`CHECK` 制約</li></ul> <main id="notice" type='explain'><h4>説明</h4><p>制約名がユーザー定義であり、かつ対象テナント内に既に存在する場合は、復元しません。</p></main> |
| 外部キー          |    はい      | 外部キーを復元する過程で、システムは外部キー制約の整合性をチェックします。外部キーが存在しない行を参照していることが検出された場合、その外部キーの復元は失敗します。 |
| ビュー          |    いいえ      | テーブルを復元する際、そのテーブルに関連付けられたビューは復元されません。 |
| マテリアライズドビュー      |    いいえ      | 当該テーブルに関連付けられたマテリアライズドビューの復元はサポートされていません。 |
| マテリアライズドビューのログ  |    いいえ      | 当該テーブルに関連付けられたマテリアライズドビューのログの復元はサポートされていません。 |
| ローカルインデックス      |    はい      | N/A |
| グローバルインデックス      |    はい      | N/A |
| フルテキストインデックス      |    はい      | N/A|
| JSON複数値インデックス |    はい      | N/A|
| ベクトルインデックス      |    はい      | N/A|
| 空間インデックス      |    はい      | テーブルレベルの復元を実行する際、座標系は復元されません。対象テナントに参照用の座標系が存在しない場合、空間インデックスは復元されません。対象テナントに座標系が存在する場合、空間インデックスは復元されます。 |
| 自動インクリメント列        |    はい      | N/A |
| 主キーのないテーブル      |    はい      | N/A |
| 統計情報      |    はい      | N/A |
| トリガー        |    はい      | <ul><li> テーブルを元のテーブル名で復元する場合、そのテーブルに関連付けられたトリガーも復元されます。ただし、<ul><li>Oracleモードでは、トリガーが存在するユーザーが存在しない場合、そのトリガーの復元は失敗します。</li> <li>MySQLモードでは、トリガーが存在するデータベースが存在しない場合、そのトリガーの復元は失敗します。</li></ul></li> <li>テーブルがリネームされている場合、つまり新しいテーブル名で復元する場合、そのテーブルに関連付けられたトリガーは復元されません。</li></ul> |
| 関数、ストアドプロシージャ、パッケージ |    いいえ  | テーブルを復元する際、そのテーブルに関連付けられた関数、ストアドプロシージャ、およびパッケージは復元されません。 |
| シノニム        |    いいえ      | テーブルを復元する際、そのテーブルに関連付けられたシノニムは復元されません。 |
| LOB          |    はい      | N/A |
| Sequence     |    いいえ      | テーブルを復元する際、そのテーブルが依存するSequenceは復元されません |
