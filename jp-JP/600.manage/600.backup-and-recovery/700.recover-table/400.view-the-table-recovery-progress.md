# テーブルレベルリストアの進捗状況を確認する

テーブルレベルリストアコマンドが正常に実行された後、ビューを通じてテーブルレベルリストアの進捗状況を確認できます。

## 操作手順

1. `root`ユーザーで、リストア対象のテーブルが存在するテナントが属するクラスタの`sys`テナントにログインします。

2. テーブルレベルリストアの進捗状況を確認します。

   システムテナントは、ビュー`CDB_OB_RECOVER_TABLE_JOBS`を使用して、テーブルレベルリストア全体の進捗状況を確認できます。

   ```sql
   obclient [(none)]> SELECT * FROM oceanbase.CDB_OB_RECOVER_TABLE_JOBS\G
   ```

   クエリ結果の例は以下のとおりです：

   ```shell
   *************************** 1. row ***************************
                  TENANT_ID: 1
                     JOB_ID: 1
        INITIATOR_TENANT_ID: 1
           INITIATOR_JOB_ID: 0
            START_TIMESTAMP: 2023-06-01 06:00:00.000000
                     STATUS: RECOVERING
            AUX_TENANT_NAME: AUX_RECOVER$1692106995896258
         TARGET_TENANT_NAME: backup_tenant
                 IMPORT_ALL: 0
                    DB_LIST:
                 TABLE_LIST: `TEST`.`T1`
                RESTORE_SCN: 1692104831498747191
        RESTORE_SCN_DISPLAY: 2023-06-01 00:00:00.000000
             RESTORE_OPTION: pool_list=small_pool_0&primary_zone=z1
                BACKUP_DEST: file:///data2/nfs/ob_backup_oracle_tenant/archive,file:///data2/nfs/ob_backup_oracle_tenant/data
            BACKUP_SET_LIST: file:///data2/nfs/ob_backup_oracle_tenant/data/backup_set_1_full
          BACKUP_PIECE_LIST: file:///data2/nfs/ob_backup_oracle_tenant/archive/piece_d1001r1p1
              BACKUP_PASSWD: NULL
          EXTERNAL_KMS_INFO: NULL
              REMAP_DB_LIST:
           REMAP_TABLE_LIST: `TEST`.`T1`:`RECOVER_TEST`.`T3`
      REMAP_TABLEGROUP_LIST:
      REMAP_TABLESPACE_LIST:
                     RESULT:
                    COMMENT:
   1 row in set
   ```

   このビューには、リストア実行時にユーザーが入力したリストアパラメータ情報やリストア結果などの情報が記録されています。

   テーブルレベルリストアの全プロセスには、補助テナントのリストア操作とテナント間のインポート操作が含まれます。ビュー`CDB_OB_RECOVER_TABLE_JOBS`には、2つのタスクレコードが対応しています：1つは`sys`テナントのタスクレコード、もう1つは対象となるユーザーテナント自身のタスクレコードです。具体的には：

   * `sys`テナントのタスクレコードは、主に対象ユーザーテナントのテーブルレベルリストアの進捗状況を記録します。対象テナントのテーブルレベルリストアタスク全体が終了すると、そのタスクも終了します。

   * 対象ユーザーテナント自身のタスクレコードには、補助テナントのリストア進捗状況とテーブルインポートタスクの進捗状況が含まれます。補助テナントのリストアタスクとテーブルのインポートタスクの両方が終了すると、そのタスクも終了します。

   クエリ結果において、`AUX_RECOVER$1692106995896258`は補助テナント、`backup_tenant`は対象ユーザーテナントを表し、リストアするテーブルは`TEST`.`T1`です。`STATUS`はテーブルレベルリストアの現在の段階を示します：

   * `PREPARE`：タスク初期化段階
   * `RECOVERING`：対象テナントのリストア完了を待機中。この状態は`sys`テナントにのみ表示されます。
   * `RESTORE_AUX_TENANT`：補助テナントのリストア
   * `PRECHECK_IMPORT`：インポート前チェック
   * `GEN_IMPORT_JOB`：インポートタスクの初期化
   * `IMPORTING`：テーブルのインポート中
   * `CANCELING`：タスクのキャンセル中
   * `COMPLETED`：タスク完了
   * `FAILED`：タスク失敗

   ビュー内の`STATUS`の値が`COMPLETED`の場合、テーブルレベルリストアは完了したことを意味します。ビュー`CDB_OB_RECOVER_TABLE_JOBS`のフィールドに関する詳細説明については、[テーブルレベルリストア関連ビュー紹介](700.views-of-the-table-recovery.md)を参照してください。

3. テーブルレベルリストアが完了するまでの間、テーブルレベルリストアの段階に応じて、補助テナントのリストアタスクの進捗状況と対象テナントのインポートタスクの進捗状況を確認できます。

   * 補助テナントのリストア中は、補助テナントのリストアタスクの進捗状況を確認します。

      ```sql
      obclient [(none)]> SELECT * FROM oceanbase.CDB_OB_RESTORE_PROGRESS\G
      ```

      補助テナントのリストアは、テナントレベルの物理リストアプロセスと同じです。物理リストアの進捗状況を確認する方法の詳細については、[物理リストアの進捗状況を確認する](../600.restore-data/400.view-the-restore-progress.md)を参照してください。

   * テーブルのインポート中は、対象テナントのインポートタスクの進捗状況を確認します。

      ```sql
      obclient [(none)]> SELECT * FROM oceanbase.CDB_OB_IMPORT_TABLE_JOBS\G
      ```

      クエリ結果の例は以下のとおりです：

      ```shell
      *************************** 1. row ***************************
                  TENANT_ID: 1010
                     JOB_ID: 3
        INITIATOR_TENANT_ID: 1010
           INITIATOR_JOB_ID: 2
            START_TIMESTAMP: 2023-08-16 17:59:28.689435
            SRC_TENANT_NAME: AUX_RECOVER$1692179849034890
              SRC_TENANT_ID: 1014
                     STATUS: IMPORT_TABLE
                 IMPORT_ALL: 0
                    DB_LIST:
                 TABLE_LIST: `TEST`.`T1`
              REMAP_DB_LIST:
           REMAP_TABLE_LIST: `TEST`.`T1`:`RECOVER_TEST`.`T3`
      REMAP_TABLEGROUP_LIST:
      REMAP_TABLESPACE_LIST:
          TOTAL_TABLE_COUNT: 0
       FINISHED_TABLE_COUNT: 0
         FAILED_TABLE_COUNT: 0
                     RESULT:
                    COMMENT:
      1 row in set
      ```

      クエリ結果によると、`STATUS`が`IMPORT_TABLE`の場合、テーブル`TEST`.`T1`のインポート中であることを示します。テーブルのインポート中は、各テーブルのインポートの詳細情報も確認できます。

      ```sql
      obclient [(none)]> SELECT * FROM oceanbase.CDB_OB_IMPORT_TABLE_TASKS\G
      ```

      クエリ結果の例は以下のとおりです：

      ```shell
      *************************** 1. row ***************************

                            TASK_ID: 1047
                             JOB_ID: 3
                      SRC_TENANT_ID: 1004

                       SRC_DATABASE: test
                          SRC_TABLE: t1
                      SRC_PARTITION: NULL
                  TARGET_TABLESPACE: NULL
                  TARGET_TABLEGROUP: NULL

                       TARGET_TABLE: t3
                       TABLE_COLUMN: 7

               IMPORTED_INDEX_COUNT: 0
                 FAILED_INDEX_COUNT: 0
             TOTAL_CONSTRAINT_COUNT: 1
          IMPORTED_CONSTRAINT_COUNT: 0

      IMPORTED_REF_CONSTRAINT_COUNT: 0
        FAILED_REF_CONSTRAINT_COUNT: 0
                             RESULT:
                            COMMENT:
      1 row in set
      ```

   `CDB_OB_IMPORT_TABLE_JOBS`、`CDB_OB_IMPORT_TABLE_TASKS`などのビューのフィールドに関する詳細説明については、[テーブルレベルリストア関連ビュー紹介](700.views-of-the-table-recovery.md)を参照してください。
