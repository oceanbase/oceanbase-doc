# テーブルレベルのリカバリのキャンセル

指定したテーブルのリカバリ処理中に、`ALTER SYSTEM CANCEL RECOVER TABLE` ステートメントを使用してテーブルのリカバリを停止できます。このステートメントは、対応するテナント内のすべてのテーブルレベルのリカバリタスクをキャンセルしますが、リカバリ前の準備時に作成されたリソースプールは解放しません。

## 手順

1. `root` ユーザーで、リカバリ対象のテーブルが存在するクラスタの `sys` テナントにログインします。

2. 以下のコマンドを実行して、直ちにリカバリをキャンセルします。

   ```sql
   ALTER SYSTEM CANCEL RECOVER TABLE dest_tenant_name;
   ```

   ここで、`dest_tenant_name` には、リカバリ対象のテーブルが存在するターゲットテナント名を入力する必要があります。

## 次のステップ

テーブルレベルのリカバリをキャンセルした後、再度テーブルレベルのリカバリを実行しない場合は、ターゲットテナントが属するクラスタで以下のコマンドを実行して、リカバリ前の準備時に作成されたリソースプールを手動で解放できます。

```sql
DROP RESOURCE POOL restore_pool;
```

ここで、`restore_pool` は、リカバリ前の準備時に補助テナント用に作成されたリソースプールの名前を表します。

リソースプールの削除に関する詳細な操作と説明については、[リソースプールの削除](../../200.tenant-management/600.common-tenant-operations/1500.resource-pool-management/600.delete-resource-pool.md)を参照してください。
