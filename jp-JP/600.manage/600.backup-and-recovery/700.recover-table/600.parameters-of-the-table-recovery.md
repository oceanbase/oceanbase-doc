# テーブルレベル復元関連パラメータの紹介

このセクションでは、テーブルレベル復元コマンドに含まれる関連パラメータについて説明します。

## テーブルレベル復元コマンド関連

### コマンド

* テーブルレベル復元

  ```sql
  ALTER SYSTEM
  RECOVER TABLE table_name_list
  TO [TENANT [=]] dest_tenant_name
  FROM uri
  [UNTIL {TIME='timestamp'} | {SCN=scn} ]
  WITH 'restore_option'
  [WITH KEY FROM 'backup_key_path' ENCRYPTED BY 'password']
  [REMAP TABLE remap_table_name_list]
  [REMAP TABLEGROUP remap_tablegroup_list]
  [REMAP TABLESPACE remap_tablespace_list]
  [DESCRIPTION [=] description];
  ```

* 実行中のテーブルレベル復元タスクをキャンセル

   ```sql
   ALTER SYSTEM CANCEL RECOVER TABLE dest_tenant_name;
   ```

### パラメータ説明

|         パラメータ                |     説明                                        |
|-----------------------------|------------------------------------------------|
|   table_name_list           |  復元するテーブル。形式は <code>database_name.table_name1,database_name.table_name2,...</code> のようにします。複数のテーブルは半角カンマ（,）で区切ります。</br><code>database_name</code> と <code>table_name</code> を指定する場合：<ul> <li>名前はシステムが実際に格納している名前と一致している必要があります。<ul><li>Oracleモードのテナントでは、<code>database_name</code> の名前はテーブルが存在するユーザー名と同じです。また、<code>database_name</code> と <code>table_name</code> はデフォルトで大文字小文字を区別せず、英字の大文字で内部テーブルに保存されます。</li> <li>MySQLモードのテナントでは、<code>database_name</code> の名前はテーブルが属するデータベース名です。また、<code>database_name</code> と <code>table_name</code> が大文字小文字を区別するかどうかは、ソーステナント作成時に指定した変数 <code>lower_case_table_names</code> の値によって決まります。</br>変数 <code>lower_case_table_names</code> は、データベース名とテーブル名が大文字小文字を区別するかどうかを設定します。テナント作成時にこの変数の値を指定しなかった場合、デフォルトでデータベース名とテーブル名は小文字で保存され、大文字小文字を区別せずに比較されます。変数 <code>lower_case_table_names</code> の詳細については、<a href="../../../700.reference/800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/3600.lower_case_table_names-global.md">lower_case_table_names</a> を参照してください。</li></ul> </li> <li><code>database_name</code> または <code>table_name</code> に特殊文字が含まれる場合、その特殊文字を含む <code>database_name</code> または <code>table_name</code> はバッククォート（``）で囲む必要があります。</li> <li>あるデータベースのすべてのテーブルを復元する場合は、database_name.\* と表現します。</li> <li>テナント内のすべてのユーザーテーブルを復元する場合は、\*.\* と表現します。</li></ul>    |
|  dest_tenant_name           | テーブルを復元する対象テナント名。テーブルの復元はユーザーテナントへのみサポートされ、`sys` テナントやMetaテナントへの復元はサポートされていません。                                             |
|  uri                        | データバックアップとログアーカイブのパスをそれぞれ指定します。テナントレベルの物理復元コマンドのパラメータと同じです。データバックアップがPLUS ARCHIVELOG方式で開始された場合は、一方のパスのみを入力する必要があります。そうでない場合は、データバックアップとログアーカイブの少なくとも2つのパスをそれぞれ入力する必要があります。例：`'file:///backup/archive, file:///backup/data'`。                                               |
|    {TIME='timestamp'} \| {SCN=scn}          | 指定された復元終点です。このポイントまで復元し、そのポイントを含みます。`TIME` または `SCN` に復元する場合は、`=` で指定した値を結びます。`UNTIL` 句を指定しない場合、デフォルトで最新のポイントまで復元されます。                                              |
| restore_option     | `pool_list`、`locality`、`primary_zone`、`concurrency` をサポートしており、異なるパラメータ間は `&` で区切ります。`locality` と `primary_zone` を指定する際は、ソーステナントとの同型性を保つことを推奨します。<ul><li>`pool_list`：必須。ユーザーのリソースプールを入力します。複数のリソースプールは半角カンマ（,）で区切ります。</li>  <li>`locality`：オプション。補助テナントのレプリカ分散の Locality 情報を入力します。これは、補助テナントが存在するクラスタの `pool_list` の Zone 情報と一致している必要があります。記入しない場合、デフォルトで resource_pool の `zone_list` に従い、各 Zone に F レプリカが1つ設定されます。</br>入力例: `locality='F@z1,F@z2,F@z3'` </li> <li>`primary_zone`：オプション。補助テナントの Leader レプリカの優先位置を入力します。`pool_list` 及び `locality` とのマッチング、つまり Zone 情報の一致と `primary_region` 内に少なくとも2つの Paxos メンバーが存在するという制限を満たす必要があります。記入しない場合、システムは `locality` の `zone_list` に従って、Leaderをこれらの Zone にランダムに分散します。 </br>入力例: `primary_zone='z1'`</li> <li>`concurrency`：オプション。データ復元の並列度を指定します。指定しない場合、デフォルトでそのテナントに割り当てられた MAX_CPU 数に等しくなります。</br>入力例：`concurrency=50` </li></ul>   |
| WITH KEY FROM 'backup_key_path' ENCRYPTED BY 'password' | 暗号化テナントの秘密鍵バックアップ情報を指定します。ソーステナントに透過的データ暗号化が設定されている場合にのみ、復元時に秘密鍵バックアップ関連情報を指定する必要があります。詳細は以下の通りです：<ul><li><code>backup_key_path</code>：秘密鍵のバックアップパス。</li> <li><code>password</code>：秘密鍵をバックアップする際に設定した暗号化パスワード。</li></ul> |
|  remap_table_name_list      | 復元後のテーブル名を変更します。テーブル名のみを変更し、所属するデータベースを変更しない場合、またはテーブル名を変更せずに他のデータベースに移行する場合、さらにテーブル名を変更し、所属するデータベースも他のデータベースに変更する場合をサポートします。ソースオブジェクトと変更後のオブジェクトは半角コロン（:）で結びます。具体的な書式例は以下の通りです：<ul> <li>テーブル名を <code>student</code> から <code>student2</code> に変更し、所属するデータベースは変更しません：<code>REMAP TABLE school.student:student2</code>。</br>所属するデータベースを変更しない場合、ターゲットテナントで同名のテーブルを作成する際、システムはデフォルトでそのテナント内の同名データベースにテーブルを復元します。同名のデータベースが存在しない場合、テーブルの復元は失敗します。</li> <li>テーブル名は変更せず、所属するデータベースを <code>school</code> から <code>college</code> に変更します：<code>REMAP TABLE school.student:college.student</code>。</li> <li>テーブル名を <code>student</code> から <code>student2</code> に変更し、所属するデータベースを <code>school</code> から <code>college</code> に変更します：</code>REMAP TABLE school.student:college.student2</code>。</li> <li><code>school</code> データベース内のすべてのテーブルを <code>college</code> データベースに復元します：<code>REMAP TABLE school.`*`:college.`*`</code>。 </li></ul> <main id="notice" type='explain'><h4>説明</h4><p>変更後の <code>database_name</code> または <code>table_name</code> に特殊文字が含まれる場合、その特殊文字を含む <code>database_name</code> または <code>table_name</code> はバッククォート（``）で囲む必要があります。</p></main>             |
|  remap_tablegroup_list      | テーブルが属するテーブルグループを変更します。ソーステーブルがテーブルグループに紐づけられている場合、ターゲットテナントで同名のテーブルグループを作成する際、システムはデフォルトでそのテナント内の同名テーブルグループにテーブルを復元します。同名のテーブルグループが存在しない場合、テーブルの復元は失敗します。ターゲットテナント内に他のテーブルグループが存在する場合、このステートメントを使用してテーブルを他のテーブルグループに復元することもできます。ソースオブジェクトと変更後のオブジェクトは半角コロン（:）で結びます。 </br>例えば、ソーステーブルグループ <code>tg1</code> 内のすべてのテーブルをターゲットテナントのテーブルグループ <code>newtg1</code> に復元する場合：<code>REMAP TABLEGROUP tg1:newtg1</code>。                                              |
|  remap_tablespace_list      | テーブルが属するテーブルスペースを変更します。テーブルスペースはOceanBaseデータベースにおける論理単位で、現在は主にデータ暗号化に使用されます。ソーステーブルがテーブルスペースに紐づけられている場合、ターゲットテナントで同名のテーブルスペースを作成する際、システムはデフォルトでそのテナント内の同名テーブルスペースにテーブルを復元します。同名のテーブルスペースが存在しない場合、テーブルの復元は失敗します。ターゲットテナント内に他のテーブルスペースが存在する場合、このステートメントを使用してテーブルを他のテーブルスペースに復元することもできます。ソースオブジェクトと変更後のオブジェクトは半角コロン（:）で結びます。</br> 例えば、ソーステーブルスペース <code>ts1</code> 内のすべてのテーブルをターゲットテナントのテーブルスペース <code>newts1</code> に復元する場合：<code>REMAP TABLESPACE ts1:newts1</code>。                                             |

## テーブルレベル復元のパフォーマンス関連

### 復元補助テナント段階

テーブルレベル復元における復元補助テナント段階は、テナントレベル復元と同じです。この段階に関連するパフォーマンスパラメータおよび説明については、[物理復元関連パラメータ紹介](../600.restore-data/800.parameters-of-the-restore.md)を参照してください。

### テナント間データ導入段階

**コマンド**

```sql
ALTER SYSTEM SET ddl_thread_score = int_value Tenant=tenant_name;
```

```sql
ALTER SYSTEM SET recover_table_concurrency= int_value Tenant=tenant_name;
```

```sql
ALTER SYSTEM SET recover_table_dop = int_value Tenant=tenant_name;
```

***パラメータの説明***

|         パラメータ                |     説明                                        |
|-----------------------------|------------------------------------------------|
| [ddl_thread_score](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/1850.ddl_thread_score.md)            | テナントOBServerノード上のテーブルレベル復元スレッドプールの数を制御します。デフォルト値は0で、内部デフォルトスレッド数は2を意味します。|
| [recover_table_concurrency](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/7320.recover_table_concurrency.md)   | テナントの複数テーブル並列復元の並列度を制御し、最大で `recover_table_concurrency` 個のテーブルが同時にテナント間データ導入を実行できるように指定します。デフォルト値は0で、内部デフォルトでは最大1個のテーブルがテナント間データ導入を実行できることを意味します。|
| [recover_table_dop](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/7325.recover_table_dop.md)            | 単一テーブル復元の並列度を制御します。デフォルト値は0で、内部デフォルトの並列度は1を意味します。<p>このパラメータは具体的に以下の2つの段階に影響します：</p><ul><li>データ復元段階<p>システムはテーブルの各パーティションを最大 `recover_table_dop` 個の復元サブタスクに分割し、各サブタスクは独立したテーブルレベル復元スレッドによって実行され、並列復元が実現されます。</p> <p>総並列度の計算式：`単一テーブル最大並列度 = パーティション総数 * recover_table_dop`</p> <p>例：現在復元中のテーブルが4つのパーティションを持ち、`recover_table_dop` の値が2の場合、総並列スレッド数は `4*2=8` となります。</p></li> <li>インデックス再構築段階<p>システムは既に復元されたテーブルデータに基づき、並列実行(Parallel Execution, PX)を利用してインデックスを再構築します。PXの並列度は `recover_table_dop` によって決定されます。PXの詳細およびチューニングについては、[並列実行](../../../700.reference/1000.performance-tuning-guide/500.sql-optimization/350.parallel-execution/100.parallel-execution-concept.md)を参照してください。</p></li></ul> |
