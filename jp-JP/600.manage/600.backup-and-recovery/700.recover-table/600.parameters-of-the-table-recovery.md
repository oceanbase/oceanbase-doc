# テーブルレベル復元関連パラメータの紹介

このセクションでは、テーブルレベル復元コマンドに含まれる関連パラメータについて説明します。

## テーブルレベル復元コマンド関連

### コマンド

* テーブルレベルの復元

  ```sql
  ALTER SYSTEM
  RECOVER TABLE table_name_list
  TO [TENANT [=]] dest_tenant_name
  FROM uri
  [UNTIL {TIME='timestamp'} | {SCN=scn} ]
  WITH 'restore_option'
  [WITH KEY FROM 'backup_key_path' ENCRYPTED BY 'password']
  [REMAP TABLE remap_table_name_list]
  [REMAP TABLEGROUP remap_tablegroup_list]
  [REMAP TABLESPACE remap_tablespace_list]
  [DESCRIPTION [=] description];
  ```

* 実行中のテーブルレベル復元タスクのキャンセル

   ```sql
   ALTER SYSTEM CANCEL RECOVER TABLE dest_tenant_name;
   ```

### パラメータの説明

|         パラメータ                |     説明                                        |
|-----------------------------|------------------------------------------------|
|   table_name_list           |  復元するテーブル。形式は <code>database_name.table_name1,database_name.table_name2,...</code> のようになり、複数のテーブルは半角カンマ（,）で区切ります。</br><code>database_name</code> と <code>table_name</code> を指定する場合：<ul> <li>名前はシステムが実際に保存している名前と一致している必要があります。<ul><li>Oracleモードのテナントでは、<code>database_name</code> の名前はテーブルが属するユーザー名と同じです。また、<code>database_name</code> と <code>table_name</code> はデフォルトで大文字小文字を区別せず、英字の大文字で内部テーブルに保存されます。</li> <li>MySQLモードのテナントでは、<code>database_name</code> の名前はテーブルが属するデータベース名です。また、<code>database_name</code> と <code>table_name</code> が大文字小文字を区別するかどうかは、ソーステナント作成時に指定した変数 <code>lower_case_table_names</code> の値によって決まります。</br>変数 <code>lower_case_table_names</code> は、データベース名とテーブル名が大文字小文字を区別するかどうかを設定します。テナント作成時にこの変数の値を指定しなかった場合、デフォルトでデータベース名とテーブル名は小文字で保存され、大文字小文字を区別せずに比較されます。変数 <code>lower_case_table_names</code> の詳細については、<a href="../../../700.reference/800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/3600.lower_case_table_names-global.md">lower_case_table_names</a> を参照してください。</li></ul> </li> <li><code>database_name</code> または <code>table_name</code> に特殊文字が含まれる場合、特殊文字を含む <code>database_name</code> または <code>table_name</code> はバッククォート（``）で囲む必要があります。</li> <li>あるデータベースのすべてのテーブルを復元する場合は、database_name.\* と表現できます。</li> <li>テナント内のすべてのユーザーテーブルを復元する場合は、\*.\* と表現できます。</li></ul>    |
|  dest_tenant_name           | テーブルを復元する対象テナント名。テーブルの復元はユーザーテナントへのみサポートされており、`sys` テナントやMetaテナントへの復元はサポートされていません。                                             |
|  uri                        | データバックアップとログアーカイブのパスをそれぞれ指定します。これはテナントレベルの物理復元コマンドのパラメータと同じです。データバックアップがPLUS ARCHIVELOG方式で開始された場合は、一方のパスのみを入力する必要があります。そうでない場合は、データバックアップとログアーカイブについて少なくとも2つのパスをそれぞれ入力する必要があります。例：`'file:///backup/archive, file:///backup/data'`。                                               |
|    {TIME='timestamp'} \| {SCN=scn}          | 指定された復元終点です。このポイントまで復元し、そのポイントを含みます。<code>TIME</code> または <code>SCN</code> に復元する場合は、`=` で指定した値を結びます。<code>UNTIL</code> 句を指定しない場合、デフォルトで最新のポイントまで復元されます。                                              |
| restore_option     | `pool_list`、`locality`、`primary_zone`、`concurrency`をサポートしており、パラメータ間は `&` で区切ります。`locality` と `primary_zone` を指定する場合は、可能な限りソーステナントと同型に保つことを推奨します。<ul><li>`pool_list`：必須。ユーザーのリソースプールを入力します。複数のリソースプールは半角カンマ（,）で区切ります。</li>  <li>`locality`：オプションです。スタンバイテナントのレプリカ分散のローカリティ情報を入力します。スタンバイテナントが配置されているクラスタの `pool_list` のゾーン情報と一致している必要があります。指定しない場合、resource_poolの`zone_list`に従って、各ゾーンに1つのFレプリカがデフォルトで設定されます。</br>入力例: `locality='F@z1,F@z2,F@z3'` </li> <li>`primary_zone`：オプションです。スタンバイテナントのリーダーレプリカの優先位置を入力します。`pool_list` および `locality` とのマッチング、すなわちゾーン情報の一致と `primary_region` 内に少なくとも2つのPaxosメンバーが存在するという制限を満たす必要があります。指定しない場合、システムは `locality` の `zone_list` に従って、これらのゾーンにリーダーをランダムに分散します。 </br>入力例: `primary_zone='z1'`</li> <li>`concurrency`：オプションです。データ復元の並列度を指定します。指定しない場合、デフォルトでそのテナントに割り当てられたMAX_CPU数に等しくなります。</br>入力例：`concurrency=50` </li></ul>   |
| WITH KEY FROM 'backup_key_path' ENCRYPTED BY 'password' | テナントの秘密鍵バックアップ情報を指定します。復元時に秘密鍵バックアップ関連情報を指定する必要があるのは、ソーステナントで透過的データ暗号化が設定されている場合のみです。詳細は以下のとおりです：<ul><li><code>backup_key_path</code>：秘密鍵のバックアップパス。</li> <li><code>password</code>：秘密鍵をバックアップする際に設定した暗号化パスワード。</li></ul> |
|  remap_table_name_list      | 復元後のテーブル名を変更します。テーブル名のみを変更し、テーブルが属するデータベースは変更しない場合、またはテーブル名は変更せずに他のデータベースに移動する場合、さらにはテーブル名と所属データベースの両方を変更する場合もサポートしています。ソースオブジェクトと変更後のオブジェクトは、半角カンマ（:）で区切ります。具体的なフォーマット例は以下のとおりです：<ul> <li>テーブル名を<code>student</code>から<code>student2</code>に変更し、テーブルが属するデータベースは変更しません。<code>REMAP TABLE school.student:student2</code>。</br>所属データベースを変更しない場合、ターゲットテナントに復元してテーブルを作成する際、システムはデフォルトで、ターゲットテナント内の同名データベースにテーブルを復元します。同名のデータベースが存在しない場合、テーブルの復元は失敗します。</li> <li>テーブル名は変更せず、テーブルが属するデータベースを<code>school</code>から<code>college</code>に変更します：<code>REMAP TABLE school.student:college.student</code>。</li> <li>テーブル名を<code>student</code>から<code>student2</code>に変更し、テーブルが属するデータベースを<code>school</code>から<code>college</code>に変更します：</code>REMAP TABLE school.student:college.student2</code>。</li> <li><code>school</code>データベース内のすべてのテーブルを<code>college</code>データベースに復元します：<code>REMAP TABLE school.`*`:college.`*`</code>。 </li></ul> <main id="notice" type='explain'><h4>説明</h4><p>変更対象の<code>database_name</code>または<code>table_name</code>に特殊文字が含まれる場合、その特殊文字を含む<code>database_name</code>または<code>table_name</code>はバッククォート（``）で囲む必要があります。</p></main>             |
|  remap_tablegroup_list      | テーブルが属するテーブルグループの名前を変更します。ソーステーブルがテーブルグループに紐づけられている場合、ターゲットテナントに復元してテーブルを作成する際、システムはデフォルトで、ターゲットテナント内の同名テーブルグループにテーブルを復元します。同名のテーブルグループが存在しない場合、テーブルの復元は失敗します。ターゲットテナント内に他のテーブルグループがある場合、このステートメントを使用して、テーブルを他のテーブルグループに復元することもできます。ソースオブジェクトと変更後のオブジェクトは、半角カンマ（:）で区切ります。 </br>例えば、ソーステーブルグループ<code>tg1</code>内のすべてのテーブルをターゲットテナントのテーブルグループ<code>newtg1</code>に復元します：<code>REMAP TABLEGROUP tg1:newtg1</code>。                                              |
|  remap_tablespace_list      | テーブルが属するテーブルスペースの名前を変更します。テーブルスペースはOceanBaseデータベースにおける論理的な単位であり、現在は主にデータ暗号化に使用されています。ソーステーブルがテーブルスペースに紐づけられている場合、ターゲットテナントに復元してテーブルを作成する際、システムはデフォルトで、ターゲットテナント内の同名テーブルスペースにテーブルを復元します。同名のテーブルスペースが存在しない場合、テーブルの復元は失敗します。ターゲットテナント内に他のテーブルスペースがある場合、このステートメントを使用して、テーブルを他のテーブルスペースに復元することもできます。ソースオブジェクトと変更後のオブジェクトは、半角カンマ（:）で区切ります。</br> 例えば、ソーステーブルスペース<code>ts1</code>内のすべてのテーブルをターゲットテナントのテーブルスペース<code>newts1</code>に復元します：<code>REMAP TABLESPACE ts1:newts1</code>。                                             |

## テーブルレベル復元のパフォーマンス関連

### 復元補助テナント段階

テーブルレベル復元における復元補助テナント段階は、テナントレベル復元と一致します。この段階に関連するパフォーマンスパラメータおよび説明については、[物理復元関連パラメータ紹介](../600.restore-data/800.parameters-of-the-restore.md)を参照してください。

### テナント間データ導入段階

**コマンド**

```sql
ALTER SYSTEM SET ddl_thread_score = int_value Tenant=tenant_name;
```

```sql
ALTER SYSTEM SET recover_table_concurrency= int_value Tenant=tenant_name;
```

```sql
ALTER SYSTEM SET recover_table_dop = int_value Tenant=tenant_name;
```

***パラメータの説明***

|         パラメータ                |     説明                                        |
|-----------------------------|------------------------------------------------|
| [ddl_thread_score](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/1850.ddl_thread_score.md)            | テナントOBServerノード上のテーブルレベル復元スレッドプールの数を制御します。デフォルト値は0で、内部デフォルトスレッド数は2を意味します。|
| [recover_table_concurrency](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/7320.recover_table_concurrency.md)   | テナントの複数テーブル並列復元の並列度を制御し、最大で `recover_table_concurrency` 個のテーブルが同時にテナント間データ導出を実行できるように指定します。デフォルト値は0で、内部デフォルトでは最大1つのテーブルのテナント間データ導出を許可することを意味します。|
| [recover_table_dop](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/7325.recover_table_dop.md)            | 単一テーブル復元の並列度を制御します。デフォルト値は0で、内部デフォルトの並列度は1を意味します。<p>このパラメータは、具体的に以下の2つの段階に影響します：</p><ul><li>データ復元段階<p>システムは、テーブルの各パーティションを最大 `recover_table_dop` 個の復元サブタスクに分割し、各サブタスクは独立したテーブルレベル復元スレッドによって実行され、並列復元を実現します。</p> <p>総並列度の計算式：`単一テーブル最大並列度 = パーティション総数 × recover_table_dop`</p> <p>例：現在復元中のテーブルが4つのパーティションを持ち、`recover_table_dop` の値が2の場合、総並列スレッド数は `4×2=8` となります。</p></li> <li>インデックス再構築段階<p>システムは、既に復元されたテーブルデータに基づき、並列実行(Parallel Execution, PX)を利用してインデックスを再構築します。PXの並列度は `recover_table_dop` によって決定されます。PXの詳細およびチューニングについては、[並列実行](../../../700.reference/1000.performance-tuning-guide/500.sql-optimization/350.parallel-execution/100.parallel-execution-concept.md)を参照してください。</p></li></ul> |
