# テーブル単位の復旧に関するパラメータの紹介

このセクションでは、主にテーブル単位の復旧コマンドに含まれる関連パラメータについて説明します。

## テーブル単位の復旧コマンド関連

### コマンド

* テーブル単位のリカバリ

  ```sql
  ALTER SYSTEM
  RECOVER TABLE table_name_list
  TO [TENANT [=]] dest_tenant_name
  FROM uri
  [UNTIL {TIME='timestamp'} | {SCN=scn} ]
  WITH 'restore_option'
  [WITH KEY FROM 'backup_key_path' ENCRYPTED BY 'password']
  [REMAP TABLE remap_table_name_list]
  [REMAP TABLEGROUP remap_tablegroup_list]
  [REMAP TABLESPACE remap_tablespace_list]
  [DESCRIPTION [=] description];
  ```

* 実行中のテーブル単位のリカバリタスクをキャンセルする

   ```sql
   ALTER SYSTEM CANCEL RECOVER TABLE dest_tenant_name;
   ```

### パラメータの説明

|         パラメータ                |     説明                                        |
|-----------------------------|------------------------------------------------|
|   table_name_list           | 復元するテーブル。書式は <code>database_name.table_name1,database_name.table_name2,...</code> のようになります。複数のテーブルを指定する場合は、半角カンマ（,）で区切ります。</br><code>database_name</code> と <code>table_name</code> を指定する際には、以下の点に注意してください：<ul> <li>名前はシステムが実際に保存している名前と一致している必要があります。</ul><li>Oracleモードのテナントでは、<code>database_name</code> の名前はテーブルが属するユーザー名と同じであり、<code>database_name</code> と <code>table_name</code> はデフォルトで大文字と小文字を区別せず、内部テーブルには英字の大文字で格納されます。</li> <li>MySQLテナントでは、<code>database_name</code> の名前はテーブルが属するデータベース名であり、<code>database_name</code> と <code>table_name</code> が大文字と小文字を区別するかどうかは、ソーステナント作成時に指定した変数 <code>lower_case_table_names</code> の値によって決まります。</br>変数 <code>lower_case_table_names</code> は、データベース名とテーブル名が大文字と小文字を区別するかどうかを設定します。テナント作成時にこの変数の値が指定されていない場合、デフォルトではデータベース名とテーブル名は小文字で格納され、比較も大文字と小文字を区別せずに行われます。変数 <code>lower_case_table_names</code> の詳細については、<a href="../../../700.reference/800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/3600.lower_case_table_names-global.md">lower_case_table_names</a> を参照してください。</li></ul> </li> <li><code>database_name</code> または <code>table_name</code> に特殊文字が含まれる場合、特殊文字を含む <code>database_name</code> または <code>table_name</code> はバッククォート（``）で囲む必要があります。</li> <li>あるデータベース内のすべてのテーブルを復元する場合は、database_name.\* と表記します。</li> <li>テナント内のすべてのユーザーテーブルを復元する場合は、\*.\* と表記します。</li></ul>    |
|  dest_tenant_name           | テーブルを復元する対象のターゲットテナント名。テーブルをユーザーテナントにのみ復元でき、`sys` テナントやMetaテナントへの復元はサポートされていません。                                             |
|  uri                        | データバックアップとログアーカイブのパスをそれぞれ指定します。これは、テナントレベルの物理復元コマンドのパラメータと同じです。データバックアップがPLUS ARCHIVELOG方式で開始された場合は、パスを1つ入力するだけで済みます。そうでない場合は、データバックアップとログアーカイブの少なくとも2つのパスをそれぞれ入力する必要があります。例：`'file:///backup/archive, file:///backup/data'`。                                               |
|    {TIME='timestamp'} \| {SCN=scn}          | 指定された復元ポイント。そのポイントまで復元し、そのポイントを含みます。`TIME` または `SCN` まで復元する場合は、指定する値を `=` で結合する必要があります。`UNTIL` 句を指定しない場合、デフォルトでは最新のポイントまで復元されます。                                              |
| restore_option     | `pool_list`、`locality`、`primary_zone`、`concurrency` をサポートしており、パラメータ間は `&` で区切ります。`locality` と `primary_zone` を指定する際は、ソーステナントとの同型性を維持することを推奨します。<ul><li>`pool_list`：必須項目。ユーザーのリソースプールを入力します。複数のリソースプールは、英語のカンマ（,）で区切ります。</li>  <li>`locality`：オプション。スタンバイテナントのレプリカ分散のローカリティ情報を入力します。スタンバイテナントが存在するクラスタの `pool_list` のゾーン情報と一致させる必要があります。このパラメータを省略した場合、デフォルトではresource_poolの`zone_list`に基づいて各ゾーンにFレプリカが設定されます。</br>入力例：`locality='F@z1,F@z2,F@z3'` </li> <li> `primary_zone`：オプション。スタンバイテナントのリーダーレプリカの優先位置を入力します。`pool_list`および`locality`とのマッチング、すなわちゾーン情報のマッチングと`primary_region`内に少なくとも2つのPaxosメンバーが存在するという制限を満たす必要があります。このパラメータを省略した場合、システムは`locality`の`zone_list`に従ってこれらのゾーンにリーダーをランダムに分散します。 </br>入力例：`primary_zone='z1'`</li> <li>`concurrency`：オプション。テーブルレベルの復旧<b>物理復旧段階</b>の並列度を指定します。指定しない場合、デフォルトでそのテナントに割り当てられたMAX_CPU数となります。テーブルレベルの復旧プロセスについては、<a href="../../../700.reference/100.oceanbase-database-concepts/1000.high-data-reliability-and-availability/500.backup-and-recovery/400.recovery-architecture.md">復旧プロセス</a>を参照してください。</br>入力例：`concurrency=50` </li></ul>   |
| WITH KEY FROM 'backup_key_path' ENCRYPTED BY 'password' | 暗号化テナントの秘密鍵バックアップ情報を指定します。復旧時に秘密鍵バックアップ関連情報を指定する必要があるのは、ソーステナントに透過的暗号化が設定されている場合に限ります。その中で：<ul><li><code>backup_key_path</code>：秘密鍵のバックアップパス。</li> <li><code>password</code>：秘密鍵をバックアップする際に設定した暗号化パスワード。秘密鍵バックアップに関する操作については、<a href="../400.data-backup/100.preparation-before-data-backup.md">バックアップ前の準備</a>の**秘密鍵のバックアップ**を参照してください。</li></ul> |
|  remap_table_name_list      | 復元後のテーブル名をリネームします。テーブル名のみをリネームし、テーブルが属するデータベースは変更しない場合、またはテーブル名は変更せず、他のデータベースにのみリネームする場合、さらにはテーブル名をリネームし、同時に所属するデータベースも他のデータベースにリネームする場合もサポートされています。ソースオブジェクトとリネーム対象オブジェクトの間は、英字のコロン（:）で結びつけます。具体的なフォーマット例は以下のとおりです：<ul> <li>テーブル名を <code>student</code> から <code>student2</code> にリネームし、テーブルが属するデータベースは変更しません：<code>REMAP TABLE school.student:student2</code>。</br>所属するデータベースが変更されない場合、ターゲットテナントに復元してテーブルを作成する際、システムはデフォルトでテーブルをターゲットテナントの同名のデータベースに復元します。同名のデータベースが存在しない場合、テーブルの復元は失敗します。</li> <li>テーブル名は変更せず、テーブルが属するデータベースを <code>school</code> から <code>college</code> に変更します：<code>REMAP TABLE school.student:college.student</code>。</li> <li>テーブル名を <code>student</code> から <code>student2</code> にリネームし、テーブルが属するデータベースを <code>school</code> から <code>college</code> に変更します：</code>REMAP TABLE school.student:college.student2</code>。</li> <li><code>school</code> 下のすべてのテーブルを <code>college</code> に復元します：<code>REMAP TABLE school.`*`:college.`*`</code>。 </li></ul> <main id="notice" type='explain'><h4>説明</h4><p>リネームする <code>database_name</code> または <code>table_name</code> に特殊文字が含まれている場合、特殊文字を含む <code>database_name</code> または <code>table_name</code> をバッククォート（``）内に入れる必要があります。</p></main>       |
|  remap_tablegroup_list      | テーブルが属するテーブルグループをリネームします。ソーステーブルがテーブルグループにバインドされている場合、ターゲットテナントに復元してテーブルを作成する際、システムはデフォルトでテーブルをターゲットテナント内の同名のテーブルグループに復元します。同名のテーブルグループが存在しない場合、テーブルの復元は失敗します。ターゲットテナントに他のテーブルグループがある場合、このステートメントを使用してテーブルを他のテーブルグループに復元することもできます。ソースオブジェクトとリネーム対象オブジェクトの間は、英字のコロン（:）で結びつけます。 </br>たとえば、ソーステーブルグループ <code>tg1</code> 内のすべてのテーブルをターゲットテナントのテーブルグループ <code>newtg1</code> に復元します：<code>REMAP TABLEGROUP tg1:newtg1</code>。                                              |
|  remap_tablespace_list      | テーブルが属するテーブルスペースをリネームします。テーブルスペースはOceanBaseデータベースにおける論理的な単位であり、現在主にデータ暗号化に使用されています。ソーステーブルがテーブルスペースにバインドされている場合、ターゲットテナントに復元してテーブルを作成する際、システムはデフォルトでテーブルをターゲットテナント内の同名のテーブルスペースに復元します。同名のテーブルスペースが存在しない場合、テーブルの復元は失敗します。ターゲットテナントに他のテーブルスペースがある場合、このステートメントを使用してテーブルを他のテーブルスペースに復元することもできます。ソースオブジェクトとリネーム対象オブジェクトの間は、英字のコロン（:）で結びつけます。</br> たとえば、ソーステーブルスペース <code>ts1</code> 内のすべてのテーブルをターゲットテナントのテーブルスペース <code>newts1</code> に復元します：<code>REMAP TABLESPACE ts1:newts1</code>。                                             |

## テーブルレベルの復旧性能関連

### フォローアップテナントの復旧段階

テーブルレベルの復旧におけるフォローアップテナントの復旧段階は、テナントレベルの復旧と同じです。この段階に関連するパフォーマンスパラメータとその説明については、[物理復旧関連パラメータの紹介](../600.restore-data/800.parameters-of-the-restore.md)を参照してください。

### テナント間のテーブルエクスポート段階

**コマンド**

```sql
ALTER SYSTEM SET ddl_thread_score = int_value Tenant=tenant_name;
```

```sql
ALTER SYSTEM SET recover_table_concurrency= int_value Tenant=tenant_name;
```

```sql
ALTER SYSTEM SET recover_table_dop = int_value Tenant=tenant_name;
```

**パラメータの説明**

|         パラメータ                |     説明                                        |
|-----------------------------|------------------------------------------------|
| [ddl_thread_score](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/1950.ddl_thread_score.md)            | テナントOBServerノード上のテーブルレベル復旧スレッドプールの数を制御します。デフォルト値は0で、内部デフォルトのスレッド数は2を意味します。|
| [recover_table_concurrency](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/7810.recover_table_concurrency.md)   | テナントの複数テーブル並列復旧の並列度を制御し、最大で`recover_table_concurrency`個のテーブルが同時にテナント間のテーブルエクスポートを実行することを許可します。デフォルト値は0で、内部デフォルトでは最大1個のテーブルがテナント間のテーブルエクスポートを実行することを許可することを意味します。|
| [recover_table_dop](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/7815.recover_table_dop.md)            | 単一テーブル復旧の並列度を制御します。デフォルト値は0で、内部デフォルトの並列度は1を意味します。<p>このパラメータは具体的に以下の2つの段階に影響します：</p><ul><li>データ復旧段階<p>システムはテーブルの各パーティションを最大`recover_table_dop`個の復旧サブタスクに分割し、各サブタスクは独立したテーブルレベル復旧スレッドによって実行され、並列復旧を実現します。</p> <p>総並列度の計算式：`単一テーブル最大並列度 = パーティション総数 * recover_table_dop`</p> <p>例：現在復旧中のテーブルに4つのパーティションがあり、`recover_table_dop`の値が2である場合、総並列スレッド数は`4*2=8`となります。</p></li> <li>インデックス再構築段階<p>システムは既に復旧されたテーブルデータに基づき、パラレル実行(Parallel Execution, PX)を利用してインデックスを再構築します。PXの並列度は`recover_table_dop`によって決定されます。PXの詳細な説明とチューニングについては、[パラレル実行](../../../700.reference/1000.performance-tuning-guide/500.sql-optimization/350.parallel-execution/100.parallel-execution-concept.md)を参照してください。</p></li></ul>
