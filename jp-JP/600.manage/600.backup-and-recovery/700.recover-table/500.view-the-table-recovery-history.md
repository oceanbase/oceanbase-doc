# テーブルレベルの復元結果を確認する

テーブルレベルの復元タスクが終了した後、ビューを使用してテーブルレベルの復元結果を確認できます。

## ステップ１：テーブルレベル復元タスク全体の実行結果を確認する

1. `root`ユーザーで、復元対象のテーブルがあるターゲットテナントが配置されているクラスタの`sys`テナントにログインします。

2. 以下のコマンドを実行して、テーブルレベル復元タスク全体の結果と補助テナントの復元結果を確認します。

   * テーブルレベル復元タスク全体の結果を確認します。

      ```shell
      obclient> SELECT * FROM oceanbase.CDB_OB_RECOVER_TABLE_JOB_HISTORY WHERE TENANT_ID = tenant_id\G
      ```

## ステップ2：テナント間データ導入タスク全体の実行結果を確認する

テーブルレベルの復元タスク全体の実行状況に基づき、テナント間データ導入タスク全体の実行結果を詳しく確認できます。

1. `root`ユーザーで、復元対象のテーブルが存在するテナントが属するクラスタの`sys`テナントにログインします。

2. 以下のコマンドを実行して、対象テナントのテナント間インポートタスクの結果を確認します。

   ```shell
   obclient> SELECT * FROM oceanbase.CDB_OB_IMPORT_TABLE_JOB_HISTORY WHERE TENANT_ID = tenant_id AND INITIATOR_JOB_ID = recover_table_job_id\G
   ```

   ここで、`tenant_id`は実際のテナントIDに、`recover_table_job_id`は**手順1：テーブルレベルの復元タスク全体の実行結果を確認する**で照会したテーブルレベルの復元タスクの`JOB_ID`に置き換える必要があります。

   `CDB_OB_IMPORT_TABLE_JOB_HISTORY`ビューの各フィールドは、基本的に`CDB_OB_IMPORT_TABLE_JOBS`と対応しています。その中で、`COMMENT`フィールドはタスク失敗時の関連エラー情報を記録するために使用されます。ビュー`CDB_OB_IMPORT_TABLE_JOB_HISTORY`のフィールドに関する詳細な説明については、[物理復元関連ビューの紹介](700.views-of-the-table-recovery.md)を参照してください。

## 手順3：各テーブルの実行結果を確認する

テナント間データ導入タスクの実行状況に基づき、インポートに失敗したテーブルがある場合は、各テーブルの実行結果を詳しく確認できます。

1. `root`ユーザーで、復元対象のテーブルが存在するテナントが属するクラスタの`sys`テナントにログインします。

2. 以下のコマンドを実行して、各テーブルのインポート結果を確認します。

   ```shell
   obclient> SELECT * FROM oceanbase.CDB_OB_IMPORT_TABLE_TASK_HISTORY WHERE TENANT_ID = tenant_id AND JOB_ID = import_table_job_id\G
   ```

   ここで、`tenant_id`は実際のテナントIDに、`import_table_job_id`は**手順2：テナント間データ導入タスク全体の実行結果を確認する**で照会したテナント間データ導入タスクの`JOB_ID`に置き換える必要があります。

   `CDB_OB_IMPORT_TABLE_TASK_HISTORY`ビューの各フィールドは、基本的に`CDB_OB_IMPORT_TABLE_TASKS`と対応しています。その中で、`COMMENT`フィールドはタスク失敗時の関連エラー情報を記録するために使用されます。ビュー`CDB_OB_IMPORT_TABLE_TASK_HISTORY`のフィールドに関する詳細な説明については、[物理復元関連ビューの紹介](700.views-of-the-table-recovery.md)を参照してください。
