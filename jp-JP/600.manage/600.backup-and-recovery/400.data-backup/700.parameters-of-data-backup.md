# データバックアップ関連パラメータの確認

バックアップ操作を実行した後、バックアップ関連パラメータの設定情報を確認できます。

## システムテナントからユーザーテナントのデータバックアップ関連パラメータを確認する

1. `root` ユーザーでクラスタの `sys` テナントにログインします。

2. 以下のステートメントをそれぞれ実行し、バックアップ関連のパラメータ設定情報を確認します。

   * バックアップやバックアップのクリーンアップなど、高可用性低優先順位のタスクの現在のワーカースレッド数を確認します。

      例：

      ```sql
      obclient(root@sys)[(none)]> SHOW PARAMETERS LIKE '%ha_low_thread_score%'\G
      ```

      クエリ結果は次のとおりです：

      ```shell
      *************************** 1. row ***************************
               zone: zone1
           svr_type: observer
             svr_ip: 172.xx.xxx.xxx
           svr_port: 2882
               name: ha_low_thread_score
          data_type: INT
              value: 0
               info: the current work thread score of high availability low thread. Range: [0,100] in integer. Especially, 0 means default value
            section: OBSERVER
              scope: TENANT
             source: DEFAULT
         edit_level: DYNAMIC_EFFECTIVE
      default_value: 0
          isdefault: 1
      1 row in set
      ```

      テナントレベルの構成パラメータ `ha_low_thread_score` は、バックアップやバックアップのクリーンアップなど、高可用性低優先順位のタスクの現在のワーカースレッド数を指定するために使用され、デフォルト値は `0` です。データバックアップのタスクの実行速度が遅すぎる場合は、構成パラメータ `ha_low_thread_score` の値を適宜引き上げることができます。推奨されるのは、毎回値を2倍にする方法です。構成パラメータ `ha_low_thread_score` の詳細については、[ha_low_thread_score](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3500.ha_low_thread_score.md)を参照してください。

      バックアップ時のファイルシステムへの同時書き込み数を設定する例：

      ```shell
      obclient(root@sys)[(none)]> ALTER SYSTEM SET ha_low_thread_score = 4 TENANT = mysql_tenant;
      ```

      この例では、構成パラメータ `ha_low_thread_score` の値を `4` に設定することで、そのテナント（`mysql_tenant`）のバックアップタスクのワーカースレッド数が `4` であることを意味します。

   * テナント内のバックアップパラメータ情報（ソース側の設定情報を除く）を確認します。

      ビュー `oceanbase.CDB_OB_BACKUP_PARAMETER` は、現在のクラスタ内のすべてのテナントが設定したバックアップパラメータ情報を記録しています。

      ```sql
      obclient(root@sys)[oceanbase]> SELECT * FROM oceanbase.CDB_OB_BACKUP_PARAMETER\G
      ```

      クエリ結果の例：

      ```shell
      *************************** 1. row ***************************
      TENANT_ID: 1004
           NAME: data_backup_dest
          VALUE: oss://oceanbase-test-bucket/backup/data/?host=xxx.aliyun-inc.com&access_id=xxx&access_key=xxx&delete_mode=delete&checksum_type=md5&enable_worm=true
      1 row in set
      ```

     この例では、`TENANT_ID` が `1004` のテナントのデータバックアップパス（`data_backup_dest`）は `oss://oceanbase-test-bucket/backup/data/?host=xxx.aliyun-inc.com&access_id=xxx&access_key=xxx` であり、同時にそのバックアップファイルのクリーンアップモード（`delete_mode`）は `delete` です。ここで、`delete_mode` には主に以下の2つのモードがあります：

      * `delete` モード：クリーンアップモードが要件を満たすバックアップファイルを直接削除することを表します。

          このモードでは、バックアップファイルをクリーンアップする際、クリーンアップ要件を満たすバックアップファイルはシステムによって直接削除されます。

      * `tagging` モード：クリーンアップモードがクリーンアップ要件を満たすバックアップファイルにタグを設定することを示し、バックアップファイルは保持されます。

          このモードでは、バックアップファイルをクリーンアップする際、クリーンアップ要件を満たすバックアップファイルに対して、システムはこれらのファイルにタグを設定します。タグの `key` は `"delete_mode"`、`value` は `"tagging"` であり、後で設定したタグを使用して OSS または AWS S3 上でこれらのファイルのライフサイクルを管理できるようにします。

      さらに、そのテナントのバックアップパスのパラメータにおいて、`checksum_type=md5` は MD5 アルゴリズムを使用してバックアップファイルの整合性を検証することを意味します。`enable_worm=true` は、OceanBaseデータベースが WORM の仕様に従ってそのパスに対する書き込みおよび削除操作を実行することを意味します。

   * テナント内のバックアップパスの設定関連情報（ソース側の設定情報を含む）を確認します。

      ビュー `CDB_OB_BACKUP_STORAGE_INFO` には、すべてのテナントのバックアップまたはアーカイブパスの設定関連情報が記録されています。

      ```shell
      obclient(root@sys)[oceanbase]> SELECT TENANT_ID, PATH, DEST_TYPE, EXTENSION, MAX_IOPS, MAX_BANDWIDTH, MAX_BANDWIDTH_DISPLAY FROM oceanbase.CDB_OB_BACKUP_STORAGE_INFO WHERE DEST_TYPE='backup_data';
      ```

      クエリ結果の例は以下のとおりです：

      ```shell
      +-----------+---------------------------------------------+-------------+-----------------------------------------------+----------+---------------+-----------------------+
      | TENANT_ID | PATH                                        | DEST_TYPE   | EXTENSION                                     | MAX_IOPS | MAX_BANDWIDTH | MAX_BANDWIDTH_DISPLAY |
      +-----------+---------------------------------------------+-------------+-----------------------------------------------+----------+---------------+-----------------------+
      |      1004 | oss://oceanbase-test-bucket/backup/data     | backup_data | checksum_type=md5&enable_worm=true&zone=zone1 |     1000 |             0 | UNLIMITED             |
      +-----------+---------------------------------------------+-------------+-----------------------------------------------+----------+---------------+-----------------------+
      1 row in set
      ```

      クエリ結果において、テナントIDが `1004` のテナントのバックアップパスは `oss://oceanbase-test-bucket/backup/data` です。`checksum_type=md5` は MD5 アルゴリズムを使用してバックアップファイルの整合性を検証することを意味します。`enable_worm=true` は、OceanBaseデータベースが WORM の仕様に従ってそのパスに対する書き込みおよび削除操作を実行することを意味します。ソース側の設定は `zone=zone1` であり、`zone1` のノードのみがそのパスにアクセスできることを意味します。I/O スロットリングについて、`MAX_IOPS` が `1000` であることは、現在のバックアップパスが1秒間に最大約1000回のI/Oリクエストを許可することを意味します。`MAX_bandWIDTH_DISPLAY` が `UNLIMITED` であることは、帯域幅を制限しないことを意味します。

## ユーザーテナントが自身のデータバックアップ関連パラメータを確認する方法

1. テナント管理者がデータベースにログインします。

   <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>MySQLテナントの管理者ユーザーは <code>root</code> ユーザー、Oracleテナントの管理者ユーザーは <code>SYS</code> ユーザーです。</p>
   </main>

2. 以下の各ステートメントを実行して、バックアップ関連のパラメータ設定情報を確認します。

   * バックアップ、バックアップクリーンアップなどの高可用性低優先順位タスクの現在のワーカースレッド数を確認します。

      例：

      ```shell
      obclient(root@mysql001)[(none)]> SHOW PARAMETERS LIKE '%ha_low_thread_score%'\G
      ```

      クエリ結果は次のとおりです：

      ```shell
      *************************** 1. row ***************************
               zone: zone1
           svr_type: observer
             svr_ip: 172.xx.xxx.xxx
           svr_port: 2882
               name: ha_low_thread_score
          data_type: INT
              value: 0
               info: the current work thread score of high availability low thread. Range: [0,100] in integer. Especially, 0 means default value
            section: OBSERVER
              scope: TENANT
             source: DEFAULT
         edit_level: DYNAMIC_EFFECTIVE
      default_value: 0
          isdefault: 1
      1 row in set
      ```

      テナントレベルの構成パラメータ `ha_low_thread_score` は、バックアップ、バックアップクリーンアップなどの高可用性低優先順位タスクの現在のワーカースレッド数を指定するために使用され、デフォルト値は `0` です。データバックアップタスクの実行速度が遅すぎる場合は、構成パラメータ `ha_low_thread_score` の値を適宜引き上げることができます。推奨されるのは、毎回値を2倍にすることです。構成パラメータ `ha_low_thread_score` の詳細については、[ha_low_thread_score](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3500.ha_low_thread_score.md)を参照してください。

      ユーザーテナントが自身のテナントバックアップ時のファイルシステムへの同時書き込み数を設定する例は以下のとおりです：

      ```shell
      obclient(root@mysql001)[(none)]> ALTER SYSTEM SET ha_low_thread_score = 4;
      ```

      例では、構成パラメータ `ha_low_thread_score` の値を `4` に設定しているため、現在のテナントバックアップタスクのワーカースレッド数は `4` です。

   * 当該テナントのバックアップパラメータ情報（ソース側の設定情報を除く）を確認します。

      ユーザーテナントは、`oceanbase.DBA_OB_BACKUP_PARAMETER` ビュー（MySQLモード）または `SYS.DBA_OB_BACKUP_PARAMETER` ビュー（Oracleモード）を使用して、自身のテナントに設定されたバックアップパラメータ情報を確認できます。

      :::tab
      tab MySQLモード

      MySQLモードでのクエリ例は以下のとおりです：

      ```shell
      obclient(root@mysql001)[oceanbase]> SELECT * FROM oceanbase.DBA_OB_BACKUP_PARAMETER;
      ```

      tab Oracleモード

      Oracleモードでのクエリ例は以下のとおりです：

      ```shell
      obclient(SYS@oracle001)[SYS]> SELECT * FROM SYS.DBA_OB_BACKUP_PARAMETER;
      ```

      :::

      クエリ結果の例は以下のとおりです：

      ```shell
      +------------------+-------------------------------------------------------------------------------------------------------------------------------------------------------+
      | NAME             | VALUE                                                                                                                                                 |
      +------------------+-------------------------------------------------------------------------------------------------------------------------------------------------------+
      | data_backup_dest | oss://oceanbase-test-bucket/backup/data/?host=xxx.aliyun-inc.com&access_id=xxx&access_key=xxx&delete_mode=delete&checksum_type=md5&enable_worm=true   |
      +------------------+-------------------------------------------------------------------------------------------------------------------------------------------------------+
      1 row in set
      ```

      クエリ結果によると、現在のテナントバックアップパスのパラメータでは、`checksum_type=md5` はMD5アルゴリズムを使用してバックアップファイルの整合性を検証することを示し、`enable_worm=true` はOceanBaseデータベースがWORM仕様に従ってそのパスに対する書き込みおよび削除操作を実行することを示します。

   * 現在のテナントバックアップパスの設定関連情報（ソース側の設定情報を含む）を確認します。

      ユーザーテナントは、`oceanbase.DBA_OB_BACKUP_STORAGE_INFO` ビュー（MySQLモード）または `SYS.DBA_OB_BACKUP_STORAGE_INFO` ビュー（Oracleモード）を使用して、自身のテナントのバックアップまたはアーカイブパスの設定関連情報を確認できます。

      :::tab
      tab MySQLモード

      MySQLモードでのクエリ例は以下のとおりです：

      ```shell
      obclient(root@mysql001)[oceanbase]> SELECT PATH, DEST_TYPE, EXTENSION, MAX_IOPS, MAX_BANDWIDTH, MAX_BANDWIDTH_DISPLAY FROM oceanbase.DBA_OB_BACKUP_STORAGE_INFO WHERE DEST_TYPE='backup_data';
      ```

      tab Oracleモード

      Oracleモードでのクエリ例は以下のとおりです：

      ```shell
      obclient(SYS@oracle001)[SYS]> SELECT PATH, DEST_TYPE, EXTENSION, MAX_IOPS, MAX_BANDWIDTH, MAX_BANDWIDTH_DISPLAY FROM SYS.DBA_OB_BACKUP_STORAGE_INFO WHERE DEST_TYPE='backup_data';
      ```

      :::

      クエリ結果の例は以下のとおりです：

      ```shell
      +---------------------------------------------+-------------+-----------------------------------------------+----------+---------------+-----------------------+
      | PATH                                        | DEST_TYPE   | EXTENSION                                     | MAX_IOPS | MAX_BANDWIDTH | MAX_BANDWIDTH_DISPLAY |
      +---------------------------------------------+-------------+-----------------------------------------------+----------+---------------+-----------------------+
      | oss://oceanbase-test-bucket/backup/data     | backup_data | checksum_type=md5&enable_worm=true&zone=zone1 |     1000 |             0 | UNLIMITED             |
      +---------------------------------------------+-------------+-----------------------------------------------+----------+---------------+-----------------------+
      1 row in set
      ```

      クエリ結果によると、現在のテナントのバックアップパスは `oss://oceanbase-test-bucket/backup/data` です。`checksum_type=md5` はMD5アルゴリズムを使用してバックアップファイルの整合性を検証することを示し、`enable_worm=true` はOceanBaseデータベースがWORM仕様に従ってそのパスに対する書き込みおよび削除操作を実行することを示します。ソース側の設定は `zone=zone1` であり、`zone1` のノードのみがこのパスにアクセスできることを意味します。I/O スロットリングについて、`MAX_IOPS` が `1000` であることは、現在のバックアップパスが1秒間に最大約1000個のI/Oリクエストを許可することを意味します。`MAX_bandWIDTH_DISPLAY` が `UNLIMITED` であることは、帯域幅に制限がないことを意味します。
