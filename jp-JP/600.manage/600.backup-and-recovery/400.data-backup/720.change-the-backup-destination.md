# バックアップ先の変更

データバックアップを有効にした後、ビジネスニーズに応じてバックアップ先を変更できます。

## 注意事項

自動クリーンアップは、`DATA_BACKUP_DEST` および `LOG_ARCHIVE_DEST` で現在指定されているパス配下のバックアップおよびアーカイブデータのみをクリーンアップできます。バックアップ先を変更した場合、元のバックアップパス配下のデータは手動でのみクリーンアップできます。バックアップの手動クリーンアップの詳細な操作については、[指定されたバックアップまたはアーカイブデータの手動クリーンアップ](../500.clear-backup-data/100.manual-backup-cleanup/200.cleaning-up-specified-backup-data.md)および[バックアップパスまたはアーカイブパスの手動クリーンアップ](../500.clear-backup-data/100.manual-backup-cleanup/300.clear-the-backup_dest_or_archivelog_dest.md)を参照してください。

## 手順

1. テナント管理者がクラスタの `sys` テナントまたはユーザーテナントにログインします。

2. 現在進行中のバックアップタスクがあるかどうかを確認します。詳細な操作については、[データバックアップの進捗状況の確認](500.view-data-backup-progress.md)を参照してください。

   クエリ結果が空ではない場合、データバックアップが進行中であることを意味し、進行中のバックアップタスクを停止する必要があります。バックアップタスクの停止の詳細な操作については、[バックアップの停止](400.stop-data-backup.md)を参照してください。

3. バックアップ先を再設定します。

   バックアップ先を再設定する際、置き換えるディレクトリがそのテナントが以前使用したバックアップディレクトリの場合、そのディレクトリ配下に `format` ファイルが存在している必要があります。それ以外の場合、置き換えるディレクトリは空である必要があります。

   バックアップ先設定の詳細な操作については、[バックアップ前の準備](100.preparation-before-data-backup.md)を参照してください。

4. 完了後、ビュー `CDB_OB_BACKUP_PARAMETER`（`sys` テナント）または `DBA_OB_BACKUP_PARAMETER`（ユーザーテナント）をクエリし、新しいバックアップ先が正常に設定されているかどうかを確認します。詳細な操作については、[データバックアップ関連パラメータの確認](700.parameters-of-data-backup.md)を参照してください。

## 次の操作

バックアップ先の変更が成功した後、フルデータバックアップを再度開始する必要があります。フルデータバックアップの開始の詳細な操作については、[フルデータバックアップの開始](200.initiate-full-data-backup.md)を参照してください。
