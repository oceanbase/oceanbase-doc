# バックアップパスのソース側設定を変更する

データバックアップ中に、ユーザーは業務上の実際の状況に応じて、バックアップパスのソース側設定、すなわち`zone`、`idc`、または`region`の設定を変更できます。変更後、新しい設定情報が元の設定情報を上書きします。

## 制限事項

* V4.2.5バージョンでは、V4.2.5 BP2以降のバージョンからバックアップパスのソース側設定を変更できるようになりました。
* ユーザーテナントは自身のテナントのバックアップパスのソース側設定のみを変更でき、システムテナントが特定のユーザーテナントのバックアップパスのソース側設定を変更することはサポートされていません。

## 注意事項

* バックアップパスの`zone`、`idc`、または`region`設定を変更する際、RegionレベルまたはIDCレベルで設定する必要がある場合は、まず`ALTER SYSTEM MODIFY ZONE zone_name SET REGION=region_name;`または`ALTER SYSTEM MODIFY ZONE zone_name SET IDC=idc_name;`ステートメントを使用してRegion情報またはIDC情報を設定する必要があります。IDCレベルのソース側設定を推奨します。これにより、より多くのネットワーク帯域幅リソースを持つIDCでバックアップタスクを実行できるだけでなく、バックアップタスクの選択可能なノード範囲も広がり、ユーザーはクラスタ内のIDC内Zoneの変更状況を気にする必要もありません。

* バックアップパスの`zone`、`idc`、または`region`設定を変更する際、Root Serviceのリーダーノードが指定された`zone`、`idc`、または`region`内に存在しない場合、バックアップタスクはターゲットバックアップパスにバックアップメタデータを正常に書き込むことができず、最終的にバックアップタスクの実行に失敗します。バックアップパスのソース側設定には、Primary Zone範囲を含めることを推奨します。

* バックアップパスの`zone`、`idc`、または`region`設定を変更する際、バックアップタスクが実行中である場合、実行中のタスクは設定変更を認識するまで最大で数分かかるため、設定変更期間中に設定範囲外のノードがバックアップパスにアクセスし、異なるIDCやリージョン間のトラフィックが発生する可能性があります。

## 手順

1. テナント管理者がクラスタのユーザーテナントにログインします。

2. 以下のステートメントを実行して、バックアップパスのソース側構成を変更します。

   SQLステートメントは次のとおりです：

   ```sql
   ALTER SYSTEM {ALTER|CHANGE|MODIFY} EXTERNAL_STORAGE_DEST PATH [=] 'path' SET ATTRIBUTE = '{zone=zone_name | idc=idc_name | region=region_name}';
   ```

   関連パラメータの説明は以下のとおりです：

   * `path`：変更対象のバックアップパスを指定します。アーカイブメディアがオブジェクトストレージタイプの場合、オブジェクトストレージのホストアドレス、アクセスキーなどの情報も含める必要があります。例えば、アーカイブメディアがOSSの場合、このパスの形式は次のとおりです：

      * V4.2.5 BP3以降のバージョン：`oss://oceanbase-test-bucket/backup/databackup?host=xxxx`

        <main id="notice" type='explain'>
        <h4>説明</h4>
        <p>V4.2.5 BP3以降のバージョンでは、互換性のため、パス形式に`access_key`、`access_id`などのキー情報が含まれている場合でも設定は成功します。</p>
        </main>

      * V4.2.5 BP2バージョン：`oss://oceanbase-test-bucket/backup/databackup?host=xxxx&access_key=xxxx&access_id=xxxx`

   * `zone=zone_name | idc=idc_name | region=region_name`：現在のバックアップパスのソースを指定します。`zone`、`idc`、または`region` の3つの異なるレベルの構成を選択でき、同時に1つのレベルのみを選択するか、設定しないこともできます。

     複数のZone、複数のIDC、または複数のRegionを設定する必要がある場合は、複数のZone/IDC/Region間には英字のカンマ（,）と英字のセミコロン（;）を使用して区切ります。そのうち：

     * 英字のカンマ（,）は、バックアップタスクの実行ノードを選択する際、左右のZone/IDC/Region内のノードが同等の優先順位を持つことを示します。
     * 英字のセミコロン（;）は、左側のZone/IDC/Region内のノードの優先順位が右側よりも高いことを示し、つまり左側のZone/IDC/Region内のノードを優先的に選択してバックアップタスクを実行します。

     例えば、`zone=z1,z2;z3`と設定すると、`z1`、`z2`、`z3`をバックアップのソースとして指定し、`z1`、`z2`は同一の優先順位であり、`z1`、`z2`の優先順位は`z3`よりも高いことを意味します。

   * 設定時に、設定した`zone`、`idc`、または`region`が存在しない場合、ソース情報が存在しないというエラー（エラーコード`-9133`）が表示されます。

   例：

   * バックアップパス`oss://oceanbase-test-bucket/backup/data?host=****.aliyun-inc.com`のソース構成を`zone=z1,z2;z3`から`idc=idc1;idc2`に変更します。

      ```shell
      obclient> ALTER SYSTEM CHANGE EXTERNAL_STORAGE_DEST PATH='oss://oceanbase-test-bucket/backup/data?host=****.aliyun-inc.com' SET ATTRIBUTE = 'idc=idc1;idc2';
      ```

   * バックアップパス`file:///data/nfs/backup/data`のソース構成を`zone=z1,z2;z3`から`region=region1`に変更します。

      ```shell
      obclient> ALTER SYSTEM CHANGE EXTERNAL_STORAGE_DEST PATH='file:///data/nfs/backup/data' SET ATTRIBUTE = 'region=region1';
      ```

   詳細な例については、[ALTER/CHANGE/MODIFY EXTERNAL_STORAGE_DEST](../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/1430.alter-system-change-external-storage-dest-of-mysql-mode.md)を参照してください。

3. 変更が成功したら、ビュー`DBA_OB_BACKUP_STORAGE_INFO`を照会して確認します。

   バックアップパスのソース構成を確認する詳細な手順については、[データバックアップ関連パラメータの確認](700.parameters-of-data-backup.md)を参照してください。
