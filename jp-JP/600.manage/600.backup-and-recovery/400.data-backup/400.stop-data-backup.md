# バックアップの停止

データバックアップを開始した後、実行中のバックアップタスクを停止できます。バックアップを停止した後、自動バックアップクリーンアップ機能が有効になっている場合、バックアップクリーンアップタスクは不完全なバックアップを適時にクリーンアップします。

## 前提条件

実行中のバックアップタスクを停止すると、システム上に一部の不完全なバックアップデータが生成されます。リソースの占有を防ぐため、事前に自動バックアップクリーンアップ機能を有効にし、不完全なバックアップを適時にクリーンアップすることを推奨します。自動バックアップクリーンアップ機能の有効化に関する操作については、[期限切れバックアップの自動クリーンアップ](../500.clear-backup-data/100.cleaning-up-backed-up-data-automatically.md)を参照してください。

## 背景情報

現在のクラスタには、`sys`、`mysql_tenant`、`oracle_tenant` の3つのテナントがあり、テナント `mysql_tenant` と `oracle_tenant` はどちらもデータバックアップを実行していると仮定します。

## システムテナントによるバックアップの停止

`sys` テナントは、クラスタ内のすべてのテナントまたは指定されたテナントのデータバックアップを停止できます。

1. `root` ユーザーでクラスタの `sys` テナントにログインします。

2. 以下のステートメントを実行して、データバックアップを停止します。

   * クラスタ内のすべてのテナントのデータバックアップを停止する

       この方法では、クラスタ内のすべてのテナントのデータバックアップタスクが停止されます。

       ```shell
       obclient [(none)]> ALTER SYSTEM CANCEL BACKUP;
       ```

   * クラスタ内の指定されたテナントのデータバックアップを停止する

        この方法では、指定されたテナントで実行中のデータバックアップタスクのみが停止され、クラスタ内の他のテナントには影響しません。

        ```shell
        obclient [(none)]> ALTER SYSTEM CANCEL BACKUP TENANT = mysql_tenant;
        ```

        <main id="notice" type='explain'>
        <h4>説明</h4>
        <p>複数のテナントを同時に指定する場合は、テナント名の間に英語のカンマ (`,`) を使用して区切ります。</p>
        </main>

## ユーザーテナントによるバックアップの停止

ユーザーテナントは、自身で実行中のデータバックアップタスクを停止でき、他のテナントには影響しません。

1. テナント管理者がデータベースにログインします。

   この例では、`root` ユーザーで `mysql_tenant` テナントにログインするか、`SYS` ユーザーで `oracle_tenant` テナントにログインすることができます。

2. 以下のステートメントを実行して、データバックアップを停止します。

    ```shell
    obclient [(none)]> ALTER SYSTEM CANCEL BACKUP;
    ```
