# バックアップ前の準備

データのバックアップを行う前に、バックアップ先の設定やバックアップキーなどの準備が必要です。

## バックアップ先の設定

バックアップ先を設定する際、システムテナントはユーザーデータを含まず、クラスタ管理用のテナントであり、バックアップ・リストアはサポートされていないため、`sys` テナントでは `DATA_BACKUP_DEST` パラメータの設定は不要です。

### 注意事項

バックアップ先を設定する際、各テナントのバックアップパスは独立した空のディレクトリとして設定する必要があります。異なるテナント間で同じバックアップパスを設定することはできません。

### 手順

1. `sys`テナントまたはユーザーテナントのテナント管理者がデータベースにログインします。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>MySQLモードの管理者ユーザーは<code>root</code>ユーザーであり、Oracleモードの管理者ユーザーは<code>SYS</code>ユーザーです。</p>
   </main>

2. バックアップ先を設定します。

   <main id="notice" type='notice'>
   <h4>注意</h4>
   <p>OceanBaseデータベースV4.0.xからV4.1.0へのアップグレードの場合、アップグレード後にバックアップパスを変更する必要があります。OceanBaseデータベースV4.1.xからV4.2.0へのアップグレードの場合、アップグレード後もバックアップパスを変更する必要はありません。</p>
   </main>

   * システムテナントが指定されたテナントに対してバックアップ先を設定します

     ```sql
     ALTER SYSTEM SET DATA_BACKUP_DEST= 'data_backup_path' TENANT = mysql_tenant;
     ```

   * ユーザーテナントが自身のテナントのバックアップ先を設定します

     ```sql
     ALTER SYSTEM SET DATA_BACKUP_DEST= 'data_backup_path';
     ```

   ステートメントに関する説明は以下のとおりです：

   * このステートメントを使用して、バックアップパスおよびソース側の設定を構成できます。現在、OceanBaseデータベースでサポートされているバックアップメディアには、NFS、Alibaba Cloud OSS、Azure Blob（V4.2.5バージョンでは、V4.2.5 BP6以降からサポート）、AWS S3、およびS3プロトコルに対応したオブジェクトストレージ（例：Huawei OBS、Google GCS、Tencent Cloud COSなど）が含まれます。一部のバックアップメディアは、使用するためのいくつかの基本的な要件を満たす必要があります。各バックアップメディアの具体的な要件については、[物理バックアップと復元の概要](../100.overview-of-physical-backup-and-recovery.md)の**バックアップメディア要件**を参照してください。

   * バックアップパスのソース側とは、そのバックアップパスにアクセスできるノード範囲を指定することを意味します。バックアップパスのソース側設定の詳細については、[SET DATA_BACKUP_DEST](../../../700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/3500.set-data-backup-dest.md)を参照してください。

     バックアップパスのソース側設定後、修正が可能です。具体的な修正手順については、[バックアップパスのソース側設定を変更する](710.modify-the-configuration-of-backup-destination.md)を参照してください。

   詳細な設定については以下のとおりです。

    :::tab
    tab アリババクラウドOSS

    OSSをバックアップメディアとして使用する場合、バックアップパスの設定に加えて、`delete_mode` パラメータを使用してバックアップファイルのクリーンアップモードを構成することもできます。`delete_mode` パラメータは現在、`delete` モードと `tagging` モードの2種類をサポートしています。`delete_mode` パラメータを設定しない場合、デフォルトでは `delete` モードが使用されます。

    さらに、OSSは `checksum_type` パラメータを使用して検証アルゴリズムを指定し、バックアップデータの整合性を検証することもサポートしています。サポートされる値は `md5` および `no_checksum` です。`checksum_type` パラメータを明示的に設定しない場合、デフォルト値は `md5` となります。

    V4.2.5バージョンでは、V4.2.5 BP7バージョンから、OceanBaseデータベースはコンプライアンス保持ポリシーが設定済みのアリババクラウドOSSバケットをバックアップパスとして使用できるようになりました。バックアップパスを設定する際には、`enable_worm` パラメータを使用して、OceanBaseデータベースがバケットの保持ポリシー（WORMポリシー）に基づいてそのパスに対して書き込みおよび削除操作を実行するかどうかを指定できます。このパラメータの許容値は `true` および `false` です。`enable_worm` パラメータを明示的に設定しない場合、デフォルトは `false` となります。`enable_worm=true` に設定する場合は、同時に `checksum_type=md5` を明示的に設定する必要があります。このパラメータは設定後、変更することはできません。

    <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>OceanBaseデータベースは現在、コンプライアンス保持ポリシーを自動的に設定することはありません。バックアップパスを設定する前に、OSSバケットが正しく保持ポリシー（WORMポリシー）が設定され、ロックされていることを確認してください。</p>
    </main>

    各パラメータの詳細については、[SET DATA_BACKUP_DEST](../../../700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/3500.set-data-backup-dest.md)を参照してください。

    <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>OSSをバックアップメディアとして使用する場合、OSSパスの各パラメータは <code>&</code> 記号で区切られます。入力したパラメータ値には、大文字と小文字の英字、数字、<code>/-_$+=</code> およびワイルドカードのみを含めるようにしてください。上記以外の文字を入力すると、設定が失敗する可能性があります。</p>
    </main>

    例：

    * OSSをバックアップメディアとして使用する場合、システムテナントが指定されたテナント `mysql_tenant` にバックアップパスを設定し、バックアップファイルのクリーンアップモードを構成するとともに、検証アルゴリズムを `md5` に指定します。

      ```shell
      obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='oss://oceanbase-test-bucket/backup/data?host=****.aliyun-inc.com&access_id=****&access_key=****&delete_mode=delete&checksum_type=md5' TENANT = mysql_tenant;
      ```

      バックアップデータの整合性を検証したくない場合は、`checksum_type` パラメータを `no_checksum` に設定できます。例：

      ```shell
      obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='oss://oceanbase-test-bucket/backup/data?host=****.aliyun-inc.com&access_id=****&access_key=****&delete_mode=delete&checksum_type=no_checksum' TENANT = mysql_tenant;
      ```

    * OSSをバックアップメディアとして使用する場合、システムテナントが指定されたテナント `mysql_tenant` にバックアップパスを設定し、バックアップファイルのクリーンアップモードを構成するとともに、WORM対応方式によるオブジェクトへの書き込みおよび削除を指定し、検証アルゴリズムを `md5` に指定します。

      <main id="notice" type='notice'>
      <h4>注意</h4>
      <ul><li>OceanBaseデータベースは現在、コンプライアンス保持ポリシーを自動的に設定することはありません。バックアップパスを設定する前に、OSSバケットが正しく保持ポリシー（WORMポリシー）が設定され、ロックされていることを確認してください。</li>
      <li>WORMポリシーが設定されたバケットをバックアップパスとして使用する場合、クリーンアップモードとして <code>tagging</code> モードの使用を推奨します。</li></ul>
      </main>

      ```shell
      obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='oss://oceanbase-test-bucket/backup/data?host=****.aliyun-inc.com&access_id=****&access_key=****&delete_mode=tagging&checksum_type=md5&enable_worm=true' TENANT = mysql_tenant;
      ```

    * OSSをバックアップメディアとして使用する場合、ユーザーが自身のテナントにバックアップパスを設定し、バックアップファイルのクリーンアップモードを構成するとともに、検証アルゴリズムを `md5` に指定します。

      ```shell
      obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='oss://oceanbase-test-bucket/backup/data?host=****.aliyun-inc.com&access_id=****&access_key=****&delete_mode=delete&checksum_type=md5';
      ```

    例では、`oss://` はOSSをバックアップメディアタイプとして使用することを表し、バケット名は `oceanbase-test-bucket`、バケット内のパスは `/backup/data` です。また、パスとパラメータは `?` で区切り、パラメータ間は `&` で区切ります。`host` はバケットのホストアドレスを設定するために使用され、`access_id` および `access_key` は `OSS` のアクセスキーを設定するために使用されます。`delete_mode=delete` はクリーンアップモードが `delete` であり、MD5アルゴリズムを使用してアーカイブファイルの整合性を検証することを表します。`enable_worm=true` は、システムがWORMの仕様に基づいて書き込みと削除操作を実行することを示します。注意が必要なのは、OceanBaseデータベースは現在、コンプライアンス保持ポリシーを自動的に設定することはありません。バックアップパスを設定する前に、OSSバケットが正しく保持ポリシー（WORMポリシー）が設定され、ロックされていることを確認してください。

    tab NFS

    <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>NFSをバックアップメディアとして使用する際は、以下の点にご注意ください：</p>
    <ul>
    <li><code>data_backup_dest</code> の値には、疑問符（?）を含む文字列を設定することはサポートされていません。</li>
    <li><code>data_backup_dest</code> の値は絶対パスに設定する必要があります。OBServerサーバーが <code>data_backup_dest</code> に対して書き込み権限を持っていることを確認してください。</li>
    <li>すべてのOBServerサーバーが同じサーバーのNFSをマウントしていることを確保してください。また、バックアップの円滑な進行を保証するため、本記事で推奨されるパラメータを使用してNFSをマウントする必要があります。NFSのマウントに関する具体的な操作については、<a href="../200.deploy-nfs.md">NFSクライアントのデプロイ</a>を参照してください。</li>
    </ul>
    </main>

    例：

    * NFSをバックアップメディアとして使用する場合、システムテナントが指定されたテナント `mysql_tenant` にバックアップパスを設定します。

      ```shell
      obclient> ALTER SYSTEM SET DATA_BACKUP_DEST= 'file:///data/nfs/backup/data' TENANT = mysql_tenant;
      ```

    * NFSをバックアップメディアとして使用する場合、ユーザー・テナントが自身のテナントにバックアップパスを設定します。

      ```shell
      obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='file:///data/nfs/backup/data';
      ```

    上記の例では、`file://` はNFSをバックアップメディアとして使用することを示し、バックアップパスは `file:///data/nfs/backup/data` です。

    tab AWS S3

    OSSと同様に、AWS S3も`delete_mode`パラメータを使用してバックアップファイルのクリーンアップモードを設定でき、設定方法はOSSと同じです。同様に、AWS S3も`checksum_type`パラメータを使用してチェックサムアルゴリズムを指定し、バックアップデータの整合性を検証できます。サポートされる値は`md5`および`crc32`です。`checksum_type`パラメータを明示的に設定しない場合、デフォルト値は`md5`になります。

    `delete_mode`パラメータと`checksum_type`パラメータの詳細については、[SET DATA_BACKUP_DEST](../../../700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/3500.set-data-backup-dest.md)を参照してください。

    <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>オブジェクトストレージをバックアップメディアとして使用する場合、オブジェクトストレージパスの各パラメータは<code>&</code>記号で区切られます。入力したパラメータ値には、大文字と小文字の英字、数字、<code>/-_$+=</code>、およびワイルドカードのみを含めるようにしてください。上記以外の文字を入力すると、設定が失敗する可能性があります。</p>
    </main>

    AWS S3をバックアップメディアとして使用する構成例は次のとおりです：

    * S3をバックアップメディアとして使用する場合、システムテナントが指定されたテナント`mysql_tenant`に対してバックアップパスを設定し、クリーンアップモードを`delete`に設定し、チェックアルゴリズムを`crc32`に指定します。

      ```shell
      obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='s3://oceanbase-test-bucket/backup/data?host=s3.<region>.amazonaws.com&access_id=****&access_key=****&s3_region=****&delete_mode=delete&checksum_type=crc32' TENANT = mysql_tenant;
      ```

    * AWS S3をバックアップメディアとして使用する場合、ユーザー テナントが自身のテナントに対してバックアップパスを設定し、クリーンアップモードを`delete`に設定し、チェックアルゴリズムを`crc32`に指定します。

      ```shell
      obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='s3://oceanbase-test-bucket/backup/data?host=s3.<region>.amazonaws.com&access_id=****&access_key=****&s3_region=****&delete_mode=delete&checksum_type=crc32';
      ```

    例では、`s3://`はS3をバックアップメディアとして使用することを示し、バケット名`oceanbase-test-bucket`、バケット内のパスは`/backup/data`です。同時に、`?`を使用してパスの他のパラメータを区切り、パラメータ間は`&`で区切ります。`host`はAmazon S3サービスのドメイン名を設定するために使用され、`access_id`と`access_key`はAWSサービスのアクセスキーを設定するために使用されます。`s3_region`はS3をバックアップメディアとして使用する場合、必須パラメータであり、S3のバケットが存在する地域を表します。クリーンアップモードは`delete`で、CRC32アルゴリズムを使用してバックアップデータの整合性を検証します。

    AWS S3パス形式の詳細については、[付録：AWS S3パス形式の説明](../1600.appendix-explanation-of-aws-s3-backupdest.md)を参照してください。

    tab S3プロトコル互換のオブジェクトストレージ

    ほとんどのオブジェクトストレージがS3プロトコルに対応しているため、OceanBaseデータベースの要件を満たすS3プロトコルに互換性があり、OceanBaseシステムコールを実装したいくつかのS3APIの動作にも対応するオブジェクトストレージは、OceanBaseデータベースのバックアップメディアとして利用でき、S3プロトコルを通じてアクセスできます。例えば：OBS、GCS、COSなどはすべてS3プロトコルを通じてアクセスします。

    S3プロトコルで接続されるOBS、GCS、COSなどのオブジェクトストレージでは、`checksum_type` パラメータを使用してチェックサムアルゴリズムを指定し、バックアップデータの整合性を検証することもサポートしています。このパラメータには `md5` のみが許可されています。`checksum_type` パラメータを明示的に設定しない場合、デフォルト値は `md5` です。`checksum_type` パラメータの詳細については、[SET DATA_BACKUP_DEST](../../../700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/3500.set-data-backup-dest.md)を参照してください。

    <main id="notice" type='notice'>
    <h4>注意</h4>
    <ul><li>オブジェクトストレージをバックアップメディアとして使用する場合、オブジェクトストレージパスの各パラメータは <code>&</code> 記号で区切られます。入力したパラメータ値には、大文字と小文字の英字、数字、<code>/-_$+=</code> およびワイルドカードのみを含めるようにしてください。上記以外の文字を入力すると、設定が失敗する可能性があります。</li>
    <li>S3プロトコルに互換性がある一部のオブジェクトストレージでは、AWS S3 SDKのデフォルトのURLエンコード方式をサポートしていない場合があります。この場合、<code>s3://</code> プロトコルを使用してアクセスすると、9129や9026などのオブジェクトストレージ関連のエラーコードが表示されることがあります。その際は、クラスタレベルの構成パラメータ <a href="../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16720.ob_storage_s3_url_encode_type.md">ob_storage_s3_url_encode_type</a> を設定して、AWS S3がリクエストを送信する際のURLエンコード方式をRFC3986標準に準拠させるように推奨します。詳細な設定方法については、以下の <b>COSをバックアップメディアとして使用する操作手順と例</b> を参照してください。</li></ul>
    </main>

    **OBSをバックアップメディアとして使用する構成例は次のとおりです**：

    * OBSをバックアップメディアとして使用する場合、システムテナントが指定テナント `mysql_tenant` にバックアップパスを設定します。

      ```shell
      obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='s3://oceanbase-test-bucket/backup/data?host=obs.****.myhuaweicloud.com&access_id=****&access_key=****' TENANT = mysql_tenant;
      ```

    * OBSをバックアップメディアとして使用する場合、ユーザーテナントが自身のテナントにバックアップパスを設定します。

      ```shell
      obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='s3://oceanbase-test-bucket/backup/data?host=obs.****.myhuaweicloud.com&access_id=****&access_key=****';
      ```

    上記の例では、`s3://` はS3プロトコルに互換性のあるオブジェクトストレージをバックアップメディアとして使用することを表し、バケット名は `oceanbase-test-bucket`、バケット内のパスは `/backup/data` です。同時に、`?` を使用してパスの他のパラメータを区切り、パラメータ間には `&` を使用して区切ります。`host` はOBSサービスのドメイン名を設定するために使用され、`access_id` と `access_key` はOBSサービスのアクセスキーを設定するために使用されます。

    **GCSをバックアップメディアとして使用する構成例は次のとおりです**：

    * GCSをバックアップメディアとして使用する場合、システムテナントが指定テナント `mysql_tenant` にバックアップパスを設定します。

      ```shell
      obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='s3://oceanbase-test-bucket/backup/data?host=https://storage.googleapis.com&access_id=****&access_key=****' TENANT = mysql_tenant;
      ```

    * GCSをバックアップメディアとして使用する場合、ユーザーテナントが自身のテナントにバックアップパスを設定します。

      ```shell
      obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='s3://oceanbase-test-bucket/backup/data?host=https://storage.googleapis.com&access_id=****&access_key=****';
      ```

    上記の例では、`s3://` はS3プロトコルに互換性のあるオブジェクトストレージをバックアップメディアとして使用することを表し、バケット名は `oceanbase-test-bucket`、バケット内のパスは `/backup/data` です。同時に、`?` を使用してパスの他のパラメータを区切り、パラメータ間には `&` を使用して区切ります。`host` はGCSサービスのドメイン名を設定するために使用され、`access_id` と `access_key` はGCSサービスのアクセスキーを設定するために使用されます。

    **COSをバックアップメディアとして使用する操作手順と例は次のとおりです**：

    1. クラスタレベルの構成パラメータ `ob_storage_s3_url_encode_type` の値を確認します。

        ```shell
        obclient> SHOW PARAMETERS LIKE '%ob_storage_s3_url_encode_type%';
        ```

        照会結果は次のとおりです：

        ```shell
        +-------+----------+----------------+----------+-------------------------------+-----------+---------+---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+----------+---------+---------+-------------------+
        | zone  | svr_type | svr_ip         | svr_port | name                          | data_type | value   | info                                                                                                                                                                                        | section  | scope   | source  | edit_level        |
        +-------+----------+----------------+----------+-------------------------------+-----------+---------+---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+----------+---------+---------+-------------------+
        | zone1 | observer | 172.xx.xxx.xxx |     2882 | ob_storage_s3_url_encode_type | NULL      | default | Determines the URL encoding method for S3 requests."default": Uses the S3 standard URL encoding method."compliantRfc3986Encoding": Uses URL encoding that adheres to the RFC 3986 standard. | OBSERVER | CLUSTER | DEFAULT | DYNAMIC_EFFECTIVE |
        +-------+----------+----------------+----------+-------------------------------+-----------+---------+---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+----------+---------+---------+-------------------+
        1 row in set
        ```

    2. 値が `default` の場合は、`compliantRfc3986Encoding` に変更します。

        ```shell
        obclient>ALTER SYSTEM SET ob_storage_s3_url_encode_type='compliantRfc3986Encoding';
        ```

        この構成パラメータの詳細については、[ob_storage_s3_url_encode_type](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16720.ob_storage_s3_url_encode_type.md)を参照してください。

    3. バックアップパスを設定し、`delete_mode` パラメータを使用してバックアップファイルのクリーンアップモードを構成します。

        COSをバックアップメディアとして使用する場合、システムテナントが指定テナント `mysql_tenant` にバックアップパスを設定します。`delete` クリーンアップモードに設定された例は次のとおりです：

        ```shell
        obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='s3://oceanbase-test/backup/data?host=cos.ap-xxxx.myqcloud.com&access_id=***&access_key=***&delete_mode=delete' TENANT = mysql_tenant;
        ```

        COSをバックアップメディアとして使用する場合、ユーザーテナントが自身のテナントにバックアップパスを設定します。`delete` クリーンアップモードに設定された例は次のとおりです：

        ```shell
        obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='s3://oceanbase-test/backup/data?host=cos.ap-xxxx.myqcloud.com&access_id=***&access_key=***&delete_mode=delete';
        ```

        例では、`s3://` はS3プロトコルを使用してバックアップパスにアクセスすることを表し、バケット名は `oceanbase-test`、バケット内のパスは `/backup/archive` です。同時に、`?` を使用してパスの他のパラメータを区切り、パラメータ間には `&` を使用して区切ります。`host` はCOSのホストアドレス、つまりエンドポイント（バケット名を含まないアドレス）を設定するために使用され、`access_id` と `access_key` は `COS` のアクセスキーを設定するために使用されます。

    tab Azure Blob

    V4.2.5バージョンでは、V4.2.5 BP6バージョンからAzure Blobをバックアップメディアとしてサポートしています。

    OSSと同様に、Azure Blobも`delete_mode`パラメータと`checksum_type`パラメータをサポートしています。そのうち、`delete_mode`パラメータはバックアップファイルのクリーンアップモードを設定するために使用され、`delete_mode`パラメータを明示的に設定しない場合、デフォルトで`delete`モードが使用されます。`checksum_type`パラメータは、バックアップファイルの整合性を検証するための検証アルゴリズムを指定するために使用され、サポートされる値は`md5`および`no_checksum`です。`checksum_type`パラメータを明示的に設定しない場合、デフォルト値は`md5`です。

    さらに多くのパラメータの詳細については、[SET DATA_BACKUP_DEST](../../../700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/3500.set-data-backup-dest.md)を参照してください。

    例：

    <main id="notice" type='notice'>
    <h4>注意</h4>
    <ul><li>オブジェクトストレージをバックアップメディアとして使用する場合、オブジェクトストレージパスの各パラメータは<code>&</code>記号で区切られます。入力したパラメータ値には、大文字と小文字の英字、数字、<code>/-_$+=</code>、およびワイルドカードのみを含めるようにしてください。上記以外の文字を入力した場合、設定に失敗する可能性があります。</li>
    <li>Azure Blobをバックアップメディアとして使用する場合、<code>host</code>パラメータのプレフィックスは<code>http://</code>または<code>https://</code>。同时，由于に指定する必要があります。Azure Blobはデフォルトでセキュアな転送を有効にしているため、デフォルトでは<code>https://</code>経由でアクセスします。<code>http://</code>経由でアクセスする必要がある場合は、Azure Blobのセキュアな転送オプションを無効にする必要があります。Azure Blobのセキュアな転送オプションを無効にする方法の詳細については、<a href="https://learn.microsoft.com/en-us/azure/storage/common/storage-require-secure-transfer?toc=%2Fazure%2Fstorage%2Fblobs%2Ftoc.json&bc=%2Fazure%2Fstorage%2Fblobs%2Fbreadcrumb%2Ftoc.json">Azure Blob公式ドキュメント</a>を参照してください。</li></ul>
    </main>

    * Azure Blobをバックアップメディアとして使用する場合、システムテナントが指定されたテナント`mysql_tenant`に対してバックアップパスを設定し、クリーンアップモードを`delete`に設定するとともに、検証アルゴリズムを`md5`に指定します。

      ```shell
      obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='azblob://oceanbase-test-bucket/backup/data?host=http://****.blob.core.windows.net&access_id=****&access_key=****&delete_mode=delete&checksum_type=md5' TENANT = mysql_tenant;
      ```

    * Azure Blobをバックアップメディアとして使用する場合、ユーザーが自身のテナントに対してバックアップパスを設定し、クリーンアップモードを`delete`に設定するとともに、検証アルゴリズムを`md5`に指定します。

      ```shell
      obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='azblob://oceanbase-test-bucket/backup/data?host=http://****.blob.core.windows.net&access_id=****&access_key=****&delete_mode=delete&checksum_type=md5';
      ```

    例では、`azblob://`はAzure Blobをバックアップメディアタイプとして使用することを示しており、バケット名は`oceanbase-test-bucket`、バケット内のパスは`backup/data`です。また、`?`を使用してパスとパラメータを区切り、パラメータ間は`&`で区切ります。`host`はバケットのホストアドレスであり、コンテナプロパティやストレージアカウントの接続文字列を連結することで取得できます。`access_id`はストレージアカウント名、`access_key`はAzure Blobのアクセスキー、クリーンアップモードは`delete`、アーカイブファイルの整合性はMD5アルゴリズムを使用して検証されます。

    :::

3. 設定が成功すると、ビューを使用して詳細な設定情報を確認できます。

   `sys`テナントは`CDB_OB_BACKUP_PARAMETER`ビューを使用して確認でき、ユーザーテナントは`DBA_OB_BACKUP_PARAMETER`を使用して確認できます。

   データバックアップ関連のパラメータ情報と確認方法については、[データバックアップ関連パラメータの確認](700.parameters-of-data-backup.md)を参照してください。

### 設定後の注意事項と説明

パラメータ `data_backup_dest` の設定が完了すると、デフォルトでシステムは設定された宛先ディレクトリに `format` ファイルを作成し、バックアップ宛先の有効性を検証するための情報として使用します。これにより、宛先内のデータの整合性が保証されます。そのため、データバックアップの宛先 `data_backup_dest` を設定する際には、以下の点に注意する必要があります：

* `format` ファイルが存在しない場合、設定対象となる宛先ディレクトリが空であることを要件とします。そうでない場合、システムは `-9080` エラーを報告し、「formatファイルが見つからない」と表示されます。

* `format` ファイルが既にある場合、その内容の検証が通過していることを要件とします。そうでない場合、システムは `-9081` エラーを報告し、「formatファイルが不一致です」と表示されます。formatファイルの内容検証では、クラスタ、テナント、およびバックアップ宛先のメディアタイプなどが、現在の操作対象のクラスタ、テナントおよびバックアップメディアタイプと一致しているかどうかが確認されます。

* バックアップタスクを実行する際、`format` ファイルが存在しない場合や `format` ファイルの検証に失敗した場合、タスクは失敗します。

## バックアップキー

データのバックアップを実行する前に、ソーステナントの暗号化状況を考慮する必要があります。また、ソーステナントに透過的暗号化が設定されている場合は、そのソーステナントのキーもバックアップする必要があります。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>キーをバックアップした後、データの復元を行う前に、ソーステナントの暗号化情報によってキーのローテーションがトリガーされた場合、ソーステナントのキーを再びバックアップする必要があります。</p>
</main>

1. `sys`テナントまたはユーザーテナントのテナント管理者としてデータベースにログインします。

2. キーをバックアップします。

   * システムテナントが指定されたテナントのキーをバックアップする

     ```sql
     ALTER SYSTEM BACKUP KEY TENANT = tenant_name TO 'backup_key_path' ENCRYPTED BY 'password';
     ```

   * ユーザーテナントが自身のテナントのキーをバックアップする

     次のステートメントを使用します：

     ```sql
     ALTER SYSTEM BACKUP KEY TO 'backup_key_path' ENCRYPTED BY 'password';
     ```

   ステートメントの説明：

   * `backup_key_path`：キーをバックアップするパスを指定します。このパスはユーザーが独自に定義し、データのバックアップやログアーカイブのパスと重複してはなりません。

   * `password`：キーのバックアップパスに暗号化パスワードを指定します。

   システムテナントがテナント`mysql_tenant`のキーを`file:///data_backup_dest/key`パスにバックアップする例は次のとおりです：

   ```shell
   obclient> ALTER SYSTEM BACKUP KEY TENANT = mysql_tenant TO 'file:///data_backup_dest/key' ENCRYPTED BY '******';
   ```

3. 設定が成功すると、ビューを使用してキーのバックアップパスを確認できます。

   * システムテナントはビュー`CDB_OB_BACKUP_STORAGE_INFO`を使用してキーのバックアップパスを確認します

     ```shell
     obclient> SELECT * FROM oceanbase.CDB_OB_BACKUP_STORAGE_INFO;
     ```

   * ユーザーテナントはビュー`DBA_OB_BACKUP_STORAGE_INFO`を使用してキーのバックアップパスを確認します

     :::tab
     tab MySQLモード

     ステートメントは以下のとおりです：

     ```shell
     obclient> SELECT * FROM oceanbase.DBA_OB_BACKUP_STORAGE_INFO;
     ```

     Oracleモード

     ステートメントは次のとおりです：

     ```shell
     obclient> SELECT * FROM SYS.DBA_OB_BACKUP_STORAGE_INFO;
     ```

     :::

     ビュー`CDB_OB_BACKUP_STORAGE_INFO`および`DBA_OB_BACKUP_STORAGE_INFO`のフィールドの詳細については、[CDB_OB_BACKUP_STORAGE_INFO](../../../700.reference/700.system-views/300.system-view-of-sys-tenant/200.dictionary-view-of-sys-tenant/15100.oceanbase-cdb_ob_backup_storage_info-of-sys-tenant.md)および[DBA_OB_BACKUP_STORAGE_INFO](../../../700.reference/700.system-views/300.system-view-of-sys-tenant/200.dictionary-view-of-sys-tenant/15200.oceanbase-dba_ob_backup_storage_info-of-sys-tenant.md)を参照してください。
