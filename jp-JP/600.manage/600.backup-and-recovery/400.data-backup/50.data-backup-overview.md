# データバックアップの概要

この記事では、主にデータバックアップのアーキテクチャとバックアップファイルのストレージメカニズムについて説明します。

## データバックアップのアーキテクチャ

データバックアップでは、優先的にフォロワー（follower）コピーを使用してバックアップを行います。

## データバックアップファイルのストレージメカニズム

データバックアップシナリオにおいて、ネイティブNFSプロトコルは大量の小さなファイル（例えば、数千万個の2MBファイル）を処理する際にパフォーマンスが低下するため、OceanBaseデータベースV4.x系ではデータ集約ストレージメカニズムを導入しました。これは、各バックアップユニット（backup item）をパッケージ化して保存することで、小さなファイルの数を削減する仕組みです。バックアップユニットには、SSTableメタデータ、Tabletメタデータ、マクロブロックオブジェクトの3種類のデータが含まれます。デフォルトでは、各バッチで2048個のバックアップユニットが集約されます（各バックアップユニットの最大サイズは2MB）。また、メタデータとマクロブロックのサイズに差異があるため、最終的に生成される集約ファイルのサイズも異なります。
