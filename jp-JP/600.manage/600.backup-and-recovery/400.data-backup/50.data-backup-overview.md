# データバックアップの概要

このセクションでは、データバックアップのアーキテクチャとバックアップファイルのストレージメカニズムについて説明します。

## データバックアップアーキテクチャ

データバックアップでは、優先的にFollowerレプリカを使用してバックアップを行います。データバックアップのアーキテクチャは以下の図のとおりです。

![データバックアップアーキテクチャ図](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.2.1/600.manage/daba-backup-architecture-new.png)

## データバックアップファイルのストレージメカニズム

データバックアップのシナリオでは、ネイティブNFSプロトコルは大量の小ファイル（例えば、数千万個の2MBファイル）を処理する際にパフォーマンスが低下します。そのため、OceanBaseデータベースはV4.xバージョンからデータ集約ストレージメカニズムを導入しました。これは、各バックアップアイテム（backup item）をパッケージ化して保存し、小ファイルの数を減らすものです。バックアップアイテムには、SSTableメタデータ、Tabletメタデータ、マクロブロックオブジェクトの3種類のデータが含まれます。デフォルトでは、各バッチで2048個のバックアップアイテム（各バックアップアイテムの最大サイズは2MB）が集約されます。一度の集約で処理されるバックアップアイテムの数（`backup_data_file_size/2 MB`）は、テナントレベルの構成パラメータ[backup_data_file_size](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/500.backup_data_file_size.md)で調整できます。また、メタデータとマクロブロックのサイズには差異があるため、最終的に生成される集約ファイルのサイズも異なります。
