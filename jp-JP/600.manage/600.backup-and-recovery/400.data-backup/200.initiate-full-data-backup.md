# フルデータバックアップの開始

ログアーカイブが開始された後、フルデータバックアップを開始できます。

## 前提条件

フルデータバックアップを実行する前に、以下の事項を確認してください：

* 現在アーカイブモードが有効であることを確認します。ログアーカイブタスクの`STATUS`が`DOING`の場合にのみ、データバックアップを開始できます。

  ログアーカイブタスクのステータスを確認する方法については、[アーカイブ進捗状況の確認](../300.log-archive/600.view-log-archive-progress.md)を参照してください。

  アーカイブモードを有効にする方法については、[アーカイブモードの有効化](../300.log-archive/300.open-the-log-archive-mode.md)を参照してください。

## バックアップの準備（オプション）

データバックアップを開始する前に、バックアップ後のバックアップセットにパスワードを設定できます。

1. `root`ユーザーでクラスタの`sys`テナントにログインします。

2. （オプション）次のコマンドを実行して、バックアップのパスワードを設定します。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>このパスワードはバックアップ後のバックアップセットのパスワードです。このオプションを設定した場合、そのバックアップセットを使用して復元する際にはこのパスワードを入力する必要があり、またこのパスワードは削除できません。</p>
   </main>

   ```shell
   obclient [(none)]> SET ENCRYPTION ON IDENTIFIED BY 'password' ONLY;
   ```

   例：

   ```shell
   obclient [(none)]> SET ENCRYPTION ON IDENTIFIED BY '******' ONLY;
   ```

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>バックアップパスワードを設定した後、データバックアップを開始する前であれば、セッションを切断してから再度データベースに接続することで、この設定を取り消すことができます。</p>
   </main>

## フルバックアップの開始

準備が完了したら、以下の方法でフルデータバックアップを開始できます。

現在のクラスタには、`sys`、`mysql_tenant`、`oracle_tenant` の3つのテナントがあり、テナント `mysql_tenant` と `oracle_tenant` はいずれもデータバックアップ開始前の準備が完了していると仮定します。

### システムテナントによるフルバックアップの開始

`sys` テナントは、クラスタ内のすべてのテナントまたは指定されたテナントに対してフルデータバックアップを開始できます。

1. `root` ユーザーでクラスタの `sys` テナントにログインします。

2. (オプション) テナントのバックアップ並列度を設定します。

   バックアップの並列度は、テナントレベルの構成パラメータ `ha_low_thread_score` によって制御されます。この構成パラメータは、バックアップやバックアップクリーンアップなどの中低優先度タスクの現在のワーカースレッド数を指定するために使用され、値の範囲は [0, 100] で、デフォルト値は `0` です。バックアップ開始前に、構成パラメータ `ha_low_thread_score` の値を適切に引き上げることができ、推奨されるのは毎回値を倍増させることです。構成パラメータ `ha_low_thread_score` の関連操作については、[データバックアップ関連パラメータの確認](700.parameters-of-data-backup.md)を参照してください。

   構成パラメータ `ha_low_thread_score` の詳細については、[ha_low_thread_score](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3600.ha_low_thread_score.md)を参照してください。

   * クラスタ内のすべてのテナントのバックアップ並列度を設定します

      ```sql
      obclient [(none)]>  ALTER SYSTEM SET ha_low_thread_score = 10 TENANT = all_user;
      ```

      または

      ```sql
      obclient [(none)]>  ALTER SYSTEM SET ha_low_thread_score = 10 TENANT = all;
      ```

      <main id="notice" type='explain'>
      <h4>説明</h4>
      <p>OceanBaseデータベースはV4.2.1バージョンから、<code>TENANT = all_user</code> と <code>TENANT = all</code> は同じ意味を持ちます。有効範囲がすべてのユーザーテナントの場合、<code>TENANT = all_user</code> を使用することを推奨します。今後 <code>TENANT = all</code> は廃止され、使用されなくなります。</p>
      </main>

   * クラスタ内の指定されたテナントのバックアップ並列度を設定します

      ```sql
      obclient [(none)]>  ALTER SYSTEM SET ha_low_thread_score = 10 TENANT = mysql_tenant;
      ```

3. 以下のステートメントを実行して、フルデータバックアップを開始します。

   * クラスタ内のすべてのテナントに対してフルデータバックアップを開始します

      この方法では、クラスタ内のすべてのテナントに対してフルデータバックアップが開始されます。

      ```sql
      ALTER SYSTEM BACKUP DATABASE [PLUS ARCHIVELOG];
      ```

      ここで、`PLUS ARCHIVELOG` はオプションです。`PLUS ARCHIVELOG` を追加すると、データバックアップ処理中にアーカイブログも同時にバックアップされ、最終的にバックアップディレクトリにはアーカイブログを含む完全なデータセットが生成されます。このデータセットは復旧機能を備えており、アーカイブログに依存せずに、このデータセットを使用してテナントのデータを `min_restore_scn` ポイントに復元できます。さらに、Community EditionユーザーとStandalone Editionユーザーは、このデータセットを使用してスタンバイテナントを作成できます。アーカイブログを含む完全なデータセットを使用してスタンバイテナントを作成する詳細な手順については、[BACKUP DATABASE PLUS ARCHIVELOG機能を使用したスタンバイテナントの作成](../../400.high-availability/300.physical-standby-database-disaster-recovery/200.create-a-standby-tenant/400.create-a-standby-tenant-by-backup-database-plus-archivelog.md)を参照してください。

      クラスタ内のすべてのテナントに対してフルデータバックアップを開始する例は次のとおりです：

      ```sql
      obclient [(none)]> ALTER SYSTEM BACKUP DATABASE;
      ```

      コマンドの実行が成功すると、この例では、システムはクラスタ内の `mysql_tenant` および `oracle_tenant` テナントに対してフルデータバックアップを開始します。

   * クラスタ内の指定されたテナントに対してフルデータバックアップを開始します

      この方法では、指定されたテナントにのみフルデータバックアップが開始され、クラスタ内の他のテナントには影響しません。ステートメントは次のとおりです：

      ```sql
      ALTER SYSTEM BACKUP TENANT = mysql_tenant [PLUS ARCHIVELOG] ;
      ```

      `mysql_tenant` テナントに対してフルデータバックアップを開始する例は次のとおりです：

      ```shell
      obclient [(none)]> ALTER SYSTEM BACKUP TENANT = mysql_tenant;
      ```

      <main id="notice" type='explain'>
      <h4>説明</h4>
      <p>複数のテナントを同時に指定する場合、テナント名の間には英語のカンマ (`,`) を使用して区切ります。</p>
      </main>

      コマンドの実行が成功すると、この例では、システムはクラスタ内の `mysql_tenant` テナントに対してフルデータバックアップを開始します。

   フルバックアップ中は、フルバックアップの進捗状況をリアルタイムで確認できます。具体的な操作については、[データバックアップの進捗状況の確認](../400.data-backup/500.view-data-backup-progress.md)を参照してください。

### ユーザーテナントによるフルバックアップの開始

ユーザーテナントは、自身のテナントに対してフルデータバックアップを開始でき、他のテナントには影響しません。

1. テナント管理者がデータベースにログインします。

    この例では、`root` ユーザーを使用して `mysql_tenant` テナントにログインすることができます。または、`SYS` ユーザーを使用して `oracle_tenant` テナントにログインすることもできます。

2. (オプション)バックアップの並列度を設定します。

   バックアップの並列度は、テナントレベルの構成パラメータ `ha_low_thread_score` によって制御されます。この構成パラメータは、バックアップやバックアップクリーンアップなどの中低優先順位タスクの現在のワーカースレッド数を指定するために使用され、値の範囲は [0, 100] で、デフォルト値は `0` です。バックアップ開始前に、構成パラメータ `ha_low_thread_score` の値を適切に引き上げることができ、推奨されるのは毎回値を倍増させることです。構成パラメータ `ha_low_thread_score` の関連操作については、[データバックアップ関連パラメータの確認](700.parameters-of-data-backup.md)を参照してください。

   構成パラメータ `ha_low_thread_score` の詳細については、[ha_low_thread_score](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3600.ha_low_thread_score.md)を参照してください。

   ```sql
   obclient [(none)]>  ALTER SYSTEM SET ha_low_thread_score = 10;
   ```

3. 以下のステートメントを実行して、フルデータバックアップを開始します。

   ステートメントは次のとおりです：

    ```sql
    ALTER SYSTEM BACKUP DATABASE [PLUS ARCHIVELOG];
    ```

    そのうち、`PLUS ARCHIVELOG` はオプションです。`PLUS ARCHIVELOG` を追加すると、データバックアップ処理中にアーカイブログも同時にバックアップされ、最終的にバックアップディレクトリにはアーカイブログを含む完全なデータセットが生成されます。このデータセットは復旧機能を備えており、アーカイブログに依存せずに、このデータセットを使用してテナントのデータを `min_restore_scn` ポイントに復元できます。さらに、Community EditionユーザーおよびStandalone Editionユーザーは、このデータセットからスタンバイテナントを作成できます。アーカイブログを含む完全なデータセットを使用してスタンバイテナントを作成する方法の詳細な手順については、[BACKUP DATABASE PLUS ARCHIVELOG機能を使用したスタンバイテナントの作成](../../400.high-availability/300.physical-standby-database-disaster-recovery/200.create-a-standby-tenant/400.create-a-standby-tenant-by-backup-database-plus-archivelog.md)を参照してください。

    ユーザーテナントが自身のテナントに対してフルデータバックアップを開始する例は以下のとおりです：

    ```sql
    obclient [(none)]> ALTER SYSTEM BACKUP DATABASE;
    ```

   コマンドの実行が成功すると、システムは自身のテナントに対してフルデータバックアップを開始します。

   フルバックアップ中は、フルバックアップの進捗状況をリアルタイムで確認できます。具体的な操作については、[データバックアップの進捗状況の確認](../400.data-backup/500.view-data-backup-progress.md)を参照してください。
