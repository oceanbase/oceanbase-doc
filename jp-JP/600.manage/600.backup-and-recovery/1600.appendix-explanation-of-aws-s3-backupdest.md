# 付録：S3パス形式の説明

この記事では、主にAWS S3およびS3互換のオブジェクトストレージにおけるバックアップまたはアーカイブパスの一般的な形式と、関連情報の取得方法について説明します。

## AWS S3

### 汎用フォーマット

AWS S3バックアップパスまたはアーカイブパスの汎用フォーマットは以下のとおりです：

```shell
s3://[bucket_name]/[path]?host=s3.[region].amazonaws.com&access_id=[AWS_Access_Key_ID]&access_key=[AWS_Secret_Access_Key]&s3_region=[region]
```

上記のパスにおいて、`s3://`、`/`、`?host=`、`s3.`、`.amazonaws.com`、`&access_id=`、`&access_key=`、および `&s3_region=` はすべて固定情報であり、置き換える必要はありません。置き換える必要がある情報は以下のとおりです：

* `[bucket_name]`：AWS S3バケットの名前。

* `[path]`：バケット内でユーザーが定義するバックアッププレフィックス。

* `[AWS_Access_Key_ID]`：AWSのアクセスキーID。

* `[AWS_Secret_Access_Key]`：AWSのアクセスキー。

* `[region]`：AWS S3バケットが存在するリージョン。

### 関連情報の取得

#### アクセスキー、キーID、およびストレージの所在リージョン

[AWS CLI](https://docs.aws.amazon.com/zh_cn/cli/latest/userguide/cli-chap-welcome.html)を例にとると、ユーザーが `aws configure` コマンドで設定した情報は、バックアップまたはアーカイブパス内のアクセスキー、アクセスキーID、およびバケットの所在リージョン情報に対応します。

`aws configure` コマンドを実行する際には、`AWS Access Key ID`、`AWS Secret Access Key`、`Default region name` を入力する必要があります。これら3つのパラメータは、それぞれパス形式の `[AWS_Access_Key_ID]`、`[AWS_Secret_Access_Key]`、および `[region]` に対応します。

たとえば、`aws configure` コマンドを使用してアクセスキー、キーID、およびリージョン情報を設定するステートメントの例は以下のとおりです：

```shell
$ aws configure
AWS Access Key ID [None]: my_fake_access_id
AWS Secret Access Key [None]: my_fake_access_key
Default region name [None]: cn-north-1
Default output format [None]:
```

#### バケット名

ユーザーは `aws s3 ls` コマンドを使用して、自身が所有するすべてのバケットを一覧表示できます。

ステートメントの例は以下のとおりです：

```shell
$ aws s3 ls
2025-07-07 17:08:50 mybucket1
2025-07-08 14:55:44 mybucket2
```

例からわかるように、ユーザーが所有するバケットは `mybucket1` と `mybucket2` です。必要に応じて、バックアップ宛先として使用するバケット名を `[bucket_name]` として選択できます。

#### バケット内のバックアッププレフィックス

バックアッププレフィックス `[path]` はユーザーが定義します。[プレフィックス命名規則](https://docs.aws.amazon.com/zh_cn/AmazonS3/latest/userguide/using-prefixes.html)を満たす前提で、そのプレフィックス下に他のオブジェクトがないことを確認してください。

ユーザーは `aws s3 ls` コマンドを使用して、指定されたバケット内のすべてのオブジェクトとプレフィックスを一覧表示できます。

ステートメントの例は以下のとおりです：

```shell
$ aws s3 ls s3://mybucket
PRE my_prefix/
2025-07-07 17:06:27         88 mydoc.txt
```

例からわかるように、バケット `mybucket` 内にはルートレベルのオブジェクト `mydoc.txt` とプレフィックス `my_prefix/` があります。バックアッププレフィックス `[path]` は、`my_prefix/` 以外の任意のプレフィックスにカスタマイズできます。たとえば、`my_prefix/backup/data` などです。

### 完全なバックアップまたはアーカイブパスへの統合

上記の方法に基づき、テキストから取得したパス関連情報は以下のとおりです：

* `[bucket_name]`：mybucket
* `[path]`：my_prefix/backup/data
* `[AWS_Access_Key_ID]`：my_fake_access_id
* `[AWS_Secret_Access_Key]`：my_fake_access_key
* `[region]`：cn-north-1

最終的に統合されたバックアップまたはアーカイブパスの例は次のとおりです：

```shell
s3://mybucket/my_prefix/backup/data?host=s3.cn-north-1.amazonaws.com.cn&access_id=my_fake_access_id&access_key=my_fake_access_key&s3_region=cn-north-1
```

## minioなどS3プロトコルに準拠するオブジェクトストレージ

minioなどS3プロトコルに準拠するオブジェクトストレージの場合、バックアップまたはアーカイブパスの一般的な形式は以下のとおりです：

```shell
s3://[bucket_name]/[path]?host=[endpoint]&access_id=[Access_Key_ID]&access_key=[Secret_Access_Key]
```

その中で：

* `[bucket_name]`：サードパーティのオブジェクトストレージのバケット名。例：mybucket。このパラメータの意味はAWS S3と同じです。

* `[path]`：サードパーティのオブジェクトストレージのバケット内でユーザーが定義したバックアッププレフィックス。例：my_prefix/backup/data。取得方法はAWS S3と類似しています。

* `[endpoint]`：サードパーティのオブジェクトストレージサービスへのアクセスポイント。

  AWS CLIでは、サービスのアクセスポイントとは`[endpoint]`で指定された内容を指します。ローカルデプロイのminioを例にとると、そのエンドポイントは`[ip]:[port]`で構成されています。例：http://127.0.0.1:9000。其他第三方对象存储的 endpoint。詳細については、該当するサービスプロバイダーにお問い合わせください。

  AWS CLIでminioのエンドポイントにアクセスする例を以下に示します。

  ```shell
  $ aws s3 ls --endpoint http://127.0.0.1:9000
  2025-07-07 17:08:50 mybucket1
  2025-07-08 14:55:44 mybucket2
  ```

* `[Access_Key_ID]`：サードパーティのオブジェクトストレージサービスのアクセスキーID。例：my_fake_access_id。このパラメータの意味はAWS S3と同じです。

* `[Secret_Access_Key]`：サードパーティのオブジェクトストレージサービスのアクセスシークレットキー。例：my_fake_access_key。このパラメータの意味はAWS S3と同じです。

minioを例に、最終的に統合されたバックアップまたはアーカイブパスの例を以下に示します：

```shell
s3://mybucket/my_prefix/backup/data?host=http://127.0.0.1:9000&access_id=my_fake_access_id&access_key=my_fake_access_key
```
