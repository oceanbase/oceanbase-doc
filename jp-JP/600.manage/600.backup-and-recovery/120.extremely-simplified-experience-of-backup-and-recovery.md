# 物理バックアップとリカバリの極めてシンプルな体験

このドキュメントは、OceanBaseデータベースの物理バックアップとリカバリを初めて使用するユーザー向けに、テナントレベルでのバックアップとリカバリの簡単な例を通じて、最小限必要な操作手順を提供することを目的としています。主な手順は以下の3つです：

1. ログアーカイブを開始します。
2. データバックアップを開始します。
3. 物理リカバリを開始します。

## 注意事項

* 本記事では、テナントのバックアップを例に説明します。複数のテナントをバックアップする場合は、バックアップ宛先およびアーカイブ宛先の設定時に、各テナントのバックアップパスとアーカイブパスを独立した空ディレクトリとして設定する必要があります。異なるテナント間で同じパスを設定することはできません。
* OceanBaseデータベースは、同一クラスタ内での復旧だけでなく、異なるクラスタ間での復旧もサポートしています。

## 前提条件

この例では、バックアップメディアとしてNFSを使用します。物理バックアップ・リカバリの体験を始める前に、NFSのデプロイが完了していることを確認してください。NFSのデプロイに関する操作については、[NFSのデプロイ](200.deploy-nfs.md)を参照してください。

## 背景情報

本記事では、暗号化されていないテナント`oracle_test`を例に、物理バックアップ機能を使用してこのテナントをバックアップし、その後バックアップデータを使用して新しいテナント`oracle_backup`を復元する方法について説明します。

この例の重要なポイントは以下のとおりです：

1. ソーステナントのログアーカイブパスは`/data/nfs/backup/archive`です。
2. アーカイブはデフォルトのビジネス優先モード（Optional）を選択し、2日ごとに1つのログピースを分割します。
3. ソーステナントのデータバックアップパスは`/data/nfs/backup/data`です。
4. 復元対象のターゲットテナント`oracle_backup`のリソースプールは`restore_pool`、レプリカ`Locality`は`F@z1`であり、テナントを最新のポイントに復元します。

   テナントがマルチレプリカクラスタに属している場合は、[データの復元](600.restore-data/100.preparation-before-recovery.md)の手順に従って復元を実行してください。

## 手順

### ステップ１：ログアーカイブの開始

1. `oracle_test` テナントのテナント管理者でデータベースにログインします。

2. 以下のコマンドを実行して、アーカイブ先を設定します。

   ```sql
   obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=file:///data/nfs/backup/archive';
   ```

3. ログアーカイブモードを有効にします。

   ```sql
   obclient> ALTER SYSTEM ARCHIVELOG;
   ```

4. ログアーカイブステータスが `DOING` であることを確認します。ログアーカイブステータスが `DOING` の場合にのみ、データバックアップを開始できます。

   ```sql
   obclient> SELECT * FROM DBA_OB_ARCHIVELOG\G
   ```

   クエリ結果は次のとおりです：

### ステップ2：データバックアップの開始

ログアーカイブステータスが `DOING` になっていることを確認したら、データバックアップを開始できます。

1. `oracle_test` テナントのテナント管理者でデータベースにログインします。

2. 以下のコマンドを実行して、バックアップ先を設定します。

   ```sql
   obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='file:///data/nfs/backup/data';
   ```

3. フルデータバックアップを開始します。

   ```sql
   obclient> ALTER SYSTEM BACKUP DATABASE;
   ```

4. データバックアップの終了を待ちます。

   ビュー `DBA_OB_BACKUP_TASKS` を照会します。照会結果のタスクリストが空であれば、データバックアップは完了しています。

   ```sql
   obclient> SELECT * FROM DBA_OB_BACKUP_TASKS;
   ```

5. データバックアップの結果を確認します。

   ```sql
   obclient> SELECT * FROM DBA_OB_BACKUP_JOB_HISTORY;
   ```

   クエリ結果は次のとおりです：


詳細なデータバックアップの操作と説明については、[データバックアップ](400.data-backup/100.preparation-before-data-backup.md)セクションを参照してください。

### ステップ3：物理復旧の実行

1. `root` ユーザーで、ターゲットテナントが存在するクラスタの `sys` テナントにログインします。

2. ターゲットテナントに必要なリソースを作成します。

   1. リソースユニット `unit_backup` を作成します。

      ```sql
      obclient> CREATE RESOURCE UNIT unit_backup MAX_CPU 8, MEMORY_SIZE = '16G', MAX_IOPS 10240, MIN_IOPS=10240;
      ```

   2. ターゲットテナントが使用するリソースプールを作成します。ソーステナントと同じ構成を維持することを推奨します。つまり、リソースプール内の `UNIT_NUM` の数をソーステナントと同じにします。

      ```sql
      obclient> CREATE RESOURCE POOL restore_pool UNIT = 'unit_backup', UNIT_NUM = 1, ZONE_LIST = ('z1');
      ```

3. 物理復旧を実行し、新しいテナント `oracle_backup` を復旧します。

   ```sql
   obclient> ALTER SYSTEM RESTORE oracle_backup FROM 'file:///data/nfs/backup/data,file:///data/nfs/backup/archive' WITH 'pool_list=restore_pool&locality=F@z1';
   ```

詳細な物理復旧の操作と説明については、[データの復旧](600.restore-data/100.preparation-before-recovery.md)セクションを参照してください。
