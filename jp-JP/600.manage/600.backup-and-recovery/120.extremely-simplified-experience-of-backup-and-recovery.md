# 物理バックアップとリストアの極めてシンプルな体験

このドキュメントは、OceanBaseデータベースの物理バックアップとリストアを初めて使用するユーザーに向けた、最小限の操作手順を提供することを目的としています。主に以下の3つのステップで構成されています：

1. ログアーカイブの開始。
2. データバックアップの開始。
3. 物理リストアの開始。

## 注意点

* 本記事では、1つのテナントのバックアップを例に説明します。複数のテナントをバックアップする場合は、バックアップ宛先およびアーカイブ宛先の設定時に、各テナントのバックアップパスとアーカイブパスを独立した空ディレクトリに設定する必要があります。異なるテナント間で同じパスを設定してはなりません。
* OceanBaseデータベースは、同一クラスタ内での復元だけでなく、異なるクラスタ間での復元もサポートしています。

## 前提条件

この例では、バックアップ媒体としてNFSを使用します。物理バックアップ・リストアの手順を確認する前に、NFSのデプロイが完了していることを確認してください。NFSのデプロイに関する操作については、[NFSのデプロイ](200.deploy-nfs.md)を参照してください。

## 背景

本記事では、非暗号化テナント `oracle_test` を例に、物理バックアップ機能を使用してこのテナントをバックアップし、その後バックアップデータから新しいテナント `oracle_backup` を復元する方法について説明します。

この例の重要なポイントは以下のとおりです：

1. ソーステナントのログアーカイブパスは `/data/nfs/backup/archive` です。
2. アーカイブはデフォルトのビジネス優先モード (Optional) を選択し、1日ごとにログピースを分割します。
3. ソーステナントのデータバックアップパスは `/data/nfs/backup/data` です。
4. 復元対象のターゲットテナント `oracle_backup` のリソースプールは `restore_pool`、レプリカ `Locality` は `F@z1` とし、テナントを最新の時点に復元します。

   テナントが存在するクラスタがマルチレプリカクラスタの場合は、[データの復元](600.restore-data/100.preparation-before-recovery.md)の章を参照し、手順に従って復元を実行してください。

## 手順

### ステップ１：ログアーカイブの開始

1. `oracle_test` テナントのテナント管理者としてデータベースにログインします。

2. 以下のコマンドを実行し、アーカイブの宛先を設定します。

   ```sql
   obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=file:///data/nfs/backup/archive';
   ```

3. ログアーカイブモードを有効にします。

   ```sql
   obclient> ALTER SYSTEM ARCHIVELOG;
   ```

4. ログアーカイブのステータスが `DOING` であることを確認します。データバックアップを開始できるのは、ログアーカイブのステータスが `DOING` の場合のみです。

   ```sql
   obclient> SELECT * FROM DBA_OB_ARCHIVELOG\G
   ```

   クエリ結果は次のとおりです：

### ステップ2：データバックアップの開始

ログアーカイブの状態が `DOING` になったら、データバックアップを開始できます。

1. `oracle_test` テナントのテナント管理者としてデータベースにログインします。

2. 以下のコマンドを実行し、バックアップの宛先を設定します。

   ```sql
   obclient> ALTER SYSTEM SET DATA_BACKUP_DEST='file:///data/nfs/backup/data';
   ```

3. フルデータバックアップを開始します。

   ```sql
   obclient> ALTER SYSTEM BACKUP DATABASE;
   ```

4. データバックアップの終了を待ちます。

   ビュー `DBA_OB_BACKUP_TASKS` を照会できます。クエリ結果のタスクリストが空の場合、データバックアップは終了したことを意味します。

   ```sql
   obclient> SELECT * FROM DBA_OB_BACKUP_TASKS;
   ```

5. データバックアップの結果を確認します。

   ```sql
   obclient> SELECT * FROM DBA_OB_BACKUP_JOB_HISTORY;
   ```

   クエリ結果は次のとおりです：


データバックアップの詳細な操作手順および説明については、[データバックアップ](400.data-backup/100.preparation-before-data-backup.md)の章を参照してください。

### ステップ3：物理復元の実行

1. `root` ユーザーとして、対象テナントが存在するクラスタの `sys` テナントにログインします。

2. 対象テナントに必要なリソースを作成します。

   1. リソースユニット `unit_backup` を作成します。

      ```sql
      obclient> CREATE RESOURCE UNIT unit_backup MAX_CPU 8, MEMORY_SIZE = '16G', MAX_IOPS 10240, MIN_IOPS=10240;
      ```

   2. 対象テナントが使用するリソースプールを作成します。可能であれば、ソーステナントと同型に保つことを推奨します。つまり、リソースプール内の `UNIT_NUM` の数をソーステナントと同じにします。

      ```sql
      obclient> CREATE RESOURCE POOL restore_pool UNIT = 'unit_backup', UNIT_NUM = 1, ZONE_LIST = ('z1');
      ```

3. 物理復元を実行し、新しいテナント `oracle_backup` を復元します。

   ```sql
   obclient> ALTER SYSTEM RESTORE oracle_backup FROM 'file:///data/nfs/backup/data,file:///data/nfs/backup/archive' WITH 'pool_list=restore_pool&locality=F@z1';
   ```

物理復元の詳細な操作手順および説明については、[データの復元](600.restore-data/100.preparation-before-recovery.md)の章を参照してください。
