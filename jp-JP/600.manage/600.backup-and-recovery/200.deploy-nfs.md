# NFSのデプロイ

バックアップメディアを選択する際は、OSSをバックアップ先として使用することを推奨します。OSSはより高い安定性を持っています。

NFSをバックアップ先として使用する必要がある場合は、このセクションの内容に基づいてNFSをデプロイできます。NFSにはソフトウェア版とハードウェア版があり、ソフトウェア版のNFSは不安定で、NFSがハングする可能性があり、これによりバックアップタスクが停止したり、NFSをマウントしたマシンが正常に動作できなくなることがあります。そのため、専用のNFSハードウェアデバイスを使用することを推奨します。

## 注意事項

* NFS環境を使用する場合、NFSをマウントした上でバックアップを開始する必要があります。バックアップ期間中にNFSに問題が発生した場合は、まずデータのバックアップとログアーカイブを停止し、その後NFSの問題を解決する必要があります。

* OceanBaseデータベースはNFS 3以降のバージョンをサポートしています。

* SSDを用いたNFSサービスの使用を推奨します。NFSのパフォーマンス不足による不安定な状態を回避できます。

* NFSをバックアップメディアとして使用する際には、すべてのOBServerノードが同一サーバーのNFSをマウントしていることを確認してください。また、バックアップの円滑な実行を確保するため、本記事で推奨されているパラメータを使用してNFSをマウントする必要があります。具体的なNFSのマウント手順については、本節の**NFSクライアントのデプロイ**を参照してください。

* OBServerノードを再起動する際には、まずNFSを起動し、その後OBServerノードを起動する必要があります。

* 新しいマシンを追加した後、OBServerノードを起動する前に、新しいマシンがNFSを正常にマウントしているか、または他のメディアへのバックアップが可能であることを確認する必要があります。

## NFSソフトウェアのサーバー側をデプロイする

<main id="notice" type='notice'>
<h4>注意</h4>
<p>NFSハードウェアデバイスを使用している場合は、この操作をスキップし、NFSクライアントを直接デプロイすることができます。</p>
</main>

1. NFSサーバーにログインします。

2. 以下のコマンドを実行し、YUMパッケージマネージャーを使用してNFSをインストールします。

   ```shell
   sudo yum install nfs-utils
   ```

3. Exportsを設定します。

   1. バックアップに必要な容量とパフォーマンスを考慮し、適切なディレクトリを選択して共有ディレクトリとします。

      例えば、本記事では共有ディレクトリとして`/data/nfs_server/`を選択します。

   2. `sudo vim /etc/exports` コマンドを使用して設定ファイルを開き、以下の情報を設定します。

      ```shell
      /data/nfs_server/ xx.xx.xx.xx/16(rw,sync,all_squash)
      ```

      ここで、`xx.xx.xx.xx` はアクセスを許可するネットワークセグメントを表します。

   3. 以下のコマンドを実行し、匿名ユーザーに権限を付与し、`exports` で指定されたディレクトリへのアクセス権限を確保します。

      :::tab
      tab CentOS 7

      CentOS 7の場合、NFSはデフォルトで匿名ユーザーとして<code>nfsnobody</code>を使用します。コマンドは以下のとおりです：

      ```shell
      sudo chown nfsnobody:nfsnobody -R /data/nfs_server
      ```

      tab CentOS 8

      CentOS 8以降のバージョンでは、NFSはデフォルトで匿名ユーザーとして<code>nobody</code>を使用します。コマンドは以下のとおりです：

      ```shell
      sudo chown nobody:nobody -R /data/nfs_server
      ```

      :::

4. 以下のコマンドを実行して、NFSを再起動します。

   ```shell
   sudo systemctl restart nfs-server
   ```

5. Slot Tableを設定します。

   1. `sudo vim /etc/sysctl.conf` コマンドを実行して、`sysctl.conf` 設定ファイルを開き、ファイルに以下の情報の行を追加します。

      ```xml
      sunrpc.tcp_max_slot_table_entries=128
      ```

   2. 以下のコマンドを実行して、同時に発生するNFSリクエストの数を128に変更します。

      ```sql
      sudo sysctl -w sunrpc.tcp_max_slot_table_entries=128
      ```

      コマンドが正常に実行されると、`cat /proc/sys/sunrpc/tcp_max_slot_table_entries` コマンドで設定が反映されているかどうかを確認できます。返された値が128の場合、変更に成功しました。

   3. (オプション) マシンを再起動します。

## NFSクライアントのデプロイ

NFSクライアントをデプロイする際には、すべてのOBServerノードで操作を行う必要があります。

以下の説明では、ある特定のOBServerノードでの操作を例に、操作ガイドを提供します。

1. OBServerノードにログインします。

2. 以下のコマンドを実行して、YUMパッケージマネージャーを使用してNFSをインストールします。

   ```shell
   sudo yum install nfs-utils
   ```

3. Slot Tableを設定します。

   1. `sudo vim /etc/sysctl.conf` コマンドを実行して、`sysctl.conf` 設定ファイルを開き、そのファイルに次の情報を追加します：

      ```xml
      sunrpc.tcp_max_slot_table_entries=128
      ```

   2. 以下のコマンドを実行して、同時に発起されるNFSリクエスト数を128に変更します。

      ```sql
      sudo sysctl -w sunrpc.tcp_max_slot_table_entries=128
      ```

      コマンドが正常に実行された後、`cat /proc/sys/sunrpc/tcp_max_slot_table_entries` コマンドを使用して設定が反映されているかどうかを確認できます。返された値が128の場合、変更は成功しています。

   3. (オプション) マシンを再起動します。

4. 適切なディレクトリを選択してMountポイントとし、以下のコマンドを実行してNFSをマウントします。

      :::tab
      tab NFS 3.x

      例えば、このドキュメントでは`/data/nfs`ディレクトリにマウントされていると仮定しています。適切なディレクトリがない場合は、新しいディレクトリを作成できます。

      ```shell
      sudo mount -tnfs -o rw,nfsvers=3,sync,lookupcache=positive,hard,nolock,timeo=600,wsize=1048576,rsize=1048576,namlen=255 10.10.10.1:/data/nfs_server /data/nfs
      ```

      tab NFS 4.x

      例えば、本記事では`/data/nfs`ディレクトリにマウントされていると仮定します。適切なディレクトリがない場合は、新しいディレクトリを作成できます。

      ```shell
      sudo mount -tnfs -o rw,nfsvers=4.1,sync,lookupcache=positive,hard,timeo=600,wsize=1048576,rsize=1048576,namlen=255 10.10.10.1:/data/nfs_server /data/nfs
      ```

      :::

      ステートメント内では：

      * `nfsvers`：使用するNFSバージョンを表します。NFS 4.xを使用する場合、NFS 4.1以上を推奨します。NFS 4.0では、ファイル名変更後に古いファイルが読み取られるリスクがあるため、使用を避けることを推奨します。

      * `sync`：同期書き込みを使用してデータをサーバーにタイムリーにフラッシュし、データの一貫性を保証します。

      * `lookupcache=positive`：オペレーティングシステムカーネルが指定されたマウントポイントのディレクトリキャッシュを管理する方法を指定します。有効なパラメータは `all` / `none` / `pos` / `postive` です。`postive` は、ディレクトリまたはファイルへの並列アクセス時に誤って存在しないと判断する問題を回避し、データの一貫性を保証するために使用されます。

      * `hard`：NFSが利用不可な場合、システムはアプリケーションの読み書きリクエストをブロックし、データの一貫性を保証します。`soft` オプションを使用することはできません。データエラーのリスクがあります。

      * `lock/nolock`：サーバー上でNLMプロトコルを使用してファイルをロックするかどうかを選択します。デフォルトは `lock` です。NFS 4.xプロトコルセットはファイルロックを統合しているのに対し、NFS 3.xプロトコル自体はファイルロックをサポートしていません。NFS 3.xプロトコルを使用する場合は、マウント時に `nolock` 値を追加することを推奨します。

      * `timeo`：リトライの待機時間を指定します。単位は0.1秒です。設定する際には、あまりに大きな値を設定しないことを推奨します。推奨値は `600` です。

      * `wsize`：書き込まれるデータブロックサイズを表します。推奨値は `1048576` です。

      * `rsize`：読み込まれるデータブロックサイズを表します。推奨値は `1048576` です。

      * `namlen`：推奨値は `255` です。

      * `10.10.10.1`：NFSサーバーのIPアドレスを表します。

      <main id="notice" type='notice'>
      <h4>注意</h4>
      <ul>
      <li>NFS 3/4をマウントする際には、バックアップマウント環境のパラメータに例で推奨されているパラメータが含まれていることを必ず確認してください。</li>
      <li>Docker環境では、ホストマシン上でNFSをマウントした後、Docker内にマッピングする必要があります。Docker内部で直接NFSをマウントすると、クライアントが停止する可能性があります。</li>
      </ul>
      </main>

5. マウントが完了したら、以下のコマンドを実行してNFSのパフォーマンスを検証できます。

   ```shell
   fio -filename=/data/nfs/fio_test -direct=1  -rw=randwrite -bs=2048K -size=100G  -runtime=300 -group_reporting -name=mytest  -ioengine=libaio -numjobs=1 -iodepth=64 -iodepth_batch=8 -iodepth_low=8 -iodepth_batch_complete=8
   ```

   例えば、実行結果は以下のようになります：

   ```shell
   Run status group 0 (all jobs):
   WRITE: io=322240MB, aggrb=1074.2MB/s, minb=1074.2MB/s, maxb=1074.2MB/s, mint=300006msec, maxt=300006msec
   ```

## NFS3マウント時のエラー処理

NFSをデプロイする際、NFS3をマウント時に `requested NFS version or transport protocol is not supported` エラーが発生した場合、以下の手順で対処できます。

1. NFSサーバーにログインします。

2. NFSサーバーがサポートしているバージョンを確認します。

   ```shell
   sudo cat /proc/fs/nfsd/versions
   ```

   以下の情報が返されることがわかります：

   ```shell
   -2 -3 +4 +4.1 +4.2
   ```

   ここで、`-3` はNFS3が無効であることを示しています。

3. 設定を調整します。

   以下の手順でNFS3を有効にすることができます：

   1. `/etc/nfs.conf` ファイルが存在するかどうか確認します。存在する場合は、`/etc/nfs.conf` ファイル内の `vers3=y` の前の `#` を削除する必要があります。

      変更後のサンプルファイルは次のとおりです：

      ```shell
      [nfsd]
      # debug=0
      # threads=8
      # host=
      # port=0
      # grace-time=90
      # Tease-time=90
      # udp=y
      # tcp=y
      # vers2=n
         vers3=y
      # vers4=y
      # vers4.0=y
      # vers4.1=y
      # vers4.2=y
      # rdma=n
      ##
      ```

   2. `/etc/sysconfig/nfs` ファイルが存在するかどうか確認します。存在する場合は、`/etc/sysconfig/nfs` ファイルの `RPCNFSDARGS` パラメータに `-N 3` が指定されているかどうか確認します。指定されている場合は、`-N 3` を削除する必要があります。

      例えば、`-N 3` を削除すると、`RPCNFSDARGS` パラメータの値は次のようになります：

      ```shell
      RPCNFSDARGS="-N 2 -N 4"
      ```

4. 以下のコマンドを実行して、NFSを再起動します。

   ```shell
   sudo systemctl restart nfs-server
   ```

5. 再びNFSサーバーがサポートしているバージョンを確認します。

   ```shell
   sudo cat /proc/fs/nfsd/versions
   ```

   以下の情報が返されることがわかります：

   ```shell
   -2 +3 -4 -4.1 -4.2
   ```

   ここで、`+3` はNFS3が有効であることを示しています。
