# アーカイブパスのクリーンアップ

アーカイブを停止した後、必要に応じてアーカイブパスをクリーンアップできます。アーカイブパスをクリーンアップしても、元のアーカイブパス下のファイルは削除されません。アーカイブパスをクリーンアップした後、後で再び元のパスを使用する必要がある場合は、再度`SET LOG_ARCHIVE_DEST`コマンドを使用してアーカイブパスを元のパスに設定できます。

## 注意事項

アーカイブパスをクリーンアップするには、テナントの現在のアーカイブ状態が`STOP`状態であることが必要です。アーカイブ状態の詳細な操作方法については、[アーカイブ進捗状況の確認](600.view-log-archive-progress.md)を参照してください。

## 手順

1. `sys`テナントまたはユーザーテナントのテナント管理者としてデータベースにログインします。

   <main id="notice" type='explain'>
        <h4>説明</h4>
   <p>MySQLモードの管理者ユーザーは<code>root</code>ユーザー、Oracleモードの管理者ユーザーは<code>SYS</code>ユーザーです。</p>
   </main>

2. 以下のコマンドを実行して、アーカイブパスをクリーンアップします。

   * システムテナントが指定されたテナントのアーカイブパスをクリーンアップする

     ```shell
     obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST='' TENANT = tenant_name;
     ```

   * ユーザーテナントが自身のアーカイブパスをクリーンアップする

     ```shell
     obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST='';
     ```
