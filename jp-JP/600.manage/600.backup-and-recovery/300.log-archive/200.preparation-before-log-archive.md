# ログアーカイブ前の準備

この記事では、ログアーカイブを行う前の準備について説明します。

## （オプション）アーカイブ並列度を設定する

アーカイブモードを有効にする前に、ログアーカイブの並列度を設定することで、テナントのログアーカイブ速度を向上させることができます。

1. `sys` テナントまたはユーザーテナントのテナント管理者がデータベースにログインします。

2. 適切なステートメントを選択して、構成パラメータ `log_archive_concurrency` を設定します。

   テナントレベルの構成パラメータ `log_archive_concurrency` は、ログアーカイブの総作業スレッド数を設定するために使用されます。この構成パラメータはダイナミックに有効化され、OBServerノードの再起動は不要です。この構成パラメータの値の範囲は[0, 100]で、デフォルト値は `0` であり、OceanBaseデータベースが自動的に選択するログアーカイブ並列度を使用することを意味します。デフォルト値の使用を推奨します。

   <main id="notice" type='notice'>
   <h4>注意</h4>
   <p>小規模なテナント（CPUが4コア以下のテナント）では、デフォルト値を使用することを推奨し、この構成パラメータの値を変更しないでください。</p>
   </main>

   設定方法は次のとおりです：

   * `sys` テナントによる指定テナントのログアーカイブ並列度の調整

     ```shell
     ALTER SYSTEM SET log_archive_concurrency = 10 TENANT = mysql_tenant;
     ```

   * `sys` テナントによるすべてのテナントのログアーカイブ並列度の調整

     ```sql
     ALTER SYSTEM SET log_archive_concurrency = 10 TENANT = all_user;
     ```

     または

     ```sql
     ALTER SYSTEM SET log_archive_concurrency = 10 TENANT = all;
     ```

     <main id="notice" type='explain'>
     <h4>説明</h4>
     <p>OceanBaseデータベースはV4.2.1バージョンから、<code>TENANT = all_user</code> と <code>TENANT = all</code> のセマンティクスは同じです。すべてのユーザーテナントに適用範囲が必要な場合は、<code>TENANT = all_user</code> を使用することをお勧めします。<code>TENANT = all</code> は今後廃止されます。</p>

   * ユーザーテナントによる自身のテナントのログアーカイブ並列度の調整

     ```sql
     ALTER SYSTEM SET log_archive_concurrency = 10;
     ```

   構成パラメータ `log_archive_concurrency` の詳細については、[log_archive_concurrency](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/4500.log_archive_concurrency.md)を参照してください。

## アーカイブ先の設定

ログアーカイブタスクを開始する前に、`ALTER SYSTEM` コマンドを使用して `LOG_ARCHIVE_DEST` パラメータを設定する必要があります。システムテナントはユーザーデータを含まず、クラスタ管理用のテナントであり、バックアップ・リカバリをサポートしていないため、`sys` テナントではアーカイブ先の設定は不要です。

アーカイブ先の設定を行う操作の主な内容は、`LOCATION`、`BINDING` および `PIECE_SWITCH_INTERVAL` プロパティの設定です。

### 注意事項

アーカイブ宛先を設定する際には、各テナントのアーカイブパスは独立した空のディレクトリに設定する必要があります。異なるテナント間で同じアーカイブパスを設定することはできません。

### 手順

1. `sys`テナントまたはユーザーテナントのテナント管理者がデータベースにログインします。

   <main id="notice" type='explain'>
        <h4>説明</h4>
   <p>MySQLモードの管理者ユーザーは<code>root</code>ユーザーで、Oracleモードの管理者ユーザーは<code>SYS</code>ユーザーです。</p>
   </main>

2. アーカイブ先を設定します。

   <main id="notice" type='notice'>
   <h4>注意</h4>
   <p>OceanBaseデータベースV4.0.xからV4.1.0へのアップグレードの場合、アップグレード後にアーカイブパスを変更する必要があります。OceanBaseデータベースV4.1.xからV4.2.xへのアップグレードの場合、アップグレード後にはアーカイブパスを変更する必要はありません。また、OceanBaseデータベースV4.1.xからV4.2.xへのアップグレード時には、アップグレード中にログアーカイブを実行できます。</p>
   </main>

   * システムテナントが指定されたテナントに対してアーカイブ先を設定します。

     ```sql
     ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=archive_path [BINDING=archive_mode] [PIECE_SWITCH_INTERVAL=piece_switch_interval]' TENANT = tenant_name;
     ```

   * ユーザーテナントが自身のテナントに対してアーカイブ先を設定します。

     ```sql
     ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=archive_path [BINDING=archive_mode] [PIECE_SWITCH_INTERVAL=piece_switch_interval]';
     ```

   詳細な設定については以下を参照してください。

   * `LOCATION`属性を設定します(必須)

      `LOCATION`プロパティは、アーカイブパスを指定するために使用されます。現在、OceanBaseデータベースでサポートされているアーカイブメディアはNFS、Alibaba Cloud OSS、Azure Blob(バージョンV4.2.5では、V4.2.5 BP6以降からサポートされています)、AWS S3、およびS3プロトコルに対応するオブジェクトストレージ(例：Huawei OBS、Google GCS、Tencent Cloud COSなど)です。一部のアーカイブメディアは使用前にいくつかの基本的な要件を満たす必要があります。各アーカイブメディアの具体的な要件については、[物理バックアップと復旧の概要](../100.overview-of-physical-backup-and-recovery.md)の**バックアップメディアの要件**を参照してください。

      :::tab
      tab 阿里クラウド OSS

      OSSをアーカイブメディアとして使用する場合、アーカイブパス、`host`、`access_key`、`access_id`など設定するほか、`delete_mode`パラメータも設定できます。`delete_mode`パラメータは現在、`delete`モードと`tagging`モードの2種類がサポートされています。`delete_mode`パラメータを明示的に設定しない場合は、デフォルトで`delete`モードが使用されます。

      さらに、OSSでは`checksum_type`パラメータを使用して検証アルゴリズムを指定し、アーカイブファイルの整合性を検証することもできます。サポートされる値は`md5`および`no_checksum`です。`checksum_type`パラメータを明示的に設定しない場合は、デフォルト値は`md5`となります。

      バージョンV4.2.5では、V4.2.5 BP7以降のOceanBaseデータベースは、コンプライアンス保持ポリシーが設定済みのAliyun OSSバケットをアーカイブパスとして使用できるようになりました。アーカイブパスを設定する際には、`enable_worm`パラメータを使用して、OceanBaseデータベースがバケットの保持ポリシー（WORMポリシー）に基づいて該当パスに対して書き込みおよび削除操作を実行するかどうかを指定できます。このパラメータの許容値は`true`および`false`です。`enable_worm`パラメータを明示的に設定しない場合、デフォルトは`false`となります。`enable_worm=true`を設定する際には、同時に`checksum_type=md5`を明示的に設定する必要があります。このパラメータは一度設定すると変更できなくなります。

      <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>OceanBaseデータベースは現在、コンプライアンス保持ポリシーを自動的に設定することはありません。アーカイブパスを設定する前に、OSSバケットに正しく保持ポリシー(WORMポリシー)が設定されており、ロックされていることを確認してください。</p>
      </main>

      各パラメータの詳細については、[SET LOG_ARCHIVE_DEST](../../../700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/150.set-log-archive-dest.md)を参照してください。

      <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>OSSをアーカイブメディアとして使用する場合、OSSパスの各パラメータは<code>&</code>記号によって区切られます。入力したパラメータ値には英字の大文字・小文字、数字、<code>/-_$+=</code>およびワイルドカードのみを含めるようにしてください。上記以外の文字を入力した場合、設定が失敗する可能性があります。</p>
      </main>

      例：

      * OSSをアーカイブメディアとして使用する場合、システムテナントが指定テナント`mysql_tenant`にアーカイブパスを設定し、クリーンアップモードを`delete`に設定するとともに、検証アルゴリズムを`md5`に指定します。

        ```shell
        obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=oss://oceanbase-test-bucket/backup/archive?host=****.aliyun-inc.com&access_id=****&access_key=****&delete_mode=delete&checksum_type=md5' TENANT = mysql_tenant;
        ```

        アーカイブファイルの整合性を検証したくない場合は、`checksum_type`パラメータを`no_checksum`に設定できます。例：

        ```shell
        obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=oss://oceanbase-test-bucket/backup/archive?host=****.aliyun-inc.com&access_id=****&access_key=****&delete_mode=delete&checksum_type=no_checksum' TENANT = mysql_tenant;
        ```

      * OSSをアーカイブメディアとして使用する場合、システムテナントが指定テナント`mysql_tenant`にアーカイブパスを設定し、クリーンアップモードを`tagging`に設定するとともに、WORMサポート方式でのオブジェクトの書き込みおよび削除を指定し、検証アルゴリズムを`md5`に指定します。

        <main id="notice" type='notice'>
        <h4>注意</h4>
        <ul><li>OceanBaseデータベースは現在、コンプライアンス保持ポリシーを自動的に設定することはありません。アーカイブパスを設定する前に、OSSバケットに正しく保持ポリシー(WORMポリシー)が設定されており、ロックされていることを確認してください。</li>
        <li>WORMポリシーが設定されたバケットをアーカイブパスとして使用する場合、クリーンアップモードとして<code>tagging</code>モードの使用を推奨します。</li></ul>
        </main>

        ```shell
        obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=oss://oceanbase-test-bucket/backup/archive?host=****.aliyun-inc.com&access_id=****&access_key=****&delete_mode=tagging&checksum_type=md5&enable_worm=true' TENANT = mysql_tenant;
        ```

      * OSSをアーカイブメディアとして使用する場合、ユーザーテナントが自身のテナントにアーカイブパスを設定し、クリーンアップモードを`delete`に設定するとともに、検証アルゴリズムを`md5`に指定します。

        ```shell
        obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=oss://oceanbase-test-bucket/backup/archive?host=****.aliyun-inc.com&access_id=****&access_key=****&delete_mode=delete&checksum_type=md5';
        ```

      例では、`oss://`はOSSをアーカイブメディアタイプとして使用することを表し、バケット名は`oceanbase-test-bucket`、バケット内のパスは`/backup/archive`です。また、`?`を使用してパスとパラメータを区切り、パラメータ間は`&`で区切ります。`host`はバケットのホストアドレスを設定するために使用され、`access_id`と`access_key`は`OSS`のアクセスキーを設定するために使用されます。`delete_mode=delete`はクリーンアップモードが`delete`であり、MD5アルゴリズムを使用してアーカイブファイルの整合性を検証することを意味します。`enable_worn=true`は、システムがWORMの規格に基づいて書き込みと削除操作を実行することを示します。注意すべき点として、OceanBaseデータベースは現在、コンプライアンス保持ポリシーを自動的に設定することはありません。アーカイブパスを設定する前に、OSSバケットに正しく保持ポリシー(WORMポリシー)が設定されており、ロックされていることを確認してください。

      tab NFS

      <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>NFSをアーカイブメディアとして使用する場合、以下の点にご注意ください：</p>
      <ul>
      <li><code>LOCATION</code> の値には、疑問符（?）を含む文字列を設定することはサポートされていません。</li>
      <li><code>LOCATION</code> の値は絶対パスに設定する必要があります。OBServerサーバーが <code>LOCATION</code> に対して読み取り・書き込み権限を持っていることを確認してください。</li>
      <li>すべてのOBServerサーバーが同一のNFSサーバーにマウントされていることを保証する必要があります。また、アーカイブの円滑な進行を確保するため、本記事で推奨されるパラメータを使用してNFSをマウントするようにしてください。NFSのマウントに関する具体的な操作については、<a href="../200.deploy-nfs.md">NFSクライアントのデプロイ</a>を参照してください。</li>
      </ul>
      </main>

      例：

      * NFSをアーカイブメディアとして使用する場合、システムテナントが指定されたテナント `mysql_tenant` にアーカイブパスを設定します。

        ```shell
        obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=file:///data/nfs/backup/archive' TENANT = mysql_tenant;
        ```

      * NFSをアーカイブメディアとして使用する場合、ユーザーのテナント自身にアーカイブパスを設定します。

        ```shell
        obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=file:///data/nfs/backup/archive';
        ```

      上記の例では、`file://` はNFSをアーカイブメディアとして使用することを表し、アーカイブパスは `/data/nfs/backup/archive` です。

      tab AWS S3

      OSSと同様に、AWS S3も`delete_mode`パラメータを使用してアーカイブファイルのクリーンアップモードを設定でき、その設定方法はOSSと同じです。同様に、AWS S3も`checksum_type`パラメータを使用して検証アルゴリズムを指定し、アーカイブファイルの整合性を検証できます。指定可能な値には`md5`および`crc32`が含まれます。`checksum_type`パラメータを明示的に設定しない場合、デフォルト値は`md5`となります。

      `delete_mode`パラメータと`checksum_type`パラメータの詳細については、[SET LOG_ARCHIVE_DEST](../../../700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/150.set-log-archive-dest.md)を参照してください。

      <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>オブジェクトストレージをアーカイブメディアとして使用する場合、オブジェクトストレージパスの各パラメータは<code>&</code>記号で区切られます。入力したパラメータ値には大文字と小文字の英字、数字、<code>/-_$+=</code>、ワイルドカードのみを含めるようにしてください。上記以外の文字を入力すると、設定が失敗する可能性があります。</p>
      </main>

      S3をアーカイブメディアとして使用する構成例は以下のとおりです：

      * S3をアーカイブメディアとして使用する場合、システムテナントが指定テナント`mysql_tenant`にアーカイブパスを設定し、クリーンアップモードを`delete`に設定し、検証アルゴリズムを`crc32`に指定します。

        ```shell
        obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=s3://oceanbase-test-bucket/backup/archive?host=s3.<region>.amazonaws.com&access_id=******&access_key=******&s3_region=******&delete_mode=delete&checksum_type=crc32' TENANT = mysql_tenant;
        ```

      * S3をアーカイブメディアとして使用する場合、ユーザーテナントが自身のテナントにアーカイブパスを設定し、クリーンアップモードを`delete`に設定し、検証アルゴリズムを`crc32`に指定します。

        ```shell
        obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=s3://oceanbase-test-bucket/backup/archive?host=s3.<region>.amazonaws.com&access_id=******&access_key=******&s3_region=******&delete_mode=delete&checksum_type=crc32';
        ```

      上記の例では、`s3://`はAWS S3をアーカイブメディアとして使用することを表し、バケット名は`oceanbase-test-bucket`、バケット内のパスは`/backup/archive`です。同時に、`?`を使用してパスとパラメータを区切り、パラメータ間は`&`で区切ります。`host`はAmazon S3サービスのドメイン名を設定するために使用され、`access_id`と`access_key`はAWSサービスのアクセスキーを設定するために使用されます。`s3_region`はS3をアーカイブメディアとして使用する場合、必須パラメータであり、S3のバケットが存在する地域を表します。クリーンアップモードは`delete`、アーカイブファイルの整合性はCRC32アルゴリズムを使用して検証されます。

      AWS S3パス形式の詳細については、[付録：AWS S3パス形式の説明](../1600.appendix-explanation-of-aws-s3-backupdest.md)を参照してください。

      tab S3プロトコル互換のオブジェクトストレージ

      ほとんどのオブジェクトストレージがS3プロトコルを互換しているため、OceanBaseデータベースの要件に適合し、かつS3プロトコルを互換しているオブジェクトストレージは、OceanBaseデータベースのアーカイブメディアとして利用可能です。また、S3プロトコルを使用してこれらのオブジェクトストレージにアクセスできます。例えば、OBS、GCS、COSなどはすべてS3プロトコルでアクセスされます。

      S3プロトコルで接続されるOBS、GCS、COSなどのオブジェクトストレージでは、`checksum_type` パラメータを使用してチェックサムアルゴリズムを指定し、アーカイブファイルの整合性を検証することもサポートされています。ただし、`md5` のみ有効です。`checksum_type` パラメータを明示的に設定しない場合、デフォルト値は `md5` となります。`checksum_type` パラメータの詳細については、[SET LOG_ARCHIVE_DEST](../../../700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/150.set-log-archive-dest.md)を参照してください。

      <main id="notice" type='notice'>
      <h4>注意</h4>
      <ul><li>オブジェクトストレージをアーカイブメディアとして使用する場合、オブジェクトストレージパスの各パラメータは <code>&</code> 文字で区切られます。入力したパラメータ値には、大文字と小文字の英字、数字、<code>/-_$+=</code> およびワイルドカードのみを含めるようにしてください。上記以外の文字を入力すると、設定が失敗する可能性があります。</li>
      <li>S3プロトコルを互換している一部のオブジェクトストレージでは、AWS S3 SDKのデフォルトのURLエンコード方式がサポートされていない場合があります。この場合、<code>s3://</code> プロトコルを使用してアクセスする際、9129や9026などのオブジェクトストレージ関連のエラーコードが表示された場合は、クラスタレベルの構成パラメータ<a href="../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16720.ob_storage_s3_url_encode_type.md">ob_storage_s3_url_encode_type</a>を設定して、AWS S3がリクエストを送信する際のURLエンコード方式をRFC3986標準に準拠させるよう推奨します。詳細な設定方法については、以下の<b>COSをアーカイブメディアとして使用する手順と例</b>を参照してください。</li></ul>
      </main>

      **OBSをアーカイブメディアとして使用する構成例は以下のとおりです**：

      * OBSをアーカイブメディアとして使用する場合、システムテナントが指定されたテナント `mysql_tenant` にアーカイブパスを設定します。

        ```shell
        obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=s3://oceanbase-test-bucket/backup/archive?host=obs.****.myhuaweicloud.com&access_id=****&access_key=****' TENANT = mysql_tenant;
        ```

      * OBSをアーカイブメディアとして使用する場合、ユーザーが所属するテナントにアーカイブパスを設定します。

        ```shell
        obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=s3://oceanbase-test-bucket/backup/archive?host=obs.****.myhuaweicloud.com&access_id=****&access_key=****';
        ```

      上記の例では、`s3://` はS3プロトコルを互換しているオブジェクトストレージをアーカイブメディアとして使用することを表します。バケット名は `oceanbase-test-bucket` で、バケット内のパスは `/backup/archive` です。同時に、`?` を使用してパスとパラメータを区切り、パラメータ間は `&` で区切ります。`host` はOBSサービスのドメイン名を設定するために使用され、`access_id` および `access_key` はOBSサービスのアクセスキーを設定するために使用されます。

      **GCSをアーカイブメディアとして使用する構成例は以下のとおりです**：

      * GCSをアーカイブメディアとして使用する場合、システムテナントが指定されたテナント `mysql_tenant` にアーカイブパスを設定します。

        ```shell
        obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=s3://oceanbase-test-bucket/backup/archive?host=https://storage.googleapis.com&access_id=****&access_key=****' TENANT = mysql_tenant;
        ```

      * GCSをアーカイブメディアとして使用する場合、ユーザーが所属するテナントにアーカイブパスを設定します。


      上記の例では、`s3://` はS3プロトコルを互換しているオブジェクトストレージをアーカイブメディアとして使用することを表します。バケット名は `oceanbase-test-bucket` で、バケット内のパスは `/backup/archive` です。同時に、`?` を使用してパスとパラメータを区切り、パラメータ間は `&` で区切ります。`host` はGCSサービスのドメイン名を設定するために使用され、`access_id` および `access_key` はGCSサービスのアクセスキーを設定するために使用されます。

          例では、`s3://` はS3プロトコルを使用してアーカイブパスにアクセスします。バケット名は `oceanbase-test` で、バケット内のパスは `/backup/archive` です。同時に、`?` を使用してパスとパラメータを区切り、パラメータ間は `&` で区切ります。`host` はCOSのホストアドレス、つまりエンドポイント（バケット名を含まないアドレス）を設定するために使用されます。`access_id` および `access_key` は `COS` のアクセスキーを設定するために使用されます。クリーンアップモードは `delete` です。

      tab Azure Blob

      V4.2.5バージョンでは、V4.2.5 BP6バージョンから始めて、Azure Blobをアーカイブメディアとしてサポートします。

      OSSと同様に、Azure Blobも`delete_mode`パラメータと`checksum_type`パラメータをサポートしています。そのうち、`delete_mode`パラメータはアーカイブファイルのクリーンアップモードを設定するために使用され、`delete_mode`パラメータを明示的に設定しない場合、デフォルトで`delete`モードが使用されます。`checksum_type`パラメータは、アーカイブファイルの整合性を検証するための検証アルゴリズムを指定するために使用され、サポートされる値は`md5`および`no_checksum`です。`checksum_type`パラメータを明示的に設定しない場合、デフォルト値は`md5`です。

      さらに多くのパラメータの詳細については、[SET LOG_ARCHIVE_DEST](../../../700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/150.set-log-archive-dest.md)を参照してください。

      例：

      <main id="notice" type='notice'>
      <h4>注意</h4>
      <ul><li>オブジェクトストレージをアーカイブメディアとして使用する場合、オブジェクトストレージパスの各パラメータは<code>&</code>記号で区切られます。入力したパラメータ値には、大文字と小文字の英字、数字、<code>/-_$+=</code>、およびワイルドカードのみを含めるようにしてください。上記以外の文字を入力した場合、設定に失敗する可能性があります。</li>

      * Azure Blobをアーカイブメディアとして使用する場合、システムテナントが指定されたテナント`mysql_tenant`に対してアーカイブパスを設定し、クリーンアップモードを`delete`に設定するとともに、検証アルゴリズムを`md5`に指定します。

        ```shell
        obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=azblob://oceanbase-test-bucket/backup/archive?host=http://****.blob.core.windows.net&access_id=****&access_key=****&delete_mode=delete&checksum_type=md5' TENANT = mysql_tenant;
        ```

      * Azure Blobをアーカイブメディアとして使用する場合、ユーザーが自身のテナントに対してアーカイブパスを設定し、クリーンアップモードを`delete`に設定するとともに、検証アルゴリズムを`md5`に指定します。

        ```shell
        obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=azblob://oceanbase-test-bucket/backup/archive?host=http://****.blob.core.windows.net&access_id=****&access_key=****&delete_mode=delete&checksum_type=md5';
        ```

      例において、`azblob://`はAzure Blobをアーカイブメディアタイプとして使用することを表し、バケット名は`oceanbase-test-bucket`、バケット内のパスは`/backup/archive`です。また、パスとパラメータを`?`で区切り、パラメータ間は`&`で区切ります。`host`はバケットのホストアドレスであり、コンテナプロパティやストレージアカウントの接続文字列を結合することで取得できます。`access_id`はストレージアカウント名、`access_key`はAzure Blobのアクセスキーです。クリーンアップモードは`delete`で、アーカイブファイルの整合性はMD5アルゴリズムを使用して検証されます。

   * `BINDING`プロパティを設定します(オプション)

        `BINDING`プロパティは、アーカイブと業務の優先モードを設定するために使用されます。現在、`Optional`モードと`Mandatory`モードがサポートされています。設定しない場合は、デフォルトで`Optional`モードになります。

        * `Optional`モードは、ユーザー業務を優先する場合を表します。このモードでは、アーカイブ(ログアーカイブ)の速度がログ生成速度に追いつかない場合、ログがアーカイブされる前に回収され、断流が発生する可能性があります。

        * `Mandatory`モードは、アーカイブを優先する場合を表します。このモードでは、アーカイブがユーザーのデータ書き込みに追いつかない場合、ユーザーによる書き込みができない可能性があります。

        アーカイブメディアとしてNFSを使用する場合、システムテナントが指定されたテナント`mysql_tenant`に対してアーカイブパスを設定し、`BINDING`プロパティを設定する例は次のとおりです：

        ```shell
        obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=file:///data/nfs/backup/archive BINDING=Optional' TENANT = mysql_tenant;
        ```

        アーカイブメディアとしてNFSを使用する場合、ユーザーテナントが自身のテナントに対してアーカイブパスを設定し、`BINDING`プロパティを設定する例は次のとおりです：

        ```shell
        obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=file:///data/nfs/backup/archive BINDING=Optional';
        ```

   * `PIECE_SWITCH_INTERVAL`プロパティを設定します(オプション)

        `PIECE_SWITCH_INTERVAL`プロパティは、`piece`の切り替えサイクルを設定するために使用され、値の範囲は`[1d, 7d]`です。設定しない場合、デフォルトは`1d`となります。

        アーカイブメディアとしてNFSを使用する場合、システムテナントが指定されたテナント`mysql_tenant`に対してアーカイブパスを設定し、2日ごとにログ`piece`を切り替えるように設定する例は次のとおりです：

        ```shell
        obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=file:///data/nfs/backup/archive BINDING=Optional PIECE_SWITCH_INTERVAL=1d' TENANT = mysql_tenant;
        ```

        アーカイブメディアとしてNFSを使用する場合、ユーザーテナントが自身のテナントに対してアーカイブパスを設定し、2日ごとにログ`piece`を切り替えるように設定する例は次のとおりです：

        ```shell
        obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST='LOCATION=file:///data/nfs/backup/archive BINDING=Optional PIECE_SWITCH_INTERVAL=1d';
        ```

3. 設定が完了したら、ビューを使用して詳細なパラメータ設定情報を確認できます。

   `sys`テナントは`CDB_OB_ARCHIVE_DEST`ビューを使用して確認でき、ユーザーテナントは`DBA_OB_ARCHIVE_DEST`ビューを使用して確認できます。

   アーカイブパラメータの詳細な確認手順については、[アーカイブパラメータの確認](800.view-parameters-of-log-archive.md)を参照してください。

### 設定後の注意事項と説明

パラメータ `LOG_ARCHIVE_DEST` の設定が成功すると、デフォルトでシステムは設定された宛先ディレクトリに `format` ファイルを作成し、バックアップ宛先の有効性を検証するための情報を格納します。これにより、宛先内のデータの整合性が確保されます。そのため、ログアーカイブの宛先を設定する際には、以下の点に注意する必要があります：

* `format` ファイルが存在しない場合、設定された宛先ディレクトリが空であることを要件とします。そうでない場合、システムは `-9080` エラーを報告し、「format ファイルが見つからない」というメッセージが表示されます。

* `format` ファイルが既に存在する場合、その内容の検証が成功していることを要件とします。そうでない場合、システムは `-9081` エラーを報告し、「format ファイルが不一致です」というメッセージが表示されます。format ファイルの内容の検証では、クラスタ、テナント、およびバックアップ宛先のタイプが現在の操作対象のクラスタ、テナント、およびバックアップ宛先のタイプと一致しているかどうかを確認します。

* バックアップタスクを実行する際、`format` ファイルが存在しないか、または `format` ファイルの検証に失敗した場合、タスクは失敗します。

さらに、アーカイブ宛先の設定が成功した後は、増分的な設定はサポートされません。例えば、NFSのアーカイブパス `/data/nfs/backup/archive` に `BINDING` プロパティを `Mandatory`、`PIECE_SWITCH_INTERVAL` プロパティを `1d` として設定しているとします。`PIECE_SWITCH_INTERVAL` を `2d` に更新したいが、`BINDING` プロパティの設定 `Mandatory` を維持したい場合でも、コマンド内で他のプロパティの値を指定する必要があります。そうでない場合、未指定のプロパティはデフォルト値を使用します。

変更を行うには、以下のステートメントを再度実行する必要があります。

* システムテナントによる指定テナントの変更

  ```shell
  obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST = 'LOCATION=file:///data/nfs/backup/archive BINDING=Mandatory PIECE_SWITCH_INTERVAL=2d' TENANT = mysql_tenant;
  ```

* ユーザーテナントによる自身のテナントの変更

  ```shell
  obclient> ALTER SYSTEM SET LOG_ARCHIVE_DEST = 'LOCATION=file:///data/nfs/backup/archive BINDING=Mandatory PIECE_SWITCH_INTERVAL=2d';
  ```

## （オプション）アーカイブ遅延を設定する

OceanBaseデータベースは、テナントレベルの構成パラメータ `archive_lag_target` を使用して、テナントログアーカイブの遅延時間を制御します。この構成パラメータは、ミリ秒（ms）、秒（s）、分（m）、時間（h）単位で設定でき、デフォルト値は2分です。これは、前回のアーカイブI/Oと次のアーカイブI/Oとの最大間隔時間を指定するために使用され、オンラインログが適時にアーカイブされるようにし、データ損失のリスクを低減します。

OceanBaseデータベースでは、ログストリーム単位でアーカイブが行われます。現在のログストリームにログ書き込みがあり、かつそのログストリームの最後のアーカイブから経過した時間が構成パラメータ `archive_lag_target` で指定された時間間隔を超えた場合、そのログストリームはアーカイブ動作をトリガーし、未アーカイブのログをすべてアーカイブします。

例えば、構成パラメータが `archive_lag_target='120s'`（つまり2分）に設定されている場合、各ログストリームは2分ごとにアーカイブ動作を試行します（他の条件が満たされている場合、例えばログアーカイブのキャッシュアグリゲーションバッファが満杯になる場合を除く）。これにより、該当するログストリームの今回のアーカイブ動作と前回のアーカイブ動作との間隔が2分以下となるようにします。注意すべき点として、構成パラメータ `archive_lag_target` の値を0に設定すると、リアルタイムアーカイブの効果が得られます。

構成パラメータ `archive_lag_target` の詳細については、[archive_lag_target](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/200.archive_lag_target.md)を参照してください。

### 前提条件

構成パラメータ `archive_lag_target` の値を変更する際には、アーカイブ先の設定が完了していることを確認してください。アーカイブパスが設定されていない場合、構成パラメータ `archive_lag_target` の値を変更すると、システムから `log_archive_dest has not been set, set archive_lag_target is not allowed` のメッセージが表示されます。

### 注意事項

* アーカイブメディアがOSS/NFSの場合、構成パラメータ `archive_lag_target` の値は許容範囲内の任意の値に設定できます。一方、アーカイブメディアがS3およびS3プロトコルに対応したその他のオブジェクトストレージの場合、構成パラメータ `archive_lag_target` の値は `60s` より小さくすることはできません。`60s` より小さい場合、システムはエラーを返します。

* 構成パラメータ `archive_lag_target` を適切な値に設定することをお勧めします。これにより、過度なIO操作によるシステム性能への影響を回避できます。特に、オブジェクトストレージを使用する場合に注意が必要です。また、値が大きすぎてもデータ復旧のタイムリーさを満たせない可能性があるため、具体的なビジネスニーズやアーカイブメディアの性能に基づいてRPOを調整する必要があります。

### 設定方法

1. `sys` テナントまたはユーザーテナントのテナント管理者がデータベースにログインします。

2. 実際の状況に応じて、適切なステートメントを選択し、アーカイブ遅延を設定します。

   設定方法は以下のとおりです：

   * `sys` テナントが指定されたテナントに対してアーカイブ遅延時間を設定します

     ```shell
     obclient> ALTER SYSTEM SET archive_lag_target = '120s' TENANT = mysql_tenant;
     ```

   * `sys` テナントがすべてのユーザーテナントに対してアーカイブ遅延時間を設定します

     ```shell
     obclient> ALTER SYSTEM SET archive_lag_target = '120s' TENANT = all_user;
     ```

   * ユーザーテナントが自身のテナントに対してアーカイブ遅延時間を設定します

     ```shell
     obclient> ALTER SYSTEM SET archive_lag_target = '120s';
     ```
