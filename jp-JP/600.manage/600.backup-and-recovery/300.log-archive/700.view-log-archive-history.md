# アーカイブ履歴の確認

ビューを使用して、現在進行中のアーカイブ情報を含むアーカイブの履歴情報を確認できます。

## システムテナントからクラスタ内のすべてのテナントのアーカイブ履歴を確認する

`sys` テナントは、`oceanbase.CDB_OB_ARCHIVELOG_SUMMARY` ビューを使用して、クラスタ内のすべてのテナントのアーカイブ履歴情報を確認できます。

1. `root` ユーザーでクラスタの `sys` テナントにログインします。

2. 以下のステートメントを実行して、クラスタ内のすべてのテナントのアーカイブ履歴情報を確認します。

上記の例では、現在のクラスタにはテナントIDが `1002` と `1004` の2つのテナントのアーカイブ情報があります。そのうち、`1002` テナントは2回目のアーカイブ開始で、2ラウンド分のアーカイブ情報があります。`1004` テナントは初めてアーカイブを開始したため、現在のアーカイブ情報のみがあります。

`1002` テナントの最初のラウンドのアーカイブでは、`piece id` がそれぞれ `1` ～ `3` の3つのピースが生成されました。アーカイブログの範囲は `'2022-06-01 06:00:00.000000'` ～ `'2022-06-03 12:00:00.000000'` です。また、`10GB` の実際のアーカイブデータがクリーンアップされており、この部分のクリーンアップされたデータの圧縮前のデータ量は `25GB` です。

`1004` テナントの `round_id` は `1` であり、初めてアーカイブが開始されたことを示しています。アーカイブメディアのタイプは `OSS` で、バケットは `oceanbase-test-bucket`、パスは `/backup/archive` です。アーカイブ開始以来、`piece id` がそれぞれ `1` と `2` の2つのピースが生成されており、アーカイブされたログの範囲は `'2022-06-20 01:00:00.000000'` ～ `'2022-06-21 08:00:00.000000'` です。

`CDB_OB_ARCHIVELOG_SUMMARY` ビューの詳細については、[CDB_OB_ARCHIVELOG_SUMMARY](../../../700.reference/700.system-views/300.system-view-of-sys-tenant/200.dictionary-view-of-sys-tenant/5700.o-cdb_ob_archivelog_summary-of-sys-tenant.md) を参照してください。

## ユーザーテナントが現在のテナントのアーカイブ履歴を確認する

ユーザーテナントは、`oceanbase.DBA_OB_ARCHIVELOG_SUMMARY`ビュー（MySQLモード）および`sys.DBA_OB_ARCHIVELOG_SUMMARY`ビュー（Oracleモード）を使用して、自身のテナントのアーカイブ履歴を確認できます。

1. ユーザーテナントのテナント管理者がデータベースにログインします。

   <main id="notice" type='explain'>
        <h4>説明</h4>
        <p>MySQLテナントの管理者ユーザーは<code>root</code>ユーザー、Oracleテナントの管理者ユーザーは<code>SYS</code>ユーザーです。</p>
   </main>

2. 以下のステートメントを実行して、現在のテナントのログアーカイブ履歴を確認します。
