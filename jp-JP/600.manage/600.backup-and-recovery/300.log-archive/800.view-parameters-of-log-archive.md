# アーカイブパラメータの確認

ログアーカイブプロセス中に、アーカイブ関連のパラメータ設定情報を確認できます。

## システムテナントでテナントのアーカイブパラメータを確認する

1. `root` ユーザーでクラスタの `sys` テナントにログインします。

2. 以下のステートメントを実行して、テナントのアーカイブ関連パラメータを確認します。

   * すべてのテナントのログアーカイブのアーカイブパラメータ情報（ソース側の構成情報は除く）を確認します。

      ビュー `CDB_OB_ARCHIVE_DEST` には、すべてのテナントのログアーカイブに設定されたアーカイブパラメータ情報が記録されています。

      ```sql
      obclient [(none)]> SELECT * FROM oceanbase.CDB_OB_ARCHIVE_DEST;
      ```

      クエリ結果は次のとおりです：

      ```shell
      +-----------+---------+-----------------------+---------------------------------------------------------------------------------------------------------------------------------------------------------+
      | TENANT_ID | DEST_NO | NAME                  | VALUE                                                                                                                                                   |
      +-----------+---------+-----------------------+---------------------------------------------------------------------------------------------------------------------------------------------------------+
      |      1002 |       0 | binding               | OPTIONAL                                                                                                                                                |
      |      1002 |       0 | dest_id               | 1002                                                                                                                                                    |
      |      1002 |       0 | path                  | file:///data/nfs/backuparchive                                                                                                                          |
      |      1002 |       0 | piece_switch_interval | 1d                                                                                                                                                      |
      |      1002 |       0 | state                 | ENBALE                                                                                                                                                  |
      |      1004 |       0 | binding               | Mandatory                                                                                                                                               |
      |      1004 |       0 | dest_id               | 1001                                                                                                                                                    |
      |      1004 |       0 | path                  | oss://oceanbase-test-bucket/backup/archive?host=xxx.aliyun-inc.com&access_id=xxx&access_key=xxx&delete_mode=tagging&checksum_type=md5&enable_worm=true  |
      |      1004 |       0 | piece_switch_interval | 1d                                                                                                                                                      |
      |      1004 |       0 | state                 | ENBALE                                                                                                                                                  |
      +-----------+---------+-----------------------+---------------------------------------------------------------------------------------------------------------------------------------------------------+
      10 rows in set
      ```

      クエリ例では、現在のクラスタにはテナントIDが `1002` と `1004` の2つのテナントがあり、アーカイブパラメータが設定されています。

      テナントIDが `1002` のテナントの場合、ログアーカイブ時のアーカイブパスは `file:///data/nfs/backuparchive` です。`binding` の値は `OPTIONAL` であり、アーカイブと業務の優先モードは `Optional` モード、つまりユーザー業務優先を意味します。`piece_switch_interval` が `1d` であることは、ログアーカイブ実行時に1日ごとに1つのログピースを分割することを意味します。`state` が `ENABLE` であることは、このアーカイブ宛先が有効な状態であることを意味します。

      テナントIDが `1004` のテナントの場合、ログアーカイブ時のアーカイブパスおよびパス関連パラメータは `oss://oceanbase-test-bucket/backup/archive?host=xxx.aliyun-inc.com&access_id=xxx&access_key=xxx&delete_mode=tagging&checksum_type=md5&enable_worm=true` です。`binding` の値は `Mandatory` であり、アーカイブと業務の優先モードは `Mandatory` モード、つまりアーカイブ優先を意味します。`piece_switch_interval` が1日であることは、ログアーカイブ実行時に1日ごとに1つのログピースを分割することを意味します。`state` が `ENABLE` であることは、このアーカイブ宛先が有効な状態であることを意味します。

      `CDB_OB_ARCHIVE_DEST` ビューの詳細については、[CDB_OB_ARCHIVE_DEST](../../../700.reference/700.system-views/300.system-view-of-sys-tenant/200.dictionary-view-of-sys-tenant/5400.o-cdb_ob_archive_dest-of-sys-tenant.md)を参照してください。

   * すべてのテナントのログアーカイブのアーカイブパス関連情報（ソース側の構成情報を含む）を確認します。

      ビュー `CDB_OB_BACKUP_STORAGE_INFO` には、すべてのテナントのバックアップまたはアーカイブパスの構成情報が記録されています。

      ```shell
      obclient [(none)]> SELECT TENANT_ID, PATH, DEST_TYPE, EXTENSION FROM oceanbase.CDB_OB_BACKUP_STORAGE_INFO WHERE DEST_TYPE='archive_log';
      ```

      クエリ結果の例は次のとおりです：

      ```shell
      +-----------+---------------------------------------------+-------------+-----------------------------------------------+
      | TENANT_ID | PATH                                        | DEST_TYPE   | EXTENSION                                     |
      +-----------+---------------------------------------------+-------------+-----------------------------------------------+
      |      1004 | oss://oceanbase-test-bucket/backup/archive  | archive_log | checksum_type=md5&enable_worm=true&zone=zone1 |
      +-----------+---------------------------------------------+-------------+-----------------------------------------------+
      1 row in set
      ```

      クエリ結果において、テナントIDが `1004` のテナントの場合、そのアーカイブパスは `oss://oceanbase-test-bucket/backup/archive` です。`enable_worm=true` は、OceanBaseデータベースがWORMの仕様に従ってこのパスへの書き込みおよび削除操作を実行することを意味します。`checksum_type=md5` は、MD5アルゴリズムを使用してアーカイブファイルの整合性を検証することを意味します。ソース側の構成が `zone=zone1` であることは、zone1のノードのみがこのパスにアクセスできることを意味します。

   * テナントのログアーカイブの並列度を確認します。

      テナントのログアーカイブの並列度は、テナントレベルの構成パラメータ `log_archive_concurrency` によって制御されます。この構成パラメータの値の範囲は [0, 100] で、デフォルト値は `0` であり、OceanBaseデータベースの適応型ログアーカイブの並列度を使用することを意味します。構成パラメータ `log_archive_concurrency` の詳細については、[log_archive_concurrency](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/4500.log_archive_concurrency.md)を参照してください。

      ```sql
      obclient [(none)]> SHOW PARAMETERS LIKE 'log_archive_concurrency';
      ```

      クエリ結果の例は次のとおりです：

      ```shell
      +-------+----------+----------------+----------+-------------------------+-----------+-------+------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+------------+--------+---------+-------------------+---------------+-----------+
      | zone  | svr_type | svr_ip         | svr_port | name                    | data_type | value | info                                                                                                                                                                                                                                                                                                                               | section    | scope  | source  | edit_level        | default_value | isdefault |
      +-------+----------+----------------+----------+-------------------------+-----------+-------+------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+------------+--------+---------+-------------------+---------------+-----------+
      | zone1 | observer | 172.xx.xxx.xxx |     2882 | log_archive_concurrency | NULL      | 0     | log archive concurrency, for both archive fetcher and sender. If the value is default 0, the database will automatically calculate the number of archive worker threads based on the tenant specification, which is tenant max_cpu divided by 4; otherwise set the the worker count equals to the value.Range: [0, 100] in integer | LOGSERVICE | TENANT | DEFAULT | DYNAMIC_EFFECTIVE | 0             |         1 |
      +-------+----------+----------------+----------+-------------------------+-----------+-------+------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+------------+--------+---------+-------------------+---------------+-----------+
      1 row in set
      ```

## ユーザーテナントが自身のテナントのアーカイブパラメータを確認する

1. テナント管理者がデータベースにログインします。

   <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>MySQLテナントの管理者ユーザーは <code>root</code> ユーザー、Oracleテナントの管理者ユーザーは <code>SYS</code> ユーザーです。</p>
   </main>

2. 以下のステートメントを実行して、現在のテナントのアーカイブ関連パラメータを確認します。

   * テナントのログアーカイブのアーカイブパラメータ情報（ソース側の構成情報を除く）を確認します。

      ユーザーテナントは、ビュー `oceanbase.DBA_OB_ARCHIVE_DEST` (MySQLモード) およびビュー `SYS.DBA_OB_ARCHIVE_DEST` (Oracleモード) を使用して、自身のテナントのアーカイブパラメータ情報を確認できます。

      :::tab
      tab MySQLモード

      ```shell
      obclient [oceanbase]> SELECT * FROM oceanbase.DBA_OB_ARCHIVE_DEST;
      ```

      tab Oracleモード

      ```shell
      obclient [SYS]> SELECT * FROM SYS.DBA_OB_ARCHIVE_DEST;
      ```

      :::

      クエリ結果は次のとおりです：

      ```shell
      +---------+-----------------------+---------------------------------+
      | DEST_NO | NAME                  | VALUE                           |
      +---------+-----------------------+---------------------------------+
      |       0 | binding               | OPTIONAL                        |
      |       0 | dest_id               | 1002                            |
      |       0 | path                  | file:///data/nfs/backup/archive |
      |       0 | piece_switch_interval | 1d                              |
      |       0 | state                 | ENBALE                          |
      +---------+-----------------------+---------------------------------+
      6 rows in set
      ```

   * テナントのログアーカイブのアーカイブパスに関する情報（ソース側の構成情報を含む）を確認します。

      ユーザーテナントは、ビュー `oceanbase.DBA_OB_BACKUP_STORAGE_INFO` (MySQLモード) およびビュー `SYS.DBA_OB_BACKUP_STORAGE_INFO` (Oracleモード) を使用して、自身のテナントのログアーカイブのアーカイブパスのソース側の構成情報を確認できます。

      :::tab
      tab MySQLモード

      ```shell
      obclient [oceanbase]> SELECT PATH, DEST_TYPE, EXTENSION FROM oceanbase.DBA_OB_BACKUP_STORAGE_INFO WHERE DEST_TYPE='archive_log';
      ```

      tab Oracleモード

      ```shell
      obclient [SYS]> SELECT PATH, DEST_TYPE, EXTENSION FROM SYS.DBA_OB_BACKUP_STORAGE_INFO WHERE DEST_TYPE='archive_log';
      ```

      :::

      クエリ結果の例は次のとおりです：

      ```shell
      +--------------------------------------------+-------------+------------------------------+
      | PATH                                       | DEST_TYPE   | EXTENSION                    |
      +--------------------------------------------+-------------+------------------------------+
      | oss://oceanbase-test-bucket/backup/archive | archive_log | checksum_type=md5&zone=zone1 |
      +--------------------------------------------+-------------+------------------------------+
      1 row in set
      ```

   * テナントのログアーカイブの並列度を確認します。

      テナントのログアーカイブの並列度は、テナントレベルの構成パラメータ `log_archive_concurrency` によって制御されます。この構成パラメータの値の範囲は [0, 100] で、デフォルト値は `0` です。これは、OceanBaseデータベースの適応型ログアーカイブの並列度を使用することを意味します。構成パラメータ `log_archive_concurrency` の詳細については、[log_archive_concurrency](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/4500.log_archive_concurrency.md)を参照してください。

      ```shell
      obclient [(none)]> SHOW PARAMETERS LIKE 'log_archive_concurrency';
      ```

      クエリ結果の例は次のとおりです：

      ```shell
      +-------+----------+----------------+----------+-------------------------+-----------+-------+------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+------------+--------+---------+-------------------+---------------+-----------+
      | zone  | svr_type | svr_ip         | svr_port | name                    | data_type | value | info                                                                                                                                                                                                                                                                                                                               | section    | scope  | source  | edit_level        | default_value | isdefault |
      +-------+----------+----------------+----------+-------------------------+-----------+-------+------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+------------+--------+---------+-------------------+---------------+-----------+
      | zone1 | observer | 172.xx.xxx.xxx |     2882 | log_archive_concurrency | NULL      | 0     | log archive concurrency, for both archive fetcher and sender. If the value is default 0, the database will automatically calculate the number of archive worker threads based on the tenant specification, which is tenant max_cpu divided by 4; otherwise set the the worker count equals to the value.Range: [0, 100] in integer | LOGSERVICE | TENANT | DEFAULT | DYNAMIC_EFFECTIVE | 0             |         1 |
      ```
