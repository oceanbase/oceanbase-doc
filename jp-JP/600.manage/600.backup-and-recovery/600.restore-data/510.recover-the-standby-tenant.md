# スタンバイテナントのログセグメント再生

復元が成功すると、復元されたテナントはすべてスタンバイテナントとなります。`RECOVER` コマンドを実行することで、テナントの復元時に指定したログアーカイブソースからログの再生を続けることができます。

## 背景

物理復元のプロセスは物理スタンバイデータベースと統一されており、物理復元後のテナントはスタンバイテナントとなります。その後、このテナントはスタンバイテナントとして関連サービスを提供することも、プライマリテナントとしてサービスを提供することもできます。

## 前提条件

復元操作が成功したことを確認してください。復元結果の確認に関する操作については、[復元結果の確認](../600.restore-data/500.view-the-restore-history.md)を参照してください。

## システムテナントがスタンバイテナントのログ再生を指定する場合

1. `root` ユーザーでクラスタの `sys` テナントにログインします。

2. 以下のステートメントを実行して、ログ再生操作を実行します。

   ステートメントは以下のとおりです：

   * 指定されたタイムスタンプまでのログを再生し、そのタイムスタンプポイントを含みます。

     ```shell
     obclient(root@sys)[oceanbase]> ALTER SYSTEM RECOVER STANDBY TENANT tenant_name UNTIL TIME='timestamp';
     ```

   * 指定された SCN までのログを再生し、その SCN ポイントを含みます。

     ```shell
     obclient(root@sys)[oceanbase]> ALTER SYSTEM RECOVER STANDBY TENANT tenant_name UNTIL SCN=scn;
     ```

   * 終点なし、アーカイブソースのログを継続的に再生します。

     ```shell
     obclient(root@sys)[oceanbase]> ALTER SYSTEM RECOVER STANDBY TENANT tenant_name UNTIL UNLIMITED;
     ```

     <main id="notice" type='explain'>
     <h4>説明</h4>
     <p>このコマンドは一度に1つのスタンバイテナントのみを指定できます。複数のテナントを指定する必要がある場合は、このコマンドを繰り返し実行する必要があります。</p>
     </main>

   ステートメントの実行が成功した後、スタンバイテナントのログ再生をキャンセルする場合は、以下のステートメントを実行します。

   ```shell
   obclient(root@sys)[oceanbase]> ALTER SYSTEM RECOVER STANDBY TENANT tenant_name CANCEL;
   ```

3. スタンバイテナントのログ再生進捗状況を確認します。

   ```shell
   obclient(root@sys)[oceanbase]> SELECT TENANT_ID, LS_ID, STATUS, READABLE_SCN FROM oceanbase.CDB_OB_LS WHERE TENANT_ID=xxx;
   ```

   ログ再生が停止したタイムスタンプを確認する場合は、`SCN_TO_TIMESTAMP` 関数を使用して変換できます。ステートメントは以下のとおりです。

   ```shell
   obclient(root@sys)[oceanbase]> SELECT TENANT_ID, LS_ID, STATUS, SCN_TO_TIMESTAMP(READABLE_SCN) FROM oceanbase.CDB_OB_LS WHERE TENANT_ID=xxx;
   ```

## スタンバイテナントによる自己ログの再生

スタンバイテナントも自己のログ再生を開始できます。

1. ユーザーテナントのテナント管理者がデータベースにログインします。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>MySQLモードの管理者ユーザーは <code>root</code> ユーザー、Oracleモードの管理者ユーザーは <code>SYS</code> ユーザーです。</p>
   </main>

2. 以下のステートメントを実行して、ログ再生操作を実行します。

   ステートメントは以下のとおりです：

   * 指定されたタイムスタンプまでログを再生し、そのタイムスタンプのポイントを含みます。

     ```shell
     obclient> ALTER SYSTEM RECOVER STANDBY UNTIL TIME='timestamp';
     ```

   * 指定されたSCNまでログを再生し、そのSCNのポイントを含みます。

     ```shell
     obclient> ALTER SYSTEM RECOVER STANDBY UNTIL SCN=scn;
     ```

   * 終点なし、アーカイブされたソース側のログを継続的に再生します。

     ```shell
     obclient> ALTER SYSTEM RECOVER STANDBY UNTIL UNLIMITED;
     ```

     <main id="notice" type='explain'>
     <h4>説明</h4>
     <p>このコマンドは一度に1つのスタンバイテナントのみを指定できます。複数のテナントを指定する必要がある場合は、このコマンドを繰り返し実行する必要があります。</p>
     </main>

   ステートメントの実行が成功した後、スタンバイテナントのログ再生をキャンセルする場合は、以下のステートメントを実行できます。

   ```shell
   obclient> ALTER SYSTEM RECOVER STANDBY CANCEL;
   ```

3. スタンバイテナントのログ再生進捗状況を確認します。

   ```shell
   obclient> SELECT LS_ID, STATUS, READABLE_SCN FROM oceanbase.DBA_OB_LS;
   ```

   ログ再生が停止したタイムスタンプを確認する必要がある場合は、`SCN_TO_TIMESTAMP` 関数を使用して変換できます。ステートメントは以下のとおりです。

   ```shell
   obclient> SELECT LS_ID, STATUS, SCN_TO_TIMESTAMP(READABLE_SCN) FROM oceanbase.DBA_OB_LS;
   ```
