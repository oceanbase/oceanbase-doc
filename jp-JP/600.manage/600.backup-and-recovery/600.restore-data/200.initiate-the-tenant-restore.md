# 物理復旧の実行

この記事では、コマンドを使用してテナントレベルで物理復旧を行う方法について説明します。現在、OceanBaseデータベースはテナントレベルでのポイントインタイムに基づくフル復旧をサポートしています。

OceanBaseデータベースの復旧は、同一クラスタ内での復旧と、異なるクラスタ間での復旧の両方をサポートしています。

復旧処理では、ユーザーが入力したコマンドに基づき、バックアップ先から必要なマクロブロックデータを対応するフルバックアップおよび増分バックアップからターゲットテナントに復元し、トランザクションログの同期取得と再生も同時に行われます。

## 前提条件

物理復旧を実行する前に、復旧前の準備が完了していることを確認してください。具体的な操作については、[復旧前の準備](../600.restore-data/100.preparation-before-recovery.md)を参照してください。

## 注意事項

現在のバージョンでは、データのバックアップと同時にテナントレベルの構成パラメータもバックアップされますが、バックアップされたテナントレベルの構成パラメータはユーザーへの設定参考としてのみ使用され、物理復旧時には直接テナントに復元されません。構成パラメータのバックアップに関する詳細は、[構成パラメータのバックアップ](../400.data-backup/320.backup-parameters.md)を参照してください。

## 手順

1. `root` ユーザーでクラスタの `sys` テナントにログインします。

2. (オプション) 以下のステートメントを実行して、バックアップの復元パスワードを設定します。

   バックアップの復元パスワードは、データバックアップ時にパスワードが追加された場合にのみ設定する必要があります。

   ```sql
   SET DECRYPTION IDENTIFIED BY 'password';
   ```

   ここで、`password` はバックアップ時に追加したパスワードに置き換える必要があります。フルバックアップと増分バックアップで設定したパスワードが異なる場合は、複数のパスワードを入力し、パスワード間は英字のカンマ（,）で区切ります（フルバックアップのパスワードを先に、増分バックアップのパスワードを後に配置します）。

   フルバックアップと増分バックアップで設定したパスワードが同じ場合の例：

   ```sql
   SET DECRYPTION IDENTIFIED BY '******';
   ```

   フルバックアップと増分バックアップで設定したパスワードが異なる場合の例：

   ```sql
   SET DECRYPTION IDENTIFIED BY '******','******';
   ```

3. 以下のステートメントを実行して、暗号化情報を設定します。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>暗号化されていない場合、または復元時に元のキー管理サービスにアクセスできる場合は、この手順をスキップしてください。</p>
   </main>

   ```shell
   obclient [(none)]> SET @kms_encrypt_info = '<encrypted_string>';
   ```

   ここで、`<encrypted_string>` は `EXTERNAL_KMS_INFO` の値であり、`EXTERNAL_KMS_INFO` はテナントレベルの構成パラメータです。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p><code>external_kms_info</code> は、一部のキー管理情報を格納するために使用されます。この構成パラメータの詳細については、<a href="../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3300.external_kms_info.md">external_kms_info</a>を参照してください。</p>
   </main>

4. 以下のステートメントを実行して、復元タスクの実行を開始します。

   ステートメントは以下のとおりです：

   * 指定されたタイムスタンプまで復元

      ```sql
      ALTER SYSTEM RESTORE dest_tenant_name FROM uri UNTIL TIME='timestamp' WITH 'pool_list=pool_name[&locality=locality][&primary_zone=zone_name][&concurrency=int_num][&kms_encrypt={true | false}]' [WITH KEY FROM 'backup_key_path' ENCRYPTED BY 'password'] [DESCRIPTION description];
      ```

   * 指定されたSCNまで復元

      ```sql
      ALTER SYSTEM RESTORE dest_tenant_name FROM uri UNTIL SCN=scn WITH 'pool_list=pool_name[&locality=locality][&primary_zone=zone_name][&concurrency=int_num][&kms_encrypt={true | false}]' [WITH KEY FROM 'backup_key_path' ENCRYPTED BY 'password'] [DESCRIPTION description];
      ```

   * 最新のポイントまで復元

      ```sql
      ALTER SYSTEM RESTORE dest_tenant_name FROM uri WITH 'pool_list=pool_name[&locality=locality][&primary_zone=zone_name][&concurrency=int_num][&kms_encrypt={true | false}]' [WITH KEY FROM 'backup_key_path' ENCRYPTED BY 'password'] [DESCRIPTION description];
      ```

   ステートメント内の一部のパラメータの説明は以下のとおりです：

   * `dest_tenant_name`：復元対象の新しいテナントの名前。

   * `uri`：データバックアップパスとログアーカイブパスをそれぞれ指定する必要があります。

   * `UNTIL [TIME|SCN]`：復元の終了点を指定します。このポイントを含むまで復元します。`TIME` または `SCN` に復元する場合は、指定された値を `=` で結合する必要があります。`TIME` または `SCN` の選択方法の詳細については、[物理復元関連パラメータの紹介](../600.restore-data/800.parameters-of-the-restore.md)を参照してください。

   * `pool_list`：復元対象の新しいテナントに作成されたリソースプールを入力します。複数のリソースプール間は、英字のカンマ（,）で区切ります。

   * `locality`、`primary_zone`：新しいテナントのレプリカ分散のローカリティ情報およびリーダーレプリカの優先位置を指定します。オプションです。これらのパラメータの詳細については、[ALTER SYSTEM - RESTORE](../../../700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/3300.restore.md)を参照してください。

   * `concurrency`：データ復元の並列度を指定します。オプションです。デフォルトは、そのテナントに割り当てられたユニットの `MAX_CPU` 値です。

   * `kms_encrypt`：オプション。`true` の場合、復元時に復元前に指定された `kms_encrypt_info` を使用する必要があることを示します。

   * `WITH KEY FROM 'backup_key_path' ENCRYPTED BY 'password'`：暗号化テナントの秘密鍵バックアップ情報を指定します。ソーステナントに透過的暗号化が設定されている場合にのみ、復元時に秘密鍵バックアップ関連情報を指定する必要があります。

      * `backup_key_path`：秘密鍵のバックアップパス。

      * `password`：秘密鍵をバックアップする際に設定した暗号化パスワード。

      秘密鍵バックアップに関する操作については、[バックアップ前の準備](../400.data-backup/100.preparation-before-data-backup.md)の**秘密鍵のバックアップ**を参照してください。

   物理復元における各パラメータの詳細については、[ALTER SYSTEM - RESTORE](../../../700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/3300.restore.md)を参照してください。

   復元の例：

   :::tab
   tab アリババOSS

   * OSSのバックアップパスとログアーカイブパスから、テナント`mysql`を指定されたタイムスタンプ`2020-06-01 00:00:00`まで復元し、指定されたリソースプールを`restore_pool`とします。同時に、ソーステナントの秘密鍵情報も復元します。

      ```sql
      obclient> ALTER SYSTEM RESTORE mysql FROM 'oss://oceanbase-test-bucket/backup/data/?host=***.aliyun-inc.com&access_id=***&access_key=***,oss://oceanbase-test-bucket/backup/archive/?host=***.aliyun-inc.com&access_id=***&access_key=***' UNTIL TIME='2020-06-01 00:00:00' WITH 'pool_list=restore_pool' WITH KEY FROM 'oss://oceanbase-test-bucket/data_backup_dest/key?host=***.aliyun-inc.com&access_id=***&access_key=***' ENCRYPTED BY '******';
      ```

   * データバックアップパスとログアーカイブパスから、テナント`mysql`を指定されたSCN`1658285759724047000`まで復元し、指定されたリソースプールを`restore_pool`とします。

      ```sql
      obclient> ALTER SYSTEM RESTORE mysql FROM 'oss://oceanbase-test-bucket/backup/data/?host=***.aliyun-inc.com&access_id=***&access_key=***,oss://oceanbase-test-bucket/backup/archive/?host=***.aliyun-inc.com&access_id=***&access_key=***' UNTIL SCN=1658285759724047000 WITH 'pool_list=restore_pool';
      ```

   * データバックアップパスとログアーカイブパスから、テナント`mysql`を現在の最新アーカイブポイントまで復元し、指定されたリソースプールを`restore_pool`とします。同時に、復元の並列度`concurrency`を`50`と指定します。

      ```sql
      obclient> ALTER SYSTEM RESTORE mysql FROM 'oss://oceanbase-test-bucket/backup/data/?host=***.aliyun-inc.com&access_id=***&access_key=***,oss://oceanbase-test-bucket/backup/archive/?host=***.aliyun-inc.com&access_id=***&access_key=***' WITH 'pool_list=restore_pool&concurrency=50';
      ```

   * データバックアップパスとログアーカイブパスから、テナント`mysql`を指定されたタイムスタンプ`2020-06-01 00:00:00`まで復元し、指定されたリソースプールを`restore_pool`、コピーローカリティを`F@z1,F@z2,F@z3`とします。

      ```sql
      obclient> ALTER SYSTEM RESTORE mysql FROM 'oss://oceanbase-test-bucket/backup/data/?host=***.aliyun-inc.com&access_id=***&access_key=***,oss://oceanbase-test-bucket/backup/archive/?host=***.aliyun-inc.com&access_id=***&access_key=***' UNTIL TIME='2020-06-01 00:00:00' WITH 'pool_list=restore_pool&locality=F@z1,F@z2,F@z3';
      ```

   * データバックアップパスとログアーカイブパスから、テナント`mysql`を指定されたタイムスタンプ`2020-06-01 00:00:00`まで復元し、指定されたリソースプールを`restore_pool`、コピーローカリティを`F@z1,F@z2,F@z3`、そして`primary_zone`を`z1`と指定します。

      ```sql
      obclient> ALTER SYSTEM RESTORE mysql FROM 'oss://oceanbase-test-bucket/backup/data/?host=***.aliyun-inc.com&access_id=***&access_key=***,oss://oceanbase-test-bucket/backup/archive/?host=***.aliyun-inc.com&access_id=***&access_key=***' UNTIL TIME='2020-06-01 00:00:00' WITH 'pool_list=restore_pool&locality=F@z1,F@z2,F@z3&primary_zone=z1';
      ```

   tab NFS

   `url` パラメータが変更された点を除き、その他のパラメータの使用方法はOSSと一致します。

   * データバックアップパスおよびログアーカイブパスからテナント `mysql` を指定されたタイムスタンプ `2020-06-01 00:00:00` まで復元し、リソースプールを `restore_pool` に指定すると同時に、ソーステナントの秘密鍵情報も復元します。

      ```sql
      obclient> ALTER SYSTEM RESTORE mysql FROM 'file:///data/nfs/backup/data,file:///data/nfs/backup/archive' UNTIL TIME='2020-06-01 00:00:00' WITH 'pool_list=restore_pool' WITH KEY FROM 'file:///data_backup_dest/key' ENCRYPTED BY '******';
      ```

   * データバックアップパスおよびログアーカイブパスからテナント `mysql` を現在の最新のアーカイブポイントまで復元し、リソースプールを `restore_pool` に指定すると同時に、復元の並列度 `concurrency` を `50` に指定します。

      ```sql
      obclient> ALTER SYSTEM RESTORE mysql FROM 'file:///data/nfs/backup/data,file:///data/nfs/backup/archive' WITH 'pool_list=restore_pool&concurrency=50';
      ```

   tab AWS S3

   `url` パラメータが変更された点を除き、その他のパラメータの使用方法はOSSと同じです。

   S3バックアップパスおよびログアーカイブパスからテナント `mysql` を指定されたタイムスタンプ `2020-06-01 00:00:00` まで復元し、リソースプールを `restore_pool` と指定します。例：

   ```sql
   obclient> ALTER SYSTEM RESTORE mysql FROM 's3://oceanbase-test-bucket/backup/data/?host=s3.<region>.amazonaws.com&access_id=***&access_key=***&s3_region=***,s3://oceanbase-test-bucket/backup/archive/?host=s3.<region>.amazonaws.com&access_id=***&access_key=***&s3_region=***,' UNTIL TIME='2023-06-01 00:00:00' WITH 'pool_list=restore_pool';
   ```

   tabはS3プロトコルに対応したオブジェクトストレージです。

   `url`パラメータが変更された点を除き、その他のパラメータの使用方法はOSSと同じです。

   * OBSのバックアップパスとログアーカイブパスからテナント`mysql`を指定されたタイムスタンプ`2020-06-01 00:00:00`まで復元し、リソースプールを`restore_pool`と指定します。

      ```sql
      obclient> ALTER SYSTEM RESTORE mysql FROM 's3://oceanbase-test-bucket/backup/data/?host=obs.***.myhuaweicloud.com&access_id=***&access_key=***,s3://oceanbase-test-bucket/backup/archive/?host=obs.***.myhuaweicloud.com&access_id=***&access_key=***' UNTIL TIME='2023-06-01 00:00:00' WITH 'pool_list=restore_pool';
      ```

   * GCSのバックアップパスとログアーカイブパスからテナント`mysql`を指定されたタイムスタンプ`2020-06-01 00:00:00`まで復元し、リソースプールを`restore_pool`と指定します。

      ```sql
      obclient> ALTER SYSTEM RESTORE mysql FROM 's3://oceanbase-test-bucket/backup/data/?host=https://storage.googleapis.com&access_id=***&access_key=***,s3://oceanbase-test-bucket/backup/archive/?host=https://storage.googleapis.com&access_id=***&access_key=***' UNTIL TIME='2023-06-01 00:00:00' WITH 'pool_list=restore_pool';
      ```

   * COSのバックアップパスとログアーカイブパスからテナント`mysql`を指定されたタイムスタンプ`2020-06-01 00:00:00`まで復元し、リソースプールを`restore_pool`と指定します。

      ```sql
      obclient> ALTER SYSTEM RESTORE mysql FROM 's3://oceanbase-test/backup/data?host=cos.ap-xxxx.myqcloud.com&access_id=***&access_key=***,s3://oceanbase-test/backup/archive?host=cos.ap-xxxx.myqcloud.com&access_id=***&access_key=***' UNTIL TIME='2023-06-01 00:00:00' WITH 'pool_list=restore_pool';
      ```
   :::

5. (オプション) 復元対象のテナントに対応するMetaテナントの作成が成功した後、復元を高速化する必要がある場合は、構成パラメータ `ha_high_thread_score` を使用して復元タスクの並列スレッド数を設定できます。

   1. `oceanbase.DBA_OB_TENANTS` ビューを使用して、復元対象のテナントに対応するMetaテナントが正常に作成されたかどうかを確認します。

      ステートメントは以下のとおりです：

      ```sql
      SELECT * FROM oceanbase.DBA_OB_TENANTS;
      ```

      クエリ結果において、`TENANT_NAME` 列で `META$` で始まるテナントがMetaテナントであり、Metaテナントの状態が `TENANT_STATUS_NORMAL` の場合、Metaテナントの作成に成功したことを示します。

      ビュー `DBA_OB_TENANTS` の他のフィールドの説明については、[DBA_OB_TENANTS](../../../700.reference/700.system-views/400.system-view-of-mysql-mode/200.dictionary-view-of-mysql-mode/12000.o-dba_ob_tenants-of-mysql-mode.md)を参照してください。

   2. 構成パラメータ `ha_high_thread_score` を設定します。

      テナントレベルの構成パラメータ `ha_high_thread_score` は、高可用性・高優先順位スレッドの現在のワーカースレッド数を設定するために使用されます。デフォルト値は0で、値の範囲は [0, 100] です。10に変更することを推奨します。構成パラメータ `ha_high_thread_score` の詳細については、[ha_high_thread_score](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3500.ha_high_thread_score.md)を参照してください。

      ステートメントの例：

      ```sql
      ALTER SYSTEM SET ha_high_thread_score =10 TENANT = mysql;
      ```

## 次のステップ

* リカバリタスクを開始した後、ビューを使用してリカバリの進捗状況と結果を確認できます。具体的な操作については、[リカバリの進捗状況を確認する](../600.restore-data/400.view-the-restore-progress.md)を参照してください。

* リカバリタスクが完了した場合、低バージョンのバックアップデータから高バージョンのクラスタに復元するシナリオでは、復元されたテナントをアップグレードする必要があります。具体的な操作については、[リカバリ完了後のテナントのアップグレード](610.update-the-tenant-after-the-restore.md)を参照してください。

* 物理リカバリのプロセスは物理スタンバイデータベースと統一されており、物理リカバリ後のテナントはスタンバイテナントとなります。その後、このテナントはスタンバイテナントとして関連サービスを提供することも、プライマリテナントとしてサービスを提供することも可能です。スタンバイテナントとして、ソーステナントからログを再生する詳細な操作については、[スタンバイテナントによるセグメントログの再生](510.recover-the-standby-tenant.md)を参照してください。スタンバイテナントをプライマリテナントに変更する詳細な操作については、[スタンバイテナントをプライマリテナントに変更する](600.active-standby-tenant.md)を参照してください。
