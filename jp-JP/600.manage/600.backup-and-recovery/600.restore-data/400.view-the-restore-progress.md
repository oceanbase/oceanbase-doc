# 物理復元の進捗状況を確認する

データ復元中は、ビューを使用して物理復元の進捗状況を確認できます。

## 手順

1. `root`ユーザーで、復元対象テナントが存在するクラスタの`sys`テナントにログインします。

2. 以下のステートメントを実行して、復元の進捗状況を確認します。

   ```sql
   obclient [oceanbase]> SELECT * FROM oceanbase.CDB_OB_RESTORE_PROGRESS\G
   ```

   このビューには、復元時にユーザーが入力した関連パラメータや復元の進捗状況などの情報が記録されています。

   1回のテナント復元につき、2件のタスクレコードが対応します：`sys`テナントのタスクレコードと復元対象テナントのタスクレコードです。`sys`テナントのタスクレコードは主に復元対象テナントの復元関連情報を記録し、復元対象テナントのタスクレコードは主に自身の復元進捗情報を記録します。

   復元中は、復元進捗ビューの`STATUS`フィールドに注目します：

   * システムテナント：

      * `CREATE_TENANT` : テナントの作成。この段階ではシステムテナントが復元対象テナントを作成します。テナント作成完了後、状態は`WAIT_TENANT_RESTORE_FINISH`に変わります。作成失敗の場合は`RESTORE_FAIL`に変わります。

      * `WAIT_TENANT_RESTORE_FINISH` : 復元対象テナントの復元終了を待機します。テナント復元完了後、状態は`RESTORE_SUCCESS`に変わります。復元失敗の場合は`RESTORE_FAIL`に変わります。

      * `RESTORE_SUCCESS` : テナントの復元に成功しました。

      * `RESTORE_FAIL` : テナントの復元に失敗しました。

   * 復元対象テナント：

      * `RESTORING` : テナントデータの復元中です。復元完了後、状態は`POST_CHECK`に変わります。復元失敗の場合、状態は`RESTORE_FAIL`に変わります。

      * `POST_CHECK`: テナントロールのチェックを行い、スタンバイデータベースに戻します。操作完了後、状態は`UPGRADE`に変わります。操作失敗の場合、状態は`RESTORE_FAIL`に変わります。

      * `UPGRADE` : アップグレード段階です。バージョン間の復元の場合、テナントはアップグレードプロセスを実行します。操作完了後、状態は`RESTORE_SUCCESS`に変わります。操作失敗の場合、状態は`RESTORE_FAIL`に変わります。

      * `RESTORE_SUCCESS` : 復元に成功しました。

      * `RESTORE_FAIL` : リストアに失敗したことを示します。

   `CDB_OB_RESTORE_PROGRESS`ビューの詳細については、[リストアビュー](../600.restore-data/900.views-of-the-restore.md)を参照してください。

   リストアが完了したら、リストア結果を確認できます。具体的な操作については、[リストア結果の確認](../600.restore-data/500.view-the-restore-history.md)を参照してください。
