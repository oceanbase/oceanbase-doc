# 物理復旧の進捗状況を確認する

データ復旧中は、ビューを通じて物理復旧の進捗状況を確認できます。

## 手順

1. `root`ユーザーで、復元対象のテナントが存在するクラスタの`sys`テナントにログインします。

2. 以下のステートメントを実行して、復元の進捗状況を確認します。

   ```sql
   obclient [oceanbase]> SELECT * FROM oceanbase.CDB_OB_RESTORE_PROGRESS\G
   ```

   このビューには、復元時にユーザーが入力した関連パラメータや復元の進捗状況などの情報が記録されています。

   一度のテナント復元につき、2件のタスクレコードが対応します：`sys`テナントのタスクレコードと復元対象テナントのタスクレコードです。`sys`テナントのタスクレコードは主に復元対象テナントの復元関連情報を記録し、復元の進捗状況は記録されません。復元対象テナントのタスクレコードは主に自身の復元進捗状況を記録します。

   復元中は、復元進捗ビューの`status`フィールドに注目します：

   * システムテナント：

      * `CREATE_TENANT`：テナントの作成。この段階では、システムテナントが復元対象テナントを作成します。テナントの作成完了後、ステータスは`WAIT_TENANT_RESTORE_FINISH`に変更されます。作成に失敗した場合は`RESTORE_FAIL`に変更されます。

      * `WAIT_TENANT_RESTORE_FINISH`：復元対象テナントの復元終了を待機します。テナントの復元完了後、ステータスは`RESTORE_SUCCESS`に変更されます。復元に失敗した場合は`RESTORE_FAIL`に変更されます。

      * `RESTORE_SUCCESS`：テナントの復元に成功しました。

      * `RESTORE_FAIL`：テナントの復元に失敗しました。

   * 復元対象テナント：

      * `RESTORING`：テナントデータの復元中です。復元完了後、ステータスは`RESTORE_SUCCESS`に変更されます。復元に失敗した場合は、ステータスは`RESTORE_FAIL`に変更されます。

      * `RESTORE_SUCCESS`：復元に成功しました。

      * `RESTORE_FAIL`：復元に失敗しました。

   `CDB_OB_RESTORE_PROGRESS`ビューの詳細については、[復元ビュー](../600.restore-data/900.views-of-the-restore.md)を参照してください。

   復元完了後、復元結果を確認できます。具体的な操作については、[復元結果の確認](../600.restore-data/500.view-the-restore-history.md)を参照してください。
