# 物理リストアの進捗状況を確認する

データリストア中は、ビューを通じて物理リストアの進捗状況を確認できます。

## 操作手順

1. `root`ユーザーで、リストア対象のテナントが存在するクラスタの`sys`テナントにログインします。

2. 以下のステートメントを実行して、リストアの進捗状況を確認します。

   ```sql
   obclient [oceanbase]> SELECT * FROM oceanbase.CDB_OB_RESTORE_PROGRESS\G
   ```

   このビューには、リストア時にユーザーが入力した関連パラメータやリストアの進捗状況などの情報が記録されています。

   1回のテナントリストアは、`sys`テナントのタスク記録とリストア対象テナントのタスク記録の2つのタスク記録に対応します。`sys`テナントのタスク記録は主にリストア対象テナントのリストア関連情報を記録し、リストア対象テナントのタスク記録は主に自身のリストア進捗情報を記録します。

   リストア中は、リストア進捗ビューの`STATUS`フィールドに注目します：

   * システムテナント：

      * `CREATE_TENANT`：テナントを作成します。この段階ではシステムテナントがリストア対象テナントを作成します。テナントの作成完了後、ステータスは`WAIT_TENANT_RESTORE_FINISH`に変更されます。作成に失敗した場合は`RESTORE_FAIL`に変更されます。

      * `WAIT_TENANT_RESTORE_FINISH`：リストア対象テナントのリストア終了を待機します。テナントリストア完了後、ステータスは`RESTORE_SUCCESS`に変更されます。リストアに失敗した場合は`RESTORE_FAIL`に変更されます。

      * `RESTORE_SUCCESS`：テナントのリストアに成功しました。

      * `RESTORE_FAIL`：テナントのリストアに失敗しました。

   * リストア対象テナント：

      * `RESTORING`：テナントデータのリストア中です。リストア完了後、ステータスは`POST_CHECK`に変更されます。リストアに失敗した場合、ステータスは`RESTORE_FAIL`に変更されます。

      * `POST_CHECK`：テナントロールをチェックし、スタンバイデータベースにリストアします。操作完了後ステータスは`UPGRADE`に変更されます。操作失敗の場合、ステータスは`RESTORE_FAIL`に変更されます。

      * `UPGRADE`：アップグレード段階です。バージョン間でのリストアの場合、テナントはアップグレードプロセスを実行します。操作完了後、ステータスは`RESTORE_SUCCESS`に変更されます。操作失敗の場合、ステータスは`RESTORE_FAIL`に変更されます。

      * `RESTORE_SUCCESS`：リストアに成功しました。

      * `RESTORE_FAIL`：リストアに失敗しました。

   `CDB_OB_RESTORE_PROGRESS`ビューの詳細については、[リストアビュー](../600.restore-data/900.views-of-the-restore.md)を参照してください。

   リストア完了後、リストア結果を確認できます。具体的な操作については、[リストア結果の確認](../600.restore-data/500.view-the-restore-history.md)を参照してください。
