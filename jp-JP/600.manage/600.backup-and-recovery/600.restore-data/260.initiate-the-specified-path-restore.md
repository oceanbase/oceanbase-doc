# 指定パスでのリストアの実行

データバックアップセット(backup_set)とログアーカイブ(archivelog_piece)が業務上の理由により他のパスに手動で移動した場合、対応するbackup_setとarchivelog_pieceをロードしてからリストアコマンドを発行することで、テナントをリストアできます。

## 前提条件

* リストア対象のbackup_setとarchivelog_pieceの保存パスを確認しておく必要があります。

* リストア対象のbackup_setとarchivelog_pieceが同一テナントに属していることを確認しておく必要があります。現在、同一テナント内のbackup_setとarchivelog_pieceからのみ新しいテナントへのリストアが許可されています。

* リストア前の準備が完了していることを確認しておく必要があります。具体的な操作については、[リストア前の準備](../600.restore-data/100.preparation-before-recovery.md)を参照してください。

## 操作手順

1. `root`ユーザーで、リストア対象のテナントが存在するクラスタの`sys`テナントにログインします。

2. （オプション）`ALTER SYSTEM RESTORE...PREVIEW`コマンドを実行し、元のデータバックアップパス、ログアーカイブパス、および希望のリストア時刻を指定します。

   ステートメントは以下のとおりです：

   ```sql
   ALTER SYSTEM RESTORE FROM 'uri' UNTIL { TIME='timestamp' | SCN=scn } PREVIEW;
   ```

   関連パラメータの説明は以下のとおりです：

   * `uri`：元のデータバックアップパス`backup_data_dest`とログアーカイブパス`log_archive_dest`を指定します。この値には少なくとも1つのデータバックアップパスと1つのログアーカイブパスが含まれ、パスは半角カンマ（,）で区切られます。バックアップ中にアーカイブログバックアップが実行された場合（`BACKUP_ARCHIVE_DEST`が設定されている場合）、`uri`にはアーカイブバックアップの出力先パス`backup_archive_dest`を追加して指定する必要があります。形式は`backup_data_dest,log_archive_dest,backup_archive_dest`で、複数のパスはこの順序で並べる必要があります。

     * データバックアップ時に`TO`構文を使用してバックアップ先パスを指定した場合（例：指定ディレクトリAへのバックアップ）、`uri`内のデータバックアップパスには、バックアップ時に指定したバックアップ先パス（A）を記入する必要があります。システムパラメータ`data_backup_dest`で設定されたデフォルトパスではありません。形式は引き続き`A,log_archive_dest`です。
     * テナントが`DELETE INPUT`パラメータを使用したアーカイブバックアップを実行した場合、形式は`A,log_archive_dest,backup_archive_dest`です。

      <main id="notice" type='explain'>
      <h4>説明</h4>
      <p>V4.4.2バージョンでは、V4.4.2 BP3バージョン以降、<code>uri</code>でアーカイブバックアップの出力先パス<code>backup_archive_dest</code>を指定できるようになりました。<code>BACKUP_ARCHIVE_DEST</code>が設定されている限り、常に<code>uri</code>にアーカイブバックアップパスを含めることができ、システムは必要に応じて対応するPieceを読み取ります。古いPieceがアーカイブバックアップの出力先にあり、対応するログアーカイブの出力先のコピーがクリーンアップされ、新しいPieceがまだログアーカイブの出力先にある場合、リストアタスクは2つの出力先から同時にログを読み取ることができます。</p>
      </main>

   * `TIME='timestamp' | SCN=scn`：リストア希望日時のタイムスタンプまたはSCNを指定します。このステートメントを実行する際には、時間を明示的に指定する必要があります。

   パラメータの詳細については、[ALTER SYSTEM - RESTORE PREVIEW](../../../700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/3350.restore-preview.md)を参照してください。

   例：

   :::tab
   tab OSS

   * 元のデータバックアップパスとログアーカイブパスを指定し、指定されたSCN `1712650554000909004` にリストアすることを希望します。

      ```shell
      obclient [oceanbase]> ALTER SYSTEM RESTORE FROM 'oss://test_bucket/data?host=***&access_id=****&access_key=****, oss://test_bucket/archive?host=***&access_id=****&access_key=****' UNTIL SCN = 1712650554000909004 PREVIEW;
      ```

   * 元のデータバックアップパスとログアーカイブパスを指定し、指定されたタイムスタンプ `2024-04-09 16:15:54` にリストアすることを希望します。

      ```shell
      obclient [oceanbase]> ALTER SYSTEM RESTORE FROM 'oss://test_bucket/data?host=***&access_id=****&access_key=****, oss://test_bucket/archive?host=***&access_id=****&access_key=****' UNTIL TIME = '2024-04-09 16:15:54' PREVIEW;
      ```

   * 元のデータバックアップパス、ログアーカイブパス、アーカイブバックアップの出力先パスを指定し、指定されたタイムスタンプ `2024-04-09 16:15:54` にリストアすることを希望します。

      ```shell
      obclient [oceanbase]> ALTER SYSTEM RESTORE FROM 'oss://test_bucket/data?host=***&access_id=****&access_key=****, oss://test_bucket/archive?host=***&access_id=****&access_key=****, oss://test_bucket/backup_archive?host=***&access_id=****&access_key=****' UNTIL TIME = '2024-04-09 16:15:54' PREVIEW;
      ```

   tab NFS

   * 元データのバックアップパスとログアーカイブパスを指定し、指定されたSCN `1712650554000909004` にリストアすることを希望します。

      ```shell
      obclient [oceanbase]> ALTER SYSTEM RESTORE FROM 'file:///ob_backup/data, file:///ob_backup/archive' UNTIL SCN = 1712650554000909004 PREVIEW;
      ```

   * 元データのバックアップパスとログアーカイブパスを指定し、指定されたタイムスタンプ `2024-04-09 16:15:54` にリストアすることを希望します。

      ```shell
      obclient [oceanbase]> ALTER SYSTEM RESTORE FROM 'file:///ob_backup/data, file:///ob_backup/archive' UNTIL TIME = '2024-04-09 16:15:54' PREVIEW;
      ```

   * 元データのバックアップパス、ログアーカイブパス、およびアーカイブバックアップのターゲットパスを指定し、指定したタイムスタンプ `2024-04-09 16:15:54` にリストアすることを希望します。

      ```shell
      obclient [oceanbase]> ALTER SYSTEM RESTORE FROM 'file:///ob_backup/data, file:///ob_backup/archive, file:///ob_backup/backup_archive' UNTIL TIME = '2024-04-09 16:15:54' PREVIEW;
      ```

   :::

3. （オプション）`SHOW RESTORE PREVIEW`コマンドを実行し、指定された時間までリストアするために必要なbackup_setとarchivelog_pieceを表示します。

   <main id="notice" type='notice'>
   <h4>注意</h4>
   <p><code>ALTER SYSTEM RESTORE...PREVIEW</code>コマンドが正常に実行された後に、<code>SHOW RESTORE PREVIEW</code>コマンドを実行する必要があります。そうでない場合、必要な結果を取得できません。</p>
   </main>

   ```shell
   obclient [oceanbase]> SHOW RESTORE PREVIEW;
   ```

   例えば、結果は次のとおりです：

   ```shell
   | BACKUP_PIECE |         4 | file:///ob_backup/archive/piece_d1002r1p4                                      | start_scn_display: 20240409T160554, checkpoint_scn_display: 20240409T160754. |

   9 rows in set
   ```

   クエリ結果には、指定された時間までリストアするために必要なすべてのbackup_setとarchivelog_piece、およびこれらのファイルが元のデータバックアップとログアーカイブの出力先に保存されるパスが表示されます。業務上のニーズに応じて、ユーザーが一部またはすべてのファイルを手動で他のパスやストレージ媒体に移動した場合は、実際の状況に応じて、各backup_setとarchivelog_pieceの元のパスから現在のパスへのマッピング関係を自ら管理する必要があります。

   例えば、上記のクエリ結果で、`BACKUP_PIECE`が`1`のarchivelog_pieceを使用してリストアする必要がある場合、そのファイルが既に`oss://test_bucket/archive/piece_1`に手動で移動されている場合、`ADD RESTORE SOURCE`コマンドでバックアップパスを読み込む際に、新しい保存パス`oss://test_bucket/archive/piece_1`を選択する必要があります。

4. `ADD RESTORE SOURCE`コマンドを実行し、リストアに必要なbackup_setとarchivelog_pieceを個別に読み込みます。

   ロードパスのステートメントは以下のとおりです：

   ```sql
   ALTER SYSTEM ADD RESTORE SOURCE 'restore_path';
   ```

   ステートメントの使用方法：

   * `restore_path`：ロードする backup_set、archivelog_piece、またはアーカイブバックアップの出力先パスを入力します。1つのパスでも複数のパスでもかまいません。

      <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>ロードする backup_set、archivelog_piece、またはアーカイブバックアップデータがオブジェクトストレージに保存されている場合、各パス内の <code>host</code>、<code>access_id</code>、および <code>access_key</code> などのパラメータ情報がすべて同じである必要があります。</p>
      </main>

   * このステートメントは同一セッション内で連続して複数回実行できます。同一セッション内で複数回実行する場合、システムは指定されたパスをリストアソースリストに順次追加します。

   例：

   1. リストア対象のbackup_setをロードします。

      ```shell
      obclient [oceanbase]> ALTER SYSTEM ADD RESTORE SOURCE 'file:///ob_backup/data/backup_set_1_full';
      ```

   2. リストア対象のarchivelog_pieceをロードします。

      ```shell
      obclient [oceanbase]> ALTER SYSTEM ADD RESTORE SOURCE 'file:///ob_backup/archive/piece_d1002r1p1,file:///ob_backup/archive/piece_d1002r1p2';
      ```

      ```shell
      obclient [oceanbase]> ALTER SYSTEM ADD RESTORE SOURCE 'oss://test_bucket/archive/piece_1?host=***&access_id=x****&access_key=****';
      ```

   3. バックアップ中にアーカイブログバックアップを実行した場合（`BACKUP_ARCHIVE_DEST`が設定されている場合）、アーカイブバックアップの出力先パスもロードする必要があります。

      ```shell
      obclient [oceanbase]> ALTER SYSTEM ADD RESTORE SOURCE 'file:///ob_backup/backup_archive';
      ```

      ```shell
      obclient [oceanbase]> ALTER SYSTEM ADD RESTORE SOURCE 'oss://test_bucket/backup_archive?host=***&access_id=****&access_key=****';
      ```

5. （オプション）backup_set、archivelog_piece、またはアーカイブバックアップパスのロード中に誤ったパスを入力した場合、以下のステートメントを実行して前回の入力を取り消し、正しいリストアパスを再ロードできます。

    ```shell
    obclient [oceanbase]> ALTER SYSTEM CLEAR RESTORE SOURCE;
    ```

6. すべてのパスのロードが成功した後、リストアコマンドを呼び出します。

   <main id="notice" type='notice'>
   <h4>注意</h4>
   <ul>
   <li>リストアコマンドを実行する際には、<code>ADD RESTORE SOURCE</code>コマンドを実行したセッションと同じセッションである必要があります。異なるセッション（元のセッションが中断された場合や新しいセッションを使用した場合）の場合、以前にロードされたリストアソースリストはクリアされます。</li>
   <li><code>ADD RESTORE SOURCE</code>コマンドを実行した後、同一セッション内でバックアップの出力先を指定するリストアコマンドを使用してテナントをリストアすることはできません。</li>
   <li>リストアコマンドを実行した後、リストアが成功したかどうかにかかわらず、以前にロードされたリストアソースリストはクリアされます。リストアコマンドを再度実行する必要がある場合は、リストアに必要なbackup_set、archivelog_piece、およびアーカイブバックアップパスを再ロードする必要があります。</li>
   <li>アーカイブバックアップの出力先には、フリーズ(FROZEN)されたPieceのみが保存されます。より新しい時点までリストアする場合、通常は新しいPieceとACTIVE部分を含むログアーカイブパスも提供する必要があります。ログアーカイブパスとアーカイブバックアップパスの両方を同時にロードすることを推奨します。リストア中、ログアーカイブパスとアーカイブバックアップパスのいずれにも必要なPieceが存在しない場合、リストアは失敗します。</li>
   </ul>
   </main>

   以下のステートメントを実行します：

   ```sql
   ALTER SYSTEM RESTORE restore_tenant_name [UNTIL {TIME='timestamp' | SCN=scn} ] WITH 'restore_option';
   ```

   パラメータの詳細については、[ALTER SYSTEM - RESTORE](../../../700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/3300.restore.md)を参照してください。

      各パラメータの詳細については、[物理リストア関連パラメータ紹介](800.parameters-of-the-restore.md)を参照してください。

   リストアコマンドを呼び出す例：

   * 指定されたパスからテナント`mysql`を指定されたSCN `1658285759724047000`までリストアし、リソースプールを`restore_pool`に指定します。

      ```shell
      // フル復元
      obclient [oceanbase]> ALTER SYSTEM RESTORE mysql UNTIL SCN = 1712650554000909004 WITH 'pool_list=restore_pool';

      // クイック復元
      obclient [oceanbase]> ALTER SYSTEM RESTORE mysql UNTIL SCN = 1712650554000909004 WITH 'pool_list=restore_pool&method=quick';
      ```

   * 指定されたパスからテナント`mysql`を指定されたタイムスタンプ`2024-04-09 16:15:54`までリストアし、リソースプールを`restore_pool`に指定します。

      ```shell
      // フル復元
      obclient [oceanbase]> ALTER SYSTEM RESTORE mysql UNTIL TIME = '2024-04-09 16:15:54' WITH 'pool_list=restore_pool';

      // クイック復元
      obclient [oceanbase]> ALTER SYSTEM RESTORE mysql UNTIL TIME = '2024-04-09 16:15:54' WITH 'pool_list=restore_pool&method=quick';
      ```

## 次のステップ

* リストアタスクの開始後、ビューを通じてリストアの進捗状況と結果を確認できます。詳細な操作については、[リストアの進捗状況を確認する](../600.restore-data/400.view-the-restore-progress.md)を参照してください。

* リストアタスク完了後、低いバージョンのバックアップデータから高いバージョンのクラスタにリストアするシナリオの場合、リストアされたテナントのアップグレードも行う必要があります。詳細な操作については、[リストア完了後のテナントのアップグレード](610.update-the-tenant-after-the-restore.md)を参照してください。

* 物理リストアのプロセスはフィジカルスタンバイ・データベースと統一されており、物理リストア後のテナントはスタンバイテナントとなります。その後、このテナントはスタンバイテナントとして関連サービスを提供することも、プライマリテナントに切り替えてサービスを提供することもできます。スタンバイテナントとしてログアーカイブを利用し、ソーステナントのログを継続してリプレイする詳細な操作については、[スタンバイテナントによるログのセグメントリプレイ](510.recover-the-standby-tenant.md)を参照してください。スタンバイテナントをプライマリテナントに切り替える詳細な操作については、[スタンバイテナントをプライマリテナントに切り替える](600.active-standby-tenant.md)を参照してください。
