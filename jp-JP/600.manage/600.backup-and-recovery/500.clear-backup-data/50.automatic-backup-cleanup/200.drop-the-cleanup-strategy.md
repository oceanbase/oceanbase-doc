# クリーンアップ戦略の削除

クリーンアップ戦略の設定後、期限切れバックアップの自動クリーンアップを停止したり、クリーンアップ戦略を変更したりする場合は、まずそのクリーンアップ戦略を削除する必要があります。

## 注意事項と説明

* クリーンアップ戦略を削除する際、テナント内のすべてのクリーンアップ戦略を削除すると、そのテナントの自動クリーンアップ機能が無効になります。

* クリーンアップ戦略の削除は、実行中のクリーンアップタスクには影響しません。削除されたクリーンアップ戦略によって生成されるクリーンアップタスクは、システムが次回自動クリーンアップをスケジューリングする場合にのみ生成されなくなります。

## システムテナントが指定ユーザーテナントのクリーンアップ戦略を削除する場合

1. `root` ユーザーでクラスタの `sys` テナントにログインします。

2. 以下のステートメントを実行して、クリーンアップ戦略を削除します。

   ```sql
   ALTER SYSTEM DROP DELETE BACKUP POLICY policy_name TENANT [=] tenant_name;
   ```

   このうち：

   * `policy_name`：削除するクリーンアップ戦略の名前を指定します。この情報はビュー `CDB_OB_BACKUP_DELETE_POLICY` から取得できます。

   * `tenant_name`：ユーザーテナントの名前を指定します。システムテナントからクリーンアップ戦略を削除する場合は、ユーザーテナント名を指定する必要があり、指定できるのは1つのユーザーテナント名のみです。

   例：

   * システムテナントがテナント `mysql001` のクリーンアップ戦略を削除する場合

     ```shell
     obclient(root@sys)[(none)]> ALTER SYSTEM DROP DELETE BACKUP POLICY 'default' TENANT mysql001;
     ```

   * システムテナントがテナント `oracle001` のクリーンアップ戦略を削除する場合

     ```shell
     obclient(root@sys)[(none)]> ALTER SYSTEM DROP DELETE BACKUP POLICY 'log_only' TENANT oracle001;
     ```

3. クリーンアップ戦略が削除されたかどうかを確認します。

   ```shell
   obclient(root@sys)[(none)]> SELECT * FROM oceanbase.CDB_OB_BACKUP_DELETE_POLICY WHERE tenant_id = 1002;
   ```

   クエリ結果に基づき、ビューに対応するテナントのクリーンアップ戦略記録がなくなっていれば、そのテナントのクリーンアップ戦略は正常に削除されたことを意味します。

## ユーザーテナントが自身のテナントを削除する際のクリーンアップ戦略

1. テナント管理者がデータベースにログインします。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>MySQLテナントの管理者ユーザーは<code>root</code>ユーザー、Oracleテナントの管理者ユーザーは<code>SYS</code>ユーザーです。</p>
   </main>

2. 以下のステートメントを実行して、クリーンアップ戦略を削除します。

   ステートメントは以下のとおりです：

   ```sql
   ALTER SYSTEM DROP DELETE BACKUP POLICY policy_name;
   ```

   ここで、`policy_name` は削除するクリーンアップ戦略の名前を指定するために使用されます。現在のテナントで設定されているクリーンアップ戦略は、ビュー `oceanbase.DBA_OB_BACKUP_DELETE_POLICY` または `SYS.DBA_OB_BACKUP_DELETE_POLICY` を参照して取得できます。

   例：

   :::tab
   tab MySQLモード

   MySQLモードで現在のテナントを削除する際のクリーンアップ戦略`default`。

   ```shell
   obclient(root@mysql001)[(none)]> ALTER SYSTEM DROP DELETE BACKUP POLICY 'default';
   ```

   tab Oracleモード

   Oracleモードで現在のテナントを削除する際のクリーンアップ戦略は`log_only`です。

   ```shell
   obclient(SYS@oracle001)[SYS]> ALTER SYSTEM DROP DELETE BACKUP POLICY 'log_only';
   ```

   :::

3. クリーンアップ戦略が削除されたかどうかを確認します。

   ビュー `oceanbase.DBA_OB_BACKUP_DELETE_POLICY`（MySQLモード）または `SYS.DBA_OB_BACKUP_DELETE_POLICY`（Oracleモード）を参照することで、現在のテナントのクリーンアップ戦略が削除されたかどうかを確認できます。

   :::tab
   tab MySQLモード

   MySQLモードでのクエリ例は以下のとおりです。

   ```shell
   obclient(root@mysql001)[oceanbase]> SELECT * FROM oceanbase.DBA_OB_BACKUP_DELETE_POLICY;
   ```

   tab Oracleモード

   Oracleモードでのクエリ例は以下のとおりです：

   ```shell
   obclient(SYS@oracle001)[SYS]> SELECT * FROM SYS.DBA_OB_BACKUP_DELETE_POLICY;
   ```

   :::

   クエリ結果に基づき、ビューに対応するクリーンアップ戦略のレコードがない場合、そのテナントのクリーンアップ戦略は正常に削除されたことを意味します。

## 次のステップ

クリーンアップ戦略を削除した後、バックアップファイルがタイムリーにクリーンアップされずにディスク容量が満杯となり、最終的にバックアップ操作に影響を与えるのを避けるため、削除後は速やかに新しいクリーンアップ戦略を設定してください。クリーンアップ戦略の設定手順については、[自動的に期限切れバックアップをクリーンアップする](100.cleaning-up-backed-up-data-automatically.md)を参照してください。
