# バックアップパスまたはアーカイブパスの手動クリーンアップ

バックアップパスまたはアーカイブパスを置き換えた後、不要になった元のデータのバックアップパスまたはアーカイブパスをクリーンアップできます。データのバックアップパスまたはアーカイブパスをクリーンアップすると、そのパス配下のすべてのバックアップセットやログアーカイブファイルが削除されます。

## 使用上の制限

* 置き換えられたバックアップまたはアーカイブパスのみをクリーンアップできます。現在使用中のバックアップまたはアーカイブパスのクリーンアップはサポートされていません。

* クリーンアップ中の古いパスをバックアップパスまたはアーカイブパスに再設定することはできません。

## バックアップパスのクリーンアップ

### システムテナントが指定ユーザーテナントのバックアップパスをクリーンアップする場合

1. `root`ユーザーでクラスタの`sys`テナントにログインします。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に従ってください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. テナント情報を確認し、テナントの`TENANT_ID`を取得します。

   このドキュメントでは、テナントが`mysql001`の場合を例に説明します。クエリ例は以下のとおりです：

   ```shell
   obclient(root@sys)[(none)]> SELECT TENANT_ID, TENANT_NAME, TENANT_TYPE FROM oceanbase.DBA_OB_TENANTS WHERE TENANT_NAME = 'mysql001';
   ```

   クエリ結果は次のとおりです：

   ```shell
   +-----------+-------------+-------------+
   | TENANT_ID | TENANT_NAME | TENANT_TYPE |
   +-----------+-------------+-------------+
   |      1002 | mysql001    | USER        |
   +-----------+-------------+-------------+
   1 row in set
   ```

   クエリ結果によると、このテナントの`TENANT_ID`は1002です。

3. クリーンアップ対象のバックアップパスを取得します。

   1. 指定したテナントのすべてのバックアップパス情報を確認します。

      ```shell
      obclient(root@sys)[(none)]> SELECT TENANT_ID, PATH, DEST_TYPE, STATUS FROM oceanbase.CDB_OB_BACKUP_STORAGE_INFO WHERE TENANT_ID = 1002 AND DEST_TYPE = 'backup_data';
      ```

      クエリ結果は次のとおりです：

      ```shell
      +-----------+-------------------------------+-------------+--------+
      | TENANT_ID | PATH                          | DEST_TYPE   | STATUS |
      +-----------+-------------------------------+-------------+--------+
      |      1002 | file:///data/nfs/backup/data2 | backup_data | NORMAL |
      |      1002 | file:///data/nfs/backup/data1 | backup_data | NORMAL |
      +-----------+-------------------------------+-------------+--------+
      2 rows in set
      ```

      クエリ結果によると、このテナントには2つのバックアップパス情報があります。

   2. 指定したテナントが現在使用中のバックアップパスを確認します。

      ```shell
      obclient(root@sys)[(none)]> SELECT * FROM oceanbase.CDB_OB_BACKUP_PARAMETER WHERE TENANT_ID = 1002;
      ```

      クエリ結果は次のとおりです：

      ```shell
      +-----------+------------------+-------------------------------+
      | TENANT_ID | NAME             | VALUE                         |
      +-----------+------------------+-------------------------------+
      |      1002 | data_backup_dest | file:///data/nfs/backup/data2 |
      +-----------+------------------+-------------------------------+
      1 row in set
      ```

      クエリ結果によると、現在使用中のバックアップパスは`file:///data/nfs/backup/data2`です。したがって、クリーンアップ対象のバックアップパス`file:///data/nfs/backup/data1`は現在使用中のものではないため、クリーンアップできます。

4. 以下のコマンドを実行して、指定されたバックアップパスをクリアします。

   ステートメントは以下のとおりです：

   ```sql
   ALTER SYSTEM DELETE BACKUP ALL DATA_BACKUP_DEST [=] 'data_backup_path' TENANT [=] tenant_name;
   ```

   ここで：

   * `data_backup_path`：クリアするデータバックアップパスを指定します。

   * `tenant_name`：データバックアップパスをクリアするユーザーテナントを指定します。

   例：

   :::tab
   tab OSS

   システムテナントがテナント `mysql001` のOSSバックアップパス `oss://oceanbase-test-bucket/backup/data?host=****.aliyun-inc.com` をクリアします。

   ```shell
   obclient(root@sys)[(none)]> ALTER SYSTEM DELETE BACKUP ALL DATA_BACKUP_DEST ='oss://oceanbase-test-bucket/backup/data?host=****.aliyun-inc.com' TENANT = mysql001;
   ```

   tab NFS

   システムテナントがテナント `mysql001` のNFSバックアップパス `file:///data/nfs/backup/data1` をクリアします。

   ```shell
   obclient(root@sys)[(none)]> ALTER SYSTEM DELETE BACKUP ALL DATA_BACKUP_DEST ='file:///data/nfs/backup/data1' TENANT = mysql001;
   ```

   :::

5. コマンドの実行が成功した後、ビューを使用してクリア中のパス情報を確認できます。

   ```shell
   obclient(root@sys)[(none)]> SELECT TENANT_ID, PATH, DEST_TYPE, STATUS FROM oceanbase.CDB_OB_BACKUP_STORAGE_INFO WHERE TENANT_ID = 1002 AND PATH = 'file:///data/nfs/backup/data1';
   ```

   クエリ結果の例は以下のとおりです：

   ```shell
   +-----------+-------------------------------+-------------+----------+
   | TENANT_ID | PATH                          | DEST_TYPE   | STATUS   |
   +-----------+-------------------------------+-------------+----------+
   |      1002 | file:///data/nfs/backup/data1 | backup_data | DELETING |
   +-----------+-------------------------------+-------------+----------+
   1 row in set
   ```

   クエリ結果から、パスのクリア処理中に、対応するパスの `STATUS` フィールドの値が `DELETING` に変わることが確認できます。クリアが完了すると、対応する行は削除されます。

### ユーザーテナントが自身のテナントのバックアップパスをクリアする場合

1. ユーザーテナントのテナント管理者がデータベースにログインします。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>MySQLテナントの管理者ユーザーは <code>root</code> ユーザー、Oracleテナントの管理者ユーザーは <code>SYS</code> ユーザーです。</p>
   </main>

   接続の例は以下のとおりです。データベースへの接続時は、実際の環境に準じてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql001#obdemo -p***** -A
   ```

2. クリーンアップ対象のバックアップパスを取得します。

   1. このテナント配下のすべてのバックアップパス情報を確認します。

      :::tab
      tab MySQLモード

      MySQLモードでのクエリ例は以下のとおりです：


      tab Oracleモード

      Oracleモードでのクエリ例は以下のとおりです：

      ```shell
      obclient(SYS@oracle001)[SYS]> SELECT TENANT_ID, PATH, DEST_TYPE, STATUS FROM SYS.DBA_OB_BACKUP_STORAGE_INFO WHERE DEST_TYPE = 'backup_data'\G
      ```

      :::

      クエリ結果の例は以下のとおりです：

      ```shell
      +-------------------------------+-------------+--------+
      | PATH                          | DEST_TYPE   | STATUS |
      +-------------------------------+-------------+--------+
      | file:///data/nfs/backup/data2 | backup_data | NORMAL |
      | file:///data/nfs/backup/data1 | backup_data | NORMAL |
      +-------------------------------+-------------+--------+
      2 rows in set
      ```

      クエリ結果によると、このテナント配下には2つのバックアップパス情報があります。

   2. このテナントが現在使用しているバックアップパスを確認します。

      :::tab
      tab MySQLモード

      MySQLモードでのクエリ例は以下のとおりです：

      ```shell
      obclient(root@mysql001)[(none)]> SELECT * FROM oceanbase.DBA_OB_BACKUP_PARAMETER;
      ```

      tab Oracleモード

      Oracleモードでのクエリ例は以下のとおりです：

      ```shell
      obclient(SYS@oracle001)[SYS]> SELECT * FROM SYS.DBA_OB_BACKUP_PARAMETER;
      ```

      :::

      クエリ結果の例は以下のとおりです：

      ```shell
      +------------------+-------------------------------+
      | NAME             | VALUE                         |
      +------------------+-------------------------------+
      | data_backup_dest | file:///data/nfs/backup/data2 |
      +------------------+-------------------------------+
      1 row in set
      ```

      クエリ結果によると、現在使用中のバックアップパスは`file:///data/nfs/backup/data2`であるため、クリーンアップ対象のバックアップパス`file:///data/nfs/backup/data1`は使用中ではなく、クリーンアップできます。

3.  以下のコマンドを実行して、指定されたバックアップパスをクリアします。

   ステートメントは以下のとおりです：

   ```sql
   ALTER SYSTEM DELETE BACKUP ALL DATA_BACKUP_DEST [=] 'data_backup_path';
   ```

   ここで、`data_backup_path` はクリア対象のデータバックアップパスを指定するために使用されます。

   例：

   :::tab
   tab OSS

   ユーザーテナントが自身のテナントのOSSバックアップパス `oss://oceanbase-test-bucket/backup/data?host=****.aliyun-inc.com` をクリアします。

   ```shell
   obclient> ALTER SYSTEM DELETE BACKUP ALL DATA_BACKUP_DEST ='oss://oceanbase-test-bucket/backup/data?host=****.aliyun-inc.com';
   ```

   tab NFS

   ユーザーテナントが自身のテナントのNFSバックアップパス `file:///data/nfs/backup/data1` をクリアします。

   ```shell
   obclient> ALTER SYSTEM DELETE BACKUP ALL DATA_BACKUP_DEST ='file:///data/nfs/backup/data1';
   ```

   :::

4.  コマンドの実行が成功した後、ビューを通じてクリア中のパス情報を確認できます。

   :::tab
   tab MySQLモード

   MySQLモードでのクエリ例は以下のとおりです：

   ```shell
   obclient(root@mysql001)[(none)]> SELECT PATH, DEST_TYPE, STATUS FROM oceanbase.DBA_OB_BACKUP_STORAGE_INFO WHERE PATH = 'file:///data/nfs/backup/data1';
   ```

   tab Oracleモード

   Oracleモードでのクエリ例は以下のとおりです：

   ```shell
   obclient(SYS@oracle001)[SYS]> SELECT PATH, DEST_TYPE, STATUS FROM SYS.DBA_OB_BACKUP_STORAGE_INFO WHERE PATH = 'file:///data/nfs/backup/data1';
   ```

   :::

   クエリ結果の例は以下のとおりです：

   ```shell
   +-------------------------------+-------------+----------+
   | PATH                          | DEST_TYPE   | STATUS   |
   +-------------------------------+-------------+----------+
   | file:///data/nfs/backup/data1 | backup_data | DELETING |
   +-------------------------------+-------------+----------+
   1 row in set
   ```

   クエリ結果からわかるように、パスのクリア処理中、対応するパスの `STATUS` フィールドの値が `DELETING` に変わります。クリアが完了すると、対応する行は削除されます。

## アーカイブパスのクリーンアップ

### システムテナントが指定したユーザーテナントのアーカイブパスをクリーンアップする場合

1. `root` ユーザーでクラスタの `sys` テナントにログインします。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に準じてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. テナント情報を確認し、テナントの `TENANT_ID` を取得します。

   このドキュメントでは、テナント `mysql001` を例に説明します。クエリ例は以下のとおりです：

   ```shell
   obclient(root@sys)[(none)]> SELECT TENANT_ID, TENANT_NAME, TENANT_TYPE FROM oceanbase.DBA_OB_TENANTS WHERE TENANT_NAME = 'mysql001';
   ```

   クエリ結果は次のとおりです：

   ```shell
   +-----------+-------------+-------------+
   | TENANT_ID | TENANT_NAME | TENANT_TYPE |
   +-----------+-------------+-------------+
   |      1002 | mysql001    | USER        |
   +-----------+-------------+-------------+
   1 row in set
   ```

   クエリ結果によると、このテナントの `TENANT_ID` は1002です。

3. クリーンアップ対象のアーカイブパスを取得します。

   1. 指定したテナントのすべてのアーカイブパスを確認します。

      ```shell
      obclient(root@sys)[(none)]> SELECT TENANT_ID, PATH, DEST_TYPE, STATUS FROM oceanbase.CDB_OB_BACKUP_STORAGE_INFO WHERE TENANT_ID = 1002 AND DEST_TYPE = 'archive_log';
      ```

      クエリ結果の例は次のとおりです：

      ```shell
      +-----------+----------------------------------+-------------+---------+
      | TENANT_ID | PATH                             | DEST_TYPE   | STATUS  |
      +-----------+----------------------------------+-------------+---------+
      |      1002 | file:///data/nfs/backup/archive2 | archive_log | NORMAL  |
      |      1002 | file:///data/nfs/backup/archive1 | archive_log | NORMAL  |
      +-----------+----------------------------------+-------------+---------+
      1 row in set
      ```

      クエリ結果によると、このテナントには2つのアーカイブパス情報があります。

   2. 指定したテナント内で使用中のアーカイブパスを確認します。

      ```shell
      obclient(root@sys)[(none)]> SELECT TENANT_ID, NAME, VALUE FROM oceanbase.CDB_OB_ARCHIVE_DEST WHERE TENANT_ID = tenant_id AND NAME = 'path';
      ```

      クエリ結果の例は次のとおりです：

      ```shell
      +-----------+------+------------------------------------+
      | TENANT_ID | NAME | VALUE                              |
      +-----------+------+------------------------------------+
      |      1002 | path | file:///data/nfs/backup/archive2   |
      +-----------+------+------------------------------------+
      1 row in set
      ```

      クエリ結果によると、使用中のアーカイブパスは `file:///data/nfs/backup/archive2` であり、クリーンアップ対象のパス `file:///data/nfs/backup/archive1` は使用中のアーカイブパスではないため、クリーンアップできます。

4. 以下のコマンドを実行して、指定したアーカイブパスをクリーンアップします。

   ステートメントは以下のとおりです：

   ```sql
   ALTER SYSTEM DELETE BACKUP ALL LOG_ARCHIVE_DEST [=] 'log_archive_path' TENANT [=] tenant_name;
   ```

   その中で：

   * `log_archive_path`：クリーンアップ対象のアーカイブパスを指定します。

   * `tenant_name`：クリーンアップ対象のアーカイブパスのユーザーテナントを指定します。

   例：

   :::tab
   tab OSS

   システムテナントがテナント `mysql001` のOSSアーカイブパス `oss://oceanbase-test-bucket/backup/archive?host=****.aliyun-inc.com` をクリーンアップします。

   ```shell
   obclient(root@sys)[(none)]> ALTER SYSTEM DELETE BACKUP ALL LOG_ARCHIVE_DEST ='oss://oceanbase-test-bucket/backup/archive?host=****.aliyun-inc.com' TENANT = mysql001;
   ```

   tab NFS

   システムテナントがテナント `mysql001` のNFSアーカイブパス `file:///data/nfs/backup/archive1` をクリーンアップします。

   ```shell
   obclient(root@sys)[(none)]> ALTER SYSTEM DELETE BACKUP ALL LOG_ARCHIVE_DEST ='file:///data/nfs/backup/archive1' TENANT = mysql001;
   ```

   :::

5. コマンド実行が成功した後、ビューを通じてクリーンアップ中のパス情報を確認できます。

   ```shell
   obclient(root@sys)[(none)]> SELECT TENANT_ID, PATH, DEST_TYPE, STATUS FROM oceanbase.CDB_OB_BACKUP_STORAGE_INFO WHERE TENANT_ID = 1002 AND PATH = 'file:///data/nfs/backup/archive1';
   ```

   クエリ結果の例は以下のとおりです：

   ```shell
   +-----------+----------------------------------+-------------+-----------+
   | TENANT_ID | PATH                             | DEST_TYPE   | STATUS    |
   +-----------+----------------------------------+-------------+-----------+
   |      1002 | file:///data/nfs/backup/archive1 | archive_log | DELETING  |
   +-----------+----------------------------------+-------------+-----------+
   1 row in set
   ```

   クエリ結果から、パスのクリーンアップ処理中に、該当パスの `STATUS` フィールドの値が `DELETING` に変わることが確認できます。クリーンアップ完了後、該当行は削除されます。
