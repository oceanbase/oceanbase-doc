# バックアップのクリーンアップに関するパラメータの紹介

現在、クリーンアップポリシーの設定では、ユーザーが `recovery_window` パラメータを設定することのみがサポートされています。このパラメータの設定により、バックアップファイルのクリーンアップが判断されます。

## recovery_window パラメータ

このパラメータは、バックアップデータの復元可能な時間窓を制御し、バックアップデータの有効期限切れを判断する基準として使用されます。`recovery_window` パラメータの設定には時間単位が必要です。

`recovery_window` によるデータバックアップの有効期限切れの判断方法：「現在時刻 - バックアップ時点」 >= `recovery_window` の条件を満たす最新のバックアップよりも古いすべてのバックアップは、有効期限切れと見なされます。

例えば、`recovery_window='7d'` を設定すると、現在時刻から遡って7日間以内のデータは復元可能であることを保証し、この7日間のデータ復元と無関係なバックアップデータは有効期限切れのデータと見なされます。

以下の簡単な例を通じて、`recovery_window` を設定した後、どのバックアップデータが有効期限切れとなるかを説明します。現在のデータバックアップ状況は以下の図のとおりです。

![自動バックアップクリーンアップの例](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.2.1/EN_US/600.manage/600.backup-and-recovery/BackupCleanup.png)

自動クリーンアップの場合、システムは1回のフルバックアップ + 数回の増分バックアップによって有効期限切れデータをクリーンアップします。上記の図を例にすると：

* 最初のグループのバックアップ：1月1日のフルバックアップ `backup_set 1`、1月4日の増分バックアップ `backup_set 2`。

* 2番目のグループのバックアップ：1月7日のフルバックアップ `backup_set 3`、1月11日の増分バックアップ `backup_set 4`。

* 3番目のグループのバックアップ：1月14日のフルバックアップ `backup_set 5`。

現在時刻が1月15日の場合、最も早い復元ポイントは1月8日です。つまり、1月8日から1月15日までのバックアップデータは復元可能であることが保証されます。データの復元はフルバックアップに基づく必要があるため、1月8日から1月14日のフルバックアップ以前のデータ復元は、復元可能ポイントより前の最初のフルバックアップ `backup_set 3` に依存します。そのため、システムは `backup_set 3` を保持し、1月7日以前のバックアップデータはすべて有効期限切れのバックアップデータと見なされます。つまり、最初のグループのバックアップ `backup_set 1` と `backup_set 2` が有効期限切れのバックアップとなります。自動クリーンアップ機能を起動すると、有効期限切れのバックアップデータはクリーンアップされます。
