# SYSテナント/RSサービスの問題

OceanBaseデータベースにおいて、RS（Root Service）はクラスタリソース管理や分散戦略の実行を担当するコアサービスとして、クラスタ内で非常に重要な役割を果たします。また、RSに計算およびストレージリソースを提供するSYSテナントも、マルチレプリカによる自己選出方式を通じて高可用性を実現しています。規模が大きい環境や負荷が高い場合、極端な状況やハードウェアの問題など、ごく稀ではありますが、SYSテナントのキューが積み残されることによって問題が発生する可能性があります。このセクションでは、そのような状況に対する緊急対応策をいくつか紹介します。

## 緊急対応方法

`sys` テナントのキューが積み残された場合、以下の方法で対処することができます。

### sysテナントリソースの拡張

1. 各テナントに割り当てられるリソースの確認方法は以下のとおりです

   ```sql
   obclient> SELECT a.tenant_name,a.tenant_id,b.name unit_config,c.name pool_name,b.max_cpu,b.min_cpu
   FROM
   OCEANBASE.DBA_OB_TENANTS a,
   OCEANBASE.DBA_OB_UNIT_CONFIGS b,
   OCEANBASE.DBA_OB_RESOURCE_POOLS c
   WHERE a.tenant_id=c.tenant_id
   AND b.unit_config_id = c.unit_config_id
   ORDER BY a.tenant_id desc;
   ```

2. 以下のコマンドを実行して、`sys` テナントのCPUおよびメモリリソースを拡張します。

   ```sql
   ALTER RESOURCE UNIT unit_config_name min_cpu = 2,max_cpu = 2,memory_size = '2G',max_iops = 10000,min_iops = 10000;
   ```

   <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>OceanBase V3.2以降では、<code>resource unit</code>設定の変更はCPUおよびメモリの設定のみが実際に有効であり、ディスクやIOPSなどの他のIOパラメータは一時的に無効となり、デフォルトで十分です。</p>
   </main>

### stop serverの実行

`sys` テナントのキューが積み残された場合、`stop server` を実行してRS/SYSテナントが存在するマシンを隔離することができます。

```sql
obclient> ALTER SYSTEM STOP SERVER "xx.xx.xx.xx:2882";
```

### 問題ノードの再起動

問題のあるRSが存在するOBノードを再起動します。詳細については、[OBServerノードの再起動](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000002101077)を参照してください。
