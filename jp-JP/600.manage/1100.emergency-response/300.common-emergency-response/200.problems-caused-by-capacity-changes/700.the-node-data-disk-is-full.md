# ノードのデータディスク容量がいっぱいになった

OceanBaseのデータディスク容量がいっぱいになることは一般的ではありませんが、満杯になるとダンプできない、メジャーコンパクションできない、メモリを解放できないといった問題が発生し、結果としてクラスタへの書き込みができなくなります。

## 緊急対応の手順

データディスク容量がいっぱいになった場合の対処法は以下の通りです：

1. 複数のテナントが分散配置されているOBノードについては、まずノードの拡張とUnitの移行によるデータの均等化を検討します。

   * ノードの拡張

     ノードの拡張はOCPのページ操作またはコマンドライン操作を使用できます。具体的な手順については、[ノードの追加](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000002100824)を参照してください。

   * Unitを拡張ノードへ手動で移行する。

     OCPを使用した手動移行では、Unitの仕様をダブルクリックしてリソースの移行操作を行います。具体的な手順については、[Unitの分布の確認](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000002099463)を参照してください。移行は単一ゾーン内でのみ可能です。

2. Unitの移行やノード拡張によるデータ均等化が一時的にできない場合は通常、以下の方法で緊急対応します。

   * OceanBaseクラスタのディスク最大容量の割合を引き上げる。

     ```sql
     ALTER system SET datafile_disk_percentage = 98;
     ```

     このパラメータのデフォルト値は`90`です。緊急時に値を引き上げることで、一時的に容量を確保できます。

   * 削除可能なデータ、テーブル、冗長インデックスなどを削除し、リサイクルビンのデータを空にします。リサイクルビンのデータはクリーンアップ後はリストアできません。データのクリーンアップは、必ず内容をよく確認したうえで実行してください。
