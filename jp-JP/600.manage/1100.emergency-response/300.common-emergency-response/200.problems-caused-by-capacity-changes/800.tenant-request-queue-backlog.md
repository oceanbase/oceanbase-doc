# テナントリクエストキューのバックログ

OceanBaseはマルチテナントデータベースクラスタであり、テナント間ではスレッドとコルーチンを通じてCPUリソースが割り当て・スケジュールされます。クラスタのテナントリクエスト量が増加したり、複雑なクエリ処理やCPUリソース不足が発生すると、キューによるリクエストのバックログが生じます。主な現象として、SQLの応答時間が長くなったり、処理応答速度が遅くなったりします。本記事では、このような状況に対処する緊急対応方法について説明します。

## 緊急対応方法

現在のクラスタ内のテナントでキューによるリクエストバックログが発生した場合、以下のいくつかの側面から対処を開始できます：

1. テナントのCPUリソースを拡張するか、負荷の少ないマシンへのプライマリ切り替えを試みます。

   テナント内のCPU拡張は、`UNIT_CONFIG`や`UNIT_NUM`を変更することで実現できます。OCPを使用して操作を実行することを推奨します。コマンドラインでの操作手順は以下のとおりです：

   i. 以下のSQLステートメントを実行し、現在のテナントが使用している`unit_config`を確認します。

      <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>複数のレプリカが異なる<code>resource_pool</code>を使用している可能性があります。個別に調整する必要があります。</p>
      </main>

      ```sql
      SELECT a.tenant_name,a.tenant_id,b.name unit_config,c.name pool_name,b.max_cpu,b.min_cpu
      FROM
      OCEANBASE.DBA_OB_TENANTS a,
      OCEANBASE.DBA_OB_UNIT_CONFIGS b,
      OCEANBASE.DBA_OB_RESOURCE_POOLS c
      WHERE a.tenant_id=c.tenant_id
      AND b.unit_config_id = c.unit_config_id
      ORDER BY a.tenant_id desc;
      ```

   ii. 生成されたSQLステートメントを実行します。

      <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>OceanBase V3.2バージョンまで、<code>resource unit</code>設定の変更では、CPUとメモリの設定のみが実際に有効になります。その他のI/Oパラメータ（例：ディスク、IOPSなど）は一時的に無効となり、デフォルト設定で問題ありません。</p>
      </main>

      ```sql
      ALTER RESOURCE UNIT unit_config_name min_cpu=2,max_cpu=2,memory_size ='2G',max_iops=10000,min_iops=10000;
      ```

2. ユニット数の多いテナントについては、クラスタレベルでの拡張は、ゾーン内にOBServerノードを追加し、その後`unit_num`を増やすことで実現できます。

3. 実行回数に異常な急増が見られるSQLを特定し、業務部門と確認のうえで実行制限をかけます。

   1. 実行回数に急増が見られるSQLを判断します。

      OCPのSQL診断機能を参考に、SQLの履歴実行傾向を確認し、実行回数オプションを選択することで、指定された期間内の特定のSQLの実行回数の傾向を確認できます。

   2. SQLの実行を制限します。

      SQLの実行計画にhint max_concurrentを追加することで、SQLの並列処理を制限し、SQLの実行を制限します。例：

      ```sql
      CREATE OUTLINE outline_name ON sql_id USING HINT /*+max_concurrent(1)*/;
      ```
