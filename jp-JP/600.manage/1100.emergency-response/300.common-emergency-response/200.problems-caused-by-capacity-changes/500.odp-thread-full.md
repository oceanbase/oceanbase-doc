# ODPスレッド満杯

obproxyのデフォルトのスレッドパラメータは8192です。アプリケーションからの接続リクエスト数がこの値を超えると、接続拒否として表れます。この記事では、obproxyのスレッドが満杯になった場合の対処方法について説明します。

## 緊急時の対応フロー

obproxyのスレッドが満杯になる状況は一般的には発生しにくいですが、発生した場合は通常以下の2つのケースに基づいて対処します。

* 集中式デプロイメントのODPクラスタを使用する場合。

  集中式デプロイメントのODPクラスタを使用している場合、スレッドが満杯になった場合は、ODPクラスタの拡張を検討し、新たに追加されたODPノードでアプリケーションの接続リクエストを分散させることが一般的です。OCPでobproxyノードを拡張する手順は以下の通りです：

  1. OCPにログインします。

  2. 左側のナビゲーションバーで**OBProxy**をクリックします。

  3. クラスタリストから操作対象のOBProxyクラスタを選択し、OBProxyクラスタの概要ページに移動します。

  4. **OBProxyの追加**をクリックします。

  5. ポップアップウィンドウで**ソフトウェアバージョン、データセンター、SQLポート、Exporter、マシンタイプ、マシン選択方法、ホスト**などの情報を入力します。

  6. **OK**をクリックします。

  詳細については、[OBProxyの追加](../../../../700.reference/1200.database-proxy/200.obproxy-management/300.manage-obproxy/100.add-obproxy.md)を参照してください。

* スポットデプロイメントのobproxy、または現在ノードを拡張できないODPクラスタの場合

  スポットデプロイメントのobproxyノードを使用している場合、スレッドが満杯になった場合は、一時的に最大接続スレッド数を引き上げて現在の問題を解決することを検討できます。OCP内でobproxyクラスタの構成パラメータを直接変更します。詳細については、OCP使用ガイドを参照してください。
