# ODPスレッド満杯

obproxyのデフォルトスレッドパラメータは8192個です。アプリケーションからの接続要求数がこの値を超えると、接続拒否として表れます。このセクションでは、obproxyのスレッドが満杯になった場合の対処方法について説明します。

## 緊急時の対応フロー

obproxyのスレッドが満杯になることは一般的ではありませんが、発生した場合は通常、以下の2つのケースに基づいて対処します。

* 集中式デプロイメントのODPクラスタを使用している場合。

  集中式デプロイメントのODPクラスタを使用している場合、スレッドが満杯になった場合は、通常、ODPクラスタの拡張を検討します。新しいODPノードを追加することで、アプリケーションの接続要求を分散します。OCPでobproxyノードを拡張する手順は以下のとおりです：

  1. OCPにログインします。

  2. 左側のナビゲーションバーで**OBProxy**をクリックします。

  3. クラスタリストから操作対象のOBProxyクラスタを選択し、OBProxyクラスタの概要ページに移動します。

  4. **<UI-TERM key="ocp-v2.Detail.Overview.AddObproxy">OBProxyを追加する</UI-TERM>**をクリックします。

  5. ポップアップウィンドウで、**ソフトウェアバージョン、データセンター、SQLポート、Exporter、マシンタイプ、マシン選択方法、ホスト**などの情報を入力します。

  6. **<UI-TERM key="oms-v2.pages.EndpointPublic.Confirmation">確定</UI-TERM>**をクリックします。

  詳細については、[OBProxyの追加](../../../../700.reference/1200.database-proxy/200.obproxy-management/300.manage-obproxy/100.add-obproxy.md)を参照してください。

* ポイントツーポイントデプロイメントのobproxy、または現在ノードを拡張できないODPクラスタの場合

  ポイントツーポイントデプロイメントのobproxyノードを使用している場合、スレッドが満杯になった場合は、一時的に最大接続スレッド数を引き上げて現在の問題を解決することを検討できます。OCPで直接obproxyクラスタの構成パラメータを変更します。詳細については、OCPの使用ガイドを参照してください。
