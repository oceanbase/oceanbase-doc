# ノードのログディスク(Clog)容量がいっぱい

Clogログディスクの容量がいっぱいになると、クラスタは通常、レプリカ不在による選挙の行われない状態、書き込み失敗、レプリカ不足などの現象を示します。

## シナリオの概要

業務によるデータ書き込みが失敗し、調査の結果、バックグラウンドのclogログディスクが満杯であることが判明しました。

## 緊急対応の手順

クラスタデータの一貫性を損なわない前提で、clogディスクの容量満杯問題を解決するには、一般的に以下の手順に従う必要があります：

1. テナントの書き込みを積極的に停止し、clogディスクが一時的に空けた容量が業務の書き込みによって再びすぐに満杯になり、修復不能になるのを防ぎます。

2. クラスタの書き込みを停止した後、clogディスクのしきい値比率を一時的に引き上げ、95%から98%に調整します。

   ```sql
   ALTER system SET log_disk_utilization_limit_threshold  = 98 server ='[IPアドレス]:2882';
   ```

3. 一定期間観察します。ほとんどの場合、clogが追いつくとクラスタは回復します。回復しない場合は、OceanBaseテクニカルサポートにお問い合わせください。
