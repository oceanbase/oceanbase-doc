# ノードのログディスク(Clog)容量がいっぱいです

Clogディスクの容量がいっぱいになると、クラスタは通常、リーダー不在の選挙、書き込み失敗、レプリカ不足などの現象を示します。

## シナリオの概要

業務によるデータ書き込みが失敗し、調査の結果、バックグラウンドのClogディスクが満杯であることが判明しました。

## 緊急対応の手順

クラスタデータの一貫性を損なわない前提で、Clogディスクの容量不足問題を解決するには、一般的に以下の手順に従う必要があります：

1. テナントの書き込みを積極的に停止し、Clogディスクが一時的に空けた容量が、業務の書き込みによって再びすぐに満杯になり、修復不能になるのを防ぎます。

2. クラスタの書き込みを停止した後、Clogディスクのしきい値比率を一時的に引き上げ、95%から98%に調整します。

   ```sql
   ALTER system SET log_disk_utilization_limit_threshold  = 98 server ='[IPアドレス]:2882';
   ```

3. しばらく観察します。ほとんどの場合、Clogが追いついた後、クラスタは回復します。回復しない場合は、OceanBaseテクニカルサポートにお問い合わせください。
