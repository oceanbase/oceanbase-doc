# ストレージレイヤーによる行数推定

統計情報の収集は実行計画生成の前に発生するため、統計情報を収集した後にも大量の増分・削除・変更操作が発生し、また適時に統計情報を再収集しない場合、計画生成時に古い統計情報が使用され、正確な行数推定ができず、最適な実行計画を選択できない可能性があります。この問題を解決するために、OceanBaseデータベースのオプティマイザーはリアルタイムでストレージレイヤーによる行数推定メカニズムをサポートしており、よりリアルタイムかつ正確な統計情報を取得できます。

計画生成時には、テーブルのインデックスに基づいて複数のベーステーブルスキャンパスを生成します。これを「ベーステーブルパス」と簡略化して呼びます。OceanBaseデータベースのストレージレイヤーでは、インデックスはすべてツリー構造として存在するため、計画生成時に各ベーステーブルパスに対して、テーブルの述語条件に基づいて複数のクエリ範囲（QUERY RANGE）を生成します。これにより、特定のデータ領域を迅速にスキャンして無駄なデータスキャンを回避できます。この特性に基づき、OceanBaseデータベースのオプティマイザーは計画生成時にベーステーブルパス上の関連するQUERY RANGEを事前にストレージレイヤーに送信し、ストレージレイヤーがクエリ範囲の合計行数を高速に推定してオプティマイザに返します。この過程でオプティマイザーはリアルタイムかつ正確な行数を得ることができます。これがストレージレイヤーによる行数推定です。

ただし、すべてのQUERY RANGEとパーティションがストレージレイヤーによる行数推定に使用されるわけではありません。ストレージレイヤーによる行数推定は比較的時間がかかる操作であり、計画生成全体の時間消費を考慮して、以下の2つの制限が設けられています：

* ベーステーブルパス上のQUERY RANGEの数が多くなると、システム変数`range_index_dive_limit`を超えると、ランダムに選択された対応するシステム変数個数のQUERY RANGEのみをストレージレイヤーによる行数推定に使用します。
* パーティションテーブルのパーティションカット後のパーティション数が多くなると、システム変数`partition_index_dive_limit`を超えると、ランダムに選択された対応するシステム変数個数のパーティションのみをストレージレイヤーによる行数推定に使用します。

注意すべき点として、ストレージレイヤーによる行数推定はベーステーブルパスにのみ適用され、JOINやGROUP BYなどの他の演算子には適用されません。
