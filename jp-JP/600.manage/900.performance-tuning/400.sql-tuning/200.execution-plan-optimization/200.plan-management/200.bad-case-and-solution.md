# プランキャッシュの欠点と解決策

## プランキャッシュの欠点

前節で述べたように、パラメータ化されたSQL文に対して実行計画が生成されると、その計画はプランキャッシュに保存され、以降のSQL実行はすべてこの実行計画をヒットします。このような計画の再利用方式は、計画生成時間を節約できますが、データの偏りがある場合には悪いケースが隠れています。ここでは例を挙げて説明します。

テーブル`t1`の定義は以下のとおりです。`c1`列には2種類の値しかなく、そのうち値`0`が全データの1％を占め、値`1`が全データの99％を占めていると仮定します。また、`c2`列には1から10までの合計10種類の値があり、それぞれの値が10％ずつを占めています。したがって、`SELECT * FROM t1 WHERE c1 = ? AND c2 = ?`というSQL文について、計画生成時にオプティマイザーが見た条件が`c1 = 0 and c2 = 1`である場合、オプティマイザーはインデックス`idx1`を選択し、まずインデックスから`c1 = 0`を満たす1％のデータを照会し、その後インデックスからテーブルにアクセスして`C2 = 1`で条件を満たさないデータをフィルタリングして返します。この場合、1％のデータをスキャンしてインデックスから1％のデータをテーブルに戻すだけでクエリが完了します。しかし、その後サーバーが別のSQL文を受信し、ユーザーが指定した条件が`c1 = 1 and c2 = 1`に変わった場合、以前に生成された計画を再利用すると、まずインデックス`idx1`から`C1 = 1`を満たす99％のデータを照会し、その後インデックスからテーブルにアクセスして`C2 = 1`で条件を満たさないデータをフィルタリングして返します。この場合、99％のデータをスキャンしてインデックスから99％のデータをテーブルに戻す必要があり、クエリを完了するためには99％のデータをスキャンする必要があります。明らかにこのSQL文に対しては、インデックス`idx2`を使用する方が良い選択です。なぜなら、どのような値を取る場合でも、`idx2`を使用すると常に10％のデータをスキャンして10％のデータをテーブルに戻すだけで済むため、SQLの実行時間がより安定するからです。

```
create table t1 (
  c1 int,
  c2 int,
  c3 int,
  key idx1 (c1),
  key idx2 (c2)
);
```

このような状況に遭遇した場合、ユーザーはoutlineを使用してSQLに実行計画をバインドし、このクエリリクエストが`idx2`インデックスを使用するよう強制できます。もちろん、このSQLに対しては実際にはもっと良い最適化方法がありますが、これは本記事の議論の重点ではないため、詳しくは触れません。

## プランバインディング

プランバインディングとは、OceanBaseデータベースが提供する、SQLを変更することなく、データベース内にoutlineを作成することで実行計画を制御できる仕組みです。現在、OceanBaseデータベースでは2種類のoutline作成方法が提供されており、構文は以下のとおりです。

```
/* SQL_TEXTを使用してOutlineを作成 */
CREATE [OR REPLACE] OUTLINE outline_name ON stmt [ TO target_stmt ]

/* SQL_IDを使用してOutlineを作成 */
CREATE [OR REPLACE] OUTLINE outline_name ON sql_id USING HINT hint;
```

上記のSQLについて、以下の方法でoutlineを作成し、OceanBaseデータベースがこのSQLを実行する際にインデックス`idx2`を使用するように求めることができます。注意が必要なのは、OceanBaseデータベースは2つのパラメータ化されたSQLが同一であるかどうかを判断する際に、スペースや大文字・小文字を無視しないため、`SQL_TEXT`方式でoutlineを作成すると、`create outline`ステートメントに記述されたSQLと実際に実行されるSQLが完全に一致しない可能性が高く、その結果outlineがバインドできなくなる問題が発生しやすいということです。そのため、`SQL_ID`方式でoutlineを作成することを推奨します。

```
/* SQL_TEXT方式 */
CREATE OUTLINE otl_idx2 ON SELECT/*+ index(T1 idx2)*/ * FROM t1 WHERE c1 = 1 AND c2 = 1;

/* SQL_ID方式 */
CREATE OUTLINE otl_idx2 ON '27F4FC32407331073407EAA24F5E5FA4'
USING HINT /*+ index(T1 idx2)*/ ;
```
