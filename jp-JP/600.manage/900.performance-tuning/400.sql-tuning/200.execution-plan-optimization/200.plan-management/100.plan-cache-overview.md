# プランキャッシュの概要

OceanBaseデータベースには多数のリライトルールと複雑なプラン生成アルゴリズムが存在し、これらはOceanBaseデータベースに強力な最適化能力をもたらしています。しかし、すべてのことは二面性を持っています。より多くのリライト試行やより複雑なプラン生成アルゴリズムは、必然的にプラン生成にかかる時間を長くする結果となります。極端なTPシナリオでは、主キー単一ポイントクエリのSQLがプラン生成に1msを要するかもしれませんが、その実行にはわずか0.5msで済む場合もあります。このような状況下で、各SQL実行時に毎回プランを再生成すると、SQLの主な処理時間の大半がプラン生成に費やされてしまいます。そのため、OceanBaseデータベースは同じSQLが共有できるように、実行プランをキャッシュする「プランキャッシュ」メカニズムを導入しました。

## プランキャッシュ

OceanBaseデータベースがSQLリクエストを受けると、まずfast parserモジュールを使用してSQLテキストを一度高速パラメータ化します。高速パラメータ化とは、SQLテキスト内の定数パラメータをワイルドカード`?`に置き換える処理です。例えば、`SELECT * FROM t1 WHERE c1 = 1`は`SELECT * FROM t1 WHERE c1 = ?`に置き換えられます。次に、データベースはこのパラメータ化されたSQLに対して、既に生成済みのプランがプランキャッシュに存在するかどうかを確認します。見つかった場合は、そのプランを直接実行します。見つからない場合は、新しいSQL用の実行プランを生成し、生成したプランをプランキャッシュに保存して、後続のSQLで利用できるようにします。通常、プランキャッシュから直接取得する実行プランは、再生成するよりも少なくとも1桁程度の時間短縮が期待でき、そのためプランキャッシュを利用することで、実行プランの取得時間を大幅に短縮し、SQLの応答時間を削減することができます。
