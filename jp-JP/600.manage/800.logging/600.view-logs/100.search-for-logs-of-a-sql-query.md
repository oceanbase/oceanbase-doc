# 特定のSQLリクエストのログを検索する

OceanBaseデータベースは、特定のSQLリクエストに関連するログを検索する機能をサポートしています。ただし、現在のシステムログレベルや具体的なSQL例外シナリオによって制限されるため、ログファイル内で対応するSQLリクエストのログが必ず見つかるとは限りませんが、試してみる価値は常にあります。

特定のSQLリクエストのログを検索することは、可観測性の分野において非常に有用な技術です。基本的な技術ポイントは、ノードIPアドレスとTRACE_IDを用いてログファイルからログを検索し、手がかりを捉え、それをたどってフルリンクを通じて最初の発見現場を特定することです。その特徴は、「事後」および「フルリンク」という2つの属性を備えている点にあり、モニタリング指標の強力な補完となります。モニタリング指標は異常の検出に長けており、一方でシステムログは詳細やフルリンク追跡に優れています。

## 手順

1. OceanBaseクラスタにログインし、以下のSQLを実行します。このSQLはエラーを返します。

    ```shell
    obclient> select timestamp'0001-01-33';
    ERROR 1525 (HY000): Incorrect DATETIME value: '0001-01-33'
    ```

    <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>ここで実行するSQLは示すためのものであり、実際の業務では通常アプリケーションシステムがSQLを実行します。場合によっては、エラーコードの返却や高い処理時間などの異常が発生することがあります。その際は、アプリケーション担当者が運用担当者に連絡し、問題の特定を支援してもらいます。</p>
    </main>

2. システムテナントにログインし、`GV$OB_SQL_AUDIT`ビューを使用して、このSQLの実行情報を照会します。

    <main id="notice" type='notice'>
    <h4>注意</h4>
    <p><code>GV$OB_SQL_AUDIT</code>から結果が取得できない場合は、audit機能が無効になっているかどうか確認してください。つまり、<code>enable_sql_audit</code>構成パラメータが<code>False</code>に設定されているかどうかを確認してください。<code>enable_sql_audit</code>構成パラメータの詳細については、<a href="../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/8800.enable_sql_audit.md">enable_sql_audit</a>を参照してください。</p>
    </main>

    ```
    SVR_IP: xx.xx.xx.158

    ```

3. 対象ノードにログインし、`TRACE_ID`を使用してログファイルを検索します。

    ```
    [hellodba@xx.xx.xx.158 /home/admin/oceanbase/log]
    $ grep 'YB4206019C9E-0005F55950FFAF04-0-0' observer.log
    [2023-03-12 14:47:40.670100] WARN  resolve_const (ob_resolver_utils.cpp:2420) [116987][T1_TNT_L0_G0][T1][YB4206019C9E-0005F55950FFAF04-0-0] [lt=21] Incorrect DATETIME value: '0001-01-33'
    [2023-03-12 14:47:40.670205] WARN  resolve_const (ob_resolver_utils.cpp:2420) [116987][T1_TNT_L0_G0][T1][YB4206019C9E-0005F55950FFAF04-0-0] [lt=37] Incorrect DATETIME value: '0001-01-33'
    ```

    <main id="notice" type='notice'>
    <h4>注意</h4>
    <p><code>observer.log</code>で関連ログがgrepできない場合は、<code>observer.log</code>ファイルが切り替わった可能性があります。その場合は、<code>grep YB4206019C9E-0005F55950FFAF04-0-0 observer.log.*</code>と入力してください。</p>
    </main>

    `TRACE_ID`に関連するログを検索することは最初のステップに過ぎず、真の目的は綿密な分析にあります：

    * ログのコンテキスト、OSメトリクス、OSイベントなど、多角的な指標を組み合わせて、このノードを分析します。
    * `TRACE_ID`に対応するRPC呼び出しを通じて、他のOceanBaseノード、ODPノード、アプリケーションノードをつなぎ合わせ、エンドツーエンドで分析します。
