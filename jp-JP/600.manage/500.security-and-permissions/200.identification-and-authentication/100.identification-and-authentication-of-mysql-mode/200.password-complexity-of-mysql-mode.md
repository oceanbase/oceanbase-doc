# パスワードの複雑さ

悪意のあるパスワード攻撃を防ぐため、OceanBaseデータベースではユーザーが必要に応じてパスワードの複雑さを検証する関数を設定し、ログインするユーザーの本人確認を行うことで、データベースのセキュリティを向上させることができます。本記事では、OceanBaseデータベースのログインユーザーのパスワードの複雑さを設定する方法について説明します。

## 関連変数の紹介

OceanBaseデータベースのMySQLモードでは、一連のシステム変数を設定することでパスワードの複雑さのルールを定義できます。これらの設定はテナントレベルです。ユーザー作成時やユーザーパスワードの変更時に、システム変数の設定に基づいてパスワードが検証され、検証に失敗するとエラーが表示されます。関連するシステム変数は以下の表のとおりです。

|   変数名   |    機能  |   使用方法    |
|------------|---------|--------------|
|   validate_password_check_user_name   |ユーザーのパスワードをユーザー名と同じにできるかどうかを指定します。|<ul><li>`on`：ユーザーのパスワードはユーザー名と同じにできません。</li><li>`off`：ユーザーのパスワードはユーザー名と同じにできます。デフォルト値は`off`です。</li></ul>|
|validate_password_length|ユーザーパスワードの最小文字数を設定します。|デフォルト値は0です。|
|validate_password_mixed_case_count|ユーザーパスワードに含まれる大文字と小文字の最小文字数を設定します。|デフォルト値は0です。|
|validate_password_number_count|ユーザーパスワードに含まれる数字の最小文字数を設定します。|デフォルト値は0です。|
|validate_password_policy|パスワード検証ポリシーを設定します。| <ul><li>`low`：パスワードの長さのみを検証します。</li><li>`medium`：パスワードの長さ、大文字・小文字・数字・特殊文字の数、およびユーザー名とパスワードが同一かどうかを検証します。</li></ul>|
|validate_password_special_char_count|ユーザーパスワードに含まれる特殊文字の最小文字数を設定します。|デフォルト値は0です。|

上記のシステム変数で制御される複雑さのルールに加えて、OceanBaseデータベースは平文パスワードの最大長を128バイトに制限しています（バイト単位で計算し、中国語の漢字は通常3バイトを占めます）。`CREATE USER` ステートメントの `IDENTIFIED BY` 句で指定されたパスワードの長さがこの上限を超えると、ステートメントの実行は失敗し、`ERROR 1235 (0A000): create a user with an excessively long password not supported` エラーが発生します。現在、この長さの検証は `CREATE USER` ステートメントでのみ実行され、`ALTER USER`、`SET PASSWORD` などのパスワード変更ステートメントはこの制限を受けません。

## パスワードの複雑さの設定

<main id="notice" type='notice'>
    <h4>注意</h4>
    <p>本番環境では、パスワードの総文字数を20文字に設定し、数字、大文字、小文字、特殊文字を含めることを推奨します。パスワードの複雑さが低いほど、例えばユーザー名を含む場合や繰り返しの文字を使用する場合などは、解読される可能性が高くなります。セキュリティ上の理由から、ユーザーのパスワードは高い複雑さを持たせる必要があります。
    </p>
  </main>

このセクションでは、パスワードの最小文字数を8文字とし、大文字3文字以上、小文字3文字以上、特殊文字1文字以上を含め、ユーザー名と同じパスワードを禁止し、検証ポリシーを`medium`に設定する例を用いて、パスワードの複雑さを設定する手順を説明します。

1. rootユーザーとしてクラスタのMySQLテナントにログインします。

    ```shell
    obclient -uroot@mysql -P2881 -h10.xxx.xxx.1 -p*******
    ```

2. システム変数を使用してパスワードの複雑さを設定します。

    ```shell
    obclient> SET GLOBAL validate_password_check_user_name=on;
    obclient> SET GLOBAL validate_password_length=8;
    obclient> SET GLOBAL validate_password_mixed_case_count=3;
    obclient> SET GLOBAL validate_password_special_char_count=1;
    obclient> SET GLOBAL validate_password_policy='medium';
    ```

3. 終了後再ログインし、変数が有効になっているか確認します。

    ```shell
    obclient> SHOW VARIABLES LIKE 'validate%';
    +--------------------------------------+--------+
    +--------------------------------------+--------+
    | VARIABLE_NAME                        | VALUE  |
    +--------------------------------------+--------+
    | validate_password_check_user_name    | off     |
    | validate_password_length             | 8      |
    | validate_password_mixed_case_count   | 3      |
    | validate_password_number_count       | 0      |
    | validate_password_policy             | medium |
    | validate_password_special_char_count | 1      |
    +--------------------------------------+--------+
    6 rows in set (0.00 sec)
    ```

4. パスワードの複雑さを検証します。

    2つのユーザーを作成し、それぞれ要件を満たすパスワードと満たさないパスワードを設定します。

    ```shell
    obclient> CREATE USER sectest1 IDENTIFIED BY '******';
    ERROR 1819 (HY000): Your password does not satisfy the current policy
    requirements

    obclient> CREATE USER sectest1 IDENTIFIED BY '***1_%';
    Query OK, 0 rows affected
    ```

    設定したパスワードの複雑さが要件を満たさない場合、ユーザーの作成は失敗します。
