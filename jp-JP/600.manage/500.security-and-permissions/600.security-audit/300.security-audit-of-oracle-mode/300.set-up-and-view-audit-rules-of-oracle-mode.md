# 監査ルールの設定と確認

セキュリティ監査を有効にした後、ユーザーの操作を監査するために具体的なセキュリティ監査ルールを設定する必要があります。

## 監査ルールの設定

`ORAAUDITOR` ユーザーでOracleテナントにログインします。組み込みの監査管理ユーザー `ORAAUDITOR` を使用して、以下の監査ルールを設定できます：

* ステートメント監査：特定の操作を監査します。具体的なオブジェクトは指定せず、特定のユーザーまたはすべてのユーザーに適用することができます。
* オブジェクト監査：特定のオブジェクト上で実行される特定の操作を監査します。特定のユーザーまたはすべてのユーザーに適用することができます。

監査ルールはDDLステートメント `audit/noaudit` で設定され、監査ルール自体もスキーマオブジェクトです。

監査ルールの設定に関する詳細は、[AUDIT](../../../../700.reference/500.sql-reference/100.sql-syntax/300.common-tenant-of-oracle-mode/900.sql-statement-of-oracle-mode/300.dcl-of-oracle-mode/200.audit-of-oracle-mode.md)を参照してください。

例えば、ユーザー `user1` のテーブル `tbl1` に対するすべてのINSERT、UPDATE、DELETE操作を監査する場合：

```shell
obclient> AUDIT INSERT,UPDATE,DELETE ON user1.tbl1;
```

## 監査ルールの確認

監査ルールを設定した後、一連のOracle互換データディクショナリビューを使用して監査ルールの情報を確認できます。

| ディクショナリビュー     |  機能説明   |
|-----------|--------|
| [ALL_DEF_AUDIT_OPTS](../../../../700.reference/700.system-views/500.system-view-of-oracle-mode/200.dictionary-view-of-oracle-mode/1000.all_def_audit_opts-of-oracle-mode.md)  | 新規作成されたオブジェクトのデフォルト監査ルールを記録します。各列の値は以下のとおりです：<ul><li>  <code>-/-</code>：デフォルトで監査なし </li><li> <code>A/-</code>: ステートメントが正常に実行された場合にのみ監査 </li><li> <code>-/A</code>: ステートメントが失敗した場合にのみ監査 </li><li> <code>A/A</code>: ステートメントの実行が成功または失敗した場合に監査 </li></ul>  |
| [DBA_STMT_AUDIT_OPTS](../../../../700.reference/700.system-views/500.system-view-of-oracle-mode/200.dictionary-view-of-oracle-mode/20000.dba_stmt_audit_opts-of-oracle-mode.md) | ステートメントレベルの監査の詳細設定を記録します。  |
| [DBA_OBJ_AUDIT_OPTS](../../../../700.reference/700.system-views/500.system-view-of-oracle-mode/200.dictionary-view-of-oracle-mode/16900.dba_obj_audit_opts-of-oracle-mode.md)  | オブジェクトレベルの監査の詳細設定を記録します。  |

`ALL_DEF_AUDIT_OPTS` 内の監査ルールを確認します。例：

```shell
obclient> SELECT * FROM SYS.ALL_DEF_AUDIT_OPTS;
```
