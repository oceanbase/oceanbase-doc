# セキュリティ監査の有効化

一連のフィルターを通じて、特定のイベントに対するセキュリティ監査を実現します。

<main id="notice" >
  <h4>機能の適用範囲</h4>
  <p>この内容はOceanBaseデータベースEnterprise Editionにのみ適用されます。OceanBaseデータベースCommunity Editionは、現在監査機能をサポートしていません。</p>
</main>

## 監査範囲

フィルターでフィルタリングできる次元には、アカウント、イベントタイプ、イベント属性などが含まれます。各フィルターでは、フィルタリングされたイベントを監査するかどうかを選択できます。

## 使用制限と注意事項

* 式は、`SELECT` ステートメントの出力列（select item）に直接かつ一意に配置する必要があり、親式（parent expr）の制限はありません。
* 式はサブクエリ内に記述できません。
* フィルターを定義した後、ユーザーに設定して初めて有効になります。
* フィルターとユーザーは1対多の関係です。つまり、1つのフィルターを複数のユーザーに設定できますが、1人のユーザーには1つのフィルターしか設定できません。
* 接続の確立時に、現在のセッションがどの監査フィルター（Audit Filter）を使用するかが決定され、その後のセッションのライフサイクル全体で変更されません。

## フィルターの作成

フィルターを作成してMySQLテナントの監査モードを有効にします。フィルターは監査イベントタイプの選択的なフィルタリングをサポートしており、現在は「すべてのイベントを記録する」「すべてのイベントを記録しない」「ログインとログアウトのみを記録する」の3種類から選択できます。

### 構文

[AUDIT_LOG_FILTER_SET_FILTER](../../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/400.functions-of-mysql-mode/970.audit-functions-of-mysql-mode/400.audit-log-filter-set-filter-of-mysql-mode.md) 関数（式）を使用してフィルターを作成します。コマンドは以下のとおりです：

```sql
AUDIT_LOG_FILTER_SET_FILTER('filter_name', 'definition_of_filters');
```

**各フィールドの説明は以下のとおりです：**

| フィールド | 説明 |
|------|-----|
| filter_name           | フィルター名を指定するために使用します。 <main id="notice" type='explain'><h4>説明</h4><p><code>AUDIT_LOG_FILTER_SET_FILTER</code>は<code>CREATE OR REPLACE</code>のセマンティクスを持ち、既存のオブジェクトに対してDDLを実行すると上書きされます。</p></main> |
| definition_of_filters | 監査フィルターの具体的な設定を定義するために使用し、JSON形式で記述します。現在のバージョンのフィルター設計方針はMySQLと互換性がありますが、監査イベントタイプのフィルタリングのみをサポートしています。|

現在、サポートされているフィルター設定のタイプは以下のとおりです：

* すべてのイベントを記録します。

    ```sql
    {
    "filter": {
        "log": true
    }
    }
    ```

    または

    ```sql
    {
    "filter": {
        "log": true,
        "class": [
        { "name": "connection" },
        { "name": "general" },
        { "name": "table_access" }
        ]
    }
    }
    ```

* すべてのイベントを記録しません。

    ```sql
    {
    "filter": {
        "log": false
    }
    }
    ```

* ログインとログアウトのみを記録します。

    ```sql
     {
    "filter": {
        "log": true,
        "class": [
        { "name": "connection" }
        ]
    }
    }
    ```

**監査イベントの分類は以下のとおりです：**

|    イベントタイプ   | 説明 |
|--------------|------|
| connection   | ログイン/ログアウト。|
| table_access | DMLステートメント。|
| general      | cmdステートメント、parserエラー。|

### 例

すべてのイベントを記録するフィルター `log_all` を作成します。

```shell
obclient [test]>SELECT AUDIT_LOG_FILTER_SET_FILTER('log_all', '{ "filter": { "log": true } }');
```

* DDLが正常に実行された場合、式は `OK` を返します。

    ```shell
    +-------------------------------------------------------------------------+
    | AUDIT_LOG_FILTER_SET_FILTER('log_all', '{ "filter": { "log": true } }') |
    +-------------------------------------------------------------------------+
    | OK                                                                      |
    +-------------------------------------------------------------------------+
    1 row in set
    ```

* DDLが失敗した場合、`SELECT` ステートメントは正常に実行されますが、式の出力結果はエラーメッセージとなります。

    ```shell
    obclient [test]>SELECT AUDIT_LOG_FILTER_SET_FILTER('log_err', '1');
    ```

    実行結果は次のとおりです：

    ```shell
    +---------------------------------------------+
    | AUDIT_LOG_FILTER_SET_FILTER('log_err', '1') |
    +---------------------------------------------+
    | ERROR: JSON parsing error.                  |
    +---------------------------------------------+
    1 row in set
    ```

[mysql.audit_log_filter](../../../../700.reference/700.system-views/400.system-view-of-mysql-mode/200.dictionary-view-of-mysql-mode/3170.mysql-audit_log_filter-of-mysql-mode.md) ビューで監査フィルターの定義を確認します。

```shell
obclient [test]> select * from mysql.audit_log_filter;
```

実行結果は次のとおりです：

```shell
+---------+-------------------------------+
| NAME    | FILTER                        |
+---------+-------------------------------+
| log_all | { "filter": { "log": true } } |
+---------+-------------------------------+
1 row in set (0.003 sec)
```

**各フィールドの説明は以下のとおりです：**

| **フィールド名** | **説明**   |
|--------------|------------|
| NAME   | フィルター名 |
| FILTER | フィルター定義 |

## フィルターの設定

フィルターを設定して対象のユーザーに割り当てて初めて、バックグラウンドスレッドが監査ログを出力できます。

### 構文

[AUDIT_LOG_FILTER_SET_USER](../../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/400.functions-of-mysql-mode/970.audit-functions-of-mysql-mode/500.audit-log-filter-set-user-of-mysql-mode.md) 関数（式）を使用して、ユーザーにフィルターを設定します。

```sql
AUDIT_LOG_FILTER_SET_USER('user_name', 'filter_name');
```

**各フィールドの説明は以下のとおりです：**

| フィールド | 説明 |
|------|-----|
| user_name   | ユーザー名を指定するために使用されます。<main id="notice" type='explain'><h4>説明</h4><p><code>AUDIT_LOG_FILTER_SET_USER</code>で指定する<code>user@host</code>は、既存のユーザーである必要はありません。ワイルドカードや存在しないユーザーを指定することも可能です。存在しないユーザーを指定した場合、ログイン監査時に有効になります。<code>user_name</code>には以下の制限があります：<ul><li><code>user</code>はフィールド全体のみをワイルドカード(<code>%</code>)で指定できます。</li><li><code>host</code>フィールドや<code>test_%</code>のような部分的なワイルドカードの指定はサポートされていません。<code>host</code>または<code>test_%</code>を指定した場合、フィルターを作成できません。</li></ul></p></main>|
| filter_name | フィルター名を指定するために使用されます。<main id="notice" type='explain'><h4>説明</h4><p><code>AUDIT_LOG_FILTER_SET_USER</code>は<code>CREATE OR REPLACE</code>のセマンティクスを持ち、既存のオブジェクトに対してDDLを実行すると上書きされます。指定された<code>filter_name</code>が存在しない場合、DDLは有効になりませんが、エラーも報告されません。</p></main>|

### 例

フィルター `log_all` をユーザー `user001` に設定します。

```shell
obclient [test]> SELECT AUDIT_LOG_FILTER_SET_USER('user001', 'log_all');
```

* DDLが正常に実行された場合、式は `OK` を返します。

    ```shell
    +-------------------------------------------------+
    | AUDIT_LOG_FILTER_SET_USER('user001', 'log_all') |
    +-------------------------------------------------+
    | OK                                              |
    +-------------------------------------------------+
    1 row in set
    ```

* DDLの実行が失敗した場合、`SELECT` ステートメントは正常に実行されますが、式の出力結果はエラーメッセージとなります。

    ```shell
    obclient [test]>SELECT AUDIT_LOG_FILTER_SET_USER('log_err', '1');
    ```

    実行結果は次のとおりです：

    ```shell
    +--------------------------------------------+
    | AUDIT_LOG_FILTER_SET_USER('log_err', '1')  |
    +--------------------------------------------+
    | ERROR: Invalid character in the user name. |
    +--------------------------------------------+
    1 row in set (0.001 sec)
    ```

[mysql.audit_log_user](../../../../700.reference/700.system-views/400.system-view-of-mysql-mode/200.dictionary-view-of-mysql-mode/3175.mysql.audit_log_user-of-mysql-mode.md) ビューで監査フィルターとユーザーのマッピング関係を確認します。

```shell
obclient [test]> select * from mysql.audit_log_user;
```

実行結果は次のとおりです：

```shell
+---------+------+------------+
| USER    | HOST | FILTERNAME |
+---------+------+------------+
| user001 | %    | log_all    |
+---------+------+------------+
1 row in set (0.003 sec)
```

**各フィールドの説明は以下のとおりです：**

| **フィールド名** | **説明**   |
|--------------|------------|
| USER       | ユーザー名 |
| HOST       | ホスト名 |
| FILTERNAME | フィルター名 |

## 監査の有効化

パラメータ [audit_log_enable](../../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/230.audit_log_enable.md) を使用して、MySQLテナント内の監査機能を有効にします。

```shell
obclient> ALTER SYSTEM SET audit_log_enable=TRUE;
```
