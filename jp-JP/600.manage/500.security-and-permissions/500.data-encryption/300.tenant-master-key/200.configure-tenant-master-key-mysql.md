# テナントマスターキーの生成 (MySQLモード)

本記事では、MySQLモードのテナントでテナントマスターキーを生成する方法について説明します。生成後は、透過的データ暗号化(TDE)、列暗号化、関数暗号化機能を利用できます。

<main id="notice" type='notice'>
  <h4>機能の適用範囲</h4>
  <p>OceanBaseデータベースCommunity Editionは、現在テナントマスターキー関連機能をサポートしていません。</p>
</main>

## 前提条件

* MySQLモードのテナントが作成済みであること。
* 管理者ユーザーでテナントにログインしていること。

## マスターキーの生成

マスターキー生成に関する説明：

1. 透過的データ暗号化(TDE)機能を使用するには、事前にマスターキーを生成する必要があります。マスターキーの値(`tde_method`の値)は`none`以外である必要があります。ログ再生時の循環依存を回避するため、`tde_method`が`internal`に設定されている場合、TDEのclogは暗号化されません。
2. 列暗号化機能もマスターキーが`none`以外である必要があります。
3. 関数暗号化機能も、`none`以外のマスターキーを事前に生成する必要があります。
4. 上記3つの機能では、すべて`tde_method`を`obcloud`に設定することを推奨します。

以下は`obcloud`方式の例です。外部KMSサービスを使用する場合は、`tde_method`を`obcloud`に設定し、`external_kms_info`を構成してください。

1. 管理者ユーザーでクラスタのMySQLテナントにログインします。

2. 以下のステートメントを実行して、`obcloud`方式の暗号化を有効にします。

   パラメータ`tde_method`はマスターキーの格納方式を設定するために使用され、デフォルトは`none`で、暗号化が無効であることを意味します。

   パラメータ`tde_method`の詳細については、[tde_method](../../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/7800.tde_method.md)を参照してください。

   <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>パラメータ<code>tde_method</code>は一度設定すると、変更できなくなります。</p>
   </main>

   ```sql
   ALTER SYSTEM SET tde_method='obcloud';
   ```

3. 以下のステートメントを実行して、該当テナント上のすべてのOBServerノードにおけるパラメータ`tde_method`の値が`obcloud`であることを確認します。

   ```sql
   SHOW PARAMETERS LIKE 'tde_method';
   ```

4. 以下のステートメントを実行して、キーマネジメント情報を設定します。

   パラメータ `external_kms_info` の詳細については、[external_kms_info](../../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3200.external_kms_info.md) を参照してください。

   ```sql
   -- この例は参考用です。実際のキーマネジメント情報に置き換えてください。
   ALTER SYSTEM SET external_kms_info='{
            "KMS_HOST": "kms.ob.com:443",
            "ROOT_CERT": "******",
            "PRIVATE_KEY": "******",
            "PRIVATE_KEY_PHRASE": "ob2025",
            "SCENE": "ANT",
            "KEY_NAME": "ob_cluster_key",
            "CALLER": "oceanbase_admin"}';
   ```

## プライマリキーのローテーション

セキュリティを高めるため、プライマリキーを定期的にローテーションすることを推奨します。プライマリキーをローテーションした後、新しいデータは新しいキーで暗号化され、古いデータは引き続き古いキーで復号化できます。

```sql
ALTER INSTANCE ROTATE INNODB MASTER KEY;
```

* 列暗号化機能の使用：[列暗号化ルールの作成](../500.column-encryption/200.column-encryption-of-mysql-mode/200.create-column-encryption-rule-of-mysql-mode.md)を参照してください。
* 関数暗号化機能の使用：[ENHANCED_AES_ENCRYPT](../../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/400.functions-of-mysql-mode/500.encryption-and-compression-functions-of-mysql-mode/820.enhanced-aes-encrypt-of-mysql-mode.md)および[ENHANCED_AES_DECRYPT](../../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/400.functions-of-mysql-mode/500.encryption-and-compression-functions-of-mysql-mode/830.enhanced-aes-decrypt-of-mysql-mode.md)を参照してください。
