# ログストリームの変更

1つのログストリームは1つのログストリームグループに属し、各ログストリームグループ内のログストリーム数はPrimary Zone内のZone数によって決定されます。そのため、Primary ZoneのZoneリストにある各Zoneには、ログストリームグループ内の1つのログストリームのLeaderが配置されることができます。

ユーザーは必要に応じてログストリームに対する変更操作を実行し、各`UNIT_GROUP`（同種Zoneモード）/`UNIT_LIST`（異種Zoneモード）間でログストリームの分布を手動で均等化できます。

## 背景情報

現在のバージョンでは、同種Zoneモードと異種Zoneモードのテナントをサポートしています。ここで、以下の点に注意してください：

*   同種Zoneモードでは、Unit Groupを指定してログストリームを作成する必要があります。

*   異種Zoneモードでは、UNIT_LISTを指定してログストリームを作成する必要があります。

  同種Zoneモードと異種Zoneモードの詳細な違いについては、[データ分散](../300.replica-management/400.data-distribution.md)を参照してください。

## 注意事項

ログストリームの変更を操作する前に、以下の点に注意してください：

* 変更対象のログストリームは存在し、その状態が `NORMAL` でなければなりません。

* 変更対象のログストリームのテナントの状態が `NORMAL` でなければなりません。

* プライマリテナント上でログストリームの `UNIT_GROUP`（同種Zoneモード）/`UNIT_LIST`（異種Zoneモード）を変更する場合、テナント内のすべてのログストリームに現在ロードバランシングタスクがないことが必要です。

* スタンバイテナント上でログストリームの `UNIT_GROUP`（同種Zoneモード）/`UNIT_LIST`（異種Zoneモード）属性を変更することは推奨されません。スタンバイテナントはログストリームの `UNIT_GROUP`/`UNIT_LIST` 属性を自動的に調整するため、手動で変更しても反映されない可能性があるためです。

* ログストリームの `UNIT_GROUP`（同種Zoneモード）/`UNIT_LIST`（異種Zoneモード）を変更する際、ターゲット `UNIT_GROUP`/`UNIT_LIST` の状態が `ACTIVE` でなければなりません。

* ログストリームの `PRIMARY_ZONE` を変更する場合、変更後のZoneがテナントの `ZONE_LIST` に確実に含まれている必要があります。ログストリームの `PRIMARY_ZONE` の設定は、テナントの `PRIMARY_ZONE` の設定とは若干異なります。ログストリームでは `z1` または `z2` のように単一のZoneのみを指定でき、テナントのように `z1,z2`、`z1; z2`、または `RANDOM` といった複数のZoneや区切り文字を使用した指定はできません。

* ログストリームを変更する際、テナントレベルの構成パラメータ `enable_rebalance` が無効であること、つまり値が `False` でなければなりません。`enable_rebalance` が有効な場合、テナントのロードバランシングモジュールがログストリームの `PRIMARY_ZONE` および `UNIT_GROUP`（同種Zoneモード）/`UNIT_LIST`（異種Zoneモード）属性を自動的に調整する可能性があります。

* 同種Zoneモードでは、ブロードキャスト電子ストリームとシステムログストリーム（1番ログストリーム）のみが `UNIT_GROUP` の0への指定をサポートします。

* 異種Zoneモードでは、ユーザーログストリームの `UNIT_LIST` は空にすることはできません。

## ステップ１：変更前の確認

1. 管理者ユーザーがクラスタの`sys`テナントまたはユーザーテナントにログインします。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に準じてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. 変更対象のログストリームを持つテナントの状態をクエリし、テナントの状態が`NORMAL`であることを確認します。

   * システムテナント

      ```shell
      obclient> SELECT TENANT_ID, TENANT_NAME, STATUS, TENANT_ROLE FROM oceanbase.DBA_OB_TENANTS WHERE tenant_name = 'mq_t1';
      ```

   * ユーザーテナント

      :::tab
      tab MySQLモード

      MySQLモードでは、以下のコマンドを実行してテナントの状態をクエリします。

      ```shell
      obclient> SELECT TENANT_ID, TENANT_NAME, STATUS, TENANT_ROLE FROM oceanbase.DBA_OB_TENANTS;
      ```

      tab Oracleモード

      Oracleモードでは、以下のコマンドを実行してテナントの状態をクエリします。

      ```shell
      obclient> SELECT TENANT_ID, TENANT_NAME, STATUS, TENANT_ROLE FROM SYS.DBA_OB_TENANTS;
      ```

      :::

   クエリ結果の例は以下のとおりです：

   ```shell
   +-----------+-------------+--------+-------------+
   | TENANT_ID | TENANT_NAME | STATUS | TENANT_ROLE |
   +-----------+-------------+--------+-------------+
   |      1002 | mq_t1       | NORMAL | PRIMARY     |
   +-----------+-------------+--------+-------------+
   1 row in set
   ```

   クエリ結果によると、テナントの状態は`NORMAL`です。

3. テナントのログストリームに現在進行中のロードバランシングタスクがないかどうかをクエリします。プライマリテナント上でログストリームの`UNIT_GROUP`（同種Zoneモード）/`UNIT_LIST`（異種Zoneモード）を変更する場合、テナントのすべてのログストリームに現在ロードバランシングタスクがない必要があります。

   * ユーザーテナント

      :::tab
      tab MySQLモード

      MySQLモードでは、以下のコマンドを実行して、テナントのログストリームのロードバランシングタスクの状態をクエリします。

      ```shell
      obclient> SELECT count(*) AS task_cnt FROM oceanbase.DBA_OB_BALANCE_TASKS WHERE SRC_LS = 1001 or DEST_LS=1001;
      ```

      tab Oracleモード

      Oracleモードでは、以下のコマンドを実行して、テナントのログストリームのロードバランシングタスクの状態をクエリします。

      ```shell
      obclient> SELECT count(*) AS task_cnt FROM SYS.DBA_OB_BALANCE_TASKS WHERE SRC_LS = 1001 or DEST_LS=1001;
      ```

      :::

   クエリ結果の例は以下のとおりです：

   ```shell
   +----------+
   | task_cnt |
   +----------+

   +----------+
   1 row in set
   ```

   クエリ結果が`0`の場合、テナントのログストリームに現在進行中のロードバランシングタスクがないことを意味します。

      * ユーザーテナント

5. ログストリームの`UNIT_GROUP`（同種Zoneモード）/`UNIT_LIST`（異種Zoneモード）を変更する場合は、テナントのUnit情報をクエリし、ターゲット`UNIT_GROUP`（同種Zoneモード）/`UNIT_LIST`（異種Zoneモード）のデータディスクの残存容量が変更対象のログストリームを収容できることを確認する必要があります。

      ```shell

      | UNIT_GROUP_ID | UNIT_ID | ZONE | SVR_IP         | SVR_PORT |
      ```

7. 構成パラメータ`enable_rebalance`の値が`False`であるかどうかを確認します。値が`True`の場合、ログストリームの変更操作後、テナントのロードバランシングモジュールが自動的にログストリームの`PRIMARY_ZONE`および`UNIT_GROUP`（同種Zoneモード）/`UNIT_LIST`（異種Zoneモード）の属性を調整する可能性があります。

   * システムテナント

      ```shell
      obclient> ALTER SYSTEM SET enable_rebalance = 'False' TENANT = mq_t1;
      ```

   * ユーザーテナント

      ```shell
      obclient> ALTER SYSTEM SET enable_rebalance = 'False';
      ```

## ステップ2：ログストリームの変更

各項目のチェックが要件を満たしていることを確認した後、業務状況に応じて適切な操作を選択し、ログストリームを変更します。

### システムテナントによるユーザーテナントのログストリームの変更

1. `root` ユーザーでクラスタの `sys` テナントにログインします。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に準じてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. ログストリームを変更します。

   システムテナント内で、ユーザーテナントのログストリームを変更するSQLステートメントは以下のとおりです：

   ```sql
   ALTER SYSTEM MODIFY LS [=] ls_id [UNIT_GROUP [=] unit_group_id] | [UNIT_LIST [=] (unit_id_list)][, PRIMARY_ZONE [=] 'zone_name'] TENANT [=] 'tenant_name';
   ```

   ステートメントの関連説明は以下のとおりです：

   * `ls_id`：変更対象のログストリームのID。

   * `unit_group_id`：変更対象のログストリームのターゲットUnit GroupのIDを指定します。これは同種Zoneモードのテナントにのみ適用されます。`unit_group_id` はシステムテナント内で、`oceanbase.DBA_OB_UNITS` ビューをクエリすることで取得できます。

   * `unit_id_list`：変更対象のログストリームが分散するターゲットUnitリストを指定します。これは異種Zoneモードのテナントにのみ適用されます。`unit_id_list` はシステムテナント内で、`oceanbase.DBA_OB_UNITS` ビューをクエリすることで取得できます。各ZoneにつきUnitは1つまでです。

   * `zone_name`：ターゲットZoneの名前。

   * `tenant_name`：変更対象のログストリームのターゲットテナント名。

   * ログストリームの変更操作を実行する際には、少なくともログストリームのいずれかのプロパティ `UNIT_GROUP`（同種Zoneモード）/`UNIT_LIST`（異種Zoneモード）または `PRIMARY_ZONE` を変更する必要があります。

   例：

   :::tab
   tab 同種Zoneモード

   * ログストリームの `UNIT_GROUP` のみを変更する場合

      テナント `mq_t1` の1002番ログストリームの位置を1002番の `UNIT_GROUP` に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_GROUP 1002 TENANT = mq_t1;
      ```

   * ログストリームの `PRIMARY_ZONE` のみを変更する場合

      テナント `mq_t1` の1002番ログストリームLeaderの優先順位を `z1` に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 PRIMARY_ZONE 'z1' TENANT = mq_t1;
      ```

   * ログストリームの `UNIT_GROUP` と `PRIMARY_ZONE` を同時に変更する場合

      テナント `mq_t1` の1002番ログストリームの位置を1002番の `UNIT_GROUP` に変更し、ログストリームLeaderの優先順位を `z1` に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_GROUP 1002, PRIMARY_ZONE 'z1' TENANT = mq_t1;
      ```

   tab 異種Zoneモード

   * ログストリームの `UNIT_LIST` のみを変更する場合

      テナント `mq_t1` の1002番ログストリームの位置を1004、1005、1006の `UNIT_LIST` に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_LIST (1004,1005,1006) TENANT = mq_t1;
      ```

   * ログストリームの `PRIMARY_ZONE` のみを変更する場合

      テナント `mq_t1` の1002番ログストリーム Leaderの第一優先順位を `z1` に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 PRIMARY_ZONE 'z1' TENANT = mq_t1;
      ```

   * ログストリームの `UNIT_LIST` と `PRIMARY_ZONE` を同時に変更する場合

      テナント `mq_t1` の1002番ログストリームの位置を1004、1005、1006の `UNIT_LIST` に変更し、ログストリーム Leaderの第一優先順位を `z1` に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_LIST (1004,1005,1006), PRIMARY_ZONE 'z1' TENANT = mq_t1;
      ```

   :::

3. ログストリームが正常に変更されたかどうかを確認します。

   ```shell
   obclient> SELECT LS_ID, PRIMARY_ZONE, LS_GROUP_ID, UNIT_LIST FROM oceanbase.CDB_OB_LS WHERE TENANT_ID=1002 AND LS_ID = 1002 AND STATUS = 'NORMAL';
   ```

   クエリ結果の例は以下のとおりです：

   ```shell
   +-------+--------------+-------------+----------------+
   | LS_ID | PRIMARY_ZONE | LS_GROUP_ID | UNIT_LIST      |
   +-------+--------------+-------------+----------------+
   |  1002 | z1;z2,z3     |        1001 | 1004,1005,1006 |
   +-------+--------------+-------------+----------------+
   1 row in set
   ```

   変更前後のログストリームを比較し、ログストリームの `UNIT_LIST`（同種Zoneモードでは、`UNIT_GROUP_ID` が同じUnitのグループ）、`PRIMARY_ZONE` などが期待通りであれば、変更は成功したことを意味します。

### ユーザーテナントが自身のテナントのログストリームを変更する場合

1. MySQLテナントまたはOracleテナントのテナント管理者がデータベースに接続します。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に準じてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mq_t1#obdemo -p***** -A
   ```

2. ログストリームを変更します。

   ユーザーテナントがログストリームを変更するSQLステートメントは以下のとおりです：

   ```sql
   ALTER SYSTEM MODIFY LS [=] ls_id [UNIT_GROUP [=] unit_group_id] | [UNIT_LIST [=] (unit_id_list)][, PRIMARY_ZONE [=] 'zone_name'];
   ```

   ステートメントの関連説明は以下のとおりです：

   * `ls_id`：変更対象のログストリームのID。

   * `unit_group_id`：変更対象のログストリームのターゲットUnit GroupのIDを指定します。これは同種Zoneモードのテナントにのみ適用されます。`unit_group_id`はシステムテナントで、`oceanbase.DBA_OB_UNITS`ビューをクエリすることで取得できます。

   * `unit_id_list`：変更対象のログストリームを分散配置するターゲットUnitリストを指定します。これは異種Zoneモードのテナントにのみ適用されます。`unit_id_list`はシステムテナントで、`oceanbase.DBA_OB_UNITS`ビューをクエリすることで取得できます。各ZoneにはUnitを1つまで割り当てることができます。

   * `zone_name`：ターゲットZoneの名前。

   * ログストリームの変更操作を実行する際には、少なくともログストリームの1つの属性を変更する必要があります：`UNIT_GROUP`（同種Zoneモード）/`UNIT_LIST`（異種Zoneモード）または `PRIMARY_ZONE`。

   例：

   :::tab
   tab 同種Zoneモード

   * ログストリームの `UNIT_GROUP` のみを変更する場合

      1002番ログストリームの位置を1002の `UNIT_GROUP` に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_GROUP 1002;
      ```

   * ログストリームの `PRIMARY_ZONE` のみを変更する場合

      1002番ログストリームのLeaderの優先順位を `z1` に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 PRIMARY_ZONE 'z1';
      ```

   * ログストリームの `UNIT_GROUP` と `PRIMARY_ZONE` を同時に変更する場合

      1002番ログストリームの位置を1002の `UNIT_GROUP` に変更し、ログストリームLeaderの優先順位を `z1` に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_GROUP 1002, PRIMARY_ZONE 'z1';
      ```

   tab 異種Zoneモード

   * ログストリームの `UNIT_LIST` のみを変更する場合

      1002番ログストリームの位置を1004、1005、1006の `UNIT_LIST` に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_LIST (1004,1005,1006);
      ```

   * ログストリームの `PRIMARY_ZONE` のみを変更する場合

      1002番ログストリームのLeaderの優先順位を `z1` に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 PRIMARY_ZONE 'z1';
      ```

   * ログストリームの `UNIT_LIST` と `PRIMARY_ZONE` を同時に変更する場合

      1002番ログストリームの位置を1004、1005、1006の `UNIT_LIST` に変更し、ログストリームのLeaderの優先順位を `z1` に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_LIST (1004,1005,1006), PRIMARY_ZONE 'z1';
      ```

   :::

3. ログストリームが正常に変更されたかどうかを確認します。

   MySQLモードを例に、クエリ例は以下のとおりです。

   ```shell
   obclient> SELECT LS_ID, PRIMARY_ZONE, LS_GROUP_ID, UNIT_LIST FROM oceanbase.DBA_OB_LS WHERE LS_ID = 1002 AND STATUS = 'NORMAL';
   ```

   クエリ結果の例は以下のとおりです：

   ```shell
   +-------+--------------+-------------+----------------+
   | LS_ID | PRIMARY_ZONE | LS_GROUP_ID | UNIT_LIST      |
   +-------+--------------+-------------+----------------+
   |  1002 | z1;z2,z3     |        1001 | 1004,1005,1006 |
   +-------+--------------+-------------+----------------+
   1 row in set
   ```

   変更前後のログストリームを比較し、ログストリームの`UNIT_LIST`（同種Zoneモードでは、`UNIT_GROUP_ID`が同じUnitの集合）、`PRIMARY_ZONE`などが期待通りであれば、変更は成功したことを意味します。
