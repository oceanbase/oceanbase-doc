# ログストリームの変更

1つのログストリームは1つのログストリームグループに属し、各ログストリームグループ内のログストリーム数はプライマリゾーン内のゾーン数によって決定されます。そのため、プライマリゾーンのゾーンリスト内の各ゾーンには、ログストリームグループ内の1つのログストリームのリーダーが配置されることになります。

ユーザーは必要に応じてログストリームに対する変更操作を実行し、各`UNIT_GROUP`（同一構成ゾーンモード）/`UNIT_LIST`（異構成ゾーンモード）間でのログストリームの分布を手動で均衡化できます。

## 制限

* V4.2.5バージョンについては、V4.2.5 BP1以降のバージョンでのみログストリームの変更操作がサポートされます。

* V4.xより前のバージョンでは、OceanBaseデータベースはテナントの同一構成ゾーンモードのみをサポートしています。V4.2.5バージョンでは、V4.2.5 BP5バージョンからテナントの異種ゾーンモードがサポートされます。その中で：

  * 同一構成ゾーンモードでは、ログストリームの分散を変更するための`UNIT_GROUP`およびログストリームの`PRIMARY_ZONE`を変更できます。
  * 異種ゾーンモードでは、ログストリームの分散を変更するための`UNIT_LIST`およびログストリームの`PRIMARY_ZONE`を変更できます。

  同一構成ゾーンモードと異種ゾーンモードの詳細については、[データ分散](../300.replica-management/400.data-distribution.md)を参照してください。

## 注意事項

変更ログストリームの操作を実行する前に、以下の点に注意する必要があります：

* 変更対象のログストリームは存在していなければならず、その状態は `NORMAL` である必要があります。

* 変更対象のログストリームのテナントの状態も `NORMAL` である必要があります。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>V4.2.5 BP1バージョンでは、変更対象のログストリームのテナントの状態が <code>CREATING</code> または <code>DROPPING</code> であってはなりません。</p>
   </main>

* プライマリテナント上でログストリームの `UNIT_GROUP`（同一構成ゾーンモード）/`UNIT_LIST`（異種構成ゾーンモード）を変更する際、テナント内のすべてのログストリームに現在ロードバランシングタスクがないことが求められます。

* スタンバイテナント上でログストリームの `UNIT_GROUP`（同一構成ゾーンモード）/`UNIT_LIST`（異種構成ゾーンモード）プロパティを変更することは推奨されません。スタンバイテナントはログストリームの `UNIT_GROUP`/`UNIT_LIST` プロパティを自動的に調整するため、手動で変更した場合、その変更が反映されない可能性があります。

* ログストリームの `UNIT_GROUP`（同一構成ゾーンモード）/`UNIT_LIST`（異種構成ゾーンモード）を変更する際、ターゲットの `UNIT_GROUP`/`UNIT_LIST` の状態は `ACTIVE` である必要があります。

* ログストリームの `PRIMARY_ZONE` を変更する際、変更後のゾーンがテナントの `ZONE_LIST` 内にあることを確認する必要があります。ログストリームの `PRIMARY_ZONE` の設定は、テナントの `PRIMARY_ZONE` の設定と若干異なります。ログストリームでは、テナントのように `z1,z2`、`z1; z2`、または `RANDOM` といった複数のゾーンを指定することはできず、`z1` または `z2` のように単一のゾーンのみを指定できます。

* ログストリームを変更する際、テナントレベルの構成パラメータ `enable_rebalance` は無効である必要があり、値は `False` である必要があります。`enable_rebalance` が有効な場合、テナントのロードバランシングモジュールはログストリームの `PRIMARY_ZONE` および `UNIT_GROUP`（同一構成ゾーンモード）/`UNIT_LIST`（異種構成ゾーンモード）プロパティを自動的に調整する可能性があります。

* ブロードキャストログストリームとシステムログストリーム（ログストリーム1番）のみが、`UNIT_GROUP` を0に指定することをサポートしています。

* 異種構成ゾーンモードでは、ユーザーログストリームの指定する `UNIT_LIST` は空にすることはできません。

## ステップ１：変更前の確認

1. 管理ユーザーがクラスタの`sys`テナントまたはユーザーテナントにログインします。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に基づいてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. 変更対象のログストリームを持つテナントの状態を照会し、テナントの状態が`NORMAL`であることを確認します。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>V4.2.5 BP1バージョンでは、変更対象のログストリームを持つテナントの状態が<code>CREATING</code>または<code>DROPPING</code>であってはなりません。</p>
   </main>

   * システムテナント

      ```shell
      obclient> SELECT TENANT_ID, TENANT_NAME, STATUS, TENANT_ROLE FROM oceanbase.DBA_OB_TENANTS WHERE tenant_name = 'mq_t1';
      ```

   * ユーザーテナント

      :::tab
      tab MySQLモード

      MySQLモードでは、次のコマンドを実行してテナントの状態を照会します。

      ```shell
      obclient> SELECT TENANT_ID, TENANT_NAME, STATUS, TENANT_ROLE FROM oceanbase.DBA_OB_TENANTS;
      ```

      tab Oracleモード

      Oracleモードでは、次のコマンドを実行してテナントの状態を確認します。

      ```shell
      obclient> SELECT TENANT_ID, TENANT_NAME, STATUS, TENANT_ROLE FROM SYS.DBA_OB_TENANTS;
      ```

      :::

   照会結果の例は次のとおりです：

   ```shell
   +-----------+-------------+--------+-------------+
   | TENANT_ID | TENANT_NAME | STATUS | TENANT_ROLE |

   +-----------+-------------+--------+-------------+
   1 row in set
   ```

   照会結果によると、テナントの状態は`NORMAL`です。

3. テナントのログストリームに現在進行中のロードバランシングタスクがあるかどうかを照会します。メインテナント上でログストリームの`UNIT_GROUP`(同一構成ゾーンモード)/`UNIT_LIST`(異種構成ゾーンモード)を変更する場合、テナントのすべてのログストリームに現在ロードバランシングタスクがないことが求められます。

   * システムテナント


   * ユーザーテナント

      :::tab
      tab MySQLモード

      MySQLモードでは、以下のコマンドを実行して、テナントのログストリームのロードバランシングタスクの状態を照会します。

      ```shell
      obclient> SELECT count(*) AS task_cnt FROM oceanbase.DBA_OB_BALANCE_TASKS WHERE SRC_LS = 1001 or DEST_LS=1001;
      ```

      tab Oracleモード

      Oracleモードでは、以下のコマンドを実行して、テナントのログストリームのロードバランシングタスクの状態を照会します。

      ```shell
      obclient> SELECT count(*) AS task_cnt FROM SYS.DBA_OB_BALANCE_TASKS WHERE SRC_LS = 1001 or DEST_LS=1001;
      ```

      :::

   照会結果の例は次のとおりです：

   ```shell
   +----------+
   | task_cnt |
   +----------+
   |        0 |
   +----------+
   1 row in set
   ```

   照会結果が`0`の場合、テナントのログストリームに現在進行中のロードバランシングタスクがないことを意味します。

      * ユーザーテナント

         :::tab
         tab MySQLモード

         MySQLモードでは、以下のコマンドを実行して、ログストリームがブロードキャストログストリームであるかどうかを確認します。

5. ログストリームの`UNIT_GROUP`(同一構成ゾーンモード)/`UNIT_LIST`(異種構成ゾーンモード)を変更する場合、テナントのユニット情報を照会し、ターゲット`UNIT_GROUP`(同一構成ゾーンモード)/`UNIT_LIST`(異種構成ゾーンモード)上のデータディスクの残り容量が変更対象のログストリームを収容できることを確認する必要があります。

   以下の操作はシステムテナントで実行する必要があります。

   1. 以下のコマンドを実行して、テナントのユニット情報を照会し、ターゲット`UNIT_GROUP`(同一構成ゾーンモード)/`UNIT_LIST`(異種構成ゾーンモード)の状態が`ACTIVE`であることを確認します。


7. 構成パラメータ`enable_rebalance`の値が`False`であるかどうかを確認します。値が`True`の場合、ログストリームの変更操作を実行した後、テナントのロードバランシングモジュールは自動的にログストリームの`PRIMARY_ZONE`および`UNIT_GROUP`(同一構成ゾーンモード)/`UNIT_LIST`(異種構成ゾーンモード)プロパティを調整する可能性があります。


   * システムテナント

      ```shell
      obclient> ALTER SYSTEM SET enable_rebalance = 'False' TENANT = mq_t1;
      ```

   * ユーザーテナント

      ```shell
      obclient> ALTER SYSTEM SET enable_rebalance = 'False';
      ```

## ステップ2：ログストリームの変更

各項目のチェックが要件を満たしていることを確認した後、業務状況に応じて適切な操作を選択し、ログストリームを変更します。

### システムテナントによるユーザーテナントのログストリームの変更

1. `root` ユーザーでクラスタの `sys` テナントにログインします。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に基づいてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. ログストリームを変更します。

   システムテナント内で、ユーザーテナントのログストリームを変更するSQL文は以下のとおりです：

   ```sql
   ALTER SYSTEM MODIFY LS [=] ls_id [UNIT_GROUP [=] unit_group_id] | [UNIT_LIST [=] (unit_id_list) ][,PRIMARY_ZONE [=] 'zone_name'] TENANT [=] 'tenant_name';
   ```

   文に関する説明は以下のとおりです：

   * `ls_id`：変更対象のログストリームのID。

   * `unit_group_id`：変更対象のログストリームのターゲットUnitグループのID。同一構成ゾーンモードのテナントにのみ適用されます。`unit_group_id` はシステムテナント内で、`oceanbase.DBA_OB_UNITS` ビューを照会することで取得できます。

   * `unit_id_list`：変更対象のログストリームが配置されるターゲットUnitのリスト。異種構成ゾーンモードのテナントにのみ適用されます。`unit_id_list` はシステムテナント内で、`oceanbase.DBA_OB_UNITS` ビューを照会することで取得できます。各ゾーンには最大1つのUnitまで指定可能です。

   * `zone_name`：ターゲットゾーンの名前。

   * `tenant_name`：変更対象のログストリームのターゲットテナントの名前。

   * ログストリームの変更操作を実行する際には、少なくともログストリームのいずれかのプロパティを変更する必要があります。同一構成ゾーンモードでは `UNIT_GROUP`、異種構成ゾーンモードでは `UNIT_LIST`、または `PRIMARY_ZONE` を変更します。

   例：

   :::tab
   tab 同構成ゾーンモード

   * ログストリームの `UNIT_GROUP` のみを変更します。

      テナント `mq_t1` の1002番目のログストリームの位置を1002番目の `UNIT_GROUP` に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_GROUP 1002 TENANT = mq_t1;
      ```

   * ログストリームの `PRIMARY_ZONE` のみを変更します。

      テナント `mq_t1` の1002番目のログストリームのリーダーの優先順位を `z1` に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 PRIMARY_ZONE 'z1' TENANT = mq_t1;
      ```

   * ログストリームの `UNIT_GROUP` と `PRIMARY_ZONE` を同時に変更します。

      テナント `mq_t1` の1002番目のログストリームの位置を1002番目の `UNIT_GROUP` に変更し、ログストリームのリーダーの優先順位を `z1` に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_GROUP 1002, PRIMARY_ZONE 'z1' TENANT = mq_t1;
      ```

   tab 異種ゾーンモード

   * ログストリームの `UNIT_LIST` のみを変更します。

      テナント `mq_t1` の1002番目のログストリームの位置を1004、1005、1006の `UNIT_LIST` に変更します。

### ユーザーテナントが自身のログストリームを変更する

1. MySQLモードまたはOracleモードのテナント管理者がデータベースに接続します。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に基づいてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mq_t1#obdemo -p***** -A
   ```

2. ログストリームを変更します。

   ユーザーテナントがログストリームを変更するためのSQLステートメントは以下のとおりです：

   ```sql
   ALTER SYSTEM MODIFY LS [=] ls_id [UNIT_GROUP [=] unit_group_id] | [UNIT_LIST [=] (unit_id_list) ][,PRIMARY_ZONE [=] 'zone_name'];
   ```

   ステートメントの関連説明は以下のとおりです：

   * `ls_id`：変更対象のログストリームのID。

   * `unit_group_id`：変更対象のログストリームのターゲットUnit GroupのID。同一構成Zoneモードのテナントにのみ適用されます。`unit_group_id`はシステムテナントで、`oceanbase.DBA_OB_UNITS`ビューを照会することで取得できます。

   * `unit_id_list`：変更対象のログストリームが配置されるターゲットUnitのリスト。異種構成Zoneモードのテナントにのみ適用されます。`unit_id_list`はシステムテナントで、`oceanbase.DBA_OB_UNITS`ビューを照会することで取得できます。各Zoneには最大1つのUnitまで指定可能です。

   * `zone_name`：ターゲットZoneの名前。

   * ログストリームの変更操作を実行する際には、少なくともログストリームのいずれかのプロパティを変更する必要があります。同一構成Zoneモードでは`UNIT_GROUP`、異種構成Zoneモードでは`UNIT_LIST`、または`PRIMARY_ZONE`を変更します。

   例：

   :::tab
   tab 同構成ゾーンモード

   * ログストリームの `UNIT_GROUP` のみを変更します

      ログストリーム1002の位置を1002の `UNIT_GROUP` に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_GROUP 1002;
      ```

   * ログストリームの `PRIMARY_ZONE` のみを変更します

      ログストリーム1002のリーダーの優先順位を `z1` に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 PRIMARY_ZONE 'z1';
      ```

   * ログストリームの `UNIT_GROUP` と `PRIMARY_ZONE` を同時に変更します

      ログストリーム1002の位置を1002の `UNIT_GROUP` に変更し、ログストリームリーダーの優先順位を `z1` に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_GROUP 1002, PRIMARY_ZONE 'z1';
      ```

   タブ 異種ゾーン モード

   * ログストリームの `UNIT_LIST` のみを変更します。

      ログストリーム1002の位置をログストリーム1004、1005、1006の `UNIT_LIST` に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_LIST (1004,1005,1006);
      ```

   * ログストリームの `PRIMARY_ZONE` のみを変更します。

   * ログストリームの `UNIT_LIST` と `PRIMARY_ZONE` を同時に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_LIST (1004,1005,1006), PRIMARY_ZONE 'z1';
      ```

   :::

3. ログストリームが正常に変更されたかどうかを確認します。
