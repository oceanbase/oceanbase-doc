# ログストリームの変更

1つのログストリームは1つのログストリームグループに属し、各ログストリームグループ内のログストリームの数はプライマリゾーン内のゾーン数によって決定されます。そのため、プライマリゾーンのゾーンリストにある各ゾーンには、ログストリームグループ内の1つのログストリームのリーダーが配置されます。

ユーザーは必要に応じてログストリームに対する変更操作を実行し、各`UNIT_GROUP`（同種ゾーンモード）/`UNIT_LIST`（異種ゾーンモード）間でのログストリームの分布を手動で均等化できます。

## 背景

現在のバージョンでは、同種ゾーンモードと異種ゾーンモードのテナントをサポートしています。ここで、以下の点に注意してください：

* 同種ゾーンモードでは、Unit Groupを指定してログストリームを作成する必要があります。

* 異種ゾーンモードでは、UNIT_LISTを指定してログストリームを作成する必要があります。

  同種ゾーンモードと異種ゾーンモードの詳細な違いについては、[データ分散](../300.replica-management/400.data-distribution.md)を参照してください。

## 注意事項

ログストリームの変更操作を実行する前に、以下の点に注意してください：

* 変更対象のログストリームは存在し、その状態が`NORMAL`である必要があります。

* 変更対象のログストリームのテナントの状態も`NORMAL`である必要があります。

* プライマリテナント上でログストリームの`UNIT_GROUP`（同種ゾーンモード）/`UNIT_LIST`（異種ゾーンモード）を変更する場合、そのテナントのすべてのログストリームに現在ロードバランシングタスクがないことが要件です。

* スタンバイテナント上でログストリームの`UNIT_GROUP`（同種ゾーンモード）/`UNIT_LIST`（異種ゾーンモード）属性を変更することは推奨されません。スタンバイテナントはログストリームの`UNIT_GROUP`/`UNIT_LIST`属性を自動的に調整するため、手動で変更しても反映されない可能性があります。

* ログストリームの`UNIT_GROUP`（同種ゾーンモード）/`UNIT_LIST`（異種ゾーンモード）を変更する場合、対象の`UNIT_GROUP`/`UNIT_LIST`の状態が`ACTIVE`である必要があります。

* ログストリームの`PRIMARY_ZONE`を変更する場合、変更後のZoneがテナントの`ZONE_LIST`に含まれていることを確認する必要があります。ログストリームの`PRIMARY_ZONE`の設定は、テナントの`PRIMARY_ZONE`の設定とは若干異なります。ログストリームでは`z1`や`z2`など単一のZoneのみを指定でき、テナントのように`z1,z2`、`z1; z2`、`RANDOM`といった複数のZoneを指定することはできません。

* ログストリームを変更する際、テナントレベルの構成パラメータ`enable_rebalance`がオフ、つまり値が`False`である必要があります。`enable_rebalance`がオンの場合、テナントのロードバランシングモジュールがログストリームの`PRIMARY_ZONE`および`UNIT_GROUP`（同種ゾーンモード）/`UNIT_LIST`（異種ゾーンモード）属性を自動的に調整する可能性があります。

* 同種ゾーンモードでは、ブロードキャスト電子ストリームとシステムログストリーム（1番ログストリーム）のみが`UNIT_GROUP`を0に指定することをサポートしています。

* 異種ゾーンモードでは、ユーザーログストリームの指定`UNIT_LIST`は空にすることができません。

## ステップ１：変更前の確認

1. 管理者ユーザーがクラスタの`sys`テナントまたはユーザーテナントにログインします。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に準じてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. 変更対象のログストリームを持つテナントの状態を確認し、テナントの状態が`NORMAL`であることを確認します。

   * システムテナント

      ```shell
      obclient> SELECT TENANT_ID, TENANT_NAME, STATUS, TENANT_ROLE FROM oceanbase.DBA_OB_TENANTS WHERE tenant_name = 'mq_t1';
      ```

   * ユーザーテナント

      :::tab
      tab MySQLモード

      MySQLモードでは、以下のコマンドを実行してテナントの状態を確認します。

      ```shell
      obclient> SELECT TENANT_ID, TENANT_NAME, STATUS, TENANT_ROLE FROM oceanbase.DBA_OB_TENANTS;
      ```

      tab Oracleモード

      Oracleモードでは、以下のコマンドを実行してテナントの状態を確認します。

      ```shell
      obclient> SELECT TENANT_ID, TENANT_NAME, STATUS, TENANT_ROLE FROM SYS.DBA_OB_TENANTS;
      ```

      :::

   クエリ結果の例は以下のとおりです：

   ```shell
   +-----------+-------------+--------+-------------+
   | TENANT_ID | TENANT_NAME | STATUS | TENANT_ROLE |
   +-----------+-------------+--------+-------------+
   |      1002 | mq_t1       | NORMAL | PRIMARY     |
   +-----------+-------------+--------+-------------+
   1 row in set
   ```

   クエリ結果によると、テナントの状態は`NORMAL`です。

3. テナントのログストリームに現在進行中のロードバランシングタスクがないかどうかを確認します。プライマリテナント上でログストリームの`UNIT_GROUP`（同種ゾーンモード）/`UNIT_LIST`（異種ゾーンモード）を変更する場合、テナントのすべてのログストリームに現在ロードバランシングタスクがない必要があります。

   * システムテナント


   * ユーザーテナント

      :::tab
      tab MySQLモード

      MySQLモードでは、以下のコマンドを実行して、テナントのログストリームのロードバランシングタスクの状態を確認します。

      ```shell
      obclient> SELECT count(*) AS task_cnt FROM oceanbase.DBA_OB_BALANCE_TASKS WHERE SRC_LS = 1001 or DEST_LS=1001;
      ```

      tab Oracleモード

      Oracleモードでは、以下のコマンドを実行して、テナントのログストリームのロードバランシングタスクの状態を確認します。

      ```shell
      obclient> SELECT count(*) AS task_cnt FROM SYS.DBA_OB_BALANCE_TASKS WHERE SRC_LS = 1001 or DEST_LS=1001;
      ```

      :::

   クエリ結果の例は次のとおりです：

   ```shell
   +----------+
   | task_cnt |
   +----------+
   |        0 |
   +----------+
   1 row in set
   ```

   クエリ結果が `0` の場合、テナントのログストリームに現在進行中のロードバランシングタスクはないことを意味します。

   2. クエリで得られたログストリーム情報に基づき、ログストリームがブロードキャストログストリームであるかどうかを確認する必要がある場合は、ログストリームの `FLAG` 列の情報も確認する必要があります。`FLAG` 列の値が `DUPLICATE` の場合、そのログストリームはブロードキャストログストリームであることを意味します。

      * ユーザーテナント

         :::tab
         tab MySQLモード

         MySQLモードでは、以下のコマンドを実行して、ログストリームがブロードキャストログストリームであるかどうかを確認します。

5. ログストリームの `UNIT_GROUP`（同種ゾーンモード）/`UNIT_LIST`（異種ゾーンモード）を変更する場合は、テナントのUnit情報を照会し、対象の `UNIT_GROUP`（同種ゾーンモード）/`UNIT_LIST`（異種ゾーンモード）のデータディスクの残り容量が変更対象のログストリームを収容できることを確認する必要があります。

   以下の操作はシステムテナントで実行する必要があります。

   1. 以下のコマンドを実行して、テナントのUnit情報を照会し、対象の `UNIT_GROUP`（同種ゾーンモード）/`UNIT_LIST`（異種ゾーンモード）の状態が `ACTIVE` であることを確認します。

      ```shell
      obclient> SELECT UNIT_GROUP_ID, UNIT_ID, ZONE, SVR_IP, SVR_PORT FROM oceanbase.DBA_OB_UNITS WHERE TENANT_ID=1002 AND STATUS = 'ACTIVE' ORDER BY UNIT_GROUP_ID;
      ```

      クエリ結果は次のとおりです：

      ```shell
      +---------------+---------+------+----------------+----------+
      | UNIT_GROUP_ID | UNIT_ID | ZONE | SVR_IP         | SVR_PORT |
      +---------------+---------+------+----------------+----------+
      |          1001 |    1001 | z1   | xxx.xx.xxx.198 |     2882 |
      |          1001 |    1002 | z2   | xxx.xx.xxx.196 |     2882 |
      ```

      ```shell
      obclient> SELECT SVR_IP, SVR_PORT, (DATA_DISK_CAPACITY - DATA_DISK_IN_USE) / 1024 / 1024 / 1024 AS REST_DATA_SIZE_IN_GB FROM oceanbase.GV$OB_SERVERS;
      ```

      クエリ結果は次のとおりです：

      ```shell
      +----------------+----------+----------------------+
      | SVR_IP         | SVR_PORT | REST_DATA_SIZE_IN_GB |
      ```

      ```shell
      SUM(OCCUPY_SIZE)/1024/1024/1024 AS OCCUPY_SIZE_GB,
      SUM(REQUIRED_SIZE)/1024/1024/1024 AS REQUIRED_SIZE_GB
      FROM __ALL_VIRTUAL_TABLET_POINTER_STATUS
      ```

6. ログストリームの `PRIMARY_ZONE` を変更する場合は、変更後のZoneがテナントの `ZONE_LIST` に含まれていることを確認する必要があります。テナントの `ZONE_LIST` は、テナントのローカリティ情報から確認できます。

      ```shell
      obclient> SELECT PRIMARY_ZONE, LOCALITY FROM oceanbase.DBA_OB_TENANTS;
      ```

      tab Oracleモード

      Oracleモードでは、以下のコマンドを実行して、テナントの状態を確認します。

      ```shell
      obclient> SELECT PRIMARY_ZONE, LOCALITY FROM SYS.DBA_OB_TENANTS;
      ```

   クエリ結果の例は以下のとおりです：

   例の結果では、テナント `mq_t1` の `LOCALITY` は `FULL{1}@z1, FULL{1}@z2, FULL{1}@z3` であり、テナントの `ZONE_LIST` に `z1`、`z2`、`z3` の3つのゾーンが含まれていることを示しています。

7. 構成パラメータ `enable_rebalance` の値が `False` かどうかを確認します。値が `True` の場合、ログストリームの変更操作後、テナントのロードバランシングモジュールがログストリームの `PRIMARY_ZONE` および `UNIT_GROUP`（同種ゾーンモード）/`UNIT_LIST`（異種ゾーンモード）属性を自動的に調整する可能性があります。

   ```shell
   obclient> SHOW PARAMETERS LIKE '%enable_rebalance%';
   ```

   値が `False` でない場合は、以下のコマンドを実行して、構成パラメータ `enable_rebalance` の値を `False` に設定する必要があります。

   * システムテナント

      ```shell
      obclient> ALTER SYSTEM SET enable_rebalance = 'False' TENANT = mq_t1;
      ```

   * ユーザーテナント

      ```shell
      obclient> ALTER SYSTEM SET enable_rebalance = 'False';
      ```

## ステップ2：ログストリームの変更

各項目のチェックが要件を満たしていることを確認した後、業務状況に応じて適切な操作を選択し、ログストリームを変更します。

### システムテナントからユーザーテナントへのログストリームの変更

1. `root` ユーザーでクラスタの `sys` テナントにログインします。

   接続例は以下の通りです。データベースへの接続時は、実際の環境に準じてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. ログストリームを変更します。

   システムテナント内で、ユーザーテナントのログストリームを変更するSQLステートメントは以下の通りです：

   ```sql
   ALTER SYSTEM MODIFY LS [=] ls_id [UNIT_GROUP [=] unit_group_id] | [UNIT_LIST [=] (unit_id_list)][, PRIMARY_ZONE [=] 'zone_name'] TENANT [=] 'tenant_name';
   ```

   ステートメントの関連説明は以下の通りです：

   * `ls_id`：変更対象のログストリームID。

   * `unit_group_id`：変更対象のログストリームのターゲットUnit GroupのIDを指定します。同種ゾーンモードのテナントにのみ適用されます。`unit_group_id` はシステムテナント内で、`oceanbase.DBA_OB_UNITS` ビューをクエリすることで取得できます。

   * `unit_id_list`：変更対象のログストリームを分散配置するターゲットUnitリストを指定します。異種ゾーンモードのテナントにのみ適用されます。`unit_id_list` はシステムテナント内で、`oceanbase.DBA_OB_UNITS` ビューをクエリすることで取得できます。各ゾーンにおけるUnit数は1つまでです。

   * `zone_name`：ターゲットゾーンの名前。

   * `tenant_name`：変更対象のログストリームのターゲットテナント名。

   * ログストリームの変更操作を実行する際には、少なくともログストリームの1つの属性を変更する必要があります：`UNIT_GROUP`（同種ゾーンモード）/`UNIT_LIST`（異種ゾーンモード）または `PRIMARY_ZONE`。

   例：

   :::tab
   tab 同種ゾーンモード

   * ログストリームの `UNIT_GROUP` のみを変更する場合

      テナント `mq_t1` の1002番ログストリームの位置を1002番の `UNIT_GROUP` に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_GROUP 1002 TENANT = mq_t1;
      ```

   * ログストリームの `PRIMARY_ZONE` のみを変更する場合

      テナント `mq_t1` の1002番ログストリームLeaderの優先順位を `z1` に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 PRIMARY_ZONE 'z1' TENANT = mq_t1;
      ```

   * ログストリームの `UNIT_GROUP` と `PRIMARY_ZONE` を同時に変更する場合

      テナント `mq_t1` の1002番ログストリームの位置を1002の `UNIT_GROUP` に変更し、ログストリームリーダーの第一優先度を `z1` に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_GROUP 1002, PRIMARY_ZONE 'z1' TENANT = mq_t1;
      ```

   tab 異種ゾーンモード

   * ログストリームの `UNIT_LIST` のみを変更します。

      テナント `mq_t1` の1002番ログストリームの位置を1004、1005、1006の `UNIT_LIST` に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_LIST (1004,1005,1006) TENANT = mq_t1;
      ```

   * ログストリームの `PRIMARY_ZONE` のみを変更します。

      テナント `mq_t1` の1002番ログストリームリーダーの第一優先度を `z1` に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 PRIMARY_ZONE 'z1' TENANT = mq_t1;
      ```

   * ログストリームの `UNIT_LIST` と `PRIMARY_ZONE` を同時に変更します。

      テナント `mq_t1` の1002番ログストリームの位置を1004、1005、1006の `UNIT_LIST` に変更し、ログストリームリーダーの第一優先度を `z1` に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_LIST (1004,1005,1006), PRIMARY_ZONE 'z1' TENANT = mq_t1;
      ```

   :::

3. ログストリームが正常に変更されたか確認します。

   ```shell
   obclient> SELECT LS_ID, PRIMARY_ZONE, LS_GROUP_ID, UNIT_LIST FROM oceanbase.CDB_OB_LS WHERE TENANT_ID=1002 AND LS_ID = 1002 AND STATUS = 'NORMAL';
   ```

   クエリ結果の例は以下のとおりです：

   ```shell
   +-------+--------------+-------------+----------------+
   | LS_ID | PRIMARY_ZONE | LS_GROUP_ID | UNIT_LIST      |
   +-------+--------------+-------------+----------------+
   |  1002 | z1;z2,z3     |        1001 | 1004,1005,1006 |
   +-------+--------------+-------------+----------------+
   1 row in set
   ```

   変更前後のログストリームを比較し、ログストリームの対応する `UNIT_LIST`（同種ゾーンモードでは、`UNIT_GROUP_ID` が同じユニットの集合）、`PRIMARY_ZONE` などが期待通りであれば、変更は成功したことを意味します。

### ユーザーテナントが自身のテナントのログストリームを変更する場合

1. MySQLモードまたはOracleモードのテナント管理者がデータベースに接続します。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に準じてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mq_t1#obdemo -p***** -A
   ```

2. ログストリームを変更します。

   ユーザーテナントがログストリームを変更するSQLステートメントは以下のとおりです：

   ```sql
   ALTER SYSTEM MODIFY LS [=] ls_id [UNIT_GROUP [=] unit_group_id] | [UNIT_LIST [=] (unit_id_list)][, PRIMARY_ZONE [=] 'zone_name'];
   ```

   ステートメントの関連説明は以下の通りです：

   * `ls_id`：変更対象のログストリームのID。

   * `unit_group_id`：変更対象のログストリームのターゲットUnit GroupのIDを指定します。同種ゾーンモードのテナントにのみ適用されます。`unit_group_id`はシステムテナントで、`oceanbase.DBA_OB_UNITS`ビューをクエリすることで取得できます。

   * `unit_id_list`：変更対象のログストリームを分散配置するターゲットUnitのリストを指定します。異種ゾーンモードのテナントにのみ適用されます。`unit_id_list`はシステムテナントで、`oceanbase.DBA_OB_UNITS`ビューをクエリすることで取得できます。各ゾーンにおいてUnit数は1つを超えません。

   * `zone_name`：ターゲットゾーンの名前。

   * 変更ログストリームの操作を実行する際には、少なくともログストリームの1つの属性`UNIT_GROUP`（同種ゾーンモード）/`UNIT_LIST`（異種ゾーンモード）または`PRIMARY_ZONE`を変更する必要があります。

   例：

   :::tab
   tab 同種ゾーンモード

   * ログストリームの`UNIT_GROUP`のみを変更する場合

      1002番ログストリームの位置を1002番の`UNIT_GROUP`に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_GROUP 1002;
      ```

   * ログストリームの`PRIMARY_ZONE`のみを変更する場合

      1002番ログストリームLeaderの優先順位を`z1`に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 PRIMARY_ZONE 'z1';
      ```

   * ログストリームの`UNIT_GROUP`と`PRIMARY_ZONE`を同時に変更する場合

      1002番ログストリームの位置を1002番の`UNIT_GROUP`に変更し、ログストリームLeaderの優先順位を`z1`に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_GROUP 1002, PRIMARY_ZONE 'z1';
      ```

   tab 異種ゾーンモード

   * ログストリームの`UNIT_LIST`のみを変更する場合

      1002番ログストリームの位置を1004、1005、1006の`UNIT_LIST`に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_LIST (1004,1005,1006);
      ```

   * ログストリームの`PRIMARY_ZONE`のみを変更する場合

      1002番ログストリームLeaderの優先順位を`z1`に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 PRIMARY_ZONE 'z1';
      ```

   * ログストリームの`UNIT_LIST`と`PRIMARY_ZONE`を同時に変更する場合

      1002番のログストリームの位置を1004、1005、1006の`UNIT_LIST`に変更し、ログストリームリーダーの第一優先順位を`z1`に変更します。

      ```shell
      obclient> ALTER SYSTEM MODIFY LS 1002 UNIT_LIST (1004,1005,1006), PRIMARY_ZONE 'z1';
      ```

   :::

3. ログストリームが正常に変更されたかどうかを確認します。

   MySQLモードを例に、クエリの例は以下のとおりです。

   ```shell
   obclient> SELECT LS_ID, PRIMARY_ZONE, LS_GROUP_ID, UNIT_LIST FROM oceanbase.DBA_OB_LS WHERE LS_ID = 1002 AND STATUS = 'NORMAL';
   ```

   クエリ結果の例は以下のとおりです：

   ```shell
   +-------+--------------+-------------+----------------+
   | LS_ID | PRIMARY_ZONE | LS_GROUP_ID | UNIT_LIST      |
   +-------+--------------+-------------+----------------+
   |  1002 | z1;z2,z3     |        1001 | 1004,1005,1006 |
   +-------+--------------+-------------+----------------+
   1 row in set
   ```

   変更前後のログストリームを比較し、ログストリームが対応する`UNIT_LIST`（同種ゾーンモードでは、`UNIT_GROUP_ID`が同じユニットの集合）、`PRIMARY_ZONE`などが期待通りであれば、変更は成功したことを意味します。
