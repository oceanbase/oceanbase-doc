# ログストリームの作成

ユーザーはビジネスニーズに応じて、`UNIT_GROUP`（同種Zoneモード）または`UNIT_LIST`（異種Zoneモード）上にログストリームを作成し、各サービスノード上のテナントのログストリーム数を手動で調整できます。

## 背景情報

現在のバージョンでは、同種Zoneモードと異種Zoneモードのテナントをサポートしています。ここで、それぞれのモードについて説明します。

*   同種Zoneモードでは、Unit Groupを指定してログストリームを作成する必要があります。

*   異種Zoneモードでは、UNIT_LISTを指定してログストリームを作成する必要があります。

  同種Zoneモードと異種Zoneモードの詳細な違いについては、[データ分散](../300.replica-management/400.data-distribution.md)を参照してください。

## 注意事項

ログストリームの作成操作を実行する前に、以下の点にご注意ください：

* 現在は通常のユーザーログストリームのみの作成がサポートされており、ブロードキャストログストリームの作成はサポートされていません。

* ログストリームの作成操作はプライマリテナントでのみ実行できます。また、作成対象のログストリームのテナントの `STATUS` と `SWITCHOVER_STATUS` は `NORMAL` でなければなりません。

* ログストリームを作成する際：

  * 同一Zoneモードでは、ターゲット `UNIT_GROUP` の状態が `ACTIVE` で、ビュー `DBA_OB_UNITS` 内のターゲット `UNIT_GROUP_ID` の値が0以外の必要があります。

  * 異種Zoneモードでは、ターゲット `UNIT_LIST` の状態が `ACTIVE` で、指定したターゲット `UNIT_LIST` が空以外の必要があります。

* 作成対象のログストリームに `PRIMARY_ZONE` を指定する場合、指定したZoneがテナントの `ZONE_LIST` に確実に含まれている必要があります。ログストリームの `PRIMARY_ZONE` の設定は、テナントの `PRIMARY_ZONE` の設定とは若干異なります。ログストリームではZoneを1つのみ指定でき、例えば `z1` または `z2` とします。テナントのように `z1,z2`、`z1; z2`、または `RANDOM` といった指定はできません。

* ロードバランシング関連の構成パラメータは、値を `False` に設定します。設定しなかった場合は：

  * テナントレベルの構成パラメータ [enable_rebalance](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2800.enable_rebalance.md) が有効、すなわち値が `True` の場合、作成されたログストリームはシステムによってターゲットの `UNIT_GROUP`/`UNIT_LIST` から他の `UNIT_GROUP`/`UNIT_LIST` へ移動されます。

  * テナントレベルの構成パラメータ [enable_transfer](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3000.enable_transfer.md) が有効、すなわち値が `True` の場合、作成されたログストリームは削除される可能性があります。

## ステップ１：作成前の確認

1. 管理者ユーザーがクラスタの`sys`テナントまたはユーザーテナントにログインします。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に準じてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. テナントの状態、`PRIMARY_ZONE`、およびLocalityに関する情報をクエリします。

   ログストリームを作成する際、テナントの`STATUS`と`SWITCHOVER_STATUS`はどちらも`NORMAL`である必要があります。また、ログストリームの`PRIMARY_ZONE`を指定する場合は、指定したZoneがテナントの`ZONE_LIST`に確実に含まれている必要があります。テナントの`ZONE_LIST`は、テナントのLocalityに含まれるZoneを参照することで確認できます。

   * システムテナント

      ```shell
      obclient(root@sys)[oceanbase]> SELECT TENANT_ID, TENANT_NAME, STATUS, SWITCHOVER_STATUS, TENANT_ROLE, PRIMARY_ZONE, LOCALITY FROM oceanbase.DBA_OB_TENANTS WHERE tenant_name = 'mq_t1';
      ```

   * ユーザーテナント

      :::tab
      tab MySQLモード

      MySQLモードでは、以下のコマンドを実行してテナントの状態をクエリします。

      ```shell
      obclient> SELECT TENANT_ID, TENANT_NAME, STATUS, SWITCHOVER_STATUS, TENANT_ROLE, PRIMARY_ZONE, LOCALITY FROM oceanbase.DBA_OB_TENANTS;
      ```

      tab Oracleモード

      Oracleモードでは、以下のコマンドを実行して、テナントの状態をクエリします。

      ```shell
      obclient> SELECT TENANT_ID, TENANT_NAME, STATUS, SWITCHOVER_STATUS, TENANT_ROLE, PRIMARY_ZONE, LOCALITY FROM SYS.DBA_OB_TENANTS;
      ```

      :::

   クエリ結果の例は以下のとおりです：

   ```shell
   +-----------+-------------+--------+-------------------+-------------+--------------+-------------------------------------+
   | TENANT_ID | TENANT_NAME | STATUS | SWITCHOVER_STATUS | TENANT_ROLE | PRIMARY_ZONE | LOCALITY                            |
   +-----------+-------------+--------+-------------------+-------------+--------------+-------------------------------------+
   |      1002 | mq_t1       | NORMAL | NORMAL            | PRIMARY     | RANDOM       | FULL{1}@z1, FULL{1}@z2, FULL{1}@z3  |
   +-----------+-------------+--------+-------------------+-------------+--------------+-------------------------------------+
   1 row in set
   ```

3. テナントのUnit情報をクエリし、ターゲットの`UNIT_GROUP`（同種Zoneモード）/`UNIT_LIST`（異種Zoneモード）の状態が`ACTIVE`であることを確認します。

   システムテナントで以下のコマンドを実行し、テナントのUnit情報をクエリします。

    ```shell
    obclient(root@sys)[oceanbase]> SELECT UNIT_GROUP_ID, UNIT_ID, ZONE, SVR_IP, SVR_PORT FROM oceanbase.DBA_OB_UNITS WHERE TENANT_ID=1002 AND STATUS = 'ACTIVE' ORDER BY UNIT_GROUP_ID;
    ```

    クエリ結果は次のとおりです：

    ```shell
    +---------------+---------+------+----------------+----------+
    | UNIT_GROUP_ID | UNIT_ID | ZONE | SVR_IP         | SVR_PORT |
    +---------------+---------+------+----------------+----------+
    |          1001 |    1001 | z1   | xxx.xx.xxx.198 |     2882 |
    |          1001 |    1002 | z2   | xxx.xx.xxx.196 |     2882 |
    |          1001 |    1003 | z3   | xxx.xx.xxx.204 |     2882 |
    |          1002 |    1004 | z1   | xxx.xx.xxx.194 |     2882 |
    |          1002 |    1005 | z2   | xxx.xx.xxx.192 |     2882 |
    |          1002 |    1006 | z3   | xxx.xx.xxx.197 |     2882 |
    +---------------+---------+------+----------------+----------+
    6 rows in set
    ```

4. 構成パラメータ[enable_rebalance](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2800.enable_rebalance.md)と[enable_transfer](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3000.enable_transfer.md)が無効な状態、つまり値が`False`であることを確認します。

   ユーザーテナントで以下のコマンドを実行し、構成パラメータの値をクエリします。

   ```shell
   obclient> SHOW PARAMETERS LIKE '%enable_rebalance%';
   ```

   ```shell
   obclient> SHOW PARAMETERS LIKE '%enable_transfer%';
   ```

   値が`True`の場合は、以下のコマンドを実行して、それぞれの値を`False`に変更できます。

   ```shell
   obclient> ALTER SYSTEM SET enable_rebalance = False;
   ```

   ```shell
   obclient> ALTER SYSTEM SET enable_transfer = False;
   ```

## ステップ2：ログストリームの作成

各項目のチェックが要件を満たしていることを確認後、業務状況に応じて適切な操作を選択し、テナントのログストリームを作成します。

### システムテナントがユーザーテナントのためにログストリームを作成する

1. `root` ユーザーでクラスタの `sys` テナントにログインします。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に準じてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. ログストリームを作成します。

   システムテナントがユーザーテナントのためにログストリームを作成するSQLステートメントは以下のとおりです：

   ```sql
   ALTER SYSTEM CREATE LS {UNIT_GROUP [=] unit_group_id} | {UNIT_LIST [=] (unit_id_list) }[, PRIMARY_ZONE [=] 'zone_name'] TENANT [=] 'tenant_name';
   ```

   ステートメントの関連説明は以下のとおりです：

   * `unit_group_id`：作成対象のログストリームのターゲット `UNIT_GROUP` のIDを指定します。これは同種Zoneモードのテナントにのみ適用されます。`unit_group_id` はシステムテナントで `oceanbase.DBA_OB_UNITS` ビューをクエリすることで取得できます。

   * `unit_id_list`：作成対象のログストリームが配置されるUnitのリストを指定します。これは異種Zoneモードのテナントにのみ適用されます。`unit_id_list` はシステムテナントで `oceanbase.DBA_OB_UNITS` ビューをクエリすることで取得できます。各Zoneに配置されるUnitは最大1つです。

   * `zone_name`：ターゲットZoneの名前です。`PRIMARY_ZONE` を指定しない場合、システムがテナント内の同一 `UNIT_GROUP`（同種Zoneモード）/`UNIT_LIST`（異種Zoneモード）内の `PRIMARY_ZONE` の均等維持のルールに基づいて割り当てます。

   * `tenant_name`：作成対象のログストリームのターゲットテナント名です。

   例：

   :::tab
   tab 同種Zoneモード

   * IDが1001の`UNIT_GROUP`にログストリームを作成します。

      ```shell
      obclient(root@sys)[(none)]> ALTER SYSTEM CREATE LS UNIT_GROUP 1001 TENANT = mq_t1;
      ```

      ステートメント実行後、システムは指定された`UNIT_GROUP_ID`が1001の`UNIT_GROUP`（対応するUnitはそれぞれ1001、1002、1003）にログストリームを作成します。

   * IDが1001の`UNIT_GROUP`にログストリームを作成し、そのログストリームの`PRIMARY_ZONE`を`z1`に設定します。

      ```shell
      obclient(root@sys)[(none)]> ALTER SYSTEM CREATE LS UNIT_GROUP 1001, PRIMARY_ZONE 'z1' TENANT = mq_t1;
      ```

      ステートメント実行後、システムは指定された`UNIT_GROUP_ID`が1001の`UNIT_GROUP`（対応するUnitはそれぞれ1001、1002、1003）にログストリームを作成し、そのプライマリZoneを`z1`に設定します。

   tab 異種Zoneモード

   * `UNIT_ID` がそれぞれ1001、1002、1003の `UNIT_LIST` に対して、ログストリームを作成します。

      ```shell
      obclient(root@sys)[(none)]> ALTER SYSTEM CREATE LS UNIT_LIST (1001,1002,1003) TENANT = mq_t1;
      ```

      ステートメント実行後、システムは指定された1001、1002、1003の `UNIT_LIST` にログストリームを作成します。

   * `UNIT_ID` がそれぞれ1001、1002、1003の `UNIT_LIST` に対してログストリームを作成し、そのログストリームの `PRIMARY_ZONE` を `z1` に設定します。

      ```shell
      obclient(root@sys)[(none)]> ALTER SYSTEM CREATE LS UNIT_LIST (1001,1002,1003), PRIMARY_ZONE 'z1' TENANT = mq_t1;
      ```

      ステートメント実行後、システムは指定された1001、1002、1003の `UNIT_LIST` にログストリームを作成し、そのプライマリZoneを `z1` に設定します。

   :::

3. 作成されたログストリームを確認します。

   1. 新規作成されたログストリームの `LS_ID` を取得します。

      ```shell
      obclient(root@sys)[oceanbase]> SELECT * FROM oceanbase.CDB_OB_TENANT_EVENT_HISTORY WHERE EVENT='CREATE LS' AND TENANT_ID=1002 ORDER BY TIMESTAMP DESC LIMIT 1\G
      ```

      クエリ結果の例は以下のとおりです：

      ```shell
      *************************** 1. row ***************************
       TENANT_ID: 1002
       TIMESTAMP: 2026-01-09 11:31:14.284278
          MODULE: LS COMMAND
           EVENT: CREATE LS
           NAME1: ARGS
          VALUE1: {op:1, op str:"CREATE LS", tenant_id:1002, ls_id:{id:-1}, unit_group_id:1001, ls_primary_zone:"z1"}
           NAME2: LS_ID
          VALUE2: 1003
           NAME3: LS_GROUP_ID
          VALUE3: 1002
           NAME4: UNIT_GROUP_ID
          VALUE4: 1001
           NAME5: PRIMARY_ZONE
          VALUE5: z1
           NAME6: NULL
          VALUE6:
      EXTRA_INFO: NULL
          SVR_IP: 6.xx.xxx.xxx
        SVR_PORT: 13324
        TRACE_ID: Y3xxxxxxxxxxx-xxxxxxxxxxxxxxx-x-x
       COST_TIME: 19407
        RET_CODE: 0
       ERROR_MSG: NULL
      1 row in set
      ```

      クエリ結果によると、新規作成されたログストリームの `LS_ID` は1003です。

   2. 新規作成されたログストリームの詳細情報を確認します。

      ```shell
      obclient(root@sys)[oceanbase]> SELECT LS_ID, STATUS, PRIMARY_ZONE, LS_GROUP_ID, UNIT_LIST FROM oceanbase.CDB_OB_LS WHERE TENANT_ID=1002 AND LS_ID = 1003;
      ```

      クエリ結果の例は以下のとおりです：

      ```shell
      +-------+--------+--------------+-------------+----------------+
      | LS_ID | STATUS | PRIMARY_ZONE | LS_GROUP_ID | UNIT_LIST      |
      +-------+--------+--------------+-------------+----------------+
      |  1003 | NORMAL | z1;z2,z3     |        1001 | 1001,1002,1003 |
      +-------+--------+--------------+-------------+----------------+
      1 row in set
      ```

      クエリ結果によると、新規作成されたログストリームの状態は `NORMAL`、プライマリZoneは `z1` であり、1001、1002、1003 の `UNIT_LIST` に配置されています（同種Zoneモードでは、`UNIT_GROUP_ID` が同じUnitのグループに対応）。これは期待された結果と一致し、ログストリームの作成は成功しました。

### ユーザーテナントが自身のテナントにログストリームを作成する

1. MySQLテナントまたはOracleテナントのテナント管理者がデータベースに接続します。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に準じてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mq_t1#obdemo -p***** -A
   ```

2. ログストリームを作成します。

   ユーザーテナントがログストリームを作成するSQLステートメントは以下のとおりです：

   ```sql
   ALTER SYSTEM CREATE LS {UNIT_GROUP [=] unit_group_id} | {UNIT_LIST [=] (unit_id_list) }[, PRIMARY_ZONE [=] 'zone_name'];

   ```

   ステートメントの関連説明は以下のとおりです：

   * `unit_group_id`：作成対象のログストリームのターゲット `UNIT_GROUP` のIDを指定します。これは同種Zoneモードのテナントにのみ適用されます。`unit_group_id` はシステムテナントで、`oceanbase.DBA_OB_UNITS` ビューをクエリすることで取得できます。

   * `unit_id_list`：作成対象のログストリームが配置されるUnitのリストを指定します。これは異種Zoneモードのテナントにのみ適用されます。`unit_id_list` はシステムテナントで、`oceanbase.DBA_OB_UNITS` ビューをクエリすることで取得できます。各Zoneに配置されるUnitは最大1つです。

   * `zone_name`：ターゲットZoneの名前です。`PRIMARY_ZONE` を指定しない場合、システムがテナント内の同一 `UNIT_GROUP`（同種Zoneモード）/`UNIT_LIST`（異種Zoneモード）内の `PRIMARY_ZONE` の均等維持のルールに基づいて自動的に割り当てます。

   例：

   :::tab
   tab 同種Zoneモード

   * IDが1001の`UNIT_GROUP`にログストリームを作成します。

     ```shell
     obclient> ALTER SYSTEM CREATE LS UNIT_GROUP 1001;
     ```

     ステートメント実行後、システムは指定された`UNIT_GROUP_ID`が1001（対応するUnitはそれぞれ1001、1002、1003）の上にログストリームを作成します。

   * IDが1001の`UNIT_GROUP`にログストリームを作成し、そのログストリームの`PRIMARY_ZONE`を`z1`に設定します。

     ```shell
     obclient> ALTER SYSTEM CREATE LS UNIT_GROUP 1001, PRIMARY_ZONE 'z1';
     ```

     ステートメント実行後、システムは指定された`UNIT_GROUP_ID`が1001（対応するUnitはそれぞれ1001、1002、1003）の上にログストリームを作成し、そのプライマリZoneを`z1`に設定します。

   tab 異種Zoneモード

   * `UNIT_ID` がそれぞれ1001、1002、1003の `UNIT_LIST` に対して、ログストリームを作成します。

      ```shell
      obclient> ALTER SYSTEM CREATE LS UNIT_LIST (1001,1002,1003);
      ```

      ステートメント実行後、システムは指定された1001、1002、1003の `UNIT_LIST` にログストリームを作成します。

   * `UNIT_ID` がそれぞれ1001、1002、1003の `UNIT_LIST` に対して、ログストリームを作成するとともに、そのログストリームの `PRIMARY_ZONE` を `z1` に設定します。

      ```shell
      obclient> ALTER SYSTEM CREATE LS UNIT_LIST (1001,1002,1003), PRIMARY_ZONE 'z1';
      ```

      ステートメント実行後、システムは指定された1001、1002、1003の `UNIT_LIST` にログストリームを作成し、そのプライマリZoneを `z1` に設定します。

   :::

3. 作成したログストリームを確認します。

   MySQLテナントを例に、操作は以下のとおりです。

   1. 新規作成されたログストリームの `LS_ID` を取得します。

      ```shell
      obclient> SELECT * FROM oceanbase.DBA_OB_TENANT_EVENT_HISTORY WHERE EVENT='CREATE LS' ORDER BY TIMESTAMP DESC LIMIT 1\G
      ```

      クエリ結果の例は以下のとおりです：

      ```shell
      *************************** 1. row ***************************
       TENANT_ID: 1002
       TIMESTAMP: 2026-01-09 11:31:14.284278
          MODULE: LS COMMAND

           NAME2: LS_ID
          VALUE2: 1003
           NAME3: LS_GROUP_ID
          VALUE3: 1002
           NAME4: UNIT_GROUP_ID
          VALUE4: 1001
           NAME5: PRIMARY_ZONE
          VALUE5: z1
           NAME6: NULL
          VALUE6:
      EXTRA_INFO: NULL
          SVR_IP: 6.xx.xxx.xxx
        SVR_PORT: 13324
        TRACE_ID: Y3xxxxxxxxxxx-xxxxxxxxxxxxxxx-x-x
       COST_TIME: 19407
        RET_CODE: 0
       ERROR_MSG: NULL

      ```

      クエリ結果から、新規作成されたログストリームの `LS_ID` は1003であることがわかります。

   2. 新規作成されたログストリームの詳細情報を確認します。

      ```shell

      ```

      クエリ結果の例は以下のとおりです：

      ```shell
      +-------+--------+--------------+-------------+----------------+
      | LS_ID | STATUS | PRIMARY_ZONE | LS_GROUP_ID | UNIT_LIST      |
      +-------+--------+--------------+-------------+----------------+
      |  1003 | NORMAL | z1;z2,z3     |        1001 | 1001,1002,1003 |

      ```

      クエリ結果から、新規作成されたログストリームの状態は `NORMAL`、プライマリZoneは `z1` であり、1001、1002、1003 の `UNIT_LIST` に分散配置されていることがわかります（同種Zoneモードでは、`UNIT_GROUP_ID` が同じUnitのグループに対応）。これは期待された結果と一致し、ログストリームの作成は成功です。
