# ログストリームの作成

ユーザーは業務ニーズに応じて、`UNIT_GROUP`（同一構成ゾーンモード）または`UNIT_LIST`（異構成ゾーンモード）上でログストリームを作成し、各サービスノード上のテナントのログストリーム数を手動で調整できます。

## 使用制限

* V4.2.5バージョンでは、V4.2.5 BP2以降のバージョンでログストリームの作成がサポートされています。
* V4.xより前のバージョンでは、OceanBaseデータベースはテナントの同一構成ゾーンモードのみをサポートしています。V4.2.5バージョンでは、V4.2.5 BP5バージョンからテナントの異種ゾーンモードがサポートされます。その中で：

  * 同一構成ゾーンモードでは、Unit Groupを指定してログストリームを作成する必要があります。
  * 異種ゾーンモードでは、UNIT_LISTを指定してログストリームを作成する必要があります。

  同一構成ゾーンモードと異種ゾーンモードの詳細な違いについては、[データ分散](../300.replica-management/400.data-distribution.md)を参照してください。

## 注意事項

ログストリームの作成操作を実行する前に、以下の点に注意する必要があります：

* 現在は通常のユーザーログストリームのみの作成がサポートされており、ブロードキャストログストリームの作成はサポートされていません。
* ログストリームの作成操作は、プライマリテナントでのみ完了できます。また、ログストリームを作成するテナントの`STATUS`と`SWITCHOVER_STATUS`は`NORMAL`である必要があります。
* ログストリームを作成する際には：

  * 同型ゾーンモードでは、ターゲット`UNIT_GROUP`の状態は`ACTIVE`でなければならず、ビュー`DBA_OB_UNITS`内のターゲット`UNIT_GROUP_ID`の値は0であってはなりません。
  * 異型ゾーンモードでは、ターゲット`UNIT_LIST`の状態は`ACTIVE`でなければならず、指定されたターゲット`UNIT_LIST`は空であってはなりません。

* 作成予定のログストリームに`PRIMARY_ZONE`を指定する場合、指定したゾーンがテナントの`ZONE_LIST`に含まれていることを確認する必要があります。ログストリームにおける`PRIMARY_ZONE`の設定は、テナントの`PRIMARY_ZONE`の設定と若干異なります。ログストリームでは、`z1`や`z2`などの単一のゾーンのみを指定でき、テナントのように`z1,z2`、`z1; z2`、または`RANDOM`といった複数のゾーンを指定することはできません。
* ロードバランシング関連の構成パラメータは、値を`False`として無効にすることを推奨します。そうしない場合、次のような動作になります：

  * テナントレベルの構成パラメータ[enable_rebalance](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2900.enable_rebalance.md)が有効になっている場合、作成されたログストリームはシステムによってターゲット`UNIT_GROUP`/`UNIT_LIST`から他の`UNIT_GROUP`/`UNIT_LIST`へ移行されます。

  * テナントレベルの構成パラメータ[enable_transfer](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3100.enable_transfer.md)が有効になっている場合、作成されたログストリームは削除される可能性があります。

## ステップ１：作成前の確認

1. 管理者ユーザーがクラスタの`sys`テナントまたはユーザーテナントにログインします。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に基づいてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. テナントの状態、`PRIMARY_ZONE`、およびローカリティ関連情報を照会します。

   ログストリームを作成する際、テナントの`STATUS`と`SWITCHOVER_STATUS`はどちらも`NORMAL`である必要があります。同時に、ログストリームの`PRIMARY_ZONE`を指定する場合は、指定されたゾーンがテナントの`ZONE_LIST`に含まれていることを確認する必要があります。テナントの`ZONE_LIST`は、テナントのローカリティに含まれるゾーンを参照してください。

   * システムテナント

      ```shell
      obclient> SELECT TENANT_ID, TENANT_NAME, STATUS, SWITCHOVER_STATUS, TENANT_ROLE, PRIMARY_ZONE, LOCALITY FROM oceanbase.DBA_OB_TENANTS WHERE tenant_name = 'mq_t1';
      ```

   * ユーザーテナント

      :::tab
      tab MySQLモード

      MySQLモードでは、以下のコマンドを実行してテナントの状態を確認します。

      ```shell
      obclient> SELECT TENANT_ID, TENANT_NAME, STATUS, SWITCHOVER_STATUS, TENANT_ROLE, PRIMARY_ZONE, LOCALITY FROM oceanbase.DBA_OB_TENANTS;
      ```

      tab Oracleモード

      Oracleモードでは、以下のコマンドを実行してテナントの状態を確認します。

      ```shell
      obclient> SELECT TENANT_ID, TENANT_NAME, STATUS, SWITCHOVER_STATUS, TENANT_ROLE, PRIMARY_ZONE, LOCALITY FROM SYS.DBA_OB_TENANTS;
      ```

      :::

   クエリ結果の例は次のとおりです：

   ```shell
   +-----------+-------------+--------+-------------------+-------------+--------------+-------------------------------------+
   | TENANT_ID | TENANT_NAME | STATUS | SWITCHOVER_STATUS | TENANT_ROLE | PRIMARY_ZONE | LOCALITY                            |
   +-----------+-------------+--------+-------------------+-------------+--------------+-------------------------------------+
   |      1002 | mq_t1       | NORMAL | NORMAL            | PRIMARY     | RANDOM       | FULL{1}@z1, FULL{1}@z2, FULL{1}@z3  |
   +-----------+-------------+--------+-------------------+-------------+--------------+-------------------------------------+
   1 row in set
   ```

3. テナントのUnit情報を照会し、ターゲット`UNIT_GROUP`(同構成ゾーンモード) /`UNIT_LIST`(異構成ゾーンモード)の状態が`ACTIVE`であることを確認します。

   システムテナントで以下のコマンドを実行して、テナントのUnit情報を照会します。

    ```shell
    obclient> SELECT UNIT_GROUP_ID, UNIT_ID, ZONE, SVR_IP, SVR_PORT FROM oceanbase.DBA_OB_UNITS WHERE TENANT_ID=1002 AND STATUS = 'ACTIVE' ORDER BY UNIT_GROUP_ID;
    ```

    クエリ結果は次のとおりです：

    ```shell
    +---------------+---------+------+----------------+----------+
    | UNIT_GROUP_ID | UNIT_ID | ZONE | SVR_IP         | SVR_PORT |
    +---------------+---------+------+----------------+----------+
    |          1001 |    1001 | z1   | xxx.xx.xxx.198 |     2882 |
    |          1001 |    1002 | z2   | xxx.xx.xxx.196 |     2882 |
    |          1001 |    1003 | z3   | xxx.xx.xxx.204 |     2882 |
    |          1002 |    1004 | z1   | xxx.xx.xxx.194 |     2882 |
    |          1002 |    1005 | z2   | xxx.xx.xxx.192 |     2882 |
    |          1002 |    1006 | z3   | xxx.xx.xxx.197 |     2882 |
    +---------------+---------+------+----------------+----------+
    6 rows in set
    ```

4. 構成パラメータ[enable_rebalance](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2900.enable_rebalance.md)と[enable_transfer](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3100.enable_transfer.md)が無効であるかどうか、つまり値が`False`であるかどうかを確認します。

   ユーザーテナントでは、以下のコマンドを実行して、構成パラメータの値を照会します。

   ```shell
   obclient> SHOW PARAMETERS LIKE '%enable_rebalance%';
   ```

   ```shell
   obclient> SHOW PARAMETERS LIKE '%enable_transfer%';
   ```

   値が`True`の場合は、以下のコマンドを実行して、それぞれの値を`False`に変更します。

   ```shell
   obclient> ALTER SYSTEM SET enable_rebalance = False;
   ```

   ```shell
   obclient> ALTER SYSTEM SET enable_transfer = False;
   ```

## ステップ2：ログストリームの作成

各項目のチェックが要件を満たしていることを確認したら、業務状況に応じて適切な操作を選択し、テナント用のログストリームを作成します。

### システムテナントがユーザーテナントにログストリームを作成する

1. `root` ユーザーでクラスタの `sys` テナントにログインします。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に基づいてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. ログストリームを作成します。

   システムテナントがユーザーテナントにログストリームを作成するためのSQL文は以下のとおりです：

   ```sql
   ALTER SYSTEM CREATE LS {UNIT_GROUP [=] unit_group_id} | {UNIT_LIST [=] (unit_id_list) } [,PRIMARY_ZONE [=] 'zone_name'] TENANT [=] 'tenant_name';
   ```

   文に関する説明は以下のとおりです：

   * `unit_group_id`：作成するログストリームのターゲット `UNIT_GROUP` のIDを指定します。同一構成Zoneモードのテナントにのみ適用されます。`unit_group_id` はシステムテナントで、`oceanbase.DBA_OB_UNITS` ビューを照会することで取得できます。

   * `unit_id_list`：作成するログストリームが配置されるUnitのリストを指定します。異種構成Zoneモードのテナントにのみ適用されます。`unit_id_list` はシステムテナントで、`oceanbase.DBA_OB_UNITS` ビューを照会することで取得できます。各ZoneにはUnitが1つまで配置されます。

   * `zone_name`：ターゲットZoneの名前。`PRIMARY_ZONE` を指定しない場合、システムがテナント内の同一 `UNIT_GROUP`（同一構成Zoneモード）/`UNIT_LIST`（異種構成Zoneモード）内の `PRIMARY_ZONE` を均等に分散するルールに基づいて割り当てます。

   * `tenant_name`：作成するログストリームのターゲットテナントの名前。

   例：

   :::tab
   tab 同構成ゾーンモード

   * IDが1001の`UNIT_GROUP`にログストリームを作成します。

      ```shell
      obclient> ALTER SYSTEM CREATE LS UNIT_GROUP 1001 TENANT = mq_t1;
      ```

      ステートメント実行後、システムは指定された`UNIT_GROUP_ID`が1001（それぞれのUnitは1001、1002、1003に対応）のログストリームを作成します。

   * IDが1001の`UNIT_GROUP`にログストリームを作成し、そのログストリームの`PRIMARY_ZONE`を`z1`に設定します。

      ```shell
      obclient> ALTER SYSTEM CREATE LS UNIT_GROUP 1001, PRIMARY_ZONE 'z1' TENANT = mq_t1;
      ```

      ステートメント実行後、システムは指定された`UNIT_GROUP_ID`が1001（それぞれのUnitは1001、1002、1003に対応）のログストリームを作成し、そのプライマリゾーンを`z1`に設定します。

   tab 異種ゾーンモード

   * `UNIT_ID` がそれぞれ1001、1002、1003の `UNIT_LIST` にログストリームを作成します。

      ```shell
      obclient> ALTER SYSTEM CREATE LS UNIT_LIST (1001,1002,1003) TENANT = mq_t1;
      ```

      ステートメント実行後、システムは指定された1001、1002、1003の `UNIT_LIST` にログストリームを作成します。

   * `UNIT_ID` がそれぞれ1001、1002、1003の `UNIT_LIST` にログストリームを作成し、そのログストリームの `PRIMARY_ZONE` を `z1` に設定します。

      ```shell
      obclient> ALTER SYSTEM CREATE LS UNIT_LIST (1001,1002,1003), PRIMARY_ZONE 'z1' TENANT = mq_t1;
      ```

      ステートメント実行後、システムは指定された1001、1002、1003の `UNIT_LIST` にログストリームを作成し、そのプライマリゾーンを `z1` に設定します。

   :::

3. 作成したログストリームを確認します。

   1. 新規作成したログストリームの `LS_ID` を取得します。

      ```shell
      obclient> SELECT * FROM oceanbase.CDB_OB_TENANT_EVENT_HISTORY WHERE EVENT='CREATE LS' AND TENANT_ID=1002 ORDER BY TIMESTAMP DESC LIMIT 1\G
      ```

      クエリ結果の例は以下のとおりです：

      ```shell
      *************************** 1. row ***************************
       TENANT_ID: 1002
       TIMESTAMP: 2025-06-19 11:31:14.284278
          MODULE: LS COMMAND
           EVENT: CREATE LS
           NAME1: ARGS
          VALUE1: {op:1, op str:"CREATE LS", tenant_id:1002, ls_id:{id:-1}, unit_group_id:1001, ls_primary_zone:"z1"}
           NAME2: LS_ID
          VALUE2: 1003
           NAME3: LS_GROUP_ID
          VALUE3: 1002
           NAME4: UNIT_GROUP_ID
          VALUE4: 1001
           NAME5: PRIMARY_ZONE
          VALUE5: z1
           NAME6: NULL
          VALUE6:
      EXTRA_INFO: NULL
          SVR_IP: 6.xx.xxx.xxx
        SVR_PORT: 13324
        TRACE_ID: Y3xxxxxxxxxxx-xxxxxxxxxxxxxxx-x-x
       COST_TIME: 19407
        RET_CODE: 0
       ERROR_MSG: NULL
      1 row in set
      ```

      クエリ結果から、新規作成したログストリームの `LS_ID` は1003であることがわかります。

   2. 新規作成したログストリームの詳細情報を確認します。

      ```shell
      obclient> SELECT LS_ID, STATUS, PRIMARY_ZONE, LS_GROUP_ID, UNIT_LIST FROM oceanbase.CDB_OB_LS WHERE TENANT_ID=1002 AND LS_ID = 1003;
      ```

      クエリ結果の例は以下のとおりです：

      ```shell
      +-------+--------+--------------+-------------+----------------+
      | LS_ID | STATUS | PRIMARY_ZONE | LS_GROUP_ID | UNIT_LIST      |
      +-------+--------+--------------+-------------+----------------+
      |  1003 | NORMAL | z1;z2,z3     |        1001 | 1001,1002,1003 |
      +-------+--------+--------------+-------------+----------------+
      1 row in set
      ```

      クエリ結果から、新規作成したログストリームの状態が `NORMAL` であり、プライマリZoneが `z1` であり、1001、1002、1003の `UNIT_LIST`（同一構成Zoneモードでは、`UNIT_GROUP_ID` が同一のUnitグループに対応）に配置されていることがわかります。これは予想される結果と一致しており、ログストリームの作成は成功しました。

### ユーザーテナントが自身のログストリームを作成する

1. MySQLモードまたはOracleモードのテナント管理者がデータベースに接続します。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に基づいてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mq_t1#obdemo -p***** -A
   ```

2. ログストリームを作成します。

   ユーザーテナントがログストリームを作成するためのSQL文は以下のとおりです：

   ```sql
   ALTER SYSTEM CREATE LS {UNIT_GROUP [=] unit_group_id} | {UNIT_LIST [=] (unit_id_list) } [,PRIMARY_ZONE [=] 'zone_name'];
   ```

   文に関する説明は以下のとおりです：

   * `unit_group_id`：作成対象のログストリームのターゲット`UNIT_GROUP`のIDを指定します。同一構成Zoneモードのテナントにのみ適用されます。`unit_group_id`はシステムテナントで、`oceanbase.DBA_OB_UNITS`ビューを照会することで取得できます。

   * `unit_id_list`：作成対象のログストリームが配置されるUnitのリストを指定します。異種構成Zoneモードのテナントにのみ適用されます。`unit_id_list`はシステムテナントで、`oceanbase.DBA_OB_units`ビューを照会することで取得できます。各Zoneには最大1つのUnitまで指定可能です。

   * `zone_name`：ターゲットZoneの名前。`PRIMARY_ZONE`を指定しない場合、システムがテナント内の同一`UNIT_GROUP`(同一構成Zoneモード)/`UNIT_LIST`(異種構成Zoneモード)内の`PRIMARY_ZONE`を均等に分散するルールに基づいて割り当てます。

   例：

   :::tab

      ステートメント実行後、システムは指定された`UNIT_GROUP_ID`が1001（それぞれのユニットは1001、1002、1003に対応）のログストリームを作成し、そのプライマリゾーンを`z1`に設定します。

   * `UNIT_ID` がそれぞれ1001、1002、1003の `UNIT_LIST` にログストリームを作成し、そのログストリームの `PRIMARY_ZONE` を `z1` に設定します。
