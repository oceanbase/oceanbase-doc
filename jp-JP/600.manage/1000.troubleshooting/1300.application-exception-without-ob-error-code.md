# アプリケーション例外 -- エラーメッセージにOceanBaseのエラーコードが含まれない場合

データベースは運用中にさまざまな例外状況が発生することがあります。例えば、アプリケーションエラー、データベース接続エラー、データベース権限問題、データベースリソース問題、ネットワーク問題などです。これらすべての状況の中で、アプリケーション例外というものがありますが、そのエラーメッセージにはOBのエラーコードが含まれていません。このような問題では、問題とOceanBaseデータベースとの関連性を判断することが一般的に難しく、そのためトラブルシューティングの方向性が不明確になることが多いです。

皆様がこのようなシナリオでの問題の根本原因を迅速に特定し、効率的に解決できるよう支援するために、ここでは明確で実用的な、アプリケーション例外でありながらエラーメッセージにOceanBaseのエラーコードが含まれない場合のエラー調査プロセスをまとめました。このプロセスは明確な操作手順を提供し、問題処理の効率を向上させ、業務への影響を可能な限り低減することを目指しており、日常的な運用保守作業を強力にサポートします。

## プロセスの紹介

アプリケーションの実行に異常が発生し、エラーメッセージにOceanBaseのエラーコード情報が含まれていない場合は、このプロセスに従って問題のトラブルシューティングを行うことができます。

アプリケーション側のエラーロジックを分析し、接続切断の異常が発生しているかどうかを判断します：

* はいの場合は、[アプリケーションの接続切断問題のトラブルシューティング](1500.application-disconnection.md)ドキュメントを参照してトラブルシューティングを行います。

* いいえの場合は、再現可能かどうかをさらに判断します：

  * はいの場合は、プログラムコードのデバッグやネットワークパケットキャプチャ分析（例：tcpdumpなど）などの手段を用いて、プログラムコードのエラー原因を分析し、問題のトリガーロジックを明確にするための分析方向を確認します。

  * いいえの場合は、既存の情報とプログラム自体のロジックを組み合わせて、エラー原因を推測し、問題のトリガーロジックを明確にするための分析方向を確認します。

## 典型的なケース

:::tab
タブ 一般（モードを問わない）

* データベース接続が異常に切断されました。具体的なトラブルシューティングの手順については、[SQL実行エラー：接続が切断されました](https://www.oceanbase.com/knowledge-base/odc-1000000000262290?back=kb)を参照してください。

* ユーザーが分散クラスタ環境で複数のIPアドレスを設定し、複数のIPアドレスからクラスタに接続してログインしたい場合。具体的なトラブルシューティングの手順については、[OBClientクライアントツールは複数のIP接続ログインをどのようにサポートするのか](https://www.oceanbase.com/knowledge-base/oceanbase-database-1000000000683684)を参照してください。

* OceanBaseデータベースが業務の`commit`を実行する際、以下の例外エラーが発生しました：`Transaction resolution unknown`。具体的なトラブルシューティングの手順については、[アプリケーションエラー：Transaction resolution unknown](https://www.oceanbase.com/knowledge-base/oceanbase-database-1000000000322510)を参照してください。

* アプリケーション側からのフィードバック：大量データのインポート時に、アプリケーションログに`Connection is closed & Connection reset`というエラーが表示されます。具体的なトラブルシューティングの手順については、[OBProxyがメモリ使用量の上限を超えたためアプリケーションエラーが発生：Connection reset](https://www.oceanbase.com/knowledge-base/oceanbase-database-proxy-1000000000210042?back=kb)を参照してください。

* ビジネスがテスト環境で実行される際、アプリケーション側からSQLの平均実行時間は2msと観測されましたが、本番環境で実行されると実行時間は30〜40msに変化しました。しかし、データベース内のSQL実行時間は増加していません。具体的なトラブルシューティングの手順については、[アプリケーション側のSQL実行時間がデータベース内よりも大幅に高い問題](https://www.oceanbase.com/knowledge-base/oceanbase-database-proxy-1000000000210045?back=kb)を参照してください。

タブ MySQLモード

* クライアントがSQLを実行する際に、直接エラー`Lost connection to MySQL server during query`が報告されます。通常、このようなエラーはサーバー側で異常が発生し、接続が切断されたことによって引き起こされます。具体的なトラブルシューティング手順については、[クライアントエラーLost connection to MySQL server during queryのいくつかの原因](https://www.oceanbase.com/knowledge-base/oceanbase-database-1000000000210010?back=kb)を参照してください。

tab Oracleモード

* システムがOracleデータベースからOceanBaseデータベースのOracleテナントに切り替えた後、JBossでデプロイされたJDBCアプリケーションで接続数不足の問題が発生しました。具体的なトラブルシューティング手順については、[JBossでデプロイされたJDBCアプリケーションで接続数不足の問題が発生した場合](https://www.oceanbase.com/knowledge-base/oceanbase-connector-j-1000000000217899?back=kb)を参照してください。

:::
