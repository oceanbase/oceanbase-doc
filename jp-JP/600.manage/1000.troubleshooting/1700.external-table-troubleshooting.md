# 外部テーブルのよくある質問とトラブルシューティングガイド

## 背景

OBServerがJNIフレームワークを導入し、現在の外部データレイクとの連携を橋渡しするフレームワークとして採用して以来、多くの環境初期化に関連する問題に直面することがあります。

## 問題1：HDFS/ODPS JNI外部テーブルの作成時にエラーが表示される

### エラー1: ERROR 11056: JNI env could not be found

#### 原因

JNI Envの環境初期化が失敗した原因は、以下の可能性があります：

1. `ob_java_home` の設定が誤っており、`libjvm.so` ダイナミックライブラリを正しく読み込めません。このダイナミックライブラリは、環境初期化でJVMを起動するための重要なライブラリです。

2. `ob_java_opts` の設定が誤っています。現在、CPPフレームワークとJNIフレームワークの連携には一定の制限があるため、多くの設定上の問題を避けるために、JVMプロセスを起動するための関連パラメータを強制的に設定する必要があります。パラメータの設定については、[ob_java_opts](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16650.ob_java_opts.md)を参照してください。

3. JNI Env環境が依存する `libhdfs.so` ライブラリファイル（OceanBaseデータベースとJVM間の通信を橋渡しするもの）の配置パスと `_ob_additional_lib_path` が一致していないため、正確に設定する必要があります。

#### 解決策

1. 現在の `java home` 設定が存在するか手動で確認し、特に現在のユーザーがそのパスへのアクセス権限を持っているかを確認します。`java home` は存在するものの、OBServerの起動ユーザーにそのパスへのアクセス権限がない場合があります。

2. [ob_java_opts](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16650.ob_java_opts.md)を参照し、`ob_java_opts` に必須の項目が欠落していないか確認します。

3. `_ob_additional_lib_path` の設定パスが存在するか、およびOBServerの起動ユーザーがそのパスへのアクセス権限を持っているかを確認します。

### エラー2: ERROR 11032: HDFS: path not found

#### 原因

HDFS: path not found エラーが発生する一般的なシナリオは以下のとおりです：

1. Kerberos認証が有効なHDFS環境で、特定のHDFS外部テーブルにアクセスする際、権限不足によりアクセスできない場合、-11032 エラーが発生します。

2. Kerberos認証の設定が正しいにもかかわらず、HDFS: path not found エラーが発生する場合、外部テーブル作成ステートメントで指定された外部テーブルのパスが誤っており、存在しないパスを指している可能性があります。

3. 外部テーブルへのアクセスは初期段階では正常だが、クエリ実行後しばらくして11032 エラーが発生する場合、HDFSの対応する外部テーブルパス下のファイルに不良ブロックが発生している可能性があります。これは、HDFS DataNodeがそのデータブロックにエラーがあり、アクセスできないと報告し、エラーが発生することを引き起こします。

#### 解決策

1. Kerberos認証のkeytabとprincipalが有効であり、対応するユーザーがHDFSクラスタへのアクセス権限を持っていることを確認し、外部テーブルの権限を再設定してKerberos認証を設定します。

2. 対応するHDFSパスが正しく存在することを確認し、外部テーブルのHDFSパスマッピングを再構築します。

3. お客様の運用保守チームにフィードバックし、データの破損ブロック状況を確認した上で、破損ブロックの調整または環境の切り替えによる検証を続行することができます。

### エラー3：ERROR 4016: Internal Error

#### 原因

Internal Errorが発生する原因は、以下の可能性があります：

1. 外部テーブルのクエリ実行時にInternal Errorが発生した場合、外部テーブルの実際の設定型と期待が一致しないことが原因である可能性があります。例えば、`String` 型の列を `Int` 型にマッピングしたことで、一部のフィールドデータの変換に失敗した場合などです。
2. その他の予期しないプログラム実行パスがInternal Errorをトリガーした場合。

#### 解決策

1. 外部テーブルの作成ステートメントおよび対応する外部テーブルデータファイルのメタデータ型マッピングが正しいかどうか確認します。

2. 関連ログを確認し、エラーログのスタックを取得して、エラーが発生した具体的な詳細を確認します。
