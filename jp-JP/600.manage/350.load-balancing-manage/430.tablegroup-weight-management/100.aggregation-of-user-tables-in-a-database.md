# データベース内のユーザーテーブルの集約

ユーザーテーブルの集約とは、同一テナント内の指定されたユーザーテーブルを単一のログストリームにバインドすることを指します。OceanBaseデータベースは、Databaseを`Sharding = 'NONE'`のテーブルグループにバインドすることで、そのDatabase内のすべてのユーザーテーブルの集約を実現します。同様に、複数のDatabaseを同一のテーブルグループにバインドすることで、複数のDatabaseにまたがるユーザーテーブルの集約も実現できます。

## 使用制限

現在、データベース内のユーザーテーブルの集約機能はMySQLモードでのみサポートされており、Oracleモードでは対応していません。

## 新規データベースのユーザーテーブルの自動集約を有効にする

データベース内のユーザーテーブルの自動集約スイッチは、テナントレベルの構成パラメータ`enable_database_sharding_none`によって制御されます。デフォルトは`False`で、データベース内のユーザーテーブルの自動集約は有効ではありません。

ユーザーは業務ニーズに応じて、データベース内のユーザーテーブルの自動集約を有効にすることができます。新規データベースのユーザーテーブルの自動集約を有効にする方法は以下のとおりです：

1. MySQLモードのテナント管理者がデータベースに接続します。

   接続例は以下のとおりですが、データベースへの接続時は実際の環境に準じてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql_tenant#obdemo -p***** -A
   ```

2. テナント構成パラメータ`enable_database_sharding_none`の値を確認します。

   ```shell
   obclient(root@mysql001)[(none)]> SHOW PARAMETERS LIKE '%enable_database_sharding_none%';
   ```

   クエリ結果は次のとおりです：

   ```shell
   +-------+----------+----------------+----------+-------------------------------+-----------+-------+----------------------------------------------------------------------------------------+--------------+--------+---------+-------------------+---------------+-----------+
   | zone  | svr_type | svr_ip         | svr_port | name                          | data_type | value | info                                                                                   | section      | scope  | source  | edit_level        | default_value | isdefault |
   +-------+----------+----------------+----------+-------------------------------+-----------+-------+----------------------------------------------------------------------------------------+--------------+--------+---------+-------------------+---------------+-----------+
   | zone1 | observer | 172.xx.xxx.xxx |     2882 | enable_database_sharding_none | BOOL      | False | Enable automatic creation of sharding none tablegroup for new databases in MySQL mode. | LOAD_BALANCE | TENANT | DEFAULT | DYNAMIC_EFFECTIVE | False         |         1 |
   +-------+----------+----------------+----------+-------------------------------+-----------+-------+----------------------------------------------------------------------------------------+--------------+--------+---------+-------------------+---------------+-----------+
   1 row in set
   ```

3. 構成パラメータ`enable_database_sharding_none`の値を`True`に変更します。

   ```shell
   obclient(root@mysql001)[(none)]> ALTER SYSTEM SET enable_database_sharding_none = True;
   ```

データベース内のユーザーテーブルの自動集約(`enable_database_sharding_none`の値が`True`)を有効にすると、その後そのテナントで作成されるすべてのデータベースは、デフォルトでSharding属性が`NONE`のテーブルグループにバインドされ、テーブルグループ名の形式は`TG_DB_{database_id}`となります。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>データベース内のユーザーテーブルの自動集約を有効にした後：</p>
<ul><li>後から作成されるデータベースにのみ適用され、既存のデータベースには影響しません。</li>
<li>データベース作成時に、デフォルトでバインドされるテーブルグループ名がユーザーが作成したテーブルグループ名と競合する場合、データベースは作成されますが、テーブルグループは自動的にバインドされません。ユーザーは<code>ALTER DATABASE TABLEGROUP</code>ステートメントを使用して、Sharding属性が<code>NONE</code>のテーブルグループを自らバインドする必要があります。</li></ul>
</main>

例えば、データベース内のユーザーテーブルの自動集約を有効にした後、データベース`infotest`を作成したとします。

```shell
obclient(root@mysql001)[(none)]> CREATE DATABASE infotest;
```

ビュー `DBA_OB_DATABASES`(`sys` テナントでビュー `CDB_OB_DATABASES` をクエリ)を使用して、データベースのデフォルトテーブルグループを確認できます。

```shell
obclient(root@mysql001)[(none)]> SELECT * FROM oceanbase.DBA_OB_DATABASES WHERE DATABASE_NAME = 'infotest';
```

```shell
+---------------+---------------+--------------------+-----------+---------+-----------------+
| DATABASE_NAME | IN_RECYCLEBIN | COLLATION          | READ_ONLY | COMMENT | TABLEGROUP_NAME |
+---------------+---------------+--------------------+-----------+---------+-----------------+
| infotest      | NO            | utf8mb4_general_ci | NO        |         | TG_DB_500004    |
+---------------+---------------+--------------------+-----------+---------+-----------------+
1 row in set
```

クエリ結果によると、このデータベースのデフォルトテーブルグループは `TG_DB_500004` です。ここで、`500004` はデータベースのIDです。

## 複数のデータベースにまたがるユーザーテーブルの集約を設定する

ユーザーは、複数のデータベースの `TABLEGROUP` プロパティを変更し、同じ `Sharding = 'NONE'` のテーブルグループにバインドすることで、複数のデータベースにまたがるユーザーテーブルの集約を実現できます。

操作手順は以下のとおりです：

1. MySQLテナントのテナント管理者がデータベースに接続します。

   接続例は以下のとおりですが、データベースへの接続時は実際の環境に準じてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql_tenant#obdemo -p***** -A
   ```

2. 以下のコマンドを実行して、対象データベースの `TABLEGROUP` プロパティを変更します。

   ステートメントは以下のとおりです：

   ```sql
   ALTER DATABASE [database_name] TABLEGROUP [=] tablegroup_name;
   ```

   ここで：

   * `database_name`：対象データベースの名前。オプションです。明示的に指定しない場合、変更対象のデータベースは現在のデータベースを意味します。

   * `tablegroup_name`：Shardingプロパティが `NONE` のテーブルグループ名。

   * このステートメントは、対象データベース内のすべてのテーブルの `TABLEGROUP` プロパティを変更します。

   * 対象データベース内に、テーブルグループのSharding要件を満たせない分布を持つテーブルが存在する場合、ステートメントの実行はエラーになります。

   例：

   ```shell
   obclient(root@mysql001)[infotest]> ALTER DATABASE infotest TABLEGROUP =tg_test;
   ```

3. ビュー `DBA_OB_DATABASES`(`sys` テナントでビュー `CDB_OB_DATABASES` をクエリ)を使用して、テーブルグループが正常に変更されたかどうかを確認します。

   ```shell
   obclient(root@mysql001)[(none)]> SELECT * FROM oceanbase.DBA_OB_DATABASES WHERE DATABASE_NAME = 'infotest';
   ```

   クエリ結果は次のとおりです：

   ```shell
   +---------------+---------------+--------------------+-----------+---------+-----------------+
   | DATABASE_NAME | IN_RECYCLEBIN | COLLATION          | READ_ONLY | COMMENT | TABLEGROUP_NAME |
   +---------------+---------------+--------------------+-----------+---------+-----------------+
   | infotest      | NO            | utf8mb4_general_ci | NO        |         | tg_test         |
   +---------------+---------------+--------------------+-----------+---------+-----------------+
   1 row in set
   ```

4. 上記の操作を繰り返し、複数のターゲットデータベースを同じテーブルグループにバインドします。

## 次のステップ

データベースの `tablegroup` プロパティを変更しても、システムはすぐにすべてのユーザーテーブルのパーティションを同じログストリームに整列させるわけではありません。ユーザーがユーザーテーブルの集約を早急に実行したい場合は、`DBMS_BALANCE.TRIGGER_PARTITION_BALANCE` サブプログラムを呼び出して、手動で一度パーティションの均衡をトリガーできます。手動でパーティションの均衡をトリガーする詳細な操作については、[パーティションの均衡を手動でトリガーする](../600.partition-balance-management/200.manually-trigger-a-partition-balancing-task.md)を参照してください。

または、ユーザーは定期的なパーティション均衡タスクのトリガーを待つこともできます。定期的なパーティション均衡タスクの詳細については、[定期的なパーティション均衡タスクの設定](../600.partition-balance-management/100.configure-a-scheduled-partition-balancing-task.md)を参照してください。
