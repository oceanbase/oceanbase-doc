# パーティションの手動バランス調整

定期的なパーティションのバランス調整タスクを設定するほかに、`DBMS_BALANCE` システムパッケージの `TRIGGER_PARTITION_BALANCE` サブプログラムを手動で呼び出して、一時的なパーティションのバランス調整をトリガーすることもできます。

## 使用制限

ユーザーテナントのみがパーティションの手動バランス調整をサポートしており、sysテナントはサポートしていません。

## 注意事項

* システム内で他のバランス調整タスクが実行されている場合は、パーティションの手動バランス調整タスクをトリガーできません。現在のバランス調整タスクが完了するまで待ってから、手動でのパーティションのバランス調整操作を実行してください。

   sysテナントはビュー [CDB_OB_BALANCE_JOBS](../../../700.reference/700.system-views/300.system-view-of-sys-tenant/200.dictionary-view-of-sys-tenant/7800.o-cdb_ob_balance_jobs-of-sys-tenant.md) を使用して、指定したテナントで他の進行中のバランス調整タスクがあるかどうかを確認できます。ユーザーテナントは [DBA_OB_BALANCE_JOBS](../../../700.reference/700.system-views/400.system-view-of-mysql-mode/200.dictionary-view-of-mysql-mode/7800.o-dba_ob_balance_jobs-of-mysql-mode.md) ビューを使用して、他の進行中のバランス調整タスクがあるかどうかを確認できます。

* パーティションの手動バランス調整を実行する前に、テナントレベルの構成パラメータ `enable_rebalance` と `enable_transfer` の値がどちらも `True` であることを確認する必要があります。いずれか一方のパラメータの値が `True` でない場合、パーティションの手動バランス調整コマンドは実行失敗します。

* 現在のテナントのパーティションがすでにバランスが取れている場合、システムは `partitions are already balanced, no need to trigger partition balance` のエラーメッセージを表示します。

## パーティションの手動バランス調整のトリガー

1. テナント管理者がクラスタのMySQLテナントまたはOracleテナントにログインします。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に従ってください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql_tenant#obdemo -p***** -A
   ```

2. `DBMS_BALANCE` システムパッケージの `TRIGGER_PARTITION_BALANCE` サブプログラムを呼び出して、一時的なパーティションのバランス調整をトリガーします。

    :::tab
    tab MySQLモード

    MySQLモードのステートメントは以下のとおりです：

    ```sql
    CALL DBMS_BALANCE.TRIGGER_PARTITION_BALANCE(balance_timeout);
    ```

    ここで、`balance_timeout` はバックグラウンドのパーティションバランス調整タスクの実行タイムアウト時間を秒単位で制御します。この値を指定しない場合、バックグラウンドのパーティションバランス調整タスク（手動でトリガーされたものと定期的にトリガーされたものの両方）にはタイムアウト時間がなく、タスクが完了するまで継続的に実行されます。

    例：

    * パーティションのバランスを一度だけ手動でトリガーし、バックグラウンドのパーティションバランス調整タスクにタイムアウト時間を設定しない場合。

      ```shell
      obclient [oceanbase]> CALL DBMS_BALANCE.TRIGGER_PARTITION_BALANCE();
      ```

    * パーティションのバランスを1回トリガーし、バックグラウンドのパーティションバランスタスクのタイムアウト時間を7200秒に設定します。

      ```shell
      obclient [oceanbase]> CALL DBMS_BALANCE.TRIGGER_PARTITION_BALANCE(7200);
      ```

    `DBMS_BALANCE` システムパッケージの `TRIGGER_PARTITION_BALANCE` サブプログラムの詳細については、[TRIGGER_PARTITION_BALANCE](../../../700.reference/600.pl-reference/200.pl-mysql/1000.pl-system-package-mysql/20800.dbms-balance-mysql/200.trigger-partition-balance-mysql.md)を参照してください。

    tab Oracleモード

    Oracleモードのステートメントは以下のとおりです：

    ```sql
    BEGIN
        DBMS_BALANCE.TRIGGER_PARTITION_BALANCE(balance_timeout);
    END;
    ```

    ここで、`balance_timeout` はバックグラウンドのパーティションバランスタスクの実行タイムアウト時間を制御するために使用され、単位は秒です。この値を指定しない場合、手動でトリガーされたものとタイマーでトリガーされたものを含む、すべてのバックグラウンドのパーティションバランスタスクにはタイムアウト時間がなく、タスクが完了するまで継続的に実行されます。

    例：

    * パーティションのバランスを1回トリガーし、バックグラウンドのパーティションバランスタスクにタイムアウト時間を設定しません。

      ```shell
      obclient [SYS]> DELIMITER //
      ```

      ```shell
      obclient [SYS]> BEGIN
          DBMS_BALANCE.TRIGGER_PARTITION_BALANCE();
      END;//
      ```

      ```shell
      obclient [SYS]> DELIMITER ;
      ```

    * パーティションのバランスを1回トリガーし、バックグラウンドのパーティションバランスタスクのタイムアウト時間を7200秒に設定します。

      ```shell
      obclient [SYS]> DELIMITER //
      ```

      ```shell
      obclient [SYS]> BEGIN
          DBMS_BALANCE.TRIGGER_PARTITION_BALANCE(7200);
      END;//
      ```

      ```shell
      obclient [SYS]> DELIMITER ;
      ```

    `DBMS_BALANCE` システムパッケージの `TRIGGER_PARTITION_BALANCE` サブプログラムの詳細については、[TRIGGER_PARTITION_BALANCE](../../../700.reference/600.pl-reference/300.pl-oracle/1400.pl-system-package-oracle/2700.dbms-balance-oracle/200.trigger-paptition-balance-oracle.md)を参照してください。

    :::

## 次のステップ

手動でパーティションのバランスをトリガーした後、実際のパーティション移動はバックグラウンドのバランスタスクによって非同期で実行されます。ユーザーはビューを通じてパーティションバランスタスクの実行状況を確認できます。具体的な操作については、[バックグラウンドのパーティションバランスタスクの確認](500.view-background-partition-balancing-task.md)を参照してください。
