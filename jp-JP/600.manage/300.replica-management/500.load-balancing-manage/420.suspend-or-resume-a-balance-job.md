# バランスジョブの一時停止と再開

テナントで実行中のバランスジョブがある場合、他に緊急の変更が必要になった場合、そのバランスジョブの実行が緊急変更に影響を与えないようにするため、ユーザーは現在実行中のバランスジョブを一時停止し、緊急変更が完了した後に再開して実行を続けることができます。

## 制限

* V4.2.5バージョンでは、V4.2.5 BP2以降のバージョンからBalance Jobの一時停止および再開がサポートされます。

* Balance Jobの一時停止または再開の操作は、プライマリデータベース（すなわちプライマリテナント）でのみ実行できます。

* Balance Jobを一時停止または再開する際には、そのBalance Jobのステータスが`CANCELING`であってはなりません。

## 実行中のBalance Jobを一時停止する

### システムテナントがユーザーテナントで実行中のBalance Jobを一時停止する

1. `root` ユーザーでクラスタの `sys` テナントにログインします。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に基づいてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. テナント関連情報を取得します。

   ```shell
   obclient> SELECT TENANT_ID, TENANT_NAME, TENANT_ROLE FROM oceanbase.DBA_OB_TENANTS WHERE tenant_name = 'mq_t1';
   ```

   クエリ結果の例は次のとおりです：

   ```shell
   +-------------+-----------+-------------+
   | TENANT_NAME | TENANT_ID | TENANT_ROLE |
   +-------------+-----------+-------------+
   | mq_t1       |      1002 | PRIMARY     |
   +-------------+-----------+-------------+
   1 row in set
   ```

3. ビュー `CDB_OB_BALANCE_JOBS` を照会して、現在実行中のタスクとその状態を取得します。

   ```shell
   obclient [oceanbase]> SELECT TENANT_ID, JOB_ID, JOB_TYPE, STATUS FROM oceanbase.CDB_OB_BALANCE_JOBS WHERE TENANT_ID = 1002;
   ```

   クエリ結果の例は次のとおりです：

   ```shell
   +-----------+--------+--------------------+--------+
   | TENANT_ID | JOB_ID | JOB_TYPE           | STATUS |
   +-----------+--------+--------------------+--------+
   |      1002 |  62944 | TRANSFER_PARTITION | DOING  |
   +-----------+--------+--------------------+--------+
   1 row in set
   ```

   クエリ結果によると、現在のBalance Jobの状態は `DOING` であり、`CANCELING` ではないため、このJobを一時停止できます。

4. 以下のステートメントを実行して、このBalance Jobを一時停止します。

   ```sql
   ALTER SYSTEM SUSPEND BALANCE JOB TENANT = 'tenant_name';
   ```

   例：

   ```shell
   obclient [oceanbase]> ALTER SYSTEM SUSPEND BALANCE JOB TENANT ='mq_t1';
   ```

5. 実行が成功した後、再度ビュー `CDB_OB_BALANCE_JOBS` を照会すると、現在のタスクの状態が `SUSPEND` に変更されていることが確認できます。

   ```shell
   obclient [oceanbase]> SELECT TENANT_ID, JOB_ID, JOB_TYPE, STATUS FROM oceanbase.CDB_OB_BALANCE_JOBS WHERE TENANT_ID = 1002;
   ```

   クエリ結果は次のとおりです：

   ```shell
   +-----------+--------+--------------------+---------+
   | TENANT_ID | JOB_ID | JOB_TYPE           | STATUS  |
   +-----------+--------+--------------------+---------+
   |      1002 |  62944 | TRANSFER_PARTITION | SUSPEND |
   +-----------+--------+--------------------+---------+
   1 row in set
   ```

### ユーザーテナントが自身のテナントで実行中のBalance Jobを一時停止する

1. MySQLモードまたはOracleモードのテナント管理者がデータベースに接続します。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に基づいてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql_tenant#obdemo -p***** -A
   ```

2. ビュー`DBA_OB_BALANCE_JOBS`を照会し、現在実行中のタスクとその状態を取得します。

   :::tab
   tab MySQLモード

   MySQLモードのクエリステートメントは以下のとおりです：

   ```shell
   obclient [oceanbase]> SELECT JOB_ID, JOB_TYPE, STATUS FROM oceanbase.DBA_OB_BALANCE_JOBS;
   ```

   tab Oracleモード

   Oracleモードでのクエリステートメントは以下のとおりです：

   ```shell
   obclient [SYS]> SELECT JOB_ID, JOB_TYPE, STATUS FROM SYS.DBA_OB_BALANCE_JOBS;
   ```

   :::

   照会結果の例は次のとおりです：

   ```shell
   +--------+--------------------+---------+
   | JOB_ID | JOB_TYPE           | STATUS  |
   +--------+--------------------+---------+
   |  62944 | TRANSFER_PARTITION |   DOING |
   +--------+--------------------+---------+
   1 row in set
   ```

   照会結果によると、現在のBalance Jobの状態は`DOING`であり、`CANCELING`ではないため、このJobを一時停止できます。

3. 以下のステートメントを実行して、このBalance Jobを一時停止します。

   ```shell
   obclient> ALTER SYSTEM SUSPEND BALANCE JOB;
   ```

4. 実行が成功した後、再度ビュー`DBA_OB_BALANCE_JOBS`を照会すると、現在のタスクの状態が`SUSPEND`に変更されていることが確認できます。

   :::tab
   tab MySQLモード

   MySQLモードのクエリステートメントは以下のとおりです：

   ```shell
   obclient [oceanbase]> SELECT JOB_ID, JOB_TYPE, STATUS FROM oceanbase.DBA_OB_BALANCE_JOBS;
   ```

   tab Oracleモード

   Oracleモードにおけるクエリステートメントは以下のとおりです：

   ```shell
   obclient [SYS]> SELECT JOB_ID, JOB_TYPE, STATUS FROM SYS.DBA_OB_BALANCE_JOBS;
   ```

   :::
