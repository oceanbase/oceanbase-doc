# パーティションの手動バランス調整

定期的なパーティションバランス調整タスクを設定するほかに、`DBMS_BALANCE` システムパッケージ内の `TRIGGER_PARTITION_BALANCE` サブルーチンを手動で呼び出すことで、一度だけパーティションのバランス調整をトリガーすることもできます。

## 制限事項

パーティションの手動バランシングはユーザーテナントのみでサポートされており、sysテナントではサポートされていません。

## 注意事項

* システム内で他のバランシングタスクが実行中の場合、パーティションの手動バランシングタスクを開始することはできません。現在のバランシングタスクが完了してから、パーティションの手動バランシング操作を実行する必要があります。

   sysテナントは、ビュー[CDB_OB_BALANCE_JOBS](../../../../700.reference/700.system-views/300.system-view-of-sys-tenant/200.dictionary-view-of-sys-tenant/7400.o-cdb_ob_balance_jobs-of-sys-tenant.md)を使用して、指定されたテナントに他の進行中のバランシングタスクがあるかどうかを確認できます。ユーザーテナントは、[DBA_OB_BALANCE_JOBS](../../../../700.reference/700.system-views/400.system-view-of-mysql-mode/200.dictionary-view-of-mysql-mode/7500.o-dba_ob_balance_jobs-of-mysql-mode.md)ビューを使用して、他の進行中のバランシングタスクがあるかどうかを確認できます。

* パーティションの手動バランシングを開始する前に、テナントレベルの構成パラメータ`enable_rebalance`と`enable_transfer`の値がどちらも`True`であることを確認する必要があります。いずれか一方の構成パラメータの値が`True`でない場合、パーティションの手動バランシングを開始するコマンドの実行は失敗します。

* 現在のテナントのパーティションがすでにバランスが取れている場合、システムは`partitions are already balanced, no need to trigger partition balance`というエラーメッセージを表示します。

## パーティションの手動バランス調整

1. テナント管理者がクラスタのMySQLテナントまたはOracleテナントにログインします。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に基づいてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql_tenant#obdemo -p***** -A
   ```

2. `DBMS_BALANCE` システムパッケージ内の `TRIGGER_PARTITION_BALANCE` サブルーチンを呼び出して、パーティションのバランス調整をトリガーします。

    :::tab
    タブ MySQLモード

    MySQLモードのステートメントは以下のとおりです：

    ```sql
    CALL DBMS_BALANCE.TRIGGER_PARTITION_BALANCE(balance_timeout);
    ```

    ここで、`balance_timeout` はバックグラウンドのパーティション均衡タスクの実行に対するタイムアウト時間を秒単位で制御します。この値が指定されていない場合、手動でトリガーされるパーティション均衡タスクと定期的にトリガーされるパーティション均衡タスクの両方について、タイムアウト時間はなく、タスクが完了するまで実行し続けます。

    例：

    * パーティション均衡を一度トリガーし、バックグラウンドのパーティション均衡タスクにタイムアウト時間を設定しません。

      ```shell
      obclient [oceanbase]> CALL DBMS_BALANCE.TRIGGER_PARTITION_BALANCE();
      ```

    * パーティション均衡を一度トリガーし、バックグラウンドのパーティション均衡タスクのタイムアウト時間を7200秒に設定します。

      ```shell
      obclient [oceanbase]> CALL DBMS_BALANCE.TRIGGER_PARTITION_BALANCE(7200);
      ```

    `DBMS_BALANCE` システムパッケージ内の `TRIGGER_PARTITION_BALANCE` サブルーチンの詳細については、[TRIGGER_PARTITION_BALANCE](../../../../700.reference/500.sql-reference/300.pl-reference/200.pl-mysql/1000.pl-system-package-mysql/20800.dbms-balance-mysql/200.trigger-partition-balance-mysql.md)を参照してください。

    tab Oracleモード

    Oracleモードのステートメントは以下のとおりです：

    ```sql
    BEGIN
        DBMS_BALANCE.TRIGGER_PARTITION_BALANCE(balance_timeout);
    END;
    ```

    ここで、`balance_timeout` はバックグラウンドのパーティション再均衡タスクの実行に対するタイムアウト時間を秒単位で制御します。この値が指定されていない場合、手動でトリガーされるパーティション再均衡タスクと定期的にトリガーされるパーティション再均衡タスクの両方について、タイムアウト時間はなく、タスクの実行完了まで継続的に実行されます。

    例：

    * パーティション再均衡を一度トリガーし、バックグラウンドのパーティション再均衡タスクにタイムアウト時間を設定しません。

      ```shell
      obclient [SYS]> DELIMITER //
      ```

      ```shell
      obclient [SYS]> BEGIN
          DBMS_BALANCE.TRIGGER_PARTITION_BALANCE();
      END;//
      ```

      ```shell
      obclient [SYS]> DELIMITER ;
      ```

    * パーティション再均衡を一度トリガーし、バックグラウンドのパーティション再均衡タスクのタイムアウト時間を7200秒に設定します。

      ```shell
      obclient [SYS]> DELIMITER //
      ```

      ```shell
      obclient [SYS]> BEGIN
          DBMS_BALANCE.TRIGGER_PARTITION_BALANCE(7200);
      END;//
      ```

      ```shell
      obclient [SYS]> DELIMITER ;
      ```

    `DBMS_BALANCE` システムパッケージ内の `TRIGGER_PARTITION_BALANCE` サブルーチンの詳細については、[TRIGGER_PARTITION_BALANCE](../../../../700.reference/500.sql-reference/300.pl-reference/300.pl-oracle/1400.pl-system-package-oracle/2700.dbms-balance-oracle/200.trigger-paptition-balance-oracle.md)を参照してください。

    :::

## 次のステップ

パーティションの手動バランシングがトリガーされると、実際のパーティション移行はバックグラウンドのバランシングタスクによって非同期で実行されます。ユーザーはビューを通じてパーティションバランシングタスクの実行状況を確認できます。詳細な操作については、[バックグラウンドのパーティションバランシングタスクの表示](500.view-background-partition-balancing-task.md)を参照してください。
