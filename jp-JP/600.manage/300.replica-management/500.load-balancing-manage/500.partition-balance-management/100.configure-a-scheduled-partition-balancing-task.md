# 定時パーティション均衡タスクの設定

OceanBaseデータベースでは、ユーザーテナントを作成する際に、システムに組み込まれた定時パーティション均衡タスク`SCHEDULED_TRIGGER_PARTITION_BALANCE`が自動的に設定されます。デフォルトでは毎日00:00にパーティションの均衡処理が実行されます。ユーザーは`DBMS_SCHEDULER`システムパッケージのサブルーチンを使用して、定時パーティション均衡タスクの各種パラメータを設定できます。

## 制限事項

システムテナント（sysテナント）では、定期的なパーティションバランシングタスクの設定はサポートされていません。

## 定期的なパーティションバランシングタスクの有効化

現在のバージョンで新規作成されたユーザーテナントについては、デフォルトで定期的なパーティションバランシングタスクが有効になっており、再度有効化する必要はありません。V4.2.3以前のバージョンから現在のバージョンにアップグレードされたユーザーテナントについては、デフォルトで定期的なパーティションバランシングタスクが無効になっています。以下の手順を参照して、定期的なパーティションバランシングタスクを有効にすることができます。

1. テナント管理者がクラスタのMySQLテナントまたはOracleテナントにログインします。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に基づいてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql_tenant#obdemo -p***** -A
   ```

2. テナントレベルの構成パラメータ`partition_balance_schedule_interval`の値が`0s`であるかどうか確認します。

   定期的なパーティションバランシングタスク`SCHEDULED_TRIGGER_PARTITION_BALANCE`を有効にする前に、自動トリガーによるパーティションバランシングタスクが無効であることを確認する必要があります。これは、テナントレベルの構成パラメータ`partition_balance_schedule_interval`の値が`0`であることを意味します。

   テナントレベルの構成パラメータ`partition_balance_schedule_interval`が`0s`であるかどうかを確認し、もしそうでない場合は、その値を`0s`に設定します。ステートメントは以下のとおりです。

   ```shell
   obclient> SHOW PARAMETERS LIKE '%partition_balance_schedule_interval%';
   ```

   ```shell
   obclient> ALTER SYSTEM SET partition_balance_schedule_interval='0s';
   ```

3. `DBMS_SCHEDULER`システムパッケージの`ENABLE`サブルーチンを呼び出して、定期的なパーティションバランシングタスク`SCHEDULED_TRIGGER_PARTITION_BALANCE`を有効にします。

   :::tab
   tab MySQLモード

   MySQLモードのテナントで定期的なパーティション均衡タスクを有効にする例は以下のとおりです：

   ```shell
   obclient [oceanbase]> CALL DBMS_SCHEDULER.ENABLE('SCHEDULED_TRIGGER_PARTITION_BALANCE');
   ```

   tab Oracleモード

   Oracleモードのテナントで定期パーティション均衡タスクを有効にする例は以下のとおりです：

   ```shell
   obclient [SYS]> DELIMITER //
   ```

   ```shell
   obclient [SYS]> BEGIN
        DBMS_SCHEDULER.ENABLE('SCHEDULED_TRIGGER_PARTITION_BALANCE');
   END;//
   ```

   ```shell
   obclient [SYS]> DELIMITER ;
   ```

   `ENABLE`サブルーチンの詳細については、[ENABLE](../../../../700.reference/500.sql-reference/300.pl-reference/300.pl-oracle/1400.pl-system-package-oracle/14200.dbms-scheduler-oracle/800.enable-scheduler-oracle.md)を参照してください。

   :::

## 定時パーティション均衡タスクの無効化

現行バージョンで新規作成されたユーザーテナントについては、デフォルトで定時パーティション均衡タスクが有効になっています。また、業務上の必要に応じて、定時パーティション均衡タスクを無効にすることも可能です。定時パーティション均衡タスクを無効にした後でも、構成パラメータ `partition_balance_schedule_interval` を `0s` より大きい値に設定することで自動トリガー、または手動トリガーによりパーティション均衡タスクを開始できます。

1. テナント管理者がクラスタのMySQLテナントまたはOracleテナントにログインします。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に基づいてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql_tenant#obdemo -p***** -A
   ```

2. `DBMS_SCHEDULER` システムパッケージの `DISABLE` サブルーチンを呼び出し、定時パーティション均衡タスク `SCHEDULED_TRIGGER_PARTITION_BALANCE` を無効にします。

   :::tab
   tab MySQLモード

   MySQLモードのテナントで定期パーティション均衡タスクを無効にする例は以下のとおりです：

   ```shell
   obclient [oceanbase]> CALL DBMS_SCHEDULER.DISABLE('SCHEDULED_TRIGGER_PARTITION_BALANCE');
   ```

   tab Oracleモード

   Oracleモードのテナントで定期パーティション均衡タスクを無効にする例は以下のとおりです：

   ```shell
   obclient [SYS]> DELIMITER //
   ```

   ```shell
   obclient [SYS]> BEGIN
        DBMS_SCHEDULER.DISABLE('SCHEDULED_TRIGGER_PARTITION_BALANCE');
   END;//
   ```

   ```shell
   obclient [SYS]> DELIMITER ;
   ```

   `DISABLE`サブルーチンの詳細については、[DISABLE](../../../../700.reference/500.sql-reference/300.pl-reference/300.pl-oracle/1400.pl-system-package-oracle/14200.dbms-scheduler-oracle/500.disable-scheduler-oracle.md)を参照してください。

   :::

## 定時パーティション均衡タスクのスケジュール時間の調整

定時パーティション均衡タスクを有効にすると、システムはデフォルトで毎日00:00にパーティション均衡を実行しますが、ユーザーは必要に応じて変更できます。

1. テナント管理者がクラスタのMySQLテナントまたはOracleテナントにログインします。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に基づいてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql_tenant#obdemo -p***** -A
   ```

2. `DBMS_SCHEDULER`システムパッケージの`SET_ATTRIBUTE`サブルーチンを呼び出して、パーティション均衡タスクの次回のスケジュール時間を調整します。たとえば、次回01:00にパーティション均衡を実行するように調整します。

   :::tab
   タブ MySQLモード

   MySQLモードのテナントでは、定時パーティション均衡タスクの実行時間を`2024-06-12 01:00:00`に調整する例は以下のとおりです：

   ```shell
   obclient [oceanbase]> CALL DBMS_SCHEDULER.SET_ATTRIBUTE('SCHEDULED_TRIGGER_PARTITION_BALANCE', 'NEXT_DATE', '2024-06-12 01:00:00');
   ```

   tab Oracleモード

   Oracleモードのテナントでは、定時パーティション均衡タスクの実行時間を`12-Jun-2024 01:00:00`に調整する例は以下のとおりです：

   ```shell
   obclient [SYS]> DELIMITER //
   ```

   ```shell
   obclient [SYS]> BEGIN
        DBMS_SCHEDULER.SET_ATTRIBUTE('SCHEDULED_TRIGGER_PARTITION_BALANCE', 'NEXT_DATE', '12-Jun-2024 01:00:00');
   END;//
   ```

   ```shell
   obclient [SYS]> DELIMITER ;
   ```

   `SET_ATTRIBUTE`サブルーチンの詳細については、[SET_ATTRIBUTE](../../../../700.reference/500.sql-reference/300.pl-reference/300.pl-oracle/1400.pl-system-package-oracle/14200.dbms-scheduler-oracle/1100.set-attribute-oracle.md)を参照してください。

   :::

## 定時パーティション均衡タスクのスケジューリング頻度の調整

デフォルトでは、定時パーティション均衡タスクのスケジューリング頻度は1日1回ですが、ユーザーは必要に応じて変更できます。

1. テナント管理者として、クラスタのMySQLテナントまたはOracleテナントにログインします。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に基づいてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql_tenant#obdemo -p***** -A
   ```

2. `DBMS_SCHEDULER`システムパッケージの`SET_ATTRIBUTE`サブルーチンを呼び出し、パーティション均衡タスクのスケジューリング頻度を調整します。たとえば、2日ごとにパーティション均衡を実行するように調整します。

   :::tab
   タブ MySQLモード

   ステートメントは以下のとおりです：

   ```sql
   CALL DBMS_SCHEDULER.SET_ATTRIBUTE('SCHEDULED_TRIGGER_PARTITION_BALANCE', 'REPEAT_INTERVAL', 'FREQ=str_value; INTERVAL=int_value');
   ```

   その中で：

   * `FREQ`：スケジューリング頻度を指定するための時間単位。サポートされている値は `MINUTELY`（分）、`HOURLY`（時間）、`DAILY`（日）、および `WEEKLY`（週）です。
   * `INTERVAL`：具体的な数値、つまりどのくらいの単位時間ごとにタスクをトリガーするかを指定します。例えば、`FREQ=DAILY; INTERVAL=2` は2日ごとにタスクをトリガーすることを意味します。

   MySQLモードのテナントが定期的なパーティションのバランシングタスクの実行頻度を2日ごとに調整する例は以下のとおりです：

   ```shell
   obclient [oceanbase]> CALL DBMS_SCHEDULER.SET_ATTRIBUTE('SCHEDULED_TRIGGER_PARTITION_BALANCE', 'REPEAT_INTERVAL', 'FREQ=DAILY; INTERVAL=2');
   ```

   tab Oracleモード

   ステートメントは以下のとおりです：

   ```sql
   BEGIN DBMS_SCHEDULER.SET_ATTRIBUTE('SCHEDULED_TRIGGER_PARTITION_BALANCE', 'REPEAT_INTERVAL', 'FREQ=str_value; INTERVAL=int_value');
   END;
   ```

   その中で：

   * `FREQ`：スケジューリング頻度を指定するための時間単位。サポートされている値は `MINUTELY`（分）、`HOURLY`（時間）、`DAILY`（日）、および `WEEKLY`（週）です。
   * `INTERVAL`：具体的な数値、つまりどのくらいの時間ごとにタスクをトリガーするかを指定します。例えば、`FREQ=DAILY; INTERVAL=2` は2日ごとにタスクをトリガーすることを意味します。

   Oracleモードのテナントが定期的なパーティション均衡タスクの実行頻度を2日ごとに調整する例は以下のとおりです：

   ```shell
   obclient [SYS]> DELIMITER //
   ```

   ```shell
   obclient [SYS]> BEGIN
        DBMS_SCHEDULER.SET_ATTRIBUTE('SCHEDULED_TRIGGER_PARTITION_BALANCE', 'REPEAT_INTERVAL', 'FREQ=DAILY; INTERVAL=2');
   END;//
   ```

   ```shell
   obclient [SYS]> DELIMITER ;
   ```

   `SET_ATTRIBUTE` サブルーチンの詳細については、[SET_ATTRIBUTE](../../../../700.reference/500.sql-reference/300.pl-reference/300.pl-oracle/1400.pl-system-package-oracle/14200.dbms-scheduler-oracle/1100.set-attribute-oracle.md)を参照してください。

   :::

## 定時パーティションバランスタスクの単一実行のタイムアウト時間の調整

デフォルトでは、定時パーティションバランスタスクの単一実行にはタイムアウト制限がありません。ユーザーは業務上の実際の状況に応じて変更する必要があります。

定時パーティションバランスタスクの単一実行のタイムアウト時間を調整することは、実際には`TRIGGER_PARTITION_BALANCE`サブルーチンを呼び出すことでトリガーされるすべてのバックグラウンドパーティションバランスタスクの実行タイムアウト時間を調整することになるため、この値を調整すると手動でトリガーされるパーティションバランスタスクにも影響します。手動でパーティションバランスをトリガーする詳細な操作については、[手動でパーティションバランスタスクをトリガーする](200.manually-trigger-a-partition-balancing-task.md)を参照してください。

1. テナント管理者がクラスタのMySQLテナントまたはOracleテナントにログインします。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に基づいてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql_tenant#obdemo -p***** -A
   ```

2. `DBMS_SCHEDULER`システムパッケージの`SET_ATTRIBUTE`サブルーチンを呼び出し、単一タスク実行のタイムアウト時間を調整します。

   :::tab
   タブ MySQLモード

   ステートメントは以下のとおりです：

   ```sql
   CALL DBMS_SCHEDULER.SET_ATTRIBUTE('SCHEDULED_TRIGGER_PARTITION_BALANCE', 'JOB_ACTION', 'DBMS_BALANCE.TRIGGER_PARTITION_BALANCE(balance_timeout)');
   ```

   ここで、`balance_timeout` は単一タスク実行のタイムアウト時間を秒単位で指定します。この値が空の場合、バックグラウンドのバランシングタスクにタイムアウト時間がないことを意味します。

   MySQLモードのテナントが単一タスク実行のタイムアウト時間を7200秒に調整する例は以下のとおりです：

   ```shell
   obclient [oceanbase]> CALL DBMS_SCHEDULER.SET_ATTRIBUTE('SCHEDULED_TRIGGER_PARTITION_BALANCE', 'JOB_ACTION', 'DBMS_BALANCE.TRIGGER_PARTITION_BALANCE(7200)');
   ```

   tab Oracleモード

   ステートメントは以下のとおりです：

   ```sql
   BEGIN DBMS_SCHEDULER.SET_ATTRIBUTE('SCHEDULED_TRIGGER_PARTITION_BALANCE', 'JOB_ACTION', 'DBMS_BALANCE.TRIGGER_PARTITION_BALANCE(balance_timeout)');
   END;
   ```

   ここで、`balance_timeout` は単一タスク実行のタイムアウト時間を秒単位で指定します。この値が空の場合、バックグラウンドのバランシングタスクにタイムアウト時間がないことを意味します。

   Oracleモードのテナントが単一タスク実行のタイムアウト時間を7200秒に調整する例は以下のとおりです：

   ```shell
   obclient [SYS]> DELIMITER //
   ```

   ```shell
   obclient [SYS]> BEGIN
        DBMS_SCHEDULER.SET_ATTRIBUTE('SCHEDULED_TRIGGER_PARTITION_BALANCE', 'JOB_ACTION', 'DBMS_BALANCE.TRIGGER_PARTITION_BALANCE(7200)');
   END;//
   ```

   ```shell
   obclient [SYS]> DELIMITER ;
   ```

   `SET_ATTRIBUTE` サブルーチンの詳細については、[SET_ATTRIBUTE](../../../../700.reference/500.sql-reference/300.pl-reference/300.pl-oracle/1400.pl-system-package-oracle/14200.dbms-scheduler-oracle/1100.set-attribute-oracle.md)を参照してください。

   :::

## パーティション再均衡スケジュールタスクの最大実行時間の調整

デフォルトでは、パーティション再均衡スケジュールタスクの最大実行時間は7200秒（2時間）です。この値を変更することは推奨されません。

1. テナント管理者がクラスタのMySQLテナントまたはOracleテナントにログインします。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に基づいてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql_tenant#obdemo -p***** -A
   ```

2. `DBMS_SCHEDULER`システムパッケージの`SET_ATTRIBUTE`サブルーチンを呼び出して、パーティション再均衡スケジュールタスクの最大実行時間を調整します。

   :::tab
   タブ MySQLモード

   ステートメントは以下のとおりです：

   ```sql
   CALL DBMS_SCHEDULER.SET_ATTRIBUTE('SCHEDULED_TRIGGER_PARTITION_BALANCE', 'MAX_RUN_DURATION', 'max_time');
   ```

   ここで、`max_time` はパーティション均等化ステートメントをトリガーする最大実行時間を秒単位で指定します。

   MySQLモードのテナントでパーティション均等化ステートメントの最大実行時間を3600秒（1時間）に調整する例は次のとおりです：

   ```shell
   obclient [oceanbase]> CALL DBMS_SCHEDULER.SET_ATTRIBUTE('SCHEDULED_TRIGGER_PARTITION_BALANCE', 'MAX_RUN_DURATION', '3600');
   ```

   tab Oracleモード

   ステートメントは以下のとおりです：

   ```sql
   BEGIN DBMS_SCHEDULER.SET_ATTRIBUTE('SCHEDULED_TRIGGER_PARTITION_BALANCE', 'MAX_RUN_DURATION', 'max_time');
   END;
   ```

   ここで、`max_time` はパーティション均衡ステートメントの最大実行時間を秒単位で指定します。

   Oracleモードのテナントでパーティション均衡ステートメントの最大実行時間を3600秒（1時間）に調整する例は次のとおりです：

   ```shell
   obclient [SYS]> DELIMITER //
   ```

   ```shell
   obclient [SYS]> BEGIN
        DBMS_SCHEDULER.SET_ATTRIBUTE('SCHEDULED_TRIGGER_PARTITION_BALANCE', 'MAX_RUN_DURATION', '3600');
   END;//
   ```

   ```shell
   obclient [SYS]> DELIMITER ;
   ```

   `SET_ATTRIBUTE` サブルーチンの詳細については、[SET_ATTRIBUTE](../../../../700.reference/500.sql-reference/300.pl-reference/300.pl-oracle/1400.pl-system-package-oracle/14200.dbms-scheduler-oracle/1100.set-attribute-oracle.md)を参照してください。

   :::

## 次のステップ

スケジュールタスクは、パーティション再均衡タスクをトリガーするためだけに使用されます。トリガー条件が満たされると、システムは自動的にパーティション再均衡タスクをトリガーします。パーティション再均衡タスクがトリガーされた後：

* ビューを使用して、スケジュールされたパーティション再均衡タスクのトリガー履歴を確認できます。詳細な操作については、[スケジュールされたパーティション再均衡タスクのトリガー履歴の表示](400.view-the-triggering-history-of-the-scheduled-partition-balancing-task.md)を参照してください。

* 実際のパーティション移行は、バックグラウンドの再均衡タスクによって非同期で実行されます。ビューを使用して、パーティション再均衡タスクの実行状況を確認できます。詳細な操作については、[バックグラウンドのパーティション再均衡タスクの表示](500.view-background-partition-balancing-task.md)を参照してください。

  <main id="notice" type='explain'>
  <h4>説明</h4>
  <p>パーティション再均衡タスクが正常にトリガーされた後、テナントレベルの構成パラメータ<code>enable_rebalance</code>と<code>enable_transfer</code>の値のいずれかが<code>True</code>以外の場合、このスケジュールタスクは失敗します。</p>
