# クラスタパラメータの確認

システムテナントとユーザーテナントはどちらもクラスタのパラメータを確認できます。

クラスタパラメータを確認する主な方法は以下のとおりです：

* `SHOW` ステートメントを使用してクラスタパラメータを確認する

  クラスタ内の隠れたパラメータ（`_xx_xx`形式のパラメータ）を除くすべてのパラメータとそのすべてのプロパティの説明を確認できます。また、隠れたパラメータの値がデフォルト値以外に変更されている場合も、`SHOW` ステートメントを使用して確認できます。

* `GV$OB_PARAMETERS` ビューを使用してクラスタパラメータを確認する

  `SHOW` ステートメントとは異なり、`GV$OB_PARAMETERS` ビューを使用すると、クラスタ内のすべてのパラメータ（隠れたパラメータ、つまり `_xx_xx` 形式のパラメータを含む）とそのすべてのプロパティの説明を確認できます。

パラメータの詳細については、[パラメータとシステム変数の概要](../../../700.reference/800.configuration-items-and-system-variables/000.configuration-items-and-system-variables-overview.md)を参照してください。

## SHOWステートメントを使用してクラスタパラメータを確認する

システムテナント（`sys` テナント）とユーザーテナントはどちらもSHOWステートメントを使用してクラスタパラメータの値を確認できます。また、システムテナントは `TENANT` キーワードを指定することで、指定したテナントのパラメータ情報を確認できます。

1. システムテナントまたはユーザーテナントでクラスタにログインします。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に準じてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -utest@mysql#obdemo -p***** -A
   ```

   データベースへの接続操作の詳細については、[データベース接続の概要（MySQLモード）](../../../300.develop/100.application-development-of-mysql-mode/100.connect-to-oceanbase-database-of-mysql-mode/100.connection-methods-overview-of-mysql-mode.md)および[データベース接続の概要（Oracleモード）](../../../300.develop/200.application-development-of-oracle-mode/100.connect-to-oceanbase-database-of-oracle-mode/100.connection-methods-overview-of-oracle-mode.md)を参照してください。

2. 以下のコマンドを実行して、クラスタパラメータを確認します。

   ステートメントは以下のとおりです：

   ```sql
   obclient [xxx]> SHOW PARAMETERS [SHOW_PARAM_OPTS] [TENANT = tenant_name];
   ```

   ここで：

   * `[SHOW_PARAM_OPTS]` は `[LIKE 'pattern' | WHERE expr]` と指定できます。`WHERE expr` で指定できる列属性は `SHOW PARAMETERS` の実行結果にある列属性と一致します。

   * `TENANT` キーワードを指定すると、指定したテナントのパラメータ情報を確認できます。

   * システムテナントまたはユーザーテナントがパラメータをクエリする例は以下のとおりです。

      ```sql
      obclient [(none)]> SHOW PARAMETERS LIKE '%syslog_level%';
      ```

      クエリ結果は次のとおりです：

      ```shell
      +-------+----------+----------------+----------+--------------+-----------+-------+------------------------------------------------------------------------------------------------------------------------------+----------+---------+---------+-------------------+---------------+-----------+
      | zone  | svr_type | svr_ip         | svr_port | name         | data_type | value | info                                                                                                                         | section  | scope   | source  | edit_level        | default_value | isdefault |
      +-------+----------+----------------+----------+--------------+-----------+-------+------------------------------------------------------------------------------------------------------------------------------+----------+---------+---------+-------------------+---------------+-----------+
      | zone1 | observer | 172.xx.xxx.xxx |     2882 | syslog_level | STRING    | WDIAG | specifies the current level of logging. There are DEBUG, TRACE, WDIAG, EDIAG, INFO, WARN, ERROR, seven different log levels. | OBSERVER | CLUSTER | DEFAULT | DYNAMIC_EFFECTIVE | WDIAG         |         1 |
      +-------+----------+----------------+----------+--------------+-----------+-------+------------------------------------------------------------------------------------------------------------------------------+----------+---------+---------+-------------------+---------------+-----------+
      1 row in set
      ```

   * システムテナントが指定したテナントのパラメータをクエリする例を以下に示します。

      ```sql
      obclient [(none)]> SHOW PARAMETERS LIKE '%syslog_level%' TENANT = mysql001;
      ```

      クエリ結果は次のとおりです：

      ```shell
      +-------+----------+----------------+----------+--------------+-----------+-------+------------------------------------------------------------------------------------------------------------------------------+----------+---------+---------+-------------------+---------------+-----------+
      | zone  | svr_type | svr_ip         | svr_port | name         | data_type | value | info                                                                                                                         | section  | scope   | source  | edit_level        | default_value | isdefault |
      +-------+----------+----------------+----------+--------------+-----------+-------+------------------------------------------------------------------------------------------------------------------------------+----------+---------+---------+-------------------+---------------+-----------+
      | zone1 | observer | 172.xx.xxx.xxx |     2882 | syslog_level | STRING    | WDIAG | specifies the current level of logging. There are DEBUG, TRACE, WDIAG, EDIAG, INFO, WARN, ERROR, seven different log levels. | OBSERVER | CLUSTER | DEFAULT | DYNAMIC_EFFECTIVE | WDIAG         |         1 |
      +-------+----------+----------------+----------+--------------+-----------+-------+------------------------------------------------------------------------------------------------------------------------------+----------+---------+---------+-------------------+---------------+-----------+
      1 row in set
      ```

   クエリ結果の各列の意味は、以下の表のとおりです。

   |     列名    |  含義                             |
   |------------|-----------------------------------|
   | zone       | 所在の Zone。                      |
   | svr_type   | 服务器类型。                        |
   | svr_ip     | 服务器 IP。                          |
   | svr_port   | 服务器的端口。                        |
   | name       | パラメータ名。                         |
   | data_type  | パラメータのデータ型。`STRING`、`CAPACITY`などが含まれます。              |
   | value      | パラメータの値。 <main id="notice" type='explain'><h4>説明</h4><p>構成パラメータの値を変更する際、指定したZoneまたはServerの構成パラメータ値を変更できるため、異なるZoneまたはServerに対応する構成パラメータの値は異なる場合があります。</p></main>  |
   | info       | パラメータの説明情報。           |
   | section    | パラメータが属する分類： <ul><li>`SSTABLE`：SSTable関連のパラメータを表します。</li> <li>`OBSERVER`：OBServer関連のパラメータを表します。</li>  <li>`ROOT_SERVICE`：Root Service関連のパラメータを表します。</li> <li>`TENANT`：テナント関連のパラメータを表します。</li> <li>`TRANS`：トランザクション関連のパラメータを表します。</li> <li>`LOAD_BALANCE`：ロードバランシング関連のパラメータを表します。</li>  <li>`DAILY_MERGE`：マージ関連のパラメータを表します。</li> <li>`CLOG`：clog関連のパラメータを表します。</li>   <li>`LOCATION_CACHE`：Location Cache関連のパラメータを表します。</li> <li>`CACHE`：キャッシュ関連のパラメータを表します。</li>   <li>`RPC`：RPC関連のパラメータを表します。</li> <li>`OBPROXY`：OBProxy関連のパラメータを表します。</li></ul>    |
   | scope      | パラメータの範囲属性： <ul><li>`TENANT`：このパラメータがテナントレベルのパラメータであることを表します</li> <li>`CLUSTER`：このパラメータがクラスタレベルのパラメータであることを表します</li></ul>         |
   | source     | 現在の値の出典： <ul><li>`TENANT`</li> <li>`CLUSTER` </li>  <li>`CMDLINE`</li> <li>`OBADMIN` </li>  <li>`FILE`</li> <li>`DEFAULT`</li></ul>           |
   | edit_level | この構成パラメータの変更動作を定義します： <ul><li>`READONLY`：このパラメータは変更できないことを表します。</li> <li>`STATIC_EFFECTIVE`：このパラメータは変更できますが、OBServerを再起動しないと変更が有効になりません。</li>   <li>`DYNAMIC_EFFECTIVE`：このパラメータは変更でき、変更後は動的に反映されます。</li></ul>          |
   | default_value | パラメータのデフォルト値。 |
   | isdefault  | 現在の値がデフォルト値かどうか。<ul><li>0：現在の値がデフォルト値ではないことを表します。</li><li>1：現在の値がデフォルト値であることを表します。</li></ul> |

## GV$OB_PARAMETERSビューでクラスタ構成パラメータを確認する

1. システムテナントまたはユーザーテナントでクラスタにログインします。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に準じてください。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -utest@mysql#obdemo -p***** -A
   ```

   データベース接続の詳細な操作手順については、[データベース接続の概要（MySQLモード）](../../../300.develop/100.application-development-of-mysql-mode/100.connect-to-oceanbase-database-of-mysql-mode/100.connection-methods-overview-of-mysql-mode.md)および[データベース接続の概要（Oracleモード）](../../../300.develop/200.application-development-of-oracle-mode/100.connect-to-oceanbase-database-of-oracle-mode/100.connection-methods-overview-of-oracle-mode.md)を参照してください。

2. 以下のコマンドを実行して、`oceanbase`データベースに入ります。

   ```sql
   obclient > USE oceanbase;
   ```

   <main id="notice" type='explain'>
            <h4>説明</h4>
            <p>この手順はMySQLテナントのみが実行する必要があります。Oracleテナントは無視してください。</p>
   </main>

3. 以下のコマンドを実行して、クラスタパラメータを確認します。

   クエリ例は以下のとおりです：

   ```sql
   obclient> SELECT * FROM GV$OB_PARAMETERS WHERE NAME LIKE '%syslog_level%';
   ```

   クエリ結果は次のとおりです：

   ```shell
   +----------------+----------+-------+---------+-----------+--------------+-----------+-------+------------------------------------------------------------------------------------------------------------------------------+----------+-------------------+---------------+-----------+
   | SVR_IP         | SVR_PORT | ZONE  | SCOPE   | TENANT_ID | NAME         | DATA_TYPE | VALUE | INFO                                                                                                                         | SECTION  | EDIT_LEVEL        | DEFAULT_VALUE | ISDEFAULT |
   +----------------+----------+-------+---------+-----------+--------------+-----------+-------+------------------------------------------------------------------------------------------------------------------------------+----------+-------------------+---------------+-----------+
   | 172.xx.xxx.xxx |     2882 | zone1 | CLUSTER |      NULL | syslog_level | STRING    | WDIAG | specifies the current level of logging. There are DEBUG, TRACE, WDIAG, EDIAG, INFO, WARN, ERROR, seven different log levels. | OBSERVER | DYNAMIC_EFFECTIVE | WDIAG         | YES       |
   +----------------+----------+-------+---------+-----------+--------------+-----------+-------+------------------------------------------------------------------------------------------------------------------------------+----------+-------------------+---------------+-----------+
   1 row in set
   ```

  `GV$OB_PARAMETERS`ビューの詳細については、[GV$OB_PARAMETERS(MySQLモード)](../../../700.reference/700.system-views/400.system-view-of-mysql-mode/300.performance-view-of-mysql-mode/2100.gv-ob_parameters-of-mysql-mode.md)を参照してください。
