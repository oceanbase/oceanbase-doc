# マルチテナント機能の体験

OceanBaseデータベースはマルチテナント機能を備えており、クラスタレベルでインスタンスリソースのプール化を実現しています。OceanBaseデータベースでは、各テナントが1つのインスタンスとなります（MySQLのInstanceに相当します）。テナント間ではデータ、権限、リソースが分離されており、各テナントは独立したアクセスポートおよびCPU、メモリアクセスリソースを保有しています。

## 背景情報

OceanBaseデータベースは、テナントのリソース割り当て（CPU、メモリ）を柔軟に調整でき、そのプロセス全体が上位のビジネスに対して透過的です。マルチテナント方式により、OceanBaseクラスタはユーザーがリソースを効率的に活用し、可用性とパフォーマンスを保証しつつコストを最適化し、必要に応じて柔軟に拡張することを可能にします。

OceanBaseデータベースのマルチテナントの概念をより容易に理解できるよう、以下ではOceanBaseデータベースのテナントを作成する例をステップごとに説明します。

## リソース仕様Unit Configの作成

OceanBaseデータベースにおいて、リソースユニットUnitは、テナントがCPUやメモリを使用する最小の論理単位であり、クラスタの拡張やロードバランシングの基本単位でもあります。クラスタノードの追加・削除、拡張・縮小時には、リソースユニットのノード上での配置を動的に調整し、リソースの均等な使用を実現します。一方、Unit Configは、1つのUnitが使用する計算・ストレージリソース（メモリ、CPU、I/Oなどを含む）の仕様を規定した設定情報です。

OceanBaseデータベースは分散アーキテクチャを採用しているため、1つのテナントはリソース仕様、リソースプール、レプリカタイプ、レプリカの配置といった複数の異なる観点から柔軟に定義できます。そのため、テナントを作成する際も、「unit config -> resource pool -> tenant」という順序で作成・定義する必要があります。

OceanBaseデータベースでテナントを作成する前に、まずテナントのUnit Configを決定する必要があります。`sys`テナントの管理者として、以下のSQL文を使用して作成します。

以下では、それぞれ`unit1`と`unit2`の2つのUnit Configを作成し、CPU、メモリ、使用する最大値および最小値を指定します。

* `unit1`リソースユニットのCPU使用量を3コア、メモリ使用量を6GBに設定します。

    ```sql
    obclient [oceanbase]> CREATE RESOURCE UNIT UNIT1 MAX_CPU =3,MIN_CPU =3 ,MEMORY_SIZE ='6G';
    ```

* `unit2`リソースユニットのCPU使用量を4コア、メモリ使用量を8GBに設定します。

    ```sql
    obclient [oceanbase]> CREATE RESOURCE UNIT UNIT2 MAX_CPU =4,MIN_CPU =4 ,MEMORY_SIZE ='8G';
    ```

## リソースプールの作成とUnit Configの関連付け

Unit Configは一連のテナントの設定仕様情報であり、Resource Poolはテナントのリソースエンティティです。このステップでは、Resource Poolを作成し、Unit Configと関連付ける必要があります。

`pool1`と`pool2`という2つの異なるリソースプールを作成し、それぞれ`unit1`と`unit2`に指定します。これにより、リソースユニットとリソースプールの対応付けを実現します。`UNIT_NUM`は、1つのレプリカ内で指定する`unit`ユニットの数を表します（同一テナント内で、1つのノード上には最大1つの`unit`しか存在できません）。`ZONE_LIST`は、テナントが現在のクラスタ内のどのレプリカにデプロイされるかを指定します。

この例では、単一ノードクラスタであることを考慮し、単一のUnitとZone Listを指定します。Resource Poolを作成する際には、十分なリソースが残っていることを確認する必要があります。リソースが不足している場合は、既存の`test`テナントを削除するか、既存テナントのUnit Configをより小さな値に調整してみてください。調整方法については、[テナントリソースサイズの調整](#テナント設定の変更とインスタンスリソース仕様の調整)を参照してください。

```sql
obclient [oceanbase]> CREATE RESOURCE POOL pool1 UNIT='UNIT1',UNIT_NUM=1,ZONE_LIST=('zone1');
obclient [oceanbase]> CREATE RESOURCE POOL pool2 UNIT='UNIT2',UNIT_NUM=1,ZONE_LIST=('zone1');
```

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>上記の例は単一ノードのクラスタ環境を対象としています。クラスタに3つのノードがある場合、<code>ZONE_LIST</code>の値は<code>('zone1','zone2','zone3')</code>となります。ここで、Zoneの名前は作成状況に応じて具体的に入力する必要があります。</p>
  </main>

## 作成したリソースプールに基づいてテナントを作成する

ユニット構成とリソースプールの作成が完了し、リソースユニットとリソースプールの対応付けが終了したら、通常通りテナントの作成を開始できます。

この例では単一ノードクラスタであるため、単一レプリカのテナントしか作成できません。3レプリカのテナントを作成したい場合は、OceanBaseクラスタに少なくとも3つのノードが必要です。

`tenant1` という名前の単一レプリカテナントを定義し、文字セットを `utf8mb4` に設定します。また、`pool1` のリソースプールを使用し、`ob_tcp_invited_nodes` はテナントのアローリスト定義であり、初期値は '%' に設定できます。これは任意のIPアドレスからのアクセスを許可することを意味し、後で変更可能です。

```sql
obclient [oceanbase]> CREATE TENANT IF NOT EXISTS tenant1 CHARSET='utf8mb4', ZONE_LIST=('zone1'), PRIMARY_ZONE='zone1', RESOURCE_POOL_LIST=('pool1') SET ob_tcp_invited_nodes='%';
```

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>上記の例は単一ノードのクラスタ環境を対象としており、単一レプリカのテナントしか作成できません。クラスタに3つのノードがある場合、<code>ZONE_LIST</code> の値は ('zone1','zone2','zone3') に、<code>PRIMARY_ZONE</code> は <code>'zone1;zone2;zone3'</code> に設定します。これは、テナントのリーダーが <code>zone1</code> に優先的に配置され、次に <code>zone2</code> に配置されることを意味します。</p>
  </main>

同様に、`tenant2` という名前の単一レプリカテナントを定義し、文字セットを `utf8mb4` に設定します。また、`pool2` のリソースプールを使用します。

```sql
obclient [oceanbase]> CREATE TENANT IF NOT EXISTS tenant2 CHARSET='utf8mb4', ZONE_LIST=('zone1'), PRIMARY_ZONE='zone1', RESOURCE_POOL_LIST=('pool2') SET ob_tcp_invited_nodes='%';
```

`tenant1` と `tenant2` のテナント作成が完了したら、`oceanbase.DBA_OB_TENANTS` ビューを照会することで、テナントが正常に作成されたかどうか確認できます。

```sql
obclient [oceanbase]> SELECT * FROM DBA_OB_TENANTS;
```

上記の操作が完了したら、同一クラスタ内で2つのテナントを作成する手順が完了します。次に、テナント内で通常のデータベース操作を実行できます。

`root` ユーザーでクラスタの `tenant1` テナントにログインし、テストテーブルを作成します。

クラスタ内の2つのテナントのリソース、データ、権限はすべて分離されていることがわかります。さらにテストを行い、OceanBaseデータベースのテナント分離機能を体験することができます。

## テナント設定の変更とインスタンスリソース仕様の調整

OceanBaseデータベースでは、テナントのCPUおよびメモリリソースを柔軟に調整でき、その変更はオンラインで即時反映され、業務への影響はありません。テナントが使用するCPUやメモリサイズを変更する場合、リソースプールやテナント自体を調整する必要なく、対応するUnit Configを調整するだけで済みます。

テナントリソースユニットは、システムビュー`oceanbase.DBA_OB_UNIT_CONFIGS`で確認できます。

```sql
obclient [oceanbase]> SELECT * FROM oceanbase.DBA_OB_UNIT_CONFIGS;
+----------------+-----------------+----------------------------+----------------------------+---------+---------+-------------+---------------+----------+----------+-------------+
| UNIT_CONFIG_ID | NAME            | CREATE_TIME                | MODIFY_TIME                | MAX_CPU | MIN_CPU | MEMORY_SIZE | LOG_DISK_SIZE | MAX_IOPS | MIN_IOPS | IOPS_WEIGHT |
+----------------+-----------------+----------------------------+----------------------------+---------+---------+-------------+---------------+----------+----------+-------------+
|              1 | sys_unit_config | 2022-11-17 18:00:47.297945 | 2022-11-17 18:00:47.297945 |       1 |       1 |  8053063680 |    8053063680 |    10000 |    10000 |           1 |
|           1010 | unit1           | 2022-12-15 11:40:17.811095 | 2022-12-15 11:40:17.811095 |       3 |       3 |  6442450944 |    2147483648 |     128  |     128  |           0 |
|           1011 | unit2           | 2022-12-16 16:16:27.053872 | 2022-12-16 16:16:27.053872 |       4 |       4 |  8589934592 |    8589934592 |     128  |     128  |           0 |
+----------------+-----------------+----------------------------+----------------------------+---------+---------+-------------+---------------+----------+----------+-------------+
6 rows in set (0.003 sec)
```

クエリ結果によると、`unit1`リソースユニットのCPU使用量は3コア、メモリ使用量は6GBです。

以下のコマンドを実行して、`unit1`リソースユニットのCPUおよびメモリ使用量を5コア、10GBに調整します。

```sql
obclient [oceanbase]>  ALTER resource unit unit1 max_cpu =5,min_cpu =5 ,memory_size ='10G';
Query OK, 0 rows affected

obclient [oceanbase]> SELECT * FROM oceanbase.DBA_OB_UNIT_CONFIGS;
+----------------+-----------------+----------------------------+----------------------------+---------+---------+-------------+---------------+----------+----------+-------------+
| UNIT_CONFIG_ID | NAME            | CREATE_TIME                | MODIFY_TIME                | MAX_CPU | MIN_CPU | MEMORY_SIZE | LOG_DISK_SIZE | MAX_IOPS | MIN_IOPS | IOPS_WEIGHT |
+----------------+-----------------+----------------------------+----------------------------+---------+---------+-------------+---------------+----------+----------+-------------+
|              1 | sys_unit_config | 2022-11-17 18:00:47.297945 | 2022-11-17 18:00:47.297945 |       1 |       1 |  8053063680 |    8053063680 |    10000 |    10000 |           1 |
|           1010 | unit1           | 2022-12-15 11:40:17.811095 | 2023-01-05 16:24:17.287801 |       5 |       5 | 10737418240 |    2147483648 |     128  |     128  |           0 |
|           1011 | unit2           | 2022-12-16 16:16:27.053872 | 2022-12-16 16:16:27.053872 |       4 |       4 |  8589934592 |    8589934592 |     128  |     128  |           0 |
+----------------+-----------------+----------------------------+----------------------------+---------+---------+-------------+---------------+----------+----------+-------------+
6 rows in set (0.037 sec)
```

上記のように、テナント設定の変更はオンラインで即時反映されます。変更が成功すると、`unit1`のCPUとメモリは5コア、10GBになります。OceanBaseデータベースはカーネルの仮想化技術を利用しており、設定変更後もデータ移行や切り替えなしで、テナントのCPUおよびメモリリソースを即座に有効化でき、業務への影響はありません。

`DBA_OB_UNITS`情報を確認することで、リソースユニット、リソースプール、クラスタ内のテナントの対応情報、およびCPUとメモリの情報を取得できます。

```sql
obclient [oceanbase]> SELECT * FROM DBA_OB_UNITS;
```
