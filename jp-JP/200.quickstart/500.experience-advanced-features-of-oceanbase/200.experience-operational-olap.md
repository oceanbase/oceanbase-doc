# Operational OLAPの体験

OceanBaseデータベースは、さまざまな種類のワークロードを処理できるシナリオに対応しています。OceanBaseデータベースは、ピアノードに基づく分散アーキテクチャを採用しているため、高同時実行性とスケーラビリティを備えたOLTPタスクを処理すると同時に、同一のデータエンジン内でMPPアーキテクチャに基づいてOLAPの並列計算を実行できます。そのため、2つのデータセットを維持管理する必要がありません。

OceanBaseデータベースでは、大量のオンライン業務データに対して直接並列分析を行うだけでなく、PDML機能（Parallel DML）を利用して、一括書き込みされた大規模トランザクションを並行処理で迅速かつ安全に実行することも可能です。そして、これらすべては、トランザクションの一貫性を厳密に保証しつつ実現されます。

以下では、手動でTPC-Hテストを実行し、OceanBaseデータベースがOperational OLAPシナリオにおいてどのような特徴と使い方を持つかを示します。TPC-Hは、意思決定支援業務に基づく業界で一般的に使用されるベンチマークであり、大量のデータセット上で実行される一連の複雑なクエリリクエストを通じて、データベースシステムの分析および意思決定支援能力を検証します。詳細については、TPC公式ウェブサイトを参照してください。（2021年5月20日、OceanBaseデータベースは1526万QphHの成績でTPC-Hの世界記録を更新しました。また、TPC-CおよびTPC-Hの両方の記録を同時に更新した唯一のデータベースでもあり、オンライン取引とリアルタイム分析という2種類の業務シナリオを同時に処理できる能力を証明しています。詳細については、[TPC-H Result](https://www.tpc.org/tpch/results/tpch_results5.asp?version=3)を参照してください。）

## TPC-Hテストの手動実行

以下は、TPC公式のTPC-Hツールを用いて、手動でステップバイステップでTPC-Hテストを実行する方法です。手動テストは、特に一部のパラメータ設定について、OceanBaseデータベースをより深く理解し学ぶのに役立ちます。

### 環境のチューニングを実行する

1. OceanBaseデータベースのチューニングを行います。

   システムテナント(`sys`テナント)で以下のステートメントを実行して、関連パラメータを設定してください。

   ```bash
   # テストテナントにより多くのリソースを提供するために、sysテナントが使用するメモリを調整します。実際の環境に応じて動的に調整する必要があります。
   ALTER SYSTEM SET system_memory='15g';
   ALTER RESOURCE UNIT sys_unit_config memory_size ='15G';
   # パラメータのチューニング
   ALTER SYSTEM SET trace_log_slow_query_watermark='100s';
   ALTER SYSTEM SET enable_sql_operator_dump=True;
   ALTER SYSTEM SET _hash_area_size='3g';
   ALTER SYSTEM SET memstore_limit_percentage=50;
   ALTER SYSTEM SET enable_rebalance=False;
   ALTER SYSTEM SET memory_chunk_cache_size='0';
   ALTER SYSTEM SET major_compact_trigger=5;
   ALTER SYSTEM SET cache_wash_threshold='30g';
   # ログレベルと保存数の調整
   ALTER SYSTEM SET syslog_level='ERROR';
   ALTER SYSTEM SET max_syslog_file_count=100;
   ALTER SYSTEM SET enable_syslog_recycle='True';
   ```

2. テナント構成を設定します。

   テストテナント(ユーザーテナント)で以下のステートメントを実行して、関連パラメータを設定してください。

   ```bash
   # グローバルパラメータの設定
   SET GLOBAL ob_sql_work_area_percentage=80;
   SET GLOBAL optimizer_use_sql_plan_baselines = true;
   SET GLOBAL optimizer_capture_sql_plan_baselines = true;
   ALTER SYSTEM SET ob_enable_batched_multi_statement='true';
   # テナント設定では、トランザクションのタイムアウトを防ぐために
   SET GLOBAL ob_query_timeout=36000000000;
   SET GLOBAL ob_trx_timeout=36000000000;
   SET GLOBAL max_allowed_packet=67108864;
   SET GLOBAL secure_file_priv('');
   /*
   parallel_server_targetは、テストテナントに割り当てられたResource UnitのCPU数の10倍 × マシン数 × 0.8に設定することを推奨します。
   テストテナントで使用されるUnit構成が次の場合：`CREATE RESOURCE UNIT $unit_name max_cpu 26;`
   その値は26*10*3*0.8=624です
   */
   SET GLOBAL parallel_servers_target=624;
   ```

3. パラメータの設定が完了したら、クラスタを再起動してください。

6. ファイルをコンパイルします。

調整後のクエリSQLについては、[GitHub](https://github.com/oceanbase/obdeploy/tree/master/plugins/tpch/3.1.0/queries)を参照してください。GitHubで提供されているSQL文内の`cpu_num`を実際の並列数に変更する必要があります。並列数の値は利用可能なCPUの総数と同じにすることを推奨します。両者が等しい場合、パフォーマンスが最も良くなります。

`sys`テナントで以下のコマンドを使用して、テナントの利用可能なCPUの総数を確認できます。

```sql
select sum(max_cpu) from DBA_OB_UNITS ;
```

例えば`q1`の場合、修正後のSQL文は次のとおりです：

```sql
select /*+    parallel(96) */   ---parallelパラレル実行を追加
   l_returnflag,
   l_linestatus,
   sum(l_quantity) as sum_qty,
   sum(l_extendedprice) as sum_base_price,
   sum(l_extendedprice * (1 - l_discount)) as sum_disc_price,
   sum(l_extendedprice * (1 - l_discount) * (1 + l_tax)) as sum_charge,
   avg(l_quantity) as avg_qty,
   avg(l_extendedprice) as avg_price,
   avg(l_discount) as avg_disc,
   count(*) as count_order
from
   lineitem
where
   l_shipdate <= date '1998-12-01' - interval '90' day
group by
   l_returnflag,
   l_linestatus
order by
   l_returnflag,
   l_linestatus;
```

### テストの実行

上記の手順で生成されたデータとSQLを使用して、スクリプトを独自に作成できます。テストのサンプル操作は以下のとおりです：

1. `queries` ディレクトリにテストスクリプト `tpch.sh` を作成します。

   ```bash
   #!/bin/bash
   TPCH_TEST="obclient -h $host_ip -P $host_port -utpch_100g_part@tpch_mysql  -D tpch_100g_part  -ptest -c"
   # ウォームアップ
   for i in {1..22}
   do
      sql1="source db${i}.sql"
      echo $sql1| $TPCH_TEST >db${i}.log  || ret=1
   done
   # 実際の実行
   for i in {1..22}
   do
      starttime=`date +%s%N`
      echo `date  '+[%Y-%m-%d %H:%M:%S]'` "BEGIN Q${i}"
      sql1="source db${i}.sql"
      echo $sql1| $TPCH_TEST >db${i}.log  || ret=1
      stoptime=`date +%s%N`
      costtime=`echo $stoptime $starttime | awk '{printf "%0.2f\n", ($1 - $2) / 1000000000}'`
      echo `date  '+[%Y-%m-%d %H:%M:%S]'` "END,COST ${costtime}s"
   done
   ```

2. テストスクリプトを実行します。

   ```bash
   sh tpch.sh
   ```

### FAQ

* データのインポートに失敗しました。エラーメッセージは次のとおりです：

  ```bash
  ERROR 1017 (HY000) at line 1: File not exist
  ```

  `tbl` ファイルは、接続先のOceanBaseデータベースが存在するマシンの特定のディレクトリに配置する必要があります。これは、データのロードがローカルからのみ可能だからです。

* データの確認時にエラーが発生しました。エラーメッセージは次のとおりです：

  ```bash
  ERROR 4624 (HY000)：No memory or reach tenant memory limit
  ```

  メモリ不足です。テナントのメモリを増やすことを推奨します。

* データのインポート時にエラーが発生しました。エラーメッセージは次のとおりです：

  ```bash
  ERROR 1227 (42501) at line 1: Access denied
  ```

  ユーザーにアクセス権限を付与する必要があります。以下のコマンドを実行して権限を付与します：

  ```bash
  grant file on *.* to tpch_100g_part;
  ```

## obdツールを使用したTPC-Hテストの自動実行

  <main id="notice" >
    <h4>適用対象</h4>
    <p>この内容はOceanBaseデータベースCommunity Editionにのみ適用されます。OceanBaseデータベースEnterprise Editionは現在、obdの使用をサポートしていません。</p>
  </main>

TPC-Hテストでは、TPC公式ウェブサイトが提供するデータセット生成ツールを参照することもできますが、obdを使用してデータセットの生成、テーブル作成、データインポートなどを簡単に行うことができ、さらに22個のSQL文の実行も自動化できます。
obdを使用してTPC-Hテストを実行する前に、OceanBaseとobdがデプロイされたノードにobtpchコンポーネントをインストールする必要があります：

```test
sudo yum install obtpch
```

完了後、以下のコマンドを実行することで、データセットサイズが1GBのTPC-Hテストを開始できます。このプロセスには、データセットの生成、スキーマのインポート、およびテストの自動実行が含まれます。本記事では、テスト環境のデプロイが[OceanBaseデータベースのクイックスタート](../100.quickly-experience-oceanbase-for-community.md)の手順と一致していることを前提としています。クラスタ名、パスワード、インストールディレクトリなどに違いがある場合は、具体的な状況に応じて調整してください。

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>データセットファイルを格納するための十分なディスク容量が確保されていることを確認してください。容量不足によりシステム異常が発生するのを防ぐためです。</p>
  </main>
