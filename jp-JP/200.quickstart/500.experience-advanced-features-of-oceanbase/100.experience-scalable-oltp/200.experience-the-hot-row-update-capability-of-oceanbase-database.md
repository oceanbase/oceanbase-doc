# OceanBaseデータベースのホットスポット行更新機能を体験する

オンライン取引やeコマース業界の発展に伴い、業務システムにおけるホットスポットの同時実行処理による負荷が徐々に課題となっています。短期間で残高が大量に更新されるホットアカウントや、マーケティングイベントで人気商品が限定販売される場合などがその典型的な例です。ホットスポット更新とは、短時間にデータベース内の同一行データの特定フィールド値（残高、ストックなど）に対して高い同時実行処理が行われることを指します。この際のボトルネックは主に、リレーショナルデータベースがトランザクションの一貫性を保つために、データ行の更新を「ロック取得→更新→ログ書き込み・コミット→ロック解放」という手順で行う必要があり、このプロセスが本質的に直列処理であることにあります。したがって、ホットスポット行の更新性能を向上させる鍵は、ロックを保持する時間をできるだけ短縮することにあります。

学術的には早くから「早期ロック解放（Early Lock Release）」（ELR）という手法が提案されていますが、ELRの例外処理シナリオが非常に複雑であるため、業界では成熟した実装例がほとんどありません。OceanBaseデータベースはこの問題に対し、継続的な研究を通じて分散アーキテクチャに基づく実装方法を提案し、このような業務シナリオにおける単一行の同時実行更新性能を向上させました。これは、OceanBaseデータベースの「スケーラブルなOLTP」の重要な機能の一つとなっています。

本記事では、複数の同時実行処理が発生する単一行更新のシナリオを構築し、OceanBaseデータベースのELR機能の使用方法と効果の比較を紹介します。複数の同時実行処理が発生する環境で検証するため、より良い結果を得るためには、少なくとも本例と同等のノード構成で体験と検証を行うことを推奨します。OceanBaseデータベースのELRの設計と原理については、その複雑さからここでは詳細には触れません。

本例では、16コア・128GB構成のノードを使用します。以下に、OceanBaseデータベースのELR機能を段階的に体験します。

## ステップ１：テストテーブルを作成し、テストデータを挿入する

まず、テストデータベースにテーブルを作成し、テストデータを挿入します。

```sql
CREATE TABLE `sbtest1` (
   `id` int(11) NOT NULL AUTO_INCREMENT,
   `k` int(11) NOT NULL DEFAULT '0',
   `c` char(120) NOT NULL DEFAULT '',
   `pad` char(60) NOT NULL DEFAULT '',
   PRIMARY KEY (`id`)
);

INSERT INTO sbtest1 VALUES(1,0,'aa','aa');
```

この例では、`UPDATE sbtest1  SET k=k+1 WHERE id=1` のようなステートメントを使用して、主キークエリ方式で `k` 列に対する同時実行更新を行います。より多くのデータを挿入してテストすることも可能ですが、単一行に対する同時実行の負荷テストであるため、全体の結果には基本的に影響しません。

## ステップ２：同時実行更新シナリオを構築する

この例では、Pythonのマルチスレッドを使用して同時実行更新をシミュレートします。同時に50個のThreadを起動し、各Threadがid=1の行データに対してkフィールドの値を+1します。ご自身で構築した環境でも、以下のスクリプト `ob_elr.py` を直接使用してテストすることができます。スクリプト内のデータベース接続情報を修正するだけで使用可能です。

```python
#!/usr/bin/env python3

from concurrent.futures import ThreadPoolExecutor
import pymysql
import time
import threading

# database connection info
config = {
    'user': 'root@test',
    'password': '****',
    'host': 'xxx.xxx.xxx.xxx',
    'port': 2881,
    'database': 'test'
}

# parallel thread and updates in each thread
parallel = 50
batch_num = 2000

# update query
def update_elr():
    update_hot_row = ("update sbtest1 set k=k+1 where id=1")
    cnx = pymysql.connect(**config)
    cursor = cnx.cursor()

    for i in range(0,batch_num):
        cursor.execute(update_hot_row)
    cursor.close()
    cnx.close()

start=time.time()

with ThreadPoolExecutor(max_workers=parallel) as pool:
    for i in range(parallel):
        pool.submit(update_elr)

end = time.time()
elapse_time = round((end-start),2)

print('Parallel Degree:',parallel)
print('Total Updates:',parallel*batch_num)
print('Elapse Time:',elapse_time,'s')
print('TPS on Hot Row:' ,round(parallel*batch_num/elapse_time,2),'/s')
```

## ステップ３：デフォルト設定でテストを実行する

比較のため、まずELRをデフォルトで有効にしない状態でテストを行い、テストマシン上で直接 `ob_elr.py` スクリプトを実行します。

この例では、50の並列数で、合計100000回の更新を行います。

```shell
./ob_elr.py
```

実行完了後、テストスクリプトは実行時間とTPSを出力します：

```shell
[root@obce00 ~]# ./ob_elr.py
Parallel Degree: 50
Total Updates: 100000
Elapse Time: 54.5 s
TPS on Hot Row: 1834.86 /s
```

テスト結果は以下のとおりです：

ELRを有効にしないデフォルト設定では、この例のテスト環境において、単一行の同時実行更新のTPSは1834.86/sです。

## ステップ4：OceanBaseデータベースのELR設定を開く

次に、OceanBaseデータベースのホットスポット行機能を有効にします。まず、`root`ユーザーでクラスタの`sys`テナントにログインする必要があります。

```shell
[root@obce00 ~]# obclient -h127.0.0.1 -P2881 -uroot@sys  -Doceanbase -A -p -c
```

その後、以下の2つのパラメータを設定します。`enable_early_lock_release`パラメータの適用範囲は、特定のテナントを指定することも、すべてのテナントを指定することもできます。すなわち、`tenant=all`です。

``` sql
ALTER SYSTEM SET _max_elr_dependent_trx_count = 1000;
ALTER SYSTEM SET enable_early_lock_release=true tenant= test;
```

## ステップ5：OceanBaseデータベースのELRを有効にしてテストを実行する

ホットスポット行機能を有効にした後、再度テストを実行します。実行前に、テーブル`sbtest`内の`id=1`のレコードを確認します。`k`フィールドの値は100000です。これは、デフォルト設定で100000回の更新が実行されたためです。

```shell
SELECT * FROM sbtest1 WHERE id=1;
+----+--------+----+-----+
| id | k      | c  | pad |
+----+--------+----+-----+
|  1 | 100000 | aa | aa  |
+----+--------+----+-----+
1 row in set
```

次に、テストマシンで再び`ob_elr.py`を実行します。引き続き50の並列数を使用し、合計100000回の更新を行います。

```shell
./ob_elr.py
```

実行完了後、テストスクリプトは実行時間とTPSを出力します：

```shell
[root@obce00 ~]# ./ob_elr.py
Parallel Degree: 50
Total Updates: 100000
Elapse Time: 12.16 s
TPS on Hot Row: 8223.68 /s
```

テスト結果は以下のとおりです：

OceanBaseデータベースでELRの早期ロック解放機能を有効にすると、単一行更新のTPSは8223.68/sに達し、デフォルト設定と比較して約4.5倍向上します。

同時に、テーブル`sbtest1`の`k`値が200000であることから、今回も100000回の更新が行われたことがわかります。

```sql
SELECT * FROM sbtest1 WHERE id=1;
+----+--------+----+-----+
| id | k      | c  | pad |
+----+--------+----+-----+
|  1 | 200000 | aa | aa  |
+----+--------+----+-----+
1 row in set
```

この例では、単一行の同時更新のシナリオのみを紹介しましたが、OceanBaseデータベースのELR機能は、複数文のトランザクションの同時更新もサポートしています。文の数やシナリオの違いによって、同様に顕著なパフォーマンス向上が得られます。

さらに、OceanBaseデータベースのELRは、複数地域にまたがる高ネットワーク遅延のシナリオにも適用できます。例えば、デフォルトのシナリオでは単一のトランザクションが30msかかる場合でも、パラレル処理でELRを有効にすることで、TPSスループットが約100倍向上します。

OceanBaseデータベースのログプロトコルはMulti-Paxosに基づいて構築されており、2PCコミットプロセスが最適化されているため、ELRを有効にした後でも、ノードのダウンや再起動、リーダーの切り替えが発生した場合でも、トランザクションの一貫性を保証できます。これらの実験を構築して体験してみることができます。
