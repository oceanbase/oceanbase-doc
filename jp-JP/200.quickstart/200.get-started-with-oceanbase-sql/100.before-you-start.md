# ご利用の前に

OceanBase 分散型データベースをより効果的に体験し、使い始めるために、まずは、最も一般的な特性の違いである **メモリ** と **タイムアウト時間** について理解しておきましょう。

## メモリについて

OceanBase データベースは LSM-Tree ベースのストレージエンジンです。従来のデータベースのようにダーティページをリアルタイムにフラッシュするメカニズムとは異なり、データをメモリ上の MemTable とディスク上の SSTable に分割します。すべてのデータ更新・書き込み操作はメモリ上の MemTable で行われ、メモリ使用量が一定のしきい値に達するとコンパクションがトリガーされて SSTable にダンプされ、アクティブなメモリがリリースされます。このアーキテクチャの利点は、ランダム I/O をシーケンシャル I/O に変換することで、より大きな書き込みスループットを実現できることです。詳細については、[ストレージアーキテクチャの概要](https://en.oceanbase.com/docs/common-oceanbase-database-10000000001971327) を参照してください。

LSM-Tree は増分データをメモリに保存し、一定のしきい値に達するまでダンプ処理を行わないため、小規模なテナントインスタンスが許容能力を超える高密度書き込み (データインポートや大量のバッチ処理など) が行われると、MemTable の上限に達し、新たなリクエストを受け付けられなくなります。OceanBase データベースには、以下の処理方法があります。

* 書き込み速度制限を有効にする：メモリへの書き込みが一定のしきい値に達すると、OceanBase データベースはクライアントのインポート速度を自動的に制限します。

* テナントメモリ拡張：環境内のノードの総メモリリソースには比較的余裕があるため、テナントメモリの拡張が可能です。

* テナントメモリ内の MemTable の比率を調整する：ノードの総メモリが制限されていて拡張できない場合、テナントメモリ内の MemTable 比率を調整して書き込み可能なメモリを増やし、さらにダンプしきい値を下げてダンプをより迅速に実行することができます。

### 書き込み速度制限の有効化

OceanBase データベースは、書き込み過負荷保護機能を備えています。リソースが不足し、メモリを拡張できない場合、サーバ側の書き込み速度制限によってメモリを保護し、書き込み上限超過を防ぎます。サーバ側の書き込み速度制限機能は、以下の 2 つの設定項目を設定することで有効化できます。

* `writing_throttling_trigger_percentage`：書き込み速度のしきい値を設定するために使用します。MemStore の使用済みメモリがこのしきい値 (パーセント) に達すると、書き込み速度制限がトリガーされます。この設定項目の値の範囲は [1, 100] で、デフォルト値は 60 です。値が 100 の場合は、書き込み速度制限機構が無効になります。

* `writing_throttling_maximum_duration` ：書き込み速度制限がトリガーされた後、残りの MemStore メモリが割り当てられるのに必要な時間です。デフォルト値は 2h です。この設定項目は通常変更しません。

テナント管理者アカウントにおいて、メモリ書き込みが 80% に達した時点で速度制限を開始し、残りのメモリで 2 時間分の書き込み速度制限を確保するように設定します。例：

```sql
obclient> ALTER SYSTEM SET writing_throttling_trigger_percentage = 80;
Query OK, 0 rows affected

obclient> ALTER SYSTEM SET writing_throttling_maximum_duration = '2h';
Query OK, 0 rows affected
```

### テナントメモリ拡張

環境のメモリリソースに比較的余裕がある場合、最適な対処法はテナントメモリの増量です。

メモリ設定の手順は以下のとおりです。

1. `root` ユーザーで OceanBase クラスターの sys テナントにログインし、以下の SQL 文を実行して、現在テナントで使用されている `UNIT_CONFIG NAME` を確認します。

   ```sql
   obclient> SELECT NAME FROM DBA_OB_UNIT_CONFIGS;
   +-----------------+
   | NAME            |
   +-----------------+
   | sys_unit_config |
   | test_unit       |
   +-----------------+
   2 rows in set
   ```

   <main id="notice" type='explain'>
    <h4>説明</h4>
    <p> <ul><li><code>sys_unit_config</code> は管理テナントのパラメーターであり、通常は変更しません。</li><li>本例では、テナント <code>test</code> の <code>unit_config name</code> は <code>test_unit</code> です。</li></ul> </p>
   </main>

2. テナントの `unit_config name` をコピーし、以下のコマンドを使用してメモリ拡張を行います。

   ```sql
   obclient> ALTER RESOURCE UNIT test_unit MIN_CPU = 2, MAX_CPU = 2, MEMORY_SIZE = '10G', MAX_IOPS = 10000, MIN_IOPS = 10000;
   ```

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>現在のバージョンでは、CPU とメモリの設定のみ有効であり、その他の I/O パラメーター (IOPS など) は有効ではありません。</p>
  </main>

### テナントメモリ内の MemStore の比率の調整

テナントメモリ内の MemStore の比率は、以下の設定項目で調整します。

* `freeze_trigger_percentage`：テナントの MemStore メモリ使用量が、この設定項目で制限されている比率に達すると、自動的にダンプが実行され、ダンプ後に使用されていたメモリがリソースされます。この設定項目の値の範囲は [1,99] で、デフォルト値は 20 です。MemStore の使用率が 20% を超えると、ダンプがトリガーされます。
* `memstore_limit_percentage`：この設定項目は、テナントメモリ内で MemStore への書き込みに使用できる比率を制御します。値の範囲は [0, 100) で、デフォルト値は 0 です。これは、テナントが MemStore に使用できるメモリがテナントの総利用可能メモリに占める比率をシステムが自動的に調整することを意味します。

メモリ不足の場合は、`memstore_limit_percentage` の値を大きくし、`freeze_trigger_percentage` の値を小さくすることで、一時的に容量を拡張し、迅速にデータをダンプしてメモリをリソースすることができます。

例：

```sql
obclient> ALTER SYSTEM SET freeze_trigger_percentage = 20;
Query OK, 0 rows affected

obclient> ALTER SYSTEM SET memstore_limit_percentage = 70;
Query OK, 0 rows affected
```

## タイムアウト時間について

OceanBase データベースでは、クエリ実行時または DML 操作実行時に `timeout` または `Transaction is timeout` エラーが発生することがあります。これは、ユーザーが様々なビジネスシーンに合わせて調整できるようにするために、クエリとトランザクションのタイムアウトに対しデフォルトの時間を設定しているためです。

OceanBase データベースではタイムアウト時間に関して以下の変数が利用でき、`SHOW VARIABLES LIKE '%timeout%';` コマンドで確認することができます。

* [ob_query_timeout](https://en.oceanbase.com/docs/common-oceanbase-database-10000000001972234)：クエリのタイムアウト時間 (単位：us、デフォルト値：10000000)。

* [ob_trx_timeout](https://en.oceanbase.com/docs/common-oceanbase-database-10000000001972241)：トランザクションのタイムアウト時間 (単位：us、デフォルト値：86400000000)。

* [ob_trx_idle_timeout](https://en.oceanbase.com/docs/common-oceanbase-database-10000000001972152)：トランザクションアイドルタイムアウト時間 (単位：us、デフォルト値：86400000000)。

### タイムアウト時間の設定

タイムアウト時間の設定方法は以下のとおりです。

* セッション / グローバルでの変数の設定。例：

   ```sql
   obclient> SET ob_query_timeout = 10000000;
   Query OK, 0 rows affected

   obclient> SET GLOBAL ob_query_timeout = 10000000;
   Query OK, 0 rows affected
   ```

* JDBC 接続文字列による設定。例：

   ```html
   jdbc:mysql://10.1.0.0:1001/unittests?user=**u**@sys&password=******&sessionVariables = ob_query_timeout = 60000000000,ob_trx_timeout = 60000000000&xxxx
   ```

* SQL レベルでの Hint 設定の追加。例：

   <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>この方法は、現在の SQL 文に対してのみ有効です。 </p>
   </main>

   ```sql
   SELECT /*+query_timeout(100000000)  */  c1 FROM t1;
   ```
