# ご利用開始前に

OceanBase分散データベースをより快適にお使いいただくため、ご利用開始前に**メモリ**と**タイムアウト時間**という2つの最も一般的な特性の違いを理解しておきましょう。

## メモリについて

OceanBaseデータベースは、LSM-Treeを基盤としたストレージエンジンです。従来のデータベースが汚れたページをリアルタイムでフラッシュする仕組みとは異なり、OceanBaseデータベースではデータをメモリ上のMemTableとディスク上のSSTableに分けて管理します。すべてのデータ更新や書き込み操作はメモリ上のMemTableで行われ、メモリ使用量が一定のしきい値に達するとコンパクションがトリガーされ、データはSSTableにダンプされ、アクティブなメモリが解放されます。このアーキテクチャの利点は、ランダムI/OをシーケンシャルI/Oに変換し、より高い書き込みスループットを提供できることです。詳細については、[ストレージアーキテクチャの概要](../../700.reference/100.oceanbase-database-concepts/900.storage-architecture/100.storage-architecture-overview.md)を参照してください。

LSM-Treeは増分データをすべてメモリに格納し、一定のしきい値に達して初めてダンプをトリガーするため、小規模なテナントインスタンスがその処理能力を超える高頻度書き込みシナリオ（例えば、データインポートや大量のデータバッチ処理など）で動作する場合、MemTableが上限に達して新しいリクエストを受け付けられなくなる可能性があります。OceanBaseデータベースでは、以下のような対処方法が用意されています：

* 書き込み制限の有効化：メモリへの書き込みが一定のしきい値に達した場合、OceanBaseデータベースはクライアントのインポート速度を自動的に制限します。

* テナントメモリの拡張：環境内のノードの総メモリリソースが比較的十分な場合、テナントのメモリを拡大できます。

* テナントメモリ内のMemTableの割合の調整：ノードの総メモリが限られており、拡張が不可能な場合でも、テナントメモリ内のMemTableの割合を調整することで、書き込み可能なメモリ容量を拡大し、ダンプのしきい値を引き下げてより早くダンプを発生させることができます。

### 書き込み制限の有効化

OceanBaseデータベースには書き込み過負荷保護機能が備わっており、リソースが限られていてメモリを拡張できない場合でも、サーバー側の書き込み制限を設定することでメモリを保護し、書き込み超過を防ぐことができます。サーバー側の書き込み制限機能を有効にするには、以下の2つの構成パラメータを設定します。

* [writing_throttling_trigger_percentage](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/9000.writing_throttling_trigger_percentage.md)：書き込み速度のしきい値を設定します。MemStoreの使用済みメモリがこのしきい値（パーセンテージ）に達した場合、書き込み制限がトリガーされます。この構成パラメータの値の範囲は[1, 100]で、デフォルト値は60です。値を100に設定すると、書き込み制限メカニズムが無効になります。

* [writing_throttling_maximum_duration](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/8900.writing_throttling_maximum_duration.md)：書き込み制限がトリガーされた後、残りのMemStoreメモリを使い切るまでに必要な時間を指定します。デフォルト値は2時間で、この構成パラメータは通常変更しません。

テナントの管理者アカウントで、メモリ使用率が80％に達した時点で制限を開始し、残りのメモリが2時間分の書き込み制限を確実に提供できるように設定します。例：

```sql
obclient> ALTER SYSTEM SET writing_throttling_trigger_percentage = 80;
Query OK, 0 rows affected

obclient> ALTER SYSTEM SET writing_throttling_maximum_duration = '2h';
Query OK, 0 rows affected
```

### テナントメモリの拡張

環境内のメモリリソースが比較的豊富な場合、最適な対処方法はテナントのメモリを増やすことです。

メモリ設定手順は以下のとおりです：

1. `root`ユーザーでOceanBaseクラスタのsysテナントにログインし、以下のSQLステートメントを実行して、現在のテナントが使用している`UNIT_CONFIG NAME`を確認します。

   ```sql
   obclient> SELECT NAME FROM DBA_OB_UNIT_CONFIGS;
   +-----------------+
   | NAME            |
   +-----------------+
   | sys_unit_config |
   | test_unit       |
   +-----------------+
   2 rows in set
   ```

   <main id="notice" type='explain'>
    <h4>説明</h4>
    <p> <ul><li><code>sys_unit_config</code>は管理テナントのパラメータであり、通常は変更しません。</li><li>この例では、テナント<code>test</code>の<code>unit_config name</code>は<code>test_unit</code>です。</li></ul> </p>
   </main>

2. テナントの`unit_config name`をコピーし、以下のコマンドを使用してメモリ拡張を完了します。

   ```sql
   obclient> ALTER RESOURCE UNIT test_unit MIN_CPU = 2, MAX_CPU = 2, MEMORY_SIZE = '10G', MAX_IOPS = 10000, MIN_IOPS = 10000;
   ```

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>現在のバージョンでは、CPUとメモリの設定のみが有効であり、その他のI/Oパラメータ（例えばIOPS）はまだ有効ではありません。</p>
  </main>

### テナントメモリ内のMemStoreの割合の調整

以下の構成パラメータを使用して、テナントメモリ内のMemStoreの割合を調整します：

* `freeze_trigger_percentage`：この構成パラメータで指定された使用率に達すると、自動的にダンプがトリガーされ、使用されているメモリが解放されます。この構成パラメータの値の範囲は[1,99]で、デフォルト値は20です。これは、MemStoreの利用率が20％を超えるとダンプがトリガーされることを意味します。
* `memstore_limit_percentage`：この構成パラメータは、テナントメモリ内でMemStoreへの書き込みに使用可能な割合を制御します。値の範囲は[0, 100)で、デフォルト値は0です。これは、テナントがMemStoreに使用するメモリが、その総利用可能メモリに占める割合をシステムが適応的に調整することを意味します。

メモリ不足時には、`memstore_limit_percentage`の値を引き上げ、`freeze_trigger_percentage`の値を引き下げることで、一時的な拡張と早期のダンプによる解放効果を得ることができます。

OceanBaseクラスタのsysテナントに`root`ユーザーでログインし、`memstore_limit_percentage`の値を引き上げ、`freeze_trigger_percentage`の値を引き下げます。例：

```sql
obclient> ALTER SYSTEM SET freeze_trigger_percentage = 20;
Query OK, 0 rows affected

obclient> ALTER SYSTEM SET memstore_limit_percentage = 70;
Query OK, 0 rows affected
```

## タイムアウト時間について

OceanBaseデータベースでは、クエリやDML操作を実行する際に`timeout`または`Transaction is timeout`というエラーが発生する場合があります。これは、OceanBaseデータベースがクエリおよびトランザクションのタイムアウトに対してデフォルト設定を行っており、ユーザーが異なるビジネスシナリオに応じて調整できるようにするためです。

OceanBaseデータベースでは、以下のタイムアウト時間関連の変数が提供されており、`SHOW VARIABLES LIKE '%timeout%';`コマンドで確認できます。

* [ob_query_timeout](../../700.reference/800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/9000.ob_query_timeout-global.md)：クエリのタイムアウト時間（単位：us）。デフォルト値は10000000です。

* [ob_trx_timeout](../../700.reference/800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/10300.ob_trx_timeout-global.md)：トランザクションのタイムアウト時間（単位：us）。デフォルト値は86400000000です。

* [ob_trx_idle_timeout](../../700.reference/800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/10100.ob_trx_idle_timeout-global.md)：トランザクションのアイドル状態のタイムアウト時間（単位：us）。デフォルト値は86400000000です。

### タイムアウト時間の設定

タイムアウト時間の設定方法は以下の通りです：

* セッションまたはグローバルで変数を設定します。例：

   ```sql
   obclient> SET ob_query_timeout = 10000000;
   Query OK, 0 rows affected

   obclient> SET GLOBAL ob_query_timeout = 10000000;
   Query OK, 0 rows affected
   ```

* JDBC接続文字列で設定します。例：

   ```html
   jdbc:mysql://10.1.0.0:1001/unittests?user=**u**@sys&password=******&sessionVariables = ob_query_timeout = 60000000000,ob_trx_timeout = 60000000000&xxxx
   ```

* SQLレベルでHintを追加して設定します。例：

   <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>この方法は現在のSQL文にのみ有効です。 </p>
   </main>

   ```sql
   SELECT /*+query_timeout(100000000)  */  c1 FROM t1;
   ```
