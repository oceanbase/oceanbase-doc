# LOAD DATAステートメントを使用したデータのダイレクトロード

`LOAD DATA` ステートメントは、Hintとして `direct` を使用して、ダイレクトロードを行うかどうかを示します。

## 制限事項

* インポート処理中は、同時に2つの書き込み操作文を実行することができません（つまり、同時に1つのテーブルに書き込むことはできません）。これは、インポート処理中にテーブルロックがかかるためであり、またインポート処理全体を通じて読み取り操作のみが可能だからです。
* トリガー(Trigger)での使用はサポートされていません。
* 生成列を含むテーブルはサポートされていません（一部のインデックスでは隠れた生成列が作成されます。例：KEY `idx_c2` (`c2`(16)) GLOBAL）。
* 単一行で2MBを超えるデータのインポートはサポートされていません。
* Liboblogおよびフラッシュバッククエリ(Flashback Query)はサポートされていません。
* `LOB`型はサポートされていますが、パフォーマンスは比較的低く、`LOB`は元のトランザクションによるデータ書き込み経路を利用します。
* ダイレクトロードはDDLステートメントに属し、複数行のトランザクション（複数の操作を含むトランザクション）内で実行することはできません。

## 注意事項

OceanBaseデータベースは、パラレル処理技術を用いて`LOAD DATA`のデータインポート速度を最適化します。この操作では、データが複数のサブタスクに分割されて並行して実行され、各サブタスクは独立したトランザクションとして扱われます。そのため、主キーがないテーブルの場合、データの書き込み順序は元のファイル内の順序と異なる可能性があります。

## 構文

```sql
LOAD DATA /*+ direct(need_sort,max_error) parallel(N) */ [REMOTE_OSS | LOCAL] INFILE 'file_name' ...
```

`LOAD DATA`構文の詳細については、[LOAD DATA](../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/5900.load-data-of-mysql-mode.md)を参照してください。

**パラメータの説明：**

|パラメータ|説明|
|------|------|
| direct | ダイレクトロードを実行することを示します。|
| need_sort | OceanBaseデータベースによるデータのソートが必要かどうかを示します。</br>値は`bool`型です：<ul><li>`true`：ソートが必要であることを示します。</li><li>`false`：ソートが不要であることを示します。</li></ul>|
| max_error | 容認される最大のエラー行数を示します。値は`INT`型であり、この数値を超えると`LOAD DATA`は失敗として報告されます。|
| parallel(N) | データ読み込みの並列度で、必須項目です。値は1より大きい整数です。|
| REMOTE_OSS \| LOCAL | オプション項目です。<ul><li> <code>REMOTE_OSS</code>は、OSSファイルシステムからデータを読み取るかどうかを指定します。<main id="notice" type='notice'><h4>注意</h4><p>このパラメータを使用する場合、<code>file_name</code>は必ずOSSのアドレスでなければなりません。</p></main>  </li><li> <code>LOCAL</code>は、クライアントのローカルファイルシステムからデータを読み取るかどうかを指定します。`LOCAL`パラメータを使用しない場合、サーバー側（OBServerノード）のファイルシステムからデータを読み取ります。</li></ul> |

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>ここで言うOSSとは、オブジェクトストレージのOSS(<code>oss://</code>)、COS(<code>cos://</code>)、S3(<code>s3://</code>)などを指します。以下も同様です。</p>
</main>

## ワイルドカード方式による複数ファイルのインポート

複数ファイルのインポートを容易にするため、ファイルワイルドカード機能が導入されました。server_diskおよびOSSタイプのファイルソースに適用されますが、クライアントディスク(client_disk)には適用されません。

### クラスタ内ファイルシステム（server_disk）のダイレクトロードの使用方法

* **server_diskの例：**

  * ファイル名に一致するもの：`load data /*+ parallel(20) direct(true, 0) */ infile '/xxx/test.*.csv' replace into table t1 fields terminated by '|';`

  * ディレクトリに一致するもの：`load data /*+ parallel(20) direct(true, 0) */ infile '/aaa*bb/test.1.csv' replace into table t1 fields terminated by '|';`

  * ディレクトリとファイル名の両方に一致するもの：`load data /*+ parallel(20) direct(true, 0) */ infile '/aaa*bb/test.*.csv' replace into table t1 fields terminated by '|';`

* **server_diskの注意点：**

  * 一致するファイルが少なくとも1つ存在しなければ、エラーコード4027が返されます。

  * `load data /*+ parallel(20) direct(true, 0) */ infile '/xxx/test.1*.csv,/xxx/test.6*.csv' replace into table t1 fields terminated by '|';` の入力に対して、`/xxx/test.1*.csv,/xxx/test.6*.csv` は全体一致と見なされます。一致するものがない場合、エラー4027が報告されます。

  * POSIXのGLOB関数でサポートされているワイルドカードのみがサポートされています。たとえば、`test.6*(6|0).csv` および `test.6*({0.csv,6.csv}|.csv)` は `ls` コマンドで検索できますが、GLOB関数では一致せず、エラー4027が報告されます。

### クラウドオブジェクトストレージサービス（OSS）ダイレクトロードの使用方法

* **OSS例：**

  * ファイル名のマッチング：`load data /*+ parallel(20) direct(true, 0) */ remote_oss infile 'oss://xxx/test.*.csv?host=xxx&access_id=xxx&access_key=xxx' replace into table t1 fields terminated by '|';`

* **OSSの注意点：**

  * ディレクトリのマッチングはサポートされていません。例えば、`load data /*+ parallel(20) direct(true, 0) */ remote_oss infile 'oss://aa*bb/test.*.csv?host=xxx&access_id=xxx&access_key=xxx' replace into table t1 fields terminated by '|';` を実行すると、`OB_NOT_SUPPORTED` が返されます。

  * ファイル名のワイルドカードは `*` と `?` のみをサポートしています。他のワイルドカードは入力は可能ですが、マッチング結果は得られません。

## 例

  <main id="notice" type='explain'>
     <h4>説明</h4>
     <p>以下の例は、サーバー側のファイルからデータをインポートする方法です。OceanBaseデータベースの <code>LOAD DATA</code> ステートメントによるダイレクトロードでは、ローカルファイル(<code>LOCAL INFILE</code>)の読み込みもサポートされています。<code>LOAD DATA LOCAL INFILE</code> の詳細な例については、<a href="../700.migrate-data-from-csv-file-to-oceanbase-database/200.use-the-load-command-to-load-the-csv-data-file-to-the-oceanbase-database.md"><code>LOAD DATA</code> ステートメントを使用したデータのインポート</a>を参照してください。</p>
   </main>

1. OBServerノードが存在するマシンにログインし、`/home/admin` ディレクトリにテストデータを作成します。

    <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>OceanBaseデータベースの <code>LOAD DATA</code> ステートメントは、OBServerノードのローカル入力ファイルの読み込みのみをサポートしています。そのため、インポートする前にファイルを特定のOBServerにコピーする必要があります。</p>
    </main>

    ```shell
    [xxx@xxx /home/admin]# ssh admin@10.10.10.1

    [admin@xxx /home/admin]# vi tbl1.csv
    1,11
    2,22
    3,33
    ```

2. インポートするファイルのパスを設定します。

    システム変数 `secure_file_priv` を設定して、ファイルのインポートまたはエクスポート時にアクセスできるパスを構成します。

    <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>セキュリティ上の理由により、システム変数 <code>secure_file_priv</code> を設定する場合、ローカルソケット経由でデータベースに接続し、このグローバル変数を変更するSQLステートメントを実行する必要があります。詳細については、<a href="../../700.reference/800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/11500.secure_file_priv-global.md">secure_file_priv</a>を参照してください。</p>
    </main>

    1. OBServerノードが存在するマシンにログインします。

        ```shell
        [xxx@xxx /home/admin]# ssh admin@10.10.10.1
        ```

    2. 以下のコマンドを実行して、ローカルUnixソケット接続方式でテナント `mysql001` に接続します。

        ```shell
        obclient -S /home/admin/oceanbase/run/sql.sock -uroot@mysql001 -p******
        ```

    3. インポートパスを `/home/admin` に設定します。

        ```shell
        obclient [(none)]> SET GLOBAL secure_file_priv = "/home/admin";
        Query OK, 0 rows affected
        ```

3. データベースに再接続した後、`LOAD /*+ APPEND */ DATA` ステートメントを使用してデータをインポートします。

    ```shell
    obclient [test]> CREATE TABLE tbl1(col1 INT PRIMARY KEY,col2 INT);
    Query OK, 0 rows affected

    obclient [test]> SELECT * FROM tbl1;
    Empty set

    obclient [test]> LOAD DATA /*+ direct(true,1024) parallel(16) */ INFILE '/home/admin/tbl1.csv' INTO TABLE tbl1 FIELDS TERMINATED BY ',';
    Query OK, 3 rows affected
    Records: 3  Deleted: 0  Skipped: 0  Warnings: 0

    obclient [test]> SELECT * FROM tbl1;
    +------+------+
    | col1 | col2 |
    +------+------+
    |    1 |   11 |
    |    2 |   22 |
    |    3 |   33 |
    +------+------+
    3 rows in set
    ```
