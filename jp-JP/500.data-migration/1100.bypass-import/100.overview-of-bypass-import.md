# ダイレクトロードの概要

OceanBaseデータベースは、ダイレクトロード方式でデータをデータベースに挿入することをサポートしています。つまり、OceanBaseデータベースは`data`ファイルに直接データを書き込む機能をサポートしています。ダイレクトロードは、SQL層のインターフェースをバイパスし、`data`ファイルに直接領域を割り当ててデータを挿入することで、データインポートの効率を向上させることができます。

## 使用シナリオ

* **データ移行と同期**：他のデータベース（MySQL、Oracle、または旧バージョンのOceanBaseデータベースなど）から大規模なデータをOceanBase V4.xクラスタに移行する必要があります。

  * **利点**：従来のSQLインターフェースは、大量データ移行時のパフォーマンスに制限がありますが、ダイレクトロードはSQL層をバイパスして直接データファイルに書き込むため、移行効率を向上させることができます。また、**異種データベース間の移行**もサポートしており、例えばMySQLからの移行時にはダイレクトロードを使用して迅速にデータを読み込むことができます。

* **従来のETLプロセスの最適化**：データがソース側で抽出・変換された後、ターゲット側にロードする際には通常、短時間で大量のデータを読み込む必要があります。ダイレクトロード技術を使用することで、データインポートのパフォーマンスが向上します。

  * **利点**：ダイレクトロードは、最終データを直接OceanBaseデータベースの下層データファイルに書き込むため、SQLインターフェースを通じて1件ずつ挿入する際のパフォーマンスボトルネックを回避できます。また、**ELTプロセス**（Extract-Load-Transform）に対しても同様に適用可能であり、まず効率的にデータを読み込んだ上で、その後の分析を行うことができます。

* **ファイルまたは外部データソースの高速ロード**：CSV、ParquetなどのファイルやHadoop、Kafkaなどの外部データソースから、一括でデータをOceanBaseデータベースにロードします。

  * **利点**：**分散並列ロード**をサポートしており、データをパーティションやシャード単位に分割した後、複数のノードに同時に書き込みます。

* **異なるバージョン間のバックアップデータ復旧**：OceanBaseデータベースV1.4x/V3.x/V2.xバージョンのバックアップデータ（論理または物理バックアップ）を、直接OceanBaseデータベースV4.xバージョンにインポートします。

  * **サポートバージョンは以下の通りです**：

    * **論理バックアップ(V1.4x/V2.2.30)**：OceanBaseデータベースV1.4x/V2.2.30バージョンの論理バックアップ形式は、ダイレクトロードを通じて直接OceanBaseデータベースV4.xバージョンに復旧できます。
    * **物理バックアップ(V3.x/V2.2.77)**：OceanBaseデータベースV3.x/V2.2.77の物理バックアップ形式は、ダイレクトロードを通じて直接OceanBaseデータベースV4.xバージョンに復旧できます。

  * **利点**：ダイレクトロードを使用して、あらかじめベースラインデータを高バージョンのクラスタにインポートすることで、論理アップグレード時に大量のデータを引きずり込むことによるメインデータベースのオンライン業務への干渉を回避できます。

## 注意事項

* ダイレクトロードでは、既存のすべてのデータが一度書き直されます。元のテーブルのデータ量が非常に大きい場合、またはインポートするデータ量が少ない場合、どちらもダイレクトロードを使用するのは適切ではありません。

* ダイレクトロードの過程で一時ファイルが生成されます。インポートするデータ量が多い場合、一時ファイルが占有するディスク容量も大きくなるため、ディスク容量に注意し、ダイレクトロードによって生成される一時ファイルがディスク容量を圧迫するのを防ぐ必要があります。また、ダイレクトロードの`並列度 >= 8`の場合、システムは一時ファイルを圧縮して、一時ファイルの容量占有を削減します。
