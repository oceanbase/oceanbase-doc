# OceanBaseデータ移行ツールを使用して、OceanBaseクラスタのMySQLテナントからOracleテナントへデータを移行する

本記事では、OceanBaseデータ移行ツールを使用して、OceanBaseデータベースのMySQLテナントからOracleテナントへデータを移行する方法について説明します。

## OceanBaseデータエクスポート・インポートツールの概要

OceanBaseデータエクスポート・インポートツールには、エクスポートツールobdumperとインポートツールobloaderが含まれます。

* obdumperは、Javaで開発されたクライアントエクスポートツールです。このツールを使用して、OceanBaseデータベース内で定義されたオブジェクトとデータをファイルにエクスポートできます。obdumperの詳細については、[obdumperの概要](https://www.oceanbase.com/docs/enterprise-oceanbase-dumper-loader-cn-10000000001142215)を参照してください。

* obloaderは、Javaで開発されたクライアントインポートツールです。このツールは非常に柔軟なコマンドラインオプションを提供しており、さまざまな複雑なシナリオで定義とデータをOceanBaseにインポートできます。obloaderの詳細については、[obloaderの概要](https://www.oceanbase.com/docs/enterprise-oceanbase-dumper-loader-cn-10000000001142221)を参照してください。

## 手順

1. obdumperとobloaderの実行環境を準備します。[環境の準備](https://www.oceanbase.com/docs/enterprise-oceanbase-dumper-loader-cn-10000000001142213)および[ツールのダウンロード](https://www.oceanbase.com/docs/enterprise-oceanbase-dumper-loader-cn-10000000001142214)を参照してください。

2. エクスポートデータを格納するディレクトリを作成します。

3. テーブル構造/データをエクスポートします。

   ```shell
   [xxx@xxx /ob-loader-dumper-4.0.0-RELEASE/bin]
   $./obdumper -h <ホストIP> -P <ポート> -u <ユーザー> -p <パスワード> [--sys-user <sysテナント内のユーザー名> --sys-password <sysテナント内の特定ユーザーのパスワード>] -c <クラスタ名> -t <テナント> -D <スキーマ名> [--ddl] [--csv|--sql] [--all|--table 'テーブル名'] -f <データファイルまたはディレクトリ>
   ```

   <main id="notice" type='explain'>
     <h4>説明</h4>
     <ul>
     <li>OceanBase物理ノードのホストアドレスとポートを使用してデータをエクスポートする場合、<code>-c</code>オプションを指定する必要はありません。</li>
     <li>obdumperコマンドラインオプションの詳細については、<a href="https://www.oceanbase.com/docs/enterprise-oceanbase-dumper-loader-cn-10000000001142216">コマンドラインオプション</a>を参照してください。</li>
     </ul>
   </main>

4. テーブル構造/データをインポートします。

   ```shell
   [xxx@xxx /ob-loader-dumper-4.0.0-RELEASE/bin]
   $./obloader -h <ホストIP> -P <ポート> -u <ユーザー> -p <パスワード>  --sys-user <sysテナント内のrootユーザーまたはproxyroユーザー> --sys-password <sysテナント内のアカウントパスワード> -c <クラスタ> -t <テナント> -D <スキーマ名> [--ddl] [--csv|--sql] [--all|--table 'テーブル名'] -f <データファイルまたはディレクトリ>
   ```

    <main id="notice" type='explain'>
     <h4>説明</h4>
     <ul>
     <li>OceanBase物理ノードのホストアドレスとポートを使用してデータをインポートする場合、<code>-c</code>オプションを指定する必要はありません。</li>
     <li>obloaderコマンドラインオプションの詳細については、<a href="https://www.oceanbase.com/docs/enterprise-oceanbase-dumper-loader-cn-10000000001142222">コマンドラインオプション</a>を参照してください。</li>
     </ul>
   </main>

### テーブル構造の移行

obdumperとobloaderを使用してテーブル構造を移行する際は、`--sys-user`および`--sys-password`オプションを指定して、テーブル構造メタデータ情報を取得する必要があります。これらのオプションを指定しない場合、エクスポート/インポート機能およびパフォーマンスに大きな影響を与える可能性があります。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p><code>--sys-user</code>オプションは、<code>sys</code>テナント内で特定の権限を持つユーザーに接続するために使用されます。エクスポート時にこのオプションを指定しない場合、デフォルトでは<code>--sys-user root</code>が指定されます。</p>
  </main>

#### DDL定義ファイルのインポート

シナリオの説明：クラスタ`test4000`のテナント`mysql001`にあるSchema`test_data`から、サポートされているすべての定義情報を`/home/admin/test_migrate_data/ddl_data`ディレクトリにエクスポートし、クラスタ`test4000`のテナント`oracle001`にあるSchema`obloader_user01`にインポートします。

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>MySQLテナントからエクスポートされたDDLファイルは、Oracleテナントの構文要件に適合していないため、MySQLテナントからエクスポートされたDDLファイルを、まずOracleテナントの構文要件に適合するDDLファイルに変更した後、Oracleテナントにインポートします。</p>
    <p>例えば、テナント<code>mysql001</code>からエクスポートされたDDLファイルの変更ルールは以下のとおりです：</p>
    <ul>
    <li><code>if not exists</code>キーワードとシングルクォートを削除します。</li>
    <li>データ型をOracleモードで共通するデータ型に変更します：
    <ul>
    <li><code>int(11)</code>を<code>number(11)</code>に変更します。</li>
    <li><code>varchar(50)</code>を<code>varchar2(50)</code>に変更します。</li>
    </ul>
    </li>
    <li>デフォルトの照合順序と文字セットパラメータ<code>default charset=utf8mb4</code>、<code>default collate=utf8mb4_general_ci</code>を削除します。</li>
    </ul>
    <p>Oracleモードのデータ型の詳細については、<a href="https://www.oceanbase.com/docs/enterprise-oceanbase-database-cn-10000000000886657">組み込みデータ型の概要</a>を参照してください。</p>
  </main>
