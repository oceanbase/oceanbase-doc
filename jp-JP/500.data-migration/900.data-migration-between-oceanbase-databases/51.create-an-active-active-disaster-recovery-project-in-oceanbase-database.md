# OMSを使用したOceanBaseデータベースの同一種類テナントによる災害復旧アクティブ/アクティブプロジェクトの作成

本記事では、OceanBase Migration Service（OMS）を使用してOceanBaseデータベースの同一種類テナントによる災害復旧アクティブ/アクティブプロジェクトを作成するための背景情報について簡単に説明します。

## 背景

ますます多くのユーザーがOMSを使用してデータ移行を行うにつれて、OMSが対応すべきユーザーシナリオも多様化しています。現在広く利用されている単一リージョン間のデータ移行や同期シナリオに加えて、OMSは複数リージョン間でのデータ移行、および異なる都市間でのデータ同期やアクティブ/アクティブ同期もサポートしています。

現在、OMSがサポートしている災害復旧アクティブ/アクティブシナリオは以下のとおりです：

* 同一都市内のデータ移行とデータ同期

* 同一都市内のプライマリ/スタンバイ災害復旧

* 同一都市内のアクティブ/アクティブ

* 異なる都市間のデータ移行とデータ同期

* 異なる都市間のプライマリ/スタンバイ災害復旧

* 異なる都市間のアクティブ/アクティブ

プライマリ/スタンバイ災害復旧は、データ災害復旧が必要なシナリオで一般的です。OMSを使用して本番データセンターからスタンバイデータセンターへのデータ同期プロジェクトを作成することで（プロジェクトのリアルタイム性を確保）、本番データセンターで災害やダウンなどの事象が発生した場合でも、業務をスタンバイデータセンターに切り替えることができ、業務への影響を回避できます。

しかし、プライマリ/スタンバイ災害復旧では、スタンバイデータセンターのリソースが無駄になるなどの問題が生じやすいです。そのため、OMSはアクティブ/アクティブのソリューションを提供しており、実際の業務トラフィックを同時に2つのデータセンターで処理します。

OceanBaseデータベースの災害復旧アクティブ/アクティブデータ移行プロジェクトには、フォワードスイッチの手順がなく、また災害復旧アクティブ/アクティブデータ移行プロジェクトでは、1つのリンクでのみDDLパラメータを有効にすることが許可されています。

## 関連ドキュメント

OMSを使用してOceanBaseデータベースの同一種類テナントによる災害復旧アクティブ/アクティブプロジェクトを作成するための詳細な操作情報については、[OceanBaseデータベースの災害復旧アクティブ/アクティブデータ移行](https://www.oceanbase.com/docs/enterprise-oms-doc-cn-1000000000091376)を参照してください。
