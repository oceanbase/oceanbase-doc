# OMSを使用したOceanBaseデータベースの同一タイプテナントによるディザスタリカバリアクティブ-アクティブプロジェクトの作成

本記事では、OceanBase Migration Service（OMS）を使用してOceanBaseデータベースの同一タイプテナントによるディザスタリカバリアクティブ-アクティブプロジェクトを作成する背景情報について簡潔に紹介します。

## 背景情報

ますます多くのユーザーがOMSを使用してデータ移行を行う中、OMSが対応すべきユースケースも多様化しています。現在広く利用されている単一リージョンのデータ移行やデータ同期に加え、OMSは複数リージョン間でのデータ移行、および異なる都市間でのデータ同期やアクティブ-アクティブ同期もサポートしています。

現在OMSがサポートするディザスタリカバリアクティブ-アクティブシナリオは以下の通りです：

* 同一都市内のデータ移行とデータ同期

* 同一都市内のプライマリ/スタンバイディザスタリカバリ

* 同一都市内のアクティブ-アクティブ

* 異なる地域間のデータ移行とデータ同期

* 異なる地域間のプライマリ/スタンバイディザスタリカバリ

* 異なる地域間のアクティブ-アクティブ

プライマリ/スタンバイディザスタリカバリは、データディザスタリカバリが必要なシナリオで一般的です。OMSを基盤として、プライマリデータセンターからスタンバイデータセンターへのデータ同期プロジェクト（プロジェクトのリアルタイム性を確保するため）を作成することで、本番データセンターで災害やダウンなどの事象が発生した場合、業務をスタンバイデータセンターに切り替えることができ、業務への影響を回避できます。

しかし、プライマリ/スタンバイディザスタリカバリでは、スタンバイデータセンターのリソースが遊休状態が問題になりがちです。そのため、OMSはアクティブ-アクティブのソリューションを提供しており、実際の業務トラフィックを同時に2つのデータセンターが負担する方式です。

OceanBaseデータベースのディザスタリカバリアクティブ-アクティブデータ移行プロジェクトには、フォワードスイッチングの手順がなく、またディザスタリカバリアクティブ-アクティブデータ移行プロジェクトでは、1つのリンクでのみDDLパラメータを有効にできます。
