# DataXを使用してOceanBaseのテーブルデータをOracleデータベースに移行する

DataXは、Alibaba Cloud DataWorksのデータ統合機能のオープンソース版であり、Alibabaグループ内で広く利用されているオフラインデータ同期ツール/プラットフォームです。DataXは、MySQL、Oracle、SQL Server、PostgreSQL、HDFS、Hive、ADS、HBase、TableStore（OTS）、MaxCompute（ODPS）、Hologres、DRDS、OceanBaseなど、さまざまな異種データソース間の効率的なデータ同期機能を実装しています。

OceanBaseデータベースCommunity Editionのお客様は、[DataXオープンソースサイト](https://github.com/alibaba/datax)からソースコードをダウンロードし、ご自身でコンパイルできます。コンパイル時には、必要に応じて`pom.xml`で不要なデータベースプラグインを除外することができます。そうしない場合、コンパイルされたバイナリは非常に大きくなります。

## フレームワーク設計

DataXはオフラインデータ同期フレームワークとして、「Framework + Plugin」モードで構築されています。データソースの読み取りと書き込みをReader/Writerプラグインに抽象化し、同期フレームワーク全体に統合します。

* Readerはデータ収集モジュールとして機能し、データソースからデータを収集してフレームワークに送信します。

* Writerはデータ書き込みモジュールとして機能し、フレームワークからデータを継続的に取得し、ターゲット側に書き込みます。

* FrameworkはReaderとWriterを接続し、両者間のデータ伝送チャネルとして機能するとともに、バッファリング、ストリーム制御、並行処理、データ変換などのコア技術的課題を処理します。

DataXはタスク単位でデータを移行します。各タスクは1つのテーブルのみを処理し、各タスクには`json`形式の設定ファイルがあります。設定ファイルには`reader`と`writer`の2部分が含まれます。`reader`と`writer`はそれぞれ、DataXがサポートするデータベースの読み書きプラグインです。例えば、OceanBaseのテーブルデータをOracleデータベースに移行する操作では、OceanBaseデータベースからデータを読み取ってOracleデータベースに書き込む必要があるため、OceanBaseデータベースの`oceanbasev10reader`プラグインとOracleデータベースの`oraclewriter`プラグインを組み合わせて使用します。ここでは`oceanbasev10reader`プラグインと`oraclewriter`プラグインについて紹介します。

### `oceanbasev10reader`プラグイン

実装原理として、`oceanbasev10reader`はDataXフレームワークからReaderが生成したプロトコルデータを取得し、INSERT文を生成します。データ書き込み時に主キーまたは一意キーの競合が発生した場合、OceanBaseデータベースのMySQLテナントは`replace`モードを使用してテーブル内のすべてのフィールドを更新できますが、OceanBaseデータベースのOracleテナントは現在INSERT方式のみを使用できます。

`oceanbasev10reader`プラグインは、OceanBaseデータベースからデータを読み取る機能を実装しています。基盤実装として、`oceanbasev10reader`プラグインはJavaクライアント（基盤となるMySQL JDBCまたはOceanBase Client）を介してobproxy経由でOceanBaseデータベースにリモート接続し、対応するSQL文を実行してOceanBaseデータベースからデータをSELECTします。

実装原理を簡潔に言えば、OceanBaseデータベースはJavaクライアント（基盤となるMySQL JDBCまたはOceanBase Client）を介してobproxy経由でOceanBaseデータベースにリモート接続し、ユーザーの設定情報に基づいてクエリ文を生成してリモートのOceanBaseデータベースに送信します。リモートのOceanBaseデータベースは、そのSQLの実行結果をDataX独自のデータ型を用いて抽象化されたデータセットに組み立て直し、下流のWriterへと処理を引き渡します。

### `oraclewriter`プラグイン

`oraclewriter`プラグインは、データをOracleメインデータベースのターゲットテーブルに書き込む機能を実装しています。基盤実装として、`oraclewriter`プラグインはJDBC接続を介してリモートのOracleデータベースに接続し、対応する`insert into ...`文を実行してデータをOracleデータベースに書き込みます。Oracleデータベース内部では、データはバッチ単位でコミットされます。

実装原理として、OracleWriterはDataXフレームワークからReaderが生成したプロトコルデータを取得し、ユーザーの設定に基づいて対応するSQL文`insert into...`を生成して、データをOracleメインデータベースのターゲットテーブルに挿入します。

詳細な機能とパラメータの説明については、公式ドキュメントを参照してください：[`oraclewriter`プラグイン](https://github.com/alibaba/DataX/blob/master/oraclewriter/doc/oraclewriter.md).

### DataX設定ファイル

設定ファイルの例：

```json
{
  "job": {
    "content": [
      {
        "reader": {
          "name": "streamreader",
          "parameter": {
            "sliceRecordCount": 10,
            "column": [
              {
                "type": "long",
                "value": "10"
              },
              {
                "type": "string",
                "value": "hello、こんにちは、世界-DataX"
              }
            ]
          }
        },
        "writer": {
          "name": "streamwriter",
          "parameter": {
            "encoding": "UTF-8",
            "print": true
          }
        }
      }
    ],
    "setting": {
      "speed": {
        "channel": 2
       }
    }
  }
}
```

<main id="notice" type='notice'>
<h4>注意</h4>
<p>dataxはテーブルデータのみを移行します。ターゲット側に対応するテーブルオブジェクト構造を事前に作成しておく必要があります。</p>
</main>

`json` 設定ファイルをDataXのディレクトリ `job` またはカスタムパスに配置します。実行方法は以下のとおりです：

```bash
$bin/datax.py job/stream2stream.json
```

DataXタスクの実行終了時には、上記の出力情報を含む平均転送量、書き込み速度、読み書き失敗数などの簡単なタスクレポートが生成されます。

DataXの `job` パラメータ `settings` では、速度パラメータやエラーレコードの許容度などを指定できます。

```json
"setting": {
            "speed": {
                "channel": 10
            },
            "errorLimit": {
                "record": 10,
                "percentage": 0.1
            }
        }
```

パラメータの説明：

- `errorLimit` はエラーレコード数の許容範囲を表します。この制限を超えるとタスクは中断され終了します。
- `channel` は並列数です。理論上、並列数が多いほど移行性能は向上します。ただし、実際の運用では、ソース側の読み取り負荷、ネットワーク転送性能、およびターゲット側の書き込み性能も考慮する必要があります。

## `環境準備`

tarファイルのダウンロードURL：http://datax-opensource.oss-cn-hangzhou.aliyuncs.com/datax.tar.gz

インストールファイルの解凍：

```shell
tar zxvf datax.tar.gz
cd datax
```

ディレクトリ構造は以下のとおりです：

```shell
$tree -L 1 --filelimit 30
.
├── bin
├── conf
├── job
├── lib
├── log
├── log_perf
├── plugin
├── script
└── tmp
```

インストールファイルには、以下のディレクトリが含まれています。それぞれの役割を確認してください。

| ディレクトリ名 | 説明 |
| --- | --- |
| bin | 実行可能ファイルのディレクトリです。このディレクトリ内のdatax.pyは、DataXタスクの起動スクリプトです。 |
| conf | ログファイルの設定ディレクトリです。このディレクトリには、dataxとタスクに関係ない設定ファイルが格納されています。 |
| lib | 実行時依存パッケージです。このディレクトリには、DataXの実行に必要なグローバルJARファイルが格納されています。 |
| job | このディレクトリには、dataxのインストールをテスト検証するためのタスク設定ファイルがあります。 |
| log | ログファイルのディレクトリです。このディレクトリには、dataxタスクの実行ログが格納されています。dataxの実行時、ログは標準出力に出力されると同時に、logディレクトリにも書き込まれます。 |
|plugin|プラグインファイルのディレクトリです。このディレクトリには、DataXがサポートする各種データソースプラグインが保存されています。|

## DataXを使用してOceanBaseデータをOracleデータベースに移行する例

OceanBaseデータをOracleデータベースに移行する場合、ソース側とターゲット側が同時にDataXサーバーとネットワークで接続できない場合は、CSVファイルを経由して中継できます。ソースデータベースとターゲットデータベースが同時にDataXサーバーと接続できる場合は、DataXを使用して直接、ソースからターゲットへデータを移行できます。

例：OceanBaseからtest.t1テーブルのデータをOracleデータベースのtest.t1に移行します。

myjob.json設定ファイルは以下のとおりです：

```javascript
{
    "job": {
        "setting": {
            "speed": {
                "channel": 4
            },
            "errorLimit": {
                "record": 0,
                "percentage": 0.1
            }
        },
        "content": [
            {
                "reader": {
                    "name": "oceanbasev10reader",
                    "parameter": {
                        "username": "******",
                        "password": "******",
                        "column": ["*"],
                        "connection": [
                            {
                                "table": ["t1"],
                                "jdbcUrl": ["jdbc:oceanbase://172.30.xxx.xxx:2883/test"]
                            }
                        ]
                    }
                },
                "writer": {
                    "name": "oraclewriter",
                    "parameter": {
                        "obWriteMode": "insert",
                        "column": ["*"],
                        "preSql": ["truncate table t1"],
                        "connection": [
                            {
                                "jdbcUrl": "jdbc:oracle:thin:@172.30.xxx.xxx:1521:test",
                                "table": ["TEST.T1"]
                            }
                        ],
                        "username": "******",
                        "password":"******",
                        "writerThreadCount":10,
                        "batchSize": 1000,
                        "memstoreThreshold": "0.9"
                    }
                }
            }
        ]
    }
}
```

パラメータ説明

|    パラメータ    |          説明    |
|----------|--------------------|
| name | データベースに接続するためのreaderまたはwriterに対応するデータベースプラグインの名前を記述します。MySQLのreaderプラグインはmysqlreader、OceanBaseのwriterプラグインはoceanbasev10writerです。具体的なreaderとwriterのプラグインについては、dataxのドキュメントを参照してください：[DataXデータソースガイド](https://github.com/alibaba/datax)。|
| jdbcUrl  |接続先データベースへのJDBC情報を記述し、JSON配列を使用して記述します。1つのデータベースに複数の接続アドレスを入力することもできます。JSON配列に1つのJDBC接続を入力するだけで済みます。jdbcUrlはMySQL公式仕様に準拠しており、接続オプションの制御情報を入力することができます。詳細については、[MySQL公式ドキュメント](http://dev.mysql.com/doc/connector-j/en/connector-j-reference-configuration-properties.html)を参照してください。 <main id="notice" type='notice'><h4>注意</h4><p><ul><li>jdbcUrlはconnection設定ユニットに含まれている必要があります。</li> <li>OceanBaseデータベースはobproxyを介して接続する必要があり、ポートはデフォルトで2883です。</li><li> writer側のjdbcUrlには、接続文字列の両端に<code>[]</code>を付加する必要はありませんが、reader側のjdbcUrlには必ず<code>[]</code>を両端に付加する必要があります。</li></ul></p></main>  <ul><li>必須：はい</li> <li>デフォルト値：なし</li></ul>    |
| username |データソースのユーザー名</li> <li>必須：はい</li> <li>デフォルト値：なし</li></ul>    |
| password |データソースの指定ユーザー名のパスワード</li> <li>必須：はい</li> <li>デフォルト値：なし</li></ul>              |
| table    |同期が必要な選択されたテーブル。JSON配列を使用して記述するため、複数のテーブルを同時に抽出することができます。複数のテーブルを設定した場合、ユーザーは複数のテーブルが同一のスキーマ構造であることを確認する必要があります。MySQLReaderは、テーブルが同一の論理テーブルであるかどうかをチェックしません。<main id="notice" type='notice'><h4>注意</h4><p>tableはconnection設定ユニットに含まれている必要があります。</p></main> <ul><li>必須：はい</li> <li>デフォルト値：なし</li></ul>  |
| column   | 設定されたテーブルで同期が必要な列名の集合。JSON配列を使用してフィールド情報を記述します。columnsを`['*']`に設定することは推奨されません。テーブル構造が変更された場合、この設定も変更されるためです。具体的な列名を指定する設定方法を推奨します。列のトリミング、つまり一部の列のみをエクスポートすることができます。列の並べ替え、つまりテーブルのスキーマ情報に従わない順序で列をエクスポートすることができます。定数の設定が可能で、ユーザーはMySQL SQL構文に従って指定する必要があります：``["id", "`table`", "1", "'bazhen.csy'", "null", "to_char(a + 1)", "2.3" , "true"]``。 <main id="notice" type='explain'><h4>説明</h4><p><ul><li><code>id</code> は通常の列名です。</li> <li><code>table</code> は予約語を含む列名です。</li> <li><code>1</code> は整数定数です。</li>  <li><code>bazhen.csy</code> は文字列定数です。</li> <li><code>null</code> はNULLポインタです。</li> <li><code>to_char(a + 1)</code> は式です。</li> <li><code>2.3</code> は浮動小数点数です。</li><li><code>true</code> はブール値です。</li></ul> </p></main> <ul><li>必須：はい</li> <li>デフォルト値：なし</li></ul> |
| where    | 絞り込み条件です。MySQLReaderは、指定されたcolumn、table、where条件を組み合わせてSQLを生成し、このSQLに基づいてデータを抽出します。実際の業務シナリオでは、通常は当日のデータを同期することを選択します。そのため、where条件を`gmt_create > $bizdate`と指定することができます。 <main id="notice" type='notice'><h4>注意</h4><p> <code>where</code> 条件を <code>limit 10</code> と指定することはできません。<code>limit</code> はSQLの有効な <code>where</code> 句ではありません。<code>where</code> 条件を使用すると、業務の増分同期を順次行うことができます。<code>where</code> ステートメントを記入しない場合、<code>where</code> の <code>key</code> または <code>value</code> を指定しない場合でも、DataXは全量データの同期と見なします。</p></main><ul><li>必須：いいえ</li><li>デフォルト値：なし</li></ul>   |

jobファイルを設定した後、そのjobを実行します。コマンドは以下のとおりです：

```shell
python datax.py ../job/myjob.json
```
