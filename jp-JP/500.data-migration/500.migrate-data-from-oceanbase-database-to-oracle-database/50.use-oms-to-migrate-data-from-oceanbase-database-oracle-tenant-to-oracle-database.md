# OMSを使用してOceanBaseデータベースのOracleテナントからOracleデータベースへデータを移行する

本記事では、OceanBase Migration Service（OMS）を使用してOceanBaseデータベースのOracleテナントからOracleデータベースへデータを移行する際の背景情報について簡単に説明します。

## 背景

OMSコンソールでOceanBaseデータベースのOracleテナントからOracleデータベースへのデータ移行プロジェクトを作成すると、構造移行、フル移行、および増分同期を通じて、ソース側データベースの既存業務データと増分データをシームレスにOracleデータベースへ移行できます。

Oracleデータベースは、単一プライマリデータベース、単一スタンバイデータベース、およびプライマリ/スタンバイデータベースなどのモードをサポートしています。OceanBaseデータベースのOracleテナントからOracleデータベースへデータを移行する際、異なるタイプのデータソースに対応する操作も異なります。

| タイプ | サポートされる操作 |
|-----|-----------------------------------------------------------|
| プライマリストア | スキャナー移行 + フル移行 + 増分同期 + フル検証 + リバース増分 |
| スタンバイストア | スタンバイストアのOracleデータソースをデータ移行のターゲットとしてサポートしていません |
| プライマリ/スタンバイストア | プライマリストア：スキャナー移行 + フル移行 + 増分同期をサポートします </br> スタンバイストア：フル検証 + リバース増分をサポートします |

同時に、OMSは複数のOceanBaseデータベースのOracleテナントのテーブルデータをOracleデータベースの同一テーブルに集約する機能をサポートしており、この場合構造移行は不要で、フル移行と増分同期のみが必要です。この集約同期機能の使用制限は以下のとおりです：

* フル移行および増分同期について、ソース側に存在する列は、ターゲット側にも存在しなければなりません。この要件を満たさない場合、OMSはエラーを報告します。

* プライマリキー列は、ソース側のテーブルに存在しなければなりません。

* ターゲットテーブルの列には、ソース側に存在しない列を含めることができます。
