# Oracle互換アプリケーションのエラー処理規範

この記事では、主にOracle互換アプリケーションのエラー処理規範について説明します。

OceanBaseデータベースはV2.0バージョンからOracleデータベースとの完全な互換性を備え、Oracle互換テナントモードを提供しています。エラーコードに関しては、エラーコード、SQLSTATE、エラーメッセージの3つの情報がOracleデータベースと一致するように努めています。そのため、当社のプロダクト設計原則として、アプリケーションのエラー処理規範はOracleデータベースの処理規範を参考にすることができます。しかし、分散型データベースであるOceanBaseデータベースは、集中型のOracleデータベースと本質的に異なり、分散環境特有の一部のエラーはOracleデータベースのエラーコードでは表現できません。そのため、このような内部エラーコードはエラーコード`ORA-00600`にマッピングされ、これはOceanBaseデータベース固有のエラーコードであることを示しています。

OceanBaseデータベースのOracleテナントモードでは、エラーメッセージの形式はOracleデータベースと互換性があり、「プレフィックス+数字コード」の形式で返されます。エラーがSQLに起因する場合は、`ORA`で始まるエラーメッセージが返されます。エラーがストアドプロシージャに起因する場合は、`PLS`で始まるエラーメッセージが返されます。OceanBaseデータベースサーバー側のOracleテナントモードにおける完全なエラーコード一覧については、[エラー情報の概要](../../../../700.reference/900.error-code/700.error-code-of-oracle-mode/100.use-error-information-of-oracle-mode.md)を参照してください。

`ORA-00600`エラーコードについては、アプリケーションプログラムはエラーメッセージから具体的な内部エラーコードを抽出する必要があります。例えば、以下のエラーメッセージでは、内部エラーコードは`6210`です。

```shell
ORA-00600: internal error code, arguments: -6210, Transaction timeout occurred, please rollback the transaction, set the variable ob_trx_timeout to a larger value and then restart the transaction
```

## エラーコード情報の取得

異なる言語のドライバーは、エラー情報を取得するために異なるAPIを提供しています。各ドライバーの詳細については、[接続方法の概要](../../100.connect-to-oceanbase-database-of-oracle-mode/100.connection-methods-overview-of-oracle-mode.md) の **ドライバー** ページを参照してください。

### Javaドライバーライブラリ

JDBCを使用するJavaアプリケーションがSQLステートメントの実行に失敗した場合、SQLException例外をキャッチできます。この例外には、エラーコード、SQLSTATE、エラーメッセージの3種類の情報が含まれています。SQLException例外の詳細については、[JDBC APIドキュメント](https://docs.oracle.com/javase/1.5.0/docs/api/java/sql/SQLException.html) を参照してください。

SQLException例外をキャッチする方法は以下のとおりです：

* getErrorCode() を呼び出してエラーコードを取得します。
* getSQLState() を呼び出してSQLSTATEを取得します。
* getMessage() を呼び出してエラーメッセージを取得します。

### OBCIドライバーライブラリ

OBCIは、Oracle OCI互換のC言語ドライバーライブラリを提供しています。関数呼び出しが `OCI_ERROR` を返す場合、アプリケーションは関数 [OCIErrorGet()](https://docs.oracle.com/cd/B12037_01/appdev.101/b10779/oci16ms9.htm) の出力パラメータからエラー情報を取得します：

* 出力パラメータerrcodepからエラーコードを取得します。
* 出力パラメータsqlstateからSQLSTATEを取得します。
* 出力パラメータbufpからエラーメッセージを取得します。

## エラー処理の規範

OceanBaseデータベースのOracleテナントモードにおけるほとんどのエラーコードについて、アプリケーションは特別な処理を行う必要がなく、そのまま外部にエラーを報告できます。フォールトトレランスとアプリケーションの堅牢性を向上させるため、特定のエラーコードについては、異なるシナリオやエラーの性質に応じて、以下の4つの異なるポリシーを採用することができます：

1. ポリシー1：ステートメントのタイプに基づいて処理します。

   * `SELECT` ステートメントの実行時にタイムアウトエラーが発生した場合、副作用がないため、リトライが可能です。

   * リモートまたは分散実行による `UPDATE` などの変更ステートメントの実行時にタイムアウトエラーが発生した場合、ステートメントが実際に正常に実行されたかどうかは不確定であり、トランザクションをロールバックする必要があります（変更ステートメントのセマンティクスが冪等である場合、そのステートメントのリトライを試みることができます）。

   * `COMMIT` または `ROLLBACK` ステートメントの実行時にタイムアウトエラーが発生した場合、トランザクションの状態が不明であるため、直接外部にエラーを報告する必要があります。

2. ポリシー2：任意のステートメントの実行時にエラーが発生した場合、現在のトランザクションをロールバックしてから、トランザクションをリトライします。

3. ポリシー3：任意のステートメントの実行時にエラーが発生した場合、現在のステートメントをリトライします。

4. ポリシー4：任意のステートメントの実行時にエラーが発生した場合、現在の接続を閉じてから、再接続します。

特に、開発習慣上、OCIインターフェースを使用して開発されたサービス系アプリケーションの多くは長時間接続を使用します。データベースサーバー側でランタイム例外が発生し、処理が行われない場合、サービスが自動的に復旧できなくなる可能性があります。このようなアプリケーションでは、以下の **OceanBaseデータベース固有のエラーコード** および **Oracle互換エラーコード** に記載されている推奨事項に従ってエラー処理を行う必要があります。

### OceanBaseデータベース固有のエラーコード

以下のエラーコードは、一般的なOceanBaseデータベースサーバー固有の実行時例外のエラーコードです。下表に示されている異なる「内部エラーコード」に基づき、アプリケーションは「処理ポリシー」の推奨事項に従って対処できます。

| エラーコード | 内部エラーコード | 意味 | ステートメント実行結果 | トランザクションステータス | 対処策 |
|-----------|------------|--------------------|---------------|---------|--------------|
| ORA-00600 | 4012       | 実行タイムアウト            | 不明          |  未知    | 策略一       |
| ORA-00600 | 4038       | 現在のレプリカがプライマリレプリカではないため、サービスを提供できません。一般的には、レプリカのプライマリ切り替え時に発生する可能性があります。| 失敗 | 変更なし | 策略三 |
| ORA-00600 | 4225       | パーティションが存在しません。一般的には、レプリカ移行時に発生する可能性があります。| 失敗  | 変更なし  |  策略三 |
| ORA-00600 | 6210       | トランザクションの実行時間が制限時間を超過 | 失敗          | 変更なし     | 策略二        |
| ORA-00600 | 6231       | レプリカデータが読み取り不可能です。一般的には、レプリカ移行時に発生する可能性があります。| 失敗 | 変更なし | 策略三 |
| ORA-00600 | 8001~8004  | 接続が回復できません         | 失敗          | 未知     | 策略四       |

### Oracle互換エラーコード

一般的なOracleデータベースと互換性のあるエラーコードについては、Oracleデータベースと同じ処理方法を遵守してください。特に、以下のエラーコードはOceanBaseデータベースのOracleテナントモードでよく見られる例外であり、アプリケーションは下表の「処理ポリシー」の推奨事項に従って処理することができます。

| エラーコード | 意味 | ステートメント実行結果 | トランザクションステータス | 対処方針 |
|-----------|-----------------------------------|-------------|----------|---------|
| ORA-01555 | 読み取ったスナップショットバージョンが古すぎる | 失敗 | 変更なし | ポリシー3 |
| ORA-24761 | トランザクションがシステム内部でロールバックされた | 失敗 | ロールバックされた | ポリシー2 |
| ORA-08177 | 現在のトランザクションはシリアライズできません。一般的にRR（Repeatable Read）およびSerializable分離レベルでトランザクションの同時実行競合が発生した場合に起こります。</br>トランザクション分離レベルの詳細については、[トランザクション分離レベルの概要](../../../../700.reference/100.oceanbase-database-concepts/800.transaction-management/200.transaction-concurrency-and-consistency/400.transaction-isolation-level/100.transaction-isolation-level-overview.md)を参照してください。 | 失敗 | 変更なし | ポリシー2 |

OBCIを使用するアプリケーションの場合、ドライバー側からはOracleデータベースと互換性のあるエラーコードが返され、これもOracleデータベースと同じ処理方法に従います。特に、アプリケーションは以下のエラーコードに注意する必要があります。

| エラーコード | 意味 | 対処策 |
|-----------|-----------------------------|-------------------------------------------|
| ORA-03113 | サーバーとの接続が切断されました | 接続を再確立します |
| ORA-01403 | 期待される行数が実際に返された結果の行数よりも多い | エラーを報告するか、アプリケーションのロジックが正しいかどうかを確認します |
| ORA-01405 | 列値が空です | NULL値の問題を処理します |
| ORA-01406 | 返された結果がバッファ長を超えています | データ受信用のバッファ長を拡大します |
