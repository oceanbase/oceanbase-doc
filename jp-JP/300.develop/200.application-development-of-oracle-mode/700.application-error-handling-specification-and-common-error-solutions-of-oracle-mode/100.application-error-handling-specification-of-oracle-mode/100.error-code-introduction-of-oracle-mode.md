# エラーコードの紹介

この記事では、OceanBaseデータベースにおけるエラーコードの構成と意味について説明します。

Javaドライバーを使用する場合でもCドライバーを使用する場合でも、OceanBaseデータベースに接続して任意のSQLステートメントの実行が失敗した場合、実行失敗を示すエラーが返されます。エラーには通常、以下の3つの情報が含まれます：

* 32ビット整数で表されるエラーコード

* 5文字からなる文字列、すなわちSQLSTATE

* 人間が読み取り可能なエラーメッセージを含む文字列

たとえば、クライアントOBClientを使用してOceanBaseデータベースに接続し、SQLステートメントの実行に失敗した場合、システムはターミナルに次のようなエラーメッセージを出力します：

```shell
ERROR 1054 (42S22): Unknown column ‘haha’ in ‘field list’
```

ここで、`1054` がエラーコード、括弧内の `42S22` がSQLSTATE、コロンの後ろが具体的なエラーメッセージです。

互換性設計原則に基づき、同一のエラーに対して、MySQLモード（`sys` テナントはMySQLモードに属する）とOracleモードでは異なるエラーコードが返される可能性があります。例えば、OceanBase内部エラーコード `-5217` は、SQLステートメントで存在しない列名が参照されていることを示します。このエラーコードは、2種類のテナントモードでの動作が以下の表のように異なります。

|   テナントモード       | エラーコード               |  SQLSTATE       |  エラーメッセージ                   |
|-----------------|-------------------|------------------|----------------------------|
|  MySQL          | 1054               |   42S22          |  Unknown column            |
|  Oracle         | 904、すなわちORA-00904  |   42S22          |  invalid identifier        |

エラーコード解析ツールob_error 10を使用すると、エラーコードの意味や内部エラーコードと外部エラーコードのマッピング関係を照会できます。エラーコード解析ツールob_errorの詳細については、[ob_error](../../../../700.reference/1500.Components-and-Tools/100.manage/300.ob-error.md)を参照してください。

## SQLSTATE

SQLSTATEは、SQL標準で規定されたエラーコードであり、5桁の数字または大文字のラテン文字で構成される文字列値です。この5桁の数字の最初の2桁は大きなエラーカテゴリを示し、残りの3桁はより具体的なエラー原因を示します。たとえば、`00` は成功を示し、`01` は警告を示し、`02` は見つからないことを示し、`22` はデータ関連のエラーを示し、`42` は構文エラーを示します。したがって、同一のエラーに対して、OceanBaseデータベースはMySQLモードとOracleモードで同じSQLSTATEを返します。

理論的には、SQL標準に従うすべてのデータベースは一貫したSQLSTATEを返すため、アプリケーションのエラー処理ロジックは異なるデータベースと互換性があります。

## エラーコード

SQL標準で規定されたSQLSTATEというエラーコードはすでに存在しますが、標準の発展は常にデータベースベンダーの実践に遅れがちであり、各ベンダーはより詳細なエラー原因を識別するために独自のエラーコード（ベンダーコード）を定義する必要があります。さらに、各ベンダーが独自に定義したエラーコードは、異なるデータベース間で互換性がありません。

OceanBaseデータベースでは、非互換のカスタムエラーコードに対応するSQLSTATEは一般的に `HY000` です。

## エラーメッセージ

エラーメッセージは人間に優しいヒント情報を提供しますが、人間にしか優しくありません。エラーメッセージはバージョンの進化に伴って変更される可能性があり、また、同一のエラーが異なる言語環境の設定によって現地語で異なるエラーメッセージとして表示される場合もあるため、一般的にはアプリケーションにおいてはエラーコードまたはSQLSTATEに基づいてエラー処理を行うべきであり、エラーメッセージに基づくべきではありません。
