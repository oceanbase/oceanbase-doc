# トランザクションタイムアウト、エラーコードORA-00600

本記事では、OceanBaseデータベースのOracleモードにおいて、トランザクションがコミットされないままタイムアウトした場合に発生する`ORA-00600`エラーの処理方法について説明します。

## 現象

トランザクションが開始された後、長時間にわたってコミットされない場合、テーブルデータのクエリを実行する際にエラーが発生します。

```sql
obclient [SYS]> CREATE TABLE ordr(
    id number NOT NULL PRIMARY KEY
    , name varchar(10) NOT NULL
    , value number
    ,gmt_create timestamp NOT NULL DEFAULT current_timestamp);   //データ準備
Query OK, 0 rows affected

obclient [SYS]> INSERT INTO ordr(id, name, value, gmt_create) VALUES (1,'CN',10001, current_timestamp);
Query OK, 1 row affected

obclient [SYS]> INSERT INTO ordr(id, name, value) VALUES (2,'US', 10002);
Query OK, 1 rows affected

obclient [SYS]> INSERT INTO ordr(id, name, value) VALUES (3,'EN', 10003);
Query OK, 1 rows affected

obclient [SYS]> SELECT sysdate, t.* FROM ordr t;
+-----------+----+------+-------+------------------------------+
| SYSDATE   | ID | NAME | VALUE | GMT_CREATE                   |
+-----------+----+------+-------+------------------------------+
| 05-SEP-22 |  1 | CN   | 10001 | 05-SEP-22 04.34.37.145469 PM |
| 05-SEP-22 |  2 | US   | 10002 | 05-SEP-22 04.34.46.776463 PM |
| 05-SEP-22 |  3 | EN   | 10003 | 05-SEP-22 04.34.46.776463 PM |
+-----------+----+------+-------+------------------------------+
3 rows in set

obclient [SYS]> COMMIT;

obclient [SYS]> INSERT INTO ordr(id, name, value) VALUES (4,'JP', 10004);
Query OK, 1 rows affected

/* 長時間操作なし */

obclient [SYS]> SELECT sysdate, t.* FROM ordr t;
ORA-00600: internal error code, arguments: -6210, Transaction timeout occurred, please rollback the transaction, set the variable ob_trx_timeout to a larger value and then restart the transaction
```

このエラーメッセージに対応するエラーコードは以下のとおりです：

* エラーコード：ORA-00600

* OceanBaseエラーコード：6210

エラーコードの詳細については、[エラーコードの概要](../../../../700.reference/900.error-code/700.error-code-of-oracle-mode/100.use-error-information-of-oracle-mode.md)を参照してください。

## 考えられる原因

トランザクション未コミットタイムアウトとは、トランザクションが指定されたしきい値を超えてもまだコミットされていない状態を指します。トランザクションが指定された時間を超えてもコミットされない場合、システムはエラーを報告します。トランザクション未コミットタイムアウトは、テナント変数`ob_trx_timeout`によって制御され、デフォルト値は86400000000マイクロ秒、すなわち24時間です。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>OceanBaseデータベースでは、トランザクションが長時間コミットされずロックを保持し、他のセッションに影響を与えることを防ぐために、2種類のタイムアウトロジックが設計されています：トランザクションアイドルタイムアウトとトランザクション未コミットタイムアウトです。通常、これらのうちどちらか一方のタイムアウトメカニズムが先にトリガーされます。</p>
  </main>

## 解決策

以下の手順に従って、テナント変数を確認し変更した後、`ROLLBACK` ステートメントでトランザクションをロールバックしてコミットし、その後の操作を続けてください。

1. テナント変数 `ob_trx_timeout` の値を確認し、トランザクションのタイムアウト時間が設定値を超えていないかどうかを確認します。

   トランザクションのコミットされていないタイムアウト時間のしきい値は、テナント変数 `ob_trx_timeout` によって制御され、単位はマイクロ秒です。デフォルト値の24時間（86400000000マイクロ秒）を使用することを推奨します。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>以下の変数設定方法は現在のセッションにのみ有効です。設定を永続的に有効にするには、<code>SET GLOBAL</code> 構文を使用して同じ変数を設定した後、セッションを再起動して有効化してください。</p>
  </main>

   ```sql
   obclient [SYS]> SHOW VARIABLES LIKE 'ob_trx_timeout';
   +----------------+-----------+
   | Variable_name  | Value     |
   +----------------+-----------+
   | ob_trx_timeout | 100000000 |
   +----------------+-----------+
   1 row in set

   obclient [SYS]> SET SESSION ob_trx_timeout=86400000000;
   Query OK, 0 rows affected
   ```

2. `ROLLBACK` を使用してトランザクションをロールバックします。

   ```sql
   obclient [SYS]> ROLLBACK;
   Query OK, 0 rows affected
   ```

3. `COMMIT` を実行してトランザクションをコミットします。

   ```sql
   obclient [SYS]> COMMIT;
   Query OK, 0 rows affected
   ```

4. 再度 `ordr` テーブルのデータを照会すると、操作は成功します。

   ```sql
   obclient [SYS]> SELECT sysdate, t.* FROM ordr t;
   +-----------+----+------+-------+------------------------------+
   | SYSDATE   | ID | NAME | VALUE | GMT_CREATE                   |
   +-----------+----+------+-------+------------------------------+
   | 05-SEP-22 |  1 | CN   | 10001 | 05-SEP-22 04.34.37.145469 PM |
   | 05-SEP-22 |  2 | US   | 10002 | 05-SEP-22 04.34.46.776463 PM |
   | 05-SEP-22 |  3 | EN   | 10003 | 05-SEP-22 04.34.46.776463 PM |
   +-----------+----+------+-------+------------------------------+
   3 rows in set
   ```
