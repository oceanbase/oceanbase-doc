# 単一テーブルクエリ

単一テーブルクエリとは、1つのテーブルのみに関連するクエリを指します。

## 単一テーブルクエリ構文

単一テーブルクエリの構文は以下のとおりです：

```sql
SELECT [ALL | DISTINCT] select_list FROM table_name
              [ WHERE query_condition ]
              [ GROUP BY group_by_expression ]
              [ HAVING group_condition ]
              [ ORDER BY column_list ][ASC | DESC]
              [ Row_Limiting_Clause ]

column_list：
 column_name[,column_name...]
```

`WHERE`、`GROUP BY`、`HAVING`、`ORDER BY` といったキーワードを同時に使用する場合、その順序には明確な制限があります。キーワードの実行順序は以下のとおりです：

1. `FROM` を実行してテーブルを検索します。

2. `WHERE` を実行して制約条件を指定します。

3. `GROUP BY` を実行して取得した各レコードをグループ化します。`GROUP BY` がない場合は、全体が1つのグループとなります。

4. `HAVING` を実行してグループ化された結果をフィルタリングします。

5. `SELECT` を実行します。

6. `DISTINCT` を実行して重複を削除します。

7. `ORDER BY` を実行して結果を条件に基づいて昇順または降順にソートします。

8. `ROWNUM` を実行して結果の表示件数を制限します。

`WHERE` と `HAVING` の違いは、`WHERE` はグループ化前にデータをフィルタリングし、`HAVING` はグループ化後の結果でフィルタリングを行い、最終的にSQL全体のクエリ結果を返す点です。

クエリステートメントの詳細な使い方については、[SELECT](../../../700.reference/500.sql-reference/100.sql-syntax/300.common-tenant-of-oracle-mode/900.sql-statement-of-oracle-mode/200.dml-of-oracle-mode/500.select-of-oracle-mode/100.simple-select-of-oracle-mode.md)を参照してください。

### FROM関数クエリ

OceanBaseデータベースのOracleモードでは、`SELECT * FROM FUNCTION(*);` の構文を使用して、テーブル型を返す関数を呼び出し、その関数の実行結果をテーブルデータとしてクエリできます。

`SELECT * FROM FUNCTION(*);` を使用する際には、以下の点に注意する必要があります：

* 関数が返すデータ型は、テーブル型でなければなりません。

* テーブル関数が返す列数と列型は、呼び出し元が必要とする列数と列型と一対一で対応していなければなりません。

* テーブル関数が返す行数は、呼び出し元が必要とする行数以上でなければなりません。

* 関数のパラメータの数と型は、関数定義と一致していなければなりません。

カスタム型の詳細については、[CREATE TYPE](../../../700.reference/500.sql-reference/300.pl-reference/300.pl-oracle/1100.ddl-operations-on-stored-pl-units-oracle/1200.create-type-oracle.md)および[ユーザー定義サブタイプ](../../../700.reference/500.sql-reference/300.pl-reference/300.pl-oracle/200.data-type-oracle/500.user-defined-data-types-oracle.md)を参照してください。

関数の作成に関する詳細は、[CREATE FUNCTION](../../../700.reference/500.sql-reference/300.pl-reference/300.pl-oracle/1100.ddl-operations-on-stored-pl-units-oracle/700.create-function-oracle.md)および[関数の作成](../../../700.reference/500.sql-reference/300.pl-reference/300.pl-oracle/700.stored-procedure-and-functions-oracle/300.create-a-function-oracle.md)を参照してください。

例：

1. テーブル型 `emp_type` を定義します。

    ```shell
    obclient [SYS]> DELIMITER //
    obclient [SYS]> CREATE OR REPLACE TYPE emp_type AS OBJECT (id NUMBER); //
    Query OK, 0 rows affected
    ```

2. テーブル型を含むコレクション型 `emp_type_list` を定義します。

    ```shell
    obclient [SYS]> CREATE OR REPLACE TYPE emp_type_list IS TABLE OF emp_type; //
    Query OK, 0 rows affected
    ```

3. テーブル型を返す関数 `get_emp_info` を作成します。

    ```shell
    obclient [SYS]> CREATE OR REPLACE FUNCTION get_emp_info
            RETURN emp_type_list PIPELINED
        IS CURSOR emp_list_cursor IS SELECT EMPNO FROM emp;
            v_emp_id_type emp_type;
          v_emp_id varchar2(5);
          BEGIN
          OPEN emp_list_cursor;
          LOOP
          FETCH emp_list_cursor INTO v_emp_id;
          EXIT WHEN emp_list_cursor%notfound;
          v_emp_id_type := emp_type(v_emp_id);
          PIPE ROW(v_emp_id_type);
          END LOOP;
          CLOSE emp_list_cursor;
          RETURN;
          END;//
    Query OK, 0 rows affected

    obclient [SYS]> DELIMITER ;
    ```

4. 関数の実行結果をクエリします。

    ```shell
    obclient [SYS]> SELECT * FROM get_emp_info();
    ```

    実行結果は次のとおりです：

    ```shell
    +------+
    | ID   |
    +------+
    | 1369 |
    | 1499 |
    | 1566 |
    | 1698 |
    | 1788 |
    | 1902 |
    +------+
    6 rows in set
    ```

## 条件クエリ

特定の条件を満たすデータを照会する場合、`SELECT` クエリステートメントに `WHERE` 句を追加することで実現できます。

### 条件クエリ構文

条件クエリを実行する際、まず `FROM` 句の後に `WHERE` 句を使用して指定された条件に一致するレコードを照会し、その後 `SELECT` ステートメントで指定された列を選択します。

条件クエリのSQLステートメントの形式は以下のとおりです：

```sql
SELECT select_list FROM table_list
WHERE query_condition;
```

キーワード `WHERE` の後には、1つまたは複数の条件を記述できます。条件とは、前のデータをフィルタリングするものであり、`WHERE` の条件を満たすデータのみが返されます。

### よく使われるクエリ条件

`WHERE` 句でよく使われるクエリ条件は、以下の表に示されています。

|   クエリ条件タイプ   |                     述語                      |
|------------|---------------------------------------------|
| 比較クエリ       | =、\>、\<、\>=、\<=、!=、\<\>                     |
| 論理クエリ（複数条件） | AND、OR、NOT  |
| あいまいクエリ（文字列マッチング） | LIKE、NOT LIKE               |
| 区間クエリ（範囲指定） | BETWEEN AND、NOT BETWEEN AND |
| 指定集合クエリ     | IN、NOT IN                   |
| NULL値クエリ   | IS NULL、IS NOT NULL         |

### 比較条件クエリ

比較条件クエリ演算子には、`=`、`>`、`<`、`>=`、`<=`、`!=`、`<>` が含まれます。

#### 等しい（=）

指定された列の値が、ターゲット値と等しいデータを照会します。値が文字列型の場合は、シングルクォートまたはダブルクォートで囲む必要があります。一般的な書式は次のとおりです：

```sql
SELECT column_name [,column_name...] FROM table_name WHERE column_name = const_value;
```

例：

```shell
obclient [SYS]> SELECT empname, deptno FROM emp WHERE deptno = 30;
+---------+--------+
| EMPNAME | DEPTNO |
+---------+--------+
| BLAKE   |     30 |
+---------+--------+
1 row in set

obclient [SYS]> SELECT empname, deptno FROM emp WHERE deptno = '30';
+---------+--------+
| EMPNAME | DEPTNO |
+---------+--------+
| BLAKE   |     30 |
+---------+--------+
1 row in set

obclient [SYS]> SELECT empname, deptno FROM emp WHERE empname = 'ALLEN';
+---------+--------+
| EMPNAME | DEPTNO |
+---------+--------+
| ALLEN   |     35 |
+---------+--------+
1 row in set
```

#### 等しくない（\<\> および !=）

不等号には、`<>` と `!=` の2種類の書き方が含まれます。一般的な書式は次のとおりです：

```sql
SELECT column_name [,column_name...] FROM table_name WHERE column_name <> const_value;
SELECT column_name [,column_name...] FROM table_name WHERE column_name != const_value;
```

例：

```shell
obclient> SELECT empname, deptno FROM emp WHERE deptno <> 30;

| FORD    |     45 |
+---------+--------+

obclient> SELECT empname, deptno FROM emp WHERE deptno != 30;

| EMPNAME | DEPTNO |
+---------+--------+

| ALLEN   |     35 |

| FORD    |     45 |
+---------+--------+
```

#### 大于（\>）と小于（\<）

大なり（`>`）および小なり（`<`）は、数値を大きさの順に比較します。比較対象が文字の場合は、ASCIIコードに対応する値で比較し、文字の位置に従って順次比較します。一般的な書式は以下のとおりです：

```sql
SELECT column_name [,column_name...] FROM table_name WHERE column_name < const_value;
SELECT column_name [,column_name...] FROM table_name WHERE column_name > const_value;
```

### 論理条件クエリ

論理クエリ演算子の「かつ」（`AND`）と「または」（`OR`）は、複数の条件を含むクエリをサポートします。

#### かつ（AND）

`AND` の両方の条件を満たすデータを返します。一般的な書式は次のとおりです：

```sql
SELECT column_name [,column_name...] FROM table_name WHERE
query_condition AND query_condition;
```

例：

```shell
obclient> SELECT empname, deptno, sal FROM emp WHERE deptno<=30 AND sal > 1000;
+---------+--------+------+
| EMPNAME | DEPTNO | SAL  |
+---------+--------+------+
| BLAKE   |     30 | 2850 |
| SCOTT   |     25 | 3000 |
+---------+--------+------+
2 rows in set
```

#### または（OR）

いずれか一方の条件を満たすデータが返されます。一般的な書式は次のとおりです：

```sql
SELECT column_name [,column_name...] FROM table_name WHERE
query_condition OR query_condition;
```

例：

```shell
obclient> SELECT empname, deptno, sal FROM emp WHERE deptno <= 30 OR sal > 1000;
+---------+--------+------+
| EMPNAME | DEPTNO | SAL  |
+---------+--------+------+
| SMITH   |     20 |  800 |
| ALLEN   |     35 | 1600 |
| JONES   |     40 | 2975 |
| BLAKE   |     30 | 2850 |
| SCOTT   |     25 | 3000 |
| FORD    |     45 | 3000 |
+---------+--------+------+
6 rows in set
```

### あいまいクエリ（LIKE）

述語 `LIKE` は文字列のマッチングに使用できます。一般的な形式は以下のとおりです：

```sql
[NOT] LIKE pattern
```

構文の意味は、指定されたプロパティ列の値が `pattern` と一致するタプルを検索することです。`pattern` は完全な文字列であることも、ワイルドカード `%` と `_` を含むこともできます。その中で：

* アンダースコア `_` は任意の1文字にマッチします。

* パーセント記号 `%` は、値内の0文字以上の任意の文字列にマッチします。パターン `%` は `NULL` とマッチしません。

<main id="notice" type='explain'>
    <h4>説明</h4>
    <p>OceanBaseデータベースのOracleモードでは、以下の条件を満たす場合、<code>like</code> は <code>=</code> 比較に変更されます：</p>
    <p>
     <ul>
      <li><code>pattern</code> に <code>%</code> または <code>_</code> のワイルドカードが含まれておらず、<code>escape</code> もありません。</li>
      <li>フィールドタイプは <code>LOB</code> ではありません。Oracleモードでは <code>LOB</code> タイプは <code>=</code> 比較をサポートしていないため、変換できません。</li>
      <li><code>pattern</code> は固定長の <code>char</code> または <code>nchar</code> タイプではありません。</li>
     </ul></p>
</main>

以下の例は、従業員名の最初の4文字が `ALLE` で、最後の1文字が任意の文字であるデータを照会するものです。

```shell
obclient> SELECT empname, deptno FROM emp WHERE empname LIKE 'ALLE_';
+---------+--------+
| EMPNAME | DEPTNO |
+---------+--------+
| ALLEN   |     35 |
+---------+--------+
1 row in set
```

以下の例は、従業員名の先頭文字が `A` のデータを照会するものです。

```shell
obclient> SELECT empname, deptno FROM emp WHERE empname LIKE 'A%';
+---------+--------+
| EMPNAME | DEPTNO |
+---------+--------+
| ALLEN   |     35 |
+---------+--------+
1 row in set
```

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>データベースの文字セットがASCIIの場合、1つの漢字には2つの <code>_</code> が必要です。文字セットがGBKの場合は、1つの <code>_</code> だけが必要です。</p>
  </main>

### 区間クエリ（BETWEEN AND）

演算子`BETWEEN ... AND`は、2つの値の間にあるデータを選択します。これらの値は数値、テキスト、または日付である可能性があります。一般的な形式は次のとおりです：

```sql
SELECT column_name [,column_name...] FROM table_name WHERE
[NOT] BETWEEN min_const_value AND max_const_value;
```

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>区間クエリの2つの境界値の順序を入れ替えないでください。左側の値より大きく、かつ右側の値以下でなければなりません。</p>
  </main>

例：

### 指定集合クエリ（IN）

演算子 `IN` は、`WHERE` 句で複数の値を指定し、それらを一つの集合として扱うことを可能にします。`IN` は、指定された列のデータがその集合内のいずれかの値と一致すれば、そのデータが返されることを意味します。`NOT IN` は、集合内のいずれの値ともマッチしないデータが返されることを意味します。一般的な書式は以下のとおりです：

```sql
SELECT column_name [,column_name...] FROM table_name WHERE
column_name [NOT] IN (const_value,const_value,const_value...);
```

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <ul>
    <li><code>[NOT] IN</code> の集合内の値の型は、すべて同一または互換性がある必要があります。</li>
    <li><code>[NOT] IN</code> の集合内の値ではワイルドカードはサポートされていません。</li>
    </ul>
  </main>

例：

```shell
obclient> SELECT * FROM emp WHERE deptno IN (30,40,50,60);
+-------+---------+---------+------+-----------+------+------+--------+------+
| EMPNO | EMPNAME | JOB     | MGR  | HIREDATE  | SAL  | COMM | DEPTNO | AGE  |
+-------+---------+---------+------+-----------+------+------+--------+------+
|  1566 | JONES   | MANAGER | 1839 | 02-APR-81 | 2975 | NULL |     40 |   22 |
|  1698 | BLAKE   | MANAGER | 1839 | 01-MAY-81 | 2850 | NULL |     30 |   33 |
+-------+---------+---------+------+-----------+------+------+--------+------+
2 rows in set
```

### NULL値専用クエリ（IS NULL/IS NOT NULL）

比較演算子、`LIKE`、`BETWEEN AND`、`IN`、`NOT IN` は `NULL` 値に対するクエリ結果が正確ではないため、NULL値専用のクエリステートメントである `IS NULL` と `IS NOT NULL` を使用することを推奨します。

#### IS NULL

`IS NULL` は、指定された列の値が `NULL` のデータを照会するために使用されます。一般的な書式は次のとおりです：

```sql
SELECT column_name [,column_name...] FROM table_name WHERE
column_name IS NULL;
```

例：

```shell

| EMPNO | EMPNAME | JOB     | MGR  | HIREDATE  | SAL  | COMM | DEPTNO | AGE  |

|  1566 | JONES   | MANAGER | 1839 | 02-APR-81 | 2975 | NULL |     40 |   22 |
|  1698 | BLAKE   | MANAGER | 1839 | 01-MAY-81 | 2850 | NULL |     30 |   33 |
|  1788 | SCOTT   | ANALYST | 1566 | 15-JUL-87 | 3000 | NULL |     25 |   33 |
|  1902 | FORD    | ANALYST | 1566 | 05-DEC-81 | 3000 | NULL |     45 |   22 |
+-------+---------+---------+------+-----------+------+------+--------+------+

```

#### IS NOT NULL

`IS NOT NULL` は、指定された列の値が `NULL` 以外のデータを照会するために使用されます。一般的な書式は次のとおりです：

```sql
SELECT column_name [,column_name...] FROM table_name WHERE
column_name IS NOT NULL;
```

## グループ化クエリ

ORDER BY句は、クエリ結果を1つまたは複数のプロパティ列に基づいて昇順（ASC）または降順（DESC）で並べ替えるために使用されます。デフォルト値は昇順です。

### グループ化クエリ構文

`GROUP BY` は単一フィールドによるグループ化と複数フィールドによるグループ化をサポートしています。`WHERE` 句を使用すると、グループ化の前にデータをフィルタリングできます。`HAVING` 句を使用すると、グループ化後にデータをフィルタリングできます。`ORDER BY` 句を使用すると、グループ化後にデータをソートできます。グループ化クエリのSQLステートメントの形式は以下のとおりです：

```sql
SELECT select_list FROM table_list
  [WHERE query_condition]
  GROUP BY group_by_expression
  [HAVING group_condition];

select_list：
  column_name, group_function,...
```

構文のパラメータの説明は以下のとおりです：

* `group_function` は集計関数を表します。

* `group_by_expression` はグループ化式を表し、複数の式はカンマで区切ります。

* `group_condition` はグループ化後のデータフィルタリングを表します。

グループ化でよく使用される集計関数は以下の表のとおりです。

| 集計関数   |      機能      |
|---------|--------------|
| MAX()   | 指定された列の最大値を照会します。   |
| MIN()   | 指定された列の最小値を照会します。   |
| COUNT() | クエリ結果の行数を統計的に集計します。   |
| SUM()   | 指定された列の合計を返します。    |
| AVG()   | 指定された列データの平均値を返します。 |

### グループ化クエリの例

サンプルテーブル `fruit_order` を作成し、適切なデータを挿入します。

```sql

  order_id Number(10,2),
  user_id Number(10,2),
  user_name VARCHAR2(16),
  fruit_price Number(10,2),
  order_year Date,

);

  (1,1011,'張三',13.11,Date'2019-01-01'),
```

## クエリでRow_Limiting_Clauseを使用する

Row_Limiting_Clauseは、`SELECT`クエリが返す行数を制限するために使用され、ページネーション操作でよく利用されます。

### N行目以降のデータを照会する

#### 例1

4行目以降のデータを照会します。

```sql
obclient> SELECT * FROM tb OFFSET 4 ROW;
+------+------+------+
| ID   | NAME | NUM  |
+------+------+------+
|    5 | b    |  700 |
|    6 | a    |   80 |
+------+------+------+
2 rows in set
```

#### 例2

5行目以降のデータを照会します。

```sql
obclient> SELECT * FROM tb OFFSET 5 ROWS;
+------+------+------+
| ID   | NAME | NUM  |
+------+------+------+
|    6 | a    |   80 |
+------+------+------+
1 row in set
```

### IDが最も低い3件のデータを照会する

```sql
obclient> SELECT * FROM tb ORDER BY id FETCH FIRST 3 ROWS ONLY;

| ID   | NAME | NUM  |
+------+------+------+

|    2 | b    |  200 |

```
