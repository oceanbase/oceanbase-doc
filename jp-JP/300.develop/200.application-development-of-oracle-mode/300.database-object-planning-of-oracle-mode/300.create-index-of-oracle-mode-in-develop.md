# インデックスの作成

テーブルの作成が完了したら、テーブルの1つまたは複数の列にインデックスを作成して、ほとんどのクエリSQLの実行速度を向上させることができます。

## インデックスの概要

インデックスは、セカンダリインデックスとも呼ばれ、オプションのテーブル構造です。OceanBaseデータベースは集約インデックステーブルモデルを採用しており、ユーザーが指定した主キーに対しては、システムが自動的に主キーインデックスを生成します。一方、ユーザーが作成するその他のインデックスはセカンダリインデックスとなります。業務ニーズに応じて、特定のフィールドにインデックスを作成することで、これらのフィールドに対するクエリの高速化を図ることができます。

インデックスは、一意インデックスと非一意インデックスに分類されます：

* 一意インデックスは、テーブル内のインデックス列に完全に同一の値を持つ行が存在しないことを保証します。OceanBaseデータベースでは、NULL値もインデックスに格納されます。

* 非一意インデックスには、完全に同一の値が存在する可能性があります。

一意インデックスと非一意インデックスの詳細については、[一意インデックスと非一意インデックス](../../../700.reference/100.oceanbase-database-concepts/400.database-objects/100.database-objects-of-oracle-mode/300.index-of-oracle-mode/300.unique-and-non-unique-indexes-of-oracle-mode.md)を参照してください。

パーティションテーブルにおいては、インデックスはローカルインデックスとグローバルインデックスに分類されます：

* ローカルインデックスは、単一のパーティション上のデータに対して作成されるインデックスであり、そのためインデックスのキー値とテーブル内のデータとは一対一の対応関係にあります。すなわち、ローカルインデックス上のあるパーティションは必ずテーブルの特定のパーティションに対応し、両者は同じパーティションルールを共有します。そのため、ローカル一意インデックスはパーティション内部での一意性を保証することはできますが、テーブルデータ全体のグローバルな一意性を保証することはできません。

* グローバルインデックスのパーティションルールはテーブルのパーティションとは独立しているため、インデックステーブル内のあるパーティションのインデックス値が、主テーブルの複数のパーティション内のデータに対応する場合があります。

ローカルインデックスとグローバルインデックスの詳細については、[ローカルインデックスとグローバルインデックス](../../../700.reference/100.oceanbase-database-concepts/400.database-objects/100.database-objects-of-oracle-mode/300.index-of-oracle-mode/200.local-and-global-indexes-of-oracle-mode.md)を参照してください。

## インデックス作成の準備

インデックスを作成する前に、以下の事項を確認する必要があります：

* データベースのOracleテナントに接続済みであることを確認してください。データベースへの接続方法については、[接続方法の概要](../100.connect-to-oceanbase-database-of-oracle-mode/100.connection-methods-overview-of-oracle-mode.md)を参照してください。

  <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>現在ログインしているテナントが属するテナントモードは、<code>sys</code>テナントから<code>oceanbase.DBA_OB_TENANTS</code>ビューを照会することで確認できます。 </p>
  </main>

* `INDEX`権限およびインデックスを追加する対象のテーブルに対する`ALTER`権限を保有していることを確認してください。現在のユーザー権限に関する操作については、[ユーザー権限の確認](../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/300.permission-of-oracle-mode/600.view-user-permissions-of-oracle-mode.md)を参照してください。該当する権限を持っていない場合は、管理者に連絡し権限付与を依頼してください。ユーザー権限に関する操作については、[直接権限付与](../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/300.permission-of-oracle-mode/200.authority-of-oracle-mode.md)を参照してください。

* テーブルが既に作成済みであることを確認してください。テーブルの作成方法については、[テーブルの作成](../300.database-object-planning-of-oracle-mode/200.create-table-of-oracle-mode-in-develop.md)を参照してください。

## インデックス作成の推奨事項

* インデックス作成用のSQL文を並行して発行する場合、テナントユニット仕様に定められたコア数の上限を超えないようにすることを推奨します。例えば、テナントのユニット仕様が4コア（4C）の場合、インデックスの同時作成数は4件を超えないようにすることを推奨します。

* 頻繁に更新されるテーブルには、過剰なインデックスを設定することを避け、クエリで頻繁に使用されるフィールドにはインデックスを作成する必要があります。

* データ量が少ないテーブルでは、インデックスを使用しない方が望ましいです。データが少ないため、すべてのデータを照会する時間がインデックスをイテレーションする時間よりも短くなる可能性があり、インデックスによる最適化効果が得られない場合があるからです。

* 変更性能が検索性能を大幅に上回る場合、インデックスの作成は推奨されません。

* 効率的なインデックスの作成：

  * インデックスには、必要なクエリの列をすべて含める必要があります。含まれる列が多いほど良く、これによりテーブルへのヒント返却回数をできるだけ減らすことができます。

  * 等値条件は常に最初に配置します。

  * フィルタリングやソート処理で大量のデータを扱う場合は、その処理を先頭に配置します。

## 唯一インデックスの作成

インデックス列に重複する値が存在しないようにしたい場合、唯一インデックスを作成できます。

[CREATE UNIQUE INDEX](../../../700.reference/500.sql-reference/100.sql-syntax/300.common-tenant-of-oracle-mode/900.sql-statement-of-oracle-mode/100.ddl-of-oracle-mode/1600.create-index-of-oracle-mode.md) ステートメントを使用し、既存のテーブルに唯一インデックスを作成するには、以下の要件を参照してください。

唯一インデックスを作成する際には、次の要件に従う必要があります：

* OceanBaseデータベースでは、インデックス名はスキーマ範囲内で一意である必要があります。

* 唯一インデックスは複数作成できますが、その列値はすべて一意である必要があります。

* インデックス列の値にはNULL値を許容します。

例1：`CREATE UNIQUE INDEX` ステートメントを使用して、テーブルに唯一インデックスを作成します。

```sql
obclient [SYS]>CREATE TABLE test(c1 NUMBER, c2 NUMBER, c3 NUMBER, c4 NUMBER, PRIMARY KEY(c1));
Query OK, 0 rows affected

obclient [SYS]> CREATE UNIQUE INDEX idx1 ON test(c2);
Query OK, 0 rows affected

obclient [SYS]> SELECT INDEX_NAME,INDEX_TYPE,TABLE_OWNER,TABLE_NAME,UNIQUENESS FROM user_indexes WHERE table_name='TEST';
+----------------------------+------------+-------------+------------+------------+
| INDEX_NAME                 | INDEX_TYPE | TABLE_OWNER | TABLE_NAME | UNIQUENESS |
+----------------------------+------------+-------------+------------+------------+
| TEST_OBPK_1667195501871902 | NORMAL     | SYS         | TEST       | UNIQUE     |
| IDX1                       | NORMAL     | SYS         | TEST       | UNIQUE     |
+----------------------------+------------+-------------+------------+------------+
2 rows in set
```

## 非一意インデックスの作成

[CREATE INDEX](../../../700.reference/500.sql-reference/100.sql-syntax/300.common-tenant-of-oracle-mode/900.sql-statement-of-oracle-mode/100.ddl-of-oracle-mode/1600.create-index-of-oracle-mode.md) ステートメントを使用し、既存のテーブルに非一意インデックスを作成するには、以下の要件を参照してください。

非一意インデックスを作成するには、次の要件に従う必要があります。

* OceanBaseデータベースでは、インデックス名はスキーマ範囲内で一意である必要があります。

* インデックス列の値は重複可能であり、NULL値を含むことができます。

例2：`CREATE INDEX` ステートメントを使用して、テーブルに非一意インデックスを作成します。

```sql
obclient [SYS]> CREATE TABLE test(c1 NUMBER, c2 NUMBER, c3 NUMBER, c4 NUMBER, PRIMARY KEY(c1));
Query OK, 0 rows affected

obclient [SYS]> CREATE INDEX idx1 ON test(c2);
Query OK, 0 rows affected
```

## ローカルインデックスの作成

ローカルインデックスとは、単一のパーティション上のデータに対して作成されるインデックスであり、そのためインデックスキー値とテーブル内のデータとは一対一の対応関係になります。つまり、ローカルインデックス上のあるパーティションは必ずテーブルのパーティションに対応し、両者は同一のパーティションルールを共有します。したがって、ローカル一意インデックスはパーティション内部での唯一性を保証することはできますが、テーブルデータ全体のグローバルな唯一性を保証することはできません。ローカルインデックスを作成するためのキーワードは `LOCAL` です。

ローカル一意インデックスを使用してデータの唯一性を制約する場合、そのインデックスにはテーブルのパーティションキーを含める必要があります。

既存のテーブルにローカルインデックスを作成するには、[CREATE INDEX](../../../700.reference/500.sql-reference/100.sql-syntax/300.common-tenant-of-oracle-mode/900.sql-statement-of-oracle-mode/100.ddl-of-oracle-mode/1600.create-index-of-oracle-mode.md) ステートメントに `LOCAL` キーワードを組み合わせて使用し、以下の要件を参照してください。

既存のテーブルにローカル一意インデックスを作成するには、[CREATE UNIQUE INDEX](../../../700.reference/500.sql-reference/100.sql-syntax/300.common-tenant-of-oracle-mode/900.sql-statement-of-oracle-mode/100.ddl-of-oracle-mode/1600.create-index-of-oracle-mode.md) ステートメントに `LOCAL` キーワードを組み合わせて使用し、以下の要件を参照してください。

ローカルインデックスを作成する際には、以下の要件に従う必要があります：

* OceanBaseデータベースでは、インデックス名はスキーマ範囲内で一意でなければなりません。

* OceanBaseデータベースのOracleモードでは、インデックスプロパティキーワードが指定されていない場合、デフォルトのインデックスプロパティは `GLOBAL` であり、作成されるインデックスはグローバルインデックスであり、かつインデックステーブルにはパーティションが1つしか存在しません。

* ローカル一意インデックスを使用してデータの唯一性を制約する場合、そのインデックスにはテーブルのパーティションキーを含める必要があります。

例3：ローカルインデックスを作成します。

Hashパーティションを使用したパーティションテーブル `tbl1_h` を作成し、その上にローカルインデックス `tbl1_h_idx1` を作成します。

```sql
obclient [SYS]> CREATE TABLE tbl1_h(col1 NUMBER PRIMARY KEY,col2 NUMBER)
       PARTITION BY HASH(col1) PARTITIONS 5;
Query OK, 0 rows affected

obclient [SYS]> CREATE INDEX tbl1_h_idx1 ON tbl1_h(col2) LOCAL;
Query OK, 0 rows affected
```

例4：ローカル一意インデックスを作成します。

テンプレート化されていないRange + Listパーティションテーブル `tbl2_f_rl` を作成し、その上にローカル一意インデックス `tbl2_f_rl_idx1` を作成します。

```sql
obclient [SYS]> CREATE TABLE tbl2_f_rl(col1 NUMBER,col2 NUMBER)
       PARTITION BY RANGE(col1)
       SUBPARTITION BY LIST(col2)
       (PARTITION p0 VALUES LESS THAN(100)
         (SUBPARTITION sp0 VALUES(1,3),
          SUBPARTITION sp1 VALUES(4,6),
          SUBPARTITION sp2 VALUES(7,9)),
        PARTITION p1 VALUES LESS THAN(200)
         (SUBPARTITION sp3 VALUES(1,3),
          SUBPARTITION sp4 VALUES(4,6),
          SUBPARTITION sp5 VALUES(7,9))
       );
Query OK, 0 rows affected

obclient [SYS]> CREATE UNIQUE INDEX tbl2_f_rl_idx1 ON tbl2_f_rl(col1,col2) LOCAL;
Query OK, 0 rows affected
```

## グローバルインデックスの作成

グローバルインデックスを作成するためのキーワードは `GLOBAL` です。ローカルインデックスと比較して、グローバルインデックスの最大の特徴は、グローバルインデックスのパーティションルールがテーブルのパーティションルールと独立していることです。グローバルインデックスでは、独自のパーティションルールとパーティション数を指定でき、必ずしもテーブルのパーティションルールと一致させる必要はありません。

[CREATE INDEX](../../../700.reference/500.sql-reference/100.sql-syntax/300.common-tenant-of-oracle-mode/900.sql-statement-of-oracle-mode/100.ddl-of-oracle-mode/1600.create-index-of-oracle-mode.md) ステートメントに `GLOBAL` キーワードを組み合わせて使用し、既存のテーブルにグローバルインデックスを作成するには、以下の要件を参照してください。

[CREATE UNIQUE INDEX](../../../700.reference/500.sql-reference/100.sql-syntax/300.common-tenant-of-oracle-mode/900.sql-statement-of-oracle-mode/100.ddl-of-oracle-mode/1600.create-index-of-oracle-mode.md) ステートメントに `GLOBAL` キーワードを組み合わせて使用し、既存のテーブルにグローバル一意インデックスを作成するには、以下の要件を参照してください。

グローバルインデックスを作成する際に遵守すべき要件は以下のとおりです：

* OceanBaseデータベースでは、インデックス名はスキーマ範囲内で一意でなければなりません。

* OceanBaseデータベースのOracleモードでは、インデックスプロパティキーワードが指定されていない場合、デフォルトのインデックスプロパティは `GLOBAL` プロパティであり、作成されるインデックスはグローバルインデックスであり、インデックステーブルにはパーティションが1つだけ存在します。

* グローバルインデックスのパーティションルールは、必ずしもテーブルのパーティションルールと一致する必要はありません。

* グローバルインデックスのパーティションルールと主テーブルのパーティションルールが同じで、かつパーティション数も同じ場合は、ローカルインデックスを作成することを推奨します。その理由の一つは、グローバルインデックスのメンテナンスコストが高いことです。もう一つの理由は、グローバルインデックスは主テーブルと同一のテーブルグループに指定しない限り、主テーブルのパーティションと物理的な位置が一致することを保証できないためです。

例5：グローバルインデックスを作成します。

Hashパーティションを使用したパーティションテーブル `tbl1_h` を作成し、Rangeパーティションを使用したグローバルインデックス `tbl1_h_idx1` を作成します。

```sql
obclient [SYS]> CREATE TABLE tbl1_h(col1 NUMBER PRIMARY KEY,col2 NUMBER)
       PARTITION BY HASH(col1) PARTITIONS 5;
Query OK, 0 rows affected

obclient [SYS]> CREATE INDEX tbl1_h_idx1 ON tbl1_h(col2) GLOBAL
       PARTITION BY RANGE(col2)
       (PARTITION p0 VALUES LESS THAN(100),
        PARTITION p1 VALUES LESS THAN(200),
        PARTITION p2 VALUES LESS THAN(300)
       );
Query OK, 0 rows affected
```

例6：グローバル一意インデックスを作成します。

非テンプレート化Range + Listパーティションテーブル `tbl2_f_rl` を作成し、グローバル一意インデックス `tbl2_f_rl_idx1` を作成します。

```sql
obclient [SYS]> CREATE TABLE tbl2_f_rl(col1 NUMBER,col2 NUMBER)
       PARTITION BY RANGE(col1)
       SUBPARTITION BY LIST(col2)
       (PARTITION p0 VALUES LESS THAN(100)
         (SUBPARTITION sp0 VALUES(1,3),
          SUBPARTITION sp1 VALUES(4,6),
          SUBPARTITION sp2 VALUES(7,9)),
        PARTITION p1 VALUES LESS THAN(200)
         (SUBPARTITION sp3 VALUES(1,3),
          SUBPARTITION sp4 VALUES(4,6),
          SUBPARTITION sp5 VALUES(7,9))
       );
Query OK, 0 rows affected

obclient [SYS]> CREATE UNIQUE INDEX tbl2_f_rl_idx1 ON tbl2_f_rl(col1) GLOBAL;
Query OK, 0 rows affected
```
