# トランザクション管理の概要

本記事では、トランザクションの基本情報と関連する制御文について説明します。

## トランザクションの概要

データベーストランザクションは、データベース上の一連の操作を含みます。トランザクションにより、データベースはある一貫した状態から別の一貫した状態へと変換されます。通常、トランザクション内のSQLにはDMLステートメントとクエリステートメントの両方が含まれます。もしトランザクション内のSQLがクエリステートメントのみである場合、このトランザクションは通常読み取り専用トランザクションと呼ばれます。

トランザクションがコミットされる前であれば、`ROLLBACK` コマンドを使用してトランザクションをロールバックできます。トランザクションに関するその他の詳細については、[トランザクションの概要](../../../700.reference/100.oceanbase-database-concepts/800.transaction-management/100.transaction/100.transaction-introduction.md)を参照してください。

## トランザクション制御文

基本的なトランザクション制御文は以下の通りです：

* `BEGIN`：明示的にトランザクションを開始します。このステートメントは使用時に省略可能です。

  * テナントセッションのシステム変数 `autocommit` の値が `0` の場合、トランザクションの自動コミット機能が無効であることを意味し、複数のSQLを一つのトランザクションとして識別するために明示的に `BEGIN` コマンドを発行する必要はありません。

  * テナントセッションのシステム変数 `autocommit` の値が `1` の場合、トランザクションの自動コミット機能が有効であることを意味します。このモードでは、各SQLは独立したトランザクションとなります。複数のSQLを一つのトランザクションとする場合は、`BEGIN` コマンドで明示的にトランザクションを開始し、同時に自動コミット機能を無効にします。`COMMIT` または `ROLLBACK` ステートメントを実行するまで、自動コミットモードには戻りません。

* `SAVEPOINT`：トランザクション中に「セーブポイント」としてマークでき、後でこのセーブポイントまでロールバックすることができます。セーブポイントはオプションであり、一つのトランザクション内で複数のセーブポイントを設定することもできます。

* `COMMIT`：現在のトランザクションをコミットして終了し、トランザクションのすべての変更を永続的に有効化し、すべてのセーブポイントを削除し、トランザクションが保持するロックを解放します。

* `ROLLBACK`：トランザクション全体で既に行われた変更をロールバックするか、特定のセーブポイント以降に行われた変更のみをロールバックします。また、ロールバックされた部分に含まれるすべてのセーブポイントを削除し、トランザクションが保持するロックを解放します。

OBClientコマンド環境では、SQLプロンプトの後にトランザクション制御コマンドを開始できるほか、セッションレベルの `autocommit` パラメータを変更して、トランザクションを自動コミットするかどうかを制御できます。

* `SET autocommit` で変数を設定すると、現在のセッションに対して即時に反映されますが、接続が切断されると設定された変数は無効になります。

* `SET GLOBAL autocommit` でテナントレベルの変数を設定する場合、設定を有効にするには、接続を切断して再接続する必要があります。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>セッション内の変数 <code>autocommit</code> の値が <code>0</code> であり、かつトランザクションが明示的にコミットされていない場合、プログラムが異常中断すると、OceanBaseデータベースは最後にコミットされていないトランザクションを自動的にロールバックします。</p>
  </main>
