# トランザクションを特定のセーブポイントまでロールバックする

チェックポイントをマークした後、`ROLLBACK TO SAVEPOINT` ステートメントを使用して、指定されたトランザクションチェックポイントまでロールバックできます。

## 前提条件

チェックポイントがマークされていることを確認してください。詳細な操作については、[チェックポイントのマーク](../300.transaction-savepoints-of-mysql-mode/100.mark-a-savepoint-of-mysql-mode.md)を参照してください。

## トランザクションをチェックポイントまでロールバックする

以下のステートメントを使用して、トランザクションを特定のチェックポイントまでロールバックできます。

```sql
ROLLBACK TO SAVEPOINT pointname;
```

ここで、`pointname` はトランザクションチェックポイントの名前を表します。

以下の例では、トランザクションに複数のDMLステートメントと複数のチェックポイントが含まれており、その後、その中の1つのチェックポイントまでロールバックします。実行結果として、チェックポイント以降の変更が破棄されることが示されています。

1. テーブルの現在のレコードを確認します。

   ```sql
   obclient> SELECT * FROM ordr;
   ```

   クエリ結果は次のとおりです：

   ```sql
   +----+------+-------+---------------------+
   | id | name | value | gmt_create          |
   +----+------+-------+---------------------+
   |  1 | CN   | 10001 | 2022-10-19 14:51:12 |
   |  2 | US   | 10002 | 2022-10-19 14:51:12 |
   |  3 | EN   | 10003 | 2022-10-19 14:51:12 |
   |  4 | JP   |  NULL | 2022-10-19 14:51:44 |
   |  5 | CN   |  NULL | 2022-10-19 14:53:56 |
   +----+------+-------+---------------------+
   5 rows in set
   ```

2. トランザクションを開き、複数のチェックポイント情報を設定します。

   ```sql
   obclient> SET SESSION autocommit=0;
   obclient> BEGIN;
   obclient> INSERT INTO ordr(id, name) VALUES(6,'FR');
   obclient> SAVEPOINT fr;
   obclient> INSERT INTO ordr(id, name) VALUES(7,'RU');
   obclient> SAVEPOINT ru;
   obclient> INSERT INTO ordr(id, name) VALUES(8,'CA');
   obclient> SAVEPOINT ca;
   ```

3. 現在のセッションで、トランザクションがコミットされていないすべての変更を確認できます。

   ```sql
   obclient> SELECT * FROM ordr;
   ```

   クエリ結果は次のとおりです：

   ```sql
   +----+------+-------+---------------------+
   | id | name | value | gmt_create          |
   +----+------+-------+---------------------+
   |  1 | CN   | 10001 | 2022-10-19 14:51:12 |
   |  2 | US   | 10002 | 2022-10-19 14:51:12 |
   |  3 | EN   |  1003 | 2022-10-19 14:51:12 |
   |  4 | JP   |  NULL | 2022-10-19 14:51:44 |
   |  5 | CN   |  NULL | 2022-10-19 14:53:56 |
   |  6 | FR   |  NULL | 2022-10-19 15:01:39 |
   |  7 | RU   |  NULL | 2022-10-19 15:01:50 |
   |  8 | CA   |  NULL | 2022-10-19 15:02:15 |
   +----+------+-------+---------------------+
   8 rows in set
   ```

4. トランザクションをチェックポイント `ru` までロールバックします。

   ```sql
   obclient> ROLLBACK TO SAVEPOINT ru;
   obclient> SELECT * FROM ordr;
   ```

   クエリ結果は次のとおりです：

   ```sql
   +----+------+-------+---------------------+
   | id | name | value | gmt_create          |
   +----+------+-------+---------------------+
   |  1 | CN   | 10001 | 2022-10-19 14:51:12 |
   |  2 | US   | 10002 | 2022-10-19 14:51:12 |
   |  3 | EN   |  1003 | 2022-10-19 14:51:12 |
   |  4 | JP   |  NULL | 2022-10-19 14:51:44 |
   |  5 | CN   |  NULL | 2022-10-19 14:53:56 |
   |  6 | FR   |  NULL | 2022-10-19 15:01:39 |
   |  7 | RU   |  NULL | 2022-10-19 15:01:50 |
   +----+------+-------+---------------------+
   7 rows in set
   ```

   クエリ結果から、`(8,'CA')` はチェックポイント `ru` 以降に挿入されたデータであるため、ロールバック後、この変更は破棄されたことが確認できます。

5. トランザクションをコミットし、テーブルの最新の変更にチェックポイント `ru` 以前の変更が含まれていることを確認します。

   ```sql
   obclient> COMMIT;
   obclient> SELECT * FROM ordr;
   ```

   クエリ結果は次のとおりです：

   ```sql
   +----+------+-------+---------------------+
   | id | name | value | gmt_create          |
   +----+------+-------+---------------------+
   |  1 | CN   | 10001 | 2022-10-19 14:51:12 |
   |  2 | US   | 10002 | 2022-10-19 14:51:12 |
   |  3 | EN   |  1003 | 2022-10-19 14:51:12 |
   |  4 | JP   |  NULL | 2022-10-19 14:51:44 |
   |  5 | CN   |  NULL | 2022-10-19 14:53:56 |
   |  6 | FR   |  NULL | 2022-10-19 15:01:39 |
   |  7 | RU   |  NULL | 2022-10-19 15:01:50 |
   +----+------+-------+---------------------+
   7 rows in set

トランザクションのロールバックに関するその他の例と説明については、[トランザクションのロールバック](../500.roll-back-transactions-of-mysql-mode.md)を参照してください。
