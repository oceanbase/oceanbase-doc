# MySQL互換アプリケーションのエラー処理規範

この記事では、MySQL互換アプリケーションのエラー処理規範について説明します。

OceanBaseデータベースはV1.0バージョンからMySQLデータベースとの全面的な互換性を備えています。エラーコードに関しては、エラーコード、SQLSTATE、エラーメッセージの3つの情報において、可能な限りMySQLデータベースとの一貫性を保証しています。そのため、当社のプロダクト設計原則に基づき、アプリケーションのエラー処理方法はMySQLデータベースの処理規範を参考にすることができます。ただし、分散型データベースであるOceanBaseデータベースは、スタンドアロンのMySQLデータベースとは本質的に異なり、分散環境特有の一部のエラーはMySQLデータベースのエラーコードでは表現できません。したがって、エラーコードの値が4000を超える場合、そのエラーコードはOceanBaseデータベース固有のエラーコードであることを示します。エラーコードの値が4000以下の場合、それはMySQLデータベースとの互換エラーコードであることを示します。OceanBaseデータベースサーバー側のMySQLテナントモードにおける完全なエラーコード一覧については、[エラー情報の概要](../../../../700.reference/900.error-code/600.error-code-of-mysql-mode/100.use-error-information-of-mysql-mode.md)を参照してください。

アプリケーションが検出するエラーには、データベースサーバー側から返されるエラーの他に、ドライバーライブラリがローカルで返すエラー（例えば、データベース接続の確立失敗）も含まれる場合があります。OceanBaseデータベースのMySQLテナントを使用するアプリケーションは、MySQLのドライバーライブラリ（例えば、MySQL JDBC Driver）を使用できるため、この部分のエラーコードについては、OceanBaseデータベースとMySQLデータベースは完全に互換性があります。このようなクライアントエラーコードの値域は通常2000～3000です。

## エラー情報の取得

言語ごとに異なるドライバーが提供するAPIを使用してエラー情報を取得します。各ドライバーの詳細については、[OceanBaseデータベース公式ドキュメント](https://www.oceanbase.com/docs/common-oceanbase-database-cn-10000000001698766)および[MySQLデータベース公式ドキュメント](https://dev.mysql.com/doc/refman/8.0/en/connectors-apis.html)を参照してください。

### Javaドライバーライブラリ

JDBCを使用するJavaアプリケーションでSQL文の実行に失敗した場合、SQLException例外をキャッチできます。この例外には、エラーコード、SQLSTATE、エラーメッセージの3種類の情報が含まれています。SQLException例外の詳細については、[JDBC APIドキュメント](https://docs.oracle.com/javase/1.5.0/docs/api/java/sql/SQLException.html)を参照してください。

SQLException例外をキャッチする方法は以下のとおりです：

* getErrorCode()を呼び出してエラーコードを取得する
* getSQLState()を呼び出してSQLSTATEを取得する
* getMessage()を呼び出してエラーメッセージを取得する

### libmysql Cドライバーライブラリ

libmysqlを使用するC言語アプリケーションでSQL文の実行に失敗した場合、以下の方法でエラー情報を取得できます：

* mysql_errno()を呼び出してエラーコードを取得する
* mysql_sqlstate()を呼び出してSQLSTATEを取得する
* mysql_error()を呼び出してエラーメッセージを取得する

## エラー処理規範

OceanBaseデータベースのMySQLテナントモードにおけるほとんどのエラーコードについて、アプリケーションは特別な処理を行う必要がなく、そのまま外部にエラーを報告できます。フォールトトレランスとアプリケーションの堅牢性を向上させるため、特定のエラーコードに対しては、異なるシナリオやエラーの性質に応じて、以下の4つの異なるポリシーを採用できます：

1. ポリシー1：ステートメントのタイプに基づいて処理します。

   * `SELECT` ステートメントの実行時にタイムアウトエラーが発生した場合、副作用がないため、リトライできます。

   * リモートまたは分散実行による `UPDATE` などの変更ステートメントの実行時にタイムアウトエラーが発生した場合、ステートメントが実際に正常に実行されたかどうかは不確定であり、トランザクションをロールバックする必要があります（変更ステートメントのセマンティクスが冪等である場合、そのステートメントをリトライできます）。

   * `COMMIT` または `ROLLBACK` ステートメントの実行時にタイムアウトエラーが発生した場合、トランザクションの状態が不明であるため、直接外部にエラーを報告する必要があります。

2. ポリシー2：任意のステートメントの実行時にエラーが発生した場合、現在のトランザクションをロールバックし、その後トランザクションをリトライします。

3. ポリシー3：任意のステートメントの実行時にエラーが発生した場合、現在のステートメントをリトライします。

4. ポリシー4：任意のステートメントの実行時にエラーが発生した場合、現在の接続を閉じ、その後再接続します。

### MySQL互換エラーコード

エラーコード値が4000以下のMySQLデータベース互換のエラーコードについては、MySQLデータベースと同じ処理方法を遵守してください。特に、アプリケーションは以下のエラーコードに注意する必要があります。

| エラーコード | SQLSTATE | 意味 | 対処策 |
|-----------|----------|-----------|----------------------|
| 1205      | HY000    | デッドロックが検出されました | 現在のトランザクションをロールバックして再試行します |
| 1213      |40001     | ロック待機タイムアウト   | 現在のトランザクションをロールバックして再試行します |
