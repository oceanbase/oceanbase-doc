# トランザクションアイドルタイムアウト、エラーコードERROR 6002

本記事では、OceanBaseデータベースのMySQLモードにおいて、トランザクションがアイドル状態でタイムアウトした後に`ERROR 6002`エラーが報告される場合の対処方法について説明します。

## 現象

トランザクションを開始してから長時間待機した後、テーブルデータのクエリ時にエラーが発生します。

```sql
obclient [test]> SELECT * FROM ordr;
+----+------+-------+---------------------+
| id | name | value | gmt_create          |
+----+------+-------+---------------------+
|  1 | CN   |  NULL | 2022-04-02 14:03:31 |
|  2 | UK   |  NULL | 2022-04-02 14:03:31 |
|  3 | US   |  NULL | 2022-03-31 17:04:55 |
+----+------+-------+---------------------+
3 rows in set

obclient [test]> BEGIN;

obclient [test]> UPDATE ordr SET value=1003 WHERE id=3;
Query OK, 1 rows affected
Rows matched: 1  Changed: 1  Warnings: 0

obclient [test]> SELECT * FROM ordr;
+----+------+-------+---------------------+
| id | name | value | gmt_create          |
+----+------+-------+---------------------+
|  1 | CN   |  NULL | 2022-04-02 14:03:31 |
|  2 | UK   |  NULL | 2022-04-02 14:03:31 |
|  3 | US   |  1003 | 2022-03-31 17:04:55 |
+----+------+-------+---------------------+
3 rows in set

/* 長時間操作なし */

obclient [test]> SELECT * FROM ordr;
ERROR 6002 (25000): Transaction idle timeout occurred, please rollback the transaction, set the variable ob_trx_idle_timeout to a larger value and then restart the transaction
```

このエラーメッセージに対応するエラーコードは以下のとおりです：

* エラーコード：ERROR 6002

* OceanBaseエラーコード：6278

* MySQL互換エラーコード：6002

エラーコードの詳細については、[エラーコードの概要](../../../../700.reference/900.error-code/600.error-code-of-mysql-mode/100.use-error-information-of-mysql-mode.md)を参照してください。

## 考えられる原因

トランザクションアイドルタイムアウトとは、トランザクション内の2つのステートメントの実行間隔が指定されたしきい値を超えたことを意味します。トランザクションのアイドル時間が指定されたしきい値を超えた場合、引き続きデータベース操作を実行すると、システムはエラーを報告します。トランザクションのアイドルタイムアウトは、テナント変数`ob_trx_idle_timeout`によって制御され、デフォルト値は86400000000マイクロ秒、すなわち24時間です。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>OceanBaseデータベースでは、トランザクションが長時間コミットされずロックを保持することで他のセッションに影響を与えるのを防ぐため、トランザクションアイドルタイムアウトとトランザクション未コミットタイムアウトという2つのタイムアウトロジックが設計されています。通常、これらのうちどちらか一方のタイムアウトメカニズムが先にトリガーされます。 </p>
</main>

## 解決策

以下の手順に従って、テナント変数を確認および修正し、その後 `ROLLBACK` でトランザクションをロールバックしてから、操作を続けてください。

1. 変数 `ob_trx_idle_timeout` の値を確認し、操作のタイムアウト時間が設定値を超えていないかどうかを確認します。

   トランザクションのアイドルタイムアウト時間のしきい値は、テナント変数 `ob_trx_idle_timeout` によって制御され、単位はマイクロ秒です。デフォルト値の24時間（86400000000マイクロ秒）を使用することを推奨します。

   <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>以下の変数設定方法は現在のセッションにのみ有効です。設定を永続的に有効にするには、<code>SET GLOBAL</code> 構文を使用して同じ変数を設定した後、セッションを再起動して有効化してください。 </p>
   </main>

   ```sql
   obclient [test]> SHOW VARIABLES LIKE 'ob_trx_idle_timeout';
   +---------------------+-----------+
   | VARIABLE_NAME       | VALUE     |
   +---------------------+-----------+
   | ob_trx_idle_timeout | 120000000 |
   +---------------------+-----------+
   1 row in set

   obclient [test]> SET SESSION ob_trx_idle_timeout=86400000000;
   Query OK, 0 rows affected
   ```

2. `ROLLBACK` を使用してトランザクションをロールバックします。

   ```sql
   obclient [test]> ROLLBACK;
   Query OK, 0 rows affected
   ```

3. 再度テーブルのデータを照会します。照会は成功します。

   ```sql
   obclient [test]> SELECT * FROM ordr;
   +----+------+-------+---------------------+
   | id | name | value | gmt_create          |
   +----+------+-------+---------------------+
   |  1 | CN   |  NULL | 2022-04-02 14:03:31 |
   |  2 | UK   |  NULL | 2022-04-02 14:03:31 |
   |  3 | US   |  NULL | 2022-03-31 17:04:55 |
   +----+------+-------+---------------------+
   3 rows in set
   ```
