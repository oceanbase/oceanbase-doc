# サーバーへの接続が切断され、エラーコードERROR 2013が返される場合の対処方法

本記事では、OceanBaseデータベースのMySQLモードにおいてサーバーへの接続が切断され、`ERROR 2013`エラーが報告された場合の対処方法について説明します。

## 現象

データベースへの接続に成功した後、セッションが長時間アイドル状態となり、その後`ordr`テーブルのデータを確認するSQL文を実行すると、接続が切断されたエラーが発生します。

```sql
obclient [test]> SELECT * FROM ordr;
ERROR 2013 (HY000): Lost connection to MySQL server during query
```

## 考えられる原因

OceanBaseデータベースでは、セッションのアイドル時間が指定されたしきい値を超えると、システムが現在の接続を自動的に閉じ、次回の操作時に`ERROR 2013`エラーを報告します。

## 解決策

以下の手順を参照して、セッション関連変数の値を確認し、必要に応じて修正してください。以下の変数設定方法は現在のセッションにのみ有効です。設定を永続的に有効にするには、同じ変数に対して `SET GLOBAL` 構文を使用して設定した後、セッションを再起動して有効化してください。

1. 対応するMySQLテナントに再接続します。

2. システムと時間に関連する変数を確認します。

   ```sql
   obclient [test]> SHOW VARIABLES LIKE '%time%';
   +---------------------------------+------------------+
   | Variable_name                   | Value            |
   +---------------------------------+------------------+
   | connect_timeout                 | 10               |
   | default_password_lifetime       | 0                |
   | error_on_overlap_time           | OFF              |
   | explicit_defaults_for_timestamp | ON               |
   | interactive_timeout             | 10000            |
   | lock_wait_timeout               | 31536000         |
   | long_query_time                 | 10               |
   | max_execution_time              | 0                |
   | net_read_timeout                | 30               |
   | net_write_timeout               | 60               |
   | ob_pl_block_timeout             | 3216672000000000 |
   | ob_query_timeout                | 10000000         |
   | ob_trx_idle_timeout             | 86400000000      |
   | ob_trx_lock_timeout             | -1               |
   | ob_trx_timeout                  | 86400000000      |
   | system_time_zone                | +08:00           |
   | timestamp                       | 0                |
   | time_format                     | %H:%i:%s         |
   | time_zone                       | +8:00            |
   | wait_timeout                    | 10000            |
   +---------------------------------+------------------+
   20 rows in set
   ```

3. 変数 `wait_timeout` の値を `28800` に設定します。

   ```sql
   obclient [test]> SET wait_timeout = 28800;
   Query OK, 0 rows affected
   ```

4. 変数 `interactive_timeout` の値を `28800` に設定します。

   ```sql
   obclient [test]> SET interactive_timeout = 28800;
   Query OK, 0 rows affected
   ```

5. 再び `ordr` テーブルを確認します。正常にクエリできます。

   ```sql
   obclient [test]> SELECT * FROM ordr;
   +----+---------------------+---------------------+
   | id | gmt_create          | gmt_modified        |
   +----+---------------------+---------------------+
   |  1 | 2022-03-16 14:23:10 | 2022-03-16 14:23:10 |
   |  2 | 2022-03-16 14:23:10 | 2022-03-16 14:23:10 |
   |  3 | 2022-03-16 14:23:10 | 2022-03-16 14:23:10 |
   +----+---------------------+---------------------+
   3 rows in set
   ```
