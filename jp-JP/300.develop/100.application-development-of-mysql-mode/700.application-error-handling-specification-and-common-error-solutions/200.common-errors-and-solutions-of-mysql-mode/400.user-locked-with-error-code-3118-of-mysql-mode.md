# ユーザーがロックされ、エラーコードERROR 3118が表示される

本記事では、OceanBaseデータベースのMySQLモードでユーザーがロックされた後に`ERROR 3118`エラーが表示される場合の対処方法について説明します。

## 現象

`ny1`ユーザーでクラスタの`MySQL`テナントにログインし、複数回パスワードを間違えた後、システムからエラーが表示され、ユーザーがロックされたことを示します。

```sql
[admin@k08j13249.eu95sqa /home/admin]
$obclient -h10.10.10.1 -P2881 -uny1@MySQL -p**8*** -A
ERROR 3118 (HY000): User locked
```

このエラーメッセージに対応するエラーコードは以下のとおりです：

* エラーコード：ERROR 3118

* OceanBaseエラーコード：5039

* MySQL互換エラーコード：3118

エラーコードの詳細な説明については、[エラーコードの概要](../../../../700.reference/900.error-code/600.error-code-of-mysql-mode/100.use-error-information-of-mysql-mode.md)を参照してください。

## 考えられる原因

OceanBaseデータベースでは、ログイン失敗時の処理ポリシーが設定されています。複数回のログイン失敗があったユーザーに対して、OceanBaseデータベースはそのユーザーをロックします。これにより、悪意のあるパスワード攻撃を防ぎ、データベースを保護し、データベースの安全性を向上させます。ログイン失敗時の処理ポリシーに関する操作と説明については、[ログイン失敗時の処理ポリシー](../../../../600.manage/500.security-and-permissions/200.identification-and-authentication/100.identification-and-authentication-of-mysql-mode/300.login-failure-handling-of-mysql-mode.md)を参照してください。

## 解決策

以下の手順に従ってユーザーをロック解除し、再ログインしてください。

1. `root`ユーザーでクラスタの該当するテナントにログインします。MySQLテナントのデフォルト管理者ユーザーは`root`です。

   <main id="notice" type='explain'>
    <h4>説明</h4>
    <p> ユーザーのロック解除操作は通常管理者が実行します。一般ユーザーがロック解除操作を実行するには、グローバルな <code>CREATE USER</code> 権限が必要です。</p>
   </main>

2. ユーザー`ny1`のロックを解除します。

   ```sql
   obclient> ALTER USER 'ny1' account UNLOCK;
   Query OK, 0 rows affected
   ```

3. 再び`ny1`ユーザーでクラスタの対応するテナントにログインします。
