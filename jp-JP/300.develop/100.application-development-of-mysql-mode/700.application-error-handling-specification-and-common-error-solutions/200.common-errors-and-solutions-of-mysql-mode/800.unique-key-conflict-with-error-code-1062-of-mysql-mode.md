# データの挿入時に重複した入力があると警告され、エラーコードERROR 1062が表示される場合の対処方法

本記事では、OceanBaseデータベースのMySQLモードでデータを挿入する際に重複した入力があると警告され、`ERROR 1062` エラーが表示される場合の対処方法について説明します。

## 現象

主キーを持つテーブル`t_insert`にデータを挿入する際、主キー値が重複していると表示されます。

```sql
obclient> SELECT * FROM t_insert;
+----+------+-------+---------------------+
| id | name | value | gmt_create          |
+----+------+-------+---------------------+
|  1 | CN   | 10001 | 2022-10-12 15:17:17 |
|  2 | US   | 10002 | 2022-10-12 16:29:16 |
|  3 | EN   | 10003 | 2022-10-12 16:29:26 |
+----+------+-------+---------------------+
3 rows in set

obclient> INSERT INTO t_insert(id, name, value) VALUES (3,'UK', 10003),(4, 'JP', 10004);
ERROR 1062 (23000): Duplicate entry '3' for key 'PRIMARY'
```

このエラーメッセージに対応するエラーコードは以下のとおりです：

* エラーコード：ERROR 1062

* OceanBaseエラーコード：5024

* MySQL互換エラーコード：1062

エラーコードの詳細については、[エラーコードの概要](../../../../700.reference/900.error-code/600.error-code-of-mysql-mode/100.use-error-information-of-mysql-mode.md)を参照してください。

## 考えられる原因

テーブルにデータを挿入する際、テーブルに一意性制約が設定されている場合、同じレコードを再度挿入するとシステムからエラーが報告されます。

## 解決策

以下の2つの方法を参照して、競合を解決してください。

**方法1**：`INSERT IGNORE INTO` ステートメントを使用して制約競合を回避します。`IGNORE` キーワードは、制約競合によって引き起こされる `INSERT` の失敗の影響を無視できます。

1. `t_insert` テーブルにデータを挿入する際に `IGNORE` キーワードを追加します。

   ```sql
   obclient> SELECT * FROM t_insert;
   +----+------+-------+---------------------+
   | id | name | value | gmt_create          |
   +----+------+-------+---------------------+
   |  1 | CN   | 10001 | 2022-10-12 15:17:17 |
   |  2 | US   | 10002 | 2022-10-12 16:29:16 |
   |  3 | EN   | 10003 | 2022-10-12 16:29:26 |
   +----+------+-------+---------------------+
   3 rows in set

   obclient> INSERT IGNORE INTO t_insert(id, name, value) VALUES (3,'UK', 10003),(4, 'JP', 10004);
   Query OK, 1 row affected
   ```

2. 再度 `t_insert` テーブルのデータを確認します。主キー値と同じレコードが破棄され、主キー値が異なるレコードが正常に挿入されていることがわかります。

   ```sql
   obclient> SELECT * FROM t_insert;
   +----+------+-------+---------------------+
   | id | name | value | gmt_create          |
   +----+------+-------+---------------------+
   |  1 | CN   | 10001 | 2022-10-12 15:17:17 |
   |  2 | US   | 10002 | 2022-10-12 16:29:16 |
   |  3 | EN   | 10003 | 2022-10-12 16:29:26 |
   |  4 | JP   | 10004 | 2022-10-12 17:02:52 |
   +----+------+-------+---------------------+
   4 rows in set
   ```

**方法2**：`INSERT INTO ON DUPLICATE KEY UPDATE` を使用して制約競合を回避し、重複する主キーまたは一意のキーに対する後続の処理を指定できます。以下の例では、競合する行の内容を更新しました。

   <main id="notice" type='explain'>
    <h4>説明</h4>
    <p><ul><li><code>ON DUPLICATE KEY UPDATE column_name = expr</code> を指定する場合：挿入する主キーまたは一意のキーに重複する値がある場合、<code>column_name = expr</code> 値付けステートメントを使用して、テーブル内の競合する行のデータを更新できます。<code>column_name = expr</code> 値付けステートメントは、競合する行に1列または複数の列の値を代入できます。複数の列の値を代入する場合は、列と列の間にカンマを使用して区切ります。</li><li><code>ON DUPLICATE KEY UPDATE column_name = expr</code> を指定しない場合：挿入する主キーまたは一意のキーに重複する値がある場合、システムはエラーを報告します。</li></ul>  </p>
   </main>

1. `t_insert` テーブルにデータを挿入する際に `INSERT INTO ON DUPLICATE KEY UPDATE` を使用して、制約競合を回避します。

   ```sql
      obclient> SELECT * FROM t_insert;
   +----+------+-------+---------------------+
   | id | name | value | gmt_create          |
   +----+------+-------+---------------------+
   |  1 | CN   | 10001 | 2022-10-12 15:17:17 |
   |  2 | US   | 10002 | 2022-10-12 16:29:16 |
   |  3 | EN   | 10003 | 2022-10-12 16:29:26 |
   +----+------+-------+---------------------+
   3 rows in set

   obclient> INSERT INTO t_insert(id, name, value) VALUES (3,'UK', 10003),(4, 'JP', 10004) ON DUPLICATE KEY UPDATE name=VALUES(name);
   Query OK, 1 row affected
   ```

2. 再度 `t_insert` テーブルのデータを確認します。主キー値と同じレコードが更新され、主キー値が異なるレコードが正常に挿入されていることがわかります。

   ```sql
   obclient> select * from t_insert;
   +----+------+-------+---------------------+
   | id | name | value | gmt_create          |
   +----+------+-------+---------------------+
   |  1 | CN   | 10001 | 2022-10-12 15:17:17 |
   |  2 | US   | 10002 | 2022-10-12 16:29:16 |
   |  3 | UK   | 10003 | 2022-10-12 16:29:26 |
   |  4 | JP   | 10004 | 2022-10-12 18:04:32 |
   +----+------+-------+---------------------+
   4 rows in set
   ```
