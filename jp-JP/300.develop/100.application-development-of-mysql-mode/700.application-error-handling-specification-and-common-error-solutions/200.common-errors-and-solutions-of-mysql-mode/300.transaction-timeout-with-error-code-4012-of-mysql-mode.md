# トランザクションタイムアウト、エラーコードERROR 4012

本記事では、OceanBaseデータベースのMySQLモードにおいて、トランザクションがコミットされないままタイムアウトした場合に発生する`ERROR 4012`エラーの処理方法について説明します。

## 現象

トランザクションが開始された後、長時間にわたってコミットされないままであると、テーブルデータのクエリを実行する際にエラーが発生します。

```sql
obclient [test]> BEGIN;
Query OK, 0 rows affected

obclient [test]> SELECT * FROM ordr;
+----+------+-------+---------------------+
| id | name | value | gmt_create          |
+----+------+-------+---------------------+
|  1 | CN   |  NULL | 2022-04-02 14:03:31 |
|  2 | UK   |  NULL | 2022-04-02 14:03:31 |
|  3 | US   |  NULL | 2022-03-31 17:04:55 |
+----+------+-------+---------------------+
3 rows in set

/* 長時間操作なし */

obclient [test] SELECT * FROM ordr;
ERROR 4012 (25000): Transaction timeout occurred, please rollback the transaction, set the variable ob_trx_timeout to a larger value and then restart the transaction
```

このエラーメッセージに対応するエラーコードは以下のとおりです：

* エラーコード：ERROR 4012

* OceanBaseエラーコード：6210

* MySQL互換エラーコード：4012

エラーコードの詳細については、[エラーコードの概要](../../../../700.reference/900.error-code/600.error-code-of-mysql-mode/100.use-error-information-of-mysql-mode.md)を参照してください。

## 考えられる原因

トランザクション未コミットタイムアウトとは、トランザクションが指定されたしきい値を超えても依然としてコミットされない状態を指します。トランザクションが指定された時間を超えてもコミットされない場合、システムはエラーを報告します。トランザクション未コミットタイムアウトは、テナント変数`ob_trx_timeout`によって制御され、デフォルト値は86400000000マイクロ秒、すなわち24時間です。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>OceanBaseデータベースでは、トランザクションが長時間コミットされずにロックを保持し、他のセッションに影響を与えることを防ぐために、2種類のタイムアウトロジックが設計されています：トランザクションアイドルタイムアウトとトランザクション未コミットタイムアウトです。通常、どちらか一方のタイムアウトメカニズムが先にトリガーされます。</p>
</main>

## 解決策

以下の手順に従って、テナント変数を確認および修正し、`ROLLBACK` ステートメントでトランザクションをロールバックしてコミットした後、操作を続けてください。

1. テナント変数 `ob_trx_timeout` の値を確認し、トランザクションのタイムアウト時間が設定値を超えていないかどうかを確認します。

   トランザクションの未コミットタイムアウトしきい値は、テナント変数 `ob_trx_timeout` によって制御され、単位はマイクロ秒です。デフォルト値の24時間（86400000000マイクロ秒）を使用することを推奨します。

   <main id="notice" type='explain'>
    <h4>説明</h4>
    <p> 以下の変数設定方法は現在のセッションにのみ有効です。設定を永続的に有効にするには、<code>SET GLOBAL</code> 構文を使用して同じ変数を設定し、その後セッションを再起動して有効化してください。</p>
   </main>

   ```sql
   obclient> SHOW VARIABLES LIKE 'ob_trx_timeout';
   +----------------+-----------+
   | Variable_name  | Value     |
   +----------------+-----------+
   | ob_trx_timeout | 100000000 |
   +----------------+-----------+
   1 row in set

   obclient [test]> SET SESSION ob_trx_timeout=86400000000;
   Query OK, 0 rows affected
   ```

2. `ROLLBACK` を使用してトランザクションをロールバックします。

   ```sql
   obclient> ROLLBACK;
   Query OK, 0 rows affected
   ```

3. `COMMIT` を実行してトランザクションをコミットします。

   ```sql
   obclient> COMMIT;
   Query OK, 0 rows affected
   ```

4. 再度 `ordr` テーブルのデータを照会すると、操作は成功します。

   ```sql
   obclient [test]> SELECT * FROM ordr;
   +----+------+-------+---------------------+
   | id | name | value | gmt_create          |
   +----+------+-------+---------------------+
   |  1 | CN   |  NULL | 2022-04-02 14:03:31 |
   |  2 | UK   |  NULL | 2022-04-02 14:03:31 |
   |  3 | US   |  NULL | 2022-03-31 17:04:55 |
   +----+------+-------+---------------------+
   3 rows in set
   ```
