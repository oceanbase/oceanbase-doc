# インデックスの作成

本記事では、SQLステートメントを使用してインデックスを作成する方法について説明します。また、インデックスを作成するための前提条件、インデックスの概要、制限事項、推奨事項なども紹介し、いくつかのサンプルを提供します。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>本記事では、主に<code>CREATE INDEX</code>ステートメントを使用してインデックスを作成する方法について説明します。他のインデックス作成方法については、<a href="../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2600.create-table-of-mysql-mode.md">CREATE TABLE</a>または<a href="../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/1600.alter-table-of-mysql-mode.md">ALTER TABLE</a>ステートメントを参照してください。</p>
</main>

## インデックスの概要

インデックスとは、セカンダリインデックスとも呼ばれ、オプションのテーブル構造です。OceanBaseデータベースではクラスタリングインデックステーブルモデルが採用されており、ユーザーが指定した主キーに対してはシステムが自動的に主キーインデックスを生成します。一方、ユーザーが作成するその他のインデックスはセカンダリインデックスとなります。自身のビジネスニーズに応じて、どのフィールドにインデックスを作成するかを決定することで、これらのフィールドでのクエリ速度を向上させることができます。

OceanBaseデータベースのインデックスに関する詳細については、[インデックスの概要](../../../700.reference/100.oceanbase-database-concepts/400.database-objects/200.database-objects-of-mysql-mode/300.index-of-oracle-mode/100.index-overview-of-mysql-mode.md)を参照してください。

## 前提条件

インデックスを作成する前に、以下の事項を確認してください：

* OceanBaseクラスタがデプロイされており、MySQLモードのテナントが作成されていること。OceanBaseクラスタのデプロイに関する詳細については、[デプロイ概要](../../../400.deploy/100.deploy-overview.md)を参照してください。

* OceanBaseデータベースのMySQLテナントに接続していること。データベースへの接続に関する詳細については、[接続方法の概要](../100.connect-to-oceanbase-database-of-mysql-mode/100.connection-methods-overview-of-mysql-mode.md)を参照してください。

* データベースが作成されていること。データベースの作成に関する詳細については、[データベースの作成](100.create-database-of-mysql-mode-in-develop.md)を参照してください。

* テーブルが作成されていること。テーブルの作成に関する詳細については、[テーブルの作成](300.create-table-of-mysql-mode-in-develop.md)を参照してください。

* `INDEX`権限を持っていること。現在のユーザー権限を確認する操作については、[ユーザー権限の確認](../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/400.view-user-permissions-of-mysql-mode.md)を参照してください。この権限を持っていない場合は、管理者に連絡して権限付与を依頼してください。ユーザー権限に関する操作については、[直接権限付与](../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/200.authority-of-mysql-mode.md)を参照してください。

## インデックス作成の制限

* OceanBaseデータベースでは、インデックス名がデータベース（DataBase）内で一意である必要があります。

* インデックス名の長さは64バイトを超えてはなりません。

* 一意インデックスの使用制限：

  * 1つのテーブルに複数の一意インデックスを作成できますが、各一意インデックスに対応する列値はすべて一意でなければなりません。

  * 主キー以外の列の組み合わせがグローバル一意性を満たすことを希望する場合、グローバル一意インデックスを使用して実現する必要があります。

  * ローカル一意インデックスを使用する場合、インデックスにはテーブルのパーティション関数に含まれるすべての列を含める必要があります。

* グローバルインデックスを使用する場合、グローバルインデックスのパーティションルールは必ずしもテーブルのパーティションルールと完全に同じまたは一致する必要はありません。

* スペースインデックスの使用制限：

  * スペースインデックスはローカルインデックスのみをサポートし、グローバルインデックスはサポートしていません。

  * スペースインデックスを作成する列は `SRID` プロパティとして定義されている必要があります。そうでない場合、その列に追加されたスペースインデックスはその後のクエリで効果を発揮しません。`SRID` に関する詳細については、[空間参照システム(SRS)](../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/100.basic-elements-of-mysql-mode/100.data-type-of-mysql-mode/900.spatial-data-type-of-mysql-mode/200.spacial-reference-system-of-mysql-mode.md)を参照してください。

  * スペースデータ型のデータ列に対してのみスペースインデックスを作成できます。OceanBaseデータベースがサポートする空間データ型については、[空間データ型の概要](../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/100.basic-elements-of-mysql-mode/100.data-type-of-mysql-mode/900.spatial-data-type-of-mysql-mode/100.spatial-data-type-overview-of-mysql-mode.md)を参照してください。

  * スペースインデックスを作成する列の列プロパティは `NOT NULL` でなければなりません。`NOT NULL` ではない場合は、`ALTER TABLE` ステートメントを使用してその列の列プロパティを `NOT NULL` に変更した後、スペースインデックスを追加することができます。列プロパティの変更に関する具体的な操作については、[列の制約タイプの定義](../../../700.reference/300.database-object-management/100.manage-object-of-mysql-mode/200.manage-tables-of-mysql-mode/400.define-the-constraint-type-for-a-column-of-mysql-mode.md)を参照してください。

  * OceanBaseデータベースでは、現在 `ALTER TABLE` を使用して列の `SRID` プロパティを変更することはサポートされていません。そのため、空間インデックスを有効にするには、テーブル作成時に空間列の `SRID` プロパティを正しく定義しておく必要があります。

## インデックス作成の推奨事項

* インデックスがカバーする列と用途を簡潔に説明できる名前を使用することを推奨します。例えば、`idx_customer_name` などです。さらに詳しい命名規則については、[オブジェクトの命名規範の概要](../../../700.reference/400.database-design-specifications-and-practices/100.object-naming-conventions/100.overview-of-object-naming-conventions.md)を参照してください。

* グローバルインデックスのパーティションルールと主テーブルのパーティションルールが同じであり、かつパーティション数も同じ場合、ローカルインデックスを作成することを推奨します。

* インデックス作成のSQLステートメントのパラレル実行件数は、テナントのユニット仕様におけるコア数の上限を超えないようにしてください。例えば、テナントのユニット仕様が4コア(4C)の場合、インデックスの並列作成は4件を超えないことを推奨します。

* データ更新頻度の高いテーブルには、過剰なインデックスを追加しないようにし、クエリで頻繁に使用されるフィールドにはインデックスを作成することを推奨します。

* データ量が少ないテーブルでは、インデックスを使用しない方がよい場合があります。データが少ないため、すべてのデータをクエリするのにかかる時間の方が、インデックスをトラバースするよりも短くなる可能性があり、インデックスの最適化効果が得られなくなる恐れがあります。

* 性能変更が検索性能を大幅に上回る場合、インデックスを作成することを推奨しません。

* 高効率なインデックスを作成するには：

  * インデックスには必要なクエリ対象の列をすべて含めるようにしてください。含まれる列が多いほど、テーブルへのアクセス回数を最小限に抑えることができます。

  * 等値条件は常に最初に配置します。

  * 大規模なフィルタリングやソート処理は、先頭に配置します。

## コマンドラインを使用してインデックスを作成する

[CREATE INDEX](../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2200.create-index-of-mysql-mode.md) ステートメントを使用してインデックスを作成してください。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p><code>SHOW INDEX FROM table_name;</code> ステートメントを使用して、テーブル内のインデックス情報を確認できます。ここで、<code>table_name</code> はテーブル名です。</p>
</main>

## 例

### 例1：一意インデックスを作成する

インデックス列に重複する値が存在しない場合、一意インデックスを作成できます。

以下のSQLステートメントを使用して、`tbl1` という名前のテーブルを作成し、テーブル `tbl1` に `col2` 列に基づく一意インデックスを作成します。

1. テーブル `tbl1` を作成します。

    ```sql
    obclient [test]> CREATE TABLE tbl1(col1 INT, col2 INT, col3 VARCHAR(50), PRIMARY KEY (col1));
    ```

2. テーブル `tbl1` の `col2` 列に基づいて、`idx_tbl1_col2` という名前の一意インデックスを作成します。

    ```sql
    obclient [test]> CREATE UNIQUE INDEX idx_tbl1_col2 ON tbl1(col2);
    ```

3. テーブル `tbl1` のインデックス情報を確認します。

    ```sql
    obclient [test]> SHOW INDEX FROM tbl1;
    ```

    実行結果は次のとおりです：

    ```shell
    +-------+------------+---------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+------------+
    | Table | Non_unique | Key_name      | Seq_in_index | Column_name | Collation | Cardinality | Sub_part | Packed | Null | Index_type | Comment   | Index_comment | Visible | Expression |
    +-------+------------+---------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+------------+
    | tbl1  |          0 | PRIMARY       |            1 | col1        | A         |        NULL | NULL     | NULL   |      | BTREE      | available |               | YES     | NULL       |
    | tbl1  |          0 | idx_tbl1_col2 |            1 | col2        | A         |        NULL | NULL     | NULL   | YES  | BTREE      | available |               | YES     | NULL       |
    +-------+------------+---------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+------------+
    2 rows in set
    ```

### 例3：ローカルインデックスを作成する

ローカルインデックスはパーティションインデックスとも呼ばれ、ローカルインデックスを作成するためのキーワードは `LOCAL` です。ローカルインデックスのパーティションキーはテーブルのパーティションキーと同じであり、ローカルインデックスのパーティション数もテーブルのパーティション数と同じであるため、ローカルインデックスのパーティションメカニズムはテーブルのパーティションメカニズムと同一です。ローカルインデックスおよびローカル一意インデックスの作成がサポートされています。ローカル一意インデックスを使用してデータの一意性を制約する場合、そのローカル一意インデックスにはテーブルのパーティションキーが含まれている必要があります。

以下のSQLステートメントを使用して、`tbl3_rl` という名前のコンポジットパーティションテーブルを作成し、テーブル `tbl3_rl` に `col1` および `col2` 列に基づくローカル一意インデックスを作成します。

1. Range + Listコンポジットパーティションテーブル `tbl3_rl` を作成します。

    ```sql
    obclient [test]> CREATE TABLE tbl3_rl(col1 INT,col2 INT)
      PARTITION BY RANGE(col1)
      SUBPARTITION BY LIST(col2)
        (PARTITION p0 VALUES LESS THAN(100)
          (SUBPARTITION sp0 VALUES IN(1,3),
          SUBPARTITION sp1 VALUES IN(4,6),
          SUBPARTITION sp2 VALUES IN(7,9)),
        PARTITION p1 VALUES LESS THAN(200)
          (SUBPARTITION sp3 VALUES IN(1,3),
          SUBPARTITION sp4 VALUES IN(4,6),
          SUBPARTITION sp5 VALUES IN(7,9))
        );
    ```

2. テーブル `tbl3_rl` に `col1` および `col2` 列に基づいて `idx_tbl3_rl_col1_col2` という名前のインデックスを作成します。

    ```sql
    obclient [test]> CREATE UNIQUE INDEX idx_tbl3_rl_col1_col2 ON tbl3_rl(col1,col2) LOCAL;
    ```

3. テーブル `tbl3_rl` のインデックス情報を確認します。

    ```sql
    obclient [test]> SHOW INDEX FROM tbl3_rl;
    ```

    実行結果は次のとおりです：

    ```shell
    +---------+------------+-----------------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+------------+
    | Table   | Non_unique | Key_name              | Seq_in_index | Column_name | Collation | Cardinality | Sub_part | Packed | Null | Index_type | Comment   | Index_comment | Visible | Expression |
    +---------+------------+-----------------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+------------+
    | tbl3_rl |          0 | idx_tbl3_rl_col1_col2 |            1 | col1        | A         |        NULL | NULL     | NULL   | YES  | BTREE      | available |               | YES     | NULL       |
    | tbl3_rl |          0 | idx_tbl3_rl_col1_col2 |            2 | col2        | A         |        NULL | NULL     | NULL   | YES  | BTREE      | available |               | YES     | NULL       |
    +---------+------------+-----------------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+------------+
    2 rows in set
    ```

### 例4：グローバルインデックスを作成する

グローバルインデックスを作成するためのキーワードは `GLOBAL` です。

以下のSQLステートメントを使用して、`tbl4_h` という名前のパーティションテーブルを作成し、テーブル `tbl4_h` に `col2` 列に基づくグローバルインデックスを作成します。

1. Hashパーティションを指定したパーティションテーブル `tbl4_h` を作成します。

    ```sql
    obclient [test]> CREATE TABLE tbl4_h(col1 INT PRIMARY KEY,col2 INT)
      PARTITION BY HASH(col1) PARTITIONS 5;
    ```

2. テーブル `tbl4_h` に、`col2` 列に基づくRangeパーティションインデックスである `idx_tbl4_h_col2` という名前のグローバルインデックスを作成します。

    ```sql
    obclient [test]> CREATE INDEX idx_tbl4_h_col2 ON tbl4_h(col2) GLOBAL
      PARTITION BY RANGE(col2)
      (PARTITION p0 VALUES LESS THAN(100),
        PARTITION p1 VALUES LESS THAN(200),
        PARTITION p2 VALUES LESS THAN(300)
      );
    ```

3. テーブル `tbl4_h` のインデックス情報を確認します。

    ```sql
    obclient [test]> SHOW INDEX FROM tbl4_h;
    ```

    実行結果は次のとおりです：

    ```shell
    +--------+------------+-----------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+------------+
    | Table  | Non_unique | Key_name        | Seq_in_index | Column_name | Collation | Cardinality | Sub_part | Packed | Null | Index_type | Comment   | Index_comment | Visible | Expression |
    +--------+------------+-----------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+------------+
    | tbl4_h |          0 | PRIMARY         |            1 | col1        | A         |        NULL | NULL     | NULL   |      | BTREE      | available |               | YES     | NULL       |
    | tbl4_h |          1 | idx_tbl4_h_col2 |            1 | col2        | A         |        NULL | NULL     | NULL   | YES  | BTREE      | available |               | YES     | NULL       |
    +--------+------------+-----------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+------------+
    2 rows in set
    ```

### 例5：空間インデックスを作成する

空間インデックスとは、空間データを処理および最適化するために使用されるデータベースのインデックスです。地理情報システム（GIS）や位置データのストレージとクエリにおいて広く利用されています。OceanBaseデータベースは、通常のインデックス作成構文を使用して空間インデックスを作成することをサポートしていますが、空間インデックスには `SPATIAL` キーワードが必要です。

次のSQLステートメントを使用して、`tbl5` という名前のテーブルを作成し、テーブル `tbl5` に `g` 列に基づく空間インデックスを作成します。

1. テーブル `tbl5` を作成します。

    ```sql
    obclient [test]> CREATE TABLE tbl5(id INT,name VARCHAR(20),g GEOMETRY NOT NULL SRID 0);
    ```

2. テーブル `tbl5` に `g` 列に基づいて、`idx_tbl5_g` という名前の空間インデックスを作成します。

    ```sql
    obclient [test]> CREATE INDEX idx_tbl5_g ON tbl5(g);
    ```

3. テーブル `tbl5` のインデックス情報を確認します。

    ```sql
    obclient [test]> SHOW INDEX FROM tbl5;
    ```

    実行結果は次のとおりです：

    ```shell
    +-------+------------+------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+------------+
    | Table | Non_unique | Key_name   | Seq_in_index | Column_name | Collation | Cardinality | Sub_part | Packed | Null | Index_type | Comment   | Index_comment | Visible | Expression |
    +-------+------------+------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+------------+
    | tbl5  |          1 | idx_tbl5_g |            1 | g           | A         |        NULL | NULL     | NULL   |      | SPATIAL    | available |               | YES     | NULL       |
    +-------+------------+------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+------------+
    1 row in set
    ```

### 例6：関数インデックスを作成する

テーブル内の1列または複数の列の値に基づいて計算された結果に基づいて作成されるインデックスを関数インデックスと呼びます。関数インデックスは一種の最適化技術であり、関数インデックスを使用することでクエリ時に一致する関数値を迅速に特定でき、重複計算を回避し、クエリ効率を向上させることができます。

OceanBaseデータベースのMySQLモードでは、関数インデックスの式に対して制限が設けられており、一部のシステム関数の式を関数インデックスとして使用することは禁止されています。具体的な関数リストについては、[関数インデックスがサポートするシステム関数の一覧](../../../700.reference/300.database-object-management/100.manage-object-of-mysql-mode/500.manage-indexes-of-mysql-mode/500.function-index-list-of-supported-functions-of-mysql-mode.md)および[関数インデックスがサポートしないシステム関数の一覧](../../../700.reference/300.database-object-management/100.manage-object-of-mysql-mode/500.manage-indexes-of-mysql-mode/600.function-index-list-of-not-supported-functions-of-mysql-mode.md)を参照してください。

次のSQLステートメントを使用して、`tbl6`という名前のテーブルを作成し、テーブル`tbl6`に`c_time`列に基づく関数インデックスを作成します。

1. テーブル`tbl6`を作成します。

    ```sql
    obclient [test]> CREATE TABLE tbl6(id INT, name VARCHAR(18), c_time DATE);
    ```

2. テーブル`tbl6`上に`idx_tbl6_c_time`という名前のインデックスを作成します。このインデックスは、`c_time`列の年部分に基づいて作成されます。

    ```sql
    obclient [test]> CREATE INDEX idx_tbl6_c_time ON tbl6((YEAR(c_time)));
    ```

3. 以下のSQLステートメントを使用すると、作成された関数インデックスを確認できます。

    ```sql
    SHOW INDEX FROM tbl6;
    ```

    実行結果は次のとおりです：

    ```shell
    obclient [test]> SHOW INDEX FROM tbl6;
    +-------+------------+-----------------+--------------+-------------+-----------+-------------+----------+--------+------+------------+-----------+---------------+---------+----------------+
    ```
