# テーブルグループの作成

本記事では、SQLステートメントを使用してテーブルグループを作成する方法について説明します。また、テーブルグループを作成するための前提条件、テーブルグループの概要、制限事項、推奨事項などを紹介し、いくつかの例も提供します。

## テーブルグループの概要

OceanBaseデータベースにおいて、テーブルグループとは論理的な概念であり、Tableの集合を指します。テーブルグループを定義することで、一連のテーブルが物理ストレージ上の隣接関係を制御できます。

OceanBaseデータベースのテーブルグループに関する詳細については、[テーブルグループの概要](../../../700.reference/300.database-object-management/100.manage-object-of-mysql-mode/400.manage-table-groups-of-mysql-mode/100.about-table-groups-of-mysql-mode.md)を参照してください。

## 前提条件

テーブルグループを作成する前に、以下の点を確認してください：

* OceanBaseクラスタがデプロイされており、MySQLモードのテナントが作成されていること。OceanBaseクラスタのデプロイに関する詳細については、[デプロイの概要](../../../400.deploy/100.deploy-overview.md)を参照してください。

* OceanBaseデータベースのMySQLテナントに接続していること。データベースへの接続に関する詳細については、[接続方法の概要](../100.connect-to-oceanbase-database-of-mysql-mode/100.connection-methods-overview-of-mysql-mode.md)を参照してください。

* データベースが作成されていること。データベースの作成に関する詳細については、[データベースの作成](100.create-database-of-mysql-mode-in-develop.md)を参照してください。

* グローバルな`CREATE`(`*.*`)権限を持っていること。現在のユーザー権限を確認する操作については、[ユーザー権限の確認](../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/400.view-user-permissions-of-mysql-mode.md)を参照してください。この権限を持っていない場合は、管理者に連絡して権限付与を依頼してください。ユーザー権限の付与に関する操作については、[直接権限付与](../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/200.authority-of-mysql-mode.md)を参照してください。

## テーブルグループの作成制限

* OceanBaseデータベースでは、各テーブルグループの名前は同一テナント内で一意である必要があります。
* テーブルグループ名は64文字を超えてはなりません。
* テーブルグループ名には大文字と小文字を区別した英字、数字、アンダースコアのみ使用でき、かつアルファベットまたはアンダースコアで始める必要があります。
* テーブルグループ名にOceanBaseデータベースのキーワードを使用することはできません。OceanBaseデータベースのMySQLモードの予約語については、[予約語](../../../700.reference/500.sql-reference/800.reserved-keyword-of-mysql-mode.md)を参照してください。

## テーブルグループ作成の推奨事項

* テーブルグループ名は簡潔で説明的であり、その用途や内容を明確に反映させることが推奨されます。これにより、後続の管理とメンテナンスが容易になります。例えば、テーブルグループの命名には、ビジネス要件、機能モジュール、データタイプなどの要素を考慮し、注文テーブルグループ、ユーザーテーブルグループ、商品テーブルグループをそれぞれ`order_tablegroup`、`user_tablegroup`、`product_tablegroup`として命名することができます。
* テーブルグループを作成する前に、ビジネス要件、データ関係、クエリパターンなどの要素を考慮し、テーブルをグループ化する必要があるかどうかを決定するための良好な計画と設計を行うことを推奨します。
* テーブル間の関連性とクエリ頻度に基づき、関連するテーブルを同一のテーブルグループ内に配置することで、クエリ効率とデータの可用性を向上させることが推奨されます。
* テーブルグループの権限を適切に付与・管理し、権限を付与されたユーザーのみがテーブルグループに対して操作できるようにすることで、データの安全性と整合性を維持することが推奨されます。

## コマンドラインを使用したテーブルグループの作成

[CREATE TABLEGROUP](../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2700.create-tablegroup-of-mysql-mode.md) ステートメントを使用してテーブルグループを作成してください。

`CREATE TABLEGROUP` ステートメントの形式は次のとおりです：

```sql
CREATE TABLEGROUP tablegroup_name [tablegroup_option];
```

**パラメータの説明：**

* `tablegroup_name`：テーブルグループ名。
* `tablegroup_option`：テーブルグループの `SHARDING` プロパティ。オプションです。`SHARDING` プロパティを指定しない場合、デフォルトで `ADAPTIVE` のテーブルグループが作成されます。テーブルグループの `SHARDING` プロパティの値は以下のとおりです：

  * `NONE`：テーブルグループに追加されるテーブルには制限はありません。
  * `PARTITION`：テーブルグループに追加されるテーブルに対応するパーティションは、テーブルグループ内のすべてのテーブルのパーティション方式（パーティションタイプ、パーティション数、パーティション値）と一致する必要があります。
  * `ADAPTIVE`：`SHARDING` を指定しない場合、デフォルト値です。テーブルグループに追加されるテーブルに対応するパーティションとサブパーティションは、テーブルグループ内のすべてのテーブルのパーティションとサブパーティション方式（パーティションタイプ、パーティション数、パーティション値）と一致する必要があります。

  パーティションの詳細については、[パーティションの概要](../../../700.reference/300.database-object-management/100.manage-object-of-mysql-mode/300.manage-partitions-of-mysql-mode/100.partition-overview-of-mysql-mode.md)を参照してください。

## 例

### 例1：SHARDINGプロパティを指定しないテーブルグループを作成する

1. `SHARDING` プロパティを指定せずに、`test_tbl_tg1` という名前のテーブルグループを作成します。

    ```sql
    CREATE TABLEGROUP test_tbl_tg1;
    ```

2. 次のSQLステートメントを使用して、Hash + Rangeパーティションのコンポジットパーティションテーブル `test_tbl1_hr` を作成し、`TABLEGROUP` を `test_tbl_tg1` と指定します。

    ```sql
    CREATE TABLE test_tbl1_hr(col1 INT,col2 INT) TABLEGROUP = test_tbl_tg1
    PARTITION BY HASH(col1)
        SUBPARTITION BY RANGE(col2)
        SUBPARTITION TEMPLATE
        (SUBPARTITION p0 VALUES LESS THAN(100),
        SUBPARTITION p1 VALUES LESS THAN(200),
        SUBPARTITION p2 VALUES LESS THAN(300)
        )
    PARTITIONS 10;
    ```

3. 次のSQLステートメントを使用して、パーティション化されていないテーブル `test_tbl1` を作成し、`TABLEGROUP` を `test_tbl_tg1` と指定するとエラーが表示されます。

    ```sql
    CREATE TABLE test_tbl1 (col INT,col2 INT) TABLEGROUP = test_tbl_tg1;
    ```

    実行結果は次のとおりです：

    ```shell
    ERROR 4179 (HY000): not all tables are non-partitioned or partitioned, add table to tablegroup not allowed
    ```

4. 次のSQLステートメントを使用して、Hashパーティションのパーティションテーブル `test_tbl1_h` を作成し、`TABLEGROUP` を `test_tbl_tg1` と指定するとエラーが表示されます。

    ```sql
    CREATE TABLE test_tbl1_h(col1 INT,col2 INT) TABLEGROUP = test_tbl_tg1
      PARTITION BY HASH(col1) PARTITIONS 10;
    ```

    実行結果は次のとおりです：

    ```shell
    ERROR 4179 (HY000): part level is not equal, add table to tablegroup not allowed
    ```

5. 次のSQLステートメントを使用して、テーブルグループ `test_tbl_tg1` 内にどのようなテーブルがあるか確認します。

    ```sql
    SELECT * FROM oceanbase.DBA_OB_TABLEGROUP_TABLES WHERE tablegroup_name = 'test_tbl_tg1';
    ```

    実行結果は次のとおりです：

    ```shell
    +-----------------+-------+--------------+----------+
    | TABLEGROUP_NAME | OWNER | TABLE_NAME   | SHARDING |
    +-----------------+-------+--------------+----------+
    | test_tbl_tg1    | test  | test_tbl1_hr | ADAPTIVE |
    +-----------------+-------+--------------+----------+
    1 row in set
    ```

### 例2：SHARDINGプロパティを指定してテーブルグループを作成する

#### SHARDINGプロパティをNONEに指定したテーブルグループの作成

1. 次のSQLステートメントを使用して、`SHARDING` プロパティを `NONE` に指定したテーブルグループ `test_tbl_tg2` を作成します。

    ```sql
    CREATE TABLEGROUP test_tbl_tg2 SHARDING = 'NONE';
    ```

2. 次のSQLステートメントを使用して、パーティション化されていないテーブル `test_tbl2` を作成し、`TABLEGROUP` を `test_tbl_tg2` と指定します。

    ```sql
    CREATE TABLE test_tbl2 (col INT) TABLEGROUP = test_tbl_tg2;
    ```

3. 次のSQLステートメントを使用して、パーティション化されたテーブル `test_tbl2_h` を作成し、`TABLEGROUP` を `test_tbl_tg2` と指定します。

    ```sql
    CREATE TABLE test_tbl2_h(col1 INT,col2 VARCHAR(50)) TABLEGROUP = test_tbl_tg2
      PARTITION BY HASH(col1) PARTITIONS 10;
    ```

#### SHARDINGプロパティをPARTITIONに指定したテーブルグループの作成

1. 次のSQLステートメントを使用して、`SHARDING` プロパティを `PARTITION` に指定したテーブルグループ `test_tbl_tg3` を作成します。

    ```sql
    CREATE TABLEGROUP test_tbl_tg3 SHARDING = 'PARTITION';
    ```

2. 次のSQLステートメントを使用して、ハッシュパーティションの一級パーティションテーブル `test_tbl3_h` を作成し、`TABLEGROUP` を `test_tbl_tg3` と指定します。

    ```sql
    CREATE TABLE test_tbl3_h(col1 INT) TABLEGROUP = test_tbl_tg3
      PARTITION BY HASH(col1) PARTITIONS 10;
    ```

3. 次のSQLステートメントを使用して、パーティション化されていないテーブル `test_tbl3` を作成し、`TABLEGROUP` を `test_tbl_tg3` と指定するとエラーが表示されます。

    ```sql
    CREATE TABLE test_tbl3 (col INT) TABLEGROUP = test_tbl_tg3;
    ```

    実行結果は次のとおりです：

    ```shell
    ERROR 4179 (HY000): not all tables are non-partitioned or partitioned, add table to tablegroup not allowed
    ```

4. 次のSQLステートメントを使用して、ハッシュ+レンジパーティションの二次パーティションテーブル `test_tbl3_hr` を作成し、`TABLEGROUP` を `test_tbl_tg3` と指定します。

    ```sql
    CREATE TABLE test_tbl3_hr(col1 INT,col2 INT) TABLEGROUP = test_tbl_tg3
    PARTITION BY HASH(col1)
        SUBPARTITION BY RANGE(col2)
        SUBPARTITION TEMPLATE
        (SUBPARTITION p0 VALUES LESS THAN(100),
        SUBPARTITION p1 VALUES LESS THAN(200),
        SUBPARTITION p2 VALUES LESS THAN(300)
        )
    PARTITIONS 10;
    ```
