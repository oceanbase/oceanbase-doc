# JDBC設定例

本記事では、JDBC設定例を紹介します。JDBCはJavaデータベース接続用インターフェースです。OceanBaseはJDBCドライバーを提供しており、JavaアプリケーションからOceanBaseデータベースへの接続をサポートしています。JDBCドライバーのダウンロードURLは：[OceanBase JDBCドライバー](https://en.oceanbase.com/softwarecenter)。

JDBCを使用してデータベースに接続する際は、データベース使用のパフォーマンスを最大限にするために、関連するパラメーターを設定する必要があります。ここでは、いくつか関連するパラメーターの設定をご紹介します。

JDBC接続の例：

```java
conn=jdbc:oceanbase://xxx.xxx.xxx.xxx:2881/test?rewriteBatchedStatements=TRUE&allowMultiQueries=TRUE&useLocalSessionState=TRUE&useUnicode=TRUE&characterEncoding=utf-8&socketTimeout=10000&connectTimeout=30000
```

この接続では、関係する設定パラメーターは以下のとおりです：

* `rewriteBatchedStatements`：TRUEに設定することが推奨されます。

  * OceanBaseのJDBCドライバーは、デフォルトではexecuteBatch()ステートメントを無視し、一括で実行される一連のSQLステートメントを分割して、1つずつデータベースに送信します。この場合、一括挿入は実際には単一挿入となり、直接的にパフォーマンスの低下につながります。一括挿入を実際に実行するには、このパラメーターをTRUEに設定する必要があります。これにより、ドライバーはSQLを一括処理で実行します。つまり、addBatchメソッドを使用して、同一テーブル上の複数のinsertステートメントを結合し、1つのinsertステートメント内の複数のvalues値の形式にすることで、batch insertのパフォーマンスを向上させます。

  * 必ずprepareStatementメソッドを使用して、各insertをprepareしてから、addBatchを実行する必要があります。そうしないと、統合実行がされません。

* `allowMultiQueries`：TRUEに設定することが推奨されます。

  JDBCドライバーは、アプリケーションコードが複数のSQLをセミコロン（;）で連結して、1つのSQLとしてserverに送信することを許可しています。

* `useLocalSessionState`：トランザクションが頻繁的にOBデータベースにsession変数クエリSQLを送信するのを回避するには、TRUEに設定することが推奨されます。

  session変数は主に：autocommit、read_only、およびtransaction isolation。

* `socketTimeout`：SQL実行時に、socketがSQLの応答を待機する時間。

* `connectTimeout`：接続確立時に、接続を待機する時間。

* `useCursorFetch`：`TRUE` に設定することが推奨されます。

  大規模なデータ量のクエリステートメントに対して、データベースServerはCursorを作成し、FetchSizeのサイズに応じてデータをClientに配布します。このプロパティを `TRUE` に設定すると、自動的に `useServerPrepStms=TRUE` も設定されます。

* `useServerPrepStms`：SQLをデータベースserverに送信するためにPSプロトコルを使用するかどうかを制御します。

  `TRUE` に設定されている場合、SQLはデータベース内で2つのステップで実行されます：

  * `？` を含むSQL文をデータベースServerに送信してPrepareします（`SQL_audit: request_type=5`）。

  * データベース内で実際のValueを使用してExecute（`SQL_audit: request_type=6`）。

* `cachePrepStmts`：JDBC driverがPreparedStatmentをキャッシュするためにPS cacheを有効にするかどうかを制御し、prepareの重複実行（client側とserver側）を回避します。`cachePrepStmts=TRUE` は、`useServerPrepStms=TRUE` を使用して同一のSQLをbatch executeシナリオに有効です。各batch excecuteには、prepareと `executecachePrepStmts=TRUE` が含まれ、重複するprepare操作を回避できます。

* `prepStmtCacheSQLLimit`：PS cacheに格納可能なSQLの長さには制限があり、長すぎるSQLはキャッシュに格納できません。prepStmtCacheSize：PS cacheに保存できるSQLの数。

* `maxBatchTotalParamsNum`：batch操作において、1つのSQLが最大、サポートできるパラメーターの数（つまり、batch 内の `?` の数）。パラメーター数が制限を超えた場合、batch SQLは分割されます。
