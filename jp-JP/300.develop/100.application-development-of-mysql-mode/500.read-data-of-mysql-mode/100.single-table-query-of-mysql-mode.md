# 単一テーブルクエリ

単一テーブルクエリでは、複数のテーブル間の関係には触れず、1つのテーブルのみが対象となります。単一テーブルクエリを通じて、データの検索、フィルタリング、ソートなどの操作を実現できます。

本記事では、`SELECT` ステートメントを使用してOceanBaseデータベースのMySQLモードにおける単一テーブルクエリを実行する方法について説明します。

## 単一テーブルクエリ構文

単一テーブルクエリの構文は以下のとおりです：

```sql
SELECT [ALL | DISTINCT] select_list FROM table_name
              [ WHERE query_condition ]
              [ GROUP BY group_by_expression ]
              [ HAVING group_condition ]
              [ ORDER BY column_list ][ASC | DESC]
              [ LIMIT limit_clause ]

column_list：
 column_name[,column_name...]
```

クエリステートメントの詳細な使用方法については、[SELECT](../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/8100.select-of-mysql-mode/100.select-of-mysql-mode.md)を参照してください。

`WHERE`、`GROUP BY`、`HAVING`、`ORDER BY`、`LIMIT` これらのキーワードを一緒に使用する場合、その順序には明確な制限があります。キーワードの実行順序は以下のとおりです：

1. `FROM` を実行してテーブルを見つけます。

2. `WHERE` を実行して制約条件を指定します。

3. `GROUP BY` を実行して取得した各レコードをグループ化（集計）します。`GROUP BY` がない場合は、全体が1つのグループとなります。

4. `HAVING` を実行して、グループ化された結果をフィルタリングします。

5. `SELECT` を実行します。

6. `DISTINCT` を実行して重複を削除します。

7. `ORDER BY` を実行して、条件に基づいて結果を昇順または降順でソートします。

8. `LIMIT` を実行して、結果の件数を制限します。

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p><code>WHERE</code> と <code>HAVING</code> の違いは、<code>WHERE</code> はグループ化前にデータをフィルタリングし、<code>HAVING</code> はグループ化後の結果からフィルタリングを行い、最終的にSQL全体のクエリ結果を返すことです。</p>
  </main>

```shell
|  2 | William   |      1 |  21 |  90.5 | 2021-09-02      |

|  4 | James     |      1 |  20 |  87.5 | 2021-09-03      |
|  5 | Sophia    |      0 |  20 |  91.5 | 2021-09-05      |
|  6 | Benjamin  |      1 |  21 |  96.5 | 2021-09-01      |
|  7 | Ava       |      0 |  22 |  89.5 | 2021-09-06      |
|  8 | Michael   |      1 |  18 |  93.5 | 2021-09-08      |
|  9 | Charlotte |      1 |  19 |    88 | 2021-09-06      |
| 10 | Ethan     |      1 |  20 |    92 | 2021-09-01      |
+----+-----------+--------+-----+-------+-----------------+
```

### SELECT基本クエリ

#### すべての列を照会する

* `SELECT * FROM student;` ステートメントを使用して、すべての学生情報を照会できます。

* すべてのフィールドを手動でリストアップし、`SELECT id,name,gender,age,score,enrollment_date FROM student;` ステートメントを使用して、すべての学生情報を照会することもできます。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p><code>*</code> を使用するとすべてのフィールドを迅速にリストアップできますが、すべてのフィールドを手動でリストアップする方が、クエリのパフォーマンスやコードの可読性、保守性の面でより優れています。</p>
</main>

例1：以下のSQLステートメントを使用して、テーブル `student` のすべての行のデータを照会し、各行の `id`、`name`、`gender`、`age`、`score`、`enrollment_date` 列のデータを返します。

```sql
SELECT id,name,gender,age,score,enrollment_date FROM student;
```

実行結果は次のとおりです：

```shell
|  4 | James     |      1 |  20 |  87.5 | 2021-09-03      |
|  5 | Sophia    |      0 |  20 |  91.5 | 2021-09-05      |
|  6 | Benjamin  |      1 |  21 |  96.5 | 2021-09-01      |
|  7 | Ava       |      0 |  22 |  89.5 | 2021-09-06      |
|  8 | Michael   |      1 |  18 |  93.5 | 2021-09-08      |

| 10 | Ethan     |      1 |  20 |    92 | 2021-09-01      |
```

#### 指定された列を照会する

テーブル内で列名に基づいて指定された列データを検索します。

例2：以下のSQLステートメントを使用して、テーブル `student` のすべての行のデータを照会し、各行の `id` と `name` 列のデータを返します。

```sql
SELECT id,name FROM student;
```

実行結果は次のとおりです：

```shell
+----+-----------+
| id | name      |
+----+-----------+
|  1 | Emma      |
|  2 | William   |
|  3 | Olivia    |
|  4 | James     |
|  5 | Sophia    |
|  6 | Benjamin  |
|  7 | Ava       |
|  8 | Michael   |
|  9 | Charlotte |
| 10 | Ethan     |
+----+-----------+
10 rows in set
```

#### 計算された値のクエリ

クエリ内で指定された列に対してデータ処理を実行できます。

例3：次のSQLステートメントを使用して、テーブル `student` のすべての行の `id`、`name`、および `age` 列のデータを照会し、各行の `age` 列の値に `1` を加算します。実行結果には `id`、`name`、および `age+1` の3つの列が含まれます。

```sql
SELECT id,name,age+1 FROM student;
```

指定された列に対するデータ処理のその他のクエリ方法については、**クエリ内での演算子と関数の使用**を参照してください。

### 条件クエリ

特定の条件を満たすデータを照会する場合は、`SELECT` クエリステートメントに `WHERE` 句を追加することで実現できます。

キーワード `WHERE` の後ろには、1つまたは複数の条件を指定できます。条件とは、前のデータをフィルタリングするものであり、`WHERE` の条件を満たすデータのみが返されます。

`WHERE` 句でよく使用されるクエリ条件は以下の表のとおりです。

|   クエリ条件タイプ   |                     述語           |
|------------|---------------------------------------------|
| 比較クエリ       | `=`、`>`、`<`、`>=`、`<=`、`!=`、`<>` |
| 論理クエリ（複数条件） | `AND`、`OR`、`NOT`  |
| あいまいクエリ（文字列マッチング） | `LIKE`、`NOT LIKE`               |
| 区間クエリ（範囲指定） | `BETWEEN AND`、`NOT BETWEEN AND` |
| 指定集合クエリ     | `IN`、`NOT IN`                   |
| NULL値クエリ   | `IS NULL`、`IS NOT NULL`         |

クエリ条件の詳細については、[比較演算子](../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/200.operator-of-mysql-mode/500.comparison-operators-of-mysql-mode.md)を参照してください。

#### 比較条件クエリ

比較条件クエリ演算子には、`=`、`>`、`<`、`>=`、`<=`、`!=`、`<>` が含まれます。

* 等しい（`=`）：指定された列の値がターゲット値と等しいデータを照会します。値が文字列型の場合は、シングルクォートまたはダブルクォートで囲む必要があります。

    例4：以下のSQLステートメントを使用して、テーブル `student` 内の `gender` 列が `1` と等しいすべての行を照会し、これらの行の `id`、`name`、`gender` 列のデータを返します。

    ```sql
    SELECT id,name,gender FROM student WHERE gender = 1;
    ```

    実行結果は次のとおりです：

    ```shell
    +----+-----------+--------+
    | id | name      | gender |
    +----+-----------+--------+
    |  2 | William   |      1 |
    |  4 | James     |      1 |
    |  6 | Benjamin  |      1 |
    |  8 | Michael   |      1 |
    |  9 | Charlotte |      1 |
    | 10 | Ethan     |      1 |
    +----+-----------+--------+
    6 rows in set
    ```

* 等しくない（`<>` および `!=`）：不等号には `<>` と `!=` の2種類の書き方が含まれます。

    例5：以下のSQLステートメントを使用して、テーブル `student` 内の `gender` 列が `1` と等しくないすべての行を照会し、これらの行の `id`、`name`、`gender` 列のデータを返します。

    ```sql
    SELECT id,name,gender FROM student WHERE gender <> 1;
    ```

    実行結果は次のとおりです：

    ```shell
    +----+--------+--------+
    | id | name   | gender |
    +----+--------+--------+
    |  1 | Emma   |      0 |
    |  3 | Olivia |      0 |
    |  5 | Sophia |      0 |
    |  7 | Ava    |      0 |
    +----+--------+--------+
    4 rows in set
    ```

* より大きい（`>`）とより小さい（`<`）：より大きい（`>`）とより小さい（`<`）は数値を大きさで比較します。比較するのが文字の場合は、ASCIIコードに対応する値で比較し、比較時には文字が対応する位置ごとに順番に比較します。

    <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>以上と同様に、より大きいか等しい（\>=）とより小さいか等しい（\<=）も使用します。 </p>
    </main>

    例6：以下のSQLステートメントを使用して、テーブル `student` 内の `score` 列が `90` より小さいすべての行を照会し、これらの行の `id`、`name`、`score` 列のデータを返します。

    ```sql
    SELECT id,name,score FROM student WHERE score < 90;
    ```

    実行結果は次のとおりです：

    ```shell
    +----+-----------+-------+
    | id | name      | score |
    +----+-----------+-------+
    |  1 | Emma      |    85 |
    |  4 | James     |  87.5 |
    |  7 | Ava       |  89.5 |
    |  9 | Charlotte |    88 |
    +----+-----------+-------+
    4 rows in set
    ```

#### 論理条件クエリ

論理クエリ演算子の「かつ」（`AND`）と「または」（`OR`）は、複数の条件を含むクエリをサポートします。

* かつ（`AND`）：`AND` の両方の条件を満たすデータを返します。

    例7：以下のSQLステートメントを使用して、テーブル `student` 内で `gender` が `1` に等しく、かつ `score` が `90` 以下のすべての行を照会し、これらの行の `id`、`name`、`gender`、および `score` 列のデータを返します。

    ```sql
    SELECT id,name,gender,score FROM student WHERE gender = 1 AND score <= 90;
    ```

    実行結果は次のとおりです：

    ```shell
    +----+-----------+--------+-------+
    | id | name      | gender | score |
    +----+-----------+--------+-------+
    |  4 | James     |      1 |  87.5 |
    |  9 | Charlotte |      1 |    88 |
    +----+-----------+--------+-------+
    2 rows in set
    ```

* または（OR）：いずれか一方の条件を満たすデータはすべて返されます。

    例8：以下のSQLステートメントを使用して、テーブル `student` 内で `gender` が `1` に等しいか、`score` が `90` 未満のすべての行を照会し、これらの行の `id`、`name`、`gender`、および `score` 列のデータを返します。

    ```sql
    SELECT id,name,gender,score FROM student WHERE gender = 1 OR score < 90;
    ```

    実行結果は次のとおりです：

    ```shell
    +----+-----------+--------+-------+
    | id | name      | gender | score |
    +----+-----------+--------+-------+
    |  1 | Emma      |      0 |    85 |
    |  2 | William   |      1 |  90.5 |
    |  4 | James     |      1 |  87.5 |
    |  6 | Benjamin  |      1 |  96.5 |
    |  7 | Ava       |      0 |  89.5 |
    |  8 | Michael   |      1 |  93.5 |
    |  9 | Charlotte |      1 |    88 |
    | 10 | Ethan     |      1 |    92 |
    +----+-----------+--------+-------+
    8 rows in set
    ```

#### あいまいクエリ（LIKE）

述語 `LIKE` は文字列のマッチングに使用できます。

構文の意味は、対応する列の値が `pattern` とマッチするデータを検索することです。`pattern` は完全な文字列であることも、ワイルドカード `%` および `_` を含むこともできます。その中で：

* アンダースコア（_）は任意の1文字にマッチします。

* パーセント記号（%）は、値内の0文字以上の任意の文字列にマッチします。パターン「%」は `NULL` とマッチしません。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>データベースの文字セットがASCIIの場合、1つの漢字には2つの <code>_</code> が必要です。文字セットがGBKの場合は、1つの <code>_</code> だけが必要です。</p>
</main>

例9：以下のSQLステートメントを使用して、テーブル `student` 内の `name` に `am` が含まれるすべての行を照会し、これらの行の `id` と `name` 列のデータを返します。

```sql
SELECT id,name FROM student WHERE name LIKE '%am%';
```

実行結果は次のとおりです：

```shell
+----+----------+
| id | name     |
+----+----------+
|  2 | William  |
|  4 | James    |
|  6 | Benjamin |
+----+----------+
3 rows in set
```

#### 区間クエリ（BETWEEN AND）

演算子 `BETWEEN ... AND` は、2つの値の間にあるデータを選択します。これらの値は数値、テキスト、または日付にすることができます。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>区間クエリの2つの境界値の順序を入れ替えないでください。左側の値より大きく、かつ右側の値以下でなければなりません。</p>
</main>

例10：以下のSQLステートメントを使用して、テーブル `student` 内の `score` 値が `85 ~ 90` の範囲にあるすべての行を照会し、これらの行の `id`、`name`、`score` 列のデータを返します。

```sql
SELECT id,name,score FROM student WHERE score BETWEEN 85 AND 90;
```

実行結果は次のとおりです：

```shell
+----+-----------+-------+
| id | name      | score |
+----+-----------+-------+
|  1 | Emma      |    85 |
|  4 | James     |  87.5 |
|  7 | Ava       |  89.5 |
|  9 | Charlotte |    88 |
+----+-----------+-------+
4 rows in set
```

#### 指定集合クエリ（IN）

演算子 `IN` は、`WHERE` 句で指定された複数の値を集合と呼びます。`IN` は、指定された列のデータが集合内のいずれかの値と一致すれば、そのデータが返されることを意味します。`NOT IN` は、集合内のいずれの値とも一致しないデータが返されることを意味します。

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <ul>
    <li><code>[NOT] IN</code> 集合内の値の型は一致しているか、互換性がある必要があります。</li>
    <li><code>[NOT] IN</code> 集合内の値はワイルドカードをサポートしていません。</li>
    </ul>
  </main>

例11：以下のSQLステートメントを使用して、テーブル `student` 内の `id` 値が集合 `(1, 3, 5, 7)` に含まれるすべての行を照会し、これらの行の `id` と `name` 列のデータを返します。

```sql
SELECT id,name FROM student WHERE id IN (1,3,5,7);
```

実行結果は次のとおりです：

```shell
+----+--------+
| id | name   |
+----+--------+
|  1 | Emma   |
|  3 | Olivia |
|  5 | Sophia |
|  7 | Ava    |
+----+--------+
4 rows in set
```

#### NULL値専用クエリ

比較演算子、`LIKE`、`BETWEEN AND`、`IN`、`NOT IN` は `NULL` 値に対するクエリ結果が正確ではないため、`NULL` 値専用のクエリステートメントである `IS NULL` と `IS NOT NULL` の使用を推奨します。さらに、セキュアイコール（`<=>`）も使用でき、通常の数値だけでなく `NULL` 値も判断できます。

* `IS NULL`：指定された列の値が `NULL` であるデータを照会します。

    例12：以下のSQLステートメントを使用して、テーブル `student` 内の `score` が空のすべての行を照会し、これらの行の `id`、`name`、`score` 列のデータを返します。

    ```sql
    SELECT id,name,score FROM student WHERE score IS NULL;
    ```

    実行結果は次のとおりです：

    ```shell
    Empty set
    ```

* `IS NOT NULL`：指定された列の値が `NULL` 以外のデータを照会します。

    例13：以下のSQLステートメントを使用して、テーブル `student` 内の `score` が空でないすべての行を照会し、これらの行の `id`、`name`、`score` 列のデータを返します。

    ```sql
    SELECT id,name,score FROM student WHERE score IS NOT NULL;
    ```

    実行結果は次のとおりです：

    ```shell
    +----+-----------+-------+
    | id | name      | score |
    +----+-----------+-------+
    |  1 | Emma      |    85 |
    |  2 | William   |  90.5 |
    |  3 | Olivia    |  95.5 |
    |  4 | James     |  87.5 |
    |  5 | Sophia    |  91.5 |
    |  6 | Benjamin  |  96.5 |
    |  7 | Ava       |  89.5 |
    |  8 | Michael   |  93.5 |
    |  9 | Charlotte |    88 |
    | 10 | Ethan     |    92 |
    +----+-----------+-------+
    10 rows in set
    ```

### グループ化クエリ

`GROUP BY` 句は、クエリ結果をグループ化するために使用されます。

`GROUP BY` は単一フィールドのグループ化と複数フィールドのグループ化をサポートしており、`WHERE` 句を使用してグループ化前にデータをフィルタリングしたり、`HAVING` 句を使用してグループ化後にデータをフィルタリングしたり、`ORDER BY` 句を使用してグループ化後にデータをソートしたりできます。

グループ化でよく使用される集計関数は以下の表のとおりです。

| 集計関数   |      機能      |
|---------|--------------|
| MAX()   | 指定された列の最大値を照会します。   |
| MIN()   | 指定された列の最小値を照会します。   |
| COUNT() | クエリ結果の行数を統計的に集計します。   |
| SUM()   | 指定された列の合計を返します。    |
| AVG()   | 指定された列データの平均値を返します。 |

#### グループ化クエリの例

既存のサンプルテーブル `fruit_order` は、以下のデータを含みます：

```shell
+----------+---------+-----------+-------------+------------+
| order_id | user_id | user_name | fruit_price | order_year |
+----------+---------+-----------+-------------+------------+
|        1 |    1011 | A1        |       13.11 |       2019 |
|        2 |    1022 | B2        |       23.34 |       2019 |
|        3 |    1022 | B2        |       12.22 |       2019 |
|        4 |    1011 | A1        |       22.21 |       2020 |
|        5 |    1033 | C3        |       51.55 |       2020 |
|        6 |    1011 | A1        |       58.83 |       2020 |
|        7 |    1022 | B2        |       14.66 |       2021 |
|        8 |    1022 | B2        |       34.44 |       2021 |
|        9 |    1033 | C3        |       63.66 |       2021 |
+----------+---------+-----------+-------------+------------+
```

* 単一フィールドによるグループ化クエリ。

    例14：各顧客の注文数を照会し、`user_id` と `COUNT(order_id)` を出力します。

    ```sql
    SELECT user_id, COUNT(order_id) FROM fruit_order GROUP BY user_id;
    ```

    実行結果は次のとおりです：

    ```shell
    +---------+-----------------+
    | user_id | COUNT(order_id) |
    +---------+-----------------+
    |    1011 |               3 |
    |    1022 |               4 |
    |    1033 |               2 |
    +---------+-----------------+
    3 rows in set
    ```

* 複数フィールドによるグループ化クエリ。

    例15：各顧客の年間注文数を照会し、`user_id`、`order_year` と `COUNT(order_id)` を出力します。

    ```sql
    SELECT user_id,order_year, COUNT(order_id) FROM fruit_order GROUP BY user_id,order_year;
    ```

    実行結果は次のとおりです：

    ```shell
    +---------+------------+-----------------+
    | user_id | order_year | COUNT(order_id) |
    +---------+------------+-----------------+
    |    1011 |       2019 |               1 |
    |    1022 |       2019 |               2 |
    |    1011 |       2020 |               2 |
    |    1033 |       2020 |               1 |
    |    1022 |       2021 |               2 |
    |    1033 |       2021 |               1 |
    +---------+------------+-----------------+
    6 rows in set
    ```

* グループ化前のフィルタリング。

    例16：2020年の各顧客の注文数を照会し、`user_id` と `COUNT(order_id)` を出力します。

    ```sql
    SELECT user_id, COUNT(order_id) FROM fruit_order t WHERE t.order_year = 2020 GROUP BY user_id;
    ```

    実行結果は次のとおりです：

    ```shell
    +---------+-----------------+
    | user_id | COUNT(order_id) |
    +---------+-----------------+
    |    1011 |               2 |
    |    1033 |               1 |
    +---------+-----------------+
    2 rows in set
    ```

* グループ化後のフィルタリング。

    例17：2019年の注文数が1より大きい顧客を照会し、`user_id` と `COUNT(order_id)` を出力します。

    ```sql
    SELECT user_id, COUNT(order_id) FROM fruit_order t WHERE t.order_year = 2019 GROUP BY user_id HAVING COUNT(order_id)>=2;
    ```

    <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>クエリに <code>HAVING</code> が含まれている場合、まず <code>HAVING</code> 句を含まない場合のSQLクエリ結果を取得し、その結果に基づいて <code>HAVING</code> 条件を使用して一致するデータをフィルタリングし、最後にこれらのデータを返します。このため、<code>HAVING</code> の後ろに集計関数を使用でき、この集計関数は <code>SELECT</code> の後ろの集計関数と同じである必要はありません。 </p>
    </main>

    実行結果は次のとおりです：

    ```shell
    +---------+-----------------+
    | user_id | COUNT(order_id) |
    +---------+-----------------+
    |    1022 |               2 |
    +---------+-----------------+
    1 row in set
    ```

* グループ化後のソート。

    例18：各顧客の注文の最大金額を照会し、その後最大金額を降順で `user_id` と `MAX(fruit_price)` を出力します。

    ```sql
    SELECT user_id, MAX(fruit_price) FROM fruit_order t GROUP BY user_id ORDER BY MAX(fruit_price) DESC;
    ```

    実行結果は次のとおりです：

    ```shell
    +---------+------------------+
    | user_id | MAX(fruit_price) |
    +---------+------------------+
    |    1033 |            63.66 |
    |    1011 |            58.83 |
    |    1022 |            34.44 |
    +---------+------------------+
    3 rows in set
    ```

### ソートクエリ

`ORDER BY` 句は、クエリ結果を1つまたは複数のプロパティ列に基づいて昇順（`ASC`）または降順（`DESC`）で並べ替えるために使用されます。デフォルトは昇順です。

`ORDER BY` は単一フィールドのソート、複数フィールドのソート、エイリアスによるソート、関数によるソートをサポートしており、複数フィールドのソートはカンマで区切られます。

ソートクエリを実行する際、`ASC` または `DESC` キーワードを追加しない場合、デフォルトでクエリ結果は昇順に並べ替えられます。

テーブル `student` 内で、`score` の値が `85 ~ 90` のデータを照会します。

    ```sql
    SELECT id,name,score FROM student ORDER BY score;
    ```

### クエリ結果の件数を制限する

`LIMIT` ステートメントは、`SELECT` クエリが返す行数を制限でき、ページネーション操作によく使用されます。

クエリに `LIMIT` を含むSQLステートメントの書式は以下のとおりです：

```sql
LIMIT [offset,] count_num
```

説明は以下のとおりです：

* `offset` はオフセット量を表し、いくつの行をスキップするかを示します。`offset` は省略可能で、デフォルトは0であり、0行をスキップすることを意味します。`offset` の値の範囲は \[0,+∞) です。

* `count_num` は、`offset` 行をスキップした後からデータを取得し始め、`count_num` 行のレコードを取得することを示します。`count_num` の値の範囲は \[0,+∞) です。

* `offset` と `count_num` の値には式を使用できず、明示的な数字のみを続けることができます。

* `LIMIT` の後ろの数字は負の数にすることはできません。

#### LIMIT n, m を使用したクエリ

* 最初の m 行のレコードを取得します。

    例23：テーブル `student` 内の列 `id`、`name` の最初の 5 件のデータを照会します。

    ```sql
    SELECT id,name FROM student LIMIT 5;
    ```

    実行結果は次のとおりです：

    ```shell
    +----+---------+
    | id | name    |
    +----+---------+
    |  1 | Emma    |
    |  2 | William |
    |  3 | Olivia  |
    |  4 | James   |
    |  5 | Sophia  |
    +----+---------+
    5 rows in set
    ```

* n 行のレコードをスキップした後の m 行のレコードを取得します。

    <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>n 行のレコードをスキップした後、残りのデータの行数が m より小さい場合、クエリ結果は残りのすべてのデータになります。</p>
    </main>

    例23：テーブル `student` 内の列 `id`、`name` の 3 番目の行以降の 3 行のデータを照会します。

    ```sql
    SELECT id,name FROM student LIMIT 3,3;
    ```

    実行結果は次のとおりです：

    ```shell
    +----+----------+
    | id | name     |
    +----+----------+
    |  4 | James    |
    |  5 | Sophia   |
    |  6 | Benjamin |
    +----+----------+
    3 rows in set
    ```

* 最大値のレコードを取得します。

    例24：テーブル `student` 内で `score` の最大値のレコードを取得するには、まず `score` で降順にソートしてから、最初の 1 件のレコードを取得します。

    ```sql
    SELECT id,name,score FROM student ORDER BY score DESC LIMIT 1;
    ```

    実行結果は次のとおりです：

    ```shell
    +----+----------+-------+
    | id | name     | score |
    +----+----------+-------+
    |  6 | Benjamin |  96.5 |
    +----+----------+-------+
    1 row in set
    ```

#### ページネーションクエリ

`LIMIT` はページネーションクエリのロジックに従って使用することもできます。

SQLステートメントの形式は以下のとおりです：

```sql
LIMIT (page_no - 1) * page_size, page_size;
```

構文のパラメータの説明は以下のとおりです：

* `page_no` はページ番号を表し、1から始まり、範囲は \[1,+∞) です。

* `page_size` は1ページあたりに表示されるレコード数を表し、範囲は \[1,+∞) です。例えば、page_no = 5、page_size = 10 の場合、5ページ目の10件のデータを取得することを意味します。

例25：テーブル `student` 内で、各ページに2件のデータを表示し、1ページ目、2ページ目、3ページ目のデータを順次取得します。

1ページ目：

```sql
SELECT id,name FROM student ORDER BY id LIMIT 0,2;
```

実行結果は次のとおりです：

```shell
+----+---------+
| id | name    |
+----+---------+
|  1 | Emma    |
|  2 | William |
+----+---------+
2 rows in set
```

2ページ目：

```sql
SELECT id,name FROM student ORDER BY id LIMIT 2,2;
```

実行結果は次のとおりです：

```shell
+----+--------+
| id | name   |
+----+--------+
|  3 | Olivia |
|  4 | James  |
+----+--------+
2 rows in set
```

3ページ目：

```sql
SELECT id,name FROM student ORDER BY id LIMIT 4,2;
```

実行結果は次のとおりです：

```shell
+----+----------+
| id | name     |
+----+----------+
|  5 | Sophia   |
|  6 | Benjamin |
+----+----------+
2 rows in set
```
