# ラテラル派生テーブル

本記事では、ラテラル派生テーブル（Lateral Derived Table）の基本概念、使用制限、および関連する例を紹介します。

## ラテラル派生テーブルの概要

派生テーブル（Derived Table）とは、`FROM` 句内で使用されるサブクエリであり、その結果セットは一時的に外側のクエリでテーブルとして扱われます。派生テーブルは通常、グループ化や集計処理を行うために使用されたり、特定の条件を満たすデータセットを作成して主クエリでさらに利用するために用いられます。

一方、ラテラル派生テーブル（Lateral Derived Table）は、特別な種類の派生テーブルであり、`LATERAL` キーワードを使用することで、同じ `FROM` 句内で以前に定義された他のテーブルや派生テーブルのフィールドを参照できるようにします。これにより、派生テーブル内のサブクエリは同一の `FROM` 句内で定義されたテーブルに依存し、これらのテーブルのカラム値にアクセスできます。

ラテラル派生テーブルの主な特徴は、それらが `FROM` 句内で先に定義されたテーブルのカラムを参照できることです。これは通常の派生テーブルにはない機能です。

## ラテラル派生テーブル（LATERALキーワード）の使用制限

* `LATERAL` キーワードは `FROM` 句内で使用する必要があります。これは、コンマで区切られたテーブルリスト内に配置されるか、結合式内（例：`JOIN`、`INNER JOIN`、`CROSS JOIN`、`LEFT [OUTER] JOIN`、`RIGHT [OUTER] JOIN`）に配置されることが可能です。
* `LATERAL` が `JOIN` ステートメント内で左側のテーブルのフィールドを参照している場合、許可される結合タイプには `INNER JOIN`、`CROSS JOIN`、および `LEFT [OUTER] JOIN` が含まれます。
* `LATERAL` が `JOIN` ステートメント内で右側のテーブルのフィールドを参照している場合、有効な結合操作は `INNER JOIN`、`CROSS JOIN`、および `RIGHT [OUTER] JOIN` です。
* ラテラル派生テーブル内で集約関数を参照する場合、その集約関数はラテラル派生テーブルを含む `FROM` 句が属する外部クエリに直接依存してはなりません。つまり、ラテラル派生テーブル内部では集約関数を使用して外部クエリの結果を直接参照することはできません。

## LATERALキーワードの使用方法

```sql
SELECT select_list
FROM table_name1,
LATERAL (SELECT select_list
         FROM table_name2
         WHERE table_name2.col_name = table_name1.col_name) AS lateral_derived_table_name;
[...]
```

**パラメータの説明：**

| **パラメータ** | **説明** |
|----------|----------|
| select_list | 検索する列のリストで、列名、式、集計関数などになります。複数の列をカンマで区切ることができます。|
| table_name1 | クエリ対象となる主テーブルです。|
| LATERAL | 横方向に結合されたサブクエリ（横方向に派生したテーブル）を指定するために使用されます。|
| table_name2 | 従属テーブルで、`LATERAL` サブクエリ内で参照され、各行の `table_name1` データに関連する追加情報を提供します。|
| lateral_derived_table_name | 後続のクエリで参照するために使用される従属テーブルの別名です。|
| [...] | オプションのクエリ句、例えば `WHERE` 句などです。|

## 例

### テストテーブルを作成し、テストデータを追加する

1. テーブル `students` を作成します。

    ```sql
    CREATE TABLE students (
      id INT AUTO_INCREMENT PRIMARY KEY,
      name VARCHAR(50) NOT NULL,
      age INT
    );
    ```

2. テーブル `students` に3件のデータを挿入します。

    ```sql
    INSERT INTO students (name, age)
      VALUES ('name1', 20),
      ('name2', 22),
      ('name3', 21);
    ```

3. テーブル `scores` を作成します。

    ```sql
    CREATE TABLE scores (
      id INT AUTO_INCREMENT PRIMARY KEY,
      student_id INT,
      subject VARCHAR(50) NOT NULL,
      score DECIMAL(5, 2),
      FOREIGN KEY (student_id) REFERENCES students(id)
    );
    ```

4. テーブル `scores` に9件のデータを挿入します。

    ```sql
    INSERT INTO scores (student_id, subject, score)
      VALUES (1, 'A', 86.5),
      (1, 'B', 90.0),
      (1, 'C', 91.5),
      (2, 'A', 86.0),
      (2, 'B', 92.0),
      (2, 'C', 89.5),
      (3, 'A', 93.0),
      (3, 'B', 92.5),
      (3, 'C', 85.0);
    ```

### テストデータのクエリ

`students` と `scores` の2つのテーブルから、各生徒の氏名、平均点、および最高点を取得します。

Q1：複数のサブクエリを使用して要件データを取得します。`scores` テーブルに対して2回の独立したグループ化集計操作を行い、`scores` テーブルを2回スキャンして平均点と最高点をそれぞれ計算します。その後、`WHERE` 句を使用して結果を `students` テーブルと結合します。

```sql
SELECT st.name, sc.avg_score, scs.max_score
FROM students st,
  (SELECT student_id, AVG(score) avg_score
   FROM scores
   GROUP BY student_id) sc,
   (SELECT student_id, MAX(score) max_score
   FROM scores
   GROUP BY student_id) scs
WHERE sc.student_id = st.id
AND scs.student_id = st.id;
```

実行結果は次のとおりです：

```shell
+-------+-----------+-----------+
| name  | avg_score | max_score |
+-------+-----------+-----------+
| name1 | 89.333333 |     91.50 |
| name2 | 89.166667 |     92.00 |
| name3 | 90.166667 |     93.00 |
+-------+-----------+-----------+
3 rows in set
```

Q2：`LATERAL` キーワードを使用して要件データを取得します。`LATERAL` キーワード(横方向の派生テーブル)を使用し、1行のSQLステートメントで各生徒の平均点と最高点を同時に計算します。また、各生徒 `ID` に対して `scores` テーブルを1回のみスキャンします。

```sql
SELECT st.name, ld_tbl.avg_score, ld_tbl.max_score
FROM students st,
  LATERAL (SELECT AVG(score) avg_score, MAX(score) max_score
           FROM scores sc
           WHERE sc.student_id = st.id) ld_tbl;
```

実行結果は次のとおりです：

```shell
+-------+-----------+-----------+
| name  | avg_score | max_score |
+-------+-----------+-----------+
| name1 | 89.333333 |     91.50 |
| name2 | 89.166667 |     92.00 |
| name3 | 90.166667 |     93.00 |
+-------+-----------+-----------+
3 rows in set
```

Q2では、Q1に比べて大きなデータセットを処理する場合、`scores` テーブルに対する重複スキャンを回避しているため、パフォーマンスがより高い可能性があります。また、Q2の書き方はより明確でコンパクトであり、理解や保守が容易です。
