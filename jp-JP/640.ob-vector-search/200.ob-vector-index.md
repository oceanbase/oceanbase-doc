# ベクトルインデックスの作成

本記事は、OceanBase におけるベクトルインデックスの作成、クエリ、メンテナンス、削除について紹介します。

OceanBase ベクトルインデックスの具体的な説明については以下のとおりです：

* HNSW インデックスをサポートします：インデックス列の最大次元は 4096 です。HNSW インデックスはメモリインデックスであり、メモリに完全にロードする必要があります。DML とリアルタイムクエリをサポートします。

* HNSW_SQ インデックスをサポートします：HNSW_SQ インデックスは、HNSW インデックスとほぼ同等の構築速度、クエリパフォーマンス、リコール率を提供しますが、総メモリ使用量は元の 1/2 ～ 1/3 に削減され、パフォーマンスとリコール率に高い要求があるシナリオに適しています。

* (実験的機能) IVF インデックスをサポートします：データベースに基づいて実装された IVF インデックスは、常駐メモリを消費せず、パフォーマンス要件がそれほど高くないが、データ量が大きく、コストに敏感なシナリオに適しています。

* インデックス距離アルゴリズムとして、L2、内積 (IP)、コサイン距離をサポートしています。

* フィルタ条件付きベクトルクエリをサポートします。フィルタ条件はスカラータイプの条件でも、空間関係のどちらでも構いません。例えば、ST_Intersects 等でも構いません。多値インデックス / 全文インデックス / グローバルインデックスは、プリフィルターとしてサポートされています。

* 同一テーブルにベクトルインデックスと全文インデックスの作成をサポートします。

## 準備作業

HNSW/HNSW_SQ ベクトルインデックスを使用する前に、[ob_vector_memory_limit_percentage](https://en.oceanbase.com/docs/common-oceanbase-database-10000000001976671) を設定してベクトル機能を有効にする必要があります。IVF/IVF_SQ/IVF_PQ インデックスは常駐メモリを必要としないため、ベクトル機能を有効にするためにこのパラメーターを手動で設定する必要はありません。

```sql
ALTER SYSTEM SET ob_vector_memory_limit_percentage = 30;
```

## インデックスクエリの概要

ベクトルインデックスクエリは、100% の結果の正確性を保証するものではなく、近似最近傍検索の一種です。対応するベクトルクエリの精度指標はリコール率です。例えば、10 個の最近傍を検索する際に、安定して 9 個の正しい結果を返せる場合、リコール率は 90% となります。リコール率の説明については以下のとおりです：

* リコール率は、構築パラメーターとクエリパラメーターの影響を受けます。

* インデックスクエリパラメーターは、インデックス作成時に指定され、後で変更することはできません。ただし、session 変数を通じて設定することができます：HNSW/HNSW_SQ インデックスは `ob_hnsw_ef_search` を通じて、IVF/IVF_SQ/IVF_PQ インデックスは `ob_ivf_nprobes` を通じて設定されます。session 変数が設定されている場合には、その値が優先的に使用されます。具体的な設定方法については、[ob_hnsw_ef_search](https://en.oceanbase.com/docs/common-oceanbase-database-10000000001976680) および [ob_ivf_nprobes](https://en.oceanbase.com/docs/common-oceanbase-database-10000000002179539) を参照してください。

クエリ構文は以下のとおりです：

```sql
SELECT ... FROM $table_name ORDER BY $distance_function($column_name, $vector_expr) [APPROXIMATE|APPROX] LIMIT $num (OFFSET $num);
```

使用説明については以下のとおりです：

* クエリ構文の要件：
  * ベクトルインデックスパスを選択するには、`APPROXIMATE` / `APPROX` キーワードを指定しなければなりません。
  * `ORDER BY` と `LIMIT` 句を含めなければなりません。
  * `ORDER BY` は、単一のベクトル条件のみをサポートします。
  * `LIMIT + OFFSET` の値の範囲は、`(0, 16384]` です。

* 距離関数の使用ルール：
  * `APPROXIMATE` / `APPROX` が指定されていない場合、`inner_product` / `negative_inner_product` / `L2` を呼び出しても、クエリプランはベクトルインデックスパスを選択しません。ただし、エラーは発生しません。
  * `APPROXIMATE` / `APPROX` を指定し、距離関数とベクトルインデックスアルゴリズムが一致しない場合、クエリプランはベクトルインデックスパスを選択しません。ただし、エラーも発生しません。
  * `APPROXIMATE` / `APPROX` を指定した場合、式が `inner_product` であると、クエリプランはベクトルインデックスパスを選択しません。
  * `APPROXIMATE` / `APPROX` を指定し、式が `negative_inner_product` / `L2` であり、ベクトルインデックスアルゴリズムと一致する場合、クエリプランはベクトルインデックスパスを選択します。

* その他の説明：
  * `WHERE` 条件は、ベクトルインデックスクエリ後のフィルタ条件として機能します。
  * `LIMIT` 句を指定しないとエラーが発生します。

## インデックスの作成、クエリおよび削除の例

### 注意事項

OceanBase ベクトルインデックスの作成は、テーブル作成時と後から作成される、2 つの方法がサポートされています。インデックスを作成する際の注意：

* ベクトルインデックス作成後は、全てのパラメーターの変更はサポートされなくなります。

* ベクトルインデックスを作成すには、`VECTOR` キーワードが必要となります。

* 後から作成されるインデックスのパラメーターと説明は、テーブル作成時にインデックスを作成する場合と同様です。

* データ量が大きい場合は、データの書き込みを完了してからインデックスを作成することを推奨します。これにより、最適なクエリのパフォーマンスが得られます。

* HNSW_SQ インデックス / IVF インデックス / IVF_SQ インデックス / IVF_PQ インデックスは、データの書き込み後に作成し、大量のインクリメンタルデータの書き込み後にインデックスを再作成することを推奨します。各インデックスの作成の詳細については、以下の具体的な例を参照してください。

### テーブル作成時におけるインデックスの作成

HNSW/HNSW_SQ インデックスパラメーターの説明：

| パラメーター | デフォルト値 | 値の範囲 | 必須かどうか | 説明 | 備考 |
|------|--------|----------|----------|------|------|
| distance |  | l2/inner_product/cosine | はい | ベクトル距離関数のタイプを指定する。 | l2 はユークリッド距離を表し、inner_product は内積距離を表し、cosine はコサイン距離を表します。 |
| type |  | hnsw | はい | インデックスタイプを指定する。 | 現在のところ `hnsw` / `hnsw_sq8`がサポートされています。 |
| lib | vsag | vsag | いいえ | ベクトルインデックスライブラリのタイプを指定する。 | 現在のところ VSAG ベクトルライブラリのみサポートしています。 |
| m | 16 | [5,64] | いいえ | HSNW インデックス作成パラメーター、各ノードの最大隣接数。 | 値が大きくなるほどインデックスの作成は遅くなりますが、クエリのパフォーマンスは高まります。 |
| ef_construction | 200 | [5,1000] | いいえ | HNSW インデックス作成パラメーター、インデックス作成時の候補集合のサイズ。 | 値が大きくなるほどインデックス作成が遅くなりますが、インデックスのクオリティは高まります。`ef_construction` は `m` より大きくなければなりません。|
| ef_search | 64 | [1,1000] | いいえ | HNSW インデックスクエリパラメーター、クエリ時の候補集合のサイズ。 | 値が大きくなるほどクエリが遅くなりますが、リコール率は高まります。 |

## インデックスのメンテナンス

インクリメンタルデータが多すぎる状況では、クエリのパフォーマンスが低下することがあります。インクリメンタルデータテーブルのデータ量を減らし、ベクトルインデックスのメンテナンスを行うため、OceanBase は、`DBMS_VECTOR` を導入しています。

### インクリメンタルリフレッシュ

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>IVF/IVF_SQ/IVF_PQ インデックスにはインクリメンタルリフレッシュメカニズムがありません。</p>
</main>

インデックス作成後の入力データが多い場合には、インクリメンタルリフレッシュを使用することを推奨します。

構文については以下のとおりです：

```shell
  PROCEDURE refresh_index(
    IN     idx_name               VARCHAR(65535),                 ---- インデックス名
    IN     table_name             VARCHAR(65535),                 ---- テーブル名
    IN     idx_vector_col         VARCHAR(65535) DEFAULT NULL,    ---- ベクトル列名
    IN     refresh_threshold      INT DEFAULT 10000,              ---- インクリメンタルデータの数
    IN     refresh_type           VARCHAR(65535) DEFAULT NULL);   ---- FAST
```

インクリメンタルリフレッシュは 15 分おきに 1 回チェックされます。インクリメンタルデータが 1 万本を超えると自動的にインクリメンタルリフレッシュが行なわれます。

### フルリフレッシュ

インデックス作成後の更新または削除データが多い場合には、フルリフレッシュを使用することを推奨します。

構文については以下のとおりです：

```shell
  PROCEDURE rebuild_index(
    IN     idx_name                VARCHAR(65535),                    ---- インデックス名
    IN     table_name              VARCHAR(65535),                    ---- テーブル名
    IN     idx_vector_col          VARCHAR(65535) DEFAULT NULL,       ---- ベクトル列名
    IN     delta_rate_threshold    FLOAT DEFAULT 0.2,                 ---- インクリメンタルデータの割合
    IN     idx_organization        VARCHAR(65535) DEFAULT NULL,       ---- インデックスタイプ
    IN     idx_distance_metrics    VARCHAR(65535) DEFAULT 'EUCLIDEAN',---- 距離タイプ
    IN     idx_parameters          LONGTEXT DEFAULT NULL,             ---- インデックスパラメーター
    IN     idx_parallel_creation   INT DEFAULT 1);                    ---- インデックス並列作成の並列度、予約は、構文のみサポート
```

フルリフレッシュは 24 時間に 1 回チェックされます。新に増加したデータが既存データの 20% を超えた場合には、フルリフレッシュが自動的に行なわれます。フルリフレッシュは既存のインデックスを消去し、バックグラウンドで新しいインデックスが作成されますが、速度は遅いです。

#### インデックスのメンテナンスの例

テストテーブルを作成します。

```sql
CREATE TABLE vector_index_test(c1 INT, c2 VECTOR(3), PRIMARY KEY(c1), VECTOR INDEX idx1(c2) WITH (distance=l2, type=hnsw, lib=vsag));
```

テストデータを入力します。

```sql

INSERT INTO vector_index_test VALUES(2, '[0.484526,0.669954,0.986755]');

INSERT INTO vector_index_test VALUES(4, '[0.148869,0.878546,0.028024]');
INSERT INTO vector_index_test VALUES(5, '[0.334970,0.857377,0.886132]');
INSERT INTO vector_index_test VALUES(6, '[0.117582,0.302352,0.471198]');
INSERT INTO vector_index_test VALUES(7, '[0.551185,0.231134,0.075354]');
INSERT INTO vector_index_test VALUES(8, '[0.185221,0.315131,0.558301]');

```

```sql

-- フル更新がトリガーされます。

```
