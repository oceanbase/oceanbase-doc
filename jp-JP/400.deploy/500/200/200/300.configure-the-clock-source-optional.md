# (オプション) クロックソースの設定

本記事では、クラスター内の複数マシンに NTP クロックソースを設定する方法について説明します。OceanBase データベースをスタンドアロンデプロイする場合、個人テストを行う場合、または NTP クロック同期が既に設定されている場合は、設定は不要です。

分散型 OceanBase クラスターのデプロイを予定している場合、クラスター内の各マシンの時刻同期を確保する必要があります。そうしない場合、クラスターは起動せず、サービス実行時に異常が発生します。OceanBase クラスターの許容クロック偏差は 2 秒以内です。2 秒を超えると、オーナレス状態になります。クロック同期を回復した後、OceanBase クラスターを再起動すると、正常に復旧します。

<main id="notice" type='explain'>
   <h4>説明</h4>
   <ul>
   <li>
   <p>本記事では、x86 アーキテクチャの CentOS Linux 7.9 イメージ環境を基に操作手順を示します。他の環境では多少異なる場合がありますので、実際の環境をご確認ください。</p>
   </li>
   <li>
   <p>OceanBase は V4.0.0 以降、動的時刻変更をサポートしており、変更間隔が 2 秒以内であれば、データの正確性とクラスターの安定稼働に影響を与えません。</p>
   </li>
   <li>
   <p>OCP Express または OCP をデプロイするノードと OceanBase クラスターが同一ノード上にない場合、OCP Express または OCP のノードと OceanBase クラスタノードのクロックソースを同期させる必要があります。これは、運用中にクロックずれによって OCP Express または OCP の動作異常が発生するのを防ぐためです。</p>
   </li>
   </ul>
</main>

## 前提条件

NTP クロックソースを設定する前に、すべてのマシンの root 権限を持っていることを確認します。

## 操作手順

以下の手順に従って、NTP クロック同期を設定します。

1. 各マシンで以下のコマンドを実行して、NTP をインストールします。

   ```shell
   yum install ntp ntpdate -y
   ```

2. 以下のコマンドを実行して、サーバーの NTP 接続を確認します。

   ```shell
   [root@centos-01 ~]# ntpq -4p
   remote refid st t when poll reach delay offset jitter
   ==============================================================================
   *time6.aliyun.co xxx.xxx.xxx.xxx 2 u 712 1024 377 21.951 4.253 4.208
   ```

3. (オプション) NTP サーバーサービスを有効化します。

   NTP サーバーが既に存在する場合は、この手順をスキップできます。このドキュメントでは、ターゲットマシン `10.10.10.1` を NTP サーバとして使用します。

   1. 設定ファイルを編集します。

      root ユーザーで NTP サーバにログインし、以下のコマンドで設定ファイルを編集します：

      ```shell
      vi /etc/ntp.conf
      ```

      設定ファイルに以下の内容を追加します：

      ```shell
      server <your_ntp_server_ip>
      ```

      設定ファイルを保存して閉じます。

   2. 以下のコマンドを実行して NTP サーバーサービスを再起動します：

      ```shell
      service ntpd restart
      ```

   3. 以下のコマンドを実行して、NTP サーバーサービスが正常に起動しているかどうかを確認します：

      ```shell
      ps -ef | grep -i ntpd
      ```

   4. 以下のコマンドを実行して、NTP サービスを起動時に自動的に開始するように設定します：

      ```shell
      chkconfig ntpd on
      ```

4. NTP クライアントサービスを開始します。

   <main id="notice" type='notice'>
     <h4>注意</h4>
     <p>NTP サーバサービスの起動後、5 分間待ってから NTP クライアントサービスを開始する必要があります。そうしない場合、システムが &quot;no server suitable for synchronization found&quot; を表示します。</p>
   </main>

   1. root ユーザーを使用して OBServer ノードサーバーにログインします。

   2. 以下のコマンドを実行して、NTP サービスを停止します：

      ```shell
      service ntpd stop
      ```

   3. 以下のコマンドを実行して、NTP サーバーの時刻を同期します：

      ```shell
      ntpdate 10.10.10.1
      ```

   4. 設定ファイルを編集します。

      以下のコマンドを実行して、設定ファイルを開きます：

      ```shell
      vi /etc/ntp.conf
      ```

      設定ファイルに以下の内容を追加します：

      ```shell
      server <your_ntp_server_ip>
      ```

   5. 以下のコマンドを実行して、NTP サービスを起動します：

      ```shell
      /etc/init.d/ntpd start
      ```

5. 以下のコマンドを実行して、設定が正常に完了したかどうかを検証します：

   コマンドを実行：

   ```shell
   ntpstat
   ```

   以下の結果が返されます：

   ```shell
   synchronised to NTP server (xxx.xxx.xxx.xxx) at stratum 3
   time correct to within 2 ms
   polling server every 64 s
   ```

   コマンドを実行：

   ```shell
   timedatectl
   ```

   以下の結果が返されます：

   ```shell
         Local time: Thu 2021-04-22 11:02:32 CST
     Universal time: Thu 2021-04-22 03:02:32 UTC
           RTC time: Thu 2021-04-22 11:02:32
          Time zone: Asia/Shanghai (CST, +0800)
        NTP enabled: yes
   NTP synchronized: yes
    RTC in local TZ: yes
         DST active: n/a
   ```

   上記コマンドを実行して対応する結果が返されると、NTP サービスが有効であることを示します。
