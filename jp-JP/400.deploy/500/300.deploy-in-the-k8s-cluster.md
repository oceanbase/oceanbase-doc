# Kubernetes 環境における OceanBase クラスターのデプロイ

本記事では、ob-operator を使用して Kubernetes 環境に OceanBase クラスターをデプロイする方法を、例を挙げて説明します。

## 前提条件

開始する前に、以下の条件を満たしていることを確認してください。

- 利用可能な Kubernetes クラスターがあり、9 個以上の CPU、33 GB の利用可能なメモリ、および 360 GB の利用可能なストレージがあります。

- ob-operator は cert-manager に依存しています。cert-manager がインストール済みであることを確認してください。cert-manager のインストール方法については、対応する [インストールガイド](https://cert-manager.io/docs/installation/) を参照してください。

- OceanBase クラスターに接続するには、MySQL クライアントまたは OBClient がインストール済みである必要があります。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>本記事では、ob-operator V2.2.0 を例に操作手順を説明します。他のバージョンでは、若干異なる場合があります。異なるバージョンの操作手順については、<a href='https://en.oceanbase.com/docs/community-ob-operator-doc-en-10000000001735158'>ob-operator マニュアル</a>の該当するバージョンを参照することができます。</p>

## ob-operator のデプロイ

ob-operator を使用すると、Kubernetes 上の OceanBase データベースのデプロイと運用保守を簡素化できます。ob-operator は以下の 2 つの方法でデプロイすることができます。

### Helm を使用したデプロイ

以下のコマンドを実行して、ob-operator をデプロイすることができます。

```shell
helm repo add ob-operator https://oceanbase.github.io/ob-operator/
helm install ob-operator ob-operator/ob-operator --namespace=oceanbase-system --create-namespace --version=2.2.0
```

パラメーターの説明：

- `--namespace`：名前空間は必要に応じてカスタマイズすることができますが、`oceanbase-system` の使用を推奨します。

- `--version`：ob-operator のバージョン番号で、最新バージョンを使用することを推奨します。

### 設定ファイルによるデプロイ

以下のコマンドを実行して、設定ファイルを用いて ob-operator をデプロイすることができます。

```shell
kubectl apply -f https://raw.githubusercontent.com/oceanbase/ob-operator/2.2.0_release/deploy/operator.yaml
```

#### ob-operator のカスタマイズ

ob-operator をカスタマイズする必要がある場合、以下のコマンドを実行して設定ファイルをダウンロードすることができます。

```shell
wget https://raw.githubusercontent.com/oceanbase/ob-operator/2.2.0_release/deploy/operator.yaml
```

必要に応じて設定ファイルを修正した後、以下のコマンドを実行してカスタムデプロイを行います。構成ファイル内の設定項目の詳細については、[ob-operator の設定](https://en.oceanbase.com/docs/community-ob-operator-doc-en-10000000001735159) を参照することができます。

```shell
kubectl apply -f operator.yaml
```

## OceanBase クラスターのデプロイ

1. PVC を作成します

   ob-operator は OceanBase クラスターをデプロイする際、OceanBase クラスターのストレージとして PVC を作成する必要があります。本記事では、local-path-provisioner を使用して PVC を管理します。デプロイコマンドは以下のとおりです。

   ```shell
   kubectl apply -f https://raw.githubusercontent.com/rancher/local-path-provisioner/v0.0.24/deploy/   local-path-storage.yaml
   ```

   詳細については、[local-path-provisioner](https://github.com/rancher/local-path-provisioner) を参照することができます。

2. Namespace を作成します

   以下のコマンドを実行して、OceanBase クラスターのデプロイに使用される Namespace を作成します。

   ```shell
   kubectl create namespace oceanbase
   ```

   作成後、`kubectl get namespace oceanbase` コマンドを実行し、作成に成功したかどうか (ステータスが `Active` であること) を確認することができます。

3. デフォルトユーザーのシークレットを作成する

   OceanBase クラスターを作成する前に、以下のコマンドを実行して、OceanBase クラスター内の特定のユーザー情報を格納する Secret を複数作成する必要があります。

   ```shell
   kubectl create secret -n oceanbase generic root-password --from-literal=password='<root_password>'
   kubectl create secret -n oceanbase generic proxyro-password --from-literal=password='<proxyro_password>'
   ```

   `<root_password>` と `<proxyro_password>` は、それぞれ root@sys ユーザーと proxyro@sys ユーザーのパスワードを表し、設定したいパスワードに変更する必要があります。作成後、`kubectl get secret -n oceanbase` コマンドを実行して、Secret リソースの作成に成功したかどうかを確認することができます。

4. OceanBase クラスターを定義する

   OceanBase クラスターは YAML 構成ファイルで定義されます。`obcluster.yaml` という構成ファイルを作成するには、以下のコマンドを実行することができます。

   ```shell
   vi obcluster.yaml
   ```

   構成ファイルの内容例を以下に示します。

   ```yaml
   apiVersion: oceanbase.oceanbase.com/v1alpha1
   kind: OBCluster
   metadata:
     name: obcluster
     namespace: oceanbase
   spec:
     clusterName: obcluster
     clusterId: 1
     userSecrets:
       root: root-password
       proxyro: proxyro-password
     topology:
       - zone: zone1
         replica: 1
       - zone: zone2
         replica: 1
       - zone: zone3
         replica: 1
     observer:
       image: oceanbase/oceanbase-cloud-native:4.2.1.1-101010012023111012
       resource:
         cpu: 2
         memory: 10Gi
       storage:
         dataStorage:
           storageClass: local-path
           size: 50Gi
         redoLogStorage:
           storageClass: local-path
           size: 50Gi
         logStorage:
           storageClass: local-path
           size: 20Gi
     monitor:
       image: oceanbase/obagent:4.2.1-100000092023101717
       resource:
         cpu: 1
         memory: 1Gi
   ```

   主な設定項目は以下のとおりです。詳細な設定項目については、[クラスターの作成](https://en.oceanbase.com/docs/community-ob-operator-doc-en-10000000001735170) を参照することができます。

   |                設定項目                | 必須入力かどうか |                                     説明                                      |
   | ------------------------------------ | -------- | ----------------------------------------------------------------------------- |
   | metadata.name                        | 必須     | クラスター名。K8s のリソース名。                                                    |
   | metadata.namespace                   | 必須     | クラスターが存在する名前空間。                                                          |
   | spec.clusterName                     | 必須     | OceanBase クラスター名。                                                            |
   | spec.clusterId                       | 必須     | OceanBase クラスター ID。                                                           |
   | spec.userSecrets                     | 必須     | OceanBase クラスターのデフォルトユーザーの Secret。                                             |
   | spec.userSecrets.root                | 必須     | OceanBase クラスター root@sys ユーザーの Secret 名。Secret には password フィールドが含まれている必要があります。 |
   | spec.userSecrets.proxyro             | オプション     | OceanBase クラスター proxyro@sys ユーザーの Secret 名。Secret には password フィールドが含まれている必要があります。   |
   | spec.topology                        | 必須     | OceanBase クラスターのデプロイメント topo の定義。各 Zone の定義を含みます。                      |
   | spec.topology[i].zone                | 必須     | OceanBase クラスター内の Zone 名。                                                       |
   | spec.topology[i].replica             | 必須     | OceanBase クラスター内の　Zone に含まれる OBServer ノード数。                                 |
   | spec.observer.image                  | 必須     | 使用する OceanBase データベースイメージ。                                              |
   | spec.observer.resource               | 必須     | OceanBase クラスターにおける OBServer ノードのリソース設定。                                          |
   | spec.observer.resource.cpu           | 必須     | OceanBase クラスターにおける OBServer ノード の CPU リソース設定。2 より大きい整数値に設定することを推奨します。2 未満の場合、システム異常が発生します。                                     |
   | spec.observer.resource.memory        | 必須     | OceanBase クラスター内の OBServer ノードの Memory リソース設定。推奨値は 10 GiB を超え、10 GiB 未満の場合はシステム異常が発生します。                                  |
   | spec.observer.storage                | 必須     | OceanBase クラスター内の OBServer ノードのストレージ設定。                                          |
   | spec.observer.storage.dataStorage    | 必須     | OceanBase クラスター内の OBServer ノードのデータストレージ設定。`memory` サイズの 3 倍以上を推奨します。                                      |
   | spec.observer.storage.redoLogStorage | 必須     | OceanBase クラスター内の OBServer ノードの Clog ストレージ設定。`memory` サイズの 3 倍以上を推奨します。                                    |
   | spec.observer.storage.logStorage     | 必須     | OceanBase クラスター内の OBServer ノードの動作ログの保存設定。10 GiB 以上を推奨します。                                  |
   | spec.observer.storage.*.storageClass | 必須     | ストレージ設定を有効にするために、PVC 作成時に使用する storageClass を定義します。                      |
   | spec.observer.storage.*.size         | 必須     | ストレージ設定で有効になり、PVC 作成時の容量を定義するために使用されます。                                   |
   | spec.monitor                         | オプション     | モニタリング設定。有効化することを推奨します。ob-operator は OBAgent を使用してモニタリングデータの収集を行い、Prometheus と連携することで OceanBase クラスターの状態モニタリングを実現します。  |
   | spec.monitor.image                   | 必須     | OBAgent が使用するイメージ。                                                       |
   | spec.monitor.resource                | 必須     | モニタリング対象コンテナが使用するリソース。                                                          |
   | spec.monitor.resource.cpu            | 必須     | モニタリング対象コンテナが使用する CPU リソース。                                                     |
   | spec.monitor.resource.memory         | 必須     | モニタリング対象コンテナが使用する memory リソース。                                                  |

5. OceanBase クラスターのデプロイ

   ```shell
   kubectl apply -f obcluster.yaml
   ```

   以下のコマンドを実行し、OceanBase クラスターの状態を確認します。状態が `running` になれば、OceanBase クラスターのデプロイと初期化が完了したことを表しています。このプロセスは通常数分を要し、主な時間のかかる部分はイメージの取得とクラスターの初期化です。

   ```shell
   kubectl get obclusters.oceanbase.oceanbase.com obcluster -n oceanbase
   ```

### OceanBase クラスターへのダイレクト接続

OceanBase クラスターのデプロイ後、このセクションの手順に従って OceanBase クラスターに直接接続できます。ODP をデプロイした後に、ODP 経由で OceanBase クラスターに接続することを推奨します。ODP のデプロイ手順については、下記の [ODP のデプロイ](#デプロイ%20ODP) を参照することができます。

1. OceanBase クラスターの Pod アドレスを取得する

   ```shell
   kubectl get pods -n oceanbase -l ref-obcluster=obcluster -o wide
   ```

   例の `oceanbase` は metadata.namespace の値に対応し、`obcluster` は metadata.name の値に対応します。実際の構成に合わせて置き換える必要があります。

   出力は以下のとおりです：

   ```shell
   NAME                                READY   STATUS    RESTARTS   AGE    IP            NODE     NOMINATED NODE   READINESS GATES
   obcluster-1-zone2-c76d303299a9      2/2     Running   0          4m     10.10.10.1    node-x   <none>           <none>
   obcluster-1-zone3-2cdf3cd8a05e      2/2     Running   0          4m     10.10.10.2    node-x   <none>           <none>
   obcluster-1-zone1-94904330202f      2/2     Running   0          4m     10.10.10.3    node-x   <none>           <none>
   ```

2. OceanBase クラスターへの接続

   OceanBase クラスターへの接続は、任意のノードの IP アドレスを使用して行うことができます。接続コマンドは以下のとおりです。

   ```shell
   mysql -h10.10.10.1 -P2881 -uroot@sys -p oceanbase -A -c
   ```

## ODP のデプロイ

ODP は YAML 設定ファイルで定義され、詳細なデプロイ手順は以下のとおりです。

1. ODP の設定ファイルを作成する

   ```shell
   vi obproxy.yaml
   ```

   ここでは、設定ファイル名として `obproxy.yaml` を例に、ファイルの内容を以下に示します：

   ```yaml
   apiVersion: v1
   kind: Service
   metadata:
     name: svc-obproxy
     namespace: oceanbase
   spec:
     type: ClusterIP
     selector:
       app: obproxy
     ports:
       - name: "sql"
         port: 2883
         targetPort: 2883
       - name: "prometheus"
         port: 2884
         targetPort: 2884
   
   ---
   apiVersion: apps/v1
   kind: Deployment
   metadata:
     name: obproxy
     namespace: oceanbase
   spec:
     selector:
       matchLabels:
         app: obproxy
     replicas: 2
     template:
       metadata:
         labels:
           app: obproxy
       spec:
         containers:
           - name: obproxy
             image: oceanbase/obproxy-ce:4.2.1.0-11
             ports:
               - containerPort: 2883
                 name: "sql"
               - containerPort: 2884
                 name: "prometheus"
             env:
               - name: APP_NAME
                 value: helloworld
               - name: OB_CLUSTER
                 value: obcluster
               - name: RS_LIST
                 value: ${RS_LIST}
               - name: PROXYRO_PASSWORD
                 valueFrom: 
                   secretKeyRef:
                     name: proxyro-password
                     key: password
             resources:
               limits:
                 memory: 2Gi
                 cpu: "1"
               requests: 
                 memory: 200Mi
                 cpu: 200m
   ```

   主な環境変数の設定説明：

   - `APP_NAME`：ODP のアプリケーション名。

   - `OB_CLUSTER`：ODP 接続の OceanBase クラスター名。

   - `RS_LIST`：OceanBase クラスターの rs_list の形式は、`${ip1}:${sql_port1};${ip2}:${sql_port2};${ip3}:${sql_port3}` で、実際のデプロイ状況に応じて置き換える必要があります。OceanBase クラスターにダイレクト接続して `SELECT GROUP_CONCAT(CONCAT(SVR_IP, ':', SQL_PORT) SEPARATOR ';') AS RS_LIST FROM oceanbase.DBA_OB_SERVERS;` コマンドを実行して確認できます。OceanBase クラスターへのダイレクト接続操作については、[OceanBase クラスターへのダイレクト接続](#ダイレクト接続%20OceanBase%20クラスター) を参照することができます。

   - `PROXYRO_PASSWORD`：`name` には、前述で作成した proxyro@sys ユーザーの Secret 名を指定する必要があります。Secret には password フィールドが含まれている必要があります。

2. ODP のデプロイ

   ```shell
   kubectl apply -f obproxy.yaml
   ```

3. デプロイの成功を検証する

   以下のコマンドを実行して、ODP の Pod の状態を確認してください。

   ```shell
   kubectl get pod -A | grep obproxy
   ```

   出力は以下のとおりです。obproxy の Pod が 2 つあります。

   ```shell
   oceanbase            obproxy-5cb8f4d975-pmr59                          1/1     Running   0          21s
   oceanbase            obproxy-5cb8f4d975-xlvjp                          1/1     Running   0          21s
   ```

   以下のコマンドを実行して、ODP のサービスを確認してください。

   ```shell
   kubectl get svc svc-obproxy -n oceanbase
   ```

   出力は以下のとおりです：

   ```shell
   NAME          TYPE        CLUSTER-IP   EXTERNAL-IP   PORT(S)             AGE
   svc-obproxy   ClusterIP   10.10.10.1   <none>        2883/TCP,2884/TCP   2m26s
   ```

### ODP による OceanBase クラスターへの接続

OceanBase クラスターへの接続には ODP の使用を推奨します。OceanBase データベースと ODP のデプロイ後、以下の手順で OceanBase クラスターに接続することができます。

1. ODP のサービス接続アドレスを取得する

   ```shell
   kubectl get svc ${servicename} -n ${namespace}
   
   # for example
   kubectl get svc svc-obproxy -n oceanbase
   ```

   出力は以下のとおりです：

   ```shell
   # output
   NAME          TYPE        CLUSTER-IP   EXTERNAL-IP   PORT(S)             AGE
   svc-obproxy   ClusterIP   10.10.10.1   <none>        2883/TCP,2884/TCP   2m26s
   ```

2. OceanBase クラスターへの接続

   CLUSTER-IP と PORT を使用して接続できます。対応する接続コマンドは以下のとおりです。

   ```shell
   mysql -h10.10.10.1 -P2883 -uroot@sys#obcluster -p oceanbase -A -c
   ```

## OceanBase クラスターの監視

OceanBase Dashboard ツールを使用して、OceanBase クラスターを監視することができます。OceanBase Dashboard は ob-operator と連携する GUI 運用保守ツールです。現在の最新バージョンは V0.2.1 であり、クラスター管理、テナント管理、バックアップ管理、パフォーマンス監視、ターミナル接続などの機能を備えています。K8s 環境において、ob-operator と連携して OceanBase クラスターのパフォーマンス指標を監視するための最適なツールです。

### OceanBase Dashboard のデプロイ

Kubernetes パッケージマネージャー Helm を使用して OceanBase Dashboard をインストールすることを推奨します。Helm が既にインストールされていることを確認した後、以下の 3 つのコマンドを実行すれば、デフォルトの名前空間に OceanBase Dashboard をインストールすることができます。

```shell
helm repo add ob-operator https://oceanbase.github.io/ob-operator/
helm repo update ob-operator
helm install oceanbase-dashboard ob-operator/oceanbase-dashboard --version=0.2.1
```

その他の名前空間に OceanBase Dashboard をインストールする場合、最後のインストールコマンドを以下のコマンドに置き換えることができます。

```shell
helm install oceanbase-dashboard ob-operator/oceanbase-dashboard --version=0.2.1 -n <namespace> --create-namespace
```

ここで、`<namespace>` は OceanBase Dashboard をインストールする対象の名前空間に設定する必要があります。対象の名前空間が存在しない場合は、`--create-namespace` を指定して作成することができます。クラスターが LoadBalancer サービスをサポートしている場合、インストール時に `--set service.type=LoadBalancer` を設定して、LoadBalancer タイプのサービスを作成するように指定することができます。

コマンド実行後、以下が出力されれば、OceanBase Dashboard のデプロイは成功です。

```shell
NAME: oceanbase-dashboard
LAST DEPLOYED: Wed May  8 11:04:49 2024
NAMESPACE: default
STATUS: deployed
REVISION: 1
TEST SUITE: None
NOTES:
Welcome to OceanBase dashboard

1. After installing the dashboard chart, you can use `port-forward` to expose the dashboard outside like:

  > kubectl port-forward -n default services/oceanbase-dashboard-oceanbase-dashboard 18081:80 --address 0.0.0.0

then you can visit the dashboard on http://$YOUR_SERVER_IP:18081

2. Use the following command to get password for default admin user 

  > echo $(kubectl get -n default secret oceanbase-dashboard-user-credentials -o jsonpath='{.data.admin}' | base64 -d)

Log in as default account:
Username: admin
Password: <Get from the above command>
```

OceanBase Dashboard のデプロイ後、K8s クラスターは必要なイメージの取得に時間を要します。以下のコマンドで、OceanBase Dashboard のインストールが完了したかどうかを確認することができます。

```shell
kubectl get deployment oceanbase-dashboard-oceanbase-dashboard
```

出力は以下のとおりです。`READY` 列に `1/1` と表示されている場合、インストールが完了しており、次の操作に進むことができます。

```shell
NAME                                      READY   UP-TO-DATE   AVAILABLE   AGE
oceanbase-dashboard-oceanbase-dashboard   1/1     1            1           2m10s
```

### OceanBase Dashboard へのアクセス

OceanBase Dashboard のデフォルトログインアカウントは `admin` です。出力結果の 2 番目のコマンドで、デフォルトアカウントのパスワードを取得することができます。コマンドは以下のとおりです。

```shell
echo $(kubectl get -n default secret oceanbase-dashboard-user-credentials -o jsonpath='{.data.admin}' | base64 -d)
```

OceanBase Dashboard には、以下の 3 つのアクセス方法があります。状況に応じて適切な方法を選択することができます。

- NodePort によるアクセス：OceanBase Dashboard は、デフォルトで NodePort タイプのサービスを作成します。NodePort を介して OceanBase Dashboard にアクセスすることができます。

- LoadBalancer 経由でアクセス：ご利用のクラスターが LoadBalancer サービスをサポートしている場合、LoadBalancer 経由で OceanBase Dashboard にアクセスすることができます。

- Port Forward による一時的なアクセス：クラスターノードのポートにアクセスできない場合、上記の 2 つのサービスは利用できません。Port Forward を使用して、OceanBase Dashboard に一時的にアクセスすることができます。

:::tab
NodePort を介して tab にアクセスする

OceanBase Dashboard はデフォルトで NodePort タイプのサービスを作成します。ノードで公開されているポートを取得するには、以下のコマンドを実行することができます。なお、サービス名は、指定された Helm Chart 名によって変化します。具体的なサービス名は、OceanBase Dashboard インストール時の出力結果の最初のコマンドで確認することができます。本例では `oceanbase-dashboard-oceanbase-dashboard` となります。

```shell
kubectl get svc oceanbase-dashboard-oceanbase-dashboard
```

出力は以下のとおりです：

```shell
NAME                                      TYPE       CLUSTER-IP   EXTERNAL-IP  PORT(S)        AGE
oceanbase-dashboard-oceanbase-dashboard   NodePort   10.10.10.1   <none>       80:30176/TCP   13m
```

ブラウザから該当する K8s ノードの `PORT` ポートにアクセスすると、OceanBase Dashboard のログイン画面が表示されます。サービスのポート番号は K8s によって動的に割り当てられ、ノードの IP アドレスは `kubectl get nodes -o wide` コマンドを実行することで確認することができます。

タブは LoadBalancer 経由でアクセスします

OceanBase Dashboard のインストール時に LoadBalancer タイプのサービスを作成するように指定することができます。また、OceanBase Dashboard のインストール後に以下のコマンドを実行して、サービスタイプを LoadBalancer に変更することもできます。

```shell
kubectl patch -n oceanbase-dashboard svc oceanbase-dashboard-oceanbase-dashboard --type=merge --patch='{"spec": {"type": "LoadBalancer"}}'
```

変更完了後、クラスターは OceanBase Dashboard サービスに外部 IP アドレスを割り当てます。この外部 IP アドレスを通じて OceanBase Dashboard のページにアクセスすることができます。変更後、しばらく待ってからサービス情報を再度確認すると、External IP フィールドに値が割り当てられていることがわかります。

```shell
kubectl get svc oceanbase-dashboard-oceanbase-dashboard
```

出力は以下のとおりです：

```shell
NAME                                      TYPE           CLUSTER-IP      EXTERNAL-IP    PORT(S)        AGE
oceanbase-dashboard-oceanbase-dashboard   LoadBalancer   10.10.10.1      10.10.10.2     80:18082/TCP   1d5h
```

ブラウザで `http://10.10.10.2:18082` を入力すると OceanBase Dashboard にアクセスすることができます。ここでは `EXTERNAL-IP` が `10.10.10.2`、`PORT` が `18082` の場合を例としており、実際の出力内容に合わせて置き換えることが必要となります。

Port Forward を使用して tab に一時的にアクセスします

クラスターノードのポートにアクセスできず、NodePort タイプのサービスを使用して OceanBase Dashboard を公開することができない、さらに LoadBalancer サービスもサポートされていないような場合には、`kubectl port-forward` コマンドを使用して、OceanBase Dashboard を現在のマシンの指定ポートに転送し、一時的にアクセスすることができます。例えば、次のコマンドを実行すると、OceanBase Dashboard が現在のマシン (このコマンドを実行しているマシン) の `18081` ポートに示されます。

```shell
kubectl port-forward -n default services/oceanbase-dashboard-oceanbase-dashboard 18081:80 --address 0.0.0.0
```

他のコンピュータのブラウザから、このマシンの `18081` ポートにアクセスすると、ログイン画面が表示されます。上記のコマンドを実行したマシンがご自身の PC の場合、ブラウザで `http://127.0.0.1:18081` にアクセスすると、サービスにアクセスすることができます。
:::
