# OceanBaseデータベースのJava SDK環境のデプロイ

OceanBaseデータベースは、外部テーブルのサードパーティデータソースとしてファイルシステムと接続するために、Java SDKとの連携に対応しています。この機能はJNI(Java Native Interface)フレームワークを使用して実装されているため、OceanBaseデータベースの環境にはJava SDKの構築が必要です。

## 環境の設定

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>HDFS/ODPS外部テーブル機能を使用する場合、OceanBaseデータベースが分散デプロイされている環境では、すべてのマシンノードで以下のJava環境のデプロイと依存関係のインストールを行う必要があります。単一のノードだけに設定することはできません。</p>
</main>

すべての環境設定と依存関係のインストール操作は、adminユーザーとして実行する必要があります。次のコマンドでユーザーを切り替えてください：

```bash
su - admin
```

### Java環境のデプロイと設定

1. [ダウンロードサイト]((https://www.openlogic.com/openjdk-downloads))からOpenJDK Javaのインストールパッケージをダウンロードします。

    <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>请使用 OpenJDK 8 最新版本。</p>
    </main>

    ここでは例として、OpenJDK 8u422-b05バージョンをダウンロードする手順を説明します。

    ```shell
    [admin@xxx /home/admin/rpm]# wget https://builds.openlogic.com/downloadJDK/openlogic-openjdk/8u422-b05/openlogic-openjdk-8u422-b05-linux-x64.tar.gz
    ```

2. ダウンロードしたインストールパッケージを通常の手順で解凍します。

    例：

    ```shell
    [admin@xxx /home/admin/rpm]# tar -zxvf openlogic-openjdk-8u422-b05-linux-x64.tar.gz
    ```

    ```shell
    [admin@xxx /home/admin/rpm]# ls openlogic-openjdk-8u422-b05-linux-x64
    ASSEMBLY_EXCEPTION  LICENSE  THIRD_PARTY_README  bin  demo  include  jre  lib  man  release  sample  src.zip
    ```

    インストールパスは以下の通りです：

    ```shell
    /home/admin/rpm/openlogic-openjdk-8u422-b05-linux-x64
    ```

    <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>このパスは、現在のOBServer実行ノード上のJavaホームディレクトリを設定するために使用されます。これは、構成パラメータob_java_homeの値に対応します。</p>
    </main>

### 依存関係のインストール

OceanBaseデータベースでHDFS/ODPS外部テーブル機能を使用するには、さらに以下のコンポーネントへの依存関係が必要です。

* devdeps-hdfs-sdk RPMパッケージ:

  このパッケージには、HDFS/ODPSなどの外部テーブルの実行時に必要な動的リンクライブラリファイルが含まれており、JVM環境とJNI(Java Native Interface)が相互作用するためのコアインターフェースを提供します。このコンポーネントは、Java仮想マシンとローカルの外部テーブルJava SDKとの間の通信ブリッジとして機能し、外部テーブル機能の安定した動作を保証します。

* devdeps-java-extensions RPMパッケージ:

  このパッケージは、HDFS外部テーブルやその他の外部データソース（ODPSなど）に必要なコア依存ライブラリ（JARファイル）を統合したものです。この拡張パッケージには、完全なJavaランタイムの依存関係チェーンが含まれており、分散環境における外部テーブル機能の互換性とパフォーマンスの最適化を保証します。

#### 依存するHDFS.so動的ライブラリのデプロイと設定

1. devdeps-hdfs-sdk RPMインストールパッケージを取得します。

    * Enterprise Editionをご利用のお客様は、テクニカルサポートにご連絡の上、devdeps-hdfs-sdk RPMインストールパッケージを取得してください。
    * Community Edition(オープンソース版)をご利用のお客様は、[Alibaba Cloud OceanBaseミラー](https://mirrors.aliyun.com/oceanbase/)ページの`development-kit/`ディレクトリをクリックし、開発ツールリソースディレクトリからdevdeps-hdfs-sdk RPMインストールパッケージをダウンロードできます。
2. インストールパッケージを取得したら、以下のコマンドでインストールを実行します。

    ```shell
    sudo rpm -Uvh devdeps-hdfs-sdk-3.3.6-xxxxx.xxx.xxx.rpm
    ```

    例：

    ```shell
    sudo rpm -Uvh devdeps-hdfs-sdk-3.3.6-112024123116.el7.x86_64.rpm
    ```

3. インストールが正しく行われたかを確認します。

    `libhdfs.so`と`libhdfs.so.0.0.0`ファイルが存在し、それらのシンボリックリンクが正常であることを確認する必要があります。

    例：

    ```shell
    $ll /usr/local/oceanbase/deps/devel/lib
    total 376
    lrwxrwxrwx 1 root root     16 Dec 24 19:49 libhdfs.so -> libhdfs.so.0.0.0
    -rwxr-xr-x 1 root root 384632 Dec 24 19:09 libhdfs.so.0.0.0
    ```

#### 依存するjarパッケージパスのデプロイと設定

1. devdeps-java-extensions RPMインストールパッケージを取得します。

    * Enterprise Editionをご利用のお客様は、テクニカルサポートにご連絡の上、devdeps-java-extensions RPMインストールパッケージを取得してください。
    * Community Edition(オープンソース版)をご利用のお客様は、[Alibaba Cloud OceanBaseミラー](https://mirrors.aliyun.com/oceanbase/)ページのdevelopment-kit/ディレクトリをクリックし、開発ツールリソースディレクトリからdevdeps-java-extensions RPMインストールパッケージをダウンロードできます。

      <main id="notice" type='notice'>
        <h4>注意</h4>
        <p><ul>
        <li><b>OceanBaseデータベースV4.3.5 BP1以前のバージョン：</b>バージョン1.0.0の`devdeps-java-extensions`RPMインストールパッケージをダウンロードしてください。</li>
        <li><b>OceanBaseデータベースV4.3.5 BP2以降のバージョン：</b>バージョン1.0.1の`devdeps-java-extensions`RPMインストールパッケージをダウンロードしてください。</li>
        <li><b>OceanBaseデータベースV4.4.0バージョン：</b>バージョン1.0.1の`devdeps-java-extensions`RPMインストールパッケージをダウンロードしてください。</li></ul></p>
      </main>

2. インストールパッケージを取得したら、以下のコマンドでインストールを実行します。

    ```shell
    sudo rpm -Uvh devdeps-java-extensions-x.x.x-xxxxxxxxxxxx.xxx.xxxxxx.rpm
    ```

    例：

    ```shell
    sudo rpm -Uvh devdeps-java-extensions-1.0.0-122025032514.el7.x86_64.rpm
    ```

3. インストールが正しく行われたかを確認します。

    インストールパス`/home/admin/oceanbase/jni_packages/v1.0.0`に`oceanbase-odps-connector-jar-with-dependencies.jar`ファイルが存在することを確認します。

    例：

    ```shell
    $ll /home/admin/oceanbase/jni_packages/v1.0.0
    total 52756
    drwxr-sr-x 4 root root     4096 Dec 24 20:25 hadoop
    drwxr-xr-x 3 root root     4096 Dec 24 20:25 lib
    -rw-r--r-- 1 root root 54008720 Dec 24 19:52 oceanbase-odps-connector-jar-with-dependencies.jar
    ```

    <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>このパスは、OBServerが起動するJVMがロード可能な実行依存JARパッケージのパスを設定するために使用されます。これは、構成パラメータob_java_connector_pathの値に対応します。</p>
    </main>

## (オプション) observerプロセスの再起動

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p><ul><li>初めてJava SDK環境を使用する場合は、observerプロセスを再起動する必要はありません。</li><li>現在、OBServerのJNI関連の設定は、変更してもすぐには反映されません。そのため、Java関連の環境変数の設定を変更した場合は、observerプロセスを再起動して設定を有効にする必要があります。</li></ul></p>
</main>

HDFS/ODPS外部テーブル機能を使用する際には、対応するOBServerで以下の設定を行う必要があります。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>以下の構成パラメータはすべてクラスタ全体に適用されるため、一度設定すれば、各ノードで個別に行う必要はありません。</p>
</main>

### ステップ1：Java環境の起動に関する設定

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>以下の操作はすべてsysテナントで実行します。</p>
</main>

1. 外部テーブルのSDK（Java SDK）からのアクセスを許可するため、Java環境を有効にします。

    **コマンド例：**

    ```sql
    ALTER SYSTEM SET ob_enable_java_env = true;
    ```

    <!-- 该设置的详细介绍信息，参见 [ob_enable_java_env](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16630.ob_enable_java_env.md)。 -->

2. 現在のOBServer実行ノード上のJavaホームディレクトリを設定します。

    <main id="notice" type='explain'>
      <h4>説明</h4>
      <p>このパスは、OpenJDK Javaのインストールパスを指定します。</p>
    </main>

    **コマンド例：**

    ```sql
    ALTER SYSTEM SET ob_java_home = "/home/admin/rpm/openlogic-openjdk-8u422-b05-linux-x64";
    ```

    <!-- 该设置的详细介绍信息，参见 [ob_java_home](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16635.ob_java_home.md)。 -->

3. OBServer起動時にJVMが読み込む実行用依存JARパッケージのパスを設定します

    <main id="notice" type='explain'>
      <h4>説明</h4>
      <p>このパスは、JARパッケージのRPMインストールパスを指定します。</p>
    </main>

    **コマンド例：**

    ```sql
    ALTER SYSTEM SET ob_java_connector_path = "/home/admin/oceanbase/jni_packages/v1.0.0";
    ```

    <!-- 该设置的详细介绍信息，参见 [ob_java_connector_path](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16640.ob-java-connector-path.md)。 -->

4. Java環境の起動に関する関連設定を行います。

   1. 対応するログフォルダパスを作成します。

       ```shell
       mkdir -p /home/user/jvmlogs
       mkdir -p /home/user/jvmlogs/heapdumps
       ```

   2. Java実行時のJVM起動オプションを設定します。

       **示例如下：**

       ```sql
       ALTER SYSTEM SET ob_java_opts="-Xmx2048m -Xmn2048m -XX:-CriticalJNINatives -Djdk.lang.processReaperUseDefaultStackSize=true -Xrs -XX:+HeapDumpOnOutOfMemoryError -Xloggc:/home/admin/gc.log -XX:+PrintGCDetails -XX:+PrintGCDateStamps -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/home/admin/heapdumps/ -XX:+UseConcMarkSweepGC -XX:+UseParNewGC -XX:CMSInitiatingOccupancyFraction=75 -XX:+UseCMSInitiatingOccupancyOnly -XX:+CMSClassUnloadingEnabled -XX:+TieredCompilation -XX:+ExplicitGCInvokesConcurrentAndUnloadsClasses ";
       ```

       <!-- 该设置的详细介绍信息，参见 [ob_java_opts](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16650.ob_java_opts.md)。 -->

       <main id="notice" type='notice'>
         <h4>注意</h4>
         <p><ul><li>このパラメータの変更を反映するには、observerプロセスの再起動が必要です。現在のHDFS連携では、メモリコピーはHDFSデータストリームから直接C++のメモリヒープに行われるため、<code>-Xmx2048m -Xms2048m</code>の設定値は適宜小さくすることができます。</li><li>GCログファイルは、設定されたフォルダパスが存在する場合にのみ生成されます。パスが存在しない場合、ログは生成されません。</li></ul></p>
       </main>

5. (オプション) ODPSでJava SDKを使用するための設定を行います。

    <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>HDFS Java SDKではこの設定は不要です。その他の設定はすべて同じです。</p>
    </main>

    Java SDKを使用するには、`_use_odps_jni_connector`を`true`に設定する必要があります。

    ```sql
    ALTER SYSTEM SET _use_odps_jni_connector = true;
    ```

### ステップ2：LD_LIBRARY_PATHの設定

OceanBase 数据库的 JNI SDK 作为扩展功能，通过动态库加载机制实现。为确保功能可用性，需在所有 OBServer 节点上配置动态库搜索路径，即设置 `LD_LIBRARY_PATH` 环境变量，且对应 OBServer 节点都应配置才可使用。
OceanBaseデータベースのJNI SDKは拡張機能として、動的ライブラリの読み込みメカニズムによって実現されています。機能の可用性を確保するためには、すべてのOBServerノードで、`LD_LIBRARY_PATH`環境変数として動的ライブラリの検索パスを適切に設定する必要があります。

**設定例：**

```shell
$ vim ~/.bashrc
export LD_LIBRARY_PATH=/home/admin/rpm/openlogic-openjdk-8u422-b05-linux-x64/jre/lib/amd64/server:/usr/local/oceanbase/deps/devel/lib

$ source ~/.bashrc
```

### ステップ3：observerプロセスの再起動

すべてのマシンでobserverプロセスを停止し、その後再起動します。

1. `admin`ユーザーに切り替えます。

    ```shell
    [admin@xxx /home/admin/oceanbase/etc]# su - admin
    ```

2. observerプロセスを停止します。

    ```shell
    -bash-4.2$ kill -9 `pidof observer`
    ```

3. observerプロセスを再起動します。

    ```shell
    -bash-4.2$ cd /home/admin/oceanbase && /home/admin/oceanbase/bin/observer
    ```

    <main id="notice" type='explain'>
      <h4>説明</h4>
      <p>observerプロセスを再起動する際、起動パラメータを再度指定する必要はありません。前回の起動パラメータが設定ファイルに保存されているためです。</p>
    </main>
