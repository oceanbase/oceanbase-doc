# （オプション）クロックソースの設定

OceanBase関連製品間では、時間について暗黙の関連性があります。そのため、OceanBase製品のすべてのサーバーの物理時刻は同期されている必要があり、誤差はできるだけ2秒以内、できればそれ以下に抑える必要があります。したがって、クラスタ内の複数ノードおよびOCPノードのクロックには、クロック同期サービスであるNTPまたはchronyを設定し、すべてのノードのクロック偏差を2秒以内に保証する必要があります。本記事では、クラスタ内の複数のマシンにNTPクロックソースを設定する方法について説明します。

OceanBaseデータベースを単一マシンでインストールしている場合は、この設定は不要です。

## 前提条件

NTPクロックソースを設定する前に、すべてのマシンで`root`ユーザー権限を持っていることを確認してください。

## 手順

以下の手順に従って、NTPクロック同期を設定します。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>通常、Linuxに組み込まれているNTPサービスを使用して時間を同期できます。現在のマシン環境に安定して信頼性の高いNTPサーバーがある場合は、それをすべてのサーバーのNTPソースとして選択します。ない場合は、固定の1台のサーバーを選択し、それをNTPソースとして使用します。</p>
  </main>

1. 各マシンでYUMパッケージマネージャを使用してNTPをインストールします。

   ```shell
   [root@xxx /]# yum install ntp ntpdate -y
   ```

2. `ntp.conf`ファイルを設定します。

   ```shell
   [root@xxx /]# vi /etc/ntp.conf
   restrict default ignore
   restrict 127.0.0.1
   restrict 192.168.0.0 mask 255.255.0.0

   driftfile /var/lib/ntp/drift
   pidfile /var/run/ntpd.pid
   #logfile /var/log/ntp.log

   # local clock
   server 127.127.1.0
   fudge 127.127.1.0 stratum 10

   server 192.168.XX.XX iburst minpoll 4 maxpoll 6
   ```

   パラメータの説明：

   * `restrict`は、IPアドレスに関連するクロック同期コマンドの権限を指定するために使用されます。

      ```shell
      restrict [IP] mask [netmask_IP] [parameter]
      ```

      `parameter`には`ignore`、`nomodify`、`noquery`、`notrap`、`notrust`などが含まれます。`ignore`はデフォルトですべてのタイプのNTP同期を拒否します。

   * `server`は、上位NTPソースサーバーを指定するために使用されます。

      ```shell
      server [IP or hostname] [prefer]
      ```

      上位NTPソースサーバーがない場合、127.127.1.0に設定することができます。これは、ローカルマシンがNTPソースサーバーとして機能することを意味します。

3. NTP同期サービスを再起動します。

   ```shell
   [root@xxx /]# systemctl restart ntpd
   [root@xxx /]# systemctl status ntpd
   ```

4. NTP同期状態を確認します。

   <main id="notice" type='explain'>
     <h4>説明</h4>
     <p>NTPサービスが起動したばかりの場合は、しばらく待ってからntpstatコマンドを実行してください。</p>
   </main>

   ```shell
   [root@xxx /]# ntpstat
   [root@xxx /]# ntpq
   remote          refid       st  t  when  poll reach delay offset jitter
   ========================================================================
   LOCAL(0)        .LOCL.      10  l  589   64   0     0.000 0.000  0.000
   *192.168.XX.XX  xxx.xxx.xxx.xxx  2   u  18    64   377   1.591 0.249  0.054
   ```

   コマンド ntpq の結果パラメータの意味：

   * `remote`：使用中のNTPサーバーを表します。`*` は現在選択されているNTPサーバーを表します。`LOCAL` はローカルを表します。`x` は使用されなくなったことを表します。`-` は使用されなくなったことを表します。`+` は優先順位が高いことを表します。`#` は良好だが使用されていないことを表します。
   * `refid`：リモートNTPサーバーが使用する上位レベルのNTPサーバー。`INIT` は取得中を表します。
   * `st`：リモートNTPサーバーのStratum（レベル）。
   * `when`：最終同期から現在までの時間（デフォルトは秒、`h` は時間、`d` は日を表します）。
   * `poll`：同期の頻度、単位：秒。
   * `delay`：ローカルからリモートNTPサーバーまでの往復時間（ミリ秒単位）。
   * `offset`：ローカルとリモートNTPサーバーの時刻偏差（ミリ秒単位）。
   * `jitter`：ローカルとリモートNTPサーバーの時刻偏差の平均偏差（ミリ秒単位）。

5. 最終的なチェック方法。

   最終的な同期遅延のチェックは以下を基準とします：

   ```shell
   [root@xxx /]# clockdiff 192.168.XX.XX
   ..................................................
   host=192.168.XX.XX rtt=1(0)ms/1ms delta=0ms/0ms Sat Apr 18 14:41:40 2020
   ```

6. （オプション）手動同期方法。

   時刻に常に大きな誤差がある場合は、`ntpdate` コマンドを使用して手動で時刻を修正できます。これは自動同期サービスと競合するため、事前にNTPサービスを停止する必要があります。

   ```shell
   [root@xxx /]# systemctl stop ntpd
   [root@xxx /]# ntpdate -u 192.168.XX.XX
   18 Apr 14:54:20 ntpdate[108001]: adjust time server 192.168.XX.XX offset -0.000180 sec
   ```

   この方法が有効であれば、システムのcrontabに設定します。

   ```shell
   [root@xxx /]# crontab -e
   * * * * * /sbin/ntpdate -u 192.168.XX.XX 2>&1 1>>/tmp/ntpupdate.log
   ```

7. （オプション）ファイアウォールルール。

   標準的な環境ではファイアウォールを無効にする必要があります。サーバー環境でどうしてもファイアウォールを有効にする必要がある場合は、以下のルールを参考に操作してください。

   ```shell
   [root@xxx /]# iptables --A INPUT --p udp --i eth0 --s 192.168.1.0/16 --dport 123 --j ACCEPT
   [root@xxx /]# systemctl restart ntpd
   ```
