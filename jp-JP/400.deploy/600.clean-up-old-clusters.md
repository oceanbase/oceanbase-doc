# 古いクラスターのクリーンアップ

以前 OceanBase クラスターをデプロイしたマシンに、新しい OceanBase クラスターを再デプロイする場合は、新しいクラスターをデプロイする前に、古いクラスターをクリーンアップしてください。

本記事では 3 つのシナリオをご紹介します。クラスターの状況に合わせて、適切なシナリオをご参照ください。

## 古いクラスターのクリーンアップに関する提案

古いクラスター環境をクリーンアップする前に、データのバックアップを行うことを推奨します。これにより、データの完全性と安全性を保証し、将来復元や移行でデータが必要になった場合に備えて、データのレプリカを確保することができます。

OceanBase クラスターのデータバックアップ関連情報については、[バックアップ前の準備](https://en.oceanbase.com/docs/common-oceanbase-database-10000000001971546) を参照してください。

## シナリオ 1：コマンドラインを使用してデプロイされた OceanBase クラスター

マシン上のクラスターがコマンドラインを使用して手動でデプロイされた場合は、このセクションを参照してクリーンアップすることができます。

### 手順 1：サービスの停止とアンインストール

古い observer プロセスを停止し、実行されないことを確保します。次に、関連するデータベースソフトウェアをアンインストールします。手順は以下のとおりです：

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>observer プロセスを停止すると、OceanBase データベースは使用できなくなります。そのため、以下の操作を実行する前に、クラスターが既に使用されていないこと、およびバックアップが必要なデータのバックアップが完了していることをもう一度確認してください。データの損失やシステムが使用できなくなることを避けるため、慎重に操作してください。</p>
</main>

1. 以下のコマンドを使用して、observer プロセスが存在するかどうかを確認します。

   ```shell
   ps -ef|grep observer
   ```

2. (オプション) observer プロセスを停止します。

   マシンに observer プロセスが存在する場合、以下のコマンドを使用して古い observer プロセスを停止してください：

   ```shell
   kill -9 `pidof observer`
   ```

3. 以下のコマンドを使用して、インストール済みの OceanBase データベース RPM パッケージ名を確認します。

   ```shell
   rpm -qa|grep oceanbase
   ```

4. 以下のコマンドを使用して、インストール済みの OceanBase データベース RPM パッケージをアンインストールします。

   ```shell
   sudo rpm -e $rpm_name
   ```

   ここで、`$rpm_name` はアンインストールするソフトウェアパッケージの名前です。

   以下のコマンドを使用すると、RPM パッケージのアンインストールが完了したかどうかを確認できます。

   ```shell
   rpm -ql $rpm_name
   ```

5. すべての OBServer ノード上のサービスの停止とアンインストールが終了するまで、手順 1 ～ 4 を繰り返します。

### 手順 2：データベースファイルのクリーンアップ

データファイル、ログファイル、その他の一時ファイルを含む古いデータベースファイルを削除します。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>以下の削除操作は元に戻すことができません。つまり、削除されたファイルとディレクトリを復元することはできません。そのため、以下のコマンドを実行する前に、削除するディレクトリ内のデータが使用されないことを確認してください。</p>
</main>

1. 以下のコマンドを使用して、observer プロセスの実行ログディスクファイルを削除します。

   ```shell
   sudo rm -rf /home/admin/oceanbase/*
   ```

2. 以下のコマンドを使用して、observer プロセスのログディスクファイルを削除します。

   ```shell
   sudo rm -rf /data/log1/*
   ```

3. 以下のコマンドを使用して、observer プロセスのデータディスクファイルを削除します。

   ```shell
   sudo rm -rf /data/1/*
   ```

4. すべての OBServer ノード上の古いデータベースファイルの削除が終了するまで、手順 1 ～ 3 を繰り返します。

## シナリオ 2：obd を使用してデプロイされた OceanBase クラスター

マシン上のクラスターが obd コマンドを使用してデプロイされた場合は、このセクションを参照してクリーンアップすることができます。

1. クラスターのステータスを確認する

   ```shell
   obd cluster list
   ```

   出力は以下のとおりです。詳細なステータスの紹介については、[obd cluster list](https://en.oceanbase.com/docs/community-obd-en-10000000001181575) を参照してください。

   ```shell
   +--------------------------------------------------------+
   |                     Cluster List                       |
   +------+-------------------------------+-----------------+
   | Name | Configuration Path            | Status (Cached) |
   +------+-------------------------------+-----------------+
   | test | /home/admin/.obd/cluster/odp  | running         |
   | demo | /home/admin/.obd/cluster/demo | running         |
   +------+-------------------------------+-----------------+
   ```

2. スタンバイテナントが存在するかどうかを確認する

   ここでは test クラスターを例に操作手順を説明します。実際の状況に応じてクラスタ名を変更してください。

   ```shell
   obd cluster tenant show test -g
   ```

   以下のように出力される場合、スタンバイテナントが存在せず、クラスターには sys テナントのみが存在することを示します。クラスター内のテナントにスタンバイテナントが存在する場合の出力内容とフィールドの意味の詳細については、[obd を使用したプライマリ / スタンバイテナントのデプロイ](https://en.oceanbase.com/docs/community-obd-en-10000000001181619) を参照してください。

   ```shell
   +-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
   |                                                                                     tenant base info                                                                                    |
   +-------------+-------------+--------------------+--------------+---------+---------+-------------+---------------------+---------------------+---------------+-------------+-------------+
   | tenant_name | tenant_type | compatibility_mode | primary_zone | max_cpu | min_cpu | memory_size | max_iops            | min_iops            | log_disk_size | iops_weight | tenant_role |
   +-------------+-------------+--------------------+--------------+---------+---------+-------------+---------------------+---------------------+---------------+-------------+-------------+
   | sys         | SYS         | MYSQL              | RANDOM       | 3.0     | 3.0     | 1024M       | 9223372036854775807 | 9223372036854775807 | 2048M         | 3           | PRIMARY     |
   +-------------+-------------+--------------------+--------------+---------+---------+-------------+---------------------+---------------------+---------------+-------------+-------------+
   ```

3. (オプション) プライマリ / スタンバイテナントのデカップリング

   クラスター内のテナントにスタンバイテナントが存在する場合、クラスターを破棄する時にエラーが報告されます。このとき、プライマリ / スタンバイテナントのデカップリングか、破棄コマンドの強制実行を選択することができます。クラスターを破棄すると、スタンバイテナントは使用できなくなります。実際のシナリオに応じて、この手順を実行するかどうかを選択してください。

   プライマリ / スタンバイテナントのデカップリング操作に関する詳細手順については、[プライマリ / スタンバイテナントのデカップリング](https://en.oceanbase.com/docs/community-obd-en-10000000001181620) を参照してください。

4. クラスターを破棄する

   <main id="notice" type='notice'>
     <h4>注意</h4>
     <p><code>obd cluster destroy</code> コマンドは元に戻すことができません。observer プロセスの停止と同時に、データベースファイルが削除されます。そのため、以下のコマンドを実行する前に、クラスターが使用されていないこと、およびバックアップが必要なデータのバックアップが完了していることを確認してください。</p>
   </main>

   ここでは test クラスターを例に操作手順を説明します。実際の状況に応じてクラスタ名を変更してください。

   ```shell
   obd cluster destroy test -f [--igs]
   ```

   `-f` は、作業ディレクトリで実行中のプロセスが検出されると、プロセスを強制的に停止し、クラスターを破棄することを意味します。

   `--igs` は、クラスター内のテナントが他のクラスターにスタンバイテナントを持つ場合、`obd cluster destroy` コマンドが強制的に実行されることを意味します。

## シナリオ 3：systemd を使用してデプロイされた OceanBase クラスター

マシン上のクラスターが systemd を使用してデプロイされた場合は、このセクションを参照してクリーンアップすることができます。

1. OceanBase データベースを停止する

   ```shell
   [admin@test001 ~]$ sudo systemctl stop oceanbase
   ```

2. OceanBase データベースをアンインストールする

   1. OceanBase データベースソフトウェアパッケージを削除する

      オンラインインストール方法では、以下のコマンドを実行することができます：

      ```shell
      [admin@test001 ~]$ sudo yum erase package
      ```

      `package` は削除対象のソフトウェアパッケージ名に置き換える必要があります。ソフトウェアパッケージ名は `yum list | grep oceanbase` コマンドで確認できます。

      オフラインインストール方式では、以下のコマンドを実行することができます：

      ```shell
      [admin@test001 ~]$ sudo rpm -e package
      ```

      `package` は削除対象のソフトウェアパッケージ名に置き換える必要があります。ソフトウェアパッケージ名は `rpm -qa | grep oceanbase` コマンドで確認できます。

   2. (オプション) OceanBase データベースのデータを削除する

      <main id="notice" type='explain'>
        <h4>説明</h4>
        <p>ソフトウェアパッケージを削除すると、環境内の OceanBase データベースはアンインストールされていますが、OceanBase データベースのデータは残ります。後日 OceanBase データベースを再デプロイする場合、該当する OceanBase データベースのデータを表示および操作することができます。この手順で OceanBase データベースのデータを削除すると、デプロイ済みの OceanBase データベースは完全にアンインストールされます。そのため、以下のコマンドを実行する前に、削除するディレクトリ内のデータが使用されないことを確認してください。</p>
      </main>

      OceanBase データベースのインストールディレクトリを削除する

      ```shell
      [admin@test001 ~]$ sudo rm -rf /home/admin/oceanbase
      ```

      OceanBase データベースのデータディレクトリを削除する

      ```shell
      [admin@test001 ~]$ sudo rm -rf /var/lib/oceanbase
      ```

## 関連ドキュメント

* OceanBase クラウドプラットフォーム (OceanBase Cloud Platform、OCP) を使用して OceanBase クラスターを管理している場合、関連する操作インターフェースのヒントに従ってクラスターを削除します。操作の詳細については、[クラスターの削除](https://en.oceanbase.com/docs/common-ocp-10000000001187628) を参照してください。

* Kubernetes 環境で OceanBase データベースをデプロイしている場合、ob-operator を使用して OceanBase クラスターを管理することができます。クラスター削除操作の詳細については、[クラスターの削除](https://en.oceanbase.com/docs/community-ob-operator-doc-en-10000000001195658) を参照してください。
