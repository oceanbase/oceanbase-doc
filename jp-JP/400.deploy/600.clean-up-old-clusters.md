# 古いクラスタの削除

マシンにOceanBaseクラスタがデプロイされていたことがあり、現在新しいOceanBaseクラスタを再デプロイしたい場合は、新しいクラスタをデプロイする前に古いクラスタを削除してください。

本記事では3つのシナリオに分けて説明します。お使いのクラスタの状況に応じて、適切なシナリオを選択して参照してください。

## 古いクラスタの削除に関する推奨事項

古いクラスタ環境を削除する前に、データのバックアップを行うことを推奨します。これにより、データの完全性と安全性が確保され、将来必要になった場合にデータのレプリカを保持しておき、復元や移行を行うことができます。

OceanBaseクラスタのデータバックアップに関する詳細は、[バックアップ前の準備](../600.manage/600.backup-and-recovery/400.data-backup/100.preparation-before-data-backup.md)を参照してください。

## シナリオ1：コマンドラインでデプロイされたOceanBaseクラスタ

マシン上のクラスタがコマンドラインで手動でデプロイされた場合は、このセクションの内容を参照して削除することができます。

### ステップ１：サービスの停止とアンインストール

古いobserverプロセスを停止し、それらが実行されないようにします。次に、関連するデータベースソフトウェアをアンインストールします。手順は以下のとおりです：

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>observerプロセスを停止すると、OceanBaseデータベースが使用できなくなります。そのため、以下の操作を実行する前に、クラスタが使用されていないこと、およびバックアップが必要なデータのバックアップが完了していることを再度確認してください。データ損失やシステムの利用不能を防ぐため、慎重に操作してください。</p>
</main>

1. 以下のコマンドを使用して、observerプロセスが存在するかどうかを確認します。

   ```shell
   ps -ef|grep observer
   ```

2. (オプション) observerプロセスを停止します。

   マシン上にobserverプロセスが存在する場合は、以下のコマンドを使用して古いobserverプロセスを停止します：

   ```shell
   kill -9 `pidof observer`
   ```

3. 以下のコマンドを使用して、インストール済みのOceanBaseデータベースRPMパッケージ名を確認します。

   ```shell
   rpm -qa|grep oceanbase
   ```

4. 以下のコマンドを使用して、インストール済みのOceanBaseデータベースRPMパッケージをアンインストールします。

   ```shell
   sudo rpm -e $rpm_name
   ```

   ここで、`$rpm_name` はアンインストールするソフトウェアパッケージの名前です。

   以下のコマンドを使用して、RPMパッケージのアンインストールが完了したかどうかを確認できます。

   ```shell
   rpm -ql $rpm_name
   ```

5. ステップ1～4を繰り返し、すべてのOBServerノードのサービスを停止し、アンインストールします。

### ステップ2：データベースファイルの削除

データファイル、ログファイル、その他の一時ファイルを含む古いデータベースファイルを削除します。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>以下の削除操作は不可逆的であり、削除後のファイルやディレクトリは復元できません。そのため、以下のコマンドを実行する前に、削除対象のディレクトリ内のデータが使用されていないことを確認してください。</p>
</main>

1. 以下のコマンドを使用して、observerプロセスの実行ログディスクファイルを削除します。

   ```shell
   sudo rm -rf /home/admin/oceanbase/*
   ```

2. 以下のコマンドを使用して、observerプロセスのログディスクファイルを削除します。

   ```shell
   sudo rm -rf /data/log1/*
   ```

3. 以下のコマンドを使用して、observerプロセスのデータディスクファイルを削除します。

   ```shell
   sudo rm -rf /data/1/*
   ```

4. ステップ1～3を繰り返し、すべてのOBServerノードから古いデータベースファイルを削除します。

## シナリオ2：obdを使用してデプロイされたOceanBaseクラスタ

マシン上のクラスタがobdコマンドによってデプロイされた場合は、このセクションの内容を参照してクリーンアップを行うことができます。

1. クラスタの状態を確認する

   ```shell
   obd cluster list
   ```

   出力は以下のようになります。詳細な状態の説明については、[obd cluster list](https://www.oceanbase.com/docs/community-obd-cn-1000000000634909)を参照してください。

   ```shell
   +--------------------------------------------------------+
   |                     Cluster List                       |
   +------+-------------------------------+-----------------+
   | Name | Configuration Path            | Status (Cached) |
   +------+-------------------------------+-----------------+
   | test | /home/admin/.obd/cluster/odp  | running         |
   | demo | /home/admin/.obd/cluster/demo | running         |
   +------+-------------------------------+-----------------+
   ```

2. スタンバイテナントが存在するかどうかを確認する

   ここではtestクラスタを例に操作を説明します。実際の状況に応じてクラスタ名を変更する必要があります。

   ```shell
   obd cluster tenant show test -g
   ```

   出力が以下のようになる場合、スタンバイテナントは存在せず、クラスタ内にはsysテナントのみが存在します。クラスタ内のテナントにスタンバイテナントが存在する場合、その出力内容とフィールドの意味の詳細については、[obdを使用したプライマリ/スタンバイテナントのデプロイ](https://www.oceanbase.com/docs/community-obd-cn-1000000000634947)を参照してください。

   ```shell
   +-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
   |                                                                                     tenant base info                                                                                    |
   +-------------+-------------+--------------------+--------------+---------+---------+-------------+---------------------+---------------------+---------------+-------------+-------------+
   | tenant_name | tenant_type | compatibility_mode | primary_zone | max_cpu | min_cpu | memory_size | max_iops            | min_iops            | log_disk_size | iops_weight | tenant_role |
   +-------------+-------------+--------------------+--------------+---------+---------+-------------+---------------------+---------------------+---------------+-------------+-------------+
   | sys         | SYS         | MYSQL              | RANDOM       | 3.0     | 3.0     | 1024M       | 9223372036854775807 | 9223372036854775807 | 2048M         | 3           | PRIMARY     |
   +-------------+-------------+--------------------+--------------+---------+---------+-------------+---------------------+---------------------+---------------+-------------+-------------+
   ```

3. (オプション) プライマリ/スタンバイテナントの分離

   クラスタ内のテナントにスタンバイテナントが存在する場合、クラスタを破棄する際にエラーが発生します。この場合、プライマリ/スタンバイテナントを分離するか、強制的に破棄コマンドを実行するかを選択できます。クラスタが破棄された後、スタンバイテナントは使用できなくなります。実際のシナリオに応じて、この手順を実行するかどうかを選択できます。

   プライマリ/スタンバイテナントの分離の詳細な操作については、[プライマリ/スタンバイテナントの分離](https://www.oceanbase.com/docs/community-obd-cn-1000000000634948)を参照してください。

4. クラスタを破棄する

   <main id="notice" type='notice'>
     <h4>注意</h4>
     <p><code>obd cluster destroy</code> コマンドは不可逆であり、observerプロセスを停止すると同時にデータベースファイルも削除されます。したがって、以下のコマンドを実行する前に、クラスタが使用されていないこと、およびバックアップが必要なデータのバックアップが完了していることを確認してください。</p>
   </main>

   ここではtestクラスタを例に操作を説明します。実際の状況に応じてクラスタ名を変更する必要があります。

   ```shell
   obd cluster destroy test -f [--igs]
   ```

   `-f` は、作業ディレクトリ内に実行中のプロセスが検出された場合、プロセスを強制停止し、クラスタを破棄することを意味します。

   `--igs` は、クラスタ内のテナントが他のクラスタにスタンバイテナントを持つ場合、`obd cluster destroy` コマンドを強制的に実行することを意味します。

## シナリオ3：systemdを使用してデプロイされたOceanBaseクラスタ

マシン上のクラスタがsystemdによってデプロイされている場合は、このセクションの内容を参照してクリーンアップすることができます。

1. OceanBaseデータベースを停止します。

   ```shell
   [admin@test001 ~]$ sudo systemctl stop oceanbase
   ```

2. OceanBaseデータベースをアンインストールします。

   1. OceanBaseデータベースのソフトウェアパッケージを削除します。

      オンラインインストール方式では、次のコマンドを実行します：

      ```shell
      [admin@test001 ~]$ sudo yum erase package
      ```

      `package` は削除対象のソフトウェアパッケージ名に置き換える必要があります。ソフトウェアパッケージ名は、`yum list | grep oceanbase` コマンドで確認できます。

      オフラインインストール方式では、次のコマンドを実行します：

      ```shell
      [admin@test001 ~]$ sudo rpm -e package
      ```

      `package` は削除対象のソフトウェアパッケージ名に置き換える必要があります。ソフトウェアパッケージ名は、`rpm -qa | grep oceanbase` コマンドで確認できます。

   2. (オプション) OceanBaseデータベースのデータを削除します。

      <main id="notice" type='explain'>
        <h4>説明</h4>
        <p>ソフトウェアパッケージを削除すると、環境内のOceanBaseデータベースはアンインストールされますが、OceanBaseデータベースのデータは残ります。後でOceanBaseデータベースを再デプロイする場合でも、そのOceanBaseデータベースのデータを確認および操作できます。この手順でOceanBaseデータベースのデータを削除すると、デプロイしたOceanBaseデータベースは完全にアンインストールされます。そのため、以下のコマンドを実行する前に、削除するディレクトリ内のデータが使用されなくなっていることを確認してください。</p>
      </main>

      OceanBaseデータベースのインストールディレクトリを削除します。

      ```shell
      [admin@test001 ~]$ sudo rm -rf /home/admin/oceanbase
      ```

      OceanBaseデータベースのデータディレクトリを削除します。

      ```shell
      [admin@test001 ~]$ sudo rm -rf /var/lib/oceanbase
      ```

## 関連ドキュメント

* OceanBaseクラスタをOceanBaseクラウドプラットフォーム(OceanBase Cloud Platform、OCP)で管理している場合は、関連する操作画面で指示に従ってクラスタを削除するだけです。詳細な操作については、[クラスタの削除](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-1000000000125896)を参照してください。

* Kubernetes環境でOceanBaseデータベースをデプロイしている場合は、ob-operatorを使用してOceanBaseクラスタを管理し、クラスタの削除に関する詳細な操作については、[クラスタの削除](https://www.oceanbase.com/docs/community-ob-operator-doc-1000000000659349)を参照してください。
