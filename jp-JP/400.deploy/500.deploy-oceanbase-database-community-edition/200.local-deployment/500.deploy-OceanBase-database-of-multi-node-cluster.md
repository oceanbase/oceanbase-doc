# コマンドラインを使用したOceanBaseデータベースの本番環境へのデプロイ

本記事では、obdのコマンドラインを使用してOceanBaseデータベースの本番環境をデプロイする方法について説明します。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>obdは、コマンドラインを使用したOceanBaseデータベースの本番環境へのデプロイに加えて、GUIを使用したOceanBaseクラスタ環境へのデプロイもサポートしています。obdのGUIを使用したデプロイを推奨します。詳細な手順については、<a href="400.deploy-by-ui/100.deploy-by-obd.md">obd GUIを使用したOceanBaseクラスタのデプロイ</a>を参照してください。</p>
</main>

## 用語解説

* コントロールマシン

  obdがインストールされたマシンで、OceanBaseクラスタを管理し、OceanBaseクラスタのインストールパッケージとクラスタ構成情報を格納します。

* ターゲットマシン

  OceanBaseデータベースがインストールされたマシンです。

* OceanBaseデータベース

  完全に自社開発されたエンタープライズ向けネイティブ分散型データベースです。詳細については、[OceanBaseデータベースドキュメント](https://www.oceanbase.com/docs/oceanbase-database-cn)を参照してください。

* obd

  OceanBase Deployerの略称で、OceanBaseのインストールおよびデプロイツールです。詳細については、[OceanBaseインストールおよびデプロイツールドキュメント](https://www.oceanbase.com/docs/obd-cn)を参照してください。

* ODP

  OceanBase Database Proxyの略称で、OceanBaseデータベース専用のプロキシサーバーです。OBDP（OBProxyとも呼ばれます）。詳細については、[OceanBaseデータベースプロキシドキュメント](https://www.oceanbase.com/docs/odp-doc-cn)を参照してください。

* OBAgent

  OBAgentはOceanBaseデータベースのモニタリング収集フレームワークであり、プッシュ方式とプル方式の両方のデータ収集モードをサポートしており、さまざまなアプリケーションシナリオに対応できます。

* obconfigserver

  OceanBase Configserverの略称で、OceanBaseのメタデータ登録、ストレージ、およびクエリサービスを提供します。詳細については、[ob-configserver](https://github.com/oceanbase/obclient/blob/master/README.md)を参照してください。

* Grafana

  Grafanaはオープンソースのデータ可視化ツールであり、データソース内の各種指標データを可視化表示することで、システムの稼働状態や性能指標をより直感的に理解できるようにします。詳細については、[Grafana公式サイト](https://grafana.com/)を参照してください。

* Prometheus

  Prometheusはオープンソースのサービス監視システムおよび時系列データベースであり、汎用的なデータモデルと迅速なデータ収集、ストレージ、およびクエリインターフェースを提供します。詳細については、[Prometheus公式サイト](https://prometheus.io/)を参照してください。

## 前提条件

OceanBaseデータベースをデプロイする前に、以下の情報を確認してください：

* マシンがソフトウェアおよびハードウェア要件を満たしていること。詳細については、[ソフトウェアおよびハードウェア要件](../200.local-deployment/100.requirements-for-software-and-hardware.md)を参照してください。

* 本番環境では、環境および構成チェックが必要です。具体的な操作については、[デプロイ前の設定](200.environment-and-configuration-checks/100.view-resources-optional.md)の章を参照してください。

* コントロールマシンにobdとOBClientクライアントがインストール済みであること。最新バージョンのインストールを推奨します。詳細については、公式Webサイトの「OceanBaseインストール・デプロイツール」ドキュメントの[クイックスタート／obdのインストール](https://www.oceanbase.com/docs/common-obd-cn-1000000003892241)および[OBClientドキュメント](https://github.com/oceanbase/obclient/blob/master/README.md)を参照してください。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>OceanBase All in Oneのインストール時には、obdとOBClientクライアントが自動的にインストールされます。したがって、以下の手順1に従ってOceanBase All in Oneをダウンロードおよびインストールする予定がある場合は、この要件を無視しても構いません。</p>
  </main>

  <ul>
  <li>
  <p>本番環境では、ODPとアプリケーションを同一マシン上にデプロイすることを推奨します。これにより、ODPがアプリケーションにアクセスする時間を節約できます。各アプリケーションのサーバー上にODPサービスを1つデプロイできます。</p>

  </li>
  <li>
  <p>スタンドアロンデプロイの手順については、OceanBaseインストール・デプロイツールのドキュメント内の<a href="https://www.oceanbase.com/docs/common-obd-cn-1000000003754549">OceanBaseクラスタのデプロイ</a>を参照してください。</p>
  </li>
  </ul>

## 手順

<main id="notice" type='notice'>
  <h4>注意</h4>
  <ul>
  <li>
  <p>以下の内容は、x86アーキテクチャのCentOS Linux 7.9イメージを環境としています。他の環境では若干異なる場合があります。</p>
  </li>
  <li>
  <p>OceanBaseクラスタをデプロイする前に、データのセキュリティを確保するため、rootユーザー以外に切り替えることを推奨します。</p>
  </li>
  </ul>
</main>

### ステップ１：(オプション) OceanBase All in Oneをダウンロードしてインストールする

V4.0.0以降、OceanBaseは統一されたインストールパッケージであるOceanBase All in Oneを提供しています。この統一されたインストールパッケージを使用すると、obd、OceanBaseデータベース、ODP、OBAgentなどのコンポーネントを一度にインストールできます。

また、必要に応じて[OceanBaseソフトウェアダウンロードセンター](https://en.oceanbase.com/softwarecenter)から一部のコンポーネントを選択してダウンロード・インストールしたり、特定のコンポーネントのバージョンを指定してインストールすることもできます。

#### オンラインインストール

マシンがネットワークに接続されている場合は、以下のコマンドを実行してオンラインインストールを行うことができます。

```shell
[admin@test001 ~]$ bash -c "$(curl -s https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/download-center/opensource/oceanbase-all-in-one/installer.sh)"
[admin@test001 ~]$ source ~/.oceanbase-all-in-one/bin/env.sh
```

#### オフラインインストール

マシンがネットワークに接続できない場合は、以下の手順に従ってオフラインインストールを行います。

1. [OceanBaseソフトウェアダウンロードセンター](https://en.oceanbase.com/softwarecenter)から最新のOceanBase All in Oneインストールパッケージをダウンロードし、コントロールマシンの任意のディレクトリにコピーします。

2. インストールパッケージがあるディレクトリで、以下のコマンドを実行してインストールパッケージを解凍し、インストールします。

   ```shell
   [admin@test001 ~]$ tar -xzf oceanbase-all-in-one-*.tar.gz
   [admin@test001 ~]$ cd oceanbase-all-in-one/bin/
   [admin@test001 bin]$ ./install.sh
   [admin@test001 bin]$ source ~/.oceanbase-all-in-one/bin/env.sh
   ```

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p><code>which obd</code>および<code>which obclient</code>コマンドを実行することで、インストールが正常に完了したかどうかを確認できます。<code>.oceanbase-all-in-one</code>ディレクトリ内のobdおよびobclientのパスが見つかる場合、インストールは成功しています。</p>
</main>

### ステップ2：obdの設定

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>本記事はobd V3.5.0を例に操作ガイドを提供します。obdのバージョンによって設定ファイルが異なる場合がありますので、実際の設定ファイルに従ってください。obdに関するその他の詳細については、<a href="https://www.oceanbase.com/docs/obd-cn">OceanBaseインストールおよびデプロイメントツールドキュメント</a>を参照してください。</p>
</main>

OceanBaseクラスタをオフラインでデプロイする場合は、**ステップ1**を参照してコントロールマシンからOceanBase All in Oneをダウンロードしてインストールしてください。OceanBase All in Oneが提供するコンポーネントは相互適応テストを経ており、公式推奨バージョンです。

オフラインデプロイで、デプロイに必要なコンポーネントのバージョンに特別な要件がある場合は、[OceanBaseソフトウェアダウンロードセンター](https://en.oceanbase.com/softwarecenter)から対応するバージョンのコンポーネントのインストールパッケージをダウンロードし、ダウンロードしたインストールパッケージをコントロールマシンの任意のディレクトリにコピーします。そのディレクトリで以下のステップ1〜3に従って、インストールパッケージをobdのローカルイメージライブラリにアップロードします。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>オンラインでOceanBaseクラスタをデプロイする場合は、ステップ1〜3をスキップしてください。</p>
</main>

1. リモートリポジトリを無効にします。

   ```shell
   [admin@test001 rpm]$ obd mirror disable remote
   ```

   <main id="notice" type='explain'>
     <h4>説明</h4>
     <p>OceanBase All in Oneをインストールすると、リモートリポジトリがデフォルトで無効になります。<code>obd mirror list</code> コマンドで確認すると、Type=remoteに対応するEnabledがFalseに変更されているため、リモートイメージソースが無効になっていることを示しています。</p>
   </main>

2. インストールパッケージをローカルイメージライブラリに追加します。

   ```shell
   [admin@test001 rpm]$ obd mirror clone *.rpm
   ```

3. ローカルイメージライブラリ内のインストールパッケージリストを表示します。

   ```shell
   [admin@test001 rpm]$ obd mirror list local
   ```

4. 設定ファイルを選択します。

   マシン上のobdが直接ダウンロードによってインストールされた場合は、`/usr/obd/example` ディレクトリでobdが提供する設定ファイルのサンプルを確認できます。

   マシン上のobdがOceanBase All in Oneの解凍によってインストールされた場合は、`~/.oceanbase-all-in-one/obd/usr/obd/example` ディレクトリでobdが提供する設定ファイルのサンプルを確認できます。リソース条件に応じて、該当する設定ファイルを選択してください。

   <main id="notice" type='explain'>
     <h4>説明</h4>
     <p>設定ファイルには、スモールスペック開発モードとプロフェッショナル開発モードの2種類があり、両モードの設定ファイルの構成パラメータは基本的に同じですが、設定される仕様が若干異なります。実際のリソース条件に基づいて選択できます。</p>
     <ul>
     <li>
     <p>スモールスペック開発モード：個人デバイス（メモリ8GB以上）に適しており、設定ファイル名には <code>mini</code> または <code>min</code> の識別子が含まれます。</p>
     </li>
     <li>
     <p>プロフェッショナル開発モード：高スペックのECSまたは物理サーバー（利用可能なリソースが16コア64GB以上）に適しています。</p>
     </li>
     </ul>
   </main>

   シングルマシンデプロイを選択した場合、つまりターゲットマシンが1台のみの場合は、シングルマシンデプロイ設定ファイルを参照してください。

   * ローカルシングルマシンデプロイ設定例：mini-local-example.yaml、local-example.yaml

   * シングルマシンデプロイ設定例：mini-single-example.yaml、single-example.yaml

   * シングルマシンデプロイ+ODP設定例：mini-single-with-obproxy-example.yaml、single-with-obproxy-example.yaml

   デプロイを分散型に選択した場合、つまりターゲットマシンが複数の場合は、分散型インストール設定ファイルを参照してください。

   * OceanBaseデータベースの分散型デプロイ設定例：mini-distributed-example.yaml、distributed-example.yaml

   * OceanBaseデータベース+ODPの分散型デプロイ設定例：mini-distributed-with-obproxy-example.yaml、distributed-with-obproxy-example.yaml

   * すべてのコンポーネントの分散型デプロイ：all-components-min.yaml、all-components.yaml

5. 設定ファイルを修正します。

   <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>環境の実際の状況に応じて、以下のパラメータを修正する必要があります。</p>
   </main>

   1. 設定ファイルを作成します。

      ```shell
      vim deploy.yaml
      ```

      ここはあくまでも例です。実際の状況に応じて設定ファイル名をカスタマイズできます。

   2. ユーザー名とパスワードを修正します。

      ```yaml
      ## Only need to configure when remote login is required
      user:
        username: admin
      #   password: your password if need
        key_file: /home/admin/.ssh/id_rsa
      #   port: your ssh port, default 22
      #   timeout: ssh connection timeout (second), default 30
      ```

      `username` はターゲットマシンにログインするためのユーザー名であり、ユーザー名に `home_path` の書き込み権限があることを確認してください。`password` と `key_file` はどちらもユーザー認証に使用されますが、通常はどちらか一方のみを入力する必要があります。

      <main id="notice" type='notice'>
        <h4>注意</h4>
        <p>秘密鍵のパスを設定した後、秘密鍵にパスワードが不要な場合は、<code>password</code> をコメントアウトまたは削除してください。そうしないと、<code>password</code> が秘密鍵のパスワードとしてログインに使用され、検証に失敗する可能性があります。</p>
      </main>

   3. マシンのIPアドレス、ポート、関連ディレクトリを修正し、メモリ関連パラメータとパスワードを設定します。

      ```yaml
      oceanbase-ce:
        # version: 4.2.5.0
        servers:
          # Please don't use hostname, only IP can be supported
          - name: server1
            ip: 10.10.10.1
          - name: server2
            ip: 10.10.10.2
          - name: server3
            ip: 10.10.10.3
        global:
          devname: eth0
          cluster_id: 1
          # please set memory limit to a suitable value which is matching resource.
          memory_limit: 64G # The maximum running memory for an observer
          system_memory: 30G # The reserved system memory. system_memory is reserved for general tenants.
          datafile_size: 192G # Size of the data file.
          datafile_next: 200G
          datafile_maxsize: 1T
          log_disk_size: 192G # The size of disk space used by the clog files.
          scenario: htap
          enable_syslog_wf: false # Print system logs whose levels are higher than WARNING to a separate log file. The default value is true.
          max_syslog_file_count: 4 # The maximum number of reserved log files before enabling auto recycling. The default value is 0.
          enable_auto_start: true
          # observer cluster name, consistent with obproxy's cluster_name
          appname: obdemo
          mysql_port: 2881 # External port for OceanBase Database. The default value is 2881. DO NOT change this value after the cluster is started.
          rpc_port: 2882 # Internal port for OceanBase Database. The default value is 2882. DO NOT change this value after the cluster is started.
          obshell_port: 2886 # Operation and maintenance port for OceanBase Database.
          # The working directory for OceanBase Database. OceanBase Database is started under this directory. This is a required field.
          home_path: /home/admin/observer
          # The directory for data storage. The default value is $home_path/store.
          data_dir: /data
          # The directory for clog. The default value is the same as the data_dir value.
          redo_dir: /redo
          root_password: ****** # root user password, can be empty
          proxyro_password: ******** # proxyro user pasword, consistent with obproxy's observer_sys_password, can be empty
        server1:
          zone: zone1
        server2:
          zone: zone2
        server3:
          zone: zone3
      ```

      マシン内に矛盾する構成パラメータが存在する場合は、関連する構成パラメータを対応するserverに移動して設定できます。設定ファイル内で、対応するserverの設定の優先順位は `global` よりも高いです。例えば、2台のマシン間でポートが異なる場合：

      ```yaml
      server2:
        mysql_port: 3881
        rpc_port: 3882
        zone: zone2
      server3:
        mysql_port: 2881
        rpc_port: 2882
        zone: zone3
      ```

      | パラメータ | 必須 | デフォルト値 | 説明 |
      |----------|-----------|----------|----------|
      | version | オプション | イメージライブラリの最新バージョン | デプロイ対象コンポーネントのバージョンを指定します。通常は指定不要です。 |
      | servers | 必須 | なし | 各マシンは `- name: マシン識別子 (改行) ip: マシンIP` の形式で指定する必要があります。複数のマシンがある場合は、それぞれに対して指定します。マシン識別子は重複してはなりません。</br> マシンIPが重複しない場合は、`- <ip> (改行) - <ip>` の形式でも指定可能です。この場合、`- <ip>` の形式は `- name: マシンIP(改行) ip: マシンIP` と同じ意味になります。 |
      | devname | オプション | なし | `servers` で指定したIPアドレスに対応するNICカードです。`ip addr` コマンドでIPとNICカードの対応関係を確認できます。 |
      | memory_limit | オプション | 0 | observerプロセスが環境から取得できる最大メモリ量です。設定されていない場合は、`memory_limit_percentage` パラメータに従います。詳細については、[memory_limit](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/13800.memory_limit.md)および[memory_limit_percentage](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/13900.memory_limit_percentage.md)を参照してください。 |
      | system_memory | オプション | 0M | 予約されたシステムメモリです。このパラメータ値は `memory_limit` のメモリを占有します。設定されていない場合、OceanBaseデータベースは自動的に調整します。 |
      | datafile_size | オプション | 0 | 対応するノードのデータファイル（block_file）サイズを指定します。設定されていない場合は、`datafile_disk_percentage` パラメータに従います。詳細については、[datafile_size](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/4900.datafile_size.md)および[datafile_disk_percentage](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/4600.datafile_disk_percentage.md)を参照してください。 |

### ステップ3：OceanBaseクラスタをデプロイ

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>このセクションで使用されるコマンドの詳細な使い方については、OceanBaseインストールおよびデプロイツールのドキュメントにある<a href="https://www.oceanbase.com/docs/common-obd-cn-1000000003754444">クラスタコマンドグループ</a>を参照してください。</p>
</main>

1. OceanBaseクラスタをデプロイ

   ```shell
   [admin@test001 ~]$ obd cluster deploy obtest -c deploy.yaml
   ```

   インターネット接続がある場合、`obd cluster deploy` コマンドを実行すると、obdはターゲットマシンにデプロイに必要なインストールパッケージが存在するかどうかを確認します。インストールパッケージがない場合、obdは自動的にYUMリポジトリから取得します。

2. OceanBaseクラスタを起動

   ```shell
   [admin@test001 ~]$ obd cluster start obtest
   ```

   起動に成功すると、obshell Dashboardとモニタリングコンポーネントへのアクセスアドレスが出力されます。Alibaba Cloudや他のクラウド環境では、プロキシサーバーの設定によりパブリックIPアドレスが取得できないため、プライベートIPアドレスが出力される場合があります。このIPアドレスはパブリックIPアドレスではないため、正しいアドレスを使用する必要があります。

3. OceanBaseクラスタの状態を確認

   ```shell
   # obdが管理するクラスタリストを確認
   [admin@test001 ~]$ obd cluster list

   # obtestクラスタの状態を確認
   [admin@test001 ~]$ obd cluster display obtest
   ```

4. (オプション)クラスタ構成を変更

   OceanBaseデータベースには数百もの構成パラメータがあり、そのうち一部は相互依存しています。OceanBaseデータベースに慣れるまでは、サンプル構成ファイルの設定を変更することは推奨されません。ここでは、構成を変更して有効にする方法を示します。

   `obd cluster edit-config` コマンドを使用して編集モードに入り、クラスタ構成を変更します。

   ```shell
   [admin@test001 ~]$ obd cluster edit-config obtest
   ```

   設定を変更して保存して終了すると、obdはこの変更を有効にする方法を指示します。変更を保存した後、以下のコマンドを入力します。

   ```shell
   Search param plugin and load ok
   Search param plugin and load ok
   Parameter check ok
   Save deploy "obtest" configuration
   Use `obd cluster reload obtest` to make changes take effect.
   ```

   obdが出力したコマンドをコピーして実行します。

   ```shell
   [admin@test001 ~]$ obd cluster reload obtest
   ```

### ステップ4：OceanBaseクラスタに接続する

ここでは、OBClientクライアントを使用してOceanBaseクラスタに接続する例を示します：

```shell
obclient -h<IP> -P<PORT> -u<user_name>@<tenant_name>#<cluster_name> -p -c -A
# example
obclient -h10.10.10.4 -P2883 -uroot@sys#obdemo -p -c -A
```

パラメータの説明：

* -h：OceanBaseデータベースへの接続IPアドレス。直接接続する場合はOBServerノードのアドレス、ODP経由で接続する場合はODPのアドレスを指定します。

* -u：OceanBaseデータベースの接続アカウント。書式は以下のとおりです：`ユーザー名@テナント名#クラスタ名`、`クラスタ名:テナント名:ユーザー名`、`クラスタ名-テナント名-ユーザー名`、または `クラスタ名.テナント名.ユーザー名`。MySQLテナントの管理者ユーザー名はデフォルトで `root` です。

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>接続時に使用するクラスタ名は、構成ファイル内の <code>appname</code> の設定名であり、デプロイ時の <code>deploy name</code> ではありません。</p>
  </main>

* -P：OceanBaseデータベースへの接続ポート。直接接続する場合は `mysql_port` 設定項目の値、ODP経由で接続する場合は `listen_port` 設定項目の値を指定します。

* -p：OceanBaseデータベースへの接続パスワード。

* -c：OBClient実行環境において、コメントを無視しないようにします。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>Hintは特殊なコメントであり、-cの影響を受けません。</p>
  </main>

* -A：OBClientがデータベースに接続する際、統計情報を自動取得しないようにします。

OceanBaseクラスタへの接続手順の詳細については、[OceanBaseデータベースに接続する](../../../300.develop/100.application-development-of-mysql-mode/100.connect-to-oceanbase-database-of-mysql-mode/100.connection-methods-overview-of-mysql-mode.md) を参照してください。

### ステップ5：ユーザーテナントを作成する

OceanBaseクラスタをデプロイした後、業務操作用にユーザーテナントを作成することを推奨します。sysテナントはクラスタ管理専用であり、業務シナリオでの使用には適していません。

次の2つの方法でユーザーテナントを作成できます：

* 方法1：obdを使用してユーザーテナントを作成します。

  ```shell
  obd cluster tenant create <deploy name> [-n <tenant name>] [flags]
  # example
  obd cluster tenant create test -n obmysql --max-cpu=2 --memory-size=2G --log-disk-size=3G --max-iops=10000 --iops-weight=2 --unit-num=1 --charset=utf8
  ```

  このコマンドはデフォルトで、クラスタの残りのすべての利用可能リソースに基づいてテナントを作成します。各パラメータを設定することで、テナントが使用するリソース量を制御できます。コマンドの詳細な使用方法については、obdマニュアルの[クラスタコマンドグループ](https://www.oceanbase.com/docs/common-obd-cn-1000000003754444)にある `obd cluster tenant create` コマンドを参照してください。

* 方法2：コマンドラインを使用してユーザーテナントを作成します。詳細な操作については、[テナントの作成](../../../600.manage/200.tenant-management/600.common-tenant-operations/200.manage-create-tenant.md)を参照してください。

## 関連操作

### クラスタの管理

以下のコマンドを実行して、obdデプロイ済みのクラスタを管理できます。詳細なコマンドについては、OceanBaseインストールおよびデプロイツールのドキュメント[クラスタコマンドグループ](https://www.oceanbase.com/docs/common-obd-cn-1000000003754444)を参照してください。

```shell
# クラスタリストの表示
obd cluster list

# クラスタの状態の確認。例として、デプロイ名がobtestの場合
obd cluster display obtest

# 実行中のクラスタの停止。例として、デプロイ名がobtestの場合
obd cluster stop obtest

# デプロイ済みのクラスタの破棄。例として、デプロイ名がobtestの場合
obd cluster destroy obtest
```

### OceanBase All in Oneのアンインストール

以下の手順に従って、インストール済みのOceanBase All in Oneをアンインストールします。

1. インストールパッケージのアンインストール

   ```shell
   [admin@test001 ~]$ cd oceanbase-all-in-one/bin/
   [admin@test001 bin]$ ./uninstall.sh
   ```

2. 環境変数の削除

   ```shell
   [admin@test001 bin]$ vim ~/.bash_profile
   # このファイル内のsource /home/admin/.oceanbase-all-in-one/bin/env.shを削除
   ```

3. 変更の有効化

   環境変数を削除した後、ターミナルに再ログインするか、sourceコマンドを実行して変更を有効にする必要があります。以下のコマンドを参照してください。

   ```shell
   [admin@test001 ~]$ source ~/.bash_profile
   ```
