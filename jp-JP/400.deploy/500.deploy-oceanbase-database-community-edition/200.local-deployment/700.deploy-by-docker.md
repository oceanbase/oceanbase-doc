# OceanBaseデータベースコンテナ環境のデプロイ

本記事では、Dockerコンテナを使用して単一ノードのOceanBaseデータベースをデプロイする方法について説明します。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>本記事の操作は学習またはテストシナリオにのみ適用されます。本番環境での使用は避けてください。</p>
</main>

## 前提条件

本記事の操作を実行する前に、以下の情報を確認してください：

* Dockerがインストール済みであり、Dockerサービスが起動されていること。詳細な操作手順については、[Dockerドキュメント](https://docs.docker.com/get-docker/)を参照してください。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>x86アーキテクチャのMACマシンでは、OceanBaseデータベースのデプロイにはV4.9.0およびそれ以前のバージョンのDockerのみがサポートされています。Dockerは<a href="https://desktop.docker.com/mac/main/amd64/81317/Docker.dmg?_gl=17jelfd_gcl_auOTk5Nzk0MDUwLjE3MTE4ODMyNzM._gaNDQyMjE1MDE5LjE3MTE4ODMyNzQ._ga_XJWPQMJYHQ*MTcxOTIxOTEwMy4xMS4xLjE3MTkyMjEwMTAuNjAuMC4w">リンク</a>からダウンロードできます。</p>
  </main>

* マシンがソフトウェアおよびハードウェア要件を満たしていること。詳細については、[ソフトウェアおよびハードウェア要件](../200.local-deployment/100.requirements-for-software-and-hardware.md)を参照してください。

## OceanBaseデータベースのデプロイメント

### （オプション）ステップ１：OceanBaseデータベースイメージの取得

以下のコマンドを実行して、OceanBaseデータベースに必要なイメージを取得します。

* OceanBaseデータベース関連のイメージを検索します

  ```shell
  [admin@test001 ~]$ sudo docker search oceanbase
  ```

* OceanBaseデータベースの最新イメージを取得します

  ```shell
  [admin@test001 ~]$ sudo docker pull oceanbase/oceanbase-ce
  ```

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <ul>
    <li>
    <p>Dockerイメージの取得に失敗した場合は、quay.ioまたはghcr.ioリポジトリからイメージを取得することもできます。その際は、上記の取得コマンド内の<code>oceanbase/oceanbase-ce</code>を<code>quay.io/oceanbase/oceanbase-ce</code>または<code>ghcr.io/oceanbase/oceanbase-ce</code>に置き換えてください。例えば、<code>sudo docker pull quay.io/oceanbase/oceanbase-ce</code>を実行すると、quay.ioからイメージが取得されます。</p>
    </li>
    <li>
    <p>このステップのコマンド内のリポジトリアドレスを変更した場合、ステップ2のコマンドでも同様にリポジトリアドレスを変更する必要があります。2つのコマンドで使用するリポジトリは統一しておく必要があります。</p>
    </li>
    <li>
    <p>上記のコマンドはデフォルトで最新バージョンを取得しますが、実際のニーズに応じて<a href="https://hub.docker.com/r/oceanbase/oceanbase-ce/tags">dockerhub</a>、<a href="https://quay.io/repository/oceanbase/oceanbase-ce?tab=tags">quay.io</a>、または<a href="https://github.com/oceanbase/docker-images/pkgs/container/oceanbase-ce">ghcr.io</a>からバージョンを選択できます。</p>
    </li>
    </ul>
  </main>

### ステップ2：OceanBaseデータベースインスタンスを起動する

以下のコマンドを実行して、OceanBaseデータベースインスタンスを起動します。

:::tab

tab 現在のコンテナでデプロイされている最大スペックのインスタンスに基づく

```shell
[admin@test001 ~]$ sudo docker run -p 2881:2881 -v $PWD/ob:/root/ob -v $PWD/obd/cluster:/root/.obd/cluster --name obstandalone -e MODE=NORMAL -e OB_TENANT_PASSWORD=***** -d oceanbase/oceanbase-ce
```

tab ミニ版のスタンドアロンインスタンスをデプロイ

```shell
[admin@test001 ~]$ sudo docker run -p 2881:2881 -v $PWD/ob:/root/ob -v $PWD/obd/cluster:/root/.obd/cluster --name obstandalone -e MODE=MINI -e OB_TENANT_PASSWORD=***** -d oceanbase/oceanbase-ce
```

tab クイックスタートモードでインスタンスをデプロイする

クイックスタートモードでは、テナントおよびリソース関連の環境変数が設定されている場合、`OB_TENANT_PASSWORD` と `OB_SYS_PASSWORD` を除く他の変数はすべて無効になります。作成されるユーザーテナント名はデフォルトで `test` となり、これ以外の値を指定することはできません。

```shell
[admin@test001 ~]$ sudo docker run -p 2881:2881 -v $PWD/ob:/root/ob -v $PWD/obd/cluster:/root/.obd/cluster --name obstandalone -e MODE=SLIM -d oceanbase/oceanbase-ce
```

:::

例に記載されているオプションの役割は以下のとおりです：

* `-p` は、コンテナのポートをホストのポートにマッピングするために使用されます。例では、コンテナ内の `2881` ポートをホストの `2881` ポートにマッピングしています。

* `-v` は、コンテナとホスト間でファイルやディレクトリを共有し、データの永続化や設定の共有を実現するために使用されます。デフォルトでは、システムはコンテナの `/root/ob` ディレクトリにOceanBaseデータベースをデプロイし、その設定を `/root/.obd/cluster` に保存します。このオプションを使用して、ホスト上でデータを永続化できます。

  また、`-v` オプションを使用して、実行するSQLをマウントして実行することもできます。例は以下のとおりです。`{init_sql_folder_path}` を実際の初期化SQLファイルのパスに変更する必要があります。

  ```shell
  [admin@test001 ~]$ sudo docker run -p 2881:2881 -v {init_sql_folder_path}:/root/boot/init.d --name obstandalone -e MODE=SLIM -d oceanbase/oceanbase-ce
  ```

* `--name` は、Dockerコンテナの名前を設定するために使用されます。例では、`obstandalone` という名前のDockerコンテナを作成しています。

* `-e` は、環境変数を設定するために使用されます。例では、`MODE` はOceanBaseデータベースの起動モードを設定し、`OB_TENANT_PASSWORD` はOceanBaseデータベースのroot@testユーザーのパスワードを設定します。詳細な環境変数については、以下の[設定可能な環境変数](#設定可能な環境変数)を参照してください。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>Docker起動時には、デフォルトで <code>enable_rich_error_msg</code> パラメータが有効になっています。エラーが発生した場合、traceコマンドを使用して詳細なエラー情報を取得できます。</p>
</main>

起動には2～5分かかる見込みです。以下のコマンドを実行し、`boot success!` が返された場合は起動に成功したことを意味します。

```shell
[admin@test001 ~]$ sudo docker logs obstandalone | tail -1
boot success!
```

### ステップ3：OceanBaseデータベースインスタンスに接続する

oceanbase-ceイメージには、obd(OceanBase Deployer、OceanBaseのインストールおよびデプロイツール)とOBClient(OceanBaseコマンドラインクライアント)がインストールされています。コンテナ内でobdコマンドを使用してインスタンスを管理したり、OBClientクライアントを使用してインスタンスに接続したりすることもできますし、ホストマシンのローカルOBClientまたはMySQLクライアントを使用してOceanBaseデータベースインスタンスに接続することもできます。

#### コンテナ内からの接続

1. Dockerコンテナに入る

   ```shell
   [admin@test001 ~]$ sudo docker exec -it obstandalone bash
   ```

2. クラスタの詳細を確認する

   ```shell
   # クラスタリストを表示
   obd cluster list
   # obclusterクラスタの詳細を表示
   obd cluster display obcluster
   ```

3. クラスタに接続する

   ```shell
   obclient -h127.0.0.1 -uroot@sys -A -Doceanbase -P2881 -p
   ```

#### ホストマシンのローカルクライアントを使用した接続

ホストマシンのローカルOBClientまたはMySQLクライアントを使用してOceanBaseデータベースインスタンスに接続することもできます。例：

```shell
[admin@test001 ~]$ obclient -uroot@sys -h127.0.0.1 -P2881 -p
```

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>OceanBaseデータベースインスタンスの起動時に環境変数でパスワードを設定しなかった場合、インスタンス内で作成されたユーザーはデフォルトで空のパスワードを使用します。</p>
</main>

接続に成功すると、ターミナルに以下の内容が表示されます：
