# OceanBaseデータベースコンテナ環境のデプロイ

本記事では、Dockerコンテナを使用して単一ノードのOceanBaseデータベースをデプロイする方法について説明します。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>このドキュメントで説明する操作は学習またはテストシナリオにのみ適用されます。本番環境には適用しないでください。</p>
</main>

## 前提条件

本記事の操作を実行する前に、以下の事項を確認してください：

* Dockerがインストール済みで、Dockerサービスが起動していること。詳細な操作手順については、[Dockerドキュメント](https://docs.docker.com/get-docker/)を参照してください。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>x86アーキテクチャのMACマシンでは、OceanBaseデータベースのデプロイはV4.9.0以下のDockerバージョンのみをサポートしています。Dockerをダウンロードするには、<a href="https://desktop.docker.com/mac/main/amd64/81317/Docker.dmg?_gl=17jelfd_gcl_auOTk5Nzk0MDUwLjE3MTE4ODMyNzM._gaNDQyMjE1MDE5LjE3MTE4ODMyNzQ._ga_XJWPQMJYHQ*MTcxOTIxOTEwMy4xMS4xLjE3MTkyMjEwMTAuNjAuMC4w">リンク</a>をクリックしてください。</p>
  </main>

* マシンがソフトウェアおよびハードウェア要件を満たしていること。詳細については、[ソフトウェアおよびハードウェア要件](../200.local-deployment/100.requirements-for-software-and-hardware.md)を参照してください。

## OceanBaseデータベースのデプロイ

### （オプション）ステップ1：OceanBaseデータベースイメージの取得

以下のコマンドを実行して、OceanBaseデータベースに必要なイメージを取得します。

* OceanBaseデータベース関連のイメージの検索

  ```shell
  [admin@test001 ~]$ sudo docker search oceanbase
  ```

* OceanBaseデータベースの最新イメージの取得

  ```shell
  [admin@test001 ~]$ sudo docker pull oceanbase/oceanbase-ce
  ```

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <ul>
    <li>
    <p>Dockerイメージの取得に失敗した場合は、quay.ioまたはghcr.ioリポジトリからイメージを取得することもできます。上記の取得コマンドの<code>oceanbase/oceanbase-ce</code>を<code>quay.io/oceanbase/oceanbase-ce</code>または<code>ghcr.io/oceanbase/oceanbase-ce</code>に置き換えて、例えば<code>sudo docker pull quay.io/oceanbase/oceanbase-ce</code>を実行してquay.ioからイメージを取得します。</p>
    </li>
    <li>
    <p>このステップのコマンドでリポジトリのアドレスを変更した場合、ステップ2のコマンドでも同様にリポジトリのアドレスを変更する必要があります。2つのコマンドで使用するリポジトリは統一しておく必要があります。</p>
    </li>
    <li>
    <p>上記のコマンドはデフォルトで最新バージョンを取得します。実際のニーズに応じて、<a href="https://hub.docker.com/r/oceanbase/oceanbase-ce/tags">dockerhub</a>、<a href="https://quay.io/repository/oceanbase/oceanbase-ce?tab=tags">quay.io</a>、または<a href="https://github.com/oceanbase/docker-images/pkgs/container/oceanbase-ce">ghcr.io</a>からバージョンを選択できます。</p>
    </li>
    </ul>
  </main>

### ステップ2：OceanBaseデータベースインスタンスの起動

以下のコマンドを実行して、OceanBaseデータベースインスタンスを起動します。

:::tab

tab 現在のコンテナデプロイの最大仕様に基づくインスタンス

```shell
[admin@test001 ~]$ sudo docker run -p 2881:2881 -p 2886:2886 -v $PWD/ob:/root/ob -v $PWD/obd/cluster:/root/.obd/cluster --name obstandalone -e MODE=NORMAL -e OB_TENANT_PASSWORD=***** -d oceanbase/oceanbase-ce
```

tab ミニ版の独立インスタンスをデプロイ

```shell
[admin@test001 ~]$ sudo docker run -p 2881:2881 -p 2886:2886 -v $PWD/ob:/root/ob -v $PWD/obd/cluster:/root/.obd/cluster --name obstandalone -e MODE=MINI -e OB_TENANT_PASSWORD=***** -d oceanbase/oceanbase-ce
```

tab クイックスタートモードでインスタンスをデプロイ

クイックスタートモードでは、テナントおよびリソース関連の環境変数を設定しても、`OB_TENANT_PASSWORD` と `OB_SYS_PASSWORD` を除き、他の変数は有効になりません。作成されるユーザーテナント名はデフォルトで `test` となり、これ以外の名前を指定することはできません。

```shell
[admin@test001 ~]$ sudo docker run -p 2881:2881 -p 2886:2886 -v $PWD/ob:/root/ob -v $PWD/obd/cluster:/root/.obd/cluster --name obstandalone -e MODE=SLIM -d oceanbase/oceanbase-ce
```

:::

例に含まれるオプションの役割は以下のとおりです：

* `-p` はコンテナのポートをホストポートにマッピングするために使用します。例では、コンテナ内の `2881` ポートと `2886` ポートをそれぞれホストの `2881` ポートと `2886` ポートにマッピングします。

* `-v` はコンテナとホスト間でファイルやディレクトリを共有し、データの永続化や設定の共有を実現するために使用します。デフォルトでは、システムはコンテナの `/root/ob` ディレクトリにOceanBaseデータベースをデプロイし、その設定を `/root/.obd/cluster` に保存します。このオプションを使用することで、ホスト上にデータを永続化できます。

  `-v` オプションを使用して、実行するSQLをマウントして実行することもできます。例を以下に示します。`{init_sql_folder_path}` を実際の初期化SQLファイルのパスに変更する必要があります。

  ```shell
  [admin@test001 ~]$ sudo docker run -p 2881:2881 -p 2886:2886 -v {init_sql_folder_path}:/root/boot/init.d --name obstandalone -e MODE=SLIM -d oceanbase/oceanbase-ce
  ```

* `--name` はDockerコンテナ名を設定するために使用します。例では、`obstandalone` という名前のDockerコンテナを作成します。

* `-e` は環境変数を設定するために使用します。例では、`MODE` はOceanBaseデータベースの起動モードを設定し、`OB_TENANT_PASSWORD` はOceanBaseデータベースのroot@testユーザーのパスワードを設定します。詳細な環境変数については、後述の [設定可能な環境変数](#設定可能な環境変数) を参照してください。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>Docker起動時には、<code>enable_rich_error_msg</code> パラメータがデフォルトで有効になっています。エラーが発生した場合、traceコマンドを使用して詳細なエラー情報を取得できます。</p>
</main>

起動には約2〜5分かかります。以下のコマンドを実行し、`boot success!` が返された場合、起動に成功したことを意味します。

```shell
[admin@test001 ~]$ sudo docker logs obstandalone | tail -1
boot success!
```

### ステップ3：OceanBaseデータベースインスタンスに接続

oceanbase-ceイメージには、obd（OceanBase Deployer、OceanBaseのインストール・デプロイツール）とOBClient（OceanBaseコマンドラインクライアント）がインストールされています。コンテナに入ってobdコマンドとOBClientクライアントを使用してインスタンスに接続するか、ホストのローカルOBClientまたはMySQLクライアントを使用してOceanBaseデータベースインスタンスに接続することもできます。

#### コンテナに入った後の接続

1. Dockerコンテナに入る

   ```shell
   [admin@test001 ~]$ sudo docker exec -it obstandalone bash
   ```

2. クラスタの詳細を確認する

   ```shell
   # クラスターリストの確認
   obd cluster list
   # obclusterクラスターの詳細表示
   obd cluster display obcluster
   ```

3. クラスターへの接続

   ```shell
   obclient -h127.0.0.1 -uroot@sys -A -Doceanbase -P2881 -p
   ```

#### ホスト機のローカルクライアントを使用した接続

ホスト機のローカルにあるOBClientまたはMySQLクライアントを使用して、OceanBaseデータベースインスタンスに接続することができます。例：

```shell
[admin@test001 ~]$ obclient -uroot@sys -h127.0.0.1 -P2881 -p
```

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>OceanBaseデータベースインスタンス起動時に環境変数でパスワードを設定しなかった場合、インスタンス内で作成されたユーザーはデフォルトで空のパスワードを使用します。</p>
</main>

接続成功後、端末には以下の内容が表示されます：

## 設定可能な環境変数

| 変数名  |  デフォルト値  | 値の説明 | 説明   |
|--------|----------|--------|-------|
| MODE | MINI | <ul><li><code>MINI</code>：コンテナがクラスタを起動するために最小限のリソースを使用します。</li><li><code>NORMAL</code>：コンテナが可能な限りすべてのリソースを使用してクラスタを起動します。</li><li><code>SLIM</code>：コンテナがOceanBaseデータベースのみを起動し、クイックスタートモードを使用します。</li></ul><main id="notice" type='explain'><h4>説明</h4><p><code>MODE</code>が<code>SLIM</code>に設定されている場合、テナントおよびリソース関連の環境変数を設定しても、<code>OB_TENANT_PASSWORD</code>と<code>OB_SYS_PASSWORD</code>を除き、他の変数は有効になりません。</p></main> | クラスタの起動モードを設定します。 |
| EXIT_WHILE_ERROR | true | <ul><li><code>true</code>：OceanBaseデータベースを起動できない場合、コンテナを終了します。</li><li><code>false</code>：OceanBaseデータベースを起動できない場合、コンテナを終了せず、デバッグのためにコンテナにログインできます。</li></ul> | OceanBaseデータベースを起動できない場合にコンテナを終了するかどうかを制御します。 |
| OB_CLUSTER_NAME | obcluster | なし | OceanBaseクラスタ名を設定します。 |
| OB_TENANT_NAME | test | 最長63バイト、大文字小文字の英字、数字、アンダースコアのみ、OceanBaseデータベースのキーワードではないこと。 |  設定後、OceanBaseクラスタ内に同名のMySQLテナントが作成されます。設定しない場合、デフォルトで`test`という名前のMySQLテナントが作成されます。<main id="notice" type='explain'><h4>説明</h4><p><code>MODE</code>が<code>SLIM</code>に設定されている場合、ユーザーテナント名はデフォルトで<code>test</code>になり、他の値に設定しても無効です。</p></main> |
