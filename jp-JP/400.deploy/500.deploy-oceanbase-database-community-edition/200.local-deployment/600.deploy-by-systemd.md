# systemdを使用したOceanBaseデータベースのデプロイ

本記事では、systemdを使用して単一ノードのOceanBaseデータベースをデプロイおよび管理する方法について説明します。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>このドキュメントの操作は学習またはテストシナリオにのみ適用されます。本番環境での使用は避けてください。</p>
</main>

## 前提条件

本記事の操作を実行する前に、以下の情報を確認してください：

* 使用している環境がRPMプラットフォームであること。現在、サポートされているシステムは以下の通りです。

  * Anolis OS 8.Xバージョン（カーネルLinux 4.19バージョン以上）

  * CentOS Linux 8.Xバージョン（カーネルLinux 4.19バージョン以上）

  * Debian 10、11、12バージョン（カーネルLinux 4.19バージョン以上）

  * openEuler 22.03および24.03バージョン（カーネルLinux 5.10.0バージョン以上）

  * Ubuntu 18.04、20.04、22.04バージョン（カーネルLinux 4.19バージョン以上）

* 環境にjqコマンドラインツールがインストール済みであり、systemdがシステムおよびサービスマネージャーとして正しく設定されていること。

* データベース接続ツール（MySQLクライアントまたはOBClientクライアント）が環境にインストール済みであること。

* デプロイ予定のOceanBaseデータベースがV4.2.2以降のバージョンであること。

* 使用しているユーザーがsudoコマンドを実行する権限を持っていること。

## OceanBaseデータベースのデプロイメント

### ステップ１：OceanBaseデータベースのインストール

使用する環境が外部ネットワークに接続できるかどうかにより、オンラインインストールとオフラインインストールの2種類のインストール方法があります。

:::tab
tab オンラインインストール

1. OceanBaseイメージソースを追加します。

   ```shell
   [admin@test001 ~]$ sudo yum-config-manager --add-repo https://mirrors.aliyun.com/oceanbase/OceanBase.repo
   ```

2. OceanBaseデータベースをインストールします。

   ```shell
   [admin@test001 ~]$ sudo yum install oceanbase-ce oceanbase-ce-libs obclient
   ```

   このコマンドはデフォルトで最新バージョンをデプロイします。バージョン番号を指定して特定のバージョンをインストールすることも可能です。例えば、`yum install oceanbase-ce-4.2.2.0` コマンドを使用してOceanBaseデータベースV4.2.2バージョンをインストールできます。最新バージョンのインストールを推奨します。

tab オフラインインストール

1. [OceanBaseソフトウェアダウンロードセンター](https://en.oceanbase.com/softwarecenter)から、必要なバージョンのOceanBaseデータベースおよび対応する依存ライブラリ（`OceanBase Libs`）をダウンロードします。ダウンロードが完了したら、インストールパッケージをマシンにコピーします。最新バージョンのインストールパッケージを使用することを推奨します。

2. インストールパッケージがあるディレクトリで、rpmコマンドを実行してOceanBaseデータベースをインストールします。

   ```shell
   [admin@test001 ~]$ rpm -ivh oceanbase-ce-*.rpm
   ```

:::

### ステップ2：OceanBaseデータベースを起動する

OceanBaseデータベースのインストール後、以下の手順に従ってOceanBaseデータベースを起動します。

1. (オプション)設定ファイルを変更する

   このステップに従って設定ファイルを変更できます。変更しない場合は、設定ファイル内のデフォルト設定を使用してデプロイが行われます。

   ```shell
   [admin@test001 ~]$ vim /etc/oceanbase.cnf
   ```

   このファイルに含まれる構成パラメータの内容は以下のとおりです：

   ```shell
   mysqlPort=2881
   rootPwd=""
   redoDir=/var/lib/oceanbase/redo
   dataDir=/var/lib/oceanbase/data
   datafile_size=2G
   cpu_count=16
   memory_limit=6G
   system_memory=1G
   log_disk_size=13G
   ```

   <main id="notice" type='explain'>
     <h4>説明</h4>
     <ul>
     <li>
     <p>この設定ファイルに他の構成パラメータを追加できます。詳細な構成パラメータの紹介については、<a href='../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/200.system-configuration-items-overview-list.md'>構成パラメータの概要</a>を参照してください。</p>
     </li>
     <li>
     <p>現在、OBServerノードのIPアドレス(<code>127.0.0.1</code>)とゾーン(<code>zone1</code>)は変更できません。</p>
     </li>
     </ul>
   </main>

   設定ファイル内の構成パラメータの紹介は以下の表のとおりです：

   | パラメータ | 必須 | デフォルト値 | 説明 |
   |----------|-----------|----------|----------|
   | mysqlPort | オプション | 2881 | OceanBaseデータベースのSQLサービスプロトコルのポート番号。 |
   | rootPwd | オプション | 空 | OceanBaseクラスタのスーパーユーザー（`root@sys`）のパスワード。複雑なパスワードを設定することを推奨します。 |
   | redoDir | オプション | /var/lib/oceanbase/redo | clog、ilog、slogのディレクトリ。独立したディスクに設定することを推奨します。 |
   | dataDir | オプション | /var/lib/oceanbase/data | SSTableなどのデータを格納するディレクトリ。独立したディスクに設定することを推奨します。 |
   | datafile_size | オプション | 0 | 対応するノードのデータファイル（block_file）のサイズを指定します。設定されていない場合は、`datafile_disk_percentage`パラメータに従います。詳細については、[datafile_size](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/4900.datafile_size.md)および[datafile_disk_percentage](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/4600.datafile_disk_percentage.md)を参照してください。 |
   | cpu_count | オプション | 0 | OceanBaseデータベースで使用可能なCPUの総数です。0に設定すると、自動的に検出されます。 |
   | memory_limit | オプション | 0 | observerプロセスが環境から取得できる最大メモリ量です。設定されていない場合は、`memory_limit_percentage`パラメータに従います。パラメータの詳細については、[memory_limit](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/13800.memory_limit.md)および[memory_limit_percentage](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/13900.memory_limit_percentage.md)を参照してください。 |
   | system_memory | オプション | 0M | 予約されたシステムメモリです。このパラメータ値は`memory_limit`のメモリを占有します。設定されていない場合、OceanBaseデータベースは適応します。 |
   | log_disk_size | オプション | 0 | Redoログディスクのサイズを設定します。設定されていない場合は、`log_disk_percentage`パラメータに従います。詳細については、[log_disk_size](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/13000.log_disk_size.md)および"log_disk_percentage"(../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/12900.log_disk_percentage.md)を参照してください。 |

2. OceanBaseデータベースを起動する

   ```shell
   [admin@test001 ~]$ sudo systemctl start oceanbase
   ```

### ステップ3：OceanBaseデータベースに接続する

ここでは、OBClientを使用してOceanBaseデータベースに接続する例を示します。コマンドは以下のとおりです：

```shell
[admin@test001 ~]$ obclient -h127.0.0.1 -uroot@sys -P2881 -p -A oceanbase
```

パラメータの説明：

* -h：OceanBaseデータベースへの接続IPアドレス。systemdで起動されたOceanBaseデータベースのデフォルトIPアドレスは`127.0.0.1`です。

* -u：OceanBaseデータベースの接続アカウント。書式：`ユーザー名@テナント名`。MySQLテナントの管理者ユーザー名のデフォルトは`root`です。

* -P：OceanBaseデータベースへの接続ポート。systemdで起動されたOceanBaseデータベースのデフォルトポートは`2881`です。

* -p：OceanBaseデータベースへの接続パスワード。接続コマンド内で指定するのではなく、コマンド実行後のプロンプトで入力することを推奨します。パスワードテキストは非表示です。

* -A：OBClientがデータベースに接続する際に統計情報を自動取得しないことを示します。

* oceanbase：アクセスするデータベースの名前。業務データベース名に変更可能です。

## OceanBaseデータベースの管理

現在、OceanBaseデータベースの起動(start)、停止(stop)、およびステータス(status)の確認は、systemdを使用してのみサポートされています。

* OceanBaseデータベースのステータスの確認

  ```shell
  [admin@test001 ~]$ sudo systemctl status oceanbase
  ```

  OceanBaseデータベースのステータスを確認する方法は以下のとおりです：

  * `Active`が`active (running)`と表示され、かつ`Status`が`Service is running`と表示されている場合、OceanBaseデータベースが起動中であることを意味します。

  * `Active`が`active (running)`と表示され、かつ`Status`が`Service is ready`と表示されている場合、OceanBaseデータベースが正常に起動されたことを意味します。

  * `Active`が`inactive (dead)`と表示されている場合、サービスが停止したことを意味し、つまりOceanBaseデータベースも停止しています。

  * `Active`が`failed`と表示されている場合、サービスにエラーが発生したことを意味し、ログを確認してトラブルシューティングが必要です。

* OceanBaseデータベースの停止

  ```shell
  [admin@test001 ~]$ sudo systemctl stop oceanbase
  ```

* OceanBaseデータベースのアンインストール

  OceanBaseデータベースをアンインストールする前に、まずOceanBaseデータベースを停止することを推奨します。その後、以下の手順でOceanBaseデータベースをアンインストールします。

  1. OceanBaseデータベースソフトウェアパッケージの削除

     オンラインインストール方式では、次のコマンドを実行できます：

     ```shell
     [admin@test001 ~]$ sudo yum erase package
     ```

     `package`は削除対象のソフトウェアパッケージ名に置き換える必要があります。ソフトウェアパッケージ名は、`yum list | grep oceanbase`コマンドで確認できます。

     オフラインインストール方式では、次のコマンドを実行できます：

     ```shell
     [admin@test001 ~]$ sudo rpm -e package
     ```

     `package`は削除対象のソフトウェアパッケージ名に置き換える必要があります。ソフトウェアパッケージ名は、`rpm -qa | grep oceanbase`コマンドで確認できます。

  2. (オプション) OceanBaseデータベースデータの削除

     最初のステップを実行すると、環境内のOceanBaseデータベースはアンインストールされますが、OceanBaseデータベースのデータは残ります。今後OceanBaseデータベースを再デプロイする場合でも、そのOceanBaseデータベースのデータを確認および操作できます。

     このステップでOceanBaseデータベースデータを削除すると、デプロイしたOceanBaseデータベースは完全にアンインストールされます。

     OceanBaseデータベースのインストールディレクトリの削除

     ```shell
     [admin@test001 ~]$ rm -rf /home/admin/oceanbase
     ```

     OceanBaseデータベースデータディレクトリの削除

     ```shell
     [admin@test001 ~]$ rm -rf /var/lib/oceanbase
     ```
