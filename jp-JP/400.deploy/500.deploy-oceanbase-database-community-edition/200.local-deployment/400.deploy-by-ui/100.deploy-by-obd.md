# obdグラフィカルインターフェースを使用したOceanBaseクラスタのデプロイ

本記事では、x86アーキテクチャのCentOS Linux 7.9イメージを環境として、obdグラフィカルインターフェースを使用してOceanBaseデータベースをデプロイする方法について説明します。

## 名詞の紹介

* OceanBaseデータベース

  企業向けに完全自社開発されたネイティブ分散型データベースです。詳細については、[OceanBaseデータベースドキュメント](https://www.oceanbase.com/docs/oceanbase-database-cn)を参照してください。

* obd

  OceanBase Deployer、OceanBaseのインストールおよびデプロイツールで、略称はobdです。詳細については、[OceanBaseインストールおよびデプロイツールドキュメント](https://www.oceanbase.com/docs/obd-cn)を参照してください。

* ODP

  OceanBase Database Proxy、OceanBaseデータベース専用のプロキシサーバーで、OceanBaseデータベースの略称はODP（OBProxyとも呼ばれる）です。詳細については、[OceanBaseデータベースプロキシドキュメント](https://www.oceanbase.com/docs/odp-doc-cn)を参照してください。

* OBAgent

  OBAgentはOceanBaseデータベースのモニタリング収集フレームワークであり、プッシュ方式とプル方式の2種類のデータ収集モードをサポートしており、さまざまなアプリケーションシナリオに対応できます。

* obconfigserver

  OceanBase Configserver、obconfigserverはOceanBaseのメタデータ登録、保存、およびクエリサービスを提供します。詳細については、[ob-configserver](https://github.com/oceanbase/ob-configserver/tree/main)を参照してください。

* Grafana

  Grafanaはオープンソースのデータ可視化ツールであり、データソース内の各種指標データを可視化表示することで、システムの稼働状態やパフォーマンス指標をより直感的に理解できます。詳細については、[Grafana公式サイト](https://grafana.com/)を参照してください。

* Prometheus

  Prometheusはオープンソースのサービス監視システムおよび時系列データベースであり、汎用的なデータモデルと迅速なデータ収集、保存、およびクエリのインターフェースを提供します。詳細については、[Prometheus公式サイト](https://prometheus.io/)を参照してください。

* Alertmanager

  Alertmanagerはオープンソースのアラートマネージャーであり、Prometheusなどの監視システムからのアラートを処理し、アラートの重複排除、グループ化、ルーティング、ミュートなどの機能を提供します。詳細については、[Prometheus公式サイト](https://prometheus.io/)を参照してください。

## 前提条件

開始する前に、以下の条件を満たしていることを確認してください：

* マシンがソフトウェアおよびハードウェア要件を満たしていること。詳細については、[ソフトウェアおよびハードウェア要件](../../200.local-deployment/100.requirements-for-software-and-hardware.md)を参照してください。

* 本番環境では、環境および構成チェックを実行する必要があります。具体的な操作については、[デプロイ前の設定](../200.environment-and-configuration-checks/100.view-resources-optional.md)の章を参照してください。

* OceanBaseデータベースのみをデプロイする場合、少なくとも2vCPU、8GBのメモリ、19GBのディスク容量が必要です。メモリ制限とは、`free -g` コマンドを実行した際の出力結果における `available` 列の値を指します。

* OceanBaseデータベースおよびすべてのコンポーネントをデプロイする場合、少なくとも4vCPU、10GBのメモリ、25GBのディスク容量が必要です。推奨されるメモリ容量は16GB以上です。メモリ制限とは、`free -g` コマンドを実行した際の出力結果における `available` 列の値を指します。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>CPUコア数が少ない環境では、obdのデフォルト設定により最低CPU-Core数は8となります。CPUコア数を低く設定しすぎると、OceanBaseデータベースのパフォーマンスに悪影響を与える可能性があります。</p>
</main>

## ソフトウェアの準備

obdを使用してOceanBaseデータベースをグラフィカルにデプロイする場合、オンラインデプロイとオフラインデプロイの2種類のデプロイ方法があります。

* オンラインデプロイ：obdが配置されているマシンは外部ネットワークへのアクセスが可能である必要があり、デプロイに必要なインストールパッケージの事前設定は不要です。デプロイ中、obdはリモートイメージリポジトリからデプロイに必要なインストールパッケージを取得します。

* オフラインデプロイ：デプロイ中は外部ネットワークへのアクセスが不要であり、デプロイに必要なインストールパッケージを事前にobdのローカルイメージライブラリにアップロードする必要があります。オフラインデプロイを選択する場合は、必要なバージョンのOceanBase All in Oneインストールパッケージを直接ダウンロードすることを推奨します。

デプロイ方法によってソフトウェアの準備方法が異なりますので、実際の状況に応じて適切な方法でソフトウェアを準備してください。

### オンラインデプロイ

オンラインデプロイを選択した場合、このセクションのコマンドを参照してコントロールマシンにobdをインストールできます。

```shell
[admin@test001 ~]$ sudo yum install -y yum-utils
[admin@test001 ~]$ sudo yum-config-manager --add-repo https://mirrors.aliyun.com/oceanbase/OceanBase.repo
[admin@test001 ~]$ sudo yum install -y ob-deploy
[admin@test001 ~]$ source /etc/profile.d/obd.sh
```

### オフラインデプロイ

オフラインデプロイを選択した場合、このセクションのコマンドを参照してOceanBase All in Oneをダウンロードし、インストールできます。

[OceanBaseソフトウェアダウンロードセンター](https://en.oceanbase.com/softwarecenter)から最新のOceanBase All in Oneをダウンロードし、コントロールマシンにコピーします。以下のコマンドを実行して解凍し、インストールします：

```shell
[admin@test001 ~]$ tar -xzf oceanbase-all-in-one-*.tar.gz
[admin@test001 ~]$ cd oceanbase-all-in-one/bin/
[admin@test001 bin]$ ./install.sh
[admin@test001 bin]$ source ~/.oceanbase-all-in-one/bin/env.sh
```

### ステップ１：グラフィカルインターフェースを起動する

1. グラフィカルインターフェースを起動する

   コマンドラインで `obd web` コマンドを実行してグラフィカルインターフェースを起動し、表示されたアドレスをクリックしてアクセスします。

   ```shell
   [admin@test001 ~]$ obd web
   start OBD WEB in 0.0.0.0:8680
   please open http://10.10.10.1:8680
   ```

   <main id="notice" type='explain'>
     <h4>説明</h4>
     <ul>
     <li>
     <p>グラフィカルインターフェースはデフォルトでポート8680を使用します。<code>obd web -p <PORT></code> コマンドを使用してポートを指定できます。</p>
     </li>
     <li>
     <p>Alibaba Cloudや他のクラウド環境では、プログラムがパブリックIPアドレスを取得できず、プライベートIPアドレスが出力される場合があります。このIPアドレスはパブリックIPアドレスではないため、正しいアドレスを使用してグラフィカルインターフェースにアクセスする必要があります。</p>
     </li>
     <li>
     <p><code>obd web</code> コマンドは <code>0.0.0.0</code> にバインドされています。複数のNICを使用したデプロイメントの場合、アクセス可能な任意のIPアドレスからグラフィカルインターフェースにアクセスできます。</p>
     </li>
     <li>
     <p>nohupまたはscreenコマンドを使用して、<code>obd web</code> コマンドをバックグラウンドで実行するよう設定できます。</p>
     </li>
     </ul>
   </main>

2. （オプション）グラフィカル操作画面の右上隅にある **Chinese** 文字にマウスを置くと、表示される言語に応じて中国語と英語の画面を切り替えることができます。

   <img width="677" height="419.5" src="https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V2.1.0/en-US/2.quick-start/3.use-ui-deploy-oceanbase-04.png" alt="言語切り替え">

3. グラフィカルインターフェースで **体験の旅を開始** をクリックし、表示される **OceanBaseデプロイガイドをお使いください** の画面で **OceanBaseおよび関連ツール** モジュールを選択し、**インストール** をクリックしてOceanBaseデータベースのデプロイ画面に進みます。

### ステップ2：デプロイ設定

**デプロイ設定**ページで、クラスタ名、負荷タイプ、およびデプロイメントコンポーネントを設定できます。**デプロイ設定**ページの内容は以下のとおりです。

1. クラスタ設定

   <!-- ![クラスタ設定](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V3.6.0/deploy-by-gui/200.use-ui-deploy-oceanbase-01.png) -->

   | モジュール | 説明 |
   |---------|--------|
   | デプロイ設定 | クラスタ名はobd専用デプロイ製品の一意の名称であり、デフォルトは`myoceanbase`です。カスタマイズ可能ですが、既存のデプロイ名と重複してはなりません。クラスタ名は英字で始まり、英字または数字で終わる必要があり、英字、数字、アンダースコアを含み、長さは2～32文字の間である必要があります。`obd cluster list`コマンドを使用して、obdで管理されているクラスタを確認できます。 |
   | データベースのデプロイ | **バージョン**の下にあるドロップダウンリストからOceanBaseデータベースのバージョンを選択できます。対応するコンポーネントの**詳細を見る**をクリックすると、そのコンポーネントのドキュメントを表示できます。 |
   | ロードタイプ | **タイプ**の下にあるドロップダウンリストからOceanBaseクラスタのロードタイプを選択できます。異なるタイプのロードバランシングにはそれぞれ説明が付いており、各タイプの適用シナリオを理解するのに役立ちます。<main id="notice" type='explain'><h4>説明</h4><p>このモジュールは、デプロイ予定のOceanBaseデータベースのバージョン番号がV4.2.5以上の場合にのみ表示されます。</p></main> |

2. コンポーネントの選択

   <!-- ![コンポーネントの選択](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/obd/V3.6.0/deploy-by-gui/200.use-ui-deploy-oceanbase-02.png) -->

   デフォルトではOBProxyコンポーネントのみがチェックされています。**オプションコンポーネント**の下にある対応するコンポーネントの前のチェックボックスをクリックして、該当するコンポーネントをデプロイするかどうかを設定できます。コンポーネントのバージョンは常に最新バージョンに固定されており、対応するコンポーネントの後ろにある**詳細を見る**をクリックすると、そのコンポーネントのドキュメントを表示できます。

   <main id="notice" type='explain'>
     <h4>説明</h4>
     <p>GrafanaおよびAlertManagerコンポーネントのデプロイはOBAgentおよびPrometheusコンポーネントに依存し、PrometheusコンポーネントのデプロイはOBAgentコンポーネントに依存します。具体的には、GrafanaまたはAlertManagerコンポーネントをチェックすると、OBAgentおよびPrometheusコンポーネントも自動的にチェックされ、OBAgentコンポーネントのチェックを外すと、Grafana、AlertManager、およびPrometheusコンポーネントも自動的にチェックが外されます。</p>
   </main>

設定完了後、**次のステップ**をクリックすると、**ノード設定**ページに移動します。

**クラスタ設定**ページでは、システムテナントの管理者ユーザー(root@sys)のパスワード、データおよびログディレクトリ、データベースおよび各コンポーネントのポートとパラメータ設定など、クラスタを設定できます。このセクションではそれぞれについて説明します。

## 関連操作

### デプロイ済みのクラスタを管理する

以下のコマンドを実行して、obdによってデプロイされたクラスタを管理できます。その他の操作の詳細については、[クラスタコマンドグループ](https://www.oceanbase.com/docs/common-obd-cn-1000000003892230)を参照してください。

```shell
# クラスタリストを表示する
[admin@test001 ~]$ obd cluster list

# クラスタの状態を表示する。例として、デプロイ名がmyoceanbaseの場合
[admin@test001 ~]$ obd cluster display myoceanbase

# 実行中のクラスタを停止する。例として、デプロイ名がmyoceanbaseの場合
[admin@test001 ~]$ obd cluster stop myoceanbase

# デプロイ済みのクラスタを破棄する。例として、デプロイ名がmyoceanbaseの場合
[admin@test001 ~]$ obd cluster destroy myoceanbase
```

### 特定バージョンのコンポーネントをデプロイする

OceanBase All in Oneを使用してデプロイする場合、OceanBase All in OneのパッケージはOceanBaseデータベースのバージョンに基づいてイテレーションされます。パッケージ内の他のコンポーネントに更新バージョンがある場合は、[OceanBaseソフトウェアダウンロードセンター](https://en.oceanbase.com/softwarecenter)から最新バージョンのコンポーネントをダウンロードし、以下の手順に従ってローカルイメージライブラリにアップロードします。obdによるデプロイ時に、ローカルイメージライブラリ内の最新バージョンが自動的に取得されます。

1. コンポーネントインストールパッケージがあるディレクトリに移動し、インストールパッケージをローカルイメージライブラリに追加します。

   ```shell
   [admin@test001 rpm]$ obd mirror clone *.rpm
   ```

2. ローカルイメージライブラリ内のインストールパッケージリストを表示します。

   ```shell
   [admin@test001 rpm]$ obd mirror list local
   ```
