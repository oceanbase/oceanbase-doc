# OCPによるOceanBaseクラスタのデプロイ

本記事では、x86アーキテクチャのCentOS Linux 7.9イメージを環境として、OCPのGUIを使用してOceanBaseデータベースをデプロイする方法を紹介します。

## 前提条件

* OCPがデプロイ済みであること。詳細な操作については、[Community Edition OceanBaseクラウドプラットフォームのデプロイ](https://www.oceanbase.com/docs/common-ocp-1000000002078206)を参照してください。

* 現在OCPにログインしているユーザーが**ADMIN**または**ORG_ADMIN**ロールであること。

* デプロイに必要なoceanbase-ce、oceanbase-ce-libs、oceanbase-ce-utilsソフトウェアパッケージがOCPにアップロードされていること。詳細な操作については、公式Webサイトの「OceanBaseクラウドプラットフォーム」ドキュメント[ソフトウェアパッケージ管理/ソフトウェアパッケージのアップロード](https://www.oceanbase.com/docs/common-ocp-1000000002077811)を参照してください。

* (オプション)マルチレプリカOceanBaseクラスタを作成する場合は、現在のOCPに利用可能なODPクラスタが存在している必要があります。ODPクラスタの追加方法については、公式Webサイトの「OceanBaseクラウドプラットフォーム」ドキュメント[OBProxy管理/OBProxyクラスタの作成](https://www.oceanbase.com/docs/common-ocp-1000000002077790)を参照してください。

## 手順

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>本記事はOCP V4.3.4 Community Editionを例に操作手順を説明します。OCPのバージョンによって操作画面が異なる場合がありますので、実際の画面に従ってください。</p>
</main>

### ステップ１：マシンをOCPリソースプールに追加する

OceanBaseクラスタをデプロイする前に、このセクションの内容に従ってマシンをOCPリソースプールに追加する必要があります。

1. OCPにログインします。

2. 左側のナビゲーションバーで **ホスト** をクリックして、**ホスト** ページに移動します。

3. **ホスト** ページの右上隅で **ホストの追加** をクリックします。

4. ポップアップダイアログでマシン情報を入力します。

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.2.5/400.deploy/200.deploy-by-ocp-01.png)

   各フィールドの入力方法は以下の表のとおりです。

   |   **フィールド** |         **説明**     |
   |------------|----------------------|
   | **IPアドレス**  | 追加するマシンのIPアドレスを入力してください。複数のIPアドレスを同時に追加できます（複数のIPアドレスはカンマで区切ります）。  |
   | **SSHポート** | デフォルトは`22`です。               |
   | **マシンタイプ**   | 同じホストを設定するために指定されるラベルであり、OCPがホストをより適切に管理するために使用されます。対応するマシンタイプがない場合は、ドロップダウンメニューから**新規マシンタイプ**をクリックして新しいマシンタイプを追加できます。|
   | **データセンター**   | マシンが属するデータセンターを選択します。対応するデータセンターがない場合は、ドロップダウンメニューから**新規データセンター**をクリックして、OCPに新しいデータセンター情報を追加します。データセンター情報には**データセンター**と**リージョン**が含まれます。<ul><li>データセンターは、OceanBaseクラスタが記録する必要があるホストのプロパティの一つであり、このプロパティはOceanBaseクラスタのロードバランシングおよびSQL文ルーティングポリシーの参照項目となります。実際の状況に応じてご入力ください。</li><li>リージョンは、ホストが属する地理的なエリアを示すものであり、OceanBaseクラスタが記録する必要があるホストのプロパティの一つです。OceanBaseクラスタのロードバランシングおよびSQL文ルーティングポリシーに一定の影響を与えるため、実際の状況に応じてご入力ください。</li></ul><main id="notice" type='explain'><h4>説明</h4><p>OCP V3.1.1バージョンからマルチアベイラビリティゾーンモードがサポートされています。新しいデータセンターを追加すると、現在のOCPが存在するアベイラビリティゾーン内に新しいデータセンターが作成されます。</p></main>|
   | **ホストタイプ**     | **物理マシン**、**コンテナ**、**ECS**の3つのオプションがあります。**コンテナ**タイプを選択した場合、**ポートマッピング**を入力する必要があります。これは、ocp-agentとホスト、ocp exportとホストの合計2組のマッピング関係を指定するもので、対応する形式は`<ホストポート>:<Docker内のocp-agentポート>,<ホストポート>:<Docker内のocp-exporterポート1>`です。   |
   | **資格情報**   | リモートログイン用の物理マシンの資格情報を選択します。ドロップダウンメニューから**新規資格情報**をクリックして新しい資格情報を作成できます。 </br>新しい資格情報を追加する際には、以下の点に注意してください：<ul><li>**資格情報名**：英字で始まり、英字または数字で終わるもので、英字、数字、アンダースコアを含み、長さは2～64文字です。</li><li>**認証タイプ**：**パスワード認証**、**公開鍵認証**、**既に設定済みのパスワードレス**の3種類が含まれます。</li> <li>**ユーザータイプ**：root権限を持つSSHユーザーをサポートします。root権限を持つ通常のユーザーは、sudoコマンドをパスワードレスで実行するために事前に設定する必要があります。OCPは現在、すべてのコマンドのsudoパスワードレス実行のみをサポートしており、これは`/etc/sudoers`ファイルに`username ALL=(ALL) NOPASSWD:ALL`を追加することで実現されます。</li></ul>|
   | **ホストエイリアス（オプション）**   | オプションで、ホストに他の名前を設定します。   |
   | **説明（オプション）**     | ホストのコメントであり、ホストをより適切に管理するために使用されます。      |

5. 入力が完了したら、**OK** をクリックします。

### ステップ2：OceanBaseクラスタを作成する

このセクションでは、OCPを使用してOceanBaseクラスタを作成する方法について説明します。

1. OCPのホームページで、実際のビジネスシナリオに基づいて、新しいクラスタを作成するためのエントリを見つけます。

   * 管理可能なクラスタがない場合、システムは**クラスタ**ページで新しいクラスタの作成を促します。その場合は、表示されるメッセージの中から**クラスタの作成**を直接クリックします。

   * 既に管理可能なクラスタがある場合は、左側の**クラスタ**をクリックし、**クラスタ**ページの右上隅にある**クラスタの作成**をクリックします。

   <main id="notice" type='explain'>
     <h4>説明</h4>
     <p>OCPはデフォルトで分散型クラスタを作成します。<b>クラスタの作成</b>ページの右上隅で、デプロイするクラスタモード（<b>分散型クラスタ</b>と<b>スタンドアロン集中型</b>）を選択できます。ここでは、<b>分散型クラスタ</b>の作成を例に説明します。</p></main>

2. **クラスタの作成**ページで、クラスタの基本情報を設定します。

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.2.5/400.deploy/200.deploy-by-ocp-02.png)

   基本情報の詳細は以下の表を参照してください。

   |    **構成**       |     **説明**    |
   |-------------------|-----------------|
   | **クラスタタイプ**      | **プライマリクラスタ**を選択します。<main id="notice" type='notice'><h4>適用対象</h4><p>OCP Community Editionは、新規のプライマリクラスタの作成のみをサポートしています。</p></main>  |
   | **クラスタ名**      | 管理対象のクラスタ名をカスタマイズします。クラスタ名は英字で始まり、英字または数字で終わる必要があります。英字、数字、アンダースコアを含み、長さは2～32文字です。 |
   | **root@sysパスワード** | カスタムまたはランダム生成が可能です。パスワードは以下の複雑さ要件を満たす必要があります：</br> <ul><li>長さ：8～32文字</li><li>次の4種類の文字のうち、少なくとも3種類以上を含む：数字（0～9）、大文字（A～Z）、小文字（a～z）、特殊記号`~!@#%^&*_-+=|(){}[]:;,.?/`</li></ul>パスワード入力後、**パスワードのコピー**をクリックして、カスタムまたはランダム生成されたパスワードをクリップボードにコピーできます。 |
   | **OceanBaseバージョン**   | リストから既存のOceanBaseデータベースバージョンを選択するか、ドロップダウンメニューで**ソフトウェアパッケージのアップロード**をクリックして、OceanBaseデータベースRPMパッケージをアップロードします。     |
   | **関連OBProxyクラスタ** | このオプションは、既存のODPクラスタを関連付けるために使用されます。マルチレプリカのOceanBaseクラスタを作成した場合は、**関連OBProxyクラスタ**スイッチをオンにして、そのOceanBaseクラスタにODPクラスタを関連付けることを推奨します。関連付け後、業務に関連するSQLリクエストは正確に対応するレプリカに転送されるため、OceanBaseデータベースへのアクセス効果は、スタンドアロンデータベースへのアクセスに匹敵します。<ul><li>デフォルトでは、`proxyro@sys`ユーザーを使用して関連付けられており、ユーザー名とパスワードを入力する必要はありません。</li><li>ドロップダウンボックスから関連付けるODPクラスタを選択します。ドロップダウンボックスに関連付けるODPクラスタがない場合は、本記事の**前提条件**に記載されているリンクを参照してODPクラスタを追加してください。</li></ul> <main id="notice" type='notice'><h4>注意</h4><ul><li>OceanBaseクラスタとネットワークが一致し、空でないOBProxyクラスタのみを選択できます。</li><li><p><b>OceanBaseバージョン</b>で選択したクラスタがV4.0以降のバージョンの場合、V4.0.0以降のバージョンのOBProxyクラスタのみを関連付けることができます。</p></li></ul></main> |
   | **ワークロードタイプ** | ドロップダウンボックスから対応するワークロードタイプを選択します。OCPは、異なるワークロードタイプに基づいてOceanBaseクラスタに異なる設定を行います。ワークロードタイプの詳細は以下のとおりです：<ul><li><b>Express OLTP</b>：貿易、決済コアシステム、インターネットの高スループットアプリケーションなどのワークロードに適しています。外部キーなどの制限はなく、ストアドプロシージャもなく、長時間のトランザクションや大規模なトランザクション、複雑な結合や複雑なサブクエリもありません。</br>バージョン制限：OceanBaseデータベースV4.2.5以降のバージョンに適しています。</li><li><b>HTAP</b>：ハイブリッドOLAPとOLTPのワークロードに適しています。通常、アクティブな運用データ、不正検出、パーソナライズされた提案から即時の洞察を得るために使用されます。</br>バージョン制限：OceanBaseデータベースV4.2.5以降のバージョンに適しています。</li><li><b>OLAP</b>：リアルタイムデータウェアハウス分析シナリオに使用されます。</br>バージョン制限：OceanBaseデータベースV4.3.0以降のバージョンに適しています。</li><li><b>Complex OLTP</b>：銀行、保険システムなどのワークロードに適しています。これらは通常、複雑な結合、複雑な関連サブクエリ、PLで記述されたバッチ処理ジョブ、長時間および大規模なトランザクションを持っています。短時間で実行されるクエリには、パラレル実行が使用されることがあります。</br>バージョン制限：OceanBaseデータベースV4.2.5以降のバージョンに適しています。</li><li><b>OBKV</b>：キー値ワークロードとHBaseのようなワイドカラムワークロードに使用されます。これらのワークロードは通常、非常に高いスループットを持ち、遅延に敏感です。</br>バージョン制限：OceanBaseデータベースV4.2.5以降のバージョンに適しています。</li></ul> |

3. クラスタのデプロイモード情報を設定します。

   デフォルトでは、3つのゾーンの情報が追加されます。デプロイするクラスタのゾーン数が3より多い場合は、下の**+ 新規ゾーン**ボタンをクリックしてゾーン情報を追加できます。デプロイするクラスタのゾーン数が3未満の場合は、ゾーンの後ろにある削除アイコンをクリックします。

   ![2](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.2.5/400.deploy/200.deploy-by-ocp-03.png)

   各ゾーンで設定する必要がある情報とその説明は以下の表を参照してください。

   |       **構成**     |            **説明**               |
   |--------------------|-----------------------------------|
   | **ゾーン名**      | 通常デフォルトの名前が付けられていますが、必要に応じてカスタマイズすることもできます。ゾーン名は英字で始まり、英字または数字で終わる必要があり、長さは2～32文字です。複数のゾーンをデプロイするOceanBaseクラスタでは、必ず1つのゾーンがプライマリゾーンのリージョンと同一である必要があります。 |
   | **データセンター**           | ゾーンが存在するデータセンター。1つのゾーンは1つのデータセンターにのみ存在できます。|
   | **マシンタイプ（オプション）**   | マシンタイプを選択した場合、後続のホストリストはそのマシンタイプに基づいてフィルタリングされます。 |
   | **CPUアーキテクチャ**   | 選択した**OceanBaseバージョン**に複数の異なるアーキテクチャのインストールパッケージが存在する場合、このソフトウェアパッケージに対応するホストのハードウェアアーキテクチャを選択する必要があります。<main id="notice" type='notice'><h4>注意</h4><ul><li><p>デフォルトのアーキテクチャタイプは最初のインストールパッケージのアーキテクチャタイプであり、切り替えが可能です。指定されたアーキテクチャに切り替えると、<b>ホスト</b>リストにそのアーキテクチャのホストが表示されます。</p></li><li><p>異なるゾーンに異なるアーキテクチャを設定する場合、ハイブリッドアーキテクチャデプロイメントモードでは安定性およびパフォーマンスに問題が生じる可能性があるため、慎重に操作してください。</p></li></ul></main>        |
   | **ホスト**           | 複数のホストを選択するか、新しいホストを追加することができます。           |
   | **Root Serviceの場所** | Root Serviceが配置されるマシンのIPアドレスを選択します。複数レプリカを持つOceanBaseクラスタでは、各ゾーンにRoot Serviceを指定する必要があります。        |
   | **ゾーン優先順位**  | クラスタのsysテナントのプライマリレプリカの分散に優先順位を指定します。最も高い優先順位を持つゾーンはPrimary Zoneと見なされ、その数は1つだけです。指定しない場合、デフォルトでは最初のゾーンが第一優先順位となります。順序付け方法は以下の通りです：<ol><li>左側のリストボックスから1つ以上のゾーンを選択します。左側のリストボックスには、現在のクラスタで利用可能なすべてのゾーンが表示されます。</li><li>中央の>ボタンをクリックします。これにより、選択されたゾーンは<b>優先順位</b>リストに移動します。同時に選択された複数のゾーンは同じ優先順位を持ちます。</li><li>1、2の操作を繰り返して、次に低い優先順位のゾーンを追加します。</li><li>優先順位を調整するには、<b>優先順位</b>リスト内でドラッグして順序を変更します。リスト内では上から下へ向かって優先順位が順次低下します。</li></ol>   |

4. クラスタにCgroupを有効にするかどうかを選択します。

   Cgroupは主にOceanBaseクラスタ内のテナント間およびテナント内のCPUリソースの分離に使用されます。作成するOceanBaseクラスタがV4.0以降のバージョンの場合、システムはデフォルトでCgroupを有効にし、より強力なCPU/IOPSの分離を実現します。Cgroupを有効にすると、パフォーマンスが約7%低下します。ビジネスシナリオが単一テナント、小規模構成(<14C>)であり、かつより高いデータベースパフォーマンスが必要な場合は、Cgroupを無効にすることを推奨します。また、ホスト上のOSカーネルバージョンが4.1.9未満の場合、クラスタはテナントを作成できず、この場合システムはデフォルトでCgroupを無効にし、Cgroupのスイッチも表示されません。

5. CPUオーバーコミットを設定します。

   **CPUオーバーコミット設定**スイッチをオンにして、CPUオーバーコミットの割合を設定できます。デフォルト値は120%で、スライダーまたは入力ボックスを使用してオーバーコミット率を101%～200%の範囲で設定できます。

   システム上の異なるテナントのワークロードは、制御可能な範囲で交互に実行されるため、CPUリソースを設定する際にオーバーコミット設定を行うことでリソース利用率を向上させることができます。異なるビジネスシナリオのワークロードが重複すると、OceanBaseクラスタの実行中にワークロード過負荷などの状況が発生し、異なるテナント間でスレッドがCPUを競合する現象が起こり、結果として実際のビジネスシナリオが遅くなる可能性があります。

6. **パラメータ設定**モジュールを開き、クラスタパラメータを設定します。

   ![3](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.2.5/400.deploy/200.deploy-by-ocp-05.png)

   * **基本設定**でワークロードタイプを設定した場合、システムはワークロードタイプに対応するパラメータテンプレートをデフォルトで選択します。

   * 図①のように、起動パラメータ項目を個別に追加し、それぞれに値を設定できます。OceanBaseデータベースのパラメータの詳細については、[構成パラメータの概要](../../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/200.system-configuration-items-overview-list.md)を参照してください。

   * また、図②のように、**パラメータテンプレートの選択**をクリックしてパラメータテンプレートを選択すると、システムはテンプレート内のパラメータと設定を自動的にここに入力します。**新規クラスタパラメータテンプレートの作成**をクリックして、クラスタ用のパラメータテンプレートを作成することもできます。詳細については、公式Webサイトの「OceanBaseクラウドプラットフォーム」ドキュメント[クラスタ管理/クラスタパラメータテンプレートの管理](https://www.oceanbase.com/docs/common-ocp-1000000002077892)を参照してください。

   OCPシステムは、一般的なパラメータ設定を含む以下の6種類の組み込みテンプレートを提供しており、テンプレートを直接適用してクラスタの初期設定を行うことができます。具体的な説明は以下の通りです：

   |           テンプレート            |                                   説明                                   |
   | ------------------------- | ------------------------------------------------------------------------ |
   | COMPLEX_OLTPデフォルトパラメータテンプレート | **Complex OLTP** ロードタイプに対応し、このテンプレートはOceanBaseデータベースV4.2.5以降のバージョンでのみ使用可能です。 |
   | HTAPデフォルトパラメータテンプレート         | **HTAP** ロードタイプに対応し、このテンプレートはOceanBaseデータベースV4.2.5以降のバージョンでのみ使用可能です。         |
   | KVデフォルトパラメータテンプレート           | **OBKV** ロードタイプに対応し、このテンプレートはOceanBaseデータベースV4.2.5以降のバージョンでのみ使用可能です。         |
   | EXPRESS_OLAPデフォルトパラメータテンプレート | **Express OLAP** ロードタイプに対応し、このテンプレートはOceanBaseデータベースV4.2.5以降のバージョンでのみ使用可能です。 |
   | OLAPデフォルトパラメータテンプレート         | **OLAP** ロードタイプに対応し、このテンプレートはOceanBaseデータベースV4.3.0以降のバージョンでのみ使用可能です。         |
   | 2.2.77デフォルトパラメータテンプレート       | OceanBaseクラスタV2.2.77バージョンで推奨されるパラメータ設定であり、本番環境での使用を想定しています。          |

7. **カスタム設定**を開き、クラスタレベルのユーザー設定（OSの所有者ユーザーなど）、パス設定（ソフトウェアのインストールパス、データディスクパス、ログディスクパスなど）、ポート設定（SQLポート、RPCポートなど）を実行できます。

   * OSの所有者ユーザーの設定：

     このユーザーは、OBServerのインストールや実行に使用されるOSユーザーであり、編集はサポートされていません。ocp.operation.default.os.userパラメータのデフォルト設定を調整することでこのユーザーを変更できます。このパラメータの変更は、分散型クラスタの作成、OBProxyクラスタの作成、およびアービトレーションサービスの作成時にのみ影響を及ぼし、既存のクラスタの他の設定には影響しません。

   * パスの設定：

     | 構成パラメータ | 説明 |
     |---|----|
     | ソフトウェアのインストールパス | <ul><li><b>OSのユーザー</b>がadminの場合、<b>ソフトウェアのインストールパス</b>はデフォルトで <code>/home/admin/oceanbase</code> となります。カスタムパスの指定も可能です。</li><li><b>OSのユーザー</b>がadmin以外の場合、<b>ソフトウェアのインストールパス</b>はデフォルトで <code>/opt/oceanbase/oceanbase</code> となります。カスタムパスの指定も可能です。</li></ul>  |
     | データディスクパス | デフォルトは `/data/1` です。カスタムパスの指定も可能です。 |
     | ログディスクパス | デフォルトは `/data/log1` です。カスタムパスの指定も可能です。本番環境では、OceanBaseデータベースのログディスク容量をマシンメモリ容量の3倍以上に設定することを推奨します。また、パフォーマンスへの影響を避けるため、データディレクトリとログディレクトリを同一ディスクにマウントすることは推奨されません。<main id="notice" type='explain'><h4>説明</h4><p>OCP V4.3.0 BP1以降では、以下のバージョンのOceanBaseクラスタを作成する際、slogディレクトリはログディスクに配置され、データディスクとは結びつけられなくなりました。この場合、<code>log_disk_size=0</code> を設定すると、clog専用領域とみなされます。つまり、デフォルトの <code>log_disk_percentage</code> は90% となります。slogとclogが格納されるディスクのサイズが40GiB未満の場合、slog専用領域として確保される容量は4GiB未満となり、slogの書き込みに影響を与える可能性があります。</p><ul><li>V4.2.4.0 ≤ OceanBaseデータベースバージョン ＜ V4.3.0.0</li><li>OceanBaseデータベースバージョン ≥ V4.3.1.0</li></ul>slogに関する詳細は、<a href="../../../../700.reference/100.oceanbase-database-concepts/1200.observer-node-architecture/100.observer-installation-directory-structure.md">OBServerノードのインストールディレクトリ構造</a>を参照してください。</main> |

     設定完了後、**テスト**をクリックしてパスが利用可能かどうかを確認します。利用不可能な場合は、テスト結果に基づいてトラブルシューティングを行うか、パスを他の利用可能なパスに変更します。

   * ポートの設定：

     |   構成   |             説明              |
     | -------- | ----------------------------- |
     | SQLポート | デフォルトは2881で、カスタムポートにも対応しています。 |
     | RPCポート | デフォルトは2882で、カスタムポートにも対応しています。 |

     設定完了後、**テスト**をクリックしてポートが占有されていないかどうかを確認します。占有されている場合は、利用可能なポートを再設定する必要があります。

     ![5](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.2.5/400.deploy/200.deploy-by-ocp-05.png)

8. テスト完了後、**送信**をクリックします。

9. 表示される**送信内容の確認**ダイアログボックスで、情報に誤りがないことを確認し、**OK**をクリックします。
