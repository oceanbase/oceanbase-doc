# （オプション）クロックソースの設定

本記事では、クラスタ内の複数のマシンにNTPクロックソースを設定する方法について説明します。OceanBaseデータベースを単一マシンでデプロイする予定がある場合、または個人テストを行う場合、またはすでにNTPクロック同期を設定している場合は、この設定は不要です。

分散型OceanBaseクラスタをデプロイする場合は、クラスタ内の各マシン間で時間の同期を保証する必要があります。そうでないと、クラスタは起動できず、サービスの実行時にも異常が発生します。OceanBaseクラスタで許容されるクロック偏差は2秒を超えてはなりません。2秒を超えると、リーダーが存在しない状態になります。クロック同期を回復した後、OceanBaseクラスタを再起動すると正常に戻ります。

<main id="notice" type='explain'>
   <h4>説明</h4>
   <ul>
   <li>
   <p>本記事はx86アーキテクチャのCentOS Linux 7.9イメージ環境に基づいて操作ガイドを提供します。その他の環境では若干異なる場合がありますので、実際の環境に準じてください。</p>
   </li>
   <li>
   <p>OceanBaseはV4.0.0以降、動的なクロック変更をサポートしています。変更間隔が2秒以内であれば、データの正確性やクラスタの安定した動作に影響はありません。</p>
   </li>
   <li>
   <p>OCPがOceanBaseクラスタノード上にデプロイされていない場合でも、OCPノードとOceanBaseクラスタノード間でクロック同期を設定する必要があります。これは、使用中にクロック偏差によってOCPの操作異常が発生するのを防ぐためです。</p>
   </li>
   </ul>
</main>

## 前提条件

NTP時計ソースを設定する前に、すべてのマシンでrootユーザー権限を持っていることを確認してください。

## 手順

以下の手順に従ってNTP時計同期を設定します。

1. 各マシンで以下のコマンドを実行してNTPをインストールします。

   ```shell
   yum install ntp ntpdate -y
   ```

2. 以下のコマンドを実行して、サーバーのNTP接続を確認します。

   ```shell
   [root@centos-01 ~]# ntpq -4p
   remote refid st t when poll reach delay offset jitter
   ==============================================================================
   *time6.aliyun.co xxx.xxx.xxx.xxx 2 u 712 1024 377 21.951 4.253 4.208
   ```

3. (オプション) NTPサーバーサービスを有効にします。

   NTPサーバーが既にある場合は、この手順をスキップできます。このドキュメントでは、ターゲットマシン`10.10.10.1`をNTPサーバーとして使用します。

   1. 設定ファイルを編集します。

      rootユーザーとしてNTPサーバーにログインし、以下のコマンドを実行して設定ファイルを編集します：

      ```shell
      vi /etc/ntp.conf
      ```

      設定ファイルに以下の内容を追加します：

      ```shell
      server <your_ntp_server_ip>
      ```

      設定ファイルを保存して閉じます。

   2. 以下のコマンドを実行して、NTPサーバーサービスを再起動します：

      ```shell
      service ntpd restart
      ```

   3. 以下のコマンドを実行して、NTPサーバーサービスが正常に起動したかどうかを確認します：

      ```shell
      ps -ef | grep -i ntpd
      ```

   4. 以下のコマンドを実行して、NTPサービスの起動時自動起動を設定します：

      ```shell
      chkconfig ntpd on
      ```

4. NTPクライアントサービスを有効にします。

   <main id="notice" type='notice'>
     <h4>注意</h4>
     <p>NTPサーバーサービスが起動した後、NTPクライアントサービスを有効にするまで5分待機する必要があります。そうしないと、「no server suitable for synchronization found」というメッセージが表示されます。</p>
   </main>

   1. rootユーザーとしてOBServerノードサーバーにログインします。

   2. 以下のコマンドを実行して、NTPサービスを停止します：

      ```shell
      service ntpd stop
      ```

   3. 以下のコマンドを実行して、NTPサーバーの時間を同期します：

      ```shell
      ntpdate 10.10.10.1
      ```

   4. 設定ファイルを編集します。

      以下のコマンドを実行して、設定ファイルを開きます：

      ```shell
      vi /etc/ntp.conf
      ```

      設定ファイルに以下の内容を追加します：

      ```shell
      server <your_ntp_server_ip>
      ```

   5. 以下のコマンドを実行して、NTPサービスを起動します：

      ```shell
      /etc/init.d/ntpd start
      ```

5. 以下のコマンドを実行して、設定が正常に機能しているかどうかを検証します。

   コマンドを実行します：

   ```shell
   ntpstat
   ```

   次の結果が返されます：

   ```shell
   synchronised to NTP server (xxx.xxx.xxx.xxx) at stratum 3
   time correct to within 2 ms
   polling server every 64 s
   ```

   コマンドを実行します：

   ```shell
   timedatectl
   ```

   次の結果が返されます：

   ```shell
         Local time: Thu 2021-04-22 11:02:32 CST
     Universal time: Thu 2021-04-22 03:02:32 UTC
           RTC time: Thu 2021-04-22 11:02:32
          Time zone: Asia/Shanghai (CST, +0800)
        NTP enabled: yes
   NTP synchronized: yes
    RTC in local TZ: yes
         DST active: n/a
   ```

   上記のコマンドを実行して対応する結果が返された場合、NTPサービスが有効であることを示します。
