# Kubernetes環境におけるOceanBaseクラスタのデプロイ

本記事では、ob-operatorを使用してKubernetes環境にOceanBaseクラスタをデプロイする方法を、例を挙げて説明します。

## 前提条件

開始する前に、以下の条件を満たしていることを確認してください。

- 利用可能なKubernetesクラスタがあり、9個以上のCPU、33 GBの利用可能なメモリ、および360 GBの利用可能なストレージがあります。

- ob-operatorはcert-managerに依存しています。cert-managerがインストール済みであることを確認してください。cert-managerのインストール方法については、対応する [インストールガイド](https://cert-manager.io/docs/installation/)を参照してください。

- OceanBaseクラスタに接続するには、MySQLクライアントまたはOBClientがインストール済みである必要があります。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>本記事では、ob-operator V2.2.0を例に操作手順を説明します。他のバージョンでは、若干異なる場合があります。異なるバージョンの操作手順については、<a href='https://en.oceanbase.com/docs/community-ob-operator-doc-en-10000000001735158'>ob-operatorマニュアル</a>の該当するバージョンを参照することができます。</p>
</main>

## ob-operatorのデプロイ

ob-operatorを使用すると、Kubernetes上のOceanBaseデータベースのデプロイと運用保守を簡素化できます。ob-operatorは以下の2つの方法でデプロイすることができます。

### Helmを使用したデプロイ

以下のコマンドを実行して、ob-operatorをデプロイすることができます。

```shell
helm repo add ob-operator https://oceanbase.github.io/ob-operator/
helm install ob-operator ob-operator/ob-operator --namespace=oceanbase-system --create-namespace --version=2.2.0
```

パラメータの説明：

- `--namespace`：ネームスペースは必要に応じてカスタマイズすることができますが、`oceanbase-system` の使用を推奨します。

- `--version`：ob-operatorのバージョン番号で、最新バージョンを使用することを推奨します。

### 設定ファイルによるデプロイ

以下のコマンドを実行して、設定ファイルを用いてob-operatorをデプロイすることができます。

```shell
kubectl apply -f https://raw.githubusercontent.com/oceanbase/ob-operator/2.2.0_release/deploy/operator.yaml
```

#### ob-operatorのカスタマイズ

ob-operatorをカスタマイズする必要がある場合、以下のコマンドを実行して設定ファイルをダウンロードすることができます。

```shell
wget https://raw.githubusercontent.com/oceanbase/ob-operator/2.2.0_release/deploy/operator.yaml
```

必要に応じて設定ファイルを修正した後、以下のコマンドを実行してカスタムデプロイを行います。構成ファイル内の構成パラメータの詳細については、[ob-operatorの設定](https://en.oceanbase.com/docs/community-ob-operator-doc-en-10000000001735159)を参照することができます。

```shell
kubectl apply -f operator.yaml
```

## OceanBaseクラスタのデプロイ

1. PVCを作成します

   ob-operatorはOceanBaseクラスタをデプロイする際、OceanBaseクラスタのストレージとしてPVCを作成する必要があります。本記事では、local-path-provisionerを使用してPVCを管理します。デプロイコマンドは以下のとおりです。

   ```shell
   kubectl apply -f https://raw.githubusercontent.com/rancher/local-path-provisioner/v0.0.24/deploy/local-path-storage.yaml
   ```

   詳細については、[local-path-provisioner](https://github.com/rancher/local-path-provisioner)を参照することができます。

2. Namespaceを作成します

   以下のコマンドを実行して、OceanBaseクラスタのデプロイに使用されるNamespaceを作成します。

   ```shell
   kubectl create namespace oceanbase
   ```

   作成後、`kubectl get namespace oceanbase` コマンドを実行し、作成に成功したかどうか(ステータスが `Active` であること)を確認することができます。

3. デフォルトユーザーのシークレットを作成する

   OceanBaseクラスタを作成する前に、以下のコマンドを実行して、OceanBaseクラスタ内の特定のユーザー情報を格納するSecretを複数作成する必要があります。

   ```shell
   kubectl create secret -n oceanbase generic root-password --from-literal=password='<root_password>'
   kubectl create secret -n oceanbase generic proxyro-password --from-literal=password='<proxyro_password>'
   ```

   `<root_password>` と `<proxyro_password>` は、それぞれroot@sysユーザーとproxyro@sysユーザーのパスワードを表し、設定したいパスワードに変更する必要があります。作成後、`kubectl get secret -n oceanbase` コマンドを実行して、Secretリソースの作成に成功したかどうかを確認することができます。

4. OceanBaseクラスタを定義する

   OceanBaseクラスタはYAML構成ファイルで定義されます。`obcluster.yaml` という構成ファイルを作成するには、以下のコマンドを実行することができます。

   ```shell
   vi obcluster.yaml
   ```

   構成ファイルの内容例を以下に示します。

   ```yaml
   apiVersion: oceanbase.oceanbase.com/v1alpha1
   kind: OBCluster
   metadata:
     name: obcluster
     namespace: oceanbase
   spec:
     clusterName: obcluster
     clusterId: 1
     userSecrets:
       root: root-password
       proxyro: proxyro-password
     topology:
       - zone: zone1
         replica: 1
       - zone: zone2
         replica: 1
       - zone: zone3
         replica: 1
     observer:
       image: oceanbase/oceanbase-cloud-native:4.2.1.1-101010012023111012
       resource:
         cpu: 2
         memory: 10Gi
       storage:
         dataStorage:
           storageClass: local-path
           size: 50Gi
         redoLogStorage:
           storageClass: local-path
           size: 50Gi
         logStorage:
           storageClass: local-path
           size: 20Gi
     monitor:
       image: oceanbase/obagent:4.2.1-100000092023101717
       resource:
         cpu: 1
         memory: 1Gi
   ```

   主な構成パラメータは以下のとおりです。詳細な構成パラメータについては、[クラスタの作成](https://en.oceanbase.com/docs/community-ob-operator-doc-en-10000000001735170)を参照することができます。

   |                構成パラメータ                | 必須入力かどうか |                                     説明                                      |
   | ------------------------------------ | -------- | ----------------------------------------------------------------------------- |
   | metadata.name                        | 必須     | クラスタ名。K8sのリソース名。                                                    |
   | metadata.namespace                   | 必須     | クラスタが存在するネームスペース。                                                          |
   | spec.clusterName                     | 必須     | OceanBaseクラスタ名。                                                            |
   | spec.clusterId                       | 必須     | OceanBaseクラスタID。                                                           |
   | spec.userSecrets                     | 必須     | OceanBaseクラスタのデフォルトユーザーのSecret。                                             |
   | spec.userSecrets.root                | 必須     | OceanBaseクラスタroot@sysユーザーのSecret名。Secretにはpasswordフィールドが含まれている必要があります。 |
   | spec.userSecrets.proxyro             | オプション     | OceanBaseクラスタproxyro@sysユーザーのSecret名。Secretにはpasswordフィールドが含まれている必要があります。   |
   | spec.topology                        | 必須     | OceanBaseクラスタのデプロイメントtopoの定義。各Zoneの定義を含みます。                      |
   | spec.topology[i].zone                | 必須     | OceanBaseクラスタ内のZone名。                                                       |
   | spec.topology[i].replica             | 必須     | OceanBaseクラスタ内の　Zoneに含まれるOBServerノード数。                                 |
   | spec.observer.image                  | 必須     | 使用するOceanBaseデータベースイメージ。                                              |
   | spec.observer.resource               | 必須     | OceanBaseクラスタにおけるOBServerノードのリソース設定。                                          |
   | spec.observer.resource.cpu           | 必須     | OceanBaseクラスタにおけるOBServerノード のCPUリソース設定。2より大きい整数値に設定することを推奨します。2未満の場合、システム異常が発生します。                                     |
   | spec.observer.resource.memory        | 必須     | OceanBaseクラスタ内のOBServerノードのMemoryリソース設定。推奨値は10 GiBを超え、10 GiB未満の場合はシステム異常が発生します。                                  |
   | spec.observer.storage                | 必須     | OceanBaseクラスタ内のOBServerノードのストレージ設定。                                          |
   | spec.observer.storage.dataStorage    | 必須     | OceanBaseクラスタ内のOBServerノードのデータストレージ設定。`memory` サイズの3倍以上を推奨します。                                      |
   | spec.observer.storage.redoLogStorage | 必須     | OceanBaseクラスタ内のOBServerノードのClogストレージ設定。`memory` サイズの3倍以上を推奨します。                                    |
   | spec.observer.storage.logStorage     | 必須     | OceanBaseクラスタ内のOBServerノードの動作ログの保存設定。10 GiB以上を推奨します。                                  |
   | spec.observer.storage.*.storageClass | 必須     | ストレージ設定を有効にするために、PVC作成時に使用するstorageClassを定義します。                      |
   | spec.observer.storage.*.size         | 必須     | ストレージ設定で有効になり、PVC作成時の容量を定義するために使用されます。                                   |
   | spec.monitor                         | オプション     | モニタリング設定。有効化することを推奨します。ob-operatorはOBAgentを使用してモニタリングデータの収集を行い、Prometheusと連携することでOceanBaseクラスタの状態モニタリングを実現します。  |
   | spec.monitor.image                   | 必須     | OBAgentが使用するイメージ。                                                       |
   | spec.monitor.resource                | 必須     | モニタリング対象コンテナが使用するリソース。                                                          |
   | spec.monitor.resource.cpu            | 必須     | モニタリング対象コンテナが使用するCPUリソース。                                                     |
   | spec.monitor.resource.memory         | 必須     | モニタリング対象コンテナが使用するmemoryリソース。                                                  |

5. OceanBaseクラスタのデプロイ

   ```shell
   kubectl apply -f obcluster.yaml
   ```

   以下のコマンドを実行し、OceanBaseクラスタの状態を確認します。状態が `running` になれば、OceanBaseクラスタのデプロイと初期化が完了したことを表しています。このプロセスは通常数分を要し、主な時間のかかる部分はイメージの取得とクラスタの初期化です。

   ```shell
   kubectl get obclusters.oceanbase.oceanbase.com obcluster -n oceanbase
   ```

### OceanBaseクラスタへのダイレクト接続

OceanBaseクラスタのデプロイ後、このセクションの手順に従ってOceanBaseクラスタに直接接続できます。ODPをデプロイした後に、ODP経由でOceanBaseクラスタに接続することを推奨します。ODPのデプロイ手順については、下記の「ODPのデプロイ」を参照することができます。

1. OceanBaseクラスタのPodアドレスを取得する

   ```shell
   kubectl get pods -n oceanbase -l ref-obcluster=obcluster -o wide
   ```

   例の `oceanbase` はmetadata.namespaceの値に対応し、`obcluster` はmetadata.nameの値に対応します。実際の構成に合わせて置き換える必要があります。

   出力は以下のとおりです：

   ```shell
   NAME                                READY   STATUS    RESTARTS   AGE    IP            NODE     NOMINATED NODE   READINESS GATES
   obcluster-1-zone2-c76d303299a9      2/2     Running   0          4m     10.10.10.1    node-x   <none>           <none>
   obcluster-1-zone3-2cdf3cd8a05e      2/2     Running   0          4m     10.10.10.2    node-x   <none>           <none>
   obcluster-1-zone1-94904330202f      2/2     Running   0          4m     10.10.10.3    node-x   <none>           <none>
   ```

2. OceanBaseクラスタへの接続

   OceanBaseクラスタへの接続は、任意のノードのIPアドレスを使用して行うことができます。接続コマンドは以下のとおりです。

   ```shell
   mysql -h10.10.10.1 -P2881 -uroot@sys -p oceanbase -A -c
   ```

## ODPのデプロイ

ODPはYAML設定ファイルで定義され、詳細なデプロイ手順は以下のとおりです。

1. ODPの設定ファイルを作成する

   ```shell
   vi obproxy.yaml
   ```

   ここでは、設定ファイル名として `obproxy.yaml` を例に、ファイルの内容を以下に示します：

   ```yaml
   apiVersion: v1
   kind: Service
   metadata:
     name: svc-obproxy
     namespace: oceanbase
   spec:
     type: ClusterIP
     selector:
       app: obproxy
     ports:
       - name: "sql"
         port: 2883
         targetPort: 2883
       - name: "prometheus"
         port: 2884
         targetPort: 2884

   ---
   apiVersion: apps/v1
   kind: Deployment
   metadata:
     name: obproxy
     namespace: oceanbase
   spec:
     selector:
       matchLabels:
         app: obproxy
     replicas: 2
     template:
       metadata:
         labels:
           app: obproxy
       spec:
         containers:
           - name: obproxy
             image: oceanbase/obproxy-ce:4.2.1.0-11
             ports:
               - containerPort: 2883
                 name: "sql"
               - containerPort: 2884
                 name: "prometheus"
             env:
               - name: APP_NAME
                 value: helloworld
               - name: OB_CLUSTER
                 value: obcluster
               - name: RS_LIST
                 value: ${RS_LIST}
               - name: PROXYRO_PASSWORD
                 valueFrom:
                   secretKeyRef:
                     name: proxyro-password
                     key: password
             resources:
               limits:
                 memory: 2Gi
                 cpu: "1"
               requests:
                 memory: 200Mi
                 cpu: 200m
   ```

   主な環境変数の設定説明：

   - `APP_NAME`：ODPのアプリケーション名。

   - `OB_CLUSTER`：ODP接続のOceanBaseクラスタ名。

   - `RS_LIST`：OceanBaseクラスタのrs_listの形式は、`${ip1}:${sql_port1};${ip2}:${sql_port2};${ip3}:${sql_port3}` で、実際のデプロイ状況に応じて置き換える必要があります。OceanBaseクラスタにダイレクト接続して `SELECT GROUP_CONCAT(CONCAT(SVR_IP, ':', SQL_PORT) SEPARATOR ';') AS RS_LIST FROM oceanbase.DBA_OB_SERVERS;` コマンドを実行して確認できます。OceanBaseクラスタへのダイレクト接続操作については、「OceanBaseクラスタへのダイレクト接続」を参照することができます。

   - `PROXYRO_PASSWORD`：`name` には、前述で作成したproxyro@sysユーザーのSecret名を指定する必要があります。Secretにはpasswordフィールドが含まれている必要があります。

2. ODPのデプロイ

   ```shell
   kubectl apply -f obproxy.yaml
   ```

3. デプロイの成功を検証する

   以下のコマンドを実行して、ODPのPodの状態を確認してください。

   ```shell
   kubectl get pod -A | grep obproxy
   ```

   出力は以下のとおりです。obproxyのPodが2つあります。

   ```shell
   oceanbase            obproxy-5cb8f4d975-pmr59                          1/1     Running   0          21s
   oceanbase            obproxy-5cb8f4d975-xlvjp                          1/1     Running   0          21s
   ```

   以下のコマンドを実行して、ODPのサービスを確認してください。

   ```shell
   kubectl get svc svc-obproxy -n oceanbase
   ```

   出力は以下のとおりです：

   ```shell
   NAME          TYPE        CLUSTER-IP   EXTERNAL-IP   PORT(S)             AGE
   svc-obproxy   ClusterIP   10.10.10.1   <none>        2883/TCP,2884/TCP   2m26s
   ```

### ODPによるOceanBaseクラスタへの接続

OceanBaseクラスタへの接続にはODPの使用を推奨します。OceanBaseデータベースとODPのデプロイ後、以下の手順でOceanBaseクラスタに接続することができます。

1. ODPのサービス接続アドレスを取得する

   ```shell
   kubectl get svc ${servicename} -n ${namespace}

   # for example
   kubectl get svc svc-obproxy -n oceanbase
   ```

   出力は以下のとおりです：

   ```shell
   # output
   NAME          TYPE        CLUSTER-IP   EXTERNAL-IP   PORT(S)             AGE
   svc-obproxy   ClusterIP   10.10.10.1   <none>        2883/TCP,2884/TCP   2m26s
   ```

2. OceanBaseクラスタへの接続

   CLUSTER-IPとPORTを使用して接続できます。対応する接続コマンドは以下のとおりです。

   ```shell
   mysql -h10.10.10.1 -P2883 -uroot@sys#obcluster -p oceanbase -A -c
   ```

## OceanBaseクラスタの監視

OceanBase Dashboardツールを使用して、OceanBaseクラスタを監視することができます。OceanBase Dashboardはob-operatorと連携するGUI運用保守ツールです。現在の最新バージョンはV0.2.1であり、クラスタ管理、テナント管理、バックアップ管理、パフォーマンス監視、ターミナル接続などの機能を備えています。K8s環境において、ob-operatorと連携してOceanBaseクラスタのパフォーマンス指標を監視するための最適なツールです。

### OceanBase Dashboardのデプロイ

KubernetesパッケージマネージャーHelmを使用してOceanBase Dashboardをインストールすることを推奨します。Helmが既にインストールされていることを確認した後、以下の3つのコマンドを実行すれば、デフォルトのネームスペースにOceanBase Dashboardをインストールすることができます。

```shell
helm repo add ob-operator https://oceanbase.github.io/ob-operator/
helm repo update ob-operator
helm install oceanbase-dashboard ob-operator/oceanbase-dashboard --version=0.2.1
```

その他のネームスペースにOceanBase Dashboardをインストールする場合、最後のインストールコマンドを以下のコマンドに置き換えることができます。

```shell
helm install oceanbase-dashboard ob-operator/oceanbase-dashboard --version=0.2.1 -n <namespace> --create-namespace
```

ここで、`<namespace>` はOceanBase Dashboardをインストールする対象のネームスペースに設定する必要があります。対象のネームスペースが存在しない場合は、`--create-namespace` を指定して作成することができます。クラスタがLoadBalancerサービスをサポートしている場合、インストール時に `--set service.type=LoadBalancer` を設定して、LoadBalancerタイプのサービスを作成するように指定することができます。

コマンド実行後、以下が出力されれば、OceanBase Dashboardのデプロイは成功です。

```shell
NAME: oceanbase-dashboard
LAST DEPLOYED: Wed May  8 11:04:49 2024
NAMESPACE: default
STATUS: deployed
REVISION: 1
TEST SUITE: None
NOTES:
Welcome to OceanBase dashboard

1. After installing the dashboard chart, you can use `port-forward` to expose the dashboard outside like:

  > kubectl port-forward -n default services/oceanbase-dashboard-oceanbase-dashboard 18081:80 --address 0.0.0.0

then you can visit the dashboard on http://$YOUR_SERVER_IP:18081

2. Use the following command to get password for default admin user

  > echo $(kubectl get -n default secret oceanbase-dashboard-user-credentials -o jsonpath='{.data.admin}' | base64 -d)

Log in as default account:
Username: admin
Password: <Get from the above command>
```

OceanBase Dashboardのデプロイ後、K8sクラスタは必要なイメージの取得に時間を要します。以下のコマンドで、OceanBase Dashboardのインストールが完了したかどうかを確認することができます。

```shell
kubectl get deployment oceanbase-dashboard-oceanbase-dashboard
```

出力は以下のとおりです。`READY` 列に `1/1` と表示されている場合、インストールが完了しており、次の操作に進むことができます。

```shell
NAME                                      READY   UP-TO-DATE   AVAILABLE   AGE
oceanbase-dashboard-oceanbase-dashboard   1/1     1            1           2m10s
```

### OceanBase Dashboardへのアクセス

OceanBase Dashboardのデフォルトログインアカウントは `admin` です。出力結果の2番目のコマンドで、デフォルトアカウントのパスワードを取得することができます。コマンドは以下のとおりです。

```shell
echo $(kubectl get -n default secret oceanbase-dashboard-user-credentials -o jsonpath='{.data.admin}' | base64 -d)
```

OceanBase Dashboardには、以下の3つのアクセス方法があります。状況に応じて適切な方法を選択することができます。

- NodePortによるアクセス：OceanBase Dashboardは、デフォルトでNodePortタイプのサービスを作成します。NodePortを介してOceanBase Dashboardにアクセスすることができます。

- LoadBalancer経由でアクセス：ご利用のクラスタがLoadBalancerサービスをサポートしている場合、LoadBalancer経由でOceanBase Dashboardにアクセスすることができます。

- Port Forwardによる一時的なアクセス：クラスタノードのポートにアクセスできない場合、上記の2つのサービスは利用できません。Port Forwardを使用して、OceanBase Dashboardに一時的にアクセスすることができます。

:::tab

tab NodePortを介してアクセスする

OceanBase DashboardはデフォルトでNodePortタイプのサービスを作成します。ノードで公開されているポートを取得するには、以下のコマンドを実行することができます。なお、サービス名は、指定されたHelm Chart名によって変化します。具体的なサービス名は、OceanBase Dashboardインストール時の出力結果の最初のコマンドで確認することができます。本例では `oceanbase-dashboard-oceanbase-dashboard` となります。

```shell
kubectl get svc oceanbase-dashboard-oceanbase-dashboard
```

出力は以下のとおりです：

```shell
NAME                                      TYPE       CLUSTER-IP   EXTERNAL-IP  PORT(S)        AGE
oceanbase-dashboard-oceanbase-dashboard   NodePort   10.10.10.1   <none>       80:30176/TCP   13m
```

ブラウザから該当するK8sノードの `PORT` ポートにアクセスすると、OceanBase Dashboardのログイン画面が表示されます。サービスのポート番号はK8sによって動的に割り当てられ、ノードのIPアドレスは `kubectl get nodes -o wide` コマンドを実行することで確認することができます。

tab LoadBalancerを介してアクセスする

OceanBase Dashboardのインストール時にLoadBalancerタイプのサービスを作成するように指定することができます。また、OceanBase Dashboardのインストール後に以下のコマンドを実行して、サービスタイプをLoadBalancerに変更することもできます。

```shell
kubectl patch -n oceanbase-dashboard svc oceanbase-dashboard-oceanbase-dashboard --type=merge --patch='{"spec": {"type": "LoadBalancer"}}'
```

変更完了後、クラスタはOceanBase Dashboardサービスに外部IPアドレスを割り当てます。この外部IPアドレスを通じてOceanBase Dashboardのページにアクセスすることができます。変更後、しばらく待ってからサービス情報を再度確認すると、External IPフィールドに値が割り当てられていることがわかります。

```shell
kubectl get svc oceanbase-dashboard-oceanbase-dashboard
```

出力は以下のとおりです：

```shell
NAME                                      TYPE           CLUSTER-IP      EXTERNAL-IP    PORT(S)        AGE
oceanbase-dashboard-oceanbase-dashboard   LoadBalancer   10.10.10.1      10.10.10.2     80:18082/TCP   1d5h
```

ブラウザで `http://10.10.10.2:18082` を入力するとOceanBase Dashboardにアクセスすることができます。ここでは `EXTERNAL-IP` が `10.10.10.2`、`PORT` が `18082` の場合を例としており、実際の出力内容に合わせて置き換えることが必要となります。

tab Port Forwardを介した一時的なアクセス

クラスタノードのポートにアクセスできず、NodePortタイプのサービスを使用してOceanBase Dashboardを公開することができない、さらにLoadBalancerサービスもサポートされていないような場合には、`kubectl port-forward` コマンドを使用して、OceanBase Dashboardを現在のマシンの指定ポートに転送し、一時的にアクセスすることができます。例えば、次のコマンドを実行すると、OceanBase Dashboardが現在のマシン(このコマンドを実行しているマシン)の `18081` ポートに示されます。

```shell
kubectl port-forward -n default services/oceanbase-dashboard-oceanbase-dashboard 18081:80 --address 0.0.0.0
```

他のコンピュータのブラウザから、このマシンの `18081` ポートにアクセスすると、ログイン画面が表示されます。上記のコマンドを実行したマシンがご自身のPCの場合、ブラウザで `http://127.0.0.1:18081` にアクセスすると、サービスにアクセスすることができます。
:::
