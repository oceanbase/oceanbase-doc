# Kubernetes環境におけるOceanBaseクラスタのデプロイ

本記事では、例を交えてob-operatorを使用してKubernetes環境にOceanBaseクラスタをデプロイする方法を紹介します。

## 前提条件

開始する前に、以下の条件を満たしていることを確認してください：

- 利用可能なKubernetesクラスタがあり、少なくとも9つのCPUコア、33GBのメモリ、および360GBのストレージ容量が確保されていること。

- ob-operatorはcert-managerに依存しているため、cert-managerがインストール済みであることを確認してください。cert-managerのインストール方法については、対応する[インストールドキュメント](https://cert-manager.io/docs/installation/)を参照してください。

- OceanBaseクラスタに接続するには、MySQLクライアントまたはOBClientがインストール済みである必要があります。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>本記事では、ob-operator V2.2.0を例に操作手順を説明しますが、他のバージョンでは若干異なる場合があります。異なるバージョンの操作手順については、<a href='https://www.oceanbase.com/docs/community-ob-operator-doc-1000000000659334'>ob-operatorマニュアル</a>の該当するバージョンの内容を参照してください。</p>
</main>

## ob-operatorのデプロイ

ob-operatorを使用すると、Kubernetes上でOceanBaseデータベースのデプロイおよび運用保守が簡素化されます。ob-operatorは以下の2つの方法でデプロイできます。

### Helmを使用したデプロイ

以下のコマンドを実行してob-operatorをデプロイします。

```shell
helm repo add ob-operator https://oceanbase.github.io/ob-operator/
helm install ob-operator ob-operator/ob-operator --namespace=oceanbase-system --create-namespace --version=2.2.0
```

パラメータの説明：

- `--namespace`：ネームスペース。必要に応じてカスタマイズ可能です。`oceanbase-system`の使用を推奨します。

- `--version`：ob-operatorのバージョン番号。最新バージョンの使用を推奨します。

### 設定ファイルを使用したデプロイ

以下のコマンドを実行して、設定ファイルを使用してob-operatorをデプロイします。

```shell
kubectl apply -f https://raw.githubusercontent.com/oceanbase/ob-operator/2.2.0_release/deploy/operator.yaml
```

#### ob-operatorのカスタマイズ

ob-operatorをカスタマイズする場合は、以下のコマンドを実行して設定ファイルをダウンロードします。

```shell
wget https://raw.githubusercontent.com/oceanbase/ob-operator/2.2.0_release/deploy/operator.yaml
```

必要に応じて設定ファイルを修正した後、以下のコマンドを実行してカスタムデプロイを行います。設定ファイル内の構成パラメータの詳細な意味については、[ob-operatorの設定](https://www.oceanbase.com/docs/community-ob-operator-doc-1000000000659330)を参照してください。

```shell
kubectl apply -f operator.yaml
```

## OceanBaseクラスタのデプロイ

1. PVCの作成

   ob-operatorはOceanBaseクラスタをデプロイする際に、OceanBaseクラスタのストレージとしてPVCを作成する必要があります。本記事ではlocal-path-provisionerを使用してPVCを管理します。デプロイコマンドは以下のとおりです：

   ```shell
   kubectl apply -f https://raw.githubusercontent.com/rancher/local-path-provisioner/v0.0.24/deploy/
   ```

   詳細については[local-path-provisioner](https://github.com/rancher/local-path-provisioner)を参照してください。

2. Namespaceの作成

   以下のコマンドを実行して、OceanBaseクラスタのデプロイに使用するNamespaceを作成します。

   ```shell
   kubectl create namespace oceanbase
   ```

   作成後、`kubectl get namespace oceanbase` コマンドを実行して、作成に成功したかどうか（ステータスが `Active` の場合）確認できます。

3. デフォルトユーザーのSecretの作成

   OceanBaseクラスタを作成する前に、まず以下のコマンドを実行して、OceanBaseクラスタ内の特定のユーザーを格納するためにいくつかのSecretを作成する必要があります。

   ```shell
   kubectl create secret -n oceanbase generic root-password --from-literal=password='<root_password>'
   kubectl create secret -n oceanbase generic proxyro-password --from-literal=password='<proxyro_password>'
   ```

   `<root_password>` と `<proxyro_password>` はそれぞれroot@sysユーザーとproxyro@sysユーザーのパスワードを表しており、ご自身で設定したいパスワードに変更する必要があります。作成後、`kubectl get secret -n oceanbase` コマンドを実行して、Secretリソースが正常に作成されたかどうか確認できます。

4. OceanBaseクラスタの定義

   OceanBaseクラスタはyaml設定ファイルによって定義されます。以下のコマンドを実行して設定ファイルを作成します。ここでは、設定ファイル名を `obcluster.yaml` とします。

   ```shell
   vi obcluster.yaml
   ```

   設定ファイルの内容例は以下のとおりです。

   ```yaml
   apiVersion: oceanbase.oceanbase.com/v1alpha1
   kind: OBCluster
   metadata:
     name: obcluster
     namespace: oceanbase
   spec:
     clusterName: obcluster
     clusterId: 1
     userSecrets:
       root: root-password
       proxyro: proxyro-password
     topology:
       - zone: zone1
         replica: 1
       - zone: zone2
         replica: 1
       - zone: zone3
         replica: 1
     observer:
       image: oceanbase/oceanbase-cloud-native:4.2.1.1-101010012023111012
       resource:
         cpu: 2
         memory: 10Gi
       storage:
         dataStorage:
           storageClass: local-path
           size: 50Gi
         redoLogStorage:
           storageClass: local-path
           size: 50Gi
         logStorage:
           storageClass: local-path
           size: 20Gi
     monitor:
       image: oceanbase/obagent:4.2.1-100000092023101717
       resource:
         cpu: 1
         memory: 1Gi
   ```

   主な構成パラメータの紹介は以下のとおりです。詳細な構成パラメータについては[クラスタの作成](https://www.oceanbase.com/docs/community-ob-operator-doc-1000000000659352)を参照してください。

   |                パラメータ                | 必須   |                                     説明                                      |
   | ------------------------------------ | -------- | ----------------------------------------------------------------------------- |
   | metadata.name                        | はい    | クラスタ名。K8sにおけるリソースの名前です。                                                    |
   | metadata.namespace                   | はい    | クラスタが属するネームスペースです。                                                          |
   | spec.clusterName                     | はい    | OceanBaseクラスタ名です。                                                            |
   | spec.clusterId                       | はい    | OceanBaseクラスタIDです。                                                           |
   | spec.userSecrets                     | はい    | OceanBaseクラスタのデフォルトユーザーのSecretです。                                             |
   | spec.userSecrets.root                | はい    | OceanBaseクラスタroot@sysユーザーのSecret名前で、Secretにはpasswordフィールドを含める必要があります。 |
   | spec.userSecrets.proxyro             | 任意    | OceanBaseクラスタproxyro@sysユーザーのSecret名前で、Secretにはpasswordフィールドを含める必要があります。   |
   | spec.topology                        | はい    | OceanBaseクラスタのデプロイメントtopoの定義で、各Zoneの定義を含みます。                      |
   | spec.topology[i].zone                | はい    | OceanBaseクラスタ内のZone名です。                                                       |
   | spec.topology[i].replica             | はい    | OceanBaseクラスタ内のZoneに含まれるOBServerノード数です。                                 |
   | spec.observer.image                  | はい    | 使用するOceanBaseデータベースイメージです。                                              |
   | spec.observer.resource               | はい    | OceanBaseクラスタ内のOBServerノードのリソース設定です。                                          |
   | spec.observer.resource.cpu           | はい    | OceanBaseクラスタ内のOBServerノードのCPUリソース設定です。2より大きく2未満の整数に設定することを推奨します。2未満に設定するとシステム異常が発生します。                                     |
   | spec.observer.resource.memory        | はい   | OceanBaseクラスタ内のOBServerノードのメモリリソース設定です。推奨値は10Giを超える値で、10Gi未満ではシステム異常が発生する可能性があります。                                  |
   | spec.observer.storage                | はい   | OceanBaseクラスタ内のOBServerノードのストレージ設定です。                                          |
   | spec.observer.storage.dataStorage    | はい   | OceanBaseクラスタ内のOBServerノードのデータストレージ設定で、少なくとも`memory`サイズの3倍以上を推奨します。                                      |
   | spec.observer.storage.redoLogStorage | はい   | OceanBaseクラスタ内のOBServerノードのClogストレージ設定で、少なくとも`memory`サイズの3倍以上を推奨します。                                    |
   | spec.observer.storage.logStorage     | はい   | OceanBaseクラスタ内のOBServerノードの実行ログストレージ設定で、サイズは少なくとも10Gi以上を推奨します。                                  |
   | spec.observer.storage.*.storageClass | はい   | ストレージ設定に適用され、PVC作成時に使用するstorageClassを定義します。                      |
   | spec.observer.storage.*.size         | はい   | ストレージ設定に適用され、PVC作成時の容量を定義します。                                   |
   | spec.monitor                         | 任意   | モニタリング設定で、有効化を推奨します。ob-operatorはOBAgentを使用してモニタリングデータの収集を行い、Prometheusと連携することでOceanBaseクラスタの状態監視を実現します。  |
   | spec.monitor.image                   | はい   | OBAgentが使用するイメージです。                                                       |
   | spec.monitor.resource                | はい   | モニタリングコンテナが使用するリソースです。                                                          |
   | spec.monitor.resource.cpu            | はい   | モニタリングコンテナが使用するCPUリソースです。                                                     |
   | spec.monitor.resource.memory         | はい   | モニタリングコンテナが使用するメモリリソースです。                                                  |

5. OceanBaseクラスタのデプロイ

   ```shell
   kubectl apply -f obcluster.yaml
   ```

   以下のコマンドを実行してOceanBaseクラスタのステータスを確認します。ステータスが `running` に変わったら、OceanBaseクラスタのデプロイと初期化が完了したことを意味します。このプロセスには通常数分かかり、主にイメージの取得とクラスタの初期化に時間がかかります。

   ```shell
   kubectl get obclusters.oceanbase.oceanbase.com obcluster -n oceanbase
   ```

### OceanBaseクラスタへの直接接続

OceanBaseクラスタをデプロイした後、このセクションの手順に従ってOceanBaseクラスタに直接接続できます。ODPをデプロイした後は、ODP経由でOceanBaseクラスタに接続することを推奨します。ODPのデプロイ方法については、以下の[ODPのデプロイ](#ODPのデプロイ)を参照してください。

1. OceanBaseクラスタPodアドレスを取得する

   ```shell
   kubectl get pods -n oceanbase -l ref-obcluster=obcluster -o wide
   ```

   例の`oceanbase`はmetadata.namespaceの値に、`obcluster`はmetadata.nameの値に対応します。実際の構成に応じて置き換える必要があります。

   出力は次のとおりです：

   ```shell
   NAME                                READY   STATUS    RESTARTS   AGE    IP            NODE     NOMINATED NODE   READINESS GATES
   obcluster-1-zone2-c76d303299a9      2/2     Running   0          4m     10.10.10.1    node-x   <none>           <none>
   obcluster-1-zone3-2cdf3cd8a05e      2/2     Running   0          4m     10.10.10.2    node-x   <none>           <none>
   obcluster-1-zone1-94904330202f      2/2     Running   0          4m     10.10.10.3    node-x   <none>           <none>
   ```

2. OceanBaseクラスタに接続する

   任意のノードのIPアドレスを使用してOceanBaseクラスタに接続できます。対応する接続コマンドは以下のとおりです。

   ```shell
   mysql -h10.10.10.1 -P2881 -uroot@sys -p oceanbase -A -c
   ```

## ODPのデプロイ

ODPはyaml設定ファイルによって定義され、詳細なデプロイ手順は以下のとおりです。

1. ODPの設定ファイルを作成します

   ```shell
   vi obproxy.yaml
   ```

   ここでは、設定ファイル名を`obproxy.yaml`とした場合の内容を例に示します。

   ```yaml
   apiVersion: v1
   kind: Service
   metadata:
     name: svc-obproxy
     namespace: oceanbase
   spec:
     type: ClusterIP
     selector:
       app: obproxy
     ports:
       - name: "sql"
         port: 2883
         targetPort: 2883
       - name: "prometheus"
         port: 2884
         targetPort: 2884

   ---
   apiVersion: apps/v1
   kind: Deployment
   metadata:
     name: obproxy
     namespace: oceanbase
   spec:
     selector:
       matchLabels:
         app: obproxy
     replicas: 2
     template:
       metadata:
         labels:
           app: obproxy
       spec:
         containers:
           - name: obproxy
             image: oceanbase/obproxy-ce:4.2.1.0-11
             ports:
               - containerPort: 2883
                 name: "sql"
               - containerPort: 2884
                 name: "prometheus"
             env:
               - name: APP_NAME
                 value: helloworld
               - name: OB_CLUSTER
                 value: obcluster
               - name: RS_LIST
                 value: ${RS_LIST}
               - name: PROXYRO_PASSWORD
                 valueFrom:
                   secretKeyRef:
                     name: proxyro-password
                     key: password
             resources:
               limits:
                 memory: 2Gi
                 cpu: "1"
               requests:
                 memory: 200Mi
                 cpu: 200m
   ```

   主な環境変数の設定について説明します：

   - `APP_NAME`：ODPのアプリケーション名。

   - `OB_CLUSTER`：ODPが接続するOceanBaseクラスタ名。

   - `RS_LIST`：OceanBaseクラスタのrs_listで、形式は `${ip1}:${sql_port1};${ip2}:${sql_port2};${ip3}:${sql_port3}` となります。実際のデプロイ状況に応じて置き換える必要があります。OceanBaseクラスタに直接接続して、`SELECT GROUP_CONCAT(CONCAT(SVR_IP, ':', SQL_PORT) SEPARATOR ';') AS RS_LIST FROM oceanbase.DBA_OB_SERVERS;` コマンドを実行することで確認できます。OceanBaseクラスタへの直接接続操作については、[OceanBaseクラスタへの直接接続](#OceanBaseクラスタへの直接接続)を参照してください。

   - `PROXYRO_PASSWORD`：上記で作成したproxyro@sysユーザーのSecret名を`name`に設定し、Secretにはpasswordフィールドを含める必要があります。

2. ODPをデプロイします

   ```shell
   kubectl apply -f obproxy.yaml
   ```

3. デプロイが成功したかどうかを検証します

   以下のコマンドを実行して、ODPのPodの状態を確認します。

   ```shell
   kubectl get pod -A | grep obproxy
   ```

   出力は以下のとおりで、2つのobproxy Podが存在します。

   ```shell
   oceanbase            obproxy-5cb8f4d975-pmr59                          1/1     Running   0          21s
   oceanbase            obproxy-5cb8f4d975-xlvjp                          1/1     Running   0          21s
   ```

   以下のコマンドを実行して、ODPのサービスを確認します。

   ```shell
   kubectl get svc svc-obproxy -n oceanbase
   ```

   出力は以下のとおりです：

   ```shell
   NAME          TYPE        CLUSTER-IP   EXTERNAL-IP   PORT(S)             AGE
   svc-obproxy   ClusterIP   10.10.10.1   <none>        2883/TCP,2884/TCP   2m26s
   ```

### ODPを使用してOceanBaseクラスタに接続する

OceanBaseクラスタへの接続には、ODPを使用することを推奨します。OceanBaseデータベースとODPがデプロイされた後、以下の手順でOceanBaseクラスタに接続できます。

1. ODPのサービス接続アドレスを取得します

   ```shell
   kubectl get svc ${servicename} -n ${namespace}

   # for example
   kubectl get svc svc-obproxy -n oceanbase
   ```

   出力は次のとおりです：

   ```shell
   # output
   NAME          TYPE        CLUSTER-IP   EXTERNAL-IP   PORT(S)             AGE
   svc-obproxy   ClusterIP   10.10.10.1   <none>        2883/TCP,2884/TCP   2m26s
   ```

2. OceanBaseクラスタに接続します

   CLUSTER-IPとPORTを使用して接続できます。対応する接続コマンドは以下のとおりです。

   ```shell
   mysql -h10.10.10.1 -P2883 -uroot@sys#obcluster -p oceanbase -A -c
   ```

## OceanBaseクラスタの監視

OceanBase Dashboardツールを使用して、OceanBaseクラスタを監視できます。OceanBase Dashboardは、ob-operatorと連携したGUIベースの運用保守ツールであり、現在の最新バージョンはV0.2.1です。クラスタ管理、テナント管理、バックアップ管理、パフォーマンス監視、端末接続などの機能を備えており、Kubernetes環境においてob-operatorと組み合わせてOceanBaseクラスタのパフォーマンス指標を監視するための最適なツールです。

### OceanBase Dashboardのデプロイ

OceanBase Dashboardのインストールには、KubernetesパッケージマネージャーであるHelmを使用することを推奨します。Helmがインストール済みであることを確認したら、以下の3つのコマンドを実行することで、デフォルトのネームスペースにOceanBase Dashboardをインストールできます。

```shell
helm repo add ob-operator https://oceanbase.github.io/ob-operator/
helm repo update ob-operator
helm install oceanbase-dashboard ob-operator/oceanbase-dashboard --version=0.2.1
```

他のネームスペースにOceanBase Dashboardをインストールする場合は、最後のインストールコマンドを次のコマンドに置き換えてください。

```shell
helm install oceanbase-dashboard ob-operator/oceanbase-dashboard --version=0.2.1 -n <namespace> --create-namespace
```

ここで、`<namespace>` はOceanBase Dashboardをインストールするターゲットネームスペースに設定する必要があります。ターゲットネームスペースが存在しない場合は、`--create-namespace` を設定して作成できます。クラスタがLoadBalancerサービスをサポートしている場合は、インストール時に `--set service.type=LoadBalancer` を設定して、LoadBalancerタイプのサービスを作成することもできます。

コマンド実行後に以下の出力が表示された場合、OceanBase Dashboardのデプロイは成功です。

```shell
NAME: oceanbase-dashboard
LAST DEPLOYED: Wed May  8 11:04:49 2024
NAMESPACE: default
STATUS: deployed
REVISION: 1
TEST SUITE: None
NOTES:
Welcome to OceanBase dashboard

1. After installing the dashboard chart, you can use `port-forward` to expose the dashboard outside like:

  > kubectl port-forward -n default services/oceanbase-dashboard-oceanbase-dashboard 18081:80 --address 0.0.0.0

then you can visit the dashboard on http://$YOUR_SERVER_IP:18081

2. Use the following command to get password for default admin user

  > echo $(kubectl get -n default secret oceanbase-dashboard-user-credentials -o jsonpath='{.data.admin}' | base64 -d)

Log in as default account:
Username: admin
Password: <Get from the above command>
```

OceanBase Dashboardをデプロイした後、K8sクラスタは必要なイメージを取得するために一定の時間を要します。以下のコマンドを使用して、OceanBase Dashboardのインストールが完了したかどうかを確認できます。

```shell
kubectl get deployment oceanbase-dashboard-oceanbase-dashboard
```

出力が以下のようになり、`READY` 列に `1/1` が表示されている場合、インストールが完了し、その後の操作を続けることができます。

```shell
NAME                                      READY   UP-TO-DATE   AVAILABLE   AGE
oceanbase-dashboard-oceanbase-dashboard   1/1     1            1           2m10s
```

### OceanBase Dashboardへのアクセス

OceanBase Dashboardには、デフォルトで`admin`というログインアカウントが作成されています。出力された2番目のコマンドを実行することで、このデフォルトアカウントのパスワードを取得できます。コマンドは以下のとおりです。

```shell
echo $(kubectl get -n default secret oceanbase-dashboard-user-credentials -o jsonpath='{.data.admin}' | base64 -d)
```

OceanBase Dashboardへのアクセス方法は以下の3つあり、状況に応じて適切な方法を選択できます。

- NodePort経由でのアクセス：OceanBase DashboardにはデフォルトでNodePortタイプのサービスが作成されているため、NodePortを通じてOceanBase Dashboardにアクセスできます。

- LoadBalancer経由でのアクセス：クラスタがLoadBalancerサービスをサポートしている場合、LoadBalancerを通じてOceanBase Dashboardにアクセスできます。

- Port Forwardによる一時的なアクセス：クラスタノードのポートがアクセス不可能で、上記の2つのサービスを利用できない場合、Port Forwardを通じてOceanBase Dashboardに一時的にアクセスできます。

:::tab
tab NodePortによるアクセス

OceanBase DashboardはデフォルトでNodePortタイプのサービスを作成します。以下のコマンドを実行することで、ノード上で公開されているポートを取得できます。なお、サービス名は指定したHelm Chart名に応じて変更されるため、注意が必要です。具体的には、OceanBase Dashboardのインストール時に出力される最初のコマンドに記載されているサービス名を参照してください。本記事の例では、`oceanbase-dashboard-oceanbase-dashboard` となります。

```shell
kubectl get svc oceanbase-dashboard-oceanbase-dashboard
```

出力は次のとおりです：

```shell
NAME                                      TYPE       CLUSTER-IP   EXTERNAL-IP  PORT(S)        AGE
oceanbase-dashboard-oceanbase-dashboard   NodePort   10.10.10.1   <none>       80:30176/TCP   13m
```

このK8sノードの `PORT` ポートにブラウザでアクセスすると、OceanBase Dashboardのログイン画面が表示されます。サービスのポート番号はK8sによって動的に割り当てられ、ノードのIPアドレスは `kubectl get nodes -o wide` コマンドを実行することで確認できます。

tab LoadBalancer経由でアクセス

OceanBase Dashboardのインストール時にLoadBalancerタイプのサービスを作成するよう指定することも、OceanBase Dashboardのインストール後に以下のコマンドを実行してサービスタイプをLoadBalancerに変更することもできます。

```shell
kubectl patch -n oceanbase-dashboard svc oceanbase-dashboard-oceanbase-dashboard --type=merge --patch='{"spec": {"type": "LoadBalancer"}}'
```

変更完了後、クラスタはOceanBase Dashboardサービスに外部IPアドレスを割り当てます。この外部IPアドレスを使用してOceanBase Dashboardのページにアクセスできます。変更後しばらく待ってから再度サービス情報を確認すると、External IPフィールドに値が代入されていることが確認できます。

```shell
kubectl get svc oceanbase-dashboard-oceanbase-dashboard
```

出力は次のとおりです：

```shell
NAME                                      TYPE           CLUSTER-IP      EXTERNAL-IP    PORT(S)        AGE
oceanbase-dashboard-oceanbase-dashboard   LoadBalancer   10.10.10.1      10.10.10.2     80:18082/TCP   1d5h
```

ブラウザに `http://10.10.10.2:18082` を入力すると、OceanBase Dashboardにアクセスできます。ここでは、`EXTERNAL-IP` を `10.10.10.2`、`PORT` を `18082` としていますが、実際の出力に応じて置き換える必要があります。

タブ：ポートフォワードによる一時的なアクセス

クラスタノードのポートがアクセスできない場合、NodePort型のサービスを使用してOceanBase Dashboardを公開することができず、LoadBalancerサービスもサポートされていません。この場合、`kubectl port-forward` コマンドを使用して、OceanBase Dashboardを現在のマシンの指定されたポートに公開し、一時的にアクセスできます。例えば、以下のコマンドを実行すると、OceanBase Dashboardが現在のマシン（このコマンドを実行しているマシン）の `18081` ポートに公開されます。

```shell
kubectl port-forward -n default services/oceanbase-dashboard-oceanbase-dashboard 18081:80 --address 0.0.0.0
```

別のパソコンのブラウザからこのマシンの `18081` ポートにアクセスすると、ログイン画面が表示されます。上記のコマンドを実行したマシンが個人用のパソコンの場合、ブラウザで `http://127.0.0.1:18081` にアクセスすると、サービスにアクセスできます。
:::
