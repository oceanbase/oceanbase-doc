# データ転送の概要

OceanBase APシナリオにおいて、**データ転送**は**データ移行**、**データインポート**、**データ同期**、および**データサブスクリプション**を含みます。それぞれデータベースの切り替え、一括テーブル投入、継続的なデータ書き込みの整合性、変更イベントの配信に対応しています。以下では、**ビジネス目標**に基づいて選定ポイントをまとめ、対応するドキュメントへのリンクを示します。

## データ移行

明確な時点または段階で**ターゲットデータベースの構築または置換**を完了し、業務の読み書きをOceanBase（または新しいテナント）に切り替え、構造の整合性とデータの収束を図ります。

* **典型的なシナリオ**：MySQL/Oracleなどの一括または段階的な置換；OceanBaseバージョンのアップグレード、クラスタの置換；TPデータベースからの移行後のAP処理；特定の時点の履歴スナップショットのみが必要で、継続的なCDCが不要な少数のオフライン移行。

* **関連ドキュメント**：[データ移行の概要](200.data-migration/100.ap-data-migration-overview.md)、[ツールを使用したデータ移行](200.data-migration/200.migrate-data-with-tools.md)、[データインポート戦略とベストプラクティス](200.data-migration/500.best-practices-migrating-from-mainstream-databases-to-oceanbase.md)、[主要APデータベースからOceanBaseへの移行に関するベストプラクティス](200.data-migration/500.best-practices-migrating-from-mainstream-databases-to-oceanbase.md)。

### データインポート

外部データを**OceanBaseの内部テーブルにインポート**する際、データソースはローカルファイル、オブジェクトストレージ、HDFSなどが可能です。`LOAD DATA`、外部テーブル、`FILES`テーブル関数、または`INSERT INTO ... SELECT`などの方法でインポートを実行できます。

* **典型的なシナリオ**：履歴明細やログアーカイブの一括取り込み；CSV/ORC/ParquetなどのファイルがOSS、HDFSなどのリモートパスにある場合；超大規模テーブルや全量データを**ダイレクトロード**でより効率的に書き込む場合；外部テーブルや`FILES`を使用してレイクハウスのデータを読み取った後、**内部テーブルにインポート**する場合。

* **関連ドキュメント**：[データインポートの概要](300.data-import/100.data-import-overview.md)、[LOAD DATA FROM FILES](300.data-import/200.load-data-import.md)、[LOAD DATA INFILE](300.data-import/200.load-data-import.md)、[LOAD DATA LOCAL INFILE](300.data-import/200.load-data-import.md)、[ダイレクトロードの概要](300.data-import/100.data-import-overview.md)、[全量ダイレクトロード](300.data-import/100.data-import-overview.md)、[INSERT INTO SELECT FROM FILES](300.data-import/300.insert-into/100.insert-into-select-from-files.md)、[外部テーブルを使用したINSERT INTO SELECTによるインポート](300.data-import/300.insert-into/200.insert-into-select-from-external-table.md)、[obloaderを使用したデータインポート](300.data-import/500.import-data-with-obloader.md)。

### データ同期

**長期間**にわたり、ターゲットデータベース（通常はOceanBase）とソースデータベースの間で**業務上許容可能な一貫性**または遅延の上限を維持し、ツールが**ターゲットデータベースへの継続的な書き込み**を行います。

* **典型的なシナリオ**：同一リージョン/異リージョンの災害復旧、二台構成のホットスタンバイ；切り替え前後の短期間の二重書き込みとロールバックウィンドウ；マルチアクティブまたは読み書き分離環境におけるレプリカとプライマリデータベースの整合性。

* **関連ドキュメント**：[データ同期の概要](400.data-synchronization/100.data-synchronization.md)。

### データサブスクリプション

上流から**データベースログやCDCイベント**を継続的に読み取り、解析後に**Kafka、Flink**などに転送します。これにより、**複数の下流システム**がそれぞれ消費、処理、または選択的にデータベースに書き込みます。

* **典型的なシナリオ**：Canal、Flink CDCなどのコンポーネントを使用してデータベースの変更をサブスクライブし、変更データをKafkaなどのメッセージシステムに書き込みます。これにより、リアルタイムデータウェアハウス、ストリーム処理タスク、または複数の業務システムがそれぞれ消費できます。

* **関連ドキュメント**：[データサブスクリプションの概要](400.data-synchronization/300.data-subscription.md)、[データ同期の概要](400.data-synchronization/100.data-synchronization.md)（OMSのデータ書き込み経路と照らし合わせて参照）、[データインポート戦略とベストプラクティス](200.data-migration/500.best-practices-migrating-from-mainstream-databases-to-oceanbase.md)。
