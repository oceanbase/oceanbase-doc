# OceanBase AP 概要

## OceanBase AP とは

OceanBase は、完全に自社開発のエンタープライズレベルのネイティブ分散型データベースであり、一般的なハードウェア上で金融業界レベルの高可用性を実現し、「3 リージョン 5 センター」という都市レベルの障害による損失が発生しない自動ディザスタリカバリの新基準を確立し、TPC-C 標準テストにおいて世界記録を更新したことがあります。シングルクラスター規模は 1,500 ノードを超え、クラウドネイティブ、強固な一貫性の実現、Oracle/MySQL との高い互換性などの特徴を備えています。V4.3.x バージョンでは、OceanBase データベースは分析処理 (AP) シナリオの最適化に重点を置き、トランザクション処理 (TP) と分析処理 (AP) の統合を実現しました。今回の更新では、OceanBase の LSM-Tree アーキテクチャに基づいて、行ストアのストレージと列ストアのストレージの一体化を実現すると同時に、列ストアのストレージに基づく新しいベクトル化エンジンとコスト評価モデルを導入しました。これらの機能強化により、ワイドテーブルの処理効率が大幅に向上し、AP シナリオにおけるクエリのパフォーマンスが著しく改善されました。同時に、リアルタイムインポート、セカンダリインデックス、高並列プライマリキークエリなど、リアルタイム OLAP における一般的なニーズもサポートしています。

![ap-intro](https://obportal.s3.ap-southeast-1.amazonaws.com/doc/img/OceanBase-Database-EN/ap-intro.png)

## コアの強み

* **信頼性と安定性**

  * TP と AP の一体化構築による、金融のコア取引システムで実証された安定性。
  * 業界初となる 3 リージョン 5 センターでは都市レベルの障害による損失が発生しないディザスタリカバリをサポート可能で、世界トップクラスの RPO = 0、RTO 8 秒未満の障害自動復旧能力を備え、厳しい条件下でのビジネス継続性が可能となります。

* **高パフォーマンス分析**

  * OceanBase データベースは列ストアおよび列混合ストレージ、およびさまざまなクエリ最適化手段をサポートしており、優れたクエリパフォーマンスを保証します。さらに、OceanBase データベース V4.3 バージョンではベクトル化エンジン 2.0 を実装しており、データ形式、オペレータ実装の最適化、ストレージベクトル化の最適化などにより、ベクトル化エンジンの実行パフォーマンスが大幅に向上しました。
  * Ad-hoc クエリのパフォーマンスは ClickHouse と同等です。
  * TPC-H 30,000 GB で 1 位。

* **低コストで管理しやすい**

  * HTAP 混合ワークロードは、従来の TP+AP の 2 つのシステムに代わる単一システムで、データベースやテーブルのシャーディングが不要です。

* **HSAP**

  * 分析結果をオンラインデータサービスで直接提供します。

* **マルチモデル**

  * JSON、GIS、テキストなどの非構造化データを SQL を用いて分析できます。

## 適用シナリオ

#### シナリオ 1：リアルタイムレポートとリアルタイムリスクコントロール

以下のようなデータベースの使用方法があります：ほとんどのシナリオでは、データベースは OLTP ワークロードであり、ごく一部のケースで OLAP ワークロードが発生します。このようなシナリオでは、分析のために専用の AP クラスターを購入するのは非常に非効率的です。この場合、OceanBase データベースの行と列の混合レプリカを使用するか、行ストアレプリカに列ストアインデックスを作成することができます。行形式で TP、列形式で AP を行い、リソースグループによってソフト分離を実現します。

行ストアを基盤とし、列ストアインデックスを作成することで、クラスター内で列ストアの機能を獲得し、クエリを高速化できます。行ストアと列ストアは同一クラスター内に存在し、同じリソースセットを共有しています。リソース分離の要件があるため、同一テナント内で cgroup 分離、CPU、I/O などの分離を行い、TP と AP 間で相互干渉が起こらないようにしています。

- TP は行ストアを使用
- AP は列ストアインデックスを使用 (ストレージのオーバーヘッドを削減)
- 隔離はリソースグループを使用

![image1](https://obportal.s3.ap-southeast-1.amazonaws.com/doc/img/OceanBase-Database-EN/Scenario1.png)

#### シナリオ 2：軽量リアルタイムデータウェアハウス

OceanBase データベースは、列ストア、並列実行エンジン、ベクトル化エンジン、リライトとコストに基づくオプティマイザーを基盤としており、軽量データウェアハウスの役割を担う能力を備えています。データウェアハウスのシナリオでは、OceanBase データベースを全面的に使用して ETL を簡素化することができます。マテリアライズドビューを使用して ETL を簡素化し、同時に Flink をサポートすることもできます。Flink query を変更せずに引き続き使用して OceanBase データベースをストレージとして使用できます。OceanBase データベースは、ODS のログをサブスクライブしてリアルタイムにストリーミング計算を行い、その結果を ODS に書き込んで、外部システムとのインタラクティブクエリやフェデレーションクエリに使用できます。

- AP は列ストアを使用
- TP は行ストアインデックスを使用 (AP ポイントクエリを高速化)
- 隔離はリソースグループを使用

#### シナリオ 3：Serving シナリオ

Serving シナリオとは、リアルタイムの意思決定とインタラクティブなデータ探索をサポートするために、迅速な応答と低レイテンシでデータの処理と分析を必要とするシナリオを指します。通常、集計操作の高速化には列指向ストレージが採用され、インデックスを利用してデータ検索時間を短縮し、分散コンピューティングフレームワークを活用して水平方向にスケールすることで、大規模データセットを処理します。

Serving のパフォーマンスを向上させるため、ビジネスでは通常、結果を事前に結合して、大規模なワイドテーブルをデータベースに格納します。その後、この大規模なワイドテーブル上で、高並列の単一テーブル集計操作を実行します。

OceanBase データベースは、Serving シナリオにおいて ClickHouse の代替として使用できます。
