# V$OB_PROCESSLIST

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>このビューはV4.0.0バージョンから導入されました。</p>
</main>

## 機能の概要

ビュー `V$OB_PROCESSLIST` は、本OBServerノードのセッション情報を表示するために使用されます。

## フィールドの説明

|      フィールド名      |         タイプ          | NULL値を許容するか |                              説明                              |
|----------------|---------------------|------------|--------------------------------------------------------------|
| SVR_IP         | varchar(46)         | NO         | サーバーIPアドレス                                                    |

| SQL_PORT       | bigint(20)          | NO         | SQLポート番号                                                      |

| MASTER_SESSID  | bigint(20) unsigned | NO         | 主session ID。同じSQLの複数のサブセッションをつなぐために使用されます                        |
| USER_CLIENT_IP | varchar(46)         | NO         | ユーザークライアントIPアドレス                                                     |
| USER_HOST      | varchar(128)        | NO         | ユーザークライアントのホスト名                                                     |

| RETRY_INFO     | bigint(20)          | NO         | 現在のコマンドのリトライ情報。通常は最後のリトライ時のエラーコードです                                      |
| SQL_ID         | varchar(32)         | NO         | SQL ID情報                                                    |
| TRANS_ID       | bigint(20) unsigned | NO         | トランザクションID                                                        |

| SSL_CIPHER     | varchar(4096)       | NO         | 暗号化パスワード名                                                       |

| TRANS_STATE    | varchar(32)         | NO         | トランザクションの状態（セッションにトランザクションがない場合は空になります）：<ul><li>`IDLE`：アイドル状態。トランザクションが開始されていないことを示します。</li> <li>`ACTIVE`：トランザクションが明示的に開始されました。`START TRANSACTION`、`BEGIN` などのステートメントで明示的に開始されます。</li> <li>`IMPLICIT_ACTIVE`：トランザクションが暗黙的に開始されました。`autocommit = on` モードでは、DML などのデータ変更ステートメントを実行するとトランザクションが開始されます。</li> <li>`ROLLBACK_SAVEPOINT`：トランザクションがセーブポイントへのロールバック中です。</li> <li>`IN_TERMINATE`：トランザクションが終了中です。内部的な理由による終了とユーザーが開始したトランザクションの終了（例えば、`COMMIT`、`ROLLBACK` ステートメントの実行）が含まれます。</li> <li>`ABORTED`：例外が発生してトランザクションが内部的に終了またはロールバックされました。</li> <li>`ROLLED_BACK`：トランザクションはすでにロールバックされています。</li> <li>`COMMIT_TIMEOUT`：トランザクションのコミットがタイムアウトしました。</li> <li>`COMMIT_UNKNOWN`：トランザクションのコミット結果が不明です。</li> <li>`COMMITTED`：トランザクションは正常にコミットされました。</li></ul>                                                          |

| CLIENT_INFO    | varchar(4096)       | NO         | DBMS_APPLICATION_INFO.SET_CLIENT_INFO プロシージャによって設定された情報              |
| LEVEL | bigint(20) | NO | このセッションのエンドツーエンド監視レベルを表します。例：1 は level 1 の診断情報を表します<main id="notice" type='explain'><h4>説明</h4><p>このフィールドはV4.2.1バージョンから導入されました。</p></main> |
| SAMPLE_PERCENTAGE | bigint(20) | NO | このセッションのエンドツーエンドトレースサンプリング頻度を表します。 例：50は診断情報のサンプリング確率が50％であることを表します<main id="notice" type='explain'><h4>説明</h4><p>このフィールドはV4.2.1バージョンから導入されました。</p></main> |
| RECORD_POLICY | varchar(32) | NO | このセッションのエンドツーエンドトレース記録ポリシーを表します。主に以下の3種類のポリシーがサポートされています：<ul><li>ALL：サンプリングが有効なすべてのトレースのトレースポイント情報はログファイルに出力され、各span終了時に即座に出力されます。 </li><li>ONLY_SLOW_QUERY：サンプリングが有効なトレースのトレースポイント情報の中で、Slow Queryに該当するリクエストのトレースのみがログファイルに出力され、その他の情報は破棄されます。この出力ポリシーでは、トレースログの出力タイミングはリクエストがSlow Queryと判定された後にのみ行われます。Proxyにおいて、ルートspan（トランザクションレベルのspan）については、Slow Queryが発見された場合にのみルートspanが出力されます。 </li><li>SAMPLE_AND_SLOW_QUERY：サンプリングが有効なトレースのトレースポイント情報の中で、以下の条件を満たすトレースはすべてログファイルに出力されます：<ol><li>隠しパラメータ<code>_print_sample_ppm</code>を使用して0.01％の確率でサンプリングを行い、かつサンプリング結果が選択された場合にのみログに出力されます</li><li>ONLY_SLOW_QUERYモードでの出力条件を満たす</li></ol>このモードでは、span終了時にログが出力されるわけではありません。条件1を満たす場合は、クライアント側でこのトレースログが強制的に出力されることがマークされ、その情報は後続のリンクコンポーネントに転送されます。条件2を満たす場合は、出力タイミングはONLY_SLOW_QUERYと同じです。</li></ul><main id="notice" type='explain'><h4>説明</h4><p>このフィールドはV4.2.1バージョンから導入されました。</p></main> |
| LB_VID | bigint(20) | NO   | 公有クラウド環境においてロードバランシング経由で直接データベースに接続する場合、この列にはロードバランシングサービスのVPC IDが表示されます。それ以外の場合はNULLが表示されます<main id="notice" type='explain'><h4>説明</h4><p>このフィールドはV4.2.1バージョンから導入されました。</p></main> |

| OUT_BYTES | bigint(20) | NO | このセッションの流出トラフィックを表します。単位はbyteです<main id="notice" type='explain'><h4>説明</h4><p>このフィールドはV4.2.1バージョンから導入されました。</p></main> |
| USER_CLIENT_PORT  | bigint(20)          | NO   | クライアントのアドレス情報<main id="notice" type='explain'><h4>説明</h4><p>このフィールドはV4.2.3バージョンから導入されました。</p></main>|
| PROXY_USER        | varchar(128)        | NO   |<ul><li>プロキシユーザーによるログインの場合、プロキシユーザーの名前が返されます。</li><li>プロキシユーザー以外のユーザーによるログインの場合、空になります。</li></ul> <main id="notice" type='explain'><h4>説明</h4><p>このフィールドはV4.2.3バージョンから導入されました。</p></main> |
| SERVICE_NAME      | varchar(64)         | NO   | このセッションがどのサービス名によって作成されたか。値が`NULL`の場合は、このセッションがサービス名によって作成されていないことを示します。<main id="notice" type='explain'><h4>説明</h4><p>このフィールドはV4.2.4バージョンから導入されました。</p></main> |
| TOTAL_CPU_TIME    | bigint(21)          | NO   | 現在のコマンド実行におけるCPU使用時間（単位：秒）<main id="notice" type='explain'><h4>説明</h4><ul><li>V4.3.x系では、このフィールドはV4.3.1バージョンから導入されました。</li> <li>V4.2.1系では、このフィールドはV4.2.1 BP5バージョンから導入されました。V4.2.x系の他のバージョンでは、このフィールドはV4.2.5バージョンから導入されました。</li></ul></main>      |
| TOP_INFO          | varchar(262143)     | NO   | 実行中のSQLが存在する上位レベルのPLステートメント情報が表示されます<main id="notice" type='explain'><h4>説明</h4><ul><li>V4.3.x系では、このフィールドはV4.3.3バージョンから導入されました。</li> <li>V4.2.1系では、このフィールドはV4.2.1 BP9バージョンから導入されました。V4.2.x系の他のバージョンでは、このフィールドはV4.2.5バージョンから導入されました。</li></ul></main>     |
| MEMORY_USAGE      | bigint(20)          | NO   | 単一SQL文が現在使用しているメモリサイズ（単位：バイト）<main id="notice" type='explain'><h4>説明</h4><p>V4.2.5系では、このフィールドはV4.2.5 BP2バージョンから導入されました。</p></main>|
