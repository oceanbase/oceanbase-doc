# V$OB_LS_LOG_RESTORE_STATUS

<main id="notice" type='explain'>
<h4>説明</h4>
<p>このビューはV4.2.0バージョンから導入されました。</p>
</main>

## 機能の概要

テナント内のログストリームレベルのログ復元状態を表示します。

## フィールドの説明

| **フィールド** | **タイプ** | **NULL許容** | **説明** |
| --- | --- | --- | --- |
| TENANT_ID | bigint(20) | NO | テナントID |
| LS_ID | bigint(20) | NO | ログストリームID |
| SYNC_LSN | bigint(20) unsigned | NO | スタンバイデータベースの最大連続多数派のポイント/最大消費可能ポイント(LSN) |
| SYNC_SCN | bigint(20) unsigned | NO | スタンバイデータベースの最大連続多数派のポイント/最大消費可能ポイント(SCN) |
| SYNC_STATUS | varchar(128) | NO | ログストリームの復元状態 <ul><li>NORMAL：正常に同期中  </li><li>SOURCE HAS A GAP：ログソース側にGapがあります </li><li>STANDBY LOG NOT MATCH：復元ログとスタンバイデータベースが競合し、同じLSNでスタンバイデータベースとログソース側のログが一致しません  </li><li>CHECK USER OR PASSWORD：レプリケーションアカウントのユーザー名またはパスワードが間違っており、ログソース側にアクセスできません  </li><li>CHECK NETWORK：ログソース側が到達不能です。設定されたテナントのアクセスエントリIPまたはPORTが誤っている場合が含まれます  </li><li>FETCH LOG TIMEOUT：ログの取得がタイムアウトしました  </li><li>RESTORE SUSPEND：ログ復元が設定された最大同期ポイントに達しました  </li><li>STANDBY NEED UPGRADE：スタンバイデータベースのバージョンがプライマリデータベースより古く、スタンバイデータベースのバージョンを更新する必要があります  </li><li>CHECK PRIMARY ALIVE：プライマリデータベースにアクセスできません。プライマリデータベースが削除されていないか確認してください  </li><li> NOT AVAILABLE：その他の異常によりログ同期が利用できません </li></ul>|
| ERR_CODE | bigint(20) | NO | エラーコード。正常な同期中はこのエラーコードは0です |
| COMMENT | varchar(2048) | NO | エラーの詳細情報。正常な同期中はこの列は空です |

## クエリ例

ユーザーテナントが自身のテナントにおけるログストリームレベルのログの復元状態を照会します。

```shell
obclient [oceanbase]> SELECT * FROM oceanbase.V$OB_LS_LOG_RESTORE_STATUS;
```

クエリ結果は次のとおりです：

```shell

|      1016 |     1 | 283804256 | 1736328456982102000 | NORMAL      |        0 |         |
|      1016 |  1001 | 196814299 | 1736328433807314000 | NORMAL      |        0 |         |
+-----------+-------+-----------+---------------------+-------------+----------+---------+
2 rows in set
```
