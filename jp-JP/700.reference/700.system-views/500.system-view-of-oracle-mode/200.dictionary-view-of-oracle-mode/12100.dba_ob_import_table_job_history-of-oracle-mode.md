# DBA_OB_IMPORT_TABLE_JOB_HISTORY

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>このビューは、V4.2.1バージョンから導入されました。</p>
</main>

## 機能の概要

このテナントのインポートタスクの履歴を表示します。

## フィールドの説明

| **フィールド** | **タイプ** | **NULL許容** | **説明** |
| --- | --- | --- | --- |
| JOB_ID | NUMBER(38) | NO | ジョブID |
| INITIATOR_TENANT_ID | NUMBER(38) | NO | 親ジョブのテナントID |
| INITIATOR_JOB_ID | NUMBER(38) | NO | 親ジョブが属するJOB ID |
| START_TIMESTAMP | VARCHAR2(256) | NO | ジョブ開始時のテナント現在時間 |
| FINISH_TIMESTAMP | VARCHAR2(256) | NO | ジョブ完了時のテナント現在時間 |
| SRC_TENANT_NAME | VARCHAR2(64) | NO | ソーステナント名 |
| SRC_TENANT_ID | NUMBER(38) | NO | ソーステナントID |
| STATUS | VARCHAR2(64) | NO | インポート終了ステータス：IMPORT_FINISH |
| IMPORT_ALL | NUMBER(38) | NO | テナント内のすべてのテーブルをインポートするかどうか。ユーザーが`RECOVER TABLE *.*`を指定した場合にのみこの値は1となり、他のシナリオでは値は0となる |
| DB_LIST | CLOB | YES | 完全に復元するデータベース |
| TABLE_LIST | CLOB | YES | 復元するテーブル |
| REMAP_DB_LIST | CLOB | YES | 重命名されたデータベース。書式は次のとおりです：`db1:new_db1, db2:newdb2` |
| REMAP_TABLE_LIST | CLOB | YES | 重命名されたテーブル。書式は次のとおりです：`db1.t1:new_t1, db1.t2:db2.new_t2` |
| REMAP_TABLEGROUP_LIST | CLOB | YES | 重マッピングされたテーブルグループのリスト。テーブルを元のテーブルグループからターゲットのテーブルグループに再マッピングできます。書式は次のとおりです：`tg1:new_tg1, tg2:new_tg2` |
| REMAP_TABLESPACE_LIST | CLOB | YES | 重マッピングされたテーブルスペースのリスト。テーブルを元のテーブルスペースからターゲットのテーブルスペースに再マッピングできます。書式は次のとおりです：`ts1:new_ts1, ts2:new_ts2` |
| TOTAL_TABLE_COUNT | NUMBER(38) | NO | テーブルインポートの総数 |
| FINISHED_TABLE_COUNT | NUMBER(38) | NO | インポートが完了したテーブル数 |
| FAILED_TABLE_COUNT | NUMBER(38) | NO | インポートに失敗したテーブル数 |
| RESULT | VARCHAR2(64) | YES | テーブルレベルの復元タスクの結果：<ul><li>SUCCESS  </li><li>FAIL </li></ul> |
| COMMENT | CLOB | YES | 備考情報 |
| DESCRIPTION | CLOB | YES | 復元コマンドで指定されたDESCRIPTION情報 |

## クエリ例

ユーザーテナントは、自身のテナントにおけるインポートタスクの結果を確認します。

```shell
obclient [SYS]> SELECT * FROM SYS.DBA_OB_IMPORT_TABLE_JOB_HISTORY\G
```
