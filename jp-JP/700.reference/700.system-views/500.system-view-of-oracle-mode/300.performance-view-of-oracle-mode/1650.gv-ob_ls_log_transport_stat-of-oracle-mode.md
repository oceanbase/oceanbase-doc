# GV$OB_LS_LOG_TRANSPORT_STAT

<main id="notice" type='explain'>
<h4>説明</h4>
<p>V4.4.2バージョンでは、このビューはV4.4.2 BP2バージョンから導入されました。</p>
</main>

## 機能の概要

ビュー`GV$OB_LS_LOG_TRANSPORT_STAT`は、強同期モードでのテナント内すべてのノード上の各LS（ログストリーム）がスタンバイデータベースにログをプッシュする転送状態を表示します。クエリを実行するには、プライマリテナント（プライマリデータベース）またはプライマリテナント（プライマリデータベース）が属するクラスタの`sys`テナントにログインする必要があります。

## フィールドの説明

|      フィールド名    |      型           | NULL許容 |    説明     |
|-----------------|---------------------|----------------|-------------|
| TENANT_ID       | NUMBER(38)          | NO   | テナントID     |
| LS_ID           | NUMBER(38)          | NO   | ログストリームID     |
| SVR_IP          | VARCHAR2(46)        | NO   | サーバーのIPアドレス    |
| SVR_PORT        | NUMBER(38)          | NO   | サーバーのポート番号     |
| ROLE            | VARCHAR2(32)        | NO   | ログストリームレプリカロール：<ul><li>`LEADER`：リーダーレプリカ</li> <li>`FOLLOWER`：フォロワーレプリカ</li></ul>     |
| ENABLED         | NUMBER(38)          | NO   | ログ転送サービス（Transport Service）が有効かどうか   |
| END_LSN         | NUMBER(38)          | NO   | プライマリテナント（プライマリデータベース）PalfがコミットしたLSN    |
| END_SCN         | NUMBER(38)          | NO   | プライマリテナント（プライマリデータベース）PalfがコミットしたSCN     |
| LAST_SENT_LSN   | NUMBER(38)          | NO   | スタンバイテナント（スタンバイデータベース）に最後に送信されたLSN     |
| LAST_SENT_SCN   | NUMBER(38)          | NO   | スタンバイテナント（スタンバイデータベース）に最後に送信されたSCN      |
| STANDBY_END_LSN | NUMBER(38)          | NO   | スタンバイテナント（スタンバイデータベース）で確認済みの書き込みLSN     |
| STANDBY_END_SCN | NUMBER(38)          | NO   | スタンバイテナント（スタンバイデータベース）で確認済みの書き込みSCN     |
| STANDBY_ADDR    | VARCHAR2(52)        | NO   | スタンバイテナント（スタンバイデータベース）の現在のログストリームリーダーのアドレス。`0.0.0.0:0`の場合は無効です    |

## クエリ例

プライマリテナント内で、自身のテナントに属するすべてのノード上の各LSがスタンバイテナントにログをプッシュする転送状態を照会します。

1. プライマリテナントLSの同期モードを確認します。

   ```shell
   obclient(root@oracle001)[SYS]> SELECT SVR_IP, SVR_PORT, LS_ID, ROLE, SYNC_MODE FROM SYS.GV$OB_LOG_STAT WHERE ROLE = 'LEADER';
   ```

   クエリ結果は次のとおりです：

   ```shell
   +-------------+----------+-------+--------+-----------+
   | SVR_IP      | SVR_PORT | LS_ID | ROLE   | SYNC_MODE |
   +-------------+----------+-------+--------+-----------+
   | 6.xx.xxx.91 |     2882 |     1 | LEADER | SYNC      |
   | 6.xx.xxx.91 |     2882 |  1001 | LEADER | SYNC      |
   +-------------+----------+-------+--------+-----------+
   2 rows in set
   ```

   結果が`SYNC`と表示されている場合、現在のテナントのログストリーム同期モードが強力同期モードであることを意味します。

2. そのプライマリテナントのすべてのノード上で、各ログストリームがスタンバイテナントにログをプッシュする伝送状態を照会します。

   ```shell
   obclient(root@oracle001)[SYS]> SELECT SVR_IP, SVR_PORT, LS_ID, ROLE, ENABLED,
       END_LSN, LAST_SENT_LSN, STANDBY_END_LSN, STANDBY_ADDR
       FROM SYS.GV$OB_LS_LOG_TRANSPORT_STAT WHERE ROLE = 'LEADER';
   ```

   クエリ結果は次のとおりです：

   ```shell
   +-------------+----------+-------+--------+---------+-----------+---------------+-----------------+-------------------+
   | SVR_IP      | SVR_PORT | LS_ID | ROLE   | ENABLED | END_LSN   | LAST_SENT_LSN | STANDBY_END_LSN | STANDBY_ADDR      |
   +-------------+----------+-------+--------+---------+-----------+---------------+-----------------+-------------------+
   | 6.xx.xxx.91 |     2882 |     1 | LEADER |       1 | 305150963 |     305150963 |       305150963 | 6.xx.xxx.160:2882 |
   | 6.xx.xxx.91 |     2882 |  1001 | LEADER |       1 | 201294294 |     201294294 |       201294294 | 6.xx.xxx.160:2882 |
   +-------------+----------+-------+--------+---------+-----------+---------------+-----------------+-------------------+
   2 rows in set
   ```
