# GV$OB_SQL_WORKAREA_MEMORY_INFO

<main id="notice" type='explain'>
<h4>説明</h4>
<p>このビューは、V2.2.77バージョンから導入されました。</p>
</main>

## 機能の概要

すべてのOBServerノード上のSQLワークエリアに関する全体的な情報を表示します。これには、最大利用可能メモリ、現在使用中のメモリ、現在保持されているメモリなどが含まれます。このビューを通じて、現在のテナント内でのワークエリアの使用状況、例えばメモリ利用率などを把握することができます。

## フィールドの説明

|        **フィールド名**        |   **タイプ**   | **NULLを許容するか** |                                                                **説明**                                                                |
|------------------------|------------|----------------|----------|
| MAX_WORKAREA_SIZE      | NUMBER(38) | NO             | ワークエリアの最大メモリサイズ。パラメータによって使用可能なメモリ量が決定され、単位はバイトです                      |
| WORKAREA_HOLD_SIZE     | NUMBER(38) | NO             | ワークエリアの現在のホールドメモリサイズ。単位はバイトです。<main id="notice" type='explain'><h4>説明</h4><p>>具体的な使用量はメモリ管理モジュールから取得できないため、ホールド値のみを取得できます。</p></main>   |
| MAX_AUTO_WORKAREA_SIZE | NUMBER(38) | NO             | autoモード時の予想される最大利用可能メモリサイズ。単位はバイトです。最大利用可能メモリは、`max_work_area_size - hold + total_mem_used`という式で計算されると考えることができます。これは、現在のワークエリア状況において、auto管理による最大メモリサイズを示します |
| MEM_TARGET             | NUMBER(38) | NO             | 現在のワークエリアで利用可能なメモリの目標サイズ。単位はバイトです。max_auto_work_areaとの違いは、この値がmax_auto_work_areaの一定割合である点です                                                          |
| TOTAL_MEM_USED         | NUMBER(38) | NO             | 現在のautoメモリの使用サイズ。単位はバイトです。ここでは、SQL自動メモリ管理モジュールによって統計されたサイズであり、実際の使用サイズではありません   |
| GLOBAL_MEM_BOUND       | NUMBER(38) | NO             | autoモードにおけるグローバル最大利用可能メモリサイズ。単位はバイト                               |
| DRIFT_SIZE             | NUMBER(38) | NO             | 現在の必要メモリ変化サイズ。単位はバイトです。主に変動値の統計に使用され、変動が一定範囲に達すると、グローバルバウンドサイズの再計算が自動的にトリガーされます|
| WORKAREA_COUNT         | NUMBER(38) | NO             | 登録されている演算子プロファイルの数                           |
| MANUAL_CALC_COUNT      | NUMBER(38) | NO             | 定期的ではないタイミングでグローバルバウンドサイズを計算した回数                     |
| SVR_IP                 | VARCHAR2(46)   | NO             | サーバーIPアドレス   |
| SVR_PORT               | NUMBER   | NO             | サーバーのポート番号   |

## クエリ例

ユーザーテナント内で、そのテナントのすべてのOBServerノード上のSQLワークエリア情報を照会します。

```shell
obclient [SYS]> SELECT * FROM SYS.GV$OB_SQL_WORKAREA_MEMORY_INFO;
```
