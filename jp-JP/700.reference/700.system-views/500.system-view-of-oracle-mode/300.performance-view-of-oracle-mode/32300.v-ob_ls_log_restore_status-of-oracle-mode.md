# V$OB_LS_LOG_RESTORE_STATUS

<main id="notice" type='explain'>
<h4>説明</h4>
<p>このビューは、V4.2.0バージョンから導入されました。</p>
</main>

## 機能の概要

このテナントのログストリームレベルのログ復元状態を表示します。

## フィールドの説明

| **フィールド** | **タイプ** | **NULL許容** | **説明** |
| --- | --- | --- | --- |
| TENANT_ID | NUMBER(38) | NO | テナントID |
| LS_ID | NUMBER(38) | NO | ログストリームID |
| SYNC_LSN | NUMBER(38) | NO | スタンバイデータベースの最大連続多数派のビット/最大消費可能ビット（LSN） |
| SYNC_SCN | NUMBER(38) | NO | スタンバイデータベースの最大連続多数派のビット/最大消費可能ビット（SCN） |
| SYNC_STATUS | VARCHAR2(128) | NO | ログストリームの復旧状態 <ul><li>NORMAL：通常同期中  </li><li>SOURCE HAS A GAP：ログソース側にGapが存在する </li><li>STANDBY LOG NOT MATCH：復旧ログとスタンバイデータベースが競合し、同一LSNのスタンバイデータベースとログソース側のログが異なる  </li><li>CHECK USER OR PASSWORD：レプリケーションアカウントのユーザー名またはパスワードが間違っており、ログソース側にアクセスできない  </li><li>CHECK NETWORK：ログソース側へのアクセスができない。これには、設定されたテナントのアクセスエントリIPまたはPORTが誤っている場合が含まれます  </li><li>FETCH LOG TIMEOUT：ログ取得タイムアウト  </li><li>RESTORE SUSPEND：ログ復旧が設定された最大同期ビットに達した  </li><li>STANDBY NEED UPGRADE：スタンバイデータベースのバージョンがプライマリデータベースよりも古く、スタンバイデータベースのバージョンを更新する必要があります  </li><li>CHECK PRIMARY ALIVE：プライマリデータベースにアクセスできないため、プライマリデータベースが削除されていないか確認します  </li><li>NOT AVAILABLE：その他の例外によりログ同期が利用できない </li></ul>|
| ERR_CODE | NUMBER(38) | NO | エラーコード。通常同期中はこのエラーコードは0です |
| COMMENT | VARCHAR2(2048) | NO | エラーの詳細情報。通常同期中はこの列は空です |

## クエリ例

ユーザーテナントが自身のログストリームレベルのログの復元状態を照会します。

```shell
obclient [SYS]> SELECT * FROM SYS.V$OB_LS_LOG_RESTORE_STATUS;
```

クエリ結果は次のとおりです：

```shell

|      1018 |  1001 | 196814299 | 1736328433807314000 | NORMAL      |        0 |         |
+-----------+-------+-----------+---------------------+-------------+----------+---------+
2 rows in set
```
