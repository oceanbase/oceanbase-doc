# GV$OB_FLT_TRACE_CONFIG

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>このビューはV4.2.1バージョンから導入されました。</p>
</main>

## 機能の概要

エンドツーエンド・トレースの診断情報を表示します。

## フィールド説明

| **項目** | **型** | **NULL許容** | **説明** |
| --- | --- | --- | --- |
| TENANT_ID | NUMBER(38) | NO | テナントID </li><li>その他の値：ユーザーテナントまたはMetaテナントID </li></ul> |
| TYPE | VARCHAR2(16) | NO | 診断情報のモニタリングレベル  </li><li>module/actionレベル：モジュールと操作レベルで診断情報をモニタリングします </li><li>client_identifierレベル：クライアント識別子レベルで診断情報をモニタリングします </li></ul> |
| TENANT_NAME | VARCHAR2(128) | NO | テナント名 |
| MODULE_NAME | VARCHAR2(4096) | NO | Module名 |
| ACTION_NAME | VARCHAR2(4096) | NO | Action名 |
| CLIENT_IDENTIFIER | VARCHAR2(65) | NO | Client Identifier名 |
| LEVEL | NUMBER(38) | NO | このセッションのエンドツーエンドトレースのモニタリングレベルを表します。例えば、1はレベル1の診断情報を意味します |
| SAMPLE_PERCENTAGE | NUMBER(38) | NO | このセッションのエンドツーエンドトレースのサンプリング頻度を表します。例えば、50は診断情報を50%の確率でサンプリングすることを意味します |
| RECORD_POLICY | VARCHAR2(32) | NO | このセッションのエンドツーエンドトレースの記録ポリシーを表します。主に以下の3種類のポリシーをサポートしています：<ul><li>ALL：すべてのヒットサンプリングでトレースを開始したトレースのスポット情報をログファイルに出力し、各span終了時にログファイルに出力します。 </li><li>ONLY_SLOW_QUERY：すべてのヒットサンプリングでトレースを開始したトレースのスポット情報のうち、Slow Queryのリクエストトレースのみをログファイルに出力し、その他は破棄します。この出力ポリシーでは、Traceログの出力タイミングは、リクエストが終了してSlow Queryと判定された後です。Proxyでは、ルートspan、つまりトランザクションレベルのspanは、Slow Queryが検出された場合にのみルートspanを出力します。 </li><li>SAMPLE_AND_SLOW_QUERY：すべてのヒットサンプリングでトレースを開始したトレースのスポット情報のうち、以下の条件を満たすTraceをログファイルに出力します：<ol><li>隠れパラメータ<code>_print_sample_ppm</code>を使用して万分の一の確率でサンプリングし、サンプリング結果が選択された場合にのみログに出力します</li><li>ONLY_SLOW_QUERYモードの出力条件を満たす</li></ol>このモードでは、ログの出力タイミングもspan終了時ではありません。条件1を満たす場合は、クライアント側でそのTraceログが強制的に出力されるとマークされ、その情報は後続のリンクコンポーネントに渡されます。条件2を満たす場合は、出力タイミングはONLY_SLOW_QUERYと同じです。</li></ul> |

## クエリ例

フルリンクトレースの診断情報を確認し、上位10件のレコードを表示します。

```shell
obclient [SYS]> SELECT * FROM SYS.GV$OB_FLT_TRACE_CONFIG  WHERE ROWNUM < 10;
```
