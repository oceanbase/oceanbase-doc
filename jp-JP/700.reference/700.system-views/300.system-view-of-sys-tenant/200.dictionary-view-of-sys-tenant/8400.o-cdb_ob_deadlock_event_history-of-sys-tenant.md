# oceanbase.CDB_OB_deadLOCK_EVENT_HISTORY

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>このビューはV4.0.0バージョンから導入されました。</p>
</main>

## 機能の概要

ビュー `CDB_OB_DEADLOCK_EVENT_HISTORY` は、デッドロックイベントの履歴を表示します。このビューはrootテナント配下で全テナントの履歴を表示します。

## フィールドの説明

| フィールド名 | 型 | NULL許容 | 説明 |
| ------- | ------ | ------ | ------ |
| TENANT_ID      | bigint(20)          | NO   | テナントID     |
| EVENT_ID       | bigint(20) unsigned | NO   | デッドロックイベントの番号     |
| SVR_IP         | varchar(46)         | NO   | デッドロックイベントに関与したノードのIPアドレス     |
| SVR_PORT       | bigint(20) unsigned | NO   | デッドロックイベントに関与したノードのポート番号     |
| DETECTOR_ID    | bigint(20) unsigned | NO   | デッドロックイベントに関与したノードID識別子（プロセス内一意）     |
| REPORT_TIME    | timestamp(6)        | NO   | デッドロックイベントの報告時間（報告サーバーのタイムスタンプ基準）     |
| CYCLE_IDX      | bigint(20)          | NO   | そのノードのループ内での番号     |
| CYCLE_SIZE     | bigint(20)          | NO   | デッドロックイベントに関与したノード数     |
| ROLE           | longtext            | NO   | そのノードがデッドロックイベント内で果たす役割：<ul><li>witness</li><li>victim </li></ul> |
| PRIORITY_LEVEL | longtext            | NO   | そのノードの優先度の階層的な記述：<ul><li>extreme-low</li><li>low</li><li>normal</li><li>high</li><li>extreme-high </li></ul> |
| PRIORITY       | bigint(20) unsigned | NO   | そのノードの持つ優先度値。優先度が同じ場合にのみ優先度値が比較可能となり、ループ内で優先度値が最も低いノードが除外される     |
| CREATE_TIME    | timestamp(6)        | NO   | そのノードの作成時間     |
| START_DELAY_US | bigint(20) unsigned | NO   | そのノードが作成後、デッドロック検出を開始できるまでの待機時間。単位はマイクロ秒     |
| MODULE         | longtext            | NO   | そのノードが存在するモジュール。値は固定で transaction となる     |
| VISITOR        | longtext            | NO   | そのノードが表すリソースアクセス者。形式は `{session_id:$1}:{txid:$2}`。`$1` と `$2` はどちらも数字     |
| OBJECT         | longtext            | NO   | そのノードが取得しようとするリソース。行の主キー内容の説明。形式は `{addr:“$1:$2”}:{ls:$3}:{tablet:$4}:{row_key:{$5}}`。ここで<ul><li><code>\$1</code> はIPアドレス。 </li><li><code>\$2</code> はPORT。 <code>\$1</code> と共に競合が発生したマシンのプロセスアドレスを構成する。 </li><li><code>\$3</code> は競合が発生した際のログストリーム。 </li><li><code>\$4</code> は競合が発生した際のTablet。 </li><li><code>\$5</code> は行ロックの主キーを文字列化した内容。 </li></ul>     |
| EXTRA_NAME1    | longtext            | YES  | 上位層がデッドロック報告イベントに追加したい追加情報名1。形式は `wait_sql`     |
| EXTRA_VALUE1   | longtext            | YES  | トランザクションがデッドロックを発生させている現在実行中のSQL内容     |
| EXTRA_NAME2    | longtext            | YES  | 上位層がデッドロック報告イベントに追加したい追加情報名2。形式は `hold_sql_request_time`     |
| EXTRA_VALUE2   | longtext            | YES  | ロック保持ステートメントのリクエスト時間     |
| EXTRA_NAME3    | longtext            | YES  | 上位層がデッドロック報告イベントに追加したい追加情報名3。形式は `hold_sql`     |
| EXTRA_VALUE3   | longtext            | YES  | `cycle_idx - 1` 行のレコードに対応するObjectを保持するSQLステートメント     |

## クエリ例

全テナントのデッドロックイベント履歴を照会します。

```shell
obclient [oceanbase]> SELECT * FROM oceanbase.CDB_OB_DEADLOCK_EVENT_HISTORY LIMIT 10;
```
