# V$OB_LS_LOG_RESTORE_STATUS

<main id="notice" type='explain'>
<h4>説明</h4>
<p>このビューはV4.2.0バージョンから導入されました。</p>
</main>

## 機能の概要

すべてのユーザーテナントのログの復元状態をログストリーム単位で表示します。

## フィールドの説明

| **フィールド名** | **型** | **NULL許容** | **説明** |
| --- | --- | --- | --- |
| TENANT_ID | bigint(20) | NO | テナントID |
| LS_ID | bigint(20) | NO | ログストリームID |
| SYNC_LSN | bigint(20) unsigned | NO | スタンバイデータベースの過半数のレプリカに連続して記録された最終位置（ログを読み取れる上限）(LSN) |
| SYNC_SCN | bigint(20) unsigned | NO | スタンバイデータベースの過半数のレプリカに連続して記録された最終位置（ログを読み取れる上限）(SCN) |
| SYNC_STATUS | varchar(128) | NO | ログストリームの復元状態 <ul><li>NORMAL：正常に同期中  </li><li>SOURCE HAS A GAP：ログソース側にギャップがあります </li><li>STANDBY LOG NOT MATCH：復元するログとスタンバイデータベースが競合しています。同じLSNでスタンバイデータベースとログソース側のログが異なります  </li><li>CHECK USER OR PASSWORD：レプリケーションアカウントのユーザー名またはパスワードが間違っており、ログソースにアクセスできません  </li><li>CHECK NETWORK：ログの取得元に接続できません。テナントの接続先IPアドレスまたはポート番号の設定に誤りがある場合も該当します  </li><li>FETCH LOG TIMEOUT：ログの取得がタイムアウトしました  </li><li>RESTORE SUSPEND：ログ復元が設定された最大同期ポイントに達しました  </li><li>STANDBY NEED UPGRADE：スタンバイデータベースのバージョンがプライマリデータベースより古く、スタンバイデータベースのバージョンを更新する必要があります  </li><li>CHECK PRIMARY ALIVE：プライマリデータベースにアクセスできません。プライマリデータベースが削除されていないか確認してください  </li><li> NOT AVAILABLE：その他の異常によりログ同期が利用できません </li></ul>|
| ERR_CODE | bigint(20) | NO | エラーコード。正常な同期中はこのエラーコードは0です |
| COMMENT | varchar(2048) | NO | エラーの詳細情報。正常な同期中はこの列は空です |

## クエリ例

システムテナントで、すべてのユーザーテナントのログの復元状態をログストリーム単位で照会します。

```shell
obclient [oceanbase]> SELECT * FROM oceanbase.V$OB_LS_LOG_RESTORE_STATUS;
```

クエリ結果は次のとおりです：

```shell

|      1016 |  1001 | 196679703 | 1736328313704108000 | NORMAL      |        0 |         |
+-----------+-------+-----------+---------------------+-------------+----------+---------+
2 rows in set
```
