# Catalogの概要

さまざまな外部データソースに格納されたデータのクエリを容易にするため、OceanBaseデータベースはOracleモードでCatalog（データカタログ）機能を導入しました。新しいデータ階層を追加することで、外部データソースの統合管理を実現します。

## Catalogの種類

Catalogは以下の2種類に分類されます：

* Internal Catalog（内部データカタログ）

  OceanBaseデータベース内部に保存されるデータを管理するために使用されます。各テナントには`internal`という名前の内部データカタログが1つだけ存在します。Internal Catalogは作成、削除、変更できません。

* External Catalog（外部データカタログ）

  外部データソースに接続し、外部データのメタ情報を取得するために使用されます。External Catalogを通じて外部データを直接クエリでき、データのインポートや移行は不要です。

## Catalogの利点

* マルチレベルデータ管理アーキテクチャ

  既存のDatabase-Table階層にCatalog階層を追加し、Catalog-Database-Tableの3層構造を形成することで、外部データソースのディレクトリツリーへの直接アクセスをサポートします。

* 自動マッピングとオンデマンドクエリ

  `CREATE EXTERNAL CATALOG` を使用して外部データソースへの接続を宣言するだけで、外部テーブルへのクエリをそのまま透過的に実行できます。マッピングテーブルを手動で作成する必要はありません。

* 統一されたクエリエクスペリエンス

  外部データソースをクエリする際、構文はローカルテーブルと一致し、データソース間の結合による分析をサポートします。

## Catalogの特長

* 複数のデータソースをサポート

  ODPS（MaxCompute）、HMS（Hive、Iceberg）、JDBC（SQL Server）などの外部データソースをサポートします。JDBC（SQL Server）はV4.4.2 BP4バージョンからサポートされています。

* 権限の分離

  Catalog階層を通じて外部データソースへのアクセス権限を制御します。一般ユーザーはCatalogを作成するために`CREATE CATALOG`システム権限を付与される必要があり、対応するCatalogにアクセスするためにはそのCatalogの`USE CATALOG`オブジェクト権限が必要となります。これによりデータの安全性が確保されます。詳細については、以下の[権限説明](#権限説明)を参照してください。

* パフォーマンス最適化

  カタログベースのクエリ計画最適化により、中間データ転送を削減し、クロスソースクエリの効率を向上させます。

## 適用シナリオ

* データソースを組み合わせた分析

  OceanBaseデータベースのデータと外部データソースを組み合わせて分析するシナリオ。

* データレイク/データウェアハウス連携

  統一されたデータレイクアーキテクチャを構築し、ODPS、Hiveなどの外部システムに保存された大量のデータを直接クエリします。

* ETLパイプラインの最適化

  データ移行のステップを削減し、カタログを介してソースシステムのデータに直接アクセスすることで、ETL開発の複雑さを低減します。

## 権限説明

Oracleモードにおけるカタログの権限モデルは以下のとおりです：

* `CREATE CATALOG`はシステム権限であり、この権限を持つユーザーはカタログを作成および削除できます。付与方法：`GRANT CREATE CATALOG TO user_name [WITH ADMIN OPTION];`、権限の付与状況は`SYS.DBA_SYS_PRIVS`ビューで確認できます。
* `USE CATALOG`はカタログレベルのオブジェクト権限であり、この権限を持つユーザーは対象カタログに切り替えてその中のオブジェクトにアクセスできます。付与方法：`GRANT USE CATALOG ON CATALOG catalog_name TO user_name;`、権限の付与状況は`SYS.DBA_TAB_PRIVS` / `SYS.USER_TAB_PRIVS`ビューで確認できます。
* ユーザーがカタログの作成に成功すると、自動的にそのカタログの`USE CATALOG`オブジェクト権限を取得します。
* 対象カタログに`USE CATALOG`権限がない場合、`SHOW CATALOGS`の結果にそのカタログは表示されません。

## 使用制限

現在のバージョンでは、カタログ内のデータは読み取り専用（read-only）であり、変更をサポートしていません。カタログ下のオブジェクトに対するすべての変更ステートメント（例：`DROP TABLE`、`INSERT INTO`など）の実行は禁止されます。
