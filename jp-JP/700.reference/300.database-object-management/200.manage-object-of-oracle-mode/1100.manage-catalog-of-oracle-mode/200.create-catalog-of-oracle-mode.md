# Catalogの作成

本記事では、SQLステートメントを使用してExternal Catalogを作成する方法について説明します。

## 権限要件

External Catalogを作成するには、現在のユーザーが`CREATE CATALOG`システム権限を持っている必要があります。

```text
GRANT CREATE CATALOG TO user_name;
```

OceanBaseデータベースの権限の詳細については、[Oracleモードの権限分類](../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/300.permission-of-oracle-mode/000.permission-classification-of-oracle-mode.md)を参照してください。

## 構文

External Catalogを作成するSQLステートメントの形式は次のとおりです：

```sql
CREATE EXTERNAL CATALOG external_catalog_name
    PROPERTIES [=] (properties_type_list);

properties_type_list:
    odps_type_list
    | hms_type_list
    | jdbc_type_list

odps_type_list:
    TYPE = 'ODPS',
    [ACCESSTYPE = 'accesstype_string',]
    ACCESSID = 'string',
    ACCESSKEY = 'string',
    STSTOKEN = 'string',
    ENDPOINT = 'string',
    TUNNEL_ENDPOINT = 'string',
    PROJECT_NAME = 'string',
    [QUOTA_NAME = 'string',]
    REGION = 'string'

hms_type_list:
    TYPE = 'HMS',
    URI = 'string'
    [, KRB5CONF = 'string']
    [, KEYTAB = 'string']
    [, PRINCIPAL = 'string']
    [, MAX_CLIENT_POOL_SIZE = 20]
    [, SOCKET_TIMEOUT = 10000000]

jdbc_type_list:
    TYPE = 'JDBC',
    URL = 'string'
```

**パラメータ説明：**

* `external_catalog_name`：作成する外部データカタログの名前。大文字小文字を区別せず、二重引用符で囲まれていない場合はすべて大文字に変換して保存されます。
* `PROPERTIES [=] (properties_type_list)`：外部データカタログタイプの関連属性オプションを指定するために使用されます。
* `odps_type_list`：ODPSタイプの外部データカタログ（ODPS Catalog）の関連属性リストを表します。
* `hms_type_list`：HMSタイプの外部データカタログ（HMS Catalog）の関連属性リストを表します。
* `jdbc_type_list`：JDBCタイプの外部データカタログ（JDBC Catalog）の関連属性リストを表します。

External Catalog作成構文の詳細なパラメータ説明については、[CREATE EXTERNAL CATALOG](../../../500.sql-reference/100.sql-syntax/300.common-tenant-of-oracle-mode/900.sql-statement-of-oracle-mode/100.ddl-of-oracle-mode/4700.create-external-catalog-of-oracle-mode.md)を参照してください。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>MySQLモードとは異なり、Oracleモードの<code>CREATE EXTERNAL CATALOG</code>ステートメントは<code>IF NOT EXISTS</code>句をサポートしていません。</p>
</main>

## 例

### ODPSタイプのExternal Catalogを作成する

外部テーブルからMaxComputeデータを読み書きする際、値は`ODPS`となります。

`CREATE EXTERNAL CATALOG`を使用してMaxCompute（ODPS）への接続を作成し、マッピングテーブルを手動で作成することなくODPSテーブルデータを直接クエリできます。Catalog下のオブジェクトは読み取り専用です。

**例：**

```sql
obclient> CREATE EXTERNAL CATALOG tmp_odps_catalog PROPERTIES = (TYPE = 'ODPS', ACCESSID = '$odps_accessid', ACCESSKEY = '$odps_accesskey', ENDPOINT = '$odps_endpoint', TUNNEL_ENDPOINT = 'http://xxx.maxcompute.aliyun.com', PROJECT_NAME = 'odps_test_project');

obclient> DROP CATALOG tmp_odps_catalog;
```

### HMSタイプのExternal Catalogを作成する

OceanBaseデータベースは、HMS Catalog機能により、Hiveメタデータ（Metastore）の統一管理を実現します。HMS Catalogを利用することで、OceanBaseはHiveテーブルに対応するHDFSストレージパス上のデータに直接アクセスでき、効率的なデータレイクのクエリと分析をサポートします。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>HMS Catalogを作成する前に、HMSがアクセスする予定の基盤ストレージのファイルデータがHDFS上にある場合は、Java SDK環境のデプロイが完了している必要があります。JAVA SDK環境の設定に関する詳細は、<a href="../../../../400.deploy/300.deploy-oceanbase-enterprise-edition/500.deploy-the-ob-java-sdk-environment.md">OceanBaseデータベースJAVA SDK環境のデプロイ</a>を参照してください。</p>
</main>

**例：**

```sql
obclient> CREATE EXTERNAL CATALOG tmp_hms_catalog PROPERTIES = (TYPE = 'HMS', URI = 'thrift://xx.xx.xx.xx:9083');

obclient> DROP CATALOG tmp_hms_catalog;
```

HMS Catalogがサポートするテーブル形式などの情報については、MySQLモードの[Catalogの作成](../../100.manage-object-of-mysql-mode/1000.manage-catalog-of-mysql-mode/200.create-catalog-of-mysql-mode.md)の**HMSタイプのExternal Catalogを作成する**セクションを参照してください。

### JDBCタイプのExternal Catalogを作成する

V4.4.2 BP4バージョンから、OracleモードはJDBCタイプのExternal Catalogをサポートしています。現在はSQL Serverデータソースへの接続のみをサポートしています。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>JDBC Catalogを作成する前に、Java SDK環境のデプロイが完了している必要があり、devdeps-java-extensions RPMパッケージは1.0.6以降のバージョンである必要があります。JAVA SDK環境の設定に関する詳細は、<a href="../../../../400.deploy/300.deploy-oceanbase-enterprise-edition/500.deploy-the-ob-java-sdk-environment.md">OceanBaseデータベースJAVA SDK環境のデプロイ</a>を参照してください。</p>
</main>

**例：**

```sql
obclient> CREATE EXTERNAL CATALOG test_jdbc_catalog PROPERTIES = (TYPE = 'JDBC', URL = 'jdbc:sqlserver://10.10.10.1:1433');

obclient> DROP CATALOG test_jdbc_catalog;
```

作成成功後、Catalog名 + Schema名 + テーブル名の3部構成の名前でSQL Server内のテーブルにアクセスできます。例：`test_jdbc_catalog.dbo.table_name`。また、まず`SET CATALOG`を使用して対象Catalogに切り替え、次に`Schema名.テーブル名`の2部構成の名前でアクセスすることもできます。例：`dbo.table_name`。

外部テーブルの列型は、devdeps-java-extensionsが提供する列メタデータ(`targetType`)によって決定され、Oracleモードのデータ型にマッピングされます。SQL Serverデータソースの主要な型のマッピングは以下のとおりです：

| **SQL Server型** | **Oracleモードの型** |
|---------------------|-------------------------|
| BIT | NUMBER(1) |
| TINYINT | NUMBER(3) |
| SMALLINT | NUMBER(5) |
| INT | NUMBER(10) |
| BIGINT | NUMBER(19) |
| DECIMAL / NUMERIC | NUMBER(p,s) |
| SMALLMONEY | NUMBER(10,4) |
| MONEY | NUMBER(19,4) |
| REAL / FLOAT(24) | BINARY_FLOAT |
| FLOAT(53) / DOUBLE | BINARY_DOUBLE |
| CHAR(n) | VARCHAR2(n CHAR) |
| VARCHAR(n) | VARCHAR2(n CHAR) |
| NCHAR(n) | NVARCHAR2(n) |
| NVARCHAR(n) | NVARCHAR2(n) |
| BINARY(n) | RAW(n) |
| VARBINARY(n) | RAW(n) |
| DATE | DATE |
| TIME | INTERVAL DAY (1) TO SECOND (n) |
| SMALLDATETIME | TIMESTAMP(0) |
| DATETIME | TIMESTAMP(3) |
| DATETIME2 | TIMESTAMP(7) |
| サポートされていない型 | UNSUPPORTED |

<main id="notice" type='notice'>
  <h4>注意</h4>
  <ul>
  <li>JDBCカタログのオブジェクトは読み取り専用であり、<code>INSERT</code>、<code>UPDATE</code>、<code>DELETE</code>、<code>ALTER TABLE</code>、<code>DROP TABLE</code> などの変更ステートメントの実行はサポートされていません。</li>
  <li>外部テーブルに <code>UNSUPPORTED</code> と表示されるデータ型の列が存在する場合、その列はクエリできません。他の列のクエリには影響しません。</li>
  </ul>
</main>
