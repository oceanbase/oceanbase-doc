# パーティションのTRUNCATE

ビジネスニーズに応じて、パーティションテーブル内の対象パーティションのデータを削除し、パーティション構造を保持することができます。

## パーティションテーブルにおけるパーティションのTRUNCATE操作のサポート状況

OceanBaseデータベースのOracleモードでは：

* 1階層のパーティションテーブルについては、現在RangeパーティションとListパーティションに対してのみパーティションのTRUNCATE操作をサポートしており、Hashパーティションに対するサポートはありません。

* コンポジット・パーティションテーブルについては、現在Range/Listタイプ（組み合わせ）のパーティションに対してのみパーティションのTRUNCATE操作をサポートしています。

OceanBaseデータベースのOracleモードにおける、1階層のパーティションテーブルとコンポジット・パーティションテーブルのパーティションのTRUNCATE操作に対するサポート状況は、次の表のとおりです。

| パーティションテーブル |      パーティションタイプ                           | 第1レベルのパーティションのTRUNCATE | サブパーティションのTRUNCATE |
|-------|------------------------------------------|------------------|------------------|
| 1階層のパーティションテーブル | Range / List                         | サポート             | -                |
| 1階層のパーティションテーブル | Hash                                 | サポートなし           | -                |
| コンポジット・パーティションテーブル | Range + Range / Range + List         | サポート             | サポート            |
| コンポジット・パーティションテーブル | Range + Hash                         | サポート             | サポートなし          |
| コンポジット・パーティションテーブル | List + Range / List + List           | サポート             | サポート            |
| コンポジット・パーティションテーブル | List + Hash                          | サポート             | サポートなし          |
| コンポジット・パーティションテーブル | Hash + Range / Hash + List           | サポートなし           | サポート            |
| コンポジット・パーティションテーブル | Hash + Hash                          | サポートなし           | サポートなし          |

## パーティションのTRUNCATE操作の説明

パーティションのTRUNCATEを実行する際は、Truncate対象のパーティションにアクティブなトランザクションやクエリが存在しないようにしてください。存在する場合、SQL文がエラーになったり、異常が発生したりする可能性があります。`sys`テナントで、`oceanbase.GV$OB_TRANSACTION_PARTICIPANTS`ビューを参照することで、現在終了していないトランザクションのコンテキスト状態を確認できます。

### パーティションのTRUNCATEがグローバルインデックスに与える影響

Oracleモードでは、グローバルインデックスを持つ1階層のパーティションテーブルまたはコンポジット・パーティションテーブルに対してパーティションのTRUNCATEを実行する際、`ALTER TABLE`ステートメントに`UPDATE GLOBAL INDEXES`キーワードを追加してグローバルインデックス情報を更新する必要があります。`UPDATE GLOBAL INDEXES`キーワードを追加しない場合、パーティションのTRUNCATE後、そのパーティションテーブル上のグローバルインデックスは使用不可状態になります。

Range、Interval、またはListパーティション（第1レベルのパーティションおよびサブパーティションを含む）を使用し、`TRUNCATE`パーティション操作をサポートするテーブルについて、`UPDATE GLOBAL INDEXES`を指定した場合、システムはグローバルインデックスを再構築せず、バックグラウンドでのメジャーコンパクションによるデータ削除を通じて、遅延（lazy）メンテナンス戦略でインデックスの有効性を維持します。これにより、インデックスの無効化によるクエリの中断やパフォーマンスの低下を回避できます。ただし、この最適化は通常のグローバルインデックスにのみ適用されます。以下のシナリオでは、この最適化はトリガーされません：

* 第1レベルのパーティションがHashパーティションである場合（サブパーティションがRangeまたはListであっても）、サブパーティションに対してTruncate操作を実行する場合。
* パーティションキーが通常の列ではなく式である場合。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>V4.4.2バージョンでは、V4.4.2 BP1バージョンから <code>INTERVAL</code> パーティションテーブルが <code>UPDATE GLOBAL INDEXES</code> 構文をサポートしています。</p>
</main>

#### パーティション DDL時のグローバルインデックス動作を制御する隠し構成パラメータ

V4.3.5では、OceanBaseデータベースはV4.3.5 BP2から、テナントレベルの隠し構成パラメータ `_ob_enable_truncate_partition_preserve_global_index` を導入しました。このパラメータは、メインテーブルのパーティションに `TRUNCATE`/`DROP`（以下、パーティションDDL）を実行する際に、グローバルインデックスを有効な状態に保つかどうかを制御します。アップグレードされたテナントの場合、この隠し構成パラメータのデフォルト値は `False` です。新規テナントの場合、デフォルト値は `True` です。設定値による動作の比較は以下の通りです：

| 構成パラメータ値 | パーティションDDL実行中の動作 | パーティションDDL実行後の結果 |
|----------|-----------------------|-------------------------|
| True | `TRUNCATE`/`DROP` の対象となるメインテーブルのパーティションのみDMLを許可せず、メインテーブルの他のパーティションは通常通りDML可能。| グローバルインデックスは無効にならない：メインテーブルとすべてのインデックステーブルでDML操作を実行でき、メインテーブルに関連するグローバルインデックスは無効にならない。|
| False | `TRUNCATE`/`DROP` の対象となるメインテーブルのパーティションのみDMLを許可せず、メインテーブルの他のパーティションは通常通りDML可能。| グローバルインデックスは無効になる：メインテーブルとすべてのインデックステーブルでDML操作を実行できるが、メインテーブルに関連するグローバルインデックスは無効になるか、再構築される。|

**例：**

* インデックスは維持されます。

    ```shell
    obclient> ALTER SYSTEM SET "_ob_enable_truncate_partition_preserve_global_index" = True;
    ```

* インデックスは無効になります。

    ```shell
    obclient> ALTER SYSTEM SET "_ob_enable_truncate_partition_preserve_global_index" = False;
    ```

### パーティションのTRUNCATEが並行DDL/DML/クエリに与える影響

パーティションのTRUNCATEはOffline DDL操作に属します。パーティションのTRUNCATEを実行する際、OceanBaseデータベースは対象パーティションにパーティションレベルの排他的ロックを設定します。

| 操作タイプ | パーティションのTRUNCATE実行中の影響 |
|----------|------------------------------|
| 並行DDL | 禁止またはブロックされます。同一テーブルに対する他の任意のDDL操作は同時に実行できません。|
| 並行DML | <ul><li>対象パーティション：完全にブロックされます。</li><li>他のパーティション：通常は並行可能です。ただし、ステートメントが明示的に他のパーティションにアクセスする必要があります。</li></ul>|
| 並行クエリ(`SELECT`) | 影響を受けず、正常に実行できます。|

## 第1レベルのパーティションのTRUNCATE

ビジネスニーズに応じて、1階層のパーティションテーブルまたはコンポジット・パーティションテーブルの第1レベルのパーティションをTruncateできます。

### 構文

```sql
ALTER TABLE table_name TRUNCATE PARTITION partition_name_list [UPDATE GLOBAL INDEXES];

partition_name_list:
  partition_name [, partition_name ...]
```

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <ul>
    <li>
    <p>第1レベルのパーティションをTruncateする際、1つまたは複数のパーティションのデータを削除できます。</p>
    </li>
    <li>
    <p>コンポジット・パーティションテーブルの第1レベルのパーティションをTruncateすると、そのパーティションおよび対応するサブパーティションのデータがすべて削除されます。</p>
    </li>
    </ul>
  </main>

### 例

* 1階層のパーティションテーブル `tbl1_r` の `M202001` および `M202002` パーティションのデータを削除し、グローバルインデックス情報を更新します。

  ```sql
  obclient> CREATE TABLE tbl1_r(log_id INT,log_date DATE NOT NULL DEFAULT SYSDATE)
         PARTITION BY RANGE(log_date)
          (PARTITION M202001 VALUES LESS THAN(TO_DATE('2020/02/01','YYYY/MM/DD'))
           , PARTITION M202002 VALUES LESS THAN(TO_DATE('2020/03/01','YYYY/MM/DD'))
           , PARTITION M202003 VALUES LESS THAN(TO_DATE('2020/04/01','YYYY/MM/DD'))
           , PARTITION M202004 VALUES LESS THAN(TO_DATE('2020/05/01','YYYY/MM/DD'))
           , PARTITION M202005 VALUES LESS THAN(TO_DATE('2020/06/01','YYYY/MM/DD'))
           , PARTITION M202006 VALUES LESS THAN(TO_DATE('2020/07/01','YYYY/MM/DD'))
           , PARTITION M202007 VALUES LESS THAN(TO_DATE('2020/08/01','YYYY/MM/DD'))
           , PARTITION M202008 VALUES LESS THAN(TO_DATE('2020/09/01','YYYY/MM/DD'))
           , PARTITION M202009 VALUES LESS THAN(TO_DATE('2020/10/01','YYYY/MM/DD'))
           , PARTITION M202010 VALUES LESS THAN(TO_DATE('2020/11/01','YYYY/MM/DD'))
           , PARTITION M202011 VALUES LESS THAN(TO_DATE('2020/12/01','YYYY/MM/DD'))
           , PARTITION M202012 VALUES LESS THAN(TO_DATE('2021/01/01','YYYY/MM/DD'))
           , PARTITION MMAX VALUES LESS THAN (MAXVALUE)
           );
  Query OK, 0 rows affected

  obclient> ALTER TABLE tbl1_r TRUNCATE PARTITION M202001,M202002 UPDATE GLOBAL INDEXES;
  Query OK, 0 rows affected
  ```

*
  RANGE+LISTパーティションのコンポジット・パーティションテーブル `t2_f_rl` の第1レベルのパーティション `p0` および `p1` のデータをすべて削除します。

  ```sql
  obclient> ALTER TABLE t2_f_rl TRUNCATE PARTITION p0,p1;
  ```

## サブパーティションのTRUNCATE

ビジネスニーズに応じて、コンポジット・パーティションテーブル内のサブパーティションをTRUNCATEできます。

### 構文

```sql
ALTER TABLE table_name TRUNCATE SUBPARTITION subpartition_name_list[ UPDATE GLOBAL INDEXES ];

subpartition_name_list:
  subpartition_name[, subpartition_name ...]
```

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>サブパーティションをTRUNCATEする場合、1つまたは複数のサブパーティションのデータをすべて削除できます。</p>
  </main>

### 例

パーティションテーブル `t2_f_lr` の第1レベルのパーティション `p1` 内のサブパーティション `sp3` および `sp4` のデータをすべて削除し、グローバルインデックス情報を更新します。

```sql
obclient> CREATE TABLE t2_f_rl(col1 INT,col2 VARCHAR2(50))
       PARTITION BY RANGE(col1)
       SUBPARTITION BY LIST(col2)
       (PARTITION p0 VALUES LESS THAN(100)
         (SUBPARTITION sp0 VALUES('01'),
          SUBPARTITION sp1 VALUES('02')
          ),
        PARTITION p1 VALUES LESS THAN(200)
         (SUBPARTITION sp2 VALUES('01'),
          SUBPARTITION sp3 VALUES('02'),
          SUBPARTITION sp4 VALUES('03')
         )
        );
Query OK, 0 rows affected

obclient> ALTER TABLE t2_f_rl TRUNCATE SUBPARTITION sp3,sp4 UPDATE GLOBAL INDEXES;
Query OK, 0 rows affected
```
