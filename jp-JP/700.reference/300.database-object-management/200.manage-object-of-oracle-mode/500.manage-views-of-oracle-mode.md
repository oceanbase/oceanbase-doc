# ビューの管理

この記事では、ビューの作成、変更、削除について説明します。

ビューはテーブルのクエリ結果を表示するために使用されます。テーブルが使用できる場合のほとんどすべての場合、ビューも使用できます。頻繁にアクセスするデータが複数のテーブルに分散している場合、ビューを使用するのが最適な方法です。

## 通常のビューを作成する

`CREATE VIEW` ステートメントを使用して通常のビューを作成できます。作成後は、そのビューに対してDMLステートメントを実行できます。

Oracleモードでは、ビューを作成するためのSQL構文は以下のとおりです：

```sql
CREATE [OR REPLACE] [[NO] FORCE] VIEW view_name [(column_name_list)]
    AS select_stmt
    [view_check_option];

column_name_list:
    column_name [, column_name ...]

view_check_option:
    WITH READ ONLY
    | WITH CHECK OPTION
```

その中で：

* `OR REPLACE`：作成しようとしているビュー名が既に存在する場合、新しい定義でビューを再作成することを示します。

* `[NO] FORCE`：ビューを作成する際に、そのビューに基表または参照されるオブジェクトタイプが存在するかどうか、またビューが属するスキーマの所有者が権限を持っているかどうかを考慮したくない場合は、`FORCE` を指定する必要があります。

  基表が存在し、ビューが属するスキーマの所有者が権限を持っていることを確認した場合は、`NO FORCE` を指定できます。デフォルトは `NO FORCE` です。

* `column_name_list`：基表と同様に、ビューも一意の列名を持たなければならず、重複してはなりません。デフォルトでは、`SELECT` ステートメントで取得される列名がビューの列名として使用されます。

  ビューの列に明確な名前を定義したい場合は、オプションの `column_name_list` 句を使用でき、IDの間はカンマで区切ります。`column_name_list` の名前の数は、`SELECT` ステートメントで取得される列数と等しくなければなりません。

  `SELECT` ステートメントで取得される列は、テーブル列への単純な参照である場合もあります。関数、定数値、演算子などを使用した式である場合もあります。

* `select_stmt`：ビューを定義する `SELECT` ステートメントであり、このステートメント内の情報は基表または他のビューから選択できます。

* `WITH READ ONLY`：ビューを作成または置き換える際のオプションであり、ビューを読み取り専用として指定し、DML操作（`INSERT`、`UPDATE`、`DELETE`）には使用できないようにします。つまり、ビューを介した挿入、更新、削除操作を禁止します。

* `WITH CHECK OPTION`：ビューを作成するための構文であり、挿入または更新されるデータがビューの定義条件を満たすことを保証するために使用されます。つまり、ビューを介したDML操作を許可しますが、操作後のデータはビューの定義条件を満たしている必要があります。

    <main id="notice" type='explain'>
      <h4>説明</h4>
      <p>Oracleモードの <code>WITH CHECK OPTION</code> 構文は、<code>LOCAL</code> または <code>CASCADED</code> として指定することをサポートしておらず、デフォルトは <code>CASCADED</code> です。</p>
    </main>

    V4.2.5バージョンでは、V4.2.5 BP7バージョン以降、ビューのフィルタ条件（`where_clause`）にサブクエリを含む場合に `WITH CHECK OPTION` 句を指定することがサポートされています。

    <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>フィルタ条件で <code>WITH CHECK OPTION</code> 句を使用する場合、ビュー定義では <code>JOIN</code> 操作の使用は現在サポートされていません。</p>
    </main>

**例：**

テーブル `tbl1` 内の `col1` および `col2` 列を選択して、ビュー `view1` を作成します。

```shell
obclient> CREATE OR REPLACE FORCE VIEW view1(vcol1, vcol2)
    AS SELECT col1, col2
       FROM tbl1;
```

## 通常のビューの変更

`CREATE OR REPLACE VIEW` ステートメントを使用して、通常のビューを変更できます。

**例：**

ビュー `stock_item` を変更します。

```shell
obclient> CREATE OR REPLACE VIEW stock_item
    AS SELECT /*+ leading(s) use_merge(i) */
           i_price,
           i_name,
           i_data,
           s_i_id,
           s_w_id,
           s_order_cnt,
           s_ytd,
           s_remote_cnt,
           s_quantity,
           s_data,
           s_dist_01,
           s_dist_02,
           s_dist_03,
           s_dist_04,
           s_dist_05,
           s_dist_06,
           s_dist_07,
           s_dist_08,
           s_dist_09,
           s_dist_10
       FROM stok s, item i
       WHERE s.s_i_id = i.i_id;
```

## ビューの削除

`DROP VIEW` ステートメントを使用して、1つまたは複数のビューを削除できます。ビューを削除しても、ビューが参照するテーブルは削除されません。

現在のビューが他のビューによって参照されている場合、依存するビューを削除すると、そのビューに依存する他のビューのクエリが失敗します。

ビューを削除する際は、現在のユーザーがそのビューに対する `DROP` 権限を持っていることを確認する必要があります。

Oracleモードでは、ビューを削除するSQL構文は次のとおりです：

```sql
DROP VIEW view_name;
```

**例：**

ビュー `v1` を削除します。

```shell
obclient> DROP VIEW v1;
```
