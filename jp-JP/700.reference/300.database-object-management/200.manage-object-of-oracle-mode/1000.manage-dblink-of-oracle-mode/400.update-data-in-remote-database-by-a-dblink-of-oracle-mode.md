# DBLinkを使用してリモートデータベースのデータを変更する

DBLinkを作成した後、DBLinkを使用してリモートデータベースのデータを変更できます。現在、DBLinkを使用してOceanBaseデータベースのOracleモードおよびOracleデータベースにデータを書き込むことがサポートされています。

## 制限事項

* DBLinkの書き込み機能を使用する場合、リモートデータベースがOceanBaseデータベースである場合は、リモートOceanBaseデータベースのバージョンがV4.1.0以降である必要があります。リモートデータベースがOracleデータベースの場合は、Oracle 11g以降のバージョンを使用することを推奨します。

* DBLinkのデータ書き込み機能には、リバースリンクという特性があります。この特性は主に、リモートデータベースからローカルデータベースのオブジェクト（テーブル、ビュー、シノニムなど）にアクセスするために使用されます。DBLinkのデータ書き込み機能でリバースリンク特性を使用する必要がある場合は、DBLinkを作成する際にローカルデータベースの`ip`、`port`、`user_name`、`tenant_name`、`pass_word`などの情報を提供する必要があります。具体的な操作方法および詳細な説明については、[DBLinkの作成](../1000.manage-dblink-of-oracle-mode/100.create-a-dblink-of-oracle-mode.md)を参照してください。

* 現在、リバースリンク特性はOceanBaseデータベースのOracleモード間のアクセスのみをサポートしており、OceanBaseデータベースのOracleモードからOracleデータベースへのアクセスはまだサポートされていません。

## 前提条件

* DBLinkが作成済みであること。DBLinkの作成手順については、[DBLinkの作成](100.create-a-dblink-of-oracle-mode.md)を参照してください。

* OceanBase V4.2.1以降のバージョンでは、DBLink機能を使用してリモートのOracleデータベースにアクセスする場合、クラスタ内のすべてのOBServerノードにOCI-12.2をインストールし、設定する必要があります。また、OceanBase V4.2.1より前のバージョンからV4.2.1以降のバージョンにアップグレードする場合も、既に設定されているOCI-11.2をOCI-12.2に再設定する必要があります。

  OCI-12.2のインストールおよび設定の詳細な手順については、[OCIのインストールと設定](600.install-and-configure-the-oci.md)を参照してください。

## 注意事項

* DBLinkを使用してリモートデータベースにデータを書き込む際、OceanBaseデータベースはローカルおよびリモートのXAトランザクションを自動的に開始します。ユーザーが手動で開始する必要はありません。

  XAトランザクションの詳細については、[XAトランザクション](../../../100.oceanbase-database-concepts/800.transaction-management/100.transaction/900.xa-transactions.md)を参照してください。

* SQLにおいてDBLinkを使用してリモートデータベースにデータを書き込む場合、ローカルおよびリモートのXAトランザクションをコミットするために、明示的に`COMMIT`ステートメントを使用する必要があります。現時点では、`autocommit = True`を設定してトランザクションの自動コミットを有効にすることはサポートされていません。SQLにおいてDBLinkを使用してデータを書き込む際、XAトランザクションが開始されると、システムはこのセッションの`autocommit`値を強制的に`False`に設定し、XAトランザクションがコミットまたはロールバックされるまで元の値に戻りません。

* アノニマブロックにおいてDBLinkを使用してリモートデータベースにデータを書き込む場合、トランザクションのコミット方法は通常のトランザクションと同様です。`autocommit = True`を設定してトランザクションの自動コミットを有効にすることができます。`autocommit = False`に設定した場合、`COMMIT`ステートメントを使用して明示的にコミットする必要があります。

  システム変数`autocommit`は、トランザクションの自動コミットを有効にするかどうかを設定するために使用されます。デフォルト値は`True`です。その他のシステム変数`autocommit`の説明については、[autocommit](../../../800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/600.autocommit-global.md)を参照してください。

* XAトランザクションが長時間を要すると予想される場合、XAトランザクションのタイムアウトによる予期しないエラーを防ぐために、`set ob_trx_timeout = 1000000000;`ステートメントを使用して、トランザクションのタイムアウト時間を事前に延長できます。

  システム変数`ob_trx_timeout`は、トランザクションのタイムアウト時間を設定するために使用されます。デフォルト値は`86400000000`で、単位はマイクロ秒です。その他のシステム変数`ob_trx_timeout`に関する情報については、[ob_trx_timeout](../../../800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/10300.ob_trx_timeout-global.md)を参照してください。

## リモートデータベースのデータを変更する

DBLinkを使用してリモートデータベースのデータを変更する操作には、データの挿入、更新、置換、削除などが含まれ、主に`INSERT`、`UPDATE`、`MERGE INTO`、`DELETE`の4種類のDMLステートメントで実現されます。

### データの挿入

DBLinkを使用してテーブルにデータを挿入する基本構文は以下のとおりです：

```sql
obclient> INSERT INTO table_name@dblink_name (list_of_columns) VALUES (list_of_values);
```

関連パラメータの説明は以下のとおりです：

* `table_name@dblink_name`：`table_name` は変更対象のリモートデータベースのテーブル名を表します。`dblink_name` はDBLink名を表します。

* `list_of_columns`：テーブルに挿入するデータの列を指定します。

* `list_of_values`：`list_of_columns` で指定された列に対応する値で、一対一で対応していなければなりません。

DBLinkを使用してリモートデータベースのテーブル `t1` に行データ `(11,11)` を挿入する例は以下のとおりです：

```sql
obclient> SELECT * FROM t1@ob_dblink;
+------+------+
| C1   | C2   |
+------+------+
|    1 |    1 |
+------+------+
1 row in set

obclient> INSERT INTO t1@ob_dblink VALUES (11,11);
Query OK, 1 row affected

obclient> SELECT * FROM t1@ob_dblink;
+------+------+
| C1   | C2   |
+------+------+
|    1 |    1 |
|   11 |   11 |
+------+------+
2 rows in set
```

DBLinkを使用してリモートデータベースのテーブルにデータを挿入する操作は、直接テーブルにデータを挿入する操作と似ています。ステートメント内で操作対象のテーブル名の後に `@dblink_name` の接尾辞を追加するだけです。テーブルへのデータ挿入の詳細な操作については、[データの挿入](../../../../300.develop/200.application-development-of-oracle-mode/400.write-data-of-oracle-mode/100.insert-data-of-oracle-mode-in-develop.md)を参照してください。

その他の `INSERT` ステートメントの詳細な使用方法と説明については、[INSERT](../../../500.sql-reference/100.sql-syntax/300.common-tenant-of-oracle-mode/900.sql-statement-of-oracle-mode/200.dml-of-oracle-mode/200.insert-of-oracle-mode.md)を参照してください。

### データの更新

DBLinkを使用してテーブルデータを更新する基本構文は以下のとおりです：

```sql
obclient> UPDATE table_name@dblink_name
SET column_name = value [, column_name = value]...
[WHERE condition];
```

関連パラメータの説明は以下のとおりです：

* `table_name@dblink_name`：`table_name` は変更対象のリモートデータベースのテーブル名を表します。`dblink_name` はDBLink名を表します。

* `column_name = value [, column_name = value]`：更新する列を指定します。等号（=）の後ろの `value` が更新後の目標値です。

* `WHERE condition`：条件句は、更新される行が満たす必要がある条件を指定します。条件句がない場合、更新対象のテーブルの該当列のすべてのレコードが更新されます。

DBLinkを使用して、リモートデータベースのテーブル `t2` 内の `C1` 列の値を `3` に変更する例は以下のとおりです：

```sql
obclient> SET ob_trx_timeout = 1000000000;
Query OK, 0 rows affected

obclient> SELECT * FROM t2@ob_dblink;
+------+------+
| C1   | C2   |
+------+------+
|    2 |    2 |
+------+------+
1 row in set

obclient> UPDATE t2@ob_dblink SET C1 = 3;
Query OK, 1 row affected

obclient> SELECT * FROM t2@ob_dblink;
+------+------+
| C1   | C2   |
+------+------+
|    3 |    2 |
+------+------+
1 rows in set
```

DBLinkを使用してリモートデータベースのテーブルデータを更新する操作は、直接テーブルデータを更新する操作と似ています。ステートメント内で操作対象のテーブル名の後に `@dblink_name` サフィックスを追加するだけです。テーブルデータの更新に関する詳細な操作については、[データの更新](../../../../300.develop/200.application-development-of-oracle-mode/400.write-data-of-oracle-mode/200.update-data-of-oracle-mode-in-develop.md)を参照してください。

その他の `UPDATE` ステートメントの詳細な使用方法と説明については、[UPDATE](../../../500.sql-reference/100.sql-syntax/300.common-tenant-of-oracle-mode/900.sql-statement-of-oracle-mode/200.dml-of-oracle-mode/600.update-of-oracle-mode.md)を参照してください。

### データの置換

DBLinkを使用してテーブルデータを置き換える基本構文は以下のとおりです：

```sql
obclient> MERGE INTO table_name@dblink_name alias1
USING (table|view|sub_query) alias2
ON (join condition)
WHEN MATCHED THEN
    UPDATE table_name
    SET col1 = col1_val,
        col2 = col2_val
WHEN NOT MATCHED THEN
    INSERT (column_list) VALUES (column_values);
```

関連パラメータの説明は以下のとおりです：

* `MERGE INTO table_name@dblink_name alias1`：変更対象のリモートデータベースのテーブル名とエイリアスを指定します。`dblink_name` はDBLink名を表します。

* `USING (table|view|sub_query) alias2`：ソーステーブル（ビュー、サブクエリ）とエイリアスを指定します。

* `ON (join condition)`：判断条件を指定します。

* `WHEN MATCHED THEN UPDATE table_name SET col1 = col_val1 , col2 = col2_val`：条件がマッチした場合、`UPDATE` ステートメントを実行します。

* `WHEN NOT MATCHED THEN INSERT (column_list) VALUES (column_values);`：条件がマッチしない場合、`INSERT` ステートメントを実行します。

`MERGE INTO` ステートメントを使用してデータを置き換える際、ソーステーブルのレコードがターゲットテーブルに存在しない場合は、ターゲットテーブルにデータを挿入します。ソーステーブルのレコードがターゲットテーブルに存在する場合は、レコードを更新します。

DBLinkを使用してリモートデータベースのテーブル `t3` のデータを置き換える例は以下のとおりです：

```sql
obclient> SELECT * FROM t3@orcl_dblink;
+------+------+
| C1   | C2   |
+------+------+
|    3 |    3 |
|    4 |    4 |
+------+------+
2 row in set

obclient> SELECT * FROM t4;
+------+------+
| C1   | C2   |
+------+------+
|    5 |    5 |
|    6 |    6 |
+------+------+
2 row in set

obclient> MERGE INTO t3@orcl_dblink a
 USING (SELECT C1,C2 FROM t4 ) b
 ON (a.C1 = b.C1)
 WHEN MATCHED THEN
     UPDATE SET a.C2 = b.C2
 WHEN NOT MATCHED THEN
     INSERT (a.C1,a.C2) VALUES(b.C1, b.C2);
Query OK, 2 rows affected

obclient> SELECT * FROM t3@orcl_dblink;
+------+------+
| C1   | C2   |
+------+------+
|    3 |    3 |
|    4 |    4 |
|    5 |    5 |
|    6 |    6 |
+------+------+
4 row in set
```

DBLinkを使用してリモートデータベースのテーブルデータを置き換える操作は、直接データを置き換える操作と似ています。ステートメント内で操作対象のテーブル名の後に `@dblink_name` サフィックスを追加するだけです。テーブルデータの置き換えの詳細な操作については、[データの置き換え](../../../../300.develop/200.application-development-of-oracle-mode/400.write-data-of-oracle-mode/400.replace-data-of-oracle-mode-in-develop.md) を参照してください。

`MERGE INTO` ステートメントの詳細な使用方法と説明については、[MERGE](../../../500.sql-reference/100.sql-syntax/300.common-tenant-of-oracle-mode/900.sql-statement-of-oracle-mode/200.dml-of-oracle-mode/300.merge-of-oracle-mode.md) を参照してください。

### データの削除

DBLinkを使用してテーブルデータを削除する基本構文は以下のとおりです：

```sql
obclient> DELETE FROM table_name@dblink_name [WHERE condition];
```

関連パラメータの説明は以下のとおりです：

* `table_name@dblink_name`：`table_name` は変更対象のリモートデータベースのテーブル名を表します。`dblink_name` はDBLink名を表します。

* `WHERE condition`：条件句は、削除するデータが満たす必要がある条件を指定します。条件句がない場合は、テーブル全体の削除が実行されます。

DBLinkを使用して、リモートデータベースのテーブル `t5` から `C2 = 7` のデータ行を削除する例は以下のとおりです：

```sql
obclient> SET ob_trx_timeout = 1000000000;
Query OK, 0 rows affected

obclient> SELECT * FROM t5@orcl_dblink;
+------+------+
| C1   | C2   |
+------+------+
|    7 |    7 |
|    8 |    8 |
+------+------+
2 row in set

obclient> DELETE FROM t5@orcl_dblink WHERE C2 = 7;
Query OK, 1 row affected

obclient> SELECT * FROM t5@orcl_dblink;
+------+------+
| C1   | C2   |
+------+------+
|    8 |    8 |
+------+------+
1 row in set
```

DBLinkを使用してリモートデータベースのテーブルデータを削除する操作は、直接テーブルデータを削除する操作と似ています。ステートメント内で操作対象のテーブル名の後に `@dblink_name` サフィックスを追加するだけです。テーブルデータの詳細な操作については、[データの削除](../../../../300.develop/200.application-development-of-oracle-mode/400.write-data-of-oracle-mode/300.delete-data-of-oracle-mode-in-develop.md) を参照してください。

その他の `DELETE` ステートメントの詳細な使用方法と説明については、[DELETE](../../../500.sql-reference/100.sql-syntax/300.common-tenant-of-oracle-mode/900.sql-statement-of-oracle-mode/200.dml-of-oracle-mode/100.delete-of-oracle-mode.md) を参照してください。

### DBLinkの書き込みはSAVEPOINT機能をサポートします

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>DBLinkの書き込みは <code>SAVEPOINT</code> 機能をサポートしており、トランザクションを指定されたセーブポイントまでロールバックすることができます。</p>
</main>

**例：**

リモートデータベースに空のテーブル `tbl1` があり、以下のSQLステートメントを使用して、DBLinkがトランザクションを指定されたセーブポイントまでロールバックすることを示します。

1. リモートテーブル `tbl1` に行1を挿入します。

    ```sql
    INSERT INTO tbl1@dblink_o2 VALUES(1);
    ```

2. `sp1` という名前のセーブポイントを作成します。

    ```sql
    SAVEPOINT sp1;
    ```

3. リモートテーブル `tbl1` に行2を挿入します。

    ```sql
    INSERT INTO tbl1@dblink_o2 VALUES(2);
    ```

4. `sp2` という名前のセーブポイントを作成します。

    ```sql
    SAVEPOINT sp2;
    ```

5. 変更を `sp1` までロールバックします。

    ```sql
    ROLLBACK TO sp1;
    ```

6. リモートテーブル `tbl1` に行3を挿入します。

    ```sql
    INSERT INTO tbl1@dblink_o2 VALUES(3);
    ```

7. トランザクションをコミットします。

    ```sql
    COMMIT;
    ```

8. テーブル `tbl1` のデータを照会します。

    ```sql
    obclient [SYS]> SELECT * FROM tbl1@dblink_o2;
    ```

    実行結果は次のとおりです：

    ```shell
    +------+
    | C1   |
    +------+
    |    1 |
    |    3 |
    +------+
    2 rows in set
    ```
