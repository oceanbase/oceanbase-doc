# 複合トリガーの作成

複合トリガーには、行前、行後、ステートメント前、ステートメント後の4種類のトリガーイベントのうち、1つから4つを含めることができます。または、INSTEAD OFトリガーイベントのみを含むこともできます。

## 概要

テーブルまたは編集可能なビューに作成された複合トリガーは、複数の時点で発生することができます。複合トリガーは実行タイミングごとにセクションに分かれており、各セクションには実行部と例外処理部（オプション）があります。これらすべての部分は共通のPL状態にアクセスできます。この共通状態はトリガーステートメントの開始時に確立され、トリガーステートメントの終了時に破棄されます。トリガーステートメントがエラーを引き起こした場合でも影響を受けません。

## 複合トリガーの制限事項

複合DMLトリガーには以下の制限があります：

* `OLD`、`NEW`、`PARENT` は宣言部に現れることはできません。また、`BEFORE STATEMENT` 部分や `AFTER STATEMENT` 部分にも現れることはできません。

* `NEW` の値を変更できるのは `BEFORE EACH ROW` 部分のみです。

* あるセクションでは、別のセクションで発生した例外を処理することはできません。

* セクション内に `GOTO` ステートメントが含まれる場合、その `GOTO` ステートメントのターゲットは同一のセクション内に存在している必要があります。

## トリガーの作成

複合トリガーの宣言部（オプション）では、実行タイミングごとに分かれたすべてのセグメントで使用できる変数とサブプログラムを宣言できます。トリガーが発生すると、宣言部は任意のセクションが実行される前に実行されます。これらの変数とサブプログラムは、トリガーを起動したステートメントの実行中に利用できます。

編集不可なビューに作成された複合トリガーは、実際の意味での複合トリガーではありません。なぜなら、それには1つのセクションしかないからです。編集不可なビューに単純な複合トリガーを作成する構文は以下のとおりです：

```sql
CREATE TRIGGER FOR dml_event_clause ON view_name
[{ FOLLOWS | PRECEDES } other_trigger_name]
COMPOUND TRIGGER
INSTEAD OF EACH ROW IS BEGIN
sql_statement;
END INSTEAD OF EACH ROW;
```

テーブルまたは編集可能なビューに作成された複合トリガーには、少なくとも1つのセクションがあります。トリガーに複数のセクションがある場合、それらは任意の順序で配置できますが、実行タイミングは重複してはなりません。セクションが存在しない場合、その実行タイミングでは何の操作も発生しません。

複合トリガーには主に以下のセクションがあります：

|実行タイミング                 |     セクション         |
|------------------------|--------------------|
|トリガーステートメント実行前        |   BEFORE STATEMENT|
|トリガーステートメント実行後          |   AFTER STATEMENT |
|トリガーステートメントの影響を受ける各行の前 |   BEFORE EACH ROW |
|トリガーステートメントの影響を受ける各行の後 |   AFTER EACH ROW  |

複合トリガーには初期化部はありませんが、`BEFORE STATEMENT` では必要な初期化を行うことができます。これは他のセクションよりも先に実行されるためです。

複合トリガーに `BEFORE STATEMENT` 部分も `AFTER STATEMENT` 部分もなく、かつそのトリガーステートメントがいずれの行にも影響を与えない場合、トリガーは決して発生しません。

複合トリガーを使用して、変更情報を子テーブルに記録します。例：

1. `employees` と `emp_salaries` の2つのテーブルが存在すると仮定します。

   ```sql
   obclient [SYS]> CREATE TABLE employees (
       employee_id NUMBER PRIMARY KEY,
       name VARCHAR2(50),
       salary NUMBER(8,2),
       department_id NUMBER);
   ```

   ```sql
   obclient [SYS]> CREATE TABLE emp_salaries (
      emp_id NUMBER NOT NULL,
      change_date DATE   NOT NULL,
      salary NUMBER(8,2) NOT NULL,
      FOREIGN KEY (emp_id)
      REFERENCES employees (employee_id) ON DELETE CASCADE);
   ```

   同時に、テーブル `employees` のデータは以下のとおりです。

   ```sql
   obclient [SYS]> SELECT * FROM employees;
   ```

2. トリガー `maintain_emp_salaries` を作成します。

   ```sql
    obclient [SYS]> delimiter /
   ```

    ```sql
    obclient [SYS]> CREATE OR REPLACE TRIGGER maintain_emp_salaries
    FOR UPDATE OF salary ON employees
      COMPOUND TRIGGER

    threshold CONSTANT SIMPLE_INTEGER := 7;

    TYPE salaries_t IS TABLE OF emp_salaries%ROWTYPE INDEX BY SIMPLE_INTEGER;
    sal  salaries_t;
    idx  SIMPLE_INTEGER := 0;

    PROCEDURE flush_proc IS
      n CONSTANT SIMPLE_INTEGER := sal.count();
    BEGIN
      FORALL j IN 1..n
        INSERT INTO emp_salaries VALUES sal(j);
      sal.delete();
      idx := 0;
      DBMS_OUTPUT.PUT_LINE(n || '行をフラッシュ');
    END flush_proc;

    -- AFTER EACH ROW セグメント:

    AFTER EACH ROW IS
    BEGIN
      idx := idx + 1;
      sal(idx).emp_id := :NEW.employee_id;
      sal(idx).change_date := SYSTIMESTAMP;
      sal(idx).salary := :NEW.salary;
      IF idx >= threshold THEN
        flush_proc();
      END IF;
    END AFTER EACH ROW;

    -- AFTER STATEMENT時間帯:

    AFTER STATEMENT IS
    BEGIN
      flush_proc();
    END AFTER STATEMENT;
    END maintain_emp_salaries;
    /
    ```

    ```sql
    obclient [SYS]> SET SERVEROUTPUT ON;
    ```

3. 部門 `50` の各従業員の給与を8%引き上げます。

    ```shell
    obclient [SYS]> UPDATE employees
            SET salary = salary * 1.08
            WHERE department_id = 50
            /
    Query OK, 10 rows affected
    Rows matched: 10  Changed: 10  Warnings: 0

    7行をフラッシュ
    Flushed 7 rows
    3行をフラッシュ
    Flushed 3 rows
    ```

    3秒待ってから、以下のコマンドを実行します：

    ```sql
    obclient [SYS]> BEGIN
      DBMS_LOCK.SLEEP(3);
      END
     /
    ```
