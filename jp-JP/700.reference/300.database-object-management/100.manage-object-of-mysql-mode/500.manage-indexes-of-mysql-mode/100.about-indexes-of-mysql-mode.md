# インデックスについて

テーブルの作成が完了すると、テーブルの1つまたは複数の列にインデックスを作成して、テーブル上のSQL文の実行速度を高速化できます。インデックスを正しく使用することで、物理I/Oや論理I/Oを削減できます。

OceanBaseデータベースのテーブルストレージモデルはインデックス集約型テーブルモデルです。ユーザーが主キーを指定しない場合、システムは隠れた主キーを自動生成します。

インデックスの長所、短所、および使用原則：

長所：

* データのクエリ速度を向上させます。

* インデックスを使用することで、クエリ処理中に最適化ハイダラーを利用し、システムのパフォーマンスを向上させることができます。

短所：

* インデックスの作成とメンテナンスには時間がかかり、データ量が増えるにつれて費やす時間も増加します。

* テーブル内のデータに追加、削除、変更がある場合、インデックスも動的にメンテナンスする必要があり、データの保守速度が低下します。

使用原則：

* 頻繁に更新されるテーブルには、過剰なインデックスを作成することを避け、クエリで頻繁に使用されるフィールドにはインデックスを作成するべきです。

* データ量が少ないテーブルでは、インデックスを使用しない方が望ましいです。データが少ないため、全データのクエリにかかる時間がインデックスのイテレーションにかかる時間よりも短くなる可能性があり、インデックスによる最適化効果が得られない場合があります。

* 変更性能が検索性能を大幅に上回る場合、インデックスを作成すべきではありません。
