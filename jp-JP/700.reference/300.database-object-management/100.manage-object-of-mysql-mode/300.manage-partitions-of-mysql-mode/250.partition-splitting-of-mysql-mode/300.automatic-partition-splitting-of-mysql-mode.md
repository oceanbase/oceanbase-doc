# 自動パーティションの分割

OceanBaseデータベースでは、事前に自動パーティション分割ルールを設定し、データ量が一定のレベルに達すると自動的にパーティションの分割処理を実行します。これにより、データの増加に応じてデータベーステーブルを自動的に拡張でき、単一パーティションのデータ量が過大になることによるロードバランシングやパフォーマンスの問題を回避できます。

## 自動パーティション分割操作のサポート状況

現在のバージョンでは、Range/Range Columnsパーティションのパーティションに主キーテーブルが存在する場合にのみ、自動パーティション機能をサポートしています。

## 使用上の制限と注意事項

* ListパーティションやHashパーティションテーブルの自動分割はサポートされていません。
* セカンダリパーティションテーブルの自動分割はサポートされていません。
* 自動分割されるテーブルのパーティションキーと主キープレフィックスが異なる場合はサポートされていません。
* 主キーのないテーブルの自動パーティション分割はサポートされていません。
* カラムストアテーブルの自動パーティション分割はサポートされていません。
* カラムストアレプリカの自動パーティション分割はサポートされていません。
* テーブルが属する`TABLEGROUP`（テーブルグループ）に複数のテーブルが含まれている場合、自動パーティション分割はサポートされていません。この`TABLEGROUP`にこのテーブルのみが含まれている場合は、自動パーティション分割をサポートします。
* マテリアライズドビューの自動パーティション分割はサポートされていません。
* フルテキストインデックスの自動分割はサポートされていません。
* 空間インデックスの自動分割はサポートされていません。
* ベクトルインデックスの自動分割はサポートされていません。
* OceanBaseデータベースは [global_index_auto_split_policy](../../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3350.global_index_auto_split_policy.md)構成パラメータをサポートしており、新規作成されるグローバルインデックスで自動パーティション機能を有効にするかどうかを制御します。新規作成されたグローバルインデックスで自動パーティションが有効になっている場合、データ量に応じてパーティションルールが再生成され、事前に分割されます。

## テーブル単位の自動パーティション設定

`CREATE TABLE`時に、`SIZE`句を設定することで、単一の自動パーティションテーブルを作成します。

### テーブル作成時の自動パーティション構文

```sql
CREATE TABLE table_name (column_definition_list, PRIMARY KEY(column_name_list))
    PARTITION BY RANGE [COLUMNS]([column_name_list]) [SIZE('size_value')]
    [(range_partition_list)];

column_definition_list:
    column_definition[, column_definition ...]

column_name_list:
    column_name[, column_name ...]

range_partition_list:
    PARTITION partition_name VALUES LESS THAN (value_list)[, PARTITION partition_name VALUES LESS THAN (value_list) ...]

value_list:
    value[, value ...]
```

#### パラメータの説明

|       **パラメータ**       | **説明** |
|----------------------|----------|
| table_name           | テーブル名を指定します。|
| column_definition_list | 列定義リストを指定します。これには、列名、データ型、制約などが含まれます。詳細については、[CREATE TABLE](../../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2600.create-table-of-mysql-mode.md)を参照してください。|
| PRIMARY KEY | テーブルの主キーを指定します。|
| PARTITION BY RANGE \[COLUMNS\]\(\[column_name_list\]\) | 事前パーティションキーを指定します。自動パーティションがトリガーされると、入力された事前パーティションキーが実際のパーティションキーとして使用されます(`column_name_list`が記述されていない場合は、主キーがパーティションキーとして使用されます)。<main id="notice" type='notice'><h4>注意</h4><p><ul><li>複数列のパーティションキーを指定する場合は、<code>PARTITION BY RANGE COLUMNS()</code>を使用する必要があります。</li><li>事前パーティションキーに対する操作制限は、パーティションキーと同じです。</li></ul></p></main>|
| SIZE('size_value') | オプションです。パーティションの分割しきい値を指定します。値の範囲は[1MB, +∞)です。`SIZE()`句が省略されている場合、テナントレベルの構成パラメータ`auto_split_tablet_size`の値がデフォルトで読み込まれます。`size_value`には`unlimited`を指定でき、これは分割しきい値が無制限であり、分割されず、今後新しい自動パーティション分割がスケジュールされないことを意味します。 <main id="notice" type='explain'><h4>説明</h4><p>V4.4.2バージョンでは、V4.4.2 BP1バージョン以降、自動パーティション分割のしきい値の下限が128MBから1MBに調整されました。</p></main> <main id="notice" type='notice'><h4>注意</h4><p>テーブルのデータ量が多いシナリオでは、<code>SIZE</code>を小さく設定しすぎることは推奨されません。大量のパーティションが生成され、後続のパーティション操作やシステムの安定性に影響を与える可能性があるためです。</p></main>|
| range_partition_list | オプションです。事前にパーティションポイント（パーティションルール）を作成します。<main id="notice" type='notice'><h4>注意</h4><p>事前にパーティションポイントを作成する場合は、事前パーティションキーを指定する必要があります。指定しない場合は、エラーが発生します。</p></main>|

### テーブルの自動パーティション属性を変更する構文

```sql
ALTER TABLE table_name
    PARTITION BY RANGE [COLUMNS]([column_name_list]) [SIZE('size_value')]
    [(range_partition_list)];

column_name_list:
    column_name[, column_name ...]

range_partition_list:
    PARTITION partition_name VALUES LESS THAN (value_list)[, PARTITION partition_name VALUES LESS THAN (value_list) ...]

value_list:
    value[, value ...]
```

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p><code>ALTER TABLE ... PARTITION BY ...</code>ステートメントを使用する際にパーティションルールが定義されていない場合、Online DDL方式でテーブルの自動パーティション属性が変更され、既存のパーティション定義には影響しません。</p>
</main>

#### パラメータの説明

|       **パラメータ**       | **説明** |
|----------------------|----------|
| column_name_list     | 非パーティションテーブルのプリパーティションキーを変更します。`ALTER TABLE` ステートメントを使用して非パーティションテーブルの自動パーティショニング属性を変更する際に、`RANGE()` 内にプリパーティションキー情報を指定すると、スキーマ内の対応するレコードが変更されます。情報を指定しない場合は、既存の設定が維持されます。<main id="notice" type='notice'><h4>注意</h4><p>複数列のパーティションキーに変更する場合は、<code>PARTITION BY RANGE COLUMNS()</code> を使用してください。</p></main>|
| SIZE('size_value')   | オプションです。テーブルの自動パーティショニングのしきい値を変更します。値の範囲は [1MB, +∞) です。`size_value` を `unlimited` に変更しても、既存のパーティションには影響せず、今後新しい自動パーティションの分割はスケジュールされません。 <main id="notice" type='explain'><h4>説明</h4><p>V4.4.2 バージョンでは、V4.4.2 BP1 以降、自動パーティション分割のしきい値の下限が 128MB から 1MB に調整されました。</p></main> <main id="notice" type='notice'><h4>注意</h4><p>テーブルデータ量が多いシナリオでは、<code>SIZE</code> を小さく設定しすぎることは推奨されません。大量のパーティションが生成され、後続のパーティション操作やシステムの安定性に影響を与える可能性があるためです。</p></main>|
| range_partition_list | オプションです。パーティションルールを変更します。`SIZE` 句を使用せずにパーティション定義を指定した場合、パーティションルールのみが変更され、既存の自動パーティション定義には影響しません。|

## テナントレベルの自動パーティショニング設定

テナントレベルのパラメータ `enable_auto_split` と `auto_split_tablet_size` を設定することで、要件を満たすテナント内のテーブルに対して、グローバル設定に基づいてテーブルの自動分割を制御します。`CREATE TABLE` 時に `SIZE` 構文を省略した場合、以下のテナントレベルのパラメータに基づいて自動パーティションテーブルを作成するかどうかが決定されます（デフォルトでは主キー列が自動パーティションテーブルのパーティションキーとして使用されます）。

* [enable_auto_split](../../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2350.enable_auto_split.md)：テナントレベルのパラメータで、テナントの自動パーティショニング機能を有効にするかどうかを制御します。
* [auto_split_tablet_size](../../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/450.auto_split_tablet_size.md)：テナントレベルのパラメータで、テナントの自動パーティショニング機能が有効な場合に、分割をトリガーするしきい値を制御します。

`SIZE` 構文を省略し、かつ `enable_auto_split` を `true` に設定した場合、分割制限に合致するテーブルにのみ自動パーティションが設定され、制限に合致しないテーブルには適用されません。例えば、サブパーティションテーブル、非Rangeパーティションテーブル、主キーのないテーブル、またはパーティションキーと主キーのプレフィックスが一致しないパーティションテーブルを作成すると、通常は非自動パーティションテーブルとして作成されます（ユーザーが手動で自動分割の特別な構文を記述した場合でもエラーが発生します）。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>ビュー <code>information_schema.TABLES</code> またはシステムテナントで <code>oceanbase.CDB_TABLES</code> を使用して、テーブルの自動パーティショニング属性を確認できます。</p>
</main>

## 自動パーティショニングの動作説明

### 自動パーティション DDL 操作

* パーティションルールの変更：パーティションを主キーのRangeによるパーティションに変更する場合のみサポートされます。その他のパーティションルールの変更はサポートされません。
* 主キーの変更：主キー変更後の自動パーティションキーが主キーのプレフィックスである必要があります。
* 列操作：プリパーティションキーの操作制限は、パーティションキーと同等です。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>その他のDDL操作は、非自動パーティションテーブルと同じ要件が適用されます。</p>
</main>

### DML 行動

分割中は、分割前後の2つのスキーマが共存する状態となり、ソースパーティションとターゲットパーティションのDML動作は、同一のデータに対する操作となります。例えば、ソースパーティションへの書き込みやクエリは、可能な限り対応するターゲットパーティションへのクエリや書き込みに変換されます。ターゲットパーティションへの書き込みやクエリは、ソースパーティションから転送された書き込みを認識します。具体的な動作は以下の通りです：

| N/A | ソースパーティションを指定した DML (INSERT INTO t1 PARTITION(p0) ...) | ソースパーティションに関わる DML (SELECT * FROM t1) | ターゲットパーティションを指定した DML | ターゲットパーティションに関わる DML |
|-----|---------------------------------------------------|------------------------------------|-------------------|-------------------|
| 分割開始トランザクション前 | 通常 | 通常 | エラー、存在しないパーティションに対する操作と同じ動作 | このケースなし |
| 分割中 | エラーが発生する可能性あり、エラー時の動作は存在しないパーティションに対する操作と同じ | エラーなし、内部で書き込みのストリーミング切り替えとクエリの文再試行を行う | 通常 | 通常 |
| 分割終了トランザクション後 | エラー、存在しないパーティションに対する操作と同じ動作 | このケースなし | 通常 | 通常 |

## 例

### 例1：テーブルレベルの自動パーティションテーブルを作成する

1. 自動パーティション機能を無効にします。

    ```sql
    AlTER SYSTEM SET enable_auto_split = FALSE;
    ```

    <main id="notice" type='explain'>
      <h4>説明</h4>
      <p><code>SHOW PARAMETERS LIKE 'enable_auto_split';</code> を使用して、自動パーティション機能が有効かどうかを確認できます。</p>
    </main>

2. 自動パーティションテーブル `test1_tbl1` を作成し、プリパーティションキーは指定せず、分割しきい値を10GBに設定します。

    ```sql
    CREATE TABLE test1_tbl1 (col1 INT, col2 INT, col3 VARCHAR(30), PRIMARY KEY(col1, col2))
        PARTITION BY RANGE() SIZE('10GB');
    ```

3. 自動パーティションテーブル `test1_tbl2` を作成し、プリパーティションキーを `col1` に、分割しきい値を10GBに設定します。

    ```sql
    CREATE TABLE test1_tbl2 (col1 INT, col2 INT, col3 VARCHAR(30), PRIMARY KEY(col1, col2))
        PARTITION BY RANGE(col1) SIZE('10GB');
    ```

4. 自動パーティションテーブル `test1_tbl3` を作成し、プリパーティションキーと分割しきい値を指定しません（分割しきい値はデフォルトで `auto_split_tablet_size` の値が使用されます）。

    ```sql
    CREATE TABLE test1_tbl3 (col1 INT, col2 INT, col3 VARCHAR(30), PRIMARY KEY(col1, col2))
        PARTITION BY RANGE();
    ```

5. 自動パーティションテーブル `test1_tbl4` を作成する際、プリパーティションキーを `col1, col2` に、分割しきい値を10GBに設定し、事前にパーティションマーカー `P0`、`P1`、`P2`、`P3` を作成します。

    ```sql
    CREATE TABLE test1_tbl4 (col1 INT, col2 INT, col3 VARCHAR(30), PRIMARY KEY(col1, col2))
        PARTITION BY RANGE COLUMNS(col1, col2) SIZE('10GB')
            (PARTITION P0 VALUES LESS THAN (100, MAXVALUE),
             PARTITION P1 VALUES LESS THAN (500, MAXVALUE),
             PARTITION P2 VALUES LESS THAN (800, MAXVALUE),
             PARTITION P3 VALUES LESS THAN (MAXVALUE, MAXVALUE));
    ```

6. テーブルの自動パーティション属性を確認します。

    ```sql
    SELECT TABLE_SCHEMA, TABLE_NAME, AUTO_SPLIT, AUTO_SPLIT_TABLET_SIZE
    FROM information_schema.TABLES
    WHERE TABLE_NAME LIKE "test1%"
    ORDER BY TABLE_NAME;
    ```

    実行結果は次のとおりです：

    ```shell
    +--------------+------------+------------+------------------------+
    | TABLE_SCHEMA | TABLE_NAME | AUTO_SPLIT | AUTO_SPLIT_TABLET_SIZE |
    +--------------+------------+------------+------------------------+
    | db_test      | test1_tbl1 | TRUE       |            10737418240 |
    | db_test      | test1_tbl2 | TRUE       |            10737418240 |
    | db_test      | test1_tbl3 | TRUE       |              134217728 |
    | db_test      | test1_tbl4 | TRUE       |            10737418240 |
    +--------------+------------+------------+------------------------+
    4 rows in set
    ```

### 例2：テーブルの自動パーティション属性を変更する

1. 自動パーティションテーブル `test2_tbl1` を作成し、プリパーティションキーを `col1` に、分割しきい値を10GBに設定します。

    ```sql
    CREATE TABLE test2_tbl1 (col1 INT, col2 INT, col3 VARCHAR(30), PRIMARY KEY(col1, col2))
        PARTITION BY RANGE(col1) SIZE('10GB');
    ```

2. テーブル `test2_tbl1` の自動パーティションしきい値を1GBに変更します。

    ```sql
    ALTER TABLE test2_tbl1 PARTITION BY RANGE() SIZE('1GB');
    ```

    または

    ```sql
    ALTER TABLE test2_tbl1 PARTITION BY RANGE(col1) SIZE('1GB');
    ```

3. 自動パーティションテーブル `test2_tbl2` を作成し、プリパーティションキーを `col1`、分割しきい値を10GBに指定します。また、事前にパーティションポイント `p0`（値が100未満の行）、`p1`（値が100以上200未満の行）、`p_max`（値が200以上の行）を作成します。

    ```sql
    CREATE TABLE test2_tbl2 (col1 INT, col2 INT, col3 VARCHAR(30), PRIMARY KEY(col1, col2))
        PARTITION BY RANGE(col1) SIZE('10GB')
            (PARTITION p0 VALUES LESS THAN(100),
             PARTITION p1 VALUES LESS THAN(200),
             PARTITION p_max VALUES LESS THAN (MAXVALUE));
    ```

4. テーブル `test2_tbl2` の自動パーティションしきい値を5GBに変更し、事前に作成したパーティションポイントを `p0`（値が300未満の行）と `p_max`（値が300以上の行）に変更します。

    ```sql
    ALTER TABLE test2_tbl2
        PARTITION BY RANGE(col1) SIZE('5GB')
            (PARTITION p0 VALUES LESS THAN(300),
             PARTITION p_max VALUES LESS THAN (MAXVALUE));
    ```

5. 自動パーティションテーブル `test2_tbl3` を作成し、プリパーティションキーを `col1`、分割しきい値を10GBに指定します。

    ```sql
    CREATE TABLE test2_tbl3 (col1 INT, col2 INT, col3 VARCHAR(30), PRIMARY KEY(col1, col2))
        PARTITION BY RANGE(col1) SIZE('10GB');
    ```

6. テーブル `test2_tbl3` の自動パーティションを禁止します。この変更は既存のパーティションには影響せず、今後新たな自動パーティションの分割はスケジュールされません。

    ```sql
    ALTER TABLE test2_tbl3 PARTITION BY RANGE() SIZE('unlimited');
    ```

7. 自動パーティションテーブル `test2_tbl4` を作成し、プリパーティションキーを `col1`、分割しきい値を10GBに指定します。

    ```sql
    CREATE TABLE test2_tbl4 (col1 INT, col2 INT, col3 VARCHAR(30), PRIMARY KEY(col1, col2))
        PARTITION BY RANGE(col1) SIZE('10GB');
    ```

8. テーブル `test2_tbl4` のプリパーティションキーを `col1` から `col1,col2` に変更します。

    ```sql
    ALTER TABLE test2_tbl4 PARTITION BY RANGE COLUMNS(col1,col2) SIZE('10GB');
    ```

9. 非自動パーティションテーブル `test2_tbl5` を作成します。

    ```sql
    CREATE TABLE test2_tbl5 (col1 INT, col2 INT, col3 VARCHAR(30), PRIMARY KEY(col1, col2));
    ```

10. `SIZE` 句を指定せずにテーブル `test2_tbl5` を自動パーティションテーブルに変更します。分割しきい値はデフォルトで `auto_split_tablet_size` の値が使用されます。

    ```sql
    ALTER TABLE test2_tbl5 PARTITION BY RANGE COLUMNS(col1);
    ```

11. テーブルの自動パーティション属性を確認します。

    ```sql
    SELECT TABLE_SCHEMA, TABLE_NAME, AUTO_SPLIT, AUTO_SPLIT_TABLET_SIZE
    FROM information_schema.TABLES
    WHERE TABLE_NAME LIKE "test2%"
    ORDER BY TABLE_NAME;
    ```

    実行結果は次のとおりです：

    ```shell
    +--------------+------------+------------+------------------------+
    | TABLE_SCHEMA | TABLE_NAME | AUTO_SPLIT | AUTO_SPLIT_TABLET_SIZE |
    +--------------+------------+------------+------------------------+
    | db_test      | test2_tbl1 | TRUE       |             1073741824 |
    | db_test      | test2_tbl2 | TRUE       |             5368709120 |
    | db_test      | test2_tbl3 | FALSE      |                      0 |
    | db_test      | test2_tbl4 | TRUE       |            10737418240 |
    | db_test      | test2_tbl5 | TRUE       |              134217728 |
    +--------------+------------+------------+------------------------+
    5 rows in set
    ```

### 例3：自動パーティション機能を有効にした後でテーブルを作成する

1. 自動パーティション機能を有効にします。

    ```sql
    AlTER SYSTEM SET enable_auto_split = TRUE;
    ```

2. 非パーティションテーブル `test3_tbl1` を作成します。テナントレベルで全ての非パーティションテーブルが `SIZE` パーティションを自動使用するよう設定されているため、通常のテーブル作成構文は自動的に自動パーティションを行い、テナントレベルのパラメータを読み取ります。

    ```sql
    CREATE TABLE test3_tbl1 (col1 INT, col2 INT, PRIMARY KEY(col1));
    ```

3. 自動パーティションの非パーティションテーブル `test3_tbl2` を作成します。パーティションキーを指定していないため、デフォルトで主キーがパーティションキーとして使用されます。

    ```sql
    CREATE TABLE test3_tbl2 (col1 INT, col2 INT, PRIMARY KEY(col1))
        PARTITION BY RANGE ();
    ```

4. 自動パーティションの非パーティションテーブル `test3_tbl3` を作成します（分割しきい値は1024MB、ユーザー設定を使用）。

    ```sql
    CREATE TABLE test3_tbl3 (col1 INT, col2 INT, PRIMARY KEY(col1))
        PARTITION BY RANGE () SIZE('1024MB');
    ```

5. 非自動パーティションテーブル `test3_tbl4` を作成します。

    ```sql
    CREATE TABLE test3_tbl4 (col1 INT, col2 INT, PRIMARY KEY(col1))
        PARTITION BY RANGE () SIZE('unlimited');
    ```

6. 主キーのないテーブルは自動パーティション要件を満たさないため、`enable_auto_split = true` でも自動パーティションは有効になりません。

    ```sql
    CREATE TABLE test3_tbl5 (col1 INT, col2 INT);
    ```

7. 主キーのないテーブルは自動パーティション要件を満たさないため、手動で自動パーティションを有効にするとエラーが発生します。

    ```sql
    CREATE TABLE test3_tbl6 (col1 INT, col2 INT)
        PARTITION BY RANGE ();
    ```

    実行結果は次のとおりです：

    ```shell
    ERROR 1235 (0A000): auto partitioned table without primary key is not supported
    ```

8. テーブルの自動パーティション属性を確認します。

    ```sql
    SELECT TABLE_SCHEMA, TABLE_NAME, AUTO_SPLIT, AUTO_SPLIT_TABLET_SIZE
    FROM information_schema.TABLES
    WHERE TABLE_NAME LIKE "test3%"
    ORDER BY TABLE_NAME;
    ```

    実行結果は次のとおりです：

    ```shell
    +--------------+------------+------------+------------------------+
    | TABLE_SCHEMA | TABLE_NAME | AUTO_SPLIT | AUTO_SPLIT_TABLET_SIZE |
    +--------------+------------+------------+------------------------+
    | db_test      | test3_tbl1 | TRUE       |              134217728 |
    | db_test      | test3_tbl2 | TRUE       |              134217728 |
    | db_test      | test3_tbl3 | TRUE       |             1073741824 |
    | db_test      | test3_tbl4 | FALSE      |                      0 |
    | db_test      | test3_tbl5 | FALSE      |                      0 |
    +--------------+------------+------------+------------------------+
    5 rows in set
    ```

### 例4：グローバルインデックスで自動パーティションを有効にする

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>自動パーティションが有効なテーブルでは、構成パラメータ <a href="../../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3350.global_index_auto_split_policy.md">global_index_auto_split_policy</a> が無効であっても、作成されるグローバルインデックスは自動的にパーティション化されます。</p>
</main>

1. 自動パーティションテーブル `test4_tbl1` を作成します（分割しきい値は1024MB、ユーザー設定を使用）。

    ```sql
    CREATE TABLE test4_tbl1 (col1 INT, col2 INT, col3 INT, PRIMARY KEY(col1))
        PARTITION BY RANGE () SIZE('1024MB');
    ```

2. テーブル `test4_tbl1` にグローバルインデックス `idx1_test4_tbl1` を作成します。

    ```sql
    CREATE INDEX idx1_test4_tbl1 ON test4_tbl1 (col2) GLOBAL;
    ```

3. 新規グローバルインデックスで自動パーティション機能を有効にします。

    ```sql
    ALTER SYSTEM SET global_index_auto_split_policy = 'ALL';
    ```

4. 非自動パーティションのパーティションテーブル `test4_tbl2` を作成します。

    ```sql
    CREATE TABLE test4_tbl2(col1 INT, col2 INT, col3 INT, PRIMARY KEY(col1))
        PARTITION BY RANGE(col1)
        (PARTITION p0 VALUES LESS THAN(100),
        PARTITION p1 VALUES LESS THAN(200),
        PARTITION p2 VALUES LESS THAN(300));
    ```

5. テーブル `test4_tbl2` にグローバルインデックス `idx1_test4_tbl2` を作成します。

    ```sql
    CREATE INDEX idx1_test4_tbl2 ON test4_tbl2 (col2) GLOBAL;
    ```
