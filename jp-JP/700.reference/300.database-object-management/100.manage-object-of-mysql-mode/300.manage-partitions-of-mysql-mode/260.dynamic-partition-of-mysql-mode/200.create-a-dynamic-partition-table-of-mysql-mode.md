# 動的パーティションテーブルの作成

OceanBaseデータベースでは、`DYNAMIC_PARTITION_POLICY`ブロックを使用して、テーブル作成時にその動的パーティション管理の属性を指定します。

本記事では、SQLステートメントを使用して動的パーティションテーブルを作成する方法について説明します。

## 使用上の制限と注意事項

* 現在のバージョンでは、動的パーティションテーブルを作成するには、少なくとも1つのパーティション定義を指定する必要があります。
* 次のタイプのパーティションテーブルでのみ動的パーティション管理を有効にできます：

  * Range Columnsパーティションで、かつパーティションキーが`date`、`datetime`、`timestamp`、`year`、`bigint`（`BIGINT_PRECISION`精度を指定）タイプのパーティションテーブル。
  * Rangeパーティションで、かつパーティションキーが`year`、`bigint`（`BIGINT_PRECISION`精度を指定）タイプのパーティションテーブル。
  * List Columnsパーティションを使用し、パーティションキーが日時を文字列として格納する列であるテーブル。パーティションキーの文字列型には `VARCHAR`/`CHAR` を使用でき、形式は `TIME_UNIT` の値によって決まります：

    * `TIME_UNIT = 'year'` の場合：文字列パーティションキーの形式は `YYYY` です。例：`2026`。
    * `TIME_UNIT = 'month'` の場合：文字列パーティションキーの形式は `YYYYMM` です。例：`202608`。
    * `TIME_UNIT = 'day'` の場合：文字列パーティションキーの形式は `YYYYMMDD` です。例：`20260819`。
    * `TIME_UNIT = 'hour'` の場合：文字列パーティションキーの形式は `YYYYMMDDHH` です。例：`2026081910`。

    <main id="notice" type='explain'>
      <h4>説明</h4>
      <p>V4.4.2では、V4.4.2 BP3から、日時を文字列として格納する列をパーティションキーとするList Columnsパーティションテーブルで動的パーティション管理がサポートされています。</p>
    </main>

* 動的パーティション管理を有効にできるのは、単一レベルのパーティションテーブルのパーティションと、コンポジット・パーティションテーブルの第1レベルのパーティションのみです。
* テーブル作成後、パーティションの事前作成と期限切れパーティションの削除は即座には実行されません。次回の動的パーティション管理タスクの自動スケジュールを待つか、手動で動的パーティション管理タスクを1回スケジュールする必要があります。動的パーティション管理タスクのスケジュールに関する詳細は、[動的パーティション管理タスク](500.dynamic-partition-management-task-of-mysql-mode.md)を参照してください。

## 権限要件

動的パーティションテーブルを作成するには`CREATE`権限が必要です。OceanBaseデータベースの権限に関する詳細は、[MySQLモードの権限分類](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md)を参照してください。

## 構文

動的パーティションテーブルを作成するSQLステートメントの形式は以下のとおりです：

```sql
CREATE TABLE [IF NOT EXISTS] table_name (table_definition_list)
    DYNAMIC_PARTITION_POLICY [=] (dynamic_partition_policy_list)
    partition_option;

dynamic_partition_policy_list:
    dynamic_partition_policy_option [, dynamic_partition_policy_option ...]

dynamic_partition_policy_option:
    ENABLE = {true | false}
    | TIME_UNIT = {'hour' | 'day' | 'week' | 'month' | 'year'}
    | PRECREATE_TIME = {'-1' | '0' | 'n {hour | day | week | month | year}'}
    | EXPIRE_TIME = {'-1' | '0' | 'n {hour | day | week | month | year}'}
    | TIME_ZONE = {'default' | 'time_zone'}
    | BIGINT_PRECISION = {'none' | 'us' | 'ms' | 's'}
```

## 動的パーティション管理属性パラメータの説明

|   **プロパティ名**   | **説明** | **必須** | **変更は可能か** |
|------------------|----------|--------------|----------------|
| ENABLE           | 動的パーティション管理を有効にするかどうかを示します。値は以下のとおりです：<ul><li>`true`：デフォルト値で、動的パーティション管理を有効にすることを示します。</li><li>`false`：動的パーティション管理を無効にすることを示します。</li></ul>| いいえ | はい |
| TIME_UNIT        | パーティションの時間単位、つまり自動的に作成されるパーティション境界の間隔を示します。値は以下のとおりです：<ul><li>`hour`：時間ごとにパーティションを分割します。</li><li>`day`：日ごとにパーティションを分割します。</li><li>`week`：週ごとにパーティションを分割します。</li><li>`month`：月ごとにパーティションを分割します。</li><li>`year`：年ごとにパーティションを分割します。</li></ul>| はい | いいえ |
| PRECREATE_TIME   | 事前作成時間を示します。動的パーティション管理を1回スケジュールすると、**パーティション上限の最大値 > now() + precreate_time** になるようにパーティションが事前作成されます。値は以下のとおりです：<ul><li>`-1`：デフォルト値で、パーティションを事前作成しないことを示します。</li><li>`0`：現在のパーティションのみを事前作成することを示します。</li><li>`n {hour \| day \| week \| month \| year}`：対応する時間幅のパーティションを事前作成することを示します。例えば、`3 hour` は3時間以内のパーティションを事前作成することを示します。</li></ul>  <main id="notice" type='explain'><h4>説明</h4><p><ul><li>複数のパーティションを事前作成する必要がある場合、パーティション境界の間隔は <code>TIME_UNIT</code> となります。</li><li>最初に事前作成されるパーティションの境界は、既存の最大パーティション境界を <code>TIME_UNIT</code> の単位で切り上げた値となります。</li></ul></p></main>| いいえ | はい |
| EXPIRE_TIME      | パーティションの有効期限を示します。動的パーティション管理を1回スケジュールすると、**パーティション上限 < now() - expire_time** のすべての期限切れパーティションが削除されます。値は以下のとおりです：<ul><li>`-1`：デフォルト値で、パーティションは永遠に期限切れにならないことを示します。</li><li>`0`：現在のパーティションを除く、それ以前のすべてのパーティションが期限切れになることを示します。</li><li>`n {hour \| day \| week \| month \| year}`：パーティションの有効期限を示します。例えば、`1 day` はパーティションの有効期限が1日であることを示します。</li></ul>| いいえ | はい |
| TIME_ZONE        | 現在時刻と日時型（`date`、`datetime`、`year` 型）のパーティションキーの大きさを比較する際に依存するタイムゾーン情報を示します。値は以下のとおりです：<ul><li>`default`：デフォルト値で、タイムゾーンを追加で設定せず、テナントのタイムゾーンを使用することを示します。上記の型以外では、`time_zone`フィールドは`default`である必要があります。</li><li>`time_zone`：カスタムタイムゾーンのオフセット値を示します。例えば、`+8:00` などのタイムゾーンオフセット値です。</li></ul>| いいえ | いいえ |
| BIGINT_PRECISION | `bigint`型のパーティションキーのタイムスタンプ精度を示します。値は以下のとおりです：<ul><li>`none`：デフォルト値で、精度がないことを示します（パーティションキーが `bigint` 型でない場合）。</li><li>`us`：マイクロ秒精度。</li><li>`ms`：ミリ秒精度。</li><li>`s`：秒精度。</li></ul>| いいえ | いいえ |

テーブル作成構文の詳細なパラメータ説明については、[CREATE TABLE](../../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2600.create-table-of-mysql-mode.md)を参照してください。

### 動的パーティションパラメータの制限

* `TIME_UNIT`：パーティションキーが `date` 型の場合、パラメータ `TIME_UNIT` では `hour` を使用できません。パーティションキーが `year` 型の場合、パラメータ `TIME_UNIT` では `year` のみを使用できます。
* `PRECREATE_TIME`：最大で2048個のパーティションを事前作成できます。
* `TIME_ZONE`：パーティションキーが `date`、`datetime`、または `year` 型の場合にのみ、パラメータ `TIME_ZONE` でカスタムタイムゾーンのオフセット値を指定できます。その他の型では `default` のみ指定可能です。
* `BIGINT_PRECISION`：このパラメータの値を `us`、`ms`、`s` に設定できるのは、パーティションキーの型が `bigint` の場合のみです。その他のパーティションキー型では、このパラメータの値は `none` のみとなります。
* `TIME_UNIT`、`TIME_ZONE`、`BIGINT_PRECISION` は指定後、変更できません。

## 例

### Range Columnsパーティションの例

Range Columnsパーティションの動的パーティションテーブル `test_tbl1` を作成し、動的パーティションの属性を以下のように設定します：

* パーティションの境界を1時間ごとに設定します。
* 現在時刻から3時間以内のパーティションを事前作成します。
* パーティションの上限が現在時刻の1日前より早いパーティションを削除します。
* 北京時間（UTC+8）を用いて時間を判断し、パーティションの境界と有効期限のロジックがこのタイムゾーンに基づくことを保証します。
* パーティションキー `col2` は `DATETIME` 型であるため、`bigint` のタイムスタンプ精度を設定する必要はありません。

```sql
CREATE TABLE test_tbl1 (col1 INT, col2 DATETIME)
    DYNAMIC_PARTITION_POLICY(
        ENABLE = true,
        TIME_UNIT = 'hour',
        PRECREATE_TIME = '3 hour',
        EXPIRE_TIME = '1 day',
        TIME_ZONE = '+8:00',
        BIGINT_PRECISION = 'none'
    )
    PARTITION BY RANGE COLUMNS (col2)(
        PARTITION P0 VALUES LESS THAN ('2025-04-15 13:30:00')
    );
```

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>テーブル作成後、パーティションの事前作成と期限切れパーティションの削除は即座には実行されません。次回の動的パーティション管理タスクの自動スケジュールを待つか、手動で動的パーティション管理タスクを1回スケジュールする必要があります。詳細については、<a href="500.dynamic-partition-management-task-of-mysql-mode.md">動的パーティション管理タスク</a>を参照してください。</p>
</main>

### List Columns パーティションの例

List Columns パーティションの動的パーティションテーブル `test_tbl2` を作成します。パーティションキーは日付を文字列として格納する列で、形式は `YYYYMMDD` です。動的パーティションのプロパティを以下のように設定します：

* パーティション境界の自動作成間隔を1日とし、パーティションを分割します。
* パーティション境界を1日ごとに設定します。
* 現在時刻から3日以内のパーティションを事前作成します。
* パーティションの上限が現在時刻から30日前より早いパーティションを削除します。
* 北京時間(UTC+8)で時間を判断し、パーティション境界と有効期限のロジックがこのタイムゾーンに基づくことを確保します。
* パーティションキー `col2` は `VARCHAR` 型であるため、`bigint` 型のタイムスタンプ精度を設定する必要はありません。

```shell
obclient> CREATE TABLE test_tbl2 (col1 INT, col2 VARCHAR(20))
    DYNAMIC_PARTITION_POLICY(
        ENABLE = true,
        TIME_UNIT = 'day',
        PRECREATE_TIME = '3 day',
        EXPIRE_TIME = '30 day',
        TIME_ZONE = '+8:00',
        BIGINT_PRECISION = 'none'
    )
    PARTITION BY LIST COLUMNS(col2) (
        PARTITION p_20260801 VALUES IN ('20260801')
    );
```
