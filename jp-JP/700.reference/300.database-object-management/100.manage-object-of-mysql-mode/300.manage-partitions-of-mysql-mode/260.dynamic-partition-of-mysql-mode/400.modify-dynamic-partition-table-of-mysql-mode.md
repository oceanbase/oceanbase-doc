# 動的パーティションテーブルの変更

OceanBaseデータベースでは、`DYNAMIC_PARTITION_POLICY` ブロックを変更することで、テーブルの動的パーティション管理属性を変更できます。

本記事では、SQLステートメントを使用して動的パーティションテーブルを変更する方法について説明します。

## 使用上の制限と注意事項

* 動的パーティション管理パラメータの変更は、パーティションの事前作成や期限切れパーティションの削除に即時には反映されません。次回の動的パーティション管理タスクが自動的にスケジュールされるのを待つか、手動で動的パーティション管理タスクを1回スケジュールする必要があります。動的パーティション管理タスクのスケジュールに関する詳細は、[動的パーティション管理タスク](500.dynamic-partition-management-task-of-mysql-mode.md)を参照してください。
* `TIME_UNIT`、`TIME_ZONE`、`BIGINT_PRECISION` パラメータは動的パーティションテーブル作成時に指定し、一度指定すると変更できません。
* 動的パーティションポリシーを変更する際に `TIME_UNIT` を指定するかどうかは、テーブルで動的パーティション管理が有効になっているかどうかによって異なります：

  * 動的パーティション管理が有効なテーブルでは、`TIME_UNIT` を指定する必要はなく、変更文でも指定できません（指定するとエラーが発生します）。
  * 動的パーティション管理が有効でないテーブル（通常のパーティションテーブルなど）では、変更文で `TIME_UNIT` を指定する必要があります。

## 権限要件

動的パーティションテーブルを変更するには `ALTER` 権限が必要です。OceanBaseデータベースの権限に関する詳細は、[MySQLモードの権限分類](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md)を参照してください。

## 構文

動的パーティションテーブルを変更するSQLステートメントの形式は以下のとおりです：

```sql
ALTER TABLE table_name [SET] DYNAMIC_PARTITION_POLICY [=] (dynamic_partition_policy_list);

dynamic_partition_policy_list:
    dynamic_partition_policy_option [, dynamic_partition_policy_option ...]

dynamic_partition_policy_option:
    ENABLE = {true | false}
    | TIME_UNIT = {'hour' | 'day' | 'week' | 'month' | 'year'}
    | PRECREATE_TIME = {'-1' | '0' | 'n {hour | day | week | month | year}'}
    | EXPIRE_TIME = {'-1' | '0' | 'n {hour | day | week | month | year}'}
```

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p><code>TIME_UNIT</code> はテーブル作成時に指定し、一度指定すると変更できません。動的パーティション管理が有効なテーブルを変更する場合は、<code>TIME_UNIT</code> を指定できません。動的パーティション管理が有効でないテーブルに動的パーティションポリシーを追加する場合は、<code>TIME_UNIT</code> を指定する必要があります。</p>
</main>

## 動的パーティション管理属性パラメータの説明

|   **プロパティ名**   | **説明** | **必須** | **変更は可能か** |
|------------------|----------|--------------|----------------|
| ENABLE           | 動的パーティション管理を有効にするかどうかを示します。値は以下のとおりです：<ul><li>`true`：デフォルト値で、動的パーティション管理を有効にします。</li><li>`false`：動的パーティション管理を無効にします。</li></ul>| いいえ | はい |
| TIME_UNIT        | パーティションの時間単位、つまり自動的に作成されるパーティション境界の間隔を示します。値は以下のとおりです：<ul><li>`hour`：時間単位でパーティションを分割します。</li><li>`day`：日単位でパーティションを分割します。</li><li>`week`：週単位でパーティションを分割します。</li><li>`month`：月単位でパーティションを分割します。</li><li>`year`：年単位でパーティションを分割します。</li></ul>  <main id="notice" type='explain'><h4>説明</h4><p><ul><li>このパラメータは動的パーティションテーブル作成時に指定し、一度指定すると変更できません。</li><li>動的パーティション管理が有効なテーブルを変更する場合は、このパラメータを指定する必要はなく、変更ステートメント内でも指定できません（指定するとエラーが発生します）。</li><li>動的パーティション管理が有効でないテーブルに動的パーティションポリシーを追加する場合は、このパラメータを指定する必要があります。</li><li>パーティションキーのタイプと <code>TIME_UNIT</code> の値の対応制限については、<a href="200.create-a-dynamic-partition-table-of-mysql-mode.md">動的パーティションテーブルの作成</a> を参照してください。</li></ul></p></main>| いいえ | いいえ |
| PRECREATE_TIME   | 事前作成時間を示します。動的パーティション管理を1回スケジュールすると、**パーティションの上限値の最大値 > now() + precreate_time** になるようにパーティションが事前作成されます。値は以下のとおりです：<ul><li>`-1`：デフォルト値で、パーティションを事前作成しません。</li><li>`0`：現在のパーティションのみを事前作成します。</li><li>`n {hour \| day \| week \| month \| year}`：指定された時間範囲のパーティションを事前作成します。例えば、`3 hour` は現在時刻から3時間以内のパーティションを事前作成します。</li></ul>  <main id="notice" type='explain'><h4>説明</h4><p><ul><li>複数のパーティションを事前作成する必要がある場合、パーティション境界の間隔は <code>TIME_UNIT</code> です。</li><li>最初に事前作成されるパーティションの境界は、既存の最大パーティション境界を <code>TIME_UNIT</code> の単位で切り上げた値になります。</li></ul></p></main>| いいえ | はい |
| EXPIRE_TIME      | パーティションの有効期間を示します。動的パーティション管理を1回スケジュールすると、**パーティションの上限値 < now() - expire_time** のすべての期限切れパーティションが削除されます。値は以下のとおりです：<ul><li>`-1`：デフォルト値で、パーティションは永遠に期限切れになりません。</li><li>`0`：現在のパーティションを除く、それ以前のすべてのパーティションが期限切れになります。</li><li>`n {hour \| day \| week \| month \| year}`：パーティションの有効期間を示します。例えば、`1 day` はパーティションの有効期間が1日であることを示します。</li></ul>| いいえ | はい |

テーブルの変更構文における各パラメータの詳細については、[ALTER TABLE](../../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/1600.alter-table-of-mysql-mode.md)を参照してください。

## 例

1. テーブルの作成：

    ```sql
    CREATE TABLE test_tbl1 (col1 INT, col2 DATETIME)
    DYNAMIC_PARTITION_POLICY(
        ENABLE = true,
        TIME_UNIT = 'hour',
        PRECREATE_TIME = '3 hour',
        EXPIRE_TIME = '1 day',
        TIME_ZONE = '+8:00',
        BIGINT_PRECISION = 'none'
    )
    PARTITION BY RANGE COLUMNS (col2)(
        PARTITION P0 VALUES LESS THAN ('2025-04-15 13:30:00')
    );
    ```

2. テーブル `test_tbl1` の動的パーティション情報を確認します。

    ```sql
    SELECT * FROM oceanbase.DBA_OB_DYNAMIC_PARTITION_TABLES
    WHERE TABLE_NAME = 'test_tbl1';
    ```

    クエリ結果は次のとおりです：

    ```shell
    +---------------+------------+----------+-----------------------+--------+-----------+----------------+-------------+-----------+------------------+
    | DATABASE_NAME | TABLE_NAME | TABLE_ID | MAX_HIGH_BOUND_VAL    | ENABLE | TIME_UNIT | PRECREATE_TIME | EXPIRE_TIME | TIME_ZONE | BIGINT_PRECISION |
    +---------------+------------+----------+-----------------------+--------+-----------+----------------+-------------+-----------+------------------+
    | test          | test_tbl1  |   500004 | '2025-04-15 13:30:00' | TRUE   | HOUR      | 3HOUR          | 1DAY        | +8:00     | NONE             |
    +---------------+------------+----------+-----------------------+--------+-----------+----------------+-------------+-----------+------------------+
    1 row in set
    ```

3. 動的パーティションテーブル `test_tbl1` を変更し、動的パーティション属性を以下のように設定します：

   * 現在時刻から1日以内のパーティションを事前作成します。
   * パーティションは期限切れになりません。

   ```sql
   ALTER TABLE test_tbl1 DYNAMIC_PARTITION_POLICY(
       ENABLE = true,
       PRECREATE_TIME = '1 day',
       EXPIRE_TIME = '-1'
   );
   ```

4. 再度、テーブル `test_tbl1` の動的パーティション情報を確認します。

    ```sql
    SELECT * FROM oceanbase.DBA_OB_DYNAMIC_PARTITION_TABLES
    WHERE TABLE_NAME = 'test_tbl1';
    ```

    クエリ結果は次のとおりです：

    ```shell
    +---------------+------------+----------+-----------------------+--------+-----------+----------------+-------------+-----------+------------------+
    | DATABASE_NAME | TABLE_NAME | TABLE_ID | MAX_HIGH_BOUND_VAL    | ENABLE | TIME_UNIT | PRECREATE_TIME | EXPIRE_TIME | TIME_ZONE | BIGINT_PRECISION |
    +---------------+------------+----------+-----------------------+--------+-----------+----------------+-------------+-----------+------------------+
    | test          | test_tbl1  |   500004 | '2025-04-15 13:30:00' | TRUE   | HOUR      | 1DAY           | -1          | +8:00     | NONE             |
    +---------------+------------+----------+-----------------------+--------+-----------+----------------+-------------+-----------+------------------+
    1 row in set
    ```

    <main id="notice" type='explain'>
      <h4>説明</h4>
      <p>動的パーティション管理パラメータの変更は、パーティションの事前作成や期限切れパーティションの削除に即時には反映されません。次回の動的パーティション管理タスクが自動的にスケジュールされるのを待つか、手動で動的パーティション管理タスクを1回スケジュールする必要があります。詳細については、<a href="500.dynamic-partition-management-task-of-mysql-mode.md">動的パーティション管理タスク</a>を参照してください。</p>
    </main>

5. まだ動的パーティション管理が有効になっていない通常のRange Columnsパーティションテーブルに動的パーティションポリシーを追加します。

   1. 通常のRange Columnsパーティションテーブル `test_tbl3` を作成します。

      ```sql
      CREATE TABLE test_tbl3 (col1 INT, col2 DATETIME)
          PARTITION BY RANGE COLUMNS (col2)(
              PARTITION P0 VALUES LESS THAN ('2026-09-14 00:00:00')
          );
      ```

   2. `test_tbl3` に動的パーティションポリシーを追加し、動的パーティション属性を以下のように設定します：

      * パーティション境界を日単位で設定します。
      * 現在時刻から3日以内のパーティションを事前作成します。
      * パーティションの上限値が現在時刻の30日前より前のパーティションを削除します。

      ```sql
      ALTER TABLE test_tbl3 DYNAMIC_PARTITION_POLICY(
          ENABLE = true,
          TIME_UNIT = 'day',
          PRECREATE_TIME = '3 day',
          EXPIRE_TIME = '30 day'
      );
      ```

      <main id="notice" type='explain'>
        <h4>説明</h4>
        <p><ul><li>動的パーティション管理が有効になっていないテーブルに動的パーティションポリシーを追加する場合、<code>TIME_UNIT</code> を指定する必要があります。</li><li>パーティションキーが時間型の場合、<code>TIME_ZONE</code> のデフォルト値は <code>default</code>、<code>BIGINT_PRECISION</code> のデフォルト値は <code>none</code> であり、省略できます。</li></ul></p>
      </main>

6. 手動で動的パーティション管理タスクを1回トリガーし、事前作成されたパーティションを確認します。

   ```sql
   CALL DBMS_PARTITION.MANAGE_DYNAMIC_PARTITION();
   ```

   テーブル `test_tbl3` のパーティション情報を確認します：

   ```sql
   SELECT TABLE_NAME, PARTITION_NAME, PARTITION_DESCRIPTION
   FROM information_schema.PARTITIONS
   WHERE TABLE_NAME = 'test_tbl3'
   ORDER BY PARTITION_ORDINAL_POSITION;
   ```

   クエリ結果では、事前に作成された3つの日単位のパーティションが確認できます。
