# テーブルロック

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>OceanBaseデータベースCommunity Editionは、V4.2.5バージョンからテーブルロック機能をサポートしています。</p>
</main>

テーブルロックは最も基本的なロック戦略であり、テーブル全体をロックし、任意の時点で同一テーブルに対する読み書き操作を許可するのは一つのセッションのみです。`LOCK TABLES` ステートメントを使用してテーブルをロックできます。

データベースは複数のユーザーが共有するリソースです。複数のユーザーが同時にデータにアクセスすると、データベース内では複数のトランザクションが同一データに同時にアクセスする状況が発生します。並行操作を制御しない場合、正しくないデータが読み取られたり保存されたりし、データベースの整合性が損なわれる可能性があります。ロックは、データベースの並行制御を実現するための非常に重要な技術です。リソースの安全性（つまりデータの完全性と整合性）を確保するために、ロックメカニズムが導入されました。このロックメカニズムを利用して、トランザクション間のデータ並行アクセスおよびデータの整合性を実現します。

## 前提条件

* `LOCK TABLES` ステートメントを使用する前に、以下のテナントレベルの構成パラメータを有効にする必要があります：

    ```sql
    ALTER SYSTEM SET enable_lock_priority = TRUE;
    ```

    上記のテナントレベルの構成パラメータの詳細については、[enable_lock_priority](../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2750.enable_lock_priority.md)を参照してください。

    <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>対応するテナントの <code>enable_lock_priority</code> を有効にした後、すべてのノードが直ちにその設定を認識できるわけではありません。そのため、ビュー <code>GV$OB_PARAMETERS</code> を使用してすべてのノード上の対応する構成パラメータの値を照会し、テナント内のすべてのマシンで有効になっていることを確認する必要があります。</p>
    </main>

* プロキシ経由でクラスタに接続する場合は、プロキシの以下の設定も有効にする必要があります：

    ```sql
    ALTER PROXYCONFIG SET proxy_id = 1;
    ALTER PROXYCONFIG SET client_session_id_version = 2;
    ALTER PROXYCONFIG SET enable_single_leader_node_routing = false;
    ```

    上記のプロキシ設定の詳細については、[proxy_id](https://www.oceanbase.com/docs/common-odp-doc-cn-1000000001409988)、[client_session_id_version](https://www.oceanbase.com/docs/common-odp-doc-cn-1000000001410074)、および [enable_single_leader_node_routing](https://www.oceanbase.com/docs/common-odp-doc-cn-1000000001410098)を参照してください。

## 操作例

`test1` テーブルに読み取りロックを設定し、`test2` テーブルに書き込みロックを設定します。

```sql
LOCK TABLES test1 as t1 READ LOCAL, test2 as t2 LOW_PRIORITY WRITE;
```

* テーブルを読み取り専用モードでロックすると、そのテーブルは `select` のみ可能で、変更はできません。テーブルをロックする際に、そのテーブル上にトランザクションが存在する場合、`lock` ステートメントはトランザクションが終了するまで待機します。複数のセッションが同時にこの操作をテーブルに対して実行できます。
* テーブルを読み書きモードでロックすると、`lock table` のセッションはテーブルに対して変更やクエリなどの操作を実行できますが、他のセッションはそのテーブルに対して何も操作できません。`select` もブロックされます。

`LOCK TABLES` ステートメントの詳細については、[LOCK TABLES](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/6000.lock-table-of-mysql-mode.md)を参照してください。
