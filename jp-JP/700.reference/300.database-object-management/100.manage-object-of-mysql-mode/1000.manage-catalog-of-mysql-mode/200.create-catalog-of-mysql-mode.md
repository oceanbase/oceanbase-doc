# Catalogの作成

本記事では、SQLステートメントを使用してExternal Catalogを作成する方法について説明します。

## 権限要件

External Catalogを作成するには、現在のユーザーが`CREATE CATALOG`権限を持っている必要があります。OceanBaseデータベースの権限の詳細については、[MySQLモードの権限分類](../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md)を参照してください。

## 構文

External Catalogを作成するSQLステートメントの形式は以下のとおりです：

```sql
CREATE EXTERNAL CATALOG [IF NOT EXISTS] external_catalog_name
    PROPERTIES [=] (properties_type_options);

properties_type_options:
    odps_type_list
    | hms_type_list
    | jdbc_type_list

odps_type_list:
    TYPE = 'ODPS',
    [ACCESSTYPE = 'accesstype_string',]
    ACCESSID = 'string',
    ACCESSKEY = 'string',
    STSTOKEN = 'string',
    ENDPOINT = 'string',
    TUNNEL_ENDPOINT = 'string',
    PROJECT_NAME = 'string',
    [QUOTA_NAME = 'string',]
    [COMPRESSION = 'compression_string',]
    REGION = 'string'

hms_type_list:
    TYPE = 'HMS',
    URI = "string"
    [, KRB5CONF = "string"]
    [, KEYTAB = "string"]
    [, PRINCIPAL = "string"]
    [, MAX_CLIENT_POOL_SIZE = 20]
    [, SOCKET_TIMEOUT = 10000000]

jdbc_type_list:
    TYPE = 'JDBC',
    URL = 'string'

accesstype_string:
    aliyun
    | sts
    | app

compression_string:
    zlib
    | zstd
    | lz4
    | odps_lz4
```

**パラメータの説明：**

* `IF NOT EXISTS`：省略可能です。作成対象の外部データカタログが現在のテナントに既に存在する場合、この句を指定すると警告が表示されます。省略するとエラーになります。
* `external_catalog_name`：作成する外部データカタログの名前を表します。
* `PROPERTIES [=] (properties_type_options)`：外部データカタログのタイプに応じたプロパティを指定します。
* `odps_type_list`：ODPSタイプの外部データカタログ（ODPS Catalog）の関連属性リストを表します。
* `hms_type_list`：HMSタイプの外部データカタログ（HMS Catalog）の関連属性リストを表します。
* `jdbc_type_list`：JDBCタイプの外部データカタログ（JDBC Catalog）の関連属性リストを表します。

External Catalogの作成時に指定できるパラメータの詳細については、[CREATE EXTERNAL CATALOG](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2150.create-external-catalog-of-mysql-mode.md)を参照してください。

## ODPSタイプのExternal Catalogの作成

外部テーブルでMaxComputeのデータを読み書きする場合、`TYPE`に`ODPS`を指定します。

`CREATE EXTERNAL CATALOG`を使用してMaxCompute（ODPS）への接続を作成し、マッピングテーブルを手動で作成することなくODPSテーブルデータを直接クエリできます。Catalog下のオブジェクトは読み取り専用です。MaxComputeへのデータ書き込みには、[ODPS外部テーブル](../../../../620.obap/400.data-lake/200.data-lake-integration/300.odps/200.odps-external-table.md)を使用してください。

**例：**

```shell
obclient> CREATE EXTERNAL CATALOG test_odps_catalog
    PROPERTIES = (
        TYPE = 'ODPS',
        ACCESSID = '$odps_accessid',
        ACCESSKEY = '$odps_accesskey',
        ENDPOINT = '$odps_endpoint',
        TUNNEL_ENDPOINT = 'http://xxx.maxcompute.aliyun.com',
        PROJECT_NAME = 'mysqltest_regression_sqlqa',
        QUOTA_NAME = '',
        COMPRESSION_CODE = ''
    );
```

## HMSタイプのExternal Catalogの作成

OceanBaseデータベースは、HMS Catalog機能を通じてHiveメタデータ（Metastore）の統一管理を実現します。HMS Catalogにより、OceanBaseはHiveテーブルに対応するHDFSストレージパス内のデータに直接アクセスでき、効率的なデータレイクのクエリと分析をサポートします。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>HMSがアクセスするファイルがHDFS上にある場合は、HMS Catalogを作成する前にJava SDK環境をデプロイしてください。手順は、<a href="../../../../400.deploy/300.deploy-oceanbase-enterprise-edition/500.deploy-the-ob-java-sdk-environment.md">OceanBaseデータベースのJava SDK環境をデプロイする</a>を参照してください。</p>
</main>

### HMS Catalogのサポート状況

現在のバージョンのHMS Catalogは、HiveとIcebergのテーブル形式に対応しています。いずれの形式でも統計情報を読み取り、SQLプランの最適化に利用できます。

#### Hive形式のサポート状況

現在のバージョンは`Parquet`、`ORC`、`Textfile`、`OpenCSV`の4種類の形式をサポートしています。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>複合型については、現在のバージョンでは <code>Parquet</code> フォーマットの <code>ARRAY</code> 型のみがサポートされています。</p>
</main>

#### Icebergのサポート状況

現在のバージョンでは、Iceberg V1とV2の2種類をサポートしています。

OceanBaseデータベースは、Schema EvolutionおよびPartition Transformを経たIcebergテーブルの読み取りをサポートしています。

#### Hiveバージョンのサポート

OceanBaseは現在、以下のHiveバージョンのHMS Catalogをサポートしています：

* Hive 1.2.x
* Hive 2.3.x
* Hive 3.1.x
* Hive 4.x

### 認証タイプのサポート

OceanBaseデータベースは、以下の2種類のHMS Catalog認証方式をサポートしています：

| 認証タイプ | 説明 | 設定要件 |
|----------|------|---------|
| SIMPLE   | ユーザー名とパスワードに基づくシンプルな認証（デフォルト）| `PROPERTIES` 句で `KRB5CONF`、`KEYTAB`、`PRINCIPAL` パラメータを指定する必要はありません。|
| KERBEROS | Kerberosプロトコルに基づく強力な認証（エンタープライズレベルのセキュリティ環境に適しています）。| `PROPERTIES` 句で `KRB5CONF`、`KEYTAB`、`PRINCIPAL` パラメータを指定する必要があります。|

**例：**

* SIMPLE認証のHMS Catalogを作成します。通常認証モードで、Location認証の設定は不要です。

    ```shell
    obclient> CREATE EXTERNAL CATALOG test_hms_catalog
        PROPERTIES = (
        TYPE = 'HMS',
        URI = "thrift://xxx.xxx.xxx.xxx:xxxx"
        );
    ```

* Kerberos認証のHMS Catalogを作成します。

    ```shell
    obclient> CREATE EXTERNAL CATALOG test_hms_catalog_kerberos
        PROPERTIES = (
            TYPE = 'HMS',
            URI = "thrift://xxx.xxx.xxx.xxx:xxxx",
            PRINCIPAL = "hive/xxx@xxx.COM",
            KEYTAB = "/xxx/xxx/xxx/hadoop.keytab",
            KRB5CONF = "/etc/xxx.conf"
        );
    ```

## Location認証

OceanBaseデータベースのHMS Catalogでは、External Locationで鍵を管理し、外部ストレージに安全にアクセスできます。HMSのテーブルにアクセスすると、システムがテーブルのパスに対応するExternal Locationを検索し、見つかった場合はその鍵を使って認証します。

### Location認証のシナリオ

ストレージタイプとセキュリティ要件に基づき、Location認証は以下のシナリオに分類されます：

| **ストレージタイプ** | **認証方式** |
|-------------|---------------|
| OSS         | AK/SK認証。|
| HDFS        | HDFSには以下の認証方式があります：<ul><li>無認証（Kerberosが不要で、HDFSユーザーを指定する必要もありません）。</li><li>ユーザー認証（Kerberosは不要ですが、特定のHDFSユーザーとしてアクセスする必要があります）。</li><li>Kerberos認証あり、HDFSは単一NameNode構成（非HAモード）。</li><li>Kerberos認証あり、HDFSは高可用性（HA）モード。</li><li>Kerberos認証なし、HDFSは高可用性（HA）モード。</li></ul>|

### 手順

1. Location認証シナリオを決定します。

    ストレージタイプとセキュリティ要件に基づいて、対応する認証シナリオを選択します。

2. Locationオブジェクトを作成します。

    `CREATE LOCATION`ステートメントを使用して、対応するシナリオのLocationオブジェクトを作成します。Locationの作成方法の詳細については、[CREATE LOCATION](../../../500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2230.create-location-of-mysql-mode-in-sql.md)を参照してください。

3. Catalogを関連付けます。

    Catalogの作成時に追加の設定は不要です。システムがテーブルのストレージパスに対応するLocationを自動的に選択します。

### Location認証シナリオの設定例

#### OSSストレージ認証

Alibaba CloudのオブジェクトストレージOSSにアクセスするためのLocationオブジェクトを作成します。

```shell
CREATE LOCATION oss_credential
    URL = 'oss://bucket-name/path'
    CREDENTIAL = (
        ACCESSID = 'your-access-key-id'
        ACCESSKEY = 'your-access-key-secret'
        HOST = 'oss-region.aliyuncs.com'
    );
```

#### HDFSストレージ認証

* シナリオ1：無認証モード。

    HDFSクラスタでKerberos認証が無効な開発環境やテスト環境（`hadoop.security.authentication=simple`）では、Locationを作成する必要はありません。

* シナリオ2：ユーザー認証モード。

    Kerberosは不要ですが、特定のHDFSユーザーとしてアクセスする必要があります。

    <main id="notice" type='explain'>
      <h4>説明</h4>
      <p>Kerberos認証が有効になっていないクラスタで、関連するHDFSパスへのアクセスに特定のユーザーの権限が必要な場合に適用されます。</p>
    </main>

    Locationの作成：HDFSユーザーを指定します。

    ```shell
    CREATE LOCATION hdfs_user01
        URL = 'hdfs://namenode:8020/'
        CREDENTIAL (
            USER = 'hdfs_user_name'
        );
    ```

* シナリオ3：Kerberos認証が有効で、HDFSが単一NameNode構成（非HAモード）の場合。

    <main id="notice" type='explain'>
      <h4>説明</h4>
      <p><code>CONFIGS</code>内の<code>dfs.data.transfer.protection</code>は、HDFSクラスタの設定と一致している必要があります。</p>
    </main>

    Locationの作成：Kerberos認証 + 単一NameNode構成のHDFS。

    ```shell
    CREATE LOCATION hdfs_kerberos_single
        URL = 'hdfs://namenode.example.com:8020/'
        CREDENTIAL (
            PRINCIPAL = "hdfs/xxx@xxx.COM",
            KEYTAB = "/data/hdfs.keytab",
            KRB5CONF = "/data/krb5.conf",
            CONFIGS = 'dfs.data.transfer.protection=integrity'
        );
    ```

* シナリオ4：Kerberos認証が有効で、HDFSが高可用性（HA）モードの場合。

    ```shell
    CREATE LOCATION hdfs_kerberos_ha
        URL = 'hdfs://${nameservice id}'
        CREDENTIAL (
            PRINCIPAL = "hdfs/xxx@xxx.COM",
            KEYTAB = "/etc/ob/hdfs.keytab",
            KRB5CONF = "/etc/krb5.conf",
            CONFIGS = 'dfs.data.transfer.protection=${string}#dfs.nameservices=${nameservice id}#dfs.ha.namenodes.${nameservice id}=${namenode1}, ${namenode2}#dfs.namenode.rpc-address.${nameservice id}.${namenode1}=${namenode 1 address}#dfs.namenode.rpc-address.${nameservice id}.${namenode2}=${namenode 2 address}#dfs.ha.automatic-failover.enabled.${nameservice id}=true#dfs.client.failover.proxy.provider.${nameservice id}=org.apache.hadoop.hdfs.server.namenode.ha.ConfiguredFailoverProxyProvider'
            );
    ```

* シナリオ5：Kerberos認証が無効で、HDFSが高可用性（HA）モードの場合。

    <main id="notice" type='explain'>
      <h4>説明</h4>
      <p>Kerberosが無効で、HDFSが高可用性（HA）モードの場合、<code>PRINCIPAL</code>、<code>KEYTAB</code>、および<code>KRB5CONF</code>パラメータの設定は不要です。</p>
    </main>

    ```shell
    CREATE LOCATION hdfs_location_ha
        URL = 'hdfs://${nameservice id}'
        CREDENTIAL (
            CONFIGS = 'dfs.nameservices=${nameservice id}#dfs.ha.namenodes.${nameservice id}=${namenode1}, ${namenode2}#dfs.namenode.rpc-address.${nameservice id}.${namenode1}=${namenode 1 address}#dfs.namenode.rpc-address.${nameservice id}.${namenode2}=${namenode 2 address}#dfs.ha.automatic-failover.enabled.${nameservice id}=true#dfs.client.failover.proxy.provider.${nameservice id}=org.apache.hadoop.hdfs.server.namenode.ha.ConfiguredFailoverProxyProvider'
            );
    ```

## JDBCタイプのExternal Catalogの作成

OceanBaseデータベースV4.4.2 BP4以降では、JDBC Catalogを介してSQL Serverデータベースに接続できます。`CREATE EXTERNAL CATALOG` を実行してSQL Serverへの接続を作成すると、マッピングテーブルを手動で作成することなく、SQL Serverのテーブルやビューを直接クエリできるようになります。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>JDBC Catalogを作成する前に、Java SDK環境をデプロイし、devdeps-java-extensionsのRPMパッケージ（バージョン1.0.6以降）をインストールしてください。分散デプロイ構成では、すべてのOBServerノードでこの手順を実行します。詳細は、<a href="../../../../400.deploy/300.deploy-oceanbase-enterprise-edition/500.deploy-the-ob-java-sdk-environment.md">OceanBaseデータベースのJava SDK環境をデプロイする</a>を参照してください。</p>
</main>

### JDBC Catalogのサポート状況

* 現在のバージョンでは、SQL Serverデータソースへの接続のみをサポートしており、`URL` は `jdbc:sqlserver:` で始まる必要があります。
* JDBC CatalogのオブジェクトとSQL Serverのオブジェクトの対応関係は以下のとおりです：

  | SQL Serverオブジェクト | JDBC Catalogのオブジェクト |
  |-----------------|----------------------|
  | `URL` の `databaseName` で指定されたデータベース | Catalog |
  | スキーマ（例：`dbo`） | データベース |
  | テーブル、ビュー | テーブル |

* JDBC Catalog下のオブジェクトは読み取り専用であり、`INSERT`、`UPDATE`、`DELETE`、`ALTER TABLE`、`DROP TABLE` などの変更ステートメントを実行すると、`this operation in catalog is not supported` エラーが発生します。
* JDBC Catalog内のデータをクエリする際、現在のユーザーには、そのCatalogに対する `USE CATALOG` 権限と `SELECT` 権限の両方が必要です。

### データ型のマッピング

MySQLモードでのSQL ServerとOceanBaseデータベースのデータ型の対応を以下に示します。

| SQL Serverのデータ型 | OceanBaseデータベースのデータ型 |
|---------------------|--------------------------|
| bit | TINYINT(1) |
| tinyint | TINYINT(3) UNSIGNED |
| smallint | SMALLINT(6) |
| int | INT(11) |
| bigint | BIGINT(20) |
| decimal(p,s)、numeric(p,s) | DECIMAL(p,s) |
| smallmoney | DECIMAL(10,4) |
| money | DECIMAL(19,4) |
| real、float(24) | FLOAT |
| float(53) | DOUBLE |
| char(n)、varchar(n)、nchar(n)、nvarchar(n) | VARCHAR(n) |
| varchar(max)、nvarchar(max)、text、ntext | LONGTEXT |
| binary(n)、varbinary(n) | VARBINARY(n) |
| varbinary(max)、image | LONGBLOB |
| date | DATE |
| smalldatetime | DATETIME |
| datetime | DATETIME(3) |
| datetime2(n) | DATETIME(n)（nが6を超える場合はDATETIME(6)） |
| time(n) | TIME(n)（nが6を超える場合はTIME(6)） |

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p><ul>
    <li>SQL Serverでシステム型に基づいて作成されたエイリアス型（例えば <code>CREATE TYPE ... FROM decimal(12, 2)</code>）は、その基底型に従ってマッピングされます。</li>
    <li>マッピングがサポートされていない列（例えば <code>uniqueidentifier</code>、<code>datetimeoffset</code>、および小数部の桁数が30を超える <code>decimal</code> 型の列）は、<code>DESC</code> を実行すると型が <code>UNSUPPORTED</code> と表示されます。クエリでこれらの列が参照されていない場合は正常に実行されますが、<code>SELECT *</code> を実行するか、これらの列を参照すると、<code>Catalog remote column type not supported</code> エラーが発生します。</li>
  </ul></p>
</main>

**例：**

1. JDBC Catalogを作成し、SQL Serverデータベース `sales_db` に接続します。

    ```shell
    obclient> CREATE EXTERNAL CATALOG sqlserver_catalog
        PROPERTIES = (
            TYPE = 'JDBC',
            URL = 'jdbc:sqlserver://xxx.xxx.xxx.xxx:1433;databaseName=sales_db;user=$user_name;password=$password;encrypt=true'
        );
    ```

2. Catalogの作成ステートメントを確認します。

    ```shell
    obclient> SHOW CREATE CATALOG sqlserver_catalog;
    ```

    実行結果は以下のとおりです。`URL`内の接続情報はマスクされて表示されます。

    ```shell
    +-------------------+---------------------------------------------------------------------------------------------------------------------------------+
    | Catalog           | Create Catalog                                                                                                                  |
    +-------------------+---------------------------------------------------------------------------------------------------------------------------------+
    | sqlserver_catalog | CREATE EXTERNAL CATALOG IF NOT EXISTS `sqlserver_catalog`
    PROPERTIES = (
      TYPE = 'JDBC',
      URL = 'jdbc:sqlserver:********'
    ) |
    +-------------------+---------------------------------------------------------------------------------------------------------------------------------+
    ```

3. JDBC Catalogに切り替え、SQL Serverのスキーマ `dbo` 内のテーブルを確認します。

    ```shell
    obclient> SET CATALOG sqlserver_catalog;
    obclient> SHOW TABLES FROM dbo;
    ```

4. SQL Server内のデータをクエリします。

    ```shell
    obclient> SELECT order_id, order_amount FROM dbo.order_info WHERE order_id IN (1, 3);
    ```

    Catalogを切り替えずに、`catalog_name.schema_name.table_name` の形式でSQL Server内のテーブルに直接アクセスすることもできます。

    ```shell
    obclient> SELECT order_id, order_amount FROM sqlserver_catalog.dbo.order_info WHERE order_id IN (1, 3);
    ```
