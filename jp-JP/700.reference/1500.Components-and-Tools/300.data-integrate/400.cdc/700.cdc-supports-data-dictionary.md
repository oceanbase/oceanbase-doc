# obcdcはデータディクショナリをサポートしています

## 機能の紹介

OceanBaseデータベースはV4.1.0.0以降、データディクショナリ機能をサポートしています。データディクショナリはテナントレベルのサービスであり、その機能とは、ログストリーム情報やデータベース・テーブルのメタ情報など、OceanBaseクラスタのテナントのメタ情報をログ（clog）に永続化することです。現段階では主に、データリンク（obcdc）がログのみに依存してテナントのメタ情報を取得できるようにするために利用されています。

データディクショナリはユーザーテナントにのみサービスを提供し、PALFを通じて通常テナントのシステムログストリーム（SYS_LS）に永続化されます。ユーザーテナントが作成されると、データディクショナリサービスは自動的に有効になり、テナントSYS_LSのLEADERコピー上で実行されます。

ログアーカイブサービスが有効になっている場合、非同期データディクショナリ生成タスクが自動的にトリガーされます。OceanBaseデータベースは、テナントレベルの構成パラメータ[dump_data_dictionary_to_log_interval](../../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2300.dump_data_dictionary_to_log_interval.md)（V4.1.0.0以降サポート）および`DBMS_DATA_DICT`システムパッケージ（V4.2.5 BP1以降サポート）を使用して、定期的にデータディクショナリを生成するスケジューリングをサポートしています。データディクショナリの生成スケジューリングには、`DBMS_DATA_DICT`システムパッケージを使用することを推奨します。
<!-- DBMS_DATA_DICTの内容が統合され次第、ジャンプ先のリンクを追加します-->
OceanBaseデータベースはV4.2.0.0以降、DBA/CDBビューを使用してデータディクショナリの生成履歴を記録する機能をサポートしています。システムテナントでは`CDB_OB_DATA_DICTIONARY_IN_LOG`ビューを、通常テナントでは`DBA_OB_DATA_DICTIONARY_IN_LOG`ビューを照会することで、ディクショナリの位置情報を取得できます。

<main id="notice" type='notice'>
   <h4>注意</h4>
   <ul>
   <li><p>テナントのメタ情報の複雑さによって、データディクショナリの生成時間は数秒から数時間まで様々です。構成パラメータを設定する際には、テナントのメタ情報の複雑さを考慮する必要があります。生成サイクルが短すぎると、ディクショナリの生成が頻繁になりすぎ、データディクショナリの生成は単一スレッドタスクであるため、このスレッドが長期間占有されることになります。</p></li>
   <li><p>データディクショナリの生成過程で呼び出されるスキーマサービスは追加のメモリを占有します。テナントのスキーマ数が多くなるか、テナントのメモリ容量が小さい場合、メモリの占有が顕著になります。</p></li>
   </ul>
</main>

## 使用方法

obcdcは、設定ファイル内で`meta_data_refresh_mode`を設定することで、ログ内のデータディクショナリを使用してスキーマ情報を解析するかどうかを選択できます。`online`に設定すると、SchemaServiceを通じてOBServerノードからスキーマ情報を照会することになり、OBServerノードへのアクセスが可能である必要があります。`data_dict`に設定すると、ログ内のデータディクショナリを使用してスキーマ情報を解析することになります。

<main id="notice" type='notice'>
   <h4>注意</h4>
   <p>obcdcは、OceanBaseデータベースV4.2以降のバージョンのデータを同期する際、ユーザー設定を無視して強制的に<code>data_dict</code>モードを使用します。<code>online</code>モードを使用する場合は、<code>skip_ob_version_COMPAT_check</code>構成パラメータを<code>1</code>に変更する必要があります。</p>
</main>

例えば、設定ファイルに以下の内容を追加します。obcdc設定ファイルの詳細については、[設定ファイルの例](200.obcdc-parameters/50.example-configuration-file.md)を参照してください。

```conf
meta_data_refresh_mode=data_dict
```

設定後は、obcdcホストプロセスを再起動する必要があります。例えば、以下のコマンドを使用して起動します：

```shell
[admin@test oceanbase]$ ./bin/obcdc_tailf -f libobcdc.conf -D output.txt
```

ここでは、設定ファイルの相対パスを`libobcdc.conf`とし、obcdc処理後の出力データを`output.txt`ファイルに保存する例を挙げます。設定ファイル名と出力データの保存ファイル名は、実際の状況に応じて置き換える必要があります。`obcdc_tailf`コマンドの詳細については、[obcdc_tailf](300.obcdc-tailf.md)を参照してください。
