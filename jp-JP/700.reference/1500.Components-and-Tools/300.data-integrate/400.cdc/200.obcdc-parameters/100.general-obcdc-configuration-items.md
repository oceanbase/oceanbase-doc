# obcdcの一般的なパラメータ

本記事では、obcdcで一般的に使用されるパラメータとその説明を提供します。すべてのパラメータについては、[obcdc パラメータ説明](../200.obcdc-parameters/200.obcdc-configuration-items.md)を参照してください。

| パラメータ | 機能 | デフォルト値 | 値の範囲 | 説明 |
|-----|-----|-----|-----|---------|
| log_level | obcdcログ | ALL.\*:INFO; PALF.\*:WARN; SHARE.SCHEMA:INFO | 対象外 | ログレベル。モジュールごとに調整可能 |
| max_log_file_count | obcdcログ | 40 | [0, +∞) | 最大保存ログ数。1つのログファイルは256MB |
| rootserver_list | OceanBaseデータベースへの接続 | &#124;  | 対象外 | 起動時にRoot Serviceが配置されているマシン情報を指定する形式：`server_ip:server_rpc_port:server_sql_port`。 |
| cluster_url | OceanBaseデータベースへの接続 | &#124; | 対象外 | obconfig_url。OceanBaseクラスタRS情報のエントリポイント |
| cluster_user | OceanBaseデータベースへの接続 | &#124; | 対象外 | システムテナントのユーザー名（`oceanbase`データベースの読み取り権限が必要） |
| cluster_password | OceanBaseデータベースへの接続 | &#124; | 対象外 | システムテナントのユーザー名に対応するパスワード |
| tenant_endpoint | OceanBaseデータベースへの接続 | &#124; | 対象外 | 一般テナントのマシン情報。形式は`svr_ip:sql_port` |
| tenant_user | OceanBaseデータベースへの接続 | &#124; | 対象外 | テナントユーザー（システムテーブルの読み取り権限が必要） |
| tenant_password | OceanBaseデータベースへの接続 | &#124; | 対象外 | テナントユーザーのパスワード |
| rs_sql_connect_timeout_sec | OceanBaseデータベースへの接続 | 40 | [0, +∞)  | RSマシン（システムテナント）接続タイムアウト時間（online schemaモードではユーザーがSchemaを取得するために使用される） |
| rs_sql_query_timeout_sec | OceanBaseデータベースへの接続 | 30 | [0, +∞)  | RSのSQLリクエストタイムアウト時間 |
| tenant_sql_connect_timeout_sec | OceanBaseデータベースへの接続 | 40 | [0, +∞)  | 一般テナントのマシンへの接続タイムアウト時間 |
| tenant_sql_query_timeout_sec | OceanBaseデータベースへの接続 | 30 | [0, +∞)  | 一般テナントのSQLリクエストタイムアウト時間 |
| fetch_log_rpc_timeout_sec | ログの取得 | 15 | [0, +∞)  | ログ取得タイムアウト時間 |
| cluster_id_black_list | データフィルタリング | &#124; | 対象外 | `ob_org_cluster_id` の値を参照して設定する必要があります。ob_org_cluster_idの詳細については、[ob_org_cluster_id](../../../../800.configuration-items-and-system-variables/200.system-variable/400.session-system-variable/8200.ob_org_cluster_id-session.md)を参照してください。 |
| tb_white_list | データフィルタリング | \*.\*.\* | 対象外 | テーブルのホワイトリストを設定する（テナント.DB.TB。テナントモードでは、同期するテナントを指定する必要があります） |
| tb_black_list | データフィルタリング | &#124; | 対象外 | テーブルのブラックリストを設定する |
| working_mode | 動作モード | storage | {storage, memory} | storageモードでは、REDOログはrocksdbを介してローカルに永続化され、再起動時にローカルストレージはクリアされます |
| fetching_log_mode | 動作モード | integrated | {integrated, direct} | ログ取得モード。integratedはRPCを介してOBServerノードからログを取得することを意味し、directはアーカイブファイルを直接読み取ることを意味します |
| archive_dest | 動作モード | &#124; | 対象外 | `fetching_log_mode`が`direct`モードに設定されている場合にのみ有効になります。obcdcにOceanBaseデータベーステナントのアーカイブパス情報を提供するために使用されます（OSSモードではアクセスキーなどが含まれている必要があります） |
| meta_data_refresh_mode | 動作モード | online | {online, data_dict} | メタデータのソース。onlineモードはSQLを使用して内部テーブルからSchemaを構築することを意味し、data_dictモードはログ内のデータディクショナリからSchemaを構築することを意味します。obcdcがOceanBaseデータベースV4.2以降のバージョンのデータを同期する際、ユーザー設定を無視してdata_dictモードを強制的に使用します。onlineモードを使用する場合は、`skip_ob_version_COMPAT_check`パラメータを`1`に追加で変更する必要があります |
| skip_ob_versionCompatCheck | 動作モード/バージョン互換性 | 0 | {0, 1} | バージョンチェックを無視するかどうかを制御します。値が`1`の場合、バージョンチェックを無視します。一部の高バージョンデータ同期シナリオでは`1`に設定する必要があります（推奨されません） |
| pause_redo_dispatch_task_count_threshold | トラフィック制御 | 80 | [0, 100] | USER_QUEUEまたはRESOURCE_COLLECTORモジュールのタスク数と対応するキュー長の比率を設定します。比率が設定値に達すると、REDOログのレート制限がトリガーされます |
| part_trans_task_active_count_upper_bound | トラフィック制御 | 0 | [0, +∞) | 参加者トランザクションの予想配分上限数。値が`0`の場合、obcdc内部で自動的に調整されます。一部のシナリオでは手動で変更する必要があります。トラフィック制御パラメータの一つで、`memory_limit`（obcdcパラメータ）と同様に厳密に制限されません。そうでない場合、obcdcの同期が停止する可能性があります |
| part_trans_task_reusable_count_upper_bound | トラフィック制御 | 0 | [0, +∞) | 再利用可能な参加者トランザクション（obcdc内部で処理完了後、消費または回収を待つもの）の予想上限数。値が`0`の場合、obcdc内部で自動的に調整されます。一部のシナリオでは手動で変更する必要があります。トラフィック制御パラメータの一つで、`memory_limit`（obcdcパラメータ）と同様に厳密に制限されません。そうでない場合、obcdcの同期が停止する可能性があります |
| part_trans_task_prealloc_page_count | トラフィック制御 | 20000 | [0, +∞) | キャッシュされる参加者トランザクションの上限数。値を大きく設定しすぎると、obcdcのアイドル状態でのメモリ使用量が増加する可能性があります |
| data_start_schema_version | LogRecord出力 | &#124; | 対象外| Schemaバージョンを指定してobcdc内部のSchemaを構築します。形式はtenant_id:schema_versionです。複数のテナントは&#124;で区切ります |
| timezone | LogRecord出力 | +8:00 | 時差値 | ローカルタイムゾーンを使用して書き込まれた時刻データを処理するために使用されます。OBServerノードマシンが使用するローカルタイムゾーンと一致させる必要があります。一部のデータが書き込み時にセッションでタイムゾーンを指定している場合、obcdcの出力がユーザーが書き込んだデータと一致するようにするには、このパラメータをセッションで指定されたタイムゾーンに設定する必要があります |
| timezone_info_fpath | LogRecord出力 | `etc/timezone_info.conf` | 対象外 | タイムゾーンファイルのパス |
| enable_hbase_mode | LogRecord出力 | 0 | {0, 1} | 同期するテーブルにHBaseモードのテーブルがある場合は、この設定を有効にする必要があります |
| enable_compatible_charset | LogRecord出力 | 0 | {0, 1} | 出力されるcharsetがDRCの使用法と互換性があるかどうかを制御します |
| enable_convert_timestamp_to_unix_timestamp | LogRecord出力 | 0 | {0, 1} | timestampをunixタイムスタンプに変換するかどうかを制御します。MySQLモードで有効です |
| enable_oracle_mode_match_case_sensitive | LogRecord出力 | 0 | {0, 1} | Oracleモードのテナントのホワイトリストとブラックリストの照合を大文字小文字区別でサポートするかどうか |
| enable_output_by_table_def | LogRecord出力 | 0 | {0, 1} | ユーザー定義の列順序で列を出力するかどうかを制御します |
| enable_output_hidden_primary_key | LogRecord出力 | 0 | {0, 1} | 隠れた主キーを出力するかどうかを制御します |
| enable_output_invisible_column | LogRecord出力 | 0 | {0, 1} | 非表示列を出力するかどうかを制御します |
