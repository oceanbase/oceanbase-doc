# obcdcの一般的な構成パラメータ

本記事では、obcdcで一般的に使用される構成パラメータとその説明を提供します。すべての構成パラメータについては、[obcdc構成パラメータの説明](../200.obcdc-parameters/200.obcdc-configuration-items.md)を参照してください。

| パラメータ | 機能 | デフォルト値 | 値の範囲 | 説明 |
|-----|-----|-----|-----|---------|
| log_level | obcdcログ | ALL.\*:INFO; PALF.\*:WARN; SHARE.SCHEMA:INFO | 対象外 | ログレベルで、モジュールごとに調整可能 |
| max_log_file_count | obcdcログ | 40 | [0, +∞) | 保存するログファイルの最大数。1つのログファイルは256MB |
| rootserver_list | OceanBaseデータベースへの接続 | &#124;  | 対象外 | 起動時にRoot Serviceが存在するマシン情報を指定します。形式：`server_ip:server_rpc_port:server_sql_port`。 |
| cluster_url | OceanBaseデータベースへの接続 | &#124; | 対象外 | obconfig_url。OceanBaseクラスタRS情報へのエントリポイント |
| cluster_user | OceanBaseデータベースへの接続 | &#124; | 対象外 | システムテナントユーザー名（`oceanbase`データベースの読み取り権限あり） |
| cluster_password | OceanBaseデータベースへの接続 | &#124; | 対象外 | システムテナントユーザー名に対応するパスワード |
| tenant_endpoint | OceanBaseデータベースへの接続 | &#124; | 対象外 | 一般テナントのマシン情報。形式は`svr_ip:sql_port` |
| tenant_user | OceanBaseデータベースへの接続 | &#124; | 対象外 | テナントユーザー（システムテーブルの読み取り権限あり） |
| tenant_password | OceanBaseデータベースへの接続 | &#124; | 対象外 | テナントユーザーのパスワード |
| rs_sql_connect_timeout_sec | OceanBaseデータベースへの接続 | 40 | [0, +∞)  | RSマシン（システムテナント）の接続タイムアウト時間（online schemaモードではユーザーがSchemaを取得するために使用されます） |
| rs_sql_query_timeout_sec | OceanBaseデータベースへの接続 | 30 | [0, +∞)  | RSのSQLリクエストタイムアウト時間 |
| tenant_sql_connect_timeout_sec | OceanBaseデータベースへの接続 | 40 | [0, +∞)  | 一般テナントのマシンへの接続タイムアウト時間 |
| tenant_sql_query_timeout_sec | OceanBaseデータベースへの接続 | 30 | [0, +∞)  | 一般テナントのSQLリクエストタイムアウト時間 |
| fetch_log_rpc_timeout_sec | ログ取得 | 15 | [0, +∞)  | ログ取得のタイムアウト時間 |
| cluster_id_black_list | データフィルタリング | &#124; | 対象外 | `ob_org_cluster_id`の値を参照して設定します。ob_org_cluster_idの詳細については、[ob_org_cluster_id](../../../../800.configuration-items-and-system-variables/200.system-variable/400.session-system-variable/8200.ob_org_cluster_id-session.md)を参照してください |
| tb_white_list | データフィルタリング | \*.\*.\* | 対象外 | テーブルのアローリストを設定します（テナント.DB.TB。テナントモードでは、同期する必要があるテナント部分を指定する必要があります） |
| tb_black_list | データフィルタリング | &#124; | 対象外 | テーブルのブラックリストを設定します |
| working_mode | 動作モード | storage | {storage, memory} | storageモードでは、REDOログはrocksdbを介してローカルに永続化され、再起動時にローカルストレージはクリアされます |
| fetching_log_mode | 動作モード | integrated | {integrated, direct} | ログ取得モード。integratedはRPCを介してOBServerノードからログを取得することを意味し、directはアーカイブファイルを直接読み取ることを意味します |
| archive_dest | 動作モード | &#124; | 対象外 | `fetching_log_mode`が`direct`モードに設定されている場合にのみ有効になります。obcdcにOceanBaseデータベーステナントのアーカイブパス情報を提供するために使用されます（OSSモードではアクセスキーなどを含む必要があります） |
| meta_data_refresh_mode | 動作モード | online | {online, data_dict} | メタデータソース。onlineモードはSQLによる内部テーブルの読み込みでスキーマを構築することを示し、data_dictモードはログ内のデータディクショナリによるスキーマの構築を示します。obcdcがOceanBaseデータベースV4.2以降のバージョンのデータを同期する際、ユーザー設定を無視して強制的にdata_dictモードを使用します。onlineモードを使用する場合は、`skip_ob_version_compat_check`パラメータを`1`に変更する必要があります。 |
| skip_ob_version_compat_check | 動作モード/バージョン互換性 | 0 | {0, 1} | バージョンチェックを無視するかどうかを制御します。値が`1`の場合、バージョンチェックを無視します。一部の高バージョンデータ同期シナリオでは`1`に設定する必要があります（推奨されません）。 |
| pause_redo_dispatch_task_count_threshold | フロー制御 | 80 | [0, 100] | USER_QUEUEまたはRESOURCE_COLLECTORモジュールのタスク数と対応するキュー長の比率を設定します。比率が設定値に達した場合、REDOログの送信制限がトリガーされます。 |
| part_trans_task_active_count_upper_bound | フロー制御 | 0 | [0, +∞) | 予想される参加者トランザクション数の上限。値が`0`の場合、obcdc内部で自動調整されます。一部のシナリオでは手動で変更する必要があります。フロー制御パラメータの一つであり、`memory_limit`(obcdcパラメータ)と同様に厳密に制限されません。そうでない場合、obcdc同期が停止します。 |
| part_trans_task_reusable_count_upper_bound | フロー制御 | 0 | [0, +∞) | 予想される再利用可能な参加者トランザクション(つまり、obcdc内部で処理完了後に消費または回収されるもの)数の上限。値が`0`の場合、obcdc内部で自動調整されます。一部のシナリオでは手動で変更する必要があります。フロー制御パラメータの一つであり、`memory_limit`(obcdcパラメータ)と同様に厳密に制限されません。そうでない場合、obcdc同期が停止します。 |
| part_trans_task_prealloc_page_count | フロー制御 | 20000 | [0, +∞) | キャッシュされる参加者トランザクションの上限。値を大きくすると、obcdcのアイドル期間中のメモリ使用量が増加する可能性があります。 |
| data_start_schema_version | LogRecord出力 | &#124; | 対象外 | obcdc内部のスキーマを構築するためのスキーマバージョンを指定します。書式はtenant_id:schema_versionで、複数のテナントは&#124;で区切ります。 |
| timezone | LogRecord出力 | +8:00 | 時間オフセット値 | ローカルタイムゾーンを使用して書き込まれる時間データを処理するために使用されます。OBServerノードマシンで使用されるローカルタイムゾーンと一致させる必要があります。一部のデータが書き込みセッションでタイムゾーンを指定している場合、obcdcの出力がユーザーが書き込んだデータと一致するようにするには、この構成パラメータをセッションで指定されたタイムゾーンに設定する必要があります。 |
| timezone_info_fpath | LogRecord出力 | `etc/timezone_info.conf` | 対象外 | タイムゾーンファイルのパス |
| enable_hbase_mode | LogRecord出力 | 0 | {0, 1} | 同期するテーブルにHBaseモードのテーブルがある場合、この構成を有効にする必要があります。 |
| enable_compatibleCharsets | LogRecord出力 | 0 | {0, 1} | 出力されるcharsetがDRCの使用法と互換性があるかどうかを制御します。 |
| enable_convert_timestamp_to_unix_timestamp | LogRecord出力 | 0 | {0, 1} | timestampをunixタイムスタンプに変換するかどうかを制御します。MySQLモードで有効です。 |
| enable_oracle_mode_match_case_sensitive | LogRecord出力 | 0 | {0, 1} | Oracleモードのテナントのアローリストおよびブラックリストを大文字と小文字を区別してマッチングするかどうかをサポートします。 |
| enable_output_by_table_def | LogRecord出力 | 0 | {0, 1} | ユーザー定義の列順序に従って列を出力するかどうかを制御します。 |
| enable_output_hidden_primary_key | LogRecord出力 | 0 | {0, 1} | 隠れた主キーを出力するかどうかを制御します |
| enable_output_invisible_column | LogRecord出力 | 0 | {0, 1} | 非表示列を出力するかどうかを制御します |
