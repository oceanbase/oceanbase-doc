# 単一テナントのバックアップ設定を更新する

本記事では、APIを使用して単一テナントのバックアップ設定を更新する方法について説明します。

## 呼び出しの概要

### インターフェース制約

パスワードが設定されている場合は、認証が必要です。詳細については、[APIハイブリッド暗号化](../20.api-hybrid-encryption.md)を参照してください。

### リクエストパス

PATCH /api/v1/tenant/:name/backup/config

### リクエストパラメータ

| パラメータ | 型 | 必須 | サンプル値 | 説明 |
|-------|-----|-----|------|--------|
| data_base_uri | string | いいえ | "file:///data/backup/data" | データバックアップファイルのパス。設定後、データバックアップファイルはこのパス配下に保存されます。 |
| archive_base_uri | string | いいえ | "file:///data/backup/clog" | ログアーカイブファイルのパス。設定後、ログアーカイブファイルはこのパス配下に保存されます。 |
| log_archive_concurrency | int | いいえ | 0 | ログアーカイブの総ワーカースレッド数を設定します。デフォルト値は0、値の範囲は[0, 100]です。 |
| binding | string | いいえ | "optional" | アーカイブとビジネスの優先モードを設定します。現在、`optional`（ユーザービジネス優先）と`mandatory`（アーカイブ優先）をサポートしています。設定しない場合、デフォルトはOptionalモードです。この項目を設定する場合は、`archive_base_uri`も設定する必要があります。 |
| ha_low_thread_score | int | いいえ | 0 | バックアップ、バックアップクリーンアップなどの高可用性低優先順位タスクの現在のワーカースレッド数を指定します。バックアップ開始前に、このパラメータの値を適宜引き上げることができ、推奨は毎回値を倍増させることです。デフォルト値は0、値の範囲は[0, 100]です。 |
| piece_switch_interval | string | いいえ | 1d | pieceの切り替え周期を設定します。設定しない場合、デフォルトは1d、値の範囲は[1d, 7d]です。この項目を設定する場合は、`archive_base_uri`も設定する必要があります。 |
| archive_lag_target | string | いいえ | 7200s | テナントのログアーカイブの遅延時間を制御します。デフォルトは2分で、前後のアーカイブI/Oの最大間隔を指定するために使用されます。値の範囲は[0ms, 7200s]です。 |
| delete_policy | DeletePolicy | いいえ | {<br>"delete_policy": "{<br>"policy": "default",<br>"recovery_window": "7d",<br>},<br>} | バックアップ成功後、ビジネスニーズに応じてテナントにクリーンアップポリシーを設定できます。クリーンアップポリシーを設定したテナントは、毎時1回自動クリーンアップがトリガーされ、期限切れのバックアップが適時にクリーンアップされます。設定における各値の意味は以下の通りです：<ul><li>`policy`：オプション値で、ポリシー名を設定するために使用されます。現在、`default`のみをサポートしています。</li><li>`recovery_window`：オプション値で、ウィンドウ時間を設定します。現在時刻から、ウィンドウ内のデータは復元可能であることを保証します。</li></ul>  |

単一テナントバックアップ設定の更新における使用方法と [単一テナントバックアップ設定の設定](100.configure-backup-configuration-for-a-single-tenant.md) の違いは、`data_base_uri` と `archive_base_uri` を設定しなくてもよい点です。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p><code>binding</code> と <code>piece_switch_interval</code> を設定する場合でも、<code>archive_base_uri</code> は設定する必要があります。これら3つは紐づけられており、増分設定はサポートされていないためです。</p>
</main>

### 戻り値

| パラメータ | 型 | 説明 |
|-------|-------|------|
| successful | bool | リクエストが成功したかどうか。 |
| timestamp | time.Time | サーバーがリクエストを完了したタイムスタンプ。 |
| duration | int | サーバーがリクエストを処理した時間（ミリ秒）。 |
| status | int | HTTP Status仕様に準拠したエンコード。 |
| traceId | string | リクエストのTrace ID。 |
| data | DagDetailDTO | 非同期タスク情報。詳細は以下の **DagDetailDTO 情報のデータ構造** を参照してください。 |
| error | ApiError | リクエストによって生成されたError。以下の情報を含みます：<ul><li>`code`：エラーコード。</li><li>`message`：エラーの詳細情報。</li><li>`subErrors`：サブエラー情報。</li></ul> |

DagDetailDTOの情報データ構造は以下のとおりです：

| パラメータ | 型 | 説明 |
| --- | --- | --- |
| id | string | DAG共通ID。 |
| dag_id | int | DAG id。OceanBaseデータベースに記録される主キーです。 |
| name | string | DAG名。 |
| stage | int | DAGの現在の実行段階。 |
| max_stage | int | DAG実行プロセス中の総段階数。 |
| state | string | DAG実行状態。 |
| operator | string | DAG実行操作タイプ。 |
| start_time | time.Time | DAG実行開始時間。 |
| end_time | time.Time | DAG実行終了時間。 |
| additional_data | map[string]any | DAGその他のデータ。 |
| nodes | []NodeDetailDTO | DAG内のすべてのNode情報。[Nodeの詳細情報を取得する](../1000.task-management/2100.get-node-detail.md)を参照してください。 |

## 例

### リクエスト例

PATCH 10.10.10.1:2886/api/v1/tenant/t1/backup/config

```json
{
  "data_base_uri":"file:///data/backup/tenant/data",
  "archive_base_uri":"file:///data/backup/tenant/archive",
  "log_archive_concurrency":100,
  "binding":"Mandatory",
  "ha_low_thread_score":35,
  "piece_switch_interval":"6d",
  "archive_lag_target":"2h",
  "delete_policy":
  {
    "policy":"",
    "recovery_window":"5d"
  }
}
```
