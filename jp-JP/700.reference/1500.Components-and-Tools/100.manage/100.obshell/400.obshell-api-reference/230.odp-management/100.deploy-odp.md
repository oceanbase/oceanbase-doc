# OBProxyのデプロイ

本記事では、obshellを使用してOBProxy（OceanBaseデータベースプロキシ、ODPとも呼ばれる）をデプロイする方法について説明します。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <ul>
  <li><p>現在、OBProxy V4.1.0.0以降のバージョンのみサポートされています。</p></li>
  <li><p>このAPIはobshell V4.2.6からサポートされています。</p></li>
  </ul>
</main>

## 呼び出しの説明

### インターフェース制約

* 当ノードにはagent_passwordが設定されている必要があります。詳細については、[ノードのパスワードの設定](../100.obshell-management/1500.set-node-password.md)を参照してください。
* obshell ServerはこのAPIに対してセキュリティ検証を行います。詳細については、[APIの混合暗号化](../20.api-hybrid-encryption.md)を参照してください。
* このobshellがOBProxyサービスを管理していないことが要求されます。
* OBProxyインストールパッケージが解凍され、作業ディレクトリにインストールされていることが要求されます。

### リクエストパス

POST /api/v1/obproxy

### リクエストパラメータ

| パラメータ | 型 | 必須 | サンプル値 | 説明 |
|------|------|------|-------|------|
| name | string | いいえ | myobproxy | デプロイされるOBProxyサービス名。 |
| home_path | string | はい | /home/admin/obproxy | OBProxyの作業ディレクトリです。このディレクトリに対する読み書き権限が付与されていることを確認してください。 |
| sql_port | int | いいえ | 2883 | OBProxy SQLポート。 |
| exporter_port | int | いいえ | 2884 | OBProxy Exproterポート。 |
| rpc_port | int | いいえ | 2885 | OBProxy RPCサービスのリスニングポート。 |
| proxyro_password | string | いいえ | ******* | 対応するクラスタ内のproxyro@sysユーザーのパスワード。 |
| obproxy_sys_password | string | いいえ | ******* | root@proxysysのパスワード。 |
| rs_list | string | いいえ | 10.10.10.1:2881;10.10.10.2:2881 | 対応するクラスタのRoot Serviceリストです。設定後、OBProxyを使用して対応するOceanBaseクラスタをプロキシできますが、このクラスタのみをプロキシできます。 |
| config_url | string | いいえ | http://10.10.10.1:8080/services?Action=GetObProxyConfig | obconfigserverのURLです。設定後、OBproxyを使用してobconfigserverに登録されたすべてのクラスタをプロキシできます。 |
| parameters | map[string]string | いいえ | {</br>"server_tcp_keepidle": "5",</br>"enable_strict_kernel_release": "false"</br>} | OBProxyの構成パラメータ。 |

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>リクエストパラメータでは、<code>rs_list</code>と<code>config_url</code>を同時に指定することはできません。指定した場合、エラーが発生します。<code>rs_list</code>と<code>config_url</code>がどちらも指定されていない場合、obshellノードがOceanBaseクラスタを管理している場合、デプロイされたOBProxyはそのクラスタへの自動関連付けを試みます。</p>
</main>

### 実行結果

| パラメータ | 型 | 説明 |
|--------|-----|------|
| successful | bool | リクエストが成功したかどうかを示します。 |
| timestamp | time.Time | サーバーがリクエストを完了したタイムスタンプです。 |
| duration | int | サーバーがリクエストを処理した時間（ミリ秒）です。 |
| status | int | HTTPステータスコードに準拠したエンコードです。 |
| traceId | string | リクエストのTrace IDです。 |
| data | DagDetailDTO | 詳細は以下の**DagDetailDTOデータ構造**を参照してください。 |
| error | ApiError | リクエストで発生したErrorで、以下の情報を含みます：<ul><li>`code`：エラーコード。</li><li>`message`：エラーの詳細情報。</li><li>`subErrors`：サブエラー情報。</li></ul> |

DagDetailDTO情報のデータ構造は以下のとおりです。

| パラメータ | 型 | 説明 |
| --- | --- | --- |
| id | string | DAG共通ID。 |
| dag_id | int | DAG ID。OceanBaseデータベースに記録される主キーです。 |
| name | string | DAG名。 |
| stage | int | DAGの現在の実行段階。 |
| max_stage | int | DAG実行プロセス中の段階総数。 |
| state | string | DAGの実行状態。 |
| operator | string | DAG実行操作タイプ。 |
| start_time | time.Time | DAG実行開始時間。 |
| end_time | time.Time | DAG実行終了時間。 |
| additional_data | map[string]any | DAGその他のデータ。 |
| nodes | []NodeDetailDTO | DAG内のすべてのノード情報。[ノードの詳細情報を取得する](../1000.task-management/2100.get-node-detail.md)を参照してください。 |

## 例

### リクエスト例

POST 10.10.10.1:2886/api/v1/obproxy

この例では、`10.10.10.1:2886`ノードに対してOBProxyのデプロイリクエストを送信し、OBProxyがrs_listモードでクラスタに関連付けられるようにします（Root Serviceリストは`10.10.10.1:2881;10.10.10.2:2881;10.10.10.3:2881`です）。実際の状況に応じて、この例を変更することができます。

```json
{
    "home_path": "/data/obproxy",
    "name": "myobproxy",
    "sql_port": 2883,
    "exporter_port": 2884,
    "rpc_port": 2885,
    "rs_list": "10.10.10.1:2881;10.10.10.2:2881;10.10.10.3:2881",
    "proxyro_password": "********",
    "obproxy_sys_password": "********",
    "parameters": {
        "server_tcp_keepidle": "5",
        "enable_strict_kernel_release": "false"
    }
}
```
