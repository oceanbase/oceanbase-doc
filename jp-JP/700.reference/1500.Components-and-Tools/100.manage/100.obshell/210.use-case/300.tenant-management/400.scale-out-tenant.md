# テナントのスケールアウト

obshellでは、以下の2つの方法でテナントを拡張できます：

- APIを呼び出して拡張する

- obshellコマンドを使用して拡張する

本記事では、3レプリカのOceanBaseクラスタを例に、obshellを使用してテナントを拡張する方法（3レプリカから5レプリカへの拡張）を説明します。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>本記事で言うテナントの拡張とは、新しいテナントレプリカを追加することを指します。</p>
</main>

## 前提条件

- OceanBaseクラスタがobshellによって運用・管理されていること。詳細な判断方法および乗っ取り操作については、[obshell以外でデプロイされたクラスタの乗っ取り](../200.cluster-management/300.take-over-non-obshell-deployed-clusters.md)を参照してください。

- OceanBaseクラスタのすべてのOBServerノードとobshellが正常に動作していること。

## デプロイメントモード

本記事で使用される3台のマシンの構成は以下のとおりです（obshellはデフォルトポート2886を使用）：

| ロール | マシン | 備考 |
| --- | --- | --- |
| OBServerノード | 10.10.10.1 | OceanBaseデータベース zone1 |
| OBServerノード | 10.10.10.2 | OceanBaseデータベース zone2 |
| OBServerノード | 10.10.10.3 | OceanBaseデータベース zone3 |
| スケールアウト用OBServerノード | 10.10.10.4 | スケールアウト後、OceanBaseデータベース zone4に配置 |
| スケールアウト用OBServerノード | 10.10.10.5 | スケールアウト後、OceanBaseデータベース zone5に配置 |

## APIを使用した拡張

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>obshellは呼び出されるAPIに対してセキュリティ検証を実施します。そのため、APIを呼び出すたびに、<a href='../../400.obshell-api-reference/20.api-hybrid-encryption.md'>API混合暗号化</a>を参照してリクエストを暗号化し、curlコマンドで暗号化されたリクエストヘッダー(<code>${request_headers}</code>)とリクエストボディ(<code>${request_body}</code>)を設定する必要があります。</p>
</main>

### ステップ1：クラスタの拡張

[OceanBaseクラスタの拡張](../200.cluster-management/400.scale-out-oceanbase-cluster.md)を参照して、`10.10.10.4`と`10.10.10.5`をそれぞれ`zone4`と`zone5`に拡張します。

### ステップ2：新しいテナントレプリカの追加

任意のobshellの`POST /api/v1/tenant/:name/replicas`インターフェースを呼び出して、テナント`tenant1`を拡張します。

:::tab

tab コマンドラインコマンド

コマンドラインで対応するAPIインターフェースを呼び出す方法については、関連ドキュメントを参照してください。このインターフェースは非同期タスクを作成します。タスクの進捗状況を確認する方法については、[タスクの詳細情報を取得する](../../400.obshell-api-reference/1000.task-management/2000.get-dag-detail.md)を参照してください。タスクが完了すると、テナントレプリカの追加は終了します。

```shell
[admin@test001 ~]$ curl -H "Content-Type: application/json" -H 'X-OCS-Header:${request_headers}' -X POST -d '${request_body}' http://10.10.10.1:2886/api/v1/tenant/tenant1/replicas
```

暗号化前のリクエストボディの内容は以下のとおりです。`unit_1`はテナント`tenant1`が使用するリソース仕様です。新しいリソースユニットを作成したい場合は、ドキュメント[テナントの作成](100.create-tenant-use-obshell.md)の**手順1：リソース仕様の作成**を参照してください。

```shell
{
    "zone_list": [
        {
            "name": "zone4",
            "unit_config_name": "unit_1",
            "unit_num": 1
        }，
        {
            "name": "zone5",
            "unit_config_name": "unit_1",
            "unit_num": 1
        }
    ]
}
```

## obshellコマンドによるスケールアウト

### ステップ1：クラスタのスケールアウト

[OceanBaseクラスタのスケールアウト](../200.cluster-management/400.scale-out-oceanbase-cluster.md)を参照し、`10.10.10.4`と`10.10.10.5`をそれぞれ`zone4`および`zone5`にスケールアウトします。

### ステップ2：新規テナントレプリカの追加

任意のノードで以下のコマンドを実行することで、テナント`tenant1`の`zone4`および`zone5`へのレプリカを追加できます。コマンドの詳細については、[obshell テナントコマンドグループ](../../300.obshell-clients/250.tenant-commands.md)の**obshell tenant replica add**のセクションを参照してください。

```shell
[admin@test001 ~]$ /home/admin/oceanbase/bin/obshell tenant replica add tenant1 -z zone4,zone5 -u unit_1
```

例における`unit_1`はテナント`tenant1`が使用するリソース構成であり、実際の状況に応じて設定する必要があります。新しいリソースユニットを作成したい場合は、ドキュメント[テナントの作成](100.create-tenant-use-obshell.md)の**ステップ1：リソース構成の作成**を参照してください。

### ステップ3：テナント情報の確認

任意のノードで以下のコマンドを実行することで、指定されたテナントの情報を確認できます。コマンドの詳細については、[obshell テナントコマンドグループ](../../300.obshell-clients/250.tenant-commands.md)の**obshell tenant show**のセクションを参照してください。

```shell
[admin@test001 ~]$ /home/admin/oceanbase/bin/obshell tenant show tenant1
```
