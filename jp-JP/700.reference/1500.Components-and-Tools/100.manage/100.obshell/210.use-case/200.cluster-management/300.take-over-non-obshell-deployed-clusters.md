# obshellによる非obshellデプロイメントクラスタの引き継ぎ

obshellによる非obshellデプロイメントのOceanBaseクラスタの引き継ぎには、2つの方法があります。

- SDKメソッドによる引き継ぎ

- obshellコマンドによる引き継ぎ

本記事では、OCPでデプロイされた3レプリカのOceanBaseクラスタを例に、obshellを使用してOceanBaseクラスタを引き継ぐ方法について説明します。OceanBaseクラスタがどのような状態であっても、obshellによる引き継ぎは可能です。

## デプロイメントモード

本記事では、3台のマシンを使用する場合の状況は以下のとおりです：

| ロール | マシン | 備考 |
| --- | --- | --- |
| OBServerノード | 10.10.10.1 | OceanBaseデータベースzone1 |
| OBServerノード | 10.10.10.2 | OceanBaseデータベースzone2 |
| OBServerノード | 10.10.10.3 | OceanBaseデータベースzone3 |

## SDKメソッドによるオーバーテイク

:::tab

tab Python

例は以下のとおりです。obshell-sdk-pythonを使用してクラスタを引き継ぐ方法については、[クラスタの引き継ぎ](../../500.obshell-sdk-reference/100.python/200.cluster-management/900.takeover-cluster-of-python.md)を参照してください。

```python
from obshell import takeover, NodeConfig

def init_nodes():
    ips = [
        "10.10.10.1",
        "10.10.10.2",
        "10.10.10.3",
    ]
    work_dir = "/data/ob" # OceanBaseデータベースの作業ディレクトリ
    nodes_config = []
    for _, ip in enumerate(ips):
        node = NodeConfig(ip, work_dir)
        nodes_config.append(node)

    takeover("pwd", nodes_config) # pwd は引き継がれるクラスタのroot@sysユーザーのパスワードを表します。実際のパスワードに置き換える必要があります。
```

tab GO

例は以下のとおりです。obshell-sdk-goを使用してクラスタを引き継ぐ方法については、[クラスタの引き継ぎ](../../500.obshell-sdk-reference/200.go/200.cluster-management/900.takeover-cluster-of-go.md)を参照してください。

```go
func main() {
    ips := []string{
        "10.10.10.1",
        "10.10.10.2",
        "10.10.10.3",
    }

    workDir := "/data/ob" // OceanBaseデータベースの作業ディレクトリ
    nodeConfigs := make([]util.NodeConfig, 0)
    for _, ip := range ips {
        nodeConfigs = append(nodeConfigs, util.NewNodeConfig(ip, workDir, 2886))
    }

    // pwd は引き継がれるクラスタのroot@sysユーザーのパスワードを表します。実際のパスワードに置き換える必要があります。
    if err := util.Takeover("pwd", nodeConfigs...); err != nil {
        panic(err)
    }
}
```

## obshellコマンドによるクラスタの引き継ぎ

### ステップ1：パスワード環境変数を設定する

現在のOceanBaseクラスタのsysテナントのrootユーザーにパスワードが設定されている場合、任意のOBServerノードで以下のコマンドを実行して、obshellがパスワードを取得できるようにします。ここでは、`10.10.10.1` ノードで実行する例を示します。`pwd` は引き継がれるクラスタのroot@sysユーザーのパスワードを表し、実際のパスワードに置き換える必要があります。

```shell
[admin@test001 ~]$ export OB_ROOT_PASSWORD="pwd"
```

### ステップ2：クラスタの引き継ぎ

**ステップ1** のノード（`10.10.10.1`）で以下のコマンドを実行することで、現在のOceanBaseクラスタ内の各OBServerノードに属するobshellを起動し、引き継ぎを実行できます。obshellは、OceanBaseデータベースのインストールディレクトリの `bin` ディレクトリ内にあり（`/home/admin/oceanbase/bin/obshell`）、詳細なコマンドについては [obshell cluster start](../../300.obshell-clients/200.cluster-commands.md) を参照してください。

```shell
[admin@test001 ~]$ /home/admin/oceanbase/bin/obshell cluster start -a
```

## 引き継ぎが成功したかどうかを確認する

任意のobshellの `/api/v1/ob/info` インターフェースを呼び出すと、`agent_info` 内の `identity` が `CLUSTER AGENT` である場合、現在のOceanBaseクラスタはobshellによって運用されています。インターフェースの詳細については、[OceanBase情報のクエリ](../../400.obshell-api-reference/200.cluster-management/1800.get-oceanbase-info.md) を参照してください。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>obshellは呼び出されたAPIに対してセキュリティ検証を行います。そのため、APIを呼び出す前に、<a href='../../400.obshell-api-reference/20.api-hybrid-encryption.md'>APIハイブリッド暗号化</a> に記載されている方法でリクエストを暗号化し、curlコマンドに暗号化済みのリクエストヘッダー（<code>${request_headers}</code>）とリクエストボディ（<code>${request_body}</code>）を設定する必要があります。</p>
</main>

  ```shell
  [admin@test001 ~]$ curl -H 'X-OCS-Header:${request_headers}' -X GET http://10.10.10.1:2886/api/v1/ob/info
  ```
