# 復元の開始

obshell Dashboardでは、バックアップ済みのテナントの復元を開始できます。以下の2つの方法で復元を開始できます：

+ **方法1**：obshell Dashboardにログインし、**テナント管理**ページに移動して、右上の**復元の開始**をクリックします。

+ **方法2**：obshell Dashboardにログインし、**テナント管理**ページに移動して、テナントリストから対象のテナント名をクリックします。**概要**ページに移動したら、左側のナビゲーションバーの**バックアップ・リカバリ**をクリックして**バックアップ・リカバリ**ページに移動し、ページ右上の**復元の開始**をクリックします。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>方法1は、<b>テナント管理</b>のグローバルページから復元を開始するもので、復元時にストレージ構成の入力または変更が必要です。方法2は、テナントリストから選択した対象テナントから復元を開始するもので、復元時にはそのテナントのバックアップストレージ構成を再利用でき、ストレージ構成の入力や変更は不要です。</p>
</main>

## 手順

以下の手順では、**エントリー1** を例に説明します。

1. obshell Dashboardにログインします。

2. 左側のナビゲーションバーで **テナント管理** をクリックします。

3. ページの右上にある **復元を開始** をクリックして、**復元を開始** ページに移動します。

4. グローバルページで復元を開始する際には、復元対象のバックアップ済みファイルのストレージ設定を入力する必要があります（この手順は **エントリー1** のみで設定が必要です）。

5. 入力または変更が完了したら、**テスト** をクリックします。

   <main id="notice" type='explain'>
     <h4>説明</h4>
     <p><b>テスト</b> をクリックすると、obshellは復元対象のバックアップ済みファイルのストレージ設定をテストします。テストが成功すると、<b>復元元情報欄</b> に対応する復元元テナント名が表示されます。テストに失敗した場合はエラーが表示されますので、正しいストレージ設定を入力してください。</p>
   </main>

   <!-- ![ストレージ設定](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.4.1/obshell/V4.3.2/300.Initiate-restoration-01.png) -->

6. **復元元情報** を入力します。復元日は、表示されている復元可能な時間帯内である必要があります。復元可能な時間範囲を確認するには、ツール統合パッケージである oceanbase-ce-utils をインストールしてください。これにより、システムがバックアップセット関連情報を解析できるようになります。詳細なインストール操作については、[ob_admin インストール](../../../../200.ob-admin/100.overview-of-ob-admin.md)を参照してください。復元日時を指定しない場合、デフォルトで最新のポイントまで復元されます。

   <!-- ![復元元情報](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.4.1/obshell/V4.3.2/300.Initiate-restoration-04.png) -->

7. **復元先情報** を入力します。

   <!-- ![復元先情報](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.4.1/obshell/V4.3.2/300.Initiate-restoration-03.png) -->

   | パラメータ  | 説明  |
   |-------|------|
   | ターゲットテナント | テナント名をカスタム設定してください。テナント名は既存のテナントと重複してはなりません。システムはここで指定されたテナント名に基づいて対応するテナントを作成し、バックアップ内容をそのテナントに復元します。 |
   | 各ゾーンのUnit数 | 各ゾーンのUnit数を設定してください。ゾーン内の最小OBServer数によって、Unitの最大設定可能数が決まります。 |
   | レプリカタイプ | 値の範囲：<ul><li>フル機能レプリカ：現在サポートされている一般的なレプリカで、トランザクションログ、MemTable、SSTableなど、すべての完全なデータと機能を備えています。いつでも迅速にリーダーに切り替えて外部へのサービス提供が可能です。</li><li>読み取り専用レプリカ：完全なログ、MemTable、SSTableなどを含みます。業務上、データ読み取りの一貫性に対する要求が高くない場合に選択することを推奨します。</li></ul> |
   | Unit仕様 | このUnitが占用するリソース仕様です。現在設定可能な範囲内の値を手動で入力できます。 |
   | Unit数 | 各ゾーンのUnit数を表示します。<main id="notice" type='explain'><h4>説明</h4><p>Unit数は <b>各ゾーンのUnit数</b> の設定と一致し、変更はできません。</p></main>  |
   | ゾーン優先順位 | テナントのリーダーレプリカに優先順位を指定します。最も優先順位の高いゾーンがプライマリゾーンと見なされ、プライマリゾーンは1つだけ存在できます。ゾーン優先順位を設定しない場合は、ランダム優先順位となります。並べ替え方は以下のとおりです：<ol><li>左側のリストボックスから1つ以上のゾーンを選択します。左側のリストボックスには、現在のクラスタで利用可能なすべてのゾーンが表示されます。</li><li>中央の **>** ボタンをクリックします。選択したゾーンが <b>優先順位付き</b> リストに移動します。</li><li>a、bの操作を繰り返して、次に低い優先順位のゾーンを追加します。</li><li>優先順位を調整する場合は、<b>優先順位付き</b> リストでドラッグ＆ドロップして順序を変更できます。リストは上から下に向かって、優先順位が順次低下します。</li><li>ゾーンの後ろにある削除ボタンをクリックするか、**デフォルトに戻す** をクリックすると、<b>優先順位付き</b> リストのゾーンが左側のリストに戻ります。</li></ol>  |

8. **復元を開始** をクリックすると、復元タスクが生成されます。**タスクを見る** をクリックすると、復元タスクの進捗状況を確認できます。
