# アラートイベントの表示

この章では、アラートイベントの詳細を表示する方法について説明します。

## 手順

1. obshell Dashboardコンソールにログインします。

2. 左側のナビゲーションバーで **アラートセンター** を選択します。

3. **アラートイベント** タブをクリックします。

4. クエリボックスにクエリ条件を設定すると、**アラートイベント** リストにクエリ条件に一致するすべてのアラートイベントが返されます。

   * アラートイベントは、**オブジェクトタイプ**、**アラートオブジェクト**、**アラートレベル**、**キーワード**、**開始時間**、**終了時間** などの条件で正確に検索できます。

     | パラメータ  | 説明  |
     |-------|------|
     |オブジェクトタイプ | オブジェクトタイプは obcluster、obtenant、observer の3種類です。<ul><li>obcluster はクラスタをアラート対象とします。</li><li>obtenant はテナントをアラート対象とします。</li><li>observer は observer ノードをアラート対象とします。</li></ul> |
     | アラート対象 | **オブジェクトタイプ** に応じて、このドロップダウンリストから異なるアラート対象を選択できます。複数のアラート対象が存在する場合、そのうち1つのみを選択できます。<ul><li>オブジェクトタイプが obcluster の場合、アラート対象はクラスタ名です。</li><li>オブジェクトタイプが obtenant の場合、アラート対象は該当するテナント名です。</li><li>オブジェクトタイプが observer の場合、アラート対象は observer ノードのIPアドレスです。</li></ul> |
     | アラートレベル | 重大、警告、注意、リマインダーの4段階に分かれています。<ul><li>重大：システムの可用性が低下し、緊急に修正する必要があります。これにより、システムが完全に利用不能になるのを防ぎます。例：`マシンメモリ使用率が3分間90%を超える`。</li><li>警告：システムはまだ利用可能ですが、まもなく利用不能状態に達するため、可用性の低下を防ぐ措置を講じる必要があります。例：`OceanBaseテナント接続数が上限の80%を超える`。</li><li>注意：傾向から判断すると、システムの主要なパフォーマンス指標が低下していますが、警告が発生するレベルには達していません。この時点で調査を行うことで、潜在的な問題を発見し、警告の発生を防ぐことができます。</li><li>リマインダー：操作のリマインダーです。本質的にはアラートではなく、通常は管理者が重要な操作を実行する際に表示されます。例：`管理者がクラスタのオフライン操作を実行する`。</li></ul> |
     | キーワード | アラートのキーワードです。キーワードに基づいて対応するアラートイベントを検索できます。自由に入力できます。 |
     | 開始時間 | アラートイベントの開始時間を指します。 |
     | 終了時間 | アラートイベントの終了時間を指します。 |

   * **リセット** ボタンをクリックすると、クエリ内容が空になり、再度入力できます。

   * **折りたたむ** ボタンをクリックすると、クエリボックスが折りたたまれます。この状態では、**オブジェクトタイプ**、**アラートオブジェクト**、**アラートレベル** のみを設定してクエリできます。

5. アラートイベントに対して **ミュート** 操作を実行できます。

   * アラートイベントに注目する必要がない場合、**操作** 列の **ミュート** をクリックすると、アラートメッセージをすばやくミュートできます。

     <!-- ![イベントリスト](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.4.1/obshell/V4.3.2/450.alarm-center/200.view-alarm-events-01.png) -->

   * **ミュート** をクリックすると、ページは **アラートミュート** ページに移動し、その後 **ミュート条件** ページがポップアップ表示されます。ミュート対象タイプ、ミュート対象、ミュートアラートルール、タグが自動的に入力されます。あとはミュート終了時間と備考情報を入力し、**送信** をクリックするだけです。これにより、該当するアラートイベントのアラートステータスは **抑制** に変わり、設定された終了時間まで、そのアラートは送信されません。具体的な設定方法については、[アラートミュートの管理](300.alert-shielding-management.md)の新規ミュートを参照してください。
