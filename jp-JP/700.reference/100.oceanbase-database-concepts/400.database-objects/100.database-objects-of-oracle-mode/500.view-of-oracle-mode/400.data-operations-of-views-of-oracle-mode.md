# ビューのデータ操作

ビューはテーブルから派生されるため、テーブルと多くの類似点があります。ユーザーはビューを照会でき、一定の制限のもとでビューに対してDML操作を実行することができます。ビューに対する操作は、ビューの一部のベーステーブル内のデータに影響を与え、ベーステーブルの整合性制約およびトリガーによって制御されます。

以下の例では、テーブル `employees` にビュー `staff_dept_10` を定義します。このビューは、部門が10の従業員情報を定義しています。キーワード `CHECK OPTION` を使用してビューを作成すると、そのビュー上でのDML操作はビューで定義されたデータにのみ適用されることを示します。したがって、部門が10の従業員の行データを挿入できますが、部門が30の従業員の行データを挿入することはできません。

```sql
CREATE VIEW staff_dept_10 AS
SELECT employee_id, last_name, job_id, manager_id, department_id
FROM   employees
WHERE  department_id = 10
WITH CHECK OPTION CONSTRAINT staff_dept_10_cnst;
```
