# プライマリキー制約

プライマリキー値ルール（Primary Key Value Rule）とは、あるキーKey（キーとは、単一の列または複数の列の集合を指します）に定義されるルールであり、その役割はテーブル内の各データ行が特定のキー値によって一意に特定できることを保証することです。

​各データベーステーブルには、`PRIMARY KEY` 制約を1つしか定義することができません。この制約を構成する列（1列または複数の列）の値は、ある行データの一意な識別子として機能します。つまり、各データ行はこの主キー値によって名前付けられます。

​本記事では、以下の具体的な例を通じて主キー制約の主要な特性について説明します。

```sql
obclient> CREATE TABLE t1(c1 INT, c2 INT, CONSTRAINT pk_c1_c2 PRIMARY KEY(c1, c2));
Query OK, 0 rows affected

obclient> INSERT INTO t1 VALUES(1, 1);
Query OK, 1 row affected

obclient> INSERT INTO t1 VALUES(1, 1);
ORA-00001: unique constraint '1-1' for key 'PK_C1_C2' violated

obclient> INSERT INTO t1 VALUES(null, 1);
ORA-01400: cannot insert NULL into '(C1)'

obclient> INSERT INTO t1 VALUES(null, null);
ORA-01400: cannot insert NULL into '(C1)'
```

​`PRIMARY KEY` 完全性制約（Integrity Constraint）とは、テーブルのデータが以下の2つのルールに従うことを保証するものです：

* 任意の2行のデータにおいて、`PRIMARY KEY` 制約列（1列または複数の列）に重複する値は存在しません。

* 主キー列の値は空ではありません。つまり、ユーザーは主キー列に値を入力する必要があります。

​データベースはユーザーがテーブルに主キーを定義する必要があるとは強制しませんが、主キーを使用することで、テーブル内の各行データが一意に特定され、重複するデータ行が存在しないことが保証されます。

下図は、`dept` テーブルに定義された `PRIMARY KEY` 制約と、この制約に違反するデータ行を示しています。`dept` テーブルには、`deptno`、`dname`、`loc` の3列が含まれています。`deptno` 列に主キー制約を定義すると、この列には重複するデータが存在せず、空値も許容されません。

図にはまた、主キー制約に違反して `dept` テーブルに挿入できない2行のデータも示されています。1行目のデータの主キー値は既存データと重複しており、もう一方のデータの主キー列は空値となっています。
