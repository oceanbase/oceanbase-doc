# 一意性制約

一意キー（UNIQUE key）制約は、ユニークな列値（Unique Column Value）に関するルールであり、特定の列または列ファミリに定義されます。その役割は、挿入または更新されるデータ行の列または列ファミリの値が一意であることを保証し、テーブル内の任意の2行における特定の列または列セットの値が重複しないようにすることです。

本記事では、以下の具体的な例を通じて、一意性制約の主な特性を説明します。

```sql
obclient> CREATE TABLE t1(c1 INT, c2 INT, CONSTRAINT t1_uk_c1_c2 UNIQUE(c1, c2));
Query OK, 0 rows affected

obclient> INSERT INTO t1 VALUES(1, 1);
Query OK, 1 row affected

obclient> INSERT INTO t1 VALUES(1, 1);
OBE-00001: unique constraint '1-1' for key 'T1_UK_C1_C2' violated

obclient> INSERT INTO t1 VALUES(null, 1);
Query OK, 1 row affected

obclient> INSERT INTO t1 VALUES(null, 1);
Query OK, 1 row affected

obclient> INSERT INTO t1 VALUES(null, null);
Query OK, 1 row affected

obclient> INSERT INTO t1 VALUES(null, null);
Query OK, 1 row affected
```

また、下図のように、`dept` テーブルの `dname` 列に `UNIQUE` キー制約を定義すると、このテーブルに重複する部門名の存在は許可されませんが、ユーザーは `dname` 列にNULL値を挿入できます。`dname` 列に `NOT NULL` 制約も定義している場合は、ユーザーは `dname` 列にNULL値を挿入できません。

<!-- ![一意性制約](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/4481752461/p357313.jpg) -->

`UNIQUE` キーが複数の列で構成されている場合、このデータ列のグループは複合一意キー（Composite Unique Key）と呼ばれます。下図のように、`customer` テーブルで定義された `UNIQUE` キー制約は複合一意キーを使用しており、`area` と `phone` の2列を含みます。これは、任意の2行におけるキーの値が重複してはならないことを要求します。ユーザーは列にNULL値を入力できます。ただし、列に `NOT NULL` 制約も定義している場合は、NULL値の入力は許可されません。

ユーザーは `customer` テーブルに任意のレコードを挿入できますが、上述の `UNIQUE` キー制約の制限により、テーブル内の各行のエリアコード（Area Code）と電話番号（Telephone Number）の組み合わせは重複してはなりません。これにより、不注意による電話番号の重複問題を回避できます。
