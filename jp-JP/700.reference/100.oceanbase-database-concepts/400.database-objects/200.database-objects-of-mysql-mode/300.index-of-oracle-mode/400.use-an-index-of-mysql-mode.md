# インデックスの使用

ユーザーがインデックスを作成すると、OceanBaseデータベースはそのインデックスを自動的に維持します。すべてのDML操作は、インデックステーブルの対応するデータレコードをリアルタイムで更新します。同時に、オプティマイザーはユーザーのクエリに基づいて、インデックスを使用するかどうかを自動的に選択します。本記事では、インデックススキャンの方法について説明します。

SQLクエリ文が述語条件でインデックス列を検索する場合、データベースは自動的に述語条件をクエリの範囲として抽出し、つまりインデックステーブルの開始キーと終了キーとなります。データベースは開始キーに基づいてデータの開始位置を特定でき、終了キーに基づいてデータの終了位置を特定できます。そして、開始位置と終了位置に含まれるデータがこのクエリによってスキャンされる必要があります。

インデックステーブルについては、OceanBaseデータベースはMemTableとSSTableを使用してデータを保存します。そのうち、MemTableはBTree構造を使用し、SSTableはマクロブロック構造を使用しています。MemTableまたはSSTableはいずれも上記のスキャンプロセスに従って、対応するデータをスキャンし、最終的なデータ行はMemTableとSSTableのデータ行が融合した完全なデータ行になります。

そのため、OceanBaseデータベースによるインデックステーブルデータの完全なクエリプロセスは以下の通りです：

1. MemTable内でデータをクエリします。

2. SSTable内でデータをクエリします。

3. MemTableとSSTable内のデータを融合し、完全な行を得ます。

SQLクエリ文がインデックステーブル内の列のみを含む場合、データベースはユーザーが指定した列に基づいて、上記のクエリプロセスに従って、対応するインデックステーブルのMemTableとSSTableをクエリし、完全なデータ行を得ます。

SQLクエリ文がインデックステーブル内の列に加えて他の列も含む場合、データベースはまずインデックステーブルを介して関連する行をクエリし、その後、行上の主キーに基づいて上記のクエリプロセスに従って、主テーブルから必要なデータ列をクエリします。このプロセスは「テーブルへの戻り」(table lookup) とも呼ばれます。
