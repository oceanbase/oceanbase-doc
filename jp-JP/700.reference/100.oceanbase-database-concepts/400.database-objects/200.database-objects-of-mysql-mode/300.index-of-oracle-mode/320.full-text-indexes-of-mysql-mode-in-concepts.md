# 全文インデックス

OceanBaseデータベースのMySQL互換モードでは、`CHAR`、`VARCHAR`、および`TEXT`型の列に全文インデックスを作成できます。さらに、プライマリテーブル内や同一の列に複数の全文インデックスを作成することも可能です。

全文インデックスは、プライマリキーの有無に関わらず、パーティション表と非パーティション表の両方に作成できます。全文インデックスを作成する際の制限事項は以下の通りです。

* 全文インデックスは、`CHAR`、`VARCHAR`、および`TEXT`型の列にのみ作成できます。
* 現在のバージョンのOceanBaseデータベースでは、ローカル全文インデックスのみを作成できます。
* 全文インデックスを作成する際、`UNIQUE`キーワードを指定することはできません。
* 複数の列にまたがる全文インデックスを作成する場合、それらの列が同じ文字セットを使用している必要があります。

これらの構文とルールに基づいて、OceanBaseデータベースの全文インデックス機能を使用し、テキストデータを効率的に検索および取得できます。

## DML操作

全文インデックスを含むテーブルに対して、`INSERT INTO ON DUPLICATE KEY`、`REPLACE INTO`、複数テーブルの更新および削除、更新可能ビューの更新など、複雑なDML操作を実行できます。

**以下にいくつかの例を示します:**

* `INSERT INTO ON DUPLICATE KEY`:

    ```sql
    INSERT INTO articles VALUES ('OceanBase', 'Fulltext search index support insert into on duplicate key')
        ON DUPLICATE KEY UPDATE title = 'OceanBase 4.3.3';
    ```

* `REPLACE INTO`:

    ```sql
    REPLACE INTO articles(title, context) VALUES ('Oceanbase 4.3.3', 'Fulltext search index support replace');
    ```

* 複数テーブルの更新および削除。

  1. `tbl1`という名前のテーブルを作成します。

     ```sql
     CREATE TABLE tbl1 (a int PRIMARY KEY, b text, FULLTEXT INDEX(b));
     ```

  2. `tbl2`という名前のテーブルを作成します。

     ```sql
     CREATE TABLE tbl2 (a int PRIMARY KEY, b text);
     ```

  3. 複数のテーブルに対して`UPDATE`文を実行します。

     ```sql
     UPDATE tbl1 JOIN tbl2 ON tbl1.a = tbl2.a
         SET tbl1.b = 'dddd', tbl2.b = 'eeee';
     ```

     ```sql
     UPDATE  tbl1 JOIN tbl2 ON tbl1.a = tbl2.a SET tbl1.b = 'dddd';
     ```

     ```sql
     UPDATE tbl1 JOIN tbl2 ON tbl1.a = tbl2.a SET tbl2.b = tbl1.b;
     ```

  4. 複数のテーブルに対して`DELETE`文を実行します。

     ```sql
     DELETE tbl1, tbl2 FROM tbl1 JOIN tbl2 ON tbl1.a = tbl2.a;
     ```

     ```sql
     DELETE tbl1 FROM tbl1 JOIN tbl2 ON tbl1.a = tbl2.a;
     ```

     ```sql
     DELETE tbl1 FROM tbl1 JOIN tbl2 ON tbl1.a = tbl2.a;
     ```

* 更新可能ビューに対するDML操作。

  1. `fts_view`という名前のビューを作成します。

     ```sql
     CREATE VIEW fts_view AS SELECT * FROM tbl1;
     ```

  2. 更新可能ビューに対して`INSERT`文を実行します。

     ```sql
     INSERT INTO fts_view VALUES(3, 'cccc'), (4, 'dddd');
     ```

  3. 更新可能ビューに対して`UPDATE`文を実行します。

     ```sql
     UPDATE fts_view SET b = 'dddd';
     ```

     ```sql
     UPDATE fts_view JOIN normal ON fts_view.a = tbl2.a
        SET fts_view.b = 'dddd', tbl2.b = 'eeee';
     ```

  4. 更新可能ビューに対して`DELETE`文を実行します。

     ```sql
     DELETE FROM fts_view WHERE b = 'dddd';
     ```

     ```sql
     DELETE tbl1 FROM fts_view JOIN tbl1 ON fts_view.a = tbl1.a AND 1 = 0;
     ```

## 全文インデックストークナイザ

OceanBaseデータベースは、全文インデックス用に複数の組み込みトークナイザ（パーサー）をサポートしているため、ビジネスシナリオに最適なテキストトークン化戦略を選択できます。デフォルトのトークナイザは**Spaceトークナイザ**です。その他のトークナイザは、`WITH PARSER`パラメータを使用して明示的に指定する必要があります。

**トークナイザ一覧:**

* **Spaceトークナイザ**
* **Basic Englishトークナイザ**
* **IKトークナイザ**
* **Ngramトークナイザ**
* **jiebaトークナイザ**

**設定例:**

テーブルの作成または変更時に、`CREATE TABLE` または `ALTER TABLE` 文で全文インデックスを作成する際に `WITH PARSER tokenizer_option` パラメータを設定することで、トークナイザの種類を指定します。トークナイザのプロパティパラメータの詳細については、[インデックスの作成](https://en.oceanbase.com/docs/common-oceanbase-database-10000000001973637) を参照してください。

```sql
CREATE TABLE tbl2(id INT, name VARCHAR(18), doc TEXT,
    FULLTEXT INDEX full_idx1_tbl2(name, doc)
      WITH PARSER NGRAM
      PARSER_PROPERTIES=(ngram_token_size=3));


-- 既存の全文インデックスのトークナイザを変更する
ALTER TABLE tbl2(id INT, name VARCHAR(18), doc TEXT,
    FULLTEXT INDEX full_idx1_tbl2(name, doc)
      WITH PARSER NGRAM
      PARSER_PROPERTIES=(ngram_token_size=3));  -- Ngramの例
```

### Spaceトークナイザ (デフォルト)

**概要:**

* スペース、句読点（カンマやピリオドなど）、または英数字以外の文字（アンダースコア `_` を除く）でテキストを分割します。
* トークン化の結果には、長さが `min_token_size` (デフォルト: 3) から `max_token_size` (デフォルト: 84) の間にある有効なトークンのみが含まれます。
* 中国語の文字は個別の文字として扱われます。

**例の説明:**

* スペース、カンマ、ピリオド、その他の記号が区切り文字として機能します。連続する中国語の文字は1つの単語として扱われます。

### Basic English (Beng) トークナイザ

**概要:**

* Spaceトークナイザに似ていますが、アンダースコア（`_`）を保持せず、区切り文字として扱います。
* 英語のフレーズを分割するのには適していますが、スペースのない用語（「iPhone15」など）に対する効果は限定的です。

**ユースケース:**

* 英語ドキュメント（ログやコメントなど）の基本的な検索。

**例の説明:**

* アンダースコア（`_`）で分割されます。Spaceトークナイザとの主な違いは `_` の扱い方です。

### Ngramトークナイザ

**概要:**

* **固定長N-gramトークン化**: デフォルトでは `n=2` です。連続する区切り文字以外の文字を、長さ `n` のサブシーケンスに分割します。
* 区切り文字のルールはSpaceトークナイザと同じです（`_` と英数字を保持します）。
* **長さ制限パラメータはサポートしていません**。可能なすべての長さnのトークンを出力します。

**ユースケース:**

* 短いテキスト（ユーザーIDや注文番号など）のあいまい検索。
* 固定長の特徴抽出が必要なシナリオ（パスワードポリシーの分析など）。

**例の説明:**

* デフォルトの `n=2` の場合、重複する部分を含め、連続する2文字のすべてのトークンを出力します。

### Ngram2トークナイザ

**概要:**

* **動的なN-gramの範囲**をサポートします: `min_ngram_size` および `max_ngram_size` パラメータを使用して、トークンの長さの範囲を設定します。
* 複数のトークン長をカバーする必要があるシナリオに適しています。

**ユースケース:** 複数の固定長トークンを同時に必要とするシナリオ。

<main id="notice" type='explain'>
  <h4>注記</h4>
  <p>Ngram2トークナイザを使用する場合、より多くのメモリを消費することに注意してください。たとえば、<code>min_ngram_size</code> と <code>max_ngram_size</code> の範囲が広い場合、大量のトークンの組み合わせが生成され、リソース消費が高くなる可能性があります。</p>
</main>

**例の説明:**

* 長さが4〜6文字の連続するすべてのサブシーケンスを出力します。トークンは重複する場合があります。

### IKトークナイザ

**概要:**

* オープンソースのIK Analyzerに基づく中国語トークナイザです。

* 英単語、メールアドレス、URL（`://` なし）、IPアドレス、および同様の形式を自動的に認識します。

**ユースケース:** 中国語のトークン化

**ビジネスシナリオ:**

<!-- * Eコマースの製品説明検索（例：「HuaweiMate60」の完全一致など）。 -->
* ソーシャルメディアのコンテンツ分析（例：ユーザーコメントからのキーワード抽出など）。

* **スマートモード (Smart mode)**: 各文字が1つのトークンにのみ属し、重複がないことを保証します。また、各トークンの長さを可能な限り長くし、トークンの数を最小限に抑えます。数字と助数詞を1つのトークンに結合しようと試みます。

* **max_wordモード**: 同じ文字を異なるトークンに含め、可能な限り多くのトークンを提供します。

### jiebaトークナイザ

**概要:** オープンソースのPythonツール `jieba` に基づくトークナイザです。正確（precise）モード、全（full）モード、検索エンジン（search-engine）モードをサポートします。

**特徴:**

* **正確モード**: 辞書に従って厳密に分割します。
* **全モード**: 可能なすべての分割の組み合わせをリストアップします。



**ユースケース:**

<!-- * 医療および技術用語の分析（例：「AI」の正確な分割など）。 -->
* 多言語混在テキストの処理（例：ソーシャルメディア上の中国語と英語が混在するコンテンツなど）。

jiebaトークナイザプラグインはご自身でインストールする必要があります。ビルドマシンでのインストール手順については、[トークナイザプラグイン](../../../../1600.oceanbase-database-plugin/200.tokenizer-plugin.md) を参照してください。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>トークナイザプラグインは現在実験的な機能であり、本番環境での使用は推奨されません。</p>
</main>

### トークナイザの選択戦略

| **ビジネスシナリオ** | **推奨トークナイザ** | **理由** |
| --- | --- | --- |
| 英語の製品タイトル検索 | **Space または Basic English** | シンプルかつ効率的であり、英語のトークン化の習慣に適合しています。 |
| 中国語の製品説明検索 | **IKトークナイザ** | 中国語の用語を正確に識別し、カスタム辞書をサポートします。 |
| ログのあいまい検索（例：エラーコード） | **Ngramトークナイザ** | 辞書は不要で、スペースのないテキストのあいまいクエリのニーズをカバーします。 |
| 技術論文のキーワード抽出 | **jiebaトークナイザ** | 新語の発見や複雑なモード切り替えをサポートします。 |
