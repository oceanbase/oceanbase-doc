# マルチテナントアーキテクチャの概要

OceanBaseデータベースは、単一クラスタでマルチテナント設計を採用しており、本質的にクラウドデータベースアーキテクチャをサポートしています。パブリッククラウド、プライベートクラウド、ハイブリッドクラウドなど、さまざまなデプロイメント形態に対応しています。

<!-- ![paxos-group.png](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.3.5/multi-tenant-architecture.png) -->

OceanBaseデータベースは、テナントを通じてリソースの分離を実現し、各データベースサービスのインスタンスが他のインスタンスの存在を意識することがないようにします。また、権限制御によりテナントデータの安全性を確保し、OceanBaseデータベースの強力な拡張性と組み合わせることで、安全で柔軟なDBaaSサービスを提供できます。

テナントは論理的な概念です。OceanBaseデータベースでは、テナントはリソース割り当ての単位であり、データベースオブジェクト管理とリソース管理の基盤となります。システム運用、特にクラウドデータベースの運用において重要な影響を及ぼします。テナントはある程度、従来のデータベースの「インスタンス」という概念に相当します。テナント間は完全に隔離されています。データセキュリティの観点から、OceanBaseデータベースはテナント間のデータアクセスを許可せず、ユーザーのデータ資産が他のテナントによって盗用されるリスクを防ぎます。リソース使用量に関しては、OceanBaseデータベースはテナントがそのリソースクォータを「専有」しているかのように表現されます。全体として、テナントはさまざまなデータベースオブジェクトのコンテナであると同時に、リソース（CPU、メモリ、I/Oなど）のコンテナでもあります。
