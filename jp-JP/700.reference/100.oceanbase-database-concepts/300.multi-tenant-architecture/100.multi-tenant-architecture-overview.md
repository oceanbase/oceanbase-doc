# マルチテナントアーキテクチャの概要

OceanBaseデータベースは、単一クラスタでマルチテナント設計を採用しており、その設計上、クラウドデータベースアーキテクチャをサポートしています。パブリッククラウド、プライベートクラウド、ハイブリッドクラウドなど、さまざまなデプロイメント形態に対応しています。

<!-- ![paxos-group.png](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.3.5/multi-tenant-architecture.png) -->

OceanBaseデータベースは、テナントを通じてリソースの分離を実現し、データベースサービスの各インスタンスが他のインスタンスの存在を意識せずに利用できるようにします。また、権限制御によりテナントデータの安全性を確保し、OceanBaseデータベースの強力な拡張性と組み合わせることで、安全で柔軟なDBaaSサービスを提供できます。

テナントは論理的な概念です。OceanBaseデータベースでは、テナントはリソース割り当ての単位であり、データベースオブジェクト管理とリソース管理の基盤となります。システム運用、特にクラウドデータベースの運用において重要な影響を及ぼします。テナントはある程度、従来のデータベースの「インスタンス」という概念に相当します。テナント間は完全に隔離されています。データセキュリティの観点から、OceanBaseデータベースはテナント間のデータアクセスを許可せず、ユーザーのデータ資産が他のテナントによって盗用されるリスクを防ぎます。リソースの使用に関しては、OceanBaseデータベースではテナント（tenant）がそのリソース枠を「専有」します。全体として、テナントはさまざまなデータベースオブジェクトのコンテナであると同時に、リソース（CPU、Memory、I/Oなど）のコンテナでもあります。
