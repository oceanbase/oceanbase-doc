# Oracleモードのトランザクション分離レベル

## Oracleモードでサポートされている分離レベル

OceanBaseデータベースは、Oracleモードで以下の分離レベルをサポートしています：

* コミット済み読み取り（Read Committed）：トランザクションが実行するクエリは、そのクエリ開始前にコミットされたデータのみを参照できます。Read Committedでは、反復不可能読み取りとファントムリードの2つの異常状態を防ぐことはできません。

* 直列化可能（Serializable）：トランザクションのクエリは、トランザクション開始前にコミットされたデータのみを参照できます。これは最も厳密な分離レベルであり、ダーティリード、反復不可能読み取り、ファントムリードの3つの異常状態を防ぐことができます。トランザクションは直列実行されているかのように見えます。

OceanBaseデータベースのデフォルトの分離レベルは**Read Committed**です。

## 分離レベルの動作比較

Oracleデータベースは**Read Committed**と**Serializable**の2つの分離レベルをサポートしており、OceanBaseデータベースのOracleモードは、これら2つの分離レベルにおいてOracleデータベースと同じ動作をします。

## 分離レベルの設定方法

分離レベルの設定には、トランザクションレベルとセッションレベルの2つの方法があります。

* トランザクションレベル

  ```sql
  SET TRANSACTION ISOLATION LEVEL [READ COMMITTED | SERIALIZABLE];
  ```

  このステートメントは新しいトランザクションを開始し、そのトランザクションの分離レベルを設定します。

* セッションレベル

  ```sql
  ALTER SESSION SET ISOLATION_LEVEL = [READ COMMITTED | SERIALIZABLE];
  ```

## 分離レベルの使用制限

* トランザクションの実行中に分離レベルを設定することは許可されていません。そうすると、以下のエラーが発生します：

  ```javascript
  ERROR:OBE-01453: SET TRANSACTION must be first statement of transaction
  ```

* Serializable分離レベルを有効にするには、グローバルタイムスタンプサービス（Global Timestamp Service）が有効であることを確認する必要があります。

* Sessionはセッションレベルのトランザクション分離レベルを維持し、トランザクション開始時にそのセッションレベルの分離レベルを取得します。この分離レベルは、トランザクションレベルの分離レベルによって上書きされる可能性があります。
