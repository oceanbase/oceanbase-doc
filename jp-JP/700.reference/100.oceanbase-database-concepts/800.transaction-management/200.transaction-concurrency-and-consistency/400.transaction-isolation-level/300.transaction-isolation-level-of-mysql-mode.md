# MySQLモードのトランザクション分離レベル

## MySQLモードでサポートされている分離レベル

OceanBaseデータベースは、MySQLモードで以下の4つの分離レベルをサポートしています：

* 未コミット読み取り（Read Uncommitted）：あるトランザクションが、別のトランザクションによって未コミットのデータを読み取ることができます。トランザクションAがデータ項目を変更したもののまだコミットしていない場合、トランザクションBはその未コミットの変更を即座に確認できます。トランザクションAが変更をロールバック（操作を取り消す）した場合、トランザクションBが読み取ったデータは、以前存在したが現在は存在しない「ダーティ」なデータになります。現在のOceanBaseは、*未コミット読み取り（Read Uncommitted）*分離レベルを構文的にのみサポートしており、ユーザーが**未コミット読み取り**の分離レベルを指定した場合、実際には**コミット済み読み取り**が使用されます。

* コミット済み読み取り（Read Committed）：あるトランザクションが実行するクエリでは、そのクエリ開始前にコミットされたデータのみを確認できます。コミット済み読み取りは、反復不可能読み取りおよびファントムリード（Phantom Read）の2つの異常状況を防ぐことはできません。

* 反復可能読み取り（Repeatable Read）：トランザクション内で異なる時間に読み取った同一のデータは一貫しています。

* 直列化可能（Serializable）：この分離レベルは、OracleデータベースのSerializableに類似しており、厳密な意味でのSerializableではありません。

OceanBaseデータベースのデフォルトの分離レベルは**コミット済み読み取り（Read Committed）**です。

## 分離レベルの動作比較

MySQLデータベースは**未コミット読み取り**、**コミット済み読み取り**、**反復可能読み取り**、**直列化可能**の4つの分離レベルをサポートしていますが、OceanBaseデータベースのMySQLモードは、これら4つの分離レベルにおいてMySQLデータベースとは一定の差異があります。

* **未コミット読み取り**：
  MySQLデータベースは**未コミット読み取り**をサポートしていますが、OceanBaseデータベースは**未コミット読み取り**の構文のみをサポートしています。現在のOceanBaseは、*未コミット読み取り（Read Uncommitted）*分離レベルを構文的にのみサポートしており、ユーザーが**未コミット読み取り**の分離レベルを指定した場合、実際には**コミット済み読み取り**が使用されます。

* **コミット済み読み取り**：
  **コミット済み読み取り**分離レベルで行が更新条件を満たすかどうかを判断する際、MySQLデータベースは半一貫性読み取りを使用します。行が並行トランザクションによって更新されている場合、MySQLデータベースは並行トランザクションの終了を待ち、最新のバージョンで更新が必要かどうかを判断します。一方、OceanBaseデータベースでは、並行トランザクションが更新しているかどうかに関係なく、常にステートメントスナップショット内のバージョンに基づいて行が更新条件を満たすかどうかを判断します。

* **反復可能読み取り**：
  **反復可能読み取り**分離レベルで書き込み競合が発生した場合、MySQLデータベースでは後から書き込んだトランザクションが先に書き込んだトランザクションの終了を待ちます。先に書き込んだトランザクションがロールバックした場合、後から書き込んだトランザクションは元のバージョンで直接更新します。先に書き込んだトランザクションがコミットした場合、**後から書き込んだトランザクションは新しくコミットされたバージョンで更新を行います**。OceanBaseデータベースでは、後から書き込んだトランザクションが先に書き込んだトランザクションの終了を待ちます。先に書き込んだトランザクションがロールバックした場合、後から書き込んだトランザクションは元のバージョンで直接更新します。先に書き込んだトランザクションがコミットした場合、**後から書き込んだトランザクションはロールバックしてエラーを返します**。

* **直列化可能**：
  MySQLデータベースの**直列化可能**分離レベルは2段階ロック（2PL）を使用し、厳密な直列化可能性を保証します。OceanBaseデータベースの**直列化可能**分離レベルはスナップショット分離（Snapshot Isolation）を使用し、厳密な直列化可能性を保証することはできません。

## 分離レベルの設定方法

分離レベルの設定には、グローバルレベルとセッションレベルの2つの方法があります。

```sql
SET [GLOBAL | SESSION] TRANSACTION ISOLATION LEVEL [READ COMMITTED | REPEATABLE READ | SERIALIZABLE | READ UNCOMMITTED];
```

## 分離レベルの使用制限

* トランザクションの実行中に分離レベルを設定することは許可されていません。そうした場合、以下のエラーが表示されます：

    ```sql
    ERROR 1568 (25001): Transaction characteristics can't be changed while a transaction is in progress
    ```

* グローバルレベルの分離レベルは、セッションレベルの分離レベルによって上書きされます。
