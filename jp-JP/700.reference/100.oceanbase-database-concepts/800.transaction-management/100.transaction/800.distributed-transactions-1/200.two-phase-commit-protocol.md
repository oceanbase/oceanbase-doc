# 2フェーズコミット

#docslug#/oceanbase-database/oceanbase-database/V4.0.0/two-phase-commit-protocol
OceanBaseデータベースは、ネイティブの2フェーズコミットプロトコルを実装しており、分散トランザクションの原子性を保証します。

2フェーズコミットプロトコルには、コーディネーター（Coordinator）と参加者（Participant）という2つのロールが含まれます。コーディネーターはプロトコル全体の進行を管理し、複数の参加者が最終的に一致した決定に至るようにします。参加者はコーディネーターの要求に応答し、コーディネーターの指示に従って準備操作（prepare）およびコミット/アボート操作（commit/abort）を実行します。

## 分散トランザクションのコミットプロセス

### PREPAREフェーズ

コーディネーター：コーディネーターはすべての参加者に対して準備リクエスト（prepare request）を送信します。

参加者：参加者は準備リクエストを受信すると、コミットが可能かどうかを判断します。可能な場合は準備ログ（prepare log）を永続化し、コーディネーターに準備成功を返します。不可能な場合は準備失敗を返します。

### COMMITフェーズ

コーディネーター：コーディネーターはすべての参加者からの準備確認（prepare ack）を受信した後、COMMIT状態に入り、ユーザーにトランザクションのコミット成功を返します。その後、すべての参加者にトランザクションのコミットリクエスト（commit request）を送信します。

参加者：参加者はコミットリクエストを受信すると、リソースを解放して行ロックを解除し、コミットログ（commit log）をコミットします。ログの永続化が完了すると、コーディネーターに`commit ok`メッセージを返信し、最後にトランザクションコンテキストを解放して終了します。
