# OBServerノードのインストールディレクトリ構造

OBServerノードの作業ディレクトリには通常、audit、bin、etc、etc2、etc3、log、run、storeという8つのディレクトリがありますが、これら8つのディレクトリがすべてインストールに必要なわけではありません。OBServerノードを起動する前に、etc、log、run、storeの4つのディレクトリが存在していることを確認し、同時にstoreディレクトリ内にはclog、slog、sstableの3つのディレクトリがある必要があります。etc2とetc3はバックアップ設定ファイル用であり、OBServerノードによって作成されます。auditディレクトリには監査ログが保存され、これもOBServerノードによって作成されます。binディレクトリはobserverバイナリファイルを格納するために使用され、後続の特定を容易にします。

```shell
├─audit
├─bin
├─etc
├─etc2
├─etc3
├─log
├─run
├─store
       ├─clog
       ├─slog
       ├─sstable
```

## 設定ファイルディレクトリ

etc、etc2、etc3はすべて設定ファイルのディレクトリです。これら3つのディレクトリの内容は完全に一致しており、違いは後者の2つのディレクトリがOBServerノードの作成時に自動的に作成されるものであり、最初のディレクトリは起動前に準備する必要があるということです。etc2とetc3は設定ファイルを追加で保存するディレクトリであり、config_additional_dir構成パラメータによって制御されます。設定変更後は、標準のetc/observer.config.binに書き込むだけでなく、これらのディレクトリにも構成パラメータファイルが追加で作成されます。サーバー起動時には、追加ディレクトリの構成パラメータファイルは読み込まれず、単なる追加バックアップとして扱われます。追加ディレクトリに権限がある場合は自動的に作成されますが、権限がない場合はログにERRORが報告されます。

設定ファイルには、クラスタおよびテナントレベルの構成パラメータの増分情報が保存されています。クラスタ設定は、データベースに接続してalter systemを実行することで変更できるほか、コマンドラインから構成パラメータを指定することも可能です。コマンドラインからの構成パラメータの指定は既存の設定を上書きします。コマンドラインでは、以下のパラメータを使用してOBServerノードの構成パラメータを変更できます：

```shell
-z,--zone ZONE           zone name ノードが属するゾーンの名前
-p,--mysql_port PORT     mysql port SQLサービスプロトコルのポート番号
-P,--rpc_port PORT       rpc port クラスタ内部通信のポート番号
-n,--appname APPNAME     application name このOceanBaseクラスタの名前
-c,--cluster_id ID       cluster id このOceanBaseクラスタのID
-d,--data_dir DIR        OceanBase data directory SSTableなどのデータを格納するディレクトリ
-i,--devname DEV         net dev interface サービスプロセスがバインドするNICデバイス名
-r,--rs_list RS_LIST     root service list root serviceリスト
-l,--log_level LOG_LEVEL server log level システムログレベル
-o,--optstr OPTSTR       extra options string 追加構成パラメータの形式は、構成名 = 新値、構成名 = 新値となります
```

## ログファイルディレクトリ

logディレクトリは実行ログを格納するディレクトリであり、observerログ、RSログ、選出ログが含まれています。個々のログファイルのサイズは256MBです。

`enable_syslog_recycle`がtrueに設定され、`max_syslog_file_count`が0より大きい場合、不要なログファイルは自動的に削除されます。そのうち、`enable_syslog_recycle`はOBServerノード起動前の古いログを記録するスイッチを有効にするかどうかを設定します。`max_syslog_file_count`と組み合わせて使用し、回収ロジックが古いログファイルを考慮するかどうかを決定します。`max_syslog_file_count`は各ログの最大ログ数を設定します。

## データファイルディレクトリ

storeはデータファイルのディレクトリであり、`clog`、`slog`、`sstable`の3つのサブディレクトリが含まれています。そのうち`clog`、`slog`はトランザクションログディレクトリであり、`slog`は静的データの書き込みに関するトランザクションログを、`clog`は動的データの書き込みに関するトランザクションログを格納します。`sstable`はベースラインデータディレクトリです。`sstable`ディレクトリにはblock_fileというファイルがあり、このファイルはOBServerノード起動後に作成され、そのサイズは`datafile_size`または`datafile_disk_percentage`によって制御されます。
