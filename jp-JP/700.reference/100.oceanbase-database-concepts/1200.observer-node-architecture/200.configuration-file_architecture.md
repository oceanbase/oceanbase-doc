# 設定ファイル

OceanBaseデータベースの構成パラメータは、クラスタレベルの構成パラメータとテナントレベルの構成パラメータに分かれています。OBServerノードは、すべての構成パラメータをシリアライズして、作業ディレクトリ内の設定ファイル`etc/observer.conf.bin`に保存します。その後、この作業ディレクトリでOBServerノードを起動するたびに、この設定ファイルが読み込まれます。

## 構成パラメータの確認

* 通常テナントが構成パラメータを確認する場合、仮想テーブルの形式で、クラスタ設定とテナント設定を含む現在のテナントの構成パラメータ情報が表示されます。クラスタレベルの構成パラメータはすべて読み取り専用です。テナントレベルの構成パラメータは、構成パラメータの属性に基づいて変更可否が決定されます。

  通常テナントが`SHOW PARAMETERS`ステートメントを使用して、自身のテナントレベルの構成パラメータ情報を確認するSQLステートメントは以下のとおりです：

  ```sql
  SHOW PARAMETERS [SHOW_PARAM_OPTS]
  ```

* システムテナントが構成パラメータを確認する場合

  システムテナントは`SHOW PARAMETERS`ステートメントを使用して、クラスタレベルの構成パラメータとテナントレベルの構成パラメータ情報を確認できます。`TENANT`キーワードを追加することで、指定したテナントの構成パラメータを確認できます。
  * `TENANT`を指定しない場合、システムテナントレベルの構成パラメータ情報が表示されます。これにはクラスタ設定とテナント設定が含まれます。クラスタ設定とテナント設定は、それぞれの属性に基づいて変更可否が決定されます。

  * 特定の通常テナントを指定した場合、表示される構成パラメータ内容は通常テナントと完全に一致します。

  SQLステートメントは以下のとおりです：

  ```sql
  SHOW PARAMETERS [SHOW_PARAM_OPTS] TENANT = tenant_name
  ```

構成パラメータの詳細情報は以下の表のとおりです：

|    列名    |                          意味                          |
|----------|------------------------------------------------------|
| svr_ip   | マシンのIPアドレス                                                |
| svr_port | マシンのポート番号                                                |
| name     | 構成パラメータ名                                                 |
| value    | 構成パラメータ値                                                 |
| type     | 構成パラメータデータ型 ( NUMBER,STRING,CAPACITY... )                |
| info     | 構成パラメータ説明                                                |
| section  | 構成パラメータ分類                                                |
| scope    | 構成パラメータ範囲属性（ Tenant\|Cluster ）                           |
| source   | 現在値の出典（ Tenant\|Cluster\|CommandLine\|ObAdmin\|File ） |
| edit_level | この構成パラメータの変更動作を定義します： <ul><li>`READONLY`：この構成パラメータは変更できないことを示します。</li> <li>`STATIC_EFFECTIVE`：この構成パラメータは変更可能ですが、変更を有効にするにはOBServerノードの再起動が必要です。</li>   <li>`DYNAMIC_EFFECTIVE`：この構成パラメータは変更可能で、変更は動的に反映されます。</li></ul>          |
| default_value | 構成パラメータのデフォルト値。 |
| isdefault  | 現在値がデフォルト値かどうか。<ul><li>0：現在値がデフォルト値ではないことを示します。</li><li>1：現在値がデフォルト値であることを示します。</li></ul> |

## 構成パラメータの変更

<main id="notice" type='explain'>
    <h4>説明</h4>
    <p>クラスタレベルの構成パラメータは、システムテナントでのみ設定できます。</p>
  </main>

MySQLモードでは、構成パラメータを変更するSQL構文は次のとおりです：

```sql
ALTER SYSTEM [SET] parameter_name = expression [PARAM_OPTS]
```

システムテナントでは、`TENANT` キーワードを指定することで、すべてのテナントまたは特定のテナントの構成パラメータを変更できます。SQL構文は次のとおりです：

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>実行が成功すると、指定されたすべてのテナントの構成パラメータが変更されます。</p>
  </main>

```sql
ALTER SYSTEM [SET] parameter_name = expression [PARAM_OPTS] TENANT =  all|all_user|all_meta|tenant_name
```
<main id="notice" type='explain'>
  <h4>説明</h4>
  <ul><li><code>all</code>：V4.2.1バージョン以降、<code>tenant = all</code> と <code>tenant = all_user</code> は同じ意味を持ち、すべてのユーザーテナントに適用されることを示します。<code>all</code> 構文は廃止予定であり、使用は推奨されません。  </li><li> <code>all_user</code>：すべてのユーザーテナントに適用されます。</li><li><code>all_meta</code>：すべてのMETAテナントに適用されます。 </li></ul>
</main>

Oracleモードでは、構成パラメータを変更するSQL構文は次のとおりです：

```sql
ALTER SYSTEM SET parameter_name = expression [PARAM_OPTS]
```

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p><code>PARAM_OPTS</code> は、構成パラメータ設定に使用されるその他の制限条件を示します。例えば、Zoneの指定やOBServerノードの指定などです。</p>
  </main>

## 構成パラメータストレージ

OBServerノードは永続化時に設定ファイルを使用し、実行時には内部テーブルを維持します。

構成パラメータには2種類の実テーブルがあります：クラスタレベルの構成パラメータテーブルと各テナントのテナントレベルの構成パラメータテーブルです。ユーザーがSQLを実行してクラスタレベルの構成パラメータを変更する場合はクラスタレベルの構成パラメータテーブルに書き込まれ、それ以外の場合は対応するテナントレベルの構成パラメータテーブルに書き込まれます。読み取り時は、クラスタレベルの構成パラメータはクラスタレベルの構成パラメータテーブルのみを使用し、テナントレベルの構成パラメータはテナントレベルの構成パラメータテーブルから読み取ります。

### 設定ファイル形式

```javascript
ObRecordHeader
[CLUSTER]
CLUSTER_PARAMETER_UPDATES
[TENANT_ID1]
TENANT_ID1_PARAMETER_UPDATES
[TENANT_ID2]
TENANT_ID2_PARAMETER_UPDATES
```

### 更新

更新とは、各OBServerノードが必要に応じて、内部テーブルまたは設定ファイルから永続化された増分変更を読み取り、メモリにロードするプロセスを指します。observerプロセスが起動したばかりの時、設定ファイルから構成パラメータをロードします。通常の運用中にユーザーが構成パラメータを変更した場合、OBServerノードは内部テーブルからロードします。

#### **設定ファイルからのロード**

OBServerノード起動時、構成パラメータは設定ファイルから優先的にロードされます。構成パラメータのロード順序は以下のとおりです：

1. コードの内容と実行環境に基づいてデフォルト設定を計算します。

2. 設定ファイル内の設定を項目ごとに設定します。

3. テナントレベルの構成パラメータは、クラスタレベルの構成パラメータをコピーした後、テナントの設定値で上書きされます。

4. コマンドライン引数で渡された構成パラメータ値に基づいて設定します。

#### **内部テーブルからの読み込み**

構成パラメータの主な更新シナリオは、内部テーブルからの読み込みです。つまり、既に正常に動作する設定がある状態で、特定の構成パラメータ値を変更する必要がある場合です。

`ALTER SYSTEM SET` のSQLが検証を通過すると、対応する構成パラメータが存在する内部テーブルが更新され、RSはハートビートを通じて各OBServerノードに通知し、構成パラメータの内部テーブルを再読み込んで設定を更新するよう指示します。OBServerノードがRSから通知を受信すると、バックグラウンドスレッドが「構成パラメータの更新」というタスクを開始します。このタスクの主なプロセスは以下のとおりです：

1. 内部テーブルの構成パラメータ値を読み取ります。

2. 現在の構成パラメータをコピーします。

3. 内部テーブルの構成パラメータを、コピーした構成パラメータに項目ごとに適用します。

4. 完了後、コピーした構成パラメータの値が有効かどうか確認します。

5. 内部テーブルの値を設定ファイルに永続化します。

6. 構成パラメータのコピーで元の構成パラメータを置き換えます。

テナントレベルの構成パラメータのプロセスはクラスタレベルの構成パラメータと同じですが、唯一の違いは構成パラメータが存在する内部テーブルが異なることです。
