# カラムストアレプリカ

カラムストアレプリカは読み取り専用レプリカと同様に、選挙やログ投票には参加せず、完全なSSTable/clog/MemTableを保持します。読み取り専用レプリカと比較して、カラムストアレプリカの最も顕著な特徴は、ユーザーテーブルのベースラインデータがカラムストア方式で保存される点です。ここでいうユーザーテーブルにはレプリケーションテーブルが含まれますが、インデックステーブル、内部テーブル、システムテーブルなどは含まれません。

カラムストアレプリカには主に以下の特徴があります：

* 完全なログ、MemTable、SSTableなどを含みます。

* Paxosメンバーグループを構成することはできません。Paxosメンバーとしてログ投票には参加せず、観察者としてPaxosメンバーのログをリアルタイムで追従し、ローカルで再生するため、投票メンバーの増加によるトランザクションコミットの遅延は発生しません。

* 業務上、データ読み取りの一貫性に対する要求が高くない場合、読み取り専用サービスを提供できます。

* 同一のログストリーム上で、ユーザーテーブルはMajor SSTableレベルでカラムストアモードで保存されます。

* 他のレプリカタイプに変換することはできません。

その他の機能と説明は以下の表のとおりです。

|      機能項目           |                      説明                       |
|----------------------|-----------------------------------------------|
| レプリカ名および略称        | COLUMNSTORE(C)                                   |
| LOGの有無           | あり。非同期ログですが、Paxosグループには属さず、単なるリスナー(ASYNC_CLOG)です |
| MemTableの有無          | あり(WITH_MEMSTORE)                              |
| SSTableの有無          | あり(WITH_SSSTORE)       |
| データセキュリティ         | 中                                             |
| リーダーへの復旧時間     | サポートされていません                                           |
| リソースコスト           | 高                                             |
| サービス                 | 非一貫性読み取りが可能                                        |
| レプリカタイプ変換制限     | 他のレプリカタイプへの変換はできません                                   |
