# テナントリソースの水平スケーリング

テナントリソースの水平管理とは、主にリソースプールの `UNIT_NUM` を調整することで、テナントの利用可能なリソースを動的に変更することです。具体的には、リソースプールの `UNIT_NUM` を調整することで、プール内の各ゾーンにおけるユニット数を変更し、その結果、該当するゾーン上でのテナントのサービス能力を向上または低下させることができます。

V4.x以前のバージョンでは、OceanBaseデータベースはテナントの同一構成ゾーンモードのみをサポートしていました。同一構成ゾーンモードでは、テナント内の各ゾーンの `UNIT_NUM` がすべて同一である必要がありました。

V4.2.5バージョンから、OceanBaseデータベースはV4.2.5 BP5バージョン以降、テナントの異構成ゾーンモードをサポートしています。異構成ゾーンモードでは、テナント内の各ゾーンの `UNIT_NUM` は同一でも異なっても構いませんが、一つのテナントの全ゾーンで使用できる `UNIT_NUM` の種類は最大で2種類までです。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>通常、既存のテナントやアップグレードされたテナントについては、デフォルトで同一構成ゾーンモードになっています。異構成ゾーンモードを有効にする場合は、テナントレベルの構成パラメータ <code>zone_deploy_mode</code> の値を <code>hetero</code>（異構成ゾーンモード）に変更する必要があります。変更後、<code>homo</code>（同一構成ゾーンモード）に戻すことはできません。</p>
</main>

`UNIT_NUM` の変更には、`UNIT_NUM` を増やす場合と減らす場合の2種類があります：

* 同一構成ゾーンモードでデプロイされたテナントについて：

  * リソースプールがテナントに付与されていない場合、個別にリソースプールの `UNIT_NUM` を増減できます。

  * リソースプールがテナントに付与されている場合、テナントに付与されたすべてのリソースプールの `UNIT_NUM` を同時に調整するしかなく、個別に調整することはできません。

* 異構成ゾーンモードでデプロイされたテナントについては、リソースプールがテナントに付与されているかどうかに関係なく、調整が可能です。つまり、テナントに付与されたすべてのリソースプールの `UNIT_NUM` を同時に調整することも、個別にリソースプールの `UNIT_NUM` を増減することもサポートされています。

`UNIT_NUM` を増減することは、本質的にユニットの追加と削除を行うことです。リソースプールの `UNIT_NUM` を調整するためのサンプルステートメントは以下のとおりです：

```shell
obclient> CREATE RESOURCE POOL rp1 UNIT 'uc1', UNIT_NUM 2, ZONE_LIST ('zone1', 'zone2');
```

1. 異構成ゾーンモードのリソースプール、または同一構成ゾーンモードでテナントに付与されていないリソースプールについて、個別にリソースプールの `UNIT_NUM` を調整します：

    ```shell
    obclient> ALTER RESOURCE POOL rp1 UNIT_NUM 3; // UNIT_NUMを増やす

    obclient> ALTER RESOURCE POOL rp1 UNIT_NUM 2; // UNIT_NUMを減らす

    obclient> ALTER RESOURCE POOL rp1 UNIT_NUM 1 DELETE UNIT = (1001, 1003); // ユニットを指定してUNIT_NUMを減らす
    ```

2. テナントのすべてのリソースプールの `UNIT_NUM` を同時に調整します：

    ```shell
    obclient> CREATE RESOURCE POOL rp2 UNIT 'uc1', UNIT_NUM 2, ZONE_LIST ('zone1', 'zone2');

    obclient> CREATE RESOURCE POOL rp3 UNIT 'uc1', UNIT_NUM 2, ZONE_LIST ('zone3');

    obclient> CREATE TENANT tt RESOURCE_POOL_LIST = ('rp2', 'rp3') ...;

    obclient> ALTER RESOURCE TENANT tt UNIT_NUM = 3; // 2つのresource poolのUNIT_NUMを同時に増やす

    obclient> ALTER RESOURCE TENANT tt UNIT_NUM = 1; // 2つのResource PoolのUNIT_NUMを同時に減らす
    ```

## UNIT_NUMの増加

* `UNIT_NUM`を増やす例1：

  リソースプールを作成した後、個別に単一のリソースプールの`UNIT_NUM`を増やすことができます。

  ```shell
  obclient> CREATE RESOURCE POOL r_p0 UNIT 'uc1', UNIT_NUM 2, ZONE_LIST ('zone1', 'zone2', 'zone3');
  ```

  異種ゾーンモードのリソースプール、または同種ゾーンモードでテナントに付与されていないリソースプールについて、個別にリソースプールの`UNIT_NUM`を増やすステートメントは以下のとおりです。

  ```shell
  obclient> ALTER RESOURCE POOL r_p0 UNIT_NUM 3;
  ```

* `UNIT_NUM`を増やす例2：

  `UNIT_NUM`を増やすことは、通常、テナントの拡張シナリオで行われます。例えば、テナントに付与されたリソースプールの場合：

  ```shell
  obclient> CREATE RESOURCE POOL r_p0 UNIT 'uc1', UNIT_NUM 2, ZONE_LIST ('zone1', 'zone2', 'zone3');
  ```

  ```shell
  obclient> CREATE TENANT tt RESOURCE_POOL_LIST = ('r_p0');
  ```

  この例では、テナント`tt`がリソースプール`r_p0`を使用しています。`zone1`、`zone2`、`zone3`の各ゾーンにはそれぞれ2つのユニットがありますが、業務量の増加に伴い、各ゾーンの2つのユニットでは現在の業務量を処理できなくなります。そのため、新しいビジネス要件を満たすために、テナントのサービス能力を向上させるために`UNIT_NUM`を増やすことを検討する必要があります。

  以下のステートメントを使用して、リソースプール`r_p0`のユニット数を`3`に調整し、テナントのサービス能力を向上させることができます。

  ```sql
  obclient> ALTER RESOURCE TENANT tt UNIT_NUM = 3;
  ```

## UNIT_NUMを小さくする

* `UNIT_NUM` を小さくする例1：

  リソースプールを作成した後、個別のリソースプールの `UNIT_NUM` を小さくすることができます。

  ```shell
  obclient> CREATE RESOURCE POOL r_p0 UNIT 'uc1', UNIT_NUM 2, ZONE_LIST ('zone1', 'zone2', 'zone3');
  ```

  異種ゾーンモードのリソースプール、または同種ゾーンモードでテナントに付与されていないリソースプールについて、個別のリソースプールの `UNIT_NUM` を小さくするステートメントは次のとおりです：

  ```shell
  obclient> ALTER RESOURCE POOL r_p0 UNIT_NUM 1;
  ```

  指定されたUNITを削除することで、個別のリソースプールの `UNIT_NUM` を小さくすることもできます。ステートメントは次のとおりです：

  ```shell
  obclient> ALTER RESOURCE POOL r_p0 UNIT_NUM 1 DELETE UNIT=(1001,1002,1003);
  ```

* `UNIT_NUM` を小さくする例2：

  `UNIT_NUM` を小さくすることは、通常、テナントのスケーリングダウンのシナリオで行われます。例えば、テナントに付与されたリソースプールの場合：

  ```shell
  obclient> CREATE RESOURCE POOL r_p0 UNIT 'uc1', UNIT_NUM 2, ZONE_LIST ('zone1', 'zone2', 'zone3');
  ```

  ```shell
  obclient> CREATE TENANT tt RESOURCE_POOL_LIST = ('r_p0');
  ```

  この例では、テナント `tt` がリソースプール `r_p0` を使用しています。`zone1`、`zone2`、`zone3` の各ゾーンにはそれぞれ2つのUnitがありますが、業務の調整により、各ゾーンに2つのUnitを必要としなくなったため、新しいビジネスニーズを満たすために `UNIT_NUM` を小さくすることを検討する必要があります。

  以下のステートメントを使用して、リソースプール `r_p0` 内のテナントのUnit数を `1` に調整し、テナントのサービス能力を低下させることができます。

  ```shell
  obclient> ALTER RESOURCE TENANT tt UNIT_NUM = 1;
  ```

  また、同種ゾーンモードでは、指定された `UNIT_GROUP` を削除することで `UNIT_NUM` の数を小さくすることもできます。

  ```shell
  obclient> ALTER RESOURCE TENANT tt  UNIT_NUM = 1 DELETE UNIT_GROUP =(1001);
  ```
