# 分散実行計画の管理

分散実行計画はHintを使用して管理し、SQLクエリのパフォーマンスを向上させることができます。

分散実行フレームワークでサポートされているHintには、`ORDERED`、`LEADING`、`USE_NL`、`USE_HASH`、`USE_MERGE`などがあります。

## PARALLELヒント

分散実行の並列度を指定します。以下の例のように、3つのWorkerを有効化してスキャンを並列実行します。

```sql
obclient> SELECT /*+ PARALLEL(3) */ MAX(L_QUANTITY) FROM tbl1;
```
OceanBaseデータベースは、テーブルレベルの`PARALLEL`ヒントもサポートしており、構文は以下のとおりです。
```sql
/*+ PARALLEL(table_name n) */
```
グローバルな並列度とテーブルレベルの並列度を同時に指定した場合、テーブルレベルの並列度は適用されません。

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>複雑なクエリでは、スケジューラーが2つのDFOを並列的にパイプライン実行することがあります。この場合、有効なWorkerの数は並列度の2倍、すなわち<code>PARALLEL * 2</code>となります。</p>
  </main>

## ORDEREDヒント

`ORDERED` ヒントは、パラレルクエリ計画内の `JOIN` の順序を指定し、`FROM` ステートメント内の順序に厳密に従って生成されるよう強制します。

以下の例のように、`customer` を左テーブル、`orders` を右テーブルとして強制的に指定し、`NESTED LOOP JOIN` を使用します：

```sql
obclient> CREATE TABLE lineitem(
    l_orderkey           NUMBER(20) NOT NULL ,
    l_linenumber         NUMBER(20) NOT NULL ,
    l_quantity           NUMBER(20) NOT NULL ,
    l_extendedprice      DECIMAL(10,2) NOT NULL ,
    l_discount           DECIMAL(10,2) NOT NULL ,
    l_tax                DECIMAL(10,2) NOT NULL ,
    l_shipdate           DATE NOT NULL,
    PRIMARY KEY(L_ORDERKEY, L_LINENUMBER));
Query OK, 1 row affected

obclient> CREATE TABLE customer(
    c_custkey            NUMBER(20) NOT NULL ,
    c_name               VARCHAR(25) DEFAULT NULL,
    c_address            VARCHAR(40) DEFAULT NULL,
    c_nationkey          NUMBER(20) DEFAULT NULL,
    c_phone              CHAR(15) DEFAULT NULL,
    c_acctbal            DECIMAL(10,2) DEFAULT NULL,
    c_mktsegment         CHAR(10) DEFAULT NULL,
    c_comment            VARCHAR(117) DEFAULT NULL,
    PRIMARY KEY(c_custkey));
Query OK, 1 row affected

obclient> CREATE TABLE orders(
    o_orderkey           NUMBER(20) NOT NULL ,
    o_custkey            NUMBER(20) NOT NULL ,
    o_orderstatus        CHAR(1) DEFAULT NULL,
    o_totalprice         DECIMAL(10,2) DEFAULT NULL,
    o_orderdate          DATE NOT NULL,
    o_orderpriority      CHAR(15) DEFAULT NULL,
    o_clerk              CHAR(15) DEFAULT NULL,
    o_shippriority       NUMBER(20) DEFAULT NULL,
    o_comment            VARCHAR(79) DEFAULT NULL,
    PRIMARY KEY(o_orderkey,o_orderdate,o_custkey));
Query OK, 1 row affected

obclient> INSERT INTO lineitem VALUES(1,2,3,6.00,0.20,0.01,'01-JUN-02');
Query OK, 1 row affected

obclient> INSERT INTO customer VALUES(1,'Leo',null,null,'1390000****',null,'BUILDING',null);
Query OK, 1 row affected

obclient> INSERT INTO orders VALUES(1,1,null,null,'01-JUN-20',10,null,8,null);
Query OK, 1 row affected

obclient>SELECT /*+ ORDERED USE_NL(orders) */o_orderdate, o_shippriority
        FROM customer, orders WHERE c_mktsegment = 'BUILDING' AND
         c_custkey = o_custkey GROUP BY o_orderdate, o_shippriority;

+-------------+----------------+
| O_ORDERDATE | O_SHIPPRIORITY |
+-------------+----------------+
| 01-JUN-20   |              8 |
+-------------+----------------+
1 row in set
```

手書きのSQLでは、ユーザーが `JOIN` の最適な順序を把握している場合、`ORDERED` ヒントを追加することで、テーブルを `FROM` 句の後に順序通りに記述できるため、`ORDERED` ヒントは非常に役立ちます。

## LEADINGヒント

`LEADING` ヒントは、パラレルクエリ計画で最初に `JOIN` するテーブルを指定します。`LEADING` 内のテーブルの左から右の順序が `JOIN` の順序となります。これは `ORDERED` よりも柔軟性があります。
  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p><code>ORDERED</code> と <code>LEADING</code> ヒントを同時に使用した場合、<code>ORDERED</code> ヒントのみが有効になります。</p>
  </main>

## PQ_DISTRIBUTE ヒント

PQ ヒント、すなわち `PQ_DISTRIBUTE` は、パラレルクエリ計画内のデータ配布方法を指定するために使用されます。PQ ヒントは、分散 `JOIN` 時のデータ配布方法を変更します。

PQ ヒントの基本構文は以下のとおりです：

```sql
PQ_DISTRIBUTE(tablespec outer_distribution inner_distribution)
```

パラメータの説明は以下のとおりです：

* `tablespec` は対象となるテーブルを指定します。`JOIN` の右テーブルに注目します。

* `outer_distribution` は左テーブルのデータ配布方法を指定します。

* `inner_distribution` は右テーブルのデータ配布方法を指定します。

二つのテーブルのデータ配布方法は、以下の六種類があります：

* `HASH`, `HASH`

* `BROADCAST`, `NONE`

* `NONE`, `BROADCAST`

* `PARTITION`, `NONE`

* `NONE`, `PARTITION`

* `NONE`, `NONE`

その中で、パーティションを伴う二つの配布方法では、左テーブルまたは右テーブルにパーティションが存在し、かつパーティションキーが `JOIN` のキーである必要があります。要件を満たさない場合、PQ ヒントは効果を発揮しません。

```sql
obclient> CREATE TABLE t1(c1 INT PRIMARY KEY, c2 INT, c3 INT, c4 DATE);
Query OK, 0 rows affected

obclient> CREATE INDEX i1 ON t1(c3);
Query OK, 0 rows affected

obclient> CREATE TABLE t2(c1 INT(11) NOT NULL, c2 INT(11) NOT NULL, c3 INT(11) NOT NULL, PRIMARY KEY (c1, c2, c3)) PARTITION BY KEY(c2) PARTITIONS 4;
Query OK, 0 rows affected

obclient> EXPLAIN BASIC SELECT /*+USE_PX PARALLEL(3) PQ_DISTRIBUTE
        (t2 BROADCAST NONE) LEADING(t1 t2)*/ * FROM t1 JOIN t2 ON
         t1.c2 = t2.c2\G
*************************** 1. row ***************************
Query Plan:
================================================
|ID|OPERATOR                          |NAME    |
------------------------------------------------
|0 |EXCHANGE IN DISTR                 |        |
|1 | EXCHANGE OUT DISTR               |:EX10001|
|2 |  HASH JOIN                       |        |
|3 |   EXCHANGE IN DISTR              |        |
|4 |    EXCHANGE OUT DISTR (BROADCAST)|:EX10000|
|5 |     PX BLOCK ITERATOR            |        |
|6 |      TABLE SCAN                  |t1      |
|7 |   PX BLOCK ITERATOR              |        |
|8 |    TABLE SCAN                    |t2      |

```

## USE_NLヒント

`USE_NL` ヒントは `NESTED LOOP JOIN` の使用を指定し、かつ `USE_NL` で指定されたテーブルが `JOIN` の右テーブルである必要があります。

以下の例のように、`join1` を `NESTED LOOP JOIN` としたい場合、ヒントの書き方は `LEADING(a, (b,c)) USE_NL((b,c))` です。

`USE_NLJ` ヒントを `ORDERED`、`LEADING` ヒントと併用する場合、`USE_NLJ` で指定されたテーブルが右テーブルでない場合、`USE_NLJ` ヒントは無視されます。

## USE_HASHヒント

`USE_HASH` ヒントは `HASH JOIN` の使用を指定し、かつ `USE_HASH` で指定されたテーブルが `JOIN` の右テーブルである必要があります。

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p><code>ORDERED</code> および <code>LEADING</code> ヒントを使用しておらず、かつオプティマイザーが生成した結合順序で指定されたテーブル間に直接的な <code>JOIN</code> 関係がない場合、<code>USE_HASH</code> ヒントは無視されます。</p>
  </main>

## USE_MERGEヒント

`USE_MERGE` ヒントは `MERGE JOIN` の使用を指定し、かつ `USE_MERGE` で指定されたテーブルが `JOIN` の右テーブルである必要があります。

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p><code>ORDERED</code> および <code>LEADING</code> ヒントを使用しておらず、かつオプティマイザーが生成した結合順序で指定されたテーブル間に直接的な <code>JOIN</code> 関係がない場合、<code>USE_MERGE</code> ヒントは無視されます。</p>
  </main>
