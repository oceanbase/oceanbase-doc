# PL実行メカニズム

​OceanBaseデータベースのPLコードは、コンパイル実行のみをサポートしています。本記事では、主にPLエンジンとOBServerおよびSQLエンジン間の実行メカニズムについて説明します。

コンパイル実行は、解釈実行よりもパフォーマンスの面で優れています。特に、PLエンジン内部で計算要素が多いシナリオにおいて、パフォーマンスの向上が顕著になります。

​コンパイル実行のフレームワークでは、PLソースコードが直接対応するプラットフォームの実行可能なコードにコンパイルされます。PLエンジンが実行される際、OBServerはコンパイル済みの実行可能なコードを直接呼び出します。同時に、コンパイル済みのPLコードはPLキャッシュにキャッシュされるため、同じPLコードは一度だけコンパイルすれば済みます。

​![PL](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.2.1/700.reference/100.oceanbase-database-concepts/700.user-interface-and-query-language/200.pl-execution-mechanism/1.PL.png)

PLコードは定義時にOBServerに保存され、アプリケーションがストアドプロシージャを呼び出すと、まずデータ辞書からPLコードの定義を読み取り、次にその定義を実行可能なバイナリコードにコンパイルしてPLキャッシュに保存します。実行時にはPLエンジンがPLキャッシュから実行可能なコードを取得し、SQLエンジンと協力してPLコードを実行します。

​ストアドプロシージャ間でネストされた呼び出しを行うことができます。例えば、現在のPLブロックから別のストアドプロシージャを呼び出すことも可能です。
