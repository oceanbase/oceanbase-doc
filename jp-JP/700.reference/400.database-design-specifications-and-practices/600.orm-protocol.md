# ORMの使用規約

ORMとは、オブジェクト関係マッピング(Object Relational Mapping、略称ORM)のことで、オブジェクト指向言語とリレーショナルデータベースの異なる型体系の間でデータを変換する技術です。これにより、プログラムからはデータベースを「仮想的なオブジェクトデータベース」として扱えます。

* resultClassを戻り値パラメータとして使用しないでください。すべてのクラス属性名がデータベースフィールドと一対一で対応している場合でも、マッピングを明示的に定義してください。各テーブルについても対応するマッピングが必要です。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>マッピング関係を設定することで、フィールドとDOクラスを分離し、保守を容易にします。</p>
  </main>

* sql.xml設定におけるパラメータについて注意：`#{}` と `#param#` 内で `${}` を使用しないでください。この方法ではSQLインジェクションが発生しやすくなります。

* iBATISに組み込まれている `queryForList(String statementName,int start,int size)` の使用は推奨されません。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>このメソッドは、statementNameに対応するSQL文の結果をすべて取得してから、subListでstartとsizeが指定する範囲を取り出します。このため、本番環境でOOMが発生した事例があります。この問題を解決する方法として、sqlmap.xmlに <code>#start#</code>, <code>#size#</code> を導入することができます。例：</p>
    <pre><code class="language-unknow">
    Map<String, Object> map = newHashMap<String, Object>();
    map.put("start", start);
    map.put("size", size);
    </code></pre>
  </main>

* HashMapやHashTableを直接クエリ結果セットの出力として使用することは許可されていません。

  失敗例：ある開発者は `<resultMap>` の記述を省き、データベースから返された結果をHashTableで直接受け取りました。普段はLongに変換されていたbigintが、データベースのバージョンが異なる本番環境ではBigIntegerに変換され、障害が発生しました。

* データテーブルレコードを更新する際には、レコードに対応するgmt_modifiedフィールドの値を現在時刻に更新する必要があります。

* POJOを引数に取り、更新対象かどうかにかかわらずすべてのフィールドを更新する汎用インターフェースは作成しないでください。たとえば、常に`update table set c1=value1,c2=value2,c3=value3;` を実行するのは正しくありません。SQLを実行する際には、変更されていないフィールドを更新しないでください。一つにはエラーが発生しやすいこと、二つには効率が低いこと、三つにはbinlogの使用容量が増えることが挙げられます。
