# データベース接続仕様

本記事では、OceanBaseにおけるデータベース接続の仕様について説明します。

* 接続プールを使用する場合は、接続の最大アイドル時間を設定する必要があります。

* フロントエンドプログラムがデータベースまたはデータベースプロキシ層に接続する際、JDBCでは、接続タイムアウトを1秒に設定することを推奨します。接続に失敗した場合は、間隔を空けて再接続する仕組みが必要です。

* プログラム側のログには、データベース接続に関する標準的なOceanBaseエラーコードおよび接続先のデータベース情報（IPアドレス、ポート、データベースユーザー名など）を記録する必要があります。これはDBAによる障害調査に利用されます。

* 接続プールを使用するフロントエンドプログラムでは、業務要件に応じて初期接続数、最小接続数、最大接続数を設定する必要があります。タイムアウトは30秒を推奨します。接続の有効性チェックまたはアイドルタイムアウトを設定し、接続を回収する仕組み（最大3600秒）も設定する必要があります。

* プログラム側で使用するデータベース接続用の共有ライブラリ（.so）、JARファイル、およびクライアントデータベースのバージョンは、本番データベースサーバーのバージョンと互換性がある必要があります。

* DB切り替えについて、`use <dbname>` の実行は推奨されません。`Connection.setCatalog(dbname)` インターフェースの使用を推奨します。

* ReadOnlyの設定について、`set session transaction readonly` の実行は推奨されません。`Connection.setReadOnly(xx)` インターフェースの使用を推奨します。

* トランザクションを実行する際は、SQL文の数にかかわらず、実行前に必ず `getConnection` を再度実行し、実行後には `close connection` を実行する必要があります。接続を取得してから閉じるまでに実行できるトランザクションは1つだけです。`getConnection`、トランザクションの実行、`close connection` の順に処理します。現在のOceanBaseでは、各トランザクションの開始から実行、終了までをすべて同じサーバーで行う必要があるためです。Aサーバーで開始されたトランザクションがBサーバーでも有効であるとは保証されません。このため、Java Connectorでは、現在の接続がトランザクション中の場合、次のSQL文も直前と同じサーバーにルーティングする必要があります。現在の接続がトランザクション外の場合は、次のSQL文に応じて最適なサーバーにルーティングできます。
