# ユーザー名の命名規則

データベースの使用にあたり、開発者は様々なユーザーを作成し、これらのユーザーを通じてデータベース操作を行います。ユーザー作成時には、一定の命名規則に従うことが望まれます。本記事は、開発者がデータベース内のユーザー名を規範化する一助となることを目的としています。本記事の命名ルールはすべて推奨事項であり、開発者の参考としてください。

本記事で紹介するユーザー名の命名規則は、ユーザー機能によって区分されており、異なる業務では異なるシナリオに基づいて区分することができます。本記事はあくまで一例です。データベース内の非システムユーザーは、機能に応じて大まかに以下のカテゴリに分類できます：業務オブジェクト所有者ユーザー、アプリケーションデータベースアクセスユーザー、ツール系ユーザー、監視系ユーザー、データバックアップユーザー、データベース管理ユーザー、テスト汎用ユーザーなどです。各機能のユーザーに対する命名規則はそれぞれ以下の通りです。

* **業務オブジェクト所有者ユーザー**

  業務オブジェクト所有者ユーザーは、データベース内のオブジェクトの作成やメンテナンスなどを担当します。この種のユーザーに対する命名ルールは「サブシステム略称 + data」です。例：サブシステム略称が abs の場合、ユーザー名は "absdata" となります。

* **アプリケーションデータベースアクセスユーザー**

  アプリケーションデータベースアクセスユーザーは、主にデータベースへの接続と業務データのアクセス・操作を担当します。この種のユーザーに対する命名ルールは「サブシステム略称 + opr」です。例：サブシステム略称が abs の場合、ユーザー名は "absopr" となります。

* **ツール系ユーザー**

  データベース内には多くのツール系ユーザーが存在します。例えば、データ移行に使用されるユーザーなどです。移行ツールのタイプに基づいて命名することも検討できます。例：
  * kettle ユーザー、命名ルールは「サブシステム略称 + ktl」です。例：サブシステム略称が abs の場合、ユーザー名は "absktl" となります。

  * sqoop ユーザー、命名ルールは「サブシステム略称 + sqp」です。例：サブシステム略称が abs の場合、ユーザー名は "abssqp" となります。

* **監視系ユーザー**

  データベースでは、専用の監視ユーザーを作成できます。名前は dbmonopr とします。

* **データバックアップユーザー**

  データベース内でバックアップ専用に使用されるユーザーです。命名ルールは「サブシステム略称 + bak」です。例：サブシステム略称が abs の場合、ユーザー名は "absbak" となります。

* **データベース管理ユーザー**

  データベース管理ユーザーは DBA ユーザーであり、データベースの管理に使用されます。名前は "dbmgr" とします。本番データベースとテストデータベースを区別するため、テストデータベース内の DBA ユーザーを "testmgr" と命名することもできます。

* **テスト汎用ユーザー**

  テストデータベースでデータベース操作を行う、権限が高くテスト担当者が使用するユーザーです。命名ルールは「サブシステム略称 + test」です。例：サブシステム略称が abs の場合、ユーザー名は "abstest" となります。
