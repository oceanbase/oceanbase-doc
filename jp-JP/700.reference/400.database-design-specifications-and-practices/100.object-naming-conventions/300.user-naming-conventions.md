# ユーザー名の命名規則

データベースを使用する際、開発者はさまざまなユーザーを作成し、これらのユーザーを通じてデータベース操作を行います。ユーザーを作成する際には、ユーザー名に一定の規則に従うことが望ましいです。本記事は、開発者がデータベース内のユーザー名を規範的に命名するための参考となるよう作成されました。本記事の命名ルールはすべて推奨事項であり、開発者の参考としてください。

本記事で紹介するユーザー名の命名規則は、ユーザー機能に基づいて区別されており、異なる業務ではそれぞれのシナリオに応じて区別することができます。本記事はあくまでも一例です。データベース内の非システムユーザーは、機能に応じて大まかに以下のカテゴリに分類できます：業務オブジェクトの所有者ユーザー、アプリケーションによるデータベースへのアクセスユーザー、ツール系ユーザー、モニタリング系ユーザー、データバックアップユーザー、データベース管理ユーザー、テスト用ユーザーなど。各機能に対するユーザーの命名規則は以下の通りです。

* **業務オブジェクトの所有者ユーザー**

  業務オブジェクトの所有者ユーザーは、データベース内のオブジェクトの作成や維持管理などを担当します。この種のユーザーに対する命名ルールは「サブシステム略称 + data」です。例：サブシステムの略称がABSの場合、このユーザーの名前は「absdata」となります。

* **アプリケーションによるデータベースへのアクセスユーザー**

  アプリケーションによるデータベースへのアクセスユーザーは、主にデータベースに接続して業務データへのアクセスと操作を担当します。この種のユーザーに対する命名ルールは「サブシステム略称 + opr」です。例：サブシステムの略称がABSの場合、このユーザーの名前は「absopr」となります。

* **ツール系ユーザー**

  データベース内には多くのツール系ユーザーが存在します。例えば、データ移行を行うユーザーは、移行ツールの種類に基づいて命名することが考えられます。例：
  * Kettleユーザーの命名ルールは「サブシステム略称 + ktl」です。例：サブシステムの略称がABSの場合、このユーザーの名前は「absktl」となります。

  * Sqoopユーザーの命名ルールは「サブシステム略称 + sqp」です。例：サブシステムの略称がABSの場合、このユーザーの名前は「abssqp」となります。

* **モニタリング系ユーザー**

  データベース内には、専用のモニタリングユーザーを作成できます。その名前はdbmonoprとします。

* **データバックアップユーザー**

  データベース内でバックアップ専用のユーザーです。命名ルールは「サブシステム略称 + bak」です。例：サブシステムの略称がABSの場合、このユーザーの名前は「absbak」となります。

* **データベース管理ユーザー**

  データベース管理ユーザーはDBAユーザーであり、データベースの管理を担当します。その名前は「dbmgr」とします。本番データベースとテストデータベースを区別するため、テストデータベース内のDBAユーザーを「testmgr」と命名することもできます。

* **テスト用ユーザー**

  テストデータベース内でデータベース操作を行う、権限が高くテスターが使用するユーザーです。命名ルールは「サブシステム略称 + test」です。例：サブシステムの略称がABSの場合、このユーザーの名前は「abstest」となります。
