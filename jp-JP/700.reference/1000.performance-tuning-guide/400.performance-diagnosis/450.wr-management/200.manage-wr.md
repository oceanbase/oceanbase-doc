# WRの管理

OceanBaseデータベースはDBMSパッケージを提供しており、このパッケージを使用してWR関連のクラスタスナップショットを管理できます。これには、手動でスナップショットを作成したり、特定のスナップショットを削除したり、タイマースレッドの時間間隔を変更することでクラスタスナップショットの収集頻度を調整したりする操作が含まれます。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>この機能はsysテナントでのみ使用でき、アップグレード中は利用できません。</p>
</main>

## スナップショットの作成

WRは自動的にスナップショットを作成しますが、スナップショットの収集時点を調整する必要がある場合は、手動で新しいクラスタスナップショットを作成できます。手動で作成後、タイマーは新しく設定された時間間隔でデータを収集します。コマンドは以下のとおりです：

```sql
DBMS_WORKLOAD_REPOSITORY.CREATE_SNAPSHOT(
    flush_level  VARCHAR(64) DEFAULT 'TYPICAL'
    );
```

ここで、`flush_level` の値は現在、定期スナップショット(TYPICAL)のみをサポートしています。つまり、ほとんどの統計データは定期スナップショットモードでのみ収集されます。例：

```shell
obclient(root@sys)[(none)]> CALL DBMS_WORKLOAD_REPOSITORY.CREATE_SNAPSHOT(flush_level => 'TYPICAL');
```

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>手動でスナップショットを作成すると、タイマーはリセットされます。例えば、デフォルトの1時間間隔で定期スナップショットを有効にした場合：<ul><li>12:21 タイマーが発生し、スナップショットを作成します  </li><li>13:21 タイマーが発生し、次のスナップショットを作成します </li><li>13:45 ユーザーが手動でスナップショットを作成します </li><li>14:45 タイマーが発生し、次のスナップショットを作成します </li></ul>手動でスナップショットを作成した後、タイマーは設定された間隔で次のスナップショットの生成をトリガーし続けます。</p>
</main>

## スナップショットポリシーの設定

### スナップショット間隔と保持時間の設定

スナップショット間隔と保持時間を変更することで、クラスタスナップショットの収集頻度を調整します。コマンドは以下のとおりです：

```sql
DBMS_WORKLOAD_REPOSITORY.MODIFY_SNAPSHOT_SETTINGS(
   retention          INT    DEFAULT  NULL,
   interval           INT    DEFAULT  NULL,
   topnsql            INT    DEFAULT  NULL,
   sqlstat_interval   INT    DEFAULT  NULL
   );
```

関連フィールドの説明は以下のとおりです：

| フィールド | 説明 |
|------|-----|
| retention | スナップショットの保持時間です。この時間を超えるスナップショットは自動的に削除されます。単位は分です。[1440分（1日）、52560000分（100年）]の範囲です。<ul><li>値を0に指定した場合、永遠に保持されます。保持時間は57816000分（110年）に設定されます。  </li><li>値をNULLに指定した場合、元の保持時間が維持されます。 </li></ul>|
| interval | 各スナップショット間の間隔設定です。単位は分です。[10分、525600分（1年）]の範囲です。<ul><li>値を0に指定した場合、自動および手動スナップショットが無効になり、保持時間としてより大きなシステム定義値（110年）が使用されます。</li><li>値をNULLに指定した場合、現在の間隔設定が維持されます。</li></ul>|
| topnsql | WRがSQLSTATをディスクに書き込む際に記録するデータ数です。[30、50000]の範囲です。 |
| sqlstat_interval|  SQLSTATスナップショットをディスクに書き込む時間間隔です。単位は分です。|

例えば、各スナップショットの保持時間を2265分（約1日12時間）、各スナップショット間の間隔を16分に設定し、ディスク書き込み時に30件のSQLSTATデータを記録し、SQLSTATスナップショットのディスク書き込み時間間隔を5分に設定します。例：

```shell
obclient(root@sys)[(none)]> CALL DBMS_WORKLOAD_REPOSITORY.MODIFY_SNAPSHOT_SETTINGS('2265','16', 30, 5);
```

* `oceanbase.CDB_WR_CONTROL` ビューで、すべてのテナントのWR関連設定情報を確認します。

  ```shell
  obclient(root@sys)[(none)]> SELECT * FROM oceanbase.CDB_WR_CONTROL;
  ```

  実行結果は次のとおりです：

  ```shell

    1 row in set (0.018 sec)
  ```

  | **フィールド** | **説明** |

## スナップショットの削除

<main id="notice" type='notice'>
  <h4>注意</h4>
  <ol><li>削除するスナップショットIDがシステム内に有効に存在するIDであることを確認してください。</li><li>削除操作を実行すると、指定された範囲内のスナップショットデータが永久に削除されます。慎重に操作してください。</li></ol>
</main>

削除するスナップショットの範囲の開始および終了スナップショットIDを指定し、指定範囲内のスナップショットデータを削除するコマンドは以下のとおりです：

```sql
DBMS_WORKLOAD_REPOSITORY.DROP_SNAPSHOT_RANGE(
    low_snap_id    INT,
    high_snap_id   INT
    );
```

関連フィールドの説明は以下のとおりです：

| フィールド | 説明 |
|------|-----|
| low_snap_id | 削除するスナップショットの開始スナップショットID |
| high_snap_id | 削除するスナップショットの終了スナップショットID |

**スナップショットを削除する手順は以下のとおりです：**

1. まず、テナント内のすべてのSNAP_IDを取得します。

    ```shell
    obclient(root@sys)[(none)]> select count(1),min(snap_id), max(snap_id) from oceanbase.DBA_WR_SNAPSHOT;
    ```

    実行結果は次のとおりです：

    ```shell
    +-----------+--------------+--------------+
    | count(1) | min(snap_id) | max(snap_id) |
    +-----------+--------------+--------------+
    |         1 |            2 |            2 |
    +-----------+--------------+--------------+
    1 row in set (0.039 sec)
    ```

2. SNAP_IDの範囲内のスナップショットデータを削除します。

    ```shell
    obclient(root@sys)[(none)]> CALL DBMS_WORKLOAD_REPOSITORY.DROP_SNAPSHOT_RANGE('2','2');
    Query OK, 0 rows affected (1.018 sec)
    ```

3. SNAP_IDが正常に削除されたかどうかを確認します。

    ```shell
    obclient(root@sys)[(none)]> select count(1),min(snap_id), max(snap_id) from oceanbase.DBA_WR_SNAPSHOT;
    ```
