# ASHの概要

## ASHの概要

ASH（Active Session History）は、データベース内のすべてのアクティブセッション情報を記録するための診断ツールです。

ASHレポート（OceanBase Active Session History Report）は、瞬間的に発生した異常を特定できる分析レポートを提供します。パフォーマンスレポートと比較して、より細かい粒度の診断情報を提供できます。一般的なパフォーマンスレポートは、時間単位のスナップショット情報をカバーしており、問題の診断粒度はセッションレベルまで深く掘り下げることができません。そのため、一部の瞬間的なジッター情報はパフォーマンスレポートから詳細な実行内容を得ることが難しいのです。このような問題を解決するために、セッションレベルの細かい粒度の診断情報を提供するASHレポートを利用できます。

ASHレポートはデフォルトで有効なバックグラウンドパフォーマンス収集タスクであるため、パフォーマンス問題を分析する際には、手動で関連パラメータを開いて問題を再現する必要はありません。問題が発生した時間帯を明確にし、関連コマンドを呼び出すだけで、問題発生時のパフォーマンスデータを収集できます。

## 適用シナリオ

ASHレポートは、瞬間的に発生する異常シナリオの診断に使用されます。これらのシナリオでは通常、細かい粒度、リアルタイム、またはセッションレベルの分析機能が必要です。以下のシナリオでの使用を推奨します：

* リアルタイムの動的問題診断。

  例えば、特定の時間帯にSQL応答時間が急激に上昇したり、システムリソースがボトルネックに遭遇したりする場合、従来のモニタリングではデータベースシステムのすべてのアクティブセッションを観察することができません。

* ディストリビューションシステムのノード間問題。

  OceanBaseデータベースのSQL実行チェインは、通常複数のOBServerノードに関与します。ASHはTRACE_ID/SQL_IDなどの情報を通じて、複数ノードの実行情報を関連付けることができます。

* SQL実行段階の診断。

  ASHは、SQL演算子レベルの実行を観察する新しい手段として機能します。待機イベントや実行段階などの情報を組み合わせることで、PLAN_MONITORなどの他のトラブルシューティング手段では提供できない情報を提供できます。

* リソース競合と競争分析。

  複数のセッションが同一リソース（ロック、キャッシュなど）を争う、または特定のセッションが過剰なCPUを占有するなどのシナリオでは、ASHはリアルタイムのアクティブセッションの占有追跡と待機イベントの関連付けを通じてトラブルシューティングを行うことができます。

* セッションレベルの問題調査。

  単一セッションが長時間異常またはブロックされる、または長時間トランザクションなどのシナリオでは、ASHは対応するSESSION_IDを直接フィルタリングし、その履歴行動を分析し、根本原因を掘り下げることができます。これにより、PROCESSLISTよりも包括的な診断情報を提供できます。

* バックグラウンドタスクのオーバーヘッド分析。

  ASHモデルでは、バックグラウンドタスクはバックグラウンドセッションであり、Program/Module/Actionフィールドを使用してバックグラウンドタスクの属性をマークし、待機イベントなどの次元でバックグラウンドタスクの実行オーバーヘッドを細かく分析します。

* コールドスタートと初期化の問題。

  セッションの頻繁な接続確立・切断、SQL解析や計画生成の遅延などのシナリオでは、多くの場合従来のモニタリングでは見落とされることがあります。従来のモニタリングで「異常があるが原因が説明できない」と表示された場合は、ASHを使用して調査してみてください。

## 主な特徴

ASHレポートは軽量で常に有効なネイティブ診断ツールとして、従来のモニタリングとは異なります：

| 比較項目 | 従来型モニタリング | ASH分析手法 |
|-----|-----|-----|
| モニタリングの観点 | 閾値アラートメカニズム（例：CPU使用率 >90%） | 全履歴の遡及（秒単位のサンプリングによりデータベースの瞬時状態を復元） |
| デプロイの複雑さ | モニタリング指標とアラートルールの事前定義が必要 | ゼロ設定での接続（セッション/リソース/ロックなど200以上の観点を自動記録） |
| 診断の深さ | 異常の特定（問題ノードの識別） | 根因追跡（具体的なセッション、ロックタイプ、リソース競合チェーンの解析） |
| データ粒度 | 集計指標（例：分単位のCPU平均値） | 生スナップショット（セッションレベルの実行段階/待機イベントの詳細を保持） |

以下の主要な特徴により、従来のモニタリングを超えることが実現されています：

* すぐに使える。

  事前に監視項目を定義する必要はなく、データベースカーネルに組み込まれたサンプリングメカニズムを直接利用して、リアルタイムでセッションレベルの状態を記録します。

* セカンド単位の遡り。

  セカンド単位のサンプリングデータを通じて、任意の過去の時点のデータベース運用の詳細（セッション実行段階、リソース占有、ロック競合状態など）を完全に再現できます。

* 全景洞察。

  特定のセッションまたはSQLのブロック原因（例：「セッション123がロックを保持し解放しないためにブロックされている」）を特定できるだけでなく、グローバルリソース競合（例：「CPUの80％が特定のリソースグループに占有されている」）を分析することもできます。

このレポートを通じて、過去の診断時間内にデータベースリソースを高く占有したSQLや、OceanBaseクラスタの過去セッションの実行詳細などの情報を理解できます。これらの情報に基づいてSQLを最適化することで、SQLの実行効率を向上させることができます。
