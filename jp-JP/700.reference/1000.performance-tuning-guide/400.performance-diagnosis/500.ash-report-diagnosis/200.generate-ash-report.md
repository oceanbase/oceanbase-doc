# ASHレポートの生成

ASH PLパッケージを呼び出すことで、対応するASHレポートを生成できます。

## SQL構文

ASH PLパッケージの情報は、以下のいくつかのフィールドで構成されています：

:::tab
tab MySQLモード

```sql
obclient [oceanbase]> call dbms_workload_repository.ash_report(
  'BTIME',
  'ETIME',
  'SQL_ID',
  'TRACE_ID',
  'WAIT_CLASS',
  'REPORT_TYPE',
  'SVR_IP',
  'SVR_PORT',
  'TENANT_ID');
```

tab Oracleモード

```sql
obclient [SYS]> call dbms_workload_repository.ash_report(
  BTIME => 'xxxx',
  ETIME => 'xxxx',
  SQL_ID => 'xxxx',
  TRACE_ID => 'xxxx',
  WAIT_CLASS => 'xxxx',
  REPORT_TYPE => 'xxxx',
  SVR_IP => 'xxxx',
  SVR_PORT=> 'xxxx',
  TENANT_ID => 'xxxx');
```

:::

パラメータの説明は以下のとおりです：

| **パラメータ** | **説明** |
| --- | --- |
| BTIME | サンプリング開始時間。必須です。 |
| ETIME | サンプリング終了時間。必須です。 |
| SQL_ID | サンプリング対象のSQLの`SQL_ID`。このフィールドを指定しないか、`NULL`と指定する場合は、`SQL_ID`に制限がないことを意味します。 |
| TRACE_ID | サンプリング対象のSQLの`TRACE_ID`。このフィールドを指定しないか、`NULL`と指定する場合は、`TRACE_ID`に制限がないことを意味します。 |
| WAIT_CLASS | サンプリング対象のイベントタイプ。`WAIT_CLASS`の値は`GV$OB_ACTIVE_SESSION_HISTORY.WAIT_CLASS`フィールドの値を参照します。このフィールドを指定しないか、`NULL`と指定する場合は、待機タイプに制限がないことを意味します。 |
| REPORT_TYPE | レポートタイプ。現在は`HTML`と`TEXT`の2種類をサポートしています。このフィールドを指定しないか、`NULL`と指定する場合は、デフォルトで`TEXT`タイプとなります。 |
| SVR_IP | ASHレポートを生成するノードのIPアドレスを指定します。このフィールドを指定しないか、`NULL`と指定する場合は、`SVR_IP`に制限がないことを意味します。 |
| SVR_PORT | ASHレポートを生成するノードのポート番号を指定します。このフィールドを指定しないか、`NULL`と指定する場合は、`SVR_PORT`に制限がないことを意味します。 |
| TENANT_ID | ASHレポートを生成するテナントIDを指定します。このフィールドを指定しないか、`NULL`と指定する場合は、`TENANT_ID`に制限がないことを意味します。 |

<main id="notice" type='notice'>
  <h4>注意</h4>
  <ul>
  <li>異なるテナント間で、SVR_IP、SVR_PORT、TENANT_IDを制限しない場合の動作は次のとおりです：<ul><li>sysテナントについては、すべてのIPアドレス、ポート、およびテナントの情報を収集します。</li><li>ユーザーテナントについては、そのテナント内のすべてのIPアドレスとポートの情報を収集します。</li></ul></li>
  <li>MySQLモードでは、必須ではないフィールドのうちいずれかが明示的に特定の値に設定された場合、残りの必須ではないフィールドも明示的にNULLに設定する必要があり、省略してはなりません。</li></ul>
</main>

このパッケージに関する情報は、`GV$OB_ACTIVE_SESSION_HISTORY`ビューを照会することで取得できます。`GV$OB_ACTIVE_SESSION_HISTORY`ビューはセッションの活動情報を提供します。データベースに接続され、キュー待機中の任意のセッションは、アクティブなセッションと見なされます。各セッションのサンプリングは、`GV$OB_ACTIVE_SESSION_HISTORY`ビューから返される一連の行データによって実行され、セッションサンプリング期間中の各セッションはビュー内に表示されます。このビューの詳細については、[GV$OB_ACTIVE_SESSION_HISTORY(MySQLモード)](../../../700.system-views/400.system-view-of-mysql-mode/300.performance-view-of-mysql-mode/800.gv-ob_active_session_history-of-mysql-mode.md)および[GV$OB_ACTIVE_SESSION_HISTORY(Oracleモード)](../../../700.system-views/500.system-view-of-oracle-mode/300.performance-view-of-oracle-mode/900.gv-ob_active_session_history-of-oracle-mode.md)を参照してください。

## 手順

ASHレポートを生成する手順は以下のとおりです。

:::tab
タブ MySQLモード

1. テナント管理者としてクラスタのMySQLテナントにログインし、OceanBaseデータベースにアクセスします。

    ```shell
    $ obclient -h172.xx.xxx.xxx -Pxxxx -uroot@mysql -pxxxx -A
    ```

2. コンソール画面にレポート情報が表示されます。

    ASH PLパッケージを呼び出し、診断対象の開始時間、終了時間、および終了後のレポート表示形式を入力します。

    <main id="notice" type='explain'>
      <h4>説明</h4>
      <p>コンソール画面でレポート内容を確認する際は、表示形式をTEXTに設定することを推奨します。</p>
    </main>

    * 画面上でレポート内容をTEXT形式で表示します。

      診断開始時間を`2024-02-22 19:26:47`、診断終了時間を`2024-06-22 19:27:07`、レポート表示形式を`TEXT`に設定します。その他のフィールド値は必要に応じて設定します。

      ```shell
      obclient [test]> CALL DBMS_WORKLOAD_REPOSITORY.ASH_REPORT(  '2023-09-22 10:26:47',  '2024-06-22 20:27:07', NULL, NULL, NULL, 'TEXT', NULL, NULL, NULL);
      ```

      生成された一部の内容を抜粋します：

3. (オプション)ローカルでレポート情報を確認します。

   レポート内容をTXTファイルまたはHTMLページとして確認します。ここでは、HTML形式で生成されたものを例に説明します。

    1. フィジカルマシンにログインします。

        ```shell
        [admin@xxxxxx.eu95sqa /home/admin]
        ```

    2. ASHレポートスクリプトファイル`ash_report.html`を作成します。このスクリプトファイルは、OBServerが配置されているマシンに配置するだけで済みます。

        ```shell
        [admin@xxxxxx.eu95sqa /home/admin]
        $vim ash_report_my.html
        ```

    3. スクリプト内容を生成します。

        ```shell
        tee ash_report_my.html
        CALL DBMS_WORKLOAD_REPOSITORY.ASH_REPORT(  '2023-09-22 10:26:47',  '2024-06-22 20:27:07', NULL, NULL, NULL, 'HTML', NULL, NULL, NULL);
        notee
        ```

    4. データベースにログインし、`ash_report_my.html`スクリプトを実行します。

        ```shell
        $ obclient -h172.xx.xxx.xxx -Pxxxx -uroot@mysql -pxxxx -A
        ```

        ```shell
        obclient [test]> source ash_report_my.html;
        ```

        スクリプトの実行が成功すると、画面上にHTML形式のレポート内容が表示されます。

    5. データベースからログアウトし、フィジカルマシンに移動して`ash_report_my.html`ファイルのパスを確認します。

        ```shell
        [admin@k08j13249.eu95sqa /home/admin]
        $ls
        ALTER                              ash_report_my.html
        ```

        `ash_report_my.html`ファイルのパスが`home/admin/ash_report_my.html`であることが確認されました。

    6. フィジカルマシンからファイルをローカルにエクスポートします。

       1. 新しいShell画面を開き、ファイルを保存するパスに移動します。

          ```shell
          PS C:\Users\xxx\Desktop\ASH>
          ```

       2. `scp`コマンドを使用して、`ash_report_my.html`ファイルをフィジカルマシンからローカルマシンにインポートします。

          ```shell
          scp admin@xx.xx.xx.xx:/home/admin/ash_report_my.html  /
          ```

       3. ローカルパスで`ash_report_my.html`ファイルを開いて、レポート情報を確認します。
