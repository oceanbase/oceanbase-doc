# DELETE

`DELETE` 演算子は、指定された条件を満たすデータ行をデータテーブルから削除するために使用します。

OceanBaseデータベースでサポートされている `DELETE` 演算子には、`DELETE` と `DISTRIBUTED DELETE` があります。

## DELETE

`DELETE` 演算子は、データテーブルの単一パーティション内のデータを削除するために使用します。

以下の例のように、Q1 クエリはテーブル `t1` から `c2>'100'` を満たすすべての行を削除します。

```sql
--Oracleモードの場合：

obclient> CREATE TABLE t1 (c1 INT PRIMARY KEY, c2 VARCHAR2(10));
Query OK, 0 rows affected

obclient> CREATE TABLE t2 (c1 INT PRIMARY KEY, c2 VARCHAR2(10)) PARTITION BY
             HASH(c1) PARTITIONS 10;
Query OK, 0 rows affected

obclient> CREATE TABLE t3 (c1 INT PRIMARY KEY, c2 VARCHAR2(10));
Query OK, 0 rows affected

obclient> CREATE INDEX IDX_t3_c2 ON t3 (c2) PARTITION BY HASH(c2) PARTITIONS 3;
Query OK, 0 rows affected

--MySQLモードの場合：

obclient> CREATE TABLE t1 (c1 INT PRIMARY KEY, c2 INT);
Query OK, 0 rows affected

obclient> CREATE TABLE t2 (c1 INT PRIMARY KEY, c2 INT) PARTITION BY
             HASH(c1) PARTITIONS 10;
Query OK, 0 rows affected

obclient> CREATE TABLE t3 (c1 INT PRIMARY KEY, c2 INT);
Query OK, 0 rows affected

obclient> CREATE INDEX IDX_t3_c2 ON t3 (c2) PARTITION BY HASH(c2) PARTITIONS 3;
Query OK, 0 rows affected
Q1:
obclient> EXPLAIN DELETE FROM t1 WHERE c2 > '100';

Query Plan:

|ID|OPERATOR   |NAME|EST. ROWS|COST  |
--------------------------------------

|1 | TABLE SCAN|T1  |10000    |108697|

Outputs & filters:

  1 - output([T1.C1], [T1.C2]), filter([T1.C2 > '100']),
      access([T1.C1], [T1.C2]), partitions(p0)
```

上記の例では、実行計画表示の `outputs & filters` に `DELETE` 演算子の出力情報が詳細に記載されています。

|   **情報名**    |                                                 **意味**                                                       |
|---------------|-------------------------------------------------------------------------------------------------------------------|
| output        | この演算子が出力する式です。    |
| filter        | この演算子のフィルター条件です。例では `DELETE` 演算子に `filter` が設定されていないため、`nil` です。削除ステートメントでは、`WHERE` 句の述語がベーステーブルにプッシュダウンされます。例えば、Q1 クエリの `c2>'100'` は1番目の演算子にプッシュダウンされました。 |
| table_columns | 削除操作に関連するデータテーブルの列です。     |

`DELETE` 演算子のその他の例：

* Q2 クエリは `t1` テーブルのすべてのデータ行を削除します。

* Q3 クエリは、パーティションテーブル `t2` から `c1 = 1` を満たすデータ行を削除します。

* Q4 クエリは、パーティションテーブル `t2` から `c2 > '100'` を満たすデータ行を削除します。実行計画からわかるように、`DELETE` 演算子は `EXCHANGE` 演算子の下に配置されているため、2番目と3番目の演算子はパーティション単位でスケジュールされるタスクとして実行されます。計画の実行時、4番目の演算子が `t2` テーブルのあるパーティションで `c2 > '100'` を満たすデータをスキャンし、3番目の `DELETE` 演算子は対応するパーティションでスキャンされたデータのみを削除します。


## DISTRIBUTED DELETE

`DISTRIBUTED DELETE` 演算子は、データテーブルの複数のパーティションからデータを削除するために使用します。

以下の例のように、Q5 クエリはテーブル `t3` から `c2 > '100'` を満たすすべてのデータ行を削除します。`t3` は本来非パーティションテーブルですが、`t3` にグローバルインデックス `idx_t3_c2` が存在するため、各行は複数のパーティションにまたがって存在します。

```sql
Q5:
obclient> EXPLAIN DELETE FROM t3 WHERE c2 > '100';

| Query Plan                                                                       |

| ====================================================================             |
| |ID|OPERATOR                   |NAME         |EST.ROWS|EST.TIME(us)|             |

| |1 |└─PX COORDINATOR           |             |1       |8           |             |
| |2 |  └─EXCHANGE OUT DISTR     |:EX10000     |1       |8           |             |
| |3 |    └─PX PARTITION ITERATOR|             |1       |7           |             |
| |4 |      └─TABLE RANGE SCAN   |t3(IDX_t3_c2)|1       |7           |             |
| ====================================================================             |
| Outputs & filters:                                                               |
| -------------------------------------                                            |
|   0 - output(nil), filter(nil)                                                   |

|   1 - output([t3.c1], [t3.c2]), filter(nil), rowset=16                           |
|   2 - output([t3.c1], [t3.c2]), filter(nil), rowset=16                           |

23 rows in set
```

上記の例の実行計画表示の `outputs & filters` に `DISTRIBUTED DELETE` 演算子の情報が詳細に記載されており、フィールドの意味は `DELETE` 演算子と同じです。
