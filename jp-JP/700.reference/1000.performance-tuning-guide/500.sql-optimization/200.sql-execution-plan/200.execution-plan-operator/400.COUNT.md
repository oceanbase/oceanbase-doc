# COUNT

`COUNT` 演算子は、Oracleの `ROWNUM` 機能との互換性を提供し、`ROWNUM` 式の自動インクリメント操作を実現します。

一般的なシナリオでは、SQLクエリに `ROWNUM` が含まれる場合、SQLオプティマイザーは実行計画を生成する際に `COUNT` 演算子を割り当てます。ただし、場合によっては、SQLオプティマイザーは `ROWNUM` を含むSQLを `LIMIT` 演算子に書き換えることがあり、その場合は `COUNT` 演算子は割り当てられません。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p><code>COUNT</code> 演算子は、OceanBaseデータベースのOracleモードでのみ利用できます。</p>
  </main>

## COUNT演算子が割り当てられる通常のシナリオ

例1：`ROWNUM` を含むSQLクエリで `COUNT` 演算子が正常に割り当てられるシナリオ。

```sql
obclient> CREATE TABLE t1(c1 INT, c2 INT);
Query OK, 0 rows affected

obclient> INSERT INTO t1 VALUES(1, 1);
Query OK, 1 rows affected

obclient> INSERT INTO t1 VALUES(3, 3);
Query OK, 1 rows affected

obclient> INSERT INTO t1 VALUES(5, 5);
Query OK, 1 rows affected

Q1:
obclient> EXPLAIN SELECT c1,ROWNUM FROM t1;

Query Plan:
| ====================================
|ID|OPERATOR   |NAME|EST. ROWS|COST|
------------------------------------
|0 |COUNT      |    |1        |37  |
|1 | TABLE SCAN|T1  |1        |36  |
====================================

Outputs & filters:
-------------------------------------
  0 - output([T1.C1], [rownum()]), filter(nil)
  1 - output([T1.C1]), filter(nil),
      access([T1.C1]), partitions(p0)

obclient> SELECT c1,ROWNUM FROM t1;
+------+--------+
| C1   | ROWNUM |
+------+--------+
|    1 |      1 |
|    3 |      2 |
|    5 |      3 |
+------+--------+
3 rows in set
```

上記の例では、実行計画表示の `outputs & filters` が `COUNT` 演算子の出力情報を詳細に示しています。

| **情報名** |                               **意味**                                |
|----------|---------------------------------------------------------------------|
| output   | この演算子が出力する式。ここで `rownum()` は `ROWNUM` に対応する式を表します。        |
| filter   | この演算子におけるフィルタ条件。例では `COUNT` 演算子に `filter` が設定されていないため、`nil` です。 |

上記の実行計画例の出力結果からわかるように、`ROWNUM` に対応する式の初期値は1です。データが `COUNT` 演算子を通過するたびに、`COUNT` 演算子は `ROWNUM` に対応する式の値に1を加算し、`ROWNUM` 式の自動インクリメント操作を実現します。

## COUNT演算子が割り当てられないシナリオ

例2：`rownum` を含むSQLが `LIMIT` に書き換えられた後、`COUNT` 演算子が割り当てられないシナリオ。

```sql
Q2:
obclient> EXPLAIN SELECT 1 FROM DUAL WHERE ROWNUM < 2;

Query Plan:
| ====================================
|ID|OPERATOR   |NAME|EST. ROWS|COST|
------------------------------------
|0 |LIMIT      |    |1        |1   |
|1 | EXPRESSION|    |1        |1   |
====================================

Outputs & filters:
-------------------------------------
  0 - output([1]), filter(nil), limit(?), offset(nil)
  1 - output([1]), filter(nil)
      values({1})
```

上記の実行計画例の出力結果からわかるように、SQLに `ROWNUM` が含まれていても、SQLオプティマイザーによって書き換えられると、`ROWNUM` を含む式は等価な `LIMIT` 式に変換されます。この変換の利点は、より多くの最適化を行えることです。詳細については、[LIMIT](../200.execution-plan-operator/1200.LIMIT.md)を参照してください。
