# TABLE SCAN

`TABLE SCAN`演算子は、ストレージ層とSQL層のインターフェースであり、オプティマイザーがどのインデックスを選択してデータにアクセスするかを表示するために使用されます。

OceanBaseデータベースV4.1.0では、通常インデックスとグローバルインデックスの両方に対して、インデックス回表のロジックが`TABLE SCAN`演算子内にカプセル化されています。実行計画の表示時には、`is_index_back`という識別子で演算子が回表が必要かどうかを示し、`is_global_index`という識別子で演算子がグローバルインデックスをスキャンしているかどうかを示します。
例：`TABLE SCAN`演算子を含む実行計画

```sql
Q1：
obclient> CREATE TABLE t1(c1 INT PRIMARY KEY, c2 INT, c3 INT, c4 INT);
obclient> CREATE INDEX e1 ON t1(c1,c2);
obclient> EXPLAIN SELECT * FROM t1 WHERE c1 = 1;
+--------------------------------------------------------------------------+
| Query Plan                                                               |
+--------------------------------------------------------------------------+
| =========================================                                |
| |ID|OPERATOR |NAME|EST.ROWS|EST.TIME(us)|                                |
| -----------------------------------------                                |
| |0 |TABLE GET|T1  |1       |3           |                                |
| =========================================                                |
| Outputs & filters:                                                       |
| -------------------------------------                                    |
|   0 - output([T1.C1], [T1.C2], [T1.C3], [T1.C4]), filter(nil), rowset=16 |
|       access([T1.C1], [T1.C2], [T1.C3], [T1.C4]), partitions(p0)         |
|       is_index_back=false, is_global_index=false,                        |
|       range_key([T1.C1]), range[1 ; 1],                                  |
|       range_cond([T1.C1 = 1])                                            |
+--------------------------------------------------------------------------+
```

|           **情報名**             |         **意味**       |

Q4クエリにおいて、`TABLE SKIP SCAN`は特定の条件下で既存のインデックスを利用してスキャンを高速化することができます。OceanBaseデータベースは以下の制限条件を満たす場合、`TABLE SKIP SCAN`を選択しようとします：

* テーブルに統計情報が収集済みであること。
* クエリ条件に結合インデックスのサフィックス列が含まれており、他のインデックスの最左前綴ではないこと。
* オプティマイザーがTABLE SKIP SCANとテーブルスキャンのコストを比較し、TABLE SKIP SCANの方がコストが低いことを発見した場合。

| operator                                    | `TABLE SCAN`演算子の`operator`には3種類の形式があります：`TABLE SCAN`、`TABLE GET`、および`TABLE SKIP SCAN`です。 <ul><li>`TABLE SCAN`は範囲スキャンに属し、0行または複数行のデータを返します。</li>   <li> `TABLE GET`は主キーを使用して直接位置を特定し、0行または1行のデータを返します。</li>  <li> `TABLE SKIP SCAN`は範囲スキャンに属し、ジャンプ実行を行うため、0行または複数行のデータを返します。</li><li>`TABLE RANGE SCAN`は範囲スキャンに属し、0行または複数行のデータを返します。</ul>      |
| name                                        | データへのアクセスにどのインデックスを使用するかを選択します。選択されたインデックスの名前はテーブル名の後に付きます。インデックスの名前がない場合、主テーブルスキャンが実行されていることを意味します。ここでは注意が必要ですが、OceanBaseデータベースでは主テーブルとインデックスの組織構造は同じであり、主テーブル自体もインデックスの一種です。    |
| output                                      | この演算子の出力列。    |
| filter                                      | この演算子のフィルタープレディケート。例のQ5クエリの`TABLE RANGE SCAN`演算子には`filter`が設定されていないため、`nil`となります。     |
| partitions                                  | クエリでスキャンする必要があるパーティション。  |
| is_index_back                               | この演算子がテーブルへの戻りが必要かどうか。例えば、Q1クエリでは主テーブルを選択しているため、テーブルへの戻りは不要です。Q2クエリでは、インデック列は`(c2,c3,c1)`であり、クエリで`c4`列を返す必要があるため、テーブルへの戻りが必要です。  |
| is_global_index                             | この演算子がグローバルインデックスをスキャンするかどうか。例えば、Q2クエリでは通常のインデックスが使用されているため、`is_global_index`は`false`となります。Q3クエリでは`t2`テーブルの`i2`インデックスが使用され、`i2`インデックスはグローバルインデックスであるため、`is_global_index`は`true`となります。 |
|  range_key/range/range_cond | <ul><li> `range_key`：インデックスの`rowkey`列。</li>     <li> `range`：インデックスが開始して終了するスキャン位置。完全なテーブルスキャンかどうかを判断するには、`range`の範囲に注目する必要があります。例えば、`rowkey`が3列あるシナリオでは、`range(MIN,MIN, MIN ; MAX, MAX, MAX)`は本質的な完全なテーブルスキャンを表します。</li>   <li> `range_cond`：インデックスのスキャン開始と終了位置を決定する関連プレディケート。</li></ul>    |
