# TABLE SCAN

`TABLE SCAN` 演算子はストレージ層とSQL層のインターフェースであり、オプティマイザーがどのインデックスを使用してデータにアクセスするかを示します。

OceanBase データベース V4.1.0 では、通常インデックスとグローバルインデックスについて、インデックスへの再アクセスロジックは `TABLE SCAN` 演算子内にカプセル化されています。実行計画の表示時には、`is_index_back` が演算子がインデックスへの再アクセスを必要とするかどうかを示し、`is_global_index` が演算子がグローバルインデックスをスキャンしているかどうかを示します。
例：`TABLE SCAN` 演算子を含む実行計画

```sql
Q1：
obclient> CREATE TABLE t1(c1 INT PRIMARY KEY, c2 INT, c3 INT, c4 INT);
obclient> CREATE INDEX e1 ON t1(c1,c2);
obclient> EXPLAIN SELECT * FROM t1 WHERE c1 = 1;
+--------------------------------------------------------------------------+
| Query Plan                                                               |
+--------------------------------------------------------------------------+
| =========================================                                |
| |ID|OPERATOR |NAME|EST.ROWS|EST.TIME(us)|                                |
| -----------------------------------------                                |
| |0 |TABLE GET|T1  |1       |3           |                                |
| =========================================                                |
| Outputs & filters:                                                       |
| -------------------------------------                                    |
|   0 - output([T1.C1], [T1.C2], [T1.C3], [T1.C4]), filter(nil), rowset=16 |
|       access([T1.C1], [T1.C2], [T1.C3], [T1.C4]), partitions(p0)         |
|       is_index_back=false, is_global_index=false,                        |
|       range_key([T1.C1]), range[1 ; 1],                                  |
|       range_cond([T1.C1 = 1])                                            |
+--------------------------------------------------------------------------+
```

上記の例では、実行計画表示の `outputs & filters` が `TABLE SCAN` 演算子の出力情報を詳細に示しています：

|           **情報名**             |         **意味**       |
|------------------------------------|-----------------------|
| operator                                    | `TABLE SCAN` 演算子の `operator` には3つの形式があります：`TABLE SCAN`、`TABLE GET`、`TABLE SKIP SCAN`。<ul><li>`TABLE SCAN` は範囲スキャンに属し、0行または複数行のデータを返します。</li>   <li> `TABLE GET` は主キーで直接位置を特定し、0行または1行のデータを返します。</li>  <li> `TABLE SKIP SCAN` は範囲スキャンに属し、ジャンプ実行を行い、0行または複数行のデータを返します。</li> </ul>      |

| is_index_back                               | この演算子が再テーブルアクセスを必要とするかどうかを示します。例えば、Q1クエリではメインテーブルが選択されているため、再テーブルアクセスは不要です。|
| is_global_index                             | この演算子がグローバルインデックスをスキャンしているかどうかを示します。例えば、Q2クエリでは通常のインデックスが使用されているため、`is_global_index` は `false` です。Q3クエリでは、`t2` テーブルの `i2` インデックスが使用されており、`i2` インデックスはグローバルインデックスであるため、`is_global_index` は `true` です。 |

Q4 クエリでは、特定の条件下で `TABLE SKIP SCAN` が既存のインデックスを利用してスキャンを高速化できます。OceanBase データベースは、以下の制限条件を満たす場合、`TABLE SKIP SCAN` の選択を試みます：

* テーブルの統計情報が収集されていること。
* クエリ条件に結合インデックスのサフィックス列が含まれており、それが他のインデックスの左端のサフィックスではないこと。
* オプティマイザーが TABLE SKIP SCAN と全表スキャンのコストを比較し、TABLE SKIP SCAN の方がコストが低いと判断した場合。

| operator                                    | `TABLE SCAN` 演算子の `operator` には3つの形式があります：`TABLE SCAN`、`TABLE GET`、`TABLE SKIP SCAN`。 <ul><li>`TABLE SCAN` は範囲スキャンに属し、0行または複数行のデータを返します。</li>   <li> `TABLE GET` は主キーで直接位置を特定し、0行または1行のデータを返します。</li>  <li> `TABLE SKIP SCAN` は範囲スキャンに属し、ジャンプ実行を行い、0行または複数行のデータを返します。</li><li>`TABLE RANGE SCAN` は範囲スキャンに属し、0行または複数行のデータを返します。</ul>      |
| name                                        | データにアクセスするために使用するインデックスを選択します。選択したインデックス名はテーブル名の後に続きます。インデックス名がない場合、メインテーブルのスキャンが実行されていることを意味します。ここで注意が必要なのは、OceanBaseデータベースでは、メインテーブルとインデックスの組織構造が同じであり、メインテーブル自体もインデックスであるということです。    |
| output                                      | この演算子の出力列。    |
| filter                                      | この演算子のフィルター述語。例えば、Q5クエリの `TABLE RANGE SCAN` 演算子では `filter` が設定されていないため、`nil` となります。     |
| partitions                                  | クエリでスキャンするパーティション。  |
| is_index_back                               | この演算子がメインテーブルへの再アクセスを必要とするかどうか。例えば、Q1クエリではメインテーブルが選択されているため、メインテーブルへの再アクセスは不要です。Q2クエリでは、インデックス列が `(c2,c3,c1)` であり、クエリで `c4` 列を返す必要があるため、メインテーブルへの再アクセスが必要です。  |
| is_global_index                             | この演算子がグローバルインデックスをスキャンしているかどうか。例えば、Q2クエリで使用されているインデックスは通常のインデックスであるため、`is_global_index` は `false` です。Q3クエリでは、`t2` テーブルの `i2` インデックスが使用されており、`i2` インデックスはグローバルインデックスであるため、`is_global_index` は `true` です。 |
|  range_key/range/range_cond | <ul><li> `range_key`：インデックスの `rowkey` 列。</li>     <li> `range`：インデックスのスキャン開始位置と終了位置。全表スキャンかどうかを判断するには、`range` の範囲に注目する必要があります。例えば、`rowkey` が3列ある場合、`range(MIN,MIN, MIN ; MAX, MAX, MAX)` は真の意味での全表スキャンを表します。</li>   <li> `range_cond`：インデックスのスキャン開始位置と終了位置を決定する関連述語。</li></ul>    |
