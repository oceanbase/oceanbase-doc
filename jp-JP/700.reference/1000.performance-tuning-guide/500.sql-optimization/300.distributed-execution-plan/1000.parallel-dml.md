# パラレルDML

パラレルDMLは、パラレル実行メカニズムを利用して大規模データベースのテーブルやインデックスに対する挿入、更新、削除などの操作の実行効率を向上させます。意思決定支援システム（DSS）向けのデータベースでは、パラレルDMLはクエリと更新機能を提供し、パラレルクエリ機能を補完します。OLTPデータベースでは、パラレルDML操作によりバッチ処理ジョブの実行が高速化されます。

## パラレルDMLの有効化と無効化

OceanBaseデータベースでは、SQLステートメントまたはセッションでパラレルDMLを明示的に有効にすることができます。

### SQLステートメントでのパラレルDMLの有効化と無効化

SQLステートメントでパラレルDMLを有効にするには、ステートメント内に以下のHintを挿入します：

```sql
/*+ ENABLE_PARALLEL_DML PARALLEL(3) */
```

通常、`ENABLE_PARALLEL_DML` Hintと`PARALLEL` Hintを組み合わせて使用する必要があります。ただし、ターゲットテーブルのスキーマでテーブルレベルの並列度が指定されている場合は、`ENABLE_PARALLEL_DML` Hintのみを指定する必要があります。

以下の例では、`ENABLE_PARALLEL_DML` Hintと`PARALLEL(n)`パラメータを同時に使用して並列度`n`を指定しており、`n > 1`、並列度`dop=2`です。

```sql
CREATE TABLE t1 (c1 INT PRIMARY KEY, c2 INT) NOPARALLEL;
CREATE TABLE t2 (c1 INT PRIMARY KEY, c2 INT) PARALLEL 11 PARTITION BY HASH(c1) PARTITIONS 3;
CREATE TABLE t3 (c1 INT PRIMARY KEY, c2 INT) PARALLEL 10 PARTITION BY HASH(c1) PARTITIONS 4;
```

```sql
/*+ DISABLE_PARALLEL_DML */
```

セッションでパラレルDMLが有効になっていても、特定のSQLステートメント内で`DISABLE_PARALLEL_DML` Hintを使用してパラレルDMLを無効にできます。

### セッションでのパラレルDMLの有効化と無効化

デフォルトでは、SQLステートメントで`PARALLEL` Hintを使用しても、パラレルDMLは有効になりません。そのため、セッション単位でパラレルDMLを有効にする必要があります。

MySQLモードでセッション内のパラレルDMLを有効にする構文は次のとおりです：

```sql
SET _FORCE_PARALLEL_DML_DOP = n;
```

ここで、nは1より大きい値です。

Oracleモードでセッション内のパラレルDMLを有効にする構文は次のとおりです：

```sql
ALTER SESSION ENABLE PARALLEL DML;
```

Oracleモードでは、セッション内で強制的にパラレルDMLを有効にする必要がある場合は、以下のSQLステートメントを実行します：

```sql
ALTER SESSION FORCE PARALLEL DML PARALLEL n;
```

```sql
SET _FORCE_PARALLEL_DML_DOP = 1;
```

```sql
ALTER SESSION DISABLE PARALLEL DML;
```

パラレルDMLを無効にした場合、SQL文で `PARALLEL` Hintを使用しても、パラレルDMLは実行されません。

### セグメント間のパラレル処理をサポート

以下のSQL文を用いて、テーブルのパーティションに対するパラレル処理機能を説明します。

1. テストテーブル `branch_sp_tbl_src` を作成します。

    ```sql
    CREATE TABLE branch_sp_tbl_src(id INT PRIMARY KEY, v INT) PARTITION BY KEY(id) PARTITIONS 4;
    ```

2. テストテーブル `branch_sp_tbl_dest` を作成します。

    ```sql
    CREATE TABLE branch_sp_tbl_dest LIKE branch_sp_tbl_src;
    ```

3. 実行計画を確認します。

    以下のSQL文を実行することで、この挿入操作の実行方法を示します。

    ```sql
    obclient [test]> EXPLAIN BASIC INSERT /*+enable_parallel_dml parallel(100) query_timeout(1000000000)*/ INTO branch_sp_tbl_dest SELECT id, v FROM branch_sp_tbl_src ON DUPLICATE KEY UPDATE v = v + 1;
    ```

    実行結果は次のとおりです：


## 使用方法

OceanBaseデータベースは、以下のSQL文のパラレル実行機能をサポートしています：

* `INSERT INTO SELECT`
* `UPDATE`
* `DELETE`

テーブルに以下のインデックスタイプが存在する場合、並列実行をサポートする必要があります：

* ローカルインデックス
* シングルパーティション全体インデックス
* マルチパーティション全体インデックス

### 並列DMLがサポートするシナリオ

| DBLink | 不支持 | 不支持 | 不支持 | 不支持 |
| その他 | 以下のステートメントは並列DMLをサポートしません：<ul><li>`INSERT ... VALUES ...`</li><li>`INSERT INTO ON DUPLICATE KEY UPDATE`</li><li>`REPLACE`</li></ul> | `ON UPDATE CURRENT_TIMESTAMP`を含む列はサポートしません | | |

`INSERT`で書き込むテーブルに自動インクリメント列がある場合、その自動インクリメント列が主キーまたはパーティションキーであり、かつその列が指定されている場合、並列DMLはサポートされません。

**例：**

1. テーブル `tbl1` を作成します。列 `col1` は自動インクリメント列であり、主キーとして指定されています。

    ```sql
    CREATE TABLE tbl1(col1 INT AUTO_INCREMENT PRIMARY KEY, col2 INT, col3 INT);
    ```

2. テーブル `tbl2` を作成します。列 `col1` は自動インクリメント列です。

    ```sql
    CREATE TABLE tbl1(col1 INT AUTO_INCREMENT, col2 INT, col3 INT);
    ```

3. テーブル `tbl3` を作成します。

    ```sql
    CREATE TABLE tbl3(col1 INT, col2 INT, col3 INT);
    ```

4. `INSERT`でデータを書き込む際、自動インクリメント列 `col1` が主キーであるため、並列DMLはサポートされません。

    ```sql
    INSERT /*+enable_parallel_dml parallel(3)*/ INTO tbl1 SELECT * FROM tbl3;
    ```

5. `INSERT`でデータを書き込む際、列 `col1` が指定されていないため、並列DMLはサポートされます。

    ```sql
    INSERT /*+enable_parallel_dml parallel(3)*/ INTO tbl1(col2, col3) SELECT col2, col3 FROM tbl3;
    ```

6. `INSERT`でデータを書き込む際、列 `col1` が自動インクリメント列のみであるため、並列DMLはサポートされます。

    ```sql
    INSERT /*+enable_parallel_dml parallel(3)*/ INTO tbl2 SELECT * FROM tbl3;
    ```

### パラレルDMLによる関連更新

関連更新とは、`UPDATE` ステートメントで複数のテーブルを結合し、関連するテーブルのデータに基づいてターゲットテーブルを更新する操作を指します。パラレルDML機能を利用することで、大規模なデータ更新操作のパフォーマンスを大幅に向上させることができます。

**例：**

以下の手順では、パラレルDMLを使用して関連更新機能を実現する方法を示します。

1. テストテーブル `customers` と `orders` を作成します。

    ```sql
    CREATE TABLE customers (
        id INT PRIMARY KEY,
        name VARCHAR(50),
        customer_level VARCHAR(10)
    );
    ```

    ```sql
    CREATE TABLE orders (
        order_id INT PRIMARY KEY,
        customer_id INT,
        discount DECIMAL(3, 2),
        amount DECIMAL(10, 2)
    );
    ```

2. テストデータを挿入します。

   * `customers` テーブルに顧客データを挿入します：

       ```sql
       INSERT INTO customers (id, name, customer_level) VALUES
       (1, 'Alice', 'VIP'),
       (2, 'Bob', 'NORMAL'),
       (3, 'Charlie', 'OTHER');
       ```

   * `orders` テーブルに注文データを挿入します：

       ```sql
       INSERT INTO orders (order_id, customer_id, discount, amount) VALUES
       (101, 1, NULL, 1000.00),
       (102, 2, NULL, 2000.00),
       (103, 3, NULL, 1500.00),
       (104, 1, NULL, 3000.00),
       (105, 2, NULL, 2500.00);
       ```

3. パラレルDMLによる関連更新を実行します。

    `EXPLAIN` を使用して、パラレルDMLによる関連更新の実行計画を確認します。`PARALLEL` ヒントを使用して並列度を4に指定し、`customers` テーブルの顧客ランク（`customer_level`）に基づいて、`orders` テーブルの割引フィールド（`discount`）を更新します。

    ```sql
    EXPLAIN UPDATE /*+ PARALLEL(4) */
        orders o JOIN customers c ON o.customer_id = c.id
    SET o.discount = CASE
        WHEN c.customer_level = 'VIP' THEN 0.9
        WHEN c.customer_level = 'NORMAL' THEN 0.95
        ELSE 1.0
        END;
    ```
