# パラレル実行の有効化方法と優先順位

OceanBaseデータベースのオプティマイザーは、パラレル実行を通じてSQLクエリの実行時間を最適化することをサポートしています。オプティマイザーでは、パラレルリソース量を示すためにパラレル度DOP（Degree of Parallel）を使用できます。実際のビジネスシナリオにおいて、パラレル実行を有効にするかどうか、また必要なDOPの大きさについては、クエリの実際の実行状況とビジネス要件を総合的に考慮し、経験に基づいて必要なパラレル度を決定する必要があります。

OceanBaseデータベースは現在、Auto DOP、Hint、システム変数、Schema DOPなど、複数の方法でクエリのパラレル実行を有効にすることをサポートしています。ただし、以下のシナリオではパラレル実行はサポートされていません：

* PL UDFやdblinkが関与する場合、クエリのパラレル実行の有効化は禁止されています。
* DASスキャンを使用するベーステーブルについては、指定されたパラレル度をサポートしておらず、計画形態ではパラレル度が1と表示されます。

クエリがパラレル実行をサポートする前提で、複数のパラレル実行有効化方法の優先順位は、高いものから低いものへと以下のとおりです：

* テーブルレベルのパラレルHintによるDOP設定
* グローバルパラレルHintによるDOP設定
* システム変数によるDOP設定
* Schema DOP

## テーブルレベルのパラレルヒントによるDOPの設定

テーブルレベルのパラレルヒントによるDOPの設定とは、ヒント内で直接テーブルオブジェクトの並列度を指定することを指します。基本的なSQL構文は以下のとおりです：

```sql
/*+PARALLEL ( @qb_name table_name dop_value)*/
```

例えば、クエリQ1では、テーブル`t1`と`t2`にそれぞれDOP = 8およびDOP = 4でパラレル実行するように指定しています。例：

```shell
Q1: SELECT /*+PARALLEL(t1 8) PARALLEL(t2 4)*/ * FROM t1, t2 WHERE t1.c1 = t2.c1;
```

クエリ内でヒントを使用して並列度を指定していないテーブルについては、他の優先順位が低い方法に基づいてDOPが決定されます。例えば、クエリQ2では、テーブル`t1`に対してのみDOP = 8でパラレル実行するように指定しています。他の方法でパラレル処理が有効になっていない場合、テーブル`t2`はDOP = 1、つまりパラレル処理を有効にしない状態でスキャンされます。

```shell
Q2: SELECT /*+PARALLEL(t1 8)*/ * FROM t1, t2 WHERE t1.c1 = t2.c1;
```

## グローバルパラレルヒントによるDOPの設定

グローバルパラレルヒントは、クエリでデフォルトで使用される並列度を指定するために使用されます。基本的なSQL構文は以下のとおりです：

```sql
/*+PARALLEL ( dop_value )*/
/*+PARALLEL ( AUTO )*/
/*+PARALLEL ( MANUAL )*/
```

例えば、クエリQ3では`PARALLEL( 8 )`が、クエリ内のテーブル`t1`と`t2`に対してDOP = 8を使用するように指定しています。

グローバルパラレルヒントは、クエリで使用される並列度の取得戦略も指定できます。例えば、クエリQ4では`PARALLEL ( AUTO )`が、クエリ内のすべてのテーブルに対してAuto DOPの並列度取得戦略を使用するように指定しています。

グローバルパラレルヒントの優先順位はテーブルレベルのパラレルヒントよりも低いため、グローバルとテーブルレベルの両方のパラレルヒントが同時に存在する場合、グローバルヒントはテーブルレベルのヒントが存在しないテーブルにのみ適用されます。例えば、クエリQ5では、テーブル`t1`はテーブルレベルのヒントによりDOP = 8を使用し、テーブル`t2`はグローバルヒントによりDOP = 4を使用します。クエリQ6では、テーブル`t1`はテーブルレベルのヒントによりDOP = 8を使用し、テーブル`t2`はAuto DOP戦略に基づいて自動的にDOP値を取得します。

```shell
Q3: SELECT /*+PARALLEL(8)*/ * FROM t1, t2 WHERE t1.c1 = t2.c1;
Q4: SELECT /*+PARALLEL(AUTO)*/ * FROM t1, t2 WHERE t1.c1 = t2.c1;
Q5: SELECT /*+PARALLEL(t1 8) PARALLEL(4)*/ * FROM t1, t2 WHERE t1.c1 = t2.c1;
Q6: SELECT /*+PARALLEL(t1 8) PARALLEL ( AUTO )*/ * FROM t1, t2 WHERE t1.c1 = t2.c1;
```

## システム変数によるDOPの設定

並列度に関連するシステム変数には2種類あり、それぞれDOP取得戦略の設定と固定DOPの設定に使用されます。

DOP取得戦略の設定は、`GLOBAl`または`SESSION`レベルの`parallel_degree_policy`変数を設定することで、Auto DOP戦略を有効にします。Auto DOP戦略では、一定のアルゴリズムに基づいてテーブルオブジェクトのDOP値が計算されます。詳細については、[Auto DOP戦略の有効化](../300.distributed-execution-plan/600.auto-dop.md)を参照してください。

グローバル`PARALLEL`ヒントによってDOPが指定されている場合、またはAuto DOP戦略が有効になっている場合、あるいは`parallel_degree_policy`変数によってAuto DOP戦略が有効になっている場合、固定DOPの設定は無効になります。その他のシナリオでは、以下の内部システム変数を使用して、クエリまたはDMLで使用される並列度を設定できます。例：

```shell
SET _enable_parallel_query = 1;
SET _enable_parallel_dml = 1;
SET _force_parallel_query_dop = 8;
SET _force_parallel_dml_dop = 8;
```

## スキーマDOP

固定DOP戦略を使用し、以下の内部システム変数を使用してパラレル処理を有効にする場合、DOP = 1に設定されていると、クエリはテーブル作成時に指定されたDOPを使用してテーブルのオブジェクトに対してパラレル実行を開始します。

```shell
SET _enable_parallel_query = 1;
SET _enable_parallel_dml = 1;
SET _force_parallel_query_dop = 1;
SET _force_parallel_dml_dop = 1;
```

次の例では、テーブル `t1` を作成する際にテーブルDOP = 8を指定します。`ALTER TABLE` を使用してテーブル `t1` のDOPを4に調整し、`ALTER INDEX` を使用してインデックス `idx1` のDOPを2に調整すると、その後のクエリは調整後のDOPを使用してテーブルのオブジェクトとインデックスに対してパラレル実行を開始します。

```shell
CREATE TABLE t1(c1 INT, c2 INT, c3 INT) PARALLEL 8;
CREATE INDEX idx1 ON t1(c1);
ALTER TABLE t1 PARALLEL 4;
ALTER INDEX idx1 PARALLEL 2;
```
