# パラレル実行のチューニング技術

本記事では、OceanBaseの基本的なパラレル実行のチューニング技術について説明します。

## 統計情報の手動収集

オプティマイザーに保存されている統計情報が古くなっていると、最適でない計画が生成される可能性があります。V3.2とV4.1では、それぞれ統計情報を手動で収集するためのインターフェースが提供されています：

* [オプティマイザー統計情報V3.2.x](https://www.oceanbase.com/docs/enterprise-oceanbase-database-cn-10000000000945957)
* [オプティマイザー統計情報V4.x](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000035686)

### V3.2バージョン

V3.2では、主表の統計情報を手動で収集する構文は以下のとおりです（インデックステーブルはサポートされていません）：

**MySQLモード構文：**

```sql
-- まず、analyze構文のサポートを有効にする必要があります：
ALTER SYSTEM SET enable_sql_extension = true;

-- ユーザーTESTのテーブルT1の統計情報を収集し、すべての列のバケット数をauto戦略に設定します：
ANALYZE TABLE T1 COMPUTE STATISTICS FOR ALL COLUMNS SIZE AUTO;
```

**Oracleモード構文：**

```sql
-- ユーザーTESTのテーブルT1のグローバルレベルの統計情報を収集し、すべての列のバケット数をauto戦略に設定します：
CALL dbms_stats.gather_table_stats('TEST', 'T1', granularity=>'GLOBAL', method_opt=>'FOR ALL COLUMNS SIZE AUTO');

-- またはanalyze構文を使用します：
-- ユーザーTESTのテーブルT1の統計情報を収集し、すべての列のバケット数をauto戦略に設定します：
ANALYZE TABLE T1 COMPUTE STATISTICS FOR ALL COLUMNS SIZE AUTO;
```

### V4.1バージョン

V4.1では、主表およびインデックステーブルの統計情報を手動で収集する構文は以下のとおりです：

**MySQLモード構文：**

```sql
-- ユーザーTESTのテーブルT1のグローバルレベルの統計情報を収集し、すべての列のバケット数をauto戦略に設定します：
CALL dbms_stats.gather_table_stats('TEST', 'T1', granularity=>'GLOBAL', method_opt=>'FOR ALL COLUMNS SIZE AUTO');

-- ユーザーTESTのテーブルT1のインデックスIDXのインデックス統計情報を収集し、並列度を4に設定します（IDXは一意ではないため、テーブル名を指定する必要があります）：
CALL dbms_stats.gather_index_stats('TEST', 'IDX', degree=>4, tabname=>'T1');
```

**Oracleモード構文：**

```sql
-- ユーザーTESTのテーブルT1のグローバルレベルの統計情報を収集し、すべての列のバケット数をauto戦略に設定します：
CALL dbms_stats.gather_table_stats('TEST', 'T1', granularity=>'GLOBAL', method_opt=>'FOR ALL COLUMNS SIZE AUTO');

-- ユーザーTESTのインデックスIDXのインデックス統計情報を収集し、並列度を4に設定します（IDXは一意であるため、テーブル名の指定は不要です）：
CALL dbms_stats.gather_index_stats('TEST', 'IDX', degree=>4);
```

## Partition Wise Joinを使用したパーティション方式の変更

PoCシナリオにおいて、大きなテーブル`JOIN`が存在し、業務上許容される場合、大きなテーブルが同じパーティション方式を使用し、それらを同一のテーブルグループにバインドすることで、パフォーマンスが最適な`partition wise join`を実現できます。

`partition wise join`を使用する際には、並列度もパーティション数に適応させる必要があり、これにより最適なパフォーマンスを得ることができます。

## 並列度とパーティション数の適応

一般的に、並列度とパーティション数は一定の整数比関係にあり、良好なパフォーマンスが得られます。

詳細については、[パラレル実行](100.parallel-execution-concept.md)のロードバランシングによるパフォーマンスの最適化を参照してください。

## 適切なインデックスの作成

適切なインデックスを作成することで、データのスキャン量を削減し、パラレル実行のパフォーマンスを向上させることができます。どのテーブルや列にインデックスを作成するかについては、汎用的な解決策はなく、具体的なSQLに基づいて個別に分析する必要があります。

## レプリケーションテーブルの作成

V4.2以降では、レプリケーションテーブルを作成することでデータの再分散を削減し、パラレル実行性能を向上させることができます。レプリケーションテーブルの詳細については、[レプリケーションテーブルの紹介](https://www.oceanbase.com/knowledge-base/oceanbase-database-20000000027)を参照してください。基本的な構文例は以下のとおりです：

```sql
CREATE TABLE dup_t1(c1 int) duplicate_scope = 'cluster';
```
