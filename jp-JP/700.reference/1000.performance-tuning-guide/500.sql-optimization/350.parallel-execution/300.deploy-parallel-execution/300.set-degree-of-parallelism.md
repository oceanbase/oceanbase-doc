# パラレル実行の並列度の設定

並列度（Degree Of Parallelism、略称：DOP）とは、単一のDFO（Data Flow Operation）が実行時に使用するワーカースレッド数を指します。

パラレル実行の設計目的は、マルチコアリソースを効率的に活用することです。OceanBaseのパラレル実行フレームワークでは、並列度を指定する複数の方法が提供されており、手動で指定することも、データベースに自動選択させることも可能です。

## パラレル度の設定に関する推奨事項

基本的な原則として、PARALLELの設定はCPUリソースを最大限に活用することを目的としており、単純に最大値を追求するものではありません。

### 例

テナントのCPU数が20個である場合を想定します：

- 単一テーブルに対する単純な操作（単一テーブルのスキャンやフィルタリング、追加・削除・更新など）では、PARALLELの理論値を20に設定できます。
- 複数テーブルの`JOIN`クエリやグローバルインデックスを含むPDMLでは、PARALLELの理論値を10に設定できます。
- より複雑な実行計画で、右側が深い木構造（つまり、実行計画内の操作木の右側がより深い部分）の場合、PARALLELの理論値を約7に設定できます。

#### 例の説明

現在のテナントのCPU数が20個の場合を想定します：

- 単一テーブル操作では、DFOは1つしか存在しません。そのため、全20個のCPUをそのDFOに割り当てることができます。

  例えば、そのDFOがほとんどの時間をI/O操作に費やしている場合、CPUを最大限に活用するために、パラレル度を25など、やや高く設定できます。

  チューニング後、単一テーブルの単純操作（単一テーブルのスキャンやフィルタリング、追加・削除・更新など）におけるPARALLELの実際の値は30です。

- 複数テーブルの`JOIN`では、同時に2つのDFOが起動し、データパイプラインを形成します（1つのDFOがproducer、もう1つがconsumer）。したがって、各DFOには10個のCPUを割り当てることができます。

  実際には、各DFOが割り当てられたCPUを最大限に活用できる保証はありません。そのため、CPUをより効率的に活用するために、例えば15に設定するなど、適宜パラレル度を調整できます。ただし、無制限にパラレル度を上げるべきではありません。50に設定しても実質的なメリットは得られず、スレッドスケジューリングオーバヘッドとフレームワークスケジューリングオーバヘッドが増加するだけです。

  チューニング後、複数テーブルの`JOIN`クエリやグローバルインデックスを含むPDMLにおけるPARALLELの実際の値は15です。

- 右側が深い木構造の実行計画では、簡単なSQLクエリを例に、右側が深い木構造の実行計画の状況を説明します：

   ```sql
   SELECT /*+ parallel(10) */ column1, column2
   FROM table1
   WHERE condition1;
   ```

   このクエリでは、`parallel(10)` ヒントを使用して、システムに対してパラレル度10の計画で実行するよう指示しています。実行計画が次のようになると仮定します：

   ```plaintext
   ======================================================================
   | ID  | OPERATOR                 | NAME    | EST.ROWS  | EST.TIME(us)|
   ----------------------------------------------------------------------
   | 0   | SELECT STATEMENT          |         |         |              |
   | 1   |  PX COORDINATOR           |         |         |              |
   | 2   |   PX SEND QC (RANDOM)     | :EX10000|         |              |
   | 3   |    PX BLOCK ITERATOR      |         | N rows  |              |
   | 4   |     TABLE ACCESS (FULL)   | table1  | N rows  |              |
   ======================================================================
   ```

   この実行計画では、操作木の右側に右側が深い木構造の部分があることがわかります。例えば、操作記号が `PX SEND QC` および `PX BLOCK ITERATOR` の部分です。この段階では、複数のDFOが起動し、各DFOが実行計画の一部を担当します。

   システムがこの右側が深い木構造の計画の特定の部分で同時に3つのDFOを起動することを決定し、各DFOに7個のCPUが割り当てられると仮定します。これは、各DFOが計算リソースを最大限に活用し、全体のクエリパフォーマンスを向上させるためです。

   チューニング後、パラレル度を10～15に設定することで、システムにより大きな並列実行の余地を提供し、計画の異なる部分が必要とする可能性のあるパラレル度に適応させることができます。このような調整は、大規模なデータセットを処理する場合や、高いパラレル度での実行が必要なクエリの場合に、全体のパフォーマンスを向上させることができます。

## パラレル度の手動指定

テーブルのスキャン時に常に並列実行を使用するように、テーブルのパラレル度を手動で指定できます。OceanBaseでは、OracleモードとMySQLモードの構文が若干異なります。

### MySQLモードでの並列度の手動指定

#### テーブル属性による並列度の指定

以下のステートメントは、それぞれメインテーブルとインデックスのスキャン並列度を指定しています。

```sql
ALTER TABLE table_name PARALLEL 4;
ALTER TABLE table_name ALTER INDEX index_name PARALLEL 2;
```

SQLが単一のテーブルのみに関わる場合、メインテーブルをクエリすると、メインテーブルが配置されているDFO以外のDFOも並列度4で実行されます。インデックステーブルをクエリすると、インデックステーブルが配置されているDFO以外のDFOも並列度2で実行されます。

SQLが複数のテーブルに関わる場合、PARALLELの最大値がプラン全体のDOPとして使用されます。

#### PARALLEL HINTによる並列度の指定

グローバルPARALLEL HINTを使用して、SQL全体の並列度を指定することができます。また、テーブルレベルのPARALLEL HINTを使用して、特定のテーブルの並列度を指定することもできます。1つのSQLで複数のテーブルに対してPARALLEL HINTが指定されている場合、各テーブルが属するDFOのDOPは、各テーブルのParallel値によって決定されます。1つのDFOに複数のテーブルが含まれる場合、それらのPARALLEL値のうち最大値がそのDFOのDOPとなります。

#### SESSION上で並列度を指定する

現在のセッションで並列度が一度指定されると、そのセッション内のすべてのクエリステートメントは指定された並列度で実行されます。単一行を照会するSQLであってもこの並列度が適用されるため、パフォーマンスが低下する可能性があることに注意してください。

```sql
set _force_parallel_query_dop = 3;
```

DMLステートメントに対して上記のコマンドを使用しても、DMLステートメントのクエリ部分のみが並列実行され、書き込み部分は引き続き直列です。書き込み部分も並列にしたい場合は、以下のコマンドを使用する必要があります：

```sql
set _force_parallel_dml_dop = 3;
```

`_force_parallel_query_dop` を1より大きな値に変更すると、現在のセッション上のクエリはすべて1より大きな並列度で実行されます。`_force_parallel_query_dop` を1に変更すると、現在のセッション上のSQLでは並列実行が有効になりません。

注意点として、ここでの設定は、DMLステートメントを含む、セッション全体のクエリに対してグローバルに適用されます。これらの設定を使用する際は、必ず慎重に行い、セッション全体の実行に与える影響を十分に理解しておく必要があります。

#### セッション単位での並列度の指定

現在のセッションで並列度が指定されると、そのセッション内のすべてのクエリステートメントは指定された並列度で実行されます。単一行を照会するSQLであってもこの並列度が適用されるため、パフォーマンスが低下する可能性があります。

```sql
ALTER SESSION FORCE PARALLEL QUERY PARALLEL 3;
```

DMLステートメントに対して上記のコマンドを使用しても、DMLステートメントのクエリ部分のみが並列実行され、書き込み部分は引き続き直列です。書き込み部分も並列にしたい場合は、以下のコマンドを使用してください：

```sql
ALTER SESSION FORCE PARALLEL DML PARALLEL 3;
```

セッションレベルの並列を無効にするには、以下のコマンドを使用します：

```sql
ALTER SESSION DISABLE PARALLEL QUERY;
```

## パラレル度の優先順位

TABLE HINT > グローバルHINT > SESSION並列度 > TABLE DOP
