# 非同期統計情報収集

非同期統計情報収集は、データ量に大きな変化が生じたテーブルやパーティションをタイムリーに処理するために使用されます。システムは定期的にテーブルやパーティションのデータ変更状況をチェックし、独立した判断基準に基づくしきい値に従って、非同期収集の候補範囲に追加するかどうかを決定します。

非同期統計情報収集と[自動統計情報収集](400.collect-statistics-automatically.md)は、異なる2つの収集メカニズムです。自動統計情報収集はメンテナンスウィンドウを通じて、欠落または期限切れの統計情報を収集します。一方、非同期統計情報収集は独立したバックグラウンドタスクでデータの変更状況をチェックします。

OceanBaseデータベースはV4.2.4バージョンから非同期統計情報収集をサポートしています。V4.3.5 BP2バージョン以降、システムは前回の統計情報収集以降のデータ変更率に基づいて、テーブルやパーティションが非同期収集の候補範囲に該当するかどうかを判断します。

## 非同期収集候補条件の判断

データ変更率の計算式は以下の通りです：

```text
データ変更率 = （新規行数 + 更新行数 + 削除行数）/ 前回統計情報記録の行数
```

ここで、新規行数、更新行数、削除行数は、前回の統計情報収集以降に累積的に影響を受けた行数です。デフォルトでは、データ変更率が2を超える場合（つまり、累積影響行数が前回統計情報記録の行数の2倍を超える場合）、テーブルまたはパーティションは非同期収集の候補範囲に入ります。

前回統計情報記録の行数が0の場合、現在モニタリングされている累積新規行数から累積削除行数を引いた値が0より大きい場合、テーブルまたはパーティションは非同期収集の候補範囲に入ります。計算結果が0の場合、前回統計情報記録の行数が0であるだけでは候補範囲には入りません。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>上記条件を満たすことは、テーブルまたはパーティションが非同期収集の候補範囲に入ったことを意味するものの、統計情報が直ちに収集完了することを意味するものではありません。非同期統計情報収集のデフォルトの判断しきい値は2です。自動統計情報収集は<code>STALE_PERCENT</code>で統計情報の有効期限しきい値を制御し、そのデフォルト値は10（つまり10%）です。</p>
</main>

## パーティションテーブルの判断粒度

システムは、異なるタイプのテーブルに対して、以下の粒度で独立して非同期収集の候補条件を判断します：

* 非パーティションテーブルの場合、テーブル単位で判断します。

* 単一レベルのパーティションテーブルの場合、パーティション単位で判断します。

* コンポジット・パーティションテーブルの場合、サブパーティション単位で判断します。
