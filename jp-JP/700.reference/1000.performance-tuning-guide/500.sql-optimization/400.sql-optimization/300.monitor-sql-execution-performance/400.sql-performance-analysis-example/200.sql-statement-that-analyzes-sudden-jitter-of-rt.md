# RTの急激な変動を引き起こすSQLの分析

問題の分析には、外部診断ツールであるTarsを使用するか、`(G)V$OB_SQL_AUDIT`ビューを使用して問題を調査することを推奨します。

`(G)V$OB_SQL_AUDIT`を使用した問題調査の手順は以下の通りです：

1. オンライン環境でRTが変動した場合、その変動が継続的に高い状態ではない場合、変動発生後に直ちにSQL Auditを無効化する（`ALTER SYSTEM SET enable_sql_audit = false;`を設定）ことを検討し、変動を引き起こしたSQLリクエストがSQL Auditに記録されるようにします。

2. SQL Auditを使用して、変動が発生した直前の一定期間におけるRTの上位Nリクエストを照会し、異常なSQLを分析します。

3. 対応するRT異常リクエストを特定した場合、SQL Audit内のそのリクエストの記録を分析して問題を調査します：

a. 長時間待機イベントが発生していないか確認します。

b. ロジックリード回数が異常に多いかどうかを分析します（大規模アカウントが突然増加した場合に発生する可能性があります）。

   ```sql
   ロジックリード回数 = 2 * ROW_CACHE_HIT
   + 2 * BLOOM_FILTER_CACHE_HIT
   + BLOCK_CACHE_HIT + DISK_READS
   ```

SQL Audit内でRTが変動したリクエストデータが既に削除されている場合は、OBServerノード内の変動時点に遅延クエリのTraceログが存在するかどうかを確認し、対応するTraceログを分析する必要があります。
