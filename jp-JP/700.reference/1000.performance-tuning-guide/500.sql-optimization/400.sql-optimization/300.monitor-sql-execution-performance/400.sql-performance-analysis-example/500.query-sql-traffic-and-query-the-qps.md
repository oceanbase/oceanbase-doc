# SQLトラフィックの分布状況とQPSの確認

場合によっては、OceanBaseデータベースノード間で負荷の不均衡が発生し、パフォーマンスボトルネックを引き起こす可能性があります。このような問題を診断するために、各OBServerノード間のSQLトラフィックの分布状況および各ノードのクエリ処理速度（QPS）を照会することができます。

以下は、特定のSQL文が過去1秒間に各ノードでどのように実行されたかを確認するためのSQLクエリ例です：

```sql
SELECT
  /*+ PARALLEL(15) */ -- クエリの高速化のために15個の並列スレッドを使用
  t2.zone,            -- OBServerノードが属するリージョンを表示
  t1.svr_ip,          -- SQLを処理するOBServerノードのIPアドレスを表示
  COUNT(*) AS RPC_COUNT,  -- 各ノードで実行されるRPC（リモートプロシージャコール）の数を統計
  AVG(t1.elapsed_time) AS AVG_ELAPSED_TIME, -- 各ノード上のSQL文の平均実行時間を計算
  AVG(t1.queue_time) AS AVG_QUEUE_TIME      -- 各ノード上のSQL文の平均キュー待機時間を計算
FROM
  oceanbase.GV$OB_SQL_AUDIT t1,  -- oceanbaseシステムビューで、SQL監査情報を提供
  __all_server t2                -- システムテーブルで、すべてのOBServerの情報を含む
WHERE
  t1.svr_ip = t2.svr_ip          -- JOIN条件を確保し、SQL監査レコードとサーバー情報をマッチング
  AND t1.tenant_id = 1001        -- クエリ対象のテナントIDを指定
  AND t1.sql_id = 'BF7AA13A28DF50BA5C33FF19F1DBD8A9' -- クエリ対象の特定のSQL文のIDを指定
  AND t1.is_executor_rpc = 0     -- フィルタ条件で、実行者RPCリクエスト以外のみを計算するようにします
  AND t1.request_time > (time_to_usec(now()) - 1000000) -- クエリ時間範囲を最近1秒以内に制限
  AND t1.request_time < time_to_usec(now()) -- 現在時刻を基準に、リクエスト時間が1秒以内であることを確保
GROUP BY
  t1.svr_ip; -- サーバーIPアドレスに基づいて結果をグループ化
```
