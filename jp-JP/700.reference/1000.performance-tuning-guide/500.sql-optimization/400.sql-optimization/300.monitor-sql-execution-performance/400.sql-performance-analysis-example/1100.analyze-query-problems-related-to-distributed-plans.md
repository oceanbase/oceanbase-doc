# 分散実行計画に関連するクエリ問題の分析

分散実行計画は、以下の手順でクエリ問題を分析します：

1.`(G)V$OB_PLAN_CACHE_PLAN_STAT`ビューおよび`(G)V$OB_SQL_AUDIT`の実行計画タイプに関するレコードを確認し、分散実行計画であるかどうかを判断します。

2.その実行計画が正しいかどうかを分析します。

3.`trace_id`を使用してクエリ`(G)V$OB_SQL_AUDIT`に関連付け、実行されたすべてのサブプランの時間消費状況を確認します。各サブプランのRPC実行には1件のSQL Auditレコードが対応しており、このSQL Auditレコードを分析して問題を特定します。

以下の例のように、`is_executor_rpc = 1`はサブプランの実行がSQL Auditに記録されていることを示し、主に実行に関連する情報を記録します。`isExecutorRpc = 0`は、SQLリクエストを受信したスレッドのSQL Auditにおける記録を示します。この記録には、SQL情報や実行計画情報の取得など、SQL実行プロセスの情報が含まれます。

```sql
obclient> SELECT/*+ PARALLEL(15)*/sql_id, is_executor_rpc, elapsed_time
           FROM oceanbase.GV$OB_SQL_AUDIT WHERE trace_id = 'YB420AB74FC6-00056349D323483A';

| sql_id                           | is_executor_rpc | elapsed_time |

+----------------------------------+-----------------+--------------+
```
