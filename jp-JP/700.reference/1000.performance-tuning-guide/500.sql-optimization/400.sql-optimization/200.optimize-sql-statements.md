# SQLチューニングの基本的なプロセス

SQLチューニングにおいて、遅延するSQLの分析手順は以下のとおりです：

1. グローバルSQL監査テーブル`(G)V$OB_SQL_AUDIT`、SQLトレース、および計画キャッシュビューを使用してSQL実行パフォーマンス情報を確認し、SQLリクエストの処理過程で時間消費やリソース（メモリ、ディスクI/Oなど）の消費を引き起こすSQLを初期段階で特定します。例：[特定の期間内に実行時間が上位N位のリクエストを照会する](300.monitor-sql-execution-performance/400.sql-performance-analysis-example/1000.query-the-top-n-requests-with-the-most-execution-time.md)。

   SQLパフォーマンス分析については、[SQL実行パフォーマンス監視](300.monitor-sql-execution-performance/100.gv-ob-sql-audit.md)を参照してください。

2. 単一のSQLの実行パフォーマンスは、そのSQLの実行計画に関連している場合が多いため、実行計画の分析が最も重要な手段です。`EXPALIN`コマンドを実行して、オプティマイザが指定されたSQLに対して生成した論理的実行計画を確認し、チューニングの方向性を決定します。例：[実行計画の形状を確認して分析する](300.monitor-sql-execution-performance/400.sql-performance-analysis-example/300.view-and-analyze-the-execution-plan.md)。

   実行計画の詳細については、[SQL実行計画の概要](../200.sql-execution-plan/100.introduction-to-sql-execution-plans.md)を参照してください。

3. SQLに含まれるテーブル、列、述語などのオブジェクトに関する統計情報を収集します。統計情報はコストモデルにおいて最適な実行計画を選択するための鍵となり、オプティマイザは統計情報を利用して計画選択戦略を最適化できます。詳細については、[統計情報の収集](400.optimizer-statistics/100.statistics-overview.md)を参照してください。

4. 具体的な遅延SQLを特定し、一部のSQLの実行時間やリソース消費を期待通りにするための一般的な最適化方法は以下のとおりです：
   * SQLを等価書き換えして最適な実行計画を生成します。詳細については、[クエリの書き換え](500.query-rewrite/100.query-rewrite-overview.md)を参照してください。
   * 複数のテーブルにアクセスするSQLの場合、複数のテーブル間の結合問題にも注意が必要です。アクセスパス、結合順序、結合アルゴリズムなどを最適化することで、クエリの最適化を実現します。詳細については、[アクセスパス](600.query-optimization/100.access-path/100.access-path-overview.md)、[結合アルゴリズム](600.query-optimization/200.join-algorithm/200.join-algorithm.md)、[結合順序](600.query-optimization/200.join-algorithm/400.join-order.md)を参照してください。
