# 関連用語

**実行計画**

オプティマイザーが特定のSQLに対して生成する実行プロセスで、一般的に演算子木を用いて表現されます。

**ローカル計画**

実行計画が単一のテーブルまたはパーティションテーブルの単一のパーティションのみに関わり、かつそのテーブルまたはパーティションが現在のノード上にある場合、その計画は「ローカル計画」となります。

**リモート計画**

実行計画が単一のテーブルまたはパーティションテーブルの単一のパーティションのみに関わり、かつそのテーブルまたはパーティションが他のノード上にある場合、その計画は「リモート計画」となります。

**分散計画**

実行計画が複数のテーブルまたはパーティションに関わる場合、その計画は分散計画となります。

**アクセスパス**

特定のテーブルにアクセスする際に使用されるアクセス方法で、主表アクセスとセカンダリインデックスアクセスの2種類があります。詳細については、[アクセスパス](400.sql-optimization/600.query-optimization/100.access-path/100.access-path-overview.md)を参照してください。

**結合順序**

複数のテーブルを結合する際の各テーブル間の結合順序です。現在、OceanBaseデータベースは左深木の結合順序のみをサポートしています。詳細については、[結合順序](400.sql-optimization/600.query-optimization/200.join-algorithm/400.join-order.md)を参照してください。

**結合アルゴリズム**

2つのテーブルを結合する際に使用されるアルゴリズムで、Nested Loop Join、Merge Join、Hash Joinの3種類があります。

**クエリのリライト**

ユーザーのクエリを等価に書き換えることで、最適な実行計画の生成を容易にするプロセスです。

**実行計画のバインド**

ユーザーがOutlineを指定することで、特定のSQLの実行計画を指定するプロセスです。詳細については、[計画のバインド](400.sql-optimization/700.manage-execution-plans/200.plan-binding.md)を参照してください。

**SQL Plan Management (**SPM)**

計画進化のメカニズムです。オプティマイザーが新しい計画を生成した際、この進化メカニズムを通じてその計画のパフォーマンスが低下しないことを保証します。パフォーマンスが低下した場合はその計画の使用を拒否し、そうでない場合はその計画を使用します。

**Adaptive Cursor Sharing (ACS)**

オプティマイザーが各パラメータ化されたSQLに対して複数の計画を保存し、SQL文内の述語の選択度空間に基づいて適切な計画を選択できるようにするメカニズムです。

**Data Flow Object (DFO)**

分散実行計画は、データ再配分ポイントを境界として、並列実行可能な論理的サブプランに分割され、各サブプランは1つのDFOによってカプセル化されます。
