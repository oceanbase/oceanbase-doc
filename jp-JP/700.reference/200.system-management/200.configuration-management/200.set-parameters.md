# パラメータの設定

OceanBaseデータベースのパラメータは、クラスタレベル構成パラメータとテナントレベル構成パラメータに分類されます。パラメータを設定することで、OceanBaseデータベースの動作をビジネス要件に合わせてカスタマイズできます。

## パラメータの分類

OceanBaseデータベースの構成パラメータは、クラスタレベル構成パラメータとテナントレベル構成パラメータに分類されます。構成パラメータの設定により、クラスタ全体のロードバランシング、マージ時間、マージ方式、リソース割り当て、モジュールのオン/オフなどの機能を制御できます。

* クラスタレベル構成パラメータ：対象範囲はクラスタ内のすべてのOBServerです。

* テナントレベル構成パラメータ：対象範囲は、クラスタ内における現在のテナントが配置されているOBServerです。

名前が「_」で始まる構成パラメータは隠れた構成パラメータと呼ばれ、例えば`_ob_max_thread_num`などが該当します。これらは開発者が障害のトラブルシューティングや緊急な運用保守時にのみ使用します。本記事では隠れた構成パラメータについて詳しく説明しません。以下の説明に含まれる構成パラメータには隠れた構成パラメータは含まれません。

異なるテナント間での構成パラメータの表示と変更のレベルは、次の表のとおりです：

| テナントタイプ | パラメータの確認    | パラメータの設定  |
|---------|-------------|-------------|
| システムテナント | クラスタレベル構成パラメータ、テナントレベル構成パラメータ<main id="notice" type='explain'><h4>説明</h4><p><code>SHOW PARAMETERS</code> ステートメントは、<code>TENANT</code> キーワードを指定することで、指定したテナントの構成パラメータ情報を確認します。</p></main>| クラスタレベル構成パラメータ、テナントレベル構成パラメータ<main id="notice" type='explain'><h4>説明</h4><p>システムテナントでは、<code>TENANT</code> キーワードを指定することで、すべてまたは指定したテナントのテナントレベル構成パラメータを変更できます。</p></main>|
| 通常テナント | クラスタレベル構成パラメータと当該テナントのテナントレベル構成パラメータ   | 当該テナントのテナントレベル構成パラメータ|

現在のOceanBaseデータベースにおける構成パラメータの主なデータ型と関連説明は、次の表のとおりです：

|    データ型     |                                              説明                                               |
|-------------|-----------------------------------------------------------------------------------------------|
| BOOL        | boolean型（ブール）。true/falseをサポートします。                                                                 |
| CAPACITY    | 容量単位。b（バイト）、k（KB、キロバイト）、m（MB、メガバイト）、g（GB、10億バイト）、t（TB、1兆バイト）、p（PB、1000億バイト）をサポートします。単位は大文字と小文字を区別せず、デフォルトはmです。 |
| DOUBLE      | 倍精度浮動小数点数。64ビットのストレージ容量を使用し、小数点以下15桁まで正確で、有効桁数は16桁です。                                                |
| INT         | int64整数型。正の整数、負の整数、および0をサポートします。                                                                           |
| MOMENT      | 時刻。形式は`hh:mm`（例：`02:00`）です。または、時間を指定しないことを示す特別値`disable`も使用できます。現在は`major_freeze_duty_time`パラメータでのみ使用されます。         |
| STRING      | 文字列。ユーザーが入力した文字列の値。                                                                               |
| STRING_LIST | 文字列リスト。セミコロン（;）で区切られた複数の文字列です。                                                                       |
| TIME        | 時間型。us（マイクロ秒）、ms（ミリ秒）、s（秒）、m（分）、h（時）、d（日）などの単位をサポートします。接尾辞を付けない場合、デフォルトは秒（s）です。単位は大文字と小文字を区別しません。              |

## 構成パラメータの変更

:::tab
tab MySQLモード

MySQLモードで構成パラメータを変更するSQL構文は以下のとおりです：

```sql
ALTER SYSTEM [SET]
parameter_name = expression [SCOPE = {SPFILE | BOTH}] [COMMENT [=] 'text']
[ TENANT [=] ALL|all_user|all_meta|tenant_name ] {SERVER [=] 'ip:port' | ZONE [=] 'zone'};
```

パラメータ説明：

* `parameter_name`：変更する構成パラメータ名を指定します。

* `expression`：変更後の構成パラメータの値を指定します。

* `COMMENT 'text'`：この変更に関するコメントを追加します。このパラメータはオプションですが、省略しないことを推奨します。

* `SCOPE`：この構成パラメータ変更の適用範囲を指定します。デフォルトは`BOTH`です。

  * `SPFILE`：内部テーブル内の構成パラメータ値のみを変更することを示します。OBServerノードの再起動後に有効になります。再起動後に有効になる構成パラメータのみサポートされます。

  * `BOTH`：内部テーブル内の構成パラメータ値とメモリ内の構成パラメータ値の両方を変更することを示します。変更は即時に有効になり、OBServerノードの再起動後も設定値は有効です。

* `TENANT`：システムテナント配下で、すべてまたは指定したテナントのテナントレベル構成パラメータを変更するために使用します。

  * `ALL`：V4.2.1バージョン以降、<code>tenant = all</code> と <code>tenant = all_user</code> は同じ意味を持ち、どちらもすべてのユーザーテナントに適用されることを示します。<code>all</code> 構文は廃止予定であり、使用は推奨されません。

  * `all_user`：すべてのユーザーテナントに適用されます。
  * `all_meta`：すべてのMETAテナントに適用されます。

  * `tenant_name`：指定するテナントを指定します。

* `SERVER`：指定したServerインスタンスの特定の構成パラメータのみを変更します。

* `ZONE`：この構成パラメータの変更が指定されたクラスタの特定のServerタイプに対して行われることを示します。指定しない場合は、すべてのクラスタの特定のServerタイプに対して行われます。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <ul>
    <li>複数の構成パラメータを同時に変更する場合は、カンマ（,）で区切ります。</li>
    <li>クラスタレベルの構成パラメータは、通常のテナントでは設定できず、システムテナント（<code>sys</code> テナント）から通常のテナントへの設定も指定できません。システムテナント配下でのみ設定が可能です。例えば、<code>ALTER SYSTEM SET memory_limit='100G' TENANT='test_tenant'</code> ステートメントを実行するとエラーが発生します。これは、<code>memory_limit</code> がクラスタレベルの構成パラメータだからです。</li>
    <li>テナントレベルの構成パラメータは、そのテナント内で直接変更できるほか、システムテナント配下で <code>TENANT</code> キーワードを指定することで変更できます。</li>
    <li><code>ALTER SYSTEM</code> ステートメントでは、ZoneとOBServerを同時に指定することはできません。Zoneを指定する場合は1つのZoneのみを指定でき、OBServerを指定する場合も1つのOBServerのみを指定できます。変更時にZoneもOBServerも指定しない場合、クラスタレベルの構成パラメータはクラスタ内のすべてのOBServer上で有効になり、テナントレベルの構成パラメータは現在のテナントがクラスタ内に存在するOBServer上で有効になります。</li>
    <li>構成パラメータがクラスタレベルかテナントレベルかを確認するには、<code>SHOW PARAMETERS</code> ステートメントの実行結果における <code>scope</code> 列の値を判断します。</li>
    <ul>
    <li><code>scope</code> の値が <code>CLUSTER</code> の場合、クラスタレベルの構成パラメータです。</li>
    <li><code>scope</code> の値が <code>TENANT</code> の場合、テナントレベルの構成パラメータです。</li>
    </ul>
    </ul>
  </main>

`log_disk_utilization_threshold` パラメータを変更する例を以下に示します：

```shell
obclient> ALTER SYSTEM SET log_disk_utilization_threshold = 20;
```

指定したZoneの `log_disk_utilization_threshold` パラメータを変更する例を以下に示します：

```shell
obclient> ALTER SYSTEM SET log_disk_utilization_threshold = 20 ZONE='z1';
```

指定したOBServerの `log_disk_utilization_threshold` パラメータを変更する例を以下に示します：

```shell
obclient> ALTER SYSTEM SET log_disk_utilization_threshold = 20 SERVER='XXX.XXX.XXX.XXX:XXXXX';
```

システムテナント配下で、すべてまたは指定したテナントのテナントレベル構成パラメータを変更する例を以下に示します：

```shell
obclient> ALTER SYSTEM SET log_disk_utilization_threshold = 20 TENANT='ALL';

obclient> ALTER SYSTEM SET log_disk_utilization_threshold = 20 TENANT='Oracle';
```

<main id="notice" type='explain'>
<h4>説明</h4>
<p>実行が成功すると、指定されたすべてのテナントのパラメータが変更されます。</p>
</main>

tab Oracleモード

Oracleモードで構成パラメータを変更するSQL構文は次のとおりです：

```sql
ALTER SYSTEM SET parameter_name = expression
```

パラメータ説明：

* parameter_name：変更する構成パラメータ名を指定します。

* expression：変更後の構成パラメータの値を指定します。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <ul>
    <li>複数の構成パラメータを同時に変更する場合は、カンマ（,）で区切ります。</li>
    <li>Oracleモードでは、テナントレベルの構成パラメータのみを設定できます。</li>
    <li>テナントレベルの構成パラメータは、現在のテナント内で直接変更することも、システムテナント内で<code>TENANT</code>キーワードを指定して変更することもできます。</li>
    </ul>
  </main>

`log_disk_utilization_threshold` パラメータを変更する例は以下のとおりです：

```shell
obclient> ALTER SYSTEM SET log_disk_utilization_threshold = 20;
```

## 構成パラメータのリセット

:::tab
tab MySQLモード

MySQLモードでのパラメータをリセットするSQL構文は以下のとおりです：

```sql
ALTER SYSTEM [RESET]
parameter_name [SCOPE = {MEMORY | SPFILE | BOTH}] {TENANT [=] 'tenant_name'};
```

パラメータ説明：

* `RESET` は、現在のパラメータ値をクリアし、パラメータのデフォルト値または起動時値を使用します。

* `SCOPE`：このパラメータ変更の有効範囲を指定します。デフォルトは `BOTH` です。

  * `MEMORY`：メモリ内のパラメータ値のみをリセットします。変更は即時に反映されますが、OBServerノードが再起動するとこの変更は無効になります（現在、この方法をサポートするパラメータはありません）。

  * `SPFILE`：内部テーブル内のパラメータ値のみをリセットします。変更はOBServerノードの再起動後に有効になります。再起動後に有効になるパラメータのみがサポートされます。

  * `BOTH`：内部テーブル内のパラメータ値とメモリ内のパラメータ値の両方をリセットします。リセットは即時に反映され、OBServerノードが再起動しても設定値は有効です。

* `TENANT`：システムテナント内で、すべてのテナントまたは指定したテナントのテナントレベルのパラメータをリセットするために使用します。

  * `tenant_name`：テナントを指定します。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <ul>
    <li>複数のパラメータを同時にリセットする場合は、カンマ（,）で区切ります。</li>
    <li>クラスタレベルのパラメータは、通常のテナントではリセットできず、システムテナント（<code>sys</code> テナント）から通常のテナントに指定してリセットすることもできません。システムテナント内でのみリセットがサポートされます。例えば、<code>ALTER SYSTEM RESET memory_limit TENANT='test_tenant'</code> ステートメントを実行するとエラーが発生します。これは、<code>memory_limit</code> がクラスタレベルのパラメータだからです。</li>
    <li>テナントレベルのパラメータは、そのテナント内で直接変更することも、システムテナント内で <code>TENANT</code> キーワードを指定して変更することもできます。</li>
    <li><code>ALTER SYSTEM RESET</code> ステートメントでは、ZoneやOBServerを指定することはできません。</li>
    <li>パラメータがクラスタレベルかテナントレベルかを確認するには、<code>SHOW PARAMETERS</code> ステートメントの実行結果における <code>scope</code> 列の値に基づいて判断できます：</li>
    <ul>
    <li><code>scope</code> の値が <code>CLUSTER</code> の場合、クラスタレベルのパラメータです。</li>
    <li><code>scope</code> の値が <code>TENANT</code> の場合、テナントレベルのパラメータです。</li>
    </ul>
    </ul>
  </main>

`log_disk_utilization_threshold` パラメータをリセットする例を以下に示します：

```sql
obclient> ALTER SYSTEM RESET log_disk_utilization_threshold;
```

システムテナント内で、すべてのテナントまたは指定したテナントのテナントレベルのパラメータをリセットします。例：

```sql
obclient> ALTER SYSTEM RESET log_disk_utilization_threshold TENANT='ALL';
obclient> ALTER SYSTEM RESET log_disk_utilization_threshold TENANT='Oracle';
```

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>実行が成功すると、指定されたすべてのテナントのパラメータが変更されます。</p>
  </main>

tab Oracleモード

Oracleモードで構成パラメータを変更するSQL構文は次のとおりです：

```sql
ALTER SYSTEM [RESET] parameter_name = expression;
```

パラメータ説明：

* `RESET` は、現在のパラメータ値をクリアし、パラメータのデフォルト値または起動時値を使用します。

* parameter_name：リセットする構成パラメータ名を指定します。

* expression：構成パラメータのリセット値を指定します。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <ul>
    <li>複数の構成パラメータを同時にリセットする場合は、カンマ（,）で区切ります。</li>
    <li>Oracleモードでは、テナントレベルの構成パラメータのみをリセットできます。</li>
    <li>テナントレベルの構成パラメータは、そのテナント内で直接リセットすることも、システムテナント内で <code>TENANT</code> キーワードを指定してリセットすることもできます。</li>
    </ul>
  </main>

`log_disk_utilization_threshold` パラメータをリセットする例：

```sql
obclient> ALTER SYSTEM RESET log_disk_utilization_threshold;
```

## パラメータの確認

パラメータを確認するSQL構文は次のとおりです：

```sql
SHOW PARAMETERS [LIKE 'pattern' | WHERE expr] [TENANT = tenant_name]
```

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <ul>
    <li>システムテナントでは、自身のテナントレベルのパラメータとクラスタレベルのパラメータ情報を確認できます。また、<code>TENANT</code> キーワードを指定することで、指定したテナントのパラメータ情報を確認できます。</li>
    <li>通常テナントでは、自身のテナントレベルのパラメータおよびシステムテナントのクラスタレベルのパラメータ情報を確認できます。</li>
    <li><code>WHERE expr</code> で指定できる列属性は、<code>SHOW PARAMETERS</code> の実行結果に含まれる列属性と一致している必要があります。</li>
    </ul>
  </main>

`SHOW PARAMETERS` ステートメントを使用してパラメータを確認する例は以下のとおりです：

```shell
obclient> SHOW PARAMETERS WHERE scope = 'tenant';

obclient> SHOW PARAMETERS WHERE svr_ip != 'XXX.XXX.XXX.XXX';

obclient> SHOW PARAMETERS WHERE INFO like '%ara%';

obclient> SHOW PARAMETERS LIKE 'large_query_threshold';
```

実行結果は次のとおりです：

```shell
+-------+----------+----------------+----------+-----------------------+-----------+-------+-------------------------------------------------------------------------------------------------------------------------------------------------------------------+---------+---------+---------+-------------------+---------------+-----------+
| zone  | svr_type | svr_ip         | svr_port | name                  | data_type | value | info                                                                                                                                                              | section | scope   | source  | edit_level        | default_value | isdefault |
+-------+----------+----------------+----------+-----------------------+-----------+-------+-------------------------------------------------------------------------------------------------------------------------------------------------------------------+---------+---------+---------+-------------------+---------------+-----------+
| zone1 | observer | 172.xx.xxx.xxx |     2882 | large_query_threshold | TIME      | 5s    | threshold for execution time beyond which a request may be paused and rescheduled as a \'large request\', 0ms means disable \'large request\'. Range: [0ms, +∞)   | TENANT  | CLUSTER | DEFAULT | DYNAMIC_EFFECTIVE | 5s            |         1 |
+-------+----------+----------------+----------+-----------------------+-----------+-------+-------------------------------------------------------------------------------------------------------------------------------------------------------------------+---------+---------+---------+-------------------+---------------+-----------+
1 row in set
```

実行結果に含まれる列属性は、次の表のとおりです：

|  プロパティ名      |          意味                                                                                            |
|-----------|----------------------------------------------------------------------------------------------------------|
| zone      | ゾーンの場所        |
| svr_type   | マシンタイプ      |
| svr_ip     | マシンIP     |
| svr_port   | マシンポート  |
| name       | パラメータ名      |
| data_type  | パラメータデータ型。`NUMBER`、`STRING`、`CAPACITY`などが含まれます   |
| value      | パラメータ値 <br>**説明**<br>  パラメータ値を変更する際には、指定したゾーンまたはサーバーのパラメータ値を変更できるため、異なるゾーンまたはサーバーに対応するパラメータの値は異なる場合があります。    |
| info       | パラメータの説明情報     |
| section    | パラメータが属する分類： <ul><li>`SSTABLE`：SSTable関連のパラメータを表します。</li><li> `OBSERVER`：OBServerノード関連のパラメータを表します。   </li><li>`ROOT_SERVICE`：Root Service関連のパラメータを表します。</li><li> `TENANT`：テナント関連のパラメータを表します。   </li><li>`TRANS`：トランザクション関連のパラメータを表します。</li><li> `LOAD_BALANCE`：ロードバランシング関連のパラメータを表します。   </li><li>`DAILY_MERGE`：マージ関連のパラメータを表します。</li><li> `CLOG`：Clog関連のパラメータを表します。   </li><li>`LOCATION_CACHE`：Location Cache関連のパラメータを表します。</li><li> `CACHE`：キャッシュ関連のパラメータを表します。   </li><li>`RPC`：RPC関連のパラメータを表します。</li><li> `OBPROXY`：OBProxy関連のパラメータを表します。</li></ul>    |
| scope      | パラメータ範囲属性： <ul><li>`TENANT`：このパラメータがテナントレベルのパラメータであることを示します</li><li> `CLUSTER`：このパラメータがクラスタレベルのパラメータであることを示します</li></ul>  |
| source     | 現在の値の出典： <ul><li>`TENANT`</li><li> `CLUSTER`   </li><li>`CMDLINE`</li><li> `OBADMIN`   </li><li>`FILE`</li><li> `DEFAULT`  </li></ul> |
| edit_level | この構成パラメータの変更動作を定義します：<ul><li>`READONLY`：このパラメータは変更できません。</li><li> `STATIC_EFFECTIVE`：このパラメータは変更できますが、OBServerノードを再起動しないと変更が有効になりません。</li><li>  `DYNAMIC_EFFECTIVE`：このパラメータは変更でき、変更後は動的に反映されます。</li></ul>     |
| default_value | パラメータのデフォルト値。 |
| isdefault  | 現在の値がデフォルト値かどうか。<ul><li>0：現在の値がデフォルト値ではないことを示します。</li><li>1：現在の値がデフォルト値であることを示します。</li></ul> |
