# パラメータの設定

OceanBaseデータベースの構成パラメータは、クラスタレベルとテナントレベルに分かれています。構成パラメータを設定することで、OceanBaseデータベースの動作を業務要件に合わせることができます。

## パラメータの分類

OceanBaseデータベースの構成パラメータは、クラスタレベルとテナントレベルに分かれています。構成パラメータの設定により、クラスタ全体のロードバランシング、コンパクション時間、コンパクション方式、リソース割り当て、モジュールのオン/オフなどの機能を制御できます。

* クラスタレベルの構成パラメータ：その適用範囲はクラスタ内のすべてのOBServerです。

* テナントレベルの構成パラメータ：その適用範囲は、クラスタ内の現在のテナントが存在するOBServerです。

名前が「_」で始まる構成パラメータは隠しパラメータと呼ばれ、例えば`_ob_max_thread_num`などがあります。これらは開発者が障害調査や緊急の運用保守時にのみ使用します。本記事では隠しパラメータについて詳しく説明しません。以下の構成パラメータには隠しパラメータは含まれません。

異なるテナントにおける構成パラメータの表示および変更レベルは、以下の表のとおりです：

| テナントタイプ | パラメータの確認 | パラメータの設定 |
|---------|-------------|-------------|
| システムテナント | クラスタレベルの構成パラメータ、テナントレベルの構成パラメータ<main id="notice" type='explain'><h4>説明</h4><p><code>SHOW PARAMETERS</code> ステートメントは、<code>TENANT</code> キーワードを指定することで、指定されたテナントの構成パラメータ情報を確認します。</p></main>| クラスタレベルの構成パラメータ、テナントレベルの構成パラメータ<main id="notice" type='explain'><h4>説明</h4><p>システムテナントでは、<code>TENANT</code> キーワードを指定することで、すべてまたは指定されたテナントのテナントレベルの構成パラメータを変更できます。</p></main>|
| 一般テナント | クラスタレベルの構成パラメータと当該テナントのテナントレベルの構成パラメータ | 当該テナントのテナントレベルの構成パラメータ|

現在のOceanBaseデータベースにおける構成パラメータの主なデータ型と関連説明は、以下の表のとおりです：

|    データ型     |                                              説明                                               |
|-------------|-----------------------------------------------------------------------------------------------|
| BOOL        | boolean型（ブール）。true/falseをサポートします。                                                                 |
| CAPACITY    | 容量単位。b（バイト）、k（KB、キロバイト）、m（MB、メガバイト）、g（GB、10億バイト）、t（TB、テラバイト）、p（PB、ペタバイト）をサポートします。単位は大文字と小文字を区別しません。デフォルトはmです。 |
| DOUBLE      | 雙精度浮動小数点数。64ビットのストレージ容量を使用し、小数点以下15桁まで正確に表現できます。有効桁数は16桁です。                                                |
| INT         | int64整数型。正の整数、負の整数、および0をサポートします。                                                                           |
| MOMENT      | 時刻。形式は`hh:mm`（例：`02:00`）または特別値`disable`であり、時間を指定しないことを意味します。現在、このパラメータは`major_freeze_duty_time`パラメータでのみ使用されています。         |
| STRING      | 文字列。ユーザーが入力した文字列の値。                                                                               |
| STRING_LIST | 文字列リスト。セミコロン（;）で区切られた複数の文字列です。                                                                       |
| TIME        | 時間型。us（マイクロ秒）、ms（ミリ秒）、s（秒）、m（分）、h（時間）、d（日）などの単位をサポートします。接尾辞を付けない場合、デフォルトは秒（s）です。単位は大文字と小文字を区別しません。              |

## パラメータの変更

:::tab
tab MySQLモード

MySQLモードで構成パラメータを変更するSQL構文は以下のとおりです：

```sql
ALTER SYSTEM [SET]
parameter_name = expression [SCOPE = {SPFILE | BOTH}] [COMMENT [=] 'text']
[ TENANT [=] ALL|all_user|all_meta|tenant_name ] {SERVER [=] 'ip:port' | ZONE [=] 'zone'};
```

パラメータの説明：

* `parameter_name`：変更する構成パラメータ名を指定します。

* `expression`：変更後の構成パラメータ値を指定します。

* `COMMENT 'text'`：この変更に関するコメントを追加します。このパラメータはオプションですが、省略しないことを推奨します。

* `SCOPE`：この構成パラメータ変更の適用範囲を指定します。デフォルトは `BOTH` です。

  * `SPFILE`：内部テーブル内の構成パラメータ値のみを変更し、OBServerノードの再起動後にのみ有効になることを示します。再起動後にのみ有効になる構成パラメータのみサポートされます。

  * `BOTH`：内部テーブル内の構成パラメータ値とメモリ内の構成パラメータ値の両方を変更し、変更は即時に有効になり、OBServerノードの再起動後も構成値は引き続き有効です。

* `TENANT`：システムテナント内で、すべてまたは指定されたテナントのテナントレベルの構成パラメータを変更するために使用されます。

  * `ALL`：V4.2.1バージョン以降、<code>tenant = all</code> と <code>tenant = all_user</code> は同じ意味を持ち、どちらもすべてのユーザーテナントに対して有効であることを示します。<code>all</code> 構文は廃止されつつあり、使用は推奨されません。

  * `all_user`：すべてのユーザーテナントに対して有効です。
  * `all_meta`：すべてのMETAテナントに対して有効です。

  * `tenant_name`：テナントを指定します。

* `SERVER`：指定されたServerインスタンスの特定の構成パラメータのみを変更します。

* `ZONE`：この構成パラメータの変更が指定されたクラスタの特定のServerタイプに対して行われることを示します。それ以外の場合は、すべてのクラスタの特定のServerタイプに対して行われます。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <ul>
    <li>複数の構成パラメータを同時に変更する場合は、カンマ（,）で区切ります。</li>
    <li>クラスタレベルの構成パラメータは、通常のテナントから設定することはできず、システムテナント（つまり <code>sys</code> テナント）から通常のテナントの設定として指定することもできません。システムテナント内でのみ設定がサポートされます。たとえば、<code>ALTER SYSTEM SET memory_limit='100G' TENANT='test_tenant'</code> ステートメントを実行するとエラーが発生します。これは、<code>memory_limit</code> がクラスタレベルの構成パラメータだからです。</li>
    <li>テナントレベルの構成パラメータは、そのテナント内で直接変更することも、システムテナント内で <code>TENANT</code> キーワードを指定して変更することもできます。</li>
    <li><code>ALTER SYSTEM</code> ステートメントでは、ZoneとOBServerを同時に指定することはできません。また、Zoneを指定する場合は1つのZoneのみ、OBServerを指定する場合は1つのOBServerのみを指定できます。変更時にZoneもOBServerも指定しない場合、クラスタレベルの構成パラメータはクラスタ内のすべてのOBServer上で有効になり、テナントレベルの構成パラメータは現在のテナントがクラスタ内に存在するOBServer上で有効になります。</li>
    <li>構成パラメータがクラスタレベルかテナントレベルかを確認するには、<code>SHOW PARAMETERS</code> ステートメントの実行結果における <code>scope</code> 列の対応する値に基づいて判断できます。</li>
    <ul>
    <li><code>scope</code> 値が <code>CLUSTER</code> の場合、クラスタレベルの構成パラメータを示します。</li>
    <li><code>scope</code> 値が <code>TENANT</code> の場合、テナントレベルの構成パラメータを示します。</li>
    </ul>
    </ul>
  </main>

`log_disk_utilization_threshold` パラメータを変更する例は次のとおりです：

```shell
obclient> ALTER SYSTEM SET log_disk_utilization_threshold = 20;
```

指定されたZoneの `log_disk_utilization_threshold` パラメータを変更する例は次のとおりです：

```shell
obclient> ALTER SYSTEM SET log_disk_utilization_threshold = 20 ZONE='z1';
```

指定されたOBServerの `log_disk_utilization_threshold` パラメータを変更する例は次のとおりです：

```shell
obclient> ALTER SYSTEM SET log_disk_utilization_threshold = 20 SERVER='XXX.XXX.XXX.XXX:XXXXX';
```

システムテナント内で、すべてまたは指定されたテナントのテナントレベルの構成パラメータを変更します。例：

```shell
obclient> ALTER SYSTEM SET log_disk_utilization_threshold = 20 TENANT='ALL';

obclient> ALTER SYSTEM SET log_disk_utilization_threshold = 20 TENANT='Oracle';
```

<main id="notice" type='explain'>
<h4>説明</h4>
<p>実行が成功した後、指定されたすべてのテナントの構成パラメータが変更されます。</p>
</main>

tab Oracleモード

Oracleモードで構成パラメータを変更するSQL構文は次のとおりです：

```sql
ALTER SYSTEM SET parameter_name = expression
```

パラメータの説明：

* parameter_name：変更する構成パラメータ名を指定します。

* expression：変更後の構成パラメータ値を指定します。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <ul>
    <li>複数の構成パラメータを同時に変更する場合は、カンマ（,）で区切ります。</li>
    <li>Oracleモードでは、テナントレベルの構成パラメータのみを設定できます。</li>
    <li>テナントレベルの構成パラメータは、現在のテナント内で直接変更することも、システムテナント内で <code>TENANT</code> キーワードを指定して変更することもできます。</li>
    </ul>
  </main>

`log_disk_utilization_threshold` パラメータを変更する例は次のとおりです：

```shell
obclient> ALTER SYSTEM SET log_disk_utilization_threshold = 20;
```

## パラメータの確認

パラメータを確認するためのSQL構文は以下のとおりです：

```sql
SHOW PARAMETERS [LIKE 'pattern' | WHERE expr] [TENANT = tenant_name]
```

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <ul>
    <li>システムテナントでは、自身のテナントレベルのパラメータとクラスタレベルのパラメータ情報を確認できます。また、<code>TENANT</code> キーワードを指定することで、特定のテナントのパラメータ情報を確認することもできます。</li>
    <li>通常のテナントでは、自身のテナントレベルのパラメータおよびシステムテナントのクラスタレベルのパラメータ情報を確認できます。</li>
    <li><code>WHERE expr</code> で指定できる列属性は、<code>SHOW PARAMETERS</code> が返す結果の列属性と一致していなければなりません。</li>
    </ul>
  </main>

`SHOW PARAMETERS` ステートメントを使用してパラメータを確認する例は以下のとおりです：

```shell
obclient> SHOW PARAMETERS WHERE scope = 'tenant';

obclient> SHOW PARAMETERS WHERE svr_ip != 'XXX.XXX.XXX.XXX';

obclient> SHOW PARAMETERS WHERE INFO like '%ara%';

obclient> SHOW PARAMETERS LIKE 'large_query_threshold';
```

実行結果は次のとおりです：

```sehll
+-------+----------+----------------+----------+-----------------------+-----------+-------+------------------------------------------------------------------------------------------------------------------------------+---------+---------+---------+-------------------+---------------+-----------+
| zone  | svr_type | svr_ip         | svr_port | name                  | data_type | value | info                                                                                                                         | section | scope   | source  | edit_level        | default_value | isdefault |
+-------+----------+----------------+----------+-----------------------+-----------+-------+------------------------------------------------------------------------------------------------------------------------------+---------+---------+---------+-------------------+---------------+-----------+
| zone1 | observer | xx.xx.xx.xx |    28824 | large_query_threshold | NULL      | 5s    | threshold for execution time beyond which a request may be paused and rescheduled as a \'large request\'. Range: [1ms, +∞)   | TENANT  | CLUSTER | DEFAULT | DYNAMIC_EFFECTIVE | 5s            |         1 |
+-------+----------+----------------+----------+-----------------------+-----------+-------+------------------------------------------------------------------------------------------------------------------------------+---------+---------+---------+-------------------+---------------+-----------+
1 row in set (0.204 sec)
```

実行結果の列属性は以下の表のとおりです：

|  フィールド名      |          意味                                                                                            |
|-----------|----------------------------------------------------------------------------------------------------------|
| zone      | 所属するZone        |
| svr_type   | マシンのタイプ      |
| svr_ip     | マシンのIPアドレス     |
| svr_port   | マシンのポート  |
| name       | パラメータ名      |
| data_type  | パラメータのデータ型。`NUMBER`、`STRING`、`CAPACITY`などが含まれます   |
| value      | パラメータ値 <br>**説明**<br>  パラメータ値を変更する際には、指定されたZoneまたはServerのパラメータ値を変更できるため、異なるZoneまたはServerに対応するパラメータの値は異なる場合があります。    |
| info       | パラメータの説明情報     |
| section    | パラメータが属するカテゴリ： <ul><li>`SSTABLE`：SSTable関連のパラメータを示します。</li><li> `OBSERVER`：OBServerノード関連のパラメータを示します。   </li><li>`ROOT_SERVICE`：Root Service関連のパラメータを示します。</li><li> `TENANT`：テナント関連のパラメータを示します。   </li><li>`TRANS`：トランザクション関連のパラメータを示します。</li><li> `LOAD_BALANCE`：ロードバランシング関連のパラメータを示します。   </li><li>`DAILY_MERGE`：コンパクション関連のパラメータを示します。</li><li> `CLOG`：clog関連のパラメータを示します。   </li><li>`LOCATION_CACHE`：Location Cache関連のパラメータを示します。</li><li> `CACHE`：キャッシュ関連のパラメータを示します。   </li><li>`RPC`：RPC関連のパラメータを示します。</li><li> `OBPROXY`：OBProxy関連のパラメータを示します。</li></ul>    |
| scope      | パラメータの範囲属性： <ul><li>`TENANT`：このパラメータがテナントレベルのパラメータであることを示します</li><li> `CLUSTER`：このパラメータがクラスタレベルのパラメータであることを示します</li></ul>        |
| source     | 現在の値の出所： <ul><li>`TENANT`</li><li> `CLUSTER`   </li><li>`CMDLINE`</li><li> `OBADMIN`   </li><li>`FILE`</li><li> `DEFAULT`  </li></ul>    |
| edit_level | この構成パラメータの変更動作を定義します：<ul><li>`READONLY`：このパラメータは変更できないことを示します。</li><li> `STATIC_EFFECTIVE`：このパラメータは変更可能ですが、OBServerノードの再起動後にのみ有効になります。</li><li>  `DYNAMIC_EFFECTIVE`：このパラメータは変更可能であり、変更後は即時に反映されます。</li></ul>    |
| default_value | パラメータのデフォルト値。 |
| isdefault  | 現在の値がデフォルト値かどうか。<ul><li>0：現在の値がデフォルト値ではないことを示します。</li><li>1：現在の値がデフォルト値であることを示します。</li></ul> |
