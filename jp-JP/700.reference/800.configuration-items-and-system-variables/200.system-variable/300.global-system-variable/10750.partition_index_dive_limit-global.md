# partition_index_dive_limit

<main id="notice" type='explain'>
    <h4>説明</h4>
    <p>V4.2.x系では、この変数はV4.2.5バージョンおよびV4.2.1 BP9バージョンから導入されました。</p>
  </main>

## 機能の概要

`partition_index_dive_limit`は、ストレージ層で行を推定する際にオプティマイザーが使用するパーティション数の上限を指定します。

## 権限要件

* クエリ変数

  * グローバルレベル

    sysテナントとすべてのユーザーテナントは`SHOW VARIABLES`ステートメント、または`SYS.TENANT_VIRTUAL_GLOBAL_VARIABLE`ビュー（Oracleモード）および`information_schema.GLOBAL_VARIABLES`ビュー（MySQLモード）を使用してグローバルシステム変数の値を確認できます。

  * セッションレベル

    sysテナントとすべてのユーザーテナントは`SHOW VARIABLES`ステートメント、または`SYS.TENANT_VIRTUAL_SESSION_VARIABLE`ビュー（Oracleモード）および`information_schema.SESSION_VARIABLES`ビュー（MySQLモード）を使用してセッションシステム変数の値を確認できます。

* 変数の変更

  * グローバル有効

    * sysテナントはグローバルシステム変数の値を直接変更できます。
    * MySQLユーザーテナントは`SUPER`または`ALTER SYSTEM`権限が必要です。
    * Oracleユーザーテナントは`ALTER SYSTEM`権限が必要です。

  * セッション有効

    sysテナントとすべてのユーザーテナントは、自身のテナントに属するセッションシステム変数の値を直接変更できます。

## プロパティの説明

| **プロパティ** |      **説明**                            |
|--------|------------------------------------------------------|
| パラメータタイプ   | Int                                                     |
| デフォルト値    |    10                                                   |
| 値の範囲   |   [0, INT64_MAX] <main id="notice" type='explain'><h4>説明</h4><p>ここで：<ul><li> `0` は制限なしを意味します。ただし、負の値に設定することも可能で、その場合の意味は `0` と同じです。</li><li> `INT64_MAX` は64ビット符号付き整数型の最大値を表します。</p></ul></main>|
| 適用範囲   | <ul><li>Global</li> <li>Session </li></ul>             |
| 変更は可能か  | はい。`SET` または `ALTER SESSION SET` ステートメントを使用して変更できます。|

## 使用方法

この変数を変更することで、オプティマイザーがストレージ層で行推定を行う際のパーティション数の制限を制御できます：

* パーティション数がこの変数より少ない場合、常にすべてのパーティションを選択してストレージ層で行推定を行います。
* パーティション数がこの変数以上の場合、ランダムに `partition_index_dive_limit` 個のパーティションを選択してストレージ層で行推定を行い、推定結果を同比率で拡大します。
* この変数が `0` の場合、常にすべてのパーティションを選択してストレージ層で行推定を行います。
* `range_index_dive_limit` と `partition_index_dive_limit` がどちらも負の数値の場合、ストレージ層で行推定を行うポリシーはV4.2.5以前のバージョンにロールバックし、単一パーティションの10個の範囲内でのみストレージ層で行推定を行います。それを超える場合はサンプリングしません。

## 設定例

1. テーブルを作成し、データを挿入します。

    ```shell
    obclient> CREATE TABLE t11(c1 int, c2 int, index i1(c2)) PARTITION BY range(c1) (partition p0 values less than(10), partition p1 values less than(20), partition p2 values less than(30));
    Query OK, 0 rows affected (0.112 sec)

    obclient> INSERT INTO t11 SELECT 1,1 FROM table(generator(10));
    Query OK, 10 rows affected (0.007 sec)
    Records: 10  Duplicates: 0  Warnings: 0

    obclient> INSERT INTO t11 SELECT 11,11 FROM table(generator(20));
    Query OK, 20 rows affected (0.003 sec)
    Records: 20  Duplicates: 0  Warnings: 0

    obclient> INSERT INTO t11 SELECT 21,21 FROM table(generator(30));
    Query OK, 30 rows affected (0.003 sec)
    Records: 30  Duplicates: 0  Warnings: 0
    ```

2. 実行計画を確認します。デフォルトのシナリオでは、10個のパーティションを超えない範囲でストレージ層での行推定が適用されます。
