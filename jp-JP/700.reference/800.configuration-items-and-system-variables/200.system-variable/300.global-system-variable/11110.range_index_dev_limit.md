# range_index_dive_limit

<main id="notice" type='explain'>
    <h4>説明</h4>
    <p>V4.2.x系では、この変数はV4.2.5およびV4.2.1 BP9バージョンから導入されました。</p>
  </main>

## 機能の概要

`range_index_dive_limit`は、オプティマイザーがストレージ層で行を推定する際に使用する範囲（range）の数の制限を示すために使用されます。

## 権限要件

* クエリ変数

  * グローバルレベル

    sysテナントとすべてのユーザーテナントは、`SHOW VARIABLES`ステートメント、または`SYS.TENANT_VIRTUAL_GLOBAL_VARIABLE`ビュー（Oracleモード）および`information_schema.GLOBAL_VARIABLES`ビュー（MySQLモード）を使用してグローバルシステム変数の値を確認できます。

  * セッションレベル

    sysテナントとすべてのユーザーテナントは、`SHOW VARIABLES`ステートメント、または`SYS.TENANT_VIRTUAL_SESSION_VARIABLE`ビュー（Oracleモード）および`information_schema.SESSION_VARIABLES`ビュー（MySQLモード）を使用してセッションシステム変数の値を確認できます。

* 変数の変更

  * グローバル有効

    * sysテナントはグローバルシステム変数の値を直接変更できます。
    * MySQLユーザーテナントは、`SUPER`または`ALTER SYSTEM`権限を持っている場合にのみグローバルシステム変数の値を変更できます。
    * Oracleユーザーテナントは、`ALTER SYSTEM`権限を持っている場合にのみグローバルシステム変数の値を変更できます。

  * セッション有効

    sysテナントとすべてのユーザーテナントは、自身のテナントのセッションシステム変数の値を直接変更できます。

## プロパティの説明

| **プロパティ** |        **説明**        |
|--------|----------------------------|
| パラメータタイプ   | Int                                                     |
| デフォルト値    |    10                                                   |
| 値の範囲   |   [0, INT64_MAX] <main id="notice" type='explain'><h4>説明</h4><p>その中で：<ul><li> `0` は制限なしを意味します。ただし、負の数に設定することも可能であり、その場合の意味は `0` と同じです。</li><li> `INT64_MAX` は64ビット符号付き整数型の最大値を表します。</p></ul></main>|
| 適用範囲   | <ul><li>Global</li> <li>Session </li></ul>             |
| 変更は可能か  | はい。`SET` ステートメントを使用して変更できます。|

## 使用方法

この変数を変更して、オプティマイザーがストレージ層で行を推定する際の範囲の数の制限を制御します：

* 範囲の数がこの変数より小さい場合、常にすべての範囲を選択してストレージ層で行を推定します。
* 範囲の数がこの変数以上の場合、ランダムに`range_index_dive_limit`個の範囲を選択してストレージ層で行を推定し、推定結果を比例して拡大します。
* この変数が0の場合、常にすべての範囲を選択してストレージ層で行を推定します。
* `range_index_dive_limit`と`partition_index_dive_limit`が同じく負の数の場合、ストレージ層で行を推定するポリシーは古いバージョンにロールバックされ、単一パーティションで10個以下の範囲に対してのみストレージ層で行を推定します。

## 設定例

1. テーブルを作成し、データを挿入します。

    ```shell
    obclient> CREATE TABLE t1(c1 int, c2 int, index i1(c1));
    Query OK, 0 rows affected (0.173 sec)

    obclient> INSERT INTO t1 SELECT 1,1 FROM table(generator(10));
    Query OK, 10 rows affected (0.003 sec)
    Records: 10  Duplicates: 0  Warnings: 0

    obclient> INSERT INTO t1 SELECT 2,2 FROM table(generator(20));
    Query OK, 20 rows affected (0.001 sec)
    Records: 20  Duplicates: 0  Warnings: 0

    obclient> INSERT INTO t1 SELECT 3,3 FROM table(generator(30));
    Query OK, 30 rows affected (0.001 sec)
    Records: 30  Duplicates: 0  Warnings: 0
    ```

2. 実行計画を確認します。デフォルトのシナリオでは、10個以下のrangeについてはすべてストレージ層での行数推定が採用されます。

    ```shell
    obclient> EXPLAIN SELECT c1 FROM t1 WHERE c1 in (1,2,3);
    +---------------------------------------------------------------------------------------------------------+
    | Query Plan                                                                                              |
    +---------------------------------------------------------------------------------------------------------+
    | ==================================================                                                      |
    | |ID|OPERATOR        |NAME  |EST.ROWS|EST.TIME(us)|                                                      |
    | --------------------------------------------------                                                      |
    | |0 |TABLE RANGE SCAN|t1(i1)|60      |11          |                                                      |
    | ==================================================                                                      |
    | Outputs & filters:                                                                                      |
    | -------------------------------------                                                                   |
    |   0 - output([t1.c1]), filter(nil), rowset=256                                                          |
    |       access([t1.c1]), partitions(p0)                                                                   |
    |       is_index_back=false, is_global_index=false,                                                       |
    |       range_key([t1.c1], [t1.__pk_increment]), range(1,MIN ; 1,MAX), (2,MIN ; 2,MAX), (3,MIN ; 3,MAX),  |
    |       range_cond([t1.c1 IN (1, 2, 3)])                                                                  |
    +---------------------------------------------------------------------------------------------------------+
    12 rows in set (0.008 sec)
    ```

3. 変数を変更し、ストレージ層での行数推定を1つのrangeに限定します。

    ```shell
    obclient> SET range_index_dive_limit = 1;
    Query OK, 0 rows affected (0.001 sec)
    ```

4. 実行計画を確認すると、ストレージ層での行数推定が選択されたのは3番目のrange（3, MIN; 3, MAX）のみであり、推定結果は`30 * 3 = 90`となっています。

    ```shell
    obclient> EXPLAIN SELECT c1 FROM t1 WHERE c1 in (1,2,3);
    +---------------------------------------------------------------------------------------------------------+
    | Query Plan                                                                                              |
    +---------------------------------------------------------------------------------------------------------+
    | ==================================================                                                      |
    | |ID|OPERATOR        |NAME  |EST.ROWS|EST.TIME(us)|                                                      |
    | --------------------------------------------------                                                      |
    | |0 |TABLE RANGE SCAN|t1(i1)|90      |12          |                                                      |
    | ==================================================                                                      |
    | Outputs & filters:                                                                                      |
    | -------------------------------------                                                                   |
    |   0 - output([t1.c1]), filter(nil), rowset=256                                                          |
    |       access([t1.c1]), partitions(p0)                                                                   |
    |       is_index_back=false, is_global_index=false,                                                       |
    |       range_key([t1.c1], [t1.__pk_increment]), range(1,MIN ; 1,MAX), (2,MIN ; 2,MAX), (3,MIN ; 3,MAX),  |
    |       range_cond([t1.c1 IN (1, 2, 3)])                                                                  |
    +---------------------------------------------------------------------------------------------------------+
    12 rows in set (0.003 sec)
    ```
