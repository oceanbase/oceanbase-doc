# ob_org_cluster_id

<main id="notice" type='explain'>
<h4>説明</h4>
<p>この変数はV1.4バージョンから導入されました。</p>
</main>

## 機能の概要

`ob_org_cluster_id`は、OceanBaseデータベースのセッションレベルの`cluster_id`を設定します。この値はトランザクションログに永続化されます。

## 権限要件

* 変数の確認

  `sys`テナントとすべてのユーザーテナントは`SHOW VARIABLES`ステートメント、または`SYS.TENANT_VIRTUAL_SESSION_VARIABLE`ビュー（Oracleモード）および`information_schema.SESSION_VARIABLES`ビュー（MySQLモード）を使用して、セッションのシステム変数の値を確認できます。

* 変数の変更

  `sys`テナントとすべてのユーザーテナントは、自身のテナント内のセッションシステム変数の値を直接変更できます。

## プロパティの説明

| **プロパティ**  |      **説明**       |
|---------|-------------------|
| パラメータタイプ    | int               |
| デフォルト値     | 0、クラスタ固有の`cluster_id`を使用することを示します。これはクラスタ作成時に生成される一意の識別子です。    |
| 値の範囲    | \[0, 4294967295\] |
| 適用範囲    | セッション          |
| 変更は可能か  |  はい。`SET`ステートメントを使用して変更できます。 |

## 使用方法

通常、`ob_org_cluster_id`変数を設定する必要はありません。OceanBaseデータベースがログ（clog）を生成する際にデフォルト値が使用されます。OMSは`ob_org_cluster_id`変数を使用してデータフィルタリング機能を実現できます。OMSのデータフィルタリング機能の詳細と設定については、「OceanBase Migration Service」の**MySQLからOceanBaseデータベースのMySQLテナントへのデータ移行プロジェクトの作成**を参照してください。

例：OMS obcdcコンポーネントの`cluster_id`ブロックリストを`cluster_id_black_list=2147473648`に設定し、OBServerノードで書き込み時にセッション変数を`SET ob_org_cluster_id=2147473648;`と設定します。その場合、obcdcがデータを受信すると、`cluster_id`が`2147473648`に等しいすべてのデータをフィルタリングします。

## 設定例

OceanBaseデータベースのセッションレベルの`cluster_id`を`2147473648`に設定します。

```shell
obclient> SET ob_org_cluster_id = 2147473648;
```
