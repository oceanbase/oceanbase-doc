# ob_org_cluster_id

<main id="notice" type='explain'>
<h4>説明</h4>
<p>この変数はV1.4バージョンから導入されました。</p>
</main>

## 機能の概要

`ob_org_cluster_id`は、OceanBaseデータベースのセッションレベルでの`cluster_id`を設定するために使用されます。この値はトランザクションログに永続化されます。

## 権限要件

* 変数の確認

  `sys`テナントとすべてのユーザーテナントは`SHOW VARIABLES`ステートメント、または`SYS.TENANT_VIRTUAL_SESSION_VARIABLE`ビュー(Oracleモード)および`information_schema.SESSION_VARIABLES`ビュー(MySQLモード)を使用して、セッションシステム変数の値を確認できます。

* 変数の変更

  `sys`テナントとすべてのユーザーテナントは、直接自テナントのセッションシステム変数の値を変更できます。

## プロパティの説明

| **プロパティ** | **説明** |
|---------|-------------------|
| パラメータタイプ | int |
| デフォルト値 | 0。クラスタ自身の`cluster_id`、つまりクラスタ作成時に生成される一意の識別子を使用することを示します。 |
| 値の範囲 | \[0, 4294967295\] |
| 適用範囲 | セッション |
| 変更は可能か | はい。`SET`ステートメントを使用して変更できます。 |

## 使用方法

通常、`ob_org_cluster_id`変数を設定する必要はありません。OceanBaseデータベースがログ(clog)を生成する際には、デフォルト値が使用されます。OMSは変数`ob_org_cluster_id`を使用してデータフィルタリング機能を実現できます。OMSのデータフィルタリング機能の詳細と構成については、「OceanBase移行サービス」の**MySQLからOceanBaseデータベースのMySQLテナントへのデータ移行プロジェクトの作成**を参照してください。

例えば、OMS obcdcコンポーネントが`cluster_id`のブラックリストを`cluster_id_black_list=2147473648`に設定し、OBServerノードが書き込む際にセッション変数を`SET ob_org_cluster_id=2147473648;`に設定した場合、obcdcはデータを受信した後、`cluster_id`が`2147473648`に等しいすべてのデータをフィルタリングします。

## 設定例

OceanBaseデータベースのセッションレベルでの`cluster_id`を`2147473648`に設定します。

```shell
obclient> SET ob_org_cluster_id = 2147473648;
```
