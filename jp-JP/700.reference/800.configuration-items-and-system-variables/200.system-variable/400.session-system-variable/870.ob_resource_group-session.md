# ob_resource_group

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>V4.4.x系では、この変数はV4.4.2 BP4バージョンから導入されました。</p>
</main>

## 機能の概要

`ob_resource_group`は、現在のセッションにデフォルトのリソースグループを指定するために使用されます。設定後、そのセッション上で実行されるSQL文は、デフォルトでこのリソースグループに対応するCPUとIOPSのリソースを使用します。この変数の優先順位はSQLレベル（カラムマッピング）のリソース分離とユーザーレベルのリソース分離よりも高く、`RESOURCE_GROUP`ヒントよりも低いです。

この変数は主に、SQLがサードパーティによって生成され、個別に`RESOURCE_GROUP`ヒントを追加するのが不便な場合に使用されます。アプリケーションが接続初期化段階で一度`ob_resource_group`を設定すると、その接続で後に実行されるSQLは、デフォルトで指定されたリソースグループに従ってスケジュールされます。

## 権限要件

* 変数の確認

  * `sys`テナントとすべてのユーザーテナントは`SHOW VARIABLES`ステートメント、または`SYS.TENANT_VIRTUAL_SESSION_VARIABLE`ビュー（Oracleモード）および`information_schema.SESSION_VARIABLES`ビュー（MySQLモード）を使用して、セッションのシステム変数の値を確認できます。

* 変数の変更

  * `sys`テナントとすべてのユーザーテナントは、自身のテナント内のセッションシステム変数の値を直接変更できます。

## プロパティの説明

| **プロパティ** | **説明** |
|---------|---------|
| パラメータタイプ | varchar |
| デフォルト値 | 空文字列。セッションレベルのデフォルトリソースグループが指定されていないことを表します。 |
| 値の範囲 | 空文字列、または現在のテナント内に既に存在するリソースグループ名 |
| 適用範囲 | セッション |
| 変更は可能か | はい。`SET`ステートメント（MySQLモード）または`ALTER SESSION SET`ステートメント（Oracleモード）を使用して変更できます。 |

## 使用方法

* この変数はセッションレベルでのみサポートされ、グローバルレベルはサポートされていません。つまり、現在の接続にのみ有効であり、他の接続には影響しません。また、`SET GLOBAL`や`ALTER SYSTEM`による設定もサポートされていません。

* 設定時、OceanBaseデータベースはリソースグループ名が有効かどうか、およびそのリソースグループが現在のテナント内に存在するかどうかを検証します。リソースグループが存在しない場合、エラーが返され、この変数は元の値のまま維持されます。MySQLモードでは`ERROR 4710 (HY000): consumer group <リソースグループ名> does not exist`が返され、Oracleモードでは`OBE-29368: consumer group <リソースグループ名> does not exist`が返されます。

* この変数は、現在のテナントがリソース計画を通じてリソース分離を有効にしていることを前提としています。テナントにリソース計画が設定されていない場合、すべてのリソースグループは無効となります。この場合、デフォルトのリソースグループ`OTHER_GROUPS`を指定しても、リソースグループが存在しないためエラーが発生します。

* 変数を空文字列に設定すると、セッションレベルのデフォルトリソースグループがクリアされ、そのセッションにおける後続のSQLステートメントは、SQLレベルまたはユーザーレベルのリソース分離ルールによって決定されるリソースグループに従います。

* この変数の変更は即時に反映され、実行計画キャッシュのエビクションは不要です。キャッシュされている実行計画も、次回の実行時には新しいリソースグループに従ってスケジューリングされます。

* 1つのSQLステートメントがリソースグループとマッチする場合、以下の順序で高い優先順位から順次判定し、マッチしたルールで処理を終了します：`RESOURCE_GROUP` ヒント > セッションシステム変数 `ob_resource_group` > SQLレベル（Columnマッピング）リソース分離 > ユーザーレベルリソース分離 > デフォルトリソースグループ `OTHER_GROUPS`。Functionレベルのリソース分離はバックグラウンドタスクに適用され、SQLステートメントのリソースグループマッチングには関与しません。

* 接続プールを使用する場合、物理接続の初期化時または貸し出し時にこの変数を設定し、接続が他の業務で再利用される前に再度設定またはクリアすることを推奨します。そうでない場合、接続が再利用された後、後続のリクエストが前の業務で設定されたリソースグループを使用してしまい、リクエストが意図しないリソースグループに割り当てられる可能性があります。

## 設定例

* MySQLモード

  * 現在のセッションにリソースグループ `batch_group` を指定します。

    ```shell
    obclient> SET SESSION ob_resource_group = 'batch_group';
    ```

  * 現在のセッションの値を確認します。

    ```shell
    obclient> SELECT @@session.ob_resource_group;
    ```

  * セッションレベルのデフォルトリソースグループをクリアします。

    ```shell
    obclient> SET SESSION ob_resource_group = '';
    ```

* Oracleモード

  * 現在のセッションにリソースグループ `batch_group` を指定します。

    ```shell
    obclient> ALTER SESSION SET ob_resource_group = 'batch_group';
    ```

  * セッションレベルのデフォルトリソースグループをクリアします。Oracleモードでは、空文字列は `NULL` と同等であり、以下の2つの書き方は同じ効果があります。

    ```shell
    obclient> ALTER SESSION SET ob_resource_group = '';
    obclient> ALTER SESSION SET ob_resource_group = NULL;
    ```

* セッションビューでセッションレベルのデフォルトリソースグループを確認します。ここで、`RESOURCE_GROUP` 列は、そのセッションで設定されたリソースグループ名を反映するだけであり、設定されていない場合、MySQLモードでは空文字列、Oracleモードでは `NULL` となります。これはヒントやリソース分離ルールとマッチした後に最終的に有効になるリソースグループではありません。

  * MySQLモード

    ```shell
    obclient> SELECT id, user, resource_group
        -> FROM oceanbase.GV$OB_PROCESSLIST
        -> WHERE id = CONNECTION_ID();
    ```

  * Oracleモード

    ```shell
    obclient> SELECT id, resource_group
        -> FROM SYS.GV$OB_PROCESSLIST
        -> WHERE id = SYS_CONTEXT('USERENV', 'SID');
    ```
