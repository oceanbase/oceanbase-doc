# max_syslog_file_count

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>この構成パラメータは、V1.4バージョンから導入されました。</p>
</main>

## 機能の概要

`max_syslog_file_count`は、ログファイルを回収する前に保持できるログファイル数を設定します。

<main id="notice" type='explain'>
 <h4>説明</h4>
 <ul><li>この構成パラメータは、圧縮されていないログファイルの数のみを制御します。</li><li>各ログファイルは最大256MBのディスク容量を使用できます。</li></ul>
</main>

## 権限要件

* パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこのパラメータを確認できます。

* パラメータの変更

  この構成パラメータは`sys`テナントのみが変更でき、ユーザーテナントでは変更できません。

## プロパティの説明

| **プロパティ**  |  **説明**  |
|-----------|----------|
| パラメータタイプ   | INT       |
| デフォルト値     | 0、ログファイルを削除しないことを示します。        |
| 変更は可能か | はい。`ALTER SYSTEM SET` ステートメントを使用して変更できます。|
| OBServerノードの再起動が必要か | 不要です。設定は即時に反映されます。  |

## 使用方法

* すべてのタイプのログファイルの合計数の上限は`max_syslog_file_count`であり、FIFO（First In First Out）ポリシーに基づいてログファイルの廃棄が行われます。FIFOポリシーでは、ログの最後の変更時間を基準に優先順位を決定します。例えば、ログファイル`xxxxxxxx.log.20231123223441234`の末尾の時間をもとにソートして順序を決めます。

* ファイル数の保持ルールとは、次のようなものです：すべてのローリング後の`xxxxxx.log.xxxxx`ファイルの総数の上限は`max_syslog_file_count`の値であり、すべてのローリング後の`xxxxxx.log.wf.xxxxx`ファイルの総数の上限も`max_syslog_file_count`の値です。**ただし、現在書き込み中のアクティブなログファイル（例えばobserver.logやrootservice.log）およびそれに対応するWFファイルは、この数の制限の統計に含まれません。**

* Traceログが高速に生成され、その数が多すぎる場合、OBServerのログファイルの容量を占有し、OBServerのログが早期に廃棄される可能性があります。このような状況に直面した場合は、フルトレースのレベルを調整して適切なログ量を決定することを推奨します。Traceログのレベルの詳細については、[フルトレース方法](../../../../600.manage/900.daily-inspection/900.full-link-detection/300.full-link-diagnosis.md)を参照してください。

* パラメータ`max_syslog_file_count`とパラメータ[syslog_disk_size](22500.syslog_disk_size.md)との関係：

  1. `max_syslog_file_count=0`, `syslog_disk_size=0`：ディスクが満杯になるまでログを回収しません。
  2. `max_syslog_file_count=0`, `syslog_disk_size>0`：ログの総サイズが`syslog_disk_size`に近づくと、最も古いログファイルを削除して容量を回収し始めます。
  3. `max_syslog_file_count>0`, `syslog_disk_size=0`：特定のログファイルの数が`max_syslog_file_count`を超えた場合、最も古いログファイルを削除して容量を回収し始めます。
  4. `max_syslog_file_count>0`, `syslog_disk_size>0`：特定のログファイルの数が`max_syslog_file_count`を超えた場合、またはログの総サイズが`syslog_disk_size`に近づいた場合、最も古い圧縮ファイルを削除して容量を回収し始めます。

## 設定例

ログファイルを回収する前に保持できるログファイル数を20に設定します。

```shell
obclient> ALTER SYSTEM SET max_syslog_file_count=20;
```
