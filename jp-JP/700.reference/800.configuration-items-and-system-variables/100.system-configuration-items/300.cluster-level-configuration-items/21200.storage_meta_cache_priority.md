# storage_meta_cache_priority

<main id="notice" type='explain'>
<h4>説明</h4>
<p>この構成パラメータは、V4.2.0バージョンから導入されました。</p>
</main>

## 機能の概要

`storage_meta_cache_priority`は、kvcache内でストレージMetaキャッシュの優先順位を制御します。

## 権限要件

* パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこのパラメータを確認できます。

* パラメータの変更

  この構成パラメータは`sys`テナントのみが変更でき、ユーザーテナントでは変更できません。

## プロパティの説明

| **プロパティ** | **説明**    |
|-----------|------------|
| パラメータタイプ             | Int |
| デフォルト値               | 10 |
| 値の範囲             | [1,+∞) |
| 変更は可能か           | はい。`ALTER SYSTEM SET`ステートメントを使用して変更できます。|
| OBServerノードの再起動が必要か | 不要です。設定は即時に反映されます。 |

## 使用方法

OceanBaseデータベースは、Table StoreやSSTableなどのメタデータをストレージMetaとして統一的に抽象化し、kvcacheメモリ内で一元的に管理します。Metaキャッシュの利用率が低い場合や頻繁にミスが発生する場合、ユーザーは負荷の特性に応じてその優先順位を変更することで、限られたkvcacheメモリリソースをより効率的かつ柔軟に活用できます。

kvcache内では、キャッシュの優先順位数値が大きいほど優先順位が高く、占有するメモリが削除されにくくなります。既存のキャッシュタイプの優先順位構成パラメータは以下のとおりです：

* [tablet_ls_cache_priority](22700.tablet_ls_cache_priority.md)、デフォルト値は1000、値の範囲は[1,+∞)です。

* [opt_tab_stat_cache_priority](16800.opt_tab_stat_cache_priority.md)、デフォルト値は1、値の範囲は[1,+∞)です。

* [index_block_cache_priority](10600.index_block_cache_priority.md)。デフォルト値は10で、取り得る範囲は[1,+∞)です。

* [user_block_cache_priority](24500.user_block_cache_priority.md)。デフォルト値は1で、取り得る範囲は[1,+∞)です。

* [user_row_cache_priority](24700.user_row_cache_priority.md)。デフォルト値は1で、取り得る範囲は[1,+∞)です。

* [bf_cache_priority](2500.bf_cache_priority.md)。デフォルト値は1で、取り得る範囲は[1,+∞)です。

* [fuse_row_cache_priority](9600.fuse_row_cache_priority.md)。デフォルト値は1で、取り得る範囲は[1,+∞)です。

メモリ内Metaキャッシュの優先順位のデフォルト値は`index_block_cache_priority`と同じであり、`tablet_ls_cache_priority`に次いで低いことに注意してください。

## 設定例

kvcache内のストレージMetaキャッシュの優先順位を10に設定します。

```shell
obclient> ALTER SYSTEM SET storage_meta_cache_priority='10';
```
