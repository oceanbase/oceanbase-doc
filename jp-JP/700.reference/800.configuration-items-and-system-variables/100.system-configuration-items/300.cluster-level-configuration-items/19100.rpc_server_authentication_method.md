# rpc_server_authentication_method

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>この構成パラメータは、V3.2.4バージョンから導入されました。</p>
</main>

## 機能の概要

`rpc_server_authentication_method`は、RPCサーバー側のセキュリティ認証方式を設定します。

`sys`テナントは、クライアントとサーバー側でそれぞれコマンドを実行することで、認証方式を設定できます。

## 権限要件

* パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこのパラメータを確認できます。

* パラメータの変更

  この構成パラメータは`sys`テナントのみが変更でき、ユーザーテナントでは変更できません。

## プロパティの説明

| **プロパティ** | **説明** |
| ------ | ------ |
| パラメータタイプ             | String |
| デフォルト値               | ALL |
| 値の範囲             |<ul> <li> NONE：認証を行わないことを示します。セキュリティ要件が高いシナリオでは、サーバー側で`NONE`を無効にすることを推奨します。</li> <li>ALL：サーバー側のデフォルト認証方式で、任意の認証方式(NONE、SSL_NO_ENCRYPT)をサポートします。</li> <li>SSL_NO_ENCRYPT：ローカルのSSL証書と秘密鍵に基づき、SSLハンドシェイクによって認証を完了しますが、その後の通信は暗号化されません。</li></ul>|
| 変更は可能か           | はい。`ALTER SYSTEM SET`ステートメントを使用して変更できます。|
| OBServerの再起動が必要か | 不要です。設定は即時に反映されます。 |

## 使用方法

1. クライアント側では`rpc_client_authentication_method`パラメータを設定する必要があります。詳細および設定方法については[rpc_client_authentication_method](../300.cluster-level-configuration-items/18900.rpc_client_authentication_method.md)を参照してください。

2. サーバー側では、複数の認証方式を同時に設定できます。一度に複数の認証方式を設定する場合は、英字のカンマで区切ります。この構成パラメータは大文字と小文字を区別しません。

   ```sql
   ALTER SYSTEM SET rpc_server_authentication_method = 'NONE, SSL_NO_ENCRYPT';
   ```

3. すべてのパラメータ値が正しく設定されている場合は、最新の設定が優先されます。そうでない場合は、元の認証方式が維持され、この設定は有効になりません。
   例えば、元の認証方式が `NONE` の場合、現在 `alter system set rpc_server_authentication_method = 'SSL_NO_ENCRYPT, ANY';` と設定しても（ただし、値の範囲に `ANY` 値は含まれていないため）、この設定は有効にならず、サーバー側の認証方式は引き続き `NONE` のままです。

4. サーバー側の構成パラメータ値に応じて、許可されるクライアントタイプは以下のとおりです：

   |サーバー側構成パラメータ値|許可されるクライアントタイプ|
   |-------------|----------------- |
   |NONE         |<ul> <li>アップグレードしていない古いクライアント（認証されていないクライアントを含む）</li> <li>認証方式が `NONE` の新しいクライアント</li></ul>|
   |SSL_NO_ENCRYPT|認証方式が `SSL_NO_ENCRYPT` の新しいクライアント|
   |ALL           |上記2つのケースの合計|

## 設定例

RPCサーバー側のセキュリティ認証方式をALLに設定します。

```shell
obclient> ALTER SYSTEM SET rpc_server_authentication_method = 'ALL';
```
