# arbitration_degradation_policy

<main id="notice" type='explain'>
<h4>説明</h4>
<p>この構成パラメータは、V4.3.4バージョンから導入されました。</p>
</main>

## 機能の概要

`arbitration_degradation_policy`は、自動デグレードのポリシーを設定します。

## 権限要件

* パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこのパラメータを確認できます。

* パラメータの変更

  この構成パラメータは`sys`テナントのみが変更でき、ユーザーテナントでは変更できません。

## プロパティの説明

|        プロパティ                  |     説明      |
|------------------------------|-------------|
| パラメータタイプ                      | String        |
| デフォルト値                        | LS_POLICY       |
| 値の範囲                      | <ul><li>`LS_POLICY`：障害が発生したログストリームレプリカをデグレードします。</li> <li>`CLUSTER_POLICY`：障害が発生したログストリームレプリカをデグレードする前に、ログストリームのリーダーが自身とRSとのネットワーク接続状況を確認します。接続できない場合は、デグレードを実行せず、リーダーの職務も解除しません。</li></ul> |
| 変更は可能か                    | はい。`ALTER SYSTEM SET`ステートメントを使用して変更できます。         |
| OBServerノードの再起動が必要か    | 不要です。設定は即時に反映されます。     |

## 使用方法

構成パラメータの値が`CLUSTER_POLICY`の場合、ログストリームのリーダーはアービトレーションによるデグレードを実行する前に、自身がRSとネットワーク接続されているかどうかをチェックします。RSとの接続が確立できない場合、アービトレーションによるデグレードを実行せず、リーダーの職を辞し、最終的にRSとネットワーク接続されているレプリカにリーダーが切り替わるようにします。職を辞したレプリカは、以後リーダーに選出されることは許可されません。また、定期的にRSとのネットワーク接続状況をチェックし、RSとのネットワーク接続が回復した場合にのみ、そのレプリカがリーダーに選出されることを許可します。

## 設定例

ログストリームのアービトレーションによるデグレードポリシーを`CLUSTER_POLICY`に設定します。

```shell
obclient> ALTER SYSTEM SET arbitration_degradation_policy = 'CLUSTER_POLICY';
```
