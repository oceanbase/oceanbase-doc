# log_storage_warning_trigger_percentage

<main id="notice" type='explain'>
<h4>説明</h4>
<p>V4.2.xの他のバージョンでは、V4.2.5バージョンから導入されました。V4.2.1バージョンでは、V4.2.1 BP7バージョンから導入されました。</p>
</main>

## 機能の概要

`log_storage_warning_trigger_percentage`は、ログディスク障害をトリガーする書き込みパフォーマンスの割合しきい値を設定します。

## 権限要件

* パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこのパラメータを確認できます。

* パラメータの変更

  この構成パラメータは`sys`テナントのみが変更でき、ユーザーテナントは変更できません。

## プロパティの説明

|      **プロパティ**      |  **説明**  |
|------------------  |----------|
| パラメータタイプ            | Int       |
| デフォルト値              | 0        |
| 値の範囲            | [0, 50]、推奨値は10未満です。|
| 変更は可能か          | はい。`ALTER SYSTEM SET` ステートメントを使用して変更できます。|
| OBServerノードの再起動が必要か | 不要です。設定は即時に反映されます。       |

## 使用方法

* ログディスク障害検出アルゴリズムは、ログディスクへの書き込みパフォーマンスのベースラインデータを継続的に収集し、現在のログディスク書き込みパフォーマンスを監視してベースラインパフォーマンスと比較します。現在の書き込みパフォーマンスがベースラインパフォーマンスに比べて大幅に低下し、一定時間正常に回復しない場合、ログディスク障害としてマークされます。
* パラメータ`log_storage_warning_trigger_percentage`とパラメータ[log_storage_warning_tolerance_time](13100.log_storage_warning_tolerance_time.md)の関係：

  * `log_storage_warning_trigger_percentage`の値が0の場合、パフォーマンスデータは検出されず、元のロジックに従って、ログディスクへの書き込み遅延がパラメータ`log_storage_warning_tolerance_time`の値を超える場合、ログディスク障害と見なされます。
  * `log_storage_warning_trigger_percentage`の値が0より大きい場合、現在のログディスクの書き込みパフォーマンスがベースラインパフォーマンスの`log_storage_warning_trigger_percentage`%未満に低下し、かつパフォーマンスの低下が`log_storage_warning_tolerance_time`秒間続く場合、ログディスク障害と見なされます。
  * `log_storage_warning_trigger_percentage`は、ログディスク障害をトリガーする書き込みパフォーマンスの割合しきい値を制御します。値が大きいほど、障害検出アルゴリズムは敏感になります。`log_storage_warning_tolerance_time`は、パフォーマンス低下の持続時間を制御します。この構成パラメータは検出アルゴリズムの堅牢性を制御し、値が大きいほど、検出アルゴリズムは堅牢になります。

## 設定例

ログディスク障害検出アルゴリズムの書き込みパフォーマンスの割合しきい値を5に、パフォーマンス低下の持続時間しきい値を3秒に設定します。つまり、ログディスクの書き込みパフォーマンスがベースラインパフォーマンスの5%未満に低下し、かつ持続時間が3秒の場合、ログディスク障害と見なされます。

```shell
obclient> ALTER SYSTEM SET log_storage_warning_trigger_percentage = 5;
obclient> ALTER SYSTEM SET log_storage_warning_tolerance_time = '3s';
```
