# rpc_server_authentication_method

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>この構成パラメータは、V3.2.4バージョンから導入されました。</p>
</main>

## 機能の概要

`rpc_server_authentication_method`は、RPCサーバーのセキュリティ認証方式を設定します。

`sys`テナントは、クライアントとサーバーでそれぞれ認証プランをコマンドで設定するだけで済みます。

## 権限要件

* パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこのパラメータを確認できます。

* パラメータの変更

  この構成パラメータは`sys`テナントのみが変更でき、ユーザーテナントでは変更できません。

## プロパティの説明

| **プロパティ** | **説明** |
| ------ | ------ |
| パラメータタイプ             | String |
| デフォルト値               | ALL |
| 値の範囲             |<ul> <li> NONE：認証を行わないことを示します。セキュリティ要件が高いシナリオでは、サーバー側で `NONE` を無効にすることを推奨します。</li> <li>ALL：サーバーのデフォルト認証方式であり、任意の認証方式（NONE、SSL_NO_ENCRYPT）をサポートすることを示します。</li> <li>SSL_NO_ENCRYPT：ローカルのSSL証書と秘密鍵に基づき、SSLハンドシェイクによって認証を完了しますが、その後の通信は暗号化されません。</li></ul>|
| 変更は可能か           | はい。`ALTER SYSTEM SET` ステートメントを使用して変更できます。|
| OBServerの再起動が必要か | 不要です。設定は即時に反映されます。 |

## 使用方法

1. クライアント側では`rpc_client_authentication_method`構成パラメータを設定する必要があります。詳細と設定については[rpc_client_authentication_method](../300.cluster-level-configuration-items/19200.rpc_client_authentication_method.md)を参照してください。
2. サーバー側では、複数の認証方式を同時に設定できます。一度に複数の認証方式を設定する場合、認証方式の間は英字のカンマで区切ります。この構成パラメータは大文字と小文字を区別しません。

   ```sql
   ALTER SYSTEM SET rpc_server_authentication_method = 'NONE, SSL_NO_ENCRYPT';
   ```

3. パラメータの値がすべて正しく設定されている場合は、最新の設定が優先されます。そうでない場合は、元の認証方式が維持され、今回の設定は無効となります。
   例えば、元の認証方式が`NONE`で、現在`alter system set rpc_server_authentication_method = 'SSL_NO_ENCRYPT, ANY';`（ただし、値の範囲に`ANY`値がないため）と設定した場合、今回の設定は無効となり、サーバーの認証方式は引き続き`NONE`となります。
4. サーバーの構成パラメータ値によって、許可されるクライアントタイプは以下のとおりです：

   |サーバー構成パラメータ値|許可されるクライアントタイプ|
   |-------------|----------------- |
   |NONE         |<ul> <li>アップグレードされていない古いクライアント（認証されていないクライアントを含む）</li> <li>認証方式が`NONE`の新しいクライアント</li></ul>|
   |SSL_NO_ENCRYPT|認証方式が`SSL_NO_ENCRYPT`の新しいクライアント|
   |ALL           |上記2つのケースの合計|

## 設定例

RPCサーバーのセキュリティ認証方式をALLに設定します。

```shell
obclient> ALTER SYSTEM SET rpc_server_authentication_method = 'ALL';
```
