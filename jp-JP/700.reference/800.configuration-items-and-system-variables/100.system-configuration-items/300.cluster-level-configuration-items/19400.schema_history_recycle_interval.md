# schema_history_recycle_interval

<main id="notice" type='explain'>
<h4>説明</h4>
<ul><li>内部の改良と最適化に伴い、V4.4.2バージョンでは、この構成パラメータはV4.4.2 BP1バージョンから削除され、使用されなくなりました。今後のSchema複数バージョン履歴データの回収は、スケジュールタスク<code>SCHEDULED_RECYCLE_SCHEMA_HISTORY</code>によって制御され、その回収タスクのスケジューリング間隔は<code>DBMS_SCHEDULER</code>の<code>SET ATTRIBUTE</code>サブプログラムを使用して変更できます。</li>
<li>この構成パラメータはV1.4バージョンから導入されました。</li></ul>
</main>

## 機能の概要

`schema_history_recycle_interval`は、システム内部で`schema`複数バージョンレコード回収タスクを実行する時間間隔を設定します。

## 権限要件

* パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこのパラメータを確認できます。

* パラメータの変更

  この構成パラメータは`sys`テナントのみが変更でき、ユーザーテナントでは変更できません。

## プロパティの説明

|      **プロパティ**      |  **説明**   |
|------------------|-----------|
| パラメータタイプ             | Time      |
| デフォルト値               | 10m、10分を意味します       |
| 値の範囲             | [0s, +∞)<main id="notice" type='explain'><h4>説明</h4><ul><li>値が0の場合、<code>schema</code>複数バージョンレコード回収タスク機能を無効にすることを意味します。</li> <li>値が0以外の場合、<code>schema</code>複数バージョンレコード回収タスクを実行する時間間隔を意味します。</li></ul></main> |
| 変更は可能か           | はい。<code>ALTER SYSTEM SET</code>ステートメントを使用して変更できます。|
| OBServerノードの再起動が必要か | 不要です。設定は即時に反映されます。      |

## 設定例

システム内部で`schema`複数バージョンレコード回収タスクを実行する時間間隔を10分に設定します。

```shell
obclient> ALTER SYSTEM SET schema_history_recycle_interval = '10m';
```
