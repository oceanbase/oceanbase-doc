# arbitration_degradation_policy

<main id="notice" type='explain'>
<h4>説明</h4>
<ul><li>V4.3.x系では、この構成パラメータはV4.3.4バージョンから導入されました。</li>
<li>V4.2.5系では、この構成パラメータはV4.2.5 BP1バージョンから導入されました。</li>
<li>V4.2.1系では、この構成パラメータはV4.2.1 BP8バージョンから導入されました。</li>
</ul>
</main>

## 機能の概要

`arbitration_degradation_policy`は、自動降格ポリシーを設定します。

## 権限要件

* パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこのパラメータを確認できます。

* パラメータの変更

  この構成パラメータは`sys`テナントのみが変更でき、ユーザーテナントは変更できません。

## プロパティの説明

|        プロパティ                  |     説明      |
|------------------------------|-------------|
| パラメータタイプ                      | String        |
| デフォルト値                        | LS_POLICY       |
| 値の範囲                      | <ul><li>`LS_POLICY`：障害が発生したログストリームレプリカをダウングレードします。</li> <li>`CLUSTER_POLICY`：障害が発生したログストリームレプリカをダウングレードする前に、ログストリームリーダーは自身とRSとのネットワーク接続性を確認します。接続が確立されていない場合、ダウングレードは実行されず、リーダーは退任しません。</li></ul> |
| 変更は可能か                    | はい。`ALTER SYSTEM SET` ステートメントを使用して変更できます。         |
| OBServerノードの再起動が必要か    | 不要です。設定は即時に反映されます。     |

## 使用方法

この構成パラメータの値が`CLUSTER_POLICY`の場合、ログストリームリーダーはアービトレーションによる降格を実行する前に、自身とRSとのネットワーク接続を確認します。RSとの接続が確立されていないことが判明した場合、アービトレーションによる降格を実行せず、リーダーの職務を解除し、最終的にRSとネットワーク接続が確立されたレプリカにリーダーが切り替わるようにします。職務を解除されたレプリカは、以後リーダーに選出されることは許可されず、定期的にRSとのネットワーク接続を確認します。RSとのネットワーク接続が回復した場合、そのレプリカは再びリーダーに選出されることが許可されます。

## 設定例

ログストリームレプリカの自動降格ポリシーを`CLUSTER_POLICY`に設定します。

```shell
obclient> ALTER SYSTEM SET arbitration_degradation_policy = 'CLUSTER_POLICY';
```
