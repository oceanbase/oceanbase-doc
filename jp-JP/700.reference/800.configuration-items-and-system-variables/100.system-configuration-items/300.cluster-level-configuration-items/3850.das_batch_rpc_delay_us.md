# das_batch_rpc_delay_us

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>この構成パラメータは、V4.4.2 BP2バージョンから導入されました。</p>
</main>

## 機能の概要

`das_batch_rpc_delay_us`は、グローバルインデックスのテーブルへのバッチRPCチャネル(`LOOKUP_DAS_BATCH_REQ1/2`)の集約送信遅延を制御します。

## 権限要件

* パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこのパラメータを確認できます。

* パラメータの変更

  この構成パラメータは`sys`テナントのみが変更でき、ユーザーテナントでは変更できません。

## プロパティの説明

|  **プロパティ**   | **説明** |
|-------------|----------|
| パラメータタイプ    | Int |
| デフォルト値      | 100 |
| 値の範囲    | [0, 1000000] |
| 単位        | マイクロ秒(us)|
| 変更は可能か  | はい。`ALTER SYSTEM SET`ステートメントを使用して変更できます。|
| OBServerノードの再起動が必要か | 不要です。設定は即時に反映されます。|

## 使用方法

構成パラメータ`das_batch_rpc_delay_us`は`LOOKUP_DAS_BATCH_REQ1/2`という`batch`タイプにのみ適用され、`CLOG_BATCH_REQ`など他の`batch`チャネルの遅延には影響しません。

集約遅延が大きいほど、単一のRPCで集約できるリクエスト数は多くなりますが、個々のリクエストの待機時間も長くなります。値を0に設定すると、ほとんど集約せず、リクエストを即時に送信します。

集約遅延(`das_batch_rpc_delay_us`)の設定には、以下の制限があります：

* チャネルが有効(`_enable_das_batch_rpc = 1`)なテナントでのみ実際に使用されます。チャネルが無効(`_enable_das_batch_rpc = 0`)の場合、パラメータ`das_batch_rpc_delay_us`は無効ですが保持されます。
* `das_batch_rpc_delay_us` の上限値1000000us（1秒）は保護値であり、通常のチューニングではこの上限に近づけないようにしてください。近づけると、単一のルックアップなどの待機時間が著しく増大します。

## 設定例

* 200usに調整し、集約度を向上させます。

    ```shell
    obclient> ALTER SYSTEM SET das_batch_rpc_delay_us = 200;
    ```

* デフォルト値の100usに戻します。

    ```shell
    obclient> ALTER SYSTEM SET das_batch_rpc_delay_us = 100;
    ```
