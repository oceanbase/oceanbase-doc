# syslog_compress_func

<main id="notice" type='explain'>
  <h4>説明</h4>
  <ul><li>V4.3.x系では、この構成パラメータはV4.3.1バージョンから導入されました。</li><li>V4.2.x系では、この構成パラメータはV4.2.3バージョンから導入されました。</li></ul>
</main>

## 機能の概要

`syslog_compress_func`はシステムログの圧縮アルゴリズムを設定します。

圧縮機能が有効な場合、`observer.log`、`rootservice.log`、`election.log`、`trace.log` の4種類のタイムスタンプ付きファイルが圧縮されますが、対応する `.wf` 拡張子を持つファイルは圧縮されません。

## 権限要件

* パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこのパラメータを確認できます。

* パラメータの変更

  この構成パラメータは`sys`テナントのみが変更でき、ユーザーテナントでは変更できません。

## プロパティの説明

| **プロパティ** | **説明** |
| -------- | -------- |
| パラメータタイプ   | String |
| デフォルト値     | none、システムログファイルを圧縮しないことを表します。 |
| 値の範囲   |none, zstd_1.0, zstd_1.3.8|
| 変更は可能か | はい。`ALTER SYSTEM SET`ステートメントを使用して変更できます。|
| OBServerノードの再起動が必要か | 不要です。設定は即時に反映されます。  |

## 使用方法

* ログ圧縮アルゴリズムを設定しても、ログ圧縮は即座に開始されません。ログの量またはディスクの上限に達したときに、最も古いログファイルから圧縮が開始されます。これにより、より多くの未圧縮のログが保持され、ログの分析や問題の調査が容易になります。

* `syslog_compress_func`の値が変更された後、以降のログは変更後のアルゴリズムで圧縮されます。既に圧縮済みのログファイルは変更の必要はありません。ログファイルを削除する際は、タイムスタンプのみ比較され、ファイルの拡張子は区別されません。

* **構成パラメータ `syslog_compress_func` と構成パラメータ [syslog_file_uncompressed_count](22060.syslog_file_uncompressed_count.md)、[syslog_disk_size](22050.syslog_disk_size.md)、[max_syslog_file_count](13300.max_syslog_file_count.md) の関係：**

  * `syslog_compress_func = none`：

    1. `syslog_file_uncompressed_count` の値が無効になります。
    2. `syslog_disk_size` と `max_syslog_file_count` が共同でログファイルの上限を制御し、数とサイズの両方の制限を満たします。

  * `syslog_compress_func != none`：

    1. `max_syslog_file_count` の値が無効になります。
    2. ログ数が `syslog_file_uncompressed_count` の値を超える部分は圧縮され、全体が `syslog_disk_size` の値に近づいたときに最も古いログの削除が開始されます。

## 設定例

システムログの圧縮アルゴリズムを zstd_1.3.8 に設定します。

```shell
obclient> ALTER SYSTEM SET syslog_compress_func = 'zstd_1.3.8';
```
