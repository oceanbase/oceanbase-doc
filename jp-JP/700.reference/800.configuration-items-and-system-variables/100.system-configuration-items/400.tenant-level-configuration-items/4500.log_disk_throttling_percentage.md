# log_disk_throttling_percentage

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>この構成パラメータは、V4.2.0バージョンから導入されました。</p>
</main>

## 機能の概要

`log_disk_throttling_percentage`は、ログ書き込みスロットリングをトリガーする回収不能なログのディスク容量占有率です。

## 権限要件

* パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこのパラメータを確認できます。

* パラメータの変更

  `sys`テナントとユーザーテナントはこの構成パラメータを変更できます。

## プロパティの説明

|      **プロパティ**      |    **説明**    |
|------------------|--------------|
| パラメータタイプ             | Int |
| デフォルト値               | 60 |
| 値の範囲             | [40，100] |
| 変更は可能か           | はい。`ALTER SYSTEM SET`ステートメントを使用して変更できます。|
| OBServerノードの再起動が必要か | 不要です。設定は即時に反映されます。  |

## 使用方法

[log_disk_throttling_maximum_duration](4400.log_disk_throttling_maximum_duration.md)とlog_disk_throttling_percentageの2つの構成パラメータは、いずれもログスロットリングに影響します。

* `log_disk_throttling_percentage`の設定値が小さいほど、ログスロットリングの開始タイミングは早くなります。
* `log_disk_throttling_maximum_duration`の設定値が大きいほど、ログスロットリングが持続する時間が長くなり、スロットリングの強度も大きくなります。

書き込み負荷とダンプ速度の差が大きいシナリオでは、`log_disk_throttling_percentage`を小さくし、`log_disk_throttling_maximum_duration`を大きくすることを試すことができます。まずは`log_disk_throttling_maximum_duration`を大きくすることを推奨します。

## 設定例

ログ書き込みスロットリングをトリガーする回収不能なログのディスク容量占有率を80に設定します。

```shell
obclient> ALTER SYSTEM SET log_disk_throttling_percentage=80;
```
