# archive_lag_target

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>この構成パラメータは、V4.2.0バージョンから導入されました。</p>
</main>

## 機能の概要

`archive_lag_target`は、テナントログアーカイブの遅延時間を制御します。

## 権限要件

* パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこのパラメータを確認できます。

* パラメータの変更

  `sys`テナントとユーザーテナントはこの構成パラメータを変更できます。

## プロパティの説明

|      **プロパティ**    |   **説明**   |
|------------------|--------------|
| パラメータタイプ             | Time |
| デフォルト値               | 120s |
| 値の範囲             | [0ms, 7200s] |
| 変更は可能か           | はい。`ALTER SYSTEM SET` ステートメントを使用して変更できます。|
| OBServerノードの再起動が必要か | 不要です。設定は即時に反映されます。      |

## 使用方法

* ログアーカイブに基づく物理スタンバイデータベースのシナリオでは、スタンバイテナントの同期要件に応じて、構成パラメータ`archive_lag_target`の値を調整できます。スタンバイテナントの遅延要件の半分に設定することができます。

* ネットワークに基づく物理スタンバイデータベースなどの他のシナリオでは、テナントの書き込み負荷とアーカイブの時宜性要件に応じて、構成パラメータ`archive_lag_target`の値を調整することを推奨します。時宜性が満たされる前提で、単一のログストリームが`archive_lag_target`で設定された期間内に、少なくとも1つの64MBサイズのログファイルを生成するようにします。

  <main id="notice" type='explain'>
  <h4>説明</h4>
  <p>アーカイブファイルはOceanBaseデータベースのログファイルと同構造であり、1つのログファイルは1つのNormal型のアーカイブファイルを完全にアップロードできます。</p>
  </main>

## 設定例

テナントログアーカイブの遅延時間を120秒に設定します。

```shell
obclient> ALTER SYSTEM SET archive_lag_target ='120s';
```
