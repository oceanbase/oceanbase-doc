# zone_deploy_mode

<main id="notice" type='explain'>
<h4>説明</h4>
<p>V4.2.5バージョンでは、この構成パラメータはV4.2.5 BP5バージョンから導入されました。</p>
</main>

## 機能の概要

`zone_deploy_mode`は、テナント内の各ゾーンにおけるユニットの配置モードを設定します。

## 権限要件

* パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこのパラメータを確認できます。

* パラメータの変更

  `sys`テナントとユーザーテナントはこの構成パラメータを変更できます。

## プロパティの説明

| プロパティ                | 説明      |
|---------------------|-----------|
| パラメータタイプ             | String |
| デフォルト値               | homo |
| 値の範囲             |<ul><li>`homo`：同構成ゾーンモード </li><li>`hetero`：異構成ゾーンモード</li></ul>|
| 変更は可能か           | はい。`ALTER SYSTEM SET` ステートメントを使用して変更できます。|
| OBServerノードの再起動が必要か | 不要です。設定は即時に反映されます。 |

## 使用方法

新規作成されたテナントやアップグレードされた既存のテナントは、デフォルトで同一構成ゾーンモードになります。同一構成ゾーンモードでは、各ゾーンのユニット数が同一でなければならず、ログストリームは各ゾーンに対称的に分散され、ログストリームはユニットグループにバインドされます。

* 1つのユニットグループは各ゾーンの1つのユニットで構成され、各ユニットは1つのユニットグループにのみ属します。

* 1つのログストリームは1つのユニットグループにのみ属し、各ログストリームのレプリカはそのユニットグループ内の各ユニットに分散されます。

* ユニットのスケーリングはユニットグループ単位でのみ可能であり、各ゾーンのUNIT_NUMは同期して調整し、一貫性を保つ必要があります。

異種ゾーンモードを有効にするには、構成パラメータ`zone_deploy_mode`の値を`hetero`に変更する必要があります。変更後、構成パラメータ`zone_deploy_mode`の値を`homo`に変更することはできません。

同一構成ゾーンモードと比較して、異種ゾーンモードの主な使用上の違いは以下の通りです。

* ログストリームの分散にはもはやユニットグループという概念がなく、各ゾーンのログストリームレプリカは対称的なユニットに限定されなくなりました。

* テナント内の各リソースプールの`UNIT_NUM`は異なる場合がありますが、最大でも2種類の異なる`UNIT_NUM`しか許可されません。

* テナント内の特定のリソースプールの`UNIT_NUM`を個別に変更することで、リソースプール単位でのスケーリングが可能になりました。

* `ALTER RESOURCE TENANT`ステートメントを使用して`UNIT_NUM`を減らしてスケールダウンする際、`UNIT_GROUP`を指定して削除することはサポートされていません。

* ログストリーム運用コマンド`ALTER SYSTEM CREATE LS`および`ALTER SYSTEM MODIFY LS`使用時、`UNIT_GROUP`パラメータを指定することはサポートされていません。

## 設定例

テナントの各ゾーンの配置モードを異種ゾーンモードに設定します。

```shell
obclient> ALTER SYSTEM SET zone_deploy_mode = 'hetero';
```
