# log_archive_concurrency

<main id="notice" type='explain'>
<h4>説明</h4>
<p>この構成パラメータは、V4.1.0バージョン以降、テナントレベルでの適用範囲に調整されました。</p>
</main>

## 機能の概要

`log_archive_concurrency`は、ログアーカイブの並列度を設定します。

## 権限要件

* パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこのパラメータを確認できます。

* パラメータの変更

  `sys`テナントとユーザーテナントはこの構成パラメータを変更できます。

## プロパティの説明

| **プロパティ** | **説明** |
| --- | --- |
| パラメータタイプ | Int |
| デフォルト値 | 0、OceanBaseデータベースの自動適応型ログアーカイブ並列度を使用します。 <main id="notice" type='explain'><h4>説明</h4><p>この構成パラメータは、V4.2.0バージョン以降、デフォルト値が1から0に調整されました。</p></main>|
| 値の範囲 | [0，100] <main id="notice" type='explain'><h4>説明</h4><p>この構成パラメータは、V4.2.0バージョン以降、値の範囲が[1,100]から[0,100]に調整されました。</p></main>|
| 変更は可能か | はい。`ALTER SYSTEM SET`ステートメントを使用して変更できます。|
| OBServerノードの再起動が必要か | 不要です。設定は即時に反映されます。  |

## 使用方法

アーカイブワーカースレッド数は、テナントの`max_cpu`の自動適応値の計算ルールに基づき、それぞれ次のようになります：

* `テナントのMAX_CPU <= 8` の場合、`アーカイブスレッド数 = MAX_CPU`。
* `8 < テナントのMAX_CPU < 32` の場合、`アーカイブスレッド数 = max(8, MAX_CPU/2)`、つまり `MAX_CPU/2` の計算結果が8未満の場合は8を取ります。
* `テナントのMAX_CPU >= 32` の場合、`アーカイブスレッド数 = max(16, MAX_CPU/4)`、つまり `MAX_CPU/4` の計算結果が16未満の場合は16を取ります。

## 設定例

* sysテナントは、ユーザーテナントのMySQLログアーカイブの並列度を調整します。

  ```shell
  obclient> ALTER SYSTEM SET log_archive_concurrency = 5 tenant = 'mysql';
  ```

* MySQLテナントは、自身のログアーカイブの並列度を調整します。

  ```shell
  obclient> ALTER SYSTEM SET log_archive_concurrency = 5;
  ```
