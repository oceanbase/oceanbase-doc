# enable_gts_standalone

<main id="notice" type='explain'>
<h4>説明</h4>
<p>V4.2.5バージョンにおいて、この構成パラメータはV4.2.5 BP5バージョンから導入されました。</p>
</main>

## 機能の概要

`enable_gts_standalone`は、テナントのGTSサービスが専用ユニットを使用する機能を有効にするかどうかを設定します。GTS専用を有効にすると、GTSサービスのパフォーマンスと安定性が向上します。

## 権限要件

* パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこのパラメータを確認できます。

* パラメータの変更

  `sys`テナントとユーザーテナントはこの構成パラメータを変更できます。

## プロパティの説明

| プロパティ              | 説明      |
|---------------------|-----------|
| パラメータタイプ             | Bool |
| デフォルト値               | False |
| 値の範囲             |<ul><li>`True`：GTS専有モードを有効化 </li><li>`False`：GTS専有モードを無効化 </li></ul>|
| 変更は可能か           | はい。`ALTER SYSTEM SET` ステートメントを使用して変更できます。|
| OBServerノードの再起動が必要か | 不要です。設定は即時に反映されます。 |

## 使用方法

テナントのGTSサービスは、システムログストリームが配置されるユニットによって提供されます。GTSサービスとユーザーログストリームが同一ユニット上にある場合、ユーザーログストリームのアクセス負荷や運用操作の影響を受けるリスクがあります。GTSサービスがテナント全体の可用性に影響を与えないようにするため、OceanBaseデータベースではGTSサービス専用ユニットの機能を提供しています。

GTS専用機能を有効にすると、ロードバランシングは自動的に一組のユニットをシステムログストリームに割り当てます（優先順位はログストリームの運用コマンドで指定されたunit_listまたは現在のunit_list）。その後、ユーザーログストリームは自動的に他のユニットに分散されます。

GTS専用機能を有効にした場合、テナントのすべてのゾーンの`UNIT_NUM`が2以上であり、かつ構成パラメータ[enable_rebalance](2900.enable_rebalance.md)が有効な状態である必要があります。これにより、GTS専用機能が有効になります。

## 設定例

GTS専用機能を有効にします。

```shell
obclient> ALTER SYSTEM SET enable_gts_standalone = True;
```
