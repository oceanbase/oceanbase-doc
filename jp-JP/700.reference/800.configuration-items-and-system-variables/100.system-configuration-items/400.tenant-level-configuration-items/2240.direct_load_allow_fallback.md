# direct_load_allow_fallback

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>この構成パラメータは、V4.3.4バージョンから導入されました。</p>
</main>

## 機能の概要

`direct_load_allow_fallback`は、ダイレクトロードを指定したデータインポート操作で、ダイレクトロードがサポートしないシナリオに遭遇した場合、データインポート操作を通常インポート方式に戻すかどうかを制御します。

## 権限要件

* パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこのパラメータを確認できます。

* パラメータの変更

  `sys`テナントとユーザーテナントはこの構成パラメータを変更できます。

## プロパティの説明

| **プロパティ** | **説明** |
| -------- | -------- |
| パラメータタイプ  | Bool |
| デフォルト値    | True <main id="notice" type='explain'><h4>説明</h4><p>この構成パラメータはV4.3.5バージョンから、デフォルト値がFalseからTrueに調整されました。</p></main>|
| 値の範囲  |<ul><li>False：ダイレクトロードがサポートされない場合、通常のインポート方式への戻りを許可せず、データインポート操作でエラーが発生します。 </li><li>True：ダイレクトロードがサポートされない場合、通常のインポート方式への戻りを許可し、データインポート操作でエラーが発生しません。 </ li></ul> |
| 変更は可能か | はい。`ALTER SYSTEM SET`ステートメントを使用して変更できます。|
| OBServerノードの再起動が必要か | 不要です。設定は即時に反映されます。 |

## 使用方法

* データインポート方式をダイレクトロードに手動でHintを追加して制御する場合も、構成パラメータ[default_load_mode](2050.default_load_mode.md)でグローバルに設定する場合も、`direct_load_allow_fallback`の値に基づいて、ダイレクトロードがサポートしない場合の動作が判断されます。

## 設定例

ダイレクトロードがサポートしないシナリオでインポート操作を実行する際にエラーを報告せず、通常インポート方式への戻りを許可します。

```shell
obclient> ALTER SYSTEM SET direct_load_allow_fallback = True;
```
