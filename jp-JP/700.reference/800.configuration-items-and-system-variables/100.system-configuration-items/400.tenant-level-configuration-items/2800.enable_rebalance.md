# enable_rebalance

<main id="notice" type='explain'>
  <h4>説明</h4>
  <ul><li>この構成パラメータはV1.4バージョンから導入されました。</li><li>この構成パラメータはV4.2.0バージョンからクラスタレベルからテナントレベルに調整されました。</li></ul>
</main>

## 機能の概要

`enable_rebalance`は、自動ロードバランシング機能を有効にするかどうかを設定します。

異なるテナント配下の構成パラメータは、異なるロードバランシング操作を制御します：

* システムテナント配下では、テナント間でのロードバランシングを実行するかどうかを制御します。

  * false：バックグラウンドでのUnit移行操作は行いませんが、ノードが永久にオフラインになったりDELETING状態になったりした場合は、Unit移行はこの構成パラメータの制御を受けません。
  * true：Unit移行によりロードバランス状態を実現できます。

* ユーザーテナント配下では、テナント内でのロードバランシングを実行するかどうかを制御します。

  * false：テナント内でのロードバランシング操作は行われず、既に実行中のロードバランシング操作はキャンセルされます。この状態でテナントのUnit数を増減する操作を試みた場合、システムはエラーを返します。

  * true：テナント内でロードバランシング操作を実行できます。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <ul>
  <li>テナント間のロードバランシングを実現するには、システムテナント配下の<code>enable_rebalance</code>構成パラメータをTrueに設定する必要があります。この構成パラメータを無効にすると、テナント間でのロードバランシング操作が行われないことを保証できます。</li>
  <li>テナントのスケーリング操作を行うか、テナントパーティションの自動ロードバランシング機能を利用するには、テナント配下で<code>enable_rebalance</code>構成パラメータを有効にして、自動ロードバランシングとパーティション移行を実現する必要があります。逆に、この構成パラメータを無効にすると、テナント内の自動ロードバランシング操作が停止します。</li>
  </ul>
</main>

## 権限要件

* パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこのパラメータを確認できます。

* パラメータの変更

  `sys`テナントとユーザーテナントはこの構成パラメータを変更できます。

## プロパティの説明

| **プロパティ** | **説明** |
| --- | --- |
| パラメータタイプ | BOOL |
| デフォルト値 | True |
| 値の範囲 |<ul><li>  True：有効 </li><li> False：無効 </li></ul>|
| 変更は可能か  | はい。`ALTER SYSTEM SET`ステートメントを使用して変更できます。|
| OBServerノードの再起動が必要か | 不要です。設定は即時に反映されます。   |

## 設定例

* テナント間のバランシングとテナント内のバランシングをどちらも無効にします。

  ```shell
  obclient> ALTER SYSTEM SET enable_rebalance = false tenant = all_user;
  ```

* テナント間のバランシングのみを有効にします。

  ```shell
  obclient> ALTER SYSTEM SET enable_rebalance = true tenant='all_user';
  ```

* テナント間のバランシングを無効にし、テナント内のバランシングを有効にします。

  ```shell
  obclient> ALTER SYSTEM SET enable_rebalance = false tenant='all_user';
            ALTER SYSTEM SET enable_rebalance = true tenant='MYSQL';
  ```
