# schema_history_expire_time

<main id="notice" type='explain'>
<h4>説明</h4>
<ul><li>内部の改修と最適化により、V4.4.2バージョンでは、この構成パラメータはV4.4.2 BP1バージョン以降、クラスタレベルからテナントレベルに変更されました。</li>
<li>この構成パラメータはV1.4バージョンから導入されました。</li></ul>
</main>

## 機能の概要

`schema_history_expire_time`は、スキーマのマルチバージョン履歴データの保持期間を設定するために使用できます。また、遅延削除されるテナントの保持期間を設定するためにも使用できます。

## 権限要件

* パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこのパラメータを確認できます。

* パラメータの変更

  `sys`テナントとユーザーテナントはこの構成パラメータを変更できます。

## プロパティの説明

|      **プロパティ**      |  **説明**  |
|------------------|----------|
| パラメータタイプ             | Time     |
| デフォルト値               | 7d、dは日を表します<main id="notice" type='explain'><h4>説明</h4><p>この構成パラメータはV4.0.0バージョン以降、デフォルト値が30dから7dに調整されました。</p></main>    |
| 値の範囲             | [1m, 30d]<main id="notice" type='explain'><h4>説明</h4><p>この構成パラメータはV4.0.0バージョン以降、値の範囲が[1m, 365d]から[1m, 30d]に調整されました。</p></main> |
| 変更は可能か           | はい。`ALTER SYSTEM SET`ステートメントを使用して変更できます。|
| OBServerノードの再起動が必要か | 不要です。設定は即時に反映されます。      |

## 設定例

スキーマのマルチバージョン履歴データの保持期間を7日に設定します。

```shell
obclient> ALTER SYSTEM SET schema_history_expire_time = '7d';
```

この構成パラメータの値を7dに設定すると、直近7日間に生成されたスキーマのマルチバージョン履歴データが保持され、期限切れで使用されなくなったスキーマのマルチバージョン履歴データは回収されます。
