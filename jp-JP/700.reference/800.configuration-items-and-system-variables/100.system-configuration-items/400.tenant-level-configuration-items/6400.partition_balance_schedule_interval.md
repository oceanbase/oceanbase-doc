# partition_balance_schedule_interval

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>この構成パラメータは、V4.2.0バージョンから導入されました。</p>
</main>

## 機能の概要

`partition_balance_schedule_interval`は、パーティションのロードバランシングのスケジューリング間隔を設定します。

## 権限要件

* 構成パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこの構成パラメータを確認できます。

* 構成パラメータの変更

  `sys`テナントとユーザーテナントはこの構成パラメータを変更できます。

## プロパティの説明

| **プロパティ** | **説明** |
| -------- | -------- |
| パラメータタイプ       | Time |
| デフォルト値         | 0秒、バックグラウンドでのパーティションの自動ロードバランシングが無効であることを示します。  |
| 値の範囲       | [0s,+∞)    |
| 変更は可能か     |  はい。`ALTER SYSTEM SET`ステートメントを使用して変更できます。|
| OBServerノードの再起動が必要か    | 不要です。設定は即時に反映されます。     |

## 使用方法

* パーティションのロードバランシングを有効にするには、構成パラメータ`partition_balance_schedule_interval`の値が、構成パラメータ[balancer_idle_time](600.balancer_idle_time.md)の値より大きい必要があります。

* **V4.4.x系では、パーティションのロードバランシングの動作が異なります：**

  * V4.4.1より前のバージョン

    パーティションの自動ロードバランシングの間隔は、この構成パラメータによって制御されます。

  * V4.4.1以降のバージョン

    V4.4.1バージョンから、パーティションの定期ロードバランシングタスクがサポートされています。構成パラメータ`partition_balance_schedule_interval`を使用したパーティションのロードバランシングの制御は推奨されなくなりました。

      * V4.4.1バージョンで新規作成されたユーザーテナントでは、構成パラメータ`partition_balance_schedule_interval`のデフォルト値は0です。これは、バックグラウンドでのパーティションの自動ロードバランシングがデフォルトで無効であることを意味します。同時に、パーティションの定期ロードバランシングタスクはデフォルトで有効になっており、パーティションのロードバランシングのトリガーは定期タスクおよびユーザーによる手動トリガーに依存します。

      * 他のバージョンからV4.4.1バージョンにアップグレードされたユーザーテナントでは、構成パラメータ`partition_balance_schedule_interval`の値はアップグレード前と一致し、パーティションの定期ロードバランシングタスクはデフォルトで無効になっています。

## 設定例

* システムテナント内で任意のテナントのパーティションのロードバランシングのスケジューリング間隔を1時間に変更します。

  ```shell
  obclient(root@sys)[oceanbase]> ALTER SYSTEM SET partition_balance_schedule_interval = '1h' tenant = all;
  obclient(root@sys)[oceanbase]> ALTER SYSTEM SET partition_balance_schedule_interval = '1h' tenant = 'tenant_name';
  ```

* ユーザーテナント内で自身のテナントのパーティションのロードバランシングのスケジューリング間隔を1時間に変更します。

  ```shell
  obclient [test]> ALTER SYSTEM SET partition_balance_schedule_interval = '1h';
  ```
