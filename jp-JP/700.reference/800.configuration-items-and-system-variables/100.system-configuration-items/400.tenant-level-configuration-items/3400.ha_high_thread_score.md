# ha_high_thread_score

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>この構成パラメータはV4.0.0バージョンから導入されました。</p>
</main>

## 機能の概要

`ha_high_thread_score`は、高可用性関連タスクに使用する高優先度の現在のワーカースレッド数を設定します。

## 権限要件

* 構成パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこの構成パラメータを確認できます。

* 構成パラメータの変更

  `sys`テナントとユーザーテナントはこの構成パラメータを変更できます。

## プロパティの説明

| **プロパティ** | **説明** |
| --- | --- |
| パラメータタイプ | Int |
| デフォルト値 | 0、デフォルトのワーカースレッド数として8を使用することを意味します |
| 値の範囲 | [0, 100] |
| 変更は可能か | はい。`ALTER SYSTEM SET`ステートメントを使用して変更できます。|
| OBServerノードの再起動が必要か | 不要です。設定は即時に反映されます。  |

## 使用方法

V4.xバージョンでは、移行・レプリケーションやバックアップ・リカバリなど、高可用性（High Availability）に関連するタスクは、テナントレベルのDagSchedulerによってスケジュールされ実行されます。各テナントのスレッドリソースには制限があるため、具体的なタスクタイプに基づいて構成パラメータを区別するのではなく、タスクの優先度と重要度に基づいて3つの高可用性関連の構成パラメータが設定されています。各構成パラメータは異なるタスクタイプに対応します：

<main id="notice" type='notice'>
<h4>注意</h4>
<p>V4.xの各バージョンでは、構成パラメータが対応するタスクの分類が異なる場合があります。</p>
</main>

* ha_high_thread_score：レプリケーション、Rebuild、リカバリなどの高優先度・高可用性タスクキューで使用するスレッドの並列数を設定します。
* ha_mid_thread_score：移行などの中優先度・高可用性タスクキューで使用するスレッドの並列数を設定します。
* ha_low_thread_score：バックアップ、バックアップのバックアップ、バックアップのクリーンアップなどの低優先度・高可用性タスクキューで使用するスレッドの並列数を設定します。

## 設定例

このテナントの高可用性関連タスクに使用する高優先度の現在のワーカースレッド数を10に設定します。

```shell
obclient> ALTER SYSTEM SET ha_high_thread_score =10;
```
