# enable_ls_leader_balance

<main id="notice" type='explain'>
<h4>説明</h4>
<ul><li>V4.4.x系では、この構成パラメータはV4.4.2バージョンから導入されました。</li>
<li>V4.2.5系では、この構成パラメータはV4.2.5 BP6バージョンから導入されました。</li></ul>
</main>

## 機能の概要

`enable_ls_leader_balance`は、ログストリームのリーダーに対する自動ロードバランシングを有効にするかどうかを制御します。

## 権限要件

* 構成パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこの構成パラメータを確認できます。

* 構成パラメータの変更

  `sys`テナントとユーザーテナントは`ALTER SYSTEM SET`ステートメントを使用してこの構成パラメータを変更できます。

## プロパティの説明

|  **プロパティ** | **説明** |
|-----------|----------|
| パラメータタイプ   | Bool |
| デフォルト値     | True |
| 値の範囲   | <ul><li>`True`：ログストリームのリーダーに対する自動ロードバランシングを有効にする</li><li>`False`：ログストリームのリーダーに対する自動ロードバランシングを無効にする</li></ul>|
| 変更は可能か | はい。`ALTER SYSTEM SET`ステートメントを使用して変更できます。|
| OBServerノードの再起動が必要か | 不要です。設定は即時に反映されます。|

## 使用方法

* [enable_rebalance](2800.enable_rebalance.md)が有効（値は`True`）の場合、`enable_ls_leader_balance`はログストリームのリーダーに対する自動ロードバランシングを無効にするかどうかを個別に制御できます。

* この構成パラメータが無効の場合（値は`False`）、ログストリームレベルでの自動リーダー切り替えは発生しませんが、パーティションレベルではリーダーが異なるログストリーム間でTransferが行われることによりリーダー切り替えが発生する可能性があります。

## 設定例

* ユーザーテナントが自身のテナントのログストリームリーダーに対する自動ロードバランシングを無効にします。

  ```shell
  obclient> ALTER SYSTEM SET enable_ls_leader_balance = False;
  ```

* システムテナントは`mysql`テナントのログストリームリーダーの自動ロードバランシングを無効にすることを指定します。

  ```shell
  obclient> ALTER SYSTEM SET enable_ls_leader_balance = False TENANT = 'mysql';
  ```
