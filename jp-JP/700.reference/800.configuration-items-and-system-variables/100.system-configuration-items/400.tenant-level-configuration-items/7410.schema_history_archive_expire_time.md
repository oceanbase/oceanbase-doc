# schema_history_archive_expire_time

<main id="notice" type='explain'>
<h4>説明</h4>
<p>V4.4.2バージョンでは、この構成パラメータはV4.4.2 BP1バージョンから導入されました。</p>
</main>

## 機能の概要

構成パラメータ `schema_history_archive_expire_time` は、Schemaのマルチバージョン履歴アーカイブデータの保持期間を指定するために使用されます。

アーカイブテーブルの無限増大を避けるため、OceanBaseデータベースは制御可能なGC（Garbage Collection）を導入しています。回収時には、回収ポイントに対応する schema_version と保持時間を組み合わせてアーカイブGCの締め切りバージョンを計算し、アーカイブ履歴データをバッチで削除します。

## 権限要件

* パラメータの確認

  `sys`テナントとすべてのユーザーテナントは `SHOW PARAMETERS` ステートメント、または `GV$OB_PARAMETERS` ビューを使用してこのパラメータを確認できます。

* パラメータの変更

  `sys`テナントとユーザーテナントはこの構成パラメータを変更できます。

## プロパティの説明

|      **プロパティ**      |  **説明**  |
|------------------|----------|
| パラメータタイプ             | Time     |
| デフォルト値               | 0   |
| 値の範囲             | <ul><li>`0`：アーカイブ履歴データのGCを無効にすることを示します。</li> <li>`[30d, 365d]`：少なくとも指定日数のアーカイブ履歴データを保持することを示します。ビジネス上許容可能な保持時間に設定することを推奨します。</li></ul> |
| 変更は可能か           | はい。`ALTER SYSTEM SET` ステートメントを使用して変更できます。|
| OBServerノードの再起動が必要か | 不要です。設定は即時に反映されます。      |

## 設定例

* システムテナント

  * テナント `tenant1` 内のSchemaマルチバージョン履歴アーカイブデータのGCを無効にします。

    ```shell
    obclient(root@sys)[(none)]> ALTER SYSTEM SET schema_history_archive_expire_time = '0' TENANT = tenant1;
    ```

  * テナント `tenant1` 内のスキーママルチバージョン履歴アーカイブデータの保持期間を90日に設定します。

    ```shell
    obclient(root@sys)[(none)]> ALTER SYSTEM SET schema_history_archive_expire_time = '90d' TENANT = tenant1;
    ```

* ユーザーテナント

  * このテナントのスキーママルチバージョン履歴アーカイブデータのGCを無効にします。

    ```shell
    obclient> ALTER SYSTEM SET schema_history_archive_expire_time = '0';
    ```

  * このテナントのスキーママルチバージョン履歴アーカイブデータの保持期間を90日に設定します。

    ```shell
    obclient> ALTER SYSTEM SET schema_history_archive_expire_time = '90d';
    ```
