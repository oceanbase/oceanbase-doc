# choose_migration_source_policy

<main id="notice" type='explain'>
  <h4>説明</h4>
  <ul><li>V4.3.x系では、この構成パラメータはV4.3.2バージョンから導入されました。</li><li>V4.2.x系では、この構成パラメータはV4.2.1 BP7バージョンとV4.2.3バージョンから導入されました。</li></ul>
</main>

## 機能の概要

`choose_migration_source_policy`は、移行時にソース側レプリカを選択する優先ポリシーを指定します。

## 権限要件

* パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこのパラメータを確認できます。

* パラメータの変更

  `sys`テナントとユーザーテナントは`ALTER SYSTEM SET`ステートメントを使用してこの構成パラメータを変更できます。

## プロパティの説明

| **プロパティ** | **説明** |
| -------- | -------- |
| パラメータタイプ   | String |
| デフォルト値     | idc |
| 値の範囲   | <ul><li>idc：同一IDC内のマシンでは、Followerレプリカをソースとして優先的に選択します。Leaderレプリカしかない場合は、Leaderレプリカを選択します。</li><li>region：同一Region内のマシンでは、Followerレプリカをソースとして優先的に選択します。Leaderレプリカしかない場合は、Leaderレプリカを選択します。</li></ul>|
| 変更は可能か | はい。`ALTER SYSTEM SET`ステートメントを使用して変更できます。|
| OBServerノードの再起動が必要か | 不要です。設定は即時に反映されます。   |

## 使用方法

* 地域情報に基づき、移行元レプリカが配置されているサーバーと移行先サーバー間のネットワーク関係は、以下の3つのエリアに分類されます：同一IDC内、同一リージョン内の異なるIDC間、リージョンをまたいだエリア間です。

  * `choose_migration_source_policy`の値がIDCの場合。

    同一IDC内で、Followerレプリカを保持するマシンをソースとして優先的に選択します。条件を満たすFollowerレプリカが複数存在する場合は、ランダムに1つを選択します。条件を満たすFollowerレプリカが存在しない場合は、条件を満たすLeaderレプリカを選択します。それも存在しない場合は、Regionモードにフォールバックします。

  * `choose_migration_source_policy`の値がRegionの場合。

    * 同一リージョン内の異なるIDCエリア間。

      同一リージョン内で、Followerレプリカを保持するマシンをソースとして優先的に選択します。条件を満たすFollowerレプリカが複数存在する場合は、ランダムに1つを選択します。条件を満たすFollowerレプリカが存在しない場合は、条件を満たすLeaderレプリカを選択します。それも存在しない場合は、次のリージョンをまたいだエリア間での選択に進みます。

    * リージョンをまたいだエリア間。

      リージョンをまたいだエリア内で、Followerレプリカを保持するマシンをソースとして優先的に選択します。条件を満たすFollowerレプリカが複数存在する場合は、ランダムに1つを選択します。条件を満たすレプリカが存在しない場合は、エラー4600を返します。

* 同一リージョン内で、IDC間の帯域幅が同一IDC内の帯域幅よりも著しく劣る場合は、この構成パラメータの値をIDCに設定することを推奨します。両者の帯域幅の差が顕著でない場合は、この値をRegionに設定することを推奨します。

* OBServerのリージョン位置情報を正しく設定する必要があります。設定が不正確な場合、移行元機能は正常に動作しません。

## 設定例

移行元レプリカを同一IDC内のレプリカから優先的に選択するように設定します。

```shell
obclient> ALTER SYSTEM SET choose_migration_source_policy='idc';
```
