# partition_balance_schedule_interval

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>この構成パラメータは、V4.2.0バージョンから導入されました。</p>
</main>

## 機能の概要

`partition_balance_schedule_interval`は、パーティションの均衡スケジューリング間隔を設定します。

## 権限要件

* パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこのパラメータを確認できます。

* パラメータの変更

  `sys`テナントとユーザーテナントはこの構成パラメータを変更できます。

## プロパティの説明

| **プロパティ** | **説明** |
| -------- | -------- |
| パラメータタイプ       |  Time |
| デフォルト値         | 2h<main id="notice" type='explain'><h4>説明</h4><ul><li>V4.2.1バージョンでは、V4.2.1 BP9以降のバージョンで新規作成されるユーザーテナントのデフォルト値は0です。</li> <li>V4.2.xのその他のバージョンでは、V4.2.4以降のバージョンで新規作成されるユーザーテナントのデフォルト値は0です。</li></ul></main>  |
| 値の範囲       | [0s,+∞) <main id="notice" type='explain'><h4>説明</h4><p>値が0sの場合、バックグラウンドの自動パーティション再平衡を無効にすることを意味します。</p></main>   |
| 変更は可能か     |  はい。`ALTER SYSTEM SET`ステートメントを使用して変更できます。|
| OBServerノードの再起動が必要か    | 不要です。設定は即時に反映されます。     |

## 使用方法

* パラメータ`partition_balance_schedule_interval`の値が、パラメータ[balancer_idle_time](600.balancer_idle_time.md)の値より大きい場合にのみ、パーティションの均衡を有効にできます。

* **V4.2.xバージョン(V4.2.1バージョンを除く)では、パーティションの均衡動作が異なります：**

  * V4.2.4以前のバージョン

    自動パーティション均衡の間隔はこの構成パラメータによって制御されます。

  * V4.2.4以降のバージョン

    * V4.2.4バージョンから、定期的なパーティション均衡タスクがサポートされるようになり、パラメータ`partition_balance_schedule_interval`を使用したパーティションの均衡の制御は推奨されなくなりました。V4.2.4バージョンで新規作成されたユーザーテナントでは、パラメータ`partition_balance_schedule_interval`のデフォルト値は0であり、定期的なパーティション均衡タスクはデフォルトで有効になっており、パーティションの均衡のトリガーは定期的なタスクおよびユーザーによる手動トリガーに依存します。

    * 他のバージョンからV4.2.4バージョンにアップグレードされたユーザーテナントでは、パラメータ`partition_balance_schedule_interval`の値はアップグレード前と同じになり、定期的なパーティション均衡タスクはデフォルトで無効になります。

## 設定例

* ユーザーテナントでは、そのテナントの構成パラメータのみを変更します：

  ```shell
  obclient [test]> ALTER SYSTEM SET partition_balance_schedule_interval = '1h';
  ```

* システムテナントでは、任意のテナントの構成パラメータを変更できます：

  ```shell
  obclient [test]> ALTER SYSTEM SET partition_balance_schedule_interval = '1h' tenant = all;
  obclient [test]> ALTER SYSTEM SET partition_balance_schedule_interval = '1h' tenant = 'tenant_name';
  ```
