# audit_trail

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>この構成パラメータはV2.2.30バージョンから導入されました。</p>
</main>

## 機能の概要

`audit_trail`は、データベース監査を有効にするかどうかを設定します。

## 権限要件

* パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこのパラメータを確認できます。

* パラメータの変更

  `sys`テナントとユーザーテナントはこの構成パラメータを変更できます。

## プロパティの説明

| **プロパティ** | **説明** |
| -------- | -------- |
| パラメータタイプ           | String     |
| デフォルト値             | NONE        |
| 値の範囲           | <ul><li>NONE：監査を無効にします。</li><li>OS：監査レコードをローカルファイルに書き込みます。</li><li>LOG：監査レコードを監査ログに書き込みます。ログのアーカイブ、圧縮、ローテーション、クリーンアップ、暗号化などの管理戦略をサポートします。</li><li>DB：監査レコードを内部テーブルに書き込みます。</li><li>DB,EXTENDED：監査レコードを内部テーブルに書き込みます。レコードには実行されたSQL文が含まれます。</li><li>DB_EXTENDED：監査レコードを内部テーブルに書き込みます。レコードには実行されたSQL文が含まれます。</li></ul><main id="notice" type='explain'><h4>説明</h4><p><code>LOG</code>値はV4.4.2 BP2バージョンから導入されました。</p></main>   |
| 変更は可能か         | はい。`ALTER SYSTEM SET`ステートメントを使用して変更できます。|
| OBServerノードの再起動が必要か | 不要です。設定は即時に反映されます。   |

## 設定例

データベース監査を無効に設定します。

```shell
obclient> ALTER SYSTEM SET audit_trail ='NONE';
```
