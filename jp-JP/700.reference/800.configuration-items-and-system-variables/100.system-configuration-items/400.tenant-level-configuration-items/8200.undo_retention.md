# undo_retention

<main id="notice" type='explain'>
  <h4>説明</h4>
  <ul><li>この構成パラメータは、V4.0.0バージョンでシステム変数から構成パラメータに変更されました。 </li><li>この構成パラメータは、V2.1バージョンからシステム変数として導入されました。 </li></ul>
  <p></p>
</main>

## 機能の概要

`undo_retention`は、システムが保持すべきマルチバージョンデータの範囲を設定し、マイナーコンパクション時のマルチバージョンデータの回収を制御します。

## 権限要件

* 構成パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこの構成パラメータを確認できます。

* 構成パラメータの変更

  `sys`テナントとユーザーテナントはこの構成パラメータを変更できます。

## プロパティの説明

| **プロパティ** | **説明** |
| -------- | -------- |
| パラメータタイプ             | Int         |
| デフォルト値               | 1800、単位は秒       |
| 値の範囲             | [0, 4294967295]|
| 変更は可能か           | はい。`ALTER SYSTEM SET`ステートメントを使用して変更できます。|
| OBServerノードの再起動が必要か | 不要です。設定は即時に反映されます。 |

## 使用方法

OceanBaseデータベースのマイナーコンパクションでは、複数バージョンの履歴データ行が保持されます。`undo_retention`を使用して、マイナーコンパクション時に保持するマルチバージョンデータの範囲を制御できます。

具体的には：

* `undo_retention`の値が`0`の場合、複数バージョンを保持するマイナーコンパクションは無効であり、マイナーコンパクションファイルには現在の最新バージョンの行データのみが保持されます。

* `undo_retention`の値が`0`より大きい場合、複数バージョンを保持するマイナーコンパクションが有効であり、その期間（単位：秒）以内のマルチバージョン行データがマイナーコンパクションファイルに保持されます。

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>テナントで複数バージョンを保持するマイナーコンパクションが有効になっている場合、メジャーコンパクションは対応する増分マイナーコンパクションファイルを保持しますが、Major SSTableにはマルチバージョンデータは格納されません。この構成パラメータの値を大きくしすぎないようにしてください。設定値が高すぎると、保持されるSSTableの数が上限を超える可能性があります。</p>
  </main>

## 設定例

システムが保持すべきマルチバージョンデータ範囲を1800秒に設定します。

```shell
obclient> ALTER SYSTEM SET undo_retention=1800;
```
