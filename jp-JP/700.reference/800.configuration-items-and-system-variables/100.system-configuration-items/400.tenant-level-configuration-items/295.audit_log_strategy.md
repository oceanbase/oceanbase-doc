# audit_log_strategy

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>この構成パラメータは、V4.2.4バージョンから導入されました。</p>
</main>

## 機能の概要

`audit_log_strategy`は、監査レコードのファイル書き込みポリシーを制御します。

<main id="notice" >
  <h4>適用対象</h4>
  <p>この内容はOceanBaseデータベースEnterprise Editionにのみ適用されます。OceanBaseデータベースCommunity Editionは現在、監査機能をサポートしていません。</p>
</main>

## 権限要件

* パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこのパラメータを確認できます。

* パラメータの変更

  `sys`テナントとユーザーテナントは`ALTER SYSTEM SET`ステートメントを使用してこの構成パラメータを変更できます。

## プロパティの説明

| **プロパティ** | **説明** |
| -------- | -------- |
| パラメータタイプ   | String |
| デフォルト値     | ASYNCHRONOUS |
| 値の範囲   | <ul><li>ASYNCHRONOUS：非同期ログ書き込みを示します。バッファがいっぱいになると、同期待機します。</li><li>PERFORMANCE：非同期ログ書き込みを示します。バッファがいっぱいになると、データは破棄されます。</li><li>SYNCHRONOUS：同期ログ書き込みを示します。</li></ul>|
| 変更は可能か | はい。`ALTER SYSTEM SET` ステートメントを使用して変更できます。|
| OBServerノードの再起動が必要か | 不要です。設定は即時に反映されます。   |

## 使用方法

`audit_log_strategy`を使用すると、さまざまなログ書き込みポリシーを設定でき、パフォーマンスとログの整合性のバランスを実現できます。非同期書き込みを使用する場合は、[audit_log_buffer_size](210.audit_log_buffer_size.md)を使用してバッファサイズを制御できます。

## 設定例

監査レコードのファイル書き込みポリシーを非同期ログ書き込みに設定し、バッファが満杯になった場合は同期待機します。

```shell
obclient> ALTER SYSTEM SET audit_log_strategy='ASYNCHRONOUS';
```
