# log_disk_throttling_maximum_duration

<main id="notice" type='explain'>
<h4>説明</h4>
<p>この構成パラメータは、V4.2.0バージョンから導入されました。</p>
</main>

## 機能の概要

`log_disk_throttling_maximum_duration`は、ログ制限がトリガーされた後のログディスクの最大利用可能時間を調整します。

## 権限要件

* パラメータの確認

  `sys`テナントとすべてのユーザーテナントは`SHOW PARAMETERS`ステートメント、または`GV$OB_PARAMETERS`ビューを使用してこのパラメータを確認できます。

* パラメータの変更

  `sys`テナントとユーザーテナントはこの構成パラメータを変更できます。

## プロパティの説明

|      **プロパティ**      |    **説明**    |
|------------------|--------------|
| パラメータタイプ             | Time |
| デフォルト値               | 2h、2時間を表す |
| 値の範囲             | [1s、3d] |
| 変更は可能か           | はい。`ALTER SYSTEM SET` ステートメントを使用して変更できます。|
| OBServerノードの再起動が必要か | 不要です。設定は即時に反映されます。  |

## 使用方法

`log_disk_throttling_maximum_duration`と[log_disk_throttling_percentage](4700.log_disk_throttling_percentage.md)の2つの構成パラメータは、ログ制限に影響します。

* `log_disk_throttling_percentage`の値が小さいほど、ログ制限の開始タイミングは早くなります。
* `log_disk_throttling_maximum_duration`の値が大きいほど、予想されるログ制限のサポート時間は長くなり、制限の強度も大きくなります。

書き込み負荷とダンプ速度の差が大きいシナリオでは、`log_disk_throttling_percentage`を小さめに、`log_disk_throttling_maximum_duration`を大きめに設定することを試してください。`log_disk_throttling_maximum_duration`を優先的に大きくすることを推奨します。

## 設定例

テナントデータディクショナリ永続化の周期を24時間に設定します。

```shell
obclient> ALTER SYSTEM SET log_disk_throttling_maximum_duration = '24h';
```
