# MySQL外部テーブルプラグイン

本記事では、OceanBaseデータベースに外部テーブルJDBCプラグインをインストールし、使用する方法について説明します。外部テーブルJDBCプラグインを使用することで、JDBCがサポートするデータソース（現在はMySQLデータベースのデータソースへのアクセスのみをサポートしています）にアクセスできます。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p><ul><li>V4.4.1バージョンから外部テーブルJDBCプラグインサービスがサポートされています。同時に、OceanBaseデータベースはJDBCプラグインサービスに基づいてMySQL外部テーブルプラグインをリリースしました。</li><li>現在この機能は実験的な特性であり、本番環境での使用は推奨されません。</li></ul></p>
</main>

## 機能制限

* OceanBaseデータベースのOracleモード：現在、この機能はOracleモードをサポートしていません。
* データ型：`Array`型は現在サポートされていません。
* クエリ制限：

  * 並列クエリはサポートされていません。
  * 同一データソースの複数テーブルに対する`JOIN`は、単一のSQLとしてデータソースにプッシュダウンされません。
  * 集計関数や`LIMIT`などはプッシュダウンされません。

* 依存関係管理：JARパッケージは動的ロードをサポートしていないため、プロセス起動前にJARパッケージを指定ディレクトリに配置する必要があります。
* タイムアウト設定：プラグインを介したクエリタイムアウト時間の設定はできません。
* パラメータ変更：テーブル`PARAMETERS`の属性は変更できません。テーブルを再作成する必要があります。

## 前提条件

* OceanBaseデータベースのデプロイが完了し、MySQLモードのユーザーテナントが作成されていること。
* JDK（バージョン ≥ 11）がインストール済みで、`JAVA_HOME`環境変数が設定されていること。

## MySQL外部テーブルプラグインのJARパッケージパスの設定

[MySQL外部テーブルプラグインのダウンロードURL](https://github.com/oceanbase/oceanbase-plugins/releases/download/external-v1.0.0/oceanbase-external-plugin-1.0.0-jar-with-dependencies.jar)からMySQL外部テーブルプラグインのJARパッケージをダウンロードし、指定ディレクトリ（パラメータ`ob_java_connector_path`ディレクトリ内）に配置します。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>設定ディレクトリには<code>admin</code>ユーザーが必要です。つまり、OBServerサービスが読み書き権限を持っている必要があります。</p>
</main>

**例：**

1. JARパッケージを配置するためのディレクトリを作成します。

    ```shell
    mkdir -p /jdbc/plugin/jar/package/directory
    ```

2. そのディレクトリに移動します。

    ```shell
    cd /jdbc/plugin/jar/package/directory
    ```

3. MySQL外部テーブルプラグインのJARパッケージをダウンロードします。

    ```shell
    wget https://github.com/oceanbase/oceanbase-plugins/releases/download/external-v1.0.0/oceanbase-external-plugin-1.0.0-jar-with-dependencies.jar
    ```

## OceanBaseデータベースパラメータの設定（再起動後に反映）

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>JAVA SDK環境を初めて使用する場合は、observerプロセスを再起動する必要はありません。</p>
</main>

1. Javaを有効化します。

    **例：**

    ```sql
    ALTER SYSTEM SET ob_enable_java_env = true;
    ```

    詳細については、[ob_enable_java_env](../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16630.ob_enable_java_env.md)を参照してください。

2. 現在のOBServerノード上のJavaホームディレクトリを設定します。

    <main id="notice" type='explain'>
      <h4>説明</h4>
      <p>このパスはJDKのHOMEディレクトリから取得されます。<code>$JAVA_HOME</code>環境変数に設定するだけで済みます。</p>
    </main>

    **例：**

    ```sql
    ALTER SYSTEM SET ob_java_home = "/java/home/path";
    ```

    詳細については、[ob_java_home](../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16635.ob_java_home.md)を参照してください。

3. JDBCプラグインのJARファイルディレクトリを設定します。

    <main id="notice" type='explain'>
      <h4>説明</h4>
      <p>MySQL外部テーブルプラグインのJARファイルディレクトリのみを設定する必要があります。JARファイル名は不要です。ディレクトリ内のJARファイルは自動的に展開されます。</p>
    </main>

    **例：**

    ```sql
    ALTER SYSTEM SET ob_java_connector_path = "/jdbc/plugin/jar/package/directory";
    ```

    詳細については、[ob_java_connector_path](../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16640.ob-java-connector-path.md)を参照してください。

4. Java環境起動に関するパラメータを設定します。

    1. 対応するログフォルダのパスを作成します。

        ```shell
        mkdir -p /home/user/jvmlogs
        mkdir -p /home/user/jvmlogs/heapdumps
        ```

    2. Java実行時のJVM起動パラメータを設定します。

        **例：**

        ```sql
        ALTER SYSTEM SET ob_java_opts = "-Djdk.lang.processReaperUseDefaultStackSize=true -XX:+HeapDumpOnOutOfMemoryError -Xrs -Xmx2048m -Xms2048m -Xloggc:/home/user/jvmlogs/gc.log -XX:+PrintGCDetails -XX:+PrintGCDateStamps -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/home/user/jvmlogs/heapdumps/ -XX:+UseGCLogFileRotation -XX:NumberOfGCLogFiles=10 -XX:GCLogFileSize=100M -XX:+UseG1GC  -XX:-CriticalJNINatives --add-opens=java.base/java.nio=org.apache.arrow.memory.core,ALL-UNNAMED -Darrow.allocation.manager.type=Netty";
        ```

        詳細については、[ob_java_opts](../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16650.ob_java_opts.md)を参照してください。

        <main id="notice" type='notice'>
          <h4>注意</h4>
          <p><ul><li>この構成パラメータを変更するには、observerプロセスを再起動する必要があります。現在使用されているメモリコピーは、データストリームをC++メモリヒープに直接コピーする方式なので、<code>-Xmx2048m -Xms2048m</code>の設定を適宜削減できます。</li><li>関連するGCログファイルについては、対応する設定フォルダのパスが存在していればよいです。対応するパスが存在しない場合、関連するログファイルも存在しません。</li></ul></p>
        </main>

5. OceanBaseデータベースを再起動し、プラグインが正常にインストールされたか確認します。

    **例：**

    ```sql
    SELECT *
    FROM oceanbase.GV$OB_PLUGINS
    WHERE TYPE = 'EXTERNAL TABLE'
    AND STATUS = 'READY';
    ```

    実行結果は次のとおりです：

## データ型

MySQLデータベースには豊富なデータ型がありますが、OceanBaseデータベースのMySQL外部テーブルプラグインはまだ完全にはサポートしていません。現在のバージョンのOceanBaseデータベースのMySQL外部テーブルプラグインがサポートするデータ型は以下のとおりです：

* 整数型：`TINYINT`、`SMALLINT`、`MEDIUMINT`、`INT`、`BIGINT`（`UNSIGNED`を含む）
* 浮動小数点数：`FLOAT`、`DOUBLE`、`DECIMAL`
* 文字列型：`CHAR`、`VARCHAR`
* テキスト型：`TEXT`、`CLOB`
* バイナリ型：`BINARY`、`VARBINARY`、`BLOB`
* 日付時刻：`DATE`、`TIME`、`DATETIME`、`TIMESTAMP`、`YEAR`
* ブール型：`BOOLEAN`
* 空間型：`GIS`関連
* その他の型：`JSON`、`ENUM`、`SET`

## 述語のプッシュダウンルール

データアクセス効率を向上させるため、OceanBaseデータベースは一部の述語をリモートのMySQLデータベースにプッシュダウンすることをサポートしています。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>ここでいう述語とは、SQLの<code>WHERE</code>条件のことで、場所によってはpredicateやfilterとも表記されます。</p>
</main>

プッシュダウンがサポートされる述語の条件：

* データ型：整数、浮動小数点数（一部のシナリオ）、文字列（`CHAR`型を除く）
* 演算子：`=`、`!=(<>)`、`<=`、`<`、`>=`、`>`、`IS [NOT] NULL`、`[NOT] IN`、`[NOT] LIKE`、`[NOT] BETWEEN`
* 組み合わせ式：`AND`、`OR`、`NOT`

## システムのアップグレード

既存のOceanBaseクラスタでは、ノードごとに再起動する方法でプラグインをインストールまたはアップグレードできます。

推奨されるアップグレード手順は以下のとおりです：

1. 新しいバージョンのプラグインJARファイルを指定ディレクトリ（パラメータ`ob_java_connector_path`が指すディレクトリ）に配置します。
2. ノードを1つずつ再起動し、再起動時にノードのプラグインロード状況を確認します。
3. OceanBaseクラスタの再起動が完了したら、クラスタのプラグインインストール状況を確認します。

クラスタのアップグレードに関する情報については、[OceanBaseクラスタのアップグレード](../../450.oceanbase-version-upgrade/200.upgrade-oceanbase-enterprise-edition/300.start-upgrade.md)を参照してください。
