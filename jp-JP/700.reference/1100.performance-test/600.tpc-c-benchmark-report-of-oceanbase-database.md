# OceanBase TPC-C パフォーマンステストレポート

## テスト環境 (Alibaba Cloud ECS)

* 3ノードのハードウェア構成

    | サービスタイプ | ECSタイプ | インスタンス数 | マシンコア数 | メモリ |
    | --- | --- | --- | --- | --- |
    | OceanBaseデータベース | ecs.g7.8xlarge | 3 | 32C | 128G <br>各マシンのシステムディスクは300G、さらに2枚の400GクラウドディスクをclogディスクおよびDataディスクとしてマウント。パフォーマンスレベルはPL1です。|
    | ODP、Benchmark SQL | ecs.c7.16xlarge | 1 | 64C | 128G |

* 3ノードのテナント仕様

    ```sql
    CREATE RESOURCE UNIT tpcc_unit max_cpu 26, memory_size '100g'
    CREATE RESOURCE POOL tpcc_pool unit = 'tpcc_unit', unit_num = 1, zone_list=('zone1','zone2','zone3');
    CREATE TENANT tpcc_tenant resource_pool_list=('tpcc_pool'),  zone_list('zone1', 'zone2', 'zone3'), primary_zone=RANDOM, locality='F@zone1,F@zone2,F@zone3' set variables ob_compatibility_mode='mysql', ob_tcp_invited_nodes='%';
    ```

* ソフトウェアバージョン

    | サービスタイプ | ソフトウェアバージョン |
    | --- | --- |
    | OceanBaseデータベース | <ul><li>Enterprise Edition：OceanBase 4.2.2.0</li><li>Community Edition：OceanBase_CE 4.2.2.0 </li></ul> |
    | ODP | OceanBase 4.2.1 |
    | Benchmark SQL | Benchmark SQL V5.0 |
    | JDBC | mysql-connector-java-5.1.47 |
    | OS | CentOS Linux release 7.9.2009 (Core) |

## テストプラン

1. obdを使用してOceanBaseクラスタをデプロイし、ODPとTPC-Cを別々のマシンにデプロイすることで、クライアント側の負荷不足がパフォーマンスボトルネックになるのを防ぎます。

2. 3ノードのOceanBaseクラスタのデプロイ規模は1：1：1で、デプロイが成功したら、まずTPC-Cテスト用の新しいテナントとユーザーを作成します（sysテナントはクラスタを管理するための組み込みシステムテナントであり、直接sysテナントを使用してテストを行わないでください）。また、テナントの`primary_zone`をRANDOMに設定します。

3. テスト手順の詳細については、以下を参照してください：[OceanBaseデータベースTPC-Cテスト](../1100.performance-test/500.run-the-tpc-c-benchmark-on-oceanbase-database.md)。
