# OceanBaseデータベースのSysbenchテスト

本記事では、OceanBaseデータベースのOLTPパフォーマンスをSysbenchテストで測定する方法について説明します。本記事では、OceanBaseに対してSysbenchテストを実行するために2つの方法を使用します：

* obd testコマンドを使用して、ワンクリックでSysbenchテストを実行します。

* 公式Sysbenchツールを使用して、手動でステップバイステップでテストを実行します。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>ユーザー体験と使いやすさを向上させ、すべての開発者がデータベースを使用する際に良好なパフォーマンスを得られるようにするため、OceanBaseデータベースはV4.0.0以降のバージョンで多くの最適化が施されました。このパフォーマンステスト方法は、基本的なパラメータに基づいてチューニングを行い、開発者が良好なデータベースパフォーマンス体験を得られるようにします。</p>
</main>

## Sysbenchとは

SysbenchはLuaJITに基づくスクリプト可能なマルチスレッドベンチマークツールであり、CPU、メモリ、スレッド、I/O、データベースなどのパフォーマンステストを実行できます。さまざまなシステムパラメータ下でのデータベース負荷状況を評価するためによく使用され、ソースコードを変更することなく、カスタムluaスクリプトを通じて異なる業務タイプのテストを実現できます。Sysbenchには主に以下のテストが含まれます：

* CPUパフォーマンス

* ディスクI/Oパフォーマンス

* スケジューラパフォーマンス

* メモリ割り当ておよび転送速度

* POSIXスレッドパフォーマンス

* データベースパフォーマンス（OLTPベンチマーク）

## 環境準備

* JDK：JDK 1.8u131以降のバージョンを推奨します。

* make：yum install make

* automake：yum install automake

* autoconf：yum install autoconf

* libtool：yum install libtool

* gcc：yum install gcc

* mariadb-devel：yum install mariadb-devel mariadb

* JDBC：mysql-connector-java-5.1.47バージョンを推奨します。

* Sysbench：1.0以降のバージョンを推奨します。

* OBClient：詳細については、[OBClientドキュメント](https://github.com/oceanbase/obclient/blob/master/README.md)を参照してください。

   <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>使用するOBClientバージョンが2.2.0以上の場合、デフォルトでob20プロトコルとフルパス追跡機能が有効になり、Sysbenchテストのパフォーマンスに影響を与える可能性があります。環境変数を設定して手動で無効にすることを推奨します：<code>export ENABLE_PROTOCOL_OB20=0</code>。</p>
   </main>

* OceanBaseデータベース：ODPを個別にデプロイすることを推奨します。詳細については、OceanBaseのクイックスタートを参照してください。

* IOPS：ディスクIOPSは10000以上を推奨します。

* テナント仕様：

   ```sql
   CREATE RESOURCE UNIT sysbench_unit max_cpu 26, memory_size '100g';
   CREATE RESOURCE POOL sysbench_pool unit = 'sysbench_unit', unit_num = 1, zone_list=('zone1','zone2','zone3');
   CREATE TENANT sysbench_tenant resource_pool_list=('sysbench_pool'),  zone_list('zone1', 'zone2', 'zone3'), primary_zone=RANDOM, locality='F@zone1,F@zone2,F@zone3' set variables ob_compatibility_mode='mysql', ob_tcp_invited_nodes='%';
   ```

   <main id="notice" type='notice'>
   <h4>注意</h4>
   <ul>
      <li>上記のテナント仕様は、<a href="400.sysbench-benchmark-report-of-oceanbase-database.md">OceanBase Sysbench性能テストレポート</a>に記載されているハードウェア構成に基づいています。ご自身のデータベースのハードウェア構成に応じて、動的に調整する必要があります。</li>
      <li>クラスタをデプロイする際は、安定性を確保するため、リソース利用率を最大限にする（例えば、すべてのメモリを使用する）<code>obd cluster autodeploy</code>コマンドの使用は避けることを推奨します。代わりに、設定ファイルを個別にチューニングし、リソース利用率を最大限にすることを推奨します。</li>
   </ul>
   </main>

## テスト計画

1. 今回のテストでは5台のマシンを使用します。Sysbenchとobdは1台のマシンにデプロイし、ODPは別の1台のマシンに単独でデプロイします。obdを使用してOceanBaseクラスタをデプロイするには3台のマシンが必要であり、OceanBaseクラスタの規模は1:1:1です。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>Sysbenchテストでは、Sysbench、ODP、obdをデプロイするマシンに一定の柔軟性があり、OBServerの総コア数に応じて以下の3つのケースに分かれます：</p>
   <ul>
      <li>OBServerの総コア数が47コア以下の場合、そのマシンには8コア64GBで十分です。</li>
      <li>OBServerの総コア数が48コアから72コアの間の場合、そのマシンには16コア128GBが必要です。</li>
      <li>OBServerの総コア数が73コア以上の場合、そのマシンには32コア128GBが必要です。</li>
   </ul>
   </main>

2. デプロイが完了したら、まずSysbenchテスト用の新しいテナントとユーザーを作成します（sysテナントはクラスタを管理するための組み込みシステムテナントであり、直接sysテナントを使用してテストを行わないでください）。テナントの`primary_zone`をRANDOMに設定します。RANDOMとは、新しく作成されるテーブルパーティションのリーダーがこの3台のマシンにランダムに割り当てられることを意味します。

3. Sysbenchを使用して30個のテーブルをインポートします。各テーブルには100万行のデータが含まれます。

4. Sysbenchクライアントを起動し、`point_select`、`read_write`、`read_only`、`write_only`の各テストを実行します。

5. 各ラウンドのテストでは`--time`を60秒に設定し、スレッド数は`32/64/128/256/512/1024`などの値を指定できます。

  </ul>

## Sysbenchテストを手動で実行する

### テスト仕様

```shell
--mysql-db=test
--table_size=1000000
--tables=30
--threads=32/64/128/256/512/1024
--report-interval=10
--time=60
--db-ps-mode=disable
--rand-type=uniform
```

### Sysbenchのインストール

以下の手順に従ってSysbenchをインストールします。

1. Sysbenchをダウンロードします。

   詳細については、[SysbenchのダウンロードURL](https://github.com/akopytov/sysbench/releases/tag/1.0.20)を参照してください。

2. Sysbenchを解凍します。

   ```bash
   unzip ./1.0.20.zip
   ```

3. Sysbenchをコンパイルします。

   Sysbenchの解凍ディレクトリに移動し、以下のコマンドを実行してSysbenchをコンパイルします：

   ```bash
   [wieck@localhost ~] $ cd sysbench-1.0.20
   [wieck@localhost sysbench-1.0.20] $./autogen.sh
   [wieck@localhost sysbench-1.0.20] $./configure --prefix=/usr/sysbench/ --with-mysql-includes=/usr/include/mysql/ --with-mysql-libs=/usr/lib64/mysql/ --with-mysql
   [wieck@localhost sysbench-1.0.20] $make
   [wieck@localhost sysbench-1.0.20] $make install
   [wieck@localhost sysbench-1.0.20] $cp -r /usr/sysbench/share/sysbench/* /usr/sysbench/bin/
   ```

   パラメータの説明：

   | パラメータ名 | 説明 |
   | --- | --- |
   | --prefix | Sysbenchのインストールディレクトリを指定します。 |
   | --with-mysql-includes | MySQLのincludesディレクトリを指定します。 |
   | --with-mysql-libs | MySQLのlibディレクトリを指定します。 |
   | --with-mysql | SysbenchはデフォルトでMySQLをサポートしています。 |

4. 以下のコマンドを実行して、Sysbenchが正常にインストールされたかどうかを確認します：

   ```bash
   [wieck@localhost sysbench-1.0.20] $./src/sysbench --help
   ```

   次の情報が返された場合、Sysbenchのインストールは成功です。

   ```sql
   Usage:
      sysbench [options]... [testname] [command]
   Commands implemented by most tests: prepare run cleanup help
   ```

### チューニング

Sysbenchテストを実行する前に、OceanBaseデータベースを簡単に設定する必要があります。

OBServerチューニング

```sql
ALTER system SET enable_sql_audit=false;
ALTER system SET enable_perf_event=false;
ALTER system SET syslog_level='PERF';
alter system set enable_record_trace_log=false;
```

### 手順

以下の手順に従ってSysbenchテストを実行します。

1. 以下のコマンドを実行して、データベースを初期化します。

   ```bash
   /usr/sysbench/bin/sysbench oltp_read_write.lua --mysql-host=x.x.x.x --mysql-port=xxxx --mysql-db=test --mysql-user=$user@$tenant --mysql-password=xxx --table_size=1000000 --tables=30 --threads=150 --report-interval=10 --rand-type=uniform --time=60 cleanup
   ```

2. 以下のコマンドを実行して、新しいテーブルを作成します。

   ```bash
   /usr/sysbench/bin/sysbench oltp_read_write.lua --mysql-host=x.x.x.x --mysql-port=xxxx --mysql-db=test --mysql-user=$user@$tenant --mysql-password=test --table_size=1000000 --tables=30 --threads=150 --report-interval=10 --rand-type=uniform --time=60 prepare
   ```

3. 以下のコマンドを実行して、テストを実行します。

   ```bash
   /usr/sysbench/bin/sysbench oltp_read_write.lua --mysql-host=x.x.x.x --mysql-port=xxxx --mysql-db=test --mysql-user=$user@$tenant --mysql-password=xxx --table_size=1000000 --tables=30 --threads=150 --report-interval=10 --time=60 --rand-type=uniform --db-ps-mode=disable run
   ```

   パラメータの説明：

   | パラメータ名 | 説明 |
   | --- | --- |
   | --mysql-host | OceanBaseデータベースを実行するマシンのIPアドレス。ODPがある場合は、ODPのIPアドレスを使用することを推奨します。 |
   | --mysql-port | ポート番号。 |
   | --mysql-db | 接続先のデータベース。 |
   | --mysql-user | ユーザー名。 |
   | --mysql-password | パスワード。 |
   | --table_size | 各テーブルの初期化データ数。 |
   | --tables | 初期化するテーブルの数。 |
   | --threads | 起動するスレッド数。 |
   | --time | 実行時間。`0`に設定した場合、時間制限はありません。 |
   | --report-interval | 実行中のログ、単位は秒です。 |
   | --events | 最大リクエスト数。このオプションを指定すると、--timeオプションは不要になります。 |
   | --rand-type | データへのアクセス時に使用するランダム関数。値は`special`、`uniform`、`gaussian`、または`pareto`となります。デフォルト値は`special`で、以前の値は`uniform`でした。 |
   | --skip_trx=on | 読み取り専用テストでトランザクションを有効または無効にします。デフォルトでは有効です。 |
   | --percentile=N | パーセンタイルrtを出力します。デフォルト値は`95`です。 |
   | oltp_write_only | Sysbenchのluaディレクトリには、insertやpoint_selectなど、さまざまなシナリオ向けのテストケースが組み込まれています。 |

#### 説明

 テスト結果については、[OceanBase Sysbench性能テストレポート](../1100.performance-test/400.sysbench-benchmark-report-of-oceanbase-database.md)を参照してください。

## FAQ

* Sysbenchのインストールに失敗しました。エラーメッセージは次のとおりです：

   ```bash
   automake 1.10.x (aclocal) wasn't found, exiting
   ```

   オペレーティングシステムにAutomakeがインストールされていません。以下のコマンドを実行してAutomakeをインストールします：

   ```sql
   yum install automake.noarch
   ```

* Sysbenchのインストールに失敗しました。エラーメッセージは次のとおりです：

   ```bash
   libtoolize 1.4+ wasn't found, exiting
   ```

   オペレーティングシステムにLibtoolがインストールされていません。以下のコマンドを実行してLibtoolをインストールします：

   ```sql
   yum install libtool
   ```

* Sysbenchのインストールに失敗しました。エラーメッセージは次のとおりです：

   ```bash
   drv_mysql.c:35:19: fatal error: mysql.h: No such file or directory
   ```

   オペレーティングシステムにMySQLのlibライブラリがインストールされていません。以下のコマンドを実行してインストールします：

   ```sql
   yum install mysql-community-devel.x86_64
   ```

* Sysbenchのインストールに失敗しました。エラーメッセージは次のとおりです：

   ```bash
   cannot find MySQL client libraries in /usr/lib/mysql/
   ```

   以下のコマンドを実行してMySQLのlibライブラリを検索します。通常は`/usr/lib64/mysql`にあります。

   ```sql
   find /usr -name mysql
   ```

* SysbenchとOceanBaseデータベースの両方の設定が適切であるにもかかわらず、パフォーマンスは依然として低いです。

   1. SysbenchはCPU、メモリ、ネットワークに非常に敏感なテストです。クライアントと対象のテストデータベースが同一のローカルエリアネットワーク内にない場合、ネットワーク遅延がSysbenchのパフォーマンスに影響を与える可能性があります。

   2. OceanBaseデータベースクラスタがODPを使用していることに関連しています。まず、単一のOceanBaseデータベースプロセスに対して高同時実行のストレステストを実施し、その結果をODP使用時のシナリオと比較することができます。

   3. ODPとSysbenchを同一マシン上に個別にデプロイし、ODPを通じてSysbenchテストを実行することを推奨します。

* 高同時実行のストレス下でも、システムのCPU利用率は依然として低いのはなぜですか？

  全体的にCPU利用率は低いものの、一部のモジュールでは非常に高い利用率に達することがあります。
