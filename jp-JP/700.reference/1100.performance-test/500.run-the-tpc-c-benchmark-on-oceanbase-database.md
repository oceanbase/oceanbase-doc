# OceanBaseデータベースのTPC-Cテスト

## TPC-Cとは

TPC-Cは、OLTP（オンライン取引処理）システムをテストするための規格であり、商品販売モデルを用いてOLTPシステムを評価します。詳細については、[TPC-C中国語紹介](https://github.com/domino-succ/tpcc-hbase/wiki/%E4%B8%AD%E6%96%87-TPC-C%E7%AE%80%E4%BB%8B)を参照してください。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>ユーザー体験と使いやすさを向上させるため、OceanBaseデータベースはV4.0.0以降で多くの最適化が行われました。このパフォーマンステスト方法は、基本的なパラメータに基づいてチューニングを行うことで、開発者が良好なデータベースパフォーマンスを得られるように設計されています。</p>
</main>

## 環境準備

* JDK：JDK 1.8u131以降のバージョンを推奨します。

* JDBC：mysql-connector-java-5.1.47バージョンを推奨します。他のバージョンでは構文の互換性に問題が生じる可能性があります。

* Ant：apache-ant-1.10以降のバージョンを推奨します。

* Benchmark SQL：Benchmark SQL 5.0を推奨します。

* OBClient：詳細については、[OBClientドキュメント](https://github.com/oceanbase/obclient/blob/master/README.md)を参照してください。

* OceanBaseデータベース：ODPを個別にデプロイすることを推奨します。詳細については、[OceanBaseデータベースのクイックスタート](../../200.quickstart/100.quickly-experience-oceanbase-for-community.md)を参照してください。

* IOPS：ディスクIOPSは10,000以上を推奨します。

* テナント仕様：

  ```sql
  CREATE RESOURCE UNIT tpcc_unit max_cpu 26, memory_size '100g';
  CREATE RESOURCE POOL tpcc_pool unit = 'tpcc_unit', unit_num = 1, zone_list=('zone1','zone2','zone3');
  CREATE TENANT tpcc_tenant resource_pool_list=('tpcc_pool'),  zone_list('zone1', 'zone2', 'zone3'), primary_zone=RANDOM, locality='F@zone1,F@zone2,F@zone3' set variables ob_compatibility_mode='mysql', ob_tcp_invited_nodes='%';
  ```

     <main id="notice" type='notice'>
   <h4>注意</h4>
   <ul>
      <li>上記のテナント仕様は、<a href="600.tpc-c-benchmark-report-of-oceanbase-database.md">OceanBase TPC-C性能テストレポート</a>に記載されているハードウェア構成に基づいています。ご自身のデータベースのハードウェア構成に応じて動的に調整する必要があります。</li>
      <li>クラスタをデプロイする際は、<code>obd cluster autodeploy</code>コマンドの使用を避けることを推奨します。このコマンドは安定性を確保するため、リソース利用率を最大限にすることはありません（例えば、すべてのメモリを使用することはありません）。設定ファイルを個別にチューニングし、リソース利用率を最大限にすることを推奨します。</li>
   </ul>
   </main>

## テスト計画

1. 今回のテストでは4台のマシンが必要です。Benchmark SQL、ODP、obdはそれぞれ別のマシンに単独でデプロイされ、クライアント側の負荷をかけるマシンとして使用します。obdを使用してOceanBaseクラスタをデプロイするには3台のマシンが必要であり、OceanBaseクラスタの規模は1:1:1です。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>TPC-Cテストでは、Benchmark SQL、ODP、obdをデプロイするマシンには一定の柔軟性があり、OBServerの総コア数に応じて以下の3つのケースに分かれます：</p>
   <ul>
      <li>OBServerの総コア数が47コア以下の場合、そのマシンには8コア64GBで十分です。</li>
      <li>OBServerの総コア数が48コアから72コアの間の場合、そのマシンには16コア128GBが必要です。</li>
      <li>OBServerの総コア数が73コア以上の場合、そのマシンには32コア128GBが必要です。</li>
   </ul>
   </main>

2. デプロイが完了したら、TPC-Cテストを実行するための新しいテナントとユーザーを作成します（sysテナントはクラスタを管理するための組み込みシステムテナントであり、テストには直接sysテナントを使用しないでください）。テナントの`primary_zone`を`RANDOM`に設定します。`RANDOM`とは、新しく作成されるテーブルパーティションのリーダーがこの3台のマシンにランダムに配置されることを意味します。

## obdワンクリックテスト

```bash
sudo yum install -y yum-utils
sudo yum-config-manager --add-repo https://mirrors.aliyun.com/oceanbase/OceanBase.repo
sudo yum install obtpcc java
obd test tpcc obperf --tenant=tpcc_mysql --warehouses 10  --run-mins 1
```

### 注意

* obdはtpccを実行します。詳細なパラメータについては、[obd test tpcc](https://www.oceanbase.com/docs/community-obd-cn-10000000000768424)を参照してください。

* この例では、大部分のパラメータにデフォルト値が使用されています。ユーザーのシナリオでは、必要に応じてパラメータを調整できます。例えば、この例で使用されるクラスタ名は`obperf`、テナント名は`tpcc_mysql`です。

* obdを使用してワンクリックテストを実行する場合、クラスタのデプロイはobdによってインストールおよびデプロイされていなければなりません。そうでない場合、クラスタの情報を取得できず、クラスタの設定に基づく
パフォーマンスチューニングができなくなります。

* システムテナントのパスワードがターミナルログインによって変更され、デフォルトの空値ではない場合は、まずターミナルでパスワードをデフォルト値に変更し、次に[obd cluster edit-config](https://www.oceanbase.com/docs/community-obd-cn-10000000000768422)コマンドを使用して、構成ファイル内でシステムテナントにパスワードを設定する必要があります。構成パラメータは`# root_password: # root user password`です。`obd cluster edit-config`コマンドの実行が終了した後、変更を有効にするために`obd cluster reload`コマンドも実行する必要があります。

* `obd test tpcc`実行後、システムは実行手順と出力を詳細にリストアップします。データ量が多いほど、時間がかかります。

* `obd test tpcc`コマンドは、テストデータの生成、転送、OceanBaseパラメータの最適化、読み込み、テストを含むすべての操作を自動的に完了します。他の追加操作は不要です。途中でエラーが発生した場合は、[obd test tpcc](https://www.oceanbase.com/docs/community-obd-cn-10000000000768424)を参照して再試行できます。例えば、データの生成と転送をスキップして、直接読み込みとテストを実行します。

## TPC-Cテストの手動実行

### Antのインストール

次の手順に従ってAntをインストールします：

1. Antをダウンロードします。

    ```bash
    wget "http://archive.apache.org/dist/ant/binaries/apache-ant-1.10.6-bin.zip"
    ```

2. Antをインストールします。

    ```bash
    unzip apache-ant-1.10.6-bin.zip
    ```

3. 環境変数を設定します。

    ```bash
    [admin@obtest004 ~]$ sudo vim /etc/profile

    #ant
    export ANT_HOME=xx/apache-ant-1.10.6
    export PATH=xx/apache-ant-1.10.6/bin:$PATH

    [admin@obtest004 ~]$ source /etc/profile
    ```

4. インストールが成功したかどうか確認します。

    ```bash
    [admin@obtest004 ~]$ant -version
    ```

    以下のメッセージが返された場合、インストールは成功です。

    ```sql
    Apache Ant(TM) version 1.10.6 compiled on May 2 2019
    ```

### Benchmark SQLのインストール

次の手順に従ってBenchmark SQLをインストールします：

1. Benchmark SQLをダウンロードします。

    詳細については、[Benchmark SQLのダウンロードURL](https://sourceforge.net/projects/benchmarksql/files/latest/download/)を参照してください。

2. Benchmark SQLを解凍します。

    ```bash
    unzip ./benchmarksql-5.0.zip
    ```

3. Benchmark SQLをコンパイルします。

  Benchmark SQLの解凍後のディレクトリに移動し、Antを使用してBenchmark SQLをコンパイルします：

  ```bash
  [admin@obtest004 ~] $ cd benchmarksql-5.0
  [admin@obtest004 benchmarksql-5.0] $ ant
  ```

1. `benchmarksql-5.0/src/client/jTPCC.java` ファイルを修正し、OceanBaseデータベース関連の内容を追加します。

    ```java
    if (iDB.equals("firebird"))
    ```

    `benchmarksql-5.0/src/client/jTPCCConfig.java` ファイルを修正し、OceanBaseデータベースタイプを追加します。

    ```java
    public final static int

    DB_ORACLE = 2,
    ```

4. `benchmarksql-5.0/run` ディレクトリに、ファイル `prop.oceanbase` を作成します。

    ```java

    driver=com.mysql.jdbc.Driver
    conn=jdbc:mysql://$host_ip:$port/$db_name?rewriteBatchedStatements=true&allowMultiQueries=true&useLocalSessionState=true&useUnicode=true&characterEncoding=utf-8&socketTimeout=30000000

    osCollectorInterval=1
    //osCollectorSSHAddr=user@dbhost
    //osCollectorDevices=net_eth0 blk_sda
    ```

    **prop.oceanbaseのパラメータの説明：**

    * JDBC接続文字列：`conn=jdbc:mysql://x.x.x.x(ip):xx(port)/xxxx(dbname)?rewriteBatchedStatements=true&allowMultiQueries=true&useLocalSessionState=true&useUnicode=true&characterEncoding=utf-8&socketTimeout=3000000`

    * rewriteBatchedStatements：

      * パラメータは非常に重要であり、データ導入効率に深刻な影響を与えるため、無視してはなりません。

      * データのインポートが遅い場合は、該当するテナントにログインし、`show full processlist` を使用して有効になっているかどうか確認できます。

      * new orderトランザクションでもbatch updateが使用されるため、データインポートとベンチマーク段階で有効にする必要があります。

    * 同時実行数 (terminals)：600。MySQLテナント構成では、同時実行数は具体的な設定に基づいて動的に調整する必要があります。

    * useLocalSessionState：autocommit、read_only、およびtransaction isolationの内部値（JDBC側のローカル値）を使用するかどうかを示します。trueに設定することを推奨します。falseに設定した場合、リモート側にステートメントを送信する必要があり、リクエスト頻度が増加し、パフォーマンスに影響します。

    * warehouses/loadWorkersの2項目は、ストレステストデータ量を設定するために使用され、適宜調整できます。

    * numTerminals > 0 && numTerminals <= 10*numWarehousesとなり、terminalsの範囲はこの区間内である必要があります。

### チューニング

1. ODPのチューニングは、sysテナントで実行してください。

    `obclient -h$host_ip -P$host_port -uroot@sys -A` コマンドを実行してシステムテナントに入ります。

    ```sql
    ALTER PROXYCONFIG SET proxy_mem_limited='4G';

    ALTER PROXYCONFIG SET enable_compression_protocol=false;
    ```

2. observerのチューニングは、sysテナントで実行してください。

    `obclient -h$host_ip -P$host_port -uroot@sys -A` コマンドを実行してシステムテナントに入ります。

    ```sql
    ALTER SYSTEM SET enable_sql_audit=false;

    select sleep(5);

    ALTER SYSTEM SET enable_perf_event=false;

    ALTER SYSTEM SET syslog_level='PERF';

    ALTER SYSTEM SET enable_record_trace_log=false;
    ```

3. チューニングパラメータの設定が完了したら、`obd cluster restart $cluster_name` コマンドを実行してクラスタを再起動します。

### 手順

以下のコマンドはすべて、`benchmarksql-5.0/run` ディレクトリで実行します。以下の手順に従ってTPC-Cテストを実行します：

1. 以下のコマンドを実行して、環境を初期化します：

    ```bash
    ./runDatabaseDestroy.sh prop.oceanbase
    ```

2. 以下のコマンドを実行して、テーブルを作成しデータをインポートします：

    ```bash
    ./runDatabaseBuild.sh prop.oceanbase
    ```

3. マージを実行します（sysテナントからログインする必要があります）。

    Majorマージは、現在の大きなバージョンのSSTableとMemTableを前の大きなバージョンのフルスタティックデータとマージし、ストレージ層の統計情報をより正確にし、生成される実行計画をより安定させます。

    ```sql
    MySQL [(none)]> USE oceanbase
    Database changed
    MySQL [oceanbase]> ALTER SYSTEM major freeze tenant=<your tenant name>;
    Query OK, 0 rows affected
    ```

4. マージが完了したかどうかを確認します。

    ```sql
    MySQL [oceanbase]> SELECT FROZEN_SCN, LAST_SCN FROM oceanbase.CDB_OB_MAJOR_COMPACTION;
    +---------------------+---------------------+
    | FROZEN_SCN          | LAST_SCN            |
    +---------------------+---------------------+
    | 1667239201167716767 | 1667239201167716767 |
    | 1667239200111919300 | 1667239200111919300 |
    | 1667239201167452168 | 1667239201167452168 |
    | 1667239201168053124 | 1667239201168053124 |
    | 1667239201167520213 | 1667239201167520213 |
    +---------------------+---------------------+
    ```

    すべての `FROZEN_SCN` と `LAST_SCN` の値が等しい場合、マージが完了したことを示します。

5. 統計情報を手動で収集します。

    `obclient -h$host_ip -P$host_port -u$user@$tenant -p=password -A -D$database` コマンドを実行して、テストテナントに入ります。

    ```sql
    call dbms_stats.gather_schema_stats('$db_name',degree=>96);
    ```

6. 以下のコマンドを実行して、ストレステストを実行します：

    ```bash
    ./runBenchmark.sh prop.oceanbase
    ```

#### 説明

テスト結果については、[OceanBase TPC-C性能テストレポート](../1100.performance-test/600.tpc-c-benchmark-report-of-oceanbase-database.md)を参照してください。

## FAQ

* Benchmark SQLツールを停止するにはどうすればよいですか。

    自動停止：prop.oceanbaseのrunMins設定値に依存します。

    強制停止：`ps auxf | grep java --` を実行してJavaプロセスを削除し、runBenchmarkプロセスを終了します。

* mainタイプが見つからない。エラーメッセージは次のとおりです：

    ```bash
    Could not find the main class: ExecJDBC.  Program will exit.
    ```

    2つの可能性があります：JDKをアップグレードするか、JDBCバージョンをアップグレードするかのどちらかです。次のコマンドを実行してJavaをインストールします：

    ```sql
    sudo yum install jdk
    ```

* ターミナル数が無効です。エラーメッセージは次のとおりです：

    ```bash
    Invalid number of terminals!
    ```

    これはprop.oceanbaseで設定されたterminals値が正しくないためです。`numTerminals > 0 && numTerminals <= 10 * numWarehouses` の範囲内のterminals値を入力する必要があります。

* トランザクションタイムアウト。エラーメッセージは次のとおりです：

    ```bash
    transaction timeout
    ```

    タイムアウト時間を延長する必要があります。テストテナントで次のコマンドを実行します：`set global ob_query_timeout=36000000000;set global ob_trx_timeout=36000000000`。
