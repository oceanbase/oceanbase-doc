# ALTER FUNCTION

`ALTER FUNCTION` ステートメントは、独立関数を再コンパイルするために使用します。

  <main id="notice" >
    <h4>機能の適用範囲</h4>
    <p>この内容はOceanBaseデータベースEnterprise Editionにのみ適用されます。OceanBaseデータベースCommunity EditionはMySQLモードのみを提供します。</p>
  </main>

## 前提条件

関数が `SYS` スキーマにある場合は、`SYSDBA` 権限で接続する必要があります。それ以外の場合、関数は現在ユーザーのスキーマに存在するか、ユーザーは `ALTER ANY PROCEDURE` システム権限を持っている必要があります。

## 構文

`ALTER FUNCTION` の構文は次のとおりです：

```sql
ALTER FUNCTION [ schema. ] function_name
{ function_compile_clause } ;
```

ここで、`function_compile_clause` の構文は次のとおりです：

```sql
COMPILE [ DEBUG ] [ compiler_parameters_clause ... ] [ REUSE SETTINGS ]
```

## セマンティクス

|           構文            |   キーワードまたは構文ノード    |                 説明                 |
|-------------------------|---------------|------------------------------------|
| alter_function          | schema        | 関数が存在するスキーマ名。デフォルトは現在ユーザーのスキーマ。 |
| alter_function          | function_name | 再コンパイルする関数の名前。                       |
| function_compile_clause | --            | 関数を無効に関わらず再コンパイルします。                    |

## 例

以下の例では、ユーザー `sys` が所有する関数 `get_salary_by_dept` を明示的に再コンパイルします。

```sql
ALTER FUNCTION sys.get_salary_by_dept COMPILE;

```

データベースが `get_salary_by_dept` の再コンパイル時にコンパイルエラーに遭遇しない場合、`get_salary_by_dept` は有効になります。データベースはその後、実行時の再コンパイルなしに関数を実行できます。

`get_salary_by_dept` の再コンパイルでコンパイルエラーが発生した場合、データベースはエラーを返し、`get_salary_by_dept` は無効となります。データベースは `get_salary_by_dept` に依存するすべてのオブジェクトも無効にします。その後、これらのオブジェクトを明示的に再コンパイルせずに参照した場合、データベースは実行時に暗黙的に再コンパイルします。
