# カーソルプロパティ

カーソルプロパティは、関連するカーソル情報を提供します。

  <main id="notice" >
    <h4>適用対象</h4>
    <p>この内容はOceanBaseデータベースEnterprise Editionにのみ適用されます。OceanBaseデータベースCommunity EditionはMySQLモードのみを提供します。</p>
  </main>

カーソルプロパティの値を取得する構文は cursor_name%attribute です。例：c1%NOTFOUND。カーソルプロパティの種類は以下のとおりです：

* `%FOUND` ブール型プロパティ。カーソルの最後の読み取りでレコードが返された場合、値は `TRUE` です。

* `%NOTFOUND` ブール型プロパティ。`%FOUND` の逆です。

* `%ISOPEN` ブール型プロパティ。カーソルが開いている場合、`TRUE` を返します。

* `%ROWCOUNT` 数値型プロパティ。カーソルから読み取ったレコード数を返します。

## 主要なカーソルプロパティとその戻り値

|   **プロパティ名**   |                                                                   **宣言済みカーソルの値**                                                                   |                                                                                  **暗黙カーソルの値**                                                                                   |
|-------------|-------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `%FOUND`    | カーソルが開いている状態で `FETCH` 操作がない場合、`NULL` を返します。直近の `FETCH` 操作で1行のレコードが返された場合、`TRUE` を返します。直近の `FETCH` 操作でレコードが返されなかった場合、`FALSE` を返します。 | DMLまたは `SELECT INTO` ステートメントが実行されていない場合、`NULL` を返します。直近に実行されたDMLまたは `SELECT INTO` ステートメントで1行のレコードが返された場合、`TRUE` を返します。直近に実行されたDMLまたは `SELECT INTO` ステートメントでレコードが返されなかった場合、`FALSE` を返します。 |
| `%NOTFOUND` | カーソルが開いている状態で `FETCH` 操作がない場合、`NULL` を返します。直近の `FETCH` 操作で1行のレコードが返された場合、`FALSE` を返します。直近の `FETCH` 操作でレコードが返されなかった場合、`TRUE` を返します。 | DMLまたは `SELECT INTO` ステートメントが実行されていない場合、`NULL` を返します。直近に実行されたDMLまたは `SELECT INTO` ステートメントで1行のレコードが返された場合、`FALSE` を返します。直近に実行されたDMLまたは `SELECT INTO` ステートメントでレコードが返されなかった場合、`TRUE` を返します。 |
| `%ROWCOUNT` | カーソルが開いている状態の場合、0以上の数値を返します。                                                                                                                     | DMLまたは `SELECT INTO` ステートメントが実行されていない場合、`NULL` を返します。それ以外の場合、0以上の数値を返します。                                                                                                                 |
| `%ISOPEN`   | カーソルが開いている状態の場合、`TRUE` を返します。それ以外の場合、`FALSE` を返します。                                                                                                              | �常に `FALSE` です。                                                                                                                                                                   |

## 例

**例：シンプルカーソルでデータを取得します。**

```javascript
obclient> CREATE TABLE employees (
      employee_id INT,
      first_name VARCHAR(50),
      last_name VARCHAR(50),
      manager_id INT,
      salary NUMERIC
    );
Query OK, 0 rows affected

obclient> INSERT INTO employees VALUES(111, 'DEL', 'FA BEN', 1, 1500);
Query OK, 1 rows affected

obclient> INSERT INTO employees VALUES(112, 'AXEL', 'BELL', 1, 1000);
Query OK, 1 rows affected

obclient> INSERT INTO employees VALUES(113, 'CRIS',  'RACHAR', 1, 1000);

Query OK, 1 rows affected

obclient> DECLARE
        CURSOR c_emp IS SELECT first_name, salary
            FROM employees where rownum<5;
        v_ename  employees.first_name%TYPE;
        v_sal    employees.salary%TYPE;
     BEGIN
         OPEN c_emp;
         FETCH c_emp INTO v_ename, v_sal;
         WHILE c_emp%FOUND LOOP
             DBMS_OUTPUT.PUT_LINE(v_ename||'''s salary is '||to_char(v_sal) );
             FETCH c_emp INTO v_ename, v_sal;
         END LOOP;
         CLOSE c_emp;
END;
/
Query OK, 0 rows affected

DEL's salary is 1500
AXEL's salary is 1000
CRIS's salary is 1000
```

**例：パラメータを使用した渡し方。**

```javascript
obclient> DECLARE
        CURSOR c_emp (in_job_id varchar default 'AC_MGR' ) IS
             SELECT first_name, salary
             FROM employees where job_id = in_job_id;
        v_jobid  employees.job_id%TYPE;
        v_emp_name employees.first_name%TYPE;
        v_sal employees.salary%TYPE;
     BEGIN
         v_jobid := 'IT_PROG';
         OPEN c_emp(in_job_id => v_jobid);
         LOOP
             FETCH c_emp INTO v_emp_name, v_sal;
             EXIT WHEN c_emp%NOTFOUND;
             DBMS_OUTPUT.PUT_LINE('DEPT '||v_jobid||': '||v_emp_name||'''s salary is '||to_char(v_sal) );
         END LOOP;
         CLOSE c_emp;
END;
/
Query OK, 0 rows affected

DEPT IT_PROG: Alexander's salary is 9000
DEPT IT_PROG: Bruce's salary is 6000
DEPT IT_PROG: David's salary is 4800
DEPT IT_PROG: Valli's salary is 4800
DEPT IT_PROG: Diana's salary is 4200
```

## NO_DATA_FOUNDと%NOTFOUNDの違い

`NO_DATA_FOUND` と `%NOTFOUND` の違いは以下の表のとおりです。

| **違い** |            **NO_DATA_FOUND**             |                                                                                                                                   **%NOTFOUND**                                                                                                                                   |
|---------|------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 定義が異なる    | `NO_DATA_FOUND` は例外定義です。                   | `%NOTFOUND` はカーソルのプロパティです。                                                                                                                                                                                                                                                                |
| トリガー条件が異なる  | `SELECT ... INTO` ステートメントは `NO_DATA_FOUND` をトリガーします。 | <ul><li> 明示的カーソルの `WHERE` 句で検索結果が見つからない場合、`%NOTFOUND` がトリガーされます。   </li><li> `UPDATE` または `DELETE` ステートメントの `WHERE` 句で検索結果が見つからない場合、`SQL%NOTFOUND` がトリガーされます。   </li><li> プル処理のループでは、`%NOTFOUND` または `%FOUND` を使用してループの終了条件を判断します。</li></ul>    |
