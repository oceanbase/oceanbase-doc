# REFRESH

`REFRESHE`は、指定されたマテリアライズドビューをリフレッシュします。

<main id="notice" >
  <h4>機能の適用範囲</h4>
  <p>この内容はOceanBaseデータベースEnterprise Editionにのみ適用されます。OceanBaseデータベースCommunity EditionはMySQLモードのみを提供します。</p>
</main>

## 構文

```sql
DBMS_MVIEW.REFRESH (
    { list                 IN     VARCHAR2
    | tab                  IN     DBMS_UTILITY.UNCL_ARRAY}
    [, method                 IN     VARCHAR2       := NULL]
    [, rollback_seg           IN     VARCHAR2       := NULL]
    [, push_deferred_rpc      IN     BOOLEAN        := true]
    [, refresh_after_errors   IN     BOOLEAN        := false]
    [, purge_option           IN     BINARY_INTEGER := 1]
    [, parallelism            IN     BINARY_INTEGER := 0]
    [, heap_size              IN     BINARY_INTEGER := 0]
    [, atomic_refresh         IN     BOOLEAN        := true]
    [, nested                 IN     BOOLEAN        := false]
    [, out_of_place           IN     BOOLEAN        := false]
    [, skip_ext_data          IN     BOOLEAN        := false]
    [, refresh_parallel       IN     BINARY_INTEGER := 0]
    [, nested_refresh_mode    IN     VARCHAR2       := NULL]
    [, async                  IN     BOOLEAN        := false]
);
```

## パラメータの説明

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>ネストされていないマテリアライズドビューには連鎖リフレッシュ動作が存在せず、<code>nested</code>および<code>nested_refresh_mode</code>パラメータを指定しても意味がありません。デフォルトでは独立リフレッシュとなります。</p>
</main>

|       **パラメータ**       |           **説明**                |
|----------------------|-----------------------------------|
| list                 | カンマ区切りのリフレッシュ対象マテリアライズドビュー名のリストです。現在、単一のマテリアライズドビューのみのリフレッシュをサポートしており、複数のマテリアライズドビューの同時リフレッシュはサポートされていません。|
| tab                  | リフレッシュ対象マテリアライズドビュー名の配列です。現在、単一のマテリアライズドビュー名配列のみのリフレッシュをサポートしており、複数のマテリアライズドビュー名配列の同時リフレッシュはサポートされていません。|
| method               | マテリアライズドビューのリフレッシュ戦略を定義し、作成時にデフォルトの戦略を指定できます。選択可能な方法は以下の通りです：<ul><li>`F`または`f`：高速リフレッシュ。</li><li>`?`：強制リフレッシュ。</li><li>`C`または`c`：フルリフレッシュ。</li><li>`A`または`a`：常にリフレッシュ。`C`と同義です。</li></ul>|
| rollback_seg         | 現在実質的な効果はありません。Oracle互換性のためのものです。|
| push_deferred_rpc    | 現在実質的な効果はありません。Oracle互換性のためのものです。|
| refresh_after_errors | 現在実質的な効果はありません。Oracle互換性のためのものです。|
| purge_option         | 現在実質的な効果はありません。Oracle互換性のためのものです。|
| parallelism          | 現在実質的な効果はありません。Oracle互換性のためのものです。|
| heap_size            | 現在実質的な効果はありません。Oracle互換性のためのものです。|
| atomic_refresh       | 現在実質的な効果はありません。Oracle互換性のためのものです。|
| nested               | ネストされたマテリアライズドビューのリフレッシュモードを指定します。取り得る値は以下の通りです：<ul><li>`FALSE`：デフォルト値で、ネストされたマテリアライズドビューを独立リフレッシュすることを示します。</li><li>`TRUE`：ネストされたマテリアライズドビューを連鎖リフレッシュすることを示します。</li></ul>|
| out_of_place         | 現在実質的な効果はありません。Oracle互換性のためのものです。|
| skip_ext_data        | 現在実質的な効果はありません。Oracle互換性のためのものです。|
| refresh_parallel     | リフレッシュ操作の並列度、つまり同時に実行するリフレッシュ操作のスレッド数です。|
| nested_refresh_mode  | ネストされたマテリアライズドビューの連鎖リフレッシュが一貫性のあるリフレッシュ動作か非一貫性のあるリフレッシュ動作かを指定します。取り得る値は以下の通りです：<ul><li>パラメータ`nested`を`FALSE`に指定した場合、パラメータ`nested_refresh_mode`を指定するとエラーが発生します。</li><li>パラメータ`nested`を`TRUE`に指定した場合：<ul><li>パラメータ`nested_refresh_mode`の取り得る値は以下の通りです：<ul><li>`inconsistent`：連鎖非一貫性リフレッシュを示します。</li><li>`consistent`：連鎖一貫性リフレッシュを示します。</li></ul> </li><li>パラメータ`nested_refresh_mode`を指定しない場合、デフォルトで連鎖非一貫性リフレッシュとなります。</li></ul> </li></ul>|
| async               | 非同期リフレッシュを行うかどうかを指定します。取り得る値は以下の通りです：<ul><li>`FALSE`：デフォルト値で、リフレッシュタスク完了後に戻ることを示します。</li><li>`TRUE`：`REFRESH`を呼び出した後、バックグラウンドでリフレッシュタスクを作成してすぐに戻ることを示します。</li></ul> <main id="notice" type='explain'><h4>説明</h4><p>V4.4.2バージョンでは、このパラメータはV4.4.2 BP2バージョンから導入されました。</p></main>|

## 例

* 独立更新モード：

  * パラメータ `mv_name` のみを指定します。

    ```shell
    obclient> CALL DBMS_MVIEW.REFRESH('mv1');
    ```

  * パラメータ `mv_name` とパラメータ `nested` の値を `false` に指定します。

    ```shell
    obclient> CALL DBMS_MVIEW.REFRESH(
        'mv1',
        nested=> false);
    ```

* 連鎖非一貫性更新モード：

  * パラメータ `mv_name` を指定し、パラメータ `nested` の値を `true` に設定しますが、パラメータ `nested_refresh_mode` は指定しません。

    ```shell
    obclient> CALL DBMS_MVIEW.REFRESH(
        'mv1',
        nested=> true);
    ```

  * パラメータ `mv_name` を指定し、パラメータ `nested` の値を `true` に設定するとともに、パラメータ `nested_refresh_mode` の値を `inconsistent` に設定します。

    ```shell
    obclient> CALL DBMS_MVIEW.REFRESH(
        'mv1',
        nested=> true,
        nested_refresh_mode => 'inconsistent');
    ```

* 連鎖一貫性更新モード：

  パラメータ `mv_name` を指定し、パラメータ `nested` の値を `true` に設定するとともに、パラメータ `nested_refresh_mode` の値を `consistent` に設定します。

  ```shell
  obclient> CALL DBMS_MVIEW.REFRESH(
      'mv1',
      nested=> true,
      nested_refresh_mode => 'consistent');
  ```

* 以下はエラーが発生するシナリオです：

  * パラメータ `nested` の値を `false` に設定し、さらにパラメータ `nested_refresh_mode` の値も指定した場合、エラーが発生します。

    ```shell
    obclient> CALL DBMS_MVIEW.REFRESH(
        'mv1',
        nested=> false,
        nested_refresh_mode => 'xxxx');
    ```

  * パラメータ `nested` の値を指定せず、パラメータ `nested_refresh_mode` の値のみを指定した場合、エラーが発生します。

    ```shell
    obclient> CALL DBMS_MVIEW.REFRESH(
        'mv1',
        nested_refresh_mode => 'xxxx');
    ```

  * パラメータ `nested` の値を `true` に設定し、パラメータ `nested_refresh_mode` の値を無効な文字列に設定した場合、エラーが発生します。

    ```shell
    obclient> CALL DBMS_MVIEW.REFRESH(
        'mv1',
        nested=> true,
        nested_refresh_mode => '無効な文字列');
    ```
