# BIND_ARRAY

`BIND_ARRAY` ストアドプロシージャは、PL/SQLコレクションを動的SQLステートメントのプレースホルダーにバインドするために使用します。

`BIND_VARIABLE` は1回の呼び出しで1つのプレースホルダーに1つの値をバインドしますが、`BIND_ARRAY` はコレクション全体をバインドします。`EXECUTE` を呼び出すと、OceanBaseデータベースはコレクションの要素ごとにステートメントを実行するため、SQLの実行回数を削減できます。

OceanBaseデータベースは、V4.4.2 BP4以降で `BIND_ARRAY` ストアドプロシージャをサポートしています。

  <main id="notice" >
    <h4>機能の適用範囲</h4>
    <p>この内容はOceanBaseデータベースEnterprise版にのみ適用されます。OceanBaseデータベースCommunity版はMySQLモードのみを提供します。</p>
  </main>

## 構文

```sql
DBMS_SQL.BIND_ARRAY(
  c           IN INTEGER,
  name        IN VARCHAR2,
  table_value IN <table_type>,
  index1      IN INTEGER DEFAULT 1,
  index2      IN INTEGER DEFAULT -1);
```

`table_value` と、それに対応する `<table_type>` には、以下の組み合わせを使用できます。`BIND_ARRAY` は、異なるコレクション型を受け取れるようにオーバーロードされています。

```sql
<table_value>     <table_type>
n_tab             Number_Table
c_tab             Varchar2_Table
d_tab             Date_Table
bl_tab            Blob_Table
cl_tab            Clob_Table
bf_tab            Binary_Float_Table
bd_tab            Binary_Double_Table
```

## パラメータの説明

|   **パラメータ**   |               **説明**                |
|------------|-------------------------------------|
| c          | コレクションをバインドするカーソルのID。                      |
| name       | ステートメント内のプレースホルダー名。名前の先頭にはコロン（`:`）を付けることができます。          |
| table_value | バインドするPL/SQLコレクション変数。                    |
| index1     | バインドする要素の開始添字。`index1` と `index2` を省略すると、コレクション全体がバインドされます。   |
| index2     | バインドする要素の終了添字。`index1` と `index2` を省略すると、コレクション全体がバインドされます。   |

## 使用上の注意点

* サポートされているコレクション型は、`Number_Table`、`Varchar2_Table`、`Date_Table`、`Blob_Table`、`Clob_Table`、`Binary_Float_Table`、`Binary_Double_Table` です。コレクション自体には、連想配列、ネストしたテーブル（Nested Table）、またはVARRAYを使用できます。

* `index1` と `index2` は、両方とも指定するか、両方とも省略する必要があります。両方を省略すると、コレクションのすべての要素がバインドされます。両方を指定すると、添字が `[index1, index2]` の範囲内にある要素のみがバインドされます。連想配列の場合、`DELETE` で削除された要素はバインドの対象外です。

* `index1` と `index2` がコレクション要素の添字の範囲を超える場合、`ORA-06532` エラーが発生します。

* 同じプレースホルダーに対して保持できるバインドは1つだけです。同じプレースホルダーに対して `BIND_ARRAY` または `BIND_VARIABLE` を繰り返し呼び出すと、後のバインドが前のバインドを上書きします。

* 同じカーソルで `BIND_VARIABLE` と `BIND_ARRAY` を併用できます。この場合、スカラーとしてバインドした値は各回の実行で繰り返し使用されます。

* ステートメントの反復回数は、各配列でバインド対象となる要素数のうち、最も少ない数になります。例えば、3つの要素を持つ `:id` と2つの要素を持つ `:name` を同時にバインドした場合、`EXECUTE` は2回だけ実行します。

* `EXECUTE` は、すべての実行で影響を受けた行数の合計を返します。

* バインド対象のコレクションが空で、ステートメントに `RETURNING INTO` 句が含まれる場合、ステートメントは1回実行されます。`RETURNING INTO` 句が含まれない場合は、`ORA-06532` エラーが発生します。

* `RETURNING INTO` の出力プレースホルダーにも、`BIND_ARRAY` を使用して同じ型の空のコレクションをバインドする必要があります。`EXECUTE` の実行完了後、`VARIABLE_VALUE` ですべての戻り行を取得します。返される行数は、入力コレクションの要素数より少なくなる場合があります。

## 例

テストテーブル `t_bind_array_demo` を作成します。

```sql
CREATE TABLE t_bind_array_demo (id NUMBER, name VARCHAR2(20));
```

例1：`Number_Table` と `Varchar2_Table` を使用して3行のデータを一括挿入します。`EXECUTE` は影響を受けた行数の合計を返します。

```sql
DECLARE
  c INTEGER;
  v_ids DBMS_SQL.NUMBER_TABLE;
  v_names DBMS_SQL.VARCHAR2_TABLE;
  ret INTEGER;
BEGIN
  c := DBMS_SQL.OPEN_CURSOR;
  DBMS_SQL.PARSE(c, 'INSERT INTO t_bind_array_demo(id, name) VALUES(:id, :name)', DBMS_SQL.NATIVE);

  v_ids(1) := 1;
  v_ids(2) := 2;
  v_ids(3) := 3;
  v_names(1) := 'a';
  v_names(2) := 'b';
  v_names(3) := 'c';

  DBMS_SQL.BIND_ARRAY(c, ':id', v_ids);
  DBMS_SQL.BIND_ARRAY(c, ':name', v_names);

  ret := DBMS_SQL.EXECUTE(c);
  DBMS_OUTPUT.PUT_LINE('affected rows: ' || ret);

  DBMS_SQL.CLOSE_CURSOR(c);
END;
/
```

例2：`index1` と `index2` を使用して、コレクション内の添字が2から3の要素のみをバインドします。

```sql
DECLARE
  c INTEGER;
  v_ids DBMS_SQL.NUMBER_TABLE;
  ret INTEGER;
BEGIN
  c := DBMS_SQL.OPEN_CURSOR;
  DBMS_SQL.PARSE(c, 'UPDATE t_bind_array_demo SET name = ''updated'' WHERE id = :id', DBMS_SQL.NATIVE);

  v_ids(1) := 1;
  v_ids(2) := 2;
  v_ids(3) := 3;
  v_ids(4) := 4;

  DBMS_SQL.BIND_ARRAY(c, ':id', v_ids, 2, 3);

  ret := DBMS_SQL.EXECUTE(c);
  DBMS_OUTPUT.PUT_LINE('affected rows: ' || ret);

  DBMS_SQL.CLOSE_CURSOR(c);
END;
/
```

例3：`RETURNING INTO` 句を含む `DELETE` ステートメントを一括実行し、`VARIABLE_VALUE` で削除された行を取得します。

```sql
DECLARE
  c INTEGER;
  v_ids DBMS_SQL.NUMBER_TABLE;
  v_deleted DBMS_SQL.NUMBER_TABLE;
  ret INTEGER;
BEGIN
  c := DBMS_SQL.OPEN_CURSOR;
  DBMS_SQL.PARSE(c, 'DELETE FROM t_bind_array_demo WHERE id = :id RETURNING id INTO :out_id', DBMS_SQL.NATIVE);

  v_ids(1) := 1;
  v_ids(2) := 2;

  DBMS_SQL.BIND_ARRAY(c, ':id', v_ids);
  DBMS_SQL.BIND_ARRAY(c, ':out_id', v_deleted);

  ret := DBMS_SQL.EXECUTE(c);
  DBMS_SQL.VARIABLE_VALUE(c, ':out_id', v_deleted);

  FOR i IN v_deleted.FIRST .. v_deleted.LAST LOOP
    DBMS_OUTPUT.PUT_LINE('deleted id: ' || v_deleted(i));
  END LOOP;

  DBMS_SQL.CLOSE_CURSOR(c);
END;
/
```

テーブルのデータをクエリし、一括操作の結果を確認します。

```sql
SELECT * FROM t_bind_array_demo ORDER BY id;
```

テストテーブルを削除します。

```sql
DROP TABLE t_bind_array_demo;
```
