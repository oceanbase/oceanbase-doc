# CLEAN_AUDIT_TRAIL

`CLEAN_AUDIT_TRAIL` プロシージャは、監査トレイルレコードをクリーンアップするために使用されます。

  <main id="notice" >
    <h4>機能の適用範囲</h4>
    <p>この内容はOceanBaseデータベースEnterprise Editionにのみ適用されます。OceanBaseデータベースCommunity EditionはMySQLモードのみを提供します。</p>
  </main>

## 構文

```sql
DBMS_AUDIT_MGMT.CLEAN_AUDIT_TRAIL(
audit_trail_type         IN PLS_INTEGER,
use_last_arch_timestamp  IN BOOLEAN DEFAULT TRUE);
```

## パラメータ説明

|           パラメータ           |        説明        |
|-------------------------|----------------------|
| audit_trail_type        | クリーンアップが必要な監査トレイルのタイプです。監査トレイルのタイプについては、[DBMS_AUDIT_MGMT 監査トレイルタイプ](../2600.dbms-audit-mgmt-oracle/100.dbms-audit-mgmt-overview-oracle.md)を参照してください。 |
| use_last_arch_timestamp | 最後にアーカイブされたタイムスタンプを使用してクリーンアップするレコードを判断するかどうかを指定します。値は以下のとおりです： <ul><li> `TRUE` の値は、最後のアーカイブタイムスタンプより前に作成された監査レコードのみをクリーンアップすべきであることを示します。  </li><li> `FALSE` の値は、すべての監査レコードをクリーンアップすべきであることを示します。</li></ul>    デフォルト値は `TRUE` です。この値を使用することを推奨します。これにより、意図しないレコードのクリーンアップを防ぐことができます。 |

## 使用方法

`CLEAN_AUDIT_TRAIL` プロシージャは通常、`SET_LAST_ARCHIVE_TIMESTAMP` プロシージャの後に呼び出されます。`SET_LAST_ARCHIVE_TIMESTAMP` プロシージャは、監査レコードの最終アーカイブタイムスタンプを設定するために使用されます。

## 例

以下の例では、`CLEAN_AUDIT_TRAIL` プロシージャを呼び出して、最終アーカイブタイムスタンプ以前に更新されたすべての監査トレイルレコードをクリーンアップします。

```sql
BEGIN
   DBMS_AUDIT_MGMT.CLEAN_AUDIT_TRAIL(
      audit_trail_type         =>  DBMS_AUDIT_MGMT.AUDIT_TRAIL_ALL,
      use_last_arch_timestamp  =>  TRUE);
END;
```
