# DROP_JOB

`DROP_JOB` プロシージャは、1つまたは複数のジョブ、または1つまたは複数のジョブクラスに含まれるすべてのジョブを削除するために使用されます。ジョブを削除すると、そのジョブに設定されたすべてのパラメータ値も削除されます。

  <main id="notice" >
    <h4>機能の適用範囲</h4>
    <p>この内容はOceanBaseデータベースEnterprise Editionにのみ適用されます。OceanBaseデータベースCommunity EditionはMySQLモードのみを提供します。</p>
  </main>

## 構文

```sql
DBMS_SCHEDULER.DROP_JOB (
job_name                IN VARCHAR2,
force                   IN BOOLEAN DEFAULT FALSE,
defer                   IN BOOLEAN DEFAULT FALSE,
commit_semantics        IN VARCHAR2 DEFAULT 'null');
```

## パラメータ説明

|        パラメータ       |      説明      |
|------------------|-----------------|
| job_name         | ジョブまたはジョブクラスの名前。名前はカンマ区切りのリストです。ジョブクラスの場合は、`SYS` スキーマを指定する必要があります。ジョブクラス名を指定した場合、そのジョブクラスに属するジョブは削除されますが、ジョブクラス自体は削除されません。 |
| force            | `TRUE` に設定されている場合、Schedulerはまず実行中のジョブインスタンスを停止しようと試み、その後ジョブを削除します。  |
| defer            | `TRUE` に設定されている場合、Schedulerはまず実行中のジョブの実行完了を許可しようと試み、その後ジョブを削除します。   |
| commit_semantics | コミットセマンティクス。以下のタイプをサポートします： <ul><li> `STOP_ON_FIRST_ERROR`：最初のエラーで戻りますが、それ以前の成功した削除操作はディスクにコミットされます。これがデフォルト設定です。</li>   <li> `TRANSACTIONAL`：最初のエラーで戻り、そのエラー以前の結果をロールバックします。`force` が `TRUE` に設定されている場合、このタイプはサポートされません。</li>    <li> `ABSORB_ERRORS`：任意のエラーを吸収し、残りのジョブを無効化し、すべての成功した無効化操作をコミットします。ジョブまたはジョブリストを無効化する場合にのみサポートされます。</li> </ul> |

## 使用方法

`force` と `defer` の両方が `FALSE` に設定されており、`DROP_JOB` を呼び出したときにジョブが実行中の場合、そのジョブを削除しようとすると操作は失敗します。`commit_semantics` の設定によっては、`DROP_JOB` の呼び出し全体が失敗する可能性があります。

`force` と `defer` の両方を `TRUE` に設定すると、エラーが発生します。

## 例

```sql
BEGIN
  DBMS_SCHEDULER.DROP_JOB(job_name => 'job_test');
END;
```
