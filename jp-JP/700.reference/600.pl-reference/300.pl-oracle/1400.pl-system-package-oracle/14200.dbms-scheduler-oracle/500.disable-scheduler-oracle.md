# DISABLE

`DISABLE` プロシージャは、プログラムやジョブを無効にするために使用されます。

Schedulerオブジェクトが無効化されると、その `enabled` プロパティは `FALSE` に設定されます。

  <main id="notice" >
    <h4>機能の適用範囲</h4>
    <p>この内容はOceanBaseデータベースEnterprise Editionにのみ適用されます。OceanBaseデータベースCommunity EditionはMySQLモードのみを提供します。</p>
  </main>

## 構文

```sql
DBMS_SCHEDULER.DISABLE (
job_name              IN VARCHAR2,
force                 IN BOOLEAN DEFAULT FALSE,
commit_semantics      IN VARCHAR2 DEFAULT 'STOP_ON_FIRST_ERROR');
```

## パラメータ説明

|        パラメータ       |      説明         |
|------------------|--------------------|
| job_name             | 無効にするジョブの名前です。複数のジョブ名はカンマ区切りのリストとして指定できます。ジョブクラス名を指定した場合、そのジョブクラス内のすべてのジョブが無効化されますが、ジョブクラス自体は無効化されません。グループ名を指定した場合、そのグループが無効化されますが、グループメンバーの有効状態は影響を受けません。 <p>システム内部で定義されているスケジュールタスクは以下の通りです：</p><ul><li>`SCHEDULED_TRIGGER_PARTITION_BALANCE`：パーティションの均衡タスク</li> <li>`SCHEDULED_RECYCLE_SCHEMA_HISTORY`：Schemaのマルチバージョン履歴データ回収タスク（V4.4.2バージョンでは、V4.4.2 BP1バージョンからサポートされています）</li> <li>`SCHEDULED_RUN_INSPECTION`：Root Service自己検査タスク（V4.4.2バージョンでは、V4.4.2 BP1バージョンからサポートされています）</li> <li>`SCHEDULED_PURGE_RECYCLEBIN`：ゴミ箱クリーンアップタスク（V4.4.2バージョンでは、V4.4.2 BP2バージョンからサポートされています）</li></ul>     |
| force            | `TRUE` の場合、他のオブジェクトがそのオブジェクトに依存していても、そのオブジェクトを無効化します。   |
| commit_semantics | コミットセマンティクス。以下のタイプをサポートします： <ul><li> `STOP_ON_FIRST_ERROR`：このプロシージャは最初のエラーで戻りますが、それ以前に成功した無効化操作はディスクにコミットされます。これがデフォルト設定です。   </li><li> `TRANSACTIONAL`：このプロシージャは最初のエラーで戻り、そのエラー発生前に行われたすべての操作をロールバックします。ジョブまたはジョブリストの無効化時にのみサポートされます。また、`force` が `TRUE` に設定されている場合は、このタイプはサポートされません。   </li><li>`ABSORB_ERRORS`：このプロシージャは、どんなエラーでも収集し、残りのジョブを無効化し、すべての成功した無効化操作をコミットします。ジョブまたはジョブリストの無効化時にのみサポートされます。</li></ul>     |

## 使用方法

既に無効化されたオブジェクトを無効化してもエラーは発生しません。

`force` オプションの目的は依存関係を認識することであり、依存オブジェクトを変更するものではありません。

ジョブを無効化するということは、ジョブのメタデータは存在するものの、処理や実行を行うべきではない状態にすることです。ジョブが無効化されると、ジョブキュー内の `state` は `disabled` に変更されます。`force` が `FALSE` に設定されており、かつジョブが現在実行中の場合は、エラーが返されます。`force` が `TRUE` に設定されている場合、ジョブは無効化されますが、現在実行中のインスタンスが実行を完了することは許可されます。

プログラムが無効化されると、その状態は無効に変わります。無効化されたプログラムとは、メタデータは依然として存在するものの、そのプログラムを参照するジョブは実行できない状態を指します。`force` が `FALSE` に設定されている場合、どのジョブもそのプログラムを参照してはならず、そうでない場合はエラーが発生します。`force` が `TRUE` に設定されている場合、そのプログラムを参照するジョブは無効化されません。なぜなら、それらのジョブのプログラムが無効になり、実行に失敗するからです。そのプログラムを参照して実行中のジョブは `DISABLE` 呼び出しの影響を受けず、実行を続けることができます。プログラムが無効化されると、そのプログラムに関連するパラメータは影響を受けません。

## 例

* `empprogram` ジョブを無効化します。

  ```shell
  obclient(SYS@oracle001)[SYS]> delimiter //
  ```

  ```shell
  obclient(SYS@oracle001)[SYS]> BEGIN
    SYS.DBMS_SCHEDULER.DISABLE(
              job_name => 'empprogram',
              force => TRUE,
              COMMIT_SEMANTICS => 'STOP_ON_FIRST_ERROR');
  END;//
  ```

  ```shell
  obclient(SYS@oracle001)[SYS]> delimiter ;
  ```

* スケジュールされたパーティションの均等化タスクを無効にします。

  ```shell
  obclient(SYS@oracle001)[SYS]> CALL DBMS_SCHEDULER.DISABLE(job_name => 'SCHEDULED_TRIGGER_PARTITION_BALANCE');
  ```

  または

  ```shell
  obclient(SYS@oracle001)[SYS]> CALL DBMS_SCHEDULER.DISABLE('SCHEDULED_TRIGGER_PARTITION_BALANCE');
  ```
