# OPEN

`OPEN` ステートメントは、指定されたモードで内部または外部 `LOB` を開くために使用されます。有効なモードは、読み取り専用と読み書きです。

  <main id="notice" >
    <h4>適用対象</h4>
    <p>この内容はOceanBaseデータベースEnterprise Editionにのみ適用されます。OceanBaseデータベースCommunity EditionはMySQLモードのみを提供します。</p>
  </main>

## 構文

```sql
DBMS_LOB.OPEN (
lob_loc   IN OUT NOCOPY BLOB,
open_mode IN            BINARY_INTEGER);

DBMS_LOB.OPEN (
lob_loc   IN OUT NOCOPY CLOB CHARACTER SET ANY_CS,
open_mode IN            BINARY_INTEGER);
```

## パラメータ説明

|  **パラメータ**   |                                 **説明**                                  |
|-----------|-------------------------------------------------------------------------|
| lob_loc   | `LOB` ロケーター。詳細については、[DBMS_LOBの使用方法](../9300.dbms-lob-oracle/100.dbms-lob-overview-oracle.md)を参照してください。 |
| open_mode | 開き方。`BLOB` および `CLOB` 型に対して、モードは `LOB_READONLY` または `LOB_READWRITE` です。      |

## 使用上の注意

<main id="notice" type='explain'>
    <h4>説明</h4>
    <p><code>LOB</code> を読み取り専用モードで開いてから、<code>LOB</code> に書き込もうとすると、エラーが返されます。</p>
  </main>

* `OPEN` は内部および外部 `LOB` サーバー間を往復する必要があります。内部 `LOB` の場合、`OPEN` トリガーは `OPEN` 呼び出しに依存する他のコードを実行します。

* すべての `LOB` 操作をOpen/Closeインターフェースでラッピングすることは必須ではありません。`LOB` を開いた場合、トランザクションをコミットする前にそれを閉じる必要があります。そうでない場合、エラーが発生します。内部 `LOB` を閉じると、`LOB` 列上の機能インデックスとドメインインデックスが更新されます。

* トランザクションによって開かれたすべての `LOB` を閉じる前にトランザクションをコミットすると、エラーが発生します。エラーが返された場合、開かれた `LOB` のオープン状態は破棄されますが、トランザクションは成功裏にコミットされます。これには、トランザクション内の `LOB` および非 `LOB` データに加えられたすべての変更のコミットが含まれますが、ドメインおよび関数ベースのインデックスは更新されません。このような場合は、`LOB` 列に対して機能インデックスとドメインインデックスを再構築する必要があります。
