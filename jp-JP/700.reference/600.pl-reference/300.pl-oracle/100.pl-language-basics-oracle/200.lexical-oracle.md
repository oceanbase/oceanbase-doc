# 語法

PLの構成要素は、区切り文字、識別子、テキスト、コンパイル指示、コメントといった最小単位です。

    <h4>適用対象</h4>

  </main>

## 区切り文字

区切り文字とは、PLにおいて特別な意味を持つ文字または文字の組み合わせです。区切り文字に他の文字（スペース文字を含む）を埋め込まないでください。

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>本記事で説明する区切り文字とOBClientの区切り文字は、意味が異なります。</p>
  </main>

PLでサポートされている区切り文字は以下の表のとおりです：

| 区切り文字 |    **意味**     |
|------|---------------|
| +    | 加算演算子         |
| :=   | 赋値演算子         |
| =\>  | 結合演算子         |
| %    | 属性指示子         |
| '    | 文字列境界文字        |
| .    | 要素アクセス演算子         |
| \|\| | 接続演算子         |
| /    | 除算演算子         |
| \*\* | 幂演算子         |
| (    | 式またはリストの開始境界文字 |
| )    | 式またはリストの終了境界文字 |
| :    | ホスト変数指示子       |
| ,    | 区切り文字           |
| \<\< | タグの開始境界文字     |
| \>\> | タグの終了境界文字     |
| /\*  | 複数行コメントの開始境界文字   |
| \*/  | 複数行コメントの終了境界文字   |
| \*   | 乗算演算子         |
| "    | 引用符で囲まれた境界文字     |
| ..   | 範囲演算子         |
| =    | 関係演算子（等しい）     |
| \<\> | 関係演算子（不等しい）    |
| !=   | 関係演算子（不等しい）    |
| \~=  | 関係演算子（不等しい）    |
| \^=  | 関係演算子（不等しい）    |
| \<   | 関係演算子（小さい）     |
| \>   | 関係演算子（大きい）     |
| \<=  | 関係演算子（小さいか等しい）  |
| \>=  | 関係演算子（大きいか等しい）  |

## 識別子

識別子は、定数、カーソル、例外、キーワード、タグ、パッケージ、予約語、サブプログラム、型、変数などのPL要素に名前を付けるために使用されます。

識別子の各文字（アルファベットであるかどうかにかかわらず）は意味を持ちます。例えば、識別子 `firstname` と `first_name` は異なります。

隣接する識別子を区切るには、1つ以上のスペース文字または句読点を使用する必要があります。

二重引用符で囲まれていない限り、PL識別子は大文字小文字を区別しません。例えば、識別子 `firstname`、`FirstName`、`FIRSTNAME` は同じです。

### 予約語

PL予約語は、特別な意味を持つ識別子です。

予約語を通常のユーザー定義識別子として使用することは推奨されません。PL予約語のリストについては、付録[PL予約語](../1500.pl-keywords-oracle.md)を参照してください。

### 事前定義済み識別子

事前定義済み識別子は、事前定義パッケージ `STANDARD` を使用して宣言します。

事前定義済み識別子のリストについては、[プログラムパッケージ STANDARD による PL 環境の定義](../900.package-oracle/500.package-standard-definition-of-pl-environment-oracle.md)を参照してください。

事前定義済みの識別子をユーザー定義識別子として使用できますが、ローカルでの宣言がグローバルな宣言を上書きするため、この方法は推奨されません。

### ユーザー定義識別子

ユーザー定義識別子は、データベースの文字セットから構成される、通常のまたは引用される識別子です。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>ユーザー定義識別子は、直接的に意味を表現できるものである必要があります。例えば、<code>cost_per_employee</code> は文字通りの意味が理解できますが、<code>cpe</code> はそうではありません。</p>
  </main>

### 通常のユーザー定義識別子

ユーザーは識別子を定義できます。PLはユーザー定義識別子に対して以下の要件と制限を設けています：

* 最初の文字はアルファベットでなければなりません。

* アルファベット、数字、および正斜線（/）、アスタリスク（\*）、アンド記号（\&）、ドル記号（$）などを含むことができます。

* 長さは128文字を超えてはなりません。

* PL予約語をPL識別子として使用することはできません。

* PL識別子は大文字小文字を区別しません。

以下のユーザー定義識別子は有効です：

```sql
t8
telephone#
credit_limit
FirstName
OceanBase$number
money$$tree
SN##
try_again_
```

### 引用符識別子

クォート付きのユーザー定義識別子は、二重引用符で囲みます。

二重引用符の間には、データベース文字セットの任意の文字を使用できますが、二重引用符、改行文字、およびヌル文字は除きます。

以下の引用符識別子は有効です：

```sql
"X+Y"
"first name"
"on/off switch"
"department(s)"
"*** body info ***"
```

クォート付きのユーザー定義識別子は大文字小文字を区別します。ただし、クォートなしのクォート付きユーザー定義識別子が有効な通常のユーザー定義識別子である場合、その識別子が参照される際の二重引用符はオプションです。省略した場合、識別子は大文字小文字を区別しません。

予約語をクォート付きのユーザー定義識別子として使用できますが、推奨されません。予約語は有効な通常のユーザー定義識別子ではないため、識別子は常に二重引用符で囲む必要があり、大文字小文字を区別します。

```sql
obclient> DECLARE
    "HELLO" varchar2(10) := 'hello';    -- HELLOはユーザー定義識別子です
    "ALL" varchar2(10) := 'all';             -- ALLは予約語です
BEGIN
    DBMS_OUTPUT.Put_LINE(Hello);       -- 二重引用符は省略可能です。省略した場合、大文字小文字を区別しません。
    DBMS_OUTPUT.Put_LINE("ALL");      -- 二重引用符は必須です。
end;
/
```

出力結果は次のとおりです：

```sql
hello
all
```

## テキスト

テキストの値は、識別子によって表現されるものでも、他の値から計算されるものでもありません。

例えば、119は整数テキストであり、'xyz'は文字テキストですが、`1+2`はテキストではありません。

PLテキストには、すべてのSQLテキストと`BOOLEAN`テキスト（SQLにはない）が含まれます。`BOOLEAN`テキストは、事前定義された論理値`TRUE`、`FALSE`、または`NULL`です。`NULL`は未知の値を表します。

PL文字テキストを使用する際には、以下の点に注意してください：

* 文字テキストは大文字小文字を区別します。例えば、「A」と「a」は異なります。

* スペース文字には意味があります。例えば、'abc'と'a b c'は異なります。

* PLには行続け文字がありません。「この文字列は次のソースコード行で続く」ということを示すために使用されます。次のソースコード行で文字列を続ける場合は、改行文字を使用する必要があります。連結演算子（\|\|）を使用して改行を回避することもできます。

```sql
obclient> BEGIN
  DBMS_OUTPUT.PUT_LINE('The string
                       breaks here.');
  DBMS_OUTPUT.PUT_LINE('The string ' ||
                       'contains no line-break character.');
END;
/
```

出力結果は次のとおりです：

```sql
The string
breaks here.
The string contains no line-break character.
```

* 「0」から「9」は、整数テキストの0から9とは等しくありません。PLはこれらを整数に変換するため、算術式で使用できます。

* 文字列の長さが0の文字テキストの値は`NULL`であり、空文字列と呼ばれます。ただし、この`NULL`値は`BOOLEAN`型の`NULL`値ではありません。

* 通常の文字テキストは、データベースの文字セットに含まれる文字で構成されます。

* 照会文字テキストは、照会文字セットに含まれる文字で構成されます。

## コンパイラ指示

コンパイラ指示は、コンパイラがコンパイル時に処理する指示です。

コンパイラ指示は、キーワード`PRAGMA`で始まり、その後に指示名が続きます。コンパイラ指示は宣言の中または宣言の前に記述できます。特定のコンパイラ指示には追加の制限が適用される場合もあります。一部のコンパイラ指示にはパラメータが含まれており、コンパイラが指示名やパラメータを認識できない場合、そのコンパイラ指示は無効になります。

PLがサポートするコンパイラ指示の種類は以下のとおりです：

| コンパイラ指示                | 意味                                                                                         |
|------------------------|--------------------------------------------------------------------------------------|
| `AUTONOMOUS_TRANSACTION` Pragma | 単独のサブプログラムを独立したトランザクション内で実行し、他のトランザクションから独立しており、他のセッションで行われている作業の影響を受けないことを示します。 |
| `COVERAGE` Pragma               | テストカバレッジを測定するために使用され、コンパイラにコードカバレッジの分析を指示します。                                    |
| `EXCEPTION_INIT` Pragma         | 例外にコードを割り当て、例外をその名前とコードで識別できるようにします。                               |
| `INLINE` Pragma                 | コンパイラに対し、関数呼び出しではなく、呼び出し箇所で関数をインライン展開するよう指示します。                                    |
| `RESTRICT_REFERENCES` Pragma    | 特定のユニット内のPL/SQLサブプログラムがテーブル、ビューなどのオブジェクトへの参照を制限します。                              |
| `SERIALLY_REUSABLE` Pragma      | パッケージの状態がサーバーの1回の呼び出し期間中のみ必要であることを示し、長時間実行されるセッションのメモリ消費を削減できます。                |
| `UDF` Pragma                    | コンパイラに対し、このPL/SQLユニットをユーザー定義関数としてコンパイルするよう指示します。                                |

### 例

**例1：`SERIALLY_REUSABLE` Pragmaの使用例**

```sql
CREATE PACKAGE pkg1 IS
   PRAGMA SERIALLY_REUSABLE;
   num NUMBER := 0;
   PROCEDURE init_pkg_state(n NUMBER);
   PROCEDURE print_pkg_state;
END pkg1;
/
CREATE PACKAGE BODY pkg1 IS
   PRAGMA SERIALLY_REUSABLE;
   PROCEDURE init_pkg_state (n NUMBER) IS
   BEGIN
      pkg1.num := n;
   END;
   PROCEDURE print_pkg_state IS
   BEGIN
      dbms_output.put_line('Num: ' || pkg1.num);
   END;
END pkg1;
/
DROP PACKAGE pkg1;
```

**例2：`AUTONOMOUS_TRANSACTION` Pragmaの使用例**

```sql
CREATE OR REPLACE PROCEDURE log_error(message VARCHAR2) IS
   PRAGMA AUTONOMOUS_TRANSACTION;
BEGIN
   INSERT INTO error_log (error_message, log_date) VALUES (message, SYSDATE);
   COMMIT;
END log_error;
```

**例3：`EXCEPTION_INIT` Pragmaの使用例**

```sql
DECLARE
   deadlock_detected EXCEPTION;
   PRAGMA EXCEPTION_INIT(DEADLOCK_detected, -60);
BEGIN
   -- デッドロック例外を発生させるコード
   -- ...
EXCEPTION
   WHEN deadlock_detected THEN
      DBMS_OUTPUT.PUT_LINE('A deadlock was detected.');
END;
```

**例4：`INLINE`プラグマを使用する例**

```sql
CREATE OR REPLACE FUNCTION add_numbers(a NUMBER, b NUMBER) RETURN NUMBER IS
   PRAGMA INLINE(add_numbers, 'YES');
BEGIN
   RETURN a + b;
END add_numbers;
```

## コメント

コメントの目的は、他のアプリケーション開発者がソースコードを理解できるようにすることです。PLコンパイラはコメントの内容を無視します。

通常、コメントは各コードセグメントの用途を説明するために使用されます。また、廃止されたり未完成のコードセグメントをコメントに変えて無効化することもできます。

### 1行コメント

1行コメントは `--` で始まり、その行の終わりまで続きます。

テストやデバッグ時に、コメントを使用して1行のコードを無効にすることができます。例：

```sql
-- INSERT INTO t1 VALUES(1, 1)
```

### 複数行コメント

複数行コメントは `/ *` で始まり、`* /` で終わり、複数行にまたがることができます。

複数行コメントのディマーターを使用してコードセグメントを「コメントアウト」することができます。ネストされた複数行コメントは使用しないでください。1つの複数行コメントの中に別の複数行コメントを含めることはできません。ただし、複数行コメントの中に1行コメントを含めることは可能です。

以下の例は構文エラーを引き起こします：

```sql
/*
  IF 1 + 2 = 3 THEN
    some_condition := TRUE;
  /* 必須
THEN
 ステートメントは常に実行されます*/
  END IF;
*/
```

## 語法的な空白文字

語法要素の間に空白文字を挿入することで、ソースコードを読みやすくすることができます。

以下の例を参照してください：

```sql
obclient> DECLARE
  a    NUMBER := 5;
  b    NUMBER := 1;
  max  NUMBER;
BEGIN
  IF a>b THEN max:=a;ELSE max:=b;END IF;  -- 構文は正しいが読みにくい

  -- 以下のステートメントの方が読みやすい:

  IF a > b THEN
    max:=a;
  ELSE
    max:=b;
  END IF;
END;
/
```
