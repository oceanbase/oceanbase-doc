## 区切り文字

区切り文字とは、PLにおいて特別な意味を持つ文字または文字の組み合わせです。区切り文字に他の文字（スペース文字を含む）を埋め込まないでください。

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>本記事で説明する区切り文字とOBClientの区切り文字は、意味が異なります。</p>
  </main>

| =\>  | 結合演算子         |
| %    | プロパティ指示子         |
| '    | 文字列境界符        |
| .    | 要素アクセス演算子         |
| \|\| | 接続演算子         |
| /    | 除算演算子         |
| \*\* | 幾何平均演算子         |
| (    | 式またはリストの開始境界符 |
| )    | 式またはリストの終了境界符 |

| \>\> | ラベルの終了境界符     |

## 識別子

識別子は、定数、カーソル、例外、キーワード、ラベル、パッケージ、予約語、サブプログラム、型、変数などのPL要素に名前を付けるために使用されます。

識別子内の各文字（アルファベットであるかどうかにかかわらず）は意味を持ちます。例えば、識別子 `firstname` と `first_name` は異なります。

隣接する識別子を区切るには、1つ以上のスペース文字または句読点を使用する必要があります。

二重引用符で囲まれていない限り、PL識別子は大文字小文字を区別しません。例えば、識別子 `firstname`、`FirstName`、`FIRSTNAME` は同じです。

### 予約キーワード

PL予約キーワードは、特別な意味を持つ識別子です。

予約キーワードを通常のユーザー定義識別子として使用することは推奨されません。PL予約キーワードのリストについては、付録[PL予約キーワード](../1500.pl-keywords-oracle.md)を参照してください。

### 事前定義済み識別子

事前定義済み識別子は、事前定義パッケージ `STANDARD` を使用して宣言します。

事前定義済み識別子のリストについては、[プログラムパッケージ STANDARD による PL 環境の定義](../900.package-oracle/500.package-standard-definition-of-pl-environment-oracle.md)を参照してください。

事前定義済み識別子をユーザー定義識別子として使用できますが、ローカルでの宣言がグローバルな宣言を上書きするため、この方法は推奨されません。

### ユーザー定義識別子

ユーザー定義識別子は、データベース文字セットの文字で構成される、通常のまたは引用される識別子です。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>ユーザー定義識別子は、その意味を直接表現できるようにする必要があります。例えば、<code>cost_per_employee</code> は文字通りの意味を解釈できますが、<code>cpe</code> はできません。</p>
  </main>

### 通常のユーザー定義識別子

ユーザーは識別子を定義できます。PLはユーザー定義識別子に対して以下の要件と制限を設けています：

* 最初の文字はアルファベットでなければなりません。

* アルファベット、数字、および正斜線（/）、アスタリスク（\*）、アンド記号（\&）、ドル記号（$）などを含むことができます。

* 長さは128文字を超えてはなりません。

* PL予約語をPL識別子として使用することはできません。

* PL識別子は大文字小文字を区別しません。

以下のユーザー定義識別子は有効です：

```sql
t8
telephone#
credit_limit
FirstName
OceanBase$number
money$$tree
SN##
try_again_
```

### 引用符識別子

引用符を伴うユーザー定義識別子は、二重引用符で囲まれます。

二重引用符の間では、データベース文字セットの任意の文字を使用できますが、二重引用符、改行文字、およびヌル文字は除きます。

以下の引用符識別子は有効です：

```sql
"X+Y"
"first name"
"on/off switch"
"department(s)"
"*** body info ***"
```

引用符を伴うユーザー定義識別子は大文字小文字を区別します。ただし、引用符を伴うユーザー定義識別子（二重引用符なし）が有効な通常のユーザー定義識別子である場合、その識別子が参照される際の二重引用符はオプションです。省略した場合、識別子は大文字小文字を区別しません。

予約語を引用符を伴うユーザー定義識別子として使用できますが、この方法は推奨されません。予約語は有効な通常のユーザー定義識別子ではないため、識別子は常に二重引用符で囲む必要があり、大文字小文字を区別する必要があります。

```sql
obclient> DECLARE
    "HELLO" varchar2(10) := 'hello';    -- HELLOはユーザー定義識別子
    "ALL" varchar2(10) := 'all';             -- ALLは予約語
BEGIN
    DBMS_OUTPUT.Put_Line(Hello);       -- 二重引用符を省略できます。省略した場合、大文字小文字を区別しません。
    DBMS_OUTPUT.Put_LINE("ALL");      -- 二重引用符の使用が必須です。
end;
/
```

出力結果は次のとおりです：

```sql
hello
all
```

## テキスト

テキストの値は、識別子によって表されるものでも他の値から計算されるものでもありません。

例えば、119は整数テキストであり、'xyz'は文字テキストですが、`1+2`はテキストではありません。

PLテキストには、すべてのSQLテキストと`BOOLEAN`テキストが含まれます（SQLには含まれません）。`BOOLEAN`テキストは、事前定義された論理値`TRUE`、`FALSE`、または`NULL`です。`NULL`は未知の値を表します。

PL文字テキストを使用する際は、以下の点に注意してください：

* 文字テキストは大文字と小文字を区別します。例えば、「A」と「a」は異なります。

* スペース文字には意味があります。例えば、'abc'と'a b c'は異なります。

* PLには行続き文字がありません。これは「この文字列は次のソースコード行で続く」ということを示すために使用されます。次のソースコード行で文字列を続ける場合は、改行文字を使用する必要があります。連結演算子（\|\|）を使用して改行を回避することもできます。

```sql
obclient> BEGIN
  DBMS_OUTPUT.PUT_LINE('The string
                       breaks here.');
  DBMS_OUTPUT.PUT_LINE('The string ' ||
                       'contains no line-break character.');
END;
/
```

出力結果は次のとおりです：

```sql
The string
breaks here.
The string contains no line-break character.
```

* 「0」から「9」は整数テキストの0から9とは等しくありません。PLはこれらを整数に変換するため、算術式で使用できます。

* 文字数がゼロの文字テキストの値は`NULL`であり、空文字と呼ばれます。ただし、この`NULL`値は`BOOLEAN`の`NULL`値ではありません。

* 通常の文字テキストは、データベースの文字セットから構成されます。

* 国家文字テキストは、国家文字セットから構成されます。

## コンパイル指示

コンパイル指示とは、コンパイラがコンパイル時に処理する指示です。

コンパイル指示は、キーワード `PRAGMA` で始まり、その後に指示名が続きます。コンパイル指示は宣言の中または宣言の前に記述することができます。特定のコンパイル指示には追加の制限もあります。一部のコンパイル指示にはパラメータが含まれており、コンパイラが指示名やパラメータを認識できない場合、そのコンパイル指示は無効になります。

PLがサポートするコンパイル指示の種類は以下のとおりです：

| コンパイル指示                | 意味                                                                                         |
|------------------------|--------------------------------------------------------------------------------------|
| `AUTONOMOUS_TRANSACTION` Pragma | 独立したトランザクション内でこの単独のサブプログラムを実行し、他のトランザクションと相互に独立しており、他のセッションで行われている作業の影響を受けないことを示します。 |
| `COVERAGE` Pragma               | テストカバレッジを測定するために使用され、コンパイラにコードカバレッジの分析を指示します。                                    |
| `EXCEPTION_INIT` Pragma         | 例外にコードを割り当て、例外をその名前とコードで識別できるようにします。                               |
| `INLINE` Pragma                 | コンパイラに対し、関数呼び出しではなく、呼び出し箇所で関数をインライン展開するよう指示します。                                    |
| `RESTRICT_REFERENCES` Pragma    | 特定ユニット内のPL/SQLサブプログラムがテーブル、ビューなどのオブジェクトへの参照を制限します。                              |
| `SERIALLY_REUSABLE` Pragma      | パッケージの状態はサーバーの1回の呼び出し期間中のみ必要であることを示し、長時間実行されるセッションのメモリオーバーヘッドを削減できます。                |
| `UDF` Pragma                    | コンパイラに対し、このPL/SQLユニットをユーザー定義関数としてコンパイルするよう指示します。                                |

### 例

**例1：`SERIALLY_REUSABLE`プラグマの使用例**

```sql
CREATE PACKAGE pkg1 IS
   PRAGMA SERIALLY_REUSABLE;
   num NUMBER := 0;
   PROCEDURE init_pkg_state(n NUMBER);
   PROCEDURE print_pkg_state;
END pkg1;
/
CREATE PACKAGE BODY pkg1 IS
   PRAGMA SERIALLY_REUSABLE;
   PROCEDURE init_pkg_state (n NUMBER) IS
   BEGIN
      pkg1.num := n;
   END;
   PROCEDURE print_pkg_state IS
   BEGIN
      dbms_output.put_line('Num: ' || pkg1.num);
   END;
END pkg1;
/
DROP PACKAGE pkg1;
```

**例2：`AUTONOMOUS_TRANSACTION`プラグマの使用例**

```sql
CREATE OR REPLACE PROCEDURE log_error(message VARCHAR2) IS
   PRAGMA AUTONOMOUS_TRANSACTION;
BEGIN
   INSERT INTO error_log (error_message, log_date) VALUES (message, SYSDATE);
   COMMIT;
END log_error;
```

**例3：`EXCEPTION_INIT`プラグマの使用例**

```sql
DECLARE
   deadlock_detected EXCEPTION;
   PRAGMA EXCEPTION_INIT(DEADLOCK_detected, -60);
BEGIN
   -- デッドロック例外を発生させるコード
   -- ...
EXCEPTION
   WHEN deadlock_detected THEN
      DBMS_OUTPUT.PUT_LINE('A deadlock was detected.');
END;
```

**例4：`INLINE`プラグマの使用例**

```sql
CREATE OR REPLACE FUNCTION add_numbers(a NUMBER, b NUMBER) RETURN NUMBER IS
   PRAGMA INLINE(add_numbers, 'YES');
BEGIN
   RETURN a + b;
END add_numbers;
```

## コメント

コメントの目的は、他のアプリケーション開発者がソースコードを理解できるようにすることです。PLコンパイラはコメントの内容を無視します。

通常、コメントは各コードセグメントの用途を説明するために使用されます。また、廃止されたり未完成のコードセグメントをコメントに変えて無効化することもできます。

### 1行コメント

1行コメントは `--` で始まり、その行の終わりまで続きます。

テストやデバッグ時に、コメントを使用して1行のコードを無効にすることができます。例：

```sql
-- INSERT INTO t1 VALUES(1, 1)
```

### 複数行コメント

複数行コメントは `/ *` で始まり、`* /` で終わり、複数行にまたがることができます。

複数行コメントのディマーターを使用してコードセグメントを「コメントアウト」できます。ネストされた複数行コメントは使用しないでください。1つの複数行コメントに別の複数行コメントを含めることはできません。ただし、複数行コメントには1行コメントを含めることができます。

以下の例は構文エラーを引き起こします：

```sql
/*
  IF 1 + 2 = 3 THEN
    some_condition := TRUE;
  /* 必須
THEN
 ステートメントは常に実行される*/
  END IF;
*/
```

## 語法間の空白文字

語法要素の間に空白文字を挿入することで、ソーステキストをより読みやすくすることができます。

以下の例を参照してください：

```sql
obclient> DECLARE
  a    NUMBER := 5;
  b    NUMBER := 1;
  max  NUMBER;
BEGIN
  IF a>b THEN max:=a;ELSE max:=b;END IF;  -- 構文は正しいが読みにくい

  -- 以下の文の方が読みやすい：

  IF a > b THEN
    max:=a;
  ELSE
    max:=b;
  END IF;
END;
/
```
