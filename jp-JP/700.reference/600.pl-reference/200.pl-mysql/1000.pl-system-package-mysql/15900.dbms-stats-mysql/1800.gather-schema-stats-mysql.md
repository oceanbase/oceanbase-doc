# GATHER_SCHEMA_STATS

`GATHER_SCHEMA_STATS` プロシージャは、指定されたスキーマ内のすべてのオブジェクトの統計情報を収集するために使用されます。

## 構文

```sql
DBMS_STATS.GATHER_SCHEMA_STATS (
  ownname            VARCHAR2,
  estimate_percent   NUMBER DEFAULT AUTO_SAMPLE_SIZE,
  block_sample       BOOLEAN DEFAULT FALSE,
  method_opt         VARCHAR2 DEFAULT DEFAULT_METHOD_OPT,
  degree             NUMBER DEFAULT NULL,
  granularity        VARCHAR2 DEFAULT DEFAULT_GRANULARITY,
  cascade            BOOLEAN DEFAULT NULL,
  no_invalidate      BOOLEAN DEFAULT FALSE,
  stattype           VARCHAR2 DEFAULT 'DATA',
  force              BOOLEAN DEFAULT FALSE);
```

## パラメータ説明

|        パラメータ       |      説明    |
|------------------|--------------|
| ownname          | テーブルが存在するスキーマ。  |
| estimate_percent | 行数の推定値の割合。有効範囲は \[0.000001,100\]。  |
| block_sample     | データベースがランダムブロックサンプリング (`TRUE`) を使用するか、ランダム行サンプリング (`FALSE`) を使用するかを指定します。デフォルト値は `FALSE` です。ランダムブロックサンプリングの方が効率的ですが、データがディスク上にランダムに分散していない場合、サンプル値に相関が生じる可能性があります。     |
| method_opt       | グローバル、スキーマ、データベース、またはディクショナリレベルで設定を行う場合は、`FOR ALL` 構文のみを使用できます。それ以外の場合、`method_opt` は以下のオプションのいずれか、またはその組み合わせのみとなります： <ul><li> `FOR ALL [INDEXED | HIDDEN] COLUMNS [size_clause]`   </li>   <li> `FOR COLUMNS [column_clause]`    ここで、`size_clause` は `size_clause := SIZE {integer | REPEAT | AUTO | SKEWONLY}` と定義されます。 `column_clause` は `column_clause := column_name | extension name | extension` と定義されます。 </li>   <li> `integer`：ヒストグラムのバケット数。有効範囲は \[1,2048\]。   </li>   <li> `REPEAT`：既存のヒストグラムを持つ列に対してのみヒストグラムを収集します。   </li>   <li> `AUTO`：データの分布と列のワークロードに基づいて、ヒストグラムを収集する列を決定します。   </li>   <li> `SKEWONLY`：列のデータ分布に基づいて、ヒストグラムを収集する列を決定します。   </li>   <li>`column_name`：列名。   </li>   <li> `extension`：`(column_name, colume_name [, ...])` 形式の列のグループまたは式を指定できます。 </li>   </ul>   デフォルト値は `FOR ALL COLUMNS SIZE AUTO` です。 |
| degree           | パラレル度。デフォルト値は `NULL` です。`NULL` は `CREATE TABLE` または `ALTER TABLE` ステートメントの `DEGREE` 句で指定されたテーブルのデフォルト値を使用することを意味します。`DEGREE=>NULL`、`DEGREE=>n` を使用する場合、オブジェクトのサイズがパラレル実行を保証しない場合、`DBMS_STATS` はシリアル実行を使用する可能性があります。  |
| granularity      | 収集する統計情報の粒度（テーブルがパーティション化されている場合にのみ適用されます）。 <ul><li> `ALL`：すべての（サブパーティション、パーティション、グローバル）統計情報を収集します。    </li>   <li> `APPROX_GLOBAL AND PARTITION`： `GLOBAL AND PARTITION` と同様ですが、この場合、グローバル統計情報はパーティションレベルの統計情報の集計です。このオプションは、異なる値の数と異なるキーを持つインデックスの数以外のすべての統計情報を集計します。ただし、統計情報を持つパーティションのみを集計します。`partname` が `NULL` であるか、集計が実行できない場合（例えば、いずれかのパーティションの統計情報が欠けている場合）、グローバル統計情報が収集されます。    </li>   <li> `AUTO`：パーティションタイプに基づいて粒度を決定します。デフォルト値です。    </li>   <li> `DEFAULT`：グローバルおよびパーティションレベルの統計情報を収集します。このオプションは廃止されており、`GLOBAL AND PARTITION` の使用を推奨します。    </li>   <li> `GLOBAL`：グローバル統計情報を収集します。    </li>   <li> `GLOBAL AND PARTITION`：グローバルおよびパーティションレベルの統計情報を収集します。複合パーティションオブジェクトであっても、サブパーティションレベルの統計情報は収集されません。    </li>   <li> `PARTITION`：パーティションレベルの統計情報を収集します。    </li>   <li> `SUBPARTITION`：サブパーティションレベルの統計情報を収集します。    |
| cascade          | テーブルと列の統計情報を収集するだけでなく、インデックスに関する統計情報も収集します。これは、スキーマ内の各インデックスに対して `GATHER_INDEX_STATS` プロシージャを実行したことに相当します。 |
| no_invalidate | 統計情報を収集する際にプランキャッシュをフラッシュするかどうかを指定します。`TRUE` に設定すると、統計情報を収集する際にプランキャッシュをフラッシュしません。|
| stattype         | 現在の統計情報が格納されている場所。  |
| force            | 統計情報の収集を強制し、ロックの状態を無視するかどうかを指定します。デフォルトは `FALSE` です。`TRUE` に設定すると、統計情報がロックされていても収集されます。     |

## 例外

|    エラーコード    |         説明         |
|-----------|--------------------|
| HY000     |  <ul><li>該当スキーマが存在しない、または権限が不足しています。</li><li>入力値が誤っています。</li></ul>     |

## 使用方法

このプロシージャを呼び出すには、テーブル所有者である必要があります。`SYS` が所有するオブジェクトを使用する場合は、テーブル所有者または `SYSDBA` 権限が必要です。

## 例

`hr` スキーマ下のすべてのテーブルの統計情報を収集します。

```sql
obclient> CALL DBMS_STATS.GATHER_SCHEMA_STATS ('hr', degree=>64,no_invalidate=>TRUE);
Query OK, 0 rows affected
```
