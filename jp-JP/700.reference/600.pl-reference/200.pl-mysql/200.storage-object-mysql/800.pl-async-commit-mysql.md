# PL非同期コミットの最適化

OceanBaseデータベースでは、ストアドプロシージャ(Stored Procedure)は業務ロジックを実装するための重要な仕組みです。現在の実装では、ストアドプロシージャ内のトランザクションコミットは同期方式を採用しており、ワーカースレッドがトランザクションコミットインターフェースを呼び出した後、トランザクションのコミットが完了するまでブロックされます。極端な場合を除き、ローカルトランザクションのコミット時間はほとんどの場合マイクロ秒単位で、分散トランザクションはミリ秒単位です（主にネットワーク通信遅延）。そのため、分散トランザクションが発生すると、PL全体の遅延が大幅に増加し、スループットも大幅に低下します。この問題を緩和してPLのパフォーマンスをさらに向上させるため、V4.4.2バージョンではPL非同期コミットの最適化がサポートされています。

## PL非同期コミットの最適化を有効にする

`ob_enable_pl_async_commit` システム変数を使用して、この最適化を有効にするかどうかを制御します。
システムのスループットまたはTPSがビジネス要件を満たせない場合、`ob_enable_pl_async_commit` を有効にして、PL非同期コミットの最適化を試すことができます。ほとんどのコミットシナリオで一定のパフォーマンス向上が見られ、高同時実行環境ではシステムのスループットが大幅に向上します。

## ストアドプロシージャでASYNC_COMMITを宣言する

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>ストアドプロシージャの <code>ASYNC_COMMIT</code> 機能は、V4.4.2 BP3バージョンからサポートされています。</p>
</main>

MySQLモードでは、ストアドプロシージャまたはストアドファンクションを作成する際、パラメータリストの後、プロシージャ本体（または関数本体）の前に `ASYNC_COMMIT` 特性を宣言できます。これにより、そのオブジェクトが非同期コミットシナリオ向けであることを示します。この特性は対象を識別するための宣言であり、`SHOW CREATE PROCEDURE` の出力には反映されません。実際に非同期コミットを有効にするかどうかは、引き続きシステム変数 `ob_enable_pl_async_commit` によって制御されます。

### 構文

```sql
CREATE PROCEDURE sp_name ([proc_parameter[,...]]) ASYNC_COMMIT
    routine_body
```

### 例

```sql
DELIMITER $$
CREATE PROCEDURE proc_async_commit() ASYNC_COMMIT
BEGIN
    INSERT INTO t1 VALUES(1);
    COMMIT;
END $$
DELIMITER ;
```

## 使用例

1. テストテーブルを作成します。

    ```shell
    obclient> CREATE TABLE test1(a int);
    ```

2. ストアドプロシージャ `test` を作成します。

    ```shell
    obclient> DELIMITER $$
    CREATE PROCEDURE test()
    BEGIN
    DECLARE counter INT DEFAULT 1;
    WHILE counter <= 1000 DO
        INSERT INTO t0 (a) VALUES (counter);
        commit;
        SET counter = counter + 1;
    END WHILE;
    END $$

    DELIMITER ;
    ```

3. パフォーマンス比較テストを実行します。

    * PL非同期コミットの最適化を有効にします。

        ```shell
        obclient> SET ob_enable_pl_async_commit=ON;
        obclient> call test();
        Query OK, 0 rows affected (5.376 sec)
        obclient> call test();
        Query OK, 0 rows affected (5.122 sec)
        obclient> call test();
        Query OK, 0 rows affected (5.131 sec)
        obclient> call test();
        Query OK, 0 rows affected (5.117 sec)
        obclient> call test();
        Query OK, 0 rows affected (4.946 sec)
        ```

    * PL非同期コミットの最適化を無効にします。

       ```shell
       obclient> SET ob_enable_pl_async_commit=OFF;
       obclient> call test();
        Query OK, 0 rows affected (5.489 sec)
        obclient> call test();
        Query OK, 0 rows affected (5.484 sec)
        obclient> call test();
        Query OK, 0 rows affected (5.481 sec)
        obclient> call test();
        Query OK, 0 rows affected (5.440 sec)
        obclient> call test();
        Query OK, 0 rows affected (5.501 sec)
       ```

    データベーステーブルに1000件のデータをループ挿入し、データを挿入するたびに即座にトランザクションをコミットします。最適化を有効にした場合の平均所要時間は `5.1384s` です。最適化を無効にした場合の平均所要時間は `5.479s` です。パフォーマンスは約6%向上します。1回のトランザクションで処理するデータが多いほど、トランザクションが大きくなり、コミットにかかる時間が長くなります。その結果、SQLとの並列処理の効果が高まり、パフォーマンス向上も大きくなります。
