# OBProxyクラスタの作成

通常、OceanBaseデータベースをデプロイする際には既にOBProxyクラスタが作成されています。新しいOBProxyを複数追加してOceanBaseクラスタに接続する必要がある場合は、OCPを使用してOBProxyクラスタを作成できます。

## 前提条件

現在ログインしているユーザーがOBPROXY_MANAGERロールを持ち、OBProxyを管理する権限が付与されていること。現在のユーザーがOBPROXY_MANAGERロールを持っていない場合は、まずそのユーザーにこのロールを追加する必要があります。具体的な操作については、《OCPユーザーガイド》の[ユーザーの編集](https://en.oceanbase.com/docs/enterprise-oceanbase-ocp-en-10000000000838749)を参照してください。

## 手順

1. OCPにログインします。

2. 左側のナビゲーションバーで**OBProxy**をクリックし、OBProxyページに移動します。

3. 右上の**OBProxyクラスタの作成**をクリックします。

4. **OBProxyクラスタの作成**ページで、以下の情報を入力します：

   1. 次の表を参考に、**<UI-TERM key="oms-cloud.Migration.Detail.BasicInformation">基本情報</UI-TERM>**を設定します。

      | パラメータ                   | 説明                                                                                                                      |
      |------------------------|---------------------------------------------------------------------------------------------------------------------------|
      | クラスタ名                  | 実際のビジネス状況に応じて、英字で始まり、英字、数字、アンダースコアを含むクラスタ名をカスタマイズできます。                                                 |
      | Proxyroアカウントのパスワードを入力 | ProxyroアカウントはOBProxyがOBクラスタにアクセスするために使用されます。入力しない場合は、Proxyroアカウントのデフォルトパスワードを使用して接続します。パスワードの形式要件は以下のとおりです：<ul><li>長さは8～32文字です。</li><li>英字、数字、特殊文字`~!@#%^&*_-+=|(){}[]:;,.?/`のみを含むことができます。</li><li>大文字、小文字、数字、特殊文字をそれぞれ2つ以上含む必要があります。 </li></ul> |
      | ロードバランシング管理             | ロードバランシング管理を有効にすると、OBLBを設定することでOBProxyクラスタのロードバランシング機能を向上させることができます。<ul><li>OBLBサービス：OCPのデプロイ時に既に設定されているOBLBサービスを選択するか、**<UI-TERM key="ocp-v2.Component.LBLoadBalanceConditon.AddOblbService">OBLBサービスを追加する</UI-TERM>**ボタンをクリックして、右側のパネルで新しいOBLBサービスを作成します。<ul><li>OBLBサービスのアドレス：OBLBのサービスアドレス。</li><li>OBLBサービスのポート：デフォルトは9090ですが、実際の状況に応じて変更できます。</li><li>ユーザー名とパスワード：OBLBサービスのユーザー名とパスワードで、OBLBインターフェースを呼び出す認証情報として使用されます。</li></ul></li><li>VIP：OBLBの具体的なVIPアドレスを選択します。</li><li>アクセスポート：デフォルトは2883で、カスタムポート番号をサポートしています。</li><li>ドメイン設定（オプション）：VIPとポートを指すための設定情報です。プラットフォームはVIPとドメインのマッピング関係を提供していないため、独自にDNSサービスを準備する必要があります。</li></ul><main id="notice" type='explain'><h4>説明</h4><p><b>ロードバランシング管理</b>の<b>SLBサービス</b>は専用クラウド環境でのみ適用されます。技術サポートに連絡し、協力を依頼することを推奨します。</p></main>|
      | アクセスアドレス       | **<UI-TERM key="ocp-v2.OBProxy.New.LoadBalancingManagement">負荷分散管理</UI-TERM>**が無効の場合に表示されます。OBProxyクラスタのアクセスアドレスであり、テナントの接続文字列の生成にのみ使用され、実際の使用には影響しません。ロードバランシングは自ら設定する必要があります。VIPアドレスの場合は、ご自身で申請し、OBProxy Serverにバインドする必要があります。  |
      | アクセスポート       | **<UI-TERM key="ocp-v2.OBProxy.New.LoadBalancingManagement">負荷分散管理</UI-TERM>**が無効の場合に表示されます。デフォルトは2883ですが、VIPの実際のポートに応じて入力する必要があります。  |
      | 起動方式       | このOBProxyクラスタの起動方式です。取り得る値：<ul><li> ConfigUrl：複数クラスタ起動方式です。このOBProxyクラスタは複数のOceanBaseクラスタにアクセスできます。   </li><li> RsList：単一クラスタ起動方式です。このOBProxyクラスタは、OBProxyクラスタ作成時に指定した1つのOceanBaseクラスタにのみアクセスできます。OBProxyクラスタ作成後に接続可能なOBクラスタを追加することはできません。</li> </ul>    |
      | 接続可能なOceanBaseクラスタの選択 | このOBProxyクラスタがアクセス可能なOceanBaseクラスタを設定します。 <ul><li> **<UI-TERM key="ocp-v2.Detail.TakeOver.StartupMode">起動方法</UI-TERM>**がConfigUrlに設定されている場合、このパラメータは必須ではありません。クラスタ作成後、[接続可能なOceanBaseクラスタの追加](../200.manage-obproxy-clusters/600.manage-ob-cluster-in-obproxy.md)から追加できます。   </li><li> **<UI-TERM key="ocp-v2.OBProxy.New.StartupMode">起動方法</UI-TERM>**がRsListに設定されている場合、このパラメータは必須です。ドロップダウンリストから対応するクラスタを選択します。 </li><li> パスワードボックスにそのクラスタのproxyroユーザーの接続資格情報が存在する場合、proxyroユーザーがデフォルトで選択されます。   </li><li>パスワードボックスにそのクラスタのproxyroユーザーの接続資格情報が存在しない場合、**<UI-TERM key="odc.components.RecordPage.CreateConnection">新規接続</UI-TERM>**をクリックして、そのクラスタのproxyroユーザーのための接続資格情報を作成してください。 </li> </ul>   |

      <!-- ![08261923](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.1.0/user-guide/odp-management/create-odp-cluster-basic-information.png) -->

   2. （オプション）**<UI-TERM key="ocp-v2.OBProxy.New.DeploymentObproxy">OBProxyをデプロイする</UI-TERM>**を設定します。

      OBProxyクラスタの作成時にOBProxyをデプロイする必要がある場合は、この手順で設定できます。そうでない場合はこの手順をスキップし、クラスタ作成後にOBProxyの乗っ取りまたは追加によってクラスタにOBProxyを追加することができます。

      1. **<UI-TERM key="ocp-v2.OBProxy.New.DeploymentObproxy">OBProxyをデプロイする</UI-TERM>**のスイッチをオンにします。

      2. 次の表を参考にデプロイメント情報を入力します。

         | パラメータ             |    説明                                                      |
         |-----------------|--------------------------------------------------------------|
         | SQLポート        | デフォルトは2883です。                                                 |
         | Exporterポート   | デフォルトは2884です。                                                 |
         | ソフトウェアバージョン        | インストールするOBProxyのバージョンを選択します。<main id="notice" type='explain'><h4>説明</h4><p><b>接続可能なOBクラスタ</b>にV4.0以上のバージョンのクラスタが存在する場合、V4.0.0以上のバージョンのOBProxyソフトウェアパッケージのみを選択できます。</p></main>|
         | **<UI-TERM key="ocp-v2.Cluster.Import.OBServerTable.ComputerRoom">データセンター</UI-TERM>**、**機種（オプション）**、**<UI-TERM key="ocp-v2.component.alarm.AlarmTargetLabel.Host">ホスト</UI-TERM>** | OBProxyのデプロイに使用するホストを選択します。ホストの**<UI-TERM key="ocp-v2.Cluster.Import.OBServerTable.ComputerRoom">データセンター</UI-TERM>**、**機種（オプション）**、**<UI-TERM key="ocp-v2.Monitor.AddMonitor.CollectTable.Host">ホスト</UI-TERM>**も含まれます。 |

         <!-- ![08261945](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.1.0/user-guide/odp-management/depoly-odp.png) -->

         システムはデフォルトで2つのホストの選択を表示しており、これは2つのOBProxyをデプロイするのに十分です。

         * より多くをデプロイする場合は、**<UI-TERM key="ocp-v2.page.OBProxy.AddObproxy">OBProxyを追加する</UI-TERM>**をクリックしてホストを追加できます。

         * 1つのOBProxyのみをデプロイする場合は、上図のようにホストの後ろの削除アイコンをクリックしてそのホストを削除できます。

   3. **<UI-TERM key="ocp-v2.Component.AddOBServerDrawer.ParameterSettings">パラメータ設定</UI-TERM>** を開き、起動パラメータを追加または変更します。パラメータの説明については、[OBProxy パラメータ説明](../400.odp-cluster-parameters.md)を参照してください。

      <!-- ![4](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.1.0/user-guide/odp-management/set-parameters.png) -->

5. **<UI-TERM key="ocp-v2.Oracle.Component.RoleSelect.Submitted">提出する</UI-TERM>** をクリックし、OBProxy クラスタの作成を開始します。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>obproxy をインストールする際、システムは関連するインストールディレクトリの権限が正しいかどうかをチェックします。現在、<code>/home/admin/logs/obproxy</code> ディレクトリおよびその親ディレクトリに対して、指定されたユーザー（デフォルトは admin）が読み取り権限と実行権限を持っているかどうかを再帰的にチェックできます。権限がない場合、ログに「check directory xxx permission failed, reason: xxx」というエラーが報告されます。</p>
   </main>
