# フォロアー優先読み取り

ODPはフォロアー優先読み取りのルーティングポリシーをサポートしており、ユーザー変数`proxy_route_policy`でこのルーティングを設定します。フォロアー優先読み取りは弱い整合性読み取り時にのみ有効となり、リーダーとフォロアーの均等な選択ではなく、常にフォロアーから優先的に読み取ります。

OceanBaseデータベースがサポートするクライアントツールでクラスタの業務テナントにログインした後、以下のステートメントを実行してセッション変数`proxy_route_policy`を設定します：

```sql
obclient> SET @proxy_route_policy='[policy]';
```

パラメータ`[policy]`の取り得る値は3つあります：

1. 値が`follower_first`の場合、ルーティングロジックはフォロアーを優先します（クラスタがメジャーコンパクション中であっても）。優先順位は以下のとおりです：

   同一データセンター内でメジャーコンパクション中でないフォロアー --\> 同一都市内の異なるデータセンターでメジャーコンパクション中でないフォロアー --\> 同一データセンター内でメジャーコンパクション中のフォロアー --\> 同一都市内の異なるデータセンターでメジャーコンパクション中のフォロアー --\> 同一データセンター内でメジャーコンパクション中でないリーダー --\> 同一都市内の異なるデータセンターでメジャーコンパクション中でないリーダー --\> 異なる都市でメジャーコンパクション中でないフォロアー --\> 異なる都市でメジャーコンパクション中のフォロアー --\> 異なる都市でメジャーコンパクション中でないリーダー --\> 異なる都市でメジャーコンパクション中のリーダー

2. 値が`unmerge_follower_first`の場合、ルーティングロジックはメジャーコンパクション中でないフォロアーノードを優先します。優先順位は以下のとおりです：

   同一データセンター内でメジャーコンパクション中でないフォロアー --\> 同一都市内の異なるデータセンターでメジャーコンパクション中でないフォロアー --\> 同一データセンター内でメジャーコンパクション中でないリーダー --\> 同一都市内の異なるデータセンターでメジャーコンパクション中でないリーダー --\> 同一データセンター内でメジャーコンパクション中のフォロアー --\> 同一都市内の異なるデータセンターでメジャーコンパクション中のフォロアー --\> 異なる都市でメジャーコンパクション中でないフォロアー --\> 異なる都市でメジャーコンパクション中でないリーダー --\> 異なる都市でメジャーコンパクション中のフォロアー --\> 異なる都市でメジャーコンパクション中のリーダー

3. その他の値を指定した場合、通常の弱い整合性読み取りでのリーダーとフォロアーの均等なルーティングロジックに戻ります。優先順位は以下のとおりです：

   同一データセンター内でメジャーコンパクション中でないリーダーまたはフォロアー --\> 同一都市内の異なるデータセンターでメジャーコンパクション中でないリーダーまたはフォロアー --\> 同一データセンター内でメジャーコンパクション中のリーダーまたはフォロアー --\> 同一都市内の異なるデータセンターでメジャーコンパクション中のリーダーまたはフォロアー --\> 異なる都市でメジャーコンパクション中でないリーダーまたはフォロアー --\> 異なる都市でメジャーコンパクション中のリーダーまたはフォロアー
