# LDCルーティング

ロジカルデータセンター(Logical Data Center、LDC)ルーティングは、分散リレーショナルデータベースを複数の地域および複数のデータセンターに展開する際に発生するリモートルーティングの遅延問題を解決するために使用できます。

OceanBaseデータベースは、典型的な高可用性分散リレーショナルデータベースとして、Paxosプロトコルを使用してログ同期を行い、自然に複数の地域および複数のデータセンターへの展開方式をサポートしており、高い信頼性の災害復旧保証を提供します。しかし、実際に複数の地域および複数のデータセンターに展開する場合、どのデータベースもリモートルーティングの遅延問題に直面します。

ロジカルデータセンター(Logical Data Center、LDC)ルーティングは、この問題を解決するために設計されました。OceanBaseクラスタの各ゾーンにRegion属性とIDC属性を設定し、ODPにIDC名構成パラメータを指定した後、データリクエストがODPに送信されると、ODPは以下の優先順位でルーティング転送を行います：

1. 本データセンターでコンパクション中でないレプリカを選択します。

2. 同じリージョン内のデータセンターでコンパクション中でないレプリカを選択します。

3. 本データセンターでコンパクション中のレプリカを選択します。

4. 同じリージョン内のデータセンターでコンパクション中のレプリカを選択します。

5. ローカルリージョン以外のデータセンターでコンパクション中でないレプリカをランダムに選択します。

6. ローカルリージョン以外のデータセンターでコンパクション中のレプリカをランダムに選択します。

LDCルーティングの設定には、以下の3つの手順が必要です：

1. OceanBaseクラスタのLDC設定。

2. ODPのLDC設定。

3. アプリケーションで弱い一貫性読み取りを設定します。

   <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>LDCが設定されていない場合、OceanBaseデータベースを複数の地域および複数のデータセンターに展開すると、弱い一貫性読み取りはデータのすべてのプライマリおよびフォロワーレプリカに均等にアクセスし、ローカルリージョン以外のデータセンター上のレプリカにアクセスすると、システムの応答時間が大幅に増加します。</p>
   </main>

## OceanBaseクラスタのLDC設定

1. OceanBaseデータベースがサポートするクライアントツールを使用して、rootユーザーでクラスタのsysテナントにログインします。

2. ログイン後、以下のサンプルステートメントを実行してLDCを設定します。

   ```sql
   obclient> ALTER SYSTEM MODIFY zone "z1" SET region = "SHANGHAI";

   obclient> ALTER SYSTEM MODIFY zone "z1" SET idc = "zue";
   ```

   ここで：

   * パラメータ`region`はゾーンが属するリージョン情報を表し、通常は都市名（大文字と小文字が区別されます）に設定されます。

   * パラメータ`idc`はそのゾーンが位置するIDC情報を表し、通常はIDC名（小文字）に設定されます。

   * パラメータ`zone`は現在設定されているゾーンの名前です。

   * 1つのOceanBaseクラスタには複数のリージョンがあり、1つのリージョンには複数のゾーンがあり、1つのゾーンは1つのIDC属性に対応します。

3. OBServerノードのLDC設定が有効になっているかどうかを確認します。

   クエリステートメントは以下のとおりで、返された結果の該当するゾーンのRegionとIDCフィールドの値が設定値と一致するかどうかを確認します。

   ```sql
   obclient> SELECT * FROM oceanbase.DBA_OB_ZONES;
   ```

## ODPのLDC設定

ODPのLDC設定には2つの方法があります。ここでは、zueをサンプルIDCとして説明します：

* ODPプロセス起動時にパラメータ指定による設定（推奨される方法）、サンプルステートメントは以下のとおりです。

  ```shell
  cd /opt/taobao/install/obproxy-1.5.5
  ./bin/obproxy -o proxy_idc_name=zue
  ```

* OceanBaseデータベースがサポートするクライアントツールで`ALTER`ステートメントを実行してODP構成パラメータを変更します。サンプルステートメントは以下のとおりです。

  ```sql
  obclient> ALTER PROXYCONFIG SET proxy_idc_name= 'zue';
  ```

上記のサンプルでzue IDCを例にとると、ODPにLDCを設定した後、アプリケーションが上海zue IDCにデプロイされている場合、アプリケーションロジックが弱い整合性読み取りを開始すると、リクエストは優先的に上海IDCに送信されます。

ODPにLDCを設定した後、以下のステートメントを使用して設定が有効になっているかどうかを確認できます。

```sql
obclient> SHOW PROXYINFO IDC;
```

## アプリケーションの弱い整合性読み取りの設定

LDCルーティングは、弱い整合性読み取りのシナリオに対してのみ有効になります。アプリケーションの弱い整合性読み取りを設定するには、以下の3つの方法があります：

* SQLにHINTを含めて指定します。サンプルステートメントは以下のとおりです。

  ```sql
  obclient> SELECT /*+read_consistency(weak)*/ * FROM t1;
  ```

* Sessionレベルのシステム変数を設定して指定します（現在のSessionにのみ有効）。サンプルステートメントは以下のとおりです。

  ```sql
  obclient> SET @@ob_read_consistency='weak';
  ```

* グローバルレベルのシステム変数を設定して指定します（そのテナントのすべての接続に有効）。サンプルステートメントは以下のとおりです。

  ```sql
  obclient> SET @@global.ob_read_consistency='weak';
  ```
