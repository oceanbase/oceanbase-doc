# 9000 ～ 9499

この範囲は、バックアップ・リストアのエラーコードおよびSTORAGE 3.0のエラーコードを表します。

## ERROR 9001 (HY000) : URI error

* OceanBase エラーコード：9001

* エラー原因：バックアップ・リストア設定の宛先リンクが誤っている可能性があります。

* 解決策：バックアップ・リストアに関する設定を確認し、修正してください。

## ERROR 9002 (HY000) : OSS file MD5 error

* OceanBase エラーコード：9002

* エラー原因：OSSファイルのデータ検証に誤りがあります。OSS上のデータに異常なエラーが発生した可能性があります。

* 解決策：OSSテクニカルサポートにお問い合わせいただき、具体的な原因を調査してください。

## ERROR 9003 (HY000) : OSS error

* OceanBase エラーコード：9003

* エラー原因：OSSで未知のエラーが発生しました。

* 解決策：OSSテクニカルサポートにお問い合わせいただき、具体的な原因を調査してください。

## ERROR 9033 (HY000) : Backup meta info stored in system dictionary does not match with current system status

## ERROR 9036 (HY000) : Backup is in progress

## ERROR 9038 (HY000) : Cannot add replica during set member list in restore

* OceanBase エラーコード：9038

* エラーの原因：`set member list`段階ではレプリケーションがサポートされません。

* 解決策：復元の`set member list`ステップではレプリカの複製をサポートできません。この時点で多数派レプリカが存在する場合、復元は続行できます。多数派レプリカが存在しなくなった場合は、復元をキャンセルしてから、復元タスクを再スケジュールする必要があります。

## ERROR 9039 (HY000) : pg log archive leader changed

* OceanBase エラーコード：9039

* エラーの原因：ログアーカイブのLeaderが切り替わりました。

* 解決策：内部エラーコードです。Leader切り替えが検出されると、現在のPGのログアーカイブプロセスが中断されます。新しいLeaderが自動的にバックアップ作業を継続します。運用保守の介入は不要です。

## ERROR 9040 (HY000) : backup can not start

* OceanBase エラーコード：9040

* 解決策：ログアーカイブが`DOING`状態になるのを待ってください。長期間`BEGINNING`状態が続く場合は、OceanBaseテクニカルサポートにお問い合わせいただき、具体的な原因を調査してください。

* エラー原因：オブジェクトストレージエラーコード。一般的な原因はオブジェクトストレージの接続性および互換性の問題です。
* 解決策：オブジェクトストレージの接続性を確認し、接続性に問題がないことを確認した後、テクニカルサポートに連絡して調査を依頼してください。

## ERROR 9133 (HY000) : Backup zone or backup idc or backup region invalid

* OceanBase エラーコード：9133

* エラー原因：設定されたバックアップパスまたはアーカイブパスのソース側のZone/IDC/Regionが存在しません（例えば、クラスタにzone1,zone2しかないのに、ユーザーがbackup zoneの設定でzone=zone3,zone4と設定した場合、zone3,zone4が存在しないとこのエラーが発生します）。

* 解決策：`DBA_OB_ZONES`ビューを照会し、入力されたLocalityが存在するか確認してください。修正後、再度設定してください。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>このエラーコードはV4.3.5バージョンから導入されました。</p>
</main>

## ERROR 9135 (HY000) ：tmp file exceeds disk quota

* OceanBase エラーコード：9135

* エラー原因：一時ファイルのディスクへの書き込みデータ量が設定上限を超えています。

* 解決策：現在エラーが発生しているSQLが予想以上のデータ量を生成していないか確認してください（例えば、一時ファイルのディスクへの書き込みデータ量の上限が最大500GBと予想されている場合）。予想通りであれば、パラメータ`temporary_file_max_disk_size`を適切な値に調整できます。

<h4>説明</h4>
<p>V4.3.5バージョンでは、このエラーコードはV4.3.5 BP1バージョンから導入されました。</p>
</main>

## ERROR 9139 (HY000) : kms destination is not valid

* OceanBase エラーコード：9139

* エラー原因：バックアップテナントで透過的データ暗号化が有効な場合、復元テナントでキーファイルのアドレスを指定しなかった、または指定したアドレスが誤っていた。

* 解決策：復元コマンドで正しいキーファイルのアドレスを指定するか、復元前に `SET @kms_encrypt_info` セッション変数を設定して正しいキーファイルのアドレスを指定します。

## ERROR 9149 (HY000) : backup dest is not allowed to set when log_only policy exists

* OceanBase エラーコード：9149

* エラー原因：`log_only` のクリーンアップポリシーは、ログアーカイブのみが有効でデータバックアップがない場合に適用されます。`log_only` クリーンアップポリシーが存在する場合、データバックアップパスの設定は許可されません。

* 解決策：まず `log_only` クリーンアップポリシーを削除し、その後データバックアップパスを設定します。

<h4>説明</h4>

## ERROR 9151 (HY000) : backup clean can not start, because %s

* OceanBase エラーコード：9151

* エラー原因：データバックアップおよびアーカイブのクリーンアップを開始できません。原因として、関連テナントの状態が `NORMAL` 以外である可能性があります（例：作成中の `CREATING` 状態、復元中の `RESTORE` 状態など）、または関連テナントにクリーンアップポリシーが設定されていない可能性があります（期限切れクリーンアップの場合）。

* 解決策：テナントの状態を確認してください。期限切れクリーンアップの場合、関連テナントにクリーンアップポリシーが正しく設定されているか確認する必要があります。

<main id="notice" type='explain'>
<h4>説明</h4>
<p>V4.4.x系では、このエラーコードはV4.4.1バージョンから導入されました。</p>

## ERROR 9202 (HY000) : Auto extend param is not ready to start extending file

* OceanBase エラーコード：9202

* エラー原因：設定などの問題により、自動拡張が開始されていないか、`datafile` の事前設定されたディスク使用リソースが上限に達しています。

* 解決策：`__all_virtual_disk_stat` テーブルの `free_size` フィールドが0であるか確認してください。もしそうであれば、ディスク容量がすでに使い果たされていることを意味します。`datafile` のしきい値を引き上げるか、ディスクを拡張する必要があります。
