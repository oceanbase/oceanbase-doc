# LOAD DATA

## 説明

このステートメントは、外部からデータをインポートするために使用されます。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p><ul><li>トリガー(Trigger)を持つテーブルでは、<code>LOAD DATA</code> ステートメントの使用が禁止されています。</li><li>外部ファイルからデータをインポートするには、<code>FILE</code> 権限と以下の設定が必要です：<ul><li>サーバー側のファイルを読み込む場合、システム変数 <a href="../../../../800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/11500.secure_file_priv-global.md">secure_file_priv</a> を事前に設定し、インポートまたはエクスポートファイルへのアクセスパスを設定する必要があります。</li><li>クライアント側のローカルファイルを読み込む場合、MySQL/OBClientクライアントを起動する際に <code>--local-infile[=1]</code> オプションを追加して、ローカルファイルシステムからのデータ読み込み機能を有効にする必要があります。</li></ul></li></ul></p>
</main>

OceanBaseデータベースの `LOAD DATA` ステートメントは、以下の入力ファイルの読み込みをサポートしています：

* サーバー側(OBServerノード)ファイル：ファイルはOceanBaseデータベースのOBServerノード上にあります。`LOAD DATA INFILE` ステートメントを使用して、サーバー側のファイルからデータベーステーブルにデータを読み込むことができます。

* クライアント側(ローカル)ファイル：ファイルはクライアントのローカルファイルシステム上にあります。`LOAD DATA LOCAL INFILE` ステートメントを使用して、クライアントのローカルファイルからデータベーステーブルにデータを読み込むことができます。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>OceanBaseデータベースのMySQLモードは、V4.2.2バージョン以降、<code>LOAD DATA LOCAL INFILE</code> 構文を使用してローカルデータファイルを読み込むことをサポートしています。また、<code>LOAD DATA LOCAL INFILE</code> コマンドを実行する際、システムは自動的に <code>IGNORE</code> オプションを追加します。</p>
  </main>

* OSSファイル：ファイルはOSSファイルシステム上にあります。`LOAD DATA REMOTE_OSS INFILE` ステートメントを使用して、OSSファイル内のデータをデータベーステーブルに読み込むことができます。

`LOAD DATA` は現在、CSV形式のテキストファイルのインポートをサポートしており、インポートプロセス全体は以下の手順に分けられます：

1. ファイルの解析：OceanBaseデータベースは、ユーザーが入力したファイル名に基づいてファイル内のデータを読み取り、指定された並列度に応じて入力ファイル内のデータを並列または直列で解析します。

2. データの分散：OceanBaseは分散型データベースであるため、各パーティションのデータは異なるOBServerノードに分散されている可能性があります。<code>LOAD DATA</code> は解析されたデータに対して計算を行い、データを送信するOBServerノードを決定します。

3. データの挿入：ターゲットOBServerノードがデータを受信すると、ローカルで `INSERT` 操作を実行して、データを対応するパーティションに挿入します。

## 構文

```sql
LOAD DATA
    [/*+ PARALLEL(N) load_batch_size(M) APPEND */]
   |[/*+ PARALLEL(N) direct(bool, int) */]
    [REMOTE_OSS | LOCAL] INFILE 'file_name'
    [REPLACE | IGNORE]
    INTO TABLE table_name
    [{FIELDS | COLUMNS}
        [TERMINATED BY 'string']
        [[OPTIONALLY] ENCLOSED BY 'char']
        [ESCAPED BY 'char']
    ]
    [LINES
        [STARTING BY 'string']
        [TERMINATED BY 'string']
    ]
    [IGNORE number {LINES | ROWS}]
    [(column_name_var
        [, column_name_var] ...)]
```

## パラメータの説明

|                パラメータ                |            説明                   |
|----------------------------------|-------------------------------------------|
| parallel(N)                      | データ読み込みの並列度。`N` のデフォルト値は `4` です。   |
| load_batch_size(M)               | 1回の挿入で処理するバッチサイズを指定します。`M` のデフォルト値は `100` です。推奨値の範囲は \[100,1000\] です。    |
| APPEND | Hintを使用してダイレクトロード機能を有効にします。これにより、データファイル内に直接領域を割り当ててデータを書き込むことが可能になります。`APPEND` Hintはデフォルトで使用される `direct(true, 0)` と同じであり、オンライン統計情報収集(`GATHER_OPTIMIZER_STATISTICS` Hint)機能も実現できます。   |
| direct | Hintを使用してダイレクトロードを有効にします。`direct(bool, int)` の `bool` パラメータは、指定されたCSVファイルをソートする必要があるかどうかを示します。`true` はソートが必要であることを示し、`int` は許容される最大エラー行数を示します。 |
| REMOTE_OSS \| LOCAL | オプション。<ul><li> <code>REMOTE_OSS</code>は、OSSファイルシステムからデータを読み取るかどうかを指定します。<main id="notice" type='notice'><h4>注意</h4><p>このパラメータを使用する場合、<code>file_name</code>は必ずOSSのアドレスである必要があります。</p></main>  </li><li> <code>LOCAL</code>は、クライアントのローカルファイルシステムからデータを読み取るかどうかを指定します。`LOCAL` パラメータを使用しない場合、サーバー側(OBServerノード)のファイルシステムからデータが読み取られます。</li></ul> |
| file_name                        | 入力ファイルのパスとファイル名を指定します。 <code>file_name</code> は次の形式です：<ul><li>OBServersノードまたはクライアント上のインポートファイル：<code>/\$PATH/\$FILENAME</code>。</li><li>OSS上のインポートファイル：<code>oss://\$PATH/\$FILENAME/?host=\$HOST&access_id=\$ACCESS_ID&access_key=\$ACCESSKEY</code>。</li></ul>     パラメータの説明は以下のとおりです：<ul><li><code>\$PATH</code>：バケット内のファイルパスを指定し、ファイルが存在するディレクトリを示します。</li><li><code>\$FILENAME</code>：ファイル名を指定し、アクセスする具体的なファイルを示します。</li><li><code>\$HOST</code>：OSSサービスのホスト名またはCDN高速化のドメイン名、つまりアクセスするOSSサービスのアドレスを指定します。</li><li><code>\$ACCESS_ID</code>：OSSサービスへのアクセスに必要なAccess Key IDを指定し、認証に使用されます。</li><li><code>\$ACCESSKEY</code>：OSSサービスへのアクセスに必要なAccess Key Secretを指定し、認証に使用されます。</li></ul>    <main id="notice" type='explain'> <h4>説明</h4> <p>OSS上のファイルをインポートする際には、以下の情報を確認する必要があります：<ul><li>OSSバケットとファイルへのアクセス権限を確保してください。指定されたバケットとファイルを読み取るために十分な権限が必要です。通常、これはOSSコンソールまたはOSS APIを使用してアクセス権限を設定し、アクセスキー(Access Key IDとAccess Key Secret)を適切な権限を持つ資格情報として構成する必要があります。</li><li>データベースサーバーがネットワーク経由で指定された <code>$HOST</code> アドレスに接続でき、OSSサービスにアクセスできることを確認してください。OSSサービスのCDN高速化ドメイン名を使用する場合は、CDN設定が正しく、ネットワーク接続が正常であることも確認する必要があります。</li></ul></p> </main>  |
| REPLACE \| IGNORE                | 唯一キーの競合が発生した場合、`REPLACE` は競合する行を上書きし、`IGNORE` は競合する行を無視します。 `LOAD DATA` はテーブルの主キーに基づいてデータが重複しているかどうかを判断します。テーブルに主キーが存在しない場合、`REPLACE` と `IGNORE` オプションに違いはありません。デフォルトでは、重複データが存在する場合、`LOAD DATA` はエラーが発生したデータをログファイルに記録します。 <main id="notice" type='notice'><h4>注意</h4><p><ul><li>MySQLモードで <code>LOAD DATA LOCAL INFILE</code> コマンドを実行すると、システムは自動的に <code>IGNORE</code> オプションを追加します。この動作により、MySQLデータベースとの互換性が向上します。</li><li><code>REPLACE</code> または <code>IGNORE</code> 句を使用する場合、並列度が <code>1</code> より大きいと、競合する行の最後に挿入されるレコードは、直列実行の結果と異なる可能性があります。競合レコードの挿入結果を厳密に保証する必要がある場合は、このステートメントの並列度を指定しないでください(または並列度を <code>1</code> に設定してください)。</li></ul></p></main> |
| table_name                       | データをインポートするテーブルの名前。パーティションテーブルとパーティションテーブルの両方をサポートします。  |
| FIELDS \| COLUMNS                | フィールドの形式を指定します。 <ul><li> `ENCLOSED BY`：エクスポート値の修飾子を設定します。  </li> <li> `TERMINATED BY`：エクスポート列の終了文字を設定します。 </li> <li>`ESCAPED BY`：エクスポート値で無視する文字を設定します。</li></ul>    |
| LINES STARTING BY                | 行の開始文字を指定します。   |
| LINES TERMINATED BY              | 行の終了文字を指定します。  |
| IGNORE number { LINES \| ROWS } | 最初の数行を無視します。`LINES` はファイルの最初の数行を表し、`ROWS` はフィールド区切り文字で指定された最初の数行のデータを表します。デフォルトでは、入力ファイル内のフィールドがテーブルの列と1対1で対応します。入力ファイルにすべての列が含まれていない場合、不足している列は以下のルールに従ってデフォルトで補完されます：  <ul><li> 文字型：空の文字列。   </li> <li> 数値型：0。    </li> <li> 日付型：`0000-00-00`。</li></ul>    |
| column_name_var                  | インポートする列名を指定します。  |

## 注意事項

### ダイレクトロード時のワイルドカードルール

`LOAD DATA` ステートメントでは、`Hint direct` を使用してダイレクトロードを実行するかどうかを指定します。複数ファイルのインポートを容易にするため、ファイルワイルドカード機能が導入されており、server_diskおよびOSSタイプのファイルソースに適用されますが、クライアントディスク(client_disk)には適用されません。

#### クラスタ内ファイルシステム(server_disk)のダイレクトロードの使用方法

* server_diskの例：

  * ファイル名のマッチング：`load data /*+ parallel(20) direct(true, 0) */ infile '/xxx/test.*.csv' replace into table t1 fields terminated by '|';`

  * ディレクトリのマッチング：`load data /*+ parallel(20) direct(true, 0) */ infile '/aaa*bb/test.1.csv' replace into table t1 fields terminated by '|';`

  * ディレクトリとファイル名の同時マッチング：`load data /*+ parallel(20) direct(true, 0) */ infile '/aaa*bb/test.*.csv' replace into table t1 fields terminated by '|';`

* server_diskの注意事項：

  * マッチするファイルが少なくとも1つ存在しなければ、`OB_FILE_NOT_EXIST` エラーが報告されます。

  * `load data /*+ parallel(20) direct(true, 0) */ infile '/xxx/test.1*.csv,/xxx/test.6*.csv' replace into table t1 fields terminated by '|';` の入力に対して、`/xxx/test.1*.csv,/xxx/test.6*.csv` は全体一致と見なされます。マッチするものがない場合、`OB_FILE_NOT_EXIST` エラーが報告されます。

  * POSIXのGLOB関数でサポートされるワイルドカードのみがサポートされています。例えば、`test.6*(6|0).csv` および `test.6*({0.csv,6.csv}|.csv)` は `ls` コマンドで検索できますが、GLOB関数ではマッチせず、`OB_FILE_NOT_EXIST` エラーが報告されます。

#### クラウドオブジェクトストレージサービス(OSS)のダイレクトロードの使用方法

* ossの例：

  * ファイル名のマッチング：`load data /*+ parallel(20) direct(true, 0) */ remote_oss infile 'oss://xxx/test.*.csv?host=xxx&access_id=xxx&access_key=xxx' replace into table t1 fields terminated by '|';`

* ossの注意事項：

  * ディレクトリのマッチングはサポートされていません。例えば：`load data /*+ parallel(20) direct(true, 0) */ remote_oss infile 'oss://aa*bb/test.*.csv?host=xxx&access_id=xxx&access_key=xxx' replace into table t1 fields terminated by '|';` は `OB_NOT_SUPPORTED` を返します。

  * ファイル名ワイルドカードは `*` と `?` のみをサポートします。他のワイルドカードは入力は許可されていますが、マッチする結果はありません。

詳細については、[LOAD DATAステートメントを使用したデータ/ファイルのダイレクトロード](../../../../../500.data-migration/1100.bypass-import/200.use-load-data-statement-to-bypass-import-data.md)を参照してください。

## 例

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p><code>LOAD DATA</code>でデータを読み込む際、<code>\N</code> を使用して <code>NULL</code> を表すことができます。</p>
</main>

### サーバー側ファイルからのデータインポート

例1：サーバー側ファイルからデータをインポートします。

1. グローバルセキュリティパスを設定します。

   ```shell
   obclient> SET GLOBAL secure_file_priv = "/"
   Query OK, 0 rows affected
   obclinet> \q
   Bye
   ```

   <main id="notice" type='explain'>
     <h4>説明</h4>
     <p><code>secure_file_priv</code>は<code>GLOBAL</code>変数であるため、<code>\q</code>を実行して終了する必要があります。</p>
   </main>

2. データベースに再接続した後、外部ファイルからデータをインポートします。

   ```shell
   obclient> LOAD DATA INFILE 'test.sql' INTO TABLE t1;
   Query OK, 0 rows affected
   ```

例2：`APPEND`ヒントを使用してダイレクトロード機能を有効にします。

```shell
LOAD DATA /*+ PARALLEL(4) APPEND */
   INFILE '/home/admin/a.csv'
   INTO TABLE t;
```

例3：`direct(bool, int)`ヒントを使用してダイレクトロード機能を有効にします。ダイレクトロードファイルはOSS上に配置できます。

```shell
load data /*+ parallel(1) direct(false,0)*/ remote_oss infile 'oss://antsys-oceanbasebackup/backup_rd/xiaotao.ht/lineitem2.tbl?host=***.oss-cdn.***&access_id=***&access_key=***' into table lineitem fields terminated by '|' enclosed by '' lines starting by '' terminated by '\n';
```

### クライアント（ローカル）ファイルからデータをインポートする

例4：次のステートメントを使用して、ローカルファイルからOceanBaseデータベースのテーブルにデータをインポートします。

1. ターミナルまたはコマンドプロンプトウィンドウを開き、次のコマンドを入力してクライアントを起動します。

    ```shell
    obclient --local-infile -hxxx.xxx.xxx.xxx -P2881 -uroot@mysql001 -p****** -A -Dtest
    ```

    実行結果は次のとおりです：

    ```shell
    Welcome to the OceanBase.  Commands end with ; or \g.
    Your OceanBase connection id is 3221719526
    Server version: OceanBase 4.2.2.0 (r100000022023121309-f536833402c6efe9364d5a4b61830a858ef24d82) (Built Dec 13 2023 09:58:18)

    Copyright (c) 2000, 2018, OceanBase and/or its affiliates. All rights reserved.

    Type 'help;' or '\h' for help. Type '\c' to clear the current input statement.

    obclient [test]>
    ```

    <main id="notice" type='notice'>
      <h4>注意</h4>
      <p><code>LOAD DATA LOCAL INFILE</code>機能を使用するには、V2.2.4以降のバージョンのOBClientクライアントを使用してください。指定されたバージョンのOBClientクライアントがない場合は、MySQLクライアントを使用してデータベースに接続することもできます。</p>
    </main>

2. クライアントで、`LOAD DATA LOCAL INFILE` ステートメントを実行してローカルデータファイルを読み込みます。

    ```shell
    obclient [test]> LOAD DATA LOCAL INFILE '/home/admin/test_data/tbl1.csv' INTO TABLE tbl1 FIELDS TERMINATED BY ',';
    ```

    実行結果は次のとおりです：

    ```shell
    Query OK, 3 rows affected
    Records: 3  Deleted: 0  Skipped: 0  Warnings: 0
    ```

### OSSファイルからデータをインポートする

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>オブジェクトストレージパスを使用する場合、パスの各パラメータは <code>&</code> 記号で区切られています。入力するパラメータ値には、大文字と小文字の英字、数字、<code>\/-_$+=</code> およびワイルドカードのみを含めてください。上記以外の文字を入力した場合、設定が失敗する可能性があります。</p>
</main>

`direct(bool, int)` ヒントを使用してダイレクトロード機能を有効にし、インポートファイルはOSS上に配置できます。

```shell
LOAD DATA /*+ direct(true,1024) parallel(16) */ REMOTE_OSS INFILE 'oss://antsys-oceanbasebackup/backup_rd/xiaotao.ht/lineitem2.tbl?host=***.oss-cdn.***&access_id=***&access_key=***' INTO TABLE tbl1 FIELDS TERMINATED BY ',';
```
