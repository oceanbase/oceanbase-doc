# ALTER/CHANGE/MODIFY EXTERNAL_STORAGE_DEST

## 説明

このステートメントは、このテナントのバックアップまたはアーカイブパスのソースを変更するために使用されます：`zone`、`idc` または `region` の構成。変更後、新しい構成情報が元の構成情報を上書きします。

## 制限事項と注意点

* このステートメントはユーザーテナントのみが実行でき、システムテナント(sysテナント)は実行できません。

* パスの `zone`、`idc` または `region` の構成を変更する前に、リージョンレベルまたはIDCレベルを設定する必要がある場合は、`ALTER SYSTEM MODIFY ZONE zone_name SET REGION=region_name;` または `ALTER SYSTEM MODIFY ZONE zone_name SET IDC=idc_name;` ステートメントを使用して、それぞれリージョン情報またはIDC情報を設定する必要があります。IDCレベルのソース構成を設定することを推奨します。これにより、より多くのネットワーク帯域幅リソースを持つIDCでバックアップタスクを実行できるだけでなく、バックアップタスクの選択可能なノード範囲も広がり、ユーザーはクラスタ内のIDC内のゾーンの変更状況を気にする必要がなくなります。

* バックアップパスのソース構成を変更する際、バックアップタスクが実行中の場合、実行中のタスクは構成の変更を認識するまで最大で数分かかるため、構成変更期間中に構成範囲外のノードがバックアップパスにアクセスし、異なるデータセンターやリージョン間のトラフィックが発生する可能性があります。

## 権限要件

このステートメントを実行するユーザーは `ALTER SYSTEM` 権限を持っている必要があります。OceanBaseデータベースの権限の詳細については、[MySQLモードの権限分類](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md)を参照してください。

## 構文

```sql
ALTER SYSTEM {ALTER|CHANGE|MODIFY} EXTERNAL_STORAGE_DEST PATH [=] 'path' SET ATTRIBUTE = '{zone=zone_name | idc=idc_name | region=region_name}';
```

## パラメータの説明

|          パラメータ               |         説明                                      |
|-----------------------------|--------------------------------------------------|
| path                        | 変更対象のバックアップパスまたはアーカイブパスを指定します。アーカイブメディアがオブジェクトストレージタイプの場合、オブジェクトストレージのホストアドレス、アクセスキーなどの情報も含める必要があります。例えば、アーカイブメディアがOSSの場合、このパスの形式は以下のとおりです：<ul><li>V4.2.5 BP3以降のバージョン：`oss://oceanbase-test-bucket/backup/databackup?host=xxxx`<main id="notice" type='explain'><h4>説明</h4><p>V4.2.5 BP3以降のバージョンでは、互換性のため、パス形式に<code>access_key</code>、<code>access_id</code>などの鍵情報が含まれている場合でも設定は成功します。</p></main> </li> <li>V4.2.5 BP2バージョン：`oss://oceanbase-test-bucket/backup/databackup?host=xxxx&access_key=xxxx&access_id=xxxx`</li></ul> |
| zone=zone_name \| idc=idc_name \| region=region_name | 現在のバックアップパスまたはアーカイブパスのソースを指定します。`zone`、`idc`、または`region`の3つの異なるレベルの構成を選択でき、同時に1つのレベルのみを選択するか、設定しないこともできます。明示的に指定されない場合、デフォルトでは設定されません。<p>アーカイブパスのソース構成を変更する場合：<ul><li>ログアーカイブのすべてのトラフィックはリーダーレプリカによって書き込まれるため、ログアーカイブパスにはアクセス優先順位の違いはなく、アーカイブパスへのアクセスを許可するノードの範囲のみが制限されます。複数のゾーン、複数のIDC、または複数のリージョンを設定する必要がある場合は、複数の値を英語のカンマ（,）または英語のセミコロン（;）で区切ります。例えば、`zone=z1,z2;z3`は`z1`、`z2`、`z3`をアーカイブパスのソースとして指定することを意味します。</li> <li>`zone`、`idc`、または`region`を変更する場合、リーダーレプリカが指定された`zone`、`idc`、または`region`内に存在する必要があります。そうでない場合、ログアーカイブは進行できません。</li></ul></p> <p>バックアップパスのソース構成を変更する場合：<ul><li>複数のゾーン、複数のIDC、または複数のリージョンを設定する必要がある場合は、複数のゾーン/IDC/リージョン間を英語のカンマ（,）と英語のセミコロン（;）で区切ります。その中で：<ul><li>英語のカンマ（,）は、バックアップタスクの実行ノードを選択する際、左右のゾーン/IDC/リージョン内のノードが同等の優先順位を持つことを意味します。</li> <li>英語のセミコロン（;）は、左側のゾーン/IDC/リージョン内のノードの優先順位が右側よりも高いことを意味し、つまり左側のゾーン/IDC/リージョン内のノードを優先的に選択してバックアップタスクを実行します。</li></ul>例えば、`zone=z1,z2;z3`と設定すると、`z1`、`z2`、`z3`をバックアップのソースとして指定し、`z1`、`z2`は同一の優先順位であり、`z1`、`z2`の優先順位は`z3`よりも高いことを意味します。</li> <li>バックアップパスの`zone`、`idc`、または`region`構成を変更する場合、Root Serviceのリーダーノードが指定された`zone`、`idc`、または`region`内に存在する必要があります。そうでない場合、バックアップタスクはターゲットバックアップパスにバックアップメタデータを正常に書き込むことができず、最終的にバックアップタスクの実行に失敗します。バックアップパスのソース構成には、Primary Zoneの範囲を含めることを推奨します。</li></ul></p> |

## 例

* アーカイブパスのソース構成を変更する

  もともとアーカイブパスのソース構成が `zone=z1,z2,z3` であった場合、現在はソース構成を `region=region1` に変更する必要があります。変更後は、`region1` 内のノードのみがこのパスにアクセスできます。

  * OSS

    ```shell
    obclient> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='oss://oceanbase-test-bucket/backup/archive?host=****.aliyun-inc.com' SET ATTRIBUTE = 'region=region1';
    ```

  * NFS

    ```shell
    obclient> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='file:///data/nfs/backup/archive' SET ATTRIBUTE = 'region=region1';
    ```

  * S3

    ```shell
    obclient> ALTER SYSTEM CHANGE EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=s3.<region>.amazonaws.com' SET ATTRIBUTE = 'region=region1';
    ```

  * S3プロトコル互換のオブジェクトストレージ（OBS/GCS/COS）

    ```shell
    obclient> ALTER SYSTEM CHANGE EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=obs.****.myhuaweicloud.com' SET ATTRIBUTE = 'region=region1';
    ```

    ```shell
    obclient> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=https://storage.googleapis.com' SET ATTRIBUTE = 'region=region1';
    ```

    ```shell
    obclient> ALTER SYSTEM ALTER EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=cos.ap-xxxx.myqcloud.com' SET ATTRIBUTE = 'region=region1';
    ```

* バックアップパスのソース構成を変更する

  もともとバックアップパスのソース構成が `zone=z1,z2;z3` であった場合、現在はソース構成を `idc=idc1;idc2` に変更する必要があります。変更後は、`idc1`、`idc2` 内のノードがこのパスにアクセスでき、`idc1` の優先順位が `idc2` よりも高くなります。

  * OSS

    ```shell
    obclient> ALTER SYSTEM CHANGE EXTERNAL_STORAGE_DEST PATH='oss://oceanbase-test-bucket/backup/data?host=****.aliyun-inc.com' SET ATTRIBUTE = 'idc=idc1;idc2';
    ```

  * NFS

    ```shell
    obclient> ALTER SYSTEM ALTER EXTERNAL_STORAGE_DEST PATH='file:///data/nfs/backup/data' SET ATTRIBUTE = 'idc=idc1;idc2';
    ```

  * S3

    ```shell
    obclient> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/data?host=s3.<region>.amazonaws.com' SET ATTRIBUTE = 'idc=idc1;idc2';
    ```

  * S3プロトコル互換のオブジェクトストレージ（OBS/GCS/COS）

    ```shell
    obclient> ALTER SYSTEM CHANGE EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/data?host=obs.****.myhuaweicloud.com' SET ATTRIBUTE = 'idc=idc1;idc2';
    ```

    ```shell
    obclient> ALTER SYSTEM ALTER EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/data?host=https://storage.googleapis.com' SET ATTRIBUTE = 'idc=idc1;idc2';
    ```

    ```shell
    obclient> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test/backup/data?host=cos.ap-xxxx.myqcloud.com' SET ATTRIBUTE = 'idc=idc1;idc2';
    ```
