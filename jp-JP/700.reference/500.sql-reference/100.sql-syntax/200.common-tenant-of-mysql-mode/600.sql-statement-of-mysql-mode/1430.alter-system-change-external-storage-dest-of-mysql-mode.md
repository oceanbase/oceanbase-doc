# ALTER/CHANGE/MODIFY EXTERNAL_STORAGE_DEST

## 説明

このステートメントは、テナントのバックアップまたはアーカイブパスのソース側設定（`zone`、`idc`、または `region` の設定）、I/O スロットリングパラメータ（`max_iops` および `max_bandwidth`）、および `access_id` と `access_key` などのキー情報を変更するために使用します。変更後、新しい設定情報が既存の設定情報を上書きします。

## 使用制限と注意事項

* このステートメントはユーザーテナントのみが実行でき、システムテナント（sys テナント）は実行できません。

* パスの `zone`、`idc`、または `region` 設定を変更する前に、リージョンレベルまたは IDC レベルを設定する必要がある場合は、まず `ALTER SYSTEM MODIFY ZONE zone_name SET REGION=region_name;` または `ALTER SYSTEM MODIFY ZONE zone_name SET IDC=idc_name;` ステートメントを使用して、それぞれリージョン情報または IDC 情報を設定してください。IDC レベルのソース側設定を推奨します。これにより、ネットワーク帯域幅リソースが豊富な IDC を使用してバックアップタスクを実行できるだけでなく、バックアップタスクの選択可能なノード範囲も広がります。また、ユーザーはクラスタ内の IDC 内の Zone の変更状況を気にする必要がありません。

* バックアップパスのソース側設定を変更する際、バックアップタスクが実行中の場合、実行中のタスクが設定変更を認識するまでに最大数分かかるため、設定変更期間中も設定範囲外のノードがバックアップパスにアクセスし、データセンターまたはリージョンを跨ぐトラフィックが発生する可能性があります。

* I/O スロットリングパラメータ（`max_iops` および `max_bandwidth`）および `access_id` と `access_key` 情報の変更は、オブジェクトストレージパスでのみサポートされています。バックアップメディアが NFS パスの場合、I/O スロットリングパラメータ（`max_iops` および `max_bandwidth`）や `access_id`、`access_key` 情報を設定すると、システムはサポートされないエラーを返し、エラーコードは `1235` です。

* オブジェクトストレージパスに `ACCESS_INFO` プロパティ（`access_id` と `access_key` 情報）を設定する際、パラメータの形式が正しくない場合（例えば、余分な `=` がある、`access_id` または `access_key` が欠けているなど）、システムは `OB_OBJECT_STORAGE_PERMISSION_DENIED` エラー（エラーコード `-9116`）を返します。

* バックアップパスまたはアーカイブパスが Assume Role 方式でオブジェクトパスにアクセスする場合：

  * `ACCESS_INFO = 'access_id=new_access_id&access_key=new_access_key'` を設定すると、システムはエラーを返します。

  * `ATTRIBUTE` 内の I/O スロットリングパラメータのみを設定し（`ACCESS_INFO` プロパティを設定しない場合）、システムはサポートされないと提示するか、設定が反映されない可能性があります。

* 同一パスに対して同じ `ATTRIBUTE` + `ACCESS_INFO` プロパティを複数回設定することは許可されています。

## 権限要件

このステートメントを実行するユーザーは `ALTER SYSTEM` 権限を持っている必要があります。OceanBase データベースの権限の詳細については、[MySQLモードの権限分類](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md)を参照してください。

## 構文

```sql
ALTER SYSTEM {ALTER|CHANGE|MODIFY} EXTERNAL_STORAGE_DEST
  PATH [=] 'path'
  SET [ATTRIBUTE = '[{zone=zone_name | idc=idc_name | region=region_name}][&max_iops=iops_num][&max_bandwidth=bandwidth_num]']
  [ACCESS_INFO = 'access_id=new_access_id&access_key=new_access_key'];
```

## パラメータ説明

|          パラメータ                                     |         説明                                      |
|---------------------------------------------------|--------------------------------------------------|
| path                                              | 変更対象のキー情報を持つバックアップパスまたはアーカイブパスを指定します。指定するパスは、現在のテナントで既に設定されているバックアップパスまたはアーカイブパスでなければならず、オブジェクトストレージパスである必要があります。また、パスには `host` 情報が含まれている必要があります。OSS を例にすると、このパスの形式は次のとおりです：`oss://oceanbase-test-bucket/backup/databackup?host=***`。 |
| zone=zone_name \| idc=idc_name \| region=region_name | 現在のバックアップパスまたはアーカイブパスのソースを指定します。`zone`、`idc`、または `region` の3つの異なるレベルの設定を選択できますが、一度に1つのレベルのみを選択するか、設定しないこともできます。明示的に指定しない場合、デフォルトでは設定されません。<p>アーカイブパスのソース側設定を変更する場合：<ul><li>ログアーカイブのすべてのトラフィックはリーダーレプリカによって書き込まれるため、ログアーカイブパスにはアクセス優先順位の違いはなく、アーカイブパスにアクセスできるノードの範囲のみが制限されます。複数の Zone、複数の IDC、または複数の Region を設定する必要がある場合は、複数の値を半角カンマ（,）または半角セミコロン（;）で区切ります。例えば、`zone=z1,z2;z3` は、`z1`、`z2`、`z3` をアーカイブパスのソースとして指定します。</li> <li>`zone`、`idc`、または `region` を変更する場合、リーダーレプリカが指定された `zone`、`idc`、または `region` 内に存在する必要があります。そうでない場合、ログアーカイブは進行できません。</li></ul></p> <p>バックアップパスのソース側設定を変更する場合：<ul><li>複数の Zone、複数の IDC、または複数の Region を設定する必要がある場合、複数の Zone/IDC/Region を半角カンマ（,）と半角セミコロン（;）で区切ります。その中で：<ul><li>半角カンマ（,）は、バックアップタスクのノードを選択する際、左右の Zone/IDC/Region 内のノードが同等の優先順位を持つことを示します。</li> <li>半角セミコロン（;）は、左側の Zone/IDC/Region 内のノードの方が右側よりも優先順位が高いことを示し、バックアップタスクの実行には左側の Zone/IDC/Region 内のノードが優先的に選択されます。</li></ul>例えば、`zone=z1,z2;z3` と設定すると、`z1`、`z2`、`z3` をバックアップのソースとして指定し、`z1`、`z2` は同等の優先順位を持ち、`z1`、`z2` の優先順位が `z3` よりも高いことを意味します。</li> <li>バックアップパスの `zone`、`idc`、または `region` 設定を変更する場合、Root Service のリーダーノードが指定された `zone`、`idc`、または `region` 内に存在する必要があります。そうでない場合、バックアップタスクはターゲットバックアップパスにバックアップメタデータを書き込むことができず、結果としてバックアップタスクの実行が失敗します。バックアップパスのソース側には Primary Zone の範囲を含める設定を推奨します。</li></ul></p> |
| max_iops        | 現在のバックアップパスまたはアーカイブパスで使用できる最大 IOPS を指定します。値は正の整数で、1秒間に約何回の I/O リクエストが可能かを表します。明示的に設定しない場合、そのパスの IOPS に制限がなく、基盤となるオブジェクトストレージおよびネットワークの能力によって決定されます。<p>例：`max_iops=1000`</p> |
| max_bandwidth   | 現在のバックアップパスまたはアーカイブパスで使用できる最大帯域幅を指定します。値は単位を含む正の整数です。サポートされている単位は kb、mb、gb で、それぞれ KB/s、MB/s、GB/s を表します。明示的に設定しない場合、そのパスの帯域幅に制限がありません。<p>例：`max_bandwidth=1000mb`</p>  |
| access_id=new_access_id&access_key=new_access_key | 変更後の新しい `access_id` と `access_key` 情報を指定します。`access_id` と `access_key` は両方とも入力する必要があります。|

## 例

### アーカイブパスのソース側設定を変更する

アーカイブパスの元のソース側設定が `zone=z1,z2,z3` であると仮定します。現在、ソース側設定を `region=region1` に変更する必要があります。変更後は、`region1` 内のノードのみがこのパスにアクセスできます。

  * OSS

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='oss://oceanbase-test-bucket/backup/archive?host=****.aliyun-inc.com' SET ATTRIBUTE = 'region=region1';
    ```

  * NFS

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='file:///data/nfs/backup/archive' SET ATTRIBUTE = 'region=region1';
    ```

  * S3

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM CHANGE EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=s3.<region>.amazonaws.com' SET ATTRIBUTE = 'region=region1';
    ```

  * S3プロトコル互換のオブジェクトストレージ（OBS/GCS/COS）

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM CHANGE EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=obs.****.myhuaweicloud.com' SET ATTRIBUTE = 'region=region1';
    ```

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=https://storage.googleapis.com' SET ATTRIBUTE = 'region=region1';
    ```

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM ALTER EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=cos.ap-xxxx.myqcloud.com' SET ATTRIBUTE = 'region=region1';
    ```

### バックアップパスのソース側設定を変更する

バックアップパスの元のソース側設定が `zone=z1,z2;z3` であると仮定します。現在、ソース側設定を `idc=idc1;idc2` に変更する必要があります。変更後は、`idc1`、`idc2` 内のノードがこのパスにアクセスでき、`idc1` の優先順位が `idc2` より高くなります。

  * NFS

### アーカイブパスのI/Oスロットリングパラメータ（`max_iops` と `max_bandwidth`）の設定

`max_iops` と `max_bandwidth` の両方のパラメータを同時に設定することも、どちらか一方のみを設定することもできます。これらのパラメータはオブジェクトストレージパスでのみ設定可能で、NFSパスではI/Oスロットリングパラメータの設定はサポートされていません。

* OSS

  `max_iops` と `max_bandwidth` の両方のパラメータを同時に設定する例を以下に示します。

  ```shell
  obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='oss://oceanbase-test-bucket/backup/archive?host=****.aliyun-inc.com' SET ATTRIBUTE = 'max_iops=1000&max_bandwidth=1000mb';
  ```

  `max_iops` のみを設定する例を以下に示します。

  ```shell
  obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='oss://oceanbase-test-bucket/backup/archive?host=****.aliyun-inc.com' SET ATTRIBUTE = 'max_iops=1000';
  ```

  `max_bandwidth`を個別に設定する例を以下に示します。

  ```shell
  obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='oss://oceanbase-test-bucket/backup/archive?host=****.aliyun-inc.com' SET ATTRIBUTE = 'max_bandwidth=1000mb';
  ```

* S3

  `max_iops`と`max_bandwidth`の両方のパラメータを同時に設定する例を以下に示します。

  ```shell
  obclient(root@mysql001)[(none)]> ALTER SYSTEM CHANGE EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=s3.<region>.amazonaws.com' SET ATTRIBUTE = 'max_iops=1000&max_bandwidth=1000mb';
  ```

### バックアップパスのI/Oスロットリングパラメータ(`max_iops`および`max_bandwidth`)の設定

<main id="notice" type='explain'>
<h4>説明</h4>
<p>I/Oスロットリングパラメータの設定に関する推奨事項：</p>
<ul><li>高い同時実行性と帯域幅に敏感なマルチテナント環境では、異なるバックアップパスごとに異なる<code>max_iops</code>または<code>max_bandwidth</code>パラメータ値を設定し、バックアップが本番業務の帯域幅とIOPSに与える影響を分離することができます。</li>
<li>実際のネットワーク帯域幅とオブジェクトストレージのスロットリングポリシーを踏まえ、まずは低い値から始めて徐々に調整することを推奨します。例えば、まず<code>max_iops=500&max_bandwidth=100mb</code>に設定して観察し、その後バックアップ時間と業務のピーク負荷に基づいて微調整します。</li></ul>
</main>

`max_iops`と`max_bandwidth`の両方のパラメータを同時に設定することも、`max_iops`または`max_bandwidth`のどちらか一方のみを個別に設定することもできます。I/Oスロットリングパラメータの設定は、オブジェクトストレージパスでのみサポートされており、NFSパスではサポートされていません。

* OSS

  `max_iops`と`max_bandwidth`の両方のパラメータを同時に設定する例を以下に示します。

  ```shell
  obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='oss://oceanbase-test-bucket/backup/data?host=****.aliyun-inc.com' SET ATTRIBUTE = 'max_iops=1000&max_bandwidth=1000mb';
  ```

  `max_iops`を個別に設定する例を以下に示します。

  ```shell
  obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='oss://oceanbase-test-bucket/backup/data?host=****.aliyun-inc.com' SET ATTRIBUTE = 'max_iops=1000';
  ```

  `max_bandwidth`を個別に設定する例を以下に示します。

  ```shell
  obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='oss://oceanbase-test-bucket/backup/data?host=****.aliyun-inc.com' SET ATTRIBUTE = 'max_bandwidth=1000mb';
  ```

* S3

  `max_iops`と`max_bandwidth`の両方のパラメータを同時に設定する例を以下に示します。

  ```shell
  obclient(root@mysql001)[(none)]> ALTER SYSTEM CHANGE EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/data?host=s3.<region>.amazonaws.com' SET ATTRIBUTE = 'max_iops=1000&max_bandwidth=1000mb';
  ```

* S3プロトコル互換のオブジェクトストレージ(OBS/GCS/COS)
