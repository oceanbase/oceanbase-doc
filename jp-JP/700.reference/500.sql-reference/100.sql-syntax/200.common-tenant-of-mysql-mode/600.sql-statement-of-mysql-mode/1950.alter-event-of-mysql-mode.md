# ALTER EVENT

このステートメントは、既存のイベントを変更するために使用されます。

## 構文

```sql
ALTER
    [DEFINER = user]
    EVENT event_name
    [ON SCHEDULE schedule]
    [ON COMPLETION [NOT] PRESERVE]
    [RENAME TO new_event_name]
    [ENABLE | DISABLE | DISABLE ON SLAVE]
    [COMMENT 'string']
    [DO event_body]
```

## パラメータの説明

| パラメータ | 説明 |
|-------|-----------|
|event_name|作成するイベントの名前を指定します。|
|DEFINER|オプションパラメータで、イベントを変更するユーザーを指定します。現在、カスタムユーザーはサポートされておらず、デフォルトは現在のユーザーです。|
|ON SCHEDULE schedule|イベント実行のスケジュールを変更します。タイムスタンプ+INTERVALをサポートしており、「2020-12-01 00:00:00」+INTERVAL 1 DAYのように記述します。時間は整数でなければならず、時間単位としてYEAR、MONTH、DAY、HOUR、MINUTE、SECONDがサポートされています。|
|ON COMPLETION [NOT] PRESERVE|イベントの実行完了後にイベントを保持するかどうかを定義します。デフォルトでは保持されません（NOT PRESERVE）、つまりイベントの実行完了後に自動的に削除されます。|
|ENABLE、DISABLE、DISABLE ON SLAVE|イベントの状態を定義します。デフォルトでは作成時に`ENABLE`となっており、イベントの作成と同時に有効になることを意味します。<br> `DISABLE` はイベント作成後に無効になり、手動で有効にされるまでイベントは自動的に実行されません。<br>`DISABLE ON SLAVE` はレプリケーション環境でのみ使用され、サーバー上でイベントは実行されません。|
|COMMENT 'string'| オプションパラメータで、イベントにコメントを追加します。|
|DO event_body|イベントの元の操作に代わる新しいSQL文を提供します。現在、単一のSQL文と`BEGIN END`複数のSQL文をサポートしています。|

## 例

```shell
obclient> ALTER EVENT myevent
    ON SCHEDULE
      AT '2024-07-02 00:00:00' + INTERVAL 1 DAY
    DO
      TRUNCATE TABLE myschema.mytable;
```
