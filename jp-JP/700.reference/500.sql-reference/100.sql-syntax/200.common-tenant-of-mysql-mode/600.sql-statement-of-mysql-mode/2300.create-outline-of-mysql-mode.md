# CREATE OUTLINE

## 説明

このステートメントは、アウトラインを作成するために使用します。作成方法は2通りあります。1つは `SQL_TEXT` を使用する方法（ユーザーが実行したパラメータ付きの元のステートメント）で、もう1つは `SQL_ID` を使用する方法です。

## 使用上の制限と注意事項

* V4.4.2 BP3より前のバージョンでは、アウトラインを作成するには、対象のデータベースに切り替えて実行する必要があります。
* V4.4.2 BP3から、データベース単位およびテナント単位のアウトラインを指定できます。
* `SQL_ID` が同じ場合、`SQL_TEXT` を使用して作成されたアウトラインは、`SQL_ID` を使用して作成されたアウトラインを上書きします。`SQL_TEXT` を使用する方法の方が優先順位が高くなります。また、OceanBaseデータベースは `SQL_ID` で異なるSQLを区別します。`SQL_ID` は、`SQL_TEXT` をパラメータ化した後にMD5ハッシュを適用して得られます。同じSQLテキストでも、改行やタブが1文字でも違うと、MD5で得られる `SQL_ID` は異なります。実際の本番システムでは、`SQL_ID` を使用したアウトラインのバインドを推奨します。
* `MAP` に `db.table` 形式が含まれる場合、`SCOPE = TENANT` を明示的に指定する必要があります。指定しないと、作成時にエラーが発生します。
* 同じ `BINDING_RULE` 内では、データベース名の `pattern` とテーブル名の `pattern` にそれぞれ最大1つの変数を含めることができます。複雑な式は複数のアウトラインに分割してください。
* 変数は参照する前に定義する必要があります。同じ名前の変数を複数回定義することはできません。
* `db.*` はサポートされていません。等価な式 `'db_${D:[0-9]+}'.'${T:.*}'` などを使用してください。
* 正規表現にはPOSIX拡張構文を使用します。後方参照やゼロ幅アサーションなどの複雑な機能はサポートされていません。
* `SCOPE = DATABASE` かつ `MAP` を指定しないアウトラインのみ、従来の動作をそのまま維持します。これは従来の完全一致アウトラインに相当します。
* `MAX_CONCURRENT` によるレート制限用アウトラインでは、現在 `BINDING_RULE` はサポートされていません。
* テナントをまたぐアウトラインのバインドはサポートされていません。

## 構文

```sql
sql_text_stmt:
    CREATE [OR REPLACE] OUTLINE outline_name ON stmt
        [TO target_stmt
        | BINDING_RULE (binding_item)];

binding_item:
    SCOPE = {DATABASE | TENANT}
    | MAP = {real_name TO 'pattern', ...}

sql_id_stmt:
    CREATE [OR REPLACE] OUTLINE outline_name ON sql_id USING HINT hint;
```

## パラメータの説明

|    **パラメータ**    | **説明** |
|----------------|----------|
| sql_text_stmt  | `SQL_TEXT` を使用してアウトラインを作成するステートメントを表します。|
| sql_id_stmt    | `SQL_ID` を使用してアウトラインを作成するステートメントを表します。|
| outline_name   | 作成するアウトライン名を指定します。|
| OR REPLACE     | オプションです。`OR REPLACE` を指定すると、作成しようとするアウトラインが既に存在する場合、既存のアウトラインを置き換えます。|
| stmt           | 一般的には、ヒントと元のパラメータを持つDMLステートメントです。|
| TO target_stmt | オプションです。`TO target_stmt` を指定しない場合、データベースが受け付けるSQLがパラメータ化された後、`stmt` からヒントを除去してパラメータ化したテキストと同じであれば、そのSQLに `stmt` 内のヒントをバインドして実行計画を生成します。ヒントを含むステートメントに対して固定計画を適用したい場合は、`TO target_stmt` で元のSQLを指定する必要があります。 <main id="notice" type='notice'><h4>注意</h4><p><code>target_stmt</code> を使用する場合、<code>stmt</code> と <code>target_stmt</code> がヒントを除去した後完全に一致することが厳密に要求されます。</p></main>|
| BINDING_RULE (binding_item) | オプションです。このアウトラインの適用範囲を指定します。詳細については、後述の [binding_item](#binding_item) を参照してください。<main id="notice" type="explain"><h4>説明</h4><p>V4.4.2では、V4.4.2 BP3から <code>BINDING_RULE</code> 句が導入されました。</p></main>|
| sql_id         | `sql_id` に対応するSQLステートメントに既にヒントが設定されている場合、アウトラインで指定されたヒントが元のステートメント内のすべてのヒントを上書きします。|
| hint           | アウトラインのヒントを指定します。形式は `/*+ xxx */` です。ヒント構文の詳細については、[Optimizer Hint](../../../../1000.performance-tuning-guide/500.sql-optimization/400.sql-optimization/700.manage-execution-plans/100.optimizer-hint.md)を参照してください。|

### binding_item

* `SCOPE = {DATABASE | TENANT}`：

  * `SCOPE = DATABASE`：デフォルト値です。現在のデータベースでのみ有効になります。
  * `SCOPE = TENANT`：現在のテナント内のすべてのデータベースで有効になります。

* `MAP = {real_name TO 'pattern', ...}`：右側の `pattern` を、左側の実際のテーブル名または `db.table` に適用します。`pattern` には `${変数名}` または `${変数名:正規表現}` を記述できます。

  <main id="notice" type="notice">
    <h4>注意</h4>
    <ul>
      <li><code>MAP</code> の左側が <code>db.table</code> 形式の場合、右側の <code>pattern</code> は <code>'db_pattern'.'table_pattern'</code> のように、2組の引用符に分けて記述する必要があります。</li>
      <li>同じ <code>BINDING_RULE</code> 内では、変数は参照する前に定義する必要があります。同じ名前の変数は、すべての参照箇所で同じ値でなければなりません。</li>
    </ul>
  </main>

## 例

* `SQL_TEXT` を使用してアウトラインを作成します。

    ```shell
    obclient> CREATE OUTLINE otl_idx_c2
        ON SELECT/*+ index(t1 idx_c2)*/ * FROM t1 WHERE c2 = 1;
    ```

* `SQL_ID` を使用してアウトラインを作成します。

    ```shell
    obclient> CREATE OUTLINE otl_idx_c2
        ON 'ED570339F2C856BA96008A29EDF04C74'
        USING HINT /*+ index(t1 idx_c2)*/;
    ```
