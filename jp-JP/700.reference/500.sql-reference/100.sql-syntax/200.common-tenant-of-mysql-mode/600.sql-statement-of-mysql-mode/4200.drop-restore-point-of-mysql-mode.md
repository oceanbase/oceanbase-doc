# DROP RESTORE POINT

## 説明

このステートメントは、復元ポイント（Restore Point）を削除するために使用します。

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p><ul><li>V4.x系では、DROP RESTORE POINTステートメントは現在サポートされていません。</li><li>システムテナントでは、復元ポイントの作成と削除はサポートされていません。</li></ul></p>
  </main>

## 構文

```sql
DROP RESTORE POINT restore_point;
```

## パラメータ説明

|      パラメータ       |    説明    |
|---------------|----------|
| restore_point | 復元ポイント名を指定します。 |

## 例

1. テナントの既存の復元ポイントを確認します。

   ```sql
   obclient> SELECT * FROM V$RESTORE_POINT;
   +-----------+------------------+----------------------------+------+
   | TENANT_ID | SNAPSHOT         | TIME                       | NAME |
   +-----------+------------------+----------------------------+------+
   |      1001 | 1630407064663511 | 2021-08-31 18:51:04.665692 | rp1  |
   +-----------+------------------+----------------------------+------+
   1 row in set
   ```

2. 復元ポイント `rp1` を削除します。

   ```sql
   obclient> DROP RESTORE POINT rp1;
   Query OK, 0 rows affected
   ```

# CREATE RESTORE POINT

## 説明

このステートメントは、復元ポイント（Restore Point）を作成するために使用します。この機能を使用すると、現在時刻のデータスナップショットを保持し、後でそのデータスナップショットを基準としてクエリを実行できます。現在、データをこの復元ポイントまでロールバックすることはサポートされていません。

復元ポイント作成後、`V$RESTORE_POINT` ビューでその復元ポイントの `SNAPSHOT` 値を確認できます。その後、`SELECT * FROM table_name AS OF SNAPSHOT snapshot;` を使用して、データスナップショット内の値を照会できます。

>**注意**
>
> sysテナントではリストアポイントの作成はサポートされていません。

## 構文

```sql
CREATE RESTORE POINT restore_point;
```

## パラメータ説明

|      パラメータ       |    説明    |
|---------------|----------|
| restore_point | リストアポイント名を指定します。 |

## 説明

Restore Point機能の制限事項は以下のとおりです：

* 物理バックアップはサポートされていません。

* プライマリ/スタンバイデータベースはサポートされていません。

* 各テナントで`10`個のRestore Pointが上限です。

* Restore Pointを作成した後、そのポイント作成前に存在したテーブルに対してDDLステートメントを実行すると、システムはエラーを返します。

* Restore Point機能はGTSに依存してグローバルな一貫性のあるスナップショットを維持するため、Restore Pointを使用する際はGTSを有効にする必要があります。

  GTSを有効にするSQLコマンドは以下のとおりです。

  ```sql
  obclient> SET GLOBAL ob_timestamp_service='GTS';
  ```

## 例

1. テーブル`test1`を作成し、1行のデータを挿入します。

   ```sql
   obclient> CREATE TABLE test1 (c1 INT,c2 INT);
   Query OK, 0 rows affected

   obclient> INSERT INTO test1(c1,c2) values (1,1);
   Query OK, 1 row affected
   ```

2. リストアポイント`rp1`を作成します。

   ```sql
   obclient> CREATE RESTORE POINT rp1;
   Query OK, 0 rows affected
   ```

3. テーブル`test1`にさらにデータを挿入し、コミットします。

   ```sql
   obclient> INSERT INTO test1(c1,c2) values (2, 2),(3,3);
   Query OK, 2 rows affected
   Records: 2  Duplicates: 0  Warnings: 0

   obclient> commit;
   Query OK, 0 rows affected
   ```

4. テーブル`test1`の現在のバージョンのデータをクエリします。

   ```sql
   obclient> SELECT * FROM test1;
   +------+------+
   | c1   | c2   |
   +------+------+
   |    1 |    1 |
   |    2 |    2 |
   |    3 |    3 |
   +------+------+
   3 rows in set
   ```

5. 作成したリストアポイント`rp1`の情報を確認し、バージョン番号に基づいて履歴バージョンのデータを確認します。

   ```sql
   obclient> SELECT * FROM V$RESTORE_POINT;
   +-----------+------------------+----------------------------+------+
   | TENANT_ID | SNAPSHOT         | TIME                       | NAME |
   +-----------+------------------+----------------------------+------+
   |      1001 | 1630407064663511 | 2021-08-31 18:51:04.665692 | rp1  |
   +-----------+------------------+----------------------------+------+
   1 row in set

   obclient> SELECT * FROM test1 AS OF SNAPSHOT 1630407064663511;
   +------+------+
   | c1   | c2   |
   +------+------+
   |    1 |    1 |
   +------+------+
   1 row in set
   ```
