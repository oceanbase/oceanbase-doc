# ALTER TABLE

## 概要

このステートメントは、既存のテーブルの構造を変更するために使用されます。例えば、テーブルおよびテーブルプロパティの変更、列の追加、列およびプロパティの変更、列の削除などを行います。

## 構文

```sql
ALTER TABLE table_name [alter_option [, alter_option] ...]
    [partition_options]

alter_option: {
      table_options
      ADD [COLUMN] col_name column_definition
          [FIRST | BEFORE | AFTER column_name]
    | ADD [COLUMN] (col_name column_definition, ...)
    | ADD {INDEX | KEY} [index_name]
          [index_type] (key_part,...) [index_option [ index_option ...]
    | ADD [CONSTRAINT [constraint_name]] UNIQUE [INDEX | KEY]
          [index_name] index_desc
    | ADD [CONSTRAINT [constraint_name]] FOREIGN KEY
          [index_name] index_desc
          REFERENCES reference_definition
          [match_action][reference_option [,reference_option ...]]
    | ADD PRIMARY KEY (column_name)
    | ADD CONSTRAINT [constraint_name] CHECK (expression)[[NOT] ENFORCED]
    | ADD PARTITION (range_partition [, range_partition ...])
    | ALTER [COLUMN] column_name {
          SET DEFAULT const_value
        | DROP DEFAULT
      }
    | ALTER {CHECK | CONSTRAINT} symbol [NOT] ENFORCED
    | ALTER INDEX index_name
          [VISIBLE | INVISIBLE]
    | CHANGE [COLUMN] column_name column_definition
    | DROP [COLUMN] column_name [, DROP COLUMN column_name ...]
    | DROP [COLUMN] column_name
    | DROP {PARTITION | SUBPARTITION} partition_name [, partition_name ...]
    | DROP TABLEGROUP
    | DROP FOREIGN KEY fk_name
    | DROP PRIMARY KEY [, ADD PRIMARY KEY (column)]
    | DROP INDEX index_name
    | DROP CHECK constraint_name
    | MODIFY [COLUMN] column_definition
    | RENAME COLUMN old_col_name TO new_col_name
    | RENAME [TO] table_name
    | RENAME {INDEX | KEY} old_index_name TO new_index_name
    | [SET] table_option [ table_option ...]
    | TRUNCATE {PARTITION | SUBPARTITION} partition_name [, partition_name ...]
    | MODIFY PARTITION partition_name ADD SUBPARTITION (add_subpartition_option)
    | FORCE

column_definition:
    column_name data_type
    [DEFAULT const_value] [AUTO_INCREMENT]
    [NULL | NOT NULL] [[PRIMARY] KEY] [UNIQUE [KEY]] comment
    [[FIRST | BEFORE | AFTER column_name]]

index_desc:
   (column_desc [, column_desc ...]) [index_type] [index_option [ index_option ...]]

column_desc:
     column_name [(length)] [ASC | DESC]

match_action:
   MATCH {SIMPLE | FULL | PARTIAL}

reference_option:
   ON {DELETE | UPDATE} {RESTRICT | CASCADE | SET NULL | NO ACTION | SET DEFAULT}

key_part:
    {index_col_name [(length)] | (expr)} [ASC | DESC]

index_type:
    USING BTREE

index_option:
     [GLOBAL | LOCAL]
    | block_size
    | compression
    | STORING(column_name [, column_name ...])
    | comment
    | KEY_BLOCK_SIZE [=] INT_VALUE

table_option:
      TABLEGROUP = tablegroup_name
    | block_size
    |lob_inrow_threshold [=] num
    | compression
    | AUTO_INCREMENT [=] INT_VALUE
    | comment
    | parallel_clause
    | READ {ONLY \| WRITE}
    | KEY_BLOCK_SIZE [=] INT_VALUE
    | TABLE_MODE [=] 'table_mode_value'
    | auto_increment_cache_size [=] INT_VALUE
    | DUPLICATE_SCOPE= 'none | cluster'

parallel_clause:
    {NOPARALLEL | PARALLEL integer}

table_mode_value:
    NORMAL
    | QUEUING
    | MODERATE
    | SUPER
    | EXTREME

partition_options:
    partition_option [partition_option] ...

partition_option:
      PARTITION BY HASH(expression)
      [subpartition_option] PARTITIONS partition_count
    | PARTITION BY KEY([column_name [, column_name ...]])
      [subpartition_option] PARTITIONS partition_count
    | PARTITION BY RANGE {(expression) | COLUMNS (column_name [, column_name ...])}
      [subpartition_option] (range_partition [, range_partition ...])

subpartition_option:
      SUBPARTITION BY HASH(expression)
      SUBPARTITIONS subpartition_count
    | SUBPARTITION BY KEY(column_name [, column_name ...])
      SUBPARTITIONS subpartition_count
    | SUBPARTITION BY RANGE {(expression) | COLUMNS (column_name [, column_name ...])}
      (range_subpartition [, range_subpartition ...])

range_partition:
    PARTITION partition_name
    VALUES LESS THAN {(expression [, expression ...]) | MAXVALUE}

range_subpartition:
    SUBPARTITION subpartition_name
    VALUES LESS THAN {(expression [, expression ...]) | MAXVALUE}

partition_count | subpartition_count:
    INT_VALUE

add_subpartition_option:
    {SUBPARTITION subpartition_name VALUES LESS THAN range_partition_expr
        [, SUBPARTITION subpartition_name VALUES LESS THAN range_partition_expr] ...}
    | {SUBPARTITION subpartition_name VALUES IN list_partition_expr
        [, SUBPARTITION subpartition_name VALUES IN list_partition_expr] ...}
```

## パラメータの説明

| **カテゴリ**        |           **パラメータ**             |        **説明**                               |
|----------------|--------------------------------|----------------------------------------------|
|alter_option | ADD \[COLUMN\]                              | 列を追加し、生成列の追加もサポートしています。     |
| | \[FIRST  \| BEFORE \| AFTER column_name\]                  | 追加された列をテーブルの最初の列として、または `column_name` 列の直前または直後に配置します。現在、OceanBaseデータベースでは、`ADD COLUMN`構文でのみ列の位置を設定できます。     |
||ADD {INDEX \| KEY}|テーブルにインデックスを追加します。|
||ADD [CONSTRAINT UNIQUE [INDEX \| KEY]|一意性制約を追加します。|
| | ADD FOREIGN KEY                                            | 外部キーを追加します。外部キー名を指定しない場合、テーブル名 + `OBFK` + 作成日時で自動的に命名されます。(例: 2021年8月1日00:00:00に`t1`テーブルに作成された外部キー名は`t1_OBFK_1627747200000000`になります)。外部キーは、テーブル間で関連するデータをクロスリファレンスするための機能を持ちます。`UPDATE`または`DELETE`操作が親テーブルのキー値と子テーブルの一致する行に影響を与える場合、その結果は`ON UPDATE`および`ON DELETE`句の参照操作によって決まります：<ul><li>`CASCADE`：親テーブルから行を削除または更新すると、同時に子テーブルの一致する行も自動的に削除または更新されます。</li><li>`SET NULL`：親テーブルから行を削除または更新すると、子テーブルの外部キー列が`NULL`に設定されます。</li><li>`RESTRICT`：親テーブルに対する削除または更新操作を拒否します。</li><li>`NO ACTION`：遅延チェックを指定します。</li></ul>また、`SET DEFAULT`操作もサポートされています。<main id="notice" type='notice'><h4>注意</h4><p>外部キー制約を追加する際には、現在のユーザーが親テーブルに対して<code>REFERENCES</code>権限を持っていることを確認してください。</p></main>|
| | ADD PRIMARY KEY                                            | 主キーを追加します。1つ以上の列を主キーとして指定できます。複数の列を指定した場合、それらは複合主キーとなります。               |
| | ADD \[PARTITION\]                                          | パーティションテーブルにパーティションを追加します。  |
| | ALTER INDEX                                                | インデックスの可視性を変更します。インデックスの状態が`INVISIBLE`の場合、SQLオプティマイザーはそのインデックスを選択しません。    |
| | key_part        | 関数インデックスを作成します。 |
| | index_col_name  | インデックスの列名を指定します。各列名の後ろに`ASC`(昇順)を指定できます。現在のバージョンでは、降順(`DESC`)のインデックス構文のみがサポートされており、その他の機能は有効になりません。デフォルトは昇順です。インデックスのソート方法は、まず`index_col_name`内の最初の列の値でソートします。その列の値が同じレコードについては、次の列名の値でソートし、このように続きます。 |
| | CHECK                                                      | `CHECK`制約を変更します。以下の操作をサポートしています：<ul><li>新しい`CHECK`制約を追加します。</li>   <li>現在の名前が`constraint_name`の`CHECK`制約を削除します。</li>  </ul>  |
| | expr            | 合法的な関数インデック表現式を表し、論理式も許可されます。例えば、`c1=c1`。<br>**注意** OceanBaseデータベースの現在のバージョンでは、生成列に対して関数インデックスの作成が禁止されています。             |
| | \[NOT\] ENFORCED                                           | `constraint_name` という名前の `CHECK` 縛りを強制的に適用するかどうかを指定します。 <ul><li> 省略または `ENFORCED` を指定した場合、デフォルト状態として、制約を作成し強制的に適用します。</li>   <li> `NOT ENFORCED` を指定した場合、制約を作成しますが、強制的に適用しません。</li> </ul>   |
| | ALTER \[COLUMN\] {SET DEFAULT const_value \| DROP DEFAULT} | 列のデフォルト値を変更します。  |
| | CHANGE \[COLUMN\]                                          | 列名と列定義を変更します。特定の文字データ型 (`VARCHAR`、`VARBINARY`、`CHAR` など) の長さを増やす場合にのみサポートされます。    |
| | DROP \[COLUMN\]                                            | 列を削除します。主キー列は削除できません。   |
| | DROP {PARTITION \| SUBPARTITION}                           | パーティションを削除します： <ul><li> `PARTITION`：Range、List タイプのパーティションに対して、指定されたパーティションを削除します（指定されたパーティションにサブパーティションが存在する場合は、同時にそのパーティション内のすべてのサブパーティションも削除します）。パーティション定義とその中のデータを含め、パーティション上に存在するインデックスもメンテナンスします。</li>   <li> `SUBPARTITION`：`*-RANGE`、`*-LIST` タイプのサブパーティションに対して、指定されたサブパーティションを削除します。パーティション定義とその中のデータを含め、パーティション上に存在するインデックスもメンテナンスします。</li></ul>    複数のパーティション名はカンマで区切ります。<br> **注意** パーティションを削除する際は、そのパーティション上にアクティブなトランザクションやクエリが存在しないようにしてください。そうでない場合、SQL ステートメントがエラーになる可能性があります。また、一部の例外状況が発生する可能性もあります。   |
| | DROP \[TABLEGROUP\]                                        | テーブルグループを削除します。  |
| | DROP \[FOREIGN KEY\]                                       | 外部キーを削除します。  |
| | DROP \[PRIMARY KEY\]                                       | 主キーを削除します。<main id="notice" type='explain'><h4>説明</h4><p>MySQLモードでは、以下の条件では主キーを削除することはできません：<ul><li>このテーブルが外部キー情報を含む親テーブルである場合。</li> <li>このテーブルが子テーブルであり、かつ主キー列に外部キー参照列が含まれている場合。</li> </ul> </p>|
| | DROP INDEX index_name | 索引を削除します。<main id="notice" type='notice'><h4>注意</h4><p><ul><li>既存の実装では、同時にインデックスの追加と削除を行う機能は非原子的であり、システムが一定期間インデックスが利用不可な状態になる可能性があります(例えば、インデックス <code>idx1_tbl1(col1, col2)</code> を <code>idx1_tbl2(col1, col2, col3)</code> に変更する場合、<code>ALTER TABLE tbl1 DROP INDEX idx1_tbl1, ADD INDEX idx1_tbl2(col1, col2, col3);</code> を実行すると、まず既存のインデックス <code>idx1_tbl1</code> を削除し、その後にインデックス <code>idx1_tbl2</code> を作成します。この過程で、<code>idx1_tbl1</code> が一時的に存在せず、<code>idx1_tbl2</code> もまだ作成されていない期間が生じるためです)。そのため、OceanBaseデータベースV4.2.5バージョンにおいて、この操作はV4.2.5 BP1バージョンから無効化されています。</li><li>コマンド <code>ALTER SYSTEM SET _enable_drop_and_add_index = true;</code> を使用して構成パラメータを有効化することで、1つのSQLステートメント内で同時にインデックスの追加と削除操作を許可することができますが、この操作は慎重に使用する必要があります。</li></ul></p></main>|
| | MODIFY \[COLUMN\]                                          | 列属性を変更します。 |
| | RENAME COLUMN old_col_name TO new_col_name| 列名を変更します。列名のみを変更し、列定義は変更されません。   <main id="notice" type='notice'><h4>注意</h4> <p><ul><li>ターゲットの名前がテーブル内にすでに存在する場合、実行時にエラーが発生します。</li><li>リネームされる列に循環参照がある場合は、正常に実行できます。例えば <code>ALTER TABLE t1 RENAME COLUMN a to b, RENAME COLUMN b to a;</code>。</li><li>リネームされる列にインデックスが作成されているか、外部キー制約がある場合、<code>RENAME COLUMN</code> は正常に実行でき、インデックス定義および外部キー制約は自動的に連鎖的に変更されます。</li><li>同じ <code>ALTER TABLE</code> ステートメント内で、<code>RENAME COLUMN</code> と <code>ADD PARTITION</code>／<code>ALTER COLUMN</code> の同時実行はサポートされていません。</li></ul></p></main>|
| | RENAME \[TO\] table_name                                   | テーブル名の変更。 <main id="notice" type='notice'><h4>注意</h4><p><code>RENAME TABLE</code> 操作中、テーブルロックと読み書き防御措置が追加されたため、操作にかかる時間が増加します。他のユーザーによるDDL操作への影響を避けるため、<code>RENAME TABLE</code> 操作を一括で実行することは推奨されません。</p></main>|
| | RENAME {INDEX \| KEY}                                      | インデックスまたはキーのリネーム。   |
| | \[SET\] table_option                                       | テーブルレベルのプロパティを設定します。以下のパラメータが選択可能です：<ul><li> `REPLICA_NUM`：テーブルのレプリカ数を設定します（現在サポートされていません）。</li>   <li> `tablegroup_name`：テーブルが属するテーブルグループを設定します。</li>   <li> `BLOCK_SIZE`：テーブルのマイクロブロックサイズを設定します。デフォルトは `16384`（つまり16KB）で、値の範囲は \[1024,1048576\] です。</li>  <li> `lob_inrow_threshold`：`INROW` のしきい値を設定します。LOBデータのサイズがこのしきい値を超えると、`OUTROW` ストレージに変換され、LOB Metaテーブルに格納されます。デフォルトは4KBです。</li>   <li> `COMPRESSION`：テーブルの圧縮方式を設定します。デフォルトは `None` で、圧縮されないことを意味します。</li>   <li> `AUTO_INCREMENT`：テーブル内の自動インクリメント列の次の値を設定します。増加または減少させることができます。<main id="notice" type='notice'><h4>注意</h4><p>テーブルの自動インクリメントフィールドの値を減らす場合、以下の点にご注意ください：</br>テーブル内に既存データがあり、かつ自動インクリメント列の最大値が新しい <code>AUTO_INCREMENT</code> 値以上である場合、新しい <code>AUTO_INCREMENT</code> 値は自動的にテーブル内の自動インクリメント列の現在の最大値の次の値に調整されます。例えば、自動インクリメント列の現在の最大値が5で、現在の <code>AUTO_INCREMENT</code> の値が8の場合、<code>AUTO_INCREMENT</code> を0から6の間の任意の値に設定すると、ステートメントが正常に実行された後、実際の <code>AUTO_INCREMENT</code> の値はすべて6に調整されます。</p></main></li>   <li> `comment`：テーブルのコメント情報を設定します。</li>   <li> `PROGRESSIVE_MERGE_NUM`：段階的なマージのステップ数を設定します。値の範囲は \[0,100\] です。</li>   <li> `parallel_clause`：テーブルレベルの並列度を指定します。</li> <li> `NOPARALLEL`：並列度が `1` で、デフォルト設定です。</li>   <li> `PARALLEL integer`：並列度を指定します。`integer` の値は `1` 以上です。</li> </ul>     |
| | READ {ONLY \| WRITE} | テーブルの読み書き権限を指定します。詳細は以下のとおりです：<ul><li>`READ ONLY`：テーブルは読み取り専用であり、変更や削除できません。<main id="notice" type='notice'><h4>注意</h4><p>テーブルレベルの <code>READ ONLY</code> パラメータは、<code>SUPER</code> 権限を持つユーザーには効果がありません。通常のユーザーのみに適用されます。</p></main></li><li>`READ WRITE`：デフォルト値で、テーブルは読み取り、変更、および削除できます。</li></ul>|
| | TRUNCATE {PARTITION \| SUBPARTITION}                       | パーティションデータを削除します：<ul><li> `PARTITION`：RangeおよびListタイプのパーティションに対して、指定したパーティション内のすべてのデータを削除します（指定したパーティションにサブパーティションが存在する場合、そのパーティション内のすべてのサブパーティションのデータも同時に削除されます）。また、パーティション上のインデックスもメンテナンスされます。</li>   <li> `SUBPARTITION`：`*-RANGE` および `*-LIST` タイプのサブパーティションに対して、指定したサブパーティション内のすべてのデータを削除します。同時に、パーティション上のインデックスもメンテナンスされます。</li> </ul>   複数のパーティション名はカンマで区切ります。<br> **注意** パーティションデータを削除する際は、そのパーティション上にアクティブなトランザクションやクエリがないようにしてください。そうでない場合、SQLステートメントがエラーになるか、一部の異常状況が発生する可能性があります。 |
| | DUPLICATE_SCOPE | レプリケーションテーブルプロパティを変更します。<ul><li>`none`：現在のテーブルを通常テーブルに変換することを示します。</li><li>`cluster`：現在のテーブルをレプリケーションテーブルに変換することを示します。</li></ul> 詳細については、[レプリケーションテーブルプロパティの変更](../../../../300.database-object-management/100.manage-object-of-mysql-mode/200.manage-tables-of-mysql-mode/650.change-duplicate-scope-of-mysql-mode.md)を参照してください。|
|index_option | KEY_BLOCK_SIZE [=] INT_VALUE | オプションで、インデックスキー・ブロックのサイズ(バイト単位)を指定します。テーブルまたはインデックスの圧縮度を制御するために使用されます。現在のバージョンではこのキーワード構文のみがサポートされており、機能は有効になりません。|
|table_option | TABLE_MODE | オプションで、マージトリガーしきい値とマージ戦略を指定します。つまり、データダンプ後のマージ動作を制御します。値の詳細については、以下の[table_mode_value](#table_mode_value)を参照してください。|
| | auto_increment_cache_size | キャッシュされる自動インクリメント値の数を設定します。このパラメータのデフォルト値は0であり、この項目が設定されていないことを示します。システムはテナントレベルのパラメータ([auto_increment_cache_size](../../../../800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/300.auto_increment_cache_size-global.md))を使用して自動インクリメント列のキャッシュサイズを設定します。|
|partition_option | PARTITION BY {HASH(key) ...} PARTITIONS partition_count | パーティションキー、方法および数を定義します。パーティション操作には、パーティション再分割、パーティション追加、パーティション削除、パーティションクリアが含まれます。詳細については、[パーティション操作](../700.ddl-function-of-mysql-mode/800.partitioning-operations-of-mysql-mode.md)を参照してください。 |
|subpartition_option|SUBPARTITION BY {HASH(expression) ...}|各パーティションに対して、サブパーティションスキームを定義します。|
|range_partition|PARTITION partition_name VALUES LESS THAN {value}| Range/Range Columnsパーティションの一階層または二階層パーティションの定義を指定します。|
| add_subpartition_option | MODIFY PARTITION partition_name ADD SUBPARTITION (add_subpartition_option) | 二階層パーティションを追加します。<main id="notice" type='notice'><h4>注意</h4><p><ul><li>ハッシュまたはキー型の二階層パーティションタイプのシナリオでは、二階層パーティションを追加できません。</li><li>OceanBaseデータベースV4.2.5では、V4.2.5 BP4以降のバージョンから二階層パーティションの追加がサポートされています。</li></ul></p></main>|
| add_subpartition_option | add_subpartition_option | 追加された二階層パーティションの定義を示します。|
| add_subpartition_option | range_partition_expr    | Range/Range Columnsパーティション式を示します。|
| add_subpartition_option | list_partition_expr     | List/List Columnsパーティション式を示します。|
|| FORCE |廃棄列を削除します。<main id="notice" type='explain'><h4>説明</h4><p><ul><li>OceanBaseデータベースV4.2.5では、V4.2.5 BP5以降のバージョンから廃棄列の削除がサポートされています。</li><li>一部の列が削除されても、それらの列が使用されなくなったとしても、物理ストレージ領域を占有しています。これらの廃棄列を削除し、関連領域を回収するには、廃棄列を削除する必要があります。</li></ul></p></main>|

### table_mode_value

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>以下のリストに示されている <code>TABLE_MODE</code> モードにおいて、<code>NORMAL</code> モードを除くすべてのモードは <code>QUEUING</code> テーブルを表します。この <code>QUEUING</code> テーブルは最も基本的なテーブルタイプであり、その後に記載されるいくつかのモード（NORMAL モードを除く）はより積極的なマージ戦略を使用しています。</p>
</main>

* `NORMAL`：デフォルト値で、通常を意味します。このモードでは、データダンプ後にマージがトリガーされる確率は非常に低いです。
* `QUEUING`：このモードでは、データダンプ後にマージがトリガーされる確率は低いです。
* `MODERATE`：適度であることを意味します。このモードでは、データダンプ後にマージがトリガーされる確率は中程度です。
* `SUPER`：スーパーであることを意味します。このモードでは、データダンプ後にマージがトリガーされる確率は高いです。
* `EXTREME`：極端であることを意味します。このモードでは、ダンプ後マージがトリガーされる確率が高いです。

マージに関する詳細については、[適応的マージ](../../../../200.system-management/500.manage-data-storage/200.merge-management/320.adaptive-compavtion.md)を参照してください。

  ```shell
  obclient> CREATE TABLE tbl12(a INT, b INT AS (a + 1), c INT, d INT, CONSTRAINT d_check CHECK(d > 0)) PARTITION BY HASH(c + 1) PARTITIONS 2;

  obclient> ALTER TABLE tbl12 RENAME COLUMN a TO e;

  ```

* リネームされる列がパーティション式によって参照されている場合、列名の変更はサポートされておらず、実行時にエラーが発生します。

  ```shell
  obclient> ALTER TABLE tbl12 RENAME COLUMN c TO e;
  ERROR 3855 (HY000): Column 'c' has a partitioning function dependency and cannot be dropped or renamed.
  ```

* リネームされる列が `CHECK` 約束によって参照されている場合、列名の変更はサポートされておらず、実行時にエラーが発生します。

  ```shell
  obclient> ALTER TABLE tbl12 RENAME COLUMN d TO e;
  ERROR 3959 (HY000): Check constraint 'd_check' uses column 'd', hence column cannot be dropped or renamed.
  ```

* リネームされる列が関数インデックスによって参照されている場合、列名の変更はサポートされておらず、実行時にエラーが発生します。

  ```shell
  DROP TABLE IF EXISTS tbl12;
  obclient> CREATE TABLE tbl12(i INT, INDEX ((i+1)));
  Query OK, 0 rows affected

  obclient> ALTER TABLE tbl12 RENAME COLUMN i TO j;
  ERROR 3837 (HY000): Column 'i' has a functional index dependency and cannot be dropped or renamed.
  ```

* リネームされる列がビューによって参照されている場合、`RENAME COLUMN`の実行は成功しますが、ビューのクエリ時にエラーが発生します。このため、ユーザーによるビュー定義の手動修正が必要です。

  ```shell
  obclient> CREATE TABLE tbl13(a INT);
  Query OK, 0 rows affected

  obclient> CREATE VIEW v1 AS SELECT a + 1 FROM tbl13;
  Query OK, 0 rows affected

  obclient> SELECT * FROM v1;
  Empty set

  obclient> ALTER TABLE tbl13 RENAME COLUMN a TO b;
  Query OK, 0 rows affected

  obclient> SELECT * FROM v1;
  ERROR 1356 (42S22): View 'test.v1' references invalid table(s) or column(s) or function(s) or definer/invoker of view lack rights to use them
  ```

* リネームされる列がストアドプロシージャによって参照されている場合、`RENAME COLUMN`の実行は成功しますが、`CALL` Procedureの呼び出し時にエラーが発生します。このため、ユーザーによる手動修正が必要です。

  ```shell
  obclient> CREATE TABLE tbl14(a INT);
  Query OK, 0 rows affected

  obclient> CREATE PROCEDURE proc() SELECT a + 1 FROM tbl14;
  Query OK, 0 rows affected

  obclient> CALL proc();
  Empty set

  obclient> ALTER TABLE tbl14 RENAME COLUMN a TO b;
  Query OK, 0 rows affected

  obclient> CALL proc();
  ERROR 1054 (42S22): Unknown column 'a' in 'field list'
  ```
