# CREATE TABLE

## 説明

このステートメントは、データベース内に新しいテーブルを作成するために使用されます。

## 構文

```sql
CREATE [hint_options] TABLE [IF NOT EXISTS] table_name
      (table_definition_list) [table_option_list] [partition_option] [IGNORE | REPLACE] [AS] select;

CREATE TABLE [IF NOT EXISTS] table_name
      LIKE table_name;

table_definition_list:
    table_definition [, table_definition ...]

table_definition:
      column_definition
    | [CONSTRAINT [constraint_name]] PRIMARY KEY index_desc
    | [CONSTRAINT [constraint_name]] UNIQUE {INDEX | KEY} [index_name] index_desc
    | [CONSTRAINT [constraint_name]] FOREIGN KEY [index_name] (column_name, ...) reference_definition
    | {INDEX | KEY} [index_name] [index_type] (key_part,...) [index_optionn_list]
    | [CONSTRAINT [constraint_name]] CHECK(expression) [NOT ENFORCED | ENFORCED]

column_definition_list:
    column_definition [, column_definition ...]

column_definition:
     column_name data_type
         [DEFAULT const_value] [AUTO_INCREMENT]
         [NULL | NOT NULL] [[PRIMARY] KEY] [UNIQUE [KEY]] comment
         [COLUMN_FORMAT {FIXED | DYNAMIC | DEFAULT}]
         [STORAGE {DISK | MEMORY}]
         [reference_definition]
   | column_name data_type
         [GENERATED ALWAYS] AS (expr) [VIRTUAL | STORED]
         [opt_generated_column_attribute]
         [reference_definition]

index_desc:
    (column_desc_list) [index_type] [index_option_list]

reference_definition:
    REFERENCES tbl_name (key_part,...)
    [match_action] [opt_reference_option_list]

match_action:
    MATCH {SIMPLE | FULL | PARTIAL}

opt_reference_option_list:
    reference_option [,reference_option ...]

reference_option:
    ON {DELETE | UPDATE} {RESTRICT | CASCADE | SET NULL | NO ACTION | SET DEFAULT}

key_part:
    {index_col_name [(length)] | (expr)} [ASC | DESC]

index_type:
    USING BTREE

index_option_list:
    index_option [ index_option ...]

index_option:
      [GLOBAL | LOCAL]
    | block_size
    | compression
    | STORING(column_name_list)
    | comment
    | KEY_BLOCK_SIZE [=] INT_VALUE
    | WITH PARSER parser_name

table_option_list:
    table_option [ table_option ...]

table_option:
      [DEFAULT] {CHARSET | CHARACTER SET} [=] charset_name
    | [DEFAULT] COLLATE [=] collation_name
    | table_tablegroup
    | block_size
    | lob_inrow_threshold [=] num
    | compression
    | AUTO_INCREMENT [=] INT_VALUE
    | comment
    | TTL (ttl_definition)
    | ROW_FORMAT [=] REDUNDANT|COMPACT|DYNAMIC|COMPRESSED|DEFAULT
    | PCTFREE [=] num
    | parallel_clause
    | READ {ONLY | WRITE}
    | DUPLICATE_SCOPE [=] 'none|cluster'
    | KEY_BLOCK_SIZE [=] INT_VALUE
    | TABLE_MODE [=] 'table_mode_value'
    | auto_increment_cache_size [=] INT_VALUE
    | AVG_ROW_LENGTH [=] value
    | CHECKSUM [=] {0 | 1}
    | CONNECTION [=] 'connect_string'
    | {DATA | INDEX} DIRECTORY [=] 'absolute path to directory'
    | DELAY_KEY_WRITE [=] {0 | 1}
    | ENCRYPTION [=] {'Y' | 'N'}
    | ENGINE [=] engine_name
    | INSERT_METHOD [=] { NO | FIRST | LAST}
    | MAX_ROWS [=] value
    | MIN_ROWS [=] value
    | PACK_KEYS [=] {0 | 1 | DEFAULT}
    | PASSWORD [=] 'string'
    | STATS_AUTO_RECALC [=] {DEFAULT | 0 | 1}
    | STATS_PERSISTENT [=] {DEFAULT | 0 | 1}
    | STATS_SAMPLE_PAGES [=] value
    | UNION [=] (tbl_name[,tbl_name]...)

parallel_clause:
    {NOPARALLEL | PARALLEL integer}

table_mode_value:
    NORMAL
    | QUEUING
    | MODERATE
    | SUPER
    | EXTREME

partition_option:
      PARTITION BY HASH(expression)
      [subpartition_option] PARTITIONS partition_count
    | PARTITION BY KEY([column_name_list])
      [subpartition_option] PARTITIONS partition_count
    | PARTITION BY RANGE {(expression) | COLUMNS (column_name_list)}
      [subpartition_option] (range_partition_list)
    | PARTITION BY LIST {(expression) | COLUMNS (column_name_list)}
      [subpartition_option] PARTITIONS partition_count

subpartition_option:
      SUBPARTITION BY HASH(expression)
      SUBPARTITIONS subpartition_count
    | SUBPARTITION BY KEY(column_name_list)
      SUBPARTITIONS subpartition_count
    | SUBPARTITION BY RANGE {(expression) | COLUMNS (column_name_list)}
      (range_subpartition_list)
    | SUBPARTITION BY LIST(expression)

range_partition_list:
    range_partition [, range_partition ...]

range_partition:
    PARTITION partition_name
    VALUES LESS THAN {(expression_list) | MAXVALUE}

range_subpartition_list:
    range_subpartition [, range_subpartition ...]

range_subpartition:
    SUBPARTITION subpartition_name
    VALUES LESS THAN {(expression_list) | MAXVALUE}

expression_list:
    expression [, expression ...]

column_name_list:
    column_name [, column_name ...]

partition_name_list:
    partition_name [, partition_name ...]

partition_count | subpartition_count:
    INT_VALUE
```

## パラメータの説明

|                        **パラメータ**                        |        **説明**        |
|------------------------------------------------------|-----------------------------------|
| hint_options | ヒントオプションを指定します。オプションです。<main id="notice" type='notice'><h4>注意</h4><p>現在のバージョンでは、<code>CREATE TABLE</code> ステートメントのヒントオプションは <code>/*+ parallel(N) */</code> タイプに限定されており、ここで <code>N</code> は並列度です。また、このヒントオプションは <code>CREATE TABLE ... AS SELECT ...</code> のシナリオにのみ適用され、テーブル作成時のデータクエリと書き込み操作の並列度を制御できます。</p></main>|
| IF NOT EXISTS | `IF NOT EXISTS` を指定した場合、作成対象のテーブルが既に存在していてもエラーは報告されません。指定されていない場合、作成対象のテーブルが既に存在すると、システムはエラーを報告します。 |
| IGNORE \| REPLACE | オプションであり、`CREATE TABLE ... SELECT` ステートメントを使用する際に、重複する一意キー値の行をどのように処理するかを指示します。重複する一意キー値の行がある場合、<code>IGNORE</code> または <code>REPLACE</code> を指定しないとエラーが発生します。<ul><li><code>IGNORE</code>：新しいテーブルの一意キー値とコピーされたデータの特定の行との間で競合が発生した場合、その競合する行は無視され、新しいテーブルにコピーされません。<code>IGNORE</code> オプションは重複するデータをスキップし、一意キーの競合を引き起こさない行のみをコピーします。</li><li><code>REPLACE</code>：一意キー値が重複するデータ行に遭遇した場合、元の新しいテーブルの行は新しくコピーされたデータの行に置き換えられます。</li></ul>|
| PRIMARY KEY                                          | 作成するテーブルに主キーを指定します。指定しない場合は、隠れた主キーが使用されます。OceanBaseデータベースは、テーブルの主キーを変更すること、または `ALTER TABLE` ステートメントを使用してテーブルに主キーを追加することをサポートしています。詳細については、[ALTER TABLE](1600.alter-table-of-mysql-mode.md)を参照してください。    |
| FOREIGN KEY                                          | 作成するテーブルに外部キーを指定します。外部キー名を指定しない場合、テーブル名 + `OBFK` + 作成時間を使用して命名されます（例えば、2021年8月1日00:00:00に `t1` テーブルに作成された外部キー名は `t1_OBFK_1627747200000000` です）。外部キーは、テーブル間で関連データを相互参照することを許可します。詳細については、以下の[reference_definition](#reference_definition)を参照してください。<main id="notice" type='notice'><h4>注意</h4><p>外部キー制約を追加する際には、現在のユーザーが親テーブルに対して <code>REFERENCES</code> 権限を持っていることを確認する必要があります。</p></main>|
| KEY \| INDEX                                         | 作成するテーブルにキーまたはインデックスを指定します。インデックス名を指定しない場合、インデックス参照の最初の列をインデックス名として使用します。命名に重複がある場合は、アンダースコア（_）+ 番号の方法で命名されます（例えば、`c1` 列を使用して作成されたインデックスに命名の重複がある場合、インデックス名は `c1_2` となります）。`SHOW INDEX` ステートメントを使用して、テーブル上のインデックスを表示できます。    |
| key_part        | （関数）インデックスを作成します。 |
| index_col_name  | インデックスの列名を指定します。各列名の後ろに `ASC`（昇順）をサポートします。現在のバージョンでは、降順（`DESC`）ソートインデックス構文のみがサポートされており、機能は有効ではありません。デフォルトは昇順です。インデックスのソート方式は次のとおりです：まず `index_col_name` 内の最初の列の値でソートします。その列の値が同じレコードは、次の列名の値でソートします。これを繰り返します。 |
| expr            | 有効な関数インデックス式を表し、ブール式を許可します。例えば、`c1=c1` です。<main id="notice" type='notice'><h4>注意</h4><p>OceanBaseデータベースの現在のバージョンでは、生成列上の関数インデックスの作成は禁止されています。 </p></main>              |

### reference_definition

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>列定義後に <code>reference_definition</code> ステートメントを追加する場合、関連する構文のみがサポートされ、機能は有効になりません。例えば、<code>CREATE TABLE tb11(id INT PRIMARY KEY, sid INT REFERENCES tb11(id) MATCH FULL ON DELETE SET NULL);</code> このステートメントは正常に実行されますが、<code>MATCH FULL</code> および外部キー制約の動作（この例では <code>ON DELETE SET NULL</code> を指します）は実際には有効になりません。外部キーの追加が必要な場合は、<code>Foreign Key</code> の句で指定してください。この動作はMySQL 5.7と互換性があります。</p>
</main>

* `REFERENCES tbl_name (key_part,...)`：外部キーが参照するプライマリテーブルと列を指定します。

  * `tbl_name`：参照されるテーブルの名前、つまり外部キーが参照するプライマリテーブルの名前です。
  * `key_part`：参照されるテーブル内の列名、つまり外部キーが参照するプライマリテーブルの列です。ほとんどの場合、これは主キーまたは一意キーの列です。

* `match_action`：外部キー制約チェック時に使用するマッチング方法を指定します。単純、完全、または部分的です。

  * `MATCH SIMPLE`：デフォルト値。外部キーのいずれかの列が `NULL` の場合、外部キー制約はチェックされません。
  * `MATCH FULL`：参照される外部キー列がマッチと見なされる場合、すべての外部キー列は非 `NULL` 値である必要があります。
  * `MATCH PARTIAL`：外部キーが部分的に `NULL` であることを許可し、部分的なマッチも外部キー制約を満たすと見なされます。

* `opt_reference_option_list`：プライマリテーブルの値を削除または更新したときに、外部キーテーブルがどのように応答するかを定義します。以下のオプションが含まれます：

  * `ON DELETE`：プライマリテーブルの行が削除されたときに実行する操作を定義します。
  * `ON UPDATE`：プライマリテーブルの行が更新されたときに実行する操作を定義します。

  これらのオプションの後には、次のアクションを続けることができます：

  * `RESTRICT`：プライマリテーブルの行の削除または更新を阻止します。
  * `CASCADE`：プライマリテーブルの行が削除または更新されたとき、対応する外部キーテーブルの行を削除または更新します。
  * `SET NULL`：外部キーの対応する列を `NULL` に設定します（列が `NULL` 値を許可する場合）。
  * `NO ACTION`：`RESTRICT` と同様です。
  * `SET DEFAULT`：外部キーの対応する列をそのデフォルト値に設定します（列にデフォルト値がある場合）。

### table_mode_value

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>以下にリストされている <code>TABLE_MODE</code> モードでは、<code>NORMAL</code> モードを除くすべてのモードが <code>QUEUING</code> テーブルを表します。この <code>QUEUING</code> テーブルは最も基本的なテーブルタイプであり、その後にリストされているいくつかのモード（NORMALモードを除く）は、より積極的なコンパクション戦略を使用しています。</p>
</main>

* `NORMAL`：デフォルト値で、通常を表します。このモードでは、データダンプ後にコンパクションがトリガーされる確率は非常に低いです。
* `QUEUING`：このモードでは、データダンプ後にコンパクションがトリガーされる確率は低いです。
* `MODERATE`：適度を表します。このモードでは、データダンプ後にコンパクションがトリガーされる確率は中程度です。
* `SUPER`：スーパーを表します。このモードでは、データダンプ後にコンパクションがトリガーされる確率は高いです。
* `EXTREME`：極端を表します。このモードでは、ダンプ後にコンパクションがトリガーされる確率は高いです。

コンパクションの詳細については、[適応型コンパクション](../../../../200.system-management/500.manage-data-storage/200.merge-management/320.adaptive-compavtion.md)を参照してください。
