# SELECT文

SELECT文の構文は比較的複雑です。この節ではまず一般的なSELECT文の構文構造を紹介し、次にコレクション型のSELECT文の構文構造について説明します。

## 概要

このステートメントは、テーブル内の内容を照会するために使用されます。

## 構文

```sql
SELECT
        [/*+ hint statement */]
        [ALL | DISTINCT | UNIQUE | SQL_CALC_FOUND_ROWS]
        [HIGH_PRIORITY]
        [STRAIGHT_JOIN]
        [SQL_SMALL_RESULT] [SQL_BIG_RESULT] [SQL_BUFFER_RESULT]
        select_expr_list
        [FROM from_list [WHERE condition]]
        [GROUP BY group_expression_list [WITH ROLLUP] [HAVING condition]]
        [ORDER BY order_expression_list]
        [limit_clause]
        [FOR UPDATE [opt_for_update_wait]]
        [LOCK IN SHARE MODE];
select_expr:
 table_name.*
  | table_alias_name.*
  | expr [[AS] column_alias_name]

from_list:
      DUAL
    | table_reference [, table_reference ...]

table_reference:
      simple_table
    | joined_table
    | table_name@dblink_name

simple_table:
    table_factor [partition_option]
        [sample_clause [opt_seed]]
        [[AS] table_alias_name][index_hint]
    | (select_stmt [sample_clause [opt_seed])
        [AS] table_alias_name [index_hint]
    | (table_reference_list) [index_hint]

joined_table:
      table_reference [NATURAL][INNER] JOIN simple_table [join_condition]
    | table_reference outer_join_type JOIN simple_table join_condition

partition_option:
    PARTITION (partition_name_list)

sample_clause:
    SAMPLE [BLOCK] [ ALL | BASE | INCR] (sample_percent)

opt_seed:
    SEED(integer)

index_hint:
    {USE | FORCE | IGNORE} {KEY | INDEX}
       [FOR {JOIN | ORDER BY | GROUP BY}] (index_list)

index_list:
    index_name [, index_name ...]

partition_name_list:
    partition_name [, partition_name ...]

outer_join_type:
    [NATURAL]{LEFT | RIGHT | FULL} [OUTER]

join_condition:
    ON expression

condition:
    expression

group_expression_list:
    group_expression [, group_expression ...]

group_expression:
    expression [ASC | DESC]

order_expression_list:
    order_expression [, order_expression ...]

order_expression:
    expression [ASC | DESC]

limit_clause:
  LIMIT {[offset,] row_count |row_count OFFSET offset}

opt_for_update_wait:
    WAIT { DECIMAL | INTNUM }
  | NOWAIT | NO_WAIT
  | SKIP LOCKED
```

## パラメータの説明

|                                パラメータ                                |                           説明                       |
|--------------------------------------------------------------------|---------------------------------------------------------|
| ALL \| DISTINCT \| UNIQUE \| SQL_CALC_FOUND_ROWS                                            | データベーステーブルには、重複する値が含まれる場合があります。<ul><li>`DISTINCT` \| `UNIQUE`：クエリ結果の同じ行は1行のみ表示されます。</li>   <li>`ALL`：すべての行をリストアップします。デフォルトは `ALL` です。  </li>   <li>  `SQL_CALC_FOUND_ROWS`：`LIMIT` 句を持つクエリでは、すべての返された行数を記録し、次の実行される `FOUND_ROWS()` 関数ですべての行数を取得できます。</li></ul>    |
| HIGH_PRIORITY | オプションです。この `SELECT` ステートメントを、テーブル更新操作よりも高い優先順位に指定します。現在のバージョンでは、このキーワード構文のみサポートされており、機能は有効になりません。|
| STRAIGHT_JOIN | オプションです。オプティマイザーに、`FROM` 句で指定された順序でテーブルを結合するよう強制します。チューニングコマンドであり、実行結果には影響しません。<main id="notice" type='notice'><h4>注意</h4><p>OceanBaseデータベースは、MySQLにおける <code>STRAIGHT_JOIN</code> 構文とは完全に互換性がありません。<code>STRAIGHT_JOIN</code> がテーブル結合の順序を明示的に指定できる場合、OceanBaseデータベースはそのコマンドに基づいて実行します。そうでない場合は、OceanBaseデータベースはこのコマンドを無視します。</p></main>|
| SQL_SMALL_RESULT \| SQL_BIG_RESULT  | オプションです。`GROUP BY` または `DISTINCT` を使用する場合、`SQL_BIG_RESULT` または `SQL_SMALL_RESULT` を指定して、オプティマイザに結果セットのサイズを通知できます。現在のバージョンでは、このキーワード構文のみサポートされており、機能は有効になりません。|
| SQL_BUFFER_RESULT | オプションです。`SQL_BUFFER_RESULT` オプションを使用すると、結果セットを一時テーブルに強制的に保存します。現在のバージョンでは、このキーワード構文のみサポートされており、機能は有効になりません。|
| select_expr                                                                                 | クエリ対象の式または列名をカンマ（,）で区切ってリストアップします。また、アスタリスク（\*）を使用してすべての列を表すこともできます。   |
| AS othername                                                                                | 出力フィールドを再命名します。   |
| FROM table_references                                                                       | データを読み取るテーブルまたはテーブルのリストを指定します（マルチテーブルクエリをサポートしています）。   |
| WHERE where_conditions                                                                      | オプションです。`WHERE` 句は、フィルタリング条件を設定するために使用され、クエリ結果には条件を満たすデータのみが含まれます。`where_conditions` は式です。  |
| GROUP BY group_by_list                                                                      | 分類および集計に使用します。    |
| WITH ROLLUP                                                                                 | 各グループを集計してより上位の集計（超集計とも呼ばれます）を表し、追加の行を生成します。  |
| HAVING search_confitions                                                                    | `HAVING` 句は`WHERE`句と似ていますが、`HAVING`句では集計関数（例：`SUM`、`AVG`など）を使用できます。 |
| SAMPLE \[BLOCK\] \[ ALL \| BASE \| INCR\] (sample_percent)                                  | 一部のレコードのみをスキャンします。<ul><li> `BLOCK` はランダムなデータブロックをスキャンすることを示し、デフォルトではランダムな行をスキャンします。   </li>   <li>  `ALL` はすべてのデータをスキャンすることを示し、デフォルト値は`ALL`です。   </li>   <li>  `BASE` はベースラインデータをスキャンすることを示します。   </li>   <li>  `INCR` は増分データをスキャンすることを示します。   </li>   <li>  `sample_percent` はサンプリング比率で、単位は%です。`INTEGER`または`DECIMAL`タイプを使用できます。  </li></ul>                          |
| SEED integer                                                                                | サンプリングのシード値。範囲は \[0,4294967295\] です。同じサンプリングシード値は常に同じ結果を返します。  |
| {USE \| FORCE \| IGNORE} {KEY \| INDEX} \[FOR {JOIN \| ORDER BY \| GROUP BY}\] (index_list) | 指定されたインデックスを使用してクエリを実行するかどうかを指定します。<ul><li> `USE`：特定の操作でインデックスを使用することを指示します。   </li>   <li>  `FORCE`：特定の操作でインデックスを強制的に使用することを指示します。   </li>   <li>  `IGNORE`：特定の操作でインデックスを使用しないことを意味します。   </li>   <li>  `FOR JOIN`：インデックスを使用して結合を指定します。   </li>   <li>  `FOR ORDER BY`：インデックスを使用してソートを指定します。   </li>   <li>  `FOR GROUP BY`：インデックスを使用してグループ化を指定します。</li></ul>    |
| SQL_CALC_FOUND_ROWS                                                                         | クエリ結果を昇順（`ASC`）または降順（`DESC`）で表示するために使用されます。デフォルトは`ASC`です。  |
| \[LIMIT {\[offset,\] row_count \|row_count OFFSET offset}\]                                 | `SELECT`ステートメントが指定されたレコード数を返すように強制します。`LIMIT`は1つまたは2つの数値パラメータを受け取ります。パラメータは整数定数でなければなりません。<ul><li> 2つのパラメータが指定されている場合、最初のパラメータは最初に返されるレコード行のオフセットを指定し、2番目のパラメータは返されるレコード行の最大数を指定します。初期レコード行のオフセットは0です。   </li>   <li> 1つのパラメータのみが指定されている場合、それは返されるレコード行の最大数を表し、オフセットは0になります。</li></ul>    |
| FOR UPDATE                                                                                  | 他のトランザクションによる並行変更や、特定のトランザクション分離レベルでの並行読み取りを防ぐために、クエリ結果のすべての行に排他ロックをかけます。詳細なロックオプションについては、[opt_for_update_wait](#opt_for_update_wait)を参照してください。 |
| PARTITION(partition_list)                                                                   | クエリ対象のテーブルのパーティション情報を指定します。例えば `partition(p0,p1...)` です。     |
| dblink_name | dblinkを使用して、リモートデータベーステーブルのデータをクエリします。<main id="notice" ><h4>説明</h4><p>この内容はOceanBaseデータベースEnterprise Editionにのみ適用されます。OceanBaseデータベースCommunity Editionでは、<code>dblink</code>機能は現在サポートされていません。</p></main>|
| LOCK IN SHARE MODE | クエリ結果をロックします。|

### opt_for_update_wait

* `WAIT`：他のトランザクションがリソースを解放するのを待つ時間。この時間を超えると、リソースを取得できなかったことを返します。単位は秒です。
* `NOWAIT` または `NO_WAIT`：他のトランザクションがリソースを解放するのを待たず、即座にリソースを取得できなかったことを返します。
* `SKIP LOCKED`：行ロックを取得するのを待たず、クエリが直ちに実行され、結果セットからロックされた行が削除されます。

`FOR UPDATE` の使用例については、[SELECT FOR UPDATEによるロック](../../../../../../300.develop/100.application-development-of-mysql-mode/500.read-data-of-mysql-mode/300.use-operators-and-functions-in-query-of-mysql-mode/1000.lock-query-results-select-for-update-of-mysql-mode.md)を参照してください。

## 例

### シンプルなテーブルクエリの例

以下のテーブル `a` を例にします。

![](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.1.0/EN_US/7.reference/4.development-reference/Select-sample.jpg)

* テーブル `a` から `name` のデータを読み取ります。

  ```sql
  obclient> SELECT name FROM a;
  +------+
  | name |
  +------+
  | a    |
  | b    |
  | a    |
  +------+
  ```

* クエリ結果で `name` を重複除去します。

  ```sql
  obclient> SELECT DISTINCT name FROM a;
  +------+
  | name |
  +------+
  | a    |
  | b    |
  +------+
  ```

* テーブル `a` から `id`、`name`、`num` をクエリし、`num` 列を 2 で割って出力します。出力する列名は `avg` とします。

  ```sql
  obclient> SELECT id, name, num/2 AS avg FROM a;
  +------+------+----------+
  | id   | name | avg      |
  +------+------+----------+
  |    1 | a    |  50.0000 |
  |    2 | b    | 100.0000 |
  |    3 | a    |  25.0000 |
  +------+------+----------+
  ```

* フィルタ条件 `name = 'a'` に基づいて、テーブル `a` から対応する `id`、`name`、および `num` を出力します。

  ```sql
  obclient> SELECT id, name, num FROM a WHERE name = 'a';
  +------+------+------+
  | id   | name | num  |
  +------+------+------+
  |    1 | a    |  100 |
  |    3 | a    |   50 |
  +------+------+------+
  ```

* テーブル `a` から `id`、`name` をクエリし、`name` でグループ化して `num` の合計を求め、その結果を出力します。

  ```sql
  obclient> SELECT id, name, SUM(num) FROM a GROUP BY name;
  +------+------+----------+
  | id   | name | SUM(num) |
  +------+------+----------+
  |    1 | a    |      150 |
  |    2 | b    |      200 |
  +------+------+----------+
  ```

* テーブル `a` から `id`、`name` をクエリし、`name` でグループ化して `num` の合計を求めます。次に、`num` の合計が `160` より小さい行のみをクエリし、その結果を出力します。

  ```sql
  obclient> SELECT id, name, SUM(num) as sum FROM a GROUP BY name HAVING SUM(num) < 160;
  +------+------+------+
  | id   | name | sum  |
  +------+------+------+
  |    1 | a    |  150 |
  +------+------+------+
  ```

* テーブル `a` から `id`、`name`、`num` をクエリし、`num` で昇順 (`ASC`) にソートしてクエリ結果を出力します。

  ```sql
  obclient> SELECT * FROM a ORDER BY num ASC;
  +------+------+------+
  | id   | name | num  |
  +------+------+------+
  |    3 | a    |   50 |
  |    1 | a    |  100 |
  |    2 | b    |  200 |
  +------+------+------+
  ```

* テーブル `a` から `id`、`name`、`num` をクエリし、`num` で降順 (`DESC`) にソートしてクエリ結果を出力します。

  ```sql
  obclient> SELECT * FROM a ORDER BY num DESC;
  +------+------+------+
  | id   | name | num  |
  +------+------+------+
  |    2 | b    |  200 |
  |    1 | a    |  100 |
  |    3 | a    |   50 |
  +------+------+------+
  ```

* テーブル `a` から `id`、`name`、`num` をクエリし、`LIMIT` を使用して強制的に 2 行目から開始して、テーブル `a` の 2 行の結果を返します。

  ```sql
  obclient> SELECT * FROM a LIMIT 1,2;
  +------+------+------+
  | id   | name | num  |
  +------+------+------+
  |    2 | b    |  200 |
  |    3 | a    |   50 |
  +------+------+------+
  ```

* `SELECT ... FOR UPDATE` を使用すると、テーブルに行レベルのロックをかけることができます。`LIMIT 1` 句を使用した場合、クエリ最適化では演算子をテーブルスキャンステップに下げるため、`LIMIT` で返される行のみにロックをかけます。

  ```sql
  obclient> SELECT * FROM a LIMIT 1 FOR UPDATE;
  ```

* `ORDER BY` 句を使用してクエリ結果をソートする場合、まず結果をソートしてから `LIMIT 1` を実行するため、この場合、選択されたすべての行にロックがかかります。

  ```sql
  obclient> SELECT * FROM a ORDER BY id LIMIT 1 FOR UPDATE;
  ```

* `LOCK IN SHARE MODE` を使用して、テーブル `a` のクエリ結果をロックします。

  ```shell
  obclient> SELECT * FROM a LOCK IN SHARE MODE;
  +------+------+------+
  | id   | name | num  |
  +------+------+------+
  |    1 | a    |  100 |
  |    2 | b    |  200 |
  |    3 | a    |  50 |
  +------+------+------+
  3 row in set
  ```

### dblinkを使用したデータクエリの例

* リモートの `test` データベース内の `number_t` テーブルを読み取ります。

  ```shell
  obclient> SELECT * FROM number_t@ob_dblink;
  +--------+-------------+---------+---------------------+--------------------------------+
  | c_int  | c_bigint    | c_float |    c_double         |   c_decimal                    |
  +--------+-------------+---------+---------------------+--------------------------------+
  | 214748 | 92233720368 | 3.40282 | 1.7976931348623157  | 123456789123456789.1234567890  |
  +--------+-------------+---------+---------------------+--------------------------------+
  1 row in set
  ```

* リモートの `test` データベース内の `number_t` テーブルを読み取り、ローカルの `number_t` テーブルとJOIN操作を行います。

  ```sql
  obclient> SELECT a.c_decimal, b.c_double FROM number_t a, number_t@ob_dblink b where a.c_int = b.c_int;
  +--------------------------------+---------------------+
  |   c_decimal                    |    c_double         |
  +---------------------+--------------------------------+
  | 123456789123456789.1234567890  |  1.7976931348623157 |
  +---------------------+--------------------------------+
  1 row in set
  ```

* リモートの `mysql` データベース内の `datetime_t` テーブルを読み取ります。

  ```sql
  obclient> SELECT * FROM mysql.datetime_t@ob_dblink;
  +-------------+------------+---------+----------------------+----------------------+
  | c_date      | c_time     | c_year  | c_datetime           |  c_timestamp         |
  +-------------+------------+---------+-----------------------+---------------------+
  |  2023-04-13 | 12:12:12   |  2078   | 2100-11-01 12:12:13  | 2100-12-01 21:14:15  |
  +-------------+------------+---------+----------------------+----------------------+
  1 row in set
  ```
