# CREATE TABLESPACE

## 説明

このステートメントは、TableSpace（テーブルスペース）の論理オブジェクトを作成するために使用されます。TableSpaceのプロパティは暗号化をサポートしています。

## 権限要件

`CREATE TABLESPACE` ステートメントを実行するには、現在のユーザーが `CREATE TABLESPACE` の管理権限を持っている必要があります。OceanBaseデータベースの権限の詳細については、[MySQLモードの権限分類](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md)を参照してください。

## 構文

* 暗号化されたテーブルスペースを作成します。

  ```sql
  CREATE TABLESPACE tablespace_name [ENCRYPTION [=] 'tablespace_encryption_option'];

  tablespace_encryption_option:
      N
      | Y
      | AES-256
      | AES-256-GCM
      | AES-128
      | AES-128-GCM
      | AES-192
      | AES-192-GCM
      | SM4-CBC
      | SM4-GCM
  ```

* テーブルスペースを作成します。

  ```sql
    CREATE TABLESPACE tablespace_name
    [ADD DATAFILE 'file_name']
    [FILE_BLOCK_SIZE = value]
    USE LOGFILE GROUP logfile_group
    [EXTENT_SIZE [=] extent_size]
    [INITIAL_SIZE [=] initial_size]
    [AUTOEXTEND_SIZE [=] autoextend_size]
    [MAX_SIZE [=] max_size]
    [NODEGROUP [=] nodegroup_id]
    [WAIT]
    [COMMENT [=] 'string']
    [ENGINE [=] engine_name]
  ```

  <main id="notice" type='notice'>
  <h4>注意</h4>
  <p>このキーワード構文のみがサポートされており、機能は有効ではありません。この構文のキーワードは <code>ENCRYPTION</code> と同時に実行できません。そうしないと、構文エラーが発生します。</p>
</main>

## パラメータの説明

|        パラメータ        |          説明           |
|-------------------|-------------------------|
| tablespace_name   | 作成するTableSpaceオブジェクトの名前を指定します。|
| ENCRYPTION        | オプション。暗号化に使用するキーワードを指定し、TableSpaceで使用する暗号化アルゴリズムを指定します。キーワード`ENCRYPTION`で暗号化アルゴリズムを指定しない場合、デフォルトでは暗号化されないTableSpaceが作成されます。暗号化アルゴリズムの詳細については、以下の[tablespace_encryption_option](#tablespace_encryption_option)を参照してください。|

### tablespace_encryption_option

* `N`：暗号化しないことを示します。
* `Y`：`Y` を使用する場合、デフォルトで `AES-256` を使用することを示します。
* `AES-256`：256ビットの鍵を使用して暗号化および復号化を行います。
* `AES-256-GCM`：256ビットの鍵を使用したGCMモード。
* `AES-128`：128ビットの鍵を使用して暗号化および復号化を行います。
* `AES-128-GCM`：128ビットの鍵を使用したGCMモード。
* `AES-192`：192ビットの鍵を使用して暗号化および復号化を行います。
* `AES-192-GCM`：192ビットの鍵を使用したGCMモード。
* `SM4-CBC`：SM4アルゴリズムはCBCモードを採用し、各データブロックは前のブロックの暗号化された出力と異なる値をXOR演算した後に暗号化されます。
* `SM4-GCM`：SM4アルゴリズムはGCMモードを採用し、このモードではSM4がデータ暗号化と認証機能の両方を提供します。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p><ul><li>AES (Advanced Encryption Standard) は対称暗号化アルゴリズムであり、同じ鍵を使用してデータの暗号化と復号化を行うことを意味します。AESアルゴリズム自体はブロック暗号化に基づいており、通常は128ビットのブロックでデータを暗号化します。</li><li>AES-GCM (Galois/Counter Mode) は、ブロック暗号化アルゴリズム（例えばAES）を処理するための操作モードであり、暗号化とデータ認証（メッセージ認証コードとも呼ばれる）を提供します。</li><li>SM4アルゴリズムのブロック長は128ビット、鍵長も128ビットです。</li></ul></p>
</main>

## 例

* 暗号化されていないTableSpaceオブジェクトを作成します。

  ```shell
  CREATE TABLESPACE tablespace001;
  ```

* 透過的データ暗号化 (TDE) を使用するTableSpaceオブジェクトを作成します。

  1. 暗号化方式を組み込みの透過的暗号化に設定します。

      ```shell
      ALTER SYSTEM SET tde_method = 'internal';
      ```

  2. 現在の暗号化方式の構成を表示します。

      ```shell
      SHOW PARAMETERS LIKE 'tde_method';
      ```

  3. 新しいマスター暗号化キーを生成します。

      ```shell
      ALTER INSTANCE ROTATE INNODB MASTER KEY;
      ```

      <main id="notice" type='notice'>
        <h4>注意</h4>
        <p>このコマンドは実行可能ですが、ディスク容量がいっぱいの場合、新しいマスター暗号化キーの生成は完了しません。</p>
      </main>

  4. `tablespace2` という名前の暗号化されたテーブルスペースを作成し、`SM4-GCM` 暗号化アルゴリズムを使用します。

      ```shell
      CREATE TABLESPACE tablespace002 ENCRYPTION = 'SM4-GCM';
      ```
