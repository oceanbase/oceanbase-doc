# CREATE EXTERNAL CATALOG

## 説明

このステートメントは、データベース内に外部データカタログ（External Catalog）を作成し、外部データソースに接続して外部データのメタデータを取得するために使用されます。これにより、データのインポートや移行を行わずに直接外部データをクエリできます。

## 使用上の制限と注意事項

* 現在、`ODPS`、`HMS` および `JDBC` タイプの External Catalog の作成がサポートされています。そのうち、`JDBC` タイプは V4.4.2 BP4 以降でサポートされており、現在は SQL Server データソースへの接続のみサポートしています。
* HMSがアクセスするファイルがHDFS上にある場合は、HMS Catalogを作成する前にJava SDK環境をデプロイしてください。手順は、[OceanBaseデータベースのJava SDK環境をデプロイする](../../../../../400.deploy/300.deploy-oceanbase-enterprise-edition/500.deploy-the-ob-java-sdk-environment.md)を参照してください。
* JDBC Catalogを作成する前に、Java SDK環境をデプロイし、devdeps-java-extensionsのRPMパッケージ（バージョン1.0.6以降）をインストールしてください。手順は、[OceanBaseデータベースのJava SDK環境をデプロイする](../../../../../400.deploy/300.deploy-oceanbase-enterprise-edition/500.deploy-the-ob-java-sdk-environment.md)を参照してください。
* JDBC Catalog では、オブジェクトは読み取り専用となり、`INSERT`、`UPDATE`、`DELETE`、`ALTER TABLE`、`DROP TABLE` などの変更ステートメントの実行はサポートされません。

## 権限要件

`CREATE EXTERNAL CATALOG` ステートメントを実行するには、現在のユーザーが `CREATE CATALOG` 権限を持っている必要があります。OceanBase データベースの権限に関する詳細は、[MySQLモードの権限分類](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md)を参照してください。

## 構文

```sql
CREATE EXTERNAL CATALOG [IF NOT EXISTS] external_catalog_name
    PROPERTIES [=] (properties_type_options);

properties_type_options:
    odps_type_list
    | hms_type_list
    | jdbc_type_list

odps_type_list:
    TYPE = 'ODPS',
    [ACCESSTYPE = 'accesstype_string',]
    ACCESSID = 'string',
    ACCESSKEY = 'string',
    STSTOKEN = 'string',
    ENDPOINT = 'string',
    TUNNEL_ENDPOINT = 'string',
    PROJECT_NAME = 'string',
    [QUOTA_NAME = 'string',]
    [COMPRESSION = 'compression_string',]
    REGION = 'string'

hms_type_list:
    TYPE = 'HMS',
    URI = "string"
    [, KRB5CONF = "string"]
    [, KEYTAB = "string"]
    [, PRINCIPAL = "string"]
    [, MAX_CLIENT_POOL_SIZE = 20]
    [, SOCKET_TIMEOUT = 10000000]

jdbc_type_list:
    TYPE = 'JDBC',
    URL = 'string'

accesstype_string:
    aliyun
    | sts
    | app

compression_string:
    zlib
    | zstd
    | lz4
    | odps_lz4
```

## パラメータの説明

|    **パラメータ**     | **説明** |
|-----------------|----------|
| IF NOT EXISTS   | 省略可能です。作成対象の外部データカタログが現在のテナントに既に存在する場合、この句を指定すると警告が表示されます。省略するとエラーになります。|
| external_catalog_name | 作成する外部データカタログの名前を表します。|
| PROPERTIES [=] (properties_type_options) | 外部データカタログのタイプに応じたプロパティを指定します。詳細については、以下の [properties_type_options](#properties_type_options) を参照してください。|

### properties_type_options

* `odps_type_list`：ODPSタイプの外部データカタログ（ODPS Catalog）の関連プロパティリストを表します。詳細については、以下の [odps_type_list](#odps_type_list) を参照してください。
* `hms_type_list`：HMSタイプの外部データカタログ（HMS Catalog）の関連プロパティリストを表します。詳細については、以下の [hms_type_list](#hms_type_list) を参照してください。
* `jdbc_type_list`：JDBCタイプの外部データカタログ（JDBC Catalog）の関連プロパティリストを表します。詳細については、以下の [jdbc_type_list](#jdbc_type_list) を参照してください。

### odps_type_list

* `TYPE`：外部データカタログのタイプを指定するために使用されます。値は `ODPS` です。外部テーブルを使用してMaxComputeのデータを読み書きする場合に指定します。
* `ACCESSTYPE`：オプションです。MaxCompute のアカウントタイプを指定するために使用され、デフォルト値は `aliyun` です。アカウントタイプの値（大文字小文字を区別しません）は以下のとおりです：

  * `aliyun`
  * `sts`
  * `app`

* `ACCESSID`：AccessKey ID を指定します。`ACCESSTYPE` が `aliyun`、`app`、または空の場合は、`aliyun`/`app` アカウント、または MaxCompute へのアクセス権限を持つ RAM ユーザーの AccessKey ID を指定します。
* `ACCESSKEY`：AccessKey Secret を指定します。`ACCESSTYPE` が `aliyun`、`app`、または空の場合は、`aliyun`/`app` アカウント、または MaxCompute へのアクセス権限を持つ RAM ユーザーの AccessKey Secret を指定します。
* `STSTOKEN`：`ACCESSTYPE` が `sts` の場合に、MaxCompute サービスにアクセスするためのトークンを指定します。
* `ENDPOINT`：MaxCompute のエンドポイント（ドメイン名）を指定します。
* `TUNNEL_ENDPOINT`：Tunnel Endpoint を指定するために使用されます。MaxCompute Catalog は Tunnel SDK を使用してデータを取得します。
* `PROJECT_NAME`：MaxCompute 内のプロジェクトスペース名を指定するために使用されます。プロジェクトスペース（Project）は MaxCompute の基本的な組織単位であり、従来のデータベースシステムにおけるデータベース（Database）やスキーマ（Schema）に似た概念です。
* `QUOTA_NAME`：オプションです。Quota を指定するために使用されます。Quota は MaxCompute においてコンピュートリソースプール（計算、アクセス、書き込み）を表します。ユーザーが対応する Quota を設定している場合、このパラメータで特定の Quota を指定します。
* `COMPRESSION`：オプションです。データソースの圧縮形式を指定するために使用されます。設定しない場合は圧縮が有効ではありません。値（大文字小文字を区別しません）は以下のとおりです：

  * `zlib`
  * `zstd`
  * `lz4`
  * `odps_lz4`

* `REGION`：MaxComputeが有効なリージョンを指定するために使用します。

### hms_type_list

* `TYPE`：Hiveが管理するデータを外部テーブルから読み取る場合、外部データカタログのタイプに`HMS`を指定します。
* `URI`：アクセス先の`HMS`サービスの`thrift` URIを`thrift://$host:$port`の形式で指定します。各項目の意味は次のとおりです。

  * `$host`：`thrift`のIPアドレスを表します。
  * `$port`：`thrift`ポートを表します。`HMS`のデフォルト`thrift`ポートは9083です。

* `KRB5CONF`：オプションです。Kerberos認証を有効にした`HMS`サービスにアクセスする際に必要なKerberos設定ファイルのパスを指定するために使用します。

    <main id="notice" type='notice'>
      <h4>注意</h4>
      <p><code>KRB5CONF</code>パラメータは、<code>HMS</code>でKerberos認証が有効な場合にのみ設定する必要があります。</p>
    </main>

* `KEYTAB`：オプションです。Kerberos認証を有効にした`HMS`サービスにアクセスする際に必要な`KEYTAB`鍵ファイルのパスを指定するために使用します。OceanBaseクラスタが分散デプロイ構成の場合は、対象となるすべてのOBServerノードの指定パスにこのファイルを配置してください。

    <main id="notice" type='notice'>
      <h4>注意</h4>
      <p><code>KEYTAB</code>パラメータは、<code>HMS</code>でKerberos認証が有効な場合にのみ設定する必要があります。</p>
    </main>

* `PRINCIPAL`：オプションです。Kerberos認証を有効にした`HMS`サービスにアクセスする際に必要なKerberosプリンシパル名を指定するために使用します。通常は`service/HOST@REGION.com`の形式で存在し、例えば`hive/hadoop@QA.COM`のようになります。

    <main id="notice" type='notice'>
      <h4>注意</h4>
      <p><code>PRINCIPAL</code>パラメータは、<code>HMS</code>でKerberos認証が有効な場合にのみ設定する必要があります。</p>
    </main>

* `MAX_CLIENT_POOL_SIZE`：オプションです。現在のCatalogで利用可能なクライアントキューの最大サイズを指定するために使用します。デフォルト値は20で、現在のHMS Catalogが`HMS`サービスに接続するクライアントを最大20個起動できることを意味します。
* `SOCKET_TIMEOUT`：オプションです。現在のCatalogで利用可能なクライアントアクセスのタイムアウト時間を指定するために使用します。デフォルトは10000000（10秒）です。

### jdbc_type_list

* `TYPE`：外部データカタログのタイプを指定するために使用します。値は`JDBC`（大文字小文字を区別しません）です。
* `URL`：外部データソースに接続するためのJDBC接続文字列を`jdbc:<subprotocol>:<connection_properties>`の形式で指定します。空の文字列は指定できません。長さは1024文字未満にしてください。現在サポートされているのはSQL Serverの接続文字列のみです。`jdbc:sqlserver://$host:$port;databaseName=$database_name;user=$user_name;password=$password[;property=value...]`の各項目の意味は次のとおりです。

  * `$host`：SQL ServerサービスのIPアドレスまたはホスト名を表します。
  * `$port`：SQL Serverサービスのポートを表します。
  * `$database_name`：アクセスするSQL Serverデータベースの名前を表します。
  * `$user_name`：SQL Serverにアクセスするユーザー名を表します。
  * `$password`：SQL Serverにアクセスするユーザーのパスワードを表します。
  * `property=value`：オプションです。SQL Server JDBCドライバーがサポートするその他の接続プロパティを指定するために使用します。例えば、`encrypt=true`などです。

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p><ul>
      <li><code>jdbc_type_list</code>は<code>TYPE</code>と<code>URL</code>の2つのプロパティのみをサポートしています。その他のプロパティ（例えば<code>URI</code>）を指定すると、<code>Invalid argument</code>エラーが発生します。</li>
      <li>SQL Server以外のサブプロトコル（例えば<code>jdbc:mysql:</code>、<code>jdbc:postgresql:</code>）を指定した場合、Catalog自体は作成できますが、そのCatalog内のオブジェクトにアクセスするとエラーが発生します。</li>
    </ul></p>
  </main>

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>OceanBaseデータベースは<code>URL</code>の値を暗号化して保存します。<code>SHOW CREATE CATALOG</code>ステートメントを実行すると、<code>URL</code>のうち、<code>jdbc:&lt;subprotocol&gt;:</code>の部分だけがそのまま表示され、それ以降は<code>********</code>と表示されます。</p>
  </main>

## 例

* `ODPS`タイプのExternal Catalogを作成します。

    ```shell
    obclient> CREATE EXTERNAL CATALOG test_odps_catalog
        PROPERTIES = (
            TYPE = 'ODPS',
            ACCESSID = '$odps_accessid',
            ACCESSKEY = '$odps_accesskey',
            ENDPOINT = '$odps_endpoint',
            TUNNEL_ENDPOINT = 'http://xxx.maxcompute.aliyun.com',
            PROJECT_NAME = 'mysqltest_regression_sqlqa',
            QUOTA_NAME = '',
            COMPRESSION_CODE = ''
        );
    ```

* `HMS`タイプのExternal Catalogを作成します。

  * SIMPLE認証のHMS Catalogを作成します。通常認証モードで、Location認証の設定は不要です。

      ```shell
      obclient> CREATE EXTERNAL CATALOG test_hms_catalog
          PROPERTIES = (
              TYPE = 'HMS',
              URI = "thrift://xxx.xxx.xxx.xxx:xxxx"
          );
      ```

  * Kerberos認証のHMS Catalogを作成します。

      ```shell
      obclient> CREATE EXTERNAL CATALOG test_hms_catalog_kerberos
          PROPERTIES = (
              TYPE = 'HMS',
              URI = "thrift://xxx.xxx.xxx.xxx:xxxx",
              PRINCIPAL = "hive/xxx@xxx.COM",
              KEYTAB = "/xxx/xxx/xxx/hadoop.keytab",
              KRB5CONF = "/etc/xxx.conf"
          );
      ```

* `JDBC`タイプのExternal Catalogを作成し、SQL Serverデータベース`sales_db`に接続します。

    ```shell
    obclient> CREATE EXTERNAL CATALOG sqlserver_catalog
        PROPERTIES = (
            TYPE = 'JDBC',
            URL = 'jdbc:sqlserver://xxx.xxx.xxx.xxx:1433;databaseName=sales_db;user=$user_name;password=$password;encrypt=true'
        );
    ```

## Location認証

OceanBaseデータベースのHMS Catalogでは、External Locationで鍵を管理し、外部ストレージに安全にアクセスできます。HMSのテーブルにアクセスすると、システムがテーブルのパスに対応するExternal Locationを検索し、見つかった場合はその鍵を使って認証します。

### Location認証のシナリオ

ストレージタイプとセキュリティ要件に基づき、Location認証は以下のシナリオに分類されます：

| **ストレージタイプ** | **認証方式** |
|-------------|---------------|
| OSS         | AK/SK認証。|
| HDFS        | HDFSには以下の認証方式があります：<ul><li>認証なし（Kerberos不要で、HDFSユーザーの指定も不要）。</li><li>ユーザー認証（Kerberos不要ですが、特定のHDFSユーザーとしてアクセスする必要があります）。</li><li>Kerberos認証あり、HDFSは単一NameNode構成（非HAモード）。</li><li>Kerberos認証あり、HDFSは高可用性（HA）モード。</li><li>Kerberos認証なし、HDFSは高可用性（HA）モード。</li></ul>|

### 手順

1. Location認証のシナリオを決定します。

    ストレージタイプとセキュリティ要件に基づいて、対応する認証シナリオを選択します。

2. Locationオブジェクトを作成します。

    `CREATE LOCATION`ステートメントを使用して、対応するシナリオのLocationオブジェクトを作成します。Locationの作成方法の詳細については、[CREATE LOCATION](2230.create-location-of-mysql-mode-in-sql.md)を参照してください。

3. Catalogを関連付けます。

    Catalogの作成時に追加の設定は不要です。システムがテーブルのストレージパスに対応するLocationを自動的に選択します。

### Location認証シナリオの設定例

#### OSSストレージ認証

Alibaba CloudのオブジェクトストレージOSSにアクセスするためのLocationオブジェクトを作成します。

```shell
CREATE LOCATION oss_credential
    URL = 'oss://bucket-name/path'
    CREDENTIAL = (
        ACCESSID = 'your-access-key-id'
        ACCESSKEY = 'your-access-key-secret'
        HOST = 'oss-region.aliyuncs.com'
    );
```

#### HDFSストレージ認証

* シナリオ1：認証なしモード。

    HDFSクラスタでKerberos認証が無効な開発環境やテスト環境（`hadoop.security.authentication=simple`）では、Locationを作成する必要はありません。

* シナリオ2：ユーザー認証モード。

    Kerberosは不要ですが、特定のHDFSユーザーとしてアクセスする必要があります。

    <main id="notice" type='explain'>
      <h4>説明</h4>
      <p>Kerberos認証が有効になっていないクラスタで、対象のHDFSパスに特定のユーザーのみがアクセスできる場合に適用されます。</p>
    </main>

    Locationの作成：HDFSユーザーを指定します。

    ```shell
    CREATE LOCATION hdfs_user
        URL = 'hdfs://namenode:8020/'
        CREDENTIAL (
            USER = 'hdfs_user_name'
        );
    ```

* シナリオ3：Kerberos認証が有効で、HDFSが単一NameNode構成（非HAモード）の場合。

    <main id="notice" type='explain'>
      <h4>説明</h4>
      <p><code>CONFIGS</code>内の<code>dfs.data.transfer.protection</code>は、HDFSクラスタの設定と一致している必要があります。</p>
    </main>

    Locationの作成：Kerberos認証 + 単一NameNode構成のHDFS。

    ```shell
    CREATE LOCATION hdfs_kerberos_single
        URL = 'hdfs://namenode.example.com:8020/'
        CREDENTIAL (
            PRINCIPAL = "hdfs/xxx@xxx.COM",
            KEYTAB = "/data/hdfs.keytab",
            KRB5CONF = "/data/krb5.conf",
            CONFIGS = 'dfs.data.transfer.protection=integrity'
        );
    ```

* シナリオ4：Kerberos認証が有効で、HDFSが高可用性（HA）モードの場合。

    ```shell
    CREATE LOCATION hdfs_kerberos_ha
        URL = 'hdfs://${nameservice id}'
        CREDENTIAL (
            PRINCIPAL = "hdfs/xxx@xxx.COM",
            KEYTAB = "/etc/ob/hdfs.keytab",
            KRB5CONF = "/etc/krb5.conf",
            CONFIGS = 'dfs.data.transfer.protection=${string}#dfs.nameservices=${nameservice id}#dfs.ha.namenodes.${nameservice id}=${namenode1}, ${namenode2}#dfs.namenode.rpc-address.${nameservice id}.${namenode1}=${namenode 1 address}#dfs.namenode.rpc-address.${nameservice id}.${namenode2}=${namenode 2 address}#dfs.ha.automatic-failover.enabled.${nameservice id}=true#dfs.client.failover.proxy.provider.${nameservice id}=org.apache.hadoop.hdfs.server.namenode.ha.ConfiguredFailoverProxyProvider'
            );
    ```

* シナリオ5：Kerberos認証が無効で、HDFSが高可用性（HA）モードの場合。

    <main id="notice" type='explain'>
      <h4>説明</h4>
      <p>Kerberosが有効化されておらず、HDFSが高可用性（HA）モードの場合、<code>PRINCIPAL</code>、<code>KEYTAB</code>、<code>KRB5CONF</code>パラメータは設定不要です。</p>
    </main>

    ```shell
    CREATE LOCATION hdfs_location_ha
        URL = 'hdfs://${nameservice id}'
        CREDENTIAL (
            CONFIGS = 'dfs.nameservices=${nameservice id}#dfs.ha.namenodes.${nameservice id}=${namenode1}, ${namenode2}#dfs.namenode.rpc-address.${nameservice id}.${namenode1}=${namenode 1 address}#dfs.namenode.rpc-address.${nameservice id}.${namenode2}=${namenode 2 address}#dfs.ha.automatic-failover.enabled.${nameservice id}=true#dfs.client.failover.proxy.provider.${nameservice id}=org.apache.hadoop.hdfs.server.namenode.ha.ConfiguredFailoverProxyProvider'
            );
    ```
