# INSERT

## 説明

このステートメントは、テーブルに1つまたは複数のレコードを追加するために使用されます。

## 使用上の制限と注意事項

サブクエリに対して直接挿入操作を行うことはサポートされていません。例：`INSERT INTO (SELECT * FROM t1) VALUES(1, 1)`。

## 権限要件

* `INSERT` ステートメントを実行するには、対象テーブルに対する `INSERT` 権限が必要です。
* `INSERT ... SELECT ...` ステートメントを実行するには、対象テーブルに対する `INSERT` 権限だけでなく、ソーステーブル（`SELECT` 句で参照されるテーブル）に対する `SELECT` 権限も必要です。

OceanBaseデータベースの権限の詳細については、[MySQLモードの権限分類](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md)を参照してください。

## 構文

```sql
INSERT {into_table_insert | overwrite_table_insert};

into_table_insert:
    [hint_options] [IGNORE] [INTO]
    single_table_insert
    [ON DUPLICATE KEY UPDATE update_asgn_list]

hint_options:
    [/*+ [APPEND | DIRECT(bool, int, ['load_mode'])] enable_parallel_dml PARALLEL(N) | NO_DIRECT */]

load_mode:
    full
    | inc
    | inc_replace

single_table_insert:
    table_name [PARTITION (partition_name, ...)] [(column_list)] {VALUES | VALUE} (values_list)[, (values_list) ...]
    | table_name [PARTITION (partition_name, ...)] [(column_list)] select_stmt
    | table_name [PARTITION (partition_name, ...)] SET update_asgn_list

column_list:
    column_name [,column_name ...]

values_list:
    value [,value ...]

value:
    expr
    | DEFAULT

update_asgn_list:
    column_name = expr [,column_name = expr ...]

overwrite_table_insert:
     [/*+ PARALLEL(N)*/] OVERWRITE [INTO] table_name [(column_list)] [PARTITION (partition_name, ...)] select_stmt;
```

## パラメータの説明

|         **パラメータ**        |      **説明**     |
|-------------------------|-------------------|
| into_table_insert       | テーブルにデータを挿入するために使用します。|
| hint_options            | オプションです。Hintオプションを指定するために使用します。詳細については、以下の [hint_options](#hint_options) を参照してください。|
| IGNORE                  | オプションです。データ挿入時に発生するエラーを無視するよう指示します。|
| INTO                    | オプションです。次に挿入先を指定することを示します。省略可能です。|
| single_table_insert     | テーブルへのデータ挿入方法を指定します。現在、3種類のデータ挿入方法がサポートされています。詳細については、以下の [single_table_insert](#single_table_insert) を参照してください。|
| table_name              | 挿入するテーブル名を指定します。|
| PARTITION (partition_name, ...) | オプションです。データを挿入するテーブルのパーティションを指定するために使用します。複数のパーティションに同時に挿入する場合は、カンマ（,）で区切ります。`partition_name` は挿入するテーブルの指定したパーティション名を表します。|
| column_list             | オプションです。データを挿入する列を指定するために使用します。複数の列に同時に挿入する場合は、カンマ（,）で区切ります。|
| column_name             | 挿入するテーブルの指定した列名を表します。|
| ON DUPLICATE KEY UPDATE update_asgn_list | オプションです。重複する主キーまたは一意キーに対する処理操作を指定します。<ul><li>`ON DUPLICATE KEY UPDATE` を指定した場合、挿入しようとする主キーまたは一意キーが重複しているとき、設定値で挿入する値を置き換えます。</li><li>`ON DUPLICATE KEY UPDATE` を指定しない場合、挿入しようとする主キーまたは一意キーが重複しているとき、挿入は失敗します。</li></ul> `update_asgn_list` は代入文を表します。詳細については、以下の [update_asgn_list](#update_asgn_list) を参照してください。|
| overwrite_table_insert  | クエリ結果でテーブルまたはパーティション内の既存データを上書きするために使用します。`INSERT OVERWRITE SELECT` ステートメントの使用方法の詳細については、[データの挿入](../../../../../300.develop/100.application-development-of-mysql-mode/400.write-data-of-mysql-mode/100.insert-data-of-mysql-mode-in-develop.md) の **INSERT OVERWRITE SELECT ステートメントを使用したデータの挿入** セクションを参照してください。|
| select_stmt             | `SELECT` 句を指定します。クエリステートメントの詳細については、[SELECT ステートメント](8100.select-of-mysql-mode/100.select-of-mysql-mode.md)を参照してください。|

### hint_options

* `[APPEND | DIRECT(bool, int, [load_mode])] enable_parallel_dml PARALLEL(N)`：

  * `APPEND | DIRECT(bool, int, [load_mode])`：オプションです。Hintを使用してダイレクトロード機能を有効にします。

    <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>ダイレクトロードタスクの実行中は、OceanBaseデータベースのアップグレード操作を同時に行うことは推奨されません。これにより、ダイレクトロードタスクが失敗する可能性があります。</p>
    </main>

    * `APPEND`：デフォルトでは `DIRECT(true, 0)` と同等ですが、オンライン統計情報収集（`GATHER_OPTIMIZER_STATISTICS` Hint）の機能も実現できます。

    * `DIRECT(bool, int, [load_mode])`：

      * `bool`：書き込むデータをソートする必要があるかどうかを示します。取り得る値は以下のとおりです：

        * `true`：ソートが必要であることを示します。
        * `false`：ソートが不要であることを示します。

      * `int`：許容される最大誤った行数を示します。

      * `load_mode`：オプションパラメータで、ダイレクトロードのモードを示します。値は英字のシングルクォートで囲む必要があります。取り得る値は以下のとおりです：

        * `full`：デフォルト値で、フルインポートを示します。

        * `inc`：増分ダイレクトロードのシナリオで使用されます。主キーが競合した場合、挿入または競合を無視する方法で処理されます。具体的な動作は、ステートメント内の `IGNORE` オプションや `inc` モードでの実行セマンティクスによって異なります。増分ダイレクトロードの制限事項については、[データインポートの概要](../../../../../620.obap/300.obap-data-transfer/300.data-import/100.data-import-overview.md)を参照してください。

        * `inc_replace`：増分インポートを示しますが、主キーの重複をチェックしません。これは `REPLACE` のセマンティクスを持つ増分インポートに相当します。

            <main id="notice" type='notice'>
              <h4>注意</h4>
              <p><code>load_mode</code> の値が <code>inc_replace</code> の場合、<code>INSERT</code> ステートメントに <code>IGNORE</code> キーワードを使用することはできません。</p>
            </main>

        `INSERT INTO SELECT` を使用したダイレクトロードの詳細については、[データインポートの概要](../../../../../620.obap/300.obap-data-transfer/300.data-import/100.data-import-overview.md)を参照してください。

  * `enable_parallel_dml parallel(N)`：オプションで、データロードの並列度を設定します。

    <main id="notice" type='explain'>
      <h4>説明</h4>
      <p>通常、<code>enable_parallel_dml</code> ヒントと <code>parallel</code> ヒントは併用して並列DMLを有効にする必要があります。ただし、ターゲットテーブルのスキーマでテーブルレベルの並列度が指定されている場合は、<code>enable_parallel_dml</code> ヒントのみを指定する必要があります。</p>
    </main>

* `NO_DIRECT`：単一のSQLに対してダイレクトロードを強制的に適用しないように制御します。入力されたSQLにこのヒントが含まれている場合、そのステートメント全体で他のダイレクトロード関連のヒントが無視され、通常のインポートが実行されます。

ヒントの詳細については、[Optimizer Hint](../../../../1000.performance-tuning-guide/500.sql-optimization/400.sql-optimization/700.manage-execution-plans/100.optimizer-hint.md)を参照してください。

### single_table_insert

* `[(column_list)] {VALUES | VALUE} (values_list)[, (values_list) ...]`：一連の明示的な値をターゲットテーブルに直接挿入します。

  * `column_list`：オプションで、データ挿入に対応する列名のリストを指定します。複数の列名はカンマ（`,`）で区切ります。

  * `VALUES | VALUE`: 挿入する値のリストを導入するために使用されるキーワードです。

  * `values_list`: 挿入するデータ値のリストを指定するために使用され、括弧（`()`）で囲みます。複数の値リストを使用でき、値リスト間はカンマ（`,`）で区切ります。各値リストは1行のデータを表します。

    * `values`：挿入する個々の値で、各値は1列に対応し、値はカンマ（`,`）で区切られます。式（`expr`）や `DEFAULT` キーワードを使用して列のデフォルト値を代入することもできます。

  **例：**

  * テーブル `tbl1` に1行のデータを挿入します。

    ```sql
    INSERT INTO tbl1(col1, col2) VALUES(1, 'A1');
    ```

  * テーブル `tbl1` に複数行のデータを挿入します。

    ```sql
    INSERT INTO tbl1(col1, col2) VALUES(2, 'A2'),(3, 'A3');
    ```

* `[(column_list)] select_stmt`：1つまたは複数のソーステーブルからデータを選択し、クエリ結果をターゲットテーブルに挿入します。

  * `column_list`：オプションです。データ挿入に対応する列名のリストを指定します。複数の列名はカンマ（`,`）で区切ります。
  * `select_stmt`: 実行するクエリステートメントを指定します。その結果がターゲットテーブルに挿入されます。`select_stmt` は結果セットを返す必要があります。クエリステートメントの具体的な構造とオプションについては、[SELECT ステートメント](8100.select-of-mysql-mode/100.select-of-mysql-mode.md)を参照してください。

  **例：**

  ```sql
  INSERT INTO tbl1(col1, col2) SELECT col1, col2 FROM tbl2 WHERE col2 = 'a3';
  ```

* `SET update_asgn_list`：`SET` 句を使用して各列の値を指定し、データをターゲットテーブルに挿入します。`update_asgn_list` は代入ステートメントを表します。詳細については、後述の [update_asgn_list](#update_asgn_list) を参照してください。

  **例：**

  ```sql
  INSERT INTO tbl1 SET col1= 4, col2='a4';
  ```

### update_asgn_list

`column_name = expr [, ...]`：列名が式のリストに等しいことを指定し、既存の行を更新します。複数の値のペアはカンマ（`,`）で区切ります。

**例：**

* キー競合が発生した場合、ターゲット行の `col2` 列の値を、元々挿入しようとした値（つまり `VALUES(col2)`、この例では `a2`）に更新するよう指定します。

  ```sql
  INSERT INTO tbl1(col1, col2) VALUES (2, 'a2') ON DUPLICATE KEY UPDATE col2 = VALUES(col2);
  ```

## 例

サンプルテーブル `test_tbl1` と `test_tbl2` の定義は以下のとおりです：

```sql
CREATE TABLE test_tbl1(col1 INT PRIMARY KEY, col2 INT)
    PARTITION BY KEY(col1)
         (PARTITION p0,
          PARTITION p1,
          PARTITION p2,
          PARTITION p3
         );
```

```sql
CREATE TABLE test_tbl2(col1 INT PRIMARY KEY, col2 INT);
```

* テーブル `test_tbl1` の指定された `p0` パーティションに単一行データを挿入します。

  ```sql
  INSERT INTO test_tbl1 PARTITION(p0) (col1) VALUES(5);
  ```

  テーブル `test_tbl1` のデータを確認します：

  ```sql
  SELECT * FROM test_tbl1 PARTITION(p0);
  ```

  結果は次のとおりです：

  ```shell
  +------+------+
  | col1 | col2 |
  +------+------+
  |    5 | NULL |
  +------+------+
  1 row in set
  ```

* 更新可能なビュー `v` に値を挿入します。

  ```sql
  CREATE VIEW v AS SELECT * FROM test_tbl2;
  ```

  ```sql
  INSERT INTO v VALUES (1, 1);
  ```

  ビュー `v` のデータを確認します：

  ```sql
  SELECT * FROM v;
  ```

  結果は次のとおりです：

  ```shell
  +------+------+
  | col1 | col2 |
  +------+------+
  |    1 |    1 |
  +------+------+
  1 row in set
  ```

* `INSERT OVERWRITE SELECT` の例：

  1. テーブル `test_tbl1` にデータを挿入します。

     ```sql
     INSERT INTO test_tbl1 VALUES (1, 30),(2, 25),(3, 22);
     ```

  2. `INSERT OVERWRITE SELECT` ステートメントを使用して、`col2` が25より大きい条件で `test_tbl1` からデータを選択し、それらのデータを `test_tbl2` に挿入して既存の内容を上書きします。

     ```sql
     INSERT OVERWRITE test_tbl2 SELECT * FROM test_tbl1 WHERE col2 > 25;
     ```

  3. データ上書き後のテーブル `test_tbl2` の内容を確認します。

     ```sql
     SELECT * FROM test_tbl2;
     ```

     結果は次のとおりです：

     ```shell
     +------+------+
     | col1 | col2 |
     +------+------+
     |    1 |   30 |
     +------+------+
     1 row in set
     ```

## ダイレクトロード関連の制限 (INSERT構文)

`INSERT INTO ... SELECT ...` を `APPEND`、`DIRECT(...)`、`enable_parallel_dml`、`parallel(N)` などのヒントと組み合わせてダイレクトロードを実行する場合、[データインポートの概要](../../../../../620.obap/300.obap-data-transfer/300.data-import/100.data-import-overview.md)で説明されている**ダイレクトロード機能**の適用範囲と制限に加え、以下の **`INSERT INTO SELECT` ステートメントレベル** の制限も満たす必要があります。

### フルダイレクトロード

* PDML (Parallel Data Manipulation Language、並列データ操作言語) のみサポートしており、非PDMLではダイレクトロードを使用できません。並列DMLの詳細については、[並列DML](../../../../1000.performance-tuning-guide/500.sql-optimization/300.distributed-execution-plan/1000.parallel-dml.md)を参照してください。
* ダイレクトロードはDDLステートメントであるため、複数行トランザクション(複数の操作を含むトランザクション)内で実行することはできません。
* `BEGIN` 内で実行することはできません。
* `Autocommit` は1に設定する必要があります。

### 増分ダイレクトロード

* PDMLのみサポートしており、非PDMLではダイレクトロードを使用できません。並列DMLの詳細については、[並列DML](../../../../1000.performance-tuning-guide/500.sql-optimization/300.distributed-execution-plan/1000.parallel-dml.md)を参照してください。
* インデックス(主キーを除く)を持つテーブルは、増分ダイレクトロードをサポートしません。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>トリガー、生成列、Liboblog、フラッシュバッククエリ、および増分ダイレクトロードがターゲットテーブルの構造(外部キー、<code>GLOBAL</code>インデックス、制約、一意インデックスなど)に与える制限は、<strong>ダイレクトロード機能</strong>レベルの一般的な制限に属します。詳細については、<a href="../../../../../620.obap/300.obap-data-transfer/300.data-import/100.data-import-overview.md">データインポートの概要・フル/増分ダイレクトロードの注意事項</a>を参照してください。</p>
</main>
