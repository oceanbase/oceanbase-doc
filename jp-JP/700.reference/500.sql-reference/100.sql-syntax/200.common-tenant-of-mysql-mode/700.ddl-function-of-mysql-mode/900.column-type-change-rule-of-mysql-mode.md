# 列型変更ルール

OceanBaseデータベースのMySQLモードで列型を変更する際には、まずテーブルレベルの列型変更ルール、特に一部のデータ型の使用禁止シナリオを考慮する必要があります。次に、列型変更におけるソースデータ型とターゲットデータ型の変更ルールを検討します。

## テーブル単位の列型変更ルール

### 禁止ルール

* 外部キー制約

  Online DDLおよびOffline DDLについて、以下の特殊な場合（注意：対象となる型の変更は表示精度のみを変更し、ストレージ構造は変更しないことに注意してください）以外のシナリオでは、外部キー列の型を変更することはサポートされません。
  * 列のデータ型が `FLOAT(m,n)` の場合、精度の変更はサポートされますが、`SIGNED` と `UNSIGNED` の相互変換はサポートされません。

  * 列のデータ型が `DOUBLE(m,n)` の場合、精度の変更はサポートされますが、`SIGNED` と `UNSIGNED` の相互変換はサポートされません。

  * 列のデータ型が `VARCHAR(m)` の場合、精度を大きくする変更はサポートされますが、精度を小さくする変更や `CHAR` 型への変更はサポートされません。

* `CHECK` 制約

  Online DDLおよびOffline DDLについて、`CHECK` 制約を持つ整数型列の場合、列型を値の範囲がより広い整数型列型に変更する（例えば、INTからBIGINTに変更する）場合、Onlineで変更できます。その他の `CHECK` 制約を持つ列では、依然として列型の変更はサポートされません。

* Trigger制約

  Offline DDLに限り、列に `DISABLE` 以外のTrigger制約がある場合、列型の変更は禁止されます。すべてが `DISABLE` のTriggerである場合、DDL操作に影響はなく、新しいテーブルにはこの `DISABLE` のTriggerを含める必要があります。

### 変更ルール

* 同じデータ型で長さが長くなる場合（例えば、ある列のデータ型を `CHAR` から `CHAR(11)` に変更する場合、OceanBaseデータベースでは `CHAR` のストレージ方式はOnline操作で可能であり、データの書き直しも不要です。）、その列にインデックステーブルのみが存在する場合、Onlineでインデックス列の長さを変更できます。ただし、その列が主キーまたはパーティションキーに変更された場合は、Offline操作を実行する必要があります。すなわち、「**同じ型で長さが長くなり、主キーまたはパーティションキーがある場合はOffline**」ということです。

  + `VARCHAR` 型の長さを長くする場合、Onlineで変更できますが、インデックステーブルなどの関連依存オブジェクトのSchemaも同時に変更する必要があります。注意が必要な点として、この場合、主キーまたはパーティションキーを変更しても、Online方式で済む可能性があります。すなわち、「**ユーザーがデータの変更を予想していない場合でも、依存オブジェクト内のSchemaも変更する必要があります**」ということです。

  + 整数型の長さを長くする場合、Onlineで変更できます。通常の列、主キー列、パーティションキー、インデックス列、生成列に依存する列、および `CHECK` 制約を持つ列がサポートされます。

  <main id="notice" >
    <h4>注意</h4>
    <p>文字列型の列の長さ変更については、通常、インデックス列の型変更はOnlineで行うことができますが、プレフィックスインデックス（インデックスが列値の一部のみを含む場合）は例外です。</p>
  </main>

* OceanBaseデータベースでは、列型が数値データ型、文字データ型、日付データ型の場合、その列がインデックステーブル、外部キー、主キー、パーティションキーなどによって参照されていない場合、Onlineで変更できます。依存オブジェクトによって参照されている場合は、Offline方式で変更する必要があります。すなわち、「**大きな型の変更に依存オブジェクトがある場合はOffline**」ということです。

* OceanBaseデータベースでは、列型が整数型の場合、外部キー列、外部キーに依存する列、および生成列の列型変更はサポートされていません。

* 数値データ型について、`SIGNED` と `UNSIGNED` の変換が発生した場合、型変更が許可されている場合でも、Offline操作を実行する必要があります。文字データ型について、文字セットと照合順序Collationの変更が発生した場合、列型変更が許可されている場合でも、Offline操作を実行する必要があります。

* ある列が生成列によって参照されている場合、列型の変更操作は許可されます。

## 列単位の変換ルール

OceanBaseデータベースでは、すべての列データ型は数値データ型、文字データ型、時間データ型の3つの大きなカテゴリに分類されます。これら3つのカテゴリ間での変換ルールは似ており、また各カテゴリ内での変更ルールも似ていますが、いくつかの特殊なケースも存在します。

以下の各表では、それぞれのカテゴリ内およびカテゴリ間の変換状況を示しています。

### 数値データ型間の変換

数値データ型は以下に分類されます：

* 整数型：`TINYINT`、`SMALLINT`、`MEDIUMINT`、`INT`、`BIGINT`

* 小数点型：`FLOAT`、`DOUBLE`

* 固定小数点型：`NUMBER`

* バイナリ：`BIT`
