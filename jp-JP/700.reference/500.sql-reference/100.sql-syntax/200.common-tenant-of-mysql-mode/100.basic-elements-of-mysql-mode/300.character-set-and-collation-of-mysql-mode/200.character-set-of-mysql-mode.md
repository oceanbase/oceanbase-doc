# 文字セット

OceanBaseデータベースのデフォルト文字セットは `utf8mb4` です。

OceanBaseデータベースが現在サポートしている文字セットは以下の通りです：

* `binary`

* `gbk`

* `gb18030`

* `utf16`

* `utf8mb4`/`utf8mb3`

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p><ul><li>シームレスな移行をサポートするため、OceanBaseデータベースでは構文上、<code>UTF8</code> を <code>UTF8MB4</code> の同義語と見なします。</li><li><code>utf8mb3</code> は <code>utf8mb4</code> のエイリアスです。</li></ul></p>
  </main>

* `latin1`

* `gb2312`

* `gb18030_2022`

* `ascii`

* `tis620`

* `ujis`

* `euckr`

* `eucjpms`

* `cp932`

* `utf16le`

* `sjis`

* `dec8`

* `hkscs`

* `hkscs31`

* `big5`

* `cp850`

* `hp8`

* `macroman`

* `swe7`

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>OceanBaseデータベースV4.3.5では、V4.3.5 BP1から以下の文字セットがサポートされています：<code>gb2312</code>、<code>ujis</code>、<code>euckr</code>、<code>eucjpms</code>、<code>cp932</code>、<code>cp850</code>、<code>hp8</code>、<code>macroman</code> および <code>swe7</code>。</p>
</main>

OceanBaseデータベースの現在のバージョンでは、`gb18030` と `gb18030_2022` 間の暗黙的な変換はサポートされていませんが、ユーザーは `CONVERT` を使用して、`gb18030` 文字列の文字セットを明示的に `gb18030_2022` に変換できます。この変換はUnicodeを経由せず、エンコードを保持する方法が採用されています。以下の例では、‘龴’ のエンコードは変換前後で `0xFE59` と変わらず、変化しません。

```shell
obclient [(none)]> SELECT HEX(CONVERT(_gb18030 0xFE59 USING gb18030_2022)), HEX(CONVERT(_gb18030_2022 0xFE59 USING gb18030));
```

結果は次のとおりです：

```shell
+--------------------------------------------------+--------------------------------------------------+
| HEX(CONVERT(_gb18030 0xFE59 USING gb18030_2022)) | HEX(CONVERT(_gb18030_2022 0xFE59 USING gb18030)) |
+--------------------------------------------------+--------------------------------------------------+
| FE59                                             | FE59                                             |
+--------------------------------------------------+--------------------------------------------------+
1 row in set
```

## デフォルト以外の文字セットの指定

OceanBaseデータベースは、サーバーとの通信においてデフォルト以外の文字セットを指定することをサポートしています。例えば、`gbk` 文字セットを使用する場合、サーバーに接続した後、以下のステートメントを実行します：

```sql
SET NAMES gbk;
```

注意点として、`SET NAMES` ステートメントはクライアントが入力する文字のエンコーディングを変更しません。例えば、`SET NAMES` を使用してクライアントのエンコーディングを `gb18030_2022` に設定するには、クライアントが既に `gb18030_2022` エンコーディングを使用している必要があります。そうでない場合、文字化けが発生します。

```shell
/* クライアントはutf8mb4文字セットを使用し、デフォルトでutf8mb4文字セットのテーブルtを作成 */
obclient> CREATE TABLE t(c VARCHAR(100));
Query OK, 0 rows affected

/* utf8mb4エンコードの文字を挿入 */
obclient> INSERT INTO t VALUES ('文字セット');
Query OK, 1 row affected

/* 現在のセッションの文字セットを変更しますが、クライアントが実際に使用する文字セットは変更されません */
obclient> SET NAMES gb18030_2022;
Query OK, 0 rows affected

/* 依然としてutf8mb4エンコードで文字を挿入 */
obclient> INSERT INTO t VALUES ('文字セット');
Query OK, 1 row affected

/* テーブルtのデータをクエリすると、文字化けが発生します */
obclient> SELECT * FROM t;
+----------+
| c        |
+----------+
| �ַ���      |
| 字符�     |
+----------+
2 rows in set

/* 現在のセッションの文字セットをutf8mb4に変更 */
obclient> SET NAMES utf8mb4;
Query OK, 0 rows affected

/* 再度テーブルtのデータをクエリしますが、2回目に挿入した文字は依然として文字化けしています */
obclient> SELECT * FROM t;
+--------------+
| c            |
+--------------+
| 字符集       |
| 瀛楃闆      |
+--------------+
2 rows in set
```
