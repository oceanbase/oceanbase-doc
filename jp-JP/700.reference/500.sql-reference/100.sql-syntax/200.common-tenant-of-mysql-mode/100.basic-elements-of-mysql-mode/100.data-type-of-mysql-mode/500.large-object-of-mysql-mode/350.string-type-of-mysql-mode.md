# STRING型

`STRING`型はテキスト型の一種であり、AP業務のサポートと移行をより効果的に行うことができます。また、主キーとして使用する不定長文字列もサポートしています。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>OceanBaseデータベースV4.3.5では、V4.3.5 BP1バージョンからテキストデータ型<code>STRING</code>がサポートされています。</p>
</main>

## 基本機能

* テーブル作成時に`STRING`型のデータ長を指定する必要はなく、最大で16MB（16777216バイト）のデータを格納できます。

* `STRING`型の列（以下、String列と略称）は、主キー列やインデックス列として使用できるほか、Key/Range columns/List columnsパーティショニングタイプのパーティションキーとしても使用できます。

* `STRING`型は特殊な`LOB`型です：

  * `STRING`型が非主キー列の場合、長さが`LOB_INROW_THRESHOLD`（`LOB`列のしきい値）を超えると、行外にオーバーフローして保存されます。
  * `STRING`型が主キー列の場合、すべてのデータは行内に保存され、データの長さは主キーの長さに制限されます。

## 使用上の制限

* `STRING`型のデフォルト値は`NULL`のみをサポートします。

* `STRING`型が非主キー列の場合、行外にオーバーフローするかどうかは`LOB_INROW_THRESHOLD`の影響を受けます。

  `LOB_INROW_THRESHOLD`の詳細については、[LOB型](400.lob-type-of-mysql-mode.md)および[ob_default_lob_inrow_threshold](../../../../../../800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/6300.ob_default_lob_inrow_threshold-global.md)を参照してください。

* String列を主キーまたはインデックスキーとして使用する場合、書き込み（または更新）時に主キーまたはインデックスキーの長さが16KBを超えるとエラーが発生します。

* String列を含むインデックスを作成する際、主表のString列が既に行外にオーバーフローしている場合、インデックスの作成に失敗し、エラーが発生します。

* String列に対するインデックス作成後、そのString列にデータを書き込んだり更新したりする際、データが行外にオーバーフローする必要がある（つまり、データ長が`LOB_INROW_THRESHOLD`より大きい）場合、データの書き込み/更新ができず、エラーが発生します。

* String列をパーティションキーとして使用する場合、書き込み（または更新）するデータが既に行外にオーバーフローしているLOBである場合、データの書き込み（または更新）ができず、エラーが発生します。（例：`INSERT INTO ... SELECT ...`、`SELECT`のデータが行外にオーバーフローしている場合）。

* ダイレクトロードのシナリオで、ターゲットテーブルのString列にインデックスが存在し、インポート後にターゲットテーブルのString列が行外にオーバーフローする必要がある（つまり、データ長が`LOB_INROW_THRESHOLD`より大きい）場合、データのインポートに失敗し、エラーが発生します。

* 増分ダイレクトロードのシナリオで、ターゲットテーブルのString列にインデックスが存在し、ソーステーブルの対応するString列が既に行外にオーバーフローしている場合、データのインポートに失敗し、エラーが発生します。

## 使用例

1. テーブル `test_tbl1` を作成します。`col1`、`col2`、`col3` は文字列型の列であり、`col1` 列が主キーです。テーブルは `col1` の値に基づいてKEYパーティションに分割され、4つのパーティションに分かれます。

   ```sql
   CREATE TABLE test_tbl1 (col1 STRING PRIMARY KEY,
       col2 STRING,
       col3 STRING,
       col4 VARCHAR(10))
       PARTITION BY KEY(col1) PARTITIONS 4;
   ```

2. 文字列列 `col2` にインデックス `idx_test_tbl1` を作成します。

   ```sql
   CREATE INDEX idx_test_tbl1 ON test_tbl1(col2);
   ```

3. テーブル `test_tbl1` の定義を確認します。

   ```sql
   SHOW CREATE TABLE test_tbl1;
   ```

   実行結果は次のとおりです：

   ```shell
   +-----------+-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
   | Table     | Create Table                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
   +-----------+-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
   | test_tbl1 | CREATE TABLE `test_tbl1` (
   `col1` string NOT NULL,
   `col2` string DEFAULT NULL,
   `col3` string DEFAULT NULL,
   `col4` varchar(10) DEFAULT NULL,
   PRIMARY KEY (`col1`),
   KEY `idx_test_tbl1` (`col2`) BLOCK_SIZE 16384 LOCAL
   ) ORGANIZATION INDEX DEFAULT CHARSET = utf8mb4 ROW_FORMAT = DYNAMIC COMPRESSION = 'zstd_1.3.8' REPLICA_NUM = 1 BLOCK_SIZE = 16384 USE_BLOOM_FILTER = FALSE ENABLE_MACRO_BLOCK_BLOOM_FILTER = FALSE TABLET_SIZE = 134217728 PCTFREE = 0
   partition by key(col1)
   (partition `p0`,
   partition `p1`,
   partition `p2`,
   partition `p3`) |
   +-----------+-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
   1 row in set
   ```

4. テーブル `test_tbl1` にテストデータを挿入します。

   ```sql
   INSERT INTO test_tbl1 VALUES("A1", "B1", "C1", "D1"),("A2", "B2", "C2", "D2");
   ```

5. テーブル `test_tbl1` のデータを確認します。

   ```sql
   SELECT * FROM test_tbl1;
   ```

   実行結果は次のとおりです：

   ```shell
   +------+------+------+------+
   | col1 | col2 | col3 | col4 |
   +------+------+------+------+
   | A2   | B2   | C2   | D2   |
   | A1   | B1   | C1   | D1   |
   +------+------+------+------+
   2 rows in set
   ```
