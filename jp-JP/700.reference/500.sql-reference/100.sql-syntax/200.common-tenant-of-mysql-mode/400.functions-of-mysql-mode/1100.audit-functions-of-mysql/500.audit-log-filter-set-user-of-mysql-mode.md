# AUDIT_LOG_FILTER_SET_USER

## 説明

この関数（式）は、ユーザーにフィルターを設定するために使用されます。

<main id="notice" >
  <h4>適用対象</h4>
  <p>この内容はOceanBaseデータベースEnterprise Editionにのみ適用されます。OceanBaseデータベースCommunity Editionは現在監査機能をサポートしていません。</p>
</main>

## 構文

```sql
AUDIT_LOG_FILTER_SET_USER('user_name', 'filter_name');
```

## 説明

### パラメータの説明

* `user_name`：ユーザー名を指定します。

    <main id="notice" type='explain'>
      <h4>説明</h4>
      <p><code>AUDIT_LOG_FILTER_SET_USER</code> で指定される <code>user@host</code> は既存のユーザーである必要はありません。ワイルドカードや存在しないユーザーを指定することができます。<code>user_name</code> には以下の制限があります：<ul><li><code>host</code> フィールドの指定はサポートされていません。</li><li><code>user</code> はフィールド全体に対するワイルドカード <code>%</code> のみをサポートしており、<code>test_%</code> のような部分ワイルドカードの書き方はサポートされていません。</li></ul></p>
    </main>

* `filter_name`：フィルター名を指定します。

    <main id="notice" type='explain'>
      <h4>説明</h4>
      <p><code>AUDIT_LOG_FILTER_SET_USER</code> は <code>CREATE OR REPLACE</code> セマンティクスであり、既存のオブジェクトに対するDDL実行は上書きされます。指定された <code>filter_name</code> が存在しない場合、DDLは有効にならず、エラーも報告されません。</p>
    </main>

### 戻り値

式の入力は文字列定数でなければならず、出力は文字列型です。

* DDL実行が成功した場合、式は `OK` を返します。
* DDL実行が失敗した場合、`SELECT` ステートメントは依然として正常に実行され、式の出力結果はエラーメッセージになります。

## 例

フィルター `log_all` をユーザー `user001` に設定します。

```sql
SELECT AUDIT_LOG_FILTER_SET_USER('user001', 'log_all');
```

実行結果は次のとおりです：

```shell
+-------------------------------------------------+
| AUDIT_LOG_FILTER_SET_USER('user001', 'log_all') |
+-------------------------------------------------+
| OK                                              |
+-------------------------------------------------+
1 row in set
```
