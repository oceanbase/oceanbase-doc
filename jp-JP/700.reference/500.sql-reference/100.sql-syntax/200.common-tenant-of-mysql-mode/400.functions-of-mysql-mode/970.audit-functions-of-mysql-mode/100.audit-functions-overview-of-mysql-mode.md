# 監査関数の概要

OceanBaseデータベースの監査メカニズムは、一連のフィルターを通じて特定のイベントを監査します。フィルターでフィルタリングできる次元には、アカウント、イベントタイプ、イベント属性などが含まれます。各フィルターでは、フィルタリングされたイベントを監査するかどうかを選択できます。

<main id="notice" >
  <h4>機能の適用範囲</h4>
  <p>この内容はOceanBaseデータベースEnterprise Editionにのみ適用されます。OceanBaseデータベースCommunity Editionは、現在監査機能をサポートしていません。</p>
</main>

## 監査関数

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>デフォルトのフィルターを設定することができ、フィルターが明示的に設定されていないすべてのユーザーに適用されます。</p>
</main>

OceanBaseデータベースMySQLモードの現在のバージョンでサポートされている監査関数（式）は、次のテーブルのとおりです。

| **関数名** | **説明** |
| ------------ | -------- |
| [AUDIT_LOG_FILTER_SET_FILTER](400.audit-log-filter-set-filter-of-mysql-mode.md)       | フィルターを作成するために使用されます。|
| [AUDIT_LOG_FILTER_SET_USER](500.audit-log-filter-set-user-of-mysql-mode.md)           | ユーザーにフィルターを設定するために使用されます。|
| [AUDIT_LOG_FILTER_REMOVE_USER](300.audit-log-filter-remove-user-of-mysql-mode.md)     | ユーザーからフィルターを削除するために使用されます。|
| [AUDIT_LOG_FILTER_REMOVE_FILTER](200.audit-log-filter-remove-filter-of-mysql-mode.md) | フィルターを削除するために使用されます。|
| [AUDIT_LOG_ENCRYPTION_PASSWORD_SET](600.audit-log-encryption-password-set-of-mysql-mode.md) | 現在書き込み中の監査ログをアーカイブし、新しい暗号化キーを生成するために使用されます。|
| [AUDIT_LOG_ENCRYPTION_PASSWORD_GET](700.audit-log-encryption-password-get-of-mysql-mode.md) | アーカイブファイル名の `pwd_id` に基づいて、対応するアーカイブログファイルの暗号化パスワード（またはキーマテリアル）を返すために使用されます。|

## 使用制限と注意事項

* 式は、`SELECT` ステートメントの出力列（つまり select item）に直接かつ一意に配置する必要があり、親式（parent expr）の制限はありません。

* 式はサブクエリ内に記述できません。

* フィルターを定義した後、ユーザーに設定して初めて有効になります。

* フィルターとユーザーは1対多の関係にあります。つまり、1つのフィルターを複数のユーザーに設定でき、1人のユーザーには1つのフィルターしか設定できません。

* 接続を確立する際に、現在のセッションがどの監査フィルター（Audit Filter）を使用するかが決定され、その後のセッションライフサイクル全体で変更されません。

  * `AUDIT_LOG_FILTER_SET_USER` および `AUDIT_LOG_FILTER_REMOVE_USER` を呼び出してフィルター（Filter）とユーザー（User）のバインド関係を変更しても、現在接続されているセッションには影響しません。
  * フィルター（Filter）の定義を変更したり、フィルター（Filter）を削除したりすると、既に接続されているセッションに影響します。

* `AUDIT_LOG_FILTER_REMOVE_FILTER`は、このフィルター(Filter)に紐づいているすべての監査ユーザー(Audit User)との関連を連鎖的に削除し、対応するユーザーによる操作は監査の対象外となります。
