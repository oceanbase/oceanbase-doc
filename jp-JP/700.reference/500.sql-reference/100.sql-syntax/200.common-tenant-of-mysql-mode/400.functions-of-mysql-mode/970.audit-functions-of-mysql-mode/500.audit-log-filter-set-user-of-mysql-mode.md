# AUDIT_LOG_FILTER_SET_USER

## 説明

この関数（式）は、ユーザーにフィルターを設定するために使用されます。

<main id="notice" >
  <h4>機能の適用範囲</h4>
  <p>この内容はOceanBaseデータベースEnterprise版にのみ適用されます。OceanBaseデータベースCommunity版は、現在監査機能をサポートしていません。</p>
</main>

## 構文

```sql
AUDIT_LOG_FILTER_SET_USER('user_name', 'filter_name');
```

## 説明

### パラメータの説明

* `user_name`：ユーザー名を指定するために使用されます。

    <main id="notice" type='explain'>
      <h4>説明</h4>
      <p><code>AUDIT_LOG_FILTER_SET_USER</code> で指定する <code>user@host</code> は既存のユーザーである必要はありません。ワイルドカードや存在しないユーザーを記述できます。<code>user_name</code> には以下の制限があります：</p><ul><li><code>host</code> フィールドの指定はサポートされていません。</li><li><code>user</code> はフィールド全体のみをワイルドカード <code>%</code> で指定でき、<code>test_%</code> のような部分ワイルドカードはサポートされていません。</li></ul>
    </main>

* `filter_name`：フィルター名を指定するために使用されます。

    <main id="notice" type='explain'>
      <h4>説明</h4>
      <p><code>AUDIT_LOG_FILTER_SET_USER</code> は <code>CREATE OR REPLACE</code> のセマンティクスを持ち、既存のオブジェクトに対してDDLを実行すると上書きされます。指定した <code>filter_name</code> が存在しない場合、DDLは効果を持ちませんが、エラーも報告されません。</p>
    </main>

### 戻り値

式の入力は文字列定数でなければならず、出力は文字列型です。

* DDLの実行が成功した場合、式は `OK` を返します。
* DDLの実行が失敗した場合、`SELECT` ステートメントは正常に実行され、式の出力結果はエラーメッセージとなります。

## 例

フィルター`log_all`をユーザー`user001`に設定します。

```sql
SELECT AUDIT_LOG_FILTER_SET_USER('user001', 'log_all');
```

結果は次のとおりです：

```shell
+-------------------------------------------------+
| AUDIT_LOG_FILTER_SET_USER('user001', 'log_all') |
+-------------------------------------------------+
| OK                                              |
+-------------------------------------------------+
1 row in set
```
