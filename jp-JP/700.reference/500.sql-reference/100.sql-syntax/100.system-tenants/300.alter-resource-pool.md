# ALTER RESOURCE POOL

## 説明

`ALTER RESOURCE POOL` ステートメントは、`UNIT`、`UNIT_NUM`、`ZONE_LIST` を含むリソースプールのプロパティを変更するために使用されます。

## 制限事項と注意点

* `ALTER RESOURCE POOL` ステートメントを使用してリソースプールのプロパティを変更する場合、各ステートメントでは一度に1つのプロパティのみを変更できます。`UNIT`、`UNIT_NUM`、`ZONE_LIST` のうち2つ以上のプロパティを同時に変更する必要がある場合は、複数のステートメントで実行する必要があります。

* 以前のバージョンでは、OceanBaseデータベースはテナントの同型ゾーンモードのみをサポートしていました。同型ゾーンモードでは、テナント内の各ゾーンのユニット数が同一であることが求められます。V4.2.5 BP5（V4.2.5バージョン専用）以降のバージョンから、OceanBaseデータベースはテナントの異種ゾーンモードをサポートしています。異種ゾーンモードでは、テナント内の各ゾーンのユニット数は異なっても構いませんが、1テナントにつき最大2種類の `unit_num` しか許可されません。`UNIT_NUM` を増減する際には、以下の点に注意してください。

  * 異種ゾーンモードでは、リソースプールが既にテナントに割り当てられているかどうかに関係なく、`ALTER RESOURCE POOL` ステートメントを使用して `UNIT_NUM` を増減できます。

    <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>通常、既存のテナントまたはアップグレードされたテナントについては、デフォルトで同型ゾーンモードになっています。異種ゾーンモードを有効にするには、構成パラメータ <code>zone_deploy_mode</code> の値を <code>hetero</code>（異種ゾーンモード）に変更する必要があります。変更後、<code>homo</code>（同型ゾーンモード）に戻すことはできません。</p>
    </main>

  * 同型ゾーンモードでは、リソースプールが既にテナントに割り当てられている場合、`ALTER RESOURCE POOL` ステートメントを使用することはできず、`ALTER RESOURCE TENANT` ステートメントを使用して変更する必要があります。`ALTER RESOURCE TENANT` ステートメントの詳細については、[ALTER RESOURCE TENANT](300.alter-resource-tenant.md)を参照してください。

## 権限要件

リソースプールを変更できるのは、`sys` テナントの `root` ユーザー（`root@sys`）のみです。他のテナントではリソースプールの変更はサポートされていません。

## 構文

```sql
ALTER RESOURCE POOL pool_name
      UNIT [=] unit_name
    | UNIT_NUM [=] unit_num [DELETE UNIT = (unit_id_list)]
    | ZONE_LIST [=] ('zone_name' [, 'zone_name' ...]);
```

## パラメータの説明

|                  **パラメータ**                 |                    **説明**                                                                  |
|-------------------------------------------|----------------------------------------------------------------------------------------------|
| unit_name                                 | リソースプールで使用するリソースの仕様名を変更します。                                                                |
| unit_num                                  | 変更後の単一ゾーン内のユニット数を指定します。<code>unit_num</code> を増やす場合、その値はターゲットゾーン内のノード数以下である必要があります。<main id="notice" type=notice'><h4>注意</h4><p>異種ゾーンモードでは、<code>unit_num</code> を増減する際、テナント内の各ゾーンの <code>unit_num</code> 数は異なっても構いませんが、同一テナント内の全ゾーンで <code>unit_num</code> の種類は最大2種類までとなります。</p><p>例えば、テナントにリソースプール <code>pool1</code>、<code>pool2</code>、<code>pool3</code> の3つがあり、それぞれの <code>unit_num</code> が2、4、4である場合、<code>pool3</code> の <code>unit_num</code> を1に変更すると、システムは <code>More than two distinct unit_num in a single tenant not allowed</code> というエラーを報告します。</p></main>   |
| DELETE UNIT                               | <code>unit_num</code> を減らす際、<code>DELETE UNIT</code> を使用して指定されたユニットを削除できます。<code>DELETE UNIT</code> を指定しない場合、システムはランダムに対応する数のユニットを削除します。<main id="notice" type=notice'><h4>注意</h4><p><code>DELETE UNIT</code> を使用して指定された <code>unit_id</code> を削除する場合、複数のゾーンがある場合は、以下の条件も満たす必要があります：<ul><li>削除する <code>unit_id</code> リスト内で、各ゾーン内の削除ユニット数は等しくなければなりません。</li>   <li>削除対象の <code>unit_id</code> リスト内で、各ゾーン内の残存ユニット数は指定された <code>unit_num</code> と一致している必要があります。</li></ul> </p></main>    |
| ZONE_LIST                                 | 変更後のリソースプールのゾーンリストを指定します。                                                                 |

## 例

* リソースプール `pool1` の複数のプロパティを同時に変更することはできません。たとえば、次のステートメントでは `UNIT`、`UNIT_NUM`、`ZONE` の各プロパティが同時に変更されているため、実行時にエラーが発生します。

  ```sql
  obclient [oceanbase]> ALTER RESOURCE POOL pool1 UNIT='unit2', UNIT_NUM=1, ZONE_LIST=('zone1');
  ERROR 1235 (0A000): alter unit_num, resource_unit, zone_list in one cmd not supported
  ```

  特に、`UNIT_NUM` を減らす場合は、指定されたユニットを削除できます。

  ```sql
  obclient [oceanbase]> ALTER RESOURCE POOL pool1 UNIT_NUM=1 DELETE UNIT = (1002);
  ```

* リソースプール `pool1` で使用されるリソース仕様を `unit2` に変更します。

  ```sql
  obclient [oceanbase]> ALTER RESOURCE POOL pool1 UNIT='unit2';
  ```
