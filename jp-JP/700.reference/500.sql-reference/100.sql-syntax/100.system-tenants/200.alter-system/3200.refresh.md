# REFRESH

## 説明

このステートメントシリーズは、スキーマ、タイムゾーン情報、各種キャッシュなどのリフレッシュ操作をトリガーするために使用されます。

このステートメントはsysテナントでのみ実行がサポートされています。

## 構文

```sql
alter_system_refresh_stmt:
  ALTER SYSTEM refresh_action;

refresh_action:
  REFRESH SCHEMA
  | REFRESH TIME_ZONE_INFO
  | FLUSH LOCATION CACHE [TENANT [=] tenant_list]
  | FLUSH KVCACHE [TENANT [=] tenant_name] [CACHE [=] cache_name]

tenant_list:
  tenant_name,tenant_name ...
```

## パラメータの説明

|         **パラメータ**       |         **説明**          |
|------------------------|----------------------------|
| REFRESH SCHEMA         | スキーマをリフレッシュします。<br>**説明** 通常、システムがDDL操作を実行すると、Root ServiceはすべてのOBServerノードに対してスキーマのリフレッシュを自動的に通知します。ただし、一部のOBServerノードで異常が発生したり、Root Serviceとのネットワークが切断された場合は、手動でスキーマをリフレッシュする必要があります。    |
| REFRESH TIME_ZONE_INFO | クラスタ内のすべてのServerに対し、ローカルのタイムゾーン情報を更新するよう通知します。<main id="notice" type='explain'><h4>説明</h4><p>現在のバージョンではこのパラメータはサポートされていません。</p></main>  |
| FLUSH LOCATION CACHE | 指定された位置のキャッシュをクリアします。
| FLUSH KVCACHE          | スケーラブルなメモリKVCacheをクリアします。 <ul><li> `tenant_name` と `cache_name` を指定した場合、指定されたテナントの指定されたKVCacheを削除します。</li>   <li> `tenant_name` のみを指定した場合、指定されたテナントのすべてのKVCacheを削除します。</li>   <li> `tenant_name` と `cache_name` 両方を指定しない場合、すべてのテナントのすべてのKVCacheを削除します。</li></ul>    |

## 例

* スキーマをリフレッシュします。

  ```shell
  obclient> ALTER SYSTEM REFRESH SCHEMA;
  Query OK, 0 rows affected
  ```

* ローカルキャッシュをリフレッシュします。

  ```shell
  obclient> ALTER SYSTEM FLUSH LOCATION CACHE;
  Query OK, 0 rows affected
  ```

* すべてのKVCacheをリフレッシュします。

  ```shell
  obclient> ALTER SYSTEM FLUSH KVCACHE;
  Query OK, 0 rows affected
  ```

* MySQLテナントのKVCacheをリフレッシュします。

  ```shell
  obclient> ALTER SYSTEM FLUSH KVCACHE TENANT 'MySQL';
  Query OK, 0 rows affected
  ```
