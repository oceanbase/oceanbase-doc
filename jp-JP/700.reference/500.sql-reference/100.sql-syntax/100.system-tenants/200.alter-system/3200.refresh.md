# REFRESH

## 説明

このステートメントシリーズは、スキーマ、タイムゾーン情報、各種キャッシュなどのリフレッシュ操作をトリガーするために使用されます。

このステートメントはsysテナントでのみ実行がサポートされています。

## 構文

```sql
alter_system_refresh_stmt:
  ALTER SYSTEM refresh_action;

refresh_action:
  REFRESH SCHEMA
  | REFRESH TIME_ZONE_INFO
  | FLUSH KVCACHE [TENANT [=] tenant_name] [CACHE [=] cache_name]

tenant_list:
  tenant_name,tenant_name ...
```

## パラメータ説明

|         **パラメータ**       |         **説明**          |
|------------------------|----------------------------|
| REFRESH SCHEMA         | Schemaをリフレッシュします。 <br>**説明**  通常、システムがDDL操作を実行すると、Root ServiceはすべてのOBServerノードに対してSchemaのリフレッシュを自動的に通知します。特定のOBServerノードで異常が発生したり、Root Serviceとのネットワークが切断された場合は、手動でSchemaをリフレッシュする必要があります。    |
| REFRESH TIME_ZONE_INFO | クラスタ内のすべてのサーバーに通知し、ローカルのタイムゾーン情報を更新します。 <main id="notice" type='explain'><h4>説明</h4><p> 現在のバージョンではこのパラメータはサポートされていません。</p></main>  |
| FLUSH KVCACHE          | 動的に拡張可能なメモリKVCacheをクリアします。 <ul><li> `tenant_name` と `cache_name` を指定した場合、指定されたテナントの指定されたKVCacheを削除します。</li>   <li> `tenant_name` のみを指定した場合、指定されたテナントのすべてのKVCacheを削除します。</li>   <li> `tenant_name` と `cache_name` を指定しなかった場合、すべてのテナントのすべてのKVCacheを削除します。</li></ul>    |

## 例

* スキーマをリフレッシュします。

  ```shell
  obclient> ALTER SYSTEM REFRESH SCHEMA;
  Query OK, 0 rows affected
  ```

* すべてのKVCacheをリフレッシュします。

  ```shell
  obclient> ALTER SYSTEM FLUSH KVCACHE;
  Query OK, 0 rows affected
  ```

* MySQLテナントのKVCacheをリフレッシュします。

  ```shell
  obclient> ALTER SYSTEM FLUSH KVCACHE TENANT 'MySQL';
  Query OK, 0 rows affected
  ```
