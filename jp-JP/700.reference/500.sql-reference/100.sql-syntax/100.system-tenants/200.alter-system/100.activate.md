# ACTIVATE STANDBY

物理復旧が完了した後、または物理スタンバイデータベースのシナリオでスタンバイからプライマリへの切り替えを準備する際に、`ALTER SYSTEM ACTIVATE STANDBY` コマンドを使用してスタンバイテナントをプライマリテナントとしてアクティブ化できます。

`ALTER SYSTEM ACTIVATE STANDBY` コマンドの実行が成功すると、元のスタンバイテナントのテナントロールは `STANDBY` から `PRIMARY` に変更されます。テナントロールの詳細については、[テナントロールの概要](../../../../../600.manage/400.high-availability/300.physical-standby-database-disaster-recovery/600.role-switch/100.role-switch-overview.md)を参照してください。

## 制限事項と注意点

* このコマンドを実行するには、スタンバイテナントのすべてのログストリームのレプリカがオンラインである必要があります。スタンバイテナントのログストリームのレプリカがオフラインの場合は、対応するレプリカが永続的にオフラインになってから実行する必要があります。

* このコマンドは一度に1つのスタンバイテナントしかプライマリテナントとしてアクティブ化できません。複数のテナントをアクティブ化する必要がある場合は、このコマンドを繰り返し実行する必要があります。

## 権限要件

`sys` テナントの `root` ユーザー (`root@sys`) または各テナントの管理者ユーザーによって実行する必要があります。その中で：

* MySQLモードのデフォルト管理者ユーザーは `root` ユーザーです。

* Oracleモードのデフォルト管理者ユーザーは `SYS` ユーザーです。

## 構文

```sql
ALTER SYSTEM ACTIVATE STANDBY
  [TENANT tenant_name]
  [VERIFY];
```

## パラメータの説明

| パラメータ | 説明 |
|--------------|---------------------------------------------------------|
| tenant_name  | 主テナントとしてアクティブ化するスタンバイテナントの名前を指定します。 <main id="notice" type='notice'> <h4>注意</h4> <p>このコマンドを実行する際、システムテナントのみが <code>TENANT tenant_name</code> パラメータで操作対象のテナントを指定する必要があります。通常のテナントは自身のテナントに対してのみこのコマンドを実行できるため、このパラメータを指定する必要はありません。</p></main> |
| VERIFY      | オプションです。このパラメータを使用する場合、`ACTIVATE STANDBY` コマンドを実行するために必要な前提条件がすでに整っているかどうかを事前に検証します。 <main id="notice" type='notice'><h4>注意</h4><p><ul><li>主・スタンバイテナント間のロール変換の実行には一定の失敗リスクが伴います。<code>VERIFY</code> コマンドは単に初期検証を行い、ロール変換の前提条件を満たしているかどうかを評価するものであり、この操作の失敗可能性を低減するのに役立ちますが、<code>ACTIVATE STANDBY</code> 操作自体は実際には実行されません。</li><li><code>VERIFY</code> コマンドが正常に実行されたとしても、その後の <code>ACTIVATE STANDBY</code> 操作が必ず成功するとは限りません。</li></ul></p></main>|

## 例

* 物理スタンバイデータベースのシナリオでは、スタンバイテナントが存在するクラスタのシステムテナントが、スタンバイテナント `tenant1` をプライマリテナントとしてアクティブ化します。または、物理バックアップ復旧のシナリオでは、スタンバイテナントが存在するクラスタのシステムテナントが、新しく復旧されたスタンバイテナント `tenant1` をプライマリテナントとしてアクティブ化してサービスを提供します。

  ```sql
  obclient [oceanbase]> ALTER SYSTEM ACTIVATE STANDBY TENANT tenant1;
  ```

* 物理スタンバイデータベースのシナリオでは、スタンバイテナントが自身をプライマリテナントとしてアクティブ化します。または、物理バックアップ復旧のシナリオでは、スタンバイテナントが自身をプライマリテナントとしてアクティブ化してサービスを提供します。

   ```sql
   obclient [SYS]> ALTER SYSTEM ACTIVATE STANDBY;
   ```
