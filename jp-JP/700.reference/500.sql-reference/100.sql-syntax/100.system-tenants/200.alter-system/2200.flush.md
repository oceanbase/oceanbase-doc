# FLUSH PLAN CACHE

## 説明

このステートメントは、指定されたデータベースとSQL IDのプランキャッシュをクリアするために使用します。

## 構文

```sql
ALTER SYSTEM FLUSH PLAN CACHE
     [
      [SQL_identifier] [database_list] tenant_list
      ] [GLOBAL]

database_list:
     databases ='database_name, database_name...'

tenant_list:
     TENANT = 'tenant_name, tenant_name....'
```

## パラメータの説明

|       パラメータ     |         説明      |
|----------------|----------------------|
| tenant_list    | テナント範囲を指定するために使用します。`SQL_identifier`と`database_list`パラメータを指定する場合は、操作をテナント範囲内に限定するために`tenant_list`を指定する必要があります。<main id="notice" type='explain'><h4>説明</h4><p> システムテナント <code>sys</code> のみが <code>tenant_list</code> を指定できます。他のテナントはこのパラメータを指定できず、自己のプランキャッシュのみをクリアできます。システムテナントが <code>tenant_list</code> を指定しない場合、すべてのテナントのプランキャッシュがクリアされます。</p></main>   |
| SQL_identifier | SQLを指定するために使用します。形式は `sql_id = 'xxx'` です。このパラメータを指定しない場合、すべてのSQLのプランキャッシュがクリアされます。<main id="notice" type='explain'><h4>説明</h4><p>システムテナント sys で `SQL_identifier` パラメータを使用する場合は、`tenant_list` を指定する必要があります。通常のテナントでは `tenant_list` パラメータを指定できません。</p></main>     |
| database_list  | データベースを指定するために使用します。このパラメータを指定しない場合、すべてのプランキャッシュがクリアされます。<main id="notice" type='explain'><h4>説明</h4><p>システムテナント sys で `database_list` パラメータを使用する場合は、`tenant_list` を指定する必要があります。通常のテナントでは `tenant_list` パラメータを指定できません。</p></main>  |
| GLOBAL         | オプションのフィールドです。このパラメータを指定しない場合、ローカルのプランキャッシュがクリアされます。指定した場合、そのテナントが存在するすべてのサーバー上のプランキャッシュがクリアされます。    |

## 例

* すべてのプランキャッシュをクリアします。

  ```sql
  obclient> ALTER SYSTEM FLUSH PLAN CACHE;
  Query OK, 0 rows affected
  ```

* MySQLテナントとOracleテナントのプランキャッシュをクリアします。

  ```sql
  obclient> ALTER SYSTEM FLUSH PLAN CACHE TENANT = 'MySQL','Oracle';
  Query OK, 0 rows affected
  ```

* sysテナントで指定されたプランキャッシュを削除します。

  ```sql
  obclient> ALTER SYSTEM FLUSH PLAN CACHE sql_id='B601070DFC14CB85FDA3766A69A9E1B3'
        databases='myob1' tenant='tenant1' GLOBAL;
  Query OK, 0 rows affected
  ```

* 通常のテナントがDBAとしてログインし、自己のプランキャッシュをクリアします。

  ```sql
  obclient> ALTER SYSTEM FLUSH PLAN CACHE sql_id='B601070DFC14CB85FDA3766A69A9E1B3'
         databases='myob1' GLOBAL;
  Query OK, 0 rows affected
  ```
