# RECOVER STANDBY CANCEL

## 説明

スタンバイテナントでログのセグメントリプレイ、または継続的なリプレイが実行中の場合、`ALTER SYSTEM RECOVER... CANCEL` ステートメントを使用してリプレイをキャンセルできます。

## 権限要件

`sys` テナントの `root` ユーザー (`root@sys`) または各テナントの管理者ユーザーによって実行する必要があります。以下がその詳細です：

* MySQLモードのデフォルト管理者ユーザーは `root` ユーザーです。
* Oracleモードのデフォルト管理者ユーザーは `SYS` ユーザーです。

## 構文

```sql
ALTER SYSTEM RECOVER STANDBY [TENANT [=] tenant_name] CANCEL;
```

## パラメータの説明

| パラメータ       | 説明                                                                                                   |
|------------|------------------------------------------------------------------------------------------------------------|
| tenant_name| ログリプレイをキャンセルするスタンバイテナントを指定します。一度に指定できるのは1つのテナントのみです。複数のテナントを対象とする場合は、コマンドを繰り返し実行してください。<br><br><main id="notice" type='notice'> <h4>注意</h4> <p>システムテナントから実行する場合は、<code>TENANT = tenant_name</code> 句で操作対象のテナントを指定する必要があります。通常テナントから実行する場合は、自身のテナントのみが対象となるため、この句は指定できません。</p></main>   |

## 例

* スタンバイテナント `restore_oracle_tenant` が存在するクラスタのシステムテナントが、スタンバイテナントのログリプレイをキャンセルします。

  ```sql
  obclient [oceanbase]> ALTER SYSTEM RECOVER STANDBY TENANT restore_oracle_tenant CANCEL;
  ```

* スタンバイテナント `restore_oracle_tenant` が、自身のテナントのログリプレイをキャンセルします。

  ```shell
  obclient [SYS]> ALTER SYSTEM RECOVER STANDBY CANCEL;
  ```
