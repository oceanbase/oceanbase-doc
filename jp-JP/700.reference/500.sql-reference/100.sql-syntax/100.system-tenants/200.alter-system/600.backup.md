# BACKUP

`ALTER SYSTEM BACKUP` ステートメントは、データバックアップを開始するために使用されます。データバックアップには、フルバックアップと増分バックアップが含まれます。

フルバックアップはすべてのマクロブロックをバックアップします。増分バックアップは、前回のフルバックアップ以降に追加または変更されたすべてのマクロブロックをバックアップします。

システムパラメータ `data_backup_dest` で指定されたデフォルトのパスのほかに、`TO '<dest>'` 構文を使用して、データを指定のパスにバックアップすることもできます。この方法は一回限りの操作であり、システムパラメータを変更したり、その後の自動スケジュールバックアップに影響を与えたりすることはありません。詳細な操作については、[指定ディレクトリへのバックアップ](../../../../../600.manage/600.backup-and-recovery/400.data-backup/310.backup-to-a-specified-directory.md)を参照してください。

<main id="notice" type='explain'>
<h4>説明</h4>
<p>V4.4.2バージョンでは、V4.4.2 BP3バージョンから、バックアップターゲットパスの指定機能がサポートされています。</p>
</main>

## 使用制限と注意事項

* データバックアップを開始する前に、アーカイブモードが有効であり、アーカイブタスクの `STATUS` が `DOING` であることを確認してください。

  ログアーカイブタスクの状態を確認する操作については、[アーカイブ進捗の確認](../../../../../600.manage/600.backup-and-recovery/300.log-archive/600.view-log-archive-progress.md)を参照してください。

  アーカイブモードを有効にする構文については、[ARCHIVELOG](200.archivelog.md)を参照してください。

* 増分データバックアップを実行するには、フルデータバックアップが既に存在していることを確認する必要があります。フルデータバックアップが存在しない状態で直接増分バックアップを開始すると、システムは増分バックアップを自動的にフルバックアップに切り替えます。

* 低バージョンのクラスタから高バージョン（現在のバージョン）のクラスタへのアップグレードの場合、現在のテナントが低バージョンでフルバックアップを実行していたとしても、高バージョンのクラスタにアップグレードした後、直接増分バックアップを開始すると、システムは増分バックアップを自動的にフルバックアップに切り替えます。

* `TO '<dest>'` 構文を使用してバックアップ先パスを指定する場合、以下の制限があります：
  * システムテナントは `TO` 構文を使用して1つのテナントのみを指定でき、複数のテナントに同時にバックアップを開始することはサポートされていません。これは、複数のテナントが同じターゲットルートパスを共有すると、異なるテナントのバックアップセットが相互に上書きされるためです。
  * 指定されたターゲットパスに履歴バックアップがない場合（初回バックアップ）、増分バックアップは自動的にフルバックアップに切り替わります。

* `PLUS ARCHIVELOG` パラメータを含むデータバックアップタスクと `BACKUP_ARCHIVE_DEST` の変更は相互排他の関係にあります。`PLUS ARCHIVELOG` パラメータを含むデータバックアップタスクの実行中に `BACKUP_ARCHIVE_DEST` から Piece ファイルをコピーする可能性があるため、Piece ファイルがコピーされながら削除される状況を避けるために、`BACKUP_ARCHIVE_DEST` を変更する間に `PLUS ARCHIVELOG` パラメータを含むデータバックアップタスクを開始すると失敗します。`PLUS ARCHIVELOG` パラメータを含むデータバックアップタスクの実行中に `BACKUP_ARCHIVE_DEST` を変更すると、システムは `OPT_NOT_ALLOW` エラーを返します。`BACKUP_ARCHIVE_DEST` を変更する構文については、[SET BACKUP_ARCHIVE_DEST](3850.set-backup-archive-dest.md)を参照してください。

## 権限要件

`sys` テナントの `root` ユーザー（`root@sys`）または各テナントの管理者ユーザーが実行する必要があります。具体的には：

* MySQLモードのデフォルト管理者ユーザーは `root` ユーザーです。
* Oracleモードのデフォルト管理者ユーザーは `SYS` ユーザーです。

## 構文

```sql
ALTER SYSTEM backup_action [DESCRIPTION [=] 'description'];

backup_option:
      BACKUP DATABASE [TO 'dest'] [PLUS ARCHIVELOG]
    | BACKUP TENANT [=] {tenant_name[, tenant_name]...} [TO 'dest'] [PLUS ARCHIVELOG]
    | BACKUP INCREMENTAL DATABASE [TO 'dest'] [PLUS ARCHIVELOG]
    | BACKUP INCREMENTAL TENANT [=] tenant_name [TO 'dest'] [PLUS ARCHIVELOG]

```

## パラメータ説明

| パラメータ            | 説明                                                                |
|-----------------|---------------------------------------------------------------------------|
| PLUS ARCHIVELOG | データバックアップに `PLUS ARCHIVELOG` キーワードを追加すると、データバックアップの過程でアーカイブログも同時にバックアップでき、最終的にバックアップディレクトリにはアーカイブログを含む完全なデータセットが生成されます。このデータセットはリストア可能なため、ユーザーはアーカイブログに依存せずに、このデータセットを使用してテナントのデータを `MIN_RESTORE_SCN` ポイント（バックアップセットで最新にリストア可能なSCN）までリストアできます。 |
| tenant_name     | システムテナントがバックアップ対象のテナント名を指定します。複数のテナント名を同時に指定することができ、異なるテナント名は半角カンマ（,）で区切ります。`TO 'dest'` 構文を使用してバックアップ先パスを指定する場合、1つのテナントのみを指定できます。すべてのユーザーテナントを指定する必要がある場合は、システムテナントで `ALTER SYSTEM BACKUP [INCREMENTAL] DATABASE` ステートメントを実行する必要があります。<main id="notice" type='notice'> <h4>注意</h4><p>このコマンドを実行する際は、システムテナントのみが <code>TENANT = tenant_name</code> 句を使用して操作対象のテナントを指定できます。ユーザーテナントは自身のテナントでのみこのコマンドを実行できるため、<code>TENANT = tenant_name</code> 句を指定することはできません。</p></main>                        |
| INCREMENTAL     | 増分バックアップを表します。                                                             |
| dest            | バックアップ先パスを指定します。オプションです。指定しない場合は、システムパラメータ `data_backup_dest` で指定されたデフォルトパスが使用されます。この構文は一回限りの処理であり、システムパラメータを変更したり、その後の自動スケジュールバックアップに影響を与えたりすることはありません。<main id="notice" type='notice'> <h4>注意</h4><p><code>TO 'dest'</code> 構文を使用する場合、システムテナントは1つのテナントのみを指定できます。</p></main> |
| description      | この操作の説明情報を指定します。オプションです。 |

## 例

現在のクラスタには `sys`、`mysql_tenant`、`oracle_tenant` の3つのテナントがあり、テナント `mysql_tenant` と `oracle_tenant` はどちらもデータバックアップ開始前の準備作業を完了していると仮定します。

* システムテナント

  * システムテナントはクラスタ内のすべてのユーザーテナントに対してフルデータバックアップを開始します。

    ```sql
    obclient [oceanbase]> ALTER SYSTEM BACKUP DATABASE;
    ```

    ステートメントの実行後、システムはクラスタ内の `mysql_tenant` テナントと `oracle_tenant` テナントに対してフルデータバックアップを開始します。

  * システムテナントがテナント `mysql_tenant` に対してフルデータバックアップを開始します。

    ```sql
    obclient [oceanbase]> ALTER SYSTEM BACKUP TENANT = mysql_tenant;
    ```

  * システムテナントがテナント `mysql_tenant` に対して、アーカイブログを含むフルデータバックアップを開始します。

    ```sql
    obclient [oceanbase]> ALTER SYSTEM BACKUP TENANT = mysql_tenant PLUS ARCHIVELOG;
    ```

    ステートメント実行後、システムは該当テナントのデータバックアップパスに、アーカイブログを含む完全なデータセットを生成します。Community版および単一マシン版のユーザーは、フィジカルスタンバイ・データベースのシナリオでこのデータセットを使用してスタンバイテナントを作成できます。アーカイブログを含む完全なデータセットを使用してスタンバイテナントを作成する詳細な操作については、[BACKUP DATABASE PLUS ARCHIVELOG機能を使用してスタンバイテナントを作成する](../../../../../600.manage/400.high-availability/300.physical-standby-database-disaster-recovery/200.create-a-standby-tenant/400.create-a-standby-tenant-by-backup-database-plus-archivelog.md)を参照してください。

  * システムテナントがクラスタ内のすべてのテナントに対して増分データバックアップを開始します。

    ```sql
    obclient [oceanbase]> ALTER SYSTEM BACKUP INCREMENTAL DATABASE;
    ```

    この例では、ステートメント実行後、システムはクラスタ内の `mysql_tenant` テナントと `oracle_tenant` テナントに対して増分データバックアップを開始します。

  * システムテナントがテナント `mysql_tenant` に対して増分データバックアップを開始します。

    ```sql
    obclient [oceanbase]> ALTER SYSTEM BACKUP INCREMENTAL TENANT = mysql_tenant;
    ```

  * システムテナントがテナント `mysql_tenant` に対して、指定されたバックアップターゲットパスのフルデータバックアップを開始します。

    ```sql
    obclient [oceanbase]> ALTER SYSTEM BACKUP TENANT = mysql_tenant TO 'file:///data/backup/one_time_dest';
    ```

  * システムテナントがテナント `mysql_tenant` に対して、指定されたバックアップターゲットパスの増分データバックアップを開始します。

    ```sql
    obclient [oceanbase]> ALTER SYSTEM BACKUP INCREMENTAL TENANT = mysql_tenant TO 'file:///data/backup/one_time_dest';
    ```

  * システムテナントがテナント `mysql_tenant` に対して、指定されたバックアップターゲットパスのフルデータバックアップを開始し、同時にアーカイブログもバックアップします。

    ```sql
    obclient [oceanbase]> ALTER SYSTEM BACKUP TENANT = mysql_tenant TO 'file:///data/backup/self_contained_dest' PLUS ARCHIVELOG;
    ```

  * システムテナントがテナント `mysql_tenant` に対して、指定されたバックアップターゲットパスの増分データバックアップを開始し、同時にアーカイブログもバックアップします。

    ```sql
    obclient [oceanbase]> ALTER SYSTEM BACKUP INCREMENTAL TENANT = mysql_tenant TO 'file:///data/backup/self_contained_dest' PLUS ARCHIVELOG;
    ```

* ユーザーテナント

  * テナント `mysql_tenant` が自身に対してフルデータバックアップを開始します。

    ```sql
    obclient [oceanbase]> ALTER SYSTEM BACKUP DATABASE;
    ```

  * テナント `oracle_tenant` が自身に対して、アーカイブログを含むフルデータバックアップを開始します。

    ```sql
    obclient [SYS]> ALTER SYSTEM BACKUP DATABASE PLUS ARCHIVELOG;
    ```

  * テナント `mysql_tenant` が自身に対して増分データバックアップを開始します。

    ```sql
    obclient [oceanbase]> ALTER SYSTEM BACKUP INCREMENTAL DATABASE;
    ```

  * テナント `mysql_tenant` が、指定したバックアップ先パスに対してフルデータのバックアップを開始します。

    ```sql
    obclient [oceanbase]> ALTER SYSTEM BACKUP DATABASE TO 'file:///data/backup/one_time_dest';
    ```

  * テナント `mysql_tenant` が、指定したバックアップ先パスに対して増分データのバックアップを開始します。

    ```sql
    obclient [oceanbase]> ALTER SYSTEM BACKUP INCREMENTAL DATABASE TO 'file:///data/backup/one_time_dest';
    ```

  * テナント `mysql_tenant` が、指定したバックアップ先パスに対して増分データのバックアップを開始し、同時にアーカイブログもバックアップします。

    ```sql
    obclient [oceanbase]> ALTER SYSTEM BACKUP INCREMENTAL DATABASE TO 'file:///data/backup/self_contained_dest' PLUS ARCHIVELOG;
    ```

  * テナント `mysql_tenant` が、指定したバックアップ先パスに対してフルデータのバックアップを開始し、同時にアーカイブログもバックアップします。

    ```sql
    obclient [oceanbase]> ALTER SYSTEM BACKUP DATABASE TO 'file:///data/backup/self_contained_dest' PLUS ARCHIVELOG;
    ```
