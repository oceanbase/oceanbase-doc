# RESTORE

## 説明

`ALTER SYSTEM RESTORE` ステートメントは、テナントのバックアップデータを復元するために使用されます。

## 制限事項と注意点

* OceanBaseデータベースの物理的復元は、同一クラスタ内での復元だけでなく、異なるクラスタ間でもサポートされています。

* `ALTER SYSTEM RESTORE` ステートメントを使用して物理的復元を行う前に、復元対象のバックアップデータのバージョンを確認してください。OceanBaseデータベースは現在、低バージョンのバックアップデータを同一バージョンまたは高バージョンに復元することのみをサポートしており、同一バージョン内の小さなバージョン間での逆方向復元はサポートされていません。

* `ALTER SYSTEM RESTORE` ステートメントを使用して物理的復元を行う前に、復元対象のテナントに必要なリソースが作成されていることを確認してください。復元対象のテナントに必要なリソースを作成する具体的な操作については、[復元前の準備](../../../../../600.manage/600.backup-and-recovery/600.restore-data/100.preparation-before-recovery.md)を参照してください。

* `ALTER SYSTEM RESTORE` ステートメントを使用して復元されたテナントは、デフォルトでスタンバイテナントとなります。メインテナントとしてサービスを提供するには、`ALTER SYSTEM ACTIVATE STANDBY` ステートメントを実行する必要があります。`ALTER SYSTEM ACTIVATE STANDBY` ステートメントの詳細については、[ACTIVATE STANDBY](100.activate.md)を参照してください。

## 権限要件

`ALTER SYSTEM RESTORE` ステートメントを実行できるのは、`sys` テナントの `root` ユーザー (`root@sys`) のみです。

## 構文

```sql
ALTER SYSTEM RESTORE dest_tenant_name FROM uri [ UNTIL {TIME='timestamp' | SCN=scn} ] WITH 'restore_option' [WITH KEY FROM 'backup_key_path' ENCRYPTED BY 'password'] [DESCRIPTION [=] 'description'];

restore_option:
  pool_list=pool_name[&locality=locality][&primary_zone=zone_name][&concurrency=int_num][&kms_encrypt={true | false}]
```

## パラメータの説明

|         パラメータ        |     説明                                                          |
|--------------------|-------------------------------------------------------------------|
| dest_tenant_name   | 復旧する新テナントの名前を指定します。                                                |
| uri                | バックアップ時に設定されたデータバックアップパス `backup_data_dest` とログアーカイブパス `log_archive_dest` を指定します。この値には少なくとも1つのデータバックアップパスと1つのログアーカイブパスが含まれ、パス間は `,` で区切ります。<p>現在、OceanBaseデータベースがサポートしているアーカイブ宛先メディアはNFS、Alibaba Cloud OSS、Azure Blob(V4.2.5バージョンではV4.2.5 BP6バージョンからサポート)、AWS S3、およびS3プロトコルに互換性のあるオブジェクトストレージです。例：Huawei OBS、Google GCS、Tencent Cloud COS。`uri` パスの例については、[SET LOG_ARCHIVE_DEST](150.set-log-archive-dest.md)または[SET DATA_BACKUP_DEST](3500.set-data-backup-dest.md)を参照してください。</p> |
| timestamp          | 指定されたタイムスタンプに復旧します。このタイムスタンプまで復旧し、その `timestamp` ポイントを含みます。指定された `timestamp` は `=` で結合する必要があります。`timestamp` は `YYYY-MM-DD HH24:MI:SS.FF` フォーマットのみをサポートしており、小数部（`FF`）は0〜6桁の小数点以下をサポートしており、マイクロ秒単位で正確になります。復旧時に `timestamp` と `scn` の値をどのように選択するかについて詳しくは、[物理復旧関連パラメータの紹介](../../../../../600.manage/600.backup-and-recovery/600.restore-data/800.parameters-of-the-restore.md)を参照してください。|
| scn                | 指定されたSCNに復旧します。このSCNポイントまで復旧し、その `scn` ポイントを含みます。指定された `scn` は `=` で結合する必要があります。|
| restore_option       | `pool_list`、`locality`、`primary_zone`、`concurrency`、`kms_encrypt` などのパラメータをサポートしており、異なるパラメータ間は `&` で区切ります。localityとprimary_zoneを指定する際は、ソーステナントと同構成に保つことを推奨します。異構成の場合、テナント復旧後にプライマリテナントとしてアクティブ化されると、ロードバランシング操作が発生し、パフォーマンスに影響を与える可能性があります。<ul><li>`pool_list`：必須項目。復旧対象の新テナントが作成されたリソースプールを入力します。複数のリソースプール間は、英語のカンマ（,）で区切ります。</li>  <li>`locality`：オプション。新テナントのレプリカ分散のローカリティ情報を指定します。新テナントが属するクラスタのpool_listのZone情報と一致させる必要があります。ソーステナントと同構成の場合、新テナントとソーステナントのFレプリカ数が同じであることを推奨します。明示的に指定しない場合、デフォルトでは `resource_pool` の `zone_list` に従って各Zoneに1つのFレプリカが設定されます。</br>入力例: `locality='F@z1,F@z2,F@z3'`。 </li>  <li> `primary_zone`：オプション。新テナントのリーダーレプリカの優先位置を指定します。`pool_list` および `locality` と一致させる必要があります。つまり、Zone情報の一致と `primary_region` 内に少なくとも2つのPaxosメンバーが存在するなどの制限を満たす必要があります。ソーステナントと同構成の場合、新テナントとソーステナントの第一優先順位のPrimary Zone数が同じであることを推奨します。明示的に指定しない場合、システムは `locality` の `zone_list` に従ってこれらのZoneにリーダーをランダムに分散します。</br>入力例: `primary_zone='z1'`</li> <li>`concurrency`：オプション。データ復旧の並列度を指定します。明示的に指定しない場合、デフォルトでそのテナントに割り当てられたMAX_CPU数と等しくなります。例えば、システムテナントが復旧対象のテナントに割り当てた `MAX_CPU` が16であると仮定すると、明示的に指定しない場合、`concurrency` のデフォルト値は16になります。</br>入力例: `concurrency=50`</li> <li>`kms_encrypt`：オプション。`true` の場合、復旧時に復旧前に指定した `kms_encrypt_info` を使用する必要があることを示します。</li></ul>   |
| WITH KEY FROM 'backup_key_path' ENCRYPTED BY 'password' | 暗号化テナントの秘密鍵バックアップ情報を指定します。ソーステナントに透過的暗号化が設定されている場合に限り、復旧時に秘密鍵バックアップ関連情報を指定する必要があります。その内容は以下のとおりです。<ul><li><code>backup_key_path</code>：秘密鍵のバックアップパス。</li> <li><code>password</code>：バックアップ秘密鍵時に設定した暗号化パスワード。</li></ul> |
| description |オプションで、ユーザーが指定する説明情報です。 |

## 例

* NFSデータバックアップパスとNFSログアーカイブパスから、テナント`mysql`を指定されたタイムスタンプ`2022-06-01 00:00:00`まで復元します。リソースプールは`restore_pool`、コピーローカリティは`F@z1,F@z2,F@z3`、`primary_zone`は`z1`と指定します。

   ```sql
   obclient [oceanbase]> ALTER SYSTEM RESTORE mysql FROM 'file:///data/nfs/backup/data,file:///data/nfs/backup/archive' UNTIL TIME='2022-06-01 00:00:00' WITH 'pool_list=restore_pool&locality=F@z1,F@z2,F@z3&primary_zone=z1';
   ```

* NFSデータバックアップパスとNFSログアーカイブパスから、テナント`mysql`を現在の最新のアーカイブポイントまで復元します。リソースプールは`restore_pool`、データ復元の並列度`concurrency`は50と指定します。

   ```sql
   obclient [oceanbase]> ALTER SYSTEM RESTORE mysql FROM 'file:///data/nfs/backup/data,file:///data/nfs/backup/archive' WITH 'pool_list=restore_pool&concurrency=50';
   ```

* NFSデータバックアップパスとNFSログアーカイブパスから、テナント`mysql`を指定されたSCNまで復元します。リソースプールは`restore_pool`と指定します。

   ```sql
   obclient [oceanbase]> ALTER SYSTEM RESTORE mysql FROM 'file:///data/nfs/backup/data,file:///data/nfs/backup/archive' UNTIL SCN=1658285759724047000 WITH 'pool_list=restore_pool';
   ```

* OSSバックアップパスとOSSログアーカイブパスから、テナント`mysql`を指定されたタイムスタンプ`2022-06-01 00:00:00`まで復元します。リソースプールは`restore_pool`と指定します。

   ```sql
   obclient [oceanbase]> ALTER SYSTEM RESTORE mysql FROM 'oss://oceanbase-test-bucket/backup/data/?host=xxx.aliyun-inc.com&access_id=xxx&access_key=xxx,oss://oceanbase-test-bucket/backup/archive/?host=xxx.aliyun-inc.com&access_id=xxx&access_key=xxx' UNTIL TIME='2022-06-01 00:00:00' WITH 'pool_list=restore_pool';
   ```

* ターゲットクラスタで`RESTORE`コマンドを実行し、テナントのバックアップとアーカイブを使用して、スタンバイテナントを作成および復元します。

   ```sql
   obclient [oceanbase]> ALTER SYSTEM RESTORE restore_oracle_tenant FROM 'file:///data/nfs/backup//ob_backup_oracle_tenant/archive,file:///data/nfs/backup//ob_backup_oracle_tenant/data' UNTIL TIME='2022-11-11 15:04:23.825558' with 'pool_list=small_pool_2&primary_zone=z1';
   ```
