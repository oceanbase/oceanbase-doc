# CANCEL DELETE BACKUP

## 説明

`CANCEL DELETE BACKUP` ステートメントは、実行中のクリーンアップタスクをキャンセルするために使用します。

`CANCEL DELETE BACKUP` ステートメントは、実行中のクリーンアップタスクのみをキャンセルします。キャンセルしたいクリーンアップタスクが今後スケジュールされないようにするには、まず `DROP DELETE BACKUP POLICY` ステートメントで自動クリーンアップポリシーを削除し、その後 `CANCEL DELETE BACKUP` ステートメントを実行する必要があります。`DROP DELETE BACKUP POLICY` ステートメントの詳細については、[DELETE BACKUP](1270.delete-backup.md)を参照してください。

## 権限要件

`sys` テナントの `root` ユーザー(`root@sys`)または各テナントの管理者ユーザーが実行する必要があります。具体的には：

* MySQLモードのデフォルト管理者ユーザーは `root` ユーザーです。
* Oracleモードのデフォルト管理者ユーザーは `SYS` ユーザーです。

## 構文

```sql
ALTER SYSTEM CANCEL DELETE BACKUP [TENANT [=] {tenant_name[, tenant_name]...} ];
```

## パラメータ説明

| パラメータ            | 説明                                                                                                               |
|-----------------|--------------------------------------------------------------------------------------------------------------------|
| tenant_name     | システムテナントがキャンセル対象のクリーンアップタスクを持つテナント名を指定します。複数のテナント名を同時に指定することができ、異なるテナント名は半角カンマ（,）で区切ります。システムテナントで `TENANT = tenant_name` 句を指定しない場合、すべてのユーザーテナントで実行中のクリーンアップタスクを同時にキャンセルすることを意味します。<main id="notice" type='notice'> <h4>注意</h4><p>このコマンドを実行する際、システムテナントのみが <code>TENANT = tenant_name</code> 句を使用して操作対象のテナントを指定できます。ユーザーテナントは自身のテナントでのみこのコマンドを実行できるため、<code>TENANT = tenant_name</code> 句を指定することはできません。</p></main>                        |

## 例

* システムテナントが `mysql_tenant` テナントのクリーンアップポリシー `default` をキャンセルします。

  ```shell
  obclient [oceanbase]> ALTER SYSTEM DROP DELETE BACKUP POLICY 'default' TENANT = mysql_tenant;
  ```

* システムテナントが `mysql_tenant` テナントおよび `oracle_tenant` テナントで実行中のクリーンアップタスクをキャンセルします。

  ```shell
  obclient [oceanbase]> ALTER SYSTEM CANCEL DELETE BACKUP TENANT mysql_tenant, oracle_tenant;
  ```

* テナント `oracle_tenant` が自身のテナントで実行中のクリーンアップタスクをキャンセルします。

  ```sql
  obclient [SYS]> ALTER SYSTEM CANCEL DELETE BACKUP;
  ```
