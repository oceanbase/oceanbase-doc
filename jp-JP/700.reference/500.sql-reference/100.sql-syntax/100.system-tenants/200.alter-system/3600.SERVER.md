# SERVER

## 説明

このステートメントは、システム内のOBServerの状態を管理し、OBServerの追加、削除、起動、停止などの操作を制御します。

このステートメントはsysテナントでのみ実行がサポートされています。

## 構文

```sql
alter_system_server_stmt:
    ALTER SYSTEM server_action SERVER ip_port_list [zone];

server_action:
      ADD
    | DELETE
    | CANCEL DELETE
    | START
    | STOP
    | FORCE STOP
    | ISOLATE

ip_port_list:
    ip_port [, ip_port ...]
```

## パラメータの説明

|    **パラメータ**    |      **説明**      |
|---------------|----------------------|
| ip_port       | OBServerのIPアドレスとポートを指定します。   |
| zone          | Zoneを指定した場合、対象のServerに対してZone検証が実行されます。   |
| ADD           | OBServerを追加します。`ADD`はOBServerをサービスリストに追加し、サービスリストに含まれるOBServerのみがサービスを提供できます。 |
| DELETE        | OBServerを削除します。`DELETE`操作は、OBServerがクリアされた後にサービスリストから削除され、この操作によりUnit移行が発生します。   |
| CANCEL DELETE | OBServerの削除を取り消します。    |
| START         | OBServerを起動します。  |
| STOP          | OBServerを停止します。`STOP`は、停止後のレプリカ数が多数派を満たしているか確認し、Clogログの同期完了を待機し、Leaderレプリカが他のノードに切り替わる（つまりLeader再選出）のを待機します。     |
| FORCE STOP    | OBServerを強制的に停止します。`FORCE STOP`は、停止後のレプリカ数が多数派を満たしているか確認し、Leaderレプリカが他のノードに切り替わる（つまりLeader再選出）のを待機します。 <main id="notice" type='notice'><h4>注意</h4><p> OBServerの強制停止は通常の運用操作ではありません。強制停止はClogログの同期完了を待たないため、この操作は安全ではなく、一般的には使用を推奨しません。</p></main>  |
| ISOLATE       | 故障したOBServerを隔離します。新しい読み書きリクエストは、隔離された故障したマシンのプロセスにルーティングされません。`ISOLATE`は、Leaderレプリカが他のノードに切り替わる（つまりLeader再選出）のを待機しません。       |

## 例

クラスタにOBServer `xxx.xx.xxx.xx1` を追加します。

```sql
obclient> ALTER SYSTEM ADD SERVER 'xxx.xx.xxx.xx1:xxxx' ZONE 'zone1';
```
