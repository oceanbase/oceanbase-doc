# MAJORとMINOR

## 概要

このステートメントは、システムテナントからストレージ層のコンパクションまたはダンプ（フリーズ）を開始するために使用されます。手動コンパクションはテナントレベルのみがサポートされており、手動ダンプはテナントレベル、ゾーンレベル、サーバーレベル、ログストリームレベル、パーティションレベルをサポートしています。

## 構文

```sql
ALTER SYSTEM merge_action;

merge_action:
      MAJOR FREEZE [tenant_list]
    | MAJOR FREEZE [tenant_list]
    | MINOR FREEZE [tenant_list | server_list | zone_list | {TENANT [=] tenant_name LS [=] ls_id} | {TENANT [=] tenant_name TABLET_ID = tablet_id}]
    | {SUSPEND | RESUME} MERGE [tenant_list]
    | CLEAR MERGE ERROR [tenant_list]

tenant_list:
    TENANT [=]  { all | all_user | all_meta } | tenant_name [, tenant_name ...]

server_list:
    SERVER [=] ('ip:port' [, 'ip:port'...])

zone_list:
    ZONE [=] ('zone_name' [, 'zone_name' ...]);
```

## パラメータの説明

|          **パラメータ**         |      **説明**      |
|---------------------------|------------------|
| MAJOR FREEZE              | 毎日のメジャーフリーズを実行します。<br>`TENANT=all`または`TENANT=all_user`を使用すると、すべてのユーザーテナント（システムテナントとMetaテナントを除く）をマージできます。`all_user`を使用することを推奨します。`all`は今後廃止されます。`TENANT=all_meta`を使用すると、すべてのMetaテナントをマージできます。また、`TENANT=tenant_name [, tenant_name ...]`を使用して特定のテナントのみをマージすることもできます。</br>       |
| MINOR FREEZE              | マイナーフリーズを実行します。            |
| {SUSPEND \| RESUME} MERGE | 毎日のメジャーフリーズを一時停止または再開します。<br>`TENANT=all`または`TENANT=all_user`を使用すると、すべてのテナント（システムテナントとMetaテナントを除く）の毎日のメジャーフリーズを一時停止または再開できます。`all_user`を使用することを推奨します。`all`は今後廃止されます。`TENANT=all_meta`を使用すると、すべてのMetaテナントの毎日のメジャーフリーズを一時停止または再開できます。また、`TENANT=tenant_name [, tenant_name ...]`を使用して特定のテナントのみの毎日のメジャーフリーズを一時停止または再開することもできます。</br>      |
| CLEAR MERGE ERROR         | メジャーフリーズエラーをクリアします。<br>`TENANT=all`または`TENANT=all_user`を使用すると、すべてのテナント（システムテナントとMetaテナントを除く）のメジャーフリーズエラーをクリアできます。`all_user`を使用することを推奨します。`all`は今後廃止されます。`TENANT=all_meta`を使用すると、すべてのMetaテナントのメジャーフリーズエラーをクリアできます。また、`TENANT=tenant_name [, tenant_name ...]`を使用して特定のテナントのみのメジャーフリーズエラーをクリアすることもできます。</br>       |
| MAJOR FREEZE TENANT [=] tenant_name  | 特定テナントのメジャーフリーズを指定します。<main id="notice" type='explain'><h4>説明</h4><p>このステートメントは、システム（sys）テナントでのみ実行できます。</p></main>|
| tenant_name               | テナントのメジャーフリーズまたはマイナーフリーズを指定します。          |
| TABLET_ID                 | パーティションのマイナーフリーズを指定します。          |
| SERVER                    | サーバーのマイナーフリーズを指定します。          |
| ZONE                      | ZONEのマイナーフリーズを指定します。         |
| LS                        | ログストリームのマイナーフリーズを指定します。          |

## 例

### ストレージレイヤーのメジャーコンパクションの例

* システムテナントがシステムテナントの毎日のメジャーコンパクションを開始します。

  ```sql
  obclient> ALTER SYSTEM MAJOR FREEZE;
  Query OK, 0 rows affected
  ```

* システムテナントがすべてのユーザーテナント（システムテナントとMetaテナントを除く）のメジャーコンパクションを開始します。

  ```sql
  obclient> ALTER SYSTEM MAJOR FREEZE TENANT = all_user;
  Query OK, 0 rows affected
  ```

* システムテナントがすべてのMetaテナントのメジャーコンパクションを開始します。

  ```sql
  obclient> ALTER SYSTEM MAJOR FREEZE TENANT = all_meta;
  Query OK, 0 rows affected
  ```

* システムテナントが指定されたテナント `tenant1` および `tenant2` のメジャーコンパクションを開始します。

  ```sql
  obclient> ALTER SYSTEM MAJOR FREEZE TENANT = tenant1,tenant2;
  Query OK, 0 rows affected
  ```

### ストレージレイヤーのダンプの例

* システムテナントがシステムテナントのダンプを開始します。

  ```sql
  obclient> ALTER SYSTEM MINOR FREEZE;
  Query OK, 0 rows affected
  ```

* システムテナントがすべてのユーザーテナント（システムテナントとMetaテナントを除く）のダンプを開始します。

  ```sql
  obclient> ALTER SYSTEM MINOR FREEZE TENANT = all_user;
  Query OK, 0 rows affected
  ```

* システムテナントがすべてのMetaテナントのダンプを開始します。

  ```sql
  obclient> ALTER SYSTEM MINOR FREEZE TENANT = all_meta;
  Query OK, 0 rows affected
  ```

* システムテナントが指定されたテナント `tenant1` および `tenant2` のダンプを開始します。

  ```sql
  obclient> ALTER SYSTEM MINOR FREEZE TENANT = tenant1,tenant2;
  Query OK, 0 rows affected
  ```

* システムテナントが指定されたテナント `tenant1` の指定されたパーティションのダンプを開始します。

  ```sql
  obclient> ALTER SYSTEM MINOR FREEZE tenant = tenant1 tablet_id = 1100611139453887;
  Query OK, 0 rows affected
  ```

* システムテナントが指定されたOBServerのダンプを開始します。

  ```sql
  obclient> ALTER SYSTEM MINOR FREEZE SERVER = ('10.XXX.XXX.XXX:2882');
  Query OK, 0 rows affected
  ```

* システムテナントが指定されたテナントの指定されたログストリームのダンプを開始します。

   ```sql
   obclient> ALTER SYSTEM MINOR FREEZE tenant = t1 LS 1;
   Query OK, 0 rows affected
   ```

* システムテナントが指定されたテナントの指定されたログストリーム内の指定されたパーティションのダンプを開始します。

   ```sql
   obclient> ALTER SYSTEM MINOR FREEZE tenant = t1 ls 1 tablet_id = 60000;
   Query OK, 0 rows affected
   ```

### 毎日のメジャーコンパクションの一時停止または再開の例

* システムテナントは、システムテナントおよびメタテナントを除くすべてのユーザーテナントの毎日のメジャーコンパクションを一時停止します。

  ```sql
  obclient> ALTER SYSTEM SUSPEND MERGE TENANT = all_user;
  Query OK, 0 rows affected
  ```

* システムテナントは、指定されたテナント `tenant1` と `tenant2` の毎日のメジャーコンパクションを一時停止します。

  ```sql
  obclient> ALTER SYSTEM SUSPEND MERGE TENANT = tenant1,tenant2;
  Query OK, 0 rows affected
  ```

* システムテナントは、すべてのメタテナントの毎日のメジャーコンパクションを一時停止します。

  ```sql
  obclient> ALTER SYSTEM SUSPEND MERGE TENANT = all_meta;
  Query OK, 0 rows affected
  ```

* システムテナントは、システムテナントおよびメタテナントを除くすべてのユーザーテナントの毎日のメジャーコンパクションを再開します。

  ```sql
  obclient> ALTER SYSTEM RESUME MERGE TENANT = all_user;
  Query OK, 0 rows affected
  ```

* システムテナントは、指定されたテナント `tenant1` と `tenant2` の毎日のメジャーコンパクションを再開します。

  ```sql
  obclient> ALTER SYSTEM RESUME MERGE TENANT = tenant1,tenant2;
  Query OK, 0 rows affected
  ```

* システムテナントは、すべてのメタテナントの毎日のメジャーコンパクションを再開します。

  ```sql
  obclient> ALTER SYSTEM RESUME MERGE TENANT = all_meta;
  Query OK, 0 rows affected
  ```

### メジャーコンパクションエラーのマークをクリアする例

* システムテナントは、システムテナントおよびメタテナントを除くすべてのユーザーテナントのメジャーコンパクションエラーのマークをクリアします。

  ```sql
  obclient> ALTER SYSTEM CLEAR MERGE ERROR TENANT = all_user;
  Query OK, 0 rows affected
  ```

* システムテナントは、指定されたテナント `tenant1` と `tenant2` のメジャーコンパクションエラーのマークをクリアします。

  ```sql
  obclient> ALTER SYSTEM CLEAR MERGE ERROR TENANT = tenant1,tenant2;
  Query OK, 0 rows affected
  ```

* システムテナントは、すべてのメタテナントのメジャーコンパクションエラーのマークをクリアします。

  ```sql
  obclient> ALTER SYSTEM CLEAR MERGE ERROR TENANT = all_meta;
  Query OK, 0 rows affected
  ```

### パーティションレベルのダンプを開始する

1. テーブルのTABLET IDを照会します。

    **例：**

    ```sql
    SELECT t1.tenant_id, t2.tenant_name, t1.database_name, t1.table_id, t1.table_name, t1.tablet_id, t1.PARTITION_NAME, t1.SUBPARTITION_NAME
    FROM oceanbase.CDB_OB_TABLE_LOCATIONS t1, oceanbase.DBA_OB_TENANTS t2
    WHERE t1.tenant_id=t2.tenant_id
    AND t1.table_name = 'test_tbl1'
    AND t2.tenant_name = 'oracle001';
    ```

    実行結果は次のとおりです：

    ```shell
    +-----------+-------------+---------------+----------+------------+-----------+----------------+-------------------+
    | tenant_id | tenant_name | database_name | table_id | table_name | tablet_id | PARTITION_NAME | SUBPARTITION_NAME |
    +-----------+-------------+---------------+----------+------------+-----------+----------------+-------------------+
    |      1004 | oracle001   | SYS           |   500011 | TEST_TBL1  |    200008 | P1             | SP0               |
    |      1004 | oracle001   | SYS           |   500011 | TEST_TBL1  |    200009 | P1             | SP1               |
    |      1004 | oracle001   | SYS           |   500011 | TEST_TBL1  |    200010 | P1             | SP2               |
    |      1004 | oracle001   | SYS           |   500011 | TEST_TBL1  |    200011 | P1             | SP3               |
    |      1004 | oracle001   | SYS           |   500011 | TEST_TBL1  |    200012 | P2             | SP4               |
    |      1004 | oracle001   | SYS           |   500011 | TEST_TBL1  |    200013 | P2             | SP5               |
    |      1004 | oracle001   | SYS           |   500011 | TEST_TBL1  |    200014 | P2             | SP6               |
    |      1004 | oracle001   | SYS           |   500011 | TEST_TBL1  |    200015 | P2             | SP7               |
    +-----------+-------------+---------------+----------+------------+-----------+----------------+-------------------+
    8 rows in set
    ```

    詳細なビューのフィールド情報については、[oceanbase.CDB_OB_TABLE_LOCATIONS](../../../../700.system-views/300.system-view-of-sys-tenant/200.dictionary-view-of-sys-tenant/10400.o-cdb_ob_table_locations-of-sys-tenant.md)を参照してください。

2. ダンプを開始します。

    **例：**

    ```sql
    ALTER SYSTEM MINOR FREEZE TENANT = oracle001 TABLET_ID = 200008;
    ```
