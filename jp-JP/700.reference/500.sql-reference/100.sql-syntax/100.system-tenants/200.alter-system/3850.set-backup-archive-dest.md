# SET BACKUP_ARCHIVE_DEST

## 説明

`ALTER SYSTEM SET BACKUP_ARCHIVE_DEST` ステートメントは、ユーザーテナントのアーカイブログバックアップのバックアップ宛先、つまりアーカイブログバックアップファイルの保存パスを設定するために使用されます。

## 使用上の制限と注意事項

* V4.4.2バージョンでは、V4.4.2 BP3バージョンから `ALTER SYSTEM SET BACKUP_ARCHIVE_DEST` ステートメントがサポートされています。

* システムテナントとMetaテナントはバックアップ・リストアをサポートしていないため、バックアップ宛先の設定は不要です。ユーザーテナントに対してのみ `BACKUP_ARCHIVE_DEST` の設定が可能です（既存のログアーカイブ機能と一致します）。

* アーカイブログバックアップの宛先は `LOG_ARCHIVE_DEST` と同じにすることはできません。

* `BACKUP_ARCHIVE_DEST` の変更とアーカイブログバックアップタスクの開始は相互排他です：`BACKUP_ARCHIVE_DEST` を変更している間にアーカイブログバックアップを開始すると失敗します。アーカイブログバックアップタスクが終了していない場合は `BACKUP_ARCHIVE_DEST` を変更できず、システムは `OPT_NOT_ALLOW` エラーを返します。

* `BACKUP_ARCHIVE_DEST` の変更と `PLUS ARCHIVELOG` パラメータを持つデータバックアップタスクの開始は相互排他です：`PLUS ARCHIVELOG` パラメータを持つデータバックアップタスクの実行中に `BACKUP_ARCHIVE_DEST` から Pieceファイルをコピーする可能性があるため、Pieceがコピー中に削除されるのを防ぐために、`BACKUP_ARCHIVE_DEST` を変更している間に `PLUS ARCHIVELOG` パラメータを持つデータバックアップタスクを開始すると失敗します。`PLUS ARCHIVELOG` パラメータを持つデータバックアップタスクの実行中に `BACKUP_ARCHIVE_DEST` を変更すると、変更操作が失敗し、システムは `OPT_NOT_ALLOW` エラーを返します。

* 現在、OceanBaseデータベースでサポートされているバックアップメディアは、NFS、Alibaba Cloud OSS、Azure Blob、AWS S3、およびS3プロトコルに準拠したオブジェクトストレージです。例：Huawei OBS、Google GCS、Tencent Cloud COS。一部のバックアップメディアは使用する前にいくつかの基本要件を満たす必要があります。各バックアップメディアの具体的な要件については、[物理バックアップとリストアの概要](../../../../../600.manage/600.backup-and-recovery/100.overview-of-physical-backup-and-recovery.md)の**バックアップメディア要件**を参照してください。

## 権限要件

`sys` テナントの `root` ユーザー(`root@sys`)または各テナントの管理者ユーザーによって実行する必要があります。詳細は以下の通りです：

* MySQLモードのデフォルト管理者ユーザーは `root` ユーザーです。
* Oracleモードのデフォルト管理者ユーザーは `SYS` ユーザーです。

## 構文

```sql
ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=backup_archive_path' [TENANT = tenant_name];
```

## パラメータ説明

| パラメータ                  |                     説明                        |
|-----------------------|------------------------------------------------|
| backup_archive_path      | アーカイブログバックアップのバックアップパスを指定します。このパラメータの詳細については、下記の[backup_archive_path](#backup_archive_path)を参照してください。 |
| tenant_name           | システムテナントがアーカイブログバックアップの宛先を設定するテナント名を指定します。<main id="notice" type='notice'> <h4>注意</h4><p>このコマンドを実行する際は、システムテナントのみが <code>TENANT = tenant_name</code> 句を使用して操作対象のテナントを指定する必要があります。ユーザーテナントは自身のテナントでのみこのコマンドを実行できるため、この句を指定する必要はありません。</p></main> |

### backup_archive_path

アーカイブログバックアップのバックアップパス設定を指定するために使用されます。以下では、異なる種類のメディアに対する `backup_archive_path` の形式について説明します。

#### NFS

```sql
ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=file://your-nfs-server/your-backup-path' [TENANT = tenant_name];
```

ここで：

* `file://your-nfs-server/your-backup-path`：OceanBaseデータベースがアクセス可能なNFSサーバーのパスで、アーカイブログのバックアップファイルを保存するために使用されます。

#### オブジェクトストレージ

```sql
# Alibaba Cloud OSS
ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=oss://your-bucket-name/your-archive-path?host=oss-your-region.aliyuncs.com&access_id=your-access-id&access_key=your-access-key[&delete_mode={delete | tagging}][&checksum_type={md5 | no_checksum}][&enable_worm=true]' [TENANT = tenant_name];

# AWS S3
ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=s3://your-bucket-name/your-archive-path?host=s3.your-region.amazonaws.com&access_id=your-access-id&access_key=your-access-key&s3_region=your-s3-region[&delete_mode={delete | tagging}][&checksum_type={md5 | crc32}]' [TENANT = tenant_name];

# S3プロトコル互換のオブジェクトストレージ（例：Huawei OBS、Google GCS、Tencent Cloud COS）
ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=s3://your-bucket-name/your-archive-path?host=your-service.com&access_id=your-access-id&access_key=your-access-key[&addressing_model={virtual_hosted_style | path_style}][&checksum_type=md5]' [TENANT = tenant_name];

# Azure Blob
ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=azblob://your-bucket-name/your-archive-path?host=http://your-service.com&access_id=your-access-id&access_key=your-access-key[&delete_mode={delete | tagging}][&checksum_type=md5]' [TENANT = tenant_name];
```

関連パラメータの説明は以下のとおりです：

<main id="notice" type='notice'>
<h4>注意</h4>
<p>オブジェクトストレージをバックアップ媒体として使用する場合、オブジェクトストレージのパスに含まれる各パラメータは <code>&</code> 記号で区切られます。入力するパラメータ値には、英字の大文字と小文字、数字、<code>/-_$+=</code> およびワイルドカードのみ含まれていることを確認してください。上記以外の文字を入力した場合、設定が失敗する可能性があります。</p>
</main>

* `host`：オブジェクトストレージサービスへのアクセスドメイン名。

  Azure Blobオブジェクトストレージの場合、`host` パラメータの値はコンテナのプロパティまたはストレージアカウントの接続文字列を連結して取得できます。`host` パラメータのプレフィックスには、`http://` または `https://` を指定する必要があります。Azure Blobではデフォルトで安全な転送が有効になっているため、通常は `https://` でアクセスします。`http://` でアクセスする場合は、Azure Blobの安全な転送オプションを無効にする必要があります。Azure Blobの安全な転送オプションを無効にする詳細な操作については、[Azure Blob公式ドキュメント](https://learn.microsoft.com/en-us/azure/storage/common/storage-require-secure-transfer?toc=%2Fazure%2Fstorage%2Fblobs%2Ftoc.json&bc=%2Fazure%2Fstorage%2Fblobs%2Fbreadcrumb%2Ftoc.json)を参照してください。

* `access_id`：オブジェクトストレージのアクセスキーID。

* `access_key`：オブジェクトストレージのアクセスキー。

* `delete_mode`：バックアップファイルのクリーンアップモードを設定します。このパラメータはOSS、AWS S3、COS（S3プロトコルでアクセスする場合）、Azure Blobで利用できるオプションパラメータであり、他のパラメータとは `&` 記号で結合されます。現在、このパラメータでサポートされている値は以下の2種類です：

  * `delete`：クリーンアップモードが直接削除であることを示します。これは、クリーンアップ要件を満たすバックアップファイルを直接削除します。

    このモードに設定すると、バックアップファイルを自動的にクリーンアップする際、クリーンアップ要件を満たすバックアップファイルはシステムによって直接削除されます。

  * `tagging`：クリーンアップ要件を満たすバックアップファイルに`Tag`を設定するクリーンアップモードであることを示します。バックアップファイルは保持されます。

    このモードに設定すると、バックアップファイルを自動的にクリーンアップする際、クリーンアップ要件を満たすバックアップファイルにシステムがタグを設定します。タグの`key`は`"delete_mode"`、`value`は`"tagging"`となり、ユーザーは後から設定されたタグを使ってオブジェクトストレージ上でこれらのファイルのライフサイクルを管理できます。

* `checksum_type`：バックアップファイルの整合性を検証するためのチェックサムアルゴリズムを指定します。明示的に指定しない場合、すべてのオブジェクトストレージはデフォルトでMD5チェックサムアルゴリズムを使用します。オブジェクトストレージによって、このパラメータでサポートされている値は以下のとおりです：

  * `md5`：MD5アルゴリズムを使用してバックアップファイルの整合性を検証します。

  * `no_checksum`：バックアップファイルの整合性を検証しません。この値はOSSとAzure Blobでのみサポートされています。S3プロトコルでアクセスするオブジェクトストレージ、AWS S3、OBS、GCS、COSなどでは、S3 SDKの制限により、この値はサポートされていません。

  * `crc32`：CRC32アルゴリズムを使用してバックアップファイルの整合性を検証します。この値はAWS S3でのみサポートされています。

* `enable_worm`：オプションパラメータです。バックアップの宛先がAlibaba Cloud OSSであり、かつ宛先のBucketにコンプライアンス保持ポリシー（WORM）が設定されている場合、このパラメータを`true`に設定する必要があります。

  OSSの保持ポリシーにはWORM（Write Once Read Many）特性があり、ユーザーがデータを削除不可・改ざん不可の状態で保存および使用できるようにします。ユーザーがBucketに保持ポリシーを設定し、そのポリシーをロックすると、保持ポリシーで指定されたObjectの保持期間が満了するまで、そのBucket内ではObjectのアップロードと読み取りのみが可能になります。Objectの保持期間が満了すると、そのObjectを変更または削除できます。

  <main id="notice" type='notice'>
  <h4>注意</h4>
  <ul>
  <li>OceanBaseデータベースは現在、コンプライアンス保持ポリシーの設定を代行するものではありません。バックアップパスを設定する前に、OSSバケットで保持ポリシー（WORMポリシー）が正しく設定され、ロックされていることを確認してください。</li>
  <li>設定対象のパスが属するバケットにWORMポリシーが設定・ロックされており、バックアップの宛先設定時に<code>enable_worm=true</code>を指定しなかった場合、ステートメント実行後にシステムはエラーを返し、<code>enable_worm=true</code>の設定が必要であることを示します。</li>
  <li><code>enable_worm</code>パラメータは一度設定すると、その後の変更はサポートされません。</li>
  <li>WORMポリシーが設定されたバケットをバックアップパスとして使用する場合、バックアップのクリーンアップモードとして<code>tagging</code>モードの使用を推奨します。</li></ul>
  </main>

  `enable_worm`パラメータのサポート値は以下のとおりです：

  * `true`：はい。OceanBaseデータベースがWORMの仕様に従って、そのパスに対する書き込みおよび削除操作を実行することを示します。<code>true</code>に設定する場合、<code>checksum_type=md5</code>も明示的に設定する必要があります。

  * `false`：いいえ。このパラメータが明示的に指定されていない場合、デフォルト値は`false`です。

* `s3_region`：Amazon S3バケットが配置されているリージョン。バックアップ媒体がAWS S3の場合、必ず指定するパラメータです。

* `addressing_model`：オブジェクトストレージへのアクセスURL形式を設定します。S3互換プロトコルでアクセスするオブジェクトストレージ（OBS、GCS、COSなど）に対して使用できるオプションパラメータで、他のパラメータとは`&`記号で結合します。このパラメータは現在、以下の2つの値をサポートしています：

  * `virtual_hosted_style`：デフォルト値で、Virtual-hosted-styleでオブジェクトストレージにアクセスすることを示します。
  * `path_style`：Path-styleでオブジェクトストレージにアクセスすることを示します。

  例えば、ユーザーテナントが自身のテナントでOBSをバックアップ媒体として使用し、Virtual-hosted-style形式でOBSにアクセスするよう設定する場合、サンプルステートメントは以下のとおりです：

  ```shell
  ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=s3://oceanbase-test-bucket/backup/backup_archive?host=obs.****.myhuaweicloud.com&access_id=****&access_key=****&addressing_model=virtual_hosted_style';
  ```

## 例

* システムテナント

  * システムテナントがテナント `mysql_tenant` のアーカイブログバックアップの宛先をNFSに設定します。

    ```shell
    obclient [oceanbase]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=file:///data/nfs/backup/backup_archive' TENANT = mysql_tenant;
    ```

  * システムテナントがテナント `mysql_tenant` のアーカイブログバックアップの宛先をOSSに設定し、バックアップファイルのクリーンアップモードを `delete` に設定します。また、MD5アルゴリズムを使用してバックアップファイルの整合性を検証します。

    ```shell
    obclient [oceanbase]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=oss://oceanbase-test-bucket/backup/backup_archive?host=****.aliyun-inc.com&access_id=****&access_key=****&delete_mode=delete&checksum_type=md5' TENANT = mysql_tenant;
    ```

  * システムテナントがテナント `mysql_tenant` のアーカイブログバックアップの宛先をOSSに設定し、バックアップファイルのクリーンアップモードを `delete` に設定します。ただし、バックアップファイルの整合性は検証しません。

    ```shell
    obclient [oceanbase]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=oss://oceanbase-test-bucket/backup/backup_archive?host=****.aliyun-inc.com&access_id=****&access_key=****&delete_mode=delete&checksum_type=no_checksum' TENANT = mysql_tenant;
    ```

  * システムテナントがテナント `mysql_tenant` のアーカイブログバックアップの宛先をOSSに設定し、バックアップファイルのクリーンアップモードを `tagging` に設定します。また、MD5アルゴリズムを使用してバックアップファイルの整合性を検証します。

    ```shell
    obclient [oceanbase]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=oss://oceanbase-test-bucket/backup/backup_archive?host=****.aliyun-inc.com&access_id=****&access_key=****&delete_mode=tagging&checksum_type=md5' TENANT = mysql_tenant;
    ```

  * システムテナントがテナント `mysql_tenant` のアーカイブログバックアップの宛先をOSSに設定し、バックアップファイルのクリーンアップモードを `tagging` に設定します。また、MD5アルゴリズムを使用してバックアップファイルの整合性を検証します。このパスで `enable_worm=true` を設定すると、システムはWORMの仕様に従ってこのパスへの書き込みおよび削除操作を実行します。

    <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>OceanBaseデータベースは現在、コンプライアンス保持ポリシーの設定を代行するものではありません。バックアップパスを設定する前に、OSSバケットで保持ポリシー（WORMポリシー）が正しく設定され、ロックされていることを確認してください。</p>
    </main>

    ```shell
    obclient [oceanbase]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=oss://oceanbase-test-bucket/backup/backup_archive?host=****.aliyun-inc.com&access_id=****&access_key=****&delete_mode=tagging&checksum_type=md5&enable_worm=true' TENANT = mysql_tenant;
    ```

  * システムテナントがテナント `mysql_tenant` のアーカイブログバックアップの宛先をAWS S3に設定し、バックアップファイルのクリーンアップモードを `delete` に設定します。また、CRC32アルゴリズムを使用してバックアップファイルの整合性を検証します。

    ```shell
    obclient [oceanbase]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=s3://oceanbase-test-bucket/backup/backup_archive?host=s3.<region>.amazonaws.com&access_id=****&access_key=****&s3_region=****&delete_mode=delete&checksum_type=crc32' TENANT = mysql_tenant;
    ```

  * システムテナントがテナント `mysql_tenant` のアーカイブログバックアップの宛先をOBSに設定し、S3プロトコルでアクセスします。

    ```shell
    obclient [oceanbase]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=s3://oceanbase-test-bucket/backup/backup_archive?host=obs.****.myhuaweicloud.com&access_id=****&access_key=****' TENANT = mysql_tenant;
    ```

  * システムテナントがテナント `mysql_tenant` のアーカイブログバックアップの宛先をGCSに設定し、S3プロトコルでアクセスします。

    ```shell
    obclient [oceanbase]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=s3://oceanbase-test-bucket/backup/backup_archive?host=https://storage.googleapis.com&access_id=****&access_key=****' TENANT = mysql_tenant;
    ```

  * システムテナントがテナント `mysql_tenant` のアーカイブログバックアップの宛先をCOSに設定し、バックアップファイルのクリーンアップモードを `delete` に設定します。また、S3プロトコルでアクセスします。

    <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>COSをバックアップメディアとして使用する場合、事前にクラスタレベル構成パラメータ <a href="../../../../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16620.ob_storage_s3_url_encode_type.md">ob_storage_s3_url_encode_type</a> を設定する必要があります。詳細な操作については、<a href="../../../../../600.manage/600.backup-and-recovery/400.data-backup/100.preparation-before-data-backup.md">バックアップ前の準備</a>を参照してください。</p>
    </main>

    ```shell
    obclient [oceanbase]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=s3://oceanbase-test/backup/backup_archive?host=cos.ap-xxxx.myqcloud.com&access_id=***&access_key=***&delete_mode=delete' TENANT = mysql_tenant;
    ```

  * システムテナントがテナント`mysql_tenant`のアーカイブログバックアップ宛先を設定します。バックアップメディアはAzure Blob、クリーンアップモードは`delete`に設定し、検証アルゴリズムは`md5`を指定します。

    ```shell
    obclient [oceanbase]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=azblob://oceanbase-test-bucket/backup/backup_archive?host=http://****.blob.core.windows.net&access_id=****&access_key=****&delete_mode=delete&checksum_type=md5' TENANT = mysql_tenant;
    ```

* ユーザーテナント

  * テナント`mysql_tenant`が自身のアーカイブログバックアップ宛先を設定します。バックアップメディアはNFSです。

    ```shell
    obclient [oceanbase]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=file:///data/nfs/backup/backup_archive';
    ```

  * テナント`mysql_tenant`が自身のアーカイブログバックアップ宛先を設定します。バックアップメディアはOSS、バックアップファイルのクリーンアップモードは`tagging`、バックアップファイルの整合性検証にはMD5アルゴリズムを使用します。

    ```shell
    obclient [oceanbase]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=oss://oceanbase-test-bucket/backup/backup_archive?host=****.aliyun-inc.com&access_id=****&access_key=****&delete_mode=tagging&checksum_type=md5';
    ```

  * テナント`mysql_tenant`が自身のアーカイブログバックアップ宛先を設定します。バックアップメディアはOSS、バックアップファイルのクリーンアップモードは`tagging`、バックアップファイルの整合性検証にはMD5アルゴリズムを使用します。このパスで`enable_worm=true`を設定すると、システムはWORMの仕様に従ってこのパスへの書き込みおよび削除操作を実行します。

    </main>

    ```shell
    obclient [oceanbase]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=oss://oceanbase-test-bucket/backup/backup_archive?host=****.aliyun-inc.com&access_id=****&access_key=****&delete_mode=tagging&checksum_type=md5&enable_worm=true';
    ```

  * テナント`mysql_tenant`が自身のアーカイブログバックアップ宛先を設定します。バックアップメディアはAWS S3、バックアップファイルのクリーンアップモードは`tagging`、バックアップファイルの整合性検証にはCRC32アルゴリズムを使用します。

    ```shell
    obclient [oceanbase]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=s3://oceanbase-test-bucket/backup/backup_archive?host=s3.<region>.amazonaws.com&access_id=****&access_key=****&s3_region=****&delete_mode=tagging&checksum_type=crc32';
    ```

  * テナント`mysql_tenant`が自身のアーカイブログバックアップ宛先を設定します。バックアップメディアはOBS、S3プロトコルでアクセスします。

    ```shell
    obclient [oceanbase]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=s3://oceanbase-test-bucket/backup/backup_archive?host=obs.****.myhuaweicloud.com&access_id=****&access_key=****';
    ```

  * テナント`mysql_tenant`が自身のアーカイブログバックアップ宛先を設定します。バックアップメディアはGCS、S3プロトコルでアクセスします。

    ```shell
    obclient [oceanbase]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=s3://oceanbase-test-bucket/backup/backup_archive?host=https://storage.googleapis.com&access_id=****&access_key=****';
    ```

  * テナント`mysql_tenant`が自身のアーカイブログバックアップ宛先を設定します。バックアップメディアはCOS、バックアップファイルのクリーンアップモードは`delete`、S3プロトコルでアクセスします。

    <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>COSをバックアップメディアとして使用する場合、事前にクラスタレベル構成パラメータ<a href="../../../../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16620.ob_storage_s3_url_encode_type.md">ob_storage_s3_url_encode_type</a>を設定する必要があります。詳細な操作手順については、<a href="../../../../../600.manage/600.backup-and-recovery/400.data-backup/100.preparation-before-data-backup.md">データバックアップ前の準備</a>を参照してください。</p>
    </main>

    ```shell
    obclient [oceanbase]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=s3://oceanbase-test/backup/backup_archive?host=cos.ap-xxxx.myqcloud.com&access_id=***&access_key=***&delete_mode=delete';
    ```

  * テナント`mysql_tenant`が自身のアーカイブログバックアップ宛先を設定します。バックアップメディアはAzure Blob、クリーンアップモードは`delete`に設定し、検証アルゴリズムは`md5`を指定します。

    ```shell
    obclient [oceanbase]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=azblob://oceanbase-test-bucket/backup/backup_archive?host=http://****.blob.core.windows.net&access_id=****&access_key=****&delete_mode=delete&checksum_type=md5';
    ```

## アーカイブログバックアップ宛先の設定を確認する

アーカイブログバックアップの出力先を設定した後、以下のビューで設定情報を確認できます。関連するビューの `dest_type` フィールドには、アーカイブログバックアップ用に `backup_archive_log` という種別が追加されています。

システムテナントは `CDB_OB_BACKUP_STORAGE_INFO` および `CDB_OB_ARCHIVE_DEST` ビューを使用して、すべてのテナントのバックアップ出力先設定を確認できます。

```sql
obclient(root@sys)[(none)]> SELECT * FROM oceanbase.CDB_OB_BACKUP_STORAGE_INFO WHERE dest_type = 'backup_archive_log';
```

クエリ結果は次のとおりです：

```shell
+-----------+------------------------+----------+---------+--------------------+---------------+-----------+-----------------------------------------+----------------------------+----------+---------------+-----------------------+--------+
| TENANT_ID | PATH                   | ENDPOINT | DEST_ID | DEST_TYPE          | AUTHORIZATION | EXTENSION | CHECK_FILE_NAME                         | LAST_CHECK_TIMESTAMP       | MAX_IOPS | MAX_BANDWIDTH | MAX_BANDWIDTH_DISPLAY | STATUS |
+-----------+------------------------+----------+---------+--------------------+---------------+-----------+-----------------------------------------+----------------------------+----------+---------------+-----------------------+--------+
|      1002 | file:///data/backuparg |          |    1004 | backup_archive_log |               |           | 1002_connect_file_20260831T154520.obbak | 2026-08-31 15:45:20.327659 |        0 |             0 | UNLIMITED             | NORMAL |
+-----------+------------------------+----------+---------+--------------------+---------------+-----------+-----------------------------------------+----------------------------+----------+---------------+-----------------------+--------+
1 row in set
```

```sql
obclient(root@sys)[(none)]> SELECT * FROM oceanbase.CDB_OB_ARCHIVE_DEST WHERE name LIKE '%backup_archive%';
```

クエリ結果は次のとおりです：

```shell
+-----------+---------+------------------------+------------------------+
| TENANT_ID | DEST_NO | NAME                   | VALUE                  |
+-----------+---------+------------------------+------------------------+
|      1002 |   10000 | backup_archive_dest_id | 1004                   |
|      1002 |   10000 | backup_archive_path    | file:///data/backuparg |
|      1002 |   10000 | backup_archive_state   | ENABLE                 |
+-----------+---------+------------------------+------------------------+
3 rows in set
```

クエリ結果において、`CDB_OB_BACKUP_STORAGE_INFO` ビューの `PATH` フィールドはアーカイブログバックアップ出力先のストレージパスであり、`DEST_TYPE` フィールドの値が `backup_archive_log` であることは、その出力先のタイプがアーカイブログバックアップ出力先であることを示します。`CDB_OB_ARCHIVE_DEST` ビューでは、`backup_archive_path` の値がアーカイブログバックアップ出力先のパス、`backup_archive_dest_id` の値がその出力先の `dest_id`、`backup_archive_state` の値が `ENABLE` であることは、そのバックアップ出力先が有効な状態にあることを示します。

ユーザーテナントは `DBA_OB_BACKUP_STORAGE_INFO` および `DBA_OB_ARCHIVE_DEST` ビューを使用して、自身のテナントのバックアップ出力先設定を確認できます。

```sql
obclient(root@mysql001)[(none)]> SELECT * FROM oceanbase.DBA_OB_BACKUP_STORAGE_INFO WHERE dest_type = 'backup_archive_log';
```
