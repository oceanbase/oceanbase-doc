# パターンマッチング条件

パターンマッチング条件（Pattern-matching Condition）は、文字データを比較するために使用されます。

パターンマッチング条件のタイプには、`LIKE` 条件と `REGEXP_LIKE` 条件があります。

## LIKE 条件

`LIKE` 条件は、パターンマッチングに使用されます。等号演算子（=）は、ある文字値が別の文字値と完全に一致することを指しますが、`LIKE` 条件は、最初の値で2番目の文字値によって指定されたパターンを検索することで、ある文字値の一部と別の文字値を照合します。

`LIKE` は、入力文字セットで定義された文字を使用して文字列を計算します。

### LIKE 条件構文

```sql
char1 [NOT] LIKE char2 [ ESCAPE esc_char ]
```

    <h4>説明</h4>
    <p><code>LIKE</code> 条件に「||」文字が含まれる場合、それを論理OR演算子として使用でき、<code>sql_mode</code> によって制御されます：</p>
    <ul>
    <li><code>sql_mode</code> に <code>PIPES_AS_CONCAT</code> が含まれていない場合、<code>||</code> は論理OR演算子として認識されます。</li>
    <li><code>sql_mode</code> に <code>PIPES_AS_CONCAT</code> が含まれている場合、<code>||</code> は文字連結演算子として認識されます。</li>
    </ul>
  </main>

### パラメータの説明

|    パラメータ    |                                     説明                                     |
|----------|----------------------------------------------------------------------------|
| char1    | 文字式、例えば文字列は、検索値と呼ばれます。                                                         |
| char2    | 文字式、通常はリテラルで、パターンと呼ばれます。                                                         |
| esc_char | 文字式、通常はリテラルで、`ESCAPE` は `esc_char` をエスケープ文字として識別します。エスケープ文字がパターンマッチング文字の前に置かれると、そのパターンマッチング文字は通常の文字として解釈されます。 |

### 使用方法

`esc_char` が指定されていない場合、デフォルトのエスケープ文字はありません。`char1`、`char2`、または `esc_char` のいずれかが NULL の場合、結果は不明です。それ以外の場合、エスケープ文字（指定されている場合）は長さ1の文字列でなければなりません。

すべての文字式（`char1`、`char2`、`esc_char`）は、`CHAR`、`VARCHAR2`、`NCHAR`、または `NVARCHAR2` など、任意のデータ型を取ることができます。データ型が異なる場合、OceanBaseデータベースはそれらをすべて `char1` のデータ型に変換します。

パターンには、以下の特殊なパターンマッチング文字を含めることができます：

* アンダースコア (_) は、値の1文字（マルチバイト文字セットの1バイトではない）に完全に一致することを示します。

* パーセント記号 (%) は、値の0文字以上の任意の文字列に一致することを示します（マルチバイト文字セットの1バイトとは対照的です）。パターン「%」はNULLに一致しません。

* `LIKE` がワイルドカードを検出しない場合、`=` に変換できます。例えば、`SELECT * FROM t1 WHERE c1 LIKE 'ABC';` は、「filter("c1"='abc')”と等価です。

`ESCAPE` 句を使用して、パターン内に実際の文字 `%` または `_` を含めることができます。エスケープ文字がパターン内の文字 `%` または `_` の前にある場合、OceanBaseデータベースはその文字を特殊なパターンマッチング文字として解釈するのではなく、パターンの文字通りの意味で解釈します。また、エスケープ文字自体も検索できます。例えば、`@` がエスケープ文字である場合、`@@` を使用して `@` を検索できます。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>ASCIIに等価なアンダースコア (_) とパーセント記号 (%) のみがパターンマッチング文字として認識されます。これらの東アジア文字セットおよびUnicodeにおける全角バリアントは通常の文字と見なされます。</p>
  </main>

以下の例では、`x` \[不\] がパターン `y` に一致する場合、`TRUE` となります。`y` では、文字 `%` は0文字以上の任意の文字列に一致しますが、NULLは除きます。文字 `_` は任意の1文字に一致します。パーセント記号 (%) とアンダースコア (_) 以外の任意の文字を `ESCAPE` の後に続けることができます。前方にエスケープ文字がある場合、ワイルドカードはリテラルとして扱われます。

```sql
x [NOT] LIKE y [ESCAPE 'z']
```

### 例

以下のステートメントでは `LIKE` 条件が使用されています。`ESCAPE '\'` は、`%A\_B%` 内の `\` の後のパターンマッチング文字 '_' を通常の文字として解釈します。

```sql
SELECT last_name FROM emp WHERE last_name LIKE '%A\_B%' ESCAPE '\' ORDER BY last_name;
```

## REGEXP_LIKE 条件

`REGEXP_LIKE` は正規表現によるマッチングに使用されます。`REGEXP_LIKE` は、入力文字セットで定義された文字を使用して文字列を評価します。

### REGEXP_LIKE 条件構文

```sql
REGEXP_LIKE(source_char, pattern [, match_param ])
```

### パラメータの説明

|     パラメータ      |                                 説明                                  |
|-------------|---------------------------------------------------------------------|
| source_char | 検索値として使用される文字式で、データ型は `CHAR`、`VARCHAR2`、`NCHAR`、`NVARCHAR2`、または `CLOB` が可能です。 |
| pattern     | 正規表現で、通常はテキストリテラルです。データ型は `CHAR`、`VARCHAR2`、`NCHAR`、または `NVARCHAR2` が可能です。     |
| match_param | データ型 `VARCHAR2` または `CHAR` の文字式で、条件のデフォルトのマッチング動作を変更するために使用されます。                   |

### 使用方法

`pattern` は最大512バイトを含むことができます。`pattern` のデータ型が `source_char` のデータ型と異なる場合、OceanBaseデータベースは `pattern` を `source_char` のデータ型に変換します。

`match_parameter` には、以下のいずれか1つ以上の値を指定できます：

* `'i'` は大文字小文字を区別しないマッチングを指定します。

* `'c'` は大文字小文字を区別するマッチングを指定します。

* `'n'` は、句点 (.) が改行文字に一致することを許可します。このパラメータを省略した場合、句点は改行文字と一致しません。

* `'m'` は、ソース文字列を複数行として扱うことを意味します。OceanBaseデータベースは、`^` と `$` をソース文字列の任意の行の開始と終了と解釈し、必ずしもソース文字列全体の開始または終了に限定されません。このパラメータを省略した場合、OceanBaseデータベースはソース文字列を単一行として扱います。

* `'x'` は、空白文字を無視することを意味します。デフォルトでは、空白文字はそれ自体と一致します。

`match_parameter` に互換性のない複数の値を指定した場合、OceanBaseデータベースは最後の値を使用します。例えば、'ic' を指定した場合、OceanBaseデータベースは大文字小文字を区別するマッチングを使用します。指定した文字が上記の値に該当しない場合、エラーが返されます。

`match_parameter` を省略した場合、以下のマッチングルールに従います：

* デフォルトの大文字小文字の区別は、`NLS_SORT` システム変数の値によって決定されます。

* ピリオド (.) は改行文字と一致しません。

* ソース文字列は単一行として扱われます。

### 例

テーブル `emp` を作成し、データを挿入します。

```sql
CREATE TABLE emp(manager_id INT, first_name varchar(50), last_name varchar(50), hiredate varchar(50),SALARY INT);
INSERT INTO emp VALUES(300, 'Steven', 'King',  '2019-09-11',23600);
INSERT INTO emp VALUES(200, 'Steven', 'Markle', '2019-11-05', 23800);
INSERT INTO emp VALUES(100, 'Deven',  'Part',  '2018-10-01',24000);
INSERT INTO emp VALUES(200, 'Carlos', 'Ross',  '2019-06-11',23500);
INSERT INTO emp VALUES(200, 'Teven',  'Bell', '2019-05-25', 23000);
INSERT INTO emp VALUES(200, 'Stephen', 'Stiles',  '2018-06-11',24500);
INSERT INTO emp VALUES(100, 'Ame', 'De Haan', '2018-05-01',11000);
INSERT INTO emp VALUES(100, 'Jon', 'Errazuriz', '2017-07-21', 1400);
COMMIT;
```

クエリは、名前が `Steven` または `Stephen` で、姓が **Ste** で始まり、**en** で終わり、その間に **v** または **ph** がある従業員の名前と姓を返します。

```sql
obclient> SELECT first_name, last_name FROM emp WHERE REGEXP_LIKE (first_name, '^Ste(v|ph)en$')
ORDER BY first_name, last_name;
+------------+-----------+
| FIRST_NAME | LAST_NAME |
+------------+-----------+
| Stephen    | Stiles    |
| Steven     | King      |
| Steven     | Markle    |
+------------+-----------+
3 rows in set
```

クエリは、姓に二重母音が含まれる従業員の姓を返します（`last_name` に隣接する a、e、i、o、u が 2つ含まれている場合、大文字小文字は区別されません）。

```sql
obclient> SELECT last_name
     FROM emp
     WHERE REGEXP_LIKE (last_name, '([aeiou])\1', 'i')
     ORDER BY last_name;
+-----------+
| LAST_NAME |
+-----------+
| De Haan   |
+-----------+
1 row in set
```
