# LOCK TABLE

## 説明

このステートメントは、指定されたモードで1つまたは複数のテーブル、テーブルのパーティション、またはサブパーティションをロックします。

ロックされたテーブルは、トランザクションがコミットされるか、ロールバックされるか、またはロック前のセーブポイントまでロールバックされるまで、そのロック状態を維持します。

<main id="notice" type='explain'>
    <h4>説明</h4>
    <p>ロックするテーブルは、ユーザー自身のスキーマ内に存在している必要があります。または、ユーザーは <code>LOCK ANY TABLE</code> システム権限を持っている必要があります。</p>
</main>

## 構文

```sql
LOCK TABLE [ schema. ]table_name

  [ partition_extension_clause]
    [, [ schema. ] table_name
      [ partition_extension_clause ]
     ]...
  IN lock_mode MODE
  [ NOWAIT
   | WAIT integer
  ]

partition_extension_clause:

    PARTITION (partition_name, ...)
  | SUBPARTITION (subpartition_name, ...)

```

## 構文の説明

| **項目** | **説明** |
| --- | --- |
| table_name  | ロックするテーブル名を指定します。 |
| partition_name | ロックするパーティション名を指定します。 |
| subpartition_name | ロックするサブパーティション名を指定します。|
| lock_mode | ロックモードを指定します。OceanBaseデータベースの現在のバージョンでサポートされているロックモードは以下のとおりです：<ul><li>`ROW SHARE`：ロックされたテーブルへの並行アクセスを許可しますが、ユーザーがテーブル全体をロックして排他的にアクセスすることは禁止します。</li><li> `ROW EXCLUSIVE` ：`ROW SHARE` と同じですが、`SHARE` モードでのテーブルロックも禁止します。更新、挿入、削除を実行する際には、自動的に `ROW EXCLUSIVE` ロックが取得されます。</li><li> `SHARE`：並行クエリを許可しますが、ロックされたテーブルの更新を禁止します。 </li><li>  `SHARE ROW EXCLUSIVE`：テーブル全体の参照を許可し、他のユーザーがテーブル内の行を参照することも許可しますが、他のユーザーが `SHARE` モードでテーブルをロックしたり、行を更新したりすることは禁止します。</li><li> `EXCLUSIVE`：ロックされたテーブルへのクエリのみを許可し、その他の操作は禁止します。</li></ul>  |
| NOWAIT | 実行対象のテーブル、パーティション、またはサブパーティションのロック時にロック競合が発生した場合、`NOWAIT` を指定すると、データベースは直ちに制御権をユーザーに返します。この場合、データベースはメッセージを返し、テーブル、パーティション、またはサブパーティションが別のユーザーによってロックされていることを通知します。 |
| WAIT | ロック競合が発生した場合、ステートメントは競合するロックが解放されるのを待機します。タイムアウトするまで待機します。タイムアウト時間は、ユーザーが設定した `integer` の時間（単位：秒）です。`integer` の値に制限はありません。 |

## 例

以下の例では、サブパーティションテーブルを作成し、そのパーティションにロックをかける操作を実行します。

1. サブパーティションテーブル `test` を作成します。ここで、`SUBPARTITION TEMPLATE` によって生成されるサブパーティション名は、パーティション名 + 's' + サブパーティションテンプレート名となります。例えば、`p0` パーティションにはサブパーティション `p0ssp0`、`p0ssp1`、`p0ssp2` が存在します。

   ```shell
   CREATE TABLE TEST(col1 INT, col2 INT)
   PARTITION BY RANGE (col1)
   SUBPARTITION BY RANGE (col2)
     SUBPARTITION TEMPLATE
       (
       SUBPARTITION sp0 VALUES LESS THAN (3),
       SUBPARTITION sp1 VALUES LESS THAN (6),
       SUBPARTITION sp2 VALUES LESS THAN (9)
       )
   (
     PARTITION p0 VALUES LESS THAN (100),
     PARTITION p1 VALUES LESS THAN (200),
     PARTITION p2 VALUES LESS THAN (300)
   );
   ```

2. テーブル全体 `test` に排他ロックをかけます。

   ```sql
   obclient> LOCK TABLE test IN EXCLUSIVE MODE;
   ```

3. テーブル `test` のパーティション `p1` に排他ロックをかけます。

   ```sql
   obclient> LOCK TABLE test PARTITION (p1) IN EXCLUSIVE MODE;
   ```

4. テーブル `test` のサブパーティション `p1ssp1` に排他ロックを取得します。

   ```sql
   obclient> LOCK TABLE test SUBPARTITION (p1ssp1) IN EXCLUSIVE MODE;
   ```

5. テーブル `test` の複数のパーティションに排他ロックを取得します。

   ```sql
   obclient> LOCK TABLE test PARTITION (p1, p2) IN EXCLUSIVE MODE;
   ```

6. テーブル `test` の複数のサブパーティションに排他ロックを取得します。

   ```sql
   obclient> LOCK TABLE test SUBPARTITION (p0ssp1, p1ssp2) IN EXCLUSIVE MODE;
   ```

7. テーブル `test` の複数のパーティションとサブパーティションに排他ロックを取得します。

   ```sql
   obclient> LOCK TABLE test PARTITION (p1, p2), test SUBPARTITION (p0ssp0, p0ssp1) IN EXCLUSIVE MODE;
   ```

8. テーブル `test` に存在しないパーティションに排他ロックを取得します。以下の例では、パーティション `p3` は存在しませんが、パーティション `p0` でもロックは取得できず、ステートメント全体がロールバックされます。

   ```sql
   obclient> LOCK TABLE test PARTITION (p0, p3) IN EXCLUSIVE MODE;
   OBE-02149: Specified partition does not exist
   ```

9. 2つのクライアントでそれぞれテーブル `test` に対するロックを取得します。ロックを保持しているクライアントは排他ロックを、ロックを要求するクライアントは共有ロックを取得します。
   `LOCK TABLE` ステートメントで `WAIT N`/`NOWAIT` キーワードが設定されていない場合、そのタイムアウト時間はステートメントのタイムアウト時間とトランザクションのタイムアウト時間の最小値に依存します。この例では、1秒後にロック競合のエラーが報告されます。

   ```sql
   # conn1
   obclient> START TRANSACTION;
   obclient> LOCK TABLE test IN EXCLUSIVE MODE;

   # conn2
   obclient> START TRANSACTION;
   obclient> SET ob_trx_timeout = 10000000000; # 10000 秒
   obclient> SET ob_query_timeout = 1000000;   # 1 秒

   # ロックを要求するクライアントは1秒後にロック競合のエラーを報告します
   obclient> LOCK TABLE test IN SHARE MODE;
   OBE-30006: resource busy; acquire with WAIT timeout expired
   ```

10. 2つのクライアントでそれぞれテーブル `test` に対するテーブルロックを取得します。ロックを保持しているクライアントは排他ロックを、ロックを要求するクライアントは共有ロックを取得し、`NOWAIT` キーワードを使用します。
    `LOCK TABLE` ステートメントで `NOWAIT` キーワードが設定されている場合、テーブルロックの競合が発生すると、即座にエラーが報告され、「NOWAIT」というメッセージがエラーメッセージに表示されます。このエラーメッセージは、ステートメントで `WAIT N`/`NOWAIT` キーワードが設定されていない場合とは異なります。

    ```shell
    # conn1
    obclient> START TRANSACTION;
    obclient> LOCK TABLE test IN EXCLUSIVE MODE;

    # conn2
    obclient> START TRANSACTION;
    obclient> LOCK TABLE test IN SHARE MODE NOWAIT;
    OBE-00054: resource busy and acquire with NOWAIT specified or timeout expired
    ```

11. 2つのクライアントでそれぞれテーブル `test` に対するテーブルロックを取得します。ロックを保持しているクライアントは排他ロックを、ロックを要求するクライアントは共有ロックを取得し、`WAIT N` キーワードを使用します。
    `LOCK TABLE` ステートメントで `WAIT N` キーワードが設定されている場合、テーブルロックの競合が発生すると、N秒待機します。N秒後にロックが解除されない場合、エラーが報告され、「timeout expired」というメッセージがエラーメッセージに表示されます。このエラーメッセージは、ステートメントで `WAIT N`/`NOWAIT` キーワードが設定されていない場合とは異なります。

    ```shell
    # conn1
    obclient> START TRANSACTION;
    obclient> LOCK TABLE test IN EXCLUSIVE MODE;

    # conn2
    obclient> START TRANSACTION;

    # クライアントは1秒後にロック競合のエラーを返します
    obclient> LOCK TABLE test IN SHARE MODE WAIT 1;
    OBE-00054: resource busy and acquire with NOWAIT specified or timeout expired
    ```
