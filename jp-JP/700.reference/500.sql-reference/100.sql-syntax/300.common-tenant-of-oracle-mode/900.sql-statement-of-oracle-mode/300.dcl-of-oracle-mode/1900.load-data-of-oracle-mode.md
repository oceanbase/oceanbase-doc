# LOAD DATA

## 概要

このステートメントは、外部からデータをインポートするために使用されます。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p><ul><li>トリガー(Trigger)を持つテーブルでは、<code>LOAD DATA</code> ステートメントを使用することはできません。</li><li>外部ファイルからデータをインポートするには、<code>FILE</code> 権限と以下の設定が必要です：<ul><li>サーバー側のファイルをロードする場合、システム変数<a href="../../../../../800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/11500.secure_file_priv-global.md">secure_file_priv</a>を事前に設定し、インポートまたはエクスポートファイルにアクセスできるパスを設定する必要があります。</li><li>クライアント側のローカルファイルをロードする場合、MySQL/OBClientクライアントを起動時に<code>--local-infile[=1]</code>オプションを追加して、ローカルファイルシステムからのデータロード機能を有効にする必要があります。</li></ul></li></ul></p>
</main>

OceanBaseデータベースの`LOAD DATA`ステートメントは、次の入力ファイルをロードできます：

* サーバー側(OBServerノード)のファイル：ファイルはOceanBaseデータベースのOBServerノード上にあります。`LOAD DATA INFILE`ステートメントを使用して、サーバー側のファイルからデータをデータベーステーブルにロードできます。

* クライアント(ローカル)のファイル：ファイルはクライアントのローカルファイルシステムにあります。`LOAD DATA LOCAL INFILE`ステートメントを使用して、クライアントのローカルファイルからデータをデータベーステーブルにロードできます。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>OceanBaseデータベースのOracleモードは、バージョンV4.2.2以降で、<code>LOAD DATA LOCAL INFILE</code>構文を使用してローカルデータファイルをロードすることをサポートしています。</p>
  </main>

* OSSファイル：ファイルはOSSファイルシステムにあります。`LOAD DATA REMOTE_OSS INFILE`ステートメントを使用して、OSSファイルからデータをデータベーステーブルにロードできます。

`LOAD DATA`現在、CSV形式のテキストファイルのインポートに対応しており、全体的なインポートプロセスは以下の手順に分けることができます：

1. ファイルの解析：OceanBaseデータベースは、ユーザーが指定したファイル名に基づいてファイル内のデータを読み取り、指定された並列度に基づいて入力ファイル内のデータを並列またはシリアル処理します。

2. データの配布：OceanBaseは分散データベースであり、各パーティションのデータは異なるOBServerノードに分散されている可能性があるため、`LOAD DATA`は解析されたデータを計算し、データをどのOBServerノードに送信する必要があるかを決定します。

3. データの挿入：ターゲットOBServerノードがデータを受け取ると、そのノード上で`INSERT`操作を実行して、データを対応するパーティションに挿入します。

外部ファイルからデータをインポートするには、`FILE`権限が必要です。`GRANT FILE ON *.* TO $user_name;`ステートメントを使用して権限付与できます。ここで、`$user_name`は`LOAD DATA`コマンドを実行するユーザーです。

## 構文

```sql
LOAD DATA
    [ [/*+ PARALLEL(N) load_batch_size(M) APPEND */]
      | [/*+ PARALLEL(N) direct(bool, int) */] ]
    [REMOTE_OSS | LOCAL] INFILE 'file_name'
    INTO TABLE table_name
    [{FIELDS | COLUMNS}
        [TERMINATED BY 'string']
        [[OPTIONALLY] ENCLOSED BY 'char']
        [ESCAPED BY 'char']
    ]
    [LINES
        [STARTING BY 'string']
        [TERMINATED BY 'string']
    ]
    [IGNORE number {LINES | ROWS}]
    [(column_name_var
        [, column_name_var] ...)]
```

## パラメータの説明

|                パラメータ               |        説明                     |
|----------------------------------|---------------------------------|
| parallel(N)                      | データの読み込み並列度。`N` のデフォルト値は `4` です。    |
| load_batch_size(M)               | 一度に挿入するバッチサイズを指定します。`M` のデフォルト値は `100` です。推奨値の範囲は \[100,1000\] です。  |
| APPEND | ヒントを使用してダイレクトロード機能を有効にします。つまり、データファイル内に直接領域を割り当ててデータを書き込むことがサポートされます。`APPEND` ヒントはデフォルトで `direct(true, 0)` と同じ動作になります。同時に、オンライン統計情報収集(`GATHER_OPTIMIZER_STATISTICS` ヒント)の機能も実現できます。   |
| direct | ヒントを使用してダイレクトロードを有効にします。`direct(bool, int)` の `bool` パラメータは、指定されたCSVファイルがソートが必要かどうかを示します。`true` はソートが必要を意味します。`int` は許容される最大エラー行数を示します。 |
| REMOTE_OSS \| LOCAL | オプションです。<ul><li> <code>REMOTE_OSS</code> は、OSSファイルシステムからデータを読み込むかどうかを指定するために使用されます。<main id="notice" type='notice'><h4>注意</h4><p>このパラメータを使用する場合、<code>file_name</code> はOSSアドレスでなければなりません。</p></main>  </li><li> <code>LOCAL</code> は、クライアントのローカルファイルシステムからデータを読み込むかどうかを指定するために使用されます。`LOCAL` パラメータを使用しない場合、データはサーバー側(OBServerノード)のファイルシステムから読み込まれます。</li></ul> |
| file_name                        | 入力ファイルのパスとファイル名を指定します。<code>file_name</code> には以下の形式があります：<ul><li>インポートファイルがOBServerノードまたはクライアント上にある場合：<code>/\$PATH/\$FILENAME</code>。</li><li>インポートファイルがOSS上にある場合：<code>oss://\$PATH/\$FILENAME/?host=\$HOST&access_id=\$ACCESS_ID&access_key=\$ACCESSKEY</code>。</li></ul>     パラメータの説明は以下のとおりです：<ul><li><code>\$PATH</code>：バケット内のファイルパスを指定し、ファイルが存在するディレクトリを示します。</li><li><code>\$FILENAME</code>：ファイル名を指定し、アクセス対象の具体的なファイルを示します。</li><li><code>\$HOST</code>：OSSサービスのホスト名またはCDN加速ドメインを指定し、アクセス対象のOSSサービスのアドレスを示します。</li><li><code>\$ACCESS_ID</code>：OSSサービスへのアクセスに必要なAccess Key IDを指定し、認証に使用されます。</li><li><code>\$ACCESSKEY</code>：OSSサービスへのアクセスに必要なAccess Key Secretを指定し、認証に使用されます。</li></ul>    <main id="notice" type='explain'> <h4>説明</h4> <p>OSS上のファイルをインポートする際には、以下の情報を確認してください：<ul><li>OSSバケットおよびファイルへのアクセス権限を確保してください。指定されたバケットとファイルを読み取るための十分な権限が必要です。これは通常、OSSコンソールまたはOSS APIを通じてアクセス権限を設定し、アクセスキー(Access Key IDとAccess Key Secret)を適切な権限を持つ資格情報を設定することによって実現されます。</li><li>データベースサーバーがネットワーク経由で指定された <code>$HOST</code> アドレスに接続できるようにしてください。OSSサービスにアクセスするために。CDN加速ドメインを使用している場合は、CDN設定が正しいことと、ネットワーク接続が正常であることを確認してください。</li></ul></p> </main> |
| table_name                       | インポートデータのテーブル名。パーティションテーブルと非パーティションテーブルをサポートしています。  |
| FIELDS \| COLUMNS                | フィールドの形式を指定します。 <ul><li> `ENCLOSED BY`：エクスポート値の修飾子を設定します。  </li> <li> `TERMINATED BY`：エクスポート列の終了文字を設定します。 </li> <li>`ESCAPED BY`：エクスポート値が無視する文字を設定します。</li></ul>   |
| LINES STARTING BY                | 行の開始文字を指定します。   |
| LINES TERMINATED BY              | 行の終了文字を指定します。 |
| IGNORE number { LINES \| ROWS } | 最初の何行かを無視します。`LINES` はファイルの最初のいくつかの行、`ROWS` はフィールド区切り記号で指定される最初のいくつかのデータ行を指します。デフォルトでは、入力ファイル内のフィールドをテーブルの列と1対1で対応付けます。入力ファイルにすべての列が含まれていない場合、不足している列は以下の規則に従ってデフォルトで補完されます： <ul><li> 文字列タイプ：空文字列。   </li> <li> 数値タイプ：0。    </li> <li> 日付タイプ：`0000-00-00`。</li></ul>    |
| column_name_var                  | インポートする列名を指定します。   |

## 例

### 例1：サーバーサイド（OBServerノード）のファイルからデータをインポートする

1. グローバルセキュリティパスを設定します。

   <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>セキュリティ上の理由により、システム変数 <code>secure_file_priv</code> を設定する際は、ローカルSocket経由でのみデータベースに接続し、このグローバル変数を変更するSQLステートメントを実行できます。詳細については、<a href="../../../../../800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/11500.secure_file_priv-global.md">secure_file_priv</a>を参照してください。</p>
   </main>

   ```shell
   obclient> SET GLOBAL secure_file_priv = "/";
   ```

2. ログアウトします。

   <main id="notice" type='explain'>
     <h4>説明</h4>
     <p><code>secure_file_priv</code> は <code>GLOBAL</code> 変数であるため、<code>\q</code> を実行してログアウトすることで有効になります。</p>
   </main>

   ```shell
   obclinet> \q
   ```

   実行結果は次のとおりです：

   ```shell
   Bye
   ```

3. 再接続した後、`LOAD DATA` ステートメントを使用してデータをインポートします。

   * 標準的なインポート。

      ```shell
      obclient> LOAD DATA INFILE '/home/admin/test.csv' INTO TABLE t1;
      ```

   * `APPEND` Hintを使用してダイレクトロードを有効化します。

      ```shell
      LOAD DATA /*+ PARALLEL(4) APPEND */ INFILE '/home/admin/test.csv' INTO TABLE t1;
      ```

### 例2：OSSファイルからデータをインポートする

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>オブジェクトストレージパスを使用する場合、オブジェクトストレージパスの各パラメータは <code>&</code> 記号で区切られます。入力されたパラメータ値には大文字と小文字の英字、数字、<code>\/-_$+=</code> およびワイルドカードのみを含めるようにしてください。上記以外の文字を入力すると、設定が失敗する可能性があります。</p>
</main>

`direct(bool, int)` Hintを使用してダイレクトロード機能を有効にし、インポートファイルはOSS上にあります。

```shell
LOAD DATA /*+ direct(true,1024) parallel(16) */ REMOTE_OSS INFILE 'oss://antsys-oceanbasebackup/backup_rd/xiaotao.ht/lineitem2.tbl?host=***.oss-cdn.***&access_id=***&access_key=***' INTO TABLE tbl1 FIELDS TERMINATED BY ',';
```

### 例3：クライアント（ローカル）ファイルからデータをインポートする

次のステートメントを使用して、ローカルファイルからOceanBaseデータベースのテーブルにデータをインポートします。

1. ターミナルまたはコマンドプロンプトウィンドウを開き、以下のコマンドを入力してクライアントを起動します。

   ```shell
   obclient --local-infile -hxxx.xxx.xxx.xxx -P2881 -usys@oracle001 -p******
   ```

   実行結果は次のとおりです：

   ```shell
   Welcome to the OceanBase.  Commands end with ; or \g.
   Your OceanBase connection id is 3221548006
   Server version: OceanBase 4.2.2.0 (r100000032024010510-75c47d4be18a399e13c5309de1a81da5caf4e7c0) (Built Jan  5 2024 10:17:55)

   Copyright (c) 2000, 2018, OceanBase and/or its affiliates. All rights reserved.

   Type 'help;' or '\h' for help. Type '\c' to clear the current input statement.

   obclient [SYS]>
   ```

    <main id="notice" type='notice'>
      <h4>注意</h4>
      <p><code>LOAD DATA LOCAL INFILE</code>機能を使用するには、V2.2.4以降のバージョンのOBClientクライアントを使用してください。</p>
    </main>

2. クライアントで、`LOAD DATA LOCAL INFILE` ステートメントを実行して、ローカルデータファイルを読み込みます。

   ```shell
   obclient [SYS]> LOAD DATA LOCAL INFILE '/home/admin/test_data/tbl1.csv' INTO TABLE tbl1 FIELDS TERMINATED BY ',';
   ```

   実行結果は次のとおりです：

   ```shell

   Records: 3  Deleted: 0  Skipped: 0  Warnings: 0
   ```
