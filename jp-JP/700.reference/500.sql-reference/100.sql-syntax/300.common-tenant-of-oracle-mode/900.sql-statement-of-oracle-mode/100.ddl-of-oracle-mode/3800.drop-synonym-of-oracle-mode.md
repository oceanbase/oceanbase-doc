# DROP SYNONYM

## 説明

このステートメントは、シノニムを削除するために使用されます。

## 構文

```sql
DROP [PUBLIC] SYNONYM [ schema. ]synonym_name [FORCE];
```

## パラメータの説明

|      パラメータ      |                                        説明                                         |
|--------------|-----------------------------------------------------------------------------------|
| PUBLIC       | `PUBLIC` を指定して、パブリックシノニムを削除します。`PUBLIC` を指定しない場合は、プライベートシノニムが削除されます。                                     |
| schema       | シノニムが存在するスキーマを指定します。`schema.` を省略した場合、デフォルトではシノニムは自身のモードにあります。`PUBLIC` を指定した場合、シノニムに対して `schema` を指定する必要はありません。 |
| synonym_name | `synonym_name` はシノニムの名前を表します。                                                          |
| FORCE        | `FORCE` を指定すると、依存関係のあるテーブルやユーザー定義型を持つシノニムを削除できます。                                                   |

## 例

* プライベートシノニムを削除します。

  ```sql
  obclient> DROP SYNONYM user1.syn1;
  Query OK, 0 rows affected
  ```

* `PUBLIC` シノニムを削除します。

  ```sql
  obclient> DROP PUBLIC SYNONYM syn2;
  Query OK, 0 rows affected
  ```

## 注意事項

シノニムを削除するには、以下の権限が必要です：

* プライベートシノニムを削除する場合：

  * 削除する `synonym` は対応するスキーマ内に存在している必要があります。

  * `DROP ANY SYNONYM` 権限が付与されている必要があります。

* パブリックシノニムを削除する場合：

  * `PUBLIC` キーワードを指定し、`schema` を指定してはなりません。

  * `DROP PUBLIC SYNONYM` 権限が付与されている必要があります。
