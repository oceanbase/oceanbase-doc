# CREATE OUTLINE

## 説明

このステートメントは、アウトラインを作成するために使用します。アウトラインの作成方法は2通りあります。1つは `SQL_TEXT`（ユーザーが実行したパラメータ付きの元のステートメント）を使用する方法で、もう1つは `SQL_ID` を使用して作成する方法です。

## 使用上の制限と注意事項

## 注意事項

* `SQL_ID` が同じ場合、`SQL_TEXT` 方式で作成されたアウトラインは、`SQL_ID` 方式で作成されたアウトラインを上書きします。`SQL_TEXT` 方式の優先順位が高いです。また、OceanBaseデータベースは `SQL_ID` で異なるSQLを区別しますが、`SQL_ID` は `SQL_TEXT` をパラメータ化した後に `MD5` ハッシュを適用して得られるものです。同じSQLテキストでも改行やタブが1文字でも違うと、`MD5` によって得られる `SQL_ID` は異なります。実際の本番システムでは、`SQL_ID` を使用したアウトラインのバインドを推奨します。
* V4.4.2 BP3 より前のバージョンでアウトラインを作成する場合は、対応するユーザーとして実行する必要があります。
* V4.4.2 BP3 以降のバージョンでは、データベースレベルおよびテナントレベルのアウトラインの指定をサポートしています。
* `MAP` に `db.table` 形式が含まれる場合は、`SCOPE = TENANT` を明示的に指定する必要があります。そうでない場合、作成時にエラーが発生します。
* 同一の `BINDING_RULE` 内で、各データベース名 `pattern` とテーブル名 `pattern` に対して、各1つの変数しか使用できません。複雑な式は、複数のアウトラインに分割してください。
* 変数は定義してから参照する必要があります。同名の変数の定義は1回しか行えません。
* `db.*` はサポートされていません。`'db_${D:[0-9]+}'.'${T:.*}'` などの等価表現を使用してください。
* 正規表現はPOSIX拡張構文を採用しており、逆参照やゼロ幅アサーションなどの複雑な機能はサポートされていません。
* `SCOPE = DATABASE` かつ `MAP` を指定しないアウトラインのみ、従来の動作をそのまま維持します。これは従来の完全一致アウトラインに相当します。
* `MAX_CONCURRENT` トラフィック制御型のアウトラインは、現在 `BINDING_RULE` をサポートしていません。
* テナント間のアウトラインバインドはサポートされていません。

## 構文

```sql
sql_text_stmt:
    CREATE [OR REPLACE] OUTLINE outline_name ON stmt
        [TO target_stmt
        | BINDING_RULE (binding_item)];

binding_item:
    SCOPE = {DATABASE | TENANT}
    | MAP = {real_name TO 'pattern', ...}

sql_id_stmt:
    CREATE [OR REPLACE] OUTLINE outline_name ON 'sql_id' USING HINT hint;
```

## パラメータの説明

| **パラメータ**       |  **説明**     |
|----------------|--------------------|
| sql_text_stmt  | `SQL_TEXT` を使用してアウトラインを作成するステートメントを表します。|
| sql_id_stmt    | `SQL_ID` を使用してアウトラインを作成するステートメントを表します。|
| OR REPLACE     | オプションです。`OR REPLACE` を指定すると、作成しようとするアウトラインが既に存在する場合、既存のアウトラインを置き換えます。|
| outline_name   | 作成するアウトライン名を指定します。|
| stmt           | 通常はヒントと元のパラメータを持つDMLステートメントです。|
| TO target_stmt | オプションです。`TO target_stmt` を指定しない場合、データベースが受け入れるSQLがパラメータ化された後、`stmt` から `hint` を除去してパラメータ化したテキストと同じであれば、そのSQLを `stmt` の `hint` にバインドして実行計画を生成します。`hint` を含むステートメントに対して固定計画を適用したい場合は、`TO target_stmt` で元のSQLを指定する必要があります。 <main id="notice" type='notice'><h4>注意</h4><p><code>target_stmt</code> を使用する場合、<code>stmt</code> と <code>target_stmt</code> がヒントを除去した後、完全に一致することが厳密に要求されます。</p></main>|
| BINDING_RULE (binding_item) | オプションです。このアウトラインの適用範囲を指定するために使用します。詳細については、以下の [binding_item](#binding_item) を参照してください。<main id="notice" type='explain'><h4>説明</h4><p>V4.4.x バージョンでは、V4.4.2 BP3 から <code>BINDING_RULE</code> 句が導入されました。</p></main>|
| sql_id         | `sql_id` に対応するSQLステートメントにすでにヒントがある場合、アウトラインで指定されたヒントが元のステートメント内のすべてのヒントを上書きします。  |
| hint           | アウトラインのヒントを指定します。形式は `/*+ xxx */` です。ヒント構文の詳細については、[Optimizer Hint](../../../../../1000.performance-tuning-guide/500.sql-optimization/400.sql-optimization/700.manage-execution-plans/100.optimizer-hint.md) を参照してください。|

### binding_item

* `SCOPE = {DATABASE | TENANT}`：

  * `SCOPE = DATABASE`：デフォルト値で、現在のデータベースにのみ有効です。
  * `SCOPE = TENANT`：現在のテナント内のすべてのデータベースに有効です。

* `MAP = {real_name TO 'pattern', ...}`：左側の実際のテーブル名/`db.table` に右側の `pattern` を適用します。`pattern` には `${変数名}` または `${変数名:正規表現}` を記述できます。

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <ul>
      <li><code>MAP</code> の左側が <code>db.table</code> 形式の場合、右側の <code>pattern</code> は、データベース名とテーブル名のパターンをそれぞれ単一引用符で囲み、ドットで区切る必要があります：<code>'db_pattern'.'table_pattern'</code>。</li>
      <li>同一の <code>BINDING_RULE</code> 内では、変数は定義後に参照する必要があります。同名の変数は、すべての参照箇所で値が一致している必要があります。</li>
    </ul>
  </main>

## 例

1. テストテーブル `employees` を作成します。

    ```shell
    obclient> CREATE TABLE employees (
       emp_id INT,
       dept_id INT,
       salary INT,
       emp_name VARCHAR(50));
   ```

2. テーブル `employees` にデータを挿入します。

    ```shell
    obclient> INSERT INTO employees VALUES
       (1001, 10, 10000, 'John'),
       (1002, 10, 12000, 'Mike'),
       (1003, 20, 15000, 'Sarah');
    ```

3. テーブル `employees` の `dept_id` 列にインデックス `idx_dept_id` を作成します。

    ```shell
    obclient> CREATE INDEX idx_dept_id ON employees(dept_id);
    ```

4. `SQL_TEXT` を使用して `outline1` を作成します。

    ```shell
    obclient> CREATE OUTLINE outline1
        ON SELECT/*+ index(employees idx_dept_id)*/ * FROM employees WHERE dept_id = 10;
    ```

5. `SQL_ID` を使用して `outline2` を作成します。

    1. まず、アウトラインをバインドするSQLの `SQL_ID` を確認します。

        ```shell
        obclient> SELECT sql_id, trace_id, client_ip, user_name, query_sql
           FROM sys.V$OB_SQL_AUDIT
           WHERE query_sql LIKE '%employees%';
        ```

    2. 調べた `SQL_ID` を使用してアウトラインを作成します。

        ```shell
        obclient> CREATE OUTLINE outline2
            ON '549D27D6DD54688A9B25FD82D5650B96'
            USING HINT /*+ index(employees idx_dept_id)*/;
        ```
