# CREATE OUTLINE

## 説明

このステートメントは、アウトラインを作成するために使用します。アウトラインの作成方法は2通りあります。1つは `SQL_TEXT`（ユーザーが実行したパラメータ付きの元のステートメント）を使用する方法で、もう1つは `SQL_ID` を使用して作成する方法です。

## 使用上の制限と注意事項

## 注意事項

* `SQL_ID` が同じ場合、`SQL_TEXT` 方式で作成されたアウトラインは `SQL_ID` 方式で作成されたアウトラインを上書きします。`SQL_TEXT` 方式で作成されたものの方が優先順位が高くなります。また、OceanBaseデータベースは `SQL_ID` によって異なるSQLを区別します。`SQL_ID` は `SQL_TEXT` をパラメータ化した後、`MD5` アルゴリズムでハッシュ値を求めることで得られます。同じSQLテキストでも、改行やタブ文字が1つ増えただけで、得られる `SQL_ID` は異なります。本番システムでは、`SQL_ID` を用いたアウトラインのバインドを推奨します。
* V4.4.2 BP3より前のバージョンでは、アウトラインを作成するには、対応するユーザーとしてログインして実行する必要があります。
* V4.4.2 BP3以降では、データベースレベルおよびテナントレベルのアウトラインを指定できます。
* `MAP` に `db.table` 形式が含まれる場合は、`SCOPE = TENANT` を明示的に指定する必要があります。指定しない場合、作成時にエラーが発生します。
* 同一の `BINDING_RULE` 内では、各データベース名の `pattern` と各テーブル名の `pattern` に含められる変数は、それぞれ最大1つです。複雑な式は複数のアウトラインに分割してください。
* 変数は参照する前に定義する必要があります。同名の変数を複数回定義することはできません。
* `db.*` はサポートされていません。代わりに、同等の式 `'db_${D:[0-9]+}'.'${T:.*}'` を使用してください。
* 正規表現にはPOSIX拡張構文を使用します。後方参照やゼロ幅アサーションなどの複雑な機能はサポートされていません。
* `SCOPE = DATABASE` で、かつ `MAP` がないアウトラインのみ、動作が従来と完全に同じです。これは従来の完全一致によるアウトラインに相当します。
* `MAX_CONCURRENT` による流量制限を行うアウトラインでは、現在 `BINDING_RULE` はサポートされていません。
* テナントをまたぐアウトラインのバインドはサポートされていません。

## 構文

```sql
sql_text_stmt:
    CREATE [OR REPLACE] OUTLINE outline_name ON stmt
        [TO target_stmt
        | BINDING_RULE (binding_item)];

binding_item:
    SCOPE = {DATABASE | TENANT}
    | MAP = {real_name TO 'pattern', ...}

sql_id_stmt:
    CREATE [OR REPLACE] OUTLINE outline_name ON 'sql_id' USING HINT hint;
```

## パラメータの説明

| **パラメータ**       |  **説明**     |
|----------------|--------------------|
| sql_text_stmt  | `SQL_TEXT` を使用してアウトラインを作成するステートメントを表します。|
| sql_id_stmt    | `SQL_ID` を使用してアウトラインを作成するステートメントを表します。|
| OR REPLACE     | オプションです。`OR REPLACE` を指定すると、作成しようとするアウトラインが既に存在する場合、既存のアウトラインを置き換えます。|
| outline_name   | 作成するアウトライン名を指定します。|
| stmt           | 通常はヒントと元のパラメータを持つDMLステートメントです。|
| TO target_stmt | オプションです。`TO target_stmt` を指定しない場合、データベースが受け取ったSQLをパラメータ化した結果が、`stmt` からヒントを除去してパラメータ化したテキストと一致する場合、そのSQLに `stmt` のヒントをバインドして実行計画を生成します。`hint` を含むステートメントに対して固定計画を適用したい場合は、元のSQLを指定するために `TO target_stmt` が必要です。 <main id="notice" type='notice'><h4>注意</h4><p><code>target_stmt</code> を使用する場合、<code>stmt</code> と <code>target_stmt</code> は、ヒントを除去した後で完全に一致する必要があります。</p></main>|
| BINDING_RULE (binding_item) | オプションです。アウトラインが有効になる範囲を指定します。詳細については、後述の [binding_item](#binding_item) を参照してください。<main id="notice" type='explain'><h4>説明</h4><p>V4.4.x系では、V4.4.2 BP3以降で <code>BINDING_RULE</code> 句が導入されています。</p></main>|
| sql_id         | `sql_id` が対応するSQLステートメントに既にヒントがある場合、アウトラインで指定されたヒントが元のステートメント内のすべてのヒントを上書きします。  |
| hint           | アウトラインのヒントを指定します。形式は `/*+ xxx */` です。ヒント構文の詳細については、[Optimizer Hint](../../../../../1000.performance-tuning-guide/500.sql-optimization/400.sql-optimization/700.manage-execution-plans/100.optimizer-hint.md)を参照してください。|

### binding_item

* `SCOPE = {DATABASE | TENANT}`：

  * `SCOPE = DATABASE`：デフォルト値です。現在のデータベースでのみ有効になります。
  * `SCOPE = TENANT`：現在のテナント内のすべてのデータベースで有効になります。

* `MAP = {real_name TO 'pattern', ...}`：左側の実際のテーブル名または `db.table` に、右側の `pattern` を適用します。`pattern` には `${変数名}` または `${変数名:正規表現}` を記述できます。

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p><ul>
      <li><code>MAP</code> の左側が <code>db.table</code> 形式の場合、右側の <code>pattern</code> は、<code>'db_pattern'.'table_pattern'</code> のように、それぞれ引用符で囲んだ2つの部分に分ける必要があります。</li>
      <li>同一の <code>BINDING_RULE</code> 内では、変数は参照する前に定義する必要があります。また、同名の変数は、参照するすべての箇所で同じ値を取る必要があります。</li>
    </ul></p>
  </main>

## 例

1. テストテーブル `employees` を作成します。

    ```shell
    obclient> CREATE TABLE employees (
       emp_id INT,
       dept_id INT,
       salary INT,
       emp_name VARCHAR(50));
   ```

2. テーブル `employees` にデータを挿入します。

    ```shell
    obclient> INSERT INTO employees VALUES
       (1001, 10, 10000, 'John'),
       (1002, 10, 12000, 'Mike'),
       (1003, 20, 15000, 'Sarah');
    ```

3. テーブル `employees` の `dept_id` 列にインデックス `idx_dept_id` を作成します。

    ```shell
    obclient> CREATE INDEX idx_dept_id ON employees(dept_id);
    ```

4. `SQL_TEXT` を使用して `outline1` を作成します。

    ```shell
    obclient> CREATE OUTLINE outline1
        ON SELECT/*+ index(employees idx_dept_id)*/ * FROM employees WHERE dept_id = 10;
    ```

5. `SQL_ID` を使用して `outline2` を作成します。

    1. まず、アウトラインをバインドするSQLの `SQL_ID` を確認します。

        ```shell
        obclient> SELECT sql_id, trace_id, client_ip, user_name, query_sql
           FROM sys.V$OB_SQL_AUDIT
           WHERE query_sql LIKE '%employees%';
        ```

    2. 調べた `SQL_ID` を使用してアウトラインを作成します。

        ```shell
        obclient> CREATE OUTLINE outline2
            ON '549D27D6DD54688A9B25FD82D5650B96'
            USING HINT /*+ index(employees idx_dept_id)*/;
        ```
