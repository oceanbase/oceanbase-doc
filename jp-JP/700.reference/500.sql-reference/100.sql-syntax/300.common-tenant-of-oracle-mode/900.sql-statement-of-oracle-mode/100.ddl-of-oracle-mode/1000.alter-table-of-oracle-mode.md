# ALTER TABLE

## 概要

このステートメントは、既存のテーブルの構造を変更するために使用され、テーブルおよびテーブルプロパティの変更、列の追加、列およびプロパティの変更、列の削除などが含まれます。

## 構文

```sql
ALTER TABLE table_name  alter_table_action_list;

alter_table_action_list:
    alter_table_action [, alter_table_action ...]

alter_table_action:
      ADD {column_definition | (column_definition_list)}
    | ADD [CONSTRAINT [constraint_name]] UNIQUE (column_name [, column_name ]...)
    | ADD [CONSTRAINT [constraint_name]] FOREIGN KEY (column_name_list) references_clause
    | ADD [CONSTRAINT [constraint_name]] CHECK (expr)
    | ADD CONSTRAINT constraint_name PRIMARY KEY (column_name)
    | ADD CONSTRAINT constraint_name FOREIGN KEY(foreign_col_name) REFERENCES
        reference_tbl_name(column_name);
    | ALTER INDEX index_name [VISIBLE | INVISIBLE]

    | ADD range_partition_list
    | DROP {PARTITION | SUBPARTITION} partition_name_list [UPDATE GLOBAL INDEXES]
    | DROP TABLEGROUP
    | DROP CONSTRAINT constraint_name
    | DROP PRIMARY KEY
    | DROP COLUMN column_name
    | {ENABLE | DISABLE} CONSTRAINT constraint_name
    | MODIFY [COLUMN] column_definition
    | MODIFY CONSTRAINT constraint_name { ENABLE | DISABLE }
    | MODIFY PRIMARY KEY (column_name_list)
    | RENAME [TO] table_name
    | RENAME COLUMN old_col_name TO new_col_name
    | RENAME { PARTITION | SUBPARITION } partition_name TO new_name
    | SET TABLEGROUP tablegroup_name
    | [SET] table_option_list
    | TRUNCATE {PARTITION | SUBPARTITION} partition_name_list [UPDATE GLOBAL INDEXES]
    | MODIFY PARTITION partition_name ADD add_subpartition_list
    | DUPLICATE_SCOPE= 'none | cluster'
    | FORCE

rename_table_action_list:
    rename_table_action [, rename_table_action ...]

rename_table_action:
    table_name TO table_name

column_definition_list:
    column_definition [, column_definition ...]

column_definition:
    column_name data_type
    [GENERATED BY DEFAULT AS IDENTITY | GENERATED ALWAYS AS IDENTITY]
    [DEFAULT const_value]
    [NULL | NOT NULL] [[PRIMARY] KEY] [UNIQUE [KEY]] comment

column_desc_list:
    column_desc [, column_desc ...]

column_desc:
     column_name [(length)] [ASC | DESC]

references_clause:
     REFERENCES table_name [ (column_name, column_name ...) ] [ON DELETE {SET NULL | CASCADE}]

index_option:
      [GLOBAL | LOCAL]
    | block_size
    | compression
    | STORING(column_name_list)
    | comment

table_option_list:
    table_option [ table_option ...]

table_option:
      table_group
    | block_size
    | compression
    | comment
    | parallel_clause
    | TABLE_MODE [=] 'table_mode_value'

parallel_clause:
    {NOPARALLEL | PARALLEL integer}

table_mode_value:
    NORMAL
    | QUEUING
    | MODERATE
    | SUPER
    | EXTREME

add_subpartition_list:
    {SUBPARTITION subpartition_name VALUES LESS THAN range_partition_expr, ...}
    | {SUBPARTITION subpartition_name VALUES list_partition_expr, ...}

partition_option:
      PARTITION BY HASH(column_name_list)
      [subpartition_option] hash_partition_define
    | PARTITION BY RANGE (column_name_list)
      [subpartition_option] (range_partition_list)
    | PARTITION BY LIST (column_name_list)
      [subpartition_option] (list_partition_list)

/*テンプレート化されたサブパーティション*/
subpartition_option:
      SUBPARTITION BY HASH (column_name_list) hash_subpartition_define
    | SUBPARTITION BY RANGE (column_name_list) SUBPARTITION TEMPLATE
      (range_subpartition_list)
    | SUBPARTITION BY LIST (column_name_list) SUBPARTITION TEMPLATE
      (list_subpartition_list)

/*テンプレート化されていないサブパーティション*/
subpartition_option:
      SUBPARTITION BY HASH (column_name_list)
    | SUBPARTITION BY RANGE (column_name_list)
    | SUBPARTITION BY LIST (column_name_list)

subpartition_list:
      (hash_subpartition_list)
    | (range_subpartition_list)
    | (list_subpartition_list)

hash_partition_define:
      PARTITIONS partition_count [TABLESPACE tablespace] [compression]
    | (hash_partition_list)

hash_partition_list:
    hash_partition [, hash_partition, ...]

hash_partition:
    partition [partition_name] [subpartition_list/*テンプレート化されていないサブパーティションのみ定義可能*/]

hash_subpartition_define:
      SUBPARTITIONS subpartition_count
    | SUBPARTITION TEMPLATE (hash_subpartition_list)

hash_subpartition_list:
    hash_subpartition [, hash_subpartition, ...]

hash_subpartition:
    subpartition [subpartition_name]

range_partition_list:
    range_partition [, range_partition ...]

range_partition:
    PARTITION [partition_name]
    VALUES LESS THAN {(expression_list) | (MAXVALUE)}
    [subpartition_list/*テンプレート化されていないサブパーティションのみ定義可能*/]
    [ID = num] [physical_attribute_list] [compression]

range_subpartition_list:
    range_subpartition [, range_subpartition ...]

range_subpartition:
    SUBPARTITION subpartition_name
    VALUES LESS THAN {(expression_list) | MAXVALUE} [physical_attribute_list]

list_partition_list:
    list_partition [, list_partition] ...

list_partition:
    PARTITION [partition_name]
    VALUES (DEFAULT|expression_list)
    [subpartition_list/*テンプレート化されていないサブパーティションのみ定義可能*/]
    [ID num] [physical_attribute_list] [compression]

list_subpartition_list:
    list_subpartition [, list_subpartition] ...

list_subpartition:
    SUBPARTITION [partition_name] VALUES (DEFAULT|expression_list) [physical_attribute_list]

expression_list:
    expression [, expression ...]

column_name_list:
    column_name [, column_name ...]

partition_name_list:
    partition_name [, partition_name ...]

partition_count | subpartition_count:
    INT_VALUE
```

## 構文の説明

|                       パラメータ                       |                説明                   |
|------------------------------------------------|----------------------------------------------------------------------------------------|
| ADD                                            | 列を追加します。現在、主キー列の追加はサポートされていません。      |
| MODIFY COLUMN                             | 列プロパティを変更します。     |
| MODIFY CONSTRAINT                              | 制約の状態を有効または無効にします。外部キー制約と `CHECK` 制約のみをサポートしています。    |
| DROP PRIMARY KEY                          | 主キーを削除します。<br>**説明** Oracleモードの場合、テーブルが外部キー情報の親テーブルである場合は、主キーを削除することはできません。|
| DROP COLUMN                               | 列を削除します。主キー列の削除は許可されません。   |
| ADD UNIQUE                          | 唯一性インデックスを追加します。       |
| ADD INDEX                                  | 普通のインデックスを追加します。      |
| ALTER INDEX                              | インデックスプロパティを変更します。      |
|  FOREIGN KEY     | 外部キーを追加します。外部キー名を指定しない場合、テーブル名 + `OBFK` + 作成時刻で命名されます。(例：2021年8月1日00:00:00に`t1`テーブルに作成された外部キー名は`t1_OBFK_1627747200000000`です)。外部キーは、関連データを異なるテーブル間でクロスリファレンスできます。
| ADD PARTITION                              | パーティションを追加します。    |
| DROP {PARTITION \| SUBPARTITION}               | パーティションの削除：<ul><li> `PARTITION`：RangeまたはListタイプのパーティションに対して、指定されたパーティションを削除します(指定されたパーティションにサブパーティションが存在する場合、そのパーティション内のすべてのサブパーティションも同時に削除されます)。パーティションの定義とその中のデータを含め、パーティション上のローカルインデックスを維持します。</li>   <li> `SUBPARTITION`：\*-Rangeまたは\*-Listタイプのサブパーティションに対して、指定されたサブパーティションを削除します(パーティションの定義とその中のデータを含めます)。同時に、パーティション上のローカルインデックスを維持します。</li> </ul>   `UPDATE GLOBAL INDEXES`を指定した場合、パーティションを削除する際にグローバルインデックスも同期して更新されます。指定しない場合は、パーティションテーブル上のグローバルインデックスは非使用状態にする必要があります。複数のパーティション名はカンマで区切ります。<br>**注意** パーティションを削除する際は、そのパーティション上でアクティブなトランザクションやクエリがないようにしてください。そうでない場合、SQLステートメントがエラーを返す可能性がありますか、または一部の例外状況が発生する可能性があります。 |
| TRUNCATE {PARTITION \| SUBPARTITION}           | パーティションデータの削除：<ul><li> `PARTITION`：RangeまたはListタイプのパーティションに対して、指定されたパーティション内のすべてのデータをクリアします(指定されたパーティションにサブパーティションが存在する場合、そのパーティション内のすべてのサブパーティションのデータも同時にクリアされます)。同時に、パーティション上のローカルインデックスを維持します。</li>   <li> `SUBPARTITION`：\*-Rangeまたは\*-Listタイプのサブパーティションに対して、指定されたサブパーティション内のすべてのデータをクリアします。同時に、パーティション上のローカルインデックスを維持します。</li> </ul>   `UPDATE GLOBAL INDEXES`を指定した場合、パーティションデータをクリアする際にグローバルインデックスも同期して更新されます。指定しない場合は、パーティションテーブル上のグローバルインデックスは非使用状態にする必要があります。複数のパーティション名はカンマで区切ります。<br>**注意** パーティションデータを削除する際は、そのパーティション上でアクティブなトランザクションやクエリがないようにしてください。そうでない場合、SQLステートメントがエラーを返す可能性がありますか、または一部の例外状況が発生する可能性があります。       |
| MODIFY PARTITION partition_name ADD add_subpartition_list | サブパーティションを追加します。<main id="notice" type='notice'><h4>注意</h4><p>Hashタイプのサブパーティションを持つテーブルでは、サブパーティションの追加はサポートされません。</p></main>|
| RENAME \[TO\] table_name                       | テーブルのリネーム。  |
| RENAME { PARTITION \| SUBPARITION } partition_name TO new_name| パーティションまたはサブパーティションのリネーム。`new_name`は変更するパーティションの新しい名前を指定します(大文字と小文字は区別されません)。パーティションのリネーム操作は主テーブルの関連パーティションを変更しますが、ローカルインデックスのパーティション名には影響しません。パーティション名の変更結果を確認するには、ビュー`USER_TAB_PARTITIONS`および`USER_TAB_SUBPARTITIONS`を使用します。詳細については、[パーティションのリネーム](../../../../../300.database-object-management/200.manage-object-of-oracle-mode/200.manage-partitions-of-oracle-mode/310.rename-a-partition-of-oracle-mode.md)を参照してください。パーティションのリネーム中に、関連パーティションのロックリソースを保持しているDMLと競合すると、パーティション名の変更操作がブロックされ、DMLが関連パーティションのロックリソースを解放するまで待機します。|
| DROP TABLEGROUP                            | テーブルグループの削除。    |
| SET TABLEGROUP                                 | テーブルがどのテーブルグループに属するかを設定します。   |
| DROP CONSTRAINT                            | 制約の削除。    |
| SET BLOCK_SIZE                                 | パーティションテーブルの`BLOCK`サイズを設定します。      |
| SET COMPRESSION                                | テーブルの圧縮方式を設定します。     |
| SET USE_BLOOM_FILTER                           | BloomFilterを使用するかどうかを設定します。       |
| SET COMMENT                                    | 注釈情報を設定します。    |
| SET PROGRESSIVE_MERGE_NUM                      | 進化的なマージステップ数を設定します。値の範囲は \[0,100\] です。   |
| parallel_clause                                | テーブルレベルの並列度を指定します：<ul><li> `NOPARALLEL`：並列度は`1`で、デフォルトの設定です。</li>   <li> `PARALLEL integer`：並列度を指定します。`integer`は`1`以上である必要があります。</li></ul>  **注意**  並列度を指定した場合、優先順位は以下の通りです：ヒントによる並列度 > `ALTER SESSION`による並列度 > テーブルレベルの並列度。     |
| {ENABLE \| DISABLE} CONSTRAINT constraint_name | 制約の状態を変更します。外部キー制約または`CHECK`制約をサポートしています。         |
| MODIFY PRIMARY KEY                             | 主キーを変更します。         |
| FORCE | 不要な列を削除します。|
| TABLE_MODE | オプション。マージトリガーしきい値とマージ戦略を指定するために使用され、データダンプ後のマージ動作を制御します。値の詳細については、以下[table_mode_value](#table_mode_value)を参照してください。|
| DUPLICATE_SCOPE | コピー元テーブルのプロパティを変更します。<ul><li>`none`：現在のテーブルを通常のテーブルに変換します。</li><li>`cluster`：現在のテーブルをコピー元テーブルに変換します。</li></ul> 詳細については、[コピー元テーブルのプロパティを変更](../../../../../300.database-object-management/200.manage-object-of-oracle-mode/100.manage-tables-of-oracle-mode/650.change-duplicate-scope-of-oracle-mode.md)を参照してください。|

### table_mode_value

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>以下のリストに示されている <code>TABLE_MODE</code> モードにおいて、<code>NORMAL</code> モードを除くすべてのモードは <code>QUEUING</code> テーブルを表します。この <code>QUEUING</code> テーブルは最も基本的なテーブルタイプであり、その後に記載されるいくつかのモード（NORMAL モードを除くもの）はより積極的なマージ戦略を使用しています。</p>
</main>

* `NORMAL`：デフォルト値で、通常を表します。このモードでは、データダンプ後にマージがトリガーされる確率は非常に低いです。
* `QUEUING`：このモードでは、データダンプ後にマージがトリガーされる確率は低いです。
* `MODERATE`：適度を表します。このモードでは、データダンプ後にマージがトリガーされる確率は中程度です。
* `SUPER`：スーパーを表します。このモードでは、データダンプ後にマージがトリガーされる確率は高いです。
* `EXTREME`：極端を表します。このモードでは、ダンプ後にマージがトリガーされる確率は比較的高いです。

マージに関する詳細については、[適応的マージ](../../../../../200.system-management/500.manage-data-storage/200.merge-management/320.adaptive-compavtion.md)を参照してください。

## 例

### フィールド型の変更

* テーブル `tbl1` のフィールド `col1` のフィールド型を変更します。

  ```sql
  obclient> CREATE TABLE tbl1(col1 VARCHAR(3));
  Query OK, 0 rows affected

  obclient> ALTER TABLE tbl1 MODIFY col1 CHAR(10);
  Query OK, 0 rows affected

  obclient> DESCRIBE tbl1;
  +-------+----------+------+-----+---------+-------+
  | FIELD | TYPE     | NULL | KEY | DEFAULT | EXTRA |
  +-------+----------+------+-----+---------+-------+
  | COL1  | CHAR(10) | YES  | NULL | NULL    | NULL  |
  +-------+----------+------+-----+---------+-------+
  1 row in set
  ```

### 列のリネーム操作

* テーブル `tbl1` の列 `col1` の名前を `col2` に変更します。

  ```shell
  obclient> ALTER TABLE tbl1 RENAME COLUMN col1 TO col2;
  Query OK, 0 rows affected

  obclient> DESCRIBE tbl1;
  +-------+-------------+------+-----+---------+-------+
  | FIELD | TYPE        | NULL | KEY | DEFAULT | EXTRA |
  +-------+-------------+------+-----+---------+-------+
  | COL2  | VARCHAR2(10) | YES  | NULL | NULL    | NULL  |
  +-------+-------------+------+-----+---------+-------+
  1 row in set
  ```

### 列の追加と削除

  * テーブル `tbl2` を作成します。

    ```sql
    obclient> CREATE TABLE tbl2 (col1 NUMBER(30) PRIMARY KEY,col2 VARCHAR(50));
    Query OK, 0 rows affected
    ```

  * テーブル `tbl2` に `col3` 列を追加します。

    ```sql
    +-------+--------------+------+-----+---------+-------+
    3 rows in set
    ```

#### カラム削除操作

- **単一カラムの削除**

  * テーブル `tbl2` の `col3` 列を削除します。

    ```sql
    obclient> ALTER TABLE tbl2 DROP COLUMN col3;

    ```

- **複数カラムの削除**

  * テーブル `tbl2` に `col3`、`col4`、`col5` 列を追加します。

    ```sql
    obclient> ALTER TABLE tbl2 ADD col3 NUMBER(30);
    ```


- **不要なカラムの削除**

  * テーブル `tbl2` の不要な `col2`、`col3`、`col4`、`col5` 列を削除します。

   ```shell
   obclient> ALTER TABLE tbl2 FORCE;
   Query OK, 0 rows affected
   ```

### インデックス操作

  * テーブル `tbl2` に一意のインデックスを作成します。

    ```shell
    obclient> DROP TABLE tbl2;
    Query OK, 0 rows affected

    obclient> CREATE TABLE tbl2 (col1 NUMBER(30) PRIMARY KEY,col2 VARCHAR(50), col3 INT);
    Query OK, 0 rows affected

    obclient> ALTER TABLE tbl2 ADD CONSTRAINT constraint_TBL2 UNIQUE (col2, col3);
    Query OK, 0 rows affected

    obclient> DESC tbl2;
    +-------+--------------+------+-----+---------+-------+
    | FIELD | TYPE         | NULL | KEY | DEFAULT | EXTRA |
    +-------+--------------+------+-----+---------+-------+
    | COL1  | NUMBER(30)   | NO   | PRI | NULL    | NULL  |
    | COL2  | VARCHAR2(50) | YES  | MUL | NULL    | NULL  |
    | COL3  | NUMBER(38)   | YES  | NULL | NULL    | NULL  |
    +-------+--------------+------+-----+---------+-------+
    3 rows in set

    obclient> INSERT INTO tbl2 VALUES('1','2','2');
    Query OK, 1 row affected

    obclient> INSERT INTO tbl2 VALUES('2','2','2');
    ORA-00001: unique constraint '2-2' for key 'CONSTRAINT_TBL2' violated

    obclient> INSERT INTO tbl2 VALUES('2','3','2');
    Query OK, 1 row affected
    ```

### 外部キー操作

* テーブル `ref_t2` に外部キーを追加し、`DELETE` 操作が親テーブルのキー値と子テーブルの行に一致する場合に、`SET NULL` 操作を実行します。

  ```shell
  obclient> CREATE TABLE ref_t1(c1 INT PRIMARY KEY,C2 INT);
  Query OK, 0 rows affected

  obclient> CREATE TABLE ref_t2(c1 INT PRIMARY KEY,C2 INT);
  Query OK, 0 rows affected

  obclient> ALTER TABLE ref_t2 ADD CONSTRAINT fk1 FOREIGN KEY (c2) REFERENCES ref_t1(c1) ON DELETE SET NULL;
  Query OK, 0 row affected
  ```

### パーティション操作

* テンプレート化されていないネストedbパーティションテーブル `tbl3` の主要パーティション `p1` に、ネストedbパーティション `p1_r4` を追加します。
