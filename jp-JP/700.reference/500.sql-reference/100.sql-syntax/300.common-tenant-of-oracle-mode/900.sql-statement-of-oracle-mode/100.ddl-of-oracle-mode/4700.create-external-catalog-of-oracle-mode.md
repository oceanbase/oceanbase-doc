# CREATE EXTERNAL CATALOG

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>このステートメントはV4.3.5 BP2バージョンからサポートされています。なお、JDBCタイプのExternal CatalogはV4.4.2 BP4バージョンからサポートされています。</p>
</main>

## 説明

このステートメントは、データベース内に外部データカタログ(External Catalog)を作成し、外部データソースに接続して外部データのメタ情報を取得するために使用されます。これにより、データのインポートや移行を行わずに外部データを直接クエリできます。

## 使用上の制限と注意事項

* 現在、`ODPS`、`HMS`、`JDBC`タイプのExternal Catalogの作成がサポートされています。そのうち、`JDBC`タイプはV4.4.2 BP4バージョンからサポートされており、現在はSQL Serverデータソースへの接続のみをサポートしています。
* MySQLモードとは異なり、Oracleモードの`CREATE EXTERNAL CATALOG`ステートメントは`IF NOT EXISTS`句をサポートしていません。作成しようとするCatalogが既に存在する場合、エラーが発生します。
* Catalog名は大文字小文字を区別せず、二重引用符で囲まれていないCatalog名はすべて大文字に変換されて保存されます。大文字小文字を保持する必要がある場合は、Catalog名を二重引用符で囲むことができます。
* HMS Catalogを作成する前に、HMSがアクセスする予定の基盤ストレージのファイルデータがHDFS上にある場合は、Java SDK環境のデプロイが完了している必要があります。JAVA SDK環境の設定に関する詳細は、[OceanBaseデータベースJAVA SDK環境のデプロイ](../../../../../../400.deploy/300.deploy-oceanbase-enterprise-edition/500.deploy-the-ob-java-sdk-environment.md)を参照してください。
* JDBC Catalogを作成する前に、Java SDK環境のデプロイが完了しており、devdeps-java-extensions RPMパッケージが1.0.6以降のバージョンである必要があります。JAVA SDK環境の設定に関する詳細は、[OceanBaseデータベースJAVA SDK環境のデプロイ](../../../../../../400.deploy/300.deploy-oceanbase-enterprise-edition/500.deploy-the-ob-java-sdk-environment.md)を参照してください。
* External Catalog下のオブジェクトは読み取り専用であり、`INSERT`、`UPDATE`、`DELETE`、`ALTER TABLE`、`DROP TABLE`などの変更ステートメントの実行はサポートされていません。

## 権限要件

`CREATE EXTERNAL CATALOG`ステートメントを実行するには、現在のユーザーが`CREATE CATALOG`システム権限を持っている必要があります。OceanBaseデータベースの権限に関する詳細は、[Oracleモードの権限分類](../../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/300.permission-of-oracle-mode/000.permission-classification-of-oracle-mode.md)を参照してください。

ユーザーがCatalogを正常に作成すると、そのCatalogの`USE CATALOG`オブジェクト権限が自動的に付与されます。これは`SYS.USER_TAB_PRIVS`ビューで確認できます。

## 構文

```sql
CREATE EXTERNAL CATALOG external_catalog_name
    PROPERTIES [=] (properties_type_list)

properties_type_list:
    odps_type_list
    | hms_type_list
    | jdbc_type_list

odps_type_list:
    TYPE = 'ODPS',
    [ACCESSTYPE = 'accesstype_string',]
    ACCESSID = 'string',
    ACCESSKEY = 'string',
    STSTOKEN = 'string',
    ENDPOINT = 'string',
    TUNNEL_ENDPOINT = 'string',
    PROJECT_NAME = 'string',
    [QUOTA_NAME = 'string',]
    REGION = 'string'

hms_type_list:
    TYPE = 'HMS',
    URI = 'string'
    [, KRB5CONF = 'string']
    [, KEYTAB = 'string']
    [, PRINCIPAL = 'string']
    [, MAX_CLIENT_POOL_SIZE = 20]
    [, SOCKET_TIMEOUT = 10000000]

jdbc_type_list:
    TYPE = 'JDBC',
    URL = 'string'

accesstype_string:
    aliyun
    | sts
    | app
```

## パラメータ説明

|    **パラメータ**     | **説明** |
|-----------------|----------|
| external_catalog_name | 作成する外部データカタログの名前を表します。大文字小文字を区別せず、二重引用符で囲まれていない場合はすべて大文字に変換して保存されます。|
| PROPERTIES [=] (properties_type_list) | 外部データカタログタイプの関連属性オプションを指定するために使用します。詳細については、以下の [properties_type_list](#properties_type_list) を参照してください。|

### properties_type_list

* `odps_type_list`：ODPSタイプの外部データカタログ（ODPS Catalog）の関連属性リストを表します。詳細については、以下の [odps_type_list](#odps_type_list) を参照してください。
* `hms_type_list`：HMSタイプの外部データカタログ（HMS Catalog）の関連属性リストを表します。詳細については、以下の [hms_type_list](#hms_type_list) を参照してください。
* `jdbc_type_list`：JDBCタイプの外部データカタログ（JDBC Catalog）の関連属性リストを表します。詳細については、以下の [jdbc_type_list](#jdbc_type_list) を参照してください。

### odps_type_list

* `TYPE`：外部データカタログのタイプを指定するために使用し、値は `ODPS` です。これは、外部テーブルからMaxComputeデータを読み書きする場合の値です。
* `ACCESSTYPE`：オプションです。MaxComputeのアカウントタイプを指定するために使用し、デフォルト値は `aliyun` です。アカウントタイプの値（大文字小文字を区別しない）は以下のとおりです：

  * `aliyun`
  * `sts`
  * `app`

* `ACCESSID`：AccessKey IDを指定するために使用します。`ACCESSTYPE` の値が `aliyun`/`app` アカウントタイプ、または空の場合、`aliyun`/`app` アカウント、またはMaxComputeへのアクセス権限を持つRAMユーザーのAccessKey IDです。
* `ACCESSKEY`：AccessKey Secretを指定するために使用します。`ACCESSTYPE` の値が `aliyun`/`app` アカウントタイプ、または空の場合、`aliyun`/`app` アカウント、またはMaxComputeへのアクセス権限を持つRAMユーザーのAccessKey Secretです。
* `STSTOKEN`：tokenを指定するために使用します。`ACCESSTYPE` の値が `sts` アカウントタイプの場合、これはMaxComputeサービスにアクセスするためのtokenです。
* `ENDPOINT`：MaxComputeのEndPoint（ドメインノード）を指定するために使用します。
* `TUNNEL_ENDPOINT`：Tunnel Endpointを指定するために使用します。MaxCompute CatalogはTunnel SDKを使用してデータを取得します。
* `PROJECT_NAME`：MaxCompute内のプロジェクトスペース名を指定するために使用します。プロジェクトスペース（Project）はMaxComputeの基本的な組織単位であり、従来のデータベースのデータベースまたはスキーマの概念に相当します。
* `QUOTA_NAME`：オプションです。Quotaを指定するために使用します。QuotaはMaxComputeにおいてコンピュートリソースプール（計算、アクセス、書き込み）を表します。ユーザーが対応するQuotaを設定している場合、このパラメータで特定のQuotaを指定します。
* `REGION`：MaxComputeを有効化したリージョンを指定するために使用します。

### hms_type_list

* `TYPE`：外部データカタログのタイプを指定するために使用し、値は `HMS` です。これは、外部テーブルからHiveが管理するデータを読み取る場合の値です。
* `URI`：アクセスする `HMS` サービスの `thrift` URIリンクを指定するために使用します。形式は `thrift://$host:$port` です。ここで：

  * `$host`：`thrift` IPアドレスを表します。
  * `$port`：`thrift` ポートを表します。`HMS` のデフォルト `thrift` ポートは9083です。

* `KRB5CONF`：オプションです。Kerberos認証を有効にした `HMS` サービスにアクセスする際に必要なKerberos設定ファイルのパスを指定するために使用します。

    <main id="notice" type='notice'>
      <h4>注意</h4>
      <p><code>HMS</code> でKerberos認証が有効な場合にのみ、<code>KRB5CONF</code> パラメータを設定する必要があります。</p>
    </main>

* `KEYTAB`：オプションです。Kerberos認証を有効にした `HMS` サービスにアクセスする際に必要な `KEYTAB` キータブファイルのパスを指定するために使用します。OceanBaseクラスタが分散デプロイメントの場合、関連する各OBServerノードの指定されたパスに、このファイルが存在する必要があります。

    <main id="notice" type='notice'>
      <h4>注意</h4>
      <p><code>KEYTAB</code>パラメータは、<code>HMS</code>でKerberos認証が有効な場合にのみ設定する必要があります。</p>
    </main>

* `PRINCIPAL`：オプションです。Kerberos認証を有効にした`HMS`サービスにアクセスする際に必要なKerberos主体（Principal）名を指定します。通常は`service/HOST@REGION.com`の形式で表され、例えば`hive/hadoop@QA.COM`のようになります。

    <main id="notice" type='notice'>
      <h4>注意</h4>
      <p><code>PRINCIPAL</code>パラメータは、<code>HMS</code>でKerberos認証が有効な場合にのみ設定する必要があります。</p>
    </main>

* `MAX_CLIENT_POOL_SIZE`：オプションです。HMSクライアント接続プールの最大接続数を指定します。デフォルト値は`20`です。
* `SOCKET_TIMEOUT`：オプションです。HMSクライアントのソケットタイムアウト時間を指定します。単位はマイクロ秒です。デフォルト値は`10000000`（つまり10秒）です。

### jdbc_type_list

* `TYPE`：外部データカタログのタイプを指定するために使用します。値は`JDBC`となります。外部テーブルがJDBCプロトコルを介してデータソースからデータを読み取る場合に、この値を指定します。現在、SQL Serverデータソースへの接続のみをサポートしています。
* `URL`：JDBC接続文字列、つまりSQL ServerデータソースへのJDBC URLを指定するために使用します。例：`jdbc:sqlserver://10.10.10.1:1433;databaseName=master;encrypt=true;trustServerCertificate=true`。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p><code>URL</code>は暗号化されて保存されます。<code>SHOW CREATE CATALOG</code>ステートメントを実行してカタログの作成ステートメントを確認するとき、<code>URL</code>はマスキングされて表示されます。</p>
</main>

JDBCカタログ下の外部テーブルの列タイプは、devdeps-java-extensionsが提供する列メタデータ（`targetType`）によって決定され、Oracleモードのデータタイプにマッピングされます。SQL Serverデータソースの主要なタイプマッピングは以下のとおりです：

| **SQL Serverタイプ** | **Oracleモードのタイプ** |
|---------------------|-------------------------|
| BIT | NUMBER(1) |
| TINYINT | NUMBER(3) |
| SMALLINT | NUMBER(5) |
| INT | NUMBER(10) |
| BIGINT | NUMBER(19) |
| DECIMAL / NUMERIC | NUMBER(p,s) |
| SMALLMONEY | NUMBER(10,4) |
| MONEY | NUMBER(19,4) |
| REAL / FLOAT(24) | BINARY_FLOAT |
| FLOAT(53) / DOUBLE | BINARY_DOUBLE |
| CHAR(n) | VARCHAR2(n CHAR) |
| VARCHAR(n) | VARCHAR2(n CHAR) |
| NCHAR(n) | NVARCHAR2(n) |
| NVARCHAR(n) | NVARCHAR2(n) |
| BINARY(n) | RAW(n) |
| VARBINARY(n) | RAW(n) |
| DATE | DATE |
| TIME | INTERVAL DAY (1) TO SECOND (n) |
| SMALLDATETIME | TIMESTAMP(0) |
| DATETIME | TIMESTAMP(3) |
| DATETIME2 | TIMESTAMP(7) |
| サポートされていないタイプ | UNSUPPORTED |

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>外部テーブルに <code>UNSUPPORTED</code> と表示されるデータ型の列が存在する場合、その列はクエリできません。他の列へのクエリは影響を受けません。</p>
</main>

## 例

* JDBCタイプのExternal Catalogを作成します。

  ```sql
  obclient> CREATE EXTERNAL CATALOG tmp_jdbc_catalog PROPERTIES = (TYPE = 'JDBC', URL = 'jdbc:sqlserver://10.10.10.1:1433');

  obclient> DROP CATALOG tmp_jdbc_catalog;
  ```

* ODPSタイプのExternal Catalogを作成し、使用しなくなったら削除します。

  ```sql
  obclient> CREATE EXTERNAL CATALOG tmp_odps_catalog PROPERTIES = (TYPE = 'ODPS', ACCESSID = '$odps_accessid', ACCESSKEY = '$odps_accesskey', ENDPOINT = '$odps_endpoint', TUNNEL_ENDPOINT = 'http://xxx.maxcompute.aliyun.com', PROJECT_NAME = 'odps_test_project');

  obclient> DROP CATALOG tmp_odps_catalog;
  ```
