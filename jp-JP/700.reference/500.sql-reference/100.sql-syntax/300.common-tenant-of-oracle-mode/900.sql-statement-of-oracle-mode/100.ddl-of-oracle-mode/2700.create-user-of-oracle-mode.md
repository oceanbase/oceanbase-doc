# CREATE USER

## 説明

`CREATE USER` ステートメントは、新しいOceanBaseデータベースユーザーを作成するために使用します。新しいユーザーを作成すると、そのユーザーでOceanBaseデータベースに接続できるようになります。

## 制限事項及び注意点

* 認証文字列形式検証：`IDENTIFIED WITH ... BY VALUES` は `$S$` 形式を検証し、`$A$`（`sha2`）などの誤った形式は拒否されます。
* 対応していないODPでは、SM3ユーザー（認証プラグイン `ob_sm3_password` を使用するユーザー）への接続を完了できません。

## 権限要件

`CREATE USER` ステートメントを実行してユーザーを作成するには、現在のユーザーが `CREATE USER` システム権限を持っている必要があります。OceanBaseデータベースの権限の詳細については、[Oracleモードの権限分類](../../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/300.permission-of-oracle-mode/000.permission-classification-of-oracle-mode.md)を参照してください。

## 構文

```sql
CREATE USER user_name
    { IDENTIFIED BY [VALUES] password
    | IDENTIFIED WITH auth_plugin [BY password]
    }
    [REQUIRE {NONE | SSL | X509 | tls_option}]
    [PROFILE profile_name]
    [DEFAULT TABLESPACE tablespace_name];

auth_plugin:
    caching_sha2_password
    | ob_sm3_password

tls_option:
      CIPHER cipher_name
    | ISSUER issuer_name
    | SUBJECT subject_name
```

## パラメータ説明

| パラメータ   | 説明     |
|-------|-----------|
| user_name | ユーザー名。新規ユーザー作成後、`dba_users` テーブルにそのユーザーのエントリが追加されます。同名のユーザーが既に存在する場合は、エラーが発生します。 |
| IDENTIFIED BY | 作成予定のユーザーのパスワードを設定します。ここではパスワードは平文ですが、`dba_users` テーブルに格納された後、サーバー側で暗号化されます。パスワードに特殊文字 <code>~!@#%^&*_-+=`\|(){}[]:;',.?/</code> が含まれる場合は、半角二重引用符（<code>"</code>）で囲む必要があります。|
| IDENTIFIED BY VALUES | 作成予定のユーザーのパスワードを設定します。ここではパスワードは暗号文であり、直接 `dba_users` テーブルに格納されます。 |
| IDENTIFIED WITH auth_plugin [BY password] | 認証プラグインと対応する認証情報を指定します。 <ul><li>`auth_plugin`：ユーザー認証方式（認証プラグイン）を指定するために使用します。詳細は下記 [auth_plugin](#auth_plugin) を参照してください。</li><li>`BY password`：オプションです。平文のパスワードを指定するために使用します。</li></ul> <main id="notice" type='explain'><h4>説明</h4><p>V4.4.2バージョンでは、<code>IDENTIFIED WITH</code> 構文はV4.4.2 BP2バージョンからサポートされています。</p></main> |
| REQUIRE | ユーザーのパスワード検証要件を指定します。以下の値があります。<ul><li>`NONE`：ユーザーにパスワード検証要件がないことを意味し、ユーザーは任意のパスワードを使用するか、パスワードを設定しなくてもよいことを意味します。</li><li>`SSL`：ユーザーはSSL接続を使用した認証を行う必要があることを意味します。</li><li>`X509`：ユーザーはX509証明書を使用した認証を行う必要があることを意味します。</li><li>`tls_option`：ユーザーは指定されたTLS（Transport Layer Security）要件を満たす必要があることを意味します。</li></ul> |
| tls_option | TLS要件の具体的なオプションを指定します。<ul><li>`CIPHER`：TLS接続で使用する暗号化アルゴリズムまたは暗号スイートを指定するために使用します。</li><li>`ISSUER`：TLS証明書の発行者（Issuer）を指定するために使用します。</li><li>`SUBJECT`：TLS証明書の主体（Subject）を指定するために使用します。</li></ul> |
| PROFILE | ユーザープロファイルを指定します。ユーザープロファイルは、作成されるユーザーに適用できる一連の事前定義された権限と制限です。 |
| DEFAULT TABLESPACE | ユーザーのデフォルトテーブルスペースを指定します。テーブルスペースは、ユーザーデータを格納するための論理構造です。 |

### auth_plugin

* `caching_sha2_password`：SHA-256ベースのパスワード認証プラグインで、より高いセキュリティレベルを提供します。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>V4.4.2バージョンでは、V4.4.2 BP2バージョンから認証プラグイン <code>caching_sha2_password</code> がサポートされています。</p>
  </main>

* `ob_sm3_password`：このプラグインは、認証プロトコルとステートマシンを `caching_sha2_password` と完全に共有します（AuthSwitch、高速認証/完全認証、TLS/RSAによるパスワードの暗号化送信）。ただし、アルゴリズムとメタデータは独立しており、パスワードの保存と認証検証にSHA-256の代わりにSM3ハッシュアルゴリズムを使用します。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>V4.4.2バージョンでは、V4.4.2 BP3バージョンから認証プラグイン <code>ob_sm3_password</code> がサポートされています。</p>
  </main>

## 例

* ユーザー `test1` を作成し、平文のパスワードを指定する

  ```sql
  obclient [SYS]> CREATE USER test1 IDENTIFIED BY "********";
  ```

* ユーザー `test2` を作成し、暗号文のパスワードを指定すると同時に、SSL接続を使用した認証を必須とする

  ```sql
  obclient [SYS]> CREATE USER test2 IDENTIFIED BY VALUES "********" REQUIRE SSL;
  ```

* ユーザー `test3` を作成し、`caching_sha2_password` 認証プラグインの使用を明示的に指定する

  ```sql
  obclient [SYS]> CREATE USER test3 IDENTIFIED WITH caching_sha2_password BY "********";
  ```
