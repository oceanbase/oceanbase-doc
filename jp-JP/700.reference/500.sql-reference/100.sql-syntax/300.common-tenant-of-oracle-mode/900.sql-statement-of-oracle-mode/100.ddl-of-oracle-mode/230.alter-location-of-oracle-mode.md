# ALTER LOCATION

## 説明

このステートメントは、Locationオブジェクトのプロパティを変更するために使用します。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>OceanBaseデータベースV4.4.xでは、V4.4.1バージョンから <code>ALTER LOCATION</code> ステートメントがサポートされています。</p>
</main>

## 権限要件

* 実行権限：

    `ALTER LOCATION` ステートメントを実行するには、現在のユーザーが `CREATE LOCATION` 権限を持っている必要があります。OceanBaseデータベースの権限の詳細については、[Oracleモードの権限分類](../../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/300.permission-of-oracle-mode/000.permission-classification-of-oracle-mode.md)を参照してください。

* 認証資格権限：

    提供された `ACCESSID` と `ACCESSKEY` は、ターゲットストレージサービスへの合法的なアクセス権限を持っている必要があります。

## 構文

```sql
ALTER LOCATION location_name SET
    {URL = 'file_path'
    | CREDENTIAL = (credential_list)
    };

credential_list:
    ACCESSID = 'string'
    ACCESSKEY = 'string'
    HOST = 'string'
    [S3_REGION = 'string']
    [PRINCIPAL = 'string']
    [KEYTAB = 'string']
    [KRB5CONF = 'string']
    [CONFIGS = 'string']
    [USERNAME = 'string']
```

## パラメータ説明

|      **パラメータ**     | **説明** |
|-------------------|----------|
| location_name     | 変更対象のLocationオブジェクト名を表します。|
| URL = 'file_path' | 外部ストレージパスを変更するために使用します。詳細については、後述の [file_path](#file_path) を参照してください。|
| CREDENTIAL        | HDFSまたはオブジェクトストレージへのアクセスパスを変更するために必要な情報を表します。詳細については、後述の [credential_list](#credential_list) を参照してください。|

### file_path

外部テーブルファイルの保存パスは、以下の形式となります：

* ローカルパスの形式は次のとおりです：`URL = '[file:// | sfile://] local_file_path'`

  * `file://`：このプロトコルヘッダーは、複数のOBServerノードで同じ論理パスのファイルに遭遇した場合、それぞれ異なるファイルとして扱われ、個別に処理されることを示します。各ノードは、ローカルパス下のファイルを独立して読み取ります。
  * `sfile://`：このプロトコルヘッダーは、複数のOBServerノードで同じ論理パスのファイルに遭遇した場合、システムが論理パスに基づいて重複処理を行い、データを1部しか読み取らないようにすることを示します（マルチサーバーのロードバランシングをサポートします）。

    <main id="notice" type='notice'>
      <h4>注意</h4>
      <p><ul><li><code>sfile://</code> を使用する場合、システムはファイルサイズの一貫性検証を実行します。同一の論理パス下にあるファイルが異なるOBServerノード上でサイズが一致しない場合、システムはデータの不整合による結果の誤りを防ぐために、<code>OB_INVALID_EXTERNAL_FILE</code> エラーを返します。</li> <li>V4.4.2バージョンでは、V4.4.2 BP2バージョンから <code>ALTER LOCATION</code> 構文のローカルURLパス形式に <code>sfile://</code> プロトコルヘッダーのサポートが追加されました。</li></ul></p>
    </main>

  * `local_file_path`：相対パスまたは絶対パスを指定できます。

* HDFSパス形式は次のとおりです：`URL = 'hdfs://localhost:port/PATH'`。ここで、`localhost` はHDFSのアドレス、`port` はHDFSのポート番号、`PATH` はHDFS内のディレクトリパスを指します。

* オブジェクトストレージ（OSS/S3）パス形式は次のとおりです：`URL = '{oss | s3}://bucket/remote_file_path'`。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>Locationオブジェクトを作成するパスには、パラメータを含めないでください。</p>
</main>

### credential_list

* `ACCESSID`：オブジェクトストレージへのアクセスユーザーのAccessKey IDを変更するために使用します。
* `ACCESSKEY`：オブジェクトストレージへのアクセスユーザーのAccessKey Secretを変更するために使用します。
* `HOST`：オブジェクトストレージサービスのホストアドレスを変更するために使用します。
* `S3_REGION`：オプションです。S3オブジェクトストレージのサービスリージョンを変更するために使用します。
* `PRINCIPAL`：オプションです。ターゲットHDFSクラスタがKerberos環境を有する場合、ログイン認証ユーザーを変更するために使用します。
* `KEYTAB`：オプションです。ターゲットHDFSクラスタがKerberos環境を有する場合、認証キーテーブルファイルのパスを変更するために使用します。
* `KRB5CONF`：オプションです。ターゲットHDFSクラスタがKerberos環境を有する場合、ユーザーがKerberos環境を使用するファイルのパスを変更するために使用します。
* `CONFIGS`：オプションです。ターゲットHDFSクラスタがKerberos環境を有する場合、追加のクラスタ構成パラメータを変更するために使用します。
* `USERNAME`：オプションです。ターゲットHDFSクラスタがKerberos環境を有する場合、ユーザーの一意の識別情報を変更するために使用します。

## 例

Locationオブジェクト `test_location_oss` の `CREDENTIAL` 情報を変更します。

```shell
obclient> ALTER LOCATION test_location_oss SET
    CREDENTIAL = (
        ACCESSID = '******'
        ACCESSKEY = '******'
        HOST = '******'
        );
```
