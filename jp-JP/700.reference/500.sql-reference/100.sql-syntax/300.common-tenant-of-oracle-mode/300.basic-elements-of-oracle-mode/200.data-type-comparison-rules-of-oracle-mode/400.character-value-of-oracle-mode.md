# 文字値の比較規則

文字データは文字値の大きさに基づいて比較されます。これには2つの尺度があり、それぞれバイナリ比較と言語比較、および比較時に末尾の空白を補うかどうかです。このセクションでは、文字データの2つの尺度における比較規則について説明します。

## バイナリ比較と言語比較

### バイナリ比較

デフォルトのバイナリ比較では、OceanBaseデータベースはデータベースの文字セット内の文字の数値コードの連結値に基づいて文字列を比較します。ある文字の値が文字セット内で別の文字の値よりも大きい場合、その文字の方が大きいとされます。OceanBaseデータベースはASCII文字セットとEBCDIC文字セットをサポートしていません。

### 言語比較

言語ソートでは、SQLのソートと比較はすべて`NLS_SORT`で指定された言語ルールに従います。文字コードのバイナリ順が、その言語で必要な並べ替え順と一致しない場合、言語比較が使用されます。`NLS_SORT`パラメータの設定が`BINARY`以外であり、かつ`NLS_COMP`パラメータが`LINGUISTIC`に設定されている場合、言語比較が使用されます。

## 末尾の空白を補う比較と補わない比較

### 末尾の空白を補う比較

末尾の空白を補う比較では、2つの値の長さが異なると、OceanBaseデータベースはまず短い方の値の末尾にスペースを追加して長さを等しくします。その後、OceanBaseデータベースは最初の異なる文字が現れるまで、2つの値を1文字ずつ比較します。最初の異なる文字の位置で、より大きな文字を持つ値の方が大きいとされます。2つの値に異なる文字がない場合、それらは等しいとされます。この規則は、2つの値が末尾の空白の数だけ異なる場合に等しいことを意味します。

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>OceanBaseデータベースが末尾の空白を補う比較を使用するのは、比較対象の値がどちらもデータ型<code>CHAR</code>、<code>NCHAR</code>、テキストリテラル、または<code>USER</code>関数の戻り値の場合のみです。</p>
  </main>

### 末尾の空白を補わない比較

末尾の空白を補わない比較では、OceanBaseデータベースは最初の異なる文字が現れるまで、2つの値を1文字ずつ比較します。その位置で、より大きな文字を持つ値の方が大きいとされます。異なる長さの2つの値が短い方の値の比較が終わるまで同じであった場合、長い方の値の方が大きいとされます。長さが等しい2つの値に異なる文字がない場合、それらの値は等しいとされます。

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>比較対象の少なくとも一方が<code>VARCHAR2</code>または<code>NVARCHAR2</code>の場合、OceanBaseデータベースは末尾の空白を補わない比較を使用します。</p>
  </main>

異なる比較セマンティクスを使用して2つの文字値を比較した結果は、異なる場合があります。以下の表の例は、末尾の空白を補う場合と補わない場合の比較結果を示しています。

|      末尾の空白を補う       |       末尾の空白を補わない       |
|-----------------|-----------------|
| 'ac' \> 'ab'    | 'ac' \> 'ab'    |
| 'ab' \> 'a    ' | 'ab' \> 'a   '  |
| 'ab' \> 'a'     | 'ab' \> 'a'     |
| 'ab' = 'ab'     | 'ab' = 'ab'     |
| 'ac' \> 'ab'    | 'ac' \> 'ab'    |
| 'a      ' = 'a' | 'a     ' \> 'a' |
