# 日付時刻DATEと間隔INTERVALの計算

日付(DATE)、タイムスタンプ(TIMESTAMP、TIMESTAMP WITH TIME ZONE、TIMESTAMP WITH LOCAL TIME ZONE)、および間隔(INTERVAL YEAR TO MONTH、INTERVAL DAY TO SECOND)のデータ型は算術演算をサポートしています。この記事では主に、日付時刻DATEと間隔INTERVALの計算ルールについて説明します。

OceanBaseデータベースは以下のルールに基づいて結果を計算します：

* 日付やタイムスタンプ値(間隔値ではない場合)の算術演算では`NUMBER`定数を使用できます。OceanBaseデータベースは内部でタイムスタンプ値を日付値に変換し、算術的な日付時刻および間隔式における`NUMBER`定数を日数と解釈します。例えば、`SYSDATE`+1は明日です。`SYSDATE`-7は1週間前です。`SYSDATE`+(10/1440)は10分後です。

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>日付またはタイムスタンプ値に対して乗算または除算を行うことはできません。</p>
  </main>

* OceanBaseデータベースは`BINARY_FLOAT`および`BINARY_DOUBLE`オペランドを`NUMBER`に変換します。

* 各`DATE`値には時間要素が含まれており、多くの日付演算の結果にも1日の一部を表す分数が含まれます。例えば、1.5日は36時間です。OceanBaseの組み込み関数は、これらの分数を返して`DATE`データに対する一般的な操作を実行します。例えば、`MONTHS_BETWEEN` 関数は2つの日付の間の月数を返します。結果の小数部分は31日の月のその部分を表します。

* オペランドが`DATE`値または数値であり、かつタイムゾーンや小数秒の部分を含まない場合：

  * OceanBaseデータベースは、他のオペランドをDATEデータに変換します。数値に間隔を掛ける演算は例外で、間隔が返されます。
  * もう一方のオペランドにタイムゾーン値がある場合、OceanBaseデータベースは返される値に現在のセッションのタイムゾーンを使用します。
  * もう一方のオペランドに小数秒の数値がある場合、その小数秒の数値は失われます。

* タイムスタンプ、時間間隔、または数値を`DATE` データ型専用の組み込み関数に渡す場合、OceanBaseデータベースは非 `DATE` 値を `DATE` 値に変換します。

* 間隔計算で日付時刻値が返される場合、結果は実際の日付時刻値でなければなりません。そうでない場合、データベースはエラーを返します。例：

  ```sql
  SELECT TO_DATE("31-AUG-2004','DD-MON-YYYY") + TO_YMINTERVAL("0-1") FROM DUAL;
  SELECT TO_DATE("29-FEB-2004','DD-MON-YYYY") + TO_YMINTERVAL("1-0") FROM DUAL;
  ```

  最初のステートメントは31日の月に1ヶ月を加算すると、計算結果が9月31日となり、これは有効な日付ではないため実行失敗です。2番目のステートメントは、4年ごとにしか存在しない日付に1年を加算することは無効で、実行失敗です。しかし、2月29日の4年前を加算することは有効で、計算結果は `2008年2月29日` となります：

  ```sql
  SELECT TO_DATE("29-FEB-2004", "DD-MON-YYYY") + TO_YMINTERVAL("4-0") FROM DUAL;
  ```
