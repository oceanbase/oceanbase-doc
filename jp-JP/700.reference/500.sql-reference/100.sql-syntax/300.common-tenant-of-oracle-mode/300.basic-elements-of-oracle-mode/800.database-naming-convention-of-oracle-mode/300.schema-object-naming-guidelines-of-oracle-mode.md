# スキーマオブジェクトの命名に関する推奨事項

本記事では、スキーマオブジェクトの命名に関するいくつかの推奨事項を提示します。

OceanBaseデータベースのオブジェクト命名に関する推奨事項は以下のとおりです：

* 省略せず、内容を表す、綴りやすい名前、または広く知られた略称を使用してください。

* 一貫した命名規則を使用してください。

* 複数のテーブルにまたがる同一のエンティティや属性を表す場合は、同じ名前を使用してください。

オブジェクトに名前を付ける際、使いやすさと内容のわかりやすさを両立できない場合は、内容がより明確に伝わる名前を選択してください。データベース内のオブジェクトは長期間使用され続ける可能性があるため、10年後のユーザーには `pmdd` という名前のテーブルの列が何の情報を格納するためのものか理解できない可能性があります。これに対し、`payment_due_date` という名前の方がはるかに明確でわかりやすいでしょう。

一貫した命名規則を使用することで、アプリケーション内で各テーブルが果たす役割をユーザーが理解しやすくなります。例えば、`FINANCE` アプリケーションに属するすべてのテーブル名の頭に `fin_` を付けるといった具合です。

テーブル間で同じ内容を表す列には同じ名前を使用してください。例えば、従業員テーブルと部門テーブルが同じ部門番号を持つ場合、この列は実際には同じ値を格納しています。そのため、従業員テーブルと部門テーブルではこの列を共に `department_id` と命名しています。
