# Schemaオブジェクトの命名に関する推奨事項

本記事では、Schemaオブジェクトの命名に関するいくつかの推奨事項を提供します。

OceanBaseデータベースのオブジェクト命名に関する推奨事項は以下のとおりです：

* 完全で、記述的で、綴りやすい名前、または広く知られた略語を使用します。

* 一貫した命名ルールを使用します。

* 複数のテーブルにまたがる同一のエンティティや属性を表す場合は、同じ名前を使用します。

オブジェクトに名前を付ける際、シンプルさと使いやすさと記述性のバランスが取れない場合は、より記述的な名前を選択してください。データベース内のオブジェクトは長期間使用される可能性があるため、10年後にユーザーが `pmdd` という名前のテーブルの列が何の情報を格納するためのものか理解するのが難しくなることを避けるためです。対照的に、`payment_due_date` という名前の方がはるかに明確でわかりやすいです。

一貫した命名ルールを使用することで、アプリケーション内で各テーブルが果たす役割をユーザーが理解しやすくなります。例えば、`FINANCE` アプリケーションに属するすべてのテーブルの名前を `fin_` で始めるようにします。

同じ内容を表すテーブルには同じ名前を使用します。例えば、従業員テーブルと部門テーブルが同じ部門番号を持っている場合、この列は実際には同じ値を格納しています。そのため、従業員テーブルと部門テーブルではこの列を `department_id` という名前で呼んでいます。
