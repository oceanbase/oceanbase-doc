# ヒントの概要

ヒントとは、SQL文にコメントとして記述されるものであり、OceanBaseデータベースのオプティマイザーに指示を伝えるために使用されます。ヒントを使用することで、オプティマイザーが指定された実行計画を生成するようになります。

通常、オプティマイザーはユーザーのクエリに対して最適な実行計画を選択します。そのため、ユーザーがヒントを指定する必要はありません。しかし、特定のシナリオでは、オプティマイザーが生成した実行計画がユーザーの要件を満たさない場合があります。このような場合、ユーザーはヒントを使用して特別な実行計画を明示的に指定し、生成する必要があります。

ヒントはできるだけ控えめに使用することを推奨します。関連するテーブルの統計情報を収集し、ヒントなしで`EXPLAIN PLAN`ステートメントを使用してオプティマイザーの計画を評価した後にのみ、ヒントの使用を慎重に検討することをお勧めします。データベースの条件を変更したり、今後のバージョンでクエリ性能が向上したりすると、コード内のヒントがパフォーマンスに大きな影響を与える可能性があります。

## ヒントの使用

一つのステートメントには一つのヒントコメントしか含められず、そのコメントは `CREATE`、`SELECT`、`UPDATE`、`INSERT`、`REPLACE` または `DELETE` キーワードの後に続けなければなりません。

ステートメント内でのヒントの構文は以下のとおりです：

```sql
{CREATE|DELETE|INSERT|SELECT|UPDATE|REPLACE} /*+ hint_text [,hint_text...] */
```

構文的に見ると、ヒントは特殊なSQLコメントですが、コメントの左側のマーカーの後にプラス記号（+）が追加されている点が異なります。サーバー側がSQLステートメント内のヒントを認識できない場合、オプティマイザーはユーザーが指定したヒントを無視してデフォルトの計画で生成された実行ロジックを使用します。また、ヒントはオプティマイザーが生成する実行計画のロジックにのみ影響し、SQLステートメントのセマンティクスには影響しません。

ヒントを定義する際に注意すべきいくつかのルールは以下のとおりです：

* プラス記号（+）は、データベースがコメントをヒントリストとして解釈するようにします。プラス記号はコメントの左側のマーカーの直後に続けなければならず、スペースは許可されません。

* プラス記号（+）とヒントテキストの間のスペースは省略可能です。コメント内に複数のヒントが含まれる場合、ヒント間には少なくとも1つのスペースを使用して区切ります。

* スペルミスや構文エラーを含むヒントは無視されます。ただし、同じコメント内で他の正しく指定されたヒントは考慮されます。

* `CREATE`、`DELETE`、`INSERT`、`REPLACE`、`SELECT` または `UPDATE` キーワードの後に続かないヒントは無効です。

* ヒントの組み合わせが互いに矛盾する場合、ヒントは無効です。ただし、データベースは同じコメント内で他の矛盾しないヒントを使用することを検討します。

## ヒント内でクエリブロックを定義する

複数のヒント内でオプションのクエリブロック名を定義することで、そのヒントが適用されるクエリブロックを指定できます。

この構文を使用すると、外部クエリ内で組み込みビューに適用されるヒントを指定できます。

クエリブロックパラメータの構文は `@queryblock` であり、ここで `queryblock` はクエリ内で指定されるクエリブロックの識別子です。`queryblock` の識別子はシステム生成のものでも、ユーザー自身が指定したものでも構いません。クエリブロック内で直接適用するヒントを指定する場合、`@queryblock` は無視されます。

* システム生成の識別子は、クエリに対して `EXPLAIN` を使用して生成できます。

* QB_NAME を使用して、ユーザー定義の名前を指定できます。

## グローバルヒントの定義

多くのヒントは特定のテーブルやインデックスに適用できるだけでなく、よりグローバルにビュー内のテーブルや一部のインデックスの列にも適用できます。構文要素 `tablespec` と `indexspec` はこれらのグローバルヒントを定義します。

`tablespec` の構文は以下のとおりです：

```sql
[ view.[,view. ]... ] table_name
```

アクセスするテーブルは、ステートメント内に表示されているとおりに完全に指定する必要があります。そのステートメントでテーブルのエイリアスが使用されている場合、ヒント内でもエイリアスを使用し、テーブル名は使用しません。ただし、スキーマ名がステートメントに現れている場合でも、ヒント内で使用するテーブル名にスキーマ名を含めないでください。

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p><code>tablespec</code> 句を使用してグローバルヒントを指定しても、ANSI接続を使用するクエリでは機能しません。これは、オプティマイザーが解析時に追加のビューを生成するためです。代わりに、<code>@queryblock</code> を使用して、そのヒントが適用されるクエリブロックを指定できます。</p>
  </main>

`indexspec` の構文は以下のとおりです：

```sql
{ index
| ( [ table. ]column_name [ [ table. ]column_name ]...)
}
```

ヒントの説明部分において、`tablespec` の後に `indexspec` が続く場合、テーブル名とインデックス名を区切るためにカンマを使用することは許可されていますが必須ではありません。また、複数回出現する `indexspec` を区切るためにカンマを使用することも許可されていますが、必須ではありません。
