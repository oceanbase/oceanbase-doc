# クエリ変換に関連するHint

クエリ変換に関連するHintには、NO_REWRITE Hint、NO_EXPAND Hint、USE_CONCAT Hint、MERGE Hint、NO_MERGE Hint、UNNEST Hint、NO_UNNEST Hint、PLACE_GROUP_BY Hint、NO/place_GROUP_BY Hint、およびNO_PRED_DEDUCE Hintが含まれます。

## NO_REWRITE ヒント

`NO_REWRITE` ヒントは、オプティマイザーにクエリブロックのクエリ書き換えを無効にするよう指示します。

`NO_REWRITE` ヒントの構文は次のとおりです：

```sql
/*+ NO_REWRITE [ ( @queryblock ) ] */
```

`NO_REWRITE` ヒントの例は次のとおりです：

```sql
SELECT /*+ NO_REWRITE */ sum(s.amount_sold) AS dollars
FROM sales s, times t
WHERE s.time_id = t.time_id
GROUP BY t.calendar_month_desc;
```

## NO_EXPAND ヒント

`NO_EXPAND` ヒントは、オプティマイザーに `WHERE` 句内の `OR` 条件または `IN` リストを持つクエリに対して `OR` 拡張を検討しないよう指示します。通常、オプティマイザーは `OR` 拡張を使用する方がコストが低いと判断した場合に `OR` 拡張を使用します。

`NO_EXPAND` ヒントの構文は次のとおりです：

```sql
/*+ NO_EXPAND [ ( @queryblock ) ] */
```

`NO_EXPAND` ヒントの例は次のとおりです：

```sql
SELECT /*+ NO_EXPAND */ *
  FROM employees e, departments d
  WHERE e.manager_id = 108
     OR d.department_id = 110;
```

## USE_CONCAT ヒント

`USE_CONCAT` ヒントは、オプティマイザーに `UNION ALL` 演算子を使用して、クエリの `WHERE` 句内の組み合わせ `OR` 条件を複合クエリに変換するよう指示します。`USE_CONCAT` ヒントが設定されていない場合、この変換は連結クエリを使用するコストが使用しない場合よりも低い場合にのみ発生します。

`USE_CONCAT` ヒントの構文は次のとおりです：

```sql
/*+ USE_CONCAT [ ( @queryblock ) ] */
```

`USE_CONCAT` ヒントの例は次のとおりです：

```sql
SELECT /*+ USE_CONCAT */ *
  FROM employees e
  WHERE manager_id = 108
     OR department_id = 110;
```

## MERGE ヒント

`MERGE` ヒントを使用すると、クエリでビューをマージできます。

`MERGE` ヒントの構文は次のとおりです：

```sql
/*+ MERGE [ ( @queryblock )  | ( [ @queryblock ] tablespec ) ] */
```

ビューのクエリブロックの `SELECT` リストに `GROUP BY` 句または `DISTINCT` 演算子が含まれている場合、オプティマイザーは複雑なビューのマージを有効にした後にのみ、ビューをアクセス中のステートメントにマージできます。サブクエリが関連性がない場合でも、複雑なマージを使用して `IN` サブクエリをアクセスステートメントにマージできます。

`MERGE` ヒントの例は次のとおりです：

```sql
SELECT /*+ MERGE(v) */ e1.last_name, e1.salary, v.avg_salary
   FROM employees e1,
        (SELECT department_id, avg(salary) avg_salary
           FROM employees e2
           GROUP BY department_id) v
   WHERE e1.department_id = v.department_id
     AND e1.salary > v.avg_salary
   ORDER BY e1.last_name;
```

`MERGE` ヒントにパラメータを指定しない場合は、ビューのクエリブロック内に配置する必要があります。`MERGE` ヒントでビュー名をパラメータとして指定する場合は、外部クエリ内に配置する必要があります。

## NO_MERGE ヒント

`NO_MERGE` ヒントは、オプティマイザーに対し、外部クエリと任意のインラインビュークエリを単一のクエリにマージしないよう指示します。

`NO_MERGE` ヒントの構文は次のとおりです：

```sql
/*+ NO_MERGE [ ( @queryblock )  | ( [ @queryblock ] tablespec ) ] */
```

このヒントは、ビューへのアクセス方法に影響を与えます。次の例文では、ビュー `seattle_dept` のマージができません。

```sql
SELECT /*+ NO_MERGE(seattle_dept) */ e.last_name, seattle_dept.dept_name
  FROM employees e,
       (SELECT location_id, dept_id, dept_name
          FROM departments
          WHERE location_id = 1700) seattle_dept
  WHERE e.dept_id = seattle_dept.dept_id;
```

ビュークエリブロック内で `NO_MERGE` ヒントを使用する場合、パラメータを指定する必要はありません。外部クエリで `NO_MERGE` ヒントを使用する場合は、ビュー名をそのパラメータとして指定する必要があります。

## UNNEST ヒント

`UNNEST` ヒントは、オプティマイザーに対し、サブクエリをネストせず、代わりにそのヒントを含むクエリブロックの本体にサブクエリの本体をマージするよう指示します。これにより、オプティマイザーはアクセスパスと結合を評価する際にそれらを一緒に考慮します。

`UNNEST` ヒントの構文は次のとおりです：

```sql
/*+ UNNEST [ ( @queryblock ) ] */
```

オプティマイザーは、ネストされたサブクエリを解除する前に、まずサブクエリが有効かどうかを検証します。`UNNEST` ヒントを使用する場合、オプティマイザーはサブクエリブロックの有効性のみをチェックします。サブクエリブロックが有効であれば、サブクエリのネストは直接解除されます。

`UNNEST` ヒントの例は次のとおりです：

```sql
SELECT AVG(t1.c) FROM t1
WHERE t1.b >=
    (SELECT /*+UNNEST*/AVG(t2.b)
     FROM t2
     WHERE t1.a = t2.a);
```

## NO_UNNEST ヒント

`NO_UNNEST` ヒントは、ネスト解除操作を無効にするために使用されます。

`NO_UNNEST` ヒントの構文は次のとおりです：

```sql
/*+ NO_UNNEST [ ( @queryblock ) ] */
```

`NO_UNNEST` ヒントの例は次のとおりです：

```sql
SELECT /*+NO_UNNEST(@qb1)*/AVG(t1.c)
FROM t1 WHERE t1.b >=
    (SELECT /*+qb_name(qb1)*/AVG(t2.b)
     FROM t2）
     WHERE t1.a = t2.a);
```

## PLACE_GROUP_BY ヒント

`PLACE_GROUP_BY` ヒントは、オプティマイザーに対し、`GROUP BY` の位置置換ルールを採用するよう指示します。この場合、オプティマイザーは変換後のコスト増大を考慮しません。

`PLACE_GROUP_BY` ヒントの構文は次のとおりです：

```sql
/*+ PLACE_GROUP_BY [ ( @queryblock ) ] */
```

`PLACE_GROUP_BY` ヒントの例は次のとおりです：

```sql
SELECT /*+PLACE_GROUP_BY*/SUM(t1.c),SUM(t2.c) FROM t1, t2
WHERE t1.a = t2.a AND t1.b > 10 AND t2.b > 10
GROUP BY t1.a;
```

## NO/place_GROUP_BY ヒント

`NO_PLACE_GROUP_BY` ヒントは、`GROUP BY` の位置置換を無効にするために使用されます。

`NO_PLACE_GROUP_BY` ヒントの構文は次のとおりです：

```sql
/*+ NO_PLACE_GROUP_BY [ ( @queryblock ) ] */
```

`NO_PLACE_GROUP_BY` ヒントの例は次のとおりです：

```sql
SELECT /*+NO_PLACE_GROUP_BY*/SUM(t1.c),SUM(t2.c) FROM t1, t2
WHERE t1.a = t2.a AND t1.b > 10 AND t2.b > 10
GROUP BY t1.a;
```

## NO_PRED_DEDUCE ヒント

`NO_PRED_DEDUCE` ヒントは、オプティマイザーに対し、述語導出変換ルールを使用しないよう指示するために使用されます。

`NO_PRED_DEDUCE` ヒントの構文は次のとおりです：

```sql
/*+ NO_PRED_DEDUCE [ ( @queryblock ) ] */
```

`NO_PRED_DEDUCE` ヒントの例は次のとおりです：

```sql
SELECT /*+NO_PRED_DEDUCE(@qb1)*/ *
FROM  (
  SELECT /*+no_merge qb_name(qb1)*/ t1.a, t2.b
  FROM t1, t2
  WHERE t1.a = t2.a) v, t3
WHERE t3.a = 1 AND t3.a = v.a;
```
