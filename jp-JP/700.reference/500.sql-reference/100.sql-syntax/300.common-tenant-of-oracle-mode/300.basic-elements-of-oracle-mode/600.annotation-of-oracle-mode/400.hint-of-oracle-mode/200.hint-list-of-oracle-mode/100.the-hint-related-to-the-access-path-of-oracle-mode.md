# アクセスパスに関連するヒント

アクセスパスに関連するヒントには、INDEXヒントとFULLヒントが含まれます。

## INDEXヒント

`INDEX` ヒントは、オプティマイザーに対して指定されたテーブルに対してインデックススキャンを使用するよう指示します。`INDEX` ヒントは、関数、ドメイン、B-Tree、ビットマップ、およびビットマップ結合に基づくインデックスに使用できます。

`INDEX` ヒントの構文は次のとおりです：

```sql
/*+ INDEX ( [ @queryblock ] tablespec [ indexspec [ indexspec ]... ] ) */
```

ヒントの動作は `indexspec` スペックによって決まります：

* `INDEX` ヒントが単一の利用可能なインデックスを指定した場合、データベースはそのインデックスに対してスキャンを実行します。オプティマイザーは、フルテーブルスキャンやテーブル上の別のインデックスのスキャンを検討しません。

* `INDEX` ヒントが利用可能なインデックスのリストを指定した場合、オプティマイザーはリスト内の各インデックスのスキャンコストを検討し、最も低いコストでインデックススキャンを実行します。データベースがこのリストから複数のインデックスをスキャンし、結合されたアクセスパスのコストが最も低い場合、データベースはこのスキャン方式を選択します。データベースは、リストにないインデックスに対するフルテーブルスキャンやスキャンを検討しません。

* `INDEX` ヒントで具体的なインデックスが指定されていない場合、オプティマイザーはテーブル上の各利用可能なインデックスのスキャンコストを検討し、最も低いコストでインデックススキャンを実行します。データベースが複数のインデックスをスキャンし、結合されたアクセスパスのコストが最も低い場合、データベースはこのスキャン方式を選択します。オプティマイザーはフルテーブルスキャンを検討しません。

`INDEX` ヒントの例は次のとおりです：

```sql
SELECT /*+ INDEX (employees emp_department_ix)*/ employee_id, department_id
FROM employees
WHERE department_id > 50;
```

## FULLヒント

`FULL` ヒントは、オプティマイザーに対して指定されたテーブルに対してフルテーブルスキャンを実行するよう指示します。

`FULL` ヒントの構文は次のとおりです：

```sql
/*+ FULL ( [ @queryblock ] tablespec ) */
```

`FULL` ヒントの例は次のとおりです：

```sql
SELECT /*+ FULL(e) */ employee_id, last_name
FROM hr.employees e
WHERE last_name LIKE :al;
```

例では、データベースは `WHERE` 句の条件によって提供される `last_name` 列のインデックスがある場合でも、テーブル `employees` に対して完全なテーブルスキャンを実行してこのステートメントを実行します。

`FROM` 句では、テーブル `employees` には別名 `e` があります。そのため、ヒントはテーブルの名前ではなく別名に基づいてテーブルを参照する必要があります。`FROM` 句でスキーマ名が指定されている場合でも、ヒントでそれらを参照しないでください。
