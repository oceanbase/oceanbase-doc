# 接続操作に関連するヒント

接続操作に関連するヒントには、USE_MERGEヒント、NO_USE_MERGEヒント、USE_HASHヒント、NO_USE_HASHヒント、USE_NLヒント、NO_USE_NLヒント、USE_BNLヒント、およびNO_USE_BNLヒントが含まれます。

## USE_MERGE ヒント

`USE_MERGE` ヒントは、オプティマイザーに対し、指定された各テーブルを別の行リソースと `sort-merge` 接合で結合し、指定されたテーブルを右側のテーブルとして使用するよう指示します。

`USE_MERGE` ヒントの構文は次のとおりです：

```sql
/*+ USE_MERGE ( [ @queryblock ] tablespec [ tablespec ]... ) */
```

`USE_NL` および `USE_MERGE` ヒントは、`LEADING` または `ORDERED` ヒントと一緒に使用することを推奨します。参照されるテーブルが結合の右側のテーブルの場合、オプティマイザーはこれらのヒントを使用します。参照されるテーブルが左側のテーブルの場合、ヒントは無視されます。`USE_MERGE` は、テーブルを右側のテーブルとして指定した場合に `MERGE JOIN` アルゴリズムを使用するようにします。OceanBaseデータベースでは、`MERGE JOIN` アルゴリズムを使用する際には、等価条件のある `join-condition` が必要であるため、等価条件のない2つのテーブルを結合する場合、`USE_MERGE` は無効です。

`USE_MERGE` ヒントの例は次のとおりです：

```sql
SELECT /*+ USE_MERGE(employees departments) */ *
FROM employees, departments
WHERE employees.department_id = departments.department_id;
```

## NO_USE_MERGE ヒント

`NO_USE_MERGE` ヒントは、指定されたテーブルを内部テーブルとして使用し、別の行リソースに並列結合する際に、`USE_MERGE` ヒントで使用される結合を除外するようオプティマイザーに指示します。

`NO_USE_MERGE` ヒントの構文は次のとおりです：

```sql
/*+ NO_USE_MERGE ( [ @queryblock ] tablespec [ tablespec ]... ) */
```

`NO_USE_MERGE` ヒントの例は次のとおりです：

```sql
SELECT /*+ NO_USE_MERGE(e d) */ *
FROM employees e, departments d
WHERE e.department_id = d.department_id;
```

## USE_HASH ヒント

`USE_HASH` ヒントは、オプティマイザーに対し、指定された各テーブルを別の行リソースとHASH-JOINアルゴリズムで結合し、指定されたテーブルを右側のテーブルとして使用するよう指示します。

`USE_HASH` ヒントの構文は次のとおりです：

```sql
/*+ USE_HASH ( [ @queryblock ] tablespec [ tablespec ]... ) */
```

`USE_HASH` ヒントの例は次のとおりです：

```sql
SELECT /*+ USE_HASH(l h) */ *
  FROM orders h, order_items l
  WHERE l.order_id = h.order_id
    AND l.order_id > 2400;
```

## NO_USE_HASH ヒント

`NO_USE_HASH` ヒントは、指定されたテーブルを内部テーブルとして使用し、別の行リソースに並列結合する際に、`USE_HASH` ヒントで使用される結合を除外するようオプティマイザーに指示します。

`NO_USE_HASH` ヒントの構文は次のとおりです：

```sql
/*+ NO_USE_HASH ( [ @queryblock ] tablespec [ tablespec ]... ) */
```

`NO_USE_HASH` ヒントの例は次のとおりです：

```sql
SELECT /*+ NO_USE_HASH(e d) */ *
FROM employees e, departments d
WHERE e.department_id = d.department_id;
```

## USE_NL ヒント

`USE_NL` ヒントは、オプティマイザーに対し、指定された各テーブルを別の行リソースにネストループ結合で結合するよう指示します。また、指定されたテーブルを内部テーブルとして使用し、NL-JOINアルゴリズムを適用します。

`USE_NL` ヒントの構文は次のとおりです：

```sql
/*+ USE_NL ( [ @queryblock ] tablespec [ tablespec ]... ) */
```

`USE_NL` ヒントと `USE_MERG` ヒントは、`LEADING` または `ORDERED` ヒントと一緒に使用することを推奨します。参照されるテーブルが結合の内部テーブルの場合、オプティマイザーはこれらのヒントを使用します。参照されるテーブルが外部テーブルの場合、ヒントは無視されます。

以下の例では、ヒントによりネストループが強制的に実行され、`orders` テーブルに対してフルスキャンが行われ、フィルター条件 `l.order_id = h.order_id` が各行に適用されました。フィルター条件を満たす各行について、インデックス `order_id` を使用して `order_items` にアクセスします。

```sql
SELECT /*+ USE_NL(l h) */ h.customer_id, l.unit_price * l.quantity
FROM orders h, order_items l
WHERE l.order_id = h.order_id;
```

## NO_USE_NL ヒント

`NO_USE_NL` ヒントは、オプティマイザーに対し、指定されたテーブルを内部テーブルとして使用して別の行リソースに結合する際に、Nest-Loop結合を除外するよう指示します。

`NO_USE_NL` ヒントの構文は次のとおりです：

```sql
/*+ NO_USE_NL ( [ @queryblock ] tablespec [ tablespec ]... ) */
```

`NO_USE_NL` ヒントの例は次のとおりです：

```sql
SELECT /*+ NO_USE_NL(e d) */ *
FROM employees e, departments d
WHERE e.department_id = d.department_id;
```

## USE_BNL ヒント

`USE_BNL` ヒントは、オプティマイザーに対し、指定された各テーブルを別の行リソースにブロックネストループ結合で結合するよう指示します。また、指定されたテーブルを内部テーブルとして使用し、BNL-JOINアルゴリズムを適用します。

`USE_BNL` ヒントの構文は次のとおりです：

```sql
/*+ USE_BNL ( [ @queryblock ] tablespec [ tablespec ]... ) */
```

`USE_BNL` ヒントは、`LEADING` または `ORDERED` ヒントと一緒に使用することを推奨します。参照されるテーブルが結合の内部テーブルの場合、オプティマイザーはこれらのヒントを使用します。参照されるテーブルが外部テーブルの場合、ヒントは無視されます。

```sql
SELECT /*+ USE_BNL(l h) */ h.customer_id, l.unit_price * l.quantity
FROM orders h, order_items l
WHERE l.order_id = h.order_id;
```
