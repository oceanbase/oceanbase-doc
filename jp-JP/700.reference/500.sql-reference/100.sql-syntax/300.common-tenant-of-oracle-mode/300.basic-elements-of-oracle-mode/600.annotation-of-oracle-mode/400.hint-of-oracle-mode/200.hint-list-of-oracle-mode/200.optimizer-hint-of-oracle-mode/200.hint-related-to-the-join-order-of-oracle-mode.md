# Optimized ヒントの種類のJoin Order Hint

SQLクエリにおいて、結合順序に関連するヒントには、`ORDERED` ヒントと`LEADING` ヒントがあります。

| ヒントの種類 | 説明                                             |
|-----------|-------------------------------------------------|
| `LEADING`   | ヒントで指定されたテーブルの順序で結合します。`FROM` 句内で一部のテーブルのみを指定した場合、指定されたテーブルが駆動表として他のテーブルと結合します。    |
| `ORDERED`   | `FROM` 句の順序でテーブルを結合します。                 |

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p><code>LEADING</code> ヒントを使用して、希望する結合順序を明示することを推奨します。<code>ORDERED</code> ヒントは特定の結合順序のみを指定でき、かつ結合順序はリライトの影響を受けるためです。</p>
</main>

## `LEADING` Hint

`LEADING` ヒントは、オプティマイザーに対して指定された順序でテーブルを結合するよう指示します。`ORDERED` ヒントよりも柔軟性が高く、`LEADING` Hintでは有効な結合順序の中から任意の順序を明示的に定義できます。一方、`ORDERED` ヒントは特定の結合順序のみを指定でき、かつ結合順序はリライトの影響を受けます。希望する結合順序を明示するには、`LEADING` ヒントの使用を推奨します。

### 構文

```sql
/*+ LEADING ( [ @queryblock ] tablespec [ tablespec ]...  ) */
```

### 使用方法と注意事項

`LEADING` ヒントは、指定されたテーブル名がクエリ内に現れるテーブル名と完全に一致する場合にのみ有効になります。

* ヒントで指定された`table_name`が存在しない場合、`LEADING` ヒントは無効になります。

* ヒント内に重複するテーブルがある場合、`LEADING` ヒントは無効になります。

* オプティマイザーが結合処理中に対応するテーブルを見つけられない場合、そのテーブル以降に指定された結合順序は無効になりますが、そのテーブルより前に指定された順序は引き続き有効です。

* 結合グラフ内の依存関係により、指定された順序で最初に指定されたテーブルを結合できない場合、`LEADING` ヒントは無効になります。

* 互いに競合する2つ以上の`LEADING` ヒントを指定した場合、`LEADING` ヒントは無効になります。

* `ORDERED` ヒントを指定した場合、それがすべての`LEADING` ヒントを上書きします。

### 例

```SQL
SELECT /*+ LEADING(e j) */ *
FROM employees e, departments d, job_history j
WHERE e.department_id = d.department_id
  AND e.hire_date = j.start_date;
```

## `ORDERED` ヒント

クエリでデフォルトの結合順序を使用します。`ORDERED` ヒントの優先順位は `LEADING` ヒントよりも高く、`ORDERED` ヒントが存在する場合、`LEADING` ヒントは無効になります。
`ORDERED` ヒントを使用する場合、OUTLINE DATAには `ORDERED` ヒントが表示されず、代わりに完全な `LEADING` ヒントが出力されます。

### 構文

```sql
/*+ ORDERED */
```

### 例

`employees`、`departments`、`job_history` の3つのテーブルを結合する必要があると仮定します：

```sql
SELECT /*+ ORDERED */ e.employee_id, d.department_name, j.job_id
FROM employees e, departments d, job_history j
WHERE e.department_id = d.department_id
  AND e.hire_date = j.start_date;
```

この例では、データベースは `employees`、`departments`、`job_history` の順序でこれら3つのテーブルを結合します。
