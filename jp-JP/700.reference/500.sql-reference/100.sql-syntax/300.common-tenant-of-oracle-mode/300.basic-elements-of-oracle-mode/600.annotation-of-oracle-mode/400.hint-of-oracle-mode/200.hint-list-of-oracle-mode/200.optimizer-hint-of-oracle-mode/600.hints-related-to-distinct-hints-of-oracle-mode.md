# Optimized HintタイプのDistinct Hint

Distinct Hintは、`DISTINCT` キーワードを含むクエリを処理する際に、オプティマイザーが特定の動作を取るよう指示するために使用されます。

| Hintタイプ                    | 説明                                                   |
|-----------------------------|--------------------------------------------------------|
| `USE_HASH_DISTINCT`           |  オプティマイザーが `HASH` アルゴリズムを使用して `DISTINCT` 操作を実行するように有効化します。その逆操作は `NO_USE_HASH_DISTINCT` Hintです。  |
| `NO_USE_HASH_DISTINCT`        |  オプティマイザーが `DISTINCT` 操作を実行する際に `HASH` アルゴリズムを使用しないように無効化します。その逆操作は `USE_HASH_DISTINCT` Hintです。  |
| `DISTINCT_PUSHDOWN`           |  オプティマイザーに対し、分散環境で `DISTINCT` プッシュダウンを許可するよう指示します。その逆操作は `NO_DISTINCT_PUSHDOWN` Hintです。  |
| `NO_DISTINCT_PUSHDOWN`        |  オプティマイザーに対し、分散環境で `DISTINCT` プッシュダウンを禁止するよう指示します。その逆操作は `DISTINCT_PUSHDOWN` Hintです。  |

## `USE_HASH_DISTINCT` Hint

`USE_HASH_DISTINCT` Hintは、オプティマイザーが `HASH` アルゴリズムを使用して `DISTINCT` 操作を実行するように有効化します。その逆操作は `NO_USE_HASH_DISTINCT` Hintです。

### 構文

```sql
/*+ USE_HASH_DISTINCT [ ( [ @ qb_name ] ) ] */
```

### 例

以下のクエリ例では、`USE_HASH_DISTINCT` を使用して `HASH` 重複除去アルゴリズムを有効にします。

```sql
-- `USE_HASH_DISTINCT` ヒントを使用して、クエリが `DISTINCT` 操作を実行する際に `HASH` アルゴリズムを採用するようにする
EXPLAIN BASIC SELECT /*+ USE_HASH_DISTINCT */ DISTINCT c1, c2, c3 FROM t1;

| Outputs & filters:                                                |

|   0 - output([T1.C1], [T1.C2], [T1.C3]), filter(nil), rowset=16   |
```

## `NO_USE_HASH_DISTINCT` Hint

`NO_USE_HASH_DISTINCT` Hintは、distinct操作で使用される具体的なアルゴリズムを無効にします。その逆操作は `USE_HASH_DISTINCT` Hintです。

### 構文

```sql
/*+ NO_USE_HASH_DISTINCT [ ( [ @ qb_name ] ) ] */
```

### 例

以下のクエリ例では、`NO_USE_HASH_DISTINCT` を使用して、オプティマイザーが `DISTINCT` 操作を実行する際の `HASH` アルゴリズムの使用を無効にします。OceanBaseは `HASH` と `MERGE` の2種類の重複除去アルゴリズムをサポートしているため、`NO_USE_HASH_DISTINCT` Hintを使用すると、実質的にはMERGE重複除去アルゴリズムが使用されます。

```sql
-- `NO_USE_HASH_DISTINCT` ヒントを使用して、クエリが `DISTINCT` 操作を実行する際に `HASH` アルゴリズムを使用せず、代わりに `MERGE` アルゴリズムを使用するようにします。
EXPLAIN BASIC SELECT /*+ NO_USE_HASH_DISTINCT */ DISTINCT c1, c2, c3 FROM t1;
+-------------------------------------------------------------------+
| Query Plan                                                        |
+-------------------------------------------------------------------+
| =============================                                     |
| |ID|OPERATOR           |NAME|                                     |
| -----------------------------                                     |
| |0 |MERGE DISTINCT     |    |                                     |
| |1 |└─SORT             |    |                                     |
| |2 |  └─TABLE FULL SCAN|T1  |                                     |
| =============================                                     |
| Outputs & filters:                                                |
| -------------------------------------                             |
|   0 - output([T1.C1], [T1.C2], [T1.C3]), filter(nil), rowset=16   |
|       distinct([T1.C1], [T1.C2], [T1.C3])                         |
|   1 - output([T1.C1], [T1.C2], [T1.C3]), filter(nil), rowset=16   |
|       sort_keys([T1.C1, ASC], [T1.C2, ASC], [T1.C3, ASC])         |
|   2 - output([T1.C1], [T1.C2], [T1.C3]), filter(nil), rowset=16   |
|       access([T1.C1], [T1.C2], [T1.C3]), partitions(p0)           |
|       is_index_back=false, is_global_index=false,                 |
|       range_key([T1.__pk_increment]), range(MIN ; MAX)always true |
+-------------------------------------------------------------------+
```

## `DISTINCT_PUSHDOWN` Hint

`DISTINCT_PUSHDOWN` ヒントは、オプティマイザーに対し、分散実行時に `DISTINCT` 操作のプッシュダウンを行うよう指示します。これにより、各パーティションノードでローカルな重複除去処理を先行させることが可能になります。その逆操作は `NO_DISTINCT_PUSHDOWN` ヒントです。

### 構文

```sql
/*+ DISTINCT_PUSHDOWN [ ( [ @ qb_name ] ) ] */
```

### 例

以下のクエリ例では、`DISTINCT_PUSHDOWN` を使用して分散実行時の `DISTINCT` 操作のプッシュダウンを有効にしています。ヒントを追加しない場合、デフォルトで `DISTINCT` のプッシュダウンが行われます。

```sql
-- `DISTINCT_PUSHDOWN` ヒントを使用して、分散クエリで `DISTINCT` 操作を各パーティションノードにプッシュダウンする
CREATE TABLE tp1(c1 INT, c2 INT, c3 INT) PARTITION BY HASH(c1) PARTITIONS 10;
EXPLAIN BASIC SELECT /*+ DISTINCT_PUSHDOWN */ DISTINCT c2, c3 FROM tp1;
+---------------------------------------------------------------------------+
| Query Plan                                                                |
+---------------------------------------------------------------------------+
| ===============================================                           |
| |ID|OPERATOR                         |NAME    |                           |
| -----------------------------------------------                           |
| |0 |PX COORDINATOR                   |        |                           |
| |1 |└─EXCHANGE OUT DISTR             |:EX10001|                           |
| |2 |  └─HASH DISTINCT                |        |                           |
| |3 |    └─EXCHANGE IN DISTR          |        |                           |
| |4 |      └─EXCHANGE OUT DISTR (HASH)|:EX10000|                           |
| |5 |        └─HASH DISTINCT          |        |                           |
| |6 |          └─PX PARTITION ITERATOR|        |                           |
| |7 |            └─TABLE FULL SCAN    |TP1     |                           |
| ===============================================                           |
| Outputs & filters:                                                        |
| -------------------------------------                                     |
|   0 - output([INTERNAL_FUNCTION(TP1.C2, TP1.C3)]), filter(nil), rowset=16 |
|   1 - output([INTERNAL_FUNCTION(TP1.C2, TP1.C3)]), filter(nil), rowset=16 |
|       dop=1                                                               |
|   2 - output([TP1.C2], [TP1.C3]), filter(nil), rowset=16                  |
|       distinct([TP1.C2], [TP1.C3])                                        |
|   3 - output([TP1.C2], [TP1.C3]), filter(nil), rowset=16                  |
|   4 - output([TP1.C2], [TP1.C3]), filter(nil), rowset=16                  |
|       (#keys=2, [TP1.C2], [TP1.C3]), dop=1                                |
|   5 - output([TP1.C2], [TP1.C3]), filter(nil), rowset=16                  |
|       distinct([TP1.C2], [TP1.C3])                                        |
|   6 - output([TP1.C2], [TP1.C3]), filter(nil), rowset=16                  |
|       force partition granule                                             |
|   7 - output([TP1.C2], [TP1.C3]), filter(nil), rowset=16                  |
|       access([TP1.C2], [TP1.C3]), partitions(p[0-9])                      |
|       is_index_back=false, is_global_index=false,                         |
|       range_key([TP1.__pk_increment]), range(MIN ; MAX)always true        |
+---------------------------------------------------------------------------+
```

## `NO_DISTINCT_PUSHDOWN` ヒント

`NO_DISTINCT_PUSHDOWN` ヒントは、オプティマイザーが分散実行時に `DISTINCT` 操作のプッシュダウンを行うことを禁止します。その逆操作は `DISTINCT_PUSHDOWN` ヒントです。

### 構文

```sql
/*+ NO_DISTINCT_PUSHDOWN [ ( [ @ qb_name ] ) ] */
```

### 例

以下のクエリ例では、`NO_DISTINCT_PUSHDOWN` を使用して分散実行時の `DISTINCT` 操作のプッシュダウンを禁止しています。
