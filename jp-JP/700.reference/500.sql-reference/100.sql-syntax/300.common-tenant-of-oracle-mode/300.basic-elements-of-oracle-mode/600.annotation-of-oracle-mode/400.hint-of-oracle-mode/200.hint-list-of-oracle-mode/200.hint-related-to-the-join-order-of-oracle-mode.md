# 接続順序に関連するヒント

接続順序に関連するヒントには、ORDEREDヒントとLEADINGヒントが含まれます。

## ORDEREDヒント

`ORDERED` ヒントは、データベースに対し、テーブルを `FROM` 句に記述された順序で結合するよう指示します。
  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p><code>LEADING</code> ヒントの方が一般的であるため、<code>ORDERED</code> ヒントの使用は推奨されません。</p>
  </main>

`ORDERED` ヒントの構文は次のとおりです：

```sql
/*+ ORDERED */
```

結合するSQLステートメントから `ORDERED` ヒントを省略した場合、オプティマイザーが結合するテーブルの順序を選択します。オプティマイザーが各テーブルから選択する行数を把握していない場合は、`ORDERED` ヒントを使用して結合順序を指定できます。これにより、オプティマイザーよりも内部テーブルと外部テーブルを適切に選択できます。この `ORDERED` ヒントを指定した後にリライトが発生した場合、リライト後のステートメントの `FROM` 句の順序でテーブルを結合します。

## LEADINGヒント

`LEADING` ヒントは、オプティマイザーに対し、実行計画内で指定されたテーブルをドライバーテーブルとして使用し、テーブルの結合順序を指定するよう指示します。`LEADING` ヒントは `ORDERED` ヒントよりも一般的です。

`LEADING` ヒントの構文は次のとおりです：

```sql
/*+ LEADING ( [ @queryblock ] tablespec [ tablespec ]...  ) */
```

`LEADING` ヒントは、ユーザーが指定した順序でテーブルを結合することを保証するため、厳密なチェックが行われます。ルールは以下のとおりです：

* ヒントで指定された `table_name` が存在しない場合、`LEADING` ヒントは無効になります。

* ヒントに重複するテーブルが存在する場合、`LEADING` ヒントは無効になります。

* オプティマイザーが結合中に対応するテーブルを見つけられない場合、そのテーブル以降のテーブルで指定された結合順序は無効になり、そのテーブルより前に指定された順序は引き続き有効です。

* 結合グラフ内の依存関係により、指定された順序で最初に指定されたテーブルを結合できない場合、`LEADING` ヒントは無効になります。

* 2つ以上の競合する `LEADING` ヒントが指定されている場合、`LEADING` ヒントは無効になります。

* `ORDERED` ヒントを指定した場合、それがすべての `LEADING` ヒントを上書きします。

`LEADING` ヒントの例は次のとおりです：

```sql
SELECT /*+ LEADING(e j) */ *
    FROM employees e, departments d, job_history j
    WHERE e.department_id = d.department_id
      AND e.hire_date = j.start_date;
```
