# スキーマオブジェクトの参照

SQLステートメントでオブジェクトを参照する際、OceanBaseデータベースはSQLステートメントのコンテキストを考慮し、ネームスペース内でそのオブジェクトを見つけます。その後、指定された操作を実行します。ネームスペース内で参照されるオブジェクトが見つからない場合、エラーが返されます。

## ユーザースキーマのオブジェクトの参照

本記事では、具体的な例を通じてOceanBaseデータベースがSQLステートメント内のオブジェクトの参照をどのように解釈するかを説明します。

次のSQLステートメントを実行して、`departments`という名前のテーブルに1行のデータを追加します：

```sql
INSERT INTO departments
VALUES (280, 'ENTERTAINMENT_CLERK', 206, 1700);
```

SQLステートメントのコンテキストに基づいて、`departments`データベース内では以下のいずれかの場合が考えられます：

* 自分のスキーマ内のテーブル

* 自分のスキーマ内のビュー

* テーブルまたはビューの専用シノニム

* 公開シノニム

OceanBaseデータベースはまず、自分のスキーマ内のネームスペースで参照されるオブジェクトを解釈しようとします。次に、そのスキーマ以外のネームスペースを検討します。この例では、OceanBaseデータベースの解釈プロセスは以下のようになります：

1. OceanBaseデータベースはまず、自分のスキーマのネームスペース内でオブジェクトを特定しようとします。オブジェクトが専用シノニムである場合、OceanBaseデータベースはそのシノニムが表すオブジェクトを見つけることができます。このオブジェクトは自分のスキーマ内にある場合もありますが、他のスキーマ内や別のデータベース内でもあり得ます。また、このオブジェクトは他のシノニムである場合もあり、その場合は、OceanBaseデータベースはそのシノニムが表すオブジェクトを見つけることができます。

2. オブジェクトがネームスペース内で見つかった場合、OceanBaseデータベースはそのオブジェクトに対してSQLステートメントを実行しようとします。この例では、OceanBaseデータベースは`departments`に1行のデータを追加しようとします。このオブジェクトのタイプがSQLステートメントで必要なタイプではない場合、OceanBaseデータベースはエラーを返します。この例では、`departments`はテーブル、ビュー、またはテーブルまたはビューに解決できる専用シノニムでなければなりません。もし`departments`がシーケンスである場合、OceanBaseデータベースはエラーを返します。

3. この時点で、どのネームスペースでもオブジェクトが見つからない場合、OceanBaseデータベースは公開シノニムを含むネームスペースを検索します。オブジェクトが公開シノニムを含むネームスペースにある場合、OceanBaseデータベースはそのオブジェクトに対してSQLステートメントを実行しようとします。このオブジェクトのタイプがSQLステートメントで必要なタイプではない場合、OceanBaseデータベースはエラーを返します。この例では、`departments`がシーケンスを表す公開シノニムである場合、OceanBaseデータベースはエラーを返します。

公開シノニムが依存するテーブルやユーザー定義型を含む場合、依存するオブジェクトと同じスキーマ内に同名のオブジェクトを作成することはできません。

逆に、シノニムが依存するテーブルやユーザー定義の型がない場合、依存するオブジェクトと同じスキーマ内に同じ名前のオブジェクトを作成することができます。OceanBaseデータベースはすべての依存オブジェクトを無効にし、次回アクセス時に再検証を行います。

## 他のスキーマ内のオブジェクトの参照

参照するオブジェクトが他のスキーマに属する場合、オブジェクトの名前に対応するスキーマ名を追加する必要があります。構文は以下のとおりです：

```sql
schema.object
```

次の例は、`hr`という名前のスキーマ内で`employees`テーブルを削除する方法を示しています：

```sql
DROP TABLE hr.employees;
```
