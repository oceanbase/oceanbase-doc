# 弱い一貫性の読み取り

本記事では、OceanBaseデータベースにおける弱い一貫性の読み取りを行うための最適な推奨事項について説明します。

バッチ処理や統計処理など、リアルタイム性の要件がそれほど高くないアプリケーションにおいては、プライマリレプリカへの影響を避けるために、弱い一貫性の読み取りを設定できます。セッションレベルまたは弱い一貫性の読み取りのヒントを設定し、読み取り操作をスタンバイレプリカで実行します。

* SELECTクエリステートメントにヒントを追加

  ```sql
  SELECT /*+read_consistency(weak)*/ * FROM test WHERE c1=1;
  ```

* セッションレベルでシステム変数を設定(1=FROZEN、2=WEAK、3=STRONG)

  ```sql
  SET @@ob_read_consistency= 2;
  ```

* リピータブルリードとシリアライズ可能な分離レベルでは、弱い読み取りリクエストの実行がサポートされています。例は以下のとおりです。

  ```sql
  obclient> SET transaction read only;
  Query OK, 0 rows affected (0.001 sec)
  obclient> SELECT /*+ read_consistency(weak)*/ * FROM t WHERE a=2;
  +------+------+
  | ID   | A    |
  +------+------+
  | NULL |    2 |
  +------+------+
  1 row in set (0.001 sec)
  ```

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>シリアライズ可能な分離レベルでは、トランザクション開始後にトランザクションスナップショットが保持され、トランザクションコミット後にスナップショットが回収されます。そのため、シリアライズ可能な分離レベルでは、トランザクションを適時にコミットすることが重要です。そうしない場合、ディスク使用量の増加や読み取り速度の低下といった問題が発生する可能性があります。</p>
  </main>
