# CREATE TYPE

`CREATE TYPE`は、新しいユーザー定義データ型（UDT）を定義するために使用されます。`CREATE TYPE`を使用して、型の名前とそのプロパティ、メソッド、およびその他のプロパティを指定できます。

  <main id="notice" >
    <h4>適用対象</h4>
    <p>この内容はOceanBaseデータベースEnterprise Editionにのみ適用されます。OceanBaseデータベースCommunity EditionはMySQLモードのみを提供します。</p>
  </main>

`CREATE TYPE`は、次のスキーマを作成または置き換えることを宣言します：

* 抽象データ型（ADT）

  + 例えば、データベース内で構造化されたプロパティを持ち、メソッドとしてカプセル化する必要がある複雑なデータを表現したい場合は、抽象データ型を作成できます。例えば、住所や従業員を表すADTを作成できます。

* 独立変数配列（VARRAY）タイプ

  + 例えば、固定された上限を持つ配列を表現し、その配列全体をストレージおよび検索する必要がある場合は、VARRAYタイプを定義できます。

* 独立ネストテーブルタイプ

  + 例えば、同じ種類のデータの無限の集合を保存およびアクセスし、その集合内の各項目が無秩序である場合は、ネストテーブルタイプを使用できます。

* 不完全オブジェクトタイプ

  不完全タイプとは、フォワードタイプ定義によって作成されるタイプです。不完全と呼ばれるのは、名前はありますが、プロパティやメソッドがないためです。他のタイプから参照されることができ、相互に参照するタイプをカスタマイズできます。ただし、完全なタイプを作成してから、テーブルの列、オブジェクトの列、またはネストテーブルタイプの列を作成するために使用できます。例えば、不完全タイプは通常、タイプ間の相互参照が予想される場合に作成されます。最初に、不完全タイプをプレースホルダーとして宣言し、その後、参照タイプの定義が完了したら、不完全タイプをさらに定義します。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>オブジェクト型の形式パラメータのデフォルト値は、非決定的なデフォルト値をサポートします。</p>
</main>

`CREATE TYPE BODY`は、その型の実装コードを自動的に生成することを宣言します。つまり、作成した型にメソッドが含まれている場合は、CREATE TYPE BODYステートメントを使用してこれらのメソッドの実装コードも提供する必要があります。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <ul>
    <li>作成した型のスキーマがメソッドを宣言せずにプロパティのみを宣言している場合、Bodyを作成する必要はありません。</li>
    <li>CREATE TYPEステートメントを使用して、ネストテーブル（Nested Table）と可変配列（VARRAY）タイプを作成できますが、関連付けられた配列は作成できません。PLブロックまたはパッケージでは、3種類の集合型を定義できます。</li>
    </ul>
  </main>

## 前提条件

スキーマ内で型を作成するには、`CREATE TYPE` のシステム権限が必要です。他のユーザーのスキーマ内で型を作成するには、`CREATE ANY TYPE` のシステム権限が必要です。これらの権限は直接付与することも、ロールを通じて付与することもできます。

その型の定義で参照されるすべての他の型にアクセスするために、その型の所有者には明示的に `EXECUTE` オブジェクト権限を付与する必要があります。または、その型の所有者に `EXECUTE ANY TYPE` のシステム権限を付与する必要があります。所有者はロールを通じてこれらの権限を取得することはできません。

型の所有者が他のユーザーにその型へのアクセス権限を付与しようとする場合、所有者に対してその型の `EXECUTE` オブジェクト権限を `GRANT OPTION` で付与するか、または `ADMIN OPTION` で `EXECUTE ANY TYPE` のシステム権限を付与する必要があります。そうでない場合、型の所有者には他のユーザーにその型へのアクセス権限を付与するための十分な権限がありません。

OceanBaseデータベースの現行バージョンでは、`CREATE TABLE` ステートメントを使用して新しいテーブルを作成する際、独自のオブジェクト型（ユーザー定義オブジェクト型 - UDTとも呼ばれる）を定義できますが、これらのカスタム型はデータベース テーブルの列のデータ型として使用できません。つまり、これらのUDTをテーブル構造の一部として直接使用することはできません。例えば、列を作成してその型を直接カスタムのオブジェクト型として指定することはできません。

ただし、テーブル作成時にユーザー定義オブジェクト型 (UDT) を使用できなくても、PL/SQLプログラムを作成する際には、カスタムオブジェクト型を使用してプログラム内部で使用する変数、パラメータ、および関数の戻り値型を定義できます。

## 例

### タイプコードの作成例

#### 例1：オブジェクトタイプを作成する

`person_typ` という名前のオブジェクトタイプを作成します。このタイプには、`name` と `age` の2つのプロパティと、オブジェクトの年齢を返すためのメンバ関数 `get_age` が含まれます。

```sql
CREATE TYPE person_typ AS OBJECT (
  name VARCHAR2(50),
  age NUMBER,
  MEMBER FUNCTION get_age RETURN NUMBER);
```

#### 例2：可変長配列(VARRAY)タイプを作成する

`number_list` という名前の `VARRAY` タイプを作成します。これは最大10個の数値を格納できます。

```sql
CREATE TYPE number_list AS VARRAY(10) OF NUMBER;
```

### 完全な使用例

オブジェクトタイプの作成を例に、完全な使用方法を示します。

#### ステップ1：オブジェクトタイプを作成する

まず、オブジェクトタイプとそのメンバ関数を定義する必要があります。ここでは、メンバ関数 `get_age` が単純にオブジェクトの年齢を返すと仮定します。

```sql
CREATE OR REPLACE TYPE person_typ AS OBJECT (
  name VARCHAR2(50),
  age NUMBER,
  MEMBER FUNCTION get_age RETURN NUMBER
);
/
```

```sql
CREATE OR REPLACE TYPE BODY person_typ AS
  MEMBER FUNCTION get_age RETURN NUMBER IS
  BEGIN
    RETURN self.age;
  END get_age;
END;
/
```

#### ステップ2：PL/SQLからオブジェクトタイプを使用する

1. テーブル `people` を作成します。

    ```sql
    CREATE TABLE people (person_id NUMBER, person_name VARCHAR2(50), person_age NUMBER);
    ```

2. PL/SQLプログラム内で、`person_typ` タイプの変数を宣言してこれらのデータを操作できます：

    ```sql
    DECLARE
      v_person person_typ := person_typ('Alice', 30);
    BEGIN
      -- peopleテーブルにデータを挿入
      INSERT INTO people (person_id, person_name, person_age) VALUES (1, v_person.name, v_person.age);
      COMMIT;
    END;
    /
    ```
