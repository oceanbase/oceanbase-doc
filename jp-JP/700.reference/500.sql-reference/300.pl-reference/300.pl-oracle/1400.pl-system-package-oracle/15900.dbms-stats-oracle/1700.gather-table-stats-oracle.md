# GATHER_TABLE_STATS

`GATHER_TABLE_STATS`プロシージャは、テーブルと列の統計情報を収集するために使用されます。

  <main id="notice" >
    <h4>適用対象</h4>
    <p>この内容はOceanBaseデータベースEnterprise Editionにのみ適用されます。OceanBaseデータベースCommunity EditionはMySQLモードのみを提供します。</p>
  </main>

## 構文

```sql
DBMS_STATS.GATHER_TABLE_STATS (
  ownname             VARCHAR2,
  tabname             VARCHAR2,
  partname            VARCHAR2 DEFAULT NULL,
  estimate_percent    NUMBER DEFAULT AUTO_SAMPLE_SIZE,
  block_sample        BOOLEAN  DEFAULT FALSE,
  method_opt          VARCHAR2 DEFAULT DEFAULT_METHOD_OPT,
  degree              NUMBER   DEFAULT to_degree_type(get_param('DEGREE')),
  granularity         VARCHAR2 DEFAULT DEFAULT_GRANULARITY,
  cascade             BOOLEAN DEFAULT NULL,
  no_invalidate       BOOLEAN DEFAULT FALSE,
  no_invalidate       BOOLEAN DEFAULT FALSE,
  stattype            VARCHAR2 DEFAULT 'DATA',
  force               BOOLEAN DEFAULT FALSE,
  hist_est_percent    NUMBER DEFAULT AUTO_SAMPLE_SIZE,
  hist_block_sample   BOOLEAN DEFAULT NULL
  );
```

## パラメータの説明

|        パラメータ       |      説明        |
|------------------|-------------------|
| ownname          | ユーザー名。ユーザー名を `NULL` に設定した場合、現在ログインしているユーザー名がデフォルトで使用されます。   |
| tabname          | テーブル名。       |
| partname         | パーティション名。       |
| estimate_percent | 推定行の割合。有効範囲は \[0.000001,100\] です。   |
| block_sample     | データベースがランダムブロックサンプリング (`TRUE`) を使用するか、ランダム行サンプリング (`FALSE`) を使用するかを決定します。デフォルト値は `FALSE` です。ランダムブロックサンプリングの方が効率は高いですが、データがディスク上にランダムに配置されていない場合、サンプル値に相関性が生じる可能性があります。   |
| method_opt       | グローバル、スキーマ、データベース、または辞書レベルで設定する場合、`FOR ALL` 構文のみを使用できます。それ以外の場合、`method_opt` は以下のオプションのいずれか、またはその組み合わせのみを指定できます： <ul><li> `FOR ALL [INDEXED \| HIDDEN] COLUMNS [size_clause]`   </li>   <li> `FOR COLUMNS [column_clause]`    ここで、`size_clause` は `size_clause := SIZE {integer \| REPEAT \| AUTO \| SKEWONLY}` として定義されます。 `column_clause` は `column_clause := column_name \| extension name \| extension` として定義されます。 </li>   <li> `integer`：ヒストグラムのバケット数。有効範囲は \[1,2048\] です。   </li>   <li> `REPEAT`：既存のヒストグラムがある列のみからヒストグラムを収集します。   </li>   <li> `AUTO`：データの分布と列のワークロードに基づいて、ヒストグラムを収集する列を決定します。   </li>   <li> `SKEWONLY`：列のデータ分布に基づいて、ヒストグラムを収集する列を決定します。   </li>   <li> `column_name`：列名。   </li>   <li> `extension`：`(column_name, colume_name [, ...])` 形式の列グループまたは式を指定できます。    デフォルト値は `FOR ALL COLUMNS SIZE AUTO` です。</li>   </ul> |
| degree           | パラレル度。デフォルト値は `NULL` です。`NULL` は、`CREATE TABLE` または `ALTER TABLE` ステートメント内の `DEGREE` 句で指定されたテーブルのデフォルト値を使用することを意味します。`DEGREE=>NULL`、`DEGREE=>n` を使用する場合、オブジェクトのサイズがパラレル実行を保証しない場合、`DBMS_STATS` はシリアル実行を使用する可能性があります。       |
| granularity      | 収集する統計情報の粒度（テーブルがパーティション化されている場合にのみ適用されます）。 <ul><li> `ALL`：すべて（サブパーティション、パーティション、およびグローバル）の統計情報を収集します。</li> <li> `APPROX_GLOBAL AND PARTITION`： `GLOBAL AND PARTITION` と同様ですが、この場合、グローバル統計情報はパーティションレベルの統計情報の集計です。このオプションは、異なる値の数とインデックスの異なるキーの数以外のすべての統計情報を集計します。ただし、統計情報があるパーティションのみを集計します。`partname` が `NULL` である場合、または集計を実行できない場合（例えば、いずれかのパーティションの統計情報が欠落している場合）、グローバル統計情報が収集されます。   </li> <li> `AUTO`：パーティションタイプに基づいて粒度を決定します。これがデフォルト値です。   </li> <li> `DEFAULT`：グローバルおよびパーティションレベルの統計情報を収集します。このオプションは廃止されており、代わりに `GLOBAL AND PARTITION` の使用を推奨します。   </li> <li> `GLOBAL`：グローバル統計情報を収集します。   </li> <li> `GLOBAL AND PARTITION`：グローバルおよびパーティションレベルの統計情報を収集します。複合パーティションオブジェクトであっても、サブパーティションレベルの統計情報は収集されません。   </li> <li> `PARTITION`：パーティションレベルの統計情報を収集します。   </li> <li> `SUBPARTITION`：サブパーティションレベルの統計情報を収集します。</li>  </ul>  |
| cascade          | テーブルと列の統計情報に加えて、インデックスに関する統計情報も収集します。これは、スキーマ内の各インデックスに対して`GATHER_INDEX_STATS`プロシージャを実行することと同等です。    |
| no_invalidate    | 統計情報を収集する際にPlan Cacheをフラッシュするかどうか。`TRUE`に設定すると、統計情報を収集する際にPlan Cacheをフラッシュしません。   |
| stattype         | 現在の統計情報が格納される場所。 |
| force            | ロック状態を無視して強制的に統計情報を収集するかどうか。デフォルトは`FALSE`です。`TRUE`に設定すると、統計情報がロックされていても収集されます。  |
| hist_est_percent | ヒストグラムのサンプリング率を指定します。|
| hist_block_sample | ヒストグラムのサンプリング方法を指定します。|

## 異常時の対応

|    エラーコード    |     説明     |
|-----------|------------|
| ORA-20000 | テーブルが存在しないか、権限が不足しています。 |
| ORA-20001 | 入力値が誤っています。     |

## 使用方法

このプロシージャを呼び出すには、テーブルの所有者である必要があります。`SYS` が所有するオブジェクトを使用する場合は、テーブルの所有者または `SYSDBA` 権限を持っている必要があります。

値が `TRUE` および `FALSE` のパラメータについては、`BEGIN ... END` ブロック内でこのプロシージャを実行する必要があることに注意してください。

## 例

ユーザー `testUser01` の `tbl1` テーブルの統計情報を収集します。

```sql
obclient> BEGIN
            DBMS_STATS.GATHER_TABLE_STATS('testUser01', 'tbl1', method_opt=>'FOR ALL COLUMNS SIZE 5', granularity=>'ALL', degree=>4, no_invalidate=>FALSE);
         END;
Query OK, 0 rows affected
```
