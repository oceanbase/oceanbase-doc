# ステートメント情報の収集とSQL文に対する並列処理への影響

OceanBaseデータベースはコンパイル時に、ステートメント内にDML文やパッケージ変数の読み書きが含まれるかどうかなどの要素を収集します。これらの情報は主にネストされたシナリオで、UDF(User-Defined Functions)またはトリガーを含むDML文が並列実行を必要とするかどうかを判断するために使用されます。

  <main id="notice" >
    <h4>適用対象</h4>
    <p>この内容はOceanBaseデータベースEnterprise Editionにのみ適用されます。OceanBaseデータベースCommunity EditionはMySQLモードのみを提供しています。</p>
  </main>

ステートメントでは以下の情報が収集されます：

* ステートメント内部に読み書きSQL文(DML/DDL/TCL文を含む)が存在するかどうかを分析します。
* ステートメント内部にパッケージ変数の読み書きが存在するかどうかを分析します。
* ステートメント内部にシーケンスが存在するかどうかを分析します。
* ステートメント内部で他のステートメントにアクセスします。

## UDF/トリガー関連DML文の並列実行に関する説明

UDF/トリガー関連DML文の並列実行時、対応するステートメントに並列処理への影響要因が存在する場合、自動的に並列処理を禁止し、直列実行に切り替えます。同時に、`parallel_enable`句を使用してUDFの並列実行機能を強制的に有効にすることも可能です。ユーザーがUDFを作成する際に`parallel_enable`句を指定し、そのUDFに関連付けられたPDML文がある場合、UDF内部に並列処理への影響要因が存在するかどうかに関係なく、強制的に並列実行されます。

以下の一般的なPDMLトリガーUDF/トリガー実行時、並列実行は直列実行に変更されます：

* PDML文がトリガーするUDFまたはトリガー内部にDML文が存在する場合。
* PDML文がトリガーするUDFまたはトリガー内部に`SELECT`文が存在する場合。
* PDML文がトリガーするUDFまたはトリガー内部にパッケージ変数の読み書きが存在し、外部ステートメントまたはグローバルオブジェクトにアクセスする場合。

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>並列クエリ文が関連付けるUDF内部にSELECT文のみが含まれている場合、並列実行を許可します。</p>
  </main>

SQL文がトリガーするUDF(トリガー)については、以下の制限があります：

* 外層のSQL文がクエリまたはDML文の場合、UDFはトランザクションを終了したり、セーブポイントを作成またはロールバックしたり、`ALTER SYSTEM`/`ALTER SESSION`を実行したりすることはできません。
* 外層のSQLがDML文の場合、UDF内部では同一のテーブルを読み書きすることはできません。

上記の制限は、PLからの呼び出し、関数本体への直接埋め込み、`EXECUTE IMMEDIATE`文を使用した実行、または`DBMS_SQL`パッケージを使用した実行に関わらず適用されます。
