# EVENT

イベント（EVENT）とは、特定の時点または指定された時間間隔で自動的に実行されるように事前に定義されたSQLタスクです。各イベントは、トリガー条件（つまりスケジューリング計画）、実行するSQL文またはストアドプロシージャで構成されています。イベントの定義はデータベースに保存され、データベースとともにメンテナンスされるため、サーバー再起動後でもイベントが計画通りに実行されることを保証します。

トリガーとは異なり、トリガーはデータ操作に基づいてSQL実行をトリガーしますが、イベントは時間の変化に基づいてSQL実行をトリガーします。これにより、ユーザーは設定された時間計画に従ってSQL文やストアドプロシージャを自動的に実行できます。この機能により、データベースの自動処理能力が大幅に向上し、定期的なデータメンテナンス、統計集計、定時通知など、さまざまなシナリオに適しています。

<main id="notice" type='explain'>
  <h4>説明</h4>
  <p>OceanBaseデータベースV4.2.5では、V4.2.5 BP2バージョンから、イベントは<CODE>call</CODE>ステートメントを使用してストアドプロシージャを呼び出すことをサポートし、開始時間または終了時間の設定において時間式と関数をサポートしています。</p>
</main>

**主な特徴**：

* スケジューリングルール：

  * 精確な時間点：特定の時間点でイベントを1回実行するように設定できます。
  * 定期的な実行：秒、分、時間、日、月などの周期で繰り返し実行することをサポートします。
  * 複雑なスケジューリング：<code>EVERY</code>、<code>STARTS</code>、<code>ENDS</code>などのキーワードを組み合わせて使用することで、平日のみ実行、特定の日付範囲内で実行など、複雑なスケジューリングロジックを実現できます。

* SQLサポート：

  * データの挿入、更新、削除を含む、任意の合法的なSQL文を実行できます。
  * トランザクション処理をサポートし、イベント実行の原子性と一貫性を保証します。

* 動的制御：

  * サービスの再起動なしで、実行時にイベントスケジューラーを動的に有効または無効にできます。
  * 既存のイベントを変更または削除でき、ビジネスニーズの変化に対応できます。

## 権限要件

EVENTを使用するには、`GRANT EVENT`権限が必要です。OceanBaseデータベースの権限の詳細については、[MySQLモードの権限分類](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md)を参照してください。

## EVENTの開始と停止

イベントは特殊なイベントスケジューラースレッドによって実行されます。次の方法でイベントスケジューラーを有効または無効にできます。

* イベントスケジューラーを有効にする：

    ```shell
    obclient> SET GLOBAL event_scheduler = ON;
    ```

* イベントスケジューラーを無効にする：

    ```shell
    obclient> SET GLOBAL event_scheduler = OFF;
    ```

## 使用方法と注意点

* `EVERY interval`に`START TIME`を設定しない場合、`END TIME`は無限に実行されます。
* 繰り返しイベントの場合、イベントの実行時間がスケジューリング間隔を超えると、同一時間に複数のイベントが発生します。ユーザー自身が実行時間がスケジューリング間隔未満であることを保証する必要があります。
* 最大実行時間を設定することはできません（単発イベントの最大実行時間は24時間です）。
* 1つのイベントを使用して別のイベントを作成することは推奨されません。
* 既に開始されたイベントは、スケジュール計画を変更することができません。
* 既に開始されたイベントは、`event_name`を変更しないでください。そうしないと、正しく終了できない可能性があります。
* このイベントが連続して16回失敗した場合、実行が停止されます。
