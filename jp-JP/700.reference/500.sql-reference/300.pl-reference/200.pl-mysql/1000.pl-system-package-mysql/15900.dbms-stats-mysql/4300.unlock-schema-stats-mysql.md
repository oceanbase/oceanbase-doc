# UNLOCK_SCHEMA_STATS

`UNLOCK_SCHEMA_STATS` プロシージャは、スキーマ内のすべてのテーブルの統計情報をロック解除します。

## 構文

```sql
DBMS_STATS.UNLOCK_SCHEMA_STATS (
  ownname        VARCHAR2,
  stattype       VARCHAR2 DEFAULT 'ALL');
```

## パラメータの説明

|    パラメータ    |        説明       |
|----------|--------------------|
| ownname  | スキーマの名前。  |
| stattype | ロックのタイプ。一般的には以下の3種類のロックタイプがあります：  <ul><li> `'ALL'` </li>  <li> `'DATA'`   </li>  <li> `'CACHE'` </li>  </ul>  |

## 使用方法

* このプロシージャを呼び出すには、テーブルの所有者である必要があります。`SYS` が所有するオブジェクトの場合、テーブルの所有者であるか、`SYSDBA` 権限を持つ必要があります。

* テーブルの統計情報がロックされている場合、そのテーブルに依存するすべての統計情報、すなわちテーブルレベルの統計情報、列レベルの統計情報、ヒストグラム統計情報、およびすべてのインデックスに依存する統計情報もロックされます。

* オブジェクトの統計情報がロックされている場合、`SET_*`、`DELETE_*`、`IMPORT_*`、`GATHER_*` プロシージャを実行して、単一のテーブル、インデックス、または列の統計情報を変更しようとするとエラーが発生します。

* `UNLOCK_SCHEMA_STATS` プロシージャと `UNLOCK_TABLE_STATS` プロシージャは、対応するパーティションの統計情報をロック解除することはできません。`LOCK_TABLE_STATS` プロシージャを呼び出すと、テーブルレベルでロック位置が設定されます。この場合、パーティションやインデックスなどの依存オブジェクトの統計情報は収集できません。また、テーブルの統計情報がロックされていると、依存オブジェクトも自動的にロックされるため、パーティションの統計情報をロックするために `LOCK_PARTITION_STATS` プロシージャを明示的に呼び出す必要はありません。

## 例

`hr` スキーマ内のすべてのテーブルの統計情報をロック解除します。

```sql
obclient [test]> USE hr;
Database changed
obclient [hr]> CALL DBMS_STATS.UNLOCK_SCHEMA_STATS ('hr', stattype=>'ALL');
Query OK, 0 rows affected
```
