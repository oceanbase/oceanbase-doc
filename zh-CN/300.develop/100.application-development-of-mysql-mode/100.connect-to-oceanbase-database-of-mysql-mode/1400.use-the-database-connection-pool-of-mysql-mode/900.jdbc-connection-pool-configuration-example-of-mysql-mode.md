# JDBC 配置示例

本文介绍 JDBC 配置示例，包括常用参数说明、性能调优建议和故障排除指南。

在使用 JDBC 进行数据库连接的时候，需要配置相关参数来获得数据库使用的最佳性能。这里推荐一些相关参数的配置。

## JDBC 连接示例

JDBC 连接示例如下：

```java
conn=jdbc:oceanbase://xxx.xxx.xxx.xxx:2881/test?rewriteBatchedStatements=TRUE&allowMultiQueries=TRUE&useLocalSessionState=TRUE&useUnicode=TRUE&characterEncoding=utf-8&socketTimeout=10000&connectTimeout=30000
```

## 常用参数说明

在此连接中，涉及到的配置参数如下：

### 性能相关参数

* `rewriteBatchedStatements`：建议设置为 TRUE。

  * OceanBase 的JDBC 驱动在默认情况下会无视 executeBatch() 语句，把批量执行的一组 SQL 语句拆散，一条一条地发给数据库，此时批量插入实际上是单条插入，直接造成较低的性能。要想实际执行批量插入，需要将该参数置为 TRUE， 驱动才会批量执行 SQL。即使用 addBatch 方法把同一张表上的多条 insert 语句合在一起，做成一条 insert 语句里的多个 values 值的形式，提高 batch insert 的性能。

  * 必须使用 prepareStatement 方式来把每条 insert 做 prepare，然后再 addBatch，否则不能合并执行。

* `allowMultiQueries`：建议设置为 TRUE。

  JDBC 驱动允许应用代码把多个 SQL 用分号（;）拼接在一起，作为一个 SQL 发给 server 端。

* `useLocalSessionState`：建议设置为 TRUE，避免交易频繁向 OB 数据库发送 session 变量查询 SQL。

  session变量主要为：autocommit，read_only 和 transaction isolation。

* `useCursorFetch`：建议设置为 `TRUE`。

  对于大数据量的查询语句，数据库 Server 会建立 Cursor 并根据 FetchSize 的大小向 Client 分发数据。这个属性设为 `TRUE`，会自动连带设置 `useServerPrepStms=TRUE`。

* `useServerPrepStms`：控制是否使用 PS 协议来把 SQL 发送给数据库 server。

  设置为 `TRUE` 时，SQL 在数据库内会分为两步执行：

  * 把包含 `？`的 SQL 文本发送到数据库 Server 做 Prepare（`SQL_audit: request_type=5`）；

  * 用真实 Value 在数据库内做 Execute（`SQL_audit: request_type=6`）。

* `cachePrepStmts`：控制 JDBC driver 是否开启 PS cache 来缓存 PreparedStatment，避免重复执行 prepare（client 端和 server 端）。`cachePrepStmts=TRUE` 对使用 `useServerPrepStms=TRUE` 并重复对同一条 SQL 做 batch execute 的场景有帮助。每一次 batch excecute 都会包含 preare 和 `executecachePrepStmts=TRUE` 可以避免重复的 prepare 操作。

* `prepStmtCacheSQLLimit`：可以放入 PS cache 的 SQL 的长度限制，超长 SQL 不可放入缓存。prepStmtCacheSize：PS cache 可以保存的SQL数量。

* `maxBatchTotalParamsNum`：针对 batch 操作，一条 SQL 最多能支持多少个参数（即 batch 中 `?` 的个数）。如果参数个数大于限制，batch SQL 将会被拆分。

### 超时相关参数

* `socketTimeout`：执行 SQL 时，socket 等待 SQL 返回的时间。建议设置为 10000-30000 毫秒。

* `connectTimeout`：建立连接时，等待连接的时间。建议设置为 30000 毫秒。

* `autoReconnect`：当连接断开时，是否自动重新连接。建议设置为 TRUE。

* `maxReconnects`：自动重连的最大次数。建议设置为 3。

* `initialTimeout`：自动重连的初始等待时间。建议设置为 2 秒。

### 字符集相关参数

* `useUnicode`：是否使用 Unicode 字符编码。建议设置为 TRUE。

* `characterEncoding`：字符编码方式。建议设置为 utf-8。

* `characterSetResults`：结果集的字符集。建议设置为 utf-8。

### 其他重要参数

* `useSSL`：是否使用 SSL 连接。建议设置为 FALSE，除非有特殊安全需求。

* `allowPublicKeyRetrieval`：是否允许从服务器获取公钥。建议设置为 TRUE。

* `serverTimezone`：服务器时区。建议设置为 Asia/Shanghai 或 UTC。

* `zeroDateTimeBehavior`：处理零日期时间的行为。建议设置为 CONVERT_TO_NULL。

## 性能调优建议

1. **批量操作优化**：
   * 启用 `rewriteBatchedStatements=TRUE`，提高批量插入性能。
   * 使用 `addBatch()` 和 `executeBatch()` 方法进行批量操作。
   * 设置合适的 `maxBatchTotalParamsNum` 值，避免批量操作被拆分。

2. **预处理语句优化**：
   * 启用 `useServerPrepStms=TRUE` 和 `cachePrepStmts=TRUE`，提高 SQL 执行效率。
   * 设置合适的 `prepStmtCacheSize` 和 `prepStmtCacheSQLLimit` 值，缓存常用 SQL。

3. **连接池优化**：
   * 使用连接池管理数据库连接，避免频繁创建和销毁连接。
   * 设置合理的连接池大小，根据应用并发量和数据库性能调整。
   * 启用连接检测，确保连接有效。

4. **查询优化**：
   * 使用 `useCursorFetch=TRUE` 和设置合适的 `fetchSize`，提高大数据量查询性能。
   * 避免使用 `SELECT *`，只查询需要的列。
   * 使用索引优化查询性能。

5. **事务优化**：
   * 使用 `useLocalSessionState=TRUE`，减少 session 变量查询。
   * 合理设置事务隔离级别，避免不必要的锁等待。
   * 控制事务大小，避免长事务。

## 故障排除指南

1. **连接超时**：
   * 症状：应用报错 "Connection timed out"。
   * 原因：数据库响应慢或网络问题。
   * 解决方案：
     * 增加 `socketTimeout` 和 `connectTimeout` 值。
     * 检查网络连接和数据库负载。
     * 优化慢查询。

2. **连接断开**：
   * 症状：应用报错 "Connection is closed"。
   * 原因：数据库连接被关闭或超时。
   * 解决方案：
     * 启用 `autoReconnect=TRUE`。
     * 设置合理的 `maxReconnects` 和 `initialTimeout` 值。
     * 使用连接池并启用连接检测。

3. **字符集问题**：
   * 症状：中文显示乱码。
   * 原因：字符集设置不正确。
   * 解决方案：
     * 设置 `useUnicode=TRUE` 和 `characterEncoding=utf-8`。
     * 确保数据库和表的字符集为 utf8mb4。

4. **批量操作失败**：
   * 症状：批量插入性能低或失败。
   * 原因：`rewriteBatchedStatements` 未启用或参数设置不正确。
   * 解决方案：
     * 启用 `rewriteBatchedStatements=TRUE`。
     * 使用 `prepareStatement` 和 `addBatch` 方法。
     * 设置合适的 `maxBatchTotalParamsNum` 值。

5. **预处理语句问题**：
   * 症状：SQL 执行效率低。
   * 原因：预处理语句缓存未启用或参数设置不正确。
   * 解决方案：
     * 启用 `useServerPrepStms=TRUE` 和 `cachePrepStmts=TRUE`。
     * 设置合适的 `prepStmtCacheSize` 和 `prepStmtCacheSQLLimit` 值。
     * 使用 `prepareStatement` 方法执行 SQL。

## 最佳实践

1. **连接字符串配置**：

   ```java
   jdbc:oceanbase://xxx.xxx.xxx.xxx:2881/test?rewriteBatchedStatements=TRUE&allowMultiQueries=TRUE&useLocalSessionState=TRUE&useUnicode=TRUE&characterEncoding=utf-8&socketTimeout=10000&connectTimeout=30000&useCursorFetch=TRUE&useServerPrepStms=TRUE&cachePrepStmts=TRUE&prepStmtCacheSize=250&prepStmtCacheSQLLimit=2048&autoReconnect=TRUE&maxReconnects=3&initialTimeout=2&serverTimezone=Asia/Shanghai&zeroDateTimeBehavior=CONVERT_TO_NULL
   ```

2. **代码示例**：

   ```java
   // 批量插入示例
   String sql = "INSERT INTO test_table (id, name) VALUES (?, ?)";
   try (Connection conn = dataSource.getConnection();
        PreparedStatement pstmt = conn.prepareStatement(sql)) {
       for (int i = 0; i < 1000; i++) {
           pstmt.setInt(1, i);
           pstmt.setString(2, "name" + i);
           pstmt.addBatch();
       }
       pstmt.executeBatch();
   }
   
   // 查询示例
   String sql = "SELECT id, name FROM test_table WHERE id > ?";
   try (Connection conn = dataSource.getConnection();
        PreparedStatement pstmt = conn.prepareStatement(sql)) {
       pstmt.setInt(1, 100);
       try (ResultSet rs = pstmt.executeQuery()) {
           while (rs.next()) {
               int id = rs.getInt("id");
               String name = rs.getString("name");
               System.out.println("id: " + id + ", name: " + name);
           }
       }
   }
   ```
