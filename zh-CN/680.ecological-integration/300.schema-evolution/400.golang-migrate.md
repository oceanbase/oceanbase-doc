# 使用 golang-migrate 对 OceanBase 数据库进行 Schema 版本管理

## 概述

golang-migrate 是 Go 生态中常用的数据库迁移工具，支持基于 SQL 脚本执行数据库对象的版本迁移和回滚。本文介绍如何使用 golang-migrate 连接 OceanBase 数据库 MySQL 模式租户，并完成迁移创建、执行、校验和回滚。

## 版本兼容性

- OceanBase 数据库 ≥ V4.2.5。
- OBProxy ≥ V4.3.1。

## 前提条件

在使用 golang-migrate 之前，确认：

- 已安装 Go 环境。Go 安装参见 [Go 官方安装文档](https://go.dev/doc/install)。
- 您已完成部署 OceanBase 数据库并且创建了 MySQL 模式用户租户。创建用户租户的详细信息，参见 <a href="../../600.manage/200.tenant-management/600.common-tenant-operations/200.manage-create-tenant.md">创建租户</a> 。

## 操作步骤

### 步骤一：获取 OceanBase 数据库连接串

联系 OceanBase 数据库部署人员获取连接串，例如：

```
obclient -h$host -P$port -u$user_name -p$password -D$database_name
```

**参数说明：**

* `$host`：连接 IP。ODP 连接用 ODP 地址；直连用 OBServer IP。
* `$port`：连接端口。ODP 默认 `2883`；直连默认 `2881`。
* `$database_name`：数据库名称。

<main id="notice" type='notice'>
    <h4>注意</h4>
    <p>连接租户的用户需要拥有该数据库的 <code>CREATE</code>、<code>INSERT</code>、<code>DROP</code> 和 <code>SELECT</code> 权限。更多有关用户权限的信息，请参见 <a href="../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md">MySQL 模式下的权限分类</a>。</p>
</main>

* `$user_name`：连接账户。ODP 格式：`用户@租户#集群` 或 `集群:租户:用户`；直连格式：`用户@租户`。
* `$password`：账户密码。

更多连接串的信息，请参见 <a href="../../300.develop/100.application-development-of-mysql-mode/100.connect-to-oceanbase-database-of-mysql-mode/300.connect-to-an-oceanbase-tenant-by-using-obclient-of-mysql-mode.md">通过 OBClient 连接 OceanBase 租户</a>。

**示例如下：**

```shell
obclient -hxxx.xxx.xxx.xxx -P2881 -utest_user001@mysql001 -p****** -Dtest
```

### 步骤二：安装 migrate 命令行工具

本文以使用 golang-migrate V4.15.2 版本安装为例，操作如下：

```shell
# （可选）配置 Go 模块代理
export GOPROXY=https://goproxy.cn,direct

# 安装带 MySQL 驱动的 migrate 命令行工具
go install -tags 'mysql' github.com/golang-migrate/migrate/v4/cmd/migrate@v4.15.2

# 将 Go 可执行文件目录加入当前会话的 PATH
export PATH="$PATH:$(go env GOPATH)/bin"

#验证是否安装成功
migrate -version
```

如果需要永久生效，请将 $(go env GOPATH)/bin 添加到 shell 启动文件（如 ~/.zshrc 或 ~/.bashrc）中。

### 步骤三：创建迁移文件

在项目目录下执行以下命令，创建 migrations 目录并生成一组迁移文件：

```shell
migrate create -ext sql -dir migrations -seq init_oceanbase_test
ls -la migrations/
```

执行成功后，将在 migrations 目录下生成如下文件：

000001_init_oceanbase_test.up.sql
000001_init_oceanbase_test.down.sql
其中：

- up.sql 文件用于定义数据库升级操作。
- down.sql 文件用于定义数据库回滚操作。


### 步骤四：编写迁移 SQL

编辑迁移文件 `migrations/000001_init_oceanbase_test.up.sql` 和 `migrations/000001_init_oceanbase_test.down.sql`，分别写入数据库升级和回滚 SQL。

本示例中的迁移内容包括：

- 创建表、外键和索引。
- 插入初始化数据。
- 新增列。
- 创建视图。
- 回滚时删除相关对象。

**up 迁移**（`000001_init_oceanbase_test.up.sql`）：

```sql
-- 创建用户表
CREATE TABLE users (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(50) NOT NULL UNIQUE,
    email VARCHAR(100) NOT NULL UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    status TINYINT DEFAULT 1 COMMENT '1:active, 0:inactive',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';

CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_status ON users(status);
CREATE INDEX idx_users_created_at ON users(created_at);

-- 创建订单表
CREATE TABLE orders (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id BIGINT NOT NULL,
    order_no VARCHAR(32) NOT NULL UNIQUE,
    amount DECIMAL(10,2) NOT NULL DEFAULT 0.00,
    status TINYINT DEFAULT 0 COMMENT '0:pending, 1:paid, 2:cancelled',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单表';

CREATE INDEX idx_orders_user_id ON orders(user_id);
CREATE INDEX idx_orders_order_no ON orders(order_no);
CREATE INDEX idx_orders_status ON orders(status);

INSERT INTO users (username, email, password_hash) VALUES
('oceanbase_admin', 'admin@demo.com', 'hashed_password_admin'),
('oceanbase_user1', 'user1@demo.com', 'hashed_password_user1'),
('oceanbase_user2', 'user2@demo.com', 'hashed_password_user2');

INSERT INTO orders (user_id, order_no, amount, status) VALUES
(1, 'ORD202401001', 99.99, 1),
(2, 'ORD202401002', 149.50, 0),
(3, 'ORD202401003', 299.00, 1);

-- 商品表、ALTER、视图
CREATE TABLE products (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    sku VARCHAR(64) NOT NULL UNIQUE,
    name VARCHAR(200) NOT NULL,
    price DECIMAL(12,2) NOT NULL DEFAULT 0.00,
    stock INT NOT NULL DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='商品表';

INSERT INTO products (sku, name, price, stock) VALUES
('SKU-001', '示例商品 A', 19.90, 100),
('SKU-002', '示例商品 B', 59.00, 50);

ALTER TABLE users ADD COLUMN last_login_at TIMESTAMP NULL DEFAULT NULL COMMENT '最后登录时间';

CREATE INDEX idx_products_stock ON products(stock);

CREATE OR REPLACE VIEW v_user_order_stats AS
SELECT
    u.id AS user_id,
    u.username,
    COUNT(o.id) AS order_count,
    COALESCE(SUM(o.amount), 0) AS total_amount
FROM users u
LEFT JOIN orders o ON o.user_id = u.id
GROUP BY u.id, u.username;

```

**down 迁移**（`000001_init_oceanbase_test.down.sql`）：

```sql
-- 回滚时先删视图与依赖，再删表，顺序与 up 相反。
DROP VIEW IF EXISTS v_user_order_stats;
ALTER TABLE users DROP COLUMN last_login_at;
DROP TABLE IF EXISTS products;
DROP TABLE IF EXISTS orders;
DROP TABLE IF EXISTS users;
```

### 步骤五：执行迁移到 OceanBase

1. （可选）配置 ODP 参数

   如果通过 ODP 代理端口连接 OceanBase 数据库，请先在系统租户中设置以下 ODP 参数：

   ```sql
   ALTER PROXYCONFIG SET proxy_id=1;
   ALTER PROXYCONFIG SET client_session_id_version=2;
   ALTER PROXYCONFIG SET enable_single_leader_node_routing = false;
   ```

   **参数说明：**
   * `proxy_id`：ODP 实例 ID，单个 ODP 实例可设置为 1，多个 ODP 实例部署时，需每个实例分配不同的 proxy_id，例如 1、2、3。
   * `client_session_id_version`：设置生成 Client Session ID 算法。
   * `enable_single_leader_node_routing`：强制使用标准 OceanBase 2.0 协议通信。

2. **测试数据库连接**

   使用 OBClient 或 MySQL 客户端连接目标库，确认网络与账号正常，例如：

   ```shell
   obclient -h$host -P$port -u$user_name -p$password -e "SELECT VERSION();"
   ```

   返回结果示例如下：

   ```shell
   5.7.25-OceanBase-v4.2.5.0
   ```


3. **执行向上迁移**

   执行以下命令，将迁移脚本应用到 OceanBase 数据库：

   ```shell
   migrate -path migrations -database "mysql://$user_name:$password@tcp($host:$port)/$database_name?charset=utf8mb4&parseTime=True&loc=Local" up
   ```

   **参数说明：**
   * `$host`：OceanBase 数据库连接 IP。
   * `$port`：OceanBase 数据库连接端口。使用 ODP 连接时默认端口为 2883，直连 OBServer 时默认端口为 2881。
   * `$user_name`：OceanBase 数据库用户名。
   * `$password`：OceanBase 数据库用户密码。
   * `$database_name`：OceanBase 数据库名。

    <main id="notice" type='notice'>
        <h4>注意</h4>
        <p>如果用户名或密码中包含特殊字符，请先进行 URL 编码。</p>
    </main>

4. **查看当前迁移版本**

   执行以下命令查看当前数据库已应用的迁移版本：

   ```shell
   migrate -path migrations -database "mysql://$user_name:$password@tcp($host:$port)/$database_name?charset=utf8mb4&parseTime=True&loc=Local" version
   ```

   返回 `1` 表示当前已应用到第 1 个迁移版本。

5. **回滚迁移**

   如果需要回滚最近一次迁移，可执行以下命令：

   ```shell
   migrate -path migrations -database "mysql://$user_name:$password@tcp($host:$port)/$database_name?charset=utf8mb4&parseTime=True&loc=Local" down 1
   ```

   执行 down 1 后，迁移版本将回退到 0。业务表和视图会被删除，仅保留 schema_migrations 表。此后可再次执行 up 命令重新应用迁移。

## 结果验证

连接 OceanBase 目标数据库，执行以下命令确认迁移结果：

```shell
obclient -h$host -P$port -u$user_name -p$password -D$database_name -e "
SHOW TABLES;
DESCRIBE users;
SELECT * FROM v_user_order_stats LIMIT 5;
SELECT * FROM schema_migrations;
"
```

如果迁移成功，预期可以看到以下结果：

- 存在表 `users`、`orders`、`products` 和 `schema_migrations`。
- 存在视图 `v_user_order_stats`。
- `users` 表中包含 `last_login_at` 列。
- `schema_migrations` 表中记录了当前迁移版本。

## 常见问题

**Q1：migrate 命令找不到？**

**原因**：未将 Go 的 bin 目录加入 PATH。

**解决方案**：执行 `echo 'export PATH=$PATH:$(go env GOPATH)/bin' >> ~/.bashrc` 或 `echo 'export PATH=$PATH:$HOME/go/bin' >> ~/.bashrc` 后执行 `source ~/.bashrc`，或使用完整路径调用 `migrate`。

**Q2：连接串中的用户名包含 @，执行 migrate 报错？**

**原因**：在数据库连接 URL 中，@ 是保留字符。如果用户名中包含 @ 且未进行 URL 编码，连接串会解析失败。

**解决方案**：将用户名中的 `@` 替换为 `%40` 再填入 database URL，例如 `user@tenant` 写为 `user%40tenant`。
