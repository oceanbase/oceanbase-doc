# 通过 Archery 管理 OceanBase 数据库实例

## 概述

Archery 是一个 SQL 审核平台，提供工作流管理、权限控制和消息通知等能力。本文介绍如何通过 Archery 管理 OceanBase 数据库实例，包括元数据库配置、SQL 查询、SQL 审核、SQL 执行和账号管理。

## 版本兼容性

- OceanBase 数据库 ≥ V4.2.5。
- OBProxy ≥ V4.3.1。

## 前提条件

在使用 Archery 之前，确认：

- 已安装 Archery。请参考 [Archery 官方文档](https://archerydms.com/home/) 进行安装。
- 您已完成部署 OceanBase 数据库并且创建了 MySQL 模式用户租户。创建用户租户的详细信息，参见 <a href="../../600.manage/200.tenant-management/600.common-tenant-operations/200.manage-create-tenant.md">创建租户</a>。
- 已在创建的 MySQL 兼容模式租户下开通 Binlog 服务。详情请参见 <a href="../../700.reference/1500.Components-and-Tools/300.data-integrate/100.oblogproxy-overview.md">OceanBase Binlog 服务</a>。

## 操作步骤

### 步骤一：获取 OceanBase 数据库连接串

联系 OceanBase 数据库部署人员获取连接串，例如：

```
obclient -h$host -P$port -u$user_name -p$password -D$database_name
```

**参数说明：**

* `$host`：连接 IP。ODP 连接用 ODP 地址；直连用 OBServer IP。
* `$port`：连接端口。ODP 默认 `2883`；直连默认 `2881`。
* `$database_name`：数据库名称。

    <main id="notice" type='notice'>
        <h4>注意</h4>
        <p>连接租户的用户需要拥有该数据库的 <code>CREATE</code>、<code>INSERT</code>、<code>DROP</code> 和 <code>SELECT</code> 权限。更多有关用户权限的信息，请参见 <a href="../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md">MySQL 模式下的权限分类</a>。</p>
    </main>

* `$user_name`：连接账户。ODP 格式：`用户@租户#集群` 或 `集群:租户:用户`；直连格式：`用户@租户`。
* `$password`：账户密码。

更多连接串的信息，请参见 <a href="../../300.develop/100.application-development-of-mysql-mode/100.connect-to-oceanbase-database-of-mysql-mode/300.connect-to-an-oceanbase-tenant-by-using-obclient-of-mysql-mode.md">通过 OBClient 连接 OceanBase 租户</a>。

**示例如下：**

```shell
obclient -hxxx.xxx.xxx.xxx -P2881 -utest_user001@mysql001 -p****** -Dtest
```

### 步骤二：在 Archery 中添加 OceanBase 实例

登录 Archery 管理界面后，进入实例管理页面，创建数据库实例。
创建实例时，请将数据库类型选择为 MySQL，并填写 OceanBase 数据库连接信息。配置项说明如下：

- **实例名称**：自定义实例名称，用于在 Archery 中区分不同数据库实例。
- **实例地址**：$host:$port。
- **数据库名**：$database_name。
- **用户名**：$user_name。
- **密码**：$password。
- **字符集**：建议选择 utf8 或 utf8mb4。

完成上述配置后，保存实例信息。

### 步骤三：使用 Archery 管理功能

将 OceanBase 实例接入 Archery 后，您可以使用 SQL 查询、SQL 审核和数据归档等功能。

#### SQL 查询

在 Archery 的 **SQL 查询 / 在线查询** 页面中，选择目标实例和数据库，输入待执行的 SQL 语句后，单击 **SQL 查询**即可。

#### SQL 审核和数据归档

在使用 SQL 审核或数据归档功能前，请完成以下配置。

* 配置 ODP 参数

   如果通过 ODP 连接 OceanBase，请先连接系统租户并执行以下命令：

   ```sql
   ALTER PROXYCONFIG SET proxy_id=1;
   ALTER PROXYCONFIG SET client_session_id_version=2;
   ALTER PROXYCONFIG SET enable_single_leader_node_routing = false;
   ```

   **参数说明：**

   * `proxy_id`：ODP 实例 ID。单个 ODP 实例可设置为 1；多个 ODP 实例部署时，需为每个实例分配不同的 proxy_id。。
   * `client_session_id_version`：设置生成 Client Session ID 算法。
   * `enable_single_leader_node_routing`：强制使用标准 OceanBase 2.0 协议通信。

* 配置业务租户参数

   在业务租户中执行以下命令，临时开启锁优先级：

   ```sql
   ALTER SYSTEM SET enable_lock_priority = TRUE;
   ```

   相关 DDL 执行完成后，请及时关闭该参数：

   ```sql
   ALTER SYSTEM SET enable_lock_priority = FALSE;
   ```

   **参数说明：**

   * `enable_lock_priority`：为表锁优先级开关，开启后特定 DDL（`RENAME TABLE`）将有最高锁优先级。

   <main id="notice" type='notice'>
        <h4>注意</h4>
        <p>长期开启 enable_lock_priority 可能影响 DML 锁竞争的公平性，并导致性能抖动。</p>
   </main>



**配置 SQL 审核功能**：

如需使用 SQL 审核功能，请在 **Archery 的 系统管理 / 配置管理** 页面中填写 goInception 相关配置。
goInception 可使用 OceanBase 组织维护的集成分支，详情请参见
[goInception Integration 分支](https://github.com/oceanbase/goInception.git)。

**配置数据归档功能**：

如需使用数据归档功能，请提前在 Archery 所在宿主机部署 PTArchiver。
PTArchiver 安装包可联系技术支持人员获取。

## 结果验证

完成实例配置后，您可以通过以下方式验证 OceanBase 实例是否已成功接入 Archery：

- 在 **SQL 查询 / 在线查询** 页面执行 SQL 语句，并正常返回查询结果。
- 提交 **SQL 审核工单**，并完成审批流程。
- 创建并执行**数据归档**任务。
- 查看实例的**数据字典**、**账号信息**等元数据。

如果上述操作均可正常执行，则说明 OceanBase 实例已成功接入 Archery。

## 常见问题

### Q1：执行归档任务时报错 internal Server Error

**原因**：未安装 percona-toolkit，或 pt-archiver 及其依赖不完整。

**解决方案**：

1. 安装依赖包：

   ```shell
   yum install perl perl-DBI perl-DBD-MySQL
   ```

2. 安装 percona-toolkit：

   percona-toolkit 安装包可联系技术支持人员获取。

3. 配置环境变量：

   ```shell
   echo "export PTOST=/root/percona-toolkit" >> /etc/profile
   echo "export PATH=\$PATH:\$PTOST/bin" >> /etc/profile
   source /etc/profile
   ```

### Q2：执行相关操作时报错 You have an error in your SQL syntax ... near 'LOCK TABLES'

**原因**：OceanBase 低版本不支持 GRANT LOCK TABLES 语法。

**解决方案**：

请将相关组件升级到以下版本或更高版本：
+ 升级 OceanBase 到 V4.2.5 或更高版本。
+ 升级 OBProxy 到 V4.3.1 或更高版本。

### Q3：报错 Table 'performance_schema.events_statements_history' doesn't exist

**原因**：OceanBase 没有 performance_schema 库，该功能不兼容。

### Q4：pt_query_digest 无法解析 OB 慢日志

**原因**：OB 的慢日志和 MySQL 慢日志格式不同，pt_query_digest 无法解析。

### Q5：报错 Can't initialize character set utf-8

**原因**：在配置 OceanBase 实例时，字符集不能写 utf-8。

**解决方案**：字符集需要写 utf8 或 utf8mb4。
