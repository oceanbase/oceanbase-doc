# 使用 AWS DMS 实现 MySQL 与 OceanBase MySQL 租户之间的双向数据迁移

AWS Database Migration Service (DMS) 是 AWS 提供的云数据库迁移服务，支持同构和异构数据库之间的数据迁移。AWS DMS 提供了全量迁移、增量迁移和持续数据复制功能，能够用于数据库迁移、数据同步、数据集成等场景。结合 OceanBase 数据库，可以实现 MySQL 与 OceanBase 之间的双向数据迁移。

## 版本兼容性

| 组件 | 版本要求 |
|------|---------|
| OceanBase | ≥ V4.2.5 |
| ODP | ≥ V4.3.5 |

## 使用限制

* OceanBase 不支持 `CREATE TEMPORARY TABLES` 和 `EVENT` 权限，可能导致迁移评测失败，但不会影响实际数据迁移。
* 增量迁移 OceanBase 到 MySQL 时，必须通过 ODP 连接，不能直接连接 OBServer。
* 增量迁移需要部署 Binlog 服务，直接连接 OBServer 无法使用 binlog 功能。

## 前提条件

在使用 AWS DMS 之前，确认：
* 已安装并配置 AWS DMS。安装和配置请参考 [AWS DMS 官方文档](https://docs.aws.amazon.com/dms/latest/userguide/Welcome.html)。
* 已部署 OceanBase 数据库并创建了 MySQL 模式用户租户。创建用户租户的详细信息，参见 [创建租户](../../600.manage/200.tenant-management/600.common-tenant-operations/200.manage-create-tenant.md)。
* 如需增量迁移，已在创建的 MySQL 兼容模式租户下开通 Binlog 服务。详情请参见 [OceanBase Binlog 服务](../../700.reference/1500.Components-and-Tools/300.data-integrate/100.oblogproxy-overview.md)。

## 操作步骤

### 步骤一：获取 OceanBase 数据库连接串

联系 OceanBase 数据库部署人员获取连接串，例如：

```shell
obclient -h$host -P$port -u$user_name -p$password -D$database_name
```

**参数说明：**
* `$host`：连接 IP。ODP 连接用 ODP 地址；直连用 OBServer IP。
* `$port`：连接端口。ODP 默认 `2883`；直连默认 `2881`。
* `$database_name`：数据库名称。
    <main id="notice" type='notice'>
        <h4>注意</h4>
        <p>连接租户的用户需要拥有该数据库的 <code>CREATE</code>、<code>INSERT</code>、<code>DROP</code> 和 <code>SELECT</code> 权限。更多有关用户权限的信息，请参见 <a href="../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md">MySQL 模式下的权限分类</a>。</p>
    </main>
* `$user_name`：连接账户。ODP 格式：`用户@租户#集群` 或 `集群:租户:用户`；直连格式：`用户@租户`。
* `$password`：账户密码。

更多连接串的信息，请参见[通过 OBClient 连接 OceanBase 租户](../../300.develop/100.application-development-of-mysql-mode/100.connect-to-oceanbase-database-of-mysql-mode/300.connect-to-an-oceanbase-tenant-by-using-obclient-of-mysql-mode.md)。

**示例如下：**

```shell
obclient -hxxx.xxx.xxx.xxx -P2881 -utest_user001@mysql001 -p****** -Dtest
```

### 步骤二：配置 MySQL 参数

如果源端为 MySQL 数据库，需要登录 MySQL 数据库，修改参数配置以避免迁移评测失败：

```sql
SET GLOBAL net_read_timeout = 600;
SET GLOBAL net_write_timeout = 600;
```

确保参数值大于 300 秒，建议设置为 600 秒。

### 步骤三：执行全量迁移

1. 在 AWS DMS 控制台选择 `Replication instances` 点击 `Create replication instance` 创建复制实例。
2. 选择 `Endpoints` 点击 `Create endpoint` 创建源端点和目标端点：
   * MySQL 到 OceanBase：源端点为 MySQL，目标端点为 OceanBase。
   * OceanBase 到 MySQL：源端点为 OceanBase（通过 ODP 连接），目标端点为 MySQL。
3. 选择 `Tasks` 点击` Create Task` 创建迁移任务，选择迁移类型为 `Migrate only`。
4. 启动迁移任务，监控任务状态，`Successful ` 表示迁移成功。
5. 验证迁移结果，确认数据完整性。

### 步骤五：执行增量迁移

如需持续数据同步，可配置增量迁移：

1. 确保源端数据库已开启 binlog（MySQL）或已部署 Binlog 服务（OceanBase）。
2. 在 AWS DMS 控制台选择 `Tasks` 点击` Create Task` 创建迁移任务，选择迁移类型为 `Migrate and replicate` 或 `Replicate only` 。
3. 启动迁移任务，监控 CDC 状态，`Loadcompleted,replication ongoing` 表示增量迁移中。
4. 验证增量数据同步情况。

<main id="notice" type='notice'>
    <h4>注意</h4>
    <p>OceanBase 到 MySQL 的增量迁移必须通过 ODP 连接，不能直接连接 OBServer。</p>
</main>


## 结果验证

运行成功后，可根据以下步骤验证迁移结果：

1. 登录 AWS DMS 控制台。
2. 查看迁移任务状态，确认任务状态为 `Successful` 或 `Loadcompleted,replication ongoing`（增量迁移）。
3. 检查任务统计信息，确认已迁移的表数量、记录数量和错误数量。
4. 连接目标数据库，执行数据校验查询，对比源端和目标端的数据记录数：

   ```sql
   SELECT COUNT(*) FROM table_name;
   ```

5. 抽样检查关键数据，确认数据一致性。
