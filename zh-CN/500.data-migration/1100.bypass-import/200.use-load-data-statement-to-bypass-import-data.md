# 使用 LOAD DATA 语句旁路导入数据

`LOAD DATA` 语句通过 Hint 使用 `direct` 来表示是否走旁路导入。

## 使用限制

* 在导入过程中无法同时执行两个写操作语句（即不能同时写一个表），因为导入过程中会先加表锁，并且整个导入过程中只能进行读操作。
* 不支持在触发器（Trigger）使用。
* 不支持含有生成列的表（某些索引会产生隐藏生成列，例如 KEY `idx_c2` (`c2`(16)) GLOBAL）。
* 不支持单行超过 2M 的数据导入。
* 不支持 Liboblog 和闪回查询（Flashback Query）。
* 支持 `lob` 类型，但是性能比较差，`lob` 会走原来事务写入数据的路径。
* 旁路导入属于 DDL 语句，不能在多行事务（包含多个操作的事务）中运行。

## 注意事项

OceanBase 数据库通过并行处理技术优化 `LOAD DATA` 的数据导入速率。该操作将数据分成多个子任务并行执行，每个子任务都视为独立的事务，执行顺序是不固定的。因此对于没有主键的表，数据写入顺序可能与原文件中的顺序不同。

## 语法

```sql
LOAD DATA /*+ direct(need_sort,max_error) parallel(N) */ [REMOTE_OSS | LOCAL] INFILE 'file_name' ...
```

更多 `LOAD DATA` 语法的信息，请参见 [LOAD DATA](../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/5900.load-data-of-mysql-mode.md)。

**参数解释：**

|参数|描述|
|------|------|
| direct | 表示走旁路导入。|
| need_sort | 表示是否需要 OceanBase 数据库对数据进行排序。</br>值为 `bool` 类型：<ul><li>`true`：表示需要排序。</li><li>`false`：表示不需要排序。</li></ul>|
| max_error | 表示最大的容忍的错误的行数。值为 `INT` 类型，超过这个数值`LOAD DATA` 会报失败。|
| parallel(N) | 加载数据的并行度，必填项，取值是大于 1 的整数。|
| REMOTE_OSS \| LOCAL | 可选项，<ul><li> <code>REMOTE_OSS</code> 用于指定是否从 OSS 文件系统读取数据。<main id="notice" type='notice'><h4>注意</h4><p>如果使用了此参数，<code>file_name</code> 必须是一个 OSS 的地址。</p></main>  </li><li> <code>LOCAL</code> 用于指定是否从客户端的本地文件系统读取数据。如果不使用 `LOCAL` 参数，那么将从服务器端（OBServer 节点）的文件系统读取数据。</li></ul> |

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>这里所指的 OSS 泛指对象存储 OSS（<code>oss://</code>）、COS（<code>cos://</code>）、S3（<code>s3://</code>） 等，下文同理。</p>
</main>

## 通配符方式支持多文件导入

为便于多文件导入，引入文件通配符功能，适用于 server_disk 和 OSS 类型的文件源，不适用于客户端磁盘（client_disk）。

### 集群内文件系统（server_disk）旁路导入使用方法

* **server_disk 示例**：

  * 匹配文件名：`load data /*+ parallel(20) direct(true, 0) */ infile '/xxx/test.*.csv' replace into table t1 fields terminated by '|';`

  * 匹配目录：`load data /*+ parallel(20) direct(true, 0) */ infile '/aaa*bb/test.1.csv' replace into table t1 fields terminated by '|';`

  * 同时匹配目录和文件名：`load data /*+ parallel(20) direct(true, 0) */ infile '/aaa*bb/test.*.csv' replace into table t1 fields terminated by '|';`

* **server_disk 注意事项：**

  * 必须存在至少一个匹配的文件，否则返回错误码 4027。

  * 对 `load data /*+ parallel(20) direct(true, 0) */ infile '/xxx/test.1*.csv,/xxx/test.6*.csv' replace into table t1 fields terminated by '|';` 的输入，`/xxx/test.1*.csv,/xxx/test.6*.csv` 会被认为是整体匹配，若无匹配则报错 4027。

  * 只支持 POSIX 的 GLOB 函数能支持的通配符，例如 `test.6*(6|0).csv` 和 `test.6*({0.csv,6.csv}|.csv)` 尽管可通过 `ls` 命令查找，但 GLOB 函数无法匹配，会报错 4027。

### 云对象存储服务（OSS）旁路导入使用方法

* **OSS 示例：**

  * 匹配文件名：`load data /*+ parallel(20) direct(true, 0) */ remote_oss infile 'oss://xxx/test.*.csv?host=xxx&access_id=xxx&access_key=xxx' replace into table t1 fields terminated by '|';`

* **oss 注意事项：**

  * 不支持目录匹配。例如：`load data /*+ parallel(20) direct(true, 0) */ remote_oss infile 'oss://aa*bb/test.*.csv?host=xxx&access_id=xxx&access_key=xxx' replace into table t1 fields terminated by '|';` 会返回 `OB_NOT_SUPPORTED`。

  * 文件名通配符只支持 `*` 和 `?`。其他通配符虽然允许输入，但无法匹配任何结果。

### 跨版本备份数据恢复使用方法

#### V1.4x/V3.x 版本备份数据作为数据源

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>对于 OceanBase 数据库 V4.2.5 版本，旁路导入从 V4.2.5 BP1 版本开始支持将 OceanBase 数据库 V1.4x/V3.x 版本的备份数据（V1.4x 是逻辑备份，V3.x 是物理备份）直接导入到 OceanBase 数据库 V4.x 版本中。</p>
</main>

* **V3.x 版本备份数据作为数据源**

  * 备份数据在 OSS 上，示例如下：

      ```sql
      LOAD DATA /*+ parallel(32) direct(false, 0) */
          REMOTE_OSS INFILE 'oss://xxxx/backup_set_XX_full_YY/data/backup_table_id/?host=***&access_id=***&access_key=***&load_data_format=ob_backup_3_x'
          INTO TABLE table_name;
      ```

  * 备份数据在本地，示例如下：

      ```sql
      LOAD DATA /*+ parallel(32) direct(false, 0) */
          INFILE 'file:///xxxx/backup_set_XX_full_YY/data/backup_table_id/?load_data_format=ob_backup_3_x'
          INTO TABLE table_name;
      ```

  * 关键字段解释

    * `backup_table_name`：没有出现在语法中，表示备份数据的源表表名（源表）。
    * `table_name`：表示 V4.x 集群里待导入的目标表表名（目标表）。
    * `backup_set_XX_full_YY`：`XX` 表示备份的版本号，`YY` 表示日期。
    * `backup_table_id`：表示源表在备份数据里的表 ID。可以在 V3.x 集群中查询，示例如下：

      ```sql
      SELECT table_id
      FROM oceanbase.gv$table
      WHERE table_name = backup_table_name;
      ```

  * V3.x 版本备份数据作为数据源注意事项

    * 本地文件路径，需要在路径前加上 `file://`。
    * 路径里 `backup_set_XX_full_YY` 的 `XX` 字段不要改动，否则可能会导入错误版本的物理备份数据。
    * 备份数据里不包含创建表的 SQL，需要先在 V4.x 的集群中创建目标表，同时保证目标表和源表的列类型完全一致。

* **V1.4x 版本备份数据作为数据源**

  * 备份数据在 OSS 上，示例如下：

    ```sql
    LOAD DATA /*+ parallel(32) direct(false, 0) */
        REMOTE_OSS INFILE 'oss://xxxx/base_data_version/tenant_id/backup_table_id/?host=***&access_id=***&access_key=***&load_data_format=ob_backup_1_4'
        INTO TABLE table_name;
    ```

  * 备份数据在本地，示例如下：

    ```sql
    LOAD DATA /*+ parallel(32) direct(false, 0) */
        INFILE 'file:///xxxx/base_data_version/tenant_id/backup_table_id/?host=***&access_id=***&access_key=***&load_data_format=ob_backup_1_4'
        INTO TABLE table_name;
    ```

  * 关键字段解释

    * `backup_table_name`：没有出现在语法中，表示备份数据的源表表名（源表）。
    * `table_name`：表示 V4.x 集群里待导入的目标表表名（目标表）。
    * `backup_table_id`：表示源表在备份数据里的表 ID。
    * `base_data_version`：`version` 表示备份版本号，表示只导入该版本下的备份数据。
    * `tenant_id`：表示 V1.4x 集群中源表属于的租户，目标表和源表租户没有任何关系，这里的`tenant_id` 只作为路径解析的一部分。

  * V1.4x 版本备份数据作为数据源注意事项

    * 本地文件路径，需要在路径前加上 `file://`。
    * 不要改动 `base_data_version` 同级目录下的 `version` 文件夹，否则可能会发生非预期的错误。
    * `backup_table_name` 和 `backup_table_id` 的对应关系可以在 `/xxxx/version/tenant_id/data_table_ids_list` 文件中查看。
    * 备份数据里包含创建表的 SQL，在 `/xxxx/version/tenant_id/backup_table_id/backup_table_id_definition` 文件里，用户需要先在 V4.x 的集群中创建表。

* **注意事项**

  * 上面示例给出了语法支持的范围，旁路导入其它路径暂不支持。
  * 路径不支持通配符匹配。
  * 不支持 `IGNORE N ROWS`。
  * 只支持普通表备份数据导入，不支持索引表导入，只支持走全量旁路导入。
  * 需要指定旁路导入 Hint，可以指定 `append` 或 `direct`，其中 `direct` Hint 内可以指定是否排序，建议指定不排序，否则导入速度会变慢，`append` Hint 默认不走排序。

#### V2.X 版本备份数据作为数据源

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>对于 OceanBase 数据库 V4.2.5 版本，旁路导入从 V4.2.5 BP4 版本开始支持将 OceanBase 数据库 V2.x 版本的备份数据（逻辑或物理备份）直接导入到 OceanBase 数据库 V4.x 版本中。</p>
</main>

OceanBase 数据库支持以 V2.x 版本（V2.2.30 和 V2.2.77 版本，其中 V2.2.30 是逻辑备份，V2.2.77 是物理备份）逻辑备份和物理备份数据作为数据源，导入数据到 V4.x 集群中。

* **逻辑备份**

  * 备份数据在 OSS 上，示例如下：

      ```sql
      LOAD DATA /*+ parallel(10) direct(false, 0) */
          REMOTE_OSS INFILE 'oss://xxx/backup_version/tenant_id/backup_table_id/?host=***&access_id=***&access_key=***&load_data_format=ob_backup_2_x_log'
          INTO TABLE table_name;
      ```

  * 备份数据在 NFS 上，示例如下：

      ```sql
      LOAD DATA /*+ parallel(10) direct(false, 0) */
          INFILE 'file:///xxx/backup_version/tenant_id/backup_table_id/?load_data_format=ob_backup_2_x_log'
          INTO TABLE table_name;
      ```

  * 关键字段解释

    * `backup_table_name`：没有出现在语法中，表示备份数据的源表表名（源表）。
    * `table_name`：表示 V4.x 集群里待导入的目标表表名（目标表）。
    * `backup_version`：表示备份的版本号。
    * `tenant_id`：表示 V2.x 集群中源表的租户，目标表和源表租户没有任何关系，这里的 `tenant_id` 只作为路径解析的一部分。
    * `backup_table_id`：表示源表在备份数据里的表 ID。可以在 V2.x 集群中查询，示例如下：

      ```sql
      SELECT table_id
      FROM oceanbase.gv$table
      WHERE table_name = backup_table_name;
      ```

  * 使用方法

    * 在 SQL 语句中需要指定备份版本。
    * 需要先在 V4.x 的集群中创建表，创建表的 SQL 存储在 `oss:///xxx/backup_version/tenant_id/backup_table_id/backup_table_id_definition` 文件里，由运维保证创建表的正确性，旁路导入内部只做列类型检查。

* **物理备份**

  * 备份数据在 OSS 上，示例如下：

      ```sql
      LOAD DATA /*+ parallel(10) direct(false, 0) */
          REMOTE_OSS INFILE 'oss://xxx/backup_set_xxx/data/backup_table_id/?host=***&access_id=***&access_key=***&load_data_format=ob_backup_2_x_phy'
          INTO TABLE table_name;
      ```

  * 备份数据在 NFS 上，示例如下：

      ```sql
      LOAD DATA /*+ parallel(10) direct(false, 0) */
          INFILE 'file:///xxx/backup_set_xxx/data/backup_table_id/?load_data_format=ob_backup_2_x_phy'
          INTO TABLE table_name;
      ```

  * 关键字段解释

    * `backup_table_name`：没有出现在语法中，表示备份数据的源表表名（源表）。
    * `table_name`：表示 V4.x 集群里待导入的目标表表名（目标表）。
    * `backup_table_id`：表示源表在备份数据里的表 ID。
    * `backup_set_xx_full_yy`：`xx` 表示备份的版本号，`yy` 表示日期。
    * `tenant_id`：表示 V2.x 集群中源表的租户，目标表和源表租户没有任何关系，这里的 `tenant_id` 只作为路径解析的一部分。

  * 使用方法

    * 需要先在 V4.x 版本的集群中创建表，由运维保证表 Schema 要和 V2.x 版本集群中保持一致，旁路导入内部只做列类型检查，备份数据里不包含创建表的 SQL，要在 V2.x 版本集群中查询。
    * 需要指定导入表的 `table_id`，由运维保证要和对应表在 V2.x 版本集群中的 `table_id` 保持一致。

* **注意事项**

  * 备份前需要做 Major 合并，导入只解析 Major SSTable 中的宏块。
  * 不支持索引表导入。

## 示例

  <main id="notice" type='explain'>
     <h4>说明</h4>
     <p>下面的示例是从服务器端文件导入数据的方法。OceanBase 数据库 <code>LOAD DATA</code> 语句旁路导入数据还支持加载本地文件（<code>LOCAL INFILE</code>）的方式。更多有关 <code>LOAD DATA LOCAL INFILE</code> 的示例信息，请参见 <a href="../700.migrate-data-from-csv-file-to-oceanbase-database/200.use-the-load-command-to-load-the-csv-data-file-to-the-oceanbase-database.md">使用 <code>LOAD DATA</code> 语句导入数据</a></p>
   </main>

1. 登录到要连接 OBServer 节点所在的机器，在 `/home/admin` 目录下创建测试数据。

    <main id="notice" type='explain'>
    <h4>说明</h4>
    <p>OceanBase 数据库中的 <code>LOAD DATA</code> 语句仅支持加载 OBServer 节点本地的输入文件。因此，需要在导入之前将文件拷贝到某台 OBServer 上。</p>
    </main>

    ```shell
    [xxx@xxx /home/admin]# ssh admin@10.10.10.1

    [admin@xxx /home/admin]# vi tbl1.csv
    1,11
    2,22
    3,33
    ```

2. 设置导入的文件路径。

    设置系统变量 `secure_file_priv`，配置导入或导出文件时可以访问的路径。

    <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>由于安全原因，设置系统变量 <code>secure_file_priv</code> 时，只能通过本地 Socket 连接数据库执行修改该全局变量的 SQL 语句。更多信息，请参见 <a href="../../700.reference/800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/11500.secure_file_priv-global.md">secure_file_priv</a>。</p>
    </main>

    1. 登录到要连接 OBServer 节点所在的机器。

        ```shell
        [xxx@xxx /home/admin]# ssh admin@10.10.10.1
        ```

    2. 执行以下命令，通过本地 Unix Socket 连接方式连接租户 `mysql001`。

        ```shell
        obclient -S /home/admin/oceanbase/run/sql.sock -uroot@mysql001 -p******
        ```

    3. 设置导入路径为 `/home/admin`。

        ```shell
        obclient [(none)]> SET GLOBAL secure_file_priv = "/home/admin";
        Query OK, 0 rows affected
        ```

3. 重新连接数据库后，使用 `LOAD /*+ APPEND */ DATA` 语句导入数据。

    ```shell
    obclient [test]> CREATE TABLE tbl1(col1 INT PRIMARY KEY,col2 INT);
    Query OK, 0 rows affected

    obclient [test]> SELECT * FROM tbl1;
    Empty set

    obclient [test]> LOAD DATA /*+ direct(true,1024) parallel(16) */ INFILE '/home/admin/tbl1.csv' INTO TABLE tbl1 FIELDS TERMINATED BY ',';
    Query OK, 3 rows affected
    Records: 3  Deleted: 0  Skipped: 0  Warnings: 0

    obclient [test]> SELECT * FROM tbl1;
    +------+------+
    | col1 | col2 |
    +------+------+
    |    1 |   11 |
    |    2 |   22 |
    |    3 |   33 |
    +------+------+
    3 rows in set
    ```
