# 共享存储容灾部署方案

OceanBase 数据库共享存储模式依赖日志服务提供数据的持久性以及多副本计算节点提供数据的高可用。本文档介绍了 OceanBase SS 支持的容灾部署方案。

OceanBase SS 通过对象存储保证了数据的完整性，通过日志服务保证了日志的完整性，从而提供以下高可用解决方案：

* **基于 Paxos 一致性协议的多副本高可用日志服务（LogService）解决方案**

  该方案基于 Paxos 一致性协议提供多副本高可用容灾能力，读写节点（RW）通过 Paxos 协议直接写入日志服务的多副本中完成持久化，只读节点（RO）通过最近的日志服务副本读取日志，并在本地回放出热点数据。在少数派副本不可用（三副本集群允许一个副本不可用）时，计算节点的读写不受影响，依旧可以正常提供服务。

* **基于多副本计算节点的高可用读写节点（RW）解决方案：**

  该方案可以依赖多副本的只读节点来提供容灾能力，当读写节点不可用时，数据库可以自动执行容灾切换并恢复服务，保证不丢数据（RPO = 0），故障恢复时间在 8 秒以内（RTO < 8s）。

* **基于单副本拉起的高可用解决方案：**

  该方案可以在没有计算节点的情况下也提供容灾能力。遇到不存在只读节点来容灾的情况，由于 OceanBase SS 数据库将数据完整存储在对象存储，并由日志服务保证了增量数据的完整性，因此可以通过一台全新的计算节点拉起完整的服务能力。具体方式是从对象储将数据与元数据恢复在本地，并从日志服务恢复增量数据，同样保证不丢数据（RPO = 0），故障恢复时间在分钟级别（RTO 为分钟级）。

OceanBase SS 推荐如下部署模式，用户可根据机房配置以及性能和可用性的需求进行灵活选择。

| 部署方案 | 容灾能力 | RTO | RPO |
|---------|---------|-----|-----|
| 同城单机房（计算节点多副本） | 机器级无损容灾 | 8s 内 | 0 |
| 同城单机房（计算节点单副本） | 单副本拉起容灾 | 分钟级 | 0 |
| 同城多机房（计算节点多副本） | 机房级无损容灾 | 8s 内 | 0 |
| 同城三机房（日志服务三副本） | 日志服务机房级无损容灾 | 8s 内 | 0 |

## 同城单机房部署（计算节点多副本）

当只有一个机房时，可以在同一机房内部署读写节点和多个只读节点来达到机器级无损容灾。当读写节点所在的 Server 宕机时，系统可以自动执行容灾切换，将只读节点提升为读写节点继续提供服务，不丢数据（RPO = 0），故障恢复时间在 8 秒以内（RTO < 8s）。

## 同城单机房部署（计算节点单副本）

当只有一个机房且只部署单个计算节点时，可以利用单副本拉起机制来提供容灾能力。当计算节点不可用时，可以通过一台全新的计算节点，从对象储恢复数据与元数据，并从日志服务恢复增量数据，拉起完整的服务能力。该方案保证不丢数据（RPO = 0），故障恢复时间在分钟级别（RTO 为分钟级）。

## 同城多机房部署（计算节点多副本）

当同城具备多个机房条件时，可以将计算节点（RW 与 RO）跨机房部署，从而达到机房级无损容灾能力。当读写节点所在机房不可用时，系统可以自动执行容灾切换到其他机房的只读节点，继续提供服务，不丢数据（RPO = 0），故障恢复时间在 8 秒以内（RTO < 8s）。

## 同城三机房部署（日志服务三副本）

日志服务支持三机房三副本部署，保证整机房的容灾能力。将日志服务的三个副本分别部署在三个不同的机房，当任意一个机房不可用时，日志服务依然可以正常提供服务，保证日志的持久性和完整性。

### 说明

* 计算节点（RW 与 RO）以及日志服务（LogService）当前只支持同城部署。
* 计算节点支持单机房以及多机房部署，而日志服务只支持三机房三副本部署。
