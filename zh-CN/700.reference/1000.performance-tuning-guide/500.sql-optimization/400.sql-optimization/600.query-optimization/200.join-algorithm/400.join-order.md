# 联接顺序

在多表联接的场景中，优化器的一个很重要的任务是决定各个表之间的联接顺序（Join Order），因为不同的联接顺序会影响中间结果集的大小，进而影响到计划整体的执行代价。

为了减少执行计划的搜索空间和计划执行的内存占用，OceanBase 数据库优化器在生成联接顺序时主要考虑左深树的联接形式。下图展示了左深树、右深树和多支树的计划形状。

![数](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer-enterprise/V4.2.1/700.reference/1000.performance-tuning-guide/500.sql-optimization/400.sql-optimization/600.query-optimization/200.join-algorithm/connection-order.png)

OceanBase 数据库在生成联接顺序时，会根据系统变量 `_join_order_enum_threshold`（默认值为 10）选择枚举算法：

* 当查询中的表数量 **小于** 该阈值时，使用 **迭代动态规划（Iterative Dynamic Programming, IDP）算法**。
* 当查询中的表数量 **大于等于** 该阈值时，使用 **排列枚举算法**。

## 迭代动态规划算法

如果给定 N 个基表的联接，IDP 算法的执行流程如下：

1. 初始化一个 N 层的动态规划数据结构，将第 0 层设置为所有基表的候选计划。
2. 该算法将动态规划过程分为多轮迭代。每轮在当前基础上执行一定步长的动态规划枚举：

    * 在每轮 DP 中，逐层枚举第 i 层的计划（i 从 1 递增到当前步长），计划由第 j 层的计划与第 i-j-1 层的计划联接生成。
    * 如果中间路径数量超过阈值（由 `_idp_step_reduction_threshold` 控制，默认 5000），则缩减步长以控制搜索空间。
    * 每轮结束后，通过贪心策略选出代价最小的联接计划作为下一轮的基础。

3. 最终从最高层选出最优的计划。

## 排列枚举算法

当表数量较多时，使用排列枚举算法，其执行流程如下：

1. 使用贪心方法生成一个初始的左深联接树作为初始解。
2. 在初始解的基础上，不断枚举下一个排列。每个排列对应一棵左深联接树，枚举过程中利用启发式规则进行裁剪。枚举的排列数量上限由系统变量 `_optimizer_max_permutations`（默认值为 2000）控制。
3. 在所有枚举的排列中，选出最优的计划。

## 计划的比较

在联接枚举过程中，同一个表集合可能产生多种候选路径。对于两个候选路径，优化器会考虑多维度的支配关系（Domination）来决定保留哪些计划。当新增一条候选路径时，优化器会将其与当前已有的所有候选路径逐一比较：

* 如果新路径被某条已有路径支配（或两者等价），则新路径被丢弃。
* 如果新路径支配某条已有路径，则已有路径被移除。
* 如果两者不可比较（各有优劣），则同时保留。

比较时会考虑以下维度，只有在所有维度上都不劣于对方时才构成支配：

1. 代价。
2. 并行度。
3. 数据分布。
4. 流式属性。
5. 输出顺序。

## Hint 机制 /*+LEADING(table_name_list)*/

OceanBase 数据库提供了 Hint 机制 `/*+LEADING(table_name_list)*/` 去控制多表联接的顺序。

**示例如下：**

1. 创建表 `tbl1`。

    ```shell
    obclient> CREATE TABLE tbl1(col1 INT, col2 INT, PRIMARY KEY(col1));
    ```

2. 创建表 `tbl2`。

    ```shell
    obclient> CREATE TABLE tbl2(col1 INT, col2 INT, PRIMARY KEY(col1));
    ```

3. 创建表 `tbl3`。

    ```shell
    obclient> CREATE TABLE tbl3(col1 INT, col2 INT, PRIMARY KEY(col1));
    ```

4. 先做 `tbl1` 表、`tbl2` 表的 `JOIN` 联接，然后再和 `tbl3` 表做 `JOIN` 联接。

    ```shell
    obclient> EXPLAIN SELECT * FROM tbl1, tbl2, tbl3
        WHERE tbl1.col1 = tbl2.col2
        AND tbl2.col1 = tbl3.col2;
    ```
