# max_syslog_file_count

<main id="notice" type='explain'>
<h4>说明</h4>
<p>该配置项从 V1.4 版本开始引入。</p>
</main>

## 功能描述

`max_syslog_file_count` 用于设置在回收日志文件之前可以容纳的日志文件数量，统一控制所有类型 Log 的总量。

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>每个日志文件最多可以占用 256 MB 的磁盘空间。</p>
</main>

## 属性说明

|      **属性**      |  **描述**  |
|------------------  |----------|
| 参数类型            | INT       |
| 默认值              | 0，表示不会删除任何日志文件。        |
| 取值范围            | [0, +∞) |
| 是否可修改          | 是，支持通过 `ALTER SYSTEM SET` 语句修改。|
| 是否重启 OBServer 节点生效 | 否        |

## 使用说明

* 所有类型的日志数量的总和上限为 `max_syslog_file_count`，并采用 FIFO（先进先出）策略进行日志文件的淘汰。FIFO 策略选择的时间节点为日志最后一次的修改时间，例如日志文件 `xxxxxxxx.log.20231123223441234` 结尾时间进行排序决定先后顺序。

* 如果 Trace 日志生成的速度过快，数量过多，可能会抢占 OBServer 日志文件的空间，导致 OBServer 日志被较早地淘汰。面对这种情况，建议您调整全链路诊断的级别，以确定适合的日志量，有关 Trace 日志级别的详细信息请参见[全链路追踪方法](../../../../600.manage/900.daily-inspection/900.full-link-detection/300.full-link-diagnosis.md)。

## 配置示例

```shell
obclient> ALTER SYSTEM SET max_syslog_file_count=0;
```
