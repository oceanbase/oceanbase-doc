# ob_vector_index_active_segment_max_size

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>该配置项从 V4.6.0 版本开始引入。</p>
</main>

## 功能描述

`ob_vector_index_active_segment_max_size` 用于控制单个分区中活跃增量段（Active Segment）的最大内存占用量。当活跃增量段中新写入的向量数据占用内存超过该阈值时，系统会触发冻结及持久化操作，将内存中的增量数据落盘。

<main id="notice" type='notice'>
  <h4>功能适用性</h4>
  <p>该配置项仅适用于 OceanBase 数据库 MySQL 模式。</p>
</main>

## 权限要求

* 查询配置项

  `sys` 租户和 MySQL 用户租户均可以使用 `SHOW PARAMETERS` 语句或视图 `GV$OB_PARAMETERS` 查询该配置项。

* 修改配置项

  `sys` 租户和 MySQL 用户租户均可修改该配置项。

## 属性说明

| **属性** | **描述** |
| -------- | -------- |
| 参数类型 | Cap |
| 默认值 | 0，表示自适应，系统会自动根据租户可用向量内存，设置不同的阈值：<ul><li>4GB 以下为 32MB</li><li>4GB~16GB（包含边界）则为 64MB</li><li>16GB 以上为 128MB</li></ul> |
| 取值范围 | [0, +∞)，单位为 MB|
| 是否可修改 | 是，支持通过 `ALTER SYSTEM SET` 语句修改。 |
| 是否重启 OBServer 节点生效 | 否，设置后立即生效。 |

## 使用说明

* 调大阈值：可降低冻结频率，以规避在增量写入速度过大时产生过多活跃增量段（Active Segment），导致搜索性能下降。
* 调小阈值：除特殊测试场景外，不建议调小阈值。以规避冻结操作过于频繁，影响整体搜索性能。
* 重启数据库：重启数据库时，系统需要恢复内存数据，阈值过大将增加重启恢复时间。重启前，建议调小阈值，以降低重启恢复时间。或在业务低峰期进行重启操作。

## 配置示例

设置单个分区的向量索引 Active Segment 最大内存占用量为 256MB。

```sql
ALTER SYSTEM SET ob_vector_index_active_segment_max_size = '256MB';
```

查看当前配置。

```sql
SHOW PARAMETERS LIKE 'ob_vector_index_active_segment_max_size';
```
