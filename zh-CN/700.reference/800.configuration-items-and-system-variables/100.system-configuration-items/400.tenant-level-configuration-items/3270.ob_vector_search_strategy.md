# ob_vector_search_strategy

<main id="notice" type='explain'>
  <h4>说明</h4>
  <ul><li>在 V4.3.x 版本中，该配置项从 V4.3.5.5 hotfix6 版本开始引入。</li><li>在 V4.4.x 版本中，该配置项从 V4.4.1 hotfix10 版本开始引入。</li><li>在 V4.6.x 版本中，该配置项从 V4.6.0 版本开始引入。</li></ul>
</main>

## 功能描述

`ob_vector_search_strategy` 用于控制向量索引查询时的查询策略，默认为 RECALL_FIRST，即深度搜索模式；LATENCY_FIRST 为响应时间优先模式。

## 权限要求

* 查询配置项

  `sys` 租户和所有用户租户均可以使用 `SHOW PARAMETERS` 语句或视图 `GV$OB_PARAMETERS` 查询该配置项。

* 修改配置项

  `sys` 租户和用户租户均可修改该配置项。

## 属性说明

| **属性**  |    **描述**  |
|-----------|---------------|
| 参数类型    | String |
| 默认值      | RECALL_FIRST |
| 取值范围    | RECALL_FIRST, LATENCY_FIRST |
| 是否可修改 | 是，支持通过 `ALTER SYSTEM SET` 语句修改。|
| 是否重启 OBServer 节点生效 | 否，设置后立即生效。 |

## 使用说明

* 如果要保证响应时间的情况，需要设置 `ob_vector_search_strategy` 为 `LATENCY_FIRST`。
* 对于 RT 不敏感且要求高召回率的场景，采用默认 `RECALL_FIRST` 即可。
* 设置为 `LATENCY_FIRST` 时为响应优先模式/快速模式，用户要求尽快返回结果，且 RT 相对稳定。
* 设置为 `RECALL_FIRST` 时为结果优先模式/深度搜索模式，用户要求尽量搜索到满足 limit K 条数据，容忍部分查询明显变慢。

## 配置示例

设置向量索引查询策略为响应时间优先模式。

```shell
obclient> ALTER SYSTEM SET ob_vector_search_strategy = 'LATENCY_FIRST';
```
