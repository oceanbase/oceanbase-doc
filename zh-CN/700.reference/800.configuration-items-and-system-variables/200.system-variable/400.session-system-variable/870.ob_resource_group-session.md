# ob_resource_group

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>对于 V4.4.x 版本，该变量从 V4.4.2 BP4 版本开始引入。</p>
</main>

## 功能描述

`ob_resource_group` 用于为当前 Session 指定默认资源组。设置后，该 Session 上执行的 SQL 语句默认使用该资源组对应的 CPU 和 IOPS 资源。该变量的优先级高于 SQL 级（Column 映射）资源隔离和 User 级资源隔离，低于 `RESOURCE_GROUP` Hint。

该变量主要用于 SQL 由第三方生成、不便逐条添加 `RESOURCE_GROUP` Hint 的场景：应用在连接初始化阶段设置一次 `ob_resource_group`，该连接后续执行的 SQL 即默认按指定资源组调度。

## 权限要求

* 查询变量

  * `sys` 租户和所有用户租户均可以使用 `SHOW VARIABLES` 语句或视图 `SYS.TENANT_VIRTUAL_SESSION_VARIABLE`（Oracle 模式）及视图 `information_schema.SESSION_VARIABLES`（MySQL 模式）查看 Session 系统变量的值。

* 修改变量

  * `sys` 租户和所有用户租户均可以直接修改本租户的 Session 系统变量的值。

## 属性说明

| **属性** | **描述** |
|---------|---------|
| 参数类型 | varchar |
| 默认值 | 空字符串，表示不指定 Session 级默认资源组 |
| 取值范围 | 空字符串，或当前租户中已存在的资源组名称 |
| 生效范围 | Session |
| 是否可修改 | 是，支持通过 `SET` 语句（MySQL 模式）或 `ALTER SESSION SET` 语句（Oracle 模式）修改。 |

## 使用说明

* 该变量仅支持 Session 级别，不支持 Global 级别。即只对当前连接生效，不会影响其他连接，也不支持通过 `SET GLOBAL` 或 `ALTER SYSTEM` 设置。

* 设置时，OceanBase 数据库会校验资源组名称是否合法以及该资源组在当前租户中是否存在。如果资源组不存在，则返回错误，且该变量保留原有的取值：MySQL 模式返回 `ERROR 4710 (HY000): consumer group <资源组名称> does not exist`，Oracle 模式返回 `OBE-29368: consumer group <资源组名称> does not exist`。

* 该变量依赖当前租户已通过资源计划启用资源隔离。如果租户未配置资源计划，则所有资源组都不会生效，此时即使指定默认资源组 `OTHER_GROUPS`，同样会因资源组不存在而报错。

* 将变量设置为空字符串即可清除 Session 级默认资源组，该 Session 后续的 SQL 语句回落到 SQL 级资源隔离规则或 User 级资源隔离规则确定资源组。

* 该变量修改后立即生效，无需淘汰执行计划缓存。对于已缓存的执行计划，下次执行时同样按新的资源组调度。

* 一条 SQL 语句匹配资源组时，按以下顺序从高到低逐级判定，命中即停止：`RESOURCE_GROUP` Hint > Session 系统变量 `ob_resource_group` > SQL 级（Column 映射）资源隔离 > User 级资源隔离 > 默认资源组 `OTHER_GROUPS`。Function 级资源隔离作用于后台任务，不参与 SQL 语句的资源组匹配。

* 使用连接池时，建议在物理连接初始化或借出时设置该变量，并在连接被其他业务复用前重新设置或清空。否则，连接被复用后，后续请求可能会使用上一个业务设置资源组，导致请求串组。

## 配置示例

* MySQL 模式

  * 为当前 Session 指定资源组 `batch_group`。

    ```shell
    obclient> SET SESSION ob_resource_group = 'batch_group';
    ```

  * 查看当前 Session 的取值。

    ```shell
    obclient> SELECT @@session.ob_resource_group;
    ```

  * 清除 Session 级默认资源组。

    ```shell
    obclient> SET SESSION ob_resource_group = '';
    ```

* Oracle 模式

  * 为当前 Session 指定资源组 `batch_group`。

    ```shell
    obclient> ALTER SESSION SET ob_resource_group = 'batch_group';
    ```

  * 清除 Session 级默认资源组。Oracle 模式中空字符串等同于 `NULL`，以下两种写法效果相同。

    ```shell
    obclient> ALTER SESSION SET ob_resource_group = '';
    obclient> ALTER SESSION SET ob_resource_group = NULL;
    ```

* 在会话视图中查看 Session 级默认资源组。其中 `RESOURCE_GROUP` 列仅反映该 Session 配置的资源组名称，未配置时 MySQL 模式为空字符串、Oracle 模式为 `NULL`，不是 Hint 或资源隔离规则匹配后最终生效的资源组。

  * MySQL 模式

    ```shell
    obclient> SELECT id, user, resource_group
        -> FROM oceanbase.GV$OB_PROCESSLIST
        -> WHERE id = CONNECTION_ID();
    ```

  * Oracle 模式

    ```shell
    obclient> SELECT id, resource_group
        -> FROM SYS.GV$OB_PROCESSLIST
        -> WHERE id = SYS_CONTEXT('USERENV', 'SID');
    ```
