# 表组概述

在分布式数据库中，表的关系和数据分布对性能具有重要影响。为此，表组（Table Group）作为一种逻辑概念，多个表中的数据可能分布在不同的机器上，这在执行复杂的操作（例如 Join 查询或跨表事务）时，就会涉及到跨机器的通信，导致性能下降。表组支持非分区表和分区表。

## 什么是表组？

表组是一种将分区方式相同的表聚集在一起的结构。在分布式数据库中，特别是OceanBase中，表中用来进行数据分区的列被称为分区键。通过对分区键值进行 Hash 计算，可以锁定数据所归属的具体分区。一个表组内每个表的同号分区被称为一个分区组。

## 为什么使用表组？

表组的主要作用是减少或避免跨机器操作。在OceanBase数据库中，当创建分区或进行负载均衡时，一个分区组的所有分区会被放置在同一台机器上。这意味着只要操作的数据在同一个分区组内，就不会出现跨机器的操作，从而提高了查询效率和系统性能。

### OceanBase 的分区与表组

OceanBase数据库支持分区功能，以便满足扩展性和多点写入的需求。在进行分区时，OceanBase会在设计上保证具有相同分区方式（如相同的分区个数和相同的 Hash 计算算法）的表被聚集为一个表组。尽管数据库无法干涉用户的具体操作，但可以通过分析业务特点，大概率地确保某些操作所涉及的跨表数据能够位于同一分区组中。这种优化策略能显著提升数据库在复杂查询和事务处理中的性能。

### 实例说明

以学生表与班级表为例，假设这两个表都有班级 ID 列。用户可以将班级 ID 列作为分区键，这样同一班级的数据便会聚集到同一分区。这样，在进行班级 ID 的 JOIN 操作时，系统只需在该分区的机器上处理数据，而无需在所有分区上进行跨机操作。

对于分布式写事务，若需要在学生表中新增学生信息并在班级表中更新学生总数，虽然这两个操作在不同的表，但如果这两个表的相关分区均在同一台 OBServer 上，OceanBase 数据库对单机分布式事务执行进行了优化，使得这种操作相较于跨机器的分布式事务具有更好性能。

### 表组的限制与删除操作

由于表组内的表必须保持相同的分区方式，因此表组里的表不支持打破分区规则进行单独的分区操作。然而，通过对整个表组进行分区操作，可以同时更改组内所有表的分区。

当前的表组功能设计中，一个分区对应一个日志流，数据变动日志通过 Paxos 算法在主副本与备副本之间同步。如果涉及多分区的事务，则需要处理多个日志流的写入。因此，这类操作依旧需要进行分布式事务的管理。为了优化这种情况，OceanBase 支持将表组绑定，以确保同一分区组的跨表写事务可以在一个日志流中原子提交，将分布式事务优化为单机事务，从而提高执行效率。

然而，表组绑定也带来了一定的复杂性，使得从表组中删除表变得困难。目前，OceanBase 不支持直接删除表组中的表。用户需根据自身业务情况灵活使用表组功能，以最大化地发挥其优势。
