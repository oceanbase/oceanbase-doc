# 搜索索引（Search Index）

本文介绍 OceanBase 数据库 MySQL 模式下的搜索索引（Search Index）：其基于 GIN 实现，面向 JSON、ARRAY 等复杂类型提供全路径倒排能力，常用于混合搜索场景以及分析型数据库（如 ADB）能力替换场景。

## 能力概述

搜索索引在**单列**上构建统一的倒排结构，对列内**多条路径**的取值建立索引条目，从而在一条索引上同时支撑多种访问方式，例如：

* **等值**：指定路径下的标量等值匹配；
* **包含**：集合或嵌套结构中的成员/子结构包含关系；
* **范围**：有序类型上的区间条件；
* **全文检索**：路径下文本内容的关键词类检索。

与「为每个访问路径单独建函数索引」或「仅覆盖数组展开场景的多值索引」相比，搜索索引强调**一次建索引、覆盖多路径**，降低索引数量与维护成本，并便于应对半结构化数据中路径频繁变化或查询模式多样的情况。

## 与其他索引类型的关系

| 对比维度 | 搜索索引 | 函数索引 | 多值索引 |
|----------|----------|----------|----------|
| 典型数据 | JSON / ARRAY 等复杂类型 | 表达式计算结果 | 常配合 `CAST(... AS ... ARRAY)` 的 JSON 数组元素 |
| 路径覆盖 | 一条索引可对**多路径**建倒排 | 通常**一路径或一表达式**对应一条索引 | 面向**数组元素展开**等模式 |
| 访问能力 | 等值、包含、范围、全文等（依路径与类型） | 与表达式语义一致 | 以数组元素检索为主 |
| 与「搜索」体系 | 与**向量搜索、混合搜索**等场景衔接自然 | 通用加速 | 偏 JSON 数组类查询 |

**全文索引**面向 `CHAR` / `VARCHAR` / `TEXT` 等**整列文本**的分词与检索；搜索索引则面向**复杂类型内部路径**的检索需求，二者适用列类型与建模方式不同，可并存使用。

**向量索引**用于近似最近邻等向量检索；在混合搜索中，常与全文、标量条件组合。搜索索引可承担**半结构化路径条件**侧的能力，与向量、全文形成互补。

## 应用场景

### 混合搜索（Hybrid Search）

当业务表同时存在向量、全文、标量以及 **JSON/ARRAY/MAP** 上的过滤或检索条件时，需要在一次请求中组合多种谓词。搜索索引为复杂类型路径提供统一的倒排支撑，减少「每路径一索引」的组合爆炸，便于与 [索引混合搜索](../../../../../640.ob-vector-search/350.ob-vector-hybrid-search/200.ob-vector-index-hybrid-search.md) 所描述的混合搜索能力配合使用。

### 分析型数据库（ADB）能力替换

在从分析型数据库迁移或双跑时，常见需求包括对半结构化列按**任意路径**进行过滤与检索。搜索索引通过全路径倒排，更接近「单列多路径、一套索引」的建模方式，有利于迁移同类工作负载。

## 实现要点（概念层）

* **GIN（Generalized Inverted Index）**：以倒排方式组织路径与取值的索引项，支撑多类操作符与多路径共存。
* **全路径索引**：对列内可索引路径统一维护倒排，查询时按路径下推至索引访问，而非依赖为每个路径单独物化二级索引（具体下推与优化行为以实际版本与计划为准）。
