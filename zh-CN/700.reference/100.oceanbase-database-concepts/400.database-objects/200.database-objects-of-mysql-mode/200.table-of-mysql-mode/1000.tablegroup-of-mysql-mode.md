# 表组概述

在分布式数据库中，表的关系和数据分布对性能具有重要影响。为此，表组（Table Group）作为一种逻辑概念，用于优化关联表的分区分布，确保同号分区在同一个单元（Unit）内部，以减少跨节点请求对性能的影响。

## 什么是表组？

表组并不是一个物理对象，而是一个逻辑集合，表示一组具有相同分区策略和特性表。在表组内，所有表必须满足以下条件：

- 具有相同的 Locality（副本类型、数量及位置）
- 拥有相同的 Primary Zone（Leader 位置及其优先级）
- 采用相同的分区方式

通过定义表组，用户可以有效地控制表在物理存储上的邻近关系。一个包含分区表的表组由多个分区组（Partition Group）组成，每个分区组中包含一个分区的所有副本。系统会自动调度，确保同一分区组的所有分区位于同一台 OBServer 上，并且这些分区的 Leader 也会在同一台服务器上。

## 为什么使用表组？

在分布式数据库中，多个表中的数据可能分布在不同的机器上。在执行 JOIN 查询或跨表事务等复杂操作时，这种数据分散导致需要进行跨机器通信，进而影响数据库性能。表组功能的引入能够有效避免这些跨机器操作，从而显著提升数据库的性能。

### OceanBase 的分区与表组

OceanBase 数据库为了满足扩展性和多点写入等需求，支持将表的数据分成多个分区进行存储。分区键是参与具体数据分区的列，通过该列的值进行 Hash 计算，可以确定数据所在的分区。为了将分区方式相同的表聚集在一起，形成表组，要求同组内各表的分区数量和 Hash 计算方式一致。

![tablegroup](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/observer/kv/tablegroup.png)

在创建分区时，OceanBase 数据库会将一个分区组的所有分区放置于同一机器上，这样，无论是跨表操作还是 JOIN 查询，只要涉及的数据在同一分区组内，就可以避免跨机器操作。

### 实例说明

以学生表与班级表为例，假设这两个表都有班级 ID 列。用户可以将班级 ID 列作为分区键，这样同一班级的数据便会聚集到同一分区。这样，在进行班级 ID 的 JOIN 操作时，系统只需在该分区的机器上处理数据，而无需在所有分区上进行跨机操作。

对于分布式写事务，若需要在学生表中新增学生信息并在班级表中更新学生总数，虽然这两个操作在不同的表，但如果这两个表的相关分区均在同一台 OBServer 上，OceanBase 数据库对单机分布式事务执行进行了优化，使得这种操作相较于跨机器的分布式事务具有更好性能。

### 表组的限制与删除操作

由于表组内的表必须保持相同的分区方式，因此表组里的表不支持打破分区规则进行单独的分区操作。然而，通过对整个表组进行分区操作，可以同时更改组内所有表的分区。

当前的表组功能设计中，一个分区对应一个日志流，数据变动日志通过 Paxos 算法在主副本与备副本之间同步。如果涉及多分区的事务，则需要处理多个日志流的写入。因此，这类操作依旧需要进行分布式事务的管理。为了优化这种情况，OceanBase 支持将表组绑定，以确保同一分区组的跨表写事务可以在一个日志流中原子提交，将分布式事务优化为单机事务，从而提高执行效率。

然而，表组绑定也带来了一定的复杂性，使得从表组中删除表变得困难。目前，OceanBase 不支持直接删除表组中的表。用户需根据自身业务情况灵活使用表组功能，以最大化地发挥其优势。
