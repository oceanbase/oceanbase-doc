# 向量索引

HNSW 系列向量索引是 OceanBase 数据库针对稠密向量数据提供的、基于内存图结构的近似最近邻（ANN）索引类型，用于加速向量相似度搜索。该系列索引需要将索引数据完整载入内存，支持 DML 与实时检索，在召回率与查询延迟上表现较好，适用于向量检索、推荐、检索增强生成（RAG）等场景。

## 索引类型与特点

HNSW 系列包含三种索引类型，在内存占用、召回率与构建/查询性能之间提供不同取舍：

| 索引类型 | 说明 |
|----------|------|
| **HNSW** | 基于 HNSW（Hierarchical Navigable Small World）图结构的内存索引，索引列最大维度为 4096。构建与查询均不做向量量化，召回率最高，内存占用也最大。 |
| **HNSW_SQ** | 在 HNSW 图结构上引入标量量化（SQ），在保持与 HNSW 相近的构建速度、搜索性能和召回率的同时，将总内存占用降低到约 1/2～1/3。 |
| **HNSW_BQ** | 在 HNSW 图结构上引入二值量化（BQ，Rabitq 算法），将向量压缩至原大小的约 1/32，显著降低内存占用；召回率略低于 HNSW，维度越高内存优化效果越明显。 |

三者均为**局部索引**，按表分区组织；支持 L2、内积（IP）、余弦等距离算法，并与 OceanBase 的向量搜索语法与距离函数配合使用。

## 与存储和内存的关系

* HNSW 系列索引数据常驻内存，不落盘持久化为独立索引文件；分区内向量通过 Active Segment、Frozen Segment 等增量段管理，并通过配置项控制冻结、落盘及与基线的合并，详见向量搜索文档中的内存与持久化说明。
* 创建、重建或扩容向量数据时，需要保证租户有足够内存；可通过 `ob_vector_memory_limit_percentage` 等配置限制向量索引占用的内存比例，并通过系统包与视图进行内存估算与监控。

## 适用场景

* **在线向量检索**：需要低延迟、高召回的 ANN 查询（如相似商品、相似文档、以图搜图）。
* **RAG / 混合检索**：与全文检索、过滤条件结合，做混合排序与精排。
* **对内存可控的部署**：可在 HNSW、HNSW_SQ、HNSW_BQ 之间按内存与精度需求选择；数据量极大且对内存敏感时，可考虑结合 IVF 系列等非全内存索引方案。
