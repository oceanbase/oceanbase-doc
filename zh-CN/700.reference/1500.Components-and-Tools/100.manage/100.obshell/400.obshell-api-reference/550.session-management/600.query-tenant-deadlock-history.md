# 查询租户死锁历史

本文介绍如何通过 API 查询租户的死锁历史记录，支持分页功能。

## 调用说明

如果设置了密码，则需要通过认证。详情可参见 [API 混合加密](../20.api-hybrid-encryption.md)。

### 请求路径

GET /api/v1/tenant/:name/deadlocks

### 请求参数

| 参数 | 类型 | 必选 | 示例值 | 描述 |
| --- | --- | --- | --- | --- |
| name | string | 是 | t1 | 租户名称。该参数通过路径参数指定。 |
| page | uint64 | 否 | 1 | 页码，默认为 1。该参数通过 query param 指定。 |
| size | uint64 | 否 | 10 | 每页大小，默认为 2147483647。该参数通过 query param 指定。 |

### 返回结果

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| successful | bool | 请求是否成功。 |
| timestamp | time.Time | 服务端完成请求的时间戳。 |
| duration | int | 服务端处理请求的时间（毫秒）。 |
| status | int | 符合 HTTP Status 规范的编码。 |
| traceId | string | 请求的 Trace ID。 |
| data | PaginatedDeadLocks | 返回的分页死锁历史列表，包含如下信息：<ul><li>`contents`：死锁历史列表。详情参见下文 **DeadLock 的数据结构**。</li><li>`page`：分页信息。详情参见下文 **CustomPage 的数据结构**。</li></ul> |
| error | ApiError | 请求产生的 Error，包含如下信息：<ul><li>`code`：错误码。</li><li>`message`：错误详细信息。</li><li>`subErrors`：子错误信息。</li></ul> |

DeadLock 的数据结构：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| event_id | string | 死锁事件 ID，是死锁事件的唯一标识。 |
| report_time | time.Time | 死锁报告时间。 |
| size | int64 | 死锁环中的节点数量。 |
| nodes | []DeadLockNode | 死锁节点列表。详情参见下文 **DeadLockNode 的数据结构**。 |

DeadLockNode 的数据结构：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| svr_ip | string | 服务器 IP 地址。 |
| svr_port | int | 服务器端口。 |
| idx | int | 节点在死锁环中的索引编号。 |
| transaction_hash | string | 事务 Hash 值。 |
| roll_backed | bool | 是否已回滚。 |
| resource | string | 请求的资源。 |
| sql | string | 执行的 SQL 语句。 |

CustomPage 的数据结构：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| total_elements | uint64 | 总记录数。 |
| total_pages | uint64 | 总页数。 |
| size | uint64 | 每页大小。 |
| number | uint64 | 当前页码。 |
