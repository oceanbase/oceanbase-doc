# 触发巡检

本文介绍如何通过 API 触发集群巡检。巡检支持基础巡检（basic）和性能巡检（performance）两种场景。

## 调用说明

如果设置了密码，则需要通过认证。详情可参见 [API 混合加密](../20.api-hybrid-encryption.md)。

### 请求路径

POST /api/v1/obcluster/inspection

### 请求参数

| 参数 | 类型 | 必选 | 示例值 | 描述 |
| --- | --- | --- | --- | --- |
| scenario | string | 是 | basic | 巡检场景，支持 `basic`（基础巡检）或 `performance`（性能巡检）。大小写不敏感。 |

### 返回结果

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| successful | bool | 请求是否成功。 |
| timestamp | time.Time | 服务端完成请求的时间戳。 |
| duration | int | 服务端处理请求的时间（毫秒）。 |
| status | int | 符合 HTTP Status 规范的编码。 |
| traceId | string | 请求的 Trace ID。 |
| data | DagDetailDTO | 返回的任务 DAG 详情。详情参见下文 **DagDetailDTO 的数据结构**。 |
| error | ApiError | 请求产生的 Error，包含如下信息：<ul><li>`code`：错误码。</li><li>`message`：错误详细信息。</li><li>`subErrors`：子错误信息。</li></ul> |

DagDetailDTO 的数据结构：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| id | string | DAG 通用 ID。 |
| dag_id | int | DAG id，是记录在 OceanBase 数据库中的主键。 |
| name | string | DAG 名称。 |
| stage | int | DAG 的当前执行阶段。 |
| max_stage | int | DAG 执行过程中的总阶段数。 |
| state | string | DAG 执行状态。 |
| operator | string | DAG 执行操作类型。 |
| start_time | time.Time | DAG 执行起始时间。 |
| end_time | time.Time | DAG 执行结束时间。 |
| additional_data | map[string]any | DAG 其他数据。 |
| nodes | []NodeDetailDTO | DAG 内的所有 Node 信息，详见 [获取 Node 的详细信息](..//1000.task-management/2100.get-node-detail.md)。 |

## 示例

### 请求示例

POST 10.10.10.1:2886/api/v1/obcluster/inspection

```json
{
    "scenario": "basic"
}
```

## 巡检任务介绍

### 基础（BASIC）巡检任务

基础巡检任务主要关注 OceanBase 集群的稳定性和可用性，包括错误检查、日志检查、磁盘检查、表检查、租户检查、集群检查、归档检查、网络检查和系统检查等方面。这些巡检项旨在及时发现可能导致集群故障或数据丢失的潜在问题，确保集群能够稳定运行。基础巡检涵盖了从系统层面的内核参数、文件系统配置，到应用层面的死锁检测、Leader 选举、内存使用等各个维度的健康检查。

### 性能（PERFORMANCE）巡检任务

性能巡检任务主要关注 OceanBase 集群的性能优化和资源利用效率，包括索引优化、查询性能、压缩算法配置、网络性能、CPU 和磁盘 IO 性能等方面。这些巡检项旨在识别可能影响系统性能的配置问题或资源瓶颈，帮助优化集群的运行效率。性能巡检涵盖了从查询执行参数、缓存配置，到网络延迟、磁盘 IOPS、宏块利用率等性能相关的各个维度。
