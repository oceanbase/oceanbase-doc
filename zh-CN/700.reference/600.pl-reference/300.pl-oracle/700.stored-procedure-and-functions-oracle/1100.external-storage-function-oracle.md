# 外部存储函数

## Java UDF

Java UDF 是指用 Java 语言实现的用户自定义函数（User-Defined Function，通过 Java UDF 功能，可以实现在 PL/SQL 层调用 Java 语言实现的 UDF 或 Procedure，进一步拓宽了 PL 的使用场景。

### 构造并调用 Java UDF 函数

操作步骤如下：

1. jar 包编译

    <main id="notice" type='notice'>
    <h4>注意</h4>
    <p><ul><li>下述示例仅供学习使用，生产环境请使用 maven 等工具管理 Java 代码生命周期。</li><li>为了避免依赖问题，建议打 fat jar 包，即 <code>with-dependencies</code> jar 包。</p>
    </main>

    在当前版本，Java UDF 需要先编译成 jar 包再上传到 OBServer。
    您可以编译并打包下述代码为 `my_add.jar` 后，然后可以在 OBServer 中创建 Java UDF，代码如下：

    ```java
    package org.example;

    public class MyAdd {
        public static int myAddImpl(int a, int b) {
            int c = a + b;
            return c;
        }
    }
    ```

    之后使用 `javac` 命令将 MyAdd.java 编译成 jar 包（需要提前安装 JDK），命令如下：

    ```shell
    mkdir -p target && javac -g -d target MyAdd.java && cd target && jar cvf my_add.jar *
    ```

2. jar 包上传

    jar 包编译完成之后，需要上传到 OBServer 才能被 Java UDF 使用。在 OceanBase 数据库 Oracle 模式中，可以使用 `DBMS_JAVA.OB_LOADJAR` 来上传 jar 包。如果 jar 包在 OBServer 节点上，可以使用 `utl_file` 读取文件内容再上传；如果 jar 包在远程节点，可以使用 JDBC 上传。

    <main id="notice" type='explain'>
    <h4>说明</h4>
    <p><code>DBMS_JAVA.OB_LOADJAR</code> 接受两个参数，第一个参数是 <code>BLOB</code> 类型的 jar 包 <code>binary</code>，第二个参数是可选的 <code>flag</code>，若指定 <code>-F</code>，遇到同名类后则会覆盖之前的结果。</p>
    </main>

    **上传本地 jar 包**

    可以通过以下 PL/SQL 上传 OBServer 本地的 jar 包：

    ```sql
    -- jar 包所在的 directory
    CREATE OR REPLACE DIRECTORY JAR_DIR AS 'path/to/direcotry/of/jar';

    -- 读取并上传 jar 包
    DECLARE
    v_file      UTL_FILE.FILE_TYPE;
    v_buffer    RAW(32767);
    v_blob      BLOB;
    v_amount    BINARY_INTEGER := 32767;
    BEGIN

    DBMS_LOB.CREATETEMPORARY(v_blob, TRUE);

    v_file := UTL_FILE.FOPEN('JAR_DIR', 'my_add.jar', 'r');

    BEGIN
        LOOP
        UTL_FILE.GET_RAW(v_file, v_buffer, v_amount);
        DBMS_LOB.WRITEAPPEND(v_blob, UTL_RAW.LENGTH(v_buffer), v_buffer);
        END LOOP;
    EXCEPTION
        WHEN NO_DATA_FOUND THEN
        NULL;
    END;

    UTL_FILE.FCLOSE(v_file);

    -- -F for force
    DBMS_JAVA.OB_LOADJAR(v_blob, '-F');

    DBMS_LOB.FREETEMPORARY(v_blob);

    EXCEPTION
    WHEN OTHERS THEN
        IF UTL_FILE.IS_OPEN(v_file) THEN
        UTL_FILE.FCLOSE(v_file);
        END IF;
        IF DBMS_LOB.ISTEMPORARY(v_blob) = 1 THEN
        DBMS_LOB.FREETEMPORARY(v_blob);
        END IF;
        RAISE;
    END;
    /
    ```

    **上传远端 jar 包**

    可以通过以下 Java 代码通过 JDBC 上传在 OBServer 远端的 jar 包：

    ```sql
    // url is location of the jar
    void ob_loadjar(String url) throws IOException, SQLException {
        InputStream is = new URL(url).openStream();
        ByteArrayOutputStream baos = new ByteArrayOutputStream();

        {
            byte[] bytes = new byte[40960];
            int len;
            while ((len = is.read(bytes)) != -1) {
                baos.write(bytes, 0, len);
            }
        }

        PreparedStatement ps = conn.prepareStatement(
                "declare\n" +
                        "jar blob := ?;\n" +
                        "flags varchar2(64) := ?;\n" +
                        "begin\n" +
                        "dbms_java.ob_loadjar(jar ,flags);\n" +
                        "end;");

        Blob b = new com.oceanbase.jdbc.Blob(baos.toByteArray());
        ps.setBlob(1, b);
        ps.setString(2, "-F");  // -F for force
        ps.execute();
        Statement s = conn.createStatement();
    }
    ```

4. 创建 PL 函数

    在创建 PL UDF 或 Procedure 时，指定 `LANGUAGE JAVA` 子句表明该 PL 是一个 Java 函数/过程包装，再通过 `NAME` 子句指定入口方法签名，示例如下：

    ```sql
    create or replace function my_add(a number, b number) return number as
    LANGUAGE JAVA
    NAME 'org.example.MyAdd.myAddImpl(int, int) return int';
    /
    ```

    <main id="notice" type='explain'>
    <h4>说明</h4>
    <p><ul><li>PL 函数或过程包装仅能使用同 schema 下的 <code>Java Class</code>。</li><li>jar 包上传和 PL/SQL 包装创建没有严格的先后次序要求，只要保证 PL/SQL 包装调用时可以找到相应 Java 类对象即可。</li></p>
    </main>

### 使用限制

* 在 OceanBase 数据库 V4.4.2 BP1 版本暂不支持在 OBServer 侧通过 Java 源码创建 Java UDF。
* 源码中如果存在 `oracle.sql.BLOB`，需要使用 `java.sql.Blob` 代替。
* 源码中如果存在 `oracle.sql.CLOB`，需要使用 `java.sql.Clob` 代替。

### 沙箱模式

自 V4.4.2 BP3 版本开始，Java UDF 支持运行在独立的沙箱子进程中。开启沙箱模式后，JVM 与 Observer 主进程隔离运行，避免 JVM 异常影响数据库主进程。公有云部署场景建议开启。

开启方式：在开启 `ob_enable_java_udf` 和 `ob_enable_java_env` 配置项之后，设置 `ob_enable_java_udf_sandbox` 配置项为 `TRUE`。

```sql
ALTER SYSTEM SET ob_enable_java_udf_sandbox = TRUE;
```

更多信息请参考 [ob_enable_java_udf_sandbox](../../../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/16655.ob_enable_java_udf_sandbox.md)。
