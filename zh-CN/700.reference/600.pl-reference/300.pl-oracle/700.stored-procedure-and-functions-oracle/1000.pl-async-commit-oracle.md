# PL 异步提交优化

在 OceanBase 数据库中，存储过程（Stored Procedure）是用户业务逻辑的重要载体。当前实现中，存储过程内的事务提交采用同步方式，即工作线程在调用事务提交接口后，需要阻塞等待事务提交完成后才能返回。非极端情况下，本地事务提交耗时大多在微秒级，分布式事务耗时在毫秒级（主要是网络通信延迟），因此当出现分布式事务时，PL 整体延迟会大幅提高，吞吐量也会大幅下降。因此 V4.4.2 版本支持 PL 异步提交优化，缓解以上问题，进一步提升 PL 性能。

## 启用 PL 异步提交优化

使用 `ob_enable_pl_async_commit` 系统变量控制是否开启该优化。
当系统的吞吐量或 TPS 达不到业务要求时，可尝试打开 `ob_enable_pl_async_commit`，开启 PL 异步提交优化，大部分提交场景都会有一定的性能提升，高并发场景会大幅提高系统的吞吐量。

## 使用示例

1. 创建测试表。

    ```shell
    obclient> CREATE TABLE test1(a int);
    obclient> CREATE TABLE test2(a int);
    ```

2. 创建存储过程 `test`。

    ```shell
    obclient> create or replace procedure test(b int)
    as 
    begin 
    FOR i IN 1..b LOOP
        insert into test1 values(i);
        update test1 set a = i + b where a = i;
        delete from test1 where a = i;
        delete from test1 where a = i + b;
        commit;
        insert into test2 values(i);
        update test2 set a = i + b where a = i;
        delete from test2 where a = i;
        delete from test2 where a = i + b;
        commit;
    END LOOP;
    end;
    /
    ```

3. 性能对比测试执行。

    * 开启 PL 异步提交优化。

        ```shell
        obclient> SET GLOBAL ob_enable_pl_async_commit=ON;
        obclient> call test(10);
        Query OK, 0 rows affected (13.955 sec)
        ```

    * 关闭 PL 异步提交优化。

       ```shell
       obclient> SET GLOBAL ob_enable_pl_async_commit=OFF;
       obclient> call test(10);
       Query OK, 0 rows affected (19.408 sec)
       ```

    开启优化后耗时 `13.955s`。关闭优化后耗时 `19.408s`，性能明显提升。一次事务中处理的数据越多，事务越大，提交耗时越久，那么和 SQL 并行起来的效果就会越好，性能提升也越大。
