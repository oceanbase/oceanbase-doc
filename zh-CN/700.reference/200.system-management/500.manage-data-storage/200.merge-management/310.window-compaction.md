# 窗口合并

窗口合并（Window Compaction）是 OceanBase 数据库引入的一种全新的合并形式。用户可以在指定的时间窗口内执行增量式、按需式的合并。

## 背景信息

窗口合并实际调度的是分区级合并。在窗口合并期间，系统会收集各个分区的统计信息，并对每个分区进行评分。相关的评分因子包括：

* 增量行数 (inc_row_cnt)

* 距离上次合并的天数

* 表的查询频率（热度）

* 是否需要回收 MDS_INFO

* 列存或行存类型

进行窗口合并调度时，系统会尽量按从高优先级到低优先级的顺序调度。并按批次调度，限制租户内最多未执行的合并任务的数量，从而让合并任务的数量和结束时间可控。

## 使用限制及注意事项

* 同一时间内，租户合并与窗口合并只能存在一个，并且租户合并可以打断窗口合并。

* 窗口合并期间，不能通过 `ALTER SYSTEM SET` 语句修改租户级配置项 `compaction_low_thread_score` 的值。如果需要调整窗口合并的线程数，必须使用 `DBMS_DAILY_MAINTENANCE.SET_THREAD_COUNT()` 来设置，否则系统会报错。

## 前提条件

* 触发合并前，需要确保全局合并开关已开启，全局合并开关由集群级配置项 [enable_major_freeze](../../../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/7000.enable_major_freeze.md) 控制，默认值为 `True`，表示开启合并开关。

  如果当前集群未开启全局合并开关，请参考以下操作开启全局合并开关。

  1. 使用 `root` 用户登录集群的 `sys` 租户。

  2. 确认全局合并开关是否已开启。

     ```shell
     obclient(root@sys)[(none)]> SHOW PARAMETERS LIKE 'enable_major_freeze';
     ```

  3. 如果显示未开启，执行以下语句，开启合并开关。

     ```shell
     obclient(root@sys)[(none)]> ALTER SYSTEM SET enable_major_freeze='True';
     ```

* 如果需要触发窗口合并，需要确保租户级配置项 [enable_window_compaction](../../../800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/7000.enable_window_compaction.md) 为 `True`，即开启窗口合并。

  具体操作如下：

  1. 租户管理员登录集群的 MySQL 租户或 Oracle 租户。

  2. 确认租户级配置项 `enable_window_compaction` 的值。

     ```shell
     obclient> SHOW PARAMETERS LIKE 'enable_window_compaction';
     ```

  3. 如果值为 `True`，执行以下语句，开启窗口合并。

     ```shell
     obclient> ALTER SYSTEM SET enable_window_compaction = True;
     ```

## 配置周期性触发窗口合并

类似于每日统计信息的收集，对于当前版本的每个用户租户，都在定时任务调度器 `DBMS_SCHEDULER` 中注册了 `DAILY_MAINTENANCE_WINDOW` 任务，用户可以根据业务需要，灵活定义窗口合并任务的触发时间、执行时长等。

### 启用窗口合并任务

1. 租户管理员登录集群的 MySQL 租户或 Oracle 租户。

   连接示例如下，连接数据库时以实际环境为准。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql_tenant#obdemo -p***** -A
   ```

2. 调用 `DBMS_SCHEDULER` 系统包的 `ENABLE` 子程序，启用窗口合并。

   MySQL 模式与 Oracle 模式下的执行语句相同，示例如下：

   ```shell
   obclient> CALL DBMS_SCHEDULER.ENABLE('DAILY_MAINTENANCE_WINDOW');
   ```

启用窗口合并任务后，默认窗口合并的开始时间为凌晨 `02:00`，持续时间为 6 小时，周期为每天。

### 配置窗口合并任务下次开始的时间

启用窗口合并任务后，默认下次窗口合并任务的执行开始时间为凌晨 `02:00`，用户可以根据业务需要，配置窗口合并任务下次开始的时间。

1. 租户管理员登录集群的 MySQL 租户或 Oracle 租户。

   连接示例如下，连接数据库时以实际环境为准。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql_tenant#obdemo -p***** -A
   ```

2. 调用 `DBMS_SCHEDULER` 系统包的 `SET_ATTRIBUTE` 子程序，设置窗口合并任务下次开始的时间。

   语句如下：

   ```sql
   CALL DBMS_SCHEDULER.SET_ATTRIBUTE('DAILY_MAINTENANCE_WINDOW','NEXT_DATE', 'next_time');
   ```

   语句中，`next_time` 用于指定窗口合并任务下次开始的时间。

   例如，设置窗口合并下次开始的时间为 `2025-08-30 00:00:00`。MySQL 模式与 Oracle 模式下的执行语句相同，示例如下：

   ```shell
   obclient> CALL DBMS_SCHEDULER.SET_ATTRIBUTE('DAILY_MAINTENANCE_WINDOW', 'NEXT_DATE', '2025-08-30 00:00:00');
   ```

### 配置窗口合并任务的时长

启用窗口合并任务后，默认窗口合并任务的执行时长为 6 小时，用户可以根据业务需要，适当调整执行时长。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>修改当前任务的属性会影响正在执行的任务本身。例如，修改 <code>duration</code>的值将会影响当前正在执行的窗口合并任务。</p>
</main>

1. 租户管理员登录集群的 MySQL 租户或 Oracle 租户。

   连接示例如下，连接数据库时以实际环境为准。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql_tenant#obdemo -p***** -A
   ```

2. 调用 `DBMS_SCHEDULER` 系统包的 `SET_ATTRIBUTE` 子程序，设置窗口合并任务的执行时长。

   语句如下：

   ```sql
   CALL DBMS_SCHEDULER.SET_ATTRIBUTE('DAILY_MAINTENANCE_WINDOW', 'DURATION', duration);
   ```

   语句中，`duration` 用于指定窗口合并任务的执行时长，单位为秒。

   <main id="notice" type='notice'>
   <h4>注意</h4>
   <p>如果 `duration` 的值设置为（86400）24 小时，则表示永久窗口，即持续执行窗口合并。生产环境下需谨慎配置，建议设置合理的时间窗口。</p>
   </main>

   例如，设置窗口合并任务的时长为 10 小时，即 36000 秒。MySQL 模式与 Oracle 模式下的执行语句相同，示例如下：

   ```shell
   obclient> CALL DBMS_SCHEDULER.SET_ATTRIBUTE('DAILY_MAINTENANCE_WINDOW', 'DURATION', 36000);
   ```

## 调整窗口合并的线程数

窗口合并期间，其合并线程数不受租户级配置项 `compaction_low_thread_score` 的控制，默认由后台按照租户相关配置自适应计算合并线程数。用户也可以根据业务需要，调整窗口合并的线程数。

1. 租户管理员登录集群的 MySQL 租户或 Oracle 租户。

   连接示例如下，连接数据库时以实际环境为准。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql_tenant#obdemo -p***** -A
   ```

2. 调用 `DBMS_DAILY_MAINTENANCE` 系统包的 `SET_THREAD_COUNT` 子程序，设置窗口合并专用的合并线程数。

   例如，设置窗口合并的后台合并线程 COMPACTION_LOW 的线程数为 8。MySQL 模式与 Oracle 模式下的执行语句相同，示例如下：

   ```shell
   obclient> CALL DBMS_DAILY_MAINTENANCE.SET_THREAD_COUNT(8);
   ```

## （可选）配置窗口合并的资源管理计划

在开启了 cgroup 的集群上，窗口合并支持在合并期间切换到特定的资源管理计划，从而给合并任务提供更多的合并资源，让合并能够更快地执行，并覆盖充分多的分区，以确保业务高峰期时对分区操作的效率。

1. 租户管理员登录集群的 MySQL 租户或 Oracle 租户。

2. 调用 `DBMS_RESOURCE_MANAGER` 系统包中的 `CREATE_CONSUMER_GROUP` 子程序，创建窗口合并专用资源组。

   <main id="notice" type='notice'>
   <h4>注意</h4>
   <p>窗口合并的资源租名称 <code>INNER_DAILY_WINDOW_COMPACTION_LOW_GROUP</code> 为固定名称，不能随意变更。。</p>
   </main>

   MySQL 模式与 Oracle 模式下的执行语句相同，示例如下：

   ```shell
   obclient> CALL DBMS_RESOURCE_MANAGER.CREATE_CONSUMER_GROUP(
     CONSUMER_GROUP => 'INNER_DAILY_WINDOW_COMPACTION_LOW_GROUP',
     COMMENT => 'consumer group for daily window maintenance job'
   );
   ```

3. 调用 `DBMS_RESOURCE_MANAGER` 系统包中的 `CREATE_PLAN` 子程序，创建窗口合并专用资源计划。

   <main id="notice" type='notice'>
   <h4>注意</h4>
   <p>窗口合并的资源管理计划名称 <code>INNER_DAILY_WINDOW_PLAN</code> 为固定名称，不能随意变更。。</p>
   </main>

   MySQL 模式与 Oracle 模式下的执行语句相同，示例如下：

   ```shell
   obclient> CALL DBMS_RESOURCE_MANAGER.CREATE_PLAN(
     PLAN => 'INNER_DAILY_WINDOW_PLAN',
     COMMENT => 'plan for daily window maintenance job'
   );
   ```

4. 调用 `DBMS_RESOURCE_MANAGER` 系统包中的 `CREATE_PLAN_DIRECTIVE` 子程序，创建资源管理计划对应的资源管理计划内容。

   MySQL 模式与 Oracle 模式下的执行语句相同，示例如下：

   ```shell
   obclient> CALL DBMS_RESOURCE_MANAGER.CREATE_PLAN_DIRECTIVE(
     PLAN => 'INNER_DAILY_WINDOW_PLAN',
     GROUP_OR_SUBPLAN => 'INNER_DAILY_WINDOW_COMPACTION_LOW_GROUP',
     COMMENT => 'directive for window compaction',
     MAX_IOPS => 100,
     MIN_IOPS => 30,
     WEIGHT_IOPS => 50,
     UTILIZATION_LIMIT => 100,
     MGMT_P1 => 70
   );
   ```

配置成功后，当窗口合并任务开始执行时，系统会自动将当前的资源管理计划切换为窗口合并专用的资源计划 `INNER_DAILY_WINDOW_PLAN`，并将当前 COMPACTION_LOW 的 Function 线程（后台合并任务线程）的资源映射到窗口合并专用资源组 `INNER_DAILY_WINDOW_COMPACTION_LOW_GROUP` 上。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>配置窗口合并的资源管理计划后，窗口合并期间，不能删除窗口合并专用的资源计划 <code>INNER_DAILY_WINDOW_PLAN</code> 和窗口合并专用资源组 <code>INNER_DAILY_WINDOW_COMPACTION_LOW_GROUP</code>。如果尝试修改</p>
</main>

## 配置触发一次窗口合并

启用窗口合并任务后，如果还未到窗口合并任务指定的执行时间，用户可以根据业务需要，指定某个时间戳作为窗口合并的开始时间，尽快触发一次窗口合并。

<main id="notice" type='notice'>
<h4>注意</h4>
<ul><li>仅允许用户租户触发一次窗口合并，系统租户（<code>sys</code> 租户）不支持触发一次窗口合并。</li>
<li>触发一次窗口合并配置成功后，到达指定时间后，如果指定时间内仍存在未完成的租户合并，则窗口合并将无法发起。</li></ul>
</main>

1. 租户管理员登录集群对应的 MySQL 租户或 Oracle 租户。

   连接示例如下，连接数据库时以实际环境为准。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql_tenant#obdemo -p***** -A
   ```

2. 调用 `DBMS_DAILY_MAINTENANCE` 系统包的 `TRIGGER_WINDOW_COMPACTION_PROC` 子程序，触发一次窗口合并。

   MySQL 模式与 Oracle 模式下的执行语句相同，示例如下：

   ```shell
   obclient> CALL DBMS_DAILY_MAINTENANCE.TRIGGER_WINDOW_COMPACTION_PROC();
   ```

## 禁用窗口合并任务

如果不期望再触发窗口合并，可以调用 `DBMS_SCHEDULER` 系统包的 `DISABLE` 子程序禁用窗口合并任务。禁用后，如果租户级配置项 `enable_window_compaction` 的值仍为 `True`，则系统既不会触发窗口合并，也不会触发每日租户合并。如果期望触发每日租户合并，则需要将租户级配置项 `enable_window_compaction` 的值设置为 `False`。有关每日租户合并的详细说明，参见 [定时触发每日租户合并](300.scheduled-trigger-merge.md)。

1. 租户管理员登录集群的 MySQL 租户或 Oracle 租户。

   连接示例如下，连接数据库时以实际环境为准。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql_tenant#obdemo -p***** -A
   ```

2. 调用 `DBMS_SCHEDULER` 系统包的 `DISABLE` 子程序，禁用窗口合并。

   MySQL 模式与 Oracle 模式下的执行语句相同，示例如下：

   ```shell
   obclient> CALL DBMS_SCHEDULER.DISABLE('DAILY_MAINTENANCE_WINDOW');
   ```
