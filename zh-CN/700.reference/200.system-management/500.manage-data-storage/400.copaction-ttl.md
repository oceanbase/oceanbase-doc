# 过期数据删除

OceanBase 数据库的 TTL by Compaction 提供了过期数据的删除功能，支持对表定义 TTL（Time To Live）策略，然后系统自动处理已过期数据。TTL 用于设置数据的有效期，执行过期数据任务后超过有效期的数据将会不可见，但是数据未实际删除，过期数据占用的存储空间需要在 Compaction（合并）任务执行后才会释放。本文主要介绍如何通过命令或者设置周期性任务两种方式来发起过期数据（TTL）任务。

## 背景信息

不同于 KV 模式下的 TTL 能力，SQL 模式的关系表定义的 TTL 是在合并时异步地进行数据的删除，不占用 Clog 和写入的带宽，删除信息仅在 Oceanbase 数据库内部识别，不会同步给下游的其他应用系统。

TTL by Compaction 功能的内部实现原理如下：

1. 当 TTL 任务被触发时，具有 TTL 属性的表及其索引表、辅助表会通过事务同步一个标记删除的规则信息，满足规则的数据行会被标记为删除，数据被标记删除后就会对用户不可见。

2. 对于标记删除的数据，在下次执行 Compaction（合并）时，系统会将数据从存储层彻底删除，以便释放存储空间。

在此之前，OceanBase 数据库已实现了动态分区管理功能，但受限于其分区规则主要以时间划分，写入容易集中在一个分区里形成瓶颈，而通过 Truncate 分区来完成数据清理又会影响全局索引，而 Compaction TTL 功能则没有该问题。因此，在使用动态分区管理功能和 TTL by Compaction 功能时：

* 如果用户的业务对于数据写入带宽没有太大的需求，并且业务分区规则可以按时间分区，则可以使用动态分区管理功能。

* 如果用户的业务对于写入带宽的需求较大，并且 rowkey 范围临近的数据过期时间也较为接近，例如，写入是按照 rowkey 近似递增的顺序写入，则使用 Compaction TTL 功能更有优势。

## 注意事项

* 在 TTL 任务同步标记删除信息时，会对表加锁，与旁路导入、DDL、Transfer 等操作互斥。

* 当主表、索引表、辅助表等所有分区数超过 4000 时，可能会发生事务超时，导致标记删除信息的任务一直失败重试，可以通过调大超时时间解决，语句如下。

  ```shell
  obclient(root@sys)[(none)]> ALTER SYSTEM SET internal_sql_execute_timeout = 600; /*sys 租户下执行，单位为秒*/
  ```

* 由于标记删除信息的事务与普通 DML 事务不互斥，当两个事务并发且事务隔离级为 Read Committed，在 DML 事务内查询临近过期的数据时，可能会遇到幻读。

  例如，假设有一个标记删除信息的事务 `trans_A` 和一个普通 DML 事务 `trans_B`，以及临近过期的数据行 `rowkey_A`，在 T1 ~ T3（T1 < T2 < T3）这段时间内：

  1. 在 T1 时间点：数据行 `rowkey_A` 未达到过期时间，普通 DML 事务 `trans_B` 可以读取到 `rowkey_A` 的数据。
  2. 在 T2 时间点：数据行 `rowkey_A` 达到过期时间，标记删除信息的事务 `trans_A` 将 `rowkey_A` 标记为删除。
  3. 在 T3 时间点：普通 DML 事务 `trans_B` 再次读取 `rowkey_A`，发现已读取不到该数据。

* 当 TTL 任务未执行时，用户可以查询到表中符合过期规则的数据，若用户对过期数据有严格的可见性要求，需要在查询 SQL 中添加过滤条件。

* 在主表及其索引上执行 Offline DDL、新建索引的操作后，由于 DDL 内部实现逻辑，数据行中 ora_rowscn 信息会改写为 DDL 选择的位点，导致行真实的提交 rowscn 丢失，使得数据行的过期时间会延后。

## TTL 表的定义

### 使用限制

使用 TTL by Compaction 功能进行过期数据的删除时，对 TTL 表有以下限制

* 不支持外键约束。

* 不支持触发器。

* 不支持向量索引、全文索引。

* 仅支持 TTL 列为单列，不支持 TTL 列为虚拟列、生成列、表达式。

* 不支持表更新模式 `MERGE_ENGINE` 为 `partial_update`。

* 当前版本仅支持 TTL 列为内部隐藏列 `ora_rowscn`（近似于 rowkey，记录最后一次更新的时间戳）。

* 创建 TTL 表时，不允许添加列名为 `ora_rowscn` 的列。

### 创建具有 TTL 属性的表

创建 TTL 表的语句如下：

```sql
CREATE TABLE table_name (table_definition_list) MERGE_ENGINE = {append_only | delete_insert}
   TTL [=] col_name + INTERVAL interval_num ttl_unit BY COMPACTION;
```

语句中相关参数说明如下：

* `MERGE_ENGINE`：指定表的更新模式。当前不支持表更新模式 `MERGE_ENGINE` 为 `partial_update`。

* `col_name`：指定 TTL 过滤列。当前版本仅支持指定列名为 `ora_rowscn`（内部隐藏列，记录数据最后一次更新的时间戳）。

* `interval_num`：指定过期时间的整数数值，取值范围 [0,+∞)。值为 `0` 时，时间单位 `ttl_unit` 可以为取值中的任意值，表示数据一旦提交即过期。

* `ttl_unit`：指定过期时间的单位。取值支持 `SECOND`、`MINUTE`、`HOUR`、`DAY`、`MONTH` 或 `YEAR`。

例如，创建一个数据过期策略为 7 天的 TTL 表。

```shell
obclient> CREATE TABLE ttl_tbl1(
   id INT PRIMARY KEY,
   val VARCHAR(100)
) MERGE_ENGINE = append_only TTL ora_rowscn + INTERVAL 7 DAY BY COMPACTION;
```

TTL 表创建成功后，可以根据业务实际情况，修改表的数据过期策略，语句如下：

```shell
obclient> ALTER TABLE ttl_tbl1 SET TTL ora_rowscn + INTERVAL 1 HOUR BY COMPACTION;
```

同样，如果不再需要使用过期数据删除功能，可以删除表的数据过期策略，语句如下。

```shell
obclient> ALTER TABLE ttl_tbl1 REMOVE TTL;
```

## 发起过期数据（TTL）任务

### 开启 TTL by Compaction 功能

发起 TTL 任务要求当前租户已开启 TTL by Compaction 功能。

TTL by Compaction 功能的开关由租户级配置项 [enable_ttl]（../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/3020.enable_ttl.md）（值为 `True`）控制，该配置项在新建租户、恢复租户的场景下其默认值均为 `False`，需要用户手动开启。

1. 管理员用户登录到集群的 `sys` 租户或用户租户。

   连接示例如下，连接数据库时请以实际环境为准。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysqltenant#obdemo -p***** -A
   ```

2. 执行以下语句，开启 TTL by Compaction 功能。

   * 系统租户为指定租户开启 TTL by Compaction 功能。

      ```shell
      obclient(root@sys)[(none)]> ALTER SYSTEM SET enable_ttl = True TENANT = tenant_name;
      ```

   * 用户租户为本租户开启 TTL by Compaction 功能。

      ```shell
      obclient> ALTER SYSTEM SET enable_ttl = True;
      ```

### 手动触发过期数据（TTL）任务

开启 TTL by Compaction 功能后，用户可以手动触发一次过期数据任务。

1. 管理员用户登录到集群的 `sys` 租户或用户租户。

   连接示例如下，连接数据库时请以实际环境为准。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. 执行以下命令，手动触发一次 TTL 任务。

   * 系统租户为所有用户租户触发一次 TTL 任务。

      ```shell
      obclient(root@sys)[(none)]> ALTER SYSTEM TRIGGER TTL TENANT = all_user;
      ```

      <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>不支持系统租户通过 <code>ALTER SYSTEM TRIGGER TTL TENANT = all_meta;</code> 语句为所有 Meta 租户触发 TTL 任务。</p>
      </main>

   * 系统租户为指定租户触发一次 TTL 任务。

      ```shell
      obclient> ALTER SYSTEM TRIGGER TTL TENANT = tenant_name;
      ```

   * 用户租户为本租户触发一次 TTL 任务。

      ```shell
      obclient> ALTER SYSTEM TRIGGER TTL;
      ```

### 配置定时触发过期数据（TTL）任务的时间

开启 TTL by Compaction 功能后，系统会根据租户下 TTL 表的数据过期情况，定时触发过期数据任务。定时触发 TTL 任务的时间通过租户级配置项 [ttl_duty_time](../../800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/8095.ttl_duty_time.md) 控制，默认触发时间为每天的凌晨 `01:00`。

`ttl_duty_time` 的时刻点与租户的时区相同，建议设置在租户的业务低峰期、租户每日合并发起之前。例如，修改为凌晨 `02:00`。

修改定时触发时间的操作如下:

1. 管理员用户登录到集群的 `sys` 租户或用户租户。

   连接示例如下，连接数据库时请以实际环境为准。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysqltenant#obdemo -p***** -A
   ```

2. 执行以下语句，修改 TTL 任务的定时触发时间。

   * 系统租户为指定租户修改定时触发时间。

     ```shell
     obclient(root@sys)[(none)]> ALTER SYSTEM SET ttl_duty_time = '02:00' TENANT = tenant_name;
     ```

   * 用户租户为本租户修改定时触发时间。

      ```shell
      obclient> ALTER SYSTEM SET ttl_duty_time = '02:00';
      ```

## TTL 任务状态

TTL 任务执行过程中，可以通过视图 `CDB_OB_TTL_TASKS`（`sys` 租户）或  `DBA_OB_TTL_TASKS`（用户租户）来查看正在执行过程中的 TTL 任务详情，包含表信息、开始时间、修改时间、执行状态等。

* 系统租户

   ```shell
   obclient(root@sys)[(none)]> SELECT * FROM oceanbase.CDB_OB_TTL_TASKS;
   ```

* 用户租户

   ```shell
   obclient(root@mysqltenant)[(none)]> SELECT * FROM oceanbase.DBA_OB_TTL_TASKS; /*MySQL 模式*/
   ```

   ```shell
   obclient(root@oracletenant)[SYS]> SELECT * FROM SYS.DBA_OB_TTL_TASKS; /*Oracle 模式*/
   ```

用户租户下查询结果的示例如下：

```shell
+------------+----------+---------+----------------------------+----------------------------+--------------+------------+------------+------------+
| TABLE_NAME | TABLE_ID | TASK_ID | START_TIME                 | MODIFIED_TIME              | TRIGGER_TYPE | STATUS     | RET_CODE   | TASK_TYPE  |
+------------+----------+---------+----------------------------+----------------------------+--------------+------------+------------+------------+
| NULL       |       -1 |       1 | 2026-01-28 17:31:27.624387 | 2026-01-28 17:31:27.624387 | USER         | TRIGGERING | OB_SUCCESS | COMPACTION |
+------------+----------+---------+----------------------------+----------------------------+--------------+------------+------------+------------+
1 row in set
```

查询结果中，相关字段的详细说明，参见 [CDB_OB_TTL_TASKS](../../700.system-views/300.system-view-of-sys-tenant/200.dictionary-view-of-sys-tenant/11820.o-cdb_ob_ttl_tasks-of-sys-tenant.md) 和 [DBA_OB_TTL_TASKS](../../700.system-views/700.system-views/400.system-view-of-mysql-mode/200.dictionary-view-of-mysql-mode/15660.o-dba_ob_ttl_tasks-of-mysql-mode.md)。

TTL 任务执行结束后，还可以通过视图 [CDB_OB_TTL_TASK_HISTORY（sys 租户）](../../700.system-views/300.system-view-of-sys-tenant/200.dictionary-view-of-sys-tenant/11830.o-cdb_ob_ttl_task_history-of-sys-tenant.md) 或 [DBA_OB_TTL_TASK_HISTORY（用户租户）](../../700.system-views/700.system-views/400.system-view-of-mysql-mode/200.dictionary-view-of-mysql-mode/15670.o-dba_ob_ttl_task_history-of-mysql-mode.md) 来查看已完成的 TTL 任务历史。
