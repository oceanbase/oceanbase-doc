## ERROR 10516 (HY000) : When invoking the Increment interface, only HBase cells with a length of 8 can be converted to int64_t. the current length of the HBase cell is '%d'

* OceanBase 错误码：10516

* 错误原因：在 OBKV-HBase 中使用 Increment 接口时，要求要进行加减操作的 cell 的值（value）必须是 8 字节的 long 类型（Java long/int64），并且采用大端格式（Big-Endian，表示高位字节放在前面，低位字节放在后面）。如果不是 8 字节 long，操作会失败。常见原因如下：

  * 客户端写入的增量数据不是 8 字节 long，比如写成了字符串、文本、int32 等格式，未用 long 类型编码。
  * 该列之前用 Put 或 Append 写入过不是 8 字节的数据（比如字符串、变长二进制等），导致当前值类型不是 long。

* 解决方法如下：

  * 客户端写入增量数据时，务必以 8 字节大端 long（Java 可用 org.apache.hadoop.hbase.util.Bytes.toBytes(long)）编码。
  * 如果某个 cell 已经有数据且不是 long，可先删除或覆盖为合法的 8 字节 long 后再进行 Increment 操作。

## ERROR 11032 (HY000) : HDFS path message %s

* OceanBase 错误码：11032

* 错误原因：出现 HDFS path message %s 报错，通常见于以下场景：

  1. 开启 Kerberos 认证的 HDFS 环境中，访问某 HDFS 外部表时，若权限不足导致无法访问，会出现 -11032 错误。

  2. 若 Kerberos 认证配置正确，但仍出现 HDFS: path not found，可能是创建外部表语句中指定的外部表路径错误，指向了不存在的路径。

  3. 外部表访问初期正常，但执行查询一段时间后出现 11032 报错，可能是 HDFS 对应外部表路径下的某个文件出现坏块，即 HDFS DataNode 报告该数据块出错、无法访问，进而触发报错。

* 解决方法：
  1. 确认 Kerberos 认证的 keytab、principal 有效且对应用户拥有 HDFS 集群的访问权限，重新配置外部表权限并设置 Kerberos 认证即可。

  2. 确认对应的 HDFS 路径正确且存在，重新建立外部表的 HDFS 路径映射。

  3. 反馈至客户运维团队，确认数据坏块情况后，可选择调整坏块或更换环境继续验证。

## ERROR 11042 (HY000) : HDFS: malformed uri

* OceanBase 错误码：11042

* 错误原因：

  * URI 缺少 `hdfs://` 前缀。

  * URI 缺少路径部分，即 `hdfs://authority` 后面没有 `/path`。

* 解决方法：

  * 确保 URI 格式为 `hdfs://<namenode>:<port>/<path>`，要求包含完整的 scheme、authority 和 path 三部分。

  * 检查外部表或备份配置中的 `LOCATION` 字段的拼写是否正确。

## ERROR 11043 (HY000) : HDFS: invalid argument

* OceanBase 错误码：11043

* 错误原因：

  * HDFS 的 URI 格式错误
  * Kerberos 认证配置错误
  * HDFS 客户端环境未初始化或无效
  * HDFS 连接参数无效
  * HDFS 配置项设置失败

* 解决方法：

  * 检查 HDFS 的 URI 格式是否正确，HDFS 相关配置是否完整。
  * 确认 Kerberos 认证所需的文件（keytab、krb5.conf、ticket cache）存在且路径正确。
  * 检查 HDFS 集群网络的连通性，确保 namenode 可访问。
  * 检查 HDFS 自定义配置项的 `key=value` 的格式是否正确，确保没有空 key 或空 value。

## ERROR 11045 (HY000) : HDFS error

* OceanBase 错误码：11045

* 错误原因：

  * 重复访问，可能是已经打开的文件被再次尝试打开。

  * 在 HDFS 未成功建立连接时，就尝试执行了 delete、mkdir、list 等操作。

  * 文件删除失败，可能是文件不存在或权限不足等。

  * 目录创建失败

  * 写入失败

  * Flush 失败

* 解决方法：

  * 检查 HDFS 文件或目录权限，确认当前用户是否有读写以及删除权限。

  * 确认目标路径是否存在且格式正确。

  * 确认 HDFS 组件的生命周期管理正确，避免出现重复访问或者未成功建立连接就操作的情况。

  * 检查 HDFS 集群的磁盘空间是否充足。

## ERROR 11063 (HY000) : missing format for external table

* OceanBase 错误码：11063

* 错误原因：创建外表时，未指定文件格式或 DDL 语句中未出现有效的格式配置。

* 解决方法：

  * 在 `CREATE EXTERNAL TABLE` 语句中补充 `FORMAT` 子句，并指定与真实文件一致的 `TYPE`。

  * 确认 `TYPE` 与实际文件扩展名以及内容是否一致（例如，目录下是 `.parquet` 文件，应使用 `PARQUET`，不要用 `CSV`）。

  * 若使用 `CSV`，按需补充分隔符、编码等参数，避免建表成功但查询解析异常。

## ERROR 11064 (HY000) : missing access path for external table

* 解决方法：

  * 在 DDL 语句中补充 `LOCATION`，指向实际存放外部数据的目录或 URL。

  * 确认路径对 OceanBase 集群可访问（网络、鉴权、挂载、对象存储 AK/SK 等按环境配置）。

  * 若使用 Location 对象，先确认对象已创建且当前用户具备读权限，再在外表上引用。

  * 路径建议使用与相关人员约定一致的协议前缀（如 `file://`、`oss://`、`hdfs://` 等，以当前版本支持为准）。
