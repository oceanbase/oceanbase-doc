## ERROR 10516 (HY000) : When invoking the Increment interface, only HBase cells with a length of 8 can be converted to int64_t. the current length of the HBase cell is '%d'

* OceanBase 错误码：10516

* 错误原因：在 OBKV-HBase 中使用 Increment 接口时，要求要进行加减操作的 cell 的值（value）必须是 8 字节的 long 类型（Java long/int64），并且采用大端格式（Big-Endian，表示高位字节放在前面，低位字节放在后面）。如果不是 8 字节 long，操作会失败。常见原因如下：

  * 客户端写入的增量数据不是 8 字节 long，比如写成了字符串、文本、int32 等格式，未用 long 类型编码。
  * 该列之前用 Put 或 Append 写入过不是 8 字节的数据（比如字符串、变长二进制等），导致当前值类型不是 long。

* 解决方法如下：

  * 客户端写入增量数据时，务必以 8 字节大端 long（Java 可用 org.apache.hadoop.hbase.util.Bytes.toBytes(long)）编码。
  * 如果某个 cell 已经有数据且不是 long，可先删除或覆盖为合法的 8 字节 long 后再进行 Increment 操作。

## ERROR 11042 (HY000) : HDFS: malformed uri

* OceanBase 错误码：11042

* 错误原因：

  * URI 缺少 `hdfs://` 前缀。

  * URI 缺少路径部分，即 `hdfs://authority` 后面没有 `/path`。

* 解决方法：

  * 确保 URI 格式为 `hdfs://<namenode>:<port>/<path>`，要求包含完整的 scheme、authority 和 path 三部分。

  * 检查外部表或备份配置中的 `LOCATION` 字段的拼写是否正确。

## ERROR 11043 (HY000) : HDFS: invalid argument

## ERROR 11045 (HY000) : HDFS error

* OceanBase 错误码：11045

* 错误原因：

  * 重复访问，可能是已经打开的文件被再次尝试打开。

  * 在 HDFS 未成功建立连接时，就尝试执行了 delete、mkdir、list 等操作。

  * 文件删除失败，可能是文件不存在或权限不足等。

  * 目录创建失败

  * 写入失败

  * Flush 失败

* 解决方法：

  * 检查 HDFS 文件或目录权限，确认当前用户是否有读写以及删除权限。

  * 确认目标路径是否存在且格式正确。

  * 确认 HDFS 组件的生命周期管理正确，避免出现重复访问或者未成功建立连接就操作的情况。

  * 检查 HDFS 集群的磁盘空间是否充足。

## ERROR 11046 (HY000) : Invalid path: %.*s

* OceanBase 错误码：11046

* SQLSTATE：HY000

* 错误原因：

  * DDL 中输入的列名或路径与文件中列名的拼写或大小写不一致（Parquet、ORC、Arrow 等通常对大小写敏感）。

  * 嵌套结构路径输入错误。例如，需要访问的是 `addr.city`，但 DDL 中写成了 `addr_city` 或 `address.city`。

  * 同一外表下，部分文件缺少该列。

  * 格式符号问题。例如，列名前后多了空格、引号或者转义错误。

* 解决方法：

  * 确认 DDL 语句中外部列上的 `data_access_path` 或 `EXTERNAL_FILE_COLUMN_PATTERN` 是否真实存在于文件的 Schema 中。

  * 嵌套类型时，使用文件实际的层级路径分隔符进行精确匹配。

  * 若不同分区文件的 Schema 不同，对缺失列的部分单独创建外部表，或为该列设置 default value，避免直接使用 path 映射缺失列。

  * 修改错误的列定义，重新创建外部表。

## ERROR 11127 (HY000) : Privilege not allowed for sensitive rules

* OceanBase 错误码：11127

* 错误原因：用户没有权限执行敏感规则命令。该报错只有在执行 `GRANT PLAINACCESS ON SENSITIVE RULE '%.*s' TO '%.*s'@'%.*s'` 语句时会产生，表示执行 `GRANT` 语句的用户没有 `'%.*s'` 这条敏感规则的 `PLAINACCESS` 权限（或者有这个权限，但是没有 `GRANT OPTION`），不能将这个权限授予其他用户。

* 解决方法：需要其他有该规则的 `PLAINACCESS WITH GRANT OPTION` 权限的用户，对这个用户赋予对应的 `PLAINACCESS WITH GRANT OPTION` 权限。

<main id="notice" type='explain'>
