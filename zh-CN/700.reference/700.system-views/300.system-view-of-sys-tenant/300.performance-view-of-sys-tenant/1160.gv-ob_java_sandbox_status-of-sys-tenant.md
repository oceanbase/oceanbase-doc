# GV$OB_JAVA_SANDBOX_STATUS

<main id="notice" type='explain'>
<h4>说明</h4>
<p>对于 V4.4.2 版本，该视图从 V4.4.2 BP4 版本开始引入。</p>
</main>

## 功能描述

该视图展示所有租户在所有 OBServer 节点上的 Java UDF 沙箱状态，包括沙箱代的生命周期、通信通道池、沙箱进程资源和沙箱 JVM 资源等信息。

使用说明如下：

* 开启配置项 `ob_enable_java_udf_sandbox` 后，Java UDF 在独立的沙箱进程中执行。每一行对应一代（Generation）沙箱，每代沙箱对应一个沙箱 JVM 进程。
* 该视图只展示已存在的沙箱，查询该视图不会触发沙箱创建。
* 系统租户可以查看所有租户的沙箱，用户租户只能查看本租户的沙箱。
* `INSTANCE_COUNT` 至 `LAST_FORCE_KILL_REASON` 为租户级汇总信息，同一租户的各行取值相同。
* 尚未成功采集或无法获取的指标显示为 NULL，以区别于实际值为 `0` 的指标。

|----------------|-------------|----------------|----------------|

| TENANT_ID | bigint(20) | NO | 租户 ID。 |
| GENERATION_ID | bigint(20) | NO | 沙箱代（Generation）ID。每一代沙箱对应一个沙箱 JVM 进程。 |
| GENERATION_STATE | varchar(32) | YES | 该代沙箱的生命周期状态：<ul><li>`CREATING`：正在创建</li><li>`ACTIVE`：正常提供服务</li><li>`DRAINING`：正在排空，等待进行中的请求结束</li><li>`STOPPING`：正在停止</li><li>`DEAD`：已终止</li><li>`START_FAILED`：启动失败</li></ul> |
| STATUS | varchar(32) | NO | 该代沙箱的运行状态：<ul><li>`STARTING`：启动中</li><li>`UP`：运行中</li><li>`DRAINING`：排空中</li><li>`DOWN`：已停止</li><li>`START_FAILED`：启动失败</li></ul> |
| PROCESS_PID | bigint(20) | YES | 沙箱 JVM 进程的进程 ID。 |
| START_TIME | timestamp(6) | YES | 该代沙箱的启动时间。 |
| UPTIME_MS | bigint(20) | YES | 该代沙箱已运行的时长，单位为毫秒。 |
| DRAIN_REASON | varchar(32) | YES | 该代沙箱进入排空状态的原因，仅当 `GENERATION_STATE` 为 `DRAINING` 时有值：<ul><li>`IDLE_RETIRE`：空闲退役</li><li>`MANUAL_RETIRE`：手动退役</li><li>`TIMEOUT_STUCK`：请求超时</li><li>`OOM`：内存不足</li><li>`CHANNEL_ERROR`：通信通道错误</li><li>`CHANNEL_DEGRADED`：通信通道降级</li><li>`PROCESS_DEAD`：沙箱进程退出</li><li>`PROTOCOL_ERROR`：通信协议错误</li><li>`HANDLER_FATAL`：请求处理发生致命错误</li><li>`DRAIN_DEADLINE_EXPIRED`：排空超时</li><li>`MAX_GENERATION_LIMIT`：沙箱代数达到上限</li></ul> |
| DRAIN_DEADLINE | timestamp(6) | YES | 排空的截止时间，仅当 `GENERATION_STATE` 为 `DRAINING` 时有值。超过该时间仍未排空完成时，沙箱进程会被强制终止。 |
| FORCE_KILLED | tinyint(4) | YES | 该代沙箱进程是否被强制终止：<ul><li>`0`：否</li><li>`1`：是</li></ul> |
| FORCE_KILL_REASON | varchar(32) | YES | 强制终止的原因，取值与 `DRAIN_REASON` 相同。仅当 `FORCE_KILLED` 为 `1` 时有值。 |
| INSTANCE_COUNT | bigint(20) | YES | 该租户当前的沙箱实例数。 |
| MAX_GENERATION_COUNT | bigint(20) | YES | 该租户允许同时存在的沙箱代数上限。 |
| DRAINING_GENERATION_COUNT | bigint(20) | YES | 该租户当前处于排空状态的沙箱代数。 |
| DEFERRED_GENERATION_COUNT | bigint(20) | YES | 该租户等待延迟回收的沙箱代数。 |
| START_COUNT | bigint(20) | YES | 该租户沙箱的累计启动次数。 |
| RESTART_COUNT | bigint(20) | YES | 该租户沙箱的累计重启次数，不包含首次启动。 |
| START_FAILURE_COUNT | bigint(20) | YES | 该租户沙箱的累计启动失败次数。 |
| LAST_START_ERROR_CODE | bigint(20) | YES | 该租户最近一次沙箱启动失败的错误码。未发生过启动失败时为 NULL。 |
| LAST_START_ERROR_TIME | timestamp(6) | YES | 该租户最近一次沙箱启动失败的时间。未发生过启动失败时为 NULL。 |
| ROLLOVER_COUNT | bigint(20) | YES | 该租户沙箱的累计替换（Rollover）次数，即使用新一代沙箱替换旧沙箱的次数。 |
| ROLLOVER_COUNT_60S | bigint(20) | YES | 该租户最近 60 秒内的沙箱替换次数。 |
| LAST_ROLLOVER_REASON | varchar(32) | YES | 该租户最近一次沙箱替换的原因，取值与 `DRAIN_REASON` 相同。未发生过替换时为 NULL。 |
| LAST_ROLLOVER_TIME | timestamp(6) | YES | 该租户最近一次沙箱替换的时间。未发生过替换时为 NULL。 |
| ROLLOVER_COOLDOWN_REMAIN_US | bigint(20) | YES | 沙箱替换冷却期的剩余时间，单位为微秒。短时间内替换次数过多时会进入冷却期；不在冷却期时为 `0`。 |
| FORCE_KILL_COUNT | bigint(20) | YES | 该租户沙箱进程被强制终止的累计次数。 |
| LAST_FORCE_KILL_REASON | varchar(32) | YES | 该租户最近一次强制终止沙箱进程的原因，取值与 `DRAIN_REASON` 相同。未发生过强制终止时为 NULL。 |
| CHANNEL_POOL_CAPACITY | bigint(20) | YES | OBServer 与沙箱进程之间通信通道池的容量。 |
| FREE_CHANNEL_COUNT | bigint(20) | YES | 空闲的通信通道数。 |
| ACQUIRED_CHANNEL_COUNT | bigint(20) | YES | 正在使用的通信通道数。 |
| QUARANTINED_CHANNEL_COUNT | bigint(20) | YES | 处于隔离状态的通信通道数。 |
| REAPING_CHANNEL_COUNT | bigint(20) | YES | 正在回收的通信通道数。 |
| DISCARDED_CHANNEL_COUNT | bigint(20) | YES | 已丢弃的通信通道数。 |
| DISCARDED_CHANNEL_THRESHOLD | bigint(20) | YES | 已丢弃通信通道数的阈值。 |
| CHANNEL_ROLLOVER_REQUIRED | varchar(3) | YES | 是否因通信通道异常需要替换该代沙箱：<ul><li>`YES`：需要</li><li>`NO`：不需要</li></ul> |
| CHANNEL_ACQUIRE_FAIL_COUNT | bigint(20) | YES | 获取通信通道失败的累计次数。 |
| CHANNEL_QUARANTINE_COUNT | bigint(20) | YES | 通信通道被隔离的累计次数。 |

| PROCESS_RSS_BYTES | bigint(20) | YES | 沙箱进程的常驻内存（RSS）大小，单位为字节。 |
| PROCESS_CPU_TIME_US | bigint(20) | YES | 沙箱进程的累计 CPU 时间，单位为微秒。 |
| PROCESS_CPU_USAGE_PERCENT | double | YES | 沙箱进程的 CPU 使用率（%）。 |
| PROCESS_STATUS | varchar(32) | YES | 沙箱进程的状态：<ul><li>`IDLE`：空闲</li><li>`RUNNING`：运行中</li><li>`EXITED`：已退出</li><li>`UNKNOWN`：未知</li></ul> |
| OS_PROCESS_STATE | varchar(4) | YES | 沙箱进程在操作系统中的状态，取值与 Linux 进程状态一致，例如 `R`（运行）、`S`（可中断睡眠）、`D`（不可中断睡眠）、`Z`（僵尸）、`T`（停止）。 |

## 查询示例

查询所有租户在所有 OBServer 节点上 Java UDF 沙箱的状态和内存使用情况。

```shell
obclient> SELECT SVR_IP, TENANT_ID, GENERATION_ID, GENERATION_STATE, STATUS, PROCESS_PID, PROCESS_RSS_BYTES, HEAP_USED_BYTES, MONITOR_STATUS FROM oceanbase.GV$OB_JAVA_SANDBOX_STATUS;
```
