# 可用于生成列的数据类型规则

在 OceanBase 数据库中，纯函数（Pure Function）可用于生成列，非纯函数（Non-pure Function）不可用于生成列。

纯函数，指的是在相同的输入下总是会产生相同输出，且没有任何可观察的副作用（例如改变全局变量或数据库中的其他列）。由于它们返回值的可预测性和一致性，纯函数适合用于创建列。

非纯函数依赖于外部状态或在每次调用时可能产生不同的输出，例如依赖系统时间，会话信息，随机数生成等。由于这些特性，非纯函数不应用于生成列，因为这将导致列值不是一致和可重复的。

## 不可用于生成列的非纯函数

在 Oracle 模式下，非纯函数列表如下：

- `LOCALTIMESTAMP`
- `SESSIONTIMEZONE`
- `DBTIMEZONE`
- `SYSDATE`
- `SYSTIMESTAMP`
- `UID`
- `USER`
- `CUR_TIMESTAMP`
- `RANDOM`
- `GUID`
- `CUR_DATE`
- `USERENV`
- `REGEXP_REPLACE`
- `T_FUN_GET_TEMP_TABLE_SESSID`
- `USER_CAN_ACCESS_OBJ`

### 特殊的非纯函数

正则表达式相关的函数，如 `REGEXP_REPLACE` 被分类为非纯函数（Non-pure Functions），原因是它可能在不同的上下文中产生不同的结果。

类似于正则表达式相关的函数，被视为非纯函数的信息，可参考[可用于生成列的数据类型规则（M有SQL 模式）](../../200.common-tenant-of-mysql-mode/700.ddl-function-of-mysql-mode/1000.generated-column-rule-of-mysql-mode.md)的**特殊的非纯函数**章节。

## 特殊的时间函数

对于 `TO_DATE`, `TO_TIMESTAMP`, 和 `TO_TIMESTAMP_TZ` 这三个函数来说，它们是否为纯函数（pure function）取决于它们是否接收到了明确的日期/时间格式（format）字符串以及函数调用中是否包含了足够的日期/时间组件。当 `TO_DATE`, `TO_TIMESTAMP`, 和 `TO_TIMESTAMP_TZ` 这三个函数未指定格式字符串时，它将默认使用环境或会话级别的日期/时间格式。因为不同环境的默认设置可能不同，所以未指定格式的情况下函数不被视为纯函数。

`TO_DATE`, `TO_TIMESTAMP`, 和 `TO_TIMESTAMP_TZ` 函数成为非纯函数/纯函数需要满足下面几个条件：

1. 对于 `TO_DATE`，如果格式字符串中缺失月份和日期部分，例如仅提供了 'yyyy'，此时 `TO_DATE` 为**非纯函数**。它会返回当前月份的第一天，而当前月份随执行时刻的不同而变化。

2. 在 `TO_TIMESTAMP` 的情况下，如果格式字符串缺失了 'yyyy'，则这个函数不是纯函数。同样，即使是 'yy' 缺失也会被认为不是纯函数，因为会默认使用当前年份来填充。

   - 如果 `TO_TIMESTAMP` 格式字符串缺失月份信息 'mm'，函数也不被认为是纯函数，因为会默认填充当前月份，此时 `TO_TIMESTAMP` 是**非纯函数**。

   - 如果 `TO_TIMESTAMP` 格式字符串仅缺失日期 'dd'，则不影响函数纯净性，因为它会使用指定月份的第一天，此时 `TO_TIMESTAMP` 是**纯函数**。

   - 如果 `TO_TIMESTAMP` 格式字符串缺失时间的组件（如小时、分钟、秒或毫秒）并不影响这些函数的纯函数性质，此时 `TO_TIMESTAMP` 是**纯函数**。

8. 对于 `TO_TIMESTAMP_TZ` 来说，除了要通过与 `TO_TIMESTAMP` 相同的判断之外，还需要考虑时区（time zone）相关的格式指令。如果格式字符串包含了时区信息（如 'TZR' 或 'TZH:TZM'），函数的结果将依赖于时区设置，则被视为**非纯函数**。

对于 `TO_DATE`, `TO_TIMESTAMP`, 和 `TO_TIMESTAMP_TZ` 函数，保持纯函数性质的安全做法是提供一个完整和确定的格式字符串，并且这个字符串应该包含了所有需要的日期和时间组件。
