# PARTITIONID 伪列

PARTITIONID 伪列提供了获取每行数据所在分区 id 的能力，PARTITIONID 伪列的值由 `tablescan` 算子读原始数据时直接填值，不会进行实际的存储。本文主要介绍 PARTITIONID 伪列的使用说明。

根据分区级别和功能不同，主要介绍以下六个伪列：

|列名|类型/（oracle|类型/（oracle|
|--|--|--|
|__ob_partition_id|int/number|`partition_id`，该行数据对应 `partition` 的 `id`。|
|__ob_partition_index|int/number|`partition_index`，该行数据对应 `partition` 的序号 `index`。|
|__ob_partition_name|varchar|`partition_name`，该行数据对应 `partition` 的名字 `name`。|
|__ob_sub_partition_id|int/number|`sub_partition_id`，该行数据对应 `sub_partition` 的 `id`。|
|__ob_sub_partition_index|int/number|`sub_partition_index`，该行数据对应 `sub_partition` 的序号 `index`。|
|__ob_sub_partition_name|varchar|`sub_partition_name`，该行数据对应 `sub_partition` 的名字 `name`。|

各伪列在每种表下的预期结果值如表所示：

||part_name|part_id|part_index|sub_part_name|sub_part_id|sub_part_index|
|--|--|--|--|--|--|--|
|part_name|part_id|part_index|sub_part_name|sub_part_id|sub_part_index|
|非分区表|null|null|null|null|null|null|
|一级分区|partname|partid|partindex|null|null|null|
|二级分区|partname|partid|partindex|subpartname|subpartid|subpartindex|

## 基本语法

### SELECT 操作

Oracle 模式下因为存在 `__ob_`前缀，必须使用 `__ob_partition_id` 进行查询。

示例如下：

```sql
SELECT c1,"__ob_partition_id" from t1;
```

### UPDATE 操作

不允许对 `partitionid` 伪列进行修改，可以出现在 `where` 条件中。

示例如下：

```sql
UPDATE t1 SET c1=c1 WHERE __ob_partition_index=2;
```

## INSERT 操作

不能出现在 `insert` 的 column list 里。

## 限制汇总

### 列名与伪列字段冲突限制

* 查询语句：如果在升级到支持 `partitionid` 版本前有一个表已经有了上述伪列名，那么在查询语句中对于该列仍会返回该列真实的数据；没有的话才会返回对应的伪列值。
* 建表语句：创建表时不允许创建包含有与上述伪列名冲突的列名，否则返回 `OB_ERR_COLUMN_DUPLICATE` 的错误信息。
  * 包括 MYSQL 模式下的 `create table tt1 as select c1,__ob_partition_id from t1;` 或者 Oracle 模式下的 `create table tt1 as select c1,"__ob_partition_id" as "__ob_partition_id"  from t1`。
* Drop column：删除表中某一列时，如果表中已经有了上述伪列名，可以正常删除。否则报错 `OB_ERR_BAD_FIELD_ERROR`。
* Add column：不允许直接 `add` 冲突的 `partitionid` 伪列，否则返回 `OB_ERR_COLUMN_DUPLICATE` 的错误信息。
* Rename column：只允许将现有的与前面伪列名冲突的列名修改成其他的，否则报错 `OB_ERR_COLUMN_DUPLICATE`。

### 表类型限制

当前 OceanBase 支持的表有以下类型：

```sql
enum ObTableType
{
  SYSTEM_TABLE   = 0,
  SYSTEM_VIEW    = 1,
  VIRTUAL_TABLE  = 2,	
  USER_TABLE     = 3,
  USER_VIEW      = 4,
  USER_INDEX     = 5,      // urgly, compatible with uniform process in ddl_service
  TMP_TABLE      = 6,      // Temporary table in mysql compatibility mode
  MATERIALIZED_VIEW  = 7,  // Must be put behind, otherwise compatibility will fail
  TMP_TABLE_ORA_SESS = 8,  // Temporary table in oracle compatibility mode, session level
  TMP_TABLE_ORA_TRX  = 9,  // Temporary tables in oracle compatibility mode, transaction level
  TMP_TABLE_ALL      = 10, // All types of temporary tables, only used for alter system statements
  AUX_VERTIAL_PARTITION_TABLE = 11,
  AUX_LOB_PIECE  = 12,
  AUX_LOB_META   = 13,
  EXTERNAL_TABLE = 14,
  MAX_TABLE_TYPE
};
```

只支持对以下两种类型的表来查询 `partition` 伪列：

* USER_TABLE。
* 对用户表创建的，定义时包含了该上述伪列名的 `USER_VIEW`。查询时如果视图定义有上述伪列名可以对应包含的伪列，不可以对视图查询定义中不包含的伪列。

## 功能开关

`PARTITIONID` 伪列会占用六个列名 `__ob_partition_id`,`__ob_partition_index`，`__ob_partition_name`，`__ob_sub_partition_id`,`__ob_sub_partition_index`,`__ob_sub_partition_name`，导致用户无法再创建包含这些列名的表。

针对此问题可以通过配置项 `_enable_pseudo_partition_id` 来关闭 `PARTITIONID` 伪列功能，当需要使用上述的列名来创建表或者使用该功能遇到问题时可以选择关闭。

示例如下：

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>在系统租户中执行下面命令关闭 <code>partitionid</code> 伪列功能之后，您需要在当前租户中执行 <code>ALTER SYSTEM flush plan cache;</code>手动清除计划缓存。</p>
</main>

```sql
ALTER SYSTEM SET _enable_pseudo_partition_id = false;
```
