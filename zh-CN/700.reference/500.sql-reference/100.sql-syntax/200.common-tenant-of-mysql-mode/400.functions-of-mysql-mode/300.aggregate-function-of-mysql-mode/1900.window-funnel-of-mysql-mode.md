# WINDOW_FUNNEL

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>对于 V4.4.2 版本，该函数从 V4.4.2 BP1 版本开始引入。</p>
</main>

## 声明

```sql
WINDOW_FUNNEL(window, mode, timestamp, cond1, cond2, ..., condN)
```

## 说明

`WINDOW_FUNNEL` 是一个漏斗分析聚合函数，用于计算在指定时间窗口内按顺序满足条件的最大步骤数。

该函数兼容 Hologres/ClickHouse 语法。

### 参数说明

| **参数** | **类型** | **描述** |
|----------|----------|----------|
| window   | `BIGINT` | 表示统计的滑动时间窗口大小，单位取决于 `timestamp` 列（例如 `timestamp` 列为 `DATE` 类型时，单位为天；为 `DATETIME` 时，单位为秒）。 <main id="notice" type='notice'><h4>注意</h4><p>该参数必须为常量表达式，如果没有符合第一个条件的数据，函数返回 0。</p></main>|
| mode     | `VARCHAR` | 表示匹配模式，取值如下：<ul><li>`default`：默认模式，在同一个窗口期内，从第一个事件开始匹配，尽量匹配多的事件。</li><li>`strict_deduplication`：严格去重模式，遇到已经匹配过的相同事件就停止继续匹配。</li></ul>|
| timestamp | `DATE`/`DATETIME`/`TIMESTAMP`/`BIGINT`/`INT` | 表示时间戳的列。|
| cond1, cond2, ..., condN | `BOOLEAN` | 表示条件事件链，为布尔表达式，最多支持 256 个事件。|

### 返回说明

* 返回一个 `UINT32` 类型，值的范围为 [0, N]，N 是条件事件的个数。
* 表示在指定时间窗口内，从第一个条件开始，按顺序匹配到的最大步骤数。

## 示例

1. 创建表 `test_tbl1`。

    ```shell
    obclient> CREATE TABLE test_tbl1 (col1 INT, col2 DATETIME, col3 VARCHAR(50));
    ```

2. 向表 `test_tbl1` 插入测试数据。

    ```shell
    obclient> INSERT INTO test_tbl1 VALUES
        (1, '2026-01-01 10:00:00', 'step1'),
        (1, '2026-01-01 10:05:00', 'step2'),
        (1, '2026-01-01 10:09:00', 'step3'), -- 在 10 分钟窗口内
        (2, '2026-01-01 11:00:00', 'step1'),
        (2, '2026-01-01 11:05:00', 'step2'),
        (2, '2026-01-01 11:15:00', 'step3'), -- 超出 10 分钟窗口
        (3, '2026-01-01 11:00:00', 'step1'),
        (3, '2026-01-01 11:01:00', 'step2'),
        (3, '2026-01-01 11:02:00', 'step1'), -- 重复的 step1
        (3, '2026-01-01 11:03:00', 'step3');
    ```

3. 按 `col1` 分组，`col1` 的值是 `1` 或 `2`，统计每个组中用户（由 `col2` 标识）在 600 秒内完成 'step1' → 'step2' → 'step3' 流程的漏斗阶段进度。

    ```shell
    obclient> SELECT
        col1,
        WINDOW_FUNNEL(
            600,
            'default',
            col2,
            col3 = 'step1', col3 = 'step2', col3 = 'step3') AS funnel_stage
        FROM test_tbl1
        WHERE col1 IN (1, 2)
        GROUP BY col1
        ORDER BY col1;
    ```

    返回结果如下：

    ```shell
    +------+--------------+
    | col1 | funnel_stage |
    +------+--------------+
    |    1 |            3 |
    |    2 |            2 |
    +------+--------------+
    2 rows in set
    ```

4. 不同模式对比：展示 `default` 模式与 `strict_deduplication` 模式的区别。

    * `default` 模式：按 `col1` 分组，统计 `col1 = 3` 的用户（由 `col2` 标识）在 1800 秒内完成 'step1' → 'step2' → 'step3' 流程的漏斗阶段进度。

        ```shell
        obclient> SELECT
            col1,
            WINDOW_FUNNEL(
                1800,
                'default',
                col2,
                col3 = 'step1', col3 = 'step2', col3 = 'step3') AS funnel_stage
            FROM test_tbl1
            WHERE col1 = 3
            GROUP BY col1;
        ```

        返回结果如下：

        ```shell
        +------+--------------+
        | col1 | funnel_stage |
        +------+--------------+
        |    3 |            3 |
        +------+--------------+
        1 row in set
        ```

    * `strict_deduplication` 模式（遇到重复事件停止）：按 `col1` 分组，统计 `col1 = 3` 的用户（由 `col2` 标识）在 1800 秒内完成 'step1' → 'step2' → 'step3' 流程的漏斗阶段进度。

        ```shell
        obclient> SELECT
            col1,
            WINDOW_FUNNEL(
                1800,
                'strict_deduplication',
                col2,
                col3 = 'step1', col3 = 'step2', col3 = 'step3') AS funnel_stage
            FROM test_tbl1
            WHERE col1 = 3
            GROUP BY col1;
        ```

        返回结果如下：

        ```shell
        +------+--------------+
        | col1 | funnel_stage |
        +------+--------------+
        |    3 |            2 |
        +------+--------------+
        1 row in set
        ```
