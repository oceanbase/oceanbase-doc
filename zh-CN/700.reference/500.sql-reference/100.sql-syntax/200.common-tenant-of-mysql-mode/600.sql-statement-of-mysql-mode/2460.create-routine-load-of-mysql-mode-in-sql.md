# CREATE ROUTINE LOAD

## 描述

该语句用于创建 Routine Load 任务，持续从 Kafka 消费数据并导入到 OceanBase 数据库的表中。

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>Routine Load 是后台自动执行的数据导入过程，用户只需要创建 Routine Load 作业，系统会自动在后台定时消费 Kafka 数据并导入到目标表中。</p>
</main>

## 权限要求

创建 Routine Load Job 需要当前用户具备目标表的 `INSERT` 权限。更多有关 OceanBase 数据库权限的详细介绍，请参见 [MySQL 模式下的权限分类](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md)。

## 语法

```sql
CREATE ROUTINE LOAD job_name ON table_name
    [load_properties]
    FROM STREAM (job_properties_expr);

load_properties:
    load_property_list

load_property_list:
    load_property [, load_property ...]

load_property:
    PARALLEL [=] int_value
  | COLUMNS (col1, col2, ...)
  | PARTITION (partition_name_list)
  | IGNORE | REPLACE
  | WHERE opt_hint_value expr

job_properties_expr:
    job_property [, job_property ...]

job_property:
    TYPE [=] 'KAFKA'
  | STRING_VALUE [=] STRING_VALUE
  | FORMAT [=] (format_options)

format_options:
    TYPE = 'CSV',
    LINE_DELIMITER = '<string>' | <expr>,
    FIELD_DELIMITER = '<string>' | <expr>,
    ESCAPE = '<character>' | <expr>,
    FIELD_OPTIONALLY_ENCLOSED_BY = '<character>' | <expr>,
    ENCODING = 'charset',
    NULL_IF = ('<string>' | <expr>, '<string>' | <expr> ...),
    SKIP_BLANK_LINES = {TRUE | FALSE},
    TRIM_SPACE = {TRUE | FALSE},
    EMPTY_FIELD_AS_NULL = {TRUE | FALSE}
```

## 参数说明

| **参数** |       **描述**           |
|----------|--------------------------|
| job_name | 表示作业名称，在当前租户内唯一，用于标识该 Routine Load 作业。|
| table_name | 表示目标表名，数据将导入到该表中。|
| load_property_list | 可选项，表示数据加载属性（并发度、列映射、分区、冲突策略、过滤条件等）。详细介绍可参见下文 [load_property_list](#load_property_list)。|
| FROM STREAM | 用于设置数据源类型有关参数。|
| TYPE = 'KAFKA' | 可选项，指定数据源类型。如果不指定，则默认是 `KAFKA`。<main id="notice" type='explain'><h4>说明</h4><p>当前版本数据源类型仅支持 <code>'KAFKA'</code>。</p></main>|
| STRING = STRING | 指定 Kafka 相关配置参数列表，为键值对形式，**键名大小写敏感**。除格式配置外，支持 Kafka 标准消费者相关参数（如 `security.protocol`、`sasl.mechanism` 等）。**无需** 配置 `group.id`，系统会按并发度自动建立消费线程与分区的对应关系。详细介绍可参见下文 [kafka_expr_list](#kafka_expr_list)。|
| FORMAT [=] (format_options) | 指定 Kafka 数据格式相关的属性。`format_options` 表示 Kafka 数据格式选项，详细介绍可参见下文 [format_options](#format_options)。|

### load_property_list

* `PARALLEL [=] int_value`：指定并行度，默认值为 1。
* `COLUMNS (col1, col2, ...)`：Kafka 消息列与目标表列的映射关系。
* `PARTITION (partition_name_list)`：指定导入的目标分区。
* `{IGNORE | REPLACE}`：指定处理主键或唯一键冲突时的处理方式。

  * `IGNORE`：默认值，表示忽略冲突行。
  * `REPLACE`：表示覆盖冲突行。

* `WHERE condition`：指定数据过滤条件，在数据写入目标表之前进行条件过滤。

### kafka_expr_list

* `bootstrap.servers`：必选项，指定 Kafka Broker 地址列表，多个用逗号分隔，如 `broker1:9092,broker2:9092`。表示客户端首次连接 Kafka 的入口地址。
* `kafka_topic`：必选项，指定要消费的 Kafka Topic 名称。
* `kafka_partitions`：可选项，指定要消费的分区列表，如 `"0,1,2"`。不提供则消费该 Topic 下全部分区。
* `kafka_offsets`：可选项，指定各分区起始消费位点，与 `kafka_partitions` 一一对应，即指定对应每个分区的起始 offset，若只写一个值则对所有分区生效。如果不指定，则默认从 `OFFSET_END` 开始订阅 Topic 下的所有分区（Partition）。目前支持数字和 `OFFSET_BEGINNING`、`OFFSET_END` 混用。
* `"max_batch_interval"`：可选项，Job 每轮 “每个导入线程” 最大运行时间，单位是秒，默认是 60s（导入线程数和并发度 `PARALLEL` 有关）。
* `"max_batch_rows"`：可选项，Job 每轮 “每个导入线程” 最多读取的行数。必须大于等于 200000，默认是 10000000。
* `"max_batch_size"`：可选项，Job 每轮 “每个导入线程” 最多读取的字节数，单位是字节，范围是 100MB 到 1GB，默认是 1GB。

**名词说明**：

* **offset（消费位点）**：Kafka 分区中每条消息的逻辑位置。`OFFSET_BEGINNING` 表示从分区最早可读消息开始，`OFFSET_END` 表示从当前最新位置开始。
* **low / high watermark**：Kafka 分区中当前可消费的最小、最大 offset；指定 offset 不能低于 low watermark。

### format_options

当前仅支持 **CSV** 格式，语法与 OceanBase 现有 CSV 解析能力对齐，可参考 [LOAD DATA](5900.load-data-of-mysql-mode.md) 中的格式说明。常用选项如下：

* `TYPE`：指定数据格式，目前只支持 CSV 格式。
* `LINE_DELIMITER`：指定 CSV 文件的行分隔符，默认为 `LINE_DELIMITER='\n'`。
* `FIELD_DELIMITER`：可选项，指定 CSV 文件的列分隔符，默认为 `FIELD_DELIMITER='\t'`。
* `ESCAPE`：指定 CSV 文件的转义符号，只能为 1 个字节，默认为 `ESCAPE ='\'`。
* `FIELD_OPTIONALLY_ENCLOSED_BY`：可选项，指定 CSV 文件中包裹字段值的符号，默认为空。使用此选项表示只对部分类型的字段（如 CHAR, VARCHAR, TEXT, JSON 等）加包裹符。
* `ENCODING`：指定文件的字符集编码格式，如果不指定，默认值为 `UTF8MB4`。
* `NULL_IF`：指定被当作 `NULL` 处理的字符串。默认值为空。
* `SKIP_BLANK_LINES`：指定是否跳过空白行。默认值为 `FALSE`，表示不跳过空白的行。
* `TRIM_SPACE`：指定是否删除文件中字段的头部和尾部空格。默认值为 `FALSE`，表示不删除文件中字段头尾的空格。
* `EMPTY_FIELD_AS_NULL`：指定是否将空字符串当作 `NULL` 处理。默认值为 `FALSE`，表示不将空字符串当做 `NULL` 处理。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>Routine Load 的 CSV 解析不支持 <code>PARSE_HEADER</code>、<code>SKIP_HEADER</code>。即不能将第一行当作列名或跳过文件头行。</p>
</main>

## 示例

创建从 Kafka 导入数据到 `test_db.test_tbl1` 的 Routine Load 作业 `load_job_0`。

```shell
obclient> CREATE ROUTINE LOAD load_job_0 ON test_db.test_tbl1
    PARALLEL = 3
    WHERE id > 0
    FROM STREAM (
        TYPE = 'KAFKA',
        "kafka_topic" = "test-topic",
        "kafka_partitions" = "0,1,2",
        "kafka_offsets" = "0,0,OFFSET_BEGINNING",
        "max_batch_interval" = "3000000",
        "max_batch_rows" = "200000",
        "max_batch_size" = "104857600",
        "bootstrap.servers" = "xxx.xxx.xxx.1:xxxx",
        "security.protocol" = "sasl_plaintext",
        "sasl.mechanism" = "PLAIN",
        "sasl.username" = "******",
        "sasl.password" = "******",
        FORMAT = (
            TYPE = 'CSV',
            FIELD_DELIMITER = ',',
            TRIM_SPACE = TRUE)
        );
```
