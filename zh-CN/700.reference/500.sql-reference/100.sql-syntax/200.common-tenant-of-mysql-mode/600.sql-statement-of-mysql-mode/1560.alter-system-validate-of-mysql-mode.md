# VALIDATE

## 描述

`ALTER SYSTEM VALIDATE` 语句用于进行物理备份校验。

## 使用限制及注意事项

* 对于 V4.4.2 版本，从 V4.4.2 BP2 版本开始支持 `ALTER SYSTEM VALIDATE` 语句。

* 由于校验任务会频繁地通过访问备份介质来读取数据，进而抢占备份任务的网络资源，建议在用户租户未执行备份任务且低负载时执行校验任务。

* 指定备份校验的校验层级时：

  * 对于 V4.4.2 版本，V4.4.2 BP2 版本（不含 V4.4.2 BP2 版本）之前的备份集以及日志归档 Piece，不支持 Basic 校验，即不支持文件的完整性校验。

  * 对于 V4.3.4 版本（不含 V4.3.4 版本）之前的备份集，不支持 Physical 校验，即不支持物理数据的正确性及逻辑一致性校验。

## 权限要求

需要由各租户的管理员用户执行。其中：

* MySQL 模式的默认管理员用户为 `root` 用户。

* Oracle 模式的默认管理员用户为 `SYS` 用户。

## 语法

```sql
ALTER SYSTEM VALIDATE { BACKUP | BACKUPSET [= 'backup_set_id_list'] | ARCHIVELOG_PIECE [= 'piece_id_list'] }
    [ DATA_BACKUP_DEST = 'data_backup_path' ]
    [ LOG_ARCHIVE_DEST = 'log_archive_path' ]
    [ LEVEL = { 'basic' | 'physical' } ];

backup_set_id_list:
    backup_set_id[,backup_set_id,...]

piece_id_list:
    piece_id[,piece_id,...]
```

## 参数解释

|      参数        |        描述                                             |
|------------------|---------------------------------------------------------|
| BACKUP           | 校验当前用户租户下整个备份路径和归档路径下的所有备份集和日志归档 Piece。不支持指定校验路径（ `DATA_BACKUP_DEST` 或 `LOG_ARCHIVE_DEST`），即不支持跨集群和冷备数据场景。|
| BACKUPSET        | 校验指定的备份集。如果不指定备份集的 `backup_set_id`，则校验当前备份路径下的所有备份集。<main id="notice" type='notice'><h4>注意</h4><p>如果不指定 <code>backup_set_id</code>，系统将会获取当前配置的备份路径下的所有备份集进行校验，从而导致产生大量的校验任务，耗时较长。如果确认不需要校验所有备份集，建议在校验命令中指定 <code>backup_set_id</code>。</p></main> |
| ARCHIVELOG_PIECE | 校验指定的日志归档 Piece。如果不指定归档 Piece 的 `piece_id`，则校验当前归档路径下的所有日志归档 Piece。 <main id="notice" type='notice'><h4>注意</h4><p>如果不指定 <code>piece_id</code>，系统将会获取当前配置的归档路径下的所有归档 Piece 进行校验，从而导致产生大量的校验任务，耗时较长。如果确认不需要校验所有归档 Piece，建议在校验命令中指定 <code>piece_id</code>。</p></main>|
| DATA_BACKUP_DEST | 指定待校验的数据备份路径，可选参数。如果不指定该参数，则默认校验租户当前备份配置的备份路径。 <main id="notice" type='notice'><h4>注意</h4><p>OceanBase 数据库当前不支持在单条命令中指定多个路径。因此，在指定路径下通过指定 <code>backup_set_id</code> 校验增量备份集时，可能因为无法读取该增量备份集所依赖的其他备份集信息而报错，错误码为 9120。</p></main> |
| LOG_ARCHIVE_DEST | 指定待校验的日志归档路径，可选参数。如果不指定该参数，则默认校验租户当前归档配置的归档路径。 |
| LEVEL            | 指定校验的层级，可选参数。其中：<ul><li>`basic`：表示仅检查文件列表的完整性。</li> <li>`physical`：表示同时检查物理数据的正确性及逻辑一致性。</li></ul><p>如果不指定该参数，则默认为 `physical`。</p>|

## 示例

### 校验整个备份路径和归档路径下的所有备份集和日志归档 Piece

用户租户对本租户在当前备份和归档路径下的所有备份集和归档 Piece 发起 Basic 校验。

```shell
obclient(root@mysqltenant)[(none)]> ALTER SYSTEM VALIDATE BACKUP LEVEL = 'basic';
```

### 校验指定的备份集或日志归档 Piece

**校验备份集**

* 用户租户对本租户当前备份路径下的所有备份集发起 Basic 校验。

  ```shell
  obclient(root@mysqltenant)[(none)]> ALTER SYSTEM VALIDATE BACKUPSET LEVEL = 'basic';
  ```

* 用户租户对本租户当前备份路径下 `backup_set_id` 为 1、2 的备份集发起 Physical 校验。

  ```shell
  obclient(root@mysqltenant)[(none)]> ALTER SYSTEM VALIDATE BACKUPSET = '1,2' LEVEL = 'physical';
  ```

**校验日志归档 Piece**

* 用户租户对本租户在当前归档路径下的所有归档 Piece 发起 Basic 校验。

  ```shell
  obclient(root@mysqltenant)[(none)]> ALTER SYSTEM VALIDATE ARCHIVELOG_PIECE LEVEL = 'basic';
  ```

* 用户租户对本租户在当前归档路径下 `piece_id` 为 1、2 的日志归档 Piece 发起 Physical 校验。

  ```shell
  obclient(root@mysqltenant)[(none)]> ALTER SYSTEM VALIDATE ARCHIVELOG_PIECE = '1,2' LEVEL = 'physical';
  ```

### 校验指定路径下的备份集或日志归档 Piece

**校验备份集**

* 用户租户对本租户指定备份路径下的所有备份集发起 Basic 校验。

  ```shell
  obclient> ALTER SYSTEM VALIDATE BACKUPSET DATA_BACKUP_DEST = 'file:///data/nfs/backup/data' LEVEL = 'basic';
  ```

* 用户租户对本租户指定备份路径下 `backup_set_id` 为 1、2 的备份集发起 Physical 校验。

  ```shell
  obclient> ALTER SYSTEM VALIDATE BACKUPSET = '1,2' DATA_BACKUP_DEST = 'file:///data/nfs/backup/data' LEVEL = 'physical';
  ```

**校验日志归档 Piece**

* 用户租户对本租户在指定归档路径下的所有归档 Piece 发起 Basic 校验。

  ```shell
  obclient(root@mysqltenant)[(none)]> ALTER SYSTEM VALIDATE ARCHIVELOG_PIECE LOG_ARCHIVE_DEST = 'file:///data/nfs/backup/archive' LEVEL = 'basic';
  ```

* 用户租户对本租户在指定归档路径下 `piece_id` 为 1、2 的日志归档 Piece 发起 Physical 校验。

  ```shell
  obclient(root@mysqltenant)[(none)]> ALTER SYSTEM VALIDATE ARCHIVELOG_PIECE = '1,2' LOG_ARCHIVE_DEST = 'file:///data/nfs/backup/archive' LEVEL = 'physical';
  ```
