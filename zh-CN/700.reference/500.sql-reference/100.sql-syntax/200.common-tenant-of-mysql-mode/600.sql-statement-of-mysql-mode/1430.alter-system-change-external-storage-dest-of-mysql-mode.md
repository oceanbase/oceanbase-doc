# ALTER/CHANGE/MODIFY EXTERNAL_STORAGE_DEST

## 描述

该语句用于变更本租户备份或归档路径的源端配置（`zone`、`idc` 或 `region` 配置）以及 `access_id` 和 `access_key` 等密钥信息。修改后，新的配置信息将会覆盖原来的配置信息。

## 使用限制及注意事项

* 仅用户租户可以执行该语句，系统租户（sys 租户）不能执行该语句。

* 修改路径的 `zone`、`idc` 或 `region` 配置前，如果需要设置 Region 层级或 IDC 层级，需要先通过 `ALTER SYSTEM MODIFY ZONE zone_name SET REGION=region_name;` 或 `ALTER SYSTEM MODIFY ZONE zone_name SET IDC=idc_name;` 语句分别设置 Region 信息或 IDC 信息。推荐设置 IDC 层级的源端配置，利用有较多网络带宽资源的 IDC 来执行备份任务的同时，备份任务有更多的可选节点范围，同时用户也不需要关注集群中 IDC 内 Zone 的变化情况。

* 修改备份路径的源端配置时，如果有备份任务正在执行，由于正在执行的任务至多需要分钟级时间才能感知到配置的变化，故在配置修改期间，仍可能会有配置范围外的节点访问备份路径，导致产生跨机房或跨地域的流量。

* 仅支持变更对象存储路径的 `access_id` 和 `access_key` 信息。

## 权限要求

执行该语句的用户需要拥有 `ALTER SYSTEM` 权限。有关 OceanBase 数据库权限的详细介绍，参见 [MySQL 模式下的权限分类](../../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/100.permission-classification-of-mysql.md)。

## 语法

```sql
ALTER SYSTEM {ALTER|CHANGE|MODIFY} EXTERNAL_STORAGE_DEST PATH [=] 'path' SET [ATTRIBUTE = '{zone=zone_name | idc=idc_name | region=region_name}'] [ACCESS_INFO = 'access_id=new_access_id&access_key=new_access_key'];
```

## 参数说明

|          参数                                     |         描述                                      |
|---------------------------------------------------|--------------------------------------------------|
| path                                              | 指定待变更密钥信息的备份路径或归档路径。要求路径必须为当前租户已经设置的备份路径或归档路径，且必须为对象存储路径，同时路径中需要包含 `host` 信息。以 OSS 为例，该路径的格式如下：`oss://oceanbase-test-bucket/backup/databackup?host=***`。 |
| zone=zone_name \| idc=idc_name \| region=region_name | 指定当前备份路径或归档路径的源端。支持选择 `zone`、`idc` 或 `region` 三个不同层级的配置，只能同时选择一个层级或者不设置。如果不显式指定，则默认不设置。<p>修改归档路径的源端配置时：<ul><li>由于日志归档的所有流量均由 Leader 副本写入，故对日志归档路径来说，没有访问优先级的差异，只是限制访问归档路径的节点范围。如果需要设置多个 Zone、多个 IDC 或多个 Region，多个值之间使用英文逗号（,）或英文分号（;）分隔。例如，`zone=z1,z2;z3` 表示指定 `z1`、`z2`、`z3` 为归档路径的源端。</li> <li>修改 `zone`、`idc` 或 `region` 时，要求 Leader 副本在指定的 `zone`、`idc` 或 `region` 中，否则，日志归档将会无法推进。</li></ul></p> <p>修改备份路径的源端配置时：<ul><li>如果需要设置多个 Zone、多个 IDC 或多个 Region，多个 Zone/IDC/Region 之间使用英文逗号（,）和英文分号（;）分隔。其中：<ul><li>英文逗号（,）表示在选择执行备份任务节点时，左右两边的 Zone/IDC/Region 内的节点具有相同的优先级。</li> <li>英文分号（;）表示左边 Zone/IDC/Region 内的节点优先级比右边的高，即优先选择左边的 Zone/IDC/Region 内的节点执行备份任务。</li></ul>例如，如果设置为 `zone=z1,z2;z3` 表示指定 `z1`、`z2`、`z3` 作为备份的源端，`z1`、`z2` 在同一优先级，且 `z1`、`z2` 的优先级高于 `z3`。</li> <li>修改备份路径的 `zone`、`idc` 或 `region` 配置时，要求 Root Service 的 Leader 节点在指定的 `zone`、`idc` 或 `region` 中，否则，备份任务将无法成功向目标备份路径写入备份元数据，最终导致备份任务执行失败。建议备份路径源端设置包含 Primary Zone 范围。</li></ul></p> |
| access_id=new_access_id&access_key=new_access_key | 指定变更后的新的 `access_id` 和 `access_key` 信息。`access_id` 与 `access_key` 需要同时填写。|

## 示例

* 修改归档路径的源端配置

  假设归档路劲原来的源端配置为 `zone=z1,z2,z3`，现在需要将源端配置更改为 `region=region1`。修改后，仅 `region1` 中的节点可以访问该路径。

  * OSS

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='oss://oceanbase-test-bucket/backup/archive?host=****.aliyun-inc.com' SET ATTRIBUTE = 'region=region1';
    ```

  * NFS

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='file:///data/nfs/backup/archive' SET ATTRIBUTE = 'region=region1';
    ```

  * S3

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM CHANGE EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=s3.<region>.amazonaws.com' SET ATTRIBUTE = 'region=region1';
    ```

  * 兼容 S3 协议的对象存储（OBS/GCS/COS）

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM CHANGE EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=obs.****.myhuaweicloud.com' SET ATTRIBUTE = 'region=region1';
    ```

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=https://storage.googleapis.com' SET ATTRIBUTE = 'region=region1';
    ```

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM ALTER EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/archive?host=cos.ap-xxxx.myqcloud.com' SET ATTRIBUTE = 'region=region1';
    ```

* 修改备份路径的源端配置

  假设备份路径原来的源端配置为 `zone=z1,z2;z3`，现在需要将源端配置更改为 `idc=idc1;idc2`。修改后，`idc1`、`idc2` 中的节点可以访问该路径，且`idc1` 的优先级高于 `idc2`。

  * OSS

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM CHANGE EXTERNAL_STORAGE_DEST PATH='oss://oceanbase-test-bucket/backup/data?host=****.aliyun-inc.com' SET ATTRIBUTE = 'idc=idc1;idc2';
    ```

  * NFS

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM ALTER EXTERNAL_STORAGE_DEST PATH='file:///data/nfs/backup/data' SET ATTRIBUTE = 'idc=idc1;idc2';
    ```

  * S3

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/data?host=s3.<region>.amazonaws.com' SET ATTRIBUTE = 'idc=idc1;idc2';
    ```

  * 兼容 S3 协议的对象存储（OBS/GCS/COS）

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM CHANGE EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/data?host=obs.****.myhuaweicloud.com' SET ATTRIBUTE = 'idc=idc1;idc2';
    ```

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM MODIFY EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test-bucket/backup/data?host=https://storage.googleapis.com' SET ATTRIBUTE = 'idc=idc1;idc2';
    ```

    ```shell
    obclient(root@mysql001)[(none)]> ALTER SYSTEM ALTER EXTERNAL_STORAGE_DEST PATH='s3://oceanbase-test/backup/data?host=cos.ap-xxxx.myqcloud.com' SET ATTRIBUTE = 'idc=idc1;idc2';
    ```
