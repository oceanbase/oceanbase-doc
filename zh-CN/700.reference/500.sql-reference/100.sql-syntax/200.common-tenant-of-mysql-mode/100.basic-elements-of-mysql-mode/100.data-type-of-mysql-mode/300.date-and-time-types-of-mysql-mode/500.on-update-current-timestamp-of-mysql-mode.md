# ON UPDATE CURRENT_TIMESTAMP 列属性

## 功能介绍

`ON UPDATE CURRENT_TIMESTAMP` 是 MySQL 模式下的一个列属性，用于在行数据发生更新（`UPDATE`）时，自动将该列的值设置为当前时间戳，主要用来记录数据行的最后修改时间。

在 OceanBase 数据库中，`TIMESTAMP` 和 `DATETIME` 列均支持使用该属性，行为与 MySQL 保持一致。

## 功能描述

当表中某行的数据被更新时，系统会自动将定义了 `ON UPDATE CURRENT_TIMESTAMP` 属性的列设置为当前时间戳，无需应用程序显式赋值。该属性通常与 `DEFAULT CURRENT_TIMESTAMP` 配合使用：`DEFAULT CURRENT_TIMESTAMP` 在插入（`INSERT`）时记录创建时间，`ON UPDATE CURRENT_TIMESTAMP` 在更新时自动维护最后修改时间。

## 适用场景

- 审计日志：记录数据的最后修改时间，跟踪数据变更历史
- 数据同步：自动维护记录的更新时间，便于增量同步
- 业务表设计：需要记录行最后修改时间的场景，减少应用程序的开发工作量

## 语法格式

在 `CREATE TABLE` 语句的列定义中指定，语法如下：

```sql
列名 TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
```

也支持指定时间戳精度，精度值必须与列定义中的精度一致：

```sql
列名 TIMESTAMP(6) DEFAULT CURRENT_TIMESTAMP(6) ON UPDATE CURRENT_TIMESTAMP(6)
```

`DATETIME` 列使用方式相同：

```sql
列名 DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
```

> **说明**
>
> - 该属性仅适用于 `TIMESTAMP` 和 `DATETIME` 列，其他类型的列不支持。
> - `ON UPDATE CURRENT_TIMESTAMP` 后的精度必须与列定义中的精度一致，否则会报错。例如，列定义为 `TIMESTAMP(6)` 时，需使用 `ON UPDATE CURRENT_TIMESTAMP(6)`。
> - 除 `CREATE TABLE` 外，`ALTER TABLE` 的 `ADD COLUMN`、`MODIFY COLUMN`、`CHANGE COLUMN` 操作中同样支持使用该属性。

## 示例

创建一张包含创建时间和修改时间列的表：

```sql
obclient> CREATE TABLE t1 (
    id INT PRIMARY KEY,
    c1 VARCHAR(20),
    gmt_create TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    gmt_modified TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
Query OK, 0 rows affected

obclient> INSERT INTO t1(id, c1) VALUES (1, 'a');
Query OK, 1 row affected

obclient> SELECT id, c1, gmt_create, gmt_modified FROM t1;
+----+------+---------------------+---------------------+
| id | c1   | gmt_create          | gmt_modified        |
+----+------+---------------------+---------------------+
|  1 | a    | 2026-08-20 15:38:28 | 2026-08-20 15:38:28 |
+----+------+---------------------+---------------------+
1 row in set

obclient> UPDATE t1 SET c1 = 'b' WHERE id = 1;
Query OK, 1 row affected

obclient> SELECT id, c1, gmt_modified FROM t1;
+----+------+---------------------+
| id | c1   | gmt_modified        |
+----+------+---------------------+
|  1 | b    | 2026-08-20 15:38:30 |
+----+------+---------------------+
1 row in set
```

从结果可以看到，执行 `UPDATE` 后，`gmt_modified` 列的值被自动更新为当前时间戳，而 `gmt_create` 列保持不变。

带精度的示例：

```sql
obclient> CREATE TABLE t2 (
    c1 TIMESTAMP(6) DEFAULT CURRENT_TIMESTAMP(6) ON UPDATE CURRENT_TIMESTAMP(6)
);
Query OK, 0 rows affected
```

## 注意事项

- **MySQL 模式专属**：该属性是 MySQL 兼容模式的特性，Oracle 模式不支持。
- **精度一致**：`ON UPDATE CURRENT_TIMESTAMP` 的精度必须与列定义的精度一致，否则会报错。
- **与 `DEFAULT CURRENT_TIMESTAMP` 配合**：建议同时指定 `DEFAULT CURRENT_TIMESTAMP`，确保插入时有初始值。
- **隐式默认属性**：当系统变量 `explicit_defaults_for_timestamp` 为 OFF（默认值）时，如果表中第一个 `TIMESTAMP` 列未显式指定 `NULL` 属性和默认值，系统会自动为该列添加 `DEFAULT CURRENT_TIMESTAMP` 和 `ON UPDATE CURRENT_TIMESTAMP` 属性。有关该变量的详细信息，参见 [explicit_defaults_for_timestamp](../../../../../../800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/2600.explicit_defaults_for_timestamp-global.md)。
- **仅数据变化时触发**：仅当 `UPDATE` 实际改变了行中的其他列值时，`ON UPDATE CURRENT_TIMESTAMP` 列才会被更新；若更新后行数据没有变化（例如 `UPDATE t1 SET c1 = c1`），该列不会被刷新。
- **并行 DML 限制**：包含 `ON UPDATE CURRENT_TIMESTAMP` 列的表不支持并行 DML，详细信息参见 [并行执行分类](../../../../../../1000.performance-tuning-guide/500.sql-optimization/350.parallel-execution/150.classification-of-parallel-execution.md)。
