# BACKUP ARCHIVELOG

`ALTER SYSTEM BACKUP ARCHIVELOG ALL` 语句用于发起归档日志备份，将 `LOG_ARCHIVE_DEST` 上已冻结（FROZEN）的归档 Piece 备份到 `BACKUP_ARCHIVE_DEST` 上。备份完成后，原归档介质上的日志数据可以被安全回收，从而避免日志归档因归档介质空间满而出现断流。

在执行归档日志备份前，需要确保当前已开启归档模式，仅当租户的 `LOG_MODE` 为 `ARCHIVELOG` 时，才能发起归档日志备份。开启归档模式的相关语法，请参见 [ARCHIVELOG](200.archivelog.md)。发起归档日志备份前，还需要先通过 `ALTER SYSTEM SET BACKUP_ARCHIVE_DEST` 语句设置归档日志备份的备份目的端，相关语法，请参见 [SET BACKUP_ARCHIVE_DEST](3850.set-backup-archive-dest.md)。

## 使用限制

* 对于 V4.4.2 版本，从 V4.4.2 BP3 版本开始支持 `ALTER SYSTEM BACKUP ARCHIVELOG` 语句。

* 仅支持在主租户上发起归档日志备份，不支持在备租户上发起。

* 同一时刻同一租户只能运行一个归档日志备份任务，前一个任务未结束前，不能重新发起归档日志备份。

* 修改 `BACKUP_ARCHIVE_DEST` 与发起归档日志备份任务互斥。

* 带 `DELETE INPUT` 的归档日志备份所发起的源端副本清理任务，与带 `PLUS ARCHIVELOG` 参数的数据备份任务互斥：发起清理任务前，系统会检查同租户下是否有正在执行的带 `PLUS ARCHIVELOG` 参数的数据备份任务，如果有，归档日志备份仍会正常执行，但对应的清理任务会失败；发起带 `PLUS ARCHIVELOG` 参数的数据备份任务前，系统会检查是否有正在执行的源端副本清理任务，如果有，该数据备份任务会失败，需等待清理任务结束后重新发起。

* 关于数据备份的使用限制、注意事项及权限要求，请参见 [BACKUP](600.backup.md)。

## 注意事项

* `BACKUP ARCHIVELOG ALL` 仅处理 FROZEN 状态的 Piece，不会自动触发 Piece 冻结，也不会备份正在写入的 ACTIVE Piece。如果不存在 FROZEN 状态的 Piece，归档日志备份任务会正常完成，但不会复制数据。

* 任务启动时会确定本次待备份的 Piece，已成功备份过的 Piece 不会再次备份；任务执行期间新冻结的 Piece 由下一次归档日志备份任务处理。

* 归档日志备份为异步任务，语句执行成功仅表示任务已创建并提交，任务在后台执行，可通过 `CDB_OB_BACKUP_JOBS`、`DBA_OB_BACKUP_JOBS` 等视图查询任务的进度和结果。

## 语法

```sql
ALTER SYSTEM BACKUP ARCHIVELOG ALL [DELETE INPUT] [TENANT = tenant_name];
```

## 参数说明

| 参数            | 描述                                                                |
|-----------------|---------------------------------------------------------------------------|
| BACKUP ARCHIVELOG ALL | 发起归档日志备份，将已冻结（FROZEN）的归档 Piece 备份到 `BACKUP_ARCHIVE_DEST`。 |
| DELETE INPUT    | 可选。指定该选项后，仅当本次任务中所有 FROZEN 状态的 Piece 均成功备份后，系统才会生成清理任务，自动删除源端已备份的归档日志文件；如果归档日志备份任务失败，则不会清理源端文件。若不指定此选项，则仅备份归档日志文件，不删除源端文件。<main id="notice" type='notice'> <h4>注意</h4><p>如果有使用 CDC 直连归档消费归档数据的需求，不建议使用 <code>DELETE INPUT</code> 选项：源端 FROZEN 状态的 Piece 被清理后，可能导致 CDC 读取不到数据字典。</p></main> |
| tenant_name     | 系统租户指定待操作的租户名。<main id="notice" type='notice'> <h4>注意</h4><p>仅系统租户在执行此命令时需要通过 <code>TENANT = tenant_name</code> 子句指定待操作的租户，用户租户只能对本租户执行此命令，故不需要指定该子句。</p></main> |

## 示例

* 系统租户

  * 系统租户对指定租户发起归档日志备份。

    ```sql
    obclient [oceanbase]> ALTER SYSTEM BACKUP ARCHIVELOG ALL TENANT = mysql_tenant;
    ```

    语句执行后，系统会对集群中的 `mysql_tenant` 租户发起归档日志备份。

  * 系统租户对指定租户发起归档日志备份，备份成功完成后自动删除源端已备份的归档日志文件。

    ```sql
    obclient [oceanbase]> ALTER SYSTEM BACKUP ARCHIVELOG ALL DELETE INPUT TENANT = mysql_tenant;
    ```

    语句执行后，系统会对集群中的 `mysql_tenant` 租户发起归档日志备份，并在备份成功完成后自动删除源端已备份的归档日志文件。

* 用户租户

  * 租户 `mysql_tenant` 对本租户发起归档日志备份。

    ```sql
    obclient [oceanbase]> ALTER SYSTEM BACKUP ARCHIVELOG ALL;
    ```

    语句执行后，系统会对本租户发起归档日志备份。

  * 租户 `mysql_tenant` 对本租户发起归档日志备份，备份成功完成后自动删除源端已备份的归档日志文件。

    ```sql
    obclient [oceanbase]> ALTER SYSTEM BACKUP ARCHIVELOG ALL DELETE INPUT;
    ```

    语句执行后，系统会对本租户发起归档日志备份，并在备份成功完成后自动删除源端已备份的归档日志文件。
