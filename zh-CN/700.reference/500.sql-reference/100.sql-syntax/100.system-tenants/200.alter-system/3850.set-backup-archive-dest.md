# SET BACKUP_ARCHIVE_DEST

## 描述

`ALTER SYSTEM SET BACKUP_ARCHIVE_DEST` 语句用于为用户租户配置归档日志备份的备份目的端，即归档日志备份文件的存储路径配置。

## 使用限制及注意事项

* 对于 V4.4.2 版本，从 V4.4.2 BP3 版本开始支持 `ALTER SYSTEM SET BACKUP_ARCHIVE_DEST` 语句。

* 系统租户和 Meta 租户不支持备份恢复，不需要配置备份目的端。仅支持为用户租户配置 `BACKUP_ARCHIVE_DEST`（与现有的日志归档功能一致）。

* 归档日志备份的目的端不允许和 `LOG_ARCHIVE_DEST` 相同。

* 修改 `BACKUP_ARCHIVE_DEST` 与发起归档日志备份任务互斥：修改 `BACKUP_ARCHIVE_DEST` 期间发起归档日志备份会失败；归档日志备份任务未结束时不允许修改 `BACKUP_ARCHIVE_DEST`，系统会返回 `OPT_NOT_ALLOW` 错误。

* 修改 `BACKUP_ARCHIVE_DEST` 与带 `PLUS ARCHIVELOG` 参数的数据备份任务互斥：由于带 `PLUS ARCHIVELOG` 参数的数据备份任务执行期间可能会从 `BACKUP_ARCHIVE_DEST` 上拷贝 Piece 文件，为避免出现 Piece 一边拷贝一边删除的场景，修改 `BACKUP_ARCHIVE_DEST` 期间发起带 `PLUS ARCHIVELOG` 参数的数据备份任务会失败；带 `PLUS ARCHIVELOG` 参数的数据备份任务执行期间，修改 `BACKUP_ARCHIVE_DEST` 也会失败，系统会返回 `OPT_NOT_ALLOW` 错误。

* 目前，OceanBase 数据库支持的备份介质为 NFS、阿里云 OSS、Azure Blob、AWS S3 以及兼容 S3 协议的对象存储，例如：华为 OBS、Google GCS、腾讯云 COS。部分备份介质可能需要满足一些基本要求才能使用，有关各备份介质的具体要求，参见 [物理备份与恢复概述](../../../../../600.manage/600.backup-and-recovery/100.overview-of-physical-backup-and-recovery.md) 中的 **备份介质要求**。

## 权限要求

需要由 `sys` 租户的 `root` 用户（`root@sys`）或各租户的管理员用户执行。其中：

* MySQL 模式的默认管理员用户为 `root` 用户。
* Oracle 模式的默认管理员用户为 `SYS` 用户。

## 语法

```sql
ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=backup_archive_path' [TENANT = tenant_name];
```

## 参数说明

| 参数                  |                     描述                        |
|-----------------------|------------------------------------------------|
| backup_archive_path      | 指定归档日志备份的备份路径。有关该参数的详细说明，参见下方 [backup_archive_path](#backup_archive_path)。 |
| tenant_name           | 系统租户指定待配置归档日志备份目的端的租户名。<main id="notice" type='notice'> <h4>注意</h4><p>仅系统租户在执行此命令时需要通过 <code>TENANT = tenant_name</code> 子句指定待操作的租户，用户租户只能对本租户执行此命令，故不需要指定该子句。</p></main> |

### backup_archive_path

用于指定归档日志备份的备份路径配置。下面分别对不同类型的介质的 `backup_archive_path` 格式进行说明。

#### NFS

```sql
ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=file://your-nfs-server/your-backup-path' [TENANT = tenant_name];
```

其中：

* `file://your-nfs-server/your-backup-path`：OceanBase 数据库可以访问的 NFS 服务器的路径，用于存储归档日志的备份文件。

#### 对象存储

```sql
# 阿里云 OSS
ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=oss://your-bucket-name/your-archive-path?host=oss-your-region.aliyuncs.com&access_id=your-access-id&access_key=your-access-key[&delete_mode={delete | tagging}][&checksum_type={md5 | no_checksum}][&enable_worm=true]' [TENANT = tenant_name];

# AWS S3
ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=s3://your-bucket-name/your-archive-path?host=s3.your-region.amazonaws.com&access_id=your-access-id&access_key=your-access-key&s3_region=your-s3-region[&delete_mode={delete | tagging}][&checksum_type={md5 | crc32}]' [TENANT = tenant_name];

# 兼容 S3 协议的对象存储（例如：华为 OBS、Google GCS、腾讯云 COS）
ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=s3://your-bucket-name/your-archive-path?host=your-service.com&access_id=your-access-id&access_key=your-access-key[&addressing_model={virtual_hosted_style | path_style}][&checksum_type=md5]' [TENANT = tenant_name];

# Azure Blob
ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=azblob://your-bucket-name/your-archive-path?host=http://your-service.com&access_id=your-access-id&access_key=your-access-key[&delete_mode={delete | tagging}][&checksum_type=md5]' [TENANT = tenant_name];
```

相关参数说明如下：

<main id="notice" type='notice'>
<h4>注意</h4>
<p>使用对象存储作为备份介质时，对象存储路径的各项参数由 <code>&</code> 符号进行分隔，请确保您输入的参数值中仅包含英文字母大小写、数字、<code>/-_$+=</code> 以及通配符。如果您输入了上述以外的其他字符，可能会导致设置失败。</p>
</main>

* `host`：对象存储服务的访问域名。

  对于 Azure Blob 对象存储，其 `host` 参数对应的值可通过容器属性或存储账户的连接串拼接得到，并且要求 `host` 参数的前缀必须指定为 `http://` 或 `https://`。同时，由于 Azure Blob 默认开启了安全传输，默认是通过 `https://` 来访问，如果需要通过 `http://` 来访问，需要关闭 Azure Blob 的安全传输选项。关闭 Azure Blob 安全传输选项的详细操作，参见 [Azure Blob 官网文档](https://learn.microsoft.com/en-us/azure/storage/common/storage-require-secure-transfer?toc=%2Fazure%2Fstorage%2Fblobs%2Ftoc.json&bc=%2Fazure%2Fstorage%2Fblobs%2Fbreadcrumb%2Ftoc.json)。

* `access_id`：对象存储的访问秘钥 ID。

* `access_key`：对象存储的访问密钥。

* `delete_mode`：配置备份文件的清理模式，OSS、AWS S3、COS（以 S3 协议访问）、Azure Blob 的可选参数，与其他参数之间通过 `&` 符号连接。该参数当前支持以下两种取值：

  * `delete`：表示清理模式为直接删除满足清理要求的备份文件。

    配置为该模式后，当您通过自动方式清理备份文件时，对于满足清理要求的备份文件，系统会直接将其删除。

  * `tagging`：表示清理模式为对满足清理要求的备份文件设置 `Tag`，备份文件将仍然保留。

    配置为该模式后，当您通过自动方式清理备份文件时，对于满足清理要求的备份文件，系统会给这些文件设置标签，标签的 `key` 为 `"delete_mode"`，`value` 为 `"tagging"`，以便后续用户可以通过设置的标签在对象存储上对这些文件的生命周期进行管理。

* `checksum_type`：指定备份文件的校验算法，用于校验备份文件的完整性。如果未显式指定，所有对象存储默认均使用 MD5 校验算法。根据不同的对象存储，该参数支持的取值如下：

  * `md5`：使用 MD5 算法校验备份文件的完整性。

  * `no_checksum`：不校验备份文件的完整性。仅 OSS、Azure Blob 支持该取值。对于通过 S3 协议接入的对象存储，包括 AWS S3、OBS、GCS、COS 等，由于受到 S3 SDK 的限制，不支持该取值。

  * `crc32`：使用 CRC32 算法校验备份文件的完整性。仅 AWS S3 支持该取值。

* `enable_worm`：可选参数，当备份目的端为阿里云 OSS 且目的端 Bucket 配置了合规保留策略（WORM）时，需将该参数设置为 `true`。

  OSS 的保留策略具有 WORM（Write Once Read Many）特性，满足用户以不可删除、不可篡改的方式保存和使用数据。当用户为 Bucket 配置保留策略并锁定策略后，在保留策略指定的 Object 的保留时间到期前，仅支持在该 Bucket 中上传和读取 Object。待 Object 的保留时间到期后，才可以修改或删除该 Object。

  <main id="notice" type='notice'>
  <h4>注意</h4>
  <ul>
  <li>由于 OceanBase 数据库当前不会替代您设置合规保留策略，请在设置备份路径前确保 OSS Bucket 已正确设置保留策略（WORM 策略）并锁定。</li>
  <li>如果待设置的路径对应的 Bucket 设置并锁定了 WORM 策略，而在配置备份目的端时未指定 <code>enable_worm=true</code>，则语句执行后，系统将会报错，提示需要设置<code>enable_worm=true</code>。</li>
  <li><code>enable_worm</code> 参数一旦设置后，后续不支持变更。</li>
  <li>使用配置了 WORM 策略的 Bucket 作为备份路径时，推荐备份的清理模式使用 <code>tagging</code> 模式。</li></ul>
  </main>

  `enable_worm` 参数支持的取值如下：

  * `true`：是，表示 OceanBase 数据库会按照 WORM 的规范对该路径执行写入及删除操作。值设置为 `true` 时，要求同时显式配置 `checksum_type=md5`。

  * `false`：否。未显式指定该参数时，其默认值为 `false`。

* `s3_region`：Amazon S3 存储桶所在的区域。备份介质为 AWS S3 时，必须指定的参数。

* `addressing_model`：设置访问对象存储的 URL 格式，通过 S3 兼容协议访问的对象存储（OBS、GCS、COS 等）的可选参数，与其他参数之间通过 `&` 符号连接。该参数当前支持以下两种取值：

  * `virtual_hosted_style`：默认值，表示以 Virtual-hosted-style 访问对象存储。
  * `path_style`：表示以 Path-style 访问对象存储。

  例如，用户租户设置本租户使用 OBS 作为备份介质，并以 Virtual-hosted-style 格式访问 OBS，示例语句如下：

  ```shell
  ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=s3://oceanbase-test-bucket/backup/backup_archive?host=obs.****.myhuaweicloud.com&access_id=****&access_key=****&addressing_model=virtual_hosted_style';
  ```

## 示例

* 系统租户

  * 系统租户为租户 `mysql_tenant` 配置归档日志备份目的端，备份介质为 NFS。

    ```shell
    obclient [oceanbase]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=file:///data/nfs/backup/backup_archive' TENANT = mysql_tenant;
    ```

  * 系统租户为租户 `mysql_tenant` 配置归档日志备份目的端，备份介质为 OSS，备份文件的清理模式为 `delete`，使用 MD5 算法校验备份文件的完整性。

    ```shell
    obclient [oceanbase]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=oss://oceanbase-test-bucket/backup/backup_archive?host=****.aliyun-inc.com&access_id=****&access_key=****&delete_mode=delete&checksum_type=md5' TENANT = mysql_tenant;
    ```

  * 系统租户为租户 `mysql_tenant` 配置归档日志备份目的端，备份介质为 OSS，备份文件的清理模式为 `delete`，不校验备份文件的完整性。

    ```shell
    obclient [oceanbase]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=oss://oceanbase-test-bucket/backup/backup_archive?host=****.aliyun-inc.com&access_id=****&access_key=****&delete_mode=delete&checksum_type=no_checksum' TENANT = mysql_tenant;
    ```

  * 系统租户为租户 `mysql_tenant` 配置归档日志备份目的端，备份介质为 OSS，备份文件的清理模式为 `tagging`，使用 MD5 算法校验备份文件的完整性。

    ```shell
    obclient [oceanbase]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'LOCATION=oss://oceanbase-test-bucket/backup/backup_archive?host=****.aliyun-inc.com&access_id=****&access_key=****&delete_mode=tagging&checksum_type=md5' TENANT = mysql_tenant;
    ```

  * 系统租户为租户 `mysql_tenant` 配置归档日志备份目的端，备份介质为 OSS，备份文件的清理模式为 `tagging`，使用 MD5 算法校验备份文件的完整性。该路径配置了 `enable_worm=true` 时，系统将按照 WORM 的规范对该路径执行写入和删除操作。

    </main>

    ```shell

    ```

  * 系统租户为租户 `mysql_tenant` 配置归档日志备份目的端，备份介质为 AWS S3，备份文件的清理模式为 `delete`，使用 CRC32 算法校验备份文件的完整性。

## 查看归档日志备份目的端配置

归档日志备份目的端设置成功后，可通过以下视图查询配置信息。注意相关视图的 `dest_type` 字段为归档日志备份新增了 `backup_archive_log` 类型。

系统租户可通过 `CDB_OB_BACKUP_STORAGE_INFO` 和 `CDB_OB_ARCHIVE_DEST` 视图查看所有租户的备份目的端配置。

```sql
obclient(root@sys)[(none)]> SELECT * FROM oceanbase.CDB_OB_BACKUP_STORAGE_INFO WHERE dest_type = 'backup_archive_log';
```

查询结果如下：

```shell
+-----------+------------------------+----------+---------+--------------------+---------------+-----------+-----------------------------------------+----------------------------+----------+---------------+-----------------------+--------+
| TENANT_ID | PATH                   | ENDPOINT | DEST_ID | DEST_TYPE          | AUTHORIZATION | EXTENSION | CHECK_FILE_NAME                         | LAST_CHECK_TIMESTAMP       | MAX_IOPS | MAX_BANDWIDTH | MAX_BANDWIDTH_DISPLAY | STATUS |
+-----------+------------------------+----------+---------+--------------------+---------------+-----------+-----------------------------------------+----------------------------+----------+---------------+-----------------------+--------+
|      1002 | file:///data/backuparg |          |    1004 | backup_archive_log |               |           | 1002_connect_file_20260831T154520.obbak | 2026-08-31 15:45:20.327659 |        0 |             0 | UNLIMITED             | NORMAL |
+-----------+------------------------+----------+---------+--------------------+---------------+-----------+-----------------------------------------+----------------------------+----------+---------------+-----------------------+--------+
1 row in set
```

```sql
obclient(root@sys)[(none)]> SELECT * FROM oceanbase.CDB_OB_ARCHIVE_DEST WHERE name LIKE '%backup_archive%';
```

查询结果如下：

```shell
+-----------+---------+------------------------+------------------------+
| TENANT_ID | DEST_NO | NAME                   | VALUE                  |
+-----------+---------+------------------------+------------------------+
|      1002 |   10000 | backup_archive_dest_id | 1004                   |
|      1002 |   10000 | backup_archive_path    | file:///data/backuparg |
|      1002 |   10000 | backup_archive_state   | ENABLE                 |
+-----------+---------+------------------------+------------------------+
3 rows in set
```

查询结果中，`CDB_OB_BACKUP_STORAGE_INFO` 视图的 `PATH` 字段为归档日志备份目的端的存储路径，`DEST_TYPE` 字段的值为 `backup_archive_log`，表示该目的端的类型为归档日志备份目的端；`CDB_OB_ARCHIVE_DEST` 视图中，`backup_archive_path` 的值为归档日志备份目的端路径，`backup_archive_dest_id` 的值为该目的端的 `dest_id`，`backup_archive_state` 的值为 `ENABLE`，表示该备份目的端处于启用状态。

用户租户可通过 `DBA_OB_BACKUP_STORAGE_INFO` 和 `DBA_OB_ARCHIVE_DEST` 视图查看本租户的备份目的端配置。

```sql
obclient(root@mysql001)[(none)]> SELECT * FROM oceanbase.DBA_OB_BACKUP_STORAGE_INFO WHERE dest_type = 'backup_archive_log';
```

查询结果如下：

```shell
+-----------+------------------------+----------+---------+--------------------+---------------+-----------+-----------------------------------------+----------------------------+----------+---------------+-----------------------+--------+

|      1002 | file:///data/backuparg |          |    1004 | backup_archive_log |               |           | 1002_connect_file_20260831T154520.obbak | 2026-08-31 15:45:20.327659 |        0 |             0 | UNLIMITED             | NORMAL |
+-----------+------------------------+----------+---------+--------------------+---------------+-----------+-----------------------------------------+----------------------------+----------+---------------+-----------------------+--------+

```
