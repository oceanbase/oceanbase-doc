# 动态分区概述

动态分区是 OceanBase 数据库在 V4.3.5 BP2 版本提供的一种自动管理分区的功能，允许表根据预设规则自动创建和删除分区，从而简化运维并适应数据增长或过期的需求。

## 功能特性

* 根据 `TIME_UNIT`（如小时、天、月等）定期创建新分区，确保数据按时间范围自动扩展。

  * 分区边界基于时间单位（如 `hour`、`day`）划分，适用于按时间序列存储数据的场景（如日志、交易记录）。

* 通过 `PRECREATE_TIME` 预创建未来分区，避免因数据突增导致的分区不足问题。
* 根据 `EXPIRE_TIME` 定期清理过期分区，释放存储空间。例如：设置 `EXPIRE_TIME = '7day'` 会删除超过当前时间 7 天的旧分区。
* 支持自定义时区（`TIME_ZONE`），确保跨时区数据的一致性。
* 支持 `bigint` 类型时间戳的精度配置（如 `BIGINT_PRECISION`），适配不同时间精度需求。

### 预创建分区

当指定了至少一个分区定义时，预创建分区不会在建表后立刻创建，需等待一次动态分区管理调度，或手动执行一次动态分区管理。在执行动态分区管理时，系统会间隔 `TIME_UNIT` 创建分区，直到最大分区边界超过 `now() + precreate_time`，创建的第一个分区边界为现存最大分区边界按 `TIME_UNIT` 向上取整。例如，当前时间为 `2024-11-11 12:34:56`，调度一次动态分区管理后，分区为：

```sql
PARTITION P0 VALUES LESS THAN ('2024-11-11 13:30:00')
PARTITION P2024111113 VALUES LESS THAN ('2024-11-11 14:00:00'),
PARTITION P2024111114 VALUES LESS THAN ('2024-11-11 15:00:00'),
PARTITION P2024111115 VALUES LESS THAN ('2024-11-11 16:00:00')
```

若现存最大分区边界小于当前时间，预创建分区会尝试补充历史分区。例如现存最大分区为 `PARTITION P0 VALUES LESS THAN ('2024-11-11 11:30:00')`，当前时间为 `2024-11-11 12:34:56`，调度一次动态分区管理后，分区为：

```sql
PARTITION P0 VALUES LESS THAN ('2024-11-11 11:30:00'),
PARTITION P2024111111 VALUES LESS THAN ('2024-11-11 12:00:00'),
PARTITION P2024111112 VALUES LESS THAN ('2024-11-11 13:00:00'),
PARTITION P2024111113 VALUES LESS THAN ('2024-11-11 14:00:00'),
PARTITION P2024111114 VALUES LESS THAN ('2024-11-11 15:00:00'),
PARTITION P2024111115 VALUES LESS THAN ('2024-11-11 16:00:00')
```

补充了历史分区 `PARTITION P2024111111 VALUES LESS THAN ('2024-11-11 12:00:00')`。

### 自动创建分区的名字

系统会根据分区边界值和 `TIME_UNIT` 确定自动生成的分区名，分区名前缀为 `P`。

| **TIME_UNIT** | **分区上界** | **分区名** |
|---------------|--------------|------------|
| hour          | 2024-03-04 05:00:00 | P2024030404 |
| day           | 2024-03-05 00:00:00 | P20240304 |
| week          | 2024-03-11 00:00:00 | P2024_10（ISO 8601 第 10 周）|
| month         | 2024-04-01 00:00:00 | P202403 |
| year          | 2025-01-01 00:00:00 | P2024 |

## 注意事项

* 当前版本 `DROP` 分区后全局索引会失效，谨慎使用删除过期分区功能。
* 切主、DDL 并发等事件可能造成动态分区管理调度失败。为避免连续调度失败，未创建新分区导致数据写入失败，`PRECREATE_TIME` 不宜过小。
* 集群升级期间无法执行 DDL，期间动态分区管理功能无法使用，需要提前预建足够分区。
* 修改分区键列类型、修改分区规则后，若新表 Schema 不满足动态分区管理限制，后续动态分区管理在这张表上的调度会失败。
* 一次调度最多创建 2048 个分区。如果需要补的历史分区过多，调度多次才能满足预创建时间。
* 租户升级到 V4.3.5 BP2 版本后，动态分区管理自动开启，额外引入每小时迭代一次租户 simple table schema 的开销，纯内存操作，1 万张表耗时 0.7ms。若无需动态分区管理功能，且对此开销敏感，可通过开关关闭。
* 大压力集群执行 DDL 时，由于 table schema 变更，可能导致大量线程同时发 inner sql 刷新 full table schema，造成抖动。大压力场景谨慎使用动态分区管理功能。
* 动态分区管理功能需要在后台发送 DDL 进行分区的创建和删除。为避免 DDL 线程被持续占用，动态分区表数不宜过多。

## 使用限制

* 仅支持 Range Columns 分区和 Range 分区：

  * Range Columns 分区：分区键为 `date`、`datetime`、`timestamp`、`year`、`bigint`（指定 `BIGINT_PRECISION` 精度）类型的分区表可开启动态分区管理。其中 `date` 类型 `TIME_UNIT` 不支持 `hour`，`year` 类型 `TIME_UNIT` 仅支持 `year`。
  * Range 分区：分区键为 `year`、`bigint`（指定 `BIGINT_PRECISION` 精度）类型的分区表可开启动态分区管理。

* 仅能对一级分区表和二级分区表的一级分区开启动态分区管理。
* 动态分区参数限制：

  * `TIME_UNIT`：`date` 类型不能使用 `hour`，`year` 类型仅能使用 `year`。
  * `PRECREATE_TIME`：最多预创建 2048 个分区。
  * `TIME_ZONE`：只有 `date`、`datetime`、`year` 类型可以指定，其他类型只能为 `default`。
  * `BIGINT_PRECISION`：只有 `bigint` 可以指定该参数值（`us`、`ms`、`s`），其他类型该参数值只能为 `none`。
  * `TIME_UNIT`、`TIME_ZONE`、`BIGINT_PRECISION` 指定后不能修改。
