# 创建 Catalog

本文将向您介绍如何使用 SQL 语句创建 External Catalog。

## 权限要求

创建 External Catalog，需要当前用户拥有 `CREATE CATALOG` 系统权限。

```text
GRANT CREATE CATALOG TO user_name;
```

有关 OceanBase 数据库权限的详细介绍，参见 [Oracle 模式下的权限分类](../../../../600.manage/500.security-and-permissions/300.access-control/200.user-and-permission/300.permission-of-oracle-mode/000.permission-classification-of-oracle-mode.md)。

## 语法

创建 External Catalog 的 SQL 语句格式如下：

```sql
CREATE EXTERNAL CATALOG external_catalog_name
    PROPERTIES [=] (properties_type_list);

properties_type_list:
    odps_type_list
    | hms_type_list
    | jdbc_type_list

odps_type_list:
    TYPE = 'ODPS',
    [ACCESSTYPE = 'accesstype_string',]
    ACCESSID = 'string',
    ACCESSKEY = 'string',
    STSTOKEN = 'string',
    ENDPOINT = 'string',
    TUNNEL_ENDPOINT = 'string',
    PROJECT_NAME = 'string',
    [QUOTA_NAME = 'string',]
    REGION = 'string'

hms_type_list:
    TYPE = 'HMS',
    URI = 'string'
    [, KRB5CONF = 'string']
    [, KEYTAB = 'string']
    [, PRINCIPAL = 'string']
    [, MAX_CLIENT_POOL_SIZE = 20]
    [, SOCKET_TIMEOUT = 10000000]

jdbc_type_list:
    TYPE = 'JDBC',
    URL = 'string'
```

**参数说明：**

* `external_catalog_name`：表示要创建的外部数据目录的名称。不区分大小写，未使用双引号括起来时统一转换为大写存储。
* `PROPERTIES [=] (properties_type_list)`：用于指定外部数据目录类型的相关属性选项。
* `odps_type_list`：表示 ODPS 类型外部数据目录（ODPS Catalog）的相关属性列表。
* `hms_type_list`：表示 HMS 类型外部数据目录（HMS Catalog）的相关属性列表。
* `jdbc_type_list`：表示 JDBC 类型外部数据目录（JDBC Catalog）的相关属性列表。

有关创建 External Catalog 语法的详细参数说明信息，参见 [CREATE EXTERNAL CATALOG](../../../500.sql-reference/100.sql-syntax/300.common-tenant-of-oracle-mode/900.sql-statement-of-oracle-mode/100.ddl-of-oracle-mode/4700.create-external-catalog-of-oracle-mode.md)。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>与 MySQL 模式不同，Oracle 模式下的 <code>CREATE EXTERNAL CATALOG</code> 语句不支持 <code>IF NOT EXISTS</code> 子句。</p>
</main>

## 示例

### 创建 ODPS 类型的 External Catalog

外表读写 MaxCompute 数据时，取值为 `ODPS`。

通过 `CREATE EXTERNAL CATALOG` 创建与 MaxCompute（ODPS）的连接，实现直接查询 ODPS 表数据，无需手动创建映射表。Catalog 下对象为只读。

**示例如下：**

```sql
obclient> CREATE EXTERNAL CATALOG tmp_odps_catalog PROPERTIES = (TYPE = 'ODPS', ACCESSID = '$odps_accessid', ACCESSKEY = '$odps_accesskey', ENDPOINT = '$odps_endpoint', TUNNEL_ENDPOINT = 'http://xxx.maxcompute.aliyun.com', PROJECT_NAME = 'odps_test_project');

obclient> DROP CATALOG tmp_odps_catalog;
```

### 创建 HMS 类型的 External Catalog

OceanBase 数据库通过 HMS Catalog 功能，实现对 Hive 元数据（Metastore）的统一管理。通过 HMS Catalog，OceanBase 可直接访问 Hive 表对应的 HDFS 存储路径中的数据，支持高效的数据湖查询与分析。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>创建 HMS Catalog 前，如果 HMS 预期访问底层存储的文件数据在 HDFS 上，则需要完成 Java SDK 环境部署。有关配置 JAVA SDK 环境的详细信息，参见 <a href="../../../../400.deploy/300.deploy-oceanbase-enterprise-edition/500.deploy-the-ob-java-sdk-environment.md">部署 OceanBase 数据库 JAVA SDK 环境</a>。</p>
</main>

**示例如下：**

```sql
obclient> CREATE EXTERNAL CATALOG tmp_hms_catalog PROPERTIES = (TYPE = 'HMS', URI = 'thrift://xx.xx.xx.xx:9083');

obclient> DROP CATALOG tmp_hms_catalog;
```

有关 HMS Catalog 支持的表格式等信息，参见 MySQL 模式下的 [创建 Catalog](../../100.manage-object-of-mysql-mode/1000.manage-catalog-of-mysql-mode/200.create-catalog-of-mysql-mode.md) 中的 **创建 HMS 类型的 External Catalog** 章节。

### 创建 JDBC 类型的 External Catalog

从 V4.4.2 BP4 版本开始，Oracle 模式支持 JDBC 类型的 External Catalog，当前仅支持连接 SQL Server 数据源。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>创建 JDBC Catalog 前，需要完成 Java SDK 环境部署，且 devdeps-java-extensions RPM 包需为 1.0.6 及以上版本。有关配置 JAVA SDK 环境的详细信息，参见 <a href="../../../../400.deploy/300.deploy-oceanbase-enterprise-edition/500.deploy-the-ob-java-sdk-environment.md">部署 OceanBase 数据库 JAVA SDK 环境</a>。</p>
</main>

**示例如下：**

```sql
obclient> CREATE EXTERNAL CATALOG test_jdbc_catalog PROPERTIES = (TYPE = 'JDBC', URL = 'jdbc:sqlserver://10.10.10.1:1433');

obclient> DROP CATALOG test_jdbc_catalog;
```

创建成功后，可以通过 Catalog 名 + Schema 名 + 表名的三段式命名访问 SQL Server 中的表，例如 `test_jdbc_catalog.dbo.table_name`。也可以先使用 `SET CATALOG` 切换到目标 Catalog，再通过 `Schema 名.表名` 的两段式命名访问，例如 `dbo.table_name`。

外部表的列类型由 devdeps-java-extensions 提供的列元数据（`targetType`）决定，映射为 Oracle 模式下的数据类型。SQL Server 数据源的主要类型映射如下：

| **SQL Server 类型** | **Oracle 模式下的类型** |
|---------------------|-------------------------|
| BIT | NUMBER(1) |
| TINYINT | NUMBER(3) |
| SMALLINT | NUMBER(5) |
| INT | NUMBER(10) |
| BIGINT | NUMBER(19) |
| DECIMAL / NUMERIC | NUMBER(p,s) |
| SMALLMONEY | NUMBER(10,4) |
| MONEY | NUMBER(19,4) |
| REAL / FLOAT(24) | BINARY_FLOAT |
| FLOAT(53) / DOUBLE | BINARY_DOUBLE |
| CHAR(n) | VARCHAR2(n CHAR) |
| VARCHAR(n) | VARCHAR2(n CHAR) |
| NCHAR(n) | NVARCHAR2(n) |
| NVARCHAR(n) | NVARCHAR2(n) |
| BINARY(n) | RAW(n) |
| VARBINARY(n) | RAW(n) |
| DATE | DATE |
| TIME | INTERVAL DAY (1) TO SECOND (n) |
| SMALLDATETIME | TIMESTAMP(0) |
| DATETIME | TIMESTAMP(3) |
| DATETIME2 | TIMESTAMP(7) |
| 不支持的类型 | UNSUPPORTED |

<main id="notice" type='notice'>
  <h4>注意</h4>
  <ul>
  <li>JDBC Catalog 下的对象为只读，不支持执行 <code>INSERT</code>、<code>UPDATE</code>、<code>DELETE</code>、<code>ALTER TABLE</code>、<code>DROP TABLE</code> 等修改语句。</li>
  <li>当外部表中存在数据类型显示为 <code>UNSUPPORTED</code> 的列时，该列不可查询，查询其他列不受影响。</li>
  </ul>
</main>
