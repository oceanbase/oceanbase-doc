# 创建 DDL 触发器

OceanBase 数据库的 Oracle 模式支持系统触发器。系统触发器按照触发事件分为 Database 事件触发器和 DDL 事件触发器两类，其中 Database 事件触发器由 `LOGON`、`LOGOFF` 事件触发，DDL 事件触发器由 DDL 语句触发。从 V4.4.2 BP4 版本开始，OceanBase 数据库支持创建 BEFORE DDL 触发器。

DDL 触发器在 DDL 语句执行前自动运行，常用于记录 DDL 操作日志、审计 DDL 变更，以及通过抛出异常阻断不符合规范的 DDL 操作。

## 适用范围

* 仅 Oracle 模式的用户租户支持 DDL 触发器，不允许创建监听 `SYS` Schema 的系统触发器，即不支持 `ON SYS.SCHEMA`。
* 仅支持 `BEFORE` 触发时机，暂不支持 `AFTER DDL` 触发器。
* 主备库中的备租户不触发 DDL 触发器。
* DDL 触发器受系统触发器总开关控制，该开关默认开启。

## 语法

```sql
CREATE [OR REPLACE] TRIGGER [schema.]trigger_name
  BEFORE ddl_event [OR ddl_event]...
  ON {[schema.]SCHEMA | DATABASE}
  [FOLLOWS [owner.]other_trigger]
  [ENABLE | DISABLE]
  [WHEN (condition)]
DECLARE
  ...
BEGIN
  ...
END;
/
```

## 参数说明

| 参数 | 说明 |
|------|------|
| `trigger_name` | 触发器名称。触发器名称在同一个 Schema 内必须唯一，可以与表、存储过程同名。 |
| `BEFORE` | 指定触发器在 DDL 语句执行前触发。DDL 事件触发器仅支持 `BEFORE`。 |
| `ddl_event` | 触发事件，可以指定一个或多个事件，多个事件之间使用 `OR` 分隔。支持的事件请参见下文 **DDL 事件**。 |
| `ON SCHEMA` | 指定触发器的作用范围为 Schema 级别。不指定 `schema` 时，默认绑定创建语句执行时的 `CURRENT_SCHEMA`，不一定是登录用户所在的 Schema。触发器 Owner 由 `trigger_name` 前的 Schema 决定，可以与监听的目标 Schema 不同。 |
| `ON DATABASE` | 指定触发器的作用范围为当前用户租户内的所有用户，不跨租户。 |
| `FOLLOWS` | 指定触发器的执行顺序，即新触发器在 `other_trigger` 之后执行。 |
| `ENABLE \| DISABLE` | 指定触发器的启用状态，默认为 `ENABLE`。 |
| `WHEN (condition)` | 指定触发条件，`condition` 为布尔表达式，可使用事件属性函数构造布尔条件，不能引用 `:OLD`、`:NEW` 等伪记录。 |

## DDL 事件

| 事件（`ORA_SYSEVENT` 返回值） | 触发的语句 |
|------|------|
| `CREATE` | `CREATE TABLE`（含 CTAS、GTT）、`CREATE INDEX`、`CREATE VIEW`、`CREATE MATERIALIZED VIEW`、`CREATE MATERIALIZED VIEW LOG`、`CREATE SEQUENCE`、`CREATE PROCEDURE`、`CREATE FUNCTION`、`CREATE PACKAGE`/`PACKAGE BODY`、`CREATE TRIGGER`、`CREATE TYPE`/`TYPE BODY`、`CREATE SYNONYM`、`CREATE DATABASE LINK`、`CREATE TABLESPACE`、`CREATE DIRECTORY`、`CREATE CONTEXT`、`CREATE OUTLINE`、`CREATE USER`、`CREATE ROLE`、`CREATE PROFILE`。`CREATE OR REPLACE` 只触发一次。 |
| `ALTER` | `ALTER TABLE`、`ALTER INDEX`、`ALTER VIEW`、`ALTER MATERIALIZED VIEW`、`ALTER SEQUENCE`、`ALTER PROCEDURE`、`ALTER FUNCTION`、`ALTER PACKAGE`、`ALTER TRIGGER`、`ALTER TYPE`、`ALTER TABLESPACE`、`ALTER OUTLINE`、`ALTER USER`（含修改密码、锁定用户、修改 Profile 等）、`ALTER ROLE`、`ALTER PROFILE`。`ALTER TABLE ... RENAME` 和 `ALTER TABLE ... DROP COLUMN` 均属于 `ALTER` 事件。 |
| `DROP` | `DROP TABLE`、`DROP INDEX`、`DROP VIEW`、`DROP MATERIALIZED VIEW`、`DROP MATERIALIZED VIEW LOG`、`DROP SEQUENCE`、`DROP PROCEDURE`、`DROP FUNCTION`、`DROP PACKAGE`、`DROP TRIGGER`、`DROP TYPE`、`DROP SYNONYM`、`DROP DATABASE LINK`、`DROP TABLESPACE`、`DROP DIRECTORY`、`DROP CONTEXT`、`DROP OUTLINE`、`DROP USER`、`DROP ROLE`、`DROP PROFILE`。`DROP TABLE ... PURGE` 属于 `DROP` 事件，`CASCADE` 不会对被级联删除的对象逐个触发。 |
| `TRUNCATE` | `TRUNCATE TABLE`。`ALTER TABLE` 中的分区操作不会映射为 `TRUNCATE` 事件。 |
| `RENAME` | 独立的 `RENAME` 语句。`ALTER ... RENAME` 不触发该事件。 |
| `COMMENT` | `COMMENT ON TABLE`、`COMMENT ON COLUMN`。 |
| `ANALYZE` | 对单表执行的 `ANALYZE TABLE`。 |
| `AUDIT` / `NOAUDIT` | `AUDIT`、`NOAUDIT` 语句，需要企业版审计功能支持。 |
| `GRANT` / `REVOKE` | 对象权限、系统权限、角色的授予和回收，一条语句只触发一次。 |
| `DDL` | 捕获上述所有 DDL 事件，用于定义通用 DDL 触发器。 |

<main id="notice" type='explain'>
<h4>说明</h4>
<p><code>DDL</code> 事件还可以捕获未单独列出的事件，例如 <code>FLASHBACK TABLE ... TO BEFORE DROP</code>（<code>ORA_SYSEVENT</code> 返回 <code>UNDROP</code>）和 <code>PURGE TABLE</code>（<code>ORA_SYSEVENT</code> 返回 <code>PURGE</code>）。</p>
</main>

以下操作不会触发 DDL 触发器：

* OB 资源与租户管理语句，例如 `RESOURCE POOL`、`RESOURCE UNIT`、`TENANT`、`STANDBY TENANT`、`TABLEGROUP` 等。
* OB 或 MySQL 兼容扩展语句，例如 `OPTIMIZE`、`SET GLOBAL`、`CREATE TABLE LIKE`、`LOCATION`、`CATALOG`、限流规则等。
* Oracle 模式下语义不同的语句，例如 `CREATE DATABASE`、`ALTER DATABASE`、`ALTER SYSTEM`、`ALTER SESSION` 等。
* DDL 内部派生的动作，例如 CTAS 的插入与失败清理、隐式创建或删除的索引、物化视图的容器表等。
* 内核内部动作，例如 RootService 内部 SQL、DDL 任务的子任务与恢复、RPC 重发、日志回放、备库应用等。

## 事件属性函数

DDL 触发器的 Trigger Body 和 `WHEN` 条件中可以调用事件属性函数，获取当前 DDL 事件的相关信息。OceanBase 数据库提供以下 16 个 `ORA_*` 函数：

| 函数 | 适用事件 | 返回值 |
|------|----------|--------|
| `ORA_SYSEVENT` | 全部事件 | 当前事件的名称，即上表中的事件名。 |
| `ORA_LOGIN_USER` | 全部事件 | 当前登录用户名，不依赖 DDL 事件上下文。 |
| `ORA_INSTANCE_NUM` | 全部事件 | 当前 OBServer 节点的实例编号，不依赖 DDL 事件上下文。 |
| `ORA_DATABASE_NAME` | 全部事件 | 当前租户的名称，不依赖 DDL 事件上下文。 |
| `ORA_DICT_OBJ_OWNER` | 对象 DDL、`GRANT`/`REVOKE` | DDL 目标对象的 Owner。 |
| `ORA_DICT_OBJ_NAME` | 对象 DDL、`GRANT`/`REVOKE` | DDL 目标对象的名称。 |
| `ORA_DICT_OBJ_TYPE` | 对象 DDL、`GRANT`/`REVOKE` | DDL 目标对象的类型。`GRANT`/`REVOKE` 场景返回 `OBJECT PRIVILEGE`、`SYSTEM PRIVILEGE` 或 `ROLE PRIVILEGE`。 |
| `ORA_SQL_TXT(sql_text OUT ORA_NAME_LIST_T)` | 全部事件 | 返回触发语句的 SQL 文本，其中密码等敏感内容会脱敏，部分敏感语句可能整句返回 `***`。返回文本按每段最多 63 字节（保证多字节字符完整）拆分后写入 `sql_text`，函数返回分片数量。 |
| `ORA_IS_ALTER_COLUMN(column_name)` | `ALTER` | 指定的列在本次 `ALTER TABLE` 中被修改时返回 `TRUE`，否则返回 `FALSE`。 |
| `ORA_IS_DROP_COLUMN(column_name)` | `ALTER` | 指定的列在本次 `ALTER TABLE` 中被删除时返回 `TRUE`，否则返回 `FALSE`。 |
| `ORA_IS_CREATING_NESTED_TABLE` | `CREATE` | OceanBase 数据库不支持 Oracle 的嵌套表列，该函数兼容保留，固定返回 `FALSE`。 |
| `ORA_GRANTEE(user_list OUT ORA_NAME_LIST_T)` | `GRANT` | 返回本次授权的所有被授权用户，函数返回用户数量。 |
| `ORA_REVOKEE(user_list OUT ORA_NAME_LIST_T)` | `REVOKE` | 返回本次回收权限的所有用户，函数返回用户数量。 |
| `ORA_PRIVILEGE_LIST(privilege_list OUT ORA_NAME_LIST_T)` | `GRANT`/`REVOKE` | 返回本次授予或回收的权限名或角色名，函数返回数量。使用 `ALL` 时按 OceanBase 数据库权限模型的顺序展开。 |
| `ORA_WITH_GRANT_OPTION` | `GRANT` | 授予对象权限且带有 `WITH GRANT OPTION` 时返回 `TRUE`；`WITH ADMIN OPTION` 返回 `FALSE`。 |
| `ORA_DES_ENCRYPTED_PASSWORD` | `CREATE`/`ALTER` | OceanBase 数据库没有等价的 DES 加密值，该函数兼容保留，固定返回 `NULL`。 |

<main id="notice" type='explain'>
<h4>说明</h4>
<p><code>ORA_NAME_LIST_T</code> 是 <code>SYS.DBMS_STANDARD</code> 包中定义的集合类型，元素类型为 <code>VARCHAR2(261)</code>。上述 <code>DBMS_STANDARD</code> 中的函数可以直接裸调用，无需添加包名前缀，例如 <code>ORA_GRANTEE(user_list)</code>。在没有 DDL 事件上下文时，依赖上下文的函数返回 <code>NULL</code> 或 <code>FALSE</code>。</p>
</main>

## 使用限制

创建和使用 DDL 触发器时，需要注意以下限制：

* 触发器作用范围的匹配规则如下：

  * `ON SCHEMA` 按当前用户匹配，即当前用户执行 DDL 时触发该用户 Schema 上的 DDL 触发器；不按 DDL 目标对象的 Owner 匹配。
  * `ON DATABASE` 按当前租户匹配，当前租户内任意用户执行 DDL 时均会触发。

* 执行顺序规则如下：

  * 同一个 DDL 语句同时匹配 Schema 级和 Database 级触发器时，先执行 Schema 级触发器，再执行 Database 级触发器。
  * 同一个作用范围内，可以使用 `FOLLOWS` 指定触发器的执行顺序；未指定时，多个触发器的执行顺序不确定。
  * 不支持跨作用范围指定 `FOLLOWS`。被引用的触发器也必须是 DDL 触发器，且两者的触发事件集合存在交集。

* Trigger Body 中禁止经 SQL 或 PL 的 SPI 接口执行任何 DDL、DCL 和 `ANALYZE` 语句。

* Trigger Body 中禁止设置全局变量和系统变量。

* 普通 DDL 触发器内不能执行 `COMMIT` 或 `ROLLBACK`，否则返回 `ORA-04092` 错误。如果触发器使用 `PRAGMA AUTONOMOUS_TRANSACTION` 声明为自治事务，自治事务中的提交独立于触发器批次事务。

* 当前触发器作为 DDL 目标时，该触发器不会参与本次触发，例如 `CREATE OR REPLACE TRIGGER` 或 `DROP TRIGGER` 操作本身。

* 内核内部发起的 DDL 和备租户上的 DDL 不会触发触发器；同一条 DDL 自动重试时不会重复执行已经提交的触发器。

### 事务说明

DDL 触发器与后续的 DDL 语句不在同一个事务中执行，具体行为如下：

1. 一条 DDL 语句匹配到的所有 DDL 触发器在同一个批次事务中依次执行，执行期间会临时关闭会话的自动提交。
2. 所有触发器执行成功后，批次事务提交一次，然后才执行实际的 DDL 语句或向 RootService 发送 DDL 请求。
3. 任意一个触发器执行失败时，回滚整个批次事务，并中止本次 DDL，不执行实际的 DDL 操作。
4. 触发器批次事务提交后，即使后续 DDL 执行失败、超时或被取消，触发器已经提交的修改也不会回滚。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>由于触发器与 DDL 分属两个事务，触发器记录的日志或写入的数据在 DDL 失败时仍然存在，业务实现中需要允许这种不一致。如果需要严格保证触发器修改与 DDL 同成败，请在触发器中仅做校验或提示，不要依赖触发器写入的数据判断 DDL 是否成功。</p>
</main>

## 权限要求

* 在自己的 Schema 中创建 DDL 触发器，需要具备 `CREATE TRIGGER` 或 `CREATE ANY TRIGGER` 系统权限。
* 跨 Schema 创建 DDL 触发器，或使用 `ON schema.SCHEMA` 监听其他用户的 Schema，需要具备 `CREATE ANY TRIGGER` 系统权限。
* 创建 Database 级 DDL 触发器（`ON DATABASE`）时，在上述基础创建权限之外，还需要具备 `ADMINISTER DATABASE TRIGGER` 系统权限。

## 示例

创建一张 DDL 日志表，用于记录 DDL 事件。

```sql
CREATE TABLE ddl_log (
  event_name VARCHAR2(50),
  obj_type   VARCHAR2(50),
  obj_name   VARCHAR2(128),
  login_user VARCHAR2(128),
  ddl_time   DATE
);
```

创建一个 Schema 级的 `BEFORE CREATE` 触发器，记录 `CREATE` 语句的对象信息。

```sql
CREATE OR REPLACE TRIGGER trg_before_create
  BEFORE CREATE ON SCHEMA
BEGIN
  INSERT INTO ddl_log
    VALUES (ORA_SYSEVENT, ORA_DICT_OBJ_TYPE, ORA_DICT_OBJ_NAME, ORA_LOGIN_USER, SYSDATE);
END;
/
```

执行一条 `CREATE TABLE` 语句，验证触发器是否生效。

```sql
CREATE TABLE t_ddl_trigger_demo (id INT);
```

查询日志表，可以看到本次 `CREATE` 事件的记录。

```sql
SELECT * FROM ddl_log;
```

创建一个 Database 级的 `BEFORE DDL` 触发器，记录当前租户内所有的 DDL 事件。执行该示例的用户在具备基础创建权限之外，还需要具备 `ADMINISTER DATABASE TRIGGER` 系统权限。

```sql
CREATE OR REPLACE TRIGGER trg_before_ddl
  BEFORE DDL ON DATABASE
BEGIN
  INSERT INTO ddl_log
    VALUES (ORA_SYSEVENT, ORA_DICT_OBJ_TYPE, ORA_DICT_OBJ_NAME, ORA_LOGIN_USER, SYSDATE);
END;
/
```

创建一个 `BEFORE DROP` 触发器，在删除表时通过抛出异常阻断 `DROP TABLE` 操作。

```sql
CREATE OR REPLACE TRIGGER trg_before_drop
  BEFORE DROP ON SCHEMA
BEGIN
  IF ORA_DICT_OBJ_TYPE = 'TABLE' THEN
    RAISE_APPLICATION_ERROR(-20001, 'DROP TABLE is not allowed');
  END IF;
END;
/
```

使用完成后，删除示例中创建的触发器和表。

```sql
DROP TRIGGER trg_before_create;
```

```sql
DROP TRIGGER trg_before_ddl;
```

```sql
DROP TRIGGER trg_before_drop;
```

```sql
DROP TABLE t_ddl_trigger_demo;
```

```sql
DROP TABLE ddl_log;
```
