# V4.2.1 文档更新记录

## V4.2.1 BP8（2024-07-25）

| 功能 | 描述 |
| --- | --- |
| 日志流副本管理功能增强 | 重新设计实现日志流副本级别任务的运维方式，提供一系列语法，用于支持日志流副本的添加、删除、副本类型转换、迁移、修改日志流 Paxos 成员数量和取消容灾任务等能力，满足客户手动运维日志流副本的需求。更多信息请参见 [日志流副本概述](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000220983)。 |
| DBLink 支持指定域名访问 | OceanBase 数据库支持通过 DBLink 访问远端数据库。老版本需要在创建 DBLink 时指定远端数据库的 IP 地址，新版本增加支持配置域名地址。更多信息请参见 [创建 DBLink](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000220190)。 |
| 主备租户角色切换验证 | 新增支持主备租户角色切换验证功能（SWITCHOVER/FAILOVER VERIFY），在切换命令后添加 VERIFY 关键字，可以提前验证对应操作是否可以成功执行，如对应操作不可执行，将给出报错信息。更多信息请参见 [SWITCHOVER](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000221284)。 |
| 主备租户事件展示 | 将主备租户操作记录拆分到每个租户下，通过 `CDB/DBA_OB_TENANT_EVENT_HISTORY` 视图透出。更多信息请参见 [oceanbase.CDB_OB_TENANT_EVENT_HISTORY](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000219609)、[oceanbase.DBA_OB_TENANT_EVENT_HISTORY](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000219658)。 |
| 事务提交后 Cursor 访问 | 允许 Cursor 在没读取当前事务修改的表的情况下，在事务结束后依然可以 Fetch 数据，但需要通过 `_enable_enhanced_cursor_validation` 配置项开启。 |
| 增加 SM3 加密函数 | MySQL 模式下新增 SM3 加密函数，Oracle 模式下在 `DBMS_CRYPTO.HASH` 子程序下新增 HASH_SM3 哈希加密算法。更多信息请参见 [SM3（MySQL 模式）](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000001124411)、[DBMS_CRYPTO 概述（Oracle 模式）](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000221803)。 |
| 仲裁支持混合云双活架构 | 新增集群级配置项 `arbitration_degradation_policy`，表示不同的仲裁降级策略，优化 2F1A/4F1A 部署情况下，由于网络问题触发仲裁降级的问题。详情请参见 [arbitration_degradation_policy](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000001607047)。 |
| OBKV 响应时间统计直方图 | 在 `[G]V$OB_QUERY_RESPONSE_TIME_HISTOGRAM` 系统视图中增加了 OBKV 相关的统计类别，包括 `TABLEAPI SELECT`、`TABLEAPI INSERT`、`TABLEAPI DELETE`、`TABLEAPI UPDATE`、`TABLEAPI REPLACE`、`TABLEAPI QUERY AND MUTATE`、`TABLEAPI OTHER`、`HBASE SCAN`、`HBASE PUT`、`HBASE DELETE`、`HBASE APPEND`、`HBASE INCREMENT`、`HBASE CHECK AND PUT`、`HBASE CHECK AND DELETE`、`HBASE HYBRID BATCH` 等。详情请参见 [GV$OB_QUERY_RESPONSE_TIME_HISTOGRAM](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000833388)。 |
| OBKV-HBase 列分页 | 原生 HBase 支持列分页，在大宽表场景下提供了更好的查询性能。新版本 OBKV-HBase 也提供了类似的列分页能力，支持通过 ColumnPaginationFilter 过滤器限制返回列数。 |
| OBKV-HBase 逆序扫描 | 新增 Reverse Scan 功能，允许用户以 RowKey 逆序（从大到小）扫描表中的数据，提升查询性能。 |
| 操作系统适配支持 | 支持使用 Python 3 运行升级、TimeZone 导入等 OceanBase 内核自带的脚本，以适配部分高版本操作系统的 Python 环境依赖。 |
| 新增 `arbitration_degradation_policy` 配置项 | 新增集群级配置项，表示不同的仲裁降级策略。 `LS_POLICY` 表示默认的降级策略，`CLUSTER_POLICY` 表示降级前检查是否与 RS 网络连通。更多信息请参见 [arbitration_degradation_policy](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000001607047)。 |
| `information_schema.columns` 视图新增列 | 新增 `srs_id` 列用于表示空间坐标系信息。详情请参见 [information_schema.columns](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000611116)。 |
| `[G]V$OB_SQL_AUDIT` 视图列内容变更 | 原视图 `params_value` 字段只会记录 SQL 参数信息。新版本增加记录 PL 入参信息，暂时仅支持普通数据类型入参记录，不支持复杂数据类型入参记录。详情请参见 [GV$OB_SQL_AUDIT](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000220956)。 |
| `CDB/DBA_OB_LS_REPLICA_TASKS` 视图新增列 | 新增 `data_source_svr_ip`、`data_source_svr_port`、`is_manual` 列，用于记录容灾任务执行时引用的数据源和容灾任务生成来源。更多信息请参考 [oceanbase.CDB_OB_LS_REPLICA_TASKS](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000219506)、[oceanbase.DBA_OB_LS_REPLICA_TASKS](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000219534)。 |
| 新增 `CDB/DBA_OB_LS_REPLICA_TASK_HISTORY` 视图 | 新增系统视图，用于展示容灾任务执行历史。CDB 视图仅在 SYS 租户支持，DBA 视图在所有租户支持。更多信息请参见 [oceanbase.CDB_OB_LS_REPLICA_TASK_HISTORY](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000001097370)、[oceanbase.DBA_OB_LS_REPLICA_TASK_HISTORY](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000001097371)。 |

## V4.2.1 BP7（2024-05-30）

| 功能 | 描述 |
| --- | --- |
| 备份恢复支持 S3/OBS/GCS | 新增支持 S3 协议，可将 S3/OBS/GCS 作为日志归档和数据备份的目的端，同时支持使用 S3/OBS/GCS 上的备份数据进行物理恢复。更多信息请参见[物理备份与恢复概述](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000218106)。 |
| 旁路导入中间数据支持开启压缩 | 增加旁路导入中间数据压缩功能，通过租户级配置项  `_ob_ddl_temp_file_compress_func` 控制是否开启及使用的压缩算法。默认为 `NONE`，表示不开启压缩，适用于磁盘空间足够，希望获得更高导入性能的场景。根据业务需要可修改为 `ZSTD` 或 `LZ4`，来指定对应的压缩算法开启中间数据压缩，或设置为 `AUTO` 自适应开启压缩。 |
| SET/PIECE 级物理恢复 | 增加 SET/PIECE 级物理恢复功能，提供 `ADD RESTORE SOURCE` 命令来加载新路径的数据备份集 SET 或日志归档 PIECE，支持按需恢复到指定时间。更多信息请参见 [执行指定路径的恢复](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000827705)。|
| 迁移复制源端选择优化 | 将各 Server 按照地域信息划分为同 IDC、同 Region 不同 IDC、跨 Region 三种区域关系，同时提供 `choose_migration_source_policy` 配置项，用于迁移复制场景下，指定源端的选择模式，以便优先考虑地理位置就近因素以及 Follower 副本来提升迁移效率、降低 Leader 压力。更多信息请参见 [choose_migration_source_policy](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000833394)。 |
| 物理恢复进度统计 | 增加物理恢复进度统计功能。用户可通过 `CDB/DBA_OB_RESTORE_PROGRESS` 视图实时查看恢复进度，获得更好的使用体验。更多信息请参见 [查看物理恢复进度](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000218387)。 |
| 全局 CPU 前后台任务隔离 | 支持全局 CPU 前后台任务隔离，可以在整体层面上限制后台任务的可用资源，相对租户内使用 `DBMS_RESOURCE_MANAGER` 单独配置更加方便易用。更多信息请参见 [使用全局 CPU 资源的前后台隔离](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000859614)。 |
| 新增响应时间统计直方图 | 增加响应时间直方图功能，可基于 `[G]V$OB_QUERY_RESPONSE_TIME_HISTOGRAM` 系统视图计算和监控不同类型 SQL 的 P90/P95 之类的响应时间统计。更多信息请参见 [GV$OB_QUERY_RESPONSE_TIME_HISTOGRAM](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000833388)、[V$OB_QUERY_RESPONSE_TIME_HISTOGRAM](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000833387)。 |
| 分区均衡策略优化 | 优化分区均衡策略，支持在创建分区表时连续分区打散。当用户表存在 longtext/lob 列或局部索引时，分区磁盘均衡也会计算关联表，使磁盘使用更加均衡。更多信息请参见 [租户内均衡](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000801146)。 |
| 同城双机房类最大可用模式 | 提供日志流副本的成员列表修改能力，支持在 OCP 或 ob_admin 进行集群恢复。 |
| OBCDC 启动加速 | 优化 OBCDC 启动性能，协助提升下游 Binlog 工具的同步性能。 |
| JSON 可嵌套层数扩展 | 提供 `json_document_max_depth` 配置项，允许用户根据需求调整嵌套深度。对于超过 100 的 JSON 嵌套层数需求，用户可适当调大该配置。更多信息请参见 [json_document_max_depth](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000833393)。 |
| 基于 I/O 负载的自适应仲裁升降级 | 实现基于 I/O 负载的日志盘故障探测算法，可以更有效地探测到云盘故障并执行仲裁降级，避免云盘故障持续影响业务请求。 |
| 支持 HBase PageFilter 功能 | OB-HBase 模型下, 支持使用 HBase 中的 PageFilter 对 Row 进行限制, 返回指定数量的 Row。 |
| 备份性能优化 | 优化备份过程中连续性校验操作带来的性能开销，支持通过 `ha_low_thread_score` 控制备份使用的线程数，从而有效提高备份性能。更多信息请参见 [ha_low_thread_score](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000220387)。|
| 优化器版本调整默认值为 "4.2.1.7"（optimizer_features_enable） | V4.2.1 BP7 开始，新建的集群可以使用新版优化器能力，但从 V4.2.1 BP6 及以下版本升级到 V4.2.1 BP7 依然会保留之前的系统参数配置值。V4.2.1 BP6 及以下版本，默认值都为空，表示使用 V4.2.1.0 的优化器能力。|
| 禁用 DBMS_JOB 系统包 | V4.2.1 BP7 开始，新建集群时会禁用该功能。如有需要，请替换为 `DBMS_SCHEDULER`。老版本升级上来的集群依然保持开启状态，未来可能会被废弃。 |
| 新增 `choose_migration_source_policy` 配置项 | 新增租户级配置项，用于控制迁移源端的选择策略。更多信息请参见 [choose_migration_source_policy](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000833394)。 |
| 新增 `json_document_max_depth` 配置项 | 新增租户级配置项，用于设置 JSON 文档中允许的最大嵌套层数，默认为 100，可修改嵌套层数上限至 1024。更多信息请参见 [json_document_max_depth](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000833393)。 |

## V4.2.1 BP5（2024-04-19）

| 功能 | 描述|
|------|------|

| Buffer 表自适应合并优化 | 继续优化 Buffer 表自适应合并特性，提供 5 种档位的合并策略，允许用户根据业务场景为每张表设置不同的 `table_mode`，来应对 Buffer 表引起的读放大现象，从而提高系统长期运行下的 QPS 等性能指标。更多信息请参见 [自适应合并](700.reference/200.system-management/500.manage-data-storage/200.merge-management/320.adaptive-compavtion.md)。 |
| Processlist 统计时间优化 | 视图 `information_schema.PROCESSLIST`、`GV$OB_PROCESSLIST` 中增大 `TIME` 和 `TOTAL_TIME` 统计精度，并新增 `TOTAL_CPU_TIME` 表示请求 CPU 使用时间。 更多信息请参见 [information_schema.PROCESSLIST（MySQL 模式）](700.reference/700.system-views/400.system-view-of-mysql-mode/200.dictionary-view-of-mysql-mode/1500.information_schema-processlist-of-mysql-mode.md)、[GV$OB_PROCESSLIST（MySQL 模式）](700.reference/700.system-views/400.system-view-of-mysql-mode/300.performance-view-of-mysql-mode/700.gv-ob_processlist-of-mysql-mode.md) 和 [GV$OB_PROCESSLIST（Oracle 模式）](700.reference/700.system-views/500.system-view-of-oracle-mode/300.performance-view-of-oracle-mode/700.gv-ob_processlist-of-oracle-mode.md)。 |

| OUTROW 存储的 LOB 读写性能优化 | 支持 OUTROW LOB 进入微块缓存，减少 I/O，提升 OUTROW LOB 读写性能。更多信息请参见 [lob_enable_block_cache_threshold](700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/27200.lob_enable_block_cache_threshold.md)。 |
