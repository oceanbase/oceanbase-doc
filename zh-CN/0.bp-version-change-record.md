# V4.2.1 文档更新记录

## V4.2.1 BP5（2024-04-19）

| 功能 | 描述|
|------|------|
| 统计信息优化 | 实现新的统计信息收集框架，基于系统资源拆分了统计信息收集过程，优化了 TopK 直方图的收集流程，默认以增量方式收集统计信息，同时优化了历史统计信息的管理方式。更多信息请参见 [统计信息管理概述](700.reference/1000.performance-tuning-guide/500.sql-optimization/400.sql-optimization/400.optimizer-statistics/300.statistics-management/100.statistics-management-overview.md)。 |
| DBMS_SCHEDULER 路由优化 | 支持通过 `DBMS_SCHEDULER.SET_ATTRIBUTE` 设置 Job 路由策略。通过配置 Job 路由至 Leader 节点，降低 RPC 开销，提升执行性能。更多信息请参见 [SET_ATTRIBUTE](700.reference/500.sql-reference/300.pl-reference/300.pl-oracle/1400.pl-system-package-oracle/14200.dbms-scheduler-oracle/1100.set-attribute-oracle.md)。|
| 支持 DBMS_SCHEDULER.STOP_JOB | 新增 `DBMS_SCHEDULER.STOP_JOB` 子程序，用于终止正在运行的 Job，便于出现异常时进行 Job 管理。更多信息请参见 [STOP_JOB](700.reference/500.sql-reference/300.pl-reference/300.pl-oracle/1400.pl-system-package-oracle/14200.dbms-scheduler-oracle/1300.stop-job-oracle.md)。 |
| Buffer 表自适应合并优化 | 继续优化 Buffer 表自适应合并特性，提供 5 种档位的合并策略，允许用户根据业务场景为每张表设置不同的 `table_mode`，来应对 Buffer 表引起的读放大现象，从而提高系统长期运行下的 QPS 等性能指标。更多信息请参见 [自适应合并](700.reference/200.system-management/500.manage-data-storage/200.merge-management/320.adaptive-compavtion.md)。 |
| Processlist 统计时间优化 | 视图 `information_schema.PROCESSLIST`、`GV$OB_PROCESSLIST` 中增大 `TIME` 和 `TOTAL_TIME` 统计精度，并新增 `TOTAL_CPU_TIME` 表示请求 CPU 使用时间。 更多信息请参见 [information_schema.PROCESSLIST（MySQL 模式）](700.reference/700.system-views/400.system-view-of-mysql-mode/200.dictionary-view-of-mysql-mode/1500.information_schema-processlist-of-mysql-mode.md)、[GV$OB_PROCESSLIST（MySQL 模式）](700.reference/700.system-views/400.system-view-of-mysql-mode/300.performance-view-of-mysql-mode/700.gv-ob_processlist-of-mysql-mode.md) 和 [GV$OB_PROCESSLIST（Oracle 模式）](700.reference/700.system-views/500.system-view-of-oracle-mode/300.performance-view-of-oracle-mode/700.gv-ob_processlist-of-oracle-mode.md)。 |
| 支持 Clog 存储压缩| 新增支持 Clog 日志存储压缩功能，通过将事务提交的日志进行压缩，间接提高日志盘吞吐能力，提升日志盘可容纳的事务日志总量。更多信息请参见 [日志的压缩](700.reference/100.oceanbase-database-concepts/800.transaction-management/100.transaction/600.redo-logs.md)。 |
| OUTROW 存储的 LOB 读写性能优化 | 支持 OUTROW LOB 进入微块缓存，减少 I/O，提升 OUTROW LOB 读写性能。更多信息请参见 [lob_enable_block_cache_threshold](700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/27200.lob_enable_block_cache_threshold.md)。 |
| NETWORK_WAIT_TIME 统计项优化 | SQL AUDIT 中新增 `NETWORK_WAIT_TIME` 统计项，用于展示 Network 类别的等待事件耗时，如同步 RPC、DAS 异步 RPC 锁等。在排查远程执行的慢 SQL 问题时，可以使用该统计项确认网络开销，辅助诊断。更多信息请参见 [GV$OB_SQL_AUDIT](700.reference/1000.performance-tuning-guide/500.sql-optimization/400.sql-optimization/300.monitor-sql-execution-performance/100.gv-ob-sql-audit.md)。 |
| 默认打开 Batch NLJ 优化能力 | V4.2.1 BP5 版本开始，新建的租户会默认保持优化开关（`_NLJ_BATCHING_ENABLED`）开启。升级前已存在的老租户维持原来配置，需要手动开启。更多信息请参见 [联接算法](700.reference/1000.performance-tuning-guide/500.sql-optimization/400.sql-optimization/600.query-optimization/200.join-algorithm/200.join-algorithm.md)。 |
| 去除 Slog 目录与数据盘的绑定关系 | 新版本支持配置 Slog 使用的磁盘，可以和 Clog 共用一块 SSD，不再要求必须与数据盘绑定，避免数据盘满或性能不佳影响 Slog 写入。更多信息请参见 [使用命令行部署单机集中式 OceanBase 数据库](400.deploy/300.deploy-oceanbase-enterprise-edition/400.deploy-through-the-command-line/200.deploy-the-oceanbase-cluster-command-line/100.stand-alone-deployment-of-oceanbase-database.md)。 |
| Oracle 模式下参数设置 | V4.2.1 BP5 之前的版本，通过 `ALTER SYSTEM SET` 命令设置取值为 True/False 的参数时，必须对 True/False 添加单引号，否则会报错。V4.2.1 BP5 及之后版本，无论是否对 True/False 添加引号，都不会报错。更多信息请参见 [PARAMETER](700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/2600.PARAMETER.md)。 |
| 新增 `log_storage_compress_all` 配置项 | 新增租户级配置项，用于控制是否开启 Clog 存储压缩功能。默认为 False，表示不开启 Clog 存储压缩。更多信息请参见 [log_storage_compress_all](700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/27000.log_storage_compress_all.md)。 |
| 新增 `log_storage_compress_func` 配置项 | 新增租户级配置项，用于控制 Clog 存储压缩的压缩算法，可设置为 lz4_1.0，zstd_1.0 或 zstd_1.3.8。默认为 lz4_1.0。更多信息请参见 [log_storage_compress_func](700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/27100.log_storage_compress_func.md)。 |
| 新增 [G]V$OB_SESSION 视图 | 各租户新增该视图，用于记录 Session 信息。更多信息请参见 [V$OB_SESSION](700.reference/700.system-views/300.system-view-of-sys-tenant/300.performance-view-of-sys-tenant/16500.v-ob_session-of-sys-tenant.md) 和 [GV$OB_SESSION](700.reference/700.system-views/300.system-view-of-sys-tenant/300.performance-view-of-sys-tenant/16400.gv-ob_session-of-sys-tenant.md)。 |
| 新增 `information_schema.events` 视图 | 用于兼容 MySQL 模式下表结构。更多信息请参见 [information_schema.events](700.reference/700.system-views/400.system-view-of-mysql-mode/200.dictionary-view-of-mysql-mode/26100.information_schema.events-of-mysql-mode.md)。 |
| MySQL 模式下 SET 语句优化 | 支持一条 `SET` 语句中同时包含 names 和其他普通变量。更多信息请参见 [SET NAMES](700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/8400.set-names-of-mysql-mode.md)。 |

## V4.2.1 BP4（2024-03-01）

| 功能 | 描述|
|------|------|
| Oracle 模式下支持快速删列 | 将删列操作从真正删除变更为标记删除，极大提升了删列性能。删列后，对应列以隐藏列方式存储。更多信息请参见 [删除列（Oracle 模式）](700.reference/500.sql-reference/100.sql-syntax/300.common-tenant-of-oracle-mode/1000.ddl-function-of-oracle-mode/400.column-operations-of-oracle-mode.md)和 [ALTER TABLE（Oracle 模式）](700.reference/500.sql-reference/100.sql-syntax/300.common-tenant-of-oracle-mode/900.sql-statement-of-oracle-mode/100.ddl-of-oracle-mode/1000.alter-table-of-oracle-mode.md)。 |
| 新增 `ALTER SYSTEM CANCEL` 语法 | <ul><li>`CANCEL TRANSFER PARTITION` 语句用于取消当前正在执行的 Transfer Partition（迁移分区）任务。更多信息请参见 [CANCEL TRANSFER PARTITION](700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/1250.cancel-transfer-partition.md)。</li><li>`CANCEL BALANCE JOB` 语句用于取消正在进行的 BalanceJob。更多信息请参见 [CANCEL BALANCE JOB](700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/850.cancel-balance-job.md)。</li></ul>|
| Multi Min/Max 改写优化 | 对于 SQL 中有多个 Min/Max 存在的场景，将多个 Min/Max 改写成多个子查询，每个子查询都利用索引直接获取到最大值或最小值，以此来避免全表扫描和排序，优化查询性能。更多信息请参见 [MIN/MAX 改写](700.reference/1000.performance-tuning-guide/500.sql-optimization/400.sql-optimization/500.query-rewrite/200.rule-based-query-rewriting.md)。 |
| DBLink 支持短链接 | 通过 DBLink 访问远端数据库时，目前采用一个 Session 内复用连接（即长连接）的方式。新版本增加不复用连接（即短连接）选项，用于网络环境出现非预期问题时，降低影响。更多信息请参见 [通过 DBLink 访问远端数据库中的数据（MySQL 模式）](700.reference/300.database-object-management/100.manage-object-of-mysql-mode/900.manage-dblink-of-mysql-mode/300.access-a-remote-database-by-ablink-of-mysql-mode.md)和 [通过 DBLink 访问远端数据库中的数据（Oracle 模式）](700.reference/300.database-object-management/200.manage-object-of-oracle-mode/1000.manage-dblink-of-oracle-mode/300.access-a-remote-database-by-a-dblink-of-oracle-mode.md)。 |
| 修改 `max_syslog_file_count` 配置项语义 | 在之前版本，`max_syslog_file_count` 配置项对所有类型的系统日志分别生效，即：如果该配置项设置为 1000，表示不同类型的系统日志（如 `observer.log`、`trace.log`、`rootservice.log`...） 各允许保留 1000个。该版本开始，`max_syslog_file_count` 统一控制所有类型的系统日志数量，日志个数相互挤占，按照先进先出策略淘汰。更多信息请参见 [max_syslog_file_count](700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/13400.max_syslog_file_count.md)。 |
| 表级恢复命令调整 | 将 `ATLER SYSTEM RECOVER TABLE tablename TO TENANT tenantname` 语法中 TENANT 关键字修改为可选，即同时支持 `ATLER SYSTEM RECOVER TABLE tablename TO tenantname` 语法。更多信息请参见 [RECOVER TABLE](700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/3400.recover-table.md)。 |
| 修改 `memstore_limit_percentage` 配置项默认值| 默认值从 50 修改为 0，表示默认采用自适应策略。8G 及以下规格租户（真实 memory），配置为 40%；8G 以上规格，配置为 50%。更多信息请参见 [memstore_limit_percentage](700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/13900.memstore_limit_percentage.md)。 |
