# 索引类型选择

OceanBase 提供了多种向量索引算法，用户可以依据使用场景的不同选择合适的索引。

## 索引分类

索引分为两大类：

* 基于图的 HNSW 索引及其量化索引 HNSW_SQ 和 HNSW_BQ。
* 基于磁盘的 IVF 索引及其量化索引 IVF_PQ。

图索需要常驻内存，但是性能会高于磁盘索引，磁盘索引在缓存足够的情况下也可提供较好的性能，极端情况下可以完全不依赖常驻内存。在 OceanBase 中，可以通过 SQL 进行内存用量的估算，具体请参见[向量索引内存管理](../200.ob-vector-index-memory-management.md)。

## HNSW 系列用于高性能场景

内存图索引的性能会明显高于磁盘索引，但由于需要常驻内存，因此内存成本高，且需要数据总量动态平衡，如果数据明显增多则需要扩容：

* 内存充裕：通常是百万级数据量，要求最高召回率和高性能，使用 HNSW 索引。
* 内存充足：通常是百万～千万数据量，要求高召回和高性能，使用 HNSW_SQ 索引，占用内存约为 HNSW 索引的 1/4 ～ 1/3。
* 内存紧张：通常是千万～亿数据量，要求高召回和较高性能，使用 HNSW_BQ 索引，占用内存约为 HNSW 索引的 1/30。

这几种索引中 HNSW_SQ 的性能最高，HNSW 的召回率最高，但在标准数据集下都可以通过调节参数获得 99% 的召回率。召回率是稠密索引进行最近邻检索的准确率，例如在查询 10 个最近邻时，若能稳定返回 9 个正确结果，则召回率为 90%。

<main id="notice" type='notice'>
    <h4>注意</h4>
    <p>HNSW_BQ 是高压缩率的量化算法，在低维向量下的召回率上限可能较低。为避免性能损失，建议 HNSW_BQ 使用在 512 维及以上的向量上。</p>
</main>

### 参数建议

创建索引时，需要配置一些索引参数，这里给出不同场景下一些重要参数的建议配置。

<main id="notice" type='notice'>
    <h4>注意</h4>
    <p>对于数据量预计会增长的场景，建议根据最终数据量进行参数设置。</p>
</main>

| 场景 | 索引类型 | 参数建议 |
|---|---|---|
| 最高召回<br>（内存占用最多） | HNSW | 百万数据量：m = 16，ef_construct = 200，ef_search = 100 |
| 最高性能<br>（内存占用较少） | HNSW_SQ | 百万数据量：m = 16，ef_construct = 200，ef_search = 100<br>千万数据量：m = 32，ef_construct = 400，ef_search = 350 |
| 最佳性价比<br>（内存占用少，性能好） | HNSW_BQ | 百万数据量：m = 16，ef_construct = 200，ef_search = 100<br>千万数据量：m = 32，ef_construct = 400，ef_search = 1000，refine_k=10<br>亿级数据量：使用分区表，m = 32，ef_construct = 400，ef_search = 1000，refine_k=10 |

## IVF 系列用于高容量场景

磁盘索引用于高容量场景，可以做到完全不依赖常驻内存，对**数据量非常大**或者**只增不删**的场景，如果性能可以满足需要，就建议使用磁盘索引：

* IVF 索引：构建会相对更快，但构建过程中的内存占用也相对更高，相比 IVF_PQ 索引查询会慢一些，召回会更高。
* IVF_PQ 索引：构建会慢一些，构建过程中的内存占用也相对低，但比 IVF 的查询性能更高，召回率略低。

<main id="notice" type='notice'>
    <h4>注意</h4>
    <p>IVF_PQ 是高压缩率的量化算法，在低维向量下的召回率上限可能较低。为避免性能损失，建议 IVF_PQ 使用在 128 维及以上的向量上。</p>
</main>

### 参数建议

| 场景 | 索引类型 | 参数建议 |
|---|---|---|
| 低成本<br>（内存占用极少） | IVF_PQ | 百万数据量：nlist=1000, m=向量维度/2，nprobes = 20<br>千万数据量：nlist=3000, m=向量维度 / 2，nprobes = 20<br>亿级数据量：使用分区表，nlist=3000, m=向量维度 / 2，nprobes = 20 |

<main id="notice" type='notice'>
    <h4>注意</h4>
    <p>对于数据量预计会增长的场景，建议根据最终数据量进行参数设置。</p>
</main>
