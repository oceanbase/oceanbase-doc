# 向量数据库 VectorDBBench 测试

VectorDBBench 是一款为主流向量数据库和云服务提供基准测试结果的工具，此文档通过 VectorDBBench 测试 OceanBase 向量数据库的性能和成本效益比较。VectorDBBench 的设计注重易用性，可以轻松复现结果或测试新系统。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>此测试目前仅支持 HNSW 索引检索。</p>
</main>

## 准备工作

* 部署 V4.3.5 及以上版本 OceanBase 集群。
* 安装 Python 3.11 及以上版本。示例使用 Conda 安装。
  ```bash
  # 下载安装 Conda
  mkdir -p ~/miniconda3
  wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh -O ~/miniconda3/miniconda.sh
  bash ~/miniconda3/miniconda.sh -b -u -p ~/miniconda3
  rm ~/miniconda3/miniconda.sh

  # 重新打开终端，初始化 Conda
  source ~/miniconda3/bin/activate
  conda init --all

  # 新建和初始化 VectorDBBench 所需的 Python 环境
  conda create -n vdb python=3.11
  conda activate vdb
  ```
* 调优 HNSW 向量索引检索相关内存和查询参数：
  ```sql
  -- ob_vector_memory_limit_percentage 设置为 30%
  ALTER SYSTEM SET ob_vector_memory_limit_percentage = 30;
  -- ob_query_timeout 设置为 30 分钟
  SET GLOBAL ob_query_timeout = 3216672000000000;
  -- max_allowed_packet 设置为 1GB
  SET GLOBAL max_allowed_packet=1073741824;
  ```
  其中 `ob_vector_memory_limit_percentage = 30` 只是示意值，具体请根据租户内存和业务量调整，计算逻辑请参见 [ob_vector_memory_limit_percentage](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/6150.ob_vector_memory_limit_percentage.md)。

## 测试方法

### 克隆 VectorDBBench 代码

克隆测试工具 VectorDBBench 代码到本地。

```bash
git clone -b v0.1.0 https://github.com/wyfanxiao/VectorDBBench.git
```

### 安装依赖

进入 VectorDBBench 目录安装依赖。

```bash
cd VectorDBBench
pip install . -i
```

### 运行测试

运行 VectorDBBench。

```bash
# $host，$port，$user 需替换为实际的 OceanBase 数据库连接信息。
vectordbbench oceanbasehnsw --host $host --port $port --user $user --database test --m 16 --ef-construction 200 --ef-search 100 --case-type Performance1536D500K
```

`vectordbbench oceanbasehnsw` 更多参数信息可以通过以下命令查看：

```bash
vectordbbench oceanbasehnsw --help
```

这里列出两个常用选项：

* --num-concurrency，用于调整并发度。 VectorDBBench 会按指定的并发去执行向量查询，并选择最大的 QPS（Queries Per Second，每秒查询数）作为最终结果。
* --skip-drop-old、--skip-load ，表示跳过删除旧数据和导数的步骤。在命令行加上这两个选项后，命令仅执行向量查询操作，而不会删除旧数据重新导数。

## 常见问题

### 第一次执行测试很慢正常吗？

第一次执行测试需要在 AWS S3 存储下载所需数据集，时间可能会相对较久，为正常现象。

### 可以自定义修改测试代码吗？

可以。如果你自定义修改了测试代码，需要重新执行 `pip install . -i` 安装后再运行测试。
