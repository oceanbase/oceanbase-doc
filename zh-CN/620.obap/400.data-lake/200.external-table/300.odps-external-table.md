# ODPS 外部表

MaxCompute（ODPS）提供了两种数据访问接口：

- **Storage API**：数据服务接口，提供高效、低延迟、安全的数据读取能力。  
- **Tunnel API**：数据上传 / 下载接口，主要用于批量操作表数据（例如全表导入导出）。

OceanBase 数据库自 V4.4.0 及以上版本（MySQL 模式） 起，通过适配 ODPS API，支持通过外部表访问 MaxCompute 表。

通过创建 ODPS 外部表，实现对阿里云 MaxCompute（原 ODPS）表的 透明读写，无需数据迁移即可完成跨系统联合分析、实时报表与数据回流。

在创建 ODPS 外部表时，OceanBase 提供了针对 Storage API 和 Tunnel API 的参数配置选项，具体使用方式详见 `CREATE EXTERNAL TABLE`。两种 API 的选择建议如下表所示：

| 维度 | Storage API | Tunnel API | 适用场景 |
|------|-------------|------------|----------|
| 特点 | 支持细粒度数据访问（例如分区过滤、谓词下推）。 | 专注全表数据的高效导入 / 导出，无条件过滤能力。 | HTAP 混合负载、分区表条件查询、与计算引擎（如 Spark）深度集成。 |
| 分片策略 | 自动分片：按字节或行数动态拆分任务，提升并行效率。 | 手动分片：需开发者自行计算分区大小或行数，配置较为复杂。性能相较于 Storage API 较低，且对 ODPS 的资源配置无特殊要求，可兼容所有 ODPS 配置规格。 | <ul><li> Storage API：适用于多分区表场景，支持两种动态分片策略：<br>+ 按字节（byte）：当数据记录大小差异较大时，通过按字节分片确保各分片数据量均衡，避免计算倾斜。<br>+ 按行数（row）：当记录大小较一致时，通过固定行数分片提升并行处理效率。</ul></li><ul><li>Tunnel API：适合 ODPS 未开通相关 Storage API 服务或者兼容性场景。</ul></li> |
| 性能优化 | 低资源消耗：谓词下推减少传输数据量，计算下推到数据库侧，查询速度更快。 | 高资源消耗：全量传输可能占用大量带宽与存储。 | 需减少传输数据量、提升 HTAP 效率时选 Storage API；简单 ETL 或全量备份选 Tunnel API。 |
| 数据过滤能力 | 支持：通过 SQL 条件（例如 WHERE）过滤数据，仅传输所需部分。 | 不支持：需全量传输后本地过滤。 | 需按条件筛选数据（如分析特定用户行为）时选 Storage API。 |

## 功能概览

| 能力 | 说明 |
|------|------|
| 只读查询 | `SELECT * FROM odps_external_table` |
| 分区支持 | 支持非分区表与分区表（含动态分区识别） |
| 列映射 | 自动或显式绑定 MaxCompute 列 |
| 分区自动刷新 | 支持 `IMMEDIATE` / `INTERVAL` / `OFF` 三种同步策略 |
| 限制 | <ul><li>仅支持 MySQL 模式。</ul></li><ul><li>不支持复杂类型（如 ARRAY<MAP>）。</ul></li><ul><li>写入时要求列数与顺序严格一致。<ul><li> |

## 创建 ODPS 外部表

### 非分区表

**基础语法（自动列映射）**

```sql
-- step1: MaxCompute 上有一个表 t1
-- CREATE TABLE IF NOT EXISTS odps_project.t1 (c1 INT, c2 INT);

-- step2: OB 创建外表 t1
CREATE EXTERNAL TABLE t1 (c1 INT, c2 INT)
PROPERTIES = (
    TYPE = 'ODPS',
    ACCESSID = '*****',
    ACCESSKEY = '*****',
    ENDPOINT = 'http://service.cn-hangzhou.maxcompute.aliyun.com/api',
    PROJECT_NAME = 'odps_project',
    SCHEMA_NAME = '',
    TABLE_NAME = 't1',
    QUOTA_NAME = '',
    COMPRESSION_CODE = ''
    API_MODE = {"tunnel_api"},
);
```

<main id="notice" type='notice'>
  <h4>说明</h4>
  <p>未指定生成列时，OceanBase 按定义顺序自动映射为 <code>external$tablecol1</code>， <code>external$tablecol2...</code>。</p>
</main>

**显式列映射（推荐）**

```sql
-- step1: MaxCompute 上有一个表 t1
-- CREATE TABLE IF NOT EXISTS odps_project.t1 (c1 INT, c2 INT);

-- step2: OB 创建外表 t1
CREATE EXTERNAL TABLE t1 (
    c1 INT AS (external$tablecol1),
    c2 INT AS (external$tablecol2)
)
PROPERTIES = (
    TYPE = 'ODPS',
    ACCESSID = '*****',
    ACCESSKEY = '*****',
    ENDPOINT = 'http://service.cn-hangzhou.maxcompute.aliyun.com/api',
    PROJECT_NAME = 'odps_project',
    SCHEMA_NAME = '',
    TABLE_NAME = 't1',
    QUOTA_NAME = '',
    COMPRESSION_CODE = 'lz4'
    API_MODE = {"tunnel_api"},
);
```

<main id="notice" type='notice'>
  <h4>说明</h4>
  <p><ul><li>普通列 <code>AS (external$tablecolx)</code> 用于指定需要映射到 ODPS 的 t1 表的第 x 列（该列是普通列，不能是分区列），起始序号是 1。</ul></li><ul><li>如果像示例 1 不指定生成列，则默认生成列，序号按照列定义的顺序从 1 开始递增。</ul></li></p>
</main>

### 分区表

**关键规则：**  

- 分区列必须使用 `metadata$partition_list_colX` 显式声明。  
- `PARTITION BY` 子句必须与 MaxCompute 表分区结构一致。

```sql
-- step1: MaxCompute 上有一个分区表 t2，c1 和 c2 是普通列，c3 和 c4 是分区列
-- CREATE TABLE IF NOT EXISTS odps_project.t2 (c1 INT, c2 INT) PARTITIONED BY (c3 VARCHAR(20), c4 VARCHAR(20));

-- step2: OB 创建分区外表 t2
CREATE EXTERNAL TABLE t2 (
    c1 INT,
    c2 INT,
    c3 VARCHAR(20) AS (metadata$partition_list_col1),
    c4 VARCHAR(20) AS (metadata$partition_list_col2)
)
PROPERTIES = (
    TYPE = 'ODPS',
    ACCESSID = '*****',
    ACCESSKEY = '*****',
    ENDPOINT = 'http://service.cn-hangzhou.maxcompute.aliyun.com/api',
    PROJECT_NAME = 'odps_project',
    SCHEMA_NAME = '',
    TABLE_NAME = 't2',
    QUOTA_NAME = '',
    COMPRESSION_CODE = ''
    API_MODE = {"tunnel_api"},
)
PARTITION BY (c3, c4);
```

<main id="notice" type='notice'>
  <h4>说明</h4>
  <p><ul><li>分区列 AS (metadata$partition_list_colx) 用于指定需要映射到 ODPS 的 t2 表的第 x 个分区列，起始序号是 1。</ul></li><ul><li>分区列 <code>AS (metadata$partition_list_colx)</code> 不可省略，否则会被当作普通列处理，出现非预期错误。</ul></li><ul><li>MaxCompute 表的分区列和 OceanBase 外表的分区列需要一一对应，个数一致。</ul></li></p>
</main>

**错误示例：**

若省略 `AS (metadata$partition_list_colX)`，分区列将被当作普通列处理，导致查询失败。

```sql
-- step1: MaxCompute 上有一个分区表 t2，c1 和 c2 是普通列，c3 和 c4 是分区列
-- CREATE TABLE IF NOT EXISTS odps_project.t2 (c1 INT, c2 INT) PARTITIONED BY (c3 VARCHAR(20), c4 VARCHAR(20));

-- step2: 错误写法：分区列未使用 metadata$partition_list_colX
CREATE EXTERNAL TABLE t2 (
    c1 INT,
    c2 INT,
    c3 VARCHAR(20),   -- ⚠️ 缺少 AS (metadata$partition_list_col1)
    c4 VARCHAR(20)    -- ⚠️ 缺少 AS (metadata$partition_list_col2)
)
PROPERTIES = (
    TYPE = 'ODPS',
    ACCESSID = '*****',
    ACCESSKEY = '*****',
    ENDPOINT = 'http://service.cn-hangzhou.maxcompute.aliyun.com/api',
    PROJECT_NAME = 'odps_project',
    SCHEMA_NAME = '',
    TABLE_NAME = 't2',
    QUOTA_NAME = '',
    COMPRESSION_CODE = ''
    API_MODE = {"tunnel_api"},
)
PARTITION BY (c3, c4);    -- 虽然声明了分区，但列无分区元数据映射
```

由于 c3 和 c4 未绑定到 MaxCompute 的实际分区值，OceanBase 无法获取分区信息。因此，**分区列必须显式使用 metadata$partition_list_colX 进行映射**。

<main id="notice" type='notice'>
  <h4>说明</h4>
  <p>普通列的生成列可以显式指定，也可以不显式指定，和非分区外表一致。</p>
</main>

## 关键参数说明（PROPERTIES）

| 参数 | 必填 | 说明 |
|------|------|------|
| TYPE | 是 | 固定为 `'ODPS'` |
| ACCESSID / ACCESSKEY | 是 | RAM 用户 AccessKey（建议最小权限） |
| ENDPOINT | 是 | MaxCompute 服务地址（含地域） |
| PROJECT_NAME | 是 | MaxCompute 项目名 |
| TABLE_NAME | 是 | 表名 |
| SCHEMA_NAME | 否 | 若表在 Schema 下需指定 |
| ACCESSTYPE | 否 | 账号类型：`aliyun`（默认）/ `sts` / `app` |
| STSTOKEN | 条件 | 仅 `ACCESSTYPE = 'sts'` 时必填 |
| QUOTA_NAME | 否 | 指定计算资源配额 |
| COMPRESSION_CODE | 否 | 压缩格式：`zlib` / `zstd` / `lz4` / `odps_lz4` |

## 查询 MaxCompute 数据

通过外表访问 MaxCompute 数据与查询普通表语法相同。

```sql
-- step1: MaxCompute 上有一个表 t1
-- CREATE TABLE IF NOT EXISTS odps_project.t1 (c1 INT, c2 INT);

-- step2: OB 创建外表 t1
CREATE EXTERNAL TABLE t1 (c1 INT, c2 INT)
PROPERTIES = (
    TYPE = 'ODPS',
    ACCESSID = '*****',
    ACCESSKEY = '*****',
    ENDPOINT = 'http://service.cn-hangzhou.maxcompute.aliyun.com/api',
    PROJECT_NAME = 'odps_project',
    SCHEMA_NAME = '',
    TABLE_NAME = 't1',
    QUOTA_NAME = '',
    COMPRESSION_CODE = ''
    API_MODE = {"tunnel_api"},
);

-- step3: 查看外表 t1 对应的 MaxCompute 表 t1 中的数据
SELECT * FROM t1;

-- 以并行度 N 加快读取速度
SELECT /*+ PARALLEL(N) */ * FROM t1;
```

## 导出数据到 MaxCompute

OceanBase 支持通过标准 SQL 将内部表数据写入 MaxCompute（ODPS）外部表，实现数据导出。

```sql
-- 覆盖写入（用于全量更新）
INSERT OVERWRITE external_table_name
SELECT column_list FROM source_table [WHERE ...];

-- 追加写入（用于增量导入）
INSERT INTO external_table_name
SELECT column_list FROM source_table [WHERE ...];
```

- `external_table_name`：已创建的 MaxCompute 外部表。
- `source_table`：OceanBase 内部表或其他可查询对象。

更多详细信息，参见 [MySQL 模式下的插入数据](../../../300.develop/100.application-development-of-mysql-mode/400.write-data-of-mysql-mode/100.insert-data-of-mysql-mode-in-develop.md) 和 [Oracle 模式下的插入数据](../../../300.develop/200.application-development-of-oracle-mode/400.write-data-of-oracle-mode/100.insert-data-of-oracle-mode-in-develop.md)。

### 非分区表导出

```sql
-- step1: MaxCompute 上有一个表 t1
-- CREATE TABLE IF NOT EXISTS odps_project.t1 (c1 INT, c2 INT);

-- step2: OceanBase 创建外表 t1
CREATE EXTERNAL TABLE t1 (c1 INT, c2 INT)
PROPERTIES = (
    TYPE = 'ODPS',
    ACCESSID = '*****',
    ACCESSKEY = '*****',
    ENDPOINT = 'http://service.cn-hangzhou.maxcompute.aliyun.com/api',
    PROJECT_NAME = 'odps_project',
    SCHEMA_NAME = '',
    TABLE_NAME = 't1',
    QUOTA_NAME = '',
    COMPRESSION_CODE = ''
    API_MODE = {"tunnel_api"},
);

-- step3: OceanBase 创建普通表 t1_
CREATE TABLE t1_ (c1 INT, c2 INT);

-- step4: 通过外表导出到 MaxCompute
INSERT INTO t1 SELECT * FROM t1_;

-- 以并行度 N 加快导出速度
INSERT /*+ PARALLEL(N) */ INTO t1 SELECT * FROM t1_;

-- 指定 OVERWRITE 会覆盖原有数据，假如 t1_ 表为空表，则 t1 也会被覆写为空
INSERT OVERWRITE t1 SELECT * FROM t1_;

-- 指定插入的列
INSERT INTO t1 (c1) SELECT c1 FROM t1_;  -- c2 列插入 NULL
```

### 分区表导出

```sql
-- step1: MaxCompute 上有一个分区表 t2，c1 和 c2 是普通列，c3 和 c4 是分区列
-- CREATE TABLE IF NOT EXISTS odps_project.t2 (c1 INT, c2 INT) PARTITIONED BY (c3 VARCHAR(20), c4 VARCHAR(20));

-- step2: OceanBase 创建分区外表 t2
CREATE EXTERNAL TABLE t2 (
    c1 INT AS (metadata$odpscol1),
    c2 INT AS (metadata$odpscol2),
    c3 VARCHAR(20) AS (metadata$partition_list_col1),
    c4 VARCHAR(20) AS (metadata$partition_list_col2)
)
PROPERTIES = (
    TYPE = 'ODPS',
    ACCESSID = '*****',
    ACCESSKEY = '*****',
    ENDPOINT = 'http://service.cn-hangzhou.maxcompute.aliyun.com/api',
    PROJECT_NAME = 'odps_project',
    SCHEMA_NAME = '',
    TABLE_NAME = 't2',
    QUOTA_NAME = '',
    COMPRESSION_CODE = ''
    API_MODE = {"tunnel_api"},
)
PARTITION BY (c3, c4);

-- step3: OceanBase 创建普通表 t2_
CREATE TABLE t2_ (c1 INT, c2 INT);

-- step4: 向指定的分区导出数据
-- 注意：V4.3.5 BP2 及更高版本支持自动创建 MaxCompute 表中不存在的分区，无需预先手动创建；而该版本之前的 OceanBase 不支持此功能，必须提前在 MaxCompute 表中显式创建目标分区。
INSERT INTO t2 PARTITION (c3 = 'abc', c4 = 'def') SELECT * FROM t2_;
INSERT OVERWRITE t2 PARTITION (c3 = 'abc', c4 = 'def') SELECT * FROM t2_;
```

## 分区信息同步策略

通过 `AUTO_REFRESH` 控制 MaxCompute 分区元数据的刷新方式：  
`AUTO_REFRESH = { IMMEDIATE | OFF | INTERVAL }`

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| `IMMEDIATE` | 在每次查询的时候自动刷新 | 分区频繁变化（如小时级） |
| `OFF` | 只能手动刷新，使用：`ALTER EXTERNAL TABLE <table_name> REFRESH;` | 静态分区表 |
| `INTERVAL` | 通过 `DBMS_EXTERNAL_TABLE.AUTO_REFRESH_EXTERNAL_TABLE(x)` 设置定时任务刷新，单位为秒 | 中等频率更新 |

**启用即时刷新示例**

```sql
CREATE EXTERNAL TABLE t2 (
    c1 INT AS (metadata$odpscol1),
    c2 INT AS (metadata$odpscol2),
    c3 VARCHAR(20) AS (metadata$partition_list_col1),
    c4 VARCHAR(20) AS (metadata$partition_list_col2)
)
AUTO_REFRESH = IMMEDIATE
PROPERTIES = (
    TYPE = 'ODPS',
    ACCESSID = '*****',
    ACCESSKEY = '*****',
    ENDPOINT = 'http://service.cn-hangzhou.maxcompute.aliyun.com/api',
    PROJECT_NAME = 'odps_project',
    SCHEMA_NAME = '',
    TABLE_NAME = 't2',
    QUOTA_NAME = '',
    COMPRESSION_CODE = ''
    API_MODE = {"tunnel_api"},
)
PARTITION BY (c3, c4);
```

**手动刷新命令（AUTO_REFRESH = OFF 时使用）**

```sql
ALTER EXTERNAL TABLE t2 REFRESH;
```

## 数据类型与时区

### 类型映射

- 详细映射参考：OceanBase 与 MaxCompute 数据类型对照表

### 时区处理

- MaxCompute 时间类型（如 `DATETIME`）无显式时区信息。  
- OceanBase 默认将其视为与自身时区一致。  
- 建议：确保 OceanBase 与 MaxCompute 使用相同时区（如 `Asia/Shanghai`）。
