# 外部表概述

通常，表数据通常存储在数据库自身的存储空间中。而 外部表（External Table） 是一种特殊表类型，其数据实际存储在数据库外部的存储系统中（如对象存储、HDFS、ODPS 等），数据库仅保存元数据和访问路径。用户可通过标准 SQL 查询外部表，实现对异构数据源的统一访问。

创建外部表时，需指定：

- **数据位置**（如 OSS 路径、HDFS、ODPS 等）  
- **数据格式**（如 CSV、Parquet、ORC）

创建成功后，外部表可像普通表一样参与 JOIN、聚合、排序 等操作，但存在以下关键差异：

| 特性 | 外部表 | 普通表 |
|------|--------|--------|
| 数据存储位置 | 外部存储系统（OSS/HDFS/ODPS 等） | OceanBase 分布式存储 |
| 读写能力 | 只读 | 读写全支持 |
| 约束与索引 | 不支持添加约束、不支持创建索引 | 完整支持 |
| 查询性能 | 受网络与外部系统影响，通常较慢 | 高性能本地访问 |

## 外部表类型详解

OceanBase 支持多种外部表类型。

### 文件外部表

适用于存储在对象存储（如 OSS、兼容S3协议的对象存储）、分布式文件系统（如 HDFS）或本地文件系统中的结构化/半结构化文件。

支持通过外表直接读取外部文件，支持通过 `select into outfile` 将数据导出成外部文件，也支持通过 `insert into ... from files()` 将外表文件数据导入到 OceanBase。

**支持格式**：

- **列式存储**：Parquet（推荐）、ORC（高压缩、高性能）（V4.3.5及以上支持）  
- **行式存储**：CSV

### ODPS 外部表

OceanBase在 V4.3.5 支持了通过外表读取及导入 MaxCompute 的功能，通过适配 ODPS API，支持通过外部表访问 MaxCompute 表；通过创建 ODPS 外部表，实现对阿里云 MaxCompute（原 ODPS）表的 透明读写，无需数据迁移即可完成跨系统联合分析、实时报表与数据回流。

更多详细信息，参见[ODPS 外部表](300.odps-external-table.md)。

### JDBC 插件外部表

OceanBase JDBC 外部表插件基于 Java 实现，可将远程 MySQL 表透明映射为本地外部表，支持高效查询与跨源联邦分析。  

- 适用版本：OceanBase V4.4.1 及以上（仅限 MySQL 模式）。  
- 核心价值：无需数据迁移，通过标准 SQL 直接查询远程 MySQL 数据库。

要使用 MySQL 外表插件，必须完成以下配置：

1. 已部署 OceanBase 集群，并创建了 MySQL 模式的用户租户。
2. 所有 OBServer 节点已安装 JDK 11 或更高版本，并正确配置 `JAVA_HOME`。  
3. 已下载并部署 MySQL 外表插件 JAR 包，并配置其路径。

详细安装与配置步骤，请参考文档 [MySQL 外表插件](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000003976811)。

## Catalog 外表与外部表的关系

OceanBase 提供两种外部数据访问模式：

| 模式 | 适用场景 | 元数据管理 | 典型用法 |
|------|----------|------------|----------|
| Catalog 模式<br>(ODPS Catalog、HMS Catalog) | 预定义数据源（ODPS/HMS） | 自动同步 | `SET CATALOG my_hms;`、`SELECT * FROM db1.sales;` |
| 文件/ODPS/JDBC 外部表 | 临时文件或自定义数据源 | 手动建表 | `CREATE EXTERNAL TABLE ... LOCATION ...;` |
