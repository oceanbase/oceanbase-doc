# 数据目录概述

OceanBase 自 V4.3.5 BP2 起支持 ODPS Catalog，并在 V4.4.1 版本中进一步引入 HMS Catalog（Hive Metastore Catalog）机制，实现对数据湖及离线数仓的无缝访问。通过该能力，用户可直接以标准 SQL 查询由 Hive Metastore（HMS）管理的 Hive 表、Iceberg 表，以及 MaxCompute（ODPS）中的离线表。

这些表通常以 Parquet、ORC 等高效列式格式 存储于 HDFS、OSS 或 S3 等分布式存储系统中，构成了企业核心数据湖的重要组成部分。

与简单的元数据对接不同，OceanBase 并非仅“能读”数据湖，而是作为高性能计算引擎，对湖上数据提供显著查询加速。这得益于其内置的多项 AP 优化能力：

- **谓词下推与列裁剪**：将 WHERE 条件和 SELECT 列信息下推至数据源（如 ODPS Storage API、HDFS 文件读取层）；  
- **并行执行与向量化计算**：对大表扫描任务自动并行化，并利用向量化引擎高效处理列存数据；  
- **外表数据缓存（可选）**：对高频访问的静态湖表，支持缓存数据文件，降低重复查询延迟。

借助这些能力，用户无需将数据湖、数据仓库中的原始数据迁移到数据库内部，即可在 OceanBase 内实现查询加速：

- OceanBase 内部的实时业务表（如订单、用户画像）。
- 数据湖中的历史日志、宽表或 Iceberg 表（如用户行为、IoT 时序数据），以及 ODPS 等云原生数仓中的离线表。

这使得 OceanBase 成为 **数据湖查询入口**，真正实现 “**一处查询，全域数据**” 的联邦分析体验，只需一条 SQL，就能同时访问数据库和数据湖中的数据，大大简化了跨源分析的流程，让数据湖的使用变得更简单、更高效。

## 部署与环境依赖

| 跨机房部署建议 | HDFS 存储依赖 |
|----------------|--------------------------------------------------------------------------------------------------------------------------------------------------|
| 若 HMS 与 OBServer 跨机房部署，网络延迟可能导致元数据获取耗时达秒级，显著增加查询延迟。建议将 HMS 与 OBServer 部署在同一低延迟网络内。   | 当底层存储为 HDFS 时，需提前在 OBServer 节点部署 Java 运行环境（JDK 8/11） 并启用 Java 支持（`enable_java = true`）。详见 [部署 OceanBase JAVA SDK 环境](../../../400.deploy/300.deploy-oceanbase-enterprise-edition/500.deploy-the-ob-java-sdk-environment.md)。 |

## Catalog 与外部表的关系

OceanBase 提供两种外部数据访问模式：

| 模式 | 适用场景 | 元数据管理 | 典型用法 |
|------|----------|------------|----------|
| Catalog 模式<br>（如 HMS Catalog、ODPS Catalog） | 预定义、结构化的数据源（如 Hive 数仓、ODPS 项目） | 自动同步元数据 | `SET CATALOG my_hms;`<br>`SELECT * FROM db1.sales;` |
| 显式外部表<br>（文件/JDBC/ODPS 外表） | 临时文件、自定义路径或非 Catalog 数据源 | 手动建表定义结构 | `CREATE EXTERNAL TABLE t1 (...) LOCATION = 'oss://...';` |

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p><ul><li>Catalog 是对底层数据（如 Parquet/ORC 文件、ODPS 表）的元数据抽象。</ul></li><ul><li>当前 HMS Catalog 仅支持对接 Hive Metastore，无法直接指向任意 HDFS 路径；若需访问未注册到 HMS 的文件，应使用 <code>CREATE EXTERNAL TABLE ... LOCATION</code> 方式。</ul></li></p>
</main>

## Catalog 类型

在 OceanBase 中，Catalog 是数据库对象的顶层命名空间，用于组织和隔离不同数据源的元数据。OceanBase 支持以下 Catalog 类型：

| Catalog 类型 | 数据源 | 支持表类型 | 典型场景 |
|--------------|--------|------------|----------|
| 内部 Catalog | OceanBase 本地存储 | OceanBase 表 | 内部核心业务数据 |
| ODPS Catalog | 阿里云 MaxCompute（ODPS） | ODPS 表 | 大数据离线分析 |
| HMS Catalog | Hive Metastore（HMS） | Hive 表、Iceberg 表 | Hadoop 生态集成 |

## 创建 Catalog

OceanBase 内置的内部 Catalog 用于管理数据库自身的元数据，无需手动创建。如需使用外部数据源，可通过 [`CREATE EXTERNAL CATALOG`](../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/2150.create-external-catalog-of-mysql-mode.md) 语句创建 ODPS Catalog 或 HMS Catalog。  

## 访问 Catalog

<main id="notice" type='notice'>
  <h4>说明</h4>
  <p>当前仅 OceanBase MySQL 模式支持数据目录能力。</p>
</main>

### 查看当前租户的 Catalog

您可以通过 `SHOW CATALOGS;` 语句查看当前租户下所有已创建的 Catalog。  

示例：  

```sql
SHOW CATALOGS;
```

### 查看 Catalog 中的数据

在 Catalog 中，可以和数据库内的表一样执行任意查询操作，也可以跨 Catalog 进行联合查询。

示例如下：  

```sql
SELECT * FROM internal.ap_db.ap_table, odps_catalog.odps_db.odps_table;
```

### 跨 Catalog 查询数据

OceanBase 支持在单条 SQL 中访问多个 Catalog（如 internal、hive_catalog、odps_catalog 等）中的数据，实现联邦查询。用户可通过以下 两种方式 引用非当前上下文中的表：

**核心原则：**  

- 若未切换会话上下文，必须使用 完整三段式标识符：`catalog_name.database_name.table_name;`
- 若已切换到目标 Catalog 和 Database，则可直接使用 简写表名。

#### 方式一：使用三段式标识符（无需切换上下文）

无论当前处于哪个 Catalog，均可通过 `catalog.db.table` 三段式标识符命名名直接访问任意 Catalog 中的表。

**示例 1：在默认 internal Catalog 中查询 HMS 表**  

```sql
-- 查看当前会话上下文
SELECT CURRENT_CATALOG();   -- 返回 'internal'
SELECT DATABASE();  -- 或者使用 SELECT SCHEMA(); 返回当前数据库，如 'ap_db'

-- 跨 Catalog 查询 Hive 表
SELECT * FROM hive_catalog.hive_db.hive_table;
```
在 HMS Catalog 中查询本地表也是一样的，可以采用 `catalog.db.table` 三段式标识符命名名直接访问。

**示例 2：联邦查询（混合来源）**  

```sql
-- 假设当前在 internal.ap_db
SELECT CURRENT_CATALOG();   -- 返回 'internal'
SELECT DATABASE();  -- 或者使用 SELECT SCHEMA(); 返回当前数据库，如 'ap_db'

-- 同时访问 HMS 表和本地表
SELECT h.*, o.*
FROM hive_catalog.hive_db.hive_table h
JOIN internal.ap_db.ap_table o ON h.id = o.id;
```

#### 方式二：切换会话上下文后使用简写表名

通过 `SET CATALOG` 和 `USE` 显式切换当前会话的 Catalog 与 Database，之后可直接使用表名（无需前缀）。

**示例：在 hive_catalog.hive_db 中进行联邦查询**  
```sql
-- 切换 Catalog 和 Database
SET CATALOG hive_catalog;
USE hive_db;

-- 验证当前上下文
SELECT CURRENT_CATALOG();   -- 返回 'hive_catalog'
SELECT DATABASE();  -- 返回 'hive_db'

-- 此时可直接引用 hive_db 下的表（如 hive_table）
-- 同时仍可通过三段式访问其他 Catalog（如 internal）
SELECT h.*, o.*
FROM hive_table h                      -- 简写：当前 Catalog + DB
JOIN internal.ap_db.ap_table o ON h.id = o.id;
```

<main id="notice" type='notice'>
  <h4>说明</h4>
  <p><ul><li>若未执行 <code>SET CATALOG</code> 和 <code>USE</code>，直接写 <code>SELECT * FROM hive_table;</code> 将产生报错，因为系统会在当前 Catalog（如 internal）中查找该表。</ul></li><ul><li>切换上下文仅影响后续语句，不影响连接或事务状态。</ul></li></p>
</main>



详细文档参见 [查看 CATALOG](../../../700.reference/300.database-object-management/100.manage-object-of-mysql-mode/1000.manage-catalog-of-mysql-mode/300.view-catalog-of-mysql-mode.md)  

### 切换 Catalog  

通过 `SET CATALOG catalog_name;` 切换 Catalog，或在查询中显式指定：  

```sql
SELECT * FROM odps_catalog.database_name.table_name;
```

详细 SQL 语法文档参见 [SET CATALOG](../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/8250.set-catalog-of-mysql-mode.md)

## HMS/ODPS Catalog 支持详情

### HMS Catalog 支持详情

**访问模式**  

- **只读访问**：所有 HMS Catalog 下的对象均为只读，禁止执行 `INSERT`、`UPDATE`、`DROP TABLE` 等 DML/DDL 操作。

**支持的表类型**

| 表类型 | 格式支持 | 说明 |
|--------|----------|------|
| Hive 表 | ORC、Parquet、TextFile、CSV | - 复杂类型当前仅支持 Parquet 格式的 ARRAY 类型。<br>更多详细信息，参见[数组元素类型概述](../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/100.basic-elements-of-mysql-mode/100.data-type-of-mysql-mode/1200.array-data-type-of-mysql-mode/100.array-data-type-overview-of-mysql-mode.md) |
| Iceberg 表 | V1 / V2 / V3（推荐 Parquet） | 支持 Schema Evolution（列增删）、Partition Transform（如 `bucket()`、`year()`）等高级特性 |

**Hive 版本兼容性**

| Hive 版本 | Iceberg 支持说明 |
|-----------|------------------|
| Hive 4.x | Hive 引擎原生支持 Iceberg 表，可通过 Hive 创建/更新表，OceanBase 可直接通过 HMS Catalog 访问。 |
| Hive 1.2.x / 2.3.x / 3.1.x | Hive 本身不支持 Iceberg。但若 Iceberg 表由 Spark/Flink 等引擎创建，并将元数据注册到 Hive Metastore，OceanBase 仍可读取。 |

关键原则：只要 Iceberg 表的元数据已正确注册在 HMS 中（无论由何种引擎写入），OceanBase 即可访问。

### ODPS Catalog 支持详情

- **支持操作**：`SELECT`、`JOIN`、`GROUP BY` 等分析型查询；  
- **不支持操作**：`INSERT`、`UPDATE`、`DROP TABLE` 等写入或 DDL 操作；  
- **优化能力**：自动下推分区裁剪与列裁剪条件，减少从 ODPS 传输的数据量。

## Catalog 权限管理

OceanBase Catalog 级别的权限控制，支持细粒度授权。用户需具备相应权限才能创建、切换或查询外部 Catalog（如 ODPS、HMS）。

- Catalog 权限分为两个层级：  

  * User Level（全局级）：作用于所有 Catalog（MySQL 模式中对应 *.*）  
  * Catalog Level（对象级）：仅作用于指定 Catalog

### MySQL 模式权限体系

| 权限 | 作用范围 | 用途 |
|------|----------|------|
| `CREATE CATALOG` | User Level | 允许执行 `CREATE` / `DROP EXTERNAL CATALOG` |
| `USE CATALOG` | User Level 或 Catalog Level | 允许 `SET CATALOG`、`SHOW CATALOGS`、`SELECT FROM catalog.db.table` |

### 语法

**授予全局权限**  

适用于需要操作任意 Catalog 的管理员：  

```sql
GRANT CREATE CATALOG ON *.* TO 'user1';
GRANT USE CATALOG ON *.* TO 'user1' WITH GRANT OPTION;

REVOKE CREATE CATALOG ON *.* FROM 'user1';
REVOKE USE CATALOG ON *.* FROM 'user1';
```

**授予特定 Catalog 权限**  

适用于普通用户仅访问指定 Catalog（推荐方式）：  

```sql
-- 授予对 catalog 'odps_prod' 的 USE 和 SELECT 权限
GRANT SELECT, USE CATALOG ON CATALOG odps_prod TO 'user1' WITH GRANT OPTION;

-- 撤销权限
REVOKE USE CATALOG ON CATALOG odps_prod FROM 'user1';
```

**重要补充说明：**  

1. **创建者自动拥有权限**  

用户成功执行 `CREATE EXTERNAL CATALOG ...` 后，自动获得对该 Catalog 的 `USE CATALOG` 和 `SELECT` 权限，无需额外授权。  

示例：  

```sql
-- user1 执行
CREATE EXTERNAL CATALOG odps_dev TYPE = 'ODPS' ...;

-- 此时 user1 可直接使用该 Catalog
SET CATALOG odps_dev;
SELECT * FROM project_db.table1 LIMIT 1;
```

2. **Catalog 权限 ≠ 数据访问权限**  

即使用户已获得 `USE CATALOG` 和 `SELECT` 权限，查询 Catalog 下的表仍可能失败，原因在于：  

  * Catalog 层：用于连接 Hive Metastore（获取表结构、分区等元数据）  
  * Location 层：用于读取实际存储在 HDFS 等文件系统中的数据文件  

这两层的认证方式需分别配置，并必须与 Hadoop 集群的安全策略保持一致。  

示例：

```sql
-- user1 有 odps_prod 的 USE CATALOG 权限
SET CATALOG hms_prod;
USE sales_db;

-- 查询表时失败
SELECT * FROM sales_log LIMIT 1;
-- 产生报错

-- 原因：未创建 Location，或 user1 无该 Location 的访问权限
-- 解决方案：创建带认证信息的 Location
CREATE LOCATION hms_sales URL = 'hdfs://nn:8020/sales/'
  CREDENTIAL (USER = 'username');
```
更多关于 HMS Catalog 与 HDFS 存储的认证机制，参见[HMS Catalog](400.hms-catalog.md)。

### 权限验证示例

```sql
-- 授权
GRANT SELECT, USE CATALOG ON CATALOG ca1 TO zhangsan WITH GRANT OPTION;

-- 查看权限
SHOW GRANTS FOR zhangsan;
```

输出：  

```shell
+-------------------------------------------------------------------------+
| Grants for zhangsan@%                                                      |
+-------------------------------------------------------------------------+
| GRANT USAGE ON *.* TO 'zhangsan'                                           |
| GRANT SELECT, USE CATALOG ON CATALOG `ca1` TO 'zhangsan' WITH GRANT OPTION |
+-------------------------------------------------------------------------+
```
