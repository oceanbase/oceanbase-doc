# 列存副本读路由配置

从 **OceanBase 数据库 V4.6.0** 版本起，支持通过系统变量与 Hint 控制只读查询 **是否、何时** 在列存副本（C 副本）上规划与执行。**列存副本自动选择为默认开启行为**：`ap_query_route_policy` 默认值为 `AUTO`，优化器按规则判定后尝试列存路径，**一般无需额外配置**。若需关闭自动选择、强制列存或按 SQL 细粒度控制，见下文变量与 Hint。

系统如何从**基本条件**与**触发条件**判定是否尝试列存路径（与 **AP 查询** 相关的路由原理）见独立说明：[AP 查询与列存副本路由判定规则](210.ap-query-column-replica-routing-rules.md)。

<main id="notice" type='notice'>
  <h4>说明</h4>
  <p>列存副本的创建、Locality 与部署前置条件（如多 C 副本数量限制、合并与 DDL 影响等）见 <a href="../../600.manage/300.replica-management/150.the-use-of-columnstore-replica.md">使用列存副本</a>。从 V4.6.0 起，为使用列存副本而<strong>单独部署 ODP 并配置路由变量</strong>不再是必需步骤；直连 OBServer 或通过常规 ODP 访问时，可在会话/全局层通过本文所述变量控制列存副本选择。</p>
</main>

## 适用版本与前提

* **版本**：要求 OceanBase 数据库 **V4.6.0 及以上**。
* **租户**：需确认目标租户已在 Locality 中配置 **C 副本**，且列存副本处于可提供读服务的状态。
* **变量说明**：需确认 `ap_query_route_policy`、`ap_query_cost_threshold`、`ap_query_replica_fallback` 等变量是否在您的版本中提供、默认值及取值范围；租户内可用 `SHOW VARIABLES LIKE 'ap_query%';` 确认变量是否存在。

## 场景与策略决策

下表用于快速选型；具体语义与边界以当前版本文档及 `SHOW VARIABLES` 为准。

| 场景诉求 | 策略建议 | 说明 |
| -------- | -------- | ---- |
| 智能选择：先尝试行存副本，如果查询满足 AP 特征则重试使用列存副本，推荐大多数场景使用 | `ap_query_route_policy = AUTO`（默认） | 由优化器结合代价、并行等因素判断是否生成列存副本侧计划；可用 `ap_query_cost_threshold` 调节敏感度。 |
| 会话内分析查询强制使用列存副本（在副本可用前提下） | `ap_query_route_policy = FORCE` | 适合明确隔离到 C 副本的只读分析链路；写入仍走主副本。 |
| 完全不要自动选列存，行为对齐升级前习惯 | `ap_query_route_policy = OFF` | 不启用列存副本自动选择逻辑。 |
| 列存副本故障时可接受回落到行存执行 | `ap_query_replica_fallback = ON`（默认） | 降低因 C 副本不可用导致的查询失败。 |
| 必须只在列存上执行，不可用则失败 | `ap_query_replica_fallback = OFF` | 便于严格区分链路，但副本异常时查询可能报错。 |
| 在 AUTO 下希望更多查询尝试列存 | 适当 **降低** `ap_query_cost_threshold` | 阈值越小，越容易触发列存侧计划重试（如设置阈值为 100000）。 |
| 在 AUTO 下仅希望很重查询才尝试列存 | 适当 **提高** `ap_query_cost_threshold` | 减少小查询走列存的概率（如设置阈值为 300000）。 |
| 单条 SQL 与全局会话策略不同 | 使用 Hint `/*+opt_param('ap_query_route_policy', '...')*/` | 见下文「查询级别控制」。 |

读一致性（强读/弱读）由 [ob_read_consistency](../../700.reference/800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/8700.ob_read_consistency-global.md) 等机制共同作用，在列存副本上的具体表现请以您使用的版本说明为准。

### 系统变量说明

下列变量用于列存副本自动选择；名称与含义在多数 V4.6.0+ 版本中共通，**若与您的集群实际 `SHOW VARIABLES` 不一致，以集群为准**。

#### ap_query_route_policy

控制是否以及如何自动选择列存副本执行查询，常见取值包括：

| 取值 | 含义概要 |
| ---- | -------- |
| OFF | 关闭自动选择，相关查询按行存路径规划，查询行为与 V4.6.0 之前版本一致。 |
| AUTO | 默认策略：由优化器判断是否采用列存副本侧计划。 |
| FORCE | 在满足前提条件时，尽量在列存副本上执行只读查询。 |

**示例：**

```shell
obclient> SHOW VARIABLES LIKE 'ap_query_route_policy';
obclient> SET ap_query_route_policy = 'AUTO';
obclient> SET ap_query_route_policy = 'FORCE';
```

#### ap_query_cost_threshold

在 `AUTO` 策略下，与优化器代价相关的阈值；**单并行度** 计划代价超过该阈值时，会参与是否尝试列存副本侧计划的判断。默认值请以 `SHOW VARIABLES` 为准（默认值为 `200000`）。

**示例：**

```shell
obclient> SHOW VARIABLES LIKE 'ap_query_cost_threshold';
obclient> SET SESSION ap_query_cost_threshold = 300000;
```

#### ap_query_replica_fallback

当目标为列存副本但副本不可用或无法完成规划时，是否允许回退到行存副本执行。

| 取值 | 含义概要 |
| ---- | -------- |
| ON | 允许回退，查询尽量成功完成。 |
| OFF | 不允许因该原因回退，可能直接报错。 |

**示例：**

```shell
obclient> SHOW VARIABLES LIKE 'ap_query_replica_fallback';
obclient> SET SESSION ap_query_replica_fallback = OFF;
```

### 与 ob_route_policy 的关系

[ob_route_policy](../../700.reference/800.configuration-items-and-system-variables/200.system-variable/300.global-system-variable/8900.ob_route_policy-global.md) 用于设置 OBServer 内部选择数据副本的路由策略；取值为 `COLUMN_STORE_ONLY` 等时，读路径会限定到对应副本类型。与 `ap_query_*` 同时设置时的语义及优先级请以当前版本文档为准。

## 查询级别控制

在单条语句上使用 Hint，避免改会话全局配置：

* 强制该语句按列存副本侧策略规划（在策略与副本允许的前提下）：

    ```shell
    obclient> EXPLAIN SELECT /*+opt_param('ap_query_route_policy', 'FORCE')*/ *
       FROM t1, t2
       WHERE t1.c1 = t2.c1;
    ```

* 该语句关闭自动选择列存，选择主副本执行：

    ```shell
    obclient> EXPLAIN SELECT /*+opt_param('ap_query_route_policy', 'OFF')*/ *
        FROM t1, t2
        WHERE t1.c1 = t2.c1;
    ```

## 验证与排错建议

* 使用 `EXPLAIN`（或实际执行后的计划视图）查看是否出现列存侧算子。

* 结合 `DBA_OB_CS_REPLICA_STATS` / `CDB_OB_CS_REPLICA_STATS` 等视图确认 C 副本数据就绪与延迟情况，参见 [使用列存副本](../../600.manage/300.replica-management/150.the-use-of-columnstore-replica.md)。

* 未部署 C 副本的租户：开启上述变量通常不会改变无列存时的基本规划行为；仍以实际版本为准。
