# 列存副本自动选择

OceanBase 数据库 V4.6.0 版本引入了列存副本自动选择功能。使用列存副本自动选择功能，具体优势如下：

1. 零配置使用：无需手动识别和配置，系统自动识别 AP 查询并路由到列存副本。
2. 资源利用最大化：TP 和 AP 流量自动分流，充分利用列存副本的计算资源。
3. 支持强读：支持在列存副本上执行强一致性读，满足更多业务场景。
4. 灵活控制：提供 `OFF`、`AUTO`、`FORCE` 三种模式，满足不同场景需求。

### AUTO 模式的工作流程

1. 优化器首先尝试使用行存副本生成执行计划。
2. 计划生成后，检查计划特征（是否弱读、是否并行、代价是否高）。
3. 如果满足 AP 查询特征，触发重试，使用列存副本重新生成计划。
4. 最终使用列存副本计划执行查询。

## 列存副本强读

在 OceanBase 数据库 V4.6.0 之前版本，当查询路由到列存副本时，只能使用弱一致性读（`ob_read_consistency = 'weak'`），无法满足强一致性读的需求。

OceanBase 数据库 V4.6.0 版本引入了列存副本强读功能，支持在列存副本上执行强一致性读，具体优势如下：

* 可以读取到与主副本一致的最新数据。
* 满足需要强一致性的业务场景。
* 扩展了列存副本的使用范围。

### 列存副本强读工作原理

当查询被识别为 AP 查询并路由到列存副本时，如果使用强一致性读（默认），事务层会进行以下处理：

1. 获取全局快照：系统通过 GTS（Global Timestamp Service）获取全局一致性快照版本。
2. 检查副本状态：检查列存副本（Follower）是否已经回放到该快照版本。
3. 等待回放：如果列存副本尚未回放到快照版本，系统会等待列存副本回放完成。
4. 执行读操作：当列存副本可读后，执行强一致性读操作。

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>强读因为需要等待 Follower 回放，可能会增加查询延迟。因此耗时很短的查询并不适合在列存副本执行强读。</p>
</main>

### 强读 vs 弱读

列存副本强读与弱读的主要区别如下：

| **特性** | **强读** | **弱读** |
|----------|----------|----------|
| 一致性保证 | 强一致性，读取的数据与主副本一致 | 最终一致性，可能读取到稍旧的数据 |
| 延迟 | 需要等待 Follower 回放，可能有延迟 | 无需等待，延迟更低 |
| 适用场景 | 需要强一致性的 AP 查询 | 对一致性要求不高的 AP 查询 |
| 设置方式 | `ob_read_consistency = 'strong'`（默认） | `ob_read_consistency = 'weak'` |

**使用建议：**

* 如果业务对数据一致性要求高，使用强读（默认）。
* 如果业务可以容忍短暂的数据延迟，使用弱读可以获得更好的性能。
