# Skip Index 与表更新模式协同配置指南

列存表自 **V4.3.0** 起即支持为**基线数据**自动生成 Skip Index（列存表默认对列建 MIN_MAX 类型 Skip Index）；自 **V4.6.0** 支持对**增量数据**生成 Skip Index。

## AP 场景下的默认模式

租户级配置项只影响**之后新建、且建表语句里没写**对应选项的表；**表更新模式实际值**以 `SHOW CREATE TABLE` 为准。

| 层级 | 确认对象 | AP 下默认值| 如何查询当前值 |
|------|----------|---------------|--------------|
| **租户级** | [default_table_merge_engine](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2130.default_table_merge_engine.md) | 默认 `DELETE_INSERT`。 | `SHOW PARAMETERS LIKE 'default_table_merge_engine';` |
| **租户级** | [default_skip_index_level](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000004386530) | 默认 `1`。（新建表默认打开增量 Skip Index 开关）。 | `SHOW PARAMETERS LIKE 'default_skip_index_level';` |
| **表级** | **skip_index_level** | `1` 表示要对增量生成 Skip Index（仍须配合上一行的表模式）。 | 同上；或查视图 **SKIP_INDEX_LEVEL**（[DBA_TABLES](../../../700.reference/700.system-views/400.system-view-of-mysql-mode/200.dictionary-view-of-mysql-mode/15620.o-dba_tables--of-mysql-mode.md) / [CDB_TABLES](../../../700.reference/700.system-views/300.system-view-of-sys-tenant/200.dictionary-view-of-sys-tenant/13200.o-cdb_tables-of-sys-tenant.md)） |

### 不一致时如何修改

| 你的情况 | 改法 |
|----------|------|
| 租户级 `default_table_merge_engine` 不是想要的 | `ALTER SYSTEM SET default_table_merge_engine = 'delete_insert';`（或 `'append_only'`）。**只影响之后新建且未在 DDL 写 `MERGE_ENGINE` 的表。** |
| 租户级 `default_skip_index_level` 不是 `1` | `ALTER SYSTEM SET default_skip_index_level = 1;`（或 `0`）。**只影响之后新建且未写 `skip_index_level` 的表。** |
| **准备建新表**，希望和 AP 默认一致 | 在 `CREATE TABLE` 里直接写：`MERGE_ENGINE = delete_insert`（或 `append_only`）、`skip_index_level = 1`，不依赖租户是否改过默认。 |
| **已有表**表模式正确（即为 `DELETE_INSERT` 或 `APPEND_ONLY`），只想开/关增量 Skip Index | `ALTER TABLE tbl SET skip_index_level = 1;`（或 `0`）。**下次转储或 Minor 合并后对增量生效。** |
| **已有表**是 `partial_update`，想改成 `delete_insert` | **不能** `ALTER` 改表模式，只能**建新表指定 `MERGE_ENGINE` 再迁数据**。 |

配置项说明见 [default_table_merge_engine](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2130.default_table_merge_engine.md)、[default_skip_index_level](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000004386530)。

### 配置语法示例

```sql
-- 建表时指定
CREATE TABLE logs (
  event_time TIMESTAMP,
  level VARCHAR(10)
)
MERGE_ENGINE = DELETE_INSERT
skip_index_level = 1;

-- 修改已有表（仅 skip_index_level 可改，MERGE_ENGINE 不可改）
ALTER TABLE logs SET skip_index_level = 1;
```

<main id="notice" type='explain'>
<h4>说明</h4>
<p>建表 DDL 中未写 <code>MERGE_ENGINE</code> / <code>skip_index_level</code> 时，分别继承租户级 <a href="../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2130.default_table_merge_engine.md">default_table_merge_engine</a> 与 <a href="https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000004386530">default_skip_index_level</a>。<code>ALTER TABLE ... SET skip_index_level</code> 仅修改表级开关，<strong>不能</strong>修改 <code>MERGE_ENGINE</code>。</p>
</main>

## 原理解析

Skip Index（跳过索引）是一种存储层元数据优化技术，通过在 SSTable 微块（micro-block）级别记录列的聚合信息（如最小值、最大值、空值数量、可选 SUM 等），使查询引擎在扫描前可跳过不满足谓词条件的数据块，减少 I/O 与计算开销。详见 [列 Skip Index 属性（MySQL 模式）](../../../700.reference/300.database-object-management/100.manage-object-of-mysql-mode/200.manage-tables-of-mysql-mode/250.identify-skip-index-properties-of-mysql-mode.md) 与 [AP 特性概览](../../70.obap-features.md)。

在 AP 场景下，需区分**基线数据**与**增量数据**上 Skip Index 的生成支持与条件。

### 基线数据生成 Skip Index

* **支持情况**：OceanBase 支持对**基线数据**（Major SSTable）生成 Skip Index。列存表自 V4.3 起按列默认生成 MIN_MAX 类型；行存表需在列上显式指定 `SKIP_INDEX(MIN_MAX)` 或 `SKIP_INDEX(SUM)` 等，基线在合并时才会生成。
* **生成条件**：列存表在 Major Compaction 时按引擎策略自动生成（默认 MIN_MAX，可按列属性增加 SUM 等）；行存表仅当列有 Skip Index 属性时在合并写基线时生成。与表更新模式（MERGE_ENGINE）无直接关系。

### 增量数据生成 Skip Index

* **支持情况**：增量数据（Memtable、Mini/Minor SSTable）是否生成 Skip Index 与**表更新模式**强相关。三种模式：`PARTIAL_UPDATE`、`DELETE_INSERT`、`APPEND_ONLY`。仅当增量中记录**完整行**时，才能安全生成用户列 Skip Index。
* **生成条件**（需同时满足）：
  1. **表模式**：`MERGE_ENGINE` 取值为 `DELETE_INSERT` 或 `APPEND_ONLY`。
  2. **表级配置**：`skip_index_level = 1`（建表指定或继承租户 `default_skip_index_level = 1`）。
  3. **生效时机**：在**下一次 Mini Compaction（转储）或 Minor Compaction（合并）** 后，增量层才会带上 Skip Index。

**PARTIAL_UPDATE** 表仅记录变更列，无法在增量层安全得到完整行的 min/max 等聚合，因此**即使用户设置 `skip_index_level = 1`，系统也不会为增量数据的用户列生成 Skip Index**。详见 [创建表（MySQL 模式）— 指定表的更新模型](../../../700.reference/300.database-object-management/100.manage-object-of-mysql-mode/200.manage-tables-of-mysql-mode/200.create-a-table-for-mysql-tenant-of-mysql-mode.md)。

### skip_index_level 取值与行为（表级）

| 值 | 含义 |
|----|------|
| `0` | 列存基线按策略生成 Skip Index，行存基线按 schema 列属性生成；**增量 SSTable 不生成**任何 Skip Index。 |
| `1` | 基线行为同上；**增量 SSTable** 在表为 `DELETE_INSERT` 或 `APPEND_ONLY` 时，按与基线一致的策略生成（列存按优先级与空间限制生成，行存按 schema）。AP 场景下租户 **default_skip_index_level** 默认为 1，即新建表默认按 1 行为。 |

建表时未显式指定 `skip_index_level` 时，取租户级配置项 **default_skip_index_level** 的值（**在 AP 场景下该配置项默认值为 1**，故新建表默认会在增量上生成 Skip Index，仍需 MERGE_ENGINE 为 DELETE_INSERT 或 APPEND_ONLY）。修改 `skip_index_level` 后，新配置在**下次转储或 Minor 合并**时对增量生效。详见 [default_skip_index_level](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000004386530)。

## 不支持的场景和模式

* **PARTIAL_UPDATE 表**：不生成**增量**用户列 Skip Index；即使用户设置 `skip_index_level = 1` 也会被忽略。基线行为仍按列存/行存与 schema 生成。
* **列类型与属性限制**：以下列**不生成** Skip Index 聚合信息：
  * 虚拟生成列（virtual generated column）；
  * JSON、空间（geo）类型；
  * outrow LOB。
* **小表或低频 AP 查询**：Skip Index 的存储与 Compaction 开销可能大于收益，可按需不开启或使用 `skip_index_level = 0`。

## 适用场景建议（AP）

* **推荐**：列存表（DELETE_INSERT）、日志/指标表（APPEND_ONLY）、TTL 表（DELETE_INSERT/APPEND_ONLY + 时间列），建表时指定 `skip_index_level = 1`，使增量也具备 Skip Index。
* **不推荐**：高并发更新的 TP 表（PARTIAL_UPDATE）依赖增量 Skip Index（系统不会生成）；或小表/低频查询表开启增量 Skip Index 导致成本大于收益。

## 示例：AP 场景下配置表更新模式与 Skip Index

以下示例虚拟一个 **AP 日志/指标表** 场景：按时间范围查询、按时间列 TTL 自动过期，希望基线与增量都具备 Skip Index 以加速过滤。

### 场景说明

* 表用途：存储业务事件日志，按 `event_time` 范围查询，并按 `event_time` 做 TTL 自动过期（例如 12 小时）。
* 目标：表为 **DELETE_INSERT** 模式，**skip_index_level = 1**，使增量数据在转储/合并后也带 Skip Index；可选在部分列上显式指定 `SKIP_INDEX(MIN_MAX, SUM)` 提高优先级。

### 步骤 1：查看当前租户级配置项

在**系统租户**下执行（或 sys 租户下对指定租户查看），确认当前默认表模式与 Skip Index 等级默认值：

```sql
-- 查看默认表更新模式（默认一般为 partial_update）
SHOW PARAMETERS LIKE 'default_table_merge_engine';

-- 查看新建表的默认 skip_index_level（AP 场景下默认值为 1）
SHOW PARAMETERS LIKE 'default_skip_index_level';
```

本租户以 AP 为主，可确保租户默认如下（AP 场景下 **default_skip_index_level** 默认已为 1，可主要关注 **default_table_merge_engine**）：

```sql
ALTER SYSTEM SET default_table_merge_engine = 'delete_insert';
-- 若尚未为 1，可执行：ALTER SYSTEM SET default_skip_index_level = 1;
```

修改后**仅对之后新建的表**生效，不影响已有表。

### 步骤 2：建表时指定表更新模式与 Skip Index 等级

建表时显式指定列存 `(WITH COLUMN GROUP(each column))`、`MERGE_ENGINE = delete_insert`、`skip_index_level = 1`，并可选在列上指定 Skip Index 属性：

```sql
CREATE TABLE ap_logs (
  log_id     BIGINT,
  event_time TIMESTAMP,
  level      VARCHAR(32),
  duration_ms INT,
  extra      VARCHAR(1024),
  c3         FLOAT SKIP_INDEX(MIN_MAX, SUM),
  PRIMARY KEY (log_id)
) MERGE_ENGINE = delete_insert
  skip_index_level = 1
  WITH COLUMN GROUP(each column);
```

<main id="notice" type='explain'>
<h4>说明</h4>
<p><ul>
<li><code>WITH COLUMN GROUP(each column)</code>：创建<strong>列存表</strong>；列存基线默认按列生成 MIN_MAX 等 Skip Index，增量在满足表模式与 <code>skip_index_level</code> 时按相同策略生成。</li>
<li><code>MERGE_ENGINE = delete_insert</code>：全列更新，增量可安全生成 Skip Index。</li>
<li><code>skip_index_level = 1</code>：该表的增量 SSTable 将按策略生成 Skip Index（与基线一致）。</li>
<li><code>c3 FLOAT SKIP_INDEX(MIN_MAX, SUM)</code>：该列在 schema 上指定了 Skip Index，会按指定类型生成（MIN_MAX + SUM），并在优先级排序中靠前。</li>
</ul></p>
</main>

### 步骤 3：修改已有表的 Skip Index

若表已存在且为 `DELETE_INSERT` 或 `APPEND_ONLY`，仅需打开增量 Skip Index 时，可执行：

```sql
ALTER TABLE ap_logs SET skip_index_level = 1;
```

<main id="notice" type='explain'>
<h4>说明</h4>
<p>新配置在<strong>下一次转储或 Minor 合并</strong>后对增量数据生效。<strong>MERGE_ENGINE</strong> 不可通过 DDL 修改。</p>
<p>即使 <code>skip_index_level = 1</code>，只有 <code>MERGE_ENGINE</code> 为 <code>DELETE_INSERT</code> 或 <code>APPEND_ONLY</code> 的表，其增量 SSTable 才会实际生成用户列的 Skip Index。对于 <code>PARTIAL_UPDATE</code> 表，无论 <code>skip_index_level</code> 设为何值，用户列的增量 Skip Index 始终被禁用（仅 <code>trans_version</code> 列可生成）。配置项详见 <a href="https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000004386530">default_skip_index_level</a>。</p>
</main>
