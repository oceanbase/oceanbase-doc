# Skip Index 与表更新模式协同配置指南

OceanBase 数据库在 V4.6.0 版本支持在保证数据正确性的前提下，为合适场景自动开启 Skip Index，加速 AP 查询。

## 表更新模式与 Skip Index 的关系

Skip Index（跳过索引）是一种存储层元数据优化技术，通过在 SSTable 微块（micro-block）级别记录列的聚合信息（如最小值、最大值、空值数量等），使得查询引擎在扫描前可跳过不满足谓词条件的数据块，从而减少 I/O 和计算开销。详细信息可以参见：[Skip Index](../../../700.reference/300.database-object-management/100.manage-object-of-mysql-mode/200.manage-tables-of-mysql-mode/250.identify-skip-index-properties-of-mysql-mode.md)。

OceanBase 支持三种表更新模式：`PARTIAL_UPDATE`、`DELETE_INSERT` 和 `INSERT_ONLY`。不同模式下，增量 SSTable（minor/mini）是否记录完整行数据，直接决定了能否安全生成 Skip Index。

## 适用场景建议

### 推荐开启场景

即启用增量 Skip Index（`skip_index_level=1` + 非 `PARTIAL_UPDATE` 模式）：  
- 列存表：默认使用 `DELETE_INSERT` 模式，天然适合 AP 查询，默认开启；  
- 日志 / 指标表：`INSERT_ONLY` 模式，数据只增不改，安全高效；  
- TTL 表：时间列自动获得高优先级 Skip Index，加速过期数据过滤。

### 不推荐开启场景

即增量 Skip Index（默认或 `PARTIAL_UPDATE` 模式）：  
- 高并发更新的 TP 表（`PARTIAL_UPDATE` 模式）：即使设 `skip_index_level=1`，系统也会自动忽略用户列；  
- 小表或低频查询表：Skip Index 的存储开销可能大于性能收益。

## 表模式对增量 Skip Index 的支持

| 表模式 | 用户列（含主键） | `trans_version` 列 | Lock 行处理 |
|--------|------------------|--------------------|-------------|
| `DELETE_INSERT` | 可生成 Skip Index（记录全行，无 NOP） | 可生成（无 NOP） | 忽略（不影响正确性） |
| `INSERT_ONLY` | 可生成 Skip Index（仅插入，数据完整） | 可生成（无 NOP） | 无 Lock 行 |
| `PARTIAL_UPDATE` | 不可生成（存在 NOP，可能导致正确性问题） | 可生成（无 NOP） | 不适用 |

**说明**：  
- Lock 行：事务在提交前发生转储时写入的特殊记录（`DmlFlag = DF_LOCK`），仅表示 “加锁意图”，不修改列值。因其不携带有效数据变更，生成 Skip Index 时可安全忽略。  
- `trans_version` 列：系统隐藏列，用于 MVCC 版本控制，在所有表模式下均无 NOP，可安全生成 Skip Index。

在 `DELETE_INSERT` / `INSERT_ONLY` 模式下启用 `skip_index_level=1`，实时写入的数据也能被高效过滤，避免 “新数据查得慢” 的问题。  
系统主动禁用 `PARTIAL_UPDATE` 增量上的用户列 Skip Index，以牺牲部分性能为代价，确保查询结果绝对正确。

## 如何开启增量 Skip Index

要成功启用增量 Skip Index，必须同时满足以下条件：  
1. 表模式支持：`MERGE_ENGINE` 为 `DELETE_INSERT` 或 `INSERT_ONLY`；  
2. 配置项开启：`skip_index_level = 1`（可通过建表指定，或依赖 `default_skip_index_level = 1`）；  
3. 等待 Compaction：配置在下一次 Mini / Minor Compaction 后生效。

若表为 `PARTIAL_UPDATE`，即使 `skip_index_level = 1`，用户列的增量 Skip Index 也不会生成。

通过表级配置项 `skip_index_level` 控制是否在增量 SSTable 中生成 Skip Index。但最终是否生效，取决于两个条件：  
1. 表的 `skip_index_level` 配置值；  
2. 表的更新模式（`MERGE_ENGINE`）是否支持增量 Skip Index。

### 配置语法

```sql
-- 建表时指定
CREATE TABLE logs (
  event_time TIMESTAMP,
  level VARCHAR(10)
)
MERGE_ENGINE = DELETE_INSERT
skip_index_level = 1;  -- 启用增量 Skip Index

-- 修改已有表
ALTER TABLE logs SET skip_index_level = 1;
```

> **注意**：如果不指定 `MERGE_ENGINE` 选项，则该选项取值与租户级配置项 `default_table_merge_engine` 的值相同。

### 参数取值与行为

| 值 | 含义 |
|----|------|
| `0`（默认） | - 基线 SSTable：正常生成 Skip Index<br>- 增量 SSTable：不生成任何 Skip Index |
| `1` | - 基线 SSTable：正常生成 Skip Index<br>- 增量 SSTable：根据表模式和生成策略生成 Skip Index |

- 类型为 `INT`，当前仅支持 `0` / `1`；  
- 若建表时未显式指定 `skip_index_level`，则取租户级配置项 `default_skip_index_level` 的值；  
- 修改 `skip_index_level` 后，新配置在下一次转储（Mini Compaction）或合并（Minor Compaction）时生效。

### 租户级默认配置：`default_skip_index_level`

该参数仅用于设置新建表的 `skip_index_level` 默认值，不影响已存在的表。

- `default_skip_index_level = 0`：增量 SSTable 不生成 Skip Index。  
- `default_skip_index_level = 1`：仅当表的 `MERGE_ENGINE = 'delete_insert'` / `'INSERT_ONLY'` 时，增量 SSTable 才会生成 Skip Index，且生成的列与基线保持一致。

默认值按场景设定如下：  
* 通用场景（即原 ob_parameter_seed.ipp 中的值）：`0`  
* HTAP 场景：`0`  
* 简单 OLTP 场景（互联网应用）：`0`  
* 复杂 OLTP 场景（传统应用）：`0`  
* OLAP 场景：`1`  
* KV 场景：`0`  
* 简单 OLTP POC 场景：`0`

**重要规则**：  
即使 `skip_index_level = 1`，只有 `MERGE_ENGINE` 为 `DELETE_INSERT` 或 `INSERT_ONLY` 的表，其增量 SSTable 才会实际生成用户列的 Skip Index；  
对于 `PARTIAL_UPDATE` 表，无论 `skip_index_level` 设为何值，用户列的增量 Skip Index 始终被禁用（仅 `trans_version` 列可生成）。

配置项详细信息：[default_skip_index_level](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000004386530)
