# Skip Index 与表更新模式协同配置指南

列存表自 **V4.3.0** 起即支持为**基线数据**自动生成 Skip Index（列存表默认对列建 MIN_MAX 类型 Skip Index）；自 **V4.6.0** 支持对**增量数据**生成 Skip Index。

## AP 场景下的默认模式

### 默认模式

* **表更新模式（MERGE_ENGINE）**：若不显式指定，由租户级配置项 [default_table_merge_engine](../../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2130.default_table_merge_engine.md) 决定。该配置项默认值为 `DELETE_INSERT`。

* **Skip Index（skip_index_level）**：若不显式指定，由租户级配置项 **default_skip_index_level** 决定。该配置项**在 AP 场景下默认值为 `1`**，即 AP 场景下新建表的增量 SSTable 默认**生成** Skip Index（实际是否生成还取决于表模式为 `DELETE_INSERT` 或 `APPEND_ONLY`）。

因此，在 AP 场景下若希望**基线 + 增量**都具备 Skip Index，**skip_index_level** 在 AP 场景下已默认为 1，通常无需显式指定；需要显式指定或调整的是**表模式**（MERGE_ENGINE），因 **default_table_merge_engine** 默认仍为 `partial_update`。

### 何时需要指定或切换模式

* **建表时显式指定**（推荐）：

  在 AP 场景下，**default_skip_index_level** 已默认为 1，故表级 **skip_index_level** 通常无需显式指定。若当前租户的 **default_table_merge_engine** 仍为 `partial_update`，而业务是 AP 表（如日志表、指标表、列存分析表），应在建表时**显式指定**：

  * `MERGE_ENGINE = delete_insert`（或 `APPEND_ONLY`，适用于只增不改的表）；
  * 若租户未将 `default_skip_index_level` 设为 1，可再显式指定 `skip_index_level = 1`。

* **调整租户默认**：  

  AP 场景下 **default_skip_index_level** 已默认为 1。若该租户以 AP 为主，可将 **default_table_merge_engine** 设为 `'delete_insert'`，则**此后新建的表**在不写表选项时默认为 DELETE_INSERT 且 skip_index_level 继承 1，增量会生成 Skip Index。修改租户配置**不影响已存在的表**。

* **表模式创建后不可修改**：  

  **MERGE_ENGINE** 在创建表时指定后**不可修改**。若表已按 `partial_update` 创建，无法通过 DDL 改为 `delete_insert`，只能新建表并迁移数据。  
  **skip_index_level** 可通过 `ALTER TABLE ... SET skip_index_level = 0/1` 修改，在下次转储或 Minor 合并后对增量数据生效。

## 表更新模式与 Skip Index 的关系

Skip Index（跳过索引）是一种存储层元数据优化技术，通过在 SSTable 微块（micro-block）级别记录列的聚合信息（如最小值、最大值、空值数量、可选 SUM 等），使查询引擎在扫描前可跳过不满足谓词条件的数据块，减少 I/O 与计算开销。详见 [列 Skip Index 属性（MySQL 模式）](../../../../700.reference/300.database-object-management/100.manage-object-of-mysql-mode/200.manage-tables-of-mysql-mode/250.identify-skip-index-properties-of-mysql-mode.md) 与 [AP 特性概览](../../../70.obap-features.md)。

在 AP 场景下，需区分**基线数据**与**增量数据**上 Skip Index 的生成支持与条件。

### 基线数据生成 Skip Index

* **支持情况**：OceanBase 支持对**基线数据**（Major SSTable）生成 Skip Index。列存表自 V4.3 起按列默认生成 MIN_MAX 类型；行存表需在列上显式指定 `SKIP_INDEX(MIN_MAX)` 或 `SKIP_INDEX(SUM)` 等，基线在合并时才会生成。
* **生成条件**：列存表在 Major Compaction 时按引擎策略自动生成（默认 MIN_MAX，可按列属性增加 SUM 等）；行存表仅当列有 Skip Index 属性时在合并写基线时生成。与表更新模式（MERGE_ENGINE）无直接关系。

### 增量数据生成 Skip Index

* **支持情况**：增量数据（Memtable、Mini/Minor SSTable）是否生成 Skip Index 与**表更新模式**强相关。三种模式：`PARTIAL_UPDATE`、`DELETE_INSERT`、`APPEND_ONLY`。仅当增量中记录**完整行**时，才能安全生成用户列 Skip Index。
* **生成条件**（需同时满足）：
  1. **表模式**：`MERGE_ENGINE` 为 `DELETE_INSERT` 或 `APPEND_ONLY`。
  2. **表级配置**：`skip_index_level = 1`（建表指定或继承租户 **default_skip_index_level**；AP 场景下该配置项默认为 1）。
  3. **生效时机**：在**下一次 Mini Compaction（转储）或 Minor Compaction（合并）** 后，增量层才会带上 Skip Index。

**PARTIAL_UPDATE** 表仅记录变更列，无法在增量层安全得到完整行的 min/max 等聚合，因此**即使用户设置 `skip_index_level = 1`，系统也不会为增量数据的用户列生成 Skip Index**。详见 [创建表（MySQL 模式）— 指定表的更新模型](../../../../700.reference/300.database-object-management/100.manage-object-of-mysql-mode/200.manage-tables-of-mysql-mode/200.create-a-table-for-mysql-tenant-of-mysql-mode.md)。

### skip_index_level 取值与行为（表级）

| 值 | 含义 |
|----|------|
| `0` | 列存基线按策略生成 Skip Index，行存基线按 schema 列属性生成；**增量 SSTable 不生成**任何 Skip Index。 |
| `1` | 基线行为同上；**增量 SSTable** 在表为 `DELETE_INSERT` 或 `APPEND_ONLY` 时，按与基线一致的策略生成（列存按优先级与空间限制生成，行存按 schema）。AP 场景下租户 **default_skip_index_level** 默认为 1，即新建表默认按 1 行为。 |

建表时未显式指定 `skip_index_level` 时，取租户级配置项 **default_skip_index_level** 的值（**在 AP 场景下该配置项默认值为 1**，故新建表默认会在增量上生成 Skip Index，仍需 MERGE_ENGINE 为 DELETE_INSERT 或 APPEND_ONLY）。修改 `skip_index_level` 后，新配置在**下次转储或 Minor 合并**时对增量生效。详见 [default_skip_index_level](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000004386530)。

## 不支持的场景和模式

* **PARTIAL_UPDATE 表**：不生成**增量**用户列 Skip Index；即使用户设置 `skip_index_level = 1` 也会被忽略。基线行为仍按列存/行存与 schema 生成。
* **列类型与属性限制**：以下列**不生成** Skip Index 聚合信息：
  * 虚拟生成列（virtual generated column）；
  * JSON、空间（geo）类型；
  * outrow LOB。
* **TTL 表**：TTL 列仅支持 **DELETE_INSERT** 和 **APPEND_ONLY** 表模式。若表为 PARTIAL_UPDATE，无法使用 TTL；使用 TTL 时表模式需在建表时指定为 `delete_insert` 或 `append_only`。
* **小表或低频 AP 查询**：Skip Index 的存储与 Compaction 开销可能大于收益，可按需不开启或使用 `skip_index_level = 0`。

## 适用场景建议（AP）

* **推荐**：列存表（DELETE_INSERT）、日志/指标表（APPEND_ONLY）、TTL 表（DELETE_INSERT/APPEND_ONLY + 时间列），建表时指定 `skip_index_level = 1`，使增量也具备 Skip Index。
* **不推荐**：高并发更新的 TP 表（PARTIAL_UPDATE）依赖增量 Skip Index（系统不会生成）；或小表/低频查询表开启增量 Skip Index 导致成本大于收益。

## 如何开启增量 Skip Index

要成功启用**增量** Skip Index，必须同时满足：

1. **表模式**：`MERGE_ENGINE` 为 `DELETE_INSERT` 或 `APPEND_ONLY`。
2. **配置项**：`skip_index_level = 1`（AP 场景下默认继承租户级 **default_skip_index_level** 的取值，默认为 1）。
3. **生效时机**：在**下一次 Mini Compaction 或 Minor Compaction** 后对增量数据生效。

### 配置语法

```sql
-- 建表时指定
CREATE TABLE logs (
  event_time TIMESTAMP,
  level VARCHAR(10)
)
MERGE_ENGINE = DELETE_INSERT
skip_index_level = 1;

-- 修改已有表（仅 skip_index_level 可改，MERGE_ENGINE 不可改）
ALTER TABLE logs SET skip_index_level = 1;
```

若不指定 `MERGE_ENGINE`，则取租户级配置项 [default_table_merge_engine](../../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2130.default_table_merge_engine.md) 的值。

### 查看表的 Skip Index（skip_index_level）

可通过系统视图 **DBA_TABLES**、**CDB_TABLES** 中的 **SKIP_INDEX_LEVEL** 列查看当前表的表级配置。该列取值为 `0` 或 `1`。

* **系统租户**：系统租户可查询 [oceanbase.CDB_TABLES（系统租户）](../../../../700.reference/700.system-views/300.system-view-of-sys-tenant/200.dictionary-view-of-sys-tenant/13200.o-cdb_tables-of-sys-tenant.md)。

* **MySQL 模式**：用户租户查询 [oceanbase.DBA_TABLES（MySQL 模式）](../../../../700.reference/700.system-views/400.system-view-of-mysql-mode/200.dictionary-view-of-mysql-mode/15620.o-dba_tables--of-mysql-mode.md)

* **Oracle 模式**：可查询 [DBA_TABLES（Oracle 模式）](../../../../700.reference/700.system-views/500.system-view-of-oracle-mode/200.dictionary-view-of-oracle-mode/21800.dba_tables-of-oracle-mode.md)。

当表的 `MERGE_ENGINE = PARTIAL_UPDATE` 时，**SKIP_INDEX_LEVEL** 显示为 `NULL`，但该配置对**增量数据不生效**（系统不会为增量生成用户列 Skip Index）。仅当表为 `DELETE_INSERT` 或 `APPEND_ONLY` 且 `skip_index_level = 1` 时，增量才会实际生成 Skip Index。

### 租户级默认配置：default_skip_index_level

用于设置**新建表**的 `skip_index_level` 默认值，**不影响已存在的表**。**在 AP 场景下该配置项默认值为 `1`**，即新建表默认 `skip_index_level = 1`，仅当该表为 `DELETE_INSERT` 或 `APPEND_ONLY` 时增量才会实际生成 Skip Index。若设为 `0`，则新建表增量不生成 Skip Index。详见 [default_skip_index_level](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000004386530)。

## 示例：AP 场景下配置表更新模式与 Skip Index

以下示例虚拟一个 **AP 日志/指标表** 场景：按时间范围查询、按时间列 TTL 自动过期，希望基线与增量都具备 Skip Index 以加速过滤。

### 场景说明

* 表用途：存储业务事件日志，按 `event_time` 范围查询，并按 `event_time` 做 TTL 自动过期（例如 12 小时）。
* 目标：表为 **DELETE_INSERT** 模式，**skip_index_level = 1**，使增量数据在转储/合并后也带 Skip Index；可选在部分列上显式指定 `SKIP_INDEX(MIN_MAX, SUM)` 提高优先级。

### 步骤 1：查看当前租户级配置项

在**系统租户**下执行（或 sys 租户下对指定租户查看），确认当前默认表模式与 Skip Index 等级默认值：

```sql
-- 查看默认表更新模式（默认一般为 partial_update）
SHOW PARAMETERS LIKE 'default_table_merge_engine';

-- 查看新建表的默认 skip_index_level（AP 场景下默认值为 1）
SHOW PARAMETERS LIKE 'default_skip_index_level';
```

若计划本租户以 AP 为主，可确保租户默认如下（AP 场景下 **default_skip_index_level** 默认已为 1，可主要关注 **default_table_merge_engine**）：

```sql
ALTER SYSTEM SET default_table_merge_engine = 'delete_insert';
-- 若尚未为 1，可执行：ALTER SYSTEM SET default_skip_index_level = 1;
```

修改后**仅对之后新建的表**生效，不影响已有表。

### 步骤 2：建表时指定表更新模式与 Skip Index 等级

建表时**显式指定** `MERGE_ENGINE = delete_insert`、`skip_index_level = 1`，并可选 TTL、列上的 Skip Index 属性（参考研发示例）：

```sql
CREATE TABLE ap_logs (
  log_id     BIGINT,
  event_time TIMESTAMP,
  level      VARCHAR(32),
  duration_ms INT,
  extra      VARCHAR(1024),
  c3         FLOAT SKIP_INDEX(MIN_MAX, SUM),
  PRIMARY KEY (log_id)
) MERGE_ENGINE = delete_insert
  skip_index_level = 1
  TTL (event_time + INTERVAL 12 HOUR);
```

说明：

* `MERGE_ENGINE = delete_insert`：全列更新，增量可安全生成 Skip Index。
* `skip_index_level = 1`：该表的增量 SSTable 将按策略生成 Skip Index（与基线一致）。
* `TTL (event_time + INTERVAL 12 HOUR)`：仅 DELETE_INSERT/APPEND_ONLY 支持，且 TTL 列为时间类型，符合要求；TTL 列在 Skip Index 生成中具有高优先级。
* `c3 FLOAT SKIP_INDEX(MIN_MAX, SUM)`：该列在 schema 上指定了 Skip Index，会按指定类型生成（MIN_MAX + SUM），并在优先级排序中靠前。

若为**列存表**，可增加 `WITH COLUMN GROUP (each column)`；列存表基线默认生成 MIN_MAX，增量在 `skip_index_level = 1` 且 `delete_insert` 时按相同策略生成。

### 步骤 3：修改已有表的 Skip Index

若表已存在且为 `DELETE_INSERT` 或 `APPEND_ONLY`，仅需打开增量 Skip Index 时，可执行：

```sql
ALTER TABLE ap_logs SET skip_index_level = 1;
```

新配置在**下一次转储或 Minor 合并**后对增量数据生效。**MERGE_ENGINE** 不可通过 DDL 修改。

即使 `skip_index_level = 1`，只有 `MERGE_ENGINE` 为 `DELETE_INSERT` 或 `APPEND_ONLY` 的表，其增量 SSTable 才会实际生成用户列的 Skip Index；  
对于 `PARTIAL_UPDATE` 表，无论 `skip_index_level` 设为何值，用户列的增量 Skip Index 始终被禁用（仅 `trans_version` 列可生成）。配置项详细信息参见 [default_skip_index_level](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000004386530)。
