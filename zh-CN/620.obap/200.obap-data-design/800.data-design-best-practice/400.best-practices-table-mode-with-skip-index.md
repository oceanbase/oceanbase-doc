# Skip Index 与表更新模式协同配置指南

列存表自 **V4.3.0** 起即支持为**基线数据**自动生成 Skip Index（列存表默认对列建 MIN_MAX 类型 Skip Index）；自 **V4.6.0** 支持对**增量数据**生成 Skip Index。

Skip Index 通过在 SSTable 的微块（micro-block）级别记录列的聚合信息，例如最小值、最大值、空值数量以及可选的 SUM 信息，使查询在扫描前能够过滤掉不满足条件的数据块，从而减少不必要的 I/O 和计算开销。有关 Skip Index 的更多信息，详见 [列 Skip Index 属性（MySQL 模式）](../../../700.reference/300.database-object-management/100.manage-object-of-mysql-mode/200.manage-tables-of-mysql-mode/250.identify-skip-index-properties-of-mysql-mode.md)。在分析查询场景中，Skip Index 适用于大表扫描以及带有范围条件、等值条件等过滤条件的查询，能够有效减少扫描的数据量。在数据量较大且过滤条件选择性较好的场景下，优化效果通常更加明显。

对于列存表而言，基线数据通常可以自动具备相应的聚合信息；而增量数据如果长期未生成 Skip Index，新写入数据在查询时仍可能触发较多无效微块扫描，从而影响分析查询性能。

因此，在 AP 场景下，建议根据业务特征合理配置 **表更新模式（MERGE_ENGINE）** 和 **skip_index_level** 等参数，使**增量数据**在满足条件时也能够生成 Skip Index，以提升带过滤条件查询的执行效率。

## AP 场景下的默认模式

**增量是否生成用户列 Skip Index** 取决于表级 `MERGE_ENGINE` 与 `skip_index_level` 的组合取值。租户级配置项只影响**之后新建、且建表语句里未写**对应选项的表；表上实际定义以 `SHOW CREATE TABLE` 为准。

请您按下面几项逐项确认当前取值：

- **[default_table_merge_engine](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2130.default_table_merge_engine.md)**（租户级）
  - **查询**：`SHOW PARAMETERS LIKE 'default_table_merge_engine';`
  - **默认**：`PARTIAL_UPDATE`。**AP 建议**：改为 `delete_insert` / `append_only`，或建表 DDL **显式**写 `MERGE_ENGINE`。
  - **若不符**：`ALTER SYSTEM SET default_table_merge_engine = 'delete_insert';`（或 `'append_only'`）。**仅影响之后新建、且 DDL 未写 `MERGE_ENGINE` 的表。**

- **[default_skip_index_level](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2110.default_skip_index_level.md)**（租户级）
  - **查询**：`SHOW PARAMETERS LIKE 'default_skip_index_level';`
  - **默认**：AP 场景下为 `1`；表级配置项 `skip_index_level` 时会继承 `default_skip_index_level` 的值。
  - **若不符**：`ALTER SYSTEM SET default_skip_index_level = 1;`（或 `0`）。**仅影响之后新建、且 DDL 未写 `skip_index_level` 的表。**

- **表级 `MERGE_ENGINE`（表更新模式）**
  - **查询**：`SHOW CREATE TABLE dbname.tblname;`
  - **若要增量用户列 Skip Index**：须为 `DELETE_INSERT` 或 `APPEND_ONLY`（不能是 `PARTIAL_UPDATE`）。
  - **若不符**：**不能**用 `ALTER TABLE` 改表模式；须**建新表**指定 `MERGE_ENGINE` 并**迁数据**。新建表时也可在 DDL 中直接写明，不依赖租户默认。

- **表级 `skip_index_level`**
  - **查询**：`SHOW CREATE TABLE dbname.tblname;`，或视图 **SKIP_INDEX_LEVEL**（[DBA_TABLES](../../../700.reference/700.system-views/400.system-view-of-mysql-mode/200.dictionary-view-of-mysql-mode/15620.o-dba_tables--of-mysql-mode.md) / [CDB_TABLES](../../../700.reference/700.system-views/300.system-view-of-sys-tenant/200.dictionary-view-of-sys-tenant/13200.o-cdb_tables-of-sys-tenant.md)）。
  - **若要增量 Skip Index**：须为 `1`，且**同时**满足上一条表模式。
  - **若不符**：若表模式已是 `DELETE_INSERT` / `APPEND_ONLY`，执行 `ALTER TABLE tbl SET skip_index_level = 1;`（或 `0`）；**下次转储或 Minor 合并**后对增量生效。

**新建表想一次到位、少依赖租户默认**：在 `CREATE TABLE` 中显式写 `MERGE_ENGINE = delete_insert`（或 `append_only`）与 `skip_index_level = 1`（列存分析可再加 `WITH COLUMN GROUP(each column)`），见下文「配置语法示例」。

配置项说明见 [default_table_merge_engine](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2130.default_table_merge_engine.md)、[default_skip_index_level](../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2110.default_skip_index_level.md)。

### 配置语法示例

```sql
-- 建表时指定
CREATE TABLE logs (
  event_time TIMESTAMP,
  level VARCHAR(10)
)
MERGE_ENGINE = DELETE_INSERT
skip_index_level = 1;

-- 修改已有表（仅 skip_index_level 可改，MERGE_ENGINE 不可改）
ALTER TABLE logs SET skip_index_level = 1;
```

<main id="notice" type='explain'>
<h4>说明</h4>
<p>建表 DDL 中未写 <code>MERGE_ENGINE</code> / <code>skip_index_level</code> 时，分别继承租户级 <a href="../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2130.default_table_merge_engine.md">default_table_merge_engine</a> 与 <a href="../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2110.default_skip_index_level.md">default_skip_index_level</a>。<code>ALTER TABLE ... SET skip_index_level</code> 仅修改表级开关，<strong>不能</strong>修改 <code>MERGE_ENGINE</code>。</p>
</main>

## 技术解析

租户级、表级应查哪些项、如何改，见上文 **AP 场景下的默认模式**；本章节从存储层说明基线 / 增量差异及 `skip_index_level` 取值含义。

### 基线数据生成 Skip Index

* **支持情况**：OceanBase 支持对**基线数据**（Major SSTable）生成 Skip Index。列存表自 V4.3 起按列默认生成 MIN_MAX 类型；行存表需在列上显式指定 `SKIP_INDEX(MIN_MAX)` 或 `SKIP_INDEX(SUM)` 等，基线在合并时才会生成。
* **生成条件**：列存表在 Major Compaction 时按引擎策略自动生成（默认 MIN_MAX，可按列属性增加 SUM 等）；行存表仅当列有 Skip Index 属性时在合并写基线时生成。与表更新模式（MERGE_ENGINE）无直接关系。

### 增量数据生成 Skip Index

* **支持情况**：增量数据（Memtable、Mini/Minor SSTable）是否生成 Skip Index 与**表更新模式**强相关。仅当增量中记录**完整行**时，才能安全生成用户列 Skip Index。
* **生成条件**（需同时满足）：
  1. **表模式**：`MERGE_ENGINE` 取值为 `DELETE_INSERT` 或 `APPEND_ONLY`。
  2. **表级配置**：`skip_index_level = 1`（建表指定或继承租户 `default_skip_index_level = 1`）。
  3. **生效时机**：在**下一次 Mini Compaction（转储）或 Minor Compaction（合并）** 后，增量层才会带上 Skip Index。

<main id="notice" type='explain'>
<h4>说明</h4>
<p><code>PARTIAL_UPDATE</code> 表仅记录变更列，增量层无法稳定得到完整行的 min/max 等聚合信息，因此即使设置 <code>skip_index_level = 1</code>，系统也不会为增量用户列生成 Skip Index。</p>
</main>

### skip_index_level 取值与行为（表级）

| 值 | 含义 |
|----|------|
| `0` | 列存基线按策略生成 Skip Index，行存基线按 schema 列属性生成；**增量 SSTable 不生成**任何 Skip Index。 |
| `1` | 基线行为同上；**增量 SSTable** 在表为 `DELETE_INSERT` 或 `APPEND_ONLY` 时，按与基线一致的策略生成（列存按优先级与空间限制生成，行存按 schema）。新建表未写 `skip_index_level` 时常继承租户 **default_skip_index_level**（多为 `1`，以实际参数为准）。 |

建表时未显式指定 `skip_index_level` 时，则取租户级配置项 **default_skip_index_level** 的值。修改 `skip_index_level` 后，新配置在**下次转储或 Minor 合并**时对增量生效。

## 适用场景

### 不适用或需注意

* **PARTIAL_UPDATE 表**：不生成**增量**用户列 Skip Index；即使用户设置 `skip_index_level = 1` 也会被忽略。基线仍按列存/行存与 schema 生成。
* **列类型与属性限制**：以下列**不生成** Skip Index 聚合信息：虚拟生成列（virtual generated column）；JSON、空间（geo）类型；outrow LOB。
* **小表或低频 AP 查询**：Skip Index 的存储与 Compaction 开销可能大于收益，可按需使用 `skip_index_level = 0` 或不依赖增量 Skip Index。
* **高并发更新的 TP 表**（`PARTIAL_UPDATE`）：指望依赖**增量**用户列 Skip Index 做分析过滤时，系统不会生成，应避免按 AP 增量 Skip Index 预期调优。

### 推荐（AP）

* **列存分析表**：`WITH COLUMN GROUP(each column)`，配合 `MERGE_ENGINE = DELETE_INSERT` 与 `skip_index_level = 1`，使基线与增量均易受益于 Skip Index。
* **日志 / 指标追加写**：`MERGE_ENGINE = APPEND_ONLY`，同样配合 `skip_index_level = 1`（按需）。

## 示例：AP 列存表配置表更新模式与 Skip Index

### 场景说明

* 表用途：列存存储业务事件或指标明细，按 `event_time` 等列做范围查询与聚合。
* 目标：`WITH COLUMN GROUP(each column)`、`MERGE_ENGINE = DELETE_INSERT`、`skip_index_level = 1`；可选在部分列上显式指定 `SKIP_INDEX(MIN_MAX, SUM)`。

### 步骤 1：查看当前租户级配置项

在**系统租户**下执行（或 sys 租户下对指定租户查看），确认当前默认表模式与 Skip Index 等级默认值：

```sql
-- 查看默认表更新模式（默认一般为 partial_update）
SHOW PARAMETERS LIKE 'default_table_merge_engine';

-- 查看新建表的默认 skip_index_level（AP 场景下默认值为 1）
SHOW PARAMETERS LIKE 'default_skip_index_level';
```

若本租户以 AP 为主，可确保租户默认如下（**default_skip_index_level** 常见已为 `1`，可主要关注 **default_table_merge_engine**）：

```sql
ALTER SYSTEM SET default_table_merge_engine = 'delete_insert';
-- 若尚未为 1，可执行：ALTER SYSTEM SET default_skip_index_level = 1;
```

修改后**仅对之后新建的表**生效，不影响已有表。

### 步骤 2：建表时指定表更新模式与 Skip Index 等级

建表时显式指定列存 `(WITH COLUMN GROUP(each column))`、`MERGE_ENGINE = delete_insert`、`skip_index_level = 1`，并可选在列上指定 Skip Index 属性：

```sql
CREATE TABLE ap_logs (
  log_id     BIGINT,
  event_time TIMESTAMP,
  level      VARCHAR(32),
  duration_ms INT,
  extra      VARCHAR(1024),
  c3         FLOAT SKIP_INDEX(MIN_MAX, SUM),
  PRIMARY KEY (log_id)
) MERGE_ENGINE = delete_insert
  skip_index_level = 1
  WITH COLUMN GROUP(each column);
```

<main id="notice" type='explain'>
<h4>说明</h4>
<p><ul>
<li><code>WITH COLUMN GROUP(each column)</code>：创建<strong>列存表</strong>；列存基线默认按列生成 MIN_MAX 等 Skip Index，增量在满足表模式与 <code>skip_index_level</code> 时按相同策略生成。</li>
<li><code>MERGE_ENGINE = delete_insert</code>：全列更新，增量可安全生成 Skip Index。</li>
<li><code>skip_index_level = 1</code>：该表的增量 SSTable 将按策略生成 Skip Index（与基线一致）。</li>
<li><code>c3 FLOAT SKIP_INDEX(MIN_MAX, SUM)</code>：该列在 schema 上指定了 Skip Index，会按指定类型生成（MIN_MAX + SUM），并在优先级排序中靠前。</li>
</ul></p>
</main>

### 步骤 3：修改已有表的 Skip Index

若表已存在且为 `DELETE_INSERT` 或 `APPEND_ONLY`，仅需打开增量 Skip Index 时，可执行：

```sql
ALTER TABLE ap_logs SET skip_index_level = 1;
```

<main id="notice" type='explain'>
<h4>说明</h4>
<p>新配置在<strong>下一次转储或 Minor 合并</strong>后对增量数据生效。<code>MERGE_ENGINE</code> <strong>不可</strong>通过 <code>ALTER TABLE</code> 修改。仅当表已为 <code>DELETE_INSERT</code> 或 <code>APPEND_ONLY</code> 时，<code>skip_index_level = 1</code> 才会使增量用户列实际生成 Skip Index；<code>PARTIAL_UPDATE</code> 表不生效。租户级默认值见 <a href="../../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2110.default_skip_index_level.md">default_skip_index_level</a>。</p>
</main>
