# 并行查询执行诊断

随着 AP 业务的拓展，遇到的场景也越来越复杂，为减轻 AP 业务支持调优的负担，OceanBase 数据库在 V4.4.1 版本对执行的诊断工具SQL Plan Monitor 的能力进行了增强，主要包括：增加了诊断指标的丰富度和增强了诊断工具的易用性。

本文将介绍如何使用增强版的诊断能力。

## 确认诊断功能是否开启

1. 检查集群配置项 `enable_sql_audit` 是否开启 SQL 审计功能。

    ```shell
    obclient> SELECT * FROM oceanbase.GV$OB_PARAMETERS WHERE NAME = 'enable_sql_audit';
    ```

    该配置项不支持 Hint，具体介绍信息，参见 [enable_sql_audit](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/300.cluster-level-configuration-items/8600.enable_sql_audit.md)。

2. 检查租户配置项 `_extend_sql_plan_monitor_metrics` 的值是否为 `True`。

    * MySQL 模式：

        ```shell
        obclient> SELECT * FROM oceanbase.GV$OB_PARAMETERS WHERE NAME = '_extend_sql_plan_monitor_metrics';
        ```

    * Oracle 模式：

        ```shell
        obclient> SELECT * FROM sys.GV$OB_PARAMETERS WHERE NAME = '_extend_sql_plan_monitor_metrics';
        ```

    该配置项支持通过 Hint `OPT_PARAM('_extend_sql_plan_monitor_metrics', 'True')` 开启。

3. 确认是否开启 Query 级别的 Monitor 记录, 以下几个条件满足其一即可。

    * 在 SQL 的 Hint 中指定了 monitor。
    * Query 为并行执行，dop > 1。
    * 开启了系统变量 [enable_sql_plan_monitor](../../700.reference/800.configuration-items-and-system-variables/200.system-variable/400.session-system-variable/90.enable_sql_plan_monitor-session.md)。

## 方式一：使用 DBMS_XPROFILE.DISPLAY_PROFILE()

OceanBase 数据库从 V4.4.1 版本开始支持子程序 `DBMS_XPROFILE.DISPLAY_PROFILE()`，使用方法如下：

* sys（系统）租户查询用户租户：

    ```sql
    SELECT DBMS_XPROFILE.DISPLAY_PROFILE('$trace_id', $tenant_id);
    ```

* 用户租户中查询：

  * MySQL 模式：

      ```sql
      SELECT DBMS_XPROFILE.DISPLAY_PROFILE('$trace_id');
      ```

  * Oracle 模式：

      ```sql
      SELECT * FROM TABLE(DBMS_XPROFILE.DISPLAY_PROFILE('$trace_id'));
      ```

`DBMS_XPROFILE.DISPLAY_PROFILE()` 将会以聚合方式展示 SQL Plan Monitor 记录的监控指标，展示的指标将同时包含 V4.4.1 版本之前和 V4.4.1 版本之后的指标。此外，子程序 `DISPLAY_PROFILE` 还支持更详细的参数，具体信息参见 [DISPLAY_PROFILE（MySQL 模式）](../../700.reference/600.pl-reference/200.pl-mysql/1000.pl-system-package-mysql/20750.dbms-xprofile-mysql/200.display-profile-of-mysql-mode.md) 或 [DISPLAY_PROFILE（Oracle 模式）](../../700.reference/600.pl-reference/300.pl-oracle/1400.pl-system-package-oracle/20750.dbms-xprofile-oracle/200.display-profile-of-oracle-mode.md)。

**示例如下：**

```shell
SELECT DBMS_XPROFILE.DISPLAY_PROFILE();
```

## 使用视图 [G]V$SQL_PLAN_MONITOR

视图 `[G]V$SQL_PLAN_MONITOR` 从 V4.4.1 版本开始引入字段 `PROFILE`，用于展示 SQL Plan Monitor 拓展监控指标 profile，将监控指标输出为 Json 格式。关于视图的详细介绍，参见 [GV$SQL_PLAN_MONITOR（MySQL 模式）](../../700.reference/700.system-views/400.system-view-of-mysql-mode/300.performance-view-of-mysql-mode/5200.gv-sql_plan_monitor-of-mysql-mode.md) 或 [GV$SQL_PLAN_MONITOR（Oracle 模式）](../../700.reference/700.system-views/500.system-view-of-oracle-mode/300.performance-view-of-oracle-mode/5000.gv-sql_plan_monitor-of-oracle-mode.md)。

视图使用方法如下：

* MySQL 模式租户/系统租户：

    ```shell
    SELECT plan_line_id, plan_operation, profile
    FROM oceanbase.GV$SQL_PLAN_MONITOR
    WHERE trace_id='$trace_id'
    ORDER BY 1;
    ```

* Oracle 模式租户：

    ```shell
    SELECT plan_line_id, plan_operation, profile 
    FROM sys.GV$SQL_PLAN_MONITOR
    WHERE trace_id='$trace_id'
    ORDER BY 1;
    ```

**示例如下：**

```shell
obclient> SELECT plan_line_id, plan_operation, profile
    FROM oceanbase.GV$SQL_PLAN_MONITOR
    WHERE trace_id='Y27DB7F000001-00063CF09146F834-0-0'
    ORDER BY 1;
```

### 使用限制

使用视图查看方式有以下限制：

* 视图字段 `PROFILE` 无法兼容读取在 V4.4.1 版本之前记录的监控指标，更低版本的指标将不会输出，需要手动查询 SQL Plan Monitor 中的其他列。
* 暂时只支持线程级别的展示，不支持聚合的展示方式。
* 视图字段 `PROFILE` 默认只展示级别 1 及以下的监控指标。
