# 通过全量旁路导入与分区交换实现高效加载

OceanBase 的分区交换功能与旁路导入技术结合，为大规模增量数据加载提供了高效解决方案。通过全量旁路导入快速将数据加载到临时新建的非分区表中，再通过分区交换原子化迁移数据到目标分区表，加快现有分区表增量数据导入的性能。

## 为什么需要分区交换与全量旁路导入结合

在大数据场景下，企业经常面临海量增量数据的快速导入需求。传统的数据导入方式存在性能瓶颈，而分区交换与旁路导入的结合的方案，能兼顾导入效率与查询性能。

### 全量旁路导入与增量旁路导入优势对比

#### 增量旁路导入的特点与限制

* **数据存储格式：** 增量旁路导入的数据会生成转储文件，这些转储文件默认采用行存格式。
* **性能影响：** 在列存场景下，行存格式的转储文件会导致查询性能显著下降。
* **适用场景：** 适合小批量、频繁的数据更新场景。

#### 全量旁路导入的特点与优势

* **数据存储格式：** 全量旁路导入会重写所有数据，生成的数据文件采用列存格式（如果表配置为列存）。
* **性能优势：** 所有数据都是基线数据，查询性能最佳。
* **适用场景：** 适合大批量数据的一次性导入。

### 全量旁路导入与分区交换的优势

通过全量旁路导入结合分区交换技术，可以有效解决增量导入中数据以转储格式存储的性能瓶颈问题。该方案的核心优势在于：

* **数据格式优化：** 将增量数据转换为基线数据格式，确保所有数据均采用列存格式存储，消除行存转储文件对查询性能的负面影响。

* **性能提升：**

  - 查询性能：所有数据统一为基线格式，实现最优查询性能。
  - 导入性能：利用旁路导入的高效机制，显著提升数据加载速度。

* **架构统一性：** 通过分区交换机制，实现增量数据与存量数据的格式统一，避免混合存储格式带来的性能损耗。

这种技术方案既保持了增量导入的灵活性，又获得了全量导入的性能优势，为大规模数据处理场景提供了最佳的性能表现。

### 场景分析

#### 空表初始化

**情况：** 目标表为空，需要导入初始数据。

* **推荐方案：** 直接使用全量旁路导入
* **优势：** 所有数据都是列存基线，查询性能最佳

#### 已有数据的增量导入

**情况：** 目标表已有历史数据，需要导入新的增量数据。

##### 传统增量旁路导入

* **优势：** 导入速度快，对现有数据无影响。
* **劣势：** 新导入的数据为行存转储文件，查询性能差。

##### 传统全量旁路导入

* **优势：** 所有数据重写为列存，查询性能最佳。
* **劣势：** 需要重写全部历史数据，导入时间长，资源消耗大。

#### 全量旁路导入 + 分区交换（推荐方案）

* **优势：**

  - 新增数据通过全量旁路导入生成列存基线，查询性能最佳
  - 只需导入增量数据，不影响历史数据
  - 分区交换操作原子化，零业务中断
  - 导入性能和查询性能双重优化

### 性能对比简易示例

假设客户有一个 1TB 的订单表，每天新增 100GB 数据：

#### 传统增量旁路导入

- 历史数据：1TB（列存，查询快）
- 新增数据：100GB（行存转储，查询慢）
- 查询性能：混合存储格式，整体性能下降

#### 传统全量旁路导入

- 重写数据：1.1TB（全部列存，查询快）
- 导入时间：需要重写 1TB 历史数据 + 100GB 新数据
- 资源消耗：高

#### 全量旁路导入 + 分区交换

- 历史数据：1TB（列存，不变）
- 新增数据：100GB（列存基线，查询快）
- 导入时间：只需导入 100GB 新数据
- 查询性能：全部列存，性能最佳

## 分区交换的基本语法

### 基础分区交换语法

```sql
ALTER TABLE target_partition_table_name
    EXCHANGE PARTITION first_level_partition_name
    WITH TABLE origin_partition_table_name
    WITHOUT VALIDATION;
```

### 包含索引的分区交换语法

```sql
ALTER TABLE target_partition_table_name
    EXCHANGE PARTITION first_level_partition_name
    WITH TABLE origin_partition_table_name
    INCLUDING INDEXES
    WITHOUT VALIDATION;
```

## 使用限制

- `target_partition_table_name` 必须是二级分区表，指定交换的分区必须是该表的某个一级分区名。
- `origin_partition_table_name` 必须是一级分区表，其分区类型必须与用于交换的一级分区下的二级分区完全一致。
- 目标表的一级分区类型必须为 `RANGE (COLUMNS)` 或者 `LIST (COLUMNS)`。
- 一二级分区交换后，相关表的统计信息会失效，需要重新搜集。

## 旁路导入与分区交换示例（基于一级分区）

* **数据快速加载：** 旁路导入技术直接绕过 SQL 和 Memtable，实现海量数据秒级加载。
* **零业务中断：** 分区交换操作在后台原子化完成，对业务查询无锁表影响。
* **分区级数据管理：** 通过分区交换可精确控制数据迁移范围，支持按时间/范围分区的灵活策略。

具体操作步骤如下：

1. 在 **分区表 A** 上创建一个 **空的新分区 P**。
2. 新建一张结构与表 A 完全相同的 **非分区表 B**，并通过全量旁路导入将数据导入至表 B。
3. 利用分区交换功能，将表 A 中的新分区 P 与表 B 进行互换。

### 步骤一：创建目标分区表（订单表 orders）

假设订单表 orders 按 `order_date` 字段进行范围分区，并预留一个空分区 `p_new` 用于数据交换：

```sql
-- 创建分区表 A（示例：订单表）
CREATE TABLE orders (
  order_id BIGINT,
  order_date TIMESTAMP NOT NULL,
  customer_id INT,
  amount DECIMAL(10,2),
  product_id INT
)
PARTITION BY RANGE COLUMNS(order_date) (
  PARTITION p_old1 VALUES LESS THAN ('2023-01-01'),
  PARTITION p_old2 VALUES LESS THAN ('2023-04-01'),
  -- 新增一个空分区 p_new，用于后续数据交换
  PARTITION p_new VALUES LESS THAN ('2023-07-01')
);
```

### 步骤二：准备增量数据并创建非分区表

1. 创建/下载增量数据文件。

   假设增量数据文件为 `orders_increment.csv`，包含以下字段：

   ```
   order_id,order_date,customer_id,amount,product_id
   1001,"2023-05-01",101,199.99,1001
   1002,"2023-06-15",102,299.99,1002
   1003,"2023-05-10",103,350.00,1003
   1004,"2023-05-20",104,49.99,1004
   1005,"2023-06-01",105,450.50,1005
   1006,"2023-05-25",106,200.00,1006
   1007,"2023-06-10",107,150.75,1007
   1008,"2023-05-15",108,300.00,1008
   1009,"2023-06-20",109,499.99,1009
   1010,"2023-05-30",101,99.99,1010
   ```

2. 创建非分区表 `orders_bypass`。

   创建结构与目标分区表（订单表 orders）完全相同的非分区表 `orders_bypass`：

   ```sql
   CREATE TABLE orders_bypass (
     order_id BIGINT,
     order_date TIMESTAMP NOT NULL,
     customer_id INT,
     amount DECIMAL(10,2),
     product_id INT
   );

   -- 建个临时表
   CREATE TABLE temp_staging_table LIKE orders_bypass;
   ```

### 步骤三：旁路导入数据到非分区表 orders_bypass

通过全量旁路导入快速将数据导入非分区表 `orders_bypass`：

```sql
-- 仅示例，实际需配合工具如 OceanBase 的 ObLoader 工具
-- 使用 LOAD DATA 或 INSERT /*+ APPEND */ 导入数据
LOAD DATA /*+ APPEND */ INFILE '/tmp/orders_increment.csv'
INTO TABLE temp_staging_table
FIELDS TERMINATED BY ','
OPTIONALLY ENCLOSED BY '"'
LINES TERMINATED BY '\n'
IGNORE 1 ROWS;

-- 或使用 INSERT 批量导入（需配合 APPEND 提示）
INSERT /*+ APPEND */ INTO orders_bypass
SELECT * FROM temp_staging_table;  -- 临时表需与 orders_bypass 结构一致
```

### 步骤四：执行分区交换（Exchange Partition）

将非分区表 `orders_bypass` 的数据与分区目标分区表（订单表 `orders`）的空分区 `p_new` 进行交换：

```sql
-- 执行分区交换
ALTER TABLE orders
EXCHANGE PARTITION p_new
WITH TABLE orders_bypass
WITHOUT VALIDATION;  -- 可选：若表 B 包含索引，需同步交换
```

### 步骤五：验证数据交换结果

```sql
-- 验证分区 p_new 的数据
SELECT COUNT(*) FROM orders PARTITION (p_new);

-- 验证表 orders_bypass 是否为空（已交换后表 orders_bypass 数据会被清空）
SELECT COUNT(*) FROM orders_bypass;
```

返回结果示例：

```shell
MySQL [test_db]> SELECT COUNT(*) FROM orders PARTITION (p_new);
+----------+
| COUNT(*) |
+----------+
|       10 |
+----------+
1 row in set (0.04 sec)

MySQL [test_db]> SELECT COUNT(*) FROM orders_bypass;
+----------+
| COUNT(*) |
+----------+
|        0 |
+----------+
1 row in set (0.01 sec)
```

### 步骤六：清理数据与后续操作

```sql
-- 可选：删除空表 orders_bypass
DROP TABLE orders_bypass;

-- 可选：重命名分区 p_new 为更明确的名称
ALTER TABLE orders RENAME PARTITION p_new TO p_2023q2;
```

## 旁路导入与分区交换示例（基于二级分区）

* **数据快速加载：** 旁路导入技术直接绕过 SQL 和 Memtable，实现海量数据秒级加载。
* **零业务中断：** 分区交换操作在后台原子化完成，对业务查询无锁表影响。
* **分区级数据管理：** 通过分区交换可精确控制数据迁移范围，支持按时间/范围分区的灵活策略。
* **二级分区表增量数据导入：** 适用于一级分区为 range/list、二级分区为 hash 的复合分区表场景。

具体操作步骤如下：

1. 在二级分区表 A（一级 range/list + 二级 hash）上创建一个空的新一级分区 P。
2. 新建一张一级 hash 分区表 B，其分区类型必须与表 A 的二级分区完全一致，并通过全量旁路导入将数据导入至表 B。
3. 利用分区交换功能，将表 A 中的新一级分区 P 与表 B 进行互换。

### 步骤一：创建目标二级分区表（订单表 orders）

假设订单表 `orders` 按 `order_date` 字段进行一级范围分区，二级按 `order_id` 进行 hash 分区，并预留一个空分区 `p_new` 用于数据交换：

```sql
-- 创建二级分区表 A（示例：订单表）
CREATE TABLE orders (
  order_id BIGINT,
  order_date TIMESTAMP NOT NULL,
  customer_id INT,
  amount DECIMAL(10,2),
  product_id INT,
  PRIMARY KEY (order_id, order_date)
)
PARTITION BY RANGE COLUMNS(order_date)
SUBPARTITION BY HASH(order_id) SUBPARTITIONS 5
(
  PARTITION p_old1 VALUES LESS THAN ('2023-01-01'),
  PARTITION p_old2 VALUES LESS THAN ('2023-04-01'),
  -- 新增一个空分区 p_new，用于后续数据交换
  PARTITION p_new VALUES LESS THAN ('2023-07-01')
);
```

### 步骤二：准备增量数据并创建一级 hash 分区表

1. 创建/下载增量数据文件。

   假设增量数据文件为 `orders_increment.csv`，包含以下字段：

   ```
   order_id,order_date,customer_id,amount,product_id
   1001,"2023-05-01",101,199.99,1001
   1002,"2023-06-15",102,299.99,1002
   1003,"2023-05-10",103,350.00,1003
   1004,"2023-05-20",104,49.99,1004
   1005,"2023-06-01",105,450.50,1005
   1006,"2023-05-25",106,200.00,1006
   1007,"2023-06-10",107,150.75,1007
   1008,"2023-05-15",108,300.00,1008
   1009,"2023-06-20",109,499.99,1009
   1010,"2023-05-30",101,99.99,1010
   ```

2. 创建一级 hash 分区表 `orders_bypass`。

   创建结构与目标二级分区表（订单表 `orders`）相同的一级 hash 分区表 `orders_bypass`。分区类型必须与目标表的二级分区完全一致（即 hash 分区）。

   ```sql
   -- 创建一级 hash 分区表 B，分区数量必须与目标表的二级分区数量一致（5个）
   CREATE TABLE orders_bypass (
     order_id BIGINT,
     order_date TIMESTAMP NOT NULL,
     customer_id INT,
     amount DECIMAL(10,2),
     product_id INT,
     PRIMARY KEY (order_id, order_date)
   )
   PARTITION BY HASH(order_id) PARTITIONS 5;
   ```

<main id="notice" type='explain'>
  <h4>注意</h4>
  <p>一级 hash 分区表 <code>orders_bypass</code> 的分区类型必须与目标二级分区表 <code>orders</code> 的二级分区完全一致。即如果目标表的二级分区是 <code>SUBPARTITION BY HASH(order_id)</code>，则源表必须是 <code>PARTITION BY HASH(order_id)</code>。</p>
</main>

### 步骤三：旁路导入数据到一级 hash 分区表 orders_bypass

通过全量旁路导入快速将数据导入一级 hash 分区表 `orders_bypass`：

```sql
-- 创建临时表用于数据加载
CREATE TABLE temp_staging_table LIKE orders_bypass;

-- 使用 LOAD DATA 进行旁路导入
LOAD DATA /*+ APPEND */ INFILE '/tmp/orders_increment.csv'
INTO TABLE temp_staging_table
FIELDS TERMINATED BY ','
OPTIONALLY ENCLOSED BY '"'
LINES TERMINATED BY '\n'
IGNORE 1 ROWS;

-- 使用 INSERT 批量导入（配合 APPEND 提示实现旁路导入）
INSERT /*+ APPEND */ INTO orders_bypass
SELECT * FROM temp_staging_table;

-- 清理临时表
DROP TABLE temp_staging_table;
```

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>实际使用中，你也可以配合 OceanBase 的 ObLoader 等工具进行旁路导入，以实现更高效的数据加载。</p>
</main>

### 步骤四：执行分区交换（Exchange Partition）

将一级 hash 分区表 `orders_bypass` 的数据与目标二级分区表（订单表 orders）的空一级分区 `p_new` 进行交换：

```sql
-- 执行分区交换
ALTER TABLE orders
EXCHANGE PARTITION p_new
WITH TABLE orders_bypass
WITHOUT VALIDATION;
```

<main id="notice" type='explain'>
  <h4>注意</h4>
  <p>分区交换成功后，表 <code>orders_bypass</code> 中的数据会被清空，原数据已交换到目标分区 <code>p_new</code> 中。如果源表包含索引，可以使用 <code>INCLUDING INDEXES</code> 选项同步交换索引。</p>
</main>

### 步骤五：验证数据交换结果

验证分区交换是否成功：

```sql
-- 验证分区 p_new 的数据
SELECT COUNT(*) FROM orders PARTITION (p_new);

-- 验证表 orders_bypass 是否为空（已交换后表 orders_bypass 数据会被清空）
SELECT COUNT(*) FROM orders_bypass;
```

验证结果示例：

```shell
MySQL [test_db]> SELECT COUNT(*) FROM orders PARTITION (p_new);
+----------+
| COUNT(*) |
+----------+
|       10 |
+----------+
1 row in set

MySQL [test_db]> SELECT COUNT(*) FROM orders_bypass;
+----------+
| COUNT(*) |
+----------+
|        0 |
+----------+
1 row in set
```

### 步骤六：清理数据与后续操作

完成数据交换后，可以进行以下清理和后续操作：

```sql
-- 可选：删除空表 orders_bypass（如果不再需要）
DROP TABLE orders_bypass;

-- 可选：重命名分区 p_new 为更明确的名称
ALTER TABLE orders RENAME PARTITION p_new TO p_2023q2;

-- 重新搜集统计信息（交换后统计信息会失效）
ANALYZE TABLE orders;
```

### 不支持的使用场景

以下场景不支持分区交换：
- 一级分区表与一级分区表交换：不支持。
- 二级分区表与二级分区表交换：不支持。
- 二级分区表的一级分区为 hash 分区：不支持。目标表的一级分区必须是 range 或 list 类型。
