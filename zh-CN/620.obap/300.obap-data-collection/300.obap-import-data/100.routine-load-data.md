# 使用 Routine Load 从 Kafka 导入数据

## 概述

Routine Load 是 OceanBase 自 **V4.6.0** 起提供的、从 Kafka 持续导入数据的能力。通过执行 `CREATE ROUTINE LOAD` 创建作业后，系统会按调度周期自动从 Kafka 拉取消息并写入目标表，无需用户反复执行导入命令，适用于导入实时数据场景。

**执行机制简述**：Routine Load 基于 OceanBase 的 **DBMS Scheduler** 定时任务机制。创建作业时，系统会在调度器内注册定时任务；任务按系统配置的频率触发，自动完成“连接 Kafka → 消费消息 → 解析与转换 → 写入目标表 → 更新消费位点”的流程。因此，Routine Load 是“声明式配置、后台自动执行”的导入方式，用户只需创建、暂停、恢复或停止作业，无需手写 DML。

本文介绍如何使用 OceanBase 的 Routine Load 功能，持续从 Apache Kafka 集群消费数据并导入到指定的 OceanBase 表中，实现准实时数据同步。

## 前提条件

使用 Routine Load 前，请确认：

* OceanBase 数据库版本 **≥ V4.6.0**。
* **目标表已创建**，且当前用户对目标表具备 **INSERT** 权限。
* **Kafka 集群网络可达**，且能提供有效的 Broker 地址（`bootstrap.servers`）。
* **Kafka Topic 已存在**，且当前账号具备该 Topic 的消费权限；若 Kafka 开启了 SASL/SSL 等认证，需在作业参数中配置相应安全项。
* Kafka 消息内容为 **CSV 格式**，且与目标表列结构（列数、类型、顺序等）匹配或可通过 `COLUMNS` 映射。

<main id="notice" type='explain'>
  <h4>说明</h4>
  <p>Routine Load 适用于持续、稳定的 Kafka 数据流接入。若为一次性大批量数据导入，建议使用 `LOAD DATA` 或旁路导入功能。</p>
</main>

## 使用限制

| 项目 | 说明 |
| ---- | ---- |
| 数据源 | 仅支持 **Apache Kafka** 作为数据源。 |
| 数据格式 | 仅支持 **CSV** 格式。 |
| bootstrap.servers | 仅能配置**一个** Kafka 集群的 Broker 列表，不可混用多个集群地址，否则行为未定义。 |
| 消费位点（offset） | `kafka_offsets` 不能小于 Kafka 服务端当前分区的 **low watermark**；不建议大于 **high watermark**，否则行为由 Kafka 服务端参数 `auto.offset.reset` 决定。 |
| 目标表与权限 | 目标表必须已存在；若表不存在或权限不足，作业会进入错误状态，需停止后修正再重新创建作业。 |

## 创建 Routine Load 作业

### 语法

```sql
CREATE ROUTINE LOAD job_name ON table_name
[LOAD PROPERTIES (load_property_list)]
FROM STREAM '(' job_properties_expr ')';
```

* `job_name`：作业名称，在当前租户内唯一，用于标识该 Routine Load 作业。
* `table_name`：目标表名，数据将导入到该表。
* `LOAD PROPERTIES`：可选，数据加载属性（并发度、列映射、分区、冲突策略、过滤条件等）。
* `FROM STREAM`：数据源类型，当前仅支持 Kafka；`job_properties_expr` 为 Kafka 及格式相关配置。

### LOAD PROPERTIES（可选）

| 参数 | 说明 | 默认值 |
| ---- | ---- | ------ |
| `PARALLEL = n` | 并发度，即参与消费的线程数 | `1` |
| `COLUMNS (col1, col2, ...)` | Kafka 消息列与目标表列的映射关系 | 按消息顺序与表列顺序一一对应 |
| `PARTITION (p1, p2, ...)` | 指定导入的目标分区 | 不指定则按路由规则写入 |
| `IGNORE` / `REPLACE` | 主键或唯一键冲突时的处理：忽略冲突行 / 覆盖冲突行 | 由业务选择 |
| `WHERE condition` | 行级过滤条件，仅满足条件的行会写入目标表 | 无 |

### FROM STREAM：Kafka 与格式配置（job_properties_expr）

`job_properties_expr` 为键值对形式，**键名大小写敏感**。除格式配置外，支持 Kafka 标准消费者相关参数（如 `security.protocol`、`sasl.mechanism` 等）。**无需**配置 `group.id`，系统会按并发度自动建立消费线程与分区的对应关系。

#### 必填与常用 Kafka 参数

| 参数（键名） | 说明 | 必填 | 默认值 / 说明 |
| ------------ | ---- | ---- | -------------- |
| `bootstrap.servers` | Kafka Broker 地址列表，多个用逗号分隔，如 `broker1:9092,broker2:9092`。表示客户端首次连接 Kafka 的入口地址。 | 是 | — |
| `kafka_topic` | 要消费的 Kafka Topic 名称。 | 是 | — |
| `kafka_partitions` | 要消费的分区列表，如 `"0,1,2"`。不提供则消费该 Topic 下全部分区。 | 否 | 全部分区 |
| `kafka_offsets` | 各分区起始消费位点，与 `kafka_partitions` 一一对应；若只写一个值则对所有分区生效。支持数字或 `OFFSET_BEGINNING`、`OFFSET_END`。 | 否 | `OFFSET_END`（从最新消息开始） |
| `max_batch_interval` | 每轮每个导入线程的**最大运行时间**，单位秒。 | 否 | `60` |
| `max_batch_rows` | 每轮每个导入线程**最多读取的消息条数**。须 **≥ 200000**。 | 否 | `10000000` |
| `max_batch_size` | 每轮每个导入线程**最多读取的字节数**，单位字节，范围 100MB～1GB。 | 否 | `1073741824`（1GB） |

**名词说明**：

* **offset（消费位点）**：Kafka 分区中每条消息的逻辑位置。`OFFSET_BEGINNING` 表示从分区最早可读消息开始，`OFFSET_END` 表示从当前最新位置开始。
* **low / high watermark**：Kafka 分区中当前可消费的最小、最大 offset；指定 offset 不能低于 low watermark。

#### FORMAT（CSV 解析选项）

当前仅支持 **CSV** 格式，语法与 OceanBase 现有 CSV 解析能力对齐，可参考 [LOAD DATA（MySQL 模式）](../../../../700.reference/500.sql-reference/100.sql-syntax/200.common-tenant-of-mysql-mode/600.sql-statement-of-mysql-mode/5900.load-data-of-mysql-mode.md) 中的格式说明。常用选项如下：

| 选项 | 说明 | 默认值 |
| ---- | ---- | ------ |
| `LINE_DELIMITER` | 行分隔符 | `'\n'` |
| `FIELD_DELIMITER` | 列分隔符 | `'\t'` |
| `ESCAPE` | 转义符，单字节 | `'\'` |
| `FIELD_OPTIONALLY_ENCLOSED_BY` | 包裹字段值的符号（如双引号），多用于 CHAR/VARCHAR/TEXT/JSON 等 | 空 |
| `ENCODING` | 字符集编码 | `UTF8MB4` |
| `NULL_IF` | 视为 NULL 的字符串 | 空 |
| `TRIM_SPACE` | 是否去掉字段首尾空格 | `FALSE` |
| `SKIP_BLANK_LINES` | 是否跳过空白行 | `FALSE` |
| `EMPTY_FIELD_AS_NULL` | 是否将空字符串当作 NULL | `FALSE` |

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>Routine Load 的 CSV 解析不支持 <code>PARSE_HEADER</code>、<code>SKIP_HEADER</code>。即不能将第一行当作列名或跳过文件头行。</p>
</main>

## 管理 Routine Load 作业

| 操作 | 语法 | 说明 |
| ---- | ---- | ---- |
| 暂停 | `PAUSE ROUTINE LOAD FOR job_name;` | 暂停消费，保留作业配置与当前 offset，后续可恢复。 |
| 恢复 | `RESUME ROUTINE LOAD FOR job_name;` | 从暂停时的 offset 继续消费。 |
| 停止 | `STOP ROUTINE LOAD FOR job_name;` | 终止作业。 |

## 执行机制说明

### 后台调度与数据流

* 创建 Routine Load 作业时，系统在 **DBMS Scheduler** 管理的内部表中创建定时任务，执行频率由系统配置决定（默认不间断执行）。
* 每次触发时，系统会自动完成：解析 Kafka 配置 → 连接 Kafka → 按分区与 offset 消费消息 → 按 CSV 规则解析并转换为表行 → 写入目标表 → 更新消费进度（offset）。

更多关于定时任务机制的说明，可参见 [DBMS Scheduler 概述](../../../../700.reference/600.pl-reference/300.pl-oracle/1400.pl-system-package-oracle/14200.dbms-scheduler-oracle/100.dbms-scheduler-overview-oracle.md)（Oracle 模式）。

### 错误与重试

* **目标表不存在或权限不足**：作业会进入错误状态（如 CANCELLED），需用户修正后使用 `STOP ROUTINE LOAD` 停止该作业，再重新创建。
* 失败或需下线时，可通过 **STOP ROUTINE LOAD** 结束作业。

## 查看作业状态

可通过以下系统视图查看 Routine Load 作业的基本信息、状态及消费进度：

| 视图 | 适用场景 |
| ---- | -------- |
| `DBA_OB_ROUTINE_LOAD_JOBS` | 当前普通租户下查看本租户的 Routine Load 作业。 |
| `CDB_OB_ROUTINE_LOAD_JOBS` | 系统租户下查看所有租户的 Routine Load 作业。 |

### 作业状态含义

| 状态 | 含义 |
| ---- | ---- |
| RUNNING | 作业正常运行，正在消费 Kafka 并写入目标表。 |
| PAUSED | 作业已暂停，不再消费数据。 |
| STOPPED | 作业已正常停止，且不可恢复。 |
| CANCELLED | 作业因错误被取消。 |

## 使用示例

### 示例 1：基础 CSV 导入

目标表已存在，Kafka Topic 中为 CSV 格式消息，列与表列顺序一致。

```sql
-- 创建目标表
CREATE TABLE user_behavior (
  user_id INT PRIMARY KEY,
  action VARCHAR(50),
  timestamp TIMESTAMP
);

-- 创建 routine load 作业
CREATE ROUTINE LOAD user_behavior_load ON user_behavior
FROM STREAM (
  "bootstrap.servers" = "127.0.0.1:9092",
  "kafka_topic" = "test-topic",
  "kafka_partitions" = "0",
  "kafka_offsets" = "0",
  FORMAT = (TYPE = 'CSV', FIELD_DELIMITER = ',')
);
```

### 示例 2：带认证、过滤与并发

使用 SASL 认证，仅导入 `amount > 100` 的行，并提高并发与单批行数。

```sql
-- 创建目标表
CREATE TABLE sales_data (
  order_id BIGINT PRIMARY KEY,
  product_id INT,
  amount DECIMAL(10,2),
  order_time TIMESTAMP
);

-- 创建 routine load 作业，带 SASL 认证和过滤条件
CREATE ROUTINE LOAD sales_load ON sales_data
  PARALLEL = 3,
  WHERE amount > 100
)
FROM STREAM (
  "bootstrap.servers" = "127.0.0.1:9092",
  "kafka_topic" = "test-topic",
  "kafka_partitions" = "0,1,2",
  "kafka_offsets" = "0,0,OFFSET_BEGINNING",
  "max_batch_interval" = "60",
  "max_batch_rows" = "2000000",
  "max_batch_size" = "1000000000",
  "security.protocol" = "sasl_plaintext",
  "sasl.mechanism" = "PLAIN",
  "sasl.username" = "consumer1",
  "sasl.password" = "consumer1-password",
  FORMAT = (TYPE = 'CSV', FIELD_DELIMITER = ',', TRIM_SPACE = TRUE)
);
```

### 示例 3：完整操作

以下按操作顺序演示：创建作业、查看作业状态、暂停作业、再次查看状态确认已暂停、恢复作业。假设目标表 `user_behavior` 与 Kafka Topic 已就绪。

**步骤 1：创建 Routine Load 作业**

```sql
CREATE ROUTINE LOAD my_kafka_load ON user_behavior
FROM STREAM (
  "bootstrap.servers" = "127.0.0.1:9092",
  "kafka_topic" = "user-events",
  "kafka_partitions" = "0",
  "kafka_offsets" = "0",
  FORMAT = (TYPE = 'CSV', FIELD_DELIMITER = ',')
);
```

**步骤 2：查看作业状态**

创建后可查询系统视图确认作业已存在且处于运行中；可通过 **`progress`** 字段查看各分区的消费进度（如 offset 等）：

```sql
SELECT job_id, job_name, table_name, state, progress, create_time
FROM DBA_OB_ROUTINE_LOAD_JOBS
WHERE job_name = 'my_kafka_load';
```

示例结果：`state` 为 `RUNNING` 表示作业正在消费 Kafka 并写入目标表；`progress` 表示当前各分区的消费位点，便于监控同步进度。

**步骤 3：暂停作业**

需要临时停止消费（如维护、限流）时执行暂停，作业配置与当前消费位点会保留：

```sql
PAUSE ROUTINE LOAD FOR my_kafka_load;
```

**步骤 4：再次查看作业状态**

确认作业已暂停：

```sql
SELECT job_id, job_name, table_name, state
FROM DBA_OB_ROUTINE_LOAD_JOBS
WHERE job_name = 'my_kafka_load';
```

此时 `state` 应为 `PAUSED`，作业不再拉取新数据。

**步骤 5：恢复作业**

从暂停时的 offset 继续消费：

```sql
RESUME ROUTINE LOAD FOR my_kafka_load;
```

恢复后可再次执行步骤 2 的查询，`state` 将恢复为 `RUNNING`。若需彻底结束作业并删除配置，使用 `STOP ROUTINE LOAD FOR my_kafka_load;`（不可恢复）。
