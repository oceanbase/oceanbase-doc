# Routine Load 导入

## 概述

Routine Load 是 OceanBase 数据库于 V4.6.0 版本提供的**声明式持续数据导入能力**，支持从 Apache Kafka 集群自动、准实时地将数据同步至 OceanBase 表。用户仅需通过 DDL 语句配置数据源与目标表，系统即在后台持续消费 Kafka 消息并完成数据写入，无需额外开发消费程序或维护外部调度任务，显著降低实时数据接入的运维复杂度。

该功能基于 OceanBase 内置的 DBMS Scheduler 定时任务机制实现，具备断点续传、错误重试、资源隔离、状态监控等企业级特性，适用于日志采集、实时数仓构建、业务数据同步等流式数据处理场景。

## 功能特性

- **声明式配置**：通过 `CREATE ROUTINE LOAD` 语句定义作业，系统自动调度执行
- **准实时同步**：按配置间隔（默认每分钟）持续拉取 Kafka 数据，延迟可控
- **断点续传**：自动记录并更新 Kafka 消费位点（offset），支持暂停/恢复无缝衔接
- **数据处理能力**：
  - 支持 CSV 格式解析（自定义分隔符、转义符、空值处理等）
  - 支持列映射、数据过滤（`WHERE`）、冲突处理（`IGNORE`/`REPLACE`）
  - 支持 SASL/SSL 等 Kafka 安全认证机制
- **资源管控**：通过 `PARALLEL`、`max_batch_*` 等参数灵活控制并发与单次消费量
- **全生命周期管理**：提供 `PAUSE`、`RESUME`、`STOP` 命令及系统视图监控作业状态
- **高可靠保障**：Kafka 连接失败自动重试，异常状态可查可溯

## 前提条件

1. OceanBase 数据库版本 ≥ 4.5.1
2. 目标表已创建，且当前用户具备 `INSERT` 权限
3. Kafka 集群网络可达，且提供有效的 `bootstrap.servers` 地址
4. Kafka Topic 已存在，且具备消费权限（如需认证，需配置对应安全参数）

## 使用限制

| 项目 | 说明 |
|------|------|
| **数据源** | 仅支持 Apache Kafka（当前不支持 Pulsar、RocketMQ 等） |
| **数据格式** | 仅支持 CSV 格式（JSON、Avro 等格式暂不支持） |
| **CSV 限制** | 不支持 `PARSE_HEADER` 与 `SKIP_HEADER` 参数 |
| **认证方式** | 支持 SASL_PLAINTEXT、SASL_SSL 等，需 Kafka 集群开启对应认证 |
| **偏移量约束** | `kafka_offsets` 不能小于 Kafka 服务端 low watermark；不建议大于 high watermark（行为由 Kafka `auto.offset.reset` 控制） |
| **集群限制** | `bootstrap.servers` 仅支持单 Kafka 集群，不可混用多集群地址 |

## 创建 Routine Load 作业

### 语法

```sql
CREATE ROUTINE LOAD job_name ON table_name
[LOAD PROPERTIES (load_property_list)]
FROM STREAM '(' job_properties_expr ')';
```

### 参数说明

#### 作业基础参数

- `job_name`：作业唯一标识名（同一租户内不可重复）
- `table_name`：目标表名（需提前创建）

#### LOAD PROPERTIES（可选）

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `PARALLEL = n` | 消费并发线程数 | `1` |
| `COLUMNS (col1, col2, ...)` | 指定 Kafka 消息列与目标表列的映射关系 | — |
| `PARTITION (p1, p2, ...)` | 指定导入的目标分区 | — |
| `IGNORE \| REPLACE` | 主键冲突处理策略 | — |
| `WHERE condition` | 数据过滤条件 | — |

#### Kafka 配置参数（`job_properties_expr`）

| 参数 | 说明 | 必填 |
|------|------|------|
| `bootstrap.servers` | Kafka Broker 地址列表（逗号分隔） | 是 |
| `kafka_topic` | 消费的 Topic 名称 | 是 |
| `kafka_partitions` | 指定消费的分区（如 `"0,1,2"`） | 否（默认全部） |
| `kafka_offsets` | 对应分区的起始 offset（支持数字、`OFFSET_BEGINNING`、`OFFSET_END`） | 否（默认 `OFFSET_END`） |
| `max_batch_interval` | 单线程单次最大运行时间（秒） | `60` |
| `max_batch_rows` | 单线程单次最大消息数（≥200000） | `10000000` |
| `max_batch_size` | 单线程单次最大字节数（100MB ~ 1GB） | `1073741824` (1GB) |
| `security.protocol` 等 | librdkafka 标准消费者参数（如 SASL 认证配置） | 按需 |

> **注意**：  
> - Kafka 配置参数名大小写敏感  
> - 系统自动分配 `group.id`，用户无需配置  
> - 不支持跨 Kafka 集群混用 `bootstrap.servers`

#### FORMAT 配置（CSV 格式）

```sql
FORMAT = (
  TYPE = 'CSV',
  FIELD_DELIMITER = ',',
  LINE_DELIMITER = '\n',
  TRIM_SPACE = TRUE,
  ESCAPE = '\',
  FIELD_OPTIONALLY_ENCLOSED_BY = '"',
  ENCODING = 'UTF8MB4',
  NULL_IF = '',
  EMPTY_FIELD_AS_NULL = FALSE,
  SKIP_BLANK_LINES = FALSE
)
```
> **说明**：`PARSE_HEADER` 与 `SKIP_HEADER` 当前不支持。

## 管理 Routine Load 作业

| 操作 | 语法 | 说明 |
|------|------|------|
| **暂停作业** | `PAUSE ROUTINE LOAD FOR job_name;` | 停止消费，保留配置与当前 offset |
| **恢复作业** | `RESUME ROUTINE LOAD FOR job_name;` | 从暂停时的 offset 继续消费 |
| **停止作业** | `STOP ROUTINE LOAD FOR job_name;` | 终止作业并删除配置（不可恢复） |

## 查看作业状态

通过以下系统视图监控作业运行情况：

| 视图 | 适用场景 |
|------|----------|
| `DBA_OB_ROUTINE_LOAD_JOB` | 当前普通租户下的作业状态 |
| `CDB_OB_ROUTINE_LOAD_JOB` | 系统租户下查看所有租户的作业状态 |

### 作业状态说明

| 状态 | 含义 |
|------|------|
| `RUNNING` | 作业正常运行中 |
| `PAUSED` | 作业已暂停，未消费数据 |
| `STOPPED` | 作业已正常停止 |
| `CANCELLED` | 作业因错误被取消 |

## 使用示例

### 示例 1：基础 CSV 数据导入
```sql
-- 创建目标表
CREATE TABLE user_behavior (
  user_id INT PRIMARY KEY,
  action VARCHAR(50),
  event_time TIMESTAMP
);

-- 创建 Routine Load 作业
CREATE ROUTINE LOAD user_behavior_load ON user_behavior
FROM STREAM (
  "bootstrap.servers" = "192.168.1.10:9092",
  "kafka_topic" = "user_events",
  "kafka_partitions" = "0",
  "kafka_offsets" = "OFFSET_BEGINNING",
  FORMAT = (TYPE = 'CSV', FIELD_DELIMITER = ',', TRIM_SPACE = TRUE)
);
```

### 示例 2：带认证、过滤与并发控制
```sql
CREATE ROUTINE LOAD sales_load ON sales_data
  PARALLEL = 3,
  WHERE amount > 100
FROM STREAM (
  "bootstrap.servers" = "kafka-cluster:9092",
  "kafka_topic" = "sales_topic",
  "kafka_partitions" = "0,1,2",
  "kafka_offsets" = "0,0,OFFSET_BEGINNING",
  "max_batch_rows" = "2000000",
  "security.protocol" = "sasl_plaintext",
  "sasl.mechanism" = "PLAIN",
  "sasl.username" = "consumer_user",
  "sasl.password" = "secure_password",
  FORMAT = (TYPE = 'CSV', FIELD_DELIMITER = ',', ENCODING = 'UTF8MB4')
);
```
