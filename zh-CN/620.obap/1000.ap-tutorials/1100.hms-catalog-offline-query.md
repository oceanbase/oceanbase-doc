# OceanBase 通过 HMS Catalog 离线查询加速

## 适用场景

- **典型场景**
  + **实时报表**：结合 OceanBase 实时交易数据 + 离线宽表。  
  + **跨系统联合分析**：用户行为日志（Hive/Iceberg） + 用户画像数据（OceanBase）。
- **核心价值**  
  + **无需数据迁移**，避免冗余存储与同步延迟。  
  + **统一 SQL 引擎**，降低开发复杂度。  
  + **按需读取**，节省计算与 I/O 成本。

## 原理简介

OceanBase 从 V4.4.1 版本开始正式支持 HMS Catalog 功能。本文档为便于用户提前了解和规划 OceanBase 数据库的 AP 能力，已在 V4.3.5 文档集中提供相关使用说明。

其核心原理如下：

### Catalog 机制

- Catalog（数据目录） 是元数据的逻辑容器，每个 Catalog 对应一个外部数据源（如 MaxCompute 项目、Hive Metastore）。  
- OceanBase 内置 internal Catalog 管理本地表。

### 联邦查询（Federated Query）

- 查询引擎识别跨 Catalog 表引用（如 `hms_prod.project.table`）；  
- 元数据获取：通过 Catalog 从 HMS 获取表结构；  
- 数据读取：根据表的 Location 指向的底层存储类型，采用对应的访问协议与认证方式。  
  + 若为 HDFS，支持 Kerberos 认证；  
  + 若为 OSS 或兼容 S3 协议的对象存储，则通过兼容的文件系统实现（如 S3A、OSS-HDFS）访问，使用 AccessKey / SecretKey（AK/SK）进行签名认证。

## 本教程目标

- 掌握 OceanBase 在 AP 场景中通过 Catalog 实现 免 ETL 联邦查询 的核心能力  
- 熟练使用 HMS Catalog 访问 Hive / Iceberg 数据  

## 环境要求

- OceanBase 版本 ≥ V4.4.1（支持 HMS Catalog）  
- 网络连通性：  
  + HMS：OceanBase 节点可访问 Hive Metastore 及 HDFS/S3/OSS  
- 权限准备：  
  + Hive：HMS 读权限 + HDFS 文件读权限（通过 Location 配置）。详细信息，参见 [通过 Catalog 加载 Hive 表](../400.data-lake/200.data-lake-integration/100.hive/100.load-hive-via-catalog.md)。

## HMS Catalog 接入 Hive / Iceberg 表实验步骤

### 前提条件

在开始前，请确保以下环境已就绪：

| 条件 | 说明 |
|------|------|
| Hive Metastore (HMS) 正常运行 | 提供元数据服务，URI 格式如 `thrift://host:port` |
| 底层存储可访问 | HDFS / OSS / S3 等存储系统已配置，且 OBServer 节点有读权限 |
| 网络连通性 | OBServer 能访问 HMS（默认端口 9083 或自定义端口）及底层存储 |
| OceanBase 已部署并启用 Java 支持（**可选**） | 如果您有访问 HDFS 的需求，则需提前部署 [部署 OceanBase 数据库 JAVA SDK 环境](../../400.deploy/300.deploy-oceanbase-enterprise-edition/500.deploy-the-ob-java-sdk-environment.md) |

<main id="notice" type='notice'>
  <h4>说明</h4>
  <p>若 HMS 启用 Kerberos 认证，需额外提供 <code>KERBEROS_PRINCIPAL</code> 和 <code>KEYTAB</code> 参数。</p>
</main>

假设 HMS Catalog 中的数据目录名称为 hive_meta，hive_meta catalog 里的 test_database 数据库内有名为 test_table 的表，表数据如下:

```shell
+------------+--------+---------+--------+------------+
| product_id | amount | country | region | event_date |
+------------+--------+---------+--------+------------+
|       1001 |   2500 | CN      | East   | 2023-10-01 |
|       1003 |   1800 | JP      | Kanto  | 2023-10-03 |
|       1002 |   3500 | US      | West   | 2023-10-02 |
+------------+--------+---------+--------+------------+
```

这里展示 HMS Catalog 中的表结构，是为了使后续步骤中的验证结果更加清晰。如果实际应用场景中，您不清楚表结构，请通过 `SHOW CREATE TABLE ${catalog_name}.${hive_db_name}.${table_name};` 查看建表语句。

### 步骤 1：在 OceanBase 中创建 HMS Catalog

```sql
-- 创建外部 Catalog
CREATE EXTERNAL CATALOG hive_meta
PROPERTIES (
  TYPE = 'HMS',
  URI = 'thrift://xx.xx.xx.xx:9083'   -- 请根据您的真实配置填写 URI
);

-- 验证创建成功
SHOW CATALOGS;
```

若 HMS 有 Kerberos 认证，需额外配置 `KERBEROS_PRINCIPAL` 和 `KEYTAB`。

展示结果如下：

```
+-----------+
| Catalog   |
+-----------+
| hive_meta |
| internal  |
+-----------+
```

### 步骤 2：在 OceanBase internal catalog 中准备实时订单表

此步骤在 OceanBase **内部 Catalog** 中执行。

**创建数据库和表**

```sql
-- 切回 internal catalog（默认）
SET CATALOG internal;

-- 创建新库（可选，也可以直接用现有库）
CREATE DATABASE IF NOT EXISTS federated_demo;
USE federated_demo;

-- 创建内部表
CREATE TABLE test_table_internal (
    product_id INT,
    amount     DOUBLE,
    country    VARCHAR(10),
    region     VARCHAR(20),
    event_date DATE
);
```

**插入测试数据**

```sql
INSERT INTO test_table_internal VALUES
(1004, 4200, 'DE', 'Berlin', '2023-10-04'),
(1005, 1900, 'FR', 'Paris',  '2023-10-05'),
(1001, 3000, 'CN', 'South',  '2023-10-06');  -- 与 Hive 表有重复 product_id

-- 验证
SELECT * FROM test_table_internal;
```

在 OceanBase 中执行下面的 SQL 验证数据：
```sql
-- 查询 internal 表
SELECT * FROM sales_data_internal;
-- 输出：

```

```sql
-- 在 OceanBase 执行下面的语句查询当前配置的 HMS Catalog下的表（确认可正常访问）
```

### 步骤 3：联邦查询（联合 internal + Hive）

#### 场景 1：合并所有销售数据

```sql
SELECT
    product_id,
    amount,
    country,
    region,
    event_date,
    'internal' AS data_source
FROM federated_demo.test_table_internal

UNION ALL

SELECT
    product_id,
    amount,
    country,
    region,
    STR_TO_DATE(event_date, '%Y-%m-%d') AS event_date,  -- Hive 的 event_date 是 string，转为 DATE
    'hive' AS data_source
FROM hive_meta.test_database.test_table

ORDER BY event_date;
```

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>Hive 表的 event_date 是 string 类型，需用 STR_TO_DATE() 转为 DATE 以保证类型一致。</p>
</main>

```shell
+------------+--------+---------+--------+------------+-------------+
| product_id | amount | country | region | event_date | data_source |
+------------+--------+---------+--------+------------+-------------+
|       1001 |   2500 | CN      | East   | 2023-10-01 | hive        |
|       1002 |   3500 | US      | West   | 2023-10-02 | hive        |
|       1003 |   1800 | JP      | Kanto  | 2023-10-03 | hive        |
|       1004 |   4200 | DE      | Berlin | 2023-10-04 | internal    |
|       1005 |   1900 | FR      | Paris  | 2023-10-05 | internal    |
|       1001 |   3000 | CN      | South  | 2023-10-06 | internal    |
+------------+--------+---------+--------+------------+-------------+
6 rows in set
```

#### 场景 2：按国家统计总销售额（跨源聚合）

```sql
SELECT
    country,
    SUM(amount) AS total_sales,
    COUNT(*) AS record_count
FROM (
    SELECT product_id, amount, country, region, event_date
    FROM federated_demo.test_table_internal

    UNION ALL

    SELECT product_id, amount, country, region, event_date
    FROM hive_meta.test_database.test_table
) AS all_sales
GROUP BY country
ORDER BY total_sales DESC;
```

预期输出：

```shell
+---------+-------------+--------------+
| country | total_sales | record_count |
+---------+-------------+--------------+
| US      |        3500 |            1 |
| CN      |        5500 |            2 |  -- 2500 (Hive) + 3000 (Internal)
| DE      |        4200 |            1 |
| FR      |        1900 |            1 |
| JP      |        1800 |            1 |
+---------+-------------+--------------+
```

### 场景 3：找出只在 internal 中存在的产品

```sql
SELECT i.product_id, i.country
FROM federated_demo.test_table_internal i
LEFT JOIN hive_meta.test_database.test_table h
  ON i.product_id = h.product_id
WHERE h.product_id IS NULL;
```

输出：

```shell
+------------+---------+
| product_id | country |
+------------+---------+
|       1004 | DE      |
|       1005 | FR      |
+------------+---------+
```

**联邦聚合**

```sql
-- 联邦聚合
SELECT country, SUM(amount) AS total
FROM (
  SELECT product_id, amount, country FROM federated_demo.test_table_internal
  UNION ALL
  SELECT product_id, amount, country FROM hive_meta.test_database.test_table
) t
GROUP BY country;
```

预计输出结果为：

```shell
+---------+-------+
| country | total |
+---------+-------+
| DE      |  4200 |
| FR      |  1900 |
| CN      |  5500 |
| JP      |  1800 |
| US      |  3500 |
+---------+-------+
5 rows in set
```
