# 日志流手动运维命令相关问题

执行 `ALTER SYSTEM CREATE LS` 或 `ALTER SYSTEM MODIFY LS` 等日志流手动运维命令后，系统可能会提示报错信息，这些报错信息展示了命令无法成功执行的原因。本文主要介绍了这些报错信息后的问题原因及处理方法。

## 报错信息 1：The tenant status is not NORMAL. CREATE LS is not allowed

### 报错原因

租户状态不是 `NORMAL` 状态，不允许创建日志流。

### 处理方法

查询视图 `DBA_OB_TENANTS` 确认租户状态，如果租户当前为 `CREATING` 状态，可以等待租户创建成功后再创建日志流。

## 报错信息 2：The tenant's switchover status is not normal, CREATE LS is not allowed

### 报错原因

租户的 `SWITCHOVER_STATUS` 状态不是 `NORMAL` 状态，不允许创建日志流。

## 报错信息 3：Unknown tenant 'tenant_name'

### 报错原因

不允许为不存在的租户创建或变更日志流。

### 处理方法

请确认租户是否存在。

## 报错信息 4：Access denied

### 报错原因

不允许用户租户下指定与自己名称不一致的租户名。

## 报错信息 5：Access denied; you need (at least one of) the SUPER or ALTER SYSTEM privilege(s) for this operation

### 报错原因

不允许没有 `ALTER SYSTEM` 权限的用户创建或变更日志流。

### 处理方法

可以通过 GRANT 语句赋予当前用户 `ALTER SYSTEM` 权限。有关用户授权的详细操作，参见 [直接授予权限（MySQL 模式）](../500.security-and-permissions/300.access-control/200.user-and-permission/200.permission-of-mysql-mode/200.authority-of-mysql-mode.md) 和 [直接授予权限（Oracle 模式）](../500.security-and-permissions/300.access-control/200.user-and-permission/300.permission-of-oracle-mode/200.authority-of-oracle-mode.md)。

## 报错信息 6：CREATE LS of META or SYS tenant is not supported

### 报错原因

不允许为系统租户或 Meta 租户创建日志流。

### 处理方法

为用户租户创建日志流。

## 报错信息 7：The tenant role is not primary, CREATE LS is not allowed

### 报错原因

只能在主租户上创建日志流。

### 处理方法

在主租户上创建日志流。

## 报错信息 8：The specified unit_group is not active or does not exist, CREATE LS is not allowed

### 报错原因

不允许在不存在的 `UNIT_GROUP` 上创建日志流，并且不允许指定在 `UNIT_GROUP_ID` 为 0 的 `UNIT GROUP` 上创建日志流。

### 处理方法

查询视图 `DBA_OB_UNITS`，确认指定的 `UNIT_GROUP` 是否正确。

## 报错信息 9：Incorrect arguments to set invalid unit group

### 报错原因

不允许指定在 `UNIT_GROUP_ID` 小于 1000 的 `UNIT GROUP` 上创建日志流。

### 处理方法

查询视图 `DBA_OB_UNITS`，确认指定的 `UNIT_GROUP` 是否正确。

## 报错信息 10：The specified primary_zone is not in the tenant's zone list, CREATE LS is not allowed

### 报错原因

指定的日志流 `PRIMARY_ZONE` 不在租户的 `ZONE_LIST` 中，不允许创建日志流。创建日志流时，要求指定的 `PRIMARY_ZONE` 在租户的 `ZONE_LIST` 中，并且不允许指定多个 `PRIMARY_ZONE`。

### 处理方法

查询视图 `DBA_OB_TENANTS`，通过租户的 Locality 确认租户有哪些 Zone。

## 报错信息 11：The specified LS does not exist, MODIFY LS is not allowed

### 报错原因

日志流不存在，不允许变更日志流。

### 处理方法

查询视图 `CDB_OB_LS` 或 `DBA_OB_LS`，确认指定的日志流是否正确。

## 报错信息 12：The specified LS's status is not normal, MODIFY LS is not allowed

### 报错原因

日志流状态不是 `NORMAL` 状态，不允许变更日志流。

### 处理方法

查询 `CDB_OB_LS` 视图或 `DBA_OB_LS` 视图，确认日志流状态。如果日志流为 `CREATING` 状态，可以等待日志流创建成功后再变更，其他状态则无法变更。

## 报错信息 13：The specified primary_zone is not in the tenant's zone list, MODIFY LS is not allowed

### 报错原因

指定的日志流 `PRIMARY_ZONE` 不在租户的 `ZONE_LIST` 中，不允许变更日志流。变更日志流时，要求指定的 `PRIMARY_ZONE` 在租户的 `ZONE_LIST` 中，并且不允许指定多个 `PRIMARY_ZONE`。

### 处理方法

查询视图 `DBA_OB_TENANTS`，通过租户的 Locality 确认租户有哪些 Zone。

## 报错信息 14：The specified unit_group is not active or does not exist, MODIFY LS is not allowed

### 报错原因

`UNIT_GROUP` 不存在或者状态不是 `ACTIVE`，不允许变更日志流。

### 处理方法

查询视图 `DBA_OB_UNITS`，确认指定的 `UNIT_GROUP` 是否正确。

## 报错信息 15：The specified LS has balance tasks, MODIFY LS is not allowed

### 报错原因

主租户修改日志流的 `UNIT_GROUP` 时，要求租户没有进行负载均衡任务。

### 处理方法

查询视图 `CDB_OB_BALANCE_TASKS` 或 `DBA_OB_BALANCE_TASKS`，确认当前日志流是否有正在进行的负载均衡任务，如果有，等待负载均衡任务完成后再变更日志流。
