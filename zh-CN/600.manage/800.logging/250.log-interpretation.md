# 日志解读

介绍 OceanBase 数据库日志解读指南，涵盖各日志功能解读、日志定位，日志结构、关键场景日志解读等。

## observer.log

主服务进程运行日志，记录除选举与 RootService 外所有模块的操作，包括 SQL 解析、事务执行、存储引擎行为等。

### OBServer 启动日志

OBServer 启动日志记录了进程初始化及服务就绪的关键事件，用于诊断启动阶段问题。

* **日志定位方法**

  通过搜索关键字 `[NOTICE]` 进行定位。

* **日志定位命令**

  ```log
  [admin@OB /home/admin/oceanbase/log] $grep "NOTICE" observer.log
  ```

* **典型输出示例**

  ```log
  [2023-05-11 14:19:09.703272] INFO  [SERVER] ob_server.cpp:533 [95303][0][Y0-0000000000000000-0-0] [lt=9] [dc=0] [NOTICE] server instance start succeed

  [2023-05-11 14:19:25.555836] INFO  [SERVER] ob_server.cpp:609 [95303][0][Y0-0000000000000000-0-0] [lt=16] [dc=0] [NOTICE] observer start service(start_service_time=1683785965555827)
  ```

* **关键字段说明**

  | 日志信息                      | 说明                                                                                     |
  | ----------------------------- | ---------------------------------------------------------------------------------------- |
  | server instance start succeed | OBServer 进程启动成功。                                                                  |
  | observer start service        | OBServer 启动完成，开始提供服务；`start_service_time` 为 OBServer 开始提供服务的时间戳。 |

### 统计日志


#### 租户磁盘统计

租户磁盘使用情况，每 10s 打印一次。

* **日志定位方法**

  通过搜索关键字 `ob_tenant_disk_usage_mgr.cpp` 或 `dump tenant disk usage update info` 进行定位。

* **日志定位命令**

  ```log
  [admin@OB /home/admin/oceanbase/log] $grep "ob_tenant_disk_usage_mgr.cpp" observer.log
  ```

  或

  ```log
  [admin@OB /home/admin/oceanbase/log] $grep "dump tenant disk usage update info" observer.log
  ```

* **典型输出示例**

  ```log
  [2023-05-15 17:30:59.055858] INFO  [STORAGE] ob_tenant_disk_usage_mgr.cpp:69 [87424][0][Y0-0000000000000000-0-0] [lt=11] [dc=0] dump tenant disk usage update info(disk_usage={tenant_id:1, max_disk_size:0, used_data_size:935329792, used_meta_size:56623104})
  ```

* **关键字段说明**

  | 日志信息       | 说明                                                      |
  | -------------- | --------------------------------------------------------- |
  | tenant_id      | 租户 ID。                                                 |
  | max_disk_size  | 租户的磁盘上限（V4.x 之前版本租户没有磁盘使用量的限制）。 |
  | used_data_size | 租户内用户数据使用的磁盘空间。                            |
  | used_meta_size | 租户内管理数据使用的磁盘空间。                            |

### Leader 租约过期

Leader 租约过期触发重新选主事件。

* **日志定位方法**

  通过搜索关键字 `lease is expired`、`leader lease is expired` 进行定位。

* **日志定位命令**

  ```log
  [admin@OB /home/admin/oceanbase/log] $grep "lease is expired|leader lease is expired" election.log
  ```

* **典型输出示例**

  ```log
  [2022-05-31 15:32:19.849628] INFO  [ELECT] ob_election.cpp:1890 [44778][T1010][Y0-000000-0-0] [lt=21] leader lease expired(partition={tid:1106108697592658, partition_id:12}, lease_end=1652078088200000, current_ts=1652078139849628, election={self:"10.xx.xx.xx:2882", cur_leader:"10.xx.xx.xx:2882", state:ACTIVE, role:LEADER, lease:[1652078078000000, 1652078088200000]})
  ```

* **关键字段说明**

  | 日志信息           | 说明                               |

### Leader 无效告警

Leader 状态异常告警事件。

* **日志定位方法**

  通过搜索关键字 `current leader is invalid` 进行定位。

* **日志定位命令**

  ```log
  [admin@OB /home/admin/oceanbase/log] $grep  "current leader is invalid" rootservice.log
  ```

* **典型输出示例**

  ```log
  [2022-07-16 02:02:12.847602] WARN  [RS] ob_leader_coordinator.cpp:2067 [8570][YB420AF4005E-4626EDFC] [lt=8] [dc=0] current leader is invalid!(tenant_id=1005, ls_id=1100611139404082, invalid_reason="location cache mismatch", current_leader="11.xx.xx.xx:2882", actual_leader="11.xx.xx.xx:2882")
  ```

* **关键字段说明**

  | 日志信息        | 说明                                |
  | --------------- | ----------------------------------- |
  | invalid_reason  | 无效原因（如缓存不一致/心跳丢失）。 |

  | actual_leader   | 实际选举产生的 Leader 地址。        |
