# 校验指定备份集或日志归档 Piece

OceanBase 数据库支持指定备份集或日志归档 Piece 的校验。用户可以根据业务需要，选择仅校验当前备份路径下的指定备份集或者仅校验当前归档路径下的日志归档 Piece。

## 使用限制及注意事项

* 本文档仅用于校验当前集群内租户下 `DATA_BACKUP_DEST` 和 `LOG_ARCHIVE_DEST` 中当前指定的路径下的备份集或日志归档 Piece。如果需要校验当前备份和归档路径下的所有备份集和归档 Piece，可参考 [校验整个备份路径和归档路径](200.validate-the-data-backup-dest-and-log-archive-dest.md) 进行校验。

    此外，对于已更换备份目的端或归档目的端的场景，如果需要校验原备份路径或归档路径下的数据，可以参考 [校验指定路径下的备份集或日志归档 Piece](400.validate-the-backupset-or-archivepiece-at-the-specified-dest.md) 进行校验。

* 由于校验任务会频繁地通过访问备份介质来读取数据，进而抢占备份任务的网络资源，建议在用户租户未执行备份任务且低负载时执行校验任务。

* 指定备份校验的校验层级时：

  * 对于 V4.6.0 版本之前的备份集以及 V4.6.0 版本之前的日志归档 Piece，不支持 Basic 校验，即不支持文件的完整性校验。

  * 对于 V4.3.4 版本（不含 V4.3.4 版本）之前的备份集，不支持 Physical 校验，即不支持物理数据的正确性及逻辑一致性校验。

## 校验指定备份集

### 系统租户对用户租户的指定备份集发起备份校验

1. 使用 `root` 用户登录集群的 `sys` 租户。

   连接示例如下，连接数据库时请以实际环境为准。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. （可选）获取待校验的用户租户的备份集的 `backup_set_id`。

   ```shell
   obclient(root@sys)[(none)]> SELECT a.TENANT_ID, b.TENANT_NAME, a.BACKUP_SET_ID, a.BACKUP_TYPE, a.STATUS, a.FILE_STATUS, a.PATH 
   FROM oceanbase.CDB_OB_BACKUP_SET_FILES a, oceanbase.DBA_OB_TENANTS b 
   WHERE a.TENANT_ID = b.TENANT_ID
   AND b.TENANT_NAME = 'mysqltenant';
   ```

3. 执行以下命令，对用户租户发起指定备份集的校验。

   语句如下：

   ```sql
   ALTER SYSTEM VALIDATE BACKUPSET [= 'backup_set_id[,backup_set_id,...]'] [LEVEL = { 'basic' | 'physical' }] [TENANT = tenant_name];
   ```

   语句中相关参数说明如下：

   * `BACKUPSET`：指定待校验的备份集。支持校验租户当前备份路径下的所有备份集或指定的备份集列表。指定备份集列表时，多个备份集 `backup_set_id` 之间使用英文逗号分隔。未指定备份集的 `backup_set_id` 时，则默认校验租户当前备份路径下的所有备份集。

     <main id="notice" type='notice'>
     <h4>注意</h4>
     <p>如果不指定 <code>backup_set_id</code>，系统将会获取当前配置的备份路径下的所有备份集进行校验，从而导致产生大量的校验任务，耗时较长。如果确认不需要校验所有备份集，建议在校验命令中指定 <code>backup_set_id</code>。</p>
     </main>

   * `LEVEL`：可选参数，表示校验层级。如果不指定，则默认值为 `physical`。其中：

     * `basic` 校验：仅检查文件列表的完整性。

     * `physical` 校验：检查物理数据的正确性及逻辑一致性。

   * `TENANT`：用于指定执行校验任务的用户租户。如果不指定，则校验集群内所有用户租户的指定备份集。

   示例如下：

   * 系统租户对所有用户租户在当前备份路径下的所有备份集发起 Basic 校验。

     ```shell
     obclient(root@sys)[(none)]> ALTER SYSTEM VALIDATE BACKUPSET LEVEL = basic;
     ```

   * 系统租户对用户租户 `mysqltenant` 在当前备份路径下的所有备份集发起 Basic 校验。

     ```shell
     obclient(root@sys)[(none)]> ALTER SYSTEM VALIDATE BACKUPSET LEVEL = basic TENANT = mysqltenant;
     ```

   * 系统租户对用户租户 `mysqltenant` 在当前备份路径下 `backup_set_id` 为 1、2 的备份集发起 Physical 校验。

     ```shell
     obclient(root@sys)[(none)]> ALTER SYSTEM VALIDATE BACKUPSET = '1,2' LEVEL = physical TENANT = mysqltenant;
     ```

   * 系统租户对所有用户租户在当前备份路径下 `backup_set_id` 为 1、2 的备份集发起 Physical 校验。

     ```shell
     obclient(root@sys)[(none)]> ALTER SYSTEM VALIDATE BACKUPSET = '1,2' LEVEL = physical TENANT = mysqltenant;
     ```

4. 语句执行成功后，可分别通过 `CDB_OB_BACKUP_VALIDATE_JOBS`、`CDB_OB_BACKUP_VALIDATE_TASKS`、`CDB_OB_BACKUP_VALIDATE_JOB_HISTORY` 以及 `CDB_OB_BACKUP_VALIDATE_TASK_HISTORY` 等视图查看校验任务的状态、进度及执行结果。

   查看备份校验进度的详细操作及介绍，参见 [查看备份校验进度](600.view-the-backup-validation-process.md)。

   查看备份校验结果的详细操作及介绍，参见 [查看备份校验结果](700.view-the-backup-validation-history.md)。

### 用户租户对本租户的指定备份集发起备份校验

1. 用户租户的租户管理员登录到数据库。

   <main id="notice" type='explain'>
   <h4>说明</h4>
   <p>MySQL 租户的管理员用户为 <code>root</code> 用户，Oracle 租户的管理员用户为 <code>SYS</code> 用户。</p>
   </main>

   连接示例如下，连接数据库时请以实际环境为准。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql001#obdemo -p***** -A
   ```

2. （可选）获取待校验的备份集的 `backup_set_id`。

   :::tab
   tab MySQL 模式

   MySQL 模式下的查询语句如下：

   ```shell
   obclient(root@mysqltenant)[(none)]> SELECT BACKUP_SET_ID, BACKUP_TYPE, STATUS, FILE_STATUS, PATH FROM oceanbase.DBA_OB_BACKUP_SET_FILES;
   ```

   tab Oracle 模式

   Oracle 模式下的查询语句如下：

   ```shell
   obclient(SYS@oracletenant)[SYS]> SELECT BACKUP_SET_ID, BACKUP_TYPE, STATUS, FILE_STATUS, PATH FROM SYS.DBA_OB_BACKUP_SET_FILES;
   ```

   :::

   语句如下：

     </main>

   * `LEVEL`：可选参数，表示校验层级。如果不指定，则默认值为 `physical`。其中：

     * `basic` 校验：仅检查文件列表的完整性。

     * `physical` 校验：检查物理数据的正确性及逻辑一致性。

   示例如下：

   * 用户租户对本租户当前备份路径下的所有备份集发起 Basic 校验。

     ```shell

     ```

   * 用户租户对本租户当前备份路径下 `backup_set_id` 为 1、2 的备份集发起 Physical 校验。

     ```shell
     obclient> ALTER SYSTEM VALIDATE BACKUPSET = '1,2' LEVEL = physical;
     ```

4. 语句执行成功后，可分别通过 `DBA_OB_BACKUP_VALIDATE_JOBS`、`DBA_OB_BACKUP_VALIDATE_TASKS`、`DBA_OB_BACKUP_VALIDATE_JOB_HISTORY` 以及 `DBA_OB_BACKUP_VALIDATE_TASK_HISTORY` 等视图查看校验任务的状态、进度及执行结果。
