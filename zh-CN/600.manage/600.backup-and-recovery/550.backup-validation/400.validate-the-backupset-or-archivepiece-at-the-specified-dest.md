# 校验指定路径下的备份集或日志归档 Piece

OceanBase 数据库支持指定路径下备份集或日志归档 Piece 的校验。该方式适用于跨集群备份数据或冷备数据的校验。

## 使用限制及注意事项

* 由于校验任务会频繁地通过访问备份介质来读取数据，进而抢占备份任务的网络资源，建议在用户租户未执行备份任务且低负载时执行校验任务。

* 指定备份校验的校验层级时：

  * 对于 V4.6.0 版本之前的备份集以及 V4.6.0 版本之前的日志归档 Piece，不支持 Basic 校验，即不支持文件的完整性校验。

  * 对于 V4.3.4 版本（不含 V4.3.4 版本）之前的备份集，不支持 Physical 校验，即不支持物理数据的正确性及逻辑一致性校验。

## 校验指定路径下的备份集

### 系统租户对用户租户指定路径下的备份集发起备份校验

1. 使用 `root` 用户登录集群的 `sys` 租户。

   连接示例如下，连接数据库时请以实际环境为准。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. 执行以下命令，对用户租户发起指定路径下备份集的校验。

   语句如下：

   ```sql
   ALTER SYSTEM VALIDATE BACKUPSET [= 'backup_set_id[,backup_set_id,...]'] DATA_BACKUP_DEST = 'data_backup_path' [LEVEL = { 'basic' | 'physical' }] TENANT = tenant_name;
   ```

   语句中相关参数说明如下：

   * `BACKUPSET`：指定待校验的备份集。支持校验租户指定备份路径下的所有备份集或指定的备份集列表。指定备份集列表时，多个备份集 `backup_set_id` 之间使用英文逗号分隔。未指定备份集的 `backup_set_id` 时，则默认校验租户指定备份路径下的所有备份集。

     跨集群或冷备数据场景下，备份集的 `backup_set_id` 可根据备份目录中的文件名来获取，有关备份目录结构的详细介绍，参见 [物理备份与恢复概述](../100.overview-of-physical-backup-and-recovery.md) 中的 **数据备份目录**。

     <main id="notice" type='notice'>
     <h4>注意</h4>
     <p>如果不指定 <code>backup_set_id</code>，系统将会获取当前配置的备份路径下的所有备份集进行校验，从而导致产生大量的校验任务，耗时较长。如果确认不需要校验所有备份集，建议在校验命令中指定 <code>backup_set_id</code>。</p>
     </main>

   * `DATA_BACKUP_DEST`：指定备份集的存放路径。

     <main id="notice" type='notice'>
     <h4>注意</h4>
     <p>OceanBase 数据库当前不支持在单条命令中指定多个路径。因此，在指定路径下通过指定 <code>backup_set_id</code> 校验增量备份集时，可能因为无法读取该增量备份集所依赖的其他备份集信息而报错，错误码为 9120。</p>
     </main>

   * `LEVEL`：可选参数，表示校验层级。如果不指定，则默认值为 `physical`。其中：

     * `basic` 校验：仅检查文件列表的完整性。

     * `physical` 校验：检查物理数据的正确性及逻辑一致性。

   * `TENANT`：用于指定执行校验任务的用户租户。

   示例如下：

   * 系统租户对指定用户租户 `mysqltenant` 在指定备份路径下的所有备份集发起 Basic 校验。

     ```shell
     obclient(root@sys)[(none)]> ALTER SYSTEM VALIDATE BACKUPSET LEVEL = basic DATA_BACKUP_DEST = 'file:///data/nfs/backup/data' TENANT = mysqltenant;
     ```

   * 系统租户对指定用户租户 `mysqltenant` 在指定备份路径下 `backup_set_id` 为 1、2 的备份集发起 Physical 校验。

     ```shell
     obclient(root@sys)[(none)]> ALTER SYSTEM VALIDATE BACKUPSET = '1,2' DATA_BACKUP_DEST = 'file:///data/nfs/backup/data' LEVEL = physical TENANT = mysqltenant;
     ```

3. 语句执行成功后，可分别通过 `CDB_OB_BACKUP_VALIDATE_JOBS`、`CDB_OB_BACKUP_VALIDATE_TASKS`、`CDB_OB_BACKUP_VALIDATE_JOB_HISTORY` 以及 `CDB_OB_BACKUP_VALIDATE_TASK_HISTORY` 等视图查看校验任务的状态、进度及执行结果。

   查看备份校验进度的详细操作及介绍，参见 [查看备份校验进度](600.view-the-backup-validation-process.md)。

   查看备份校验结果的详细操作及介绍，参见 [查看备份校验结果](700.view-the-backup-validation-history.md)。

### 用户租户对本租户指定路径下的备份集发起备份校验

1. 用户租户的租户管理员登录到数据库。

   <main id="notice" type='explain'>
   <h4>说明</h4>
   <p>MySQL 租户的管理员用户为 <code>root</code> 用户，Oracle 租户的管理员用户为 <code>SYS</code> 用户。</p>
   </main>

   * `BACKUPSET`：指定待校验的备份集。支持校验租户指定备份路径下的所有备份集或指定的备份集列表。指定备份集列表时，多个备份集 `backup_set_id` 之间使用英文逗号分隔。未指定备份集的 `backup_set_id` 时，则默认校验租户指定备份路径下的所有备份集。

     * `basic` 校验：仅检查文件列表的完整性。

     * `physical` 校验：检查物理数据的正确性及逻辑一致性。

   示例如下：

   * 用户租户对本租户指定备份路径下的所有备份集发起 Basic 校验。

     ```shell
     obclient> ALTER SYSTEM VALIDATE BACKUPSET DATA_BACKUP_DEST = 'file:///data/nfs/backup/data' LEVEL = basic;
     ```

   * 用户租户对本租户指定备份路径下 `backup_set_id` 为 1、2 的备份集发起 Physical 校验。


## 校验指定路径下的日志归档 Piece
