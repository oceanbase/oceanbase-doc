# 发起归档日志备份

<main id="notice" type='explain'>
<h4>说明</h4>
<p>对于 V4.4.2 版本，从 V4.4.2 BP3 版本开始支持备份归档日志</a>。</p>
</main>

日志归档后，可以对已归档的日志数据进行备份，将日志归档目的端 `LOG_ARCHIVE_DEST` 中已冻结（FROZEN）的归档 Piece 备份到独立的备份目的端 `BACKUP_ARCHIVE_DEST`。备份完成后，原归档介质上的日志数据可以被安全回收，从而释放归档空间，避免日志归档因归档介质空间满而出现断流。

归档日志备份的典型使用场景如下：

* 归档空间回收：定期备份旧的归档 Piece，并通过 `DELETE INPUT` 选项自动清理源端已备份的归档日志文件。
* 分层存储：日志归档目的端保存近期日志，备份目的端保存较早的冻结日志。

## 前提条件

在发起归档日志备份前，您需要确认满足以下条件：

* 已开启归档模式，仅当租户的 `LOG_MODE` 为 `ARCHIVELOG` 时，才能发起归档日志备份。开启归档模式的相关操作请参见 [开启归档模式](300.open-the-log-archive-mode.md)。

## 设置归档日志的备份目的端

发起归档日志备份前，需要先设置归档日志的备份目的端，用于指定归档日志备份文件的存储路径。仅系统租户在执行设置备份目的端的操作时需要通过 `TENANT = <tenant_name>` 子句指定待操作的租户，用户租户只能对本租户执行该操作，故不需要指定该子句。

### 系统租户设置归档日志的备份目的端

`sys` 租户可以为集群中的指定用户租户设置归档日志的备份目的端。

1. 使用 `root` 用户登录集群的 `sys` 租户。

2. 执行以下语句，为指定用户租户设置归档日志的备份目的端。

   ```sql
   ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'location=<backup_archive_path>' TENANT = <tenant_name>;
   ```

   其中，`<backup_archive_path>` 为备份目的端的存储路径，支持 NFS、阿里云 OSS、Azure Blob、AWS S3 以及兼容 S3 协议的对象存储等存储介质。有关 `<backup_archive_path>` 的详细格式说明，参见 [SET BACKUP_ARCHIVE_DEST](../../../700.reference/500.sql-reference/100.sql-syntax/100.system-tenants/200.alter-system/3850.set-backup-archive-dest.md)。

   <main id="notice" type='explain'>
   <h4>说明</h4>
   <p>归档日志的备份目的端不允许与日志归档目的端相同，即 BACKUP_ARCHIVE_DEST 与 LOG_ARCHIVE_DEST 中的存储路径信息必须不同。</p>
   </main>

   示例：

   * 备份目的端存储介质为 NFS。

      ```sql
      obclient [(none)]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'location=file:///data/nfs/backup/backup_archive' TENANT = mysql_tenant;
      ```

   * 备份目的端存储介质为 OSS。

      ```sql
      obclient [(none)]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'location=oss://oceanbase-test-bucket/backup/backup_archive?host=****.aliyun-inc.com&access_id=****&access_key=****' TENANT = mysql_tenant;
      ```

### 用户租户设置归档日志的备份目的端

用户租户可以对本租户设置归档日志的备份目的端，不会影响其他租户。

1. 租户管理员登录到数据库。

    本示例中，您可以使用 `root` 用户登录 `mysql_tenant` 租户；或者也可以使用 `SYS` 用户登录 `oracle_tenant` 租户。

2. 执行以下语句，设置本租户的归档日志备份目的端。

   ```sql
   ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'location=<backup_archive_path>';
   ```

   <main id="notice" type='explain'>
   <h4>说明</h4>
   <p>归档日志的备份目的端不允许与日志归档目的端相同，即 BACKUP_ARCHIVE_DEST 与 LOG_ARCHIVE_DEST 中的存储路径信息必须不同。</p>
   </main>

   示例：

   * 备份目的端存储介质为 NFS。

      ```sql
      obclient [(none)]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'location=file:///data/nfs/backup/backup_archive';
      ```

   * 备份目的端存储介质为 OSS。

      ```sql
      obclient [(none)]> ALTER SYSTEM SET BACKUP_ARCHIVE_DEST = 'location=oss://oceanbase-test-bucket/backup/backup_archive?host=****.aliyun-inc.com&access_id=****&access_key=****';
      ```

## 发起归档日志备份

完成备份目的端的设置后，您可以通过 `ALTER SYSTEM BACKUP ARCHIVELOG` 语句发起归档日志备份。语句如下：

```sql
ALTER SYSTEM BACKUP ARCHIVELOG ALL [DELETE INPUT] [TENANT = <tenant_name>];
```

根据是否指定 `DELETE INPUT` 选项，归档日志备份的行为有所不同：

* 不带 `DELETE INPUT` 时，仅将已归档的日志数据备份到 `BACKUP_ARCHIVE_DEST`，不会删除源端的归档日志文件。
* 带 `DELETE INPUT` 时，仅当本次任务中所有 FROZEN 状态的 Piece 均成功备份后，系统才会生成清理任务，自动删除源端已备份的归档日志文件，以释放存储空间；如果归档日志备份任务失败，则不会清理源端副本。

归档日志备份的任务说明如下：

* 归档日志备份为异步任务，语句执行成功仅表示任务已创建并提交，任务在后台执行，您可以通过备份任务相关视图查询任务的进度和结果。
* 归档日志备份以 Piece 为处理单位，复制后完全保持原有的目录和文件形态，不会对归档日志做任何修改。
* 归档日志备份仅处理 FROZEN 状态的 Piece，不会自动触发 Piece 冻结，也不会备份正在写入的 ACTIVE Piece，且不影响日志归档继续向源端的 ACTIVE Piece 写入。如果不存在 FROZEN 状态的 Piece，任务会正常完成但不会复制数据。
* 任务启动时会确定本次待备份的 Piece，已成功备份过的 Piece 不会再次备份；任务执行期间新冻结的 Piece 由下一次归档日志备份任务处理。
* Piece 备份成功后，该 Piece 在备份目的端上的副本文件状态会更新为 `AVAILABLE`。

<main id="notice" type='explain'>
<h4>说明</h4>
<p>归档日志备份按照 Piece 并行调度，以文件级别的方式将数据从日志归档目的端拷贝至备份目的端，单个 Piece 的拷贝会按照日志流目录拆分并行。拷贝速度取决于 Piece 的数据大小以及两个目的端存储的读写吞吐和请求时延，该过程不会在 OBServer 本地产生额外的 IO 开销。</p>
</main>

### 系统租户发起归档日志备份

`sys` 租户可以对集群中的指定租户发起归档日志备份。仅系统租户在执行此命令时需要通过 `TENANT = <tenant_name>` 子句指定待操作的租户。

1. 使用 `root` 用户登录集群的 `sys` 租户。

2. 执行以下语句，发起归档日志备份。

   * 对 `mysql_tenant` 租户发起归档日志备份的示例如下：

      ```sql
      obclient [(none)]> ALTER SYSTEM BACKUP ARCHIVELOG ALL TENANT = mysql_tenant;
      ```

   * 对 `mysql_tenant` 租户发起归档日志备份并在备份完成后自动删除源端归档日志文件的示例如下：

      ```sql
      obclient [(none)]> ALTER SYSTEM BACKUP ARCHIVELOG ALL DELETE INPUT TENANT = mysql_tenant;
      ```

   命令执行成功后，系统会对指定租户发起归档日志备份。

### 用户租户发起归档日志备份

用户租户可以对本租户发起归档日志备份，不会影响其他租户。用户租户只能对本租户执行此命令，故不需要指定 `TENANT` 子句。

1. 租户管理员登录到数据库。

    本示例中，您可以使用 `root` 用户登录 `mysql_tenant` 租户；或者也可以使用 `SYS` 用户登录 `oracle_tenant` 租户。

2. 执行以下语句，发起归档日志备份。

   * 对本租户发起归档日志备份的示例如下：

      ```sql
      obclient [(none)]> ALTER SYSTEM BACKUP ARCHIVELOG ALL;
      ```

   * 对本租户发起归档日志备份并在备份完成后自动删除源端归档日志文件的示例如下：

      ```sql
      obclient [(none)]> ALTER SYSTEM BACKUP ARCHIVELOG ALL DELETE INPUT;
      ```

   命令执行成功后，系统会对本租户发起归档日志备份。

## 注意事项

* `DELETE INPUT` 会删除源端的物理副本，使用前应验证备份目的端存储的可靠性、可访问性，并验证恢复流程。

* 如果有使用 CDC 直连归档消费归档数据的需求，不建议使用 `DELETE INPUT` 选项：源端 FROZEN 状态的 Piece 被清理后，可能导致 CDC 读取不到数据字典。

* 备份目的端只保存 FROZEN 状态的 Piece。恢复到较新的位点时，通常仍需提供包含新 Piece 和 ACTIVE 尾部的日志归档目的端；恢复时可同时指定数据备份路径、日志归档路径和归档日志备份路径，系统会按需读取对应的 Piece，相关操作请参见 [发起恢复](../600.restore-data/200.initiate-the-tenant-restore.md)。

* 现有的备份清理策略对归档日志备份做了适配，备份清理设置的 `RECOVERY_WINDOW` 同样会对备份目的端上的副本生效，即日志归档目的端和备份目的端共用 `default` 或 `log_only` 清理策略的清理边界，不支持分别为两个目的端设置独立的 `RECOVERY_WINDOW`。有关自动清理过期备份的详细操作，请参见 [自动清理过期备份](../500.clear-backup-data/50.automatic-backup-cleanup/100.cleaning-up-backed-up-data-automatically.md)。

* 归档日志备份与过期备份清理任务不能在同一租户上并发执行，系统会拒绝或延后其中一个任务。

* 归档日志备份与其他任务存在以下互斥关系：

  * 修改 `BACKUP_ARCHIVE_DEST` 与发起归档日志备份互斥：修改 `BACKUP_ARCHIVE_DEST` 期间发起归档日志备份会失败；归档日志备份任务未结束时不允许修改 `BACKUP_ARCHIVE_DEST`，系统会返回 `OPT_NOT_ALLOW` 错误。

  * 修改 `BACKUP_ARCHIVE_DEST` 与带 `PLUS ARCHIVELOG` 参数的数据备份任务互斥：由于带 `PLUS ARCHIVELOG` 参数的数据备份任务执行期间可能会从 `BACKUP_ARCHIVE_DEST` 上拷贝 Piece 文件，为避免出现 Piece 一边拷贝一边删除的场景，修改 `BACKUP_ARCHIVE_DEST` 期间发起带 `PLUS ARCHIVELOG` 参数的数据备份任务会失败；带 `PLUS ARCHIVELOG` 参数的数据备份任务执行期间，修改 `BACKUP_ARCHIVE_DEST` 也会失败，系统会返回 `OPT_NOT_ALLOW` 错误。

  * 带 `DELETE INPUT` 的归档日志备份所发起的源端副本清理任务，与带 `PLUS ARCHIVELOG` 参数的数据备份任务互斥：发起清理任务前，系统会检查同租户下是否有正在执行的带 `PLUS ARCHIVELOG` 参数的数据备份任务，如果有，归档日志备份仍会正常执行，但对应的清理任务会失败；发起带 `PLUS ARCHIVELOG` 参数的数据备份任务前，系统会检查是否有正在执行的源端副本清理任务，如果有，该数据备份任务会失败，需等待清理任务结束后重新发起。
