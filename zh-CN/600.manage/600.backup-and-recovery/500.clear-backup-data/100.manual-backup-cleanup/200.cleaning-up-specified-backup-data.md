# 手动清理指定的备份或归档数据

因业务需要，期望清理一些特定的备份或归档时，可以参考本文档手动清理指定的数据备份集或日志归档 Piece。

## 使用限制

* 手动清理指定的备份或归档数据时，要求被操作的用户租户已配置自动清理策略，否则，无法进行清理。

* 对于仅开启了日志归档，未配置数据备份路径的场景，不允许通过手动方式清理指定的日志归档 Piece，用户只能通过将自动清理策略配置为 `log_only` 的方式来实现日志归档 Piece 的清理。

  配置自动清理策略的详细操作，参见 [自动清理过期备份](../50.automatic-backup-cleanup/100.cleaning-up-backed-up-data-automatically.md)。

## 清理指定的数据备份集

### 注意事项

清理指定的数据备份集时，需要注意以下事项：

* 不能破坏数据备份之间的依赖关系。如果某个数据备份被关联的增量备份所依赖，则被依赖的数据备份只能在所有依赖它的增量备份被删除后，才能被删除。

* 如果需要同时指定多个 `BACKUP_SET_ID` 进行清理，则要求所有 `BACKUP_SET_ID` 均在同一个备份路径下。不支持在同一条命令中清理多个路径下的数据备份。

* 对于当前正在使用的备份路径，需要至少保留一份最新的且能够用于恢复的全量数据备份。即，保留一份可用于恢复的全量备份后，才可以删除在该备份集之前的其它备份集。

4. 执行以下命令，删除指定的数据备份。

   语句如下：

   ```sql
   ALTER SYSTEM DELETE BACKUPSET backup_set_id[,backup_set_id,...] TENANT [=] tenant_name;
   ```

   其中：

   * `backup_set_id`：指定待删除的备份集的 ID，单条命令中支持同时指定多个数据备份集。同时指定多个 `backup_set_id` 进行清理时，要求所有 `backup_set_id` 均在同一个备份路径下。不支持在同一条命令中清理多个路径下的数据备份。

   * `tenant_name`：指定待删除备份集的租户。

   示例如下：

   * 删除租户 `mysql001` 的 `backup_set_id` 为 3 的数据备份集。

     ```shell
     obclient(root@sys)[(none)]> ALTER SYSTEM DELETE BACKUPSET 3 TENANT = mysql001;
     ```

   * 同时删除租户 `mysql001` 的 `backup_set_id` 为 1、2、3、4 的 4 个数据备份集。

     ```shell
     obclient(root@sys)[(none)]> ALTER SYSTEM DELETE BACKUPSET 1,2,3,4 TENANT = mysql001;
     ```

## 清理指定的日志归档 Piece

### 注意事项

清理指定的日志归档 Piece 时，需要注意以下事项：

* 需要按照顺序清理日志归档 Piece。

* 清理当前归档路径中的 Piece 时，要求被清理的 Piece 不被当前数据备份路径中的任何数据备份所依赖。

  判断待清理的 Piece 是否被某个数据备份集所依赖的方法如下：

  1. 在租户当前的备份路径中，找到一个时间比较长远的数据备份集。

  2. 查看该数据备份集的 `START_REPLAY_SCN`。

     * 系统租户

        ```shell
        obclient(root@sys)[(none)]> SELECT * FROM oceanbase.CDB_OB_BACKUP_SET_FILES WHERE TENANT_ID = tenant_id AND BACKUP_SET_ID = set_id;
        ```

     * 用户租户

        ```shell
        obclient(root@mysql001)[(none)]> SELECT * FROM oceanbase.DBA_OB_BACKUP_SET_FILES WHERE BACKUP_SET_ID = set_id;
        ```

        ```shell
        obclient(SYSt@oracl001)[SYS]> SELECT * FROM SYS.DBA_OB_BACKUP_SET_FILES WHERE BACKUP_SET_ID = set_id;
        ```

     详细操作及说明，参见 [查看数据备份结果](../../400.data-backup/600.view-data-backup-history.md)。

  3. 查看待清理的 Piece 的 `END_SCN`。
