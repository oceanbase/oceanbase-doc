# 手动清理指定的备份

因业务需要，期望清理一些特定的备份时，可以参考本文档手动清理指定的数据备份集或日志归档 Piece。

## 使用限制

手动清理指定的备份时，要求当前租户未配置自动清理策略，否则，无法进行指定备份的清理。

## 清理指定的数据备份集（Backupset）

### 注意事项

清理指定的数据备份集时，需要注意以下事项：

* 不能破坏数据备份之间的依赖关系。如果某个数据备份被关联的增量备份所依赖，则被依赖的数据备份只能在所有依赖它的增量备份被删除后，才能被删除。

* 如果需要同时指定多个 `backup_set_id` 进行清理，则要求所有 `backup_set_id` 均在同一个备份路径下。不支持在同一条命令中清理多个路径下的数据备份。

* 如果当前备份路径中有数据正在写入，需要保留一份最新的能够用于恢复的全量数据备份。

### 系统租户清理指定用户租户的指定数据备份集

1. 使用 `root` 用户登录集群的 `sys` 租户。

   连接示例如下，连接数据库时请以实际环境为准。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. 获取待清理的备份集的 `backup_set_id`。

   ```shell
   obclient(root@sys)[(none)]> SELECT * FROM oceanbase.CDB_OB_BACKUP_SET_FILES WHERE TENANT_ID = tenant_id\G
   ```

   查询结果如下：

   ```shell
   ```

3. 执行以下命令，删除指定的数据备份。

   语句如下：

   ```sql
   ALTER SYSTEM DELETE BACKUPSET backup_set_id[,backup_set_id,...] TENANT [=] tenant_name;
   ```

   其中：

   * `backup_set_id`：指定待删除的备份集的 ID，单条命令中支持同时指定多个数据备份集。同时指定多个 `backup_set_id` 进行清理时，要求所有 `backup_set_id` 均在同一个备份路径下。不支持在同一条命令中清理多个路径下的数据备份。

   * `tenant_name`：指定待删除备份集的租户。

   示例如下：

   * 删除租户 `mysql001` 的 `backup_set_id` 为 5 的数据备份集。

     ```shell
     obclient(root@sys)[(none)]> ALTER SYSTEM DELETE BACKUPSET 5 TENANT = mysql001;
     ```

   * 同时删除租户 `mysql001` 的 `backup_set_id` 为 6、7、8、9 的 4 个数据备份集。

     ```shell
     obclient(root@sys)[(none)]> ALTER SYSTEM DELETE BACKUPSET 6,7,8,9 TENANT = mysql001;
     ```

### 用户租户清理本租户指定的数据备份集

1. 用户租户的租户管理员登录到数据库。

   <main id="notice" type='explain'>
   <h4>说明</h4>
   <p>MySQL 租户的管理员用户为 <code>root</code> 用户，Oracle 租户的管理员用户为 <code>SYS</code> 用户。</p>
   </main>

   连接示例如下，连接数据库时请以实际环境为准。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@mysql001#obdemo -p***** -A
   ```

2. 获取待清理的备份集的 `backup_set_id`。

   :::tab
   tab MySQL 模式

   MySQL 模式下的查询示例如下：

   ```shell
   obclient(root@mysql001)[(none)]> SELECT * FROM oceanbase.DBA_OB_BACKUP_SET_FILES\G
   ```

   tab Oracle 模式

   Oracle 模式下的查询示例如下：

   ```shell
   obclient(SYS@oracle001)[SYS]> SELECT * FROM SYS.DBA_OB_BACKUP_SET_FILES\G

   :::

   查询结果的示例如下：

   ```shell
   ```

3. 执行以下命令，删除指定的数据备份。

   语句如下：

   ```sql
   ALTER SYSTEM DELETE BACKUPSET backup_set_id[,backup_set_id,...];
   ```

   其中：

   * `backup_set_id`：指定待删除的备份集的 ID，单条命令中支持同时指定多个数据备份集，不同 `backup_set_id` 之间使用英文逗号间隔。同时指定多个 `backup_set_id` 进行清理时，要求所有 `backup_set_id` 均在同一个备份路径下。不支持在同一条命令中清理多个路径下的数据备份。

   * `tenant_name`：指定待删除备份集的租户。

   示例如下：

   * 删除本租户 `backup_set_id` 为 5 的数据备份集。

     ```shell
     obclient> ALTER SYSTEM DELETE BACKUPSET 5;
     ```

   * 同时删除本租户 `backup_set_id` 为 6、7、8、9 的 4 个数据备份集。

     ```shell
     obclient> ALTER SYSTEM DELETE BACKUPSET 6,7,8,9;
     ```

## 清理指定的日志归档 Piece

### 注意事项

清理指定的日志归档 Piece 时，需要注意以下事项：

* 需要按照顺序清理日志归档 Piece。

* 清理当前归档路径中的 Piece 时，要求被清理的 Piece 不被当前数据备份路径中的任何数据备份所依赖。

  判断待清理的 Piece 是否被某个数据备份集所依赖的方法如下：

  1. 在租户的前备份路径中，找到一个时间比较长远的数据备份集。

  2. 查看该数据备份集的 `START_REPLAY_SCN`。

     * 系统租户

        ```shell
        obclient(root@sys)[(none)]> SELECT * FROM oceanbase.CDB_OB_BACKUP_SET_FILES WHERE TENANT_ID = tenant_id AND BACKUP_SET_ID = set_id\G
        ```

     * 用户租户

        ```shell
        obclient(root@mysql001)[(none)]> SELECT * FROM oceanbase.DBA_OB_BACKUP_SET_FILES WHERE BACKUP_SET_ID = set_id\G
        ```

        ```shell
        obclient(SYSt@oracl001)[SYS]> SELECT * FROM SYS.DBA_OB_BACKUP_SET_FILES WHERE BACKUP_SET_ID = set_id\G
        ```

     详细操作及说明，参见 [查看数据备份结果](../../400.data-backup/600.view-data-backup-history.md)。

  3. 查看待清理的 Piece 的 `END_SCN`。

     * 系统租户

       ```shell
       obclient(root@sys)[(none)]> SELECT * FROM oceanbase.CDB_OB_ARCHIVELOG_PIECE_FILES WHERE TENANT_ID = tenant_id AND PIECE_ID= piece_id\G
       ```

     * 用户租户

       ```shell
       obclient(root@mysql001)[(none)]> SELECT * FROM oceanbase.DBA_OB_ARCHIVELOG_PIECE_FILES WHERE PIECE_ID= piece_id\G
       ```

       ```shell
       obclient(SYSt@oracl001)[SYS]> SELECT * FROM SYS.DBA_OB_ARCHIVELOG_PIECE_FILES WHERE PIECE_ID= piece_id\G
       ```

     详细操作及说明，可参见 [查看 Piece 信息](../../300.log-archive/500.view-log-archive-piece.md)。

  4. 将获取到的信息进行对比，如果待清理的 Piece 的 `END_SCN`大于或等于当前备份路径中某个数据备份的 `START_REPLAY_SCN`，则表示该 Piece 被此数据备份集所依赖。

* 如果需要同时指定多个 `piece_id` 进行清理，则要求所有 `piece_id` 均在同一个归档路径下。不支持在同一条命令中清理多个路径下的日志归档 Piece。
