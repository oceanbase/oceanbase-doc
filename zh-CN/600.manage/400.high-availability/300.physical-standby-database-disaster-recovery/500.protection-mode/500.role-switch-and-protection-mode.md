# 主备切换与保护模式

本节主要介绍保护模式在主备切换中的应用。

## Failover

如果主租户在最大保护或者最大可用级别宕机时，备租户通过 Failover 的方式切换为主租户，并且可以实现无损 Failover。

在执行 Failover 的过程中，无论之前备租户的保护模式和保护级别是什么，系统都会直接切换为最大性能模式。

## Switchover

主租户通过 Switchover 切换为备租户后，备租户切换成主租户有两个选择：选择强同步的备租户，或者非强同步的备租户：

* **选择强同步的备租户**：强同步的备租户切换成主租户后，如果该备租户在切换前设置了强同步的下游，并且主备租户均将上游指向对方（即原备租户的上游是原主租户、原主租户的上游是原备租户），则其保护模式可以继续保持，仍然为最大保护模式；对于未设置强同步下游的备租户，在切换为主租户时，系统会直接将其保护模式变更为最大性能模式。

* **选择非强同步的备租户**：对于非强同步的备租户，其保护模式都是最大性能模式，切换成主租户后，其保护模式仍然是最大性能模式，但是日志流是属于强同步的状态，故需要停写降级成功后，才能正常写入。

下面通过几个场景来进行说明：

基于网络的物理备库中，假设租户 A 为主租户，当前为最大保护模式，有一个强同步的备租户为租户 B，租户 C 的上游为租户 A，是异步同步的租户。

如果通过 Switchover 将租户 A 切换成备租户，可以将租户 B 或者 C 拉起成主租户。

**场景 1**：

选择将租户 B 拉起成主租户，并且在租户 B 拉起前，设置强同步的下游为租户 A，则租户 B 拉起后，其保护模式不变，依然为最大保护模式。

**场景 2**：

选择将租户 B 拉起成主租户，但是没有给租户 B 设置强同步的下游，则租户 B 拉起后，其保护模式退化为最大性能模式，租户 A 上的保护模式在接收上游新数据后，变更为最大性能模式。

**场景 3**：

选择将租户 C 拉起成主租户，则其保护模式退化为最大性能模式，租户 A、租户 B 上的保护模式在接收上游新数据后，变更为最大性能模式。
