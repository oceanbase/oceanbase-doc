# 设置保护模式

为主租户设置强同步的备租户后，可以将主租户设置为最大可用模式或最大保护模式。

## 使用限制及注意事项

* 保护模式只能在主租户上设置。

* 对于处于最大性能模式的主租户，如果需要将保护模式设置为最大可用模式或最大保护模式，要求主租户已设置了强同步的备租户。为主租户设置强同步的备租户的详细操作，参见 [设置强同步的下游](300.set-the-sync-standby.md)。

  对于处于最大保护模式或最大可用模式的租户，可以直接将保护模式修改为最大性能模式。

* 不支持设置级联的备租户进入强同步模式。

* 将租户从最大性能模式或者最大可用模式设置为最大保护模式时，要求强同步的备租户的同步位点与主租户的同步位点相差不超过 5 秒。

  可以通过以下语句，分别检查主备租户的同步位点，要求两者的差值小于 5,000,000,000（字段`SYNC_SCN` 对应的是纳秒级的位点）即可。

  * 系统租户

    ```shell
    obclient(root@sys)[(none)]> SELECT SYNC_SCN FROM oceanbase.DBA_OB_TENANTS WHERE TENANT_ID = tenant_id;
    ```

  * 用户租户

    :::tab
    tab MySQL 模式

    MySQL 模式下的查询语句如下：

    ```shell
    obclient(root@mysql)[(none)]> SELECT SYNC_SCN FROM oceanbase.DBA_OB_TENANTS;
    ```

    tab Oracle 模式

    Oracle 模式下的查询语句如下：

    ```shell
    obclient(sys@oracle001)[SYS]> SELECT SYNC_SCN FROM SYS.DBA_OB_TENANTS;
    ```

    :::

## 操作步骤

1. 使用管理员用户登录主租户或主租户所在集群的 `sys` 租户。

   <main id="notice" type='explain'>
    <h4>说明</h4>
    <p>MySQL 模式的管理员用户为 <code>root</code> 用户，Oracle 模式的管理员用户为 <code>SYS</code> 用户。</p>
   </main>

   连接示例如下，连接数据库时请以实际环境为准。

   ```shell
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

2. 执行以下语句，为主租户设置保护模式。

   语句如下：

   ```sql
   ALTER SYSTEM SET STANDBY TENANT TO {MAXIMIZE PERFORMANCE} | {MAXIMIZE AVAILABILITY} | {MAXIMIZE PROTECTION} [TENANT = tenant_name];
   ```

   其中，`tenant_name` 用于系统租户指定待设置保护模式的主租户名。

   示例如下：

   * 系统租户将主租户 mysql 的保护模式设置为最大可用模式。

     ```shell
     obclient(root@sys)[(none)]> ALTER SYSTEM SET STANDBY TENANT TO MAXIMIZE AVAILABILITY TENANT = mysql;
     ```

   * 用户租户将本租户的保护模式设置为最大可用模式。

     ```shell
     obclient> ALTER SYSTEM SET STANDBY TENANT TO MAXIMIZE AVAILABILITY;
     ```

3. 设置成功后，可以查询 `DBA_OB_TENANTS` 视图确认是否设置成功。

   * 系统租户

     ```shell
     obclient(root@sys)[oceanbase]> SELECT TENANT_NAME, PROTECTION_MODE, PROTECTION_LEVEL FROM oceanbase.DBA_OB_TENANTS WHERE TENANT_NAME = 'mysql';
     ```

   * 用户租户

     :::tab
     tab MySQL 模式

     MySQL 模式下，查询语句如下：

     ```shell
     obclient(root@mysql)[oceanbase]> SELECT TENANT_NAME, PROTECTION_MODE, PROTECTION_LEVEL FROM oceanbase.DBA_OB_TENANTS;
     ```

     tab Oracle 模式

     Oracle 模式下，查询语句如下：

     ```shell
     obclient(sys@oracle001)[SYS]> SELECT TENANT_NAME, PROTECTION_MODE, PROTECTION_LEVEL FROM SYS.DBA_OB_TENANTS;
     ```

     :::

   查询结果的示例如下：

   ```shell
   +-------------+----------------------+----------------------+
   | TENANT_NAME | PROTECTION_MODE      | PROTECTION_LEVEL     |
   +-------------+----------------------+----------------------+
   | mysql       | MAXIMUM AVAILABILITY | MAXIMUM AVAILABILITY |
   +-------------+----------------------+----------------------+
   1 row in set
   ```

## 设置保护模式的最佳实践

主备租户默认均为最大性能模式。在最大性能模式下，备租户可以通过日志归档或者网络的方式拉取日志，实现物理同步，这种情况下，不需要关心主备租户的部署方式、操作系统、规格等。但是，在最大保护或者最大可用模式下，主租户需要关注备租户的同步进度，日志需要在备租户上持久化成功后才能返回客户端，实际上相当于主租户多了一个多数派。为了减少此类情况下对主租户业务的影响，在设置保护模式时，需要保证以下事项：

1. 主备租户最好同城部署，需要保证网络延时足够的情况下，带宽足够大。

2. 主备租户的部署方式要求必须保持同构，防止因 CPU 或者内存不足限制了备租户接收日志。

3. 强同步模式下，对主备租户进行扩缩容时，建议时刻保证备租户的资源大于或等于主租户。即扩容时先扩容备租户再扩容主租户，缩容时先缩容主租户再缩容备租户。
