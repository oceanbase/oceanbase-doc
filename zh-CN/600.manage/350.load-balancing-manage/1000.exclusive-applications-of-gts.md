# GTS 独占应用案例

租户的 GTS（global timestamp service）服务由租户系统日志流承载，向租户下的所有 OBServer 节点提供全局时间戳。由于其可用性会直接影响到整个租户的可用性，因此在集群内节点数量很多，且 QPS 很高时，需要将 GTS 流量与用户流量隔离，优先保障 GTS 的响应时间。

本节主要介绍如何通过 `UNIT_NUM` 扩容并开启 GTS 独占的方式，将 GTS 流量与用户流量隔离，从而提升用户业务的稳定性。

## 背景信息

当前版本支持 GTS 独占功能，GTS 独占功能由租户级配置项 [enable_gts_standalone](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2550.enable_gts_standalone.md) 进行控制，默认为关闭状态。用户可以根据需要开启 GTS 独占功能，开启后，系统会自动保证 GTS 所在的系统日志流独占一组 Unit。

## 场景信息

假设当前有一租户 `tenant1`，其 Locality 为 `F@zone1，F@zone2，A`，Primary Zone 为 `zone1,zone2`，租户在 `zone1` 和 `zone2` 的 `UNIT_NUM` 均为 2，租户的日志流分布情况如下图所示。

## 操作步骤

在本场景中，当 SYS 日志流所在的机器达到了瓶颈后，为了保证业务的稳定性，可以先将租户所有资源池的 `UNIT_NUM` 从 2 扩容为 3，然后将 SYS 日志流（1 号日志流）迁移复制到扩容后新增的一组 Unit 上，使 1 号日志流独占一组 Unit，再开启 GTS 独占。

详细操作如下。

1. 使用 `root` 用户登录到集群的 `sys` 租户。

2. 关闭租户内的自动均衡功能。

   将租户级配置项 [enable_rebalance](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2800.enable_rebalance.md) 的值设置为 `False`，避免触发自动均衡，语句如下。

   ```shell
   obclient(root@sys)[(none)]> ALTER SYSTEM SET enable_rebalance = False TENANT = tenant1;
   ```

3. （可选）扩容前，如果 Zone 内节点数量不足，则需要先在 zone1 和 zone2 上各添加一个节点。

   添加节点的详细操作及说明，参见 [添加节点](../100.cluster-management/300.common-cluster-operations/400.add-a-node.md)。

4. 将租户所有资源池的 `UNIT_NUM` 调整为 3。

   ```shell
   obclient(root@sys)[(none)]> ALTER RESOURCE TENANT tenant1 UNIT_NUM = 3;
   ```

   有关通过 `UNIT_NUM` 进行扩容的详细操作及说明，参见 [通过调整 Unit Number 实现租户扩缩容](../200.tenant-management/600.common-tenant-operations/800.tenant-scale-in-and-out/300.adjust-unit-number.md)。

5. 变更日志流。

   将租户 `tenant1` 的 SYS 日志流（1 号日志流）的 `UNIT_GROUP`（同构 Zone 模式）/`UNIT_LIST`（异构 Zone 模式）修改为扩容新增的一组 Unit，使 1 号日志流可以独占一组 Unit。语句如下。

   :::tab
   tab 同构 Zone 模式

    ```shell
    obclient(root@sys)[(none)]> ALTER SYSTEM MODIFY LS 1 UNIT_GROUP unit_group_id TENANT = tenant1;
    ```

   其中，`unit_group_id` 需要根据实际环境，替换为扩容后新增的 Unit 的对应的 `UNIT_GROUP_ID`。

   tab 异构 Zone 模式

   ```shell
   obclient(root@sys)[(none)]> ALTER SYSTEM MODIFY LS 1 UNIT_LIST (unit_id1,unit_id2) TENANT = tenant1;
   ```

   其中，`unit_id1`、`unit_id2` 需要根据实际环境，替换为扩容后新增的 Unit 的 `UNIT_ID`。

   :::

   有关变更日志流的详细操作及说明，参见 [变更日志流](../230.logstream-management/200.modify-a-logstream.md)。

6. 开启 GTS 独占功能。

   将租户级配置项 [enable_gts_standalone](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2550.enable_gts_standalone.md) 的值设置为 `True`，语句如下。

   ```shell
   obclient(root@sys)[(none)]> ALTER SYSTEM SET enable_rebalance = True TENANT = tenant1;
   ```

7. 重新开启租户内的自动均衡功能。

   将租户级配置项 [enable_rebalance](../../700.reference/800.configuration-items-and-system-variables/100.system-configuration-items/400.tenant-level-configuration-items/2800.enable_rebalance.md) 的值设置为 `True`，避免触发自动均衡，语句如下。

   ```shell
   obclient(root@sys)[(none)]> ALTER SYSTEM SET enable_rebalance = True TENANT = tenant1;
   ```

本场景中，租户的 `UNIT_NUM` 扩容并开启 GTS 独占后，用户日志流的 `UNIT_NUM` 保持不变，仅 SYS 日志流（1 号日志流）进行了迁移复制，没有进行日志流的数量均衡，也没有发生 Transfer，从而保证了用户业务的稳定性。租户最终的日志流分布情况如下图所示。
