## OceanBase 服务器 BIOS 设置

### 特殊设置

* 在 Intel x86 架构的环境中：

  * 建议修改配置文件 `/etc/sysctl.conf`，将参数 `vm.swappiness` 设置为 `0`，方法如下：

    ```bash
    [root@xxx /]
    $vi /etc/sysctl.conf
    vm.swappiness = 0
    ```

    应用 sysctl.conf 配置文件里的值：

    ```bash
    [root@xxx /]
    $sysctl -p    
    ```

* 在 AMD 或者 ARM 架构的环境中，建议开启 Numa。

* 在 ARM 和海光架构的环境中，建议修改配置文件 `/etc/sysctl.conf`，将参数 `kernel.numa_balancing`、`vm.zone_reclaim_mode` 和 `vm.swappiness` 设置为 `0`，方法如下：

  ```bash
  [root@xxx /]
  $vi /etc/sysctl.conf
  kernel.numa_balancing = 0
  vm.zone_reclaim_mode = 0
  vm.swappiness = 0
  ```

  应用 sysctl.conf 配置文件里的值：

  ```bash
  [root@xxx /]
  $sysctl -p
  ```

### BIOS 需要关闭以下选项

* Cstate
* Pstate
* EIST
* Power saving

### BIOS 需要配置以下选项

* Automatic Power on After Power Loss: Always on
* Intel Virtualization Technology：开启
* Hyper-threading：开启
* Hardware prefetcher：开启
* VT-d：开启
* SR-IOV：开启
* Turbo Mode：开启
* Energy performance：开启最大 performance

  <main id="notice" type='explain'>
    <h4>说明</h4>
    <p>不同的服务器修改 BIOS 的方式不同，具体操作请参见服务器操作手册。</p>
  </main>

## 磁盘挂载

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>如果一个挂载点的目录文件容量大于 16 TB，仅支持 xfs 类型。</p>
</main>

* OCP 服务器的磁盘挂载点要求如下表所示。

  |    挂载点     |       大小       |     用途      |          磁盘格式           |
  |------------|----------------|-------------|-------------------------|
  | /home      | 100 GB\~300 GB | 各组件运行日志盘    | 建议 ext4 或 xfs |
  | /data/log1 | 内存大小的 3\~4 倍   | OCP 元数据库日志盘 | 建议 ext4 或 xfs |
  | /data/1    | 取决于所需存储的数据大小   | OCP 元数据库数据盘 | 建议 ext4 或 xfs |
  | /docker    | 200 GB\~500 GB | Docker 根目录  | 建议 ext4 或 xfs |

* OBServer 节点的磁盘挂载点要求如下表所示。

  |    挂载点     |       大小       |       用途       |         文件系统格式          |
  |------------|----------------|----------------|-------------------------|
  | /home      | 100 GB\~300 GB | observer 进程运行日志盘 | 建议 ext4 或 xfs |
  | /data/log1 | 内存大小的 3\~4 倍   | observer 进程日志盘   | 建议 ext4 或 xfs |
  | /data/1    | 取决于所需存储的数据大小   | observer 进程数据盘   | 建议 ext4 或 xfs |

  <main id="notice" type='explain'>
    <h4>说明</h4>
    <p>建议根目录不小于 50 GB。如果使用 LVM，建议创建时使用条带化参数。示例如下：</p>
    <p><code>lvcreate -n data -L 3000G obvg --stripes=3 --stripesize=128</code></p>
  </main>

### 服务器磁盘配置

<main id="notice" type='notice'>
  <h4>注意</h4>
  <p>不要将 <code>/var</code> 和 <code>/opt</code> 目录单独挂载分区。</p>
</main>

* 如果磁盘配置是 480G*2 + 3.84T NVME*8，内存配置是 512G：

  1. 2 块 480G 系统盘做 RAID 1，用来安装操作系统，分 50G 挂载给根目录，分 350G 挂载给 `/home`。
  2. 8 块 3.84T 盘做 LVM。之后划分 2.1T 挂载给 `/data/log1` 做为日志盘。其余挂载给 `/data/1` 做为数据盘。（选其中 3 台服务器做 OCP 服务器，从 `/data/1` 中划分出 800G 挂载给 `/docker`）

* 如果磁盘配置是 480G*2 + 3.84T SATA SSD*8，内存配置是 512G：

  1. 2 块 480G 系统盘做 RAID 1，用来安装操作系统，分 50G 挂载给根目录，分 350G 挂载给 `/home`。
  2. 2 块盘做 RAID 1，划分 2.1T 挂载给 `/data/log1`；另外 6 块盘做 RAID 5，全部挂载给 `/data/1`。（选其中 3 台服务器做 OCP 服务器，从 `/data/1` 中划分出 800G 挂载给 `/docker`）

* 如果磁盘配置是 480G*2 + 1.92T SATA SSD*6，内存配置是 768G：

  1. 2 块 480G 系统盘做 RAID 1，用来安装操作系统，分 50G 挂载给根目录，分 350G 挂载给 `/home`。
  2. 3 块 1.92T 盘做 RAID 5，之后划分 3.1T 挂载给 `/data/log1` 做为日志盘。其余 3 块 1.92T 盘做 RAID 5，挂载给 `/data/1` 做为数据盘。（选其中 3 台服务器做 OCP 服务器，从 `/data/1` 中划分出 800G 挂载给 `/docker`）

* 如果磁盘配置是 480G*2 + 1.6T NVME*6，内存配置是 768G：

  1. 2 块 480G 系统盘做 RAID 1，用来安装操作系统，分 50G 挂载给根目录，分 350G 挂载给 `/home`。
  2. 6 块 1.6T 盘做 LVM，之后划分 3.1T 挂载给 `/data/log1` 做为日志盘。其余挂载给 `/data/1` 做为数据盘。（选其中 3 台服务器做 OCP 服务器，从 `/data/1` 中划分出 800G 挂载给 `/docker`）

* 如果磁盘配置是 960 SATA SSD*10，内存配置是 384G：

  1. 4 块 960G 盘做 RAID 5，其中分 50G 挂载给根目录，分 500G 挂载给 `/home`，其余挂载给 `/data/log1`。
  2. 6 块 960G 盘做 RAID 5，挂载给 `/data/1`。（选其中 3 台服务器做 OCP 服务器，从 `/data/1` 中划分出 800G 挂载给 `/docker`）

* 如果磁盘配置是 480G*2 + 1.6T SATA SSD*6，内存配置是 384G：

  1. 2 块 480G 系统盘做 RAID 1，用来安装操作系统，分 50G 挂载给根目录，分 350G 挂载给 `/home`。
  2. 3 块盘做 RAID 5，划分 2.1T 挂载给 /data/log1； 另外 3 块盘做 RAID 5，全部挂载给 `/data/1`。（选其中 3 台服务器做 OCP 服务器，从 `/data/1` 中划分出 800G 挂载给 `/docker`）

## 网卡设置

建议配置 2 块万兆网卡：

* bond 模式取名 `bond0`，绑定的模式可以选择 `mode1` 或 `mode4`，但建议选择 `mode4`。对于 `mode4` 模式，交换机需要配置 802.3ad 协议。
* 网卡名建议使用 `eth0`、`eth1`。
* 建议使用 network 服务，不建议使用 NetworkManager。
* 通常不要使用 team 做绑定，因为 team 会导致无法识 `/sys/class/net/team0/speed` 里面的网卡速度。
* 同一个 bond 中的网卡需要连接不同的交换机。

## RAID 设置

* 强制 RAID 卡 Cache Write Back。
* 关闭 Disk Cache。
* 自动 Rebuild 开启。
* 对于 LSI RAID 卡，需要关闭 Consistency Check 和 Patrol Read 功能，更换 RAID 卡或升级 RAID 卡驱动/Firmware 后需要再次关闭。

## 网络端口

请确保 OceanBase 以下产品的网络端口未被占用：

| 产品服务器 | 端口号 | 说明 |
| --------- | ------ | ---- |
| OAT 服务器 | 7000 | OAT 管理控制台 |
| OCP 服务器 | 8080 | OCP API/OCP-Server web 服务端口 |
| OBServer 服务器 | 2881 | OBServer SQL 监听端口 |
| OBServer 服务器 | 2882 | OBServer 之间 RPC 通信端口 |
| ODP 服务器 | 2883 | ODP 监听端口 |
| ODP 服务器 | 2884 | ODP 监控指标 API 监听端口 |

更多组件监听端口的介绍信息，参见 [组件监听端口列表](https://www.oceanbase.com/docs/common-ocp-1000000004276399)。

## SSD 的 I/O 调度器建议

* NVMe SSD 默认的 I/O 调度器为 `none`，无需调整。
* SATA SSD 的 I/O 调度器建议设置为 `none`。

## 注意事项

OceanBase 数据库在 V4.2.5 BP3、V4.2.5 BP4、V4.2.5 BP5、V4.3.5 BP1、V4.3.5 BP2、V4.3.5 BP3 和 V4.4.0 版本增加了对 X86 架构环境运行的指令集要求。OBServer 进程会在启动前检查当前环境是否支持 AVX 指令集，如果缺少该指令集会禁止启动。
